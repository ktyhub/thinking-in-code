vllm v0.21.0

vllm v0.21.0

Highlights

Diese Version enthält 367 Commits von 202 Mitwirkenden (49 neue)!

  • Transformers v4 veraltet: In dieser Version wird die Unterstützung von transformers v4 offiziell eingestellt (#40389). Benutzer sollten auf transformers v5 migrieren.
  • C++20-Build-Anforderung: vLLM erfordert jetzt einen C++20-kompatiblen Compiler für die Kompatibilität mit PyTorch (#40380). Dies ist eine bahnbrechende Build-Änderung.
  • KV-Offload + Hybrid Memory Allocator (HMA): Das KV-Offloading-Subsystem lässt sich jetzt in den Hybrid Memory Allocator integrieren, einschließlich Unterstützung für planungsseitige Schiebefenstergruppen und vollständige HMA-Aktivierung (#41228, #41445, #39571).
  • Spekulative Decodierung mit Denkbudget: Die spekulative Dekodierung berücksichtigt jetzt Argumentations-/Denkbudgets und ermöglicht die korrekte Spezifikationsdekodierung für Argumentationsmodelle (#34668).
  • TOKENSPEED_MLA-Backend auf Blackwell: Ein neues TOKENSPEED_MLA-Aufmerksamkeits-Backend ist für DeepSeek-R1/Kimi-K25-Vorfüllung + Dekodierung auf Blackwell-GPUs verfügbar (#41778).

Modellunterstützung

  • Neue Architekturen: MiMo-V2.5 (#40967), Laguna XS.2 (#41129, #41880), Moondream3 (#32325), Qianfan-OCR (#40136), Cohere MoE (#40817), Cohere Eagle (#42078).
  • Spekulative Dekodierung: EAGLE für Mistral (#41024), Gemma4 MTP (#41745), MTP für MiMo-V2.5 (#41905), Cohere Eagle (#42078).
  • DeepSeek V4: AMD/ROCm-Unterstützung (#40871), Pipeline-Parallelität (#41694), max-Argumentationsaufwand (#40982), disaggregierte Bereitstellungskorrekturen (#41957).
  • Tool-Aufruf: Cohere Reasoning und Tool-Parser (#40422), LFM2/2.5-Tool-Parser (#39243).
  • Gemma3/Gemma4: hidden_act-Variantenunterstützung (#40588), Pipeline-Parallelitätskorrektur (#40786), MoE-Korrekturen (#41206, #41574, #41401), Tool-Parser-Absturzkorrektur (#41991, #42188).
  • Model Runner V2: Unterstützung für Qwen3.5/Mamba-Hybridmodelle (#35520), logprob_token_ids-Unterstützung (#40559).
  • CUDA-Diagramm: ViT CUDA-Diagrammunterstützung für Qwen2.5-VL (#40830).
  • Kompatibilität: Anbieter HCXVisionConfig für Transformers v5 (#38447), Unterstützung für ältere rope_type-Prüfpunkte (#41734).

Motorkern

  • KV-Offloading + HMA: Scheduler-seitige Schiebefenstergruppen (#41228), vollständige HMA-Aktivierung (#41445), Multi-Connector-HMA (#39571), Speichervervollständigung pro Job (#39186), DCP/PCP-Unterstützung in OffloadingConnector (#41549), MooncakeStoreConnector für verteiltes KV-Offloading (#40900).
  • Spekulative Dekodierung: Thinking-Budgetunterstützung (#34668), Backend-Auswahl für unabhängige Verfasser (#39930), multimodale Modellunterstützung mit Warnung (#41752), Eliminierung der Zuordnung pro Schritt (#41043).
  • Model Runner V2: Korrektur der Ablehnungsstichproben-Akzeptanzrate (#40651), Neuaufbau von Metadaten vor dem Vorfüllen des Entwurfs überspringen (#40410), Neuaufbau von Metadaten zwischen Entwurfsdekodierungsschritten (#41162), Qwen3.5/Mamba-Hybridunterstützung (#35520).
  • Routing: Routing-Wiedergabe durch Geräte-Cache und asynchrone D2H-Pipeline ersetzen (#39917).
  • Ray: RayExecutorV2 standardmäßig aktiviert (#41421), Kollisionsbehebung für Akteurnamen für DP > 1 (#40398).
  • Stabilität: Zweiphasige Pause zur Verhinderung eines Scheduler-Deadlocks (#39366), threadsichere HF-Tokenizer-Wrapper (#41181), OOM-Verhinderung über max_split_size_mb während des Ladens des Modells (#41268).
  • IndexCache-Unterstützung für DSA-Modelle (#37735).

Hardware und Leistung

  • NVIDIA Blackwell: TOKENSPEED_MLA-Backend für DSR1/Kimi-K25 (#41778), schnellerer FP8-Gruppen-Quant-Packed-Kernel pro Token (#41326), FP8 auf NVIDIA Thor/SM110 (#39712), CUTLASS skaliert mm für nicht kompatible Größen (#41868).
  • Leistung: FlashInfer-Top-K/Top-P-Sampler standardmäßig aktiviert (#40376), FP8-FlashInfer-Aufmerksamkeit für ViT (#38065), TurboQuant-gemeinsame Dequant-Puffer (#40941), AllPool.forward 51 % schneller (#41163), Eliminierung der GPU<->CPU-Synchronisierung beim Pooling (#41433) und Aufmerksamkeit (#41434), Numpy-Zero-Copy Einbetten der Serialisierung (#41681), multimodales Prozessorspringen für Nur-Text (#41246), FlashInfer FP8 asynchrone TP-Fusion (#39505), NVFP4 All-Gather-GEMM-Fusion für AsyncTP (#41882), Allreduce+RMS-Fusion für DP/PP erneut aktivieren (#41458), DeepSeek bf16→fp32 über torch.mm (#41300), persistentes MLA für Sparse-Backend (#41990), konfigurierbarer Safetensors-Checkpoint-Prefetch (#41499), Fused mhc_post_pre Kernel (#41536), 2D-Grid W8W8 Group Quant Kernel (#42153), entspannte Speicherreihenfolge für KV-Cache-Swaps (#39306).
  • AMD ROCm: ROCm 7.2.2 (#41386), DBO (Dynamic Batch Optimization) (#34726), AITER Fused Allreduce+RMSNorm (#37646), Fused Shared Expert (FSE) für Qwen3-Next (#39280), DeepSeek V3.2 TP4 AITER MLA (#41835), GDN lineare Aufmerksamkeit Fusion (#40711), Beseitigung redundanter MoE-Pufferkopien in AITER (#41713), CPU-Offloading-Unterstützung (#40549), DeepEP API-Update (#39721), Begrenzung der Triton-Seitenblockgröße zur Behebung von Shared-Memory-OOM (#38502).
  • CPU: FP8-Achtung für AMX/AVX-512 (#39445), FP8 W8A16 linear (#41186), FP8 W8A16 MoE (#41314), DNNL AVX2 W8A8 Int8 (#41318), Gated DeltaNet-Achtung für Qwen 3.5/3.6 (#41025), RISC-V Automatische OMP-Thread-Bindung (#40569).
  • **Intel
  • IBM Power: VSX-Aufmerksamkeits-Backend (#40451).
  • FlexAttention: Für den Batch-invarianten Modus wieder aktiviert (#40842).
  • MLA: Abstrahierte MLA-Prefill-Backends, beseitigte cuDNN-Abhängigkeit (#32623).

Große Portion

  • Disaggregierte Bereitstellung: Bidirektionale KV-Cache-Übertragungen zwischen P und D (#32553), NIXL-Übertragungs-Redesign (#40731), EPLB-Speicher-Overhead-Optimierung (#40013), NIXL-Connector auf 1.x erhöht (#42364), Mooncake KVConnectorStats für Übertragungsbeobachtbarkeit (#40414), NIXL-P-Knoten-Vorabzurückweisungsbenachrichtigung (#41269), KV-Blockfreigabe für P-Ränge übersprungen (#40449).
  • DCP: Ausgabe und LSE in DCP A2A packen (#41160).
  • MoE: PluggableLayer-Schnittstelle für Out-of-Tree-MoE-Läufer (#35178).
  • LoRA: Erste Expert Parallel (EP)-Unterstützung (#40867), Qwen3.5 LoRA Fusion Fix (#37912).

Quantisierung

  • NVFP4: KV-Cache-Unterstützung (#40177), Triton-Dequant/QDQ-Emulationskerne für Hopper und AMD (#40033), GELU auf TRT-LLM NvFP4 fusioniertes MoE für Gemma4 (#41050), ModelOpt NVFP4 W4A16 (#41769), NVFP4 All-Gather-GEMM-Fusion für AsyncTP (#41882), GLM4-MoE NVFP4-Ladefix (#41755).
  • MXFP4: Humming MXFP4 MoE-Backend (#41083), FlashInfer CUTLASS MXFP4-MXFP8 MoE-Fix (#42089).
  • TurboQuant: Hybridmodell und einheitliche Quantisierungsunterstützung (#39931).
  • Komprimierte Tensoren: Konfigurationen mit nicht expliziten Ignorierungen zulassen (#41965).
  • FP8: Bias Loading Fix (#41424), FlashInfer Autotune aus Gründen der Korrektheit vorübergehend deaktiviert (#41524).
  • DSV4: Verbesserter Fused Indexer Q Quant-Kernel (#41428).

API & Frontend

  • Antworten API: Streaming-Tool-/Funktionsaufruf mit required (#40700) und benannter Tool-/Funktionsauswahl (#41110), erneute Übermittlung von Ausgabeelementen mit fehlenden Feldern (#41355).
  • OpenAI-Kompatibilität: system_fingerprint-Feld in Antworten (#40537), prompt_embeds-Inhaltsteilunterstützung (#40720), defer_loading- und tool_reference-Unterstützung (#40190), gerenderter Eingabeaufforderungstext in Chat-Abschlussantwort (#42052), toleriert leeren Inhalt bei erzwungener Werkzeugauswahl (#40148).
  • Tool-Aufruf: XGrammar 0.2.0 mit Struktur-Tags für strikten Tool-Aufruf + Reasoning (#40894), Cohere Reasoning/Tool-Parser (#40422), LFM2/2.5-Tool-Parser (#39243).
  • Tokenizer: Fastokens-Unterstützung (#41741).
  • RLHF: Explizite /start_weight_update und /finish_weight_update APIs (#39212).
  • ASR: Abbruch der Engine-Anfrage bei Abbruch (#41266).
  • Konfiguration: VLLM_SKIP_MODEL_NAME_VALIDATION env var (#34676), konfigurierbare Modellgewichtungs-Ladeverfolgung (#41086), Triton JIT-Kompilierungsmonitor (#40137).

Build und Abhängigkeiten

  • Breaking: C++20 für PyTorch-Kompatibilität erforderlich (#40380).
  • Breaking: Transformers v4 veraltet (#40389).
  • Docker-Bildgröße um ~2.5 GB durch verzögerten FlashInfer-Cubin-Download reduziert (#41134).
  • CUDA 13.0-Räder auf PyTorch-manylinux_2_28-Basis umgestellt (#41416).
  • Das mitgelieferte DeepGEMM-Rad wurde für Python für CPython-Kompatibilität gebaut (#41516).
  • Metadaten zur Herkunft des Container-Images eingebettet (#40653).
  • TPU-Inferenz auf v0.19.0 aktualisiert (#41844).
  • Der NIXL-Anschluss wurde auf 1.x geändert (#42364).
  • ROCm 7.2.2 (#41386).
