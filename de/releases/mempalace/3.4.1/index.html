mempalace v3.4.1

v3.4.1 – Cursor- und Antigravity-IDE-Unterstützung

Wir haben jetzt Unterstützung für zwei weitere Editoren: ein Cursor-Plugin mit nativen Hooks und erstklassige Google Antigravity-Unterstützung – beide bringen MemPalaces automatisches Speichern, Sitzungsstart-Rückruf und wörtliches Transkript-Mining auf den gleichen Standard, der bereits für Claude Code und Codex ausgeliefert wird. Zwei Zuverlässigkeitskorrekturen runden den Zyklus ab: embeddinggemma beendet keine großen Re-Embeds mehr durch OOM und migrate/repair-Backups akkumulieren sich nicht mehr, bis sie die Festplatte füllen.

Funktionen

  • Cursor-IDE-Plugin (.cursor-plugin/). Registriert automatisch den mempalace-mcp-Server, fünf Slash-Befehle (/mempalace-help, /mempalace-init, /mempalace-mine, /mempalace-search, /mempalace-status) und einen modellaufrufbaren Skill – keine manuelle ~/.cursor/mcp.json-Bearbeitung. Installieren Sie es jetzt von einem lokalen Klon oder vom Cursor-Marktplatz, sobald es veröffentlicht wurde. (#1632)
  • Cursor-IDE-Hooks (stop / preCompact / sessionStart). Automatische Hintergrundspeicherung alle N Agentenrunden, synchrones Transkript-Mining vor der Cursor-Komprimierung und Speicherabruf beim Sitzungsstart, der auf den Arbeitsbereichsbereich beschränkt ist. Ein-Befehl-Installationsprogramm bei hooks/cursor/install.sh (--scope user|project, --variant full|minimal, --dry-run, --uninstall) – idempotent und abhängigkeitsfrei.
  • Erstklassige Antigravity (Google) IDE-Unterstützung. Neues .antigravity-plugin/-Paket und idempotenter Installer, der MemPalace als Antigravity-Plugin registriert – MCP-Server, Skill und zwei Lifecycle-Hooks (Hintergrund-Mining auf Stop, wörtliche Speicherinjektion beim ersten Modellaufruf). bash 3.2 / macOS-kompatibel, teilt das gleiche ~/.mempalace/hook_state/-Verzeichnis wie die Claude Code / Codex / Cursor-Hooks und berücksichtigt jeden vorhandenen Kill-Switch. (#1633, #1771)
  • Zero-Config-Interpreter-Auflösung für Hooks. Die Hooks lösen jetzt Python aus dem mempalace-mcp-Konsolenskript-Shebang auf, bevor sie auf python3 zurückgreifen, wodurch stillschweigendes No-Op-Mining unter uv tool install-/pipx-Layouts behoben wird, bei denen das System python3 mempalace nicht importieren kann.

Fehlerbehebungen

  • embeddinggemma beendet Massen-Neueinbettungen nicht länger durch OOM. Der ONNX-Embedder hat einen einzigen Durchgang über seine gesamte Eingabe ausgeführt, sodass ein Reparaturstapel (~5.000 Dokumente) Aufmerksamkeitspuffer weit über den verfügbaren RAM hinaus zugewiesen hat und der Kernel den Prozess stillschweigend abgebrochen hat. Die Einbettung erfolgt jetzt in Teilstapeln mit jeweils 32 Dokumenten. Die Vektoren pro Dokument bleiben unverändert. (#1770)
  • Backup-Aufbewahrung, um eine unbegrenzte Festplattennutzung zu verhindern. mempalace migrate und mempalace repair max-seq-id haben bei jedem Lauf ein neues Backup in voller Größe erstellt und nie bereinigt – ein Palast wurde mit Hunderten GB veralteter Backups neben einigen hundert MB Live-Daten gefunden. Eine neue max_backups-Einstellung (Standard 10; 0 behält alle bei) bereinigt jetzt die ältesten, nachdem jedes neue Backup geschrieben wurde. (#1697) Ein großes Dankeschön an alle, die zu diesem Zyklus beigetragen haben – sowohl die IDE-Integrationen als auch einige dieser Korrekturen kamen von der Community, darunter auch eine Reihe von Erstmitwirkenden. Alle werden unten aufgeführt.
