mempalace v3.3.6

3.3.6 ist eine Feature-Version. Die Hauptarbeit des Zyklus: Standardmäßiger mehrsprachiger Abruf (Einbettung von Gemma ersetzt MiniLM, sprachübergreifende Kosinussprünge von 0.35 → 0.88), der erste Schnitt des Living-Memory-Graphen (Flure innerhalb von Flügeln, Tunnel über Flügeln, Hebbsche Potenzierung + Ebbinghaus-Zerfall, damit Verbindungen bei Verwendung stärker werden und ohne sie verblassen), Office-Document-Mining (PDF, DOCX, PPTX, XLSX, RTF, EPUB über das neue --mode extract), virtuelle Zeilennummern + OP-Schrankzeiger, die genaue Zeilenbereiche zu genauen Daten angeben, und der Bereinigungsdurchgang zur Entitätserkennung, der „Code“ aus Ihren Fluren fernhält und „Claude Code“ atomar macht. Die Versprechen haben sich nicht geändert. Jedes Wort ist genau gespeichert. Alles bleibt auf Ihrer Maschine. Keine Telemetrie. Jede Veröffentlichung schärft das, was bereits vorhanden ist.

Funktionen

  • Office-Dokument-Mining über --mode extract. Das neue mempalace mine <dir> --mode extract erfasst PDFs, Word- (.docx), PowerPoint- (.pptx), Excel- (.xlsx), RTF- und EPUB-Bücher zusätzlich zum vorhandenen Quellcode-/Textpfad. Mit pip install mempalace[extract] installieren – ruft striprtf für RTF und MarkItDown (mit [docx,pdf,pptx,xlsx]-Unterextras) für die Binärformate ab. Python 3.9-Benutzer erhalten RTF-Abdeckung nur, weil MarkItDown 3.10+ erfordert. Schubladen aus dem Extraktionspfad enthalten extract_mode-Metadaten, sodass die Meldung „bereits abgebaut?“ des Convo-Miners angezeigt wird. Überprüfung und Generierung der Schubladen-ID bleiben pro Modus isoliert (#1528). (#1555)
  • Virtuelle Zeilennummern + OP-Schrankzeiger. Gespeicherte Schubladen tragen jetzt virtuelle Zeilennummern, sodass das Leseverb CLI und die Schrankzeiger genaue Zeilenbereiche angeben können. Closet-Zeiger (Tier 6a) enthalten Datums- und Zeilenbereichsinformationen, die aus der Dateinamen- und Inhaltskörper-Datumsanalyse abgeleitet werden (python-dateutil ist jetzt eine Kernkomponente), sodass MemPalace Sie auf exakte Zeilen zu genauen Daten verweisen kann und nicht nur auf „irgendwo in dieser Schublade“. (#1555, #1584)
  • Flure innerhalb von Flügeln. Wenn zwei Entitäten (Personen, Projekte, Themen) gleichzeitig in derselben Schublade vorkommen, zeichnet der Miner jetzt einen „Flur“ auf – eine Diagrammkante, die sie innerhalb dieses Flügels verbindet. Wird automatisch als Teil des Post-Mine-Schritts in compute_hallways_for_wing berechnet, sodass das Diagramm schrittweise mit neuem Inhalt wächst, kein separater Befehl erforderlich. Grundlage für die raumübergreifende Entitätsnavigation innerhalb eines Palastes. (#1558, #1560)
  • Flügelübergreifende Tunnel, die von Fluren aus gefördert werden. Wenn dieselbe Entität in Fluren über mehrere Flügel hinweg erscheint, befördert MemPalace sie jetzt automatisch in einen Tunnel – so können Anfragen vom Flügel einer Person zu einem Projektflügel springen, in dem sie erscheinen, ohne dass jemand create_tunnel manuell aufrufen muss. Thementunnel aus dem bestehenden compute_topic_tunnels-Pfad bleiben unverändert. (#1565)
  • Dynamik der lebendigen Erinnerung (Hebbsche Potenzierung + Ebbinghaus-Zerfall). Flure und Tunnel werden jedes Mal stärker, wenn dieselbe Verbindung durch neuen Inhalt verstärkt wird („was zusammen feuert, verdrahtet zusammen“) und verblassen allmählich, wenn eine Verbindung in eingehenden Schubladen nicht mehr auftaucht. Navigationsgewichte verfolgen die tatsächliche Palastnutzung und sind nicht statisch, so dass sich das Abrufranking mit der Zeit verbessert, wenn der Palast tatsächlich genutzt wird. (#1578)
  • API-Tool-Transkripte werden automatisch an wing_api weitergeleitet. Konversationstranskripte von KI-Tools im API-Stil (Claude Code, Claude.ai, ChatGPT, Slack-Bot-Exporte, generisches OpenAI-Shape JSON usw.) werden jetzt an einen dedizierten wing_api weitergeleitet, anstatt sich in die menschlichen Konversationsflügel zu mischen. Verhindert, dass der Tool-Aufrufverkehr persönliche Bereiche/Projektbereiche belastet, und verbessert die Suchgenauigkeit, wenn Sie nach „Was habe ich gesagt“ und „Was hat der Agent gesagt“ suchen? (#1236)
  • Mehrsprachige Einbettung standardmäßig für Neuinstallationen: embeddinggemma-300m ONNX (q8, MRL→384-dim). Der bisherige Einbetter von MemPalace (all-MiniLM-L6-v2) wird nur auf Englisch trainiert – sprachübergreifende Kosinusähnlichkeit bei parallel übersetztem Text durchschnittlich 0.35 für DE/FR/HI/IT/KO/RU (RU bei 0.17, nahezu orthogonal). Ein russischsprachiger Benutzer kann seine eigenen Erinnerungen effektiv nicht finden, was das Designversprechen „100 % Rückruf“ von CLAUDE.md bricht. Die neue EmbeddinggemmaONNX-Klasse in mempalace/embedding.py bringt dies auf den 0.88-Durchschnitt (validiert verlustfrei im Vergleich zum Ollama gguf über direkten ONNX-Laufzeittest). Lazy-Downloads von onnx-community/embeddinggemma-300m-ONNX (~300 MB) bei der ersten Verwendung über huggingface_hub. Die Ausgabe wird über Matryoshka Representation Learning auf 384 Dims gekürzt, sodass das Modell ein Drop-In für die 384-Dim-Sammlungen von ChromaDB ist – keine Schemaänderung. Das Sim-Präfix ("task: sentence similarity | query: ") wird automatisch angewendet. Onboarding (python -m mempalace.onboarding) bietet jetzt das mehrsprachige Modell als Standard an – wenn Sie es auswählen, wird embedding_model: embeddinggemma in config.json geschrieben, sodass nachfolgende Läufe es ohne erneute Aufforderung übernehmen. Vorhandene Installationen, die nie die Umgebungsvariable festgelegt oder das Onboarding ausgeführt haben, bleiben auf minilm (rückkompatibel). MEMPALACE_EMBEDDING_MODEL=minilm|embeddinggemma überschreibt beide. Das Wechseln der Modelle in einem vorhandenen Palast erfordert eine erneute Einbettung. Führen Sie nach der Änderung mempalace repair rebuild-index aus. (#1483)
  • Mehrsprachige Deps wurden in den Kern verschoben. huggingface_hub, tokenizers und numpy sind jetzt erforderliche Deps, sodass der mehrsprachige Pfad nach pip install mempalace sofort funktioniert. Das Extra [multilingual] wird als No-Op-Alias ​​für die Rückkompatibilität mit Installationsskripten beibehalten. Das 300-MB-ONNX-Modell selbst wird immer noch bei der ersten Verwendung verzögert heruntergeladen, nicht bei der Installation.
  • Freundlicher ChromaDB-EF-Name-Mismatch-Fehler. Das Einschalten von MEMPALACE_EMBEDDING_MODEL in einem vorhandenen Palast, ohne rebuild-index auszuführen, brachte zuvor ChromaDBs bloßes Embedding function conflict: new: X vs persisted: Y ValueError zum Vorschein – genau, aber den Benutzern wurde nicht gesagt, wie sie es wiederherstellen können. ChromaBackend.get_collection() umschließt nun diesen Fehler und zeigt auf beide Optionen: Env-Variable zurücksetzen oder mempalace repair rebuild-index --palace <path> ausführen. (#1483)
  • hooks.auto_save-Schalter für Silent-Mode-Sitzungen. Mit dem neuen Konfigurationsknopf (und der --silent CLI-Flag-Verkabelung über den Speicherhaken) können Benutzer die automatische Tagebuchspeicherung auf Stop / PreCompact deaktivieren. Nützlich für Sitzungen im „Ruhemodus“, bei denen nicht jedes Gespräch aufgezeichnet werden soll. Das Standardverhalten bleibt unverändert – die automatische Speicherung wird weiterhin ausgeführt, sofern sie nicht ausdrücklich deaktiviert wird. (#711)
  • Filtern Sie gebräuchliche englische Inhaltswörter aus der Entitätserkennung. Hochfrequente englische Inhaltswörter („System“, „Benutzer“, „Speicher“, „Projekt“, „Kontext“ usw.) wurden vom Schubladendetektor als Entitäten markiert und verunreinigten das Entitätsregister als „Personen“. Eine mitgelieferte COCA-Wortliste (Top-N-Inhaltswörter) wird nun bei der Entitätsklassifizierung herangezogen, sodass diese gefiltert werden, bevor sie das Register erreichen. Gehärtet gegen fehlerhaftes JSON in der gebündelten Wortliste. (#1605)
  • Beim Entitätsabgleich ohne Berücksichtigung der Groß-/Kleinschreibung. Beim ersten Palast-Build (mempalace init) wurde bei den Entitätsnamen die Groß-/Kleinschreibung nicht beachtet, bei dem beim inkrementellen Mining verwendeten Tagger pro Schublade war dies jedoch nicht der Fall – daher wurde dieselbe Person zwischen init und ingest unterschiedlich getaggt („Aya“ vs. „aya“ wurden zu unterschiedlichen Entitäten). Der inkrementelle Tagger spiegelt jetzt den Matcher ohne Berücksichtigung der Groß- und Kleinschreibung wider und stellt die Konsistenz der Entitäts-Tags über den gesamten Palastlebenszyklus hinweg wieder her. (#1557)

Fehlerbehebungen

  • Stiller Datenverlust in drei Upsert-Pfaden. Drei Upsert-Sites (Dateiaufnahme, Konversationsaufnahme und ein Reparaturzweig) riefen den Embedder für unchunked Inhalte auf und schnitten stillschweigend bei der maximalen Token-Grenze des Embedders ab. Bei langen Schubladen wurde nur der erste Abschnitt indiziert, was das Versprechen einer „100 %-Erinnerung“ für lange Inhalte brach. Alle drei durchlaufen nun zuerst den Chunker, sodass das gesamte Dokument eingebettet und gespeichert wird. (#1540, Folge zu #1539)
  • Absatzblocker hat übergroße Blöcke für lange Absätze ausgegeben. Der Absatzsplitter ging davon aus, dass Absätze immer kürzer als CHUNK_SIZE waren, und gab sie im Ganzen aus; Lange Absätze (Rechtstexte, dichte technische Aufsätze) gingen stillschweigend über das Kontextfenster des Einbetters hinaus. Der Splitter begrenzt nun jeden emittierten Block fest, um CHUNK_SIZE zu würdigen. (#1538, behebt #1534)
  • Die Chunk-Obergrenze pro Datei war fest codiert und für große Transkripte zu niedrig. Eine Sicherheitsgrenze begrenzte Chunks pro Datei auf einen für den Quellcode optimierten Wert. Die Suche nach sehr umfangreichen Gesprächsprotokollen ließ den Schwanz stillschweigend hinter dieser Kappe fallen. Jetzt konfigurierbar, wobei der Standardwert angehoben wurde, um realistische Transkriptgrößen abzudecken. (#1554, behebt #1455)
  • Hook-Unterprozess/ChromaDB-Deadlock unter Windows. Stop/PreCompact-Hooks könnten bei einem bereits geöffneten ChromaDB client unter Windows einen Deadlock verursachen, sodass der Host (Claude Code) am Hook hängen bleibt. Dreiteiliger Fix: veraltete PID-Zeitüberschreitung bei Mine-Lock-Reklamation, Leerlauf-Exit-Pfad im MCP-Server und strukturierte Fehler, wenn das Deadlock-Muster erkannt wird, damit der Host wiederhergestellt werden kann. (#1562, behebt #1552)
  • create_tunnel beschädigte Wing-Namen mit Bindestrich. Der Endpunktparser teilte sich auf -, sodass Wings, deren Name einen Bindestrich enthielt (mem-palace, my-app), im mittleren Namen abgeschnitten wurden und der Tunnel auf einen nicht vorhandenen Endpunkt zeigte. Bei der Endpunktanalyse bleibt jetzt der vollständige Slug erhalten. (#1529, behebt #1504)
  • Der MCP-Knowledge-Graph-Cache erzeugte doppelte Diagramme für symbolisch verknüpfte/anders geschriebene Palastpfade. Der Cache-Schlüssel war die rohe Pfadzeichenfolge, sodass /Users/me/.mempalace/palace und /Users/me/.mempalace/Palace (Groß-/Kleinschreibung unter macOS) oder ein symbolisch verknüpfter Alias zwei separate zwischengespeicherte KnowledgeGraph-Instanzen erzeugten, die auf dieselbe SQLite-Datei zeigten, mit dem Risiko veralteter Lesevorgänge. Der Cache normalisiert sich jetzt über realpath + normcase, sodass sie auf einen einzigen kanonischen Schlüssel reduziert werden. (#1383, behebt #1372)
  • Save-Hook kürzte Projektordnernamen mit Bindestrich ab. Der Wing-Name-Parser teilte auf - auf und behielt nur das erste Segment bei, sodass mem-palace zu mem wurde. Fix behält den gesamten Projektordner-Slug bei, sodass getrennte Paläste über Hook-Aufrufe hinweg kohärent bleiben. (#1424, behebt #1410)
  • Miner hat symbolische Links stillschweigend übersprungen. Benutzer waren verwirrt über fehlende Daten nach dem Mining; Der Miner übersprang Symlinks, ohne sie aufzutauchen. Protokolliert jetzt jeden übersprungenen Symlink mit dem Grund, sodass die Lücke sichtbar ist. (#1466, behebt #1462)
  • Der vom Host durchgesickerte PYTHONPATH könnte beim Import die eigenen Module von MemPalace überschatten. Das Paket __init__ entfernt jetzt beim Import durchgesickerte Einträge, sodass das importierte MemPalace immer das installierte ist. (#1439, behebt #1423)
  • macOS-Stock-Bash-Hook-Skripte. Hook-Skripte verwendeten mapfile (Bash 4+) und zerstörten den macOS-Standard /bin/bash 3.2. Auf eine Sed-Pipeline umgestellt, sodass Hooks sofort auf jedem Mac funktionieren. (#1441, behebt #1440)
  • Plugin-Stopp/PreCompact-Hooks könnten bei einem hängengebliebenen untergeordneten Prozess auf unbestimmte Zeit hängen bleiben. Ein begrenztes Timeout stellt sicher, dass der Host immer Fortschritte machen kann, selbst wenn der untergeordnete Prozess von MemPalace fehlerhaft ist. (#1470, behebt #1465)
  • MCP-Handler geben jetzt strukturierte JSON-RPC-Fehler für fehlerhafte Eingaben zurück. Unbekannte Parameternamen gaben -32602 Invalid params anstelle eines unstrukturierten Python TypeError zurück; Parameter mit der falschen Form geben einen strukturierten Fehler anstelle eines rohen Tracebacks zurück. (#1500, #1513)
  • CLI unterscheidet zwischen „Palast existiert nicht“ und „Palast existiert, ist aber leer“. Zwei Zustände, die für einen neuen Benutzer gleich aussehen, werden jetzt separat mit jeweils umsetzbaren Meldungen zum nächsten Schritt gemeldet. (#1532, behebt #1498)
  • mempalace repair Post-Pass: VACUUM + FTS5-Neuaufbau. Nach einer Palastreparatur behielt die SQLite-Knowledge-Graph-Datei fragmentierte Seiten und einen veralteten FTS5-Index; Wenn Sie VACUUM ausführen und am Ende FTS5 neu erstellen, wird die Festplatte freigegeben und die Suchleistung wiederhergestellt. (#1523)
  • Convo-Miner-Modus-Isolierung. Die Meldung „bereits abgebaut?“ wird angezeigt. Bei der Überprüfung und Generierung der Schubladen-ID wurde extract_mode ignoriert, sodass beim Wechseln der Modi entweder derselbe Inhalt erneut ermittelt wurde (Daten-Dup) oder Schubladen-IDs zwischen den Modi kollidierten. Durch die Festlegung des Bereichs nach Modus bleiben die Schubladen jedes Modus isoliert und dedupliziert. (#1528, behebt #1505)
  • FTS5-Validierung am Ende von mir. Das Mining validiert jetzt die FTS5-Indexintegrität als Post-Schritt, sodass Beschädigungen zum Zeitpunkt des Schreibens und nicht zum Zeitpunkt des Lesens erkannt werden. (#1548, behebt #1537)
  • hooks_cli stürzte bei flachen Installationspfaden ab. Der Code indizierte Path.parents[3] unter Annahme eines tiefen Installationsbaums und löste IndexError aus, wenn MemPalace von einem flachen Pfad aus ausgeführt wurde (z. B. /opt/mp). Fügt einen Schutz hinzu, damit flache Installationen bei Hook-Befehlen nicht mehr abstürzen. (#1585)
  • Quarantäne für HNSW-Segmente: Null-Byte vs. Missing-Dim. Frühere Quarantäne-Heuristiken markierten jedes HNSW-Segment, dem das Metadatenfeld dim fehlte, als beschädigt, die meisten waren jedoch wiederherstellbar; Die Prüfung unterscheidet nun wiederherstellbare, fehlende und tatsächlich beschädigte Indexsegmente, wobei funktionierende Indexsegmente erhalten bleiben. Null-Byte-Linklistendateien (teilweise geschriebene Segmente) werden jetzt vollständig abgelehnt. (#1452, #1461, behebt #1457)
  • Mine-Lock-Inhaberdatei als UTF-8 statt als cp1252 geschrieben. Nicht-ASCII-Windows-Benutzernamen und -Pfade beschädigen die Sperrdatei nicht mehr und unterbrechen die Erkennung veralteter Sperren. (#1438)
  • Miner-Slot-Claim schreibt jetzt sofort eine Platzhalter-PID. Absturz zwischen Claim und PID-Schreiben hinterlässt keine Phantomsperre mehr. (#1543, behebt #1443)
  • mine_convos läuft jetzt innerhalb von mine_palace_lock. Zwei gleichzeitige convos mine-Aufrufe können den Index nicht mehr beschädigen. (#1477)
  • Bereinigung des Migrationstools. Das Migrationstool der ChromaDB-Version schließt jetzt seine SQLite-Verbindung und entfernt das temporäre Palastverzeichnis, wenn während der Migration eine Ausnahme ausgelöst wird. Fehlgeschlagene Migrationen verhindern, dass Dateihandles und Datenträger verloren gehen. Entity-Registry Atomic-Write löscht jetzt seinen .tmp-Sidecar, wenn das Schreiben oder Umbenennen fehlschlägt. (#1216, #1408, behebt #1373)
  • Reparaturtool toleriert leere/keine Metadatenzellen. ChromaDB gibt während der Neuerstellung gelegentlich Zellen mit leeren Metadaten-Dikten oder None zurück; Beide werden nun zu vernünftigen Standardeinstellungen gezwungen, damit der Wiederaufbau abgeschlossen wird und ansonsten festgefahrene Paläste wiederhergestellt werden. (#1459, #1445, behebt #1426) – create_tunnel MCP-Handler gibt jetzt Fehler weiter. Ein fehlerhafter Endpunkt oder eine fehlerhafte Richtung wurde verschluckt und als irreführender Erfolg zurückgegeben. breitet sich jetzt als strukturierter MCP-Fehler aus. (#1546, behebt #1473)
  • Explizite Tunnel wurden fest codiert gespeichert ~/.mempalace/tunnels.json path that ignored MempalaceConfig.palace_path. Drawers, KG triples, the people map, and every other piece of palace state honour the configured palace_path (and the MEMPALACE_PALACE_PATH env var), but palace_graph._TUNNEL_FILE was a module-level constant initialised once from os.path.expanduser("~") + "/.mempalace/tunnels.json". Under any setup where $HOME is isolated from the configured palace — subagent profiles with their own $HOME, sandboxes, multi-tenant hosts, container mounts that move the palace to /srv/ — drawers landed in the configured palace while tunnels silently landed in a different file that no other process touching the same palace could see. Worst case is the agentic one: an isolated worker calls create_tunnel then list_tunnels`ZZPH10 0ZZ`palace_graph._TUNNEL_FILE is replaced by _get_tunnel_file() which derives the path from a new MempalaceConfig.tunnel_file property (sibling of palace_path). The default single-user install is unchanged because the default palace_path is still ~/.mempalace/palace and its sibling tunnels.json is the legacy path. Backwards-compatibility: if the configured tunnel file does not exist but a file is present at the pre-3.3.6 hardcoded ~/.mempalace/tunnels.json path AND the two paths differ, _load_tunnels logs a one-line WARNING Benennen Sie beide Pfade und geben Sie eine leere Liste zurück. Wir führen absichtlich KEINE automatische Migration durch, da das stille Zusammenführen des Tunnelstatus über zwei Standorte hinweg die Gefahr birgt, dass neuere Daten überlastet werden. Der Benutzer verschiebt oder kopiert die Datei selbst. (#1467)
  • create_tunnel did not validate that the source and target rooms actually exist in the chroma index. _require_name only checked that wing/room names were non-empty strings; nothing queried the collection to confirm at least one drawer carried matching {wing, room} metadata. Pointing an explicit tunnel at a phantom room — common when an agent fabricates a room name it expects to exist, or types a slug wrong — silently succeeded. Combined with the read-bubble described in the previous fix, an agent could create_tunnel → list_tunnels and have both calls return its own bogus write. create_tunnel now calls _check_room_exists(wing, room, col) for both endpoints before persisting an explicit tunnel; if either endpoint has zero matching drawers the call raises ValueError naming the offending wing/room pair. Three deliberate carve-outs: (1) kind != "explicit" skips validation because topic tunnels generated by compute_topic_tunnels use synthetic topic:<name> room identifiers that don't correspond to real chroma rooms; (2) _get_collection returning None (palace not yet created, transient backend failure, tests without a real chroma backend) skips validation rather than fail-closed — matches the tolerance pattern used everywhere else in palace_graph; (3) exceptions raised by the underlying col.get(where=..., limit=1, include=[]) query are logged and treated as "can't verify, allow" so a temporary index fault never blocks legitimate writes. Behaviour change: existing callers that previously created tunnels pointing at empty rooms (e.g. as scaffolding before mining them) will now raise ValueError. Feilen Sie zuerst die Schublade, dann erstellen Sie den Tunnel – dies ist die Reihenfolge, die in der Dokumentation immer empfohlen wird. (#1468)

Leistung

  • Convo-Miner ruft den abgebauten Satz einmal vorab ab. Es wurde eine WHERE-Abfrage pro Datei ausgegeben, um zu prüfen, ob „bereits abgebaut?“ ist. Ruft jetzt einmal den gesamten geschürften Satz vorab ab, wodurch die Zeit, die bei großen Transkriptkorpussen benötigt wird, deutlich verkürzt wird. (#1474)
  • rebuild_index Fortschrittsrückruf. Mehrstündige Neuerstellungen melden jetzt den Fortschritt mit dem Standard-ETA-Drucker; Benutzer müssen nicht mehr raten, ob der Prozess Fortschritte macht. (#1487)
  • MCP-Kaltstart-Diagnose + Opt-In-Aufwärmphase. Fügt Sichtbarkeit darüber hinzu, welcher Embedder geladen wird und wie lange es dauert, sowie einen Opt-In-Aufwärmpfad, damit Benutzer die langsame Latenz bei der ersten Abfrage erkennen und beheben können. (#1530, behebt #1495)

Intern

  • „palace_graph._TUNNEL_FILE`` (module-level constant) replaced by ``_get_tunnel_file(config=None)`` and ``_legacy_tunnel_file()``. Tests previously monkeypatching the constant must now monkeypatch the resolver functions. The ``tests/test_palace_graph_tunnels.py::_use_tmp_tunnel_file`` helper, ``tests/test_closets.py::TestTunnels`` setup/teardown, and three tests in ``tests/test_miner.py`` were updated accordingly. Topic-tunnel tests in ``test_miner`` continue to work without stubbing ``_get_collection`` because ``kind="topic"“ schließt den neuen Validierungspfad kurz.
