Fehlerbehebung

  1. Fehler bei der Aktualisierung einzelner Tabellenmetadaten behoben, der durch das Filtern von DataSourceContainedRule verursacht wurde
  2. Parsing-Ausnahme behoben, die durch den Nullwert des Blob-Typs MySQL verursacht wurde
  3. Beheben Sie den Analysefehler der PostgreSQL/openGauss-Reset-Anweisung
  4. Korrigieren Sie das falsche Umschreiben von Parametern bei der Verwendung von Sharding und Verschlüsselung
  5. Beheben Sie die fehlgeschlagene Konvertierung monatsbezogener Klassen in IntervalShardingAlgorithm
  6. Beheben Sie die NullPointerException, wenn die Ausführungs-Select-Union-Anweisung eine Unterabfrage enthält
  7. Korrigieren Sie ein falsches Ergebnis beim Verschlüsseln und Umschreiben aufgrund einer falschen Reihenfolge der Metadaten
  8. Behebung des Analysefehlers der Trimmfunktion MySQL
  9. Behebung des MySQL-Einfügewerts mit _binary-Analysefehler

  11. Vermeiden Sie, dass EventLoop aufgrund des Schließens von JDBC-Ressourcen blockiert wird

  13. Beheben Sie ein mögliches Verbindungsleck, wenn Proxy client in der Transaktion die Verbindung trennte

  20. Skalierung: Behebung des Problems, dass die Tabelle bei der Inventarmigration sowohl Primärschlüssel als auch eindeutigen Index enthält
  21. Skalierung: Verbessern Sie die inkrementelle Migration und unterstützen Sie die neueste Position in der Mitte des Batch-Einfügungsereignisses
  22. Skalierung: Behebung des Fehlers, der durch den Nullfeldwert bei der inkrementellen Migration von openGauss verursacht wurde
  23. DistSQL: Falschen Strategienamen im Ergebnis von SHOW SHARDING TABLE RULES korrigieren

  28. Korrigieren Sie den Clustermodus ShardingSphere-JDBC, der alle Logikdatenbanken lädt

  30. Behebung von DistSQL durch Hinzufügung einer Schattenalgorithmus-Ausnahme ohne Schattendatenquelle
  31. Beheben Sie datenbankübergreifende Datenquellenverwirrungen, die durch denselben Datenquellennamen in mehreren logischen Datenbanken verursacht werden
  32. RUL DistSQL-Ausführungsfehler in der Transaktion beheben
  33. Fixstart für PostgreSQL und openGauss
  34. Agent: Der Fehler des Nullwerts im contextManager beim Sammeln von Metrikdaten wurde behoben

API Änderungen

  1. Entfernen Sie die SQL-Passthrough-Funktion zur Datenquelle
  2. Fügen Sie die neue assistedQueryEncryptorName-Schnittstelle hinzu und entfernen Sie die QueryAssistedEncryptAlgorithm-Schnittstelle
  3. Refaktorieren Sie die Lese-/Schreibaufteilung api, um die Benutzererfahrung zu verbessern
  4. Entfernen Sie die Check-Duplicate-Table-Enabled-Konfiguration
  5. Entfernen Sie die nutzlose Konfiguration des Konfigurationselements „show-process-list-enabled“.
  6. Skalierung: Schlüsselwort für einen Teil der Datenmigration DistSQL ändern
  7. Skalierung: Teil der Datenmigration DistSQL neu gestalten
  8. DistSQL: Parametertypspezifikation vereinheitlichen
  9. DistSQL: SHOW INSTANCE MODE in SHOW MODE INFO und SHOW INSTANCE INFO aufteilen
  10. DistSQL: Ändern Sie DROP SCALING jobId in CLEAN MIGRATION jobId
  11. DistSQL: Entfernen Sie COUNT INSTANCE RULES
  12. Beim Hinzufügen einer Datenbank wurde festgestellt, dass die Hochverfügbarkeit das Offline-Schalten aller Slave-Bibliotheken unterstützt und die Hauptbibliothek die Konfiguration des Leseverkehrs übernimmt
  13. SnowflakeKeyGenerateAlgorithm unterstützt die Konfiguration der Worker-ID im Standalone-Modus
  14. Ersetzen Sie sourceDataSourceName durch productionDataSourceName in der Shadow-API-Konfiguration
  15. Autorität: Entfernen Sie den veralteten nativen Autoritätsanbieter

  1. ShardingSphere-Metadaten-Refactoring zur Aufteilung tatsächlicher Metadaten und logischer Metadaten
  2. Verwenden Sie ConnectionContext und QueryContext, um ThreadLocal in FetchOrderByValueQueuesHolder, TrafficContextHolder, SQLStatementDatabaseHolder und TransactionHolder zu entfernen
  3. Ändern Sie den Standardwert der ShardingSphere-Proxy-Version im Helmdiagramm
  4. Der Docker-Container wird beendet, wenn ShardingSphere-Proxy nicht gestartet werden konnte
  5. Helm-Charts im ShardingSphere-Repository werden an das Unterprojekt shardingsphere-on-cloud übertragen
  6. Skalierung: Zahlreiche Refaktorierungen für eine bessere Wiederverwendung von Code
  7. DistSQL: Fügen Sie eine neue Kategorie mit dem Namen RUL hinzu
  8. Refaktorieren Sie das Zeitplanmodul und teilen Sie es in einen Cluster-Zeitplan und einen eigenständigen Zeitplan auf
  9. Entfernen Sie den Speichermodus, behalten Sie den Standalone-Modus und den Cluster-Modus bei
  10. Refactoring der Ladelogik für Metadatentabellen und der Persistenzlogik
  11. Refactoring verteilter Sperren, um das prägnanteste Schnittstellendesign beizubehalten
  12. Refactor: Vereinheitlichen Sie die Erstellung von Proxy-Containern in der IT aus ENV-Modulen
  13. Refactor: Vereinheitlichen Sie die Konfiguration für den von testcontainer erstellten Container
