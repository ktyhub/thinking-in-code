Shardingsphere 5.0.0

Neue Funktion

  1. Unterstützt das Parsen von SQL-Kommentaren
  2. Neue DistSQL-Syntax: Schattenregelverwaltung
  3. Neue DistSQL-Syntax: Skalierung der Jobverwaltung
  4. Neue DistSQL-Syntax: Proxy-Instanz deaktivieren
  5. Neue DistSQL-Syntax: Deaktivieren Sie die ReadWrite-Splitting-Lesedatenquelle
  6. Neue DistSQL-Syntax: DROP SHARDING ALGORITHM
  7. Neue DistSQL-Syntax: ALTER RESOURCE
  8. Neue DistSQL-Syntax: CREATE SHARDING ALGORITHM
  9. Neue DistSQL-Syntax: CREATE DEFAULT SHARDING [TABLE | DATABASE] STRATEGY
  10. Neue DistSQL-Syntax: SHOW ALL VARIABLE
  11. Neue DistSQL-Syntax: SHOW VARIABLE variableName;
  12. Unterstützt 3-Modi, einschließlich Speicher-, Standalone- und Cluster-Modus
  13. Proxy unterstützt openGauss
  14. Skalierung: Grundlegende Unterstützung für openGauss hinzufügen
  15. Skalierung: Fügen Sie die SPI-Schnittstelle des inkrementellen Task-Completion-Detect-Algorithmus hinzu
  16. Skalierung: SPI-Schnittstelle für den Datenkonsistenzprüfungsalgorithmus hinzufügen
  17. Skalierung: Grundlegende Unterstützung der automatischen Erstellung einer Tabelle auf dem Ziel für MySQL und openGauss
  18. Skalierung: Unterstützt die automatische Clusterkonfiguration, wenn der Auftrag abgeschlossen ist
  19. Skalierung: Fügen Sie weitere DistSQL-Unterstützung hinzu, z. B. Datenkonsistenzprüfung usw

API Änderung

  1. Fügen Sie die Schemanamenkonfiguration für ShardingSphere-JDBC hinzu
  2. Fügen Sie die Standard-Sharding-Spaltenkonfiguration hinzu
  3. Ändern Sie den Standardautoritätsanbieter von NATIVE in ALL_PRIVILEGES_PERMITTED
  4. Anpassung der SCTL-Syntax, zusammengeführt mit der DistSQL-RAL-Syntax
  5. SHOW RESOURCES DistSQL wird auf SHOW SCHEMA RESOURCES angepasst
  6. Entfernen Sie das logische Feld shadow und unterstützen Sie den Schattenalgorithmus

Verbesserung

  1. Unterstützen Sie das Parsen der MySQL-Union/Union-All-Anweisung
  2. Unterstützt die Anweisung PostgreSQL ABORT
  3. Refactoring und Verbesserung des Metadaten-Ladevorgangs
  4. Unterstützt die Anweisung PostgreSQL CREATE INDEX, um einen Index automatisch zu generieren, wenn kein Index angegeben ist
  5. Unterstützen Sie die Ausführung von SQL-Anweisungen mit logischem Schema
  6. Unterstützt die Konfiguration von Bindungstabellen mit verschiedenen Sharding-Spalten
  7. Optimieren Sie die Kernel-Leistung
  8. Der Proxy unterstützt Abfragen an einen Teil der information_schema-Tabellen, um die client-Verbindungserfahrung zu optimieren
  9. DistSQL unterstützt die Verwendung von Anführungszeichen, um Schlüsselwörter als Parameternamen zu verwenden
  10. Das Passwort in der ADD RESOURCE-Anweisung unterstützt Sonderzeichen
  11. ADD RESOURCE unterstützt benutzerdefinierte JDBC-Parameter und Verbindungspooleigenschaften
  12. DROP RESOURCE unterstützt den optionalen Parameter ignore single tables, der zum Ignorieren einzelner Tabellenregelbeschränkungen verwendet wird
  13. Unterstützen Sie die Verwendung von DistSQL zum Erstellen einer Sharding-Tabellenregel basierend auf Regeln zur Lese-/Schreibaufteilung
  14. Die SHOW DATABASES-Anweisung unterstützt die gleiche Syntax
  15. CREATE SHARDING TABLE RULE unterstützt die Verwendung von Inline-Ausdrücken zur Angabe von Ressourcen
  16. CREATE SHARDING TABLE RULE unterstützt die Konfiguration mit dataNodes
  17. CREATE SHARDING TABLE RULE unterstützt die Wiederverwendung vorhandener Algorithmen
  18. SET VARIABLE, Unterstützung zum Ändern der Proxy-Konfiguration
  19. Protokollerweiterungen von PostgreSQL (z. B. unterstützt Portal, nicht spezifizierter Typ)
  20. Verwendung des Netty-Executors zur Optimierung der Proxy-Leistung in bestimmten Szenarien
  21. Sorgen Sie dafür, dass die Speicherabrufgröße im Proxy strikt konfigurierbar ist
  22. Skalierung: Verbesserung der Unterstützung für PostgreSQL
  23. Skalierung: Unterstützt die gleichzeitige Datenkonsistenzprüfung auf Quell- und Zielseite

Refactor

  1. Refaktorieren Sie die SingleTable-Funktion, um die Verschlüsselung mehrerer Datenquellen zu unterstützen
  2. Passen Sie die persistente Datenstruktur des Statusknotens des Registrierungszentrums an
  3. Entfernen Sie die SQL-Umschreibung von DML für Shadow
  4. Unterstützen Sie das SQL-Routing von DDL für Shadow
  5. Skalierung: Standardimplementierung des inkrementellen Erkennungsalgorithmus für den Abschluss von Aufgaben umgestalten
  6. Skalierung: Standardimplementierung des Datenkonsistenzprüfungsalgorithmus umgestalten
  7. Skalierung: HTTP API und Binärverteilung entfernen

Fehlerbehebung

  1. Korrigieren Sie den Sharding-Intervall-Algorithmus
  2. Behebung der Ausnahme beim Umschreiben der Anweisung SHOW INDEX FROM TABLE FROM TABLE
  3. Behebung der Ausnahme beim Umschreiben von Join-Abfragen für mehrere Tabellen
  4. Beheben Sie die Ausnahme, dass der Unterabfrageindex außerhalb des gültigen Bereichs liegt
  5. Korrigieren Sie das falsche Ergebnis der Oracle-Paging-Abfrage
  6. Beheben Sie die Rewrite-Ausnahme, wenn KeyGenerateStrategy nicht in der Sharding-Funktion konfiguriert ist
  7. Behebung der durch den Oracle-Dialektfall verursachten Federation-Executor-Engine-Ausnahme
  8. Behebung der Ausnahme beim Umschreiben der Sharding- und Encrypt-Integrationsnutzung
  9. Beheben Sie die Ausnahme beim Laden von Oracle-Metadaten
  10. Beheben Sie das Problem, dass die SHOW RESOURCES-Anweisung keine benutzerdefinierten Attribute anzeigen kann
  11. Beheben Sie das Problem, dass keine SQL-Ausführungsausnahme ausgelöst wird
  12. Fix Etcd kann kein Node-Add-Ereignis senden
  13. Fix PostgreSQL Zeilen enthalten möglicherweise einen Nullwert, der im Abfrageergebnis fehlt
  14. Fix: PostgreSQL-Metadatenspalten sind nicht in der richtigen Reihenfolge
  15. Beheben Sie, dass der Zeichensatz client im Proxy möglicherweise falsch ist
