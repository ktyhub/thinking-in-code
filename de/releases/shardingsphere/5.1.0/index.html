API Änderung

  1. Entwerfen Sie die DistSQL-Syntax für die Datenbankerkennung neu
  2. In DistSQL wird das Schlüsselwort GENERATED_KEY an KEY_GENERATE_STRATEGY angepasst
  3. Der native Autoritätsanbieter ist als veraltet markiert und wird in einer zukünftigen Version entfernt
  4. Skalierung: Skalierungskonfiguration von server.yaml nach config-sharding.yaml verschieben
  5. Skalierung: Benennen Sie „clusterAutoSwitchAlgorithm SPI“ in „CompletionDetector“ und „Refactor“-Methodenparameter um
  6. Skalierung: Datenkonsistenzprüfung, Umbenennung der API-Methode und Änderung des Rückgabetyps
  7. Refactoring des Datenbankerkennungsmoduls API
  8. Die Lese-/Schreibaufteilung unterstützt die statische und dynamische Konfiguration
  9. Shadow DB entfernt die Aktivierungskonfiguration
  10. Typ des Schattenalgorithmus geändert

Verbesserung

  1. Verbessern Sie die Leistung beim Laden mehrerer einzelner Tabellen
  2. Entfernen Sie die automatisch hinzugefügte Order by Primary Key-Klausel
  3. Optimieren Sie die Routenlogik der Bindungstabelle, ohne die Spalte in der Join-Bedingung zu teilen
  4. Unterstützt die Aktualisierung des Sharding-Schlüssels, wenn das Sharding-Routing-Ergebnis gleich bleibt
  5. Optimieren Sie die Leistung der Rewrite-Engine
  6. Unterstützen Sie select Union/union all ...-Anweisungen durch die Federation Engine
  7. Unterstützt das Einfügen in die Sharding-Spalte für die Aktualisierung doppelter Schlüssel, wenn der Routenkontext gleich bleibt
  8. Verwenden Sie Union All, um SQL-Routeneinheiten für eine einfache Auswahl zusammenzuführen und so die Leistung zu verbessern
  9. Unterstützt Autocommit im ShardingSphere-Proxy
  10. ShardingSphere openGauss Proxy unterstützt die Authentifizierungsmethode sha256
  11. Entfernen Sie die Eigenschaft java.net.preferIPv4Stack=true aus dem Proxy-Startskript
  12. Entfernen Sie die Überprüfung von Nullregeln für JDBC
  13. Optimieren Sie die Leistung beim Ausführen der openGauss-Batch-Bindung
  14. Deaktivieren Sie den Ressourcenleckdetektor Netty standardmäßig
  15. Unterstützt die Beschreibung der vorbereiteten Anweisung in PostgreSQL / openGauss Proxy
  16. Optimieren Sie die Leistung bei der Ausführung von PostgreSQL-Batch-Einfügungen
  17. Fügen Sie „instance_id“ zum Ergebnis von „SHOW INSTANCE LIST“ hinzu
  18. Unterstützung für die Verwendung von „instance_id“ zum Ausführen von Vorgängen beim Aktivieren/Deaktivieren einer Proxy-Instanz
  19. Unterstützt den automatischen Kreativalgorithmus bei CREATE SHARDING TABLE RULE, wodurch die Schritte zum Erstellen einer Regel reduziert werden
  20. Unterstützung der Angabe eines vorhandenen KeyGenerators bei der Erstellung einer Sharding-Tabellenregel
  21. DROP DATABASE unterstützt die Option IF EXISTS
  22. DATANODES in SHARDING TABLE RULE unterstützt aufgezählte Inline-Ausdrücke
  23. CREATE/ALTER SHARDING TABLE RULE unterstützt komplexe Sharding-Algorithmen
  24. SHOW SHARDING TABLE NODES unterstützt Nicht-Inline-Szenarien (Bereich, Zeit usw.)
  25. Wenn die Lese-/Schreib-Aufteilungsregel nur eine Lesedatenquelle enthält, darf diese nicht deaktiviert werden
  26. Skalierung: Fügen Sie grundlegende Unterstützung für die Konsistenzprüfung von Chunked-Streaming-Daten hinzu
  27. Optimierung der Entscheidungslogik des Schattenalgorithmus zur Verbesserung der Leistung

  2. Vermeiden Sie doppeltes TCL-SQL-Parsing, wenn Sie eine vorbereitete Anweisung im Proxy ausführen
  3. Skalierung: Fügen Sie Pipeline-Module hinzu, um die Skalierung neu zu gestalten
  4. Skalierung: Refactoring mehrerer Jobkonfigurationsstrukturen

  6. Skalierung: Fügen Sie grundlegende Unterstützung für die Wiederverwendung von Pipeline-Kerncode für Verschlüsselungsaufträge hinzu
  7. Skalierung: Fügen Sie grundlegende Unterstützung für die kombinierte Ausführung von Skalierungsjobs und Verschlüsselungsjobs hinzu
  8. Skalierung: Fügen Sie die Konfiguration input und output hinzu, einschließlich workerThread und rateLimiter
  9. Skalierung: Verschieben Sie blockQueueSize in streamChannel
