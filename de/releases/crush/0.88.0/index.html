crush v0.88.0

Minor Veröffentlicht31. Juli 2026 Quellecharmbracelet/crush Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

zerquetsche v0.88.0

.crushrc ist da!

Hey! Ich hoffe, alle hatten eine tolle Woche. Wir waren bei Charm ziemlich produktiv und veröffentlichen heute ein paar coole Sachen.

Bash-Konfiguration! (.crushrc)

Ja, .crushrc ist da! Ihre vorhandene JSON-Konfiguration funktioniert immer noch, aber wir haben gerade mit der Migration auf etwas viel Flexibleres begonnen! Ein Beispiel dafür, warum das cool ist: Wenn Sie die Crush-Konfiguration in einem dotfiles-Repository verwalten, können Sie immer noch maschinenspezifische Überschreibungen vornehmen, indem Sie source verwenden, um eine separate Datei aufzurufen, die sich in Ihrem .gitignore befindet. Ich bin sicher, dass es noch viele andere Anwendungsfälle gibt. Um die vollständige Dokumentation dazu zu lesen, lesen Sie dieses Dokument. Sehen Sie sich einen Ausschnitt an, damit Sie eine Vorstellung davon haben, wie es aussieht:

# Add Ollama.
provider add ollama --type ollama --base-url "http://localhost:11434/v1"

# Register a model on Ollama.
model add ollama/llama3.3 --name "Llama 3.3" --context-window 128000

# Auto-approve some tools.
permissions allow view edit

# Add an MCP server
mcp add github \
  --type http \
  --url "https://api.githubcopilot.com/mcp/" \
  --header Authorization "Bearer $GITHUB_TOKEN"

# Load some extra config
source "$XDG_CONFIG_HOME/squid-config.sh"

# Change config based on the machine you're on.
if [[ $HOSTNAME == "babysquid" ]]; then
    option skill-path "$HOME/squid-skills"
fi

Möchten Sie Feedback geben? Treten Sie dem #crush-Kanal auf [Discord] (https://charm.land/discord) bei.

Bessere AWS Bedrock SSO-Unterstützung

@jan-xyz hat großartige Arbeit geleistet und dieses zum Leben erweckt! Bei der Nutzung von AWS Bedrock über SSO verfallen Token mit der Zeit und müssen aktualisiert werden. Crush verfügt jetzt über eine ordnungsgemäße Konfiguration und Benutzeroberfläche für die Authentifizierung und wird immer dann angezeigt, wenn Token aktualisiert werden müssen. Weitere Informationen hierzu finden Sie unter #2886. <img width="572" height="231" alt="Screenshot 2026-07-31 um 18 04 21" src="https://github.com/user-attachments/assets/993034d2-89d2-42f4-ba9c-30b01a1debd6" />

Zuverlässigerer Agent-Abruf

@sven2718 trug zu besseren Wiederholungsversuchen bei Suchvorgängen bei, wenn diese beim ersten Versuch nicht funktionierten. Suchen werden jetzt zuverlässiger sein, insbesondere wenn viele in kurzer Zeit durchgeführt werden.

Fix für Fable 5

@sven2718 hat auch mit einem Fix für Fable 5 beigetragen. Wenn Anthropic beschließt, Ihre Eingabeaufforderung aus Sicherheitsgründen abzulehnen, wird in Crush jetzt eine ordnungsgemäße Fehlermeldung angezeigt. Vorher hörte Crush einfach auf, ohne den Grund dafür anzugeben.

Crush wird jetzt auf IlluminOS kompiliert

Noch nie von IllumiOS gehört? Keiner von uns bei Charm, aber @timotheosh hat den Code angepasst, um sicherzustellen, dass er jetzt dort kompiliert wird! Go kompiliert in vielen Umgebungen und es macht immer Spaß zu sehen, wie Crush auf mehr Betriebssystemen funktioniert! Wussten Sie übrigens, dass Sie Crush auf Android verwenden können? :Roboter:

Erweitertes MCP-OAuth

In der letzten Version haben wir Unterstützung für die OAuth-Authentifizierung für MCPs bereitgestellt. @BrunoKrugel hat ein paar Korrekturen vorgenommen, damit mehr MCPs, die OAuth erfordern, wie erwartet funktionieren.

Agentische Korrekturen

Auch an Crush als Agent wurden einige Korrekturen vorgenommen. Einige davon wurden auf Fantasy erstellt und zu Crush gebracht.

Neue Hyper-Modelle

Nicht weniger wichtig ist, dass wir weiterhin Updates für Hyper bereitstellen, das stabiler als je zuvor ist und jetzt über Minimax M3 und Qwen3.7-Flash verfügbar ist.

Diese Woche ist viel passiert! Wir wünschen Ihnen viel Spaß und machen weiter so :tm:! Charme
