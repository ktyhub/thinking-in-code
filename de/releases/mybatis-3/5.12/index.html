mybatis-3 mybatis-3.5.12

„Die große Säuberung“

Änderungen mit Auswirkungen auf den Benutzer

  • #2703 Das Verweisen auf Sammlungsparameter anhand des Namens schlägt bei der Behebung von #2693 fehl

  • #2709 Behebung einer Race-Bedingung, die dadurch verursacht wurde, dass andere Threads Mapper-Methoden aufrufen, während zugeordnete Tabellen erstellt werden

  • #2727 Aktivieren Sie die Möglichkeit, eine benutzerdefinierte Konfiguration für XMLConfigBuilder bereitzustellen

  • #2731 Das Hinzufügen von Mapper könnte unter JPMS fehlschlagen

  • #2741 Attribut „affectedData“ zu @Select, @SelectProvider und <select /> hinzufügen

  • #2767 ResultType nach Namespace und ID auflösen, wenn resultType und resultMap nicht bereitgestellt werden

  • #2804 Durchsucht lesbare Eigenschaften beim Auflösen des Konstruktor-Argumenttyps nach Namen

  • Kleinere Korrektur: „boolean“ kann niemals null sein (primativ)

  • Allgemeine Bibliotheksaktualisierungen

  • Verwendet jetzt die Parameteroption für den Compiler (erforderlich für spring boot 3) (für Reflexionsanforderungen)

Codebereinigung

  • #2816 Verwenden Sie Open Rewrite, um Java-Code teilweise zu bereinigen
  • #2817 Private Konstruktoren per offenem Rewrite hinzufügen
  • #2819 Fügen Sie bei Bedarf per offenem Umschreiben das Finale hinzu
  • #2825 Bereinigen, wenn die Anweisung abbricht/Logik zurückgibt
  • #2826 Eclipse-basierte Bereinigung

Bauen

  • #2820 Test-CI-Gruppenprofil zugunsten einer direkteren Verwendung auf GH-Actions entfernen und veraltetes Surefire in der Übersicht in README.md aktualisieren
  • Anpassungen, um so schattierte ognl und javassist zu erstellen, lösen keine Warnungen mehr aus
  • Jetzt auch mit JDK 21-EA erstellen
  • Verschiedene Testbereinigungen, Aktualisierungen und Ergänzungen – Aktivieren Sie die automatische Formatierung des gesamten Java-Codes, einschließlich des Hinweises für Mitwirkende in der Readme-Datei, um die Formatierung in Codeblöcken bei Bedarf zu überspringen – Tests können jetzt JDK 11 verwenden, während die JDK 8-Laufzeit beibehalten wird
  • Pom-Bereinigung / bessere Klärung der Parameter

Dokumentation

  • Verschiedene Dokumentationsaktualisierungen

Für Mitwirkende:

  • Mybatis verwendet jetzt die automatische Formatierung der Codebasis. Wenn der Beitrag eine spezielle Formatierung erfordert, z. B. Anmerkungen oder bestimmte Javadocs, die mit den Formatierungsregeln in Konflikt stehen, verwenden Sie // @formatter:off und // @formatter:on um den Codeblock herum, der bei der Formatierung ignoriert werden soll. Wenn es sich innerhalb eines Javadoc um einen Kommentartyp handelt, ist das Ganze betroffen, also wickeln Sie dies einfach um das gesamte Javadoc. Versuchen Sie sicherzustellen, dass der Code innerhalb des nicht formatierenden Blocks ordnungsgemäß formatiert ist, um ansonsten die Lesbarkeit zu erleichtern.
