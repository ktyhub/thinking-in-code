Hyperframes v0.9.56

HyperFrames v0.9.56

Veröffentlicht am 16.11.2026.

Die Vorschau von Studio und die lokalen Server agieren jetzt nur noch für ihre eigenen Seiten. Der CLI behält seinen Cache, seinen Verlauf und seine Wiederherstellungen im Projekt. Das arm64-Lambda-Image enthält nur den überprüften ffmpeg-Build und große Vorschauen werden schneller erstellt.

Korrekturen

  • Studio-Server: Die Kompositionsdateiserver stellen keine Anmeldeinformationen oder Tool-Statusdateien mehr bereit (014326b40, #7889).
  • Studio Server: Lint und Probe werden nur für Anfragen von Studio-eigenen Seiten ausgeführt (bbac8900e, #7894).
  • Studio Server: Eine Verlaufswiederherstellung bleibt im Projekt und verwendet nur intakte Kopien (478313ba0, #7902).
  • Studio: Die Take-Wiedergabe funktioniert für eine Vorschau, deren Server undurchsichtig gemacht wurde (1e542956d, #7815).
  • Studio: Der Vorschaurahmen behält den Sandbox-Ursprung in seinem Hostsatz bei (b650d0d19, #7886).
  • Studio: Aktuelle Decks werden nur auf ihrer eigenen Site geöffnet und die Vorschau liest nur die Nachrichten ihres eigenen Frames (4067efc45, #7877).
  • Kern: Die Laufzeitbrücke prüft jede Steuernachricht, bevor sie darauf reagiert (97d8f26e7, #7892).
  • CLI: render --docker behält die Seitennetzwerkbeschränkung des Hosts im Container bei (5d8605eb8, #7890).
  • CLI: preview --stop stoppt nur den Prozess, den das System meldet und der den Port hält (ace8a78dc, #7882).
  • CLI: Der Prüfcache wird nur als Projektdatensatz gespeichert, niemals über eine verknüpfte Datei (7801e3ff3, #7884).
  • CLI: Aus dem Projektordner gelesene Verlaufs-Turn-IDs werden überprüft und verschlüsselt gesendet (6efa6b635, #7883).
  • CLI: Catch-up listet nur die Runden auf, die die App nach der Übergabe hinzugefügt hat (0f23f40f8, #7874).
  • CLI: Ein Datensatz empfangener Dateien in einem Ordner unter dem Projekt zählt für ein Rendering (1c159c550, #7900).
  • CLI: Media-use kopiert nur die Soundeffekte seiner gebündelten Indexnamen (ed93a1312, #7895).
  • Mediennutzung: Lokale Modelle beginnen in einem Ordner außerhalb des Projekts (756c2c6c1, #7888).
  • Engine: Ein zwischengespeicherter Browser wird nur verwendet, wenn seine Dateien mit dem angehefteten Build übereinstimmen (56a2d0c53, #7865).
  • Engine: Timeline-Frame-Vorhersagen bleiben innerhalb der Render-Frames (f5a74a567, #7885).
  • Engine: Jede Superset-Extraktion funktioniert in einem eigenen Ordner (a4139e9ea, #7901).
  • Parser: Das Lesen der Breite und Höhe eines Canvas-Gerüsts dauert bei jeder Eingabe genauso kurz (b856a1d63, #7873).
  • Lint: Von Agenten erstellte Szenen und Soundeffekte bleiben auf einer Timeline-Spur (98208241e, #7775).
  • Fähigkeiten: Bei eigenständigen Installationen wird der CLI auch über seinen Launcher ausgeführt (3fc3050bc, #7879).
  • AWS Lambda: Eine Version versendet das arm64-ffmpeg nur, wenn es mit dem neben seinem Build festgeschriebenen Digest übereinstimmt (d9488119b, #7872).

Leistung

  • Kern: Ein Vorschau-Build liest eine große Seite, ohne sie bei jedem Durchgang zu kopieren (082d63683, #7878).
  • Produzent: Kompilierungs- und Render-Telemetrie-Tag-Scans benötigen entsprechend der Seitengröße Zeit (82fdf406c, #7896).

Intern

  • Veröffentlichen: Jede npm-Veröffentlichung wartet auf die npm-publish-Genehmigung (a54de748e, #7870).
  • Veröffentlichen: Vorgefertigte Tarballs werden von einem Job veröffentlicht, der keinen Code aus dem Release-Commit ausführt (af0560c85, #7869).
  • CI: Veröffentlichungsworkflows werden nur für main (7bd6b9daf, #7875) ausgeführt.
  • CI: Testgeräte sehen nicht mehr wie echte HeyGen-Tasten aus, und CI lehnt eines ab, das dies tut (5dc3b336a, #7876).
