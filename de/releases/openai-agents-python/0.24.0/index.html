  • Überprüfungsmodus: Endkandidat, Release Please PR #5285.

Aufruf freigeben

🟢 GRÜNES LICHT ZUM VERSAND. Der vorbereitete 0.24.0-Kandidat hat keinen ungelösten Release-Blocker. Aufgrund der Kompatibilitätsänderungen wurden die unten beschriebenen Migrations- oder Fallback-Pfade unterstützt.

Zusammenfassung des Umfangs

  • 111 Dateien geändert (+15.444/-1.412). Hauptbereiche: Toolausführung und Fehlerwiederherstellung, dauerhafter RunState- und Sitzungsverlauf, Sandbox-Sicherheit, Ablaufverfolgung, Beispiele, Abhängigkeiten und Release-Metadaten.
  • Der Kandidat enthält den aktuellen Haupt- und #5335. Änderungen, die über „main“ hinausgehen, sind auf Release-eigene Metadaten beschränkt.

  1. Leiten Sie betroffene gespeicherte Läufe an ihren ursprünglichen SDK- und Agentencode weiter.
    • Risiko: 🟢 NIEDRIG, mit erforderlicher Upgrade-Vorsichtsmaßnahme. Einige zuvor lesbare Prüfpunkte schlagen jetzt sicher fehl, anstatt das Risiko eines falschen Agentenbesitzes einzugehen.
  • Beweis: Der Autor geht vom Schema 1.18 zum Schema 1.21 über. Der Leser lehnt bestimmte ältere Diagramme mit gleichnamigen Nicht-Root-Agenten ab, deren gespeicherte Identitätsreihenfolge von Hook-Attributen abhängen könnte, selbst wenn diese Attribute unverändert blieben. Die neue Identitätsgenerierung schließt alle Hook-Instanzattribute aus und behält den Hook-Typ bei. Diagramme, die nur durch diese Attribute unterscheidbar sind, können nicht serialisiert werden. Andere unterstützte historische Schemata bleiben lesbar.
    • Dateien: src/agents/run_state.py, src/agents/_run_state_agent_identity.py, tests/test_run_state.py. – Aktion: Beenden Sie betroffene Legacy-Aufgaben mit dem ursprünglichen SDK, den unveränderten Agentendefinitionen und der Hook-Reihenfolge, die beim Schreiben des Snapshots verwendet wurden. Verwenden Sie eindeutige Agentennamen, bevor Sie neue dauerhafte Läufe starten. Benennen Sie ein gespeichertes Diagramm nicht um und ändern Sie nicht seine Schemabezeichnung, um eine Migration zu erzwingen. Ältere SDKs können neue 1.21-Snapshots nicht lesen.

  1. Aktualisieren Sie vorhandene benutzerdefinierte Tool-Fehlerformatierer für eine dritte Kategorie. – Risiko: 🟢 NIEDRIG, mit einer expliziten Migration für umfassende Rückrufe. Ein Formatierer, der jede Nichtablehnung als fehlendes Werkzeug behandelt, kann jetzt irreführenden Text für eine abgestürzte Funktion zurückgeben.

    • Beweis: ToolErrorFormatterArgs.kind fügt "tool_exception" hinzu; das optionale Feld error wird angehängt. Der laufweite Rückruf behandelt jetzt mögliche Fehler bei dekorierten Funktionen. Explizite Pro-Tool-Handler, einschließlich expliziter None oder des Standardhandlers, behalten Vorrang. Werksseitig erstellte MCP- und Agent.as_tool-Fehler, Zeitüberschreitungen, Abbrüche und schemagestützte Programmaufrufe behalten ihr separates Verhalten.

Halten Sie Ausnahmedetails aus der für das Modell sichtbaren Ausgabe fern, sofern sie nicht absichtlich bereinigt werden. Ohne benutzerdefinierten Formatierer bleibt das Standardverhalten unverändert.

Vom Server verwaltete Konversationen behalten ihren separaten Wiederherstellungspfad. Ausstehende Schreibvorgänge behalten die Sitzungsidentität und den Komprimierungsstatus bei. Die automatische Komprimierung wartet auf ausstehende Genehmigungen. Der eigenständige Redis-Ersatz verwendet eine Transaktion. Conversations-Schreibvorgänge verwenden Stapel von höchstens 20 Elementen und können teilweise über mehrere Anfragen hinweg festgeschrieben werden.

Nach einer teilweisen Konversation müssen Sie den Remote-Verlauf überprüfen und reparieren, bevor Sie es erneut versuchen. Senden Sie die vollständige Liste nicht erneut, solange ein früherer Teil gespeichert bleibt. Andere Autoren koordinieren; Die atomare Ersetzung Redis verhindert nicht die veraltete Komprimierung über Prozesse hinweg. Redis Cluster-Lesevorgänge und -Popups bleiben weiterhin verfügbar, aber für das Anhängen, Löschen und Ersetzen von Transaktionen ist ein unterstütztes Backend erforderlich. Fehler bei der Terminalausgabe sind nicht wiederholbar.

Entwurf der wichtigsten Änderungen

Wichtige Änderungen

0.24.0 fügt laufweite Funktionsfehlerformatierung und MCP-Erkennungsanmerkungen hinzu und verbessert die Wiederherstellung, Sandbox-Sicherheit und Ablaufverfolgung. Diese Nebenversion enthält Kompatibilitätsänderungen für benutzerdefinierte Fehlerrückrufe und einige gespeicherte Agentendiagramme. Sehen Sie sich vor dem Upgrade die ersten beiden Highlights an.

Highlights:

  • Benutzerdefinierte Fehlerformatierer aktualisieren. RunConfig.tool_error_formatter kann kind="tool_exception" und optional error empfangen. Behandeln Sie die neue Art oder geben Sie None zurück, um die Standardnachricht beizubehalten. Explizite Pro-Tool-Handler behalten Vorrang. Nicht konfigurierte Standardeinstellungen bleiben unverändert.
  • Planen Sie Upgrades rund um gespeicherte Läufe. Neue RunState-Snapshots verwenden das Schema 1.21. Beenden Sie betroffene ältere gleichnamige Agentendiagramme auf ihrem ursprünglichen SDK. Behalten Sie den Agentencode und die ursprüngliche Hook-Reihenfolge bei. Verwenden Sie eindeutige Agentennamen für neue dauerhafte Läufe. Das Umbenennen eines gespeicherten Diagramms ist keine Migration.
  • Abgeschlossene Arbeiten zuverlässiger wiederherstellen. Der verzögerte Genehmigungsverlauf, abgeschlossene Tool-Ausgaben, Aliase und der Komprimierungsstatus bleiben unterstützten Wiederherstellungspfaden erhalten. Die automatische Komprimierung wartet auf Genehmigungen. Redis ersetzt den Verlauf atomar auf unterstützten eigenständigen clients. Bei angehängten Gesprächen wird das Anforderungslimit von 20 Elementen eingehalten. Gleichen Sie teilweise Schreibvorgänge ab, bevor Sie es erneut versuchen.
  • Lokale Ausführung und Anzeige härten. macOS-Sandbox-Befehle verweigern Launch Services-Anfragen. Sandbox-Tools stellen ungültige Modellargumente wieder her. Bei geschützten Mountfehlern bleiben Aufrufer-Ausnahmedaten erhalten, während der abgefangene Traceback getrennt wird. Die Echtzeit-Demo zeigt Tool-Inhalte als Text an.
  • Ehren Sie die Nachverfolgungsoptionen durch Wiederaufnahme und Bereinigung ein. Das Deaktivieren der Nachverfolgung pro Lauf gilt innerhalb der Anruferverfolgungen, und genehmigte wiederaufgenommene Tools werden an die wiederaufgenommene Agentenspanne angehängt.
  • Verwenden Sie umfangreichere Integrationsbeispiele und Metadaten. MCP-Tools stellen optionale mcp_annotations als Erkennungshinweise bereit. Neue Entscheidungsrezepte demonstrieren Klassifizierung, Routing und Toolüberprüfung mit OpenAI >=3.26.0,<4. Sie verwenden einen separaten client, ​​keinen Agentenmodelladapter.
  • Optionale Abhängigkeitssperren aktualisieren. Das Temporal-Extra verwendet temporalio==1.34.0; Das Vercel-Extra unterstützt vercel-sandbox>=0.7.0,<0.9. Die Mindestanforderungen für Core Python und OpenAI SDK bleiben unverändert.

Vielen Dank an @masasron für die Meldung des in #5335 behobenen lokalen macOS-Sandbox-Problems.
