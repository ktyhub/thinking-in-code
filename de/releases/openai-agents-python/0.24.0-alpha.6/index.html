openai-agents-python v0.24.0-alpha.6

Pre-Release Veröffentlicht3. Nov. 2026 Quelleopenai/openai-agents-python Englisches Original

openai-agents-python v0.24.0-alpha.6

Installieren Sie die Vorschau

Verwenden Sie den Standard CPython 3.10–3.14 in einer virtuellen Umgebung. Diese Räder umfassen die native Laufzeit; Es ist keine Rust-Toolchain oder Quellcode-Erstellung erforderlich. Diese Vorschau wird über GitHub Releases verteilt, nicht über PyPI.

Führen Sie den Befehl für Ihre Plattform aus:

Linux x86_64 (glibc 2.39 oder neuer)

python -m pip install "https://github.com/openai/openai-agents-python/releases/download/v0.24.0-alpha.6/openai_agents-0.24.0a6-cp310-abi3-manylinux_2_39_x86_64.whl"

macOS 11 oder neuer auf Apple Silicon

python -m pip install "https://github.com/openai/openai-agents-python/releases/download/v0.24.0-alpha.6/openai_agents-0.24.0a6-cp310-abi3-macosx_11_0_arm64.whl"

Windows x64

python -m pip install "https://github.com/openai/openai-agents-python/releases/download/v0.24.0-alpha.6/openai_agents-0.24.0a6-cp310-abi3-win_amd64.whl"

Für Intel Macs, ARM Linux, ARM Windows, Alpine/Musl, PyPy oder Free-Threaded Python werden keine Räder bereitgestellt. Die cp310-abi3-Dateinamen unterstützen auch den Standard CPython 3.11–3.14.

Überprüfen Sie die installierte Version und das native Modul:

python -c "from importlib.metadata import version; import agents._native; print(version('openai-agents'))"

Erwarten Sie 0.24.0-alpha.6 oder die entsprechende Verpackungsschreibweise Python, 0.24.0a6. SHA256SUMS enthält Prüfsummen für alle drei Räder.

Release notes

Änderungen seit 0.24.0-alpha.5. Diese Vorschau erweitert die Konversationssteuerung, die Statuswiederherstellung und die Tool-Richtlinien und umfasst öffentliche API-Änderungen.

Hinzugefügt

  • Steuern Sie eingereichte Arbeiten über ein erfasstes Turn mit get_result(), passivem events(), manueller Anforderungsbearbeitung, Steuerung und Stornierung. Stellen Sie Eingabeaufforderungen mit Session.submit(..., if_busy="queue") in die Warteschlange oder steuern Sie den aktiven Turn mit if_busy="steer". – Fügen Sie LocalStorage hinzu, um Konversationen aus einem lokalen Profil erneut zu öffnen, und erweitern Sie die tragbare SessionState-Erfassung und -Wiederherstellung. Fügen Sie Leerlauf-Forks, vom Anrufer bereitgestellte Komprimierungszusammenfassungen und Überprüfungen auf Funktionsunterstützung und Checkpoint-Bereitschaft hinzu. LocalStorage-Profile können keine tragbaren Prüfpunkte exportieren. – Fügen Sie NativeOutput für native strikte Ausgabe und PromptedOutput für JSON hinzu, validiert in Python. Der optionale max_retries führt begrenzte Korrekturen ohne Werkzeuge oder Wiederholung der Aufgabe durch. LocalStorage erfordert max_retries=0.
  • Bearbeitung manueller Werkzeuganfragen in Echtzeit und Wiederaufnahme unterstützter ausstehender Anfragen von Kontrollpunkten. Fügen Sie experimentelle Wiederherstellung externer Jobs über agents.experimental.deferred und einen optionalen MCP-Tasks-Adapter hinzu.
  • Wählen Sie Werkzeuge für jede Einreichung oder jeden Modellschritt innerhalb der Eröffnungsberechtigungen der Sitzung aus. Fügen Sie native Websuche, native Checklisten für Kinder und native Ziele für lokale Speichersitzungen hinzu. – Validieren Sie die Rückgabeanmerkungen des Python-Tools und fügen Sie Tool-Richtlinien zur Überprüfung von Argumenten und Ergebnissen hinzu. Erweitern Sie die native MCP-Unterstützung durch Argumentersetzung, Ergebnistransformationen und anwendungsverwaltete Formular- und URL-Interaktionen über unterstützte HTTP-, Standard- und Modell-WebSocket-Pfade. – Fügen Sie NetworkPolicy für native Befehle auf unterstützten Linux- und macOS-Executoren hinzu, vorbehaltlich der Netzwerk- und Unix-Socket-Beschränkungen der jeweiligen Plattform. Verwalten Sie die Lebensdauer von Remote-Executoren über ein Environment, das beim Öffnen einer Sitzung oder beim Ausführen eines Agenten bereitgestellt wird.
  • Aktivieren Sie native Kindergenehmigungen und Formularanfragen mit NativeAgents(interactions=True). Kinder teilen weiterhin die Tools und den Anwendungskontext der Sitzung.
  • Konfigurieren Sie den nativen OpenTelemetry-Export und überprüfen Sie typisierte Beobachtungen. NativeError stellt jetzt verfügbare Anbieterstatuscodes, Fehlercodes, Anforderungs-IDs und Fehlerkategorien bereit.
  • Testen Sie echte SDK-Sitzungen und Python-Tools anhand lokaler Skriptantworten mit agents.testing.ScriptedResponses, ohne Live-Modell oder API-Schlüssel.

API ändert sich

  • Verwenden Sie Agent.run() oder Agent.run_sync() für einmalige Anrufe. Die redundanten Runner-Aliase wurden entfernt.
  • Ersetzen Sie Turn.wait() und Session.wait() durch Turn.get_result() in der eroberten Runde.
  • Ersetzen Sie Session.interrupt() durch Turn.cancel() für einen Root-Turn oder Session.cancel_all() für die gesamte Sitzung.
  • Benennen Sie Subagent.submit() in Subagent.start() um. Vereinheitlichen Sie Python-Rückrufe und manuelle Tools unter FunctionTool. Entfernen Sie die separate ManualTool-Deklaration.
  • Agentenerklärungen sind unveränderlich. Erstellen Sie einen neuen Agenten, um Standardeinstellungen zu ändern, verwenden Sie with_output_type() für eine Ausgabetypvariante oder verwenden Sie unterstützte Sitzungsaktualisierungen im Leerlauf für eine offene Konversation. – Die Toolauswahl und Sitzungsaktualisierungen können die beim Öffnen der Sitzung erfassten Berechtigungen nicht erweitern. Für wiederhergestellte Sitzungen werden aktuelle Anwendungstools, Anmeldeinformationen und Richtlinien verwendet.

Behoben

  • Halten Sie das Ergebnis jeder erfassten Runde über akzeptierte Steuerung, native Fortsetzungen und spätere Übermittlungen hinweg stabil. Behalten Sie einmalige manuelle Prüfpunkte, übereinstimmende Interaktionsantworten und den Ausgabe-Reparaturstatus über unterstützte Speicher- und Wiederherstellungsgrenzen hinweg bei.
  • Verbessern Sie die native untergeordnete Stornierung und Sitzungsbereinigung. Stoppen Sie die native Arbeit, wenn Ergebnisrichtlinien ablaufen, und behalten Sie die Gründe für Richtlinienfehler bei, wenn Sie Stamm- und untergeordnete Ergebnisse melden. – Lehnen Sie fehlerhafte Python-Tool-Ergebnisumschläge ab und bewahren Sie Serverfehler durch MCP-Ergebnistransformationen. Unterstützt verschachtelte OpenAI-Erweiterungsformulare und HTTP-Telemetrieexport mit client-Zertifikaten.

Dokumentation und Beispiele

– Verschieben Sie die Vorschauquelle in das öffentliche Repository. Konzentrieren Sie sich bei der Installationsanleitung auf vorgefertigte Räder und verschieben Sie die Bauanweisungen von SDK auf CONTRIBUTING.md.

  • Fügen Sie Beispiele für Browseranwendungen, AG-UI-Streaming, verzögerte Jobs, Auswertung, Beobachtbarkeit und allgemeine Anwendungsaufgaben hinzu. Entfernen Sie Migrationshandbücher aus der Vorschaudokumentation.
