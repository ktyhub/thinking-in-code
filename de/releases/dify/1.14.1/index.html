🚀 Was ist neu in v1.14.1?

v1.14.1 ist eine Patch-Version, die sich auf Sicherheitshärtung, Workflow- und Wissensdatenbankstabilität, Bereitstellungsbereinigung und weitere Migration der UI-Plattform nach v1.14.0 konzentriert.

🔐 Sicherheit

  • Selbstgehostete SECRET_KEY-Härtung – Docker-Bereitstellungen sind nicht mehr auf einen öffentlichen Standardschlüssel angewiesen. Wenn SECRET_KEY leer bleibt, generiert API einen Laufzeitschlüssel und speichert ihn über das konfigurierte Speicher-Backend, während explizit konfigurierte Schlüssel weiterhin wie zuvor funktionieren. Danke @laipz8200 in #36049.
  • Endpunktschutz für interne Metriken – /threads und /db-pool-stat sind gehärtet, um eine unbefugte Offenlegung interner Laufzeit- und Datenbankpooldetails zu verhindern. Danke @orbisai0security in #35665.
  • Konto- und Tool-Isolierung – ein IDOR-Problem in GET /account/avatar wurde behoben und die Bereinigung der standardmäßigen Anmeldeinformationen des integrierten Tools auf den aktuellen Mandanten beschränkt. Danke @NeatGuyCoding und @GareArc in #35771 und #35887.
  • Abhängigkeitssicherheit – LiteLLM für CVE-2026-42208 aktualisiert und mehrere Backend-Abhängigkeiten aktualisiert, darunter urllib3-, gunicorn-, gitpython-, mako-, Google SDK-Pakete, Speicherbibliotheken und OpenTelemetry-Exportpakete. Danke @crazywoola in #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017 und #36050.

🧩 Workflow, HITL und App-Laufzeit

  • Workflow-Stabilität – Das Laden der Workflow-Version über das Backend API wurde wiederhergestellt, Online-Benutzerabfragen für große App-Listen behoben, Beobachterschleifen zur Größenänderung der Vorschau verhindert und Schemamodellkollisionen in Test-Workflows vermieden. Danke @hjlarry und @lyzno1 in #35817, #35786, #35936 und #36061.
  • Verfeinerung des Workflow-Authorings – Verhalten der Variablenreferenzauswahl für Untervariablen, Überlauf des Workflow-Knotentitels, Popovers von Bedingungsoperatoren, Semantik der Workflow-Checkliste und Feldauswahl für KB-Metadatenfilter korrigiert. Vielen Dank an @iamjoel, @hjlarry, @lyzno1 und @shawny011717 in #35732, #35740, #35828, #36006 und #34149.
  • Korrektheit der Workflow-Ausführung – beibehaltene Einzellauf-Eingabevariablentypen, korrigierte structured_output_enabled-Validierung, korrigierte Dateivorschau-URL-Verarbeitung in der Knotenausgabeanzeige und entsperrte Plug-in-Modellauswahltools für v1.14.0-Workflows. Vielen Dank an @Jingyi-Dify, @fatelei, @shawny011717 und @sawyer-shi in #35710, #35747, #34150 und #35794.
  • Menschlicher Input – ausgewählte Aktionswerte für Human-in-the-Loop-Flüsse verfügbar gemacht. Danke @Blackoutta in #35451.
  • Fragenklassifizierer – bearbeitbare Klassenbezeichnungen hinzugefügt. Danke @Blackoutta in #35430.

  • Dokumentindizierung – leere Dokumente vor der Vektoreinbettung überspringen und fehlende Textindizierungstechniken validieren. Danke @princepal9120 und @juyua9 in #35763 und #35941.

Upgrade-Anleitung

Wichtige Hinweise

– Diese Version beinhaltet eine neue Datenbankmigration für konfigurierbare Explore-App-Kategorien. Führen Sie im Rahmen des Upgrades Datenbankmigrationen durch. – Docker Compose-Umgebungsvariablen werden jetzt in kategorisierte Dateien unter docker/envs/** aufgeteilt. Wenn Sie ein angepasstes docker-compose.yaml oder .env verwalten, überprüfen Sie das neue Layout und wenden Sie die lokalen Anpassungen erneut sorgfältig an. – Bei selbstgehosteten Bereitstellungen werden explizit konfigurierte SECRET_KEY-Werte weiterhin berücksichtigt. Wenn SECRET_KEY leer ist, generiert und speichert Dify jetzt automatisch einen Laufzeitschlüssel.

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre benutzerdefinierten docker-compose YAML- und env-Dateien.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Holen Sie sich den neuesten Code aus dem Release-Zweig oder Tag.

    git fetch --tags
git checkout 1.14.1

  3. Stoppen Sie den Dienst. Bitte im Verzeichnis docker ausführen.

    docker compose down

  4. Daten sichern.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Überprüfen Sie das neue docker/envs/**-Env-Dateilayout und wenden Sie alle lokalen Anpassungen erneut an.

  6. Upgrade-Dienste.

    docker compose up -d

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und den Web-Frontend-Server.

  2. Holen Sie sich den neuesten Code aus dem Release-Tag.

    git fetch --tags
git checkout 1.14.1

  3. Aktualisieren Sie die Python-Abhängigkeiten.

    cd api
uv sync

  4. Führen Sie das Migrationsskript aus.

    uv run flask db upgrade

  5. Starten Sie den API-Server, den Worker und den Web-Frontend-Server neu.
