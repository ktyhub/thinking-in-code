Was hat sich geändert?

Neue Funktionen

Werkzeug-Mehrfachauswahl-Eingabe – Workflow-Tool-Knoten unterstützen jetzt Dropdown-Eingaben mit Mehrfachauswahl, sodass Benutzer beim Konfigurieren von Tool-Parametern mehrere Werte aus einer vordefinierten Liste auswählen können. (#39346)

Workflow-Knoten-Locator – Sie können jetzt eine node_id in Workflow-Ausführungsprotokollen oder Fehlermeldungen markieren, um den entsprechenden Knoten im Workflow-Editor-Canvas zu finden und hervorzuheben. (#38187)

Verbesserungen der Workflow-Blockauswahl – Das Blockauswahlfeld bietet jetzt eine verbesserte Tastaturnavigation, Kategorievorschauen und ein intuitiveres Sucherlebnis beim Hinzufügen von Knoten zu Workflows. (#39212)

Agent-DSL aus der Seitenleiste exportieren – Agent-Apps können jetzt als DSL YAML direkt aus dem App-Seitenleistenmenü exportiert werden, was die Sicherung oder Versionskontrolle von Agent-Konfigurationen erleichtert. (#39299)

Wissensverfolgung – Es wurden mehr Beobachtbarkeitsspuren zu Wissens-/RAG-Dokumentverarbeitungsvorgängen hinzugefügt, wodurch die Sichtbarkeit der Indexierungspipelines verbessert wurde. (#38959)

  • Lazy-Load-Loro-Collaboration-Laufzeit, um die anfängliche Bundle-Größe zu reduzieren (#39631) – Knoteneinstellungsfenster nicht öffnen, wenn clieinen Knoten im Kommentarmodus anklickt (#39500) – Aktives Kommentarfeld nicht schließen, wenn ein anderer Kommentar gelöst wird (#39491)

Sicherheitsverbesserungen

– Die lokale Sandbox des Agenten läuft jetzt hinter einem dedizierten Squid-Forward-Proxy mit strengen ACL-Regeln, wodurch verhindert wird, dass die Sandbox interne Dienste direkt erreicht. Nur der Endpunkt /files/ auf API und /agent-stub/ auf agent_backend sind zulässig, beide geschützt durch kurzlebige Zugriffstoken. Dadurch wird der Explosionsradius der Ausführung willkürlichen Codes in der Agent-Sandbox erheblich reduziert. (#39544) – Die Kommunikation zwischen dem Dify API und dem Agent-Backend verwendet jetzt eine tokenbasierte Authentifizierung über DIFY_AGENT_API_TOKEN / AGENT_BACKEND_API_TOKEN, wodurch die interne Servicegrenze gestärkt wird. (#39622) – Das Jinja2-Vorlagen-Rendering wurde auf die Verwendung von SandboxedEnvironment umgestellt, um Vorlageneinschleusungsangriffe in Workflow-Code-Knoten zu verhindern (#39609) – Gepatchte DoS-Schwachstelle in React Server Components (#39539) – re.fullmatch im E-Mail-Validator verwendet, um nachfolgende Zeilenumbrüche abzulehnen und so Bypass-Angriffe zu verhindern (#39320) – Validierter Kontostatus vor der Annahme von Workspace-Einladungen (#39438)

Leistung

  • Leichter Endpunkt für aktuelle Apps – Der neue Endpunkt GET /console/api/apps/recent reduziert die Latenz im Abschnitt „Arbeit fortsetzen“ auf der Startseite um ca. 69 % (3.2× schneller), wodurch SQL-Abfragen von 19+ auf 1 Projektions-SELECT und Antwortgröße um ca. 50 % reduziert werden (#39625)
  • Lazy-Load Home-Erstellungsmodalitäten – Das Laden des Erstellungsmodalcodes wird bis zur Interaktion verzögert, wodurch das anfängliche JavaScript-Bundle reduziert wird (#39634)

Verbesserungen

  • Verbesserte Benutzeroberfläche für die Workflow-Blockauswahl (#39377)

Neue Variablen

| Variable | Standard | Beschreibung | |----------|---------|-------------| | DIFY_AGENT_API_TOKEN | dify-agent-run-token-for-dev-only | Gemeinsames Bearer-Token für die Authentifizierung API → agent_backend. Ändern Sie dies in der Produktion. | | AGENT_BACKEND_API_TOKEN | dify-agent-run-token-for-dev-only | Gleiches Token auf der Agent-Backend-Seite. Muss mit DIFY_AGENT_API_TOKEN übereinstimmen. | | PLUGIN_MODEL_PROVIDERS_CACHE_ENABLED | true | Auf false setzen, wenn Plugins extern installiert werden und der Cache nicht ungültig gemacht werden kann. |

[!IMPORTANT] DIFY_AGENT_API_TOKEN ist eine neue erforderliche Variable für die sichere Kommunikation zwischen dem Dify API und dem Agent-Backend. Der Standardwert (dify-agent-run-token-for-dev-only) ist unsicher und muss in der Produktion ersetzt werden. Generieren Sie eines mit:

python -c 'import secrets; print(secrets.token_urlsafe(32))'

Stellen Sie auf der Agent-Backend-Seite den gleichen Wert wie AGENT_BACKEND_API_TOKEN ein.

Ein neuer agent_ssrf_proxy-Dienst (Squid) wird hinzugefügt. – Bearer-Authentifizierung: AGENT_BACKEND_API_TOKEN/DIFY_AGENT_API_TOKEN werden jetzt an die Dienste api, worker und agent_backend übergeben.
  • Bild-Tags auf 1.16.1 aktualisiert.

Upgrade-Anleitung

Modelltypmigration

[!IMPORTANT]

Einmalige Migration des Legacy-Modelltyps für selbst gehostete Upgrades

Wenn diese Bereitstellung von einer Dify-Version vor 1.15.0 aktualisiert wurde und diese Migration noch nicht angewendet wurde, führen Sie sie nach dem Upgrade aus.

Diese Migration ist nicht in flask db upgrade enthalten. Ohne sie können ältere Modelldatensätze dazu führen, dass modellbezogene API-Anfragen mit Fehlern fehlschlagen und betroffene Modelle nicht geladen oder verwendet werden können.

Sichern Sie die Datenbank, bevor Sie die Migration anwenden. Der Befehl wird standardmäßig im Probelaufmodus ausgeführt. Überprüfen Sie die Ausgabe, bevor Sie sie mit --apply erneut ausführen. Die Migration ist idempotent und kann sicher wiederholt werden.

Docker Verfassen

Aus dem Verzeichnis docker ausführen.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Quellcode-Bereitstellung

Nach Abschluss von flask db upgrade vom Repository-Stamm ausführen.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Führen Sie nach der Migration den Befehl „Probelauf“ erneut aus. Wenn keine weiteren Zeilenaktualisierungen oder -löschungen gemeldet werden, starten Sie die entsprechenden Dienste neu und überprüfen Sie, ob vorhandene Modelle erfolgreich geladen und aufgerufen werden können.

Docker Verfassen (empfohlen)

cd docker
docker compose down
git pull origin main
docker compose pull
docker compose up -d

Die Datenbankmigrationen werden beim Start automatisch ausgeführt.

[!IMPORTANT] Überprüfen Sie die neue Variable DIFY_AGENT_API_TOKEN in .env. Der Standardwert ist unsicher – generieren Sie ein sicheres Token für die Produktion:

python -c 'import secrets; print(secrets.token_urlsafe(32))'

Quellcode

git pull origin main
cd api
flask db upgrade
