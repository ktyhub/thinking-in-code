Einführung von Dify Agent (Experimentell): Eine neue Agentenerfahrung in Dify

[!WARNUNG] Sie sollten Dify Agent-Dienste ⚠️nur für trusted, nicht böswillige Benutzer⚠️ bereitstellen.

Wie viele von Ihnen wissen, hat das Shell-basierte LLM-Agentenparadigma einen großen Sprung in den Fähigkeiten der Agenten gebracht und unsere Einstellung zu Agenten verändert. Mittlerweile bieten Skills eine standardisierte Möglichkeit zum Paketieren und Verteilen von Funktionen, wodurch es einfacher wird, leistungsstarke Agenten zu erstellen.

Heute führen wir Dify Agent experimentell ein. Wie andere führende Agenten läuft es in einer Linux-Sandbox. Diese Version enthält:

  • Ein Builder zum Erstellen von Dify-Agenten

    • Sie können Dify-Agenten über die Benutzeroberfläche erstellen: Legen Sie eine Basisaufforderung fest, laden Sie Fähigkeiten und Dateien hoch und verbinden Sie Tools und Wissen aus dem Dify-Ökosystem.
    • Wir stellen auch einen Agenten zur Verfügung, der Sie bei der Erstellung von Dify-Agenten unterstützt. Durch Konversation kann er die Linux-Sandbox-Umgebung konfigurieren, erforderliche Pakete installieren und neue Fähigkeiten und Dateien erstellen, die Ihr Dify-Agent später verwenden kann.

  • Dify-Workflow-Integration für Dify Agent

    • Sie können einen vorhandenen Dify-Agenten in einem Dify-Workflow verwenden oder vorübergehend einen Inline-Dify-Agenten erstellen. Es führt die vom Workflow-Knoten definierte Aufgabe aus, generiert die erforderliche Ausgabe und übergibt sie an den nächsten Knoten.

  • Ein neues Web-App-Erlebnis

    • Der von Ihnen erstellte Dify Agent kann als Web-App veröffentlicht und verwendet werden. Während die Benutzererfahrung vertraut bleibt, wird sie jetzt von Dify Agent unterstützt.

Dokumente: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

Einschränkungen

Bitte beachten Sie, dass in der aktuellen experimentellen Version alle Dify-Agenten in derselben Sandbox laufen. Das bedeutet:

  • Unter normalen Umständen konfiguriert jeder Dify-Agent seine Umgebung und führt Aufgaben in seinem eigenen Arbeitsbereich aus, ohne andere zu beeinträchtigen.
  • Mit einfachen Anweisungen kann jedoch jeder Dify-Agent die Umgebungen und Daten anderer Dify-Agenten, einschließlich Benutzerdaten, lesen oder in sie eingreifen.

Die strikte Isolierung wird in einer zukünftigen Version implementiert. Im Moment

[!WARNUNG] Sie sollten Dify Agent-Dienste ⚠️nur für trusted, nicht böswillige Benutzer⚠️ bereitstellen.

Da Dify Agent noch nicht vollständig bereit ist, stellen Sie möglicherweise fest, dass einige Funktionen für Dify Agent nicht verfügbar sind. Beispielsweise ist der Dify Workflow DSL-Export nicht verfügbar, wenn der Workflow Knoten enthält, die auf Dify Agent verweisen.

Upgrade-Anleitung

[!IMPORTANT]

– Diese Version enthält neue Datenbankmigrationen. Führen Sie sie als Teil des Upgrades aus.

  • Umgebungsvariablen geändert. Sehen Sie sich den Abschnitt „Änderungen der Umgebungsvariablen“ an und aktualisieren Sie Ihr .env entsprechend.
  • Docker Compose-Konfigurationsdateien geändert. Wenn Sie ein angepasstes docker-compose.yaml verwalten, überprüfen Sie die Änderungen und wenden Sie die lokalen Anpassungen sorgfältig erneut an.

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre benutzerdefinierten docker-compose YAML- und env-Dateien. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Holen Sie sich den neuesten Code für die 1.16.0-rc1-Version. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Stoppen Sie die Dienste (führen Sie sie im Verzeichnis docker aus). 
    docker compose down
  4. Daten sichern. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Überprüfen Sie alle Änderungen an der Umgebungsdatei und wenden Sie die lokalen Anpassungen erneut an.
  6. Upgrade-Dienste. 
    docker compose up -d

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und den Web-Frontend-Server.
  2. Holen Sie sich den neuesten Code für die 1.16.0-rc1-Version. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Aktualisieren Sie die Python-Abhängigkeiten. 
    cd apiuv sync
  4. Führen Sie Datenbankmigrationen durch. 
    uv run flask db upgrade
  5. Starten Sie den API-Server, den Worker und den Web-Frontend-Server neu. Um mit der neuen Agentenfunktion zu experimentieren, müssen Sie außerdem dify-agent und Shellctl starten. Wichtig: Shellctl enthält keine integrierte Authentifizierung – aus Sicherheitsgründen wird dringend empfohlen, es in einem Container auszuführen.
