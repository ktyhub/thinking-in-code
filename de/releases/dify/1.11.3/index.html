🚀 Was ist neu in v1.11.3?

Unsere neueste Version, v1.11.3, bietet Ihnen eine Reihe von Fehlerbehebungen und Funktionen, die sich auf Leistung, Funktionalität und Benutzererfahrung konzentrieren. Hier sehen Sie, was sich geändert hat:

🎬 Neue Funktionen

  • MCP-Tool-Verbesserungen: Unterstützung für embeddedResource hinzugefügt und MCP-Tools wurden direkt angezeigt, damit @IthacaDream und @fatelei in #30261 und #30019 schneller darauf zugreifen können.
  • Batch-Vorgänge: Neuindizierungsvorgang in Dokument-Batch-Vorgängen von @fatelei in #30275 eingeführt.
  • Agent- und Workflow-Updates: Neuer AgentMaxIterationError und Verbesserungen bei App-Modus-Prüfungen machen Workflows und Agents robuster von @fatelei.
  • OAuth-Integration: Die Frontend-Anmeldung unterstützt jetzt das Flag oauth_new_user von @zyssyz123 in #30370.
  • PDF-Extraktion: Verbesserter RAG-Extraktor zur Unterstützung der Bildextraktion aus PDFs von @yangzq50 in #30399.
  • Speicher und Archiv: Archivspeicher client und Konfigurationseinstellungen von @hjlarry in #30422 hinzugefügt.
  • Übersetzung und Internationalisierung: Erste RSC-Unterstützung für Übersetzungen für ein globales Publikum von @hyoban in #30596 hinzugefügt.

🛠️ Fehlerbehebungen

  • Redis und Cache: Verwendete Pipelines zur Optimierung von Redis-Cache-Löschungen, wodurch Geschwindigkeit und Zuverlässigkeit verbessert wurden, von @fatelei in #30159.
  • UI/UX-Korrekturen: Von der Verhinderung von Seitenabstürzen aufgrund von Berechtigungsfehlern bis hin zur Korrektur der Größe von Wischschaltflächen wurden von verschiedenen Mitwirkenden mehrere Probleme im Zusammenhang mit der Benutzeroberfläche behoben.
  • Datenoperationen: Datensatzzugriffsfehler behoben und Fehlerbehandlung bei Batch-Operationen von @zhaobingshuang und anderen verbessert.
  • Leistung: Referenzen zum Laufzeitstatus unter hoher Last freigegeben, um potenzielle Speicherlecks durch @SherlockShemol in #30236 zu verhindern.
  • Sicherheit: CORS- und SSL-Probleme behoben, die sich auf Bot-Integrationen und Celery-Vorgänge ausgewirkt haben könnten.
  • Internationalisierung: Koreanische Übersetzungen und Inhalte wurden von @sangyun-han in #30347 auf Richtigkeit aktualisiert.

🔧 Unter der Haube

  • CI/CD- und Build-Verbesserungen: Verbesserte GitHub-Aktionen und Build-Prozesse für bessere Zuverlässigkeit und weniger Ausfallzeiten von @bowenliang123 und @hyoban.
  • Code- und Abfrageoptimierung: Ineffizienzen bei SQL-Abfragen und der Datenverarbeitung in Workflows und dem API wurden behoben, wodurch die allgemeine Stabilität verbessert wurde.

Der Schwerpunkt dieser Version liegt auf der Rationalisierung des Backend-Betriebs, der Stärkung der Sicherheit und der Bereicherung der Benutzeroberfläche für ein reibungsloseres und produktiveres Erlebnis. Vielen Dank an alle Mitwirkenden, die Dify verfeinert und unsere Plattform vorangetrieben haben! 🛠️💡

Upgrade-Anleitung

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre angepasste docker-compose YAML-Datei (optional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Holen Sie sich den neuesten Code aus der Hauptniederlassung

    git checkout main
git pull origin main

  3. Stoppen Sie den Dienst. Bitte im Verzeichnis docker ausführen

    docker compose down

  4. Daten sichern

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Upgrade-Dienste

    docker compose up -d

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und den Web-Frontend-Server.

  2. Holen Sie sich den neuesten Code aus dem Release-Zweig:

    git checkout 1.11.3

  3. Aktualisieren Sie die Python-Abhängigkeiten:

    cd api
uv sync

  4. Dann führen wir das Migrationsskript aus:

    uv run flask db upgrade

  5. Führen Sie abschließend den API-Server, den Worker und den Web-Frontend-Server erneut aus.
