DeepTutor v1.4.0

DeepTutor v1.4.0 Release Notes

Veröffentlichungsdatum: 2026.05.22 v1.4.0 ist der GA-Schnitt der v1.4-Linie. Es trägt den vollen v1.4.0-beta-Umfang (Auto-Modus, dreischichtige Speicher-Workbench, Agent Deep Research / Deep Solve / Frage, LlamaIndex-Chat-Refactor, Unified-Capabilities-Infrastruktur + i18n, Visualisieren/Animator-Zusammenführung, neue Chat-Tools, geteilte Einstellungen, Mehrbenutzer Isolationshärtung und der Launcher deeptutor start / deeptutor init) und fügt darüber hinaus einen gezielten Satz an Agent-Engine- und Laufzeit-Härtungskorrekturen hinzu. Den vollständigen Betaumfang finden Sie unter v1.4.0-beta.

Was ist neu seit v1.4.0-beta

Argumentationsaufwand + Denkfahnen des Anbieters

Die Agenten-Engine normalisiert nun den „Begründungsaufwand“ für alle Anbieter in einem statt, dass jede Pipeline es neu ableiten muss.

  • build_provider_extra_kwargs in deeptutor/core/agentic/client.py löst reasoning_effort gegen provider_registry auf, bildet minimal / minimum in die richtige Drahtform (DashScope verwendet minimum) und Routen die Ein-/Aus-Absicht durch Umschalten im Denkstil des Anbieters – thinking_type (DeepSeek), enable_thinking (Qwen-Stil) oder reasoning_split. Bekannte Argumentationsmodelle verwenden standardmäßig high; die Bei der Form deepseek-v4-flash wird das Denken standardmäßig deaktiviert.
  • LLMClientConfig.reasoning_effort ist durchgehend angeschlossen. Alle vier Pipelines – Agenten-Chat, Frage, Recherche, Lösung – übergeben die Bindung + Aufwand in build_completion_kwargs, also eine einzige Einstellung auf Benutzerebene steuert das Argumentationsverhalten über alle Fähigkeiten hinweg.

Tool-Schema-Fallback für strenge Anbieter

Einige OpenAI-kompatible Anbieter lehnen native Funktionsaufrufschemata mit ab ein nicht standardmäßiger Fehler. run_labeled_step erkennt jetzt diesen Fall und entfernt ihn tools / tool_choice aus der Anfrage, versucht es einmal erneut und gibt eine Warnung aus progress-Ereignis, damit der Benutzer weiß, dass der Anruf im Prosa-Modus ohne Werkzeug ausgeführt wurde. Bei Anbietern, die Toolschemata normal akzeptieren, bleibt das Verhalten unverändert.

Neustartsichere Turn Runtime

Ein Neustart des Servers oder Containers führte dazu, dass die Datenbankzeile für einen verlassen wurde In-Flight-Wende blieb auf running hängen und blockierte die nächste Nachricht darin Sitzung und das Hängenbleiben der Benutzeroberfläche an einem Ereignisstrom, der niemals stattfinden würde abgeschlossen.

  • Orphan-Erkennung – TurnRuntimeManager prüft nun, ob dies der Fall ist Der Prozess besitzt weiterhin den In-Memory-Runner der Runde. Wenn nicht, blieb das Problem bestehen Turn ist mit failed mit „Turn unterbrochen durch Server-Neustart“ gekennzeichnet. Bitte versuchen Sie es noch einmal mit Ihrer Nachricht
  • start_turn fegt veraltete aktive Kurven für die vorherige Sitzung Erstellen einer neuen Runde, sodass der Benutzer es nach einem Neustart sofort erneut versuchen kann.
  • subscribe_turn synthetisiert ein Terminal-error + done-Ereignis für die verwaiste Runde, damit das Frontend seinen Streaming-Status sauber schließt statt endlos zu warten.

Frontend API Basis – Docker Platzhalterhärtung

web/lib/api.ts wechselte von der exakten Übereinstimmung zur Teilzeichenfolgen-Token-Erkennung von den Platzhalter NEXT_PUBLIC_API_BASE und macht isApiBasePlaceholder() verfügbar zur Wiederverwendung. Dies überlebt kleine Änderungen an der Platzhalterform Docker zuvor durchgeschlüpft und eine leere Einstellungsseite mit Nr. erstellt sichtbarer Fehler. Der unbenutzte automatisch generierte web/.env.local wird mitgeliefert Beta wird entfernt.

LLM Config Probe – Klarere Statuskopie

Das /settings/llm-Probe gibt jetzt einen expliziten „Basic LLM-Abschluss“ aus gelungen. Chat validiert zusätzlich das Streaming- und Provider-Tool Kompatibilität zur Laufzeit.“ Zeile nach dem Rauchabschluss, damit die Benutzer es wissen Das Probe deckt die Streaming-/Tool-Call-Pfade bewusst nicht ab Chat-Übungen.

CLI Chat REPL – Konfigurationsoberfläche mit Dokumenten ausgerichtet

Die Oberfläche des deeptutor chat REPL wurde verschärft, damit sie zum Publikum passt Dokumente unter deeptutor.info.

  • deeptutor chat --config key=value- und --config-json '<json>'-Samen die anfängliche Konfiguration, ohne zuerst die REPL einzugeben.
  • /config set key value und /config set key=value werden beide akzeptiert; JSON-Werte ([…], {…}) werden über shlex korrekt analysiert.
  • Mit der Backslash-Fortsetzung können Sie mehrzeilige Eingabeaufforderungen in einem Durchgang senden.
  • /refs druckt einen strukturierten Zustands-Snapshot (Sitzung, Fähigkeit, Tools, KB, Verlauf, Notizbücher, Sprache, Konfiguration) anstelle einer einzelnen dunklen Linie.
  • deeptutor plugin info <name> gibt jetzt auch cli_aliases und das zurück Fähigkeit availability-Block.

Repo & Docs Hygiene

  • Neue Issue-Vorlage für die öffentliche Dokumentationsseite (.github/ISSUE_TEMPLATE/docs.yml).
  • AGENTS.md modernisiert, um Auto-Modus, Tool-Gating usw. widerzuspiegeln aktuelle Leistungsstufen.
  • .gitignore deckt .playwright-cli/ ab; abgestanden .playwright-cli/ Captures, .env.example_CN und DeepTutor.code-workspace entfernt.

Tests

  • Neues tests/core/test_agentic_client_provider_kwargs.py deckt das ab Argumentationsaufwand + Anbieter-Denkstil-Matrix.
  • Neuer tests/core/test_labeled_step_tool_fallback.py zur Ausübung der Tool-Schema-Wiederholungspfad Ende-zu-Ende gegen einen Skript-client.
  • tests/services/session/test_turn_runtime_subscribe.py sorgt für zusätzliche Abdeckung für die Wiederherstellung von Orphan-Running-Turns sowohl bei subscribe als auch bei start_turn. – tests/cli/test_chat_cli.py fügt REPL-Konfigurations-/Backslash-Tests hinzu und a Plugin-Info-Vertragsprüfung.
  • Das neue tests/cli/test_docs_contract.py behält die öffentlichen Site-Dokumente bei Synchronisierung mit der CLI-Oberfläche (Links + deeptutor …-Beispiele).
  • tests/scripts/test_docker_compose.py + web/tests/api-resolve-base.test.ts decken die neue Platzhaltererkennung ab.

Upgrade-Hinweise

  • Ab v1.4.0-beta: Drop-in. PyPI wird mit pip install -U deeptutor installiert (PyPI normalisiert 1.4.0 gegenüber 1.4.0b0). Docker-Benutzer ziehen ghcr.io/hkuds/deeptutor:latest.
  • Begründungsaufwand wird jetzt aus LLMConfig.reasoning_effort gelesen. Wenn Sie haben zuvor in extra_body manuell Anbieter-Thinking-Flags gesetzt, Der Agent wird sie weiterhin respektieren, es wird jedoch empfohlen, den Pfad festzulegen reasoning_effort und lassen Sie es vom Motor abbilden.
  • Wiederherstellung neu starten erfolgt automatisch. Nach dem Upgrade alle vorhandenen Datenbankzeilen, die aufgrund früherer Abstürze auf running hängengeblieben sind, bleiben erhalten abgeschlossen, wenn ihre Sitzung das nächste Mal geöffnet wird.
  • Beta-Artefaktbereinigung: web/.env.local wurde automatisch von generiert veralteter Launcher und wird nicht mehr benötigt. Wenn Sie das Frontend neu erstellt haben Wenn Sie diese Datei manuell bearbeiten, löschen Sie sie vor dem nächsten Build.
