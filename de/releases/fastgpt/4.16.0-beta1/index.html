#FastGPT v4.16.0-beta1

📦 Upgrade-Anleitung

1. Aktualisieren Sie die Umgebungsvariable Agent-sandbox-proxy (optional)

4.16.0 muss für den Proxy-Zugriff auf statische Ressourcen auf einen Proxy angewiesen sein. Wenn das Gateway ws und http auf demselben Port unterstützt, können Sie nur einen Port öffnen. Wenn dies nicht unterstützt wird, können Sie den HTTP-Zugriffsport festlegen, indem Sie PREVIEW_PORT festlegen.

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

Die Zugangsadresse beginnt mit http:// oder https://. Bei der Bereitstellung mit einem einzelnen Port kann es auf denselben Domänennamen und Port wie AGENT_SANDBOX_PROXY_URL verweisen, die Protokolle verwenden jedoch HTTP(S) bzw. WebSocket(S). Es wird dringend empfohlen, dass der konfigurierte Domänenname und die FastGPT-Hauptseite unterschiedliche Ursprünge verwenden. Durch die Same-Origin-Bereitstellung können diese Skripte die Same-Origin-Sicherheitsgrenze der Haupt-Site betreten und möglicherweise auf die Anmeldeinformationen oder Schnittstellen der Haupt-Site zugreifen. Das System erzwingt derzeit keine Überprüfung des Ursprungs auf Isolierung.

Sie können überprüfen, ob es zugänglich ist, indem Sie Folgendes besuchen: https://{{host}}/health.

2. Aktualisieren Sie die Umgebungsvariable „fastgpt-app“ (muss aktualisiert werden, wenn die Sandbox aktiviert ist)

Variablen werden in fastgpt-app und fastgpt-pro gleichzeitig geändert.

  1. Umgebungsvariablen hinzufügen
# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. Veraltete Sandbox-Umgebungsvariablen

AGENT_SANDBOX_DISK_MB, E2B-bezogene Variablen.

  1. Neue optionale Sandbox-Konfigurationsvariablen

| Variable | Standardwert | Beschreibung | | ---------------------------------------- | ------ | ----------------------------------------------------------------------------------- | | AGENT_SANDBOX_CPU_COUNT | 1 | Agent Sandbox CPU-Kernlimit für eine einzelne Instanz. | | AGENT_SANDBOX_MEMORY_MIB | 2048 | Speicherlimit für eine einzelne Instanz der Agent-Sandbox, Einheit MiB. | | AGENT_SANDBOX_STORAGE_SIZE_GI | 1 | Speicherkapazität der Agent-Sandbox, in Gi; Wird für das Sealos Devbox-Speicherlimit und zum Erstellen neuer PVCs im OpenSandbox Kubernetes-Modus verwendet. | | AGENT_SANDBOX_SUSPEND_MINUTES | 60 | Gibt an, wie lange die laufende Sandbox automatisch angehalten wird, nachdem sie inaktiv ist (in Minuten). | | AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS | 7 | Die angehaltene Sandbox wird nach Ablauf der inaktiven Zeit (in Tagen) automatisch archiviert. |

Der E2B-Sandbox-Anbieter wurde entfernt. Umgebungen, in denen zuvor E2B konfiguriert wurde, müssen zu opensandbox oder sealosdevbox wechseln und AGENT_SANDBOX_E2B_API_KEY löschen.

Die Vorschauprotokolle von FastGPT, fastgpt-agent-sandbox-proxy und fastgpt-agent-sandbox wurden gleichzeitig geändert. Diese Version des unterstützenden Images muss verwendet werden, wenn Agent Sandbox aktiviert wird. Eine gemischte Bereitstellung alter und neuer Versionen wird nicht unterstützt.

4. Agent-Sandbox-Daten migrieren

Diese Version passt die Agent-Sandbox von App Chat von „eine Instanz pro Konversation“ auf „eine Instanz, die von derselben App und demselben Benutzer geteilt wird“ an. Die Dateien verschiedener Konversationen werden weiterhin jeweils im Verzeichnis sessions/<chatId> gespeichert, und die veröffentlichten Skills werden im freigegebenen Verzeichnis projects gespeichert.

Wenn die Agent-Sandbox zuvor aktiviert war, muss die Migration des Legacy-Workspace in der folgenden Reihenfolge abgeschlossen werden. Umgebungen, in denen Agent Sandbox nicht aktiviert ist, können diesen Abschnitt überspringen.

Führen Sie zunächst einen Probelauf durch, um die ausstehende Anzahl der Feldnormalisierungen in der Beta6-Sandbox und die Bereinigung des alten Skill-Debug-Chats anzuzeigen. Der Trockenlauf erstellt keine Ressourcen, greift nicht auf den Objektspeicher zu und ändert keine Daten:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Führen Sie die offizielle Migration durch, nachdem Sie die Probelaufergebnisse angezeigt haben. Bei der offiziellen Migration wird zunächst die Beta6-Normalisierung durchgeführt und die Workspace-Archivierung in derselben Anfrage erst dann fortgesetzt, wenn die verbleibende ausstehende Anzahl Null erreicht:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Wenn failures nur Sandbox source is missing or deleted enthält und bestätigt wurde, dass die entsprechende App oder der entsprechende Skill nicht mehr vorhanden ist, können Sie diese verbleibenden Sandboxen explizit überspringen:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError Der Standardwert ist false, wobei die strikte Migration beibehalten wird, wenn es weggelassen wird. Dieser Schalter überspringt nur die gesamte Gruppe, deren Quelle fehlt oder vorläufig gelöscht wurde, und archiviert, löscht oder migriert die darin enthaltene Sandbox nicht. Sprungdetails werden über skippedCount und skipped zurückgegeben. Andere Fehler wie Archivierung, Objektspeicherung, Anbieter und Parallelitätskontrolle können weiterhin Migrationen blockieren. Bei der Migration wird zunächst die vollständige Vorlogik von V4.15.0-beta6 ausgeführt: Füllen Sie den sourceType/sourceId der alten Sandbox aus, bereinigen Sie die alten Felder, löschen Sie die verwaisten Ressourcen, die nicht zugeordnet werden können, und bereinigen Sie die alten Skill Debug Chat-Dreitabellendaten ohne sourceType und die alten Präfixe der privaten und öffentlichen Buckets. Skills mit derselben ID wie die App überspringen die Chat-Bereinigung. Nach erneuter Angabe der beiden Datentypen beträgt die Summe normalization.pendingCount; Wenn die Menge nicht 0 ist, wird sie nicht in das Workspace-Archiv eingetragen. Archivieren Sie nach dem Nullsetzen direkt alle alten Arbeitsbereiche und bereinigen Sie alte Computerressourcen, migrieren Sie dann die Fähigkeiten und aggregieren Sie sie schließlich nach App und Benutzer in einer Sandbox auf Benutzerebene. Solange in der Archivierungsphase ein Fehler auftritt, wird die Installationsphase nicht gestartet. Die neue Sandbox wird nach Abschluss der Workspace-Installation angehalten und bei der ersten Verwendung wie gewohnt gestartet. Skripte können sicher wiederholt werden und abgeschlossene Archivierungen und Migrationen werden nicht erneut ausgeführt; Alte Archive und alte MongoDB-Datensätze bleiben nach Abschluss der Migration als Backups erhalten.

Bitte überprüfen Sie die zurückgegebenen Ergebnisse für normalization.pendingCount, normalizationBlocked, failedCount, failures, skippedCount und skipped. Nur wenn normalization.pendingCount und failedCount beide 0 sind und normalizationBlocked false ist, bedeutet dies, dass alle nicht übersprungenen Sandbox-Migrationen abgeschlossen sind; Ältere Datensätze in skipped bleiben erhalten und werden nicht migriert.

5. HTTP-Tool-Daten migrieren

Diese Version ändert die Array-Parameter des HTTP-Tools im manuellen Modus auf das Standardschema JSON. Umgebungen, die vor dem Upgrade manuelle HTTP-Tools erstellt haben, müssen diese Migration durchführen; HTTP-Tools im OpenAPI-Modus müssen nicht migriert werden und das Skript wird automatisch übersprungen.

Führen Sie zunächst einen Probelauf durch, um die ausstehenden Daten in der aktuellen Anwendung und in historischen Versionen anzuzeigen. Der Trockenlauf verändert die Daten nicht:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Führen Sie nach Bestätigung des Ergebnisses die offizielle Migration durch:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Das Skript filtert zunächst Anwendungen nach HTTP-Tooltyp und migriert dann die entsprechenden historischen Versionen basierend auf appId dieser Anwendungen. Es werden nur manuelle Modi verarbeitet, die für apiSchemaStr nicht vorhanden sind, andere Anwendungen und OpenAPI-Modi werden nicht geändert. Die Migration wird stapelweise ausgeführt und kann problemlos wiederholt werden. total.changedDocumentCount im zurückgegebenen Ergebnis gibt die Anzahl der zur Verarbeitung gefundenen Dokumente an. Nach der formellen Ausführung können Sie einen erneuten Probelauf durchführen, um zu bestätigen, dass der Wert 0 ist.

🚀 Neue Inhalte

  1. Die Agent-Sandbox wird in eine Instanz auf App-Benutzerebene geändert. Mehrere Konversationen derselben App und desselben Benutzers verwenden die Sandbox wieder und isolieren jede Konversationsdatei über ein unabhängiges Sitzungsverzeichnis.
  2. Sandbox-HTML und -Dateien unterstützen die direkte Vorschau über kurzfristige schreibgeschützte Links und müssen zur Vorschau nicht mehr wiederholt in den Objektspeicher hochgeladen werden.
  3. App Workflow archiviert und stellt den Arbeitsbereich automatisch wieder her, wenn sich der Sandbox-Anbieter oder das Laufzeit-Image ändert, und der Upgrade-Prozess wird während der aktuellen Ausführung stillschweigend abgeschlossen.
  4. Der Workflow-Tool-Knoten unterstützt die automatische Generierung spezifizierter Eingabeparameter durch den Agenten und behält vorhandene Konfigurationen wie feste Werte, Referenzen und Benutzereingaben bei.
  5. Wenn ChatAgent ein Tool auswählt, unterstützt es die manuelle Angabe, ob Parameter für KI generiert werden sollen.
  6. Wissensdatenbankdaten unterstützen die Anpassung von metadata, und JSON-Metadaten können über API-, CSV- oder Excel-Vorlagen importiert werden; Dieses Feld wird in Suchergebnissen und Backup-Exporten beibehalten. Sowohl der Vorlagenimport als auch der Backup-Import unterstützen .csv- und .xlsx-Dateien unter Verwendung der Header q, a, index und metadata. q, a und metadata haben jeweils eine Spalte, und index kann mehrere Spalten in beliebiger Reihenfolge haben. Excel-Dateien unterstützen nur ein einzelnes Arbeitsblatt und können keine verbundenen Zellen enthalten. CSV- oder Excel-Dateien, die nicht korrekt analysiert werden können, führen zu einer Dateiformatausnahme.
  7. Laden Sie große Dateien in Blöcken hoch.
  8. Wenn der Administrator den System-Tool-Schlüssel konfiguriert, wird er verschlüsselt (kompatibel mit dem konfigurierten Schlüssel).
  9. Leere Statusführung in der Fertigkeitsliste und Verknüpfung bei der Auswahl von Fertigkeiten.

⚙️ Optimierung

  1. Rekonstruieren Sie den Lebenszyklus und den Migrationsprozess der Agent-Sandbox. Erstellen, Anhalten, Archivieren, Wiederherstellen, Löschen und Anbieterwechsel unterstützen Parallelitätsschutz, Breakpoint-Wiederaufnahme und idempotente Wiederholung.
  2. Wenn Agent Sandbox nicht verfügbar ist oder vom aktuellen Teampaket nicht unterstützt wird, deaktiviert App Chat automatisch die Sandbox-Funktion und andere Modelle, Tools, Wissensdatenbanken und Workflow-Knoten können weiterhin ausgeführt werden.
  3. Persistente Volumes können nach dem Stoppen von OpenSandbox beibehalten und bei nachfolgenden Ausführungen wiederverwendet werden; Pausen- und Archivschwellenwerte unterstützen die Konfiguration über Umgebungsvariablen.
  4. Die App und der Skill haben einen einheitlichen Runtime-Image-Upgrade-Status und die Skill-Bearbeitungsseite kann kontinuierlich die Upgrade-Ergebnisse abfragen.
  5. Erstellen Sie automatisch übergeordnete Verzeichnisse, bevor Sie Sandbox-Dateien schreiben, um Fehler beim Schreiben verschachtelter Pfade zu vermeiden.
  6. Optimieren Sie Kompatibilitätsprobleme wie alte Workflow-Daten und Werkzeugparameter.
  7. Agent Ask-Benutzeroberfläche.

🐛 Fix

  1. Das Problem wurde behoben, bei dem OpenSandbox-Ressourcen nach dem Stoppen nicht korrekt freigegeben oder wiederverwendet wurden.
  2. Beheben Sie Probleme mit Statuskonflikten und doppelten Vorgängen während der Erstellung, Wiederherstellung oder Laufzeitaktualisierung der Agent-Sandbox.
  3. Das Problem wurde behoben, bei dem Sandbox keine Dateien in verschachtelte Verzeichnisse schreiben konnte, weil das übergeordnete Verzeichnis nicht existierte.
  4. Das Problem wurde behoben, bei dem die Zahleneingabe nach dem Wechsel zwischen Agentengenerierung und manueller Eingabe zu einem normalen Textfeld wurde.
  5. Das Problem wurde behoben, bei dem die Zeichenfolgentexteingabe fälschlicherweise als Dropdown-Auswahl gerendert wurde.
  6. Das Problem wurde behoben, bei dem der JSON-Editor fälschlicherweise zur Workflow-Tool-Konfiguration hinzugefügt wurde.
  7. Das Problem wurde behoben, bei dem Tool-Ausführungsfehler in der Agent-/Workflow-Tool-Schnittstelle falsch angezeigt wurden.
  8. Das Anzeigeproblem deinstallierter Tools in der System-Tool-Liste wurde behoben.
  9. Korrigieren Sie die Standardlogik zur Versionsauswahl von Agent/Agent V2, sodass standardmäßig die neueste Version ausgewählt wird.
  10. Wenn in der S3-Datei Leerzeichen vorhanden sind, tritt beim Parsen der Bilder in der Datei aufgrund einer Schlüsselausnahme ein 404-Fehler auf.
  11. MCP SSE-Modus, Header wird wiederholt.
  12. Der Schlüssel des Agent V2-Systemtools ist nicht verschlüsselt.

🛠️ Codeoptimierung

  1. Der Sandbox-Adapter wird nach Lebenszyklus, Dateisystem, Befehlsausführung und Provider-Vertrag neu aufgeteilt und der E2B-Adapter wird entfernt.
  2. Agent Sandbox Proxy und IDE Agent fügen Vorschau der direkten Workspace-Verbindung, Bereichsanforderung, Pfad-Escape-Schutz und Sitzungsauthentifizierung hinzu.
  3. Optimierung des Workflow-Schemas, einheitlicher Tool-Aufruf und Formular-Rendering.
  4. Erweitertes Tool JSON Schema zur Unterstützung weiterer Datentypen.
  5. Zeitüberschreitung beim Lesen einheitlicher Servicedateien.
  6. Optimieren Sie das Problem der Multiprozessberechtigungssicherheit von Systemtools.
  7. Anmelde- und Authentifizierungscode umgestalten.
  8. Rekonstruieren Sie das Strombegrenzungsmodul.
