#FastGPT v4.16.1

📦 Upgrade-Anleitung

Umgebungsvariablen der Agent-Sandbox aktualisieren und Image ausführen

Wenn Sie Agent Sandbox aktivieren, überprüfen Sie bitte gleichzeitig die folgende Konfiguration in fastgpt-app und fastgpt-pro. 4.16.1 verwendet die vollständige laufende Bildadresse:

# 普通非 root 镜像，默认配置
AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.3.1

Wenn die Sandbox Apt-Abhängigkeiten installieren muss, müssen Sie zum Root-Image wechseln; Bei Bedarf können Sie die passende Bildquelle konfigurieren:

AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox-root:v0.3.1
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu

Eine vollständige Liste der Spiegelquellen für das chinesische Festland und der globalen Spiegelquellen, der Root-/Nicht-Root-Spiegelauswahl und der benutzerdefinierten Abhängigkeitsquellenkonfiguration finden Sie unter OpenSandbox-Konfiguration.

Migrationstool JSON Schemaspeicherformat

Bitte führen Sie die Migration strikt in der folgenden Versionsreihenfolge durch:

  1. Nachdem Sie sichergestellt haben, dass die 4.16.0-Version des initHttpToolSchema-Skripts ausgeführt wird, konvertieren Sie die Verlaufsarray-Parameter des manuellen HTTP-Tools in das Standardschema JSON.
  2. Führen Sie nach dem Upgrade auf 4.16.1 initToolJsonSchemaStorage in diesem Abschnitt aus.

4.16.1 überprüft die HTTP-Tool-Anwendung und ihre historische Version, die für 4.16.0 verantwortlich ist. Wenn die Daten noch alte Array-Typen enthalten, verweigert die Schnittstelle die Ausführung, um zu verhindern, dass die alten Daten direkt in Strings konvertiert werden. Bei der Migration werden nur MCP/HTTP-Tool-Anwendungen und ihre historischen Versionen verarbeitet, keine gewöhnlichen Workflow-Anwendungen.

4.16.1 vereinheitlicht das JSON-Schema von MCP/HTTP-Tools im String-Speicher. Sie können zunächst einen Probelauf durchführen, um die Änderungen zu überprüfen:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Führen Sie nach der Bestätigung von total.changedDocumentCount die offizielle Migration durch:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

🚀 Neue Inhalte

  1. Veröffentlichungskanäle von Drittanbietern, die multimodale Dateien, Audiotranskription und Zitate (falls vorhanden) unterstützen
  2. Unterstützen Sie das Team bei der Installation von System-Plug-Ins (Prozessmodus, es bestehen bestimmte Sicherheitsrisiken, zukünftige Versionen unterstützen serverlosen isolierten Betrieb).
  3. Die Sandbox unterstützt benutzerdefinierte Apt-Quellen.

⚙️ Optimierung

  1. S3-Schlüsselbenennung: Löschen Sie den ursprünglichen Dateinamen als Schlüssel, um zu verhindern, dass er zu lang wird.
  2. Das MCP/HTTP-json-Schema verwendet String-Speicher, um zu verhindern, dass benutzerdefinierte Objekte mit Mongo-Regeln in Konflikt geraten.

🐛 Fix

  1. In der Konfiguration der globalen Variablen des Workflows ist der Feldname zu lang und läuft über.
  2. AgentV2 ruft den Unterworkflow auf und der Flow-Ausgabeinhalt innerhalb des Workflows ist nicht deaktiviert.
  3. Link zur Teameinladung: Sie können dieselbe Teameinladung wiederholt erhalten.
  4. Mithilfe von Datensätzen hat die Datumsauswahl einen weiteren Tag.

🛠️ Codeoptimierung

  1. Vervollständigen Sie alle devapi-Schnittstellendokumente.
  2. Gleichzeitige Initialisierung und Protokolloptimierung des Plug-in-Systems.
  3. Das Problem wurde behoben, bei dem Fehler während des Plug-in-Vorgangs als Systemfehler ausgegeben wurden.
  4. Das Problem wurde behoben, das dadurch verursacht wurde, dass die Richtlinie --allow-net nicht festgelegt wurde, wenn die Plug-in-Version Node.js höher als v25 ist.
