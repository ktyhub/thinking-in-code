bookkeeper release-4.18.0

Release Veröffentlicht10. Juni 2026 Quelleapache/bookkeeper Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Buchhalterfreigabe-4.18.0

Release 4.18.0 ist ein Hauptfeature-Release. Es führt eine strukturierte Protokollierung im gesamten System ein Codebasis (BP-69), migriert die Wire-Protokoll-Serialisierung zu LightProto und dem nativen I/O Bibliothek auf Rust und erhöht die mindestens erforderliche Java-Version auf 17. Sie enthält auch viele Verbesserungen, Fehlerbehebungen und Abhängigkeits-/CVE-Updates.

Benutzern von Apache BookKeeper wird empfohlen, ein Upgrade auf 4.18.0 durchzuführen. Bitte überprüfen Sie die Wichtige Änderungen und bekannte Probleme finden Sie weiter unten, bevor Sie ein Upgrade durchführen.

Highlights

  • Strukturierte Protokollierung (BP-69) – Die gesamte BookKeeper-Protokollierung wurde von SLF4J konvertiert Formatieren Sie Zeichenfolgen in slog, eine strukturierte Protokollierung API, bei der jedes Ereignis einen typisierten Schlüssel/Wert enthält Attribute (z. B. ledgerId, entryId). Der Logger-Kontext wird über client weitergegeben Vorgänge, sodass alle Ereignisse, die sich auf dasselbe Hauptbuch beziehen, automatisch markiert werden. Attribute werden von log4j2 sowohl im Klartext als auch in der JSON-Ausgabe gerendert, mit einem Beispiel Konfiguration für OpenTelemetry-kompatible JSON-Protokolle. PR #4751, #4754, #4755, #4756, #4757, #4758, #4765, #4766, #4767, #4770
  • LightProto-Serialisierung – Das Wire-Protokoll, die Metadatenformate und der Stream von BookKeeper Speicherprotos wurden von Protobuf-Java nach LightProto migriert, das analysiert und Serialisiert direkt auf Netty-Puffer ohne Zwischenzuweisungen, wodurch der GC-Druck reduziert wird auf dem heißen Weg. PR #4779, #4780, #4781, #4783
  • Native E/A-Bibliothek neu geschrieben in Rust – Die native-io-Bibliothek, die für direkte E/A verwendet wird Der Buchmacher wurde von C auf Rust migriert. PR #4738
  • Java 17-Basisversion – Java 17 oder höher ist jetzt erforderlich, um BookKeeper zu erstellen und auszuführen. PR #4446
  • Die Stilllegung des Buchmachers bereinigt das Cookie (BP-68) – Der Stilllegungsadministrator API jetzt Löscht das Buchmacher-Cookie aus dem Metadatenspeicher, sodass eine stillgelegte Buchmacher-ID erstellt werden kann ohne manuelle Reinigung wiederverwendet werden. PR #4500, #4592
  • ZooKeeper Lesedrosselung während der Neureplikation (BP-66) – Neureplikation ist jetzt möglich drosselt seine ZooKeeper-Lesevorgänge und schützt so den Metadatenspeicher vor Lesestürmen, wenn es viele gibt Hauptbücher werden wiederhergestellt. PR #4258
  • Batch-Lesevorgänge unbestätigter Einträge (BP-62) – batchReadUnconfirmedAsync ist jetzt ausgesetzt auf ReadHandle. PR #4739

Breaking Changes

  • Zum Erstellen und Ausführen von BookKeeper ist Java 17+ erforderlich (zuvor Java 11) PR #4446
  • Der Standardwert von readOnlyModeOnAnyDiskFullEnabled wurde in true geändert: jetzt ein Buchmacher wechselt in den schreibgeschützten Zustand, sobald eine Ledger-Festplatte voll ist, und nicht erst, wenn alle Festplatten voll sind sind voll. Setzen Sie es wieder auf false, um das vorherige Verhalten wiederherzustellen. PR #4520
  • Das Modul bookkeeper-slogger wurde entfernt und durch die Slog-Struktur ersetzt Protokollierung API (BP-69) PR #4764
  • Die veraltete, falsch geschriebene Methode setAllocatorPoolingConcurrenncy – use wurde entfernt setAllocatorPoolingConcurrency stattdessen PR #4431
  • Die veraltete Klasse MathUtils entfernt PR #4274

Bekannte Probleme

  • PR #4730 (Thread-Blockierungs-Fix einlesen Es wurde festgestellt, dass der in dieser Version enthaltene Fehler sendResponseAndWait möglicherweise einen Deadlock verursacht auf dem Buchmacher-Lesepfad. Es wurde zurückgesetzt PR #4830, das Teil von 4.18.1 sein wird.

Funktionen

  • Unterstützt die TCP-Keep-Alive-Konfiguration für den Buchmacher-Server PR #4762
  • Neuer client API zur Prüfung, ob der BookKeeper client mit dem Metadatendienst verbunden ist PR #4342
  • Migration von Yahoo DataSketches zu Apache DataSketches 7.0.1 (KLL) PR #4774
  • Erlaubt die Konfiguration von log4j2 AsyncLogger PR #4269

Verbesserungen

Buchmacher

  • total_entry_log_space_bytes-Metrik hinzufügen PR #4507
  • Bereichern Sie GC-Metriken, um das GC-Verhalten und die in jeder Phase aufgewendete Zeit besser zu analysieren PR #4384
  • Fügen Sie eine Metrik für RocksDB getLastEntryInLedger hinzu, um die Identifizierung von Engpässen zu erleichtern PR #4529
  • ThreadFactory für den Executor in EntryLoggerAllocator festlegen PR #4562
  • Temp-Verzeichnis-Eigenschaft für die native Bibliothek hinzufügen PR #4533
  • Wenden Sie die WRITE_BUFFER_WATER_MARK-Einstellung auf untergeordnete Kanäle im Buchmacher-Netty-Server an PR #4337
  • Überspringen Sie verschwendete optimistische Cache-Einfügungen in SingleDirectoryDbLedgerStorage, wenn die Schreibsperre gehalten wird PR #4306
  • Nur überschriebene Konfigurationseinstellungen beim Start von BookieServer protokollieren PR #4768
  • Entfernen Sie nicht verwendete Journalzeiterfassung PR #4006

Client

  • Eliminieren Sie unnötige Synchronisierung auf LedgerHandle.getLength() PR #4516
  • Optimieren Sie begrenzte Batch-Lesevorgänge durch Vorhersage der Eintragsanzahl PR #4741
  • Logik zur Hostadressenauflösung für Buchmacher-ID verbessern PR #4588
  • Benennen Sie den client-Thread-Pool mit hoher Priorität um PR #4496

Werkzeuge

  • Der Befehl readledger liest alle Einträge eines Buchmachers, wenn die ersten und letzten Eintrags-IDs nicht angegeben sind PR #4692
  • ListActiveLedgersCommand optimieren PR #4602
  • Verbesserung der Nutzungsinformationen des Buchmachers CLI für die Option --help PR #4241

Buchmacher

  • Fehler beim Start des Buchmachers behoben, der durch IOException: Recovery log <id> is missing PR #4740 verursacht wurde.
  • Double Flush aufgrund einer Racebedingung in SingleDirectoryDbLedgerStorage verhindern PR #4305
  • Korrigieren Sie die Handhabung des RocksDB-Konfigurationspfads unter Windows PR #4407
  • Endlosschleife im BufferedChannel-Lesen behoben PR #4506
  • ArrayIndexOutOfBoundsException in ConcurrentLongHashMap behoben PR #4771
  • Problemumgehung für ZOOKEEPER-3825 (numerische IPs und DNS-Namen, die in mehrere numerische IPs aufgelöst werden) mit Java 17-Unterstützung hinzugefügt PR #4719
  • Behebung eines Problems, bei dem der asynchrone Protokoll-Appender Fehlerprotokolle verschluckt, wenn der Buchmacher nicht startet PR #4475
  • Fix SingleThreadExecutor, um neue Aufgaben abzulehnen, während ein drainTo ausgeführt wird und die Warteschlange leer ist PR #4488

Client

  • Behebung des Problems, dass Batch-Lesevorgänge hängen bleiben, nachdem Wiederholungsversuche wegen Digest-Konflikten ignoriert wurden PR #4789
  • Korrigieren Sie die WriteSet-Nutzung nach dem Recycling in Sequenzlesevorgängen PR #4788
  • NPE in PendingAddOp.maybeTimeout() beheben, wenn clientCtx nach recycling null ist PR #4760
  • Race Condition NPE in V3-Antwortverarbeitung während der Timeout-Prüfung behoben PR #4737
  • Behebung, dass Buchmacher WatchTask hängen bleibt PR #4481
  • Plausibilitätsprüfung in asyncBatchReadEntries PR #4579 behoben
  • Strenge Hostnamenauflösung und Loopback-Prüfung für die angekündigte Adresse hinzufügen PR #4595
  • Verwenden Sie den Instanz-Slog-Logger in LedgerHandle.batchReadUnconfirmedAsync PR #4782
  • Protokollebene für Parameterprüfungen beim Batch-Lesen auf Debuggen ändern PR #4485

Andere

  • IllegalThreadStateException im ComponentStarter-Shutdown-Hook behoben PR #4733
  • Behebung eines möglichen Jetcd-Core-Shading-Problems PR #4526
  • Behebung möglicher Klassenkonflikte während des jetcd-core-shaded-Shading-Prozesses PR #4532
  • Falschen Konfigurationsschlüssel in getHttpServerTrustStorePassword beheben PR #4301
  • Formatierung der Ausnahmemeldung im RocksdbKVStore korrigiert PR #4448
  • Behebung des Fehlers „Berechtigung verweigert“ im Bild Docker PR #4464
  • Optionen für das Ignorieren des Befehls „Sanity Test“ behoben PR #4691
  • Behebung des doppelten ZooKeeper-Aufrufs in DistributedLog getLogSegmentNames PR #4050
  • Korrigieren Sie die PID-Prüfung in bookkeeper-daemon.sh Start/Stopp PR #3113

Build, CI und Tests

  • Einführung des Befehls /bkbot zur Steuerung von CI-Workflow-Ausführungen über PR-Kommentare PR #4673, #4674, #4746
  • Aktualisieren Sie die Website auf Docusaurus 3, erstellt mit Node 24 PR #4723
  • Java 21 (LTS)-Kompatibilitätsprüfung und tägliche Java 21/Windows-Builds hinzugefügt PR #4350, #4292
  • Fügen Sie der CI eine Tippfehlerprüfung hinzu und beheben Sie vorhandene Tippfehler PR #4375
  • CI-Caching für Downloads alter Releases und Maven-Artefakte verbessern, Fehlerprotokolle verbessern PR #4722
  • OWASP-Abhängigkeitsprüfung aus CI entfernen PR #4717
  • Javadoc-Unterstützung für nur POM-schattierte Module hinzugefügt PR #4787

Abhängigkeitsaktualisierungen

  • Aktualisieren Sie Netty auf 4.2.14.Final und adressieren Sie CVEs PR #4744, #4775, #4799.
  • Aktualisieren Sie Vert.x auf 4.5.25, um CVE-2026-6860 PR #4790 zu beheben.
  • Jetty von 9.4.57 auf 12.1.7 aktualisieren PR #4710
  • Aktualisieren Sie RocksDB auf 9.9.3 PR #4580
  • Upgrade von ZooKeeper von 3.9.3 auf 3.9.5 PR #4667, #4721
  • Aktualisieren Sie Protobuf und gRPC auf die neuesten Versionen. Bereich gRPC-Abhängigkeiten über grpc-bom PR #4716, #4784
  • Aktualisieren Sie die OpenTelemetry-Bibliotheken auf 1.61.0 / 2.27.0 PR #4773
  • Aktualisieren Sie jctools auf 4.0.6 (jctools-core-jdk11) PR #4656, #4776
  • Aktualisieren Sie Lombok auf 1.18.32 für Java 22-Unterstützung PR #4267
  • Aktualisieren Sie BouncyCastle von 1.75 auf 1.78, BC-Fips von 1.0.2.4 auf 1.0.2.5 PR #4295, #4366
  • Upgrade von commons-io von 2.7 auf 2.17.0 PR #4509
  • Verwenden Sie slf4j-bom und log4j-bom in dependencyManagement PR #4346
