adk-python v2.7.0

2.7.0 (13.08.2026)

Highlights

Eine Korrektheitsveröffentlichung: Die meiste Arbeit floss in das, was ein Agent an das Modell sendet und was es zurückerhält, zusammen mit einer langen Reihe von Korrekturen in den Tools, Sitzungen, der Evaluierung und dem CLI.

  • Modelle deklarieren ihre eigenen Fähigkeiten: Ein Agent koppelt ein Ausgabeschema mit Tools, wenn das Modell es tatsächlich unterstützt, anstatt dass ADK die Unterstützung aus der Modell-ID ableitet. (2aff82c, dc5dbfa)
  • Tools können Medien zurückgeben: Die Funktionsantwort eines Tools überträgt Bilder und andere Medien direkt zurück zum Modell, sowohl auf Gemini als auch auf Anthropic, LiteLLM, Apigee und OCI. (df9d6de, 703cf43)
  • Der Konversationsverlauf behält, was Gemini braucht: Gedankensignaturen, serverseitige Tool-Aufrufteile und jedes Ergebnis eines parallelen Funktionsaufrufs überleben den Roundtrip. (d4ed347, e908137, 93dff41)
  • Jinja2-Anweisungsvorlagen: Übergeben Sie use_jinja2=True an inject_session_state und eine Anweisung kann Bedingungen und Schleifen über den Sitzungsstatus verwenden, wobei Artefakte über einen {{ artifact("name") }}-Helfer geladen werden. Jinja2 bleibt eine optionale Abhängigkeit und die Regex-Engine bleibt die Standardeinstellung. (4a00a34)
  • Schnellerer Start und Hot Paths: import google.adk erledigt weniger Arbeit und der Anforderungspfad vermeidet Pydantic-Roundtrips und quadratische Streaming-Akkumulation im LiteLLM-Adapter. (8806dc2, 9e1adde, 36fd2c8)

Breaking Changes

  • pyarrow hat das gcp-Extra verlassen: Es befindet sich im neuen bigquery-analytics-Extra, das etwa 50 MB von pip install google-adk[gcp] beansprucht. Wenn Sie BigQueryAgentAnalyticsPlugin verwenden, installieren Sie google-adk[bigquery-analytics]. (ac71709)
