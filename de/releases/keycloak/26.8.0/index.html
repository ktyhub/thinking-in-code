Die Bediener mussten die fehlenden Indizes manuell erstellen.</p> </div> <div class="paragraph"> <p>Keycloak erstellt jetzt nach dem Start automatisch übersprungene Indizes im Hintergrund mithilfe der nicht blockierenden Indexerstellung auf PostgreSQL, Oracle, MySQL/MariaDB und unterstützten Microsoft SQL Server-Editionen. Ungültige PostgreSQL-Indizes, die durch fehlgeschlagene vorherige Versuche entstanden sind, werden erkannt und automatisch neu erstellt. Bei Datenbanken ohne nicht blockierende Unterstützung protokolliert Keycloak weiterhin die SQL zur manuellen Ausführung.</p> </div> </div> <div class="sect3"> <h4 id="_vert_x_based_outbound_http_client_experimental">Vert.x-basierter ausgehender HTTP client (experimentell)</h4> <div class="paragraph"> <p>Keycloak verwendet Apache HTTP Client für alle ausgehenden Verbindungen zu externen Diensten wie Identitätsanbietern, OCSP-Respondern und Backchannel-Abmeldeendpunkten. Da Keycloak für eingehenden Datenverkehr bereits auf Vert.x/Netty ausgeführt wird, erhöht die Verwendung eines separaten HTTP-Stacks für ausgehende Verbindungen unnötige Komplexität und Abhängigkeitsaufwand.</p> </div> <div class="paragraph"> <p>Keycloak stellt jetzt einen experimentellen Vert.x-basierten HTTP client bereit, der den Apache HTTP Client durch Vert.x/Netty für alle ausgehenden Verbindungen ersetzt. Um es zu aktivieren, starten Sie Keycloak mit <code>--features=http-client:v2</code>.</p> </div> <div class="paragraph"> <p>Wenn diese Option aktiviert ist, verwendet der gesamte ausgehende HTTP-Verkehr den Vert.x HTTP client. Bestehende Konfigurationsoptionen funktionieren auf die gleiche Weise.</p> </div> <div class="paragraph"> <p>Weitere Informationen finden Sie in der Anleitung <a href="https://www.keycloak.org/server/outgoinghttp">Ausgehende HTTP-Anfragen konfigurieren</a>.</p> </div> </div> <div class="sect3"> <h4 id="_helm_chart_operator_install_experimental">Helm Chart Operator-Installation (experimentell)</h4> <div class="paragraph"> <p>Keycloak veröffentlicht jetzt ein experimentelles Helm-Diagramm zur Installation des Operators.</p> </div> <div class="paragraph"> <p>Installationsanweisungen finden Sie im <a href="https://www.keycloak.org/guides#operator">Bedienungsanleitung</a>.</p> </div> </div> </div> <div class="sect2"> <h3 id="_organizations">Organisationen</h3> <div class="sect3"> <h4 id="_shared_identity_providers_across_organizations">Organisationenübergreifende gemeinsame Identitätsanbieter</h4> <div class="paragraph"> <p>Identitätsanbieter können jetzt mit mehreren Organisationen verknüpft werden und ermöglichen so Szenarien wie ein einziger Corporate-Identity-Anbieter, der Benutzer in verschiedenen Geschäftsbereichen oder Tochtergesellschaften bedient, die jeweils als separate Organisation dargestellt werden. Jede Domäne kann unabhängig festlegen, welcher Identitätsanbieter die Authentifizierung übernimmt und ob Benutzer automatisch umgeleitet werden.
