TencentDB-Agent-Memory v0.3.6

[0.3.6] – 28.05.2026

🚀 Neue Funktionen

  • Kontextbudgetsteuerung abrufen (#71 / #70): recall.maxCharsPerMemory- und recall.maxTotalRecallChars-Konfigurationen hinzugefügt, um überlange Einträge in gebrochener Reihenfolge zu bereinigen und Überlaufteile zu verwerfen, um zu verhindern, dass lange Sitzungen den Kontext aufgrund von Speichererweiterung verdrängen.
  • L1-/L2-/L3-Eingabeaufforderungswörter passen sich der Benutzereingabesprache an (#38): Die Freitextfelder der vier Eingabeaufforderungen l1-extraction, l1-dedup, scene-extraction und persona-generation werden jetzt in der Benutzernachrichtensprache geschrieben, ohne dass locale konfiguriert werden muss.
  • Einbettung von sendDimensions optional geschlossen: Konfigurationselement embedding.sendDimensions hinzugefügt. Bei der Einstellung false wird das Feld dimensions im Anforderungstext weggelassen, was mit festdimensionalen Modellen wie BGE-M3 verbunden werden kann.
  • Gateway optionale Bearer-Authentifizierung + CORS-Whitelist: server.apiKey / TDAI_GATEWAY_API_KEY und server.corsOrigins / TDAI_CORS_ORIGINS hinzugefügt. Nach der Aktivierung müssen Nicht-/health-Routen Bearer-Token und einen konstanten Zeitvergleich tragen, um Timing-Angriffe zu verhindern. Hermes Python Client-Synchronisierung unterstützt MEMORY_TENCENTDB_GATEWAY_API_KEY.
  • Offload collect-Modus: offload.mode: "collect" hinzugefügt, der nur die Datenerfassung durchführt, ohne die L3-Komprimierung auszulösen. Es eignet sich für reine Datenakkumulation oder Debugging-Szenarien.

🐛 Fix

– L2-LLM-Fehler führt dazu, dass scene_blocks/ gelöscht wird (#88): scene_blocks/ automatisch aus dem letzten Backup wiederherstellen, wenn LLM einen Fehler auslöst, Fail-Soft-Design.

  • Der Szenendateiname enthält Leerzeichen, wodurch die Persona Scene Navigation-Referenz ungültig wird: filename-normalizer.ts hinzugefügt und der Dateiname in SceneExtractor.extract automatisch normalisiert.
  • api.runtime.state verursacht Registrierungsabsturz für undefined (#78 / #85 / #79): Optionale Kette + Fallback hinzufügen, dreistufiges Downgrade von runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw unterstützen.
  • Die Steckplatz-ID contextEngine stimmt nicht mit dem Plug-in-Namen überein.: Ändern Sie sie in memory-tencentdb, um zu vermeiden, dass openclaw doctor --fix den Steckplatz zurücksetzt.
  • L1.5-Abgleich kehrt nie zurück, was dazu führt, dass L2 einfriert: Fügen Sie ein Zeitlimit von 60 Sekunden hinzu und erzwingen Sie automatisch einen Abgleich, wenn der Context Engine-Steckplatz nicht konfiguriert ist.
  • Eigenständige Textaufgabe macht weiterhin Werkzeuge verfügbar (#58 / #59): Die Werkzeugliste wird in enableTools=false überhaupt nicht übertragen. – L2-Kaltstart überspringt falsches Update l2LastRunTime: Zeitstempel nur aktualisieren, wenn es tatsächlich ausgeführt wird.
  • sanitizeText löscht versehentlich Nicht-BMP-Zeichen wie Emoji / CJK / Math Bold (#30 / #31): Fügen Sie das u-Flag zum regulären Muster hinzu, um nur isolierte Ersatzzeichen zu finden.
  • Notfallkürzung aufgrund der MIN_KEEP-Ablehnung blockiert: _emergencyTruncateOversized hinzugefügt, erzwungenes Löschen und Paarungsbereinigung.
  • Kumulativer Zeitverbrauch mehrerer Runden aggressiver Komprimierung: geändert von 6 Runden der gesamten Tiktoken-Menge auf einen einzigen präzisen Grenzwert, 615 Nachrichten 84s → 14s.
  • FP-HEAD-DELETE löscht versehentlich eine neue Nachricht: Verwenden Sie stattdessen FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP und spielen Sie die Szene 38s→122ms ab.
  • Der erste Zusammenbau ist langsam: Fügen Sie eine schnelle Token-Schätzung vor dem Kurzschluss hinzu, 29 s → 1,4 s.
  • Token-Berechnungsgenauigkeit: details wird zu INTERNAL_KEYS hinzugefügt; l3TiktokenEncoding wird standardmäßig in cl100k_base geändert.
  • Dockerfile.hermes generiert config.yaml fehlt api_key (#77 / #81): model.api_key synchron schreiben.
  • Mehrere Probleme mit dem Installationsskript (#18 / #19 / #20 / #54 / #55): Unterstützt HERMES_AGENT_DIR-Überschreiben, Root rekursiert nicht mehr auf su, Systemd-Umgebung verwendet absolute Pfadknoten.
  • Sauberere Sicherheitshärtung: Ungültiges Cutoff ablehnen, expired/total > 80% Löschung verhindern, Mindestaufbewahrungsrichtlinie.

✨ Verbesserungen

  • l3TiktokenEncoding wird standardmäßig in cl100k_base geändert und entspricht den gängigen inländischen/Open-Source-Modell-Wortsegmentierern.
  • Offload-Log-Downgrade: AGGRESSIVE / EMERGENCY usw. werden auf Debug heruntergestuft und WARN wird bereits nach 10 Sekunden ausgegeben.
  • Docker-Dokument ergänzt cd docker/opensource-Vorschritte; Fügt eine Vorlage für Fragen/Beratungsthemen hinzu.

⚠️ Änderungen an Konfigurationselementen (Abwärtskompatibilität)

| Schlüssel | Standardwert | Beschreibung | |---|---|---| | recall.maxCharsPerMemory | 0 | 0/Nicht festgelegt = Kein Zuschneiden | | recall.maxTotalRecallChars | 0 | 0/Nicht festgelegt = Kein Zuschneiden | | embedding.sendDimensions | true | false trägt nicht dimensions, geeignet für BGE-M3 usw. | | l3TiktokenEncoding | cl100k_base (ehemals o200k_base) | Eine manuelle Überschreibung ist nur erforderlich, wenn explizit auf o200k_base | zurückgegriffen wird
