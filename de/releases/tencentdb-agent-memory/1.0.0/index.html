TencentDB-Agent-Memory v1.0.0

[1.0.0] – 11.06.2026

Offizielle Version veröffentlicht: Weiterentwicklung vom exklusiven OpenClaw-Plug-in zum universellen Speicherdienst für alle Agenten. Kompletter Gateway-unabhängiger Dienst + v2 HTTP API + offizielles TypeScript / Python SDK, jedes Agent-Framework kann auf vollständige mehrschichtige Speicher- und Kontextkomprimierungsfunktionen zugreifen.

⚠️ Breaking Changes

  • Aufteilung der Client-/Server-Architektur: Die Speicher-Engine wird vom eingebetteten OpenClaw-Plug-in in einen unabhängigen Gateway-Dienstprozess aufgeteilt, und die Bereitstellungs- und Zugriffsmethoden ändern sich.
  • Änderung der Konfigurationsstruktur: Die Plug-in-Konfigurationsstruktur wird abgeflacht und rekonstruiert, und das ursprüngliche gateway-Feld wird in die server-Verschachtelung migriert.
  • Änderung des Plug-in-Eingabemodus: Unterstützt zwei Zugriffsmodi: local (lokal im Prozess ausgeführt, Standardeinstellung) und client (Verbindung zu einem externen Speichergateway herstellen).

🚀 Unabhängiger Gateway-Dienst (v2 API)

Die Speicherkapazität ist nicht mehr an den OpenClaw-Host gebunden und wird als unabhängiger Dienst ausgeführt. Es ermöglicht das Lesen und Schreiben von Speicher sowie die Pipelineverwaltung für jeden Agenten über v2 HTTP API:

  • Vollständige Version 2 API: 14 Standardrouten, die alle Vorgänge wie Speicher-CRUD, atomare Aktualisierungen, Szenenindizierung, Pipeline-Statusabfrage usw. abdecken.
  • Pipeline-Statusabfrage (/v2/pipeline/status): Erhalten Sie den Betriebsstatus und den Fortschritt jeder Stufe von L1/L2/L3 in Echtzeit.
  • Instanzlebenszyklusverwaltung (/v2/instance/destroy): Unterstützen Sie externe Systeme beim aktiven Erstellen/Löschen von Speicherinstanzen.
  • Optionale Bearer-Authentifizierung + CORS-Whitelist: Schützen Sie die Sicherheit von API, das der Außenwelt ausgesetzt ist.
  • Überprüfung des Anforderungstexts: Erzwingen Sie eine Obergrenze von 1 MiB, um abnormale Anforderungen zu verhindern.

🚀 Offizielles SDK

  • TypeScript SDK 1.0.0 (@tencentdb-agent-memory/memory-sdk-ts): Typsicher, deckt alle v2 API ab, sofort einsatzbereit mit npm-Installation.
  • Python SDK (tencentdb-agent-memory-sdk-python): Pip-Wheel-Installation, synchroner/asynchroner Dualmodus, deckt alle v2 API ab.

🚀 Anpassung des Universal Agent-Frameworks

  • Anpassung des OpenClaw-Plug-ins: Unterstützt zwei Zugriffsmodi: local (wird lokal im Prozess ausgeführt, Standardeinstellung) und client (Verbindung mit externem Memory Gateway herstellen). Der local-Modus behält das ursprüngliche Erlebnis bei.
  • Hermes-Agent-Anpassung: memory_tencentdb_v2-Adapter, unterstützt das Multi-Tenant-Szenario des Hermes-Frameworks.
  • Universeller Zugriff: Jeder Agent, der HTTP-Anfragen senden kann (LangChain, AutoGPT, selbst entwickeltes Framework usw.), kann über SDK oder API darauf zugreifen.

🚀 Beobachtbarkeit

  • OpenTelemetry Full-Link-Trace: Unterstützt OTLP-Protokollberichte und kann mit Backends wie Jaeger / Grafana Tempo verbunden werden.
  • Langfuse-Integration: Leitet nur LLM-bezogene Spannen weiter, geeignet für die Bewertung der Qualität des Speicherabrufs.
  • Pipeline-Bewertungsindikatoren: L1-Extraktionsrate, Verteilung der Deduplizierungsentscheidung, Token-Verbrauch in jeder Phase, Rückrufverzögerung usw.

🚀 Server V2 auslagern

  • Asynchroner L1 / L1.5 / L2-Executor: unabhängige Offload-Verarbeitungspipeline, die eine groß angelegte Sitzungsgleichzeitigkeit unterstützt.
  • L3-Komprimierungsprozessor: Mermaid-Tokenisierung + Kontextbudgetkontrolle, intelligente Kontextkomprimierung.
  • MMD-Injektion: Unterstützt den multimodalen Dateninjektions-Offload-Prozess.
  • Gateway-integriertes /v2/offload/*-Routing: einheitlicher Offload API-Eingang.

📦 Bereitstellungsmethode

| Methode | Beschreibung | |------|------| | Docker Behälter | docker pull agentmemory/hermes-memory:1.0.0 | | Den Quellcode direkt ausführen | node --import tsx/esm src/gateway/server.ts | | OpenClaw-Plugin | Installiert über install-openclaw-plugin-v2.sh | | Hermes-Plugin | Integriertes memory_tencentdb_v2 Python-Plug-in |

⬆️ Upgrade-Anweisungen von 0.x

v1.0.0 und 0.x sind zwei parallel gepflegte Versionslinien:

  • 0.x (Zweig main): Integriertes OpenClaw-Plug-in, geeignet für einfache, eigenständige Szenarios
  • 1.x (Zweig feat/server): unabhängiger Speicherdienst, geeignet für die Bereitstellung mit mehreren Agenten/Multi-Frameworks/Diensten

Die Kernspeicher-Engines der beiden sind gleich (L0→L3-Schichtung + BM25/Vektor-Hybrid-Abruf + symbolisches Kurzzeitgedächtnis von Mermaid) und die Datenformate sind kompatibel.

🐛 Fix (v1.0.0-beta.2 → v1.0.0)

  • Das Hermes-Plugin install_hermes_tdai_gateway.sh wurde verbessert: Unterstützt den automatischen Root-Benutzerwechsel, die automatische Migration alter Pfade und die idempotente Erkennung, um wiederholte Installationen zu überspringen
  • Optimierung der Gateway-Konfiguration: Standardport 8420, zwei Umgebungsvariablen /etc/profile.d/ und ~/.hermes/.env synchron schreiben
  • SDK-Dokumentvervollständigung: TypeScript / Python SDK README und Zugriffsbeispiel
  • OpenClaw-Plugin.json-Konfigurationsanpassung: Entfernen Sie das veraltete Feld und passen Sie es an die neueste Version von OpenClaw an

  • Dokumentation zur eigenständigen Gateway-Bereitstellung.
  • Installationsanweisungen für das OpenClaw/Hermes-Plugin.
  • Docker-Bereitstellungs- und Konfigurationsreferenz.
