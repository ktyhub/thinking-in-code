Skywalking v10.2.0

Herunterladen

https://skywalking.apache.org/downloads/

Hinweis

Laden Sie keine Quellcodes von dieser Seite herunter. Bitte folgen Sie Build-Dokument, wenn Sie selbst Quellcodes erstellen möchten.

Kein H2, mehr BanyanDB

  • BanyanDB 0.8.0-Unterstützung hinzufügen.
  • H2-Speicheroption wird dauerhaft entfernt.

Projekt

  • Fügen Sie doc_values für Felder hinzu, die in Elasticsearch sortiert oder aggregiert werden müssen, und deaktivieren Sie alle anderen.
    • Diese Änderung hätte keine Auswirkungen auf die bestehende Bereitstellung und ihre Funktion für unsere offiziellen Release-Benutzer.
    • Warnung Wenn es benutzerdefinierte Abfrage-Plugins für unsere Elasticsearch-Indizes gibt, könnte diese Änderung diese beschädigen, da Sortierabfragen und Aggregationsabfragen, die die unerwarteten Felder verwendeten, blockiert werden.
  • [Breaking Change] debugging-query-Modul in status-query-Modul umbenennen. Relativ exponierte APIs sind UNVERÄNDERT.
  • [Breaking Change] Alle Jars des skywalking-oap-server werden nicht mehr über Maven Central veröffentlicht. Wir veröffentlichen nur den Quell-TAR und den Binär-TAR auf der Download-Seite der Website und docker-Bilder auf dem docker-Hub.
    • Warnung Wenn Sie skywalking-oap-server als Abhängigkeit in Ihrem Projekt verwenden, müssen Sie den Quell-TAR von der Website herunterladen und ihn in Ihrem privaten Maven-Repository veröffentlichen.
  • [Breaking Change] Entfernen Sie H2 dauerhaft als Speicheroption. BanyanDB 0.8 (OAP 10.2 erforderlich) ist einfach, stabil und produktionsbereit. Benötige H2 nicht mehr als Standardspeicher.
  • [Breaking Change] Erhöhen Sie die BanyanDB-Serverversion auf 0.8.0. Diese Version ist nicht mit den Vorgängerversionen kompatibel. Bitte aktualisieren Sie den BanyanDB-Server auf 0.8.0, bevor Sie OAP auf 10.2.0 aktualisieren.
  • Erweitern Sie nodejs auf v22.14.0 für die neueste UI-Kompilierung (Booster-UI).
  • tj-actions/changed-files nach dorny/paths-filter migrieren.

OAP-Server

  • Überspringen Sie die Verarbeitung von OTLP-Metrikdatenpunkten mit Flag FLAG_NO_RECORDED_VALUE, was zu außergewöhnlichen Ergebnissen führt.
  • Selbstbeobachtbarkeitsmetriken für die GraphQL-Abfrage hinzufügen, graphql_query_latency.
  • Reduzieren Sie die Anzahl der Prozessindizes und fügen Sie einen Zeitbereich hinzu, wenn Sie den Prozessindex abfragen.
  • Erweitern Sie Apache commons-io auf 2.17.0.
  • Polnische eBPF-So11y-Metriken und Fehleranzahl für Abfragemetriken hinzufügen.
  • Unterstützt Abfrageendpunktliste mit Dauerparameter (optional).
  • Ändern Sie endpoint_traffic für die zusätzliche Spalte last_ping in aktualisierbar.
  • Fügen Sie die Komponenten-ID (5023) für das GoZero-Framework hinzu.
  • Unterstützt die Kong-Überwachung.
  • Unterstützt das Hinzufügen zusätzlicher attr[0-5] für Metriken auf Service-/Endpunktebene.
  • Unterstützt die Async-Profiler-Funktion für die Leistungsanalyse.
  • Fügen Sie den Eigentümer des Metrikwerts für das TopN-Abfrageergebnis der Metriken hinzu.
  • Benennungssteuerung für EndpointDependencyBuilder hinzufügen.
  • Der Indextyp BanyanDB.IndexRule.IndexType#TREE wurde entfernt. Alle Indizes verwenden jetzt IndexType#INVERTED.
  • Fügen Sie BanyanDB Einstellungen für die maximale Abfragegröße hinzu.
  • Fix „BanyanDBTraceQueryDAO.queryBasicTraces“ unterstützt keine Abfrage nach „trace_id“.
  • Polnischer Mesh-Daten-Dispatcher: Instanz-/Endpunktmetriken werden nicht generiert, wenn sie leer sind.
  • Passen Sie die neue Metadatenstandardisierung in Istio 1.24 an.
  • Erhöhen Sie netty auf 4.1.115, grpc auf 1.68.1, Boringssl auf 2.0.69.
  • BanyanDB: Unterstützt die Aktualisierung der Gruppeneinstellungen beim Start von OAP.
  • BanyanDB: Indexmodus einführen und Banyandb-Gruppeneinstellungen umgestalten.
  • BanyanDB: Einführung der neuen Progressive TTL-Funktion.
  • BanyanDB: Unterstützt die Aktualisierung des Schemas beim Start von OAP.
  • BanyanDB: Beschleunigen Sie das OAP-Booten während der Initialisierung von BanyanDB.
  • BanyanDB: Unterstützt @EnableSort in der Spalte, um die Sortierung für IndexRule zu ermöglichen und den Standardwert auf „false“ zu setzen.
  • Unterstützt Get Effective TTL Configurations API.
  • Korrigieren Sie die gleichzeitige Änderung von ServerStatusService.statusWatchers.
  • Fügen Sie Schutz für die Weitergabekette dynamischer Konfigurationsänderungen hinzu.
  • Ruby-Komponenten-IDs hinzufügen (HttpClient=2, Redis=7, Memcached=20, Elasticsearch=47, Ruby=12000, Sinatra=12001).
  • Fügen Sie die Komponenten-ID (160) für Koffein hinzu.
  • Alarm: Unterstützt das Speichern und Abfragen des Messwert-Snapshots, wenn der Alarm ausgelöst wird.
  • Alarm: Nicht verwendete Alarm Trend-Abfrage entfernen.
  • Fehlende IP-Adresse des Remote-Endpunkts in der Span-Abfrage des Zipkin-Abfragemoduls behoben.
  • Korrigieren Sie die hierarchy-definition.yml-Konfigurationsdatei, die falsch in start.jar gepackt ist.
  • Fügen Sie die Konfigurationsdatei bydb.dependencies.properties hinzu, um Serverabhängigkeitsversionen zu definieren.
  • Fix AvgHistogramPercentileFunction verfügt nicht über die richtige Felddefinition für ranks.
  • BanyanDB: Unterstützt das neue Eigenschaftsdatenmodul.
  • MQE: Unterstützt die Funktion top_n_of zum Zusammenführen mehrerer Metriken in der Topn-Abfrage.
  • Unterstützt die Funktion labelAvg in der OAL-Engine.
  • Parameter maxLabelCount in der Funktion labelCount von OAL hinzugefügt, um die Anzahl der zählbaren Etiketten zu begrenzen.
  • Passen Sie das neue Browser-Protokoll API(/browser/perfData/webVitals, /browser/perfData/webInteractions, /browser/perfData/resources) an.
  • Schaltkreisunterbrechungsmechanismus hinzufügen.
  • BanyanDB: Unterstützung für Kompatibilitätsprüfungen basierend auf der API-Version des BanyanDB-Servers hinzugefügt.
  • MQE: Unterstützt die Bool-Operatoren &&(and) und ||(or).
  • OAP-Selbstbeobachtbarkeit: JVM-Metriken für Heap und Direktspeicher hinzufügen.
  • OAP-Selbstbeobachtbarkeit: Fügen Sie Wasserzeichen-Metriken für Stromkreisunterbrechung/-wiederherstellung hinzu.
  • KI-Pipeline: Unterstützt Abfragebasismetriknamen und prognostiziert den Metrikwert.
  • Fügen Sie Get Node List in the Cluster API hinzu.
  • Fügen Sie beim Konvertieren von Envoy-Protokollen in JSON einen Typdeskriptor hinzu, um die Persistenz zu gewährleisten und Konvertierungsfehler zu vermeiden.
  • Bseline: Unterstützung der Abfragebasislinie mit MQE und Verwendung in der Alarmregel.
  • Erhöhen Sie netty auf 4.11.118, um CVE-2025-24970 zu beheben.
  • Get Alarm Runtime Status API hinzufügen.
  • Fügen Sie lock hinzu, wenn Sie die Werte des Fensters „Alarmmetriken“ abfragen.
  • Fügen Sie einen ausfallsicheren Mechanismus hinzu, um zu verhindern, dass Verkehrsmetriken zwischen In-Memory- und Datenbankserver inkonsistent sind.
  • Fügen Sie klarere Protokolle hinzu, wenn das Format der oap-clusterinternen Daten (Metriken/Verkehr) inkonsistent ist.
  • Optimieren Sie das Laden des Metrik-Cache, wenn die Trace-Latenz größer als das Cache-Timeout ist.
  • Erlauben Sie den Anruf von lang.groovy.GString in DSL.
  • BanyanDB: Alarmabfrageergebnis ohne Sortierung korrigiert.
  • Fügen Sie eine Komponenten-ID für den virtuellen Thread-Executor hinzu.
  • Fügen Sie weitere Modellinstallationsprotokollinformationen für die OAP-Speicherinitialisierung hinzu.
  • BanyanDB: Trennen Sie die Speicherkonfiguration in eine unabhängige Datei: bydb.yaml.
  • Armeria auf 1.32.0 und einige transitive Abhängigkeiten übertragen.
  • Überspringen Sie persistente Metriken/Datensatzdaten, die abgelaufen sind.
  • Behebung des Problems fehlender Last-Ping-Daten.
  • HTTP-Header-Konfiguration für den Alarm-Webhook hinzufügen.
  • Erhöhen Sie BanyanDB Java client auf 0.8.0.
