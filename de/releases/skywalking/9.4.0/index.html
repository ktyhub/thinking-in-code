Projekt

  • Erhöhen Sie die Abhängigkeit von Zipkin und der Benutzeroberfläche von Zipkin-Objektiven auf 2.24.0.
  • Erhöhen Sie die Apache-Parent-POM-Version auf 29.
  • Upgrade der Armeria-Version auf 1.21.0.
  • Maven pom.xmls bereinigen.
  • Erhöhen Sie die Java-Version auf 11.
  • Erhöhen Sie Snakeyaml auf 2.0.

OAP-Server

  • Fügen Sie ServerStatusService im Kernmodul hinzu, um eine neue Möglichkeit zu bieten, den Startstatus anderen Modulen anzuzeigen.
  • Fügt Mikrometer als neue Komponente hinzu. (ID=141)
  • Sitzungscache in MetricsPersistentWorker umgestalten.
  • Cache-Verbesserung – Lesen Sie keine neuen Metriken aus der Datenbank in winziger Dimensionalität.
    // When
    // (1) the time bucket of the server's latest stability status is provided
    //     1.1 the OAP has booted successfully
    //     1.2 the current dimensionality is in minute.
    //     1.3 the OAP cluster is rebalanced due to scaling
    // (2) the metrics are from the time after the timeOfLatestStabilitySts
    // (3) the metrics don't exist in the cache
    // the kernel should NOT try to load it from the database.
    //
    // Notice, about condition (2),
    // for the specific minute of booted successfully, the metrics are expected to load from database when
    // it doesn't exist in the cache.
  • Entfernen Sie den Offset des Metrik-Sitzungs-Timeouts entsprechend der Worker-Erstellungssequenz.
  • Korrigierte MetricsExtension-Anmerkungsdeklarationen in manuellen Entitäten.
  • Unterstützen Sie die Priorität der Komponenten-IDs in Prozessbeziehungsmetriken.
  • Entfernen Sie die Abbruchlogik in MergableBufferedData, die zu einer unerwarteten Nichtaktualisierung führte.
  • Behebung des fehlenden Satzes LastUpdateTimestamp, der zum Ablauf der Metriksitzung führte.
  • Benennen Sie die MAL-Regel spring-sleuth.yaml in spring-micrometer.yaml um.
  • Speicherleck in Zipkin API behoben.
  • Entfernen Sie die Abhängigkeit von refresh_interval von ElasticSearch-Indizes aus der elasticsearch/flushInterval-Konfiguration. Nun, es verwendet stattdessen core/persistentPeriod + 5s als refresh_interval für alle Indizes.
  • elasticsearch/flushInterval in 5 Sekunden ändern (vorher 15 Sekunden).
  • Optimieren Sie flushInterval des ElasticSearch BulkProcessor, um zusätzliche periodische Spülungen in den kontinuierlichen Massenströmen zu vermeiden.
  • Ein unerwarteter Punkt wird hinzugefügt, wenn exp ein reiner Metrikname ist und expPrefix != null ist.
  • Unterstützt die Überwachung von MariaDB.
  • Mess-/Stream-spezifische Intervalleinstellungen in BanyanDB entfernen.
  • Fügen Sie globalspezifische Einstellungen hinzu, die zum Überschreiben globaler Konfigurationen (z. B. segmentIntervalDays, blockIntervalHours) in BanyanDB verwendet werden.
  • Verwenden Sie TTL-gesteuerte Intervalleinstellungen für die measure-default-Gruppe in BanyanDB.
  • Falsche Gruppe nicht zeitrelativer Metadaten in BanyanDB behoben.
  • Refaktorieren Sie StorageData#id von einem String-Typ in das neue StorageID-Objekt.
  • Unterstützt mehrere Komponenten-IDs in der Service-Topologieebene.
  • Fügen Sie die Annotation ElasticSearch.Keyword hinzu, um den Zielfeldtyp als keyword zu deklarieren.
  • [Breaking Change] Die Spalten component_id von service_relation_client_side und service_relation_server_side wurden durch component_ids ersetzt.
  • Unterstützt die priority-Definition im component-libraries.yml.
  • Verbesserung der Service-Topologie-Abfrage. Wenn auf der Serverseite mehrere Komponenten erkannt werden, Der Komponententyp des Knotens würde durch die Priorität bestimmt, die in der vorherigen Version zufällig war.
  • Entfernen Sie component_id von service_instance_relation_client_side und service_instance_relation_server_side.
  • Machen Sie den Satelliten-E2E-Test stabiler.
  • Fügen Sie Istio 1.16 zur Testmatrix hinzu.
  • Registrieren Sie ValueColumn als Tag für Datensatz im BanyanDB-Speicher-Plugin.
  • Erhöhen Sie Netty auf 4.1.86.
  • Entfernen Sie unnötige zusätzliche Spalten, wenn sich der Speicher im logischen Sharding-Modus befindet.
  • Der Cluster-Koordinator unterstützt den Überwachungsmechanismus zur Benachrichtigung von RemoteClientManager und ServerStatusService.
  • Behebung: ServiceMeshServiceDispatcher überschreibt die ServiceDispatcher-Debugdatei, wenn SW_OAL_ENGINE_DEBUG geöffnet wird.
  • Verwenden Sie die Operatoren groupBy und in, um die Topologieabfrage für das BanyanDB-Speicher-Plugin zu optimieren.
  • Unterstützt den Server-Status-Watcher für MetricsPersistentWorker, um die Metriken zu überprüfen, ob eine Initialisierung erforderlich ist.
  • Korrigieren Sie, dass der Zählerwert nicht korrekt ist, wenn Sie die MAL-Funktion sumPerMinLabeld oder sumHistogramPercentile verwenden.
  • Fix: Angehängte Ereignisse können nicht angezeigt werden, wenn Abfragespuren der Zipkin Lens-Benutzeroberfläche verwendet werden.
  • Entfernen Sie time_bucket für die Stream- und Measure-Typen im BanyanDB-Plugin.
  • TIME_BUCKET von Metrics und Record zu StorageData zusammenführen.
  • Unterstützt kein layer in der listServices-Abfrage.
  • Behebung, dass time_bucket von ServiceTraffic in slowSql von MAL nicht richtig eingestellt ist.
  • Korrigieren Sie das TopN-Datensatzabfrage-DAO von BanyanDB.
  • Optimieren Sie die Intervalleinstellungen von BanyanDB.
  • Unterstützung der Überwachung von AWS Cloud EKS.
  • Bump BanyanDB Java client zu 0.3.0-rc1.
  • Entfernen Sie das id-Tag aus den Kennzahlen.
  • Fügen Sie Banyandb.MeasureField hinzu, um eine Spalte als BanyanDB-Kennzahlfeld zu markieren.
  • Fügen Sie BanyanDB.StoreIDTag hinzu, um die ID eines Prozesses für die Suche zu speichern.
  • [Breaking Change] Die unterstützte Version von ShardingSphere-Proxy wird von 5.1.2 auf 5.3.1 aktualisiert. Aufgrund der Änderungen von ShardingSpheres API sind Versionen vor 5.3.1 nicht kompatibel.
  • Fügen Sie den eBPF-Netzwerkprofilierungs-E2E-Test im Pro-Speicher hinzu.
  • Bei TCP-Dienstinstanzen fehlen Instanzeigenschaften wie pod und namespace, was dazu führt, dass das Pod-Protokoll für TCP-Arbeitslasten nicht funktioniert.
  • Fügen Sie die Komponenten-ID (94) des HBase-Happybase-Moduls Python hinzu.
  • Fix gRPC-Alarm kann Einstellungen nicht von der dynamischen Konfigurationsquelle aktualisieren.
  • Fügen Sie die Konfiguration batchOfBytes hinzu, um die Größe der Massenspülung zu begrenzen.
  • Fügen Sie die Websocket-Modulkomponenten-ID Python (7018) hinzu.
  • [Optional] Optimieren Sie die Leistung einzelner Trace-Abfragen, indem Sie das Routing in ElasticSearch anpassen. SkyWalking-Trace-Segmente und Zipkin-Spans verwenden Trace-ID für das Routing. Dies ist standardmäßig AUS und wird von storage/elasticsearch/enableCustomRouting gesteuert.
  • Erweitern Sie den OAP-HTTP-Server zur Unterstützung von HTTPS
  • Handler-Scan im Hotelempfänger entfernen, stattdessen manuelle Initialisierung
  • Fügen Sie aws-firehose-receiver hinzu, um die Erfassung von AWS CloudWatch-Metriken (OpenTelemetry-Format) zu unterstützen. Hinweis: Kein HTTPS/TLS-Setup Unterstützung. Durch Befolgen der AWS Firehose-Anfrage wird Proxy-Anfrage verwendet. (https://... statt /aws/firehose/metrics), es muss ein Proxy vorhanden sein (Nginx, Envoy usw.).
  • Vermeiden Sie, dass die Versionen von Antlr-Abhängigkeiten in der Kompilierungszeit und Laufzeit unterschiedlich sein können.
  • Jetzt unterstützt PrometheusMetricConverter#escapedName auch die Konvertierung von / in _.
  • Fügen Sie fehlende TCP-Durchsatzmetriken hinzu.
  • Refaktorieren Sie die Annotation @Column, tauschen Sie Column#name und ElasticSearch.Column#columnAlias aus und benennen Sie ElasticSearch.Column#columnAlias in ElasticSearch.Column#legacyName um.
  • Fügen Sie die HTTPX-Modulkomponenten-ID Python (7019) hinzu.
  • Tests von Juni 4 auf Juni 5 migrieren.
  • HTTP-basierte Alarm-Plugins umgestalten und gemeinsame Logik in HttpAlarmCallback extrahieren.
  • Unterstützt die Metriküberwachung des Amazon Simple Storage Service (Amazon S3).
  • Unterstützt Prozesssummenmetriken im Fall AGGREGATION_TEMPORALITY_DELTA
  • Unterstützt die Amazon DynamoDB-Überwachung.
  • Unterstützt prometheus HTTP API und promQL.
  • Scope im Entity of Metrics-Abfrageprotokoll v1 ist nicht erforderlich und automatische Korrektur. Der Umfang wird anhand der Metrik selbst bestimmt.
  • Fügen Sie explizites ReadTimeout für ConsulConfigurationWatcher hinzu, um IllegalArgumentException: Cache watchInterval=10sec >= networkClientReadTimeout=10000ms zu vermeiden.
  • DurationUtils.getDurationPoints-Überschreitung beheben, wenn startTimeBucket gleich endTimeBucket ist.
  • Unterstützt den Prozess OpenTelemetry ExponentialHistogram-Metriken
  • FreeRedis-Komponenten-ID (3018) hinzufügen.

Benutzeroberfläche

  • Fügen Sie die Benutzeroberfläche von Zipkin Lens zur Webanwendung hinzu und stellen Sie sie als Proxy für den Kontextpfad /zipkin bereit.
  • Migrieren Sie das Build-Tool von vue cli nach Vite4.
  • Die Dashboards „Fix Instance Relation“ und „Endpoint Relation“ werden angezeigt.
  • Mikrometer-Symbol hinzufügen.
  • Aktualisieren Sie die Benutzeroberfläche von MySQL, um MariaDB zu unterstützen.
  • AWS-Menü zur Unterstützung der AWS-Überwachung hinzufügen.
  • Fehlendes FastAPI-Logo hinzufügen.
  • Aktualisieren Sie die Protokolldetailseite, um die formatierte Anzeige von JSON-Inhalten zu unterstützen.
  • Build-Konfiguration korrigieren.
  • Vermeiden Sie, dass Sie Prozessknoten zum ersten Mal nicht ziehen können.
  • Knotenordner zur Ignorierliste hinzufügen.
  • ElPopconfirm zu Komponententypen hinzufügen.
  • Fügen Sie ein Iframe-Widget für die Zipkin-Benutzeroberfläche hinzu.
  • Optimieren Sie die Tooltips für Diagramme, um sie benutzerfreundlicher zu gestalten.
  • Erhöhen Sie json5 von 1.0.1 auf 1.0.2.
  • Websockets-Symbol hinzufügen.
  • Implementieren Sie einen unabhängigen Modus für Widgets.
  • Erhöhen Sie die HTTP-Cache-Semantik von 4.1.0 auf 4.1.1.
  • Menüs für OpenFunction aktualisieren.
  • Automatische Aktualisierung zum Widget-unabhängigen Modus hinzufügen.
  • Fix: Löschen Sie die Trace-ID in den Protokoll- und Trace-Widgets nach Verwendung der Zuordnung.
  • Fix: Dauer für Abfragebedingungen nach Zeitbereichsänderungen zurücksetzen.
  • AWS S3-Menü hinzufügen.
  • Refactor: Optimieren Sie die Seitenleistenkomponente, um sie benutzerfreundlicher zu machen.
  • Fix: Doppelte Popup-Nachricht für das Abfrageergebnis entfernen.
  • Logo für HTTPX hinzufügen.
  • Refactor: Optimieren Sie die Visualisierung angehängter Ereignisse im Trace-Widget.
  • BanyanDB client auf 0.3.1 aktualisieren.
  • AWS DynamoDB-Menü hinzufügen.
  • Fix: Automatische Periode zum unabhängigen Modus für Widgets hinzufügen.
  • Menüs optimieren und Windows-Überwachungsmenü hinzufügen.
  • Fügen Sie eine Berechnung für den cpm5dAvg hinzu.
  • Fügen Sie eine cpm5d-Berechnung hinzu.
  • Datenverarbeitungsfehler im eBPF-Profiling-Widget behoben.
  • Unterstützung für doppelte Anführungszeichen in SlowSQL-Anweisungen.
  • Fix: Die falsche Position des Menüs beim clicken des Topologieknotens.

Dokumentation

  • Entfernen Sie die Spring Sleuth-Dokumente und fügen Sie Spring MicroMeter Observations Analysis mit der neuesten Java-Agent-Seite hinzu Verbesserung.
  • Aktualisieren Sie monitoring MySQL document, um den Teil MariaDB hinzuzufügen.
  • Ordnen Sie die Protokolldokumente in eine klarere API-Dokumentation um.
  • Dokumentation zum Ersetzen des Zipkin-Servers durch SkyWalking OAP hinzufügen.
  • Fügen Sie relative Dokumente zur Lens-Benutzeroberfläche im Zipkin-Trace-Abschnitt hinzu.
  • Profiling APIs hinzufügen.
  • Backend-Telemetriedokument und so11y Dashboard-Dokument korrigiert, da der OAP Prometheus-Abrufer seit 9.3.0 entfernt wurde
