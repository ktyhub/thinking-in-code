claude-code v2.1.288

Patch Veröffentlicht2. Okt. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.288

Was hat sich geändert?

  • $.ui.selection() für Mods hinzugefügt: Gibt den Text zurück, den Sie zuletzt im Vollbildmodus ausgewählt haben, und, wenn die Auswahl innerhalb einer Transkriptzeile liegt, diese Zeile – Ein integriertes gh api zu Cloud-Sitzungen hinzugefügt, deren Image kein GitHub CLI hat, und das integrierte Senden von Steuerzeichen aus Dateinamen, JQ-Filtern oder GitHub-Fehlern an das Terminal behoben – Wiederherstellung für eine Eingabeaufforderung hinzugefügt, die mit Strg+C gelöscht wurde: Wenn Sie bei der leeren Eingabeaufforderung nach oben drücken, wird der Entwurf zurückgebracht, einschließlich eingefügtem Text und Bildern – Es wurde eine Aufforderung zur erneuten Authentifizierung hinzugefügt, wenn ein MCP-Server während eines Tool-Aufrufs nach mehr OAuth-Bereich fragt – --max-findings <n>|all zu /code-review hinzugefügt, um mehr oder weniger Ergebnisse als das übliche Limit zu melden; Die Auswahl wird wiederverwendet, bis Sie --max-findings default passieren – Strg+F hinzugefügt, um eine Sitzung anhand des Namens zu finden, und Alt+ ↑/↓, um zwischen Gruppen in der Agentenansicht zu wechseln; Beide und Umbenennen können in keybindings.json erneut gebunden werden – Es wurde eine Bildschirmlesemodus-Ankündigung des neuen Berechtigungsmodus hinzugefügt, wenn Sie einen Plan genehmigen, auch mit Umschalt+Tab – Es wurden API-Zeitüberschreitungen während der Antwort behoben, bei denen die Runde fehlschlug: Nicht-interaktive Sitzungen und Subagenten fahren jetzt mit der Teilantwort fort, und Antworten, die nur zum Denken gedacht sind, werden erneut versucht – Es wurde behoben, dass lange Konversationen mit der Meldung „Eingabeaufforderung ist zu lang“ fehlschlugen, anstatt automatisch zu komprimieren, wenn die letzte Antwort keine Token-Nutzung meldete – Behoben, dass --resume manchmal Dateien und anderen Kontext fallen ließ, der gerade durch eine Komprimierung wiederhergestellt wurde – Ein Problem wurde behoben, bei dem eine fortgesetzte Sitzung manchmal nicht die letzte Antwort einer Runde speicherte, sodass beim nächsten --resume die Eingabeaufforderung unbeantwortet angezeigt wurde – Problem behoben, bei dem das Laden eines Transkripts beim Fortsetzen gelegentlich abgebrochen wurde, wenn dieselbe Sitzung die Datei während des Ladens neu schrieb – Problem behoben, bei dem das Fortsetzen einer Konversation, die auf 2.1.286 oder früher begonnen wurde, dazu führte, dass das frühere Denken des Modells verloren ging – Problem behoben, bei dem Sitzungstitel, Speicherabrufe und Eingabeaufforderungs-Hooks auf Mantle oder hinter Gateways, die strukturierte Ausgaben ablehnen, fehlschlugen; CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS hinzugefügt, um strukturierte Ausgaben auszuschalten
  • Fehler im automatischen Modus behoben, die Claude auf eine Bash-Berechtigungsregel verwiesen, wenn das blockierte Tool nicht Bash war – Der automatische Modus beim Umschalten von Bedrock und Mantle auf den lokalen Klassifikator für den Rest der Sitzung nach einer Anfrage an ein älteres Modell, z. B. eine WebFetch-Zusammenfassung oder einen sonnet-Subagenten, wurde behoben – Behoben: Cloud-Sitzungen, die bei einem neu ausgewählten Modell neu gestartet wurden und mit diesem Modell antworteten, nachdem der Server dies abgelehnt hatte – Behoben: Cowork-Cloud-Sitzungen blieben als „auf Eingabe wartend“ markiert, nachdem eine WebFetch-Berechtigungsaufforderung für eine nicht genehmigte URL fünf Minuten lang unbeantwortet blieb – Problem behoben, bei dem Eingabeaufforderungsvorschläge nicht auf einem Telefon angezeigt wurden, das an einer Cowork-Cloud-Sitzung teilnahm, die auf einem anderen Gerät gestartet wurde
  • Behoben, dass die Schaltfläche eines Mods manchmal eine andere Schaltflächenaktion ausführte, wenn sie in einer Ansicht gedrückt wurde, die vor dem Neustart von Claude Code gezeichnet wurde – Problem behoben, bei dem im Bereich eines Plugins nichts angezeigt wurde, wenn ein Code-Element ein Diff enthielt, das nicht geparst werden kann; es wird jetzt als einfacher Code gezeichnet – Problem mit Plugin-LSP-Servern behoben, die in initializationOptions und settings die Platzhalter literal ${user_config.*} und ${CLAUDE_PLUGIN_ROOT} anstelle von Ersatzwerten oder Manifest-Standardwerten empfangen – Der tool.call-Hook eines Plugins wurde behoben, der dazu führte, dass Bash fehlschlug und Dateisuchen den falschen Ordner in Subagenten lasen, die in einem Arbeitsbaum ausgeführt wurden – Problem behoben, bei dem die Installation des git-subdir-Plugins auf älteren Gits fehlschlug oder ein unvollständiges Plugin zwischengespeichert wurde (vor 2.39, z. B. 2.34 von Ubuntu 22.04) – Problem behoben, bei dem Plugins, die mit --plugin-dir geladen wurden, in /plugin nicht „Optionen konfigurieren“ anzeigten – Problem behoben, bei dem Hintergrundsitzungen endeten, wenn ein Plugin neu geladen oder deaktiviert wurde, während einer seiner Timer oder Lesevorgänge noch lief – Sandbox-Heredocs mit einem Trennzeichen ohne Anführungszeichen (python3 <<EOF) behoben, die bei jeder Ausführung unter Sandbox-Auto-Allow nach Genehmigung fragten, wenn der Text nur einfachen Text und einfache $VAR-Referenzen enthielt – Die Berechtigungsprüfung des Bash-Tools wurde korrigiert, sodass vor einer BASHPID-Zuweisung, deren Wert die Shell als arithmetisch auswertete, eine Eingabeaufforderung angezeigt wurde, anstatt sie stillschweigend zuzulassen – Behoben, dass Vollbildsitzungen mit „nicht behebbarem Schnittstellenfehler“ beendet wurden, wenn das Dialogfeld „Hintergrundaufgaben“ geöffnet wurde, während ein Plugin oder Mod Zeilen über der Eingabeaufforderung anzeigte
  • Problem behoben, bei dem Claude eine Nachricht an eine andere Sitzung als zugestellt gemeldet hat, obwohl diese Sitzung sie gehalten hat: In der Mitteilung heißt es jetzt, dass sie nicht zugestellt wurde, und nennt die Sitzung, und in SDK-Sitzungen kann Claude jetzt mitten in der Runde davon erfahren – Behoben: OpenTelemetry claude_code.tool.blocked_on_user umfasst die Meldung von unknown-Quellen oder -Entscheidungen in -p- und SDK-Sitzungen und für PreToolUse-Hook-Genehmigungen
  • Behoben: Erlaubnisanfragen, die unbeantwortet endeten, in -p oder in einer unterbrochenen Runde, und kein tool_decision-Ereignis auslösten – Problem behoben, bei dem „Bearbeiten und erneut versuchen“ in Cowork-Cloud-Sitzungen dazu führte, dass eine vor /compact gesendete Nachricht abgelehnt wurde, obwohl deren Verlauf noch gespeichert war – Problem behoben, bei dem unbeaufsichtigte Sitzungen (CLAUDE_CODE_RETRY_WATCHDOG) stundenlang wiederholt wurden, nachdem ein sehr langer Antwortstream fehlgeschlagen war; Claude Code streamt nun wieder und gibt nach drei Timeouts auf – Problem behoben, bei dem /login die Meldung „Anmeldung erfolgreich“ meldete, wenn Anmeldeinformationen nicht im sicheren Speicher gespeichert werden konnten; Es zeigt jetzt den Fehler an und bietet einen erneuten Versuch an, wenn die neue Anmeldung nicht wirksam wurde (anthropics/claude-code#73861) – Ein Stopp während der Bedrock-Anmeldeinformationssuche wurde behoben, der manchmal dazu führte, dass die Sitzung auf ein Fallback-Modell verschoben wurde, anstatt die Anfrage zu beenden – Ein zweiter gcpAuthRefresh/awsAuthRefresh-Browser-Anmeldevorgang wurde behoben, der sich öffnete, wenn ein Laptop aus dem Ruhezustand erwachte, während sich ein anderer Claude-Code-Prozess anmeldete
  • Agententeams korrigiert: Ein durch ein Plugin definierter Agent, der nach Namen erzeugt wird, wird jetzt mit seiner eigenen Eingabeaufforderung, seinen eigenen Tools, nicht zugelassenen Tools und seinem eigenen Aufwand anstelle der Standardeinstellungen ausgeführt – Problem behoben, bei dem Headless-Sitzungen (-p / SDK) gelegentlich SIGTERM ignorierten, wenn ein Supervisor wie timeout oder systemd daneben SIGCONT sendete – Problem behoben, bei dem neu gestartete Cloud-Sitzungen ein Modell wiederherstellten, das von der Liste der erzwungenen Modelle der Organisation abgelehnt wurde – Behoben, dass MCP-Tool-Aufrufe manchmal zweimal ausgeführt wurden, wenn das Ergebnis eines Remote-Servers über 16 MB lag oder nicht analysiert werden konnte – Problem behoben, bei dem Subagenten in der Code-Registerkarte von Claude Desktop keines der Tools eines vom Benutzer konfigurierten MCP-Servers namens memory erhielten – Problem behoben, bei dem Claude in Chrome vor jedem Screenshot und jedem Lesen einer Seite auf einer Website gefragt hat, die Sie zugelassen haben, wenn der automatische Modus nicht verfügbar ist (z. B. bei disableAutoMode oder einem älteren Modell); Eingabe, Navigation und JavaScript fragen immer noch – Fehler behoben, bei dem claude plugin install für GitHub-Quell-Plugins auf macOS- und Linux-Maschinen ohne GitHub-SSH-Schlüssel fehlschlug: Der Klon greift jetzt auf HTTPS zurück und gibt einen Hinweis aus – Behoben, dass sandbox.credentials.files-Einträge in Git-Konfigurationsdateien nicht wirksam wurden, während permissions.blockReadsOutsideWorkingDirectories aktiviert ist – Problem behoben, bei dem Claude die Designsysteme Ihrer Organisation ausließ, wenn er Folien oder ein Design mit dem Artefakt-Tool auf Team- und Enterprise-Plänen oder auf Computern mit verwalteten Einstellungen startete – Behoben, dass die Tastatur unter Windows nach dem Neustart von Claude Code nicht funktionierte (erste Anmeldung bei einem Claude-Apps-Gateway, Anbieter-Setup, /tui) – Ein Problem beim Starten eines Agenten, dessen tools: sehr viele Agent(...)-Einträge auflistet, wurde behoben – Behoben, dass Sitzungen zu Claude 3 Opus und Claude 3 Sonnet immer dann fehlschlugen, wenn ein ganzes PDF in die Konversation eintrat – Der automatische NPM-Updater meldete erfolgreich einen Fehler, wenn der Download der plattformnativen Binärdatei fehlschlug und nur der Platzhalter claude-Stub installiert wurde – Die Remote Control-Bereinigung archivierte eine Sitzung, die noch verbunden ist oder gerade von einem anderen Claude Code-Prozess wieder angehängt wurde – Problem behoben, bei dem owner/repo-Plugin-Marktplätze nur den Fehler beim zweiten Versuch anzeigten, wenn sowohl der SSH- als auch der HTTPS-Abruf fehlschlugen; Es werden nun beide Fehler angezeigt, wobei der zuerst versuchte Transport oben steht – Problem behoben, bei dem pfadbezogene .claude/rules- und verschachtelte CLAUDE.md-Dateien nicht geladen wurden, wenn durch Schreiben oder Bearbeiten eine Datei in ihrem Gültigkeitsbereich erstellt oder geändert wurde (zuvor wurden sie nur durch Lesen geladen). – Ein gefährlicher rm (z. B. einer auf / oder im Home-Verzeichnis) in einem bash -c- oder sh -c-Skript behoben, das ohne Eingabeaufforderung im BypassPermissions-Modus oder unter einer Shell-Zulassungsregel ausgeführt wurde (anthropics/claude-code#96300) – Problem behoben, bei dem LSP-Tool-Aufrufe auf unbestimmte Zeit hängen blieben, wenn ein Sprachserver die dynamische Funktionsregistrierung nutzte oder nicht mehr reagierte; Anfragen laufen jetzt nach 60 Sekunden ab (pro Server requestTimeout) – Problem behoben, bei dem idle_prompt-Benachrichtigungs-Hooks ausgelöst wurden, während Hintergrundagenten noch ausgeführt wurden (anthropics/claude-code#93672) – Problem behoben, bei dem PreToolUse- und PermissionRequest-Hooks übersprungen wurden, wenn der Abgleich fehlschlug oder die Eingabe des Tools nicht in JSON serialisiert werden konnte; Der Anruf ist jetzt blockiert – Die erste Anfrage in einer neuen Umgebung oder nach einem Modellwechsel wurde mithilfe des integrierten Ausgabelimits und des automatischen Komprimierungsfensters behoben, nicht des Servers; Diese Anfrage kann nun bis zu 1.5 Sekunden warten
  • Das Problem „Was sollte Claude stattdessen tun?“ wurde behoben. Hinweis, der in der Zeile „Unterbrochen“ angezeigt wird, nachdem Nachrichten in der Warteschlange mit Strg+Eingabe gesendet wurden – /login in einer --bare-Sitzung behoben, bei der eine Anmeldung ausgeführt wurde, die die Sitzung nie liest, was Ihre gespeicherte Anmeldung ersetzen könnte; Es steht nun, welche Anmeldeinformationen funktionieren – Der „InstructionsLoaded“-Hook wurde behoben, der agent_id und agent_type wegließ, wenn der Dateizugriff eines Subagenten eine Regel oder verschachtelte CLAUDE.md lädt; Regeln und verschachtelte CLAUDE.md-Dateien, die beim Dateizugriff geladen werden, melden jetzt auch den Aufwand – Problem behoben, bei dem das Agenten-Tool in claude mcp serve immer keine verfügbaren Agenten meldete und jeden Subagententyp ablehnte – Es wurde behoben, dass der Terminal-Cursor dem eingegebenen Text in der Suche des Vollbild-Transkript-Viewers und in der benutzerdefinierten Farbsuche von /theme nicht folgte
  • /permissions im Bildschirmlesemodus behoben: Durch die Eingabe der Nummer einer Regel wird diese jetzt ausgewählt, anstatt das Suchfeld zu öffnen
  • Verbesserter automatischer Modus: Wenn eine Konversation zu lang wird, als dass sie vom client-seitigen Sicherheitsklassifikator überprüft werden könnte, wird sie jetzt komprimiert, anstatt bei jedem Tool-Aufruf eine Aufforderung zu erfragen oder fehlzuschlagen
  • Verbesserter Screenreader-Modus: Kurze Ankündigungen, z. B. ein gelöschtes Wort, bleiben jetzt auf dem Bildschirm, bis Sie das nächste Mal eine Taste drücken oder bis sich etwas darüber auf dem Bildschirm ändert
  • Verbesserter Screenreader-Modus: Bei beantworteten Fragen in Fragedialogen wird jetzt neben dem Feld „beantwortet“ angezeigt – Die /usage-credits-Nachricht, die Team- und Enterprise-Mitgliedern angezeigt wird, deren Organisation Anfragen zur Nutzungsgutschrift deaktiviert hat, wurde verbessert
  • Verbesserte Cloud-Sitzungen: Die erste Runde einer neuen Konversation wartet nicht mehr auf einen Standard-MCP-Server, dessen Konfiguration alwaysLoad: false festlegt
  • Verbesserte „Sie sollten es wissen“-Notizen, um „wir“, „der Hauptagent“ oder „Sie“ zu sagen, je nachdem, wer für eine Entscheidung verantwortlich war – Der Fehler, der auftritt, wenn das Schreiben einer Artefaktdatenbank aufgrund der Größenbeschränkung der Datenbank verweigert wird, wurde verbessert: Es werden nun die Beschränkung und der freiwerdende Speicherplatz angegeben – Verbesserte Bash-Berechtigungsaufforderungen, um einen kürzeren Grund anzugeben, wenn ein Teil eines Befehls vor seiner Ausführung nicht überprüft werden kann
  • Selbstgehosteter Läufer: Der integrierte gh api wurde verbessert: Ein abgelehnter gh-Befehl gibt jetzt sein gh api-Äquivalent aus, --paginate folgt jeder Seite der Listen eines Repositorys und ein verschachtelter claude entfernt ihn nicht mehr – Verbesserte Wiederherstellung von Remote Control nach abgelaufenen Serveranmeldeinformationen: Sitzungen bleiben während der Erneuerung verbunden und werden beibehalten, wenn sie nach einem Serverausfall aufgegeben wird – Das Zeitlimit für Hintergrundbefehle wurde so geändert, dass es nur in unbeaufsichtigten Sitzungen gilt (-p, Agent SDK, CI, Cloud); Terminal-, Desktop-App- und VS-Code-Sitzungen sind unbegrenzt – Der client-seitige Auto-Modus-Klassifikator wurde geändert, um einen ANTHROPIC_DEFAULT_SONNET_MODEL-Pin mit dem Namen Claude Sonnet 5.5 oder Opus 5.5 zu ignorieren und stattdessen Claude Sonnet 5 zu verwenden
  • claude project purge in claude purge geändert; Der alte Name funktioniert immer noch und druckt einen Hinweis – Der n:-Filter für die Agentenansicht (und die Strg+F-Suche) wurde geändert, sodass Enter die Sitzung öffnet, deren Name am besten übereinstimmt, und nicht die oberste Zeile
  • /autocompact wurde geändert, um das automatische Komprimierungsfenster pro Modell zu speichern, sodass jedes Modell beim Wechsel seine eigene Einstellung behält – Geänderte MCP-URL-Eingabeaufforderungen von Servern, die nicht melden können, wenn Sie fertig sind, um auf „Ich bin fertig, fortfahren“ zu warten, bevor der Tool-Aufruf fortgesetzt wird, sodass Sie zuerst im Browser fertig werden können – [VSCode] Ein claude.ai-Connector wurde behoben, der nach der Autorisierung auf „Authentifizierung erforderlich“ blieb: Das Dialogfeld „MCP-Server“ bietet jetzt „Verbindung prüfen“ an – [VSCode] Die Opt-in-Tastenkombination „Neue Konversation“ (Befehl/Strg+N) wurde korrigiert, die eine Konversation in jeder sichtbaren Claude-Ansicht startete, anstatt nur in der, in der Sie sich befinden
  • [VSCode] Die Chat-Ansicht wurde korrigiert, sodass die nächste gespeicherte Sitzung fortgesetzt wurde, nachdem Sie die angezeigte Sitzung archiviert haben. Stattdessen wird jetzt eine neue Konversation gestartet
  • [Cloud-Sitzungen] Der Cloud-Sitzungsschalter in den Claude Code-Administratoreinstellungen blieb gesperrt, während eine nicht verwandte Sicherheitseinstellung geladen wurde oder nicht geladen werden konnte – [Cloud-Sitzungen] Problem behoben, bei dem das Drücken von „Stopp“, während ein selbst gehosteter Läufer noch startete, dazu führte, dass die Nachricht in der Warteschlange nicht abgebrochen wurde, die dann ausgeführt werden konnte, sobald der Läufer aktiv war
  • [Claude Tag] Die Administratoreinstellungen von Claude Tag wurden korrigiert und boten auf Kanälen, deren Einstellungen automatisch erstellt wurden, die Option „Diesen Bereich entfernen“, die immer fehlschlug
  • [Claude Tag] Claude wurde verbessert, um auch einem verwandten Slack-Thread in einem anderen Kanal zu folgen, den er nur liest, sodass Aktualisierungen dort die Konversation erreichen, die von ihnen abhängt
  • [Claude Tag] Speicherfehler auf der Konfigurationsseite eines Kanals verbessert: Zu lange Kanalanweisungen sagen jetzt, dass man sie kürzen soll, und ein wegen verlorenem Zugriff abgelehnter Speichervorgang sagt nicht mehr, dass man es noch einmal versuchen soll – Problem behoben, bei dem claude plugin test-Mods die Meldung aus der Ferne deaktivierten, wenn nur eine veraltete gespeicherte Einstellung gelesen wurde
