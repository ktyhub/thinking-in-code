claude-code v2.1.287

Patch Veröffentlicht1. Okt. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.287

Was hat sich geändert?

  • Claude Mods hinzugefügt: Plugins können jetzt tiefergehendes Verhalten ändern
  • Hinzugefügt: Sie sollten wissen, ein integrierter Mod, bei dem ein Nebenagent auf Sie aufpasst und Dinge markiert, die Sie oder Claude möglicherweise übersehen. Schalten Sie es mit /plugin enable cc-plugin-you-should-know@builtin ein (für Erstanbietersitzungen mit aktivierter Telemetrie). – Der Agentenansicht wurde ein n:<text>-Filter hinzugefügt, der Sitzungsnamen und Aufgaben abgleicht; Ein Filter zeigt jetzt Übereinstimmungen in minimierten Abschnitten an und Enter öffnet die erste Übereinstimmung – prompt_text zum OpenTelemetry user_prompt-Ereignis hinzugefügt, eine Kopie von prompt für Backends, die punktierte Schlüssel verschachteln; Lassen Sie es dort fallen oder maskieren Sie es, wo immer Sie prompt (anthropics/claude-code#70763) ablegen oder maskieren. – URL-Eingabeaufforderungen von MCP-Servern im Protokoll vom 25.11.2025 hinzugefügt, beispielsweise zur Anmeldung. Wenn ein Server nach diesem Update keine Verbindung mehr herstellt, fügen Sie „bareElicitationCapability“: true zu seinem MCP-Konfigurationseintrag hinzu
  • Windows: Es wurde eine Startwarnung hinzugefügt, wenn die Ablehnung des Bash-Tools auch das PowerShell-Tool deaktiviert, sodass Claude kein Shell-Tool hat
  • Selbstgehosteter Läufer: Ein integriertes gh api (nur REST) für Sitzungen hinzugefügt, die von Anthropic verwaltetes Git auf macOS- und Linux-Maschinen verwenden, auf denen GitHub CLI nicht installiert ist – Problem behoben, bei dem der Schnellmodus in Remote-Sitzungen, die einem Agenten ohne Benutzerkonto gehören, ausgeschaltet blieb, selbst wenn die Organisation dies zulässt – Problem behoben, bei dem Remote Control mehrere Minuten lang keine Nachrichten empfing, wenn auf eine Anfrage zur Wiederherstellung der Verbindung keine Antwort erfolgte; Jetzt gibt es nach 30 Sekunden auf und versucht es erneut
  • Problem mit Hooks behoben, die so konfiguriert waren, dass asyncRewake Claude immer wieder mit Benachrichtigungen über „Probleme gefunden“ aufweckte, wenn die Skriptdatei des Hooks fehlte; Der gebrochene Haken wird jetzt einmal gemeldet – Problem behoben, bei dem Tool-Heartbeats die SDK-Hosts nicht erreichten, während der Antwortstrom des Modells angehalten wurde und keine Daten eintrafen – Problem behoben, bei dem Bedrock- und Vertex-Startmodellprüfungen eine erzwungene availableModels-Liste ignorierten, wodurch /model auf eine Opus-Zeile reduziert werden konnte – Problem behoben, bei dem die Browserauswahl von Claude in Chrome einen JSON-Analysefehler anzeigte, wenn Chrome nicht erreichbar war
  • Die Auswahl von Fable in /model bei einem claude.ai-Login wurde korrigiert und speicherte die ID der aktuellen Version, sodass Ihre gespeicherte Standardeinstellung jetzt dem neuesten Fable folgt, wie es Opus und Sonnet tun – Beim Wechsel zwischen Opus 5.5 und Sonnet 5.5 (/model, opusplan) wurden frühere MCP-Tool-Ankündigungen neu geschrieben, wodurch frühere erweiterte Überlegungen verloren gehen konnten – Es wurden Amazon Bedrock Guardrails-Blöcke behoben, die mitten in der Antwort eintrafen und die Runde mit einem API-Fehler beendeten, anstatt mit der Meldung der Leitplanke, als die Antwort mit Nachdenken begann – Ein gefährlicher rm (z. B. einer auf / oder dem Home-Verzeichnis) wurde behoben, der seinen Always-Ask-Schutz verlor, wenn derselbe Befehl auch die Ausgabe an einen ~- oder Platzhalterpfad umleitete – Problem behoben, bei dem bei claude -p- und SDK-Sitzungen ein Modell-Fallback bei jeder späteren Nachricht wiederholt wurde, nachdem das Modell gewechselt wurde, während eine Antwort ausgeführt wurde – Problem behoben, bei dem CLAUDE.md eines Ordners nach der Fortsetzung einer Sitzung oder nach einer Komprimierung ein zweites Mal angehängt wurde – Hintergrundsitzungen wurden behoben, die von claude agents aus nicht erneut geöffnet werden konnten, nachdem der Agent beendet wurde, und der Arbeitsbaum, in dem die Sitzung gestartet wurde, wurde entfernt
  • /advisor-Paarungsprüfungen behoben: Sonnet 5.5 kann jetzt Opus 4.7 und 4.8 empfehlen, und Berater, die API ablehnen würden, werden im Voraus markiert, anstatt stillschweigend gelöscht zu werden – Problem behoben, bei dem Bash-Berechtigungsaufforderungen interne Parsernamen wie „Enthält simple_expansion“ anstelle einer einfachen Erklärung anzeigten – Es wurde eine Ursache behoben, die dazu führte, dass Vollbildsitzungen auf langsamen oder ausgelasteten Rechnern mit der Meldung „Claude Code wurde nach einem nicht behebbaren Schnittstellenfehler beendet“ beendet wurden, während während eines langen Gesprächs eine Scroll-Taste gedrückt gehalten wurde – Behebung eines Problems, bei dem die Berechtigungsobergrenzen für Organisationen pro Tool für ein MCP-Tool namens __proto__ stillschweigend gelöscht wurden – Problem behoben, bei dem Claude aufgefordert wurde, große MCP-Ergebnisse, die als JSON gespeichert wurden, mit Reads Offset und Limit zu pagen, wodurch eine lange Zeile nicht geteilt werden konnte – Die Erinnerung an die Commit-Attribution wurde behoben, die nach einer Komprimierung innerhalb eines Tool-Ergebnisses angezeigt wurde – Problem behoben, bei dem der Bildschirmlesemodus den Cursor vom eingegebenen Text in Suchfeldern (z. B. /resume und /permissions) und Anmeldecodefeldern fernhielt – Problem behoben, bei dem der Screenreader-Modus die Eingabe verweigerte, ohne dass in den Zusammenfassungsoptionen von /rewind etwas eingegeben wurde, deren hinzugefügter Kontext optional ist
  • Der Screenreader-Modus zeigte bei Genehmigungsaufforderungen einen Hinweis „Tab zum Ändern“ an, während Tab keine Aktion ausführte
  • Der Screenreader-Modus listet in /permissions und /mcp Pfeiltasten auf, die nichts bewirken, und sagt „Mit Zahlen auswählen“ in leeren Menüs oder während ein Suchfeld über die Tasten verfügt
  • Fehler im Bildschirmlesemodus behoben, bei dem die geänderten Zeilen in Aufforderungen zur Genehmigung der Dateibearbeitung und anderen Unterschieden weggelassen wurden
  • Der Screenreader-Modus sendet den claude --teleport-Fortschrittsbildschirm und ein MCP-Formularfeld während der Überprüfung bei jedem Spinner-Frame erneut an den Screenreader – Behoben: CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS entfernte das strukturierte Ausgabeformat nicht aus Sitzungstitel- und Prompt-Hook-Anfragen, die von Bedrock-gestützten Gateways abgelehnt werden – Fehler im Bildschirmlesemodus behoben, bei dem die oberen Zeilen einer zweiten Genehmigungsaufforderung, einer geänderten /config-Zeile oder der Zeile „Abgelehnter Plan“ weggelassen wurden, wenn der vorherige Bildschirm höher als das Terminalfenster war – Problem behoben, bei dem --include-partial-messages die Antwort message_stop zu spät oder nie verschickte, sodass Apps die Antwort als noch in Bearbeitung anzeigen konnten – Behoben: claude agents zeigte manchmal nicht die Berechtigungsaufforderung an, auf die eine Hintergrundsitzung wartet – Problem behoben, bei dem /ultrareview Hinweise zu .git/info/attributes gab, wenn der Upload auf einem festgeschriebenen .gitattributes stoppt, das er nicht lesen kann, z. B. einem, der als UTF-16 gespeichert ist – Behoben: claude remote-control konnte sich nicht hinter einem HTTP-Proxy registrieren, was zu einem irreführenden Fehler „Überprüfen Sie die Berechtigungen Ihrer Organisation“ führte (anthropics/claude-code#97352) – Problem behoben, bei dem Sandbox-Bash-Befehle unter Linux ein offenes Handle für die ausführbare Datei von Claude Code erbten
  • Problem behoben, bei dem sich der Punkt des Laufwerkzeugs und die drei Spinner immer noch bewegten, wenn die Einstellung „Bewegung reduzieren“ aktiviert war, und der Bestätigungsbildschirm von /rewind seine „Vorher“-Zeit aktualisierte, während Sie eine Notiz eingeben
  • Es wurde ein Problem behoben, bei dem sich die Zeiten in claude agents im Screenreader-Modus jede Sekunde änderten. Sie ändern sich jetzt höchstens alle 10 Sekunden – Ein widerrufener claude.ai-Login wurde behoben, der ein generisches API Error: 401 anstelle von „OAuth-Token widerrufen“ anzeigte; Im -p-Modus beginnt der Fehler jetzt mit „Authentifizierung fehlgeschlagen“
  • /ultrareview-Upload-Verweigerungen behoben, die Sie dazu aufforderten, eine in der Einstellungsdatei eines Repositorys benannte Variable in Ihre eigenen Benutzereinstellungen zu kopieren – Problem behoben, bei dem --output-format stream-json und SDK die Runden eines context: fork-Skill-Laufs nicht streamten, wenn /<skill> als Eingabeaufforderung eingegeben wurde, wie dies bei der Abzweigung des Skill-Tools der Fall ist
  • /feedback und /bug behoben: Das vorab ausgefüllte GitHub-Problem enthält Ihre letzten Fehlermeldungen nicht mehr und der Bestätigungsbildschirm listet sie jetzt als Teil des Berichts auf – Problem behoben, bei dem die Installation der Plugins claude plugin marketplace add --sparse und git-subdir mit der Fehlermeldung „Transport ‚http‘ nicht zulässig“ fehlschlug, wenn das Repository über einfaches http bereitgestellt wurde – Behoben: Cloud-Sitzungen verloren manchmal die frühere Konversation, wenn die Sitzung während der Komprimierung neu gestartet wurde – Es wurde ein Plugin-Neuladen behoben, der den Start---plugin-url-Download überlappte und die zwischengespeicherte Kopie des Plugin-Archivs der Sitzung beschädigte – Problem behoben, bei dem /desktop eine Teilausgabe zitierte, wenn beim Öffnen von Claude Desktop eine Zeitüberschreitung eintrat oder zu viel Ausgabe gedruckt wurde; Der Fehler nennt nun die Ursache – Es wurde behoben, dass ein MCP-Connector-Tool-Aufruf gelegentlich zweimal ausgeführt wurde oder die Aufrufe des Connectors bis zum Neustart fehlschlugen, wenn der Server die von ihm unterstützte MCP-Protokollversion änderte – Problem behoben, bei dem SessionStart-Hooks von synchronisierten Plugins in neuen Cloud-Sitzungen nicht ausgeführt wurden – Die Zusammenfassung „N Hooks ausgeführt“ des Transkripts und die Anzahl der übereinstimmenden Hooks im ausführlichen Debug-Protokoll, einschließlich der internen Rückrufe von Claude Code, wurden korrigiert, sodass ein konfigurierter Hook nicht mehr als zwei angezeigt wird – Behoben: Dateien, die Claude aus Cloud- und Fernsteuerungssitzungen sendet, schlugen fehl, wenn der Upload kurz nach dem 30-Sekunden-Timeout abgeschlossen wurde; es wartet jetzt 35 Sekunden – Problem behoben, bei dem Repositorys, die während der Sitzung in Cloud- und SDK-Sitzungen hinzugefügt wurden, ihre Fähigkeiten und Plugins nicht geladen haben und CLAUDE.md spät geladen haben, nachdem Claude das Verzeichnis gewechselt hat
  • Problem behoben, bei dem PNG-, JPEG- und WebP-Bilder mit mehr als 8.000 Pixeln auf einer Seite nicht aus einer Remote-Sitzung gesendet werden konnten; Claude schickt nun eine verkleinerte Kopie
  • Problem behoben, bei dem von den Claude-Apps gesendete Nachrichten mit 17 bis 20 angehängten Dateien nur die ersten 16 zustellten – Problem behoben, bei dem Headless-Sitzungen gemeldet haben, dass ein MCP-Server nach einem abgelehnten Anruf eine Authentifizierung benötigt, obwohl spätere Anrufe erfolgreich waren
  • macOS: Problem behoben, bei dem Fernsteuerungssitzungen gestartet wurden, bei denen claude remote-control mitten in der Drehung anhielt, wenn der Mac in den Ruhezustand wechselte
  • Windows: Es wurde behoben, dass der interaktive claude mit der Meldung „Raw-Modus wird nicht unterstützt“ hängen blieb oder abstürzte, wenn seine Eingabe weitergeleitet oder umgeleitet wurde; Jetzt wird der Grund angezeigt und der Vorgang beendet (verwenden Sie -p für die Eingabe über Pipes).
  • Grundgestein, Vertex, Mantel: Modellverfügbarkeitsprüfungen unter CLAUDE_CODE_SKIP_*_AUTH korrigiert, die einen anderen Authorization-Header senden als echte Anfragen, wenn ANTHROPIC_CUSTOM_HEADERS ihn wiederholt
  • Verbessertes /config: Einstellungen, die ‹ › zyklisch anzeigen und mit ←/→ in beide Richtungen wechseln, Narrow-Terminals stapeln jeden Wert unter seiner Beschriftung und PgUp/PgDn blättert in der Liste
  • Plugin-Marktplatzfehler wurden verbessert, um in einfachen Worten zu sagen, warum ein Marktplatz ignoriert oder abgelehnt wurde und was zu tun ist
  • Verbesserte Plugin-Auflistungen, die darauf hinweisen, wenn die Abhängigkeiten eines Plugins nicht installiert wurden, und beim Aktualisieren eines Plugins wird jetzt eine Installation erneut durchgeführt, die nicht abgeschlossen wurde – Der Fehler des Claude-Apps-Gateways, wenn Amazon Bedrock eine Modell-ID ablehnt, wurde verbessert: Entwickler sehen jetzt, welches Modell nicht verfügbar ist, und das Gateway-Protokoll nennt die gesendete ID – Verbesserte SDK-Sitzungen, sodass eine mit der Priorität „Jetzt“ gesendete Nachricht einen laufenden Webabruf oder eine Websuche nicht mehr abbricht; es wird ständig im Hintergrund geladen
  • Verbesserter /memory: Die linken und rechten Pfeiltasten schalten jetzt die Ein-/Aus-Einstellungen um, z. B. Auto-Memory
  • Verbesserte /skill-Namen, die mitten in der Nachricht eingegeben werden: Claude wird jetzt mitgeteilt, dass es sich um Fertigkeiten handelt, einschließlich der disable-model-invocation-Namen
  • Der Kontrast des Prompt-Eingaberahmens in Light-Designs und des ❯ vor Ihren früheren Nachrichten wurde verbessert
  • Verbesserte Zustellung von Dateien, die Claude aus Cloud-Sitzungen und Fernsteuerung sendet: Ein Upload, der aufgrund einer Zeitüberschreitung, eines Netzwerkfehlers oder einer 502, 503 oder 504 fehlschlägt, wird jetzt einmal wiederholt
  • Die Aussage von Claude, wenn eine Datei aus einem möglicherweise vorübergehenden Grund nicht gesendet werden kann, wurde verbessert: Es wird nun erwähnt, dass Sie die Datei in ein paar Minuten erneut anfordern können – Die Eingabeaufforderung für eine zurückgehaltene Nachricht aus einer anderen Sitzung wurde verbessert, sodass die Nachricht jetzt zwischen gestrichelten Linien angezeigt wird und mit anderen Berechtigungsaufforderungen übereinstimmt
  • Verbesserte MCP- und andere Tool-Berechtigungsaufforderungen, um den Tool-Aufruf zwischen gestrichelten Linien anzuzeigen, passend zu Dateibearbeitungsaufforderungen – Verbesserter MCP-Start im Headless-Modus: Ein Remote-Server, dessen erste Verbindung vorübergehend fehlschlägt, wird jetzt erneut versucht, ohne darauf zu warten, dass der langsamste Server die Verbindung beendet
  • Verbesserte Dateien, die Claude aus einer Remote-Sitzung sendet: Große Dateien werden jetzt von der Festplatte gestreamt, anstatt in den Speicher eingelesen zu werden, und eine Datei, die die Größenbeschränkung überschreitet, wird mit der angegebenen Beschränkung des Servers abgelehnt – Die Erklärung, die Claude gibt, wenn der Server eine Datei ablehnt, die er von einer Remote Control- oder Cloud-Sitzung sendet, wie z. B. ein übergroßes Bild, wurde verbessert – Verbesserte Handhabung großer MCP-Tool-Ergebnisse: weniger Speicher, kleinere Sitzungsdateien und kein zusätzlicher Upload zum Zählen von Token für Ergebnisse, die weit über dem Limit liegen
  • Windows: Die Geschwindigkeit des Bash-Tools wurde verbessert, indem eine Subshell entfernt wurde, die vor jedem Befehl ausgeführt wurde – Ein Shell-Schreibvorgang über einen Repo-gebundenen Symlink auf eine vertrauliche Datei oder aus dem Arbeitsbaum heraus wurde geändert, um anzugeben, wo er landet und auf eine Person wartet, auch auf Zeilen mit einem ~-Ziel
  • Opus 4.7+ und Fable wurden geändert, um standardmäßig ein 1M-Kontextfenster auf Bedrock, Vertex, Foundry und dem Claude-Apps-Gateway zu verwenden, ohne [1m]-Suffix (CLAUDE_CODE_DISABLE_1M_CONTEXT=1 behält 200K)
  • Antworten von claude agents wurden so geändert, dass sie als Nachrichten in der Warteschlange eintreffen; Andere Slash-Befehle als /stop, die während der Ausführung einer Runde gesendet werden, werden jetzt ausgeführt, wenn sie endet – Die Zulassungsregeln für das gesamte Tool Bash wurden geändert und erlauben Hooks, Shell-Schreibvorgänge in Dateien anzufordern, nicht auszuführen. Die Dateitools von Claude Code lehnen dies komplett ab (der Anthropic-Profilspeicher, die Datei mit den Host-Anmeldeinformationen).
  • Das Einfügen mit der rechten click-Taste unter Windows und Linux und das Einfügen mit der mittleren click-Taste unter Linux wurde so geändert, dass es beim Loslassen der Taste erfolgt. Wenn Sie den Zeiger vor dem Loslassen wegbewegen, wird der Vorgang abgebrochen – Der MCP-Server alwaysLoad: false wurde dahingehend geändert, dass alle Werkzeuge dieses Servers hinter der Werkzeugsuche zurückgestellt werden
  • Bildschirmlesemodus geändert, um neue oder geänderte Zeilen zu schreiben, ohne zuerst mit dem Cursor am Zeilenanfang anzuhalten; Stellen Sie CLAUDE_AX_PREPARK_MS=50 ein, um die Pause wiederherzustellen
  • Die automatischen Modellwechsel nach einer gekennzeichneten Meldung wurden geändert, um Ihr aktuelles Aufwandsniveau anstelle der Standardeinstellung des neuen Modells beizubehalten
  • Die Eingabeaufforderungen für Warteberechtigungen wurden so geändert, dass die Ältesten zuerst angezeigt werden, sodass eine neue Eingabeaufforderung nicht mehr diejenige abdeckt, die Sie gerade lesen (Eingabeaufforderungen, bei denen oben noch ein Countdown läuft). – [VSCode] „Im Hintergrund ausführen“ zu einem laufenden Befehl oder Subagenten hinzugefügt, um ihn in den Hintergrund zu verschieben und weiterzuarbeiten
  • [VSCode] Die Ausgabe von Hintergrund-Shells und Monitoren wurde zu ihren Karten in der Agentenkarte hinzugefügt
  • [VSCode] Einstellungsdialoge wurden korrigiert, die eine Zeitüberschreitung verursachten, wenn die Antwort von Claude Code zu lang war, um einen Speichervorgang zu bestätigen
  • [VSCode] Das erneute Öffnen einer Cloud-Sitzung, die die Seitenleiste bereits auf diesen Computer gebracht hatte, wurde behoben, indem sie erneut in einem neuen Tab geöffnet wurde; Stattdessen wird die Seitenleiste angezeigt – [VSCode] Problem behoben, bei dem die Registerkarte „Web“ der Seitenleiste keine Cloud-Sitzungen auflistete, die nach dem Laden des Fensters gestartet wurden; Bei einem fehlgeschlagenen Ladevorgang wird jetzt „Remote-Server ist nicht verbunden“ anstelle von „Noch keine Websitzungen“ angezeigt.
  • [VSCode] Ein Tab wurde behoben, der nach einem Neuladen wiederhergestellt wurde und einen zweiten Claude-Prozess für eine Konversation startete, die in der Seitenleiste bereits geöffnet war. Es wird jetzt der Hinweis angezeigt, dass „noch woanders geöffnet“ steht
  • [VSCode] Die Links zu Werkzeugzeilendateien, Sitzungslistenlinks und zwei Hinweise, die im Klartext angezeigt werden, wurden korrigiert
  • [VSCode] Problem behoben, bei dem der noch laufende Befehl eines Hintergrundagenten nach dem Ende der Hauptrunde als fehlgeschlagen angezeigt wurde – [VSCode] Der benutzereigene Befehl /usage oder /context wurde behoben, der den Dialog der Erweiterung öffnete, anstatt ihn auszuführen, wenn er aus dem Befehlsmenü ausgewählt wurde
  • [VSCode] Dateiverknüpfungen in der Planvorschau-Registerkarte wurden behoben, die beim Aktivieren von cli nichts bewirkten; Sie öffnen die Datei jetzt wie Links in Chat-Antworten – [VSCode] Problem behoben, bei dem das Öffnen der Eingabe oder Ausgabe eines Tools in einer Editor-Registerkarte mit „Timeout beim Warten nach 1000 ms“ auf Remote-Hosts wie WSL fehlschlug, wenn die Registerkarte langsam angezeigt wurde
  • [VSCode] Das Dialogfeld „Plugins verwalten“ wurde verbessert: Bei einem fehlgeschlagenen Hinzufügen, Entfernen oder Aktualisieren eines Marktplatzes wird jetzt angezeigt, was schief gelaufen ist – [VSCode] Der Claude-Schalter in Chrome „Standardmäßig aktiviert“ wurde geändert, um auch die eigenen Sitzungen des Editors zu verbinden, die immer noch vor Browseraktionen fragen
  • [Cloud-Sitzungen] Gelegentliche Fehler beim Abrufen von oder Pushen zu GitHub behoben, wenn GitHub ein neu ausgestelltes Zugriffstoken kurzzeitig ablehnte
  • [Claude Tag] Problem behoben, bei dem Claude in einem Slack-Thread eine Fehlerwarnung postete, z. B. eine Benachrichtigung über ein Ausgabenlimit, wenn ein Hintergrundereignis wie eine GitHub-Aktivität ihn aktivierte und niemand auf eine Antwort wartete
  • [Claude Tag] Die Seite „Ausgabenlimits“ von Claude Tag in den Admin-Einstellungen wurde korrigiert, wobei kürzlich erstellte und private Kanäle in Organisationen mit vielen Kanälen weggelassen wurden
  • [Claude Tag] Claudes Aufgabenliste in langen Slack-Threads wurde verbessert: Die Hintergrundarbeit postet sie nicht mehr selbstständig als neue Nachricht erneut, sodass Personen, die dem Thread folgen, nicht benachrichtigt werden
  • [Codeüberprüfung] Problem behoben, bei dem Kommentare und der Text „Warum dies markiert wurde“ mitten im Satz anhielten; Sie enden nun mit einem vollständigen Satz
  • [Codeüberprüfung] Problem behoben, bei dem Codeüberprüfung eine Pull-Anfrage nach einem neuen Push übersprang, wenn die Überprüfung beim vorherigen Commit zweimal fehlgeschlagen war; Es überprüft nun den neuesten Commit
  • [Codeüberprüfung] Die Karte „Fehlgeschlagene Überprüfung“ bei einer Pull-Anfrage, deren Konversation gesperrt ist, wurde verbessert: Es heißt jetzt, dass die Sperre die Überprüfung blockiert hat und dass nichts gepostet oder berechnet wurde
