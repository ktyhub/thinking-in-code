Claude-Code v2.1.319

Was hat sich geändert?

  • Geänderter automatischer Modus mit deaktivierten Telemetrie- oder Feature-Flags, auch hinter LLM-Gateways: Anrufe, die der Server nicht überprüfen kann, werden nachgefragt oder abgelehnt, ohne Rückgriff auf den integrierten Klassifikator; Stellen Sie CLAUDE_CODE_AUTO_MODE_SERVER=0 so ein, dass es weiterhin verwendet wird (Bedrock, Vertex und Foundry bleiben unverändert)
  • Geänderter Auto-Modus hinter einem LLM-Gateway: CLAUDE_CODE_AUTO_MODE_SERVER=1 schaltet die serverseitige Prüfung ein, auch wenn CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS gesetzt ist; Wenn verwaltete Einstellungen Letzteres festlegen, müssen sie auch 1 festlegen

  • Selbstgehosteter Läufer: CLAUDE_RUNNER_CHECKOUT_PATH geändert, sodass jedes Repository in einer Sitzung seinen eigenen Ordner erhält: Ein Ordnername, der bereits in der Sitzung verwendet wurde, erhält am Ende -2, -3, …
  • Selbstgehosteter Läufer: Der Upload des Debug-Protokolls einer Sitzung am Ende der Sitzung wurde entfernt. Das Protokoll einer fehlgeschlagenen Sitzung verbleibt auf dem Runner-Host, es sei denn, --remove-session-state ist festgelegt
  • [VSCode] Problem behoben, bei dem Eingabeaufforderungen mit mehr als 50.000 Zeichen stillschweigend abgeschnitten wurden: Die Eingabeaufforderung bleibt jetzt mit einem Hinweis im Chatfeld und ein Einfügen über dem Limit wird mit einem Hinweis abgelehnt – [VSCode] Ein click bei der Umfrage oder den Schaltflächen „Problem melden“ behoben, die die unvollständige Eingabeaufforderung sendeten – [VSCode] Behoben: Cloud-Sitzungen, die über die Registerkarte „Web“ der Erweiterung geöffnet wurden, brachten Runden zurück, die durch /clear oder „Wiederholen“ oder „Bearbeiten“ einer eingegebenen Eingabeaufforderung entfernt wurden – [VSCode] Problem behoben, bei dem die Datei einer gelöschten Sitzung wieder angezeigt wurde, wenn diese Sitzung in der Erweiterung umbenannt wurde
  • [VSCode] Problem behoben, bei dem Claude nach dem Neuladen eines Fensters einen nicht genehmigten Plan ausführte: Ein im Planmodus unterbrochener Schritt wird jetzt mit einer Benachrichtigung angehalten, wenn die Sitzung in einem anderen Berechtigungsmodus zurückkehrt – [VSCode] Die Meldung „Nicht angemeldet“ hinter einem Claude-Apps-Gateway wurde verbessert: Sie sieht jetzt wie ein Fehler aus und verfügt über einen Anmeldelink – [VSCode] Geänderte Links in Claudes Antworten, die auf Claude-Anmelde-, Connector- oder API-Adressen verweisen, werden nun als Text mit der Adresse angezeigt, anstatt im Browser geöffnet zu werden
  • [VSCode] Ein mögliches Einfrieren des Chat-Panels wurde behoben, wenn der Pfad eines abgelegten Elements eine sehr lange Folge von „/“-Zeichen enthielt
  • [VSCode] Der Befehl claude-vscode.toggleDictation, der das Diktat in jeder geöffneten Claude-Ansicht gleichzeitig startete, wurde korrigiert; Es funktioniert jetzt nur in der von Ihnen verwendeten Ansicht und wird durch ein zweites Drücken gestoppt
  • [VSCode] Problem behoben, bei dem das Chat-Panel langsamer wurde, während eine Antwort mit vielen nicht geschlossenen $$-Mathe-Zäunen, von denen jeder kürzer als der letzte war, einging
  • [VSCode] Das Diagnosetool des Chat-Panels für große Arbeitsbereiche wurde verbessert: Es lässt Dateien problemlos aus, gibt den kompakten Wert JSON zurück und akzeptiert einen optionalen Mindestschweregrad
  • [Cloud-Sitzungen] Geplante Aufgaben haben ein Problem behoben, bei dem ein Konnektor mit dem Namen „Memory: Runs“ stillschweigend gelöscht wurde. Er wird jetzt beibehalten und unter diesem Namen und einem kurzen Suffix gemountet
  • [Cloud-Sitzungen] Problem behoben: „Jetzt senden“ bei einer Wartenachricht in Cloud-Sitzungen, bei denen die Ausführung von Hintergrundagenten beendet wird; Sie laufen jetzt weiter
  • [Cloud-Sitzungen] Die Warnung vor einem blockierten Setup in selbstgehosteten Umgebungen wurde verbessert: Der Link bevorzugt jetzt die Standardumgebung Ihrer Organisation oder eine Umgebung mit einem Live-Runner und benennt sie
  • [Codeüberprüfung] Das Aufheben der Verknüpfung einer GitHub-Organisation wurde dahingehend geändert, dass auch die Einstellung „Alle Repositorys“ in der Codeüberprüfung deaktiviert wird. Nach der Neuverknüpfung bleibt es ausgeschaltet, bis Sie es wieder einschalten
  • [Claude Tag] Problem behoben, bei dem das Claude Tag-Setup den Start blockierte, wenn die Kanalliste nicht vollständig geladen werden konnte; Administratoren können jetzt starten, ohne einen Kanal auszuwählen
  • [Claude Tag] Der Modelladministrationsseite für Unternehmensorganisationen mit verbundenem Claude Tag wurde eine Claude Tag-Zeile hinzugefügt, die auf den Ort verweist, an dem die Modellstandards verwaltet werden
  • [Claude Tag] Das Speichern von Zulassungsregeln für den automatischen Modus in den Claude Tag-Administratoreinstellungen wurde behoben und überschrieb die Änderungen eines anderen Administrators. Das Speichern wird nun mit einer Meldung verweigert
