Leuchtturm v6.0.0

Roh-Commit changelog Wir gehen davon aus, dass diese Version in den DevTools von Chrome 84 ausgeliefert wird.

Bemerkenswerte Änderungen

So viele! Weitere Informationen finden Sie im Blogbeitrag [Lighthouse 6.0: Was ist neu] (https://web.dev/lighthouse-whats-new-6.0/).

🆕 Neue Audits

  • Größter Contentful Paint (LCP) ist eine neue Metrik, die die Zeit von der Navigation bis zum Rendern des größten Inhaltselements im Ansichtsfenster misst (#9905, #10213, #10452, #10529). – largest-contentful-paint-element ist ein begleitendes Audit, das Informationen darüber liefert, welches Element das LCP ausgelöst hat (#10517, #10713).
  • Kumulative Layoutverschiebung (CLS) ist eine neue Metrik, die das Ausmaß der unerwarteten Bewegung von Inhalten beim Laden einer Seite misst (#9037, #10427, #10495, #10570, #10728). – layout-shift-elements ist eine weitere begleitende Diagnose, die Informationen über die Elemente liefert, die sich beim Laden der Seite verschoben haben (#10702).
  • unused-javascript ist ein Audit, das schon seit einiger Zeit im Umlauf ist, aber erst jetzt standardmäßig aktiviert ist. Es berücksichtigt, was JavaScript beim Laden der Seite geladen, aber nie ausgeführt hat, und schätzt die Ladezeit, die durch Codeaufteilung, Eliminierung von totem Code oder umsichtiger Verwendung der Löschtaste eingespart werden könnte (#9854).
  • Eine PWA maskable-icon sieht auf Ihrem Homescreen einfach besser aus, daher ermutigt Sie diese neue Prüfung, mindestens eine in Ihrem Manifest verfügbar zu haben (#10370).
  • timing-budget erweitert Budgetzusicherungen, sodass sie jetzt für alle Leistungsmetriken einstellbar sind (#9901, #9925).
  • Das neue charset-Audit gewährleistet eine ordnungsgemäße Zeichenkodierung für Seiteninhalte (#10284, #10389, #10689).
  • image-size-responsive prüft, ob Bilder ein Seitenverhältnis und eine Auflösung haben, die gut mit der Darstellung auf einer Seite übereinstimmen (#10460).
  • Durch die Aktualisierung auf die neueste Version von axe-core wurden eine Reihe neuer Zugänglichkeitsprüfungen freigeschaltet: aria-hidden-body, aria-hidden-focus, aria-input-field-name, aria-toggle-field-name, duplicate-id-active, duplicate-id-aria, form-field-multiple-labels, heading-order (#9798).

⚗️ Experimentelle Audits

Diese Audits sind noch nicht Teil der standardmäßigen Lighthouse-Erfahrung, liefern aber Leistungsempfehlungen basierend auf der Analyse der JavaScript-Bundles einer Seite. Sie können heute auf der Befehlszeile mit dem Flag --preset=experimental getestet werden.

  • legacy-javascript durchsucht Ihre Bundles nach Polyfills und Bundler-Transformationen, die nicht notwendig oder veraltet sind (#10303, #10568, #10564).
  • duplicated-javascript durchsucht auch den JavaScript einer Seite und sucht nach Code, der innerhalb von Bundles oder über mehrere Bundles hinweg dupliziert wurde (#10314).
  • unused-javascript wird jetzt standardmäßig ausgeführt (wie oben erwähnt), aber wenn es unter experimental ausgeführt wird, kann die Prüfung mithilfe von Quellzuordnungen zeigen, welcher ursprüngliche Quellcode nie ausgeführt wurde und verschoben oder entfernt werden könnte (#10090).

💥 Bahnbrechende Veränderungen

  • Leistungsmetrikwerte wurden neu gewichtet, um das Ladeerlebnis eines Benutzers besser widerzuspiegeln (#9949).
  • Die metrischen Bewertungskurven wurden beim Ausführen eines Desktop-Lighthouse-Tests aktualisiert, um der schnelleren Verbindung und CPU Rechnung zu tragen (#9911, #10756).
  • frameNavigated-Ereignisse werden jetzt zum Verfolgen von Weiterleitungen verwendet, was bedeutet, dass JS-Weiterleitungen jetzt bei der Bestimmung des finalUrl des Laufs berücksichtigt werden (#10339).
  • Das emulierte Mobilgerät wurde vom Nexus 5x zum Moto G4 verschoben (der vorhandene DPR wurde jedoch unverändert gelassen) (#10191, #10749).
  • Die Voreinstellung mixed-content wurde entfernt, da sie nicht weit verbreitet war und es zu lange dauert, bis sie zum standardmäßigen Lighthouse-Erlebnis hinzugefügt wird (#10159, #10750).
  • Die Voreinstellung full wurde in experimental umbenannt, um anzuzeigen, dass der Code dort möglicherweise nicht standardmäßig zur Ausführung bereit ist (#9930, #10311, #10333, #10585).
  • Der emulierte Chrome UA-String wurde auf Chrome 80 aktualisiert (#9967).
  • installable-manifest: Symbole im Web-App-Manifest müssen abrufbar sein, um als installierbar zu gelten (#10168, #10320)

🤖💥 Wichtige Änderungen für programmatische Benutzer

Es ist unwahrscheinlich, dass sich diese Änderungen auf Endbenutzer auswirken, sie können jedoch wichtig sein, wenn Sie benutzerdefinierte Konfigurationen oder Plugins schreiben oder die Lighthouse JSON-Ausgabe verarbeiten.

  • LH.Audit.Context, das in Audits übergeben wird, wird jetzt als unveränderlich behandelt. Wenn Code zuvor an context.LighthouseRunWarnings gesendet wurde, um eine Warnung der obersten Ebene zu erhalten, sollte er diese nun in runWarnings an das Produkt des Audits zurückgeben (#10555).
  • Audit.computeLogNormalScore wurde neu definiert, um logarithmische Normalkurven mit Median- und p10-Punkten anzugeben (wobei der „Punkt abnehmender Erträge“ wegfällt). Bestehende Prüfungen wurden auf diese neue Definition verschoben, sodass keine Bewertungsänderungen auftreten sollten (#10715).
  • Den Config-Durchgängen wurde eine loadFailureMode-Einstellung hinzugefügt, um das Verhalten im Falle eines Seitenladefehlers zu steuern. Zuvor wurde dies implizit gesteuert (z. B. verursachte keine verfügbare Offline-Seite keinen Fehler) (#9987)
  • time-to-first-byte wurde in server-response-time umbenannt, um besser wiederzugeben, was bei der Prüfung gemessen wird (#10735).
  • resource-summary: details.items.size wurde aus Gründen der Übersichtlichkeit in transferSize umbenannt (#10700, #10743).
