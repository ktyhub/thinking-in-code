Scrapling v0.4

Die bisher größte Veröffentlichung von Scrapling – Einführung des Spider-Frameworks, der Proxy-Rotation und wichtiger Parser-Verbesserungen

Diese Version bringt ein vollständig asynchrones Spider-/Crawling-Framework, intelligentes Proxy-Management und bedeutende API-Änderungen mit sich, die Scrapling leistungsfähiger und konsistenter machen. Bitte lesen Sie den Abschnitt „Breaking Changes“ sorgfältig durch, bevor Sie ein Upgrade durchführen.

🕷️ Spinnen-Framework

Ein neues asynchrones Crawling-Framework, das auf anyio aufbaut, für strukturiertes, umfangreiches scraping:

from scrapling.spiders import Spider, Response

class MySpider(Spider):
  name = "demo"
  start_urls = ["https://example.com/"]

  async def parse(self, response: Response):
      for item in response.css('.product'):
          yield {"title": item.css('h2::text').get()}

MySpider().start()
  • Scrapy-like Spider API: Definieren Sie Spiders mit start_urls, asynchronen parse-Callbacks, Request/Response-Objekten und einer Prioritätswarteschlange.
  • Gleichzeitiges Crawling: Konfigurierbare Parallelitätsgrenzen, Drosselung pro Domäne und Download-Verzögerungen.
  • Unterstützung mehrerer Sitzungen: Einheitliche Schnittstelle für HTTP-Anfragen und versteckte Headless-Browser in einem einzigen Spider – Leiten Sie Anfragen anhand der ID an verschiedene Sitzungen weiter. Unterstützt die verzögerte Sitzungsinitialisierung.
  • Pause & Resume: Checkpoint-basierte Crawl-Persistenz. Drücken Sie Strg+C, um ordnungsgemäß herunterzufahren. Starten Sie dann neu, um dort fortzufahren, wo Sie aufgehört haben.
  • Streaming-Modus: Streamen Sie gelöschte Elemente, sobald sie über async for item in spider.stream() eintreffen, mit Echtzeitstatistiken – ideal für Benutzeroberflächen, Pipelines und lang laufende Crawls.
  • Erkennung blockierter Anfragen: Automatische Erkennung und Wiederholung blockierter Anfragen mit anpassbarer Logik.
  • Integrierter Export: Exportieren Sie Ergebnisse über Hooks und Ihre eigene Pipeline oder den integrierten JSON/JSONL mit result.items.to_json() bzw. result.items.to_jsonl().
  • Lebenszyklus-Hooks: on_start(), on_close(), on_error(), on_scraped_item() und weitere Hooks für die vollständige Kontrolle über den Crawl-Lebenszyklus.
  • Detaillierte Crawl-Statistiken: Verfolgen Sie Anfragen, Antworten, Bytes, Statuscodes, Proxys, Aufschlüsselungen pro Domäne/Sitzung, Anzahl der Protokollebenen und mehr.
  • UVloop-Unterstützung: Übergeben Sie use_uvloop=True an spider.start() für eine schnellere asynchrone Ausführung, sofern verfügbar.

🔄 Proxy-Rotation

  • Neue ProxyRotator-Klasse mit threadsicherer Rotation. Funktioniert mit allen Fetchern und Sitzungen: 
    from scrapling import ProxyRotatorrotator = ProxyRotator(["http://proxy1:8080", "http://proxy2:8080"])Fetcher.get(url, proxy_rotator=rotator)
  • Benutzerdefinierte Rotationsstrategien: Erstellen Sie Ihre eigene Proxy-Rotationslogik
  • Proxy-Überschreibung pro Anfrage: Übergeben Sie proxy= an jeden einzelnen get()/post()/fetch()-Aufruf, um den Sitzungsproxy für diese Anfrage zu überschreiben.

🌐 Verbesserungen beim Browser-Fetcher

  • Domain-Blockierung: Neuer blocked_domains-Parameter auf DynamicFetcher/StealthyFetcher, um Anfragen an bestimmte Domains zu blockieren (Subdomains werden automatisch abgeglichen).
  • Automatische Wiederholungsversuche: Browser-Abrufe versuchen es jetzt bei einem Fehler erneut mit den Parametern retries (Standard: 3) und retry_delay (Standard: 1s). Beinhaltet eine Proxy-fähige Fehlererkennung.
  • Antwortmetadaten: Response.meta dict speichert automatisch den verwendeten Proxy und führt Anforderungsmetadaten zusammen.
  • Response.follow(): Erstellen Sie Folge-Request-Objekte mit automatischem Referrer-Fluss, entwickelt für das Spider-System.
  • Keine automatische Wiedergabe: Browsersitzungen blockieren jetzt die automatische Wiedergabe von Inhalten, was zuvor zu Problemen geführt hat.
  • Geschwindigkeit: Verbesserte Tarnung und Geschwindigkeit durch Anpassen der Browser-Flags.

🔧 Fehlerbehebungen und Verbesserungen

  • Parser-Optimierung: Der Parser wurde für wiederholte Vorgänge optimiert und so die Leistung verbessert.
  • Fehlerhafte Seiten: Es wurde ein Fehler behoben, der dazu führte, dass der Browser nicht geschlossen wurde, wenn Seiten fehlerhafte Seiten lieferten.
  • Leerer Text: Behandeln Sie Antworten mit leerem Text.
  • Playwright-Schleife: Behebung eines Problems beim Offenlassen der Playwright-Schleife, wenn die CDP-Verbindung fehlschlägt
  • Typsicherheit: Alle Mypy-Fehler wurden behoben und Typhinweise für nicht typisierte Funktionskörper hinzugefügt. Mypy und Pyright zum CI-Workflow hinzugefügt.

⚠️ Breaking Changes

  • css_first/xpath_first entfernt: Verwenden Sie stattdessen css('.selector').first, css('.selector')[0] oder css('.selector').get().
  • Alle Auswahlen geben jetzt Selectors zurück: css('::text'), xpath('//text()'), css('::attr(href)') und xpath('//@href') geben jetzt Selectors zurück (Textknoten in Selector-Objekten werden mit tag="#text" umbrochen) anstelle von TextHandlers. Dadurch wird API über alle Auswahlmethoden und Typhinweise hinweg konsistent.
  • Response.body ist immer bytes: Konnte bisher str oder bytes sein, gibt jetzt immer bytes zurück.
  • get()/getall()-Verhalten: Bei Selector: get() gibt TextHandler (serialisierter HTML- oder Textwert) zurück, getall() gibt TextHandlers zurück. Aliase: extract_first = get, extract = getall. Der alte get_all() auf Selectors wird entfernt.
  • Selectors.first/.last: Sichere Accessoren, die Selector | None zurückgeben, anstatt IndexError auszulösen.
  • Interne Konstanten umbenannt: DEFAULT_FLAGS → DEFAULT_ARGS, DEFAULT_STEALTH_FLAGS → STEALTH_ARGS, HARMFUL_DEFAULT_ARGS → HARMFUL_ARGS, DEFAULT_DISABLED_RESOURCES → EXTRA_RESOURCES.

🔨 Weitere Änderungen

  • Abhängigkeitsänderungen: tldextract durch tld ersetzt, internes _html_utils.py zugunsten von w3lib.html.replace_entities entfernt, typing_extensions als zwingende Anforderung hinzugefügt.
  • Überarbeitung der Dokumente: Vollständiger Wechsel von MkDocs zu Zensical, neuer Abschnitt zur Spider-Dokumentation, Aktualisierung aller vorhandenen Seiten und Hinzufügung neuer API-Referenzen.
