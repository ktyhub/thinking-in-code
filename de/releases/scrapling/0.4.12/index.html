Scrapling v0.4.12

Eine Veröffentlichung, die sich darauf konzentriert, Ihre Spider intelligenter in Bezug auf die von ihnen gecrawlten Websites zu machen

[!NOTE] Folgen Sie uns auf X für tägliche Tipps und Tricks

🚀 Neue Dinge und Lebensqualität verändern sich

  • Spider können jetzt mit AutoThrottle ihre eigene Geschwindigkeit anpassen. Anstatt einen download_delay zu erraten, der entweder zu langsam ist oder Ihnen eine Sperre einbringt, misst der Spider, wie schnell jede Website antwortet, und passt die Verzögerung jeder Domain selbst an. Wenn eine Website anfängt, Sie zu blockieren oder die Geschwindigkeit zu begrenzen, verdoppelt sie die Verzögerung (oder wartet genau das, was der Retry-After-Header verlangt), bis dies aufhört, und beschleunigt dann wieder. Ihr download_delay und alle robots.txt Crawl-delay werden weiterhin als Minimum respektiert. (Überprüfen Sie die Dokumente)

    class MySpider(Spider):
    name = "adaptive"
    start_urls = ["https://example.com"]
    autothrottle_enabled = True
    autothrottle_start_delay = 2.0
    autothrottle_max_delay = 30.0
    autothrottle_block_backoff = True

  • Exportieren Sie Ihre Ergebnisse in CSV und XML, neben den JSON/JSONL-Exportprogrammen, die Sie bereits hatten. Elemente, die nicht alle dieselben Schlüssel haben, werden trotzdem exportiert, ohne etwas zu verlieren, und verschachtelte Werte werden als JSON geschrieben. (Überprüfen Sie die Dokumente)

    result = MySpider().start()
result.items.to_csv("products.csv")
result.items.to_xml("products.xml")

  • Der MCP-Server kann jetzt eine Authentifizierung erfordern, sodass Sie ihn sicher offenlegen können, anstatt ihn auf Ihrem eigenen Computer zu behalten. Jede Anfrage ohne das Token wird abgelehnt und Sie können auch einschränken, auf welche Hostnamen der Server antwortet. (Überprüfen Sie die Dokumente)

    scrapling mcp --http --auth-token "$(openssl rand -hex 32)"

  • Browser akzeptieren jetzt CDP-URLs über HTTP, nicht nur WebSocket-URLs. Neben den wss://-Endpunkt-verwalteten Browser-Anbietern können Sie jetzt jeden Browser-Abrufer oder jede MCP-Sitzung auf einen Chrome verweisen, den Sie selbst mit --remote-debugging-port=9222 gestartet haben.

  • Veröffentlichte Docker-Bilder werden jetzt mit ihrer Release-Version getaggt statt nur mit latest, sodass Sie genau die gewünschte Version anpinnen können, von @JanRK in #384.

🐛 Fehlerbehebungen

– Behoben, dass zwischengespeicherte Antworten alle ihre Cookies verloren, wenn die Antwort von einer Browser-Engine kam, die stillschweigend alle darauf basierenden Sitzungen oder Authentifizierungslogiken unterbrach, während der Entwicklungsmodus der Spiders verwendet wurde, von @amitvijapur in #379. (Behebt #376)

  • Behoben: StealthyFetcher erzwingt das Gebietsschema en-US in jedem Browser, anstatt dem Ihres Systems zu folgen, was dazu führte, dass Websites eine Nichtübereinstimmung zwischen Ihrem Gebietsschema und Ihrer IP-Adresse erkannten und Sie als verdächtig behandelten, so als würde Google mit 429 antworten. (Behebt #381)

  • Eine irreführende Fehlermeldung im Speichersystem wurde behoben und ein toter Aufruf nach Einfügungen von @fix2015 in #377 entfernt.

Leistung

  • get_all_text() ist jetzt O(Knoten), anstatt die Vorfahren jedes einzelnen Textknotens nach oben zu durchlaufen, was es auf tief verschachtelten Seiten etwa 5-6x schneller macht, von @yetval in #378.

🙏 Besonderer Dank geht an die Community für all die kontinuierlichen Tests und Rückmeldungen
