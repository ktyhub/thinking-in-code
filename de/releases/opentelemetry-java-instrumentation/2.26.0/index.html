opentelemetry-java-instrumentation v2.26.0

Minor Veröffentlicht14. März 2026 Quelleopen-telemetry/opentelemetry-java-instrumentation Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

opentelemetry-java-instrumentation v2.26.0

Diese Version zielt auf den OpenTelemetry SDK 1.60.1 ab.

Beachten Sie, dass vielen Artefakten das Suffix -alpha an die Versionsnummer angehängt ist, was darauf hinweist, dass sie immer noch Alpha-Qualität haben und weiterhin wichtige Änderungen aufweisen. Weitere Informationen finden Sie in VERSIONING.md.

⚠️ Breaking Changes an instabilen APIs

– Entfernen Sie veraltete AWS Lambda v2.2-Wrapper und forceFlush(int, TimeUnit)-Überladung (#16170) – Entfernen Sie veraltete HTTP-client/Server-Methoden (#16167) – Entfernen Sie veraltete Datenbankinstrumentierungsmethoden und -klassen (#16164) – Entfernen Sie veraltete Peer-Service-Zuordnungs-APIs (#16165) – Veraltete Runtime-Telemetry-Klassen jetzt intern machen (#16173)

  • AttributesExtractorUtil entfernen (#16152)
  • Markierungsschnittstelle von SqlClientAttributesGetter entfernen (#16205) – Netzwerk-/Server-Getter-Methoden in DB-Attribut-Getter zusammenführen (#16264, #16268) – SQL-Sanitizer-Klassen in SQL-Analysator umbenennen (#16269) – Interne gemeinsame Modulpakete umbenennen, um der neuen Namenskonvention zu folgen (#16284, #16308, #16327, #16341, #16373)

🚫 Abwertungen

– Veraltete einzelne Laufzeit-Telemetrie-Modulklassen zugunsten eines einheitlichen Moduls (#16087) – Veraltete alte HTTP-Server-Abfrageparametermethoden zugunsten der Verarbeitung vertraulicher Abfrageparameter (#16097) – Veraltete alte Getter-Methoden für RPC-Attribute zugunsten neuer Methoden, die stabile semantische Konventionen unterstützen (#16130) – Veraltete alte ClickHouse-Instrumentierungsmethoden als Teil der Vereinfachung (#16206) – Veraltete alte R2DBC-Methoden zugunsten von Methoden, die db.system.name unterstützen (#16251)

  • Veraltete alte DbClientAttributesGetter-Methoden; getErrorType() mit Implementierungen hinzugefügt (#16276) – Veraltete alte RPC-Metrikmethoden zugunsten von Methoden, die stabile semantische Konventionen unterstützen (#16298)
  • Veraltete alte DbClientAttributesGetter-Methoden; getDbName() hinzugefügt, um alte/stabile Semconv-Aufteilung besser zu unterstützen (#16318)

📈 Verbesserungen

– Serveradresse und Portattribute für Spymemcached hinzufügen (#15242) – Fügen Sie Kafka Connect als integriertes JMX-Metrikziel hinzu (#15561)

  • Konvertieren Sie die Lettuce-Instrumentierung zur Verwendung von Instrumenter (#15838) – OpenSearch Java client: bereinigte Suchabfragetexte erfassen (#15634) – Anwenden stabiler semantischer Konventionen auf Camel JMX-Metriken (#16088)
  • jvm.file_descriptor.limit-Metrik hinzufügen (#16174) – Führen Sie gRPC client-Rückrufe mit übergeordnetem Kontext aus (#16175) – SQL-Zusammenfassung: EXPLAIN-Anweisungen verarbeiten (#16184) – Vereinfachen Sie die InfluxDB-Instrumentierung (#16207) – Histogramm-Buckets für db.client.operation.duration aktualisieren (#16222) – SQL-Zusammenfassung: Unterstützung der Oracle-Dblink-Syntax (#16230) – Instrumentierung für die ZIO-HTTP-Serverroute hinzufügen (#16232) – Entfernen Sie Netzwerkattribute unter dem datenbankstabilen Semconv-Flag (#16257)
  • Unterstützung von Javalin 7 (#16261)
  • gRPC: anfängliche stabile Semconv-Unterstützung (#16304) – Ressourcenattribut os.version füllen (#16311) – Camel: Unter stabilem Semconv keine DB-Spans ausgeben (#16275)
  • Dubbo: stabile Semconv-Unterstützung (#16352) – Aktualisieren Sie die Version OpenTelemetry SDK auf 1.60.0 (#16407) – Neues stabiles LogRecordBuilder.setException() verwenden (#16423) – Konfigurieren Sie semconv-stability.opt-in mit der deklarativen Konfiguration API (#16443)
  • Unterstützung otel.event.name (#16220)

🛠️ Fehlerbehebungen

– SQL Sanitizer behandelt Fragmente in doppelten Anführungszeichen jetzt standardmäßig als Zeichenfolgenliterale (#15582) – Löschen Sie die aufgezeichnete Ausnahme, wenn die Anfrage abgeschlossen ist (#16138) – URL-Verbindungsstatus nach Beendigung von Span löschen (#16155) – Korrigieren Sie die deklarative Spring-Konfiguration mit Umgebungsvariablenersetzung (#15775) – Fehlerbehandlung bei der Sendepipeline des Ktor-Servers behoben (#16192)

  • Appender protokollieren: KeyValue-Attribute sollten Vorrang vor MDC haben (#16239)
  • Erstellen Sie für jede Anfrage ein neues PekkoRouteHolder (#16258)
  • Tomcat JMX: Negative Thread- und Sitzungslimits ignorieren (#16355) – server.port ist für HTTP-client-Spans erforderlich (#16388) – Korrektur der Ktor-Server-Instrumentierung bei der Auflösung der Peer-Adresse (#16392) – Klassenumwandlungsausnahme in der Servlet-Instrumentierung behoben (#16403) – Korrigieren Sie den leeren Antworttext auf Jetty HttpClient 9.4.24–9.4.43 (#16406)
