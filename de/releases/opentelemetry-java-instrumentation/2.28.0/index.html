opentelemetry-java-instrumentation v2.28.0

Minor Veröffentlicht19. Mai 2026 Quelleopen-telemetry/opentelemetry-java-instrumentation Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

opentelemetry-java-instrumentation v2.28.0

Diese Version zielt auf den OpenTelemetry SDK 1.62.0 ab.

Beachten Sie, dass an die Versionsnummer vieler Artefakte das Suffix -alpha angehängt ist, was darauf hinweist, dass es weiterhin wichtige Änderungen geben wird. Weitere Informationen finden Sie unter VERSIONING.md.

⚠️ Breaking Changes an instabilen APIs

– Der veraltete interne ClassInjector/ProxyInjectionBuilder API, der vom alten ExperimentalInstrumentationModule.injectClasses(ClassInjector)-Pfad verwendet wurde, wurde entfernt. Verwenden Sie stattdessen ExperimentalInstrumentationModule.exposedClassNames(). (#18112) – Die zuvor veralteten, nicht stabilen API-Methoden und die veralteten Bibliotheksaliase opentelemetry-runtime-telemetry-java8 und opentelemetry-runtime-telemetry-java17 wurden entfernt. (#18136) – Die zuvor veraltete captureEventName-Bibliotheks-Builder-Einstellung wurde aus den Eigenschaften logback-appender-1.0 und log4j-appender-2.17 OpenTelemetryAppender sowie den entsprechenden otel.instrumentation.{logback-appender,log4j-appender,jboss-logmanager}.experimental.capture-event-name-Javaagent-Eigenschaften entfernt. Verwenden Sie stattdessen den Schlüssel otel.event.name in MDC/Kontextdaten/Schlüssel-Wert-Paaren/Logstash-Markierungen/strukturierten Argumenten. (#18223) – Die zuvor veralteten experimentellen Konfigurationseigenschaften otel.instrumentation.http.client.experimental.redact-query-parameters und otel.instrumentation.common.experimental.db-sqlcommenter.enabled wurden entfernt; Verwenden Sie stattdessen otel.instrumentation.sanitization.url.experimental.sensitive-query-parameters und otel.instrumentation.common.db.experimental.sqlcommenter.enabled. (#18229) – Die veraltete Eigenschaft otel.instrumentation.servlet.experimental.add-trace-id-request-attribute wurde entfernt; Verwenden Sie stattdessen otel.instrumentation.servlet.experimental.trace-id-request-attribute.enabled. (#18237)

  • Der ktor Experimental-Helfer wurde von einer Klasse mit einem companion object zu einem object der Spitzenklasse umgestaltet. Kotlin-Quellaufrufer (Experimental.emitExperimentalTelemetry(...)) sind nicht betroffen, vorkompilierte Verbraucher müssen jedoch mit dem neuen Artefakt neu kompiliert werden. (#18343)

🚫 Abwertungen

  • Verwerfen Sie otel.instrumentation.jaxws-cxf-3.0.enabled zugunsten von otel.instrumentation.jaxws-2.0-cxf-3.0.enabled und otel.instrumentation.jaxws-metro-2.2.enabled zugunsten von otel.instrumentation.jaxws-2.0-metro-2.2.enabled. (#18184)

🌟 Neue Javaagent-Instrumentierung

– Fügen Sie die Apache Thrift 0.13-Instrumentierung für RPC client und Server-Spans und -Metriken hinzu. (#18405)

🌟 Neue Bibliotheksinstrumentierung

– Fügen Sie die Apache Thrift 0.13-Bibliotheksinstrumentierung für RPC client und Server-Spans und -Metriken hinzu. (#18405)

📈 Verbesserungen

– Die Javaagent-Instrumentierung von Couchbase 3.1 gibt jetzt den konventionelleren Instrumentierungsbereichsnamen io.opentelemetry.couchbase-3.1 anstelle von io.opentelemetry.javaagent.couchbase-3.1 aus, wenn otel.instrumentation.common.v3-preview aktiviert ist. (#18426) – Wicket-Ressourcenanforderungen verwenden jetzt den Namen der Ressourcenreferenzklasse im Server-Span-Namen, wenn otel.instrumentation.common.v3-preview aktiviert ist. (#18312, #18775)

  • Entscheiden Sie, ob Javaagent-Hilfsklassen in den Anwendungsklassenlader eingefügt oder isoliert werden, basierend auf den von einer Instrumentierung verwendeten Beratungsklassen. (#17815) – Verbessern Sie die Erkennung von cgroup v2-Container-IDs für Podman durch die Unterstützung zusätzlicher mountinfo-Layouts und Warnungen, wenn mehrere Kandidaten-IDs gefunden werden. (#18272)

🛠️ Fehlerbehebungen

  • Korrigieren Sie die Routenverfolgung von Pekko HTTP und Tapir, sodass Server-Span-Namen und http.route die spezifischste übereinstimmende Route über verschachtelte Anweisungen, Ausnahmen und Zeitüberschreitungen hinweg beibehalten. Dadurch können sich Span-Namen und http.route-Werte für betroffene Routen ändern. (#16390) – Behebung des Kontextverlusts in der Finagle-HTTP-Instrumentierung über die Konvertierung von Netty-zu-Finagle-Anfragen und die asynchronen Grenzen von twitter-util Future/Promise hinweg. (#17867) – Fixierung virtueller Threads behoben, die durch die Bereinigung veralteter Einträge in schwachen Karten verursacht wurde, die auf virtuellen Threads ausgeführt wurde; Die Bereinigung wird jetzt stattdessen vom Hintergrundthread ausgeführt. (#18113) – Vermeiden Sie die Verknüpfung von Batch-Consumer-Spans mit der Ambient-Consumer-Span, wenn Datensätze oder Nachrichten keine Weitergabeheader haben. (#18154) – Fix resetOnEachOperator() für Reactor 3.1, sodass auch der Scheduler-Hook entfernt wird, wenn die Instrumentierung deaktiviert ist. (#18258) – Endspannen, wenn RxJava 1.0-Abonnements synchron ausgelöst werden. (#18265) – Die automatische Erkennung der Dienstversion Spring Boot wurde korrigiert, sodass META-INF/build-info.properties aus dem JAR-Stammverzeichnis statt BOOT-INF/classes/ gelesen wird. (#18292) – Löschen Sie Netty VirtualField, nachdem Sie eine Antwort in der Serverinstrumentierung Netty 3.8 abgeschlossen haben. (#18358) – Korrigieren Sie JarDetails, um JarFile-Handles beim Lesen von Archiven und eingebetteten JARs zu schließen und so Ressourcenlecks während der Telemetrieerfassung zur Laufzeit zu verhindern. (#18385) – Behebung eines NullPointerException beim Konvertieren eines Agentenkontexts ohne zugehörigen Anwendungskontext in einen Anwendungskontext. (#18444) – Korrigieren Sie die Ktor-Serverinstrumentierung, um OpenTelemetry-Kontextlecks zu verhindern, die durch unvollständige Coroutine-Kontextwiederherstellung verursacht werden. (#18456)
  • Korrigieren Sie die Attribute des Vert.x-Subrouters http.route, indem Sie den Mount-Punkt dem relativen Routenpfad voranstellen. Dadurch können sich Server-Span-Namen und http.route-Werte für gemountete Unterrouten ändern. (#18462) – Korrigieren Sie den Start der Oshi-Metriken und die RSS-Speicherberichterstattung mit oshi 7.0.0. (#18478) – Korrigieren Sie die Play MVC- und Play WS-Instrumentierung in Play 3.x-Anwendungen. (#18624) – Zeichnen Sie eine Fehlerempfangsspanne auf, wenn ein umschlossener Kafka-Consumer poll() fehlschlägt. (#18625) – Beheben Sie die Bereinigung schwacher Karten beim Start des Agenten, indem Sie WeakConcurrentMapCleaner vor der Byte Buddy-Installation starten. (#18628) – Korrigieren Sie die Indy-Instrumentierung, damit sie mit dem Sicherheitsmanager ohne rekursive Bootstrap-Fehler funktioniert. (#18634) – Vermeiden Sie einen Deadlock in schwachen Caches, wenn veraltete Einträge während computeIfAbsent gelöscht werden. (#18635) – Deklarative Konfigurationsanpassungsprogramme verarbeiten jetzt fehlende Prozessor- und Detektorlisten, ohne beim Start NullPointerException auszulösen. (#18641) – Behebung eines Rennens, das verhindern könnte, dass HTTP-Server-Spans in der Instrumentierung Netty, 3.8 und 4.0 korrekt enden. (#18645) – Vermeiden Sie NumberFormatException, wenn ein JDBC-URL-Port null ist. (#18708) – Korrigieren Sie die Aufgabenausführung von Vert.x TaskQueue und OrderedExecutorFactory, sodass der Span-Kontext an in der Warteschlange befindliche Runnables weitergegeben wird. (#18709) – Begrenzen Sie die Textlänge von Redis für Batch-Abfragen, um übergroße db.statement-Werte für große Batches zu vermeiden. (#18744) – Korrigieren Sie die Bereinigung von SQL-Abfragen, sodass Kennwortklauseln in SAP HANA-Verwaltungsanweisungen geschwärzt werden, ohne dass password-Kennungen geschwärzt werden. (#18754)
