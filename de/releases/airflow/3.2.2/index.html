Luftstrom 3.2.2

Wesentliche Änderungen

– Das vom Aufruf „airflow.utils.email.send_email`` now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the ``starttls()“ durchgeführte SMTP-STARTTLS-Upgrade wurde ohne SSL-Kontext durchgeführt, sodass jedes Zertifikat akzeptiert wurde. Bereitstellungen, die Airflow absichtlich auf einen SMTP-Server mit einem selbstsignierten oder anderweitig nicht validierenden Zertifikat verweisen und das vorherige Verhalten beibehalten müssen, müssen den Pfad „email.ssl_context = "none"`` in ``airflow.cfg``. The ``"default"`` value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the ``SMTP_SSL“ festlegen; Dies gilt jetzt auch für den STARTTLS-Pfad. (#65346) – In #64963 verhält sich die Airflow-Benutzeroberfläche von den vollständig übereinstimmenden Parametern „*_pattern`` REST API query parameters to the new index-friendly ``*_prefix_pattern`` parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (``LIKE 'term%'`` via a range scan) instead of substring-based (``ILIKE '%term%'``), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing ``*_pattern“ immer noch genau wie zuvor. In #66015 wurde pro Suchleiste ein Schalter „Überall abgleichen“ hinzugefügt, sodass Benutzer, die sich auf das vorherige Teilzeichenfolgenverhalten verlassen haben, sich über die Benutzeroberfläche wieder dafür entscheiden können. Jede Sucheingabe und jede Textfilterpille verfügt jetzt neben dem Wert über ein kleines Regex-Symbol. Durch Einschalten wird der Eingang von „*_prefix_pattern`` to ``*_pattern“ umgeschaltet. (#66015) – Behebung der Trigger-Race-Bedingung und des Deadlocks, die dazu führten, dass verzögerte Aufgaben auf unbestimmte Zeit ins Stocken gerieten

Trigger, die synchrone SDK-Methoden aufrufen (z. B. „get_task_states“, verwendet von „safe_to_cancel“ in mehreren Google-Anbieterbetreibern) könnte den Auslöser zum Absturz bringen interner Unterprozess. Der Auslöser würde dann normal weiter schlagen – Für den Planer erscheint es fehlerfrei – während es stillschweigend keine Auslöser verarbeitet, was zu Problemen führt jede zurückgestellte Aufgabe führt zu einer Zeitüberschreitung. Dies wurde erstmals in Problem Nr. 64620 gemeldet; a Teilweiser Fix wurde in Airflow 3.2.1 (#64882) ausgeliefert, führte jedoch zu einem neuen Deadlock mit dem gleichen sichtbaren Symptom unter Last.

Beide Probleme werden behoben, indem die sperrbasierte Serialisierung durch eine Antwort ersetzt wird Multiplexing: Jede Anfrage trägt jetzt eine eindeutige ID und die Antwort wird zurückgeleitet der richtige Aufrufer, sodass gleichzeitige Anforderungen von Trigger-Threads nicht mehr miteinander konkurrieren oder Deadlock unabhängig davon, wie viele Trigger ausgeführt werden oder welche SDK-Methoden sie aufrufen.

Neu: Trigger-Subprozess-Watchdog

Auch wenn das Rennen behoben ist, gibt es einen Trigger, der die Ereignisschleife blockiert (z. B. durch Aufrufen). time.sleep() or performing blocking I/O directly in async def run()) würde Lassen Sie den Auslöser zuvor auf unbestimmte Zeit gesund erscheinen.

Eine neue Konfigurationsoption „[triggerer] runner_health_check_threshold“ (Standard: 30 Sekunden) fügt einen Watchdog hinzu: Wenn der Trigger-Unterprozess länger als der Schwellenwert stumm bleibt, Der übergeordnete Prozess stoppt die Aktualisierung des Heartbeats, damit der Scheduler das Hängen erkennen kann Weisen Sie Auslöser neu zu, anstatt darauf zu warten, dass sie einzeln ablaufen. Legen Sie die Option fest auf „0“, um den Watchdog zu deaktivieren. (#66412)

  • Ziehen Sie „[core] allowed_deserialization_classes_regexp“ fest, um vollständige String-Übereinstimmungen zu erfordern

    Muster in „[core] allowed_deserialization_classes_regexp“ werden jetzt abgeglichen gegen den gesamten Klassennamen mit „re.fullmatch()`` instead of ``re.match()“. Bisher war nicht nur ein Muster wie „airflow\.models\.Variable“ zugelassen die beabsichtigte Klasse, aber auch Namen, die damit begannen (z. B. „airflow.models.Variable_Malicious``), because ``re.match“ nur Anker am Anfang der Zeichenfolge.

    Der Standardwert dieser Option ist leer, was bei Standardbereitstellungen der Fall ist unberührt. Bereitstellungen, die diese Option mit darauf basierenden Mustern konfiguriert haben Präfix-Match-Semantik – zum Beispiel „airflow\.models\.“, um „jede Klasse“ zu bedeuten unter „airflow.models``" — must add ``.*“ zum Muster („airflow\.models\..*“), um das vorherige Verhalten beizubehalten. (#66499)

  • Benutzerdefinierte Fristreferenzklassen müssen jetzt bei der Deserialisierung über das neue „deadline_references`` attribute on ``AirflowPlugin``, matching the existing pattern for custom timetables and custom partition mappers. To use a custom ``DeadlineReference`` subclass, register it in a plugin's ``deadline_references`` list. Custom references that are not registered will raise ``DeadlineReferenceNotRegistered“ registriert werden. (#66737)
