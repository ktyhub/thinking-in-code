zvec v0.2.1

🚀 Zvec v0.2.1 Release Notes

Ein funktionsreiches Update mit Schwerpunkt auf Build- und CI-Verbesserungen, Plattformerweiterung, Leistungsoptimierung und Verbesserungen des Entwickler-Ökosystems.

📦 Kernfunktionen und Verbesserungen

– Unterstützung für die Integration von Jina Embeddings v5 hinzugefügt (#156)

  • benutzerdefiniertes HTTP-Einbettungsbeispiel für LM Studio / Ollama hinzugefügt (#149)
  • Python API Funktionsüberladungen für verbesserte Benutzerfreundlichkeit hinzugefügt (#197)
  • Unterstützung für Python 3.13 und 3.14 hinzugefügt (#164) – Unterstützung für plattformübergreifende Android-Builds hinzugefügt (#90) – Ice-Lake-Optimierung und L2-Batch-Distanz für int8-Quantisierung aktiviert (#213)
  • Erhöhte Indexgrößenbeschränkung für dünn besetzte Vektoren (#229)

⚡ Leistungs- und Build-Optimierung

  • Optimierte IVF-Implementierung für bessere Stabilität und Leistung (#169) – Reorganisierte architekturspezifische -march-Behandlung für saubereres Build-Verhalten (#193) – RocksDB -march=native deaktiviert, um die Build-Portabilität zu verbessern (#183)
  • Verbessertes Standardverhalten beim Erstellen von Quellen um -march=native (#184) – Automatische Deaktivierung der mathematischen march-Optimierung, wenn CPU-Funktionen nicht erkannt werden können (#220)
  • std::map durch std::unordered_map für key_id_mapping ersetzt (#153) – Beschleunigte Downloads von Abhängigkeiten von Drittanbietern über OSS-Mirror-Unterstützung (#194)
  • Konfigurierbare Unterstützung für Clang stdlib und verbessertes Standard-Build-Verhalten hinzugefügt (#210) – Probleme beim Erstellen von Teilprojekten behoben, indem CMAKE_SOURCE_DIR durch PROJECT_ROOT_DIR ersetzt wurde (#195)

🐞 Fehlerbehebungen

– Aktualisiert ANTLR4 CMAKE_POLICY von OLD auf NEW für Kompatibilität mit CMake 3.31+ (#145) – Verbesserte MSVC-Kompatibilität und Stack-Sicherheit durch Ersetzen von VLAs durch std::vector (#190) – Problem mit dem uint8-Konvertierungsüberlauf behoben (#215) – Kompilierungsprobleme in mehreren Build-Umgebungen behoben (#218)

  • Logik zur Beseitigung von Absturzrückständen behoben (#208) – Ein neuer Validator für die Cosinus-Metrik-Verarbeitung hinzugefügt (#209)
  • MIPS Euclidean-Distanzimplementierung korrigiert (#226)
  • std::vector durch std::array in der Distanzimplementierung ersetzt, wo angemessen (#201) – In der zugehörigen Low-Level-Logik auf statische Array-Nutzung umgestellt (#222) – Das Verhalten der Abfragefilterung wurde korrigiert, um Filter pro Block anstelle von Filter pro Segment zu verwenden (#223) – Unit-Tests für Sparse-Builder-Dump-Timing behoben (#237)
  • Zufälliges Float-Verhalten in Unit-Tests behoben (#182) – Kompilierungswarnung in Crash-Recovery-Unit-Tests behoben (#217)

🔧 Entwicklererfahrung

  • Installationsanweisungen für das Node.js-Paket hinzugefügt (#103)
  • Paket-Repository-Links für einfacheren Zugriff auf Abhängigkeiten hinzugefügt (#104) – Verbesserte README- und CONTRIBUTING-Dokumentation, einschließlich Repository-URL, align-Attribut-Tippfehler, Python-Versionshinweise und Aktualisierungen des Join-us-Abschnitts (#139, #150, #168, #231)
  • Projektabzeichen und Trendabzeichenaktualisierungen hinzugefügt (#132, #228)
  • Rückrufbezogene Testverbesserungen hinzugefügt (#196) – Kleinere Tippfehler in Dokumentation und Codekommentaren behoben (#225)

🤖 CI/CD & Tooling

  • macOS CI mit GitHub-Runner-Unterstützung hinzugefügt (#94) – CI-Workflow mit GitHub-gehosteten Läufern hinzugefügt (#171)
  • Buildwheel-Unterstützung in GitHub-Runner-Workflows hinzugefügt (#221)
  • Unterstützung für kontinuierliches Benchmarking hinzugefügt (#110)
  • Dependabot für automatische Abhängigkeitsaktualisierungen hinzugefügt (#181) – Aktualisierte GitHub-Aktionen für Node 24-Kompatibilität und auf die neuesten Versionen (#129, #130) – Aktualisierte Workflow-Version Python auf 3.10 (#186) – Der Haupt-CI-Workflow wurde so korrigiert, dass er nur über Linux x64 hinaus korrekt ausgelöst wird (#187)
  • Fehlerhafte GitHub-Aktionsabhängigkeiten:
    • actions/setup-java v4 → v5 (#202)
    • actions/checkout v4 → v6 (#203)
    • actions/cache v3 → v5 (#204) – Verbesserte konventionelle Pre-Commit-Integration und Upgrade auf die neueste Version (#111)
