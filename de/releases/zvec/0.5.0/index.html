🚀 Zvec v0.5.0 Release Notes

📦 Neue Funktionen

  • Volltextsuche (FTS): Zvec unterstützt jetzt nativ die Volltextsuche – fügen Sie einen FTS-Index an jedes Zeichenfolgenfeld an und fragen Sie es mit natürlichsprachlichen oder strukturierten Ausdrücken ab, mit Indexverwaltung über Collection::CreateIndex / DropIndex. (#408, #445)
  • Hybrid-Abruf: Kombinieren Sie den Volltext-, Dense-Vector- und Sparse-Vector-Abruf in einem einzigen Abfrageaufruf mit Skalarfilterung und Neuranking; Die native Ausführung mehrerer Abfragen und das Neuranking verhalten sich jetzt in Python, Go, Rust und C++ konsistent. (#459, #405)
  • DiskANN-Index: Es wurde ein neuer DiskANN-Index hinzugefügt, der den Großteil des Indexes auf der Festplatte statt im RAM speichert, wodurch die Speichernutzung für milliardenschwere Datensätze drastisch reduziert wird und eine groß angelegte ANN-Suche auf Maschinen mit begrenztem Speicher möglich wird. (#369)
  • Auswahl des Ausgabefelds: fetch() akzeptiert jetzt einen output_fields-Parameter, um zu steuern, welche Felder zurückgegeben werden. (#358)

🌐 Ökosystem

Über die Kern-Engine hinaus wird das Zvec-Ökosystem um die neue offizielle Sprache SDKs und ein visuelles Management-Tool erweitert:

  • Offizielles Go SDK (zvec-go): CGO-Bindungen, die libzvec_c_api umschließen, mit vorgefertigten Bibliotheken für Linux (x64/ARM64), macOS (ARM64) und Windows (x64).
  • Offizielle Rust SDK (zvec-rust): Sichere, idiomatische Rust-Bindungen mit RAII-Ressourcenverwaltung, Builder-APIs und Result<T>-Fehlerbehandlung; unterstützt macOS (x86_64/ARM64), Linux (x86_64/ARM64) und Windows (x86_64/MSVC).
  • Zvec Studio (zvec-studio): Ein visuelles Verwaltungstool für die eingebettete Vektordatenbank von Zvec – durchsuchen Sie Daten, testen Sie Abfragen und verwalten Sie Schemata, ohne Code schreiben zu müssen. Installieren Sie über pip install zvec-studio oder laden Sie die Desktop-App für macOS / Linux / Windows herunter.

🚀 Leistungsverbesserungen

  • Schnellere Optimierung: Wiederverwendung der ersten Vektorindexdatei als Zusammenführungsbasis während der Optimierung. (#440)
  • GIL-Freigabe in Bindungen: Geben Sie die GIL in Sammlungsbindungen frei, um eine bessere Python-Parallelität zu erreichen. (#363)

🐞 Fehlerbehebungen

  • Datenkorrektheit: Nullable-Spalten-SIGABRT bei Sammlungen mit mehreren Segmenten, Nullverlust durch nullable-Skalarfilter, Querier-Schemasynchronisierung nach DDL und SQL-Optimierer-Kreuzkontamination über segmentweise QueryInfo behoben. (#415, #416, #410, #429, #449)
  • Indexstabilität: Gehärtetes DiskANN (Medoid-Eintrag, Absturz beim gleichzeitigen Erstellen, Prune-Qualität), RaBitQ (Rohvektorzusammenführung während der Optimierung, Konverterpfad, ex_bits-Validierung), IVF-Ergebnisreihenfolge und Benennung von Vektorindizes. (#433, #456, #425, #436, #422, #421)
  • Verschiedene Korrekturen: Windows-Makrokonflikt, uint64_t-Formatbezeichner, HNSW-Kontextabruf und Python-Komponententests. (#435, #374, #386, #401)

🔧 Refactoring und Bereinigung

  • Einheitliche Abfrage API: VectorQuery wurde gelöscht, Einzelzielabfrage auf SearchQuery vereinheitlicht und Neurangierung auf eine vektorbasierte Schnittstelle umgestellt. (#428, #431, #458, #267)
  • Codebase Cleanup: modernize-use-override angewendet, segmentlokale Zeilen-IDs geklärt, den DiskANN-Build optimiert, auf eine explizite x86-CPU-Whitelist umgestellt, die Hamming-Metrik und den Buffer Manager entfernt und Fehlermeldungen überarbeitet. (#442, #419, #432, #475, #258, #365, #437, #400)

🤖 CI- und Build-Verbesserungen

  • Build Hardening: -Werror auf allen CI-Plattformen aktiviert, RISC-V FastPFOR über SIMDe behoben, Drittanbieter-Includes als SYSTEM markiert und DiskANN CMake-Pfade korrigiert. (#460, #470, #413, #464)
  • Schnelleres CI: Ccache/Sccache (inkl. Windows) hinzugefügt, Tests parallelisiert, Clang-Tidy beschleunigt, den Hauptworkflow erweitert und CRoaring auf eine Zusammenführung reduziert (~292 MB → ~ 1 MB). (#360, #439, #454, #384, #412, #417, #418, #438, #396, #448, #381)
  • Abhängigkeitsbumps: actions/cache 4→5 und codecov/codecov-action 6→7. (#466, #467)
