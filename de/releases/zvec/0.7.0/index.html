zvec v0.7.0

🚀 Zvec v0.7.0 Release Notes

⚠️ Breaking Changes

  • C++ öffentliches API auf Snake_case umgestellt: Alle öffentlichen C++ SDK-Schnittstellen (Index, Collection usw.) wurden von PascalCase nach Snake_case verschoben. Zum Beispiel Open() → open(), Search() → search(), Query() → query() und Insert() → insert(). C++ SDK-Benutzer müssen beim Upgrade ihre Aufrufseiten aktualisieren. Die C-Namen API und Python API bleiben unverändert. (#683)

📦 Neue Funktionen

  • IVF-RaBitQ-Index: RaBitQ-Quantisierungsunterstützung für IVF-Indizes hinzugefügt, wodurch RaBitQ auf Abrufszenarien mit dichteren Vektoren ausgeweitet wird. C- und Python-Bindungen sowie Testabdeckung sind im Lieferumfang enthalten. (#540)
  • Turbo-Präprozessor-Framework: Einführung einer optionalen Präprozessorkomponente im Turbo-Quantisierermodul. Die FHT-Rotation (Fast Hadamard Transform) ist jetzt implementiert. OPQ-Rotation und Dimensionsreduzierung sind für zukünftige Versionen geplant. (#548)
  • Turbo PQ-INT8-Quantisierer: Dem Turbo-Framework wurde ein PQ-basierter INT8-Quantisierer hinzugefügt, der L2-, Kosinus- und Innere-Produkt-Distanzmetriken für Benutzer abdeckt, die eine höhere Komprimierung benötigen. (#554)
  • Turbo-Datensatzquantisierer: INT8/INT4-Datensatzquantisierung und FP16-Quantisierer in das Turbo-Framework migriert, tragbare skalare Distanzkerne für Nicht-SIMD-Ziele hinzugefügt und die Kernel-Dispatch-Registrierung überarbeitet, sodass jeder Quantisierungstyp einem expliziten Backend-Pfad zugeordnet ist. (#624)
  • Einheitliche uint7/uint8-Quantisierung: Es wurden einheitliche uint7- und einheitliche uint8-Quantisierungsoptionen verfügbar gemacht, was Benutzern mehr Flexibilität beim Abwägen von Recall und Komprimierung bietet. (#608)
  • RaBitQ-Laufzeit-AVX2/AVX512-Dispatch: HNSW-RaBitQ wählt jetzt AVX2- oder AVX512-Implementierungen zur Laufzeit basierend auf der Host-CPU aus, wodurch die Notwendigkeit entfällt, einen Befehlssatz zur Build-Zeit fest zu codieren. (#632)
  • Plattformübergreifende DiskANN-Unterstützung: DiskANN wurde von Linux x86_64 auf Linux ARM64 und macOS ARM64 (Apple Silicon) erweitert. Es wählt nun das beste verfügbare I/O-Backend aus – io_uring, libaio oder pread – und greift sicher zurück. macOS verwendet F_NOCACHE und deaktiviert das Vorauslesen für DiskANN-Dateien. (#557, #599)
  • Vamana-Grafikerstellung in zwei Durchgängen: Für Vamana wurde ein optionaler Grafikerstellungspfad in zwei Durchgängen hinzugefügt, der die Grafikqualität bei einigen Datensätzen verbessert. (#634)
  • HNSW-Diagrammerstellung aus Originalvektoren: HNSW kann das Diagramm jetzt aus rohen Originalvektoren erstellen, die von einem Anbieter bereitgestellt werden, während die Suche weiterhin für die im Index gespeicherten Vektoren ausgeführt wird, wodurch die Diagrammqualität verbessert wird, wenn gespeicherte Vektoren verlustbehaftet sind. (#657)
  • FTS-Ngram-Tokenizer: Für die Volltextsuche wurde ein Ngram-Tokenizer hinzugefügt, der für den Abgleich auf Zeichenebene wie Kurztext, Code oder Pinyin nützlich ist. (#593)
  • DocIterator für die vollständige Sammlungsdurchquerung: DocIterator für das Streaming der vollständigen Sammlungsdurchquerung über C++, C und Python hinzugefügt. Der Iterator erstellt einen Snapshot, sodass spätere Schreib- und Löschvorgänge unsichtbar sind und Python API with collection.iter_docs() unterstützt. (#597)
  • musllinux-Räder: x86_64- und arm64-Python-Räder-Builds für musl-libc-Umgebungen sowie Kompatibilitätskorrekturen für musl-Thread-Stacks, Logger-Singleton-Lebensdauer und DiskANN-Heap-Überlesungen hinzugefügt. (#649)
  • Vorgefertigte SDK-Release-Pipeline: PR #628 schlägt eine GitHub-Release-Pipeline vor, die vorgefertigte C/C++ SDK-Pakete für Linux (glibc und musl, x86_64 und arm64), macOS ARM64, Windows x86_64, Android arm64 und iOS XCFrameworks erstellt und veröffentlicht, wann immer ein v*-Tag vorhanden ist wird geschoben.

🚀 Leistungsverbesserungen

  • Asynchrone DiskANN-E/A-Überlappung und dynamischer Beam: Die DiskANN-Beam-Suche wurde überarbeitet, um CPU-Arbeit mit Festplatten-E/A zu überlappen, und eine dynamische Beam-Breite wurde eingeführt, wodurch die Abfragelatenz bei festplattengebundenen Arbeitslasten reduziert wurde. (#617)
  • Kleinere dynamische Bibliotheken: Die Größe vorgefertigter dynamischer Bibliotheken wurde reduziert, indem die Symbolsichtbarkeit gesteuert, die Eliminierung von totem Code ermöglicht und die Protobuf/Protoc-Build-Abhängigkeit entfernt wurde. Unter macOS ARM64 sank libzvec_c_api.dylib von 37.21 MB auf 22.06 MB (-40.7 %) und libzvec.dylib von 36.96 MB auf 23.37 MB (-36.8 %). Der Kernsuchcode bleibt mit -O3 kompiliert, sodass die Abfrageleistung nicht beeinträchtigt wird. (#627)

🐞 Fehlerbehebungen

  • Index- und Speicherstabilität: Absturz behoben, wenn der Forward-Store-Writer nicht geöffnet werden konnte; Optimierung nach Absturzwiederherstellung aktiviert, ohne die WAL zu öffnen; dauerhaftes Schreiben von Segmentdatensätzen nur zum Löschen; verarbeitete große finale IPC-Blöcke im mmap-Store; Bereinigte verwaiste Segmentverzeichnisse nach der Wiederherstellung nach einem Absturz; und gelöschte Segmentverzeichnisse nach der Optimierung unter Windows bereinigt. (#579, #600, #618, #645, #674, #676)
  • DiskANN: DiskANN korrekt in die zvec-Kernbibliothek eingebunden; machte den Linux-AIO-Fallback für Teiloperationen sicher; Ein Überlesen des Heaps in add_vector und ein Off-by-one-Fehler in convert_pivot_data wurden behoben. (#602, #615)
  • Vamana / HNSW: Vamana berücksichtigt jetzt asymmetrische Abfragemetriken; behobene Probleme rund um HnswExternalStreamerEntity; Der pq_int8-Fehler auf ARM NEON wurde behoben. und korrigierte sphärische K-Mittel-Schwerpunktnormalisierung und K-MC2-Stichprobengewichte. (#635, #607, #682, #654, #655)
  • Suchen und Filtern: Filtervalidierung und Zurücksetzen veralteter Filterzustände korrigiert; isoliertes Gleich-oder-Umschreiben über UND in der SQL-Engine; verhindert, dass Heap-Invarianten umgangen werden; und ASan-Probleme behoben, einschließlich eines Visit_Filters nach dem anderen. (#663, #679, #633, #650)
  • Python-Bindungen: Validieren Sie die Abfrage topk und Feldnamen, lehnen Sie leere FTS-Abfragen ab, fügen Sie eine close()-Methode für Sammlungen hinzu und normalisieren Sie Dokument-Numpy-Vektoren, damit Benutzer klarere Fehler anstelle von stillem Fehlverhalten erhalten. (#616, #612, #640, #567, #653)
  • Parallelität bei der Sammlungswartung: Lese- und Schreibvorgänge können jetzt fortgesetzt werden, während Optimize ausgeführt wird. Außerdem wurden nicht übereinstimmende Skalar-Batch-Grenzen behoben. (#614, #639)
  • Build und Versionierung: Der C API meldet keine gefälschte 0.2.1-Version mehr, wenn Git-Tags fehlen; UTF-8-Pfade werden unter Windows korrekt gehandhabt; All-in-One-DLL-Exporte sind begrenzt; ANTLR4 MSVC D9025-Warnungen und ThreadQueue-Lambda-Erfassungsfehler wurden behoben; Veraltete Submodul-Patch-Marker und fehlerhafte Protobuf-Arbeitsbäume werden bereinigt. (#629, #666, #611, #693, #688, #675, #671)

🔧 Refactoring und Bereinigung

  • Thread-Pool-CPU-Affinität ist jetzt optional: Der Thread-Pool fixiert Threads nicht mehr standardmäßig an CPU-Kerne, um Überraschungen in Containern oder anderen planungssensiblen Umgebungen zu vermeiden. Affinität kann weiterhin explizit aktiviert werden. (#623)
  • Redundante Komponenten entfernt: Die redundanten Schlüsselwörter IndexLogger und unnötige virtual wurden entfernt, um die Wartungsoberfläche zu reduzieren. (#652, #631)
  • Teststabilisierung: Stabilisierte DiskANN- und IVF-Suchtests, deterministische ThreadQueue-Wartevorgänge und aktualisierte Sammlungswiederherstellungstests für die neuen APIs. (#637, #680, #686)

🤖 CI- und Build-Verbesserungen

  • Windows-/MSVC-Builds: Der Snowball-Codegen-Build wurde für MSVC-Kompatibilität auf CMake umgestaltet, Nmake-Unterstützung hinzugefügt und MSVC-Lambda-Capture- und ANTLR4-Warnungsprobleme behoben, wodurch die Windows-Entwicklung reibungsloser wurde. (#668, #661, #688, #693)
  • Abhängigkeits- und Aktionsprobleme: actions/setup-python (6→7), actions/setup-java (5→5.6.0→5.7.0) und mozilla-actions/sccache-action (0.0.10→0.0.11) aktualisiert. (#620, #641, #667, #642)
  • CI-Verhalten: Prüfungen werden jetzt ausgeführt, wenn ein PR-Entwurf fertig wird; pyproject.toml fügt einen python_version-Marker für cibuildwheel hinzu und fügt den fehlenden pytest-xdist in [dev] ein. (#670, #560)

📝 Dokumentation

  • Die README-Datei wurde auf v0.6.0 aktualisiert und der WeChat-QR-Code-Link korrigiert. (#606, #610, #651)
