🤝 Multi-Agent-Teams

CowAgent ist jetzt ein Multi-Agent-Framework. Sie können mehrere Agenten mit jeweils eigenen Rollen erstellen, um ein Team zu bilden und innerhalb einer einzigen Sitzung an komplexen Aufgaben zusammenzuarbeiten. Unterstützt auf der Webkonsole, dem Desktop client und Kanalintegrationen:

  • Teamverwaltung: Agenten erstellen und verwalten, Namen, Verantwortlichkeiten, Standardmodell, Fähigkeiten und Kenntnisse konfigurieren und das Setup von einem vorhandenen Agenten kopieren.
  • Ressourcenisolation: Jeder Agent verfügt über seinen eigenen Arbeitsbereich, Speicher und Sitzungen; Die Wissensbasis und die Fähigkeiten können geteilt oder unabhängig gehalten werden.
<Rahmen> <img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/team-overview.png" alt="Agententeam" width="800" /> </Frame>
  • Gruppenzusammenarbeit: Fügen Sie mehrere Agenten zu einer Sitzung hinzu und verwenden Sie @, um eine Nachricht an ein bestimmtes Mitglied weiterzuleiten, wobei jeder Agent sein eigenes konfiguriertes Modell verwendet.
  • Aufgabendelegation: Ein Gruppenchat hat einen leitenden Agenten, der eine Aufgabe basierend auf seinen Verantwortlichkeiten an das Mitglied weiterleiten kann, das am besten dafür geeignet ist, mit Unterstützung für mehrstufige Delegation und konfigurierbarem Umfang, Tiefe und Zeitlimit.
<Rahmen> <img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/agent-group-chat-demo.png" alt="Agent-team-group" width="800"/> </Frame>
  • Mehrere Kanalinstanzen: Ein IM-Kanal desselben Typs kann jetzt mehrere Instanzen ausführen, die jeweils an einen einzelnen Agenten oder ein Agententeam gebunden sind. Unterstützt auf WeChat, WeCom Smart Bots, Feishu, DingTalk, QQ, Telegram, Slack, Discord und mehr.
<Rahmen> <img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/channel-config.png" alt="Agent-team-channel" width="800"/> </Frame>

Danke @AaronZ345 (#2975, #2973), @zkjqd (#3096), @cowagent (#3118)

Dokumente: Agententeams

⏰ Geplante Aufgaben-Upgrades

Geplante Aufgaben können jetzt über die Konsole erstellt und verwaltet werden, wobei Kanalempfänger und Ausführungsdatensätze hinzugefügt werden:

  • Manuelle Aufgabenerstellung: Erstellen, bearbeiten und führen Sie Aufgaben direkt auf der Aufgabenseite aus und wählen Sie die Kanalinstanz und den Empfänger aus.
  • Kanalempfängerverwaltung: Verwalten Sie trusted-Empfänger pro Kanalinstanz, sodass eine Aufgabe an einen bestimmten Empfänger und nicht nur an den Kanal, in dem sie erstellt wurde, übermittelt werden kann. Danke @dajiaohuang (#3043)
  • Ausführungsaufzeichnungen: Auf einer neuen Seite mit Ausführungsaufzeichnungen können Sie die Verlaufsliste und die Details jedes Laufs überprüfen. Danke @mengluo04 (#3107)
  • Korrektur für gleichzeitige Updates: Es wurde behoben, dass Aufgaben bei gleichzeitigen Updates verloren gingen (Danke @Whxuan0701 #3062).

📊 Kontext-Nutzungsvisualisierung

Der Kontextverbrauch ist jetzt sichtbar und kontrollierbar, wodurch die Token-Kosten einfacher zu verwalten sind:

  • Kontextnutzungsansicht: Eine Ringansicht ersetzt die bisherige Schaltfläche „Kontext löschen“ und zeigt eine vollständige Aufschlüsselung dessen, was den Kontext ausmacht.
  • Kontextaktionen: Unterhalb der Ringansicht können Sie eine intelligente Komprimierung auslösen, den Kontext löschen oder die maximale Kontextgröße festlegen.
  • Kontextberechnung: Die Nutzungsaufschlüsselung wird automatisch aus der vom Modell gemeldeten Nutzung abgeleitet, wobei agent_max_context_tokens als vom Benutzer konfigurierbare Kostenobergrenze verfügbar ist.

Danke @chimyves (#3087), @sufan721 (#3079)

🤖 Modellfähigkeiten

  • Neue Modelle: deepseek-flash (DeepSeek V4.1 Flash), gpt-6-astra, claude-fable-5-1, qwen3.8-flash, glm-5.3-flash, gemini-3.8-flash und das Vision-Modell deepseek-v4-flash-vision-exp hinzugefügt (Danke @a1094174619 #3094).
  • Modell-Fallback: Konfigurieren Sie unter Modellkonfiguration > Primärmodell ein Fallback-Modell, das automatisch übernimmt, wenn das Primärmodell ausfällt, und so Unterbrechungen durch den Ausfall eines einzelnen Anbieters verhindert. Danke @alanyz106 (#3099)
  • Sechs neue Suchanbieter:
    • AnySearch (unterstützt den anonymen Modus). Danke @WangPan59 (#3083)
    • Serply (Google/Bing SERP API). Danke @googio (#3071)
    • Parallele Suche. Danke @georgeatparallel (#3116)
    • Tavily (Suche API optimiert für LLMs). Danke @1printf (#3124)
    • SearXNG (selbstgehostete Suchmaschine, nur die Instanz-URL ist erforderlich). Danke @1printf (#3124)
    • Keenable (unterstützt den anonymen Modus, kein API-Schlüssel erforderlich). Danke @ilya-bogin-keenable (#3122)

📝 Bearbeitung von Arbeitsbereichsdateien

Workspace-Dateien, Langzeitgedächtnisdokumente und Skilldefinitionen können jetzt direkt in der Webkonsole und dem Desktop client bearbeitet und gespeichert werden:

  • In-Place-Bearbeitung: Textdateien im Arbeitsbereich, im Speicher und in den Skill-Modulen (Markdown, Code, CSV, HTML, einfacher Text und mehr) können direkt bearbeitet werden, mit Tastenkombinationen für Ctrl+S zum Speichern, Esc zum Beenden und Tab zum Einrücken.
  • Sicheres Speichern: Das Speichern prüft auf Konflikte mit der Änderungszeit der Datei beim Öffnen; Wenn der Agent die Datei zwischenzeitlich geändert hat, werden Sie zuerst gefragt, anstatt sie zu überschreiben. Wenn Sie das Bedienfeld schließen, Dateien wechseln, Sitzungen wechseln oder Arbeitsbereiche wechseln, werden Sie zur Bestätigung nicht gespeicherter Änderungen aufgefordert.

Danke @zkjqd (#3076)

🛠 Verbesserungen und Korrekturen

  • Skill-Korrekturen:
    • Gehärtete Tar-Archiv-Extraktion (Danke @Whxuan0701 #3063)
    • Lösen Sie den Standardzweig eines Repositorys auf, anstatt bei der Installation eines Skills standardmäßig main zu verwenden (Danke @aniruddhaadak80 #3080)
  • MCP-Verbesserungen:
    • Unterstützt Werkzeugnamen-Präfixe (Danke @georgeatparallel #3116)
    • Abgelaufene Streamable-HTTP-Sitzungen wiederherstellen (Danke @yiheng-kkk ad1f686) – Verwenden Sie den Unterprozess wieder und löschen Sie doppelte Ladeprotokolle, wenn mehrere Agenten dasselbe mcp.json verwenden
  • Bilderzeugung: – Fehler behoben, bei dem ModelScope IMAGE_CREATE aufgrund einer Parameterinkongruenz fehlschlug (Danke @Anai-Guo #3097) – Fehler behoben, bei dem leere Base64-Daten fälschlicherweise erkannt wurden und eine leere Bilddatei erzeugten (Danke @c020627 #3133, @justinguo7777 #3131)
  • Sub-Agent-Korrektur: Ein Sub-Agent wurde behoben, der die Fallback-Einstellungen der übergeordneten Sitzung löschte (Danke @alanyz106 #3111).
  • Strukturiertes Chunking: Markdown-Speicher und Wissensdokumente werden nach Überschriftenstruktur in Chunks unterteilt, mit einer Aufforderung zum Neuaufbau, wenn die Chunk-Version veraltet ist. Danke @alanyz106 (#3115)
  • Behebung von Streaming-Fehlern: Es wurden sieben Modell-Bots behoben, die bei Streaming-Fehlern einen NameError auslösten, weil der Generator über die bereits gelöschte Ausnahmevariable geschlossen wurde, wodurch der tatsächliche Upstream-Fehler maskiert wurde (Danke @Anai-Guo #3128).
  • Korrektur des Speicherindex: Es wurden leere Textblöcke behoben, die zu Fehlern bei den Einbettungen API führten und die gesamte Speicherindexerstellung fehlschlugen, sodass auf die Schlüsselwortsuche zurückgegriffen wurde (Danke @6vision #3121).
  • Unterbrechungserkennung: Leiten Sie stop_reason an die Agent-Schleife weiter, um zu unterscheiden, ob ein Modell alleine endet oder durch die Ausgabebegrenzung abgeschnitten wird (Danke @6vision #3074).
  • Anhangserkennung: Stichwort-Anhangs-URLs mit dem aufgelösten Pfad abgleichen (Danke @Whxuan0701 #3061).
  • Gateway-Attribution: Quellenangabe zu OrcaRouter-Gateway-Anfragen hinzufügen (Danke @Marc-oss-hub #3058).
  • Proxy-Rendering: Setzen Sie den Content-Type auf /chat, damit die Konsole hinter einem Reverse-Proxy mit Nosniff korrekt rendert (Danke @alanyz106 #3110).
  • Avatar-Verarbeitung: Fehler beim Hochladen von Avataren aufgrund der Textdekodierung behoben, es werden jetzt Rohbytes gelesen (Danke @mengluo04).
  • Auswertungstool: Es wurde ein minimaler Ablauf zur Auswertung der Agenten-Trajektorie hinzugefügt. Danke @yanzhiliaoliao (#3100)
  • DingTalk-Kanal: Deaktivieren Sie den Proxy bei Streaming-Verbindungen und deaktivieren Sie ihn bei erneuter Verbindung, um wiederkehrende Fehler zu vermeiden.
  • Windows client: Eine Update-Installation, bei der die Verknüpfung unterbrochen wurde, wurde behoben.
  • Desktop client: Numerische Agent-Einstellungen wie maximale Kontexttokens wurden behoben, die nicht gelöscht werden konnten (Danke @zkjqd #3130).
  • Sicherung und Wiederherstellung: Sicherungen umfassen jetzt alle Agent-Arbeitsbereiche, mit Korrekturen für verschachtelte Archivierung, Wiederherstellungslayout und Versionskompatibilität in Multi-Agent-Setups.
  • Dokumente:
    • Einen Eintrag für traditionelles Chinesisch zum Sprachumschalter für japanische Dokumente hinzugefügt (Danke @c020627 #3072)
    • Kimi-bezogene Links hinzugefügt (Danke @oriengy #2885)

📦 So führen Sie ein Upgrade durch

  • Quellbereitstellung: Führen Sie cow update für ein click-Upgrade aus oder rufen Sie den neuesten Code ab und starten Sie neu. Siehe die Upgrade-Anleitung.
  • Desktop client: Suchen Sie nach Updates und aktualisieren Sie mit einem click im client, ​​oder holen Sie sich die neueste Version von der Download-Seite.
