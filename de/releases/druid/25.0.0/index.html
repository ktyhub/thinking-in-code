Druide Druide-25.0.0

Apache Druid 25.0.0 enthält über 300 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 51 Mitwirkenden. Weitere Einzelheiten finden Sie im vollständigen Änderungssatz.

<a name="25-highlights" href="#25-highlights">#</a> Highlights

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> MSQ-Task-Engine jetzt produktionsbereit

Die für die SQL-basierte Aufnahme verwendete Multi-Stage-Query-Task-Engine (MSQ) ist jetzt produktionsbereit. Verwenden Sie es für alle unterstützten Workloads. Weitere Informationen finden Sie auf den folgenden Seiten:

  • Einnahme – SQL-basierte Aufnahme

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Vereinfachte Druid-Bereitstellungen

Das neue start-druid-Skript vereinfacht die Bereitstellung beliebiger Kombinationen von Druid-Diensten auf einem einzelnen Server erheblich. Es ist mit den erforderlichen Konfigurationen vorinstalliert und kann zum Starten eines voll funktionsfähigen Druid-Clusters einfach durch Aufruf von ./start-druid verwendet werden. Erfahrenen Druiden bietet es außerdem die vollständige Kontrolle über die Laufzeiteigenschaften und JVM-Argumente, um einen Cluster zu erhalten, der genau Ihren Anforderungen entspricht. Das start-druid-Skript veraltet die vorhandenen Profile wie start-micro-quickstart und start-nano-quickstart. Diese Profile werden möglicherweise in zukünftigen Versionen entfernt. Weitere Informationen finden Sie unter Einzelserverbereitstellung.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> String-Wörterbuchkomprimierung (experimentell)

Unterstützung für frontcodierte String-Wörterbücher für kleinere String-Spalten hinzugefügt, was zu reduzierten Segmentgrößen mit nur geringfügigen Leistungseinbußen für die meisten Druid-Abfragen führt. Dies kann durch Festlegen von IndexSpec.stringDictionaryEncoding auf {"type":"frontCoded", "bucketSize": 4} aktiviert werden, wobei bucketSize eine beliebige Zweierpotenz kleiner oder gleich 128 ist. Durch Festlegen dieser Eigenschaft werden Indizierungsaufgaben angewiesen, Segmente mithilfe komprimierter Wörterbücher der angegebenen Bucket-Größe zu schreiben.

Mit der String-Dictionary-Komprimierung geschriebene Segmente können von älteren Versionen von Druid nicht gelesen werden. Weitere Informationen finden Sie unter Vordere Codierung. https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Kubernetes-native Aufgaben

Druid kann jetzt Kubernetes zum Starten und Verwalten von Aufgaben verwenden, sodass keine mittleren Manager erforderlich sind. Um diese Funktion zu nutzen, aktivieren Sie druid-kubernetes-overlord-extensions in der Ladeliste für Erweiterungen für Ihren Overlord-Prozess. https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-kompatible-binary" href="#25-highlights-hadoop-3-kompatible-binary">#</a> Hadoop-3-kompatible Binärdatei

Druid wird jetzt als dedizierte Binärdatei für Hadoop-3-Benutzer geliefert, die Hadoop-3-kompatible Jars enthält. Wenn Sie Hadoop-3 nicht mit Ihrem Druid-Cluster verwenden, können Sie weiterhin die klassische Binärdatei verwenden.

<a name="25-multi-stage-query-task-engine" href="#25-multi-stage-query-task-engine">#</a> Task-Engine für mehrstufige Abfragen (MSQ).

<a name="25-msq-docker-enabled" href="#25-msq-docker-enabled">#</a> MSQ für Docker aktiviert

Die MSQ-Aufgabenabfrage-Engine ist jetzt standardmäßig für Docker aktiviert. https://github.com/apache/druid/pull/13069

<a name="25-msq-query-history" href="#25-msq-query-history">#</a> Abfrageverlauf

Mehrstufige Abfragen werden nicht mehr im Dialogfeld „Abfrageverlauf“ angezeigt. Sie sind weiterhin im Bereich Letzte Abfrageaufgaben verfügbar.

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> Beschränkung für CLUSTERED BY-Spalten

Bei Verwendung der MSQ-Task-Engine zum Erfassen von Daten ist die Anzahl der Spalten, die in der CLUSTERED BY-Klausel übergeben werden können, jetzt auf 1500 begrenzt. https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> Unterstützung für die Komprimierung des String-Wörterbuchs

Die MSQ-Task-Engine unterstützt die Frontcodierung von String-Wörterbüchern für eine bessere Komprimierung. Dies kann für INSERT- oder REPLACE-Anweisungen aktiviert werden, indem indexSpec im Abfragekontext auf eine gültige json-Zeichenfolge gesetzt wird. https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> Sketch-Merging-Modus

Mitarbeiter können jetzt Schlüsselstatistiken sammeln, die zum Generieren von Partitionsgrenzen verwendet werden, entweder sequentiell oder parallel. Setzen Sie clusterStatisticsMergeMode im Abfragekontext auf PARALLEL, SEQUENTIAL oder AUTO, um den entsprechenden Skizzenzusammenführungsmodus zu verwenden. Weitere Informationen finden Sie unter Skizzen-Zusammenführungsmodus. https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> Leistungs- und Betriebsverbesserungen

– Fehlermeldungen: Bei unzulässigen MSQ-Warnungen bestimmter Typen wird die Warnung jetzt als Fehler angezeigt. https://github.com/apache/druid/pull/13198

  • Secrets: Bei Aufgaben, die SQL mit sensiblen Schlüsseln enthalten, maskiert Druid jetzt die Schlüssel beim Protokollieren mit den regulären Hilfsausdrücken. https://github.com/apache/druid/pull/13231
  • Downsampling-Genauigkeit: Die MSQ-Task-Engine verwendet beim Downsampling von Daten jetzt die Anzahl der Bytes statt der Anzahl der Schlüssel. https://github.com/apache/druid/pull/12998
  • Speichernutzung: Bei der Bestimmung von Partitionsgrenzen ist der Heap-Footprint interner Skizzen, die von MSQ verwendet werden, jetzt auf 10 % des verfügbaren Speichers oder 300 MB begrenzt, je nachdem, welcher Wert niedriger ist. Zuvor lag die Obergrenze streng bei 300 MB. https://github.com/apache/druid/pull/13274
  • Aufgabenberichte: Felder pendingTasks und runningTasks zum Arbeiterbericht hinzugefügt. Zugehörige Änderungen an der Webkonsole finden Sie unter Statusinformationen zur Abfrageaufgabe. https://github.com/apache/druid/pull/13263

<a name="25-querying" href="#25-querying">#</a> Abfrage

<a name="25-querying-enabled-async-reads-for-jdbc" href="#25-querying-enabled-async-reads-for-jdbc">#</a> Asynchrone Lesevorgänge für JDBC

JDBC-Zeitüberschreitungen bei langen Abfragen wurden verhindert, indem leere Batches zurückgegeben wurden, wenn ein Batch-Abruf zu lange dauerte. Verwendet ein asynchrones Modell, um den Ergebnisabruf gleichzeitig mit JDBC-Anfragen auszuführen. https://github.com/apache/druid/pull/13196

<a name="25-querying-in-filter" href="#25-querying-in-filter">#</a> Verbesserter Algorithmus zur Überprüfung der Werte eines IN-Filters

Um große Wertemengen zu berücksichtigen, die aus großen IN-Filtern oder aus als IN-Filtern nach unten verschobenen Verknüpfungen entstehen, verwendet Druid jetzt einen sortierten Zusammenführungsalgorithmus zum Zusammenführen der Menge und des Wörterbuchs für größere Werte. https://github.com/apache/druid/pull/13133

<a name="25-querying-context-security" href="#25-querying-context-security">#</a> Verbesserte Abfragekontextsicherheit

Die folgenden Konfigurationseigenschaften wurden hinzugefügt, die das von druid.auth.authorizeQueryContextParams gesteuerte Abfragekontext-Sicherheitsmodell verfeinern: – druid.auth.unsecuredContextKeys: Eine JSON-Liste von Abfragekontextschlüsseln, die keine Sicherheitsüberprüfung erfordern. – druid.auth.securedContextKeys: Eine JSON-Liste von Abfragekontextschlüsseln, die eine Sicherheitsüberprüfung erfordern. Wenn beide gesetzt sind, fungiert unsecuredContextKeys als Ausnahme von securedContextKeys. https://github.com/apache/druid/pull/13071

<a name="25-querying-http-response-headers" href="#25-querying-http-response-headers">#</a> HTTP-Antwortheader

Die HTTP-Antwort für eine SQL-Abfrage legt jetzt die Antwortheader korrekt fest, genau wie bei einer nativen Abfrage. https://github.com/apache/druid/pull/13052

<a name="25-nested-columns" href="#25-nested-columns">#</a> Verschachtelte Spalten

<a name="25-nested-columns-nested-columns-performance-improvement" href="#25-nested-columns-nested-columns-performance-improvement">#</a> Leistungsverbesserung bei verschachtelten Spalten

NestedDataColumnSerializer wurde verbessert, um für die fehlenden Werte jeder Zeile nicht mehr explizit Nullwerte in die Feldschreiber zu schreiben. Stattdessen wird die Übergabe des Zeilenzählers an die Feldschreiber verlagert, sodass diese Nullwerte in großen Mengen auffüllen können. https://github.com/apache/druid/pull/13101

<a name="25-nested-columns-support-for-more-formats" href="#25-nested-columns-support-for-more-formats">#</a> Unterstützung für weitere Formate

Wenn Daten während der Verarbeitung „reduziert“ werden müssen, nimmt der Operator nun ein Array auf und reduziert das Array dann in N (N = Anzahl der Elemente im Array) Zeilen, wobei jede Zeile einen der Werte aus dem Array enthält. https://github.com/apache/druid/pull/13085

<a name="25-ingestion" href="#25-ingestion">#</a> Einnahme

<a name="25-ingestion-improved-filtering-for-cloud-objects" href="#25-ingestion-improved-filtering-for-cloud-objects">#</a> Verbesserte Filterung für Cloud-Objekte

Sie können jetzt bei beliebigen Unterordnern anhalten, indem Sie die Glob-Syntax im Feld ioConfig.inputSource.filter für die native Batch-Aufnahme aus Cloud-Speichern wie S3 verwenden. https://github.com/apache/druid/pull/13027

<a name="25-ingestion-async-task-client-for-streaming-ingestion" href="#25-ingestion-async-task-client-for-streaming-ingestion">#</a> Asynchrone Aufgabe client für die Streaming-Aufnahme

Sie können jetzt die asynchrone Kommunikation zwischen dem Stream-Supervisor und den Indizierungsaufgaben aktivieren, indem Sie chatAsync im tuningConfig auf true setzen. Die asynchrone Aufgabe client verwendet einen eigenen internen Thread-Pool und ignoriert daher die Eigenschaft chatThreads. https://github.com/apache/druid/pull/13354

<a name="25-ingestion-improved-control-for-how-druid-reads-json-data-for-streaming-ingestion" href="#25-ingestion-improved-control-for-how-druid-reads-json-data-for-streaming-ingestion">#</a> Verbesserte Handhabung von JSON-Daten mit Streaming-Ingestion

Sie können jetzt besser steuern, wie Druid JSON-Daten für die Streaming-Aufnahme liest, indem Sie die folgenden Felder in der Eingabeformatspezifikation festlegen:

  • assumedNewlineDelimited, um Zeilen von JSON unabhängig zu analysieren. – useJsonNodeReader, um gültige JSON-Ereignisse beim Parsen mehrzeiliger JSON-Ereignisse beizubehalten, wenn eine Parsing-Ausnahme auftritt. Die Webkonsole wurde aktualisiert und enthält nun diese Optionen. https://github.com/apache/druid/pull/13089

<a name="25-ingestion-idle-supervisor" href="#25-ingestion-idle-supervisor">#</a> Aufnahme aus einem inaktiven Kafka-Stream

Wenn ein Kafka-Stream inaktiv wird, kann der Supervisor, der daraus Daten aufnimmt, so konfiguriert werden, dass keine neuen Indizierungsaufgaben mehr erstellt werden. Der Supervisor nimmt die Erstellung neuer Indizierungsaufgaben automatisch wieder auf, sobald der Stream wieder aktiv wird. Setzen Sie die Eigenschaft dataSchema.ioConfig.idleConfig.enabled in der jeweiligen Supervisor-Spezifikation auf „true“ oder legen Sie druid.supervisor.idleConfig.enabled auf dem Overlord fest, um dieses Verhalten zu aktivieren. Weitere Informationen finden Sie im Folgenden:

  • Overlord-Konfiguration
  • Supervisor-Spezifikation https://github.com/apache/druid/pull/13144

<a name="25-ingestion-kafka-consumer-improvement" href="#25-ingestion-kafka-consumer-improvement">#</a> Kafka Verbraucherverbesserung

Sie können jetzt den benutzerdefinierten Deserialisierer des Kafka Consumer nach seiner Instanziierung konfigurieren. https://github.com/apache/druid/pull/13097

<a name="25-ingestion-kafka-supervisor-logging" href="#25-ingestion-kafka-supervisor-logging">#</a> Kafka-Supervisor-Protokollierung

Kafka-Supervisor-Protokolle sind jetzt weniger laut. Die Supervisoren protokollieren Ereignisse jetzt auf der DEBUG-Ebene statt auf der INFO-Ebene. https://github.com/apache/druid/pull/13392

<a name="25-ingestion-fixed-overlord-leader-election" href="#25-ingestion-fixed-overlord-leader-election">#</a> Die Wahl des Overlord-Anführers wurde korrigiert

Es wurde ein Problem behoben, bei dem die Wahl des Overlord-Anführers aufgrund von Problemen bei der Wiedererlangung des Schlosses fehlschlug. Der Druide scheitert nun an diesen Aufgaben und löscht alle Sperren, damit die Wahl des Overlord-Anführers nicht blockiert wird. https://github.com/apache/druid/pull/13172

<a name="25-ingestion-support-for-inline-protobuf-descriptor" href="#25-ingestion-support-for-inline-protobuf-descriptor">#</a> Unterstützung für Inline-Protobuf-Deskriptor

Ein neuer inline-Typ protoBytesDecoder wurde hinzugefügt, der es einem Benutzer ermöglicht, den Inhalt einer Protobuf-Deskriptordatei, codiert als Base64-Zeichenfolge, inline zu übergeben. https://github.com/apache/druid/pull/13192

<a name="25-ingestion-duplicate-notices" href="#25-ingestion-duplicate-notices">#</a> Doppelte Benachrichtigungen

Bei der Streaming-Aufnahme werden Benachrichtigungen, die mit denen übereinstimmen, die sich bereits in der Warteschlange befinden, nicht in die Warteschlange gestellt. Dies wird dazu beitragen, die Größe der Benachrichtigungswarteschlange zu reduzieren. https://github.com/apache/druid/pull/13334

<a name="25-ingestion-sampling-from-stream-input-now-respects-the-configured-timeout" href="#25-ingestion-sampling-from-stream-input-now-respects-the-configured-timeout">#</a> Beim Sampling vom Stream-Eingang wird jetzt das konfigurierte Timeout berücksichtigt

Es wurde ein Problem behoben, bei dem beim Sampling aus einer Stream-Eingabe wie Kafka oder Kinesis das konfigurierte Timeout nicht eingehalten wurde, wenn im Stream keine Datensätze verfügbar waren. Sie können jetzt die maximale Zeitspanne festlegen, in der der Eintragsiterator Ergebnisse zurückgibt. https://github.com/apache/druid/pull/13296

<a name="25-ingestion-streaming-tasks-resume-on-overlord-switch" href="#25-ingestion-streaming-tasks-resume-on-overlord-switch">#</a> Streaming-Aufgaben werden auf dem Overlord-Switch fortgesetzt

Es wurde ein Problem behoben, bei dem Streaming-Aufnahmeaufgaben weiter ausgeführt wurden, bis ihre Dauer abgelaufen war, nachdem der Overlord-Anführer eine Pause für die Aufgaben angeordnet hatte. Wenn nun der Overlord-Wechsel direkt nach der Pause für die Aufgabe erfolgt, bleibt die Aufgabe auch nach der Wiederwahl des Overlords in einem pausierten Zustand. https://github.com/apache/druid/pull/13223

<a name="25-ingestion-fixed-parquet-list-conversion" href="#25-ingestion-fixed-parquet-list-conversion">#</a> Parquet-Listenkonvertierung behoben

Es wurde ein Problem bei der Parquet-Listenkonvertierung behoben, bei dem Listen komplexer Objekte unerwartet in ein zusätzliches Objekt eingeschlossen werden konnten und als [{"element":<actual_list_element>},{"element":<another_one>}...] anstelle der direkten Liste angezeigt wurden. Dadurch wird das Verhalten des Parquet-Readers für Listen strukturierter Objekte geändert, um mit anderen Konvertierungen logischer Parquet-Listen konsistent zu sein. Die Daten werden jetzt direkt abgerufen und entsprechen besser der erwarteten Struktur. https://github.com/apache/druid/pull/13294

<a name="25-ingestion-introduced-a-tree-type-to-flattenspec" href="#25-ingestion-introduced-a-tree-type-to-flattenspec">#</a> Ein Baumtyp wurde in flattenSpec eingeführt

Einführung eines tree-Typs für flattenSpec. Für den Fall, dass eine einfache hierarchische Suche erforderlich ist, ermöglicht der Typ tree eine schnellere Analyse von JSON als die Analysetypen jq und path. https://github.com/apache/druid/pull/12177

<a name="25-operations" href="#25-operations">#</a> Operationen

<a name="25-operations-compaction" href="#25-operations-compaction">#</a> Komprimierung

Das Komprimierungsverhalten wurde geändert, um die benötigte Zeit und den benötigten Speicherplatz zu verbessern:

  • Wenn Segmente abgerufen werden müssen, laden Sie sie einzeln herunter und löschen Sie sie, wenn Druid damit fertig ist. Dies nimmt immer noch Zeit in Anspruch, minimiert jedoch den erforderlichen Speicherplatz.
  • Rufen Sie keine Segmente für die Hauptkomprimierungsaufgabe ab, wenn sie nicht benötigt werden. Wenn der Benutzer ein vollständiges granularitySpec, dimensionsSpec und metricsSpec bereitstellt, überspringt Druid das Abrufen von Segmenten. Weitere Informationen finden Sie in der Dokumentation zu Komprimierung und Automatische Komprimierung. https://github.com/apache/druid/pull/13280

<a name="25-operations-idle-configs-for-the-supervisor" href="#25-operations-idle-configs-for-the-supervisor">#</a> Leerlaufkonfigurationen für den Supervisor

Sie können den Supervisor jetzt in den Leerlauf versetzen, was in Fällen nützlich ist, in denen Slots frei werden, damit die automatische Skalierung effektiver sein kann. Um das Leerlaufverhalten zu konfigurieren, verwenden Sie die folgenden Eigenschaften: | Eigentum | Beschreibung | Standard | | - | - | -| |druid.supervisor.idleConfig.enabled| (Clusterweit) Bei true kann der Supervisor inaktiv werden, wenn für einige Zeit keine Daten im Eingabestream/Thema vorhanden sind.|false| |druid.supervisor.idleConfig.inactiveAfterMillis| (Clusterweit) Supervisor wird als inaktiv markiert, wenn alle vorhandenen Daten aus dem Eingabethema gelesen wurden und inactiveAfterMillis Millisekunden lang keine neuen Daten veröffentlicht wurden.|600_000| | inactiveAfterMillis | (Einzelner Supervisor) Der Supervisor wird als inaktiv markiert, wenn alle vorhandenen Daten aus dem Eingabethema gelesen wurden und inactiveAfterMillis Millisekunden lang keine neuen Daten veröffentlicht wurden. | nein (Standard == 600_000) | https://github.com/apache/druid/pull/13311

<a name="25-operations-improved-supervisor-termination" href="#25-operations-improved-supervisor-termination">#</a> Verbesserte Supervisor-Beendigung

Probleme mit verzögerter Supervisor-Beendigung während bestimmter Übergangszustände behoben. https://github.com/apache/druid/pull/13072

<a name="25-operations-backoff-for-httppostemitter" href="#25-operations-backoff-for-httppostemitter">#</a> Backoff für HttpPostEmitter

Die Option HttpPostEmitter verfügt jetzt über einen Backoff. Das bedeutet, dass es weniger Rauschen in den Protokollen und eine geringere CPU-Auslastung geben sollte, wenn Sie diese Option für die Protokollierung verwenden. https://github.com/apache/druid/pull/12102

<a name="25-operations-dumpsegment-tool-for-nested-columns" href="#25-operations-dumpsegment-tool-for-nested-columns">#</a> DumpSegment-Tool für verschachtelte Spalten

Das DumpSegment-Tool kann jetzt mit der Option --dump nested für verschachtelte Spalten verwendet werden. Weitere Informationen finden Sie unter Dump-Segment-Tool. https://github.com/apache/druid/pull/13356

<a name="25-operations-segment-loading-and-balancing" href="#25-operations-segment-loading-and-balancing">#</a> Segmentladen und -ausgleich

<a name="25-operations-batch-allocation" href="#25-operations-batch-allocation">#</a> Stapelweise Segmentzuteilung

Die Segmentzuweisung auf dem Overlord kann einige Zeit in Anspruch nehmen, was zu Verzögerungen bei der Aufnahme führen kann, während eine Aufgabe auf die Zuweisung von Segmenten wartet. Die stapelweise Segmentzuweisung kann zur Verbesserung der Leistung beitragen. Es gibt zwei neue Eigenschaften, die sich darauf auswirken, wie Druid die Segmentzuweisung durchführt: | Eigentum | Beschreibung | Standard | | - | - | - | |druid.indexer.tasklock.batchSegmentAllocation| Wenn auf „true“ gesetzt, führt Druid Segmentzuweisungsaktionen in Stapeln aus, um den Durchsatz zu verbessern und den durchschnittlichen task/action/run/time zu reduzieren. Weitere Informationen finden Sie unter Batchverarbeitung von segmentAllocate-Aktionen.|false| |druid.indexer.tasklock.batchAllocationWaitTime|Anzahl der Millisekunden, nachdem Druid einem Stapel die erste Segmentzuweisungsaktion hinzugefügt hat, bis der Stapel ausgeführt wird. Ermöglicht dem Batch, weitere Anforderungen hinzuzufügen und die durchschnittliche Laufzeit der Segmentzuweisung zu verbessern. Diese Konfiguration wird nur wirksam, wenn batchSegmentAllocation aktiviert ist.|500| Zusätzlich zu diesen Eigenschaften gibt es neue Metriken zur Verfolgung der Stapelsegmentzuordnung. Weitere Informationen finden Sie unter Neue Metriken für die Segmentzuordnung. Weitere Informationen finden Sie hier:

  • Overlord-Operationen
  • Aufgabenaktionen und Stapelverarbeitung segmentAllocate-Aktionen https://github.com/apache/druid/pull/13369 https://github.com/apache/druid/pull/13503

<a name="25-operations-segment-loading-and-balancing-cachingcost-balancer-strategy" href="#25-operations-segment-loading-and-balancing-cachingcost-balancer-strategy">#</a> Verbesserte CachingCost-Balancer-Strategie

Die Balancer-Strategie cachingCost verhält sich jetzt ähnlicher wie die Kostenstrategie. Bei der Berechnung der Kosten für die Verschiebung eines Segments auf einen Server werden die folgenden Berechnungen durchgeführt: – Subtrahieren Sie die Eigenkosten eines Segments, wenn es vom Zielserver bedient wird

  • Subtrahieren Sie die Kosten der Segmente, die zum Löschen markiert sind https://github.com/apache/druid/pull/13321

<a name="25-operations-segment-loading-and-balancing-segment-assignment" href="#25-operations-segment-loading-and-balancing-segment-assignment">#</a> Schnellere Segmentzuweisung

Sie können jetzt eine Round-Robin-Segmentstrategie verwenden, um die anfänglichen Segmentzuweisungen zu beschleunigen. Setzen Sie useRoundRobinSegmentAssigment in der dynamischen Konfiguration des Koordinators auf true, um diese Funktion zu aktivieren. https://github.com/apache/druid/pull/13367

<a name="25-operations-segment-batch-sampling" href="#25-operations-segment-batch-sampling">#</a> Standardmäßig auf Batch-Sampling für Ausgleichssegmente

Die Batch-Stichprobenentnahme ist jetzt die Standardmethode für die Stichprobenentnahme von Segmenten während des Ausgleichs, da sie bei einer großen Anzahl verwendeter Segmente im Cluster eine deutlich bessere Leistung als die Alternative erbringt. Im Rahmen dieser Änderung gelten die folgenden Elemente als veraltet und werden in künftigen Versionen entfernt:

  • Koordinator dynamische Konfiguration useBatchedSegmentSampler
  • Dynamische Koordinatorkonfiguration percentOfSegmentsToConsiderPerMove
  • alte, nicht stapelweise Methode zur Stichprobenentnahme von Segmenten

<a name="25-operations-segment-unused-property" href="#25-operations-segment-unused-property">#</a> Nicht verwendete Eigenschaft entfernen

Die nicht verwendete Koordinatoreigenschaft druid.coordinator.loadqueuepeon.repeatDelay wurde entfernt. Verwenden Sie nur druid.coordinator.loadqueuepeon.http.repeatDelay, um die Wiederholungsverzögerung für die HTTP-basierte Segmentladewarteschlange zu konfigurieren. https://github.com/apache/druid/pull/13391

<a name="25-operations-segment-replication" href="#25-operations-segment-replication">#</a> Vermeiden Sie eine übermäßige Segmentreplikation

Der Prozess der Überprüfung des Serverinventars wurde verbessert, um eine übermäßige Replikation von Segmenten während des Segmentausgleichs zu verhindern. https://github.com/apache/druid/pull/13114

<a name="25-operations-provided-service-special-log4j-overrides-in-containerized-deployments" href="#25-operations-provided-service-special-log4j-overrides-in-containerized-deployments">#</a> Bereitstellung dienstspezifischer Log4j-Überschreibungen in Container-Bereitstellungen

Bietet eine Option zum Überschreiben der Log4j-Konfigurationseinstellungen in den Service-Level-Verzeichnissen, sodass sie mit Druid-Operator-basierten Bereitstellungen funktionieren. https://github.com/apache/druid/pull/13020

<a name="25-operations-various-docker-improvements" href="#25-operations-various-docker-improvements">#</a> Verschiedene Docker-Verbesserungen

  • Docker wurde aktualisiert, sodass es standardmäßig mit JRE 11 ausgeführt werden kann.
  • Docker aktualisiert, um standardmäßig das Bild gcr.io/distroless/java11-debian11 als Basis zu verwenden.
  • Der Buildkit-Cache Docker wurde aktiviert, um das Erstellen zu beschleunigen.
  • bash-static in das Docker-Image heruntergeladen, damit Skripte ausgeführt werden können, die Bash erfordern.
  • Builder-Image von 3.8.4-jdk-11-slim auf 3.8.6-jdk-11-slim verschoben.
  • Busybox von amd64/busybox:1.30.0-glibc auf busybox:1.35.0-glibc umgestellt.
  • Unterstützung für die Erstellung eines arm64-basierten Images hinzugefügt. https://github.com/apache/druid/pull/13059

<a name="25-operations-enabled-cleaner-json-for-various-input-sources-and-formats" href="#25-operations-enabled-cleaner-json-for-various-input-sources-and-formats">#</a> Reiniger JSON für verschiedene Eingabequellen und Formate aktiviert

JsonInclude wurde zu verschiedenen Eigenschaften hinzugefügt, um das Auffüllen von Standardwerten im serialisierten JSON zu vermeiden. https://github.com/apache/druid/pull/13064

<a name="25-operations-improved-direct-memory-check-on-startup" href="#25-operations-improved-direct-memory-check-on-startup">#</a> Verbesserte direkte Speicherprüfung beim Start

Verbesserte direkte Speicherprüfung beim Start durch bessere Unterstützung für Java 9+ in RuntimeInfo und klarere Protokollmeldungen, wenn die Validierung fehlschlägt. https://github.com/apache/druid/pull/13207

<a name="25-operations-improved-the-run-time-of-the-markasunusedovershadowedsegments-duty" href="#25-operations-improved-the-run-time-of-the-markasunusedovershadowedsegments-duty">#</a> Die Laufzeit des MarkAsUnusedOvershadowedSegments-Dutys wurde verbessert

Die Laufzeit des MarkAsUnusedOvershadowedSegments-Diensts wurde verbessert, indem alle überschatteten Segmente durchlaufen und Segmente stapelweise als nicht verwendet markiert wurden. https://github.com/apache/druid/pull/13287

<a name="25-upgrade" href="#25-upgrade">#</a> Upgrade auf 25.0.0

Berücksichtigen Sie beim Upgrade von Druid 24.0.x auf 25.0.0 die folgenden Änderungen und Aktualisierungen. Wenn Sie von einer früheren Version aktualisieren, sehen Sie sich die release notes der relevanten Zwischenversionen an.

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> Standardmäßige HTTP-basierte Segmenterkennung und Aufgabenverwaltung

Die Standardmethode zur Segmenterkennung verwendet jetzt HTTP anstelle von ZooKeeper. Dieses Update ändert die Standardeinstellungen für die folgenden Eigenschaften: | Eigentum | Neuer Standard | Vorheriger Standard | | - | - | - | | druid.serverview.type für Segmentmanagement | http | Charge | | druid.coordinator.loadqueuepeon.type für Segmentmanagement | http | Kurator | | druid.indexer.runner.type für den Overlord | httpRemote | lokal | Um ZooKeeper anstelle von HTTP zu verwenden, ändern Sie die Werte für die Eigenschaften wieder auf die vorherigen Standardwerte. ZooKeeper-basierte Implementierungen für diese Eigenschaften sind veraltet und werden in einer späteren Version entfernt. https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> Finalisierung von HLL- und Quantiles-Sketch-Aggregaten

Die Aggregationsfunktionen für HLL- und Quantilskizzen gaben bei ihrer Fertigstellung Skizzen oder Zahlen zurück, je nachdem, wo sie sich im nativen Abfrageplan befanden. Druid finalisiert Aggregatoren in den folgenden beiden Fällen nicht mehr: – Aggregatoren erscheinen auf der äußeren Ebene einer Abfrage

  • Aggregatoren werden als Eingabe für einen Ausdruck oder einen Post-Aggregator mit finalisierendem Feldzugriff verwendet Durch diese Änderung wird das Verhalten von HLL- und Quantil-Skizzen an Theta-Skizzen angepasst. Um das alte Verhalten wiederherzustellen, können Sie sqlFinalizeOuterSketches=true im Abfragekontext festlegen. https://github.com/apache/druid/pull/13247

<a name="25-upgrade-kill-tasks-mark-unused" href="#25-upgrade-kill-tasks-mark-unused">#</a> Kill-Aufgaben markieren Segmente nur dann als nicht verwendet, wenn dies angegeben ist

Wenn Sie eine Kill-Aufgabe ausführen, markiert Druid die zugrunde liegenden Segmente nur dann als nicht verwendet, wenn dies ausdrücklich angegeben wird. Weitere Informationen finden Sie in der API-Referenz. https://github.com/apache/druid/pull/13104

<a name='25-upgrade-inkompatible' href='#25-upgrade-inkompatible'>#</a> Inkompatible Änderungen

<a name='25-upgrade-inkompatible-kurator' href='#25-upgrade-inkompatible-kurator'>#</a> Aktualisieren Sie den Kurator auf 5.3.0

Apache Curator wurde auf die neueste Version, 5.3.0, aktualisiert. Diese Version stellt die Unterstützung für ZooKeeper 3.4 ein, aber Druid hat die Unterstützung für 0.22 bereits offiziell eingestellt. In 5.3.0 hat Curator die Unterstützung für Exhibitor entfernt, sodass alle zugehörigen Konfigurationen und Tests entfernt wurden. https://github.com/apache/druid/pull/12939

<a name="25-upgrade-inkompatible-parquet" href="#25-upgrade-inkompatible-parquet">#</a> Konvertierung der Parquet-Liste behoben

Das Verhalten des Parquet-Readers für Listen strukturierter Objekte wurde geändert, um mit anderen Konvertierungen logischer Parquet-Listen konsistent zu sein. Die Daten werden jetzt direkt abgerufen und entsprechen besser der erwarteten Struktur. Weitere Einzelheiten finden Sie unter Konvertierung der Parkettliste. https://github.com/apache/druid/pull/13294
