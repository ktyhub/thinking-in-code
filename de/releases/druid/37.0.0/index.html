Druide Druide-37.0.0

Apache Druid 37.0.0 enthält über 255 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 29 Mitwirkenden.

Weitere Details, einschließlich Fehlerbehebungen, finden Sie im vollständigen Änderungssatz.

Lesen Sie die Upgrade-Hinweise und inkompatible Änderungen, bevor Sie ein Upgrade auf Druid 37.0.0 durchführen. Wenn Sie ein Upgrade über mehrere Versionen durchführen, sehen Sie sich die Seite [Upgrade-Hinweise] (upgrade-notes.md) an, auf der Upgrade-Hinweise für die neuesten Druid-Versionen aufgeführt sind.

Wichtige Funktionen, Änderungen und veraltete Funktionen

Dieser Abschnitt enthält wichtige Informationen zu neuen und bestehenden Funktionen.

Hadoop-basierte Aufnahme

Die Unterstützung für die Hadoop-basierte Aufnahme wurde entfernt. Die Funktion wurde in Druid 34 veraltet.

Verwenden Sie eine der anderen von Druid unterstützten Aufnahmemethoden, z. B. die SQL-basierte Aufnahme oder die MiddleManager-lose Aufnahme mit Kubernetes.

#19109

Sperrliste abfragen

Sie können jetzt den Broker API (/druid/coordinator/v1/config/broker) verwenden, um eine Abfrageblockliste zu erstellen, um Abfragen dynamisch nach Datenquelle, Abfragetyp oder Abfragekontext zu blockieren. Die Sperrliste wird wirksam, ohne dass Druid neu gestartet werden muss. Blockregeln verwenden die AND-Logik, was bedeutet, dass alle Kriterien übereinstimmen müssen.

Das folgende Beispiel blockiert alle GroupBy-Abfragen für die Datenquelle wikipedia mit einem Abfragekontextparameter von priority gleich 0:

POST /druid/coordinator/v1/config/broker
  {
    "queryBlocklist": [
      {
        "ruleName": "block-wikipedia-groupbys",
        "dataSources": ["wikipedia"],
        "queryTypes": ["groupBy"],
        "contextMatches": {"priority": "0"}
      }
    ]
  }

#19011

Kleinere Komprimierung für Overlord-basierte Komprimierung (experimentell)

Sie können jetzt eine geringfügige Komprimierung konfigurieren, um nur neu aufgenommene Segmente zu komprimieren und gleichzeitig vorhandene komprimierte Segmente zu aktualisieren. Wenn Druid Segmente aktualisiert, aktualisiert es die Metadaten, anstatt Ressourcen zu verwenden, um sie erneut zu komprimieren. Sie können die native Komprimierungs-Engine oder die MSQ-Task-Engine verwenden.

Verwenden Sie die Komprimierungsrichtlinie mostFragmentedFirst und legen Sie entweder einen Prozentsatz des zeilenbasierten oder bytebasierten Schwellenwerts für die geringfügige Komprimierung fest.

#19059 #19205 #19016

Kaskadierende Neuindizierung (experimentell)

Mithilfe der kaskadierenden Neuindizierung können Sie jetzt altersbasierte Regeln definieren, um basierend auf dem Alter Ihrer Daten automatisch unterschiedliche Komprimierungskonfigurationen anzuwenden. Während die standardmäßige automatische Komprimierung eine einzelne flache Konfiguration auf die gesamte Datenquelle anwendet, können Sie durch die kaskadierende Neuindizierung Ihre Komprimierungseinstellungen an die Eigenschaften Ihrer Daten anpassen.

Beispielsweise können Sie aktuelle Daten in stündlichen Segmenten speichern und diese nach 90 Tagen automatisch auf tägliche Segmente übertragen, um die Segmentanzahl zu reduzieren. Sie können auch eine altersbasierte Zeilenlöschung vornehmen (z. B. das Löschen von Bot-Traffic aus älteren Daten), die Komprimierungseinstellungen ändern oder mit zunehmendem Alter der Daten zu einem Rollup mit gröberer Abfragegranularität wechseln. Regeln werden inline in der Supervisor-Spezifikation definiert.

Sie müssen Komprimierungs-Supervisoren mit der MSQ-Task-Engine verwenden, um die kaskadierende Neuindizierung zu verwenden.

#18939 #19213 #19106 #19078

Multi-Supervisor-Aufnahme

Die Multi-Supervisor-Aufnahme ist jetzt allgemein verfügbar. Sie können mehrere Stream-Supervisoren ausführen, die in dieselbe Datenquelle aufnehmen.

#18983

Schreibgeschützter Autorisierer

Druid wurde ein ReadOnly-Genehmiger hinzugefügt. Dies ist der erste globale Autorisierer für Druid. Der Autorisierer erzwingt eine globale Beschränkung für alle Nicht-READ-Vorgänge und verweigert diese unabhängig von den individuellen Benutzerberechtigungen. Mit dieser Funktion können Sie sicherstellen, dass alle Benutzer eines bestimmten Autorisierers nur auf den Lesezugriff zugreifen können.

Es gibt eine bekannte Einschränkung, bei der einige Endpunkte derzeit Schreibzugriff benötigen, obwohl sie schreibgeschützt sind, wie z. B. GET /druid/indexer/v1/supervisor. Diese Vorgänge werden fehlschlagen.

#19243

Thrift-Eingabeformat

Als Teil der Thrift-Contributor-Erweiterung unterstützt Druid jetzt Thrift-codierte Daten für die Kafka- und Kinesis-Streaming-Aufnahme mit InputFormat. Zuvor unterstützte Druid dies durch Parser, die in Druid 37 entfernt wurden.

#19111

Um diese Funktion nutzen zu können, müssen Sie druid-thrift-extensions zu Ihrer Erweiterungsladeliste hinzufügen.

Inkrementeller Cache

Der inkrementelle Segmentmetadaten-Cache (useIncrementalCache) ist jetzt allgemein verfügbar und standardmäßig auf ifSynced eingestellt. Druid blockiert Lesevorgänge aus dem Cache, bis er mindestens einmal mit dem Metadatenspeicher synchronisiert wurde, nachdem er zum Anführer geworden ist.

#19252

Kubernetes-basiertes Aufgabenmanagement

Diese Erweiterung ist jetzt allgemein verfügbar.

#19128

Dynamischer Standardabfragekontext

Sie können dem Broker jetzt standardmäßige Abfragekontextparameter als dynamische Konfiguration hinzufügen. Dadurch können Sie in Ihren Laufzeiteigenschaften festgelegte statische Standardwerte überschreiben, ohne Ihre Bereitstellung neu starten oder mehrere Abfragen einzeln aktualisieren zu müssen. Druid wendet Abfragekontextparameter basierend auf der folgenden Priorität an:

  1. Der in der Abfrage enthaltene Abfragekontext
  2. Der Abfragekontext wird als dynamische Konfiguration auf dem Broker festgelegt
  3. Die in den Laufzeiteigenschaften festgelegten Abfragekontextparameter
  4. Die im Lieferumfang von Druid enthaltenen Standardeinstellungen

Beachten Sie, dass dies wie bei anderen dynamischen Broker-Konfigurationen die beste Lösung ist. In bestimmten Fällen werden die Einstellungen möglicherweise nicht angewendet Fälle, beispielsweise wenn ein Broker kürzlich gestartet wurde und die Konfiguration noch nicht erhalten hat, oder wenn der Der Makler kann den Koordinator nicht kontaktieren. Wenn ein Abfragekontextparameter für alle Ihre Abfragen von entscheidender Bedeutung ist, legen Sie ihn in den Laufzeiteigenschaften fest.

#19144

sys.queries-Tabelle (experimentell)

Die neue Systemabfragetabelle bietet Informationen zu aktuell ausgeführten und kürzlich abgeschlossenen Abfragen, die die Dart-Engine verwenden. Diese Tabelle ist standardmäßig deaktiviert. Um die Tabelle zu aktivieren, legen Sie Folgendes fest:

druid.sql.planner.enableSysQueriesTable = true

Im Rahmen dieser Änderung unterstützt der /druid/v2/sql/queries API jetzt einen includeComplete-Parameter, der kürzlich abgeschlossene Abfragen anzeigt.

#18923

Automatische Verdichtung mit Verdichtungsüberwachern

Die automatische Komprimierung mithilfe von Komprimierungs-Supervisoren wurde verbessert, ist jetzt allgemein verfügbar und die empfohlene Standardeinstellung. Automatischen Komprimierungsaufgaben wird jetzt auto anstelle von coordinator-issued vorangestellt.

Als Teil der Verbesserung werden Verdichtungszustände nun an einem zentralen Ort gespeichert, einer neuen indexingStates-Tabelle. Einzelne Segmente müssen lediglich einen eindeutigen Verweis (indexing_state_fingerprint) auf ihren vollständigen Komprimierungszustand speichern.

Da viele Segmente in einer einzelnen Datenquelle denselben zugrunde liegenden Komprimierungsstatus aufweisen, werden die Anforderungen an die Metadatenspeicherung für die automatische Komprimierung erheblich reduziert.

Aus Gründen der Abwärtskompatibilität behält Druid weiterhin den detaillierten Komprimierungsstatus in jedem Segment bei. Diese Funktionalität wird in einer zukünftigen Version entfernt. Sie können die Speicherung des detaillierten Komprimierungsstatus stoppen, indem Sie storeCompactionStatePerSegment in der Cluster-Komprimierungskonfiguration auf false setzen. Wenn Sie es deaktivieren und ein Downgrade durchführen müssen, muss Druid alle Segmente erneut komprimieren, die seit der Änderung der Konfiguration komprimiert wurden.

Diese Änderung hat Auswirkungen auf das Upgrade der Metadatenspeicherung und des Metadaten-Cachings. Weitere Informationen finden Sie im Upgrade-Hinweis zum Metadatenspeicher für die automatische Komprimierung mit Komprimierungs-Supervisoren.

#19113 #18844 #19252

Auswahl der Brokerstufe für Echtzeitserver

Den Brokern wurden druid.broker.realtime.select.tier und druid.broker.realtime.balancer.type hinzugefügt, um optional die Stufenauswahl- und Balancer-Strategien des Brokers für Echtzeitserver zu überschreiben. Wenn diese Eigenschaften nicht festgelegt sind (Standardeinstellung), verwenden Echtzeitserver weiterhin die vorhandenen Konfigurationen druid.broker.select und druid.broker.balancer, die sowohl für historische als auch für Echtzeitserver gelten.

#19062

Manuelles Broker-Routing in der Webkonsole

Sie können jetzt konfigurieren, welchen Broker der Router für von der Webkonsole ausgegebene Abfragen verwendet. Dies empfiehlt sich möglicherweise, wenn es Broker gibt, die keinen Einblick in bestimmte Datenebenen haben, und Sie wissen, dass Sie Daten abfragen, die nur auf einer bestimmten Ebene verfügbar sind.

Um einen Broker anzugeben, fügen Sie die folgende Konfiguration zu web-console/console-config.js hinzu:

consoleBrokerService: 'druid/BROKER_NAME'

#19069

Konsulverlängerung

Mit der Mitwirkendenerweiterung druid-consul-extensions können Druid-Cluster Consul für die Diensterkennung und verwenden Wahl des Koordinators/Overlord-Anführers anstelle von ZooKeeper. Die Erweiterung unterstützt ACLs, TLS/mTLS und Metriken.

Bevor Sie zu Consul wechseln, müssen Sie die Einstellungen vornehmen Clusterweit druid.serverview.type=http und druid.indexer.runner.type=httpRemote.

Einnahme

Zeichenfolgenspalten abschneiden

Verwenden Sie die StringColumnFormatSpec-Konfiguration, um die maximale Länge für String-Dimensionsspalten festzulegen, die Sie aufnehmen:

  • Für eine bestimmte Abmessung: dimensionSchema.columnFormatSpec.maxStringLength
  • Für einen bestimmten Auftrag: indexSpec.columnFormatSpec.maxStringLength
  • Clusterweit: druid.indexing.formats.maxStringLength

Druid schneidet jede Zeichenfolge ab, die länger als die angegebene Länge ist. Standardmäßig werden Zeichenfolgenwerte nicht abgeschnitten.

Streaming-Aufnahme

Die Art und Weise, wie Aufgaben für die automatische Skalierung gestartet werden, wurde geändert

Das Verhalten von taskCountMin und taskCountStart wurde für die automatische Skalierung geändert. Druid berechnet nun die anfängliche Anzahl der zu startenden Aufgaben, indem es die Konfigurationen in der folgenden Reihenfolge überprüft: taskCountStart (optional), dann taskCount (in ioConfig), dann taskCountMin.

#19091

Verbesserte Abfrageisolation

Parameter serverPriorityToReplicas zu den Streaming-Supervisor-Spezifikationen hinzugefügt (Kafka, Kinesis und Rabbit). Dies ermöglicht es Betreibern, Aufgabenreplikate für Echtzeit-Indizierungsaufgaben auf verschiedene Serverprioritäten zu verteilen. Ähnlich wie beim historischen Tiering ermöglicht dies die Abfrageisolation für gemischte Arbeitslastszenarien auf den Peons, sodass einige Aufgabenreplikate Abfragen mit bestimmten Prioritäten verarbeiten können.

Abfragen

GroupBy-Abfragekonfiguration

Es wurde eine neue GroupBy-Abfragekonfigurationseigenschaft druid.query.groupBy.maxSpillFileCount hinzugefügt, um die maximale Anzahl der pro Abfrage erstellten Überlaufdateien zu begrenzen. Wenn der Grenzwert überschritten wird, schlägt die Abfrage mit einer eindeutigen Fehlermeldung fehl, anstatt dass historische Knoten beim Zusammenführen von Überlaufdateien nicht mehr über genügend Speicher verfügen. Das Limit kann auch pro Abfrage mit dem Abfragekontextparameter maxSpillFileCount übersteuert werden.

#19141

Verbesserte Handhabung verschachtelter Aggregate

Druid kann jetzt zwei Aggregate mit einer Projektion dazwischen zusammenführen. Beispielsweise die folgende Abfrage:

SELECT
  hr,
  UPPER(t1.x) x,
  SUM(t1.cnt) cnt,
  MIN(t1.mn) mn,
  MAX(t1.mx) mx
FROM (
  SELECT
    floor(__time to hour) hr,
    dim2 x,
    COUNT(*) cnt,
    MIN(m1 * 5) mn,
    MAX(m1 + m2) mx
  FROM druid.foo
  WHERE dim2 IN ('abc', 'def', 'a', 'b', '')
  GROUP BY 1, 2
) t1
WHERE t1.x IN ('abc', 'foo', 'bar', 'a', '')
GROUP BY 1, 2

kann wie folgt vereinfacht werden:

SELECT
  FLOOR(__time TO hour) hr,
  UPPER(dim2) x,
  COUNT(*) cnt,
  MIN(m1 * 5) mn,
  MAX(m1 + m2) mx
FROM druid.foo
WHERE dim2 IN ('abc', 'a', '')
GROUP BY 1, 2

Clusterverwaltung

Neue Strategien zur Auswahl der Broker-Stufe

Betreiber können jetzt zwei neue Broker TierSelectorStrategy-Implementierungen konfigurieren:

  • strict – Wählt nur Server aus, deren Prioritäten mit der konfigurierten Liste übereinstimmen. Beispielkonfiguration: druid.broker.select.tier=strict und druid.broker.select.tier.strict.priorities=[1]. – pooled – Bündelt Server über die konfigurierten Prioritäten hinweg und wählt unter ihnen aus, sodass Abfragen für eine verbesserte Verfügbarkeit mehrere Prioritätsstufen verwenden können. Beispielkonfiguration: druid.broker.select.tier=pooled und druid.broker.select.tier.pooled.priorities=[2,1].

Sie können druid.broker.realtime.select.tier auch verwenden, um diese Strategien für Echtzeitserver zu konfigurieren.

Datenverwaltung

Timeout-Konfiguration pro Segment

Sie können jetzt mithilfe einer dynamischen Konfiguration ein Timeout für die Segmente in einer bestimmten Datenquelle festlegen:

POST /druid/coordinator/v1/config/broker
  {
    "perSegmentTimeoutConfig": {
      "my_large_datasource": { "perSegmentTimeoutMs": 5000, "monitorOnly": false },
      "my_new_datasource": { "perSegmentTimeoutMs": 3000, "monitorOnly": true }
    }
  }

Dies ist nützlich, wenn verschiedene Datenquellen unterschiedliche Leistungsmerkmale aufweisen – beispielsweise um längere Zeitüberschreitungen für größere Datensätze zu ermöglichen.

#19221

Dauerhafter Lagerreiniger

Der dauerhafte Speicherreiniger unterstützt jetzt die konfigurierbare zeitbasierte Aufbewahrung für MSQ-Abfrageergebnisse. Bisher wurden Abfrageergebnisse für alle bekannten Aufgaben beibehalten, was bei abgeschlossenen Aufgaben unzuverlässig war. Mit dieser Änderung werden Abfrageergebnisse für einen konfigurierbaren Zeitraum basierend auf dem Zeitpunkt der Aufgabenerstellung aufbewahrt.

Die neue Konfigurationseigenschaft druid.msq.intermediate.storage.cleaner.durationToRetain steuert den Aufbewahrungszeitraum für Abfrageergebnisse. Die Standardaufbewahrungsdauer beträgt 6 Stunden.

  • tier/storage/capacity-Metrik für den Koordinator hinzugefügt. Diese Metrik spiegelt garantiert die Gesamtgröße von StorageLocation wider, die für alle historischen Daten in einer Ebene konfiguriert ist #18962 – Der MSQ-Task-Engine ChannelCounters wurden neue Metriken für die virtuelle Speicherstruktur hinzugefügt: loadBytes, loadTime, loadWait und loadFiles #18971
  • Die Metriken storage/virtual/hit/bytes, storage/virtual/hold/count und storage/virtual/hold/bytes wurden zu StorageMonitor hinzugefügt #18895 #19217 – supervisorId-Dimension für Streaming-Aufgaben zu TaskCountStatsMonitor hinzugefügt #18920 – StorageMonitor so geändert, dass es immer eingeschaltet ist #19048 – Die Metriken für Autoscaling wurden verbessert, sodass sie alle die gleichen Metriken ausgeben: supervisorId, dataSource und stream #19097

Erweiterungen

Kubernetes

Ein neuer WebClientOptions-Passthrough für den Vert.x HTTP client im kubernetes-overlord-extensions hinzugefügt. Operatoren können jetzt jede Eigenschaft des zugrunde liegenden Vert.x-WebClientOptions-Objekts mithilfe von Druid-Laufzeiteigenschaften konfigurieren. Zu den Optionen, die Sie konfigurieren können, gehören die Größe des Verbindungspools, Keep-Alive-Zeitüberschreitungen und Leerlauf-Zeitüberschreitungen. Dies ist besonders nützlich für Umgebungen mit zwischengeschalteten Load Balancern, die inaktive Verbindungen schließen. Die meisten Druid-Bereitstellungen benötigen diese Konfiguration nicht.

#19071

gRPC

Die gRPC-Abfrageerweiterung bricht jetzt In-Flight-Abfragen ab, wenn clients abbrechen oder die Verbindung trennen.

#19005

Eisberg

GCS-Lager

Die Iceberg-Eingabequelle unterstützt jetzt GCS-Warehouses. Um diese Funktion nutzen zu können, müssen Sie zusätzlich zur Iceberg-Erweiterung die Erweiterung druid-google-extensions laden. #19137

Filter

Sie können jetzt Restfilter für Nicht-Partitionsspalten konfigurieren, wenn Sie die Iceberg-Eingabequelle verwenden. Stellen Sie residualFilterMode in der Iceberg-Eingabequelle auf einen der folgenden Werte ein:

– ignore: (Standard) Erfassen Sie die verbleibenden Zeilen mit einem Warnprotokoll, sofern sie nicht durch transformSpec gefiltert werden. – fail: Der Aufnahmejob schlägt fehl, wenn restliche Filter erkannt werden. Damit stellen Sie sicher, dass Filter nur auf Partitionsspalten abzielen.

#18953

HDFS-Speicher

Unterstützung für lz4-Komprimierung hinzugefügt. Im Rahmen dieser Änderung sind nun die folgenden Metriken verfügbar:

  • hdfs/pull/size
  • hdfs/pull/duration
  • hdfs/push/size
  • hdfs/push/duration

#18982

Upgrade-Hinweise und inkompatible Änderungen

Upgrade-Hinweise

Hadoop-basierte Aufnahme

Die Unterstützung für die Hadoop-basierte Aufnahme wurde entfernt. Die Funktion wurde in Druid 34 veraltet.

Verwenden Sie eine der anderen von Druid unterstützten Aufnahmemethoden, z. B. die SQL-basierte Aufnahme oder die MiddleManager-lose Aufnahme mit Kubernetes.

#19109

AWS SDK v2

Druid verwendet jetzt die AWS SDK-Version 2.40.0, da v1 von SDK das Ende ihrer Lebensdauer erreicht hat.

#18891

Segment-Metadaten-Cache standardmäßig aktiviert

Ab Druid 37 ist der Segmentmetadaten-Cache standardmäßig aktiviert. Diese Funktion ermöglicht es dem Broker, vom Koordinator abgefragte Segmentmetadaten zwischenzuspeichern, anstatt Metadaten für jede Abfrage in der Tabelle sys.segments abrufen zu müssen. Dies verbessert die Leistung, erhöht jedoch die Speichernutzung auf Brokern.

Die druid.sql.planner.metadataSegmentCacheEnable-Konfiguration steuert diese Funktion.

#19075

Parser-Änderungen

Streaming-Aufnahme parser

Die Unterstützung für das veraltete parser wurde für Streaming-Ingest-Aufgaben wie Kafka und Kinesis entfernt. Operatoren müssen nun inputSource/inputFormat im ioConfig der Supervisor-Spezifikation angeben, und der dataSchema darf keinen Parser angeben. Tun Sie dies, bevor Sie auf Druid 37 oder höher aktualisieren.

#19173 #19166

ParseSpec und veraltete Parser entfernt

Der Parser für native Batch-Aufgaben und Indexierungsdienste für die Streaming-Aufnahme wurde entfernt. Verwenden Sie nach Möglichkeit stattdessen das Eingabeformat. Beachten Sie, dass JavascriptParseSpec und JSONLowercaseParseSpec keine InputFormat-Entsprechungen haben.

Druid unterstützt benutzerdefinierte Textdatenformate und kann das Regex-Eingabeformat zum Parsen verwenden. Seien Sie jedoch vorsichtig, wenn Sie dies tun Das Parsen von Daten ist weniger effizient als das Schreiben einer nativen Java-Erweiterung InputFormat oder die Verwendung eines externen Stream-Prozessors. Wir freuen uns über Beiträge neuer Eingabeformate.

#19239

Laufende Upgrades von Druid-Versionen vor Version 0.23

Sie können kein fortlaufendes Upgrade von Versionen vor Druid 0.23 durchführen.

#18961

Metadatenspeicher für die automatische Komprimierung mit Komprimierungs-Supervisoren

Die automatische Komprimierung mit Supervisoren erfordert ein inkrementelles Segment-Metadaten-Caching auf dem Overlord und eine neue Metadatenspeichertabelle. Es ist keine Aktion erforderlich, wenn Sie die Standardeinstellungen für die folgenden Konfigurationen verwenden:

  • druid.manager.segments.useIncrementalCache
  • druid.metadata.storage.connector.createTables

Wenn druid.manager.segments.useIncrementalCache auf never gesetzt ist, aktualisieren Sie es auf ifSynced oder always. Weitere Informationen zur Konfiguration finden Sie unter Segment-Metadaten-Cache.

Wenn Sie die druid.metadata.storage.connector.createTables-Konfiguration auf false setzen, müssen Sie die Segmenttabelle manuell ändern und die compactionStates-Tabelle erstellen. Die Postgres-DDL wird unten als Leitfaden bereitgestellt:

-- create the indexing states lookup table and associated indices
CREATE TABLE druid_indexingStates (
    created_date VARCHAR(255) NOT NULL,
    datasource VARCHAR(255) NOT NULL,
    fingerprint VARCHAR(255) NOT NULL,
    payload BYTEA NOT NULL,
    used BOOLEAN NOT NULL,
    pending BOOLEAN NOT NULL,
    used_status_last_updated VARCHAR(255) NOT NULL,
    PRIMARY KEY (fingerprint),
  );

  CREATE INDEX idx_druid_compactionStates_used ON druid_compactionStates(used, used_status_last_updated);

-- modify druid_segments table to have a column for storing compaction state fingerprints
ALTER TABLE druid_segments ADD COLUMN indexing_state_fingerprint VARCHAR(255);

Möglicherweise müssen Sie die Syntax an Ihr Tabellenbenennungspräfix und Ihr Metadatenspeicher-Backend anpassen.

#18844

Segmentverriegelung

Segmentsperre und NumberedOverwriteShardSpec sind veraltet und werden in einer zukünftigen Version entfernt. Verwenden Sie stattdessen die Zeitblocksperre. Sie können sicherstellen, dass nur die zeitliche Blocksperre verwendet wird, indem Sie druid.indexer.tasklock.forceTimeChunkLock auf true setzen, was die Standardeinstellung ist.

#19050

Inkompatible Änderungen

defaultProcessingRate-Konfiguration entfernt

Diese Konfiguration ermöglichte den Beginn von Skalierungsaktionen, bevor die ersten Metriken verfügbar wurden.

#19028

Frontcodierungsformat

Druid verwendet jetzt standardmäßig Version 1 des frontcodierten Formats anstelle von Version 0, wenn diese aktiviert ist. Version 1 wurde in Druid 26 eingeführt. Ein Downgrade oder Upgrade von einer Druid-Version vor 26 erfordert möglicherweise eine Neuindizierung, wenn Sie die Frontcodierung mit Version 0 aktiviert haben.
