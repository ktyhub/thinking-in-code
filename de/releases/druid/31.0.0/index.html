<a name="31.0.0-important-features-changes-and-deprecations-projections-experimental" href="#31.0.0-important-features-changes-and-deprecations-projections-experimental">#</a> Projektionen (experimentell)

Druid 31.0.0 bietet experimentelle Unterstützung für eine neue Funktion namens Projektionen. Projektionen sind gruppierte Voraggregate eines Segments, die automatisch zum Zeitpunkt der Abfrage verwendet werden, um die Ausführung für alle Abfragen zu optimieren, die zur Form der Projektion „passen“, indem sowohl die Berechnungs- als auch die E/A-Kosten reduziert werden, indem die Anzahl der zu verarbeitenden Zeilen reduziert wird. Projektionen sind in Segmenten einer Datenquelle enthalten und erhöhen die Segmentgröße. Sie können jedoch Daten, wie z. B. Wertewörterbücher von wörterbuchcodierten Spalten, mit den Spalten des Basissegments teilen.

Projektionen unterstützen derzeit nur die JSON-basierte Aufnahme, sie können jedoch von Abfragen verwendet werden, die die MSQ-Task-Engine oder die neue Dart-Engine verwenden. Zukünftige Entwicklungen werden die Erstellung von Prognosen im Rahmen der SQL-basierten Aufnahme ermöglichen.

Wir haben viele Pläne, diese Funktion in den kommenden Versionen weiter zu verbessern, freuen uns aber, sie verfügbar zu machen, damit Benutzer mit dem Experimentieren beginnen können, da Prognosen die Abfrageleistung erheblich verbessern können.

Weitere Informationen finden Sie unter Projektionen.

<a name="31.0.0-important-features%2C-changes%2C-and-deprecations-low-latency-high-complexity-queries-using-dart-%28experimental%29" href="#31.0.0-important-features%2C-changes%2C-and-deprecations-low-latency-high-complexity-queries-using-dart-%28experimental%29">#</a> Abfragen mit geringer Latenz und hoher Komplexität mit Dart (experimentell)

Distributed Asynchronous Runtime Topology (Dart) ist für die Unterstützung hochkomplexer Abfragen wie große Verknüpfungen, Gruppierungen mit hoher Kardinalität, Unterabfragen und allgemeine Tabellenausdrücke konzipiert, die häufig in Ad-hoc-Data-Warehouse-Workloads vorkommen. Anstatt Data-Warehouse-Engines wie Spark oder Presto zum Ausführen hochkomplexer Abfragen zu verwenden, können Sie Dart verwenden, wodurch der Bedarf an zusätzlicher Infrastruktur verringert wird.

<a name="31.0.0-functional-areas-and-related-changes-querying" href="#31.0.0-functional-areas-and-related-changes-querying">#</a> Abfrage

<a name="31.0.0-functional-areas-and-related-changes-querying-dart" href="#31.0.0-functional-areas-and-related-changes-querying-dart">#</a> Pfeil

Dart ist eine Abfrage-Engine mit Multithread-Workern, die In-Memory-Shuffles durchführt, um einstellbare Parallelität und Infrastrukturkosten für Abfragen mit geringer Latenz und hoher Komplexität bereitzustellen.

Um Dart auszuprobieren, setzen Sie druid.msq.dart.enabled in Ihren allgemeinen Laufzeiteigenschaften auf true. Anschließend können Sie Dart als Abfrage-Engine in der Webkonsole oder über API /druid/v2/sql/dart auswählen, das die gleiche JSON-Nutzlast wie /druid/v2/sql akzeptiert. Dart ist vollständig kompatibel mit aktuellen Druid-Abfrageformen und dem Speicherformat von Druid. Das bedeutet, dass Sie Dart mit Ihren vorhandenen Abfragen und Datenquellen ausprobieren können.

<a name="31.0.0-functional-areas-and-related-changes-querying-projections" href="#31.0.0-functional-areas-and-related-changes-querying-projections">#</a> Projektionen

Als experimentelle Funktion sind Projektionen noch nicht gut dokumentiert, können aber als Teil des dataSchema für die Streaming-Aufnahme und die „klassische“ Batch-Aufnahme definiert werden. Eine Beispielaufnahmespezifikation finden Sie in der Pull-Request-Beschreibung für #17214.

Das Feld groupingColumns in der Spezifikation definiert die Reihenfolge, in der Daten in der Projektion sortiert werden. <a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Upgrade-Hinweise

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array">#</a> Der Array-Aufnahmemodus ist jetzt standardmäßig auf Array eingestellt

Das SQL-basierte Erfassungskontextflag arrayIngestMode ist jetzt standardmäßig array anstelle von mvd. Dies bedeutet, dass SQL-Typen vom Typ VARCHAR ARRAY nicht mehr implizit übersetzt und in VARCHAR-Spalten gespeichert werden, sondern stattdessen als VARCHAR ARRAY gespeichert werden. Durch diese Änderung können andere Array-Typen wie BIGINT ARRAY und DOUBLE ARRAY mit MSQ in ihre jeweiligen Array-Spaltentypen eingefügt werden, anstatt wie im mvd-Modus fehlzuschlagen.

Um weiterhin mehrwertige Zeichenfolgen zu speichern, ändern Sie alle Einfüge-/Ersetzungsabfragen, um die Array-Typen mit dem Operator ARRAY_TO_MV zu umschließen.

Es ist eine Validierung vorhanden, um zu verhindern, dass die Spalten VARCHAR und VARCHAR ARRAY in derselben Tabelle gemischt werden. Daher schlagen alle von dieser Änderung betroffenen Erfassungen fehl und zeigen eine beschreibende Fehlermeldung anstelle eines unerwarteten Verhaltens.

Die Option arrayIngestMode von none wurde entfernt. Es wurde vor der Tabellenvalidierungslogik eingeführt, um Clusterbetreibern die Möglichkeit zu geben, Abfrageautoren zu zwingen, explizit array oder mvd in ihren Abfragekontexten festzulegen, bietet jedoch in Druid 31 nur wenig Nutzen.

Weitere Informationen finden Sie in den folgenden Themen:

  • Mehrwertige Dimensionen aufnehmen für die Aufnahme mehrwertiger Zeichenfolgen.
  • Arrays aufnehmen zum Aufnehmen von Arrays.

#16789

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-task-action-audit-logging" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-task-action-audit-logging">#</a> Die Überwachungsprotokollierung für Aufgabenaktionen wurde entfernt

Die veraltete Protokollierung der Aufgabenaktionsüberwachung wurde entfernt. Diese Änderung umfasst die folgenden Aktualisierungen:

– Der Endpunkt /indexer/v1/task/{taskId}/segments wird nicht mehr unterstützt.

  • Druid schreibt nicht in die Metadatentabelle druid_taskLog und liest auch nicht aus ihr.
  • Druid ignoriert die Eigenschaft druid.indexer.auditlog.enabled.
  • Druid gibt die Metrik task/action/log/time nicht aus.

Diese Änderungen sind abwärtskompatibel mit allen vorhandenen Metadatenspeichererweiterungen.

#16309

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-firehose-and-firehosefactory" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-firehose-and-firehosefactory">#</a> Firehose und FirehoseFactory entfernt

Firehose und FirehoseFactory sowie die verbleibenden Implementierungen wurden entfernt. Apache unterstützt die Druid-Feuerwehrschläuche in der Version 0.17 nicht mehr. Die Unterstützung für die Firehose-Aufnahme wurde in Version 26.0 entfernt.

#16758

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-front-coded-dictionaries" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-front-coded-dictionaries">#</a> Wörterbücher mit Frontcodierung

<!--Führen Sie dies bis 32 fort. Verschieben Sie es dann zu inkompatiblen Änderungen -->

Vorne codierte Wörterbücher reduzieren den Speicherplatz und verbessern die Leistung, indem sie für Zeichenfolgen optimiert werden, bei denen der vordere Teil ähnlich aussieht.

Sobald diese Funktion aktiviert ist, können Sie nicht einfach ein Downgrade auf eine frühere Version durchführen, die diese Funktion nicht unterstützt.

Weitere Informationen finden Sie im Migrationsleitfaden: Frontcodierte Wörterbücher. Wenn Sie diese Funktion bereits nutzen, müssen Sie nichts unternehmen.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-storage-improvement-features" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-storage-improvement-features">#</a> Funktionen zur Speicherverbesserung

Druid 31.0.0 enthält Speicherverbesserungen, die nicht abwärtskompatibel sind. Sobald Sie flexible Segmentsortierung oder Komprimierung für komplexe Spalten aktivieren, können Sie kein Downgrade auf eine Version vor 31.0.0 durchführen. Testen Sie diese Funktionen gründlich, bevor Sie sie in Ihrem Produktionscluster einführen.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Inkompatible Änderungen

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode">#</a> Der Scan-Abfrage-Legacy-Modus wurde entfernt

Der Legacy-Modus der nativen Scan-Abfrage wurde entfernt. Es wurde in Druid 0.11 eingeführt, um die Kompatibilität während eines Upgrades von älteren Druid-Versionen aufrechtzuerhalten, bei denen die Scan-Abfrage Teil einer contrib-Erweiterung war.

#16659

Hartcodierter "legacy":false nach der Entfernung des Legacy-Modus, um Fehler bei fortlaufenden Upgrades oder Downgrades zu verhindern.

#16793

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading">#</a> ZK-basiertes Segmentladen

Das Laden von ZK-basierten Segmenten ist jetzt deaktiviert. ZK servedSegmentsPath wurde in Druid 0.7.1 veraltet. Dieser alte Pfad wurde durch liveSegmentsPath ersetzt.

Segmentbedienende Prozesse wie Peons, Historicals und Indexer erstellen keine ZK loadQueuePath-Einträge mehr. Die Eigenschaften druid.zk.paths.loadQueuePath und druid.zk.paths.servedSegmentsPath werden nicht mehr verwendet.

Wechseln Sie zuerst zum HTTP-basierten Segmentladen und führen Sie dann das Versions-Upgrade durch.
