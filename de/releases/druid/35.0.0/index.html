Druide Druide-35.0.0

Apache Druid 35.0.0 enthält über 229 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 29 Mitwirkenden.

Weitere Details, einschließlich Fehlerbehebungen, finden Sie im vollständigen Änderungssatz.

Lesen Sie die Upgrade-Hinweise und inkompatible Änderungen, bevor Sie ein Upgrade auf Druid 35.0.0 durchführen. Wenn Sie ein Upgrade über mehrere Versionen durchführen, sehen Sie sich die Seite [Upgrade-Hinweise] (upgrade-notes.md) an, auf der Upgrade-Hinweise für die neuesten Druid-Versionen aufgeführt sind.

Druid 35 verwendet Jetty 12. Diese Änderung kann sich auf Ihre Bereitstellung auswirken. Weitere Informationen finden Sie im Upgrade-Hinweis für Jetty 12

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-java-support" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-java-support">#</a> Java-Unterstützung

Druid unterstützt jetzt Java 21. Beachten Sie, dass bei einigen Versionen von Java 21 während des Tests Probleme aufgetreten sind, insbesondere bei Java 21.05-21.07. Vermeiden Sie nach Möglichkeit diese Versionen.

Darüber hinaus wurde die Unterstützung für Java 11 entfernt. Upgrade auf Java 17 oder 21.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29">#</a> Virtueller Speicher (experimentell)

Der virtuelle Speicher-Fabric-Modus ermöglicht es historischen Servern, mehr Segmente zu bedienen, als ihre physische Festplatte aufnehmen kann. Anstatt Segmente zu laden, wenn sie veröffentlicht werden, werden Segmente bei Bedarf bei Abfragen geladen. Alle nicht benötigten Segmente werden von der Festplatte entfernt, aber erneut geladen, wenn für die Verarbeitung einer Abfrage dieses bestimmte Segment erforderlich ist.

Um den virtuellen Speicher zu aktivieren, setzen Sie druid.segmentCache.virtualStorage auf true.

Diese Funktion ist experimentell und weist mehrere Einschränkungen auf. Weitere Informationen finden Sie im Pull-Request:

#18176

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format">#</a> Neues Eingabeformat

Druid unterstützt jetzt ein lines-Eingabeformat. Druid liest jede Zeile aus einer Eingabe als UTF-8-Text und erstellt eine einzelne Spalte mit dem Namen line, die die gesamte Zeile als Zeichenfolge enthält. Verwenden Sie dies, um zeilenorientierte Daten in einfacher Form für die spätere Verarbeitung auszulesen.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine">#</a> Mehrstufige Abfrage-Task-Engine

Die MSQ-Task-Engine ist jetzt eine Kernfunktion von Druid und keine Erweiterung mehr. Es befindet sich seit mehreren Versionen in der Standardladeliste für Erweiterungen.

Entfernen Sie druid-multi-stage-query von druid.extensions.loadList in common.runtimes.properties, bevor Sie ein Upgrade durchführen.

Druid 35.0.0 ignoriert die Erweiterung, wenn sie in der Ladeliste enthalten ist. Zukünftige Versionen von Druid können nicht gestartet werden, da die Erweiterung nicht gefunden werden kann.

#18394

Sie können jetzt Monitore in common.runtime.properties angeben und jeder Monitor wird nur auf den entsprechenden Servertypen geladen. Bisher mussten Sie Monitore in der spezifischen runtime.properties-Datei für den Dienst definieren, für den ein Monitor gedacht ist.

Eine neue Mitwirkende-Erweiterung (druid-exact-count-bitmap) bietet Unterstützung für die genaue Kardinalitätszählung mithilfe von Roaring Bitmap über eine lange Spalte.

<a name="35.0.0-functional-area-and-related-changes-querying" href="#35.0.0-functional-area-and-related-changes-querying">#</a> Abfrage

<a name="35.0.0-functional-area-and-related-changes-querying-segment-timeout" href="#35.0.0-functional-area-and-related-changes-querying-segment-timeout">#</a> Segment-Timeout

Sie können jetzt ein Timeout für die Segmentverarbeitung einer Abfrage konfigurieren.

Um eine Zeitüberschreitung festzulegen, setzen Sie druid.processing.numTimeoutThreads auf allen Datenknoten, auf denen diese Funktion aktiviert werden soll, auf eine niedrige Zahl, z. B. 3.

Fügen Sie dann den Abfragekontextparameter perSegmentTimeout in Ihre Abfrage ein und legen Sie ihn auf einen Wert in Millisekunden fest.

<a name="35.0.0-functional-area-and-related-changes-extensions-http-client" href="#35.0.0-functional-area-and-related-changes-extensions-http-client">#</a> HTTP client

Sie können jetzt konfigurieren, welche HTTP-client-Bibliothek der Fabric8 KubernetesClient unter der Haube verwendet, um mit den k8s-Serveraufgaben zu kommunizieren, auf denen er ausgeführt wird. Die Standardeinstellung bleibt die gleiche client und Konfiguration, die Druid 34 verwendet. Die jetzt verfügbaren zusätzlichen Optionen sind okhttp und ein natives JDK HttpClient. Der Standard-client und die Standardkonfiguration sollten für die meisten Anwendungsfälle ausreichen.

Legen Sie die druid.indexer.runner.k8sAndWorker.http.httpClientType-Konfiguration auf vertx (Standard), okhttp oder jdk fest.

#18540

#18587

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs">#</a> Aufgabenprotokolle

Bei der Aufnahme ohne Middle Manager können persistente Aufgabenprotokolle nicht mehr auf unbestimmte Zeit blockiert werden. Stattdessen gibt es eine zeitliche Begrenzung für die Beibehaltung von Protokollen, deren Verletzung dazu führt, dass die Beibehaltung aufgegeben wird. Das Standard-Timeout beträgt 5 Minuten, kann jedoch durch Überschreiben von druid.indexer.runner.logSaveTimeout mit einer Dauer wie PT60S konfiguriert werden.

Darüber hinaus ist die Speicherung von Aufgabenprotokollen für den Kubernetes-Runner jetzt optional.

#18444 #18341

Der druid-kubernetes-overlord-extensions, der Kubernetes zum Starten und Verwalten von Aufgaben anstelle der mittleren Manager verwendet, ist jetzt widerstandsfähiger gegen bestimmte vorübergehende Fehler.

#18406

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure">#</a> Schnellerer Aufgabenfehler

Aufgaben-Pods geben jetzt Kubernetes-Jobereignisse aus, wenn sie während der Pod-Erstellungsphase fehlschlagen, und K8s-Aufgaben schlagen unter nicht behebbaren Bedingungen schnell fehl.

#18159

<a name="35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs" href="#35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs">#</a> Zusätzliche Konfigurationen bereitstellen

Bisher konnten Sie über eine Umgebungsvariable zusätzliche Konfigurationen angeben, die an _common gemountet werden sollen, dies galt jedoch nur für den Druid-Prozess. Sie können jetzt dieselbe Konfiguration auch auf Aufnahmeaufgaben anwenden, die als Kubernetes-Jobs übermittelt werden (MiddleManager-loser Modus), um Konsistenz über alle Aufgabentypen hinweg sicherzustellen.

#18447

<a name="35.0.0-upgrade-notes-and-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes">#</a> Upgrade-Hinweise und inkompatible Änderungen

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Upgrade-Hinweise

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default">#</a> Fallback-Vektorisierung standardmäßig aktiviert

Der druid.expressions.allowVectorizeFallback ist jetzt standardmäßig auf true eingestellt. Darüber hinaus kann SAFE_DIVIDE jetzt als Fallback vektorisieren.

#18549

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-">#</a> Anlegestelle 12

Druid verwendet jetzt Jetty 12. Ihre Bereitstellung kann davon betroffen sein, insbesondere im Hinblick auf die URI-Konformität und SNI-Hostprüfungen.

Eine neue Serverkonfigurationsoption wurde hinzugefügt: druid.server.http.uriCompliance. Jetty 12 verfügt standardmäßig über eine strikte Durchsetzung des URI-Formats RFC3986. Dies ist eine Änderung gegenüber Jetty 9. Um mögliche Breaking Changes in bestehenden Druid-Bereitstellungen zu vermeiden, ist diese Konfiguration standardmäßig auf LEGACY eingestellt, das die freizügigere URI-Format-Durchsetzung verwendet, die Jetty 9 verwendet hat. Wenn der von Ihnen betriebene Cluster keine Legacy-Kompatibilität erfordert, empfehlen wir Ihnen, in Ihrer Druid-Bereitstellung den Upstream-Jetty-Standard RFC3986 zu verwenden. Weitere Informationen finden Sie in der Dokumentation zum Steg.

Jetty 12-Server führen strenge SNI host0-Prüfungen durch, wenn TLS aktiviert ist. Wenn der Host, mit dem Ihr client eine Verbindung zum Server herstellt, nicht mit den Inhalten im Keystore übereinstimmt, wird eine 400-Antwort zurückgegeben, selbst wenn nur ein Zertifikat in diesem Keystore vorhanden ist. Dies könnte sich auf einige Anwendungsfälle auswirken, z. B. wenn Leute aus irgendeinem Grund eine Verbindung über localhost herstellen. Wenn diese Änderung Ihre Bereitstellung unterbricht, können Sie sich von der Änderung abmelden, indem Sie druid.server.http.enforceStrictSNIHostChecking in den runtime.properties für einige oder alle Ihrer Druid-Dienste auf „false“ setzen. Es wird empfohlen, dass Sie Ihr client-Verhalten ändern, um diese Änderung in jetty zu berücksichtigen, anstatt die Konfiguration nach Möglichkeit zu überschreiben.

#18424 #18623

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication">#</a> Kerberos-Authentifizierung

Die druid.auth.authenticator.kerberos.cookieSignatureSecret-Konfiguration ist jetzt obligatorisch.

#18368

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine">#</a> Mehrstufige Abfrage-Task-Engine

Die MSQ-Task-Engine ist jetzt eine Kernfunktion von Druid und keine Erweiterung mehr. Es befindet sich seit mehreren Versionen in der Standardladeliste für Erweiterungen.

Entfernen Sie druid-multi-stage-query von druid.extensions.loadList in common.runtimes.properties, bevor Sie ein Upgrade durchführen.

Druid 35.0.0 ignoriert die Erweiterung, wenn sie in der Ladeliste enthalten ist. Zukünftige Versionen von Druid können nicht gestartet werden, da die Erweiterung nicht gefunden werden kann.

#18394

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension">#</a> pac4j-Erweiterung

Aufgrund des Upgrades von pac4j 4 auf 5 hat sich die Sitzungsserialisierung von JavaSerializer von pac4j auf die Standard-Java-Serialisierung geändert. Daher werden clients von Clustern, die die Erweiterung pac4j verwenden, möglicherweise während fortlaufender Upgrades abgemeldet und müssen sich erneut authentifizieren.

#18259

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Inkompatible Änderungen

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed">#</a> Java 11-Unterstützung entfernt

Führen Sie ein Upgrade auf Java 17 oder 21 durch. Beachten Sie, dass bei einigen Versionen von Java 21 während des Tests Probleme aufgetreten sind, insbesondere bei Java 21.05-21.07. Vermeiden Sie nach Möglichkeit diese Versionen.

#18424

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Entwicklerhinweise

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests">#</a> Eingebettete Clustertests

Mit dem neuen eingebetteten Cluster-Test-Framework können Sie einfache Integrationstests mit einem voll funktionsfähigen Druid-Cluster ausführen, der auf einem einzelnen Prozess ausgeführt wird, einschließlich aller Erweiterungen, die Sie laden möchten, sowie des Metadatenspeichers ZooKeeper und Derby. Sie müssen mvn build nicht mehr ausführen, kein docker-Image erstellen oder sogar Startskripts ausführen, um Integrationstests durchzuführen.

#18147

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json">#</a> Spezialisierte virtuelle Spalten für JSON

Der von ColumnSelector zurückgegebene ColumnHolder gibt jetzt einen SelectableColumn anstelle von BaseColumn von getColumn() zurück. Der SelectableColumn kann ein BaseColumn oder eine von einer virtuellen Säule bereitgestellte Implementierung sein. Erweiterungen, die physische Spalten von einem ColumnSelector abrufen müssen, können mithilfe von instanceof prüfen, ob es sich bei der Spalte um einen BaseColumn handelt. Der Einfachheit halber wurde der Rückgabetyp von getColumnHolder auf QueryableIndex auf BaseColumnHolder spezialisiert, der immer BaseColumn von getColumn() zurückgibt. Erweiterungen, die diese Methode für QueryableIndex aufrufen, können das Ergebnis in einer Variablen vom Typ BaseColumnHolder speichern, um eine Umwandlung der Spalte zu vermeiden.

#18521

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed">#</a> reset-cluster-Tool entfernt

Das auf Entwicklungs- und Testumgebungen ausgerichtete Tool reset-cluster wurde entfernt. Es war veraltet und konnte den Metadatenspeicher nicht vollständig löschen (fehlende Tabellen upgradeSegments und segmentSchemas, die in Druid 28 bzw. 30 hinzugefügt wurden). Dieses Tool war nicht für Produktionsanwendungsfälle gedacht und sollte daher keine Auswirkungen auf Clusterbetreiber haben.

#18246

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions">#</a> Grundlegende Änderung für SQL-Metadatenerweiterungen

Der Erweiterungspunkt MetadataStorageActionHandler verfügt jetzt über einfachere APIs. Dies ist eine bahnbrechende Änderung für alle verfügbaren SQL-Metadatenerweiterungen. Die Änderungen für PostgreSQL, MySQL und SQLServer sind bereits abgeschlossen. #18479

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed">#</a> DriudLeaderClient entfernt

DruidLeaderClient wurde aus den Erweiterungen entfernt und durch eine ServiceClient-basierte Implementierung ersetzt. Darüber hinaus ist CoordinatorServiceClient zum Abfragen von nicht zum Kern gehörenden APIs, die vom Koordinator bereitgestellt werden, über druid-server verfügbar.
