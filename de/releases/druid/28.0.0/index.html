Druide Druide-28.0.0

Apache Druid 28.0.0 enthält über 420 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 57 Mitwirkenden.

Weitere Details, einschließlich Fehlerbehebungen, finden Sie im vollständigen Änderungssatz.

Lesen Sie die Upgrade-Hinweise und inkompatible Änderungen, bevor Sie ein Upgrade auf Druid 28.0.0 durchführen.

<a name="28.0.0-important-changes-and-deprecations" href="#28.0.0-important-changes-and-deprecations">#</a> Wichtige Funktionen, Änderungen und veraltete Funktionen

In Druid 28.0.0 haben wir erhebliche Verbesserungen an der Abfrage vorgenommen, um das System ANSI SQL-kompatibel zu machen. Dazu gehören Änderungen im Umgang mit NULL- und booleschen Werten sowie der booleschen Logik. Gleichzeitig wurde die Apache Calcite-Bibliothek auf die neueste Version aktualisiert. Obwohl wir bekannte Änderungen im Abfrageverhalten dokumentiert haben, lesen Sie bitte den Abschnitt Upgrade-Hinweise sorgfältig durch. Testen Sie Ihre Anwendung vor der Einführung in umfassende Produktionsszenarien und überwachen Sie dabei den Abfragestatus genau.

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility" href="#28.0.0-important-changes-and-deprecations-sql-compatibility">#</a> SQL-Kompatibilität

Druid macht die Ausführung von SQL-Abfragen weiterhin konsistenter mit dem Verhalten von Standard-SQL. Es stehen jedoch Feature-Flags zur Verfügung, um bei Bedarf das alte Verhalten wiederherzustellen.

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic">#</a> Dreiwertige Logik

Native Druid-Filter berücksichtigen jetzt standardmäßig SQL dreiwertige Logik (true, false oder unknown) anstelle der klassischen Zwei-Zustands-Logik von Druid, wenn die folgenden Standardeinstellungen gelten:

  • druid.generic.useThreeValueLogicForNativeFilters = true
  • druid.expressions.useStrictBooleans = true
  • druid.generic.useDefaultValueForNull = false

#15058

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans">#</a> Strikte Boolesche Werte

druid.expressions.useStrictBooleans ist jetzt standardmäßig aktiviert. Druid verarbeitet Boolesche Werte jetzt ausschließlich mit 1 (wahr) oder 0 (falsch). Bisher konnten „true“ und „false“ entweder als true und false sowie als 1 und 0 dargestellt werden. Darüber hinaus gibt Druid jetzt einen Nullwert für boolesche Vergleiche wie True && NULL zurück.

Wenn Sie diese Eigenschaft in runtime.properties nicht explizit konfigurieren, verwenden Cluster jetzt LONG-Typen für alle aufgenommenen booleschen Werte und in der Ausgabe boolescher Funktionen für Transformationen und Abfragezeitoperationen. Weitere Informationen finden Sie unter SQL-Kompatibilität in den Upgrade-Hinweisen.

#14734

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling">#</a> NULL-Behandlung

druid.generic.useDefaultValueForNull ist jetzt standardmäßig deaktiviert. Druid unterscheidet jetzt zwischen leeren Datensätzen und Null-Datensätzen. Bisher behandelte Druid leere Datensätze möglicherweise als leer oder null. Weitere Informationen finden Sie unter SQL-Kompatibilität in den Upgrade-Hinweisen.

#14792

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements">#</a> SQL-Planer-Verbesserungen

Druid verwendet Apache Calcite für die SQL-Planung und -Optimierung. Ab Druid 28.0.0 wurde die Calcit-Version von 1.21 auf 1.35 aktualisiert. Dieses Upgrade bringt viele Fehlerbehebungen in der SQL-Planung von Calcite mit sich.

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters">#</a> Dynamische Parameter

Im Rahmen des Calcite-Upgrades hat sich das Verhalten der Typinferenz für dynamische Parameter geändert. Um Typinterferenzprobleme zu vermeiden, CAST alle dynamischen Parameter explizit als einen bestimmten Datentyp in SQL-Abfragen. Verwenden Sie zum Beispiel:

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

Nicht verwenden:

SELECT (1 * ?)/2 as tmp

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage">#</a> Asynchrone Abfrage und Abfrage aus dem Deep Storage

Abfrage aus tiefem Speicher ist keine experimentelle Funktion mehr. Wenn Sie Abfragen aus dem Deep Storage durchführen, stehen mehr Daten für Abfragen zur Verfügung, ohne dass Sie Ihre historischen Dienste skalieren müssen, um mehr Daten aufzunehmen. Um von der Platzersparnis zu profitieren, die diese Abfrage durch Deep Storage bietet, konfigurieren Sie Ihre Laderegeln so, dass Daten aus Ihren historischen Diensten entladen werden.

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats">#</a> Unterstützung für mehrere Ergebnisformate

Abfragen aus dem Deep Storage unterstützen jetzt mehrere Ergebnisformate. Bisher unterstützte der Endpunkt /druid/v2/sql/statements/ nur Ergebnisse im object-Format. Jetzt können Ergebnisse in jedem Format geschrieben werden, das im Parameter resultFormat angegeben ist. Weitere Informationen zu Ergebnisparametern, die von Druid SQL API unterstützt werden, finden Sie unter Antworten.

#14571

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-broadened-access-for-queries-from-deep-storage" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-broadened-access-for-queries-from-deep-storage">#</a> Erweiterter Zugriff für Abfragen aus dem Deep Storage

Benutzer mit der Berechtigung STATE können mit Status-APIs für Abfragen aus dem Deep Storage interagieren. Bisher konnte nur der Benutzer, der die Abfrage übermittelte, diese APIs verwenden. Dadurch kann die Webkonsole den Ausführungsstatus der Abfragen überwachen. Benutzer mit der Berechtigung STATE können auf die Abfrageergebnisse zugreifen.

<a name="28.0.0-important-changes-and-deprecations-msq-queries-for-realtime-tasks" href="#28.0.0-important-changes-and-deprecations-msq-queries-for-realtime-tasks">#</a> MSQ-Abfragen für Echtzeitaufgaben

Die MSQ-Aufgaben-Engine kann jetzt Echtzeitsegmente in Abfrageergebnisse einbeziehen. Verwenden Sie dazu den Kontextparameter includeSegmentSource und setzen Sie ihn auf REALTIME.

<a name="28.0.0-important-changes-and-deprecations-msq-support-for-union-all-queries" href="#28.0.0-important-changes-and-deprecations-msq-support-for-union-all-queries">#</a> MSQ-Unterstützung für UNION ALL-Abfragen

Sie können jetzt die MSQ-Task-Engine verwenden, um UNION ALL-Abfragen mit UnionDataSource auszuführen.

#14981

<a name="28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource" href="#28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource">#</a> Aus mehreren Kafka-Themen in eine einzige Datenquelle aufnehmen

Sie können jetzt mit einem einzigen Supervisor Streaming-Daten aus mehreren Kafka-Themen in eine Datenquelle aufnehmen. Sie konfigurieren die Themen für die Supervisor-Spezifikation mithilfe eines Regex-Musters als Wert für topicPattern in der E/A-Konfiguration. Wenn Sie Kafka neue Themen hinzufügen, die mit der Regex übereinstimmen, beginnt Druid automatisch mit der Aufnahme dieser neuen Themen.

Wenn Sie die Aufnahme mehrerer Themen für eine Datenquelle aktivieren, führt ein Downgrade dazu, dass der Supervisor fehlschlägt. Weitere Informationen finden Sie unter Stoppen Sie Supervisoren, die mehrere Kafka-Themen aufnehmen, bevor Sie ein Downgrade durchführen.

<a name="28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening" href="#28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening">#</a> SQL UNNEST und Vereinfachung der Aufnahme

Die UNNEST-Funktion ist nicht mehr experimentell.

Druid unterstützt jetzt UNNEST bei der SQL-basierten Batch-Aufnahme und Abfrage aus tiefem Speicher, sodass Sie Arrays einfach reduzieren können. Weitere Informationen finden Sie unter UNNEST und Arrays innerhalb einer Spalte entschachteln.

Sie müssen den Kontextparameter enableUnnest: true nicht mehr einschließen, um UNNEST zu verwenden.

#14886

<a name="28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest" href="#28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest">#</a> Empfohlene Syntax für SQL UNNEST

Die empfohlene Syntax für SQL UNNEST hat sich geändert. Wir empfehlen für die meisten Abfragen die Verwendung von CROSS JOIN anstelle von Kommas, um Prioritätsprobleme zu vermeiden. Verwenden Sie zum Beispiel:

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

Nicht verwenden:

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

<a name="28.0.0-important-changes-and-deprecations-window-functions-%28experimental%29" href="#28.0.0-important-changes-and-deprecations-window-functions-%28experimental%29">#</a> Fensterfunktionen (experimentell)

Sie können Fensterfunktionen in Apache Druid verwenden, um Werte basierend auf der Beziehung einer Zeile innerhalb eines Zeilenfensters zu den anderen Zeilen innerhalb desselben Fensters zu erzeugen. Ein Fenster ist eine Gruppe zusammengehöriger Zeilen innerhalb einer Ergebnismenge. Beispielsweise Zeilen mit demselben Wert für eine bestimmte Dimension.

Aktivieren Sie Fensterfunktionen in Ihrer Abfrage mit dem Kontextparameter enableWindowing: true.

#15184

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29">#</a> Gleichzeitiges Anhängen und Ersetzen (experimentell)

Druid 28.0.0 bietet experimentelle Unterstützung für gleichzeitiges Anhängen und Ersetzen. Mit dieser Funktion können Sie die vorhandenen Daten in einem Intervall einer Datenquelle sicher ersetzen, während neue Daten an dieses Intervall angehängt werden. Eine der häufigsten Anwendungen hierfür ist das Anhängen neuer Daten an ein Intervall, während die Komprimierung dieses Intervalls bereits läuft. Weitere Informationen finden Sie unter Gleichzeitiges Anhängen und Ersetzen.

Die Segmentsperre wird veraltet und zugunsten des gleichzeitigen Anhängens und Ersetzens entfernt, das viel einfacher im Design ist. Beim gleichzeitigen Anhängen und Ersetzen sperrt Druid Komprimierungsjobs nicht aufgrund der aktiven Echtzeitaufnahme.

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs">#</a> Aufgabensperren für Batch-Ingestion-Jobs zum Anhängen und Ersetzen

Anhänge-Batch-Aufnahmejobs können jetzt Sperren gemeinsam nutzen. Auf diese Weise können Sie mehrere Anhänge-Batch-Aufnahmejobs gleichzeitig intern ausführen. Jobs zum Ersetzen von Batch-Aufnahmen erfordern weiterhin eine exklusive Sperre. Dies bedeutet, dass Sie für ein bestimmtes Intervall mehrere Batch-Aufnahmejobs zum Anhängen und einen Batch-Aufnahmejob zum Ersetzen ausführen können.

#14407

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-streaming-ingestion-with-concurrent-replace" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-streaming-ingestion-with-concurrent-replace">#</a> Streaming-Aufnahme mit gleichzeitigem Ersetzen

Streaming-Jobs, die aus Kafka und Kinesis mit APPEND-Sperren lesen, können jetzt gleichzeitig mit der Komprimierung aufgenommen werden, die mit REPLACE-Sperren ausgeführt wird. Die Segmentgranularität des Streaming-Jobs muss gleich oder feiner sein als die des gleichzeitigen Ersetzungsjobs.

<a name="28.0.0-functional-area-and-related-changes-ingestion-json-and-auto-column-indexer" href="#28.0.0-functional-area-and-related-changes-ingestion-json-and-auto-column-indexer">#</a> JSON und automatischer Spaltenindexer

Der Spaltentyp json entspricht jetzt der Verwendung von auto in JSON-basierten Dimensionsspezifikationen für die Stapelaufnahme. Aktualisieren Sie Ihre Aufnahmespezifikationen auf json, um die Features und Funktionen von auto zu nutzen, einschließlich der folgenden:

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types">#</a> Möglichkeit zur Aufnahme von ARRAY-Typen

Die SQL-basierte Aufnahme unterstützt jetzt das Speichern von ARRAY-typisierten Werten in [ARRAY-typisierten Spalten] (https://druid.apache.org/docs/latest/querying/arrays) sowie das Speichern von VARCHAR- und numerischen typisierten Arrays. Zuvor speicherte die MSQ-Aufgaben-Engine ARRAY-typisierte Werte als mehrwertige Dimensionen anstelle von ARRAY-typisierten Spalten.

Die MSQ-Aufgaben-Engine enthält jetzt den Abfragekontextparameter arrayIngestMode, der steuert, wie ARRAY-Typen werden in Druid-Segmenten gespeichert. Legen Sie den Abfragekontextparameter arrayIngestMode auf array fest, um ARRAY-Typen aufzunehmen.

In Druid 28.0.0 ist der Standardmodus für arrayIngestMode aus Gründen der Abwärtskompatibilität mvd, der nur Arrays vom Typ VARCHAR unterstützt und sie als mehrwertige Dimensionen speichert. Diese Standardeinstellung kann sich in zukünftigen Versionen ändern.

Informationen zur Migration auf das neue Verhalten finden Sie in den Aufnahmeoptionen für ARRAY-typisierte Spalten in den Upgrade-Hinweisen. Informationen zum Einfüge-, Filter- und Gruppierungsverhalten für Spalten vom Typ ARRAY finden Sie unter Array-Spalten.

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-numeric-array-type-support" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-numeric-array-type-support">#</a> Unterstützung für numerische Array-Typen

Zeilenbasierte Frames und damit auch die MSQ-Task-Engine unterstützen jetzt numerische Array-Typen. Das bedeutet, dass alle Abfragen, die Arrays nutzen oder erzeugen, mit der MSQ-Task-Engine funktionieren. Numerische Arrays können auch mithilfe der SQL-basierten Erfassung mit MSQ erfasst werden. Beispielsweise sind Abfragen wie SELECT [1, 2] jetzt gültig, da sie ein numerisches Array verwenden, anstatt mit einer nicht unterstützten Spaltentypausnahme fehlzuschlagen.

<a name="28.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-ability-to-reset-offsets-for-a-supervisor" href="#28.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-ability-to-reset-offsets-for-a-supervisor">#</a> Möglichkeit zum Zurücksetzen von Offsets für einen Supervisor

Mit neuen SQL- und nativen Abfragefunktionen können Sie bewerten, ob zwei Ausdrücke unterschiedlich sind oder nicht. Ausdrücke sind unterschiedlich, wenn sie unterschiedliche Werte haben oder wenn einer von ihnen NULL ist. Ausdrücke sind nicht eindeutig, wenn ihre Werte gleich sind oder wenn beide NULL sind.

Da die Funktionen NULL-Werte als bekannte Werte behandeln, wenn sie als Vergleichsoperator verwendet werden, geben sie immer „true“ oder „false“ zurück, selbst wenn einer oder beide Ausdrücke NULL sind.

Die folgende Tabelle zeigt den Unterschied im Verhalten zwischen dem Gleichheitszeichen (=) und IS [NOT] DISTINCT FROM:

Sie können die Leitplanke maxSubqueryBytes jetzt auf eine der folgenden Einstellungen einstellen:

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest">#</a> Empfohlene Syntax für SQL UNNEST

Die empfohlene Syntax für SQL UNNEST hat sich geändert. Wir empfehlen für die meisten Abfragen die Verwendung von CROSS JOIN anstelle von Kommas, um Prioritätsprobleme zu vermeiden. Verwenden Sie zum Beispiel:

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

Nicht verwenden:

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters">#</a> Dynamische Parameter

Die Apache Calcite-Version wurde von 1.21 auf 1.35 aktualisiert. Im Rahmen des Calcite-Upgrades hat sich das Verhalten der Typinferenz für dynamische Parameter geändert. Um Typinterferenzprobleme zu vermeiden, CAST alle dynamischen Parameter explizit als einen bestimmten Datentyp in SQL-Abfragen. Verwenden Sie zum Beispiel:

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

Nicht verwenden:

SELECT (1 * ?)/2 as tmp

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format">#</a> Verschachteltes Spaltenformat

Spalten vom Typ json, die mit Druid 28.0.0 erstellt wurden, sind nicht abwärtskompatibel mit Druid-Versionen, die älter als 26.0.0 sind. Wenn Sie ein Upgrade von einer Version vor Druid 26.0.0 durchführen und json-Spalten verwenden, aktualisieren Sie auf Druid 26.0.0, bevor Sie auf Druid 28.0.0 aktualisieren. Darüber hinaus sollten für ein Downgrade auf eine ältere Version als Druid 26.0.0 alle neuen Segmente, die in Druid 28.0.0 erstellt wurden, vor dem weiteren Downgrade erneut mit Druid 26.0.0 oder 27.0.0 aufgenommen werden.

Beim Upgrade von einer früheren Version können Sie weiterhin verschachtelte Spalten in einem abwärtskompatiblen Format schreiben (Version 4).

Fügen Sie in einem klassischen Batch-Aufnahmejob formatVersion in die dimensions-Liste der Eigenschaft dimensionsSpec ein. Zum Beispiel:

      "dimensionsSpec": {
        "dimensions": [
          "product",
          "department",
          {
            "type": "json",
            "name": "shipTo",
            "formatVersion": 4
          }
        ]
      },

Um die Standardversion verschachtelter Spalten festzulegen, legen Sie die gewünschte Formatversion in den allgemeinen Laufzeiteigenschaften fest. Zum Beispiel:

druid.indexing.formats.nestedColumnFormatVersion=4

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility">#</a> SQL-Kompatibilität

Ab Druid 28.0.0 hat sich die Standardmethode, mit der Druid Nullen und Boolesche Werte behandelt, geändert.

Bei Nullen unterscheidet Druid nun zwischen einem leeren String und einem Datensatz ohne Daten sowie zwischen einem leeren numerischen Datensatz und 0.
Sie können zum vorherigen Verhalten zurückkehren, indem Sie druid.generic.useDefaultValueForNull auf true setzen.

Diese Eigenschaft wirkt sich sowohl auf die Speicherung als auch auf Abfragen aus und muss für alle Druid-Diensttypen festgelegt werden, damit sie sowohl zur Aufnahmezeit als auch zur Abfragezeit verfügbar ist. Durch das Zurücksetzen dieser Einstellung auf den alten Wert wird das vorherige Verhalten ohne erneute Aufnahme wiederhergestellt.

Für boolesche Werte verwendet Druid jetzt ausschließlich 1 (wahr) oder 0 (falsch). Bisher konnten „true“ und „false“ entweder als true und false sowie als 1 und 0 dargestellt werden. Darüber hinaus gibt Druid jetzt einen Nullwert für boolesche Vergleiche wie True && NULL zurück.

Sie können zum vorherigen Verhalten zurückkehren, indem Sie druid.expressions.useStrictBooleans auf false setzen. Diese Eigenschaft wirkt sich sowohl auf die Speicherung als auch auf Abfragen aus und muss für alle Druid-Diensttypen festgelegt werden, damit sie sowohl zur Aufnahmezeit als auch zur Abfragezeit verfügbar ist. Durch das Zurücksetzen dieser Einstellung auf den alten Wert wird das vorherige Verhalten ohne erneute Aufnahme wiederhergestellt.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns">#</a> Aufnahmeoptionen für ARRAY-typisierte Spalten

Ab Druid 28.0.0 kann die MSQ-Task-Engine Arrays als Spalten vom Typ ARRAY erkennen und aufnehmen, wenn Sie den Abfragekontextparameter arrayIngestMode auf array setzen. Der Kontextparameter arrayIngestMode steuert, wie Werte vom Typ ARRAY in Druid-Segmenten gespeichert werden.

Wenn Sie arrayIngestMode auf array festlegen (empfohlen für SQL-Konformität), speichert die MSQ-Task-Engine alle ARRAY-typisierten Werte in [ARRAY-typisierten Spalten] (https://druid.apache.org/docs/latest/querying/arrays) und unterstützt das Speichern sowohl von VARCHAR- als auch numerisch typisierten Arrays.

Aus Gründen der Abwärtskompatibilität ist arrayIngestMode standardmäßig auf mvd eingestellt. Bei "arrayIngestMode":"mvd" unterstützt Druid nur Arrays vom Typ VARCHAR und speichert sie als [mehrwertige Zeichenfolgenspalten] (https://druid.apache.org/docs/latest/querying/multi-value-dimensions).

Wenn Sie arrayIngestMode auf none setzen, löst Druid eine Ausnahme aus, wenn versucht wird, Arrays jeglicher Art zu speichern.

Weitere Informationen zur Aufnahme von ARRAY-typisierten Spalten mit SQL-basierter Aufnahme finden Sie unter SQL-Datentypen und Array-Spalten.
