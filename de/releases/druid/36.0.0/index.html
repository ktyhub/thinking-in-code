Druide Druide-36.0.0

Apache Druid 36.0.0 enthält über 189 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 34 Mitwirkenden.

Der Operator vereinfacht die Verwaltung von Druid-Clustern mit seiner benutzerdefinierten Logik, die über konfiguriert werden kann Kubernetes CRDs. [#18435](https://github.com/apache/druid/pull/18435) #### Kostenbasierte Autoskalierung für die Streaming-Aufnahme Druid unterstützt jetzt kostenbasiertes Autoscaling für die Streaming-Aufnahme, das die Aufgabenanzahl optimiert, indem es die Verzögerungsreduzierung mit der Ressourceneffizienz in Einklang bringt. Diese Autoscaling-Strategie verwendet die folgende Formel: ``` totalCost = lagWeight × lagRecoveryTime + idleWeight × idlenessCost ``` Dies berücksichtigt die Zeit zum Löschen des Rückstands und die Rechenzeit: ``` lagRecoveryTime = aggregateLag / (taskCount × avgProcessingRate) — time to clear backlog idlenessCost = taskCount × taskDuration × predictedIdleRatio — wasted compute time ``` [#18819](https://github.com/apache/druid/pull/18819) #### Kubernetes client-Modus (experimentell) In `kubernetes-overlord-extensions` wurde ein experimenteller Kubernetes client-Modus hinzugefügt. Der neue Modus verwendet `fabric8` `SharedInformers` zum Zwischenspeichern von K8s-Metadaten. Dadurch wird der API-Verkehr zwischen dem Overlord und der k8s-Kontrollebene erheblich reduziert. Sie können diese Funktion mit der folgenden Konfiguration ausprobieren: ``` druid.indexer.runner.useK8sSharedInformers=true ``` [#18599](https://github.com/apache/druid/pull/18599) #### cgroup v2-Unterstützung cgroup v2 wird jetzt unterstützt und alle cgroup-Metriken geben jetzt `cgroupversion` aus, um zu identifizieren, welche Version verwendet wird. Die folgenden Metriken wechseln automatisch zu v2, wenn v2 erkannt wird: `CgroupCpuMonitor`, `CgroupCpuSetMonitor`, `CgroupDiskMonitor`, `MemoryMonitor`. `CpuAcctDeltaMonitor` schlägt ordnungsgemäß fehl, wenn v2 erkannt wird. Darüber hinaus sendet `CgroupV2CpuMonitor` jetzt auch `cgroup/cpu/shares` und `cgroup/cpu/cores_quota` aus. [#18705](https://github.com/apache/druid/pull/18705) #### Abfrageberichte für Dart Dart unterstützt jetzt Abfrageberichte für laufende und kürzlich abgeschlossene Abfragen. Die Berichte können vom Endpunkt `/druid/v2/sql/queries/<sqlQueryId>/reports` abgerufen werden. Das Format der Antwort ist ein JSON-Objekt mit zwei Schlüsseln, „query“ und „report“. Der „Abfrage“-Schlüssel ist die gleiche Information, die vom vorhandenen `/druid/v2/sql/queries`-Endpunkt verfügbar ist. Der Schlüssel „Bericht“ ist eine Berichtszuordnung einschließlich eines MSQ-Berichts. Sie können das Aufbewahrungsverhalten für Berichte mithilfe der folgenden Konfigurationen steuern: * `druid.msq.dart.controller.maxRetainedReportCount`: Maximale Anzahl der Berichte, die aufbewahrt werden. Der Standardwert ist 0, was bedeutet, dass keine Berichte gespeichert werden * `druid.msq.dart.controller.maxRetainedReportDuration`: Wie lange Berichte im ISO 8601-Dauerformat aufbewahrt werden. Der Standardwert ist `PT0S`, was bedeutet, dass der zeitbasierte Ablauf deaktiviert ist [#18886](https://github.com/apache/druid/pull/18886) #### Neues Segmentformat Das neue Segmentformat der Version 10 ist eine Verbesserung gegenüber Version 9. Es ist standardmäßig deaktiviert und nicht mit älteren Segmentformatversionen kompatibel. Legen Sie `druid.indexer.task.buildV10=true` fest, um Segmente im neuen Format zu erstellen. Wenn Sie ein Downgrade durchführen, müssen Sie Ihre Daten mit einer unterstützten Segmentformatversion neu indizieren. Mit dem Tool `bin/dump-segment` können Sie Segmentmetadaten anzeigen. Das Tool gibt serialisierte JSON aus. [#18880](https://github.com/apache/druid/pull/18880) [#18901](https://github.com/apache/druid/pull/18901) ### Webkonsole #### Neue Informationen in der Webkonsole verfügbar Die Webkonsole enthält jetzt Informationen über die Anzahl der verfügbaren Prozessoren und den Gesamtspeicher (in Binärbytes). Diese Informationen sind auch über die Tabelle `sys.servers` verfügbar. [#18613](https://github.com/apache/druid/pull/18613) #### Weitere Verbesserungen der Webkonsole * Nachverfolgung für inaktive Arbeiter für MSQ-Ausführungsphasen hinzugefügt [#18768](https://github.com/apache/druid/pull/18768) * Eine Aktualisierungsschaltfläche für JSON-Ansichten und Bühnenbetrachter hinzugefügt [#18768](https://github.com/apache/druid/pull/18768) * Sie können jetzt Parameter vom Typ `ARRAY` in der Abfrageansicht definieren [#18586](https://github.com/apache/druid/pull/18586) * Systemtabellenabfragen wurden so geändert, dass nun automatisch die native Engine verwendet wird [#18857](https://github.com/apache/druid/pull/18857) * Verbesserte Zeitdiagramme zur Unterstützung mehrerer Maßnahmen [#18701](https://github.com/apache/druid/pull/18701) ### Einnahme * Unterstützung für AWS `InternalError`-Codewiederholungen hinzugefügt [#18720](https://github.com/apache/druid/pull/18720) * Verbesserte Einnahme, um widerstandsfähiger zu sein. Aufnahmeaufgaben schlagen nicht mehr fehl, wenn das Hochladen des Aufgabenprotokolls mit einer Ausnahme fehlschlägt [#18748](https://github.com/apache/druid/pull/18748) * Die Art und Weise, wie Druide mit Situationen umgeht, in denen Daten nicht dem erwarteten Typ entsprechen, wurde verbessert [#18878](https://github.com/apache/druid/pull/18878) * Verbesserte JSON-Aufnahme, sodass Druid JSON-Werte direkt aus Wörterbuch- oder Indexstrukturen berechnen kann, sodass bei der Aufnahme persistente JSON-Rohdaten vollständig übersprungen werden können. Dadurch wird die Speichergröße auf der Festplatte verringert [#18589](https://github.com/apache/druid/pull/18589) * Sie können jetzt zwischen einer vollständigen wörterbuchbasierten Indizierung und einer Nur-Null-Indizierung für lange/doppelte Felder in einer verschachtelten Spalte wählen [#18722](https://github.com/apache/druid/pull/18722) #### SQL-basierte Aufnahme ##### Zusätzliche Aufnahmekonfigurationen Sie können jetzt die folgenden Konfigurationen verwenden, um zu steuern, wie Ihre Daten erfasst und gespeichert werden: * `maxInputFilesPerWorker`: Steuert die maximale Anzahl von Eingabedateien oder Segmenten pro Worker. * `maxPartitions`: Steuert die maximale Anzahl von Ausgabepartitionen für jede einzelne Stufe, was sich darauf auswirkt, wie viele Segmente während der Aufnahme generiert werden. [#18826](https://github.com/apache/druid/pull/18826) ##### Weitere Verbesserungen der SQL-basierten Aufnahme * `maxRowsInMemory` hinzugefügt, um `rowsInMemory` zu ersetzen. `rowsInMemory` fungiert jetzt als alternative Möglichkeit zur Bereitstellung dieser Konfiguration und wird ignoriert, wenn `maxRowsInMemory` angegeben ist. Bisher existierte nur `rowsInMemory` [#18832](https://github.com/apache/druid/pull/18832) #### Streaming-Aufnahme ##### Offset und Partition aufzeichnen Sie können jetzt den Datensatz-Offset (`offsetColumnName`) und die Partition (`partitionColumnName`) mithilfe von `KafkaInputFormat` erfassen. Ihre Standardnamen sind `kafka.offset` bzw. `kafka.partition`. [#18757](https://github.com/apache/druid/pull/18757) ##### Weitere Verbesserungen bei der Streaming-Aufnahme * Verbesserte Vorgesetzte, sodass sie keine Aufgaben beenden können, während der Vorgesetzte stoppt [#18767](https://github.com/apache/druid/pull/18767) * Der verzögerungsbasierte Autoscaler für die Streaming-Aufnahme wurde verbessert [#18745](https://github.com/apache/druid/pull/18745) * Der Supervisor-Autoscaler `SeekableStream` wurde verbessert, sodass er auf den Abschluss von Aufgaben wartet, bevor er nachfolgende Skalierungsvorgänge versucht. Dies trägt dazu bei, doppelte Supervisor-Verlaufseinträge zu verhindern [#18715](https://github.com/apache/druid/pull/18715) ### Abfragen #### Weitere Abfrageverbesserungen * Das Benutzererlebnis für ungültige `regex_exp`-Abfragen wurde verbessert. Es wird jetzt ein Fehler zurückgegeben [#18762](https://github.com/apache/druid/pull/18762) ### Clusterverwaltung #### Dynamische Kapazität für Kubernetes-basierte Bereitstellungen Druid kann jetzt die Task-Runner-Kapazität dynamisch anpassen. Schließen Sie das Feld `capacity` in einen POST API-Aufruf an `/druid/indexer/v1/k8s/taskrunner/executionconfig` ein. Das Festlegen eines Werts auf diese Weise überschreibt `druid.indexer.runner.capacity`. [#18591](https://github.com/apache/druid/pull/18591) #### Tabelle mit Servereigenschaften Die Tabelle `sys.server_properties` stellt die für jeden Druid-Server konfigurierten Laufzeiteigenschaften bereit. Jede Zeile stellt ein einzelnes Eigenschaftsschlüssel-Wert-Paar dar, das einem bestimmten Server zugeordnet ist. [#18692](https://github.com/apache/druid/pull/18692) #### Weitere Verbesserungen bei der Clusterverwaltung * Dienstqualitätsfilterung für den Overlord hinzugefügt, damit Gesundheitsprüfungsthreads nicht blockiert werden [#18033](https://github.com/apache/druid/pull/18033) ### Datenverwaltung #### Weitere Verbesserungen bei der Datenverwaltung * Die Komprimierungsrichtlinie `mostFragmentedFirst` wurde hinzugefügt, die Intervalle mit den kleinsten nicht komprimierten Segmenten priorisiert [#18802](https://github.com/apache/druid/pull/18802) * Die Art und Weise, wie Segmentdateien gelöscht werden, wurde verbessert, um zu verhindern, dass Teilsegmentdateien im Falle eines Fehlers während eines Löschvorgangs verbleiben [#18696](https://github.com/apache/druid/pull/18696) * Verbesserte Komprimierung, sodass mehrwertige Dimensionen für Dimensionsschemata identifiziert werden, die sie erzeugen können [#18760](https://github.com/apache/druid/pull/18760) * Verbesserte Zuverlässigkeit beim Ziehen von Segmenten [#18821](https://github.com/apache/druid/pull/18821) ### Metriken und Überwachung #### Aufgabenmetriken Alle Aufgabenmetriken geben jetzt die folgenden Dimensionen aus: `taskId`, `dataSource`, `taskType`, `groupId` und `id`. Beachten Sie, dass `id` aus Gründen der Abwärtskompatibilität ausgegeben wird. Es wird in einer zukünftigen Version zugunsten der Dimension `taskId` entfernt. [#18876](https://github.com/apache/druid/pull/18876) #### Aufnahmemetriken Die folgenden Metriken für Streaming- und Batch-Aufgaben geben jetzt die tatsächlichen Werte anstelle von 0 aus: `ingest/merge/time`, `ingest/merge/cpu` und `ingest/persists/cpu`. [#18866](https://github.com/apache/druid/pull/18866) ##### `statsd`-Metriken Die folgenden Metriken wurden zur Standardliste für `statsd` hinzugefügt: * `task/action/run/time` * `task/status/queue/count` * `task/status/updated/count` * `ingest/handoff/time` [#18846](https://github.com/apache/druid/pull/18846) #### Weitere Metriken und Überwachungsverbesserungen * Dimension `reason` zur Metrik `ingest/events/thrownAway` hinzugefügt. Dies ermöglicht eine bessere Beobachtung, warum bestimmte Ereignisse logisch von der Aufnahme ausgeschlossen werden [#188855](https://github.com/apache/druid/pull/18855) * Für alle Handler einer Phase wurde eine Protokollierung hinzugefügt, bevor sie starten oder stoppen, was Ihnen helfen kann, die Ausführungsreihenfolge zu verstehen [#18662](https://github.com/apache/druid/pull/18662) * Neue Jetty-Thread-Pool-Metriken hinzugefügt, um Thread-Statistiken zur Anforderungsbearbeitung zu erfassen: `jetty/threadPool/utilized`, `jetty/threadPool/ready` und `jetty/threadPool/utilizationRate` [#18883](https://github.com/apache/druid/pull/18883) * Dimensionen `tier` und `priority` zur Metrik `segments/max` hinzugefügt [#18890](https://github.com/apache/druid/pull/18890) * `GroupByStatsMonitor` hinzugefügt, das die Dimensionen `dataSource` und `taskId` für auf Peons ausgegebene Metriken enthält [#18711](https://github.com/apache/druid/pull/18711) * `task/waiting/time`-Metrik hinzugefügt, die die Zeit misst, die es dauert, bis eine Aufgabe zum Planen und Ausführen auf dem Task-Runner platziert wird [#18735](https://github.com/apache/druid/pull/18735) * `supervisorId` zu Streaming-Aufgabenmetriken hinzugefügt, um Situationen zu klären, in denen mehrere Vorgesetzte Daten in eine einzige Datenquelle aufnehmen [#18803](https://github.com/apache/druid/pull/18803) * `StorageMonitor` zu `druid.monitoring.monitors` hinzugefügt, um Speicher- und virtuelle Speichernutzung nach Segment-Cache zu messen [#18742](https://github.com/apache/druid/pull/18742) * Druid protokolliert jetzt Folgendes: * Gesamtzahl der gesammelten Bytes, wenn das maximale Scatter-Gather-Byte-Limit erreicht ist [#18841](https://github.com/apache/druid/pull/18841) * `query/bytes`-Metrik auch für fehlgeschlagene Anfragen [#18842](https://github.com/apache/druid/pull/18842) * Das Prometheus-Emitter-TTL-Tracking wurde geändert, um alle Label-Wert-Kombinationen und nicht nur den Metriknamen zu berücksichtigen. Etiketten werden nicht verfolgt, wenn die TTL nicht festgelegt ist [#18718](https://github.com/apache/druid/pull/18718) [#18689](https://github.com/apache/druid/pull/18689) * Der Lebenszyklus `stop()` wurde so geändert, dass er auf der Ebene `info` protokolliert wird, damit er mit `start()` übereinstimmt [#18640](https://github.com/apache/druid/pull/18640) * Der Auslöser für die Ausgabe von Metriken wurde geändert, sodass Metriken jedes Mal ausgegeben werden, wenn eine Aufgabe abgeschlossen wird [#18766](https://github.com/apache/druid/pull/18766) * Der Metrik-Emitter wurde verbessert, sodass er Metriken für alle Aufgabenabschlüsse ausgibt [#18766](https://github.com/apache/druid/pull/18766) ### Erweiterungen #### SpectatorHistogram-Erweiterung * SQL-Funktionen `SPECTATOR_COUNT` und `SPECTATOR_PERCENTILE` hinzugefügt [#18885](https://github.com/apache/druid/pull/18885) * Die Leistung der SpectatorHistogram-Erweiterung wurde durch Vektorisierung verbessert [#18813](https://github.com/apache/druid/pull/18813) ## Upgrade-Hinweise und inkompatible Änderungen ### Upgrade-Hinweise #### MSQ-Controller-Aufgaben Beim Upgrade von Druid 30 oder früher können MSQ `query_controller`-Aufgaben während eines fortlaufenden Updates aufgrund der Hinzufügung neuer Zähler fehlschlagen, die nicht abwärtskompatibel mit diesen älteren Versionen sind. Sie können entweder alle fehlgeschlagenen Abfragen nach Abschluss der Aktualisierung erneut versuchen. Oder Sie können `includeAllCounters` im Abfragekontext für alle MSQ-Jobs, die während der fortlaufenden Aktualisierung ausgeführt werden müssen, auf `false` festlegen. Alternativ können Sie zuerst auf Druid 31–35 upgraden, bevor Sie auf Druid 36 upgraden. [#18761](https://github.com/apache/druid/pull/18761) #### Segmentformat Druid 36.0.0 unterstützt die Segmentformatversion 10. Frühere Versionen von Druid unterstützen Version 10 nicht. Wenn Sie ein Downgrade durchführen, müssen Sie Ihre Daten mit einer unterstützten Segmentformatversion neu indizieren. [#18880](https://github.com/apache/druid/pull/18880) #### Veraltete Metriken Monitore auf Peons, die zuvor die Dimension `id` von `JettyMonitor`, `OshiSysMonitor`, `JvmMonitor`, `JvmCpuMonitor`, `JvmThreadsMonitor` und `SysMonitor` ausgegeben haben, um die Aufgaben-ID darzustellen, sind veraltet und werden in einer zukünftigen Version entfernt. Verwenden Sie stattdessen die Dimension `taskId`. [#18709](https://github.com/apache/druid/pull/18709) #### Metriken entfernt Die folgenden veralteten Metriken wurden entfernt: * `segment/cost/raw` [#18846](https://github.com/apache/druid/pull/18846) * `segment/cost/normalized` [#18846](https://github.com/apache/druid/pull/18846) * `segment/cost/normalization` [#18846](https://github.com/apache/druid/pull/18846) * `task/action/log/time` [#18649](https://github.com/apache/druid/pull/18649) ### Entwicklerhinweise #### Dateischnittstellen segmentieren Die neuen Schnittstellen `SegmentFileBuilder` und `SegmentFileMapper` wurden definiert, um die direkte Verwendung von `FileSmoosher` und `SmooshedFileMapper` zu ersetzen und den Segmenterstellungs- und Leseprozess zu abstrahieren. Die wichtigsten für Entwickler sichtbaren Änderungen für Erweiterungsautoren mit benutzerdefinierten Spaltenimplementierungen bestehen darin, dass die `Serializer`-Schnittstelle die `writeTo`-Methode geändert hat: * Es wird jetzt ein `SegmentFileBuilder` anstelle eines `FileSmoosher` akzeptiert * Die `ColumnBuilder`-Methode `getFileMapper` gibt jetzt einen `SegmentFileMapper` anstelle von `SmooshedFileMapper` zurück. Erweiterungen, die keine benutzerdefinierten Spaltenimplementierungen bereitstellen, sollten von diesen Änderungen nicht betroffen sein. [#18608](https://github.com/apache/druid/pull/18608) #### Weitere Entwicklerverbesserungen * Es wurde die Möglichkeit hinzugefügt, das Standard-Kafka-Image zum Testen zu überschreiben [#18739](https://github.com/apache/druid/pull/18739) * `fastDecompressor` in `safeDecompressor` geändert [#18930](https://github.com/apache/druid/pull/18930) * Erweiterungen können jetzt Abfragekit-Implementierungen bereitstellen [#18875](https://github.com/apache/druid/pull/18875) * Versionsüberschreibungen in einzelnen `pom`-Dateien entfernt. Eine vollständige Liste finden Sie im Pull-Request [#18708](https://github.com/apache/druid/pull/18708) #### Abhängigkeitsaktualisierungen Die Versionen der folgenden Abhängigkeiten wurden geändert: * `org.apache.logging.log4j:log4j-core` von `2.22.1` zu `2.25.3` [#18874](https://github.com/apache/druid/pull/18874) * `org.mozilla:rhino` von `1.7.14` zu `1.7.14.1` [#18868](https://github.com/apache/druid/pull/18868) * `net.java.dev.jna`- und `net.java.dev.jna`-Versionen von `5.13.0` bis `5.18.1` für Oshi-Monitor [#18848](https://github.com/apache/druid/pull/18848) * `com.github.oshi:oshi-core from` von `6.4.4` zu `6.9.1` [#18839](https://github.com/apache/druid/pull/18839) * `bcpkix-jdk18on` von `1.78.1` zu `1.79` [#18834](https://github.com/apache/druid/pull/18834) * `org.eclipse.jetty` von `12.0.25`bis `12.0.30` [#18773](https://github.com/apache/druid/pull/18773) * `hamcrest` von `1.3` zu `2.2` [#18708](https://github.com/apache/druid/pull/18708) * `org.apache.commons:commons-lang3` von `3.18.0` zu `3.19.0` [#18695](https://github.com/apache/druid/pull/18695) * `org.apache.maven.plugins:maven-shade-plugin` von `3.5.0` bis `3.6.1` * `com.netflix.spectator` von `1.7.0` zu `1.9.0` [#18887](https://github.com/apache/druid/pull/18887) * `org.bouncycastle:bcpkix-jdk18on` von `1.79` auf `1.81`, um `SONATYPE-2025-001911` aufzulösen # Credits @317brian @abhishekrb19 @AdheipSingh @aho135 @Akshat-Jain @amaechler @ashwintumma23 @capistrant @cecemei @clintropolis @cryptoe @dependabot[bot] @EdwinIngJ @Fly-Style @GabrielCWT @gargvishesh @gianm @GWphua @hfukada @inponomarev @jtuglu1 @keoliva @kfaraz @kgyrtkirk @Pankaj260100 @Rasnar @rohangarg @Shiyang-Zhao @TessaIO @tinnou @uds5501 @vogievetsky @vtlim @writer-jill --- > **Quelle** [Apache/Druid](https://github.com/apache/druid) · `druid-36.0.0` · 09.02.2026 · [Upstream-Version](https://github.com/apache/druid/releases/tag/druid-36.0.0) *Zum Indexieren wörtlich gespiegelt.
