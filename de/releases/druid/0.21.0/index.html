Druide Druide-0.21.0

Apache Druid 0.21.0 enthält rund 120 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 36 Mitwirkenden. Weitere Einzelheiten finden Sie in der vollständigen Liste der Änderungen und allem, was mit dem Meilenstein markiert ist.

<a name="21-new-features" href="#21-new-features">#</a> Neue Funktionen

<a name="21-operation" href="#21-operation">#</a> Vorgang

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Diensterkennung und Leiterwahl basierend auf Kubernetes

Die neue Kubernetes-Erweiterung unterstützt die Serviceerkennung und Leiterwahl basierend auf Kubernetes. Diese Erweiterung funktioniert in Verbindung mit der HTTP-basierten Serveransicht (druid.serverview.type=http) und der Aufgabenverwaltung (druid.indexer.runner.type=httpRemote), um Ihnen die Ausführung eines Druid-Clusters ohne ZooKeeper-Abhängigkeiten zu ermöglichen. Diese Erweiterung ist noch experimentell. Weitere Einzelheiten finden Sie unter Kubernetes-Erweiterung. https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> Neue dynamische Koordinatorkonfiguration, um die Anzahl der Segmente zu begrenzen, wenn ein Kandidatensegment für den Segmentausgleich gefunden wird

Sie können percentOfSegmentsToConsiderPerMove so einstellen, dass die Anzahl der Segmente begrenzt wird, die bei der Auswahl eines Kandidatensegments zum Verschieben berücksichtigt werden. Die Kandidaten werden bis zu maxSegmentsToMove * 2-Zeiten gesucht. Diese neue Konfiguration verhindert, dass Druid alle verfügbaren Segmente durchläuft, um den Segmentausgleichsprozess zu beschleunigen, insbesondere wenn Ihr Cluster über viele verfügbare Segmente verfügt. Weitere Einzelheiten finden Sie unter Dynamische Konfiguration des Koordinators. https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> status- und selfDiscovered-Endpunkte für Indexer

Der Indexer unterstützt jetzt die Endpunkte status und selfDiscovered. Weitere Informationen finden Sie unter Prozessorinformationen APIs. https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Abfragen

<a name="21-grouping-function" href="#21-grouping-function">#</a> Neue grouping-Aggregatorfunktion

Sie können die neue Aggregator-SQL-Funktion grouping mit GROUPING SETS oder CUBE verwenden, um anzugeben, welche Gruppierungsdimensionen im aktuellen Gruppierungssatz enthalten sind. Weitere Einzelheiten finden Sie unter Aggregationsfunktionen. https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Verbesserte Behandlung fehlender Argumente in Ausdrücken und Funktionen

Die Ausdrucksverarbeitung kann jetzt vektorisiert werden, wenn Eingaben fehlen. Zum Beispiel eine nicht vorhandene Spalte. Wenn in einem Ausdruck ein Argument fehlt, kann Druid jetzt anhand von Nicht-Null-Argumenten auf den richtigen Ergebnistyp schließen. Beispielsweise wird für longColumn + nonExistentColumn nonExistentColumn als (long) 0 und nicht als (double) 0.0 behandelt. Schließlich können mathematische Funktionen im standardmäßigen Nullverarbeitungsmodus eine ordnungsgemäße Ausgabe erzeugen, indem sie fehlende Argumente als Nullen behandeln. https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> Nullpunkt für TIMESTAMPADD zulassen

Die Funktion TIMESTAMPADD ermöglicht jetzt eine Nullperiode. Diese Funktionalität ist für einige BI-Tools wie Tableau erforderlich. https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Einnahme

<a name="21-parallel-ingestion-without-intervals" href="#21-parallel-ingestion-without-intervals">#</a> Für die native parallele Aufnahme sind keine expliziten Intervalle mehr erforderlich

Für parallele Aufgaben müssen Sie in granularitySpec keine expliziten Intervalle mehr festlegen. Wenn Intervalle fehlen, führt die parallele Aufgabe einen zusätzlichen Schritt zur Eingabestichprobe aus, der die zu indizierenden Intervalle sammelt. https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Unterstützung der alten Kafka-Version

Druid unterstützt jetzt Apache Kafka älter als 0.11. Um aus einer alten Version von Kafka zu lesen, setzen Sie isolation.level in consumerProperties auf read_uncommitted. Bis zu dieser Version wurden nur 0.10.2.1 getestet. Weitere Informationen finden Sie unter Kafka-Supervisor-Konfigurationen. https://github.com/apache/druid/pull/10551

Mehrphasige Segmentzusammenführung für native Batch-Aufnahme

Eine neue tuningConfig, maxColumnsToMerge, steuert, wie viele Segmente gleichzeitig in der Aufgabe zusammengeführt werden können. Diese Konfiguration kann nützlich sein, um einen hohen Speicherdruck während der Zusammenführung zu vermeiden. Weitere Details finden Sie unter tuningConfig für native Batch-Aufnahme. https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> Die native erneute Aufnahme ist weniger speicherintensiv

Parallele Aufgaben sortieren Segmente jetzt nach ID, bevor sie Unteraufgaben zugewiesen werden. Diese Sortierung minimiert die Anzahl der Zeitblöcke, die jede Unteraufgabe bearbeiten muss. Infolgedessen wird erwartet, dass jede Unteraufgabe weniger Speicher verbraucht, insbesondere wenn eine einzelne parallele Aufgabe ausgegeben wird, um Segmente über einen längeren Zeitraum erneut aufzunehmen. https://github.com/apache/druid/pull/10646

<a name="21-web-console" href="#21-web-console">#</a> Webkonsole

<a name="21-refresh-console-style" href="#21-refresh-console-style">#</a> Aktualisierte und verbesserte Webkonsolenstile

Die neuen Webkonsolenstile nutzen die Farben der Marke Druid besser aus und standardisieren durchgehend Abstände und Ränder. Die Symbol- und Hintergrundfarben sind jetzt vom Druid-Logo abgeleitet. https://github.com/apache/druid/pull/10515

<a name="21-web-console-partitioning" href="#21-web-console-partitioning">#</a> Partitionierungsinformationen sind in der Webkonsole verfügbar

Die Webkonsole zeigt jetzt Datenquellenpartitionierungsinformationen für die neuen Spalten Segment granularity und Partitioning an.

Segment granularity-Spalte auf der Registerkarte Datasources

Spalte Partitioning auf der Registerkarte Segments

https://github.com/apache/druid/pull/10533

<a name="21-web-console-dim-ordering" href="#21-web-console-dim-ordering">#</a> Die Spaltenreihenfolge in der Tabelle Schema entspricht der dimensionsSpec

Die Tabelle Schema spiegelt nun die Dimensionsreihenfolge in dimensionsSpec wider. https://github.com/apache/druid/pull/10588

<a name="21-metrics" href="#21-metrics">#</a> Metriken

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Laufzeitmetriken für den Koordinatordienst

Der Koordinator nimmt mehrere Pflichtaufgaben wahr. Zum Beispiel Segmentausgleich, Laden neuer Segmente usw. Jetzt gibt es zwei neue Metriken, mit denen Sie analysieren können, wie schnell der Koordinator diese Aufgaben ausführt.

  • coordinator/time: die Zeit, die eine einzelne Pflicht zur Ausführung benötigt
  • coordinator/global/time: die Zeit, die für die Ausführung der gesamten ausführbaren Aufgaben benötigt wird https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Abfrage-Timeout-Metrik

Eine neue Metrik liefert die Anzahl der Abfragen mit Zeitüberschreitung. Zuvor abgelaufene Abfragen wurden als unterbrochen behandelt und in den query/interrupted/count aufgenommen (weitere Einzelheiten finden Sie unter Geänderte HTTP-Statuscodes für Abfragefehler. query/timeout/count: Die Anzahl der Abfragen mit Zeitüberschreitung während des Emissionszeitraums https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Shuffle-Metriken für die Batch-Aufnahme

Zwei neue Metriken stellen Shuffle-Statistiken für MiddleManager und Indexer bereit. Diese Metriken haben die Dimension supervisorTaskId.

  • ingest/shuffle/bytes: Anzahl der pro Emissionsperiode gemischten Bytes
  • ingest/shuffle/requests: Anzahl der Shuffle-Anfragen pro Emissionszeitraum Um die Shuffle-Metriken zu aktivieren, fügen Sie org.apache.druid.indexing.worker.shuffle.ShuffleMonitor in druid.monitoring.monitors hinzu. Weitere Einzelheiten finden Sie unter Shuffle-Metriken. https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> Neuer zeitabweichungssicherer Überwachungsplaner für Metriken

Der standardmäßige Metrikmonitor-Scheduler wird auf Basis von ScheduledThreadPoolExecutor implementiert, das anfällig für unbegrenzte Uhrabweichung ist. Ein neuer Monitor-Scheduler, ClockDriftSafeMonitorScheduler, überwindet diese Einschränkung. Um den neuen Scheduler zu verwenden, setzen Sie druid.monitoring.schedulerClassName in der Datei runtime.properties auf org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler. https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-others" href="#21-others">#</a> Andere

<a name="21-rds-password-provider" href="#21-rds-password-provider">#</a> Neue Erweiterung für einen Passwortanbieter basierend auf AWS RDS-Token

Ein neuer PasswordProvider-Typ ermöglicht den Zugriff auf AWS RDS-DB-Instances mithilfe temporärer AWS-Tokens. Diese Erweiterung kann nützlich sein, wenn ein RDS als Metadatenspeicher von Druid verwendet wird. Weitere Informationen finden Sie unter AWS RDS-Erweiterung. https://github.com/apache/druid/pull/9518

<a name="21-system-table-leader" href="#21-system-table-leader">#</a> Die Tabelle sys.servers zeigt Anführer

Eine neue langtypisierte Spalte is_leader in der Tabelle sys.servers gibt an, ob der Server der Anführer ist oder nicht. https://github.com/apache/druid/pull/10680

<a name="21-https-influxdb" href="#21-https-influxdb">#</a> Die Erweiterung druid-influxdb-emitter unterstützt das HTTPS-Protokoll

Neue Konfigurationen finden Sie unter Influxdb-Emitter-Erweiterung. https://github.com/apache/druid/pull/9938

<a name="21-docker" href="#21-docker">#</a> Docker

<a name="21-small-docker" href="#21-small-docker">#</a> Kleines docker-Bild

Die Bildgröße des docker wird durch die Eliminierung unnötiger Duplikate um die Hälfte reduziert. https://github.com/apache/druid/pull/10506

<a name="21-development" href="#21-development">#</a> Entwicklung

<a name="21-dynamic-config-provider" href="#21-dynamic-config-provider">#</a> Erweiterbare Kafka-Consumer-Eigenschaften über ein neues DynamicConfigProvider

Eine neue Klasse DynamicConfigProvider ermöglicht das Abrufen von Verbrauchereigenschaften zur Laufzeit. Sie können beispielsweise DynamicConfigProvider verwenden, um bootstrap.servers von einem Speicherort wie einer lokalen Umgebungsvariablen abzurufen, wenn diese nicht statisch ist. Derzeit wird standardmäßig nur ein kartenbasierter Konfigurationsanbieter unterstützt. Informationen zum Implementieren eines benutzerdefinierten Konfigurationsanbieters finden Sie unter DynamicConfigProvider. https://github.com/apache/druid/pull/10309

<a name="21-bug-fixes" href="#21-bug-fixes">#</a> Fehlerbehebungen

Druid 0.21.0 enthält 30 Fehlerbehebungen, die vollständige Liste finden Sie hier (https://github.com/apache/druid/pulls?q=is%3Apr+milestone%3A0.21.0+is%3Aclosed+label%3ABug+).

<a name="21-post-agg-subtotal" href="#21-post-agg-subtotal">#</a> Post-Aggregator-Berechnung mit Zwischensummen

Vor 0.21.0 schlägt die Abfrage mit einem Fehler fehl, wenn Sie Post-Aggregatoren mit Zwischensummen verwenden. Jetzt ist dieser Fehler behoben und Sie können Post-Aggregatoren mit Zwischensummen verwenden. https://github.com/apache/druid/pull/10653

<a name="21-indexer-announce" href="#21-indexer-announce">#</a> Indexer melden sich selbst als Segmentserver

In 0.19.0 und 0.20.0 konnten Indexer keine Abfragen für Streaming-Daten verarbeiten, da sie sich nicht als Segmentserver bekannt gaben. Es wurde ein Fehler behoben, bei dem sie sich in 0.21.0 ordnungsgemäß ankündigen. https://github.com/apache/druid/pull/10631

<a name="21-historical-segment-loading" href="#21-historical-segment-loading">#</a> Gültigkeitsprüfung für Segmentdateien in historischen Dateien

Historicals führen jetzt eine Gültigkeitsprüfung durch, nachdem sie Segmentdateien heruntergeladen haben, und laden sie automatisch erneut herunter, wenn diese Dateien abstürzen. https://github.com/apache/druid/pull/10650

<a name="21-storage-location-selector" href="#21-storage-location-selector">#</a> StorageLocationSelectorStrategy-Injektionsfehler wurde behoben

Der Injektionsfehler beim Lesen der Konfigurationen von StorageLocationSelectorStrategy wurde behoben. https://github.com/apache/druid/pull/10363

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> Upgrade auf 0.21.0

Berücksichtigen Sie beim Upgrade von Druid 0.20.0 auf 0.21.0 die folgenden Änderungen und Aktualisierungen. Wenn Sie von einer früheren Version als 0.20.0 aktualisieren, sehen Sie sich die release notes der relevanten Zwischenversionen an.

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Verbesserte HTTP-Statuscodes für Abfragefehler

Vor dieser Version gab Druid für die meisten Abfragefehler den „internen Fehler (500)“ zurück. Jetzt gibt Druid je nach Ursache unterschiedliche Fehlercodes zurück. In der folgenden Tabelle sind die Fehler und die entsprechenden geänderten Codes aufgeführt: Ausnahme | Beschreibung| Alter Code | Neuer Code ------------ | ------------- | ------------- | ------------- SqlParseException und ValidationException von Calcite | Abfrageplanung fehlgeschlagen | 500 | 400 QueryTimeoutException | Die Ausführung der Abfrage wurde nicht innerhalb der Zeitüberschreitung abgeschlossen | 500 | 504 ResourceLimitExceededException | Die Abfrage hat mehr Ressourcen als den konfigurierten Schwellenwert angefordert | 500 | 400 InsufficientResourceException | Die Abfrage konnte nicht geplant werden, da zum Zeitpunkt der Übermittlung keine Zusammenführungspuffer verfügbar waren | 500 | 429, zusammengeführt mit QueryCapacityExceededException QueryUnsupportedException | Nicht unterstützte Funktionalität | 400 | 501 Es gibt außerdem eine neue Abfragemetrik für Abfrage-Timeout-Fehler. Weitere Einzelheiten finden Sie unter Neue Abfrage-Timeout-Metrik. https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Abfrage unterbrochener Metrik

query/interrupted/count zählt nicht mehr die Abfragen, bei denen eine Zeitüberschreitung aufgetreten ist. Diese Abfragen werden von query/timeout/count gezählt.

<a name="21-context-dimension" href="#21-context-dimension">#</a> context Dimension in Abfragemetriken

context ist jetzt eine Standarddimension, die für alle Abfragemetriken ausgegeben wird. context ist eine JSON-formatierte Zeichenfolge, die den Abfragekontext für die Abfrage enthält, auf die sich die ausgegebene Metrik bezieht. Durch das Hinzufügen einer Dimension, die zuvor nicht vorhanden war, werden einige von Druid ausgegebene Metriken geändert. Sie sollten planen, diese neue context-Dimension in Ihrer Metrik-Pipeline zu verarbeiten. Da es sich bei der Dimension um eine Zeichenfolge im JSON-Format handelt, besteht eine gängige Lösung darin, die Dimension zu analysieren und entweder zu reduzieren oder die gewünschten Bits zu extrahieren und den vollständigen Zeichenfolgen-BLOB im JSON-Format zu verwerfen. https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Veraltete Unterstützung für Apache ZooKeeper 3.4

Da ZooKeeper 3.4 schon seit einiger Zeit nicht mehr verfügbar ist, ist die Unterstützung für ZooKeeper 3.4 in 0.21.0 veraltet und wird in naher Zukunft entfernt. https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Konsistentes Serialisierungsformat und Spaltenbenennungskonvention für die sys.segments-Tabelle

Alle Spalten in der Tabelle sys.segments sind jetzt im JSON-Format serialisiert, um sie mit anderen Systemtabellen konsistent zu machen. Für Spaltennamen gilt jetzt die gleiche „Snake Case“-Konvention. https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Bekannte Probleme

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Bekannte Sicherheitslücke in der Thrift-Bibliothek

Die Thrift-Erweiterung kann für die Aufnahme von Dateien des Thrift-Formats in Druid nützlich sein. Es gibt jedoch eine [bekannte Sicherheitslücke] (https://nvd.nist.gov/vuln/detail/CVE-2020-13949) in der von Druid verwendeten Version der Thrift-Bibliothek. Die Sicherheitslücke kann ausgenutzt werden, indem bei Verwendung von Indexern in böswilliger Absicht erstellte Thrift-Dateien aufgenommen werden. Wir empfehlen, die DATASOURCE WRITE-Berechtigung nur trusted-Benutzern zu erteilen.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Berechtigungsprobleme beim Ausführen des docker-basierten Druid-Clusters

Wenn Sie den Druid docker-Cluster zum ersten Mal auf Ihrem Computer ausführen, können mithilfe des 0.21.0-Images interne Verzeichnisse mit dem Root-Konto erstellt werden. Infolgedessen können Druid-Dienste aufgrund fehlender Berechtigungen scheitern. Dieses Problem ist in https://github.com/apache/druid/issues/11166. abgelegt Wenn Sie docker Compose verwenden, können Sie dieses Problem mit den folgenden Befehlen umgehen. Diese Befehle erstellen zunächst interne Verzeichnisse mit einem alten Image und starten dann Dienste mit dem 0.21.0-Image.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

Wenn Sie docker Compose nicht verwenden, können Sie den Volume-Parameter für /opt/druid/var direkt übergeben, wenn Sie Dienste mit dem 0.21.0-Image starten. Sie können beispielsweise den folgenden Befehl ausführen, um den Koordinatordienst zu starten.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

Eine vollständige Liste der offenen Probleme finden Sie unter https://github.com/apache/druid/labels/Bug.
