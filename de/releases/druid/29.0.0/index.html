Druide Druide-29.0.0

Apache Druid 29.0.0 enthält über 350 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 67 Mitwirkenden.

Weitere Details, einschließlich Fehlerbehebungen, finden Sie im vollständigen Änderungssatz.

Lesen Sie die Upgrade-Hinweise, bevor Sie ein Upgrade auf Druid 29.0.0 durchführen. Wenn Sie ein Upgrade über mehrere Versionen durchführen, sehen Sie sich die Seite [Upgrade-Hinweise] (upgrade-notes.md) an, auf der Upgrade-Hinweise für die neuesten Druid-Versionen aufgeführt sind.

Druid 29.0.0 fügt der MSQ-Task-Engine experimentelle Unterstützung für Exportanweisungen hinzu. Dadurch können Abfrageaufgaben Daten über die EXTERN-Funktion an ein externes Ziel schreiben.

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT und UNPIVOT (experimentell)

Druid 29.0.0 fügt experimentelle Unterstützung für die SQL-Operatoren PIVOT und UNPIVOT hinzu.

Der PIVOT-Operator führt eine Aggregation durch und wandelt in der Ausgabe Zeilen in Spalten um. Im Folgenden finden Sie die allgemeine Syntax für den PIVOT-Operator:

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

Der UNPIVOT-Operator wandelt vorhandene Spaltenwerte in Zeilen um. Im Folgenden finden Sie die allgemeine Syntax für den UNPIVOT-Operator:

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> Bereichsunterstützung in Fensterfunktionen (experimentell)

Fensterfunktionen (experimentell) unterstützen jetzt Bereiche, in denen beide Endpunkte unbegrenzt sind oder die aktuelle Zeile darstellen. Bereiche funktionieren im strikten Modus, was bedeutet, dass Druid Abfragen, die nicht unterstützt werden, fehlschlägt. Sie können den strikten Modus für Bereiche deaktivieren, indem Sie den Kontextparameter windowingStrictValidation auf false setzen.

Das folgende Beispiel zeigt einen Fensterausdruck mit RANGE-Frame-Spezifikationen:

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

#15703 #15746

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-improved-inner-joins" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-improved-inner-joins">#</a> Verbesserte INNER-Joins

Druid unterstützt jetzt beliebige Join-Bedingungen für den INNER-Join. Alle Unterbedingungen, die im Rahmen des Joins nicht ausgewertet werden können, werden in einen Post-Join-Filter konvertiert. Dank verbesserter Join-Funktionen kann Druid Anwendungen wie Tableau effektiver unterstützen.

#15302

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-improved-concurrent-append-and-replace-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-improved-concurrent-append-and-replace-%28experimental%29">#</a> Verbessert gleichzeitiges Anhängen und Ersetzen (experimentell)

Sie müssen den Task-Sperrtyp für gleichzeitiges Anhängen und Ersetzen (experimentell) nicht mehr manuell mit dem Task-Kontext taskLockType bestimmen. Stattdessen kann Druid es jetzt automatisch für Sie ermitteln. Sie können den Kontextparameter "useConcurrentLocks": true für einzelne Aufgaben und Datenquellen verwenden oder mit druid.indexer.task.default.context das gleichzeitige Anhängen und Ersetzen auf Clusterebene aktivieren.

#15684

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-first-and-last-aggregators-for-double%2C-float%2C-and-long-data-types" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-first-and-last-aggregators-for-double%2C-float%2C-and-long-data-types">#</a> Erster und letzter Aggregator für Double-, Float- und Long-Datentypen

Druid unterstützt jetzt erste und letzte Aggregatoren für die Typen double, float und long in nativen und MSQ-Aufnahmespezifikationen und MSQ-Abfragen. Bisher wurden sie nur für native Abfragen unterstützt. Weitere Informationen finden Sie unter Erster und letzter Aggregator.

#14462

  • EARLIEST und EARLIEST_BY
  • LATEST und LATEST_BY

Sie können diese Funktionen zum Zeitpunkt der Aufnahme als Aggregatoren verwenden.

#15607

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-support-for-logging-audit-events" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-support-for-logging-audit-events">#</a> Unterstützung für die Protokollierung von Audit-Ereignissen

Unterstützung für die Protokollierung von Prüfereignissen und verbesserte Abdeckung der geprüften REST API-Endpunkte hinzugefügt. Um die Protokollierung von Überwachungsereignissen zu aktivieren, legen Sie die Konfiguration druid.audit.manager.type sowohl im Coordinator als auch im Overlord oder in common.runtime.properties auf log fest. Wenn Sie druid.audit.manager.type auf sql festlegen, werden Überwachungsereignisse im Metadatenspeicher gespeichert.

In beiden Fällen prüft Druid die folgenden Ereignisse:

  • Koordinator
    • Laderegeln aktualisieren
    • Suchvorgänge aktualisieren
    • Dynamische Konfiguration des Koordinators aktualisieren
    • Automatische Komprimierungskonfiguration aktualisieren
  • Oberherr
    • Senden Sie eine Aufgabe
    • Erstellen/aktualisieren Sie einen Vorgesetzten
    • Worker-Konfiguration aktualisieren
  • Grundlegende Sicherheitserweiterung
    • Benutzer erstellen
    • Benutzer löschen
    • Benutzeranmeldeinformationen aktualisieren
    • Rolle erstellen
    • Rolle löschen
    • Weisen Sie dem Benutzer eine Rolle zu
    • Rollenberechtigungen festlegen

Sofern nicht ausdrücklich angegeben, überspringt Druid Wochengranularitätssegmente für die Datenpartitionierung, da diese Segmente nicht am Monatsende oder an gröberen Intervallen ausgerichtet sind.

#15589

Mit dem Spaltenindexer auto erfasste Spalten, die nur leere oder Null enthaltende Arrays enthalten, werden jetzt als ARRAY<LONG> statt als COMPLEX<json> gespeichert.

#15505

<a name="29.0.0-functional-area-and-related-changes-general-ingestion-enabled-skipping-compaction-for-datasources-with-partial-eternity-segments" href="#29.0.0-functional-area-and-related-changes-general-ingestion-enabled-skipping-compaction-for-datasources-with-partial-eternity-segments">#</a> Das Überspringen der Komprimierung für Datenquellen mit Teil-Ewigkeitssegmenten wurde aktiviert

Druid überspringt jetzt die Komprimierung für Datenquellen mit Segmenten, deren Intervallanfang oder -ende mit den Endpunkten des Eternity-Intervalls übereinstimmt.

#15542

<a name="29.0.0-functional-area-and-related-changes-general-ingestion-kill-task-improvements" href="#29.0.0-functional-area-and-related-changes-general-ingestion-kill-task-improvements">#</a> Verbesserungen bei Kill-Aufgaben

Verbesserte Kill-Aufgaben wie folgt:

  • Es wurde ein Problem behoben, bei dem die Auto-Kill-Funktion die angegebene Pufferzeit nicht einhalten konnte. Dies trat auf, wenn mehrere ungenutzte Segmente innerhalb eines Intervalls zu unterschiedlichen Zeiten als ungenutzt markiert wurden.
  • Sie können Kill-Aufgaben mit einem optionalen Parameter maxUsedStatusLastUpdatedTime senden. Bei Festlegung auf ein Datum und eine Uhrzeit berücksichtigt der Kill-Task Segmente im angegebenen Intervall, die spätestens zu diesem Zeitpunkt als ungenutzt markiert sind. Das Standardverhalten besteht darin, alle nicht verwendeten Segmente im Intervall zu löschen, unabhängig von der Zeit, zu der Segmente als nicht verwendet markiert wurden.

#15710

Der EXTEND-Operator unterstützt jetzt die folgenden Array-Typen: VARCHAR ARRAY, BIGINT ARRAY, FLOAT ARRAY und DOUBLE ARRAY.

Das folgende Beispiel zeigt eine externe Eingabe mit den nativen Druid-Eingabetypen ARRAY<STRING>, ARRAY<LONG> und STRING:

#15458

<a name="29.0.0-functional-area-and-related-changes-sql-based-ingestion-improved-tombstone-generation-to-honor-granularity-specified-in-a-%60replace%60-query" href="#29.0.0-functional-area-and-related-changes-sql-based-ingestion-improved-tombstone-generation-to-honor-granularity-specified-in-a-%60replace%60-query">#</a> Verbesserte Tombstone-Generierung, um die in einer REPLACE-Abfrage angegebene Granularität zu berücksichtigen

MSQ REPLACE-Abfragen generieren jetzt Tombstone-Segmente, die die in der Abfrage angegebene Segmentgranularität berücksichtigen, anstatt unregelmäßige Tombstones zu generieren. #15243

Verbesserte Konsistenz des JOIN-Verhaltens für Abfragen, die entweder die native oder die MSQ-Task-Engine verwenden, um nur basierend auf Basisspalten (linke Seite) zu bereinigen.

#15299

<a name="29.0.0-upgrade-notes-and-incompatible-changes-developer-notes-improved-%60indimfilter%60-reverse-lookup-optimization" href="#29.0.0-upgrade-notes-and-incompatible-changes-developer-notes-improved-%60indimfilter%60-reverse-lookup-optimization">#</a> Verbesserte InDimFilter Reverse-Lookup-Optimierung

Diese Verbesserung umfasst die folgenden Änderungen:

  • Parameter mayIncludeUnknown zu DimFilter#optimize hinzugefügt.
  • InDimFilter#optimizeLookup wurde aktiviert, um mayIncludeUnknown zu verarbeiten und umgekehrte Suchvorgänge in einem breiteren Spektrum von Fällen durchzuführen.
  • Methode unapply in LookupExtractor geschützt und Aufrufer nach unapplyAll verschoben.

Wenn Ihre Erweiterungen einen DimFilter bereitstellen, müssen Sie sie möglicherweise neu erstellen, um die Kompatibilität mit dieser Version sicherzustellen.
