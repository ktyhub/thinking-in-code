Containerd v2.4.0

Willkommen zur v2.4.0-Version von Containerd!

containerd 2.4 ist eine reguläre (nicht LTS) Version mit einem kürzeren Supportfenster, Gedacht für Benutzer, die neue Funktionen früher übernehmen möchten. Als die Veröffentlichung Nach dem 2.3 LTS ist dies der Punkt im Veröffentlichungszyklus, an dem zuvor Veraltete Funktionen werden möglicherweise entfernt, sodass diese Version möglicherweise Fehler enthält Veränderungen; Überprüfen Sie die Hinweise unten und löschen Sie alle veralteten Warnungen von Ihrem Bitte überprüfen Sie vor dem Upgrade die aktuelle Version.

Benutzer, die Stabilität und einen längeren Support-Lebenszyklus priorisieren, sollten auf dem bleiben 2.3 LTS-Version.

Highlights

Container Runtime Interface (CRI)

  • Mount-Manager für Image-Mounts in CRI aktivieren (#13542)
  • Sandbox-Image und CNI-Verzeichniskonfiguration in CRI-Plugin-Info exportieren (#13940)
  • Standardmäßig runtimeFeatures.UserNamespacesHostNetwork auf true setzen (#13162)
  • Unterstützung der Introspektion von OCI-Laufzeitfunktionen für Nicht-Runc-Laufzeiten (#13504)

Bildverteilung

  • Härtung anwenden, um sensible Authentifizierungsheader beim Abrufen von Deskriptor-URLs zu entfernen (#12889)
  • Unterstützt die Weitergabe von HTTP 299-Warnungsheadern von Registrierungen an den Resolver (#12698)
  • Verwenden Sie klauspost/compress für die Dekomprimierung der GZIP-Ebene (#13560)

Bildspeicherung

  • client-Optionen hinzufügen, um den gesamten Ebeneninhalt beim Entpacken abzurufen, auch wenn Snapshots vorhanden sind (#14126)
  • Medientyp in Inhaltserstellungsereignisse einbeziehen (#13833)
  • Vorwärtsverweise zum GC-Sammlungskontext hinzufügen (#13634)

Knotenressourcenschnittstelle (NRI)

  • Container-Image-Name, Digest und Konfigurations-Digest für NRI-Plugins verfügbar machen (#13960)
  • Veraltungswarnungen für Plugins ausgeben, die veraltete NRI-Schnittstellen verwenden (#13916)

Laufzeit

  • Maskieren Sie /proc/interrupts und die sysfs-Pfade für die thermische Drosselung der CPU in Linux-Containern standardmäßig (#14090)
  • UpdateSandbox RPC hinzufügen, um Sandbox-Controller-Updates an den Shim weiterzugeben (#14105)
  • Vermeiden Sie einen sofortigen Neustart von Containern mit der Richtlinie restart=always, nachdem sie explizit gestoppt wurden (#13993)
  • Tracing-Kontext vom Shim an Runc und Hooks übergeben (#14036)
  • Fehler bei der Benutzer- und Gruppensuche in Container-RootFS behoben, die symbolisch mit /etc/passwd oder /etc/group verknüpft sind (#13818)
  • Implementieren Sie Windows-Named-Pipe-Server- und Protokoll-Streaming-Unterstützung in pkg/shim (#13948)
  • Protokollbereinigung standardmäßig unter Windows aktivieren (#13837)
  • Ermöglicht die Angabe des übergeordneten Prüfpunktverzeichnisses beim Prüfpunktieren mit runc (#13699)

Schnappschüsse

  • Fügen Sie Prometheus-Metriken für den Inhaltscache der EROFS-Snapshotter-Ebene hinzu (#13941)
  • Unterstützt Warmbild-Cache für Erofs Snapshotter (#13813)
  • Maximale Größenbezeichnung für Schnappschüsse hinzufügen (#13520)

Brechen

  • Entfernen Sie veraltete CRI- und Tracing-Konfigurationsoptionen:
    • enable_cdi in der CRI-Laufzeitkonfiguration entfernen (CDI ist jetzt immer aktiviert)
    • Entfernen Sie bin_dir in der CRI-CNI-Konfiguration (verwenden Sie bin_dirs).
    • Entfernen Sie endpoint, protocol und insecure in der Konfiguration des OTLP-Tracing-Prozessors (verwenden Sie standardmäßige OTLP-Umgebungsvariablen).
    • Entfernen Sie service_name und sampling_ratio in der internen Ablaufverfolgungskonfiguration (verwenden Sie Standardumgebungsvariablen OpenTelemetry) (#14166)
  • Wiederherstellung in CreateContainer entfernen (#13871)

Abwertungen

  • Die Shim-Annotation „containerd.io/runtime-allow-mounts“ wird zugunsten der Bootstrap-Erweiterung „MountCapabilities“ verworfen (#14002)
  • Veraltetes shim.Command aus pkg entfernen (#13991)
  • Adress- und Versionsfelder der Aufgabe API in den Runc-Optionen verwerfen und nach CreateTaskRequest verschieben (#13360)

Bitte probieren Sie die Release-Binärdateien aus und melden Sie etwaige Probleme unter https://github.com/containerd/containerd/issues.
