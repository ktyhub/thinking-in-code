open-webui v0.9.6

Hinzugefügt

  • 📦 Offizielles Wissensdatenbank-Synchronisierungstool. Ein neues Begleittool von Open WebUI, oikb, synchronisiert eine Wissensdatenbank mit einem lokalen Verzeichnis, einem GitHub-Repo, einem S3-Bucket, einem Confluence-Space oder einer von mehr als 40 anderen Quellen und lädt mithilfe der in dieser Version hinzugefügten inkrementellen Synchronisierungsunterstützung nur neue und geänderte Dateien hoch. oikb
  • 📂 Intelligente Verzeichnissynchronisierung für Wissensdatenbanken. Lokale Verzeichnisse können jetzt in einer Aktion mit einer Wissensdatenbank synchronisiert werden: Dateiprüfsummen werden mit bereits gespeicherten Daten verglichen und nur hinzugefügte oder geänderte Dateien werden hochgeladen, während entfernte Dateien und verwaiste Unterverzeichnisse bereinigt werden, wobei die Verzeichnisstruktur automatisch gespiegelt wird und der Fortschritt pro Datei durchgehend angezeigt wird. #19190, #19394, Commit, Commit, Commit, Commit, Commit, Commit
  • 🗂️ Wissensdatenbank-Ordner. Dateien in einer Wissensdatenbank können jetzt in verschachtelten Ordnern organisiert werden, mit Breadcrumb-Navigation, die es viel einfacher macht, Inhalte in großen Sammlungen zu verwalten und zu finden. Festschreiben, Festschreiben, Festschreiben, Festschreiben, Festschreiben, Festschreiben
  • 🧰 Dateisystem-Tool für Wissensdatenbanken. Ein neues integriertes Tool, das über die Umgebungsvariable „ENABLE_KB_EXEC“ aktiviert wird, ermöglicht KI-Modellen das Durchsuchen und Durchsuchen von Wissensdatenbankinhalten mithilfe bekannter Dateisystembefehle wie „ls“, „cat“, „grep“, „find“, „head“, „tail“ und „sed“, einschließlich Pipes zwischen ihnen. Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit
  • ✏️ Umbenennen von Dateien in Wissensdatenbanken. Dateien in einer Wissensdatenbank können jetzt direkt aus dem Arbeitsbereich umbenannt werden, wobei der neue Name überall dort angezeigt wird, wo auf die Datei verwiesen wird. Festschreiben
  • 😀 Emoji-Auswahl in der Nachrichteneingabe. Mit einer neuen Emoji-Schaltfläche in der Symbolleiste für die Rich-Text-Formatierung können Sie Emojis durchsuchen und direkt in Ihre Nachrichten einfügen. #24704
  • 🪄 Per-Chat-Fähigkeiten umschaltbar. Fertigkeiten können jetzt für eine Konversation direkt über das Chat-Integrationsmenü aktiviert oder deaktiviert werden, genauso wie Tools und Funktionen bereits funktionieren, anstatt nur über die Modellvoreinstellung. #25036, #25037
  • 🔎 Zugriffsvorschau für Benutzer und Gruppen. Administratoren können jetzt genau in der Vorschau anzeigen, auf welche Modelle, Wissensdatenbanken und Tools ein bestimmter Benutzer oder eine bestimmte Gruppe zugreifen kann, wodurch es einfacher wird, Berechtigungseinstellungen zu prüfen und zu überprüfen. Commit
  • 📄 Konfigurierbare Seitengröße für Wissensdatenbankdateien. Administratoren können jetzt eine größere Seitengröße anfordern, wenn sie die Dateien einer Wissensdatenbank über API auflisten. Dadurch wird die Anzahl der zum Abrufen großer Sammlungen erforderlichen Anforderungen reduziert, anstatt durch feste 30er-Schritte zu blättern. #25148, Commit
  • 🔃 Persistenter Verarbeitungsindikator für Wissensdateien. Dateien, die noch in einer Wissensdatenbank verarbeitet werden, zeigen jetzt beim Neuladen der Seite weiterhin einen Verarbeitungsindikator an, sodass Sie nach dem Weg- und Zurücknavigieren erkennen können, was noch aufgenommen wird. #25031, Commit
  • 📑 MinerU-Dateitypkonfiguration. Administratoren können jetzt über die neue Einstellung „MINERU_FILE_EXTENSIONS“ konfigurieren, welche Dateitypen vom MinerU-Dokumentladeprogramm verarbeitet werden, und erweitern diese über PDF hinaus auf Formate wie DOCX, PPTX und XLSX. Festschreiben
  • 📃 Unterstützung für ältere Word-Dokumente. Der Text älterer „.doc“-Word-Dateien kann jetzt zusätzlich zum modernen „.docx“-Format durch die Standard-Dokumentextraktions-Engine extrahiert werden. Festschreiben
  • 📁 Unterordner aus der Ordnerkopfzeile erstellen. Für Chat-Ordner können jetzt Unterordner direkt aus der Ordnerkopfzeile in der Chat-Ansicht erstellt werden, nicht nur aus der Seitenleiste. Festschreiben
  • ⚡ Schnellere anfängliche Seitenladevorgänge. Der Konfigurationsendpunkt, der bei jedem Seitenbesuch geladen wird, führt keine unnötige Abfrage der Benutzeranzahl mehr durch, wodurch die anfängliche Anwendungslast für die Datenbank geringer wird, insbesondere bei Instanzen mit vielen Benutzern. Commit
  • 🚀 Schnellere, durch Tools aktivierte Chat-Abschlüsse. Chat-Abschlüsse, die mehrere Tools verwenden, starten jetzt schneller, da die Tools, auf die sie verweisen, in einer einzigen Batch-Abfrage aus der Datenbank abgerufen werden, statt einer Abfrage pro Tool. #24808, Commit
  • 🏎️ Reaktionsfähigere Websuche unter Last. Die Websuche über SearXNG, Google PSE, Brave, Serper und Serpstack verwendet jetzt nicht blockierende Netzwerkaufrufe, sodass der Server während einer laufenden Suche auf andere Benutzer reagiert und gleichzeitige Suchvorgänge mit mehreren Abfragen schneller abgeschlossen werden. Festschreiben
  • 🐎 Leichtere Ollama-Backend-Verbindungen. Anfragen an Ollama-Backends verwenden jetzt einen gemeinsamen Verbindungspool wieder, anstatt jedes Mal eine neue Sitzung zu öffnen, wodurch der TCP- und TLS-Handshake-Overhead für Installationen reduziert wird, die Ollama häufig abfragen oder mehrere Backends konfiguriert haben. Festschreiben
  • 💽 Weniger redundante Modelllisten-Schreibvorgänge. Bei Bereitstellungen mit mehreren Instanzen, die von Redis unterstützt werden, wird die Modellliste nicht mehr neu geschrieben, wenn sie sich nicht geändert hat, wodurch eine wichtige Quelle redundanter Schreibvorgänge entfällt. #25469, #25474, Commit
  • 📉 Schnellere Bereinigung der Websocket-Trennung. Das Trennen der Verbindung zu einer kollaborativen Sitzung löst nicht mehr einen Scan über den gesamten Redis-Schlüsselraum aus, sondern verwendet stattdessen einen Index pro Sitzung, wodurch Verbindungsabbrüche bei großen Bereitstellungen kostengünstig bleiben. #25466, Commit
  • 📝 Automatisches Ausfüllen von Frontmatter für Tools, Funktionen und Fertigkeiten. Beim Öffnen eines Tool-, Funktions- oder Skill-Editors werden die Felder „Name“, „ID“ und „Beschreibung“ jetzt automatisch aus dem Frontmatter der Datei ausgefüllt, sodass Sie keine Metadaten erneut eingeben müssen, die bereits in der Quelle deklariert wurden. #24649, Commit
  • 🪪 Mehr Benutzerplatzhalter in benutzerdefinierten Headern. Benutzerdefinierte Header-Vorlagen für direkte Verbindungen und Toolserver unterstützen jetzt „{{USER_EMAIL}}“ und „{{USER_ROLE}}“ neben den vorhandenen Benutzer- und Sitzungsplatzhaltern. Festschreiben
  • ⏱️ Konfigurierbares MCP-Verbindungs-Timeout. Das Timeout für den ersten Handshake mit einem MCP-Tool-Server ist jetzt über die neue Einstellung „MCP_INITIALIZE_TIMEOUT“ konfigurierbar, sodass Server, die langsam starten oder viele Tools verfügbar machen, die Verbindung beenden können, anstatt eine Zeitüberschreitung zu verursachen. #25011, Commit
  • 📐 Größenbeschränkung für Profilbilder. Administratoren können jetzt die Größe von Inline-Profilbildern über die neue Einstellung „PROFILE_IMAGE_MAX_DATA_URI_SIZE“ begrenzen, um zu begrenzen, wie viel Datenbank- und Cache-Speicherplatz Inline-Avatare und Modellsymbole beanspruchen können. #25468, #25476
  • 🎫 Wildcard-OAuth-Rollenzuordnung. Administratoren können jetzt „*“ in den zulässigen OAuth-Rollen festlegen, um die Benutzerrolle jedem authentifizierten OAuth-Benutzer zu gewähren, anstatt jede akzeptierte Rolle auflisten zu müssen. #25062, Commit
  • 📊 Paginierter Feedback-Verlauf. Die Liste des Feedback- und Bewertungsverlaufs ist jetzt paginiert, sodass sie auch auf Fälle reagiert, in denen sich eine große Anzahl von Feedback-Einträgen angesammelt hat. Commit
  • 🔘 Automatisierungen in großen Mengen aktivieren oder deaktivieren. Automatisierungen können jetzt in großen Mengen über ein Aktionsmenü auf der Automatisierungsseite aktiviert oder deaktiviert werden, anstatt jede einzelne einzeln umzuschalten. Festschreiben
  • ➡️ Optionale automatische Weiterleitung zu Single Sign-On. Administratoren können jetzt „OAUTH_AUTO_REDIRECT“ aktivieren, sodass Benutzer bei Bereitstellungen mit einem Single-Sign-On-Anbieter und ohne andere Anmeldemethoden direkt zum Anbieter weitergeleitet werden, anstatt zuerst eine Anmeldeseite zu sehen. #25067, Commit
  • ☁️ Azure AI Foundry v1 mit Entra ID. Open WebUI unterstützt jetzt den OpenAI v1-Endpunkt von Azure AI Foundry zusammen mit der Microsoft Entra ID-Authentifizierung, sodass diese Verbindungen ohne manuelle Problemumgehungen funktionieren. #24761, #24985, Commit
  • 🌎 Linkup-Websuchanbieter. Administratoren können jetzt Linkup als Websuchanbieter in den Administratoreinstellungen auswählen, mit Optionen zum Konfigurieren des API-Schlüssels und der Suchtiefe. #24752, Commit
  • 🧊 Valkey-Vektordatenbankunterstützung. Valkey kann jetzt als Vektordatenbank-Backend verwendet werden, konfigurierbar über die neue „VALKEY_URL“ und zugehörige Einstellungen, einschließlich Indextyp, Distanzmetrik und HNSW-Optimierung. #24769, Commit
  • 🔄 Allgemeine Verbesserungen. In der gesamten Anwendung wurden verschiedene Verbesserungen implementiert, um Leistung, Stabilität und Sicherheit zu verbessern.
  • 🌐 Übersetzungsaktualisierungen. Übersetzungen für Spanisch (Spanien), Schwedisch, Deutsch, Koreanisch, Katalanisch, Russisch, Irisch, vereinfachtes Chinesisch, traditionelles Chinesisch, Finnisch, Polnisch, Türkisch und Malaiisch wurden verbessert und erweitert.

Behoben

  • 🛡️ Sicherheitshinweis: Diese Version enthält Sicherheits- und Zugriffskontrollkorrekturen. Wir empfehlen, Produktionsbereitstellungen so bald wie möglich zu aktualisieren. Möglicherweise werden nicht alle Sicherheitsfixes in dieser Version im Abschnitt „Fixed“ aufgeführt – einige werden möglicherweise für kurze Zeit zurückgehalten, um Administratoren Zeit für das Upgrade zu geben. Hinweise
  • 🛡️ Erzwingung der Tool-Server-Berechtigung. Die benutzerspezifische Berechtigung für Inline-Tool-Server wird jetzt bei Chat-Abschlussanfragen erzwungen, sodass Benutzer ohne diese Berechtigung die Administratoreinstellung nicht mehr umgehen können, indem sie Tool-Server direkt in ihren Anfragen angeben. Commit
  • 🔒 Wissensdatenbank-Zugriffsprüfung im Suchtool. Das integrierte Wissenssuchtool überprüft jetzt, ob der Anrufer auf eine Wissensdatenbank zugreifen kann, bevor er diese anhand der ID durchsucht, und verhindert so, dass Benutzer den Inhalt von Wissensdatenbanken lesen, auf die ihnen kein Zugriff gewährt wurde. #25113
  • 🗄️ Benutzerübergreifender Zugriff auf Abrufsammlungen. Beim Auflösen der zum Abruf verwendeten Dokumente wird nun der Zugriff des Aufrufers auf jede referenzierte Datei überprüft und von client bereitgestellte Sammlungsnamen abgelehnt, wodurch verhindert wird, dass eine gestaltete Anfrage die Dateien oder Vektorsammlungen eines anderen Benutzers in ihren Kontext zieht. Commit
  • 🔣 Validierung von Sammlungsnamen. Vektorsammlungsnamen werden jetzt abgelehnt, es sei denn, sie enthalten nur sichere Zeichen, wodurch verhindert wird, dass fehlerhafte Namen den Vektorspeicher erreichen oder aus einem Datenbankabfrageausdruck ausbrechen. #24982
  • 🚫 Unscoped Retrieval Collections werden standardmäßig abgelehnt. Abrufanfragen für Sammlungsnamen, die keiner bekannten Datei, keinem bekannten Speicher, keiner Websuche oder Wissensdatenbank entsprechen, werden Nicht-Administratoren jetzt standardmäßig verweigert, mit einer neuen Einstellung „ENABLE_RETRIEVAL_UNSCOPED_COLLECTIONS“, um bei Bedarf das vorherige Verhalten wiederherzustellen. Festschreiben
  • 📜 Autorisierung des Eingabeaufforderungsverlaufs. Beim Vergleichen, Löschen und Wiederherstellen von Eingabeaufforderungsversionen wird jetzt überprüft, ob der Verlaufseintrag zu der Eingabeaufforderung gehört, für die Sie berechtigt sind, wodurch der Zugriff auf oder die Änderung des Versionsverlaufs einer anderen Eingabeaufforderung verhindert wird. #25056
  • 🚦 Code-Interpreter-Berechtigung für den Legacy-Pfad. Der Legacy-Code-Ausführungspfad erzwingt jetzt die gleichen Berechtigungs- und Fähigkeitsprüfungen wie der aktuelle, sodass Benutzer ohne Code-Interpreter-Berechtigung keine Codeausführung mehr über ihn auslösen können. #24724
  • 🧱 Umgehung der Endpunktbeschränkung des API-Schlüssels. Die Endpunkt-Zulassungsliste, die einschränkt, welche Pfade ein API-Schlüssel erreichen darf, wird jetzt direkt mit dem weitergeleiteten Anforderungspfad abgeglichen, wodurch verhindert wird, dass eine manipulierte Anforderung die Beschränkung überschreitet. #25123
  • 🚧 Umgehung der Systemeingabeaufforderung über Anforderungsparameter. Das Flag, das die konfigurierte Systemeingabeaufforderung eines Modells überspringt, kann nicht mehr von externen clients über einen Anforderungsparameter gesetzt werden, sodass vom Administrator konfigurierte Systemeingabeaufforderungen nicht vom API aus umgangen werden können. #25156
  • 🚪 Terminal-Proxy-Pfaddurchquerung. Der Terminal-Proxy dekodiert Anforderungspfade jetzt vollständig, bevor er sie validiert, und blockiert so mehrfach codierte Nutzdaten, die andernfalls dem vorgesehenen Pfad entkommen könnten. #25157
  • 🪤 Cache-Dateipfaddurchquerung. Der Cache-Dateiserver erfordert jetzt eine genaue Übereinstimmung der Verzeichnisgrenzen und schließt damit eine Lücke, in der ein Geschwisterverzeichnis, dessen Name mit dem Namen des Cache-Verzeichnisses begann, verwendet werden könnte, um Dateien von außerhalb bereitzustellen. #25086
  • 🔀 Zugriffsprüfung für die Ollama-Backend-Auswahl. Anfragen können nicht mehr per Index auf ein beliebiges Ollama-Backend abzielen; Ein vom Aufrufer bereitgestellter Backend-Selektor wird nun anhand der Backends überprüft, die tatsächlich das angeforderte Modell bedienen. Festschreiben
  • 🔓 Benutzerübergreifende Dateiexfiltration über Bild-URLs. Wenn eine Chat-Nachricht in einem „image_url“-Feld auf eine Datei anhand ihrer ID verweist, löst der Server diese Datei jetzt nur für ihren Eigentümer, einen Administrator oder einen Benutzer mit einer expliziten Leseberechtigung auf und verhindert so, dass andere authentifizierte Benutzer den Inhalt einer Datei extrahieren, indem sie sie durch das Modell weiterleiten. #24625, Commit
  • 📌 Zugriffsprüfungen für Chat-Dateianhänge. Durch das Anhängen von Dateien an einen Chat werden jetzt nur Dateien verknüpft, die der Anrufer lesen kann, wodurch verhindert wird, dass ein Benutzer die Datei eines anderen Benutzers mit seinem Chat verknüpft, um auf dessen Inhalte zuzugreifen. #25054
  • 🧾 Überprüfung des Besitzes von Modellwissensdateien. Beim Erstellen oder Aktualisieren eines Modells wird jetzt überprüft, ob alle daran angehängten Wissensdateien Dateien sind, auf die der Editor zugreifen kann, wodurch verhindert wird, dass die Dateien eines anderen Benutzers an ein Modell angehängt werden. #25055, Commit
  • 📅 Autorisierung zum Verschieben von Kalenderereignissen. Das Aktualisieren eines Kalenderereignisses, um es in einen anderen Kalender zu verschieben, erfordert jetzt Schreibzugriff auf den Zielkalender, wodurch verhindert wird, dass Benutzer Ereignisse in Kalender einfügen, in die sie nicht schreiben können. #24764
  • 📣 Kanal-Chat-Zugriffskontrolle. Das Generieren einer Antwort in einem Kanalkontext überprüft jetzt den Zugriff des Anrufers auf diesen Kanal und begrenzt die enthaltenen Nachrichten, wodurch der Zugriff auf Kanäle oder Nachrichten verhindert wird, die der Benutzer nicht sehen darf. #24725
  • 🕸️ Webloader-SSRF-Gating mit Playwright. Wenn der Playwright-basierte Webloader verwendet wird, werden Seitennavigation und Weiterleitungen jetzt auf die gleiche Weise wie beim Standardlader validiert, wodurch eine Lücke geschlossen wird, durch die der Playwright-Pfad interne oder anderweitig blockierte URLs erreichen könnte. #24756
  • 🛂 DNS-Rebinding-Schutz für URL-Abrufe. Die für einen ausgehenden URL-Abruf validierte IP-Adresse ist jetzt dieselbe, die für die tatsächliche Verbindung verwendet wird. Dadurch wird ein DNS-Rebinding-Fenster geschlossen, in dem ein vom Angreifer kontrollierter Hostname während der Sicherheitsüberprüfung in eine öffentliche IP und dann beim Öffnen der Verbindung in eine private IP aufgelöst werden könnte. #24759
  • 🪞 OAuth-Profilbild-Umleitungsbehandlung. Der OAuth-Profilbildabruf folgt Umleitungen jetzt nur dann, wenn Administratoren dies ausdrücklich zugelassen haben, wodurch ein Fenster geschlossen wird, in dem eine Umleitung von einer extern validierten URL zum Erreichen interner Adressen verwendet werden könnte. #24809
  • 🧼 Modellprofilbild-Skriptinjektion. Modellprofilbilder werden jetzt beim Speichern validiert und nur dann inline bereitgestellt, wenn es sich um einen bekanntermaßen sicheren Bildtyp handelt. Dadurch wird verhindert, dass ein manipuliertes SVG-Profilbild Skripte in den Browsern anderer Benutzer ausführt, während vorhandene Legacy-Bilder, die die Validierung nicht bestehen, ordnungsgemäß gelöscht werden, anstatt die Modellliste zu zerstören. #25060, #25173
  • 🧯 Diagramm-Rendering-Skript-Injektion. Im Chat gerenderte Meerjungfrauen-Diagramme werden jetzt vor der Anzeige bereinigt, wodurch verhindert wird, dass ein gestaltetes Diagramm Skripte im Browser des Betrachters ausführt. #25219
  • 🔐 Schreibschutz für Dateien im geteilten Chat. Der Zugriff auf eine Datei über einen geteilten Chat gewährt jetzt nur Lesezugriff, sodass Benutzer, die einen geteilten Chat lesen können, daran angehängte Dateien nicht mehr ändern oder löschen können. #24755
  • 🔏 Cross-Origin-Einbettungs-Eingabeaufforderungssteuerung. Wenn Open WebUI in einen Iframe auf einem anderen Ursprung eingebettet ist, kann die Einbettungsseite jetzt nur dann die Chat-Eingabe steuern oder Eingabeaufforderungen senden, wenn der Benutzer sich ausdrücklich über die Einstellung „iframe Sandbox Allow Same Origin“ dafür entschieden hat, wodurch verhindert wird, dass untrusted-Hostseiten Bestätigungsdialoge auslösen oder den Chat steuern. #24767, Commit
  • 🗂️ Überprüfung der Inhaberschaft von Chat-Ordnern. Beim Erstellen eines Chats oder beim Aktualisieren eines Chat-Ordners wird jetzt überprüft, ob der referenzierte Ordner dem aktuellen Benutzer gehört, wodurch verhindert wird, dass Chats mit Ordnern verknüpft werden, die anderen Personen gehören. #24588
  • 🧩 Chat-Wiederherstellung nach beschädigtem Verlauf. Chats, deren internes Nachrichtendiagramm aufgrund einer fehlgeschlagenen Neugenerierung in einem fehlerhaften Zustand zurückblieb, werden jetzt korrekt geöffnet und geladen, wobei fehlende Rollen, übergeordnete Referenzen und aktuelle Nachrichtenzeiger automatisch wiederhergestellt werden, anstatt den Chat zu unterbrechen. #24424, #24157, #20474, #24799, Commit
  • 📨 Importierte Chats mit Ordnern werden korrekt angezeigt. Beim Importieren gruppierter Chats bleiben diese nicht mehr unsichtbar, wenn ein referenzierter Ordner fehlt; Solche Chats erscheinen jetzt in der Chat-Liste, anstatt stillschweigend verwaist zu sein. #24910, Commit
  • 🎟️ MCP-Tool-Serversitzungen bleiben verbunden. OAuth-authentifizierte MCP-Tool-Serversitzungen werden nicht mehr versehentlich vom Single-Sign-On-Sitzungshandler aktualisiert und gelöscht, sodass diese Verbindungen aktiv bleiben. #24618, Commit
  • 🤝 MCP-OAuth-Bereichserkennung. Der OAuth-Fluss für MCP-Tool-Server liest jetzt die Bereiche, die ein Server über seine geschützten Ressourcenmetadaten ankündigt, sodass die Verbindung zu Servern erfolgreich ist, die ihre eigenen Bereiche deklarieren. #24730, #24690
  • 🔍 Zuverlässigkeit der Websuche. Die Websuche ruft Seiteninhalte wieder zuverlässig mit der Standard-Webloader-Engine ab, eine neue Umgebungsvariable „USER_AGENT“ ermöglicht es Administratoren, einen echten Browser-Benutzeragenten festzulegen, sodass Abrufe nicht von Cloudflare, Wikipedia und anderen Bot-Erkennungssystemen blockiert werden, und das Startskript startet nicht mehr, wenn diese neuen Umgebungsvariablen deaktiviert sind. #24560, #24793, #24683, Commit
  • 🔥 Firecrawl-Websuchergebnisse. Die Websuche mit Firecrawl gibt jetzt korrekte Ergebnisse zurück, unabhängig davon, welches Antwortformat die Firecrawl-Version verwendet. #24712
  • 🦅 Kagi-Websuche. Die Websuche mit Kagi funktioniert wieder, nachdem der Endpunkt API und die Anforderungsmethode aktualisiert wurden, um mit Kagis aktuellem API übereinzustimmen. #25015
  • 🔢 Zahlen in Klammern in Codeblöcken. Zahlen in eckigen Klammern wie „[0]“ innerhalb von Codeblöcken werden nicht mehr entfernt, als wären sie Quellenangaben, sodass Code korrekt angezeigt und kopiert wird. #24948, Commit
  • 🔌 Zuverlässigkeit der Chat-Abschlüsse API. Direkte Aufrufe der Chat-Abschlüsse API schlagen nicht mehr mit einem internen Fehler fehl, wenn keine Chat-Sitzungs-ID angegeben wird. #24553, #25235, Commit, Commit
  • 🖼️ ComfyUI-Bildgenerierung und -bearbeitung. Das Generieren und Bearbeiten von Bildern über ein ComfyUI-Backend funktioniert jetzt wieder, auch wenn ComfyUI in einem privaten oder internen Netzwerk gehostet wird, in dem die URL-Validierung zuvor den vom Administrator konfigurierten Endpunkt blockierte. #24565, Commit, Commit
  • 🖌️ Bildgenerierung mit nicht standardmäßigen Antwortheadern. Die Bildgenerierung funktioniert jetzt mit Backends, die gültige JSON ohne einen standardmäßigen Inhaltstyp-Header zurückgeben, anstatt die Antwort abzulehnen. #24838
  • 🐘 Wissenssuche in großen Dokumenten. Die Suche in Wissensdatenbanken auf PostgreSQL schlägt nicht mehr fehl, wenn Dokumente mit sehr großem extrahierten Textinhalt gescannt werden. #24670, Commit
  • 💬 Generierung von Chattiteln. Automatisch generierte Chattitel verwenden jetzt das Modell, das aktuell in der Dropdown-Liste für den aktiven Chat ausgewählt ist, und greifen andernfalls auf das Modell aus dem aktiven Nachrichtenzweig zurück. Wenn kein Modell verfügbar ist, wird anstelle eines nicht hilfreichen Fehlers eine klare Meldung angezeigt. #24604, #24745, Commit, Commit
  • 🧮 Konsistenz bei Nachrichtensuche und Analyse. In einem Chat vorgenommene Bearbeitungen, Löschungen und Zweigänderungen werden jetzt in den Nachrichtensuchergebnissen und Analysezählungen widergespiegelt, anstatt veraltete Einträge zu hinterlassen. #25205, Commit
  • 🩹 Anmutiger Umgang mit Aufgabenfehlern im Chat. Wenn die Generierung einer Websuchabfrage, der Bildaufforderung oder eines Toolaufrufs fehlschlägt oder auf ein fehlendes Tool verweist, fällt der Chat jetzt zurück oder zeigt einen eindeutigen Fehler an, anstatt mitten in der Antwort abzubrechen. #25038, #25144, Commit
  • 🎛️ Änderungen an der Nachrichtenausgabe filtern. Bei Filterfunktionen, die die strukturierte Ausgabe einer Nachricht nach der Generierung ändern, werden diese Änderungen jetzt gespeichert und angezeigt, anstatt verworfen zu werden, wenn nur die Ausgabe, nicht der Textinhalt, geändert wurde. #24884
  • ⏩ Titel und Tags spiegeln die gefilterte Ausgabe wider. Outlet-Filter werden jetzt vor der automatischen Titel-, Tag- und Folgegenerierung ausgeführt, sodass diese auf der endgültigen gefilterten Nachricht und nicht auf der ungefilterten Version basieren. #24717
  • 💾 Der durch eine Aktion ersetzte Nachrichteninhalt bleibt bestehen. Der durch eine Aktionsfunktion über ihren Ereignisemitter ersetzte Nachrichteninhalt bleibt jetzt erhalten, wenn der Chat gespeichert wird, anstatt nach einem Neuladen der Seite auf den Originalzustand zurückgesetzt zu werden. #24585, #25485
  • 🏷️ Skill-Erwähnungen in Nachrichten. Das Erwähnen eines Skills in einer Nachricht behält jetzt den Namen des Skills als lesbaren Text bei, anstatt ihn zu entfernen, und die Auswahl eines Skills ohne Eingabe führt bei Anbietern, die leere Nachrichten ablehnen, nicht mehr zu einem Fehler. #24929, Commit
  • 🧹 Bereinigung des Nutzungs-Timers bei Sendefehler. Der im Hintergrund gestartete Nutzungsstatistik-Timer, der während der Nachrichtengenerierung gestartet wurde, wird jetzt immer gelöscht, auch wenn das Senden einer Nachricht fehlschlägt, wodurch verhindert wird, dass sich verlorene Timer über eine Sitzung ansammeln. #25478
  • 🗑️ Hintergrundaufgaben werden gestoppt, wenn ein Chat entfernt wird. Durch das Löschen oder Archivieren eines Chats werden jetzt alle laufenden Generierungs- oder Titel- und Tag-Aufgaben dafür abgebrochen, anstatt verwaiste Hintergrundarbeit weiterlaufen zu lassen. #25050, Commit
  • ⌨️ Responsive Suche nach Wissensdateien. Die Suche nach Wissensdateien in der Chat-Auswahl und der Modell-Wissensauswahl stimmt jetzt standardmäßig mit Dateinamen überein, anstatt den gesamten extrahierten Text jedes Dokuments bei jedem Tastendruck zu scannen. Dadurch bleibt die Suche bei großen Bereitstellungen reaktionsfähig und die Inhaltssuche ist als explizite Option verfügbar. #25082, #25119, Commit
  • 📥 Dokumentverarbeitung mit leeren Einbettungen. Das Speichern von Dokumenten in der Vektordatenbank stürzt nicht mehr ab, wenn ein Einbettungsschritt keine Vektoren zurückgibt, sodass der Prozess fortgesetzt werden kann, anstatt dass der gesamte Upload fehlschlägt. #25166
  • 🔤 Nicht-UTF-8-Text- und CSV-Uploads. Text- und CSV-Dateien, die in älteren Kodierungen, einschließlich Latin-1, Windows-1252 und chinesischen Kodierungen wie GB18030, gespeichert sind, werden jetzt korrekt erkannt und geladen, anstatt als Binärdatei abgelehnt zu werden oder mit einem Fehler wegen leerem Inhalt fehlzuschlagen. #25172, #24973, Commit, Commit
  • 🧽 Nullbytes in verschachtelten Daten unterbrechen das Speichern nicht mehr. Daten, die in strukturierten Feldern verschachtelte Nullbytes enthalten, werden jetzt vor dem Schreiben korrekt bereinigt, wodurch Datenbankfehler verhindert werden, die bei der vorherigen Prüfung nicht erkannt wurden. #25018, Commit
  • 🧠 Fehler löschen, wenn kein Einbettungsmodell konfiguriert ist. Die Verwendung von Wissens- oder Abruffunktionen ohne geladenes Einbettungsmodell gibt jetzt einen eindeutigen Setup-Fehler zurück, der erklärt, was konfiguriert werden muss, anstatt mit einem kryptischen Absturz fehlzuschlagen. Commit
  • 🧲 Qualität der Speichersuche. Speichersuchen wenden jetzt das konfigurierte Einbettungsabfragepräfix an, sodass der Abruf korrekt mit Einbettungsmodellen funktioniert, die eines für Abfragen erfordern. #24921, Commit
  • 📚 Kontextüberlauf des Wissenstools. Das integrierte Tool, das das Wissen eines Modells auflistet, speichert nicht mehr jede Datei in jeder Wissensdatenbank im Kontext des Modells; Es gibt jetzt standardmäßig Zusammenfassungen zurück und paginiert Dateilisten nur für eine angeforderte Wissensdatenbank. #25105, Commit
  • ⏳ Terminal-Sitzungsstabilität. Der Terminal-Proxy bleibt nicht mehr hängen, wenn eine Richtung der Verbindung vor der anderen geschlossen wird, sodass Terminal-Sitzungen sauber heruntergefahren werden, anstatt ins Stocken zu geraten. #25464, #25479
  • 🧷 Kontinuität von Tool-Aufrufen mit strengen Anbietern. Chats, die unvollständige Tool-Aufrufe oder verwaiste Tool-Ergebnisse enthalten, werden nicht mehr fortgesetzt, wenn sie an Anbieter gesendet werden, die Tool-Paarungen streng validieren, wie Anthropic und AWS Bedrock Converse. #24758, #24940, #24798, Commit
  • 🛑 Stream-Beendigung für Pipe-Funktionen. Gestreamte Antworten von Pipe-Funktionen senden jetzt immer die Standard-Stream-Ende-Markierung, sodass Chat-clients und externe Integrationen zuverlässig erkennen, wann eine Antwort abgeschlossen ist, anstatt auf Streams zu warten, die bereits abgeschlossen sind. #24763
  • 🔊 Nicht blockierende Text-zu-Sprache-Transkodierung. Durch die Konvertierung von Text-zu-Sprache-Audio in MP3 wird die Ereignisschleife des Servers nicht mehr blockiert, sodass andere Anfragen auch dann reagieren, wenn eine TTS-Antwort transkodiert wird. #24876
  • 🎚️ Standard-Text-zu-Sprache-Stimme. Text-zu-Sprache-Anfragen berücksichtigen jetzt die in der Anfrage angegebene Stimme und greifen nur dann auf die konfigurierte Standardstimme zurück, wenn keine angegeben ist, anstatt immer die Administrator-Standardeinstellung zu verwenden oder fehlzuschlagen. #15143, #25035, Commit, Commit
  • 🪝 Zuverlässige Verknüpfung von Wissensdatenbankdateien. In eine Wissenssammlung hochgeladene Dateien werden jetzt beim Hochladen selbst auf dem Server verknüpft, sodass sie auch dann an die Sammlung angehängt bleiben, wenn Sie die Seite verlassen oder schließen, bevor die Verarbeitung abgeschlossen ist. #24807, Commit
  • ☁️ Azure-Verbindungen auf benutzerdefinierten Hostnamen. Verbindungen, die als Azure-Anbieter markiert sind, verwenden jetzt den Azure-Codepfad, auch wenn der Endpunkt nicht „azure“ in seinem Hostnamen enthält, wodurch benutzerdefinierte Azure-Bereitstellungen behoben werden, die von nicht standardmäßigen Domänen bereitgestellt werden. #24882, Commit
  • 🗓️ Kalenderereignisfelder löschen. Wenn Sie die Beschreibung oder den Ort aus einem Kalenderereignis entfernen, wird das Speichern jetzt korrekt durchgeführt, anstatt den vorherigen Wert stillschweigend beizubehalten. #25026, Commit, Commit
  • 💭 Erweiterte Parametereinstellungen. Benutzerdefinierte Argumentations-Tags und benutzerdefinierte Modellparameter werden jetzt korrekt gespeichert, anstatt gelöscht zu werden, und die Anwesenheitsstrafe und die Wiederholungsstrafe speichern nicht mehr den Wert der Häufigkeitsstrafe anstelle ihres eigenen Werts. #25183, #25200, #25204
  • 📏 Anzeige langer Benutzernamen. Lange Benutzernamen überlaufen ihre Container in der Admin-Benutzerliste, in den Benutzermodalitäten und in der Seitenleiste nicht mehr. #25185
  • 🎯 Alle Fertigkeiten im Modelleditor auswählbar. Die Fertigkeitsauswahl des Modelleditors listet jetzt alle Fertigkeiten auf, auf die Sie Zugriff haben, mit einem Suchfeld für große Listen, anstatt nur die ersten 30 anzuzeigen, ohne dass Sie auf den Rest zugreifen können. #24873, Commit
  • 🔔 Genaues Wissens-Upload-Feedback. Beim Ziehen von Dateien in eine Wissensdatenbank wird keine Upload-Benachrichtigung mehr angezeigt, bevor der Upload tatsächlich verarbeitet wurde. #25484
  • ♿ Lesbarkeit des Zeitstempels mit hohem Kontrast. Der Zeitstempel der Benutzernachricht verwendet jetzt im Modus mit hohem Kontrast die richtigen Farben statt invertierter Farben, sodass er lesbar bleibt. #25461
  • ♿ Tastatur- und Screenreader-Zugriff auf Menüs. Die Integrationen, Mehroptionen und Benutzermenüs sind jetzt echte Schaltflächen mit Beschriftungen und Tastaturunterstützung, sodass sie mit der Tastatur geöffnet und von Screenreadern angesagt werden können. Commit
  • 🖱️ Fokusverlustbehandlung in Editoren. Workspace- und Admin-Editoren für Modelle, Tools, Funktionen und Fertigkeiten reagieren wieder korrekt, wenn das Browserfenster den Fokus verliert, nachdem auf den falschen Ereignisnamen gewartet wurde. #25459
  • 🛟 Resilienz gegenüber beschädigtem lokalem Speicher. Beschädigte Daten im lokalen Speicher des Browsers führen nicht mehr zum Absturz der Benutzeroberfläche. Die betroffenen Einstellungen und der Status „verworfenes Banner“ werden nun auf sichere Standardwerte zurückgesetzt. #25481
  • 📶 Leisere Benachrichtigungen über die Wiederherstellung der Verbindung. Bei kurzen Verbindungsunterbrechungen, z. B. wenn ein mobiler Tab im Hintergrund angezeigt wird, wird nicht mehr die Warnung „Verbindung verloren“ angezeigt, und die Meldung „Wiederverbindung hergestellt“ wird nur angezeigt, wenn tatsächlich eine Trennung angezeigt wurde. Commit
  • 🍎 Safari-PDF-Verarbeitung. Die PDF-Verarbeitung funktioniert jetzt in Safari, das die Stream-Iteration, auf die der vorherige Code angewiesen war, nicht unterstützt. #25151, #25473
  • 🎙️ Auflistung der Tastenkombinationen für die Stummschaltung des Sprachmodus. Die Tastenkombination zum Stummschalten des Sprachmodus wird jetzt in der Hilfefunktion für Tastenkombinationen angezeigt. #25193
  • 📎 Dokumentanhänge in Kanalmodellantworten. Das Markieren eines Modells in einem Kanalthread leitet jetzt hochgeladene Nicht-Bilddokumente wie PDFs und DOCX-Dateien in den Kontext des Modells weiter, sodass Dokumentzusammenfassungs- und Vergleichsworkflows, die bereits im direkten Chat funktionierten, jetzt auch in Kanälen funktionieren. #24896, #24898, Commit
  • 🙈 Versteckte Modelle in Kanalerwähnungen. Modelle, die als ausgeblendet markiert sind, werden nicht mehr in der Kanal-Nachrichteneingabe-Modellerwähnungsauswahl angezeigt, was der Art und Weise entspricht, wie versteckte Modelle an anderer Stelle in der Benutzeroberfläche ausgeschlossen werden. #24892
  • 🧵 Stabilität von Kanal-Threads und angehefteten Nachrichten. Das Öffnen eines Kanal-Threads oder der Ansicht „Angeheftete Nachrichten“ schlägt nicht mehr fehl, wenn eine Nachricht oder ihre Daten fehlen. #25209
  • 📺 YouTube-Kurzlink-Transkripte. Das Einfügen eines „youtu.be“-Kurzlinks in einen Chat lädt das Video-Transkript jetzt korrekt, anstatt mit einem Fehler wegen leerem Inhalt fehlzuschlagen. #24856, Commit
  • 🙉 Versteckte Modelle in Standardmodell- und Automatisierungsauswahlen. Die Admin-Auswahl für Standardmodelle und standardmäßig angeheftete Modelle sowie das Dropdown-Menü für Automatisierungsmodelle filtern jetzt versteckte Modelle heraus, im Einklang mit der Behandlung versteckter Modelle an anderer Stelle. #24869, Commit, Commit
  • 🔊 Speech-to-Text-SSL-Einstellung berücksichtigt. Speech-to-Text-Anfragen berücksichtigen jetzt die Einstellung „AIOHTTP_CLIENT_SESSION_SSL“, sodass Administratoren, die selbstsignierte Zertifikate oder benutzerdefinierte SSL-Konfigurationen verwenden, STT-Engines verwenden können, die zuvor die TLS-Überprüfung nicht bestanden haben. #24568, #24857, Commit, Commit
  • 🔗 Platzhalter in MCP-Verbindungsheadern. Benutzerdefinierte Header-Vorlagen, die auf MCP-Serververbindungen konfiguriert sind, verfügen jetzt über die Platzhalter „{{USER_ID}}“, „{{USER_NAME}}“, „{{USER_EMAIL}}“, „{{USER_ROLE}}“, „{{CHAT_ID}}“ und „{{MESSAGE_ID}}“, die zum Zeitpunkt der Anforderung interpoliert werden, was der Funktionsweise von benutzerdefinierten Headern entspricht, die bereits für direkte Verbindungen und Toolserver funktionieren. #24822
  • 🪟 Bing-Suche CLI Rauchtest. Das Ausführen des Bing-Websuchmoduls über die Befehlszeile für eine schnelle Konnektivitätsprüfung führt nicht mehr zu einer Fehlermeldung über fehlende Argumente. #24765, #24768
  • 🩺 Wiederherstellung der Datenbank-Integritätsprüfung. Nach einem vorübergehenden Datenbankverbindungsfehler wird der Endpunkt der Integritätsprüfung jetzt automatisch wiederhergestellt, anstatt auf dem betroffenen Worker dauerhaft unterbrochen zu bleiben. Commit
  • 🥾 Start auf Nicht-Unicode-Konsolen. Open WebUI stürzt beim Start nicht mehr ab, wenn die Konsole die Rahmenzeichen des Banners nicht kodieren kann, wie z. B. unter Windows oder bei umgeleiteter oder Headless-Ausgabe, und greift stattdessen auf ein Nur-Text-Banner zurück. #24965, #25482
  • 🆕 Erste Administratoranmeldung nach einem Zurücksetzen. Das Erstellen des ersten Administratorkontos wird nicht mehr durch eine zuvor gespeicherte Anmeldeeinstellung blockiert, sodass immer eine neue oder zurückgesetzte Instanz gebootet werden kann. #24821
  • 🪵 JSON-Ausnahmeprotokollierung. Wenn die Protokollformatierung JSON aktiviert ist, werden Ausnahmen jetzt korrekt mit einem strukturierten Typ, einer Nachricht und einem Stacktrace aufgezeichnet, anstatt gelöscht zu werden, und ein Protokollierungsfehler kann die Anwendung nicht mehr zum Absturz bringen. #25135, Commit
  • 🧭 Berechtigung für Workspace-Skills. Benutzer, denen nur die Berechtigung „workspace.skills“ erteilt wurde, können jetzt den Workspace-Eintrag in der Seitenleiste sehen und werden vom Workspace-Index korrekt zur Skills-Seite weitergeleitet. #24729
  • 🔁 Resiliente Datenbankmigrationen. Datenbankmigrationen überspringen jetzt bereits vorhandene Tabellen, Indizes und Spalten und fügen fehlende Primärschlüssel zu Legacy-Tabellen hinzu, sodass Upgrades auch dann erfolgreich sind, wenn Teile des Schemas zuvor manuell oder teilweise erstellt wurden. Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, Commit, #24722

Geändert

  • ⚠️ Datenbankmigrationen: Diese Version enthält Änderungen am Datenbankschema; Wir empfehlen dringend, Ihre Datenbank und alle zugehörigen Daten vor dem Upgrade in Produktionsumgebungen zu sichern. Wenn Sie eine Bereitstellung mit mehreren Workern, mehreren Servern oder mit Lastausgleich ausführen, müssen alle Instanzen gleichzeitig aktualisiert werden. Rolling Updates werden nicht unterstützt und führen aufgrund von Schemainkompatibilität zu Anwendungsfehlern.
  • ⚙️ Tool-Call-Iterationsobergrenze umbenannt und angehoben. Die Umgebungsvariable, die begrenzt, wie viele Tool-Calls eine einzelne Chat-Antwort machen darf, ist jetzt „CHAT_RESPONSE_MAX_TOOL_CALL_ITERATIONS“, wobei der Standardwert von 30 auf 256 angehoben wurde und ein neuer „-1“-Wert für unbegrenzt gilt; Der bisherige Name „CHAT_RESPONSE_MAX_TOOL_CALL_RETRIES“ fungiert weiterhin als Fallback, und Chats, die die Obergrenze erreichen, zeigen jetzt einen deutlichen Fehler im Chat an, anstatt stillschweigend anzuhalten. #24918, Commit
  • 🔐 Reduzierte öffentliche „/api/config“-Präsenz. Die „/api/config“-Antwort enthält nicht mehr mehrere Funktionsflags („enable_api_keys“, „enable_password_change_form“, „enable_version_update_check“, „enable_public_active_users_count“, „enable_easter_eggs“) für nicht authentifizierte Anrufer, wodurch die Informationen reduziert werden Offenlegung gegenüber anonymen Besuchern. Festschreiben, Festschreiben
  • 🔑 „WEBUI_SECRET_KEY“ ist jetzt selbst für nicht unterstützte Bereitstellungen eine zwingende Anforderung. Bereitstellungen, die das Backend auf explizit nicht unterstützte Weise starten (z. B. durch direktes Aufrufen von uvicorn), ohne „WEBUI_SECRET_KEY“ festzulegen, verweigern jetzt den Start, anstatt auf einen leeren Schlüssel zurückzugreifen; Die unterstützten Startmethoden (start.sh, start_windows.bat und „open-webui Serve“) legen es weiterhin automatisch fest oder generieren es automatisch, sodass Standardbereitstellungen davon nicht betroffen sind. Der direkte Start von Uvicorn wird nicht unterstützt. #25218
