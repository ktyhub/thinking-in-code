⚠️ Upgrade einer selbst gehosteten Installation – bahnbrechende Änderung

ENCRYPTION_KEY, UNSUBSCRIBE_SECRET_KEY und BETTER_AUTH_SECRET werden nicht mehr mit Werten in .env.default ausgeliefert; Sie werden pro Installation generiert und das Backend startet nicht mit dem Wert, den .env.default früher enthielt. Für eine Neuinstallation ist nichts weiter als make init-env (oder das Installationsprogramm) erforderlich. Eine Installation, die ihre eigenen Werte festlegt, benötigt nichts. Wenn Ihre Installation mit den Standardeinstellungen ausgeführt wurde (keine ENCRYPTION_KEY-Zeile in backend/.env oder Startstopps mit ENCRYPTION_KEY is set to a value that was published…), tun Sie dies von autogpt_platform/ aus – dadurch werden Ihre verbundenen Integrationen auf den neuen Schlüssel verschoben, anstatt sie zu verlieren:

  1. docker compose down
  2. Bewahren Sie den Schlüssel auf, mit dem Ihre Daten verschlüsselt sind: export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) (Wenn Sie Ihren eigenen Schlüssel festgelegt haben und ihn ersetzen, exportieren Sie stattdessen diesen Wert und bewahren Sie eine Kopie von backend/.env außerhalb des Checkouts auf.)
  3. Stellen Sie in backend/.env sicher, dass ENCRYPTION_KEY= und UNSUBSCRIBE_SECRET_KEY= vorhanden sind, ohne dass nach = und BETTER_AUTH_SECRET= in frontend/.env nichts folgt. dann make init-env (füllt jedes leere Geheimnis, überschreibt niemals einen Wert).
  4. Verschlüsseln Sie die gespeicherten Daten erneut – führen Sie zunächst einen Probelauf durch und wenden Sie dann Folgendes an: docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply
  5. Löschen Sie den unter dem alten BETTER_AUTH_SECRET gespeicherten Token-Signaturschlüssel und starten Sie dann: docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

Vollständige Anweisungen: Upgrade: Geheimnisse werden pro Installation generiert.

Außerdem in dieser Version: Der alte HS256-JWT-Verifizierungspfad wurde entfernt, sodass ein JWT_VERIFY_KEY in backend/.env nicht mehr gelesen wird (#14519); Die nicht verwendete Tabelle TrialNotificationDelivery wird durch die Migration gelöscht.
