paperclip v2026.1106.0

Papierclip v2026.1106.0

Veröffentlicht: 06.11.2026

Paperclip v2026.1106.0 enthält 515 Commits, die von 2026.1023.0-beta.0 gefördert werden. Die Überschrift lautet, dass der Paperclip Runner jetzt der Standard für neue Agenten ist: Neue Claude-, Codex-, OpenCode- und Pi-Agenten starten auf dem nativen Runner auf qualifizierten macOS- und Linux-Hosts, bestehende Agenten erhalten eine Ein-click-Aktion „Runner aktualisieren“ und GitHub Copilot tritt als nativer Harness bei. Um das herum: Projekt-Repositorys, die automatisch zu Kompetenzquellen werden, modellgestützte Prompt-Injection-Verhinderung, Beobachtbarkeit von Agenten für Braintrust oder einen beliebigen OTLP-Endpunkt, eine einheitliche Google Workspace-Verbindung, Massenbearbeitungen an der Agentenliste, Arbeitsbereiche, die sich selbst mit verschlüsselten Wiederherstellungspunkten komprimieren und ablaufen lassen, und Grok Bot und Muse als experimentelle Runner-Anbieter. Darunter werden Serverneustarts früher als bereit gemeldet, das Docker-Image wird von einem vorkompilierten Paket gestartet, Aufgabenseiten werden schneller geladen und mehr Hintergrunddienste hören auf, die Datenbank abzufragen.

Breaking Changes

  • Das Pipelines-Experiment wurde entfernt. Pipeline-Boards, Bühneneinstellungen, Fallautomatisierung, Überprüfungswarteschlangen, die pipelines CLI-Befehle, die pipelines:write-Berechtigung, die enablePipelines-Einstellung und das linkedCases-Feld in den Aufgabendetails sind verschwunden; Fälle und Routinen bleiben bestehen. Vorhandene Pipeline-Tabellen und -Datensätze bleiben unberührt und ein gespeicherter enablePipelines-Wert wird ignoriert. (#16834)
  • Ausführungsfehler erreichen Sentry standardmäßig nicht mehr. Ein Backend-DSN allein meldet keine Ausführungsfehler des Agenten mehr. Legen Sie PAPERCLIP_SENTRY_RUN_FAILURES=unexpected fest, um die zuvor gefilterte Richtlinie beizubehalten, oder all, um jede fehlgeschlagene Ausführung oder Ausführung mit Zeitüberschreitung zu melden. Der Standardwert ist off. (#16300)
  • Die Liste des Ausführungsverlaufs ist begrenzt. GET /api/companies/{companyId}/heartbeat-runs gibt standardmäßig 200 Zeilen und höchstens 1.000 zurück; clients, die auf einem unbegrenzten Array basieren, müssen ein explizites limit übergeben. (#16286)
  • paperclipai agent instructions-file:delete erfordert --yes wie die anderen destruktiven CLI-Befehle; Skripte, die es aufrufen, müssen das Flag hinzufügen. (#11504)

Highlights

  • Der Paperclip Runner ist der Standard – Neue Claude-Agenten auf Apple Silicon, Intel macOS und Linux x64 (#15993, #15997), neue Codex-Agenten auf Apple Silicon, Intel macOS, Linux x64 und Linux ARM64 (#15683) und neue OpenCode- und Pi-Agenten auf macOS und Linux x64 (#17120, #17142) startet jetzt auf dem nativen Runner statt auf dem Legacy-Adapter, über Onboarding, API und CLI, Hires, Built-Ins, Plugins und Importe hinweg; Linux benötigt GNU libc 2.39 oder höher, ein „Legacy Runner“-Override läuft unter Advanced und vorhandene Agents behalten ihren aktuellen Runner. Vorhandene Claude- und Codex-Agenten auf qualifizierten Zielen zeigen eine Aktion Upgrade-Runner an, die sie in einen click umwandelt, wobei Modell, Konto und Anweisungen erhalten bleiben und alle Einstellungen aufgelistet werden, die nicht konvertiert werden konnten (#17122). Claude-Runner-Agenten beginnen mit vorinstallierten Kernaufgaben-Tools, sind bei einfachen Aufgaben etwa 20 % schneller (#16885), übertragen die gewählte Aufwandsstufe durch Lebensläufe (#15994) und starten unter Linux ARM64 (#16372).
  • GitHub Copilot als nativer Kabelbaum – Verbinden Sie GitHub Copilot über Apps/KI-Verbindungen mit einem gespeicherten GitHub-Token; Die Modellliste des Agenten wird aus dem authentifizierten Konto ermittelt, und Copilot (CLI 1.0.88) durchläuft den Paperclip Runner mit denselben Anweisungen, Berechtigungen und Vervollständigungsgrenzen wie die anderen nativen Anbieter, einschließlich des für Daytona-Sandboxen erforderlichen Linux-Anbietermanifests (#15705, #15701, #15706).
  • Projektrepositorys werden zu Kompetenzquellen – GitHub-Repositories, die an ein neues Projekt angehängt sind, werden automatisch als Kompetenzquellen importiert: Paperclip importiert ihre Kompetenzen, überprüft den konfigurierten Zweig alle fünf Minuten erneut mit der GitHub-Verbindung der Setup-Person und installiert neue Kompetenzen, sofern sie nicht ausgeschlossen sind; Bestehende Projekte erhalten die Aktion „Repositorys übernehmen“ in Skills → Quellen, automatische Updates können angehalten werden, projektabgeleitete Skills erben den Projektzugriff und bei jeder Ausführung werden die Skillversionen fixiert, mit denen sie begonnen hat (#16066). Importe behalten den gesamten Repository-Snapshot beim gescannten Commit bei, sodass Skills, die von gemeinsam genutzten Skripten oder Geschwister-Skills abhängen, nach der Bereitstellung funktionieren, listen jeden Skill mit seinem Ordner auf und überspringen nicht unterstützte oder übergroße Dateien mit einer Warnung, anstatt fehlzuschlagen (#15731, #16308). Quellen erhalten eine Zweigauswahl, die die Zweige des Repositorys lädt, den Standard markiert und den Verweis vor dem Speichern validiert (#16288); Eine Quelle, deren verfolgter Zweig verschwunden ist, zeigt eine Zweigreparaturaktion an (#16256); Jede gespeicherte Quelle wird einmal mit gruppierten Aktualisierungsfehlern aufgelistet (#16310); und durch das Trennen einer Quelle wird diese tatsächlich entfernt, mit einer Option zum Behalten oder Löschen der importierten Fertigkeiten (#16150).
  • Modellgestützte Prompt-Injection-Verhinderung – Einstellungen → Verbindungen ermöglicht es einem Verbindungsmanager, eine gemeinsam genutzte OpenRouter-Verbindung und ein gemeinsames Modell (Standard openai/gpt-oss-safeguard-20b) auszuwählen, um Tool-Ergebnisse zu klassifizieren, bevor sie einen Agenten erreichen, wodurch das Regex-Urteil ersetzt und harmloser Code zugelassen wird, der lediglich wie ein Angriff aussieht; Die Kosten werden unter „Kosten“ angezeigt und mit der Aktion „Modellprüfungen testen“ werden zwei feste Stichproben überprüft. Aus bis zur Konfiguration. (#16976)
  • Agent-Beobachtbarkeit für Ihr eigenes Backend – Unternehmenseinstellungen → Allgemein → Agent-Beobachtbarkeit sendet native Codex- und Claude-Code-Protokolle und -Traces an Braintrust (USA) oder einen benutzerdefinierten OTLP-HTTP-Endpunkt, mit Anmeldeinformationen, die in Unternehmensgeheimnissen gespeichert sind, und einer Testaktion; standardmäßig deaktiviert (#16874). Braintrust wird dem Apps-Katalog auch mit US- und EU-Anmeldung oder API-Schlüsselmethoden hinzugefügt (#17141).
  • Eine einheitliche Google Workspace-Verbindung – Ein Google Workspace-Eintrag ersetzt die separaten Google-Diensteinstellungen: Wählen Sie Gmail, Drive (Dokumente, Tabellen, Folien) und Kalender, jeweils optional schreibgeschützt, und Zustimmung und Toolzugriff sind an diese Auswahl gebunden; Bestehende Google-Verbindungen funktionieren weiterhin (#15545). Gmail erhält eine Opt-in-Archivierungsfunktion (#16331).
  • Arbeitsbereiche, die sich selbst bereinigen – Eine Stunde nach Abschluss einer Aufgabenstruktur entfernt der Terminal-Workspace-Reaper regenerierbare Verzeichnisse wie node_modules, dist und target, die der eigene .gitignore des Repositorys ignoriert, wobei der Zweig und alle Quelländerungen beibehalten werden; Die Abklingzeit des Archivs sinkt von 7 Tagen auf 1 (#16304). Opt-in-Git-Cache-Ablauf entfernt fertige Paperclip-eigene Arbeitsbäume und private Basisklone 24 Stunden nach Fertigstellung des Aufgabenbaums und stellt sie beim genauen Commit wieder her, wenn eine Aufgabe erneut geöffnet wird (#16457, #16691); Bei aktivierten Wiederherstellungspunkten werden geschlossene Arbeitsbäume, die noch nicht übertragene Commits oder nicht übertragene Dateien enthalten, zuerst an einem verschlüsselten Wiederherstellungspunkt gespeichert und genau dann wiederhergestellt, wenn die Arbeit wieder aufgenommen wird. Inaktive offene Probleme werden nach sieben Tagen auf die gleiche Weise geparkt. Verschachtelte Multi-Repository-Auscheckvorgänge erhalten ihre eigenen Wiederherstellungspunkte. Eine Aufgabe, deren Wiederherstellungspunkt abgelaufen ist, wird in einem neuen Arbeitsbereich mit einer Notiz erneut geöffnet, anstatt fehlzuschlagen (#17248, #17271, #17257, #17269). Nicht verwendete materialisierte Skill-Versionen werden stündlich entfernt und bei Bedarf neu erstellt (#16433), und hostseitige Failover-Backups von Remote-Sandbox-Sitzungen laufen eine Woche nach Abschluss ihrer Probleme ab (#16866).
  • Aufgaben mit eigenem Arbeitsbereich – Eine Aufgabe, die Dateien benötigt, aber keine konfigurierte Quelle hat, erhält jetzt ein stabiles Firmen-/Aufgabenverzeichnis, anstatt den Home-Ordner des Agenten zu erben, Agenten können über neue Runner-Tools Repositorys für ihren Arbeitsbereich prüfen, auswählen und anfordern, und Chat-Verbindungen können Projekt- und Arbeitsbereichsstandardwerte festlegen (#15749); Eine neue Aufgabe erhält einen eigenen Klon, wenn das Standard-Auschecken des Projekts einen Arbeitsbaum enthält, den der Agent nicht lesen kann (#16095), mit einem einmaligen click-Wiederholungsversuch bei einem sauberen Auschecken, wenn das Setup auf diese Weise blockiert wird (#16909).
  • Massenänderungen an der Agentenliste – Wählen Sie Zeilen aus und filtern Sie nach Kabelbaum, um die KI-Verbindung, das Standardmodell oder beides für viele Agenten gleichzeitig zu ändern, mit einer Vorschau und einem Wiederholungsversuch bei fehlgeschlagenen Aktualisierungen; Die Statusauswahl des Dienstplans wird entfernt und pausierte Agenten zeigen ein Abzeichen statt abzublenden (#17215). In der Agentenübersicht wird angezeigt, wer in Unternehmen mit mehr als einer Person einen Agenten angelegt hat (#16055).
  • Grok Bot und Muse, beide experimentell – Mit Grok Bot können Sie einen vorhandenen Grok Bot als Agenten einladen, der Aufgaben über eine Webhook-Routine empfängt und über eine dedizierte Agent-OAuth-MCP-Verbindung arbeitet, mit geführter Einrichtung, Kopplungscodes, Fortschritt, Fragen, Dokumenten und Dateien, die zurück in die Aufgabe fließen, sowie Stopp- und Wiederherstellungskontrollen; Anbieterausgaben werden nicht gemeldet (#16219, #16338, #16274, #16305). Muse koppelt einen persönlichen Meta Muse über einen Nur-Wake-Empfänger und Vault-gestütztes OAuth mit einem zehnminütigen Einmalticket, mit Bereitschafts-, Ablauf- und Trennungskontrollen im Einladungsdialog (#16444, #16447, #16448, #16450).
  • Mit Speko mit einem Agenten sprechen – Ein Speko-Eintrag im Apps-Katalog verbindet eine Speko-Persona mit einem vorhandenen Agenten, sodass Sie von einer Aufgabe aus per Browser-Sprache oder Telefon mit ihm sprechen können, mit Transkripten, Anrufsteuerungen, Einstellungen für eingehende Leitungen, Telefonrückrufen und Anrufeinträgen in Aktivität; Wird angezeigt, während die experimentelle Einstellung Chat-Konnektoren aktiviert ist (#15728).
  • Slack-Bots, verfeinert – Die Slack-Verbindungseinstellungen werden um „Slack-Konfiguration öffnen“ und eine Zeile „Testnachricht senden“ vereinfacht, mit „Eigene App verwenden“ unter „Erweitert“ (#15679); Einfache Direktnachrichten beginnen oder setzen die Arbeit immer fort, auch wenn At-Erwähnung erforderlich für Kanalthreads aktiviert ist (#16151); und die Augenreaktion erscheint, sobald eine Erwähnung akzeptiert wird, auch in Direktnachrichten (#16491, #16494).
  • Ein robusterer GitHub-Rezensions-Bot – Der Bot hält einen Haupt-PR-Kommentar über alle Pushs hinweg auf dem neuesten Stand, ignoriert Nachrichten, die an andere Bots gerichtet sind, und markiert korrekt die Funktion, die nicht mehr funktioniert (#16901); Zusammenfassende Kommentare werden mit dem Anzeigenamen des Bots überschrieben, sodass mehrere Bots auf einem PR unterscheidbar sind (#16212); Veröffentlichungsversuche über GitHub 503/429 mit begrenztem Backoff wiederholen und Neustarts ohne doppelte Kommentare oder Prüfungen überstehen (#16284, #16883); GitHub-Bot-Tools erhalten das 60-Sekunden-Maximum des Gateways, sodass submit_review keine Zeitüberschreitung mehr aufweist (#16275); und die Einstellungen zeigen einen „Reconnect GitHub“-Hinweis mit „reconnect-the-saved-App“ als erster Option an (#16856).
  • Weitere Apps im Katalog – Daytona, mit persönlichen oder gemeinsam genutzten API-Schlüsselanmeldeinformationen und 274 generierten Aktionen für Sandboxes, Snapshots, Volumes, Dateien, Git und Befehle (#16483); Unikraft Cloud mit Aktionen, die aus den OpenAPI-Spezifikationen generiert werden, und einem Standard-Metro pro Verbindung (#17139); und Dito (#16472). Eine Anbieterkarte mit mehreren Verbindungen fasst diese hinter einer „N Verbindungen“-Zeile zusammen (#16097).
  • Agent-Kommentar in Audit – Die Beschwerden und Vorschläge, die Agenten zu ihren Werkzeugen einreichen, haben jetzt ein Zuhause: Audit erhält eine Kommentar-Registerkarte mit Agent- und Typfiltern, Textsuche, Paginierung und gemeinsam nutzbaren Links (#16884), die von jeder menschlichen Rolle durch eine neue commentary:view-Berechtigung (#16903) gelesen werden kann.

Korrekturen

  • Arbeitsbereiche und Sandboxen – Eine Remote-Sandbox, deren Ausführung vor dem Export fehlgeschlagen ist, deren Lease mit nicht exportierter Arbeit bereinigt wurde oder deren Aufgabe vor der Rekonstruktion abgebrochen wurde, wird mit ihren Dateien hinter einer expliziten Reparaturentscheidung aufbewahrt, anstatt durch Bereinigung gelöscht zu werden (#16397, #16583, #16700); Eine Aufgabe, deren Sandbox vor dem Export zerstört wurde, bietet eine Board-nur-Aktion „Aus gespeicherten Quellen fortfahren“ (#16690); Dateien, die in der Sandbox eines gestoppten Laufs verbleiben, werden automatisch wiederhergestellt und gespeicherte Follow-ups werden einmal übermittelt (#16906); ein Workspace-Export zum Zeitpunkt des Herunterfahrens behält seinen Besitz über den Finalizer-Drain (#16843); ein langes Zurückkopieren verliert nicht mehr seine Sperre durch das Zeitlimit für Leerlauftransaktionen von PostgreSQL (#16340, #16956); Bei der Wiederaufnahme einer angehaltenen wiederverwendbaren Sandbox wird das Startzeitlimit der Umgebung anstelle von festen 60 Sekunden berücksichtigt (#16802); Eine einzelne Gesundheitsprüfung mit Zeitüberschreitung ersetzt keinen Remote-Runner mehr (#16835); Läufe auf Repositorys mit Tausenden von historischen Arbeitsbereichen sitzen nicht mehr stundenlang in der „Vorbereitung“ (#16372, #16334, #16342, #16963); ein gemeinsamer Checkout bleibt nicht länger von einem Leser blockiert, dessen Identität verloren gegangen ist (#16928) und ein Arbeitsbereich, der durch den eingeschränkten Arbeitsbaum einer anderen Aufgabe blockiert ist, erhält einen klaren Konfigurationshinweis anstelle eines undurchsichtigen 403 (#16545, #16895); Eine untergeordnete Aufgabe, die einen ausgelasteten gemeinsamen Arbeitsbereich erbt, wartet, anstatt mit einem irreführenden Geheimnisfehler fehlzuschlagen (#16371); und das Erstellen einer Aufgabe mit ausgeblendetem Isolationsselektor schlägt bei der Einrichtung nicht mehr fehl (#16220).
  • Ausführungen, Wiederherstellung und Wiederholung – Aufgaben, die hinter einem beibehaltenen Arbeitsbereich oder einer fehlgeschlagenen Ausführung zurückgehalten werden, erhalten einen zuverlässigen Wiederholungsversuch auf Aufgabenebene, der Dateien beibehält, akzeptierte Ergebnisse abrechnet oder einen unabhängigen Arbeitsbereich startet (#16965, #17053, #16894, #16104); Stopp verhindert die automatische Fortsetzung, bis Sie fortfahren (#17105, #14180); Ein Serverneustart führt nicht mehr dazu, dass native Ausführungen dauerhaft angehalten werden, gespeicherte Abschlüsse wiederholt werden oder zwischenzeitlich festgelegte Bedienerstopps überschrieben werden (#16349, #16962, #16403, #15824); Legacy-Läufe, die vor dem Versand abgebrochen oder verloren gegangen sind, werden erneut versucht, anstatt als fehlgeschlagen abgerechnet zu werden (#16355, #16358), ein langsamer Abschluss schlägt bei einem Live-Controller nicht mehr fehl (#16622) und langsame unabhängige Abfragen verursachen keine Kosten mehr für Legacy-Läufe für ihre Lease (#17032); ein normaler Kommentar zu einer laufenden Aufgabe bricht nicht mehr den laufenden Wiederholungsversuch ab (#16855) und das Stoppen einer in der Warteschlange befindlichen Ausführung vor dem Start behält ihre gespeicherte Folge bei, anstatt sie trotzdem auszuführen (#16357); Nachrichten für angehaltene Agenten oder für einen anderen Agenten als den Aufgabeneigentümer werden einmal zugestellt, anstatt fehlzuschlagen oder für immer zurückgestellt zu werden (#16679, #16673); Ein Agent, der mit der Meldung „Wird ausgeführt“ hängen bleibt, wird nach einer fünfminütigen Kulanzfrist repariert (#16791); ein Claude (ACP)-Lauf mit einem blockierten Tool-Aufruf schlägt nach 30 Minuten fehl, anstatt bis zum vierstündigen Timeout ausgeführt zu werden, und MCP-Aufrufe erhalten ein 15-minütiges Timeout (#16671, #16360); Eine Erschöpfung der maximalen Anzahl an Runden wird nicht mehr fälschlicherweise als fehlendes Modell klassifiziert (#13885); und eine Codex-Antwort „Modell bei voller Kapazität“ wird als vorübergehend wiederholt (#16407).
  • Chat- und Aufgaben-Benutzeroberfläche – Durch das Ablehnen einer Anfrage über dem Composer wird das Abzeichen gelöscht, das Neuladen überlebt und die Wiederholung wird nicht mehr blockiert (#17218); Eine Nachricht an einen Runner-Agenten tauscht seinen Avatar nicht mehr kurzzeitig gegen eine generische „Arbeits“-Zeile aus (#16989); eine verbrauchte Nachverfolgung verlässt die ausstehende Warteschlange (#16317); die abschließende Antwort einer Arbeitsbaumaufgabe wird nicht mehr durch die Meldung „Arbeitsbereich bereit“ ersetzt (#16400); eine vor der ersten Agenten-Chat-Nachricht angehängte Datei überlebt die Aufgabenerstellung (#16896); Aufgaben-Toasts in einem Mehrbenutzerunternehmen werden nur für Personen angezeigt, die an der Aufgabe beteiligt sind (#16153); Durch das Laden einer Aufgabenliste werden keine unabhängigen abgeschlossenen Aufgaben mehr zu Ihrem Posteingang hinzugefügt (#16063); antwortet standardmäßig an den letzten Agenten, der Ihnen die Aufgabe zugewiesen hat (#15594); Die Seitenwandlaschen behalten eine konstante Breite (#17068, #14949); Markdown-Editoren zeigen nicht mehr gespeicherte Änderungen beim Laden nicht mehr an (#13915); und eine Slack-Aufgabe, die einer geplanten Fortsetzung nachgibt, gibt ihr Ergebnis an den ursprünglichen Thread zurück (#17045).
  • Kosten und Budgets – Ein Budget an seinem Warnschwellenwert wird als Warnung anstelle eines falschen „AGENT HARD STOP“-Banners angezeigt (#16201) und Budgetprüfungen skalieren nicht mehr mit der Anzahl unabhängiger inaktiver Agenten im Unternehmen (#17046).
  • Verbindungen und MCP – Ein fehlgeschlagener Remote-MCP-Aufruf führt nicht mehr dazu, dass alle Geschwistertools auf dieser Verbindung nicht verfügbar sind (#16890); Ein Anbieter 403 bei einem Chat-Vorgang deaktiviert nicht mehr die gesamte Slack-, GitHub- oder Discord-Verbindung (#16847, #16138); GitHub- und Slack-Channel-Tools bleiben bei späteren Ausführungen derselben Aufgabe verfügbar (#16806); Mehrere GitHub-Bewertungsthread-Antworten erhalten jeweils ihren eigenen Folgelauf (#17054) und identische Tool-Deskriptoren werden einmal aufgelistet (#16281); Bei einer großen MCP-Katalogaktualisierung wird ein Tool nicht mehr zweimal aufgeführt oder es kommt zu Deadlocks mit einem OAuth-Rückruf (#16602); Zugeordnete Werkzeugergebnisse über etwa 500 KB geben eine begrenzte Referenz und ein read_tool_result-Werkzeug zurück, anstatt zu hängen (#16980); Ältere Codex-Shell-Befehle können explizit zugewiesene Dienstgeheimnisse sehen (#17216); Native-Runner call_api folgt den eigenen Berechtigungen der Route ohne zusätzliche Sperrliste (#16040); und Sandbox-Agenten können den Ausführungsverlauf, Anhänge, Skilldateien und Wiederherstellungsdatensätze lesen und das Bridge-Token als X-API-Key (#16575, #16892, #12785 senden.
  • Adapter und CLI – Bei einem unbegrenzten Claude-Lauf schlägt der CLI-Test nicht mehr nach einer Sekunde fehl (#15329); Gleichzeitige Remote-Claude-Läufe eines Agenten unterbrechen nicht mehr die Fähigkeitsbereitstellung des anderen Agenten (#17061); eine isolierte Claude-Aufgabe mit zugewiesenen MCP-Tools wird gestartet (#17149); Eine Sandbox, deren vorinstalliertes Claude CLI älter ist, als das ausgewählte Modell benötigt, erhält die erforderliche Version privat während des Setups installiert, anstatt die Versionsprüfung nicht zu bestehen (#17259); eine Claude (ACP)-Serverinstallation schlägt nicht mehr fehl, weil die ACP-Brücke im Serverpaket fehlte (#15912); ein Runner-OpenCode-Turn übersteht übergroße SSE-Ereignisse (#16401) und verwendet die verwalteten GitHub-Anmeldeinformationen des Laufs in Shell-Befehlen (#16488); Hermes ruft unter der konfigurierten API-URL des Adapters zurück (#9425); pi_local-Laufprotokolle sind etwa 150-mal kleiner (#10249); paperclipai install und update funktionieren mit npm 12 und Knoten 26 (#14000); paperclipai service install schreibt keinen Dienst mehr, der bei einem fehlenden verwalteten Shim eine Absturzschleife ausführt (#13985); und die CLI-Browseranmeldung berücksichtigt Retry-After-Header mit Ratenbegrenzung (#16482).
  • Server und Docker – Der Start schlägt bei älteren SQL_ASCII-Datenbanken (#16958) nicht mehr fehl oder stürzt bei einer schemalosen publicBaseUrl (#13727) ab. Ein Server hinter einem Reverse-Proxy mit langsamen PTR-Suchen reagiert nach dem Upgrade nicht mehr einige Minuten lang (#16333, #16335); Eine getrennte gepoolte Verbindung schlägt nicht mehr bei Berechtigungsprüfungen, Arbeitsbereichsbereitschaft oder dem Reaper fehl (#16857, #16859); Docker startet mit vielen Dateien auf dem Datenvolume oder einem nicht standardmäßigen USER_UID/USER_GID, der nicht mehr das gesamte Volume durchläuft (#15992, #16475); beide versendeten Compose-Dateien weiterleiten PAPERCLIP_TOOL_ACTION_SIGNING_SECRET (#15202); Ein Stopp, der die Rücksynchronisierung überdauert, gibt eine wiederholbare 409 anstelle einer 500 zurück (#16032); gleichzeitige Bearbeitungen von Aufgabentiteln nicht mehr 500 (#13898); Eine fehlerhafte Kommentar-ID blockiert nicht mehr die Warteschleifen einer Aufgabe in der Warteschlange (#13912); Watchdog-Wakes übermitteln die Anweisungen des Bedieners (#13771); Die Obergrenze für untergeordnete Aufgaben zählt nur offene untergeordnete Elemente (#11542); ein Plain-Heartbeat-Agent kann wieder Aufgaben kommentieren (#12621); eine menschliche Übergabe von einem Legacy-Lauf wird nicht mehr durch eine langsame Wiederherstellung abgebrochen (#16082); und Feedback-Exporte sorgen dafür, dass öffentliche Bezeichner lesbar bleiben, während echte Token weiterhin maskiert werden (#16168).

Verbesserungen

– Experimentelle Fälle behalten eine primäre Aufgabe über Agentenübergaben hinweg mit einem dauerhaften Übergabebuch, nativen create_case-, read_case-, update_case- und handoff_case-Tools, schreibgeschützten Fallseiten und wiederverwendbaren benannten Workflow-Eingabeaufforderungen, die ein Fall beim Kickoff oder bei der Übergabe annimmt (#16959, #17114). – Eine fehlgeschlagene Überprüfung des Agentenlebenszyklus benennt den fehlgeschlagenen Schritt und eine Korrekturmaßnahme (#16418), und beim Onboarding wird der Agentendatensatz erstellt, sobald Sie seinen Namen übermitteln, sodass bei Einrichtung und Wiederholungen eine Identität erhalten bleibt (#17005). – Plugins können festgeschriebene Projekt- und Agent-Lebenszyklusereignisse mit Wiedergabe statt Abfragen abonnieren (#16203); Erhalten Sie Agentenkonfigurations-, Anweisungen-, Fertigkeits-, Verbindungs-, Tool- und Gewährungsänderungen über dauerhafte Laufzeit-Hooks (#16499, #16501, #16603, #16604, #16605); Speichern Sie agenten- und projekteigene Instanzgeheimnisse im verschlüsselten Geheimspeicher (#16191, #17034); eigene Projektspeicher- und Aufgabenarbeitsbereiche, fungieren als Standard-Arbeitsbereichsanbieter und führen native Runner-Aufgaben in Plugin-eigenen Umgebungen aus, die durch den Agentenumgebungstest überprüft wurden (#17001, #17247, #16978, #17029, #17252, #15406); und deklarieren Sie authentifizierte WebSocket-Routen und Agent-Detailansichten (#17111).

  • Mehr Hintergrundarbeit wartet auf festgeschriebene Schreibvorgänge und bekannte Fristen, anstatt die Datenbank abzufragen: Telegrammwartung (#16094), Terminal-Arbeitsbereichsbereinigung (#16282), Anmeldebereinigung (#17106), Wiederherstellung der Ausführungskontrolle (#17094), MCP-Ereignisabonnements (#17036) und Skill-Quellen-Synchronisierung (#17008); Routinen und Aufgabenmonitore werden zu ihrem gespeicherten Termin ausgelöst, anstatt auf den nächsten Scan zu warten (#16514).
  • Schnellere Starts überall: Der Server meldet die Bereitschaft früher nach einem Neustart, da die Verwaltung nach der Bereitschaft ausgeführt wird und erledigte Finalisierungen übersprungen werden (#16329, #16485, #16328); Das Docker-Image startet von einem vorkompilierten Laufzeitpaket, wodurch die Codeladezeit von bis zu 24 Sekunden auf unter 4 Sekunden verkürzt wird (#16672); Aufgabenseiten werden langsam geladen, verstecktes Rendern verzögert und die Seitenleiste für zuletzt verwendete Aufgaben wird durch eine begrenzte Anfrage aktualisiert (#16849, #16878, #16851, #16862); und Agentenstarts überschneiden sich mit GitHub, Skill-, Tool- und Sandbox-Vorbereitung, verwenden einen firmenspezifischen Git-Objekt-Cache und verifizierte Sandbox-Bilddateien wieder und führen weitaus weniger Datenbank- und Daytona-Aufrufe durch (#16620, #16608, #16585, #16487, #16687, #16493, #16683, #16536, #16521, #16527, #16561, #16468, #16480, #16552, #16484, #16473, #16425, #16424, #16461, #16498, #16576, #16569, #16414, #17026).
  • Aufgaben, Projektlisten, Posteingangserkennung und Blockiert verbergen von Agenten und vom System erstellte Aufgaben standardmäßig hinter einem Filter „Von Agenten erstellte Aufgaben anzeigen“, der pro Unternehmen gespeichert ist (#16157), und der Posteingang „Mein“ schließt Kanal-, Routine- und von Agenten erstellte Aufgaben aus, es sei denn, Sie haben einen Kommentar abgegeben, wurden zugewiesen oder haben eine offene Anfrage (#16356); Fehlerbenachrichtigungen zeigen bei der Wiederholungsaktion nur den neuesten Fehler an (#16982); und eine abgelaufene Verbindungsanforderungskarte sagt, was noch nicht verbunden ist (#14067). – Eine experimentelle Artefakte V1-Präsentation zeigt Papierstapel und Kacheln auf der Seite „Artefakte“, kompakte Zeilen im Bedienfeld und gruppierte Zeilen im Thread (#17228); Sie können Dateien direkt im Artefaktbedienfeld per Symbol oder Drag-and-Drop hochladen, ohne eine Nachricht zu senden (#15964); Die Offline-Wiederherstellungsseite stimmt mit der App überein (#16904); Die Header-Schaltfläche „Mit Provider-Trace ausführen“ wird durch die Debugging-Konfiguration des Agenten ersetzt (#17211); und auf der Registerkarte „Zugriff“ einer App werden die Fotos verknüpfter Benutzer angezeigt (#15577). – Das Hinzufügen eines Repository-Skills zu einem Agenten verzögert sich nicht mehr bei einem vollständigen Bibliothekslesevorgang (#16899) und ungültige Argumente für zugewiesene Tools, call_api und set_task_monitor geben Schemaspeicherorte und Reparaturanleitungen zurück (#16905, #16889, #16868, #16961). – paperclip_runner-Agenten können homeMode: "preconfigured" so einstellen, dass nativer Codex oder ACPX Claude mit den vorhandenen Anmeldedaten, Fähigkeiten und MCP-Konfiguration des Ausführungskontos ausgeführt wird (#16486); Der Runner meldet aktualisierte OAuth-Anmeldeinformationen, ohne dass Tokenwerte das Protokoll überschreiten (#16463) und kann verifizierte sitzungslokale Standard-MCP-Server unter Unix registrieren (#16526); Der Task-PATCH API akzeptiert expectedStatusVersion für die Backlog-to-Todo-Heraufstufung (#16893); und ein anonymer GET /api/liveness meldet die Prozessaktivität, ohne die Datenbank zu berühren (#16101). – Fehlerberichte zeichnen auf, warum ein OpenCode-Turn fehlschlägt, wenn sein Server stoppt (#16863); Sentry-Berichte für Ausführungsfehler verweisen auf die Aufgaben- und Ausführungsseiten, überspringen klassifizierte Anbieterkontingentgrenzen und melden einen nativen Wiederholungsversuch nur, wenn der Wiederholungsversuch endet (#16803, #16029, #16865); Fällige Aufgabenmonitore, die von der Wiederherstellung gehalten werden, erfassen den Grund in der Aufgabenaktivität (#16891); und wenn ein OTLP-Endpunkt konfiguriert ist, gewinnen Traces Spannweiten für die Controller-Vorbereitung, die Ausführungskonfiguration, die Arbeitsbereich- und Connector-Vorbereitung sowie die Finalisierung (#16178, #16236, #16419, #16428, #16454, #16515).

Upgrade-Anleitung

  • Migrationen 0334–0374 werden beim Upgrade ausgeführt. Additives Schema: 0334-, 0341- und 0342-Repository-Skill-Snapshots, project_skill_sources und Importbudgets; 0335 chat_slack_manager_grants und sein Link aus Slack-Registrierungen; 0336–0338 Ausführungsarbeitsbereich-Repository-Tabellen; 0339 und 0370 agenten-, plug-in- und projekteigenes company_secrets; 0344 und 0346 Grok Bot-Tische; 0349–0353 Musetische; 0357 company_observability; 0362 schnelle Injektionspräventionstabellen; 0363–0368 und 0371 Fallübergabe- und Workflowtabellen; 0372–0374 execution_workspace_restore_points; 0373 Interaktionsentlassungsspalten. Einschränkungsumschreibungen: 0340 lässt delete als Lebenszyklusereignisaktion zu; 0361 erlaubt github als KI-Standardanbieter. Auslöser: 0347, 0348 und 0354–0356 installieren Laufzeit-Invalidierungsauslöser für Agenten, Fertigkeiten, Verbindungen, Zuschüsse, Mitgliedschaften und Geheimnisse; 0358 stößt auf issues.status_version bei Wechsel des Beauftragten; 0372 lässt Wiederherstellungspunkte ablaufen, wenn Probleme behoben werden. Zeilenaktualisierungen: 0343 füllt agents.created_by_user_id aus dem Aktivitätsprotokoll auf; 0347 löst ein agent_runtime-Ereignis pro aktivem Agent aus; 0359 gewährt commentary:view an jede aktive menschliche Mitgliedschaft; 0363 füllt case_access_sources auf. Indizes: 0360 fügt einen Teilindex für die Wiederherstellung des beibehaltenen Arbeitsbereichs hinzu; 0345 und 0369 werden außerhalb einer Transaktion erstellt und können bei einer Unterbrechung sicher erneut ausgeführt werden. Erwarten Sie, dass 0343, 0345 und 0369 auf Instanzen mit großem Ausführungsverlauf länger dauern und die Prüfeinschränkung in 0339, 0362 und 0370 neu geschrieben wird, um company_secrets, budget_reservations und cost_events zu scannen.
  • Neue Agenten verwenden standardmäßig den Paperclip Runner (#15993, #15997, #15683, #17120, #17142): auf qualifizierten Hosts (Apple Silicon, Intel macOS, Linux x64 mit glibc 2.39+ und Linux ARM64 für Codex), neue Claude-, Codex-, OpenCode- und Pi-Agenten werden unabhängig von der enableNativeRunner-Einstellung auf dem nativen Runner erstellt. Bestehende Agenten bleiben unverändert; Wählen Sie unter „Erweitert“ „Legacy Runner“ aus, um einen neuen Agenten zu deaktivieren, oder verwenden Sie Upgrade Runner für die Konfiguration eines vorhandenen Agenten, um ihn zu konvertieren (#17122).
  • Neue Umgebungsvariablen, keine erforderlich. Arbeitsbereichsbereinigung: PAPERCLIP_WORKSPACE_COMPACTION_ENABLED (aktiviert, sofern nicht genau false) und PAPERCLIP_WORKSPACE_COMPACTION_DELAY_HOURS (Standard 1) steuern das Entfernen regenerierbarer Dateien aus abgeschlossenen Aufgabenarbeitsbäumen, und PAPERCLIP_WORKSPACE_REAPER_COOLDOWN_DAYS ist jetzt standardmäßig 1 anstelle von 7 (#16304); PAPERCLIP_GIT_CACHE_EXPIRATION_ENABLED und PAPERCLIP_GIT_BASE_EXPIRATION_ENABLED (Standard false) mit PAPERCLIP_GIT_CACHE_EXPIRATION_DRY_RUN (Standard true) aktivieren das Ablaufen fertiger Arbeitsbäume und Basisklone (#16457); PAPERCLIP_GIT_RESTORE_POINTS_ENABLED (Standard false) mit PAPERCLIP_GIT_RESTORE_POINT_TERMINAL_DELAY_DAYS (Standard 3), PAPERCLIP_GIT_RESTORE_POINT_IDLE_DAYS (Standard 7, 0 deaktiviert) und PAPERCLIP_GIT_RESTORE_POINT_RETENTION_DAYS (Standard 90) regeln verschlüsselte Wiederherstellungspunkte (#17248, #17271, #17241); PAPERCLIP_SKILL_VERSION_RETENTION_ENABLED (Standard true) mit _DRY_RUN (false), _KEEP (0) und _GRACE_MINUTES (60) beschneidet nicht verwendete materialisierte Skill-Versionen (#16433); PAPERCLIP_NATIVE_HARNESS_BACKUP_EXPIRATION_ENABLED (Standard true) mit _DAYS (7) und _DRY_RUN (false) lassen Remote-Sitzungs-Failover-Backups ablaufen. Wenn Sie also ein Problem erneut öffnen, das länger als dieses Fenster geschlossen ist, wird eine neue Anbietersitzung gestartet (#16866). Berichte: PAPERCLIP_SENTRY_RUN_FAILURES (off, unexpected oder all; Standard off) (#16300). Claude-Agenten berücksichtigen auch einen vorhandenen ANTHROPIC_BASE_URL und ANTHROPIC_CUSTOM_HEADERS (#16850).
  • Neue experimentelle Einstellungen, alle standardmäßig deaktiviert: Grok Bot (enableGrokBot), der Assistant-Verbindungen (MCP) erfordert, den Paperclip Runner, authentifizierte Anmeldung und ein HTTPS PAPERCLIP_PUBLIC_URL (#16219); Muse – Persönlicher Agent (enableMuse), der den Runner und öffentliches HTTPS (#16450) erfordert; Artefakte V1 (enableArtifactsV1) (#17228). Speko Voice wird unter der vorhandenen Einstellung Chat-Konnektoren (#15728) und Workflows unter Fälle (#17114) angezeigt. enablePipelines wurde entfernt (#16834). Einstellungen → Verbindungen sind jetzt immer sichtbar und hängen nicht mehr von experimentellen schnellen Antworten ab (#16976).
  • commentary:view für jede menschliche Rolle (#16903): Migration 0359 und Startup-Seeding gewähren die neue Berechtigung jeder aktiven menschlichen Mitgliedschaft, einschließlich Zuschauern, sodass jeder im Unternehmen Audit → Kommentar öffnen kann. Das Löschen dieser Berechtigung von einem Mitglied ist vorübergehend: Beim Startup-Seeding wird beim nächsten Serverstart jede Rollenstandard-Bewilligung für jedes aktive menschliche Mitglied erneut hinzugefügt, und in dieser Version gibt es keine dauerhafte Möglichkeit, sie zurückzuhalten. Der Quell-Aufgaben-Datenschutz filtert immer noch, was jede Person in Kommentaren sieht.
  • Sentry-Operatoren (#16300): PAPERCLIP_SENTRY_RUN_FAILURES=unexpected so einstellen, dass weiterhin Lauffehlerereignisse empfangen werden; Sie sind standardmäßig deaktiviert, auch wenn SENTRY_DSN_BACKEND konfiguriert ist.
  • API clients: Die Ausführungsverlaufsliste ist auf 1.000 Zeilen begrenzt (Standard 200) (#16286); das Feld linkedCases und alle Pipeline-Routen sind verschwunden (#16834); ein PATCH, der executionPolicy ersetzt und done während eines Live-Überprüfungszyklus festlegt, gibt 422 unexecuted_review_stage (#13178) zurück; und alles, was Zusammenfassungsüberschriften von GitHub-Bewertungen analysiert, muss Bot-Namen akzeptieren (#16212).
  • Benutzerdefinierte Docker-Bilder (#16672): Das ausgelieferte Bild beginnt jetzt mit node server/dist-runtime/index.mjs; Bilder, die server/dist/index.js über tsx aufgerufen haben, sollten zum Laufzeitpaket wechseln.
  • Änderung der Standardansichten: Vom Agenten und vom System erstellte Aufgaben werden in den Aufgabenlisten ausgeblendet, bis Sie „Von Agenten erstellte Aufgaben anzeigen“ aktivieren (#16157), und der Posteingang „Mein“ enthält keine Automatisierungen mehr, an denen Sie nicht teilgenommen haben (#16356). – Google Workspace (#15545): Neue Google Workspace-Anfragen hängen vom von Paperclip gehosteten OAuth-Broker-Update ab und ältere Broker lehnen sie ab; Bestehende Google-Verbindungen pro Dienst funktionieren weiterhin.
  • Kabelbaumstifte sind gegenüber v2026.1023.0 unverändert: Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286) und OpenCode 1.18.34. GitHub Copilot wird bei CLI 1.0.88 (#15701) geliefert.
  • Keine weiteren Konfigurations- oder API-Änderungen erfordern Maßnahmen.
