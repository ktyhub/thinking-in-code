Papierclip v2026.1005.0

Veröffentlicht: 05.10.2026

Paperclip v2026.1005.0 enthält 179 Commits, die von 2026.1002.0-beta.0 gefördert werden. Die Schlagzeile lautet: Agenten, die mehr mit sich führen: Grok Build läuft auf dem nativen Runner, Agenten behalten ihre eigenen Dateien aufgabenübergreifend, Unternehmenskompetenzen werden aus GitHub-Repositories synchronisiert und Browser Use Cloud stellt Agenten einen Live-Browser zur Verfügung, den die Leute beobachten und von der Aufgabe aus übernehmen können. Um diese herum: Die meisten Konnektoren sind jetzt in einem click mit standardmäßig aktivierten MCP-Aggregatoren eingerichtet, Slack-Konversationen zirkulieren zwischen dem Board und dem Thread, Agent Chat erhält seine eigene Navigation und übergibt erledigte Arbeit an die Konversation zurück, und der Task-Composer wählt Modell und Aufwand pro Nachricht aus. Darunter schützt ein langer Zuverlässigkeitsdurchgang den nativen Läufer, den Sandbox-Transport und den Heartbeat-Scheduler, einschließlich einer Korrektur für eine Server-Absturzschleife, die durch einen dauerhaft abgelehnten Lauf in der Warteschlange verursacht wird.

Breaking Changes

  • Die Snippet-Injektion der Bediener-UI wurde entfernt. Die Einstellungen PAPERCLIP_CLOUD_UI_SNIPPET und PAPERCLIP_CLOUD_UI_SNIPPET_B64 injizieren kein HTML mehr in statische Seiten oder Entwicklungsseiten. Betreiber, die sich auf sie verlassen haben, sollten die Integration vor dem Upgrade auf einen Plugin-UI-Beitrag verschieben. (#13789)
  • Tastaturkürzel sind immer aktiviert und ihre Einstellungen sind verschwunden. Die instanzweite allgemeine Umschaltung und die benutzerspezifische Profileinstellung wurden zusammen mit den Routen GET/PATCH /api/auth/preferences entfernt. PATCH /api/instance/settings/general akzeptiert keyboardShortcuts nicht mehr. Für jeden angemeldeten Benutzer sind jetzt Verknüpfungen aktiviert. (#14141, #14643)
  • Die @-Erwähnung eines Agenten startet keine Ausführung mehr. Erwähnungen in Aufgabenkommentaren bleiben als Kontext für den Beauftragten erhalten; Nur explizite Zuweisungs- und Überprüfungsanfragen beginnen mit der Arbeit. Workflows, die eine Erwähnung verwendet haben, um einen zweiten Agenten für eine Aufgabe zu gewinnen, müssen stattdessen eine Überprüfung zuweisen oder anfordern. (#14577)

Highlights

  • Grok Build auf dem nativen Runner – Grok Build verbindet den Paperclip Runner über ACP sowohl für die lokale als auch für die Daytona-Ausführung, mit separaten Abonnement-Login- und API-Schlüssel-Anmeldeinformationspfaden und geregelten Tools (#13882); Es wird bei öffentlichen Installationen mit Sandbox-eigenen Binärdateien ausgeliefert und nicht zum Zeitpunkt der Installation heruntergeladen (#14024). Die gemeinsam genutzten Harness-Laufzeiten werden zu Codex 0.156.0, Claude Agent SDK 0.3.280 und OpenCode 1.18.32 (#13838) verschoben. Modellkataloge und Reasoning-Steuerelemente werden für die Claude-, Codex-, Grok-, Gemini-, Cursor-, Kimi- und OpenCode-Adapter (#13829) und Remote Native aktualisiert Codex akzeptiert kompatible Versionen von 0.149.0 anstelle eines genauen Pins (#13853).
  • Agenten behalten ihre eigenen Dateien – Das Verzeichnis eines Agenten (AGENTS.md und seine unterstützenden Dateien) bleibt jetzt über Aufgaben und Sitzungen hinweg bestehen und wird mit dem Anweisungen-Editor geteilt; Bei gleichzeitigen Ausführungen werden nur die Dateien angewendet, die sie geändert haben, und bei neuen Speicherungen wird kein Revisionsverlauf mehr erstellt (#14420), zusätzlich zu einem neuen einfachen Verzeichnissynchronisierungstransport mit Konflikt-Preflight (#14416). Warme native Codex-Sitzungen überleben die Sammlung verwalteter Dateien, indem sie nach jeder Runde nur geänderte Dateien mit einem Prüfpunkt versehen (#14735).
  • Skills synchronisiert von GitHub – Skills erhalten eine Registerkarte „Quellen“: Wählen Sie über eine bestehende GitHub-Verbindung ein Repository aus, wählen Sie aus, welche Skill-Ordner importiert werden sollen, und aktualisieren Sie sie bei Bedarf. Installierte Snapshots bedeuten, dass Agenten GitHub während der Ausführung nie abrufen und bei einer fehlgeschlagenen Aktualisierung die letzte gute Version erhalten bleibt (#14713).
  • Browser Use Cloud, live in der Aufgabe – Ein neuer Browser Use Cloud-Connector bietet Agenten eine gesteuerte Browserautomatisierung, und Aufgaben zeigen interaktive Browser-Registerkarten an, in denen Benutzer mitverfolgen, die Seite übernehmen und den Browser nach Abschluss der Ausführung behalten können, wobei die Kosten für die Ausführung erfasst werden (#14627).
  • In einem click eingerichtete Verbindungen – Das Connector-Setup wird auf einen Bildschirm reduziert, der seine Standardeinstellungen angibt und den Rest hinter „Ändern“ und der Registerkarte „Berechtigungen“ verbirgt (#14811). Die MCP-Aggregatoren Zapier, Arcade, Composio Connect und Executor sind standardmäßig aktiviert, wobei der experimentelle Schalter entfernt wurde (#13964) und sie können über Inline-Aufgabenkarten konfiguriert werden (#13879). Die Verbindungssuche bevorzugt native Apps, fordert den Benutzer vor der Einrichtung auf, einen externen Anbieter auszuwählen (#13941) und versteht Abfragen in natürlicher Sprache (#14725). Neu im Katalog: Fireflies mit zusammenfassungsbereiten Routinen (#13890), fünf experimentellen Speicheranbietern (Mem0, Zep, Supermemory, Cognee, Honcho) hinter der standardmäßig deaktivierten enableMemoryConnectors-Einstellung sowie zugewiesenen MCP-Tools, die für Remote-nativen Codex bereitgestellt werden (#13942) und GitHub Code Review Bot als eigene, separate Karte GitHub-Werkzeuge (#14750). Persönlich eingefügte Anmeldeinformationen werden bei Einrichtung, Zustandsprüfung und Aufruf auf die gleiche Weise validiert, und neue Verbindungen fordern die Schreibbereiche an, die ihre Aktionen benötigen (#14739).
  • Slack geht in beide Richtungen – Auf dem Forum eingegebene Antworten erreichen den verknüpften Slack-Thread und setzen die gleiche Konversation fort, und zugewiesene Agenten erhalten ihre Slack-Tools während gewöhnlicher Aufgaben und geplanter Routinen (#13920). Slack-Origin-Aufgaben erhalten geregelte Tools, um die umgebende Diskussion zu lesen, Follow-ups zu erstellen und über den einladenden Bot zusammenzuarbeiten (#13828), und eine beantwortete Konversation wird auf „Leer“ gesetzt, anstatt auf „In Bearbeitung“ zu verweilen (#13809).
  • Agent Chat wird erwachsen – Eine sekundäre Chat-Seitenleiste und Landingpage geben Gesprächen ein eigenes Zuhause (#14706); Von einem Chat delegierte Aufgaben übermitteln ihre Erledigung dauerhaft an diesen (#14408); Eine im Chat eingegebene eindeutige Genehmigung löst die ausstehende Karte auf und unbeantwortete Fragen werden in den Verlauf verschoben, wo sie später beantwortet werden können (#14613); und ein Chat wird fortgesetzt, nachdem sein nativer Worker verloren gegangen ist (#13813).
  • Ein Composer, der den Lauf auswählt – Der Task Composer erhält ein nachrichtenbasiertes Modell und eine Aufwandsauswahl, die dem ausgewählten Agenten folgt, ausstehende Karten darüber sichtbar hält und auf Mobilgeräten funktioniert (#14322); Die Aufwandsoptionen entsprechen dem, was jeder Adapter tatsächlich ausführt, einschließlich Codex auf dem nativen Läufer (#14568, #14576). Aufgaben können allein aus einer Eingabeaufforderung erstellt werden und der zugewiesene Agent benennt sie (#14761). Artefakte erhalten umfangreiche Karten mit Vorschauen (#14469), einer Bilder- und Videogalerie mit Links zu vollständigen Zeilen (#13825) und Markdown- und Textanhängen, die in Aufgabenregisterkarten mit gerenderten, rohen und Download-Ansichten geöffnet werden (#14297).
  • Gesteuerte API-Tools, standardmäßig aktiviert – Die search_api- und call_api-Tools des nativen Läufers sind ohne Umgebungsvariable aktiviert (#14186); Große API-Antworten werden bis zu 1 GiB auf die Festplatte gestreamt und gespeicherter Text ist in begrenzten Seiten lesbar (#14301); und wenn ein zugewiesener App-Katalog die Grenze des Tool-Vertrags überschreitet, erreichen Agenten diese Tools immer noch über Suche und Anruf (#14218).

Korrekturen

– Native Runner und Sitzungen – Tool-Ergebnisse überleben das Herunterfahren und Neustarten, anstatt einen falschen Fehler aufzuzeichnen (#14734); Fehlgeschlagene Warm-Sitzungen werden zurückgezogen, bevor ihre Sandbox stoppt (#14747) und die wiederhergestellte Bereinigung berücksichtigt das Endergebnis des Laufs (#14767); Beim Wechseln einer Aufgabe in einen warmen Lebenszyklus wird eine wiederverwendbare Lease erworben (#14187); Der OpenCode-Ereignisstrom bleibt über Runden hinweg geöffnet (#14582) und liefert seine Abschaltberechnung (#14668); Codex-Kontobenachrichtigungen brechen eine Runde nicht mehr ab (#13902); Die Erschöpfung des Claude- und Codex-Kontingents wird für den ordnungsgemäßen Backoff klassifiziert (#13831, #13945); ACP-Terminalfehler behalten ihre redigierten Provider-Diagnosen bei (#14573) und Identitätswächter benennen die fehlgeschlagene Prüfung (#14481); Das Leselimit für native Journale beträgt überall 256 MiB (#14711); Die ausstehende Finalisierung eines akzeptierten Ergebnisses ist vor dem Stale-Lock-Sweep geschützt (#14219); Adapter machen einen verifizierten Anbieterstopp vor der Wiederherstellung des Arbeitsbereichs verfügbar (#14311); Warme Sitzungen werden unter verwaltetem GitHub-Zugriff weiter ausgeführt (#13815); und ein Lauf, der auf einen Anbieterauthentifizierungsfehler stößt, bietet eine Inline-Verbindungskarte in der Aufgabe an, damit der Benutzer reparieren und fortfahren kann (#14629).

  • Sandboxen und Arbeitsbereiche – Daytona-Befehle bleiben aktiv, nachdem der Log-Socket geschlossen wurde (#14799), bestätigter Containerverlust wird bei der Wiederaufnahme von Leases erkannt (1f3ff75d), fehlgeschlagene Zuordnungen werden bereinigt (#13979) und Zeitüberschreitungen bei der Provider-Erfassung berücksichtigen die Standardeinstellung des Treibers (#14097). ACP-Eingabeübermittlungsversuche nach einem Gateway 502 ohne duplizierte Eingabe (#14485), übergroße Startnutzlasten und duplizierter Wake-Kontext schlagen mit E2BIG nicht mehr fehl (#13793, #13891), Prozess-Proxys werden nach dem Remote-Beenden geschlossen (#13777) und relative Symlinks in sekundären Repositorys bleiben erhalten (#13953). Workspace-Exporte werden sicher abgeschlossen und wiederhergestellt (#14402), Wiederherstellungsfehler behalten das Ergebnis des Adapters bei und zeichnen auf, was fehlgeschlagen ist (#14035, #14064), große Git-Snapshots streamen über Festplattenmanifeste, anstatt ein Ausgabelimit von 1 MiB zu erreichen (#14194, #14253), Bereitschaftsprüfungen akzeptieren größere Statusausgaben (#14414), Hintergrundscans stoppen die Aktualisierung des Git-Index (#14666), Teilaufgabenüberschreibungen behalten Projekt-Setup-Befehle bei (#14502) und Repository-freie Low-trust-Aufgaben erhalten ein privates Verzeichnis (#14766).
  • Planer und Wiederherstellung – Eine Ausführung in der Warteschlange, deren Anspruch dauerhaft abgelehnt wird, wird abgebrochen, anstatt den Server in eine Absturzschleife zu versetzen (#14738); Nachläufe, die während eines Drains eintreffen, bleiben in der Warteschlange und unterbrochene Korrekturläufe erhalten einen vorübergehenden Wiederholungsversuch (#14028); Ein Problem, dessen Ausführung sein Wiederholungsbudget aufgebraucht hat, wird in einen sichtbaren blockierten Zustand eskaliert und nicht für immer übersprungen (#14046); Fortsetzungs- und Wiederholungsbudgets verwenden dauerhaften Status (#13888); Der Aufgabenbesitz wird atomar bei Ausführungen in der Warteschlange beansprucht (#13973); veraltete Fortsetzungen werden vor dem Versand storniert (#13761); eine Statusantwort, die weiterhin blockierende Arbeiten auflistet, hält die Aufgabe in Bewegung (#14626); Erledigte und abgebrochene Aufgaben behalten ihren Beauftragten bei der Freigabe (#14561); Interaktionsfortsetzungen bleiben auf ihre Aufgabe beschränkt (ded156a9) und Fragenempfänger werden abgeleitet und validiert (#14742); Von Slack und Discord stammende Aufgaben, die ihren Überprüfungspfad verlieren, werden mit intakten Nachrichtenbindungen wiederhergestellt, anstatt die Wiederherstellungsautorisierungsprüfung nicht zu bestehen (#13818); Remote-GRK-Ausführungen werden angehalten, bevor Nachrichten in der Warteschlange fortgesetzt werden (#14100); Run-Identity-Sperren blockieren nicht mehr mit Audit-Einfügungen (#14478); und mehrdeutige Datenbanktrennungen werden nicht mehr wiedergegeben (#14773).
  • Verbindungen und Apps – OAuth-Anmeldeherausforderungen und Wiederverbindungsstatus geben 422 zurück, anstatt als Abstürze gemeldet zu werden (#13786, #13794); MCP-OAuth-Setup erklärt fehlgeschlagene oder abgebrochene Zustimmung (#13855); Eine deaktivierte Slack MCP-App erhält umsetzbare Einrichtungsanweisungen (a7d3b17a); Bei Broker- und AgentMail-Fehlern bleiben die Ursachencodes auf der Zulassungsliste (#14098, #14768); Google Chat und die Profile „Dokumente“, „Tabellen“, „Folien“ und „Kalender“ erfordern weniger Bereiche (#13820, #14740); Arbeitsprodukte validieren ihre Ausführungsarbeitsbereichsreferenz (#14063); und fehlerhafte CLI-Authentifizierungs-Challenge-IDs geben 400 zurück (#14095).
  • Board-Benutzeroberfläche – Das Board stellt sich bei Serverneustarts mit einer Verbindungsmeldung und erneuten Versuchen wieder her, wobei offene Editoren gemountet bleiben (#14560) und bietet einen Wiederholungsbildschirm, wenn die App fehlschlägt, bevor React startet (#13970). Die Codehervorhebung stürzt nicht mehr bei einer Nichtübereinstimmung der Lezer-Version ab (a3749aac), destruktive Bestätigungsschaltflächen sind im hellen Design lesbar (#14328), mobile Auswahlmöglichkeiten bleiben über der Tastatur sichtbar und scrollen per Berührung (#14022, #14249, #14250, #14599), neuere Entwürfe überleben die Quittungsbereinigung (#14332), fehlgeschlagene Ausführungen anderer Benutzer bleiben bei mir außen vor (#14572), „Wiederherstellung erforderlich“ wird von „Wiederherstellung in Bearbeitung“ unterschieden. (#14326) und ein irreführender Wiederholungsversuch wird nicht mehr angezeigt, wenn die Wiederherstellung blockiert ist (#13775), neue Artefakte registrieren eine Registerkarte, ohne das Bedienfeld zu öffnen (#14193), das Aufgabenfeld zeigt Vorgänger an (#13823) und Aufgabeninhalte werden bei parallelen Serverlesevorgängen früher angezeigt (#14727). Außerdem: Eigenschaftssymbole werden an Avataren ausgerichtet (#13319), Läuferkommentare werden an Antworten ausgerichtet (#14716), Projektspeicherindikatoren werden unter ihrer Beschriftung gestapelt (#14765), Archivierung eines Unternehmens navigiert weg (#13846), experimentelle Einstellungen werden alphabetisch sortiert, wobei leere Gruppen ausgeblendet werden (#13905), und der Cursor-Adapter wählt den tatsächlichen Fehler über einen Ablaufverfolgungshinweis aus (#14636).
  • Beobachtbarkeit – Browserfehler übertragen SENTRY_ENVIRONMENT (#13784) und begrenzten Komponentenkontext (#13904); Ausführungsfehler werden von späteren Ausnahmen isoliert und ein Laufzeitfunktionsheader wird geschwärzt (#13826); und Lauffehlerberichte behalten Exitdetails, Stapel, Ursachen, Laufzeitaktivität und Wiederherstellungsklassifizierung bei (#14575, #14585, #14665, #14639, #14787).

Verbesserungen

– Das Kontomenü entfernt seine Profilzeilen für einen Header-Link und erhält eine Einladungsverknüpfung (#14480); Plugins können einen Organisationsumschalter bereitstellen (#13832, #13854); PAPERCLIP_HIDDEN_SETTINGS akzeptiert einen Platzhalter mit benannten Ausnahmen, sodass neue experimentelle Flags automatisch ausgeblendet bleiben (#13980) und ein workspaces.isolation-Schlüssel Isolationskontrollen verbirgt (#13907); Der native Läufer erhält eine gemeinsame Rich-ACP-Transportgrundlage für kommende Cursor-, GitHub-Copilot- und Pi-Anbieter (#14430); Native Agents können Teamkollegen über eine geregelte hire_agent-Aktion einstellen, die die Laufzeitkonfiguration des Anrufers von einer geschlossenen Zulassungsliste übernimmt (#13852); Die Koordinationsfähigkeit weist Agenten nicht mehr an, über Manager zu eskalieren, anstatt den Menschen zu fragen, wer handeln kann (#14188); Worktree-Seed-Source-Fehler erklären die unterstützten Setups (#14795); Google Workspace-Konnektoren werden vorübergehend auf der Seite „Verbindungen“ ausgeblendet, während die Google OAuth-Überprüfung aussteht, wobei gespeicherte Verbindungen und Laufzeitzugriff unverändert bleiben (#14774); und die README-Datei wird mit aktuellen Kabelbäumen, Anleitungslinks und einem npx-first-Schnellstart (#14741, #14744) aktualisiert.

Upgrade-Anleitung

  • Migrationen 0284–0293 werden beim Upgrade ausgeführt: 0284 fügt die benutzerspezifische Spalte keyboard_shortcuts hinzu und 0289 löscht sie; 0285 erweitert assets.byte_size auf bigint; 0286 fügt API-Antworterfassungsreservierungen hinzu; 0287 fügt Agenten-Anweisungsköpfe, Revisionen und Arbeitskopien für persistente Agentendateien hinzu; 0288 fügt Chat-Abschlusslieferungen und Aufgabenübergaben hinzu; 0290 fügt Browser Use Cloud-Sitzungen, -Läufe und -Browser hinzu; 0291–0292 fügt Unternehmens-Skill-Quellen und -Einträge hinzu, und 0291 übernimmt auch vorhandene, aus github.com importierte Skills (eine Quelle pro Repository und Tracking-Referenz, ein Eintrag pro Skill und legacySkillSourceId/skillSourcePath in die Metadaten jedes Skills eingeprägt; von GitHub Enterprise-Hosts importierte Skills, gebündelte Skills und Katalog-Skills bleiben unverändert, und es erfolgen keine Anbieteranfragen oder Inhaltsumschreibungen); 0293 fügt issues.title_needs_generation hinzu. – Operator-UI-Snippets werden entfernt (#13789): PAPERCLIP_CLOUD_UI_SNIPPET und PAPERCLIP_CLOUD_UI_SNIPPET_B64 werden ignoriert. Verschieben Sie die Integration vor dem Upgrade in einen Plugin-UI-Beitrag.
  • Tastaturkürzeleinstellungen werden entfernt (#14643): Löschen Sie alle Automatisierungen, die /api/auth/preferences aufrufen oder keyboardShortcuts an die allgemeine Einstellungsroute senden.
  • Agentenerwähnungen werden nicht mehr weitergeleitet (#14577): Verwenden Sie eine Zuweisung oder eine Überprüfungsanfrage, um einen anderen Agenten für eine Aufgabe zu gewinnen.
  • Neue Standardeinstellungen: Die API-Tools des nativen Läufers sind aktiviert, es sei denn, PAPERCLIP_RUNNER_API_TOOLS_ENABLED ist auf etwas anderes als true eingestellt; PAPERCLIP_RUNNER_API_TOOLS_COMPANY_IDS schränkt sie immer noch ein (#14186). Die MCP-Aggregatoren sind ohne das frühere enableMcpAggregators-Flag verfügbar (#13964). – Neue Umgebungsvariablen, alle optional: PAPERCLIP_RUNNER_API_COMPANY_CAPTURE_MAX_BYTES begrenzt die erfassten API-Antwortbytes pro Unternehmen (Standard 20 GiB, mindestens 1 GiB; #14301); PAPERCLIP_WORKSPACE_GIT_SNAPSHOT_TIMEOUT_MS begrenzt die Snapshot-Zeit des Arbeitsbereichs (Standard 30 Minuten, maximal 24 Stunden) und PAPERCLIP_WORKSPACE_MANIFEST_MIN_FREE_BYTES legt die freie Festplattenreserve für Snapshot-Manifeste fest (Standard 256 MiB, Minimum 64 MiB; #14253). Codex ACP-Läufe akzeptieren CODEX_API_KEY als Alternative zu OPENAI_API_KEY (#14322).
  • Kabelbaumstifte verschoben zu Codex 0.156.0, Claude Agent SDK 0.3.280 und OpenCode 1.18.32 (#13838); Gemeinsam genutzte Installationen sollten ihre Anbieter-CLIs entsprechend aktualisieren.
  • Keine weiteren Konfigurations- oder API-Änderungen erfordern Maßnahmen.
