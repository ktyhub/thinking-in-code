graphql-java v25.0

Wichtige Änderungen

Datenlader

Refactoring-Strategie

Die bestehende PerLevelDataLoaderStrategy wurde überarbeitet, was zu Vereinfachungen und Leistungsverbesserungen führte.

Neue Strategien

Es wurden zwei neue Strategien eingeführt: CHAINED und EXHAUSTED. Beide können über UnusalConfiguration konfiguriert werden (siehe nächster Abschnitt).

CHAINED ermöglicht die Verwendung verketteter DataLoader unter Beibehaltung einer Versandstrategie pro Ebene.

EXHAUSTED ist eine völlig neue Strategie, die darauf basiert, zu versenden, sobald der Motor nicht ausgelastet ist. Es spiegelt die Dispatch-Strategie des JS-Datenladers wider, jedoch für ein Multithread-System.

Ungewöhnliche Konfiguration

Für „ungewöhnliche Konfigurationen“ wurde ein allgemeinerer Konfigurationsmechanismus hinzugefügt. Damit meinen wir eine Konfiguration, von der wir nicht erwarten, dass sie von vielen Leuten verwendet wird, aber wenn sie es jetzt an einem häufigeren Ort tun

Wenn Sie beispielsweise die maximale Tiefe ändern möchten, die der Dokumentparser akzeptiert, können Sie die folgenden Methoden aufrufen.

        var parserOptions = newParserOptions().maxRuleDepth(99).build()
        GraphQL.unusualConfiguration().parsing().setDefaultParserOptions(parserOptions)

JAnmerkungen angeben

Das Team beginnt damit, https://jspecify.dev/-Annotationen als Möglichkeit zur Angabe von Nullable- und Nicht-Nullable-Feldern zu nutzen. Bei vielen wichtigen Klassen wurden diese Anmerkungen hinzugefügt, um semantisch klarer zu machen, wann ein Wert null sein kann oder nicht.

Breaking Changes

Aus Leistungsgründen wird bei Feldabrufern nicht immer ein umschließendes FetchedValue-Objekt zurückgegeben. Das bedeutet, dass graphql.execution.instrumentation.parameters.InstrumentationFieldCompleteParameters#getFetchedObject als Ersatz für die ältere Methode getFetchedValue erstellt wurde und das Rückgabeobjekt manchmal ein FetchedValue oder manchmal ein einfacher POJO-Wert sein kann.

Leistungsverbesserungen

Es wurden eine Reihe von Leistungsverbesserungen vorgenommen, um den Speicherbedarf der Bibliothek zu reduzieren. Außerdem kann der Java-Operator .stream() langsamer sein als eine direktere Schleife und viele dieser Aufrufe wurden aus Leistungsgründen geändert.
