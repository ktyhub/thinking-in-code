Firecrawl v2.8.0

v2.8.0

Firecrawl v2.8.0 ist da!

Firecrawl v2.8.0 bringt wesentliche Verbesserungen für Agenten-Workflows, Entwicklertools und selbst gehostete Bereitstellungen in den API- und SDK-Modellen, einschließlich unseres neuen Skills.

  • Parallele Agenten zum gleichzeitigen Ausführen Tausender /agent-Abfragen, unterstützt durch unser neues Spark 1 Fast-Modell.
  • Firecrawl CLI mit vollständiger Unterstützung für Scrape-, Search-, Crawl- und Map-Befehle.
  • Firecrawl-Fähigkeit, um KI-Agenten (Claude Code, Codex, OpenCode) die autonome Nutzung von Firecrawl zu ermöglichen.
  • Drei neue Modelle, die /agent antreiben: Spark 1 Fast für den sofortigen Abruf (derzeit nur in Playground verfügbar), Spark 1 Mini für komplexe Forschungsanfragen und Spark 1 Pro für erweiterte Extraktionsaufgaben.
  • Agentenverbesserungen, einschließlich Webhooks, Modellauswahl und neue MCP-Server-Tools.
  • Plattformweite Leistungsverbesserungen, einschließlich schnellerer Suchausführung und optimierter Redis-Aufrufe.
  • SDK-Verbesserungen, einschließlich Zod v4-Kompatibilität.

Und noch viel mehr, schauen Sie es sich unten an!

Neue Funktionen

  • Parallele Agenten
    Führen Sie Tausende von /agent-Abfragen parallel mit automatischer Fehlerbehandlung und intelligenter Wasserfallausführung aus. Unterstützt durch Spark 1-Fast für sofortigen Abruf, automatisches Upgrade auf Spark 1 Mini für komplexe Abfragen, die eine umfassende Recherche erfordern.

  • Firecrawl CLI
    Neue Befehlszeilenschnittstelle für Firecrawl mit vollständiger Unterstützung für Scrape-, Search-, Crawl- und Map-Befehle. Mit npm install -g firecrawl-cli installieren.

  • Feuerkriecher-Fertigkeit
    Ermöglicht Agenten wie Claude Cursor, Codex und OpenCode die Verwendung von Firecrawl für Web-Scraping und Datenextraktion, installierbar über npx skills add firecrawl/cli.

  • Spark-Modellfamilie
    Drei neue Modelle, die /agent antreiben: Spark 1 Fast für den sofortigen Abruf (derzeit in Playground verfügbar), Spark 1 Mini (Standard) für alltägliche Extraktionsaufgaben zu 60 % geringeren Kosten und Spark 1 Pro für komplexe Multi-Domain-Forschung, die maximale Genauigkeit erfordert. Spark 1 Pro erreicht eine Rückrufquote von ca. 50 %, während Mini eine Rückrufquote von ca. 40 % erreicht. Beide Tools übertreffen die Tools, die pro Aufgabe vier- bis siebenmal teurer sind, deutlich.

  • Firecrawl MCP Server Agent Tools
    Neue Tools firecrawl_agent und firecrawl_agent_status für die autonome Webdatenerfassung über MCP-fähige Agenten.

  • Agent-Webhooks
    Der Agent-Endpunkt unterstützt jetzt Webhooks für Echtzeitbenachrichtigungen über Auftragsabschluss und -fortschritt.

  • Auswahl des Agentenmodells
    Der Agent-Endpunkt akzeptiert jetzt einen model-Parameter und schließt Modellinformationen in Statusantworten ein.

  • Multi-Arch Docker-Bilder
    Selbstgehostete Bereitstellungen unterstützen jetzt zusätzlich zu amd64 auch die linux/arm64-Architektur.

  • Nur Sitemap-Crawling-Modus
    Neue Crawl-Option, um ausschließlich Sitemap-URLs zu verwenden, ohne Links zu folgen.

  • ignoreCache Kartenparameter
    Neue Option zum Umgehen zwischengespeicherter Ergebnisse beim Zuordnen von URLs.

  • Benutzerdefinierte Header für /map
    Der Kartenendpunkt unterstützt jetzt benutzerdefinierte Anforderungsheader.

  • Hintergrundbildextraktion
    Scraper extrahiert jetzt Hintergrundbilder aus CSS-Stilen.

  • Verbesserte Fehlermeldungen
    Alle benutzerseitigen Fehlermeldungen enthalten jetzt detaillierte Erklärungen, die bei der Diagnose von Problemen helfen.

API Verbesserungen

  • Suche ohne Parallelitätsbeschränkungen – Scrapes in der Suche werden jetzt direkt ohne Warteschlangenaufwand ausgeführt.
  • Geben Sie 400 für nicht unterstützte Aktionen mit eindeutigen Fehlern zurück, wenn angeforderte Aktionen von verfügbaren Engines nicht unterstützt werden.
  • Die Job-ID ist jetzt in den Suchmetadaten enthalten, um die Nachverfolgung zu erleichtern.
  • Metadatenantworten enthalten jetzt die erkannte Zeitzone.
  • Füllen Sie den Metadatentitel von og:title oder twitter:title auf, wenn er fehlt.
  • Behalten Sie den Parameter gid bei, wenn Sie Google Sheets-URLs neu schreiben.
  • Der v2-Pfad in der Batch-Scrape-Status-Paginierung wurde korrigiert.
  • Überprüfen Sie die Teameigentümerschaft, wenn Sie sie an bestehende Crawls anhängen.
  • Screenshots mit benutzerdefiniertem Ansichtsfenster oder Qualitätseinstellungen umgehen jetzt den Cache.
  • Optimierte Redis-Aufrufe über Endpunkte hinweg.
  • Reduziert übermäßiges Abrufen und Parsen von robots.txt.
  • Minimaler Timeout-Parameter für Anfragen jetzt konfigurierbar.

SDK Verbesserungen

JavaScript SDK

  • Zod v4-Kompatibilität – Schemakonvertierung funktioniert jetzt mit Zod v4 mit verbesserter Fehlererkennung.
  • Watcher-Exporte – Watcher und WatcherOptions werden jetzt vom Einstiegspunkt SDK exportiert.
  • Agent-Webhook-Unterstützung – neue Webhook-Optionen für Agentenanrufe.
  • Fehler beim erneuten Abfrageversuch – SDK wiederholt den Abfragevorgang nach vorübergehenden Fehlern.
  • Job-ID in Ausnahmen – Fehlerausnahmen enthalten jetzt jobId zum Debuggen.

Python SDK

  • Manuelle Paginierungshilfen zum Durchlaufen der Ergebnisse.
  • Agent-Webhook-Unterstützung zum Agenten client hinzugefügt.
  • Der Agent-Endpunkt akzeptiert jetzt Modellauswahlparameter.
  • Metadaten enthalten jetzt Informationen zur Parallelitätsbeschränkung.
  • Die Behandlung von max_pages in Crawl-Anfragen wurde korrigiert.

Dashboard-Verbesserungen

  • Der Dunkelmodus wird jetzt unterstützt.
  • Auf der Nutzungsseite können Sie die Guthabennutzung jetzt nach Tagen aufgeschlüsselt anzeigen.
  • Auf der Seite „Aktivitätsprotokolle“ können Sie jetzt nach dem verwendeten Schlüssel API filtern.
  • Das Ausgabeformat „Bilder“ wird jetzt im Playground unterstützt.
  • Alle Administratoren können jetzt die Abonnements ihres Teams verwalten.

Qualität und Leistung

  • Markdown-Konvertierungsprüfungen für große HTML-Dokumente überspringen.
  • Exportieren Sie Google Docs als HTML statt als PDF, um die Leistung zu verbessern.
  • Verbessertes Branding-Format mit besserer Logo-Erkennung und Fehlermeldungen für PDFs und Dokumente.
  • Verbesserte Leistung beim Laden von lopdf-Metadaten.
  • Aktualisiertes html-to-markdown-Modul mit mehreren Fehlerbehebungen.
  • Erhöhtes Markdown-Service-Body-Limit und hinzugefügte Anforderungs-ID-Protokollierung.
  • Bessere Sentry-Filterung für abgebrochene Aufträge und Engine-Fehler.
  • Die Extrakt-Rennbedingungen und die Handhabung von RabbitMQ-Giftpillen wurden korrigiert.
  • Zentralisierte Firecrawl-Konfiguration in der gesamten Codebasis.
  • Mehrere Sicherheitslücken wurden behoben, darunter CVE-2025-59466 und die Verschmutzung durch den Lodash-Prototyp.

Selbstgehostete Verbesserungen

  • CLI benutzerdefinierte API-URL-Unterstützung über firecrawl --api-url http://localhost:3002 für lokale Instanzen.
  • ARM64 Docker-Unterstützung über Multi-Arch-Images für Apple Silicon- und ARM-Server.
  • Die docker-Compose-Datenbankanmeldeinformationen wurden sofort behoben.
  • Der Start des Playwright-Dienstes wurde durch Probleme mit dem Chromium-Pfad behoben.
  • Node.js wurde auf die Hauptversion 22 anstelle einer angehefteten Nebenversion aktualisiert.
  • RabbitMQ-Gesundheitsprüfungsendpunkt hinzugefügt.
  • Die PostgreSQL-Port-Belichtung in docker-compose wurde behoben.
