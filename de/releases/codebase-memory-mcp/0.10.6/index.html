codebase-memory-mcp v0.10.6

Zwei Geschichten in einer Version: Die Verlangsamung der 0.10.x-Indizierung ist verschwunden und die Installation Fehler, die v0.10.5 überstanden haben, werden behoben – einschließlich aller Konstrukte aus den von Ihnen konfigurierten Konfigurationen hat uns geschickt. Wenn cbm seit 0.9.0 für Sie langsamer geworden ist oder install Ihren Hermes immer noch abgelehnt hat, goose, OpenCode oder Codex config, das ist die richtige Version.

Das Indexierungsregressionsprogramm (#1669)

Seit 0.10.0 war die Indizierung großer Repos von langsamer zu unbrauchbar geworden – Java 6x schlechter, C# 2.6×, TypeScript 2×. Die Ursache war nicht ein einzelner Fehler, sondern eine Familie: Arbeit pro Datei, die skaliert wurde mit dem gesamten Korpus. Alles ist fest, gemessen auf demselben Host gegen denselben Korpora wie die Berichte:

  • Java 477 s → 86 s (elasticsearch): Durch die dateiübergreifende Auflösung wurde eine Registrierung für alle neu erstellt Definition im Korpus pro Datei. Es wird jetzt einmal erstellt und mit einer Datei pro Datei geteilt Overlay für lokale Symbole.
  • C# 1211 s → 450 s (Dotnet/Runtime), jetzt mit 48 % mehr Kanten als 0.9.0: drei Korpusproportionale Scans wurden beseitigt, außerdem wurde ein Importkontextfehler behoben, der stillschweigend behoben wurde Unterdrückung von C#-Nutzungsgrenzen – eine 147 KB große generierte Datei wurde von 490 s auf 6.8 s erhöht. – TypeScript 37 s → ~24 s (microsoft/TypeScript): der Ausdruckstyp-Evaluator Gemeinsame Unterausdrücke einmal pro umschließender Alternative neu bewertet – 2^n bei TSC-Kompilierung Ketten ausbreiten. Bei einem Memo pro Knoten handelt es sich um eine Auswertung pro Knoten. die pathologische Akte aus der TS-Konformitätssuite sank von 20 s auf praktisch Null.
  • Linux-Speichervergrößerung behoben (#1654): v0.10.4 konnte einen 36-GB-Computer mit OOM versehen, der einen Baum indizierte v0.9.0 wurde in 13 Minuten bearbeitet. Die Linux-Arena-Commit-Standardeinstellung von mimalloc wird wiederhergestellt.
  • Es bleibt behoben: Eine neue Complexity Guard Suite läuft in CI auf jeder Plattform und allen Fahrten auf Zähler-Verhältnissen (niemals Wandzeit), wenn ein Pipeline-Durchgang wieder superlinear wird, und CBM_PROFILE=1 druckt jetzt Zeitangaben pro Durchgang aus jeder Produktionsbinärdatei.

Installieren: die Konstrukte aus Ihren echten Konfigurationen

Hermes (#1631, gemeldet von @iandol und Galaxy-VN, root-verursacht mit einem isolierten Repro von @rg6304): Vier normale YAML-Stücke führten dazu, dass install dauerhaft ausfiel – leerer Durchfluss Sammlungen (plugins: [], tool_choice: {}), Blocksequenzen in Spalte 0, in doppelte Anführungszeichen gesetzt Zeichenfolgen werden mit einem nachgestellten \ und Apostrophen in der Wortmitte (LET'S GO in einer Persona) fortgesetzt string öffnete ein „Zitat“, das nie geschlossen wurde). Alle vier werden jetzt akzeptiert; Zitate und Anker sind nur dort Indikatoren, wo ein Wert beginnt, die gleiche Regel, die auch im *-Fix verwendet wird v0.10.4. Die vollständigen Konfigurationen beider Reporter – jeweils 15 KB – werden durchgängig mit jedem installiert Originalbyte bleibt erhalten.

Einträge, die wir selbst geschrieben haben, werden wieder erkannt. Ältere cbm-Versionen schrieben command: nicht zitiert; der Gänseblock hat ein Pflichtfeld gewonnen; Ihr Eintrag wurde dann als „ausländisch“ deklariert für immer. Ein Eintrag unter unserem Schlüssel, der einer Form entspricht, die in einer früheren Veröffentlichung geschrieben wurde – oder dessen Befehl unsere Binärdatei auf einem verschobenen Pfad ist – wird an Ort und Stelle repariert. Wirklich ausländische Einträge werden weiterhin byte-unberührt abgelehnt.

goose (#1673 + #1675): Der Erweiterungsblock trägt jetzt den Parser des name-Feldes goose erfordert – zuvor hat goose den Eintrag stillschweigend gelöscht und die Installation war „erfolgreich“. unsichtbar. envs: {} in einem Geschwister bricht den Schreibvorgang nicht mehr ab (Community-Fix von @pcristin – ein Modellbeitrag, zusammengeführt wie er ist). Alte Blöcke werden beim Upgrade repariert. OpenCode / annotierte MCP-Einträge (#1630, #1582): wenn ein client Schlüssel zu unserem Eintrag hinzufügt („enabled“: true und Freunde), Reparaturen ersetzen jetzt nur noch den Befehlswert – Kommentare und client-Schlüssel bleiben wörtlich erhalten. Und der Besitzvergleich ist unabhängig von Trennzeichen: ein Eintrag Das Speichern von C:\...\codebase-memory-mcp.exe ist dieselbe Binärdatei wie die des Installationsprogramms C:/.../codebase-memory-mcp.exe. Die von @gotspatel gepostete Konfiguration war die Datei, die geknackt wurde dieses nach Beharrlichkeit über vier Veröffentlichungen hinweg.

Von Windows erstellte Konfigurationen mit einem UTF-8-BOM (#1656): Set-Content von PowerShell schreibt a Byte-Reihenfolge-Marke, und jede YAML-Bearbeitung an solchen Dateien schlug fehl, unabhängig vom Inhalt – die Der Reporter bewies die Inhaltsunabhängigkeit mit einer 26-Byte-Datei, und diese 26 Bytes gehörten ihnen 23-Byte-Steuerung plus genau die Stückliste. Es wird jetzt als Prolog behandelt: übersprungen Struktur, beim Schreiben erhalten.

Codex (#1633, schließt den Rest von @spam0115 aus #1580): Der Hook-Reconciler akzeptiert Das verwaltete Hook-Paar v0.10.2 hat geschrieben (einschließlich der Windows CRLF+BOM-Variante) und schreibt neu es an Ort und Stelle; Ablehnungen benennen jetzt ihren Grund, anstatt allgemein zu scheitern.

Windows: Die DACL hört auf, Sie zu bekämpfen

Die Sicherheitsbeschreibung des Laufzeitverzeichnisses wurde bei jedem Prozessstart neu gestempelt. ob etwas nicht stimmte oder nicht. #1601 zählte elf No-Op „Security Change“ USN Aufzeichnungen für eine einzelne Datei an einem Tag; #1620 atomare Veröffentlichungen im Rewrite-Fenster verloren. Der erneute Stempel wird jetzt nur dann ausgelöst, wenn sich das Verzeichnis nicht bereits im exakten Eigentümerverzeichnis befindet Zustand – und Verzeichnisse, die durch das DACL-Regime vor v0.10.3 beschädigt wurden (die leeren DACL-Protokolle). Ordner @patxisan gefunden, was einen Monat unlesbarer 0-Byte-Worker-Protokolle erklärt (sechs Berichte) werden vor Ort erkannt und repariert. (#1416, #1601, #1620)

Ebenfalls ausgeliefert: CBM_RUNTIME_DIR wird in generierten Codex-Konfigurationen weitergeleitet (#1664 – a Da der verschobene Daemon für von Codex erstellte Server unsichtbar war, fehlt ein letzter Zeilenumbruch wird nicht mehr als teilweise Analyse gemeldet, und update benennt kein Installationsprogramm mehr, das dies nicht ist dort (#1653).
