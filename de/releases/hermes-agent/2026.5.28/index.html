Hermes-Agent v0.15.0 (v2026.5.28)

Veröffentlichungsdatum: 28. Mai 2026 Seit v0.14.0: 1.302 Commits · 747 zusammengeführte PRs · 1.746 geänderte Dateien · 282.712 Einfügungen · 36.699 Löschungen · 560+ geschlossene Probleme (15 P0, 65 P1, 19 mit Sicherheitsmarkierungen) · 321 Community-Mitwirkende (einschließlich Co-Autoren)

The Velocity Release. Hermes wird erheblich schneller – beim Starten, beim Ausführen, beim Versenden von Arbeiten und beim Wachsen. Die 16.083 Zeilen run_agent.py kollabieren auf 3.821 (-76 %) über 14 zusammenhängende agent/*-Module. Kanban hat sich über 104 PRs hinweg zu einer echten Multi-Agenten-Plattform entwickelt – Orchestrator-Autozerlegung, Schwarmtopologie, geplante Aufgaben, Arbeitsbaum pro Aufgabe, Modellüberschreibungen pro Aufgabe. Die Kaltstart-Leistungswelle geht weiter: eine weitere Sekunde kürzerer Startzeit, 47 % weniger Funktionsaufrufe pro Konversation, hermes --version übertrifft den Vergleichs-Benchmark mit Codex CLI. session_search ist jetzt 4.500-mal schneller und kostenlos. Promptware-Verteidigung schützt vor Angriffen der Brainworm-Klasse. Bitwarden Secrets Manager ersetzt N pro Anbieter API-Schlüssel durch ein Bootstrap-Token. Mit Skill-Bundles kann ein Slash-Befehl einen ganzen Workflow laden. Die Ink TUI erhält einen Multisession-Orchestrator. Zwei neue image_gen-Anbieter (Krea 2 Medium + Large, FAL auf Plugin portiert), der von Nous genehmigte MCP-Katalog mit einer interaktiven Auswahl, eine OpenHands-Orchestrierungsfähigkeit, ntfy als 23. Messaging-Plattform und eine tiefe xAI-Integrationsrunde (Web Search-Plugin, xai-oauth hermes proxy Upstream, Modellerkennung ab Mai 15 + hermes migrate xai, natürliche TTS-Sprach-Tag-Pausen, base_url-Leak Guard, Ausführungsanleitung im OpenAI-Stil für Grok). 15 P0 + 65 P1-Verschlüsse daneben.

✨ Highlights

  • Der große Refactor – run_agent.py umfasst nicht mehr 16.000 Zeilen – Die Datei im Herzen von Hermes – die Agenten-Konversationsschleife – wurde von 16.083 Zeilen auf 3.821 (-76 %) reduziert, wobei der extrahierte Code redis auf 14 zusammenhängende Module unter agent/ verteilt ist. Das Verhalten ist unverändert: Bei jeder Extraktion bleibt ein Thin Forwarder auf AIAgent erhalten, jeder Test-Patch-Pfad funktioniert weiterhin, jeder externe Anrufer ist kompatibel. Der Grund, warum Sie sich darum kümmern: Die zukünftige Hermes-Entwicklung schreitet schneller voran, Plugin-Autoren können endlich die Codebasis durchsuchen und die Datei, deren Laden in Ihrem Editor 90 Sekunden gedauert hat, wird im Handumdrehen geöffnet. (#27248)
  • Kanban hat sich zu einer echten Multi-Agenten-Plattform entwickelt – 104 PRs durchgängig – Triage zerlegt eine Aufgabe automatisch in einen Baum von Unteraufgaben. hermes kanban swarm erstellt mit einem Befehl ein vollständiges Swarm v1-Diagramm – Root, Parallel Worker, Gated Verifier, Gated Synthesizer, Shared Blackboard. Aufgaben unterstützen Modellüberschreibungen pro Aufgabe (billige Modelle für Boilerplate, teure Modelle für schwierige Unteraufgaben), Standardarbeitsverzeichnisse auf Board-Ebene, Arbeitsbaumpfade und -zweige pro Aufgabe, geplante Startzeiten, konfigurierbare Anspruchs-TTL, Wiederholungsfingerabdrücke, Erkennung veralteter Aufgaben, Respawn-Guards und eine Papierkorbzone zum Löschen durch Ziehen.   • Kaltstart-Leistungswelle geht weiter – eine weitere Sekunde gespart, 47 % weniger Funktionsaufrufe pro Runde – Drei neue Optimierungsrunden: openai._base_client-Import verschieben (-240 ms / -17 MB bei jedem CLI-Aufruf), Hot-Path-Optimierungen reduzieren 47 % der Funktionsaufrufe pro Konversation (399.000 → 213.000 für 31-Runden-Chat), Komprimierungs-Machbarkeitsprüfung aufschieben (-170 bis -290 ms bei jeder Agentenkonstruktion), adaptive Unterprozessabfrage (-195 ms pro Werkzeugaufruf, 1+ Sekunde pro Runde). Der Kaltstart von Termux sinkt von 2,9 s auf 0,8 s. hermes --version Cold sinkt um 63 % (701 ms → 258 ms), wodurch sich der Direktvergleich gegen Codex CLI von 5/11 Siegen auf 6/11 dreht. (#28864, #28866, #28957, #29006, #29419, #30121, #30609, #31968)
  • session_search neu aufgebaut – kein LLM, keine Kosten, 4.500-mal schneller – Das alte session_search war ein Aux-LLM-betriebenes Tool, das ca. 699 0.30/Anruf kostete und ca. 30 Sekunden brauchte, um drei Sitzungen zusammenzufassen, was manchmal zu Verwirrung führte, wenn die richtige Sitzung nicht einmal in der FTS5-Trefferliste enthalten war. Die neue Form ist ein Tool mit drei Modi (Erkennung, Scrollen, Durchsuchen), aus denen abgeleitet wird, welche Argumente festgelegt werden – kein mode-Parameter, kein Aux-LLM, kein Konfigurationsknopf, kein Begleiter-Skill. Die Erkennung dauert etwa 20 ms statt etwa 90 s; Scrollen dauert ca. 1 ms. Das Durchsuchen Ihrer vergangenen Sitzungen nach Kontext ist jetzt kostenlos und sofort möglich. (#27590)
  • Promptware-Verteidigung – Angriffe der Brainworm-Klasse werden an drei Engpässen abgewehrt – Inspiriert durch die aktuelle Brainworm-/Promptware-Kill-Chain-Forschung (Origin HQ, arxiv 2601.09625) verteidigt Hermes nun das Kontextfenster gegen Prompt-Injection-Angriffe, die versuchen, den Agenten über Tool-Ausgabe, abgerufenen Speicher oder gespeicherte Fähigkeiten zu kapern. Single Source of Truth (tools/threat_patterns.py) mit ~15 neuen Brainworm/C2-Mustern; Der abgerufene Speicher wird beim Laden gescannt. Die Ergebnisse des Tools erhalten Trennzeichen, sodass eine schädliche Datei oder ein Remote-Dienst sich nicht als Hermes-eigener Systeminhalt ausgeben kann. Gepaart mit einem neuen security-guidance-Plugin, das gefährliche Code-Schreibvorgänge musterabgleicht. (#32269, #33131, #9151)
  • Bitwarden Secrets Manager – ein Bootstrap-Token ersetzt jeden API-Schlüssel pro Anbieter – Behalten Sie keine Klartext-API-Schlüssel in ~/.hermes/.env bei. Installieren Sie Bitwarden Secrets Manager (bws wird bei der ersten Verwendung langsam automatisch installiert), weisen Sie Hermes mit einem Bootstrap-Token (BWS_ACCESS_TOKEN) darauf hin, und alle Anmeldeinformationen, die Sie benötigen, kommen beim Start von Bitwarden. Drehen Sie secrets.bitwarden.override_existing: false um, um es umzukehren. EU Cloud und selbst gehostete Bitwarden-Server-URLs werden unterstützt. Erkannte Anmeldeinformationen werden jetzt mit ihrer Quelle gekennzeichnet, sodass Sie auf einen Blick sehen können, welche Schlüssel von Bitwarden und der lokalen Umgebung stammen.
