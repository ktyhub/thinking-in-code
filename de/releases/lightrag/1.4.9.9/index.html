LightRAG v1.4.9.9

Release Note V1.4.9.9

Wichtige Hinweise

  • Arbeitsbereich-Isolation für Pipeline-Status und In-Memory-Speicher hinzufügen: Mehrere LightRAG-Instanzen mit unterschiedlichen Arbeitsbereichen können gleichzeitig erstellt werden, was einen erheblichen Fortschritt in Richtung eines nahtlosen Arbeitsbereichwechsels innerhalb eines einzelnen LightRAG-Servers darstellt.
  • Workspace-Vektordatenisolation nach Modellname und Dimension für PostgreSQL und Qdrant hinzufügen: Bisher verwendete LightRAG eine einzelne Sammlung/Tabelle für die unterschiedliche Einbettung von Modell und Dimension, was zu Abstürzen bei Dimensionskonflikten oder Datenverschmutzung in mehreren Arbeitsbereichen führte.
  • Dimensionsauswahl wird für OpenAI und Gemini unterstützt Einbettungsmodell mit neuer Umgebungsvariable eingeführt: EMBEDDING_SEND_DIM
  • Fügen Sie LLM-Cache-Migrations- und LLM-Abfrage-Cache-Bereinigungstools zwischen verschiedenen KV-Speichern hinzu: Ermöglicht Benutzern das Wechseln von Speicher-Backends, ohne zwischengespeicherte Extraktions- und Zusammenfassungsdaten zu verlieren.
  • Verbesserte verbesserte DOCX-Extraktion mit Unterstützung für Tabelleninhalte.
  • Verbesserte XLSX-Extraktion mit korrekter Verarbeitung der Zeichen tab und newline in Zellen.
  • Kritische Sicherheitslücke in React-Server-Komponenten beheben: #2494
  • Unterstützung für automatische Textkürzung für Einbettungsfunktionen hinzufügen: Die OpenAI-Einbettungsfunktion berücksichtigt jetzt den Wert „max_token_size“ in EmbeddingFunc und schneidet Eingabetext automatisch ab, um API-Fehler zu verhindern, die durch Texte verursacht werden, die die Modell-Token-Grenzwerte überschreiten.

Aktuelles (nur für LightRAG Core-Integration)

  • Parameter der Chunking-Funktion umbenennen: Wenn Sie die Chunking-Funktion in LightRAG integrieren und Parameter nach Namen übergeben, sind entsprechende Codeaktualisierungen erforderlich.
def chunking_by_token_size(
    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,
    chunk_overlap_token_size: int = 100,
    chunk_token_size: int = 1200,
) -> list[dict[str, Any]]:
  • Injizieren Sie eine „embedding_func“ mit „model_name“ in LightRAG mithilfe von „wrap_embedding_func_with_attrs“:
@wrap_embedding_func_with_attrs(
    embedding_dim=1536, max_token_size=8192, model_name="text-embedding-3-small"
)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

rag = LightRAG(
      working_dir=WORKING_DIR,
      llm_model_func=llm_model_func,
      embedding_func=embedding_func,
)

Um einen nahtlosen Übergang zu gewährleisten, wird Legacy-Code, der „embedding_func“ ohne „model_name“ einfügt, weiterhin mit den ursprünglichen Vektortabellen ohne Suffix kommunizieren.
