LightRAG v1.4.7

Patch Veröffentlicht29. Aug. 2025 QuelleHKUDS/LightRAG Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

LightRAG v1.4.7

Wichtige Hinweise

  • Die Doc-ID-basierte Blockfilterfunktion wurde aus dem PostgreSQL-Vektorspeicher entfernt.
  • Die Eingabeaufforderungsvorlage wurde aktualisiert, wodurch alle LLM-Caches ungültig werden.
  • Der Standardwert der Umgebungsvariablen FORCE_LLM_SUMMARY_ON_MERGE wurde von 4 auf 8 geändert. Diese Anpassung reduziert die Anzahl der LLM-Aufrufe während der Dokumentationsindizierungsphase erheblich und verkürzt dadurch die Gesamtverarbeitungszeit des Dokuments.
  • Unterstützung für mehrere Rerank-Anbieter hinzugefügt (Cohere AI, Jina AI, Aliyun Dashscope). Wenn Reranking zuvor aktiviert war und eine neue Umgebungsvariable festgelegt werden muss, um Reranking erneut zu ermöglichen:
RERANK_BINDING=cohere
  • Eine neue Umgebungsvariable, LLM_TIMEOUT, wurde eingeführt, um speziell das Large Language Model (LLM)-Timeout zu steuern. Die vorhandene TIMEOUT-Variable verwaltet jetzt ausschließlich das Gunicorn-Worker-Timeout. Das Standard-LLM-Timeout ist auf 180 Sekunden eingestellt. Wenn Sie sich zuvor für die LLM-Timeout-Konfiguration auf die Variable TIMEOUT verlassen haben, aktualisieren Sie bitte Ihre Einstellungen, um stattdessen LLM_TIMEOUT zu verwenden:
LLM_TIMEOUT=180
  • Fügen Sie umfassende Umgebungsvariableneinstellungen für OpenAI- und Ollama Large Language Model (LLM)-Bindungen hinzu. Die generische Umgebungsvariable TEMPERATURE für die LLM-Temperaturregelung ist veraltet. Stattdessen wird die LLM-Temperatur jetzt mithilfe bindungsspezifischer Umgebungsvariablen konfiguriert:
# Temperature setting for OpenAI binding
OPENAI_LLM_TEMPERATURE=0.8

# Temperature setting for Ollama binding
OLLAMA_LLM_TEMPERATURE=1.0

Um endlose Ausgabeschleifen abzuschwächen und eine gierige Dekodierung für Qwen3 zu verhindern, legen Sie den Temperaturparameter auf einen Wert zwischen 0.8 und 1.0 fest. Um den „Thinking“-Modus des Modells zu deaktivieren, beachten Sie bitte die folgende Konfiguration:

### Qwen3 Specific Parameters depoly by vLLM
# OPENAI_LLM_EXTRA_BODY='{"chat_template_kwargs": {"enable_thinking": false}}'

### OpenRouter Specific Parameters
# OPENAI_LLM_EXTRA_BODY='{"reasoning": {"enabled": false}}'

Für eine vollständige Liste der Supportoptionen verwenden Sie den folgenden Befehl:

lightrag-server --llm-binding openai --help
lightrag-server --llm-binding ollama --help
lightrag-server --embedding-binding ollama --help
  • Eine vollständige Liste der neu hinzugefügten Umgebungsvariablen oder neuen Standardwerte:
# Timeout for LLM requests (seconds)
LLM_TIMEOUT=180

# Timeout for embedding requests (seconds)
EMBEDDING_TIMEOUT=30

### Number of summary segments or tokens to trigger LLM summary on entity/relation merge (at least 3 is recommended)
FORCE_LLM_SUMMARY_ON_MERGE=8

### Max description token size to trigger LLM summary
SUMMARY_MAX_TOKENS = 1200

### Recommended LLM summary output length in tokens
SUMMARY_LENGTH_RECOMMENDED=600

### Maximum context size sent to LLM for description summary
SUMMARY_CONTEXT_SIZE=12000

### RERANK_BINDING type:  null, cohere, jina, aliyun
RERANK_BINDING=null

### Enable rerank by default in query params when RERANK_BINDING is not null
# RERANK_BY_DEFAULT=True

### chunk selection strategies
###     VECTOR: Pick KG chunks by vector similarity, delivered chunks to the LLM aligning more closely with naive retrieval
###     WEIGHT: Pick KG chunks by entity and chunk weight, delivered more solely KG related chunks to the LLM
###     If reranking is enabled, the impact of chunk selection strategies will be diminished.
KG_CHUNK_PICK_METHOD=VECTOR

### Entity types that the LLM will attempt to recognize
ENTITY_TYPES=["person", "organization", "location", "event", "concept"]
