quivr v2.0.0

Quivr 2.0.0

Quivr ist eine Open-Source-Engine für Inhalte, die immer wieder ankommen. Ihre Anwendung oder die Quellen von Quivr (RSS, Microsoft 365-Postfächer, X-Listen) senden ihm Dokumente. Quivr speichert jede Version jedes Dokuments und macht es innerhalb von Sekunden durchsuchbar, nach Schlüsselwörtern, nach Bedeutung oder beidem. Außerdem prüft es jedes neue Dokument anhand Ihrer gespeicherten Benachrichtigungen. Quivr hat keine Benutzeroberfläche: Ihre Anwendung kommuniziert mit ihm über HTTP API und KI-Agenten nutzen es über quivr mcp.

2.0.0 ist die erste stabile Version des neu geschriebenen Quivr. Die Alphas dienten der Auswertung. Ab dieser Veröffentlichung macht Quivr Versprechen, auf denen Sie aufbauen können.

Was 2.0 verspricht

  • Ein stabiler API. Der HTTP-API behält den /v0-Pfad für jede 2.x-Version bei. Eine 2.x-Version fügt nur Folgendes hinzu: neue Endpunkte, optionale Felder, Antwortfelder und Aufzählungswerte. Eine Änderung, die einen funktionierenden client beschädigen könnte, wartet auf die nächste Hauptversion.
  • Upgrades, die Ihre Daten behalten. Ein Upgrade von einer 2.x-Version auf eine andere führt quivr migrate aus und führt dann den Worker und API aus, wobei Ihre Daten vorhanden sind.
  • Plugins, die ihre Kompatibilität prüfen. Ein Plugin deklariert die Plugin-Versionen API, die es unterstützt, und Quivr weigert sich, eine Version zu aktivieren, die es nicht ausführen kann.
  • Status für jede Funktion löschen. Alles in der Dokumentation ist innerhalb von 2.x stabil, mit Ausnahme einer kurzen Liste experimenteller Funktionen, die jeweils auf ihrer Seite markiert sind: Suchmesstools, Jev-Neueinstufung und Jev-beurteilte Warnungen, der dedizierte Vektorhost und die quivr-autoscaler-Binärdatei.

Versionen und Kompatibilität enthält die Details. Bekannte Grenzen listet auf, was 2.0 noch nicht macht: Es durchsucht nur Text, hat keine OCR, hat keine Benutzerkonten und hat Größenbeschränkungen pro Dokument und pro Suche.

Fangen Sie an

  • Versuchen Sie es lokal: Klonen Sie das Repository, führen Sie make dev aus und befolgen Sie dann den Schnellstart, etwa fünfzehn Minuten.
  • Installieren Sie es auf einem Server von den signierten Release-Images (linux/amd64): siehe [Quivr auf einem Computer ausführen] (https://docs.quivr.thevibecompany.co/run-quivr/single-machine) oder [Quivr bereitstellen und konfigurieren] (https://docs.quivr.thevibecompany.co/run-quivr/deploy) für Railway und Kubernetes.
  • Zuerst verstehen: Kernkonzepte und Wie Quivr funktioniert.

Kommt von einem 2.0.0 Alpha

Das Upgrade einer vorhandenen Alpha-Installation wird nicht unterstützt. Starten Sie eine neue 2.0.0-Installation oder exportieren Sie Ihre Dokumente aus der Alpha und senden Sie sie an die neue.

Seit 2.0.0-alpha.7

  • Sicherheit:
    • Quivr und seine Bilder wurden mit Go 1.27.3 für CVE-2026-111943 erstellt; – golang.org/x/net, certifi, pillow und die curl und brotli des SeaweedFS-Images sind gepatcht.
  • Suche wird nach einem Datenbankneustart wiederhergestellt, wobei die Puffer wiederhergestellt und die Hydratationsarbeit begrenzt ist.
  • Importe:
    • Die Anzahl der Warteschlangen bleibt während kontinuierlicher Importe verfügbar. – Der Autoscaler fügt Bulk-Worker für Connector-Importe hinzu.
  • Dokumentation:
    • für Neulinge neu geschrieben, mit neuen Seiten: Funktionsweise von Quivr, einem Glossar, Versionen und Kompatibilität sowie bekannten Einschränkungen;
    • Die Warnungen zur „Evaluierungsphase“ sind verschwunden.

Die vollständige Liste der Änderungen seit der ersten Alpha finden Sie in CHANGELOG.md.

  • Suche: Puffer und gebundene Hydratation nach Neustart wiederherstellen (#3953) (ec80407)
  • Sicherheit: mit Go 1.27.3 erstellen und anfällige Abhängigkeiten patchen (#3967) (426bc62)
