Was Sie tun können:

  • Ressourcenfresser identifizieren: Sortierung nach Gesamtausführungszeit, CPU-Zeit oder I/O
  • Erkennen Sie häufige Abfragen: Finden Sie Abfragen mit hoher Anrufzahl, die vom Caching profitieren könnten
  • Debuggen in Echtzeit: Sehen Sie sich aktuell laufende Abfragen an und erfahren Sie, welche client sie initiiert hat
  • Keine zusätzlichen Tools erforderlich: Die gesamte Analyse erfolgt auf der oberen Registerkarte des Netdata-Dashboards

[!IMPORTANT] Einige Funktionen erfordern eine datenbankspezifische Konfiguration (z. B. die Aktivierung von Query Store, pg_stat_statements oder profiling).

Informationen zu den Voraussetzungen finden Sie in der Dokumentation jedes Collectors.

Microsoft SQL Server Collector (Go) <a id="v290-highlight-mssql-go"></a>

Wir haben den [Microsoft SQL Server-Kollektor] (https://learn.netdata.cloud/docs/collecting-metrics/databases/microsoft-sql-server) von Grund auf in Go neu erstellt und die alte C-Implementierung ersetzt. Dies ermöglicht eine umfassende SQL Server-Überwachung mit Abfrageanalysefunktionen in Echtzeit.

Was Sie bekommen:

| Funktion | Einzelheiten | |--------------|---------------------------------------------------------------------------------------------------------------- | Vollständige Metrikabdeckung | Verbindungen, Batch-Anfragen, Puffermanager, Speicher, Wartestatistiken, Sperren, Transaktionen pro Datenbank, E/A-Latenz, Dateigrößen und SQL-Agent-Jobstatus | | Funktion „Top-Abfragen“ | Echtzeitansicht Ihrer ressourcenintensivsten Abfragen direkt im Dashboard – siehe Ausführungszeit, CPU, I/O, Speicherzuteilungen und Parallelitätsmetriken | | UI-Konfiguration | Erstellen und verwalten Sie Überwachungsjobs über das Netdata-Dashboard – keine manuelle Bearbeitung der Konfigurationsdatei erforderlich | | Replikationsüberwachung | Verfolgen Sie Replikationsstatus, Latenz und Warnungen für Transaktions-/Merge-Veröffentlichungen | | Flexible Authentifizierung | SQL-Authentifizierung, integrierte Windows-Authentifizierung, benannte Instanzen und Remoteserver |

Top-Anfragen: Identifizieren Sie Leistungsengpässe

Die neue Funktion Top Queries ruft Daten aus dem Abfragespeicher von SQL Server ab, um Folgendes anzuzeigen:

– Abfragen, die die meiste Gesamtausführungszeit oder CPU verbrauchen

  • I/O-Muster (logische Lesevorgänge, physische Lesevorgänge, Schreibvorgänge)
  • Speicherzuweisungen und Tempdb-Nutzung
  • Parallelität (DOP) über Ausführungen hinweg

[!IMPORTANT] Erfordert Abfragespeicher aktiviert für überwachte Datenbanken (SQL Server 2016+).

Der Abfragetext kann vertrauliche Daten enthalten – stellen Sie sicher, dass die Zugriffskontrollen für das Dashboard ordnungsgemäß sind.

OpenTelemetry Protokollaufnahme <a id="v290-highlight-otel-logs-ingestion"></a>

Wir erweitern unseren OpenTelemetry-Support! Nach der in v2.7.0 hinzugefügten Metrikunterstützung erfasst das otel-Plugin jetzt OpenTelemetry-Protokolle über denselben OTLP-Endpunkt gRPC.

Was ist neu

  • Protokollaufnahme: Senden Sie Protokolle von Ihrem OpenTelemetry-Collector oder instrumentierten Anwendungen direkt an Netdata.
  • Benutzerdefinierter Speicher: Protokolle werden in systemd\kompatiblen Journaldateien mithilfe einer Rust-Implementierung gespeichert (keine libsystemd-Abhängigkeit erforderlich).
  • Einheitliche Schnittstelle: Zeigen Sie OpenTelemetry-Protokolle neben Systemprotokollen auf der Registerkarte Protokolle mit vollständigen Such- und Filterfunktionen an.

Konfiguration und Aufbewahrung

Steuern Sie Ihren Protokollspeicher mit konfigurierbaren Aufbewahrungsrichtlinien:

  • Legen Sie Grenzwerte nach Festplattennutzung, Dateianzahl oder Alter fest
  • Definieren Sie benutzerdefinierte Speicherorte
  • Passen Sie die Einstellungen für Dateigröße und Zeitspanne an

Verfügbarkeit

Verfügbar auf Linux-Agents (Beta), Unterstützung für weitere Plattformen folgt in Kürze.

[!NOTE]
Diese Funktion befindet sich in der Betaphase. Wir freuen uns über Ihr Feedback!

Hinweis zur veralteten Version <a id="v290-deprecation-notice"></a>

In dieser Version geändert

Wichtige Änderungen in der nächsten Nebenversion

MS SQL Server Collector: Entfernung der C-Version

Der alte C-basierte MS SQL Server-Kollektor (Teil von windows.plugin) wird in der nächsten Nebenversion entfernt. Der Go-basierte Collector (go.d/mssql) ist jetzt die standardmäßige und empfohlene Option.

Die Go-Version bietet wesentliche Vorteile:

  • Weitere Funktionen – enthält die neue Funktion „Top-Abfragen“ für die Abfrageanalyse in Echtzeit.
  • Multi-Job-Unterstützung – Überwachen Sie mehrere SQL Server-Instanzen von einem einzigen Agenten.
  • Remoteverbindungen – stellen Sie über das Netzwerk eine Verbindung zu SQL Server-Instanzen her, nicht nur über localhost.
  • UI-Konfiguration – Erstellen und verwalten Sie Überwachungsjobs direkt über das Netdata-Dashboard.
  • Einfachere Wartung – profitiert von der gemeinsamen Infrastruktur des go.d-Frameworks und schnelleren Entwicklungszyklen. Wenn Sie derzeit den C-Collector verwenden, finden Sie Konfigurationsanweisungen in der Go-Collector-[Setup-Dokumentation] (https://learn.netdata.cloud/docs/collecting-metrics/databases/microsoft-sql-server#setup).

Wichtige Änderungen in der nächsten Hauptversion

Veraltete Komponenten

| Komponententyp | Veraltete Versionen | |----------------|-------------| | APIs | v1, v2 |

Was das bedeutet

Ab der nächsten Hauptversion werden nur v3 API und v3 Dashboard unterstützt. Diese neueren Versionen bieten verbesserte Leistung, erweiterte Funktionen und mehr Sicherheit.
