repomix v1.19.0

Diese Version verschiebt den MCP-Server mit Live-Fortschritt und -Abbruch auf SDK v2, macht die --compress-Ausgabe weitaus genauer und bringt eine große Runde Fehlerbehebungen von Erstmitwirkenden!

Was ist neu 🚀

MCP-Server auf SDK v2 und dem Protokoll 2026-07-28 (#1952, #1954)

Der MCP-Server läuft jetzt auf dem MCP TypeScript SDK v2. Clients, die das Protokoll 2026-07-28 unterstützen, handeln es automatisch aus, und vorhandene clients funktionieren wie zuvor.

– Der Server wird sauber beendet, wenn der client stdin schließt, sodass keine repomix --mcp-Prozesse zurückbleiben. – Bei der Installation werden etwa halb so viele Pakete abgerufen (171 bis 84), da v1 SDK HTTP-Transportabhängigkeiten wie Express mit sich brachte, die der reine stdio-Server nie nutzte.

Für client-Autoren: Toolschemata deklarieren jetzt JSON Schema 2020-12 (Körper unverändert) und Validierungsfehler beginnen nicht mehr mit MCP error -32602: .

MCP: Fortschritt und Abbruch für langlaufende Pakete (#1955, #1958)

pack_codebase, pack_remote_repository und generate_skill senden jetzt notifications/progress, wenn der client einen progressToken passiert, sodass lange Pakete den Live-Status anzeigen und clients, die ihr Timeout bei Fortschritt zurücksetzen, sie nicht mehr abschneiden. Im --sandbox-Modus enthalten Nachrichten nur den Bühnennamen, niemals einen Hostpfad.

Wenn Sie einen Anruf abbrechen oder die Verbindung trennen, stoppt das Paket jetzt und bereinigt seine Teilausgabe.

Verbesserungen ⚡

Genauere --compress-Ausgabe (#2003)

Goldene Tests für jede unterstützte Sprache haben eine Reihe von Fehlern aufgedeckt, die jetzt behoben sind:

– Code aus Funktionskörpern dringt nicht mehr in die Ausgabe ein, als wäre es eine Deklaration.

  • Doppelte Zeilen werden entfernt. – Deklarationen, die stillschweigend gelöscht wurden, bleiben erhalten, wie z. B. C/C++ typedef und #define, C#- und Java-Felder, Rust-Strukturfelder, Ruby attr_*-Aufrufe und CSS-at-rules.

Ausgabeänderungen für C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift und Vue. Wenn Sie sich in einer Pipeline auf --compress verlassen, können Sie mit einem Unterschied zu v1.18 rechnen.

Skill-Generierung: Bessere Tech-Stack-Erkennung (#1995)

--skill-generate liest jetzt Abhängigkeiten von Gradle Kotlin DSL (build.gradle.kts) und von den PEP 621- und Poetry-Formen von pyproject.toml.

Warnung, wenn ein Remote-URL-Pfad ignoriert wird (#1980, #1984, #433)

Eine URL wie https://github.com/owner/repo/tree/main/src/shared hat das gesamte Repository gepackt und den Pfad stillschweigend gelöscht. Repomix warnt nun und schlägt ein --include-Muster vor:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Fehlerbehebungen 🐛

Muster ignorieren, die mit einem Platzhalter enden, schließen jetzt Dateien aus (#1963, #1876, #320)

Muster wie **/npm-debug.log* und **/repomix-output.* schlossen nur Verzeichnisinhalte aus, sodass Dateien wie npm-debug.log.1 und docs/repomix-output.xml in die Ausgabe gerutscht sind. Sie sind nun ausgeschlossen. Nichts, was zuvor ausgeschlossen war, wird einbezogen.

.git/info/exclude folgt den Matching-Regeln von Git (#1871, #1870)

Ein Muster ohne Schrägstriche wie secret.txt passt jetzt in jeder Tiefe, wie in Git, sodass sub/secret.txt nicht mehr gepackt ist.

Besonderer Dank geht an @sxh313 für diesen Beitrag! 🎉

Negierte benutzerdefinierte Ignorierungsmuster werden nicht mehr invertiert (#1975, #400)

!main.ts in ignore.customPatterns oder --ignore hat main.ts ausgeschlossen, anstatt es erneut einzuschließen. Negierte Muster werden jetzt mit einer Warnung übersprungen, bis die richtige Unterstützung erreicht ist (#400).

Geteilte Ausgabedateien werden nicht mehr in den nächsten Lauf gepackt (#1921, #1920)

Mit --split-output werden Dateien wie repomix-output.1.xml aus einem früheren Lauf nicht mehr als Eingabe übernommen.

Besonderer Dank geht an @lorenzozanee für ihren ersten Beitrag! 🎉

--remove-comments Behält URLs in CSS, SCSS, Less, Vue und Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) wurde auf url(http: gekürzt, da // als Kommentar behandelt wurde. Jede Sprache verwendet jetzt ihre eigenen Kommentarregeln und Vue- und Svelte-Dateien werden nach <script>, <style> und Markup-Abschnitt behandelt.

Besonderer Dank geht an @plox-sumit für ihren ersten Beitrag! 🎉

Nicht-ASCII-Dateinamen in Git-Protokollen und Diffs (#1940, #1979)

Namen wie 日本語.txt werden in Git-Protokollen und Diffs nicht mehr als "\346\227\245..." angezeigt, und output.git.sortByChanges sortiert diese Dateien jetzt korrekt.

Besonderer Dank geht an @feiiiiii5 für ihren ersten Beitrag! 🎉

--token-count-tree 0 zeigt den vollständigen Baum (#1941)

Es wurde vorher nichts gedruckt; es zeigt jetzt jede Datei an.

Besonderer Dank geht an @feiiiiii5 für diesen Beitrag! 🎉

Verschachtelte --stdin-Pfade unter Windows (#1922)

Durch die Weiterleitung von Pfaden wie src/(routes)/page[1].ts in repomix --stdin werden unter Windows nur Dateien auf Stammebene gepackt. Verschachtelte Pfade stimmen jetzt überein.

Besonderer Dank geht an @lux-liang für ihren ersten Beitrag! 🎉

Schwerwiegende Fehler sichtbar unter --quiet und --stdout (#1875, #1874)

Ein fehlgeschlagener Pack unter --quiet oder --stdout wurde mit Code 1 beendet und nichts gedruckt. Der Fehler geht jetzt zu stderr.

Besonderer Dank geht an @sxh313 für diesen Beitrag! 🎉

MCP-Server-Korrekturen (#1867, #1866, #1865, #1864, #1869, #1868)

– --mcp --verbose schreibt keine Diagnosedaten mehr nach stdout, wo clients sie als Protokollrahmen lesen. (#1867) – Die Fehlerprotokollierung wird nach einem generate_skill- oder pack_remote_repository-Aufruf nicht mehr für den Rest der Sitzung stummgeschaltet. (#1865)

  • grep_repomix_output formatiert jetzt Kontext wie grep -C und verarbeitet sehr große Ausgaben. (#1869)

Besonderer Dank geht an @sxh313 für ihren ersten Beitrag! 🎉

Sicherheitshärtung 🔒

MCP pack_codebase führt immer den geheimen Scan aus (#1960)

Ein repomix.config.json im gepackten Verzeichnis könnte den geheimen Scan für MCP-Pakete mit security.enableSecurityCheck: false deaktivieren. Der Scan läuft jetzt immer für MCP-Pakete; Einfache CLI-Läufe folgen weiterhin der Konfigurationsdatei.

Dokumentation 📚

In den MCP-Dokumenten heißt es nun, dass pack_codebase trust ohne --sandbox den repomix.config.* in dem Verzeichnis speichert, das er packt, genauso wie der CLI dort ausgeführt wird. Verwenden Sie --sandbox, wenn Ihr Assistent möglicherweise nicht untrusted-Verzeichnisse packt, z. B. geklonte Repositorys von Drittanbietern. (#1961)

Siehe MCP-Server: Sandbox-Modus und Warum eine Konfigurationsdatei Code ist.

So aktualisieren Sie

npm update -g repomix

Wie immer gilt: Wenn Sie Probleme oder Vorschläge haben, teilen Sie uns dies bitte über GitHub-Probleme oder unsere Discord-Community mit.
