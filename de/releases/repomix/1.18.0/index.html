repomix v1.18.0

Diese Version führt den Sandbox-Modus für den MCP-Server ein, der ihn auf ein einziges Arbeitsbereichsverzeichnis beschränkt, zusammen mit einer Reihe von Sicherheitsverstärkungsänderungen auf der gesamten MCP-Tool-Oberfläche und der Remote-Repository-Verarbeitung!

Was ist neu 🚀

MCP-Sandbox-Modus (#1753, #1754)

Der MCP-Server kann jetzt mit dem Flag --sandbox auf ein einzelnes Arbeitsbereichsverzeichnis beschränkt werden:

# Confine to the current working directory
repomix --mcp --sandbox

# Confine to a specific directory
repomix --mcp --sandbox path/to/project

Standardmäßig kann der MCP-Server jeden Pfad lesen, den der Host-Benutzer lesen kann, was für einen trusted-lokalen Assistenten praktisch ist, aber zu weit gefasst, wenn der Server einem untrusted client oder Agenten ausgesetzt ist, beispielsweise beim Einbetten von Repomix in eine gehostete Anwendung. Im Sandbox-Modus:

  • Jeder Pfad ist relativ zum Arbeitsbereichsstamm. Absolute Pfade, ~, .. und Windows-Laufwerks-/UNC-Pfade werden abgelehnt und Pfade, die außerhalb des Stammverzeichnisses aufgelöst werden (einschließlich über Symlinks), werden verworfen. – Ergebnisse und Fehlermeldungen werden virtualisiert, sodass Hostpfade niemals offengelegt werden. – Es sind nur die schreibgeschützten, auf Root beschränkten Tools registriert: pack_codebase, read_repomix_output, grep_repomix_output, file_system_read_file und file_system_read_directory. Remote-Packen, Skill-Generierung und Anhängen externer Ausgaben sind deaktiviert.

Hierbei handelt es sich um eine Beschränkung der Tool-Oberfläche auf Anwendungsebene, nicht um eine Sandbox auf Betriebssystemebene: Wenn Sie den Server für untrusted clients hosten, führen Sie ihn weiterhin unter der üblichen Isolation Ihrer Plattform aus (Container, dedizierte Benutzer).

Weitere Informationen finden Sie unter [MCP-Server – Sandbox-Modus] (https://repomix.com/guide/mcp-server#sandbox-mode).

Besonderer Dank geht an @huy-trn für die Gestaltung und Implementierung dieser Funktion. Schön, einen langjährigen Mitwirkenden zurück zu haben! 🎉

Sicherheitshärtung 🔒

MCP-Dateisystem-Tools sind jetzt nur noch für die Sandbox verfügbar

Die Tools file_system_read_file und file_system_read_directory sind jetzt nur im Sandbox-Modus registriert. Außerhalb von --sandbox konnten sie jeden Pfad lesen, den der Prozess lesen kann, während ihr integrierter Secretlint-Scan als mehr Schutz dargestellt wurde, als er bot: Er erkennt bekannte geheime Formate im Dateiinhalt und sonst nichts. Im Sandbox-Modus gibt der Workspace-Root diesen Tools eine echte Zugriffsgrenze, wobei der geheime Scan als zusätzlicher heuristischer Schutz beibehalten wird.

Wenn Ihr MCP-Setup auf diesen beiden Tools basiert, fügen Sie --sandbox [dir] zu den Serverargumenten hinzu, um sie weiterhin auf diesen Arbeitsbereich beschränkt zu verwenden.

Toolbeschreibungen und Dokumentation wurden ebenfalls allgemein umformuliert, um den Secretlint-Scan als das zu beschreiben, was er ist: eine Best-Effort-Inhaltsheuristik und keine Zugriffsgrenze.

Weitere Informationen finden Sie im Sicherheitshinweis. Danke an @rafaelfiguereod-stack für den Bericht! 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-rpmv-562j-qxrv

Anmeldeinformationen in Repository-URLs werden vor der Protokollierung geschwärzt

Remote-URLs werden routinemäßig mit Inline-Anmeldeinformationen (https://<token>@github.com/owner/repo.git) geschrieben, insbesondere in CI. Repomix hat solche URLs zuvor unverändert in Konsolenausgaben, Ablaufverfolgungsprotokollen, Fehlermeldungen (Git wiederholt die vollständige Befehlszeile in seiner Fehlerausgabe) und der MCP-pack_remote_repository-Antwort wiedergegeben und die Anmeldeinformationen im Terminal-Scrollback, in CI-Build-Protokollen und in Protokollaggregationssystemen beibehalten. Alle diese Pfade redigieren jetzt Benutzerinfo-Anmeldeinformationen und bekannte Abfrageparameter für Anmeldeinformationen (token, private_token, access_token und ähnliche), bevor die URL irgendwohin geschrieben wird.

Weitere Informationen finden Sie im Sicherheitshinweis. Danke an @kakashi-kx für den Bericht! 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-w8cw-mgw9-74h7

Cloud-Metadaten-Endpunkte werden als Klonziele abgelehnt

Remote-Packing verweigert jetzt das Klonen von Cloud-Instanz-Metadaten-Endpunkten (169.254.0.0/16, fd00:ec2::254, 100.100.100.200, metadata.google.internal), die Anmeldeinformationen bereitstellen und kein Git-Repository hosten. Über den MCP-Server wählt ein KI-Agent die URL aus, sodass eine eingefügte Anweisung andernfalls einen Klon auf eine Adresse richten könnte, nach der der Benutzer nie gefragt hat. Private Netzwerke (RFC1918) bleiben weiterhin zulässig, da das Klonen von selbst gehosteten Git-Servern normal ist.

So aktualisieren Sie

npm update -g repomix

Wie immer gilt: Wenn Sie Probleme oder Vorschläge haben, teilen Sie uns dies bitte über GitHub-Probleme oder unsere Discord-Community mit.
