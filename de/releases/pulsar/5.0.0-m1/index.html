Pulsar v5.0.0-M1

23.06.2026

Apache Pulsar 5.0.0-M1 ist die erste Meilensteinversion auf dem Weg zu Apache Pulsar 5.0.0. Die allgemeine Verfügbarkeit wird später im Jahr 2026 erwartet. Es handelt sich um eine Vorschau: einen frühen Build, der Ihnen die wichtigsten neuen Funktionen von 5.0 in die Hand gibt, sodass Sie sie unter realen Arbeitslasten testen und vor der GA-Veröffentlichung Feedback senden können. Es ist nicht für die Produktion gedacht. Zwei Änderungen stechen hervor: Scalable Topics, ein neuer Thementyp, der von selbst wächst und schrumpft, und die Heraufstufung von Oxia zum empfohlenen Metadatenspeicher von Pulsar – neben einer Migration des Build-Systems zu Gradle, der Aufteilung der IO-Konnektoren in ein separates Repository und der strukturierten Protokollierung.

Eine vollständige Anleitung finden Sie in der Ankündigung: Apache Pulsar 5.0.0-M1: Eine Vorschau auf die nächste Hauptversion.

Highlights

Skalierbare Themen (Topics v5). Ein neuer Thementyp, der feste Partitionen durch bereichsbasierte Segmente ersetzt, sodass ein Thema durch transparentes Teilen und Zusammenführen von Segmenten nach oben und unten skaliert werden kann, während die Reihenfolge pro Schlüssel erhalten bleibt. Dadurch werden Ordnungsfehler und Betriebsabweichungen vermieden, die durch die Änderung der Partitionsanzahl eines regulär partitionierten Themas entstehen. Die Arbeit umfasst den Broker-seitigen Controller (PIP-468), metadatengesteuerte Transaktionen (PIP-473), die Migration von regulären zu skalierbaren Themen (PIP-475) und die automatische Aufteilung/Zusammenführung (PIP-483). Siehe PIP-460.

Neues V5 Java client API. Ein aufgeräumter, speziell entwickelter client API für skalierbare Themen, der als neues, additives pulsar-client-v5-Modul geliefert wird – die vorhandenen pulsar-client- und pulsar-client-api-Module bleiben unverändert, sodass aktuelle Anwendungen weiterhin funktionieren. Es ersetzt das klassische Consumer/Reader und die vier Abonnementtypen durch drei speziell entwickelte Verbraucher: QueueConsumer (paralleler, individuell bestätigter Arbeitswarteschlangenverbrauch mit Unterstützung für unzustellbare Nachrichten), StreamConsumer (geordnete, kumulative Bestätigungen) und CheckpointConsumer (für Stream-Prozessoren wie Flink und Spark, die ihre eigene Position verfolgen). Der V5 client funktioniert auch mit vorhandenen partitionierten und nicht partitionierten Themen, und ein Verbraucher kann einen gesamten Namespace abonnieren. In M1 wird es für Java ausgeliefert; SDKs in anderen Sprachen werden vor GA folgen. Siehe PIP-466.

Oxia ist jetzt der empfohlene Metadatenspeicher. Oxia wird zum empfohlenen Metadatenspeicher für neue Pulsar-Cluster in 5.0 und ist das Backend der Wahl für skalierbare Themen, deren Suchvorgänge auf seinen Streaming-Überwachungssitzungen aufbauen. ZooKeeper wird weiterhin vollständig unterstützt und PIP-454 fügt ein Live-Migrationsframework ohne Ausfallzeiten hinzu, das einen vorhandenen Cluster von ZooKeeper nach Oxia verschiebt, während die Datenebene weiterhin veröffentlicht und konsumiert.

Build-System von Maven nach Gradle migriert. Builds verwenden jetzt ./gradlew anstelle von mvn, mit Caching und Parallelität auf Aufgabenebene, die die lokalen und CI-Build-Zeiten erheblich verkürzen, und einem zentralen Versionskatalog (gradle/libs.versions.toml) für die Abhängigkeitsverwaltung. Die Migration ist für Benutzer transparent, die die veröffentlichten Maven-Artefakte, Docker-Bilder und schattierten client-JARs verwenden. Siehe PIP-463.

IO-Konnektoren werden in ein separates Repository aufgeteilt. Die integrierten Pulsar-IO-Konnektoren wurden aus dem Kern-Repository verschoben, damit sie ihrem eigenen Veröffentlichungsrhythmus folgen können. Siehe PIP-465. Strukturierte Protokollierung. Pulsar gibt jetzt strukturierte Protokolle über slog über die Module Broker, client, ​​Managed-Ledger, Funktionen und Metadaten aus, mit flacher Protokollausgabe JSON/OpenTelemetry und einer Umgebungsvariablen PULSAR_LOG_FORMAT zum einfachen Wechseln der Formate. Siehe PIP-467.

API und Plattformmodernisierung. Pulsar wurde von javax.* auf jakarta.* APIs (PIP-472) migriert, Protobuf v4 zum Standard gemacht, REST API-Anmerkungen von Swagger auf OpenAPI 3 migriert und unterstützt jetzt das Erstellen und Ausführen auf Java 25. Themenrichtlinien gewonnen a Legacy-fähiges, vom Metadatenspeicher unterstütztes Routing-Backend (PIP-469).

Sicherheits- und Abhängigkeitsaktualisierungen. Diese Version bündelt eine große Anzahl von Abhängigkeitsaktualisierungen, die zahlreiche CVEs in Netty, Jetty, log4j, BouncyCastle, Thrift, vert.x und async-http-client adressieren, und aktualisiert BookKeeper auf 4.18.0. Siehe Bibliotheksaktualisierungen unten.

Wichtiger Hinweis

5.0.0-M1 ist eine Hauptversion, die veraltete Funktionen entfernt und einige APIs ändert. Überprüfen Sie vor dem Upgrade Folgendes:

  • javax.* → jakarta.*-Migration (PIP-472). Benutzerdefinierte Broker-Plugins, Interceptoren, Authentifizierungs-/Autorisierungsanbieter oder andere Erweiterungen, die auf javax.*-Pakete verweisen (z. B. javax.ws.rs oder javax.servlet), müssen auf die entsprechenden jakarta.*-Pakete aktualisiert und neu kompiliert werden.
  • Etcd-Metadatenspeicher-Backend entfernt (PIP-462). Bereitstellungen, die Etcd als Metadatenspeicher verwenden, müssen vor dem Upgrade auf ZooKeeper oder Oxia migriert werden.
  • IO-Konnektoren wurden in ein separates Repository verschoben (PIP-465). Konnektoren werden nicht mehr aus dem Pulsar-Kernrepository freigegeben; Sie können sie über das Projekt „Dedicated Connectors“ beziehen.
  • Build-System ist jetzt Gradle (PIP-463). Wenn Sie Pulsar aus dem Quellcode erstellen, verwenden Sie ./gradlew anstelle von mvn. Veröffentlichte Artefakte bleiben unverändert. – fastutil-Abhängigkeit entfernt (#25413).
