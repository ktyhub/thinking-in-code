claude-mem v15.19.0

Setzen Sie ein Claude Code- oder Codex-Gespräch über „Meine Arbeit“ fort

Öffnen Sie eine Anfrage in „Meine Arbeit“ und öffnen Sie dann „Woher das kommt“. Unter jedem Claude Code oder jeder Codex-Konversation gibt es jetzt ein Nachrichtenfeld. Geben Sie eine Nachricht ein und drücken Sie auf „Senden“, und schon beginnt die gleiche Konversation. Die Antwort wird genau dort angezeigt (#6191; die Befehlsformen folgen dem Antwortcode von @wiesenthal in #6054, und der Commit schreibt ihn gut).

  • Bei jeder Konversation werden die Nachrichten, die Sie von „Meine Arbeit“ gesendet haben, und deren Antworten in der richtigen Reihenfolge angezeigt. Stopp beendet eine laufende Runde.
  • Das Feld gibt an, in welchem ​​Ordner die Runde ausgeführt wird. Wenn der aufgezeichnete Ordner nicht mehr existiert (üblicherweise nach dem Bereinigen eines Arbeitsbaums), wird die Runde im nächsthöheren vorhandenen Ordner darüber ausgeführt.
  • „Resume-Befehl kopieren“ kopiert claude --resume <id> oder codex resume <id>. Auf einem Mac öffnet „In Claude öffnen“ eine Claude Code-Konversation in der Claude-Desktop-App.
  • One Send startet einen Headless Resume (claude --resume <id> -p --output-format json oder codex exec resume <id> - --skip-git-repo-check) mit Ihrer Nachricht auf stdin. Ein fehlgeschlagener Spielzug wird als fehlgeschlagen erfasst und nie erneut versucht. Nichts wird in die Warteschlange gestellt oder zur Wiedergabe gespeichert, und nichts startet beim Start, bei einem Timer oder bei einer erneuten Verbindung.
  • Ein Neustart oder Herunterfahren eines Workers stoppt zuerst jede laufende Runde, sodass ein neu gestarteter Worker nie zum zweiten Autor derselben Konversation wird. Eine gestoppte Runde wird durch nichts erneut gesendet.
  • Eine Runde wird in Ihrem eigenen Standard-Berechtigungsmodus ausgeführt, dem gleichen, den claude -p --resume in Ihrem Terminal verwendet. Im manuellen Modus werden Werkzeugaufrufe, die einer Genehmigung bedürfen, abgelehnt und in der Zeile gezählt. Es wird kein Berechtigungs-, Modell- oder Sandbox-Flag übergeben.
  • Die neuen Routen antworten nur auf Loopback und lehnen andere Ursprünge ab. Wenn der lokale API-Token-Modus deaktiviert ist, kann ein anderes Programm auf demselben Computer sie aufrufen, ebenso wie jeder andere Worker. Aktivieren Sie auf einem gemeinsam genutzten Computer den lokalen API-Token-Modus.
  • Eine Änderung für jede Anfrage: Während eine neuere Version einer offenen Anfrage geladen wird, zeigt die Schublade weiterhin die Version an, die sie bereits hat, anstatt „Anfragedetails werden geladen…“.

Bekannte Grenzen:

– Der Codex-Pfad durch die Seite wurde auf dem Testcomputer nicht durchgehend ausgeführt. Codex-Drehungen wurden auf Läuferebene mit dem echten CLI überprüft.

  • Unter Windows erreicht Stop möglicherweise keinen CLI hinter einer .cmd-Unterlegscheibe und „In Claude öffnen“ wird nicht angeboten.
  • Ein Gespräch, das sich gerade in einem Terminal befindet, kann immer noch über „Meine Arbeit“ an der Reihe sein. In den Dokumenten von Claude Code heißt es, dass zwei Autoren in einer Sitzung Nachrichten verlieren können. „Meine Arbeit“ blockiert zwei eigene Runden in einem Gespräch.
  • Ein Worker-Absturz (kein ordnungsgemäßer Neustart) kann eine laufende Runde nicht stoppen. Es endet von selbst.
  • Ein Helfer, den der CLI zurücklässt, z. B. ein langsam beendender MCP-Server, hält die Runde als ausgeführt markiert, bis er beendet wird oder Sie auf Stopp drücken.

Bringen Sie Ihr vorhandenes Gedächtnis mit

npx claude-mem import ruft Erinnerungen direkt von der Mem0-Plattform oder Supermemory ab und speichert sie als durchsuchbare Beobachtungen in einem von Ihnen ausgewählten Projekt. Keine Exportdatei und keine Modellaufrufe (#6106).

# MEM0_API_KEY in the environment
npx claude-mem import --from mem0 --source-account personal-mem0 --user my-user-id --project imported-memory

# SUPERMEMORY_API_KEY in the environment
npx claude-mem import --from supermemory --source-account personal-supermemory --namespace my_namespace --project imported-memory
  • Starten Sie zuerst den Worker (npx claude-mem start). Fügen Sie --dry-run hinzu, um die Quell- und Druckanzahl abzurufen und zu überprüfen, ohne etwas zu schreiben.
  • Jede Quellseite wird abgerufen und überprüft, bevor etwas geschrieben wird. Abgelaufene oder ersetzte Mem0-Speicher und vergessene oder ältere Supermemory-Speicher werden übersprungen. Für Supermemory importiert --documents extrahierten Dokumenttext anstelle von Speichern.
  • Importierte Speicher werden für Claude Code (claude) abgelegt, sodass die Speichersuche sie findet. --platform <host> (zum Beispiel codex oder cursor) legt sie unter einem anderen Host ab. Bei jeder Beobachtung werden der Quelldatensatz, die ID, die Zeitstempel, die Metadaten, die Kontobezeichnung und der Umfang gespeichert.
  • Das erneute Ausführen desselben Befehls ist sicher: Bereits gespeicherte Datensätze werden als vorhanden gezählt. Es gibt keinen Hintergrundjob und keine automatische Wiederholung. – Dies ist ein einseitiger Import, keine Synchronisierung. Änderungen an der Quelle führen zu neuen Beobachtungen. Löschungen und Abläufe an der Quelle werden nicht übernommen.
  • Grenzwerte: Standardmäßig 10.000 Datensätze (--max-records bis zu 100.000), 100 MiB Quellantworten, eine Anforderungsfrist von 15 Sekunden (--timeout-ms bis zu 120.000) und 100.000 Zeichen pro Datensatz. Nichts wird stillschweigend abgebrochen: Ein übergroßer Datensatz oder eine fehlgeschlagene Anfrage stoppt den Lauf. – Die Tests verwenden synthetische Mem0- und Supermemory-Antworten, keine Live-Konten.

Dokumente: https://docs.claude-mem.ai/usage/import-providers

Codex: Gegabelte Threads erhalten Speicher

– Gezweigte Codex-Threads beginnen mit abgerufenem Speicher (#6101). Codex 0.165 hat einen fork-Sitzungsstart für seine experimentellen angehängten Thread-Forks hinzugefügt. Der SessionStart-Hook von claude-mem stimmte nicht damit überein, sodass ein abgezweigter Thread ohne Speicher gestartet wurde. Der Haken passt jetzt zu fork.

Codex-Benutzer: Genehmigen Sie einen Hook erneut. Der Matcher des SessionStart-Hooks hat sich geändert und Codex bittet erneut um Genehmigung, wenn sich die Definition eines Hooks ändert.

  1. Holen Sie sich den neuen Matcher in ~/.codex/hooks.json. npx claude-mem update und Auto-Update tun dies, wenn bei Ihrer letzten Installation Codex ausgewählt wurde. Andernfalls führen Sie npx claude-mem install aus und wählen Sie Codex.
  2. Öffnen Sie den interaktiven Codex, führen Sie /hooks aus und genehmigen Sie den SessionStart-Hook von claude-mem.

Bis Sie es genehmigen, starten Codex-Sitzungen ohne abgerufenen Speicher. Capture funktioniert weiterhin. Bis der neue Matcher in hooks.json ist, zeigt npx claude-mem doctor die Zeile Codex hooks als veraltet an.

Auch neu

  • Serverlaufzeit: In den Suchergebnissen wird angezeigt, welcher Agent einen Speicher erstellt hat (#6100). Die Serverlaufzeit speichert nun den Agenten in jedem Speicher und füllt ihn für vorhandene Speicher aus ihrer Sitzung aus. Seine MCP-Such- und Detailzeilen fügen [via <agent>] hinzu, zum Beispiel #8 — Auth redirect decision (myproject) [via cursor]. Erinnerungen ohne aufgezeichneten Agenten zeigen kein Tag. /api/sessions/observations kennzeichnet nicht mehr jeden client als Claude Code. Die Beobachtungsergebnisse des örtlichen Arbeiters tragen den Agenten noch nicht, daher wird kein Tag angezeigt.
  • Zed (#6111, danke @AdityaxDeore, schließt #5900). npx claude-mem install (oder --ide zed) registriert den MCP-Server von claude-mem in Zeds context_servers für Suche, Zeitleiste, Details und explizite Speicherungen. Kommentare in Zeds Einstellungsdatei bleiben erhalten. Es erfolgt keine automatische Erfassung, da Zed keine Hooks oder Transkriptzugriff hat. Dokumente: https://docs.claude-mem.ai/zed-integration
  • Aider (#6112, danke @AdityaxDeore, schließt #5893). Führen Sie npx claude-mem aider install in einem Projekt aus. Es fügt .claude-mem/aider-memory.md zur read:-Liste in .aider.conf.yml hinzu und npx claude-mem aider sync aktualisiert diese Datei vom Worker. Es ist pro Projekt optional: npx claude-mem install bietet es nicht an, die Speicherdatei wird durch .git/info/exclude von Git ferngehalten und es weigert sich, in Ihrem Home-Ordner ausgeführt zu werden. Keine automatische Erfassung. Dokumente: https://docs.claude-mem.ai/aider-integration
  • Grok Build erhält beim Sitzungsstart den abgerufenen Speicher (#6180, danke @krishnadobhal, schließt #5950). Grok Build ignoriert, was SessionStart-Hooks ausgeben, sodass abgerufene Notizen nie das Modell erreichten. claude-mem grok install schreibt .grok/rules/claude-mem-context.md in den aktuellen Ordner, den Grok Build aus trusted-Ordnern lädt. Der Worker aktualisiert die Zusammenfassung nach jeder Sitzung, nur in den Ordnern, in denen Sie sie installiert haben. Ein ausgeschlossenes Projekt erhält eine „ausgeschlossene“ Zeile anstelle von Notizen. Die Erfassung bleibt unverändert. Dokumente: https://docs.claude-mem.ai/grok-build
  • Französisch in der Sprachauswahl für „Meine Arbeit“, den Viewer, die Ersteinrichtung und Observation TV (#6107, danke @QuantScorpus). Ihre Erinnerungen, Regeln und Zitate bleiben wie geschrieben.
  • Drei neue Voreinstellungen für den OpenAI-kompatiblen Anbieter. Jede ist standardmäßig auf ein kleines, schnelles Modell eingestellt, da die Speicherextraktion ein hohes Volumen erfordert: – AtmoRouter, zai/glm-5.3-flash (#6108, danke @BeckleyTenriajeng)
    • TrustedRouter, deepseek/deepseek-v4-flash (#6174, danke @jperla). trustedrouter/auto bleibt als Opt-In verfügbar. Es kann eine Anfrage an ein Modell mit Grenzpreisen weiterleiten. – HopBase, deepseek-v4.1-flash (#6181, danke @victor-zzh)

Korrekturen

Datenschutz und Sicherheit

  • Der Datenordner claude-mem ist nur dem Besitzer vorbehalten (#6091, danke @DeryFerd). Unter macOS und Linux wurde ~/.claude-mem (Datenbank, Einstellungen, .env, Hook-Spool, Backups) mit einem einfachen mkdir erstellt, sodass es unter der gemeinsamen 022-Umask von anderen Konten auf dem Computer gelesen werden konnte. Er wird nun als 0700 angelegt, ein bestehender Ordner wird beim nächsten Start verschärft und neue Hook-Spool-Einträge werden als 0600 geschrieben.
  • MCP save_memory würdigt CLAUDE_MEM_EXCLUDED_PROJECTS (#6105, danke @Zhong-fan, gemeldet von @Kirat0201 in #6098; @0xABCD01 hat den gleichen Fix in #6166 gesendet). Ein Speichervorgang von einem ausgeschlossenen Checkout wurde über MCP gespeichert, während derselbe Speichervorgang über HTTP übersprungen wurde. Es wird jetzt übersprungen und die Antwort lautet „Nicht gespeichert: Dieser Checkout wird durch CLAUDE_MEM_EXCLUDED_PROJECTS ausgeschlossen.“ anstelle von „Gespeicherter Speicher #?: Ohne Titel.“ Die Cline- und Kilo-Anleitungen sagen es jetzt (#6190).
  • Serverlaufzeit: Der MCP-Connect-Befehl lehnt einen unbrauchbaren Host ab (#6176, danke @DeryFerd). Ohne CLAUDE_MEM_PUBLIC_URL erstellten GET /v1/connect und POST /v1/keys den Befehl zum Einfügen aus dem Host-Header der Anfrage und kopierten Leerzeichen, Anführungszeichen oder Pfade hinein. Ein Wert, der kein Host sein kann, erhält jetzt 400 InvalidHost und es wird kein Schlüssel geprägt.
  • Sync-Hub: FORWARD_ORIGIN muss https:// verwenden (#6175, danke @DeryFerd). Der Forward-Proxy kopiert den eingehenden Authorization-Header zum Ziel, sodass ein einfacher http://-Ursprung ihn ohne TLS senden könnte. http:// ist nur für Loopback-Hosts zulässig. Ein Wert, der keine verwendbare URL ist, schlägt jetzt lautstark fehl, anstatt stillschweigend auf den Pfad des dauerhaften Objekts zurückzugreifen.

Installieren und deinstallieren

  • Bei der Deinstallation werden die Gemini CLI-Hooks entfernt (#6088, danke @tanishqbaweja). npx claude-mem uninstall hat das Plugin gelöscht, aber die fünf Gemini CLI-Hooks von claude-mem in ~/.gemini/settings.json belassen, sodass Gemini CLI bei jedem Sitzungsstart, jeder Eingabeaufforderung, jedem Tool-Aufruf und jedem Rundenende eine fehlgeschlagene Hook-Nachricht ausgegeben hat. Jetzt deinstallieren entfernt sie und behält Ihre eigenen Einstellungen und Hooks bei. Ein settings.json mit Kommentaren bleibt unberührt, also entfernen Sie diese Haken von Hand.
  • Durch das Abbrechen der API-Tastenaufforderung wechseln Sie nicht mehr zu Claude (#6161, danke @bulanovk). Bei --provider gemini oder --provider openrouter und ohne gespeicherten Schlüssel schrieb das Abbrechen der Schlüsselaufforderung CLAUDE_MEM_PROVIDER='claude' und fuhr fort. Es stoppt jetzt mit einem Fehler und ändert nichts. – Die Legacy-Config-Prüfung des Codex-Installationsprogramms erweitert ein führendes ~\ nur unter Windows, wie der Rest von claude-mem (#6093, danke @DeryFerd).

Arbeiter und Speicher

  • Ein Worker, der beim Start auf eine ausgelastete Datenbank stößt, versucht es erneut, anstatt minutenlang mit 503 zu antworten (#6145, danke @montjeffrey, Refs #3603). Ein Ersatzarbeiter könnte während des Datenbankstarts einmal auf SQLITE_BUSY_SNAPSHOT drücken, es nie erneut versuchen und jede Anfrage bis zu einem manuellen Neustart (ca. 11 Minuten im Bericht) mit „Dienstinitialisierung“ beantworten. Der Startversuch wiederholt einen Besetztfehler nun dreimal, nach 1, 2 und 4 Sekunden. Der schlimmste Fall (27 s) passt in die 30 s, die der Haken darauf wartet, dass der Arbeiter bereit ist. Andere Fehler schlagen immer noch sofort fehl.
  • Durch das Schließen der Datenbank wird sie freigegeben (#6090, danke @DeryFerd). Zwischengespeicherte vorbereitete Anweisungen hielten die Verbindung und die Datenbankdatei nach dem Schließen geöffnet. Unter Windows wurden Wiederherstellungs-Swaps und die Bereinigung temporärer Ordner mit EPERM oder EBUSY blockiert. – Die Chroma-Bereinigung für gelöschte Sitzungen überlebt einen Worker-Exit (#6163, danke @Afloat16). Wenn der Worker beendet wurde, bevor die Bereinigung in der Warteschlange ausgeführt wurde, wurden die Vektoren der gelöschten Zeilen nie entfernt. Die Bereinigung wird nun aufgezeichnet, bevor sie beginnt. Die gleiche Änderung behebt eine Prüfung, die eine fehlende Zeile auf Bun als wiederhergestellt behandelte. – Bei Bun wird eine Datenbank, deren Ausschlusstabelle für den Synchronisierungsstart verloren gegangen ist, neu erstellt, anstatt eine leere Liste beizubehalten (#6189). – Ein ausgefallener /api/ready-Abonnent stoppt den Startvorgang für die anderen nicht mehr oder führt zu einem Startfehler (#6127, danke @Afloat16).

Aufnahme- und Erinnerungsnotizen

  • CLAUDE_MEM_SKIP_BASH_PATTERNS gilt für Antigravity CLI (#6096, danke @tanishqbaweja). agy meldet sein Shell-Tool als run_command, das die Musterprüfung nicht gelesen hat, sodass ausgeschlossene Befehle gespeichert und an den Beobachter gesendet wurden. – Eine explizite Notiz, die ein Nullzeichen enthielt, konnte die ID einer anderen Notiz erhalten, während ihr eigener Text nicht gespeichert wurde (#6170, danke @Kirat0201, schließt #6169). – Eine Claude-Code-Speicherdatei, deren Beschreibung oder metadata.type geändert wurde, wird als neue Revision gespeichert, anstatt als bereits importiert gemeldet zu werden (#6186, danke @Kirat0201, schließt #6171).
  • Erinnerungsnotizen (danke @Afloat16): – Der Titel einer Notiz stammt aus den tatsächlichen Überschriften und nicht aus einem # comment in einem Codebeispiel (#6156). – Felder, die unter dem metadata: einer Notiz verschachtelt sind, überschreiben nicht mehr den eigenen Typ oder die Sitzung der Notiz, und ein YAML-Kommentar beendet den Block nicht mehr (#6157).
    • memory ingest --source oder --cwd ohne Wert stoppt mit einem Verwendungsfehler, anstatt den aktuellen Checkout zu importieren (#6150). – Beim erneuten Scannen eines Transkripts wird eine importierte Abzweigung nicht mehr zweimal eingefügt, wenn zwei nahegelegene Abzweigungen denselben Text haben (#6149).
    • Mit CLAUDE_MEM_DEDUP_ENABLED=true werden Titel, die sich nur in Codezeichen (C++ und C#, src/config.ts und src config ts, Versionsnummern) unterscheiden, nicht mehr in einer Zeile zusammengeführt, wodurch die zweite Zeile verloren ging (#6120).
    • Importierte Beobachtungen, deren Fakten oder Dateien als eine Zeichenfolge gespeichert wurden, zeigen sie beim Abruf erneut an (#6134).

Suche und Kontext (danke @Afloat16, sofern nicht anders angegeben)

– Die semantische Suche vergleicht Datumsfenster mit den gespeicherten Zeilen, nicht mit der Kopie von Chroma, sodass eine Zeile, die in SQLite, aber noch nicht in Chroma aktualisiert wurde, im rechten Fenster landet (#6153).

  • Nach Datum sortierte Dateisuchen überspringen Chroma, sodass sie bei einem Chroma-Ausfall oder einer langsamen Einbettung nicht mehr fehlschlagen (#6123).
  • Der Dateikontext gibt die neuesten Beobachtungen zurück, wenn mehrere einen Zeitstempel teilen (#6118). – Der Kontextcache behält den richtigen Invalidierungsbereich bei, wenn das Rendern nicht in der richtigen Reihenfolge abgeschlossen wird, sodass er bei einem späteren Schreibvorgang in einem übernommenen Projekt aktualisiert wird (#6164). – Die Tiefensuche gibt ihrem untergeordneten Prozess nur die tatsächlich verbleibende Zeit, sodass ein Taktschritt wie eine NTP-Korrektur nicht mehr zu einem frühen Leer-Timeout führt (#6177, danke @DeryFerd).

Codex als Speicheranbieter (danke @Afloat16)

– Die Protokollbeschränkung von 8 MiB gilt für jede JSON-Zeile, nicht für alles, was gepuffert wird, sodass gültige Ausgaben nicht mehr abgelehnt werden (#6119). – Eine geschlossene Standard-Pipe während eines Turns schlägt fehl, dass dieser Turn sauber statt escaping als unbehandelter Fehler angezeigt wird (#6130). – Eine abgelaufene Anfrage hinterlässt keinen Abbruch-Handler mehr, der bei der nächsten Runde auf einem neuen App-Server fehlschlagen könnte (#6133).

Intelligentes Lesen der Datei

– smart_outline markiert keine Deklarationen mehr neben einem Export in derselben Zeile wie [exported] (#6141, danke @liuyinchu). – Jetzt indiziert (danke @Afloat16): anonyme export default-Funktionen, Pfeile und Klassen (#6151), Swift-Protokollmethoden und körperlose Scala-Methoden (#6154) sowie Java @interface-Deklarationen und ihre Elemente (#6160). – Die intelligente Codesuche liest jede Datei über ein Handle und stoppt bei der Obergrenze von 512 KiB, sodass eine nach der Größenprüfung ersetzte Datei das Limit nicht überschreiten kann (#6124, danke @Afloat16).

Meine Arbeit

  • Der Zielschritt verwendet die Sprache des Laufs (#6187, danke @0xABCD01, schließt #6185, gemeldet von @Fly-onlyone). Die Sprachlinie erreichte jeden Schritt außer den Zielen, sodass in #6185 147 englische Eingabeaufforderungen zu spanischen Zielen führten. Ein erster Lauf nur mit Zielen ohne festgelegte Sprache kann immer noch erraten werden. CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE legt es fest.
  • Auch in meiner Arbeit (danke @Afloat16):
    • Eine Jev-Antwort, die in der Mitte des Körpers abgeschnitten wird, gilt als Ausfall und nicht als dauerhafter Fehler für dieses Element, sodass bei der nächsten Aktualisierung erneut gefragt wird (#6158). – Ein neues git init, ein neues verschachteltes Repository oder ein entferntes .git wird übernommen, wenn My Work das nächste Mal das Projekt einer Sitzung ausarbeitet, und nicht erst nach einem Worker-Neustart (#6165). – Beim automatischen Löschen werden verspätete Lesevorgänge aus einer Runde oder einem bereits beendeten Gespräch ignoriert (#6152). – Besitzeraufforderungen behalten ihr volles Budget von 3.000 Zeichen, wenn sie Emojis und andere Zeichen außerhalb der Basisebene enthalten (#6162). – Der Opt-in-Korpus-Agent API gleicht Akzent-, Hindi-, Bengali- und spitze hebräische Wörter ab (#6168). – Die Gemini-Nutzungssummen im Setup behalten die Anzahl der abgeschlossenen Token bei, wenn dieselbe Antwort zweimal gespeichert wurde (#6146).

Aktuelle Sitzungen verwenden eine indizierte Zusammenfassungsprüfung (#6132). Der Projektkatalog entfernt Duplikate mit Sätzen (#6135). Lange eingefügte Abfragen werden bei der Obergrenze von 500 Begriffen nicht mehr gescannt (#6147).
