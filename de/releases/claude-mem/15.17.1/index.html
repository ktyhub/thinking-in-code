claude-mem v15.17.1

Offene Sitzungen werden nach einem Update weiterhin erfasst

Seit 15.16.0 löscht der Worker fünf Minuten nach dem Start und dann stündlich alte Plugin-Versionen aus dem Plugin-Cache von Claude Code. Eine Claude Code-Sitzung, die bereits geöffnet war, als ein Update eintraf, wird weiterhin aus dem Ordner der älteren Version ausgeführt. Nachdem der Sweep diesen Ordner gelöscht hatte, weigerte sich Claude Code, jeden claude-mem-Hook für diese Sitzung auszuführen („Plugin-Verzeichnis existiert nicht“), sodass die Sitzung stillschweigend aufhörte, Eingabeaufforderungen, Toolaufrufe, Beobachtungen und Zusammenfassungen zu speichern.

Der Sweep liest nun die .in_use-Datensätze, die Claude Code für jede Plugin-Version führt, und behält eine Version bei, solange eine davon geladene Sitzung noch läuft. Ordner, die von keiner laufenden Sitzung verwendet werden, werden beim nächsten Sweep dennoch entfernt, sodass die Datenträgerbereinigung von 15.16.0 bestehen bleibt. Der Worker-Sweep, npx claude-mem prune (und sein --dry-run) und der Installer folgen alle der gleichen Regel (#5971, danke @rigel905, behebt #5970).

Korrekturen

  • Kontext: Eine explizit leere Projektauswahl zeigt nichts anstelle von Beobachtungen aus jedem Projekt (#5866, danke @Afloat16).
  • Kontext: Schätzungen zu Lesekosten und Einsparungen zählen gespeicherte Fakten einmal, anstatt zusätzliche Escape-Zeichen und ein erfundenes [] für Zeilen ohne Fakten zu zählen (#5980, danke @Afloat16).
  • Beobachter: Eine gestreamte Antwort, die als Ablehnung eintrifft, zählt als generierte Ausgabe, sodass ein unterbrochener Stream nicht erneut gesendet und doppelt berechnet wird (#5843, danke @Afloat16).
  • Meine Arbeit: Der API-Agent lehnt eine Antwort ab, die der Anbieter mit content_filter gekürzt hat, anstatt einen unvollständigen Bericht zu speichern (#5878, danke @Afloat16).
  • Synchronisierung: Eine abgerufene Seite mit synchronisierten Datensätzen wartet auf einen anderen Schreiber, anstatt sofort mit der Meldung „Datenbank ist gesperrt“ fehlzuschlagen, sodass ein großer erster Abruf nicht mehr minutenlang zurückbleibt (#5996).
  • Meine Arbeit: Der Worker liest den freigegebenen Verlauf von „Meine Arbeit“ einmal pro Änderung, anstatt ihn bei jedem Synchronisierungsdurchlauf erneut zu lesen (#5986).
  • Cloud-Viewer: Ein langsam startender Cloud-Viewer lädt seine „Startseite“ neu, bis der Mitarbeiter antwortet, und eine versteckte Cloud-Registerkarte „Meine Arbeit“ schließt ihren Live-Feed, bis er wieder angezeigt wird (#5988, #5953).

Integrationen

Neue verifizierte Speicherworkflows für Agent-Frameworks, jeweils auf ein Projekt beschränkt: Vercel AI SDK (#5951), LangGraph (#5954), Pydantic AI (#5955), Microsoft Agent Framework (#6017), Haystack (#6018), LlamaIndex (#6019), Google ADK (#6020), CrewAI (#6021), Strands Agents (#6023), OpenAI-Agenten SDK (#6024), Agno (#6025), SmolAgents (#6026), AG2 (#6027) und AutoGen (#6028). Danke @Afloat16 für alle.

Auch in dieser Version

  • Cloud Viewer: Grundlage für die Weiterleitung jedes angemeldeten Kontos an seine eigene App; Das Produktionsverhalten bleibt unverändert (#5952).
  • eve-Vorlage: Die Sperrdatei der Vorlage enthält claude-mem 15.17.0, daher wird die Schaltfläche „Bereitstellen“ installiert (#5968).
