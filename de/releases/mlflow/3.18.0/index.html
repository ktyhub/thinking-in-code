mlflow v3.18.0

MLflow 3.18.0 hilft Ihnen, das Fachwissen von Agenten wiederzuverwenden, Regressionen vor dem Versand zu finden und die Qualität in der Produktion zu überwachen.

Wichtige neue Funktionen

  • Automatische Problemerkennung: Verwandeln Sie wiederkehrende Agentenfehler in Probleme, die Sie untersuchen und beheben können. Die spezielle Registerkarte „Probleme“ gruppiert verwandte Probleme und verknüpft Ergebnisse mit der Nachverfolgung von Beweisen. Zeitplanerkennung, um ständig neuen Datenverkehr zu überprüfen. (#27193, #26751, #26754, #26791, #26919, #26955, #26961, #26967, #27009, #27002, #27003, #27006, #27137, #27181, #27249, @tanghaoji; #27070, @B-Step62)
  • Skill Registry: Teilen Sie das Fachwissen Ihres Teams über Agenten und Projekte hinweg mit einem zentralen Katalog wiederverwendbarer Fähigkeiten. Entdecken Sie vorhandene Fähigkeiten und wählen Sie die Version oder den Alias ​​aus, die Sie in jedem Agent verwenden möchten. Experimental. (#26736, @mprahl; #26900, @bardenr; #27088, @Rohitkanithi)
  • Überarbeitete Auswertung und Trace-Vergleiche zum Auffinden von Regressionen: Finden Sie die Regressionen, die sich hinter aggregierten Bewertungen verbergen, bevor Sie ein Agent-Update versenden. Die neu gestaltete Vergleichs-Benutzeroberfläche führt Sie von Bewertungsänderungen zu den Eingaben, Gesprächen und den dahinter stehenden Verfolgungsschritten. Ein experimentelles Python API fügt statistische Vergleiche hinzu, um Verbesserungen von Störungen zu unterscheiden. (#26991, #26733, #26739, #26740, #26770, #26771, #26782, #26783, #26784, #26927, #26799, #26803, #26808, #26868, #26880, #26889, #26896, #27011, #27014, #27015, @joshuawong-db; #27332, #26396, @AbdulAliMamnun;
  • Online-Bewertung: Erkennen Sie Rückschritte bei der Produktionsqualität mit benutzerdefinierten codebasierten Prüfungen, die automatisch neue Ablaufverfolgungen und Gespräche mit mehreren Runden bewerten, sobald sie eintreffen. Die codebasierte Online-Bewertung ist experimentell und erfordert einen selbstgehosteten Server, der mit Jobcontainern konfiguriert ist. (#26689, #26430, #26684, #26685, #26687, @kriscon-db)

Breaking Changes

  • [Tracking] Filtern und sortieren Sie search_logged_models-Metriken nach dem höchsten Schritt und dann nach dem neuesten Zeitstempel in SQL-Speichern. Wenden Sie datasets sowohl auf das Filtern als auch auf das Sortieren an (#27215, @agtzrubio)
  • [Modellregistrierung] Stoppen Sie das Hinzufügen von registered_model_meta zu models:/-Downloads. Benutzerdefinierte Leser sollten den URI oder die Model Registry verwenden (#27173, @sunilmehta-si)
  • [Tracking] Machen Sie die Groß-/Kleinschreibung der MCP-Serverversionsidentität auf MySQL und SQL Server beachtet; Korrigieren Sie Referenzen mit nicht übereinstimmender Groß-/Kleinschreibung vor dem Upgrade (#25920, @LobsterQBA)

Datenbank-Upgrade: Sichern Sie das SQL-Backend und planen Sie ein Wartungsfenster. Stoppen Sie MLflow-Server und andere Autoren, führen Sie mlflow db upgrade <database-url> mit MLflow 3.18.0 aus und starten Sie mit der neuen Version neu. Die MCP-Versionsmigration prüft MySQL- und SQL Server-Referenzen auf Übereinstimmungen mit exakter Groß-/Kleinschreibung und stoppt, bevor sich das eigene Schema ändert, falls eine Korrektur erforderlich ist. Bei Datenbanken, bei denen die Groß-/Kleinschreibung nicht beachtet wird, verwenden Registrierungs- und MCP-Berechtigungen jetzt gespeicherte Ressourcennamen. Speichern Sie anders geschriebene Zuschüsse erneut in der hinterlegten Schreibweise. Befolgen Sie die Anleitung zum Datenbank-Upgrade.
