Codewal v0.9.3

Codewhale ist das öffentliche Produkt von Shannon Labs. Der codewhale Befehls-, NPM-Paket- und Release-Asset-Namen bleiben technisch in Kleinbuchstaben geschrieben Identifikatoren. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer aus v0.8.x Legacy deepseek / deepseek-tui-Namen sollten mit docs/REBRAND.md migriert werden.

Installieren

Empfohlen – npm (ein Befehl, alle drei Einstiegspunkte)

npm install -g codewhale

Der Wrapper lädt die passenden Dateien codewhale, codew und codewhale-tui herunter Binärdateien aus dieser Version und legt sie im selben Verzeichnis ab.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.3

Das Image enthält den codewhale-Dispatcher, das codew-Shim und die codewhale-tui-Laufzeit. Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Beide Kisten sind erforderlich – codewhale-cli produziert den codewhale-Dispatcher und das codew-Shim, während codewhale-tui die interaktive Laufzeit produziert, an die der Dispatcher delegiert. Die Installation nur einer Kiste schlägt zur Laufzeit mit dem Fehler MISSING_COMPANION_BINARY fehl.

Manueller Download – Plattformarchive (empfohlen)

Jedes der folgenden Archive enthält den codewhale-Dispatcher, den codew-Shim und die codewhale-tui-Laufzeit sowie ein Installationsskript: | Plattform | Archiv | Skript installieren | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (Installer) | CodeWhaleSetup.exe | NSIS-Setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (tragbar) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (tragbar) | codewhale-windows-arm64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Führen Sie für den Installationspfad CodeWhaleSetup.exe aus. Es installiert codewhale.exe, codew.exe und codewhale-tui.exe unter %LOCALAPPDATA%\Programs\CodeWhale\bin und fügt dieses Verzeichnis dem PATH des aktuellen Benutzers hinzu.
  • Extrahieren Sie das Archiv für Ihren Computer: codewhale-windows-x64.zip oder codewhale-windows-arm64.zip
  • Führen Sie install.bat aus (kopiert nach %USERPROFILE%\bin)
  • Fügen Sie %USERPROFILE%\bin zu Ihrem PATH hinzu Das tragbare Windows-Archiv überspringt das Installationsskript – extrahieren Sie es und führen Sie es aus einem beliebigen Verzeichnis aus. Das NSIS-Installationsprogramm ist derzeit nicht signiert und löst möglicherweise Windows SmartScreen aus, bis ein Signaturzertifikat in die Release-Pipeline eingebunden wird. An jede Plattform sind unten auch nackte, nicht archivierte Binärdateien angehängt (codewhale-<platform>, codew-<platform> und codewhale-tui-<platform>) – der npm-Wrapper und der In-App-codewhale update laden die passenden Laufzeitbinärdateien herunter, während die oben genannten .tar.gz-/.zip-Archive der empfohlene manuelle Download sind und zusätzlich ein Installationsskript bündeln. Das alte NPM-Paket deepseek-tui ist veraltet und wird nicht erneut veröffentlicht. Informationen zur Migration von v0.8.x-Legacy-Binärnamen finden Sie unter docs/REBRAND.md.

Überprüfen (empfohlen)

Laden Sie die Prüfsummenmanifeste aus dieser Version herunter und überprüfen Sie:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

Was ist in v0.9.3

Dies ist der Quellkandidat von Codewhale v0.9.3. Es handelt sich nicht um eine veröffentlichte Veröffentlichung bis die passenden Tags, Pakete, Prüfsummen und Release-Assets vorhanden sind. DeepSeek V4 Flash ist jetzt eine erstklassige Codewhale-Route und die agentenorientierte Lösung Die Werkzeugoberfläche wurde auf die aktuellen kanonischen Aktionswerkzeuge reduziert Modelle tatsächlich brauchen. Diese Version stärkt auch Anmeldeinformationen, Autorisierung, Haltbarkeit, Komprimierung und macOS-Dateianbietergrenzen beim Löschen veraltete Laufzeit- und Abhängigkeitsoberfläche.

Hinzugefügt

  • Native deepseek-v4-flash-Unterstützung über DeepSeeks Responses API, einschließlich Zustandslose Wiederholung von Argumentationselementen, semantische SSE-Terminalereignisse, strukturiert Funktionsaufrufe und -ausgaben, apply_patch und modellbewusstes Wire-Format Auswahl. Genaue aktuelle Flash-IDs verwenden Antworten; Zukunft direkt deepseek-vN-*-Modell-IDs erben diese Route konservativ, während sie benutzerdefiniert sind DeepSeek-kompatible Endpunkte behalten Chat-Abschlüsse bei, sofern sie nicht konfiguriert sind sonst. – Eine reine Pipe-codewhale auth print-api-key-Übergabe für explizit ausgewählte Anbieter. Es teilt die heimische Berechtigungsberechtigung von Codewhale und lehnt dies ab Terminalausgabe und verhindert, dass Sentinel-Platzhalter live geschaltet werden Anmeldeinformationen.
  • max_tool_calls-Durchsetzung pro Runde am Motorzugangstor, plus a Schreibbereich für benannte Dateien mit separater Lesenaht. Die Laufzeit lehnt nun ab Überschreitet Aufrufe das Budget, bevor sie ausgeführt werden, und behält die Schreibgrenze des Operators bei explizit (#4415). – Laufzeitvertrag, Quellstruktur und Persistenz-Rückstand verhindern das Namensdrift zu vermeiden, anstatt große Eigentumsflächen stillschweigend wachsen zu lassen (#3921, #4785).

Geändert

– Modellsichtbare integrierte Funktionen verwenden jetzt die kanonischen Modelle Bash, File und Run Aktionsschemata. apply_patch bleibt als einziger direkter Custom verfügbar Bearbeitungstool, das von DeepSeek Responses unterstützt wird. Der gebündelte Stop-Ship-Workflow, Flottenbefestigungen, Shell-Verknüpfungen und Motortests verwenden dieselbe Kanonik Wortschatz. – Kanonische File { action: "write" }-Anfragen werden jetzt über dasselbe weitergeleitet semantische Repo-Law-Prüfungen als erster Schreibpfad. Genehmigung, Vollzugriff, und die Workflow-Ausführung kann die Sicherheitsuntergrenze des Repositorys nicht durch Auswahl umgehen das kanonische Schema.

  • Die Codewhale-Heimauflösung wird für CLI, TUI, Bundesstaat und Secret geteilt Geschäfte. doctor ist standardmäßig offline und unterscheidet die Anmeldeinformationsquelle von Verfügbarkeit und meldet einen konsistenten Pfad-Snapshot.
  • Dauerhafte Schreibvorgänge für Laufzeitereignisse werden über gleichzeitige Prozesse hinweg serialisiert. Der Blockierungsverlauf wartet darauf, asynchrone Worker zu entfernen und das Anbieterkontingent zu erschöpfen bleibt durch Komprimierung typisiert und kann wiederholt werden (#4522). – Die Fähigkeitserkennung speichert den zusammengeführten Katalog hinter der Validierung der überwachten Zeit zwischen. Große Skill-, Engine-, Subagenten-, UI- und Ambient-Ocean-Testblöcke leben jetzt darin eigene Testnähte.
  • Begründungszusammenfassungen bleiben in der Sprache des Benutzers, völlige Qualle Silhouetten verschieben sich um den Transkripttext und zwischengespeicherte Ozeanrahmen werden hinzugefügt ihre Palettenidentität (#4807).
  • Der Authorization-Order-Vertrag dokumentiert und testet nun, wie Modi, Hooks, Berechtigungsregeln, Sicherheitsuntergrenzen, Repo-Gesetz, Genehmigungen und Sandboxing-Komposition (PR #4980).

Behoben

– macOS-Sandbox-Erweiterungen decken CloudStorage-/Dateianbieter-Arbeitsbereiche ohne ab Erweiterung unabhängiger Wege; Danke @Watcher24 für den #4085-Bericht und Reproduktion.

  • Der Vordergrund-Shell-Status wird vor der Steuerung gelöst, also ein unterbrochener Befehl kann den Komponisten nicht weiter besitzen (PR #4979). – Fehler auf MCP-Anwendungsebene und fehlerhafte Fehlerumschläge werden nicht geschlossen anstatt wie eine erfolgreiche Tool-Ausgabe auszusehen.
  • Optionale PDF-Fehler sind wahrheitsgetreu und die PDF-Klassifizierung macht keine Fehler mehr unterstützte Eingaben.
  • In Klammern eingefügte Inhalte werden aus Spuren und Anmeldeinformationsdiagnosen entfernt Behandeln Sie Platzhalter-Sentinels niemals als verwendbare Schlüssel.

Entfernt

  • Die alten aufrufbaren Aliase exec_shell, run_shell_command, read_file, write_file, list_dir, grep_files, file_search und das Duplikat Arbeits-/RLM-Registrierungen. Historisches Transkript und Richtliniensemantik bleiben erhalten lesbar, aber neue Modellumdrehungen erhalten nur die kanonische Aktionsfläche. – Die gebündelte PDF-Parser-Abhängigkeitskette, die durch die kleinere ersetzt wird optionale Extraktionsgrenze, verfolgt von #4382.

Mitwirkende

  • Turisla (@greyfreedom) dokumentiert und hat den Autorisierungsauftragsvertrag in PR #4980 gesperrt.
  • Nightt (@nightt5879) fester Vordergrund Granatenablösung vor dem Lenken in PR #4979.
  • Watcher24 (@Watcher24) hat das macOS bereitgestellt Bericht und Reproduktion des Dateianbieters für #4085.
  • Fred Leitz (@fleitz) behält erforderlich Quellenangabe für den kanonischen Workspace-Fix Bash aus PR #4673 und Problem Nr. 4674. Vollständige Hinweise finden Sie unter CHANGELOG.md und unter docs/CHANGELOG_ARCHIVE.md für ältere Versionen.
