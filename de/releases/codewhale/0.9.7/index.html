Codewal v0.9.7

Codewhale ist das öffentliche Produkt von Shannon Labs. Der codewhale Befehls-, NPM-Paket- und Release-Asset-Namen bleiben technisch in Kleinbuchstaben geschrieben Identifikatoren. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer aus v0.8.x Legacy deepseek / deepseek-tui-Namen sollten mit docs/REBRAND.md migriert werden.

Installieren

Empfohlen – npm (ein Befehl, beide Einstiegspunkte)

npm install -g codewhale

Der Wrapper lädt die übereinstimmenden Befehlsressourcen codewhale und codew herunter aus dieser Version. Beide enthalten die gleiche kompilierte Laufzeit.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.7

Das Bild stellt die gleiche Laufzeit bereit wie codewhale und codew. Die Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli --locked

Das Cargo-Paket installiert codewhale. Cargo kann keinen zweiten Befehl erstellen Alias von einem binären Ziel; Benutzer, die die kürzere Schreibweise wünschen, können a hinzufügen codew-Symlink zu der installierten ausführbaren Datei. Das npm, Homebrew, Archiv, Shell-Installer und Containerkanäle installieren beide Befehlsnamen direkt.

Manueller Download – Plattformarchive (empfohlen)

Jedes unten aufgeführte Archiv enthält dieselbe Laufzeit unter codewhale und codew-Befehlsnamen sowie ein Installationsskript:

| Plattform | Archiv | Skript installieren | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (Installer) | CodeWhaleSetup.exe | NSIS-Setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (tragbar) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (tragbar) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Führen Sie für den Installationspfad CodeWhaleSetup.exe aus. es wird installiert codewhale.exe und codew.exe unten %LOCALAPPDATA%\Programs\CodeWhale\bin und fügt dieses Verzeichnis dem hinzu PATH des aktuellen Benutzers.
  • Extrahieren Sie das Archiv für Ihre Maschine: codewhale-windows-x64.zip oder codewhale-windows-arm64.zip
  • Führen Sie install.bat aus (kopiert nach %USERPROFILE%\bin)
  • Fügen Sie %USERPROFILE%\bin zu Ihrem PATH hinzu

Das tragbare Windows-Archiv überspringt das Installationsskript – extrahieren Sie es und führen Sie es aus einem beliebigen Verzeichnis aus. Das NSIS-Installationsprogramm ist derzeit nicht signiert und löst möglicherweise Windows SmartScreen aus, bis ein Signaturzertifikat in die Release-Pipeline eingebunden wird.

Jede Plattform verfügt außerdem über nackte, nicht archivierte codewhale-<platform> und codew-<platform>-Vermögenswerte. Die sieben codewhale-tui-<platform>-Dateinamen An v0.9.5 angehängt sind byteidentische Kompatibilitätskopien, die nur zum Verlassen verwendet werden Bereits installierte v0.9.4 clients entdecken und überqueren diese einzelne Binärdatei Übergang; Aktuelle Installationsprogramme stellen keine dritte Laufzeit zur Verfügung. Das alte npm Paket deepseek-tui ist veraltet und wird nicht erneut veröffentlicht. Für Migration aus v0.8.x-Legacy-Binärnamen, siehe docs/REBRAND.md.

Überprüfen (empfohlen)

Laden Sie die Prüfsummenmanifeste aus dieser Version herunter und überprüfen Sie:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

Was ist in v0.9.7

Codewhale v0.9.7 hält den Katalog ordentlich. Grok 4.6 landet als normaler Katalog Anstelle eines anbieterförmigen Stapels von Sonderfällen tritt OrcaRouter als Reihe bei benannter Anbieter und eine Panik-Sicherheitswarnung in lru wird durch Aufheben des gelöscht Pin, der es verursacht hat, anstatt in seiner Nähe zu leben.

Hinzugefügt

  • Grok 4.6 ist der direkte xAI-Standard, auf den der Alias grok verschoben wird und grok-4.5 weiterhin explizit auswählbar. Sein 500K-Kontext, Text-/Bildeingabe, Tool und Unterstützung für strukturierte Ausgabe, low/medium/high/xhigh-Argumentation Die Bemühungen (Standard high) und die serverseitige Websuche stammen alle von der Models.dev-förmiger Katalog statt modellspezifischer Code. reasoning_effort erreicht die Leitung nur auf der exakten Route des Erstanbieters https://api.x.ai/v1, und die nutzungsbewusste Preisgrenze von 200.000 Token ist darauf ausgelegt, xAI so zu steuern Aggregatorrouten, die den Modell-Slug wiederverwenden, können die xAI-Abrechnung nicht erben.
  • OrcaRouter ist ein erstklassiger benannter Anbieter: ORCAROUTER_API_KEY, Standardbasis URL https://api.orcarouter.ai/v1, deepseek/deepseek-v4-pro Standard, orcarouter/auto-Routing-, CLI---provider-Selektor- und TUI-Picker-Einträge (#5321).

Geändert

  • Reasoning-Effort-Normalisierung und der Modellwähler lesen die Veröffentlichung eines Modells reasoning_options-Liste aus dem Katalog, anstatt jede Route zu reduzieren die historische Low/Medium-Leiter. Jede Katalogzeile, die eine Aufwandsliste veröffentlicht behält seinen eigenen Wortschatz.
  • Docs zeichnen das Live-Backend-Label DeepSeek-V4-Pro-0813 von DeepSeek auf, während die Die aufrufbare API-ID bleibt deepseek-v4-pro. Es werden keine Aliase neu zugeordnet und nein deepseek-v4-pro[1m]-Selektor wird gesendet.

Behoben

  • Beim Kopieren einer Benutzer- oder Assistentennachricht wird stattdessen deren kanonischer Inhalt übernommen Reserialisierte Transkriptzeilen unter Beibehaltung von Rollenglyphen, Fortsetzungsschienen usw visuelle Umhüllung des clipboards unter Beibehaltung des verfassten Unicodes, Markdown und harte Zeilenumbrüche. Werkzeug- und Denkzellen bleiben auf dem Bestehenden Vollständiger Transkriptpfad (#5319). – load_session führt nicht mehr bei jedem Lesevorgang eine Absturzwiederherstellung durch. Snapshot-Lesungen gehen durch ein nebenwirkungsfreies load_session_snapshot und die Wiederherstellung ist eindeutig über recover_session_for_resume, also ein Einbettungshost, der eine dauerhafte Inspektion durchführt Sitzung, während ein Tool noch ausgeführt wird, erhält keine falsche Absturzreparatur mehr (#5320).

Sicherheit

– lru bewegt sich zu 0.18, um RUSTSEC-2026-0253 zu löschen, wo sich LruCache::pop() befand nicht paniksicher und könnte leere Listenzeiger hinterlassen. Der ratatui-core =0.1.0-Pin, der transitiv lru ^0.16 erzwingt, wird angehoben, also ColorCompatBackend antwortet jetzt get_cursor_position() vom verfolgten Cursor state – die vom Upstream empfohlene Problemumgehung für das Startup-CPR-Rennen (ratatui/ratatui#2483, ratatui/ratatui#2640), dass der Pin ursprünglich funktioniert hat herum. ratatui selbst bleibt bei =0.30.0 fixiert, ebenso wie die API-Oberfläche unverändert.

Bekannte Probleme

  • Der Integrationstest exec_persistent_service::failed_exec_kills_pending_service_and_exits_nonzero ist ein bestätigter Flocken unter Parallellast („Dienst-PID-Datei ist nie erschienen“). Es wird isoliert durchgeführt und hat nichts mit einer v0.9.7-Änderung zu tun.
