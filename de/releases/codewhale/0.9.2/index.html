Codewal v0.9.2

Codewhale ist das öffentliche Produkt von Shannon Labs. Der codewhale Befehls-, NPM-Paket- und Release-Asset-Namen bleiben technisch in Kleinbuchstaben geschrieben Identifikatoren. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer aus v0.8.x Legacy deepseek / deepseek-tui-Namen sollten mit docs/REBRAND.md migriert werden.

Installieren

Empfohlen – npm (ein Befehl, alle drei Einstiegspunkte)

npm install -g codewhale

Der Wrapper lädt die passenden Dateien codewhale, codew und codewhale-tui herunter Binärdateien aus dieser Version und legt sie im selben Verzeichnis ab.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.2

Das Image enthält den codewhale-Dispatcher, das codew-Shim und die codewhale-tui-Laufzeit. Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Beide Kisten sind erforderlich – codewhale-cli produziert den codewhale-Dispatcher und das codew-Shim, während codewhale-tui die interaktive Laufzeit produziert, an die der Dispatcher delegiert. Die Installation nur einer Kiste schlägt zur Laufzeit mit dem Fehler MISSING_COMPANION_BINARY fehl.

Was ist in v0.9.2

Dies ist der Quellkandidat von Codewhale v0.9.2. Es handelt sich nicht um eine veröffentlichte Veröffentlichung bis die passenden Tags, Pakete, Prüfsummen und Release-Assets vorhanden sind.

Geändert – Verhalten

  • Die Vorgängerversion model = auto wählt keinen Netzwerkklassifizierer mehr selbst aus. Halten Sie eine DeepSeek API-Taste gedrückt, um stillschweigend deepseek-v4-flash als auszuwählen Klassifikator für jede automatische Abbiegung – die Kosten pro Abbiegung auf einer Route, nach der niemand gefragt hat, und ein Anbieter, der gegenüber den anderen privilegiert ist. Auto bleibt jetzt lokal und kostenlos es sei denn, ein expliziter [auto.router]-Block benennt einen Anbieter und ein Modell. Wenn Sie sich auf den impliziten Standardwert verlassen haben, stellen Sie ihn explizit wieder her: 
    [auto.router]provider = "deepseek"model = "deepseek-v4-flash"

[auto.router] bleibt die alte model = auto-Konfiguration. Es hat nichts damit zu tun an den Adaptive Reasoning Router einer Flotte, bei dem es sich um einen gespeicherten Dienst handelt, auf den verwiesen wird Name aus einer Flottendatei und entscheidet nur, wie schwer eine bereits eingefrorene Route ist denkt. Gelandet seit v0.9.1, noch nicht veröffentlicht. Eine Reihe von Mängeln, die von a gefunden wurden Durchleseprüfung der Richtlinien-Engine, des MCP-Proxys, des Sitzungsindex, und die App-Server-Brücke – einige davon führten zu falschen Ergebnissen wurde stillschweigend erreicht, hinter einer Antwort oder einer Protokollzeile, die gut aussah. Die Die Veröffentlichung fügt außerdem Opt-in-Sitzung, Argumentation, Lokalisierung und Prüfbarkeit hinzu Oberflächen; Bestehende Standardeinstellungen bleiben stabil, es sei denn, es wird unten explizit ein Eintrag gemacht sagt etwas anderes.

Behoben

  • Die Berechtigungseinrichtung stellt nun konsistent die Produktpositionen dar. Fragen Sie, Automatische Überprüfung und voller Zugriff, anstatt das interne never-Token preiszugeben. Dieselbe gelöste Sandbox-Richtlinie steuert jetzt die Ausführung und UI-Belege: Plan bleibt schreibgeschützt, „Fragen“ und „Automatische Überprüfung“ bleiben arbeitsbereichsbezogen und haben vollen Zugriff ist tatsächlich ohne Sandbox, es sei denn, eine strengere effektive Konfiguration gewinnt. – Die Flotteneinrichtung bleibt nicht länger stehen, wenn ein Benutzer explizit eine konfigurierte auswählt Codex- oder Grok-Route mit externer Zustimmung. Die ausgewählte Route wird aktiviert und Vor dem Speichern validiert, werden Dienstplanrollen direkt in ihrem Modellschritt geöffnet. Die Überprüfung wird bei der ersten Eingabe gespeichert und neue Profile werden standardmäßig auf das persönliche Profil eingestellt Profilverzeichnis, das der Dienstplan bei der nächsten Sitzung lädt. – Dialoge mit Anbieter-Anmeldeinformationen teilen sich jetzt einen umhüllenden, geheimnissicheren API-Schlüssel Oberfläche bei jedem Nicht-OAuth-Anbieter.
