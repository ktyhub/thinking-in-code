Codewal v0.8.66

CodeWhale ist das kanonische Projekt, der Befehl, das NPM-Paket und Name des Release-Assets. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer kommen aus Die alten v0.8.x-Namen deepseek/deepseek-tui sollten migriert werden mit docs/REBRAND.md.

Installieren

Empfohlen – npm (ein Befehl, beide Binärdateien)

npm install -g codewhale

Der Wrapper lädt die passenden Laufzeitbinärdateien aus dieser Version herunter und legt sie im selben Verzeichnis ab.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

Das Image enthält den codewhale-Dispatcher, das codew-Shim und die codewhale-tui-Laufzeit. Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Beide Kisten sind erforderlich – codewhale-cli produziert den codewhale-Dispatcher und das codew-Shim, während codewhale-tui die interaktive Laufzeit produziert, an die der Dispatcher delegiert. Die Installation nur einer Kiste schlägt zur Laufzeit mit dem Fehler MISSING_COMPANION_BINARY fehl.

Manueller Download – Plattformarchive (empfohlen)

Jedes der folgenden Archive enthält den codewhale-Dispatcher, den codew-Shim und die codewhale-tui-Laufzeit sowie ein Installationsskript: | Plattform | Archiv | Skript installieren | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (Installer) | CodeWhaleSetup.exe | NSIS-Setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (tragbar) | codewhale-windows-x64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Für den Installationspfad führen Sie CodeWhaleSetup.exe aus; Es installiert codewhale.exe, codew.exe und codewhale-tui.exe unter %LOCALAPPDATA%\Programs\CodeWhale\bin und fügt dieses Verzeichnis dem PATH des aktuellen Benutzers hinzu.
  • Extrahieren Sie codewhale-windows-x64.zip
  • Führen Sie install.bat aus (kopiert nach %USERPROFILE%\bin)
  • Fügen Sie %USERPROFILE%\bin zu Ihrem PATH hinzu Das tragbare Windows-Archiv überspringt das Installationsskript – extrahieren Sie es und führen Sie es aus einem beliebigen Verzeichnis aus. Das NSIS-Installationsprogramm ist derzeit nicht signiert und löst möglicherweise Windows SmartScreen aus, bis ein Signaturzertifikat in die Release-Pipeline eingebunden wird. An jede Plattform sind unten auch nackte, nicht archivierte Binärdateien angehängt (codewhale-<platform>, codew-<platform> und codewhale-tui-<platform>) – der npm-Wrapper und der In-App-codewhale update laden die passenden Laufzeitbinärdateien herunter, während die oben genannten .tar.gz-/.zip-Archive der empfohlene manuelle Download sind und zusätzlich ein Installationsskript bündeln. Das alte NPM-Paket deepseek-tui ist veraltet und wird nicht erneut veröffentlicht. Informationen zur Migration von v0.8.x-Legacy-Binärnamen finden Sie unter docs/REBRAND.md.

Überprüfen (empfohlen)

Laden Sie die Prüfsummenmanifeste aus dieser Version herunter und überprüfen Sie:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

Was ist in v0.8.66

Hinzugefügt

  • Legacy-Status codewhale doctor / codewhale doctor --json hinzugefügt Diagnosen, die bekannte ~/.deepseek-Zustandspfade mit ihren vergleichen ~/.codewhale-Gegenstücke und kennzeichnen nicht migrierte oder Dual-Root-Daten (#3727).
  • Sakana AI Fugu als erstklassiger OpenAI-kompatibler Anbieter mit hinzugefügt sakana/fugu-Aliase, FUGU_API_KEY/SAKANA_API_KEY-Erkennung, Anbieter-Auswahl-Verkabelung, Modellvervollständigungen und Anbieterdokumente. Geerntet von #3748 von @lerugray. – WhaleFlow-to-Fleet-Startformvalidierung hinzugefügt: der Standard-Flotten-Workflow Der Vertrag erlaubt bis zu 100 Agenten insgesamt und 5 rekursive Ringe Begrenzte Schleifen/Erweiterungen vor dem Start und Beibehaltung der Modellauswahl pro Steckplatz. – Für das gelöste Problem wurde eine schreibgeschützte /config ask-rules-Ansicht hinzugefügt permissions.toml Pfad, Dateistatus, Regelanzahl und konfiguriert Werkzeug-/Befehls-/Pfadfrageregeln. Zusammengeführt aus #3569 von @greyfreedom. – context_window-Überschreibungen auf Anbieterebene hinzugefügt, sodass OpenAI-kompatibel ist Gateways und selbst gehostete Anbieter können ihr Budget anhand ihres realen Modells kalkulieren Kontextfenster (#3545). – Das native codew-Shim wurde hinzugefügt, um Archive, Windows-Installer-Eingaben usw. freizugeben. Lokale Release-Asset-Vorbereitung und Prüfsummenüberprüfung für manuelle Installationen Sie erhalten denselben kurzen Befehl, den Cargo für die Installation des Builds verwendet.
  • OpenModel als erstklassiger Anthropic Messages-Anbieter hinzugefügt, mit Konfiguration, CLI, Anbieterauswahl, Dokumente und Registrierungsabdeckung. Geerntet aus #3585 von @noaft.
  • WeCom Bridge-Bereitstellungs- und Sicherheitsdokumentation hinzugefügt, im Lieferumfang enthalten Laufzeit-/Bridge-Befehle und Richtlinien zur Genehmigungs-Timeout-Umgebung. Geerntet aus #3640 von @pkeging. – Ein Token/Cache/Kosten-scorecard-Befehl für Offline-Release-Gating hinzugefügt, Basisregressionsprüfungen und Kostentransparenz pro Runde (#3388). Stream-JSON Exec-Metadaten melden jetzt auch konservative input_analysis und visible_final_answer_chars, sodass Benchmark-Kabelbäume das Transkript messen können Wachstum und Aufblähen der endgültigen Antwort ohne Raten (#2956, #2957).
  • Für v0.8.66 wurde ein Freigabenachweis-Ledger hinzugefügt und das externe ACP geöffnet Registrierungseinreichung für CodeWhale nach Validierung der veröffentlichten Informationen codewhale@0.8.65 ACP-Authentifizierungs-Handshake mit dem Upstream-Registrierungsprüfer (#3192). – Eine typisierte [verifier]-Konfigurationstabelle für die Verifier-Preview-Spur hinzugefügt, mit enabled und das ausgelieferte verdict_policy = "hunt"-Mapping dokumentiert und validiert (#2093).
  • Hotbar Alt+1–Alt+8-Schnellsteckplatzumschaltung mit Entscheidungskartenschlüssel hinzugefügt Begriffsklärung sowie eine Einführungskarte, die das erklärt und verwerfen kann Hotbar (#3796, #3788).
  • Release-/Dokumentenhygiene: geschützte öffentliche Installations-/Versionsschnipsel und die NPM codewhaleBinaryVersion Zeiger gegen Drift, hergestellt check-docs/check-facts schlägt bei veralteten Snippets oder nicht zugeordneten Anbietern fehl und hat sync-changelog gestoppt verhindert, dass ein Release gelöscht wird, wenn nur [Unreleased] vorhanden ist (#3767, #3768, #3769, #3770, #3771, #3772).

Geändert

  • Verzögerter automatischer Modus über die benutzerseitige Modusauswahl, Zyklus, Hotbar, /mode Befehl und Laufzeit-Thread-Modus überschreibt, bis es eine eindeutige Eingabeaufforderung und hat Verhalten bei der automatischen Überprüfung; Vorhandener auto-Modustext wird jetzt auf Agent zurückgesetzt Anstatt einen Hohlmodus auszuwählen, ist das Kopieren des Genehmigungsmodals nicht mehr impliziert Der aktuelle Modus ist YOLO (#3730, #3733).
  • Die Oberfläche und die Dokumentation zur Flotteneinrichtung wurden klarer formuliert, sodass die Flotte als dauerhaft behandelt wird Subagent-Konfigurationsebene, während WhaleFlow vom Agenten erstellt wird Orchestrierungsplan, der Flottenplätze auswählt und überwacht.
  • Die standardmäßige Konstitutionsaufforderung wurde abgespeckt, die erforderliche Struktur wurde jedoch beibehalten Anker unter Regressionsabdeckung, wodurch der statische Prompt-Footprint für reduziert wird Cache-empfindliche Wendungen (#2953). – Die Genehmigungsaufforderung wurde inline und unten verankert statt im Vollbildmodus Übernahme, sodass Kontext und Steuerelemente sichtbar bleiben, während ein Tool auf eine Entscheidung wartet (#3799). – Die Hotbar ist jetzt standardmäßig ausgeblendet, bis Sie sich explizit für die Einrichtung entscheiden (#3807); die Die interaktive Agenten-Shell ist standardmäßig auch auf Genehmigungsgesteuert mit einer gemeinsamen Freigabe eingestellt Grundlinie (#3756). – Die Modusautorität löst Genehmigungsaufforderungen jetzt über eine einzige Autorität Quelle statt Prüfungen pro Oberfläche (#3795).

Behoben

  • Die Verschiebung des Legacy-Status wurde jederzeit mit einer für den Benutzer sichtbaren Migrationsbenachrichtigung angezeigt ~/.deepseek/<state> wird in ~/.codewhale/<state> verschoben oder kopiert, also Aktualisierte Benutzer wissen, dass ihre Daten erhalten geblieben sind und sich im kanonischen Zustand befinden lebt jetzt (#3726).
  • Die Sichtbarkeit des alten .deepseek/sessions für aktualisierte Installationen wurde wiederhergestellt Durch Kopieren war bereits ein leeres ~/.codewhale/sessions-Verzeichnis vorhanden Fehlende Legacy-Sitzungseinträge im primären CodeWhale-Sitzungsspeicher ohne neuere Daten zu überschreiben (#3724).
  • Beruhigte Genehmigungsrisikoklassifizierung für schreibgeschützte Shell-Befehle wie z codewhale --version, codewhale --help und git status --porcelain also Das Modal kennzeichnet die bewährte schreibgeschützte Shell nicht mehr als destruktiv (#3730).
  • Anbieter-/Modellroutenspalten zur /cache-Turn-Telemetrie hinzugefügt, also DeepSeek Cache-Treffer-Regressionen können mit automatischen Routenänderungen korreliert werden (#3738). – Die Genehmigungsbehandlung für Laufzeit-API wurde korrigiert, sodass der Arbeitsbereich trust nicht mehr automatisch aufgelöst wird gewöhnliche Werkzeugzulassungen; trust nimmt jetzt nur noch an Wiederholungsversuchen mit Vollzugriff teil Entscheidungen während YOLO/automatische Genehmigung bleibt die Genehmigungsumgehung (#3736).
  • Modale Oberflächen wurden korrigiert, sodass der gemeinsame Ansichtsstapel vorher einen undurchsichtigen Hintergrund malt Alle Überlagerungen werden angezeigt, während die Popup-Innenräume für Plan-/Anfrageeingaben und der Plan undurchsichtig bleiben Die Bestätigungsfußzeile sorgt dafür, dass Aktionsoptionen auf schmalen Terminals sichtbar bleiben (#3732). – Ein Turn-Loop-Plan-Modus-Schutz für Dateischreibtools und schreibfähiges MCP hinzugefügt Tools, damit das „No Writes“-Versprechen von Plan vor der Genehmigung oder Ausführung durchgesetzt wird, nicht nur durch die Sandbox-/Katalogebene (#3734).
  • Die dauerhafte Überprüfungssicherheitsuntergrenze für Veröffentlichungs-ähnliche Shell-Aktionen wurde beibehalten YOLO-Modus, also cargo publish, npm publish und Tag/Release-Push-Force Genehmigung statt stillschweigender automatischer Genehmigung (#3735). – Behoben: Der externe Editor „Strg+O“ friert ein, wenn die Terminaleingabe von CodeWhale funktioniert konnte weiterhin Schlüssel lesen, während Vim/Editor das Terminal besaß, insbesondere in Windows Mintty/Cygwin-Shells. Danke @buko für die präzise Reproduktion (#3657). – Die Prüfung der OHOS-Abhängigkeitsdrift gegenüber vorübergehenden Cargo-Registry-EOFs wurde verschärft indem Sie die Abhängigkeitsgraph-Prüfung erneut versuchen, bevor CI fehlschlägt. – Der /links-Anbieter-Fallback wurde auf die aktuelle URL der CodeWhale-Dokumente aktualisiert einen Link zu Baidu Qianfan-Dokumenten hinzugefügt. Geerntet aus #3621 von @noaft.
  • Gehärteter CODEWHALE_TOOL_SURFACE=shell-only für Benchmark-/Exec-Läufe: der Nur-Shell-Oberfläche verbirgt native Werkzeuge aus dem für das Modell sichtbaren Katalog und Unbekannte CODEWHALE_TOOL_SURFACE-Werte warnen jetzt, anstatt lautlos zu fallen zurück zur vollen Werkzeugoberfläche (#2954).
  • Subagent-Fanout und Lock-Hot-Paths: Event-Channel-Headroom bleibt erhalten Fortschrittsereignisse (#3783, danke @cyq1017), unabhängigen Subagenten starten lassen Verknüpfen Sie einen einzelnen parallelen Versandstapel, anstatt ihn zu serialisieren (#3801), gerendert die Subagenten-Seitenleiste/ListSubAgents aus einem schreibgeschützten Snapshot mit Bounded Bereinigung (#3803), nicht blockierende Best-Effort-Sendungen wurden für die Aktualisierung von ListSubAgents verwendet Während noch auf kritische Ereignisse gewartet wird (#3802), wurde der Status des Subagenten verschoben Persistenzdatenträger-E/A von der Manager-Schreibsperre entfernt (#3805) und try_lock verwendet für Shell-Manager-Aktualisierung in asynchronen UI-Pfaden (#3804).
  • Herkunft: Laufzeitfortsetzungen und SubAgentHandoff erben nun Status YOLO-Autorität, während MemoryRecall, ImportedTranscript und AssistantGenerated-Eingänge bleiben geschützt (#3817).
  • Ehrlichkeit bei Genehmigungen: Sitzungsbezogene Genehmigungen werden korrekt gekennzeichnet statt „immer“ und Genehmigungsentscheidungen wurden in den Werkzeugergebnissen angezeigt (#3766). Die Mitwirkenden für diese Veröffentlichung finden Sie im changelog-Eintrag oben – Vielen Dank an alle, deren Berichte, PRs, Rezensionen und Reproduktionen es geprägt haben. Vollständige Hinweise finden Sie unter CHANGELOG.md und unter docs/CHANGELOG_ARCHIVE.md für ältere Versionen.
