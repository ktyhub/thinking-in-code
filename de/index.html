Methode

Wie STAGS release notes sammelt, normalisiert und veröffentlicht.

Ansehen →
01 Sammeln Ein geplanter Job fragt die GitHub-Releases API für jedes verfolgte Repository ab und überspringt Entwürfe, leere Körper und Vorabversionen, sofern nicht anders konfiguriert.
02 Normalisieren Jede Veröffentlichung wird auf einen stabilen Datensatz reduziert: Projekt, semantische Version, Veröffentlichungsdatum, Veröffentlichungskanal und eine aus dem Hauptteil extrahierte einzeilige Zusammenfassung.
03 Veröffentlichen Notizen werden als Markdown im Repository gespeichert und bei jedem Push als statische Seiten gerendert, sodass die Website schnell bleibt und jeder Eintrag eine stabile URL hat.
