clickhouse-java v0.11.0

版本迁移指南

重大变更

  • [client-v2, jdbc-v2] 套接字缓冲区选项 socket_rcvbuf 和 socket_sndbuf 不再有默认值。现在，仅当应用程序设置选项时才会应用这些选项 (Client.Builder#setSocketRcvbuf, Client.Builder#setSocketSndbuf，或同名的属性）。这样做是为了让操作系统 TCP 堆栈自动调整 价值观。除非绝对需要，否则不要设置它们。 (https://github.com/ClickHouse/clickhouse-java/issues/3121)

  • [client-v2，jdbc-v2] 默认情况下不再重试服务器错误 159 (TIMEOUT_EXCEEDED)。它有自己的 重试原因 ClientFaultCause.ServerTimeoutExceeded，ServerRetryable 不包括且不在其中 默认 client_retry_on_failures 列表。将 ServerTimeoutExceeded 添加到列表中以重试此错误。 (https://github.com/ClickHouse/clickhouse-java/issues/3072)

  • [r2dbc] 不再支持 1.0.0 之前的工件，因为 R2DBC API 达到了稳定的 1.0.0 版本。

  • [jdbc-v2] DatabaseMetaData#getTables 现在在 REMARKS （表注释）和 TYPE_SCHEM 中返回 null 默认值，因为元数据是使用 SHOW 语句读取的（请参阅 New 中的 jdbc_metadata_use_show_statements 条目） 特点）。设置 jdbc_metadata_use_show_statements=false 以获取表注释。 (https://github.com/ClickHouse/clickhouse-java/issues/2907)

  • [client-v2,jdbc-v2] 添加了对块压缩流的 ZSTD 压缩支持，默认情况下不使用 压缩 client 请求。以前这种情况下仅支持 LZ4。注意：添加了 ZSTD 库和原生 将库添加到 -all JDBC 包，因为现在需要它与服务器一起使用。 （https://github.com/ClickHouse/clickhouse-java/issues/3105）。

  • [client-v2，jdbc-v2] User-Agent 标头现在使用标准 ClickHouse client 格式， <client name> clickhouse-java-v2/<version> (lv:java/<java.version>; os:<os.name>; hc:ahc_<version>)： jvm:<version> 现在是 lv:java/<version>，操作系统是 os: 条目，尾随 Apache-HttpClient/<version> 替换为 hc:ahc_<version> 条目（Apache HttpClient 版本， client 内置）。添加了Client.Builder#setClientName(String, Map)（属性client_id_metadata）来添加 评论组的键/值对。该对可以设置 lv、os 和 hc 来替换 client 的值。 从 client 名称和自定义 User-Agent 值中删除前导和尾随空格。空白值 为一项操作设置的值视为未设置。如果 client 的 User-Agent 值低于 client，则 client 会记录警告 配置长度超过 200 个字符。 在 system.query_log 中解析 http_user_agent 的查询必须使用新格式。 (https://github.com/ClickHouse/clickhouse-java/issues/3202)

重要变化

  • [client-v2] com.clickhouse.client.api.observability.SpanSupport 现在使用 QUERY 和 INSERT 操作 常量（QUERY <database> 和 INSERT <database>.<table> 范围名称）。 db.operation.name 属性设置为 INSERT 用于插入操作，未设置查询，因为 SQL 语句不在 client 上进行解析。

  • [client-v2] com.clickhouse.client.api.metrics.OperationMetrics 现在有一个构造函数， OperationMetrics(ClientStatisticsHolder, OperationType)；没有操作类型的构造函数被删除。 指标由 client 创建，它始终知道其运行的操作类型，并且构造函数采用 内部类型 (com.clickhouse.client.api.internal.ClientStatisticsHolder)，因此不需要应用程序代码 来调用它。 (https://github.com/ClickHouse/clickhouse-java/issues/2974)

新功能

数据类型

  • [client-v2、jdbc-v2] 添加了对 MultiPoint 地理数据类型 (ClickHouse 26.8+) 的支持。以前的类型 client 不知道，因此读取或写入 MultiPoint 列失败并出现 Unknown data type: MultiPoint， Geometry 列内的 MultiPoint 值因变量鉴别器超出范围而失败。 MultiPoint 是 线上的Array(Point)，与Ring和LineString一模一样，所以通过读写为double[][] 通用记录、二进制读取器、POJO 绑定和 SQL 参数格式化，并从 Dynamic 列读取。在 JDBC 驱动程序 (jdbc-v2) MultiPoint 映射到 java.sql.Types.ARRAY，从 getObject 返回为 double[][] 并作为getArray的java.sql.Array，并由ResultSetMetaData和DatabaseMetaData报道。 ClickHouse 26.8 还在 Geometry 的基础上添加了 MultiPoint 变体；服务器将其附加在现有的六个变体之后，而不是按类型名称排序，因此现在 client 保持该顺序并对 Geometry 列中保存的 MultiPoint 进行解码。因为MultiPoint共享其Java 表示（double[][]）与Ring和LineString，不能通过基于形状的Geometry选择 写入路径 — 2D 值像以前一样继续解析为 Ring，而写入 MultiPoint 需要具体的 MultiPoint 列。 (https://github.com/ClickHouse/clickhouse-java/issues/3048)

  • [client-v2、jdbc-v2] 添加了对 BFloat16 数据类型 (ClickHouse 24.11+) 的支持。 BFloat16 列读作 Java float 值（加宽是无损的）并从 float/Float 值写入，包括通过通用记录、POJO Dynamic/Variant 列中保存的结合、Nullable(BFloat16) 和 BFloat16 值。写入时，client 保留 float的高16位，匹配ClickHouse服务器自己的Float32→BFloat16转换。在 JDBC 驱动程序中 （jdbc-v2）BFloat16映射到java.sql.Types.FLOAT / java.lang.Float，通过标准读写 getFloat/setFloat 和 getObject 访问器，并由 ResultSetMetaData 和 DatabaseMetaData 报告。 之前读过或写过
