clickhouse-java v0.10.0-rc1

小版本 发布时间2026年7月3日 来源ClickHouse/clickhouse-java 英文原文

clickhouse-java v0.10.0-rc1

发布迁移指南

重大变化

  • [jdbc-v2] 驱动程序不再对每个 JDBC 上的服务器设置 async_insert=0 和 wait_end_of_query=0 进行硬编码 连接。这解除了以前不起作用的两种情况：覆盖每个连接或每个连接的这些设置 语句，并针对不允许 SETTINGS 覆盖的只读配置文件使用驱动程序。有两个后果：

    • 驱动程序现在遵循这些设置的服务器端默认值（注意：从 ClickHouse 26.3、async_insert 开始 默认为 1）。删除显式 wait_end_of_query=0 是针对服务器默认值的无操作，但允许用户选择 wait_end_of_query=1。
    • java.sql.Statement.executeUpdate(java.lang.String) 返回的行数（以及匹配的 PreparedStatement 当服务器异步运行 INSERT 语句时，不再保证 INSERT 语句的准确性，并且 INSERT 正文中的解析/数据错误可能不会作为 SQLException 同步显示。以前这些是 准确，因为插入被迫同步（另请参见 https://github.com/ClickHouse/ClickHouse/issues/57768）。 要恢复以前的行为，请将每个连接的 async_insert=0（或 wait_for_async_insert=1）设置为服务器设置。 了解有关异步插入的更多信息：https://clickhouse.com/docs/optimize/asynchronous-inserts.

    (https://github.com/ClickHouse/clickhouse-java/issues/2652, https://github.com/ClickHouse/clickhouse-java/issues/2825)

  • [client-v2] Client.Builder#build() 现在抛出 ClientMisconfigurationException 而不是 IllegalArgumentException 用于身份验证和 SSL 错误配置（缺少凭据、冲突 身份验证方式，启用 SSL 身份验证时缺少 client 证书，与 trust 存储一起使用 具有 client 证书）。在这些情况下依赖从 build() 捕获 IllegalArgumentException 的呼叫者 必须捕获 ClientMisconfigurationException（通过 ClientException 扩展 RuntimeException）。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] 将 setUsername(...) + setPassword(...) 与自定义 Authorization HTTP 标头相结合（ httpHeader(HttpHeaders.AUTHORIZATION, ...)) 现在在 Client.Builder#build() 处失败 ClientMisconfigurationException 除非通过以下方式显式禁用 HTTP 基本身份验证 useHTTPBasicAuth(false)。以前此组合已被接受，并且自定义 Authorization 标头被覆盖 请求时的用户/密码。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] access_token 配置属性（通过 Client.Builder#setAccessToken(String) 或直接设置） 到 setOption）现在实际上作为 Authorization HTTP 标头值逐字应用于传出请求。 以前，该值存储在 access_token 下，但从未通过网络发送，因此单独提供它没有效果 关于认证。调用者必须自行包含方案前缀（例如 setAccessToken("Bearer <token>")），或使用 useBearerTokenAuth(String) 自动添加 Bearer 。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client.Builder#useBearerTokenAuth(String) 现在将不记名令牌存储在 access_token 下 配置密钥（带有 Bearer 前缀），而不是直接将其写入 http_header_authorization。的 HTTP 有线格式不变，但在以下情况下不再可以通过 Client#getReadOnlyConfig() 观察到令牌 http_header_authorization 钥匙。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] 修复了 Client 组件中 executionTimeout 参数使用不一致的问题。超时时间是 以前以毫秒为单位设置，但在某些地方错误地以秒为单位检索和使用。现在它正确使用 毫秒一致。 (https://github.com/ClickHouse/clickhouse-java/issues/2358)

新功能

  • [jdbc-v2、client-v2] 实施了 SSL 模式配置。现在可以将 ssl_mode 设置为 DISABLED， TRUST、VERIFY_CA 和 STRICT。 V1 用户请注意：NONE 仅受 JDBC 驱动程序支持并映射到 TRUST。 请迁移到新的命名。

  • client-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/client-v2/src/main/java/com/clickhouse/examples/client_v2/SSLExamples.java 的示例

    • jdbc-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/jdbc/src/main/java/com/clickhouse/examples/jdbc/SSLExamples.java 示例 (https://github.com/ClickHouse/clickhouse-java/pull/2874, https://github.com/ClickHouse/clickhouse-java/issues/2389, https://github.com/ClickHouse/clickhouse-java/issues/2309, https://github.com/ClickHouse/clickhouse-java/issues/2819）

  • [jdbc-v2、client-v2]（测试版） 为 JSONEachRow 实现独立读取器，为 阅读这种格式。此外，它还提供了一种使用 JDBC 驱动程序将 Json 列映射到自定义类型的方法。查看示例 在 https://github.com/ClickHouse/clickhouse-java/tree/main/examples/jdbc-v2-json-processors 和 https://github.com/ClickHouse/clickhouse-java/tree/main/examples/client-v2-json-processors. 中 (https://github.com/ClickHouse/clickhouse-java/pull/2871)

  • [client-v2] 添加了 Session API 来封装和管理 ClickHouse 会话设置（session_id、 session_check、session_timeout、session_timezone）作为可重复使用的对象。 Session实例可应用于 使用applyTo()进行任何请求设置，并且可以通过clearSession()清除会话状态。此外，还添加了 resetOption(String) 至 InsertSettings、QuerySettings 和 CommonSettings 允许删除特定设置。 明确设置为 null 的设置将不会发送到服务器，因此
