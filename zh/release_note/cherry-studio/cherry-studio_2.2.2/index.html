Cherry Studio 2.2.2 - 代理批准、提供商修复和润色

✨ 新功能

  • [计算机使用] 计算机使用现在默认开启，并在访问每个应用程序之前进行询问。选择始终、批准会话或拒绝，并在“设置”中管理保存的批准。绕过模式会跳过这些提示而不保存权限。 （所需操作：如果您不需要，请在“设置”中将其关闭。）
  • 【技能】在设置→技能中新增“导出技能至外部代理”开关。对于新安装，它默认处于关闭状态，因此如果没有明确的选择加入，则不再创建共享技能目录；已导出的安装将其保持打开状态，关闭它只会删除 Cherry Studio 创建的链接。
  • [代理] DeepSeek 模型上的代理现在在每个工具调用上方显示一条简短的意图线。代理会话默认情况下会扩展工具步骤，并折叠同类的重复调用。
  • [App]添加了波兰语支持。

💄 改进

  • [MCP] QVeris 现在支持 OAuth 浏览器登录作为其主要凭据，并使用 QVERIS_API_KEY 作为可选后备，因此无需 API 密钥即可启用它。
  • [文件] 文件大小在整个应用程序中使用一种一致的格式。
  • [代理] 改进了会话详细信息排版、图标对齐、间距和无工作空间占位符。

🐛 错误修复

  • [模型] CherryIN Claude Sonnet 4.5 工具请求不再因基岩参数验证错误而失败。
  • [模型] AWS Bedrock 上的 Claude Opus 5.5 请求现在使用自适应推理。
  • [型号] SiliconFlow 采用手动 API 按键输入；已删除过时的 OAuth 登录（如果您使用 OAuth 登录，则需要执行操作）。
  • [聊天]“输入超出上下文限制”错误现在被识别为上下文长度拒绝，因此会出现现有的恢复指南。
  • [聊天] 本地 Markdown 文件链接现在可以从不提供工件预览的聊天界面打开。
  • [聊天] 修复了加载时第一个编辑器工具栏激活丢失的问题，并且内部选项卡导航不再阻止交互。
  • [代理] 修复了当流式审批请求在其工具源之前到达时丢失的 AskUserQuestion 卡。
  • [代理] 修复了跳过所有问题时“跳过”按钮卡在最后一个 AskUserQuestion 上的问题。
  • [代理] 扩展 Pi 持久读取工具调用不再显示空白文件详细信息。
  • [代理] Pi Durable 代理现在自动加载工作区指令文件，例如 AGENTS.md。
  • [代理] 普通 MCP 工具可以通过 Pi Durable 运行时中的工具搜索来发现，而不是返回“未找到匹配的工具”。
  • [代理] 代理工具指导现在将延迟工具视为通过发现可用，并使用会话中的确切工具名称，因此代理停止将可用工具报告为丢失。
  • [代理] 当推理耗尽响应预算时，您现在可以获得准确的输出令牌限制指导，并且 DeepSeek V4.1 闪存容量可以正确解析版本化模型 ID。
  • [API Gateway] 对于第三方型号，不再删除 Claude Code MCP ToolSearch 结果。
  • [代码] Code Mate 的统一网关模型选择器现在列出了仅对代理可用的 Cherry Cloud 模型。
  • [Doctor] Doctor不再报告API密钥丢失或CherryAI和Cherry Cloud不可用的型号列表；对于 Cherry Cloud，它现在会告诉您何时需要登录。
  • [UI] 网站图标在深色模式下保持可见，并带有柔和的浅灰色背板，同时保持其原始颜色。
  • [更新程序] 更新对话框中的 Release note 现在遵循应用程序的解析语言，包括当应用程序遵循系统语言时。
