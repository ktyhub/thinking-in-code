skywalking v10.3.0

小版本 发布时间2025年11月10日 来源apache/skywalking 英文原文

skywalking v10.3.0

下载

https://skywalking.apache.org/downloads/

####通知 请勿从此页面下载源代码。 如果您想自行构建源代码，请按照构建文档。

BanyanDB Storage Option 已做好大规模准备

BanyanDB 是一个原生构建的 SkyWalking 数据库，完全专注于 SkyWalking 用例。 BanyanDB 在提高性能和优化资源利用率方面展现出巨大的潜力。在涉及约 200 个服务和每秒 200 多个调用的典型部署场景中，配置有 2 个联络节点和 2 个数据节点（每个节点配备 4 个 vCPU 和 8 GB 内存）的集群可提供稳定高效的性能。 BanyanDB还支持全跟踪采样，提供高达100%的跟踪收集能力，在不影响系统稳定性的情况下保证全面的可观察性。

BanyanDB 中的新跟踪模型

优化了BanyanDB 0.9.0的Trace模型实现，显着降低了OAP和BanyanDB之间的查询频率。 基于最新的查询特性引入了新的查询视图，大大降低了页面延迟。

项目

  • 将 BanyanDB 依赖版本（服务器和 java-client）升级为 0.9.0。
  • 修复 CVE-2025-54057，限制和验证小部件的 url。
  • 修复 MetricsPersistentWorker，从 Hour/Day 维度指标持久化进程中删除 DataCarrier 队列。 这对于降低内存成本和 Hour/Day 维度指标持续延迟非常重要。
  • [重大更改] BanyanDB：支持新的 Trace 模型。

OAP 服务器

  • 通过OAP Server实现BanyanDB的自我监控。
  • BanyanDB：支持hot/warm/cold阶段配置。
  • 修复当策略已在缓存中时查询继续分析策略错误。
  • 支持hot/warm/cold状态API和graphQL API中的阶段TTL查询。
  • PromQL服务：流量查询支持limit和正则表达式匹配。
  • 修复 HashCodeSelector 的边缘情况（Integer#MIN_VALUE 导致 ArrayIndexOutOfBoundsException）。
  • 支持Flink监控。
  • BanyanDB：支持 @ShardingKey 测量标签。
  • BanyanDB：支持metrics/traces/logs的冷阶段数据查询。
  • 将消息队列的空闲检查间隔增加到200ms，以减少低负载情况下的CPU使用率。
  • 将 Istio ServiceEntry 的 DNS 解析最大尝试次数限制为 3，并且不要等待第一个解析结果，以防 DNS 根本无法解析。
  • 支持分析 Envoy ALS 接收器中的航路点指标。
  • 在拓扑中添加Ztunnel组件。
  • [中断更改] 将 K8SServiceRelation 范围中的 componentId 更改为 componentIds。
  • 如果在 eBPF 访问日志接收器中检测到环境网格，则调整网格指标。
  • 添加对 /debugging/config/dump 状态 API 的 JSON 格式支持。
  • 增强状态 API 以支持多个 accept 标头值，例如Accept: application/json; charset=utf-8。
  • 存储：单独的SpanAttachedEventRecord用于SkyWalking轨迹和Zipkin轨迹。
  • [重大更改]BanyanDB：设置新的组策略。
  • 将 commons-beanutils 升级为 1.11.0。
  • 重构：简化Accept http header 流程​​。
  • [中断更改]存储：将 event 从指标移至记录。
  • 删除 ElasticSearch client 的 Jackson 解串器中的字符串限制。
  • 修复 disable.oal 不起作用的问题。
  • 增强e2e PHP测试的稳定性并更新PHP代理版本。
  • 添加 dameng JDBC 驱动程序的组件 ID。
  • BanyanDB：支持在文件bydb-topn.yml中自定义TopN pre-aggregation规则配置。
  • 重构：使用 SPI 实现 OTEL 处理程序以实现可扩展性。
  • 杂务：为 StorageID 添加 toString 实现。
  • 杂务：添加连接 ES 时间过长时的警告日志。
  • 修复元数据API中的查询时间范围。
  • OAP gRPC-Client 支持 Health Check。
  • [中断更改] health_check_xx 指标使响应 1 代表健康，0 代表不健康。
  • 将 grpc 提升至 1.70.0。
  • BanyanDB：支持新的索引规则类型SKIPPING/TREE，并将记录log的trace_id索引类型更新为SKIPPING
  • BanyanDB：从标签设置中删除index-only。
  • 修复 ES 存储中分析跟踪分析跨度失败的问题。
  • 添加 Ruby 运行时指标的 UI 仪表板。
  • 跟踪查询执行 HTTP APIs：使参数 service layer 可选。
  • GraphQL API：元数据、拓扑、日志和跟踪支持按名称查询。
  • [中断更改] MQE 函数 sort_values 根据聚合结果和标签而不是简单的时间序列值进行排序。
  • 自我观察：为 OAP 服务器添加 metrics_aggregation_queue_used_percentage 和 metrics_persistent_collection_cached_size 指标。
  • 优化指标聚合/持久工作人员：分离 OAL 和 MAL 工作人员和消费池。数据流信号驱动新的 MAL 消费者， 下表显示了每个工作线程的池大小、驱动模式和队列大小。
工人 池大小 信号驱动模式 队列通道大小 队列缓冲区大小
指标聚合OALWorker Math.ceil(可用处理器 * 2 * 1.5) 假 2 10000
指标聚合MALWorker 可用处理器 * 2 / 8, 至少 1 真实 1 1000
指标PersistantMinOALWorker 可用处理器 * 2 / 8, 至少 1 假 1 2000
