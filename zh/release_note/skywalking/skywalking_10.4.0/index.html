skywalking v10.4.0

项目

  • 引入OAL V2引擎：
    • 用于线程安全和可预测行为的不可变 AST 模型
    • 类型安全枚举取代基于字符串的过滤运算符
    • 精确的错误位置报告，包括文件号、行号和列号
    • 解析和代码生成阶段之间的清晰分离
    • 无需解析即可构建模型，增强了可测试性
  • 引入 MAL/LAL/Hierarchy V2 引擎 — 用 ANTLR4 解析器 + Javassist 字节码生成替换基于 Groovy 的 DSL 运行时：
    • 从 OAP 后端删除 Groovy 运行时依赖
    • 启动时快速失败编译 - 立即捕获语法和类型错误，而不是在第一次执行时捕获
    • 线程安全生成的类，没有 ThreadLocal 或共享可变状态
    • 适用于所有三个 DSL 的不可变 AST 模型（MAL、LAL、层次结构规则）
    • 显式上下文传递取代了 Groovy 绑定/闭包捕获
    • v1 (Groovy) 和 v2 (ANTLR4+Javassist) 跨版本检查器可验证 1,290 多个表达式的行为等效性
    • JMH 基准测试确认 v2 运行时加速：MAL 执行 ~6.8 倍，LAL 编译 ~39 倍/执行 ~2.8 倍，Hierarchy 执行比 Groovy v1 快 ~2.6 倍
    • 生成的类名遵循所有 DSL（MAL/LAL/Hierarchy）的 {yamlFileName}_L{lineNo}_{ruleName} 模式，以实现堆栈跟踪可追溯性
  • 重大更改 — LAL：从语法中删除 slowSql {} 和 sampledTrace {} 子 DSL。这些被可配置的 outputType 机制取代：
    • 在YAML配置中的规则级别设置outputType以指定输出实体类。使用 LALOutputBuilder SPI 注册的短名称（例如，outputType: SlowSQL、outputType: SampledTrace）或完全限定的类名称作为后备。
    • LALOutputBuilder 实现是通过 ServiceLoader 发现的，并公开 name() 方法以进行短名称解析。内置型号：SlowSQL（DatabaseSlowStatementBuilder）、SampledTrace（SampledTraceBuilder）。
    • 输出字段（例如，id、statement、latency）现在是提取器块中的常规字段分配，不再包装在子 DSL 块中。
    • 自定义输出字段在编译时根据输出类型的设置器进行验证。
    • 现在需要显式的 sink {} 块才能持久保存数据。如果没有 sink {}，则不会保存任何数据 - 这适用于所有 LAL 规则，包括使用 outputType 的规则。在 v1 中，slowSql {} 和 sampledTrace {} 将数据作为提取器内部的副作用进行调度；在 v2 中，持久性始终由接收器管道处理。
    • 输出类型解析顺序：每规则 YAML outputType（通过 SPI 或 FQCN 的短名称）> LALSourceTypeProvider SPI 默认 > Log.class。
    • 所有捆绑的 LAL 脚本（mysql-slowsql.yaml、pgsql-slowsql.yaml、redis-slowsql.yaml、envoy-als.yaml、k8s-service.yaml、mesh-dp.yaml）均已更新。
    • 具有使用 slowSql {} 或 sampledTrace {} 的自定义 LAL 脚本的用户必须迁移到新语法。请参阅 LAL 文档。
    • 将 ExtractorSpec 重命名为 MetricExtractor — 现在仅处理 LAL metrics {} 块。标准字段设置器（服务、层、时间戳等）被编译为输出构建器上的直接设置器调用。
  • 在 LAL 提取器（和过滤器级别）中添加 def 局部变量支持。支持 toJson() 和 toJsonArray() 内置函数，用于将字符串、Maps 和 protobuf Struct 转换为 Gson JSON 对象。变量支持 null 安全导航 (?.)、具有编译时类型推断的方法链接以及通过 as 的显式类型转换（内置类型或完全限定的类名，例如 def resp = parsed?.response as io.envoyproxy.envoy.data.accesslog.v3.HTTPResponseProperties）。
    • 重大变更 — LALOutputBuilder.init() 签名从 init(LogData, NamingControl) 更改为 init(LogData, Optional<Object> extraLog, NamingControl)。 extraLog 参数携带类型化输入对象（例如，HTTPAccessLogEntry 用于特使访问日志），以便输出构建器可以访问特定于协议的字段。自定义 LALOutputBuilder 实现必须更新其 init() 方法签名。

  • 修复E2E测试指标验证：如果指标值为空则验证失败。

  • 支持使用 Java 25 构建、测试和发布。

  • 添加CLAUDE.md作为项目的AI助手引导。

  • 将 Byte Buddy 升级到 1.18.7 并在 Surefire 中为 Mockito/Byte Buddy 配置显式 -javaagent，以避免 JDK 25 动态代理加载警告。

  • 在 OAP 后端将 Groovy 升级到 5.0.3。

  • 将nodejs升级到v24.13.0以进行最新的UI(booster-ui)编译。

  • 从 E2E 测试中删除 Elasticsearch 7.x (EOL) 和 OpenSearch 1.x，将所有 ES 测试升级到 8.18.8，并更新 skywalking-helm 以使用 ECK 8.18.8。

  • 添加 library-batch-queue 模块 - 一个分区的、自排空的队列，具有基于类型的调度， 自适应分区、空闲退避和吞吐量加权消耗重新平衡 (DrainBalancer)。 旨在替代高扇出场景中的 DataCarrier。

  • 将 DataCarrier 替换为 BatchQueue，用于 L1 指标聚合、L2 指标持久化、TopN 持久化， 所有三个导出器（gRPC 指标、Kafka 跟踪、Kafka 日志）和 gRPC 远程 client。 所有指标类型（OAL + MAL）现在共享统一队列，而不是单独的 OAL/MAL 池。 每个导出器都保留自己的专用队列（1 个线程），保留原始缓冲区策略。 8 核机器上的线程数比较（排除 gRPC 远程 client — 每个对等点 1 个线程不变）：

    |队列|旧线程 |旧频道|旧的缓冲槽 |新话题 |新分区|新的缓冲槽 |新政策| |--------|-------------|--------------|------------------|-------------|----
