OTLP 跟踪的指标和拓扑

使用 OpenTelemetry SDK 进行检测的应用程序不再需要 SkyWalking 代理来进行服务仪表板、拓扑和跟踪搜索。 OAP 在 OTLP 跟踪到达时对其进行存储，新的跟踪分析语言 (TAL) 将每个跨度转换为服务、实例和端点指标、拓扑以及服务调用的数据库、缓存和消息队列的仪表板。阅读 OpenTelemetry SkyWalking 中的轨迹，了解 OpenTelemetry 天文商店的单命令快速入门。

项目

  • 将 e2e 模拟发送方的 OTLP 原型更新为 v1.11.1。当前的 OpenTelemetry 收集器添加了旧副本缺少的字段，例如度量的 metadata，并且发送者严格的 JSON 解析器拒绝携带它们的记录。 Windows e2e 现在还可以重播在 GitHub 托管的 Windows 运行器上通过 OpenTelemetry Collector 0.158.0 进行的 windows_exporter 0.31.8 的记录，并断言其内存指标。
  • 将 GenAI e2e 案例的 Spring AI 应用程序替换为固定到已发布的 Spring AI 2.0.1 的内部 e2e-spring-ai-service 模块，并将模拟 LLM 端点从 e2e-service-provider 移至所有三个 GenAI 案例共享的专用 e2e-mock-llm-server 模块中。 Spring AI 应用程序之前是在测试时通过克隆 spring-projects/spring-ai-examples 并在映像构建中运行 Maven 来构建的，这解决了 spring-ai:2.0.0-SNAPSHOT：一条已被废弃的线路，其幸存的构建都比 2.0.0 GA 早一天，并且其较旧的构建已被修剪，因此该固定装置被固定到没有发布的内容，并且无法再从相同的字节重建。这两个模块都是由现有的 e2e Reactor 构建的，并与其他 e2e 服务镜像一起发布到 ghcr.io/apache/skywalking； e2e-spring-ai-service 需要 Java 17 和 Spring Boot 4，因此它被控制在 e2e 反应器中新的 jdk-17 配置文件后面，并且构建它的作业现在明确固定 JDK 17； make -C test docker 在较旧的 JDK 上预先拒绝，而不是打包丢失或陈旧的 jar，因为 clean 永远不会到达配置文件排除的模块，并且 compose 会将不存在的 jar 转换为目录。
  • 对于 receiver-proto 中的 Envoy 原型文件 SkyWalking 捆绑包，将 Envoy 项目的 NOTICE 添加到 NOTICE 和二进制发行版的 NOTICE 中。
  • BanyanDB CA 轮换以操作员的方式进行轮换：一旦拓扑显示消费者对提供者的调用，OAP trust 旧的和新的 CA，BanyanDB 重新加载新 CA 签名的证书，然后 OAP 只在存储断言运行之前 trust 新的 CA。每个步骤写入一次文件，并且 OAP 的 trust 文件被重命名到位，因此文件监视器永远不会读取半写入的文件。旋转到不相关的 CA（证明重建通道使用 trust 文件）移至末尾。它过去首先运行，当写入失败时，其中包括网络地址别名的第一次写入，该别名将保留在存储之外，直到五分钟后下一次刷新，因此拓扑断言超时。
  • BanyanDB 凭证轮换 e2e 等待拓扑显示消费者对提供者的调用，然后再轮换，就像 CA 轮换 e2e 所做的那样。它应用的不完整凭据导致该窗口中的写入失败，并且当它们包含网络地址别名的第一次写入时，该别名将保留在存储之外，直到五分钟后进行下一次刷新，因此拓扑断言超时。
  • BanyanDB 凭证和 CA 轮换 e2e 案例现在也证明写入是在轮换后完成的。他们的拓扑断言使用默认范围（最近 30 分钟），轮换之前写入的行也满足该范围，因此他们只显示查询在轮换的凭据或通道上工作。现在，每个案例都会保留其上次轮换生效的时间，并断言仅从其之后的几分钟绘制提供者拓扑。
  • 清除 e2e 测试装置中的 Dependabot CVE 警报，没有 OAP 工件附带。 Go 夹具（cases/go/service 和 cases/profiling/ebpf/network）移动到 google.golang.org/grpc 1.79.3 → 1.83.2、golang.org/x/crypto 0.51.0 → 0.55.0 和 github.com/klauspost/compress 1.15.9 → 1.18.7，Java 测试服务移动到 guava 32.0.0-jre → 33.7.2-jre 和log4j 2.25.4 → 2.25.5。

OAP 服务器

  • 为 AI 评估添加可定制的 LLM 作为法官支持，具有 OpenAI 兼容的端点/模型/API 密钥配置，并将评估结果保留为可查询的 GenAIEvaluationRecord 行以供以后检查。
  • 支持从 bydb.yml (SW_STORAGE_BANYANDB_SECRETS_MANAGEMENT_FILE) 中的新 secretsManagementFile 设置热重载 BanyanDB 凭证，匹配 ElasticSearch 存储插件。监视携带 user/password 的属性文件，因此应用由 Vault 等第 3 方工具执行的旋转，而无需重新启动 OAP。 gRPC 身份验证拦截器按 RPC 读取凭证，因此无需重新建立通道，也无需中断正在进行的查询或写入，即可交换凭证。文件包含的任何内容都会被应用，包括不完整的对，因此其中的错误会明显失败，而不是被默默地继续工作的凭据所掩盖；用户名和密码只能一起发送，所以
