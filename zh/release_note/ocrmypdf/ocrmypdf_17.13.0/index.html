OCRmyPDF v17.13.0

小版本 发布时间2026年9月28日 来源ocrmypdf/OCRmyPDF 英文原文

OCRmyPDF v17.13.0

变化

  • 不使用 Ghostscript（“推测”转换）制作的 PDF/A 现已得到验证 使用 pikepdf 的 PDF/A 支持 (pikepdf.pdfa) 而不是 veraPDF，并且 在元数据和优化步骤之后再次验证最终输出。 veraPDF 不再使用，因此可以使用无 Ghostscript 的路径 是否安装 veraPDF，包括在 Docker 映像中。文件 验证者不会像以前一样批准转到 Ghostscript；使用 -v1 运行 看看为什么。
  • 推测转换现在支持 PDF/A-1b，并修复了常见问题 以前总是将文件发送到 Ghostscript：它替换其他输出 sRGB 的意图，删除图像插值标志，设置打印标志 注释，添加 /CIDSet PDF/A-1 要求，并删除 XMP 属性 以及 PDF/A 不允许的隐藏注释。
  • 新选项 --pdfa-backend {auto,ghostscript,internal} (API: pdfa_backend=）。默认auto，尝试OCRmyPDF自带的转换 然后是幽灵脚本。 internal 从不使用 Ghostscript，因此 JPEG 会通过 不变；如果结果未获批准，则 pdfa 输出类型失败并显示 退出代码 10 和 --output-type auto 输出常规 PDF。 ghostscript 总是使用 Ghostscript。仅 Ghostscript 实现的选项 （--pdfa-image-compression、--ghostscript-jpeg-quality、 --ghostscript-jpeg-maxdpi 和 --color-conversion-strategy CMYK， Gray 或 UseDeviceIndependentColor) 现在选择 auto 下的 Ghostscript 并且是 internal 的错误。
  • OCRmyPDF 现在需要 pikepdf[pdfa] 10.15 或更高版本。 pdfa 额外 引进jsonschema、referencing和fonttools，全部由 Debian 和红帽。
  • --force-ocr 现在保留超链接，将链接注释移动到 光栅化页面； --deskew 和 --clean-final 也是如此。新模式 --mode force-ocr-no-links 保持旧的行为。 {issue}605
  • 当 Ghostscript 替换未嵌入的字体时，它现在总是使用 它自己的字体（-dNONATIVEFONTMAP），所以每个输出都是相同的 平台；在 macOS 上，本机字体查找可以嵌入数十兆字节 系统字体。当使用标准 14 以外的字体时，OCRmyPDF 会发出警告 被替换，或者当替换失去粗体或斜体样式时。 {issue}1369
  • 没有时区的创建日期现在被视为当地时间，并且 输出的日期获取该区域，并带有警告。设置TZ选择另一个 区。
  • 在默认模式下，已有文本的页面现在会停止 OCRmyPDF 直接在初始扫描之后，而不是在对之前的页面进行 OCR 后 它。该错误命名页面。 {issue}613
  • 输出文件的检查要快得多：每个流都在 最便宜的压缩方式而不是完全解码，并且 显示进度条。现在也检查 JPEG 2000 和 CCITT 图像，但是 不再检测已损坏但未被截断的 JPEG。 {issue}1570
  • OCRmyPDF 现在附带 PyInstaller 挂钩，因此可以捆绑使用它的应用程序 没有额外的选项。 Tesseract 和 Ghostscript 仍必须安装。 {issue}1024
  • 新的 PageInfo.has_visible_text，排除了不可见的文本，例如 OCR 层。 has_text 不变。

修复

  • --force-ocr 在已经有不可见 OCR 图层光栅化的扫描上 它的分辨率不低于 400 dpi，就好像文本是可见的一样，这可以 乘以文件大小。 {issue}961
  • 进程工作人员（Windows 和 macOS 上的 use_threads=False）在每个 页面为 'OcrOptions' object has no attribute 'tesseract'。 {issue}1757
  • ocrmypdf.ocr() 拒绝阈值方法名称，例如 tesseract_thresholding='adaptive-otsu'。 {issue}1460
  • --rotate-pages --tesseract-timeout 0 检测到页面方向但未检测到 旋转页面。食谱现在推荐这种旋转组合 或不使用 OCR 进行歪斜校正。 {issue}778
  • 对于 --output-type auto 和 --force-ocr，输出标记为 PDF/A 当 veraPDF 被验证或没有给出 PDF/A 声明时 未安装，如 Docker 映像中所示。 {issue}1751
  • Ghostscript 的 PDF/A 转换删除了大多数超链接（那些没有 打印标志）。 PDF/A 不允许的隐藏注释现在已 在 Ghostscript 运行之前删除，并带有与推测相同的警告 转变，而不是默默地。 {issue}605
  • 没有 /ToUnicode 字体的文本，查看者通过字形提取 Ghostscript 制作 PDF/A 时出现乱码或丢失。 {issue}1297
  • 没有等效文档信息的 XMP 元数据，例如 dc:contributor 和 dc:subject，在 Ghostscript 制作 PDF/A 时丢失了。现在是 复制其全部价值，包括多语言的每种语言 财产。 {issue}1220
  • 来自 iText 和 pdftk 的 PDF 中的图像在没有 Flate 的情况下被重新压缩 预测器，产量增加约 30%。 {issue}1620
  • 从垂直日语和其他垂直或旋转 OCR 行复制文本 有虚假空格和乱序字符。 {issue}1244
  • 以无字形后备字体设置的文本，在未安装字体时使用 覆盖脚本（例如 CJK），在选择或复制时丢失字符 Chrome 和其他基于 pdfium 的查看器。
  • 由不同分辨率的整页图像组成的页面被光栅化为 加权平均分辨率而不是最高分辨率。 {issue}948
  • 没有为 Tesseract 的语言代码设置文档语言 (/Lang) 如deu、fra和ces。没有两个字母代码的语言现在得到 他们的三字母代码。 {issue}1749
  • 一些 LaTeX PDF 在内容流中包含格式错误的数字，例如 0.000-50131235，停止 OCRmyPDF。现在它会警告并继续，因为观众 做。 {issue}1054
  • 存储为实数的 /Rotate，或带有非数字的 cm 运算符 操作数，导致页面扫描崩溃。
  • --force-ocr --ocr-engine none 在没有图像的页面上崩溃。
  • 当 OCRmyPDF 自己的 PDF/A 未能通过最终检查时
