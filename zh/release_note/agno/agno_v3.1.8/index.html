agno v3.1.8

#Changelog

新功能

  • Postgres 沙箱检查点存储：添加了 PostgresCheckpointStore，用于将沙箱检查点直接存储在 PostgreSQL 中，允许多副本部署在没有 S3 或共享文件系统的情况下恢复会话。检查点被分块、以事务方式写入、通过 SHA-256 进行重复数据删除并在读取时进行验证。它是选择加入的；现有检查点默认值不变。 (#11186)
  • 框架经理作为例程执行者：公司例程现在可以通过声明、例程 API 和人工聊天配置使用内部产品经理或操作系统经理作为执行者。保留的管理器 ID 只能从所属的 AgentOS 解析，不能被保存的或用户定义的组件替换。包括可选的每周产品经理审核。 (#11193)
  • 沙箱检查点保留：沙箱现在默认保留每个会话的三个最新检查点。配置 retain_checkpoints=None 以保留每个检查点。安全存储运行结果后，未发布或被取代的检查点将被停用并删除。 (#11187)

改进

  • 沙盒会话清理：删除沙盒支持的会话现在会在数据库事务提交后删除其热计算机和关联的检查点对象。支持单个、批量和用户范围的会话删除，而不影响调用者不拥有的会话。 (#11187)
  • 操作系统管理器专家可见性：平台构建器和平台管理器现在在 /teams 和 /teams/os-manager-internal 中显示为操作系统管理器的成员。它们仍然被排除在可重用应用程序注册表、顶级代理发现和独立代理路由之外。 (#11198)
  • Claude 默认为 Sonnet 5.5：Claude() 现在默认为 claude-sonnet-5-5，取代了已弃用的 claude-sonnet-4-5-20250929。对于拒绝这些采样参数的新 Claude 模型，非默认 temperature、top_p 和 top_k 值将被删除，并发出警告。此行为适用于 Anthropic、Bedrock、Foundry 和 Vertex 提供商。 (#11212)

行为改变

  • 检查点保留：默认情况下仅保留三个最新的沙盒检查点。现在，为较早的运行打开检查点可以提高 CheckpointObjectNotFound。设置 retain_checkpoints=None 以恢复之前的无限保留行为。 (#11187)
  • 持久沙箱启动验证：当持久队列沙箱使用主机本地默认检查点存储时，AgentOS 现在会在启动时失败。配置由每个副本共享的检查点存储，例如 PostgresCheckpointStore 或 S3CheckpointStore。以前，此无效配置仅在第一次提交时失败。 (#11187)

错误修复

  • 缺少沙盒检查点：存储中缺少已提交的检查点，现在会以明显的、不可重试的错误结束回合，停用新创建的计算机并释放会话。之前，运行仍然是 RUNNING，耗尽队列重试并阻止稍后打开会话。 (#11187)
  • 公司例程执行：拒绝状态写入和失败的 Studio 运行器委托现在正确地使例程失败。过时的归档目录条目不再与拥有的保留管理器发生冲突。 (#11193)

  • 修复：在 https://github.com/agno-agi/agno/pull/11198 中@ashpreetbedi 在操作系统管理器下显示平台专家
  • 壮举：为 https://github.com/agno-agi/agno/pull/11186 中的 @ysolanky 在 Postgres 中添加用于沙盒检查点的 PostgresCheckpointStore
  • 壮举：支持框架管理者作为公司例程执行者，@ashpreetbedi 在 https://github.com/agno-agi/agno/pull/11193 中
  • 修复：在 sonnet-4-5 退休之前，@kausmeows 在 https://github.com/agno-agi/agno/pull/11212 中将克劳德默认为 sonnet-5-5
  • 修复：https://github.com/agno-agi/agno/pull/10824 中 @23821 默认 OpenAITools 图像生成为 gpt-image-2
