agno v3.2.0

总结

Agno v3.2 通过直接工具使超级代理更快、更有能力，扩展公司任务治理和协调，引入数据库支持的 AgentOS 主页指标，将 A2A 升级到 v1.0 协议，更新 Slack 界面以使用 Bolt SDK 并使外部代理成为一流的存储组件。

Changelog

重大变更

  • OS Manager 默认值和验证： OSManager.tool_call_limit 现在默认为 24（原为 8），num_history_runs 默认为 5（原为 7）。当 OSManager(root=...) 与名为 read_file、list_files 或 search_content 的自定义工具结合使用时，AgentOS 拒绝启动。
  • A2A v1.0： AgentOS 和 A2AClient 现在运行在官方 a2a-sdk 1.x 上，因此请一起升级 Agno 服务器和 client。 (#10956)
    • 删除/v1/message:*和/v1/tasks:*航线；请改用每个实体的 A2A 端点。
    • 流事件和响应工件遵循 v1.0 形状。
    • a2a extra 现在需要 a2a-sdk[http-server]>=1.2.2,<2。
    • 直接导入已删除的 A2A 助手需要更新。
    • 默认情况下，标准 v0.3 clients 仍通过兼容线工作。
  • Slack 界面： 该界面现在在 Slack Bolt 上运行，只有开始运行的人才能批准或拒绝它，除非他们在 approvers= 中命名或映射到与 users= 相同的用户。 (#11599)
    • slack extra 现在需要 slack_bolt>=1.29.0,<2 和 slack_sdk>=3.43.0,<4；运行pip install -U "agno[slack]"。
    • 列出批准 approvers= 运行的其他人。
    • 当 Slack 在 AgentOS(authorization=...) 下提供 agent_os.manager 或没有 users= 的授权中间件时，AgentOS 拒绝启动。
    • 直接导入已删除的内部 Slack 助手（SlackEventHandler、HITLHandler、verify_slack_signature）需要更新。

新功能

  • 超级代理： 超级代理现在自行完成工作，而不是通过经理成员路由请求。 Platform Builder 是其唯一的成员。 (#11572)
    • 列出并运行代理、团队和工作流程，并读取平台活动和时间表。
    • 使用公司、文档、源文件和自定义操作系统管理器工具，并读取当前聊天历史记录。
    • 它的上下文包括可访问的组件，并且每个工具都有自己的权限检查。
  • 公司操作系统： 例程有一个专用的运行程序，任务具有更丰富的状态，并且发布的 Studio 组件可以执行工作。
    • **例程迷你代理：**例程在受限制的非聊天迷你代理上运行，具有公司工具和打包的例程技能，但没有平台或通用运行工具。它对代理发现、MCP 和 A2A 隐藏，并拒绝非常规运行。 (#11572)
    • 任务协调： 任务公开 last_run 和 API 计算的 allowed_transitions，支持直接启动，并记录持久尝试状态。超级代理可以在持久队列上启动已接受的任务，而不会阻塞会话；人类的接受和审查没有改变。 （[#11430]（https://github.com/agno-agi/agno/pull/11430），[#11562]（https://github.com/agno-agi/agno/pull/11562））
    • **公司详细信息：**通过 /company/details 或通过聊天在配置中设置公司名称和描述，并在替换现有详细信息之前进行确认。超级代理每次运行都会获得新鲜的公司背景以及简明的协调指导。 (#11502、#11569、#11563)
  • Studio 组件作为执行者： 已发布的 Studio 代理、团队和工作流程可以执行公司任务和例程。草稿不能，并且正常的执行者安全检查仍然适用。 (#11443)
  • AgentOS 主页指标： 通过 /os/metrics/* 新组件、聚合和刷新表返回每日会话、运行、令牌、用户、模型、成本、持续时间、首次令牌时间和模型延迟。刷新在所有受支持的数据库的后台运行，仅重建更改的日期，支持 ETag，并跨多个本地或远程数据库进行聚合。 (#10874)
  • 存储的外部代理组件： ClaudeAgent 和 CodexAgent 可以通过组件 API 进行保存、加载、版本控制、列出和运行。沙箱和输出架构引用通过注册表进行解析，不受支持或不可序列化的设置会显式失败，而不是被静默删除。 (#11268)
  • A2A存储任务和生命周期： A2A任务存储在数据库中，支持发送、流式传输、获取、取消、列表和订阅。为外部代理提供服务，HITL 和外部工具可以暂停和继续，代理卡同时宣传 v1.0 和 v0.3 接口。 (#10956)
  • 会话运行分页： GET /sessions/{session_id}/runs 支持通过 limit、before_run_index 和 after_run_index 选择加入光标分页。页面将顶级运行与其嵌套成员和步骤运行保持在一起，并且没有 limit 的调用仍返回裸列表。 (#8456)
  • Slack 界面： Slack 现在支持代理视图、停止、外部代理和超级代理结果。助理视图应用程序继续工作。 (#11599)
    • 代理视图： 发送的清单会打开 Slack 的代理视图，并在“消息”选项卡上显示建议的提示以及从第一条直接消息中设置的线程标题。
    • **流式传输：**带有任务卡和状态行的回复流，长回复或超过九分钟的回复将在新消息中继续而不是被剪切。
    • 停止： 按停止
