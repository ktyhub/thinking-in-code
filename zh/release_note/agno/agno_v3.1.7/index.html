agno v3.1.7

#Changelog

改进：

  • 操作系统管理器工具限制：OSManager 采用 tool_call_limit（默认 8，每个协调器运行，包括委派）和 member_tool_call_limit（默认 24，每个专家调用）。解释仅限于问题范围并以 Agno 文档为基础。将任一限制设置为 None 以恢复无限制的工具使用，如以前一样。请参阅食谱。
  • Cartesia 默认模型：CartesiaTools 现在默认为 sonic-3.6。 Cartesia 于 2026 年 10 月 20 日停用 sonic-2 快照（之前的默认快照）。

错误修复：

  • 公司例程：编辑产品的 metadata 不再取消其例程的链接。 SchedulerTools 和 Studio 无法再删除、启用、禁用或重写公司管理的计划。操作系统经理将例程和产品工作发送给产品经理。在用户隔离下，没有所有者的例程会再次运行，并且仅刷新调用者已完成的工作的档案。
  • Postgres 指标：calculate_metrics() 的工作超出了驱动程序的查询参数限制（asyncpg 上有 32,765 个会话，psycopg 上有 65,533 个会话）。在 AsyncPostgresDb 上，刷新失败现在会返回错误，而不是带有空指标的 200。
  • Postgres 上的 v3 迁移：会话到运行迁移通过服务器端游标流式传输行。内存受一批限制，因此大型 sessions 表不再耗尽内存。
  • 使用 Virtualenv 的沙箱检查点：包含 Python virtualenv 的工作区不再无法在其绝对解释器链接上捕获检查点。由于工作区文件而失败的检查点现在会以不可重试的错误结束运行并释放之前停留在 finalizing 中的会话。
  • S3 检查点取消：取消 S3CheckpointStore.aopen_archive 不再使下载的副本处于暂存状态，并且缓存对象摘要检查在事件循环之外运行。

发生了什么变化

  • 修复：将Cartesia默认的TTS模型移至https://github.com/agno-agi/agno/pull/10750中的Sonic 3.6 by @jianjian248
  • 修复：在 Postgres 上流式传输 v3 会话到运行的迁移，而不是通过 https://github.com/agno-agi/agno/pull/11183 中的 @Himanshu040604 将其全部加载到内存中
  • 修复：检查点 virtualenv 链接和发布会话，其文件无法由 https://github.com/agno-agi/agno/pull/11191 中的 @ysolanky 检查点
  • 修复：https://github.com/agno-agi/agno/pull/11175 中 @ashpreetbedi 的绑定 OS Manager 工具使用和地面解释
  • 修复：通过 https://github.com/agno-agi/agno/pull/11182 中的 @sannya-singal 计算超出驱动程序查询参数限制的 Postgres 指标
  • 修复：当 @ysolanky 在 https://github.com/agno-agi/agno/pull/11194 中取消异步打开时，删除 S3 检查点副本
  • 修复：在 https://github.com/agno-agi/agno/pull/11184 中保持 @ysolanky 一致地链接、路由和拥有公司例程
  • 杂务：通过 @kausmeows 在 https://github.com/agno-agi/agno/pull/11174 中发布 v3.1.7
