agno v3.1.11

#Changelog

新功能：

  • 在团队和工作流程中利用代理：ClaudeAgent 和 CodexAgent 现在可以是 Agno Team 的成员和 Workflow 的步骤，包括内部 Parallel、Loop、Condition 和 Router。团队负责人像任何其他成员一样将 delegate_task_to_member 委托给他们，每个工具都使用自己的模型、工具和工作区运行，在同一会话的轮流中保持自己的对话，并且团队或工作流程照常收集其运行。具有 sandbox= 的线束代理在其自己的容器中作为成员或步骤运行每个回合，AgentOS 在团队页面上列出线束成员。请参见 cookbook/frameworks/harness_teams/ 和 cookbook/frameworks/harness_workflows/。
  • 会话搜索：在会话名称、会话/用户/组件 ID、会话类型和创建/更新的时间戳上添加了带有嵌套 AND/OR/NOT 过滤器的 GET /sessions/filter-schema 和 POST /sessions/search，与跟踪 API 匹配。在 PostgreSQL 和 SQLite 中，谓词在计数和分页之前应用，并为其他适配器提供批量回退。包括同步和异步 client 方法。
  • 公司任务：POST /company/tasks 接受 status，因此可以在待办事项、就绪或取消中创建任务。任务可以在任何阶段之间移动，已完成和取消的任务可以重新打开，并且可以在任何阶段编辑标题和简介。进行中仍然仅从运行开始，并且在该运行正在执行或暂停时退出它会被拒绝。
  • 公司例程：添加了 POST /company/routines/{id}/cancel、/archive、/restore 和仅限管理员的 DELETE /company/routines/{id}。 GET /company/routines采用sort_by和sort_order。按需暂停和恢复 例程返回 409，并且调度程序运行不再移动 updated_at。

改进：

  • Cookbooks：为 AgentOS UI 添加了客户反馈工作流程，公司经理在其中读取 Markdown 反馈，提出有证据支持的项目和积压任务，并将接受留给人工。
  • 自述文件：将自述文件与文档介绍和自我改进代理平台定位保持一致。

错误修复：

  • ReaderFactory：create_reader() 现在返回一个配置有每次调用选项的新读取器，而不是缓存的单例，因此 chunk_size 和其他覆盖受到尊重，并且突变不再在 Knowledge 实例之间泄漏。
  • 工作流程步骤内容：StepOutput.to_dict() 将整数、浮点数、布尔值和字符串保留为本身，而不是对它们进行字符串化，因此返回 0 或 False 的步骤在 HITL 恢复、会话重新加载或通过 AgentOS 工作流程 API 后不再返回为 "0" 或 "False"。
  • HuggingFace：default_headers 映射到 SDK 的 headers，store 在 extra_body 中发送，并且 max_retries 和 default_query 已弃用和忽略，而不是提高 TypeError。没有工具的代理不再发送 tools=[]，这使得非流式运行返回 None 内容。
  • Google 日历：find_available_slots 现在在经过身份验证的用户的时区而不是 UTC 中工作，因此工作时间和仅日期输入意味着用户的当地时间。它还获取完整扫描窗口的事件，因此范围最后一天的繁忙时间不再免费提供。
  • 公司存档：存档任务不再阻止存档其项目或产品。可见的活动任务仍然像以前一样阻塞。
  • RedisDb：keyword_search 现在将调用者的 limit 传递给 redisvl，而不是默默返回默认的 10 个结果。
  • MMRReranker：当 limit 为零或负数时，rerank 和 arerank 不返回任何文档，而不是始终返回最接近的匹配项。
  • FieldLabeledCSVReader：page_size=0 与负值一起被拒绝，而不是在较大文件上默默地不返回任何文档。
  • AgentOSClient：从 continue_agent_run 中删除了记录但不存在的 stream 参数。使用continue_agent_run_stream进行流式传输。
