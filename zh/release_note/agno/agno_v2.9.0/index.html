agno v2.9.0

#Changelog

新功能

  • StudioRunnerTools：新的身份感知调度工具包 (agno.tools.studio_runner.StudioRunnerTools)，可将执行从 StudioTools 中分离出来。任何组件（团队领导、路由器）都可以安装它来发现和运行 Studio 构建的代理/团队/工作流程，而无需获取 Studio 的创建/编辑/删除界面。 run_* 工具将调用者的 user_id 线程连接到子运行中，以便每用户状态落在正确的人身上。
  • list_components 名称过滤器：为 list_components 添加了 name 过滤器。

错误修复

  • A2A：修复了 A2A 流 client 通过中断状态更新而丢弃任务级元数据。
  • 工作流程 (WebSocket)：通过 WebSocket 遵循选定的工作流程版本。
  • 团队 HITL：保持暂停的成员运行，以便团队 HITL 恢复能够在会话重新加载后继续存在。
  • 补液：保留有关补液的工具包说明。
  • 框架注释：Guard 框架返回注释。

行为和重大变更

  • MCP 工具 tool_name 覆盖被阻止（安全）：MCP 工具入口点不再允许调用时 tool_name 覆盖。以前，模型可以将 tool_name="delete_repo" 传递给任何 MCP 工具，服务器将在允许列表、requires_confirmation、HITL 批准的同时执行该工具，并记录所有从声明的名称解析的内容 — 绕过任何 HITL/批准门。执行的工具名称现已从 tool.name 中关闭。模型提供的 tool_name 参数作为普通参数转发（不用于选择工具），因此合法声明 tool_name 参数的工具可以继续工作。
  • 工具结果缓存现在使用每用户密钥（安全/行为更改）：使用 cache_results=True，缓存密钥现在包括稳定的运行上下文身份（user_id、session_id），修复了跨用户缓存泄漏，其中缓存工具采用 run_context（例如 MemoryTools）将一个用户的结果提供给另一个用户。 run_id 不会成为关键因素，因此缓存在用户的运行过程中仍然有用。 现有缓存行为发生变化 - 键的组成不同，因此之前的缓存命中不会以相同的方式排列。
  • 补液现在大声失败（行为改变）：反序列化具有无法解析引用的持久组件，用于静默降级（代理的工具变成 []，团队失去成员，模式/知识丢失），然后运行。无法解析的引用现在在严格路径上引发 ComponentRehydrationError（AgnoError、status_code=422）。 严格性是调用者属性： public from_dict/load 默认 strict=False （往返继续工作），但是 AgentOS 查找和每个调度路径 （REST POST /runs、继续、MCP 运行工具、StudioRunner）默认 strict=True ，现在返回 422 命名无法解析的部分，而不是运行退化的组件。固定的会员版本也受到尊重。

发生了什么变化

  • 修复：MCP 工具入口点不得允许 https://github.com/agno-agi/agno/pull/9379 中的 @ashpreetbedi 覆盖调用时 tool_name *修复：在https://github.com/agno-agi/agno/pull/9395中保留@ashpreetbedi关于补液的工具包说明
  • 修复：持续暂停的成员运行，以便团队 HITL 恢复能够在 https://github.com/agno-agi/agno/pull/9396 中 @ashpreetbedi 的会话重新加载中幸存下来
  • 壮举：StudioRunnerTools - https://github.com/agno-agi/agno/pull/9371 中的 @ashpreetbedi 用于 Studio 组件的身份感知调度工具包
  • 修复：无法解析的补液参考会严重失败；荣誉由 @ashpreetbedi 在 https://github.com/agno-agi/agno/pull/9381 中固定的会员版本
  • 修复：guard框架返回注解；通过 @ashpreetbedi 在 https://github.com/agno-agi/agno/pull/9382 中将名称过滤器添加到 list_components
  • 修复：工具结果缓存 - 每个用户密钥、ToolResult 往返、https://github.com/agno-agi/agno/pull/9380 中@ashpreetbedi 的缓存命中挂钩
  • 修复：在 https://github.com/agno-agi/agno/pull/9514 中遵循 @Ayush0054 通过 WebSocket 选择的工作流程版本
  • 修复：A2A 流 client 通过在 https://github.com/agno-agi/agno/pull/9224 中中断 @psinojiya 的状态更新来删除任务级元数据
  • 壮举：@kausmeows 在 https://github.com/agno-agi/agno/pull/9545 中发布 2.9.0 完整 Changelog：https://github.com/agno-agi/agno/compare/v2.8.7…v2.9.0
