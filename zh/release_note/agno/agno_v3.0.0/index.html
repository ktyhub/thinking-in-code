agno v3.0.0

⚠️ 重大版本。 在 v3.0 提供流量之前需要进行数据库迁移。首先阅读**v3 迁移指南，并查看每项更改的完整v3.0 Changelog**。

新功能

  • 工具结果卸载：Agent(offload_tool_results=True) / Team(...) 将任何超过 16,000 个字符的工具结果写入 AgentFS，并在消息中留下一个短信封（预览、大小、result_id）；代理获取 read_result / search_result（+ 异步）来获取其余部分。写入路径上没有模型调用。通过 ResultStore(threshold_chars=..., ttl_seconds=...) 进行调谐。 (#9436，#9684)
  • 媒体卸载：代理/团队/工作流程上的 media_storage=S3MediaStorage(bucket=...) 在持久化之前将图像、音频、视频和文件上传到本地磁盘、S3 或 GCS；该行保留一个小的 MediaReference 而不是 base64（113 KB JPEG 从约 151,000 个字符减少到 2,897 个字符）。没有架构更改。 (#9340) 文档
  • CodeMode：CodeMode(tools=[...]) 将广泛的工具模式替换为在整个会话中持续存在的一个可编程 IPython 内核 - 该模型编写 Python 并将工具作为可等待句柄调用，组合它们（变量、循环、帮助程序），而无需在脚本中往返。
  • FinanceTools：一个具有可交换数据提供商的统一财务工具包。
  • RampRouter 模型：Ramp Router 的新模型提供商 (router.com)。
  • SuperGrok OAuth：xAI 模型的设备代码身份验证。

数据库

  • 运行有自己的表：每次运行都是 agno_runs 中的一行，具有实际列（session_id、run_type、agent_id、team_id、workflow_id、user_id、parent_run_id、status、run_index）+ JSON 有效负载。将会话写入放大从 O(N²) 提高到 O(N)，并消除 DynamoDB/Firestore 项目大小上限。 session.get_messages()、get_chat_history()、db.get_session() 和 AgentOS 会话路由未更改（在读取时运行重新附加）。 (#8350)
    • 直接运行 API：db.get_run()、db.get_runs(session_id=..., status=..., limit=..., page=...)、db.upsert_run()、db.delete_run()、db.delete_runs()（同步 + 异步）； db.get_session(runs_limit=N) 和 db.get_sessions(include_runs=False)。 (#8350)
    • 单行迁移：MigrationManager(db).up() 创建运行存储，并在 12 个同步 + 4 个异步后端上以非破坏性和幂等方式复制旧运行；未迁移的数据库仍然可以工作（读取具有旧版 blob 的合并运行表）。每个适配器上跟踪的架构版本。 (#8350)
    • 键入陈旧数据库错误：MigrationRequiredError / SchemaMismatchError 列出两种补救措施； AgentOS 在 JSON 主体中携带 error_id: "migration_required_error"。 (#9669，#9631)
    • 三个新表：agno_runs、agno_jobs（持久后台队列）、agno_tool_results（卸载索引）——全部自动创建。

每用户隔离

  • 从会话扩展到指标、计划、评估、知识、组件、实体内存和 17 个矢量数据库。每个用户每天的指标汇总；无主组件/知识是共享的（所有人可读，管理员可编辑），因此启用隔离不会 404 预隔离构建块。 (#8245，#8262)

AgentOS 和 Studio

  • 持久后台执行：AgentOS(queue=QueueConfig(durable=True)) - 接受的运行是在崩溃/重新启动/部署后仍然存在的已提交行，由任何副本执行。有界并发（默认为 32，AGNO_BACKGROUND_MAX_CONCURRENCY），排队时可取消，Idempotency-Key 重复数据删除，满队列时为 429。队列 REST 表面（GET /queue/jobs、.../{job_id}、POST .../requeue、GET /queue/stats）。 Redis是可选协调，从来没有真相。 (#9079，#9504)
  • Studio 3.0 — 受监管目录：create_* 编写的草稿在 publish_component 之前不为任何人提供服务；比较并设置防护（类型为 409）、逻辑删除、存档/恢复、相关跟踪。 StudioTools 返回一个涵盖约 31 个工具的机器可读信封 ({ok, status, data, error{...}, warnings})。 (#9604)

工具

  • MiniMax 视频生成工具。 (#9529)
  • 工具包现在有一个稳定的 id，AgentOS 使用它来引用工具。

模型更新

  • Cerebras / CerebrasOpenAI 默认为 gpt-oss-120b（原为 llama-4-scout-17b-16e-instruct）。 (#9244)
  • Gemini 默认更新为 3.7 Flash。 (#9666)
  • Groq：用 openai/gpt-oss-120b 替换已弃用的 llama-3.3-70b-versatile。 (#9588)
  • OpenAI：reasoning_effort、reasoning_summary、service_tier、verbosity 接受完整的 API 值集（加宽类型；无调用中断）。
  • Claude 适用于 anthropic 1.0.0 (#9686)：Claude 型号的 SDK 兼容更新

⚠️ 重大变更

每个 2.x 用户都必须阅读本文。在 v3.0 提供流量之前需要进行数据库迁移。

存储和迁移

  • 运行不再是会话表中的 JSON Blob — 它们位于 agno_runs 中。服务前运行 MigrationManager(db).up()（或 AgentOS POST /databases/all/migrate）。 v2→v3 迁移保留旧版 runs 列作为备份；验证后使用 db.cleanup_legacy_runs_column() (SQL) / db.cleanup_legacy_runs_field() (文档/KV) 回收。
  • 陈旧/未迁移的数据库会引发键入错误，而不是默默地出现错误行为。
  • 分页：没有 limit（或 page < 1）的 page 现在会引发 ValueError，而不是返回无界/负结果。

AgentOS

  • JWT：从 JWTMiddleware 和 authorization_config 中删除 secret_key — 使用 verification_keys（列表）。
  • 元数据路线：删除了 GET /models（模型数据移至 available_models 下的 GET /config）； GET / 返回最小着陆响应； GET /info 是单个未经身份验证的元数据端点。
  • MCP 服务器配置：删除了 AgentOS(enable_mcp_server=..., mcp_config=...) — 改为传递单个 mcp_server=。
  • 后台执行 需要组件上的 db （返回 400，没有 1）。外部框架代理（LangGraph、Claude、DSPy 等）为 background=true 内联流式传输，并且不可恢复。

代理

  • 重命名参数：
    • enable_user_memories → update_memory_on_run
    • search_session_history→search_past_sessions
    • num_history_sessions → num_past_sessions_to_search
    • num_past_session_runs → num_past_session_runs_in_search
  • reasoning=True 已删除 - 显式设置 reasoning_model=<native reasoning model>。
  • continue_run / acontinue_run：删除了 updated_tools — 传递 requirements（暂停运行输出中的 RunRequirement 列表）。
  • 删除了文化功能：enable_agentic_culture、add_culture_to_context、CulturalKnowledge、文化工具和 agno_culture 表。使用 Knowledge 来共享跨用户信息。

团队和工作流程

  • Workflow 构造函数仅限关键字：Workflow(name=..., steps=[...])。 Team 不变 - Team([agent_1, agent_2]) 仍然有效，但 Team(members=[...]) 是首选。
  • 在步骤/步骤/循环/条件/路由器上删除了平直的 HITL kwargs （requires_confirmation、confirmation_message、on_reject、requires_user_input、user_input_message、user_input_schema、requires_output_review、 output_review_message、requires_iteration_review、iteration_review_message、on_error、hitl_max_retries、hitl_timeout、on_timeout）。使用 human_review=HumanReview(...)（来自 agno.workflow.types）；名称不变，除了 hitl_max_retries → max_retries、hitl_timeout → timeout。

工具

  • MultiMCPTools 已删除（与 allow_partial_failure 一起）- 每台服务器使用一个 MCPTools。
  • MCPToolbox：auth_tokens / auth_headers 已删除 - 使用 auth_token_getters。
  • DuckDuckGoTools.duckduckgo_search → web_search、duckduckgo_news → search_news（现在基于 WebSearchTools 构建）。
  • 已删除平面 Google 工具模块（agno.tools.gmail、googlesheets、googlecalendar、google_maps、google_drive、google_bigquery）- 从 agno.tools.google.* 导入。
  • Google 工具：creds_path / auth_port → credentials_path / oauth_port；工作表 enable_read_sheet 等 → 裸方法名称。
  • FileTools.check_escape → Toolkit._check_path（LocalFileSystemTools.check_escape 不受影响）。
  • SQLTools：enable_list_tables / enable_describe_table / enable_run_sql_query → 裸方法名称。
  • 塞尔兹：max_documents→max_results。
  • StudioTool 别名已删除 - 使用 StudioTools。
  • BrightData.get_screenshot：已删除未使用的 output_path。 PgVector.enable_prefix_matching 已删除（死助手）。

知识和向量数据库

  • Knowledge.add_content / add_content_async / add_contents_async 已删除 → 使用 insert() / ainsert() / ainsert_many()。
  • GDriveContextProvider 重命名为 → GoogleDriveContextProvider。
  • LanceDB：use_tantivy 已删除/忽略。
  • 使用 user_id 搜索 v3 之前的向量表会引发 ValueError（引导您进行向量数据库迁移），而不是返回空结果。

调度程序

  • update_schedule 现已列入允许名单（仅限 name、description、method、endpoint、payload、cron_expr、timezone、timeout_seconds、max_retries、retry_delay_seconds、enabled、next_run_at、disabled_reason）；任何其他键都会加注 ValueError。所有权/出处/锁定状态不再可通过通用路径写入。 v3.0.0 迁移添加了新的出处列。
  • 时间表唯一密钥从 name 更改为 (user_id, name)。如果同一用户中存在重复的计划名称，迁移将中止 - 在迁移之前进行重复数据删除。

评估

  • eval_id → run_id (#9739)：评估类不再携带 eval_id；每次运行都有自己的 run_id。 store_result_in_file 将 eval_id 参数重命名为 run_id，不再接受 file_path_to_save_results 模板中的 {eval_id} 占位符（使用 {run_id}），并且 POST /eval-runs 返回实际存储行的 ID (run_id)。重新运行不再相互覆盖。

模型与学习

  • 米斯特拉尔：mistralai v1 兼容性层已删除 - agno[mistral] 需要 mistralai>=2.0.0（并返回 models 额外版本）。
  • agno.models.metrics 模块和 Metrics 别名已删除 → 从 agno.metrics (RunMetrics) 导入。
  • Model.classify_error 已删除 → 使用 ModelProviderError.classify(error)。
  • namespace="user" 下的 实体内存 现在按用户隔离（行键嵌入 user_id 摘要）；通过 v3.0.0 迁移 (agno.learn.migrations.rekey_user_entity_learnings) 重新键入 v3 之前的行； EntityMemoryStore.delete/get 在该命名空间中需要仅关键字 user_id。
  • 删除了学习别名：MemoriesConfig → UserMemoryConfig； MemoriesStore→UserMemoryStore； Decision → DecisionLog。

已弃用（仍在工作）

  • knowledge_retriever(dependencies=...) → 更喜欢 run_context。签名仍名为 dependencies 的检索器继续通过显式向后兼容分支工作； 当两者都在场时，run_context 获胜。
  • 范围：system:read / system:write → config:read / config:write。旧名称仍然是有效的别名，现有令牌仍然有效。
  • RedisDB（矢量 DB）→ RedisDb。请注意，RedisVectorDb 也仍会导出，以与 agno.db.redis 存储适配器消除歧义。

迁移快速参考

文档：分步指南、数据库迁移和粘贴到您的编码代理提示

import asyncio
from agno.db.migrations.manager import MigrationManager

# Step 1: run before serving v3.0 traffic (up() is async)
asyncio.run(MigrationManager(db).up())

# Step 2: VERIFY the runs landed before any cleanup
assert len(db.get_runs(limit=5)) > 0, "Migration copied nothing - do NOT clean up"

# Step 3 (optional, destructive): reclaim the legacy blob column.
# The migration preserves it as a backup, so force=True is required.
db.cleanup_legacy_runs_column(force=True)   # SQL adapters
# db.cleanup_legacy_runs_field(force=True)  # document / KV adapters

在 AgentOS 上：POST /databases/all/migrate。完整详细信息请参见v3.0 changelog 文档。
