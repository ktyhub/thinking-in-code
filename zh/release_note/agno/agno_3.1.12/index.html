agno v3.1.12

#Changelog

新功能：

  • Harness Agents 的本机批准：Claude 和 Codex 自己的权限请求现在到达 AgentOS 批准 UI。当代理拥有数据库（包括一个 AgentOS 供应）时，本机请求会持续显示在现有聊天和批准视图中的暂停运行，并且 Resolve 加上继续运行会将决策返回到相同的本机执行，而无需重播提示。线束自己的策略决定何时询问 - Claude 保留其 permission_mode 和显式权限回调，Codex 支持 approval_policy="on-request" | "untrusted" | "never" 以及现有的 SDK、auto_review 和 deny_all 模式 - 因此无需打开单独的 Agno 设置。决策根据请求的确切操作进行验证，具有同步和异步延续、取消、过期和存储故障处理，沙盒代理在 Docker 和 AgentCore 中保持这一点：能力协商、决策 RPC、受保护的持久性、API-worker 丢失后重新附加、单独的批准等待和执行预算以及流程丢失后不重放。请注意，没有批准设置的 CodexAgent 现在在本机 on-request 策略下运行，因此之前无处可去的请求会暂停运行； hitl_timeout（默认 900 秒）限制了等待的时间。参见 cookbook/frameworks/human_in_the_loop/。
  • 最初禁用的公司例程：Routine(enabled=False) 允许模板传送非活动例程，用户稍后可以从 UI 打开该例程，True 仍然是默认值。禁用例程以原子方式创建，保持与其产品的链接并在列表中可见，被调度程序跳过，并在重新启动时保留用户保存的选择。该标志在 Python 和 YAML 引导程序、设置和创建 API、同步和异步公司管理器以及公司工具中​​受到尊重。重复的创建请求仍然返回 409 并且无法启用现有例程，并且现有的暂停/恢复端点启用它而不重新创建它。参见 cookbook/05_agent_os/30_company/11_disabled_routine.py。
  • 图表上的标题数字：ChartTools.create_chart() 采用可选的预格式化 value — 总计或最新值，例如 "$22.3K" 或 "94%" — 在图表块中以 "value" 形式发出，并由 Agno OS 在图表标题旁边呈现。当没有单个数字总结图表时，文档字符串告诉模型将其忽略，因此不会对平均值和比率进行求和。

改进：

  • 公司例程排序：GET /company/routines 现在还按 next_run_at、schedule_type 和 enabled 排序，因此 Agno OS 可以按“下次运行时间”、“计划”和“活动”对其例程表进行排序。暂停的例程和按需例程没有即将运行的例程，因此它们在任一方向上都是最后的，并且具有相同值的例程保持其创建顺序。
  • Cookbooks：添加了 ApifyTools 职位搜索示例，该示例使用工具挂钩限制演员的项目计数，并将每个数据集项目修剪为标题、公司、位置、发布日期和链接，因此广泛的搜索在上下文中保持较小。添加了一个完全本地的 Pixeltable RAG 示例，该示例通过 langchain-pixeltable 写入块并使用 LangChainVectorDb 搜索它们，使用本地 sentence-transformers 嵌入和 Ollama — 没有嵌入 API 密钥，也没有单独的矢量数据库服务器。

错误修复：

  • FastAPI 本机跟踪：一旦存在 AgentOS(tracing=True) 安装的全局跟踪器提供程序，FastAPI 0.142.0 就会启用自己的 OpenTelemetry 跟踪，因此 FastAPI 的请求跨度与 Agno 的请求跨度存储在一起。每次运行都成为请求范围的子级，并且跟踪记录为 fastapi.dependencies，其中包含空的 run_id、session_id 和 agent_id，从而破坏了运行视图，而每个 UI 请求都存储了自己的跟踪。 AgentOS 现在选择它从 FastAPI 的跟踪中构建的应用程序，而 setup_tracing() 会过滤外部跨度，因此存储的跟踪植根于 Agno 运行。没有 tracing=True 的应用程序保留 FastAPI 的默认设置，并且仍然保留用户在工具内创建的自己的跨度。
  • 公司例程取消：执行器接受请求后，POST /company/routines/{id}/cancel 将运行记录为 cancelled，但代理仅在下一个检查点停止。对于该窗口，API 在代理仍在工作时报告了 cancelled，并且存档、删除和执行程序更改在运行中进行。该路线现在仅记录来自持久证据的状态：实时运行单独留给 ScheduleExecutor 来解决，完成的运行通过调度程序自己的映射写入，丢失的运行被记录为 cancelled，并且超过超时的崩溃运行不再阻止存档、删除或执行程序更改。
  • AccuracyEval Judge：没有 model 和 evaluator_agent 的 AccuracyEval 使用 OpenAIChat(id="o4-mini") 构建了它的判断，OpenAI 于 2026 年 10 月 23 日关闭了该判断，因此每个判断调用都返回 404 model_not_found，没有迭代得分，并且评估报告空运行而不是其背后的提供者错误。现在默认值为 gpt-5.6-terra，它是 o4-mini 的 OpenAI 替代列表。固定退役模型的示例也会移动，并且精度示例切换到 OpenAIResponses，因为 OpenAIChat 拒绝这些模型的函数工具。
  • 每次上传的知识分块：POST /knowledge/content 接受每次上传的 chunker、chunk_size 和 chunk_overlap，而 process_content() 将它们直接应用到 content.reader — 知识库上共享的自定义或已解析的阅读器。使用该读取器的每次上传都会保留先前上传的分块器，直到进程重新启动。现在，在应用分块策略之前，上传会获得自己的读者浅层副本，因此知识库会保留自己的配置。

发生了什么变化

  • 修复：https://github.com/agno-agi/agno/pull/11327 中的@sunhouy 将知识库读者的每次上传分块选项保留在知识库阅读器之外
  • 修复：将 AccuracyEval 判断和示例移出已退役的 Op
