agno v3.1.2

修订 发布时间2026年10月8日 来源agno-agi/agno 英文原文

agno v3.1.2

#Changelog

新功能：

  • 对话压缩：Agent(compaction=True) 通过将旧的回合折叠成摘要，将长会话保留在上下文窗口内。存储的消息永远不会被重写：新的 agno_compactions 表中的 CompactionRecord 驱动派生模型有效负载，因此删除记录可以恢复完整的对话。使用 Compaction(model=..., compact_at_tokens=..., uncompacted_runs=...) 进行调谐，使用 agent.compact() / acompact() 按需折叠，并检查 run.compaction。通过 searchable=True，代理可以获得 search_compacted_history 工具，这是对存档记录的正则表达式 grep。请参阅食谱。 (#9873)
  • Codex 外部代理：添加了 CodexAgent，这是一个基于 openai-codex SDK 构建的 OpenAI Codex 适配器，以及 Claude Agent SDK、LangGraph、DSPy 和 Antigravity 适配器。 Codex 运行自己的代理循环；该适配器将其通知转换为 Agno 运行和工具调用事件，将每个 Agno 会话映射到一个 Codex 线程（设置 db 时保留），并公开 sandbox、approval_mode、reasoning_effort、output_schema 和 MCP 配置。独立工作并通过 AgentOS 工作。请参阅食谱。 (#10901)
  • HyDE 查询转换：添加 QueryTransformer 作为新的检索挂钩，并添加 HyDE 作为其第一个实现：Knowledge(vector_db=..., query_transformer=HyDE()) 使用假设答案而不是原始问题进行搜索，而重新排名器仍然根据原始查询进行评分。 HyDE使用自己的model，然后调用代理或团队的模型，然后框架默认。请参阅食谱。 (#10527)
  • 浏览器来源政策：添加了 AgentOS(cors=CORSConfig(origins=..., origin_regex=..., merge_base_app=...)) 和选择加入 PublicSurface(enforce_browser_origins=True)。现在，CORS 预检、公共运行和取消准入、身份验证错误标头、工作流 WebSocket 和 MCP 别名共享一种原始策略，并且 CORS 是最外层的中间件，因此错误响应携带一致的标头。 cors_allowed_origins 保持其现有行为。请参阅食谱。 (#10869)
  • 可配置的后续行动：代理和团队上的 followups: bool | FollowupConfig。 FollowupConfig 设置一个计数范围（num_followups 或 min_followups / max_followups），单独的模型和自定义指令，仅用于后续调用。默认提示现在保留在答案的边界内，并且不再重新提供答案 declined 的请求。现有的 num_followups 呼叫者不断收到 N 个建议。请参阅食谱。 (#10087)
  • Heabsy：添加了 Heabsy 作为 OpenAI 兼容模型提供程序，也可解析为 "heabsy:<model>"。请参阅食谱。 (#10828)
  • FlexAI：添加了 FlexAI 作为开放权重模型的 OpenAI 兼容模型提供程序，也可解析为 "flexai:<model>"。请参阅食谱。 (#10871)
  • SixtyDBTools：用于 60db 托管语音 API 的新工具包：发现工作区语音并将语音生成为 WAV 音频工件。请参阅食谱。 (#10786)

改进：

  • 页面同步日志：页面同步现在记录锁定等待、发现、每 25 页的进度和最终计数，因此长同步显示进度，无需自定义回调。添加了 AgentOS 食谱，将文档同步到 PostgreSQL 支持的知识页面并通过代理的文件系统公开它们。请参阅食谱。 (#10868)
  • OpenAIResponses 和 OpenRouterResponses：将 GPT-6 (OpenAI) 和 GPT-5/6 (OpenRouter) 识别为推理模型，因此推理状态链和加密推理重放应用以及工具调用后续操作不再因缺少推理项错误而失败。 (#10830)
  • PerplexitySearch：请求现在发送 X-Pplx-Integration: agno 标头，以便 Perplexity 可以对来自集成的流量进行归因。 (#10827)

错误修复：

  • 批准：运行中的每个 @approval 工具调用现在都会为代理和团队获取自己的批准记录。以前，同一运行中的第二次暂停没有创建任何记录，而下一次继续运行针对第一次解决的批准的新调用。 (#10812)
  • 模型响应缓存：Pydantic output_schema 类由其 JSON 模式而不是类名作为键控，因此具有相同名称但不同字段的两个模式不再共享缓存的响应。 (#10621)
  • 使用指标：MessageMetrics.cache_write_tokens 现在由 OpenAI 聊天完成和响应使用情况 (#10313) 以及 LiteLLM 的 prompt_tokens_details (#10476) 填充。以前它总是为零。
  • JsonDb：表被序列化为暂存文件并使用 os.replace 发布，因此失败的写入会使最后成功保存的表可读，而不是截断的文件。 (#10794)
  • MongoDb 和 MongoVectorDb：session_name、search_content 和关键字搜索过滤器是正则表达式转义的，因此像 (draft 这样的值不再从 GET /sessions 和 GET /memories 返回 HTTP 500，并且 v1.2 不再与 v1x2 匹配。 (#10709)
  • 工具架构：Annotated[T, ...] 提示在 JSON 架构生成之前解包到 T，而不是落入空对象架构。 (#10858)
  • SQLTools：连接 URL 是使用 URL.create 构建的，因此像 p@ssword 这样的密码不再分为密码 p 和主机 ssword@...。 (#10800)
  • 文件工具：replace_file_chunk 拒绝负数、反向和越界行范围并出现错误，并保持文件不变；有效的替换会保留尾随换行符。 (#10798)
  • GoogleCalendarTools：find_available_slots 将完整时段结束与其开始日期的关闭时间进行比较，因此不再在 16:30 提供 45 分钟时段，以 17:00 关闭，并且时段不能跨越午夜。 (#10878)
  • BaiduSearchTools、Searxng 和 SpiderTools：显式的 max_results=0 / fixed_max_results=0 现在意味着没有结果，而不是回退到默认值。 (#10877)
  • 读者：TextReader、MarkdownReader (#10779) 和 JSONReader (#10634) 接受 name 是整数或 None 的流，例如描述符支持的临时文件，而不是返回任何内容或引发。
  • Cookbooks：修复了 DynamoDB 存储自述文件中的 DynamoDb 导入路径。 (#10788)
