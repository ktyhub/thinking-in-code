agno v3.0.4

#Changelog

行为改变

  • KnowledgeManagementTools 构造函数标志已重命名，ingest_path 现在选择加入：2.x 样式的 enable_ingest / enable_remove 标志被以它们注册的工具命名的标志替换 - ingest_url、ingest_path、ingest_text、remove_content（旧名称不再被识别，如果通过则被忽略）。 ingest_path 默认为关闭：它读取服务器进程可以读取的任何路径，并且在 scope="shared" 下，它加​​载的内容可以被该知识库上的每个代理读取，因此注册它现在是一个明确的选择。 list_content 和 ingest_status 保持未标记 — 它们只读取。 (#9861)
  • agno.tools.knowledge_management 导入路径已移动：KnowledgeManagementTools（在 3.0.3 中引入）现在位于 agno.tools.knowledge；旧的模块路径消失了。 from agno.tools.file_generation import FileGenerationTools 通过兼容性垫片继续工作。 (#9861)

改进

  • agno.tools.file 和 agno.tools.knowledge 为封装：FileTools 和 FileGenerationTools 共用 agno.tools.file； KnowledgeTools（读取侧）和KnowledgeManagementTools（写入侧）共享agno.tools.knowledge，遵循agno.tools.mcp和agno.tools.finance布局。名称在第一次访问时解析，因此导入 FileTools 不再将 reportlab 和 python-docx 拉到后面 — 安装这两个组件时测量为 44.8 毫秒，之前在每次 FilesystemContextProvider 导入时付费。 (#9861)
  • AtomicMail 重用其身份验证握手：已解析的上下文（功能 JWT、API URL、帐户和收件箱 ID）在同步和异步路径中缓存在实例上，直到令牌接近到期，并键入生成它的 api_key，以便在下一次调用时重新注册。热工具调用从 ~35 秒下降到 0.4–3 秒。 (#9825)
  • AtomicMail 工作证明并行：scrypt 随机数搜索在有界线程池中分割 - 新的 pow_workers 参数，默认 min(4, cpu_count())，pow_workers=1 与旧的顺序搜索完全匹配。在难度 10 下测量：平均在 4 个工人上解决 25.9 s → 10.4 s。 pow_timeout 仍然限制搜索，找到解决方案的工作人员会克服并发超时。 (#9825)

错误修复

  • AtomicMail list_inbox 返回代理自己发送的邮件：send_email 将外发邮件归档在设置了 $draft 的收件箱邮箱中，而 list_inbox 查询该邮箱时未过滤，因此代理无法从回复中分辨出自己的外发邮件。现在，查询会过滤 notKeyword: "$draft"，解析器会删除所有 $draft 条目，并且拒绝的查询将报告为错误，而不是空收件箱。 (#9825)
  • 调用者提供的 requires_confirmation_tools 放弃了 remove_content 门：KnowledgeManagementTools 使用 setdefault 设置其确认列表，因此默默地传递您自己的列表删除了 remove_content 上的内置确认要求 - 套件中破坏数据的一个工具。该列表现在联合。 (#9861)
