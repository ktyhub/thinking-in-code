agno v3.1.4

修订 发布时间2026年10月16日 来源agno-agi/agno 英文原文

agno v3.1.4

#Changelog

新功能：

  • 沙盒化线束代理：ClaudeAgent 和 CodexAgent 采用 sandbox= 参数，并在隔离的每会话计算机内而不是在主机上运行整个线束进程，会话状态在丢失容器、主机或上一轮运行的副本时仍然存在。没有新的类可以容纳：ClaudeAgent(id="coder", db=PostgresDb(...), sandbox=DockerSandbox("agno-sandbox:local", network="isolated")) 是整个设置，代理在第一次使用时从 PostgresDb 构建其协调器。每个轮次都通过代理的 Postgres 中的租用行（<session_table>_sandbox_bindings，首次使用时创建）声明会话，启动从会话的最后提交的检查点（工作区加上线束自己的对话文件）恢复的计算，运行轮次，然后捕获并验证新的检查点，并在一个事务中发布运行行和恢复点。取消或失败的回合不会发布任何内容，之前的检查点仍保留为恢复点。该回合拒绝继续处于无法验证的状态：它传递使用上一个检查点提交的本机对话 ID（Claude 会话 ID、Codex 线程 ID），并且在模型运行之前丢失该对话 ID 的恢复会失败并显示 native_state_missing，而不是静默地启动新对话。键入的线束设置作为 JSON 传输到运行时；仅主机设置（cwd、retries、env、本机选项对象）在构造时按名称拒绝。 require_native_resume 和 strict_persistence 是 BaseExternalAgent 的新选件，而 agno[claude] / agno[codex] 安装附加件涵盖了线束 SDK。请参阅食谱。 （#11028、#11043、#11056、#11057）
  • Docker 沙盒：DockerSandbox 是客户运营的提供商。容器以 UID 1000 运行，具有只读映像文件系统、删除功能、无权限升级、CPU、内存和进程限制、/workspace 和 /runtime 的有界 tmpfs、无主机或 Docker 套接字安装，并且仅显式配置的环境值以及线束的模型 API 密钥。组网默认为none； network="isolated" 提供了一个可管理的桥接器，并且关闭了容器间的流量，而 subnet= 则选择了它的范围。确定性会话和生成身份可协调创建竞赛和丢失响应；命令永远不会自动重试。 pause / resume 通过内核冷冻机提供，DockerCheckpointTransfer 将检查点移入和移出。 cookbook/frameworks/sandbox/build_image.py 构建运行时映像。请参阅食谱。 （＃10975，＃11028）
  • Amazon Bedrock AgentCore 沙盒：AgentCoreSandbox 在 AgentCore Runtime 上实现相同的合约，AgentCoreCheckpointTransfer 位于 Docker 传输旁边。每个沙箱生成都是 Firecracker microVM 中的一个 AgentCore 运行时会话； create 通过从命名空间、代理、会话和生成派生的会话 ID 实现幂等。端口 8080 上的根服务器声明该 microVM，以 UID 1000 启动运行时，使用声明的配置和随机化身隔离以后的每个操作，以便过时的句柄永远无法对以后的声明执行操作，转发启动和轮询调用，并在 /workspace 中降至 UID 1000 的防护后面运行命令。检查点在捕获和恢复期间停止 UID 1000 进程，并以块的形式在 InvokeAgentRuntime 中移动，最大可达 2 GiB。不支持暂停，并且不使用 AgentCore 会话存储。提供商包移至 agno.sandbox.docker 和 agno.sandbox.agentcore； DockerCheckpointTransfer 现在从 agno.sandbox.docker 进口。运行时还获得了两个适用于 Docker 的 Codex 修复：它创建 CODEX_HOME，并且当没有存储的登录匹配时从 OPENAI_API_KEY 登录 Codex，因为检查点排除了 auth.json。 cookbook/frameworks/sandbox/agentcore/agentcore_setup.py 构建、推送和部署运行时。请参阅食谱。 (#11050)
  • 温暖沙盒回合：协调器在回合后将会话的计算机保留为 warm_computer_seconds（默认 300），而不是销毁它：在 Docker 上暂停，在 AgentCore 上保持空闲。该窗口内的下一个回合将恢复它，但不会恢复任何内容；否则，它将淘汰旧计算机，并在从检查点恢复的新一代计算机上采用冷路径。每次转弯后检查点仍然会被捕获，因此热计算机只是检查点已保持的状态的快捷方式。每次完成的运行上的 metadata.sandbox.resumed 都会说明轮到哪条路径，协调器上的 retire_computer / sweep_warm 会删除会话从未返回的计算机。在Docker现场直播，温暖的克劳德转弯让4.6对抗8.2的寒冷； AgentCore 3.3 与 8.2 的对比。请参阅食谱。 (#11088)
  • 通过 AgentOS 进行沙箱：沙箱代理的 POST /agents/{agent_id}/runs 将前台、流式传输和后台请求提交到持久队列，无需新端点。 Idempotency-Key 重试返回相同的运行，而不同的会话、输入、选项或附件字节返回 409。Clients 与 /runs/{run_id}/resume (last_event_index) 重新连接并使用 /runs/{run_id}/cancel 取消，包括跨副本：在另一个副本上解决的取消现在将运行记录为已取消，并保持用户对运行行的轮流。如果沙盒代理没有 Postgres 进行协调，AgentOS 将在启动时失败，一旦队列工作线程处于活动状态，就会拒绝主机本地默认检查点存储，并在启动时和提交之前验证每个沙盒代理的绑定表，为早期构建中的表命名补救措施。请参阅食谱。 （＃11043，＃11105）
  • 沙盒代理的附件：沙盒 ClaudeAgent 或 CodexAgent 上的 run / arun 接受 images= 和 files=，并且 AgentOS 运行路线接受它们作为上传。只有字节进入沙箱：每个附件在任何持久写入之前都会经过验证和编码，由线束自己的暂存器在 /workspace/.agno/uploads/<run_id>/ 下暂存，并保存在回合的检查点中，以便稍后打开新计算机仍然可以读取它。一次请求最多携带16个附件，总计512 KiB； URL、媒体引用、服务器文件路径、音频和视频均被拒绝。排队运行将附件与提交一起存储，因此重试会发送相同的字节。请参阅食谱。 （＃10990，＃11091）
  • 用于 Claude 代码的内联图像和 PDF：ClaudeAgent 现在将消息内最多 4 MiB 的附加图像（PNG、JPEG、GIF、WEBP）和 PDF 作为内容块发送，这是代理 SDK 流输入所采用的形式，而不是仅将它们写入磁盘以供 Claude 的读取工具使用。 Claude 直接看到图片，并且从不读回文件，这通常会将整个文件作为 base64 返回，并溢出 SDK 的 1 MiB 消息缓冲区和沙箱的 256 KiB 事件框架，以获取几百 KB 的图像。文件是否内联由其字节决定，因此错误标记的文件会保留在磁盘上供文件工具使用；其他文件和较大的图像保留读取路径。请参阅食谱。 (#11115)
  • 每个会话队列：在一个会话上运行的持久后台现在对于每个组件一次最多执行一个（按提交顺序）。每张门票均带有商店指定的session_seq；仅当其会话中没有同级正在运行或暂停并且没有较早的同级仍在排队时，才会声明票证，因此等待票证不会花费任何尝试，也不会产生工作槽。不同的会话在 max_concurrency 内保持并发。暂停的运行保留其会话，继续或重试的运行保留其位置，而 PENDING 运行轮询则携带 waiting_on 及其被阻止的运行。 QueueConfig.queue_per_session（默认打开）控制它，外部代理无论如何都会被序列化，并且GET /config报告有效设置。请参阅食谱。 (#9587)
  • 即时持久提交：接受持久提交的副本会在票证提交后唤醒其自己的队列工作线程，因此运行会在几毫秒内开始，而不是等待 poll_interval 进行下一次轮询。饱和的副本在插槽释放时醒来，并且对等节点仍然在自己的轮询中选择作业。持久性未受影响：该行在任何人被唤醒之前提交。 (#9667)
  • ChartTools：带有单个 create_chart 工具的新工具包，可验证图表有效负载（bar、line、area、pie、bar-horizontal、bar-stacked、area-stacked）并返回准备好的围栏图表块供 Agno OS 渲染，取代用户必须携带的模式提示。验证失败会告诉模型要修复什么，并且工具包会提供自己的指令，因此 tools=[ChartTools()] 就是代理所需要的全部。请参阅食谱。 (#8295)

改进：

  • 用于数据库支持和工厂组件的持久队列：在通过组件 API 创建的组件上、在版本固定运行上以及在 AgentFactory / TeamFactory / WorkflowFactory 提交上后台运行现在将乘坐持久队列，而不是下降到接受副本上的分离任务。接受端点在票证上标记解决方案范围（来源、所有者、版本，以及工厂的 trusted 声明和工厂输入），并且工作人员在声明时重播该解决方案。在工作线程上读取 ctx.request 的工厂运行失败，并显示一条指定修复的消息，因为实时请求无法处理票证。工厂运行的运行读取路线不再在每次轮询中回答 400。请参阅食谱。 （＃9796，＃11045）
  • Codex 权限策略命名：CodexAgent(sandbox="read-only") 被重命名为 sandbox_mode，匹配 Codex 自己的配置密钥，因为 sandbox= 现在需要一个提供程序。旧的字符串形式仍然适用于 DeprecationWarning。 (#11043)
  • Sandbox Cookbooks：cookbook/frameworks/sandbox/ 分为 docker/ 和 agentcore/ 文件夹，每个文件夹都有自己的 README 和测试日志，涵盖提供者、检查点、协调器、恢复、取消、附件、热转和 AgentOS。 build_image.py 将内置标签加载到图像存储中并验证其是否存在。 （#11050、#11081、#11105）
  • Gemini Cookbooks：更新到当前型号和 API。 (#11038)

错误修复：

  • 沙盒检查点恢复：沙盒会话中的每一秒都会失败并出现 getent unable to find entry "1000:1000" in passwd database，因为 docker cp --archive 要求守护进程将容器的用户解析为名称。现在恢复无需存档模式即可复制，并将每个恢复的条目固定为 1000:1000 本身。 (#11094)
  • 沙盒存储和协调器：队列取消与工人声称同一运行可能会在锁定顺序上陷入僵局；停止路径现在采用与每个其他存储事务相同的顺序进行会话、运行和绑定。通过 DockerSandbox 的同步调用每次调用都会泄漏 HTTP client。取消的沙箱运行现在记录了队列预期的 EXECUTING 取消阶段。在清理和提交之间标记为已完成的运行会通过停止路径，而不是将绑定保留在 finalizing 中，并且长提供程序调用会延长其租约。 （＃11057，＃11092）
  • 沙盒提交：使用 user_id 提交到没有创建的会话，或者相反，在任何票证存在之前都会回答 404，而不是留下取消作业的 500。作业在其运行行存在之前失败的前台请求将票证错误返回为 500，而不是 503，要求 client 重新连接。 (#11105)
  • WebSocket Tails：使用持久队列，当工作流运行通过 WebSocket 进行流式传输时发送第二条消息的聊天 client 停止获取第一次运行的事件。尾部泵现在按（插槽、运行）键控，重新订阅仅替换该运行的泵，并且一个插槽最多可连接 32 个运行。 (#11039)
  • API 文档顺序：文件系统路由在设置和重新同步时的数据库路由之后注册，因此生成的 API 文档按顺序列出它们。 (#11099)
  • 测试：在工厂提交开始进入持久队列后，WebSocket 工厂工作流程测试会固定它们所编写的内联路径。 (#11106)
