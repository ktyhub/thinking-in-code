agno v3.1.3

agno v3.1.3

#Changelog

新功能：

  • 持久外部代理会话：ClaudeAgent 会话现在可以在任何副本上恢复。 Claude SDK 会话 ID 存储在 Agno 会话中 (#10903)，并且使用支持转录本存储的数据库 (PostgresDb、AsyncPostgresDb、SqliteDb、AsyncSqliteDb)，每个转录本行都会镜像到新的 agno_transcripts 表中，因此稍后打开另一台计算机将从数据库而不是本地文件恢复。无法恢复的存储会话将回退到使用 Agno 历史记录播种的新 SDK 会话。 Claude 和 Codex 非流式运行现在将工具调用和结果保留在运行历史记录中。请参阅食谱。 (#10904)
  • 外部代理的后台运行和取消：ClaudeAgent 和 CodexAgent 支持 background=True、持久队列运行 ID、可恢复索引 SSE 和通过 /agents/{id}/runs/{run_id}/cancel 取消，共享本机代理的后台任务、插槽和事件流基础设施。 Claude 使用每次运行的 SDK client，Codex 保留转动手柄，因此拥有进程可以中断任一 SDK。请参阅食谱。 (#10905)
  • ClaudeAgent 的步骤重播：ClaudeAgent.continue_run / acontinue_run 采用与 Agent.continue_run 相同的 continue_from、fork 和 input 参数，以及 stream=True 和 background=True。每个工具结果都是GET /agents/{id}/runs/{run_id}/checkpoints列出的一个检查点；继续在该消息处分叉存储的 SDK 转录本，因此模型只记住之前发生的事情，并且 continue_from="last_user" 重播该回合。完成的运行永远不会就地重写：它的延续是新的同级运行。请参阅食谱。 (#10917)
  • 外部代理重试：ClaudeAgent 和 CodexAgent 采用 retries、delay_between_retries 和 exponential_backoff，默认值与 Agent 相同。使用相同的运行 ID 重试失败的尝试，并恢复它启动的 SDK 会话或 Codex 线程；限制（max_turns、max_budget_usd、Codex 预算和使用限制）和永久错误（身份验证、计费、错误请求、上下文窗口、策略）不会重试。失败尝试的工具调用仅保留一次，流消费者在尝试之间收到 type: "retry" 警告事件，重试运行记录 metadata["attempts"]，并且当代理将其错误标记为不可重试时，持久队列会立即使作业失败，包括跨工作进程重新启动。请参阅食谱。 (#10937)
  • 外部代理的指标：每个 ClaudeAgent 和 CodexAgent 运行都会报告 RunOutput.metrics 上的令牌、缓存使用情况和成本 (Claude)，metrics.details["model"] 中每个模型有一个条目，加上 Agno 的挂钟 duration 和 time_to_first_token。已完成的运行会累积到会话的 session_metrics 中，AgentOS 将其显示在会话列表、会话视图和 /metrics 中。 Codex 轮流对每个模型请求求和，而不仅仅是最后一个。请参阅食谱。 (#10925)
  • 外部代理的压缩：Claude Code 的 /compact 通过数据库支持的会话存储工作，因此压缩的会话可以从任何副本上的摘要中恢复，并且 CodexAgent.compact / acompact 压缩 Agno 会话后面的 Codex 线程。当会话运行正在进行时，压缩被拒绝。请参阅食谱。 (#10924)
  • 外部代理的存储事件：BaseExternalAgent 与 Agent 一样采用 store_events 和 events_to_skip。 AgentOS 会为外部代理打开此功能，因此一旦事件流的保留过期，运行视图和 /agents/{id}/runs/{run_id}/resume 就会从数据库中重播已完成的运行，并尊重 last_event_index。 （＃10957，＃10958）
  • 外部代理的结构化输出：ClaudeAgent 和 CodexAgent 上的 output_schema 在代理上或每次运行时采用 Pydantic 模型或 JSON 模式字典，并且运行的内容是设置了 content_type 的解析模型（或字典），与 Agent 一样。 Claude通过其结构化输出工具传递对象，不记录为工具调用； Codex 拥有严格的模式。该模式必须描述一个 JSON 对象；数组或标量根在运行前被拒绝。 AgentOS 每个请求 output_schema 表单字段现在适用于外部代理。请参阅食谱。 (#10965)
  • 外部代理媒体：图像和文件可以直接或通过 AgentOS API 和 UI 附加到 ClaudeAgent 和 CodexAgent 运行。附件在 <cwd>/.agno/uploads/<run_id>/ 下暂存，在提示中命名（Codex 本身也接收图像），记录在运行的输入上，恢复以供以后打开任何副本，并在运行后删除，除非 keep_uploads=True。音频和视频被拒绝，并显示 400，而不是服务器错误。请参阅食谱。 (#10926)
  • 会话 API 上的外部代理标识：GET /sessions、GET /sessions/{session_id} 和会话运行读取携带与代理 API（"codex"、"claude-agent-sdk"）相同的 metadata.sdk 值，在读取时覆盖来自 agent_data 外部代理的数据已经持续存在，因此现有会话没有迁移标记，并且存储的元数据保持不变。本机、团队和工作流程会话保持不变。 RunSchema 获得 metadata 字段，该字段还显示运行元数据，例如重试 attempts 和 warnings。 (#11020)
  • AnakinTools：Anakin.io 的抓取、抓取、映射和搜索 API 的新工具包作为四种标志门控方法，轮询异步作业直到它们完成，以便模型接收页面内容或链接而不是作业 ID。请参阅食谱。 (#10650)

改进：

  • 外部代理 APIs：ClaudeAgent 和 CodexAgent 采用类型化本机选项（工具、权限、MCP 服务器、线程和转向选项），而不是非类型化 _kwargs 字典，后者仍然可以使用警告。适配器构造函数仅包含关键字，agent.sdk 命名 SDK（API 和会话元数据仅发出 sdk；framework 别名保留在 Python 对象上），print_response / aprint_response 返回最终运行并在失败时引发。使用本机 SDK 比较、示例项目和可重现的可靠性套件对框架说明书进行了重新设计。 (#10926)
  • 外部代理的模型身份：ClaudeAgent 和 CodexAgent 像本机代理一样运行记录 model 和 model_provider，因此它们依赖于 AgentOS 指标页面的模型运行卡。当代理或其选项中未设置模型时，Claude 的 model 默认为 claude-sonnet-4-6，Codex 的 gpt-5.6-luna 默认为 gpt-5.6-luna，因为本机模型具有默认 id；默认是要求 SDK 运行的。选项中设置的模型仍然获胜。此前，未设置的型号将选择权留给了 CLI。 (#11018)
  • 每个会话的排队轮次：排队的外部代理打开一个会话不再一起声明尝试并将其刻录在 SessionBusyError 上。每个内置队列存储（Postgres、Redis、内存中）都会在尝试或使用工作槽之前选择会话的下一轮。 (#10974)
  • Harness Cookbooks：Claude 和 Codex 烹饪书在第 1 阶段验收测试后进行了更新，整个过程中使用了类型化的本机选项、更正的可靠性运行程序以及每个文件夹的测试日志中记录的实时结果。 (#10973)
  • 每个会话一回合：Claude Code 和 Codex 在每个会话中保留一次对话，因此在飞行中开始的第二回合现在会被 SessionBusyError（HTTP 409、error_type: session_busy）拒绝，而不是被接受并稍后失败。取消因崩溃而挂起或正在运行的运行会释放其会话。 (#10958)
  • 子代理工具沿袭：Claude 子代理进行的工具调用在 ToolExecution 和工具事件上携带 parent_tool_call_id，因此跟踪显示委托工具下的嵌套工具跨度。请参阅食谱。 (#10959)
  • 开发设置：scripts/dev_setup.sh 和 scripts/demo_setup.sh 安装相同的依赖项，因此说明书可以从任一环境运行。 (#10920)

错误修复：

  • 会话繁忙保持活动：繁忙的外部代理会话的 409 由专用的 SessionBusyError 处理程序而不是包罗万象的处理程序应答，因此保持活动连接保持打开状态，并且冲突被记录为警告而不是回溯。响应正文保持不变，并且没有其他异常采用新路径。请参阅食谱。 (#11017)
  • 附件暂存：附加到外部代理运行的文件仅在活动工作区下暂存和恢复，并在历史路径移动时告知线束。失败的暂存会回滚它创建的每个文件，包括部分写入和 keep_uploads=True，同时保留先前存在的文件。遍历运行 ID 和符号链接上传路径被拒绝。 (#10971)
  • 运行输入验证：运行请求中格式错误的 JSON images、audio、videos 和 input_files 在分派之前会被 HTTP 422 拒绝，而不是在运行中消失或失败，并且格式错误或标量根 output_schema 会被拒绝，而不是被静默删除。 (#11005)
  • CodexAgent：在流式和非流式运行中，失败的工具调用（非零退出、declined 命令、MCP 工具错误）存储为 tool_call_error=True 而不是 null。 (#10958)
  • CodexAgent：当线程无法恢复时，重播到新线程的历史记录现在包括早期的工具调用及其结果，每个被截断为 2000 个字符，而不仅仅是用户和助理文本。 (#10909)
  • 外部代理恢复：使用 stream=false 提交的运行上的 /resume 报告运行的真实状态并表示轮询运行端点，而不是在运行仍在运行时声明运行已完成。 (#10958)
  • 测试：部分工具碰撞测试不再依赖于 FastMCP 的工具命名。 (#10914)
