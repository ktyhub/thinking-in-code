mempalace v3.3.3

mempalace v3.3.3

错误修复

  • 安装回归 — mempalace-mcp 控制台脚本现在与 .claude-plugin/plugin.json 对它的引用一起在 pyproject.toml 中声明。在 v3.3.2 中，两者渐行渐远（plugin.json 在匹配的入口点落地之前发送了新的 "command": "mempalace-mcp" 表单），因此每个新的 pip install mempalace==3.3.2 都会生成一个 Claude Code 插件配置，指向未安装的二进制文件。 （＃1093，＃340）
  • 在克劳德代码 2.1.114 client 回归后恢复静默保存可见性 — 生产记录保存在本 PR 之前静默失败。 (#1021)
  • 对 status 路径元数据进行分页，以便大型宫殿不会超出 SQLite 变量限制。 （#851）
  • 解决了 Claude 插件 hook runner 跨平台/插件目录变化的问题；之前在 Windows 和某些 macOS 布局上出现问题。 (#942)
  • 具有 MEMPAL_PYTHON 覆盖路径的 .sh 挂钩的真实 python3 分辨率。 （#833）
  • 将可选的 wing 参数添加到 tool_diary_write / tool_diary_read 中，并在从停止钩写入时从 Claude 代码转录路径派生每个项目翼 - 来自不同项目的日记条目不再折叠到共享的默认翼中。 （#659）
  • 在 mempalace_search wing/room 中将空字符串视为“无过滤器”；默认使用 "" 填充每个可选参数的 LLM 代理不再被 must be a non-empty string 退回。 （＃1097，＃1084）
  • 扩展 _wing_from_transcript_path 以处理没有 -Projects- 段的 Claude Code 项目文件夹（例如 ~/dev/<parent>/<project>、~/code/<project>）。项目名称现在源自编码文件夹的最终用破折号分隔的标记，因此使用 ~/Projects/ 之外的代码的 Linux 用户可以获得每个项目的日记范围，而不是落入 wing_sessions。 （#1145，#659 的后续）
  • mempalace_diary_read(wing="") 现在返回该代理写入的每个翼的日记条目，匹配#1097“空字符串，因为没有过滤器”模式。以前默认为 wing_<agent>，将挂钩写入项目派生翼的条目隔离。 (#1145)
  • mempalace mine 现在会跳过生成的 entities.json 文件，因此其内容不会重新摄取为项目内容。 (#1175)

改进

  • 确定性挂钩保存。 保存挂钩现在使用静默 Python API 路径，因此连续的挂钩调用会在热路径上产生可重现的结果和零数据丢失。 （#673）
  • **build_graph() 内具有写入无效功能的图形缓存 - 热路径调用不再根据请求重建宫殿图。 （#661）
  • mempalace init 实体检测大修。 规范项目名称现在来自包清单（package.json、pyproject.toml、Cargo.toml、go.mod），真实的人来自 git commit 作者，而不是从散文中推断出来。包括跨姓名/电子邮件别名的联合查找重复数据删除、保留 @users.noreply.github.com 人类的机器人过滤以及按贡献份额自动“我的”标记。 (#1148)
  • 正则表达式检测器的准确性。 CamelCase 提取，因此 MemPalace、ChromaDB、OpenAI 不会碎片化；更严格的版本/连字符模式可消除 context-manager / multi-word 误报；对话 ^NAME:\s 需要 ≥2 次点击，因此 Created: <date> 元数据停止将字段名称分类为人物；扩展了常见英语分词和描述符的停用词；高代词信号被归类为人称而不是倾倒到不确定。 (#1148)
  • 初始化 → 矿工连接。 确认的实体在初始化时合并到 ~/.mempalace/known_entities.json 中，矿工读取该实体以标记抽屉元数据以进行实体过滤搜索。以前 init 的输出不会被矿工消耗；每个项目的 entities.json 被保留作为审计跟踪。 (#1157)
  • 不区分大小写的项目重复数据删除跨清单、git 和 convo 源，因此同一项目名称的大小写变体会折叠到一个审阅条目中。 (#1175)

添加

  • i18n：白俄罗斯语翻译。 (#1051)
  • i18n：德语、西班牙语和法语语言环境的实体检测。 (#1001)
  • i18n：繁体+简体中文实体检测。 (#945)
  • mempalace init --llm：可选的法学硕士辅助实体分类。默认为本地 Ollama（零-API）；还支持任何 OpenAI 兼容端点（LM Studio、llama.cpp 服务器、vLLM、OpenRouter 等）和 Anthropic Messages API。与进度指示器交互运行； Ctrl-C 彻底取消并返回部分结果。对于正则表达式检测器难以处理的大量散文文件夹（日记、成绩单、研究笔记）很有用。仅选择加入 - 默认初始化路径保持为零 - API。 （＃1150）
  • Claude Code 对话扫描器。 ~/.claude/projects/<slug>/ 目录现在使用每个会话的权威 cwd 元数据贡献项目实体，避免 slug-decoding 歧义。 （＃1150）

已知 — 推迟到 v3.3.4

  • 当 hnsw:num_threads 在集合创建时未设置时，HNSW 并行插入 SIGSEGV (#974) — 正在运行中修复为 #976，等待针对开发进行变基。

安装

pip install --upgrade mempalace==3.3.3

有关历史版本，请参阅完整的 changelog。
