mempalace v3.8.0

v3.8.0 — 快速大型宫殿、精益 MCP 代理、可唤醒代理

在 3.8.0 中，大型宫殿变得快速而小型。 Chroma 元数据工具不再冷加载 HNSW，sqlite_exact 停止扫描和补充整个宫殿的常见读取，长时间运行的 Chroma 服务器停止在自己的写入上重建其 client，代理 MCP 会话不再导入它们从未使用的存储堆栈。代理还获得持久的 logstream watch 原语，因此协调可以唤醒安全带，而不是依赖重复的五分钟等待。

性能

  • 色度元数据读取跳过矢量索引。 在 1.7 GB / 165k 抽屉宫殿上，翼范围 list_drawers(limit=20) 从 2.31 s 和 1148 MB 峰值 RSS 下降到 0.01 s 和 86 MB。 list_drawers and tunnel reads now query Chroma’s SQLite metadata directly, push filters into SQL, and hydrate only the requested previews. (#2314)
  • sqlite_exact 常见读取不再遍历整个宫殿。 在实时的 167k 抽屉/166k 壁橱宫殿中，mempalace_status 从 6997 毫秒下降到 1045 毫秒，而温暖的 mempalace_search 从 6364 毫秒下降到 210–1600 毫秒。向量排名进行批量和缓存，然后对 top-k 文档进行水化，在 SQL 中对等式过滤器进行分页，对分类结果进行缓存，并且 wing / room / hall 获得索引生成的列，而无需重写 1.6 GB 嵌入表。 （＃2308，＃2311，＃2313）
  • 长期运行的 Chroma 服务器保持平稳，而不是在自己的写入中重新加载 HNSW。 在八次搜索中，测量的 RSS 从**之前的 **951 MB → 3522 MB 更改为之后的 **940 MB → 965 MB。替换的 clients 已关闭，而真正的外部数据库更改仍会触发重建。 (#2307)
  • 集线器代理的 MCP 会话很薄。 普通的 stdio 代理现在仅导入转发路径，并且仅在需要本地回退时才延迟加载完整服务器。代理会话的运行速度约为 17 MB，导入权重从大约 80 MB 下降到 24 MB — 在 50 个代理组中避免了大约 3.9 GB。 (#2312)

代理协调

  • mempalace logstream watch 提供持久的唤醒循环。 它拥有光标前进，支持重复类型过滤器、代理自排除、持久状态文件、空闲退出和 NDJSON 跟随模式。无游标首次运行从实时提示开始；重新启动可能会重播一个事件，但不会默默地错过一个事件。 (#2315)
  • 监控协议现在记录安全恢复光标。 跨副本事件按到达顺序附加，因此 since_event_id（不是挂钟时间戳）是可恢复的高水位标记。工具描述和共享协调协议现在将该规则放在代理使用的地方。 (#2315)

诚信与运营

  • sync --apply 不再删除其源文件无法访问的抽屉。 一个 Path.exists() 将保留与删除分开，因此不可读的目录、常规文件的路径组件以及未安装的卷都与删除相同 - 从已安装的卷中挖掘的项目可能会在该卷离开时将每个抽屉丢失到一个 sync --apply，然后返回空。现在，删除需要证实而不是探测：只有当宫殿仍然可以在同一目录中看到自己的来源（常规文件）时，才可以删除不在其路径中的文件。 Everything uncorroborated lands in a new unresolved bucket, never pruned and reported the way removals are. （＃2320）
  • EmbeddingGemma 无法通过 Apple Silicon 上的 CoreML 自动选择静默存储 NaN 或零向量。 自动模式避免受影响的提供者/模型对，并且每个向量在使用前都会检查有限的非零范数。 CUDA、DirectML 和其他模型保持不变。 (#2283)
  • FTS5 自动修复功能会在重建索引之前验证并修复内容表。 它尽可能使用 Chroma 的元数据副本作为权限，并在无法建立完整性时使用 declines 进行猜测。 (#2279)
  • 网格状态在传输中保持一致。 集线器发布无令牌、最后已知的良好状态快照，以便 mempalace_mesh_peers 可以报告来自 stdio 和 HTTP 的可达性和配置文件。 (#2309)
  • 文件系统边缘情况安全失败。 sweep 报告失败的统计信息，init 处理不可读的清单路径，split 拒绝 FIFO 或符号链接输出目标，而不是阻止或写入它们。 (#2244)
  • 发布的容器获得出处和 SBOM 证明。 发布文档还添加了 Termux PRoot 安装指南、KG 取代示例以及澄清的钩子写入路由范围。 （＃2097，＃2139，＃2059，＃2123） A big thank-you to everyone who contributed to this release.贡献者和首次贡献者的名单如下。
