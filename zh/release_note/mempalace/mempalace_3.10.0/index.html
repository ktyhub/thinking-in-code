mempalace v3.10.0

mempalace v3.10.0

代理可以采用更简单的方式：具有 Palace 查询语言的 3 工具 MCP 服务器、host:harness:project 身份的共享大脑规则以及可选的本机精确向量搜索。新安装遵循 XDG，存储修复关闭了静默写入丢失路径、macOS 完整性拒绝和几次挂起。

升级注意事项

  • mempalace rules 不再接受 --agent。 传递 --host、--harness 和 --project，然后重新渲染任何已安装的共享脑块。 (#2508)
  • get_collection() 拒绝 MemPalace 永远不会读取的名称。 除配置的抽屉集合或 mempalace_closets 之外的任何名称都会引发 CollectionNameMismatchError；维护脚本可以通过_skip_name_check=True。 (#2446)
  • 当没有给出光标时，MCP 事件列表首先返回最新事件。 mempalace_event_list 和 palace_coordinate 现在默认为最新优先，除非传递 since_event_id 或 order ； mempalace logstream list 和 Logstream.list_events() 仍然默认为最旧优先。 (#2497)
  • 新安装将配置和宫殿保留在 ~/.config/mempalace （或 $XDG_CONFIG_HOME/mempalace）下。现有的 ~/.mempalace 安装保持不变。 （＃148）

性能与架构（双轨 Rust 发动机）

  • 可选本机 Rust 精确矢量加速 (rust_exact)。 将现有的 SQLite 格式读入连续的浮点缓冲区，使用 Rayon 用于大型扫描，并发布 Python GIL。本地和外部写入 使本机缓存无效。加载是集合范围的并解码 blob 安全地；串行和并行扫描保留确定性的平局排序。 复杂的过滤器和缺少的本机扩展可以追溯到 Python。

  • 独立原生矢量 CLI 和可选轮子。 GitHub 版本包括本机轮子和平台可执行文件。 CLI 通过 --vector 或 stdin 接受 JSON 嵌入向量；它不嵌入 文本或要求 Python。可能仍然需要平台运行时库。

  • NumPy top-k 优化。 在对所选对象进行排序之前缓存向量范数和分区距离 结果，在截止点保留行顺序关系。

  • 只读搜索操作停止与宫殿作家租约竞争。 searcher.py 和 _open_search_collection 现在使用 read_only=True 显式打开集合。只读查询以 SQLite WAL 读取器模式连接，无需尝试模式初始化或写入器租用锁，从而允许 CLI 和代理搜索与活动后台 MCP 服务器或写入器进程同时运行，而无需引发 MineAlreadyRunning。

重构

  • MCP 服务器是一个包，而不是一个 8 000 行模块。 mempalace.mcp_server 保留公共导入路径（TOOLS、handle_request、main、每个 tool_* 处理程序以及进程全局名称测试 Monkeypatch）。实现存在于 mempalace/mcp_server/ 下的域文件中，因此 PR 可以针对抽屉、KG、协调、协议或 HTTP，而不会与一个上帝文件发生冲突。将 exec 片段放入包命名空间中 — 物理分割，而不是行为改变。
  • CLI 是一个包，而不是 4 000 行模块。 mempalace.cli 保留公共导入路径（main、每个 cmd_* 处理程序以及名称测试 Monkeypatch）。实现位于 mempalace/cli/ 下的域文件中，因此 PR 可以针对 init、mine、search、repair、logstream 或 argparse，而不会与一个 god-file 发生冲突。将 exec 片段放入包命名空间中 — 物理分割，而不是行为改变。
  • MCP 服务器测试按域划分。 tests/test_mcp_server.py 现在是 tests/mcp/（协议、读取、搜索、写入、日记、KG、防护、陈旧库），因此社区 MCP PR 不会在一个 8 600 行测试文件上发生冲突。共享助手住在 tests/_mcp_server_helpers.py 中。
  • Searcher 是一个包，而不是 2 200 行模块。 mempalace.searcher 保留公共导入路径（search、search_memories、SearchError 和帮助程序测试 Monkeypatch）。实现位于 mempalace/searcher/ 下（排名、过滤器、sqlite BM25、候选者、查询、CLI、渲染），因此 PR 可以针对一个接缝。将 exec 片段放入包命名空间中 — 物理分割，而不是行为改变。
  • Palace ops 是一个包，而不是 1 800 行模块。 mempalace.palace 保留公共导入路径（get_collection、mine_lock、mine_palace_lock、壁橱助手和名称测试 Monkeypatch）。实施位于 mempalace/palace/（集合、后端、壁橱、矿锁、矿井集）下，因此 PR 可以针对一个接缝。将 exec 片段放入包命名空间中 — 物理分割，而不是行为改变。

特点

  • 共享大脑规则使用 host:harness:project 身份，并且可以命名任一 MCP 工具表面。 mempalace rules 采用 --host、--harness 和 --project（稳定的小写标记）而不是 --agent，加上 --mcp full|light：full（默认）命名 45 工具 mempalace-mcp 工具，以及light 以相同的散文命名 palace_query / palace_exec / palace_coordinate 三合会。渲染的块让代理从当前工作区组成身份，在开始协作时扫描收件箱，而不是在会话开始时武装观察者，并且仅在要求监听时、在声明任务后或委派后才武装 logstream watch。 logstream watch --agent 现在默认将 --state-file 更改为 ~/.mempalace/watch/<agent>.json，并将 _ 加倍，并将 : 清理为 _，因此 Windows host:harness:project 身份不需要专用路径。 (#2508)
  • mempalace-light-mcp：具有 Palace Query Language 的 3 工具 MCP 服务器。 palace_query、palace_exec 和 palace_coordinate 通过单行 PQL 字符串 (FIND "oauth" IN backend/auth LIMIT 5) 或结构化字典涵盖搜索、分类、KG、图表、日记、抽屉、挖掘、隧道和 RFC 003 协调，大约是 45 工具模式的四分之一（10.6 KB 与 41.6 KB）。写入会经过相同的清理处理程序，因此抽屉文本会逐字保留；搜索排名不变，stdio为hub优先，--read-only拒绝
