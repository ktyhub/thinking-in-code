v3.12.0 小版本

MemPalace 3.12 保持源文本和字节完整，使中断的重新挖掘可恢复，并减少维护大型宫殿所需的工作。时间戳和项目翼现在在工具和挂钩中遵循相同的规则。反重力获得了视觉宫殿浏览器，最终版本审查修复了图形身份冲突、并发检查点重复、文档过滤和最新优先分页。

 10/14
v3.11.0 小版本

现在可以按照引导步骤审核和修复宫殿，并且 EmbeddingGemma 2 作为具有本机图像、音频和视频搜索功能的选择性嵌入器出现。每一座宫殿都会记录建造它的嵌入模型，并且拒绝用不同的模型打开。对话挖掘停止丢弃文本、状态、搜索、唤醒，中心矿井在大型宫殿上保持响应，3.11 审查的一轮正确性修复加强了元数据更新、恢复和 HTTP 验证。

 09/16
v3.10.0 小版本

代理可以采用更简单的方式：具有 Palace 查询语言的 3 工具 MCP 服务器、host:harness:project 身份的共享大脑规则以及可选的本机精确向量搜索。新安装遵循 XDG，存储修复关闭了静默写入丢失路径、macOS 完整性拒绝和几次挂起。

 08/31
v3.9.0 小版本

现在，一个中心为每个代理提供服务。 CLI 搜索重用实时宫殿索引，而不是加载另一个多 GB 的 HNSW 副本，并发搜索不再相互阻塞，技能优先的协调加上选择加入的释放意识使共享大脑舰队更容易安全操作。

 08/23
v3.8.0 小版本

在 3.8.0 中，大型宫殿变得快速而小型。 Chroma 元数据工具不再冷加载 HNSW，sqlite_exact 停止扫描和补充整个宫殿的常见读取，长时间运行的 Chroma 服务器停止在自己的写入上重建其 client，代理 MCP 会话不再导入它们从未使用的存储堆栈。代理还获得持久的 logstream watch 原语，因此协调可以唤醒安全带，而不是依赖重复的五分钟等待。

v3.7.1 修订

我们设计的建筑——侧翼、房间、壁橱、抽屉——终于完成了。壁橱是可搜索的索引层：紧凑的 AAAK 指针告诉搜索者要打开哪个抽屉。搜索首先（快速）搜索壁橱，然后从抽屉中获取完整的逐字内容。 壁橱是一个增强信号，而不是一个门——直接抽屉搜索总是作为地板进行。壁橱只能改善结果，而不能隐藏它们。
