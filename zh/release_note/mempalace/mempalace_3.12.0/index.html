mempalace v3.12.0

MemPalace 3.12 保持源文本和字节完整，使中断的重新挖掘可恢复，并减少维护大型宫殿所需的工作。时间戳和项目翼现在在工具和挂钩中遵循相同的规则。反重力获得了视觉宫殿浏览器，最终版本审查修复了图形身份冲突、并发检查点重复、文档过滤和最新优先分页。

升级注意事项

  • 需要 Python 3.10 或更新版本。 不再支持 Python 3.9；原生车轮使用 Python 3.10+ ABI。
  • 下一个矿井会重新读取它所涵盖的每个源代码一次。 规范化版本 3 修复了解析和字节保存问题。文本未更改的抽屉重用其存储的向量；未更改的文件保留其壁橱和 AAAK 摘要。磁盘上不再存在的源保留其现有抽屉。在升级之前备份一个大宫殿，并为第一次通过留出时间。 (#2813)
  • 在第一次走廊写入时，走廊会迁移到 SQLite。 hallways.json 以事务方式导入到 hallways.sqlite3 中，并保留在 .imported-* 名称下。升级共享宫殿的每个安装，因为旧版本不断写入旧的 JSON 文件。降级后，用 mempalace hallways --rebuild 重建衍生走廊。 (#2895)
  • 新时间戳带有明确的 UTC 偏移量。 传统的原始时间戳被读取为本地时间，就像它们被写入一样；现有元数据不会被重写。仅日期过滤器仍然意味着本地日历日期。项目翼还对 CLI、MCP、采矿和钩子使用一种子弹规则；过滤器继续查找存储的旧拼写。 （[#2851]（https://github.com/MemPalace/mempalace/pull/2851），[升级详细信息]（https://github.com/MemPalace/mempalace/blob/main/CHANGELOG.md#upgrade-notes））
  • 本地 HTTP 集线器无需令牌即可运行；网络访问需要一个。 普通环回绑定默认情况下保持无令牌，并进行浏览器源、主机和代理标头检查。每当代理或隧道将流量转发到集线器时配置令牌。现在每个 POST /mcp 都需要 Content-Type: application/json。
  • 将 closet_llm 环境变量从 LLM_ENDPOINT、LLM_MODEL 和 LLM_KEY 重命名为 MEMPALACE_LLM_ENDPOINT、MEMPALACE_LLM_MODEL 和 MEMPALACE_LLM_KEY。外部 LLM 端点需要明确同意。 mempalace.dedup和mempalace.onboarding被移除；使用 mempalace init --embedding-model ... 进行包埋机设置。 (#2773)
  • PQL 搜索过滤器使用大写关键字。 写入 FIND auth IN backend；小写 in、limit、source、since 和 before 保留在搜索文本中。 mempalace_search 还放弃了默认的距离截止；需要时显式传递 max_distance 。 (#2725，完整升级说明)

源保真度和可恢复写入

  • 对话挖掘按书面形式存储用户转动情况。 拼写更正默认处于关闭状态。 ChatGPT 导入遵循活动对话分支，重复导出将抽屉保留在每个源文件下，Claude 消息保留其空行，Gemini 文本部分按照其 clients 预期进行连接。删除或更改内容的解析步骤记录在 transforms 元数据中。 (#2790、#2796、#2800)
  • 非 UTF-8 源字节可以在挖掘和导出中幸存。 编码元数据允许精确重建。 MCP clients 接收与 JSON 兼容的显示文本，而带有 include_source_bytes: true 的 mempalace_get_drawer 将精确的抽屉源字节返回为 base64。 NUL 字符和单独代理在存储中往返。 (#2802)
  • 重新挖掘在修剪旧抽屉之前写入替换抽屉。 失败的写入留下可恢复的文本，下一个挖掘完成中断的发布。日记摄取使用相同的顺序；不可读的采矿状态现在会停止运行，而不是被误认为是空宫殿。 (#2798)
  • 抽屉更新保留它们替换的文本。 在替换之前，先前的文本和元数据会附加并同步到 drawer_revisions.jsonl；失败的修订写入会使原始抽屉完好无损。删除删除相应的修订历史记录。 PQL 抽屉和日记写入还保留文字转义、空格和数字内容。 （[#2866]（https://github.com/MemPalace/mempalace/pull/2866），[#2772]（https://github.com/MemPalace/mempalace/pull/2772））
  • mempalace export <dir> 将机翼和房间导出为 Markdown。 后端迁移和修复保留图形数据、壁橱和边车。 (#2779)

表演和大型宫殿

  • **sqlite_exact 写入停止扫描全文索引。 ** 在实测 336,000 行宫殿上，添加 50 个抽屉从约 10 秒下降到 10 毫秒。现有的宫殿在下一次可写打开时修复不匹配的全文行 ID。 (#2744)
  • 走廊更新触及受影响的翼并更改了记录。 在复制的 228,000 个抽屉的宫殿和 830,000 个走廊上，测量的翼重新挖掘时间从约 20 秒下降到 1-4 秒，峰值内存从 3.8 GB 下降到约 150 MB。首次导入 JSON 仍会产生一次性成本。 (#2895)
  • 索引最新优先读取可加快唤醒和浏览速度。 在测量的 150,000 个抽屉的 sqlite_exact 宫殿中，2,000 个抽屉的最近读取时间从 1.5 秒下降到 80 毫秒，或者从 5 秒下降到 60 毫秒。
