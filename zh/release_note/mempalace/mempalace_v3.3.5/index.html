mempalace v3.3.5

3.3.5 是一个修复版本。 没有新的面向用户的功能 - 该周期的精力投入到数据完整性、恢复和跨进程正确性上。如果您的宫殿在一次大地雷后遭遇过 Internal error: Error finding id，或者您的知识图三元组默默地消失在虚空中，或者您在 Windows/多租户主机上运行 - 这个版本适合您。 标题修复：

  • mempalace repair --mode from-sqlite 恢复卡在 apply_logs 上的宫殿。 当 ChromaDB 的 HNSW 段写入器楔入（上游和 #1308 中报告的损坏类）时，--mode legacy 和内联修复都调用 Collection.count() 作为它们的第一次读取 - 这正是引发的调用。旧的故障模式是修复打印 Cannot recover — palace may need to be re-mined from source files，即使 SQLite 表完好无损。新模式通过元数据段连接直接从 chroma.sqlite3 读取 (id, document, metadata)，永远不会针对损坏的宫殿打开 chromadb client，并在您配置的嵌入功能下将所有内容重新插入到新的宫殿中。在真实世界的 52,300 行腐败宫殿上进行了端到端验证。 (#1308)
  • 知识图中的两个静默丢失类现在是写入时错误。 具有 valid_to < valid_from 的三元组过去被持久存储但无法访问（时间过滤器与 as_of 不匹配）； add_triple() 现在拒绝写入时的反转间隔。转发到 SQLite 的日期字符串预先通过 sanitize_iso_temporal()（别名 sanitize_iso_date()）进行验证，它接受 YYYY-MM-DD 和规范的 UTC 日期时间（YYYY-MM-DDTHH:MM:SSZ / +00:00）并拒绝其他所有内容 - 像 "yesterday" 这样的自然语言输入不再默默地生成空结果集。 行为更改：在 3.3.4（"2026"、"2026-05"）中工作的部分日期输入现在出现错误；而是传递完整日期或规范 UTC 日期时间。 （＃1214，＃1164，＃1167，＃1374，＃1417）
  • EntityRegistry.save() 现在是安全崩溃的。 人员/项目地图是数月的挖掘数据，旧代码执行了非原子 Path.write_text() — 断电、OOM 或截断和完全刷新之间的 kill -9 会默默地擦除它（注册表的 load() 吞噬了 JSONDecodeError）。现在“保存”会将同级临时文件、fsyncs 和 os.replace()s 写入到位。在重命名返回之前，以前的注册表在发生任何崩溃时都保持不变。 （＃1215）
  • MCP tool_search 穿过批量挖矿后的 HNSW 刷新窗口。 CLI 挖矿后，ChromaDB 的 HNSW 段元数据可以在大约 30-60 秒内刷新；机翼范围的 MCP 搜索正在对整个窗口进行 Internal error: Error finding id 搜索。 tool_search 现在检测到此特定瞬态，删除宫殿的 MCP 本地缓存和共享后端缓存，休眠 2 秒，然后重试一次。成功的重试会标记为 index_recovered: true，以便调用者可以观察它何时触发。对更广泛的 #1315 集群的部分修复 - tool_check_duplicate 和其他索引接触工具仍然需要相同的包装器。 (#1396)
  • Windows 和多租户主机上的跨进程正确性。 ChromaBackend.close_palace() 现在可以正确释放 ChromaDB 的 rust 端 SQLite 文件锁 - 在 shutil.rmtree 不再因 SQLITE_READONLY_DBMOVED 失败后重新打开相同的宫殿路径。而且 MCP 服务器的 _kg 不再是模块级单例：在工具调用之间轮换 MEMPALACE_PALACE_PATH 的多租户主机现在通过惰性每路径缓存命中正确的 SQLite 文件。 （#1067、#1105、#1136、#1160）
  • Windows stdio 全面采用 UTF-8。 mempalace search > out.txt 和管道fact_checker 调用不再在进程边界处mojibake 西里尔文/CJK 抽屉文本。 mcp_server、hooks_cli 和 cli/fact_checker 的重新配置均相同。 (#1282)
  • 针对 monorepos 的 miner.detect_room 路由修复。 子字符串检查是双向的，因此任何作为房间名称子字符串的令牌都会匹配，反之亦然 - views/billing-page/src/Foo.test.tsx 路由到 interviews 房间，因为 "views" in "interviews" 首先匹配。现在使用分隔符限制的标记匹配（-、_、.、/）。 （＃1004，关闭＃1002）
  • mempalace compress 不再在约 32k 个抽屉以上的宫殿上崩溃。 抽屉获取现在已分页，反映了 miner.py 中的 #851 修复。 （＃1073，＃1107） 内部：测试可靠性也通过了 - tests/test_palace_locks.py 和 tests/test_chroma_collection_lock.py 从 fork 切换到 spawn 用于子进程生成（Python 3.13 + 多线程父 = fork 下的死锁，并且 macOS 禁止通过 CoreFoundation fork-without-exec），并且几个测试文件现在将 sqlite3.connect(...) 包装在contextlib.closing() 因此故障路径上的连接也会释放。 （＃1430，＃1431） 承诺没有动摇。每个词都准确存储。一切都保留在您的机器上。没有遥测。没有我们没有告诉您的云 API 的后备方案。每个版本都会增强已有的内容。
