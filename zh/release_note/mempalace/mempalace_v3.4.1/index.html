mempalace v3.4.1

v3.4.1 — 光标和反重力 IDE 支持

我们现在支持另外两个编辑器：带有本机钩子的 Cursor 插件，以及 一流的 Google Antigravity 支持 - 两者都将 MemPalace 的自动保存、会话启动调用和逐字记录挖掘功能带到了 Claude Code 和 Codex 已经发布的相同标准。两个可靠性修复完善了这个周期：embeddinggemma 不再 OOM 杀死大型重新嵌入，并且 migrate / repair 备份停止累积，直到填满磁盘。

特点

  • 光标 IDE 插件 (.cursor-plugin/)。 自动注册 mempalace-mcp 服务器、五个斜杠命令（/mempalace-help、/mempalace-init、/mempalace-mine、/mempalace-search、/mempalace-status）和模型可调用技能 - 无需手动 ~/.cursor/mcp.json 编辑。立即从本地克隆安装，或在发布后从 Cursor 市场安装。 (#1632)
  • 光标 IDE 挂钩 (stop / preCompact / sessionStart)。 每 N 个代理轮次后台自动保存，在光标压缩之前进行同步转录本挖掘，以及范围到工作区翼的会话启动内存调用。 hooks/cursor/install.sh（--scope user|project、--variant full|minimal、--dry-run、--uninstall）的一命令安装程序 — 幂等且无依赖性。
  • 一流的 Antigravity (Google) IDE 支持。 新的 .antigravity-plugin/ 软件包和幂等安装程序，将 MemPalace 注册为 Antigravity 插件 — MCP 服务器、技能和两个生命周期挂钩（Stop 上的后台挖掘、第一次模型调用时逐字内存注入）。 bash 3.2 / macOS 兼容，与 Claude Code / Codex / Cursor 挂钩共享相同的 ~/.mempalace/hook_state/ 目录，并尊重每个现有的终止开关。 （＃1633，＃1771）
  • **钩子的零配置解释器解析。**钩子现在从 mempalace-mcp 控制台脚本 shebang 解析 Python，然后再回退到 python3，修复了 uv tool install / pipx 布局下的静默无操作挖掘，其中系统 python3 无法导入 mempalace。

错误修复

  • embeddinggemma 不再 OOM 杀死批量重新嵌入。 ONNX 嵌入器对其整个输入运行一次传递，因此修复规模批次（约 5,000 个文档）分配的注意力缓冲区远远超出可用 RAM，并且内核默默地终止了该进程。 Embedding now runs in 32-doc sub-batches;每个文档的向量没有改变。 (#1770)
  • 保留备份以防止无限制的磁盘使用。 mempalace migrate 和 mempalace repair max-seq-id 每次运行都会编写一个全新的全尺寸备份，并且从未清理过 - 一座宫殿被发现有数百 GB 的过时备份，旁边还有数百 MB 的实时数据。新的 max_backups 设置（默认 10；0 保留全部）现在会在写入每个新备份后删除最旧的备份。 (#1697) 非常感谢为本周期做出贡献的每个人 - IDE 集成和其中一些修复都来自社区，包括许多首次贡献者。每个人都记在下面。
