zvec v0.7.0

🚀 Zvec v0.7.0 Release Notes

⚠️ 重大变更

  • C++ public API 切换到 Snake_case： 所有公共 C++ SDK 接口（Index、Collection 等）已从 PascalCase 移至 Snake_case。例如，Open() → open()、Search() → search()、Query() → query() 和 Insert() → insert()。 C++ SDK 用户在升级时需要更新其调用站点。 C API 和 Python API 名称保持不变。 (#683)

📦 新功能

  • IVF RaBitQ 索引： 添加了对 IVF 索引的 RaBitQ 量化支持，将 RaBitQ 扩展到更密集的向量检索场景。包括 C 和 Python 绑定和测试覆盖率。 (#540)
  • Turbo 预处理器框架： 在 Turbo 量化器模块中引入了可选的预处理器组件。快速哈达玛变换 (FHT) 旋转现已实施，并计划在未来版本中进行 OPQ 旋转和降维。 (#548)
  • Turbo PQ-INT8 量化器： 在 Turbo 框架中添加了基于 PQ 的 INT8 量化器，涵盖了 L2、余弦和内积距离度量，适合需要更高压缩的用户。 (#554)
  • Turbo 记录量化器： 将 INT8/INT4 记录量化器和 FP16 量化器迁移到 Turbo 框架中，为非 SIMD 目标添加可移植标量距离内核，并重新设计内核调度注册表，以便每种量化类型都映射到一个显式后端路径。 (#624)
  • 统一 uint7/uint8 量化： 公开统一 uint7 并添加统一 uint8 量化选项，为用户在召回与压缩之间进行交易时提供更大的灵活性。 (#608)
  • RaBitQ 运行时 AVX2/AVX512 调度： HNSW-RaBitQ 现在根据主机 CPU 在运行时选择 AVX2 或 AVX512 实现，从而无需在构建时对指令集进行硬编码。 (#632)
  • DiskANN 跨平台支持： DiskANN 从 Linux x86_64 扩展到 Linux ARM64 和 macOS ARM64 (Apple Silicon)。现在，它会选择最佳的可用 I/O 后端 — io_uring、libaio 或 pread — 并安全回退。 macOS 使用 F_NOCACHE 并禁用 DiskANN 文件的预读。 （[#557]（https://github.com/alibaba/zvec/pull/557），[#599]（https://github.com/alibaba/zvec/pull/599））
  • Vamana 两遍图形构建： 为 Vamana 添加了可选的两遍图形构建路径，提高了某些数据集上的图形质量。 (#634)
  • 从原始向量构建 HNSW 图形： HNSW 现在可以从提供商提供的原始向量构建图形，同时搜索仍然针对存储在索引中的向量运行，从而在存储的向量有损时提高图形质量。 (#657)
  • FTS ngram 分词器： 添加了用于全文搜索的 ngram 分词器，对于短文本、代码或拼音等字符级匹配很有用。 (#593)
  • 用于完整集合遍历的 DocIterator： 添加了 DocIterator，用于跨 C++、C 和 Python 进行流式完整集合遍历。迭代器会拍摄快照，因此以后的写入和删除都是不可见的，并且Python API支持with collection.iter_docs()。 (#597)
  • musllinux 轮子： 添加了针对 musl libc 环境的 x86_64 和 arm64 Python 轮子构建，以及 musl 线程堆栈、记录器单例生命周期和 DiskANN 堆过度读取的兼容性修复。 (#649)
  • 预构建的 SDK 发布管道： PR #628 提出了一个 GitHub 发布管道，每当v* 标签已推送。

🚀 性能改进

  • DiskANN 异步 I/O 重叠和动态 Beam： 重新设计了 DiskANN Beam 搜索，使 CPU 工作与磁盘 I/O 重叠，并引入了动态 Beam 宽度，减少了磁盘绑定工作负载的查询延迟。 (#617)
  • 更小的动态库： 通过控制符号可见性、启用死代码消除以及删除 protobuf/protoc 构建依赖项，减少了预构建动态库的大小。在 macOS ARM64 上，libzvec_c_api.dylib 从 37.21 MB 下降到 22.06 MB (-40.7%)，libzvec.dylib 从 36.96 MB 下降到 23.37 MB (-36.8%)。核心搜索代码仍然使用 -O3 进行编译，因此查询性能不受影响。 (#627)

🐞 错误修复

  • **索引和存储稳定性：**修复了前向存储写入器打开失败时的崩溃问题；启用崩溃恢复后优化，无需打开 WAL；持久保留仅删除写入段记录；处理 mmap 存储中的大型最终 IPC 块；崩溃恢复后清理孤立段目录；并在 Windows 上优化后清理了退休的段目录。 (#579、#600、#618、#645、#674、#676)
  • DiskANN： 将 DiskANN 正确连接到 zvec 核心库；使 Linux AIO 后备对于部分操作来说是安全的；修复了 add_vector 中的堆过度读取和 convert_pivot_data 中的偏移一问题。 （[#602]（https://github.com/alibaba/zvec/pull/602），[#615]（https://github.com/alibaba/zvec/pull/615））
  • Vamana / HNSW： Vamana 现在支持非对称查询指标；修复了 HnswExternalStreamerEntity 周围的问题；修复了 ARM NEON 上的 pq_int8 错误；和校正球体
