FastGPT v4.16.0

📦 升级指南

1.更新Agent-sandbox-proxy环境变量（任选）

4.16.0 需要依赖代理进行静态资源代理访问，如果网关支持 ws 和 http 同一个端口，则可以只开放一个端口。如果不支持，可以设置 PREVIEW_PORT 来设置 http 访问端口。

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

访问地址以 http:// 或 https:// 。单端口配置时，可以与 AGENT_SANDBOX_PROXY_URL 指向相同的域名和端口，但协议分别使用 HTTP(S) 和 WebSocket(S)。强烈建议配置的域名与 FastGPT 主站使用不同的来源。同源配置可以使这些脚本进入主站的同源安全边界，可以访问主站相关或接口。系统当前不会检查强制来源是否隔离。

可以通过访问：https://{{host}}/health来确认是否可访问。

2.更新fastgpt环境变量(实现沙盒的需更新)

在fastgpt-app和fastgpt-pro同时修改变量。

1.增加环境指标

# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. 废弃的沙盒环境变量

AGENT_SANDBOX_DISK_MB，E2B相关变量。

  1. 新增的可选沙盒配置戒指
变量 默认值 说明
AGENT_SANDBOX_CPU_COUNT 1 Agent Sandbox单实例CPU核数上限。
AGENT_SANDBOX_MEMORY_MIB 2048 Agent Sandbox单实例内存上限，单位MiB。
AGENT_SANDBOX_STORAGE_SIZE_GI 1 Agent Sandbox 存储容量，单位 Gi；用于 Sealos Devbox 存储上限，以及 OpenSandbox Kubernetes 模式下创建新 PVC。
AGENT_SANDBOX_SUSPEND_MINUTES 60 运行中的沙箱未激活多久后自动暂停，单位分钟。
AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS 7 已暂停 Sandbox 未激活多久后自动归档，单位天。

E2B Sandbox Provider 已移除。通过 E2B 的环境需要切换为 opensandbox 或 sealosdevbox，并删除 AGENT_SANDBOX_E2B_API_KEY。

FastGPT、fastgpt-agent-sandbox-proxy 和 fastgpt-agent-sandbox 的预览协议已同步变更。启用 Agent Sandbox 时必须使用本版本镜像，不支持新旧版本混合部署。

4.清理历史系统模型配置

本版本开始在系统模型初始化及保存时使用严格的Schema。模具版本保存的数字字符串、字符串形式的价格擦除或删除字段可能导致初始化校验失败。升级后请先执行干运行，查看需要处理的模型配置；干运行不会修改数据或刷新存储：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认invalidSamples中不需要人工处理的数据后，执行正式清理：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

清洗剪贴合法数字字符串转换为数字、将字符串形式的 priceTiers 转换为只读，并删除非法的任选数字。非法或删除的必填数字使用系统默认值：LLM 的 maxContext/maxResponse/quoteMaxToken 分别为 16000/16000/13000，Embedding 的 defaultToken/maxToken 分别为 500/3000，价格为 0。functionCall 保持任选，Embedding 删除的weight 补为0。

正式执行会统一写入数据并立即刷新系统模型缓存；即使没有记录需要更新，也重新构建运行时缓存。接口可安全重复执行；再次干运行时，wouldUpdate应为0。无法通过当前完整模型架构的记录不会写入，详情会全部返回在invalidSamples中。

5. 迁移 HTTP 工具数据

本版本将手动模式 HTTP 工具的备份参数改为标准 JSON 架构。升级前创建过手动 HTTP 工具的环境需要执行此迁移；OpenAPI 模式的 HTTP 工具迁移，脚本会自动跳过。

先执行dry-run，查看当前应用及历史版本中的待处理数据。dry-run 不会修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认结果后执行正式迁移：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

脚本会先按 HTTP 工具类型筛选应用，再根据这些应用的 appId 迁移的历史版本。仅 apiSchemaStr 不的手动模式会被处理，其他应用及 OpenAPI 模式不会修改。迁移按存在一批执行且可安全重试；结果返回中 total.changedDocumentCount 表示发现的待处理文档回复数，正式执行后可再次干运行，确认为 0。

6.迁移代理沙箱数据（较慢）

本版本将App Chat的Agent Sandbox从“每个对话一个实例”调整为“同一App、同一用户共享一个实例”。不同对话的文件仍分别保存在sessions/<chatId>目录中，已发布技能则统一保存在共享的projects目录中。

如果首先启用过 Agent Sandbox，必须按以下顺序完成旧 Workspace 迁移。未启用过 Agent Sandbox 的环境可以跳过本节。

先执行 dry-run，查看 beta6 Sandbox 字段归一化和旧 Skill Debug Chat 清理的待处理数。dry-run 不会创建资源、访问对象存储或修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

查看dry-run结果后执行正式迁移。正式迁移会先执行beta6归一化，并且只是在最后待处理数归零时，才在同一请求中继续 Workspace 存档：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

如果 failures 中仅包含 Sandbox source is missing or deleted，并且已确认对应的 App 或技能确实不再存在，可以显着地跳过这些残留的沙箱：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError 默认为 false，省略时保持严格迁移。该开关只跳过源删除或已软删除的整个包，不会归档、删除或迁移其中的 Sandbox；跳过明细通过 skippedCount 和 skipped 返回。存档、对象存储、Provider 和东方控制等其他错误仍会重启迁移。

迁移会先执行 V4.15.0-beta6 的完整前置逻辑：补齐旧沙箱的 sourceType/sourceId、清理残留字段、删除无法归属的资源，并清理残留 sourceType 的技能调试聊天三数据表及未、公开 Bucket 相邻旧。与 App 同 ID 的技能会跳过聊天清理。两类数据统计后重新汇总为 normalization.pendingCount；数量不为 0时不会进入 Workspace 归档。归零后直接归档全部旧 Workspace 并清理旧计算资源，再迁移技能，最后按 App、用户聚合到用户级 Sandbox。只要归档阶段失败，安装阶段就不会开始。新的 Sandbox 会在 Workspace 安装完成后存在暂停，首次使用时再按正常流程启动。脚本可安全重试，已完成的归档和迁移重复不会执行；迁移完成后会保留旧归档和旧 MongoDB 记录作为备份。
