openhuman v0.57.53

openhuman v0.57.53

稳定性&流量升级

此版本包含聊天、语音、身份验证和集成方面的生活质量改进和可靠性修复，以及代理运行时的一些大型构建块。享受更顺畅的旅程🎉

亮点

聊天体验和 UI 优化 ✨

聊天感觉明显更干净：预定的早间简报现在保持分组（标题+正文在同一个气泡中），批准提示通过不透明的警告表面更容易阅读，并且 GFM 降价表在代理输出中正确呈现。我们还修复了边缘情况 UI 问题，例如即使在短窗口上也可以访问侧边栏编辑器页脚，并改进了附件后备解析，以便文件标记不会泄漏到重建的消息中。
(#3851、#3790、#3857、#3863、#3795) — 谢谢@sanil-23、@discolotus、@YOMXXX、@hgunduzoglu 和@rsd-darshan！

语音和音频可靠性🎙️

语音设置和免提流程更加可靠：一键通命令再次正确列入许可名单，在安装真正完成之前无法启用本地 Whisper/Piper 提供程序（具有轮询 + 更好的进度状态），并且失效会话 TTS 401 现在被正确视为会话到期，而不是嘈杂的硬错误。
(#3842、#3861、#3750) — 谢谢@oxoxDev 和@YOMXXX！

身份验证、会话和更少的死胡同🔐

登录和会话处理变得更加智能：瞬态 /auth/me 打嗝不再阻止会话持久性，传统的 /auth Web 回调被接受并为 HashRouter 安全地重写，OpenRouter OAuth 现在使用环回侦听器的实际绑定端口（修复了“端口 3000 繁忙”的情况）。现在，多个 401 路径（集成 + 语音）将用户带入干净的重新登录流程，而不是默默地失败。
(#3746、#3800、#3904、#3749) — 谢谢@samrusani、@NgoQuocViet2001、@ly-wang19 和@oxoxDev！

提供程序、推理和路由升级 ⚡

一系列面向提供商的改进已落地：OpenAI 兼容的 HTTP 超时现在是可配置的（这样长推理轮次就不会被切断），Gemini 工具调用历史正确地保留了 thought_signature，并且像 /models 404s 这样的用户错误配置错误现在在源头进行了分类，并提供了可操作的提示。我们还添加了新的提供程序选项 - ModelScope 作为内置托管提供程序，OMLX 作为具有端点+密钥凭证的指定本地提供程序。
(#3864、#3770、#3769、#3773、#3862) — 谢谢@hgunduzoglu、@oxoxDev、@yrk111222 和@hliebscher！

代理：编排、子代理和上下文空间🤖

代理运行时进行了重大升级：事件驱动的潜意识触发管道引入了长期存在的协调器会话，工具输出压缩减少了上下文膨胀（具有可逆恢复），子代理现在默认是异步+可重用的（使用生命周期工具）。我们还改进了故障行为——代理级联现在会在第一次永久性推理故障时停止，并具有更清晰的根本原因，并且在具体指导下预先调度捕获本地上下文溢出错误。
(#3650、#3869、#3887、#3779、#3771) — 谢谢@senamakel、@sanil-23 和@oxoxDev！

内存和同步性能（和正确性）🧠

内存变得更快、更正确：语义召回再次对查询敏感，情景相关性避免了 O(n²) 热路径，块评分重复数据删除现在使用更便宜的哈希集。内存树密封路径更加并发，源同步 (ZZPH100​​ZZ) 和日历扇出使用有界并发来获得更好的吞吐量。在同步方面，Composio 增量同步现在集中在通用协调器后面（提供程序跨 Notion/GitHub/Linear/ClickUp/Gmail/Slack 迁移，并且 cap math 迁移到单一事实来源）。
(#3608、#3782、#3638、#3416、#3434、#3472、 #3852、#3860、#3873、#3874、#3924、#3937) — 谢谢@michaelk1957， @mysma-9403 和 @sanil-23！

技能、工具链和 Windows/Linux shell 质量 🧰

技能管理更加清晰：在会话中卸载技能现在会将其从实时目录中撤回，内置目录条目正确显示为已安装，并且社区技能下载现在通过每个条目的 sourceUrl 进行解析（对于仅限门户的源，故障更明显）。在 Windows 上，您可以选择在生成 shell 命令时抑制控制台窗口闪烁；在 Linux 上，AppImage 构建现在可以清理绝对 RPATH 和 libxdo 的硬保护捆绑，以防止启动时崩溃。
(#3745、#3656、#3844、#3747、#3776) — 谢谢@obchain、@YonganZhang 和@oxoxDev！

通知、cron、计费和“预期错误”卫生🧾

Cron 和计费路径现在表现得更加稳健：计划作业不会将失败/空运行发布到聊天中，晨间任务获取范围限定为 24 小时新近度窗口（扩展至 Todoist，具有固定的陈旧 slugs），并且根据选定的聊天模式层正确控制信用提示（因此 BYO 用户不会错误地获得“购买信用”提示）。通过正确分类预期的用户状态事件（计费状态 cron 洪水、磁盘满洪水、提供程序耗尽瞬时聚合、OpenAI OAuth token_expired 和凭证上下文保存），还减少了大量 Sentry 噪音。
(#3789、#3872、#3923、#3775、#3913、#3911、 #3663、#3803、#3674) — 谢谢@sanil-23、@oxoxDev、@Zhang 和@CodeGhost21！

特工世界和 Tiny Place 扩展包🌍

Agent World 持续增长：TinyPlace 现在拥有一个带有 Pixi 城市渲染器的专用 World 页面，并且通过 GraphQL 路由更多读取以减少扇出。还有一个精心策划的、对代理友好的 TinyPlace 工具界面，以及专用的 tinyplace 专家子代理、改进的提要排序以及在加密 DM 设置未完成时更清晰的消息传递用户体验。
(#3867、#3879、#3876、#3868、#3919) — 谢谢@senamakel和@Felyx-Fu！

桌面导航、反馈、渠道和入门 🧭

导航和核心 UX 得到了调整：聊天线程现在具有稳定的 /chat/:threadId 路由，并且提供商 Web 视图与线程路由解耦；针对现代 UI 更新了入门演练目标；完整的应用程序内反馈板已登陆（现在在整洁的侧边栏页脚中显示为“分享反馈”）。我们还在桌面上修复了端到端的 Discord 和 Telegram 消息传递，以及小但重要的 UI 正确性修复，例如接近小时边界的例行“下次运行”标签以及仅适用于活动用户的“清除应用程序数据”。
(#3896、#3944、#3834、#3945、#3794、#3758) — 谢谢@senamakel， @YellowSnnowmann 和@obchain！

国际化和兼容性修复🌐

i18n 得到了热烈的喜爱：内存同步审核面板现已完全本地化，AI 路由工作负载标签/描述/提示也已本地化（具有完整的德语覆盖），并且诸如 {providerName} 渲染之类的占位符替换错误在多个表面上得到了修复。我们还改进了旧版兼容性：旧的 RPC 方法名称通过别名进行处理，设置诊断面板现在一致地调用规范的 openhuman.* RPC 方法（包括 AgentBox 和工具策略诊断）。
(#3706、#3870、#3792、#3655、#3875、#3926、 #3927、#3928、#3930) — 谢谢@obchain、@hliebscher、@sanil-23、@Zhang、@YOMXXX、@hgunduzoglu 和@oxoxDev！

构建、CI、CLI 和操作强化🛠️

在幕后，CI 更精简、更可靠：PR CI 现在具有稳定的最终门和基于路径的智能跳过，遗留工作流程被修剪，并且取消现在可以可靠地终止长 Rust/Tauri 子流程。在 CLI/运行时方面，SIGPIPE 在 Unix 上恢复为默认值（不再出现管道损坏恐慌），Windows stderr 管道损坏恐慌受到严格保护，并且有一个新的线束缓存审核脚本用于安全实时 JSON-RPC 缓存诊断。
(#3878、#3934、#3935、#3942、#3657、#3772、 #3895) — 谢谢@senamakel、@Zhang 和@oxoxDev！

消息、设置和边缘情况正确性 ✅

现在可以更优雅地处理一组尖锐的情况：本地会话中的托管嵌入现在提示登录（带有本地化指导），LM Studio 嵌入错误配置会报告所提供的模型名称以帮助您选择正确的 ID，并且设置面板不再因调用未注册的 RPC 方法而中断。我们还改进了空响应 UX 副本，因此当该选项不存在时，托管路由用户不会被告知“检查本地提供商”。
(#3858、#3841、#3415) — 谢谢@YOMXXX、@sanil-23 和@CodeGhost21！
