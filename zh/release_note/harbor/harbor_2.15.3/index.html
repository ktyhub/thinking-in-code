harbor v2.15.3

[!警告] 重大更改：默认情况下会阻止指向内部地址的 Webhook

GHSA-2phj-cp9f-qq6w 的修复会阻止 webhook 和 Slack 传送到私有、环回、链接本地和其他非公共地址。这包括解析为它们的主机名，例如 *.svc.cluster.local。升级后，到内部端点的现有 Webhook 无法传送，并且新的 Webhook 会被拒绝。

要再次允许它们，请在核心和作业服务上设置选择退出：

  • harbor.yml：network.allow_private_network_access: true，然后./prepare并重新启动
  • 头盔：将 {name: HARBOR_ALLOW_PRIVATE_NETWORK_ACCESS, value: "true"} 添加到 core.extraEnvVars 和 jobservice.extraEnvVars

这将完全禁用保护。仅当您 trust 所有项目管理员并在网络级别阻止 169.254.169.254 时才使用它。

[!警告] 重大更改：强制执行内容 trust 时，对未签名图像进行签名失败

GHSA-wrw5-gmvj-gf23 的修复删除了基于用户代理的豁免，允许 cosign 和 notation 提取未签名的图像。在仅允许签名图像的项目中，新的未签名图像上的 cosign sign 和 notation sign 现在会失败并显示 412 Precondition Failed。已经有签名的图像不受影响。

要允许再次签名 clients，请在 core 上设置 CONTENT_TRUST_LEGACY_SIGNER_PULL_ENABLED=true。该值必须恰好是 true。

  • 头盔：将其添加到core.extraEnvVars
  • harbor.yml 安装：没有 harbor.yml 选项。将其添加到common/config/core/env并重新启动。重新运行 ./prepare 将覆盖该文件。

豁免仍然是 client 的用户代理，但仅适用于具有项目推送权限的用户或机器人。阻止易受攻击的镜像的项目没有选择退出的权限：签名的 client 无法再提取漏洞策略阻止的镜像。

[!警告] 已知问题：特定注册表的推送复制失败，例如 AWS ECR（GHSA-wjpm-hv5w-gxr6 回归）

GHSA-wjpm-hv5w-gxr6 的安全修复程序根据静态配置的注册表端点 (c.url) 严格验证了上传位置标头。由于 AWS ECR 适配器配置 API 控制平面终端节点 (https://api.ecr..amazonaws.com)，而请求被重写到数据平面主机 (.dkr.ecr..amazonaws.com)，因此 ECR 的响应 Location 标头作为跨源目标被拒绝。

解决方法/解决方案：

PR #24113 中已提供修复，并将在即将发布的补丁版本中发布。 如果您的环境依赖于推送复制，我们建议将升级推迟到下一个补丁发布或直接应用补丁。
