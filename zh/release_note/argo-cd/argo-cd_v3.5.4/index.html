argo-cd v3.5.4

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.4/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.4/manifests/ha/install.yaml

发布签名和出处

所有 Argo CD 容器映像均由 cosign 签名。 为符合 SLSA 3 级规范的容器映像和 CLI 二进制文件生成来源。有关如何验证的信息，请参阅文档。

Changelog

安全修复

  • 关键：Kustomize 远程引用可以在存储库服务器中运行命令 (GHSA-9v9p-x54c-58gc)
  • 关键：Kustomize Helm 配置主目录可以在存储库服务器中运行命令 (GHSA-fw5c-w8rc-j7fx)
  • 严重：Jsonnet 导入可以从存储库服务器读取文件 (GHSA-m3vr-7329-44ww)
  • 严重：PreDelete/PostDelete 资源挂钩绕过了 AppProject 限制（GHSA-fmxq-cgp8-87wp、CVE-2026-77459）
  • 高：可以通过并发请求绕过登录失败率限制（GHSA-4439-h7jw-5cjj、CVE-2025-61560）
  • 高：通过 SSH Git 存储库上的存储库代理 URL 进行命令注入（GHSA-j6cw-g6p4-7hch、CVE-2026-55797）
  • 中等：启用任何命名空间中的应用程序时，扩展代理 RBAC 会忽略应用程序命名空间 (GHSA-g3ff-q88g-chrj)
  • 中等：过大的 OCI 清单可能会耗尽存储库服务器内存 (GHSA-w996-f2wq-x9c6)

潜在的重大变化

  • 呈现 Helm 图表的 Kustomize 构建不再遵循 helmGlobals.configHome。普通的 http、https 和 oci 图表存储库仍然有效。依赖于从该目录注册的 Helm 插件的构建不会 (GHSA-fw5c-w8rc-j7fx)。
  • 大于 4 MiB 的 OCI 清单现已被拒绝 (GHSA-w996-f2wq-x9c6)。
