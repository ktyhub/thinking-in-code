ppt-master v6.7.2

修订 发布时间2026年10月17日 来源hugohe3/ppt-master 英文原文

ppt-master v6.7.2

补丁发布：通过对问题历史记录的审核进行修复。其中大多数会阻止工具在报告成功时丢失、覆盖或重写内容。

安装与启动

  • 仅技能安装会再次在工作文件夹中创建项目（703aa72f，#144）。自 v6.3.0 起，project_manager.py init 就根据已安装的技能放置了项目。对于 npx skills 或插件安装，这意味着 .agents/projects/ 或插件缓存，更新可以替换它们。在存储库中签出没有任何变化。
  • 在 Windows 上，从不启动的 python3（WindowsApps 存根退出 9009 且没有输出）不再被视为完整性保护故障；代理首先使用 python 重试（e1b58732，#142 的后续操作）。

源码转换和导入

  • PDF：删除了针对一份样本论文编写的四个表格重写。他们从硬编码符号中重新派生变量类别、替换标题、删除行并发明了相关列。提取的细胞现在保持提取状态 (3aa2ec62)。
  • HTML：页面通过 BOM 及其字符集声明而不是强制的 UTF-8 进行解码，因此 <meta charset="gbk"> 页面不再作为替换字符出现。报告猜测的编码 (34d88c1a)。
  • Web：一批具有相同标题的页面获得 Report.md、Report_2.md，而不是相互覆盖 (e847939c)。代码围栏显示 <body> 的原始 .md URL 保持 Markdown，而不是简化为示例 (6a92c1fd)。
  • 导入源：GB18030 或其他非 UTF-8 编码中的 .txt 源将被解码而不是被替换 (39b470fe)。具有相同文本但不同伴随图像 (<stem>_files/) 的 Markdown 不再被视为重复项并被删除 (104bc3c9)。
  • PPTX 导入：b="true" / i="true" 现在以粗体和斜体导入，就像 "1" 已经做的那样 (8bdf440c)。页面类型分类匹配整个单词，因此“卡塔尔”或“部门”不再读作问答或章节页面 (c0ce2420)。

实时预览编辑器

-“全部保存”拒绝将暂存的编辑重播到暂存后更改的 SVG 上，从而使暂存时出现错误。之前，他们降落在现在位于该位置的元素上 (05e627cb)。

  • 保留以 _edit_ 开头的用户 ID，并且在移动行时正确解析 dy=".5" 样式的数字 (264bd669)。

导出、完成和检查

  • Arial Unicode MS 和 Monotype Corsiva 等比例字体不再采用等宽字体 (c2668566)。
  • 用单引号 preserve-color 或 stroke='currentColor' 标记的图标和插图保持其颜色和样式（05cf79cd、0cdf8765）。
  • 检查器不再无法检查可见文本为 class=…、onload=… 或 @import … 或带有 data-class 属性的幻灯片。真正的 class、事件和 CSS 导入使用仍然失败（8f00128e、923a5360）。

图片、旁白和视频

  • 名为 hero.v2.png 的清单图像不再覆盖 hero.png (e9676c5a)。
  • 图片搜索按全字排名：必填“伊朗”不再接受“地拉那”，过境处罚不再点击“商业”或“小道”（d4ac79df、b827c5ce）。
  • 页面字幕和注释遵循幻灯片 9 和幻灯片 99 (1036fd53) 之后的数字幻灯片顺序。旁白保留 #1 revenue grew 等行，并仅跳过真正的 Markdown 标题 (06008e8e)。

文档

  • 常见问题解答不再承诺 Keynote、LibreOffice 和 WPS 中的像素相同图表； Microsoft PowerPoint 是验证目标 (ac16c041)。
