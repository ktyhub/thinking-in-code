opentelemetry-java v1.68.0

小版本 发布时间2026年11月6日 来源open-telemetry/opentelemetry-java 英文原文

opentelemetry-java v1.68.0

API

  • 添加空保护和 API 使用日志记录，用于跟踪、指标、传播和上下文 API（#8913、#8968）
  • 添加稳定的 io.opentelemetry.api.impl.Base16EncodingUtils 和 TemporaryBuffers 实用程序（#8929、#8955）
  • 修复上下文 APIs 中无法编译的 Javadoc 示例 (#8934)

孵化

  • 避免 DeclarativeConfigProperties.toMap() 中的错误类型警告（#8921）

扩展

  • 跟踪传播器：处理 Jaeger 标头中格式错误的 URL 转义 (#8912)
  • 跟踪传播器：在多标头传播字段中包含 B3 调试标头 (#8930)
  • 跟踪传播器：修复 Jaeger 标头中的十六进制标志解析（#8975）

SDK

  • 从资源和重试代码中删除跨模块内部实用程序依赖项（#8916）
  • 添加由跟踪器、仪表和记录器提供商共享的实验性 SdkResourceProvider 支持 (#8865)

痕迹

  • 保留具有属性或跟踪状态的无效跨度链接（#8917）

指标

  • 在 PeriodicMetricReader 中使用专用的导出工作线程，对并发刷新进行排队，并添加默认值等于导出间隔的 setExporterTimeout() (#8827)

出口商

  • 日志记录：当时间戳未设置时，回退到 SystemOutLogRecordExporter 中观察到的时间戳 (#8944)
  • OTLP：在不受支持的 Content-Encoding 上关闭 JDK HTTP 响应正文（#8962）
  • OTLP：在托管通道 gRPC 发送方中不区分大小写地匹配 Host 标头 (#8957)
  • OTLP：修复 java.net.URI 无法解析的主机的导出器指标服务器属性 (#8941)
  • OTLP：将原始异常传递给 JDK HTTP 发送方的错误回调 (#8963)
  • OTLP：在当前线程上重试 OkHttp gRPC 导出，以避免被有界执行器拒绝 (#8965)
  • OTLP：恢复 OkHttp gRPC 发送方中的每次尝试重试日志记录（#8967）
  • OTLP：正确的导出器构建器 Javadoc (#8996)
  • OTLP：接受 0 作为最大请求正文和消息大小没有限制（[#8945]（https://github.com/open-telemetry/opentelemetry-java/pull/8945））
  • OTLP：当 InternalTelemetryVersion 设置为 LATEST 时，gRPC 导出器内部遥测使用 rpc.status_code 而不是 rpc.response.status.code (#9007)
  • Prometheus：使示例 trace_id 和 span_id 优先于过滤属性（[#8959]（https://github.com/open-telemetry/opentelemetry-java/pull/8959））

扩展

  • 突破性 孵化器：将 SamplingIntent.create() 和 getTraceStateUpdater() 从 Function 更改为 BiFunction，接受最终的 SamplingDecision，并修复一致的采样极端情况 (#8952)
  • 自动配置：匹配包含下划线的配置键的环境变量（#8933、#8951）
  • 自动配置：通过 otel.metric.export.max.batch.size 支持 PeriodicMetricReader 批量大小 (#8935)
  • 自动配置：正确的 SPI Javadoc (#8900)

测试

  • 将流畅的度量点断言添加到 MetricAssert (#8994)
  • 将支持聚合临时性选择器的构建器添加到 InMemoryMetricExporter (#8993)
