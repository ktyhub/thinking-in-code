codebase-memory-mcp v0.4.7

修订 发布时间2026年3月12日 来源DeusData/codebase-memory-mcp 英文原文

codebase-memory-mcp v0.4.7

亮点

Go LSP 混合类型解析（实验性）

Go 的新 tree-sitter + LSP 混合引擎 带来了跨文件类型感知的调用解析 - 这是 codebase-memory-mcp 的首创。基于 C 的类型解析器 (internal/cbm/lsp/) 将树托管 AST 解析与轻量级类型注册表、范围跟踪器和 30,000 多个 Go stdlib 定义相结合，以解析跨包边界的方法调用、接口调度和结构字段访问。 这是一个基础步骤：在即将发布的版本中，相同的混合方法将扩展到 TypeScript、Python、Java 和其他语言。 关键部件：

  • lsp_bridge.go — CrossFileDef 结构和 RunGoLSPCrossFile CGo 桥
  • go_lsp_cross.go — 具有结构字段和接口方法丰富的跨文件定义索引
  • go_dep_registry.go — 用于依赖性感知解析的第三方 Go 模块解析器
  • lsp/go_lsp.c — C 型解析器，具有范围感知变量跟踪、方法集解析和通道方向推断
  • lsp/generated/go_stdlib_data.c — 30K+ Go stdlib 类型/函数定义，用于开箱即用的解析

.gitignore 和 .cbmignore 支持

索引器现在尊重 .gitignore 模式 — 生成的代码、构建工件和 gitignored 的供应商依赖项不再编制索引。这是自推出以来最受欢迎的功能。

  • 完整的 .gitignore 层次结构支持：嵌套 .gitignore 文件、.git/info/exclude、否定 (!)、globstar (**)、仅目录模式 (logs/)
  • .cbmignore — 一个新文件，在 .gitignore 之上堆叠额外的忽略模式，特定于 codebase-memory-mcp 索引
  • .cgignore 仍然支持向后兼容
  • 零文件句柄泄漏 - 自定义存储库匹配器立即读取并关闭文件，避免上游库的句柄泄漏（对于 Windows 至关重要）

内存安全修复

  • Swift 扫描器堆缓冲区溢出 — 供应的 Swift 树扫描器称为 calloc(0, sizeof(ScannerState))，分配 0 或 1 字节区域，然后向其写入 uint32_t （4 字节）。固定为 calloc(1, …)。由新的 AddressSanitizer CI 作业检测到。
  • Windows 上的文件句柄泄漏 — go-gitignore 库的 NewRepository 打开 .gitignore 文件，但从不关闭它们。替换为使用 os.ReadFile + strings.NewReader 的自定义 repoMatcher — 零泄漏句柄。修复 Windows CI 故障。

新功能

  • 持久配置存储 — SQLite 支持的 ConfigStore，用于服务器设置（auto_index、auto_index_limit、mem_limit）。 CLI 用于获取/设置/列表/删除的配置子命令。
  • 综合 —help / -h — 所有 14 个 MCP 工具均记录有参数模式和 JSON 有效负载示例
  • 符号链接跳过 - 符号链接文件和目录不再索引，防止图中出现重复节点
  • .worktrees 目录跳过 — git worktree 目录被排除在索引之外（感谢 @wassertim，#37）

错误修复

  • Cypher LIMIT 受到尊重 — query_graph 中的显式 LIMIT 子句现在受到 Cypher 查询的尊重，而不是默默地受到限制（感谢 @re-thc，#40）
  • 修复了 54 个 golangci-lint 问题 — 10 个文件中的 errcheck、gocognit、funlen、nilerr、gocritic、gosec、noctx
  • 扩展的硬编码忽略列表 — 添加了 28 个新的生态系统特定目录（.next、.nuxt、.terraform、zig-cache、.cargo、bazel-out 等）。通用目录（bin、build、out）已移至仅快速模式，以避免 Go/CMake/Maven 项目中的错误排除。 ＃＃ 基础设施
  • AddressSanitizer CI 作业 — 新的 test-asan 工作流程作业捕获 C 代码中的堆缓冲区溢出、释放后使用和其他内存错误
  • CI 试运行改进 — 跨平台测试的工作流程增强
