codebase-memory-mcp v0.12.0

#v0.12.0

了解 CBM Lens 和读取文档的代码图。

v0.12.0 是迄今为止最大的 codebase-memory-mcp 版本：自 v0.11.0 以来合并了 231 个拉取请求，其中 40 个来自社区。

四个标题定义了它。

  1. CBM Lens Beta：面向人类的代码图。 到目前为止，图的力量只能通过他们的代理到达人们手中。 Lens 是我们新的人机界面。它直接为您带来代码知识图谱。它包含在您已经运行的二进制文件中，并且仅侦听环回。它将源代码、图表、架构、索引覆盖范围和浏览器本地助手并排放置，它显示的每一个事实都说明了它的来源。 Lens 是建立在 @BernhardJackiewicz 的工作基础上的，他现在加入了该项目并拥有它。

  2. 文档加入图表。 到目前为止，图表在代码停止的地方停止。现在，文档注释、Markdown、reStructuredText、AsciiDoc 和 PDF 文档、架构决策记录、图表和 OpenAPI 规范都是其中的一部分。每个都链接到它所讨论的函数、类型和文件。代理现在可以遍历您的文档并找到页面描述的确切代码，然后从函数返回到解释它的每个页面。在朗斯，你也可以。链接在设计上是严格的：只有当引用准确命名一个定义时，它才成为边缘。尚未清除准确度栏的链接族将被计数和报告，而不会被猜测到图表中。

  3. 智能 CI：图形选择测试。 detect_changes 现在可以说出更改会影响哪些测试。它从差异中生成图表，遍历依赖于更改的代码的所有内容，并在这些路径末尾命名测试，每个测试都有其原因。当证据缺失或有疑问时，它会回答“运行一切”并说明原因；它永远不会悄无声息地缩小。 codebase-memory-mcp 自己的 CI 是第一个用户：拉取请求仅运行其更改涉及的测试通道，并且图表的测试选择在每个 PR 旁边运行。

  4. 基础设施即图中的代码。 Kubernetes 清单、Helm 图表、Flux 和 Argo CD、Compose 文件、Docker 文件以及部署它们的脚本、Makefile 和 CI 作业现在已链接起来。可以通过服务的工作负载、映像和 Docker 文件跟踪服务到容器运行的程序。

代码图本身也变得更加清晰：

  • C typedef、宏和枚举器拥有自己的标识。
  • 进程启动变成 SPAWNS 边缘。
  • 解决方案修复涵盖 C#、C++、TypeScript、Python、PHP、Rust 和 Go。

升级？ 升级后每个现有项目的第一个索引是一次完整重建。详细信息请参见升级说明。一些身份和默认设置也发生了变化；请参阅重大更改。

欢迎，@BernhardJackiewicz

@BernhardJackiewicz 加入 codebase-memory-mcp 作为 UI 的子系统所有者。 @BernhardJackiewicz 在 CBM 读取表面上构建了读取界面，后来成为 CBM Lens，并将其贡献给该项目（#2068；设计和跟踪于 #1964）。他还用新的演练和屏幕截图重写了自述文件的镜头部分（#2383）。从这个版本开始，他拥有 UI 子系统并负责 Lens。我们很高兴他加入。

亮点

  • CBM Lens Beta，一个面向人们的界面。 它通过您阅读的文件或您标记的代码、图邻域以及架构、路线和热点来探索项目。它还解释了索引覆盖范围，编辑项目的架构决策记录，并使用在浏览器中运行的模型回答有关您的选择的问题。它内置于二进制文件中：codebase-memory-mcp --ui=true (#2068)。
  • 文档加入图表。
    • 文档注释引用成为从文档定义到它们命名的代码的 MENTIONS 边缘。九种语言：C#、Go、Java、Kotlin、Rust、Perl、TypeScript/JavaScript、PHP 和 C（#2550、#2593）。
    • Markdown、reStructuredText/Sphinx、AsciiDoc/Antora 和 PDF 文档将其部分链接到它们引用的代码 (#2551)。
    • 要列出命名定义的每个部分，请通过 MENTIONS 运行 trace_path inbound。
  • 架构决策成为节点。 ADR 文件成为 ADR 节点，承载其状态、日期、决策者和决策本身。一条写有“Supersedes ADR-3”的记录获得 SUPERSEDES 优势 (#2551)。
  • 图表和 API 规格进入图表。
    • Mermaid、PlantUML、Graphviz、D2、draw.io 和 Excalidraw 图成为由 DIAGRAM_ARROW 边连接的 Diagram 和 DiagramElement 节点，无论嵌入到文档中还是独立存在。
    • 每个 OpenAPI/Swagger 操作都会成为一个 Route 节点，其标识与代码注册的路由相同 (#2593)。
  • 智能 CI，由图表驱动。
    • detect_changes 和 scope: "tests" 回答了哪些测试可以达到的更改以及原因。不完整的证据变成了“运行一切”答案，并给出了其原因（#2458）。
    • 新的遍历参数 edge_types、fixpoint 和 via 为任何存储库公开相同的依赖项遍历 (#2458)。
  • 从服务到代码。 run 模式下的 trace_path 行走服务 → 工作负载 → 镜像 → Docker 文件 → 程序，以及容器的环境。 deploy 模式遵循什么部署什么，而 topology 模式则引用什么（#2597）。
  • 更清晰的代码图。
    • C 和 C++ 获取 typedef 节点、不同的宏和枚举器标识，以及通过对象类型解析的成员访问（#2543、#2458）。
    • 每个 #if 分支、#[cfg] 或 Go 构建标记编写一次的定义现在是一个节点； C/C++ 平台文件（src/unix/、src/win/、arch/x86/ 等）保留自己的路径命名节点，与 Smart CI 遵循的共享 variant_key 相关（#2458、#2630）。
    • 流程发布变成了大约 30 种语言的 SPAWNS 边缘 (#2458)。
    • 完整捕获文档评论：Go 完整文档捕获从 35% 上升到 99.999%，C# 从 10% 上升到 99.8% (#2459)。
  • 多头指数在 client 截止日期后幸存。
