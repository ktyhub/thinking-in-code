druid 29.0.0

大版本 发布时间2024年2月21日 来源apache/druid 英文原文

druid druid-29.0.0

Apache Druid 29.0.0 包含超过 350 个新功能、错误修复、性能增强、文档改进以及来自 67 个贡献者的额外测试覆盖范围。

请参阅完整的更改 了解更多详细信息，包括错误修复。

在升级到 Druid 29.0.0 之前，请查看升级说明。 如果您要跨多个版本进行升级，请参阅升级说明页面，其中列出了最新 Druid 版本的升级说明。

# 重要功能、更改和弃用

本节包含有关新功能和现有功能的重要信息。

# MSQ 导出语句（实验性）

Druid 29.0.0 添加了对 MSQ 任务引擎导出语句的实验性支持。这允许查询任务通过 EXTERN 函数 将数据写入外部目标。

#15689

# SQL PIVOT 和UNPIVOT（实验性）

Druid 29.0.0 添加了对 SQL PIVOT 和 UNPIVOT 运算符的实验性支持。

PIVOT 运算符执行聚合并将行转换为输出中的列。以下是 PIVOT 运算符的一般语法：

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

UNPIVOT 运算符将现有列值转换为行。以下是 UNPIVOT 运算符的一般语法：

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

# 窗口函数中的范围支持（实验性）

窗口函数（实验性）现在支持两个端点均无界或均为当前行的范围。范围在严格模式下工作，这意味着 Druid 将使不支持的查询失败。您可以通过将上下文参数 windowingStrictValidation 设置为 false 来关闭范围的严格模式。

以下示例显示了具有 RANGE 框架规范的窗口表达式：

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

#15703 #15746

# 改进的 INNER 连接

Druid 现在支持 INNER join 的任意连接条件。任何无法作为连接一部分进行评估的子条件都将转换为连接后过滤器。改进的连接功能使 Druid 能够更有效地支持 Tableau 等应用程序。

#15302

# 改进并发追加和替换（实验）

您不再需要手动确定并发追加的任务锁定类型，并用 taskLockType 任务上下文替换（实验性）。相反，Druid 现在可以自动为您确定它。您可以将上下文参数 "useConcurrentLocks": true 用于各个任务和数据源，或者使用 druid.indexer.task.default.context 在集群级别启用并发追加和替换。

#15684

# double、float 和 long 数据类型的第一个和最后一个聚合器

Druid 现在支持本机和 MSQ 摄取规范以及 MSQ 查询中的 double、float 和 long 类型的第一个和最后一个聚合器。以前，它们仅支持本机查询。有关详细信息，请参阅第一个和最后一个聚合器。

#14462

此外，以下函数现在可以返回数值：

  • 最早和最早_BY *最新和LATEST_BY

您可以在摄取时将这些函数用作聚合器。

#15607

# 支持记录审核事件

添加了对记录审核事件的支持，并改进了审核的 REST API 端点的覆盖范围。 要启用日志记录审核事件，请在协调器和霸主或 common.runtime.properties 中将配置 druid.audit.manager.type 设置为 log。当您将 druid.audit.manager.type 设置为 sql 时，审核事件将保留到元数据存储中。

在这两种情况下，Druid 都会审核以下事件：

  • 协调员
    • 更新加载规则
    • 更新查找
    • 更新协调器动态配置
    • 更新自动压缩配置
  • 霸主
    • 提交任务
    • 创建/更新主管
    • 更新工人配置
  • 基本安全扩展
    • 创建用户
    • 删除用户
    • 更新用户凭据
    • 创建角色
    • 删除角色
    • 为用户分配角色
    • 设置角色权限

#15480 #15653

还修复了基本身份验证集成测试的问题，即不将日志保存到数据库。

#15561

# 启用空提取查询

MSQ 任务引擎现在默认允许空摄取查询。以前，摄取不生成数据的查询会因 InsertCannotBeEmpty MSQ 错误而失败。 有关更多信息，请参阅升级说明中的清空摄取查询。

#15674 #15495

在 Web 控制台中，您可以使用切换按钮来控制在摄取查询未生成数据的情况下摄取是否失败。

#15627

# MSQ 对 Google 云端存储的支持

MSQ 任务引擎现在支持 Google Cloud Storage (GCS)。您可以将持久存储与 GCS 结合使用。有关详细信息，请参阅持久存储配置。

#15398

#15276

# 更改了 Druid 分配每周分段的方式

当请求的粒度是一个月或更大但无法分配段时，Druid 会采取日分区的方式。 除非明确指定，否则 Druid 会跳过周粒度分段进行数据分区，因为这些分段与月末或更粗粒度的间隔不一致。

#15542

# 终止任务改进

改进的杀死任务如下：

  • 解决了自动终止功能无法遵守指定缓冲期的问题。当一个时间间隔内的多个未使用的段在不同时间被标记为未使用时，就会发生这种情况。
  • 您可以使用可选参数maxUsedStatusLastUpdatedTime提交kill任务。当设置为日期时间时，终止任务会在指定时间间隔内考虑标记为未使用的段，不迟于该时间。默认行为是终止时间间隔内所有未使用的段，无论段标记为未使用的时间如何。

# 将逻辑删除的 numCorePartitions 更改为 0

墓碑段现在有 0 个核心分区。这意味着可以独立地删除或删除它们，而不会影响同一共同分区空间中其他附加段的可用性。在此更改之前，删除分区空间中包含附加段的 1 个核心分区的逻辑删除可能会导致附加段不可用。

# 升级说明和不兼容的更改

# 升级说明

# 更改了本机查询的 equals 过滤器

包含数组的混合类型 auto 列上的 相等过滤器 现在必须作为其呈现类型进行过滤。这意味着，如果任何行是数组（例如，段元数据和 information_schema 将类型报告为某种数组类型），则本机查询还必须进行筛选，就好像它们是某种数组类型一样。

此更改会影响同时包含标量和数组的混合类型 auto 列。它不会影响 SQL，由于类型本身的呈现方式，SQL 已经存在此限制。

#15503

# 控制台自动为 MSQ 查询设置 arrayIngestMode

Druid 控制台现在在数据加载流程中配置 arrayIngestMode 参数，除非手动更新，否则其值可以在 SQL 选项卡中保留。因此，在 Druid Web 控制台中加载多值维度或数组时，请注意 arrayIngestMode 参数的值，以防止意外地将 MVD 和数组混合在数据源的同一列中。

#15588

# 改进并发追加和替换（实验性）

您不再需要手动确定并发追加的任务锁定类型，并用 taskLockType 任务上下文替换（实验性）。相反，Druid 现在可以自动为您确定它。您可以将上下文参数 "useConcurrentLocks": true 用于各个任务和数据源，或者使用 druid.indexer.task.default.context 在集群级别启用并发追加和替换。

#15684

# 启用空提取查询

MSQ 任务引擎现在默认允许空摄取查询。对于不生成任何输出行的查询，MSQ 任务引擎会报告 numTotalRows 和 totalSizeInBytes 的零值，而不是 null。以前，摄取不生成数据的查询会失败，并出现 InsertCannotBeEmpty MSQ 错误。

要恢复到原始行为，请将 MSQ 查询参数 failOnEmptyInsert 设置为 true。

#15495 #15674

# 开启总车道时默认启用查询请求排队

当查询调度程序线程少于服务器 HTTP 线程时，总laning 将打开。 这会保留一些 HTTP 线程用于非查询请求，例如运行状况检查。 之前的总车道将拒绝任何超过车道容量的查询请求。 现在，多余的请求将被排队，超时时间等于 MIN(Integer.MAX_VALUE, druid.server.http.maxQueryTimeout)。

#15440

# 更改了空数组或空数组列的存储方式

使用自动列索引器摄取的仅包含空或空数组的列现在存储为 ARRAY<LONG\> 而不是 COMPLEX<json\>。

#15505

# 更改了 Druid 分配每周分段的方式

当请求的粒度是一个月或更大但无法分配段时，Druid 会采取日分区的方式。 除非明确指定，否则 Druid 会跳过周粒度分段进行数据分区，因为这些分段与月末或更粗粒度的间隔不一致。

#15589

# 删除了 auto 搜索策略

从本机搜索查询中删除了 auto 搜索策略。将 searchStrategy 设置为 auto 现在相当于 useIndexes。

#15550
