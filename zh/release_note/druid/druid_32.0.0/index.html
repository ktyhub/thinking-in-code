druid 32.0.0

Apache Druid 32.0.0 包含超过 220 个新功能、错误修复、性能增强、文档改进以及来自 52 个贡献者的额外测试覆盖范围。

请参阅完整的更改 了解更多详细信息，包括错误修复。

在升级到 Druid 32 之前，请查看不兼容的更改。 如果您要跨多个版本进行升级，请参阅升级说明页面，其中列出了最新 Druid 版本的升级说明。

# 重要功能

本节包含有关新功能和现有功能的重要信息。

# 新霸主 API

用于将段标记为已使用或未使用的 API 已从协调器移至 Overlord 服务：

  • 将数据源的所有段标记为未使用： POST /druid/indexer/v1/datasources/{dataSourceName}

  • 将数据源的所有（非阴影）段标记为已使用： DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • 将多个段标记为已使用 POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • 将多个（非阴影）段标记为未使用 POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • 将单个段标记为已使用： POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • 将单个段标记为未使用： DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

作为此更改的一部分，相应的协调器 API 已被弃用，并将在未来版本中删除：

  • POST /druid/coordinator/v1/datasources/{dataSourceName}
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}

协调员现在呼叫霸主来满足这些请求。

# 多值字符串实时查询处理

实时查询处理在表达式处理期间不再将所有字符串视为多值字符串，修复了许多错误和意外失败。这还应该提高字符串列上表达式的实时查询性能。

此更改会影响实时段的 topN 查询，其中数据行隐式为空，例如 JSON 对象中缺少的属性。

在此更改之前，这些被处理为 [] 而不是 null，导致处理实时段和已发布段之间的不一致。处理段时，该值被视为 []，topN 会忽略它。发布后，该值变成了 null，topN 不会忽略这一点。相同的查询在持久化之前和之后可能有不同的结果

进行此更改后，topN 引擎现在在处理实时段时将 [] 视为 null，这与已发布的段一致。

此更改不会影响实际的多值字符串列，无论它们是否是实时的。

# MSQ 任务引擎查询中的联接提示

Druid 现在支持使用 MSQ 任务引擎的 SQL JOIN 查询的提示。这允许查询提供应在每个连接级别使用的 JOIN 类型的提示。连接提示会递归地影响子查询。
