druid 25.0.0

大版本 发布时间2023年1月4日 来源apache/druid 英文原文

druid druid-25.0.0

Apache Druid 25.0.0 包含 300 多个新功能、错误修复、性能增强、文档改进以及来自 51 个贡献者的额外测试覆盖范围。 有关其他详细信息，请参阅完整的更改集。

# 亮点

# MSQ 任务引擎现已准备就绪

用于基于 SQL 的摄取的多阶段查询 (MSQ) 任务引擎现已准备好投入生产。将其用于任何支持的工作负载。有关更多信息，请参阅以下页面：

  • 摄入
  • 基于 SQL 的摄取

# 简化的 Druid 部署

新的 start-druid 脚本极大地简化了在单服务器上部署 Druid 服务的任意组合。它预先打包了所需的配置，只需调用 ./start-druid 即可用于启动功能齐全的 Druid 集群。对于经验丰富的 Druids，它还可以完全控制运行时属性和 JVM 参数，以获得完全满足您需求的集群。 start-druid 脚本弃用了现有配置文件，例如 start-micro-quickstart 和 start-nano-quickstart。这些配置文件可能会在未来版本中删除。详细信息请参见单服务器部署。

# 字符串字典压缩（实验）

添加了对较小字符串列的前端编码字符串字典的支持，从而减少了段大小，并且大多数 Druid 查询的性能损失很小。 这可以通过将 IndexSpec.stringDictionaryEncoding 设置为 {"type":"frontCoded", "bucketSize": 4} 来启用，其中 bucketSize 是小于或等于 128 的 2 的任意幂。设置此属性指示索引任务使用指定存储桶大小的压缩字典写入段。

旧版本的 Druid 无法读取使用字符串字典压缩编写的任何段。 欲了解更多信息，请参阅正面编码。 https://github.com/apache/druid/pull/12277

# Kubernetes-本机任务

Druid 现在可以使用 Kubernetes 来启动和管理任务，从而无需中层管理人员。 要使用此功能，请在 Overlord 进程的扩展加载列表中启用 druid-kubernetes-overlord-extensions。 https://github.com/apache/druid/pull/13156

# Hadoop-3 兼容二进制文件

Druid 现在打包为 Hadoop-3 用户的专用二进制文件，其中包含 Hadoop-3 兼容的 jar。如果您的 Druid 集群不使用 Hadoop-3，您可以继续使用经典的二进制文件。

# 多阶段查询 (MSQ) 任务引擎

# 为 Docker 启用 MSQ

现在默认为 Docker 启用 MSQ 任务查询引擎。 https://github.com/apache/druid/pull/13069

# 查询历史记录

多阶段查询不再显示在查询历史记录对话框中。它们仍然可以在 最近的查询任务 面板中找到。

# CLUSTERED BY 列的限制

使用 MSQ 任务引擎提取数据时，CLUSTERED BY 子句中可以传递的列数现在限制为 1500。 https://github.com/apache/druid/pull/13352

# 支持字符串字典压缩

MSQ 任务引擎支持字符串字典的前端编码，以实现更好的压缩。通过将 indexSpec 设置为查询上下文中的有效 json 字符串，可以为 INSERT 或 REPLACE 语句启用此功能。 https://github.com/apache/druid/pull/13275

# 草图合并模式

工作人员现在可以收集关键统计数据，用于顺序或并行生成分区边界。在查询上下文中将 clusterStatisticsMergeMode 设置为 PARALLEL、SEQUENTIAL 或 AUTO 以使用相应的草图合并模式。有关详细信息，请参阅草图合并模式。 https://github.com/apache/druid/pull/13205

# 性能和操作改进

  • 错误消息：对于某些类型的不允许的 MSQ 警告，该警告现在显示为错误。 https://github.com/apache/druid/pull/13198
  • Secrets：对于包含具有敏感键的 SQL 的任务，Druid 现在在使用帮助正则表达式记录时屏蔽键。 https://github.com/apache/druid/pull/13231
  • 下采样精度：MSQ 任务引擎现在在对数据进行下采样时使用字节数而不是键数。 https://github.com/apache/druid/pull/12998
  • 内存使用：确定分区边界时，MSQ 使用的内部草图的堆占用空间现在上限为可用内存的 10% 或 300 MB，以较低者为准。此前，上限严格限制为 300 MB。 https://github.com/apache/druid/pull/13274
  • 任务报告：将字段 pendingTasks 和 runningTasks 添加到工作人员报告中。有关 Web 控制台的相关更改，请参阅查询任务状态信息。 https://github.com/apache/druid/pull/13263

# 查询

# JDBC 异步读取

当批量获取花费太长时间时，通过返回空批次来防止长查询的 JDBC 超时。使用异步模型与 JDBC 请求同时运行结果获取。 https://github.com/apache/druid/pull/13196

# 改进了检查 IN 过滤器值的算法

为了容纳由大型 IN 过滤器或作为 IN 过滤器下推的连接产生的大型值集，Druid 现在使用排序合并算法来合并较大值的集合和字典。 https://github.com/apache/druid/pull/13133

# 增强的查询上下文安全性

添加了以下配置属性，用于细化由 druid.auth.authorizeQueryContextParams 控制的查询上下文安全模型：

  • druid.auth.unsecuredContextKeys：不需要安全检查的查询上下文密钥的 JSON 列表。
  • druid.auth.securedContextKeys：需要安全检查的查询上下文键的 JSON 列表。 如果两者均设置，则 unsecuredContextKeys 充当 securedContextKeys 的例外。 https://github.com/apache/druid/pull/13071

# HTTP 响应标头

SQL 查询的 HTTP 响应现在可以正确设置响应标头，与本机查询相同。 https://github.com/apache/druid/pull/13052

# 其他改进

  • 新维度 taskActionType 可能采用 segmentAllocate、segmentTransactionalInsert 等值。此维度针对 task/action/run/time 和新的 批量段分配 指标进行报告。 https://github.com/apache/druid/pull/13333
  • 用于全局缓存查找的指标 namespace/cache/heapSizeInBytes 现在占 40 字节的 String 对象开销。 https://github.com/apache/druid/pull/13219
  • jvm/gc/cpu 已修复为报告纳秒而不是毫秒。 https://github.com/apache/druid/pull/13383

# 嵌套列

# 嵌套列性能改进

改进了 NestedDataColumnSerializer，不再为每行的缺失值显式地将空值写入字段写入器。相反，传递行计数器会被移至字段写入器，以便它们可以批量回填空值。 https://github.com/apache/druid/pull/13101

# 支持更多格式

Druid 嵌套列和关联的 JSON 转换函数现在支持 Avro、ORC 和 Parquet。 https://github.com/apache/druid/pull/13325 https://github.com/apache/druid/pull/13375

# 在取消嵌套之前重构数据源

当数据在处理过程中需要“展平”时，运算符现在会接收一个数组，然后将数组展平为 N（N=数组中的元素数量）行，其中每行都有数组中的一个值。 https://github.com/apache/druid/pull/13085

# 摄取

# 改进了对云对象的过滤

现在，您可以在 ioConfig.inputSource.filter 字段中使用 glob 语法停在任意子文件夹处，以便从云存储（例如 S3）进行本机批量摄取。 https://github.com/apache/druid/pull/13027

# 用于流式摄取的异步任务 client

现在，您可以通过在 tuningConfig 中将 chatAsync 设置为 true 来启用流管理程序和索引任务之间的异步通信。异步任务 client 使用自己的内部线程池，因此忽略 chatThreads 属性。 https://github.com/apache/druid/pull/13354

# 改进了对流式处理 JSON 数据的处理摄入

现在，您可以通过在输入格式规范中设置以下字段来更好地控制 Druid 如何读取 JSON 数据以进行流式摄取：

  • assumedNewlineDelimited 独立解析 JSON 的行。
  • 当发生解析异常时，useJsonNodeReader 在解析多行 JSON 事件时保留有效的 JSON 事件。 Web 控制台已更新以包含这些选项。 https://github.com/apache/druid/pull/13089

# 从空闲的 Kafka 流中摄取

当 Kafka 流变得不活动时，可以将从中提取数据的主管配置为停止创建新的索引任务。一旦流再次变为活动状态，主管就会自动恢复创建新的索引任务。在相应的 Supervisor 规范中将属性 dataSchema.ioConfig.idleConfig.enabled 设置为 true 或在霸主上设置 druid.supervisor.idleConfig.enabled 以启用此行为。详情请参阅以下内容：

  • 霸主配置
  • 主管规格 https://github.com/apache/druid/pull/13144

# Kafka Consumer 改进

您现在可以在实例化后配置 Kafka Consumer 的自定义反序列化器。 https://github.com/apache/druid/pull/13097

# Kafka 主管日志记录

Kafka 主管日志现在噪音较小。主管现在在 DEBUG 级别而不是 INFO 级别记录事件。 https://github.com/apache/druid/pull/13392

# 修复了霸主领袖选举

修复了由于锁重新获取问题导致霸主领袖选举失败的问题。现在，德鲁伊无法完成这些任务并清除所有锁，这样霸主领导人选举就不会被阻止。 https://github.com/apache/druid/pull/13172

# 支持内联 protobuf 描述符

添加了新的 inline 类型 protoBytesDecoder，允许用户内联传递 Protobuf 描述符文件的内容（编码为 Base64 字符串）。 https://github.com/apache/druid/pull/13192

# 重复通知

对于流式摄取，与已在队列中的通知相同的通知将不会排队。这将有助于减少通知队列的大小。 https://github.com/apache/druid/pull/13334

# 从流输入中采样现在遵循配置的超时

修复了当流没有可用记录时从流输入（例如 Kafka 或 Kinesis）进行采样时无法遵守配置的超时的问题。您现在可以设置条目迭代器返回结果的最长时间。 https://github.com/apache/druid/pull/13296

# 在 Overlord 交换机上恢复流任务

修复了在 Overlord 领导者向任务发出暂停后，流式摄取任务继续运行直至其持续时间结束的问题。现在，当 Overlord 切换发生在它向任务发出暂停之后，即使在 Overlord 重新选举之后，任务仍保持暂停状态。 https://github.com/apache/druid/pull/13223

# 修复了 Parquet 列表转换

修复了 Parquet 列表转换的问题，其中复杂对象的列表可能会意外地包装在额外的对象中，显示为 [{"element":<actual_list_element>},{"element":<another_one>}...] 而不是直接列表。这会更改结构化对象列表的 parquet 读取器的行为，以便与其他 parquet 逻辑列表转换保持一致。现在可以直接获取数据，更接近其预期结构。 https://github.com/apache/druid/pull/13294

# 为 flattenSpec 引入了树类型

在flattenSpec基础上推出tree型。如果需要简单的分层查找，tree 类型允许比 jq 和 path 解析类型更快的 JSON 解析。 https://github.com/apache/druid/pull/12177

# 操作

# 压缩

压缩行为已发生变化，以改善所需的时间和磁盘空间：

  • 当需要获取片段时，一次下载一个片段，并在 Druid 处理完毕后将其删除。这仍然需要时间，但可以最大限度地减少所需的磁盘空间。
  • 当不需要时，不要在主要紧凑任务上获取段。如果用户提供完整的 granularitySpec、dimensionsSpec 和 metricsSpec，Druid 会跳过获取段。 有关更多信息，请参阅有关压缩 和自动压缩 的文档。 https://github.com/apache/druid/pull/13280

# Supervisor 的空闲配置

您现在可以将 Supervisor 设置为空闲，这在释放插槽以使自动缩放更加有效的情况下非常有用。 要配置空闲行为，请使用以下属性：

物业 描述 默认
druid.supervisor.idleConfig.enabled （集群范围）如果是 true，如果输入流/主题一段时间内没有数据，supervisor 可能会变得空闲。 false
druid.supervisor.idleConfig.inactiveAfterMillis （集群范围）如果已从输入主题读取所有现有数据并且在 inactiveAfterMillis 毫秒内没有发布新数据，则 Supervisor 将被标记为空闲。 600_000
inactiveAfterMillis （个别主管）如果已从输入主题读取所有现有数据并且在 inactiveAfterMillis 毫秒内没有发布新数据，则主管将被标记为空闲。 否（默认== 600_000）
https://github.com/apache/druid/pull/13311

# 改进了主管终止

修复了某些瞬态期间延迟主管终止的问题。 https://github.com/apache/druid/pull/13072

# HttpPostEmitter 的退避

HttpPostEmitter 选项现在具有退避功能。这意味着如果您使用此选项进行日志记录，日志中的噪音应该更少，CPU 使用率也更低。 https://github.com/apache/druid/pull/12102

# 用于嵌套列的 DumpSegment 工具

DumpSegment 工具现在可以通过 --dump nested 选项用于嵌套列。 有关详细信息，请参阅转储段工具。 https://github.com/apache/druid/pull/13356

# 分段加载和平衡

# 批量段分配

Overlord 上的段分配可能需要一些时间才能完成，这可能会在任务等待分配段时导致摄取延迟。 批量执行段分配有助于提高性能。 有两个新属性会影响 Druid 执行段分配的方式：

物业 描述 默认
druid.indexer.tasklock.batchSegmentAllocation 如果设置为 true，Druid 会批量执行段分配操作，以提高吞吐量并减少平均 task/action/run/time。有关详细信息，请参阅批处理 segmentAllocate 操作。 false
druid.indexer.tasklock.batchAllocationWaitTime Druid 将第一个段分配操作添加到批处理后，直到执行该批处理为止的毫秒数。允许批量添加更多请求并提高平均段分配运行时间。此配置仅在batchSegmentAllocation启用时才生效。 500
除了这些属性之外，还有新的指标来跟踪批量段分配。有关详细信息，请参阅段分配的新指标。
有关详细信息，请参阅以下内容：
  • 霸王行动
  • 任务操作和批处理 segmentAllocate 操作 https://github.com/apache/druid/pull/13369 https://github.com/apache/druid/pull/13503

# 改进的缓存成本平衡器策略

cachingCost 平衡器策略现在的行为与成本策略更加相似。在计算将段移动到服务器的成本时，将执行以下计算：

  • 如果目标服务器正在提供服务，则减去分段的自身成本
  • 减去标记为要删除的段的成本 https://github.com/apache/druid/pull/13321

# 更快的段分配

您现在可以使用循环分段策略来加速初始分段分配。在协调器动态配置中将 useRoundRobinSegmentAssigment 设置为 true 以启用此功能。 https://github.com/apache/druid/pull/13367

# 默认对平衡段进行批量采样

批量采样现在是平衡期间对段进行采样的默认方法，因为当集群中存在大量使用的段时，它的性能明显优于替代方法。 作为此更改的一部分，以下内容已被弃用并将在未来版本中删除：

  • 协调器动态配置useBatchedSegmentSampler
  • 协调器动态配置percentOfSegmentsToConsiderPerMove
  • 旧的非批量采样分段方法

# 删除未使用的属性

未使用的协调器属性 druid.coordinator.loadqueuepeon.repeatDelay 已被删除。仅使用 druid.coordinator.loadqueuepeon.http.repeatDelay 为基于 HTTP 的分段加载队列配置重复延迟。 https://github.com/apache/druid/pull/13391

# 避免段过度复制

改进了检查服务器库存的流程，以防止段平衡期间段的过度复制。 https://github.com/apache/druid/pull/13114

# 在容器化部署中提供服务特定的 log4j 覆盖

提供了一个选项来覆盖服务级别目录中的 log4j 配置设置，以便它可以与基于 Druid-operator 的部署配合使用。 https://github.com/apache/druid/pull/13020

# 各种 Docker 改进

  • 更新了 Docker 以默认与 JRE 11 一起运行。
  • 更新了 Docker 以默认使用 gcr.io/distroless/java11-debian11 图像作为基础。
  • 启用 Docker buildkit 缓存以加快构建速度。
  • 将 bash-static 下载到 Docker 映像，以便可以执行需要 bash 的脚本。
  • 将构建器图像从 3.8.4-jdk-11-slim 更改为 3.8.6-jdk-11-slim。
  • 将 busybox 从 amd64/busybox:1.30.0-glibc 切换为 busybox:1.35.0-glibc。
  • 添加了对构建基于arm64 的映像的支持。 https://github.com/apache/druid/pull/13059

# 为各种输入源和格式启用清理器 JSON

将 JsonInclude 添加到各种属性中，以避免在序列化的 JSON 中填充默认值。 https://github.com/apache/druid/pull/13064

# 改进了启动时的直接内存检查

通过在 RuntimeInfo 中提供对 Java 9+ 的更好支持以及验证失败时更清晰的日志消息，改进了启动时的直接内存检查。 https://github.com/apache/druid/pull/13207

# 改进了 MarkAsUnusedOvershadowedSegments 职责的运行时间

通过迭代所有被遮蔽的段并将段标记为批量中未使用，改进了 MarkAsUnusedOvershadowedSegments 任务的运行时间。 https://github.com/apache/druid/pull/13287

# 默认基于 HTTP 的段发现和任务管理

默认段发现方法现在使用 HTTP 而不是 ZooKeeper。 此更新更改了以下属性的默认值：

物业 新默认值 以前的默认设置
druid.serverview.type 用于分段管理 http 批次
druid.coordinator.loadqueuepeon.type 用于分段管理 http 策展人
druid.indexer.runner.type为霸主 http远程 本地
要使用 ZooKeeper 而不是 HTTP，请将属性值更改回之前的默认值。这些属性的基于 ZooKeeper 的实现已被弃用，并将在后续版本中删除。
https://github.com/apache/druid/pull/13092

# 最终确定 HLL 和分位数草图聚合

HLL 和分位数草图的聚合函数在最终确定时返回草图或数字，具体取决于它们在本机查询计划中的位置。 在以下两种情况下，Druid 不再最终确定聚合器：

  • 聚合器出现在查询的外层
  • 聚合器用作表达式或最终字段访问后聚合器的输入 此更改使 HLL 和分位数草图的行为与 theta 草图保持一致。 要恢复旧行为，您可以在查询上下文中设置 sqlFinalizeOuterSketches=true。 https://github.com/apache/druid/pull/13247

# 仅当指定时，终止任务才将段标记为未使用

当您发出终止任务时，Druid 仅在明确指定的情况下将底层段标记为未使用。欲了解更多信息，请参阅API参考 https://github.com/apache/druid/pull/13104
