druid 28.0.0

大版本 发布时间2023年11月15日 来源apache/druid 英文原文

druid druid-28.0.0

Apache Druid 28.0.0 包含超过 420 个新功能、错误修复、性能增强、文档改进以及来自 57 个贡献者的额外测试覆盖范围。

请参阅完整的更改 了解更多详细信息，包括错误修复。

在升级到 Druid 28.0.0 之前，请查看升级说明 和不兼容的更改。

# 重要功能、更改和弃用

在 Druid 28.0.0 中，我们对查询进行了实质性改进，使系统更加兼容 ANSI SQL。这包括处理 NULL 和布尔值以及布尔逻辑的更改。同时，Apache Calcite库已升级到最新版本。虽然我们已经记录了已知的查询行为更改，但请仔细阅读升级说明 部分。在将应用程序推广到广泛的生产场景之前测试您的应用程序，同时密切监视查询状态。

# SQL 兼容性

Druid 继续使 SQL 查询执行与标准 SQL 的行为更加一致。但是，如果需要，可以使用功能标志来恢复旧的行为。

# 三值逻辑

当应用以下默认设置时，Druid 原生过滤器现在默认观察 SQL 三值逻辑（true、false 或 unknown），而不是 Druid 的经典二态逻辑：

  • druid.generic.useThreeValueLogicForNativeFilters = true
  • druid.expressions.useStrictBooleans = true
  • druid.generic.useDefaultValueForNull = false

#15058

# 严格布尔值

druid.expressions.useStrictBooleans 现在默认启用。 Druid 现在严格使用 1 (true) 或 0 (false) 处理布尔值。 以前，true 和 false 可以分别表示为 true 和 false 以及 1 和 0。 此外，Druid 现在为 True && NULL 等布尔比较返回空值。

如果您未在 runtime.properties 中显式配置此属性，集群现在将 LONG 类型用于任何摄取的布尔值以及用于转换和查询时间操作的布尔函数的输出。 有关更多信息，请参阅升级说明中的 SQL 兼容性。

#14734

# NULL 处理

druid.generic.useDefaultValueForNull 现在默认处于禁用状态。 Druid 现在区分空记录和空记录。 以前，Druid 可能会将空记录视为空或 null。 有关更多信息，请参阅升级说明中的 SQL 兼容性。

#14792

# SQL 规划器改进

Druid 使用 Apache Calcite 进行 SQL 规划和优化。从德鲁伊28.0.0开始，方解石版本已从1.21升级到1.35。此次升级修复了 Calcite SQL 规划中的许多错误。

# 动态参数

作为方解石升级的一部分，动态参数的类型推断行为发生了变化。为了避免任何类型干扰问题，请在 SQL 查询中将所有动态参数显式 CAST 作为特定数据类型。例如，使用：

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

不要使用：

SELECT (1 * ?)/2 as tmp

# 异步查询和深度存储查询

从深度存储查询 不再是实验性功能。当您从深层存储中查询时，可以查询更多数据，而无需扩展历史服务以容纳更多数据。要受益于深度存储查询所提供的空间节省，请配置加载规则以从历史服务中卸载数据。

# 支持多种结果格式

来自深度存储的查询现在支持多种结果格式。 以前，/druid/v2/sql/statements/ 端点仅支持 object 格式的结果。现在，结果可以以 resultFormat 参数中指定的任何格式写入。 有关 Druid SQL API 支持的结果参数的更多信息，请参阅响应。

#14571

# 扩大深度存储查询的访问范围

具有 STATE 权限的用户可以与状态 API 交互以进行深度存储的查询。以前，只有提交查询的用户才能使用这些 API。这使得 Web 控制台能够监控查询的运行状态。具有STATE权限的用户可以访问查询结果。

#14944

# MSQ 实时任务查询

MSQ 任务引擎现在可以在查询结果中包含实时分段。为此，请使用 includeSegmentSource 上下文参数并将其设置为 REALTIME。

#15024

# MSQ 对 UNION ALL 查询的支持

#14981

# 从多个 Kafka 主题摄取到单个数据源

现在，您可以使用单个主管将流数据从多个 Kafka 主题提取到数据源。 您可以使用正则表达式模式作为 IO 配置中 topicPattern 的值来配置主管规范的主题。如果您向 Kafka 添加与正则表达式匹配的新主题，Druid 会自动开始从这些新主题中摄取。

如果您为数据源启用多主题摄取，降级将导致 Supervisor 失败。 有关更多信息，请参阅在降级之前停止从多个 Kafka 主题摄取的主管。

#14424 #14865

# SQL UNNEST 和摄取扁平化

UNNEST 函数不再是实验性的。

Druid 现在支持基于 SQL 的批量摄取和深度存储查询中的 UNNEST，因此您可以轻松扁平化数组。有关详细信息，请参阅 UNNEST 和 取消列内数组的嵌套。

您不再需要包含上下文参数 enableUnnest: true 来使用 UNNEST。

#14886

# SQL UNNEST 的推荐语法

SQL UNNEST 的推荐语法已更改。我们建议对大多数查询使用 CROSS JOIN 而不是逗号，以防止出现优先级问题。例如，使用：

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

不要使用：

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

# 窗口函数（实验）

您可以使用 Apache Druid 中的窗口函数 根据行窗口中一行与同一窗口中其他行的关系来生成值。窗口是结果集中的一组相关行。例如，特定维度具有相同值的行。

使用 enableWindowing: true 上下文参数在查询中启用窗口函数。

#15184

# 并发追加和替换（实验）

Druid 28.0.0 添加了对并发追加和替换的实验性支持。 此功能允许您安全地替换数据源某个时间间隔中的现有数据，同时将新数据附加到该时间间隔。最常见的应用之一是在该区间的压缩已经在进行时将新数据附加到区间。 有关详细信息，请参阅并发追加和替换。

段锁定将被弃用并删除，以支持并发追加和替换，这在设计上要简单得多。通过并发追加和替换，Druid 不会因为主动实时摄取而锁定压缩作业。

# 用于追加和替换批量摄取作业的任务锁

追加批量摄取作业现在可以共享锁。这允许您在同一时间内部运行多个追加批处理摄取作业。替换批量摄取作业仍然需要独占锁。这意味着您可以在给定的时间间隔内运行多个追加批量摄取作业和一个替换批量摄取作业。

#14407

# 具有并发替换的流式摄取

使用 APPEND 锁从 Kafka 和 Kinesis 读取的流作业现在可以与使用 REPLACE 锁运行的压缩同时进行摄取。流作业的分段粒度必须等于或小于并发替换作业的分段粒度。

# 基于 SQL 的摄取

# 能够摄取 ARRAY 类型

基于 SQL 的摄取现在支持在 ARRAY 类型列 中存储 ARRAY 类型值，以及存储 VARCHAR 和数字类型数组。 以前，MSQ 任务引擎将 ARRAY 类型值存储为 多值维度，而不是 ARRAY 类型列。

MSQ 任务引擎现在包含 arrayIngestMode 查询上下文参数，该参数控制如何 ARRAY 类型存储在 Druid 段中。 将 arrayIngestMode 查询上下文参数设置为 array 以摄取 ARRAY 类型。

在Druid 28.0.0中，为了向后兼容，arrayIngestMode的默认模式是mvd，它仅支持VARCHAR类型数组并将其存储为多值维度。此默认值可能会在未来版本中发生更改。

有关如何迁移到新行为的信息，请参阅升级说明中 ARRAY 类型列的摄取选项。 有关 ARRAY 类型列的插入、筛选和分组行为的信息，请参阅数组列。

# 评估清晰度的函数

新的 SQL 和本机查询函数允许您评估两个表达式是否不同。 如果表达式具有不同的值或者其中之一为 NULL，则它们是不同的。 如果表达式的值相同或均为 NULL，则表达式不不同。

由于这些函数在用作比较运算符时将 NULL 视为已知值，因此即使一个或两个表达式为 NULL，它们也始终返回 true 或 false。

下表显示了等号 (=) 和 IS [NOT] DISTINCT FROM 之间的行为差异：

一个 乙 A = B A 与 B 没有区别
0 0 真实 真实
0 1 假 假
0 空 未知 假
空 空 未知 真实

#14943

# 改进的子查询护栏

您现在可以将 maxSubqueryBytes 护栏设置为以下之一：

  • disabled：默认设置。 Druid 不会对子查询可以生成的字节数应用护栏。

  • auto：Druid 计算用于结果物化的内存量，作为堆固定内存的一部分。
    在查询上下文中，Druid 使用以下公式来确定子查询可以生成的字节数上限：

    ((total JVM space - memory occupied by lookups) * 0.5) / maximum queries that the system can handle concurrently

  • INTEGER：用于具体化子查询结果的字节数。如果您了解查询模式并希望优化内存使用，请设置特定值。
    例如，将 maxSubqueryBytes 参数设置为 300000000 (300 * 1000 * 1000) 以实现 300 MB 的限制。 将 maxSubqueryBytes 参数设置为 314572800 (300 * 1024 * 1024) 以实现 300 MiB 限制。

# 升级说明

# 升级 Druid 段表

Druid 28.0.0 在 Druid 元数据表中添加了一个新列，需要更新该表。

如果 druid.metadata.storage.connector.createTables 设置为 true 并且元数据存储用户具有 DDL 权限，则段表会在启动时自动更新以包含新的 used_status_last_updated 列。升级不需要额外的工作。

如果不满足其中任何一个要求，则需要执行升级前步骤。您必须在升级到 Druid 28.0.0 之前进行这些更新，否则协调器和霸主进程将失败。

尽管您可以手动更改表以添加新的 used_status_last_updated 列，但 Druid 还提供了 CLI 工具来执行此操作。

#12599

在下面的示例命令中：

  • lib是Druid lib目录
  • extensions是Druid扩展目录
  • base 对应配置中druid.metadata.storage.tables.base 的值，默认为druid。
  • --connectURI 参数对应于 druid.metadata.storage.connector.connectURI 的值。
  • --user 参数对应于 druid.metadata.storage.connector.user 的值。
  • --password 参数对应于 druid.metadata.storage.connector.password 的值。
  • --action 参数对应于您正在执行的更新操作。在这种情况下，它是add-last-used-to-segments

# SQL UNNEST 的推荐语法

SQL UNNEST 的推荐语法已更改。我们建议对大多数查询使用 CROSS JOIN 而不是逗号，以防止出现优先级问题。例如，使用：

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

不要使用：

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

# 动态参数

Apache Calcite 版本已从 1.21 升级到 1.35。作为方解石升级的一部分，动态参数的类型推断行为发生了变化。为了避免任何类型干扰问题，请在 SQL 查询中将所有动态参数显式 CAST 作为特定数据类型。例如，使用：

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

不要使用：

SELECT (1 * ?)/2 as tmp

# 嵌套列格式

使用 Druid 28.0.0 创建的 json 类型列不向后兼容早于 26.0.0 的 Druid 版本。 如果您要从 Druid 26.0.0 之前的版本升级并且使用 json 列，请先升级到 Druid 26.0.0，然后再升级到 Druid 28.0.0。 此外，要降级到早于 Druid 26.0.0 的版本，在进一步降级之前，应使用 Druid 26.0.0 或 27.0.0 重新摄取在 Druid 28.0.0 中创建的任何新段。

从以前的版本升级时，您可以继续以向后兼容的格式（版本 4）编写嵌套列。

在经典的批量摄取作业中，将 formatVersion 包含在 dimensionsSpec 属性的 dimensions 列表中。例如：

      "dimensionsSpec": {
        "dimensions": [
          "product",
          "department",
          {
            "type": "json",
            "name": "shipTo",
            "formatVersion": 4
          }
        ]
      },

要设置默认嵌套列版本，请在公共运行时属性中设置所需的格式版本。例如：

# SQL 兼容性

从 Druid 28.0.0 开始，Druid 处理空值和布尔值的默认方式已经改变。

对于空值，Druid 现在区分空字符串和没有数据的记录，以及空数字记录和 0。
您可以通过将 druid.generic.useDefaultValueForNull 设置为 true 来恢复到以前的行为。

此属性会影响存储和查询，并且必须在所有 Druid 服务类型上设置，以便在摄取时和查询时都可用。将此设置恢复为旧值可恢复之前的行为，而无需重新引入。

对于布尔值，Druid 现在严格使用 1 (true) 或 0 (false)。以前，true 和 false 可以分别表示为 true 和 false 以及 1 和 0。此外，Druid 现在为 True && NULL 等布尔比较返回空值。

您可以通过将 druid.expressions.useStrictBooleans 设置为 false 来恢复到以前的行为。 此属性会影响存储和查询，并且必须在所有 Druid 服务类型上设置，以便在摄取时和查询时都可用。将此设置恢复为旧值可恢复之前的行为，而无需重新引入。

# NULL 过滤器

# ARRAY 类型列的摄取选项

从 Druid 28.0.0 开始，当您将查询上下文参数 arrayIngestMode 设置为 array 时，MSQ 任务引擎可以检测数组并将其摄取为 ARRAY 类型列。 arrayIngestMode 上下文参数控制 ARRAY 类型值如何存储在 Druid 段中。

当您将 arrayIngestMode 设置为 array（建议符合 SQL 要求）时，MSQ 任务引擎将所有 ARRAY 类型值存储在 ARRAY 类型列 中，并支持存储 VARCHAR 和数字类型数组。

为了向后兼容，arrayIngestMode 默认为 mvd。当"arrayIngestMode":"mvd"时，Druid仅支持VARCHAR类型数组并将其存储为多值字符串列。

当您将 arrayIngestMode 设置为 none 时，Druid 在尝试存储任何类型的数组时都会抛出异常。

有关如何通过基于 SQL 的提取来提取 ARRAY 类型列的更多信息，请参阅SQL 数据类型 和数组列。
