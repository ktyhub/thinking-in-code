Explore 视图是 Web 控制台的简单、无状态、SQL 支持的数据探索视图。它允许用户通过点和 click 交互和可视化来探索 Druid 中的数据（而不是编写 SQL 并查看表格）。这可以为新接触 Druid 的用户提供更快的价值实现时间，并且可以让 Druid 老手快速绘制他们关心的一些数据。

# 从深层存储查询（实验）

Druid 现在支持查询仅存储在深层存储中的段。当您从深层存储中查询时，您可以查询可用于查询的更大数据，而不必扩展历史进程以容纳更多数据。要利用潜在的存储节省，请确保将加载规则配置为不将所有段加载到历史进程中。

请注意，数据源的至少一部分必须加载到历史进程中，以便代理可以规划查询。但它可以是任何段。

# 架构自动发现和数组列类型

类型感知模式自动发现现已普遍可用。 Druid 可以确定您摄取的数据的架构，而无需您手动定义架构。

作为类型感知模式发现改进的一部分，数组列类型现在普遍可用。当您使用 auto 列类型的类型感知模式自动发现来摄取数据时，Druid 可以确定模式的列类型并将它们分配给这些数组列类型。

# 智能分段加载

协调器现在更加稳定且用户友好。在新的 smartSegmentLoading 模式中，它会动态计算多个配置的值，从而最大限度地提高性能。 协调器现在可以优先加载较新的段和完全不可用的段，而不是集群中已加载一些副本的段。它还可以重新评估先前运行中做出的决策并取消不再需要的操作。此外，由段平衡启动的移动操作不会与不可用段的负载竞争，从而减少集群中变化的反应时间并加速段分配决策。

此外，现在领导层变动的影响较小，即使在协调员运行期间进行重新选举，协调员也不会陷入困境。

最后，cost 平衡器策略现在表现更好，并且能够在单个协调器运行中移动更多段。这些改进是通过借鉴 cachingCost 策略的思想来实现的。我们建议使用 cost 而不是 cachingCost，因为 cachingCost 现已弃用。

# 新查询过滤器

Druid 现在支持以下过滤器：

  • 平等：代替选择器过滤器使用。它从不匹配空值。
  • Null：匹配空值。用于代替选择器过滤器。
  • 范围：过滤尺寸值的范围。用于代替绑定过滤器。它从不匹配空值

请注意，每当 druid.generic.useDefaultValueForNull=false 或 sqlUseBoundAndSelectors 在 SQL 查询上下文中设置为 false 时，Druid 的 SQL 规划器默认使用这些新过滤器代替旧的过滤器。

您可以使用这些过滤器来过滤 ARRAY 列上的相等性和范围，而不是仅使用先前的选择器和绑定过滤器来过滤字符串。

有关详细信息，请参阅查询过滤器。

# 子查询结果的护栏

用户现在可以通过在 Broker 的配置中设置 druid.server.http.maxSubqueryRows 或在查询上下文中设置 maxSubqueryRows 来添加防护栏，以防止子查询的结果超过设置的字节数。建议使用此护栏而不是基于行的限制。

# 改进的查询规划行为

如果 CLUSTERED BY 列包含降序，Druid 现在会失败查询计划。 以前，如果任何 CLUSTERED BY 列包含降序，查询将成功计划。

# 用于 SQL 架构迁移的新代理配置

您现在可以更好地控制 Druid 如何对段之间的架构更改做出反应。当较新的段引入不同类型时（例如，如果列以前包含 LONG 值而较新的段包含 STRING），这可以使查询更具弹性。

使用新的 Broker 配置 druid.sql.planner.metadataColumnTypeMergePolicy 来控制在遇到段之间的差异时如何计算 SQL 表架构的列类型。

将其设置为以下之一：

  • leastRestrictive：只有当所有段重新索引为新类型时，架构才会更新。
  • latestInterval：一旦具有新模式的第一个作业在数据的最新时间间隔中发布段，SQL 模式就会更新。

leastRestrictive 可以具有更好的查询时间行为，并消除使用 latestInterval 时可能出现的一些查询时间错误。

# 升级说明

# Hadoop 2 已弃用

Druid 使用的许多重要依赖库不再支持 Hadoop 2。为了让 Druid 保持最新状态并找到缓解安全漏洞的途径，社区决定从本版本开始不再支持 Hadoop 2.x 版本。从 Druid 28.x 开始，Hadoop 3.x 是唯一受支持的 Hadoop 版本。

如果您现在使用 Hadoop 2.x 进行摄取，请考虑迁移到基于 SQL 的摄取或本机摄取。如果无法迁移到 Druid 摄取，请计划在升级到下一个 Druid 版本之前升级 Hadoop 基础设施。

请注意，druid 27 与 Hadoop 2 不兼容。在升级到 27.0.0 之前，您必须将 Hadoop 集群升级到 3.x。或者，您可以通过从 druid 27 源工件中显式选择 Hadoop 2 配置文件来构建与 hadoop 2 兼容的发行版。

# 用于基于 SQL 摄取的工作器输入字节

每个工作线程基于 SQL 的摄取的最大输入字节现在为 512 MiB（之前为 10 GiB）。
