druid 0.22.0

小版本 发布时间2021年9月22日 来源apache/druid 英文原文

druid druid-0.22.0

Apache Druid 0.22.0 包含 73 名贡献者提供的 400 多个新功能、错误修复、性能增强、文档改进和其他测试覆盖范围。 有关其他详细信息，请参阅完整的更改集。

# 新功能

# 查询引擎

# 支持同一查询中的多个不同聚合器

Druid 现在可以使用通常与分组集一起使用的分组聚合器来支持多个 DISTINCT“精确”计数。请注意，这仅适用于精确计数 - 当 druid.sql.planner.useApproximateCountDistinct 为 false 时，并且可以通过将 druid.sql.planner.useGroupingSetForExactDistinct 设置为 true 来启用。 https://github.com/apache/druid/pull/11014

# SQL ARRAY_AGG 和 STRING_AGG 聚合器函数

添加了 ARRAY_AGG 聚合函数，以允许将列的值或不同值累积到单个数组结果中。此版本还添加了 STRING_AGG，它与 ARRAY_AGG 类似，只不过它使用提供的“分隔符”将数组值连接到单个字符串中，并且忽略空值。这两个函数都接受最大大小参数来控制最大结果大小，如果超过该值将会失败。有关其他详细信息，请参阅 SQL 文档。 https://github.com/apache/druid/pull/11157 https://github.com/apache/druid/pull/11241

# 按位数学函数表达式和聚合器

几个新的 SQL 函数用于执行“按位”数学运算（以及相应的本机表达式），包括 BITWISE_AND、BITWISE_OR、BITWISE_XOR 等。此外，还添加了聚合函数 BIT_AND、BIT_OR 和 BIT_XOR，以使用相应的按位函数累加列中的值。有关完整详细信息，请参阅 SQL 文档。 https://github.com/apache/druid/pull/10605 https://github.com/apache/druid/pull/10823 https://github.com/apache/druid/pull/11280

# 人类可读的数字格式函数

Druid 0.22.0、HUMAN_READABLE_BINARY_BYTE_FORMAT、HUMAN_READABLE_DECIMAL_BYTE_FORMAT 和 HUMAN_READABLE_DECIMAL_FORMAT 中添加了三个新的 SQL 和原生表达式数字格式函数，允许将结果转换为更友好的查询结果消费格式。有关详细信息，请参阅 SQL 文档。 https://github.com/apache/druid/issues/10584 https://github.com/apache/druid/pull/10635

# 表达式聚合器

Druid 0.22.0 添加了一个新的“原生”JSON 查询表达式聚合器函数，它允许您使用 Druid 原生表达式执行“折叠”（也称为“减少”）操作，以在任意数量的输入列上累积一些值。这为 Druid 聚合器中的操作增加了显着的灵活性，在很多方面与 Javascript 聚合器的功能类似，但以更安全的沙盒方式进行。 除了以前可能的“映射”（表达式虚拟列）、“过滤器”（表达式过滤器）和后转换（表达式后聚合器）功能之外，现在能够对输入列执行“折叠”的表达式也真正完善了本机表达式的功能。 由于它使用表达式，因此性能尚未达到最佳，并且尚未直接记录，但它是此版本中还添加的 SQL ARRAY_AGG、STRING_AGG 和按位聚合器函数背后的基础技术。 https://github.com/apache/druid/pull/11104

# SQL 查询路由改进

Druid 0.22 添加了一些新功能，为扩展编写者提供对 Druid 路由器和代理之间如何路由查询的增强控制。第一个向 Druid 路由器添加了新的 manual 代理选择策略，该策略允许查询手动指定应根据查询上下文参数 brokerService 将查询发送到哪些 Druid 代理到 druid.router.tierToBrokerMap 中定义的任何代理池（这对应于代理集的“服务名称”druid.service）。 第二个新功能允许 Druid 路由器解析和检查 SQL 查询，以便代理选择策略也可以用于 SQL 查询。这可以通过将 druid.router.sql.enable 设置为 true 来启用。这不会影响 JDBC 查询，它使用不同的机制来促进与单个代理的“粘性”连接。 https://github.com/apache/druid/pull/11566 https://github.com/apache/druid/pull/11495

# Avatica protobuf JDBC 支持

Druid 现在支持使用 Avatica Protobuf JDBC 连接，例如与 Avatica Golang 驱动程序 一起使用，并且具有与 JSON JDBC uri 不同的端点。

String url = "jdbc:avatica:remote:url=http://localhost:8082/druid/v2/sql/avatica-protobuf/;serialization=protobuf";

https://github.com/apache/druid/pull/10543

# 改进了查询错误日志记录

查询异常已从 WARN 级别更改为 ERROR 级别，以在日志中包含其他信息以帮助解决查询故障。此外，还添加了一个新的查询上下文标志 enableQueryDebugging，它将在这些查询错误日志中包含堆栈跟踪，以提供更多信息，而无需在 DEBUG 级别启用日志。 https://github.com/apache/druid/pull/11519

# 流媒体摄取

# Kafka 和 Kinesis 流摄取的任务自动缩放

Druid 0.22.0 现在为动态 Kafka 和 Kinesis 任务扩展提供实验性支持。所包含的策略由流延迟的定期测量驱动（基于 Kafka 的消息计数，以及 Kinesis 的消息迭代器和最旧消息之间的年龄差异），并将根据“延迟”量和多个配置参数调整任务数量。有关完整信息，请参阅 Kafka 和 Kinesis 文档。 https://github.com/apache/druid/pull/10524 https://github.com/apache/druid/pull/10985

# Avro 和 Protobuf 流式输入格式和 Confluence Schema 注册表支持

Druid 流摄取现在支持更新的 InputFormat 规范格式中的 Avro 和 Protobuf，该格式取代了旧版 Druid 流格式使用的已弃用的 firehose/parser 规范。除此之外，还支持从 Confluence 架构注册表 获取这些格式的架构。有关详细信息，请参阅数据格式文档。 https://github.com/apache/druid/pull/11040 https://github.com/apache/druid/pull/11018 https://github.com/apache/druid/pull/10314 https://github.com/apache/druid/pull/10839

# Kafka 摄取支持指定 group.id

Druid Kafka 流摄取现在可以选择支持在 Druid 任务与 Kafka 代理的连接上指定 group.id。这对于访问需要将其设置为授权一部分的集群非常有用，并且可以在 Kafka Supervisor 规范的 consumerProperties 部分中指定。有关更多详细信息，请参阅 Kafka 摄取文档。 https://github.com/apache/druid/pull/11147

# 本机批量摄取

# 支持使用深层存储来存储中间 shuffle 数据

Druid 原生“完美汇总”两阶段摄取任务现在支持使用深度存储作为洗牌位置，作为中间管理器或索引器上本地磁盘的替代方案。要使用此功能，请将 druid.processing.intermediaryData.storage.type 设置为 deepstore，这将使用配置的深度存储类型。 注 - 对于“deepstore”类型，数据存储在配置的深度存储路径下的 shuffle-data 目录中，尚不支持该目录的自动清理。您可以设置云存储生命周期规则，以自动清理 shuffle-data 前缀位置的数据。 https://github.com/apache/druid/pull/11507

# 改进了本机批量摄取任务内存使用情况

Druid 原生批量摄取获得了一个新的配置选项 druid.indexer.task.batchProcessingMode，它引入了两种新的操作模式，允许批量摄取以更小、更可预测的堆内存使用占用空间运行。 CLOSED_SEGMENTS_SINKS 模式是最积极的，并且应该具有最小的内存占用，并且通过消除内存跟踪和段创建过程中产生的中间段的 mmap 来工作，但目前还没有经过很好的测试，因此被认为是实验性的。 CLOSED_SEGMENTS 是新的默认选项，消除了中间段的 mmap，但仍然跟踪堆中的整个段集，尽管此时它经过了相对良好的测试并且被认为是稳定的。 OPEN_SEGMENTS 将使用之前的摄取路径，该路径与流式摄取共享，并在中间段上执行 mmap 并构建时间线，以便这些段可以通过实时查询进行查询。对于批处理来说根本不需要这样做，但是如果 2 个较新的模式出现任何问题，可以选择 OPEN_SEGMENTS 模式。 https://github.com/apache/druid/pull/11123 https://github.com/apache/druid/pull/11294 https://github.com/apache/druid/pull/11536

# 允许批处理任务等到分段切换完成后再进行

现在可以选择将 Druid 本机批量摄取任务配置为在历史服务器完全加载摄取的段之前不会终止。这对于以下场景非常有用：当保持占用额外任务槽的权衡值得使用任务状态作为摄取是否完成以及段是否可用于查询的衡量标准时。 可以通过将 awaitSegmentAvailabilityTimeoutMillis 添加到摄取规范中的 tuningConfig 来启用此功能，该规范指定任务在终止之前等待段加载的最长时间。如果在此超时到期时并非所有段都可用，则作业仍将成功。然而，在摄入报告中，segmentAvailabilityConfirmed 将是错误的。这表明切换不成功，并且这些新索引的段可能并不全部可用于查询。另一方面，如果在超时到期之前所有段都可用于历史服务上的查询，则报告中该键的值将为 true。 目前压缩任务不支持此 tuningConfig 值。如果用户尝试为压缩指定 awaitSegmentAvailabilityTimeoutMillis 值，任务将失败，并告诉用户不支持该值。 https://github.com/apache/druid/pull/10676

# 数据生命周期管理

# 支持管理自动压缩的段和查询粒度

现在可以配置 Druid 手动和自动压缩来更改段粒度，并且手动压缩还可以更改查询粒度。此外，默认情况下，压缩将保留段粒度。这使得操作员能够更轻松地执行选项，例如将旧数据更改为更大的段和查询粒度，以换取减小的数据大小。有关详细信息，请参阅压缩文档。 https://github.com/apache/druid/pull/10843 https://github.com/apache/druid/pull/10856 https://github.com/apache/druid/pull/10900 https://github.com/apache/druid/pull/10912 https://github.com/apache/druid/pull/11009

# 允许压缩暂时跳过锁定的间隔

默认情况下，Druid 自动压缩现在将暂时跳过锁定间隔，而不是等待锁定释放，这应该会提高数据源压缩的速度。这是由 druid.coordinator.compaction.skipLockedIntervals 控制的，如果由于某种原因不需要此行为，则可以将其设置为 false。 https://github.com/apache/druid/pull/11190

# 支持额外的自动元数据清理

您可以配置自动清理，以在从 Druid 中删除某些实体后从元数据存储中删除记录：

  • 分段记录
  • 审计记录
  • 主管记录
  • 规则记录
  • 压缩配置记录
  • 主管创建的数据源记录 当您的数据源流失率较高（这意味着您经常创建和删除许多短期数据源或其他相关实体）时，此功能有助于保持性能。您可以限制保留未使用的元数据记录的时间长度，以防止元数据存储填满。有关更多信息，请参阅自动清理文档。 https://github.com/apache/druid/pull/11078 https://github.com/apache/druid/pull/11084 https://github.com/apache/druid/pull/11164 https://github.com/apache/druid/pull/11200 https://github.com/apache/druid/pull/11227 https://github.com/apache/druid/pull/11232 https://github.com/apache/druid/pull/11245

# 删除数据

新设置 dropExisting 已添加到 Druid 原生批量摄取任务和压缩的 ioConfig 中，如果设置为 true（而 appendToExist 为 false），则摄取任务将以事务方式将间隔中的所有现有段标记为未使用，并用新的段集替换它们。这在压缩用例中非常有用，在这种情况下，正常的遮蔽不会完全替换间隔中的一组段，例如当将段粒度更改为较小的大小时，并且一些较小粒度的存储桶将没有数据，从而使原始段仅部分被遮盖。 请注意，此功能仍处于实验阶段，可能会导致压缩后的 interval 中的数据暂时不可用。更改此配置不会导致间隔再次被压缩。 同样，markAsUnused 已作为选项添加到 Druid Kill 任务中，该选项将在删除所有未使用的段之前将所提供间隔中的任何段标记为“未使用”。这对于允许通过调用者的单个 API 调用来发生标记未使用 -> 删除序列以及允许在任务间隔锁定下发生取消标记操作非常有用。 https://github.com/apache/druid/pull/11070 https://github.com/apache/druid/pull/11025 https://github.com/apache/druid/pull/11501

# 协调员

# 使用基于 Apache Zookeeper 的段管理来控制协调器段加载超时超时行为

新的 Druid 协调器动态配置选项允许在使用基于 Zookeeper 的段管理时，每当段加载操作超时时控制行为。 replicateAfterLoadTimeout 当设置为 true 时，协调器将尝试将加载失败的段复制到不同的历史服务器。如果集群中存在一些缓慢的历史服务器，这有助于提高段可用性。然而，缓慢的历史记录可能仍会稍后加载该段，并且如果该段被过度复制，协调器可能需要发出删除请求。 https://github.com/apache/druid/pull/10213

# 更快的协调器分段平衡

另一个新的协调器动态配置选项 useBatchedSegmentSampler，当设置为 true 时，可以潜在地大幅提高协调器处理段平衡阶段的速度。这在具有许多段的非常大的集群大小上应该特别值得注意，但默认情况下被禁用，以防万一。 https://github.com/apache/druid/pull/11257

# 改进了负载状态 API，可以根据集群大小选择性地计算复制不足

Druid 协调器负载状态 API 现在支持一个新的可选 URL 查询参数 computeUsingClusterView，指定该参数后将导致协调器根据集群中可以将段复制到的可用服务器数量（而不是加载规则中配置的复制计数）来计算段的复制不足。例如，如果加载规则指定 2 个副本，但只有 1 个服务器可以保存段，则此 API 不会报告复制不足，因为对于给定的集群大小，段已尽可能复制。 https://github.com/apache/druid/pull/11056

# 每个协调周期加载的非主副本数量的可选限制

新的协调器动态配置 maxNonPrimaryReplicantsToLoad（默认值为 Integer.MAX_VALUE）允许操作员定义将在单个协调器执行周期中加载的非主副本数量的硬性上限。默认值将模仿当前存在的行为。 用法示例：如果将此配置设置为 1000，则协调器将在每个运行周期执行中加载最多 1000 个非主副本。这意味着，如果您以复制因子 2 摄取 2000 个段，协调器将在第一次执行时加载 2000 个主副本和 1000 个非主副本。然后下次执行时，将加载最后 1000 个非主副本。 https://github.com/apache/druid/pull/11135

# Web 控制台

# 一般改进

Druid Web 控制台的“服务”选项卡现在将显示哪些协调器和霸主服务器充当领导者，显示在表的“详细信息”列中。这应该有助于操作员能够更快地确定哪个节点是领导者，从而确定哪个节点可能有需要检查的有趣日志。 Web 控制台现在还支持使用 ASCII 控制字符，以 \uNNNN 的形式输入它们，其中 NNNN 是字符的 unicode 代码点。 https://github.com/apache/druid/pull/10951 https://github.com/apache/druid/pull/10795

# 查询视图

Druid 0.22.0 中的网络控制台查询视图获得了许多“生活质量”改进。首先，查询视图现在提供了查询执行时间的指示器： 此外，打开新页面时，查询将不再自动运行，为了防止打开浏览器时执行过时的查询，如果查询结果发生变化，页面将重置为 0，并且在加载最后一个页面重新运行查询时，查询限制将自动增加。 内联文档现在还应该包含 Druid 类型信息： 并且应该在出现查询错误时提供更好的建议： 最后，Web 控制台查询视图现在支持热键组合 command + enter（在 Mac 上）以及 Windows 和 Linux 上的 ctrl + enter。 https://github.com/apache/druid/pull/11158 https://github.com/apache/druid/pull/11128 https://github.com/apache/druid/pull/11203 https://github.com/apache/druid/pull/11365

# 数据管理

Web 控制台分段视图时间线现在可以选择任何时间间隔，而不仅仅是前一年！ Web 控制台分段视图也得到了改进，希望在与 sys.segments 表交互时具有更高的性能，包括提供“强制”Web 控制台仅使用本机 JSON API 方法来显示分段信息的功能： 查找视图也得到了改进，因此现在“投票周期”和“摘要”可作为列表视图中的列使用： 我们还添加了轮询周期验证以防止用户错误，并改进了错误报告： https://github.com/apache/druid/pull/11359 https://github.com/apache/druid/pull/10909 https://github.com/apache/druid/pull/11620

# 指标

# Prometheus 公制发射器

添加了新的“contrib”扩展 prometheus-emitter，它允许 Druid 指标直接发送到 Prometheus 服务器。有关完整详细信息，请参阅扩展文档页面：https://druid.apache.org/docs/0.22.0/development/extensions-contrib/prometheus.html https://github.com/apache/druid/pull/10412 https://github.com/apache/druid/pull/11618

# 摄取/通知/queueSize

ingest/notices/queueSize 是一个新添加的指标，用于监控 Supervisor 摄取任务控制消息处理队列大小，以帮助确定 Supervisor 是否可能因大量通知而过载。默认情况下，每个正在运行的主管都会发出此指标。 https://github.com/apache/druid/pull/11417

# 查询/分段/计数

query/segments/count 是一个新指标，已添加用于跟踪参与查询的段数。默认情况下不启用此指标，因此必须通过自定义扩展来启用，以覆盖发出的 QueryMetrics ，类似于默认情况下不发出的其他查询指标。 （我们知道这绝对不友好，希望将来有一天能让这变得更容易，抱歉）。 https://github.com/apache/druid/pull/11394

# 云集成

# AWS Web Identity/IRSA 支持

Druid 0.22.0 添加了 AWS Web Identity Token 支持，如果配置为 AWS 凭证提供程序，则允许在 Kubernetes 上使用服务账户的 IAM 角色。 https://github.com/apache/druid/pull/10541

# 对承担角色的 S3 摄取支持

来自 S3 输入源的 Druid 本机批量摄取现在可以使用 AWS 中的 AssumeRole 功能进行跨账户文件访问。可以通过在批量摄取任务中在 S3 输入源规范上设置 assumeRoleArn 和 assumeRoleExternalId 来利用这一点。有关更多详细信息，请参阅AWS 文档 和本机批处理 文档。 https://github.com/apache/druid/pull/10995

# Google Cloud Storage 支持 URI 查找

Druid 查找现在支持通过 Google Cloud Storage 加载，类似于 S3 提供的现有功能。这要求除了查找扩展之外还必须加载 druid-google-extensions，但除此之外，它就像使用 Google Cloud Storage URI 一样简单。 https://github.com/apache/druid/pull/11026

# 其他更改

# 按类型提取 Avro 联合字段

使用 Druid 批量或流式摄取的 Avro 摄取现在支持为 Avro Union 类型提取数据的替代机制。这个新选项 extractUnionsByType 仅在使用 flattenSpec 从联合类型中提取嵌套数据时才起作用，并且将导致提取的数据可与该类型一起用作展平路径的一部分。例如，给定多类型联合列 someMultiMemberUnion，启用此选项后，长值将由 $.someMultiMemberUnion.long 而不是 $.someMultiMemberUnion 提取，并且只会从联合中提取长值。有关完整信息，请参阅 Avro 文档。 https://github.com/apache/druid/pull/10505

# 支持使用带有 MySQL 扩展的 MariaDb 连接器

Druid MySQL 扩展现在支持使用 MariaDB 连接器库作为 MySQL 连接器的替代方案。这可以通过将 druid.metadata.mysql.driver.driverClassName 设置为 org.mariadb.jdbc.Driver 来完成，并且包括对 JDBC 查找和基于 SQL 的摄取所使用的 JDBC URI 参数白名单的完全支持。 https://github.com/apache/druid/pull/11402

# 添加环境变量DynamicConfigProvider

Druid 现在提供了由环境变量支持的 DynamicConfigProvider 实现。例如：

druid.some.config.dynamicConfigProvider={"type": "environment","variables":{"secret1": "SECRET1_VAR","secret2": "SECRET2_VAR"}}

有关更多信息，请参阅动态配置提供程序 文档。 https://github.com/apache/druid/pull/11377

# 为架构注册表添加 DynamicConfigProvider

支持 Confluence Schema Registry 的摄取格式现在支持通过 DynamicConfigProvider（PasswordProvider 的更新替代品）提供这些参数。这将允许摄取任务使用配置提供程序来提供此信息，而不是直接在 JSON 规范中提供，从而有可能以更安全的方式提供凭据和其他敏感配置信息。有关更多详细信息，请参阅数据格式 和动态配置提供程序 文档。 https://github.com/apache/druid/pull/11362

# 安全修复

# 控制 HTTP 和 HDFS 输入源允许的协议

Druid 0.22.0 添加了新工具来控制批量摄取中 HTTP 和 HDFS 输入源使用的允许协议集。 druid.ingestion.hdfs.allowedProtocols 默认配置为接受 hdfs 作为协议，druid.ingestion.http.allowedProtocols 默认情况下将允许 http 和 https。这可能会导致现有部署出现问题，因为它比旧版本 Druid 中的当前默认行为更具限制性，但总体而言，操作员可以更灵活地保护这些输入源。 https://github.com/apache/druid/pull/10830

# 修复 LDAP 内部凭证缓存的过期逻辑

此版本的 Druid 还修复了使用 LDAP 时 druid-basic-security 扩展中的一个缺陷，其中凭证缓存不会正确过期，可能会在应该过期后保留过期的凭证信息，直到触发另一个触发器或重新启动服务。使用 LDAP 进行授权的 Druid 集群应尽可能更新到 0.22.0 以解决此问题。 https://github.com/apache/druid/pull/11395

# 升级到 0.22.0

从 Druid 0.21.x 升级到 0.22.0 时请考虑以下更改和更新。如果您要从 0.21.0 之前的版本进行更新，请参阅相关中间版本的 release note。

# 放弃对 Apache ZooKeeper 3.4 的支持

继 0.21 正式弃用对 Zookeeper 3.4（已停产一段时间）(https://mail-archives.apache.org/mod_mbox/zookeeper-user/202004.mbox/%3C41A7EC67-D8F4-4C3A-B2DB-C2741C2EECA3%40apache.org%3E) 的支持之后，0.22.0 现已删除对 ZooKeeper 3.4 的支持。在将 Druid 集群升级到 0.22.0 之前，请务必先升级 Zookeeper 集群。 https://github.com/apache/druid/issues/10780 https://github.com/apache/druid/pull/11073

# 本机批量摄取段分配修复

Druid 0.22.0 在本机批量索引中包含一个重要的错误修复，其中索引子任务的瞬时失败可能会导致结果段中出现非连续分区，由于检查“完整”集的逻辑，这些分区永远不会变得可查询。此问题已在最新版本的 Druid 中得到解决，但需要更改批处理任务用于分配段的协议，如果您决定从 Druid 0.22.0 回滚到早期版本，此更改可能会在滚动降级期间导致问题。 为了避免滚动降级期间任务失败，请设置

druid.indexer.task.default.context={ "useLineageBasedSegmentAllocation" : false }

在霸主运行时属性中，等待所有将 useLineageBasedSegmentAllocation 设置为 true 的任务完成，然后再开始降级。这些任务全部完成后，降级应该不会有任何进一步的问题，并且可以从霸主配置中删除该设置（推荐，因为如果您运行的是 Druid 0.22.0 或更新版本，您将希望启用此设置）。 https://github.com/apache/druid/pull/11189

# SQL 时间序列不再跳过所有粒度的空存储桶

在 Druid 0.22 之前，使用单个通用分组键（例如，仅聚合器）（例如 SELECT COUNT(*), SUM(x) FROM y WHERE z = 'someval'）的 SQL 分组查询将生成一个空结果集，而不是此查询可能期望的 ZZPH100​​ZZ 不匹配任何结果。这是因为在下面这将计划为具有“ALL”粒度的时间序列查询，并且 skipEmptyBuckets 在查询上下文中设置为 true。后一个选项导致此类查询的结果不返回任何结果，因为没有包含要聚合的值的存储桶，因此它们被跳过，从而生成空结果集而不是“nil”结果集。此行为已更改为与其他 SQL 实现一致，但可以通过在查询上下文上显式设置 skipEmptyBuckets 来获得以前的行为。 https://github.com/apache/druid/pull/11188

# 德鲁伊重新摄取不兼容的更改

使用“Druid”输入源重新提取段数据的批处理任务将不再接受其任务规范的“维度”和“指标”部分，现在将在内部使用新的列过滤器来指定应保留原始段中的哪些列。此外，timestampSpec 不再被忽略，允许修改 __time 列或用不同的列替换。这些更改还修复了一个错误，即转换后的列将被忽略并且在新段上不可用。 https://github.com/apache/druid/pull/10267

# Druid Web 控制台不再支持 IE11 和其他旧版浏览器

有些功能可能仍然有效，但不再受到官方支持，因此可以使用更新的 Javascript 功能来开发 Web 控制台。 https://github.com/apache/druid/pull/11357

# 更改了默认最大分段加载队列大小

德鲁伊协调器maxSegmentsInNodeLoadingQueue动态配置已从无限制（0）更改为100。这应该使协调器在集群波动期间（例如滚动升级）以更加轻松的方式运行，但将在任何给定协调器周期中加载的段总数限制为每个服务器 100 个，这可能会减慢完全停止的集群启动和从深度存储加载的速度。 https://github.com/apache/druid/pull/11540

# 开发者通知

# CacheKeyBuilder 从 druid-processing 移至 druid-core

用 @PublicAPI 注释的 CacheKeyBuilder 类已从 druid-processing 移动到 druid-core，以便表达式可以扩展 Cacheable 接口，以允许表达式生成依赖于某些外部状态（例如查找版本）的缓存键。 https://github.com/apache/druid/pull/11358

# 查询引擎现在使用新的 QueryProcessingPool 而不是直接使用 ExecutorService

这会影响查询处理引擎中的一些方法签名，例如 QueryRunnerFactory 和 QuerySegmentWalker，以允许扩展连接到查询处理池的各个部分以及将来的替代处理池调度策略。 https://github.com/apache/druid/pull/11382

# SegmentLoader 现在是可扩展和可定制的

这允许扩展提供替代的段加载实现，以自定义 Druid 段如何从深度存储加载并可供查询引擎使用。这应该被视为不稳定的 api，并在代码中如此注释。 https://github.com/apache/druid/pull/11398
