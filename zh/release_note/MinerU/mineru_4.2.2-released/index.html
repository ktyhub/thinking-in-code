MinerU 4.2.2-released

MinerU 4.2.2-released

4.2.2

  • 完善VLM引擎的本地故障传播与生命周期管理。统一消费LMDeploy、vLLM、llama.cpp和MLX的公共健康与故障契约；确认引擎停止故障后恢复备份备份实例，并通知相关事宜，避免全局故障共用识别失败而静默降级。普通单片识别失败仍保留备份回退。
  • 增强解析服务的健康检查与任务清理。周期探测已加载并支持健康检查的运行时；暂时无法使用时拒绝新推理，恢复健康后重新开放。确认引擎死亡时，健康与能力接口明确返回错误，运行及队列任务按指定边界清理，恢复由一系列管理。完善关闭期间的在途、取消和资源释放探测顺序。
  • 修复批量解析的输入与错误处理。使用内容签名和容器识别验证文件，避免Office锁文件阻塞后续文档，同时保留名称以~$ 的合法合法的起始文档。明显的损坏、加密、资源限制、输入设备及权限错误记录为单项失败并继续；引擎、服务或故障输出停止后续处理。摘要分别报告成功、跳过、失败和未处理数量，部分失败返回非零退出码。
  • 修复批量输出路径判断。目录和多文件输入首先采用输出目录，只有一个文档时也保持一致。支持已有或新建的results.v1、results.md等带点目录，拒绝将批量结果写入已有普通文件；显式单文件输出继续支持覆盖目标文件。
  • 明确阅读与导出的职责。mineru read的Markdown编写用于渐进阅读，保留stdout、JSON和续读提示；--output PATH仅用于图片。保存当前文本片段可使用重定向或SDK，完整导出指定页面范围使用mineru parse ... -o ...，避免把受阅读重组限制的片段错误当完成整个过程。
  • 改进服务启动与退出体验。服务成功监听后打印可直接访问的API文档地址；正常Ctrl+C退出不再显示中断堆栈。删除未实现的webhook能力声明及对应文档。
  • 更新运行时依赖。最低版本调整为mineru-llama-cpp 0.2.1和mineru-vl-utils 2.0.9，与本次公共生命周期契约保持一致。

兼容性提示。原有mineru read <locator> -o part.md改为需要stdout重定向或SDK保存；需要完整产品时使用mineru parse <path> --pages <range> -o result.md。批量调用方应根据新的结果成功摘要和退出码区分完整、部分失败和全局中止。

4.2.2

  • 改进本地 VLM 故障传播和生命周期管理。使用 LMDeploy、vLLM、llama.cpp 和 MLX 的共享运行状况和故障合约。确认的引擎故障会使缓存的实例失效并通知其主机，从而防止全局中断默默地成为本地识别后备。普通的每作物失败保留现有的后备行为。
  • 加强解析服务器健康检查和任务清理。定期探测支持运行状况检查的初始化运行时。暂时不可用会拒绝新的推断，直到健康恢复。确认的引擎死亡会产生明确的运行状况和功能错误，并通过现有生命周期边界清理正在运行和排队的任务；恢复仍然是东道主的责任​​。改进关闭期间主动探测、取消和资源释放的排序。
  • 正确的批量输入验证和错误处理。验证文件内容签名和容器，以便 Office 锁定文件不会停止后续文档，同时仍支持以 ~$ 开头的有效文档。将已知的损坏、加密、资源有限、丢失或无法访问的输入报告为单独的故障并继续。引擎、服务和输出故障导致批次停止。摘要区分成功、跳过、失败和未处理的输入；部分失败返回非零退出代码。
  • 正确的批量输出路径处理。目录和多文件输入始终会生成目录输出，即使仅保留一个文档也是如此。接受现有和新的带点目录名称，例如 results.v1 和 results.md，并拒绝现有常规文件作为批处理目标。显式单文件输出继续支持覆盖其目标。
  • 澄清阅读和导出。 mineru read 的 Markdown 仍然是渐进式标准输出或带有继续提示的 JSON 读取； --output PATH 保留用于图像。通过重定向或SDK保存当前文本片段，并使用mineru parse ... -o ...导出完整的页面范围，而无需阅读预算。
  • 改进服务启动和关闭。成功绑定后打印可直接访问的 API 文档 URL，避免正常 Ctrl+C 关闭时的中断回溯，并删除未实现的 Webhook 功能声明和文档。
  • 更新运行时依赖项。共享生命周期合约需要 mineru-llama-cpp 0.2.1 和 mineru-vl-utils 2.0.9 或更新的兼容版本。

兼容性说明。将 mineru read <locator> -o part.md 替换为 stdout 重定向或 SDK 保存。如需完整导出，请使用 mineru parse <path> --pages <range> -o result.md。批处理调用者应解释结果摘要和退出代码，以区分完全成功、部分失败和中止的批处理。
