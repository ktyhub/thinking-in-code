MinerU 4.2.1-released

MinerU 4.2.1-released

4.2.1

  • 修复Doclib中断续读遗漏内容。Markdown文档或单页读取在context=0时，达到长度限制后通过next_request.locator与next_request.after继续读取当前页的剩余内容，读完后再建议下一页。CLI续读标记和SDK文档同步更新。
  • 完善托管解析服务的故障恢复。连续启动或重启失败达到上限后停止自动重试，并占用占用进程。重新设置托管模式或档位、文档重启库服务后可尝试。恢复切换模式、档位及关闭服务时，完善进程和控制通道的恢复。
  • 修复Windows托管服务端口探测。按照服务实际绑定行为检查端口，在非严格端口模式下跳过已占用或被系统保留的端口，减少探测成功后仍无法启动的问题。
  • 改善文档库服务的优雅退出。通过即时执行回调生命周期清理，使Windows流程关闭也能恢复后台任务、托管解析进程和数据库资源。
  • 修复 Windows GPU 显存信息导出。完善 DXGI 与硬件库存的 PCI 地址匹配，在同型号设备边界存在提高歧义时保留一致的显存和设备属性，硬件诊断信息的缺陷。
  • 修复修复PDF正文丢失。接受因浮点位置接近360°的正常文本方向，避免文字在修复文本回填时被错误过滤。

集成提示。嵌入式Doclib首先需要设置shutdown回调以支持关闭接口，缺少回调时返回service_unavailable。标准mineru server入口已配置该回调。

4.2.1

  • 截断后完成 Doclib 延续。 Markdown 文档和使用 context=0 的单页读取都使用 next_request.locator 和 next_request.after 在达到输出限制后恢复未完成的页面，然后建议下一页。 CLI 延续标记和 SDK 文档遵循相同的合同。
  • 绑定托管解析服务器恢复。在重复启动或重新启动失败后停止自动重试并清理剩余进程。再次设置托管模式或层，或者重新启动文档库服务器，即可继续恢复。改进模式更改、层更改和关闭期间的流程和控制通道清理。
  • 正确的 Windows 托管端口探测。匹配服务器的实际绑定行为，并在禁用严格端口模式时跳过占用或系统保留的端口，从而减少端口探测成功后的启动失败。
  • 文档库正常关闭。使用主机关闭回调来运行生命周期清理，包括 Windows 上的后台任务、托管解析进程和数据库资源。
  • 恢复 Windows GPU 内存信息。改进 DXGI 和硬件清单之间的 PCI 地址匹配，并在相同型号条目具有不明确标识时保持一致的内存和设备属性。
  • 保留原生 PDF 正文。由于浮点错误，接受接近 360° 的正常文本方向，防止水平文本在本机文本恢复过程中被过滤。

集成说明。嵌入式 Doclib 主机必须提供 shutdown 回调以支持关闭端点。丢失的回调返回 service_unavailable。标准 mineru server 入口点已提供回调。
