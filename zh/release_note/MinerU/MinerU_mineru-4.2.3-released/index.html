MinerU 4.2.3-released

修订 发布时间2026年11月16日 来源opendatalab/MinerU 英文原文

MinerU mineru-4.2.3-released

4.2.3

  • 新增单文件执行超时与托管恢复。WebUI、路由器和API服务器支持--task-timeout，默认3600秒，从取得解析名额开始计时，覆盖解析和服务端备份。超时任务返回task_timeout，独立API停止接收新任务，由配置方重建服务。路由器通过父进程监督恢复工作者超时及模型子进程，并重新启动服务，即使执行线程、事件循环或取消清理挂起也能触发恢复。
  • 改进WebUI恢复体验与进程清理。本地WebUI由路由器托管唯一worker，恢复期间显示状态，尚未提交的排队请求在服务就绪后继续。旧worker上其他未完成请求worker_restarted，问题文件可手动重试。完善Windows进程树、临时目录与控制通道恢复，明确报告模型预加载失败，并在连续三次启动恢复失败后停止自动重试。
  • 修复Doclib全文检索被图片索引挤占。构造检索文本时提取正文、图表说明，再应用修正避免调整，内嵌图片的base64占满索引而遗漏正文。升级后从解析存档重建已有索引，并保留跨页内容续接。存档不完整的文档会记录迁移原因，补齐缓存内容或重新解析后重启Doclib可继续迁移。
  • 提前检查 vLLM 与 Transformers 兼容性。启动引擎前识别 vllm<0.29.0 与 transformers>=5.23.0 的不兼容组合，并给出升级 vLLM 或调整 Transformers 版本范围的明确提示，减少模型加载阶段难以定位的失败。
  • 更新DocVortex依赖。最低版本提升至0.6.24，同步文档解析与共享渲染能力的改进。

配置提示。路由器的--worker-tier默认改为auto，由各工作人员根据自己的环境确定档位上限。需要固定上限时可显式指定flash、basic、standard或advanced。--task-timeout必须为正整数，上传、排队、客户端下载及模型启动预加载分别使用独立的等待与生命周期设置。

4.2.3

  • 添加每个文件执行超时和托管恢复。 WebUI、路由器和 API 服务器支持 --task-timeout，默认情况下，从通过解析和服务器端工件打包获取执行槽起需要 3600 秒。超时任务返回 task_timeout。独立的 API 停止接受新工作并依赖其部署主机重新创建服务。路由器从父进程中监督本地工作进程，回收超时的工作进程和模型子进程，并在执行线程、事件循环或取消清理停止时重新启动服务。
  • 改进 WebUI 恢复和进程清理。本地WebUI使用Router来管理单个worker，显示恢复状态，并在服务准备好后恢复排队等待提交的请求。被替换的工作线程上的其他未完成的请求返回 worker_restarted，并且可以手动重试受影响的文件。改进 Windows 进程树、临时目录和控制通道清理、表面模型预加载失败，并在连续三个启动失败后停止自动恢复。
  • 将图像有效负载排除在 Doclib 全文索引之外。在应用字符预算之前，根据正文内容、公式以及图形或表格描述构建搜索文本，从而防止嵌入式图像 Base64 数据挤占可搜索文本。在升级期间从缓存的解析结果重建现有索引，同时保留跨页面延续。缓存不完整的文档会记录迁移原因，并且可以在恢复或重新解析缓存并重新启动 Doclib 后恢复迁移。
  • 启动前检查 vLLM 和 Transformers 兼容性。在引擎初始化之前检测 vllm<0.29.0 和 transformers>=5.23.0 的不兼容组合，并提供升级 vLLM 或选择兼容 Transformers 系列的可行指导。
  • 更新 DocVortex。将最低版本提高到 0.6.24 以实现本机文档解析和共享渲染改进。

配置说明。路由器现在将 --worker-tier 默认为 auto，允许每个工作人员从其设备环境中选择其层上限。对于固定天花板，请指定 flash、basic、standard 或 advanced。 --task-timeout 需要一个正整数。上传、排队、client 下载和模型启动预加载使用自己的等待和生命周期设置。
