hermes-agent v2026.6.19

#爱马仕代理v0.17.0(v2026.6.19) 发布日期： 2026 年 6 月 19 日 自 v0.16.0 起： ~1,475 次提交 · ~800 个合并 PR · 更改了 1,693 个文件 · 235,390 次插入 · 50,730 次删除 · 解决了 300 多个问题 · 245 名社区贡献者

Reach 版本。 v0.16.0 将 Hermes 放在您的桌面上。 v0.17.0 是关于影响力延伸的范围——跨越新的地方与之交谈，更深入地了解您已经使用的工具，以及为团队运行 Hermes 的人员。 Hermes 达到了两个新渠道（通过 Photon 的 iMessage 和 Raft 代理网络），桌面应用程序获得了实质性的新功能，子代理现在可以在后台运行，图像生成学会了编辑，并且 Cursor 的 Composer 模型可以通过 xAI Grok 订阅访问。仪表板获得了完整的配置文件生成器和安全登录，技能中心浏览器得到了重新调整，memory 工具得到了重大升级，策展人不再在每次例行运行上花费辅助模型预算。超过 300 个问题封闭式运行，外加一轮安全检查。

✨ 亮点

  • Hermes 到达 iMessage — Photon Spectrum，无需 Mac 中继 — 现在有一个基于 Photon 托管线路池构建的 iMessage 平台插件。运行 hermes photon login，使用设备代码进行身份验证，Hermes 可以发送和接收 iMessage — 壁橱里没有 Mac 运行中继，也没有 BlueBubbles 桥来照顾。它被定位为 BlueBubbles 的继任者：免费启动，无需自行托管。如果你的朋友和家人住在蓝色泡泡里，爱马仕现在也住在那里。 (#32348、#42582、#44713 — @teknium1)
  • Raft — Hermes 作为网关通道加入 Raft 代理网络 — 新的捆绑 Raft 平台适配器让 Hermes 通过唤醒通道桥作为外部代理连接到 Raft。设置 RAFT_PROFILE，运行网桥，Raft 可以唤醒 Hermes 来处理消息——采用合约隐私设计，其中唤醒有效负载仅携带元数据（事件 ID、时间戳），而不携带消息正文。 Hermes 可以出现并工作的另一个表面。 (#48210 — @xxchan, @teknium1)
  • 功能更加强大的桌面应用程序 - v0.16.0 附带了桌面应用程序； v0.17.0 通过数十个 PR 加深了它。可重新绑定的键盘快捷键、带有每种类型切换的本机操作系统通知、将委派代理的活动流式传输到其自己的窗格的实时子代理监视窗口、带有每个模型预设的 Composer 模型选择器、自动 RTL/bidi 文本方向、可调整大小的 VS Code 主题终端窗格、每线程 Composer 草稿，以及将任何 VS Code Marketplace 主题直接安装到应用程序中的功能。桌面现在是一个严肃的日常驱动程序，而不是预览版。 (#45866、#40660、#47060、#46959、#43292、#44596 — @OutThisLife, @teknium1)
  • 后台/异步子代理 - 委派工作并继续 - delegate_task(background=true) 现在分派在后台运行的子代理并立即返回句柄。您和模型在搅动时继续工作，完整的结果在完成后作为新的转折重新进入对话。开始一个长期的研究潜水或多步骤构建，然后继续做其他事情，而不是坐在那里等待。 (#40946、#46968 — @teknium1)
  • 编辑图像，而不仅仅是生成图像 - image_generate 中的图像到图像 - image_generate 现在可以编辑和转换源图像，而不仅仅是从头开始创建图像。传递现有图像和提示，它会跨每个受支持的图像提供程序路由到后端的编辑端点（与 video_generate 相同的工具，相同的模式）。 “将此徽标设为蓝色”、“删除背景”、“将此草图转换为渲染图”——所有这些都来自您已经使用的工具。 (#48705 — @teknium1)
  • 自动化蓝图 — 无需学习 cron 即可安排事务 — 通过名称选择自动化，Hermes 会询问您需要什么 — 无需 cron 语法，无需输入 slot=value。一个蓝图定义原生呈现在每个表面上：仪表板中的表单、CLI/TUI/messenger 中的斜线命令、与代理的对话、文档目录中的条目。 “每日上午 8 点新闻发布会”变成了你通过回答问题来设置的东西，而不是通过记住 0 8 * * * 来设置。 (#41309 — @teknium1)
  • Cursor 的 Composer 模型，通过您的 xAI Grok 订阅 — grok-composer-2.5-fast 现在位于 xAI OAuth 模型选择器中，其上下文窗口已调整为完整的 200k。 Composer 是 Cursor 背后的快速编码模型 - 如果您有 xAI Grok 订阅，您现在可以直接通过 OAuth 将 Hermes 指向它，无需单独的 API 密钥。你的 Grok 计划、Hermes 的代理循环、Composer 的编码速度。 (#47908、#6f89e17 — @teknium1)
  • 仪表板中的完整配置文件生成器 — 从浏览器构建完整的 Hermes 配置文件 — 选择其型号、选择其技能、连接其 MCP 服务器 — 无需手动编辑 config.yaml。该仪表板还通过全局配置文件切换器将多配置文件管理统一到一个机器范围的视图中，因此您可以从一个位置管理每个配置文件。 (#39084、#44007 — @teknium1)
  • 技能中心浏览器重修 - 仪表板的技能中心进行了彻底的改造：连接的中心、特色部分、安装前的完整技能预览以及对每个技能的安全扫描。 trusted 水龙头（OpenAI、Anthropic、HuggingFace、NVIDIA）的浏览和安装技能现在是真正的浏览体验，而不是平面列表。 (#40384、#43398 — @teknium1)
  • memory 工具进行了重大升级 - 原子批量操作 - memory 工具获得了一个 operations 数组，该数组根据最终角色预算原子地应用一批添加/替换/删除编辑。该模型可以释放空间并在一次调用中添加新条目——即使单独添加就会超出预算——将过去脆弱的多轮舞蹈压缩为一个可靠的操作。内存更新现在更快，并且在编辑过程中失败的可能性大大降低。 (#48507 — @teknium1)
  • 安全仪表板登录 - 仪表板的身份验证得到强化：每个需要令牌的端点现在都可以在 OAuth 门后正确返回 401，websocket 身份验证使用提供的仪表板令牌，并且当 public_url 覆盖被静默拒绝时会触发警告。默认情况下，将仪表板暴露给网络更安全。 (#42578、#42578 — @benbarclay、@teknium1)
  • 官方 WhatsApp Business Cloud API 适配器 — 除了现有的 Baileys 桥之外，Hermes 现在采用 官方 WhatsApp Business Cloud API — Meta 的第一方、托管、无桥进程路径。将其指向您的企业 API 凭证，Hermes 将通过支持的渠道与 WhatsApp 进行对话，无需 QR 扫描桥接流程即可保持活动状态。 (#44331、#43921 — @jquesnelle、@teknium1)
  • Telegram 的富文本 — Bot API 10.1 丰富消息 — Telegram 回复现在通过 Bot API 10.1 呈现为正确的富消息：更好的格式、更清晰的长消息处理、本机标记而不是扁平文本。默认情况下，它是开启的，并且可以选择退出，因此您的 Telegram 对话看起来应该是这样，无需任何配置。 (#44829、#45584、#45953 — @teknium1)
  • 策展人成本优化 - 日常运行中没有辅助模型支出 - 技能策展人现在默认修剪过时的技能，但不再运行其 LLM 支持的整合通行证，除非您选择加入（curator.consolidate: true 或 hermes curator run --consolidate）。确定性不活动扫描继续免费运行；固执己见的、辅助模型支出的“建立保护伞技能”分叉现在默认关闭。常规后台管理成本零代币。 (#47840 — @teknium1)

  • memory 批处理操作 — 根据最终字符预算原子添加/替换/删除数组，因此单个调用可以释放空间并添加条目 (#48507 — @teknium1)
  • search_files 无损致密化 — 余量评估报告 + 一项值得交付的致密化改进（每个结果的代币更少，相同的匹配）（#47866 — @teknium1）

  • 上下文文件处理：可配置的截断限制+警告；将上下文文件上限缩放到模型窗口 + 截断文件处的点代理（#47251、#47846 — @teknium1）
  • 压缩：压缩摘要中的时间锚定；将 Codex OAuth 上的 gpt-5.5 的压缩触发器提高到 85%（#41102、#40957 — @teknium1）
