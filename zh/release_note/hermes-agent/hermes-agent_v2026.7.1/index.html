hermes-agent v2026.7.1

#爱马仕代理v0.18.0(v2026.7.1) 发布日期： 2026 年 7 月 1 日 自 v0.17.0 以来： ~1,720 次提交 · 998 个合并 PR · 2,215 个文件已更改 · ~251,000 个插入 · ~41,000 个删除 · 已关闭 949 个问题 · 370 多个社区贡献者

判决发布。 在过去的一周半时间里，团队几乎将所有的努力都投入到一个目标上：解决整个 Hermes Agent 存储库中的每个 P0 和 P1 问题和 PR - 并且截至此版本，100% 已关闭。 零开放 P0。 P1 零开。这是 ~700 个最高优先级的项目，作为 ~1,950 个问题和 PR 关闭的一部分而被清除。我们打算从现在开始将 P0/P1 保持为零。

除此之外，v0.18.0 还讲述了 Hermes 的思考方式以及它如何“知道其工作何时真正完成”。 Mixture-of-Agents 成为一等公民——你可以像任何其他模型一样选择命名的模型集合，每个参考模型的推理都会向你展示，聚合器的答案也会实时流式传输。特工学会了根据证据而不是共鸣来验证自己的工作，/goal 获得了完成合同，而 /learn + /journey 将自我完善变成了你可以看到和引导的东西。在底层，网关变得真正可大规模部署（缩放到零，消耗协调），桌面增长了一流的编码项目和可播放的内存图，子代理现在可以在后台扇出。

🎯 P0/P1 横扫一切 — 100% 解决

这是发布标题。在一周半的时间里，团队夜以继日地处理优先级积压工作，整个存储库中的每个 P0 和 P1 现已关闭：

优先 问题已关闭 PR 合并
P0（严重） 3 8
P1（高） 493 493 188
总计 496 196
这就是在 12 天内解决了 ~692 个最高优先级的项目 — 在扫描完成时，整个存储库的开放 P0/P1 计数达到 0。 最后一个失败的集群是中断保护压缩同级分叉错误（问题＃56391）及其修复（＃56416），在本次版本削减之前通宵关闭。
特别感谢 @kshitijk4poor，他日夜与核心团队一起处理了优先级积压的工作——cron 可靠性浪潮、压缩分叉修复、凭证泄露强化以及 P1 关闭的很大一部分都是他的。
从现在开始，我们将 P0/P1 保持在 0。 🫡

✨ 亮点

  • 混合代理现在是您可以选择的一流模型 — MoA 曾经是您可以切换的模式；现在，每个命名的 MoA 预设都在 moa 提供程序下显示为可选模型，与每个模型选择器（CLI、TUI、桌面、网关）中的 Claude、GPT 和 Grok 一起显示。选择“my-council”就像选择任何模型一样，Hermes 会自动通过该集合传递您的提示。现在，在每个表面上都可以选择一组前沿模型来思考您最困难的问题。 (#46081、#53548、#53561 — @teknium1)
  • 查看每个模型的推理，然后观看答案流 - 当 MoA 集成运行时，每个参考模型的完整输出现在呈现为其自己的标记块 - 在聚合器将它们合成为一个答案之前，您可以阅读 GPT-5 的想法、Claude 的想法以及 Grok 的想法。最终的答案现在会实时流向您，而不是在长时间的沉默后立即出现。这适用于 CLI、TUI 和桌面应用程序。你可以观看委员会的审议，而不仅仅是阅读判决结果。 (#53793、#53855、#55625、#56101 — @teknium1)
  • 代理验证自己的工作 - “完成”意味着已证明，而不是声明 - Hermes 现在记录编码工作的验证证据，并可以通过实际运行项目的检查来确定它已完成，而不是断言成功。 /goal 获得了完成合同：你说明“完成”是什么样子，固定目标循环根据该证据判断完成情况，而不是在模型感觉需要时停止。有一个 pre_verify 钩子用于在自定义检查中进行连接，以及可以明智地调整默认值的一次性迁移。 “我想我已经修复了它”和“测试通过了，这是证据”之间的区别。 (#50501、#52285、#55413、#53552 — @teknium1、@OutThisLife)
  • /learn - 通过描述将任何东西变成可重用的技能 - 运行 /learn <anything> ，Hermes 会从你指向的任何内容中提炼出可重用的技能 - 目录、URL，或者只是你五分钟前走过的工作流程。它会自动将技能写入 CONTRIBUTING.md 中的标准。下次您需要该工作流程时，它已经在那里了。现在，教 Hermes 一个新技巧只需一个命令，而不是手动技能创作会话。 (#51506、#52372 — @teknium1)
  • /journey — 一条可玩的时间线，记录了 Hermes 所了解的关于您的一切 — CLI 和 TUI 获得了 /journey，这是一个学习时间线，显示了 Hermes 随着时间的推移积累的记忆和技能 — 您可以直接从视图中编辑或删除其中任何内容。将其与桌面的新内存图（自上而下、可播放的内存和技能径向时间线）配对，您第一次可以真正“查看”您的代理所知道的内容，观察它的增长，并删除错误。你的特工的记忆不再是一个黑匣子。 (#55555、#55859、#55226 — @OutThisLife)
  • 委派一堆工作并继续进行 - 后台扇出 - delegate_task 现在可以扇出全部在 后台 运行的多个子代理：您的聊天永远不会被阻止，并且当每个子代理完成时，他们的结果会作为一个合并回合返回。开始“并行研究这五个竞争对手”或“审核这三个模块”，然后在一小群工作的同时继续做其他事情。当这一切完成后，您将得到一份清晰的摘要，而不是逐一照看。 (#49734 — @teknium1)
  • 桌面应用程序中的一流编码项目 - 桌面应用程序获得了真实的、每个配置文件的 项目 - 代码库的侧边栏、编码栏、审阅窗格、git 工作树管理和面向代理的项目工具，所有这些都由适当的 project → repo → lane 模型支持。您的编码工作不是分散的聊天会话，而是被组织成代理理解并可以采取行动的项目。它是桌面变成一个真正的编码驾驶舱。 (#49037、#54385、#54517 — @OutThisLife)
  • 大规模运行 Hermes — 缩放至零并进行排空协调 — 网关现在可以在空闲时进入休眠状态，并在重新启动、迁移或自动更新之前完全停止 — 不会丢失正在进行的对话。当没有人与之交谈时，托管或仅中继的 Hermes 可以扩展到零并按需唤醒，并且破坏性的生命周期操作可以协调外部消耗，因此没有人会在中途被切断。为团队运行 Hermes 或作为托管服务获得更高的生产级别。 (#52243、#52937、#54824 — @teknium1、@benbarclay)
  • 更便宜的自我改进 - 更智能的背景审查 - 回合后自我改进分支（决定是否保存记忆或技能的分支）现在路由到辅助模型，消化上下文而不是重播整个对话，并调整其节奏 - 因此，在回合后运行的“从刚刚发生的事情中学习”循环的成本只是以前的一小部分。你保持自我改进，你就不再为此支付主型号的全部价格。 (#49252 — @teknium1)
  • 在编辑器中编写下一个提示 — /prompt — /prompt 打开 $EDITOR，这样您就可以在真正的 Markdown 中手写长的多行提示，而不是与单行输入框打交道。起草一份详细的规范、一个结构化的问题或一个大的粘贴，保存，它就会作为您的下一条消息排队。对于那些一次写 Hermes 超过一句话的人来说，这是一件小事，但生活质量却大为提高。 (#50509 — @teknium1)
  • Google Vertex AI — Gemini 通过您的 GCP 服务帐户，无静态密钥 — Vertex AI 现在是通过 Vertex 的 OpenAI 兼容端点提供 Gemini 模型的一流提供商。普通的自定义提供程序设置总是在会话中终止的原因是 Vertex 没有静态 API 密钥 - 每个请求都需要从服务帐户 JSON 或应用程序默认凭证创建的短期 OAuth2 访问令牌 (~1h TTL)。 Hermes 现在会为您铸造并自动刷新这些令牌，因此，如果您的组织通过 Google Cloud 运行 Gemini，您将 Hermes 指向您的服务帐户，它就会正常工作 - 无需粘贴令牌，也不会在会话中过期。 (#56363 — @teknium1、@slawt)
  • 安全回合 - 此窗口强化了多个表面：MCP-config 持久性攻击面被锁定，cron base_url 覆盖可能会泄露提供者凭据被阻止，文件读取中前缀机密的不可重用哨兵，Slack 应用程序级 (xapp-) 令牌编辑，在每个后端强制执行的浏览器云元数据底层，以及跨惰性消息传递路径的 aiohttp CVE 底层。提示注入或错误配置的会话泄露凭证的方式更少。 (#50476、#56196、#54166、#56227、#52349、#56237 — @teknium1、@kshitijk4poor、@claudlos)

🧠 混合药剂 (MoA)

MoA 在这个窗口中从一个模式升级到了模型系统的一流部分。

  • 预设为可选择的虚拟模型 - 每个命名的 MoA 预设都显示为提供商 moa 下的模型；在任何模型选择器中选择它，Hermes 通过整体路由（#46081、#53561、#53775 — @teknium1)
  • /moa 现在是一次性糖 — 通过默认预设运行单个提示，然后恢复您的模型；持久切换通过模型选择器（#53548 — @teknium1）
  • 参考模型输出在 CLI、TUI 和桌面中显示为标记块 — 在聚合器综合之前阅读每个模型的推理（#53793、#53855 — @teknium1）
  • 聚合器响应流实时，而不是在沉默后显示完整（#55625 — @teknium1）
  • 参考可查看完整的工具状态并触发每个用户/工具响应；咨询参考在用户轮流结束并获得参考角色系统提示（#54016、#54007 — @teknium1）
  • 选择对 JSONL (moa.save_traces) 进行全程跟踪持久性以进行调试和评估 (#56101 — @teknium1)
  • 可靠性：通过其提供商的真实路径调用的参考+聚合器模型；从聚合器解析的上下文窗口（不是默认的 256K）；辅助任务解析给聚合器；虚拟提供商被阻止作为参考/聚合槽；容忍手动编辑的预设配置（#53580、#53780、#53827、#53281、#53275、 #53556 — @teknium1)
  • MoA 老虎机提供商身份在单个 call_llm 阻塞点上统一； HermesBench 结果记录（#55991、#53206 — @teknium1）
