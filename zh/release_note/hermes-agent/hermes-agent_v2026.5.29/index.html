hermes-agent v2026.5.29

#爱马仕代理v0.15.1(v2026.5.29) 发布日期： 2026 年 5 月 29 日 自 v0.15.0 起： 28 个提交 · 21 个合并 PR · 修补程序发布 · 9 个贡献者

补丁发布。 v0.15.0 的当天修补程序。标题修复：仪表板无限重新加载循环会影响任何在环回模式下运行 v0.15.0 的人（Docker、托管 Hermes、全新安装）。其他一些 v0.15.0 后续产品也随之而来——看板工作人员 SIGTERM、/model 选择器统一、/yolo 会话旁路、完整的 19,932 个条目的 Skills.sh 目录、.md 媒体交付恢复、网关探针降级安全、Web URL 编辑直通、看板工作人员对参考图像的愿景、事后观察默认值。 Docker 用户可以获得显式的 --insecure 选择加入环境变量（不再有绑定主机推断）、MCP 服务器裸命令路径解析和 arm64 PR 构建缓存修复。

✨ 亮点

  • 仪表板 401 重新加载循环已修复 — 在环回模式下，仪表板的身份探测 (/api/auth/me) 按设计返回 401，但 v0.15.0 的陈旧令牌重新加载防护将每个 401 视为轮换会话令牌并进行全页重新加载以获取新令牌。每个成功的同级调用都会清除一次性重新加载防护，因此页面会永远重新加载循环（Firefox：“导航到/sessions”风暴；Chrome：React 重新渲染风暴）。修复在 fetchJSON 中添加了 allowUnauthorized 选择退出，仅跳过环回陈旧令牌重新加载 - 401 仍然抛出，因此 AuthWidget 吞掉它，门控模式 login_url 重定向不受影响。关闭 #34206、#34202。 (#30698 — @austinpickett)
  • Docker 仪表板 --insecure 现在是显式环境选择加入，从未从绑定主机派生 - 以前，当仪表板绑定到非环回主机时，Docker 入口点推断为 --insecure。这将“我想要 LAN 访问”与“我想要禁用同源防护”混为一谈。该修复将它们分开：绑定主机是绑定主机，禁用仪表板的环回身份验证需要显式的 HERMES_DASHBOARD_INSECURE=1。真正想要不安全绑定的现有设置现在必须设置环境变量。 (#34188、#34204 — @benbarclay)
  • Docker 下的 MCP 裸命令解析 — 配置了裸命令（npx、npm、node）的 MCP 服务器现在针对 /usr/local/bin 进行解析，因此它们实际上在这些二进制文件所在的 Docker 映像内启动。当代理的有效路径不包含节点工具链位置时，v0.15.0 会在容器中默默地留下这些失败。 (#34186 — @benbarclay)
  • 技能页面侧边栏/源药丸已恢复 - 新仪表板技能页面中过时的 useMemo 依赖项将源药丸和类别侧边栏折叠为仅“全部”。固定的;现在，两个表面都反映了实时目录状态。 (#34194)
  • 看板工作人员可能会再次被杀死 — 看板工作人员上的 SIGTERM 被中间流程吸收，并且工作人员保持运行。关闭 #28181。 (#34045)
  • 完整的 Skills.sh 目录（858 → 19,932 条条目） — 技能中心页面正在拉取部分分页目录。现在，提取会遍历站点地图，因此所有 19,932 个 Skills.sh 条目都会显示在选择器中，而不仅仅是前 858 个。(#34025)
