hermes-agent v2026.5.28

#爱马仕代理v0.15.0(v2026.5.28) 发布日期： 2026 年 5 月 28 日 自 v0.14.0 起： 1,302 次提交 · 747 个合并 PR · 1,746 个文件已更改 · 282,712 个插入 · 36,699 个删除 · 560 多个问题已关闭（15 个 P0、65 个 P1、19 个安全标记） · 321 个社区贡献者（包括共同作者）

速度释放。 Hermes 的启动、运行、交付工作和成长速度显着加快。在 14 个内聚的 agent/* 模块中，16,083 行 run_agent.py 缩减至 3,821 行（-76%）。看板发展成为一个跨 104 个 PR 的真正的多代理平台——编排器自动分解、群拓扑、计划任务、每个任务的工作树、每个任务模型覆盖。冷启动性能浪潮仍在继续：启动时间再次缩短，每次对话函数调用次数减少 47%，hermes --version 颠覆了 Codex CLI 的正面基准。 session_search 速度提高了 4,500 倍，而且现在免费。提示软件防御可抵御 Brainworm 级攻击。 Bitwarden Secrets Manager 用一个引导令牌替换了 N 个每个提供商的 API 密钥。技能包让一个斜杠命令加载整个工作流程。 Ink TUI 拥有多会话编排器。两个新的 image_gen 提供程序（Krea 2 Medium + Large、FAL 移植到插件）、Nous 批准的带有交互式选择器的 MCP 目录、OpenHands 编排技能、ntfy 作为第 23 个消息传递平台，以及一轮深度 xAI 集成（Web 搜索插件、xai-oauth hermes proxy 上游、15 月退役模型检测 + hermes migrate xai、自然 TTS 语音标签暂停、base_url 泄漏守卫，Grok 的 OpenAI 风格执行指南）。 15 个 P0 + 65 个 P1 关闭并排。

✨ 亮点

  • 大重构 — run_agent.py 不再是 16,000 行 — Hermes 的核心文件 — 代理对话循环 — 已从 16,083 行减少到 3,821 行 (-76%)，提取的代码 redis 分布在 agent/ 下的 14 个内聚模块中。行为保持不变：每次提取都会在 AIAgent 上保留一个瘦转发器，每个测试补丁路径仍然有效，每个外部调用者都是兼容的。你关心的原因是：未来的 Hermes 开发速度更快，插件作者终于可以 grep 代码库，并且在编辑器中加载需要 90 秒的文件眨眼间就会打开。 (#27248)
  • **看板成长为一个真正的多代理平台 - 104 个端到端 PR ** - 分类自动将一项任务分解为子任务树。 hermes kanban swarm 通过一个命令创建完整的 Swarm v1 图 - 根、并行工作线程、门控验证器、门控合成器、共享黑板。任务支持每个任务模型覆盖（用于样板的廉价模型，用于硬子任务的昂贵模型）、板级默认工作目录、每个任务工作树路径和分支、计划启动时间、可配置的声明 TTL、重试指纹识别、过时任务检测、重生防护和拖动删除垃圾区域。工作人员通过 /workers/active、/runs/{id} 和 /inspect 端点进行报告。 (#27572、#28443、#28364、#28394、#28462、#28384、 #28467、#28455、#28452、#28432、#28468、#28420)
  • 冷启动 perf wave 继续进行 - 又节省了一秒，每轮函数调用减少了 47% - 三轮新的优化：推迟 openai._base_client 导入（每次 CLI 调用 -240ms / -17MB），热路径优化减少 47% 的每次对话函数调用（31 回合聊天为 399k → 213k），推迟压缩可行性检查（每个代理构建时为 -170 到 -290 毫秒），自适应子进程轮询（每个工具调用 -195 毫秒，每轮 1+ 秒）。 Termux 冷启动时间从 2.9 秒降至 0.8 秒。 hermes --version 冷性能下降 63%（701ms → 258ms），将与 Codex CLI 的正面基准测试从 5/11 获胜变为 6/11。 (#28864、#28866、#28957、#29006、#29419、#30121、 #30609、#31968)
  • session_search 重建 - 没有 LLM，没有成本，速度提高了 4,500 倍 - 旧的 session_search 是一个辅助 LLM 驱动的工具，每次调用花费约 $0.30 并花费约 30 秒来总结三个会话，有时当正确的会话甚至不在 FTS5 命中列表中时会产生混乱。新形状是一种具有三种模式（发现、滚动、浏览）的工具，根据参数设置推断 - 没有 mode 参数，没有 aux-LLM，没有配置旋钮，没有配套技能。发现时间约为 20 毫秒，而不是约 90 秒；滚动约为 1 毫秒。现在可以免费且即时地搜索您过去的会话以获取背景信息。 (#27590)
  • Promptware 防御 — Brainworm 级攻击在三个阻塞点被阻止 — 受到最近 Brainworm / Promptware Kill Chain 研究（Origin HQ，arxiv 2601.09625）的启发，Hermes 现在可以保护上下文窗口免受提示注入攻击，这些攻击试图通过工具输出、回忆的内存或存储的技能来劫持代理。单一事实来源 (tools/threat_patterns.py)，具有约 15 种新的 Brainworm/C2 模式；在加载时扫描调用的内存；工具结果会获得分隔符标记，因此恶意文件或远程服务无法冒充 Hermes 自己的系统内容。与新的 security-guidance 插件配对，该插件可对危险代码写入进行模式匹配。 (#32269、#33131、#9151)
  • Bitwarden Secrets Manager — 一个引导令牌取代每个提供商的 API 密钥 — 停止在 ~/.hermes/.env 中保留明文 API 密钥。安装 Bitwarden Secrets Manager（bws 在第一次使用时自动延迟安装），用一个引导令牌 (BWS_ACCESS_TOKEN) 将 Hermes 指向它，您需要的每个凭证在启动时都来自 Bitwarden。在 Bitwarden Web 应用程序中轮换密钥，轮换实际上会生效 — Bitwarden 默认为真实来源，因此其值会在启动时覆盖匹配的环境变量。翻转 secrets.bitwarden.override_existing: false 以反转。支持 EU Cloud 和自托管 Bitwarden 服务器 URL。检测到的凭据现在标有其来源，因此您可以一目了然地看到哪些密钥来自 Bitwarden 与本地环境。 (#30035、#31378、#30364)
  • ntfy 作为第 23 个消息传递平台 — 无需帐户即可推送通知 — ntfy 是自托管推送通知服务，无需注册，无需 API 密钥，只需一个主题 URL。 Hermes 现在将其作为平台插件进行调整（对核心进行零编辑），因此您的代理可以将来自任何 cron 作业、看板任务完成或聊天 send_message 的推送通知发送到您的手机、手表、桌面、家庭实验室。 （打捞[#30625]（https://github.com/NousResearch/hermes-agent/pull/30625）→原来[#4043]（https://github.com/NousResearch/hermes-agent/pull/4043））（[#30867]（https://github.com/NousResearch/hermes-agent/pull/30867））
  • 技能包 - /<name> 一次加载多个技能 - 技能包是一组指定的技能，可以使用一个斜线命令将它们全部加载。设置您的“写作日”捆绑包（人性化 + 构思 + 黑曜石 + youtube 内容），/writing-day 会激活该会话的所有四个。技能中心现在有健康检查、新鲜度徽章和看门狗 cron。三个新的可选技能落地：code-wiki（Karpathy 的 LLM-Wiki，持久索引开发 wiki）、openhands（委托给 OpenHands 并行编码代理）和 web-pentest（OWASP 风格的 Web 渗透测试配方）。 (#28373、#32345、#32240、#32261、#32265)
  • TUI 会话编排器 — 一个 TUI 窗口中的多个实时会话 — Ink TUI 获得了活动会话切换器叠加层。无需离开 TUI，即可列出、切换、刷新和关闭多个实时进程本地会话；使用会话范围的模型选择器调度一个新会话。再加上一波 TUI 改进 — 鼠标跟踪 DEC 模式预设、跨分支和 termux 的回滚保留、斜线下拉修复、x.com 链接渲染以及 CJK / IME 输入渲染改进。 （打捞[#27642]（https://github.com/NousResearch/hermes-agent/pull/27642））（[#32980]（https://github.com/NousResearch/hermes-agent/pull/32980），[#30084]（https://github.com/NousResearch/hermes-agent/pull/30084））

  • Nous 批准的带有交互式选择器的 MCP 目录 — 经过 Nous 审查的 MCP 服务器的精选目录，反映了可选技能的形状。运行hermes mcp，你会得到一个交互式选择器；一键安装，安装时提示凭据并写入 ~/.hermes/.env。首先随 n8n 清单一起提供。弥补了用户为 trusted MCP 服务器寻找 GitHub 的发现差距。 (#30870)

    • xai-oauth base_url 固定到 x.ai 原点 — 关闭静默凭证泄漏向量，其中 XAI_BASE_URL 可以将经过 OAuth 验证的推理重新指向攻击者控制的主机。 (#28952)
