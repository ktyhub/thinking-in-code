redis 8.12-rc1

这是 Redis 开源中 Redis 8.12 的第一个候选版本。

候选版本是功能完整的预版本。预发布版本不适合生产使用。

标题：

Redis 8.12 引入了新功能和性能改进。

我们测试 Redis 8.12 的操作系统

  • Ubuntu 22.04（果酱水母）、24.04（高贵食蚁兽）、26.04（坚决浣熊）
  • Rocky Linux 8.10、9.7、10.1
  • AlmaLinux 8.10、9.7、10.1
  • Debian 12.13 (书虫), Debian 13.4 (Trixie)
  • 阿尔派 3.23
  • macOS 14.8.4 (Sonoma)、15.7.4 (Sequoia)、26.3 (Tahoe) - 适用于 Intel 和 ARM

安全修复

  • RediSearch/RediSearch#10073 索引值哈希现在具有抗冲突性，可防止对抗性输入造成 HashDoS 式索引降级。 (MOD-14459)
  • RediSearch/RediSearch#11202 不完整的 UTF-8 字符不再在索引文本字段中超出范围读取。 （MOD-18088）

新功能

  • #15331 压缩位图 — 将 redis-roaring 集成到 Redis 核心中，以降低内存使用量并加快位图操作。 特别感谢redis-咆哮的原创者Antonio贡献了这个能力！ https://redisroaring.com/redis-merge/#/1;
  • #15986 新命令：BITRANGEINTARRAY 相当于 redis-roaring 的 R.RANGEINTARRAY，返回指定范围内的设置位偏移量
  • #15938 设置单个集合成员的过期时间；新命令：SEXPIRE、SPEXPIRE、SEXPIREAT、SPEXPIREAT 用于设置过期时间，STTL、SPTTL、SEXPIRETIME、SPEXPIRETIME 用于检索剩余 TTL 或过期时间戳
  • #15649 Bless 键：避免驱逐指定键；新命令：BLESS
  • #15829 CLUSTER MIGRATION STATUS 现在报告快照和增量迁移阶段的进度
  • #15556 TLS 命名组现在可以使用 tls-groups 进行配置
  • RedisBloom/RedisBloom#1063 Count-min-sketch 扩展：为 CMS.INITBYDIM 和 CMS.INITBYPROB 添加了可选的 CELL_SIZE 支持以降低内存使用量、CMS.INCRBY 中的负增量以减少计数以及 CMS.INFO 中的单元格大小报告
  • RedisJSON/RedisJSON#1640 自动创建 JSON 深度路径
  • RediSearch/RediSearch#10151 FT.HYBRID 现在支持 EXPLAINSCORE。 (MOD-10044)
  • RediSearch/RediSearch#11330 SQ8 新压缩现在可用于 HNSW 矢量场。 (MOD-6132)
  • RediSearch/RediSearch#10247 现在为本地 FT.HYBRID 执行启用 RETURN_STRICT 超时处理。 (MOD-16492)
  • RediSearch/RediSearch#11278 FT.ALTER 避免在架构添加期间不必要的文档重新索引。 （MOD-18171）
  • RediSearch/RediSearch#11384 仅分数/有效负载哈希更新避免重新索引。 （MOD-18182）
  • RediSearch/RediSearch#11230 当没有触及矢量索引字段时，哈希文档不再重新索引。 (MOD-17688)

错误修复

  • #15569 XDELEX DELREF 对已删除的流条目所做的更改可能无法传播到副本或 AOF
  • #15508 从某些叶节点开始时，使用随机基数树遍历的操作可能会表现不正确
  • #15604 使用共享模板的哈希值可能会错误地计算内存使用量
  • #15489 XSETID 减少流的条目添加计数器后，RDB 文件可能无法加载
  • #15626 当给定过大的相对 TTL 时，SET 可能会计算出不正确的过期时间
  • #15628 主动碎片整理可能会错误地处理紧凑哈希使用的共享模板注册表
  • #15530 故障转移后，副本可以保持连接到另一个副本而不是新的主副本
  • #15733 无效的集群槽范围在合并到有效范围后可以被接受
  • #15756 当给定过大的相对 TTL 时，RESTORE 可能会计算出不正确的过期时间
  • #15699 当 SETBIT 或 BITFIELD 扩展字符串时，内存增长可能会被错误地解释
  • #15815 XTRIM 可能会使流处于阻止加载包含该流的 RDB 文件的状态
  • #15795 当格式错误的命令通过多个网络读取到达时，Clients 可能无法接收协议错误
  • #15875 ARLASTITEMS 可以省略出现在数组中间隙之后的元素
  • #15916 在加载完成之前升级旧版 AOF 文件时，数据可能会丢失
  • #15917 Linux 上的 Hiredis clients 在建立 TCP 连接时可能会错误处理错误
  • #15869 当模块线程暂停 I/O 线程时，Redis 可能会崩溃
  • #15468 - 如果 client 已重新验证为另一个用户，则在订阅用户的频道权限被撤销或用户被删除后，Pub/Sub 订阅可以保持活动状态。
  • #15623 字段在后台过期后，由哈希字段过期通知安排的模块操作可能会延迟
  • #15680 副本迁移到不同分片后数据可能会丢失
  • #15587 LMOVEM 可能会发出与 LMOVE 生成的密钥空间通知不一致的密钥空间通知
  • #15695 命令副作用可能会传播到副本或 AOF，尽管设置应该排除它们
  • RediSearch/RediSearch#10872 当旧版 ft_index0 有效负载的 RESTORE 在 RDB 负载之外发出时，碎片不再因 SIGSEGV 而崩溃。 (MOD-15685)
  • RediSearch/RediSearch#10728 GC 计时器在 ARM 上关闭主线程，在延长正常运行时间后不再导致随机碎片崩溃。 （MOD-17309）
  • RediSearch/RediSearch#10767 当索引 FILTER 未引用架构字段时，服务器不再在写入时崩溃。 （MOD-15592）
  • RediSearch/RediSearch#11303、RediSearch/RediSearch#11304、RediSearch/RediSearch#11308、RediSearch/RediSearch#11309、 RediSearch/RediSearch#11310、RediSearch/RediSearch#11311 FT.ALTER SCHEMA ADD 与 WORKERS>0 下的查询并发运行不再导致跨 VECTOR、TAG、NUMERIC、GEO、ISMISSING 和 GEOSHAPE 节点的查询执行崩溃。 （MOD-18356、MOD-18361、MOD-18366、MOD-18367、MOD-18368）
  • RediSearch/RediSearch#11474 FT.AGGREGATE 与数字 SORTBY 优化器不再崩溃
