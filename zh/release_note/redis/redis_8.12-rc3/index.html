redis 8.12-rc3

这是 Redis 开源中 Redis 8.12 的第三个候选版本。

候选版本是功能完整的预版本。预发布版本不适合生产使用。

安全修复

  • #16127 TLS 会话可以在另一个侦听器上恢复（client 端口与集群总线），或者在 tls-auth-clients 或 tls-expected-peer-name 更改后，无需检查新设置

新功能

  • #16135 新命令：ZMOVE、BZMOVE、ZMOVEMEMBER 在排序集之间自动移动成员 - 从任一端、按分数范围或按名称 - 使用 COUNT 批处理和 NX/XX 目标条件
  • #15907 SLOWLOG GET 现在报告每个慢速命令的 CPU 时间（新的第 8 个字段），以区分运行缓慢的命令和 CPU 不足的命令；新配置参数：off-cpu-tracking

模块 API

  • #16105 RedisModule_GetUsedMemoryRatioEstimate - 与 RedisModule_GetUsedMemoryRatio 类似，但可以从模块线程调用而无需持有 GIL

错误修复

  • #16098 即使 repl-backlog-size 较大，落后超过其输出缓冲区软限制的副本也会断开连接
  • #16176 当目标拒绝命令时，原子槽迁移期间密钥可能会丢失（例如，由于 min-replicas-to-write 导致 -NOREPLICAS）
  • #16210 在原子槽迁移期间，集合成员可能在目标上错误地过期
  • #16096 具有重复 EX 或 PX 选项的 MSETEX 被传播到副本和 AOF 作为无效命令，丢失密钥
  • #16175 当 AOF 写入错误（例如磁盘已满）后开始 AOF 重写时，命令可以在 AOF 加载时重播两次
  • #15955 带有 IDMP 的 XADD 条目可能会在 AOF 重播或滞后副本上丢失，并且 XIDMPRECORD 可能会使滞后副本崩溃
  • #15930 由 XCLAIM 或 XAUTOCLAIM 创建的声称没有条目的消费者不会传播到副本或 AOF
  • #16121 某些密钥更新可能会在调整密钥空间大小时将值或 TTL 应用于不同的密钥
  • #16042 当运行使用 getkeys-api 或 getchannels-api 的模块命令时，Redis 可能会因 io-threads > 1 而崩溃
  • #16165 当模块从其键空间通知中读取由 ZPOPMIN/ZPOPMAX 清空的排序集时，Redis 可能会崩溃
  • #16125 当启用 key-memory-histograms 或 cluster-slot-stats-enabled 时，具有相同源密钥和目标密钥的 ZRANGESTORE 可能会导致释放后使用
  • #16167 当源是从无序负载加载的列表包时，ZRANGESTORE 可以创建一个分数顺序被破坏的排序集
  • #16164 不使用 sanitize-dump-payload 恢复的排序集在转换为 B+tree 编码后可以存储重复成员两次
  • #16146 格式错误的 RESTORE 有效负载或 RDB 文件可能会损坏内存（仅适用于注册关键元数据类的模块）
  • #16142 CONFIG GET 和 CONFIG REWRITE 在设置 A 时删除了 notify-keyspace-events 的 n、o 和 c 标志，因此这些事件在重新启动后停止
  • #16120 DELEX 授予 lazyfree-lazy-server-del 而不是 lazyfree-lazy-user-del
  • #16203 具有非常深的字符串模式的 Lua 脚本可能会耗尽堆栈；这种模式现在会因 pattern too complex 而失败
  • #16233 当 preload-file 与 AOF 和 1024 字节或更长的工作目录一起使用时，Redis 可能会崩溃
  • #16062 在 FreeBSD 上，捆绑的 jemalloc 接管了 libc 的 malloc 钩子，这可能会使多线程工具（例如 redis-benchmark --threads）崩溃并在 fork() 之后出现死锁
  • #16117 redis-cli 可能会从具有极端参数值的 COMMAND 回复中生成过多的帮助条目
  • #15823 当没有找到键时，redis-cli --keystats 打印空统计信息

性能和资源利用率改进

  • #15622 SORT 和 SORT_RO 不再将 listpack 编码的排序集转换为 B+tree，这增加了它们的内存使用量（也在只读副本上）
  • #16163 将排序集转换为 B+tree 的 ZADD 不再留下过大的成员索引，这会浪费内存并减慢 ZSCAN 的速度
  • #16069 Client 内存（tot-mem、mem_clients_normal、maxmemory-clients）现在包括监视键以及 Pub/Sub 通道和模式的名称
  • #16126 更快的 ZRANGESTORE 适用于较大的 REV 等级范围
  • #16156 更快的 ZRANDMEMBER，B+树排序集上有大量正数
  • #15420 更快的 SRANDMEMBER，对哈希表编码集进行正计数
  • #15901 listpack 编码哈希上的字段过期的 HEXPIRE 和 HSETEX 更新更快
