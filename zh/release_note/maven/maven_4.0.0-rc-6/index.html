maven 4.0.0-rc-6

预发布 发布时间2026年7月30日 来源apache/maven 英文原文

maven 4.0.0-rc-6

注释

Maven 4 的这个新候选版本发布是为了收集用户的反馈。 与 Maven 3 相比，Maven 4 有一些限制，因此请确保在使用 Maven 4 尝试您的项目之前运行 mvnup 工具。

自 RC-5 以来已修复的问题

RC-5 release note 中报告的所有已知问题均已修复：

  • Bean 配置错误 — 字段可访问性状态被全局缓存，导致插件配置注入失败。已修复#11433。
  • v4 API 中的并发问题 — ConcurrentModificationException 已在 #11429 中修复。
  • BOM 打包 — BOM 项目的消费者 POM 转换现在可以正确保留依赖项版本。已修复#11464。
  • macOS Gatekeeper — 提取的触发 Gatekeeper 的 JLine 本机二进制文件已从发行版中删除 (#11997)。不再需要 RC-5 中的 xattr 解决方法。

已知的兼容性问题

以下是使用 Maven 4 时的已知兼容性问题。 mvnup 在构建之前 Maven 4 将自动修复许多常见的插件版本问题。问题 以下是需要手动干预或上游修复的问题。

更严格的 POM 验证

Maven 4 强制执行比 Maven 3 更严格的验证。项目可能需要修复其 POM：

  • 重复的 XML 元素 — 重复的 <artifactId>、<properties> 等现在被拒绝（Duplicated tag 错误）。修复源 POM。
  • 重复的依赖关系声明 — 声明两次的相同 groupId:artifactId 现在被拒绝 (must be unique)。
  • 未插值表达式 — 存储库 URL、分发管理 ID 和 Maven 3 默默接受的其他字段中的 ${...} 表达式现在被拒绝。
  • 传递 POM 中的无效 XML — 传递 POM 中的非法处理指令或未声明的命名空间前缀会导致 Non-parseable POM 错误。
  • <module> 路径中的属性 — Maven 4 不再在 POM 读取时在 <module> 元素中插入 ${spark.version} 等属性。
  • CI 友好版本 — 使用 ${revision} 而不使用 flatten-maven-plugin 的项目可能会遇到缺少依赖项版本错误。
  • 无效的收集请求 — 与未插值的 ${...} 版本表达式的传递依赖关系被拒绝。

传递依赖解析更改

Maven 4 的 TransitiveDependencyManager 在所有传递深度应用 dependencyManagement （Maven 3 仅在第一层应用它）。这是故意的，但可以更改已解决的版本：

  • 先前对类路径的依赖关系可能会消失 - 添加显式声明。请参阅 #12302。
  • maven-enforcer-plugin版本规则可能会因传递版本降级而触发。
  • license-maven-plugin 可能会报告不在允许列表中的新传递依赖项。
  • 由于 OSGi 捆绑包版本不匹配，Karaf 功能验证可能会失败。

插件和扩展兼容性

某些插件和扩展需要 Maven 4 的特定版本：

  • Quarkus — 3.20 之前的版本使用与 Maven 4 的基于 Sisu 的 DI 不兼容的 ServiceLocator/RepositorySystem 模式。升级至Quarkus 3.20+。
  • Tycho — 5.0 之前的版本使用 Maven 4 破坏的 Guice/Sisu 注入模式。升级到 Tycho 5.0.3+。
  • Develocity Maven 扩展 — 由于 SLF4J 类加载更改 (ClassNotFoundException: SimpleLogger) 而无法初始化。
  • pgpverify-maven-plugin — 1.20 使用 Maven 4 解析器命中 ClassCastException 之前的版本。请参阅 resolver#1957。
  • cyclonedx-maven-plugin — 使用 ${revision} CI 友好版本时，Invalid Version Range Request 失败。
  • maven-site-plugin — Velocity 模板渲染可能因站点插件版本不兼容而失败。
  • maven-shade-plugin — dependency-reduced-pom.xml 可能会导致 The parents form a cycle 错误。
  • commons-release-plugin — clean-staging 在 Maven 4 下失败。

类加载变化

  • 依赖 Maven 3 的类域布局的插件可能会遇到 “外部导入” 错误（例如，Quarkus、JAXB 插件）。
  • Maven 4 基于前缀的存储库路由可能会阻止与 /.meta/prefixes.txt 不匹配的工件。

mvnup 后格式化

  • spotless-maven-plugin 和 sortpom-maven-plugin 可能会在 mvnup 修改 POM 文件后报告格式违规。在 mvnup 之后重新运行格式化程序。

####其他

  • 上游 POM 损坏 — 例如，hadoop-project 3.1.0–3.3.0 具有无效的 XML (<Xlint:-unchecked/>)，导致解析错误。这些需要在 HADOOP-19923 中跟踪的上游修复。
  • Enforcer POM 元素排序 — Maven 4 的模型构建器将 POM 元素重新排序为规范顺序，这可能会破坏检查元素排序的执行器规则。
  • SNAPSHOT 处理 — 在 Maven 4 的不同解析器元数据处理下，SNAPSHOT 工件可能显示为“存在，但不可用”。

🚀 新功能和改进

  • 向后移植使用硬链接而不是文件副本（#11564）@desruisseaux
  • 接受Java模块名称作为附加的artifactId，即使它们与项目的artifactId不同（#11573）@desruisseaux
  • 为模块化源添加模块感知资源处理（#11700）@desruisseaux
  • [MNG-8507] - 减少模型构建管道中的分配压力 (#12540) @gnodet
  • [向后移植 4.0.x] 修复 #12530：添加 mvnup 升级
