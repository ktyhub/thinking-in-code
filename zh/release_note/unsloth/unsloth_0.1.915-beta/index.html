unsloth v0.1.915-beta

预发布 发布时间2026年11月4日 来源unslothai/unsloth 英文原文

unsloth v0.1.915-beta

此版本引入了 Qwen3.8-Flash-Next Dynamic V3.1，完善了 Glass 主题（现在处于测试版），添加了 Composer 位置滑块，并允许模型与内置浏览器中的文件进行交互。它还带来更低的空闲内存使用量、切换 GGUF 模型时保留的聊天上下文、更快的 MLX 加载和 FP8 LoRA 训练。

亮点

  • Qwen3.8-Flash-Next Dynamic V3.1 - 10-15% 额外精度 指南
  • 跨页面、菜单、侧边栏和浏览器的 Glass 主题改进
  • 浏览器文件交互让型号 click 读取和编辑 HTML、文件和页面
  • 更低的空闲内存以及更快的 MLX 加载和重新加载
  • 在 GGUF 模型之间切换时保留聊天上下文
  • FP8 LoRA 训练，GPU 内存使用率较低
  • 作曲家位置滑块可将聊天框放置在新聊天中的任何位置

玻璃和外观

  • 在 设置 > 外观 > 编辑器 中从上到下设置聊天框位置。
  • 玻璃主题现在在菜单、面板和浏览器中具有更柔和的高光、更浅的阴影和改进的磨砂效果。
  • 图书馆、图像和火车等页面不再严重模糊背景图像。
  • 开放式对话现在背景稍微变暗，并为作曲家使用更密集的玻璃。
  • Windows 和 Linux 标题栏更好地匹配 Glass 主题和背景图像。
  • 在一个浏览器选项卡中进行的设置更改现在可以在其他打开的选项卡之间同步。

内置浏览器

  • 启用浏览器使用后，模型可以 click 并输入在聊天中创建的 HTML 和 React 页面。
  • 模型可以直接在浏览器中读取和编辑 HTML、React、Markdown、代码和文本文件。 返回 恢复之前的版本。
  • 模型还可以阅读在浏览器中打开的 PDF 和其他文档。
  • 下载提示可以记住每个站点或所有站点的权限，包括程序文件的权限。

聊天

  • 聊天现在显示工具调用之间的活动，包括 GGUF 模型上的上下文压缩。
  • 使用 + > 更多 > 从库附加来附加已保存的库文件。
  • 从 GGUF 模型切换回来现在可以保留聊天上下文，避免需要重新阅读长历史记录。
  • 当工具运行时，GGUF 模型无需询问即可一次读取最多四个网页。

连接和 API

  • OpenRouter 模型现在可以实时加载，并支持重新加载模型。
  • 改进了与较新的 MCP 服务器的兼容性。
  • Decision API 添加了 LiquidAI 的 d1 模型和 Decider 2B（仅限 MLX）。
  • 设置 > API > 快速入门现在包括curl、Python 和JavaScript 示例。

表演和媒体

  • Unsloth 启动时不再加载 PyTorch 和其他 ML 库，显着减少空闲内存使用。在 设置 > 常规 > 启动性能 中配置启动功能。
  • MLX 模型加载和重新加载速度更快，减少加载模型的上下文现在只需几秒钟。
  • 支持的 MLX 型号上的长提示使用更少的内存。
  • SDXL 在非常有限的 VRAM（包括 4 GB 设置）下渲染速度更快。
  • 模型文件夹中的图像 LoRA 现在显示在图像页面上。

培训

  • 使用 float8_training = "fp8_lora" 的最新 NVIDIA GPU 在 16 位基础上进行更快、内存更低的 LoRA 训练。
  • DPO、ORPO、KTO、GRPO 和 CPO 培训现在在 MLX 上运行。
  • 修复了在 float16 中完全微调 Gemma 4 时的崩溃问题。

修剪重叠的高光项目符号组合相关的玻璃项目符号
