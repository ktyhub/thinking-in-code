unsloth v0.1.917-beta

预发布 发布时间2026年11月11日 来源unslothai/unsloth 英文原文

unsloth v0.1.917-beta

Qwen3.8-27B 带有动态 v3.1 GGUF，可以使用 Unsloth 在本地运行。此版本还带来了重大性能改进、更流畅的 Glass 渲染、改进的代码块和 Thinking UI、HTML/PDF 聊天导出以及新的图像生成和编码代理功能。

亮点

  • 新 Qwen3.8-27B 动态 v3.1 GGUF。
  • 更快的聊天： 对流式传输、滚动、菜单和对话框的性能进行了重大改进，尤其是在长时间对话中。
  • 更光滑的玻璃： 减少打字、滚动和生成时的延迟。
  • 改进的代码块和思考： 独立滚动、可扩展的面板，具有改进的语法突出显示。
  • HTML 和 PDF 导出： 直接从聊天菜单导出聊天。
  • 图像队列： 在另一个图像正在渲染时对即将到来的图像生成进行排队。
  • MLX 上的 Claude Code 和 Codex： 通过 unsloth start 使用 MLX 模型运行编码代理。

聊天和用户界面

  • 流媒体性能不再随着对话的增长而降低。
  • 背景图像滚动更流畅，无论有或没有玻璃。
  • 更快的菜单、对话框和浏览器窗格加载。
  • 从第一句话后开始朗读，而不是等待整个回答。
  • 聊天首选项、时间格式和拼写检查现在与您的帐户同步。

图片和视频

  • FLUX.2 和 FLUX.3 在图像解码期间以相同速度使用 36–43% 的 VRAM。
  • 从图像页面或 API 排队图像生成。
  • INT8 和 FP8 图像模型现在可以在较旧的 NVIDIA GPU 上加载，包括 T4。
  • 修复了 FLUX.3 的黑色图像输出。
  • LTX-2.5 FP8 现在在 24 GB GPU 上运行。
  • Cosmos3-Nano 可以从第一帧或最后一帧继续视频 clips。

编码剂 & API

  • 使用 unsloth start 在 Mac 上使用 MLX 模型运行 Claude Code 和 Codex。
  • 新的 Unsloth MCP 预设允许编码代理访问 Unsloth 工具。
  • 没有明确代币限制的 Claude API 模型不再停留在 1,024 个代币。
  • MLX 模型现在返回正确的上下文长度错误，而不是空响应。

培训

  • 默认情况下，在 FastModel 模型中，model.generate() 现在在 T4 GPU 上快 2-8 倍。
  • 训练视觉模型时现在可以正确支持视频列。
  • Ulysses 上下文并行性现在支持 Kimi-Linear、DeepSeek、MiniMax 和 Gemma 4 文本模型。
