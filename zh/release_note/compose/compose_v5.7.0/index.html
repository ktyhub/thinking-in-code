compose v5.7.0

小版本 发布时间2026年11月2日 来源docker/compose 英文原文

compose v5.7.0

发生了什么变化

ℹ️ Compose 作为库的用户请注意： Up 现在将其创建和启动阶段作为 单个守护程序快照上的单个计划运行，对于 up -d (#14290) 和交互式 up (#14305)，作为 scale，监视重建和start 已经这样做了（#14291、#14296）。 CLI 的行为与以前一样。如果您从自己的程序中调用 api.Compose.Up：

  • Up 现在首先验证其选项，规则与 CLI 标志相同：对于与 Start.Attach 组合的 Start.Wait，以及与 OnExit、ExitCodeFrom 组合的分离 Up（无 Start.Attach），UpOptions.Validate() 返回 *api.IncompatibleOptionsError (errors.Is(err, api.ErrIncompatibleOptions)) Watch。这些组合过去常常被默默地忽略（#14306）。
  • Up 适用于给定的项目并忽略 StartOptions.Project。
  • 在两个阶段之间不会再次观察到守护进程：计划构建后退出的容器不会再次启动，并且中间删除的容器会使其启动失败而不是被跳过。现在，在创建任何容器之前，开始阶段的计划错误会失败。
  • 前台 Up 现在为 use_api_socket 服务提供 /run/secrets/docker/config.json，就像 up -d 所做的那样，并显示 pre_start 挂钩的输出。
  • 交互式 up 的键盘菜单不再由库构建：设置 NavigationMenu: true 并通过 compose.WithNavigationMenu(...) 传递实现，否则不会显示菜单并发出警告（#14324）。

此版本中对库表面的其他更改：DownOptions.Images 现在是 api.ImagePruneMode（无类型常量仍然可以编译，string 变量需要转换），并且在 Down 删除任何内容之前拒绝无效值（#14149）； compose.ServiceHash、compose.NetworkHash 和 compose.VolumeHash 不再导出，助手已移至内部包（#14405）； api.Compose 现在由六个较小的接口组装而成，具有相同的方法集（#14322）；添加了PushOptions.IgnoreMissing。
