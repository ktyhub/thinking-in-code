Scrapling v0.5

Scrapling v0.5 几乎升级了所有内容：获取、解析、蜘蛛、浏览器自动化、AI 工具和十种语言的文档 🚀

[!注意] 在 X 上关注我们，获取日常提示和技巧

[!警告] 此版本引入了许多不适合此处的重大更改。更新前请检查迁移到 v0.5 指南。

🚀 新事物和生活质量的变化

  • 用于 AI 代理的功能更强大的 MCP 服务器，可以解决几乎任何验证码（查看 文档）：

    • 完整的浏览器工作流程：填写表单、click、悬停、滚动、使用键盘、处理对话框，并按顺序等待结果。支持不同的字段类型和较慢的交互，操作在第一个错误处停止。
    • 阅读和搜索当前页面而无需重新加载：从整个页面或一个元素中提取 HTML、Markdown 或文本。可搜索的页面快照显示元素角色、名称和位置，以及保留周围上下文的聚焦视图。
    • 运行自定义 JavaScript 并进行重点屏幕截图：执行脚本，包括异步工作，并可以访问页面自己的 JavaScript。以 PNG 或 JPEG 格式捕获单个元素、视口或整个页面。
    • 检查网络活动并重用登录：检查记录的请求和响应，保存和恢复浏览器登录状态，并与打开或关闭的 Shadow DOM 内的元素进行交互。在关闭会话之前读取记录的流量。
    • 使用更少的令牌并获得更清晰的错误：更精简的工具描述和共享指南减少了重复的文本，而浏览器和请求失败会向代理发送有用的错误消息。

  • 查看页面后面的请求。启用 record_requests=True 来记录跨负载、操作和选项卡的完整流量，然后检查保存的响应，而无需再次发送请求。 （查看文档）

    from scrapling.fetchers import StealthySession

with StealthySession(record_requests=True) as session:
    session.fetch("https://example.com", network_idle=True)
    for response in session.network.search(url_pattern=r"/api/", limit=None):
        print(response.url, response.status, response.body)
    • 按 URL、方法、资源类型或状态过滤；通过 ID 检索一个响应。通过通常的 Response API 检查标头、发送的数据、API 响应、HTTP 错误和重定向。
    • 保留受支持的文本正文（有大小限制）、元数据以及无法保存正文的原因。默认限制为 1,000 个请求。适用于同步和异步会话；保存的 Python 历史记录在关闭后仍可读。

  • 保存登录一次并在运行中重复使用。 save_state(path) 和 load_state(path) 将 cookie、本地存储和 IndexedDB 保存在与 Playwright 兼容的 JSON 中。同步和异步浏览器会话都支持它们。 （查看文档）

    • 在获取或重新加载页面之前加载状态。需要一个启动的、共享的浏览器上下文，没有 proxy_rotator；选项卡、浏览器设置和 sessionStorage 不会保存。

  • 使用 pierce_shadow=True 提取打开的 Shadow DOM，然后照常使用 CSS 或 XPath。在浏览器获取器、会话和 CLI 的 --pierce-shadow 选项中可用。保留插槽内容而不更改实时页面。 HTML 捕获不包括封闭根和 iframe 文档。 （查看文档）

  • 选择您的蜘蛛探索站点的方式。 CrawlSpider 及其子类（包括 ContentSpider）支持 crawl_strategy="bfs" 进行最早的优先调度或 "dfs" 进行最新的优先调度。优先级仍然获胜，并且并发页面可以以不同的顺序完成。 （查看文档）

🐛 错误修复

  • 通过延迟小部件检测、减少不必要的等待以及有界被动挑战和隐藏帧重试循环，改进了 Cloudflare 解决方案。修复 #468 和 #509。

  • 修复了从提升的 Windows shell 启动浏览器的问题。修复#463。

  • 在添加自定义浏览器标志时保留内置隐形标志，由 @alkaz-nodemaven 在 #430 中实现。

  • 改进了浏览器响应的字符集解析，包括具有不同字母大小写、空格或引用值的声明。

  • 当不需要解决挑战时，停止将缺少 Cloudflare 挑战记录为错误。修复#459。

  • 更正了 #448 中 @yetval 的查询参数的请求指纹，#480 中 @ac1982 的空或虚假 JSON 主体，以及 #466 中 @SarwadnyaMahajan 的标头插入顺序。

  • 修复了泄漏到后续链接中的请求数据，包括过时的正文相关标头，由 @yetval 在 #462 中完成。

  • 防止被阻止的响应被存储为成功的开发缓存条目，由@Kuang-xianxin 在 #446 中实现。

  • 当爬网因异常而失败时保留检查点文件，由 @SulimanAbdulrazzaq 在 #486 中编写。

  • 更正了 robots.txt 失败处理，因此失败的查找不会缓存为爬行权限，由 @prateekraawat1 在 [#443](https://github.com/D4Vinci/Scrapli
