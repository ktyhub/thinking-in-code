Scrapling v0.4.15

今年最大的版本之一：重新设计的 MCP 服务器、RAG-ready Markdown 一行、改进的 Cloudflare 求解器以及保持打开状态以实现自动化的浏览器选项卡 🚀

[!注意] 在 X 上关注我们，获取日常提示和技巧

[!警告] 此版本引入了对 MCP 服务器的重大更改。更新前请检查重大更改 部分。

🚀 新事物和生活质量的变化

  • 浏览器选项卡现在保持打开状态并可以在请求之间重用（查看 文档）：
    • 所有浏览器会话在发出请求后都会保留其选项卡，并且下一个请求会重复使用空闲选项卡，而不是打开新选项卡。
    • 每个请求都会将自己的设置（超时、标头、资源阻塞）重新应用到它获取的选项卡，因此请求之间不会发生任何泄漏。
    • 出现错误的选项卡将被关闭并替换，新的 close_pages() 方法会关闭每个打开的选项卡。
    • 您获取的页面保持加载状态，因此下一个请求的 page_setup 函数会在离开之前在该页面上运行。这是跨请求链接自动化的构建块。
  • 使用 Response.markdown() 将任何页面变成干净的、LLM 就绪的 Markdown （查看 文档）： 
    from scrapling.fetchers import Fetcher

markdown = Fetcher.get("https://example.com").markdown(main_content_only=True)
    • 脚本、样式和隐藏的提示注入内容始终首先被删除，与清理 MCP 服务器的操作相同。
    • 通过 css_selector 仅转换您需要的元素。
    • 通过新的 rag extra (pip install "scrapling[rag]") 提供，ai/shell/all extras 也包括在内。
  • 新的 SiteToMarkdownSpider 模板可将整个网站抓取到 RAG 管道的 Markdown 语料库中（查看 文档）： 
    from scrapling.spiders import SiteToMarkdownSpider

class DocsSpider(SiteToMarkdownSpider):
    name = "docs"
    start_urls = ["https://example.com/docs/"]
    allowed_domains = {"example.com"}
    output_dir = "docs_markdown"

result = DocsSpider().start()
result.items.to_jsonl("docs.jsonl")
    • url/title/markdown 每页生成一项，可选的 output_dir 每页写入一个 Markdown 文件。
    • max_pages 限制了爬行，并且由于它基于 CrawlSpider 构建，因此覆盖 rules() 可以让您完全控制要跟踪的链接。
  • MCP 服务器已重新设计（中断） （检查 中断更改 和 文档）：
    • 这 13 个工具现在分为两种模式：一次性工具（fetch、bulk_fetch、stealthy_fetch、bulk_stealthy_fetch）始终启动自己的浏览器并显示其真实默认设置，以及通过打开一次会话进行工作的会话工具。
    • 新的 session_fetch 工具通过浏览器会话获取，而 open_session 现在仅保存浏览器级设置，并返回会话的 AI 代理的有效设置。
    • get 工具已重命名为 make_request，现在支持任何 HTTP 方法。
    • 新的 open_request_session 和 session_make_request 工具为 AI 提供持久 HTTP 会话，在请求之间保留 cookie 和浏览器指纹。
    • 这也结束了重置会话设置的获取，首先由 @Yigtwxx 在 #418 中修复。
  • MCP 服务器的 HTTP 传输现在需要身份验证并默认绑定到本地主机（破坏） 由 @yamantaka-singh 在 #414 中实现（修复 #413，检查 文档）：
    • 传递 --auth-token（或 SCRAPLING_MCP_AUTH_TOKEN 环境变量）以要求持有者令牌，或传递 --no-auth 以故意未经身份验证地提供服务。
    • 通过 --host 0.0.0.0 接受来自网络的连接。

🐛 错误修复

  • Cloudflare Turnstile/Interstitial 解决现在无论浏览器区域设置如何都可以工作，并且不再在无头模式下永远循环交互挑战。隐形页面也能在解决过程中停止崩溃，这得益于 @subediparas5 在 #412 中的贡献。 （修复 #411 和 #422）
  • 在 #410 中通过 @yetval 修复了 find/find_all 和 class_ 静默丢失多类元素，以及在 #417 中通过@yamantaka-singh 修复了空白 class_ 值和未转义的 CSS 字符串值**。
  • 修复了 development_mode 中的缓存响应在重播时丢失请求元的问题，由 @Yigtwxx 在 #419 中实现。
  • 修复了 retries 低于 1 的 HTTP 请求在不发送请求的情况下失败的问题，由 @Yigtwxx 在 #420 中完成。
