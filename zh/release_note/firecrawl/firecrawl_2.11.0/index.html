firecrawl v2.11.0

小版本 发布时间2026年6月19日 来源firecrawl/firecrawl 英文原文

firecrawl v2.11.0

改进

  • Firecrawl 研究索引 — 为代理 AI/ML 研究添加了专门索引：搜索 3M+ arXiv 论文及其背后的 GitHub 代码（问题、合并的 PR 和自述文件，每日刷新），获取论文的详细信息或相关工作，并对照全文检查声明。它在 arXivQA 上拥有最先进的召回率，在同等成本下，其性能比第二佳提供商高出 18%。通过 API、SDK、MCP 和 CLI 提供。
  • 核心端点的无钥匙访问 — 使用 /scrape、/search、/interact 和 /parse，无需官方 MCP、CLI 和 SDK clients 的 API 密钥。
  • 自动 PII 编辑 — 添加了 redactPII 选项，可在返回之前从已抓取的内容中删除个人和敏感数据（例如姓名、电子邮件、电话号码、地址和机密）。
  • deterministicJson 格式 — 添加了一种返回结构化 JSON 的格式，而无需在每个请求上运行 LLM。 Firecrawl 会为您的架构生成一个可重用的提取器，并将其缓存在每个站点上，因此重复抓取的成本更低，并且返回一致的结果。
  • 任何页面上的视频发现 — 扩展了 video 格式以在任何页面上查找视频，而不仅仅是 YouTube 等受支持的提供商，返回每个视频的 URL、标题、缩略图、持续时间等。
  • 附加您自己的浏览器自动化 — 在浏览器会话响应中添加了 CDP WebSocket URL (cdpUrl)，以便您可以直接与 Playwright、Puppeteer 或任何其他 CDP client 驱动实时 Firecrawl 浏览器会话。
  • 更智能的监控警报 — 向监控器添加了 goal，以便法学硕士根据您实际关心的内容判断每个检测到的更改是否有意义或噪音，减少警报垃圾邮件并在摘要电子邮件中首先显示重要的更改。
  • 监视器的字段级 JSON 差异 — 在 JSON 模式下抓取的监视器现在比较运行之间的实际字段值而不是渲染的页面，因此您可以准确地看到哪些字段发生了变化，而不是布局变化带来的噪音。
  • 监控电子邮件确认 — 添加了选择加入确认流程，并为外部监控收件人取消订阅 one-click；团队成员会自动确认，并且 Monitor 响应现在会报告每个收件人的订阅状态。
  • AM/PM 监控计划 — 添加了对 12 小时计划输入（如 daily at 9am 和 daily at 5:30pm）的支持，转换为正确的 UTC cron 表达式。
  • 监控 Webhook 传送状态 — 为每个监控检查添加了传送状态，以便您可以查看其 Webhook 是否已尝试、传送或失败 - 以及原因。
  • 更稳定的监视器检查 — 监视器现在在比较之前等待页面完成渲染，从而减少因部分加载页面而导致的错误警报。
  • PDF 大小上限 — 将 PDF 下载和抓取大小上限从 30 MB 提高到 50 MB。
  • Python SDK crawl() scrape kwargs — 向 crawl() 和 start_crawl() 添加了直接 scrape kwargs（formats、headers、include_tags、exclude_tags 等），无需将它们包装在 ScrapeOptions(...) 中。
  • 更清晰的 .data 错误 — 改进了在搜索结果中访问 .data 时引发的错误，使其指向 .web、.news 和 .images 及其计数，而不是返回静默的 None。
  • Python 格式默认值 — 删除了 JsonFormat 和 ChangeTrackingFormat 上所需的 type= 参数，将其默认为 ScreenshotFormat。
  • ChangeTrackingFormat 大小写 — 增加了对 type 格式的 change_tracking 和 changeTracking 的接受，以便有效负载在 Snake_case 和 CamelCase clients 之间往返。

修复

  • 通过升级 axios、esbuild、ws、openssl 和其他依赖项，解决了 API 和 SDK 的安全建议。
  • 修复了抓取工作人员在非常大的 LLM 提取器输入上停滞数十秒的问题，这之前导致作业丢失和工作人员重新启动。
  • 修复了维基百科在大约一半的维基媒体 URL 上刮掉缺失的 metadata.ogImage 的问题。
  • 修复了抓取和批量取消不会耗尽每个团队并发积压并报告过时状态的问题；排队的作业现已删除，并且 status 立即报告 cancelled。
  • 修复了信用锁被拒绝时收取的监控检查费用；被拒绝的锁现在标记检查 skipped_no_credits 并停止运行。
  • 修复了当字段值相同但重新排序时，JSON 模式监视器差异返回虚假 changed 判决； diff 现在使用顺序不敏感的相等。
  • 修复了 JSON 模式监视器将空字符串刮擦视为丢失输入并在每次运行时报告 changed 的问题。
  • 修复了针对同一检查两次调度监控 webhook 的问题。
  • 通过将 monitor.page 和 monitor.check.completed 有效负载包装在数组中以匹配爬行/批量形状，修复了监视器 Webhook 被丢弃为格式错误的问题。
  • 修复了监控法官在文本前后捏造并在长页面上丢失上下文的问题；它现在收到完整的统一差异作为唯一的证据。
  • 修复了破坏 GET /v2/monitor/:id/checks/:checkId 的损坏或意外存储的工件；不良数据现在表现为没有差异。
  • 修复了当第一行使用 td 单元格时 HTML 表格丢失标题行的问题； Markdown 转换器现在将其提升为标题，因此列标签可以保留到 document.markdown 中。
  • 修复了在某些抓取路径上绕过 PDF 大小上限的问题，因此超大的 PDF 现在会被一致拒绝。
  • 修复了通过 Python SDK 序列化往返删除的 ChangeTrackingFormat 选项（modes、prompt 和相关字段）。

API

  • 在 POST /v2/scrape、/v2/batch/scrape、/v2/crawl、/v2/parse 和 /v2/extract 上将实验性 pii 格式替换为 redactPII（boolean 或 { mode?, entities?, replaceStyle? }）；启用后，document.markdown 返回经过编辑的文本（默认为 mode: "accurate"、replaceStyle: "tag"）。旧的 pii 格式和 document.pii 块已被删除，并且现在拒绝包含 formats 中的 "pii" 的请求。
