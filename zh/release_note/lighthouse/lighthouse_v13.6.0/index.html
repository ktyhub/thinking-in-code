显着变化

  • CLI 批量 URL 审核：CLI 现在支持在单个命令中按顺序审核多个 URL - 通过传递多个 URL 参数或通过 --url-file（--fail-fast 在第一次失败时中止）（#17404）。默认报告文件名现在包含 URL 路径名 (<hostname>-<pathname>_<date>)，以避免同一主机上的页面之间发生冲突（#17405、#17423）。
  • Lantern 模拟改进：升级了 trace_engine（0.0.66 和 0.0.67）并更新了请求/图形建模以提高模拟精度（#17307、#17379）：
    • 网络和协议建模：将 HTTP/3 连接视为多路复用，在模拟步骤中记入消耗的 H2 溢出字节，从活动连接计数中排除无连接请求，并改进原始 RTT/吞吐量估计和重定向处理（#17415）。
    • 依赖关系图和指标：添加了 v8.compileModule 和 v8.evaluateModule 跟踪事件归因，使用协议 renderBlocking 状态作为渲染阻塞优先级（#16869），当文本 LCP 与 FCP 出现在同一帧中时使用 FCP 图表，并修复了模拟 LCP 故障计算（#17269）和跟踪模式导航/URL 处理（[#17431]（https://github.com/GoogleChrome/lighthouse/pull/17431），[#17433]（https://github.com/GoogleChrome/lighthouse/pull/17433））。
  • 代理资源发现 (ARD) v0.91：将 ard-schema 审核和收集器更新为 ARD v0.91 规范（ard.json 替换 ai-catalog.json），支持通过 Link HTTP 标头、<link rel="ard"> 和 /.well-known/ard.json 进行发现，对旧 ai-catalog 位置发出警告，并在报告中显示 ARD 规范版本页脚（#17258、#17259、#17260、#17448、#17452)。
  • 性能洞察 numericValue：性能洞察审核现在根据估计的时间或字节节省填充 numericValue 和 numericUnit (#17346)，并在跟踪包含多个导航时选择正确的导航 (#17174)。
  • 内存和收集优化：通过流式传输跟踪 (ReturnAsStream)、重用跟踪事件中的脚本源、逐出 speedline 中的解码帧缓冲区以及释放中间收集器和跟踪引擎状态 (#17286、#17289，减少运行期间的峰值内存使用量#17290、#17407)。
