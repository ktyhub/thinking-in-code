lighthouse v7.0.0

7.0.0 (2020-12-17)

全Changelog Lighthouse 7.0 在 辅助功能 和 PWA 类别中包括许多程序化的重大更改和新审核。指标计算的准确性有所提高，但预计几乎所有站点的性能分数都不会发生显着变化。由于新的审核，可访问性和 PWA 分数可能会有较大变化。 此版本预计将在 Chrome 89 的开发工具中发布。它于 2021 年 2 月 19 日在 PageSpeed Insights 上上线。

显着变化

  • 拍摄全页截图，用于改善查看 DOM 元素详细信息的体验。现在将显示缩略图，并且 clicking 会显示一个灯箱，显示 DOM 节点在页面中的位置。此屏幕截图将灯塔 JSON 的大小增加了约 33%。 (#11769、#11768、#11829、#11846、#11852)
  • PWA 类别发生了相当大的变化。
    • Installable 组完全由启用 Chrome 可安装标准的功能检查提供支持。这些信号与 Chrome DevTools 的 Manifest 窗格中看到的信号相同。因此，“注册服务工作者…”审核移至_PWA Optimized_组，并且“使用 HTTPS”审核现在包含在关键“可安装性要求”审核中。 -_快速而可靠_小组已经消失得无影无踪。 🌬 现在，改进后的“可安装性要求”审核包括离线功能检查，我们删除了用于检查当前页面和 start_url 离线时是否响应 200 的专用审核。另外，“移动网络上的页面加载足够快”审核已被删除，虽然它不再是 PWA 部分的一部分，但我们鼓励构建 PWA 的人们参考性能类别，以确保他们的 Web 应用程序快速且令人愉快。
  • 夜间 Lighthouse 构建 现在在 npm 上以 lighthouse@next 形式提供。请注意，虽然在发布前通过了自动化测试，但预计此版本将比常规版本更加不稳定（#11792、#11805、#11810）
  • 可访问性测试库 axe-core 已更新到最新的 4.1.1 版本。可访问性审核现在更快、更强大，并且包括多项新检查（#11661）
  • Lighthouse 在启动时运行一个小型基准测试，如果 测试机器显得动力不足 并且可能会影响 Lighthouse 指标的准确性，现在将包含一条警告 (#11350)
  • 添加了 Joomla 和 October CMS 检测，因此这些平台上的页面现在将获得有关某些 Lighthouse 审核的定制建议 (#11788)

新贡献者

感谢 Kohta Ito (@koh110) 和 Sam Stoelinga (@samos123) 的首次贡献！

🆕 新审核

  • 上面提到的新 installable-manifest PWA 审核使用 Chrome 自己的可安装性标准，因此它将始终与可安装性要求保持同步 (#11745)
  • third-party-facades 在测试页面中查找可以使用静态“外观”进行延迟加载的第三方嵌入。如果嵌入对于用户的即时交互来说不是必需的，请考虑使用其中一个外观来加速页面加载（#11290）
  • 随着 ax 版本升级，新的审核确保可访问的命名：aria-treeitem-name、aria-command-name、aria-tooltip-name、aria-meter-name 和 aria-progressbar-name (#11661)

♻️ 删除审核

  • 最新 axe-core 的更新还删除了两项检查不多的审核：layout-table 和 video-description (#11661)
  • works-offline 和 offline-start-url 审计已被删除，因为它们的检查现在已包含在新的 installable-manifest 实施中 (#11806)
  • load-fast-enough-for-pwa 审核也已被删除，因为 Lighthouse 现有的性能指标足以满足那里的需求 (#11764)
  • without-javascript 已被删除 (#11711)

💥 重大变更

  • 设备仿真配置设置和 CLI 标志已更改为更清晰且重叠更少。如果您使用了 --emulated-form-factor 或其他与仿真相关的配置，则需要进行更改。新设置应该更容易与使用真实设备、Puppeteer 或系统级节流的自定义 Lighthouse 运行器一起使用。请参阅仿真文档 了解迁移指南。 (#11779)
  • 当等待页面完全加载时，如果存在活动的高优先级网络请求，Lighthouse 现在将等待。在极少数情况下，例如应用程序初始化依赖于单个、返回缓慢的 XHR，某些性能指标可能会恶化；然而，新的测量结果现在是准确的。 （[#11738]（https://github.com/GoogleChrome/lighthouse/pull/11738），[#11851]（https://github.com/GoogleChrome/lighthouse/pull/11851））
  • 已放弃对 Node 10 的支持。所需的最低节点版本现在为 12 (#11656)

🤖💥 针对程序化用户的重大变化

这些更改不太可能影响最终用户，但如果您正在编写自定义配置、插件或处理 Lighthouse JSON 输出，这些更改可能很重要。

  • ConsoleMessages 是一个新工件，它是旧 ConsoleMessages 和 RuntimeExceptions 工件的组合，其中包含一些记录到控制台的项目的扩展数据。 RuntimeExceptions 已被删除 (#11663)
  • 以前分布在现有工件中的 DOM“节点详细信息”数据现在收集在每个元素的 NodeDetails 属性中（#11474、#11695、#11752）
  • ImageElements 工件 已被简化，以更好地表示收集的数据及其使用方式（#11703、#11707、#11733）
  • 以前，extends: true 被允许作为 extends: 'lighthouse:default' 的别名，以从默认的 Lighthouse 配置文件中扩展配置。布尔选项已被删除，以便为从任何有效的配置文件进行扩展做好准备（#11835）
  • 删除了从未使用过的将选项从配置传递到收集器的功能，以便与未来的更改兼容（#11743）
