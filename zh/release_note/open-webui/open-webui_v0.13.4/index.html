open-webui v0.13.4

修订 发布时间2026年11月17日 来源open-webui/open-webui 英文原文

open-webui v0.13.4

添加

  • 使用 Tether 携带您自己的计算机。 Tether 将您自己的计算机变成 Open WebUI 的一部分：来自 Ollama、LM Studio 或任何 OpenAI 兼容服务器、OpenAPI 和 MCP 工具服务器以及您在 Tether 应用程序中添加的开放终端服务器的模型现在仅显示在模型选择器中、+ 菜单的工具列表以及您连接的任何 Open WebUI 的终端菜单中，无论您在什么设备上打开它，Open WebUI 都可以通过 Tether 访问它们，因此他们的地址、命令和密钥永远不会离开您的计算机。这需要 Tether 0.1.14 或更高版本，或者用于 MCP 服务器的 0.1.16，工具服务器和终端需要打开“ENABLE_TOOL_SERVERS”，并且 ID 与 Open WebUI 中已有模型匹配的 Tether 模型保持隐藏。 Tether 取代了直接连接。 #34397
  • 您自己计算机上的沙盒代理。 Tether 0.1.13 或更高版本可以将计算机上的终端锁定到沙箱中，因此模型和编码代理可以在您的真实文件中工作，而无需到达计算机的其余部分：在 macOS 和支持的 Windows 设备上，打开终端及其启动的所有内容（包括编码代理）只能触摸您选择的一个文件夹，离线运行，除非您打开网络访问并且不接受任何传入连接，无需 Docker、虚拟机或管理员设置。如果沙箱无法强制执行，终端将保持停止状态，而不是在没有沙箱的情况下安静地运行，并且浏览器和桌面控制在打开时保持关闭状态。在 Tether 中的“设置”>“打开终端”>“沙盒”下将其打开。
  • 通过 Tether 进行本地 MCP 服务器。 Open WebUI 现在可以使用通过 stdio（许多 MCP 服务器的分布方式）作为本地命令运行的 MCP 服务器，通过 Tether 0.1.16 或更高版本在您的计算机上启动它们，无需 mcpo 等代理，也无需打开端口。在“设置”>“集成”>“工具”下的 Tether 中使用其命令添加一个，或通过其 Web 地址连接 MCP 服务器，然后从 + 菜单的“工具”列表中选择它。本地命令使用您自己的帐户访问权限在 Tether 的工作区沙箱之外运行。
  • 每个用户一台计算机。 连接 0.4.0 或更高版本的终端后，Open WebUI 现在按需分发沙盒计算机：任何具有连接写入权限的人都可以直接从消息输入的终端菜单创建终端，选择是每个人共享一台计算机还是每个用户、聊天或模型拥有自己的计算机，并设置其图像、CPU、内存、存储、网络配置文件、环境变量、启动目录和安装脚本，例如，克隆存储库并安装其依赖项，无需管理员设置每一项都上去。终端可以与用户和组共享，并且可以启动、停止、重新启动或删除其实例，查看文件选项可以打开任何终端的文件，而无需选择它进行聊天，系统信息显示设置脚本的运行情况，管理终端的人员可以打开其他人正在运行的实例的文件和系统信息。启动和停止需要终端 0.4.1 或更高版本，启动目录和安装脚本需要在终端映像中打开终端 0.17.7 或更高版本，网络配置文件是管理员使用“TERMINALS_NETWORK_PROFILES”定义的配置文件。
  • 将代理编码为聊天模型。 编码代理现在的工作方式与聊天中的任何其他模型非常相似。 Hermes、Antigravity、GitHub Copilot、Goose 和 Qwen Code 加入 Codex、Claude Code、Cursor、Grok、OpenCode、Cline、Gemini CLI 和 Pi，并且使用“OPEN_TERMINAL_ACP_AGENTS”添加到开放终端的任何其他 ACP 代理在安装并登录到终端后也可以正常工作。自动工具权限现在允许 Codex、Claude Code 和 Grok 自行批准例行操作，并仅传递它们升级的内容，高级参数中的推理工作现在也适用于提供工作级别的 Claude Code、Pi 和 ACP 代理，例如 OpenCode，当未为模型提供所选级别时，这些代理会停止并出现错误。现在可以重新生成回复并编辑较早的消息，并且分叉或克隆的代理聊天会从原始中断处继续：Codex 从该点继续自己的对话，其他代理从到目前为止的聊天开始，并且文件更改代理已经保留。 Claude Code 也在 0.17.20 之后的下一个开放终端版本中继续自己的对话，直到那时要求您更新开放终端。 Claude Code 和 Grok 的新代理和 Auto 需要开放终端 0.17.19 或更高版本，Claude Code、Pi 和 ACP 代理的工作量需要 0.17.9 或更高版本。 #34167
  • 页面作为选项卡打开。 当您 click 或从侧边栏拖动它们、在用户菜单中选择它们或按照聊天消息中的其中一个链接开始新聊天（也从侧边栏文件夹开始新聊天）时，注释、频道、工作区、主页和来自固定模型的新聊天现在会作为当前聊天旁边的选项卡打开，并保持打开的选项卡。
  • 排队消息引导回复。 您在回复仍在运行时发送到自己的聊天的消息现在会在服务器上等待，因此当您离开页面时它会被保留，并且回复会在下一步中结束，因此您的消息会立即得到迄今为止所做的回复。
  • 即时第一条消息。 现在，新聊天的第一条消息会在聊天仍在创建时立即显示，而不是仅在存在时显示，除非仍在上传文件。
  • 侧聊天中的完整聊天。 侧聊天现在运行与主视图相同的聊天，因此消息按钮、源、令牌使用、后续建议、斜线命令、排队消息、聊天变量、Web 搜索设置、工具事件（例如代码执行和输入请求）、HTML 和 SVG 预览、窗口在后台时的通知、页面重新加载后未发送的文本以及同时来自多个模型的答案现在也可以在主视图中使用，并且侧聊天的选项卡现在具有聊天菜单。 #34064、#34165、#34147、#34031
  • **交互式可视化。**模型现在可以使用新的可视化内置工具在聊天中直接绘制交互式图表、图表、计算器和解释器，该工具默认关闭，并在内置工具下为每个模型打开，管理员可以在管理设置 > 界面 > 可视化提示下或使用“VISUALIZATION_PROMPT_TEMPLATE”重写其说明。
  • 视频生成。 模型现在可以使用内置工具生成视频，也可以从聊天中的图像开始，一旦管理员在管理设置 > 视频下打开视频生成，就会添加到 OpenAI、LiteLLM 或 OpenRouter 的连接，这些模型提供 Veo 和 Kling 等模型，具有默认视频模型、每个模型的默认值和访问设置，并授予视频生成权限（默认情况下处于关闭状态），之后用户在 + 菜单中打开视频，可以在那里选择模型并观看模型结果在聊天中。 #13780, #13927
  • 多个图像模型。 管理员现在可以在管理设置 > 图像下添加多个图像连接，每个 OpenAI 兼容服务器（例如 LiteLLM、Gemini、ComfyUI 或 AUTOMATIC1111）都有自己的模型、大小、工作流程和访问权限，用于生成图像、编辑图像或两者兼而有之，其中 OpenAI 兼容服务器提供与模型连接相同的登录选项和自定义标头，并在未输入模型 ID 时自行列出 LiteLLM 服务器的图像模型，选择默认生成和编辑模型，并在其设置中为模型提供自己的默认图像模型，并且拥有多个图像模型的用户从消息输入的 + 菜单中的图像条目中选择一个。 #10344
  • Git 面板成为 GitHub 工作台。 随着开放终端 0.17.8 或更高版本以及在终端上登录的 GitHub CLI（包含在完整的代理和 cuda 映像中），Git 面板现在涵盖整个 GitHub 循环：浏览、搜索、创建、编辑、评论、关闭和重新打开存储库的问题、查看每个拉取请求的检查、审核状态、标签、活动和冲突以及状态过滤器和合并方法的选择，以及在整个存储库（而不仅仅是加载的列表）中搜索问题和拉取请求。聊天中的“处理此问题”、“修复”、“解决反馈”和“解决冲突”等按钮将问题、审查或冲突作为消息输入中的现成请求传递给模型，并且可以使用 Ctrl 或 Shift click 选取已更改的文件以一次丢弃多个或全部。
  • 终端跟随您的聊天。 每个聊天现在都会保存其终端和工作文件夹，并在您重新打开时切换回它们，包括您关闭的终端，管理员可以在管理设置 > 模型 > 模型默认值下选择一个默认终端，每个没有自己终端的模型的新聊天都会从该终端开始，因此每个聊天都可以在连接计算机的情况下开始。早期版本的聊天无需终端即可打开，除非它们是编码代理聊天。
  • **文件夹聊天板。**文件夹页面现在列出了他们的聊天，通过标题和消息搜索以及状态、标签、人员、活动和上次更新的过滤器进行搜索，并且可以按状态、标签或活动（例如未读、生成或等待批准）将它们显示为具有列和行的板，为每个聊天提供侧边栏的聊天菜单以重命名、移动、存档或删除它，侧边栏中的文件夹徽章现在也计算等待批准的聊天。 #33771
  • 文件夹中的聊天状态。 文件夹现在可以在编辑状态下设置聊天状态，并提供积压、待办、进行中、等待和完成作为建议，然后聊天从文件夹页面上的菜单或通过在板列之间拖动它们来获取状态，可以编辑共享文件夹的人可以设置其中每个聊天的状态，每个聊天都会显示其处于该状态的时间。
  • 文件夹自动化。 文件夹页面现在有一个自动化部分，列出了文件夹的自动化及其状态和上次运行，并在那里创建新的自动化，由自动化进行的聊天标有时钟，自动化现在可以发布到其创建者可以编辑的共享文件夹中，每个可以编辑文件夹的人都可以暂停和运行它们并查看它们的运行。
  • 文件夹页面上的知识。 文件夹页面现在有一个知识部分，列出了文件夹中新聊天可以使用的知识库、注释、聊天和文件，您可以在其中添加、上传、删除、打开和删除它们。
  • 彩色聊天标签。 标签现在可以在文件夹页面上获取适用于使用该标签的任何位置的颜色，并且聊天菜单有一个“标签”子菜单，用于查找、添加和创建标签，并且可以编辑共享文件夹的人员可以标记其中的每个聊天。
  • 就地编辑自动化。 自动化的页面现在可以编辑其名称、指令、状态、计划、模型、终端和目的地，并在更改后显示保存按钮，显示折叠在“显示更多”后面的已保存指令，将其运行列为下面的活动，并在其“更多”菜单中具有“复制链接”和“复制”。
  • 可读的代理和终端步骤。 其他模​​型的编码代理和终端工具调用的步骤现在显示在聊天中，如它们所做的那样，一个命令及其输出及其失败时的退出代码，每个编辑文件的差异及其添加和删除的行，或读取的文件，代码和网络搜索，列出的文件夹和获取的页面，并且一组步骤总结为例如运行 2 个命令、编辑 1 个文件、读取 3 个文件。其他机型通过终端工具编辑的文件的差异需要打开终端0.17.20或更高版本。
  • 模型可以提及人员。 通过聊天历史内置工具，模型现在可以按姓名或电子邮件查找用户并在回复中提及他们，并且每个提到的可以看到聊天的用户都会收到一条收件箱通知，该通知会在该回复中打开聊天。
  • 与 OpenAI 兼容的向量存储。 管理设置 > 集成下的外部知识源现在可以是 OpenAI、Azure OpenAI 或 LiteLLM 上与 OpenAI 兼容的向量存储，在服务器上进行搜索，因此不需要匹配的嵌入模型，并且您可以为知识库选择一个或多个存储，或者打开“将存储列为知识库”以显示连接的每个存储，或仅显示选定的存储，作为与端点保持同步并共享连接的访问​​设置的只读知识库。
  • 保存前检查设置。 管理设置页面现在会在“保存”旁边显示自加载或保存以来更改的设置数量，并且计数或保存的 clicking 会列出每个更改及其旧值和新值以进行确认，密码和 API 密钥保持隐藏。 #34534, #34532
  • 使用代码块进行更平滑的回复。 包含许多代码块的长回复不再会在流式传输时因每个新代码块而使选项卡停顿得更久，因此一次到达的包含 300 个代码块的回复现在会在 9 秒内显示，而不是超过两分钟。 #34495, #34492
  • 更快的大型 PDF 预览。 文件预览中的长 PDF 现在只需大约一秒即可打开，并且使用的内存要少得多，因为只绘制靠近屏幕的页面并释放远离屏幕的页面，因此 1500 页的手册不再需要半分钟以上，大型扫描文件也不再将浏览器推过许多 GB。浏览器的查找 (Ctrl+F) 现在仅匹配屏幕附近页面上的文本。 #34602, #29576
  • 更快地重新打开文件夹。 重新打开文件夹现在可以立即显示其聊天内容、详细信息和编码代理模型，并在后台刷新它们，侧边栏文件夹在折叠和再次展开时保留其加载的聊天内容，文件夹聊天列表在聊天被重命名、移动、存档或删除时立即更新。
  • 使用 Redis 实现更快的模型列表。 使用 Redis，模型列表现在加载速度更快，并且 Redis 不再保留每个模型个人资料图像的副本，这对大多数大型动画或导入图像有帮助，并且功能和工具现在接收没有个人资料图像的模型。 #34595, #34594
  • 更快的个人资料图片和知识导出。 用户、模型和频道 Webhooks 的大型个人资料图片以及知识库导出现在可以一体发送，因此一张 2 MB 的图片在大约 15 毫秒内加载，而不是几百毫秒，充满大型头像的页面不再需要几秒钟，并且在打包存档时导出知识库不再阻碍同一服务器进程上其他用户的请求。 #34598、#34597、#34600、#34599
  • 共享聊天终端。 可以回复与允许回复共享的聊天的人现在可以在该聊天的终端中工作，正如共享对话框现在指出的那样：使用终端模板为每个聊天提供自己的计算机，并且在编码代理聊天中，他们与所有者在同一台计算机和文件中工作，而使用其他终端时，他们使用自己的访问权限。 #34103
  • “文件”选项卡升级。 通过报告文件更改的终端，当显示的文件夹中的文件发生更改时，“文件”选项卡现在可以自行更新，无需加载微调器，也可以通过在聊天之外运行的命令进行更新。 Clicking 其上方的路径可让您键入要转到的文件夹（绝对文件夹或相对于当前文件夹的文件夹），使用 Tab 完成文件夹名称，或者选择并复制打开文件的完整路径，Markdown 文件会获得一个大纲按钮，列出其标题并跳转到您选择的文件夹，消息输入的工作目录菜单中的文件夹有一个打开文件夹按钮，可在新的“文件”选项卡中打开它们。 #34494, #34525
  • 终端选项卡升级。 终端选项卡现在以在其中运行的程序设置的标题命名，或者以在 macOS 和 Linux 上使用 Open Terminal 0.17.8 或更高版本运行的程序本身命名，并显示知名程序的图标，例如 Claude Code、Codex、Python 或 Node.js。当没有选择聊天终端时，打开新选项卡的菜单仍然提供文件、新文件、终端、浏览器、桌面和语音注释，并且首先选择一个会要求您从可搜索列表中选择一个终端。
  • 分组工具和技能。 消息输入的 + 菜单中的工具和技能列表现在按每个条目的来源进行分组，例如工作区、工具服务器或终端。 #34085
  • 选项卡上的回复进度。 聊天选项卡和侧边聊天选项卡现在在写入回复时显示一个旋转器，因此您可以从另一个选项卡中看到何时仍有答案。
  • 从选项卡重命名。 双 clicking 聊天选项卡现在可以重命名聊天，也可以重命名其他人在您拥有的文件夹中进行的聊天，并且在文件夹页面上重命名文件夹。
  • 从菜单中共享文件夹。 侧边栏和文件夹页面上的文件夹菜单现在为管理员和允许共享文件夹的所有者提供了共享选项。
  • 子代理权限。 管理员现在可以使用默认和组权限中的功能下的子代理开关或使用“USER_PERMISSIONS_FEATURES_SUBAGENTS”将子代理限制为选定的用户和组，而没有它的用​​户既无法获得子代理也无法获得计时器工具。 #34040, #34038
  • 更轻量的编码代理回复。 当编码代理写入其回复时，聊天内容不再大约每秒完整保存一次，因此长代理聊天每次回复写入数据库的次数要少几倍。 #34062
  • 失败的工具调用上的标签。 失败的工具调用现在保留模型给它们的短标签，也在一组调用中，其中一个失败的调用用于隐藏每个标签。 #34000, #34529
  • 将文件拖放到技能中。 拖到工作区中技能文件上的文件和文件夹现在上传到打开的文件夹中，就像上传按钮一样。
  • 可编辑的日历。 现在可以使用日历侧栏中每个日历旁边的铅笔对日历进行重命名并在创建后为其赋予另一种颜色。 #34136
  • 分析中的模型名称。 管理分析现在按代理和模型命名编码代理模型，以便从现在开始进行回复，并且会话时间线的工具提示显示模型名称而不是模型 ID。
  • 竞技场模型管理。 管理设置 > 模型中的视图过滤器现在有一个竞技场模型选项，仅列出竞技场模型，并且管理设置 > 评估中的每个竞技场模型都有一个克隆按钮，可以打开从中填充的新竞技场模型。 #34137, #34138
  • 记录了 OAuth 会话删除。 由于“OAUTH_MAX_SESSIONS_PER_USER”限制、身份提供商发送的注销或重新连接的 MCP 服务器删除存储的 OAuth 会话，现在会记录一条警告，其中列出了用户、会话和原因。 #34583, #34580
  • 辅助功能改进。 使用 Alt+Shift+箭头键移动的选项卡现在可以保持键盘焦点，因此可以将其连续移动多个位置。
  • 一般改进。 在整个应用程序中实施了各种改进，以增强性能、稳定性和安全性。

已更改

  • 需要终端 0.4.0。 与终端服务器的连接不再在管理设置 > 集成中携带策略，因此策略 ID、图像、资源、存储、空闲超时和终端上下文设置以及刷新终端按钮都消失了，服务器必须运行终端 0.4.0 或更高版本，并且使用旧连接的模型、文件夹、自动化和聊天需要选择新终端之一。从 0.3.x 升级终端需要手动迁移，因为没有自动迁移，新的终端安装在没有模板的情况下启动，Open WebUI 现在与终端服务器密钥连接，并且应从终端设置中删除“TERMINALS_OPEN_WEBUI_URL”和“TERMINALS_TOKEN_CACHE_TTL”。开放终端和 Tether 终端连接不受影响。
  • 直接连接移至 Tether。 设置 > 连接和设置 > 工具与管理设置中的直接连接和直接集成开关、直接工具服务器权限以及“ENABLE_DIRECT_CONNECTIONS”、“ENABLE_DIRECT_INTEGRATIONS”和“USER_PERMISSIONS_FEATURES_DIRECT_TOOL_SERVERS”设置一起消失，因此用户在自己的设置中添加的模型、工具服务器和终端不再出现。用户将它们添加到 Tether 应用程序（0.1.14 或更高版本，对于 MCP 服务器为 0.1.16）中，他们留在自己的计算机上并在他们连接的每个 Open WebUI 中工作。
  • 图像设置成为连接。 在该版本首次启动时，图像生成和编辑设置将变成图像连接，以前可以使用它们的每个人都会继续使用，从那时起，图像环境变量如“IMAGE_GENERATION_ENGINE”，“IMAGES_OPENAI_API_BASE_URL”和“COMFYUI_BASE_URL”将不再被读取，除非“ENABLE_PERSISTENT_CONFIG”关闭。
  • 锁定的 Docker 依赖项。 标准和精简的 Docker 映像现在从用哈希固定的锁定文件安装除 PyTorch 之外的每个 Python 包，因此重建相同版本会安装相同的包，并且编辑“backend/requirements.txt”的自定义映像必须使用“backend/update-locks.sh”重新生成锁才能使编辑生效。 #33981, #33979
  • 新的编码代理模型 ID。 编码代理模型现在仅获取由字母、数字、破折号和下划线组成的 ID，这使得固定的 Cursor 和 Pi 模型可以正常工作，并且指向名称具有其他字符（如大多数 Codex 模型中包含的点）的代理模型的引脚、默认模型和自动化，需要再次选择模型。 #34171, #34168
  • 编码代理会话重新启动一次。 早期版本的编码代理聊天中的第一条新消息会启动一个新的代理会话，该会话将聊天内容获取为文本，而不是恢复代理自己的会话。
  • 图像 API 模型检查。 通过 API 发送的图像生成和编辑请求现在在它们命名的模型上运行，该模型必须是调用者的图像模型之一，否则请求会因错误而失败，而不是图像生成忽略命名模型。
  • 实时更新事件重命名。 注释、评论、收件箱、访问更改、加密通道和通道应用程序错误的实时更新现在作为主“事件”套接字通道上的键入消息到达，因此侦听旧事件名称（例如“events:note”或“note:presence”）的自定义 clients 需要在那里侦听。
  • 聊天写入访问字段。 来自 API 的聊天响应现在在“share_mode”中携带保存的共享模式，并报告您是否可以在新的“write_access”字段中回复，因此读取“share_mode”的自定义 clients 需要进行切换。
  • 终端上传到文件。 新的终端连接现在从设置为文件系统的聊天上传开始，并且通过 Tether 连接的计算机始终使用它，因此聊天中附加的文件将保存到所选终端的工作文件夹中，而不是作为常规聊天上传进行处理，而现有连接保留其设置。建议使用开放终端 0.17.20 或更高版本，因为它修复了在多用户设置中上传变得不可读的问题。
  • 聊天菜单项已移动。 概述、工件和评论不再位于聊天菜单中，现在从选项卡栏的 + 菜单打开，其中概述作为聊天旁边的选项卡而不是全屏窗口打开。
  • 注释注释按钮。 对注释的注释现在可以从注释顶部栏中的按钮而不是从其菜单打开，并且在可以编辑的注释中，对所选文本的注释现在是格式工具栏中的注释按钮。
  • 一个标题菜单。 消息输入和注释的格式化工具栏现在在单个标题菜单中提供标题 1、2 和 3，而不是三个单独的按钮。
  • 附件菜单已重命名。 消息输入的 + 菜单中的“添加上下文”条目现在称为“附件”，其中包含附加网页、文件、注释、知识和聊天的选项。 #34431
  • 功能现在称为功能。 模型编辑器的功能部分现在称为功能。 #34433
  • 知识库标签。 聊天中的知识选择器、模型编辑器的知识选择器和附加知识库现在将它们称为知识或知识库，而不是集合、矢量数据库术语，并且知识库内的搜索框现在称为“搜索文件”。 #34432
