dify 1.17.1

[!警告] 使用捆绑 Weaviate 的自托管部署必须在启动 1.17.1 之前完成手动分阶段升级。 捆绑 Weaviate 服务器从 1.27.0 移至 1.39.2 — 12 个次要版本 — 并且不支持跳过次要版本**。拉动并重新启动可能会默默且永久地破坏矢量搜索。请参阅下面的升级指南。全新部署、外部 Weaviate 和其他矢量存储不受影响。

新功能

数据集范围的知识库 API 密钥

  • 知识库服务 - API 密钥的范围为整个工作区：一把密钥可以读取和写入租户中的每个知识库，因此提供对单个知识库的集成访问意味着可以访问所有知识库。现在可以通过知识库的 API 访问面板将密钥绑定到特定知识库，并在创建时使用工作区/此知识库范围选择器。对于任何其他数据集（文档和检索）以及不携带数据集 ID 的端点（例如 list-all），绑定键都会返回 403。现有密钥未绑定并保持其工作区范围内的行为，因此升级时不会发生任何变化。 (#37569)

工作流程节点和注释的键盘移动

  • 工作流程画布需要鼠标来重新定位任何内容。现在可以使用箭头键移动节点、多节点选择、注释标记和草稿注释（按住 Shift 可获得更大的步骤），包括注释、迭代和循环节点。连续移动是在按键释放或模糊时进行的，因此它会产生一个撤消条目，而不是每次按键一个撤消条目，并且只读模式、容器边界和协作更新仍然受到尊重。 (#41967)

市场创建者简介和主页重新设计

  • 插件作者现在在 /marketplace/creator/<handle> 上拥有公共个人资料页面，通过发布者侧边栏列出了他们的创作，可以通过侧边栏帮助菜单中的新创作者中心条目进行访问。市场主页围绕英雄、横幅轮播、粘性搜索、目录选项卡和标签/语言过滤器进行了重建，并具有堆叠和可滑动的移动布局。捆绑包不再混合到插件类别中。 (#41538)

可配置的 Markdown 表单字段名称长度

  • Markdown 表单字段名称限制被硬编码为 128 个字符，无法容纳更长的生成字段名称。现在可以通过 MARKDOWN_FORM_FIELD_NAME_MAX_LENGTH (Docker) 或 NEXT_PUBLIC_MARKDOWN_FORM_FIELD_NAME_MAX_LENGTH（直接 Web 部署）进行配置，默认为之前的 128。字符验证和原型污染保护保持不变。 (#41697)

错误修复

知识库

此版本修复了一系列提取错误，这些错误更改了文档内容而不报告错误。升级后重新导入受影响的文档；索引文本不会被追溯修复。

  • CSV 单元格在索引之前通过 pandas 类型推断。 前导零代码变成浮点数 (00123 → 123.0)，空单元格变成文字字符串 nan，包含 NA 或 NULL 的单元格变成缺失值。提取器现在将所有内容读取为文本并禁用缺失值推断；对于想要类型化解析的调用者来说，显式的 csv_args 仍然会覆盖它。 (#41922)
  • **概念表行丢失或增加了列。**单元格内的每个富文本段都作为自己的 Markdown 列发出，因此任何具有混合格式（粗体、链接、提及）的单元格都会生成额外的列并损坏表格，而空单元格会被完全跳过并将行的其余部分向左移动。现在，每列发出一个单元，其段连接在一起。 (#41993)
  • 概念数据库属性在第一次格式更改时被截断。 rich_text 和 title 属性仅读取其第一段，因此 Hello world 的标题（带有粗体 world）仅被索引为 Hello 。现在所有段都已连接。 (#42050)
  • 包含双引号的 .xls 单元格损坏了行。 提取器发出 "column":"value" 对； .xlsx 路径转义了嵌入引号，但旧版 .xls 路径对它们进行了原始插值，因此 he said "hi" 变成了 "note":"he said "hi""。现在，两个引擎对于相同的内容表现相同。 (#42049)
  • 从 URL 加载的任何 PDF 都会因裸露的 AssertionError 而崩溃。 将租户上下文添加到 PDF 提取器后，load_from_url 使用的代码路径（包括目标返回 Content-Type: application/pdf 时的内置网络抓取工具）在上传记录上断言 URL 加载从未有过。租户上下文现在是可选的，当它不存在时，图像提取将被跳过，文本提取将再次工作。 (#41950)
  • 内置网络抓取工具返回 Python 数据结构而不是页面文本。 readabilipy 将 plain_text 作为字典列表返回，该列表直接插入到输出模板中，因此每个抓取的页面都以 [{'text': '<p>…</p>'}, …] 形式返回 - 包括字典语法、引号和 HTML 标签。这些项目现在被扁平化为可读文本。 (#41954)
  • 部分段更新已擦除附件。 省略 attachment_ids 的段更新被视为“无替换”，删除段的附件绑定和多模式向量。除非明确提供 attachment_ids，否则附件现在将被保留；通过 [] 仍然可以清除它们。 (#41777)
  • 具有无效 Markdown 图像链接的文档可能会拖延索引队列。 相对、协议相对、data:、ftp: 和格式错误的图像目标都被交给远程图像获取器并进入其 SSRF 重试循环，因此具有许多错误引用的单个文档可以让索引工作人员保持足够长的时间来备份其后面的所有内容。现在验证并跳过不可获取的目标。 (#41343)
  • 删除对象存储中留下孤立文件的内容。 段删除、多模式重新索引和批量文档删除均删除了数据库行，但留下了物理附件对象 b
