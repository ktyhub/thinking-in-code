dify 1.14.2

🚀 v1.14.2 有什么新功能？

v1.14.2 是继 v1.14.1 之后的一个补丁版本，专注于安全强化、工作流程和知识可靠性、可观测性修复、代理基础工作以及部署/运行时调整。

🔐 安全和管理

  • 租户范围的敏感端点 - 加强了应用程序跟踪配置端点和 FilePreview 文本提取的租户隔离。感谢 #35793 和 #35797 中的@xr843。
  • 工具凭证安全 - 限制对工作区管理员和所有者的默认内置工具凭证更新，并在 reset-encrypt-key-pair 期间清理过时的租户工具凭证。感谢 #36264 和 #35843 中的 @NeatGuyCoding 和 @xr843。

🧩 工作流程、HITL 和应用程序运行时

  • 工作流程执行可靠性 - 在 HITL 工作流程恢复后恢复跟踪，改进工作流程运行回调跟踪，减少消息更新数据库往返，固定 Flask 上下文之外的内存获取，并正确关闭 base64 文件查找会话。感谢 #36064、#36149、#36213、#36253 中的 @Blackoutta、@CodingOnStar、@wylswz、@hjlarry 和 @escape0707，以及#36308。
  • 工作流程和模型选择改进 - 修复了未选择模型时的加载行为，通过支持的参数过滤模型预设，并改进了 API 扩展对话框控件。感谢 #36342、#36339 和 #36323 中的 @iamjoel 和 @lyzno1。

📚 数据、RAG 和知识

  • 知识库稳定性 - 修复了知识命中测试渲染、空知识创建、推荐应用程序类别排序以及推荐应用程序详细信息检索中的空处理。感谢 #36106、#36336、#36161 和 #36153 中的 @FFXN、@laipz8200、@hjlarry 和 @EvanYao826。
  • RAG 和文档处理 — 允许 LLM 节点访问检索到的知识文件、在 API 更新后重新生成文档摘要、修复管道模板渲染，并更优雅地处理 RAG 管道中的凭证获取失败。感谢 #36175、#36035、#36168 和 #36165 中的 @laipz8200、@EvanYao826、@FFXN 和 @linw1995。

🎨 Web UI 和产品体验

  • 应用程序创建和入门 — 跟踪应用程序创建源和模板 ID，从浏览器初始化用户时区和语言，并修复 WebApp 图标和描述显示。感谢 #36369、#36170、#36206 和 #36209 中的 @CodingOnStar、@lyzno1 和 @JzoNgKVO。
  • 注释和数据集 UI — 允许注释回复分数阈值低于 0.8，将未经授权的知识编辑器重定向回数据集，并修复了没有类型有效负载的标签重命名。感谢 #36337、#36073 和 #36182 中的 @JzoNgKVO、@iamjoel 和 @lyzno1。
  • UI 平台迁移和完善 — 添加了 Checkbox 和 CheckboxGroup 原语，将更多控件迁移到 @langgenius/dify-ui，改进了对话框溢出布局，并改进了帐户头像和安装流程交互。感谢@lyzno1和@CodingOnStar在#36271、#36295、#36255、#36302、#36111、 #36199 和 #36210。

🔎 可观察性和追踪

  • 跟踪可靠性 — 隔离 Langfuse v3 SDK 跟踪器提供程序，以防止跨任务干扰并添加 Phoenix 父跟踪回退行为。感谢 #36136 和 #36290 中的 @GareArc 和 @Blackoutta。

⚙️ 部署、依赖项和开发人员体验

  • 部署调整 — 将插件守护程序升级到 0.6.1，增加了默认的 GraphEngine 最小工作线程数，并刷新了 Docker 自述文件参考。感谢 #36312、#35650 和 #36303 中的 @laipz8200、@kenwoodjw 和 @RiskeyL。
  • 后端和 CI 维护 — 将静态分析转向 Pyrefly，将 Graphon 升级到 0.4.0，添加了修补程序择优来源检查，并改进了生成的合同工作流程。感谢 #36154、#36124、#36340 和 #36286 中的 @cqjjjzr、@laipz8200 和 @hyoban。
  • 依赖项更新 — 刷新了后端和代理依赖项，包括 authlib、ujson、langsmith 和 urllib3。感谢 #36112、#36121、#36142 和 #36160 中的 @dependabot[bot]。

升级指南

[!重要]

  • 此版本包括针对可配置探索应用程序类别的新数据库迁移。作为升级的一部分运行数据库迁移。
  • Docker Compose 环境变量现在分为 docker/envs/** 下的分类文件。如果您维护自定义的 docker-compose.yaml 或 .env，请仔细检查新布局并重新应用本地自定义。
  • 对于自托管部署，将继续遵循显式配置的 SECRET_KEY 值。如果 SECRET_KEY 为空，Dify 现在会自动生成并保留运行时密钥。

Docker 组合部署

  1. 备份您的自定义 docker-compose YAML 和 env 文件。

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. 从发布分支或标签获取最新代码。

    git fetch --tags
git checkout 1.14.2

  3. 停止服务。请在docker目录下执行。

    docker compose down

  4. 备份数据。

    tar -cvf volumes-$(date +%s).tgz volumes

  5. 查看新的 docker/envs/** env 文件布局并重新应用所有本地自定义。

6、升级服务。

docker compose up -d

源代码部署

  1. 停止 API 服务器、Worker 和 Web 前端服务器。

  2. 从release标签获取最新的代码。

    git fetch --tags
git checkout 1.14.2

3.更新Python依赖项。

cd api
uv sync

  1. 运行迁移脚本。

    uv run flask db upgrade

  2. 重新启动 API 服务器、Worker 和 Web 前端服务器。
