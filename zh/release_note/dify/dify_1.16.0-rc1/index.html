dify 1.16.0-rc1

[!警告] 您应该仅向 trusted、非恶意用户**⚠️ 提供 Dify Agent 服务⚠️**。

众所周知，基于 shell 的 LLM 代理范式带来了代理能力的重大飞跃，并改变了我们对代理的看法。同时，Skills提供了标准化的能力打包和分发方式，让构建强大的Agent变得更加容易。

今天，我们正在实验性地推出 Dify Agent。与其他领先代理一样，它在 Linux 沙箱中运行。此版本包括：

  • 用于创建 Dify Agent 的构建器

    • 您可以通过 UI 构建 Dify Agent：设置基本提示、上传技能和文件，以及连接 Dify 生态系统中的工具和知识。
    • 我们还提供了一个代理来帮助您构建 Dify Agents。通过对话，它可以配置 Linux 沙箱环境、安装所需的软件包以及创建 Dify Agent 稍后可以使用的新技能和文件。

  • Dify Agent 的 Dify 工作流程集成

    • 您可以在 Dify 工作流程中使用现有的 Dify Agent，或临时创建内联 Dify Agent。它将执行工作流节点定义的任务，生成所需的输出，并将其传递到下一个节点。

  • 全新的网络应用体验

    • 您构建的 Dify Agent 可以作为 Web 应用程序发布和使用。虽然用户体验仍然很熟悉，但它现在由 Dify Agent 提供支持。

文件：https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

限制

请注意，在当前的实验版本中，所有 Dify Agent 都在同一沙箱中运行。这意味着：

  • 正常情况下，每个 Dify Agent 在自己的工作空间内配置其环境并执行任务，而不会干扰其他代理。
  • 但是，通过简单的指令，任何 Dify Agent 都可以读取或干扰其他 Dify Agent 的环境和数据，包括用户数据。

未来版本将实施严格隔离。就目前而言，

[!警告] 您应该仅向 trusted、非恶意用户**⚠️ 提供 Dify Agent 服务⚠️**。

同样，由于 Dify Agent 尚未完全准备就绪，您可能会发现某些功能不适用于 Dify Agent。例如，当工作流包含引用 Dify Agent 的节点时，Dify Workflow DSL 导出不可用。

升级指南

[!重要]

  • 此版本包括新的数据库迁移。作为升级的一部分运行它们。
  • 环境变量已更改。查看环境变量更改部分并相应更新您的 .env。
  • Docker Compose 配置文件已更改。如果您维护自定义的 docker-compose.yaml，请仔细查看更改并重新应用本地自定义。

Docker 组合部署

  1. 备份您的自定义 docker-compose YAML 和 env 文件。 
    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true
  2. 获取1.16.0-rc1版本的最新代码。 
    git fetch --tags
git checkout 1.16.0-rc1
  3. 停止服务（在 docker 目录内运行）。 
    docker compose down
  4. 备份数据。 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. 检查任何 env 文件更改并重新应用本地自定义。 6、升级服务。 
    docker compose up -d

源代码部署

  1. 停止API服务器、Worker和Web前端服务器。
  2. 获取1.16.0-rc1版本的最新代码。 
    git fetch --tags
git checkout 1.16.0-rc1

3.更新Python依赖项。

cd api
uv sync
  1. 运行数据库迁移。 
    uv run flask db upgrade
  2. 重新启动 API 服务器、Worker 和 Web 前端服务器。要试验新的代理功能，您还需要启动 dify-agent 和 shellctl。 重要：shellctl 不包含内置身份验证 - 为了安全起见，强烈建议在容器内运行它。
