dify 1.19.0

Dify 1.19.0 为您的可观察性工具带来嵌套工作流程跟踪。 按照工作流程进入它调用的工作流程工具，检查每个调用内的步骤，并将 LLM 上下文保留在执行树旁边。

此版本还使工作流程工具可与应用程序包一起移植，添加技能中心自动化，并使代理文件更易于上传和预览。捆绑的插件守护程序升级到 0.6.14-local。

发布亮点 · 升级指南 · 详细变更

发布亮点

嵌套工作流跟踪

了解工作流程工具内部发生的情况，一直到其 LLM 调用。

在 1.18.0 中引入的控制台深入分析的基础上，新的外部跟踪现在包括称为工作流工具的内部持久执行步骤。子步骤出现在调用它们的工具范围下方，从而在嵌套和重复调用之间保留层次结构。 (#44673)

从外部工作流程到嵌套的LLM调用：执行树和格式化消息，一起在Langfuse中。屏幕截图来自 #44673。

  • 遵循层次结构。 展开称为“工作流程工具”以查看调用工具跨度下的内部执行步骤。
  • 了解每次调用。 重复调用和失败保留其在跟踪中的位置。
  • 保留 LLM 上下文。 检查格式化的提示和响应、令牌使用以及项目、跟踪和观察链接。

[!注意] 您保存的提供程序设置继续有效。 更丰富的层次结构适用于新的执行；历史痕迹未回填。独立嵌套的工作流运行保留由父标识符链接的单独跟踪。对于滚动部署，请遵循下面的跟踪队列转换。

将工作流程工具与您的应用程序结合使用

导出应用程序并携带其工作流程工具背后的工作流程。 .ifpkg 包包含其绑定版本的那些工作流，包括传递依赖项。导入重用目标工作区中已有的工具，并重新创建、发布和注册丢失的工具，重新映射它们的引用。 (#44592)

所有 Dify 应用程序导出现在都使用包格式 v2，包括没有工作流程工具的应用程序。仍然支持现有的 v1 导入和显式 YAML 导出。将新软件包导入旧安装之前，请参阅升级指南。 (#45353)

开发者聚焦

通过 OpenAPI 和 difyctl 管理工作区技能。 查找并检查技能、导出草稿或已发布版本、导入本地文件以及从命令行发布新版本。 (#44941)

<详情>

六个技能命令
命令 能力
difyctl get skill 列出技能，带有关键字和标签过滤器。
difyctl describe skill 阅读详细信息、草稿哈希和最新发布的版本。
difyctl get skill version 列出已发布的版本。
difyctl export skill 将草稿或选定的已发布版本导出为 ZIP。
difyctl import skill --files <dir> 创建技能或从本地文件替换现有技能草稿。
difyctl publish skill 将草稿发布为新版本。

</详情>

这些操作需要帐户调用者、相应的工作区权限以及要启用的技能。 导入不会发布。 导入现有技能被归类为破坏性的；操作目录和CLI有助于区分读、写和破坏性操作。 （#44941、#45314、#44587）

升级指南

[!重要] 部署前请阅读升级指南。 Docker Compose 现在需要 v2.35.0 或更高版本。保留现有环境文件，一起升级 Dify 组件，并在滚动部署期间使用新的跟踪队列。新的应用程序包使用格式 v2 并需要兼容的目标导入器。捆绑的插件守护程序移至 0.6.14-local。
