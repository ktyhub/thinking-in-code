dify 1.20.0

Dify 1.20.0 让您的跟踪保持流畅，让您的知识库更安全。 将跟踪导出到任何 OpenTelemetry 收集器，让 Langfuse 在其旧摄取端点退役后继续工作，并在上传的知识文件编入索引之前扫描它们是否存在恶意软件。聊天流程可以实时显示代理工具活动，个人访问令牌让脚本和代理可以代表您调用 Dify OpenAPI。捆绑的插件守护程序已升级到 0.6.15-local。 新功能 · 配置和集成更改 · 数据库迁移 · 升级指南

新功能

新 HITL：将批准纳入团队的消息传递工具中

通过电子邮件和团队已使用的消息传递工具将人工审核集成到您的工作流程中。 新的 HITL 引入了共享渠道、集中式联系人、通知模板和经过验证的批准表单，允许您的团队配置一次收件人并在人工输入节点中重复使用它们，现在默认启用 (NEXT_PUBLIC_ENABLE_HITL_IM=true)。 （#44864，#45945）

  • 联系审批者的工作地点。 配置电子邮件和 IM 平台（Slack、飞书/Lark、Microsoft Teams、钉钉或 WeCom），通过团队的现有渠道传递工作流审核请求。
  • 管理联系人中的收件人。 同步 IM 目录并从共享联系人列表中选择批准者。工作流程还可以向发起者发送信息或使用一次性动态电子邮件收件人。
  • 以卡片或表格形式批准。 收件人可以直接在支持的 IM 卡中查看请求或打开独立表格，并通过 Dify 登录或电子邮件验证来验证其身份。
  • 使用工作流上下文自定义通知。 使用模板和工作流变量在通知主题和正文中包含基本上下文。
  • 测试并跟踪交付。 发送测试通知以验证您的设置并检查交付记录以解决未按预期到达的请求。
  • 在现有工作流程中采用新的 HITL。 当您的工作流程准备就绪时，使用选择加入迁移来升级旧的人工输入节点。 配置和集成更改 下列出了部署要求。

将跟踪导出到任何 OpenTelemetry 收集器

将 Dify 执行跟踪引入您现有的可观察性堆栈中。新的 OpenTelemetry 提供程序 将应用程序和代理跟踪导出到任何兼容的收集器，使您可以在您的首选平台中一起跟踪工作流程步骤、模型调用和工具活动。使用这些跟踪来检查请求执行并诊断故障，而无需特定于供应商的 Dify 集成。 (#45659) Langfuse 跟踪现在支持 Langfuse v4 和当前的 Langfuse 云摄取服务。 现有的 Langfuse 配置继续有效。 (#45606)

[!重要] Langfuse Cloud 于 2026 年 11 月 16 日停用了其旧版摄取端点，并且自托管的 Langfuse v4 拒绝发送给它的事件。升级到 1.20.0 以继续向这些部署提供跟踪。

扫描知识上传是否存在恶意软件

在提取或建立索引之前扫描上传的文件是否存在恶意软件，从而保护您的知识库。启用后 (FILE_SCAN_ENABLED=true)，工作区所有者和管理员可以在 集成 → 文件安全扫描 下配置扫描仪一次，然后定义每个知识库如何使用它们。支持的扫描仪包括 Cloudmersive、Scanii、OPSWAT MetaDefender Cloud 和 自定义端点。 （＃46090，＃46492）

  • 根据知识库选择保护。 选择扫描仪并配置扫描不可用或无法扫描文件时的后备行为。
  • 保护 Dify 上的知识上传。 扫描涵盖经典知识库、RAG Pipeline 本地文件源和代理知识库上传。
  • 查看文件被阻止的原因。 扫描失败会显示在文档列表中以供查看。

观察代理工具在 Chatflow 中的工作情况

当 Chatflow 将任务委托给 Agent v2 节点（需要 NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true）时，用户现在可以实时查看它调用了哪些工具。工具活动会与预览和已发布的聊天中的响应一起显示，从而更轻松地跟踪代理的进度。展开任何工具卡以检查其请求和返回的内容。 (#46220)

使用个人访问令牌自动执行 OpenAPI 调用

代表您向脚本、CI 作业和个人代理授予对 Dify OpenAPI 的访问权限，而无需共享您的控制台会话。从您的 帐户 页面创建个人访问令牌，并将其范围限定为特定工作区和资源。您可以设置可选的到期日期，随着自动化的发展更新其范围，或者在不再需要时撤销它。 （＃45540，＃46606）

从树中选择GitHub知识源

从可扩展的存储库、目录、问题和拉取请求树中浏览并选择要添加到知识库的 GitHub 内容。无论您是创建新的知识库还是向现有知识库添加源，探索源结构并选择要导入的确切页面。 (#45990)

在较小的屏幕上搜索和导航

使用 Goto Anything 中的可选范围搜索内容并缩小结果范围。在较小的屏幕上，搜索和导航在抽屉​​中打开，以为当前页面保留空间。 （#45675，#45650） 直接链接现在可以打开 Studio 的空白应用程序或模板创建流程。 (#45717)

更灵活的知识描述和元数据

  • 更长的知识库描述。 增加的描述长度限制允许您为每个知识库提供更多上下文。 (#45075)
  • 外部知识元数据。 外部知识检索现在随内容一起返回文档元数据。 (#22496)

改进

降低数据库和启动开销。 节点执行更新避免重新加载存储的行，每个提供程序配置评估一次凭证策略，模型默认使用短期会话，并且嵌入调用不再保持打开的数据库会话。 Web 功能依赖项的加载也更加延迟。 （#46410、#46441、#45806、#45788、#46145） 更清晰的文档故障和更稳定的布局。 知识文档现在报告具体的故障原因和处理阶段。对话框适应狭窄的视口，并在帐户、知识、应用程序、技能和工作流程之间保持一致的生命周期。身份验证页面加载速度更快，适合较小的屏幕，并保持键盘焦点可访问。分段控件可以平滑地实现动画效果，同时保留紧凑的布局并尊重减少运动的偏好。 （#45128、#46487、#45686、#45668、#45634、#45600、#45640、#45974）

错误修复

  • 更安全的文件预览和签名链接。 沙盒内联 SVG 预览并在更新过期文件链接之前验证原始签名。 (#46505)
  • 更强的访问保护。 编辑公共流中的节点重试详细信息、防止 OAuth 回调重用、强制执行成员角色权限以及对目标数据集的范围向量删除。 （#46517、#46001、#46053、#45586）
  • 安全依赖项更新。 升级 dify-agent-runtime 中的 github.com/klauspost/compress 以解决 CVE-2026-116591，并将运行时映像中的 Node.js 更新为安全版本 24.22.3。 （#46544、#46206、#46064）
  • 可靠的阻塞工作流程。 在执行前释放数据库连接并立即返回准备失败，防止连接池耗尽并挂起等待超时的请求。 (#46254)
  • 更稳定的工作人员。 解决 Redis BRPOP 繁忙循环并防止重叠的插件升级检查，将工作人员之间的并发性限制为 20 个检查。 （#45940，#46500）
  • 完成 Chatflow 流。 在直接回复后正确关闭流，并在流恢复时重置重新连接预算。 （#45552，#46110）
  • 正确的代理执行。 保留对同一插件工具的并行调用，将声明的应用程序输入传递给代理运行，并将上传的图像传递给视觉模型。 （#45207、#45425、#45745）
  • 准确的知识检索。 通过返回 BM25 分数来恢复 Weaviate 关键字/混合结果，并在批量项目被删除时保持嵌入向量对齐。 （#45642，#45569）
  • 可靠的自定义 API 工具。 解析 OpenAPI 服务器变量，对路径参数进行百分比编码，并支持 OpenAPI 3.1 可空联合。 （#46504、#45965、#45895）

禁用 NEXT_PUBLIC_ENABLE_HITL_IM 不会回滚已保存的数据或停止已在进行的服务器端工作。

反向代理和工作配置

  • 新的 API 路由： 在 WEBHOOK 模式下，将 /callbacks/human-input/v2/im/ 转发到 API 服务（Docker Compose 中的 api:5001），保留请求路径、原始正文和提供者签名标头。捆绑的 nginx 模板已经包含此规则；添加与自定义 nginx、Ingress 或其他反向代理配置等效的内容。使用通道生成的回调 URL 配置 IM 提供程序。 (#44864)
  • 新的 Celery 队列： 包括用于异步 IM 回调处理和提交后卡更新的 human_input_delivery，以及用于 IM 联系人目录同步的 human_input_contact_sync。默认的 Docker 工作人员列表包括两者。自定义 CELERY_QUEUES、CELERY_WORKER_QUEUES 或 Celery --queues 列表必须为每个队列以及现有订阅提供一个活动使用者。 (#44864)

Docker 环境文件

docker/envs/core-services/shared.env 不再加载。在重新创建容器之前，将常见的 API、worker 和 Beat 设置移动到 api-worker.env。在该服务使用的覆盖文件中保留任何特定于服务的设置。 (#46497) 公共 URL 由 Web、API 和工作人员通过新的 envs/core-services/urls.defaults 和可选的 urls.env 共享：

  • CONSOLE_API_URL
  • CONSOLE_WEB_URL
  • SERVICE_API_URL
  • APP_API_URL

升级指南

[!重要] 在重新创建容器之前，将设置移出已停用的 shared.env。查看公共 URL、自定义 HITL 回调路由和工作器订阅。 OpenShell 部署需要兼容的网关升级，并且不再恢复主快照。捆绑的插件守护程序已更新为 0.6.15-local。

准备部署

  1. 备份数据和配置。 备份数据库、向量存储数据、上传的文件、插件守护程序存储、代理工作区存储、部署机密和环境文件。为单堆栈升级安排维护时段。
  2. 一起升级 Dify 组件。 使用匹配的 1.20.0 API、worker、Web、代理后端和本地沙箱映像以及插件守护程序 0.6.15-local。保持 SECRET_KEY、任何配置的 PASSWORD_PEPPER 和本地沙箱身份验证令牌不变。个人访问令牌依赖于SECRET_KEY；确保所有 API 副本使用相同的值。如果从1.19.0之前的版本升级，还请遵循1.19.0升级指南。
  3. 迁移 shared.env。 如果 envs/core-services/api-worker.env 不存在，请将 envs/core-services/shared.env 重命名为该路径。如果两者都存在，则仅合并缺失的设置并保留现有的 api-worker.env 值，包括有意的空分配。在相应的服务覆盖文件中保留特定于服务的设置。没有 shared.env 的部署不需要迁移。
  4. 合并公共 URL。 仅当 urls.defaults 尚不存在时才从 urls.defaults 创建 envs/core-services/urls.env。将预期的公共 URL 值移至此处，然后从各个服务文件中删除重复的分配。现有根 .env 值保留优先级。将内部 Web API 路由保留在 web.env 中。
  5. 应用环境、路由和队列更改。 遵循配置和集成更改，包括新的 HITL 设置、IM 回调路由和两个 Celery 队列。
  6. 让插件存储初始化运行。 init_permissions 现在还为守护程序的 UID 1001 准备 ./volumes/plugin_daemon，守护程序等待它完成。使用 docker compose up -d 重新创建部署，以便 init 服务运行。 (#45615)

OpenShell 部署

将 OpenShell 网关和 SDK 一起升级到 0.1.3 或支持的 0.1.x 系列中的更高版本，并一起升级 Dify API 和代理后端。网关必须支持本机服务公开和承载直通，保留从 ZZPH100​​ZZ 派生的每个沙箱授权令牌。在代理后端副本之间保持该主密钥相同。 (#45862) 从版本签出构建 OpenShell 运行时映像，并将 DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE 设置为网关计算节点可用的确切映像引用。图片必须同时包含 shellctl 和 iproute2；较旧的缓存运行时映像可能缺少所需的网络工具。 从以前的共享部署范围 shellctl 令牌升级时，生成新的高熵主密钥并一起更新所有代理后端副本。排空活动工作，然后停止并重新启动现有沙箱，以便 shellctl 使用派生凭据重新启动。重新获取已经正常运行的沙箱不会刷新其凭据。 共享卷主快照和 DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH 已删除。现有正在运行的沙箱在停止/重新启动周期中保留其状态，而新创建的绑定则从图像的默认主页开始。 DIFY_AGENT_OPENSHELL_DRIVER_CONFIG 现在是可选的。在升级之前，请查看 OpenShell 部署指南，包括其运行时映像要求。其他沙箱后端不受影响。

Docker 撰写

发布 1.20.0 标签和镜像后，正常停止部署，切换到发布版本，迁移本地配置文件，然后拉取并启动更新的服务：

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

保持启用 API 启动迁移 (MIGRATION_ENABLED=true)，或在启动新工作线程之前通过托管迁移流程应用完整的迁移链。更改环境文件后使用docker compose up -d；简单的重新启动不会重新加载它们。

源部署

在 24.x 行中使用 Python 3.13、Node.js 24.22.3 或更高版本，以及 pnpm 12.18.0。停止服务并切换到发行版后，从存储库根目录运行以下命令：

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile
