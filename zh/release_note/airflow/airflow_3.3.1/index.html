重大变化

Pandas 3 改变了 DataFrame XCom 的存储和读回方式 (#71169)

pandas 3 从“pandas”命名空间公开其公共类，因此 DataFrame 被限定为 pandas.DataFrame instead of pandas.core.frame.DataFrame。 XComs 将该名称与 序列化值，因此写入元数据数据库的名称取决于pandas的版本 推动价值的组件。 Airflow 注册两个名称以及由其中之一写入的 DataFrame pandas 版本可以由任何一个读取 - 无需更改配置，现有的 XCom 保留 可读。

你应该做什么：

  • 在 pandas 3 到达任何组件之前将此 Airflow 版本推广到每个组件 — 工作人员 特别是。在此更改之前的组件无法读取写入的 DataFrame XCom pandas 3，拉动失败：

    .. 代码块:: 文本

    ImportError：在反序列化导入的允许列表中找不到 pandas.DataFrame。
要允许它，请将其添加到配置中的 allowed_deserialization_classes 中

    该消息指向配置，但允许列表不是原因，更改它也不会 帮助。这些行没有损坏：一旦阅读器升级，它们就会再次可读。

  • 将降级视为那些 XCom 的单向门。 回滚到 Airflow 版本，无需 此更改会搁置在 pandas 3 上编写的任何 DataFrame XCom，并出现相同的错误，直到您 再次向前滚动。

  • 查看检查拉取的 DataFrame 的“dtypes”的 Dags。 reader 的 pandas 版本 确定拉取的 DataFrame 的外观，而不是编写它的版本。在 pandas 3 下， 字符串列返回为“str`` rather than ``object”及其缺失值 返回为“nan`` rather than ``None”。值未更改，但下游代码发生分支 在“dtype == "object"``, checks cells with ``is None”上，或与参考系进行比较 升级后，“DataFrame.equals()”的行为可能会有所不同。

修复配置自定义 Dag 捆绑包时 2.x 到 3.0+ 升级失败的问题 (#70994)

“0082_3_1_0_make_bundle_name_not_nullable”迁移分配了每个旧行 bundle_name='dags-folder', so triggering a DagRun raised 请求的捆绑包“dags-folder”是 未配置。 on any deployment that uses a bundle other than the default dags-folder。 “DagFileProcessorManager”现在在启动时运行一次性的尽力回填，路由每个 根据其文件路径将 Dag 影响到正确的包；无与伦比的 Dags 在接下来的自我修复 成功解析（或运行“airflow dags reserialize”立即强制解析）。

注册为敏感的选项的团队范围值现在被隐藏 (#71099)

配置选项在其基本部分下注册为敏感选项，因此到目前为止只有 选项的基本拼写被屏蔽。团队范围的覆盖——在“[<team>=<section>]”中设置 配置文件部分，或通过 AIRFLOW__<TEAM>___<SECTION>__<KEY> 环境变量 — 未被识别为相同选项并被全额退回。

现在，灵敏度是在解决团队范围拼写回基本选项后决定的，因此 团队范围的价值与基本价值完全一样。

行为改变：

  • AirflowConfigParser.as_dict(display_sensitive=False), GET /config, GET /config/section/{section}/option/{option} and airflow config list 现在返回 “< hidden >”表示注册为敏感的选项的团队范围值。部署 通过其中任何一个来读取团队的真正价值现在将获得面具；使用 display_sensitive=True 需要真实值且合适。
  • 团队范围为“_cmd`` and ``_secret`` entries are replaced with ``< hidden >”，而不是 而不是像在基本部分中那样被解析为它们的值并被删除。解决它们 团队不支持，因此命令字符串或秘密路径也不再显示。
  • 非团队配置不受影响，display_sensitive=True继续返回真实 价值观。
