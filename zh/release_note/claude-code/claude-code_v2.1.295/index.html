claude-code v2.1.295

发生了什么变化

  • 为命令和 HTTP 挂钩添加了 onFailure: "block"：无法启动、超时或以意外代码退出的挂钩会阻止操作而不是让它通过
  • 添加了程序状态协议 (OSC 7501) 支持：实现该协议的终端可以显示 Claude Code 是否正在工作、正在等待您或已完成
  • 向 /copy 选择器添加了引用文本，因此起草的消息在复制时没有 > 标记
  • 当 claude plugin install、enable、disable 和 marketplace add 写入的设置文件未加载时，添加了警告
  • 在 stderr 上添加了一行，当它是终端时，说明 claude -p 运行在最后一轮后保持打开状态时正在等待什么
  • 在 Claude 应用程序网关的 Bedrock、Vertex、Foundry 和其他云上游添加了对 timeouts.upstream_ttfb_ms 的支持：您现在设置的值限制了流在此处启动所需的时间，之后它将进行故障转移或收到 502
  • 当 ← 等待当前工具完成时停止转动时，添加了“后台取消”消息
  • 向上游的每个 Claude 应用程序网关添加了可选的 models 列表：只有列出的模型会发送到那里，故障转移时也是如此，并且条目中的一个 * 是通配符
  • 在没有托管设置的计算机上，在您自己的用户设置中添加了对 forceLoginMethod: "gateway" 和 forceLoginGatewayUrl 的支持，因此 /login 在 Claude 应用程序网关上打开
  • 当插件的自述文件没有安装行时，向 claude plugin validate 添加了建议：它会打印要粘贴的行，并且永远不会更改退出代码，即使使用 --strict 也是如此
  • 将 upstream_request_id 添加到 Claude 应用程序网关的 inference 审核事件：来自 Amazon Bedrock、Anthropic API 或其他上游的请求 ID，用于支持案例
  • 为 mods 添加了 $.ui.notify：通过您自己的通知设置引发本机通知并说明哪个频道发送了它
  • 将子项添加到 mod 的 Button：字符串和 Text，因此列表的一行是可按下的，里面有芯片或暗淡的细节
  • 添加了 CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS 以限制无人值守重试模式 (CLAUDE_CODE_RETRY_WATCHDOG) 等待 429 和 529 错误的时间
  • 在 Claude 应用程序网关的成功推理响应中添加了 request-id 标头，因此 Claude 代码遥测中的 request_id 与网关的审核日志相匹配
  • 修复了当网关、Bedrock、Vertex 或 Foundry 拒绝 context-1m beta 时 [1m] 模型上的每个请求失败的问题；克劳德代码现在在没有它的情况下重新发送
  • 修复了当后台工作开始另一轮时 claude -p 文本输出会丢弃较早响应的问题；现在，当回合结束时，会打印每个回合的响应
  • 修复了无头和 SDK 会话中的远程 MCP 服务器在中断超过 15 秒后保持断开连接的问题，或者以紧密循环的方式重新连接到服务器，该服务器在连接后立即断开每个连接；重复下降现在会减少，最多 30 秒
  • 修复了当服务器的错误回复恰好包含网络错误名称时远程 MCP 连接被丢弃的问题
  • 修复了 MCP 服务器在每次连接时重复请求同一页面最多 20 次的分页光标
  • 修复了 MCP 工具返回的 CSS、JavaScript 和 XML 文件被保存为 .bin 的问题，而读取工具拒绝这样做；字体和图标文件现在也有自己的扩展名
  • 修复了模型通过 command_description 而不是 description 时 Bash 工具调用失败的问题
  • 修复了 Chrome 中的 Claude 未将使用端口 80 (host:80) 编写的站点拒绝规则应用于该主机上的普通 http:// 页面的问题
  • 修复了 /plugin 的“错误”选项卡，在不先询问的情况下按 Enter 键删除无法加载的市场并卸载其插件
  • 修复了 claude plugin marketplace add 报告其名称下无法安装插件的市场成功的问题；现在这样的添加被拒绝
  • 修复了 CLAUDE_AUTO_BACKGROUND_TASKS 将子代理移动到后台，而编辑或 shell 命令在其后面等待，这会在子代理完成之前启动该调用

  • 修复了登录到 Claude 应用程序网关的会话中 availableModels 中列出的《神鬼寓言》模型不会出现在 /model 选择器中的问题；这样的模型现在显示其内置行，而不是为同一模型添加的 modelPicker 行
