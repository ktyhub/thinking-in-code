claude-code v2.1.285

发生了什么变化

  • 添加了 CLAUDE_CODE_DISABLE_WEB_FETCH 环境变量以关闭 WebFetch 工具
  • 添加了 claude --desktop 以在当前目录或与 --continue / --resume <id> 的会话中打开 Claude 桌面应用程序
  • 添加了 claude plugin configure <plugin> 以显示插件的选项以及未设置的选项，或使用 --values-stdin 保存从标准输入读取的新值
  • 将<server>.<key>=<value>添加到claude plugin install --config，因此可以在安装时设置捆绑的.mcpb MCP服务器自己的设置，并且无需访问/plugin即可启动→配置
  • 添加了 allowedProviders 托管设置，以限制机器可以使用哪些 API 提供程序（Anthropic API、自定义端点、Bedrock、Mantle、Vertex AI、Foundry、AWS 上的 Claude Platform 或云网关）
  • 添加了 CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES 环境变量以限制重新发送超时的非流回退请求
  • 修复了 claude -p 和 CLAUDE_CODE_FORK_SUBAGENT=1：子代理自己的代理调用现在在前台运行，因此子代理获取子代理的结果
  • 修复了通过 SSH 忽略 GIT_SSH 或 git 配置的 core.sshCommand 中设置的 ssh 程序的插件和市场安装和更新
  • 修复了当操作系统拒绝读取托管设置文件时克劳德代码拒绝启动的问题；现在，它会在没有该文件策略的情况下发出警告并启动。其他读取错误和无法解析的文件会停止每个会话
  • 修复了会话压缩后重新启动的云会话，拒绝对会话已读取或发布的工件进行下一次更新
  • 修复了 claude plugin disable 和 enable 的完整 name@marketplace id 更改另一个字母大小写而不是已安装插件自己的设置条目
  • 修复了通过远程控制发送的消息中附加的文件在单次下载失败后被遗漏的问题；网络错误、超时或服务器错误现在最多重试两次
  • 修复了使用 set_model 请求（例如代理 SDK 的 setModel）在会话中切换模型的问题，使新模型保留内置输出令牌限制和自动压缩窗口，直到重新启动
  • 修正了编辑日志和记录，显示包含 @ 的 URL 密码的一部分，或当 URL 将其 @ 写为 %40 时显示全部密码
  • 修复了工作树中的 SSH 密码和新主机提示以及接管终端的 /teleport 获取；这些获取现在会快速失败而不是询问
  • 修复了关闭在 SDK 和 -p 会话中添加的 MCP 服务器的问题，使其工具可用
  • 修复了 claude -p --permission-prompt-tool：后台子代理的权限请求现在转到提示工具，而不是被自动拒绝
  • 修复了 claude mcp list 和 claude mcp get，以及 claude mcp remove、login 和 logout 的未找到错误，从 MCP 服务器名称和值打印换行符和终端转义序列
  • 修复了沙箱自动允许在每次运行许多内联脚本（python3 -c、node -e）时请求批准，只是因为它们包含 =
  • 修复了分叉子代理不保留会话的计划模式或 dontAsk 模式的问题：分叉现在在其父级的权限模式下运行，并且无法退出计划模式
  • 修复了 claude remote-control --help 说 --[no-]chrome 默认为机器的 /chrome 设置；除非通过 --chrome，否则生成的会话会使 Chrome 中的 Claude 保持关闭状态
  • 修复了自动模式下的后台子代理在每次报告后提示第二个冗余回复的问题
  • 修复了云会话创建和 /remote-env 仅读取最新 20 个帐户环境的问题
  • 修复了远程控制在消息到达时将其标记为已读的问题，而不是在克劳德开始处理该消息时，以及在终端退出时丢失仍在排队的消息的问题（现在它在下一个恢复时到达）
  • 修复了使用 claude plugin install 或 /plugin 安装插件时，当它们的 ID 仅在 .、-、@ 或（macOS、Windows）capitals 中不同时，将其放入已安装插件的缓存或数据文件夹中；现在安装被拒绝
  • 修复了当计划写入同一响应时，挂钩和 SDK 权限回调在 ExitPlanMode 上看到丢失或过时的计划
  • 修复了云会话中的第一个回复迟到数十毫秒的问题，这是 2.1.283 中的回归
  • 修复了使用 ANTHROPIC_AUTH_TOKEN 针对 Anthropic API 进行身份验证的会话永远不会加载组织的策略
  • 修复了工作流程脚本稍后等待或根本不等待的失败的 agent()、parallel() 或 pipeline() 调用，被视为未处理的承诺拒绝，这可能会结束后台会话
  • 修复了同步钩子在钩子启动的后台进程（例如 some-daemon &）保持其输出打开时挂起克劳德代码的问题；现在，钩子在其自己的进程退出后不久就会完成
  • 修复了 WebFetch 将限速域安全检查报告为网络或企业策略块的问题
  • 修复了全屏 ctrl+o 记录在轮流打开并进行数百个文件读取或搜索时短暂冻结的问题；现在，当文本打开时，工具调用仍在运行，完成后会显示结果
  • 修复了 Amazon Bedrock 中游 modelTimeoutException 和 serviceUnavailableException 错误，显示原始 JSON 正文而不是错误消息
  • 修复了 /autofix-pr 和 /schedule 表示 Claude GitHub 应用程序未安装在尚未检查安装状态的存储库上的问题
  • 修复了取消 /artifacts 中的行 (x) 取消其文件与工件的链接，因此再次发布同一文件会创建一个新工件而不是更新它
  • 修复了工件工具在对话倒带（Esc Esc）后发布的内容，覆盖克劳德仅在倒带轮中读取的文件的新内容；现在拒绝发布，直到克劳德重新阅读该文件
  • 修复了 Artifact 允许规则（“不再询问”），允许 Artifact 工具在工作目录之外发布文件而无需询问；添加带有 --add-dir 的文件文件夹，以便规则覆盖它
  • 修复了当服务器使用与 client 预期不同的后备模型回答拒绝时，/cost 和 SDK modelUsage 报告在错误模型下转弯的问题
  • 修复了 Artifact 工具，以便发布页面不再让 Claude 覆盖其源文件，而无需重新读取，当 Claude 之前的读取被缩短或文件已更改时
  • 修复了当您之前在另一种权限模式下批准该工件时，自动模式会跳过工件工具资产上传的分类器并读取其他人的工件的问题
  • 修复了当项目文件夹短暂无法读取时 /ultrareview 中的误导性“core.worktree is set”错误
  • 修复了 macOS 和 Linux 上的 /ultrareview 无法从每个工作树配置设置 core.longpaths 的 git 工作树上传工作树的问题
  • 修复了 Artifact 工具有时会在重试临时服务器错误后报告发布与另一个会话冲突，而第一次尝试实际上已成功
  • 修复了 /ultrareview 上传，包括对名称扩展名前有冒号的凭证文件进行未提交的更改，例如 server:8443.key
  • 修复了两个会话同时恢复崩溃进程留下的登录刷新锁时罕见的身份验证失败
  • 修复了 PowerShell 工具的权限检查在其命令解析器无法启动时（例如，当计算机内存不足时）跳过拒绝和询问规则，并缓存该失败以供以后检查的问题
  • 修复了 macOS 和 Linux 上的 /ultrareview 上传在某些不寻常的文件名上运行缓慢的问题，并且其凭证文件检查丢失的文件或文件夹名称以及许多备份或编辑器标记
  • 修复了当取消在设置过程中到达时，取消的 shell 命令或挂钩仍然启动并运行到结束的问题
  • 修复了 vim 模式：在外部编辑器 (Ctrl+G) 中编辑后，正常模式下的 x 或 r 不再破坏提示末尾的粘贴文本占位符
  • 修复了被重新发送和重试的 API 输出内容过滤器阻止的响应，有时需要几分钟，而不是立即显示过滤器的错误
  • 修复了插件静默跳过仍需要配置的捆绑 .mcpb MCP 服务器：/plugin，安装消息和 claude plugin install 现在这么说并指向配置
  • 修复了压缩或恢复会话失败、在没有历史记录的情况下打开或在其保存的记录包含压缩标记或循环唤醒条目（字段丢失或格式错误）时崩溃的问题
  • WSL：修复了当更改的文件名包含冒号或以点或空格结尾时，/ultrareview 拒绝在 Linux 卷上上传结帐的问题

  • 修复了浏览器显示成功后可能永远等待的登录问题
  • Windows：修复了 /ultrareview 在某些情况下上传根植于您的主文件夹的存储库的链接工作树的问题
  • 修复了云会话在上传任何文件之前报告上传文件夹丢失的问题
  • 修复了从 claude agents 发送到后台会话的回复，等待权限提示，有时会批准挂起的命令
  • 修复了 claude attach、logs、stop、respawn 和 rm 在选项出现在命令之前（例如来自 shell 别名）时以命令名称作为提示符启动新会话的问题
  • 修复了 claude mcp list 遗漏 WebSocket (ws) MCP 服务器的问题；每个现在都列出了其 URL 和健康状态
  • 修复了 claude mcp get 对于配置条目省略 type 字段的 stdio 服务器不显示类型、命令、参数或环境的问题
  • 修复了配置 git 的 trace2 输出时，.claude/settings.local.json 允许规则保留在 git 存储库之外的问题
  • 修复了 /claude-api 评估运行器脚手架和报告生成器通过植入在输出文件中的符号链接或硬链接进行写入的问题
  • 修复了 /claude-api 评估跑步者脚手架计数响应在平均分数中在 max_tokens 处截止的问题；它们现在被标记为截断并单独计数
  • 修复了当回复使用 &nbsp; 缩进文本（例如 Markdown 表中的行标签）时，&nbsp; 在终端中显示为文字文本
  • 修复了全屏模式之外的长时间会话中途的短暂冻结（最多一秒），该冻结在 /clear 或 /compact 后返回
  • 修复了当目标是设备（例如符号链接到 /dev/null 的文件）且批准来自 IDE diff 视图或更改编辑时，已批准的编辑永远不会通过的问题
  • 修复了当流媒体持续失败时，失败的 API 请求重试最多 21 次的问题；非流式回退现在共享请求的重试预算，而不是获取一组新的重试
  • 改进了 Chrome 中的 Claude：本机主机现在报告您的计算机名称，因此可以通过计算机标记连接的浏览器，而不是“浏览器 1”/“浏览器 2”
  • 改进了 Bedrock 和 Vertex AI 会话，当管理员删除对默认模型的访问权限时，可以切换到同一层的较旧可用模型，而不是失败；会议标题和摘要现在随之回落

  • 改进的工件工具发布结果以使用更少的令牌：有关更新工件的注释更短，并且每次发布后不再重复在哪里可以找到工件
  • 改进了非流回退请求期间的 SDK 活跃度：在打开部分消息的情况下，现在在 Anthropic API、AWS 上的 Claude 平台和网关上每 30 秒发送一个 ping 流事件
  • 改进了在后台运行的会话上的 /resume 和 claude --resume：它们现在打开该会话而不是拒绝，并且 claude --resume <id> "prompt" 给出的提示会在下一轮发送给它
  • 配置许多权限拒绝规则和 MCP 工具时提高了每轮性能
  • 改进了全屏渲染关闭时在长时间会话中离开 ctrl+o 转录视图时的响应能力

  • 更改了/内存，以便不再可以从后台会话或从 Claude Code 自己的工具之一启动的会话打开自动内存；把它关掉仍然有效
  • 更改了一次性优惠，使自动模式成为您的默认权限模式，当您的用户设置默认为另一种模式时，也可以在第三方提供商上显示并关闭遥测功能
  • 更改了第三方提供商上的 claude -p 和 Python 代理 SDK 会话，或者在未配置权限模式时关闭遥测以自动模式启动，例如交互式会话； --permission-mode 仍然覆盖它
  • 将 AWS 上的 Bedrock、Mantle 和 Claude Platform 请求更改为具有非默认端口的基本 URL，以将该端口包含在 SigV4 签名的主机标头中
  • 更改了 MCP 服务器名称 widgets 以在云会话和自托管运行器上保留：您自己的服务器在其下，或类似 widgets_ 的紧密拼写，不再加载，因此将其重命名
  • 更改了 macOS 和 Linux 上的 /ultrareview，以便在上传本地结帐时保留符号引用；当前分支是符号引用的结帐现在被拒绝并给出解释
  • Windows：更改了项目和本地设置 env，不再设置 ALLUSERSPROFILE、SystemDrive 或 CommonProgramFiles 变量；相反，请在用户或托管设置中设置它们
