claude-code v2.1.302

修订 发布时间2026年10月16日 来源anthropics/claude-code 英文原文

claude-code v2.1.302

发生了什么变化

  • 新增CLAUDE_CODE_AUTO_MODE_MODEL选择client侧自动模式分类器使用的型号；它不会更改服务器端自动模式的模型
  • 在 /config 中添加了 Idle compaction 行，用于关闭或重新打开空闲压实；空闲压缩后显示的通知现在说明如何将其关闭
  • 向 /design-sync 和 /design-login 添加了独立 Claude Design (claude.ai/design) 将于 2026 年 12 月 14 日关闭的通知
  • 修复了在压缩对话时停止转弯时出现的“提示太长”错误
  • 修复了在会话中切换到 Vertex 或 Bedrock 后请求失败并显示“诊断：不允许额外输入”的问题
  • 修复了读取工具将任意大小的图像文件或以图像命名的管道或设备完全加载到内存中的问题；超过 128 MB 的图像源现在被拒绝
  • 修复了当网关使用前缀（例如 anthropic/claude-opus-4-1）命名 Opus 4 或 4.1 时，/autocompact 和 /effort 保存到错误模型的问题
  • 修复了通过 ToolSearch 或压缩后再次加载在会话中添加的工具时提示缓存未命中的问题
  • 修复了 claude plugin 和其他子命令有时在排队设置或配置写入完成之前退出的问题，这可能会丢失更改或留下 .tmp 文件
  • 修复了每次刷新时重新克隆插件市场，以及当 git 默认为 reftable ref 格式时新安装的 git 插件显示版本“未知”的问题
  • 修复了 PowerShell 工具在插件的 bin/ 文件夹中找不到命令，并在将未找到任何内容的搜索（rg、grep、findstr、git grep）通过管道传输到 Select-Object 或其他格式化 cmdlet 时报告错误的问题
  • 修复了桌面应用程序中的 Claude 指向 claude.ai 设置或 /mcp 来授权或重新连接 MCP 服务器（该选项不可用）的问题
  • 修复了当克劳德发送空的编辑列表时，以及在较新版本的工件将其关闭后，克劳德以错误的方式重试工件更新时，工件发布有时会失败的问题
  • 修复了大多数自动模式分类器块的 OpenTelemetry tool_decision 事件中缺少 classifier_category 的问题，以及当 OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT 较低时推出 tool_use_id、tool_source 和 tool_parameters 的新 tool_decision 属性
  • 修复了代理视图中的行在向下移动长列表或折叠部分后保持空白的问题
  • 修复了 claude remote-control --help 在未登录时不打印其用法并退出的问题
  • 修复了 /design consent 和 /design revoke 在云会话中失败时建议 /design-login（该会话不可用）的问题；该消息现在指向 claude.ai/design/settings
  • 修复了当服务器协商协议版本 2026-07-28 但省略 resultType、ttlMs 或 cacheScope 时，MCP 服务器显示没有工具或每个工具调用失败的问题
  • 修复了在您的计划仅使用积分支付的模型上花费使用积分的提示建议：现在在按积分计费的回复后会跳过它们
  • 修复了用反引号编写的 URL 在换行时仅在第一行为 clickable 的问题；现在，整个 URL 是支持超链接的终端中的一个链接
  • 修复了 claude plugin details <name>@builtin 建议 claude plugin list，当未找到插件时，它从不显示内置插件；它现在指向/plugin
  • 修复了一个表情符号，即链接开始时将一列包裹得太宽，从而将其隐藏在有问题的预览中并将表格变成列表
  • 修复了当杂散 .git 文件指向不存在的目录时，工作树隔离拒绝在 git 2.56 或更高版本下创建或恢复工作树的问题
  • 修复了在新进程中恢复会话后云会话的成本和使用量从零重新启动的问题
  • 自托管运行器：修复了重用以 git reftable 格式存储的结账的会话中 git 获取因“坏对象引用/头”而失败的问题
  • Windows：修复了 exFAT 或 FAT32 驱动器上项目的每个文件写入被拒绝或询问的问题，包括在使用 --plugin-dir 启动的会话中
  • 启用许多插件后，改进了启动时间：插件命令和代理文件现在加载所需的文件系统调用要少得多，尤其是在 Windows 上
  • 使用服务器端分类器改进了自动模式：对于安全检查来说太长的对话现在被压缩，而不是每个检查的工具调用都被拒绝
  • 改进了从另一个文件夹重新打开的后台会话没有 LLM 网关时的消息：它现在显示原因，而不是“未登录”
  • 将无权限模式的 claude -p 和代理 SDK 会话更改为在第三方提供商上以 default 模式启动，遥测关闭或全新安装； --permission-mode auto保持自动
  • 将 fork 子代理 (subagent_type: "fork") 更改为在 claude -p、代理 SDK、桌面应用程序和 VS Code 中默认打开，因为它们已经在终端中； CLAUDE_CODE_FORK_SUBAGENT=0 将其关闭，而 claude mcp serve 从不提供它们
  • 更改了桌面应用程序和 VS Code，以始终在后台运行主对话的子代理，就像终端一样，而不是让 Claude 选择；子代理自己的代理在 claude -p 中调用，代理 SDK、桌面应用程序和 VS Code 现在默认在前台运行
  • 将 ← for agents 页脚提示更改为在会话打开后 10 秒隐藏；等待您的客服人员数量仍然显示
  • 更改了 Chrome 中的 Claude 指令在系统提示中的位置，以便新对话可以从共享提示缓存中读取它们
  • 更改了提示和代理挂钩，以便一次最多运行 12 个事件；其余的人等待轮到他们
  • 更改了当组织的策略关闭 /feedback 时显示的消息：它现在指向 GitHub 问题而不是组织管理员
  • [VSCode] 修复了列表中未封闭代码块之后的文本在回复流时显示为纯文本，然后转换为代码的问题
  • [VSCode] 修复了当服务器 URL 包含查询字符串时从面板打开损坏的授权页面的 MCP 服务器登录问题
  • [VSCode] 修复了当无法访问带有 Claude 扩展的浏览器时 @browser 横幅显示“浏览器已连接”的问题
  • [云会话] 在例程页面上添加了一个横幅，说明其上次运行未启动的原因，例如您的组织达到了并发云会话的限制
  • [云会话]修复了除云会话中最新消息之外的每条消息“倒回至此处”失败的问题；自托管运行器需要 Claude 代码 v2.1.246 或更高版本
  • [云会话]修复了云会话中的拉取请求状态栏，当 GitHub 重新检查它时，将具有合并冲突的拉取请求翻转回就绪状态
  • [云会话]修复了例程运行在云会话意外停止后显示为“已完成”，以及在开始之前存档时显示为“取消”，而不是失败的问题
  • [云会话] 修复了云会话中的差异视图在会话的 GitHub 存储库被重命名或移动后丢失更改或无法加载的问题
  • [云会话] 修复了一个计划的例行运行，该例行运行中途失败，但在一个小时或更长时间后从一开始再次运行，这可能会重复工作，例如两次发布相同的报告
  • [云会话] 修复了开放云会话有时不会显示从其他设备发送的消息，直到您重新加载页面或 cli 离开并返回
  • [云会话] 改进了云会话无法启动时显示的错误：现在显示“连接丢失”或“服务器错误”，而不是“出现问题”
  • [远程控制]修复了计算机离线后，远程控制会话中子代理的窗格永远旋转的问题；现在显示远程控制已断开连接
  • [Claude Tag] 修正了“正在思考……”，在 Claude 通过编辑其早期消息进行回复后，在 Slack 频道或 DM 中的提及下熬夜
  • [Claude Tag] 修复了 Claude Slack 回复的编号或项目符号步骤下的代码块中的 URL 被包裹在尖括号中，这会破坏复制的命令
  • [Claude Tag] 修复了 Slack 中附加的 HEIC、SVG、TIFF 和 BMP 图像永远无法到达 Claude 的问题；它们现在作为文件到达其工作文件中，就像其他文件类型一样
  • [Claude Tag] 修复了按角色限制 Claude Tag 的组织中新渠道经理无法访问 Slack 中的 Claude 的问题；经理角色现在还授予 Slack 中的 Claude Tag
  • [Claude Tag] 修复了 MCP 服务器共享一台主机的自定义连接器，在 Claude Tag 管理设置中显示为单个连接器；现在每个服务器都有自己的连接器
  • [Claude Tag] 修复了 Slack 中的 Claude 有时会回复直接消息“DM 暂时不可用”，并在单个 Slack 查找停滞时丢弃该消息；现在它首先重试
  • [Claude Tag] 修复了在 Slack Enterprise Grid 上与 Claude 直接消息忽略 Slack 的工作区下拉列表的问题；它们现在在您上次打开 Claude 的连接工作区下运行
  • [Claude Tag] 修复了 Slack 中 Claude 通知频道的每月支出限额时说频道经理可以提高限额的问题；现在，它指定了组织所有者并链接了使用页面
  • [Claude Tag] 修复了 Claude Slack 回复中的链接吸收了紧随其后的结束粗体或斜体标记或全角标点符号，从而破坏了链接和格式
  • [Claude Tag] 改进了 Claude Tag 管理设置中的存储库搜索，可覆盖最多 100 个已连接的 GitHub 帐户，并查找 GitHub 应用程序安装的前 5,000 个之后的私人存储库
  • [Claude Tag] 改进了 Claude Tag 管理设置中的添加位置，以列出您立即键入或粘贴的频道，而不是仅在加载组织的完整频道列表后才列出
  • [Claude Tag] 改进了 Claude Tag 管理设置中工作区或频道页面上的“添加”>“域”，以便在该页面加载后可用，而不仅仅是在每个频道加载后可用
  • [Claude Tag] 更改了 Claude Tag 管理设置，将 Claude 的访问权限组织到四个选项卡中：捆绑包、连接器、技能和插件以及频道
  • [Claude Tag] 更改了组织设置中的角色页面，将为 Claude Tag 渠道经理创建的角色分组到组织自己的角色下方的折叠部分中
  • [代码审查] 修复了在离开连接 GitHub 后代码审查设置无法恢复的问题；回到管理设置，它现在在存储库选择器中重新打开
