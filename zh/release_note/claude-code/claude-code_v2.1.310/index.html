claude-code v2.1.310

修订 发布时间2026年10月23日 来源anthropics/claude-code 英文原文

claude-code v2.1.310

发生了什么变化

  • 添加了对 Bedrock、Vertex 和 Foundry 以及遥测或非必要流量禁用时的监控工具和插件监控；长时间的前台睡眠现在也被阻止了
  • 修复了拒绝 effort-2025-11-24 beta 值或对话中系统消息的某些网关和兼容服务器后面失败的请求；克劳德代码现在在没有它们的情况下重试
  • 修复了当 cleanupPeriodDays 设置为非常大的值时，后台清理会删除一些最近的文件，例如粘贴的图像
  • 修复了“提示太长”错误后的压缩，使过多的对话与密集文本（例如 base64 或 SVG）保持一致，因此下一个请求可能会再次失败
  • 修复了文件读取权限提示不显示符号链接的位置
  • 修复了长时间编辑后外部编辑器关闭时触发问题的自动继续超时的问题
  • Windows：修复了 PreToolUse 和 PermissionRequest 挂钩，让工具在缺少 Git Bash 且挂钩的命令仅为带引号的字符串（例如带引号的路径）时调用
  • 改进了在工作目录之外第一次读取之前自动模式的提示：现在它会说，当阻止这些读取时，会使 shell 命令请求权限
  • 当转录文件非常大时，改进了压缩过程中非交互式会话（-p、代理 SDK）的内存使用
  • 改进了 mod 的 Image 以在 tmux 内绘制 allow-passthrough 和 focus-events，在 kitty、Ghostty 和 iTerm2 3.5+ 中进行全屏渲染，仅显示其 alt 文本
  • Linux：改进了 /sandbox 和沙箱启动警告，以命名 Ubuntu 的 AppArmor 对用户命名空间的限制，以及当它阻止 bubblewrap 启动沙箱时如何解除它
  • 更改了 MCP 工具调用在服务器的引出未得到应答时在非交互式会话中超时的错误：它现在告诉 Claude 没有应答并且不要重复调用
  • [VSCode] 修复了按计划审核卡的“发送反馈并继续计划”按钮上的 Enter 键批准计划而不是发回您的评论
  • [VSCode] 修复了从会话历史记录的 Web 选项卡打开的云会话上“切换分支并继续”后显示“出现问题”的面板
  • [云会话]为企业自定义角色添加了克劳德代码云会话和远程控制权限，因此所有者可以按角色控制对每个会话的访问
  • [云会话]添加了一个选择文件按钮以从文件加载云环境的设置脚本
  • [云会话] 修复了云环境编辑对话框中保存和存档失败的问题，显示对话框内没有错误
  • [云会话]修复了失败的例程 API 令牌操作仅显示祝酒词；错误现在出现在例程编辑对话框中
  • [云会话] 改进了会话启动清单，以在滚动框中显示云环境的设置脚本输出
  • [云会话] 更改了在管理设置中打开云会话或远程控制以要求确认并列出具有该权限的自定义角色
  • [云会话]更改了云环境对话框以从行中打开网络访问、设置脚本和环境变量，而不是一次列出每个编辑器
  • [Claude Tag] 修复了 Claude Tag 在以粗体、斜体或删除线发送时将 ! 命令（例如 !restart 和 !help）视为普通消息的问题
  • [Claude Tag] 修复了当捆绑列表后台刷新失败时 Claude Tag 管理频道和工作区页面被加载错误替换的问题
  • [Claude Tag] 修复了管理设置中 Claude Tag 的支出限制页面报告在频道名称仍在加载时没有频道与过滤器匹配的问题
  • [代码审查]修复了代码审查管理部分在存储库列表刷新失败后隐藏其存储库和切换的问题
  • [代码审查] 改进了代码审查管理部分，以重试第一次加载，并在仍然失败时显示重试横幅
