claude-code v2.1.304

修订 发布时间2026年10月19日 来源anthropics/claude-code 英文原文

claude-code v2.1.304

发生了什么变化

  • 当首先运行的插件跳过你的 mod 的一个钩子时添加了一个脚本行，命名事件和插件
  • 将 decider: "person" 添加到 mod 的 tool.check 答案中：只有权限对话框或主机的回调才能批准请求，并且由于 mod 的原因而拒绝，没有人可以被请求
  • 将 e.isReadOnly 添加到 mod 的 tool.check 事件，当工具调用为只读时设置
  • 添加了 /auto-mode-setup：引导设置，可读取您的项目和最近的会话，以教授有关您的环境的自动模式，现在也可用于 Bedrock、Vertex、Foundry、Claude 应用程序网关和遥测禁用会话
  • 添加了 /claude-api managed-agents-secure，它将 Managed Agents 代理的设置与 Anthropic 发布的安全指南进行比较，而不进行任何更改
  • 在转录视图中的压缩摘要中添加了之前调用的工具的名称（Ctrl+O）
  • 在 Pro 和 Max 计划中添加了一条警告，当恢复不活动的对话将占用您 5 小时使用限制的明显份额时：无论如何都要恢复，或者开始新的对话，如果您参考的话，克劳德可以查找上一个对话
  • 修复了在启动时批准 ANTHROPIC_API_KEY 或在 /config 中切换“使用自定义 API 密钥”后，组织策略直到每小时检查才刷新的问题
  • 修复了当 sandbox.filesystem.denyRead glob 包含非字符类的括号（例如 [user-id] 路由文件夹）时，沙盒命令无法在 Linux 上启动的问题
  • 修复了已安装驱动器或顶层文件夹（/Volumes、/media、WSL 的 /mnt/c）的 rm -r 未收到 rm -rf /Applications 收到的安全提示的问题
  • 修复了 CLAUDE_CODE_TRANSCRIPT_LOCAL_GC 在修剪文件时磁盘已满时从保存的记录中删除消息的问题
  • 修复了一个插件，通过生成子代理或重新运行已完成的代理来保持无头运行经过 --max-turns、停止或结束输入
  • 修复了模组重新加载失败的问题，删除了保持加载版本的工具和命令，并且其关于先前版本是否仍然加载的消息是错误的或无声的
  • 修复了当具有相同标签但没有 key 的按钮被重新绘制不变时，MOD 按钮上的 click 丢失的问题
  • 修复了内置 plugin-authoring 技能中的 mod 共享在具有托管设置的计算机以及团队和企业计划上的秘密扫描时停止的问题
  • 修复了计划的 Cowork 云会话再次等待五分钟的情况，因为每个子代理的 WebFetch 都需要 URL 批准，但没有人在那里给予批准
  • 修复了写入结果和拒绝编辑将工作目录之外的文件显示为 ../../… 的问题；他们现在显示 ~/… 或完整路径
  • 修复了 claude.ai 目录插件的技能在从 Cowork 云会话中的“/”菜单中选取时未作为命令运行的问题
  • 修复了当不同帐户登录到终端时远程控制永久保留桌面对话历史记录的问题
  • 修复了在付费套餐中设置 DISABLE_TELEMETRY 或 DO_NOT_TRACK 时远程控制无法从 Claude Desktop 启动的问题
  • 修复了 SDK 和桌面会话中上下文使用检查后面等待的模型切换、消息和中断
  • 修复了 LLM 网关后面的 context_management: Extra inputs are not permitted 错误；克劳德代码现在重新发送没有该字段的请求
  • 修复了通过服务器管理的设置传递的 OpenTelemetry 设置在首次运行设置期间登录后或 /logout 后首次启动后在整个会话中被忽略的问题
  • 修复了 macOS 和 Linux 上的 Claude Desktop Code 选项卡会话中未沙盒化的 Bash 命令，看不到 shell 启动文件（例如 ~/.zshrc）中导出的环境变量
  • 修复了服务器错误后消费者条款通知被跳过一天或更长时间的问题
  • 修复了网络或服务器错误后 /privacy-settings 提供的选项可能不适用于您的问题
  • 修复了当 Claude Code 压缩 API 因太长而拒绝的对话时停止转弯后出现的“已达到上下文限制”或“提示太长”错误
  • 修正了子代理有时在收到消息或完成后立即恢复时忘记他们最近的工作
  • 修复了 --tools、--resume、--debug、--json-schema、--disable-slash-commands、--system-prompt-snapshot 和 claude update 的 claude --help 文本，以匹配实际行为
  • 修复了 claude --worktree 删除工作树及其分支，当 HEAD 分离或在另一个分支上时，在退出时不询问，这可能会丢失提交
  • 修复了每次启动时重新加载插件时恢复和云会话再次向克劳德发送整个技能列表的问题
  • 修复了未结束等待空闲管道或命名为图像的设备的读取的中断
  • 修复了当 CLAUDE_CODE_EFFORT_LEVEL 为 auto 或 unset 并且未发送级别时，/effort status、/effort ultracode 和提示的工作量指示器显示猜测的工作量级别
  • 修复了当同一工具调用上的代理 SDK 回调挂钩超时时，PreToolUse 挂钩的拒绝原因被超时错误替换的问题
  • 修复了 Bash 和 PowerShell 在无法将大型命令的输出文件复制到会话的工具结果文件夹时删除该文件的问题，除非磁盘已满
  • 修正了在多项选择题中输入的注释，在大约 100 列下的终端中，预览被“…”切断，隐藏了输入的内容 (anthropics/claude-code#82768)
  • 修复了在 1 小时提示缓存过期后按 1 小时最大触发安排的自定进度 /loop 唤醒，因此这些唤醒不再重新读取未缓存的对话
  • 修复了代理团队：批准来自主会话的关闭请求不再退出整个 CLI
  • 修复了一个技能的 once 钩子在运行后也会删除另一个技能的相同钩子
  • 修复了转录模式的 { 和 } 将提示放在不一致的行或屏幕外，而不是转录的第一行
  • 修复了 CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k 静默设置 100K 窗口的问题：该变量现在接受 k 和 M 后缀（如 --autocompact），并在值超出范围或被忽略时发出警告
  • 修复了在释放鼠标按钮之前按下代理视图中的 Ctrl+C 时清除文本选择而不复制它的问题
  • 改进了 /usage，以表示使用数据的速率限制何时结束，而不是“稍后重试”
  • 改进了会话中写入的 mod 加载、重新加载或加载失败时显示的行
  • 改进了具有多个视图的工件：当您询问它们的链接时，克劳德现在会写出每个视图的链接，并解释说当您切换视图时，地址栏保持不变
  • 改进的云会话：新对话的第一回合不再等待从 claude.ai 同步的插件的本地（stdio）MCP 服务器，除非服务器设置 alwaysLoad: true
  • 改进了当服务器拒绝携带其他会话数据的状态更新时远程会话恢复其状态的方式
  • 改进了自动模式下的会话文件大小：安全分类器的上下文不再随每个请求一起存储
  • 改进了 claude -p 无效设置警告：未加载的文件仅列出阻止它的内容，并且每个文件的长列表受到限制
  • 改进了 SDK 和无头模式下大型压缩会话的恢复：恢复后的第一个请求会更快发送
  • 当许多子代理同时运行时，提高了响应能力和吞吐量
  • 改进了在长时间或恢复对话中发送请求时的内存使用情况
  • 自托管运行器：改进了当 git 主机对会话存储库回答“未找到”时显示的错误：它现在命名存储库以及要询问的对象
  • Windows：通过直接运行 git.exe 而不是通过 cmd 启动器，使用适用于 Windows 安装的标准 Git 改进了 git 命令启动
  • 更改了 mods 的 settings.read 挂钩以接收每个设置层并重写合并的设置，因此托管 mod 可以使组织的设置达到上限，包括保留扫描使用的 cleanupPeriodDays
  • 更改了 /artifacts 删除确认以显示编号选项：1 或 Enter 保留工件，2 删除它，y、n 和 Esc 仍然有效
  • 将 Claude 在会话中打开 mods 的问题更改为纯文本，没有链接或会话 ID；当新的回合开始时它会保持亮起状态，克劳德会告诉你打开它们时加载了什么
  • 将自定义 ANTHROPIC_BASE_URL 后面的工具搜索更改为默认打开；如果没有网关，则重试来自网关的 400 或 422
  • 更改了压缩后再次向克劳德发送技能列表； /reload-skills 现在仅发送新的或更改的技能
  • 更改了技能挂钩：一个来源（存储库、您自己的文件夹或插件）的技能每个会话最多可以注册 1,024 个挂钩和 16,384 个匹配器字符
  • 更改了仅允许插件挂钩的策略下的技能：在主要对话中使用的挂钩被排除在外的技能不再获得其 allowed-tools
  • 更新了 /claude-api 技能，以在 AWS 上的 Claude 平台上使用 ant CLI，而不是回退到 SDK 或curl
  • 删除了 claude plugin validate 中预测 mod 的钩子将运行的位置的注释
  • 从 Opus 5.5 的 /fast 对话框标题中删除了“（研究预览）”标签
  • [VSCode] 在 LLM 网关后面或关闭遥测的情况下，在 Amazon Bedrock、Google Vertex AI 和 Microsoft Foundry 上的会话聊天面板中添加了 mod 绘图
  • [VSCode] 修复了会话无法启动并出现“子进程初始化未在 60000 毫秒内完成”的原因之一：SessionStart 命令挂钩运行的时间不再计入限制，总共最多 10 分钟
  • [VSCode] 修复了会话在开始时关闭的问题，保持其 Claude Code 进程运行直到开始结束
  • [VSCode] 修复了 mod 的绘图从长时间打开的面板中消失的问题，直到下一次打开也运行较旧的 Claude Code 的机器为止
  • [VSCode] 修复了设置 claudeCode.claudeProcessWrapper 时过去的对话隐藏会话的问题
  • [VSCode] 更改了后台子代理，使其在代理卡下显示为一条状态行，而不是将每一步都流式传输到聊天中；完整的成绩单保留在 /tasks 中
  • [云会话] 修复了作曲家@列表中的文件夹在云会话中不显示名称的问题，其中选择一个仅添加一个空格而不是提及
  • [Claude Tag] 修复了当任务中的通道在 Enterprise Grid 工作区之间共享时，Claude 在线程中保持沉默的问题；现在它会发布一次性注释以在新线程中@提及它
  • [Claude Tag] 修复了在线程外输入 @Claude !fork 没有得到可见回复的问题；克劳德现在向您展示一条私人注释，说明要从线程内部运行它
  • [代码审查] 为代码审查添加了审查级别：所有者为组织选择“快速”、“标准”（默认）或“深度”，并且可以为各个存储库提供自己的级别
  • [代码审查]在代码审查管理设置中添加了一个选项，可以审查GitHub组织中的每个存储库，包括后来添加的存储库，而无需一一选择
  • [代码审查]修复了管理员打开代码审查后一两分钟内打开的拉取请求被默默跳过的问题；现在正在重试和审查
