claude-code v2.1.301

修订 发布时间2026年10月15日 来源anthropics/claude-code 英文原文

claude-code v2.1.301

发生了什么变化

  • 添加了 CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS，因此无人值守重试模式 (CLAUDE_CODE_RETRY_WATCHDOG) 在使用限制处结束请求，重置距离太远而不是等待
  • 在 claude-api 技能中添加了 OpenTelemetry 跟踪指南，包括使用 ant CLI 设置跟踪目标
  • 在 vim 模式中添加了 % 动作：单独或与 d/c/y 一起跳转到匹配的括号
  • 将 rows 添加到 mod 的 Input：终端中多行的文本字段，其中 Enter 提交，Shift+Enter 或 Enter 之前的反斜杠开始新行
  • 将 classifier_verdict 和 permission_mode 添加到 OpenTelemetry tool_decision 事件，因此可以将自动模式分类器决策与权限规则分开
  • 将 classifier_category 添加到 OpenTelemetry tool_decision 事件，命名分类器块匹配的内置规则（当 OTEL_LOG_TOOL_DETAILS=1 时）
  • 修复了退出删除由 WorktreeCreate 挂钩创建的工作树而不询问它何时可以保留未推送的提交的问题
  • 修复了当最新的《神鬼寓言》模型对您的组织不可用时，Anthropic API 上的 fable（和 best）模型别名错误：克劳德代码现在在以前的《神鬼寓言》模型上重试一次
  • 修复了磁盘已满导致登录无法刷新时出现的误导性“请运行/登录”错误；现在错误命名磁盘并表示删除文件
  • 修复了当搜索程序在返回任何结果之前意外失败时 Grep 和 Glob 报告没有匹配项的问题；他们现在返回一个错误，表示搜索失败
  • 修复了工作流代理有时会跳过其步骤，并且在阅读其任务文本不包含用户权限的线束注释后，运行仍报告成功的问题
  • 修复了 PreToolUse 挂钩覆盖编辑或写入时拒绝工件更新的问题；克劳德现在编辑文件，然后重新发布，而不是在发布调用中更改它
  • 修复了参数名称非常多或非常长的技能和命令在调用时会停滞数秒的问题；现在仅填写前 64 个名称，每个名称最多 64 个字符
  • 修正了技能、命令和钩子在其参数填充许多占位符时使用大量内存的问题
  • 修复了在早于 0.53 的 VTE 上构建的终端（例如 RHEL 8 上的 MATE 终端）中的杂散字符，例如 >0q 覆盖文件夹 trust 提示符，以及退出时 shell 提示符之前的 >4m
  • 修复了某些版本的 iTerm2 启动时提示中出现的杂散 GOK 文本
  • 修复了切换到名称包含 application-inference-profile 的模型运行 awsAuthRefresh 命令并在提供者不是 Bedrock 时延迟模型切换挂钩的问题
  • 修复了在令牌刷新过程中退出 claude auth status 或 claude plugin list 等短命令后登录刷新超时和意外注销的问题
  • 修复了工具调用因权限检查期间发送的消息被报告给模型被用户拒绝而中断的问题
  • 修复了切换到上下文窗口较小的模型可能会在不先询问的情况下将使用积分花费在先前模型的摘要上的情况
  • 修复了在 LLM 网关后面，在您未选择的模型上一遍又一遍地压缩对话的问题，该网关的响应命名的模型与请求的模型不同
  • 修复了 vim 模式有时在慢速或繁忙的机器上转义后停留在 INSERT 状态的问题
  • 修复了 Esc 在 vim 模式下丢弃键入的 AskUserQuestion 答案的问题：自由文本字段现在支持 vim NORMAL 模式，并且 Esc 仅从 NORMAL 取消
  • 修复了读取工具将 .xlsm、.parquet、.epub 和 .heic 等二进制文件作为文本读取的问题
  • 修复了一个 Markdown 表格，只有一个标题行，当对于终端来说太宽时，不会绘制任何内容，包括在计划批准卡上的计划中
  • 修复了 /claude-api 技能，指出 CMEK 外部密钥端点在 AWS 上的 Claude 平台上不可用
  • 修复了使用 /rewind 后技能不再列出到模型中的问题
  • 修复了恢复会话中的压缩行，为未加载的历史记录提供 ctrl+o ；现在它会显示早期消息的保存位置，并且还会全屏显示
  • 修复了中断响应后立即返回的“新任务？/清除以保存令牌”提示
  • 修复了插件或技能挂钩的 ask 决定的权限提示不显示该挂钩来自哪个插件或技能
  • 修复了当 /diff 的 git 检查之一超时或失败时，/diff 没有注意到可引用存储库中存在冲突的樱桃选择或恢复的问题
  • 修复了在同一会话中的 Bash cd 后读取、编辑或重新运行时请求许可或被拒绝的工作流程脚本
  • 修复了深色 ANSI 主题和 16 色终端上的暗淡文本：填充框内暗淡，在选择和搜索突出显示下不暗淡，并且列表描述像其他辅助文本一样变暗
  • 修复了在新克劳德代码进程的第一个响应完成之前调用时，mod 的 $.model.fork 返回 nothing-to-fork 的问题，如 claude -p 运行和云会话中那样
  • 全屏模式：修复了 /compact 和自动压缩，在重建可见记录时短暂冻结 UI
  • 自托管运行器：修复了当托管设置限制 MCP 服务器时从 Slack 启动的会话无法找到或附加存储库的问题；使用 deniedMcpServers 关闭这些工具
  • 自托管运行器：修复了当不相关的设置或会话失败引用 git 的 Missing-ref 措辞时，会话被报告为具有已删除的源分支且不会重试的问题
  • 自托管运行器：修复了承诺重试失败或 declined 会话释放即将结束的会话的日志；重复失败现在显示计数
  • Windows：修复了停止的后台 PowerShell 命令在其输出文件中缺少结束 [killed] 行的问题
  • 改进了切换到具有较小上下文窗口的模型：对于新模型来说太长的对话现在首先由先前的模型进行总结
  • 改进了长时间运行的子代理工作时的渲染性能：其进度轨迹现在增量更新，而不是在每次渲染时完全重新处理
  • 改进的工件：克劳德编写的页面现在在粘性标题上方绘制带区，因此滚动文本不再显示在移动应用程序中
  • 改进的 mods：在 VS Code 以及桌面和移动应用程序中，问题对话框上方绘制的树现在可以容纳 Markdown 和最多 48 行；终端保留 12 行普通行
  • 更改了 mod 挂钩的 .catch 处理程序，使其仅在挂钩抛出或超时时运行；在钩子自己的调用下引发的事件现在会跳过该钩子，而不询问其 .catch
  • 更改了 mod 的 $.env.set，以便在设置或取消设置变量后使用 {} 进行解析，或者在未进行写入时使用 { deny } 说明原因
  • [VSCode] 在 Claude 的响应中添加了 LaTeX 数学渲染，包括 $$ 和多行 \[ … \] 块以及内联 $…$ 和 \(…\) 数学
  • [VSCode] 在 VS Code 和 JetBrains 面板中的 Pro 和 Max 计划的使用限制横幅中添加了“获取更多使用”链接
  • [VSCode] 修复了每次重新加载时重新打开面板时崩溃或冻结的对话
  • [VSCode] 修复了聊天面板在长时间思考过程中变慢的问题：它不再在每次更新时重新解析整个思考文本
  • [VSCode] 修复了某些语言服务器显示“[object Object]”而不是规则代码（例如 MD013）的诊断
  • [VSCode] 修复了正在加载的本机听写音频模块，以检查麦克风权限，其中不提供听写（非 claude.ai 登录、远程窗口）
