claude-code v2.1.328

发生了什么变化

  • 在 Amazon Bedrock、Google Cloud 代理平台、Microsoft Foundry 和 Claude 应用程序网关上为 Claude Opus 4.6 和 Sonnet 4.6 添加了自动模式；无权限模式的交互式会话在其中启动
  • 为 mcp_tool 挂钩添加了 "onFailure": "block"，对于命令和 HTTP 挂钩：调用失败的挂钩会阻止操作
  • 添加了当来自跳过权限提示的会话的消息可能被云会话保留和删除时的警告
  • 当 OpenTelemetry 导出器没有端点并且其数据可能会丢失时，在 /status 和 claude doctor 中添加了通知
  • 添加了 CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME，它允许主机停止 claude -p --resume 和 --continue 运行钩子延迟的工具调用
  • 添加了对嵌入 Claude Code 的应用程序的支持，以打开策略插件的 allowManagedModsOnly 选项；管理员的托管设置仍然获胜
  • 当策略的 maxEffortLevel 不是有效的工作级别时，向 Claude 应用程序网关添加了启动警告
  • 自托管运行器：添加了 --repository-folder 来命名会话用于 --capacity 1 存储库的文件夹，代替其在基本文件夹下的路径，该文件夹不能是符号链接
  • 自托管运行器：添加了主机设置时的启动警告。json 设置会话忽略的默认权限模式
  • 自托管运行器：将 --hook-label 添加到 claude self-hosted-runner orchestrator，以将选定的会话标签传递给 spawn-runner 挂钩
  • 自托管运行器：将 --metadata key=value 添加到 claude --environment，以标记 spawn-runner 挂钩的会话
  • 自托管运行器：将 claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds 添加到协调器的 /metrics 中，因此可以从新会话的等待中得知重新打开的会话的等待时间
  • 自托管运行器：添加了一个协调器指标 claude_code_self_hosted_orchestrator_sessions_given_up_total，该指标根据 Anthropic 放弃启动会话运行器的频率进行计数
  • 修复了 zsh 中的 Bash 命令在以 = 开头的单词处停止并出现“未找到”错误的问题，例如 echo ==== 或 [ a == b ]； =cmd 不再扩展为命令的路径
  • 修复了自动压缩，重用会话的早期系统提示符，而不是像 /compact 那样重建它
  • 修复了某些很长或格式错误的输入上的 Markdown 渲染冻结问题
  • 修复了罕见的屏幕冻结问题
  • 修复了当您直接输入 Esc 时，在出现权限提示或问题时经常会丢失 Esc 的问题；在发送 Alt 作为 Esc 和一个键的终端中，未使用的 Alt 或 Option 键现在 declines 在那里
