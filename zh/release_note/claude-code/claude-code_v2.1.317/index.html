claude-code v2.1.317

修订 发布时间2026年11月3日 来源anthropics/claude-code 英文原文

claude-code v2.1.317

发生了什么变化

  • 当新的云计划任务获取您没有要求的连接器时，向 /schedule 添加了警告，以及如何删除它们
  • 添加了一项检查，在 Web 或 shell 工具调用将您的帐户电子邮件地址发送到网络之前进行询问
  • 为代理 SDK 挂钩回调添加了 onFailure: "block"，因此失败的回调会阻止操作而不是让它运行
  • 当您的组织的远程管理设置尚未为会话加载时，在 Claude Desktop 的“代码”选项卡中添加了一条通知，一旦加载则添加了另一个通知
  • 添加了当自动模式的检查对子代理的工具调用没有答案时的通知，该工具调用过去不会在主视图中留下任何内容
  • 将 anthropic.plan、anthropic.seat_type、anthropic.provider 和 anthropic.custom_base_url 添加到 OTel 指标、事件和范围
  • 向 Claude 应用程序网关管理员 API、GET /v1/organizations/analytics/cost 添加了成本报告，用于读取某个日期范围内每个开发人员、每天或每个 IdP 组的过去总支出
  • 在设置了 admin: 的 Claude 应用程序网关上添加了每个开发人员 IdP 组的每日记录，并为 admin.identity_retention_days 保留，成本报告按其分组
  • 添加了 CLAUDE_CODE_DISABLE_NESTED_SESSION_ID：在自托管运行器上将其设置为 1，以使 claude -p 在会话内运行，使用该会话的 ID 和转录本，如早期版本中一样
  • 修复了项目和本地 MCP 服务器在某些 Claude 桌面会话第一次启动后断开连接的问题
  • 修复了当 LLM 网关设置为基本 URL 对其服务器端安全检查应答 403 或 422 时，自动模式每次都会失败的问题（带有 apiKeyHelper 的 403 未更改）
  • 修复了 claude auth status 在保存缓慢令牌刷新之前退出的问题，这可能会让您在下次运行时退出
  • 修复了应用程序提前启动然后在项目中打开的会话忽略项目的 effortLevel 设置，例如桌面应用程序的“代码”选项卡中的新会话
  • 修复了当链接的会话早于首页时，claude --from-pr 在具有多个会话的项目中报告“未找到对话”的问题
  • 修复了 claude.ai 和移动应用程序上两个同时权限提示中的第二个不显示文件路径或命令的问题
  • 修复了远程控制和 SDK 主机在 mod 的工具调用中提供“不再询问”的问题
  • 修复了当标题生成时收到新消息或停止到达时，会话标题在云和 SDK 会话中丢失的问题
  • 修复了当克劳德在其请求中留下一个字段时，有时不会安排自定进度的 /loop 唤醒
  • 修复了当 Artifact 工具上传、写入数据库或通过输出文件夹保存文件时云会话中的自动模式停止等待批准的问题
  • 修复了从 claude.ai 同步的技能在无法写入磁盘时丢失或每十分钟重新下载一次的问题
  • 修复了 /schedule 在创建或更新云计划任务后保留其下一次运行时间并链接出其结果的问题
  • 修复了屏幕阅读器在屏幕阅读器模式的每次更改时说出正在运行的子代理的运行时间和令牌计数的问题

  • 修复了当磁盘已满或配额丢失其记录或 ~/.claude.json 写入时 claude -p 退出 0；它现在打印一个错误，并在文本和 json 输出中退出 1。完整的 NFS 导出可能会丢失
