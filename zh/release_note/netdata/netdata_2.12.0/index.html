发布摘要

v2.11.0 带来了网络拓扑，并使日志成为仅次于指标的一流信号。 v2.12.0 增加 OpenTelemetry 跟踪、通过 Redfish 进行带外硬件监控以及使 SNMP 拓扑可调试的诊断层， 同时还进行了大量收集器、查询和稳定性修复。

第三个可观测信号到达。 Netdata 已摄取 OpenTelemetry 指标和日志。此版本添加了 跟踪：OTLP 跟踪记录由代理根据其自己的保留策略接收、规范化和存储，并具有 专门构建的列式存储——跟踪感知索引、布隆过滤器和汇总——以及一个 otel-traces 查询函数 搜索痕迹，将它们聚合在一个窗口上并驱动概览热图。您可以在新的 Traces 选项卡中探索它们 仪表板的功能，现已作为 抢先体验 功能提供。

**硬件监控进入带外。**新的 Redfish 收集器与 BMC 通信 - iDRAC、iLO 和任何 DMTF Redfish 实现 — 而不是操作系统，因此只要 BMC 保持通电且可访问 当主机本身不健康、重新启动或 断电。它附带传感器和硬件 库存功能、独立的每个传感器阈值运行状况以及按需 BMC 日志查看器。在它旁边， SMBIOS 内存 将固件的每插槽内存库存与可接受的基准进行比较，并在出现异常情况时发出警报 记录的 DIMM 丢失或恢复时变小 — 内存损失仅用总 RAM 数字无法固定到插槽上。

v2.11.0 的网络工作变得可操作。 SNMP 拓扑引擎获得了整个诊断层：每个 walk 记录它的时间、它的配置文件决策和它的失败；证据以有限形式保留并公布 独立于拓扑收集是否成功，打包到可移植存档中，并折叠到代理的 支持包。然后可以从该存档中密封地重播拓扑图并离线检查，这将 “SNMP 拓扑未看到此交换机”来自站点访问，您可以发送给我们一个文件。适用于 PAN OS 的 LLDP-V2、Meraki L2、 IpAddressTable 支持和一组可重用的拓扑角色配置文件首先拓宽了引擎可以看到的内容。

在 Netdata Cloud 中，Netdata AI 学习您的基础设施。 通过 基础设施知识，您的团队可以记录下来 只有它知道的事情——哪些服务很重要、预期是什么、正常情况是什么样的——而 Netdata AI 会记住事实 你在谈话中讲述它，然后在每次谈话、调查和报告之前阅读两者。现在的人工智能对话 在关闭的选项卡中存活下来，并且当它们变长时不再失败，并且正在退役的节点可以退役，因此它们 停止发送通知。

很多发布都是整合。 Ceph 收集器被重建作为 Prometheus 的补充 收集器并迁移到 v2 收集器框架，具有警报覆盖率和 Tentacle 支持。 go.d的秘密处理 被系统性地剥夺了特权：文件和命令秘密提供程序现在无需提升特权即可运行，并且通过 nd-run 和自动发现作业中的秘密引用不再解析，除非发现管道已关闭 明确 trusted。动态配置现在独立于作业是否报告已接受的 go.d 更改， 发现管道或秘密存储已启动，因此 clients 应检查配置状态以获取结果。查询引擎中包含六个独立的正确性修复程序，并且长期运行 dbengine、SQLite、 字典、ACLK 和 ML 修复消除了崩溃和泄漏——其中许多已经在 2.11.1 补丁中发送给用户 在这里发布和合并。
