发布摘要

Netdata v2.9.0 带来强大的数据库可观察性和扩展的 OpenTelemetry 支持。

特色 亮点 详情
交互式查询分析 支持 14+ 个数据库 • 识别慢查询
• 调试瓶颈
• 监控操作
• 无需手动数据库连接
重建 SQL Server 收集器 用 Go 重写 • 综合指标
• 查询存储集成
• 基于UI 的配置
OpenTelemetry 日志摄取 通过 otel 插件记录 • 存储在与systemd 兼容的日志文件中
• 可配置的保留策略
稳定性改进 生产可靠性 • 引擎盖下的修复可实现更稳健的操作

发布亮点

新的顶部选项卡功能：14+ 数据库和 SNMP

我们为数据库收集器添加了交互式查询分析功能，让您可以直接从 Netdata 识别慢速查询、长时间运行的操作和性能瓶颈 仪表板 — 无需连接到数据库并手动运行诊断查询。

你可以做什么：

  • 识别资源占用：按总执行时间、CPU 时间或 I/O 排序
  • 发现频繁查询：查找可能受益于缓存的高调用次数查询
  • 实时调试：查看当前正在运行的查询以及哪个 client 启动了它们
  • 不需要额外的工具：所有分析都发生在 Netdata 仪表板的“顶部”选项卡中

[!重要] 某些功能需要特定于数据库的配置（例如，启用 Query Store、pg_stat_statements 或 profiling）。

请参阅每个收集器的文档以了解先决条件。

Microsoft SQL Server 收集器 (Go)

我们用 Go 从头开始重建了 Microsoft SQL Server 收集器，取代了旧的 C 实现。这带来了全面的 SQL Server 监控和实时查询分析功能。

你得到什么：

特色 详情
完整的公制覆盖 连接、批量请求、缓冲区管理器、内存、等待统计、锁、每个数据库事务、I/O 延迟、文件大小和 SQL 代理作业状态
热门查询功能 直接在仪表板中实时查看资源最密集的查询 - 查看执行时间、CPU、I/O、内存授予和并行度指标
用户界面配置 通过 Netdata 仪表板创建和管理监控作业 - 无需手动编辑配置文件
复制监控 跟踪事务/合并发布的复制状态、延迟和警告
灵活的身份验证 SQL 身份验证、Windows 集成身份验证、命名实例和远程服务器

热门查询：识别性能瓶颈

新的 热门查询 函数从 SQL Server 的查询存储中提取数据以显示：

  • 消耗最多总执行时间或CPU的查询
  • I/O 模式（逻辑读取、物理读取、写入）
  • 内存授予和 tempdb 使用
  • 跨执行的并行性 (DOP)

[!重要] 需要在受监控的数据库 (SQL Server 2016+) 上启用查询存储。

查询文本可能包含敏感数据——确保正确的仪表板访问控制。

OpenTelemetry 日志摄取

我们正在扩大对 OpenTelemetry 的支持！在 v2.7.0 中添加指标支持 之后，otel 插件现在通过相同的 OTLP gRPC 端点摄取 OpenTelemetry 日志。

新消息

  • 日志摄取：将日志从 OpenTelemetry 收集器或仪表化应用程序直接发送到 Netdata。
  • 自定义存储：日志使用 Rust 实现存储在 systemd\ 兼容的日志文件中（不需要 libsystemd 依赖项）。
  • 统一界面：在日志选项卡中查看 OpenTelemetry 日志以及系统日志，具有完整的搜索和过滤功能。

配置和保留

使用可配置的保留策略 控制日志存储：

  • 按磁盘使用情况、文件计数或寿命设置限制
  • 定义自定义存储位置
  • 调整文件大小和时间跨度设置

可用性

可在 Linux 代理（测试版）上使用，并且即将推出对其他平台的支持。

[!注意]
此功能处于测试阶段。我们欢迎您的反馈！

下一个次要版本中的重要更改

MS SQL Server 收集器：C 版本删除

旧版基于 C 的 MS SQL Server 收集器（windows.plugin 的一部分）将在下一个次要版本中删除。基于 Go 的收集器 (go.d/mssql) 现在是默认且推荐的选项。

Go 版本具有显着的优势：

  • 更多功能 — 包括用于实时查询分析的新热门查询功能。
  • 多作业支持 — 从单个代理监控多个 SQL Server 实例。
  • 远程连接 — 通过网络连接到 SQL Server 实例，而不仅仅是本地主机。
  • UI 配置 — 直接从 Netdata 仪表板创建和管理监控作业。
  • 更容易维护 — 受益于 go.d 框架的共享基础架构和更快的开发周期。

如果您当前正在使用 C 收集器，请参阅 Go 收集器 安装文档 以获取配置说明。
