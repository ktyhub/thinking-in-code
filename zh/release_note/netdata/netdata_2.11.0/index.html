发布摘要

Netdata 一直非常擅长一件特定的事情：每秒告诉您，无需配置， 机器内部发生了什么。 v2.11.0 是不再是边界的版本。

这里发生了两件事，它们一起改变了 Netdata 是什么。

首先，Netdata 了解网络。 新的 网络监视器 仪表板提供设备库存、指标、拓扑、 流、陷阱和警报集于一处。在它后面，网络流从您的路由器接收 NetFlow、IPFIX 和 sFlow， 交换机和防火墙，并将原始记录转化为谁在与谁通话的多面视图。 网络拓扑行走 您的设备通过 SNMP 并绘制第 2 层和第 3 层映射 - LLDP 邻居、转发数据库、OSPF 和 BGP 邻接 — 而 应用程序依赖关系映射 对您的软件执行相同的操作，读取您的 Linux 主机的 内核来映射每个进程、容器和 Kubernetes 工作负载所对话的内容，无需进行任何检测。 SNMP 陷阱 Listener 使 Netdata 成为陷阱接收器，可将来自 800 多个供应商配置文件的陷阱解码为 图表和可读消息而不是原始 OID。为满足所有这些需求，SNMP 设备覆盖范围从 229 增加到 273 配置文件。通常的 Netdata 规则仍然适用：配置文件已编写，收集和存储由您自己完成 除了告诉 Netdata 设备在哪里之外，几乎没有什么需要配置的。网络监视器、网络 流和网络拓扑作为 技术预览版 提供 - 足够完整，可以立即运行，并向每个 Netdata 用户开放 虽然处于预览阶段，但进展仍然很快。

第二，同样重要的是，日志成为平台的一流支柱。此版本添加了 OpenTelemetry 日志 — OTLP 日志记录是从已提供 systemd 日志的同一个 日志 选项卡中获取、存储和查询的 和 Windows 事件，具有 journald、filelog 和 syslog 接收器、可配置保留、对数到公制转换 并解析非结构化行。更深层次的变化是架构上的：现在是相同的多面、高基数日志引擎 支持systemd 日志、Windows 事件、OpenTelemetry 日志、SNMP 陷阱和网络流。五种截然不同 信号类型、一个查询界面，全部存储在您自己的基础设施上。

围绕这两个，此版本通过新的 AWS CloudWatch 收集器 完成了主要云集 - 与 v2.10.0 中添加的 Azure Monitor 收集器 — 并围绕真正的重新标记引擎重建 Prometheus 收集器 与应用程序配置文件。所有这一切的背后是我们有史以来最大的稳定性和内存安全努力 在单个版本中：跨数据库引擎、流、ACLK、健康、ML 和 libnetdata 的 87 个增量部分。

Netdata强大的端点监控能力得到了增强。 macOS 监控已原生重建：统一 通过 Apple 的 OSLog 框架、GPU、SMC 和 IOHID 传感器、风扇、电源和电池、热压力和 NVMe 进行记录 health，之前如果不手动下降到 log show 和 powermetrics 就无法到达。添加了 Windows Active Directory 和 SMB 在重新设计的 perflib 层上进行监控，FreeBSD 添加了 系统调用监控，以及 Linux 添加了审计子系统监控。一个代理、四个端点操作系统，每个操作系统均为每秒分辨率。

在 Netdata Cloud 中，AI 故障排除变得更加准确和相关：您现在可以连接自己的 MCP 服务器 到您的 Netdata 空间（GitHub、PagerDuty 和 Atlassian，以及您自己的自定义服务器），Netdata AI 将在使用它们时使用它们 调查。除此之外，新的 车队管理 视图将节点渲染为状态六边形，节点和警报视图 重建以在50,000个节点的房间中保持流畅，沉默规则获得了时区锚定的调度，以及移动应用程序 以免费计划向所有人开放。
