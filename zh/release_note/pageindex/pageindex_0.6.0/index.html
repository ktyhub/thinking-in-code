PageIndex v0.6.0

小版本 发布时间2026年11月14日 来源VectifyAI/PageIndex 英文原文

PageIndex v0.6.0

  • 比矢量 RAG 便宜：对于索引和查询。
  • 更快：树是根据布局统计数据创建的。
  • 统一 SDK：无矢量 RAG。 本地或云，用于索引和聊天。
  • 在您的克劳德订阅上运行。

索引、聊天、代理集成，一台 client。 本地模式不需要服务器、矢量数据库、PageIndex API 密钥。

client = PageIndexClient()
client.submit_document("report.pdf")
client.chat("What does the report conclude?")

亮点

  • Flash引擎：本地默认（mode="standard"保留经典的LLM管道）。当 trustworthy 时，会消耗嵌入式书签，并且默认情况下会启用树优化 — optimize="merge" 用于确定性的无 LLM 传递，"full"（默认）添加 LLM 扩展，它会同时运行一波节点，而不是一次一个往返。
  • 一个完整的表面，本地和云：PageIndexLocalClient(storage_path=...) 与云相同的 client — 提交、树、页面内容、聊天和代理工具都存在于两种模式中，因此代码在它们之间移动不变。
  • 云文档，您自己的模型：api_key 决定您的文档所在的位置；配置好的聊天模型决定谁回答——并将两者结合起来。 PageIndexClient(api_key="pi-...", chat_model="openai/gpt-5.2") 在实时云工具集上运行相同的进程内文档 QA 引擎。页面内容通过您的流程流向您的提供商（根据您的凭证）； doc_id 以提示级别为目标； enable_citations 保留托管聊天。
  • 代理集成：云 MCP 工具合约，正在处理 - client.agent_tools()（普通函数）、as_openai_tools()、as_anthropic_tools()、as_claude_mcp()，以及用于系统提示的一键调用 openai_agent_config() / anthropic_runner_config() / claude_agent_config() 捆绑包和 agent_instructions()。云clients通过MCP桥获取实时服务器工具集（默认为只读端点）；本地 clients 获取具有相同架构和信封的进程内子集 — 代理提示端口不变。
  • 聊天界面：chat() — 在任何后端提问、回答； chat(stream=True) 显示运行情况，将思考和工具调用融入文本中，或者通过 .events 作为键入事件； chat(protocol="responses" | "messages") 使用该协议自己的形状本机驱动 OpenAI 响应或人类消息 API，而 chat_completions() 保留 OpenAI 兼容的信封 - 所有这些都具有 doc_id 定位、流式传输、诚实使用会计和跨轮提示缓存连续性。脚本逐字附加：协议通道的输出不变地返回到下一个请求。
  • 模型和连接旋钮：index_model / chat_model、index_backend / chat_backend（以及每次调用的 backend）逐字传递到每个通道 - LiteLLM 路由提供商、无钥匙 OpenAI 兼容服务器、Azure/Bedrock/Vertex 包括在内。
  • index= / chat= 插槽：平面参数的分组拼写 - 字符串简写或映射（index={"model": ..., "storage_path": ...}、chat={"model": ..., "backend": ...}）。 "cloud" / "local" 命名一侧，可选的 mode= 对其进行交叉检查，PageIndexLocalClient / PageIndexCloudClient 占用相同的插槽。 PageIndexCloudClient() 读取为 PAGEINDEX_API_KEY；无论环境如何，裸露的 PageIndexClient() 都会保持在本地。
  • 键入的配置形状：IndexConfig / CloudIndexConfig / LocalIndexConfig / ChatConfig，附带 py.typed，以便您的类型检查器看到它们。
  • 没有什么会悄然失败：未知的键、混合的方面、空值和模式/内容冲突拒绝使用消息中的法律词汇进行构建；无效凭据或丢失模型会使索引运行失败，而不是存储带有空白摘要的文档；每个云错误都带有其 HTTP 状态。
  • 依赖关系：Python >= 3.10；基础安装中的 openai-agents（聊天引擎）； SDK 的 [anthropic] 和 [claude] 附加件。 Pillow >= 9.0 现在是 highlight_region 的必需依赖项。

也在0.6.0

  • PageIndex Cloud 上的集合。 create_collection()、list_collections() 和 delete_collection() 管理它们，submit_document(..., collection_id=...) 将文档存储在一个文档中，list_documents(collection_id=...) 列出它。没有声明元数据字段的集合从其文档的元数据中学习它们。
  • 自有模型聊天保留在一个集合中，并带有盒装引用。 chat(collection_id=...) 将云发现保留在该集合内，而 citations="cite_with_boxes" 使每个引用在其页面上带有一个框。调用从未见过其图片的页面上的框被丢弃。
  • get_citations 解析库路径，例如 Research/report.pdf，这是 MCP 服务器现在引用文档的方式。

同样在 0.5.3 中：

  • 更便宜、更快的摘要。 节点摘要现在以最少的思考运行每个模型："none"，其他 "minimal"，其他 "low"，以及 Claude 自己的关闭开关。在一份 22 页的收益报告中，gpt-5-nano 的摘要成本仅为十分之一，并且在 9 秒内完成，而不是 64 秒，而 o3 的成本还不到一半。
  • 索引停止为它从未读取的缓存写入付费。 在对输入上方的提示缓存写入进行计费的模型（例如 GPT-5.6 和更新版本）上，索引不写入缓存：gpt-6-luna 为 $0.164 而不是 $0.184 索引 1,000 个页面。 index_backend={"prompt_cache_options": {"mode": "implicit"}} 保留模型自己的缓存，这使得在 30 分钟内再次索引的文档可以读取第一次运行的缓存。
  • 突破性：您选择的推理工作会按选择到达。 模型不使用的 summary_reasoning_effort 或 index_backend reasoning_effort 会在看不见的情况下被丢弃（gpt-5-nano 考虑到 "none" 以其完全默认的思维运行，比未设置时慢 7 倍）。现在它会在任何模型调用之前引发并说明要传递的内容。

同样在 0.5.2 中：

  • PageIndex Cloud 上的 Flash。 client.submit_document("report.pdf", mode="flash") 构建
