agent-lightning v0.3.0

Agent-lightning v0.3.0 是一个主要版本，引入了多项新功能和错误修复。该版本是 Agent-lightning 核心团队和社区之间的协作努力。感谢所有使此版本成为可能的贡献者。

亮点

  • Tinker 集成：支持 Tinker 作为强化学习的替代后端 (#226 #245 #264 #269 #327)。请参阅示例代码、博客 1 和博客 2。
  • Azure OpenAI 集成：支持 Azure OpenAI 作为 LLM 推理和监督微调的后端 (#256 #327)。 示例代码。
  • 添加基于 MongoDB 的 Lightning Store 作为 Lightning Store 的替代后端 (#323)。 文档。
  • Contrib 包：为社区项目添加 contrib 包。 Search-R1 被集成为一个 contrib 配方。更多即将到来。 （＃239＃396＃410＃412＃417）。
  • RESTful API：针对 Lightning Store 稳定并记录 RESTful API (#241 #275)。 文档。
  • OTel 语义约定 专为代理优化领域而设计 (#340)。 文档。
  • [预览] 代理闪电仪表板现已推出 (#288 #289 #291 #296 #371 #375)。它是用于检查和调试 Agent-lightning 实验的官方 Web 应用程序。请参阅此处 的详细信息。
  • [预览] 多模态示例，采用 VERL 和 ChartQA 数据集上的 LangGraph 代理 (#379)。 示例代码。
  • [预览] 将 Claude Code 集成为 LitAgent 并支持 SWE-Bench 上的培训 (#332 #346 #348)。 示例代码。
  • [预览] Weave 跟踪器 作为 AgentOps 跟踪器的替代品 (#277 #411 #420 #423)。 文档。
  • [预览] 轨迹级别聚合可通过 VERL 进行更高效的训练。请参阅博客 和文档。

商店基准

在此版本中，Lightning Store 核心经过重新设计，显着提高了效率和可扩展性 (#315 #318 #328 #342 #344 #356 #380 #388 #418 #421)。下面的基准测试结果证明了其影响：对于大量并发运行程序，v0.3.0 的吞吐量比 v0.2.2 提高了 15 倍。

吞吐量（#rollout/秒） v0.2.2 v0.3.0（内存中） v0.3.0 (蒙戈)
最小（批量，#runner=32，#turns=6） 8.73 9.06 8.71
中（批量，#runners=100，#turns=10） 12.03 23.26 32.79
中高（批次，#runners=300，#turns=6） 10.61 24.42 40.24
大（批量，#runners=1000，#turns=3） 3.36 14.60 50.05
长队列（队列，#runners=256，#turns=4） 7.42 30.86 57.01
大量跟踪（队列，#runners=512，#turns=20） 5.93 13.28 29.41
备注：
  1. 基准测试在单个 Standard_D32as_v4 Azure VM 上运行（使用 Standard_D64ads_v5 进行大型和繁重的跟踪测试），通过 GitHub 操作执行。
  2. 评估两种算法模式：批处理模式提交一组转出并等待所有转出完成后再开始下一组，而队列模式则维护一定数量的正在进行的转出，一旦容量释放就提交新的转出。配置详细信息可在此处 获取。
  3. 匝数与每次推出生成的跨度数成正比。
