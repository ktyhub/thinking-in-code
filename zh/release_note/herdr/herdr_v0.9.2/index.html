herdr v0.9.2

herdr v0.9.2

重大变化

  • Herdr 特定的窗格图形 API 消失了。 pane.graphics.info、set、clear 和 stream 现在返回 unknown_method。应用程序通过将标准 Kitty 图形写入终端来显示图像，而 Herdr 会以本机方式呈现这些图形。 (#4561)

添加

  • 代理可以报告自己的恢复命令。然后，Herdr 在服务器重新启动后重新打开其确切会话，无需内置集成。一旦其窗格返回到空闲 shell，自我报告的代理也会被清除。新的为您的代理人添加 Herdr 支持 指南涵盖了代理人作者的状态、简历和发布。 (#4687)
  • 使用多个前缀键：prefix = ["ctrl+space", "ctrl+s"]。每个条目都进入相同的前缀模式，prefix+? 将它们全部列出。 （＃4653，感谢@JJLiebig）
  • 转至将每个座席和终端显示为其自己的行，按工作区及其状态和路径分组。在工作区之间向左和向右跳转。 (#4384)
  • 绑定 keys.clear_pane 以清除聚焦窗格的屏幕并回滚，同时保留当前提示行。默认情况下它是未绑定的，并且仅保留 Vim 等全屏应用程序。 (#4383)
  • herdr machine status 在没有提示的情况下检查已保存的机器。 herdr machine reconnect 在您的终端中完成 SSH 身份验证，包括 MFA。打开 clients 每 30 秒重新检查一次故障机器，因此修复连接后无需重新启动。 (#3763)
  • 交互式 machine add 查找已在主机上运行的 Herdr 会话，并让您选择一个。 --label可选；该机器以其 SSH 主机命名。 （#4204、#4678，感谢@JJLiebig 和@dhh）
  • terminal session control 接受 terminal.mouse 事件，因此桥接 clients 可以在启用鼠标报告的应用程序中使用 click 按钮。 (#4685)
  • 恢复的代理一次启动一个，默认间隔 100 毫秒，而不是一次全部启动。用 [session] startup_per_agent_delay_ms 更改间距。 （＃4102，感谢@JJLiebig）

已更改

  • 图像渲染速度更快、更可靠。本地Ghostty通过临时文件而不是终端输出接收图像数据。弹出窗口和通知会裁剪自身周围的图像，而不是隐藏它们。滚动到视图之外的图像仍会保持加载状态，因此向后滚动不再重新发送它们。 （＃4561，＃4652，＃4686）
  • SSH 连接请求压缩。在慢速链接上，远程窗格在滚动一小部分时间后就会赶上。 (#4340)
  • 在已保存的计算机上滚动输出仅发送更改的行，从而减少构建日志和流代理的带宽。较旧的 clients 和服务器继续使用以前的格式。 (#4711)
  • 新窗格设置 TERM_PROGRAM=herdr 和 TERM_PROGRAM_VERSION。它们不再从启动服务器的终端继承终端会话 ID，例如 iTerm2 或 Claude Code 会话标记。 (#4104)
  • 安装后，Windows 窗格默认使用 PowerShell 7 (pwsh)，然后回退到 Windows PowerShell。显式的 default_shell 仍然获胜。 （#4297，感谢@JJLiebig）
  • 关闭工作区的最后一个选项卡现在需要确认。 （＃4379，＃4409，感谢@minatoaquaMK2）
  • 事件订阅提供完整的爆发。落后太多的读者现在会收到 events_lost 错误，而不是默默地跳过事件。 （＃4178，＃4225，感谢@minatoaquaMK2）
  • 在 Unix 上，将 SIGWINCH 发送到 Herdr client 会重新读取主机终端的颜色，因此在没有明/暗通知的情况下更改颜色的主题切换器可以刷新窗格。 （＃4349，谢谢@dhh）

已修复

  • 保存的布局在主机关闭和恢复失败后仍然存在。在登录的 Linux 上，Herdr 在系统关闭之前进行保存。每个平台在 session-snapshots/ 中最多保留 48 个布局快照以供手动恢复。 (#4320)
  • Clicking 窗格不再发送中断正在工作的代理的杂散 Escape。 (#3480)
  • 代理的第一个任务现在算作已完成，即使它是在有提示的情况下开始的。启动、恢复的会话和 Pi 的 /new 不再发出错误的完成通知。挂钩报告的状态在实时切换后仍然存在。 （＃3338，＃3990，＃3916）
  • 服务器使用更少的 CPU 并填充许多窗格。导航器、窗格分割和命名目标在大型会话中保持快速，并且突发的外部事件不再阻碍渲染。 （#4506、#4546、#4426、#4669、#4670、#4671、#4672，感谢@JJLiebig 和@minatoaquaMK2）
  • 使用同步输出的应用程序在您键入时不再显示撕裂的帧。在 Windows 上状态重绘或在空闲 Codex 周围跳转时，光标不再闪烁。 （＃2968，＃4303，感谢@JJLiebig）
  • API 套接字在发生瞬时错误后继续接受连接，因此当服务器保持运行时，CLI 命令和实时切换不再失败。 (#4601)
  • 工作树查找过程中缓慢的 Git 操作不再冻结打字。 （#4492，感谢@JJLiebig）
  • worktree open 不再接管存储库自己的工作区，因此删除工作树不再将其关闭。 (#4293)
  • 重新连接后，转发的 SSH 代理继续在远程窗格中工作。重复 --machine 命令打开的 SSH 连接要少得多。 （＃1931，＃4252）
  • OpenCode V1 窗格在子代理运行时保持工作状态或被阻止。尊重 tui.json 中的现有注册，而不是重新生成 tui.jsonc。 （＃1362，＃4240）
  • Codex 在活动输出期间不再报告空闲，它的提及弹出窗口被识别，并且重新映射的中断键不再中断检测。 （#4507、#4196，感谢@JJLiebig 和@unmanbearpig）
  • Kiro 批准提示被报告为已阻止。 Grok 空闲窗格与自定义或禁用的 OSC 标题一起解决。 （#4203、#4372、#4333，感谢@vinayshah1998）
  • Droid 的回滚清除功能受到尊重，因此其欢迎标题和旧记录不再重复。 (#4432，感谢@factory-ain3sh)
  • 当输出继续且按住移动键时，复制模式保持活动状态。 （＃3812，＃4281，谢谢@marcomayer）
  • Ctrl+Shift+字母将 Shift 保留在未启用增强键盘输入的窗格中，因此 Ctrl+Shift+C 不再以 Ctrl+C 形式出现。 （＃4581，＃4597，感谢@factory-ain3sh）
  • 通过 SSH 进行焦点切换后，跨读取分割的鼠标报告不再泄漏到 shell 中。 (#4630)
  • Windows：多行粘贴到 Claude Code 中不再在第一个换行处提交，并且 Shift+Enter 被保留。鼠标捕获在焦点更改和调整大小后仍然存在，Ctrl+Win 不再打开带有 ctrl+space 前缀的前缀模式，并且远程 clipboard 图像粘贴再次起作用。 （#4251、#4284、#4470、#4314，感谢@JJLiebig）
  • Windows：检测到 npm 安装的 OMP 和通过强化运行时启动的代理。针对 Windows 主机的 machine add 不再因“未准备好保存的计算机”而失败。 （#4313、#4579、#4309，感谢@JJLiebig）
  • theme = "terminal" 可以看到导航模式工作区突出显示。会话导航器搜索独立匹配单词。侧边栏显示由 cycling 或快捷方式选择的代理。 （#4300、#4408、#4273、#4535、#4355，感谢@minatoaquaMK2）
  • 没有终端的 session attach 会解释问题，而不是让新会话继续运行。 (#4393)
  • 套接字错误响应保留原始请求 ID，包括订阅设置错误。 (#4344)
  • plugin install 在存储库之前接受选项。 (#4446)
  • Windows 窗格从一开始就选取主机终端的浅色或深色，因此应用程序不再默认为浅色终端内的深色模式。 （＃1530，＃4369）
  • 在herdr update之后，Herdr列出了哪些正在运行的服务器仍然是旧版本，并提供了重新启动每台服务器的确切命令，并提醒您更新保存的SSH机器。
