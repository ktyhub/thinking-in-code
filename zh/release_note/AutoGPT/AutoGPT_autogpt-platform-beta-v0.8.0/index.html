AutoGPT autogpt-platform-beta-v0.8.0

⚠️ 升级自托管安装 — 重大更改

ENCRYPTION_KEY、UNSUBSCRIBE_SECRET_KEY 和 BETTER_AUTH_SECRET 不再附带 .env.default 中的值；它们是在每次安装时生成的，并且后端不会在用于包含的值 .env.default 上启动。全新安装不需要 make init-env（或安装程序）之外的任何东西。设置自己值的安装不需要任何东西。如果您的安装在默认值上运行（backend/.env 中没有 ENCRYPTION_KEY 行，或者启动以 ENCRYPTION_KEY is set to a value that was published… 停止），请从 autogpt_platform/ 执行此操作 - 它将您连接的集成移动到新密钥而不是丢失它们：

1.docker compose down 2. 保留用于加密数据的密钥： export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) （如果您设置了自己的密钥并要替换它，请导出该值并在结帐之外保留 backend/.env 的副本）。 3. 在backend/.env中，确保=中的ENCRYPTION_KEY=和UNSUBSCRIBE_SECRET_KEY=存在，且=之后没有任何内容，而frontend/.env中的BETTER_AUTH_SECRET=；然后 make init-env （填充每个空秘密，从不覆盖值）。 4. 重新加密存储的内容 - 首先试运行，然后应用： docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply 5. 清除旧BETTER_AUTH_SECRET下存储的令牌签名密钥，然后启动： docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

完整说明：升级：每次安装都会生成机密。

此外，在此版本中：删除了旧版 HS256 JWT 验证路径，因此不再读取 backend/.env 中的 JWT_VERIFY_KEY (#14519)；未使用的 TrialNotificationDelivery 表将通过迁移删除。
