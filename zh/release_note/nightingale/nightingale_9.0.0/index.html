nightingale v9.0.0

大版本 发布时间2026年7月25日 来源ccfos/nightingale 英文原文

nightingale v9.0.0

发生了什么变化

  • 壮举：警报规则支持试射 - 针对实际查询的系列按需触发规则并获取逐步报告 （查询检查→阈值→事件→通知管道→通知），在条件出现之前验证整个警报链 遇见 (#3274)
  • 壮举：日志查询支持 VictoriaLogs (#3239)
  • 壮举：警报静音规则支持 仅通知静音 — 事件仍会生成并记录（并在事件中标记为静音 列表和详细信息），同时通知被抑制 (#3250)
  • 壮举：主页支持 one-click Categraf 安装 - 收集器包随服务器一起提供，并且可以立即运行安装 脚本是根据平台生成的 (#3272)
  • 壮举：内置的 /mcp 端点现在提供细粒度的工具集（警报、目标、数据源、静音、通知规则、警报 订阅、事件管道、用户、指标、日志、仪表板、角色） - 默认情况下只读，具有写入工具和工具集 将两者列入白名单都需要明确的选择加入 (#3245)
  • 壮举：AI 技能支持授权范围 - 公共或团队私有，编辑仅限于授权团队（#3247、#3268）
  • 壮举：警报规则/静音/订阅/通知规则表单重新设计 - 部分卡、带有实时内容的右侧导航 条件摘要、自动命名、快速持续时间预设和基于场景的空状态
  • 壮举：消息模板和模板中心支持 i18n，因此单个模板以收件人的语言呈现（#3235， 第3238章，第3261章）
  • 功能：警报历史记录事件可以保留可配置的天数（CleanAlertHisEventDay，每晚批量清理）， 使用新的复合索引和游标分页 (#3264)
  • 壮举：事件管道中的 AI 摘要节点可以重用集中式 LLM 配置，而不是携带自己的配置 (#3242)
  • 壮举：控制台上的完整 i18n 覆盖
  • 功能：列表支持内联行操作、可排序的创建者和时间列以及分页快速跳线
  • 修复：聚合警报事件操作不再因 HTTP 414 而失败 — 事件 ID 现在作为 JSON 数组在 POST 正文中发送
  • 修复：批量删除历史事件不再删除仍具有活动警报的事件 (#3263)
  • 修复：引用外部配置列，以便 DDL 适用于 MySQL 9.7 (#3276)
  • 修复：在 HTML 渲染之前清理用户输入和详细 URL（XSS 强化）

新贡献者

  • 壮举：引入 Nightingale AI — 内置 AI 助手、技能市场、LLM 配置管理，以及特定于页面的提示建议
  • 壮举：重新设计的导航菜单、全局布局和表格 UI
  • 壮举：重构通知通道管理
  • 壮举：带有详细执行视图的新事件管道执行跟踪页面

升级注意事项⚠️

新的AI助手依赖于Redis Streams，因此需要Redis 5.0或更高版本（建议集群用户使用Redis 7.0+以启用分片Pub/Sub）。
