nightingale v9.2.0

小版本 发布时间2026年10月11日 来源ccfos/nightingale 英文原文

nightingale v9.2.0

发生了什么变化

  • 壮举：原生 Jira、Discord、JSM Alert、Slack 和 Mattermost 通知通道 (#3408)，并且通知通道配置可以引用用户变量 (#3349)
  • 壮举：仪表板面板可以混合数据源 - 每个查询目标都带有自己的数据源，由具有 KQL 支持的新 v2 多数据源批量查询 API 支持 (#3292)
  • 壮举：匿名、限时的仪表板共享链接，以及带有 URL 开关的只读全屏视图以隐藏标题和变量 (#3345)
  • 壮举：Grafana 仪表板导入重写 - 转换报告显示在保存之前迁移的内容以及不支持的内容
  • 功能：仪表板查询变量支持标签/值选项和 Doris SQL 时间宏；嵌入式 Grafana (iframe) 仪表板同步时间范围和刷新间隔
  • 壮举：可以禁用和重新启用用户帐户，而不会丢失其角色、团队和权限（#3395）
  • 壮举：OAuth2 登录可以将默认团队分配给新用户 (#3406)，并且 /login?sso=xxx 直接重定向到给定的 SSO 提供商
  • 壮举：内置内容支持任意语言； ja / ru / pt-BR / es / id / ko / fr 添加到后端，并且 pt-BR / es / id / ko / fr 添加到控制台 (#3352)
  • 功能：自定义警报严重性名称、活动警报事件的全屏实时视图以及按哈希过滤历史警报事件 (#3392)
  • 壮举：聚合的 Nightingale AI 页面，具有可重命名和可共享的对话（#3325）； AI助手可以通过ibex调度脚本任务（#3378）
  • feat：集成中心入门指南（收集模板→仪表板→警报规则）；新的 x509_cert 集成、rabbitmq_exporter 收集模板和 SNMP 设备运行状况警报规则（#3394、#3348）
  • 壮举：403 响应就地呈现，而不是重定向到 /403，因此 URL 可以生存并可以返回
  • 壮举：公共演示站点的无密码演示登录条目，默认关闭（#3426） - 请参阅注释
  • perf：AI 聊天增量渲染 markdown，A2A 任务存储写入放大减少约 30 倍 (#3413)
  • 安全性：通过 6to4 / NAT64 / 站点本地 IPv6 地址关闭 SSRF 防护绕过 (#3364)，编辑数据源 URL 中嵌入的凭据 (#3424)，验证 TDengine 数据库/表名称 (#3423)，收紧仪表板共享令牌范围 (#3368)，以及升级易受攻击的依赖项 (#3419、#3422)
  • 修复：配置键初始化现在跨实例收敛，修复多实例部署中的 401/登录循环 (#3385)
  • 修复：不可调度的规则 cron 模式不再在每次重新启动时使 n9e / n9e-edge / n9e-alert 崩溃，并且 cron 模式在保存时进行验证 (#3407)
  • 修复：尚未激活的警报静音现在已同步到引擎缓存中（#3386），并且空静音标签已标准化（#3425）
  • 修复：在分派警报事件之前填充恢复时间 (#3382)
  • 修复：回调通道可以在没有消息模板的情况下进行通知（#3350）
  • 修复：禁用的数据源仍然可以查询，并且不被写入目标
  • 修复：超大的 VictoriaLogs 行不再使整个查询失败 (#3344)
  • 修复：PostgreSQL 数据源在初始化 client 时使用配置的数据库 (#3367)

v9 亮点

  • 隆重推出 Nightingale AI：内置 AI 助手、技能市场、LLM 配置管理和页面感知提示建议
  • 开箱即用的内置时间序列数据库，因此小规模设置不再需要单独的 Prometheus / VictoriaMetrics
  • 重新设计的导航菜单、全局布局和表格 UI
  • 完全重建警报规则/静音规则/订阅规则/通知规则表单
  • 重新设计了通知渠道管理
  • 新的事件管道执行跟踪页面，详细显示处理过程
  • 新一代日志浏览器，统一支持Elasticsearch、Loki和VictoriaLogs

升级步骤

替换二进制文件和 integrations 目录，然后重新启动。要获取添加语言的新指标描述，还需替换 etc/metrics.yaml。

架构更改（如果您的数据库帐户可以创建表，请跳过此操作）

Nightingale 在启动时为您应用这些。如果 Nightingale 连接的数据库帐户无法更改表，请手动运行它们 — DDL 位于 https://github.com/ccfos/nightingale/blob/main/docker/migratesql/migrate.sql

ALTER TABLE `source_token` ADD COLUMN `note` varchar(255) NOT NULL DEFAULT '' COMMENT 'note';
ALTER TABLE `source_token` ADD KEY `idx_source_token_token` (`token`);
ALTER TABLE `users` ADD COLUMN `disabled` int NOT NULL DEFAULT 0 COMMENT '0:enabled 1:disabled';

PostgreSQL：

ALTER TABLE source_token ADD COLUMN note varchar(255) NOT NULL DEFAULT '';
CREATE INDEX idx_source_token_token ON source_token (token);
ALTER TABLE users ADD COLUMN disabled int NOT NULL DEFAULT 0;

注释

  • 新的AI助手依赖于Redis Streams，因此需要Redis 5.0或更高版本（建议集群用户使用Redis 7.0+，以启用分片Pub/Sub）
  • 仅替换二进制文件不会启用内置 TSDB：[EmbeddedTSDB] 部分仅存在于新的 etc/config.toml 中，因此继承旧的配置文件会使该功能关闭 - 自己复制该部分。它仅由中心进程处理（n9e-edge / n9e-alert / n9e-pushgw 忽略它并记录警告），并且数据位于该中心实例的本地磁盘上，因此它仅适合单实例部署；对于多个中心副本，请改用外部 TSDB
  • telegraf用户需要将ignore_host=false追加到metrics写入地址中，否则运行telegraf的主机将不再注册到主机列表中
  • 如果您运行n9e-edge或n9e-pushgw，请将它们与n9e一起升级
