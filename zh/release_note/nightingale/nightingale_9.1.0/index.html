nightingale v9.1.0

小版本 发布时间2026年8月6日 来源ccfos/nightingale 英文原文

nightingale v9.1.0

发生了什么变化

  • 壮举：内置时间序列数据库——Categraf 推送的指标存储在本地，因此不需要外部 Prometheus / VictoriaMetrics 即可开始；名为 embedded-tsdb 的 Prometheus 数据源在首次启动时自动注册。尊重现有设置：如果已经存在任何启用的 Prometheus 数据源，则不会自动创建数据源 - 示例仍然在本地编写，您可以添加指向内置 TSDB 的 Prometheus 数据源来查询它们 (#3283)
  • 壮举：在一个 click 中从 Grafana 导入数据源，并提供每个数据源结果摘要 (#3295)
  • 壮举：数据源页面改造 - 保存数据源后，Nightingale 使用哨兵指标对其进行探测，以报告哪些内置仪表板/警报规则模板已经有数据，并引导您进行第一个查询 (#3301)
  • feat：每周期警报评估记录 - 每个规则评估都会将其查询内容和判断方式保存到警报引擎的本地磁盘，可以从警报规则页面上的抽屉中进行检查（#3305）
  • 功能：在保存之前可以测试通知通道配置并预览消息模板（#3302）
  • 壮举：Categraf 收集配置向导 — 新的 /agents/categraf/collect.sh 端点为应用程序脚本提供服务，并在控制台中提供插件模板和指标验证 (#3286)
  • 壮举：事件管道支持尝试运行中的模拟事件、执行记录的时间范围过滤、批量启用/禁用以及新更改 API（#3281、#3285）
  • 壮举：集成中的内置警报规则模板通过 en_US i18n 得到了极大的扩展和修改（#3282）
  • 壮举：MySQL 数据源可以将额外的参数附加到 DSN (#3299)
  • 壮举：Doris 数据源支持 doris.internal_addr 边缘进程达到 FE MySQL (#3298)
  • feat：警报规则列表支持按触发类型过滤
  • 功能：主动警报事件列表显示触发时的值，添加三态标签，并记住过滤器面板、自动刷新间隔和访问时间范围
  • 壮举：日志浏览器为 Loki 和 VictoriaLogs 添加查询文档按钮，让您可以直接从日志查看器附加字段过滤器，并支持 BCE BLS 钻取
  • 壮举：仪表板 TableNG 面板支持行详细信息抽屉
  • 壮举：主机页面登录 — one-click 主机监控包、测试警报操作和后续步骤卡
  • 壮举：数据源代理和日志查询访问现在与用户和有效负载一起写入审核日志
  • 壮举：边缘重试事件持久性到中心，并收紧每个请求的超时
  • 壮举：新的 API 检查是否有任何通知已成功发送（#3300）
  • perf：加快通知记录查询和日常清理速度，由启动时在线创建的两个新 notification_record 索引支持（#3311）
  • 修复：在将事件推送到队列之前对其进行深复制，因此恢复事件不再覆盖尚未使用的触发事件
  • 修复：空白的钉钉应用配置不再破坏群组机器人通知 (#3309)
  • 修复：在 ai_* 模型上固定显式列类型以阻止 AutoMigrate 架构漂移，该漂移导致这些表的迁移失败
  • 修复：支持 max_completion_tokens 对于较新的 OpenAI 模型 (#3306)
  • 修复：在警报规则 event_relabel_config 中保护无效标签名称（#3287，#3296）
  • 修复：接受 YAML 内容以收集内置有效负载（#3307）
  • 修复：允许强制保存未通过健康检查的数据源（#3304）
  • 修复：在每个引擎集群过滤之前根据完整数据源列表探测全局默认数据源，因此不再清除另一个集群拥有的默认数据源
  • 修复：正确的警报规则单位
  • 修复：修复内置技能YAML frontmatter并在聊天中公开代码搜索工具
  • 修复：为异步表迁移提供自己的 gorm 会话，因此一个失败的语句不再毒害其余语句

V9新功能

  • 壮举：引入 Nightingale AI — 内置 AI 助手、技能市场、LLM 配置管理，以及特定于页面的提示建议
  • 壮举：内置时间序列数据库 - 开箱即用，小规模设置无需外部 Prometheus / VictoriaMetrics
  • 壮举：重新设计的导航菜单、全局布局和表格 UI
  • 壮举：重构通知通道管理
  • 壮举：带有详细执行视图的新事件管道执行跟踪页面

升级注意事项⚠️

  • 新的AI助手依赖于Redis Streams，因此需要Redis 5.0或更高版本（建议集群用户使用Redis 7.0+以启用分片Pub/Sub）。
  • 警报评估记录默认启用。警报引擎将它们写入位于 ./evallog 的本地磁盘，保留 8 天，上限为 20GB。使用 [Alert.EvalLog] 部分调整或关闭此功能 - 请参阅新的 etc/config.toml。
  • 内置 TSDB 无法通过就地二进制升级启用：[EmbeddedTSDB] 仅存在于新的 etc/config.toml 中，因此从早期版本继承的配置文件将其保留。复制该部分以启用它。它仅由中心进程处理（n9e-edge / n9e-alert / n9e-pushgw 忽略它），并将数据存储在该中心实例的本地磁盘上，因此它适合单实例部署 - 对于多个中心副本，请改用外部 TSDB。
