    • 风险：🟢低。测试循环初始化和所需检查所有权得到纠正，同时发布授权保持不变。
    • 证据：操作系统模拟在事件循环初始化后安装，并在拆卸前恢复。授权审核事件会重新运行当前 PR 触发的准备情况检查，而不是替换或取消它。源验证、本地人工批准、独立构建和 OIDC 发布保持不变。
    • 文件：tests/sandbox/test_unix_local_user_file_io.py、.github/scripts/release_automation.py、.github/workflows/release-readiness-refresh.yml、.github/workflows/release-readiness.yml。
    • 操作：提交精确的人工批准，允许刷新准备，通过正常保护进行合并，并验证发布者和上传的出处。

  3. 外部提供商覆盖现在需要明确的维护者意图

    • 风险：🟢 低，具有现有的选择加入路径。默认集成和自动示例运行不再隐式选择受影响的外部提供商案例。
  • 证据：集成引导程序会重置继承的启用标志，默认删除列出的外部提供商凭据，并拒绝外部模型覆盖而无需选择加入。外部案例默认不选；自动示例使用扩展的跳过列表。手动示例选择仍然可用。
    • 文件：.github/scripts/run_integration_tests.py、integration_tests/conftest.py、Makefile、examples/run_examples.py、integration_tests/README.md。
    • 行动：使用 make integration-tests-providers-external，当打算直接提供提供商覆盖时添加 -- --all。不要将默认覆盖范围解释为外部提供商验证。
