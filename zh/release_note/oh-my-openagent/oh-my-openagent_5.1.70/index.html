oh-my-openagent v5.1.70

普通 omo login 在 OmO 帐户关闭时从终端登录计算机。 没有 OmO 桌面应用程序的计算机（通过 SSH 的服务器、新的 Linux 盒子）运行 omo login，获取设备代码以在另一台设备上批准，并将凭据存储在操作系统凭据存储中； Attach-before-mint 拒绝 (#13096) 在向服务提出任何请求之前会应答已经拥有其设备的计算机。成功行将登录帐户命名为（Signed in to OmO as <email>.），omo whoami 也将其命名；读取失败的帐户仍然说明如何查看它。 omo logout 和 omo whoami 在关闭时运行，因此没有消息指出拒绝的命令。 login --help 描述了路线（该命令对 omo --help 保持隐藏），每个其他封闭的 login 表单都会拒绝一条命名路线的消息，封闭的提示命名两条路线，编译后的条目将裸 login、logout 和 whoami 分类为一次性启动，并使用命令使用的相同共享解析（包括 login --）。损坏物品消息也命名了终端路线，而不是仅限桌面应用程序的死胡同。测试通过 npm 启动器（针对从该源构建到启动器树的临时副本中的服务身份验证包）、编译的条目和工具包 CLI 运行流程，具有隔离的 HOME 和运行时目录、无继承的会话总线、注入的存储以及每个零薄荷情况下的拒绝文本断言。 (#13281) (#13328)

计算机使用一致性预检测试在 Windows 上通过。 缺少驱动程序消息现在在每个操作系统上打印其存储库相对路径，并带有正斜杠，因此运行在每个主机上读取相同的内容，并且 stdio-probe 测试将其替代引擎构建为主机的真正可执行文件，而不是 POSIX shell 脚本。仅 QA 工具；没有运行时行为改变。 （#13295，#13221 的一部分）

计算机使用获得其 QA 的声明结果一致性目录。 script/qa/computer/conformance/ 添加了一个类型化目录，其中每个操作系统上的每个操作、工具包和模式单元都声明它通过精确的引擎代码交付或拒绝，一份失败的报告，其中包含丢失、重复、跳过或错误编码的单元或干扰人员会话的单元，结束损坏主机作为 ENVIRONMENT_ERROR 运行的环境预检，以及 12 个无模型参考任务。仅 QA 工具；没有运行时行为改变。 （#13241，#13221 的一部分）

**桌面会话的可操作性等待测试在繁忙的主机上不再失败。**电池的等待现在在可注入时钟上运行：会话中主机的单调时间，如以前一样，以及测试中假后端自己的时钟。因此，the_battery_waits_for_an_element_that_appears_enabled_after_500_ms 在假时间中检查 500 毫秒等待，而不是主机负载可能打破的挂钟界限。运行时行为不会改变。 （#13180，修复#13178） **模糊切换在具有许多结束会话的帐户上不再失败，并且永远不会转到与确切名称不同的会话。**模糊切换首先在每个会话中尝试线程的确切 ID、别名或名称，包括其他设备上的结束会话，因此与一个会话完全匹配的名称始终会到达该会话。否则，本地、直播和结束的比赛会一起进行比较，无论比赛在哪里，明显最好的比赛都会获胜；两个同样好的比赛要求你选择。无法匹配的已结束会话不再计入 500 名候选模糊上限，因此大量历史记录不再阻止唯一匹配。 （#13141，跟随#13066）

创建别名声明后要求登录的线程仍由别名命名。 当帐户令牌在 thread_create 检查别名和声明别名之间过期时，它已创建的线程现在由其设备上的别名命名，并且调用会以 alias_scope: "local" 应答 ok，而不是出现错误。当帐户因索赔而消失时，thread_rename 也会执行相同的操作。现在，每个路径上用作本地名称的别名都会被修剪。 (#13179，跟随#13112) (#13141)

omo login 不再为已有设备的计算机注册第二个设备。 在执行任何代码、浏览器选项卡或新密钥之前，它会检查存储的登录信息以及计算机 OmO 设备服务持有的设备（包括停放的设备）。保持、不确定、锁定或不可读状态会拒绝新设备并保留现有设备，而不是在桌面旁边添加“omo CLI on ”行。当服务公布计算机身份时，两个登录流都会发送散列硬件 ID（SHA256("omo-machine-v1" + id)；原始 ID 永远不会离开计算机），并且 machine_exists 拒绝会结束登录，而不会删除或接管任何设备。 （[#13096]（https://github.com/code-yeongyu/oh-my-openagent/pull/13096））（[#13141]（https://github.com/code-yeongyu/oh-my-openagent/pull/13141））

当没有帐户登录时，线程别名不再阻止线程创建。 当别名注册表无法获取帐户令牌时，带有 alias 的 thread_create 现在会创建线程。桌面启动始终处于该状态。除非给出 name，否则别名将成为线程的本地名称，并且结果表明别名仅是本地的 (alias_scope: "local")。具有别名的 thread_rename 的作用相同。所有其他别名错误均保持不变。 （#13112，修复#13104）

修复：文件再次通过中继工作读取捆绑的 Bunshin SDK（readText、readBytes 和 read 不再拒绝“截断”
