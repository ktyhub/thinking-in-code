oh-my-openagent v5.1.66

修订 发布时间2026年11月10日 来源code-yeongyu/oh-my-openagent 英文原文

oh-my-openagent v5.1.66

omo thread 表示，当损坏的安装仅将其保留在该设备上时。 无法加载的线程 client sidecar 不再使 omo thread read <alias> 默默地回答 not_found：stderr 命名 sidecar、错误和重新安装步骤。 CLI 登录自身的警告（已退役的 trust 引脚、失败的设备服务忘记）现在也到达了 stderr。 (#12936)

默认情况下，发送给繁忙线程的消息现在会到达其正在运行的轮次。 无传递模式的 thread_send 和 thread_handoff（以及没有 --mode 的 omo thread send）引导接收者的正在运行的轮次，并在空闲时启动轮次，在此设备上和其他设备上都是如此；仅当调用者请求 follow_up 或转弯无法进行转向时（等待问题、压缩、报告无转弯纪元的引擎），消息才会在正在运行的转弯后面排队。在那一刻结束的转向转向回落到目标所在的车道，而不是失败。 （#12921，#12879 的一部分）

OmO 在 senpi 2026.11.9-2 上运行。 eval 单元等待的工具在完成时不再将正在运行的单元留为空白：其流线会一直保留，直到单元自己的输出或其结果替换它们（senpi#6257）。 (#12920)

omo remote send 现在与会话的 thread_send 沿同一条路传输到另一台设备，并且来自另一台设备的每个回复都由一个映射进行解释。 终端上的人员发送到另一台设备上的会话时会经过中继传输（相同的离线检查、针对运行转弯的相同转向预检、该设备的网关存储中的收据），同时保留自己的提示记录；当另一个设备上的命令被拒绝时（omo remote、附加 TUI、线程工具和 SDK），用户读取的内容来自单个模块，因此未应答、丢失授权或不确定结果的设备在任何地方都会读取相同的内容。 （#12911，#12879 的一部分，修复 #12885）

OmO 在 senpi 2026.11.9 上运行。 它带来了 senpi 的 admit_external_message（从另一台设备的会话中继的消息被视为普通传递），并使中继传递的读取方式与同一机器的传递完全相同，设备仅保存在其元数据中。单通道中继传输 (#12879) 两者都需要。 （[#12904]（https://github.com/code-yeongyu/oh-my-openagent/pull/12904））

** omo.dev 标题上的安装按钮不再压在或滑过药丸的右边缘。** 浮动导航栏为其最后一个控件提供与左侧徽标相同的插图，并且在 1000 像素以下，部分链接移至菜单中，因此任何语言都不会将任何内容推到药丸之外。 (#12893)

代理使用 thread_create 创建或分叉的线程现在也在此设备上以创建者自己的批准模式启动，而不是主机的默认模式。 在另一台设备上创建的会话已经这样做了（#6189）；现在，两条腿运行一个主体：根据线程所在的设备检查名称（该设备已经列出的名称是 name_conflict ），打开另一个设备上的活动线程会回答该线程，而无需再次打开它，并且创建的线程的事实（名称、工作目录、时间戳）来自引擎在两个设备上的回复。 （#12891，#12879 的一部分） 停止、关闭、重命名、重新建模、更改推理级别或读取线程的工作方式相同，无论该线程在本机上还是在您帐户的另一台设备上运行。 thread_set_reasoning 现在也到达另一台设备上的线程，并且另一个 client 仍然在两个设备上保持相同答案的没有文件的会话。 （#12890，#12879 的一部分）

**代理发送到另一台设备上的会话的消息现在到达那里，与一个设备上的会话之间的消息完全相同。**接收会话获取具有相同发送者行和权限通知的传递条目（而不是用户消息），同一设备传递携带，在相同密钥下进行重复数据删除，并且在接收时以相同方式唤醒；回复只是另一次发回。所提供的文本中没有任何内容命名它所经过的设备，并且来自终端的 omo remote send 没有变化。从 omo thread send 到另一台设备上的会话的发送被作为数据拒绝（引擎仅允许来自其自己的计算机的命令行传送）并指向 omo remote send。 （#12889，#12879 的一部分，修复 #12882，修复 #12877，修复 #12346，修复 #12865，修复#12857)

现在，向另一个会话发送消息会通过一个传递管道，无论该会话是在本机上还是在另一台设备上。 设备差异在于一个端口后面的传输模块；用户在此版本中看不到任何变化。 （#12887，#12879 的一部分
