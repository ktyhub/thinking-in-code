oh-my-openagent v5.1.69

OmO 在 senpi 2026.11.10-2 上运行。 client 可以通过 read_project_file / write_project_file (senpi#6307) 通过 RPC 读取和编辑工作区的指令文件，构建的会话可以通过 claim_session (senpi#6350) 停放和分发，Fable 5.2 提示预设获得代码库所有权语句(senpi#6360)，generate_image 与 bash (senpi#6272) 一样仅用于评估，评估单元通过 tool.<name>(...) 和 agent()/output() 助手到达每个仅评估工具 (senpi#6276)，并且 EQ 金色带有新的提示符 (senpi#6355)。 (#13054)

**应答来自另一个代理的消息的代理可以在引擎自行启动的轮次中继续应答该消息，而不会出现任何提示。**已消耗的交付授予的回复限额（通过 ID 或指定名称回复该发件人，仅从交付中批准）现在持续到交付开始的工作：正在消耗的轮次和引擎自行启动的每个后续轮次 - 一个待办事项提醒、一个目标延续、一个监视器唤醒。仅仅解决问题并不能结束它；当新消息在该答案之后开始工作时，它结束：一个人的消息或任何传递，新组将保留其自己的发件人（加入正在运行的工作的传递会添加其发件人）。覆盖回合中的回复会在下一跳处继续传递的链，因此链限制仍然会关闭它。 （#13042，#12996 的一部分）（#13044）

omo remote send 现在与其他发送一样通过相同的传送管道，并且 --steer 读取一次会话。 一个人发送给另一台设备上的会话的消息会进入 createDeliveryPipeline，其中中继地址簿对 <device>/<session> 地址的引用，因此 CLI 不再构建自己的传输调用；中继传输读取一次正在运行的转弯并对其进行转向，而 CLI 过去会先读取第二次。不运行任何内容的会话的 --steer 仍然不发送任何内容。未使用的第二个提示实现 (promptRemote) 及其参数检查已被删除。每个设备承认的发送者类型不变。 (#13038)

发送到此设备上等待问题的会话的消息现在会这样说，就像发送到另一台设备一样。 发送仍在排队，其 delivery 现在携带 waiting_on: { kind: "approval", device }。 device 是此安装的帐户设备，当安装没有设备标识时不存在。 (#13035)

现在，一个会话发送的每条消息都会为其发送的设备命名，在此设备上以及跨设备都如此，并且来自另一设备的消息将被视为接收运行下一次发送的原因，就像本地会话一样。 当无法读取设备 ID（无设备服务，或者它不应答）时，该消息仍然会发送并记录其未命名设备的原因。 （#13034，#13004 的一部分）

**发送或移交给另一台设备上的会话的消息现在会报告其 delivery_id、effective_mode 和 endpoint，就像在该设备中发送的消息一样。**答案来自帐户的会话列表，并删除了这些字段。它现在传递中继传输自身的传递事实。 endpoint 是 null，因为发送方不知道该设备上的任何端点。 (#13033) 现在，对另一台设备上的代理的回复可以通过消息头中的 id 或其名称到达它，而同一帐户上不会有任何提示。 现在，一个解析器会在该设备的线程和帐户的其他设备之间找到一个线程：一个精确的持久 ID，然后是帐户别名，然后是对每个条目进行判断的名称梯（共享名称的两个设备是命名两个设备的 ambigously_target，而不是静默选择）。 thread_send、thread_handoff、控制工具、thread_create（开式或叉式）和omo thread CLI都使用它。对运行接收的交付的发件人的回复仅从该交付中获得批准 - 通过发件人的持久 ID 或其声明的名称 - 并且必须解析为该发件人，否则将被拒绝为 reply_target_mismatch 而不发送。另一个设备上的线程显示的 id 是其持久 id；当设备发布中继列表时，中继列表就会携带它。 omo remote 动词仍按您输入的 id 作为设备的会话密钥进行调度，因此请传递设备列出的 id，直到该路径移至共享解析器。 (#13000)

发送到另一台设备上的代理现在会报告与此设备上的相同的事实。 thread_send 和 thread_handoff 也会为另一台设备上的目标应答 delivery_id 和 effective_mode，因此调用者读取传递的 ID 和它所采用的通道，无论哪个设备持有线程； message_seq和endpoint保留了该设备上的网关行的事实，而device则命名了另一行。对于同一设备和跨设备传输，回复限额（通过该代理的 id 或指定名称回答其交付的代理的运行，没有提示）被证明是相同的，并且一个奇偶校验表现在针对两条腿运行每个发送断言，因此读取传输的规则会使构建失败，而不是到达用户。 （#13006，在 #13000 之上）

子任务不再针对拒绝其进程范围编辑注册表的 senpi 引擎启动；启动失败，显示 SenpiEngineRestartRequiredError，表示要重新启动 omo。 引擎拒绝在它所指定的注册表插槽旁边加载
