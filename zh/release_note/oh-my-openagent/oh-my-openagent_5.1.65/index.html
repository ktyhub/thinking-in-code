oh-my-openagent v5.1.65

代理向另一台设备上的会话发送的消息现在会显示是谁发送的。 它过去以纯文本形式到达那里，与该会话自己的用户无法区分。现在，它与一个设备上的会话之间的消息（发送会话、其工作区和项目以及它来自的设备）携带相同的发送者行和权限通知，并且其中的前导 / 不再运行命令或在接收端扩展提示模板。来自终端的 omo remote send 不变。 （#12858，#12852 的一部分）

内存保留不再对每个记录评估其完成记录防护两次。 完成扫描现在读取防护一次并保留或删除该单个答案上的记录，并且保留测试检查它们自己的先决条件而不是断言它们。保留保留或删除的内容没有变化。 （#12783，#12532 的后续）

独立的 omo 二进制文件的 omo doctor 再次报告内存运行时大小，就像 npm install 一样。 每个内存身份的运行时大小与其上限以及跨身份的总数由两个发行版打印，因此二进制/npm doctor 奇偶校验保持不变（#12785）。 (#12783)

当两个 omo 启动同时启动时，旧的二进制运行时会被安全地修剪。 一个启动不再删除另一个启动仍在修剪的运行时，并且已删除的运行时不会报告为失败。 omo --version、--help 和 omo update 从不修剪。 （#12770，后续#12627）

**引擎无法容纳其指定模型链的子任务将不再启动。**之前，当子进程的引擎无法获取其链（较旧的引擎、拒绝的 set_retry_fallback 或未及时答复）或任务主机未通告 retry_fallback_profile 时，子进程仍会收到提示并运行在引擎自己的回退设置上，该设置可以到达其链外的模型。现在，在出现第一个提示并命名每个指定型号及其原因之前，启动会失败，并且这样的主机会因不兼容而被拒绝，并命名相同的型号。 （[#12759]（https://github.com/code-yeongyu/oh-my-openagent/issues/12759））（[#12761]（https://github.com/code-yeongyu/oh-my-openagent/pull/12761））

另一台设备上的已关闭会话上的命令现在报告与此设备上相同的错误。 它远程应答 session_not_found，本地应答 unknown_session；现在两者都回答 unknown_session。 （[#12755]（https://github.com/code-yeongyu/oh-my-openagent/issues/12755））（[#12756]（https://github.com/code-yeongyu/oh-my-openagent/pull/12756））

omo 将其设备密钥从内存传递给设备服务，无需读取凭证存储来进行中继。 全新登录（omo login、omo account adopt）会删除注销标记，然后将其内存中密钥和帐户传递给正在运行的设备服务。当服务报告没有采用的设备时，内存同步会话会重新采用它已持有的凭据。每个注销路径（注销、忘记、服务结束的会话）都会告诉服务忘记设备。启动引导程序不再读取存储的凭据。 device.adopt 仅将 account 承载到 0.1.3 或更高版本的设备服务，并且固定设备服务提升到 0.1.3（设计 D PR 4）。 (#12735) omo remote 可以在其他设备上打开、发送、切换模型、中断和关闭会话。 omo remote open <device> [--project P] [--model M] 在那里启动会话并打印 <device>/<session>； omo remote send <device>/<session> <text> 在流入时打印答案，并在回合结束时返回（--steer 引导正在运行的回合，--follow-up 在其后面排队，一旦会话获取消息，--no-wait 返回）； model、interrupt 和 close 言出必行。每个动词都是代理线程工具使用的相同远程操作，并且 --json 打印其键入的结果。现在，当另一台设备的引擎报告其正在运行的轮次时，该设备上的会话的转向就会到达该设备，而不是总是被拒绝。 （#12709，#12320 的一部分）

在另一台设备上创建或分叉线程不再等待单独的 session.locate 往返：创建在 open_session 回复上向中继请求新会话的 ID 并使用它。没有该答案的中继守护程序（较旧的主机或该设备上的较旧的服务）将像以前一样使用 session.locate 进行处理。 (#12686)

独立二进制文件上的 omo update 现在取代了已安装的 omo。 它用于打印 ~/.omo/binary-runtime/<version>/ 下副本的替换命令，下次启动时会将其放回原处，因此更新从未进行过。启动还会删除旧的运行时版本，保留前一个版本以进行回滚，并且任何版本仍在运行。 （#12627，修复#12626）

每个内存身份的运行时目录上限为 2 GiB，omo doctor 和 /doctor 显示其保存的容量。 保留后，12 小时内存维护阶段会逐出最旧的优先，直到身份适合 memory.runtime.max_bytes（默认 2 GiB，0 表示无限制，在 memory.agents.<id>.runtime 下每个代理可重写）。它首先删除折叠反射运行，然后删除完整的转录本
