oh-my-openagent v5.1.64

修订 发布时间2026年11月7日 来源code-yeongyu/oh-my-openagent 英文原文

oh-my-openagent v5.1.64

桌面内存同步现在在引擎启动后立即启动，无需等待会话。 由 omo host ensure 启动的引擎仅在会话打开时加载扩展，而桌面在引擎发送内存同步引导握手之前不会打开任何扩展，因此两者相互等待。现在，只要 RPC 引擎的启动声明了 memory-sync 通道，编译后的 omo 和 npm 启动器就会在引擎加载之前启动该声明；第一个会话重用它。失败的声明仍将内存同步报告为不可用，并且永远不会回退到 CLI 凭据。 (#12702) (#12704)

内部（仅限测试）：macOS trust 采集通过已可注入的捆绑包读取器读取 /etc/ssl/cert.pem，现在的测试证明格式错误的默认文件会生成结构化的 openssl-default-file-malformed 删除条目（文件、原因、块索引、缩小）。 (#12633)

内部（仅测试）：OpenSSL 默认文件导入器现在测试固定 BEGIN 行上的任何高字节（而不仅仅是 BOM）会删除整个文件。 (#12632)

内部（发布工具）：omo-native trust 突变工具仅当命名测试因断言而失败时才将突变体视为已杀死；仅抛出运行时错误或加载时崩溃的突变体现在报告为 crashed 并导致运行失败。 (#12631)

已修复

  • 当两个设备同时更改内存文件的同一行时，内存同步不再丢失编辑。此版本上的设备将两个编辑保留为整行，并且每个设备都会聚合。之前，编辑内容是逐字符合并到不匹配的文本中的（#12279）。
    • 在此版本的设备之间，编辑不会干扰无人编辑的线路。例外情况是一次非常大的重写：当一台设备在一次保存中添加和删除超过大约 2,000 行注释时，该保存会逐字符合并，就像此修复之前一样，因此对同一行的并发编辑仍然可以拼接。
    • 当注释的正文或新文本不以换行符结尾时，编辑仍会像以前一样逐字符合并，因此对最后一行的两个并发编辑仍然可以拼接。
    • 对于仍然运行旧版本的设备，其旧字符合并仍然可能会出现以下问题：
      • 相邻行可以融合。 旧设备会在该版本编辑的行之后重写该行。根据两个设备的内部 ID，这两个编辑可以融合成一行，后跟一个空行。实测：从head、one、two、tail开始，这个版本写的是ONE，老设备写的是TWO，结果可以是head、TWOONE、空行、tail。两款较旧的设备为 head、ONE、TWO、tail。
      • 剩余文本移动。 旧设备编辑此版本删除的行。其剩余文本连接相邻行。
      • **它自己的差异触及其他行。**旧设备的字符合并交叉到用户未编辑的行中。这种情况也会发生在两台旧设备之间。
    • 两台旧设备会保持旧角色合并，直到更新为止。 (#12597)
  • 内存同步：大内存集的推送阶段不再需要与整个集成比例的内存。每个推送步骤都用于重新读取和重写一个包含每个待处理项目数据的日志文件，每批多次。因此，推送几千个内存文件的设备峰值可达 2 GiB 或更多 (#12286)。现在，日志将待处理项目的小型索引及其数据保存在单独的文件中，并且推送仅读取正在发送的批次。在推送之前捕获该集仍保留每个捕获的文件的文本，直到捕获结束。由旧版本编写的日志在第一次读取时会被转换，包括旧版本在新索引旁边添加项目的日志。 (#12597)
  • 内存同步：接收大内存集的设备不再因加载每个文件而减慢速度。渲染步骤用于重新读取每个文件周期的每个渲染记录，因此第一次提取几千个内存文件需要数十分钟（#12285）。现在每个文件的成本相同，并且崩溃恢复行为不变。 (#12597)
  • 内存 git 不再从继承的 GIT_CONFIG_COUNT 对或 GIT_CONFIG_PARAMETERS 条目中获取 core.hooksPath、core.fsmonitor、include.path 或 includeIf.*.path，因此导出的对（例如 core.hooksPath=/dev/null）不能再默默地跳过内存存储库的钩子和镜像推送。所有其他注入的对（url.*.insteadOf、http.extraHeader、凭证、safe.directory，…）仍然适用，并重新编号；注入的列表 git 本身无法解析，会被整个删除。内存git也不再继承存储库重定向（GIT_DIR，GIT_WORK_TREE，GIT_COMMON_DIR，GIT_OBJECT_DIRECTORY，GIT_NAMESPACE，GIT_CONFIG，…），因此它不能再指向另一个存储库； GIT_INDEX_FILE、GIT_CONFIG_GLOBAL 和 GIT_CONFIG_NOSYSTEM 被保留。 （[#12360]（https://github.com/code-yeongyu/oh-my-openagent/pull/12360），修复[#12354]（https://github.com/code-yeongyu/oh-my-openagent/issues/12354））（[#12597]（https://github.com/code-yeongyu/oh-my-openagent/pull/12597））
  • 当一个内存文件的更改大于 8 MiB 批量限制时，内存同步不再停止设备的每次推送：该文件将被保留并在同步状态中以要执行的操作命名，所有其他内存都会保持同步，并且文件一旦适合就会自行同步。另一个设备对保存的文件所做的更改将被保留，并且一旦文件被保存到该设备的副本中
