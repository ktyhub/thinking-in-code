nanobot v0.2.0

🐈 nanobot v0.2.0 在这里 🎉 — 105 个 PR 合并，20 个新贡献者。特工学会了坚持目标。 标题是 /goal。使用 long_task 将线程标记为持续目标，并且活动目标每次都会固定在运行时上下文中 - 幸存于压缩，幸存于长工具链，幸存于模型自身的健忘 - 直到您调用 complete_goal。当目标处于活动状态时，挂钟超时会自动延长；流请求会回落到空闲超时而不是硬墙，因此仍在思考的模型不会在思考过程中被杀死。 第二个故事是WebUI 的成长。在作为纯源预览发布了几次之后，它现在在方向盘内 - pip install nanobot-ai，你就拥有了它。设置和 BYOK 进行了全面重新设计，斜线调色板已本地化，LAN 访问由令牌控制，推理流实时聊天，全新的图像生成工具将“画我 X”变成内联预览，而无需离开对话。 第三层是机房。代理循环得到了真正的重构 - AgentLoop.from_config() 用于干净的嵌入，_process_message 重写为功能状态机，存档摘要移至系统提示中以确保 KV 缓存稳定性，工具转换为自描述插件架构，ask_user 和 GlobTool 退役以支持更干净的替代品。五家新提供商（AWS Bedrock Converse、NVIDIA NIM、LongCat、Atomic Chat、MiMo）加入了该阵容，并以 fallback_models 作为安全网，因此单个脆弱端点无法拒绝。加上四个 [security] 修复 - SSRF、媒体路径限制、更软的工作空间边界 - 以及聊天本机配对，因此 DM 批准最终发生在聊天中，而不是在配置文件中。

亮点

  • /goal 和长时间运行的任务 — 具有为什么记忆的代理 — 新的 long_task 工具与 /goal 和 complete_goal 配合使用，将线程标记为持续目标。活动目标每回合都会镜像在运行时上下文中，因此即使在压缩后，代理也能保持锚定，WebUI 在聊天标题中显示目标，并且当目标处于活动状态时，LLM 墙超时会自动加宽，因此较长的推理过程不会在思考过程中被终止。核心代理商和子代理商均遵守较长的预算；流请求会回退到空闲超时而不是硬挂钟，因此仍在发出令牌的模型不会被过早切断。 （＃3788，＃3855）
  • 图像生成，端到端 — 新的图像生成工具加上 WebUI 图像模式，让您无需离开聊天即可从提示转到图片。生成的图像与圆形预览内嵌渲染；重播窗口和重复数据删除路径已收紧，因此图像不会在长时间会话中重复传送，并且合并过程现在在隐藏历史记录时会尊重重播窗口。 （＃3695，＃3687）
  • 车轮上的 WebUI + 一年的打磨 — pip install nanobot-ai 现在捆绑了 WebUI：启用 WebSocket 通道，运行 nanobot gateway，打开浏览器。不需要 cd webui && bun run build。经过几次以“预览”标签发布后，WebUI 现在是一个打包的界面。内部：重新设计的设置和 BYOK 流程（包括 BYOK Web 搜索）、本地化斜线调色板、在斜线命令和配置重新加载之间保持同步的模型预设徽章、实时渲染的流式推理、图像预览、由 tokenIssueSecret 控制的 LAN 访问、加载时默认为新聊天、设置返回时滚动保留、用于非安全上下文 LAN 使用的 crypto.randomUUID 填充程序，以及删除急切的 Markdown 预加载以减少首次绘制成本。 （#3653、#3661、#3703、#3709、#3656、#3658、#3733、#3759、#3782）
  • 五个新提供商和后备安全网 — 原生 AWS Bedrock Converse 成为一流提供商 (#3574)，后续措施将保留历史上的 Bedrock 工具配置 (#3758)。 NVIDIA NIM (#3707)、LongCat 通过 OpenAI 兼容路由 (#3114)、Atomic Chat 作为本地 OpenAI 兼容目标 (#3750) 和 MiMo 具有适当的思维控制接线 (#3734、#3851) 完善了该阵容。在更广泛的堆栈之上，fallback_models 允许您列出在主模型失败时接管的辅助模型 (#3756)，DeepSeek 推理历史记录将被回填而不是删除 (#3616，#3560)，Codex 提示缓存键已稳定 (#3793)，并且 Anthropic 在长请求错误时自动回落到流式传输 (#3579)。
  • 模型预设和运行时切换 — ModelPresetConfig 允许您在配置中命名模型 + 提供程序包，并在运行时通过 /model （或 WebUI 徽章）在它们之间进行交换。预设在斜杠命令、配置重新加载和设置更改之间同步，因此模型徽章始终与下一回合将出现的内容相匹配。 (#3714)
  • 核心重构 - 更清洁的代理循环，更小的表面 - AgentLoop.from_config() 集中循环组装，因此嵌入器不再触及私有内部（#3708）。 _process_message 被重写为具有显式转换而不是嵌套分支的功能状态机 (#3715)。存档的对话摘要移至系统提示中，以在压缩过程中保持 KV 缓存稳定（#3711）。工具成为一种自描述插件架构（#3729）。 ask_user 被删除，以支持结构化的 message 工具选择 (#3757)，并且 GlobTool 被淘汰，以支持 read_file glob 支持 (#3841)。经过 Vulture 和覆盖率验证的死代码被删除（#3755、#3719）。日志记录现在保留回溯并携带通道上下文（#3651、#3678）。 Ruff F 规则在 CI 中完全执行（#3672），并且代理测试套件得到扩展和重组（#3766）。新的 CLAUDE.md 和 .agent/ 指南为 AI 贡献者提供了稳定的入口（#3534、#3860）。
  • 配对、DM 批准和安全强化 — 聊天本机配对 (#3774) 让您可以从聊天内部批准 DM，而不是编辑配置。在安全方面：SSRF 在钉钉出站媒体中被阻止 (#3569)，飞书下载的媒体文件名被限制在安全路径中 (#3789)，本地媒体附件被限制在消息工具中 (#3842)，SSRF 保护恢复软化，这样短暂的失误不会毒害后续回合 (#3635)，工作空间边界违规会得到重试限制的软警告，而不是导致循环崩溃 (#3614)。 Telegram 默默地忽略未经授权的发件人，而不是泄漏错误响应 (#3629)。
  • 内存、梦想和会话持久性 — Cron jobs.json 通过损坏存储检测获得原子写入 (#3606)。 Dream 光标仅在已完成的批次上前进 (#3631)，并在恢复时正确恢复内存状态 (#3660)。重播窗口隐藏的历史记录现在已正确合并（#3687）。工作区和工具状态更改可以更可靠地端到端地重新启动。
  • 频道和平台修复 - 飞书组线程尊重回复链和主题隔离（#3547、#3704、#3747、#3775）、Matrix 跳过预启动事件并在不可恢复的身份验证上停止同步循环（#3575、#3578）、WhatsApp 语音消息干净下载（#3607）、Wecom 保留真实文件名（#3751）、Telegram 消除未经授权的行为发件人 (#3629)，微信在发送失败时引发，这样消息就不会默默地丢弃 (#3659)。在 Windows 上：shell 提取中的 UNC 路径支持 (#3764)。在 CLI 上：代理代码点在消息总线之前被清理（#3697），重试等待消息不再混淆交互输出（#3705，#3609），并且 nanobot provider logout 作为正确的命令落地（#3612）。
  • 您会感觉到的小东西 - 可配置的 bot_name / bot_icon (#3730)、可配置的 toolHintMaxLength (#3641)、在 OpenAI 兼容的 API (#3677) 上恢复真正的 SSE 流、在瞬时故障时重试 Whisper 转录 (#3646)、顺序 MCP 服务器连接以停止 CPU 旋转 (#3640)、连接前的 MCP HTTP 探测 (#3740)、速率限制下的勇敢搜索回退 (#3840)、运行时上下文中的 sender_id 用于用户感知响应 (#3549)、在用户内容后附加运行时上下文以实现缓存稳定性 (#3844)、origin_message_id 出站重复数据删除 (#3561) 和 Python SDK RunResult 最终暴露了 tools_used 和 messages (#3620)。
