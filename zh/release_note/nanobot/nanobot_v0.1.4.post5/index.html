nanobot v0.1.4.post5

🐈 纳米机器人 v0.1.4.post5 就在这里 — 57 个 PR 合并，29 个新贡献者，以及一个发布周期，它不是由奇观而是由更安静的东西决定：在最重要的地方进行仔细的改进。 这种发布让项目在日常使用中感觉更有价值。边缘变得更光滑，故障模式变得更柔和，平台变得更宽。在渠道、提供商、内存、MCP、CLI 和基础设施方面，纳米机器人不仅变得更加强大，而且更加可靠 — 更像是一种可以实际使用的工具。

亮点

  • 可靠性占据中心位置 — 此版本的很多内容都是为了让纳米机器人更加优雅地失败。代理循环不太可能崩溃，MCP 连接现在可以更好地处理取消，正确保留孤立的工具结果，并且异步 CLI/子代理输出表现得更干净。 （＃1999，＃1953，＃2075，＃1930，＃2039）
  • 内存变得更加实用 - 异步后台整合落地，整合输入更加忠实地传递，有效负载在持久化之前得到验证，并且 save_memory 的执行更加一致。这是迈向记忆的有意义的一步，感觉不那么神奇，而且更可靠。 （#1961、#1962、#1868、#1810、#1909）
  • 通道层不断成熟 - 通道插件架构已经到来，通道发现现在是自动的，内置通道/配置边界更清晰。这种结构性工作很重要：它使增长更容易，而不会使系统变得脆弱。 （＃1982，＃1888）
  • 提供商支持不断向外扩展 — Ollama 支持本地模型，VolcEngine 和 BytePlus 加入生态系统，支持 openrouter/* 模型，并且网络搜索提供商现在可以通过后备行为进行配置。纳米机器人越来越多地满足用户的需求。 （＃1863，＃1608，＃2026，＃398）
  • 可观察性和工具变得更强 - Langsmith 集成带来了更好的对话跟踪，修复了内置技能打包，更智能的文件系统/shell 工具改进了分页、后备匹配和输出行为。该系统变得更容易检查和使用 trust。 （＃1920，＃1416，＃1895）
  • 飞书得到了重大改进 - 回复/引用支持落地，工具调用现在可以在代码块中呈现，组提及行为得到改进，Groq Whisper 音频兼容性得到修复，更广泛的多媒体处理变得更好。在这个周期之后，飞书的支持感觉更加完整。 （＃1963，＃1966，＃1768，＃1741，＃2034）
  • Telegram 在群组和媒体工作流程中得到了显着改善 — 群组响应行为现在是可配置的，消息回复上下文可以跨文本和媒体工作，并且媒体文件名冲突错误已得到清理。这些单独的细节都是小细节，但组合在一起会让对话感觉更加自然。 （＃1389，＃1900，＃1796）
  • 企业和协作渠道也得到改善 - WeCom渠道支持落地，Slack线程行为得到澄清，QQ传统纯文本回复得到恢复，钉钉获得了语音识别文本检索和多媒体改进。 （＃1327，＃1784，＃1941，＃1859，＃2034）
  • CLI 和运行时行为更加可预测 — 网关端口默认值现在尊重配置，重新启动流程更加便携，Windows 兼容性受到关注，并且 shell/工作空间防护对于主扩展和基于波形符的路径变得更加严格。这是一种用户只有在丢失时才会注意到的工作——这正是它重要的原因。 （＃1797，＃1785，＃1958，＃1479，＃1827，＃1845）
  • 许多尖锐的边缘消失了 - 隐藏文件不再意外同步，非视觉模型不会收到 image_url，心跳和 cron 的噪音减少，版本 ID 现在显示在日志中。这些并不是华而不实的变化，但它们让纳米机器人感觉更稳定、更深思熟虑、更适合生产。 （＃1856，＃1901，＃1973，＃2058）

社区

热烈欢迎本版本中的 29 位新贡献者。 开源以两种方式发展：通过大胆的新想法，以及通过注意到粗糙边缘并平滑它们的耐心工作。 v0.1.4.post5 两者都有很多。感谢所有贡献功能、修复、重构、文档和基础设施改进的人——纳米机器人并不是一下子变得更强大，而是通过许多细心的双手共同推动它向前发展。 完整 Changelog：https://github.com/HKUDS/nanobot/compare/v0.1.4.post4…v0.1.4.post5

下一步是什么

展望未来，我们将继续将纳米机器人推向更加模块化、面向插件的生态系统。作为第一步，我们计划首先在通道层进行实验和迭代 - 使用通道作为更具可扩展性的架构的试验场，然后在整个项目中进一步扩展该方法。 我们还将继续使用 nightly 分支来进行更快的测试、更早的反馈以及更快地迭代新想法。如果您有兴趣帮助塑造未来，我们热烈欢迎您做出贡献。您可以在CONTRIBUTING.md中找到贡献工作流程和指南。 还有一个小注意事项：v0.1.4.post5 可能是 0.1.4 系列中的最后一个版本。它以大量的打磨和来之不易的稳定性结束了这个周期——也为接下来的事情腾出了空间。 下一个主要版本已经成型，我们认为这是值得等待的。 😉
