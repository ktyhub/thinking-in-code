nanobot v0.4.0

🐈 nanobot v0.4.0 让日常工作更容易继续 - 具有持久的对话历史记录、更强大的工作台以及更清晰的下一次更新路径。

继续前进。 网关现在将模型历史记录和浏览器记录存储在 SQLite 中，导入现有对话，并协调已保存状态的更新。稳定版和选择加入预览版共享一个更新流程，并在安装和重新启动之前进行明确确认。

浏览器工作台更易于导航和连接：完整的提示历史记录导航、远程实例、更清晰的委派任务详细信息、更丰富的附件以及更一致的移动控件。该终端获得美人鱼图查看和特定目标的本机捆绑包。两个 client 继续使用相同的 Python 网关。

此版本还明确了安装所有权。支持的托管安装可以通过应用程序更新和恢复程序；其他安装会收到有关其原始包管理器或部署的说明。恢复并不意味着恢复旧的聊天副本。在替换现有安装之前，请阅读升级说明。

亮点

  • 一次更新流程，由您确认 — 在“设置”→“关于”中检查版本，选择是否接收预览更新，查看确切版本，然后确认安装并重新启动。一旦公开版本已验证批准证明，受支持的官方安装程序和 POSIX uv 环境就可以使用应用内流程。
  • 保护当前数据的恢复 — 安装程序管理的更新可以尝试修复，并在安全的情况下恢复原始程序和服务。配置和对话不会自动替换为较旧的备份。该流程之外的安装所有者保留自己的维修路线。
  • 持久的对话历史记录 — SQLite 将模型历史记录和 WebUI 显示历史记录置于网关所有权之下。导入现有的 JSONL 历史记录并保留源备份。寻呼、实时输出协调、排队跟进和目标延续都得到了可靠性修复。
  • 更清晰的浏览器工作台 — 通过有界加载导航完整的提示历史记录、搜索加载的消息和会话句柄、内联重命名主题以及批量归档主题。委派的任务具有更清晰的运行状态和详细视图。
  • 您的工作台，位于正确的主机上 — 通过显式主机身份、配对和重新连接反馈连接到现有远程实例。更新指令识别网关计算机，而不是假设它是显示页面的设备。
  • 更丰富的文件和更好的小屏幕体验 - 本地文件和视频附件、图像缩略图、文件卡、Markdown 源视图、阅读大小控件以及触摸和主题改进。外部网站在浏览器中打开，而不是任意嵌入预览。
  • 终端中的图表 — 无需离开对话即可查看、缩放、平移和复制美人鱼图表。平台轮包含匹配的原生TUI和内置WebUI；支持的车轮安装既不需要 Bun 也不需要下载首次启动的 TUI。
  • 对模型和集成的更多控制 - 可搜索的提供程序、显式的 API 选择、每个预设请求覆盖、共享代理选择、线性和 WhatsApp 代理平台通道、QQ QR 设置和 DeepSeek 搜索。可以就地编辑、启用和禁用计划的作业，并且可以检查最近的运行。
  • 针对 Windows 空闲内存增长的修复 - 进程状态轮询现在在 3.14 之前的 Python 版本上重用本机类型和 API 绑定，同时保持实时进程检查和处理清理。

升级注意事项

  • 分发可用性。 经过验证的 v0.4.0 软件包在此 GitHub 版本和 PyPI 上提供。此版本尚未启用应用内自动安装：它需要经过验证的发布批准证明和适用的公开发布源。发布这些文件不会在预览版中注册用户或开始更新。
  • 首先通过其原始安装方法升级 v0.3.5。 该版本不包含此新的应用内更新程序。在网关计算机上以其原始操作系统帐户运行安装程序、包管理器或容器替换。现有安装不会自动转换为官方安装程序环境。请遵循安装所有者说明，包括记录的附加内容、限制和自定义选项。
  • 停止共享编写器并备份整个实例。 完成活动工作，停止使用环境或数据的所有 Nanobot 进程，并一起备份选定的配置目录和工作区。包括身份验证、会话和 WebUI 状态。不要仅复制实时 SQLite 数据库文件。升级后，使用原始启动器，检查运行版本，打开旧对话，写入新消息并验证再次重新启动。
  • SQLite 更改了降级过程。 JSONL 导入在整个 0.4.x 中仍然可用；仅适用于旧版 JSONL 的安装必须在 0.5.0 之前通过支持导入的版本。保留导入的源备份和旧的 WebUI 目录。旧版本无法读取新的 SQLite 显示历史记录。降级需要一个停止写入器备份恢复过程，该过程负责处理自备份以来创建的消息；它不是自动数据回滚。请参阅会话存储。
  • 更新可能会重新启动网关。 确认安装可能会中断正在运行的任务。关闭预览会保存订阅，但不会降级已安装的预览。恢复不能保证在永久性存储损坏、不兼容的数据写入或两个恢复过程丢失后服务恢复。丢失或无法验证的公共资产不得被视为成功安装。请参阅 [更新 n
