nanobot v0.2.2

🐈 nanobot v0.2.2 在这里 — 合并了 140 个 PR，21 个新贡献者。经纪人变强了！

标题是耐用性。 WebUI 对话现在更多地适应现实生活：记录被分段，而不是存在于一个脆弱的文件中，分叉聊天更可靠地保存回复，活动回合滚动和重播更可预测，启动路径阻塞更少，网关关闭更平静。长时间的会话、过时的提供程序、缓慢的路由、损坏的配置文件、格式​​错误的历史记录、流停滞和空的提供程序响应都不太可能破坏工作。

第二个故事是纳米机器人成为真正的 Python 运行时。 SDK 不再只是代理循环周围的一个薄层便利层：并发 run() 调用被隔离，挂钩更干净，MCP 生命周期处理更安全，运行时控制更广泛，并且文档现在从第一原理开始教授 SDK。如果您想将纳米机器人嵌入到您自己的应用程序中，v0.2.2 是第一个让人感觉这条路径是有意为之的版本。

第三个故事是工作台越来越宽，更容易居住。 WebUI 获得了自动化管理、提示导航、令牌使用可见性、移动改进、更好的更新检查、更丰富的活动计时和更快的设置界面。该生态系统通过 Firecrawl 作为无密钥 Web 数据应用程序、Exa / Bocha / Keenable / Volcengine 搜索、更多转录提供程序、自定义图像生成、更好的 Mistral 和 Kimi 处理以及跨 Telegram、飞书、WhatsApp、Slack、电子邮件、QQ、钉钉等的许多渠道修复进行了扩展。

亮点

  • 更持久的 WebUI 会话 - 分段记录存储可保持大型对话的可读性，而不会丢弃旧的回合，分叉/重播路径更可靠地保留助理回复，会话删除可清理遗留文件，刷新不再恢复陈旧的内容，并且活动回合在模型工作时保持锚定。 WebUI 还具有提示导航、更好的移动布局、更清晰的活动持续时间、令牌使用呈现、更安全的启动获取和按需版本检查。

  • Python SDK 作为一流的运行时 — SDK 现在具有更安全的并发 run() 行为、显式运行时控制、更干净的每次运行挂钩处理、更好的 MCP 清理、改进的外观生命周期行为以及更适合初学者的文档。这使得纳米机器人更容易嵌入脚本、服务、评估和定制代理产品中。

  • 网关和入门改进 — 网关获得了后台/服务控制、更干净的前台关闭、更安全的 Ctrl+C 行为以及更好的 MCP stdio 清理。围绕提供商优先的快速启动、更中立的提供商选择、更安全的 WebUI 设置、WebSocket 故障回滚以及更好的键盘导航，简化了入职流程。

  • 搜索、语音和提供商覆盖 - Web 搜索现在涵盖 Firecrawl、Exa、Bocha、Keenable 和 Volcengine 路径；转录通过共享语音输入以及 OpenRouter、StepFun、SiliconFlow、Xiaomi MiMo 和 AssemblyAI 支持进行扩展。提供商获得了更好的 Mistral 推理处理、Kimi K2.7 思维、兼容 OpenAI 的查询/主体控件、自定义图像生成、OpenAI 图像编辑、更安全的 Anthropic 工具 ID 以及更强的重试/回退行为。

  • 跨代理核心的可靠性强化 - 最近历史上下文是令牌上限的，默认情况下处于空闲自动压缩状态，Dream 解释空运行，跳过格式错误的历史记录，历史游标保持单调，工具模式估计被缓存，未知的内置工具参数被拒绝，提供程序回退记录主要错误，并且流停顿可以重试或回退而不返回截断的答案。

  • 行为更像真实应用程序的频道 - Telegram 通过更安全的回退检测获得了更丰富的消息支持；飞书具备流式恢复、WebSocket读卡、提取表、SDK懒加载、二维码登录等功能； WhatsApp 拥有已读回执、转发消息处理和 LID 映射； Slack 允许列出的频道可能需要提及；电子邮件获得附件和 IMAP 后期操作； QQ / Napcat、钉钉、微信、Matrix 等均得到针对性修复。

  • 安全和工作区边界 - 不安全的 MCP HTTP URL 在探测之前被拒绝，本地提供商端点绕过 env 代理，而云端点仍然尊重它们，工作区写入策略更清晰，git 命令从工作区子目录工作而无需放松路径保护，bwrap 获得正常的 HOME，并且剥离的图像输入不再泄漏误导性的本地路径。

社区

非常感谢所有提供 v0.2.2 的人 — 140 个 PR、21 个首次贡献者，以及大量仔细的审核工作。这一版本并不是一个重大转变，而是更多关于让纳米机器人足够可靠以保持每天开放：更稳定的会话、更干净的扩展点、更广泛的提供程序以及当实际工作时间较长时更少的锋利边缘。
