nanobot v0.1.4.post6

🐈 纳米机器人 v0.1.4.post6 就在这里 — 合并了 57 个 PR，27 个新贡献者，并且发布的内容与其说是增加表面区域，不如说是重新思考底层内容。 有些版本是关于您可以做什么的。这个问题是关于你能有多干净地做到这一点。代理运行时被正式分解，主要依赖项被删除，流传输变成端到端，并且安全漏洞被修复。在功能工作的背后，v0.1.4.post6 是一个结构性转折点——这种发布使得下一个版本成为可能。

亮点

  • 代理运行时被分解为可组合的片段 - 提取了共享的 AgentRunner，生命周期挂钩被统一为正式的 HookContext，并且即使出现故障，子代理进度现在也能保留。命令路由被重构为插件友好的结构，并且统一了 process_direct 以一致地返回 OutboundMessage。这不仅仅是清理——它是接下来的可插入代理行为、自定义执行策略和第三方生命周期集成的基础。 （＃2524，＃2541，＃2388，＃2338）
  • litellm 被本机 OpenAI + Anthropic SDKs 取代 — 整个提供商层被重写以直接与上游 SDKs 对话，而不是通过 litellm 路由。 Anthropic 的快速缓存优化、OpenAI o1 的正确 max_completion_tokens 处理以及 Gemini 认为签名保存都随之而来。如果您曾经在凌晨 2 点调试过 litellm 回溯，您就会明白为什么这很重要。 （#2448、#1109、#2468、#2550、#2453）
  • 流媒体实现端到端 — 从提供商到频道再到 CLI，流媒体输出现在作为一流路径流动。飞书获得了 CardKit 流支持，队列流增量被合并以减少 API 调用，并且通道管理器可以正确处理流边界。这就是“机器人正在打字……”和实际观察它思考之间的区别。 （＃2365，＃2545，＃2497）
  • 修复了安全漏洞 — 通过缺少身份验证验证的电子邮件注入和欺骗已得到修复。入站电子邮件现在通过 Authentication-Results 标头验证 SPF/DKIM，默认情况下启用 verify_dkim 和 verify_spf。电子邮件内容用 [EMAIL-CONTEXT] 标记，以防止电子邮件正文中的 LLM 提示注入。详情请参阅公告。 (GHSA-4gmr-2vc8-7qh3)
  • 微信支持作为完整渠道落地 - 微信（微信）加入了渠道家族，具有 HTTP 长轮询、二维码登录和插件 1.0.3 兼容性。除此之外，Telegram、QQ、WhatsApp 和飞书都获得了跨渠道增强功能，包括具有指数退避的重试机制。 （＃2412，＃2428，＃2386，＃2478）
  • 提供商覆盖范围不断扩大 - Mistral 和 OVMS 提供商到来，Step Fun (阶跃星辰) 加入生态系统，自定义提供商错误报告变得更加诚实 - 原始 API 错误而不是不透明的 JSONDecodeError。无论模型位于何处，纳米机器人都会继续满足用户的需求。 （＃2199，＃2472，＃2289，＃2139）
  • 代理在资源方面变得更加智能 - 每个会话并发调度落地，添加了本机多模式感知功能，令牌估计现在计算所有消息字段，并且内存整合正确保留了完成空间。代理循环还可以优雅地处理 CancelledError 并记录具有正确角色的子代理结果。 （＃2393，＃2304，＃2344，＃2378，＃2239，＃2104）
  • 飞书和 Telegram 均升级 - 飞书获得了流媒体卡、帖子消息中的代码块解析以及 Markdown 渲染和媒体类型的修复。 Telegram 获得了 HTTP(S) URL 媒体支持、独立的连接池以防止池耗尽，以及更安静的网络错误日志记录。个体很小，组合起来很重要。 （＃2545，＃2246，＃1814，＃1755，＃1793，＃2247，＃2272）
  • CLI 和入门变得更加强大 — 功能齐全的板载向导到来，--dir 支持多个实例，/status 显示运行时信息，-h 可以在任何地方工作，并且时区现在是可配置的。这种打磨让首次运行的体验感觉是有意为之的。 （#2101、#1763、#1985、#2123、#2477、#1136、#2266）
  • 基础设施全面强化 - 僵尸进程在 shell 超时时收获，cron 作业存储的范围仅限于工作区，MCP 工具模式正确处理可为空的参数，Docker 构建包括 openssh-client，并且测试套件被重新组织为更清晰的结构。这种工作可以防止您下个月提交的错误报告。 （#2362、#2204、#2230、#2287、#1911、#2427、#2367）

社区

热烈欢迎本版本中的27 位新贡献者。 v0.1.4.post6 的信念是，开源中最重要的工作并不总是最引人注目的。替换核心依赖项、分解运行时、关闭安全漏洞——这些都不能成为华丽的演示，但所有这些都使 Nanobot 成为一个您可以比昨天更有信心构建的项目。感谢所有贡献代码、修复、文档和想法的人。基础越来越牢固。 完整 Changelog：https://github.com/HKUDS/nanobot/compare/v0.1.4.post5…v0.1.4.post6
