nanobot v0.1.5.post3

🐈 nanobot v0.1.5.post3 在这里 🎉 — 合并了 57 个 PR，12 个新贡献者。代理学会了在线程中交谈。 如果说 v0.1.5.post2 是关于影响范围和完善的话，那么 v0.1.5.post3 就是让对话成为其平台的一等公民。飞书群组主题有单独的会议。 Discord 线程继承父允许列表并保留自己的上下文。 Telegram 可以呈现内联键盘选择。 MSTeams 会修剪过时的对话引用，以便出站消息不再默默失败。在所有通道中，现在可以覆盖每个通道的 sendProgress 和 sendToolHints - 使嘈杂的通道安静，保留冗长的通道。在底层，DeepSeek-V4 支持端到端：思维模式和遗留会话兼容性一起提供，并针对不完整的推理历史和非字符串消息内容进行后续修复，以便线程保持稳定。新的 ask_user 工具可让代理暂停并要求您在任务中进行选择。 Olostep 和 Hugging Face 加入了提供程序阵容，并且一对超时环境变量（NANOBOT_LLM_TIMEOUT_S 和 NANOBOT_OPENAI_COMPAT_TIMEOUT_S）可防止挂起的请求劫持您的会话。 WebUI 继续发展——图像上传、视频渲染、询问用户选择、模型设置——但仍然只是源代码预览，而不是捆绑到轮子中。

亮点

  • 线程无处不在 - Feishu、Discord、Slack、MSTeams - 每个频道都在此版本中成长。飞书群组主题现在隔离会话，这样一个主题中的消息就不会泄漏到另一个主题中；流媒体卡和工具提示遵循原始主题。 Discord 线程继承其父通道的 allowChannels 并获得会话隔离，这也意味着斜线命令尊重白名单。 Slack 不再丢失主动回复的线程上下文。 MSTeams 对话引用获得了基于 TTL 的修剪 (refTtlDays)、网络聊天引用的自动清理以及保持活动引用活动的触摸间隔。主题是一致的：对话属于他们的线程，而不属于整个频道。 （#3449、#3397、#3440、#3462、#3475、#3447、#3487）
  • 每通道进度和交互控制 - sendProgress 和 sendToolHints 曾经是全局开关。现在，您可以将它们放置在任何单独的通道配置中以覆盖全局默认设置 - 让 Telegram 保持安静，同时 WebSocket 保持冗长。该代理还学会了通过新的 ask_user 工具在任务中向用户询问结构化问题：在 WebUI 中，这些问题呈现为按钮，在其他渠道中，它们会返回到文本。 Telegram 拥有内联键盘 (inline_keyboards: true)，用于呈现 message 工具按钮选项。 /history [n] 命令让您无需滚动即可查看最近的消息。 （＃3487，＃2791，＃3398，＃3454，＃3466）
  • DeepSeek-V4 和更广泛的提供商堆栈 — 此版本使 DeepSeek-V4 成为一流目标：思维模式和旧会话兼容性一次性实现 (#3420)，因此您可以将代理指向 V4，而无需放弃旧的对话。现实世界的记录暴露了两个差距，并得到了专门的后续跟踪——截断或不完整的推理历史 (#3453) 和异构（非字符串）消息内容 (#3458)——因此需要大量工具的会话不会在运行中失败。最重要的是，Hugging Face Inference Providers 成为一流的提供商 (#3496)，Olostep 加入了网络搜索 (#3505)，OpenAI 兼容端点获得了用于 vLLM 引导解码和朋友的 extraBody (#3491)，超时对 NANOBOT_LLM_TIMEOUT_S / NANOBOT_OPENAI_COMPAT_TIMEOUT_S 将外部转弯限制与内部 HTTP 边界分开 (#3428、#3478)。 ZZPH100​​ZZ Copilot 正确路由 GPT-5 和 o 系列型号 (#3380)； Gemini 路由选择了 reasoning_effort="none" 和 Gemma (#3515)。
  • 内存和会话强化 — consolidationRatio (0.1–0.95) 允许您调整令牌触发的整合压缩上下文的积极程度。 maxMessages（默认 120）在不影响持久性的情况下限制重播窗口。 History.jsonl 通过 fsync 和目录同步获得原子写入，在意外关闭时关闭最后一个数据丢失窗口。 raw_archive 膨胀路径和几个卡住的合并边缘已被密封。会话现在在正常关闭时进行 fsync。结果是：内存的可调性更强，也更耐用。 （#3285、#3482、#3508、#3369、#3412、#3415、#3459）
  • macOS LaunchAgent 和部署 — 新的 docs/deployment.md 部分介绍了将 nanobot gateway 部署为 macOS LaunchAgent — plist、launchctl bootstrap/enable/kickstart、日志路径以及当您忘记停止手动网关时不可避免的端口冲突问题。对于任何希望代理在登录时在线而不保持终端打开的人很有用。 (#3441)
  • 安全性和可靠性修复 — 非 Windows 平台上通过 path_append 的 shell 注入向量已关闭。工作区目录违规现在会停止代理循环，而不是记录警告。 resolve_config_env_vars 停止剥离排除的字段。 tool_result 内容中的 Anthropic image_url 块已正确转换。 MCP 功能名称经过清理，以实现 API 型号兼容性。 Windows MCP stdio 启动器可避免 WinError 193。结构化工具事件有效负载为通道提供更丰富的进度数据。文档解析器延迟导入以缩短冷启动时间。跨提供商、渠道和代理循环的二十多个较小的修复使该版本更加完善。 （#3366、#3493、#3383、#3387、#3470、#3379、#3399、#3423）

社区

衷心感谢所有提供 v0.1.5.post3 的人 — 57 个 PR、27 个贡献者，并热烈欢迎 12 首次贡献者。每一次审查、补丁和错误报告都有帮助；这个版本是一个共同的胜利。 🎉
