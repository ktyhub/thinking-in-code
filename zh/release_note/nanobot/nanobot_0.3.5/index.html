nanobot v0.3.5

🐈 nanobot v0.3.5 将工作台带到终端 - 并使对话更容易在浏览器、终端和聊天应用程序中继续。

标题是一名代理人，更多工作地点。对于本机终端运行 nanobot，对于浏览器运行 client 或 nanobot webui。两者都使用相同的网关并保存 WebSocket 对话。终端会话可以恢复、分叉、检查和分离，而无需构建单独的代理运行时。

浏览器工作台围绕真正的多任务处理而发展：分组对话窗格、临时聊天、持久侧边栏排序、会话提及、技能市场、便携式代理插件以及用于远程 MCP 服务器的浏览器 OAuth。自动化现在具有任务和日历视图、更清晰的计划控制和每次运行回复。移动构图、设置、上下文图表、应用程序徽标和品牌提及得到了另一轮重点改进。

另一个故事是您可以检查的连续性。上下文使用和压缩是可见的，中断的工作具有更清晰的恢复控制，并且会话历史记录在分页、重新连接和升级方面更加持久。此版本还收紧了附件、流程、工作区和电子邮件身份验证边界。在替换现有安装之前，请阅读升级说明。

亮点

  • 本机终端工作台 — 从 nanobot 开始，切换会话，粘贴支持的 clipboard 图像，完成应用程序和技能参考，检查上下文和文件差异，排队后续操作，并使用 /detach 使网关保持运行。
  • 并排浏览器对话 — 在可调整大小的组中排列最多四个主题，保持侧边栏顺序，将保存的会话拖到提及中，并在不需要持久主题时使用临时聊天。
  • 更易于管理的自动化 — 在任务和日历视图之间切换、检查运行回复并通过更清晰的控制来调整计划。编辑作业会保留待执行的操作；删除一个不再导致导航被阻止。
  • 可见的上下文和更稳定的长会话 - 每轮令牌/缓存图表、上下文压缩进度、分页历史搜索、累积摘要以及适用于实际模型上下文的文件读取重复数据删除。
  • 具有更清晰身份的应用程序和技能 — SkillHub 发现、便携式代理插件、远程 MCP OAuth 和令牌刷新、可见的连接故障以及聊天中一致的应用程序徽标和品牌名称。
  • 更好的小屏幕体验 - 通过 PWA 支持、更窄的编辑器控件、可拖动的上下文表、触摸友好的图表详细信息以及与其打开方向相匹配的设置导航来进行主屏幕安装。
  • 更广泛的模型和搜索选择 - DeepSeek 响应和 V4 视觉支持、Eden AI 和 OrcaRouter 网关、AnySearch、在线 OAuth 模型目录以及更具弹性的提供商回退和响应历史记录处理。
  • 更可靠的渠道和运行时边界 - 丰富的 Telegram 流、改进的飞书入门、更安全的 QQ 附件、trusted 电子邮件身份验证结果、可选的 macOS 安全带隔离以及子进程环境中更少的凭据泄露。
  • 嵌入和操作 - SDK 主机集成挂钩、显式桌面附件、网关就绪报告以及经过检查的版本匹配的终端发行版。

升级注意事项

  • 备份配置、工作区和会话存储；首先停止旧进程。 会话 JSONL 文件现在位于配置目录的 sessions/<workspace-id>/ 树下。验证副本后，第一次升级启动会迁移现有工作区会话。不要让新旧版本同时写入同一个工作区。降级前，停止nanobot并使用nanobot sessions restore-workspace --config <config.json> --workspace <workspace>；该命令拒绝覆盖不同的现有文件。请参阅会话存储和回滚指南。
  • 电子邮件验证需要明确的接收者 trust 锚。 如果启用 verifySpf 或 verifyDkim，请使用接收邮件服务确认的确切身份配置 channels.email.trustedAuthservIds。该服务必须删除声称其身份的伪造标头，并提供一个统一的身份验证结果标头。没有此字段的现有已验证电子邮件配置将无法启动。在配置之前保持电子邮件禁用状态；不要将禁用验证作为解决方法。按照邮件升级指南进行操作。
  • 普通 nanobot 打开本机终端 UI。 使用 nanobot --classic 作为 Python 提示符，或使用 nanobot -m "Hello!" 一次性使用。平台轮子包括 WebUI 和匹配的 TUI，因此首次 TUI 启动既不需要下载 Bun，也不需要下载 GitHub。支持的 Wheel 针对 macOS 13+ arm64/x64、glibc 2.17+ Linux arm64/x64 和 Windows x64。其他平台和源代码分发版本可以使用经典提示或 WebUI；可编辑源代码开发使用 Bun。
  • 最后连接的 client 拥有按需网关生命周期。 关闭最后一个交互式 WebUI/TUI 启动器会停止该网关。在终端中使用 /detach 或 nanobot gateway --background 来完成必须在没有 client 的情况下继续进行的工作。
  • 远程项目选择使用 Nanobot 主机上的路径。 它需要限制访问。它不会从浏览器设备中选择目录，并且远程 clients 无法启用完全访问。
  • 网关运行状况响应信息更丰富。 当启用的 WebSocket 通道未运行时，/health 可以返回 HTTP 503。它不认证型号、MCP 或其他通道连接性；更新之前假设每个实时进程都返回 200 的监控。
