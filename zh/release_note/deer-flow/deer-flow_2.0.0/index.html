deer-flow v2.0.0

DeerFlow 2.0 是围绕“超级代理”安全带的彻底重写， 编排子代理、持久内存、沙盒执行、 以及可扩展的技能/工具系统。它与 1.x 行不共享任何代码， 它位于 main-1.x 分支 上。

此版本结束了 2.0.0 里程碑 自第一个 2.0 里程碑标签以来，有 182 个合并 PR。

📖 完整笔记：CHANGELOG.md · 中文版

⚠️ 重大改变

  • 运行水合 - 现在从 RunStore 运行水合并持续 interrupted 状态。现在需要拥有该运行的工人才能取消；交叉工作者 取消返回 409 而不是默默地显示成功。 （[#2932]）

✨ 亮点

  • 自我更新的自定义代理 - 代理可以对其进行持久编辑 从正常聊天中拥有 SOUL.md / config.yaml，具有完整的每用户 隔离。 （[#2713]）
  • 用户拥有的 IM 通道连接 — 用户可以绑定自己的 Slack， Telegram、Discord、飞书/Lark、钉钉、微信和 WeCom 帐号排名靠前 操作员配置的机器人。 （[#3487]）
  • 更多模型和社区搜索 - StepFun 和 MiMo 推理模型， MiniMax 用于图像/视频/播客技能以及新的音乐生成技能， 和 Brave Search / SearXNG / 无浏览器 / Serper Google 图片工具。 （[#3461]、[#3298]、[#3437]、[#3528]、[#3451]、[#3575]）
  • 更丰富的渠道 - Discord 获得仅提及模式、线程路由和 打字指示器； Telegram 通过编辑占位符来流回复 消息到位。 （[#2842]、[#3534]）
  • 可配置的循环检测，具有每个工具的频率覆盖和 延迟警告注入。 （[#2586]、[#2711]、[#2752]）
  • 子代理令牌使用实时流式传输到标头，具有跨度 归因于父线程的 Langfuse 跟踪。 （[#2882]、[#3611]）
  • 跟踪抛光 — 干净的 lead_agent / 自定义代理跟踪名称； session_id
    • user_id 传播到 Langfuse；非 ASCII 内存痕迹不再转义。 （[#3101]、[#2944]、[#3104]）
  • 默认情况下启用令牌使用跟踪，具有精细的显示模式和使用情况 归因于实际模型。 （[#2841]、[#2329]、[#3658]）
  • 灵活的记忆和建议 — 在受限情况下选择退出 tiktoken 通过 memory.token_counting 的网络；将人工智能后续建议设为可选。 （[#3465]、[#3591]）

🚀 性能

  • 将线程元数据过滤器推送到 SQL 中。 （[#2865]）
  • RunManager 中的 thread_id 运行索引以消除 O(n) 扫描。 （[#3499]）
  • 在 MemoryRunEventStore 中索引消息以消除 O(n) 扫描。 （[#3531]）
  • 缓存每个类的 Base.to_dict 列反射。 （[#3654]）
  • 加快 glob/grep 沙箱行走中的 should_ignore_name 速度。 （[#3657]）

🔒 安全

  • 拒绝 Linux 和 Windows 上的符号链接上传目标。 （[#2623]、[#2794]）
  • 屏蔽 MCP 配置响应中的敏感值；强化端点。 （[#2667]、[#3425]）
  • 拒绝跨站点身份验证 POST。 （[#2740]）
  • 封顶技能神器预览解压（zip-bomb defence）。 （[#2963]）
  • 仅在 aio (DooD) 沙盒模式下安装主机 Docker 插槽。 （[#3517]）
  • 默认情况下不绑定挂载主机 CLI 身份验证目录。 （[#3521]）

🐛 值得注意的修复

  • 内存在持久事件循环上运行，而不是在短期事件循环上运行 asyncio.run()；每个代理隔离的排队更新；封装的 JSON 响应 解析正确。 （[#2627]、[#2941]、[#3252]）
  • 在网关重新启动后从持久存储中运行 Hydrate，返回 ISO 8601 时间戳，并具有幂等取消功能。 （[#2989]、[#2599]、[#3058]）
  • 子代理与父运行的检查点隔离；超时终端 状态原子；尊重工具/中间件的模型覆盖。 （[#3559]， [#2583]，[#2641]）
  • 沙箱就绪轮询不再阻止事件循环； /mnt/user-data 合约在 API 边界执行； PVC 数据范围为 用户； Windows/Git Bash MSYS 路径转换已禁用。 （[#2822]、[#2881]、 [#2973]、[#2766]）
  • Auth 自动生成的 JWT 机密在重新启动后仍然存在；设置状态 使用缓存的响应而不是 429。（[#2933]、[#2915]）
  • 前端修复了吞没的第一条消息、登录闪烁/调整大小观察者 循环、重复的乐观消息、深度嵌套的列表渲染崩溃，以及 新聊天的线程隔离。 （[#2731]、[#2954]、[#3002]、[#3393]、[#3570]、 [#3508]）
  • 频道 — 用户拥有的 IM 现在需要绑定身份、范围文件和 助手向所有者发出命令，使提供者状态具有权威性，并使 连接流是确定性的，由共享重试助手支持， 操作护栏。 （[#3578]、[#3579]、[#3580]、[#3581]、[#3582]、 [#3583]、[#3584]）
  • 流和历史 — 中断通过 SSE 值事件传播 LangGraph SDK 和 base64 图像有效负载从流式传输和 历史响应以保持 UI 响应。 （[#3605]、[#3631]、[#3535]）
  • 前端（更多） — 工作区聊天列表分页超过 50 个线程， 当 SSR 身份验证探针无法到达网关时保持交互，并获取 适合移动设备的布局。 （[#3485]、[#3495]、[#3646]）

📦 部署和操作

  • Docker 网关默认为单个工作人员（多工作人员损坏）。 ([#3475])
  • Docker nginx 在请求时解析上游名称。 （[#2717]）
  • 包装添加了 postgres 额外的存储/检查点支持。 （[#2584]）
  • 脚本在 make dev 重新启动时保留 uv 额外内容；清理本地 nginx 停止；从网关重新加载中排除运行时状态。 （[#2767]、[#3005]、 [#3426]）
