deer-flow v2.1.0

DeerFlow 2.1 以 2.0 超级代理安全带为基础，重点关注 trust， 规模和可操作性：可验证的代理执行、持久的批量委托、 可插拔内存后端、四个新的沙箱提供程序、一个树外扩展 系统，以及企业级身份验证和授权 - 封装在 包含项目、对话分支和引用的更丰富的工作空间 对话。

此版本结束了 2.1.0 里程碑 自 2.0.0 发布以来，有 772 个合并的 PR。

📖 完整笔记：CHANGELOG.md · 中文版

⚠️ 重大变更

  • 跟踪 ID 是无条件的 — 每个网关 HTTP 响应都带有一个 X-Trace-Id 标头和 logging.enhance.enabled 现在控制日志输出 仅。运行元数据中 Client 提供的 deerflow_trace_id 值是 被覆盖，因此标头、日志和持久运行不能不一致 - 发送 用于固定相关 ID 的 X-Trace-Id 请求标头。 （[#5119]）
  • /mnt/skills 保留用于仅受管理的启用技能预测。 DEER_FLOW_HOST_SKILLS_PATH / SKILLS_HOST_PATH 不再使用，并且 目标该路径的 E2B 操作员挂载将被跳过并带有警告。 ([#4178])
  • **对于 E2B 强制执行 sandbox.replicas 作为容量限制；默认值 wait 政策现在可以使代理轮次失败，而不是超过上限。 （[#4391]）
  • SKILL.md 目录是运行时包边界 — 嵌套 SKILL.md 文件是支持数据，不再注册为独立技能。 （[#4098]）
  • 内存可插拔 (memory.manager_class)：DeerMem-私有设置 移至 memory.backend_config（自动迁移并带有警告）， /memory/config 改变了形状，storage_path 现在是根目录 （旧文件样式值将被删除并带有警告），自定义存储类别 移动到新路径并在 __init__ 中采取 config，并且后端没有 search() 在 tool 模式下快速失败。 （[#4122]、[#4023]、[#4324]）
  • database.checkpoint_delta_snapshot_frequency 移至 database.checkpoint_delta.snapshot_frequency 及其默认值更改为 1000 至 10 — 明确设置以保持旧的节奏。 （[#4516]）
  • Docker 默认绑定环回 — 已发布的入口端口绑定 两个撰写文件中的 127.0.0.1 与记录的 local-trust 相匹配 部署模型；设置 BIND_HOST 以在其他接口上公开堆栈。 （[#4618]）

✨ 亮点

  • 可验证的代理执行 - 每个工具调用都带有防篡改的、 运行时标记的收据和有界收据分类账到达模型 背景；子代理报告必须引用具有可验证交付成果的工具收据 处理牵头代理人交叉检查；和 acceptance_criteria 上 委托在父端进行确定性检查（文件存在， 记录测试命令退出状态），报告任何无法确定的情况 未经证实。 （[#4659]、[#5076]、[#5090]、[#5109]、[#4365]）
  • 大规模子代理 - 系统维护的委托分类账可防止 冗余的重新授权和总上限边界扇出（[#3877]、[#4115]）； 一个进程范围的容量控制器管理并发性，并且选择加入 batch_task 工具可运行大量独立项目，因为耐用、 可恢复的 SQL 支持的批处理，包括租用、重试、暂停/恢复/取消，以及 聊天进度面板（[#4998]、[#5289]）； task(context_mode="snapshot") 携带父会话的调度时副本（[#5367]）；和 子代理步骤历史记录将保留并显示在线程中。 （[#3845]）
  • 计划任务增长 — interval 计划加入 once 和 cron （[#5291]）；保存前可以预览即将发生的 cron 事件 （[#5381]）；运行历史记录按状态和页面向后过滤服务器端 用户界面（[#5384]、[#5363]）；任务可以固定 lead_agent 或自定义代理 （[#5286]、[#5288]）；繁忙事件在重新启动后持久排队 （[#4918]）；多实例恢复不再中断实时运行。 （[#4713]）
  • 可插拔内存 — 通过 HTTP 的新 OpenViking、mem0 和 Honcho 后端 （[#4509]、[#4528]、[#4730]）；内置 FTS5/BM25 检索适配器 （[#4360]）； LLM 辅助的整合和过时修剪（[#3996]， [#3860]，[#4143]）；每个代理的增量事实存储（[#4279]）；混合体 驱逐政策（[#4789]）；保证正确事实注入（[#3592]）； 并选择写入端事实重复数据删除。 （[#5254]）
  • 更多沙箱，更严格的控制 - 新的 E2B、BoxLite（带有暖 池）、Tenki 和 OpenSandbox 提供程序（[#3883]、[#3940]、[#3951]、[#4382]、 [#4877]);选择加入 isolated / 域-allowlist 本地网络出口 Docker 沙箱，可通过人工输入批准被拒绝的域 卡（[#5152]）；和硬化的本地容器 - 桥接网关端口绑定， 默认 seccomp，已删除功能。 （[#4986]）
  • 树外扩展 — Python 扩展提供中间件， 生命周期和系统模型观察者、网关服务和 HTTP 路由器， 使用 deerflow extensions install/upgrade/enable/disable/remove 管理 （[#4636]、[#4684]、[#4780]、[#5347]）； 0.2 扩展 API 允许扩展 观察代理做了什么（[#4863]）；和新的 RunEvidenceReader 合约 驱动持久的、基于游标的更改运行发现。 （[#5405]）
  • 企业身份验证和授权 — 具有 Keycloak 支持的通用 OIDC/SSO （[#3506]）；具有范围路由策略的个人访问令牌（[#5041]）；一个 内置 RBAC 提供程序，强制执行工具、模型和沙箱授权 在汇编和运行时（[#4260]、[#4370]、[#4540]、[#4911]、[#4439]）； 本地自注册可以关闭仅 SSO 的配置（[#4311]）； 和帐户首选项在干净的浏览器中仍然存在。 （[#5397]）
  • MCP 作为生产基础设施 — 持久的任务运行时生存
