OCRmyPDF v17.12.0

小版本 发布时间2026年9月16日 来源ocrmypdf/OCRmyPDF 英文原文

OCRmyPDF v17.12.0

变化

  • OCRmyPDF 现在需要 pikepdf 10.2 或更高版本（从 pikepdf 10 开始）。这是 第一个版本提供 pikepdf.NamePath（Object.as_int() 系列） 类型安全访问器和线程本地 explicit_conversion()。 OCR我的PDF 使用这三个方法从它未写入的 PDF 中读取可选值。
  • HEIF/HEIC 输入支持现在是一个可选附加项，ocrmypdf[heic]，而不是 默认依赖项。我们之前依赖的pi-heif包是 已停产；其后继者 pillow-heif 捆绑了 libheif、libde265 和 x265 在它的轮子中，使轮子作为一个整体获得 GPLv2 许可，所以我们不 默认安装。如果您将 HEIC 图像提供给，请安装 ocrmypdf[heic] OCRmyPDF。 Docker 图像和快照不包含它。 {issue}1746
  • 带标签的 PDF 被拒绝，因为它现在似乎包含真实文本 退出时显示代码 6 (already_done_ocr) 而不是代码 2 (input_file)， 将 PDF 的退出代码与之前的 OCR 相匹配。检查退出的脚本 带标签的 PDF 上的代码 2 需要更新。谢谢@BetterAndBetterII。 {issue}1551
  • snap 包现在是从我们的 CI 构建和发布的，而不是 Launchpad，因此 stable 频道再次跟踪发布而不是 冻结在v16.4.2。它基于 core26 并包含 JBIG2 编码器。

修复

  • 在 --output-type pdfa 文件中复制或搜索的文本显示为垃圾 （不相关字符的稳定替换，或者根本没有）当 PDF/A 转换通过 Ghostscript 9.56 到 10.04.x 运行，其中 在 Ubuntu 24.04 中包含 Ghostscript。 fpdf2 写入每种字体的 ToUnicode CMap 作为单个 bfchar 块，但 CMap 规范最多允许 每个块 100 个条目，那些 Ghostscript 版本会丢弃整个地图 当块更大时。任何具有超过 100 个不同字形的页面 受影响的，几乎是散文的每一页。 CFF CID 键控字体，例如 Noto Sans CJK 在其 Encoding CMap 中也存在同样的问题，其中 Ghostscript 版本也绘制了错误的字形。 OCRmyPDF 现在可以拆分 对于每个 fpdf2 版本，每个 CMap 块都会包含 fpdf2 编写的 100 个条目。 fpdf2 2.8.9 将拆分 ToUnicode 块本身，但不会拆分编码 块，因此修复保持不变。感谢@olafure 的分析 （{issue}1747，fpdf2 问题 py-pdf/fpdf2#1952）。
  • 包含 fi、ff、fl 的单词以及使用 --output-type pdfa 文件中缺少字母（con dentiality、e ects） 当 PDF/A 转换通过 Ghostscript 10.05.0 到 10.06.x 运行时。 这些 Ghostscript 版本会删除扩展至超过的 ToUnicode 条目 一个字符（Ghostscript bug 709030，已在 10.07.0 中修复），以及 fpdf2 渲染器的 HarfBuzz shaping 已形成可选的拉丁连字，其 条目正是这样做的。脚本中不需要 shaping 的不可见文本 现在每个字符编码一个字形，因此不存在会丢失的此类条目。 复杂的脚本仍然会成形，OCRmyPDF 现在会在受影响的情况下发出警告 Ghostscript 正在使用中，因为它们的联合映射仍然可以删除。 谢谢@kmn5 ({issue}1744)。
  • 格式错误的 PDF，其中存储了字典以外的内容 结构键 — /Resources、/Resources /XObject、/Root /AcroForm、 /Root /MarkInfo、/Root /Names、/Root /PieceInfo、注释的/A、 或图像的 /SMask ——现在可以在任何地方而不是在 少数已单独加固的地方。这样的文件被读取为 尽管没有钥匙，但戒备森严的小路已经做到了这一点。
  • 没有 /Subtype 的图像 XObject 不再从优化器中提出。
  • PdfInfo 不再在 /MarkInfo << /Marked 1 >> 上中止，其中生产者 将标志写为整数而不是布尔值。谢谢@linhongyu510 （{issue}1742）。
  • 现在可以准确读取以 PDF Real 形式编写的 /UserUnit 页面，而不是通过 二进制浮点数，因此文件写入的数字就是使用的数字。
  • --sidecar 现在拒绝输入或输出文件的任何拼写，而不仅仅是 字节相同。 ocrmypdf in.pdf out.pdf --sidecar ./in.pdf已被受理 然后用 OCR 文本默默地覆盖输入的 PDF。路径现在是 解决 .、..、符号链接和文件系统情况后进行比较。谢谢 @linhongyu510。
  • --deskew 和 --rotate-pages 现在警告说，当 与 --ocr-engine none 结合使用，因为倾斜和方向是通过以下方式测量的 OCR 引擎。其他图像处理选项不受影响。谢谢 @阿奈郭。 {issue}1735
  • 更新了当前平台的安装文档：Ubuntu 26.04 和 添加了 Fedora 43/44，删除了 Ubuntu 20.04，并显示了 uv tool install 点的位置。
  • 文档：更正了配备 JBIG2 编码器的平台列表， 现在包括 Debian 和 Ubuntu。谢谢@lcorbasson。
  • 发布流程和 CI 改进。
