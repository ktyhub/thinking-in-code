graphql-java v26.0

这是 graphql-java 的 26.0 版本。要点总结如下：合并 PR 的完整列表位于最后。

⚠️ 重大变更

现在默认强制执行查询复杂性限制

作为标准验证的一部分，新的 QueryComplexityLimits 验证检查 maxDepth（默认 100）和 maxFieldsCount（默认 100,000）。超过这些限制的查询现在将失败，并出现新的 MaxQueryDepthExceeded / MaxQueryFieldsExceeded 验证错误。

  • 使用 QueryComplexityLimits.KEY 通过 GraphQLContext 设置自定义限制。
  • 使用 QueryComplexityLimits.NONE 完全禁用。

在 #4256 中引入。

验证规则过滤 API 已更改

在 #4228 中，Validator.validateDocument(...) 和 ParseAndValidate.parseAndValidate(...) 中的规则过滤谓词从 Predicate<Class<?>> 更改为 Predicate<OperationValidationRule>。按类过滤的调用者（例如 rule -> rule != NoUnusedFragments.class）必须迁移到枚举（rule -> rule != OperationValidationRule.NO_UNUSED_FRAGMENTS）。 @Internal 类 AbstractRule 和 RulesVisitor 已被删除。

内置指令处理合并 (#4229)

  • DirectiveInfo 已被删除。替换用法：
    • DirectiveInfo.isGraphqlSpecifiedDirective(...) → Directives.isBuiltInDirective(...)
    • DirectiveInfo.GRAPHQL_SPECIFICATION_DIRECTIVES → Directives.BUILT_IN_DIRECTIVES
    • DirectiveInfo.GRAPHQL_SPECIFICATION_DIRECTIVE_MAP → Directives.BUILT_IN_DIRECTIVES_MAP
  • 指令顺序现在一致：所有 7 个内置指令首先出现，然后是用户定义的指令。
  • GraphQLSchema.Builder.clearDirectives() 最初被删除，然后在 #4276 中使用新语义重新添加 - 它清除所有 additionalDirectives，但内置指令始终在构建时自动重新添加。

OneOf 适居性验证 (#4248)

新验证器拒绝无法用有限值填充的 OneOf 输入类型（例如 input A @oneOf { a: A }）。先前验证的模式现在可能会被拒绝。

代码构建模式的非空字段验证 (#4194)

代码构建的模式现在执行与 SDL 构建的模式相同的已弃用的非空字段验证。依赖间隙的模式现在可能无法验证。

GraphQLSchema.getCodeRegistry() 不再是 @Nullable (#4247)

返回类型被错误地注释为可为空。调用者现在可以删除多余的空检查；下游无效工具将反映这一变化。

JSpecify 可空性注释广泛推出

第 2 波和第 3 波（#4184、#4274）加上许多单独的 PR，用 @NullMarked/@NullUnmarked/@Nullable 注释了 graphql.analysis、graphql.execution、graphql.language、graphql.schema 等数百个类。 Kotlin 和其他支持 null 的调用者现在将看到更严格的可空性契约；依赖于先前允许的签名的代码可能需要调整。

✨ 新功能

  • GraphQLSchema.FastBuilder (#4197) — 一个更严格但 ~5 倍更快 的模式生成器，可减少大型模式的时间和内存。
  • 查询复杂性限制 (#4256) - 深度/字段计数护栏纳入验证（请参阅上面的强制方面的重大更改）。
  • 关于操作和文档的 QueryAppliedDirective (#4297) — 在操作/文档级别应用的指令现在公开为 QueryAppliedDirective。
  • 用于异常处理后结果的新检测挂钩 (#4206、#4207) — 在 DataFetcherExceptionHandler 将异常映射到错误后观察 DataFetcherResult。 ChainedInstrumentation 正确委托新挂钩。
  • 通用 DataFetcherResult.newBuilder(T data) (#4254) — 消除了对常见 DataFetcherResult.<T>newResult().data(x)... 模式的显式类型见证的需要。
  • 重新添加了 GraphQLSchema.Builder.clearDirectives() (#4276) — 可与 GraphQLSchema.transform 一起重写非内置指令；内置函数总是会重新添加。
  • toString() 位于 AST 指令持有者 (#4195)。

⚡ 性能

  • 增量 @defer 执行更早开始 (#4174) — 一旦检测到第一个增量调用就开始处理延迟的有效负载，而不是等待初始结果完成。
  • 验证整合 (#4228) — 所有操作验证规则都在单个 OperationValidator 传递中运行，显着减少了验证开销。
  • 减少执行热路径上的分配 (#4252)：
    • Async$Many.materialisedList() — 用零拷贝 Arrays.asList() 包装器替换了 ArrayList 拷贝。
    • ResultPath.toStringValue — 惰性计算；字符串形式仅构建在第一个 toString() 上（通常仅在错误报告期间）。
    • 新的 GraphQLCodeRegistry.getDataFetcher(String, String, GraphQLFieldDefinition) 重载避免了每次获取 FieldCoordinates 分配（约 54 KB/op 减少）。
  • FastBuilder 用于架构构建 (#4197) — 请参阅新功能。
  • 修复了 ShallowTypeRefCollector，以解析应用的指令参数和枚举值定义内的类型引用 (#4288) — 正确性修复使 FastBuilder 能够在更多模式上使用。

🐛 其他值得注意的变化

执行/数据获取

  • 使用多个 @defer 片段进行 DataLoader 调度 (#4270) — 修复了当多个延迟片段运行时 DataLoader 未正确调度的情况。
  • CompletionStageSubscriber 竞争条件 (#4296) — 如果飞行中的 CompletionStage 同时解析，完成信号可能会丢失。修复由新的 jcstress 压力测试支持。
  • 非公共类上的 PropertyDataFetcher (#4287) — 实现公共接口的非公共类上的属性（例如 TreeMap.Entry）现在可以通过搜索公共接口在 Java 16+ 上正确获取。
  • ExecutableNormalizedField 尊重 GraphqlFieldVisibility (#4204) — 现在选择集 API
