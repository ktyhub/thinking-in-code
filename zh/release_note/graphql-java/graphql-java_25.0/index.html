graphql-java v25.0

数据加载器

重构策略

现有的 PerLevelDataLoaderStrategy 已被重构，从而实现了简化并提高了性能。

新策略

引入了两种新策略：“连锁”和“耗尽”。两者都可以通过 UnusalConfiguration 进行配置（请参阅下一节）。

CHAINED 允许使用链式 DataLoader，同时保持每层调度策略。

EXHAUSTED 是一种全新的策略，它的工作原理是在引擎不忙时进行调度。它反映了 JS 数据加载器调度策略，但适用于多线程系统。

异常配置

针对“异常配置”添加了更通用的配置机制。 我们指的是配置，我们不希望很多人使用，但如果他们现在在更常见的地方使用它

例如，如果您想更改文档解析器可接受的最大深度，您可以调用以下方法。

        var parserOptions = newParserOptions().maxRuleDepth(99).build()
        GraphQL.unusualConfiguration().parsing().setDefaultParserOptions(parserOptions)

J指定注释

该团队开始采用 https://jspecify.dev/ 注释作为指示可为空和不可为空字段的方式。 许多重要的类都添加了这些注释，以帮助在值可以为空或不为空时在语义上更加清晰。

重大变化

出于性能原因，包装 FetchedValue 对象并不总是在字段获取器上返回。 这意味着创建 graphql.execution.instrumentation.parameters.InstrumentationFieldCompleteParameters#getFetchedObject 是为了替换旧的 getFetchedValue 方法，并且返回对象有时可以是 FetchedValue，有时可以是简单的 POJO 值。

性能改进

进行了一系列性能改进以减少库的内存占用。 此外，Java .stream() 运算符可能比更直接的循环慢，并且出于性能原因，其中许多调用已更改。

  • 避免将具体化的 fieldValueObject 包装在 https://github.com/graphql-java/graphql-java/pull/3943 中 @samuelAndalon 的 CompletableFuture 中
  • ExecutionStrategyParameters 现在在 https://github.com/graphql-java/graphql-java/pull/3935 中具有 @bbakerman 的直接转换，无需构建器
  • ExecutionStepInfo 现在在 https://github.com/graphql-java/graphql-java/pull/3934 中无需使用 @bbakerman 的 Builder 即可直接转换
  • 出于性能原因，FpKit 现在不再使用流，作者：https://github.com/graphql-java/graphql-java/pull/3932 中的 @bbakerman
  • 通过 https://github.com/graphql-java/graphql-java/pull/3964 中的 @AlexandreCarlton 为 DataFetcherResult 实现 toString/hashCode/equals
  • 引入过滤器和映射命令式方法来替换https://github.com/graphql-java/graphql-java/pull/3931中@bbakerman的.stream()调用
  • 出于性能原因，https://github.com/graphql-java/graphql-java/pull/3930 中的@bbakerman 删除了一些Optional.map() 和.stream()
  • 停止为https://github.com/graphql-java/graphql-java/pull/3929中的@bbakerman为每个对象或列表字段创建NonNullableFieldValidator
