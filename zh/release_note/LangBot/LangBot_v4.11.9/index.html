LangBot v4.11.9

LangBot 是一个开源的 AI 聊天机器人与智能体平台，支持多种即时通讯平台、大语言模型、知识库和插件，帮助你构建、部署和管理 AI 助手。 LangBot 是一个开源 AI 聊天机器人和代理平台，它连接消息传递平台、大型语言模型、知识库和插件，帮助您构建、部署和管理 AI 助手。

LangBot v4.11.9

Box 沙箱现在在 Windows 主机上运行，代理可以按需读取上传的文件并发布他们生成的文件，新安装会将技能和上传保留在数据库中。 本版本让 Box 沙箱可以在 Windows 主机上运行；Agent 可以按需读取上传的文件，并发布自己生成的文件；新安装默认把 Skill 和上传内容保存在数据库中。

Upgrade note / 升级提示：本版本包含新的数据库迁移（0049–0053），升级前请备份 data/ 目录（使用 PostgreSQL 时同时备份数据库）；降级需要用这份备份恢复。已有部署在 config.yaml 中的存储、Skill 和 Box 设置保持不变。This release adds database migrations 0049–0053. Back up data/ (and PostgreSQL, if used) before upgrading; rolling back needs that backup. Existing deployments keep the storage, Skill and Box settings in their config.yaml.

Highlights

  • Windows host Box / Windows 主机沙箱：插件 SDK 0.7.26 让 host 后端支持 Windows：命令优先用 Git Bash 执行，没有时退回 PowerShell，结束时清理整个进程树。注意：host 不做任何隔离（UNSAFE），命令以运行 LangBot 的用户身份直接执行，群聊里不可信的用户可能通过提示词注入执行命令。它不会被自动选中，需要在 config.yaml 里显式设置 box.backend: host，或由 lbctl 原生安装写入（lbctl v0.5.14 起）。在 box.file_transfer_mode: network 下 Skill 无法在 Windows host Box 上执行；LangBot 与 Box 在同一台机器时请使用 legacy（lbctl 会自动写入）。The host backend now works on Windows (Git Bash, falling back to PowerShell; the whole process tree is cleaned up). host has no isolation and runs commands as the LangBot user, so untrusted group-chat users could run commands through prompt injection. It is never auto-selected: set box.backend: host explicitly or let lbctl (v0.5.14+) write it for native installs. Skills cannot run on a Windows host Box in network transfer mode; when LangBot and Box share one machine, use box.file_transfer_mode: legacy (lbctl sets this for you).
  • Files for Agents / Agent 文件：上传的文件保存为带权限的文件资产。Agent 先拿到文件引用，需要时再通过工具按段读取文本、图片或 PDF；Runner 可以把生成的文件发布给指定接收人，运行结束或 Core 重启后仍可下载。知识库文件、插件 SDK 也接入了同一套文件资产。Uploads become authorized file assets: Agents get references and read text, images or PDF pages on demand through tools, and Runners can publish output files that stay downloadable after the run ends or Core restarts. Knowledge-base files and the plugin SDK use the same assets.
  • Database-backed Skills and uploads by default / 新安装默认数据库存储：新安装默认把 Skill（含历史版本）和上传内容存进数据库，Box 默认通过网络传输文件，Core 与 Box 不再需要共享目录。已有部署切换到这种模式时，Core 会在启动、开放 HTTP 之前导入旧的 Skill 和本地文件，可中断恢复，导入完成后不再依赖旧目录。Docker 网络模式的 Box 可以挂载只读的本地数据集。New installs store Skills (with their version history) and uploads in the database, and Box moves files over the network instead of a shared directory. When an existing deployment switches over, Core imports old Skills and local files before serving HTTP, resumably. Docker network-mode Boxes can mount read-only local datasets.
  • Operations API / 操作 API：新增 /api/v1/operations 接口（目录、说明、执行、SSE 流），API Key 也可以确认插件权限，lbctl 等客户端可以用 API Key 确认插件权限。New /api/v1/operations routes (catalog, describe, execute, SSE) and plugin permission confirmation with an API key, so API clients such as lbctl can confirm plugin permissions.
  • WebUI：更新对话框直接显示 langbot.app 上的更新日志；插件详情页显示已安装版本并可直接升级；安装插件后按组件类型提示下一步。The update dialog shows release notes from langbot.app; plugin detail pages show the installed version and offer upgrades; installing a plugin suggests the next step.
  • Startup / 启动：启动时不再自动 pip install 缺失的依赖，而是列出缺少的包并提示重新安装后退出。LangBot no longer pip-installs missing packages at startup; it lists them and exits with reinstall instructions.
  • Fixes / 修复：反复启动失败的插件进程会退避重试，不再刷屏；Telegram 流式编辑忽略 “message is not modified”；MulticaAgent 遇到临时错误会重试，重启期间丢失的回复会补发；企业微信客服给裸 external_userid 发消息时自动解析 open_kfid；LangBot Cloud 上的告警保持需手动开启；E2B 工作区限额生效；插件打包排除虚拟环境目录。Failing plugin workers back off; Telegram streaming ignores “message is not modified”; MulticaAgent retries transient errors and recovers replies lost to restarts; WeCom customer service resolves open_kfid for bare external_userid targets; alerts stay opt-in on LangBot Cloud; E2B workspace limits are enforced; plugin packages exclude virtualenvs.
  • SDK：langbot-plugin 由 0.7.25 固定到 0.7.26。核心引脚 langbot-plugin==0.7.26。

  • 在标记之前，候选程序在新数据目录上安装了两次并运行常规操作：
    • Docker（带有插件运行时和 Box 的 docker compose，从候选提交构建的图像）；
    • uvx（uvx --from <wheel> langbot，来自 PyPI 的依赖项：SDK 0.7.26、SQLAlchemy 2.1.9）。 均通过：账户设置和WebUI； LocalAgent、EssentialCommands、WebSearch、LangRAG 和 HelloPlugin 的市场安装，并进行权限确认、启用/禁用每个管道以及卸载；模型提供者和模型测试；基于 HTTP Bot 的 LocalAgent 管道，包括 Web 搜索工具调用； !help !cmd !func !plugin !version;知识库摄取和检索；创建技能并让代理使用它；重启后数据、插件、知识库和技能完好无损。 Docker 在 Box 沙箱容器中运行命令； uvx 通过 host Box 后端运行了一个。

  • Windows：发布轮在 Windows 11 上与 uvx 一起安装（版本 26300，代码页 936，Python 3.11，安装了 Git Bash；SDK 0.7.26，SQLAlchemy 2.1.9），并通过了与本地模拟模型相同的检查表，包括 8 个同时对话（8/8，无 database is locked）。对于 box.backend: host 和 file_transfer_mode: legacy，代理运行命令 (exec) 并通过 Windows 主机 Box 写入和读回文件。打印中文和表情符号的插件保持运行时连接，并且通过标记器下载阻止了第一个 LocalAgent 对话在 2 秒内回复（没有 count_tokens 超时）。
  • 数据库迁移：由 v4.11.8（修订版 0048）、v4.10.11（0023）和 v4.10.6（0008，工作区之前）创建的数据库在 SQLite 和 PostgreSQL 上都​​升级到此版本。每次升级都达到修订版0053并干净利落地启动两次；没有行丢失，SQLite 完整性和外键检查通过，并且种子提供程序、模型、机器人和管道读回。三个真实 SQLite 数据库的副本（修订版 0042、0040 和 0008，最大 33 MB）也进行了干净升级。升级后的架构与全新安装相匹配，除了 0024 之前启动的数据库上的索引命名差异（v4.11.8 也有这种差异）。
