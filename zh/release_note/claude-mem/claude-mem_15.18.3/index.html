claude-mem v15.18.3

修订 发布时间2026年11月12日 来源thedotmack/claude-mem 英文原文

claude-mem v15.18.3

关键修复

  • Codex 在 claude-mem 更新后继续记录（#6058，感谢 @wiesenthal）。 Codex 批准在插件内附带针对插件整个文件夹的指纹的挂钩。每次 claude-mem 更新都会重写该文件夹，因此每次更新后 Codex 都会关闭所有七个 claude-mem 挂钩（“插件内容已更改；需要挂钩批准”）并且 Codex 会话停止保存，且没有任何消息。安装程序现在在您自己的 ~/.codex/hooks.json 中注册 claude-mem 的 Codex 挂钩，并且每个挂钩运行路径上的 claude-mem 启动程序，该启动程序会自行查找最新的安装。 Codex trust 根据其自己的定义和位置在 hooks.json 中挂钩，因此一次批准现在可以跨更新持续。该文件中的其他工具的挂钩保持不变，第二次安装不会改变任何内容，无法解析的 hooks.json 会被拒绝并保持不变，卸载只会删除 claude-mem 的条目。在 Codex 中关闭 claude-mem 插件仍然会停止捕获。 npx claude-mem doctor 有一个新的 Codex hooks 行，当插件打开但 hooks.json 缺少其挂钩时会发出警告。

    Codex 用户：更新后执行一次。

    1. 运行 npx claude-mem install 并选择 Codex。 npx claude-mem update 和自动更新不会移动钩子，因为旧的安装程序没有保存代理选择。安装程序打印 Registered 7 claude-mem hooks in <codex home>/hooks.json。
    2. 打开交互式 Codex，运行 /hooks，并批准七个 claude-mem 挂钩。 codex exec 无法请求批准，因此请先在交互式 Codex 中执行此操作。

    此后，更新不需要新的批准。仅当 claude-mem 钩子的定义发生更改、claude-mem 添加钩子或删除 claude-mem 之前列出的另一个工具的钩子时，Codex 才会再次询问。

改进

  • 用于工作人员 API 和 MCP HTTP 传输的可选本地 API 令牌（#6056，感谢@kartik70，关闭#5141）。这适用于具有多个操作系统用户的计算机。默认情况下它是关闭的，除非您设置它，否则不会发生任何变化。将 ~/.claude-mem/settings.json 设置为 CLAUDE_MEM_LOCAL_API_TOKEN，然后重新启动工作器和 MCP HTTP 服务器。之后，工作线程 API 和 MCP HTTP 传输会拒绝任何不携带令牌（X-Claude-Mem-Token 或 Authorization: Bearer）的请求，健康检查除外。打开作为 /?token=... 或 /viewer?token=... 的查看器。令牌只能在文件中设置：设置API无法设置或清除它，并且读取时被屏蔽。 omp、hermes 和 openclaw 尚未发送令牌。请参阅配置文档中的“本地 API 令牌”。
  • 配额回退警告指定了两个提供商（#6071，感谢@bulanovk）。当配额回退将内存工作转移到另一个提供程序时，工作日志现在会命名您选择的提供程序和实际执行工作的提供程序，说明替代者何时花费您的 Anthropic 帐户，并命名 CLAUDE_MEM_QUOTA_FALLBACK_PROVIDER=off 将其关闭。默认后备不变。
  • 用于保存和查找记忆的 n8n 工作流程（#6066，感谢@Kirat0201，关闭#5923）。可导入的 n8n 工作流程保存注释，检查工作人员确认保存，然后在所选项目中搜索和检索它。在您运行它之前它处于非活动状态并且不添加自动捕获。设置位于新的 n8n 文档页面中。

修复

  • 智能阅读（感谢@Afloat16）：
    • 同名的 getter 和 setter 现在分开展开 (#6060)。
    • Markdown 标题级别保持书面状态 (#6064)。
    • 即使声明的大小写不同，也能找到 Pascal 例程体 (#6063)。
  • Python 文档字符串保留其语句范围（#6057）。
    • 捕获的源在本机批次中进行解析（#6059）。
  • 观察解析器接受标记分隔符之前的 XML 空格（#6065，感谢 @Afloat16）。
  • Globstar 排除现在也适用于包含行终止符的路径（#6061，感谢@Afloat16）。
  • 成本报告：仅在明确要求时才会查找存储库范围的胜利（#6081），并且识别命名的转向继电器（#6082）（感谢@Kirat0201）。
  • 安装指南列出了真正的 Node.js 和 Bun 最小值（#6076，感谢 @DeryFerd）。

CI 和测试

  • 发布和 ods-native 作业固定 Bun，而不是使用最新版本 (#6075)，并且 CI 现在运行 hook-io 和 spawn-env 检查 (#6074)（感谢 @DeryFerd）。
  • Windows 测试修复：temp-dir 清理重试、每个平台的内存路径以及在 Node 无法运行它们的情况下跳过的暂停管道挂钩案例（#6072、#6073，感谢 @DeryFerd）。同步集线器测试存根已键入，以便包类型检查（#6077，感谢@DeryFerd）。
  • #4689 env-fallback 测试不再依赖于机器上真正的 Claude 登录（#6068，感谢 @bulanovk）。
