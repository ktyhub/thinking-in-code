claude-mem v15.15.1

中断后不会重播

当工作线程宕机或拒绝捕获时，某些捕获路径会保留该工作并稍后再次发送，这可能会启动无人要求的模型调用。他们现在放弃工人拒绝的工作并继续新的工作（#5663）：

  • 转录本捕获： 工作人员拒绝或无法获取的转录本行将被跳过。之前，观察者停在该行，一旦工作人员返回，就将其后面的每一行再次发送。重新启动也不再重新发送中断造成的线路。
  • Cowork： 发送失败的提示、观察或摘要将被丢弃，而不是被假脱机并由稍后的钩子再次发送。只有会话开始、会话结束和子代理停止事件仍会被假脱机处理，并且旧假脱机中留下的提示、观察结果和摘要将在下次刷新时被删除。
  • OpenCode： 工作人员拒绝的会话启动会发送一次，例如观察结果和摘要，而不是在后台重试大约 10 秒。

修复

  • 编辑： Grafana 服务帐户令牌 (glsa_)、Grafana 云令牌 (glc_) 和 Postman API 密钥 (PMAK-) 由工作人员和 Cowork shim 进行编辑。使用 CLAUDE_MEM_REDACT_DISABLED_BUILTINS（grafana_token、postman_key）（#5662，感谢 @kevin9327）按名称关闭其中之一。
  • OpenClaw： <private> 内容在输出被削减到 1,000 个字符之前从工具输出中删除。以前，私有块内的剪切会删除其结束标记，因此存储了私有文本。未闭合的 <private> 标签后面的文本现在也被删除 (#5663)。
  • 状态和医生： claude-mem status 用文字命名每个依赖项，例如“需要观察者数据目录设置”而不是 observer_dir: setup_required，其提示指向 claude-mem doctor 而不是不显示这些的“设置”屏幕。 doctor 显示新工作人员的状态，而不是删除它 (#5661)。
  • 工作状态： Done 和 Dropped 在任何地方以任何字母大小写关闭项目。之前，将所有者目标项目保存为 Done 被拒绝，尽管每个读者都已将其视为已关闭 (#5661)。
  • CCS 对齐： 损坏的排除文件被拒绝，而不是被读取为空，因此排除的观察结果保持排除状态，并且文件不会被覆盖 (#5663)。
  • 查看者： sensitive 类型的观察在会话页面上获得自己的“敏感”过滤器，而不是计入“其他”(#5663)。

也在这个版本中

  • **设置和我的工作：**每个设置、计费、扫描和刷新状态都定义一次并由安装程序、工作人员和页面共享，因此新状态无法通过类型检查，直到每个屏幕都处理它为止（#5661）。
  • 测试： 删除了约 60,000 行测试：仅检查自己的固定装置、重复案例（折叠到表格中）和代理成本报告 Python 测试的四个重复副本的测试。保持回归测试运行生产代码（#5663）。
  • CI: Bun 固定到 1.4.4，安装 ripgrep，运行 Cowork 运行程序和代理成本报告 Python 测试，并将工具密集型套件移至集成通道 (#5663)。
