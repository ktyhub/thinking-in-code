claude-mem v15.18.0

eve 特工获得与 Claude Code 和 Codex 相同的内存

claude-mem/eve 现在通过您的 cmem.ai 帐户为 eve 代理提供完整的 claude-mem 内存循环 (#6042)。

  • 会话上下文： 每个回合都从您记忆中的最近时间线开始。它在一个消息id下每回合都会刷新，因此它会替换自己而不是堆积起来。
  • 回忆每个回合： 与之前一样，在回合之前进行一次搜索。
  • 现在默认开启记录。 每次完成回合后，提供商都会向 cmem.ai 作为平台 eve 发送提示、每个工具调用的一次观察结果以及回合摘要。记录的工具调用和摘要来自您的 cmem.ai 观察员津贴，与您的其他 clients 使用的津贴相同。传递 capture: false 以保留旧的只读行为；会话上下文、回忆、搜索和 remember 继续工作。
    • 在发送任何内容之前，<private>…</private> 区域和秘密形状的文本会在您的部署中删除，其规则与 Cowork 插件使用的规则相同。
    • cmem.ai 会删除同一回合的重播（回合范围的工具调用 ID 和幂等性密钥）。
    • 每个请求发送一次。没有重试、假脱机或队列，因此中断永远不会在以后产生支出。记录失败并记录接受的事件数量。
  • 工具： search、timeline、get_observations（三步智能搜索）和 remember。
  • eve 版本： 在 eve 0.84.0 和 1.0.0-rc.9 上测试。
  • 模板： 适用于免费信用 Vercel AI 网关（克劳德，当克劳德被拒绝免费信用时回退到 openai/gpt-5-mini），或设置 ANTHROPIC_API_KEY 直接呼叫克劳德，并设置 EVE_MODEL 选择确切的模型。预定的运行会获取所有者的记忆，所有者的电子邮件必须完全匹配，并且早晨摘要示例计划会关闭。

文件：https://docs.claude-mem.ai/eve-integration

安装选择移至浏览器

标准安装现在在终端中设置运行时，然后打开本地 Web 设置以选择代理和集成、捆绑技能、模型、本机内存首选项、可选电子邮件更新和遥测 (#5967)。当有人在场时，代理 shell 可以通过 --setup browser，或者通过 --setup defer 为第一次“我的工作”访问留下选择。显式 --provider / --ide 安装和 npx claude-mem update 的行为与以前一样。

也是新的

  • Gemini CLI： 使用 npx claude-mem gemini install|status|uninstall 进行本机生命周期捕获（#5991，感谢@Kirat0201，关闭#5949）。文件：https://docs.claude-mem.ai/gemini-cli/setup
  • 您的 API 提供商的知识语料库（选择加入）： CLAUDE_MEM_CORPUS_AGENT=api 通过选定的 OpenRouter 或 OpenAI 兼容提供商而不是 Claude Agent SDK 回答 query_corpus。默认值保持不变（#5682，感谢@bulanovk）。
  • 代理 SDK： 项目范围内存示例（#5995，感谢 @Kirat0201）。

隐私说明

  • 提示历史记录上传 (#5176)： 浏览器设置在将选定的提示历史记录发送到 cmem.ai 之前进行询问（已在 v15.8.3、#5220 中修复）。 跳过此步骤不发送提示历史记录。所有者目标技能可以使用您现有的编码代理来分析本地历史记录并通过本地工作人员进行保存，而无需单独的 cmem.ai 意图上传。推理仍然使用该代理的模型提供程序。更新不会删除之前发送的数据。

修复

感谢@Afloat16 下面的每一个修复，除非给出另一个名字。

搜索和记忆

  • 长问题中的 Unicode 单词仍然与索引记忆匹配（#5997）；规范等效标题匹配（#5975）；保留 POSIX 文件历史记录中的文字反斜杠（#5985，感谢 @Kirat0201）；仅观察语义端点分页（#5892）。
  • Recall 在重复的项目合并中幸存下来 (#5990)，Chroma 在合并期间保留实时元数据，并引导大型项目而不传播行 ID (#5881、#5862)。
  • 不再合并不同的结构化观察内容（#5979）；冲突的手动会话身份被分开（#5868）。
  • 本机内存注释：引用的元数据被解码（#5983），BOM 前缀的 Markdown 解析（#5976），而 frontmatter 需要一个真正的顶级结束行（#5845）。
  • 多个部分的知识答案保持完整（#6002）。

上下文和服务器

  • 服务器上下文行服从模式过滤器（#5993，感谢@0xABCD01），并在选择先前回复时保留其平台（#6003）；发现使用稳定后缓存标签刷新（#6006）。
  • 服务器保留未链接的手动记忆的平台范围（#5875）、通过事件验证的本机收据身份（#5872）、查看器提要中的事件平台（#5846）以及捕获密钥范围内的突变收据（#5883）。
  • 委托调用键需要读取范围（#5856）；返回之前清除运行中的生成结果（#5858）；抢救的摘要主体显示在查看器中（#5869）。
  • Shutdown 在耗尽连接之前停止接受 HTTP (#5853)。
  • 当捕获被禁用时，观察者保留传递身份（#5867）；当停止的推送被拒绝时，同步会保留发件箱 (#5850)。

导入和设置

  • 导入保留压缩的 Codex 历史 (#6000)、Gemini 文本部分出处和 JSONL 历史编辑 (#5999、#5865)、提示出处中的 Unicode (#5989)、独特的遗留 Claude 提示 (#5982) 和遗留观察文本 (#5854)；复制的 OpenCode 分支活动被排除在外 (#6004)。
  • 历史导入仅限于其起始行（#5877）；本地扫描包括存档的 Codex 历史记录 (#5888)；令牌覆盖忽略了观察者历史和 Codex 上下文估计（#5847、#5886）。
  • 导出包括完整保存的历史记录（#5879）；链接数据目录祖先为媒体工作（#5874）； Claude Code 规则导入转义空间 (#5852)。
  • 遥测公开了第一个会话中的默认共享（#5884）。

我的工作

  • 共享工作同步传递是有限的，因此挂起的线程无法阻止所有者操作（#6014，感谢@LuckVd），并且读者请求有截止日期（#5860，感谢@LuckVd）。
  • 活动发布失败后，会话来源会重新发布（#6010，感谢 @bulanovk）；重试失败的共享活动发布 (#5870)。
  • 所有者目标从新保存中删除不可验证的引用，而不是拒绝整个保存（#5992，感谢@0xABCD01）；仅规则目标快照被重用（#5987）；新的焦点决策在撤消后仍然存在（#5849）。
  • 当本地文件更改时产品刷新 (#5887)，GitHub 产品从 SSH 推送输出链接 (#5998)，有价值的 git push 选项在目标之前解析 (#5885)，单引号提交主题按字面保留 (#5896)。
  • 可交付成果保留先前捕获的副本的声明（#5973）。

整合

  • OpenCode：当前 V2 内置工具合约已标准化，并保留失败的工具状态（#5857、#5855）。
  • OMP：保留本机工具语义和工具调用接收标识，并将挂钩安装到选定的配置文件中（#5871、#5864、#5876）。
  • OpenClaw：接受 JSON5 配置，并使用选定的主机配置和状态路径（#5861、#5844）。
  • Windsurf：用户挂钩命令在安装后仍然有效，并且保留 MCP 服务器身份以进行递归过滤（#5882、#5880）。
  • 光标：MCP 参数和结果 JSON 信封被解码 (#5848)。 DSH：托管脚本路径在重新安装时刷新 (#5873)。 T3 代码：在删除之前读取 TOML 插件状态 (#5851)。
  • 智能文件读取包括 C 和 C++ 标头声明、紧凑的 Java 记录构造函数和 TypeScript declare function（#6015、#6012、#6005）； XML 文字保留其结束标记 (#5977)。

编辑和性能

  • Pulumi 访问令牌和 Doppler 个人令牌经过编辑（#5984，感谢 @kevin9327）。
  • 遥测在到达时聚合事件统计信息 (#5994)，长转录行在导入时组装一次 (#5981)，OpenCode 令牌使用进行流式传输 (#5974)，查看器中的旧提示重试查找受时间限制 (#6011)。

文档

  • 代理框架指南被分组，并且删除了不存在的设置（#6030）。
  • 代币声明以每个结果的大小比率表示（#5889，感谢@Zhong-fan，#4138）。
