claude-mem v16.0.0

大版本 发布时间2026年11月18日 来源thedotmack/claude-mem 英文原文

claude-mem v16.0.0

我的工作将您的需要放在第一位

我的工作是显示代理正在做什么的页面，是根据完整的 UI 审核重建的（#6210、#6304）。您需要的内容位于顶部，长列表可以折叠，每个页面都可以在手机上通过键盘和屏幕阅读器查看。

  • 您的需求是第一位的。 在主页上，等待您的第一个请求位于顶部，屏幕上有一个橙色按钮。请求是单行的；闲置和已发货均折叠成一排，并附有计数。
  • 页面较短。 在实际安装中：主页高度约为 2,600 像素，而不是 5,138；列表打开时有 5 行，而不是 195 行；我的规则大约是 4,400 像素，而不是超过 17,000 像素。
  • 在您阅读的位置进行回复。 在每种状态下，请求的抽屉都会将回复框放在其进度线的正下方。当回复正在途中时，“在此处回复”会等待，因此消息永远不会作为第二次付费轮流进入第二个对话。
  • 焦点区域的页面从上到下阅读：需要您什么，询问尚未开始，然后是董事会。保存失败会显示哪个更改失败，并仅在该屏幕上提供“重试”选项。过去的焦点显示某个区域被标记为完成的日期。
  • 我的规则：一次决定一项规则，一个橙色批准。在手机上，滑动即可决定。
  • 适合手机。 在 390 像素手机上，每个页面的宽度均为 390 像素，底部栏用于显示“我的工作”、“焦点”和“我的规则”。
  • 键盘和屏幕阅读器。 每个控件都有一个名称；从选项卡打开工具提示；对话框、抽屉、“关闭”或“重试”后，焦点会回到原来的位置；触摸时控件为 44px。
  • 加载前的主题。 您的浅色或深色选择是在第一帧之前绘制的，包括加载和错误屏幕。
  • 简单错误。 失败是您语言中的一句话，原始原因折叠在“详细信息”下。没有任何事情会自行重试。
  • 您的语言和时钟。 时间以您的语言显示记录时间（法语为 24 小时制），另一年的一天显示该年份。新字符串被翻译成法语、韩语、土耳其语和中文；欢迎母语人士指正。
  • 减少运动。 实时更新最多移动两件事，并且在减少运动的情况下没有任何移动。

观察电视被移除

  • 电视页面及其只读远程访问从开源工作者那里消失了 (#6295)：/tv、tv.html 和 CLAUDE_MEM_TV_TOKEN 设置。经典查看器和“我的作品”保持不变。
  • 如果您从另一台机器观看电视： 设置 CLAUDE_MEM_LOCAL_API_TOKEN（现在可以保护网络访问），并删除 CLAUDE_MEM_TV_TOKEN。在此之前，仍然找到具有非环回 CLAUDE_MEM_WORKER_HOST 且没有本地 API 令牌的 TV 令牌的工作线程会绑定到 127.0.0.1（对于 IPv6 主机为 ::1）并记录 SECURITY 错误，因此在没有令牌的情况下，完整的 API 永远不会向网络开放。
  • 框架保护现在覆盖了工作人员服务的每个页面。

已在 15.20.0 和 15.21.0 中发货

您在 15.20.0 中收到了相同评论的其余部分：

  • **设置：**步骤栏、返回每个屏幕、简单错误和停止导入 (#6233)。
  • 经典查看器： 一个标题行，一个可搜索的项目选择器，“在此会话中查找”，并且在长时间线末尾没有 React 错误 185 (#6229)。
  • 从 Mem0 和超级内存导入： 接受修复 (#6206)。
  • 修复： Codex Desktop 会话在 macOS 上实时读取（#6285，感谢 @MaxWang007），并且当 settings.json 不是有效的 JSON 时工作器启动（#6259）。 接下来是 15.21.0：代码模式以启用 claude-mem 的方式启动 (#6278)，自动清除恢复并显示继续提示 (#6294)，VS Code 中的 Hermes Desktop 和 GitHub Copilot 通过 MCP 连接 (#6284、#6286)，当提示历史记录对于一次上传来说太大时，设置完成 (#6280)。 完整注释：15.20.0 和 15.21.0。

也是新的

  • SessionStart 横幅是 Claude Code 终端中的一张卡片 (#6274)。在 Claude Code 2.1.326 或更高版本上，规则 + 工具行、“以前”和时间线绘制为一张框架卡。镜像到 Claude 应用程序的会话在横幅的每一行前面显示一行，而不是挂钩的名称。

修复

  • 工作人员在处理积压工作时不断回答。 健康检查、挂钩和查看器不再等待：
    • hook spool backlog：drain 并行读取 64 个批次的文件（#6260，感谢 @Zhong-fan），并在不阻塞的情况下删除和声明它们（#6296，来自 @Afloat16 的 #6254）； @soarkit 在 #6247 中报道；
    • 工作进程启动时的项目列表，它读取每一行，现在读取项目索引（#6270；@soarkit 在#6246 中报告）；
    • Claude CLI 检查语料库素数和查询是否在缓存未命中时运行（#6256，感谢 @Afloat16；@soarkit 在 #6250 中报告）；
    • Chroma 同步的检查点，为每行重写（2,000 行约 28 MB 的写入），现在每 250 毫秒写入一次（#6204，感谢 @Zhong-fan；@soarkit 在 #6203 中报告）。
  • 文件夹 CLAUDE.md 文件： 更新一次最多获取 8 个文件夹，而不是一个接一个（#6264；@soarkit 在 #6248 中报告），claude-mem generate 读取项目的观察一次，而不是每个文件夹一次（#6265；@soarkit 在 #6249 中报告），失败的文件夹更新将与其文件夹一起记录，并通过该文件夹的下一个观察再次尝试（#6208，感谢@0xABCD01）。
  • 长 Bash 输出保留其结尾（#6292；@micronox 在#6282 中报告）。当 Claude Code 剪切大约 30,000 个字符的输出并将全文保存到文件中时，内存仅从头开始，因此最后几行（测试摘要、最终错误）丢失了。 claude-mem 现在读取该文件的末尾。
  • 本机内存注释： 标题顶部带有 type: 的注释保留其类别（#6244），并且当记录的第一个提示很长时找到注释的项目（#6272），感谢@Afloat16。
  • 最近的会议包括采用的工作树（#6268，感谢@Afloat16）。将工作树合并到其父级后，OpenClaw 的 claude-mem-recent 没有显示以前的会话。
  • 搜索： 语料库证据中可以找到较长的无间隔单词内的中文和日文术语（#6213，感谢@liuyinchu）。 smart_outline、smart_search 和 smart_unfold 查找通过赋值定义的 JavaScript 函数，例如 exports.read = function … (#6245)，并且每个 Java 方法重载都会自行展开 (#6257)，感谢 @Afloat16。
  • **更安静的错误报告：**超过 120 秒读取器截止时间的上下文读取会命名慢速读取并记录警告，而不是错误 (#6255)，并且在 Windows 上，Windows 保持锁定的假脱机条目会收到一个警告，而不是每次排水时都收到错误报告 (#6269)。
  • 现在记录了两个被删除的失败 (#6302)：当自动清除无法向 Claude 提交保存工作状态的请求时，自动清除会在记录中如此说明，并且服务器会记录 /v1/info 无法读取矢量搜索状态的原因。
  • **土耳其语：**更清晰的“我的工作”措辞和最新的土耳其语自述文件（#6287，感谢@alkank）。

对于贡献者

  • 需要 bash 4 的提交消息测试在 macOS 的 bash 3.2 上被跳过，但仍然在 Linux CI 上运行 (#6297)。
