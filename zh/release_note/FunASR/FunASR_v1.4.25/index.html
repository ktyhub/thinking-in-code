最终出版接受

  • funasr-1.4.25.tar.gz：1083745 字节； SHA-256 1ff96e278b7bf6823da0afa9290a12a84a0e641d31dd63fddaafd82a56000c80。

FunASR 1.4.25

来源：455ad37cc03bd01e85740caf64788ee4cf8ebe2c /标签v1.4.25。

修复

  • #3863：Python 3.12-compatible 布尔参数解析无需 distutils，保留规范化的无效值消息和布尔返回类型。
  • #3866：从拉丁句子时间戳输出中删除合成前导空格，同时保留时间边界、原始文本和 VAD 对齐。

此根轮不发布 #3865 中的独立 funasr-onnx 运行时修复。不包括 Open SenseVoice #3861 和 VAD #3862 更改。

验证范围

  • 更正了 #3863 头：实际的 Python 3.10/3.12 托管工件每个都有 53 个通过测试，包括 23 个布尔解析器合约。更正了 #3866 头：实际的 NumPy 1.26.4/2.4.0 工件每个都有 421 个通道和 27 个仅 CUDA 的跳过。旧的失败运行将被保留，而不是重新运行。
  • 合并源：两个 CI 选择的联合 468 次通过和 33 次跳过。早期的私有运行缺少一个 pytorch_wpe 子进程导入（467 次）；仅进程的私有依赖路径在不更改产品源或断言的情况下纠正了它。
  • 候选版本/文档检查：{‘contract-green-v3’：{‘testcase’：49，‘failure’：0，‘error’：0，‘skipped’：0}，‘static-remainder’：{‘testcase’：104，‘failure’：0，‘error’：0，‘skipped’：2}， ‘已安装行为候选’：{‘testcase’：54，‘失败’：0，‘错误’：0，‘跳过’：0}}。实际安装的候选轮和最终轮运行解析器、时间戳和模拟的 VAD 集成；最终计数：{‘testcase’：54，‘failure’：0，‘error’：0，‘skipped’：0}。所有 439 个包文件和 13 个入口点均与接受的源匹配。
  • 根模型/GPU 运行时字节与 1.4.24 相比没有变化，并且仍受其接受的 L20Z 证据的约束。没有声称新的 GPU 执行、预训练的 ASR 质量、全套或 Nano 结果。先前的存储库范围的离线尝试在在线模型查找和超时时仍然不完整。
  • 头、合并主和最终标签托管 CI 和实际结帐树分别接受。最终的 Python 轮和 sdist 是新下载的，并检查元数据、确切的源字节、存档完整性、严格的 Twine、私人离线安装和 CLI 行为。
  • 十个未更改的运行时存档重用完整的缓存字节，并通过存档完整性检查针对新资产和原始运行时版本重新进行了重新哈希。它们没有被重建或重新执行。 SHA256SUMS 涵盖所有 12 个有效负载。
  • 1.4.24 警告仍然适用：使用norm_means=True 和norm_vars=True 训练的检查点需要重新评估识别质量。 norm_vars=False 仍然是默认值。
  • 无生产升级或采用/增长声明。

发生了什么变化

  • 修复（onnx）：在 https://github.com/modelscope/FunASR/pull/3865 中使用 librosa 而不是 @tanishqbaweja 的 pydub 加载非 .wav 音频路径
  • 修复（utils）：通过 https://github.com/modelscope/FunASR/pull/3863 中的 @GPT-AGI 删除 distutils 布尔解析器
  • 修复：删除 https://github.com/modelscope/FunASR/pull/3866 中 @GPT-AGI 拉丁语句子时间戳上的前导空格
  • 由 @LauraGPT 在 https://github.com/modelscope/FunASR/pull/3875 中发布 FunASR 1.4.25

运行时下载

此 Python 版本与当前预构建的 llama.cpp / GGUF 运行时版本配对：runtime-llamacpp-v0.2.6。
