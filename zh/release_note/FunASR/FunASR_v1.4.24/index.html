最终出版接受

GitHub 版本和 PyPI 1.4.24 均已发布。两个发行版都是从官方 PyPI 下载的，并通过 SHA-256 和大小与接受的 GitHub 资产相匹配：

  • funasr-1.4.24-py3-none-any.whl：1015161字节； SHA-256 c2678ebb77c7dfba1d85a79749ad30b441159b87d17eff901e0c6ad4ebcc06c7。

官方 sdist 下载在传输超时后使用精确的 HTTP 206 范围恢复；原始部分收据和故障收据均被保留。轮子没有再次下载，PyPI 也没有重新上传。

FunASR 1.4.24

来源：20f26b7c4905d010768ec91206149df2a90104b6 /标签v1.4.24。

修复

交付#3852：忽略空的非语言符号，而不是允许字符/音素标记器扫描停止。交付#3853：填充话语的正确方差归一化。交付#3854：当批次混合具有零和非零火灾的话语（包括动态 ONNX 批次）时，保留有效的 CIF 输出和梯度。

兼容性：使用 norm_means=True 和 norm_vars=True 训练的检查点需要在校正归一化后重新评估识别质量。 norm_vars=False 仍为默认值。本地检查点往返不是预训练的识别质量评估。

这并不要求预先训练的 ASR 质量、Windows/NPU 接受度或完整的存储库套件结果。

分别发布的funasr-onnx==0.4.9和funasr-torch==0.1.6有自己的标签、封装和验证。此根包版本不会重新发布它们。 PR #3848 不包括在内。此版本并未声称每个 EOS 路径都是固定的。

验证范围

  • 新候选版本/自述文件检查：45 个案例，0 个跳过。相关文档/包/发布检查：104个案例，2个明确记录的跳过；没有失败或错误。
  • 实际安装的候选轮和最终轮：37 个通过的 CPU/ONNX 案例，每个案例涵盖分词器符号、方差标准化、本地检查点往返、存储库音频推理和 CIF 动态批次。 27 个 CUDA 参数化在本地有意跳过，并由绑定的先前硬件证据单独覆盖。所有 439 个包文件和 13 个入口点均与接受的源匹配。
  • 在重新散列 33,870 个密封证据文件和 18 个帮助程序并将确切源绑定到已安装的轮子之后，重新使用了 24 个 tokenizer/CTC 案例、34 个 FP32 CIF 案例和 4 个标准化器存储库音频案例，包括 L20Z 上的 6 个 CUDA 推理调用。 106 个案例标准化器验收保留了 102 个未更改案例和 4 个修复后的音频检查。早期线束/TF32 夹具故障仍然保留；它们不会被默默地丢弃或算作通过。此版本没有执行新的 GPU 执行，也没有预训练质量或完整 Paraformer 导出声明。
  • 本地候选构建和候选/最终包检查、测试和安装使用私有 HOME/缓存目录和单独的网络命名空间以及经过验证的网络无法访问的探测器。最终标签构建在现有发布工作流程下的 GitHub Actions 中运行，而不是本地网络命名空间。不使用新下载的预训练权重。单独报告的 #3848 测试下载事件不是此版本的授权或验证输入。
  • 从实际日志和记录的工件清单中接受发布头 CI。路线图工作检查了纯粹的头脑；其他头工作流程使用 GitHub 的临时 PR 合并提交。两个结帐树都针对确切的候选者进行了验证。合并主标签和最终标签源签出分别进行了验证。主要的API-doc工作流程还仅将保留的中文API页面从gh-pages检出到previous-pages；这个单独的文档输入被记录下来，不被视为推理源。新下载的Python Wheel/sdist通过了字节/元数据/存档/源检查、严格的Twine、离线安装、实际导入和CLI检查。
  • 10 个未更改的运行时存档重用针对新资产元数据和现有运行时源版本新鲜散列的完整缓存字节。它们没有被重建或重新执行。 SHA256SUMS 涵盖所有 12 个有效负载。这不是一个新的运行时硬件声明。
  • 没有提出完整的存储库套件、生产环境升级、Nano 基准或采用/增长声明。
