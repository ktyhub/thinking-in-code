修复

交付 #3841：传递给 generate() 的 merge_length_s 优先于构造时间/默认合并长度。交付#3833：使用当前语音段持续​​时间（而不是累积的块时间）每帧评估动态静音调度；固定阈值选择退出仍然可用。

这并不要求预先训练的 ASR 质量、Windows/NPU 接受度或完整的存储库套件结果。

单独发布的funasr-onnx==0.4.8和funasr-torch==0.1.6有自己的标签、封装和验证。此根包版本不会重新发布它们。此版本未修复单独复制的 no-LFR 前端异常。

验证范围

  • 新候选版本/自述文件检查：45 个案例，0 个跳过。相关文档/包/发布检查：104个案例，2个明确记录的跳过；没有失败或错误。
  • 实际安装的候选轮：9 个 CPU 单元合同，涵盖每次调用/构造/默认合并长度和动态/固定 VAD 调度。他们模拟的边界不是硬件推理。所有 439 个包文件和 13 个入口点均与接受的源匹配。
  • 在重新整理密封的原始收据并将确切的来源绑定到已安装的轮子后，重新使用了 #3841/#3833 中的 32 个 AutoModel 和 24 VAD 真实 L20Z FP32 分析集成案例。他们各自之前的运行总共记录了 216521 个 CUDA 事件。这不是新的 GPU 执行、BF16 运行或预训练质量验证。
  • 准确的发布头和合并主 CI 被实际日志/工件接受。最终标签工作流程和新下载的 Python Wheel/sdist 通过了字节/元数据/存档/源检查、严格的 Twine、离线安装、实际导入和 CLI 检查。
  • 10 个未更改的运行时存档重用针对新资产元数据和现有运行时源版本新鲜散列的完整缓存字节。它们没有被重建或重新执行。 SHA256SUMS 涵盖所有 12 个有效负载。这不是一个新的运行时硬件声明。
  • 没有提出完整的存储库套件、生产环境升级、Nano 基准或采用/增长声明。
