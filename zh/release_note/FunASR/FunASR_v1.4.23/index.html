FunASR 1.4.23

来源：efe5504e388613e5298e1f93d5ca9f861700b489 /标签v1.4.23。

修复

交付#3849：使用 lfr_m=lfr_n=1 初始化在线前端的有效帧光标，并避免冗余的空最终离线 VAD 块以获得精确的输入倍数。交付 #3783：在文本转换之前提供的 token_list ID 映射到模型件。使用提供的词汇表，SentencePiece ids2tokens 返回 list[str] 片段；使用 tokens2text 作为文本。如果没有提供词汇表，旧的解码文本行为将被保留。

这并不要求预先训练的 ASR 质量、Windows/NPU 接受度或完整的存储库套件结果。

分别发布的funasr-onnx==0.4.9和funasr-torch==0.1.6有自己的标签、封装和验证。此根包版本不会重新发布它们。 PR #3848 不包括在内。显式的流空输入和产生零特征的非空尾部超出了 #3849 硬件接受范围；此版本并不声称每个 EOS 路径都是固定的。

验证范围

  • 新候选版本/自述文件检查：45 个案例，0 个跳过。相关文档/包/发布检查：104个案例，2个明确记录的跳过；没有失败或错误。
  • 实际安装的候选轮和最终轮：61 个 CPU 合约，每个合约涵盖无 LFR 特征/块处理、分析 VAD 最终确定和分词器词汇语义。本地微小的 SentencePiece 和受控声学装置不是预训练的质量或硬件推理。所有 439 个包文件和 13 个入口点均与接受的源匹配。
  • 在重新哈希密封的原始收据并将确切的来源绑定到已安装的轮子后，重新使用了 #3849/#3783 中的 16 个直接 FP32/BF16 前端案例、12 个 FP32 VAD 案例和 12 个 FP32/BF16 标记器/解码器案例。早期前端运行的 6 个失败的 VAD 案例仍然被记录；后来更正的 VAD 运行通过了全部 12 项。此版本没有执行新的 GPU 执行，也没有提出预训练质量声明。
  • 本地候选构建和候选/最终包检查、测试和安装使用私有 HOME/缓存目录和单独的网络命名空间以及经过验证的网络无法访问的探测器。最终标签构建在现有发布工作流程下的 GitHub Actions 中运行，而不是本地网络命名空间。不使用新下载的预训练权重。单独报告的 #3848 测试下载事件不是此版本的授权或验证输入。
  • 从实际日志中接受准确的发布头和合并主 CI，并记录工件清单。最终标签工作流程和新下载的 Python Wheel/sdist 通过了字节/元数据/存档/源检查、严格的 Twine、离线安装、实际导入和 CLI 检查。
  • 10 个未更改的运行时存档重用针对新资产元数据和现有运行时源版本新鲜散列的完整缓存字节。它们没有被重建或重新执行。 SHA256SUMS 涵盖所有 12 个有效负载。这不是一个新的运行时硬件声明。
  • 没有提出完整的存储库套件、生产环境升级、Nano 基准或采用/增长声明。
