daily_stock_analysis v3.6.0

小版本 发布时间2026年3月14日 来源ZhuLinsen/daily_stock_analysis 英文原文

daily_stock_analysis v3.6.0

添加

  • 🗑️ 历史批量删除 — Web UI 现在支持分析历史的多选和批量删除；添加了 POST /api/v1/history/batch-delete 端点和 ConfirmDialog 组件。
  • 🔐 身份验证设置 API — 新的 POST /api/v1/auth/settings 端点，用于在运行时启用或禁用 Web 身份验证，并在需要时设置初始管理员密码
  • openclaw Skill 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ LLM 通道协议/测试 UX — .env 和 Web 设置现在共享相同的通道形状 (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED)；设置页面添加了每通道连接测试、主要/后备/视觉模型选择和协议感知模型前缀
  • 🤖 代理架构阶段 0+1 — 共享协议（AgentContext、AgentOpinion、StageResult）、提取的 run_agent_loop() 运行程序、AGENT_ARCH 交换机（single/multi）、配置注册表项
  • 🔍 Bot NL 路由 — 两层自然语言路由：廉价的正则表达式预过滤器（股票代码+金融关键字）→ 轻量级 LLM 意图解析；由AGENT_NL_ROUTING=true控制；支持多股票和策略提取
  • 💬 /ask 多股票分析 — 逗号或 vs 分隔代码（最多 5 个），并行线程执行 150 秒超时（保留部分结果），Markdown 比较摘要表位于顶部
  • 📋 /history 命令 — 通过 {platform}_{user_id}:{scope} 格式进行每个用户会话隔离（冒号分隔符防止前缀冲突）；列出 /chat 和 /ask 会话；查看详细信息或清晰
  • 📊 /strategies 命令 — 列出可用的策略 YAML 文件，按类别（趋势/形态/头部/框架）分组，并具有 ✅/⬜ 激活状态
  • 🔧 回测总结工具 — get_strategy_backtest_summary 和 get_stock_backtest_summary 注册为只读代理工具
  • ⚙️ 代理自动检测 — is_agent_available() 从 LITELLM_MODEL 自动检测；显式 AGENT_MODE=true/false 具有完全优先权
  • 🏗️ 多代理协调器（第 2 阶段） — AgentOrchestrator 具有 4 种模式 (quick/standard/full/strategy)；通过 AGENT_ARCH=multi 直接替代 AgentExecutor； BaseAgent ABC 具有工具子集过滤、缓存数据注入和结构化 AgentOpinion 输出
  • 🧩 专业代理（第 2-4 阶段） — TechnicalAgent（8 种工具，趋势/MA/MACD/交易量/模式分析）、IntelAgent（新闻与情绪、风险标志传播）、DecisionAgent（综合到决策仪表板 JSON）、RiskAgent（7 个风险类别、具有软/硬覆盖的两级严重性）
  • 📈 策略系统（第3阶段） - StrategyAgent（来自YAML技能的每个策略评估），StrategyRouter（基于规则的机制检测→策略选择），StrategyAggregator（带有回测性能因素的加权共识）
  • 🔬 深度研究代理（第 5 阶段） — 采用 3 阶段方法的 ResearchAgent（分解 → 研究子问题 → 综合报告）；代币预算跟踪；带别名的新 /research 机器人命令（/深研、/deepsearch）
  • 🧠 内存和校准（第 6 阶段） — AgentMemory 具有预测精度跟踪、置信度校准（在最小样本阈值后激活）、基于历史获胜率的策略自动加权
  • 📊 投资组合代理（第 7 阶段） — PortfolioAgent 用于多股票投资组合分析（头寸规模、行业集中度、相关风险、跨市场联动、再平衡建议）
  • 🔔 事件驱动警报（第 7 阶段） — EventMonitor 与 PriceAlert、VolumeAlert、SentimentAlert 规则；异步检查、回调通知、可序列化持久性
  • ⚙️ 新配置条目 — AGENT_ORCHESTRATOR_MODE、AGENT_RISK_OVERRIDE、AGENT_DEEP_RESEARCH_BUDGET、AGENT_MEMORY_ENABLED、AGENT_STRATEGY_AUTOWEIGHT、AGENT_STRATEGY_ROUTING — 全部在 config.py + config_registry.py 中注册（WebUI 可配置）

已更改

  • 🔐 身份验证密码状态语义 — 现在可以独立于身份验证启用来跟踪存储的密码是否存在；禁用身份验证时，/api/v1/auth/status 返回 passwordSet=false，同时保留保存的密码以供将来重新启用
  • 🔐 身份验证设置重新启用强化 - 使用存储的密码重新启用身份验证现在需要 currentPassword，并且失败的会话创建会回滚身份验证切换以避免锁定
  • ♻️ AgentExecutor 重构 — _run_loop 委托给共享 runner.run_agent_loop()；删除重复的序列化/解析/思考标签代码
  • ♻️ 统一代理切换 — Bot、API 和 Pipeline 均使用 config.is_agent_available()，而不是发散的 config.agent_mode 检查
  • 📖 README.md — 扩展了 Bot 命令部分（询问/聊天/策略/历史记录），添加了 NL 路由注释，更新了代理模式描述
  • 📖 .env.example — 添加了 AGENT_ARCH 和 AGENT_NL_ROUTING 配置文档

已修复

  • 🐛 Windows 上的会话秘密轮换 — 使用原子替换，因此即使 .session_secret 已经存在，身份验证切换也会使现有会话无效
  • 🐛 身份验证切换原子性 — 在旋转会话密钥之前保留 ADMIN_AUTH_ENABLED；轮换失败时，回滚到之前的身份验证状态
  • 🔧 LLM runtime selection guardrails — YAML 模式下渠道编辑器不再覆盖 LITELLM_MODEL / fallback / Vision；系统配置校验补上全部渠道禁用后的运行时来源检查，并修复 vertexai/... 这类协议别名模型被重复加前缀的问题
  • 🐛 多股票 /ask 后续回归 — 投资组合叠加现在与每只股票阶段共享相同的超时预算，并在超时时跳​​过，而不是阻止机器人回复； /history 现在存储可读的每只股票摘要，而不是原始仪表板 JSON；压缩的多股票输出现在呈现数字 sniper_points 值
  • 🐛 决策仪表板枚举兼容性 — 多代理 DecisionAgent 现在将 decision_type 保留在旧版 buy|hold|sell 合约中，并在风险覆盖、管道转换和下游统计/汇总之前标准化杂散 strong_* 输出
  • 🛟 多代理部分结果回退 — IntelAgent 现在缓存解析的英特尔以供下游重用，共享 JSON 解析可以容忍轻微畸形的模型输出，编排器在超时或中间管道解析失败时保留/合成最小的仪表板，而不是总是崩溃到 50/观望/未知
  • 🐛 恢复共享 LiteLLM 路由 - bot NL 意图解析和 ResearchAgent 规划/综合现在重用相同的 LiteLLM 适配器/路由器/回退/api_base 注入路径作为主要代理流程，因此 LLM_CHANNELS / LITELLM_CONFIG / OpenAI 兼容部署的行为一致
  • 🐛 机器人聊天会话向后兼容性 — 当旧历史记录已存在时，/chat 现在继续使用旧版 {platform}_{user_id} 会话 ID，并且 /history 仍然可以列出/查看/清除这些预迁移会话以及新的 {platform}_{user_id}:chat 格式
  • 🐛 EventMonitor 不支持的规则拒绝 — 配置验证/运行时加载现在拒绝或跳过监视器无法实际评估的警报类型，因此计划模式不再默默地接受永久无操作规则
  • 🐛 P0 基本面聚合稳定性修复 (#614) — 修复 get_stock_info 板块语义回归（新增 belong_boards 并保留 boards 兼容别名）、引入基本面上下文精简返回以控制 token、为基本面缓存增加最大条目淘汰，并补齐 ETF 总体状态聚合与 NaN 板块字段过滤，保证 fail-open 与最小入侵。
  • 🔧 GitHub Actions 搜索引擎环境变量补充 — 工作流新增 MINIMAX_API_KEYS、BRAVE_API_KEYS、SEARXNG_BASE_URLS 环境变量映射，使 GitHub Actions 用户可配置 MiniMax、Brave、SearXNG 搜索服务（此前 v3.5.0 已添加 provider 实现但缺少工作流配置）
  • 🤖 多代理运行时一致性 — AGENT_MAX_STEPS 现在传播到每个编排的子代理；增加了 AGENT_ORCHESTRATOR_TIMEOUT_S 合作预算，以在管道进一步级联之前停止超长管道
  • 🔌 多代理功能连接 — AGENT_RISK_OVERRIDE 现在根据硬风险发现主动降级最终仪表板； AGENT_MEMORY_ENABLED现在将最近的分析内存+置信度校准注入到专门代理中；多股票 /ask 现在运行 PortfolioAgent 以添加投资组合级别的配置和集中指导
  • 🔔 EventMonitor 运行时接线 — 计划模式现在可以从 AGENT_EVENT_ALERT_RULES_JSON 加载警报规则，在 AGENT_EVENT_MONITOR_INTERVAL_MINUTES 轮询它们，并通过现有通知服务发送触发的警报
  • 🛠️ 后续稳定性修复 — 当仪表板 JSON 解析失败时，多库存 /ask 现在回退到可用文本输出； EventMonitor 跳过语义上无效的规则，而不是中止计划启动；后台警报轮询现在独立于主计划分析循环运行
  • 🧪 多代理回归覆盖 — 添加了针对 run()、chat()、关键阶段故障、优雅降级和超时处理的协调器执行测试
  • 🧹 PortfolioAgent 清理 — post_process() 现在重用共享的 JSON 解析并删除陈旧的未使用的导入
  • 🚦 机器人异步调度 — CommandDispatcher 现在公开 dispatch_async()； NL意图解析和默认命令执行从事件循环中卸载，钉钉流直接等待异步处理程序，飞书流处理从SDK回调线程中移出
  • 🌐 异步 webhook 处理程序 — bot/handler.py 中的新 handle_webhook_async() 函数，用于异步上下文（例如 FastAPI）；直接调用dispatch_async()，无需线程桥接
  • 🧵 飞书流 ThreadPoolExecutor — 将无限的每条消息 Thread 生成替换为有上限的 ThreadPoolExecutor(max_workers=8)，以防止消息爆发时线程爆炸
  • 🔒 EventMonitor 安全性 — _check_volume() 现在可以安全地处理返回 None 的 get_daily_data（没有元组解包崩溃）； on_trigger 回调通过 asyncio.to_thread/await 支持同步和异步可调用
  • 🧹 ResearchAgent 重复数据删除 — _filtered_registry() 现在委托给 BaseAgent._filtered_registry()，而不是重复过滤逻辑
  • 🧹 机器人尾随空白清理 — 删除了 bot/handler.py、bot/dispatcher.py、bot/commands/base.py、bot/platforms/feishu_stream.py、bot/platforms/dingtalk_stream.py 上的 W291/W293 空白问题
  • 🐛 调度程序 _parse_intent_via_llm 安全 — 将易碎的 'raw' in dir() 替换为 'raw' in locals()，以实现 JSONDecodeError 处理程序中未定义变量的保护
  • 🐛 筹码结构 LLM 未填写时兜底补全 (#589) — DeepSeek 等模型未正确填写 chip_structure 时，自动用数据源已获取的筹码数据补全，保证各模型展示一致；普通分析与 Agent 模式均生效
  • 🐛 历史报告狙击点位显示原始文本 (#452) — 历史详情页现优先展示 raw_result.dashboard.battle_plan.sniper_points 中的原始字符串，避免 analysis_history 数值列把区间、说明文字或复杂点位压缩成单个数字；保留原有数值列作为回退
  • 🐛 会话前缀冲突 — 用户 ID 123 可以通过 startswith 看到用户 1234 的会话；修复了 session_id 格式中的冒号分隔符
  • 🐛 NL 预过滤误报 — re.IGNORECASE 导致 [A-Z]{2,5} 匹配常见的英语单词，如“hello”；删除了全局标志，仅对英语金融关键字使用内联 (?i:...)
  • 🐛 策略参数中的点状代码 — _get_strategy_args() 无法将 BRK.B 识别为股票代码，将其保留在策略文本中；现在接受 TICKER.CLASS 格式
  • ⏱️ efinance 长调用挂起修复 (#660) — 为所有 efinance API 调用引入 _ef_call_with_timeout() 包装（默认 30 秒，可通过 EFINANCE_CALL_TIMEOUT 配置）；使用 executor.shutdown(wait=False) 确保超时后不再阻塞主线程，彻底消除 81 分钟挂起问题
  • 🛡️ 类型安全内容完整性检查 (#660) — check_content_integrity() 现在将非字符串类型的 operation_advice / analysis_summary 视为缺失字段，避免下游 get_emoji() 因 dict.strip() 崩溃
  • 📄 报告保存与通知解耦 (#660) — _save_local_report() 不再依赖 send_notification 标志触发，--no-notify 模式下本地报告照常保存
  • 🔄 operation_advice 字典归一化 (#660) — Pipeline 和 BacktestEngine 现在将 LLM 返回的 dict 格式 operation_advice 通过 decision_type（不区分大小写）映射为标准字符串，防止因模型输出格式变化导致崩溃
  • 🛡️ runner.py usage None 防护 (#660) — response.usage 为 None 时不再抛出 AttributeError，回退为 0 token 计数
  • 📋 orchestrator 静默失败改为日志警告 (#660) — IntelAgent / RiskAgent 阶段失败现在记录 WARNING 而非静默跳过，便于诊断
