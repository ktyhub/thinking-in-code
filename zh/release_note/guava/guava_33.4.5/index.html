guava v33.4.5

使用番石榴 33.4.8，而不是番石榴 33.4.5。 33.4.5 是我们第一次尝试模块化 Guava，但我们错误配置了我们的构建，因此：

  • 包含每个类别的额外副本
  • 不声明其对注释工件的依赖关系

33.4.5（和 33.4.6）还可能导致某些优化器出现问题（如 Android 应用程序常用的优化器），以及 33.4.7 破坏 minSdkVersion 低于 26 的 Android 应用程序的构建。

所有这些问题均已在 33.4.8 版本中得到解决。抱歉给您带来麻烦了。

当您阅读 33.4.8 的 release note 时，您还应该阅读 Guava 33.4.1 的 release note，即使您不是从 Guava 33.4.0 或更早版本升级：这些 release note 包含有关 Guava 33.4.5 及更高版本对模块的影响的信息系统。

Maven

<dependency>
  <groupId>com.google.guava</groupId>
  <artifactId>guava</artifactId>
  <version>33.4.5-jre</version>
  <!-- or, for Android: -->
  <version>33.4.5-android</version>
</dependency>

Changelog

  • 将番石榴罐子（加上 guava-testlib 和 failureaccess 罐子）更改为模块化罐子。 （7a71ea0bfa，287c701a86）
  • 更改了各种类以在 Java 9+ 下停止使用 sun.misc.Unsafe。 （ee63055ddd、80aab00dc5b7a36785f5e09b6a54397388980cde、400af25292096746ed3f6164f0ff88209acbb19f、 71d0692d418a5dd001c9b3786275a5f1f94e1971、d1a3cd5037528a2ae990bfceed9cdd009fbc54de、b3bb29a54b8f13d6f6630b6cb929867adbf6b9a0、 1a300f6b2f7ba03ae9bc3620a80c4d4589c65b69)
    • 请注意，如果您在 JVM 上使用 guava-android（而不是使用 guava-jre），Guava 仍会尝试使用 sun.misc.Unsafe。未来我们会在这方面做进一步的工作。
  • 迟来的更新公共后缀列表数据。 （ee3b9c64382037f72b3a8341915cc64b87850b53、d25d62fc843ece1c3866859bc8639b815093eac8）

特别感谢@sgammon 他的模块化工作。
