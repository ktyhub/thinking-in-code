AdminLTE v4.9.0

小版本 发布时间2026年8月26日 来源ColorlibHQ/AdminLTE 英文原文

AdminLTE v4.9.0

已更改

打印的页面再次成为文档 - 页眉、侧边栏和页脚不再打印。

AdminLTE 3 没有提及这三项内容。 v4 打印了它们，在作为真实文档打印的页面上，结果是 #6113 中的发票：在菜单上花费的每张纸的 200px 读者无法 click，发票挤进了剩下的内容 - 它自己的表格将“Pro plan subscription” 横跨三行 - 侧边栏的 85 个菜单项超出了第一张纸的底部。一张发票打印成两页，第二张几乎是空的。

内容现在占据纸张的整个宽度。打印样式没有其他变化：链接目标在外部链接之后仍然打印，按钮仍然保留轮廓，所有内容仍然是白底黑字。

两条路都还在那里，现在都得到了适当的尊重：

<!-- print the whole shell, as 4.0–4.8 did -->
<html lang="en" data-lte-print="app">
<!-- or bring back one piece: .d-print-flex for the header (it is a navbar),
     .d-print-block for the sidebar and footer -->
<aside class="app-sidebar bg-body-secondary shadow d-print-block">…</aside>

无论哪种模式，.d-print-none 仍然会隐藏您不想在纸上显示的任何内容。 data-lte-print 现在每个令牌都匹配，因此 data-lte-print="plain app" 两者都设置； data-lte-print="plain" 不受影响。

由@johnnyq 报道。

已修复

布局在打印时保留其视口大小的尺寸（#6113）。

.app-wrapper 带有 min-height: 100vh 和 max-width: 100vw，并且都没有被允许打印 - 尽管打印块故意重写了相同元素的网格。纸张没有要填充的视口：无论页面有多短，包装纸都保留了整张纸，这就是为什么打印的发票将其页脚放在一张空灰色纸的底部，内容位于顶部三分之一，也是包装纸后面的任何内容都会打开一个新页面的原因。现在，两者以及页眉、正文和页脚上的 max-width: 100vw 都已重置。

打印块在不需要的元素上设置了 display。

将display: block强加在.app-sidebar上，是导致.d-print-none在4.6.0之前无法隐藏的原因，同样的形状会让.d-print-*现在无法显示。打印 shell 是“不”隐藏它的问题，因此隐藏它的规则会被限制范围，并且打印块中的任何内容都不会再强制在页眉、侧边栏或页脚上使用 display 值。

adminlte.js 未受影响； adminlte.css 经过 gzip 压缩后增长了 64 字节。

npm install admin-lte@4.9.0
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/admin-lte@4.9.0/dist/css/adminlte.min.css" />
<script src="https://cdn.jsdelivr.net/npm/admin-lte@4.9.0/dist/js/adminlte.min.js"></script>
