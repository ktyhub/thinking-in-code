repomix v1.19.0

小版本 发布时间2026年11月8日 来源yamadashy/repomix 英文原文

repomix v1.19.0

此版本将 MCP 服务器移至 SDK v2，具有实时进度和取消功能，使 --compress 输出更加准确，并带来了来自首次贡献者的大量错误修复！

新消息🚀

SDK v2 上的 MCP 服务器和 2026-07-28 协议（#1952、#1954）

MCP 服务器现在在 MCP TypeScript SDK v2 上运行。支持 2026-07-28 协议的 Clients 会自动协商，现有的 clients 会像以前一样工作。

  • 当 client 关闭标准输入时，服务器会干净地退出，因此不会留下任何 repomix --mcp 进程。
  • 安装引入了大约一半的软件包（171 到 84），因为 v1 SDK 带来了 HTTP 传输依赖项，例如纯 stdio 服务器从未使用过的 Express。

对于 client 作者：工具模式现在声明 JSON Schema 2020-12（主体不变），并且验证错误不再以 MCP error -32602: 开头。

MCP：长期运行包的进度和取消（#1955、#1958）

现在，当 client 经过 progressToken 时，pack_codebase、pack_remote_repository 和 generate_skill 会发送 notifications/progress，因此长包显示实时状态，并且在进度上重置超时的 client 不再切断它们。在 --sandbox 模式下，消息仅携带阶段名称，而不携带主机路径。

现在，取消呼叫或断开连接会停止该包并清理其部分输出。

改进 ⚡

更准确的 --compress 输出 (#2003)

对每种受支持语言的黄金测试都暴露了一系列错误，现已修复：

  • 函数体中的代码不再像声明一样泄漏到输出中。
  • 重复的行被删除。
  • 保留默默删除的声明，例如 C/C++ typedef 和 #define、C# 和 Java 字段、Rust 结构字段、Ruby attr_* 调用和 CSS at 规则。

C、C++、C#、CSS、Dart、Go、Java、JavaScript/TypeScript、Ruby、Rust、Swift 和 Vue 的输出更改。如果您在管道中依赖 --compress，则预计会与 v1.18 有所不同。

技能生成：更好的技术堆栈检测 (#1995)

--skill-generate 现在从 Gradle Kotlin DSL (build.gradle.kts) 以及 pyproject.toml 的 PEP 621 和 Poetry 形式读取依赖项。

忽略远程 URL 路径时发出警告（#1980、#1984、#433）

像 https://github.com/owner/repo/tree/main/src/shared 这样的 URL 打包了整个存储库并默默地删除了路径。 Repomix 现在发出警告并建议 --include 模式：

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

错误修复🐛

忽略以通配符结尾的模式现在排除文件（#1963、#1876、#320）

**/npm-debug.log* 和 **/repomix-output.* 等模式仅排除目录内容，因此 npm-debug.log.1 和 docs/repomix-output.xml 等文件会滑入输出中。他们现在被排除在外。之前排除的任何内容都不会被包含在内。

.git/info/exclude 遵循 Git 的匹配规则（#1871、#1870）

像 secret.txt 这样的无斜线模式现在可以在任何深度匹配，就像在 Git 中一样，因此 sub/secret.txt 不再打包。

特别感谢@sxh313 的贡献！ 🎉

否定的自定义忽略模式不再反转（#1975、#400）

ignore.customPatterns 或 --ignore 中的 !main.ts 排除了 main.ts，而不是重新包含它。现在会跳过否定模式并发出警告，直到获得适当的支持为止 (#400)。

拆分输出文件不再打包到下一次运行中（#1921、#1920）

使用 --split-output，不再将上次运行中的 repomix-output.1.xml 等文件作为输入。

特别感谢@lorenzozanee 的第一个贡献！ 🎉

--remove-comments 在 CSS、SCSS、Less、Vue 和 Svelte 中保留 URL（#1912、#1965、#1911）

url(http://example.com/logo.png) 被剪切为 url(http:，因为 // 被视为注释。每种语言现在都使用自己的注释规则，Vue 和 Svelte 文件按 <script>、<style> 和标记部分进行处理。

特别感谢@plox-sumit 的第一个贡献！ 🎉

Git 日志和差异中的非 ASCII 文件名（#1940、#1979）

像 日本語.txt 这样的名称在 git 日志和 diff 中不再显示为 "\346\227\245..."，并且 output.git.sortByChanges 现在可以正确对这些文件进行排序。

特别感谢@feiiiiiii5 的第一个贡献！ 🎉

--token-count-tree 0 显示完整的树 (#1941)

之前它什么也没打印；它现在显示每个文件。

特别感谢@feiiiiiii5 的贡献！ 🎉

Windows 上的嵌套 --stdin 路径 (#1922)

Windows 上的管道路径（例如 src/(routes)/page[1].ts 到 repomix --stdin）仅打包根级文件。嵌套路径现在匹配。

特别感谢@lux-liang 的第一个贡献！ 🎉

--quiet 和 --stdout 下可见的致命错误（#1875、#1874）

--quiet 或 --stdout 下的失败包以代码 1 退出并且不打印任何内容。错误现在转到 stderr。

特别感谢@sxh313 的贡献！ 🎉

MCP 服务器修复（#1867、#1866、#1865、#1864、#1869、#1868）

  • --mcp --verbose 不再将诊断信息写入标准输出，而 clients 将其作为协议帧读取。 (#1867)
  • 在 generate_skill 或 pack_remote_repository 调用后，错误记录不再在会话的其余部分保持沉默。 （#1865）
  • grep_repomix_output 现在像 grep -C 一样格式化上下文并处理非常大的输出。 （#1869）

特别感谢@sxh313 的第一个贡献！ 🎉

安全强化🔒

MCP pack_codebase 始终运行秘密扫描 (#1960)

打包目录中的 repomix.config.json 可以关闭对 security.enableSecurityCheck: false 的 MCP 包的秘密扫描。现在始终针对 MCP 包运行扫描；普通的 CLI 运行仍然遵循配置文件。

文档📚

MCP 文档现在声明，如果没有 --sandbox，pack_codebase trust 会在其打包的目录中包含 repomix.config.*，就像在那里运行 CLI 一样。当您的助理可能时，请使用 --sandbox
