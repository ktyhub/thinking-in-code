repomix v1.18.0

小版本 发布时间2026年8月8日 来源yamadashy/repomix 英文原文

repomix v1.18.0

此版本引入了 MCP 服务器的沙箱模式，将其限制在单个工作区目录中，以及跨 MCP 工具表面和远程存储库处理的一组安全强化更改！

新消息🚀

MCP 沙盒模式（#1753、#1754）

MCP 服务器现在可以使用 --sandbox 标志限制在单个工作区目录中：

# Confine to the current working directory
repomix --mcp --sandbox

# Confine to a specific directory
repomix --mcp --sandbox path/to/project

默认情况下，MCP 服务器可以读取主机用户可以读取的任何路径，这对于 trusted 本地助手来说很方便，但当服务器暴露给 untrusted client 或代理时（例如在托管应用程序中嵌入 Repomix 时），这就太宽泛了。在沙盒模式下：

  • 每个路径都相对于工作空间根目录。绝对路径、~、.. 和 Windows 驱动器/UNC 路径将被拒绝，并且在根目录之外解析的路径（包括通过符号链接）将被删除。
  • 结果和错误消息被虚拟化，因此主机路径永远不会暴露。
  • 仅注册只读、根限制工具：pack_codebase、read_repomix_output、grep_repomix_output、file_system_read_file 和 file_system_read_directory。远程打包、技能生成和附加外部输出被禁用。

这是工具表面的应用程序级限制，而不是操作系统级沙箱：当托管 untrusted clients 的服务器时，仍然在平台的通常隔离（容器、专用用户）下运行它。

详情请参见MCP服务器-沙盒模式。

特别感谢@huy-trn 设计和实现此功能。很高兴长期贡献者回来！ 🎉

安全强化🔒

MCP 文件系统工具现在仅限沙箱

file_system_read_file 和 file_system_read_directory 工具现已注册仅在沙箱模式。在 --sandbox 之外，他们可以读取该进程可以读取的任何路径，而其内置的 Secretlint 扫描则提供了比其提供的更多保护：它识别文件内容中已知的秘密格式，仅此而已。在沙箱模式下，工作区根目录为这些工具提供了真正的访问边界，并保留秘密扫描作为额外的启发式保护措施。

如果您的 MCP 设置依赖于这两个工具，请将 --sandbox [dir] 添加到服务器参数以继续使用它们，仅限于该工作区。

工具描述和文档也已全面重新措辞，以描述 Secretlint 扫描的本质：尽力而为的内容启发式方法，而不是访问边界。

有关详细信息，请参阅安全公告。感谢@rafaelfiguereod-stack 的报告！ 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-rpmv-562j-qxrv

存储库 URL 中的凭据在记录之前经过编辑

远程 URL 通常使用内联凭据 (https://<token>@github.com/owner/repo.git) 编写，尤其是在 CI 中。 Repomix 之前将此类 URL 按原样回显到控制台输出、跟踪日志、错误消息（git 在其失败输出中重复完整的命令行）和 MCP pack_remote_repository 响应，将凭证保留在终端回滚、CI 构建日志和日志聚合系统中。现在，在将 URL 写入任何位置之前，所有这些路径都会编辑用户信息凭据和已知凭据查询参数（token、private_token、access_token 等）。

有关详细信息，请参阅安全公告。感谢@kakashi-kx 的报告！ 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-w8cw-mgw9-74h7

云元数据端点被拒绝作为克隆目标

远程打包现在拒绝从云实例元数据端点（169.254.0.0/16、fd00:ec2::254、100.100.100.200、metadata.google.internal）进行克隆，这些端点提供凭证且不托管 git 存储库。 AI 代理通过 MCP 服务器选择 URL，因此注入的指令可能会将克隆瞄准用户从未要求过的地址。私人网络 (RFC1918) 仍然被允许，因为从自托管 git 服务器进行克隆是正常的。

如何更新

npm update -g repomix

一如既往，如果您有任何问题或建议，请通过 GitHub 问题或我们的 Discord 社区 告知我们。
