LightRAG v1.5.8rc1

重要提示

v1.5.8rc1 是候选版本。在升级生产之前，请在数据副本上进行测试。

亮点

1.配置存储：LightRAG 现在会记住哪个嵌入模型构建了您的向量

在早期版本中，在现有部署上更改 EMBEDDING_MODEL 或 EMBEDDING_DIM 会失败且无提示。根据后端的不同，LightRAG 要么保留旧向量并返回错误的邻居，要么打开一个新的空向量容器（Milvus / Qdrant / PostgreSQL）并提供根本没有向量的知识图。

v1.5.8 添加了配置存储。它是一个小型 KV 命名空间 (config)，保存每个工作区的嵌入基线：对于每个向量目标（实体、关系、块），其向量写入的嵌入空间。启动会根据当前嵌入配置检查基线。如果空间发生变化，服务器拒绝启动并指定目标和出路，而不是提供不好的结果。

  • 后端： JsonKVStorage、PGKVStorage、MongoKVStorage 和 OpenSearchKVStorage，使用 LIGHTRAG_CONFIG_STORAGE 选择。如果未设置，它遵循 LIGHTRAG_KV_STORAGE，因此大多数部署不需要新设置。 RedisKVStorage 未被承认，因此 Redis 部署默认为 JsonKVStorage，并带有启动警告。
  • 无需准备。 在首次启动 v1.5.8 时，现有部署会自行记录其基线。仅在证据上记录基线：采用探针重新嵌入一些存储的记录（每个目标最多 8 个）并将它们与存储的向量进行比较，或者确认容器为空。无法运行的探测器（例如，嵌入服务已关闭）不会记录任何内容，并会在下次启动时重试。
  • 部署锚点。 第一次启动还将部署绑定到它打开的配置容器，在 WORKING_DIR/config_storage_anchor.json（后端类型 + 容器 UUID）中。每次稍后启动都会拒绝其他类型或其他 UUID 的容器。因此，更改的 LIGHTRAG_KV_STORAGE、不同的数据库或更换的卷不再默默地移动您的配置。
  • 新的离线工具：
    • lightrag-rebuild-vdb 使用当前模型重新嵌入工作区并记录新基线。这是有意改款后的出路。
    • lightrag-migrate-config 将配置存储移动到另一种类型的后端，例如从 JSON 文件移动到 PostgreSQL。
    • lightrag-clear-storage 清除工作区离线状态，包括配置记录。
  • 多台服务器，一台 WORKING_DIR： 当每台服务器都有自己的 WORKSPACE 和端口时受支持。如果文件系统支持文件锁，则拒绝同一工作区上的第二个服务器。

有关更多信息，请参阅：

  • docs/LightRAG-API-Server.md: 后端类型之间的配置存储迁移
  • lightrag/tools/README_REBUILD_VDB.md、README_MIGRATE_CONFIG.md、README_CLEAR_STORAGE.md
  • docs/design/ConfigurationStorageDesign.md：设计概述

2.更安全的图形写入和文档删除

  • 手动图形编辑（创建/编辑/删除/合并实体和关系，insert_custom_kg）现在针对彼此以及针对 NetworkXStorage 上的摄取管道进行序列化。
  • 重新设计了实体/关系创建、编辑、合并和重命名的提交顺序，以防止操作中断时丢失数据。
  • 中断的文档删除可见且可重试。
  • 新的 lightrag-repair-chunk-tracking 工具可删除因中断删除而留下的孤立块跟踪行。

3. PostgreSQL 存储默认值 设置向导现在从官方 pgvector/pgvector 映像生成 PostgreSQL，并为图表提供 PGTableGraphStorage（普通表，无 Apache AGE）。 PGGraphStorage (AGE) 和 Redis 存储（RedisKVStorage、RedisDocStatusStorage）已弃用。他们继续工作并在启动时记录警告。

4.安全强化和新提供商

  • Ollama 兼容的 /api/* 路由受 LIGHTRAG_API_KEY 保护（请参阅重大更改）。
  • PDF 提取在资源有限的子进程中运行 pypdf。
  • 流式错误行不再回显原始提供程序异常文本。
  • OpenAI Responses API 的新 openai_responses LLM 绑定。

重大变化

  • 需要 Python 3.11 或更高版本。 不再支持 Python 3.10。 Docker 图像 (Python 3.12) 不受影响。
  • 更改现有工作区上的嵌入模型现在会拒绝启动，它过去会提供错误或空的结果。恢复以前的 EMBEDDING_MODEL / EMBEDDING_DIM，或运行 lightrag-rebuild-vdb 以重新嵌入新模型。
  • 在第一次 v1.5.8 启动后更改 LIGHTRAG_KV_STORAGE 被拒绝，而 LIGHTRAG_CONFIG_STORAGE 未设置，因为配置存储会默默地随之移动。要么将 LIGHTRAG_CONFIG_STORAGE 显式设置为锚定后端，要么使用 lightrag-migrate-config 移动配置。
  • Ollama 路由需要 API 密钥。 当设置 LIGHTRAG_API_KEY 并且取消设置 WHITELIST_PATHS 时，没有密钥的 /api/* 请求现在会收到 HTTP 403。在 Open WebUI 中，lightrag:latest 模型将从列表中消失。修复：输入密钥作为 Ollama 连接的 API 密钥（作为 Authorization: Bearer <key> 发送），或设置 WHITELIST_PATHS=/health,/api/* 以保留旧行为。
  • POST /documents/clear_cache 已删除。 使用 DELETE /documents?clear_llm_cache=true 代替。清除 LLM 缓存现在与破坏性清除一起发生。
  • 以 $ 开头的工作空间名称被保留。 用于将 WORKSPACE=$team 提供为 _team 的服务器。设置 WORKSPACE=_team（数据已存储的名称），并且没有数据移动。

升级注意事项

  1. 首先备份，然后在启动 v1.5.8 之前停止每个旧实例。 这包括所有工作线程、共享存储的服务器和维护工具。第一次启动创建配置容器并绑定锚点。不要进行滚动升级，让旧的编写器继续运行。
  2. WORKING_DIR 必须持久存在，即使每个存储都是数据库。 它现在保存 config_storage_anchor.json，对于 JSON 配置还保存 <workspace>/kv_workspace_config.json。在 Docker 中，将其保留在已安装的卷上。在 Helm 中，保留 persistence.enabled: true。每次重新启动时，临时 WORKING_DIR 都会丢失锚点和 JSON 配置。将其包含在您的备份中。
  3. 嵌入服务必须在首次启动期间可达，以便采用探针可以记录基线。检查 WARNING 的启动日志，发现无法建立基线。如果由于嵌入空间不匹配而拒绝启动，则您存储的向量与配置的模型不匹配：修复配置，或运行 lightrag-rebuild-vdb。
  4. Redis 用户： 对于 LIGHTRAG_KV_STORAGE=RedisKVStorage，配置存储默认为 WORKING_DIR 中的 JSON 文件（参见注释 2）。 Redis 存储已弃用；计划搬到 PostgreSQL。
  5. PGGraphStorage 用户： 您的部署将继续工作，并且向导会为其保留启用 AGE 的映像。要离开 AGE，请先迁移图形（python -m lightrag.tools.migrate_graph_storage --apply，无需重新索引），然后切换到 PGTableGraphStorage 和 pgvector 图像。
  6. 可选： 要将配置保留在数据库中而不是 JSON 文件中，请在每个服务器停止的情况下运行 lightrag-migrate-config --target-backend PGKVStorage（或 MongoKVStorage / OpenSearchKVStorage）。然后将 LIGHTRAG_CONFIG_STORAGE 设置为该后端。
  7. 要重新开始新的嵌入模型，请使用 lightrag-clear-storage 而不是手动删除文件。如果您手动删除文件，请同时删除 kv_workspace_config.json 和 config_storage_anchor.json。否则记录的基线会拒绝新模型。
  8. TOKEN_SECRET 应是至少 32 字节的随机值（例如，openssl rand -hex 32）。升级后的 PyJWT 会对较短的秘密发出警告。
  9. 流式错误消息是通用的。 /query/stream、/api/generate 或 /api/chat 上流中间的故障现在读取 Internal server error (error_id: …)，并且不再包含 LLM 提供程序的异常文本。流格式不变。在 error_id 的服务器日志中查找详细信息。需要更新从流中解析提供程序错误文本（例如，检测速率限制）的 client。
