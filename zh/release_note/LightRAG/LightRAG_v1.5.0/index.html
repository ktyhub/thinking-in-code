LightRAG v1.5.0

主要改进

  • 🎉✨功能：LightRAG 现在支持多模式文档处理，并且可以充分利用文档中的图像、表格和公式来回答查询。 RagAnything 的所有多模式处理能力都合并到 LightRAG 中； （RagAnything 将不再接收核心功能更新或维护）
  • ✨🎉功能：全面升级文档处理流程，支持使用MinerU和Docling解析和提取文件内容，与多模态内容分析和实体关系提取无缝集成。
  • 💡✨功能：LightRAG 现在引入本机解析，支持从 DOCX 文档中提取高质量的内容。它支持Word自动编号的精确重建，以及图像、表格和公式的提取，提供与多模态内容分析和实体关系提取的无缝集成。 本机解析器 的扩展格式支持即将推出。
  • 💡🧠功能： 引入了四种可选的文本分块策略：Fix、Recursive、Vector 和 Paragraph。 每种分块策略的参数可以通过环境变量进行配置。
  • 💡🎯功能：文件处理管道支持选择基于文件扩展名或基于每个文件的文件解析引擎和文本分块策略。详细使用说明请参考FileProcessingPipeline.md。
  • 🚀⚡性能：优化向量存储持久逻辑，将向量计算推迟到每个文件处理批次结束，从而实现集中式批量计算。 这显着减少了矢量模型调用的数量，并显着提高了 LightRAG 支持的所有矢量数据库的更新插入速度。
  • 启用对非对称模型的任务感知嵌入支持，包括 voyage-3、text-embedding-004、embed-multilingual-v3.0 和 jina-embeddings-v3。
  • 通过引入 LLM JSON 结构化输出，提高了实体/关系提取的可靠性；设置 ENTITY_EXTRACTION_USE_JSON=true 来启用它。
  • 引入 ENTITY_TYPE_PROMPT_FILE 为用户提供 LLM 驱动的实体类型识别和提取的增强指导。
  • 完全支持 AWS Bedrock API 上的 Amazon 和 Anthropic 模型。
  • 🎯✨🎉功能：实现了特定于角色的LLM配置支持，引入了四个不同的角色：EXTRACT、QUERY、KEYWORDS和VLM，每个角色都有独立的LLM设置。建议为KEYWORDS角色配置小参数、非推理、高速模型，以优化查询延迟； EXTRACT 角色采用中等参数、非推理模型来平衡准确性和吞吐量； QUERY角色采用大参数推理模型，提升查询质量。详细使用说明请参考RoleSpecificLLMConfiguration.md。

损坏了什么

  • 💥警告：当前使用 OpenSearch 和 MongoDB 图存储的用户需要仔细规划升级，因为数据迁移和系统重启可能会导致服务长时间中断。
  • ⚠️**ENTITY_TYPES 环境变量已被弃用**；在启动此新版本之前，请将其替换为 ENTITY_TYPE_PROMPT_FILE。
  • 💔删除了已弃用的字段：从 lightrag/base.py 中删除了 QueryParam.model_func
  • 对于 3.3.0 之前的 OpenSearch 版本，请先升级 OpenSearch，然后再升级 LightRAG（请参阅 https://github.com/HKUDS/LightRAG/pull/2991）。
  • ⚠️将delete_entity/delete_relation从文档API移动到图API
