LightRAG v1.5.3

⚠️ 升级说明（现有 Milvus 部署）

由于 PR #3228，升级现有 Milvus 部署会在下一个initialize_storages() 上触发一次性自动迁移：在服务准备就绪之前，旧集合被复制到新的模型后缀集合（架构升级和字节截断）中。规划大型集合的额外启动时间和写入吞吐量。

  • 迁移仅运行一次。后缀集合存在后，后续每次启动都会直接验证并加载，不会重新扫描或重新迁移旧集合。
  • 遗留数据永远不会自动删除。为了安全起见，旧的 {workspace}_{namespace} 集合将被保留，而不是被删除，因此向量存储在升级后会暂时复制。这是有意为之的——迁移不会为您回收空间。
    • 所需操作：一旦确认迁移成功并且新系统可以针对带有模型后缀的集合正常工作，请自行手动删除旧的 {workspace}_{namespace} 集合以回收存储。在此之前，重复的向量将保留在磁盘上。
  • 数据不兼容的遗留集合（不同的向量维度，或者没有向量场的旧的简单模式）不会被迁移；相反，会创建一个新的后缀集合，并且旧数据保持不变。
