LangBot v4.11.7

LangBot 是一个开源的 AI 聊天机器人与智能体平台，支持多种即时通讯平台、大语言模型、知识库和插件，帮助您构建、部署和管理 AI 助手。 LangBot 是一个开源 AI 聊天机器人和代理平台，它连接消息传递平台、大型语言模型、知识库和插件，帮助您构建、部署和管理 AI 助手。

LangBot v4.11.7

4.11.x 系列的最终稳定版本。它取代了 v4.11.6，后者已被撤回：v4.11.6 拒绝共享模型上的并发令牌计数，因此同时运行的 LocalAgent 对话可能会回退到粗略估计并失败。如果您安装了 v4.11.6，请升级到 v4.11.7。

本版本是 4.11.x 的最终稳定版，取代已撤回的 v4.11.6。v4.11.6 在多个会话同时使用同一模型时会拒绝 GZ 的 token 计数，因此 LocalAgent 改用粗略已指示，部分对话会失败。安装 v4.11.6 的用户请升级到 v4.11.7。

它不包含任何新功能。它修复了4.11.x实例通过LangBot Space遥测报告的故障，并更新了插件SDK和涉及的官方插件。

修复/修复

  • 并发令牌计数/并发令牌计数（v4.11.6 回归）：同一模型上的并发令牌不再被拒绝；只有超时或被取消后当前运行的计数，才会阻止新的计数。一个模型上的并发令牌计数不再被拒绝；只有比调用者存活时间更长的计数才会阻止新的计数。
  • Windows 插件 / Windows 插件：插件 print 中文或表情符号不再导致插件运行时断连，也不再出现 'gbk' codec can't encode 报错（SDK 0.7.24）。打印中文文本或表情符号的插件不再断开中文语言 Windows 上的插件运行时连接。
  • Windows 令牌计数 / Windows 令牌计数：LiteLLM 的 Windows 安装包自带的 tokenizer 文件是 CRLF 换行，校验失败后会重新从 openaipublic 下载；网络不通时，每个进程的第一次对话都会卡住（遥测里的 30 秒 count_tokens call timed out）。LangBot 现在启动时将这些文件转成 LF 存存到 data/tiktoken_cache，计数完全关闭。另外，计数超时或失败时 LocalAgent改用当地提示继续对话，不再整轮失败。LiteLLM 的 Windows 轮子附带 CRLF 分词器文件，这些文件未通过 tiktoken 的哈希检查并触发下载； LangBot 现在保留标准化的离线副本，并且计数失败不再导致 LocalAgent 轮次失败。
  • Runner可用性/Runner可用性：启动或重连期间，等待已安装完成插件初始化后再派发，不再报Agent runner not found: plugin:langbot-team/LocalAgent/default。
  • 插件运行时/插件运行时：运行时重连期间，工作区同步和事件派发会先等待重连完成（最多30秒），不再在断连窗口内失败；附件和流的体积超限报错会给出实际大小和处理建议（SDK）。
  • 知识库/知识库：支持库向量在后台线程中初始化。之前在较慢的机器上，首次进入库会阻塞事件循环，导致插件运行时断连、入库失败。向量后端是在事件循环之外创建的；慢速主机上的第一次摄取不再断开插件运行时连接。
  • SQLite / SQLAlchemy：非 Docker 安装（pip / uvx）在 SQLAlchemy 2.1 上首次写入插件存储声明 unknown ON CONFLICT update shape 的问题已修复，依赖加载设为 <2.2；图片刷新期间释放 SQLite 写锁，又 database is locked。
  • Box sandbox / Box沙箱：过长的改为通过临时脚本执行，修复Argument list too long和大附件命令导入失败（SDK）。
  • Runners：Coze / Dify 处理已和工作流类型的输出，不再把此类响应当成空响应；LocalAgent 推理配置为空时不再报错。命令错误响应的反序列化完成不再崩溃（SDK）。
  • Runner 交互 / Runner 交互：HTTP Bot、OneBot 等旧版本适配器上，Runner 发起的交互（例如 Dify 工作流的人工输入节点）不再报 get_interaction_capabilities 错误，改为文本问答。遗留适配器上的 Runner 交互（HTTP Bot、OneBot 等）回退到文本而不是失败。
  • 遥测/遥测提升：取消的执行记为取消而不是失败；路由失败时保留错误详情；已经是终态的执行不再报转换错误；执行链的平台字段不再被工具来源（mcp/skill等）覆盖。
  • 官方插件/官方插件：EssentialCommands 0.1.12 修复 !func；HelloPlugin 0.1.6 去掉调试输出；LocalAgent 0.2.10、CozeAgent 0.2.5、DifyAgent 0.2.8 已在 Marketplace 上架。
  • SDK：langbot-plugin 由 0.7.23 固定到 0.7.24。

发布验证

  • 所需的检查（单元测试、快速集成、PostgreSQL 合约、SQLAlchemy 2.0 / 2.1 矩阵、Box 集成、E2E 启动、核心烟雾、回归工具、lint）在发布提交中传递。
  • 在标记之前，已安装候选版本并通过 Docker (docker compose --profile box) 和 uvx（uvx --from <wheel> langbot，从 PyPI 解析的依赖项：SDK 0.7.24、SQLAlchemy 2.1.8）进行例行操作。每次运行都使用新的数据目录。检查内容包括帐户设置、WebUI、Marketplace 安装（需要确认权限）、启用和卸载、模型、通过 HTTP Bot 的 LocalAgent 管道（在 Box 沙箱中调用工具）、!help !cmd !func !plugin !version 命令、知识库摄取和检索以及重新启动后的持久性。对于 v4.11.6 候选者，在 Windows 11（代码页 936）上使用 uvx 运行了相同的检查； v4.11.7 仅在其之上更改了与平台无关的计数逻辑，包括打印中文和表情符号的插件，以及与 tokenizer 下载被阻止的第一次 LocalAgent 对话（大约 4 秒，无网络访问）。
  • Dify 1.18.0 人工输入工作流程通过 DifyAgent over HTTP Bot 端到端运行。
  • v4.11.7 添加了并发检查：在一个模型上同时进行 8-24 个 LocalAgent 对话，没有令牌计数拒绝（v4.11.6 每 24 个对话轮拒绝 3-6 个计数）。 v4.11.6 数据的就地升级也得到了验证。
