ragflow v1.0.0

经过三个候选版本后，我们很高兴地宣布 RAGFlow 1.0 正式发布，现已准备好投入生产。该版本基于 Go 进行完全重写，显着降低了部署和运行时开销，并引入了全新的 Agentic Chat 体验。我们鼓励所有用户升级以提高稳定性、性能和问题解答。

亮点

  • 用 Go 重写以实现更轻量级部署：Docker 图像大约小 10 倍，启动速度大约快 10 倍。
  • 并发性提高约 100 倍，查询延迟、内存使用和文档解析速度显着改善。
  • 全新代理聊天：通过迭代检索、工具调用和证据充分性评估，实现多步推理并回答复杂问题。

聊天和代理

  • 新增代理聊天模式，取代了之前的低、中、高、超思维级别。
  • 将 Jev 决策模型引入代理工具调用循环中，以确定可用证据是否足以回答问题。
  • 在分类代理组件中添加了对 Jev 决策模型的支持。
  • 在聊天记录中添加了提示、令牌使用情况和执行时间的存储和显示。

文档摄取和检索

  • 将 12 个内置文档解析器与管道解析器统一。
  • 添加了对多个摄取管道 DSL 版本的支持。

架构和部署

  • 将消息队列从 Redis 迁移到 NATS。
  • 采用 Kvrocks 进行缓存和检查点存储。
  • 添加了适用于 arm64 架构的 Docker 映像。
  • 在 Go 中重新实现了 RAGFlow CLI。

稳定性

  • 修复了社区报告的多个关键错误以及候选版本阶段发现的问题，进一步提高了运行时稳定性。

基准

  • 使用 RAGFlow Agentic Chat 和 MiniMax M3 在 FRAMES 多跳问答基准测试中实现了 91% 的准确率。

升级

  • 从 v1.0.0-rc1、rc2 或 rc3 开始：现有数据完全兼容。可以直接升级。
  • 从v0.27.2：您可以直接升级到v1.0.0。 RAGFlow Docker 容器启动时，数据迁移会自动运行。
  • 从 v0.27.2 之前的版本：在升级到 v1.0.0 之前，请按照迁移指南完成所需的中间升级。
  • 升级前备份所有数据。从v0.27.2到v1.0.0的数据迁移是不可逆的。如果迁移失败，请先恢复完整的升级前备份，然后再重试。

兼容性和限制

  • 不再支持已弃用的 API 别名。
  • Python SDK 不受影响。
  • DeepDoc 目前仅支持 CPU 环境。

相关参考

  • 备份和升级指南：https://ragflow.io/docs/migration_overview
  • 删除了 API：https://ragflow.io/docs/http_api_reference#removed-api-aliases
