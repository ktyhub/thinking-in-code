ragflow v0.26.0

总结

新功能

  • 模型提供商
    • 为多个提供商实现自动填充模型列表，无需手动输入模型名称。该功能目前支持：Ollama、OpenRouter、vLLM、OpenAI-API-Compatible、LM-Studio、VolcEngine、Xinference、LocalAI、BaiduYiyan、GPUStack 和 Fish Audio。
    • 允许为同一型号提供商配置多个 API 密钥。 #14595
    • 通过直接从远程模型提供者获取当前可用的模型，动态填充 UI 中的模型选择下拉列表。 #15711
  • 数据源连接器：为 Outlook、OneDrive、Microsoft Teams、Slack、SharePoint、Salesforce 和 Azure Blob Storage 实现新的数据源连接器。 #15333#15330#15332#15188#15190#15462#15466
  • 数据集 - 实现社区提取和实体解析的检查点和恢复功能，这是 GraphRAG 索引管道中最昂贵和最耗时的部分。 #15518#15523

改进

  • 删除 <think> 文本缓冲，以确保具有推理能力的模型在交互过程中感觉更快、更透明。 #15891
  • 将 MySQL 迁移标记为已应用。 #15504

模型支持

  • 四个新的 SiliconFlow 模型 #15383
  • MiniMax-M3 型号 #15513
  • 最新的 Anthropic 模型 #15516
  • Voyage 4 模型系列 #15516
  • 一致的型号列表。 #15576

国际化

  • 完成韩语翻译。 #15863
  • 完成意大利语翻译。 #15729

错误修复

  • MiniMax模型的思维模式没有正确启用。 #15496
  • Qwen3.5、Qwen3.6机型开启思维模式时触发无限循环。 #15101
  • 使用 OpenAI 兼容的聊天完成 API 端点时，流式答案会重复。 #15286#15443
  • 当 NaN（非数字）或 Inf（无穷大）等无效数字分数传递到 JSON 编码器时，聊天完成期间会导致序列化错误。 #15245#15266
  • 使用 LiteLLM 提供程序的聊天完成失败，因为无法识别的内部配置参数在到达外部 API 之前未被过滤掉。 #15427#15432
  • OpenAI 兼容的聊天完成 API 默认为流式响应。 #15356#15394
  • 在元数据过滤期间，空的 AND 结果被错误地删除。 #15477
  • MinerU 解析器错误地将重复的页面镶边（例如页眉和页脚）提取为主要文本。 #15335#15387
  • DeepDoc 模块中的文档提取期间缺少英文图表标题。 #15481
  • json 和 chunks 上游格式的 TitleChunker 返回空输出 #14247#15396
  • .tsv 文件上传尝试失败时缺少错误消息。 #15284
  • API 令牌缺少 beta 值导致令牌检索错误。 #15405
  • 限制最大页面大小以修复因大型查询而导致的系统崩溃或速度减慢。 #15292
  • Client 错误是由 OpenAI 兼容的聊天完成 API 错误地默认为流式响应引起的。 #15356#15394
  • 当用户尝试从存储后端下载丢失的文件时，会触发 HTTP 500 内部服务器错误，而不是标准 4xx client 错误。 #15369#15371
  • GraphRAG 实体排名被破坏。 #15795#15797
