go-ethereum v1.17.8

go-ethereum v1.17.8

这是一个以安全为重点的版本，修复了多个 DoS 风险问题❤️‍🩹。请注意，大多数与错误相关的修复只有在激活阿姆斯特丹分叉后才可能实现。还有一些一般正确性改进。

建议所有用户使用此版本。

所有更改

安全

  • 在 eth 和 snap p2p 协议处理程序中，改进了多个数据包处理程序的 DoS 抵抗能力（#35862、#35883、#35859、#35857、#35904、#35856）
  • 在阿姆斯特丹分叉后，JUMPDEST 分析缓存已针对攻击案例进行了强化 (#35881)
  • IP 地址预测器现在需要在接受语句之前进行 IP 验证 (#35861)
  • 解决了与 BAL 帐户相关的阿姆斯特丹后 DoS 向量 (#35865)
  • 流氓 STUN 服务器可能会因无效响应而导致节点崩溃 (#35863)

远程过程调用

  • 当发件人帐户没有余额时，eth_createAccessList 现在可以工作 (#35397)
  • eth_simulateV1 已修复，可以正确报告阿姆斯特丹之后的 ETH 传输日志 (#35617)
  • eth_simulateV1 虚拟块现在与阿姆斯特丹规范保持一致 (#35668)
  • eth_capabilities 报告受交易哈希索引限制的收据的可用性 (#35878)
  • 对于 eth_call 及相关操作，不再应用交易 Gas 限制（阿姆斯特丹分叉后）（#35845）
  • 阿姆斯特丹后记录的实时跟踪器核心/跟踪崩溃：在没有开放框架的情况下处理创建者随机数更改（#35896）
  • 解决了不正常关闭后处理信标链头更新的边缘情况 (#35804)
  • abigen 现在在部署合约的库依赖项时将使用顺序随机数 (#35888)

核心库

  • 硬编码的 Hoodi 测试网信标链创世时间不正确 (#35876)
  • 如果服务器无响应或过载，blsync 可能会卡住 (#35872)

P2P

  • 修复了 EIP-8070 Sparse Blobpool（阿姆斯特丹分支）实现中的正确性问题 (#35860)
  • 拨号调度程序现在可以处理 DNS 解析的静态节点的 IPv4 <> IPv6 转换 (#35880)

构建

  • PPA 现已发布 Ubuntu 26.04“Resolute Raccoon”(#35854)

有关更改的完整概要，请参阅 Geth 1.17.8 发布里程碑。
