go-ethereum v1.17.2

修订 发布时间2026年3月30日 来源ethereum/go-ethereum 英文原文

go-ethereum v1.17.2

这是一个维护版本，修复了几个重要的错误。值得注意的是，debug_executionWitness 中的一个关键问题之前可能会损坏节点数据，强烈建议依赖此 RPC 端点的用户进行升级。

Geth 现在还支持与布拉格前历史已被修剪的链同步，并允许通过 geth prune-history --history.chain postprague 显式删除它。

盖斯

  • 将所有网络的默认缓存大小设置为 4GB（#33836、#33975）
  • 添加了对布拉格分叉之前修剪链历史的支持（#33657，#34036）
  • 添加了 fetchpayload 命令来为特定块构建执行见证 (#33919)
  • 优化 Era 历史导入并批量插入 (#33894)
  • 为守门员添加了 womir 目标 (#34079)
  • 添加了对 geth snapshot traverse-state 和 geth snapshot traverse-rawstate 中迭代单个存储 trie 的支持 (#34051)

核心

  • 阿姆斯特丹分叉更新：
    • EIP-8024：切换到无分支规范化并扩展 EXCHANGE (#33869)
    • EIP-7778：阻止 Gas 核算且不退款 (#33593)
    • EIP-7954：增加最大合约规模（#33832）
    • EIP-7708：ETH 传输现在发出日志 (#33645)
    • 重新设计了气体测量顺序（EIP-7928 的先决条件）(#33648)
  • 通过预热 trie 节点进行状态哈希计算来改进有效负载构建 (#33945)
  • 各种二进制特里树改进（#33951、#33961、#33989、#34021、#34032、#34022、#34056）
  • 将 go-eth-kzg 升级到 v1.5.0，显着减少 VerifyCellProofBatch 中的分配 (#33963)
  • 重构状态数据库，为二进制 trie 集成做好准备 (#33816)
  • 在现有节点上启用 trie 节点历史记录保留 (#33934)
  • 通过批处理优化历史状态索引器（#33640）
  • 修复了 txlookup 中潜在的死锁 (#34039)
  • 添加了新的 RLP API（#34052、#34048）
  • 修复 Windows 上冰箱中的 dir.Sync() 失败 (#34115)

网络

  • 通过跳过同时入站/出站拨号来避免重复连接 (#33198)
  • 通过在 Discv5 测试中使用一致的远程地址处理修复了会话密钥不匹配 (#34031)
  • 为引导节点添加了 DNS 主机名解析 (#34101)

远程过程调用

  • 修复了 debug_executionWitness 中的状态损坏问题；已弃用 debug_executionWitnessByHash (#33931)
  • 将 MaxUsedGas 字段添加到 eth_simulateV1 响应中 (#32789)
  • 修复了 eth_simulateV1 中的气顶处理 (#33952)
  • 修复了在跟踪器中创建合约期间的随机数恢复边缘情况 (#33978)
  • 修复了 eth_createAccessList 以返回空列表而不是存储键的 null (#33976)
  • 如果请求的链段已被修剪，eth_getFilterLogs 现在会返回错误 (#33823)
  • 修复了 RPC 响应中的槽号编码 (#34005)
  • 对 eth_simulateV1 强制执行 RPC 调用限制 (#34616)
  • 对 eth_getProof 中的证明实施存储槽限制 (#34617)

可观察性

  • 各种 OpenTelemetry 修复（#33927、#33955）
  • 添加了对有效负载构建的 OpenTelemetry 支持 (#33773)

构建

  • 修复了 FreeBSD 上的构建问题 (#34008)

有关更改的完整概要，请参阅 Geth 1.17.2 发布里程碑。
