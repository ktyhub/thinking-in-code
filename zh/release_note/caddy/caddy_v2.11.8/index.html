caddy v2.11.8

此补丁版本包含大量错误修复和安全强化，以及一些小的补充。此版本是从我们的 2.11 维护分支中删除的：修复程序是从 master 向后移植的。 我们建议升级，特别是如果您提供 PHP 或在文件路径中使用 {host}。

非常感谢我们的赞助商提供的资源让项目保持活力，也感谢我们的维护人员在这个残酷的人工智能新时代孜孜不倦地进行分类和协助。

：警告： 请在升级之前阅读下面的重大更改。 其中大多数都会拒绝从未执行过的配置或请求，因此大多数设置不会注意到。

亮点

  • 空闲超时，第二轮。 针对 2.11.6 中引入的空闲读/写超时的更多修复：
    • 每条路由 timeouts 现在优先于服务器范围的 read_body_idle / write_idle，并且嵌套的 timeouts 使用最里面的一个。 (#8121)
    • 通过 HTTP/2，暂停读取请求正文的处理程序（例如上传到慢速上游的 reverse_proxy）不再丢失正文并失败并返回 502。(#8125)
    • 处理程序设置的最后期限现在充当上限而不是被覆盖，因此 Mercure 的 dispatch_timeout 和 FrankenPHP 的 request_body_timeout 之类的东西再次起作用。谢谢@dunglas！ （＃8145，＃8284）
    • HTTP/1.1 上传超时且剩余少量内容不再挂起，而是发送错误响应。谢谢@SiyXo511！ (#8178)
  • 用较少的功能绑定特权端口 (Linux)： 如果 CAP_NET_BIND_SERVICE 被允许但无效，Caddy 只会为了绑定特权端口而引发它。打包者可以使用 setcap cap_net_bind_service=+p 而不是 +ep，因此 Caddy 仍然在 --cap-drop ALL、OpenShift 的 restricted-v2 或带有空 CapabilityBoundingSet= 的 systemd 单元下启动。它还遵循内核的 ip_unprivileged_port_start，而不是假设 1024。（#8102、#8253）
  • 小补充：
    • 新的 log_level 指令用于设置匹配请求的访问日志级别，例如log_level @healthchecks DEBUG (#8201)
    • 新的 {time.now.rfc3339} 占位符。谢谢@steadytao！ （#8140）
    • 用于 TLS 连接策略的新 not 匹配器。谢谢@simonether！ (#8138)
    • tls 匹配器可用于 CEL expression 匹配器：tls()、tls('complete')、tls('early_data')。谢谢@stackedbyaradhya！ (#8088)
  • 反向代理：
    • 当上游首先发送 1xx 响应时，您自己设置的标头（例如通过 header 的 Strict-Transport-Security）不再丢失，例如 103 Early Hints (#8169)
    • 转发请求预告片值，而不仅仅是其名称。谢谢@krishsinghhura！ (#8246)
    • lb_retry_match 中的仅请求 expression 不再重试成功响应（自 2.11.3 以来的回归）(#8168)
    • 通过转发代理和 FastCGI 后端的拨号错误会像其他拨号错误一样重试。感谢@adarshxsh 和@zemamba！ （＃8264，＃8172）
    • weighted_round_robin 不再因权重少于上游而恐慌，并且不再在只有一个权重时选择不可用的上游；当所有主机都忙时，random_choose 选择负载最少的主机（#8159、#8320、#8160）
    • 对于 request_buffers / response_buffers unlimited，中途失败的主体不再被视为完整（#8207）
    • 当协议升级（例如 WebSocket）在设置过程中失败或 handle_response 状态不是数字时，连接和套接字不再泄漏。感谢@Version2beta 和@BenMacha！ （＃8269，＃8318）
    • HTTP/3 client 取消在调试级别记录，而不是作为警告。谢谢@larrasket！ (#8135)
  • encode: If-None-Match 列表和弱标签正确地得到 304 (#8128)，HEAD 响应不再得到伪造的 Content-Length (#8150)，并且 Accept-Encoding / Cache-Control 分割在多个标头行中都被考虑在内，代理中的标头处理也更快。感谢@Indra55、@jayhemnani9910 和@dunglas！ (#8025)
  • PHP / FastCGI： 没有 Status 的 Location 响应现在是 302 重定向，正如 CGI 指定的那样 (#8209)，并且写入超过其声明的 Content-Length 的应用程序（如页面后的 PHP 警告）不再破坏 HTTP/1.1 响应或终止 HTTP/2 连接。谢谢@Sulaiman-Dauda！ (#8212)
  • TLS 和 ECH：
    • 当 Caddy 拒绝加密的 ClientHello 时，它现在会发送重试配置，因此具有陈旧 ECH 配置的 client 可以恢复。谢谢@videah！ (#8142)
    • 也有自己的站点块的 ECH 公共名称保留该站点的 TLS 设置 (#8156)
    • 配置验证器时，client_auth 模式 request 和 verify_if_given 不再拒绝没有证书的 client (#8251)
    • 跨越多个侦听器地址的站点块不再允许一个侦听器的 TLS 连接策略（包括 client 身份验证）覆盖另一个侦听器的 TLS 连接策略。谢谢@steadytao！ (#8192)
    • TLS 策略 match 块中的重复匹配器行全部应用，而不仅仅是第一个。谢谢@simonether！ (#8137)
    • 合并的自动化策略使特定域的策略领先于通配符的策略 (#8287)，并且 ACME 发行者的 network_proxy 在重新配置后仍然存在 (#8288)
  • 球童文件：
    • 当启动失败时，caddy run 会再次打印错误，而不是使用代码 1 静默退出。感谢@IndraGunawan！ （#8180）
    • 已匹配的组中的路由不再运行其匹配器，这修复了例如try_files {path} {path}.html?{query} =404 为所有内容返回 404 (#8189)
    • 多个 handle_errors 块和 vars 现在遵循 Caddyfile 顺序（#8195、#8197）
    • header 块中的每个 ?Field 默认值都会单独检查，并尊重 match (#8217)
    • import 显示它无法读取的文件的真实操作系统错误 (#8163)，负 {args[...]} 索引不再恐慌 (#8316)，并且很长的定界标记不再使解析爬行 (#8203，#8249)
  • file_server: 常规文件 (/index.php/foo) 下的路径又是 404，可与 pass_thru 一起使用 (#8131)； browse 处理具有转义名称的目录中的符号链接 (#8152) 和超出末尾的偏移量 (#8213)
  • templates: 模板错误不再保持陈旧的 Content-Length / Etag 标头 (#8149)，无正文响应不再获得 Content-Length: 0 (这破坏了 iOS PWA) (#8153)，并修复了带有冒号的 humanize 时间布局以及用 ... 关闭的前题（＃8215，＃8259）
  • **日志记录：**父命名空间的 include 包括其子模块 (#8221)，dir_mode from_file 不再创建不可用的目录 (#8225)，并且到站点记录器的日志路由会忽略主机大小写 (#8176)
  • 管理员 API： 使用远程管理 access_control，如果任何权限条目允许，则允许请求，而不仅仅是第一个（#8317），并且 Cache-Control: must-revalidate 与其他指令一起被识别（#8330）
  • 其他修复： caddy hash-password 处理 Windows 行结尾和输入而没有最终换行符 (#8227)，basic_auth 缓存中的数据竞争消失了 (#8278)，Windows 服务不再卡在 START_PENDING (#8274) 和 uri strip_prefix / strip_suffix 句柄中正确的百分比转义和文字 % (#8005, #8345)
  • 发布版本使用 Go 1.27 （Go 1.26 仍然是构建 Caddy 的最低要求）。 （#8210）

：警告：重大更改

  • 在任何路由运行之前，每个协议上具有无效或仅点主机（如 ..）的请求都会被拒绝，并显示为 400。之前，HTTP/2 和 HTTP/3 也接受包含 / 或 \ 的主机。 (#8328)
  • request_body max_size 现在一旦 Content-Length 超出限制，就会拒绝 413 的请求，即使没有任何内容会读取正文。 (#8337)
  • 没有 index.php 的 php_fastcgi 站点： 对不存在路径的请求现在作为 index.php 发送到 PHP，正如记录的 first_exist_fallback 尝试策略始终承诺的那样，而不是落入 file_server 并返回 404。此外，PATH_INFO 和 DOCUMENT_URI 现在源自标准化路径（合并重复斜杠，删除 . 段）； REQUEST_URI 不变。
  • 以 / 结尾的 try_files / file 候选仅匹配目录，因此 /foo.txt/ 不再匹配文件 /foo.txt。 (#8326)
  • encode 现在即使请求具有 Cache-Control: no-transform 也会压缩响应（响应的 no-transform 仍然受到尊重），并且可以编码的响应始终获得 Vary: Accept-Encoding。保持旧行为：@transformable not header Cache-Control *no-transform* 和 encode @transformable。像 no-cache; no-transform 这样的畸形形式不再禁用压缩。 （＃8301，＃8025）
  • 更严格的配置验证。 一些默默接受的配置（并且没有执行您期望的操作）现在是错误：
    • 同一匹配器集中有多个 expression 线（将它们与 && 组合）（#8183）
    • 未知的 TLS curves 或 protocol_min / protocol_max 名称，例如 TLS1.3 而不是 tls1.3，后者曾经被默默忽略 (#8266)
    • TLS 策略 match 块中重复的 sni_regexp (#8137)
    • ip_mask 日志过滤器大小超出范围，例如 IPv4 的 33 (#8241)
    • basic_auth 用户名在占位符扩展后最终相同 (#8315)
    • 端口长度超过 11 个字符 (#8277)
  • 对于带有状态代码的 handle_errors 块和带有非路径匹配器的 vars，评估顺序现在遵循 Caddyfile。如果您有重叠的代码或两次设置相同的变量，则现在可能会胜出不同的块或值。 （#8195，#8197）

安全修复

感谢所有负责任地报告并帮助修复补丁的人：

  • caddyhttp：带有点段或斜杠的 Host / :authority 值在文件路径中使用时可以转义预期目录，例如 root /srv/sites/{host}，并且使用 php_fastcgi 甚至可以执行其外部的文件。此类主机现已被拒绝（见上文）。谢谢@dunglas。 （GHSA-r766-rf9f-588h，#8328）
  • fastcgi：SCRIPT_FILENAME 现在是从路径匹配器看到的相同标准化路径派生的，因此受路径匹配器保护的路由不能运行不同的脚本，例如与/admin.php/../../other.php。 php_fastcgi 重写现在也始终运行（见上文）。谢谢@pamnario。 (GHSA-f278-mgc7-46j3)
  • 文件服务器：file 匹配器不再将 /.env/./ 等路径解析为常规文件，这绕过了 path *.env 等路径规则。谢谢@dunglas。 （GHSA-25cw-38mq-q7m6，#8326）
  • 重写：{http.matchers.file.remainder} 现在在重写之前进行转义，因此双编码路径信息（如 ..%252f）在路径规则运行后无法转换为 ../。谢谢@dunglas。 （GHSA-69hv-5jfc-mvmv，#8325）
  • 文件服务器：当 HOME 和 XDG_DATA_HOME 均未设置时，Caddy 的数据目录回退到 ./caddy，并且为工作目录提供服务的 file_server 可能会暴露证书和私钥。该目录现在始终处于隐藏状态。谢谢@dunglas。 （GHSA-jf74-f69g-hcj9，#8327）
  • fastcgi：带有 index.php 的目录的 php_fastcgi 尾部斜杠重定向不能再转换为到另一个站点的开放重定向。谢谢@sam-kota。 (#8285)
  • 文件服务器：使用 hide 排除的文件不再显示在 browse 列表中，并且不再提供隐藏的 precompressed sidecar。谢谢@agammann。 (#8155)
  • 反向代理：从 1xx 响应和 handle_response 中的 copy_response_headers 中删除逐跳标头，完成对 CVE-2026-55458 的修复。感谢@SssiiiSssii1 和@tomholford。 （GHSA-8qx7-j2v2-x6q5，#8256，#8270）
  • 日志记录：query 日志过滤器现在像服务器一样解析请求 URI，因此 # 之后的参数也会被编辑。谢谢@jayhemnani9910。 (#8255)

：警告：如果您的应用程序依赖于错误行为，这些安全补丁可能会被破坏。

:rotating_light: Caddy 插件维护者注意事项：Dependabot 可能会提醒您 Caddy 中的安全修复程序，并敦促您在 go.mod 文件中升级它。如果您的插件使用的导出 API 发生更改，请仅升级 Caddy 依赖项。
