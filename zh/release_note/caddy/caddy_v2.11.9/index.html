caddy v2.11.9

这是 2.11.8 之上的快速后续，以修复它引入的回归和其他一些安全问题，主要是在 FastCGI 中。它仅包含从 master 向后移植的修复程序，以及一些小的添加内容。 如果您使用的是 2.11.8 并提供 PHP，我们建议您升级。

非常感谢我们的赞助商提供的资源让项目保持活力，也感谢我们的维护人员在这个残酷的人工智能新时代孜孜不倦地进行分类和协助。

亮点

  • 已修复：PHP 目录索引（2.11.8 中的回归）。 对带有尾部斜杠的目录（例如 /wp-admin/）的请求与目录本身而不是 index.php 相匹配，因此它从未到达 PHP，并且通常会收到 404。这会破坏 WordPress 管理页面和其他通过尾部斜杠 URL 提供索引的应用程序。 try_files 模式现在仅匹配以 / 结尾的目录。谢谢@dunglas！ (#8352)
  • 带有占位符的路径匹配器现在按预期工作：像 {env.FOO} 这样的占位符在查找之前不再小写为 {env.foo}，并且它们的值不区分大小写地与请求路径进行比较，就像静态模式一样。谢谢@BenMacha！ (#8343)
  • file_server browse 的新 plain_time_format 选项： 设置纯文本目录列表 (Accept: text/plain) 的时间布局。谢谢@steffenbusch！ (#8084)
  • 路径清理、标头重写和 weighted_round_robin 选择中的分配更少。谢谢@jvoisin！ (#7842)
  • 对于插件作者： 新的 httpcaddyfile.Helper.IsNamedRoute() 告诉指令是否在 命名路由 内解析它。 (#8354)

：警告：重大更改

  • 冲突的 client_auth 现在是 Caddyfile 错误。 当两个站点块共享同一主机名的 TLS 连接策略但设置不同的 client_auth 时，适配器用于保留第一个并默默地删除另一个，这可以悄悄地删除更严格的 mTLS 要求。 (#8306)
  • 对于运行哪个脚本不明确的 FastCGI 请求会得到 400：
    • 当转义路径（包含 % 的路径匹配器看到）和解码路径将选择不同的脚本时，例如/public/tool.php%2f..%2f..%2fadmin%2ftool.php (#8357)
    • 在 Windows 上，带有 8.3 短名称组件（如 ADMINI~1）或 :（NTFS 备用数据流）的脚本路径 (#8356)
  • FastCGI env 值现在优先于请求标头，因此 client 无法再覆盖您使用 env 设置的 HTTP_* 变量（见下文）。 (#8358)

安全修复

感谢所有负责任地报告并帮助修复补丁的人：

  • fastcgi：client 可以通过发送匹配的请求标头来覆盖使用 FastCGI 传输（或 php_fastcgi 的）env 子指令设置的任何 HTTP_* 变量，例如选择应用程序在 HTTP_X_AUTH_USER 中看到的用户。配置值现在获胜。由@JebeenLee 和@Camel4 报告，由@dunglas 修复。 （GHSA-q34h-28rj-5hjm，#8358）
  • fastcgi：在 Windows 上，NTFS 8.3 短名称和备用数据流可以运行路径规则本应拒绝的脚本，从而完成 2.11.8 的 FastCGI 修复。谢谢@dunglas。 （GHSA-9cr8-wmhh-39pm，#8356）
  • fastcgi：编码的斜线和点段可以使包含 % 的路径匹配器在运行另一个脚本时批准一个脚本。谢谢@dunglas。 (#8357)
  • fastcgi：通过 HTTP/2，在 :authority 旁边发送的 host 字段可能会使应用程序看到与 Caddy 将请求路由到的主机不同的主机 (HTTP_HOST)。谢谢@dunglas。 (#8355)
  • httpcaddyfile：合并 TLS 连接策略时，可能会默默地删除更严格的 client_auth（参见上文）。谢谢@sam-kota。 (#8306)
  • 将 GHSA-mgcc-cww5-fp2q 的 go-jose 更新为 v4.1.6。 (#8299)

：警告：如果您的应用程序依赖于错误行为，这些安全补丁可能会被破坏。

:rotating_light: Caddy 插件维护者注意事项：Dependabot 可能会提醒您 Caddy 中的安全修复程序，并敦促您在 go.mod 文件中升级它。如果您的插件使用的导出 API 发生更改，请仅升级 Caddy 依赖项。

发生了什么变化

  • caddyhttp：在请求时带有占位符的小写路径模式，由 @BenMacha 在 https://github.com/caddyserver/caddy/pull/8343 中提供
  • httpcaddyfile：在 https://github.com/caddyserver/caddy/pull/8306 中通过 @sam-kota 合并 TLS 策略时拒绝冲突的 client_auth
  • build(deps)：在https://github.com/caddyserver/caddy/pull/8340中@dependabot[bot]通过10个更新在1个目录中碰撞actions-deps组
  • 构建（deps）：通过 https://github.com/caddyserver/caddy/pull/8299 中的 @dependabot[bot] 将 github.com/go-jose/go-jose/v4 从 4.1.5 提升到 4.1.6
  • 文件服务器：在https://github.com/caddyserver/caddy/pull/8084中通过@steffenbusch配置纯文本浏览时间格式
  • 文件服务器：仅当模式以 https://github.com/caddyserver/caddy/pull/8352 中的 / by @dunglas 结尾时才匹配目录
  • httpcaddyfile: 在 https://github.com/caddyserver/caddy/pull/8354 中添加 @dunglas 的 Helper.IsNamedRoute
  • fastcgi：仅通过https://github.com/caddyserver/caddy/pull/8355中的@dunglas从路由主机获取HTTP_HOST
  • fastcgi：拒绝 https://github.com/caddyserver/caddy/pull/8356 中 @dunglas 的 Win 8.3 别名和替代数据流路径
  • caddyhttp：预先确定热路径中的缓冲区大小以减少https://github.com/caddyserver/caddy/pull/7842中@jvoisin的分配
  • fastcgi：让配置的环境变量覆盖https://github.com/caddyserver/caddy/pull/8358中@dunglas的请求标头
  • fastcgi：拒绝其转义形式选择 https://github.com/caddyserver/caddy/pull/8357 中@dunglas 的另一个脚本的路径
