caddy v2.11.6

此补丁版本包含大量次要和一些显着的增强功能和错误修复。感谢所有负责任地贡献或花费 LLM 代币来帮助此版本发布的人！

我们还有更多的工作要做，因为人工智能已经以廉价且简单的方式为所有质量水平做出了贡献。我们将尽力尽快、高效地处理这些问题。

非常感谢我们的赞助商提供的资源让项目保持活力，也感谢我们的维护人员在这个残酷的人工智能新时代孜孜不倦地进行分类和协助。

：警告： 请在升级之前阅读下面的重大更改。 其中大多数来自安全强化，大多数配置不会注意到。但是，如果您依赖于其中一种旧行为，您会想了解它。

亮点

  • 新的 url_pattern 请求匹配器： 使用 URLPattern 标准匹配请求，浏览器 (JS) 和许多 Web 框架使用相同的语法。它支持命名组、通配符和正则表达式组件。捕获的组成为占位符 ({http.url_pattern.<component>.<group>})，并且还有一个匹配的 url_pattern CEL 函数。谢谢@dunglas！ (#7787)
  • Slowloris 缓解措施： 每次成功读取或写入时都会重置新的空闲读取/写入超时。停滞的连接会被切断，而缓慢但仍在进展的连接则被留下。您还可以设置可选的最低传输速率，并且有一个新的 timeouts 处理程序指令用于每条路由的调整。 (#7913)
  • 新的 tls_automate_names 全局选项： 管理名称证书，而不在站点块中提供它们。 （#8015）
  • 新的 expected_underscore_headers 服务器选项： 如果在 2.11.4 中删除带下划线的标头字段会破坏您的应用程序，您现在可以列出要保留的特定标头。 （#7809）
  • **通过 Tailscale 和其他低 MTU 链接的 HTTP/3 现在可以正常工作，因为初始 QUIC 数据包大小较小。 (#7886)
  • 反向代理得到更多的喜爱：
    • 部分响应正确刷新到 clients (#7849)
    • TCP 半关闭在升级的流上传播 (#8027)
    • versions 3 上游现在尊重 tls_trust_pool (#8042)
    • 主动运行状况检查 状态在每个检查配置中保持独立，因此一个处理程序的失败探测器不会为其他所有人标记上游 (#7916)
    • random_choose 策略现在可以正确分发 (#7873)
  • 服务器在 encode 后面发送的事件现在立即流式传输，而不是进行缓冲。 (#7905)
  • 优雅关闭现在等待先前配置留下的服务器，因此在重新加载之前启动的长期响应不会在退出时被切断。 （#8009）
  • Caddyfile: import 现在可以在 命名路由 (#7986) 中工作，并且引号被视为文字参数 (#7875)。
  • 记录：
    • 新的 set_cookie 日志过滤器 (#7888)
    • roll_interval 接受天数 (d) (#7900)
    • 恢复的处理程序恐慌记录在错误级别 (#7924)
    • 访问日志中显示写入超时错误 (#7945)
  • **性能：**来自 @jvoisin 和 @dunglas 的请求热路径、编码协商和反向代理中的分配更少。对于大型目录，目录浏览速度要快得多。 （#7847、#7903、#7911、#7925、#7926、#7936）
  • 其他新东西：
    • {http.request.proto_name} 占位符 (#7782)
    • FastCGI 填充 SERVER_ADDR (#7912)
  • 多个 authentication 提供商不再破坏彼此的响应 (#7904)

：警告：重大更改

  • Go 1.26 现在是构建 Caddy 和插件的最低版本。 (#8056)
  • 请求标头默认限制为 16 KiB。 之前，我们使用 Go 的 1 MB 默认值。具有较大标头（巨型 cookie、超大令牌等）的请求现在将获得 431 Request Header Fields Too Large。如果您需要更多，请使用 max_header_size 服务器选项来提高它。
  • 默认情况下新的 1 分钟空闲读/写超时。 如果请求正文读取或响应写入停止（根本没有任何进展）的时间超过此时间，连接将中止。 在写入之间的暂停（如 SSE）不计算在内。 client 在身体中部变得安静的一些长期存在的流可能会受到影响。您可以使用 timeouts 服务器选项中的 read_body_idle 和 write_idle 进行调整，或者使用 timeouts 指令针对每个路由进行调整。 (#7913)
  • 包含 . 的请求标头字段现已删除，与 2.11.4 中的下划线相同。 PHP 将 . 折叠为 _，因此这些可用于模拟合法标头。如果您需要特定的，请使用新的 expected_dot_headers 服务器选项来允许它们。
  • 通配符站点的 client_auth 不再适用于具有自己的站点块的更具体的主机名。 例如，public.example.com 不再从 *.example.com 继承 mTLS。如果您依赖于该继承，请在特定站点上显式配置 client_auth。 (#7920)
  • 更严格的配置验证。 一些过去被默默接受的配置（并且可能没有达到您的预期）现在是错误：
    • 重复 named_routes (#7800)
    • 重复 forward_auth uri (#7814)
    • 无效的 weighted_round_robin 权重 (#7807)
    • 非整数 browse file_limit (#7988)
    • 重复或不明确的 map 输入 (#8067)
    • 格式错误的 map 目标占位符 (#8074)
    • 具有不明确的 @ 版本分隔符的模块路径 (#7974)
  • 管理员 API /load 现在当配置无效时返回 400，并在有效的 JSON 主体内发出警告。之前，它返回 200 和两个串联的 JSON 对象。 (#7267)
  • method 匹配器值标准化为大写，因此 method get 现在匹配 GET 请求。 (#7832)

安全修复

感谢所有负责任地报告并帮助修复补丁的人：

  • 反向代理：当路由同时使用 forward_auth 和 reverse_proxy 时，可能会在错误的上游连接上发送请求。由@carlt 报告，由@WeidiDeng 修复。 （GHSA-6365-7ppr-5r92，#7859）
  • 反向代理：来自上游的逐跳标头现在也从 101 Switching Protocols 响应中删除。谢谢@jirn073-76。
  • caddyhttp: handle_path 和 uri strip_prefix/strip_suffix 现在规范化结果路径，因此它无法绕过基于路径的授权。谢谢@steadytao。
  • caddyhttp：将 2.11.4 标头别名过滤器扩展到 .（见上文），以防止 PHP/FastCGI 后端绕过 forward_auth copy_headers。谢谢@dunglas。
  • caddyhttp：path_regexp 匹配器现在像 path 匹配器一样标准化 Windows 反斜杠。这样就完成了 CVE-2026-52844 的修复。谢谢@thientd。 (#7858)
  • 文件服务器：Windows 8.3 短名称在每个路径组件中都被拒绝，而不仅仅是最后一个。谢谢@DavidCarliez。 (#7952)
  • 文件服务器：修复了不同修改时间和大小的文件之间的 ETag 冲突。谢谢@dunglas。
  • fastcgi：client 的 Proxy 标头不再作为 HTTP_PROXY (HTTPoxy) 传递到后端。谢谢@bzyy1024。 (#7934) -反向代理：在恒定时间内比较粘性会话cookie哈希值。谢谢@alhudz。 (#7853)
  • 管理：请求路径在远程管理访问检查中标准化，源/主机允许列表不区分大小写进行比较（深度防御）。感谢@AmariahAK、@mohammed90 和@hktitof。 （＃7910，＃7973，＃7993）
  • caddyhttp：通过占位符使用的超大请求主体现在可以正确返回 413。谢谢@hktitof。 (#7969)

：警告：如果您的应用程序依赖于错误行为，这些安全补丁可能会被破坏。

:rotating_light: Caddy 插件维护者注意事项：Dependabot 可能会提醒您 Caddy 中的安全修复程序，并敦促您在 go.mod 文件中升级它。如果您的插件使用的导出 API 发生更改，请仅升级 Caddy 依赖项。 请注意，现在执行此操作还需要 Go 1.26。
