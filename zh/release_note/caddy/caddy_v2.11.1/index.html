caddy v2.11.1

我们的社区很高兴推出 Caddy 2.11！值得注意的是新功能、大量错误修复（包括多个安全补丁）以及各种 QoL（“生活质量”）增强功能。

除了 CI 作业之外，v2.11.0 没有任何代码更改。由于最近的外部更改破坏了我们的发布流程，2.11 的第一个版本是 v2.11.1。

特别赞助商鸣谢

特别感谢我们的主要赞助商：

  • ZeroSSL
  • 条纹
  • 铁路

他们与数十个较小的赞助商以及我们的维护团队一起使这个项目和新版本成为可能。谢谢大家！

显着变化

  • 加密的 ClientHello (ECH) 密钥会自动轮换。
  • 日志的时间滚动选项。
  • 如果配置最初是从命令行上的文件加载并且未通过 API 更改，SIGUSR1 现在可以重新加载配置。
  • 当上游为 HTTPS 时，反向代理现在会自动将主机标头重写为上游的地址 (#7454)
  • log_append 现在可以记录请求和响应主体，这对于调试很有用。
  • 我们的项目现在实施并要求对问题、PR、评论、回复、评论等进行协助披露（针对 AI/LLM）。
  • 很多很多其他的小改进和错误修复。

感谢参与此版本发布的所有人！

：警告：安全补丁

  • fastcgi：@dunglas 和 @AbdrrahimDahmani 的 CVE-2026-27590 - Unicode 大小写折叠长度扩展导致 FastCGI 传输中不正确的 split_path 索引（SCRIPT_NAME/PATH_INFO 混淆）。
  • admin：@1seal 的 CVE-2026-27589 - 使用 no-cors 模式尝试跨源请求可能会导致某些 API 请求成功；此类请求现已被阻止。 （为了使其实际上可被利用，执行恶意网页的 Web 浏览器必须在生产 Caddy 进程的本地运行。）
  • caddyhttp: CVE-2026-27588，作者：Asim Viladi Oglu Manizada - 对于大型主机列表 (>100)，主机匹配器变得区分大小写，从而启用基于主机的路由/身份验证旁路。
  • caddyhttp: CVE-2026-27587，作者：Asim Viladi Oglu Manizada - 路径匹配器跳过转义序列的大小写标准化，从而实现基于路径的路由/身份验证旁路。
  • caddytls：@moscowchill 的 CVE-2026-27586 - 当 CA 证书文件丢失或格式错误时，TLS client 身份验证将无法静默打开。
  • caddyhttp: CVE-2026-27585 by @parrot409 - 文件匹配器中的 glob 字符清理不当可能会导致绕过安全保护。

:rotating_light: Caddy 插件维护者注意事项：Dependabot 可能会提醒您 Caddy 中的安全修复程序，并敦促您在 go.mod 文件中升级它。如果您的插件使用的导出 API 发生更改，请仅升级 Caddy 依赖项。（然后，关闭 Dependabot。）
