重大变更

  • JUL (java.util.logging) 配置对服务器端组件不再有效 (#26330)

    此前，来自使用 JUL 的第三方库（例如 Jersey/Jetty、gRPC、Guava）的日志不受 Pulsar 的 Log4j2 配置管理，这使得它们难以控制并导致日志输出不一致。为了解决这个问题，第三方库日志记录现在通过 log4j-jul 从 JUL 桥接到 Log4j2。这统一了 conf/log4j2.yaml 下的所有日志记录，但意味着以下 JUL API 和配置不再生效：

    • -Djava.util.logging.config.file=logging.properties — 整个 JUL 配置文件被忽略
    • java.util.logging.Logger.setLevel() / addHandler() — 变为无操作
    • java.util.logging.LogManager.reset() — 变为无操作

    迁移：将任何基于 JUL 的日志记录配置移至 conf/log4j2.yaml。例如，要抑制之前在 logging.properties 中配置为 io.grpc.level=SEVERE 的 gRPC 日志，请将以下内容添加到 conf/log4j2.yaml：

    Loggers:
  Logger:
    - name: io.grpc
      level: error

    恢复：要恢复库存 JUL 行为，请设置：

    PULSAR_EXTRA_OPTS="-Djava.util.logging.manager=java.util.logging.LogManager"
