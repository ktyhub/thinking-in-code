adk-python v2.7.0

2.7.0 (2026-08-13)

亮点

正确性发布：大部分工作涉及代理向模型发送的内容以及返回的内容，以及跨工具、会话、评估和 CLI 的长尾修复。

  • 模型声明自己的功能：当模型实际支持它时，代理将输出模式与工具配对，而不是 ADK 从模型 ID 推断支持。 （[2aff82c]（https://github.com/google/adk-python/commit/2aff82c30923e5f7df5ce4101db52bce82740329），[dc5dbfa]（https://github.com/google/adk-python/commit/dc5dbfa2e475f2461177e80f7fa28c96a2bc3592））
  • 工具可以返回媒体：工具的功能响应将图像和其他媒体直接带回模型，在 Gemini 和 Anthropic、LiteLLM、Apigee 和 OCI 上都是如此。 （[df9d6de]（https://github.com/google/adk-python/commit/df9d6dec58f4cb22a1010b72e9fd8d347ce8145a），[703cf43]（https://github.com/google/adk-python/commit/703cf43f6b03550ec2b02def526f3f4ba98f7abd））
  • 对话历史记录保留了 Gemini 所需的：思想签名、服务器端工具调用部分以及并行函数调用的每个结果在往返过程中都保留下来。 (d4ed347、e908137、93dff41)
  • Jinja2 指令模板：将 use_jinja2=True 传递到 inject_session_state，并且指令可以在会话状态上使用条件和循环，并通过 {{ artifact("name") }} 帮助程序加载工件。 Jinja2 仍然是可选依赖项，正则表达式引擎仍然是默认的。 (4a00a34)
  • 更快的启动和热路径：import google.adk 的工作量更少，并且请求路径避免了 LiteLLM 适配器中的 Pydantic 往返和二次流累积。 (8806dc2、9e1adde、36fd2c8)

重大变更

  • pyarrow 留下了 gcp extra：它位于新的 bigquery-analytics extra 中，比 pip install google-adk[gcp] 少了大约 50 MB。如果您使用 BigQueryAgentAnalyticsPlugin，请安装 google-adk[bigquery-analytics]。 (ac71709)

⚠ 重大变更

  • deps: 将 pyarrow 从 gcp extra 中移出 <详情>
