ray 2.59.1

ray 2.59.1

安全修复

eMudhra 中间 CA 妥协

据报道，eMudhra 中间 CA 密钥已于 2026 年 10 月 20 日遭到泄露。除了系统存储之外，pip trust 还拥有自己的供应商证书捆绑包，因此单独更新操作系统 ca-certificates 并不能保护 pip。此版本将 Ray 安装的每个位置或将 CA 捆绑包捆绑到固定版本：

  • Docker 图像：每个 Python 版本上的 pip 26.2.2、conda 和站点包证书 2026.10.19、uv 0.13.4（#67295、#67350、选择 #67487）。
  • virtualenv 21.14.12，它为 runtime_env virtualenvs 捆绑了 pip 26.2.2。这也会将 packaging 移动到 26.3，typing-extensions 移动到 4.16.0，distlib 移动到 0.4.3，python-discovery 移动到 1.6.1（#67301，选择 #67487）。
  • Ray 安全要求中的 certifi>=2026.10.19 楼层（#67305，选择 #67487）。
  • Windows 和 macOS 轮子版本中的 pip 26.2.2 和 uv 0.13.4 (#67298，选择 #67487)。发货的车轮不提供 CA 捆绑包，因此不受影响。

aiohttp

  • 捆绑的 Runtime_env 代理依赖项、ray[default] 和映像中的 aiohttp 3.14.3 → 3.14.4（和 yarl 1.23.0 → 1.25.1）。修复了 CVE-2026-111064、CVE-2026-111066 和 GHSA-2g87-pp6c-29x5（#67304，选择 #67487；在 #67302 中报告）。

错误修复

射线数据

  • 将 pandas 元数据保留在 Arrow 块上，可供 pandas 读取。 pandas 无法解析的 Dtype 名称现在写为 `object`，因此将这些块或文件转换回 pandas 不再失败（#67576，选择 #67649）。

雷发球

  • 入口请求路由器部署不再在其运行的节点上保留代理。这些节点现在可以正常缩小（#65824，选择#67633）。
