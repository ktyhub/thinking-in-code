v3.0.5

发布日期：2026 年 10 月 30 日

3.0.5 3.0.2 3.0.6 3.0.12 3.0.0

我们很高兴地宣布 Milvus v3.0.5 发布！此版本在 QueryCoord 中添加了资源组感知负载状态，减少了多个路径中的内存使用。它还修复了协调器重启、滚动升级和暂时性 etcd 错误等稳定性问题。

改进

  • 在 QueryCoord 中添加了每个资源组的负载百分比和分片领导者准备情况，并使用其副本的资源组标记每个分片领导者，因此可以在单个资源组内路由查询（#52500、#52711）
  • 通过直接借用解码后的发帖块，减少了未评分的 Tantivy 术语查询中的复制（#54469）
  • 将 Knowhere 升级到 v3.0.17 并将可空向量偏移映射移至 Knowhere API 后面 (#54473)
  • 通过重用每个请求编码缓冲区来编码批量 RESTful 查询和搜索响应时减少内存分配 (#54540)
  • 通过在分析器过滤器中重用已编译的正则表达式和每个过滤器搜索缓存来提高文本分析器性能（#54570）
  • 添加了一个可选的两层混合压缩规划器（dataCoord.compaction.twoTierCompaction，默认关闭）以减少压缩写入放大（[#54589]（https://github.com/milvus-io/milvus/pull/54589））
  • 加载小型密封段时减少了时间戳索引内存使用量（#54659）
  • 将缺失的 status="fail" 标签添加到失败的 get 操作的 internal_storage_op_count 指标中；旧的未标记系列停止，新系列从零开始（#54637）
  • 资源组名称中第一个字符后允许使用连字符，符合分区的命名规则 (#54679)
  • 通过跨记录重用输出列来减少压缩合并排序中的内存分配（#54718）

错误修复

  • 修复了具有结构数组字段的集合可能会在首次搜索时或缓存驱逐后强制加载原始嵌入列表向量，从而增加内存使用量和查询延迟的问题 (#54167)
  • 修复了启用 CMEK 的集合上的更新插入将删除部分（主键和时间戳）写入 WAL 而不加密的问题 (#54478)
  • 修复了 ST_DWITHIN 过滤器在具有 RTREE 索引的段上返回的行数少于未索引段上的行数的问题；空几何图形不再匹配 ST_DWITHIN，与 PostGIS 一致（#54611）
  • 修复了协调器重新启动后写入存储 V3 段可能会停止的问题，因为下一次刷新使用的列布局与提交的清单冲突 (#54652)
  • 修复了从与其他集合共享物理通道的已删除数据库重播加密 WAL 消息时 QueryNode 可能会出现恐慌的问题 (#54640)
  • 修复了当省略字段且批次包含新主键时，对具有可为空结构数组字段的集合进行部分更新插入失败的问题 (#54619)
  • 修复了查询索引状态时删除分区时索引状态被错误报告为“失败”的问题 (#54670)
  • 修复了在任务执行的同时序列化同步任务统计数据时的数据争用 (#54610)
  • 修复了为字段指定非整数 max_length 返回原始解析错误而不是命名字段的无效参数错误的问题 (#54694)
  • 修复了滚动升级期间停止 MixCoord 时出现的恐慌，导致核心转储并使旧 Pod 陷入终止状态几分钟 (#54732)
  • 修复了 Milvus Backup 无法复制 FlushAll 返回的刷新位置的问题 (#54745)
  • 修复了 MixCoord 和其他组件因暂时性 etcd 错误（例如领导者更改）而崩溃的问题，这可能会导致规模缩小停止；他们现在重试并重新观看，直到 etcd 恢复（#54754）
  • 修复了同时停止集群的所有查询节点可能会挂起直至正常停止超时（默认为 30 分钟）的问题；将 queryNode.standaloneMigrateDataTimeout 重命名为 queryNode.migrateDataTimeout，旧密钥仍然有效 (#54813)
  • 修复了切换消息队列（例如从 Pulsar 切换到 Woodpecker）后，查询节点可能会从不兼容的位置不断重新连接并停止消耗数据的问题 (#54811)
