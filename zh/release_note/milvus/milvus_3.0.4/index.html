milvus v3.0.4

v3.0.4

发布日期：2026 年 10 月 26 日

3.0.4 3.0.2 3.0.6 3.0.10 3.0.0

我们很高兴地宣布 Milvus v3.0.4 发布！此版本加快了批量导入、压缩以及过滤和分组搜索的速度，为 Storage V3 添加了惰性列组加载，并修复了导入、集合加载和部分更新写入中的挂起，以及多个访问控制问题和 CVE。

改进

  • 通过并行读取输入块并急切地预取字节范围来提高排序压缩读取吞吐量（#53437）
  • 添加了对由 Parquet、Lance 和 Vortex 文件支持的外部集合中预先计算的稀疏向量的支持 (#53894)
  • 将代理 DML 任务重构为专用包以分离任务职责（#54064）
  • 确保密封段搜索的所有输出字段都从与搜索本身相同的段快照填充（#54074）
  • 添加了 queryNode.segcore.tieredStorage.lazyColumnGroupEnabled 选项（默认禁用）以推迟加载 Storage V3 列组直到首次访问，从而减少段加载时间和内存使用量 (#54169)
  • 添加了 autoIndex.params.sparse.ip.build 和 autoIndex.params.sparse.bm25.build 来分别为 IP 和 BM25 指标配置稀疏 AutoIndex 构建参数，回退到 autoIndex.params.sparse.build (#54212)
  • 通过在 CheckHealth 期间不再收集 DataCoord 自指标，减少了具有大型段元数据的集群上的运行状况检查延迟 (#54214)
  • 通过按作业 ID 对导入任务建立索引，改进了具有许多导入作业的集群的 DataCoord 导入调度性能 (#54202)
  • 通过每个 GC 周期扫描一次过时的 JSON 统计前缀，而不是每个段一次，减少垃圾收集期间的对象存储列表请求 (#54207)
  • 通过从现有数组块偏移中读取长度，改进了密封段上的 ARRAY_LENGTH 过滤器性能，将客户过滤器工作负载的 QPS 从 102 提高到 270 (#54321)
  • 将 grpc-go 升级到 v1.84.0，以便代理在解码后立即释放原始请求缓冲区，从而为每个正在进行的大型搜索节省堆的完整请求大小（对于 nq=10000、1536-dim 搜索为 61.5 MB）（#54271）
  • 添加了隐藏的 streaming.partialUpdate.enableCAS 选项（默认启用）以关闭 StreamingNode 上部分更新的比较和交换检查，以防止并发过时更新来降低写入开销（#54249）
  • 删除了代理记录每个成功查询的虚假“状态为零”警告（#54247）
  • 解码 RESTful V2 插入和更新插入请求时减少内存分配，并在转换失败时停止记录完整请求负载 (#54403)
  • 重新设计批量导入以在预导入后分配准确的每个文件 ID 范围，因此导入请求会立即返回，而无需预先调整文件大小，并修复了导入写入重试期间的日志 ID 耗尽问题 (#54416)
  • 添加了启动配置选项以覆盖 IP 和 BM25 稀疏向量字段的临时索引算法 (#54441)
  • 将 1.26.9 和 golang.org/x/net 升级到 v0.60.0 以解决 CVE-2026-78667、CVE-2026-97031 和 CVE-2026-78669 (#54451)
  • 通过从 JSON 粉碎统计数据中读取 VARCHAR、BOOL 和整数组键，而不是解析原始 JSON，改进了密封段中类型化 JSON 路径上的搜索分组 (#54456)
  • 将 OpenTelemetry 升级到 1.45.0，将 cilium/ebpf 升级到 0.22.0，并更新运行时映像中的curl、tar、zlib 和 glibc，以解决 CVE-2026-81870 和 CVE-2026-10722 (#54461)
  • 通过仅在缓存未命中时转换术语，减少了索引 ARRAY_CONTAINS 过滤器的冗余查询术语转换（#54459、#54465）
  • 通过连续安排导入任务而不是等待每个批次完成来提高导入吞吐量 (#54471)
  • 在 CDC 复制设置中的主集群和辅助集群上添加了对集群本地 Flush 和 FlushAll 的支持 (#54502)
  • 将搜索扇出工作（PK 填充、距离细化和输出字段具体化）放入专用线程池中，以便搜索不再在字段和索引加载后面排队（#54524）
