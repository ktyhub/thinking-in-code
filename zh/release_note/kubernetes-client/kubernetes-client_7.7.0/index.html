kubernetes-client v7.7.0

小版本 发布时间2026年5月12日 来源fabric8io/kubernetes-client 英文原文

kubernetes-client v7.7.0

错误

  • 修复#7747：（mockwebserver）避免 MockWebServer#shutdown() 中的 RejectedExecutionException - 线性化关闭序列以删除 httpClose-listener 与等待竞争，并使 shutdown() 针对重复调用具有幂等性（例如 JUnit @Nested afterAll 级联）
  • 修复#7734：（mockwebserver）避免将内容长度与传输编码一起发送以进行分块响应
  • 修复#7716：（举报者）SerialExecutor.execute() 现在在关闭后立即返回 - 不提供包装器，不调用scheduleNext()，并且不触及底层执行器，修复了 stop() 之后 SharedProcessor.distribute(…) 暴露的停止后 NPE 竞争
  • 修复 #7702：ExecWebSocketListener.onError 现在通过链接 KubernetesClientException 构造函数而不是事后 initCause 包装 WebSocketHandshakeException - 具有非空升级响应的握手失败不再同步抛出 IllegalStateException，因此 onFailure/exitCode 接收解析的 Status 和原始握手异常作为原因
  • 修复#7686：(httpclient-vertx-5) StackBasedRecursionGuard.enter() 在拒绝进入时不再增加深度，修复了无限 runOnContext 循环，该循环在 CPU 争用下停止了 InputStreamReadStream 上传
  • 修复#7700：ExecWebSocketListener.onError 现在通过 SerialExecutor 推迟失败处理，因此挂起的通道 3 退出状态任务首先运行，并且保留解析的退出代码，而不是被对等关闭异常覆盖
  • 修复#7698：（httpclient-vertx-5）InputStreamReadStream 现在在已传递结束信号后注册时会触发 endHandler，修复了空/快速流的竞争
  • 修复 #7696：(httpclient-vertx) 在 cancel() 中重置之前清除响应异常处理程序，以防止 StreamResetException 与未来的取消竞争
  • 修复#7695：ExecWebSocketListener 现在通过 SerialExecutor 推迟 exitCode 完成，因此挂起的 stdout/stderr 异步写入会在退出信号之前刷新
  • 修复#7632：java-generator 现在在 CRD 描述中对 <、> 和 & 进行 HTML 转义以生成有效的 Javadoc
  • 修复#7543：修复 processInlineDuplicateFields 以递归解析嵌套内联嵌入
  • 修复#7450：StandardHttpClient.shouldRetry() 不会在 Vert.x HttpClosedException 上重试
  • 修复#7350：领导者选举中回调时机不当导致双领导者
  • 修复#7265：修复从通知者缓存中暂时删除索引条目的问题

改进

  • 修复#7426：添加 HasMetadata#isSameResource 来测试两个 HasMetadata 实例是否指向同一逻辑集群资源，并具有可选的严格模式，该模式还需要匹配种类和资源版本
  • 修复#7662：（mockwebserver）新的 MockWebServer#setHttp2ClearTextEnabled(boolean) setter 选择退出 HTTP/2 明文 (h2c) 升级
  • 修复#7522：改进 kubernetes-httpclient-okhttp 的依赖管理
  • 修复#7550：添加 ResourceEventHandler onList 方法并弃用 onNothing
  • 修复#6922：添加 addOwnerReference 变体来设置控制器和 blockOwnerDeletion 字段
  • 修复#3396：（mockwebserver）增强自签名证书生成，以包含主题备用名称（SAN），以便现代 clients 进行正确的 TLS 验证
  • 修复#6923：使 crd-generator-maven-plugin 能够感知工具链
