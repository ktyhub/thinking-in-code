kubernetes-client v8.0.0

kubernetes-client v8.0.0

错误

  • 修复#8105：当重试操作、重试决策或响应清理抛出异常时，请求挂起。
  • 修复#7374：（crd-generator）生成的 CRD 不再修剪或拒绝 client 写入的内容：Object、原始 Map、List<Object>、原始集合、@JsonUnwrapped 和多态属性保留其内容，日期和时间类型仅声明其值匹配的格式（Duration、LocalDateTime 和部分类型丢失） date-time）。 Optional 属性获取其值类型的架构，而不是保留未知字段，请参阅迁移指南
  • 修复 #6779：(httpclient-jetty) 没有 WWW-Authenticate 标头（这是 API 服务器发送它们的方式）的 401 响应与其正文一起返回，而不是因“HTTP 协议违规：没有 WWW-Authenticate 标头的身份验证质询”而失败
  • 修复#6779：（httpclient-jetty、httpclient-vertx、httpclient-vertx-5）现在使用包含冒号的代理密码或包含用户但没有密码的代理 URL 来对代理进行身份验证，而不是回退到 HTTPS 请求通过代理隧道传送到 API 服务器的 Proxy-Authorization 请求标头
  • 修复 #6779：未配置密码的代理用户名将使用空密码而不是 null 发送，并且带有用户但无密码的代理 URL 作为 user: 而不是 user (RFC 7617)
  • 修复 #8134：(httpclient-jetty) 失败的 WebSocket 握手不再调用侦听器的 onError，返回的 future 已经随之失败。当重试握手时，这会在重试打开监视和执行/附加会话之前结束它们
  • 修复#8134：(httpclient-jetty) SOCKS5 代理的凭据发送给它
  • 修复 #8134：（httpclient-jetty、httpclient-vertx）非 Basic user:password 的代理凭据仅作为 Proxy-Authorization 标头添加到 HTTP 代理读取的请求中。 HTTPS 和 WSS 请求、Vert.x 隧道的 WebSocket 以及通过 SOCKS 代理的请求将它们传送到 API 服务器
  • 修复 #8134：(httpclient-vertx-5) 非 Basic user:password 的代理凭据也会由 Vert.x 在 CONNECT 上发送到 HTTP 代理，因此 HTTPS 和 WebSocket 请求通过需要它们工作的代理，并且它们不再到达 API 服务器
  • 修复 #8134：(httpclient-okhttp) 来自 API 服务器（例如通过 pods/proxy）的 407 不再使用通过代理隧道到达它的代理凭据进行应答，并且不会再次发送代理拒绝的凭据
  • 修复 #8140：(httpclient-vertx-5) 在写入之前连接已关闭的请求会失败并显示 IOException，并且会重试，而不是挂起直到请求超时（在 Windows 上可见）
  • 修复 #8134：(httpclient-jetty) 由响应设置的 Cookie 不再在以后的请求和 WebSocket 升级中发回，就像其他 HttpClient 实现一样
  • 修复#8109：写为 yyyy-MM-dd 的 java.sql.Date 被读取为本地日期，而不是 UTC 以西的前一天。 Year、Month、java.sql.Date 和 Locale 保留其 7.x 有线格式，您自己构建的映射器需要新的 Jackson2JdkTypesModule，请参阅迁移指南
  • 修复#8109：（crd-generator）byte[]、ByteBuffer、char[]、Year 和 java.sql.Date 模式与 client 写入的内容匹配（byte[] 和 ByteBuffer 是 format: byte 字符串），因此 API 服务器不再拒绝它们。 LocalDate 上的 @PrinterColumn 是 string 色谱柱，而不是显示 <invalid> 的 date 色谱柱
  • 修复 #8008：(httpclient-vertx-5) 具有 InputStream 正文和 Expect: 100-continue（二进制版本）的请求不再挂起，并且已知长度的 InputStream 正文与 Content-Length 一起发送，而不是分块
  • 修复 #8139：(httpclient-okhttp) 即使侦听器没有响应，WebSocket 也会响应服务器的关闭帧，因此端口转发和自定义侦听器会释放连接，而不是等待服务器删除连接
  • 修复#8152：（httpclient-vertx、httpclient-vertx-5、httpclient-jetty、httpclient-jdk）WebSockets 每隔 Config#websocketPingInterval 发送一个 ping（默认为 30 秒），就像 OkHttp 已经做的那样，因此关闭空闲连接的负载均衡器不再丢弃安静的手表

改进

  • 修复#8109：（crd-generator）int/Integer 和 long/Long 属性获得 format: int32 和 format: int64，就像控制器生成器一样
  • 修复#7987：(kubernetes-client-api) withShardSelector 接受原始表达式 String 旁边的类型化 ShardSelector (ShardSelector.builder().addShard(0, 4).addShard(2, 4).build())，因此 shardRange(...) CEL 语法及其十六进制边界不必手动编写
