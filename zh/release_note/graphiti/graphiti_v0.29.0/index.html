graphiti v0.29.0

Release Notes — 石墨核 0.29.0

总结

0.29.0 是两个版本中的第一个，专注于使摄取变得更便宜并且搜索管道更容易发展。标题变化：

更便宜的摄入。一种新的组合节点+边缘提取路径让单个 LLM 调用可以覆盖以前需要两次调用的内容，并且节点/边缘提取现在可以将多个片段批量处理到一个提示中。时间戳解析（valid_at / invalid_at）也被分为自己的步骤，因此它不会与结构事实提取竞争。 搜索管道返工。 graphiti_core/search/search.py​​ 的大型内部重组为即将到来的搜索和重新排序器更改奠定了基础 - 没有公开的 API 更改，但跟踪覆盖范围得到了很大改善。 新的传奇抽象。 Graphiti 上的 summarise_saga(saga_id) API 由 SagaNode 和刷新的提示支持，提供了一种一流的方式来汇总多集叙述。 生活质量。事实三重情节类型、用于过滤的情节元数据、不再破坏一流字段的更安全的属性合并，以及针对没有外部数据库的嵌入式 FalkorDB 运行的播客示例。 这对开发人员有何影响

默认值不变。组合提取是通过 extract_nodes_and_edges_bulk 上的 use_combined_extraction=True 选择加入的。现有的摄取代码继续按原样工作。 剧集索引现在从 0 开始。如果您解析 [Episode N] 标头或依赖提取结果中的 Episode_indices，请相应地更新您的偏移量。 Kuzu 用户 — 需要架构迁移。 RelatesToNode_ 现在需要一个reference_time TIMESTAMP 列。新数据库自动获取；现有商店需要一次性 ALTER TABLE RelatesToNode_ ADD reference_time TIMESTAMP。 现在设置自定义属性更加安全。节点/边上的属性字典不再覆盖第一类字段（uuid、group_id、created_at、时间戳）。如果您依赖于该覆盖行为，则需要直接设置这些字段。 需要了解的新公共表面：Graphiti.summarize_saga(saga_id)、fact_triple Episode 类型和用于自定义过滤键的 EpisodicNode.episode_metadata。 亮点

效率：摄取过程中的 LLM 调用更少、更智能

组合节点+边缘提取（特征标记）。单个 LLM 调用现在可以为一个情节生成节点和边。将 use_combined_extraction=True 传递给 extract_nodes_and_edges_bulk 以选择加入；默认行为不变。由新的提示/extract_nodes_and_edges.py 和 utils/maintenance/combined_extraction.py 支持。 多片段批量提取。 _extract_and_resolve_nodes 和 extract_edges 现在接受剧集列表，使用 [Episode N] 标头构建共享提示（新的 concatenate_episodes 帮助器），并将 Episode_indices 附加到每个提取的节点/边，以便调用者可以将结果映射回其源剧集。 解耦的时间戳分辨率。新的 extract_timestamps / extract_timestamps_batch 提示让 valid_at / invalid_at 在专用的提取后步骤中得到解析，因此结构事实提取不再与日期解析纠缠在一起。 建筑

搜索管道返工。 graphiti_core/search/search.py​​ 的重大重组（更改了约 1k 行）和新的跟踪测试覆盖范围，为即将到来的搜索/重新排序器更改铺平了道路。 传奇。 Graphiti 上的新 summarise_saga(saga_id) API，加上刷新的 summarise_sagas 提示和支持帮助程序（saga_get_previous_episode_uuid、saga_get_episode_contents）。 事实_三重剧集类型和 EpisodicNode 上的 Episode_metadata 字典用于客户定义的过滤键。 边和节点上的属性合并更安全 - 当属性字典恰好包含匹配键时，一流字段（uuid、group_id、created_at、时间戳）不再被覆盖。 通过批量边缘保存保存的reference_time，并作为列添加到Kuzu RelatesToNode 架构上。现有 Kuzu 用户可能需要一次性 ALTER TABLE RelatesToNode ADD reference_time TIMESTAMP。 及时改进

Dedup（节点和边）：组合提取路径中的范围更严格，二实体规则更宽松。 事实提取：细节保留规则，对合格对象进行更广泛的实体捕获。 刷新了summary_sagas提示。 示例/DX

example/podcast/podcast_runner.py 现在在没有外部数据库的嵌入式 FalkorDB (falkordblite) 上运行，并在摄取后执行边缘 + 节点混合搜索。 显着的内部变化

graph_operations.py 和 record_parsers.py 中的驱动程序调整。 剧集索引现在是基于 0 的（在多剧集提取的第一次迭代中是基于 1 的）。 pytest 在 server/ 和 mcp_server/ 中碰撞到 9.0.3。 锁定文件和依赖项刷新（uv group、voyageai、groq、google-genai、uvicorn、pyright、pytest-asyncio）。 接下来

下一个版本将继续这一架构轨道——预计组合提取路径将逐渐转向默认摄取模式、跨边缘分辨率和重复数据删除的额外批处理，以及基于此处返工的后续搜索管道更改。
