kops v1.37.0-beta.1

请参阅完整的 kOps 1.37 release notes 了解详细信息，包括重大更改和弃用。

发生了什么变化

  • 文档：由 @hakman 在 https://github.com/kubernetes/kops/pull/18592 中更新 1.36 release notes
  • 修复：重试在 https://github.com/kubernetes/kops/pull/18595 中列出 @hakman 在 kops delete cluster 中的云资源
  • hack：并行化GitHub发布促销并在https://github.com/kubernetes/kops/pull/18594中添加@hakman的校验和验证
  • feat(linode)：将VPC模型重构为更广泛的网络模型，并通过@moshevayner在https://github.com/kubernetes/kops/pull/18590中添加子网任务
  • 杂务：删除 https://github.com/kubernetes/kops/pull/18598 中 @hakman 对 Kubernetes 1.31 的支持
  • 文档：更新 1.36 release note 由 @hakman 在 https://github.com/kubernetes/kops/pull/18599 中发布后
  • nodeup：在https://github.com/kubernetes/kops/pull/18600中@hakman清除验证器配置时不要改变集群规范
  • azure：允许 kindnet pod CIDR 通过 https://github.com/kubernetes/kops/pull/18604 中的@hakman 到达 kube-apiserver
  • 将 https://github.com/kubernetes/kops/pull/18609 中 @hakman 的 gcloud storage 替换为 gsutil *构建（deps）：通过https://github.com/kubernetes/kops/pull/18611中的@dependabot [bot]从6.5.0到7.0.0碰撞动作/设置
  • 通过 @YahiaBadr 在 https://github.com/kubernetes/kops/pull/18612 中为 gce 添加合适的控制平面机器
  • 允许在https://github.com/kubernetes/kops/pull/18614中通过@Jefftree指定在验证期间可能未准备好的节点数量
  • 杂务（网络）：通过 @moshevayner 在 https://github.com/kubernetes/kops/pull/18615 中将 aws-cni 提升到 v1.22.3
  • 在https://github.com/kubernetes/kops/pull/18616中由@Jefftree进行可扩展性测试验证期间容忍未就绪的节点
  • aws：删除 https://github.com/kubernetes/kops/pull/18617 中 @hakman 对 API 的经典负载均衡器的支持
  • 杂务（通道）：在 https://github.com/kubernetes/kops/pull/18621 的 @moshevayner 的 alpha 通道中提升 k8s 和 Ubuntu AMI 版本
  • 构建（deps）：https://github.com/kubernetes/kops/pull/18626 中 @dependabot[bot] 从 7.0.0 到 7.0.1 的碰撞操作/结账
  • gce：通过 @Jefftree 在 https://github.com/kubernetes/kops/pull/18620 中打开控制平面节点导出器端口 (tcp/9100)
  • aws：在 https://github.com/kubernetes/kops/pull/18632 中添加 @hakman 的基于 IP 的节点名称选项
  • aws：允许共享子网忽略 https://github.com/kubernetes/kops/pull/18630 中 @hakman 的区域
  • hetzner：在 https://github.com/kubernetes/kops/pull/18631 中通过 @krillerdk 比较负载均衡器时忽略 WellKnownServices
  • 在 https://github.com/kubernetes/kops/pull/18635 中通过 @michaelasp 在 kops 中的 kindnet 上启用 nri 安装
  • azure：支持 terraform 提供程序 azurerm v5 by @hakman in https://github.com/kubernetes/kops/pull/18636
  • 通过 @krillerdk 在 https://github.com/kubernetes/kops/pull/18638 中将 hcloud-go/v2 更新到最新版本 (v2.47.0)
  • gce：通过@hakman在https://github.com/kubernetes/kops/pull/18623中使用curl从私人GCS存储桶下载nodeup
  • aws：不要将 https://github.com/kubernetes/kops/pull/18642 中的 @hakman 将主网络接口设置为“Unmanaged=yes”
  • 滚动更新：在 https://github.com/kubernetes/kops/pull/18641 中 @hakman 恢复 pod 驱逐重试之间的 5 秒延迟
  • 删除 https://github.com/kubernetes/kops/pull/18601 中 @hakman 对 gossip DNS 的支持
  • etcd-manager：在https://github.com/kubernetes/kops/pull/18645中由@hakman在使用时计算kops-utils-cp图像
  • 杂务（频道）：通过 @moshevayner 在 https://github.com/kubernetes/kops/pull/18647 中将 alpha 提升到稳定频道
  • aws：对于所有 k8s 版本，默认为 AWS CCM v1.36.1，@rifelpet 在 https://github.com/kubernetes/kops/pull/18649 中
  • 杂务（网络）：将 aws-cni 升级到 https://github.com/kubernetes/kops/pull/18648 中的 @moshevayner 版本 1.22.4
  • 删除 https://github.com/kubernetes/kops/pull/18650 中 @hakman 留下的闲言碎语
  • 通过 @hakman 在 https://github.com/kubernetes/kops/pull/18653 中删除 protokube 二进制文件
  • 文档：kOps 1.37 中的八卦删除和 @hakman 在 https://github.com/kubernetes/kops/pull/18651 中的迁移指南
  • @hakman 在 https://github.com/kubernetes/kops/pull/18654 中将实例云权限缩小到实际消费者
  • 由 @hakman 在 https://github.com/kubernetes/kops/pull/18656 中缩小实例描述权限
  • 清理 @hakman 在 https://github.com/kubernetes/kops/pull/18658 中剩余的八卦删除残留物
  • 由 @cheftako 在 https://github.com/kubernetes/kops/pull/18640 中添加动态频道标签
  • 修复（通道）：仅将已知的就绪条件视为 https://github.com/kubernetes/kops/pull/18657 中@argoyle 的健康信号
  • aws：使用@hakman在https://github.com/kubernetes/kops/pull/18661中使用curl从私人S3存储桶下载nodeup *scaletest：将 kops 可扩展性配置与调度器 QPS/BURST 的 kube-up 对齐，作者为 https://github.com/kubernetes/kops/pull/18080 中的 @ronaldngounou
  • azure：使用@hakman在https://github.com/kubernetes/kops/pull/18666中使用curl从Blob存储下载nodeup
  • 不要上传陈旧的图像。作者：@cheftako，https://github.com/kubernetes/kops/pull/18665 *scaletest：将 kops 可扩展性配置与 https://github.com/kubernetes/kops/pull/18082 中 @ronaldngounou 的 CCM concurrentNodeSyncs 的 kube-up 对齐
  • 文档：通过 @eshaanm25 在 https://github.com/kubernetes/kops/pull/17954 中删除 seccomp 功能门
