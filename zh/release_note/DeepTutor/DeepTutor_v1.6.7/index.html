DeepTutor v1.6.7

DeepTutor v1.6.7 Release Notes

发布日期： 2026.09.11 v1.6.7 是一个修复版本，几乎完全由社区报告及其背后的拉取请求组装而成 - 这里合并了 19 个。一条线索贯穿其中大部分内容：推理模型。一本书回来时只有一个空章节，一个完全没有提出任何问题的测验，以及一个包含模型自己的草稿本的章节主体，结果都是同样的失败，戴着三张面孔——象征性的预算花在隐藏的思考上，没有留下任何答案，也没有错误可以这么说。直接插入——无需迁移。

新消息

书籍不再以空章节形式到达

图书生成要求以配置层不知道的名称进行代币设置，因此它在打开 agents.yaml 之前返回了硬编码的 4096——这是用户无法筹集的预算，并且推理模型可以完全将其花费在隐藏代币上。然后，空响应被解析为空对象并降级为单个占位符章节；中途耗尽的预算产生了另一种报告形式，每一章的目标都是空白的。 Book 现在已连接到配置映射中并以 12000 为种子，并且在没有所需密钥的情况下返回的一轮会以较低的推理工作量重试一次。以前，重试仅适用于区块写入者；现在所有四个管道阶段都共享它。

模型的暂存器停止到达读取器

每当答案为空时，非流式路径就会返回模型的推理作为答案 - 流式路径明确禁止相同的事情，因此一个决定在两个代码路径上相互矛盾。另外，明确的“无需思考”请求现在已缩小为每个模型实际接受的内容：gemini-3 和 gemini-2.5-pro 将 HTTP 400 应答为 none，而面向读者的书块正是要求这一点。

思维模型不断地进行推理

将回合的 reasoning_content 重播回提供者是通过包含 deepseek 的模型名称来控制的。模型名称并不是提供商宣布其方言的方式——Volcengine Ark 采用端点 id，Doubao、GLM、Qwen 和 Kimi 思维模型各自采用自己的方式。当新的回合重播历史时，他们都失败了，而一个回合内的同一回合却有效。现在的关卡是提供者是否发送了该字段。

测验不再悄然产生任何结果

计划步骤在其管道中具有最紧张的代币预算，而思维被截断的计划返回与模型相同的空字符串，无话可说。零模板意味着零问题——并且没有错误。现在这两种情况是可以区分的，一个饥饿的计划会以较低的努力重试，并且预算不再是异常值。

失败的工具说明出了什么问题

“执行 rag 时发生未知错误。”通过聊天、研究和问题，在进入模型的过程中替换了真正的原因。现在，事业随消息一起传播。这涵盖了报告的情况，其中停止的本地嵌入服务是不可见的：适配器始终命名端点和补救措施，并且文本在其上方的一层被丢弃。拒绝连接的自托管端点现在也会指出两件事中哪一个出了问题——没有监听，或者 localhost 的容器不是为模型提供服务的机器。

公式呈现在学习者阅读的位置

掌握问题卡、ask_user 卡和推理痕迹以原始文本形式打印 $G_t = R_{t+1} + \gamma G_{t+1}$。 Traces 的情况最糟糕：守卫将它们排除在丰富的渲染器之外，这使得该渲染器自己的跟踪分支自 3 月份以来就无法访问。表面是否呈现数学现在由内容决定，而不是由表面决定，因此没有数学的气泡仍然走便宜的路径。

您可以实际提交的卡片

没有多项选择选项的掌握问题从从未呈现的字段中读取您的答案，因此“提交”永远处于禁用状态。停在 ask_user 卡上的回合可能会保留会话所有权，而没有任何活动可以回答它 - 后来的每条消息都被拒绝。两半都是固定的：当答复到达时，废弃的轮次会被回收，并且制造这些行的最终状态检查（它只接受 running，从不等待一个人的轮次）不再这样做。

阅读、可视化、导入

沉浸式阅读现在附带 PDF.js 解码器资源，因此 JPEG 2000 和 JBIG2 页面图像不再显示空白。 GeoGebra 在评估之前拒绝已知的致命命令模式，并显示它过去吞下的故障，并且图像分析在到达模型之前不再崩溃。 Codex 历史导入读取当前的推出格式，Codex 为自身注入的轮次（插件清单和类似内容）不再成为您的第一条消息或对话的标题。

值得命名的较小修复

流式提供者错误被提出，而不是作为助理的答案传递。 API 密钥池在配置解析器中仍然存在。 read_skill 会告诉丢失的文件和丢失的技能，而不是将两者都报告为“找不到技能”。命令 ids 适用于纯 HTTP 部署，其中 crypto.randomUUID 未定义。当路由器不支持任一模态对时，图像生成仅重试图像。研究工具超时和重试设置现在完全受到尊重，并且默认为停滞的提供程序的上限，而不是缓慢的工具行程。设置就绪状态为只读用户呈现，聊天恢复为附加 PDF 发明的工具调用，观看记录遵循活动提示而不是将其推离屏幕。

升级注意事项

运行pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有什么需要迁移。

  • 现在可以达到图书的代币预算。 它位于 agents.yaml 中的 capabilities.book 下，种子为 12000。之前是 4096 并且无法达到，因此默认情况下图书获得的输入要长得多。
  • 研究工具策略默认值已更改 — 超时 60 秒 → 240 秒，重试 3 → 0。研究工具本质上很慢，重试会再次支付全部超时费用。如果您在早期版本下保存了研究设置，您存储的值仍然会获胜；清除它们以获取新的默认值。
  • 已知问题： ask_user 在此升级仍可保持会话之前陷入困境。创建它们的路径是封闭的，但是现有的行在启动时还没有被扫描——这将在下一个版本中进行扫描。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.6.6…v1.6.7
