DeepTutor v1.5.10

DeepTutor v1.5.10 Release Notes

发布日期： 2026.08.07 v1.5.9 是关于提供商的；这与它们下面的路径有关——导致所有其他请求停止的批量上传、重新扫描每个索引的知识库列表、不带参数调度并重试直到预算用完的工具调用。悄然缺失的两件事也登陆了：一个帐户可以登录自己的 Codex，并且模型的回复语言最终是它自己的设置。直接插入——无需迁移，无需重新索引。

新消息

每个帐户都可以登录自己的 Codex

Codex 令牌授权一个人的 ChatGPT 计划，因此该配置文件永远无法授予，但 OAuth 端点也仅限管理员使用，这使得普通用户根本无法访问 Codex。他们现在可以自己登录：该卡位于 Models → LLM 下，它创建的配置文件将写入该用户自己的目录 (data/users/<uid>/settings/model_catalog.json)，而不是共享的管理员目录。赠款将个人行与分配的行一起解析在一个位置，因此选项列表、功能门和选择验证不会不一致 - 并且检查某人的赠款的管理员仍然只能看到他们分配的内容。合作伙伴被拒绝：合作伙伴是合成用户，承认合作伙伴意味着对其所有者的登录进行操作。

模型输出语言是它自己的设置

设置→外观现在带有两个独立的切换开关。 界面语言涵盖导航、设置和状态文本； 模型输出语言 设置聊天和功能回复的默认语言，到目前为止您只能通过提示进行操作。在分割之前写入的 interface.json 会将其单个 language 继承到两个字段中，因此在您选择之前不会发生任何变化。读取这些内容的会话前引导程序现在也是公开的 - /login 和 /register 之前一直是英语，因为匿名读取会击中门控路由器并出现 401 错误；它仅返回主题和语言，并且在此浏览器中所做的选择仍然获胜。

不带参数的工具调用会被拒绝，不会运行

在较大的工具表面和较长的历史记录下，即使模式标记了所需的字段，提供程序也会间歇性地发出带有空 arguments 的本机函数调用。无论如何，调用都被调度了，因此 工具 进行了拒绝 - exec 提出“需要非空命令”，write_note 回答“未知模式” - 并且两者都读取为“缺少参数”，因此模型重新发出相同的格式错误的调用，直到循环预算用完。现在，调度前的一名警卫会命名缺少的参数及其接受的值（包括枚举），将其转变为一轮自我纠正。规则保持狭窄：不需要默认参数，空集合单独保留，服务器注入的 kwargs 计数为提供的。

上传和知识库列表停止循环

在整个批处理期间，批量上传文件会阻止所有其他请求（包括聊天 WebSocket）：分块写入、zip 提取和每个文件的 PocketBase 上传都在异步上下文中内联运行，后续暂存过程位于 async def 后台任务中，Starlette 在循环中而不是在其线程池中等待该任务。两者现在都在工作线程中运行。分别构建一个 KB 列表响应重新加载配置并重新扫描每个项目的每个索引；它现在重用一个协调的快照 - 58 KB 的只读列表在大约 2 秒内完成，而不是使代理超时。

Deep Research 直接读取连接的黑曜石金库

当选定的知识库是链接的黑曜石库时，研究循环不再针对不存在的索引自动安装 rag。它安装了三个只读保管库工具 - obsidian_search / obsidian_read / obsidian_list - 在服务器端注入保管库路径（覆盖任何模型提供的值），将其结果视为可引用，以便证据到达引用管理器和最终报告，并交换到黑曜石特定的系统注释。索引 KB 和无 KB 运行保持不变。

服务器端后端地址到处都是IPv4环回

localhost 首先在双栈主机上解析为 ::1，而 uvicorn 绑定 0.0.0.0（仅限 IPv4），因此每个重写的 /api/* 请求都无法连接。首先固定发射器； Docker 入口点的 render_environment 和 web/proxy.ts 的最后手段默认保留主机名，现在已恢复同步。

什锦

  • Escape 停止流式合作伙伴回复，而且只有这样：在安装任何对话角色覆盖时，侦听器会退出，因此关闭模式或选择器不再杀死其背后的答案。
  • 视觉功能覆盖现在通过供应商前缀匹配 claude-（没有任何内容以 claude-4 开头，因此密钥不匹配任何内容），并识别 Kimi K3 和 Qwen3.8-Max。
  • Codex 上下文窗口元数据 在目录往返过程中保留下来，而不是被丢弃。
  • 编辑消息不再与随后的刷新竞争，因此乐观气泡不再闪烁。
  • deeptutor-cli 轮再次发送代理的提示 YAML - 它没有提示，因此提示加载失败，并且空结果在进程的生命周期内被缓存。未命中也不再被缓存，因此在重试时会拾取启动后出现的资源。

升级注意事项

pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有架构更改，没有重新索引，没有迁移。

  • 模型输出语言默认为您现有的界面语言。 分割是继承的，而不是重置 - 如果您希望使用与 UI 不同的语言进行回复，请在 设置→外观 下明确设置。
  • 默认情况下，非管理员 Codex 登录处于启用状态。 每个帐户的配置文件都保留在其自己的目录中，并且对管理员和所有其他用户不可见；普通用户登录的任何内容都不会出现在共享模型列表或授权编辑器中。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.9…v1.5.10
