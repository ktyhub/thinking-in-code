DeepTutor v1.3.3

DeepTutor v1.3.3 Release Notes

发布日期： 2026.04.30 v1.3.3是v1.3.2之后的快速后续版本。它扩大了提供商的覆盖范围 借助 NVIDIA NIM 和 Gemini 嵌入，使 Space 成为统一的附加位置 聊天记录、笔记本、题库项目、技能和记忆力，以及 继续围绕 RAG 重新索引、思维模型清理进行稳定性工作， TutorBot 历史记录和持久会话上下文。

亮点

提供者和嵌入覆盖范围

DeepTutor 现在涵盖了更多开箱即用的托管提供商设置，并保留了 运行时配置路径与设置教程和 .env 示例一致。

  • NVIDIA NIM 是一流的 LLM 提供商 - 现在自动检测提供商 识别 nvapi- 键和 NVIDIA API 底座，默认为 https://integrate.api.nvidia.com/v1，并避免发送 stream_options.include_usage 因为当该选项为 NIM 时，NIM 可能会挂起 存在。
  • Gemini 嵌入可端到端使用 - 嵌入运行时元数据， 端点验证、设置游览选择、模型建议和 .env 现在的示例包括 Gemini，具有 gemini-embedding-001、3072 尺寸和 GEMINI_API_KEY 后备支持。
  • 特定于提供者的嵌入密钥在设置写入中保留下来 - .env 写入 改为保留 SiliconFlow、DashScope、Cohere、Jina 和 Gemini 等密钥 仅保留旧的核心提供商集。
  • 依赖解析不那么脆弱 - NumPy 上限被放宽 支持 deeptutor[all] 中当前的 Manim 安装和 Windows 安装文档 现在调出 Visual Studio 构建工具/C++ 工作负载先决条件。

空间、聊天环境、技能和记忆

聊天编辑器现在将所有学习上下文视为空间上下文，而不是 将参考资料、技能和记忆分散到单独的控件中。

  • 空间在聊天历史记录上打开 - 空间入口点现在位于新的聊天记录上 聊天记录页面，可以搜索、刷新之前的对话， 直接从 Space 工作区重命名、删除和重新打开。
  • One Space 菜单支持工具栏和 @ 提及 - 旧的内联 AtMentionPopup 被聊天记录的共享空间菜单取代， 笔记本、题库项目、技能和记忆，无论是从 工具栏或输入 @。
  • 技能选择更清晰 - 技能现在在完整的选择器中打开 搜索、标签、显式多选和自动模式，而不是小型内联 作曲家旁边的下拉菜单。
  • 每轮可附加内存 - 用户可以选择运行摘要， 配置文件，或通过新的内存选择器两者。请求发送 memory_references，后端只注入选定的内存文件。
  • 上下文芯片显示完整回合设置 - 选定的历史记录、笔记本、 题库项目、技能和记忆以前都以可移动芯片的形式出现 发送；发送的用户消息还显示匹配的请求快照徽章。
  • 立即回答和会话水合保持上下文 - 重播回合并加载 课程现在包含笔记本、历史参考资料、问题库参考资料、 持久消息元数据中的技能、内存引用和附件。

会话持久性和消息规范化

对话状态现在记录更多用户的实际发送时间上下文 更加防御性地处理非短信内容。

  • 消息元数据被持久化 - SQLite 会话存储添加了一个 metadata_json列并存储一个request_snapshot用于用户消息， 包括功能、工具、选定的知识库、语言、配置、附件、 空间参考、技能和记忆选择。
  • WebSocket 明确接受内存和技能 - 传入的有效负载 将 memory_references 标准化为 summary / profile，将技能标准化为 字符串列表，并将两者具体化为消息元数据。
  • TutorBot 历史记录处理多模式内容 - 机器人历史记录和最近的机器人 预览将字符串、数组、对象和图像样式内容规范化为安全内容 显示文本，而内部 reasoning_content 则从 API 中剥离 回应。
  • 前端消息预览更安全 - 共享消息内容实用程序 现在接受未知内容，对自定义对象进行字符串化，将图像部分渲染为 [image]，并在聊天和会话列表中一致地截断预览。

内存、笔记本和思维模型清理

v1.3.2 中引入的思维输出清理现在变得更加持久 存储表面并在损坏之前拒绝格式错误的内存重写 配置文件或摘要文件。

  • 内存重写必须符合预期的形状 - 简介和摘要 现在刷新在写入之前验证允许的部分标题。如果一个思考 模型回答用户而不是返回结构化内存，写入是 拒绝而不是坚持。
  • 内存上下文是明确的 - build_memory_context() 现在仅包括 summary 和/或 profile 当请求这些文件时，匹配新的 每轮内存选择器并避免意外的默认内存注入。
  • 笔记本摘要已清理和修复 - 笔记本写入、流式传输 摘要保存，笔记本从摘要中加载条状思维标签；较老的 尽可能在读取时修复笔记本记录。
  • 流式摘要块更清晰 - 生成的笔记本摘要是 组装、清洁并在清洁后发出，因此是空的或仅暂存器 块不会流式传输到 clients。

RAG 和知识库弹性

RAG 验证现在可以在检索之前捕获更多无效的持久索引 当用户需要重新索引时返回更清晰的事件。

  • 当索引准备就绪时，过时的处理 KB 会恢复 - 如果 kb_config.json 卡在 processing 或 initializing 但现成的 LlamaIndex 版本是 已在磁盘上，知识库信息报告 ready 并隐藏过时的内容 进度条，而不是让 UI 处于永久处理状态。
  • 更多矢量存储得到验证 - LlamaIndex 存储现在检查 默认向量存储，storage_context.vector_stores，并持久化 *vector_store.json 嵌入空字典、删除字典、非数字字典、 非有限或不一致的向量。
  • 无效索引失败会发出面向用户的状态事件 - RAG 立即搜索 通过工具事件发送带有 needs_reindex 的结构化错误状态 流并避免将已知的无效索引失败视为成功 检索尝试。
  • 低级向量错误较少暴露 - 已知无效嵌入/索引 失败被记录并显示为重新索引指导而不是原始的 面向用户的日志中的 NoneType * float 样式回溯。

测试

  • 添加了知识管理器覆盖范围以促进陈旧的 processing / 当有效索引版本已存在时，initializing 状态变为 ready。
  • 添加了 NVIDIA NIM 注册表元数据、流选项的提供商覆盖范围 行为、Gemini 嵌入运行时默认值、端点验证、设置教程 提供商选择和 .env 密钥保存。
  • 添加了 metadata_json 的会话和 WebSocket 覆盖范围、请求快照、 技能规范化、内存引用解析和转向物化。
  • 添加了内存和笔记本覆盖范围，用于思维标签剥离、无效内存 重写拒绝、选择性内存上下文注入和摘要修复 阅读。
  • 添加了用于多向量存储验证的 RAG/LlamaIndex 覆盖范围， 磁盘保留的无效向量、needs_reindex 状态事件和已清理的 原始日志。
  • 添加了 TutorBot 和前端消息内容的非字符串覆盖范围， 多模式、对象、图像和截断的消息内容。

升级注意事项

  • 现有的 SQLite 会话数据库已迁移到新的数据库 会话存储第一次打开它们时的 messages.metadata_json 列。
  • 依赖隐式内存注入的自定义 WebSocket clients 现在应该 通过 memory_references: ["summary"]、["profile"] 或两者。空或不存在 内存引用有意表示“不附加长期记忆”。
  • 仍然报告无效持久向量的知识库应该是 确认活动嵌入提供商、型号、尺寸后重新索引， 和端点 URL。
  • 笔记本摘要流 clients 应该期望在之后清理摘要输出 组装，而不是依赖于转发的每个原始模型块。
  • NVIDIA NIM 用户应在新标准下配置 OpenAI 兼容模型 提供商并保持 stream_options.include_usage 对此网关禁用。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.3.2…v1.3.3
