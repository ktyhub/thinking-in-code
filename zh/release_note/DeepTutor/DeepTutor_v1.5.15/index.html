DeepTutor v1.5.15

DeepTutor v1.5.15 Release Notes

发布日期： 2026.08.20 v1.5.14 将文档放在对话旁边。这主要是关于它背后的内容：PageIndex 成为您可以自己托管并通过文档树推理进行检索的东西，问题库不再是您无法归档的列表，第三方软件包现在可以注册自己的工具和功能。几乎所有这些都是作为社区拉取请求到达的。直接插入——无需迁移，无需重新索引。

新消息

PageIndex 你可以自己托管，并检索原因

PageIndex OSS 作为自己的知识库类型加入引擎列表：与托管服务相同的接口，绑定到基础的本地库，由您已配置的 LLM（而不是 PageIndex API 密钥）驱动。 两种变体下的检索都发生了变化。过去通过内置 MCP 服务器读取 PageIndex 基址；该路径消失了，取而代之的是一个遍历文档树的小读取循环——首先是结构，然后是它需要的页面。移动部分更少，并且页面级引用相同。

题库不再是只写的

addEntryToCategory 在 v1.3.6 中发布，并且从未从前端调用，因此对于 11 个版本，学习者可以创建类别，但永远不会在其中放入任何内容。测验卡的定制下拉菜单现在使用调用它的共享类别菜单。 该页面围绕平面列表无法完成的三件事进行了重建——搜索、批量选择以及尚未提交问题的收件箱。分级掌握路径问题带有其解释和难度。 导师终于可以为你申请了。要求它对你的错误答案进行分组，银行上没有可写的句柄，所以它到达了 write_note，你的请求悄悄地变成了笔记本记录——中文 write_note 提示甚至列出了错题分析作为追加的原因。新的 question_bank 工具采用名称寻址：organize 获取一个类别名称，并在丢失时创建它，因此归档是一个列表后一次调用。仅当银行有条目时才会安装。

第三方工具和功能

两个入口点组让已安装的包无需接触树即可扩展 DeepTutor。 deeptutor.plugins 已经由功能注册表导入，而 /plugins/list 则位于 try/except 后面 - 但该模块从未存在过，因此插件发现是一条死路；现在它是真实的。 deeptutor.loop_capabilities 将聊天循环功能与内置功能一起注册，从而在名称冲突中获胜。损坏的入口点会被跳过而不是致命的，并且每个进程都会缓存发现，因此插件功能保持单例。

Apache Tika 解析

第七个文档解析引擎，可在设置 → 知识库中选择。 Tika 仅限远程：没有 Python 包，没有模型下载 - 它指向 Apache Tika 服务器 (TIKA_SERVER_URL) 并将多种格式转换为 Markdown。

LightRAG 的索引旋钮，在 UI 中

max_concurrent_files、llm_model_max_async 和 entity_extract_max_gleaning 达到了运行时设置，而 #877 中的 API 没有输入，因此只能通过手动编辑配置来达到它们。它们现在位于自己的 索引 分隔线下 - 与上面的查询旋钮不同的轴，因为它们决定了基础的“构建”方式，因此更改适用于下一个构建而不是下一个问题。连接询问已安装的 RAG-Anything 它接受什么，并丢弃其余的并发出警告，因此较旧的安装会继续在库默认值上运行而不是引发。

在知识库中重建文档树

三个修复最终完成#866。链接文件夹的子目录不再折叠到 raw/ 的顶层；来自不同子树的同名文档不再默默地相互丢弃（在空闲兄弟名称下的不同字节阶段之间发生冲突，相同的字节仍然会重复数据删除）；现在上传需要一个可选的目标文件夹。 最后一个才是真正的阻碍者。浏览器文件夹选择会报告每个文件相对于您选择的目录的路径，因此一次添加一个子树 应用开发/钉钉CLI/ 会得到 钉钉CLI/... ，无法说出它所属的位置 - 每个批次都堆积在根部，并且丢失的祖先从一开始就从未出现在有效负载中。现在，一旦文件暂存，选择器就会提供基地的现有文件夹。

书籍：学习捕获收件箱

您选择的阅读片段会按书保存，并具有明确的状态生命周期，因此可以在捕获的内容到达任何地方之前对其进行审查。另外，漂移警告变得诚实：过时页面检测的范围仅限于实际更改的知识库文档，并且当标记的页面仍在等待重新编译时，警告不会清除。

Whisper — 社区贡献

/whisper 是一个由 @alanguan73 贡献的两个座位的咨询练习室：导师扮演访客，你坐在学员座位上，主管低声指导，只有学员能看到，并在课程结束时进行汇报。它位于学习空间→更多项目下，需要安装自己的功能包——水面舰艇，咨询功能不是 DeepTutor 的一部分。 通常有用的一半工作是在运行时：功能现在可以在 CAPABILITY_COMPLETE 上发布主体及其自己声明的附加内容，而 capability、session_id 和 turn_id 保持不可欺骗。只有显式声明的子字典才会出现在事件总线上 - 元数据是一个暂存器，保存实时可调用项和您的 ask_user 答案，而且它从来都不是有线格式。

什锦

  • 模型知道今天是星期几。 如果没有实际日期，它在编写网络搜索时从训练截止点解析出“今天”。注入的块是按天粒度的，因此系统提示符在一天内保持字节稳定并保持提示缓存命中。
  • 删除回合不再使会话空白。 后代指向已删除的行，会话失去其根，并且页面呈现为空（#912）。已删除的行将从父指针树中拼接出来，并且已损坏的会话将从其最旧的孤立会话中恢复。
  • 过时的 CA 包不再破坏每个 LLM 调用。 剩余的 SSL_CERT_FILE / SSL_CERT_DIR — 在克隆没有 ca-certificates 的 conda 环境后很常见 — 使 httpx 在构建过程中引发；损坏的路径将被丢弃，因此 TLS 会回退到默认捆绑包。
  • 思考标签也在非 SSE 本地流上进行过滤。 该分支直接传递推理块；两个分支现在共享一个增量解析器，因此跨块分割或未闭合的标记无论哪种方式都表现相同。
  • 未处理的服务器错误返回 JSON 而不是 Starlette 的纯文本 500，并且处理程序保留在中间件堆栈内，因此响应仍然带有 CORS 标头。
  • 黑曜石金库可以在现实世界的文件中幸存下来 - 无法解码的字节和日期类型的前言是可以容忍的，无法打开的金库会说明原因，而不是不透明地失败。
  • 卡住的会话负载以可重试状态结束而不是旋转，并且由本机适配器作为普通字典发出的令牌使用情况被记录而不是丢失。
  • 掌握阅读停止发明路径，end_loop 在 ask_user 恢复后获得荣誉，并且 codebuddy 额外解析再次。
  • 前端在 CI 中进行了 linted。 ESLint 现在在每个版本上都在 web/ 上运行。 deeptutor.info 上的文档随此版本一起更新。

升级注意事项

pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有架构更改，没有重新索引，没有迁移。

  • PageIndex OSS 需要 API-key 或本地 LLM 配置文件。 仅 OAuth 提供程序（OpenAI Codex、GitHub Copilot、CodeBuddy）无法驱动索引，并会被拒绝并给出解释。 OSS 库仅限 PDF，每个请求最多可以选择一个。
  • PageIndex 的内置 MCP 服务器已消失。 无需配置任何内容 — 托管基地在新的阅读循环中继续工作。如果您自己将该 MCP 服务器固定在任何地方，请将其丢弃。
  • Tika 不安装任何内容。 运行 Apache Tika 服务器并将 TIKA_SERVER_URL 指向它（默认 http://localhost:9998）；没有额外的 parse-tika，因为没有 Python 封装。
  • LightRAG extra 的地板移动至 raganything>=1.2.5，这是第一个带有关键字 passthrough 的版本。较旧的安装不会被破坏 - 不受支持的旋钮会被丢弃并发出警告 - 但三个新的安装需要该地板才能生效。这些旋钮适用于下一个版本，而不是下一个问题。
  • 图书漂移警告重新设定基线一次。 指纹现在带有方案标签，因此更改公式会重新设定现有图书的基线，而不是将每一本标记为陈旧。
  • Whisper 不是主要的导航条目。 它位于 学习空间 → 更多项目 下，并且该房间需要自己的功能包 - 库存安装有页面，但没有其背后的咨询功能。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.14…v1.5.15
