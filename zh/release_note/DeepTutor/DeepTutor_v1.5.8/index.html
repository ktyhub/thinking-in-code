DeepTutor v1.5.8

DeepTutor v1.5.8 Release Notes

发布日期： 2026.08.02 维护版本只有一个目标：内存保持不变，而不是 climbing。在 V8 中途放弃之前，v1.5.7 源部署增长超过 14 GB，原因是独立的 - 前端开发服务器的堆上限从未达到持有内存的进程、无限制的进程内缓存以及为每个回合构建的新 HTTP client。直接插入 — 无需迁移，但源签出现在以不同的方式开始。

新消息

开发服务器实际上从未受到限制

next dev 在它自己生成的工作进程中进行渲染，并且 argv 中的 V8 标志不会被子进程继承——因此长期存在的 node --max-old-space-size=4096 …/next dev 从未到达保存内存的进程。在 NODE_OPTIONS 中发现没有上限，Next 替换了总 RAM 的 50%：24 GB 机器上的 12 GB 堆，V8 在 Ineffective mark-compacts near heap limit 中在单个标记压缩中 63 秒后死掉之前确实试图填充该堆。 web/scripts/dev.mjs 现在通过了 NODE_OPTIONS 的上限，worker 确实继承了这个上限，并且 Next 也尊重它 — 限制为 4 GB，并根据容器内的 cgroup 限制而不是主机的 RAM 调整大小。

源安装服务于生产构建

现在，结帐中的 deeptutor start 将前端构建到 .next-deeptutor 中并提供独立输出，重复使用该构建直到输入实际更改（web/ 树上的指纹、版本文件和构建时公共设置）。热重载转移到 deeptutor start --dev，它继续使用 .next — 单独的目录，因此两种模式在运行时都不会使另一种模式的输出无效。长时间运行的部署不再需要支付开发编译器的缓存费用。

有界LLM clients 而不是每回合一个

聊天、研究和问题管道每次都会构建一个新的 OpenAI 兼容的 client，并附带一个新的 HTTP 连接池。代理 client 和服务层提供程序现在都来自 2 个小型事件循环本地 LRU 池，以绑定、模型、凭据和基本 URL 为关键，在关闭时关闭，并在设置更改时退出。仅导入所选后端的 SDK。

缓存有上限

知识任务日志流现在限制每个任务的事件和字节，在任务结束一小时后过期，并留下一个小的完成墓碑，以便迟到的订阅者仍然知道任务已完成。已完成任务表保留 256 个条目。 LlamaIndex 索引缓存从 8 个条目减少到 2 个，并驱逐 10 分钟内空闲的所有内容。一旦队列耗尽，书籍运行时就会被释放，而不是为进程而生存。

回收已经释放的东西

在一轮、完成的书籍作业或完成的知识库任务之后，DeepTutor 会收集循环，并在 Linux 上调用 malloc_trim，以便 glibc 释放堆页面，而不是保留使 RSS 看起来永久固定的竞技场。容器和 deeptutor start 还设置了 MALLOC_ARENA_MAX=2 和较低的修剪阈值，这两个阈值都可以由已调整自己的操作员覆盖。

一场以 500 秒的形式出现的保命竞赛

web/proxy.ts 通过 Node 的 http.globalAgent 转发到后端，后者在 5 秒计时器上获取空闲套接字 - 与 uvicorn 的默认值相同。两端在同一个套接字上配备了同一个计时器，并竞相关闭它；当服务器的 FIN 到达套接字时，池同时处理一个新请求，该请求以 ECONNRESET 终止，并到达 UI，显示“无法加载会话”。现在，每次 uvicorn 发布都会设置 --timeout-keep-alive 300，使 client 成为唯一退出空闲连接的一侧。

什锦

  • deeptutor.agents、deeptutor.core.agentic、provider-core 包、文档提取器的解析器库（PyMuPDF、pypdf、python-docx、openpyxl、python-pptx）和 LLM 错误映射规则均在首次使用时解析，而不是在导入时解析。
  • python -m deeptutor.api.run_server不再以--reload开头；为其导出 DEEPTUTOR_DEV_RELOAD=1 。 Reload 运行一个 Supervisor 和一个 Worker，并保留文件观察器状态，这是开发机制。 deeptutor serve --reload 不变。

升级注意事项

从 v1.5.7 插入：pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有架构或配置更改。

  • **源签出在服务之前构建。**升级后的第一个 deeptutor start 运行 npm run build 并相应地需要更长的时间；稍后启动重用它，直到源发生更改。将 deeptutor start --dev 用于之前的热重载循环。新的 web/.next-deeptutor/ 构建目录被 git 忽略。
  • python -m deeptutor.api.run_server 默认情况下不再重新加载。 导出 DEEPTUTOR_DEV_RELOAD=1 以恢复它。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.7…v1.5.8
