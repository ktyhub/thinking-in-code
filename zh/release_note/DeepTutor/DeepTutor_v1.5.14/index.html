DeepTutor v1.5.14

DeepTutor v1.5.14 Release Notes

发布日期： 2026.08.19 v1.5.13 制作了一本书，供您阅读。这个助手将助手放在您正在阅读的内容旁边：文档在线程旁边打开，每个声明都会返回其来源页面。围绕它的其他三个转变——DeepTutor 可以通过聊天轮来配置自己，腾讯 IMA 库成为你浏览和写入的东西，而不仅仅是搜索，笔记本电脑有自己的控制台。直接插入——无需迁移，无需重新索引。

新消息

沉浸式阅读 — 文档在线程旁边打开

在功能菜单中选择沉浸式阅读，然后打开 PDF、幻灯片或知识库已接受的任何文档。读者占据了大约三分之二的工作空间，对话保留了其余的空间，而它们之间的接缝则很拖沓。 助理会读取您所看到的相同单元 - PDF 页面、幻灯片或没有自己页面的格式的大致页面大小的部分 - 因此答案引用了 [p.12]，读者滚动到那里并突出显示声明背后的句子。选择一个段落并询问它，边走边突出显示并附加注释，然后随身携带标记：导出真实的带注释的 PDF，该 PDF 会在 Preview 或 Acrobat 或 Markdown 中打开，突出显示完好无损，然后粘贴到您自己的注释中。 有两个决定使其扎根而不仅仅是自信。阅读轮流保留了整个聊天界面——网络搜索、代码执行、其他知识库——因为五种阅读工具是“添加”到它的，而不是取代它。在模型运行之前，DeepTutor 会根据开放文档运行您自己的问题，并将最热门的问题交给它，因此即使模型永远不会自己调用读取工具，也会发生接地。这是一个简单的搜索，而不是第二次 LLM 通过：没有额外的标记，第一个单词之前没有延迟。

让 DeepTutor 自行配置

“将界面切换为中文并使用更好的 PDF 解析器”现在是你说的而不是你去和 click 的东西。回合可以检查安装、应用设置、安装解析引擎或获取其模型权重（在单个调用中跟踪实时日志，而不是轮询它），并要求您提供凭据。 三个规则可以防止鲁莽行事。 新的模型或提供者在提交之前会被探测，针对永远不会到达磁盘的候选配置，因此助手无法将自己切换到无法访问的东西并在对话中切断自己的电源。 API 密钥永远不会进入模型的上下文：它会打开匹配的表单，并且您的浏览器将密钥直接发布到服务器。它可以触及的每个旋钮都是单个表中的一行，具有自己的范围和效果，因此您会被告知更改是否是即时的，需要重新启动，还是使您的嵌入无效 - 而不是稍后才发现。

腾讯IMA：您浏览和写入的库

IMA 库是可搜索的，仅此而已。现在，它还回答“这里实际上是什么”——知识库文件列表读取图书馆自己的浏览 API，而不是将连接的库报告为不可枚举，并且根据请求预算缩短的列表被标记为下限，而不是作为总数传递。 通过聊天轮流，您可以列出库、阅读整个源代码而不是检索到的片段、按新近度搜索您的笔记、添加供 IMA 摄取的 URL 以及写回笔记。这些工具是附加的：rag 仍然提供 IMA 库，因为它确实可以通过 HTTP 进行搜索，并且附加一个不再需要您进行网络搜索或其他基础操作。

连接的知识库可以再次搜索

v1.5.13 阻止了 Book 扫描连接的知识库：扫描没有返回任何内容，并且“没有”与没有相关内容的来源无法区分。这个修复范围太宽了。只有 ObsidianVault（根本没有索引）和连接的子代理（不是文档集合）确实无法访问 - linked 文件夹挂载在其他地方构建的索引，并且 LightRAG 服务器和 IMA 通过 HTTP 卸载检索。这三本书都被搁置了，所以每本书都悄悄地放弃了它们。检索现在询问是否可以从*检索基地，而不是询问它是否已连接。

笔记本电脑有一个控制台

笔记本从 Space 文档布局移至 /notebook 自己的全高控制台（旧链接重定向，包括深层链接）。可以在笔记本之间复制或移动记录，并将整个笔记本导出为一个 Markdown 文档。 随之而来的还有三个缺陷。并发保存可能会互相破坏；现在，每个笔记本都有自己的锁，并且每次写入都是原子的，因此崩溃时只会留下前一个文件，而不是截断的文件。文件损坏的笔记本会显示为标记行，而不是从列表中消失。重命名记录用于清除其知识库链接，因为无论您是否发送，API 都会转发每个字段。

设置写入停止互相覆盖

两个写入者共享 interface.json，并且双方的锁都没有覆盖对方。在修复之前进行测量，六个偏好保存与聊天轮中的六个写入丢失了所有保存。现在两者都经过一次锁定和一次原子替换。另外，设置端点停止写回设置的默认值合并视图：更改用于将当天的默认值作为显式选择冻结到文件中的主题，因此您会默默地停止跟踪以后对其中任何一个的更改。

什锦

  • 功能菜单已重新组合。 聊天、测验、可视化、掌握路径和沉浸式阅读仅需 click 即可实现；研究和解决移至更多功能。现在的分组纯粹是关于菜单顺序的——它过去用来关闭某个功能运行在哪个引擎上，这意味着如果不涉及引擎，菜单就无法重新排序。
  • write_note 报告它用来隐藏的故障。 即使没有笔记本接受写入，记录 ID 也会返回，并且被读取为成功。
  • 损坏的笔记本在解析笔记本引用时不再需要聊天拒绝，并且 /notebook/health 可以再次访问 - 它是在 /{notebook_id} 之后声明的，并已被它遮蔽。

升级注意事项

pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有架构更改，没有重新索引，没有迁移。

  • **沉浸式阅读将每个用户的材料存储在首次使用时创建的新 reading 工作区目录下。在打开文档之前不会写入任何内容。
  • **功能选择器看起来不同。**研究和解决现在位于更多功能下；没有删除任何内容，并且使用其中任何一个的会话都可以继续工作。
  • 阅读不需要新的 Python 依赖（PyMuPDF 已经是核心），并且 PDF 查看器附带前端捆绑包 - 源安装在下一个 npm install 上拾取它。
  • 扫描的纯图像文档会被拒绝并给出解释，而不是作为空阅读器打开。首先通过 OCR 运行它，或者使用执行 OCR 的解析引擎将其索引到知识库中。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.13…v1.5.14
