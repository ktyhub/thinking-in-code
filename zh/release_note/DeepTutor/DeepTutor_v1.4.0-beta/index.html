DeepTutor v1.4.0-beta

DeepTutor v1.4.0-beta Release Notes

发布日期： 2026.05.21 v1.4.0-beta 是自代理原生重写以来最大的版本。它折叠一个 端到端 自动模式 在现有功能之上，提供了 **三层内存子系统（L1/L2/L3）**带有专用工作台，可重建 深入研究/深度解决/问题在与聊天相同的代理引擎上， 围绕以下内容重新架构 聊天功能 + LlamaIndex RAG 管道 会话累积源库存，统一 功能基础设施 和 i18n，将 Animator 菜单合并到 Visualize 中，并重新组织 设置、环境和本地启动器。几个新的聊天工具 （ask_user、web_fetch、write_note、list_notebook、github_query）加上一个 删除聊天轮流、测验后续聊天和 GeoGebra 查看器完善了 释放。

亮点

自动模式 — 代理功能路由器

新的 auto 功能位于现有模式之上，并选择正确的模式 每个请求对应一个模式，而不是强迫用户预先选择一种模式。

  • 三阶段代理循环 — ANALYZING（单个 LLM 调用，流式传输） 思考）→ DELEGATING（最多 max_iterations 发出的路由器调用 delegate_to_<cap> 工具调用或原子工具调用）→ SYNTHESIZING（最终 内联答案，要么从循环中传递，要么通过结束语组装 法学硕士电话）。
  • 实现实际能力的途径 — deep_solve、deep_question、 deep_research、math_animator、visualize，加上聊天级原子 工具（web_search、web_fetch、rag…）位于同一路由器后面，因此 法学硕士可以在一轮中混合检索和完整的子功能运行。
  • 有界重试和配额 — router-LLM 的独立重试预算 错误、每次委托失败和参数验证反馈；一个可配置的 max_same_capability_calls 配额可防止循环在一种模式下旋转。
  • 干净的对话历史记录 - 子功能事件流经 forward_events 垫片用 call_id 标记每个内容事件，因此 对话回合运行时过滤器仅保留 Auto 自己的最终合成 保存历史。子运行仍会实时传输到用户界面。
  • answer_now 快速路径 — 当用户要求“立即回答”管道时 跳过分析+委托并立即生成内联回复。

三层内存子系统（内存 v2）

之前的平面内存页被结构化的三层存储所取代 具有明确的整合管道和专用工作台。

  • L1 / L2 / L3 布局 — L1 捕获原始运行轨迹，L2 保持标准化 文档记录，L3 在每个表面上保存精选的插槽（聊天、笔记本、书籍、 导师机器人）。每用户路径流经 PathService，因此多用户 部署保持隔离。
  • 固结器管道 — 模块化 consolidator/ 模块（分块器、防护装置、 解析、引用、运行、模式、行文档、元）将运行跟踪转换为 版本化的面向行的文档，具有稳定的 ID、之间的引用 图层和快照历史记录。
  • 内存工作台 UI — 新的 /memory 路线（graph、l1、l2、l3、 resolve）作为独立页面提供，带有工作台、集线器、图形查看器、运行 面板和存档状态横幅。可重复使用的 MemorySection 组件是 嵌入旧内存面板曾经所在的位置。
  • 一流的聊天工具 — read_memory 和 write_memory 曝光 作为代理工具（带有 i18n 提示），因此聊天/自动可以调用和更新内存 在一个回合内，而不需要单独的保存步骤。
  • 设置集成 — 内存现在有自己的页面 /settings/memory 具有运行控制、模式切换和存储状态。

关于代理引擎的深入研究、深度解决和问题

三个多代理管道已被重写为基于 共享代理引擎原语，删除数百个定制提示 文件和每个代理类。

  • 深入研究 → agents/research/pipeline.py — 四个阶段（Rephrase、 Decompose、Research blocks、Reporting）作为标记步骤实现 （THINK / TOOL / APPEND / OUTLINE / SECTION / FINISH）。动态 主题队列和CitationManager被保留；新的 APPEND 标签让 研究块将后续主题添加到队列中而不离开循环。 ask_user v2 使用多问题卡驱动最多三轮改写。
  • 深度求解 → agents/solve/pipeline.py — Pre-retrieve（仅限 KB）， Plan、Solve（每步 THINK / TOOL / FINISH / REPLAN 循环，带有 从求解到计划的后沿），以及最后的 Synthesize 步骤。每一步的 FINISH 流入下一步的提示上下文，因此答案如下 一个连续的叙述。
  • 问题/测验 — 协调器 + 管道替换旧的 generator / idea_agent/models模块；旧的提示目录已经是 完全删除。
  • 所有三个都放弃了旧的 agents/ 和 prompts/ 目录 各自的模式，留下一个管道文件和共享的标记步骤提示。

聊天功能和 LlamaIndex RAG 重构

代理聊天管道已围绕会话累积重建 “附加来源”清单和更干净的 LlamaIndex 管道。

  • 分支隔离源库存 — services/session/source_inventory.py 实现连接到活动分支的祖先链上的每个源。 当前回合的新来源显示了完整的预览；历史来源 显示一行，其中包含 id、名称、种类、大小和轮序号，其中 他们第一次出现。 LLM 调用 read_source(id) 来扩展完整的 按需文本。兄弟分支绝不会互相泄露源代码。
  • LlamaIndex 管道拆分 — 专用 config.py、ingestion.py、 retrievers.py和document_loader.py取代了以前的单片 管道模块。存储与 v1.3 版本保持向后兼容 索引。
  • 精益代理聊天提示 — agentic_chat.yaml (EN/ZH) 被重写为 匹配新的工具表面和源库存合同；旧的 并行工具提示脚手架消失了。
  • 内置工具注册表 — tools/builtin/__init__.py 是唯一的地方 其中聊天安装工具、提示提示和参数增强包装器位于 已注册。

能力基础设施统一

现在，每项功能都经过一个共享信封、一个 status-i18n 加载程序、 以及一个成本跟踪界面。

  • emit_capability_result 助手 — 每个功能都会发出其最终结果 通过一个助手来填充结果信封（标签、摘要、 负载、渲染提示）和跟踪使用跟踪器总数一致。
  • StatusI18n — 功能状态副本位于 capabilities/prompts/{en,zh}/<name>.yaml 并通过共享加载 StatusI18n 配件。硬编码的英文状态字符串已被删除 从管道中。
  • UsageTracker 成本面 — 代币使用和成本通过跟踪 每个功能运行一个跟踪器，暴露于结果包络，并显示 在新的 /settings/capabilities 管理页面上（实时列表、默认值、 每个功能覆盖切换）。
  • 已删除已弃用的 main.yaml 密钥 — 旧版 main.yaml 功能 副本已被删除，以支持按功能提示文件。

可视化：动画师融合为一种功能

独立的 Animator 菜单已合并到 Visualize 中，因此用户可以选择 可视化一次，系统选择渲染器。

  • render_type 鉴别器 — AnalysisAgent 选择六个渲染之一 类型 — svg、chartjs、mermaid、html（文本发射、三级 管道）或 manim_video / manim_image（Manim 子进程管道）。的 结果信封携带 render_type，因此前端委托给 正确的观看者。
  • 单侧边栏条目 — 旧的 Animator 菜单条目消失了；现在的用户 通过 Visualize 查看静态图表和 Manim 视频。的 全屏查看器/配置面板处理所有渲染类型。

新聊天工具

  • ask_user — 将 1-3 个结构化问题打包到一个有效负载中 暂停同一回合，直到用户回答。前端渲染一张卡片 让用户浏览问题并批量提交答案；的 管道继续转动，并将答案作为工具结果回传。 由 Deep Research 的 Rephrase 阶段使用，可用于聊天/自动。
  • web_fetch — 具有可读内容提取、严格方案的 URL 获取 / 私有 IP / 大小保护（在飞行前和重定向后应用）， 和 …[truncated] 输出超过上限时的标记。
  • write_note — 替换旧的 save_to_notebook 工具。两种模式： append 创建一条新记录（默认正文是渲染的记录， 可选代理编写的正文）和 edit 通过以下方式更新现有记录 record_id。
  • list_notebook — 活动的只读索引/向下钻取列表 用户的笔记本和记录。仅当用户实际拥有时才安装 笔记本电脑，因此通过构造不可能进行空运行。
  • github_query — 只读 gh CLI 包装器覆盖 pr、issue、 run、repo 和仅 GET 的 api 后备。没有突变动词 可通过工具表面到达。返回一个干净的“工具不可用” 未安装 gh 时的结果。

聊天界面功能

  • 删除聊天回合 (#443) — 消息项目现在带有稳定的 id， 会话 API 暴露 deleteMessage，聊天缩减器添加 DELETE_TURN 操作，409 与 404 检查拒绝删除仍在运行的转弯。 乐观临时 ID 在删除之前解析，以避免出现孤立的 UI 行。
  • 测验后续聊天编辑器 — FollowupChatComposer 和 QuizFollowupContext 让用户直接从测验开始聊天线程 问题。作曲家重用了主要的 ChatComposer （看，@space 选择器、KB 选择器、附件、LLM 选择器），但路由通过 专用跟随控制器。伴侣 quiz-judge.ts 助手支持 判断内联的后续答案。
  • 测验 UI 优化 — 测验答案文本区域可垂直调整大小 (#478)； 问题内容将单个换行符标准化为 Markdown 段落 (#441)。
  • GeoGebra 查看器 — Geogebra.tsx、GeogebraOpenCTA.tsx 和 GeogebraTabContext 添加一个 GeoGebra 小程序渲染器（通过加载 官方 GGB 小程序脚本），因此可以打开几何/代数片段 与聊天答案一起内联。

多用户数据隔离

v1.3.x 多用户介绍中的一些回归和差距 固定在聚焦通道中（#474，#465）。

  • 身份验证与中间件解耦 — 多用户身份解析否 不再依赖全局中间件状态，修复了 rebase 回归 在特定路由命令下导致跨用户数据泄露。
  • 旧版会话管理器路径捕获 — 旧版会话管理器 正确继承了活动用户范围，因此它的文件路径位于其中 每个用户的工作空间而不是共享的默认工作空间。
  • 前端在任何地方都使用 apiFetch — 每个经过身份验证的 client 调用 现在通过 apiFetch()，因此 auth 标头一致地附加。
  • SSL 绕过扫描 — DISABLE_SSL_VERIFY 现已到达法典提供商 以及 v1.3.10 之后仍然缺少的四个嵌入适配器。

环境设置、安装程序和本地启动器

安装 + 启动故事已被重写，以删除 .env 解析 迷宫并使deeptutor start / deeptutor init一流。

  • runtime_settings.py — 系统/身份验证/启动设置现已存在 具有显式默认值的一种类型化模块（backend_port、frontend_port、 cors_origins、disable_ssl_verify、chat_attachment_dir、…) 和 JSON 存储在data/user/settings/下。 280+ 系列传统 env_store.py 两个.env.example文件已被删除。
  • runtime/launcher.py — 拥有 后端 + 前端生命周期、端口发现、就绪探测和 清理。生成 web/.env.local，以便 Next.js 前端始终选择 解析后端端口。
  • deeptutor/runtime/banner.py — 共享本地化启动横幅 deeptutor start 和 deeptutor init 之间；阅读语言 界面设置中的首选项，以便横幅与 UI 区域设置相匹配。
  • init_wizard.py — 与提供商互动的 deeptutor init 向导 菜单，环境变量自动检测 API 键，实时 GET {base_url}/models 之前获取、策划的后备列表和可选的连接探测 保存。
  • model_catalog.py 已修剪 — 目录文件缩小了约 400 行，如下所示 将每个提供商的样板移至 provider_registry 和适配器中 模块。

设置 UI 重组

单个 /settings 页面已分为多个重点选项卡。

  • 新航线 — /settings/appearance、/settings/capabilities、 /settings/embedding、/settings/llm、/settings/mcp、 /settings/memory、/settings/search、/settings/status、 /settings/tools，具有共享布局和项目索引。
  • 工具页面 — 列出每个可聊天安装的工具、表面可用性 （例如，gh 对应 github_query），并公开每个工具的切换开关。
  • 功能页面 — 将新的 UsageTracker 成本表面与 上述每个功能的默认设置和覆盖切换。

Zulip 渠道整合

TutorBot Zulip 频道（在 v1.3.9 中添加）得到了后续修复 以及自助订阅功能（#480）。

  • 自动订阅 @mentions 频道 — 机器人可以自行订阅 它被@提及的任何渠道，因此它实际上收到了消息 在主题中。订阅频道警告已降级为信息级别，因此 启动日志不再误导性地标记成功路径。
  • 支持所有提及标志类型 — mentioned、wildcard_mentioned、 topic_wildcard_mentioned和stream_wildcard_mentioned均触发 机器人，固定频道-@-提及沉默。
  • 附件发送修复 — 重新发送的附件不再处理 Zulip 上传路径作为本地文件，上传助手不再崩溃 'str' object has no attribute 'name'，缺少路由元数据是 从 _recipient_map 重建，因此 Message must have recipients 错误 被淘汰。
  • 进度消息重复数据删除 — 内部 _tool_hint 进度事件 过滤掉频道发送，以便用户不再看到重复的“工具” 开始……”行。
  • 测试覆盖率 — 用于附件上传+发送恢复的新单元测试 和频道订阅行为。

测试

  • 针对自动管道、委托、架构和 auto 功能面 — 1100 多条新覆盖线，包括 端到端代理循环行为。
  • 新内存子系统的完整测试覆盖范围——分块器、合并器、 文档、ids、行文档、合并、元设置、模式、操作、引用、 运行，存储。
  • ask_user、github_query、list_notebook 的每个工具单元测试， web_fetch 和 write_note，以及询问用户 UI 状态帮助程序。
  • 改装聊天/研究/解决/问题管道测试 代理引擎标签（THINK / TOOL / APPEND / FINISH / …）。
  • 新的会话/源库存测试涵盖分支隔离和 累积的明显行为。
  • 前端测试涵盖消息分支帮助器、版本表面和 询问用户状态机。

升级注意事项

  • 设置文件重定位 — 首次启动将迁移任何 基于.env的设置放入新的JSON文件下 data/user/settings/。传统的 env_store 垫片已不复存在；如果你 脚本化的 .env 在外部写入，将它们指向 改为 runtime_settings.py 或 /settings API。
  • deeptutor start 是推荐的启动器 — start_web.py / start_tour.py 继续工作，但现在是薄包装纸 新款 runtime/launcher.py。向种子提供商运行一次 deeptutor init 和新机器上的凭据。
  • 动画器菜单用户 — 改为指向 可视化。的 现在，当用户请求时，功能会自动选择 Manim 视频/动画；现有的 Manim 渲染记录不受影响。
  • 内存数据迁移 — 传统的单 blob 内存格式是 首次访问时由合并器读取并写回 L2 / L3 记录。无需手动步骤；旧快照保留在磁盘上。
  • 能力作者 — 通过以下方式发出结果 capabilities/_shared.emit_capability_result 并将状态副本放入 capabilities/prompts/{en,zh}/<name>.yaml。硬编码英文状态 字符串将无法审核。
  • Beta 范围 — 此版本提供了大量新表面（汽车、 内存 v2，设置拆分）。固定到 v1.4.0-beta 进行生产，直到 GA 削减；欢迎针对任何新模块提出错误报告。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.3.10…v1.4.0-beta
