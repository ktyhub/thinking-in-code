DeepTutor v1.2.3

DeepTutor v1.2.3 Release Notes

发布日期： 2026.04.24

亮点

聊天中的文档附件

Chat 现在接受非图像文件附件（PDF、DOCX、XLSX、PPTX）和图像。编辑器中的新 paperclip 按钮可打开系统文件选择器，拖放/粘贴功能已从仅图像扩展到所有支持的文档类型。附加文档在待处理附件栏和消息历史记录中呈现为键入的预览卡（颜色编码图标 + 文件名 + 尺寸标签）。在后端，新的 document_extractor 模块使用 PyMuPDF / pypdf / python-docx / openpyxl / python-pptx （全部可选，优雅的回退）从上传的字节中提取纯文本，并将内容注入有效用户消息的 [Attached Documents] 部分，因此 LLM 无需单独的 RAG 调用即可读取文件。文件类型分类、每个文件和总大小限制以及重复名称检测由前端的 web/lib/doc-attachments.ts 和后端的 DocumentValidator 处理。 ###模型思维块展示 来自推理模型（DeepSeek-R1、具有扩展思维的 Claude、QwQ 等）的响应通常包含先前呈现为原始文本的 <think> / <|thinking|> 便签板块。新的 parseModelThinkingSegments 解析器 (web/lib/think-segments.ts) 将助理内容拆分为交替的文本和思维片段，而 AssistantResponse 现在将每个思维片段呈现为可折叠的 ModelThinkingCard（默认情况下折叠），因此用户可以窥视模型的思想链，而不会让草稿本淹没对话。不完整（仍在流动）的思维块会显示脉冲指示器并自动扩展。

用于嵌入的三态 send_dimensions (#368)

一些与 OpenAI 兼容的嵌入提供程序拒绝 OpenAI 的 text-embedding-3-* 模型所需的 dimensions 参数。修复分为两部分：首先，当型号名称与 text-embedding-3* 匹配时，适配器现在仅发送 dimensions（PR #368 by @jefflv）。其次，在“设置”页面、.env 存储 (EMBEDDING_SEND_DIMENSIONS) 和模型目录中添加了新的 发送尺寸 三态切换（自动/开/关），为操作员提供了明确的控制。 Auto（默认）保留#368启发式； On 强制为在自定义模型上接受该参数的提供者提供该参数； Off无条件压制它。切换是端到端反映的：目录 → provider_runtime.ResolvedEmbeddingConfig.send_dimensions → OpenAICompatibleEmbeddingAdapter。

LLM 提供商核心重构

单片 factory.py 已围绕新的 provider_core/ 包（约 3 000 行）进行了重写，该包为每个提供程序系列提供了自己的模块：openai_compat_provider、anthropic_provider、azure_openai_provider、github_copilot_provider 和 openai_codex_provider，全部继承自共享的 BaseProvider。 provider_factory.py 从配置中解析正确的运行时提供程序，并且通过从 PROVIDERS 注册表动态派生预设而不是维护硬编码字典，factory.py 本身从约 600 行缩减到约 490 行。新的 context_window.py 模块公开了 resolve_effective_context_window()，ContextBuilder 使用 resolve_effective_context_window() 将历史预算计算基于模型的真实上下文窗口而不是 max_tokens 输出上限，从而改善了具有大窗口的模型的长对话历史记录回忆。

Soul 模板编辑器（PR #373）

TutorBot 的“灵魂”（系统个性）现在可以直接在代理页面内创作。新的内联编辑器允许用户使用 YAML frontmatter 创建、预览和保存 SOUL.md 模板，取代了以前在磁盘上手动编辑文件的工作流程。由 @srinivasrk 贡献。

共同作者 保存到笔记本

Co-Writer 工具栏获得 保存到笔记本 按钮（📓 图标）。 Clicking 会以新的 co_writer 记录类型打开现有的 SaveToNotebookModal，因此共同作者草稿会与“知识”页面的“笔记本”选项卡中的聊天和测验条目一起显示。后端：co_writer 添加到笔记本记录类型枚举、汇总代理提示和 API 文字类型。

知识库管理改进

  • 拖放上传 - 知识页面现在接受文件直接拖放到知识库卡（或创建表单）上，并在上传开始之前进行实时扩展名/大小验证、重复名称检测和键入的文件选择列表。
  • /supported-file-types 端点 — 新的 REST 端点返回服务器当前的上传策略（接受的扩展、每个文件和每个 PDF 大小上限），因此 Web client 保持同步，无需硬编码。
  • 更丰富的知识库卡 — 每张卡现在都会显示创建/上次更新的时间戳、嵌入模型名称、维度、需要重新索引的徽章以及索引期间带有百分比读数的实时进度条。
  • 删除弹性 (#370) — shutil.rmtree 现在使用 onerror 处理程序来清除只读位并重试，从而防止 Docker 绑定安装和 Windows 权限错误将 KB 卡在列表中。
  • 进度持久性 — ProgressTracker 现在与 kb_config.json 条目一起写入快照文件并发出任务流事件，因此 WebSocket 订阅者和页面重新加载可以恢复实时索引状态，而无需依赖内存中的回调。当 KB 达到 ready 时，进度 blob 将从配置中删除，以使卡看起来像一个稳定的资源。

问题生成语言保真度

将 Book 引擎的 _language.py 中的语言指令系统提取到共享的 services/prompt/language.py 模块中。 Deep Question 代理 — Generator、IdeaAgent 和 FollowupAgent — 现在在系统提示上调用 append_language_directive()，确保测验问题、答案选择和后续答案尊重用户配置的语言，而不是偶尔转向英语。

设置页面导览重新设计

运行浏览按钮从页面底部移至顶部工具栏，位于保存草稿和应用旁边。导游本身已扩展为完成完整的保存和测试周期（保存→诊断→应用）。以前的底部区域被替换为简洁的配置注释，解释了 model_catalog.json 相对于 .env 的运行时优先级。

CLI：笔记本add-md和replace-md

两个新的 deeptutor notebook 子命令允许用户直接从终端添加或替换笔记本记录中的 Markdown 内容，这对于脚本化工作流程和 CI 管道非常有用。

错误修复

  • TutorBot 纯 CJK 机器人名称崩溃 — 创建一个名称仅包含非 ASCII 字符的机器人会产生一个空的 slug，从而破坏了 API 路线。现在生成了稳定的 ASCII 后备 (bot-<hash>)，并且前端显示创建错误 toast，而不是默默地失败。
  • React 19 I18nProvider 渲染时 setState 警告 - 在 I18nProvider 的第一次渲染期间同步调用 i18n.init()，从而触发有关渲染阶段状态更新的 React 19 警告。现在在模块加载时执行初始化；提供者主体仅通过 useEffect 同步 document.documentElement.lang。
  • 技能默认为关闭 — skillsAutoMode 现在默认为 false，因此新用户不会对自动技能注入感到惊讶，除非他们有意启用它。
  • Moonshot 默认基本 URL — 从 https://api.moonshot.ai/v1 更改为 https://api.moonshot.cn/v1 以匹配提供商当前的规范端点，并更新所有多语言自述文件。
  • 版本徽章显示 — 修复了 ZZPH100​​ZZ 合并期间引入的侧边栏版本徽章中的小渲染问题。

提供商注册表增强功能

  • custom_anthropic — Anthropic-API 兼容端点（例如 AWS Bedrock 代理）的新提供商规范，通过 Anthropic 后端而不是 OpenAI 兼容进行路由。
  • thinking_style — 新的 ProviderSpec 字段允许 Volcengine 等提供商宣传他们如何表示扩展思维模式。
  • 别名扩展 — lm-studio、anthropic-compatible、openai-compatible（连字符）现已被识别； canonical_provider_name() 使用 to_snake() 进行更稳健的归一化。

测试套件扩展

跨 15 个新文件或扩展文件的净 +1 900 测试线：test_document_extractor.py (245)、test_language_prompts.py (156)、think-segments.test.ts (122)、test_provider_runtime.py (103)、test_llm_probe_config.py (116)、test_manager_delete.py (79)、doc-attachments.test.ts (75)、test_context_window_detection.py (60)、test_progress_tracker.py (58)、quiz-question-type.test.ts (58)，以及 test_factory_provider_exec.py、test_context_builder.py、test_chat_params_config.py、test_config_module.py、test_knowledge_router.py 和 test_start_tour.py 的扩展。
