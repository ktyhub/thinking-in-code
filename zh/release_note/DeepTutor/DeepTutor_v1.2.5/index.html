DeepTutor v1.2.5

DeepTutor v1.2.5

DeepTutor v1.2.5 Release Notes

发布日期： 2026.04.25

亮点

附件存储和文件预览抽屉

聊天附件现在作为一流的会话工件保留，而不是仅作为消息行中的内联 base64 blob 存在。 Turn 运行时在文档提取之前将每个上传的文件写入新的附件存储，在消息上记录稳定的 URL，并从持久的聊天历史记录中删除庞大的 Base64 有效负载。

  • 后端附件存储 — deeptutor/services/storage/attachment_store.py 引入了可插入的 AttachmentStore 协议和植根于 data/user/workspace/chat/attachments 的默认 LocalDiskAttachmentStore。该路径可以用 CHAT_ATTACHMENT_DIR 覆盖，记录在 .env.example 中。
  • 安全附件服务 - 新的 /api/attachments/{session_id}/{attachment_id}/{filename} 路由器通过遍历安全路径解析、上传原子写入、内联 Content-Disposition、UTF-8 文件名处理和私有无缓存标头来提供存储的文件。
  • 稳定的附件元数据 — Attachment 现在带有 id 和 extracted_text； TurnRuntimeManager 生成丢失的 ID，保留原始字节，存储预览 URL，并保留从 Office/文本文档中提取的文本，以便 UI 可以准确显示助手读取的内容。
  • 右侧预览抽屉 - FilePreviewDrawer 为聊天文件添加了克劳德风格的侧面板。在桌面上，它会挤压聊天栏；在较小的屏幕上它会重叠。外壳保持安装状态以便即时打开/关闭，而重型预览主体则推迟到幻灯片动画之后以避免卡顿。
  • 预览渲染器 - PDF 在浏览器查看器中渲染，图像和 SVG 使用本机 <img> 渲染，Markdown 重用主 Markdown 渲染器，代码/文本文件使用带有语法突出显示的 RichCodeBlock，Office 文件显示后端提取的纯文本，不受支持/旧文件回退到下载卡。
  • 附件操作 - 待处理的作曲家芯片和发送的消息卡是 clickable，具有键盘焦点环、下载、复制链接、退出关闭以及用于旧会话的优雅的“未存储旧文件”消息。

更广泛的代码和文本附件覆盖范围

v1.2.4 文本/代码附件支持已大幅扩展，使后端 RAG 路由器、聊天提取器、前端上传允许列表、图标和预览荧光笔保持一致。

  • 更多接受的格式 - FileTypeRouter.TEXT_EXTENSIONS 和 TEXT_LIKE_EXTS 现在包括 JSONC/JSON5、MJS/CJS/MTS/CTS、Vue/Svelte、Kotlin 脚本、Groovy/Gradle、C#/Zig/Nim、Objective-C、Perl/Lua/Julia/Dart、 Haskell/Clojure/Elixir/Erlang/OCaml/F#、Lisp/Scheme/Racket、Solidity、fish/vim、GraphQL/protobuf、CMake/Makefile、Terraform/HCL、nginx 配置和 Dockerfile 样式文件。
  • 中央语法映射 — web/lib/code-languages.ts 将扩展名和特殊文件名（Dockerfile、Makefile、CMakeLists.txt、点文件等）映射到 Prism 语言名称，以便预览分类和代码突出显示保持同步。
  • 导出前端助手 — extOf() 现在从 web/lib/doc-attachments.ts 导出用于预览管道，并且文档图标/类别已扩展以匹配新的扩展集。

附件感知深层功能

上传的附件现在流入更多代理管道，而不仅仅是默认的聊天阶段。

  • 基本代理奇偶校验 - 当存在附件时，非流式 LLM 调用现在使用与流式调用相同的 prepare_multimodal_messages() 路径，包括非视觉模型的图像剥离/日志记录。
  • 深度求解 — DeepSolveCapability 不是仅提取第一个图像 URL，而是通过 MainSolver 将图像附件转发到规划器、求解器和重新规划调用中，因此多模式问题在整个规划-反应-写入循环中保持可见。
  • 深度问题 — 主题生成和后续回答将附件传递给底层代理。当上传的 PDF 已从 Base64 存储中提取并剥离时，模仿模式现在可以直接使用 [Attached Documents] 文本。
  • 深度研究 - 研究计划接受附件并将其转发到第一个计划 LLM 调用中，无论是改写还是分解，而不会在以后的计划轮次中重复相同的图像/文件上下文。
  • 可视化 - 可视化分析现在接收聊天附件，使图表或屏幕截图能够影响渲染类型选择和数据提取。

TutorBot 导出和笔记本捕获

TutorBot 聊天会话现在具有与常规聊天相同的捕获路径：

  • 代理聊天页面在标题中添加了 保存到笔记本 和 下载 Markdown 操作。
  • SaveToNotebookModal、notebook-api、后端笔记本请求类型和 RecordType 现在可识别新的 tutorbot 记录类型。
  • 知识页面显示 TutorBot 笔记本条目及其自己的紫色徽章和机器人图标。
  • 恢复的 TutorBot 聊天历史记录现在会跨多个帧重新捕捉到底部，因此第一次绘制后 Markdown/KaTeX 的增长不会让用户看到最新消息。

设置游览诊断和安装稳健性

现在，引导设置之旅会解释依赖项失败，而不是默默地失败：

  • Bootstrap 依赖项安装捕获 stdout/stderr 并打印真实的 pip 错误以及手动重试命令。
  • uv 分辨率在尝试安装之前检查常见安装位置（~/.local/bin、~/.cargo/bin、自制路径），并在 uv 安装成功但仍不在 PATH 上时报告明确的后续步骤。
  • uv 安装失败现在显示 Python 轮可用性、陈旧 shell PATH、PyPI 镜像问题和直接安装程序选项的本地化英文/中文提示。
  • Node.js/npm 版本检查在运行 --version 之前通过 shutil.which() 解析可执行文件，在 Python 子进程强化后改进 Windows .cmd/.bat 兼容性。

聊天和知识用户体验修复

  • 自动滚动可靠性 - useChatAutoScroll 现在在附加其突变观察器之前等待消息内容，修复了重新打开消息容器最初为空的会话时错过的底部滚动行为。
  • 预览动画优化 - globals.css 添加了 chat-preview-shell 过渡，以便抽屉滑动和聊天列挤压以相同的 220 毫秒时间一起移动。
  • 知识上传选择器 — KB 文件输入不再依赖于浏览器/操作系统 accept 过滤器，该过滤器可能会隐藏某些系统上的有效文件；选择后，应用内验证仍会强制执行支持的文件策略。
  • 本地化预览副本 - 添加了英文和中文字符串，用于预览加载、复制链接、不可用预览、旧文件、删除附件和 Office 提取文本说明。

测试套件扩展

  • 功能附件转发 - tests/core/test_capabilities_runtime.py 增加了深度解决、深度问题、深度研究和可视化附件传播的覆盖范围，包括提取文档文本的模拟模式。
  • 研究规划边缘案例 - tests/agents/research/test_research_pipeline_rag.py 验证启用改写但执行零迭代时附件是否被转发以分解，确保第一个实际规划 LLM 调用仍能看到上传的上下文。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.2.4…v1.2.5
