xerj v1.0.0-rc.102

预发布 发布时间2026年11月7日 来源xerj-org/xerj 英文原文

xerj v1.0.0-rc.102

仅限 Linux 的版本。 此版本附带 Linux 二进制文件（x86_64 和 aarch64、glibc 和 musl，以及两个 glibc 目标的 .deb）和 XERJ Query-1 模型包。 macOS 和 Windows 版本将在此版本的更新中发布。在此之前，安装程序和 releases/latest 会继续在每个平台上为 v1.0.0-rc.101 提供服务；通过下载以下资源在 Linux 上安装 rc.102。

[1.0.0-rc.102] - 2026-11-06

**rc.102：XERJ Query-1 服务规则 R8，防计数计数 路径无法表达，而rc.102公共窗口。**模型包 此版本附带的 candidate_a_s47_r8 的重量与 rc.101的candidate_a_s47（每个权重文件具有相同的sha256）并进行更改 仅如何提供答案：规则 R8（详细信息在“已更改”下）。关于 XERJ 分数 v2 （根据 Opus 5.5 = 100 衡量的信用），在四个开发系列上 teacher_dev、bench_select、s1b_dev 和 d1_select（各 400 件， 总共 1,600 名），种子 47 从 90.29 移动到 94.69（+4.40，95% 间隔 +3.32 到 +5.64，配对的世界簇引导程序）；种子 11 和 29 移动 +3.95 和+4.17。这些是开发项目，R8是根据以下诊断选择的： 这些相同的项目，因此 94.69 是样本内的编号，而不是保留的编号。错了 每个种子的答案都会上升：47 号种子上的 1,600 个答案中的 9 到 10 个，11 号种子上的 12 到 15 个。 唯一保留的读物是 fresh_v1 集，于 2026 年 11 月 4 日读过一次，并且 在 R8 下重新计分，无需第二次读取：Net 0.3333 至 0.3481，右 112 至 118，错误 11 到 12。对新措辞和新设置计数的稳健性不正确 分别测量。引擎准确地服务于评估的规则： 合并 rc.102 树，所有 1,600 个开发项目的引擎行给出 与评估的 Python 行相同的服务结果（1,600 行中的 1,600 行；284 行 仅原始状态不同，UNKNOWN 与 UNSUPPORTED，两者都是 declines）。如果没有 --facts-model-dir，节点就是 rc.101 节点。

升级注意事项

  • rc.102 捆绑包需要 rc.102 二进制文件。 rc.101 拒绝其 bundle.json（未知规则decline_v2_r8，模型状态unavailable）。 rc.102 二进制文件仍然加载 rc.101 包并在下面提供服务 decline_v2 具有合作伙伴协议，与以前一样逐字节。
  • 计数不再等待 R8 下的合作伙伴。 使用 rc.102 当问题转向计数时，会提供计数，这很难 检查通过且发动机应答；合作伙伴模型不运行，并且 partner_agreement 是 null 而不是 true。读取 final_status 和 final_answer 和以前一样。
  • 数据目录。 rc.102 保留 rc.101 的存储默认值（ZPS4 帖子，行字典存储文本，磁盘格式 4)，因此 rc.101 数据 目录打开不变。从 rc.100 进行单向升级，如下所述 rc.101 仍然适用于 rc.100 最后写入的目录。这方面没做 窗口，并结转：rc.101 表示其存储和摄取通道将 在 rc.102 之前到达公共 main。他们没有；他们在私下里 仅构建树，并且来自公共 main 的构建仍然写入格式 3 和 拒绝 format-4 目录。
  • 出处。 rc.102 二进制文件是从私有树构建的：public main 和 34a2f244（此窗口的合并）加上 XERJ-Query 引擎通道 加上模型板条箱 xerj-infer、xerj-serve 和 xerj-exec，它们是 获得专有许可，仅作为二进制 + 模型捆绑包提供。那些 板条箱不是 Apache-2.0 并且不在公共存储库中；的 Apache-2.0 许可证涵盖 main 上的引擎源代码。
  • XERJ-Query 保持选择加入状态。 标志为 --facts-model-dir <DIR>（或 XERJ_FACTS_MODEL_DIR）；如果没有它，每个 /_facts 路径都会回答 404 xerj_query_not_enabled。

添加

  • xerj autoindex <path> --facts <namespace> 将表行写入 XERJ Query-1 事实：SQLite 文件、SQL 转储、CSV/TSV 和 XLSX (#2988)。每一行都是一个主题 其中 subject_id 是键列（id、<table>_id、…或 --key），每个 另一列中的一列键入了引用该行的事实，因此计算问题会涉及到 没有手写的事实。重新运行只写更改的行（撤回旧的 版本，写入新的）并撤回删除的行；未更改的行是 无操作。在 rc.101 上测量：1,000 行 → 0.36 中的 6,000 个事实； “有多少 人们在柏林有办公室吗？” → 366 通过 path: counting 与合作伙伴 协议（金366）。映射是每行更改函数 (facts_rows::RowFactMapper::map_change) 因此流媒体源可以重用它。
  • 节点内的实时 Postgres 源 (#2984)：xerj connect postgres://… 在一致快照中对所选表进行快照，然后 通过逻辑应用每个插入、更新、删除和截断 复制，在重新启动后仍然存在，并从其确认的 LSN 恢复。 HTTP GET /_xerj/sources、GET|PUT|DELETE /_xerj/sources/{name}； MCP工具 xerj_sources（MCP 列出了 21 种不带轮毂键的工具，24 种带轮毂键的工具）。 在 x86_64 笔记本电脑（32 线程）上针对 Postgres 16 上的 PR 进行测量 同一主机：1,000,000行表，快照速度为54,776行/秒； 提交可读 p50 16.9 ms、p95 26.6 ms 超过 6,000 个样本（991） 提交/秒；在 kill -9 中流之后，27,696 行 = 27,696 个文档，其中 0 丢失、多余、陈旧或重复。参见 docs/LIVE_SOURCES.md。
  • xerj autoindex 索引 zip、tar、tar.gz/tgz 和 tar.zst 档案，其中之一 级别深，拒绝绝对和 .. 成员路径、链接和特殊路径 文件，具有字节、成员和扩展比上限 (#2982)。 xerj 来源 [--json] and docs/SOURCES.md 列出了获取数据的所有方法。
  • Cohere Rerank 作为第二个 _search 重新排名提供商，“重新排名”： {"provider": "cohere"}，关闭，直到操作员设置密钥；端点是 可配置，以便文档文本可以保留在私有 Cohere 部署上 （＃2985）。参见 docs/RERANK.md。
  • Cohere 示例 (#2983)：Cohere 的 OpenAI 兼容的嵌入器配置 Route，一个 stdlib Command RAG 示例，其引用解析为 file 和 页，
