xerj v1.0.0-rc.101

[1.0.0-rc.101] - 2026-11-05

rc.101：XERJ-Query — 引擎回答事实并计算问题 在 CPU 上运行的模型，默认情况下关闭。 此版本附带已编译的 XERJ-Query 进入二进制文件并通过 /_facts 在以以下开头的节点上提供它 --facts-model-dir <DIR>：将事实写入命名空间，询问自然语言 问题，并阅读已验证的答案及其引用的证据和确切的 产生它的程序。回答计数问题（“有多少……超过……？”） 由确切的执行者执行，仅当两个独立种子模型达成一致时才执行 程序。该模型作为单独的发布资产提供，可交换 xerj-model-bundle-v1 目录（FP16 权重，在带有 int8-guard 的 CPU 上服务） 相同权重的编码——没有 GPU，没有任何东西离开机器）。论诚实 XERJ 分数 v2（根据 Opus 5.5 衡量的信用值 = 100 分 + 计数 评估）发货的捆绑包 candidate_a_s47，分数 90.29 标准评估——不是新鲜/密封的套装；对新措辞的鲁棒性和 该捆绑包的新鲜凝固计数不单独测量。发动机服务 准确评估的捆绑包：逐字节复制其答案 共2,387个评价项目。没有标志的节点是节点 rc.100 was: no /_facts路线，无模型加载，相同的MCP工具列表。

升级说明 — 在现有数据目录上启动 rc.101 之前阅读

  • 单向数据目录升级。 rc.101 将新段写入 ZPS4 帖子 并将文本列存储为行字典块默认情况下。第一个 刷新将数据目录移动到磁盘格式4； rc.100 及每个 早期构建只读格式 3 并在打开时拒绝这样的目录（“写入 由较新的 xerj 编写”）。 rc.101 已写入的数据目录不能是 再次由 rc.100 打开 — 在首次启动之前进行备份或快照，如果 您可能需要回滚。要继续编写格式 3 的帖子，请设置 XERJ_FTS_POST_CODEC=packed 在第一个 rc.101 启动之前（和 XERJ_STORED_ROW_BLOCKS=0 保留旧的存储文本布局）；选择加入 位置关闭文本字段 (index_options: docs|freqs) 将目录移动到 格式 5。这些默认值将在 rc.102 之前的公共 main 上，因此稍后 公开版本打开 rc.101 目录。
  • 出处。 rc.101 二进制文件是从私有树构建的：public 3f6aefa8 的 main 加上 XERJ-Query 引擎通道（存储、摄取、事实 接线）加上型号板条箱 xerj-infer、xerj-serve 和 xerj-exec， 其获得专有许可，并且仅作为二进制 + 模型捆绑包提供。 这三个包不是 Apache-2.0，也不在公共存储库中；的 Apache-2.0 许可证涵盖了 main 上的引擎源代码。发动机车道 （非专有）在 rc.102 之前通过拉取请求登陆公共 main。
  • XERJ-Query 是选择加入的。 像以前一样启动的节点没有任何变化。的 标志为--facts-model-dir <DIR>；请参阅“已添加”下的第一个条目。

添加

  • XERJ-Query 是可选的。它在编译后发布并保持关闭状态直到服务器 以 --facts-model-dir <DIR>（或 XERJ_FACTS_MODEL_DIR； 旗获胜）。关闭时，节点的行为与 rc.100 相同：每个 /_facts 路径都会应答 404 xerj_query_not_enabled 命名旗帜，没有模型加载，没有事实 线程启动后，MCP工具列表中没有xerj_facts_ask（已发布的 模式是默认列表），内存命名空间和大脑以结尾 -facts又是普通的名字。上，以下所有内容均适用； xerj mcp 当它代理的节点回答 GET /_facts 时，列出 xerj_facts_ask （XERJ_MCP_FACTS=on|off 决定）。
  • 默认构建中的事实：/_facts、xerj_facts_ask MCP 工具以及 _ask 以 decline_v2 作为默认规则（verify: served 保留）。 读取final_status和final_answer：在decline_v2下是普通的status 和answer 是未经检查的程序。现在每个 _ask 响应都带有一个 path 字段、facts 或 counting 以及计数答案报告其 program_sha256与合作伙伴型号是否一致。 /_facts状态 不再携带 "spike": true 标志并报告节点的计数 状态。如果没有模型目录，XERJ-Query 将关闭（请参阅上面的条目）。
  • 在默认版本中精确计算答案。当节点启动时 具有计数作用的模型包（请参阅下面的“模型包”）， 计数问题由精确执行器回答——RC4计数路径 （堆栈 v6）在 xerj-infer 和 xerj_serve::counting 中 — 并且仅在以下情况下提供 问题转向计数，通过了严格检查，并建立了合作伙伴模型 制作相同的节目；否则，事实路径将在 decline_v2 下回答。 xerj ask CLI 获得匹配计数操作。现在COUNTING_OFF 仅当捆绑包没有计数角色或其计数模型为 缺少或未通过负载检查；在这种情况下，事实将继续发挥作用，并且只有 计数问题 decline。 依赖 rc.101 的已知限制（根据用户编写的事实衡量）： 只有当被统计对象的每一个事实都带有一个 稳定的 subject_id（每个主题一个，关于它的每一个事实）；没有它 计数为 INCOMPLETE，答案为 UNKNOWN 和 path: "facts"。的 op-set 是集合计数（“多少个 X 有 Y”，可选“distinct ”）； 总和、总计和数字阈值 decline。服务计数统计 匹配集的成员，并且不检查问题的名词： “柏林办事处总共有多少台设备？” office = Berlin以上 没有 devices 关系的事实作为经过验证的人数 (path: "counting"、partner_agreement: true、与program_sha256相同 “有多少人在柏林设有办公室”）。计算没有证据 id 的答案 根据设计，响应仅将程序命名为 program_sha256。询问 对于您所指的会员类型并读取会员计数
