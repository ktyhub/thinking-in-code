rancher v2.15.3

[!重要]

  • 如果您使用的是 Active Directory 联合身份验证服务 (AD FS)，升级到 Rancher v2.10.1 或更高版本可能会导致身份验证问题，需要手动干预。这些问题是由于 AD FS 依赖方 Trust 无法从元数据中获取签名验证证书造成的。有关更多信息，请参阅 #48655。这些问题可以通过以下两种方法之一来纠正：

  • 从联合元数据更新依赖方 Trust 信息（依赖方 Trust → 从联合元数据更新…​）。

  • 直接添加证书（依赖方 Trust → 属性 → 签名选项卡 → 添加 → 选择证书）。

Rancher v2.15.3是Rancher的最新补丁版本。这是社区版本，引入了维护更新和错误修复。

有关一般次要版本中新功能的更多信息，请参阅 v2.15.0 release notes。

漏洞的安全修复

此版本解决了以下安全问题：

牧场主

  • 修复了 Rancher 元代理端点中的一个安全漏洞，其中在无法阻止转发请求的位置评估目标白名单。经过身份验证的用户可能会导致 Rancher 服务器向允许列表旨在阻止的内部服务发送请求并接收响应。现在在请求处理程序中强制执行允许列表，该处理程序在建立任何连接之前拒绝不允许的目的地。有关更多信息，请参阅 CVE-2026-88809。
  • 修复了 Rancher RBAC 验证中的一个安全漏洞，其中未检查 GlobalRole 的 inheritedNamespacedRules 字段是否有权限升级。具有管理全局角色和全局角色绑定委托权限的用户可以在下游集群中授予超出其自身权限的权限。 GlobalRole 和 GlobalRoleBinding 准入 Webhooks 现在以与其他权限携带字段相同的方式验证此字段。有关更多信息，请参阅 CVE-2026-88810。
  • 修复了 Rancher Manager 元代理中的一个安全漏洞，其中调用者自己的 Rancher 凭据并未始终从转发到第三方云提供商主机的请求中删除。登录用户的会话凭证可以在普通使用配置视图期间发送到云提供商，并且当省略代理的凭证选择标头时可以发送 API client 的 Rancher 令牌。代理现在会在每个请求路径上删除调用者的凭据。有关更多信息，请参阅 CVE-2026-88811。
  • 修复了 Rancher 中的一个安全漏洞，其中保护本地集群 shell 的授权检查并未应用于可以到达它的每个 API 路由。任何经过身份验证的用户（包括在 local 集群上没有权限的用户）都可以在管理集群上获取非特权 shell pod，从而破坏管理平面的预期隔离。现在对所有请求表单一致地执行授权检查。有关更多信息，请参阅 CVE-2026-104623。

舰队

  • 修复了 Fleet 代理管理控制器中的权限提升漏洞，其中普通用户创建的 Fleet 集群对象可以引用 Rancher 管理 (local) 集群的管理凭据。这允许仅持有默认 user 全局角色（在本地集群上没有权限）的经过身份验证的用户在 Rancher 管理集群上获得集群管理员权限，从而在所有托管集群上获得集群管理员权限。现在，当密钥被标记为供引用命名空间使用时，Fleet 仅接受来自另一个命名空间的 kubeconfig 密钥，并且仅将代理部署到其自己的系统集群的管理集群上。有关更多信息，请参阅 CVE-2026-94290。
  • 修复了 Fleet 中的一个安全漏洞，其中集群注册期间声明的集群身份未绑定到用于请求的注册令牌。知道另一个集群的 client 标识符的有效工作区注册令牌的持有者可以获取该集群的队列管理命名空间的凭据并破坏其合法代理。舰队现在记录集群注册所用的注册令牌，并拒绝使用不同令牌声明相同集群身份的注册请求。有关更多信息，请参阅 CVE-2026-104615。

有关其他详细信息，请参阅 Rancher 的 文档 或 Rancher 的 GitHub 存储库 中的安全建议和 CVE 页面。

牧场主将军

主要错误修复

  • 修复了删除环境变量后使用环境变量配置的 Rancher 设置保留过时值和 source: env 属性的问题。当删除环境变量时，Rancher 现在会在启动时清除存储的环境源和值。然后该设置将恢复为其默认值。请参阅#58075。

集群配置

主要错误修复

  • 修复了以下问题：如果在迁移其注册令牌之前重新部署集群代理，则升级 Rancher 后导入的集群可能会变得不可用，从而使代理无法使用
