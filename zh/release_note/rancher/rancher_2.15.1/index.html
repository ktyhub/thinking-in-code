rancher v2.15.1

[!重要]

  • 如果您使用的是 Active Directory 联合身份验证服务 (AD FS)，升级到 Rancher v2.10.1 或更高版本可能会导致身份验证问题，需要手动干预。这些问题是由于 AD FS 依赖方 Trust 无法从元数据中获取签名验证证书造成的。有关更多信息，请参阅 #48655。这些问题可以通过以下两种方法之一来纠正：

  • 从联合元数据更新依赖方 Trust 信息（依赖方 Trust → 从联合元数据更新…​）。

  • 直接添加证书（依赖方 Trust → 属性 → 签名选项卡 → 添加 → 选择证书）。

Rancher v2.15.1是Rancher的最新补丁版本。这是社区版本，引入了维护更新和错误修复。

有关一般次要版本中新功能的更多信息，请参阅 v2.15.0 release notes。

漏洞的安全修复

此版本解决了以下安全问题：

牧场主

  • 修复了 Rancher 的 SAML 身份验证处理程序中的一个安全漏洞，该漏洞导致断言重播保护在高可用性（多副本）部署中无效。由于每个副本在单独的内存缓存中跟踪消耗的断言 ID，因此可以针对其他副本重放捕获的 SAML 断言，以创建其他经过身份验证的会话作为受害者。该修复跟踪所有副本中使用的断言 ID。所有 SAML 提供商都受到影响。有关更多信息，请参阅 CVE-2026-75034。
  • 修复了 Rancher 项目范围的 secretsController 中的安全漏洞，其中项目机密仅根据 field.cattle.io/projectId 注释传播到命名空间，而不验证引用的项目是否属于同一集群。在一个下游集群上具有命名空间创建权限的经过身份验证的用户可以欺骗此注释，以从另一集群中未经授权的项目泄漏项目机密。现在，控制器在传播机密之前会验证注释是否引用同一集群中的项目。有关更多信息，请参阅 CVE-2026-75033。
  • 修复了 Rancher 命令式 ext Token API（ext.cattle.io/v1 令牌）中的安全漏洞，其中任何经过身份验证的用户都可以通过提供精心设计的标签选择器、公开令牌元数据和存储的不记名令牌哈希来列出和观看其他用户的令牌。存储现在无条件强制执行每个用户范围，因此调用者只能看到自己的令牌，并且读取响应不再返回存储的令牌哈希。有关更多信息，请参阅 CVE-2026-75035。
  • 修复了 Rancher 的 GlobalRole 控制器中的一个安全漏洞，其中对 GlobalRole 资源具有委派 create 或 update 权限的用户可以将 authz.management.cattle.io/cr-name 注释设置为针对任意现有的 ClusterRole（例如内置 cluster-admin）。然后，控制器在不进行所有权检查的情况下覆盖规则，剥夺所有绑定主体的权限，并导致本地管理集群上出现持久的、集群范围的 RBAC 锁定。有关更多信息，请参阅 CVE-2026-71404。
  • 修复了 SUSE Rancher Norman /v3/users API 中的一个安全漏洞，其中更新路径未强制 User 资源上的 username、principalIds 和 displayName 字段的不变性。持有 users 上的 update 权限的调用者可以重新绑定用户的外部主体身份，从而在下一次外部登录期间启用帐户接管或创建拒绝服务条件，使现有角色绑定无法访问。 API 存储和admission-webhook 层已更新，以拒绝对这些身份字段的创建后更改。有关更多信息，请参阅 CVE-2026-71403。

舰队

  • 修复了 Fleet 的 Helm 模板预处理中的安全漏洞，其中 Fleet 控制器评估的模板可能会访问网络资源。可以提供 untrusted 捆绑包内容的用户可以公开集群元数据和有关可从控制器访问的主机的信息。 Fleet 现在拒绝其 Helm 模板值需要网络访问的捆绑包，并报告相应的 GitRepo 错误。有关更多信息，请参阅 CVE-2026-75036。
  • 修复了 Fleet 中的一个安全漏洞，其中代理在代理启动的集群注册期间提供的集群标签应用于生成的 Cluster 对象，包括用于捆绑定位的保留 management.cattle.io/ 标签。在多个 trust 域共享队列工作区命名空间的部署中，这允许注册集群匹配另一个租户的 Bundle 或 GitRepo 目标并接收该租户的清单和解析值 Secret。 Fleet 现在会丢弃代理发起的注册时提供的保留标签。独立 Rancher 部署的默认配置不受影响，因为 Rancher 使用管理器启动的注册。有关更多信息，请参阅 CVE-2026-93538。
  • 修复了 Fleet 中的一个安全漏洞，其中在未经捆绑包固定的服务帐户授权的情况下，应用了捆绑包通过 namespaceLabels 和 namespaceAnnotations 请求的命名空间标签和注释。在多租户部署中
