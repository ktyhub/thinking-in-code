Codewhale v0.9.6

修订 发布时间2026年8月12日 来源codewhale-hq/Codewhale 英文原文

Codewhale v0.9.6

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，两个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale 和 codew 命令资产 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.6

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

手动下载——平台档案（推荐）

下面的每个存档都包含 codewhale 下的相同运行时和 codew 命令名称，加上安装脚本：

Unix（Linux / macOS）：

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

窗户：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它安装 codewhale.exe和codew.exe下 %LOCALAPPDATA%\Programs\CodeWhale\bin 并将该目录添加到 当前用户路径。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径

便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。

每个平台还有 裸露、未存档 codewhale-<platform> 和 codew-<platform> 资产。七个 codewhale-tui-<platform> 文件名 附加到 v0.9.5 的是字节相同的兼容性副本，仅用于让 已安装的 v0.9.4 clients 发现并跨越这个单一二进制文件 过渡；当前的安装程序不会公开第三个运行时。遗留的 npm 软件包 deepseek-tui 已弃用并且不会重新发布。用于迁移 来自 v0.8.x 旧二进制名称，请参阅 docs/REBRAND.md。

v0.9.6 里有什么

Codewhale v0.9.6 是一个减法版本：更少的运行时防护，一个稳定的版本 及时、真实的提供者结局，以及保留的更小的压缩路径 提供者缓存。这些变化是通过匹配的终端工作台 2.1 实现的 与 Pi 0.8.41 运行，并通过重复手动压实进行测试。

添加

  • web_search 默认为 Firecrawl Cloud，无需 API 密钥；无钥匙请求 无标头且受配额限制，而可选的用户密钥会提高限制。
  • 基于 main 的绿色网络现在会发出可操作的手动部署提醒，因此 当 Cloudflare 仍然提供服务时，站点更改不会悄悄出现 较旧的修订版。
  • Mistral AI是一流的提供商路线，包括Codestral模型， 第一方推理支持、身份验证、选择器条目和别名。
  • 无头 Bash 可以传输明确请求的持久 Unix 服务 退出执行运行，并带有所有权和清理收据。
  • /remote-env 从当前 GitHub 或 CNB 分支提示打开托管工作，并且 准确说明哪些未推送、脏、忽略、秘密和会话状态保持不变 本地。
  • Linux ARM64 版本和夜间资产是使用本机进行静态 musl 构建 启动检查。
  • 维护人员可以报告观察到的来自同一匿名者的每日活跃安装， 聚合遥测数据集；没有收集额外的 client 数据。
  • 舰队派遣成员现在处于只读证据（无网络）上限 保留 Web 工具的只读 search 和 fetch 操作 — 与 普通侦察兵 - 当每个到达表面（web.run、fetch_url、 github，MCP）保持被拒绝状态并且哨兵支持的能力范围 仍然是故障关闭逆止器。
  • /fleet setup可以显示可选的、确定性的、未批准的角色到模型 仅根据已配置的就绪路由构建的咨询。接受、编辑和拒绝 全部保留在现有的人工审核配置文件保存边界内；的 咨询永远不会启动舰队或编写第二个配置。
  • /update 检查较新的 Codewhale 版本并从内部安装它 TUI，而 tui_help 为代理提供与用户看到的相同的命令和键映射。
  • Markdown 文件路径在终端支持的情况下呈现为 OSC 8 链接， 每个坐席行都可以直接打开该坐席的成绩单。
  • ACP 编辑器会话可以执行多轮文件、搜索、Git、补丁和 通过共享运行时注册表显式启用 shell 工具调用。 Shell 访问需要 client 的终端功能和 Codewhale 的终端功能 无头 shell 选择加入，并且取消会在执行之前停止运行中的工具 转返回（#5225 by @rafaelcavalheri）。
  • 小写 read 将有界类型的 PNG、JPEG、GIF 和 WebP 结果返回到 支持图像的聊天、响应、人类和 ACP 路线。纯文本路线 收到明确的遗漏收据；图像字节永远不会溢出到普通字节中 转录、导出、压缩或中继文本。

已更改

  • 全新安装默认启用匿名使用计数，并在 原生的首次运行 Codewhale 模式，可立即选择退出。先前 declines 保持关闭状态。 Codewhale不收集对话、代码、提示、文件、 存储库或分支名称、凭证、模型内容或每轮活动 时间表。
  • 宽终端使用响应式全屏海洋画布，具有适度的 排水沟：散文保持可读性，而工具、差异、工作表面、 作曲家和状态镶边可以使用可用宽度。转和主要 活动接缝呼吸，无需填充工具组内的每个调用。
  • Root CLI 帮助直接描述产品操作，而不是暴露内部 TUI/运行时层。
  • 当请求等待时，Bash action="wait" 现在默认阻塞；来电者 仍然可以请求非阻塞快照和持久服务所有权 仍然明确。
  • 压缩是一个缓存稳定的摘要请求，然后是一个提交的请求 替换摘要和有界的最近消息尾部。较早保存的会话 依然恢复。
  • 询问、工作、自动审阅和完全访问共享一个稳定的基本提示。模式 权限和实时工具目录继续存在差异；前者 Act 标签现在适用于整个产品和发货区域。
  • 完全访问现在一致地自动批准不可绕过的工具，并且 普通批准卡上显示的默认选择是可配置的。
  • 模型、上下文窗口、调度名称和嵌套代理生成收据报告 实际使用的路线和限制，而不是默默地替换 猜到了身份。
  • 儿童代理在入场前推出一张不可变的路线收据，并且 通过状态、中断、完成、恢复、工作图来保存它， 和分类账预测，因此提供商/模型归因不会漂移（#5305）。
  • 目标运行不再因为内部延续、重复间隙或 未回答问题的守卫。明确的用户限制和最终目标状态 保持权威。
  • 帐户拥有的 /rc 遥控器现在保留独家所有权和 崩溃可恢复的传递日志，直到服务器确认终端， 批准、失败和快照状态。
  • todo_write 是可选的进度表面，而不是必需的模型 仪式。
  • 新回合使用一个小型、稳定的工具箱：read、write、edit、bash、 agent、todo_write 和 tool_search。可选的进度工具保留 可见为熟悉的工作记忆；专门的原生、Web、MCP、插件、 内存、任务和验证工具经过策略过滤且可搜索； 激活的模式保留在有界的每个会话缓存中。各分代理 保留自己的搜索和缓存，包括策略允许的 Web 研究，同时 分叉上下文和父级激活仍然是热启动而不是允许列表。
  • 直接文件和 shell 模式遵循 Pi 特意设计的小契约： 有界全行读取、无散列写入、明确的多重编辑 BOM/CRLF 保存和保守模糊匹配，以及一个前景 bash 命令具有有界的时间顺序输出尾部。模式改变 执行权，不是那些原始的名字。
  • Codewhale 不再向模型重述待办事项列表。模型学习 工具结果列表中包含其自己的 todo_write 调用返回的内容， 这是普通的对话历史记录——与 Pi 的待办事项的工作方式相同。的 瞬态 <codewhale:work_state> 块，用于骑在每个的尾部 父转动循环和子代理步骤请求消失了，稳定的也消失了 系统前缀受到列表更改的干扰。快照仍然显示一次， 有人要求：<codewhale:fork_state> 阻止新分叉 分代理交接、/relay交接指令、以及代理卡。的 完整的待办事项在 UI 中保持可见。结构测试断言真实 出站提供商请求主体不携带该列表。
  • 侦察员和审阅者命名只读调查员角色。两者都准确暴露 一个 shell 入口点 — 规范的小写 bash，受严格限制 只读分类器 - 旧版 Bash 别名在目录中仍被拒绝 并在发货时。以前，不区分大小写的名称匹配允许拼写调用 Bash 通过该剥离执行，将原始 shell 返回为只读角色。

＃＃＃ 固定的

  • 现在，在小写 bash 命令运行时发送更多上下文 命令发送到 /jobs 并返回成功的运行收据而不是 谎报Command exited with code -1；该进程继续运行 并且它的完成仍然通过正常的运行时事件到达。

  • 首次运行使用情况披露现在作为本机 Codewhale 模式而不是 应用程序启动前的 shell 调查问卷。遥测仍然没有武装 直到做出本机选择，并且内存中的“禁用”选择控制 即使无法保存当前会话的首选项。

  • /compact 完成、失败、排队、重复和邮箱结果 持久的成绩单收据而不是短暂的祝酒词。流浪终端 事件不能再让以后的每个压缩都卡在已经运行的状态。

  • 压缩现在遵循 Codex 的简单转录形式：最近的用户上下文 接下来是一个普通的历史检查点。它从不附加摘要， 待办事项列表，或常设系统提示的易失 shell/worker 状态； 重新加载将持久载体迁移回恰好一个历史项目。

  • 自动压缩使用真实上下文窗口的百分比，固定到 路线的可消耗上限。压力来自于当前的父路由 提示，而不是累积计费或子模型使用。

  • 压缩、审查、验证、路由、设置、舰队、MCP、RLM、愿景、 转换和子代理调用继承解析路由的正常输出， 抽样和推理策略。小型内部任务令牌上限不再 截断思维路线或特殊情况的个人提供者。

  • 不完整的提供商响应在普通回合和每个回合中都会真实失败 内部模型消费者。部分文本保持中断，待处理的工具调用确实如此 不执行，并保留计费使用量。

  • 仅传输 (reasoning omitted) 占位符不再输入新的 记录并从恢复的会话中过滤掉。推理 展开/折叠 动作保持附加到确切渲染的单元格，包括替换后， 恢复、过滤和调整大小（#5291）。

  • 逐步预算用尽是一种类型化失败，无法释放待处理的预算 坚持不懈的服务。使用终端后取消仍按顺序收费。

  • 当提供者重用其时，延迟工具现在会保留完整的结果 重试轮上的工具调用 ID，防止成功的插件调用 进入重复执行循环。

  • 网站设置、提供商、诊断、舰队和单运行时索赔 匹配源候选。

  • 打开子代理注册不再隐藏待办事项列表：代理 面板同时显示完整的登记册和持久清单，并且 寄存器标头是一个双向门，可返回到第二个 click 上的任务。

  • ⌥V / Alt+V 详细信息和弦打开所选工作表面行自己的 检查器而不是转录本最近的工具单元，因此选定 待办事项行显示其自己的内容而不是最新的推理。

  • 首次运行的使用情况披露现在提出了一个明确的问题 - “帮助改进 码鲸？” — 明确“是，保持匿名计数”/“不，关闭 跟踪每个已发货区域中的“选择，并说明持续选择退出 命令。同意语义不变：遥测保持未武装状态，直到 选择已做出。

  • 消息中引用的 macOS 屏幕截图被复制到 收到邮件时稳定的附件目录，并且 引用被重写为稳定路径，因此图像仍然存在 代理会读它。仅屏幕截图“临时项目”下的文件 目录被触及；副本是幂等的，失败的副本会保留 原始参考。

  • 主动转弯时的手动 /compact 现在即使在发动机停止时也会排队 有界操作邮箱已饱和。请求推迟 client 端，重试为 邮箱插槽空闲，并且在稳定后无法锁定，因为已经在运行。

  • 交互式 /load、启动 --resume 和 /resume 选择器路径保留 持久化的提供者、端点和模型身份；拣选员简历也 留下持久的成绩单收据。

  • 相对 mcp_config_path 值不再取决于启动目录或 静默加载空服务器池：Codewhale 发出警告并退回到 用户全局 MCP 配置。显式绝对路径仍然具有权威性。

  • 阿里巴巴模型工作室qwen3.8-max和qwen3.8-max-preview仍在直播 他们目前的推理，但不再重播历史reasoning_content 这些路线不接受。历史推理重播现在由 确切的提供商/API/模型合同，因此未知 *-thinking 相似者 失败关闭，同时记录 Qwen、Kimi、DeepSeek、Mistral、Anthropic 和 响应连续性规则保持不变。

  • 兼容性文件/补丁调用保留可选的内容哈希保护，当 来电者提供它们。新的直接 write 和 edit 模式不会公开 哈希或预读仪式。

  • Shell 预览会阻止不完整的 UTF-8 序列而不是发出 替换字符和压缩收据报告令牌增量。

  • 嵌套代理可能会缩小但永远无法扩大其继承的深度预算 （#5317 作者：@ousamabenyounes）。

  • 容器出版物现在并行组装 AMD64 和 ARM64 映像 来自已验证的静态发布二进制文件的本机运行程序，然后 发布并检查一份多架构清单。它不再重建 这两个目标都是通过失去运行程序的单个长时间运行的 QEMU 作业实现的。

已删除

  • 无进度防护、重复读取防护和注入工具错误策略 辅导。高效的轮询、重复检查和模型拥有的恢复 不再被运行时启发法中断。
  • 无需接线的决策卡、按键绑定、悬停、shell 执行、引擎操作和 发布脚本路径已被删除，因此支持的运行时有一个路由 每一个行为。
