Codewhale v0.9.8

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，两个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale 和 codew 命令资源 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.8

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

  • 运行install.bat（复制到%USERPROFILE%\bin）

每个平台还有 裸露、未归档 codewhale-<platform> 和 codew-<platform> 资产。七个 codewhale-tui-<platform> 文件名 附加到 v0.9.5 的是字节相同的兼容性副本，仅用于让 已经安装的 v0.9.4 clients 发现并跨越这个单一二进制文件 过渡；当前的安装程序不会公开第三个运行时。遗留的 npm 包 deepseek-tui 已弃用并且不会重新发布。用于迁移 来自 v0.8.x 旧二进制名称，请参阅 docs/REBRAND.md。

v0.9.8 中有什么

Codewhale v0.9.8 运送剩余的指定饰面。剩余幅面 设置抛光移至 v0.9.9。预制第三方模板具有 已发布的 OpenAI 兼容主机（#5350）。

已修复

  • sudo（和 su/setuid 助手）再次为轮组管理员工作 谁希望 Codewhale 能够升级：Linux 启动强化 不可逆的 PR_SET_NO_NEW_PRIVS 标志 — 由每个子进程继承 — 现在可以使用 CODEWHALE_NO_NEW_PRIVS=0 跳过 (#5413)。旗帜一直亮着 默认情况下；永远不会跳过 no-ptrace 和 no-core-dump 措施。
  • 中止级进程死亡不再毒害终端（#5424）。一个 堆栈溢出、分配失败或双重恐慌会跳过恐慌挂钩 和每一个清理守卫，这就是v0.9.7用户中转出口离开的方式 小鼠将泄漏的 SGR 序列捕获到其外壳中。安 异步信号安全处理程序现在恢复终端模式并附加 ~/.codewhale/crashes/last-fatal-signal.log 的单行原因标记 在重新加注之前，保持诚实的 128+信号等待状态。信号杀死 （OOM 杀手）在设计上仍然是不可拦截的。

已更改

  • 为会话固定提示缓存前缀。工具循环不再 在每个模型步骤上从磁盘重新组合系统提示符，因此代理 写入文件不再会在中途破坏提供者 KV 前缀缓存。的 系统提示符和工具目录仅在声明的标头上重新组合 更改（/model、模式、目标、会话恢复），在记录下重新固定 原因；未声明的更改被报告为漂移，原始引脚是 保持而不是默默地成为新的基线。工作区，AGENTS.md， 技能、记忆和目标漂移现在以一个有界的方式达到模型 <context_update> 下一个用户回合的用户消息 — 历史记录追加， 不是标题重写。 /cache stats 显示引脚原因，最后一次未命中 原因、未声明的漂移计数和上下文更新计数。参见 文档/CACHE.md。

  • 插件兼容性现在针对每个组件。已审核，trusted，已启用 将技能或 MCP 与不支持的命令、代理、挂钩混合在一起的捆绑包 LSP、本机、文件系统根或生命周期突变声明保留 支持的适配器处于活动状态，并将其余适配器报告为非活动状态（full / partial / unsupported）。仍然无法启用所有不受支持的捆绑包。 功能哈希现在是 v2 并绑定此构建的激活策略，因此 旧的 v1 收据和任何后续的适配器启用更改都失败关闭为 需求审查。技能和每个 MCP 传输重新请求自己的能力 在消费边界。
