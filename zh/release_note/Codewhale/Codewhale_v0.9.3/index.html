Codewhale v0.9.3

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，所有三个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale、codew 和 codewhale-tui 此版本中的二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.3

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.9.3 里有什么

这是 Codewhale v0.9.3 候选源。这不是已发布的版本 直到匹配的标签、包、校验和和发布资产存在。 DeepSeek V4 Flash现在是一流的Codewhale路线，面向代理 工具表面已简化为当前的规范操作工具 模型实际需要。此版本还强化了凭证、授权、 删除时的耐用性、压缩和 macOS 文件提供程序边界 过时的运行时和依赖表面。

添加

  • 对 DeepSeek 响应 API 的本机 deepseek-v4-flash 支持，包括 无状态推理-项目重放、语义 SSE 终端事件、结构化 函数调用和输出、apply_patch 和模型感知线格式 选择。确切的当前 Flash ID 使用响应；未来直接 deepseek-vN-* 模型 ID 保守地继承该路线，而自定义 除非配置，否则 DeepSeek 兼容端点会保留聊天完成 否则。
  • 用于明确选择的仅管道 codewhale auth print-api-key 切换 提供商。它共享 Codewhale 的家庭范围凭证权限，拒绝 终端输出，并防止哨兵占位符生效 凭据。
  • 在发动机入口处每转 max_tool_calls 强制执行，加上 具有单独读缝的命名文件写入范围。运行时现在拒绝 执行前超出预算的调用并保持操作员的写入边界 显式（#4415）。
  • 运行时契约、源代码结构和持久性积压棘轮 名称漂移，而不是让大量所有权表面悄然增长 （＃3921，＃4785）。

已更改

  • 模型可见的内置函数现在使用规范的 Bash、File 和 Run 行动图式。 apply_patch 仍可作为一款直接定制产品 DeepSeek Responses 支持的编辑工具。捆绑的停船工作流程， 舰队固定装置、shell 快捷方式和引擎测试使用相同的规范 词汇。
  • Canonical File { action: "write" } 请求现在通过相同的 语义回购法检查为前一个写入路径。批准、完全访问、 并且工作流执行无法通过选择来绕过存储库安全层 规范模式。
  • Codewhale 家庭分辨率在 CLI、TUI、国家和秘密之间共享 商店。 doctor默认离线，区分凭证来源 可用性，并报告一个一致的路径快照。
  • 持久运行时事件写入在同时进程之间进行序列化， 阻塞历史等待会移走异步工作人员，并且提供程序配额耗尽 保持类型化并可通过压缩重试（#4522）。
  • 技能发现缓存了watched-mtime验证后面的合并目录； 大型技能、引擎、子代理、UI 和环境海洋测试块现已存在 拥有测试缝。
  • 推理摘要停留在用户的语言中，完整的水母 剪影围绕转录文本重新定位，缓存的海洋帧包括 他们的调色板身份（#4807）。
  • 授权订单合同现在记录并测试模式、挂钩、 权限规则、安全底线、回购法、批准和沙箱组成 （公关＃4980）。

已修复

  • macOS 沙箱扩展涵盖 CloudStorage/File Provider 工作区，无需 拓宽不相关的路径；感谢@Watcher24 的#4085 报告以及 繁殖。
  • 前台 shell 状态在转向之前分离，因此命令中断 无法继续拥有作曲家（PR #4979）。
  • MCP应用程序级故障和格式错误的错误包络无法关闭 而不是看起来像成功的工具输出。
  • 可选PDF故障真实，PDF分类不再遗漏 支持的输入。
  • 括号内的粘贴内容已从痕迹和凭证诊断中进行了编辑 切勿将占位符哨兵视为可用键。

已删除

  • 旧版可调用别名 exec_shell、run_shell_command、read_file、 write_file、list_dir、grep_files、file_search 以及复制品 工作/RLM 注册。历史记录和政策语义仍然存在 可读，但新模型回合仅接收规范动作面。
  • 捆绑的 PDF 解析器依赖链，将其替换为较小的 由 #4382 跟踪的可选提取边界。
