Codewhale v0.9.11

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，两个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale 和 codew 命令资产 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.11

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

v0.9.11 里有什么

Codewhale v0.9.11收紧长时间运行的代理循环，使工作流程 失败是可见的，而不是看起来成功的，增加了一个实验 具有视觉能力的 DeepSeek 路线，并准备可重现的 Codewhale-versus-Pi 在实际运行之前无需发布结果即可进行评估。完整的 项目级变更记录保留在分类发布亮点下方。

添加

  • 添加了第一方 deepseek-v4-flash-vision-exp 发现和选择 DeepSeek，包括 flash-vision 别名、捆绑的离线元数据、 注册表和选择器条目以及聊天路径上的图像输入功能。 上下文和输出限制继承自 V4 Flash，直到 DeepSeek 发布 独特的价值观；定价仍然未知，而不是猜测。
  • 添加了由提供商控制的 Codewhale-versus-Pi 奇偶校验工具，具有三个 封闭式编码任务、路线和推理努力收据、医生/试运行 模式和有界结果工件。存储库提供了线束，而不是 基准判决；可比较的实际运行仍然是一个接受门。
  • 添加了可移植、无秘密的配置导出/导入以及可审查的计划， 显式无头同意、备份和回滚以及幂等重新导入。
  • 通过现有的面向模型的 lsp 添加了有界多文件诊断 工具而不增加工具目录计数。感谢吴伊莎贝尔 (@wuisabel-gif) PR #5524。
  • 添加了便携式演示、媒体附件和操作摘要方面 命令合同，然后将所有七个实用程序处理程序移至 合同支持的调度路径。感谢保罗·阿博伊姆·平托 (@aboimpinto) PR #5525。

已更改

  • 子代理、舰队工作人员、工作流任务和线程运行时模型转为否 不再继承基于角色的隐藏台阶上限。省略或零 max_steps无界；正的用户/配置值仍然是显式的 上限，并且仍然限制在运行时安全上限。挂钟、提供商、 心跳、取消和准入保障措施不变。
  • /rc 现在镜像一个共享会话而不是转移终端 所有权：本地和网络提示在空闲时仍然可用，批准使用 先决胜出的语义，传输/完整性失败仍然存在 失败关闭。
  • 作曲家周围的终端状态行现在是两个稳定的带： provider · model · thinking level 是下面的持久标识行 每个阶段的作曲家，以及上方的单独活动行 作曲家携带现场阶段、通知和成本/指标。发送一个 提示不再重新定位作曲家上方的路线标识，并且 两行都不会重复它。
  • 嵌入式本地 Web client 现在使用当前的 CWC Ocean 层次结构，并且 可读的控件大小调整，遵循共享的 Enter/Shift+Enter 编辑器 语法，并为每个新线程选择一个提供者加模型而不进行变异 运行时默认值。准确的图像输入能力被诚实地标记；一个 支持视觉的路线并不意味着存在浏览器附件。
  • 运行时现在有一个权威的模型转动循环。占位符 crates/core 引擎树消失了，而活动的 TUI 循环及其提取 工具调用阶段保留现有策略、挂钩、取消和预算 行为。感谢孙振源 (@bistack) 用于 PR #5523。

已修复

  • 聊天完成流现在需要来自 [DONE] 或 非空 finish_reason。仅协议帧不再算作答案 内容或首次令牌时间，以及在之后结束的提供者延续 工具结果没有答案或工具调用持久失败而不是产生 虚假的 Completed 收据。
  • 选定的 v2 舰队现在可驱动一个有界的、确定性的特工名册 终端和运行时界面。车队运营商/成员/显式路线 优先级、已解决的成员身份和确切的 vision 要求 入场现在明显失败，而不是默默地后退，第一次匹配， 或重新路由。
  • task() 调度被拒绝的工作流程不再丢失该失败 在 parallel() 空插槽内或呈现成功的运行。被拒绝 调度现在运行失败，保留为具有精确类型的有界收据 计数，并显示在记录、活动详细信息和工作流程面板视图中。
  • 提供商准备情况、凭证来源解释、聚焦代理滚动、 紧凑型 /status 和 /help 渲染、shell/web 输出边界、MCP 生命周期报告和窄终端入职收到了详细的信息 下面记录了修复。
  • 便携式配置导入/导出现在保留类型表、数组、数字、 布尔值和日期时间而不将它们字符串化，同时拒绝 机器绑定 trust 覆盖层、凭证读取器、自动可执行 钩子/LSP 定义、本地路径权限、机器本地网络代理 路由、cookie、编辑占位符和嵌套或驼峰/点状 凭证密钥。项目和全局捆绑操作现在加载并验证 该文件在两个方向上的实际范围，包括 其文档仍然位于旧应用程序目录下的工作区。
  • codewhale login 现在表示 Codewhale 帐户登录（相同的浏览器 设备流程为 codewhale account login，其中 --no-open 和 --timeout-seconds）；提供商 API 密钥仅通过以下方式配置 codewhale auth set --provider <provider>，以及隐藏的遗产 --api-key/--provider 标志大声重定向而不是默默书写 一把钥匙。
  • 帐户会话更喜欢操作系统凭证管理器，现在回退 自动保存到无头设备上的私有 0600 Codewhale 秘密文件 主机、SSH 盒子和容器； CODEWHALE_CLOUD_ALLOW_FILE_SESSION_STORE 选择加入已被弃用并被忽略。
  • /update 获得了 Ctrl+Shift+U 安装和弦（编录在 docs/KEYBINDINGS.md，在所有 15 个包中进行了本地化）和启动提示 首次启动较新版本时命名先前版本和当前版本 构建，指向 /change。
  • 车队产品模型复制通行证：TUI、文档和语言环境包现在使用 舰队/成员/角色/模型/访问/一致保存，以便用户可以 说“scout”、“DeepSeek V4 Flash”或成员名称，意思相同 事。
  • 推理模型仅返回隐藏推理和干净停止（无 回答，无工具调用）现在会自动重新请求最多两次 转弯失败，而不是死胡同“提供者的反应是 不完整。”重试重用缓存的前缀，因此成本较低；一个 输出长度停止（length/max_tokens）永远不会重试，并且 持续无答案的模型在边界后仍然会诚实地失败。
  • 模型绑定工具结果现在使用凭证形状的编辑策略： 仅包含看起来像秘密的值（已知前缀、JWT、不记名令牌、 PEM 私钥块、长不透明字符串）在 read 或 shell结果到达模型，因此代码如password： 凭证？.password or "password-validator": "^5.3.0" 保持字节精确 用于编辑和回读。准确配置的凭证值仍然始终 已替换，日志/预览/导出保留了广泛的基于密钥的清理器。 (#5546, 由@ronohara 报道）
  • 终端输入关闭不再永远等待楔形 TTY 读取， Windows 启动收据可以自动替换现有记录，并且 完整的 /status 报告现在遵循活动区域设置，无需重写 包含类似大括号的文本的确切自定义提供者身份。
  • 本地化自述文件再次与英文安装和第三方通知相匹配 Surface，包括所有 18 种翻译中的 shell 完成指南。

安全

  • 统一 OAuth 设备代码轮询现在可以验证之前的验证 URL 打开它们，编辑令牌承载类型，尊重服务器减速间隔， 并使凭证保存/注销突变保持序列化。
  • 项目说明、规则目录遍历、秘密形状的配置数据、 URL 指纹和 shell 网络权限现在保留显式边界 以及详细记录中描述的故障关闭行为。

###详细变更记录

下面的注释被完整保留，因此分类的亮点不会 删除行为、迁移、安全、兼容性或验证详细信息。

  • 提供者完成现在是基于证据的。聊天完成流达到 MessageStop 仅在 [DONE] 或非空 finish_reason 之后；原始文件头 没有任何一个都是类型化的失败。消息启动、ping、使用/终端 增量、块停止和消息停止帧不算高效 内容或首次令牌的创建时间。工具结果出来后，终端提供商 没有答案或工具调用的步骤现在会发出持久的失败转弯，并且永远不会 伪造一条空的助手消息。

  • 选定的 v2 舰队是跨终端的单一有效代理名册， 运行时线程、直接工作流、队列执行、医生和 设置/准备；仅当没有舰队时才参考旧配置文件层 选择，无效的选择明显失败，并出现有限的、经过编辑的错误。 成员引用首先解析精确的 id，否则需要唯一的 显示名称、角色、固定模型、离线模型名称或提供者/模型路线； agent action=roster 公开了相同的有限名单。舰队运营商 除非显式启动，否则提供新鲜根和继承成员路由 路线或会员 pin 获胜，已解析的会员将与 请求的别名，并且 requires = ["vision"] 仅在精确的情况下被允许 具有经过验证的离线 image_input 支持的路由 — 绝不通过静默重新路由 或自定义代理推理。车队选择仍然是明确的用户/文件夹 合同独立于遗留项目配置文件加载。

  • 中断（应用程序服务器）： 现在 /prompt、prompt/request 和 prompt/run 执行真正的模型转变，而不是报告他们从未做过的工作的成功 做到了。 Runtime::handle_prompt 没有调用任何模型：它解析了配置，运行了 本地 ModelRegistry 查找，发出三个固定挂钩事件 （ResponseDelta 实际上是字符串 model-selected），并返回 HTTP 200，其中 output 设置为调用者自己的字符串化 JSON 回显 路由元数据 - 包括提示。更糟糕的是，当 thread_id 被 如果它附加了一个真实的用户行，将线程翻转到 Running，并且 然后将这个回声作为辅助消息加上一个 prompt_response检查站。没有任何东西标记该行是合成的，也没有任何东西 曾经将螺纹移出 Running 吗？所有三个端点现在都路由 通过 stdio thread/message 始终使用的相同 RuntimeBridge 使用，所以 output 是模型的流文本，model 是运行时 运行该回合的线程的报告，events 是真实的 流帧。 Runtime::handle_prompt及其合成历史书写 消失了。

  • 中断（应用程序服务器）： 失败的提示现在是键入的失败而不是 比成功塑造的身体。 POST /prompt回归 {"error":{"code":...,"message":...}} 与 400（无效请求）、404 （未找到线程）、503 (runtime_unavailable) 或 500，而不是 HTTP 500携带PromptResponse，错误文本填充到output 模型文本所属的位置。 stdio表面获得JSON-RPC -32005 runtime_unavailable 为“无法到达转动引擎，所以什么也没有” ran” — 与 -32603 不同，并且可重试。里面没有配置 提示会默默地回响而不是运行。

  • 破坏（应用程序服务器）： POST /thread 与 Message 主体运行 转。它之前回复了 status: "accepted" ResponseDelta("queued") 框架，同时不启动工作程序并调用 no 桥接——同一请求的 stdio 路径总是完成实际工作，所以 两种运输对于 accepted 的含义存在分歧。 HTTP 现在回复 status: "completed" 一旦回合达到终止状态， events 中的流帧和 data 中的转弯 ID。 Runtime::handle_thread 根本不再接受 ThreadRequest::Message：它拥有线程 簿记，而不是轮转引擎，并返回错误命名 POST /v1/threads/{id}/turns 而不是罐装承兑。

  • 破坏（应用程序服务器）： AppRequest::SubmitUserInput 现在拒绝 明确地（ok: false，error: "user_input_reply_unsupported"）而不是 返回 resolved: true 并将答案归档到没有地图的地图中 板条箱中任何位置的读者 - 提交的每个答案都是默默的 被丢弃。它不能在这种交通工具上工作：转弯时 流，stdio 循环仅执行 thread/interrupt 和队列 其他一切，因此发送到那里的答复将立即等待 等待它。拒绝命名了接受它的表面， 运行时 API 上的 POST /v1/user-input/{thread_id}/{request_id}。的 client-可见拒绝是空白干净的，并且铸造的 /tool 路径 UserInputRequest 没有变化，仍然是正品。

  • 将协调账本从 tools/subagent/coord.rs 中拆分为 tools/subagent/coord/ledger.rs。该文件包含两个不相关的内容： 面向模型的 agents/* 工具包装器，以及持久的决策/声明/ 那些包装器碰巧写入的争用记录——其消费者的记录 大多数不位于工具层（tui::coordination_detail， tui::work_surface、tui::ui::tests、core::engine::tests 均命名为这些 类型）。在 3.8k 行时，通过滚动过去开始阅读任一行 其他。纯粹的移动，从 coord 重新导出 glob，所以每个 crate::tools::subagent::coord::{…} 路径仍然解析并且没有消费者文件 已编辑；唯一内容变化所需的移动是一个持续不断的过程 从私人到 pub(super) 因为它的呼叫者留在后面。 coord.rs是 现在 2.3k 行和 ledger.rs 1.6k。

  • agent 现在是模型可以看到的唯一子代理工具。 AGENTS.md有 自生命周期以来就表示“面向模型的子代理表面仅是 agent” 工具已被删除，但还可以访问另外六个工具：agents/list， agents/message、agents/followup、agents/interrupt、agents/coordinate、 和 agents/wait 都默认为模型可见，因此它们以 目录和 tool_search 可以加载其中任何一个 - 而 agent 描述告诉模型它们存在。他们现在宣布 model_visible() -> false、相同形状的rlm和exec_shell用途：仍然 已注册，仍可按名称执行，因此可重播持久记录 针对相同的实现，从未做过广告，也从未返回过 tool_search 匹配器。

    六个动作中的五个已经是 agent 动作的复制品。第六个是 不是：agents/coordinate action=claim 是扩大写入范围的“唯一”方法 声明，并且写入执行失败关闭，因此隐藏它会留下一个 拒绝（“首先用……扩展它”）指向模型无法使用的工具 通话时间更长。 agent 获得一项操作，claim 取得写入范围 词汇 action=start 已经使用（write_roots，加上解析接受 exact_files 和 coordination_contracts）。它保留了 agents/coordinate 的 Auto 批准——门控它会导致自主扇入陷入僵局——而且它只能 扩大调用者自己的范围；对等争用仍然失败。无范围索赔 被拒绝而不是报告为已授予，因为 expand_write_claim 当每个列表为空时，返回未更改的声明 Ok。
