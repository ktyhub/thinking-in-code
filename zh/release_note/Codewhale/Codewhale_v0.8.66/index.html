Codewhale v0.8.66

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载匹配的运行时二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 codewhale 调度程序、codew 填充程序和 codewhale-tui 运行时以及安装脚本：

平台 档案 安装脚本

Linux ARM64 codewhale-linux-arm64.tar.gz install.sh
Linux RISC-V codewhale-linux-riscv64.tar.gz install.sh
macOS x64 codewhale-macos-x64.tar.gz install.sh
macOS ARM codewhale-macos-arm64.tar.gz install.sh
Windows x64（安装程序） CodeWhaleSetup.exe NSIS 设置

Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取物codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.8.66 中有什么

添加

  • 添加了 codewhale doctor / codewhale doctor --json 旧状态 将已知 ~/.deepseek 状态路径与它们的状态路径进行比较的诊断 ~/.codewhale 对应项并标记未迁移或双根数据 (#3727)。
  • 添加了 Sakana AI Fugu 作为一流的 OpenAI 兼容提供商 sakana/fugu 别名、FUGU_API_KEY / SAKANA_API_KEY 发现、 提供者选择器连接、模型完成和提供者文档。收获自 #3748 作者：@lerugray。
  • 添加了 WhaleFlow-to-Fleet 启动形状验证：默认的 Fleet 工作流程 合约允许最多 100 个代理和 5 个递归环，要求 在启动之前有界循环/扩展，并保留每个插槽的模型选择。
  • 为已解决的问题添加了只读 /config ask-rules 视图 permissions.toml 路径、文件状态、规则计数和配置 工具/命令/路径询问规则。由@greyfreedom 从 #3569 合并。
  • 添加了提供商级别的 context_window 覆盖，以便与 OpenAI 兼容 网关和自托管提供商可以根据其真实模型进行预算 上下文窗口（#3545）。
  • 添加了本机 codew 垫片以发布存档、Windows 安装程序输入、 本地发布资产准备和校验和验证，以便手动安装 接收与 Cargo 安装构建相同的简短命令。
  • 添加了 OpenModel 作为一流的 Anthropic Messages 提供者，带有配置， CLI、提供商选择器、文档和注册表覆盖范围。从 #3585 中收获 @noaft。
  • 添加了 WeCom Bridge 部署和安全文档，随附 运行时/桥命令和批准超时环境指导。收获 来自@pkeging 的#3640。
  • 添加了用于离线发布控制的令牌/缓存/成本 scorecard 命令， 基线回归检查和每回合成本可见性（#3388）。流媒体-JSON exec 元数据现在还报告保守的 input_analysis 和 visible_final_answer_chars，因此基准线束可以测量转录本 增长和最终答案膨胀而无需猜测（#2956，#2957）。
  • 为v0.8.66添加了释放证据账本并开放了外部ACP 验证发布后向 CodeWhale 提交注册表 codewhale@0.8.65 针对上游注册表检查器的 ACP 身份验证握手 （＃3192）。
  • 为验证者预览通道添加了类型化的 [verifier] 配置表，其中 enabled 和发货的 verdict_policy = "hunt" 映射已记录并 已验证（#2093）。
  • 添加了带有决策卡钥匙的热键Alt+1–Alt+8快速槽切换 消歧，加上一张介绍卡，解释并可以消除 热键栏（#3796，#3788）。
  • 发布/文档卫生：受保护的公共安装/版本片段和 npm codewhaleBinaryVersion防漂移指针，国产check-docs/check-facts 在过时的片段或未映射的提供程序上失败，并停止 sync-changelog 当只有 [Unreleased] 存在时删除版本（#3767、#3768、#3769、 ＃3770，＃3771，＃3772）。

已更改

  • 面向用户的模式选择器、循环、热键栏、/mode 的延迟自动模式 命令和运行时线程模式会覆盖，直到有明显的提示并且 自动审查行为；现有的 auto 模式文本现在折叠回代理 而不是选择空心模式，审批模式副本不再意味着 当前模式是 YOLO（#3730，#3733）。
  • 澄清了舰队设置界面和文档，因此舰队被视为耐用的 子代理配置层，而WhaleFlow是代理创作的 选择和监控队列槽位的编排计划。
  • 精简了默认的宪法提示，同时保持其所需的结构 回归覆盖下的锚点，减少静态提示足迹 缓存敏感轮次 (#2953)。
  • 使批准提示内联并位于底部锚定而不是全屏 接管，因此在工具等待决策时上下文和控件保持可见 （＃3799）。
  • 热栏现在默认隐藏，直到明确设置选择加入为止 (#3807)；的 交互式代理 shell 也默认通过共享进行审批门控 基线（#3756）。
  • 模式权限现在通过单一权限解决审批提示 源而不是每个表面检查（#3795）。

已修复

  • 每当出现用户可见的迁移通知时，就会出现遗留状态重定位 ~/.deepseek/<state> 被移动或复制到 ~/.codewhale/<state> 中，因此 升级后的用户知道他们的数据被保留以及规范状态在哪里 现在生活（#3726）。
  • 恢复了旧版 .deepseek/sessions 升级安装的可见性 一个空的 ~/.codewhale/sessions 目录已经存在，通过复制 主 CodeWhale 会话存储中缺少旧会话条目 不覆盖较新的数据（#3724）。
  • 稳定只读 shell 命令的审批风险分类，例如 codewhale --version、codewhale --help 和 git status --porcelain 等 该模式不再将经过验证的只读 shell 标记为破坏性的 (#3730)。
  • 为 /cache 转弯遥测添加了提供商/模型路线列，以便 DeepSeek 缓存命中回归可以与自动路由更改相关联 (#3738)。
  • 修复了运行时 API 批准处理，因此工作区 trust 不再自动解析 普通工具批准； trust 现在仅参与完全访问重试 决策，而 YOLO/自动批准仍然是批准旁路 (#3736)。
  • 修复了模态表面，以便共享视图堆栈之前绘制不透明的背景 任何覆盖，而计划/请求输入弹出内部保持不透明，并且计划 确认页脚使操作选择在狭窄的终端上可见（#3732）。
  • 为文件写入工具和可写入的 MCP 添加了转环计划模式防护 工具，以便在批准或执行之前执行计划的“不写入”承诺， 不仅仅是沙箱/目录层（#3734）。
  • 为类似发布的 shell 操作保留了持久审查安全底线 YOLO模式，所以cargo publish、npm publish和标签/释放推力 批准而不是默默地自动批准（#3735）。
  • 修复了 Ctrl+O 外部编辑器在 CodeWhale 的终端输入泵处冻结的问题 当 Vim/编辑器拥有终端时，可以继续读取按键，尤其是在 Windows mintty/cygwin shell。感谢@buko 的精确重现（#3657）。
  • 强化了针对瞬态 Cargo 注册表 EOF 的 OHOS 依赖漂移检查 在 CI 失败之前重试依赖关系图探测。
  • 将 /links 提供程序后备更新为当前 CodeWhale 文档 URL 并 添加了百度千帆文档链接。由@noaft 从 #3621 中收获。
  • 针对基准/执行运行的强化 CODEWHALE_TOOL_SURFACE=shell-only： 仅外壳表面隐藏模型可见目录中的本机工具，并且 未知的 CODEWHALE_TOOL_SURFACE 值现在发出警告，而不是默默下降 回到完整的工具表面（#2954）。
  • 子代理扇出和锁定热路径：保留事件通道余量 进度事件（#3783，感谢@cyq1017），让独立的子代理启动 加入单个并行调度批次而不是序列化（#3801），渲染 来自具有边界的只读快照的子代理侧边栏/ListSubAgents 清理 (#3803)，使用非阻塞尽力发送来刷新 ListSubAgents 在仍在等待关键事件（#3802）的同时，移动了子代理状态 持久性磁盘 I/O 关闭管理器写锁定（#3805），并使用 try_lock 用于异步 UI 路径中的 shell 管理器刷新 (#3804)。
  • 出处：运行时延续和 SubAgentHandoff 现在继承地位 YOLO权威，而MemoryRecall、ImportedTranscript和 AssistantGenerated 输入保持受保护（#3817）。
  • 批准诚实：准确标记会话范围的批准，而不是 “始终”，并在工具结果中显示批准决策 (#3766)。 此版本的贡献者积分位于上面的 changelog 条目中 — 感谢所有参与其报告、公关、评论和复制品的人。 有关完整说明，请参阅 CHANGELOG.md；有关旧版本，请参阅 docs/CHANGELOG_ARCHIVE.md。
