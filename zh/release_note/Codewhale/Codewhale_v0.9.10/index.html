Codewhale v0.9.10

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，两个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale 和 codew 命令资产 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.10

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

下面的每个存档都包含 codewhale 下的相同运行时和 codew 命令名称，加上安装脚本：

Unix（Linux / macOS）：

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

窗户：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它安装 codewhale.exe、codew.exe 和 codewhale.bat 下 %LOCALAPPDATA%\Programs\CodeWhale\bin，将该目录添加到 当前用户路径，并创建一个首选的开始菜单快捷方式 安装后的 Windows 终端 (wt.exe)。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 双click codewhale.bat（不是原始的.exe）推出
  • 运行 install.bat 将二进制文件和启动器复制到 %USERPROFILE%\bin
  • 将 %USERPROFILE%\bin 添加到您的路径

便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行 codewhale.bat。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。

每个平台还有裸露、未存档 codewhale-<platform> 和 codew-<platform> 资产。七个 codewhale-tui-<platform> 文件名 附加到 v0.9.5 的是字节相同的兼容性副本，仅用于让 已安装的 v0.9.4 clients 发现并跨越这个单一二进制文件 过渡；当前的安装程序不会公开第三个运行时。遗留的 npm 软件包 deepseek-tui 已弃用并且不会重新发布。用于迁移 来自 v0.8.x 旧二进制名称，请参阅 docs/REBRAND.md。

验证（推荐）

从该版本下载校验和清单并验证：

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

v0.9.10 里有什么

  • 每当窄终端截断完整的斜杠命令或 /model 完成行时，就会在有界的、环绕的悬停弹出窗口中显示完整的斜杠命令或 /model 完成行，从而关闭 #998 中剩余的范围间隙。感谢 @AiurArtanis 和 @formp3 识别受影响的表面。
  • registry_sync 不再将完整的 MCP 注册表目录发送到 对话。它需要一个必需的查询，对本地快照进行评分 主机端，最多返回八个匹配项；完整的目录保留在 磁盘，以及压缩和溢出豁免，让数百个 千字节转储到达模型不变都消失了。
  • 镜像传出 (reasoning omitted) 重播占位符的提供程序 返回作为推理增量不再将回声视为真实的 思考：确切的交通占位符在到达时被删除，所以住 会话停止显示占位符推理块流并保存 成绩单不受它们影响。
  • 交互转弯期间的中流连接丢失不再持续存在 合成 [runtime] 用户消息。重试状态是引擎内部的类型化 描述符；仅思考的丢弃重新发出请求而不声明 部分答复被保留，重试预算在机制中强制执行，并且 恢复恰好产生一个权威的最终答案。

Codewhale v0.9.10 是一个保留、身份和产品清晰度的版本：外壳和 转录本不能再在内存或磁盘上保留无限的工具输出， 中途历史插入不再束缚飞行中的工具行，每个代理 从 /agents list 可以看到运行此会话的内容，PTY 接受 Lane 有失速看门狗和有界 CI 步骤，批准结果为 持久且失败关闭（cyq1017，#5360），并且三个 $HOME 磁盘泄漏 回收。扩展表面现在命名其真实状态并仅起作用 通过审查的安装和 trust 流程以及子代理、shell、任务、 工作流状态由创建它的会话拥有（#5518）。测试 线程获得 8 MiB 堆栈，因此 lib 套件无法再使用 在负载下中止。

已修复

  • 首次运行再次在欢迎屏幕上开始。不再出现钥匙丢失的情况 跳过欢迎并自动打开本地提供商列表：输入步行到 平静的提供者解释，然后 Enter 打开选择器，因此第一个 API 密钥 可以设置。返回丢失密钥恢复仍然会打开选择器 发射。
  • 名为 no timeout 的前台 bash 命令再次受到限制。的 面向模型的 bash 工具在内部留下了省略的 timeout_ms 上限（~24.8 天）而不是 120 秒默认其自己的架构 广告，因此 CLI 在交互式提示上被阻止或挂起 网络呼叫无限期地保持开放状态——一份报告放在一个单一的 未经身份验证的CLI用工具行简单地调用了两个多小时 数秒。现在应用广告中的默认设置，这将武装 现有恢复：进程被终止，模型被告知重新运行 使用 background=true 并使用 action="wait" 进行轮询。明确的 timeout_ms 仍然因真正长时间的前台工作而受到表彰，并且 背景和交互式运行保持自己的生命周期。
  • 扩展 (/plugin) 市场不再是只读列表。 每个推荐和存储的候选者都会命名其真实状态和 主要操作 - 添加、启用、配置或不可用 - 然后输入或 鼠标 click 通过现有审查的/mcp add 运行该操作 推荐, /mcp enable, and /plugin install/trust控制器，这样 不存在第二个 trust 路径。浏览器使用和沙盒运行时停留 老实说，他们的真实设置路由不可用，而不是暗示 安装Codewhale无法执行。
  • 扩展 MCP 选项卡现在呈现一个诚实的清单：标头计数 并且可见行源自相同的配置服务器集，因此 MCP (6) 不能再位于两个渲染行上方。禁用的服务器 保持可见并标记为禁用，而不是默默消失，并且 配置的服务器在实时快照列表中不存在，因为尚未检查 通过 MCP 命令具有自己的显式重新加载功能 控制器。
  • 安装的插件行现在按其真实状态起作用：输入打开一个活动的 捆绑包 (/plugin show)，为 trusted-but-disabled 捆绑包提供启用， 或将 untrusted 捆绑包路由到现有的 trust 评论 - 通过 与斜杠命令相同的确认和持久性控制器。
  • 子代理交接和名册、后台 shell 工作、持久任务、 延迟的延续，工作流程控制现在的范围是 拥有它们的会话。记录带有不可变的根会话所有权， 过时的完成通道有效负载在重复数据删除之前被拒绝， 后台工作消耗并仅向其所属会话报告，并且 遗留的无主作业无法关闭（#5518 故障类由 @hxfhd；该报告并未声称 JavaScript 的确切出处 转载）。
  • 解析的路由包络现在到达每个出站模型调用：全部 有线方言和辅助调用夹在共享传输接缝处 在一根电汇/预订预算下，遵守提供商的输入限制，并且 同一协议上的切换模型不再继承之前的 模型的限制（#5516，#5518）。
  • 首次运行连续性：所选的入职提供商在整个过程中持续存在 重新启动，丢失的首次运行配置不再中断流程，并且 自动工作协议检查点呈现为独立设置 切换而不是将入职轨道退回到完整向导的状态 4/10 进展。
  • 明确措辞的自然语言 /goal 声明现在创建一个 在模型调度之前，提供者中立引擎中的持久目标，同时 普通任务和引用的文字记录不属于目标模式和散文 仅承认不再能够代替目标的制定。
  • /model 现在保持当前 Z.ai 默认值 (GLM-5.3) 在 旧安装已保存明确的 GLM-5.2 路由。已保存的5.2 路线保持准确；选择 5.3 会发送并记住不同的 5.3 ID。
  • 宪法检查点现在以捆绑平衡协议领先； 默认路径不写自定义构成。启动启动面 将只读聊天与文件夹绑定、审批门控的工作区分开来。
  • Tabby 和其他 IME 桥不再观察到陈旧的可见插入符号，而 正在绘制框架差异； Codewhale 在比较期间隐藏光标， 恢复规范作曲家细胞，然后再次显示它 （BrathonBai，#5023）。
  • 预标头 HTTP/2/SSE 传输失败会得到一次有界 HTTP/1.1 重试； 身份验证、提供者语义、响应正文和已固定的 HTTP/1 故障仍然是故障关闭（demian-welt，#4683）。
  • MCP tools/call 图像现在作为有界类型内容而不是 通过模型可见的 JSON 泄漏 base64。直接和并行调用共享 相同的 MIME、大小、验证和单图像边界（PR #5515 by @cacdcaecawae）。
  • Linux npm 安装并更新与 CNB 镜像竞赛的 GitHub 版本 在校验和清单层，然后从第一个经过验证的源下载 而不会让用户等待注定的慢源超时。
  • CODEWHALE_PREFER_BWRAP 现在应用记录的 Linux 沙箱覆盖， Codewhale 时代的名称拥有自己的构建元数据、挂钩会话/工具调用 ID，以及 沙箱子标记。相应的 DEEPSEEK_* 名称仍为 0.9.x 兼容性别名 (#5443)。
  • Windows 默认启动更喜欢 Windows 终端：zip 存档传送 codewhale.bat（CRLF，wt.exe 然后是 exe），install.bat 复制 启动器，并且 NSIS 开始菜单快捷方式打开它而不是原始的 二进制（#1854）。
  • fix(tui): make the header status mark honour its setting — status_indicator 对其四个记录值中的三个没有执行任何操作。标头硬编码了一个 领先的 cw 跨度和要求在努力筹码旁边有第二个标记，然后 根据文字 "cw" 过滤第二个；因为cw，遗产 whale 选择加入，每个未知值都标准化到相同的标记上， 过滤器丢弃了它们，并留下 off 没有任何可关闭的东西。 cw, whale、off 和拼写错误均呈现字节相同的标头。有一个 现在标记并且设置拥有它：cw/whale 绘制印刷标记， dots 绘制活动框架，off 删除它（thejayjetson，#5512）。
  • fix(tui)：在每个回合中历史记录上重新设置活动单元工具绑定的基础 insert — /rename 中转使运行工具行永远旋转 （＃5478）。
  • fix(tui): bound what the shell and transcript retain from tool output — 1.1 MB Bash 调用可保留超过 1 MB 的驻留时间长达一个小时；原始的 传输中的流现在上限为 16 MiB，并释放已交付的输出，以及 保留的工具输出上限为每条记录 64 KiB / 每个转录本 8 MiB （＃5472）。
  • fix(tui): reclaim the three $HOME disk leaks — 孤立会话目录， 无限制的audit.log和搁浅的写入器临时文件。
  • fix(tui): persist approval outcomes before execution (cyq1017) — 批准收据在执行前提交到会话拥有的日志中 收益；无法持久的证据会阻止该工具；恢复重建 关闭并中断批准（#5360）。
  • test(tui): break the LazyLock/env-barrier deadlock in the test harness。
  • ci: give test threads the 8 MiB stack they need — lib 套件中止 在默认 2 MiB 堆栈上加载 SIGABRT。
  • YOLO 入口点遵循锁定批准政策：--yolo、/mode yolo、 /zidong 和 Alt+Y 无法再设置完全访问 + trust + shell 配置或托管需求拥有这种态势。
  • 终端 PTY 工具在没有沙箱后端的情况下无法关闭 文件系统姿势，否则通过启动 $SHELL -i SandboxManager::prepare 与 bash 类似。
  • 技能更新拒绝替换没有 .installed-from 的目录 标记 - 已使用相同的所有权门插件。
  • 仅当每个路径操作数都位于内部时，cp/mv 才是工作空间安全的 工作区 — 自动审核不再自动允许 cp /etc/passwd .。
  • 主 CI 不再为每个分支共享一个并发组：每个 SHA 获得判决而不是取消的待定运行。密封安全 gateway 作业在 15 分钟内运行授权测试（测试破产 重组——没有删除测试）。
  • 配置夹具测试不再将 lock_test_env 作为许可证 读取已填充的 ~/.codewhale/config.toml；他们需要 EnvVarGuard 就像设置一样。安全门和 CNB 工作区测试引脚 a 密封型 CODEWHALE_HOME。 exec_persistent_service系列于 nextest 并位于货物测试二进制文件中，而不是丢弃（#5355）。
  • 短 CLI 不再等待长达三秒的遥测 POST 退出； session_end 被记录，缓冲区在下一个 互动会议。
  • 裸露的 / 现在打开一个特意小的入门套件：/help、/setup、 /model、/settings、/resume 和 /rc。完整的命令清单 仍然可以通过 /help、命令面板和直接前缀进行搜索 打字，无需预先加载整个控制界面（#5442，#5439）。
  • 第一次运行现在只要求做出可用所需的决定，保留 离线路线明确，并留下可选的提供商、工具、策略和 外观工作在渐进式/setup维修指南中。闲置的水族馆 提出一个面向任务的问题，而不是宣传教程或命令 广告牌，并且在工作区关闭后会出现本地化遥测选项 准备好而不妨碍作曲家。
  • 提供者、主动模型和推理工作摆脱了拥挤的标题 变成一个安静的、宽度感知的页脚标识。紧凑的布局保持模型和 在提供者细节之前努力并放弃整个低优先级组而不是 clipping 编辑器或控制提示。
  • 模型选择器不再重新解析 ~/.codewhale/config.toml 一次 提供商在决定谁拥有已保存的密钥时。

添加

  • /workflows 在该工作区的持久层上打开实时运行仪表板 工作流程日志：每个保留的运行，包括状态、阶段、子名册、 进度，主机端取消——仅观察，它从不启动运行。
  • 存储库指令现在从实际包含的结帐中组装： 适用的 AGENTS.md 文件将存储库根目录解析为当前目录 在一个总预算下的顺序，链接的工作树是它自己的根，并且 范围永远不会从路径提及或任何命名的分支中推断出来 main。
  • /goal 是一个 Codex 风格的控制平面：设置一个目标来调度它 到引擎，它拥有目标并自行启动第一个目标转弯 - 目标永远不会作为用户自己的消息、暂停/恢复而回显 是真正的控制行动，狩猎时代的词汇和奖杯卡是 走了。
  • /extensions 和 /plugins 为 Hooks 开设一个本地化库存， 插件、本地市场目录、技能和 MCP。已审核的建议 包括 Playwright、Chrome DevTools、Cua 计算机使用、浏览器使用以及 沙盒运行时无需授予 trust 或在打开时安装任何内容。
  • 转弯检查器现在可以打开完整记录中的最新转弯和页面 用户、推理、工具/子代理和带有页面范围搜索的助理输出， 复制并导出（天-日-月，#1682）。
  • 后台任务有界增量持久化，持久终端 原因、真实的超时/取消收据、重新启动恢复以及 可中断的连续目标延迟（#5497，#5508）。
  • /title 再次独立控制终端窗口标题 /rename，在会话保存/加载中幸存下来，并清理控制、双向和 零宽度字符（PR #5509 by @SparkofSpike）。
  • MCP 快照保留服务器是否通告了功能， 通过有界的遗留回退发现，或者没有观察到（#4170）。
  • codewhale auth status --diagnostic 报告规范路径、隔离 源、后端类和无价值的提供者源存在，无需 打开凭证存储或创建/迁移状态（#2369）。
  • codewhale doctor --probe-search 执行显式无凭据、 针对所选搜索提供商的策略检查传输探测；普通的 doctor 和 JSON 输出保持离线状态 (#5442)。
  • 安全延迟read_media工具可用于支持的只读 角色和历史收据区分本地化工具执行结果 不暴露原始有效负载（#5102）。
