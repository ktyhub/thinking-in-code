Codewhale v0.9.12

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

###推荐——GitHub官方发布

新的 macOS/Linux 安装（此版本中的校验和二进制文件）：

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.9.12" sh
"$HOME/.local/bin/codewhale" --version

对于 Windows，请使用下面匹配的安装程序或存档。对于现有的 直接安装，运行codewhale update；它打印可执行路径并 保留较新的版本。如果安装目录被不同的版本占用， 使用安装指南中的新鲜目录迁移。

二次包装——npm 和 Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

包装器下载匹配的 codewhale 和 codew 命令资源 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.12

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

窗户：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它安装 codewhale.exe、codew.exe 和 codewhale.bat 下 %LOCALAPPDATA%\Programs\CodeWhale\bin，将该目录添加到 当前用户路径，并创建一个首选的开始菜单快捷方式 安装后的 Windows 终端 (wt.exe)。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 双click codewhale.bat（不是原始的.exe）推出
  • 运行 install.bat 将二进制文件和启动器复制到 %USERPROFILE%\bin
  • 将 %USERPROFILE%\bin 添加到您的路径

便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行 codewhale.bat。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。

每个平台还有 裸露、未存档 codewhale-<platform> 和 codew-<platform> 资产。七个 codewhale-tui-<platform> 文件名 附加到 v0.9.5 的是字节相同的兼容性副本，仅用于让 已安装的 v0.9.4 clients 发现并跨越这个单一二进制文件 过渡；当前的安装程序不会公开第三个运行时。遗留的 npm 软件包 deepseek-tui 已弃用并且不会重新发布。用于迁移 来自 v0.8.x 旧二进制名称，请参阅 docs/REBRAND.md。

v0.9.12 中有什么

Codewhale v0.9.12 将计算机的使用放入二进制文件中，开辟了两条新路线 - 阿里巴巴Model Studio通过数据驱动提供者表和Concentrate 作为选择加入的 BYOK 响应网关 — 并添加云调度和 配置门控的每会话控制套接字。外壳是另一半 发布：一张新的启动卡，工作台面停靠在作曲家下方，一个 Tab 的焦点所有者、携带自己状态的工具单元以及 fleet 作为 现场集体的公共用语。完整的项目级别更改 记录保留在分类发布亮点下方。

添加

  • 计算机使用附带二进制文件。 computer-use 插件 — 38 个工具 跨 macOS、Windows、Linux 和 HarmonyOS，可访问性优先观察 具有像素回退、屏幕截图、缩放、屏幕录制和注册功能 通过 ssh 和 hdc 的远程计算机 — 嵌入 Codewhale 并写入 $CODEWHALE_HOME/builtin-plugins 首次运行，因此每个安装通道 携带它。它列为 builtin · not-reviewed 并保持禁用状态，直到 您检查并启用它：运送它并不表示同意它。的 它所取代的 stdlib-Python 计算机使用服务器已经消失。
  • 阿里巴巴模型工作室加入数据驱动的提供商表作为 openai-compatible描述符：国际兼容模式端点， DASHSCOPE_API_KEY 凭证，实时 /v1/models 发现。启文3.8 Flash 和 Qwen 3.8 Max 通过目录权威到达 - 从来没有 硬编码 ID。
  • 集中：一流的选择加入 BYOK Responses 网关和实时模型 发现和类型化 SSE 流（#5725）。
  • 云调度：远程运行器将编码代理任务卸载到隔离的 具有机器令牌身份验证和结构化作业跟踪的云沙箱 （＃5701，＃5712）。
  • 每会话控制套接字：配置门控 [control_socket] 表绑定 <sessions-dir>/<session-id>/control.sock 每次跑步会话，暴露 消息、中断、重新启动和状态 JSON-RPC 动词（#5533、#5831）。

已更改

  • 默认情况下启用匿名使用计数。 0.9.11 版本要求 第一； 0.9.12 统计相同的聚合版本/平台、会话、功能 和错误总数，除非您将其关闭，并在第一次启动时这么说一次 （政策通知版本5，模式3，notice_version取代 consent_version）。每一个记录的选择退出都会保持关闭状态：持久的 telemetry = false，在旧的选择加入通知下记录的 decline， 不可读的隐私状态，以及 CODEWHALE_TELEMETRY=0 / --telemetry false终止开关。仅显示披露记录 显示，绝不接受。 codewhale config set telemetry false转弯 它关闭并擦除排队计数； codewhale config set telemetry true 故意重新启用它。没有收集到任何新内容：没有对话， 代码、提示、文件、名称、模型内容、凭据或 IP。

  • 启动屏幕是我们自己的卡片：一条细顶线 ⑂ branch path;带有鲸鱼标记的居中边框卡片， Codewhale+版本，只有当它是真的时才会有一条公告线（ 无模型警告或 MCP 新闻），以及菜单“新建工作树/恢复” session / Changelog / 退出并右对齐真实和弦。输入 运行突出显示的条目，向上/向下移动它，然后输入直接进入 作曲家。该卡在第一次击键或命令时消失 （≤240 ms，减少运动下的瞬时）（#5826、#5801、#5815、#5286）。

  • 默认情况下，工作表面位于作曲家下方，保留历史记录 可读并且让舞台不受阻碍（#5809）。

  • 技能命令形状：FEAT-022命令形状和保留宿主 验证（#5825，#5829）。

  • 卡溶解后，工作屏幕显示 ⑂ branch path 右边的 ⋮ MCP n/m，文字记录以 ◆ session_start 收据（命名配置的会话启动挂钩）， 作曲家的底部规则为 model (effort) · permission — 该路线的一次发射阅读。出现姿势栏和指标线 仅当会话存在时。

  • 词汇：fleet 是公共术语，Pod 已从副本中退休 — 花名册、设置、详细信息、工作运行时和托管 API 消息现在显示 舰队（/fleet 规范，/pod 别名）。工作流程线接受 规范角色拼写（一般/探索/规划者/审阅者/实施/ test/advisor），其中预重命名的保留为加载时别名，以及 序列化规范名称。

  • 操作模式选择器提示被缩短以适合 80 列。

  • 页脚始终显示许可姿势；当只有一个芯片时 适合，权限芯片的优先级高于模式字（#5796）。

  • Local Ollama：只有当本地目录可以时，标题才命名模型 服务它，并说“unknown”，直到它知道为止。启动标记、网络和 应用程序图标带有新的侧视提示眼鲸鱼（#5795）。

  • 一个焦点所有者：Tab 和 Shift+Tab 可以工作，无论焦点中的内容如何 作曲家； Alt 快捷键在草稿中期仍然存在； Ctrl+Tab 不再循环 意外模式（#5798）。

  • 工具单元具有自己的状态：正在运行、失败或警告的工具 在转录本本身中如此读取，每个条目都有轨道点和 系列颜色的字形（#5799）。

  • Web：带有任务搜索的文档中心，共享空/正在加载/错误状态， 离线到后台的横幅，/changelog 在每个区域，并且是真实的 具有正确元数据的 404 错误 (#5743)。

  • Web：应用程序的颜色来自 TUI 鲸鱼生成的一个文件 调色板；手动重新输入颜色会导致 Web CI 失败 (#5797)。

  • 网络：isZh 上的单向天花板在 i18n 脊柱之外分支 — 计数可能只会减少（#5805）。

  • 内部代理移交文档已从公共树中删除，并且 .playwright-mcp/ 现在被忽略（#5800）。

  • 第一次运行立即绘制作曲家：欢迎/语言/提供者/ trust 门不再先于第一次击键。钥匙丢失和 工作区-trust 返回用户的恢复停留；语言和提供者 留在/setup。

  • 规范的鲸鱼瓷砖标记从网络传播到精确的光栅 可以承载它的表面（#5738）。

  • 死代码扫描：删除经过验证的未引用的帮助程序（未使用的构建器， 包装器和剩余标识符）并删除过时的 #[allow(dead_code)] 该项目被生产调用或测试执行。无运行时行为 改变（#5791，#5587）。

  • 远程控制恢复为每次新的预调度尝试提供新的租约 一代，同时在其类型开始时保留该一代（#5605）。

  • 公共名册语言是 Pod。 /pod为客户面；舰队残骸 内部线路、存储和迁移名称 (#5776)。

  • 压缩替换历史记录保留有限的最后用户回合（助手+ 工具结果）而不是将它们放在摘要后面。 /context 名称 压实路径和/anchor生存。失败的紧凑仍然没有 替换实时历史记录（#4394）。

  • 提供商目录：兼容主机（Baseten、Groq、Cerebras、SenseNova、 命令代码）不再编译冻结的模型名册。描述符命名 线路、URL 和环境；现场 GET /v1/models 和 Codewhale 拥有的目录 层是产品列表。命令代码是目录/描述符行，而不是 ProviderKind。目录存在不是可用性、权利或 提供者接受声明（#5783）。

  • 提供商选择不再探测或采用外部 CLI 凭据 普通拾取器使用。重用需要明确的“使用外部 CLI 凭据” 选择、精确路径确认和 Codewhale 拥有的撤销 (#5772)。

  • TUI：启动时不再显示近似的 ASCII 或块字形鲸鱼，如 产品标记。它在精确光栅时保留直接潮汐线提示 表面仍然对规范资产负责。

  • TUI：活动会话作曲家绘制相同的三单元 [↑] 发送 目标为启动，cli通过现有的回车提交来确认它 调度员（#5771）。紧凑/安静的作曲家仍然省略了控制。

  • TUI/CLI：Pod 是公共名册表面。面向用户的舰队措辞 移动到 Pod；耐用的收据密钥保持兼容（#5776）。

添加

  • openai-codex 路线的本机 ChatGPT 登录：codewhale auth chatgpt 打开浏览器 PKCE 流程并将可刷新令牌存储在 Codewhale 拥有的凭证 — 无需安装 Codex CLI。 /auth chatgpt-revoke 将它们从事件循环中清除（#5784，#5778）。

  • MCP 服务器和插件可以从会话中自助连接： 具有旋转安全令牌处理的统一身份验证流程、语音授权 当存储的凭据停止工作时 URL 和目录刷新 (#5747)。

  • /operate 读取与已登陆的 CWC OperateRecord 合约相匹配：获取 缺席记录返回真实的未找到视图，而不是捏造的 操作，并且空证据路径被拒绝而不是解决 工作区目录（#5703）。

  • TUI：预定的自动化项目进入顶部条带 （⏱ N scheduled · M running、紧凑型 ⏱ N·M）带类型 HistoryCell::Automation 在本次运行观察稳定时收到。 /automation 承认失败。合并后的页脚不包含 工作事实（#5748）。

  • 应用程序服务器可以侦听unix域套接字并通告 daemon/attach 握手，因此本地 client 可以连接到已经运行的 引擎而不是产生自己的引擎。套接字是用以下命令创建的 仅限所有者的权限和过时的套接字将在启动时回收。非unix 主机返回类型化的不支持平台拒绝； Windows 命名管道 端点已命名但尚未实现 (#5749)。

  • 引擎的内部Op/Event类型和有线协议的Op/ EventMsg 现在为每个变体携带一个编译强制双胞胎：添加一个 没有对应协议的引擎变体会导致构建失败，而不是 默默地漂流。内部耐用性工作——没有用户可见的表面 还没有改变（#5751）。

  • 机器令牌：设置 CODEWHALE_API_KEY 后，CLI 验证为 没有本地会话文件和浏览器的 Codewhale 帐户 — CI 身份验证路径，具有键入的令牌形状和密文（#5721）。

  • Compaction 发布了会话树的结构化生存合约 日记帐分录类型 (crates/tui/src/compaction/SURVIVAL_CONTRACT.md) 和 当最后一个用户回合、工具结果、/anchor 文本或 检查站收据将消失（#4394，#5782）。

  • 内部：codewhale-config 获得 RouteAuthoritySnapshot，一个不可变的 拥有已编译的提供者目录和路线的权威机构 解析器从它投影出来，所以有一个选择器、一个准备视图和一个执行 如果没有 类型级信号。决议仍然通过唯一的解析者进行；的 返回的收据区分确切的目录行、自定义端点路由 其提供者事实被故意不重用，并且允许 没有目录行的直通路线。所有国家都是无秘密的。没有来电 站点已更改，但用户可见的行为尚未更改 (#5766)。

  • 计算机会话记录现在仅计算提供者实际接受的时间 会话处于活动状态，以每秒为粒度。空闲、排队、停止和 拆卸时间被排除在外，并且分配与分配不匹配的会话 标准配置文件被拒绝而不是大约记录。覆盖范围 密封装置；没有实时提供商调用，也没有部署（#5781）。

  • 网站：公共网站改用Tideline深海设计语言 （默认为深色，带有选择加入的浅色文档表，调色板接地 TUI 的 WHALE_* 代币中）以及网站图标上的新鲸鱼品牌标志， 应用程序图标、网络清单、导航文字标记和社交卡 (#5573)。

  • 添加 codewhale dispatch / /dispatch 以便本地会话可以提出 针对显式 github、cnb 或 gitee 远程的 Codewhale 云代理。 需要确认；缺少凭据无法关闭；云工作分享 现有/jobs表面为kind=cloud。参见 DAYTONA_CLOUD_DISPATCH.md。

  • /login 接下来报告 Codewhale 帐户会话和提供商密钥 步骤。内部云代理凭证不是用户表面：有 没有 auth set-slot/auth clear-slot 命令，没有提示，也没有完成 进入它——用 codewhale login 登录是唯一的门。

  • 从ratatui翻译规范中添加Tideline组件系列 （#5698 的屏幕，乘坐#5699 工作条布局）：英雄启动 具有快速操作和选项条、通知收件箱、合并的表面 页脚带、pod 分类帐、收据 流、带有运动切换的主题列表、实时预览、设置栏、 和左轨 — 每个独立渲染模块由 28 个新固定 字节精确的黄金缓冲区。框架布线遵循潮汐线验收 门； NO_COLOR 现在支持调色板深度检测。

  • 路由合同阶段 1：RouteResolver 是运行时路径 resolve_runtime_options； codewhale providers export --json 发货 拥有的描述符目录； CLI --provider 接受任何目录路线 ID （关闭的 ProviderArg 枚举被删除）。目录层是 捆绑 → models.dev → 提供者 /v1/models → config.toml → 用户， 策略 DENY 最后且从未被覆盖。

  • 添加了针对记录的小米 MiMo 2.5 Pro 和 2.5 的提供商本机网络搜索 聊天路由，同时保持相邻模型和自定义网关故障关闭。

  • 添加结构化提供商原生网络搜索，以精确搜索 Z.AI global 和zhipu 中国通用API路线，使用每个站点的记录搜索引擎值。 现有open.bigmodel.cn配置现共享Z.AI官方型号 命名空间和凭证范围；未知的型号 ID 仍然会通过。

  • 在 ModelStudio 上添加提供商原生 Web 搜索以查找记录的 Qwen 模型 Token Plan 的响应管理，无需启用 Coding Plan 或 Anthropic 路线。

  • 添加了 /copy 将最新完成的助理响应放在 clipboard无复制工具、系统消息、隐藏推理或 活动部分输出（#5668）。
