Codewhale v0.9.1

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，所有三个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale、codew 和 codewhale-tui 此版本中的二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.1

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 codewhale 调度程序、codew 填充程序和 codewhale-tui 运行时以及安装脚本：

Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

验证（推荐）

从该版本下载校验和清单并验证：

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

v0.9.1 里有什么

Dogfood 后续行动 (2026-07-24)

添加

  • /compact [focus]：手动压实命令现在接受 注入到摘要提示中的可选焦点参数，以及 压缩摘要本身变成了结构化的九部分 继任者简报（主要意图、关键概念、文件和代码， 错误和修复、问题解决、用户消息、待处理任务、 当前工作，下一步），带有早期的压缩摘要 转发并明确禁止工具使用——替换自由形式 “N个字下”指令。 Codewhale 的引脚/工作组和 V4 前缀缓存对齐机制未更改。
  • 保存的工作流程变成斜线命令：*.workflow.js 文件下 <workspace>/.codewhale/workflows/ 和 ~/.codewhale/workflows/ 是 发现为接受自定义参数的 /name 命令（转发 到运行的 args），通过 workflow 工具启动 背景，并报告他们的运行 ID。手写 .md 命令 相同的名字总是获胜。工作流程工具的 source_path 现在也 接受用户全局 ~/.codewhale/workflows/ 商店，并且每个 稳定的运行留下了一份持久的综合报告 .codewhale/reports/<run_id>.md（状态、目标、大门、进度、 结果、验证）。

已修复

  • 消除两个 Kimi K3 模型选择器行的歧义，它们读作 无法解释的重复：裸露的 k3 现在被标记为“基米代码计划路线” 其默认的 262K 窗口被注释为计划层楼层（可提升 通过提供商 context_window 设置（针对包含 1M 的计划）， kimi-k3的1M窗口被标记为“Moonshot直达航线”。 对于同一底层模型，两者仍然是不同的、有效的路线。
  • 立即关闭面向模型的 agent 工具角色架构：type 属性 发布规范的 JSON 模式枚举 ["worker", "scout", "planner", “审阅者”、“构建者”、“验证者”、“自定义”]而不是描述 散文中公认的价值观。不再向旧别名公布 模型；它们仅在重放/反序列化边界处仍然被接受。 提供者模式清理程序（聊天完成、严格模式、人择 消息/OpenAI 响应、Moonshot/Kimi）通过测试固定到 保留封闭枚举。

已更改

  • 重新设计周围闲置的海洋：水现在正好容纳一个松散的海洋 鱼群、水母、气泡和罕见的鲸鱼浮雕 — 海藻和生物灰尘被去除。鱼儿在环绕的路径上游动， 始终面向他们移动的方向（方向只能在移动时改变） 学校在屏幕外）；铅鱼有眼睛（><o>）。 水母变成了一个脉动的钟，带有滞后摇摆的触手。全部 环境标记现在通过背景发光→墨水颜色 lerp：旅行 sin²波穿过学校，水母在地板上的脉冲， 气泡上偶尔会出现升余弦闪烁，故意 不匹配的周期，因此没有同步的选通。
  • 整合人类消息和 OpenAI 响应流开放 通过已使用的共享 client/stream_entry.rs 传输接缝 通过聊天完成：一个有界响应标头等待，共享 双/HTTP-1.1 client 策略选择，最多一个 HTTP/1.1 回退 在分类的 HTTP/2 标头停顿上重试（切勿在流主体之后重试） 已经开始），以及共享空闲超时诊断格式。两者都 适配器获得有界开放等待和 CODEWHALE_FORCE_HTTP1 H1 钉扎；线路特定的标头、身份验证、端点和 流解码位于适配器边缘，而响应提供者 保留速率限制/瞬时上游错误的重试循环。
  • 将内部委派工作人员角色类型从 SubAgentType 重命名为 FleetRole 具有规范变体（Worker、Scout、Planner、 Reviewer、Builder、Verifier、Custom）配套公共车队 词汇一对一。连线行为不变：序列化发出 仅规范舰队值，以及持久化的 agent_type 字段加上 记录的遗留拼写（general、explore、plan、review、 implementer，…）继续在反序列化/解析边界加载； 未知的角色标记仍然无法用规范词汇关闭 错误。 Codewhale v0.9.1 候选源包括运行时 API 上的一流本地网络 client， 一流的 OpenCode Go 和 TelecomJS TokenHub 提供商并恢复了 xAI 设备登录， 日历正确的每小时自动化，可构建的 OpenHarmony 工作流程-js 目标，以及自动路由、远程终端 clipboard 传输的强化， 重新启动恢复，以及连贯的 TUI、工作、证据和公开发布 表面。

添加

  • 添加 codewhale web [--port 7878]，一流的仅环回浏览器 client 优于规范运行时 API。无依赖的嵌入式 shell 支持线程生命周期、快照-然后-SSE 转录、转动启动/转向/ 中断、批准和用户问题，包括待处理请求恢复 跨选项卡重新加载，同时保留不受支持的托管， 文件、PTY、模型选择和舰队控制不存在。浏览器身份验证使用 短暂的一次性环回功能交换为不透明的、有界的、 process-local HttpOnly, SameSite=具有同源的严格会话 cookie 突变守卫；运行时令牌永远不会输入 URL、HTML、浏览器存储、日志、 或浏览器启动参数（#4423）。
  • 添加 OpenCode Go 作为一流的、订阅支持的聊天完成 提供 [providers.opencode_go]、OPENCODE_GO_API_KEY 和八个 目前记录在其 /v1/chat/completions 端点上的模型。型号 仅通过 OpenCode Go 的 Anthropic /messages 端点提供服务仍处于排除状态 这条狭窄的路线，直到 Codewhale 支持每个型号的线选择 （#1481 by @seanthefuturegorilla；实现从 PR #773 中收获 @zhangweiiii 和 @sternelee 的 PR #1050）。
  • 添加 TelecomJS TokenHub 作为一流的聊天完成提供商 [providers.telecomjs]、TELECOMJS_API_KEY 和 key-scoped live /v1/models刷新。 Models.dev 和特定于提供商的目录保留在 单独的源分区，因此任一刷新顺序都会保留两者；刷新 不要删除其他源的行，匹配不相关的模型 ID 提供商不会伪造元数据，聊天请求会忽略不支持的内容 推理场（@baendlorel 的 PR #4370；与共同作者共同收获）。
  • 准备本机 Windows ARM64 codewhale、codew 和 codewhale-tui 二进制文件、npm 选择、更新程序支持和标准/便携式版本 档案。在 GitHub 的本机 Windows 11 ARM 运行程序上构建并使用它们， 并将 Linux ARM64 版本移动到本机 Ubuntu ARM 运行程序 删除较慢的多架构交叉链接设置（#4267 by @w1w218）。
  • load_skill 工具现在支持列表：省略 name 或将 "list" 传递给 查看所有可用技能而不加载一项（#4651）。
  • 添加一个统一的 /skills 管理器，具有一个优先级感知根目录， 有界重复/影子/冲突审核、包来源以及 验证安装、更新、删除和 trust 突变（PR #4679 @SamhandsomeLee）。
  • 添加安全的代理详细信息视图和有界、结构化的 current_activity 单个工作投影，源自工作事件而不是渲染器 字符串推理。行保持紧凑，确切的证据是选择加入的，并且原始子项 输出永远不会进入父转录本（#2889 和 #4636；设计方向 作者：@aboimpinto，从 #2694 保留）。
  • 使准确的结果和委托的协调持久：非内联工具输出 成为有界收据背后不可变的会话拥有的证据；文件 突变添加了可配置的仅成功差异；和决定并写 争用通过类型化的中性扇入记录重新启动（#4619、#4636、 #4647).
  • 运行时 API 提供程序注册表和原子提供程序切换端点 (GET /v1/providers、GET /v1/providers/{id}/models、 POST /v1/providers/{id}/switch），因此 Web GUI 呈现动态 没有 setConfig+reload clobber 的提供程序/模型选择器 (#4658)。
  • 舰队设置向导的模型步骤中的类型过滤器 (/)：子字符串 匹配提供商 ID、显示标签和模型 ID 保留 OpenRouter 规模的目录可导航 (#4639)。
  • [auto.router] 配置：汽车的明确提供者/模型/思考 模式分类器路线；取消设置保留 DeepSeek flash 默认值，并且 缺少凭证会退回到本地启发式。

已更改

  • 保持顶部活动栏字面意思和可操作性：活动的待办事项首先出现， 其次是子代理，而通用操作和协调则保留在 细节表面。仅完成的栏会自动隐藏，并且顶部/侧面布局可以 通过拖动分隔线来调整大小并保留所选的大小（#4700， #4702).
  • 将每个主题的语义颜色用于作曲家模式和权限栏，以及 显示更大的内联推理预览，具有更清晰的本地/完整扩展 可供性（#4699，#4701）。
  • 围绕稳定操作工具（File、Git、 Run、延迟型 Web 以及持久任务和自动化系列），具有遗留功能 隐藏拼写以供重播。新会话不再保留工作表面 在真正的工作存在之前（PR #4675）。
  • 为终端 shell 提供一种经过深思熟虑的视觉语言：很酷的计划 → 行动 → 操作和热询问 → 自动审查 → 标题之间的完全访问斜坡匹配 并分割作曲家边缘；转录节律组相关活动；一个 精鲸使空态平静；和单细胞实时运动 真实的标签区分推理、阅读、工具使用和验证 不暴露私人推理文本。减少动作和动画关闭 设置冻结它，而 ASCII 安全终端保留信号（#4676， #4677).
  • 统一外壳工具：模型现在看到一个带有 action 的 Bash 工具 参数（运行/等待/交互/取消）。旧版 exec_shell* 名称仍为 用于转录重放的隐藏兼容别名和工具搜索目录 默认情况下保持 Bash 处于活动状态 (#4625)。
  • 工具输出内联预览从 6 行增加到 12 行（4 头 + 4 尾） 在折叠指示器之前；完整寻呼机（v 键）不变（#4603）。
  • 模式更改 (/mode agent|plan|operate) 现在持续到 settings.toml 并跨会话恢复（#4628）。
  • 计费来源：每个传出的 API 请求都带有一个 带有 client 版本和提供程序的 x-codewhale-provenance 标头 (#4324)。
  • /model 选择器的键入搜索现在对结果进行排名：提供商名称 首先匹配（向下钻取），然后是精确 id，然后是 id 前缀，然后是 活动提供者的行（#4639）。
  • 系统提示文本合并为单个prompts/text.rs 模块（字节精确常量替换 17 层文件）； 组合顺序、结构优先的绑定以及语言环境/个性 变体不变。
  • 询问、自动审核、完全访问、永不通过一项权限解决 合同：resolve_tool_permission 发动机和 resolve_approval_request_disposition 在 UI 中共享一个真值表 会话授予/拒绝、不可绕过的策略保留和模式提示 （＃4412）。
  • 将多结构工具系列折叠为单一操作调度工具 （AutomationTool、TasksTool、GithubTool、RlmTool）同时保持 旧版工具名称作为隐藏的兼容性别名用于转录回放。
  • 操作模式子项默认为叶深度 (max_depth=0)，除非 调用者明确授予更深的预算（#4598）。

  • 默认规范 Bash 运行时没有明确的 cwd 到活动状态 ToolContext.workspace，包括一个独立的子代理工作树，而不是 进入共享 shell 管理器的父工作区。回归 测试通过标记文件检测选定的工作空间，使其保留 在 PowerShell 路径拼写中有意义（#4674，PR #4673 by @fleitz）。
  • 使用本机生成 aarch64-unknown-linux-ohos 的 QuickJS 绑定 SDK的libclang和sysroot，通过final携带OHOS目标和sysroot 链接，并将不受支持的持久 PTY 依赖项排除在目标之外 同时保留非 PTY exec_shell 支持（#4470 by @shenjackyuanjie； 原始的bindgen方法由@shenyonqing在#4384中实现）。
