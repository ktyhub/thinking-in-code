Codewhale v0.9.13

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

###推荐——GitHub官方发布

新的 macOS/Linux 安装（此版本中的校验和二进制文件）：

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.9.13" sh
"$HOME/.local/bin/codewhale" --version

对于 Windows，请使用下面匹配的安装程序或存档。对于现有的 直接安装，运行codewhale update；它打印可执行路径并 保留较新的版本。如果安装目录被不同的版本占用， 使用安装指南中的全新目录迁移。

二次包装——npm 和 Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

包装器下载匹配的 codewhale 和 codew 命令资源 从本版本开始。两者都包含相同的编译运行时。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.13

该图像公开与 codewhale 和 codew 相同的运行时。的 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli --locked

Cargo 包安装 codewhale。 Cargo 无法创建第二个命令 来自一个二进制目标的别名；想要更短拼写的用户可以添加 codew 到已安装的可执行文件的符号链接。 npm、Homebrew、存档、 shell-installer 和容器通道直接安装这两个命令名称。

v0.9.13 中有什么

Codewhale v0.9.13 解决了 0.9.12 中的完整性问题： 多行粘贴又是一次粘贴，截断的工具参数无法再执行，严格 ACP clients 再次连接，并发实例停止销毁每个实例 其他人的排队文本，并且计算机使用捆绑包包含插件 0.3.1 使用不再窃取焦点的可访问性优先的指针。 DeepSeek V4.1闪存 (deepseek-flash)是默认的DeepSeek模型，具有推理能力的路由 即使模型 id 没有版本，也不要推理答案 号，并且/mcp reload在服务器时不再冻结接口 重新连接。 Codewhale 宠物与 /pet 一起到来：一个全屏栖息地， 显示引擎正在做什么，并在完成后显示答案。

添加

  • /pet 将终端移交给 Codewhale 宠物。 /pet on（或裸 /pet）为栖息地提供整个内容视口现在和每个 接受转弯，转弯完成时显示实际答案或错误， 《Escape》返回作曲家，没有取消任何内容。 /pet off 关闭视图并停止自动输入，同时耐用的伴侣保持 宠物还活着； /pet appearance|window|source|sound|export|status 地址 共同的伴侣。宠物不再生活在工作栏中：手表 面板和 /workbar watch … 消失了（#6109，#6110）。
  • Codewhale Computer Use 0.3.1 作为其自己的经过公证的 Mac 应用程序提供。下载 来自 codewhale.net/computer-use 的磁盘映像 或 v0.3.1 版本 （Codewhale-Computer-Use-0.3.1-macos-universal.dmg，拖入 应用； ZIP 保留用于应用内更新程序）。捆绑的插件和 第一方市场固定相同的 0.3.1 源，因此应用程序、 computer-use 插件和 /mcp 看到一种实现。

已修复

  • 网站的“计算机使用”下载页面可解析其状态，而无需 GitHub API（仅在绑定时使用GITHUB_TOKEN），并且每个页面都重新生成 再次在 Worker 上：Open Graph 图像路径在导入时读取品牌 SVG 时间，这是 Workers 运行时无法做到的，因此 codewhale.net 一直在提供服务 它的构建时快照。

  • Operate可以直接运行结构化工作流程，具有命名阶段、模型 舰队的分配、先决条件结果和共享预算。独立 步骤齐头并进；依赖工作等待其所需的结果和大门。 分离运行将其结果返回给拥有对话，并且无头 会话在阶段之间保持活动状态，直到最终回传被消耗。

  • 计算机使用 0.3.1：鼠标操作不再窃取焦点或收回焦点 当用户在操作中切换应用程序时前台；后台打字， 滚动和选择使用语义输入，屏幕截图的范围仅限于 目标应用程序。捆绑插件和第一方市场 pin 携带相同的 0.3.1 源。已注册的 macOS 助手负责 通过暂停和停止控件输入；无法注册的帮手 产生错误而不是默默地绕过这些控制。

  • 舰队编辑器使用标准模型选择器来管理子代理模型 和思考作业。 Enter 编辑所选行而不更改 运行会话的模型。未配置的提供程序被拒绝，保存失败 保留之前的分配，并且必须保留更改或删除的团队文件 在选择覆盖它之前重新打开。

  • 提供商目录包括 Baseten 和其他兼容提供商 模板作为可选择的行，打开现有的预填充设置表单。 基于时钟定价的 DeepSeek 路线显示当前高峰或非高峰 除了会话成本之外，还有翻译标签。

  • 扩展、团队、工作流程和自动化支持鼠标滚轮滚动。 插件和 MCP 行具有键盘启用/禁用控件和两步 移除； MCP OAuth 可以在范围拒绝后以更窄的范围重试。

  • 健康的子代理在普通父回复后继续。无头奔跑 在运行期限内保持现有引擎处于活动状态以获取子结果。 当结果队列已满或 完成后开始后续回合。

  • 子代理跟进支持多个目标和所有停放的儿童，保持 旧 ID 连接到当前的延续，并保存延续 开始工作前的身份。重复跟进不会分叉重复项。

  • 子代理验证声明的输出文件并区分真实的编辑声明 来自文件引用和不相关的工作区更改。不相交的文件声明 可以一起跑步；重叠的作者收到实际的冲突和补救措施。 显式只读 shell 分析需要强制执行本机沙箱和 当保护不可用时拒绝执行。

  • 委派深度通过保存的配置文件、嵌套工作人员和 延续。每次调用令牌、步骤和时间限制缩小继承限制； 延续保留了祖先的用法和截止日期。工人们预留空间 在这些限制内生成一份禁用工具的部分报告，然后运行声明的- 输出检查。缺少使用或报告室不可用会产生 显式后备；部分工作永远不会标记为完成。

  • 代理名册和详细信息页面具有有限的输出、可见的延续和 后代关系，以及完整诊断证据的可用句柄。 完成收据包括测量的工人和后代代币使用情况， 对每个延续计数一次，并将未报告的使用情况与零区分开来。

  • 本地化和本机帮助程序构建解决了主动结账的问题 构建脚本运行，因此共享 Cargo 目标在工作树之后继续工作 移动或被移除。

  • 选择格式错误、无法读取或重复的已保存代理配置文件 现在在任何子请求之前失败，包括当其名称与 内置角色；父级的默认路由永远不会被默默地替换。 agent(action: "roster") 列出受影响的配置文件身份和路径、舰队 运行创建执行相同的检查，并且 docs/SUBAGENTS.md 记录了 [permissions] 的有效个人资料格式（#6117，谢谢 @加布里埃尔-德格雷特）。

  • 交互式启动不再将工作人员调度延迟误认为是 终端无响应。终端所有权检查和关闭清理工作仍然存在 强制执行（#5929）。

  • 保存的运行时存储丢失的中断对话恢复到 新的范围，无需恢复旧的任务或批准。过时的会话保存 无法复活损坏的绑定（#6102）。

  • 权限检查区分文字heredoc数据和可执行命令， 包括替换和 shell stdin (#6098)。

  • 自动压缩在实时上下文压力下安静运行，保留 当前任务和最近的工具交换，同时保留系统/工具前缀 稳定。上下文替换之前保存原始历史和切换； 失败或取消的压缩保留对话（#5620，#6047）。

  • 自定义和网关提供商可以覆盖每个确切模型的上下文限制， 因此切换模型也会切换仪表和压实预算（#6108）。

  • 插件建议解释其匹配术语并记住明确的解雇 跨重新启动。通用词和存储库主机域不再触发 不相关的安装提示 (#6031)。

  • 插件trust和自动删除有键盘和鼠标确认 与确切的审核内容相关的控制措施；用户仍然可以复制命令 更改的内容需要重新审核（#6039）。

  • 面向模型的MCP启动工具可以在之后重新连接现有的配置名称 登录时无需更改其凭证密钥或重新启动健康的兄弟姐妹 (#6030)。 减少令牌到期倒计时不再使凭证看起来被撤销 就像来自另一个会话的新登录一样。

  • Gemini 设置使用官方端点支持的推理工作字段， 避免被拒绝的顶级谷歌思维对象。双子座2.5和3保持 他们支持的努力范围；签名的工具历史仍然可以推理 更改并重新启动（#6018，感谢@vmakarov-uk）。

  • 错过的自动化事件合并在一起，不会与正在运行的作业重叠； 重新启动可协调持久收据，而无需重播已接受的工作。损坏 相邻记录被隔离，同时保留其原始字节。

  • 捆绑的第一方市场列出了实际的插件捆绑包和用途 现有的安装、审查、trust 和更新路径。只读连接 检查每周验证目录和技能镜像的更改。已经存在 捆绑导致当地审查和管理控制；目录安装 下载前拒绝名称冲突，而不覆盖或授予 trust。

  • Windows 拒绝检查保留本机路径分隔符，同时保留 保守的 POSIX 扫描 shell 包装器和替换。

  • 配置示例与遥测披露一致：使用情况分析是 可选且默认启用；本地诊断不需要遥测（#6011）。

  • 子代理强制执行会话的类型化 shell 和文件拒绝规则，包括 子项启动后的完全访问权限、委派编辑和策略更新 (#6097)。

  • 实时权限编辑以原子方式到达正在运行的引擎克隆。拒绝规则 支持令牌通配符和 Windows 命令拼写，同时保留 POSIX 参数文字（#6054，感谢@h3c-hexin 和@asto18089）。

  • 工具结果图像使用现有的类型化内联路径并完全解码 在入学或提供者预测之前低于规模和分配限制。 无效图像会在文本结果旁边保留可见的遗漏收据 （改编自#6053，感谢@h3c-hexin 和@asto18089）。

  • 选择转录后，单独的 y、Y 或 r 仍保留为作曲家输入 文本。 Clicking 作曲家发布成绩单并停靠焦点。

  • 代理在父级处于活动状态时注册实时工作人员事件的更新 忙碌，包括在工人产生之前收银机打开的时候。

  • Ghostty 不再在发射标记上方显示第二条图形鲸鱼。 所选模型在第一条消息之前保持可见；未使用的会话 指标保持安静。预定计数直接打开/automation。

  • 市场安装接受兼容的克劳德插件包和根 .claude-plugin 之外的相关来源；不支持的组件失败 明确地。本机 trust 和启用审核仍然适用。

  • 在工人扇出期间 Esc 使父进程在取消工人时停止 完成。他们的收据在下一个明确的用户回合中仍然可用。

  • 即使旧状态缺少时间戳，撤消也会保留消息。会议 再次保存时，日记条目会保留其附加时间戳。

  • 扩展操作就地刷新，检查输出使用文本 寻呼机。空的启动 shell 隐藏未使用的指标并保留恢复提示 当需要关注多个 MCP 服务器时可读。

  • 直接作曲家粘贴 (Ctrl-V) 保留丰富的 clipboard 标题、列表、 链接、表格和代码为 Markdown，带有纯文本后备。完整答案 副本保留创作的 Markdown，无需终端换行；设置字段 仍然粘贴文字。

  • 嵌入式计算机使用捆绑包包括市场的 JPEG 捕获 和有限有效负载修复，因此新的内置安装也会收到它们。

  • 中文文档链接解析为贡献者指南和Windows 翻译路径的屏幕截图（#6080，感谢@c020627）。

  • GLM-5.3 推理控制遵循 Z.ai 上的强制思维合约 BigModel 路由，包括在请求先前配置时的低工作量 思考（#6051，感谢@h3c-hexin 和@asto18089）。

  • 财务调用尊重会话网络策略和面向模型的 shell， 验证者、通知和舰队指导与可执行合同相匹配 （#6052，感谢@h3c-hexin 和@asto18089）。

  • 沙箱海拔提示显示每个选项，包括 Abort。卡片 是以框架为中心的固定22行；在其边框内并填充 最多留下 18 行可用，内容为 20 到 23 行，无滚动 轨并且没有截断提示。安全出口——唯一的选择 没有任何东西——在每个终端尺寸上都被涂过底部边缘。卡片 现在从其内容测量并保留之前的选项行 否认细节，这就是缩短的内容；每个选项大约低于 60x24 描述脱落，每个选择都保持其行。选项命中框也 计入未包装的源代码行中，因此包装的描述将每个 下面的碰撞箱不同步，click 做出了与 指针下的一个。

  • Hotbar 设置模式中的 d 在清除每个插槽之前会询问。它坚持了下来 第一次击键时为 hotbar = []，以裸字母为视图 过滤器 - 破坏性键和搜索键是同一次按下。它武装了一个 确认拥有每个密钥直到得到答复，并且提示采用 简介在标题中的位置，因此它不能是从标题中脱落的行 五行预算。

  • 失败红色表示再次失败。度量线描绘了上下文阅读 错误颜色从 80 % 开始，而上面一排的姿势栏称为 相同的注意力阈值；工作流程面板绘制了 Waiting 行，例如 一架坠毁的飞机，尽管它自己的 is_running 将 Waiting 视为正常；和 工作表面将 error_fg 花在仅等待、阻塞或的待办事项上 陈旧，以及自动压缩的常规方法。 WorkTone有一个真正的 现在有 Failure 变体，并且警卫测试可以在每个 可选择的主题而不是单独的默认主题。
