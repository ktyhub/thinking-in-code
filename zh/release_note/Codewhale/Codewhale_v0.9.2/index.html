Codewhale v0.9.2

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，所有三个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale、codew 和 codewhale-tui 此版本中的二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.2

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew 填充程序，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取您机器的存档：codewhale-windows-x64.zip 或 codewhale-windows-arm64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称进行迁移的信息，请参阅 docs/REBRAND.md。

v0.9.2 中有什么

这是 Codewhale v0.9.2 候选源。这不是已发布的版本 直到匹配的标签、包、校验和和发布资产存在。

改变 — 行为

  • 旧版 model = auto 不再自行选择网络分类器。 持有 DeepSeek API 密钥用于静默选择 deepseek-v4-flash 作为 每个自动转弯的分类器 - 没有人要求的路线上的每转弯成本， 一个提供商比其他提供商享有特权。汽车现在保持本地且免费 除非显式的 [auto.router] 块命名提供者和模型。 如果您依赖隐式默认值，请显式恢复它： 
    [auto.router]
provider = "deepseek"
model = "deepseek-v4-flash"

[auto.router] 保留传统的 model = auto 配置。这是无关的 到舰队的自适应推理路由器，这是由 来自舰队文件的名称并仅决定已冻结路线的难度 认为。 自v0.9.1起登陆，尚未发布。发现的一系列缺陷 策略引擎、MCP代理、会话索引的通读审计， 以及应用程序-服务器桥 - 其中一些情况会出现错误的结果 在看起来不错的响应或日志行后面默默地到达。的 版本还增加了选择加入会话、推理、本地化和可检查性 表面；现有默认值保持稳定，除非下面明确输入 另有说法。

添加

  • /permissions 现在列出活动用户权限规则源，每个规则的 有效匹配器和全局/存储库范围，以及该范围是否适用 在当前工作空间中。 /permissions remove <number> 预览删除 并且需要快照绑定的确认令牌，因此并发编辑 无法在已确认的索引下移动不同的规则。追加和删除 共享一个相邻的锁，保留不相关的 TOML 格式和注释， 原子地替换 permissions.toml，并重新加载实时用户规则集 无需清除仅限会话的批准。 /config ask-rules 仍然是 兼容性条目；规则创建、glob/目录规则和拒绝 持久性仍然超出范围（#1186，PR #4960 by @greyfreedom）。
  • /preview-request（别名 /dryrun 和 /preview_request）是仅人类的， 下一个主要回合的无提供商检查。生产调度及 预览在聊天完成、人性化中共享一个准备好的请求接缝 消息和 OpenAI 响应，因此清单读取最终的线模型， 推理控制、工具选择、工具模式和主体哈希来自相同的 价值生产发送。需要汽车的路线、工具或车身事实 提供者分类器、MCP 连接、可变挂钩、压缩或排队 运行时注入仍然键入不可用。清单报告准确 主要角色/车道标识、上游路由源来源、请求和 有效的推理，规范的 JSON 大小，保守的离线估计， 提供商报告的使用情况为不可用，因为没有运行任何请求。它从来没有 添加模型可见的工具，发送提供者调用，或打印提示、消息， 凭证、端点路径或工作空间路径内容。明确的 /preview-request base-prompt 模式仅打印精确的有效碱基 提示；有效的系统文本在其最终哈希值后面仍然受到保护。的 确切的正文包含与以下使用的相同的权威瞬态工作/待办事项尾部 生产，包括比传统投影更新的图支持状态。 预检保留生产的单独框架的基础加工作估算， 当权威投影不可用时，关闭失败。安 用尽的活动目标代币预算也会产生类型化的不可用结果 在构建任何出站请求之前。 （#1004、#3928；试运行概念由 @GTC2080/TaoMu 从 PR #1099 中收获。）
  • 同一车道/车队的斜线命令、热键操作和 CLI 入口点 生命周期操作现在共享一种类型的控制平面合约 (codewhale-lane::control)：稳定的 <domain>.<verb> id，读与写 权限、持久性范围、精确身份目标选择、可重试性、 生命周期结果，以及一张有界的、经过消毒的收据。 docs/COMMAND_CONTROL_PLANE.md 记录它（#1888）。
  • /lane [list|status|interrupt|restart|resume] — 持久的车道控制 作曲家，由同一执行者 codewhale lane … 调用支持。 码鲸 车道中断|重新启动|恢复 are the matching CLI verbs; 车道停止保持为 lane interrupt 的兼容性拼写。将 @<lifecycle-seq> 附加到 Lane id 隔离对您观察到的确切持久代的写入，因此 并发转换被视为冲突而被拒绝，而不是采取行动（#1888）。
  • codewhale fleet list 和 /fleet [list|status|interrupt|resume] — 耐用 车队通过共享 DTO 从任一表面进行检查和控制 携带确切的提供者、提供者表 ID、模型、有效推理层， 以及分类帐记录它们时的路由源，以及键入的 not_recorded / not_applicable / redacted 没有的原因。请求与有效 推理永远不会回填：账本仅保留有效层，因此 请求的层报告 not_recorded (#4022)。
  • 捆绑的技能包现在附带 help 技能（目录第 7 代）。它是 invocation: explicit-only，因此它永远不会进入模型的环境目录 并且无需即时预算。它的主体是一个路由卡，指向 此构建实际暴露的表面 - /help 和 /help <command>， /skills 和 /skills inspect、/config、doctor 和 docs/ 树 当工作区是 Codewhale 结账时 — 并且明确禁止粘贴 命令列表或设置表进入上下文（#4698）。
  • crates/tui/assets/skills-catalog-matrix.json：原创、无提供商 期望矩阵涵盖每个捆绑技能（等级、调用、别名、 环境目录资格、隐藏别名）。合同测试 crates/tui/src/skills/catalog_matrix.rs 断言之间的双射 固定装置和发货的捆绑包，因此入门包不能在没有 明确的夹具更新。该矩阵涵盖了积极的资格和明确的 加载、非激活负数、别名解析、仅显式排除、 别名与规范冲突优先级和提示预算不变量（无 重复的目录条目，没有别名作为额外条目，并且已发货 包适合 12 000 字符的预算，不遗漏技能行）。这些 是确定性的注册表/目录/解析器断言，并且不做出任何声明 语义模型路由（#4698）。
  • 每个已发货的完整捆绑目录的区域设置路由覆盖 区域设置（en、ja、zh-Hans、zh-Hant、pt-BR、es-419、vi、ko）。否 捆绑的技能提供了本地化的路由描述，但没有发明； 经过测试的合约是规范英语的确定性回退 描述，呈现的目录在不同区域设置中字节相同。 涵盖精确标签匹配、主子标签后备和英语后备 针对合成创作的固定装置，如果捆绑的固定装置奇偶校验测试失败 技能可以在没有源支持的覆盖范围的情况下获得本地化元数据（#4698）。
  • docs/LIVE_SMOKE.md：可复制粘贴、选择加入 Kimi 的现场烟雾说明 K3 和第二个提供商/模型 (DeepSeek)。运行仅是手动的——什么都不需要 在 CI 中，测试或技能会调用它们。他们使用 env -i 加上一个一次性的 CODEWHALE_HOME； HOME 未设置而不是重新利用，并且环境 不转发提供者变量。操作员命名凭证 显式变量，并且隔离的子级在回显关闭的情况下读取其值， 在退出或中断时恢复先前的终端状态，并且永远不会持续 值或将其放入命令参数中。该页面指出了预期的 路线/模型/推理/工具接收字段，同时将提供者错误视为 在提供者配置、身份验证/权利和 线束行为已得到独立证实（#4698）。
  • 批准卡现在可以记住符合条件的安全外壳和文件写入批准 作为精确的 allow 规则，范围仅限于当前存储库。记住外壳 命令使用完整命令匹配，保留经过验证的文件和补丁路径 与工作空间相关的、危险的、关键的或回购法持有的请求保留 不符合资格，需要继续审查。
  • tui.header_items（字符串数组，可选，默认 []）：选择加入 标头芯片显示累积会话令牌使用情况作为输入/缓存命中/ 输出。在 [tui] 下设置 header_items = ["tokens"] 以启用它。的 Chip 是 header 中唯一可删除的元素——git 标签、上下文 仪表和版本标记保留其空间，狭窄的终端会丢弃 芯片而不是基准镀铬。未知条目会受到警告并 跳过，因此较新版本编写的配置仍可由较旧版本加载 （@eugenicum 请求的#4520；@XhesicaFrost 的 PR #4610，收获于 共同作者）。
  • thinking_default_expanded 让推理块开始打开，同时保持 空间作为每块切换。该设置已保留，可通过 本机和运行时配置，并记录了 SSH/tmux 可访问性 （@M-Maciej 的问题 #4925 和 PR #4928）。
  • 转录本将 LaTeX 数学的保守子集呈现为可读 无需重写隔离/内联代码的 Unicode、普通货币、转义 美元或未知命令。 PR #4973 的贡献 @SparkofSpike 通过 PR #4974 进行了强化和落地；报道者 @antarikshraya #4957。

  • 捆绑的贡献者入职技能可以同步贡献上下文， 选择合适的门，并在不充气的情况下准备摘要 环境技能目录。它遵循贡献者导航请求 #4227 作者：@JayBeest。

已修复

  • 权限设置现在一致地呈现产品姿势询问， 自动审查和完全访问，而不是泄漏内部 never 令牌。 现在，相同的已解决沙箱策略可驱动执行和 UI 收据：计划 保持只读，询问和自动审阅保持工作区范围，以及完全访问权限 实际上是未沙盒化的，除非更严格的有效配置获胜。
  • 当用户明确选择已配置的队列时，队列设置不再停止 Codex 或 Grok 外部同意路线。所选路线已激活并且 保存前进行验证，名册角色直接在其模型步骤中打开， 第一次输入时查看保存，新的配置文件默认为个人 名册在下一个会话中加载的配置文件目录。
  • 提供者凭证对话框现在共享一个包装的、秘密安全的 API 密钥 每个非 OAuth 提供商都会出现。耐用的钥匙已经存在 存储被报告为已配置而不渲染它，键入或粘贴是 清晰的框架作为替换，狭窄的帮助文本仍然可见，并且 Codex 在此模式中，Grok OAuth 流程保持无令牌状态。
  • Ctrl+O 再次打开所选内容的完整记录推理详细信息， 活动的或最新的推理块。全回合回合检查员移至 Ctrl+Alt+O 和 /turn inspect，删除快捷方式碰撞，同时保留 原始叶子细节和冲水后推理可发现。
  • 失败的子代理现在会向 他们的父母拥有经过净化的失败等级、过去的工作和完整的 转录句柄。家长对孩子的消息、跟进和中断工具 现在使用一个经过层次结构检查的邮箱路径，并持续嵌套完成 信封在指令文本修订中仍然可以安全地恢复。
  • 后台 shell 完成事件现在仅携带有界尾部加上 可检索的精确证据句柄。终端前台 Bash 结果是 在直接工具结果边界处确认并且不再发出 第二次作为背景完成工件。
  • 无提供商舰队和子代理固定模型路线现在仅拒绝 在创建工作树之前高可信度的外国提供商模型 ID，同时 显式提供者/模型对、自定义和本地端点、未知 ID 以及 聚合器线路 ID 解析保留其预期行为。
  • 手动压缩现在保留并报告提供的提供者失败 类，而不是用不透明的通用错误替换它。这不 当记录的失败不能证明配额耗尽时，推断配额耗尽。
  • 环境水母在动画时保持完整、可读的轮廓， 并且网站图标现在使用 Signal Current 桌面磁贴而不是 遗留的鲸鱼标记。
  • ACP JSON-RPC 响应保留 avante.nvim 的数字请求 ID，同时 保留 Zed 的协商字符串 ID 例外（PR #4929，作者： @atmosuwiryo）。
  • 恢复后的 shell 单元的工作不再存在，停止显示实时内容 旋转器并在转录本中进入真实的陈旧/无输出状态， 相条和侧边栏（@LI-Jialu 的 PR #4937，结束#4547）。
  • 中断的检查点和定时恢复快照仍然是检查点 而不是被提升为孤立会话文件，从而防止重复 /resume 条目（@SparkofSpike 的 PR #4963）。
  • 每个交付的区域设置都由键入的设置模式和本机所承认 选择器，完整/部分状态保持独立并经过测试（PR #4856 作者：@nightt5879，结束#4786）。上下文菜单悬停命中测试也考虑 其标题行（@XhesicaFrost 的 PR #4897；@SparkofSpike 在 第4803章）
