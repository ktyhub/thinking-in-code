长篇大论；博士

  • 10 个新型号（Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe 等！）
  • 可扩展 KV 缓存默认处于启用状态： vLLM 根据预热后实际释放的内存调整 KV 缓存的大小，因此大多数模型都会获得更大的缓存和更高的吞吐量。
  • Model Runner V1 已消失。 Model Runner V2 现在是唯一的 GPU 运行程序。
  • Blackwell 和 MI355X 上的大幅加速：高达 1.95× 解码（GB200 上的第 5 步）、1.6× 吞吐量 (GLM-5.3-Flash)、1.24–1.40× 更快的长提示 TTFT (GLM-5.3)。
  • **升级检查：**默认块大小现在为 64，ROCm 7.2 图像消失，需要 huggingface_hub >= 2.0.0。请参阅升级之前。

亮点

可扩展的KV缓存，默认开启

  • 在 CUDA 和 ROCm 上，KV 缓存的大小是根据 CUDA 图形捕获和预热后**实际空闲的内存确定的，而不是根据估计确定的（#56492）。
  • 结果： 更大的缓存（例如 H200 上的 MiniMax-M3：433k → 672k 令牌），因此在高并发时吞吐量更高，TTFT 更低。
  • 权衡： 在某些型号上，每个令牌的解码延迟可能会增加（在并发数为 128 时，某些 H200 型号上的 TPOT +6–18%）。使用 --gpu-memory-utilization 0.9 或 --no-enable-extensible-kv-cache 选择退出。
  • 通过修复分配器碎片、启动 OOM 和 KV 连接器进行了强化（#67296、#67485、#66731、#66523、#66197、#65137、#66605、#66674）。

仅适用于 Model Runner V2

  • Model Runner V1 被删除 (#63373)。
  • 双批次重叠现在在 MRV2 上运行，包括推测解码和 DCP (#61464)。

推测解码

  • 后缀解码使用 GPU 推测器在 MRV2 上运行；不再需要北极推理 (#60339)。
  • 自定义投机者： 声明性配置加上 register_speculative_method 插件 API (#63205)。
  • MRV2 草案模型投机者的 CUDA 图表 (#60989)。
  • 自适应验证与 XPress 配合使用 (#65175)。
  • 草稿 KV 缓存与目标的 dtype 匹配，因此 FP8 目标获得 FP8 草稿缓存 (#65198)。
