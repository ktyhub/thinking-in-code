cognee v1.6.6

发布日期： 2026-10-29 变化： v1.6.6rc1 → v1.6.6

拉取请求： #6266、#6337、#6339、#6340

总结

此版本的重点是使冲突处理更可靠、更易于管理，以及一些稳定性、矢量和数据布局修复。您将发现新的持久冲突解决 API、更安全地淘汰冲突选择、更快、更安全的缓存/删除路径，以及可节省重新嵌入工作的矢量处理改进。

亮点

  • 新型耐用的 API 用于解决事实冲突，因此您可以通过 API 可靠地解决数据分歧。
  • 默认情况下启用冲突审查，许多修复可确保在编辑、删除和重建时正确取消“选择”（有关冲突事实的用户决定）。
  • 在向量存储之间复制存储的向量，无需重新嵌入，以在移动/复制嵌入时节省时间和成本。
  • 更安全的删除和缓存：Redis 列表/上下文删除现在是原子删除或就地删除，并且权限/KMS 错误会浮出水面，因此不会默默地忽略失败。

新功能

  • 持久的事实冲突解决 API — 一个新的 API 端点，可让您以持久（持久）的方式解决冲突事实之间的分歧。它的作用：记录并应用所选的解决方案，以便系统一致地使用已解决的事实。为什么重要：可靠地解决会话和组件之间的数据不一致问题，减少陈旧/冲突数据带来的错误答案或令人惊讶的行为。
  • 默认冲突审查工作流程 - 系统现在默认审查冲突（以前是可选的）。它的作用：当系统检测到相互矛盾的事实（同一信息的不同来源或版本）时，它会自动将其显示出来以供审查。为什么重要：使冲突检测开箱即用，从而减少冲突，并且搜索/代理返回更清晰的结果。
  • 在存储之间复制存储的向量而无需重新嵌入 - 您现在可以将向量嵌入从一个向量存储移动或复制到另一个向量存储，而无需重新运行嵌入模型。它的作用：执行存储嵌入的直接复制。为什么重要：加速迁移和复制，并减少计算和成本，因为模型不会被重新调用。
  • DLT 列和日期单元格表示改进 - 默认情况下，每个 DLT 列（更改跟踪表中使用的列）现在都被视为值节点，并且日期单元格一次表示为时间戳值。它的作用：使平台将更改跟踪列视为具体值并避免重复日期单元格。为什么重要：修复读取数据集行和键时微妙的正确性和重复问题，提高读取和下游处理的准确性。

改进

  • 更安全地停用选择（用户关于冲突事实的决定）- 选择在正确的时间停用：在块编辑、连接器删除、数据集忘记操作时以及在重建时否则会丢失它们。这减少了数据更改后残留的过时决策。
  • 失效和格式错误的密钥快速失败 - 如果相关状态失效失败，编辑将失败； DLT 键的格式错误的提示现在会引发错误，而不是默默地跳过它们。这可以防止静默数据不一致。
  • 解决冲突时保留检索上下文 - 现在，在解决冲突时会保留用于获取支持证据的检索上下文，因此答案仍然基于相同的上下文。
  • 在写入向量之前合并和验证标签 - 现在在向量更新插入之前合并和验证标签，避免向量记录上的元数据损坏或不完整。
  • 完成多会话标记推出 - 会话标记（用于跟踪跨会话的操作）现在跨组件一致地推出，以改进会话处理和正确性。
  • 让classify()接受密封对象的明文视图——当您需要在打开加密/密封对象进行处理后对其内容进行分类时非常有用。

性能

  • 减少撤销已删除冲突事实时的检索争用——当同时撤销许多决策时，可以降低竞争条件并提高响应能力。
  • Redis 列表就地删除和原子上下文删除 - 缓存删除现在更加高效和一致，减少了延迟和部分删除状态。
  • 直接读取行的关键列 - 直接查找关键列可减少读取行时的开销，从而提高表支持数据集的读取性能。

安全

  • KMS 错误透明度 - 密钥管理系统 (KMS) 错误现在已展开，因此调用代码可以查看并正确处理加密/密钥问题，而不是隐藏它们。
  • 清理中的删除权限检查 - 清理操作现在可以验证删除权限，从而降低未经授权的数据删除的风险。

错误修复

  • 失效失败时编辑失败 - 如果无法执行相关失效，编辑现在会停止并报告错误，避免出现不一致的状态。
  • 仅在块编辑和更新时停用选项（而不是认知） - 确保在正确的生命周期阶段停用选项，以避免过早或错过停用。
  • 淘汰因重建或事实消失而丢失的选择 - 防止在删除或替换基础事实后陈旧的选择继续存在。
  • 在忘记和连接器删除时停用用户选择 - 确保在您忘记数据集或删除连接器时清除用户决策。
  • 跳过序言中的规定选择 - 避免在冲突预处理期间意外考虑规定的（静态）选择。
  • 仅在解决冲突时引用活动块 — 仅使用当前活动（未删除）的块作为支持证据，防止在解决过程中使用已删除的数据。
  • 修复仅内存删除路径 - 解决以前在纯粹内存与持久存储中操作时表现不同的路径。
  • 删除Redis上下文
