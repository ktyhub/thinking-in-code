cognee v1.6.6rc1

v1.6.6rc1 — 历史控制、连接器和同步强化

发布日期： 2026-10-23 变化： v1.6.5.dev0 → v1.6.6rc1

拉取请求： #5765、#5850、#5893、#5898、#5938、#5955、#5958、#5961、#6011、#6013、#6014、#6185

总结

此版本的重点是为用户提供对内存和搜索历史记录更清晰、更安全的控制，添加多个新连接器，并强化同步可靠性。关键的工作流程更改包括明确的历史记录清除行为、从 CLI/API 中删除搜索历史记录的新标志，以及使 Drive/Asana 同步和索引更加强大的修复。

亮点

  • 新的forget(clean_history=True)选项，这样您就可以删除搜索历史记录而无需其他输入。
  • 用户现在可以通过 API 和服务器端点删除自己的搜索历史记录。
  • 新连接器：添加了 Obsidian（保管库）、Asana（任务）和 OneNote，并强化了它们的同步。
  • 可靠性改进：Drive 和 Asana 同步更快且可恢复；图和索引操作避免了不必要的工作。

重大变更

  • 数据集删除现在会清除关联的搜索和对话历史记录：删除数据集时，所有关联的历史记录都会被删除。所需操作：如果您依赖保留的搜索或会话跟踪进行备份或审核，请在删除数据集之前导出或备份它们。
  • run_info 结构已更改：run_info 元数据不再包含之前存储的摄取管道的完整“数据”项。所需操作：任何读取 run_info 并希望嵌入数据的代码或工具都必须更新，以通过其数据 ID 获取原始项目或使用新的存储形状。此版本中包含删除旧数据形状的迁移。
  • 历史清除失败：如果无法完成清除，尝试清除历史记录的删除/忘记操作现在将失败。所需的操作：确保服务有权删除搜索历史记录，并且允许完成长时间运行的清除操作；处理调用删除 APIs 时的失败。
  • 预算/配额错误：预算耗尽和需要付款的错误更一致地出现（LLMPaymentRequiredError）。所需的操作：如果 clients 与 LLM 计费路径交互，则应捕获并处理这些异常。

新功能

  • Forget(clean_history=True)：forget 命令和 API 的新 clean_history 标志可让您清除记录的搜索历史记录，同时保留其他删除行为。它的作用：调用forget(clean_history=True)来删除与数据集或用户相关的存储的搜索历史记录。重要性：您现在可以删除用户搜索的痕迹，而无需执行其他删除操作，从而使隐私和清理操作更加清晰和轻松。
  • 删除您自己的搜索历史记录：服务器和 API 现在包含一条允许用户删除自己的搜索历史记录的路线。它的作用：最终用户（通过 API 或 UI）可以删除他们的个人查询和搜索元数据。为什么重要：通过让个人直接控制他们的搜索轨迹来提高用户隐私和合规性。
  • 黑曜石连接器（金库）：一个新的连接器，可吸收黑曜石金库（本地笔记和降价金库）。它的作用：让您将存储在 Obsidian 保险库中的笔记导入 Cognee，以便它们变得可搜索和可调用。为什么重要：扩大支持的来源，以便存储在 Obsidian 中的个人知识可以包含在内存和搜索工作流程中。
  • Asana 连接器：用于任务和事件的一流 Asana 连接器。它的作用：将 Asana 任务和事件同步到 Cognee 中，并使其可供搜索和调用。为什么重要：使用 Asana 的团队现在可以在其内存驱动的工作流程中包含任务上下文和历史记录。
  • OneNote 连接器：添加 OneNote 对摄取和同步的支持。它的作用：将 OneNote 内容拉入 Cognee，以便笔记本可搜索并链接到内存中。重要性：集成另一个主要笔记来源，以便用户的 OneNote 内容参与记忆和搜索。
  • 在召回命中中公开数据集和数据 ID：召回结果现在包括数据集（命中的来源）和基础数据 ID。它的作用：为了清晰起见，返回的召回命中包括数据集名称和原始项目 ID。为什么重要：可以更轻松地将答案追溯到源文档以进行审核和跟进。

改进

  • 通过 CogneeClient.forget 转发 clean_history，并清楚地命名仅历史记录的情况，以便 client 和服务器行为匹配以及错误消息更清晰。
  • 文档：澄清了 memory_only（仅内存删除）保留的内容与磁盘上保留的内容，以便用户更好地理解删除语义。
  • 搜索代码：重用内部delete_user_search_history逻辑，添加专用的搜索历史记录删除路由，并将搜索历史操作范围限制到调用用户，以避免意外的跨用户删除。
  • 图表和索引：每次 add_edges 调用和 has_edges 中仅查找一次图表边缘，以减少图表更新和摄取期间的冗余工作。
  • 驱动器同步：加速并扩大驱动器同步，使其更能抵抗中断（命名不可读的 PDF，更好的恢复逻辑）。
  • Asana 同步：可恢复，改进了时间戳处理，并提高重复同步令牌以避免同步卡住。
  • 索引构建：在每次版本更改时重试跳过的 HNSW 索引构建，以提高升级时矢量索引的可靠性。
  • 错误处理：通过共享助手显示预算耗尽和配额/权限错误，以便 client 代码和调用应用程序收到一致的、可操作的异常。

性能

  • 更快的图形更新：避免重复的边缘查找可减少批量 add_edges 操作期间的 CPU（实际影响：大型图形更新时更快的摄取和更低的 CPU）。
  • 更快的云端硬盘同步：文件同步运行速度更快并处理更广泛的数据集（实际影响：更快的初始同步和 Google 云端硬盘源的追赶）。
  • 索引重试改进：版本更改后 HNSW（向量索引）构建重试更加可靠，减少了阻止搜索的失败索引状态。

安全

  • 依赖项更新：boto3 现在已列在 aws install extra 中，因此当用户安装 aws extras 时，AWS 集成可以获得兼容的 SDK。更新了证书捆绑包（需要证书 2026.10.19）并刷新了容器 CA 捆绑包以提高 TLS 可靠性。
  • 针对预算/配额失败的更严格的错误传播，因此调用者会得到明确的付款/配额错误，而不是静默重试。这有助于避免泄漏意外的重试行为和表面所需的修复。

错误修复

  • 清除每个数据集删除的历史记录，以便数据集删除不再留下过时的搜索或对话历史记录。
  • 如果历史清除失败，忘记现在会失败（因此部分删除不会默默地留下痕迹）。
  • 停止在 run_info（内部管道运行元数据）内存储数据项 - 存储的 run_info 现在排除原始“数据”有效负载，以避免重复并减少存储。
  • 停止本机适配器重试配额失败，以防止忙循环重试配额错误并立即返回配额错误。
  • 修复：命名不可读的云端硬盘 PDF，以便在同步和摄取过程中仍能正确跟踪它们。
  • 修复：恢复剪切 Asana 列表，并使 Asana 列表/同步对瞬态 API 错误和分页剪切更加稳健。
  • 修复：范围跟踪跨越（可观察性）到调用用户，因此遥测不再混合用户。
  • 各种连接器强化和测试修复（Drive、OneNote、Gmail、Notion 等），以提高现实世界摄取的可靠性。

技术变更

  • 添加了大型重构和许多新的和更新的摄取连接器（Google Drive、Gmail、Notion、Obsidian、Asana、OneNote）以及新的同步代码和测试。
  • 添加了许多任务模块，用于代码文档提取、memify 全局上下文索引构建器以及内部管道和示例使用的会话蒸馏片段。
  • CI 和测试：拆分集成作业，为搜索历史删除路线添加新的 API 快照，并刷新测试覆盖范围和固定装置。
  • 内部：添加/更新了迁移（包括删除 run_info 数据字段的迁移），对服务器/client 管道进行了大量重构，以及可观察性/跟踪改进。
