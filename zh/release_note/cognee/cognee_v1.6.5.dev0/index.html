cognee v1.6.5.dev0

v1.6.5.dev0 — 蒸馏、嵌入和连接器硬化

发布日期： 2026-10-16 变化： v1.6.4.dev0 → v1.6.5.dev0

拉取请求： #5287、#5534、#5620、#5622、#5720、#5721、#5722、#5725、#5726、#5751、#5798、#5898

总结

此版本的重点是使内存蒸馏更加可靠，改进嵌入的生成和计量方式，以及强化连接器和 LLM 集成。它包括多个错误修复、安全性和操作改进，以及与旧版嵌入表面和本地缓存布局相关的一些重大更改。

亮点

  • 更可靠的蒸馏：蒸馏现在仅读取所需的 QA 轮次，密封每个策展人批次的条目，并默认策划每个新条目，以便蒸馏记忆准确且一致。
  • 嵌入改进：支持在支持的情况下请求 Base64 编码的嵌入、计量嵌入令牌的使用情况、降低默认嵌入批量大小以确保稳定性，并将本地模型缓存保持在可预测的路径下。
  • 连接器和 LLM 修复：Gmail 和 Google 日历连接器得到强化（更好的配额处理和权限），litellm 和 Mistral 模型处理得到改进，并且共享 Azure 令牌处理以降低身份验证复杂性。
  • 安全和警报：添加了向 Slack 发送的每日 CVE 警报，并更新了存储库安全文档，以帮助团队随时了解情况。

重大变更

  • 三重态嵌入/三重态 memify 表面已被删除或弃用 - 旧的三重态嵌入表面已被弃用并删除了部分内容。如果您依赖“三元组”嵌入流，请迁移到较新的嵌入表面并 memify 管道。升级之前检查您的管道和替换件。
  • 提高了 datamodel-code-generator 最低版本 - 自定义图形模型生成需要 datamodel-code-generator >= 0.56.0。如果您使用自定义图形模型，请升级此依赖项。
  • Fastembed 缓存路径更改 — FASTEMBED_CACHE_PATH 已从 .env.template 中删除，fastembed 现在默认使用 ~/.cognee/models。如果您依赖于自定义 FASTEMBED_CACHE_PATH，请更新您的环境或将缓存移至新位置。

新功能

  • 请求支持 Base64 嵌入 — 某些嵌入提供程序可以返回编码为 Base64 的向量。现在，当提供商支持时，Cognee 会请求 Base64 嵌入。重要性：base64 可以提高与某些提供商和传输的兼容性，减少编码错误并简化集成。
  • Slack 的每日 CVE 警报 — 新的自动警报将每日安全建议（CVE 摘要）发布到配置的 Slack 通道。为什么重要：让您的团队了解影响依赖项的新漏洞，以便您可以更快地采取行动。
  • 在摄取过程中克隆存储库的选定分支 - 您现在可以在拉取存储库时选择要克隆的分支。为什么重要：使摄取可重现，并允许您索引特定于分支的代码或文档，而无需手动存储库处理。
  • 嵌入令牌使用计量 - 系统现在记录每个活动使用的嵌入令牌数量。为什么重要：帮助理解和审核嵌入使用情况以进行成本跟踪和调试。

改进

  • 更集中的蒸馏：蒸馏现在仅读取所需的 QA 回合（而不是整个对话），并且策展人每批运行密封蒸馏条目，因此部分结果不会泄漏。这减少了工作量并使摘要摘要更具确定性。
  • 默认情况下，在每次蒸馏运行时整理每个新条目 - 每个新添加的内存条目都会考虑进行蒸馏，除非您更改设置，以确保及时总结新内容。
  • 将类型化条目绑定到会话的数据集 - 当系统在会话期间写入类型化（结构化）内存条目时，它们现在与该会话的数据集正确关联。为什么重要：保留正确的数据集所有权并防止数据落入错误的数据集中。
  • 在 Remember_skill_run_entry 上获取 dataset_id — 用于记住的技能输出的显式数据集路由提高了可追溯性和正确性。
  • Fastembed 和本地模型缓存更改 - Fastembed 模型现在默认保存在 ~/.cognee/models 下，以实现跨平台的一致缓存； ENV 模板不再公开已弃用的 FASTEMBED_CACHE_PATH。为什么重要：加载本地模型时更少的意外以及更好的跨机器行为。
  • 较低的默认嵌入批量大小 (36 → 32) — 减少内存峰值并提高受限机器上的稳定性。
  • 从 embed_text 返回纯向量 - 嵌入函数现在返回原始数字向量，而不是在更多位置返回包装对象，从而简化了下游使用。

性能

  • 更稳定的嵌入使用：降低默认嵌入批量大小并将模型保留在一致的本地缓存中，可以减少创建嵌入时的内存和延迟峰值。
  • 减少不必要的蒸馏工作：仅读取必要的 QA 轮次并按批次密封可减少蒸馏运行期间使用的 I/O 和 CPU。
  • 共享计数器和调步：连接器和后台轮询器在适当的情况下共享计数和调步逻辑，以避免意外过载和平滑吞吐量。

安全

  • Slack 的每日 CVE 警报 - 现在可以通过新的 GitHub Actions + Slack 流程获取依赖项漏洞的每日摘要，以帮助团队更快地做出响应。
  • 隐藏 NATURAL_LANGUAGE 表面和修复指南 - 某些表面变得不那么明显，并添加了修复注释以帮助确保部署安全。
  • Azure 令牌提供商共享 - Azure 令牌使用集中化，以减少虚假凭据刷新并简化安全处理。
  • Google 日历和 Gmail 强化 - 日历连接器现在有更严格的检查； Gmail 对每用户配额拒绝的恢复能力更强，并在邮箱处理过程中共享节奏，以避免意外的速率限制峰值。

错误修复

  • 只读取蒸馏所需的 QA 回合，以便蒸馏步骤不再加载不必要的对话回合。
  • 每次改进运行都会清空代理跟踪积压，以便新的改进运行不会看到过时的跟踪。
  • 密封每个策展人批次的蒸馏条目，以避免部分蒸馏可见。
  • 默认情况下，策划每次提取运行的每个新条目，以确保总结新的内容。
  • 将数据选择锁定在锁定状态下读取，以避免并发删除/忘记的竞争。
  • 修复可视化权限检查，以便仅在明确请求时应用权限跳过选项，并在适当时仅对数据集所有者跳过权限检查。
  • 避免 Gmail 每用户配额拒绝并共享每个邮箱的节奏，以减少操作失败。
  • 当 Cypher（图形数据库查询接口）被禁用时，返回 403 并带有明确的消息，而不是一般错误。
  • 缩小 Litellm 响应类型并正确返回 Mistral 的解析模型表示，以提高 LLM 可靠性和类型安全性。

技术变更

  • 检索和代码搜索组件的大规模重构——添加或重组了用于广泛检索器、代码检索器和混合检索的新模块，以提高搜索质量和可维护性。
  • Memify 管道重组——重构了 memify 和相关任务注册；作为 SDK 清理的一部分，一些旧的任务模块（三元组嵌入）被删除。
  • 新的评估框架资产——添加了基于 Locomo 的评估适配器、指标和许多参考运行工件，用于内部评估和端到端 QA。
  • LLM 适配器和令牌/编码实用程序的改进 - 更好的 litellm 适配器、Azure 身份处理和嵌入编码实用程序，以提高 LLM/后端提供商之间的兼容性。
  • 会话和数据选择的稳健性——会话管理和数据选择逻辑得到加强（锁定和选择检查），以避免忘记/删除工作流程的竞争。
