cognee v1.5.4rc1

v1.5.4rc1 — 混合检索、结构化证据和更安全的 MCP 包装

发布日期： 2026-09-15 变化： v1.5.4 → v1.5.4rc1 拉取请求： #4339、#4580、#4613、#4630、#4859、#4877、#4886、#4891、#4899、#4928、#4929、#4930、#4931、#4933、#4934、#4935、#4936、#4937、 #4944、#4945、#4950、#5030、#5032、#5034、#5035、#5038

总结

此版本改进了混合搜索和证据处理，添加了上下文引导的查询分解检索器，确保打包的扩展随 PyPI 轮一起提供，并加强了服务器和遥测强化。这些变化使搜索结果更加准确和可追踪，减少设置摩擦，并提高多组件部署的安全性和可靠性。

亮点

  • 新的 HybridDecompositionRetriever：基于上下文的查询分解，以实现更好的混合搜索。
  • 混合补全现在返回结构化上下文证据（机器可读的出处）。
  • 文档外部元数据保留在块上并在混合检索期间显示，因此结果包括源详细信息。
  • 发布轮现在是从源代码树构建的，因此捆绑的扩展包含在 pip 安装中。
  • MCP（服务）强化、身份验证修复和遥测编辑，以实现更安全的部署； MCP client 发布到 PyPI。

新功能

  • HybridDecompositionRetriever — 内容：一个新的检索器，使用周围的上下文将用户的问题分解为更小的、集中的子查询（上下文引导分解）。它的作用：它将这些子查询发送到检索系统并组合它们的结果。为什么重要：分解复杂的查询有助于系统在文档中找到更多相关证据，从而提高多部分或模糊问题的答案质量。
  • 来自 HYBRID_COMPLETION 的结构化上下文证据 — 内容：混合完成模式现在以结构化、机器可读的形式（不仅仅是文本）返回证据。它的作用：调用者会收到包含内容和出处信息的丰富证据对象。为什么重要：client 应用程序可以显示可靠的源代码片段，将出处附加到答案，或以编程方式过滤和排名返回的证据。
  • 文档 external_metadata 标记在块上 — 内容：当文档被拆分为可搜索块时，文档的外部元数据（用户提供的字段，如源、id、标签）将保留在每个块上。它的作用：元数据现在可用并在混合检索期间浮出水面。为什么它很重要：您可以将搜索命中追溯到原始文档，按源属性过滤结果，并构建更透明的 UI。
  • 无需 LLM 的 GLiNER 图提取后端 — 内容：一个新的可选图提取后端，无需调用 LLM 即可进行关系提取。它的作用：更便宜、更确定地提取图节点/关系。为什么重要：降低结构化信息提取的成本和延迟，在批处理管道或 LLM 调用受到限制时很有用。
  • 图中自定义模型的类型化边 — 内容：图数据模型支持自定义提取模型的类型化边（关系类型）。它的作用：让提取输出声明关系类型，以便图表存储更丰富的类型化关系。为什么重要：能够对提取的关系进行更强大的查询和可视化，使下游推理和图形查询更加有用。

改进

  • 来自源代码树的轮子打包 — 内容：发布轮子现在是从源代码树构建的，因此包含了捆绑的扩展（存储库中附带的额外插件）。它的作用：包的 pip 安装会自动包含这些扩展。为什么重要：减少手动安装后步骤并防止最终用户丢失扩展错误。
  • MCP client 和服务器更改 — 内容：对 MCP client/服务器进行多项强化和可用性改进（包括用于 cognee-mcp 的新 PyPI 包）。它的作用：改进多组件控制平面的部署和身份验证行为。为什么重要：使用 MCP 的部署安装更简单，操作更稳健。
  • 权限查找范围仅限于租户 — 内容：角色和权限查找现在仅限于租户（多租户范围）。它的作用：防止跨租户角色泄漏。为什么重要：提高多租户安装的安全性和正确性。
  • 保留 LLM 预算和回退行为 — 内容：修复保留预算详细信息（使用/成本元数据）并在请求因预算或政策而被拒绝时保留配置的模型回退。它的作用：报告和后备模型选择的行为更加可预测。为什么重要：您将在受限条件下获得准确的预算可见性和更可靠的模型回退。
  • 有界查询的检索评分修复 - 内容：在有界查询中对邻域 ID（邻近结果）进行正确评分。它的作用：当检索仅限于邻域时提高评分准确性。为什么重要：搜索相关性提高了基于邻域的查询（例如图形或本地上下文搜索）。
  • 在会话历史记录中记录每个 QA 回合 — 内容：会话/QA 历史记录现在可以可靠地记录每个回合。它的作用：对话日志和历史记录按顺序包含每个问题/答案。为什么重要：更好地审核、调试和对话会话的 UI 显示。

性能

  • 减少安装扩展时的摩擦 - 因为轮子现在包含捆绑的扩展，因此设置时间减少，并且不太可能因缺少扩展而出现运行时问题。
  • 更低的提取成本/延迟选项——免 LLM 的 GLiNER 后端为大批量作业中的图形提取提供了更快、更便宜的路径。

安全

  • API 模式下的 X-Api-Key 身份验证支持 — 内容：API 现在支持 X-Api-Key 作为身份验证方案。它的作用：允许某些部署平台更简单地使用 API 密钥。为什么重要：提高与标准 API 网关设置的互操作性。
  • 提供商聚合的遥测编辑 — 内容：从遥测聚合中编辑标识符。它的作用：防止聚合遥测中泄漏用户或租户标识符。为什么重要：提高遥测数据的隐私性和合规性。
  • MCP 服务器强化和测试覆盖范围 — 内容：多项更改强化了 MCP 服务器行为和测试。它的作用：加强身份验证处理和错误情况。为什么重要：减少攻击面并提高操作可靠性。

错误修复

  • 停止首次运行提示重复其“修复”标签 — 内容：UI/帮助文本重复已修复。为什么重要：更清晰的入职信息。
  • 当忘记未知数据集时引发类型 404 — 内容：对不存在的数据集调用忘记现在返回类型 404，而不是内部错误。为什么重要：自动删除数据集时出现更清晰的错误。
  • 恢复重新导入破坏的身份验证重新导出 — 内容：修复了影响身份验证导出的导入回归。为什么重要：恢复 clients 的预期身份验证行为。
  • 将 API 参考 Playground 指向可访问的基本 URL — 内容：文档现在链接到工作的 API Playground。为什么重要：在探索 API 时，文档的死胡同更少。
  • 示例和提取演示的修复 - 内容：几个示例和演示修复，可防止提取的节点或容器被删除、纠正注释并确保管道按预期运行。为什么重要：遵循示例可以获得更好的开发人员体验。
  • 保留 Gemini 后备并正确分类预算耗尽 — 内容：修复以便后备模型选择和预算错误类型能够正确运行。为什么重要：更可预测的法学硕士选择和错误处理。

技术变更

  • 大型 API 表面更新：添加了许多新的和更新的 API 路线和 DTO（搜索、召回、记住、同步、更新、可视化、会话等）。这些添加了混合检索和 Web UI 的功能，但向后兼容普通 clients。
  • 许多 CI 和工作流程更新：扩展了 GitHub Actions 工作流程、发布/测试自动化和打包脚本（包括发布轮构建步骤）。
  • 多个迁移中添加的数据库迁移和模式演变 - 升级可能包括新的表和索引（通常用于服务器升级）。
  • 重构和内部清理：删除了未使用的 Graphiti 集成，收紧了文档字符串和示例，并提高了检索和 MCP 组件的测试覆盖率。
