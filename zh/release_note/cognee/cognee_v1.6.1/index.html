cognee v1.6.1

v1.6.1 — Google 同步和可视化

发布日期： 2026-09-24 变化： v1.6.0 → v1.6.1

拉取请求： #5141、#5158、#5166、#5180

总结

此版本增强了 Google 集成（Drive 和 Gmail），改进了大型子图的可视化流，并简化了 GLiNER 安装和遥测。它还增加了更好的来源范围，将外部元数据标记到文档块上，以便检索返回更丰富的结果，并修复了一系列同步、摄取和 UI 问题。

亮点

  • 新的 Google Drive OAuth 连接器以及 Gmail 和共享驱动器同步 — 从 Google 工作区导入更轻松、更安全。
  • 以块的形式流式传输/可视化/json 响应，以便在加载大图形视图时不会耗尽内存。
  • GLiNER 安装程序经过彻底修改：脱离事件循环进行安装，首次使用时自动安装 CPU Torch，并报告安装遥测和错误。
  • 块现在携带文档外部元数据，并且该元数据在混合检索（组合语义+词汇搜索）中出现。

重大变更

  • dlt 现在是核心依赖项：CSV 加载器不再控制 dlt 上的导入； dlt 已提升为核心依赖。如果您从源代码安装 Cognee 或手动管理依赖项，请确保 dlt 在您的环境中可用或将由您的包管理器安装。

新功能

  • Google Drive OAuth 连接器：为 Google Drive 添加完整的基于 OAuth 的连接器，可让您从 Google 帐户或共享驱动器授权和同步文件。重要性：简化将云端硬盘内容安全引入 Cognee 的过程，并支持共享云端硬盘工作流程。
  • Gmail 和共享 Google 同步：添加 Gmail 提取和共享驱动器同步支持，以及 Google 同步操作的 UI 和进度指示器。它的作用：让您连接 Gmail 并在 UI 中监控同步进度；为什么重要：从 Gmail 中更无缝地获取和更清晰的同步状态。
  • SDK 中捆绑的 Google 连接器：与 Google 相关的连接器现已包含在 SDK 发行版中。它的作用：减少额外的安装步骤和不匹配的版本；为什么重要：更快的设置和更少的集成错误。
  • 以块的形式传输 /visualize/json：大型可视化响应（图/子图 JSON）现在以块的形式传输，而不是一个大的有效负载。它的作用：避免高内存使用并允许查看大图；为什么重要：大内存图的可视化更加可靠且响应灵敏。
  • GLiNER 安装程序改进：GLiNER 命名实体模型安装程序现在在服务器事件循环之外运行，记录安装和错误的遥测数据，并在安装失败时推荐所需的额外内容。为什么重要：避免阻塞服务器，提供更清晰的错误消息，并改进首次设置。
  • 首次使用 GLiNER 时的 CPU Torch：当 GLiNER 需要 Torch (PyTorch) 时，CPU 版本会在首次使用时安装，而不是在软件包安装时强制安装。它的作用：将大量安装推迟到必要时；为什么重要：减少不需要立即使用 GLiNER 的用户的初始安装摩擦。
  • 文档外部元数据标记在块上并在混合检索中显示：当文档被拆分为块时，您提供的外部元数据（例如原始文件路径或源 ID）现在会保留在每个块上并包含在混合搜索结果中（混合 = 语义 + 关键字搜索）。为什么重要：搜索结果包含更丰富的上下文，并且可以更轻松地将结果链接回其原始文档。

改进

  • 强化 Google Drive 同步和 OAuth 绑定：多项修复使 Drive 同步过程更加稳健，减少竞争条件，并在重新连接时保留凭据元数据。为什么重要：同步更安全、更可靠，凭证丢失更少。
  • 推迟孤立清理，直到确认摄取成功：摄取期间可能发生的临时/孤立记录的清理现在被推迟，直到确认摄取成功。为什么重要：防止在摄取过程失败或重试时意外删除项目。
  • 对源代码检查命中进行排名并显示上下文：扫描文档中的问题时，结果现在会进行排名并包括周围的上下文。为什么重要：使分类和诊断更快、更可行。
  • 完善的出处范围：出处（谁/什么产生了一条数据）现在正确地限定在调用者的可读数据集范围内，防止数据集级方向数据的泄漏。为什么重要：更强的数据隔离和更清晰的来源输出。
  • 对于无法解码的文件，更好的 HTTP 错误：对于无法解码的文件，CSV 加载程序现在返回 HTTP 415（不支持的媒体类型），而不是 500 服务器错误。为什么重要：为用户和调用者提供更清晰的错误语义。
  • 可观察性：GenAI 嵌入范围现在包括标准属性，因此跟踪和可观察性工具可以为嵌入操作获取一致的数据。

性能

  • 可视化流：分块/可视化/json 减少了峰值内存使用量，并允许渲染更大的图形快照，而不会耗尽服务器内存。
  • GLiNER 安装脱离了事件循环：安装 GLiNER 组件不再阻塞主事件循环，从而提高了首次安装期间的响应能力。
  • 在 SDK 中捆绑 Google 连接器可减少 client 侧安装摩擦，并可加快集成运行速度。

安全

  • 围绕 Google Drive 同步和 OAuth 绑定进行强化，以减少竞争条件并在重新连接时保留凭据元数据，从而减少同步失败或丢失凭据的可能性。
  • 解决了潜在的 CodeQL cookie 构造问题（使用用户提供的输入进行构造）——降低了静态分析标记的风险。
  • 访问和来源范围收紧，因此调用者只能看到他们可以读取的数据集的来源；这减少了意外的数据泄露。

错误修复

  • 为 GLiNER Python 导入固定正确的分布，以避免影子导入导致运行时错误。
  • 订购 GLiNER 安装遥测并注册错误，以便在诊断中看到故障。
  • 当 GLiNER 相关安装无法提供更清晰的修复指导时，额外推荐 gliner。
  • 解决有界图读取中的实体类型解析，以便可视化和图查询返回正确的实体标签。
  • 修复 clients 和 CI 中的数据集分页、排序和重复数据删除问题，使数据集列表和页面的行为保持一致。
  • 将 PR 文本保留在文档同步 shell 步骤之外，并从检查的页面正确计算文档路径，以避免文档同步回归。
  • 修复各种 Google 同步和集成 CI 回归问题，并使 Google 同步清理安全。
  • 删除自我改进模块中的重复重写，并公开控制以记住自我改进。

技术变更

  • 新的/重写的可视化模块和图形流实现，以支持流 JSON 和有界邻域读取。
  • 在 SQL 中为图数据库实现有界邻域读取，以限制子图大小并避免大量查询。
  • 添加了大量新测试和 CI 工作流程（可视化、Google 集成、图形/邻域合约助手、文档分类自动化）。
  • Google Drive 和 Gmail 连接器的新任务实现和文档，以及示例指南和临时混合 cognify 演示。
