cognee v1.6.7

#v1.6.7

发布日期： 2026-11-06 变化： v1.6.6rc1 → v1.6.7

拉取请求： #6266、#6337、#6338、#6339、#6340、#6342、#6392、#6404、#6493、#6512、#6540、#6546、#6550、#6564

总结

此版本加强了摄取安全性并改进了搜索和检索的行为和执行方式。在提供系统文件或数据库连接信息时，您将看到更严格的保护措施、更正确的范围搜索（针对特定文档类型或命名空间的查询）以及更快、更高效的矢量搜索评分。

亮点

  • 更安全的摄取：默认情况下拒绝原始数据库连接字符串和不安全的服务器/文件路径，从而降低意外凭证或服务器暴露的风险。
  • 搜索和回忆正确性：类型化/范围查询（针对特定文档类型或范围的查询）现在返回正确的、LLM 安全的结果，并且“感觉幸运”选择忽略禁用的数据类型。
  • 检索性能：通过批处理和并行化评分工作，PGVector、Turso 和 LanceDB 后端的查询评分速度要快得多。
  • 各种稳健性修复：修复了 LanceDB 压缩/迁移、图形更新插入、会话/忘记操作以及 SDK 用户的导出标头。

重大变更

  • 数据库和远程路径的更严格的默认摄取：默认情况下拒绝通过 HTTP 的原始数据库连接字符串和服务器文件路径。影响：之前提取此类连接字符串的工作流程或连接器将开始提取失败。操作：检查文档中的摄取配置和显式选择加入控制，以允许这些源（如果您有意使用它们）。
  • ACCEPT_LOCAL_FILE_PATH 现在还控制 s3:// 输入：如果您依赖于之前对 s3:// URI 的许可行为，则可能需要设置 ACCEPT_LOCAL_FILE_PATH 或按照记录的选择重新启用这些输入。有关详细信息，请查看摄取 API 文档。

新功能

  • 列图锚点 (DLT)：向账本/图表存储添加一个新列，用于存储“图表锚点”（帮助将表行链接回图表的小指针）。它的作用：记录列写入的锚点信息，以便图形查询和下游进程可以更可靠地引用这些行。为什么重要：提高依赖于图形支持列和账本核对的工作流程的正确性和可追溯性。

改进

  • 更严格、更清晰的摄取处理：简化了摄取消息传递，系统现在对不安全的网络或数据库连接输入有一个拒绝规则，因此更容易理解文件或连接被拒绝的原因。为什么重要：减少敏感连接字符串或远程路径的意外摄入。
  • 范围和 LLM 的独立路由约束：决定哪些文档路由到语言模型 (LLM) 以及哪些文档按范围（文档类型或命名空间）路由的代码被重构为不同的规则。它的作用：使范围搜索和 LLM 路由行为更清晰、更可预测。为什么重要：当您仅针对特定文档类型或希望保持某些搜索不受法学硕士影响时，可以提高正确性。
  • 搜索和召回范围处理：类型化范围（表示“仅搜索类型 X 的文档”的查询）现在在块搜索和引用/范围查询中一致受到尊重，并且这些相同的引用短语避免了不必要的 LLM 路由。为什么重要：范围查询返回更准确的预期结果，并避免额外的 LLM 调用。
  • 更正文件摄取的错误代码：被禁止的请求现在返回 403 以及有用的消息，而不是 415。为什么重要：更清晰的错误处理有助于操作员更快地诊断权限和门控问题。
  • 在 SDK 导出上保留 OMP 标头：导出 SDK 工件（由 Cognee X / SDK 流使用）时，保留 OpenMP 样式标头。为什么重要：避免在 SDK 导出工作流程期间丢失配置/元数据。

性能

  • 跨后端批量评分：PGVector 和 Turso 现在在单个数据库语句中对整批查询进行评分，减少多查询请求的往返和延迟（实际影响：降低多查询检索的延迟）。
  • LanceDB评分优化：在LanceDB上通过一次id扫描即可对一批查询进行评分，并且多个查询的评分通过id并行进行。实际影响：使用 LanceDB 作为向量存储时，批量检索速度更快。
  • 在一次查找 PGVector 时跳过丢失的向量集合：减少集合不存在时的浪费工作。实际影响：在某些失败情况下，检索路径更快，查找次数更少。
  • 批量删除忘记/会话缓存：与会话相关的删除被批量删除以减少开销。实际影响：更快、更高效的大规模遗忘操作。

安全

  • 默认拒绝数据库连接字符串：默认情况下拒绝原始数据库连接字符串，以防止意外获取凭据。如果您有意提取数据库源，则必须明确选择加入（请参阅文档）。为什么重要：降低凭证摄入泄露的风险。
  • 拒绝包含 Cognee 凭据的连接字符串：服务器现在将拒绝包含产品自己的凭据的摄取尝试。为什么重要：防止意外的自引用连接和凭证重用。
  • 默认情况下拒绝通过 HTTP 的服务器文件路径：除非明确允许，否则将拒绝看起来像通过纯 HTTP 的服务器文件路径的输入。为什么重要：防止从 untrusted 服务器意外获取远程文件。
  • ACCEPT_LOCAL_FILE_PATH 还控制 s3:// 输入：控制是否接受本地文件系统路径的现有环境切换现在还控制摄取 API 中的 s3:// 样式输入。为什么重要：使文件路径门控在本地和 S3 样式源之间保持一致。
