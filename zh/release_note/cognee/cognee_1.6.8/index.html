cognee v1.6.8

发布日期： 2026-11-12 变化： v1.6.7 → v1.6.8

拉取请求： #5189、#6410、#6417、#6593、#6612、#6634、#6642

总结

此版本的重点是扩展和强化集成（新的 Slack 支持和许多连接器改进）以及为嵌入和数据更新构建可靠的后台工作。您将发现新的 Slack 连接器和应用程序、更好的 Google/Drive/Gmail/Calendar 连接器行为、基于 RabbitMQ 的嵌入工作选项以及许多可靠性和出处（审核）修复，以便您的导入、更新和删除行为更加可预测。

亮点

  • 添加了功能齐全的 Slack 连接器和 @cognee Slack 应用程序，以便可以直接从 Slack 询问和记住 Slack 消息。
  • 在 RabbitMQ 上引入了嵌入工作引擎，因此后台嵌入生成更加健壮和可扩展。
  • 改进了 Google 系列连接器（云端硬盘、Gmail、日历），包括处理旧文件格式和重试逻辑，从而减少跳过的文件。
  • 针对更新和来源的许多可靠性修复：更安全的文件锁定、并发安全删除以及更正确的审计（账本）写入以避免丢失或无序历史记录。

新功能

  • Slack 连接器和 @cognee 应用程序：一种新的集成，可将 Slack 工作区连接到 Cognee，让用户直接从 Slack 消息询问（搜索）和记住（保存）信息。为什么重要：您可以在不离开 Slack 的情况下与您的 Cognee 内存进行交互 - 提出问题、保存片段并在您的团队已经沟通过的地方获得答案。
  • 通过 RabbitMQ 嵌入工作引擎：添加了一个新的嵌入工作后端，该后端在 RabbitMQ（消息代理）上运行，以在后台生成向量嵌入（用于语义搜索的数字表示）。它的作用：将嵌入生成与主服务分离，以便它可以独立扩展并从工作器故障中恢复。为什么重要：大型或突发的摄取工作负载不会阻塞主要服务，并且可以更可靠地重试和分发嵌入工作。
  • Google Drive 连接器：更好地吸收旧版 Office 格式（旧的 .xls 和 .ppt 文件）并修复早期同步错过的文件。它的作用：读取和导入更多类型的云端硬盘文件，并重新考虑之前失败的文件。为什么重要：Google 云端硬盘丢失的文档更少，内容索引更完整。
  • Gmail 和日历连接器改进：更新了源代码和重试逻辑，使 Gmail 和 Google 日历摄取更加稳健。它的作用：改进我们调用 Google API 和处理瞬时故障的方式。为什么重要：从电子邮件和日历中更可靠地导入，无需手动重新运行。
  • POST /add 接受 dlt_config：add API 现在接受 POST /add 上的 dlt_config 参数，以在摄取期间传递增量同步选项。它的作用：允许调用者在添加数据时配置增量加载器。为什么重要：可以更好地控制文件在摄取过程中如何发现和处理。
  • 代理工具输出限制作为构造函数参数：代理检索器现在接受工具输出字符限制作为构造函数参数。它的作用：可以配置代理工具允许返回的文本量。为什么重要：您可以调整代理以避免输出过长或在需要时允许更长的答案。

改进

  • 更强大的更新/删除流程：更新任务现在同时批量删除已发布（已删除）的文件，以加快清理速度并减少锁争用。为什么重要：更新完成得更快，存储清理不太可能留下过时的文件。
  • 每个位置的存储文件锁定：修复并强化了更新期间如何按位置锁定存储文件，以便一个存储位置上的操作不会阻止其他存储位置。为什么重要：减少多个更新任务接触不同存储后端时的意外争用。
  • 来源/分类帐准确性：多项修复可确保来源分类帐（添加/更新/删除的审计跟踪）以安全顺序写入事件，仅记录数据行，保留回滚条目，并最后写入删除标记（逻辑删除）。为什么重要：审计跟踪更加准确，并且能够适应部分故障，这使得调试和数据恢复更加可靠。
  • 重试和 API 弹性：引入了 Google API 重试帮助程序，并使多个 API 调用更能容忍超时和暂时性故障。为什么重要：由短暂的 Google API 错误导致的同步失败更少。
  • 连接器元数据被带入块中：连接器标题和源元数据现在被复制到存储的有效负载和块有效负载中（块是用于搜索的文档的一小部分）。它的作用：将人类友好的源名称与存储的内容一起保存。为什么重要：搜索结果和出处可以显示返回内容的更清晰的来源。
  • 从源中去除 NUL 字符：系统现在在摄取过程中从所有文档源中去除 NUL 字符。为什么重要：防止由于文件中嵌入的 NUL 导致解析问题和文本损坏。
  • 测试和 CI 强化：多项测试和 CI 改进（工作流程修复、固定集成测试密钥），使发布和集成测试更加稳定和可预测。

性能

  • 并发删除已发布的文件：更新清理现在可以并行删除已删除的文件，这减少了更新期间清理存储所花费的总时间。
  • 用于增量遍历的专用池：增量文件遍历过程（dlt 遍历，更新期间使用的发现步骤）在其自己的工作池上运行，因此它不再与其他更新任务竞争线程，从而提高了大型同步的吞吐量。

错误修复

  • 云端硬盘：修复了先前同步跳过的云端硬盘文件未被重新摄取的情况；后续同步期间丢失的文件更少。
  • 添加/更新副本修复：停止删除由跳过的添加保存的副本，并确保新的副本
