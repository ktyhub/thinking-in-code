cognee v1.6.5

v1.6.5 — 更快的跟踪处理和更丰富的代码图文档

发布日期： 2026-10-16 变化： v1.6.4 → v1.6.5

拉取请求： #5287、#5534、#5620、#5622、#5720、#5721、#5722、#5725、#5726、#5751、#5798、#5898、#5938、#5955、#5958、#5961

总结

此版本加快了跟踪和摄取管道的速度，改进了会话处理，并使代码文档可以在代码图中进行搜索。它还添加了新的 memify API、更好的嵌入兼容性 (base64) 以及一些安全性和连接器强化。

亮点

  • 更快的跟踪处理：跟踪以更少、更大的操作进行持久化和处理，以实现更低的延迟和更少的数据库写入。
  • 代码图文档字符串：函数/类文档字符串存储为图形文档并链接到代码符号，以便更好地调用和搜索代码。
  • 新的 Memify API 端点：通过 API 将内容转换为内存条目，使摄取和下游调用更简单。
  • Base64 嵌入支持：请求嵌入编码为 Base64，提供商允许它提高兼容性并减少传输问题。
  • 安全和连接器：每日 CVE Slack 警报、Google 日历连接器强化以及改进的 OAuth/令牌共享。

重大变更

  • 数据模型代码生成器要求增加：如果您使用自定义 graph_model 生成步骤，则必须具有数据模型代码生成器 >= 0.56.0。该怎么做：在生成自定义图形模型时升级该依赖项以避免生成错误。

新功能

  • 在代码图中存储代码文档字符串：文档字符串（附加到函数、类和模块的文档字符串）现在保存为一流的图形文档，并链接到相应的代码符号。它的作用：当您提取代码时，人类可读的文档字符串会被索引并连接到代码符号节点。为什么重要：搜索和代码感知代理可以返回更丰富的、上下文感知的答案，并在代码引用旁边显示内联文档。
  • 新的 Memify API 和端点：“memify”是将内容（文件、消息或其他数据）转换为系统可以存储和调用的内存条目的过程。它的作用：我们添加了服务器端点和 CLI 接线，以直接通过 API 创建内存条目 (memify)。为什么重要：它简化了将原始内容转化为可搜索、可调用的记忆，用于调用和改进流程。
  • 请求支持 Base64 嵌入：一些嵌入提供程序接受编码为 Base64 的嵌入以避免二进制传输问题。它的作用：当提供商支持时，Cognee 将请求 Base64 编码的嵌入响应。为什么重要：提高与某些提供商的互操作性，并减少发送/接收二进制嵌入有效负载时的问题。
  • 将会话的跟踪积压保留为一个文档：跟踪是来自用户会话的交互记录（事件、步骤、日志）。它的作用：Cognee 现在可以将会话的待办事项保留为一个合并文档，而不是编写许多小型跟踪文档。为什么重要：减少数据库写入并提高高流量会话的吞吐量，从而加快摄取速度并降低资源使用率。
  • 在单个 cognify 运行中构建跟踪传递窗口：“cognify”是将原始跟踪转换为内存条目的管道运行。它的作用：一次传递的跟踪窗口是在一次 cogniify 执行中计算的，而不是多次运行。为什么重要：减少重复的管道运行并加快跟踪处理速度，使结果显示得更快、更一致。

改进

  • 会话/数据集绑定可靠性和速度：绑定会话（与特定数据集绑定的会话 - 您添加的文档集合）现在可以跳过不必要的重新读取，并将技能运行正确路由到绑定数据集。这减少了延迟并修复了一些边缘情况，其中陈旧或不匹配的绑定可能会导致错误。
  • 管理和蒸馏修复：每个管理批次都会密封蒸馏条目，并且默认情况下在每次蒸馏运行时都会管理新条目。这使得内存条目的自动过滤和质量控制更加一致。
  • 嵌入令牌跟踪：活动模型现在记录嵌入令牌的使用情况，以便您可以查看每个活动的嵌入成本。
  • Google 和 Azure 身份验证共享：Google 和 Azure 的 OAuth 和令牌提供程序代码已合并，因此集成可以重用相同的适配器，从而减少重复并改进维护。
  • 改进了蒸馏的内容选择：在蒸馏过程中仅读取所需的 QA 轮数，这减少了工作并加快了蒸馏过程。

性能

  • 更快的跟踪摄取：将会话跟踪积压保留为一个文档，并在每次运行时排出积压，减少数据库写入和管道改动，提高活动会话的吞吐量。
  • 减少认知运行：构建跟踪传递窗口并在一次运行中处理它们意味着更少的管道调用和更低的跟踪到内存转换的端到端处理时间。
  • 降低嵌入传输的开销：base64 嵌入支持可以减少传输问题并提高与某些提供商的兼容性，从而实现更顺畅的嵌入流程。

安全

  • 向 Slack 发送的每日 CVE 警报：新的 GitHub Actions 作业向 Slack 发送已知 CVE 的每日摘要，以便维护人员可以跟踪易受攻击的依赖项。
  • Google 日历连接器强化和共享 OAuth 适配器：多项修复提高了 Google 集成的稳健性和错误处理能力，并集中 OAuth 行为以降低安全风险。
  • 隐藏的 NATURAL_LANGUAGE 设置和修复指南：已从公共表面中删除安全敏感表面并设置修复路径。

错误修复

  • 排出每次运行的跟踪积压：修复了一个可能导致运行期间未处理跟踪的错误。
  • 支付错误破环：解决操作过程中发生支付错误时的死循环风险。
  • 拒绝过时的会话绑定，例如禁止的 ID：现在一致地拒绝过时或无效的会话到数据集的绑定，从而防止数据的静默错误路由。
  • 只读取蒸馏所需的 QA 回合：减少蒸馏过程中不必要的读取和潜在错误。
  • 接受键入条目上的字符串 dataset_id 并将键入条目路由到会话的数据集：修复了阻止某些条目正确绑定到数据集的问题。

技术变更

  • 跨 memify、improvement 和 cogniify 管道进行大型内部重构，以整合任务注册表、蒸馏阶段和图形更改操作。
  • 新的评估工具 (Locomo) 和许多测试/CI 工作流程更新（包括用于 CVE 警报和最新库检查的新工作流程）。
  • 添加了 Azure 托管标识支持并加强了 Litellm client 行为和类型。
