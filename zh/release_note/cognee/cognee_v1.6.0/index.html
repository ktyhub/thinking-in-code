cognee v1.6.0

v1.6.0 — 无钥匙工作流程和管道可靠性

发布日期： 2026-09-18 变化： v1.5.4rc1 → v1.6.0 拉取请求： #4920、#4994、#5106

总结

此版本使得在没有云 LLM 密钥的情况下运行 Cognee 变得更加可用和可预测，增强了管道启动和恢复行为，并完成了端到端图像/音频/嵌入模型的连接。它还引入了面向开发人员的集成工具，加强了遥测隐私，并修复了摄取、召回和 CLI 方面的众多错误。

亮点

  • 无密钥优先体验：宣布本地模型下载，许多流程现在无需 LLM 密钥即可干净运行。
  • 管道稳健性：管道运行在启动时进行标记，并在崩溃后可靠地恢复，保留完整的文档。
  • 模型连接：图像和音频转录模型端到端传递，并且每个数据集记录嵌入模型，以确保嵌入一致。
  • 遥测和隐私：数据集名称在离开主机之前会被指纹识别，并且错误遥测现在会报告完整的路线，以便更好地进行诊断。
  • 开发人员工具：Enola 的新 cognee-mcp client/server 和 CLI 内容改进了集成和测试工作流程。

重大变更

  • GLiNER 从默认 Docker 映像中删除 - 默认 Docker 映像不再捆绑 GLiNER 工具。如果您依赖标准映像中存在的 GLiNER，则必须将其添加到您的映像中或单独安装。
  • 数据库和适配器重构可能需要审查 - 重构了内部数据库和向量存储适配器（包括对 Postgres/混合适配器的更改）。自托管部署或自定义适配器集成应检查其配置和自定义适配器代码的兼容性。

新功能

  • 无密钥首次使用下载和通知 - 当您在没有云 LLM 密钥的情况下运行 Cognee 时，系统现在将宣布何时需要下载本地模型文件并解释发生的情况。这有助于首次用户了解本地模型活动并避免静默/阻止下载。
  • IMAGE_TRANSCRIBE_MODEL 连接 - 图像转录（将图像转换为文本）现在传递到负责图像处理的 LLM 适配器。这使得基于图像的上传和转录在端到端上表现一致。
  • 通过旧适配器提供音频和图像 LLM 支持 - 音频和图像模型选择现在通过旧适配器层连接，因此音频转录和图像任务将跨适配器一致地使用配置的模型。
  • 添加了 MCP client/服务器 (cognee-mcp) - 添加了新的 Python client/服务器包，以支持改进的外部集成和召回/摘要工作流程的端到端测试。该工具集可帮助集成商以编程方式与 Cognee 的召回/整理功能进行交互。
  • 记录每个数据集的嵌入模型 - 用于创建向量的嵌入模型现在记录在每个数据集上（数据集是您添加的文档的集合）。 Cognee 检查重用或更新嵌入时是否使用相同的模型，以防止可能降低搜索质量的静默不匹配。

改进

  • 更好的无密钥阶段处理 - 当没有 LLM 密钥时，需要 LLM 的管道阶段现在将干净地跳过，从而防止无密钥运行期间的部分故障和混淆错误。
  • 无密钥时跳过无密钥跟踪上下文提取 — 会话上下文提取在没有密钥的情况下运行时不再尝试提取 LLM 相关的跟踪数据，从而减少日志中的噪音和错误。
  • 在 add() 期间停止探测 LLM — 添加文档不再探测云 LLM 来检测可用性，从而提高响应能力并防止在摄取期间出现不必要的 LLM 请求。
  • 开始时的管道起源标记 - 管道运行在启动时标记其起源，以便后续诊断和恢复步骤可以准确地归因运行活动。
  • 对无法解析的数据集名称进行搜索/调用失败 - 如果无法解析数据集名称，搜索和调用现在会明显失败，而不是默默地进行错误的假设。
  • 范围代理提示召回主体到数据集 - 要求系统召回内容的代理提示现在明确限定到所请求的数据集，从而减少召回结果中的跨数据集泄漏。
  • 遥测：传递数据集 ID 和标记指纹 - 遥测事件现在包括数据集 ID（内部标识符）和指纹识别的标记名称，提高可观察性，同时减少原始名称泄漏。

性能

  • 更可靠的管道恢复 - 启动恢复现在可以保留被放弃的运行完成的文档，减少重复工作并提高崩溃后的恢复速度。
  • 减少不必要的 LLM 探测 - 通过避免在 add() 和无密钥运行期间进行 LLM 探测，摄取和本地流速度更快，并且更少依赖于外部 LLM 延迟。

安全

  • 用于遥测的指纹数据集名称 - 在遥测离开主机之前，对人类可读的数据集名称进行散列（指纹）。这可以降低收集遥测数据时的隐私风险，同时保留关联事件的能力。
  • 错误遥测包括完整的路由上下文 - 报告错误时，完整的 API 路由现在包含在遥测中，以加快调试速度，同时通过指纹识别保护敏感名称。

错误修复

  • 对齐数据集权限拒绝合约 - API 权限拒绝行为已得到纠正，因此 clients 获得一致且明确的权限错误。
  • 修复会话桥和会话层重构，以便会话在没有 LLM 密钥的情况下运行 - 多项修复确保会话相关功能不再需要云 LLM 密钥即可运行。
  • 每个数据集记录和检查一次嵌入模型 - 避免重复和不一致的嵌入模型检查，并防止嵌入/调用不匹配。
  • 使用 GLiNER 上传文件时不显示 LLM 密钥错误 — 使用备用上传工具的上传流程不再虚假报告丢失的 LLM 密钥错误。
  • 让路由标记在刷新时跟随内容 - 刷新内容时，路由起源标记跟随更新的内容，因此遥测和审计跟踪保持准确。
  • 当会话条目在 CLI 中领先时保留图形结果 — 如果会话条目是领先项目，CLI 调用现在会保留图形结果。
  • 通过适配器连接图像和音频模型 - 修复了之前的差距，以便图像和音频任务一致地使用配置的模型。
  • 修复各种测试不稳定和 CI 问题——固定或修复了许多测试和 CI 工作流程（Enola CLI、嵌套发布测试、平台查找）以稳定版本。
  • 修复召回路由和搜索类型跨度调用 - 检索/路由逻辑和跨度搜索类型调用已标准化，并解决了一些边缘情况错误。
  • 对无法解析的数据集名称进行失败搜索/调用 — 确保更清晰的错误并避免在数据集名称无效时出现意外结果。

技术变更

  • 会话和提示处理的大规模重构——会话层已被合并并移至用户提示表示中；用户/系统提示被拆分，并且几个会话持久模块被重新组织。
  • 主要“改进”子系统添加 - 添加了用于分阶段改进、结果折叠、门控和图形更改记录的新模块，以支持更丰富的自动化改进工作流程。
  • 检索和搜索返工 - 重新组织了检索代码路径（完成检索器、图形完成检索器、混合检索器），并添加了更清晰的 RecallScope 以进行会话感知召回。
  • 新的后台任务和管道操作 - 管道运行生命周期（启动、日志记录、错误处理、标记）和后台任务经过重构，以使运行恢复和诊断更加稳健。
  • MCP 和召回摘要的新测试和示例 - 添加了额外的测试和示例装置以涵盖新的 mcp 工具和召回/摘要行为。
