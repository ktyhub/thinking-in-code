cognee v1.6.2

v1.6.2 — 嵌入可靠性和 Slack 历史

发布日期： 2026-09-29 变化： v1.6.1 → v1.6.2

拉请求： #4932、#4951、#5146、#5196、#5231、#5235、#5236、#5240、#5241、#5242、#5247、#5250、#5251、#5274

总结

此版本的重点是使嵌入可靠且透明（不再有静默截断），添加了 Slack 对话导入和同步，并重新组织了“技能”的存储方式，以实现更好的跨平台工具。当嵌入失败时，您将看到更清晰的错误，基于模型令牌限制的更安全的块大小调整，以及更新的 CLI/docs 以匹配这些行为。

亮点

  • 嵌入修复可防止按每个模型的令牌限制进行静默截断和大小块，以便您的内容完整且一致地嵌入。
  • Slack 集成：将对话历史记录从 Slack 导入并持续同步到 Cognee。
  • 技能已移至新的 .agents/skills 位置，并提供 Windows 链接支持和链接失败时的恢复。
  • 对于不可恢复的嵌入错误，更好的错误和更快的失败 - 您将看到真正的原因，而不是不透明的消息。
  • CLI 和文档已刷新（包括数据库迁移/命令和 Docker 快速入门身份验证修复）。

重大变更

  • 技能路径更改：内置和打包技能现在位于 .agents/skills 下（从之前的位置移动）。如果您维护引用旧路径的自定义脚本、自动化、构建挂钩或 CI，请将它们更新为 .agents/skills。添加了一个小帮助程序脚本 (link-skills.sh) 和一个 Windows 挂钩来协助链接。
  • env_file 从设置中删除：自动加载 env_file 的运行时设置已被删除。如果您依靠该行为通过设置文件加载环境变量，请在启动脚本中切换到显式 env 加载器或使用新添加的共享/env_file 帮助程序（有关示例，请参阅文档/测试）。

新功能

  • Slack 对话导入和同步 — 导入 Slack 对话历史记录并使其与 Cognee 保持同步的新集成。这会将频道和线程消息拉入您的数据集，以便搜索和内存功能可以使用 Slack 内容。为什么重要：您可以从历史 Slack 数据中构建记忆、搜索和摘要，而无需手动导出。
  • 按模型输入限制调整块大小 - 系统现在测量每个嵌入模型的输入限制（模型接受的最大标记数），并将文本拆分为大小达到该限制的块。它的作用：分块不再依赖于固定的启发式；它尊重实际模型/标记器限制以避免意外截断。为什么重要：搜索和记忆将更加完整和一致，因为文档在发送到嵌入模型时不会被悄悄缩短。
  • 技能目录重组 (.agents) 和 Windows 链接挂钩 — 技能（自动代理脚本和示例）从旧位置移至新的 .agents/skills 目录，并添加了 Windows 友好的挂钩用于链接。它的作用：标准化内置技能的位置，并使链接过程在 Windows 上运行。为什么重要：跨平台安装、链接和运行技能的工作流程更简单、更一致。

改进

  • 强大的嵌入输入限制解析 - 即使未安装可选的标记生成器库（如转换器），SDK 现在也可以解析模型的输入限制，并在适当的情况下异步执行此操作。这减少了启动意外并改进了轻量级安装的行为。
  • 跨标记器的准确标记计数 - 标记计数现在使用每个提供商的标记器（包括 HuggingFace 标记器（如果可用）），并且模型自己的特殊标记包含在计数中。它的作用：改善块大小并防止一些标记的截断。
  • Fastembed 批量填充 - 发送到快速嵌入后端的批次现在被填充到批次中最长的文本，以避免不一致的批次级截断。结果：发送混合长度输入时，静默截断更少，嵌入更可预测。
  • 更清晰的嵌入错误和快速失败行为 - 嵌入失败现在显示根本原因（而不仅仅是通用消息），并且终端错误会快速停止重试。为什么重要：当外部提供商或配置错误时，您可以更快地调试和恢复。
  • 在失败时恢复技能链接并在没有密钥的情况下验证链接 - 技能的链接过程更加稳健：部分失败尝试恢复链接，并且链接检查工作流程可以在没有密钥的情况下运行。这减少了脆弱的操作并使 CI 检查更简单。
  • CLI 文档和行为更新 — CLI 文档已得到扩展和澄清（数据库迁移命令、新示例、内存命令注释）。 Docker 快速启动 401 陷阱已得到改进，因此在缺少身份验证时快速启动可以正常运行。

性能

  • 更可靠的嵌入吞吐量 - 通过填充快速嵌入批次并将块大小调整到模型输入限制，嵌入可以避免用于降低有效吞吐量/质量的静默截断。这提高了混合长度输入的可用嵌入的实际吞吐量。
  • 在轻量级设置中更快地检测嵌入限制 - 输入限制解析现在可以在没有重量级分词器依赖性的情况下工作，并且可以异步解析，从而减少嵌入初始化期间的延迟。

安全

  • Docker 快速入门 401 处理 - Docker 快速入门和相关文档已修复，以避免令人困惑的 401 陷阱，现在提供更清晰的身份验证指南。

错误修复

  • 标记的可选变压器正确导入以进行类型检查，因此可选依赖项在安装过程中表现干净。
  • 使用标记器正确计算 HuggingFace 标记（避免使用不同标记器代码路径时出现错误计数）。
  • 即使未安装变压器，也会读取模型的输入限制，从而防止导致错误块大小的静默回退。
  • 忽略之前保存的截断/填充元数据，这些元数据可能会破坏未来的块大小决策。
  • 清除失败时恢复技能链接（链接恢复以避免技能安装损坏）。
  • 从运行时设置中删除了 env_file 设置以避免出现意外行为（请参阅重大更改）。
  • 记录委托 CLI 命令失败的完整回溯，以便更容易诊断错误。
  • 更改了数据库修剪的顺序以修复边缘情况删除排序错误。

技术变更

  • 重构将 input_limit() 嵌入到引擎接口中，并将每个限制查找与其提供者一起保留，以使限制解析可插入。
  • 删除了 fastembed 中的无操作重新加注和简化的重试谓词分类，以干净地处理丢失的嵌入 SDK。
  • 重构分词器排序保护（删除了火炬前的变压器）并添加了保护测试以防止导入顺序和填充行为的回归。
  • 大量测试和示例添加：添加或扩展了许多端到端、单元和旅程测试（嵌入限制、松弛历史记录、分块、旅程），以及新的 company_brain 多源演示和扩展的 CI 工作流程。
  • 文档和技能：大量文档更新（AGENTS.md、技能文档、迁移指南、自述文件对齐）以及 Python 技能示例的格式修复。
