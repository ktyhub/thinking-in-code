ms-swift v4.6.1

修订 发布时间2026年11月13日 来源modelscope/ms-swift 英文原文

ms-swift v4.6.1

#v4.6.1

新型号

  • NVIDIA-Nemotron-3.5-Super-VL-120B-A12B(#10377)
  • NVIDIA-Nemotron-3.5-Transcribe-30B-A4B(#10458)
  • 无限-OCR-2(#10448)
  • MiniCPM-OCR-1.0(#10414)
  • Olmo-3-7B-思考(#10371)
  • 燧石(#10482)
  • EmbeddingGemma-2(#10392)
  • Decision / System-1 系列：THX-02 (#10398)、kev-0.8b/4b/9b (#10407)、laya (#10445) 和 StartLux-Decision-v1.1 4B/9B/27B-自动思考 (#10479)。

决策任务（类型决策/JEV 系列）

  • 四个新的决策头，带有模板、对齐测试和 examples/train/decision/*.sh 配方：THX-02 (#10398)、jaredpalmer/kev-* 指针头 (#10407)、Laya (#10445) 和 StartLux (#10479)。
  • 吞吐量：Clef/Kev 得分头的整批转发 (#10551) 和 Kev 的多问题转发 (#10494)。
  • 正确性和校准：两阶段 JEV 温度校准回调 (#10399)、为确信错误的预测保留的梯度 (#10355)、具有纯文本数据的多模态基本模式 (#10420)、注入的输出嵌入保留在头模块树之外 (#10540)。
  • THX-02 特定的包装检查被 ModelMeta 上的通用 support_padding_free 标志取代 (#10480)。
  • docs/*/BestPractices/Decision.md 重写为家庭的入口点。

新功能和兼容性

  • Entropack 灵活量化，用于 QLoRA 式训练，带有新的最佳实践文档 (Flexble-Quantization-With-Entropack.md) 和 examples/train/qlora/entropack.sh。 (#10415)
  • Megatron 并行参数预检：在进程组初始化之前，在 Swift 参数入口点检查 TP/PP/CP/EP/ETP 整除性，并提供可操作的错误消息；变形金刚后端和威震天导出路径保持不变。 (#10393)
  • Gemma 4：打包 / padding_free 用于威震天后端的纯文本数据。 (#10542)
  • 华为 Ascend：威震天训练迁移到威震天-Core 0.18 和 MegatronAdaptor + TENPU (#10087)；独立环境检查脚本 examples/ascend/check_env.py (#10390)。

威震天-SWIFT 和 MTP

  • --mtp_num_layers 现在默认为 auto 并遵循模型检查点； --mtp_shared_weights 默认为自动检测（当检查点持有的 MTP 层数少于配置的深度时启用）。要将 MTP 添加到不附带 MTP 的基本模型，请设置 --mtp_num_layers N --mtp_allow_random_init true。 （#10416，需要 mcore-bridge >= 1.7.0）
  • 针对最新的威震天开发分支修复了异步检查点导入。 (#10421)

性能

  • selective_log_softmax 分块而不是按令牌循环。 (#10337)
  • 减少了 SFT 中的自定义和分块交叉熵工作。 (#10353)
  • 降低威震天训练中的 NPU 梯度、RMSNorm 和 MoE 排列开销。 (#10513)

安全

  • 在检查点的 args.json 中声明的 external_plugins 不再在恢复时以静默方式恢复。 (#10422)
  • 检查点引擎中 ZMQ 控制消息的 HMAC 身份验证，抽象为涵盖 HCCL 和 NCCL 传输。 （＃10373，＃10381）
  • load_file 现在在打开本地媒体路径之前应用 SafeMediaPath，因此不能再通过模板图像/音频加载绕过 SWIFT_MEDIA_ALLOWED_DIRS。 (#10370)

错误修复

  • RL：异步服务器推出期间保留 SP 状态 (#10426)；通过收集/缓存部署记录进行 GRPO 日志记录 (#10427)； overlong_filter 在 Liger 失败中获得荣誉 (#10404)；跨动态块保留策略梯度（#10397）；在多模态 Liger 损失中重用前向钩子输出 (#10411)；长度奖励超出配置的最大值（#10500）； PPO 回调（#9872）；服务器模式推出现在将 max_length / truncation_strategy 发送到引擎并根据训练模板对其进行验证，因此提示截断与引擎预填充相匹配 (#10549)。
  • 对齐损失：DPO 中的 alpha 发散溢出 (#10394)、稳定的 DiscoPOP 调制指数 (#10313)、EXO 平滑保持本地损失 (#10323)、BCO 运行统计在评估期间保持不变 (#10321)、MuonClip Nesterov 更新顺序 (#10341)。
  • 模板/代理：具有工具模式的代理模板（#10522），在跨代理格式的工具结果后接受用户轮次（#10523），附加用户后续操作时每次关闭（#10524），GLM-5-Next 模板（#10509），包含引号或换行符的 Gemma 4 工具调用参数（#10456），在 load_image 中合成到白色的透明图像（＃10345）。
  • 数据和指标：独立于恢复历史记录的惰性数据集回退（#10375），分布式均值累加器保留在本地（#10326），循环列表拆分中保留的项目（#10324），numpy 标量保留在训练日志之外（#10474）。
  • 基础设施：加载配置时绕过 vLLM 的 AutoConfig 覆盖 (#10503)，导出后保留最终的 GPTQ 检查点格式 (#10425)，NPU RNG 状态检查点与 CUDA/MUSA 一起设置 (#10406)，SP 数据加载器和 num_input_tokens 会计对齐 (#10508)。
  • 文档：调整 Megatron-Core / mcore-bridge 版本要求（#10526），更正 Qwen3.8-Flash-Next 参数核算（#10428），NPU 命名统一为“华为 Ascend NPU”（#10496），刷新 NPU 指南（#10356）。

环境变化

megatron-core >= 0.18（原为 >= 0.16）。（#10481、#10087）

deepspeed >= 0.19.3,< 0.20（原为 < 0.19）。

transformers < 5.23（原为 < 5.20）。 (#10453)

**`mcore-桥 >= 1.7.0
