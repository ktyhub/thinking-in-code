peft v0.21.0

peft v0.21.0

亮点

新方法

黎曼前提条件 LoRA 优化器

黎曼预处理 LoRA 优化器 (#3382)，由 @smellslikeml 贡献，是一种新的 LoRA 特定优化器，类似于 LoRA-FA 或 LoRA+，它对梯度应用黎曼预处理，以改进特征学习，并避免单独调整 LoRA 的 A 和 B 矩阵的学习率。

LoRA 变体：知识感知奇异值适应（KaSA）

KaSA 旨在从基本权重中识别知识感知奇异值。然后，它从这些权重中删除噪声知识，并专门训练与任务最相关的奇异值。由@robbiebusinessacc 和@iambogeumkim 在#3446 中实现。

超级调整 (#3518)

超级调整 使用免校准幅度评分来分配稀疏调整预算。通过 BottomK 选择，Super 适应了低幅度权重，其动机是它们为学习新任务提供了自由度，同时保持较大幅度的预训练权重不变。 Supra 在这个稀疏更新的基础上添加了 LoRA。它非常适合探索稀疏性和更高阶的适应，特别是在推理繁重的微调任务上。感谢@smellslikeml。

ShadowPEFT (#3354)

ShadowPEFT 在冻结的基础模型旁边运行一个小型影子网络。 该影子状态在每个解码器层都会更新，因此适应在整个堆栈中共享，而不是在每个目标线性层（如 LoRA）上进行单独的低秩更新。当您关心下游或 OOD 性能并希望保持与 LoRA 相同的可训练参数范围时，或者当您想要边缘上的小阴影和云中的冻结基础时，这是一个不错的选择。如果影子模型是从一个小的预训练模型开始的，那么这种方法效果最好。由@SeanLee97 贡献。

增强功能

  • 加速 MoE 目标参数计算 (#3577)：对于一个有源适配器的常见用例，重量和 MoE LoRA 增量计算被折叠到单个 baddbmm 操作中。在这种情况下，预计会有轻微的数值差异。

  • 通过支持较新的 Int8Tensor、Float8Tensor 等张量子类来支持 torchao v0.18.0。

  • 正交子空间微调 在 #3524 中进行了重大更新，根据 MetaMathQA 基准，内存占用量减少了 22%，训练时间减少了 46%，同时保持任务准确性和遗忘稳定。预计会有轻微的数值差异，尤其是在 fp16、bf16 中。

  • https://github.com/huggingface/peft/pull/3639: 感谢@amogh-nagri-11，提示学习方法现在允许删除适配器。对于适配提示，添加或加载第二个适配器不再自动激活它，这与其他 PEFT 方法处理此问题的方式一致。

变化

重构状态字典处理 (#3490)

内部更改将状态字典加载/保存特定于方法的代码路径移动到相应的调谐器。这对最终用户来说应该是透明的，并且经过了广泛的测试，并且工作原理应该与以前完全相同，但如果您怀疑模型的行为不同，请告诉我们。

在注入过程中保留适配器的可训练性 (#3495)

以前，当加载或添加第二个、第三个等适配器时，这可能会影响现有适配器（或基本模型）的 requires_grad，具体取决于 is_trainable 的值。感谢@DaoyuanLi2816，这种情况应该不再是这样了。

LoRA 适配器组合的错误修复 (#3111)

使用 add_weighted_adapter 组合 LoRA 适配器在 SVD 路径中存在错误，导致 LoRA 缩放应用两次。现在这个问题已经解决了。

OFT 使用通用量化后端 (#3355)

我们将 OFT 从特定于方法的量化后端转移到通用量化后端。这会影响bitsandbytes、GPT-Q等。这不会影响现有的检查点，但如果您遇到问题，请告诉我们。

对适配器处理进行更严格的检查

  • #3667：inject_adapter_in_model 现在拒绝具有存在于父模型（如 VeRA）上的共享状态的 PEFT 方法，因为不存在这样的父模型。由@CoralGarden52 贡献。

  • #3534：感谢 @LK-maker-007，现在，当使用针对不存在层的 add_adapter 将第二个适配器添加到 PEFT 模型时，PEFT 会抛出错误。以前，适配器不会适应任何东西，只是保持沉默。 peft_model.targeted_module_names 和 peft_model.targeted_parameter_names 不再包含重复项。它们仍然按插入顺序（而不是集合）排序。要抑制潜在错误，请捕获 peft.PeftError。

  • #3504：删除适配器时，现在会检查适配器是否已合并。如果合并，则会引发错误，因为删除它不会消除其效果。这是@DaoyuanLi2816 贡献的。
