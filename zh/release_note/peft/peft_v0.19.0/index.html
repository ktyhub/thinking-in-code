peft v0.19.0

亮点

此 PEFT 版本包含不少于九种新的 PEFT 方法，如下所述。它还包含许多增强功能，使 PEFT 对许多用户更有用。

新方法

格拉洛拉

@yeonjoon-jung01 添加了 “GraLoRA：用于参数高效微调的粒度低阶适应” 到 PEFT (#2851)。该方法将基本权重细分为更小的块，并将 LoRA 应用于这些块。这种更细粒度的适应有望提高表现力并提高性能，尤其是在更高级别（64+）时，缩小与全面微调的差距。

BD-LoRA

@Conzel 贡献了 BD-LoRA：“用于消除张量并行 LoRA 服务中的通信开销的块对角 LoRA” (#2895)。对于 BD-LoRA，LoRA 权重以块对角线方式实现。这可以减少使用张量并行性 (TP) 时的通信开销，从而加快服务速度。

vLLM 中有一个支持 BD-LoRA 的实验分支：vllm-project/vllm#28136。

墨盒

感谢 @kashif，PEFT 现在还支持 Cartridges (#2953)。此方法的主要目的是训练前缀以将长上下文压缩为短大小，从而节省令牌。在低级别上，这类似于前缀调整。 PR 还添加了一个示例配方 以快速入门。

PVeRA

“PVeRA：基于概率向量的随机矩阵适应” 由 @leofillioux 在 #2952 中添加到 PEFT。它是 VeRA 的扩展，这是一种 PEFT 方法，利用层之间的权重共享来提高参数效率。 PVeRA 在此基础上添加了概率元素，从共享参数中进行采样，并承诺提供更好的整体性能。

普软件

@fei407 在 #3037 中向 PEFT 添加了 PSOFT，“具有主子空间自适应的高效正交微调”。 OFT 和 BOFT 等正交微调技术擅长保留结构，从而保留底层基础模型的功能。 PSOFT 通过限制对低秩主子空间的适应来提高该技术的效率。

莉莉

@yibozhong 在 #2563 中向 PEFT 添加了 Lily：“跨层低阶互连适应”。 Lily 表面上与 LoRA 类似，但具有复杂的参数共享方案。 A 参数按块共享（例如，4 个连续的 q_proj 层共享相同的 A）。有一个全局共享的 B 参数池，实际的 B 是通过路由器以数据相关的方式选择的。这使得 Lily 能够使用比 LoRA 更高的等级，同时保持较低的可训练参数数量。

花生

在 #3084 中，“PEANuT：具有重量感知神经调整器的参数高效适应” 再次由 @yibozhong 添加到 PEFT。 PEANuT 在基础模型中添加了一个小型神经网络（所谓的权重感知神经调整器）。与 LoRA 相比，这增加了相同可训练参数数量的表达能力，或者允许在不牺牲表达能力的情况下大大降低参数数量。这是以相同的参数数量需要更高的内存以及降低速度为代价的。

小洛拉

我们还有另一位连续贡献者 @kashif，他也在 #3024 中贡献了 TinyLoRA：“学习 13 个参数的推理”。这是一种 PEFT 方法，允许训练极少量的参数，远低于 LoRA 1 级所能达到的参数。论文表明，特别是在强化学习中，通常只需训练几个参数即可获得良好的结果。

阿达MSS

@LonglongaaaGo 在 PEFT 中添加了 “AdaMSS：用于参数高效微调的自适应多子空间方法”。该方法将模型的基本权重分割成更小的子空间，以进行微调。此外，可以在训练期间动态地将较低的参数预算分配给不太重要的子空间，类似于 AdaLoRA 的做法。与类似的 PEFT 方法相比，这有望提供更高的表达能力和更好的泛化能力。

增强功能

将非 LoRA 适配器转换为 LoRA

在#2939中，我们向 PEFT 添加了函数，以允许将许多非 LoRA 方法的检查点转换为 LoRA 检查点。这可能很有用，因为许多其他软件包仅支持 LoRA，但不支持其他 PEFT 方法，例如扩散器 和 vLLM。借助新的转换工具，这些软件包可以使用更多的 PEFT 方法，而不仅仅是 LoRA。转换是有损的，但经验测试表明，如果 LoRA 等级足够高，误差可能会相当低。

洛拉-GA

@sambhavnoobcoder 添加了一种使用 “LoRA-GA：梯度近似的低阶自适应” (#2926) 初始化 LoRA 权重的新方法。这允许您以一种通过完全微调来对齐梯度的方式初始化 LoRA 权重，并且应该会导致更快的训练收敛。

减少入侵者尺寸

在“LoRA vs Full Fine-tuning：An Illusion of Equivalence”中，作者表明LoRA微调可以引入所谓的“入侵者维度”，从而导致遗忘。我们现在在 PEFT、reduce_intruder_dimension 中有一个删除入侵者维度的实用函数。当在微调的 LoRA 模型上调用此方法时，应该减少遗忘，同时微调的任务性能应保持几乎相同。

变压器引擎

在 #3048 中，@balvisio 在 PEFT 中添加了对 Transformer Engine（NVIDIA 的一种量化方法）的支持。

张量并行支持

在一系列 PR（#3079、#3091、#3096）中，@michaelbenayoun 添加了对 LoRA 张量并行 的支持。

重量绑定改进

在许多 LLM 中，嵌入和 LM 头都绑定了权重以节省参数数量。然而，在尝试微调这些层时，这可能会导致棘手的情况。通过一系列 PR（#2803、#2922、#2870、#2879、#3126），我们改善了用户体验。最值得注意的是，用户现在可以将 ensure_weight_tying=True 传递到他们的 PEFT 配置，以强制支持权重绑定。请检查 PEFT 权重绑定文档 了解权重绑定现在的处理方式。感谢 @romitjain、@sambhavnoobcoder 和 @Cursx 的贡献。

低精度浮动类型支持

#3055 使 LoRA 能够与使用 torch.float8_e4m3fn 等精度非常低的浮点数的基本模型配合使用。 MiniMax-M2.5 就是一个例子。

PrefixTuning 的零初始化

#3128 向前缀调整引入了零初始化，根据我们的基准测试，它显着降低了结果方差，并产生了良好的任务准确性，而无需立即进行工程设计。

LoftQ + int8 量化

通过#3088，LoftQ 实现现在支持纠正 int8 量化的错误，而无需在现有的 nf4 量化旁边使用激活阈值。

变化

去除骨头

骨 PEFT 方法在 #3115 中被删除。用户被指示使用 MiSS，这是 Bone 的改进替代品。如果您想移植旧的 Bone 检查点，请使用此 Bone 到 MiSS 转换脚本。

AutoGPTQ 和 AutoAWQ

感谢 @ZX-ModelCloud，这两种量化方法现在使用 GPTQModel 作为后端 (#2932)。

modules_to_save 中 requires_grad 的处理

以前，如果相应的 modules_to_save 被禁用，PEFT 会在原始模块上启用 requires_grad。这几乎是不可取的，因此被修复。尽管此更改在技术上向后不兼容，但这是一个极端的小众案例，因此我们不希望任何用户受到它的负面影响。
