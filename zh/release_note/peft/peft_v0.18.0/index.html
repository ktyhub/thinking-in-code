peft v0.18.0

亮点

FIXME 更新了所有更改的列表，因此添加了更多提交

新方法

道路

@ppetrushkov 在 #2678 中向 PEFT 添加了 RoAd：2D 旋转适应。 RoAd 学习仅使用元素乘法应用的 2D 旋转矩阵，因此有望在未合并状态下使用适配器进行非常快速的推理。

值得注意的是，除了 LoRA 之外，RoAd 是唯一支持_混合适配器批次_的 PEFT 方法。这意味着，当您加载具有多个 RoAd 适配器的模型时，您可以将它们全部用于同一批次中的不同样本，这比在批次之间切换适配器要高效得多：

model = PeftModel.from_pretrained(base_model, <path-to-road-adapter-A>, adapter_name="adapter-A")
model.add_adapter("adapter-B", <path-to-road-adapter-B>)

inputs = ...  # input with 3 samples
# apply adapter A to sample 0, adapter B to sample 1, and use the base model for sample 2:
adapter_names = ["adapter-A", "adapter-B", "__base__"]
output_mixed = model(**inputs, adapter_names=adapter_names)
gen_mixed = model.generate(**inputs, adapter_names=adapter_names)

阿洛拉

激活的 LoRA 是 @kgreenewald 在 #2609 中为因果语言模型添加的一项技术，允许根据输入中的特定令牌调用序列有选择地启用 LoRA 适配器。这样做的主要好处是，当适配器仅用于生成部分响应时，能够在推理期间重用大部分 KV 缓存，之后基础模型再次接管。

Arrow 和 GenKnowSub

@TheTahaaa 不仅贡献了对 Arrow（#2644 中多个加载的 LoRA 之间的动态路由算法）的支持，还贡献了 GenKnowSub，这是一种基于 Arrow 构建的技术，其中 Arrow 可用的 LoRA“库”首先通过减去通用知识适配器（例如，在维基百科子集上进行训练）进行修改，以增强特定于任务的性能。

波FT

感谢@Bilican，小波微调 (WaveFT) 被添加到 #2560 中的 PEFT 中。该方法在残差矩阵的小波域中训练稀疏更新，参数效率特别高。它对于图像生成非常有趣，因为它有望在保持主题保真度的同时生成不同的输出。

德洛拉

解耦低阶适应 (DeLoRA) 由 @mwbini 在 #2780 中添加。这种新的 PEFT 方法与 DoRA 类似，因为它解耦了学习到的适配器权重的角度和大小。然而，DeLoRA 实现这一点的方式有望更好地防止分歧。此外，它通过施加范数上限来限制学习权重的偏差，范数上限可以通过 delora_lambda 参数进行调整。

OSF

正交微调 (OSF) 由 @NikhilNayak-debug 在 #2685 中添加。通过冻结目标权重矩阵的高秩子空间并将梯度更新投影到低秩子空间，OSF 在持续学习任务上取得了良好的性能。虽然对于标准的微调过程来说，它有点占用内存，但对于那些担心先前学习的任务性能下降的任务来说，绝对值得检查。

增强功能

文本生成基准

在#2525 中，@ved1beta 将文本生成基准 添加到 PEFT。这是一个框架，用于确定和比较不同 PEFT 方法的文本生成指标，例如运行时间和内存使用情况。目前，该基准测试仍然缺乏实验设置和可视化，类似于我们在 MetaMathQA 基准测试 中的情况。如果您对此感兴趣，我们鼓励您让我们知道，或者更好的是，为这个基准做出贡献。

可靠的集成接口

PEFT 与其他库集成，例如 Transformers 和 Diffusers。为了促进这种集成，PEFT 现在提供了一个稳定的函数接口，如果适用，应该使用它。例如，set_adapter 函数 可用于在模型上的 PEFT 适配器之间切换，即使模型不是 PeftModel 实例也是如此。我们致力于保持这些函数向后兼容，因此其他库可以安全地在这些函数之上构建。

重量捆绑的处理

一些变形金刚模型可以有绑重。当涉及嵌入和 LM 头时，这种情况尤其普遍。目前，PEFT 中处理此问题的方式并不明显。因此，我们起草了一个问题来说明 #2864 中的预期行为。这表明了我们的目标是什么，尽管还没有一切都实现。

在#2803 中，@romitjain 将 ensure_weight_tying 参数添加到 LoraConfig。如果此参数设置为 True，则会强制以 modules_to_save 为目标的模块的权重绑定。因此，如果嵌入和 LM head 绑定，它们将共享权重，这对于允许权重合并等非常重要。因此，对于大多数用户来说，如果他们想要完全微调嵌入和 LM 头，我们建议启用此设置。为了向后兼容，该设置默认处于关闭状态。

请注意，根据#2864，ensure_weight_tying=True 的功能将来还将扩展为包括可训练代币（#2870）和 LoRA（待定）。

支持 LoHa 和 LoKr 中的 Conv1d 和 1x1 Conv2 层

@grewalsk 在 #2515 中扩展了 LoHa 和 LoKr 以支持 nn.Conv1d 层以及具有 1x1 内核的 nn.Conv2d。

新提示调整初始化

感谢@macmacmacmac，我们现在有了一个新的初始化选项，用于提示调整，随机离散初始化（#2815）。正如我们的 PEFT 方法比较套件 所证实的那样，此选项通常应该比随机初始化效果更好。如果您使用提示调整，请尝试一下。

将 LoRA 适配器与负权重相结合

如果您使用多个 LoRA 适配器，可以使用 model.add_weighted_adapter 将它们合并为一个适配器。然而，到目前为止，这仅适用于每个适配器的正权重。感谢@sambhavnoobcoder 和@valteu，现在也可以传递负权重了。

变化

变形金刚兼容性

在撰写本文时，变形金刚 v5 即将发布。此变形金刚版本与 PEFT < 0.18.0 不兼容。如果您计划将 Transformers v5 与 PEFT 一起使用，请将 PEFT 升级到 0.18.0+。

Python版本

此 PEFT 版本不再支持 Python 3.9，该产品已达到其使用寿命。请使用Python 3.10+。

OFT 更新

OFT 方法 已更新，使其速度稍快并稳定 #2805 中的数字。然而，这意味着升级到 PEFT 0.18.0 后，现有检查点可能会给出略有不同的结果。因此，如果您使用 OFT，我们建议重新训练适配器。
