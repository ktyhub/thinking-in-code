peft v0.17.0

peft v0.17.0

亮点

新方法

希拉

@kkb-code 贡献了稀疏高阶适配器（SHiRA，论文），它承诺比 LoRA 提供潜在的性能增益 - 特别是使用多个适配器时的概念损失得到了改善。由于适配器仅在 1-2% 的权重上进行训练，并且本质上是稀疏的，因此适配器之间的切换可能比 LoRA 更便宜。 (#2584)

密苏里州

@JL-er 在#2604 中添加了一种新的 PEFT 方法 MiSS（Matrix ShardSharing）。此方法是 Bone 的演变，根据我们的 PEFT 方法比较基准，该方法在性能和内存效率方面给出了出色的结果。如果您还没有尝试过，那么现在就应该尝试一下。

同时，Bone 将被弃用，取而代之的是 MiSS，并将在 PEFT v0.19.0 中删除。如果您已有 Bone 检查点，则可以使用 scripts/convert-bone-to-miss.py 将其转换为 MiSS 检查点并继续使用 MiSS 进行训练。

增强功能

nn.Parameter 的 LoRA

LoRA 现在能够直接瞄准 nn.Parameter（#2638、#2665）！您是否曾经拥有过这种复杂的 nn.Module，内部参数很有前途，但它过于定制，无法得到您最喜欢的微调库的支持？不用担心，现在您可以使用 target_parameters 配置属性直接定位 nn.Parameters，其工作方式与 target_modules 类似。

此选项对于具有 Mixture of Expert (MoE) 层的模型特别有用，因为这些模型通常直接使用 nn.Parameter，并且不能以 target_modules 为目标。例如，对于 Llama4 系列型号，使用以下配置来定位 MoE 权重：

config = LoraConfig(
    ...,
    target_modules=[],  # <= prevent targeting any modules
    target_parameters=["feed_forward.experts.down_proj", "feed_forward.experts.gate_up_proj"],
)

请注意，此功能仍处于实验阶段，因为它有一些警告，因此将来可能会发生变化。此外，许多专家的 MoE 权重可能相当大，因此与针对普通 nn.Linear 层相比，预计内存使用量会更高。

注入基于 state_dict 的适配器

有时，可能存在 PEFT 适配器检查点，但由于某种原因不知道相应的 PEFT 配置。要为此检查点注入 PEFT 层，您通常必须根据检查点中的 state_dict 对相应的 PEFT 配置进行逆向工程，尤其是 target_modules 参数。这可能很麻烦并且容易出错。为了避免这种情况，还可以调用 inject_adapter_in_model 并将加载的 state_dict 作为参数传递：

from safetensors.torch import load_file
from peft import LoraConfig, inject_adapter_in_model

model = ...
state_dict = load_file(<path-to-safetensors-file>)
lora_config = LoraConfig()  # <= no need to specify further
model = inject_adapter_in_model(lora_config, model, state_dict=state_dict)

在文档中查找有关 state_dict 基于注入 的更多信息。

变化

兼容性

提示学习方法中的一个错误导致modules_to_save被忽略。特别是分类任务受到影响，因为它们通常将分类/评分层添加到 modules_to_save。因此，这些层既没有经过训练，也没有在训练后存储。现在这个问题已经得到纠正。 (#2646)
