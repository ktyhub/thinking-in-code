LocalAI 4.11.0 出来了！

此版本使 LocalAI 对于音频理解、弹性模型服务、结构化决策和日常操作更加有用。音频场景现在可以结合转录、分类、声音检测和记住的说话人姓名。有序的故障转移链使公共模型在本地和远程目标上可用，而新的 Studio 和操作页面无需分布式模式即可公开这些功能。

该版本还通过 /v1/systemone、签名的 OCI 模型库和 Kimodo 文本转动画添加了一流的决策模型。它包括 243 个合并的拉取请求、353 个提交、79 个新的库条目、跨 API 和后端的集中修复以及广泛的后端源更新。

亮点：

  • 🎙️ 音频场景和记住的说话人 - 结合语音转文本、说话人分类、声音事件检测和说话人识别。 Studio 可以对录音进行分类、预览干净的间隔并按名称注册选定的扬声器。
  • 🔀 模型故障转移链 - 将本地和远程目标放在一个模型名称后面，在响应提交之前重试，观察运行状况和目标切换，并从 API、MCP 工具或 React UI 固定目标。
  • 🧭 决策模型 - 通过 /v1/systemone 宣传 decisions 用例并回答结构化选择、评分和 noul 问题，并具有验证和专用图库模型。
  • 📦 签名 OCI 库 - 将完整的模型库作为 OCI 工件分发，使用 Sigstore 策略验证它们，并使用摘要绑定的最后已知的良好缓存。
  • 🕺 Kimodo 文本到动画 - 通过 POST /3d/animate 从文本生成骨骼运动，在 Studio 中预览，并导出二进制 glTF 动画。
  • 🖥️ 操作这台机器 - 在单个 LocalAI 主机上检查资源和本地加载的模型、查看日志并停止模型，而无需启用分布式模式。
  • 🛡️ 更安全的图库和 API 行为 - 路径限制修复、更严格的凭据检查、更正预流错误、保留流式响应项目以及更可靠的模型安装。

加上聊天中的 PDF 附件提取、更深入的 Hugging Face 存储库发现、改进的硬件检测、新的意大利 Piper 声音、NeMo 二值化和 ASR 模型以及大型模型库批次。

面积 总结
🎙️ 音频场景 parakeet-cpp 可以将 ASR、二值化和声音检测结合在一个模型中。 POST /v1/audio/diarization 可以选择包含文本和版本化的扬声器配置文件。转录片段和单词可以带有说话者标签，实时会话会发出转录片段和声音检测事件。
🗣️ 记住的演讲者 配置兼容的 speaker_model 以识别来自共享语音注册表的语音。 Studio 的 Diarization 页面可预览干净的发言者间隔，并仅在明确的 命名并记住 操作后注册选定的发言者。演讲者个人资料是生物识别数据，保留选择加入的权利，并不是身份或同意的证明。
🔀 故障转移 模型配置可以定义包含本地或远程模型的有序 failover.targets 链。 LocalAI 在提交响应之前重试符合条件的故障，跟踪运行状况和恢复情况，公开 GET /api/failover 以及 SSE 事件流，添加管理 pin 和取消 pin 控件，并在响应标头中报告所选模型。 localai-proxy 后端将链连接到另一个 LocalAI 端点。
🧭 决定 模型可以显式声明 known_usecases: [decisions] 并通过 POST /v1/systemone 服务结构化请求。 LocalAI 在后端调用之前验证请求大小、问题数、状态、ID、选项、级别和 noul 标准。 React UI 公开了决策功能芯片和安装指南。
📦 OCI 画廊 图库源可以使用 oci://host/repository:tag 或摘要固定参考。 LocalAI 解析并验证摘要，强制执行层和路径限制，以原子方式进行提取，并将缓存与主动验证策略联系起来。 source_repository 添加了精确的 Sigstore 源约束。
🕺 基莫多 POST /3d/animate 接受一个 UTF-8 提示并以 30 FPS 生成 60 到 150 帧的骨骼动画。 Studio 提供动画控件、预览和本地历史记录。输出是二进制 glTF .glb，而不是人形网格。
🖥️ 单主机操作 操作→本机器显示VRAM、RAM、CPU、模型磁盘使用情况以及正在运行的模型进程。操作员可以搜索和排序模型、检查日志以及停止模型。启用分布式模式后，现有的节点工作台仍然可用。
🧠 模型 画廊的参赛作品达到 1,926 件。添加的内容包括大型 Qwen3.8 和社区模型批次、NeMo 语音和二值化模型、四个 Ita
