LocalAI v4.6.0

🎉 LocalAI 4.6.0 发布！ 🚀

<h1对齐=“中心”>
<img高度=“300”src=“https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png”>

LocalAI 4.6.0 出来了！

这是一个注重可靠性的版本：AMD ROCm 后端现在在 GPU 上全速运行，分布式模型负载在工作线程死亡时不再楔入，并且实时会话可预测地预热。它还为内置聊天 UI 带来了对话分叉、用于 PII/审核事件的 Prometheus 计数器以及模型库的 SSRF 修复。

亮点：

  • 🔴 AMD ROCm 正确运行 - ggml 音频后端卸载到 GPU，捆绑 hipBLASLt 内核调整数据（不再有较慢的通用内核），rocm-vllm 安装右轮，并找到 ASIC ID 表。
  • 🎙️ 可预测的实时 - 会话热切地预先预热整个管道（VAD、ASR、LLM、TTS），因此第一轮不再为每个模型的冷启动停顿付费，加上新的 POST /backend/load API 和“加载到内存”UI 按钮。
  • 🌿 分叉聊天 - 直接在内置 UI 中重试任何助理答案、从任意点分支新聊天、复制或复制整个对话。
  • 🛡️ 分布式强化 - 死掉的工作线程无法再固定模型加载咨询锁（~15 分钟的楔子消失了），孤立的后端工作线程会自行终止，而不是保留 VRAM。
  • 📊 PII/审核指标 - PII 检测/掩码/块导出为 Prometheus 计数器，因此您可以在过滤器停止触发时发出警报。
  • 🔒 图库 SSRF 修复 - POST /models/apply 配置 URL 获取针对私有/环回/元数据地址进行验证。

加上幂等后端安装、跨 vLLM 和 Python/MLX 后端的工具调用和推理修复、与最新推理模型的云代理兼容性以及常用的依赖项更新集。

📌 太长；博士

面积 总结
🔴 AMD ROCm 可靠性 ggml 音频后端现在使用 -DGGML_HIP=ON 进行编译并链接 HIP（真正的 GPU 卸载）； hipBLASLt TensileLibrary 数据捆绑 + HIPBLASLT_TENSILE_LIBPATH 导出； rocm-vllm 从 Python 3.12 上的 AMD 轮索引安装； amdgpu.ids 已符号链接，因此可以找到 ASIC 表。
🎙️ 实时预热+加载API 会话在启动时对整个管道进行块预热（错误会预先出现）；新的 POST /backend/load / POST /v1/backend/load、“加载到内存”UI 操作和 load_model MCP 工具。使用 disable_warmup: true 选择退出每个管道。
🌿 分叉聊天 重新生成任何助理答案（不仅仅是最后一个答案）、从任意回合分支新聊天、复制聊天或将其复制为 Markdown - 所有 client 端都在 React UI 中。
🛡️ 流程和分布式生命周期 死亡的工人不再固定每个型号的 PostgreSQL 咨询锁（有界负载上限 + 上下文范围的 lock_timeout）；后端工作人员因父母死亡而自行终止（LOCALAI_BACKEND_PARENT_WATCH）；看门狗停止将可选的 Free() 记录为错误。
⚙️ 幂等后端安装 POST /backends/apply 和 LOCALAI_EXTERNAL_BACKENDS 引导循环不再重新拉动已安装的后端，除非 force: true。
📊 PII/审计 Prometheus 计数器 /metrics 上的 localai_pii_events_total{kind,origin,action,direction}，补充了 /api/pii/events 环形缓冲区。
🔒 画廊 SSRF 强化 图库配置 URL 获取通过 ValidateExternalURL 运行，阻止私有地址、环回地址、本地链接地址和云元数据地址。
🧩 工具调用和推理修复 非流式 vLLM 工具调用已恢复； MLX/Python 后端解码聊天模板的工具调用参数，并拆分仅关闭的 </think> 推理块。

🚀 新功能和主要增强功能

🔴AMD ROCm 后端在 GPU 上正确运行

四个耦合修复使 ROCm/hipBLAS 后端实际上在 AMD 硬件上全速运行，而不是默默地回退到 CPU 或缓慢的通用内核：

  • ggml 音频后端的 GPU 卸载 (#10667)：rocm-qwen3-tts-cpp、rocm-omnivoice-cpp、acestep-cpp 和 vibevoice-cpp 仅构建 CPU，因为它们的 Makefile 传递了无操作 -DGGML_HIPBLAS=ON（上游 ggml 仅理解 -DGGML_HIP=ON）并且 CMake 链接循环省略了 hip。他们现在使用与 llama-cpp 相同的 hipblas 配方并链接 HIP 后端。
  • hipBLASLt 内核调整数据（#10660、#10672）：打包程序捆绑了 rocBLAS 数据，但没有捆绑并行的 hipBLASLt TensileLibrary_lazy_gfx*.dat 文件，因此每个 arch 默默地使用慢速内核并记录 Cannot read "TensileLibrary_lazy_gfx*.dat"。数据现已捆绑，HIPBLASLT_TENSILE_LIBPATH 由 llama-cpp 和 turboquant run.sh 导出。
  • rocm-vllm 安装右轮（#10642、#10651）：后端正在拉动仅 CUDA 的 PyPI vllm（AMD 上致命的 ModuleNotFoundError: No module named 'vllm'）。现在，它固定 CPython 3.12 并安装来自 ROCm 车轮索引 (https://wheels.vllm.ai/rocm/) 的 vLLM。
  • 找到 ASIC ID 表（#10624、#10627）：仅计算的 hipblas 图像缺少 /opt/amdgpu/share/libdrm/amdgpu.ids，因此每个模型加载都会发出警告。 Ubuntu 的 libdrm-common 副本现已符号链接到位。

🔗 PR：#10667、#10672、#10651、#10627

🎙️ 实时：急切的管道预热 + 加载到内存中 API

实时语音会话现在在会话开始时急切地、阻塞地预热整个管道（VAD、转录、LLM、TTS、声音检测、语音识别），而不是在第一次使用时延迟加载每个子模型。第一轮不再支付每个模型的冷启动停顿，并且模型加载错误在会话开始时（如 model_load_error）而不是中途出现。管道子模型同时加载，因此会话在其最慢阶段而不是总和时预热，并且失败的阶段会在连接错误中命名每个损坏的模型。

这还添加了 LocalAI 原生 POST /backend/load（和 /v1/backend/load）（/backend/shutdown 的反面），公开为“加载到内存”UI 操作和 load_model MCP 管理工具，因此管理员可以根据需要预热任何模型（包括完整管道）。 --load-to-memory 启动标志现在通过同一引擎进行路由。使用 disable_warmup: true 选择退出每个管道。

🔗 PR：#10662

🌿 在内置 UI 中分叉聊天

React 聊天 UI 获得了对话管理工具：重新生成任何助理答案（不仅仅是最后一个），从任何答案中分支一个新的聊天，将聊天复制到独立副本中，或者将整个对话以 Markdown 形式复制到 clipboard。在 DOM 和请求负载中，重试对话中的答案会在重新询问之前正确截断对话（这也修复了潜在的陈旧关闭错误，其中对话中的重试会将下游发送回模型）。所有client端，没有后端更改。

🔗 PR：#10654

🛡️ 更坚固的流程和分布式生命周期

  • 死亡工作程序咨询锁楔子 (#10600)：处于中等负载的分布式工作程序可以固定每个模型的 PostgreSQL 咨询锁，并在大约 15 分钟内使对该模型的每个后续请求与 55P03 失败。分离的加载上下文现在受到模型加载上限的限制，安装等待可以通过 singleflight.DoChan 取消，并且 lock_timeout 的范围仅限于调用者的上下文预算，而不是部署全局 GUC。
  • 双亲死亡安全网 (#10639)：如果 LocalAI 在拆卸前为 SIGKILLed，则生成的后端工作人员通常会重新设置父级以进行 init 和 linger，并保留 VRAM 及其端口。现在，每个后端都会轮询其父级 PID，并在重新设置父级时自行终止。可通过 LOCALAI_BACKEND_PARENT_WATCH（默认打开，Windows 上自动关闭）和 LOCALAI_BACKEND_PARENT_WATCH_INTERVAL（默认 2s）进行配置。目前 C++ 覆盖范围是 llama-cpp； Python 涵盖所有后端。
  • 更安静的看门狗（#10602、#10607）：可选的 Free() RPC 为许多后端和联合代理返回 gRPC Unimplemented，因此看门狗在驱逐时不再记录误导性的 Error freeing GPU resources。新的 grpcerrors.IsUnimplemented 帮助程序可将其与真正的故障区分开来。
  • 幂等后端安装 (#10643)：POST /backends/apply 和 LOCALAI_EXTERNAL_BACKENDS 启动循环不再在每次应用/启动时重新下载和重新提取已安装的后端。通过 "force": true（UI 的安装按钮仍然有效，兼作“重新安装”）。

🔗 PR：#10600、#10639、#10607、#10643

📊 PII/审计事件作为 Prometheus 计数器

PII 中间件/MITM 审计管道现在在 /metrics 上发出单个单调计数器 localai_pii_events_total{kind, origin, action, direction}，在 EventStore.Record 阻塞点进行检测。标签是有基数限制的（没有模式或用户 ID）。这补充了容量限制的 /api/pii/events 环形缓冲区，最重要的是，使静默过滤器故障可发出警报：计数器上的 rate() 检测到 PII 过滤器在部署后停止触发。

🔗 PR：#10641

🔒 画廊 SSRF 强化

POST /models/apply 为空的 id 直接获取提供的 url；在默认的 Docker 设置（无 API 密钥）中，任何可访问的 client 都可以探测内部服务或云元数据 (169.254.169.254) 并通过作业错误泄露切片。图库配置获取现在通过现有的 ValidateExternalURL 防护（保护 CORS 代理和媒体下载的防护相同）运行，阻止私有、环回、链接本地、未指定和元数据地址。仅验证普通 http(s)://； huggingface://、github:、oci://、ollama:// 和 file:// 未受影响。

🔗 PR：#10673

🐛 错误修复（回顾）

  • fix(vllm)：恢复在#10351之后回归的非流工具调用提取（功能标志被误认为是运行状态）-#10638
  • fix(python-backends)：解码聊天模板的工具调用 arguments（打破 MLX/Qwen3.5 代理循环），并在模型仅发出结束 </think> 时进行分割推理 - #10658
  • fix(cloud-proxy)：删除 temperature/top_p 并发送 max_completion_tokens，因此路由到最新的推理模型（Claude Opus 4.x、GPT-5.x）会停止 400ing - #10640
  • fix(config)：恢复滑动窗口注意力模型的默认 swa_full:true（恢复内存减少的 KV 缓存；仍然可以作为明确的每个模型选择加入） - #10674
  • fix(kokoros)：实现 AudioTranscriptionLive 特征存根，以便后端根据更新的原型进行编译 - #10612
  • fix(launcher)：将桌面启动器的数据/配置保留在 ~/.localai 下，而不是 GUI 的工作目录下 - #10610、#10613
