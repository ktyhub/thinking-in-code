paperclip v2026.1106.0

发布时间：2026-11-06

Paperclip v2026.1106.0 进行了 515 次提交，从 2026.1023.0-beta.0 升级。标题是 Paperclip Runner 现在是新代理的默认设置：新的 Claude、Codex、OpenCode 和 Pi 代理在合格的 macOS 和 Linux 主机上的本机 Runner 上启动，现有代理获得 one-click“升级运行程序”操作，而 GitHub Copilot 作为本机线束加入。围绕这一点：自动成为技能源的项目存储库、模型支持的提示注入预防、对 Braintrust 或任何 OTLP 端点的代理可观察性、统一的 Google Workspace 连接、对代理名册的批量编辑、使用加密还原点压缩和过期的工作区以及作为实验性 Runner 提供程序的 Grok Bot 和 Muse。在下面，服务器重新启动报告准备得更快，Docker 映像从预编译的捆绑包启动，任务页面加载速度更快，并且更多后台服务停止轮询数据库。

重大变更

  • 管道实验被删除。 管道板、阶段设置、案例自动化、审核队列、pipelines CLI 命令、pipelines:write 权限、enablePipelines 设置和任务详细信息中的 linkedCases 字段都消失了；案例和例行公事仍然存在。现有管道表和记录保持不变，并忽略存储的 enablePipelines 值。 (#16834)
  • 默认情况下，运行故障不再到达 Sentry。 仅后端 DSN 不再报告代理运行故障。设置 PAPERCLIP_SENTRY_RUN_FAILURES=unexpected 以保留之前的过滤策略或 all 以报告每次失败或超时的运行；默认为 off。 (#16300)
  • 运行历史列表有界。 GET /api/companies/{companyId}/heartbeat-runs 默认返回 200 行，最多 1,000 行；依赖于无界数组的 clients 必须传递显式的 limit。 (#16286)
  • paperclipai agent instructions-file:delete 需要 --yes ，就像其他破坏性的 CLI 命令一样；调用它的脚本必须添加该标志。 （[#11504]（https://github.com/paperclipai/paperclip/pull/11504））

亮点

  • Paperclip Runner 是默认设置 — Apple Silicon、Intel macOS 和 Linux x64 上的新 Claude 代理（#15993、#15997）、Apple Silicon、Intel macOS、Linux x64 和 Linux ARM64 上的新 Codex 代理(#15683) 以及 macOS 和 Linux x64 上的新 OpenCode 和 Pi 代理 (#17120、#17142) 现在在本机 Runner 而不是传统适配器上启动，涵盖入门、API 和 CLI、雇用、内置、插件和进口； Linux 需要 GNU libc 2.39 或更高版本，“旧版运行程序”覆盖位于高级下，现有代理保留其当前运行程序。合格目标上现有的 Claude 和 Codex 代理会显示一个 升级运行程序 操作，该操作可将它们转换为一个 click，保留模型、帐户和说明，并列出无法转换的任何设置 (#17122)。 Claude Runner 代理从预加载的核心任务工具开始，在简单任务上测量速度提高了约 20% (#16885)，通过简历保持所选的工作水平 (#15994)，并在 Linux ARM64 上启动 (#16372)。
  • GitHub Copilot 作为本机线束 — 通过应用程序/AI Connections 使用保存的 GitHub 令牌连接 GitHub Copilot；代理的模型列表是从经过身份验证的帐户中发现的，Copilot (CLI 1.0.88) 通过 Paperclip Runner 运行，具有与其他本机提供程序相同的指令、权限和完成边界，包括 Daytona 沙箱所需的 Linux 提供程序清单 (#15705、#15701、 [#15706]（https://github.com/paperclipai/paperclip/pull/15706））。
  • 项目存储库成为技能源 — 附加到新项目的 GitHub 存储库将自动作为技能源导入：Paperclip 导入其技能，使用设置人员的 GitHub 连接每五分钟重新检查一次配置的分支，并安装新技能（除非排除）；现有项目在技能 → 源中获得“采用存储库”操作，可以暂停自动更新，项目派生的技能继承项目访问权限，并且每次运行都会固定其开始时的技能版本（#16066）。导入将整个存储库快照保留在扫描的提交中，以便依赖于共享脚本或同级技能的技能在交付后工作，列出每个技能及其文件夹，并跳过不支持或过大的文件并发出警告，而不是失败（#15731、#16308）。源获得一个分支选择器，用于加载存储库的分支，标记默认值，并在保存之前验证引用（#16288）；跟踪分支消失的源显示分支修复操作（#16256）；每个保存的源都会列出一次，并带有分组刷新错误（#16310）；断开源确实会删除它，并可以选择保留或删除导入的技能（#16150）。
  • **模型支持的提示注入
