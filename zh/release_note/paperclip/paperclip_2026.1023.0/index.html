paperclip v2026.1023.0

发布时间：2026-10-23

Paperclip v2026.1023.0 进行了 200 次提交，从 2026.1012.1-beta.0 升级。标题是私人工作：现在可以将任务或项目标记为私人并与指定人员和代理共享；其他人无法打开它、在任务列表或搜索中找到它、读取其运行记录或通过插件访问它。围绕这一点：代理可以通过您自己的模型网关（OpenRouter、Amazon Bedrock、Google Gemini 或任何 OpenAI Responses、Anthropic Messages 或 Chat Completions 端点）运行，Slack 机器人通过 Slack 的 Manifest API 进行自我设置，GitHub 审核机器人获得两个屏幕设置和真正的 Paperclip Review 状态检查，成本成为一个精确的分类账，还显示每月订阅费，连接的助手可以通过 MCP 编辑任务、上传文件和配置代理。在下面，OpenAI Dot 和 Pi 1.0 加入了实验性 Runner，在输入时原生 OpenCode 流，每个代理都获得持久的加密身份，并且空闲实例停止每秒轮询数据库。

重大变更

  • 操作员现在可以编辑公司。 操作员角色预设从一项授权 (tasks:assign) 增加到十四项：代理创建和配置、技能、环境、邀请、任务分配、管道、连接、工具管理和使用以及审核读取。现有运营商通过正常的启动种子获得缺失的赠款；保留自定义资助范围。加入审批和会员权限管理不再预设，邀请管理员现在需要加入审批，而邀请所有者也需要会员权限管理。如果操作员主要是供阅读的，请检查您的成员角色。 (#15377)
  • GitHub 审阅机器人遵循其自己的实验设置。 GitHub 代码审阅机器人 目录条目、其设置及其管理屏幕仅在 设置 → 实验 → GitHub 审阅机器人（enableGitHubReviewBots，默认情况下关闭）打开时出现；现有的机器人在关闭时继续运行。旧的设置方法和委托代理屏幕已消失，每人自动运行标志被作者包含/排除过滤器取代（读取但忽略旧版 people[].automaticReviews 值）。 (#15416)
  • 默认情况下，预算保留未定价的使用量。 每个预算策略都会获得默认为 block 的未定价使用量设置：虽然运行的使用量没有可靠的价格，但该策略将按其限制计算，直到通过审核的成本调整流程解决费用为止。将策略设置为 allow 以继续按无价使用运行。 (#14997)

亮点

  • 私有任务和项目 — 在创建任务时将其标记为私有，或者使用其自己的成员列表将项目设为私有；首次使用时会为您创建一个个人私人项目。私人作品只能由其负责用户、创建者、当前受让人、指定受让人和私人项目成员读取，并且该规则适用于任务列表和任务计数、搜索、活动、运行详细信息、记录、事件和日志、文档、附件、工作产品以及读取的每个插件。两个表面有意保留在公司范围内：仪表板和侧边栏总计可以在不暴露标题或标识符的情况下对私人工作进行计数，并且公司运行列表显示私人任务运行的锁定行，仅包含代理、状态、时间、令牌和成本字段，因此预算监督仍然有效。隐私权也延伸至儿童；共享一个孩子永远不会暴露其父母或兄弟姐妹。默认情况下，所有者和管理员看不到私有任务，必须请求 ?breakGlass=true，这会在任务上写入审核行和警告通知。代理的访问权限与运行的负责用户相交叉，因此重用代理不会携带其他人的权限。 (#14717、#10633、#14718)
  • 自带模型网关 — 连接器获得 OpenRouter、Amazon Bedrock、Google Gemini 和通用响应 API、消息 API、聊天完成 API 和本地端点的行。 URL、协议、区域和凭据存在于连接中；代理的线束/运行时页面从下拉列表中选择兼容的连接，模型选择器接受手动 ID。 Codex（旧版和 Runner）路由到 OpenRouter 或自定义响应端点，Claude（旧版和 Runner）路由到 OpenRouter、自定义消息端点或 Bedrock，以及 OpenCode 和 Hermes 路由到 OpenRouter 或自定义聊天完成端点。没有显式模型列表的 OpenRouter 连接会加载 OpenRouter 的公共目录。 （[#14970]（https://github.com/paperclipai/paperclip/pull/14970），[#15341]（https://github.com/paperclipai/paperclip/pull/15341））
  • Slack 机器人自行设置 — 新的 Slack 机器人草稿默认为自动设置：粘贴临时应用程序配置令牌，Paperclip 通过 Slack 的清单 API 创建应用程序，通过 OAuth 安装它，链接您的 Slack 帐户，上传代理的头像，并在不涉及 Slack CLI 的情况下在四屏向导中验证交付（[#15413]（https://github.com/paperclipai/paperclip/pull/15413））。新的 需要提及 设置可阻止线程回复在没有明确提及的情况下唤醒代理 (#15612)；在 Slack Stop 开始新的转弯而不是停止后发送的后续信号（#15737）； Slack 代理现在知道人们用来链接他们的帐户、链接他们创建的每个任务以及在原始线程中报告结果和审查请求的已保存斜线命令（#15576、[#15579](https://github.com/paperclipai/pap
