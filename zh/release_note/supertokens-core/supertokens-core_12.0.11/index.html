supertokens-core v12.0.11

修订 发布时间2026年10月16日 来源supertokens/supertokens-core 英文原文

supertokens-core v12.0.11

  • 通过帐户取消链接来序列化会话创建以结束会话竞赛 (GHSA-2pc4-vw9j-454c)。
  • 强制执行 SAML 回调重放保护和请求绑定 (GHSA-3r7x-rhvc-fw28)。
  • SAML：client 可以携带可选的 ACS-URL 允许列表 (acsURLs)。设置后，登录名的 ACS URL（SP 发起）和响应 Destination/SubjectConfirmationData.Recipient（IdP 发起）必须是成员 — 将目标/收件人固定扩展至 IdP 发起的路径，该路径之前没有锚点。启用 IdP 发起的登录时需要该列表：在每次 client 创建/更新时都会检查该列表，并且在设置之前，会拒绝对现有 client 的 IdP 发起的登录（如果没有）。 （GHSA-3r7x-rhvc-fw28后续）
  • 将 SAML 身份绑定到单个经过验证的断言，该断言必须携带与 ACS URL 匹配的签名 Recipient； saml_sp_entity_id 保留其默认值 (GHSA-wfg2-vqfg-rqh6)。
  • 将 WebAuthn 登录范围限定为请求的租户 (GHSA-6v34-w48w-44rc)。
  • 阻止应用程序范围的 API 密钥更新其父 connectionUriDomain (GHSA-4rf2)。
  • 在验证时强制仪表板会话过期 (GHSA-w9fp-wv6g-pqv8)。

迁移

SAML 重播强化（由 supertokens-postgresql-插件应用）向 saml_relay_state 添加两列：saml_consumed_assertions 表和 saml_clients.acs_urls 允许列表列。该插件在启动时自动应用它们（CREATE TABLE / ADD COLUMN IF NOT EXISTS）；大型 PostgreSQL 部署可以在升级之前预先应用以下语句。添加剂和在线安全。

ALTER TABLE saml_relay_state ADD COLUMN IF NOT EXISTS in_response_to VARCHAR(256);
ALTER TABLE saml_relay_state ADD COLUMN IF NOT EXISTS acs_url TEXT;

CREATE TABLE IF NOT EXISTS saml_consumed_assertions (
    app_id VARCHAR(64) NOT NULL DEFAULT 'public',
    tenant_id VARCHAR(64) NOT NULL DEFAULT 'public',
    assertion_id VARCHAR(256) NOT NULL,
    expires_at BIGINT NOT NULL,
    CONSTRAINT saml_consumed_assertions_pkey PRIMARY KEY(app_id, tenant_id, assertion_id),
    CONSTRAINT saml_consumed_assertions_app_id_fkey FOREIGN KEY(app_id) REFERENCES apps (app_id) ON DELETE CASCADE,
    CONSTRAINT saml_consumed_assertions_tenant_id_fkey FOREIGN KEY(app_id, tenant_id) REFERENCES tenants (app_id, tenant_id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS saml_consumed_assertions_expires_at_index ON saml_consumed_assertions (expires_at);

ALTER TABLE saml_clients ADD COLUMN IF NOT EXISTS acs_urls TEXT;
