diffusers v0.40.0

小版本 发布时间2026年8月20日 来源huggingface/diffusers 英文原文

diffusers v0.40.0

[!提示] 此版本具有多个新管道，包括 LTX2.5、MiniMax H3 和 Wan Animate 2。我们还将模块化扩散器退出实验阶段并宣布其稳定支持。此外，此版本还包括对张量并行的最低限度支持。此版本中还有很多内容。因此，请参阅注释以了解详细信息。

新管道

MiniMax-H3

MiniMax-H3 一起生成视频及其配乐。单个变压器对包含文本调节、调节媒体以及目标视频和潜在音频的一个打包序列进行去噪——没有单独的声码器，也没有事后音频通道。它的条件是 Qwen3VLForConditionalGeneration，其非标准化的第 50 解码器层隐藏状态被读取而不是最后一个。

MiniMax-H3 仅集成为 模块化扩散器 块 - MiniMaxH3Blocks 及其 MiniMaxH3ModularPipeline 是整体集成。该转换将两个检查点分区发送到一个存储库中，并公开三个工作流程（t2va、fl2va、ref2va），这些工作流程可以在 from_pretrained 时间进行修剪，以便仅声明和下载该任务的组件。

MiniMax 音乐 3

MiniMax Music 3 可根据歌词和音乐描述生成长达五分钟的完整歌曲，具有富有表现力的声音和长音结构。它是自回归和扩散阶段的混合体：基于 8B Qwen3 的全局语言模型预测每帧一个语义音频标记，而小型深度解码器填充七个剩余 RVQ 码本，它们的融合隐藏状态调节 2.4B 流匹配变压器，该变压器在重叠块中产生 Flow-VAE 潜伏。 DAC 式解码器将潜在音频转换为 44.1 kHz 立体声音频。

稳定音频 3

Stable Audio 3 是 Stability AI 的文本转音频模型，可生成 44.1 kHz 的高质量立体声音频。它使用以冻结 T5Gemma 文本编码器（通过交叉注意力）和持续时间（StableAudio3DurationEmbedder 嵌入的浮点并用于自适应层规范）为条件的整流流 DiT，并使用 SAME（语义对齐音乐编码器）自动编码器 AutoencoderSAME 进行解码。

船舶共有三条管道：StableAudio3Pipeline、StableAudio3AudioToAudioPipeline 和 StableAudio3InpaintPipeline。

感谢@buffett0323 的贡献（https://github.com/huggingface/diffusers/pull/14119）。

LTX-2.5

LTX-2.5 重用现有的 LTX2Pipeline / LTX2VideoTransformer3DModel / AutoencoderKLLTX2Video 类 - 没有单独的管道类。用户可见的差异在于文本编码器：LTX-2.5 与 Gemma 4 (gemma4_unified) 检查点配对，从转换后的 LTX-2.5 存储库自动加载。

Lightricks/LTX-2.5-Diffusers 提供蒸馏 DiT (transformer/) 和完整/SFT DiT (transformer_full/)，以及两阶段生成所需的一切。除了检查点支持之外，此版本还添加了：

  • LTX2VideoDiffusionDecoderModel 和 LTX2VideoDiffusionDecodePipeline — 同一潜在空间上的第二个视频解码器，因此潜在空间在解码器之间可以互换。
  • duration_head 从文本连接器输出预测镜头长度，因此当加载的管道有镜头长度时，默认情况下会自动预测 num_frames。
  • 通过单独的现成 google/gemma-4-E2B-it 检查点 (enable_prompt_enhancement=True) 进行提示增强。
  • LTX25AutoBlocks 用于模块化扩散器（#14453）。

万动画-2

阿里巴巴万团队的 Wan-Animate-2 使用驾驶视频的运动来制作参考角色图像的动画。驾驶视频以固定长度的片段进行处理：每个片段运行一个参考提取通道，在每个转换器层中缓存驾驶片段的 K/V，针对该缓存进行去噪，并在循环内进行解码，因为下一个片段取决于前一个片段的已解码尾帧。

有两种预设可用 - 具有无分类器指导的基本检查点样本，以及没有分类器指导的几个步骤的蒸馏检查点样本。引导由管道的引导组件拥有，因此没有 guidance_scale 参数。

感谢 @kelseyee 编写集成 (https://github.com/huggingface/diffusers/pull/14413)。

JoyAI-图像-编辑-Plus

JoyAI-Image-Edit-Plus 将 JoyAI-Image 系列（8B MLLM 与 16B MMDiT 配对）扩展到多图像指令引导编辑。它接受 1-5 个参考图像加上文本指令，并将参考中的元素组合成新图像。

感谢@tangyanf 的贡献（ZZPH100​​ZZ）。

Cosmos 3 后续行动

Cosmos 3 登陆 0.39.0 并在此版本中获得更多的覆盖范围：

  • Cosmos 3 模块化管道 (Cosmos3OmniModularPipeline)，具有传输支持，用于预先计算的控制视频（边缘、模糊、深度、分割、世界场景图），以块的形式自回归生成并自动缝合。
  • 边缘支撑。
  • 蒸馏（几个步骤）文本到图像和图像到视频 通过 Cosmos3DistilledModularPipeline。
  • 模型并行度。

感谢@yzhautouskay 和@aharvajoshi10 的贡献。

模块化管道支持

模块化扩散器 不再标记为实验性 (#14525) — API 警告已被删除。

  • 此版本的三个新集成 — MiniMax-H3、MiniMax Music 3 和 Wan-Animate-2 — 仅作为模块化块提供，没有 DiffusionPipeline 一半。
  • Cosmos 3 (#14110、#14150、#14177) 和 Krea 2 (#14083，感谢@Cedric-Perauer）获得了模块化管道，并且 Anima 获得了img2img 块（#13929，感谢@PreethamNoelP）。
  • 特定于分支的输入默认值 (#14234)：当 ConditionalPipelineBlocks 的同级块为同一输入声明不同的默认值时，combine_inputs 现在将默认值合并到 None 并将每个块的默认值记录在新的 InputParam.defaults_by_block 字段中。 get_block_state 回退到块自己声明的默认值，因此每个分支在实际运行时都会解析自己的默认值。文档字符串呈现冲突的默认值，例如*“默认为 None 或 189，具体取决于工作流程”*。
  • 组卸载现在在自动卸载下工作，并且修复了组卸载设备不匹配。
  • 未使用的 intermediate_inputs 已清理，现在在 CI 中检测到过时的自动文档字符串，并且梅隆自定义块所需的输入处理已修复。

[!重要] 请尝试模块化扩散器并让我们知道您的反馈！

核心库

张量并行性

张量并行推理 现在支持 CUDA 和 AWS Neuron (Trainium/Inferentia) 上的模型推理，通过已用于上下文并行性的相同公共 API 公开：

from diffusers import TensorParallelConfig

pipe.transformer.enable_parallelism(config=TensorParallelConfig(mesh=tp_mesh))

分片与模型无关，由平面 _tp_plan 驱动，该 _tp_plan 已添加到 FLUX.1、FLUX.2 和 Qwen-Image DiT 中。 Check out the docs for more details.

新的量化后端

  • SDNQ — 免训练后端，支持 int8 低至 2 位、FP8 和其他低位浮点格式，具有可选的 SVD 校正、Hadamard 旋转和量化 INT8/FP8 matmul。在 CUDA、ROCm、XPU、MPS 和 CPU 上运行。 【SDNQ MiniMax-H3加载】(https://github.com/huggingface/diffusers/pull/14398)也登陆了。感谢@asomoza。
  • Nunchaku Lite for loading prequantized checkpoints, with fused-kernel performance documented.感谢@rootonchair。

注意，内核和卸载

  • 仅当用户请求时才下载内核
  • ROCm FlashAttention 现在使用 kernels-community/aiter-flash-attn-ck Hub 内核，删除了 aiter 依赖项。感谢@Abdennacer-Badaoui。
  • Sequence-parallel support for the _flash_3_varlen_hub backend and a mask-handling fix.感谢@zhtmike。
  • 【分体式管道DiffusionPipeline.device扣除】(https://github.com/huggingface/diffusers/pull/14383)
  • Hook forward signatures are preserved.感谢@jloftin-nv。

CLI

diffusers-cli 进行了重新设计以供代理使用（#13966），然后进行清理（#14381）：保存自定义块时写入 modular_model_index.json，以便 ModularPipeline.from_pretrained 可以作为管道加载和运行自定义块，自动 CPU 卸载适用于模块化管道，workflow 可以传递给模块化 pipelines, and output saving handles multimodal output (e.g. LTX video frames + audio) and batched video.

Skills are now installed through the CLI rather than the Makefile (#14454):

diffusers-cli skills list
diffusers-cli skills add <skill name>

🚨 重大变更和弃用

  • JAX/Flax support has been removed (#14169) — roughly 12k lines deleted. All Flax* classes and the flax extras are gone.
  • 没有 alpha 键的混合等级 LoRA 现在按其预期规模加载 (#14409)。以前，get_peft_kwargs 从排名字典的第一个条目中获取 lora_alpha 并且从未重新访问它，因此排名与第一个键的排名不同的每个模块都会获得任意的、依赖于键顺序的比例。当检查点没有带来 alpha 信息时，等级现在会镜像到 alpha 中（扩散器/PEFT 约定：alpha == 等级，比例 1.0）。具有声明的 alpha 的适配器保留它，统一等级的适配器不受影响。 Existing mixed-rank, no-alpha LoRAs will now produce different (correct) results.
  • torch_dtype is deprecated in favour of dtype (#14205, #14313), following transformers. torch_dtype still works but warns, and will be removed in 1.0.0. A torch.dtype alias was added for the docs.
  • DDUF 已弃用 (#14141)。 dduf_file warns and will be removed in 0.41.0.
