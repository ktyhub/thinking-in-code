diffusers v0.43.0

小版本 发布时间2026年11月12日 来源huggingface/diffusers 英文原文

diffusers v0.43.0

[!提示] 此版本添加了五个模块化模型集成，用于图像生成、编辑、音频视频、语音驱动动画和世界模拟。它还改进了注意力后端、张量并行性、LoRA 处理和检查点保存。

MiniMax-H3-图像

MiniMax-H3-Image 支持使用一张或多张参考图像生成文本到图像并进行编辑。该集成包括专用图像转换器和自动编码器，具有固定的六步采样计划和精炼指导。单独的提示增强工作流程可扩展简短的请求并建议宽高比。

通过ModularPipeline.from_pretrained(...)加载它，然后调用load_components(...)。 MiniMax-H3-Image 文档 涵盖参考图像提示、输出大小、提示增强和组件卸载。

皮卡 H3 Flex

Pika H3 Flex 基于 MiniMax-H3 构建，可通过六个步骤生成视频和同步立体声音频。它通过单独的模块化工作流程支持文本提示、第一帧和/或最后一帧以及多模式引用。该集成包括 LoRA 适配器加载以及在两个管道之间共享已加载的 MiniMax-H3 组件的指南。

有关工作流程选择、适配器加载和组件重用的信息，请参阅 Pika H3 Flex 文档。

P-H3-图像

Pruna AI 的 P-H3-Image 提供文本到图像生成和基于指令的编辑，最多可处理八个输入图像。其模块化管道包括一个提示上采样器，可将请求转换为详细的生成或编辑提示、图像自动编码器和文本连接器。检查点使用八个采样步骤和精炼指导。

有关图像大小调整、参考图像编辑、提示上采样和卸载的信息，请参阅 P-H3-图像文档。感谢 @nifleisch 在 #15171 中的集成。

康定斯基 S2V 1.0

Kandinsky S2V 1.0 根据参考图像和语音录音制作人物动画，包括与语音对齐的全身运动。它以五秒块的形式生成视频，并在块之间携带 FramePack 内存。提供的语音提供配乐；模型生成视频。

模块化集成支持 Lite 和 Pro 检查点，包括使用 PiflowScheduler 的精简变体，默认为 16 个步骤。有关音频准备、检查点设置和内存要求，请参阅 Kandinsky S2V 文档。感谢@nvsm 在#15164 中的集成。

潘 2

PAN 2 根据描述动作和摄像机随时间移动的提示来模拟场景。该版本通过文本到视频和图像到视频模块化工作流程集成了 29B 生成模拟器。支持上下文并行性以及 FirstBlockCache、MagCache 和 TaylorSeer 缓存。默认情况下启用提示和视频安全检查，并且需要单独的 pan2-guardrail 软件包。

有关加载、护栏和分布式推理的信息，请参阅 PAN 2 文档。集成涵盖了模拟器；编写其提示的单独推理模型是从模型文档链接的。感谢@wu-qing-157 在#15202 中的集成。

其他亮点

  • MiniMax-H3 张量并行性： 将变压器跨设备分片，包括其大型调制投影。在张量并行加载期间，复制的参数也保留其预期的数据类型。请参阅：#14609、#15147。
  • AMD 注意力支持： 新的 aiter_sage_hub 后端将 Hub 托管的 SageAttention 内核引入 RDNA4 gfx1201 GPU，并针对不支持的输入形状提供本机 SDPA 回退。请参阅#15060。
  • 注意后端修复： 在一个模型上选择后端不再更改不相关模型的后端。现在，各个注意力模块在选择后端时会检查要求并下载 Hub 内核，并且 FlashAttention-2 集成可与较新的 Hub 内核版本配合使用。参见#14335、#15000。
  • LoRA 修复： 组件权重字典现在可以在多个适配器之间正确广播，并且 Kohya 文本编码器 LoRA 保留其每个模块的 alpha 值。适配器权重文档和类型提示也阐明了支持的格式。请参阅：#15128、#15157。
  • 检查点保存： save_pretrained() 在用单文件检查点替换分片检查点时保留其他变体的分片并删除过时的索引。请参阅 #14844。
  • 模块化缓存： 有状态缓存挂钩在每次管道调用（包括引发异常的调用）后重置，因此后续生成从新的缓存状态开始。请参阅 #15212。
  • 训练示例： 修复文本到图像 LoRA 和 SDXL LCM LoRA 脚本中的梯度 clipping，更新当前 Transformers 的 FLUX 量化嵌入准备，并删除导致 --revision 训练崩溃的过期弃用块。请参阅：#15184、#15144、#15118。
  • **文档：**重新组织了分布式推理指南，更新了本机 TorchNeuron 的 AWS Trainium 示例，并更正了 Cosmos3 FP8 检查点位置。请参阅：#15172、#15138、#15236。

弃用和兼容性

  • **依赖项检查：**可用性检查现在强制执行支持的依赖项版本。低于支持的最低限度的已安装软件包将被视为不可用，并显示升级消息。例如，这些检查现在强制执行现有的 torch>=2.6 和 transformers>=4.41.2 最小值。 (#15148)
  • 重新定位的模型组件： 潜在升级器和条件嵌入器移动到 diffusers.models 下。现有检查点仍然可加载，而旧的管道模块导入已被弃用并在 1.0.0 中删除。使用公共导入，例如 from diffusers import LTX2TextConnectors。请参阅：#15111。
  • 模块化输入默认值： 显式传递 None 会保留该值。省略的输入接收读取它们的第一个块的默认值。声明为必需且具有非 None 默认值的 InputParam 被视为可选并发出警告。请参阅：#15135、#14521。
  • 训练行为： --max_grad_norm 现在在受影响的 LoRA 示例中生效。因此，以高于 clipping 阈值的梯度运行的行为可能与早期版本不同。请参阅：#15184。
  • **组件加载：**存储库配置不再导致任意组件库导入。受支持的库集之外的自定义组件模块必须已由调用者导入，并且模块化自定义块加载会在处理要求之前检查远程代码 trust。请参阅：3076605。
