keycloak 26.7.0

亮点

此版本为 Keycloak 的用户和管理员提供了新功能。此版本的亮点是：

  • 使用 SCIM API（预览版）自动进行用户配置

  • 无需外部缓存的简化多集群高可用性（预览版）

  • 带有 HAProxy 和 Traefik 蓝图的增强型反向代理指南

  • SAML clients 的逐步身份验证

继续阅读以了解有关每个新功能的更多信息。 如果您要从以前的版本升级，另请查看升级指南中列出的更改。

安全和标准

身份代理 API 具有更强的安全性

身份代理 API 允许应用程序在联合登录期间检索从外部身份提供商获取的令牌。 API 的第 2 版采用更安全且符合标准的设计取代了旧版 V1：

  • Client 级授权 - 使用专用设置（允许检索外部令牌和身份提供商允许列表）按 client 控制对外部令牌的访问，而不是将代理角色分配给各个用户。

  • 仅限机密 clients — 公开 client 会被拒绝，确保只有经过身份验证的 clients 才能检索外部令牌。

  • OAuth 2.0 兼容 - 端点使用 POST 并返回带有 access_token、error 和 error_description 字段的标准 JSON 响应。

  • 基于会话的令牌存储 - 新的在会话中存储令牌选项可将令牌保留在用户会话中以加快访问速度，并在会话到期时自动清理。数据库存储仍然可用于跨会话的持久性。

现在支持 V2，但默认情况下禁用。 V1 已弃用，但默认情况下仍启用以实现向后兼容性。在未来的版本中，V1 将被删除，V2 将成为默认值。

有关详细信息，请参阅《服务器开发人员指南》中的身份代理 APIs 章节。

可验证凭证 (OID4VCI) 的进展（实验性）

可验证凭证 (OID4VCI) 允许组织颁发防篡改、加密签名的凭证（例如员工徽章、学术文凭或专业证书），用户可以将这些凭证存储在数字钱包中并出示给第三方，而无需发行人参与。

OID4VCI 仍然是 Keycloak 中的实验性功能，但此版本带来了核心团队和社区的重大改进：

  • 完善现有功能并改进配置。除了管理 REST API 之外，现在所有内容都可以在管理 UI 中进行配置。

  • 修复了很多错误。提高了规范合规性。

  • 符合OpenID4VC 高保证互操作性配置文件 (HAIP)。 这项工作涉及引入专用的 Keycloak 实验功能 client-auth-abca，用于基于证明的 client 身份验证 (ABCA)。

  • 管理个人用户的可验证凭据。这涉及管理员为用户创建可验证凭证的能力 指示该用户可以检索可验证的凭据，以及用户能够从 Keycloak 帐户控制台开始颁发可验证的凭据。

  • 预授权代码授予支持仍处于实验阶段，已移至专用实验功能oid4vc-vci-preauth-code

  • 支持凭据刷新间隔。管理员现在可以在 client 范围设置中配置单独的刷新间隔 (vc.refresh_interval_in_seconds)，控制钱包必须刷新凭证的频率，与凭证生命周期无关。如果未明确设置，则默认为 7 天或凭证生命周期，以较小者为准。这样可以定期进行凭证轮换，以增强安全性，同时通过使用刷新令牌的自动刷新来保持用户便利性。有关详细信息，请参阅 OID4VCI 配置指南中的使用映射器创建 Client 范围部分。

  • 文档已更新和改进

使用身份断言 JWT Grant 进行跨域令牌交换（实验性）

当两个组织各自运行自己的授权服务器时，用户在跨越它们时通常需要重新进行身份验证 - 即使他们的身份已经过验证。 身份断言 JWT 授权授予 (ID-JAG) 解决了这个问题，它允许一个授权服务器向另一个授权服务器提供已签名的身份断言，然后后者颁发访问令牌，而无需用户再次登录。

Keycloak 为身份断言 JWT 授权授予提供部分实验性支持。它当前仅实现接收授权服务器角色，在令牌端点接受 ID-JAG 断言并发出访问令牌作为回报。 ID-JAG 规范的其他部分尚未实现，因此当前不支持完整的流程。

要尝试一下，请在启用 identity-assertion-jwt 功能的情况下启动 Keycloak。

非常感谢Yutaka Obuchi对此功能的贡献！

使用 SCIM API 自动配置用户（预览版）

SCIM（跨域身份管理系统）是跨多个系统读写身份资源（例如用户和组）的标准协议。它使组织能够使用广泛可用的工具自动执行用户配置和取消配置，例如与身份治理平台、人力资源系统或其他身份提供商集成。

Keycloak 具有 SCIM API，用于管理领域内的用户和组。该实现涵盖了完整的 CRUD 和 PATCH 操作、过滤和分页、架构扩展（包括企业用户扩展）和架构发现端点。

在此版本中，SCIM API 升级为预览功能。在默认配置文件中，它默认被禁用；要尝试一下，请启用 scim-api 功能。

有关更多详细信息，请参阅通过 SCIM 管理用户和组文档。

向下游应用程序发送实时安全信号（实验性）

当用户注销、更改凭据或在 Keycloak 中被禁用时，下游应用程序通常不会了解它，直到下一次令牌刷新 - 留下一个窗口，其中陈旧的会话仍保持活动状态。 OpenID 共享信号框架 (SSF) 通过让身份提供商近乎实时地将安全事件推送给依赖方来弥补这一差距。

Keycloak 现在可以充当 SSF 发送器，将签名的安全事件令牌 (SET) 传递给注册的接收器。它支持 CAEP 1.0 和 RISC 1.0 事件配置文件，并具有推送 (RFC 8935) 和轮询 (RFC 8936) 传送方法。事件被持久保存到持久的发件箱中，以便在重新启动时不会丢失信号，并且集群感知的后台耗尽程序可以处理重试和指数退避。每个领域都可以单独选择加入，并且流、主题和事件类型通过管理控制台和 REST API 进行管理。

要启用 SSF，请在启用 ssf 功能的情况下启动 Keycloak。

有关更多详细信息，请参阅共享信号框架指南。

使用 AuthZen 进行标准化授权决策（实验性）

需要细粒度授权的应用程序通常调用Keycloak的专有授权API，将它们耦合到其内部模型。 OpenID AuthZEN 授权 API 1.0 定义了策略决策点 (PDP) 和策略执行点 (PEP) 之间的供应商中立协议，使应用程序能够通过标准接口请求授权决策。

Keycloak 现在将 AuthZEN 评估 API 作为 PDP 实施。应用程序发送描述主题、资源和操作的评估请求，Keycloak 根据其配置的授权策略返回允许或拒绝决策。单个和批量评估端点均可用。

要启用 AuthZen，请在启用 authzen 功能的情况下启动 Keycloak。

有关更多详细信息，请参阅AuthZen 授权指南。

授权 AI 工具和 MCP 服务器

模型上下文协议（MCP）正在成为人工智能应用程序连接外部工具和数据源的标准方式。随着 MCP 采用率的增长，通过正确的 OAuth 2.0 授权保护这些连接至关重要。

Keycloak 不断改进其 MCP 授权服务器功能。此版本除了现有的 Visual Studio Code 集成之外，还添加了 Claude Code 的集成文档作为 MCP client。两者都使用 OAuth Client ID 元数据文档 (CIMD) 通过 PKCE 保护的公共 client 流和本地主机回调进行动态 client 注册。

有关设置说明，请参阅与模型上下文协议 (MCP) 集成指南。

通过令牌交换委托（实验性）委托跨服务的访问权限

在多服务架构中，后端服务有时需要代表另一个服务中的用户进行操作 - 例如，当网关将工作委托给下游 API 时。标准令牌交换处理 client 到 client 令牌交换，但验证请求者是否有权模拟特定用户需要额外的检查。

Keycloak 引入了代币交换委托作为一项实验性功能。它添加了一个新的委托参数化范围类型，该类型在授予交换之前验证请求用户是否有权代表目标用户进行操作。委托范围需要用户同意，并在令牌刷新时自动重新评估，因此撤销的模拟权限会立即生效。

要启用令牌交换委托，请在启用 token-exchange-delegation 功能的情况下启动 Keycloak。

SAML clients 的逐步身份验证

逐步身份验证允许应用程序对敏感操作要求更强级别的身份验证。此前，此功能仅适用于 OpenID Connect clients。

Keycloak 现在将逐步身份验证扩展到 SAML 协议，使 SAML 服务提供商能够在其身份验证请求中请求特定的身份验证上下文类。此版本中的 step-up-authentication-saml 功能已从预览版升级为支持版。

有关详细信息，请参阅服务器管理指南。

管理

使用管理员 API v2 进行声明式 client 管理（实验性）

Keycloak 引入了新的 REST API，用于管理 OIDC 和 SAML clients。 新的 API 提供严格的验证、对声明性配置的支持以及准确的 OpenAPI 规范，从而实现可靠的 client 生成。 这解决了原始 Admin REST API 长期存在的限制。 这是 Admin API v2 中的第一个资源，未来版本中还将提供更多资源。

API 可以通过 Java client、自动生成的 JavaScript、client 和 CLI 来使用。 Keycloak Operator 使用它通过 KeycloakOIDCClient 和 KeycloakSAMLClient 自定义资源以声明方式管理 client。

启用此功能还会在管理接口上启用 OpenAPI 规范端点，CLI 使用该端点来调整其命令以适应连接的服务器版本。

要尝试一下，请启用 client-admin-api:v2 功能。

有关更多详细信息，请参阅管理 API v2 指南和管理 Keycloak Clients 操作员指南。 欢迎在 Client 管理员 API v2 GitHub 讨论中提供反馈。

感谢 Robin Meese 在管理界面和 Java 管理员 client 上贡献 OpenAPI 端点， 感谢 Sebastian Schuster 参与 Admin API 工作组和 Go client 分析。

用于组织管理的细粒度委派

在 Keycloak 中管理组织以前需要 manage-realm 角色，这是一种高权限角色，授予的访问权限远远超过大多数组织管理员所需的权限。此版本为组织引入了专用管理角色和细粒度管理权限，允许管理员委派组织管理，而无需过度配置访问权限。

新的领域管理员角色提供粗粒度的委派：

  • manage-organizations — 授予对组织的完全读写访问权限，包括创建、更新和删除组织及其成员。

  • view-organizations — 授予组织及其成员只读访问权限（还需要 view-users 或细粒度管理员权限以实现用户可见性）。

  • query-organizations — 无需完全查看访问权限即可搜索和列出组织，与 query-users / query-clients / query-groups 模式一致。

manage-realm 角色继续隐式授予完整的组织管理访问权限，以实现向后兼容性。

对于每个组织的粒度，组织现在是细粒度管理权限中的一流资源类型。管理员可以创建权限来控制委派管理员可以查看或管理哪些特定组织 - 例如，授予管理一个组织的访问权限，而不授予领域中所有组织的访问权限。启用细粒度管理员权限后，组织成员查询也会尊重用户级别权限，仅返回管理员有权查看的成员。

通过组织群组自动继承角色

当组织拥有数百个都需要相同权限的用户时，向各个组织成员分配角色无法很好地扩展。组织群组现在支持领域和 client 角色分配，因此管理员可以向组织群组分配一次角色，并使其自动显示在所有群组成员的 realm_access 和 resource_access 令牌声明中。

此外，通过启用添加组角色映射配置选项，组织组成员身份协议映射器（OIDC 和 SAML）可以将这些角色包含在按组织组织的组织声明中。

有关更多详细信息，请参阅管理组织群组指南。

与新的 WebAuthn 策略选项更好的密钥兼容性

密钥允许用户使用生物识别技术或安全密钥而不是密码登录。为了正常工作，服务器必须告诉浏览器它是否更喜欢可发现的凭据（存储在设备上的密钥），而之前的“是/否”选项无法表达日益常见的首选值。

WebAuthn 策略和 WebAuthn 无密码策略现在提供一个可发现凭据选项，该选项遵循当前的 WebAuthn 规范，支持必需、首选和不鼓励值。这提高了与 iCloud 钥匙串、Google 密码管理器和 1Password 等密码提供商的兼容性。之前的需要可发现的凭据选项现已弃用，并计划在未来版本中删除。

通过显示名称搜索更轻松地发现领域

管理员经常为领域提供简短的技术名称（例如 acme-prod），但设置一个人类可读的显示名称（例如 Acme Corporation）。以前，管理控制台搜索仅与技术领域名称匹配，这使得在大型多租户部署中查找领域变得更加困难。

领域搜索现在除了领域名称之外还与显示名称相匹配，因此管理员可以通过他们记住的任何名称来查找领域。

参数化范围的类型安全验证（实验性）

参数化范围允许 OAuth clients 请求特定于上下文的访问权限 - 例如，project:12345 请求访问特定项目，或 account: savings 将令牌范围限定到特定银行账户。以前，参数值仅通过可选的正则表达式进行验证，因此很容易传递无效或意外的值。

参数化范围现在可以定义一个参数类型，用于在请求时验证捕获的值。内置类型包括字符串、整数、布尔值、用户名和自定义（根据管理员定义的正则表达式进行验证）。在启用该功能的情况下创建参数化作用域时需要该类型，以确保令牌始终携带格式正确的作用域参数。

更多详情请参阅升级指南。

其他数据源可能会被排除在运行状况检查之外

使用多个数据源时，出现故障的非关键数据源可能会导致运行状况检查端点将整个部署报告为运行状况不佳。现在可以将单个数据源排除在运行状况检查之外，因此可选或辅助数据源不会触发不必要的警报或影响负载均衡器路由。

请参阅配置多个数据源指南了解更多相关信息。

配置和运行

带有 HAProxy 和 Traefik 蓝图的增强型反向代理指南

在生产中运行 Keycloak 需要反向代理，但跨不同代理正确配置 TLS 终止、证书转发和管理 API 安全性很容易出错。

反向代理文档已得到显着扩展，包含 HAProxy 和 Traefik 的专用分步指南，涵盖 TLS 直通和重新加密模式，并解释了这些概念，以便它们也可以应用于其他代理。

有关更多详细信息，请参阅使用反向代理指南。

无需外部缓存的简化多集群高可用性（预览版）

Keycloak 的现有多集群设置需要部署和管理用于跨站点会话复制的外部 Infinispan 集群，以及用于自动故障转移的供应商特定的防护基础设施。这显着增加了操作复杂性并限制了特定环境的部署。

多集群 v2 完全消除了外部 Infinispan 要求。 Keycloak 实例使用嵌入式 Infinispan 缓存直接相互连接，并依赖同步复制的数据库作为单一事实来源。跨站点的缓存失效是通过数据库支持的发件箱模式来处理的。负载均衡器可以检测站点的停机时间，而无需外部防护基础设施。

要启用此设置，请使用无状态功能启动Keycloak。有关架构详细信息和部署蓝图，请参阅多集群部署 (v2) 指南。

Keycloak Operator kustomize 安装

以前，在普通 Kubernetes 集群上安装 Keycloak Operator 需要下载并应用单独的清单文件，这使得升级和自定义更难以管理。现在可以使用 kustomize 安装 Operator，提供声明性且可重复的安装方法。

有关安装说明，请参阅操作指南。

Keycloak Operator 的集群范围安装模式（预览版）

跨不同 Kubernetes 命名空间运行多个 Keycloak 实例的组织以前需要在每个命名空间中安装单独的 Operator。 Keycloak Operator 现在将 AllNamespaces 公开为受支持的 OLM 安装模式，允许单个 Operator 实例跨集群中的所有命名空间协调 Keycloak 自定义资源。对于非 OLM 安装，可以通过集群范围 kustomization 覆盖进行集群范围部署。

集群范围内的安装处于预览状态。有关安装说明和限制，请参阅操作员指南。
