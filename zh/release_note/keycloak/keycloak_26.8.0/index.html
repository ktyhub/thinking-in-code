keycloak 26.8.0

亮点

此版本为 Keycloak 的用户和管理员提供了新功能。 此版本的亮点是：

  • 使用 OID4VCI 和 OID4VP 颁发并验证数字钱包凭证

  • 使用 SCIM API 跨身份系统自动配置用户

  • 使用无状态模式（现已支持）在没有外部缓存的情况下运行多集群部署

  • 通过自动创建索引、减少内存使用和增强 HTTP 性能来简化管理

  • 经过同意和 FGAP 授权的人工智能代理和自动化的代币交换委托

继续阅读以了解有关每个新功能的更多信息。 如果您要从以前的版本升级，另请查看升级指南中列出的更改。

安全和标准

可验证凭证颁发通过凭证管理和撤销升级为预览版

用于可验证凭证颁发的 OpenID (OID4VCI) 功能已从实验性升级为预览版。 现在可以使用 --features=preview 或 --features=oid4vc-vci 启用它。

凭证生命周期管理现在包括刷新令牌被撤销时的撤销，并且新的应用程序启动操作 (AIA) 允许用户在经过身份验证的会话中请求凭证颁发。 密钥证明可在管理控制台中配置，并使用遵循 HAIP 配置文件的强化 x5c 证书验证。 此版本还添加了对 mdoc 格式的实验性支持，由新的实验性功能 oid4vc-mdoc 提供。 提供了 Lissi 和 Valera 钱包的集成指南，以及 SD-JWT 签名密钥设置、凭证管理和撤销的文档。

此版本中提供了示例应用程序（仅供说明，未得到官方支持）：

  • 快速入门 OID4VCI 部署 - 使用 mdoc 和 SD-JWT 凭据进行 rapid 原型设计的游乐场

  • Keycloak FAPI 游乐场中的 OID4VCI 演示 - 可显示钱包和发行者之间交换的 OID4VCI 协议消息的详细信息，并说明证明、证明、凭证刷新等高级概念。

基于证明的 client 身份验证 (client-auth-abca)、预授权代码授予 (oid4vc-vci-preauth-code)、REST 凭据提供端点 (oid4vc-vci-rest-credential-offer) 和 OpenID4VP (oid4vc-vp) 仍然是实验性功能。

使用 OID4VP 验证凭据（实验）

采用可验证凭据的组织需要一种方法来接受来自数字钱包的凭据呈现作为登录流程的一部分，而不需要传统密码。

Keycloak 现在可以充当 OID4VP 验证程序，支持用户通过钱包提供可验证凭据的身份验证流程。 验证器支持跨设备呈现流和 direct_post.jwt 加密响应模式。 用于凭证验证的 Trust 材料可以通过别名委托给外部身份提供商，并且 SD-JWT 用户属性和会话映射器可用于从所提供的凭证中提取声明。

感谢 Dominik Schlosser 的贡献。

使用共享信号框架对账户状态变化做出反应（实验性）

实验性共享信号框架 (SSF) 支持现在在启用或禁用用户时发出 RISC account-disabled 和 account-enabled 事件类型，从而将覆盖范围扩展到 26.7 中附带的 CAEP 会话和凭证事件之外。此外，事件结构已进行了修订，以便更好地符合 CAEP 和 RISC 规范，并且管理事件存储不再接收未经验证的有效负载以防止 PII 泄漏。

有关更多详细信息，请参阅共享信号框架指南。

参数化（以前是动态）作用域预览支持（预览版）

参数化作用域（以前称为动态作用域）允许 clients 在 OAuth 2.0 授权请求中传递参数值以及作用域名称。当作用域表示具有大量或动态值集的实体（例如像 project:12345 这样的项目名称）时，这尤其有用，从而无需在 Keycloak 中预定义无数单独的 client 作用域。

参数化范围已正式从实验状态转变为预览状态。

有关该功能的更多详细信息，请参阅服务器管理指南。

经过同意的代币交换委托、FGAP 授权和审计跟踪（预览版）

人工智能代理和自动化工具等应用程序需要有限的、基于同意的访问权限才能代表用户执行操作，而不需要管理员权限或暴露敏感凭据。

用户现在可以使用新的 delegation:client: 参数化范围通过 OAuth 同意来委派对 client 应用程序的访问。 生成的令牌包含一个 act 声明，将 client 标识为参与者。 与管理员-用户委派不同，即使 client 持有服务帐户凭据，client 委派也不会授予管理员 API 访问权限，从而确保泄漏的委派令牌无法升级权限。 delegation:user 和 delegation:client client 作用域现在自动创建为所有领域中的可选作用域，并且委派授权仅通过使用 delegate 和 delegate-members 作用域的 Fine-Grained Admin Permissions V2 进行控制。 委托审计事件现在包括 client 身份，并且标准令牌交换会拒绝携带委托声明的主题令牌以防止绕过。 新的 client 策略执行器允许管理员限制访问令牌中的 may_act 声明，从而让每个 client 控制哪些 client 可以参与委托。

令牌交换委托支持状态现已预览。

有关更多详细信息，请参阅代币交换委托部分。

跟踪令牌生命周期和下游服务中的模拟

当管理员冒充用户时，下游资源服务器和审核系统没有可靠的方法来识别令牌是在模拟下颁发的或冒充者是谁。

令牌生命周期事件（CODE_TO_TOKEN、REFRESH_TOKEN 等）现在通过 impersonator 和 impersonator_id 详细信息进行了丰富，从而提供了在模拟下执行的所有令牌操作的完整审核跟踪。 此外，从模拟会话发出的令牌现在在访问令牌和 ID 令牌中都包含 act（参与者）声明（RFC 8693 部分 4.1），从而允许下游资源服务器识别模拟者。 该声明始终存在且无法禁用。

安全 client 集群节点注册

新的 client 策略执行器 secure-client-node-hostname 可通过旧适配器集群节点注册端点 (/clients-managements/register-node) 防止服务器端请求伪造 (SSRF)。 机密的 client 可以预先注册攻击者选择的主机名，Keycloak 稍后将其用作管理回调（例如注销传播和推送撤销）的目标。

当执行程序附加到 client 策略时，节点主机名会在保留之前根据管理员配置的正则表达式模式列表进行验证。不匹配任何模式的注册将被拒绝。

此保护是选择性加入的，必须明确配置才能生效。

管理使用旧适配器节点注册功能的部署的管理员应将 secure-client-node-hostname 执行器添加到 client 策略并配置允许的主机名模式。 主机名模式与 DNS 主机名和 IPv4 地址匹配。端口后缀始终被拒绝。模式与裸主机名或 IP 地址进行匹配。

管理

使用 Admin API v2 进行声明式 client 管理（预览版）

Client Admin API v2 作为 Keycloak 26.7 中的实验性功能引入，已升级为预览版。 现在可以使用 --features=preview 或 --features=client-admin-api:v2 启用它。

API 提供严格的验证、声明性配置和准确的 OpenAPI 规范，用于管理 OIDC 和 SAML clients。 它可以通过 Java client、自动生成的 JavaScript、client 和 CLI 来使用，并且 Keycloak Operator 使用它通过 KeycloakOIDCClient 和 KeycloakSAMLClient 以声明方式管理 client自定义资源。

Operator 的 KeycloakOIDCClient 和 KeycloakSAMLClient 自定义资源也升级为预览版。

有关更多详细信息，请参阅管理 API v2 指南和管理 Keycloak Clients 操作员指南。欢迎反馈！

Client 秘密轮换（支持）

在不停机的情况下在生产中轮换 client 密钥需要手动协调，并且如果旧密钥在所有使用者切换到新密钥之前失效，则存在服务中断的风险。

Client 秘密轮换允许机密的 client 通过 client 策略轮换其秘密，最多同时保留两个活动秘密，以实现无缝轮换，无需停机。 管理员可以规划轮换时间表并预测应用程序何时需要采用新密钥，从而降低密钥泄露的风险。

在此版本中，Client Secret Rotation 从预览版升级为支持版。 有关更多详细信息，请参阅服务器管理指南。

通过工作流程自动邀请用户

向新创建的用户发送邀请电子邮件之前需要外部自动化或调用管理员 REST API 的 execute-actions-email 端点。

新的invite-user工作流程步骤在创建用户时自动发送操作令牌电子邮件，无需外部工具或自定义工作流程步骤提供程序。 管理员可以配置用户必须完成哪些必需操作（默认为密码更新和电子邮件验证），并可以选择为完成后流程指定 client 和重定向 URI。

有关详细信息，请参阅定义步骤指南。

感谢 bilkoua 的贡献。

管理 REST API 的协议映射器允许列表

Client 策略现在提供 allowed-protocol-mappers 执行器来限制可以通过专用管理 REST API 协议映射器端点创建或更新的协议映射器类型。

SCIM API（支持）

SCIM（跨域身份管理系统）API 提供基于标准的界面，用于管理领域内的用户和组。它可以与支持 SCIM 协议的身份管理系统和应用程序无缝集成。

在此版本中，SCIM API 从预览版升级为受支持版。 SCIM API 获得了广泛的改进，包括对多值用户属性、用户配置文件权限、搜索过滤器中的细粒度管理权限的支持以及针对大型用户群的改进性能。 有关更多详细信息，请参阅通过 SCIM 管理用户和组文档。

配置和运行

多集群 v2（支持）

多集群 v2 允许使用无状态功能连接两个或多个 Keycloak 集群，而无需外部 Infinispan 集群。 会话数据存储在数据库中，相比多集群v1简化了部署架构。

在此版本中，多集群 v2 和 stateless 功能从预览版升级为支持版。 该功能默认处于禁用状态，可以使用 --features=stateless 启用。 针对裸机和虚拟机环境的新部署指南现已与现有的 Kubernetes 指南一起提供。 有关更多详细信息，请参阅<@links.ha id="multi-cluster-v2-introduction" />。

多集群 v1（已弃用）

多集群 v1（多站点 功能）已弃用，并将在未来的主要版本中删除。 推荐的替代方案是使用无状态功能的多集群 v2。 它消除了外部 Infinispan 集群及其跨站点复制，从而简化了部署架构。

如果您使用的是 --features=multi-site，请迁移到 --features=stateless。 有关迁移说明，请参阅高可用性指南中的从多集群 v1 迁移到 v2。

支持 TLS 证书和私钥的加密 PEM 文件

以前，使用加密私钥部署 Keycloak 需要将其转换为未加密格式或使用密钥库，从而增加了操作复杂性。

Keycloak 现在支持 PEM 格式的加密 PKCS#8 私钥进行 HTTPS 配置。 使用新的 --https-certificate-key-file-password 选项提供解密密码。 管理界面还通过 --https-management-certificate-key-file-password 支持此功能。 有关详细信息，请参阅<@links.server id="enabletls"/>。

登录失败现已存储在数据库中

暴力检测数据现在默认保留在数据库中，因此临时锁定的用户在集群重新启动后仍保持锁定状态。 使用多站点或无集群功能的部署继续将登录失败存储在外部Infinispan集群中。 以前的内存中行为可用作 login-failures:v1 但已弃用。 详情请参见升级指南。

集群和节点名称的一流 CLI 选项

现在可以使用新的 --cache-embedded-cluster-name 和 --cache-embedded-node-name CLI 选项配置嵌入式缓存集群名称和节点名称，替换以前所需的低级 SPI 选项。

默认情况下，节点名称是每次启动时生成的随机值，因此很难在重新启动时关联指标、日志和 JGroups 诊断。 设置稳定的节点名称对于 Grafana 仪表板和日志聚合等可观察性工具特别有用。

使用 Keycloak Operator 进行部署时，节点名称现在会自动设置为 Kubernetes pod 名称（例如 keycloak-0）。 对于 Kubernetes 上的独立部署，请使用向下的 API 设置 KC_CACHE_EMBEDDED_NODE_NAME 以注入 pod 名称。 对于非 Kubernetes 部署，请传递 --cache-embedded-node-name= 以及唯一标识每个节点的值。

自动为大型表创建非阻塞索引

在使用大型数据库表升级 Keycloak 时，之前在架构迁移期间会跳过索引创建，以避免阻塞启动。 操作员必须手动创建缺失的索引。

Keycloak 现在在 PostgreSQL、Oracle、MySQL/MariaDB 和支持的 Microsoft SQL Server 版本上使用非阻塞索引创建在启动后自动在后台创建跳过索引。 系统会自动检测并重新创建因先前尝试失败而留下的无效 PostgreSQL 索引。 在不支持非阻塞的数据库上，Keycloak 会继续记录 SQL 以便手动执行。

基于 Vert.x 的出站 HTTP client（实验）

Keycloak 使用 Apache HTTP Client 进行与外部服务（例如身份提供程序、OCSP 响应程序和反向通道注销端点）的所有传出连接。 由于 Keycloak 已经在 Vert.x/Netty 上运行用于入站流量，因此使用单独的 HTTP 堆栈进行出站连接会增加不必要的复杂性和依赖开销。

Keycloak 现在提供了一个基于 Vert.x 的实验性 HTTP client，它将所有传出连接的 Apache HTTP Client 替换为 Vert.x/Netty。 要启用它，请使用 --features=http-client:v2 启动 Keycloak。

启用后，所有传出 HTTP 流量都使用 Vert.x HTTP client。 现有配置选项的工作方式相同。

有关更多详细信息，请参阅配置传出 HTTP 请求指南。

Helm Chart Operator 安装（实验性）

Keycloak 现在发布了一个实验性 Helm 图表来安装 Operator。

有关安装说明，请参阅操作指南。

组织

跨组织共享身份提供商

身份提供商现在可以链接到多个组织，从而实现诸如单个企业身份提供商为不同业务部门或子公司（每个部门或子公司都代表一个单独的组织）的用户提供服务等场景。每个身份提供商链接都带有自己的自动会员资格和会员类型配置，允许对每个组织的用户加入方式进行细粒度控制。

域路由已从身份提供者移至域实体。每个域都可以独立指定哪个身份提供商处理身份验证以及用户是否自动重定向。域门可确保跨组织隔离 —“用户只会自动添加到声明其电子邮件域的组织中，即使多个组织共享相同的身份提供商也是如此。

将默认值升级为非托管成员资格类型后创建的新身份提供商链接。现有链接将随托管类型一起迁移，以保留以前的行为。

有关设置说明和常见配置模式，请参阅服务器管理指南中的常见设置方法。有关迁移详细信息，请参阅升级指南。

登录页面上的社交身份提供商部分已更新，包含更新的图标、新的分隔线布局和改进的按钮标签。
