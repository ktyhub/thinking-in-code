gpt-researcher v3.8.0

新的 UI，4 分钟内即可提供详细报告

Next.js 应用程序具有与 gptr.dev 匹配的新纸张设计。设置位于一个模式中，带有研究、MCP、文档和后端选项卡；一次运行会显示一个简单语言的提要，并且一旦开始编写，源边距就会滑入。之前的 UI 在 /classic 上仍然可用。

详细报告现在在 3:27（而不是 9:11）结束。各个部分是并行研究的，默认编写器现在是 gpt-6-sol，它会在几秒钟内开始编写，而不是先对每个部分进行近一分钟的推理。测量和模型比较在#2272 中。

⚠️ 需要注意的变化

  • 默认写入器型号： SMART_LLM 现在是 openai:gpt-6-sol（以前是 openai:gpt-5.4）。设置SMART_LLM以保留之前的型号。
  • LLM 空闲超时： 在 300 秒内不发送任何内容的 LLM 调用现在失败并出现明显错误，而不是挂起运行。使用 LLM_TIMEOUT 对其进行调整（0 禁用它）。 （＃2220）
  • Docker： 根 .env 不再复制到图像中。 docker compose 在运行时加载它（需要 Compose 2.24+）；使用 docker run，通过 --env-file .env。如果您曾经推送过本地构建的映像，请旋转 .env 中的密钥。
  • 现在，当每次 LLM 尝试失败时，generate_report 都会引发，而不是返回空报告。 (#2219)

也在这个版本中

  • 在 GHCR 上为 linux/amd64 和 linux/arm64 预构建 Docker 图像：ghcr.io/assafelovic/gpt-researcher 和 ghcr.io/assafelovic/gpt-researcher-frontend-nextjs，标记有版本和 latest (#1517)
  • 研究观察者： 一个可选的生命周期观察者，用于需要结构化进度事件的集成 (#2232)
  • MiniMax 区域提供商和 Flash 默认值 (#1924)、可配置的 TypeSafe 基本 URL (#2243) 以及使用 render.yaml 蓝图 在渲染器上部署 (#2184)
  • 来自 Web UI 的多代理计划审查反馈再次起作用，多代理编写器使用 SMART_TOKEN_LIMIT 和 REASONING_EFFORT (#2272)
  • 深度研究尊重推理预算，计算重试和嵌套研究人员的成本，并将引用的知识保持字数限制（#2260、#2209、#2208）
  • MCP 搜索不再阻止事件循环，并且强制执行 max_tools 上限（#2262、#2263）
  • 配置：JSON 配置文件中的 reasoning_effort、DOC_PATH / REPORT_SOURCE env 覆盖、UTF-8 配置文件和图像生成设置均再次生效（#2230、#2248、#2249、#2199、#2246）
  • 修复了 Exa、Google、Bing、Bocha、PubMed Central、arXiv、在线文档和 Windows 文本文件的检索器、抓取器和文档加载器
  • Retriever 插件：包含 Keenable 和 Sciverse 的社区列表（#2176、#2225）

此版本包含 53 个社区拉取请求。感谢所有做出贡献的人。

安装： pip install -U gpt-researcher (0.17.0)
