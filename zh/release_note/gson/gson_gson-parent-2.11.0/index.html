gson gson-parent-2.11.0

发布 发布时间2024年5月20日 来源google/gson 英文原文

gson gson-parent-2.11.0

  • 添加了默认的 ProGuard / R8 规则（@Marcono1234、#2397、#2420；@sgjesse、#2448；@sfreilich）
    如果您使用 ProGuard 或 R8（例如 Android 项目），如果您的类具有无参数构造函数并对其字段使用 @SerializedName，则可能不再需要任何特殊的 Gson 配置。
  • 在 Android 上，Gson 现在需要 API 21 级或更高版本
  • 添加了新的 Strictness API （@marten-voorberg 和同学，#2437）
    默认情况下，Gson 的一些 API 仍然很宽松，但您现在可以使用新添加的方法 GsonBuilder#setStrictness、JsonReader#setStrictness 和 JsonWriter#setStrictness 与 Strictness.STRICT 来覆盖此行为，并在解析时严格遵守 JSON 规范。
  • 新的 FormattingStyle 类允许在 JSON 输出中配置换行符（@mihnita，#2231）
    可以使用 GsonBuilder#setFormattingStyle 和 JsonWriter#setFormattingStyle 进行设置。
  • TypeToken 默认情况下无法再捕获类型变量（@Marcono1234，#2376）
    这以前是问题的常见来源。新抛出的异常参考了故障排除指南文章，该文章对此进行了更详细的解释，并提供了更新受影响代码的建议。
  • 使用自定义适配器添加了对匿名类和本地类的序列化支持（@Marcono1234，#2498）
    例如，这会影响由 Guava 等库返回的 List 实现，这些库被实现为匿名类，而这些类之前被序列化为 null。没有自定义适配器的匿名类和本地类仍将被序列化为 null。
  • 添加了对 com.google.errorprone:error_prone_annotations\ 的依赖 您的项目可以使用 Maven 或 Gradle 依赖项排除从 Gson 中删除可传递的 error_prone_annotations 依赖项。或者，如果您在项目中手动将依赖项维护为 JAR，则可以省略 error_prone_annotations。它应该仍然可以正常工作。
    但 Gson 本身确实将其声明为必需的依赖项，如果您不执行任何自定义配置，那么 Maven 或 Gradle 将默认尝试下载并使用它。
  • 许多异常消息现在参考故障排除指南 (@Marcono1234, #2357)
    感谢有关故障排除指南的反馈！
  • 官方记录表明可能不完全支持 Java 以外的 JVM 语言，请参阅 README。
  • 保证 JsonElement#toString 产生 JSON 输出（@Marcono1234，#2659）

其他变化

错误修复

  • 修复了大 BigInteger 值的不正确 JsonPrimitive#equals 结果（@MaicolAntali，#2311）
  • 修复了大 BigDecimal 值的不正确 JsonPrimitive#equals 结果（@MaicolAntali，#2364）
  • 修复了 JsonReader 抛出 NumberFormatException 而不是 MalformedJsonException 的错误 Unicode 转义序列（@MaicolAntali，#2337）
  • 修复了 TypeToken#getParameterized 返回非泛型类型的虚假 ParameterizedType （@Marcono1234，#2447）
  • 修复了 Java 记录适配器不适用于 GraalVM 本机映像（@eamonnmcmanus，#2465）
  • 修复了当前没有写入 JSON 对象时 JsonWriter#name 不抛出异常的问题（@shivam-sehgal，#2475；@Marcono1234，#2476）
  • 修复了 Gson#getDelegateAdapter 对于 @JsonAdapter 无法正常工作的问题（@Marcono1234，#2435）
    请注意，现在不再允许将 null 作为 skipPast 值，以前允许但未记录。
  • 修复了 GsonBuilder 不拒绝 Object 和 JsonElement 的类型适配器，其默认适配器不能被覆盖（@sachinp97；#2479）
  • 修复了反序列化 BigDecimal 和 BigInteger 时不强制执行的限制（@Marcono1234，#2510）
    新的限制可以防止用户代码使用反序列化数字时出现潜在的性能问题。 Gson 本身过去和现在都没有受到这些性能问题的影响。这些限制应该足够高，不会对大多数用例造成问题，但我们欢迎您提供反馈。
  • 修复了 GsonBuilder#setDateFormat 不拒绝无效日期格式的问题（@Carpe-Wang，#2538）
  • 修复了 GsonBuilder#setDateFormat 不拒绝无效日期样式的问题（@Marcono1234，#2545）
  • 修复了 GsonBuilder#setDateFormat 忽略部分 DEFAULT 样式的问题（@Marcono1234，#2556）
  • 修复了 TypeToken#isAssignableFrom 在某些情况下抛出 AssertionError 的问题（@Marcono1234，#2544）
  • 修复了日期适配器在解析后不恢复时区的问题（@Carpe-Wang，#2549）
  • 修复了 TypeToken#equals 在某些情况下错误地返回 false 以获得相同的泛型类型参数（@d-william，#2599）
  • 修复了 pom.xml 中不正确的继承 URL（@Marcono1234，#2351）

性能改进

  • 略微减少基于反射的适配器的内存使用量（@sembseth，#2325；@Marcono1234，#2440）
  • 提高了 ToNumberPolicy#LONG_OR_DOUBLE 的解析速度（@ctasada，#2674）

Gson维护

  • 更改了许多单元测试以使用 Truth 而不是 JUnit 进行断言（@MaicolAntali，#2299，#2304）
  • 配置了 Error Prone 以在编译时自动检查错误（@MaicolAntali，#2308）
  • 简化了测试中的预期异常处理（@elevne，#2454）
  • 添加了 GraalVM Native Image 的集成测试（@Marcono1234，#2466）
  • 根据 Google 风格指南格式化代码并配置 Spotless (@MaicolAntali, #2531, #2537)
  • 使 Maven 构建可重现（@Marcono1234，#2543）
  • 删除了内部 DateTypeAdapter 类以减少代码重复（@Marcono1234，#2546）
  • 由 Dependabot 更新的依赖项和插件

GitHub 存储库

  • 将默认分支从 master 重命名为 main
  • GitHub 讨论 已启用
    对于问题、想法、提示…
  • 添加了 GitHub 拉取请求模板（@Marcono1234，#2326）
  • 添加了对 Android API 兼容性的检查（@Marcono1234，#2431）
