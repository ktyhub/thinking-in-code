containerd v2.4.0

欢迎使用 Containerd 的 v2.4.0 版本！

containerd 2.4 是一个常规（非 LTS）版本，支持窗口较短， 适用于希望更快采用新功能的用户。随着发布 在 2.3 LTS 之后，这是发布周期中之前的点 已弃用的功能可能会被删除，因此此版本可能会破坏 变化；检查下面的注释并清除您的任何弃用警告 升级前的当前版本。

优先考虑稳定性和更长支持生命周期的用户应该继续关注 2.3 LTS 发布。

亮点

容器运行时接口 (CRI)

  • 为 CRI 中的映像安装启用安装管理器 (#13542)
  • 导出 CRI 插件信息中的沙箱镜像和 CNI 目录配置 (#13940)
  • 将默认的runtimeFeatures.UserNamespacesHostNetwork设置为true (#13162)
  • 支持非 runc 运行时的 OCI 运行时功能自省 (#13504)

图像分布

  • 在获取描述符 URL 时应用强化以去除敏感的身份验证标头 (#12889)
  • 支持将 HTTP 299 警告标头从注册表传播到解析器 (#12698)
  • 使用 klauspost/compress 进行 gzip 层解压 (#13560)

图像存储

  • 添加 client 选项，即使存在快照，也可以在解压过程中获取所有图层内容 (#14126)
  • 在内容创建事件中包含媒体类型 (#13833)
  • 添加对 GC 集合上下文的前向引用 (#13634)

节点资源接口 (NRI)

  • 向 NRI 插件公开容器镜像名称、摘要和配置摘要 (#13960)
  • 对使用已弃用的 NRI 接口的插件发出弃用警告 (#13916)

运行时

  • 默认情况下屏蔽 Linux 容器中的 /proc/interrupts 和 CPU 热节流 sysfs 路径 (#14090)
  • 添加 UpdateSandbox RPC 以将沙箱控制器更新传播到垫片 (#14105)
  • 避免在显式停止后立即使用 restart=always 策略重新启动容器 (#13993)
  • 将跟踪上下文从 shim 传递到 runc 和 hooks (#14036)
  • 修复包含符号链接 /etc/passwd 或 /etc/group 的容器 rootfs 中的用户和组查找失败 (#13818)
  • 在 pkg/shim 中实现 Windows 命名管道服务器和日志流支持 (#13948)
  • 在 Windows 上默认启用日志清理 (#13837)
  • 使用 runc 进行检查点时允许指定父检查点目录（#13699）

快照器

  • 为 EROFS 快照器层内容缓存添加 Prometheus 指标（#13941）
  • 支持erofs快照器的热图像缓存（#13813）
  • 添加快照最大尺寸标签 (#13520)

打破

  • 删除已弃用的 CRI 和跟踪配置选项：
    • 删除 CRI 运行时配置中的 enable_cdi（CDI 现在始终启用）
    • 删除 CRI CNI 配置中的 bin_dir（使用 bin_dirs）
    • 删除 OTLP 跟踪处理器配置中的 endpoint、protocol 和 insecure（使用标准 OTLP 环境变量）
    • 删除内部跟踪配置中的 service_name 和 sampling_ratio (使用标准 OpenTelemetry 环境变量) (#14166)
  • 删除 CreateContainer 中的恢复 (#13871)

弃用

  • 弃用containerd.io/runtime-allow-mounts shim注释，转而使用MountCapability引导扩展（#14002）
  • 从 pkg 中删除已弃用的 shim.Command (#13991)
  • 弃用 runc 选项中的任务 API 地址和版本字段，并移至 CreateTaskRequest (#13360)

请尝试发布二进制文件并报告任何问题 https://github.com/containerd/containerd/issues.
