envoy v1.40.0

小版本 发布时间2026年10月13日 来源envoyproxy/envoy 英文原文

envoy v1.40.0

变更摘要

重大变更

  • build：Envoy 已从 WORKSPACE 切换到 bzlmod。 WORKSPACE 文件被删除； Envoy、API 和文档作为 Bazel 模块（envoy、envoy_api、envoy-docs）发布。下游必须迁移到 MODULE.bazel，并且必须将 Envoy 的自定义注册表 (https://raw.githubusercontent.com/envoyproxy/bazel-registry) 与 BCR 一起添加 - 许多 Envoy 的依赖项和修补的模块仅在那里发布。
  • 构建：密封的 LLVM/Clang 工具链从 18 增加到 22。--config=clang 和 clang-local 被删除 - Clang/libc++ 现在是默认值，不需要标志； GCC 仍然通过 --config=gcc。 --@envoy//bazel:libc++/libstdc++ 标志和 force_libcpp 定义消失了。需要主机 LLVM 工具链的下游应遵循 bazel/tests/codeql。
  • 构建：Wasm 运行时现在选择 --@proxy-wasm-cpp-host//bazel:engine=<engine>；旧的 --define wasm=/--define engine= 标志无法构建。
  • tls：AWS-LC 作为可选 SSL 库（包括 --config=aws-lc-fips）被删除。 ppc64le 构建应使用 --config=openssl。
  • mcp_router：默认情况下，下游请求标头不再转发到后端 - 特别是 authorization。使用新的每后端 header_forwarding（forward_all: true 恢复旧行为）。
  • 动态模块（Rust SDK）：HttpFilter 挂钩现在采用 &self 而不是 &mut self；每个流的可变状态必须移动到内部可变性之后。这将关闭同步过滤器链拆卸的释放后使用。

主要变化

  • HTTP/3 和 QUIC 现已稳定，包括上游 HTTP/3 和所有 QUIC 扩展。 QUIC 侦听器获得 client 证书 (mTLS) 支持，上游 QUIC 获得 client 证书，并支持 P-384/P-521 ECDSA 曲线。
  • 默认后量子：X25519MLKEM768 混合密钥交换添加到上游和下游 TLS 的默认 ECDH 曲线中，包括 FIPS 构建（可通过 envoy.reloadable_features.pqc_default_ecdh_curves 可恢复）。
  • 路由在匹配后变得可扩展：新的 route_specifiers 扩展点在路由配置、虚拟主机和路由级别对匹配的路由进行后处理（细化、删除或合成）。优先级组集群说明符和动态模块路由说明符构建在其之上。
  • 负载平衡：新的 per_worker_subset 策略将每个工作线程池大小与集群大小分离；新的 load_aware_locality 政策根据 ORCA 衍生的空间来选择地区；现在默认启用 EDS 批量更新上的合并 LB 重建。
  • 容器感知 CPU 检测实际上默认开启 — 1.37 行为仅在 --cpuset-threads 上有效；现在，只要 --concurrency 未设置，它就会适用。
  • Drain 是事件驱动的：Drain 关闭决策在 Drain 启动时推送到连接，而不是根据响应进行轮询，这也修复了 Mongo/Redis/Thrift/generic 代理的仅入站 Drain。
  • UDP 热重启：已建立的 UDP 代理会话由父级保留，而未知会话数据报将转发给子级，因此无连接侦听器在耗尽期间不再变黑。

人工智能/MCP

  • AI Protocol Manager 过滤器 (alpha) 获得 OpenAI、Anthropic 和 Gemini 方言（SSE 和 JSON）的响应端 LLM 令牌使用提取，作为类型化动态元数据 (envoy.data.ai.v3.TokenUsage) 发布，以及请求信息、模式验证和转码子过滤器以及主体重新序列化。
  • MCP 过滤器：每条路由配置、协议版本强制、所需的 client 功能、新方法组、无操作模式和可路由时的提前终止。 JSON/REST 桥添加了服务器发现、标头/协议版本验证和结果类型，现在通过模板变量防止路径遍历。

动态模块

  • 新的扩展点：集群说明符、路由说明符、标头格式化程序、早期标头突变、TLS 握手器、传输套接字中继、配置验证器和下游 STARTTLS。
  • 动态模块集群现在可以将主机选择委托给 Envoy 的内置 LB（ROUND_ROBIN、LEAST_REQUEST、RANDOM、RING_HASH、MAGLEV）。
  • 广泛强化：跨 HTTP、网络、侦听器和集群 LB 过滤器状态的大量生命周期/视图修复、延迟 HTTP 过滤器销毁、Go 和 C++ SDK 中的恐慌/异常屏障、标注的重入修复以及带有记录的加载失败的 RTLD_NOW 加载。
  • 类型化元数据获取/设置、运行时获取器、跨挂钩跟踪、流计时、上游尝试/对等地址访问器以及 Go SDK 统计/日志级别获取器。

安全和授权

  • 推进 1.39.x 安全修复：路径参数的 URL 规范化 (CVE-2026-73511/73551)、HTTP/2 预告片无 END_STREAM 和丢弃的 Host 记帐 (CVE-2026-73513/73550)、HTTP/3 UAF (CVE-2026-73512)、ext_authz无路径请求崩溃和 UAF (CVE-2026-73547/50572)、通用升级正文管道 (CVE-2026-73548)、safe_regex Latin1 模式 (CVE-2026-73552)、RBAC ignore_path_parameters (CVE-2026-73553)、管理统计名称清理(CVE-2026-73546)，oauth2/api_key_auth CONNECT 崩溃（GHSA-8vc2-jrm4-835w、GHSA-47vj-9r25-wv5j）、Brotli 解压缩器中的越界写入 (GHSA-3wvj-j6qm-62mr)。
  • TLS：每个证书的 TLS 参数、带有证书选择器的多个上游证书、SPIFFE 上游 SAN 验证、SDS 文件轮询以及 SNI 范围内的上游会话缓存。
  • OAuth2 为凭证注入器获得断言受众/密钥 ID 和 TLS client 身份验证； JWT auth 获得声明路径和 JWT 声明速率限制描述符； GCP 身份验证获得范围、受众和 IAM 访问令牌； ext_authz 在网络过滤器和路由缓存清除标头上获得影子模式。

可观察性

  • 访问日志：下游握手时间点和连接 RTT、侦听器名称和路由解析时间格式化程序、CEL 表达式格式化程序配置和纳秒直方图单位。
  • OpenTelemetry：资源检测器、自定义导出器、检测范围和类型自定义标签； ext_authz 和 ext_proc 发出 client 跨度。
  • 统计：每个集群/侦听器统计匹配器、显式标签以及修复 Prometheus 本机直方图存储桶索引偏离 1 的问题。

其他值得注意的变化

  • HTTP/1 现在接受 RFC 10008 QUERY 方法（可恢复）；没有 Content-Type 的 QUERY 在所有协议上都会被拒绝。
  • Redis 代理：RESP3 协议支持、CLUSTER SHARDS、更严格的 RESP 解码以及多项释放后使用修复。
  • 反向隧道：JWT 握手身份验证、维护间隔、失败关闭标识符验证以及一批握手生命周期修复。
  • 看门狗回溯操作、UDP 运行状况检查器、多运行状况检查器、TCP 代理负载卸载点和正文大小限制 HTTP 过滤器。
  • 修复了一系列竞赛，其中路由级配置（AWS 签名、复合、过滤器链、本地速率限制、动态模块、SDS 机密）可能会在 RDS 更新后在工作线程上被销毁。

弃用

  • envoy.extensions.config.validators 工厂由 URL 类型键入；动态模块日志和计时信息回调；遗留 HTTP 过滤器工厂基类；反向隧道 auto_close_connections； Wasm 插件级能力限制。 Docker 图像： https://hub.docker.com/r/envoyproxy/envoy/tags?page=1&name=v1.40.0 文档： https://www.envoyproxy.io/docs/envoy/v1.40.0/ Release note： https://www.envoyproxy.io/docs/envoy/v1.40.0/version_history/v1.40/v1.40.0 完整 changelog： https://github.com/envoyproxy/envoy/compare/v1.39.0…v1.40.0 签署人：Jonh Wendell jwendell@redhat.com 签署人：Ryan Northey ryan@synca.io
