GitHub ディスカッション</p>でフィードバックを歓迎します。 </div> <div class="段落"> <p>管理インターフェイス上の OpenAPI エンドポイントと Java 管理者 client に貢献してくれた <a href="https://github.com/robson90">Robin Meese</a> に感謝します。 そして、Admin API ワーキング グループと Go client 分析に参加してくれた <a href="https://github.com/sschu">Sebastian Schuster</a> に感謝します。</p> </div> </div> <div class="sect3"> <h4 id="_fine_graned_delegation_for_organization_administration">組織管理のためのきめ細かい委任</h4> <div class="段落"> <p>Keycloak で組織を管理するには、以前は <code>manage-realm</code> ロールが必要でした。これは、ほとんどの組織管理者が必要とするよりもはるかに多くのアクセス権を付与する高特権ロールです。このリリースでは、組織に専用の管理者ロールときめ細かい管理者権限が導入され、管理者はアクセスを過剰にプロビジョニングすることなく組織の管理を委任できるようになります。</p> </div> <div class="段落"> <p>新しいレルム管理者の役割は、大まかな委任を提供します。</p> </div> <div class="ulist"> <ul> <リ> <p><code>manage-organizations</code> — 組織とそのメンバーの作成、更新、削除を含む、組織への完全な読み取りおよび書き込みアクセスを許可します。</p> </li> <リ> <p><code>view-organizations</code> — 組織とそのメンバーに読み取り専用アクセスを許可します (ユーザーを表示するには、<code>view-users</code> または詳細な管理者権限も必要です)。</p> </li> <リ> <p><code>query-organizations</code> — <code>query-users</code> / <code>query-clients</code> / <code>query-groups</code> パターンと一致し、完全なビュー アクセス権を持たずに組織を検索およびリストする機能を付与します。</p> </li> </ul> </div> <div class="段落"> <p><code>manage-realm</code> ロールは、下位互換性を確保するために、組織への完全な管理アクセスを暗黙的に付与し続けます。</p> </div> <div class="段落"> <p>組織ごとの粒度の点で、組織は、きめ細かい管理者権限のファーストクラスのリソース タイプになりました。管理者は、委任された管理者が表示または管理できる特定の組織を制御する権限を作成できます。たとえば、レルム内のすべての組織にアクセス権を付与せずに、1 つの組織を管理するためのアクセス権を付与することができます。きめ細かい管理者権限が有効になっている場合、組織メンバーのクエリではユーザーレベルの権限も考慮され、管理者が表示を許可されているメンバーのみが返されます。</p> </div> </div> <div class="sect3"> <h4 id="_automatic_role_inheritance_through_organization_groups">組織グループによる自動ロール継承</h4> <div class="段落"> <p>組織に同じ権限を必要とするユーザーが何百人もいる場合、組織の個々のメンバーにロールを割り当てることは適切に拡張できません。組織グループはレルムと client ロールの割り当てをサポートするようになりました。そのため、管理者はロールを組織グループに一度割り当てると、そのロールがすべてのグループ メンバーの <code>realm_access</code> および <code>resource_access</code> トークン クレームに自動的に表示されるようになります。</p> </div> <div class="段落"> <p>さらに、<strong>組織グループ メンバーシップ</strong> プロトコル マッパー (OIDC および SAML) は、[<strong>グループ ロール マッピングの追加</strong>] 構成オプションを有効にすることで、組織ごとに編成された <code>organization</code> クレーム内にこれらのロールを含めることができます。</p> </div> <div class="段落"> <p>詳細については、「<a href="https://www.keycloak.org/docs/26.7.0/server_admin/#_managing_groups_">組織グループの管理</a>」ガイドを参照してください。</p> </div> </div> <div class="sect3"> <h4 id="_better_passkey_compatibility_with_new_webauthn_policy_options">新しい WebAuthn ポリシー オプションによるパスキーの互換性の向上</h4> <div class="段落"> <p>パスキーを使用すると、ユーザーはパスワードの代わりに生体認証またはセキュリティ キーを使用してサインインできます。正しく動作するには、サーバーはブラウザに、検出可能な認証情報 (デバイスに保存されているパスキー) を優先するかどうかを伝える必要があります。また、以前の Yes/No オプションでは、一般的になりつつある <code>preferred</code> 値を表現できませんでした。</p> </div> <div class="段落"> <p>WebAuthn ポリシーと WebAuthn パスワードレス ポリシーでは、現在の <a href="https://www.w3.org/TR/webauthn/#dom-authenticatorselectioncriteria-residentkey">WebAuthn 仕様</a> に準拠した <code>検出可能な認証情報</code> オプションが提供されるようになり、<code>required</code>、<code>preferred</code>、および <code>discourated</code> の値がサポートされます。これにより、iCloud キーチェーン、Google パスワード マネージャー、1Password などのパスキー プロバイダーとの互換性が向上します。以前の <code>検出可能な認証情報が必要</code> オプションは現在非推奨となっており、将来のリリースで削除される予定です。</p> </div> </div> <div class="sect3"> <h4 id="_easier_realm_discovery_by_display_name_search">表示名検索によるレルム検出の容易化</h4> <div class="段落"> <p>管理者はレルムに短い技術名 (<code>acme-prod</code> など) を付けることがよくありますが、人間が判読できる表示名 (<code>Acme Corporation</code> など) を設定します。以前は、管理コンソールの検索は技術的なレルム名とのみ一致するため、大規模なマルチテナント展開でレルムを見つけることが困難でした。</p> </div> <div class="段落"> <p>レルム検索では、レルム名に加えて表示名と照合するようになりました。そのため、管理者は覚えている名前でレルムを検索できます。</p> </div> </div> <div class="sect3"> <h4 id="_type_safe_validation_for_parameterized_scopes_experimental">パラメータ化されたスコープのタイプセーフ検証 (実験的)</h4> <div class="段落"> <p>パラメータ化されたスコープを使用すると、OAuth clients でコンテキスト固有のアクセスをリクエストできます。たとえば、<code>project:12345</code> で特定のプロジェクトへのアクセスをリクエストしたり、<code>account: Savings</code> でトークンのスコープを特定の銀行口座に限定したりできます。以前は、パラメータ値はオプションの正規表現によってのみ検証されていたため、無効な値または予期しない値を渡すことが簡単でした。</p> </div> <div class="段落"> <p>パラメータ化されたスコープで、リクエスト時にキャプチャされた値を検証するパラメータ タイプを定義できるようになりました。組み込みタイプには、<code>string</code>、<code>integer</code>、<code>boolean</code>、<code>username</code>、および <code>custom</code> (管理者が定義した正規表現に対して検証済み) が含まれます。この機能を有効にしてパラメータ化されたスコープを作成する場合、トークンが常に適切な形式のスコープ パラメータを確実に保持できるように、このタイプは必須です。</p> </div> <div class="段落"> <p>詳細については、<a href="https://www.keycloak.org/docs/26.7.0/upgrading/">アップグレード ガイド</a>を参照してください。</p> </div> </div> <div class="sect3"> <h4 id="_Additional_datasources_may_be_excluded_from_health_checks">追加のデータソースがヘルスチェックから除外される場合があります</h4> <div class="段落">
