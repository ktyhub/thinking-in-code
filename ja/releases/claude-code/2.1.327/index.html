claude-code v2.1.327

パッチ 公開日2026年11月17日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.327

何が変わったのか

  • /install-github-app がリポジトリを変更する前の確認を追加しました
  • サーバーの JSON を標準入力から読み取るための claude mcp add-json <name> - を追加しました。これにより、トークンがコマンド ラインから外れるようになります。クロードコードセッション内では利用できません
  • 再開されたセッションの以前のメッセージを読み込めない場合の行を追加しました
  • /status に、壊れたエージェント、スキル、コマンドおよび出力スタイル ファイル、キーバインド エラー、利用できないサンドボックス、無視された権限設定、一致しないフック マッチャーのリストを追加しました。
  • 他の設定が行をオーバーライドする場合のメモを /config に追加しました
  • ゲートウェイ ヒント ヘッダーに x-claude-code-managed-settings-checksum を追加しました。管理設定が CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 を設定する場所 (すでに実行されている場所を含む) に送信されます。
  • admin.billing_group_tag を設定するクロード アプリ ゲートウェイに対して、attributionProject 設定を使用してセッションの請求グループに名前を付けるためのサポートを追加しました。
  • 非フルスクリーン レンダラーの名前として /tui classic を追加しました。 /tui defaultはまだ動作します
  • リモート コントロール: ワークツリー モードでサーバーを停止し、実行中のセッションの git 無視ファイル (.env など) を削除する問題を修正しました。
  • --use-anthropic-git-proxy を使用したセルフホスト ランナーが、起動時に GIT_CONFIG_GLOBAL で指定された空でないディレクトリを削除する問題を修正しました。ランナーはそれを保持し、変数を無視して警告するようになりました。
  • $schema や別のツールの servers など、.mcp.json から他のトップレベル キーを削除するプロジェクト スコープの claude mcp add および claude mcp remove を修正しました。
  • /export が質問せずに既存のファイルを上書きする問題を修正しました。ダイアログで質問が表示され、/export <name> はファイルを保持し、/export を実行するよう指示します。
  • 機能フラグが読み込まれていないクラウドおよびセルフホストランナーセッションで、再起動後に承認が到着したときに、[停止]を押した後も実行を許可していたコマンドを修正しました
  • Enterキーで/teleportのロードエラー画面を閉じる問題を修正
  • click に続いて /plugin で Enter キーを押してプラグインをインストールまたは無効にする問題を修正しました
  • 使用制限メニューの後の追加の Enter キーで実行される半入力の ! コマンドを修正しました
  • 内容に括弧が含まれているいくつかの --disallowedTools ルールを修正しました
  • PowerShell(.\scripts\build.ps1 *) など、.\ でスクリプト名を指定する一部のワイルドカード PowerShell 許可ルールを無視する自動モードを修正しました。
  • クロードが自動モードでも許可されている 2 番目のスクリプトを開始すると、自動モードで実行中のコード モード スクリプトが許可のプロンプトと拒否を取得する問題を修正しました
  • 事前に開始された一部のバックグラウンド セッションがアカウント変更後に破棄されるように変更されました
  • ターミナルの使用制限で一時停止されたワークフローが、ログイン後、前のログインに戻るかプロンプトを入力するまで一時停止されたままになるように変更されました。
  • forceLoginOrgUUID によって拒否される独自のトークンを持つネストされた claude を修正しました。セッションのトークンを取得しないコマンドは、その CLAUDE_CODE_OAUTH_SCOPES を取得しなくなります。必要なものに設定します
  • プロセスが強制終了された後に同じ UUID でメッセージが再送信された場合、ヘッドレス セッションが再開時に保存されたメッセージを失う問題を修正しました。
  • 別のクラッシュやバックグラウンドへの移動後に、空の応答または強制終了されたコマンドが応答を失った後、または巻き戻されたプロンプトが戻された後にセッションが再開されるケースを修正しました。
  • クロード コードがクラッシュした場合、再起動中に [停止] が押された後に送信されたメッセージを忘れてしまうリモート セッションを修正しました。
  • /clear が失われた後に作成されたタスクを修正し、機能フラグが読み込まれていないクラウドまたはセルフホスト ランナー セッションが後で再開されると、クリアされたタスクが戻ってくる
  • 出力トークン制限で返信がカットされた直後の圧縮により、その返信のツール呼び出しとその結果が失われる問題を修正しました。
  • /config からの設定変更と同様のコマンドが警告なしで保存に失敗する問題を修正しました。プロンプトの下の行にその旨が表示されるようになりました
  • 一部のファイルを復元できなかった場合に、何も言わずに /rewind が終了する問題を修正しました。
  • プロンプトが /tmp/a.txt などのファイル パスで始まるときに貼り付けられた画像がドロップされる問題を修正しました
  • プラグインがロードまたはリロードされると、--agents で渡されたエージェントが失われる問題を修正
  • --resume ピッカーからセッションを再開するときにプラグインのエージェントがドロップされる問題を修正しました
  • https_proxy または HTTPS_PROXY がベア host:port で、その入力も出力も端末 (デスクトップ アプリ、SDK、cron) ではない場合、クロード コードの起動が拒否される問題を修正しました。
  • Linux 上の Claude コードが、Claude アプリ ゲートウェイへの最初のサインイン後やコード モードをオンにしたときなど、起動時に再起動中にシェルに戻ることがある問題を修正しました。
  • プロキシなどでモデルの設定の取得が停止したときに、最初のリクエストの前に claude -p がハングする問題を修正しました。 10秒後にはそれらなしで続行されるようになりました
  • 短いメモリ不足エラーの後に画面が空白またはフリーズしたままになる問題を修正
  • 画面がフリーズしたりセッションが終了したりする可能性のあるまれな表示障害を修正しました
  • プログラムがセッションのネットワーク プロキシに対して数千の接続を開いたままにするとクラウド セッションが中断される問題を修正
  • MOD の $.model.complete または $.model.classify 呼び出しが使用制限に達したときのターンハングを修正しました。呼び出しはすぐに API のエラーを取得するようになりました。 MODはそのエラーを処理する必要があります
  • 数千の閉じられていないタグを含む圧縮応答や一部の非常に長い WebFetch URL でのストールを修正しました。 WebFetch は、許可プロンプトの前に 2,000 文字を超える URL を拒否するようになりました。
  • クロードが返信する前に数千の @ メンションが表示されるメッセージが停止する問題を修正しました。最初の 100 件のみがファイルとして検索されるようになりました
  • 非常に大きなファイルへの書き込みを拒否した後のプロンプトのフリーズを修正しました。拒否された書き込みには短いプレビューが表示されるようになりました
  • /plugin でキーのバーストが検索ボックスに到達したときのクラッシュを修正しました
  • Linux セキュリティ ポリシーがプロセス自体のシグナル送信をブロックする、一時停止されたセッションの再開時または終了時の誤ったクラッシュ レポートと終了コードを修正しました。
  • VPN ドロップなどの長時間の停止の後、リモート MCP サーバーが切断されたままになる問題を修正しました。https 経由でホスト名によってアクセスされた他のマシン上のほとんどのサーバーは、バックグラウンドで約 1 日再試行されるようになりました。
  • クロードがすでに完全に読み込んでいたプロジェクト外の未変更ファイルを圧縮した後、「ファイルはまだ読み込まれていません」と編集を拒否する問題を修正しました。
  • head_limit および offset でページングするときに Grep で結果が繰り返されるかスキップされる問題を修正しました。コンテンツとカウントの結果がファイル パスで並べ替えられるようになりました。
  • 不明なタイプの出力を含む Jupyter ノートブックで読み取りが失敗する問題を修正
  • ノートブック ファイルの最後の改行を削除する NotebookEdit を修正しました
  • 10 MB 以上のファイルが一度に読み取るには大きすぎる場合、読み取りツールが実際のサイズではなく 512 KB を報告する問題を修正しました。

  • 新しいアーティファクトごとに承認が必要な組織において、承認した新しいアーティファクトがクラウドのスケジュールされたタスクのセッションで拒否される問題を修正しました
  • 新しいアーティファクトごとに承認が必要な組織で、エージェント SDK 上に構築されたアプリが承認した後に新しいアーティファクトが拒否される問題を修正しました
  • リストのさらに多くのリクエストが失敗したときにリストの一部、または「成果物はまだありません」を表示する /artifacts を修正しました。再試行し、リスト全体をロードできない場合は警告するようになりました。

  • 認識されないモデルに対する長い返信の改善: 32,000 出力トークンでの返信カットは、128,000 の制限で継続されるようになりました。
  • 圧縮後の完了したサブエージェントに関するリマインダーを改善しました。クロードがエージェントの出力ファイルを読み取れない場合、SendMessage でエージェントに問い合わせるように指示されるようになりました。
  • API キーと Anthropic プロファイルの両方が設定されている場合に表示される警告を改善しました。どちらが使用されているか、およびそのプロファイルに切り替える方法が表示されるようになりました。
  • /pluginの改善: マーケットプレイスを削除する前の質問に、そのプラグインの設定と保存されたデータが削除され、マーケットプレイスのページに別のマーケットプレイスのエラーが表示されなくなると表示されるようになりました。
  • Windows: PowerShell の標準インストール場所を一度に確認することで、Git Bash や PATH 上の pwsh を使用しない場合の起動時間が短縮されました。 System32 の powershell.exe が PATH で以前の 1 つよりも優先されるようになりました
  • PATH が Git for Windows の bin フォルダーを指している場合、ランチャー経由ではなく git.exe を直接起動することで、Windows での起動時間を改善しました。
  • Windows: PowerShell ツールの速度がコマンドごとに最大約 0.5 秒向上しました。
  • 自動およびバイパス許可モードで Bash ツールの変更されたファイルの差分がすぐに準備できるようになるまでの時間を改善しました
  • macOS および Linux 上の非常に深くネストされた欠落パスに対する Bash 権限チェックと、URL を含む非常に長いテキストに対するシークレット マスキングの速度が向上しました。
  • 編集内容や書き込まれたファイル内のテキストを検索するためのトランスクリプト検索の改善
  • 大きな PNG 画像の読み取り速度が向上し、代わりに送信される JPEG の品質が向上しました。
  • アーティファクトのページに表示されるアドレスによってアップロードされたファイルを読み取るようにアーティファクト ツールを改善しました。他のフォームは依然として失敗し、ほとんどの場合、ID ごとに呼び出しごとに 1 つのアップロードを読み取るように指示するメッセージが表示されます。
  • アーティファクト ツールが改善され、prompt、limit、label を使用しない一部の呼び出しでは、呼び出しが失敗するのではなく無視されるようになりました。
  • /mcp の MCP サーバー ページの改善: ローカル、リモート、エージェント サーバーは 1 つのレイアウトを共有し、メニューは「戻る」で終わり、スクリーン リーダー モード以外ではアクションに番号が付けられなくなりました。矢印キーと Enter を使用します
  • 改良された狭い端末: /status、フォームと詳細画面のレイアウトが改善され、/model と /effort は約 40 列に収まり、←/→ to adjust などの重要なヒントはそのまま表示されます。
  • 改良された /install-github-app: リポジトリ、シークレット、および API キーのステップでは、標準のリストとキーが使用され、メッセージが短くなり、スピナーが表示され、エラーが明確になりました。
  • /desktop の改善: ダウンロードの質問は、y/n ではなく標準リストです。
  • 未保存の作業を保持している可能性のあるワークツリーを削除する前に確認するように ExitWorktree を変更しました。許可ルール、自動またはバイパス許可モードで許可されていない限り、質問禁止モードまたは誰も応答できない状態で拒否されます。
  • .mcp.json が mcpServers キーを持たずにサーバーを最上位にリストする場合に、ファイルを上書きするのではなく、claude mcp add --scope project を停止するように変更しました。
  • ほとんどの許可プロンプトの矢印キーを、折り返さずに「いいえ」で停止するように変更しました。最後の答えの後の数字は「いいえ」に移動します
  • 一部のシンボリック リンクを拒否するようにパス チェックを変更しました。
  • 作業ディレクトリ内としてカウントされるものが変更されたため、一部のパスが許可を求めるようになりました
  • permissions.blockReadsOutsideWorkingDirectories を変更して、バイパス モードと自動モードでより多くの Bash コマンドについて質問し、自動モードでは一部を拒否するようにしました。
  • 読み取りまたは編集の拒否ルールに基づいてパスを指定する Bash コマンドをさらに拒否するように permissions.blockReadsOutsideWorkingDirectories を変更しました。
  • 自動モードの課金分類子リクエストへのフォールバックに関する通知を変更し、今後のリリースではフォールバックが削除されると記載しました。チェックされる各アクションについて質問されるか、拒否されます。
  • Bash(pnpm dlx *) などのパッケージを実行する許可ルールと、すでに無視されているもののパスまたはバージョン形式 (/usr/bin/npm run:*) を無視するように自動モードを変更しました。安全性チェックがそれらを決定します
  • /sandbox およびほとんどの /config 値リストが、スクリーン リーダー モード以外では番号なしになるように変更されました。矢印キーと Enter を使用します
  • 変数が非常に長いテキストに展開される Bash コマンドは拒否され、より短い値またはファイルを使用するようにというメッセージが表示されるように変更されました。
  • 名前を付けるルールの下でも、もう 1 つのコマンドの前に質問するように PowerShell ツールを変更しました。何も応答しない場合、ツール全体のルール、自動モード、またはバイパス権限モードで許可されていない限り、拒否されます。
  • 兄弟のメッセージによって再開されたサブエージェントがセッションの権限設定に従うように変更されました。今では尋ねられるかもしれないし、誰も答えられない場合には拒否されるかもしれない
  • ワークツリーの横にあるフォルダーではなく、Bash サンドボックスにそのフォルダーを与えるために、起動フォルダーの横にある相対 --add-dir を使用して --worktree を変更しました。
  • 一部の --worktree が、.. など、起動フォルダーの上の相対 --add-dir で始まり、Bash サンドボックスと --bg セッション、ワークツリーのみを提供するように変更されました。
  • 一部の認証情報ファイルのアップロードを拒否するように Chrome のクロードを変更しました。それらを自分でページに添付してください
  • 新しいアーティファクトごとにアーティファクトの承認を必要とする組織におけるアーティファクトの承認を変更しました。プラグインが作成または許可したアーティファクトのみを拒否できます。
  • それぞれの承認が必要な組織で、新しいアーティファクトを一度に拒否するよう誰も要求せず、許可プロンプトなしでセッションを変更しました。
  • 設定がアーティファクトをオフにすると、既に実行中のセッションでも通話を拒否するようにアーティファクト ツールを変更しました。
  • アーティファクトの公開プロンプトを変更して、サブエージェントでの「次回からは尋ねない」の提供と、バックグラウンド タスクの結果、他の人のメッセージ、または圧縮後の提供を停止しました。
  • claude plugin eval を変更して、プラグインの許可フックに対する拒否ルールを維持し、フックの呼び出しにフラグを立てて通過させるようにしました。
  • 完全な内容ではなく、引き出しリクエストとフック応答のモード、アクション、フィールド名を記録するように MCP サーバー ログを変更しました。
  • fg で再開した後、ほとんどのプロンプトが Esc 以外の回答をしばらく無視するように変更されました。
  • インストールされた MOD フック ツールの呼び出し時に開始を拒否しないようコード モードを変更しました。管理者は管理設定でコード モードをオフのままにすることができます
  • モデルなしで起動されたサブエージェントが、/model 以降を含め、再開時に開始されたモデルに留まるように変更されました。
  • モデルの最初のサブエージェントを、Anthropic からのそのモデルの設定なしで開始するのではなく、最大 1.5 秒 (claude -p では 10) 待機するように変更しました。
  • 再起動されたバックグラウンド サブエージェントと、自動的に起動するターンが、プラグインのロードを待機するように変更されました。
  • クロードによって実行される claude --bg など、別のクロード コード セッションが開始したセッションのほとんどの起動プロンプトを除外するようにプロンプト履歴を変更しました。
  • Amazon Bedrock、Google Vertex AI、Microsoft Foundry のターミナル セッションでのサブエージェントの進行状況の概要が、はるかに少ないトークンを使用して、会話全体ではなく短いメモから書かれるように変更されました。
  • 最初のリクエストの前に実行する git コマンドの数を減らすために、非対話型 (-p) モードを変更しました。
  • 設定を変更できないリモート VS Code、Cursor、Devin Desktop セッションでの端末のセットアップをスキップするように初回実行セットアップを変更しました。
  • フルスクリーンのテキスト選択を変更して、システム、思考、受信メッセージ行のグリフを除外しました
  • リポジトリのフラグとプラグイン配信設定をより多く無視するように Anthropic がホストするクラウド セッションを変更しました。 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC は現在、最大でも DISABLE_TELEMETRY として機能します
  • [VSCode] エクスプローラーの右側の click メニューに「クロード コード: チャットに追加」を追加しました。これにより、チャット内で選択されたファイルとフォルダーが @ メンションされます。
  • [VSCode] PreToolUse フックが確認を求めるときに与える理由が表示されない許可プロンプトを修正しました (anthropics/claude-code#85950)
  • [VSCode] 許可プロンプトのタイトルで長いツール名とファイル名が切り取られる問題を修正
  • [VSCode] ユーザーが入力し、クロードが同じファイルを再度編集した後、以前に提案された編集内容が表示されるターミナル セッションの差分を修正しました。
  • [VSCode] Escape がフィードバックや「カスタム スタイルの構築」ダイアログ、@ メンション メニュー、モデル、モード、「+」メニュー、または別のポップアップを閉じるときにクロードの応答も停止する問題を修正しました。
  • [VSCode] クロードが連続して複数の編集を行うときの速度が向上しました。キューに入れられた編集は、新しい問題を待つ 1 つを共有します。後の編集で問題が報告される可能性があります
  • [VSCode] rg が PATH 上にある場合、大規模なワークスペースでの @-mention ファイルの検索速度が向上しました。結果はターミナル内とほぼ同様にランク付けされるようになり、タイプミスに対する許容度が低くなります。
  • [VSCode] 起動の改善: モデル ピッカーは、サードパーティ プロバイダーを除き、初めて開いたフォルダー、空のウィンドウ、ワークツリーですぐに準備が整います。
  • [VSCode] 同じウィンドウ内のターミナルセッションがプロンプトを送信するときに、チャット編集の差分が開いたままになり、承認を求め続けるように変更しました。
  • [VSCode] IDE 接続から未使用のツールを削除しました (openFile、saveDocument、getOpenEditors および関連)
