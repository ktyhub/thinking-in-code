claude-code v2.1.309

パッチ 公開日2026年10月22日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.309

何が変わったのか

  • 各コマンドの前にサンドボックスの外でシェルの起動ファイルを実行する macOS および Linux 上のサンドボックス化された Bash コマンドを修正しました
  • シンボリックリンクを通じてパターンのフォルダーに到達した場合に、パスの実際の場所に適用されない macOS サンドボックス denyWrite グロブ パターンを修正しました
  • --mcp-config で渡された MCP 構成ファイルを変更できるサンドボックス コマンドと自動承認編集を修正しました
  • 無効になった MCP サーバーが、印刷セッションおよび SDK セッションで後の許可プロンプトによって再接続される問題を修正しました。
  • リダイレクトが開けない可能性があるコマンドによって設定された変数の Bash 権限チェック trusting を修正しました。
  • cd がラップまたは接頭辞されている場合、プレーン cd の場合と同様に、git を実行する前にディレクトリを変更する一部の複合コマンドを求めるプロンプトが表示されない Bash 権限チェックを修正しました。
  • サブシェルも保持する一部のコマンドで、そのパスへの Bash リダイレクトをブロックしない Edit(path) 拒否ルールを修正しました
  • ワークツリー分離セッションが、分離ガードが拒否すべき一部のロケール接頭辞付きコマンドを受け入れる問題を修正
  • zsh 上のワークツリー分離セッションが、分離ガードが拒否すべきいくつかの算術コマンドを受け入れる問題を修正しました。
  • クロード コードが作成するワークツリーとブランチ チェックアウトを修正し、他の git 操作と同様に git replace refs を無視するようにしました。
  • シンボリックリンク経由で設定ディレクトリに到達した場合にプロファイル ストアの書き込み保護が適用されない問題を修正
  • 非常に大きなネストされた CLAUDE.md の下にあるファイルを読み取った後、セッションが繰り返し圧縮される問題を修正しました。サイズ制限を超えるネストされた CLAUDE.md は、その先頭部分のみをロードするようになりました。
  • Ctrl+Enter (今すぐ送信) は、応答が開始される前に押された場合にのみメッセージをキューに入れ、フックの実行中に押された場合はメッセージをキューに残したままプロンプトのフックを再開する問題を修正しました。
  • ! モードからシェルで実行されるキーバインドされたスラッシュ コマンドを修正しました
  • まだ配信を待っている他のエージェントやセッションからのメッセージが Ctrl+O で表示されない問題を修正しました。それらは現在、トランスクリプトの下に完全に表示され、待機中としてマークされています
  • 長いツール出力プレビューが絵文字を介してカットされ、jq が解析できないセッション トランスクリプトが残る問題を修正しました。
  • 親の /proc を共有する Linux サンドボックスの PDF ページ範囲に対する「ファイルが存在しない」という読み取りレポートを修正しました
  • 接続が更新されると、Claude Desktop がホストするセッションからのメッセージが失われることがある問題を修正
  • 同じコンピューター上の端末が別のアカウントまたは組織にサインインした場合に、Claude デスクトップ アプリの Claude Code セッションに欠落していた機能を修正しました
  • git リポジトリにないフォルダーのブランチとして HEAD を示す claude remote-control ステータス行を修正しました
  • 分割ペインエージェントのチームメイトがリーダーのコマンドラインで指定されたツール拒否ルールと--toolsルールを継承しない問題を修正
  • VS Code ウィンドウのリロードまたは非対話型 --resume の後に、生成された名前で他のセッションに表示される /rename で名前変更されたセッションを修正しました
  • /code-review --fix、サブエージェント、またはシェル コマンドを通じてチェックポイントされたファイルを変更したターンに対して「コード変更なし」と表示される /rewind リストを修正しました。
  • /privacy-settings で古い「AI モデルの改善にご協力ください」値が表示される問題を修正しました。設定を取得できない場合にも表示されるようになりました
  • 組織がフィードバックを受け入れない場合に「後でもう一度試してください」というフィードバックが修正されました。サーバーの理由とバグの報告先が表示されるようになりました。
  • 特大の/フィードバックレポートがトランスクリプトなしで再送信されずに失敗する問題を修正
  • 別のスキルがすでにその名前を保持している場合、--add-dir フォルダー内のスキルにアクセスできない問題を修正しました。現在は<folder>:<name>として提供されています
  • ファイルがシェルから変更されたときに、ネストされたパッケージ自体のスキルが見つからない /verify と /code-review を修正しました
  • ant beta:worker poll --on-work がトレース コンテキストをコマンドに渡すという /claude-api スキルを修正しました
  • /claude-api スキルの C# トレース設定でクラウド プラットフォーム clients からのスパンが欠落している問題を修正しました
  • AWS 上の Claude Platform へのリクエストの API スパンが呼び出し元のトレースに参加できないという /claude-api スキルを修正しました
  • フックのプログラムがコード 2 で終了するときに PowerShell で実行されるフックがブロックされず、Windows 上で Git for Windows がインストールされていない場合に "shell": "powershell" を含む PreToolUse および PermissionRequest フックが失敗して開く問題を修正しました。
  • haiku などのエイリアスでモデルに名前を付ける MOD の turn.step フックを修正し、すべてのリクエストがモデル エラーで失敗するようになりました。エイリアスはそのモデルに解決されるようになりました。
  • ディスク読み取りエラーの後、場合によってはセッション中に、claude.ai から同期されたプラグインとスキルが削除される問題を修正
  • クロードが最初に読み取ることができなかった特定の縮小されたスクリプトやアーティファクトを含むページなど、一部の通常のページで拒否されるアーティファクトの公開と更新を修正しました
  • そのターンで会話が圧縮された後、残りのターンでアーティファクトを更新するたびにクロードが許可を求める問題を修正
  • ANTHROPIC_BEDROCK_BASE_URL がデフォルトの bedrock-runtime.<region>.amazonaws.com エンドポイントに設定されている場合、Amazon Bedrock でファイングレイン ツールのストリーミングがオフのままになる問題を修正
  • キープアライブ ping のみを送信するゲートウェイの背後でちらつく「API 応答を待機しています」ヒントを修正しました。Anthropic のバックエンドからのルートは 45 秒待機するようになりました。
  • PR、問題、コメントにロール名とプレースホルダーをメンションとして書き込むことで、無関係な GitHub ユーザーに通知するクロードを修正しました
  • Linux: バックグラウンド コマンドがセッションを超えた場合にサンドボックス書き込みがリフティングを拒否する問題を修正しました。
  • Windows: 現在のディレクトリをターゲットにし、追加の引数を運ぶ一部の Set-Location または cd コマンドを自動承認する PowerShell 権限チェックを修正しました。これらは承認を求めるようになりました
  • macOS: Xcode またはコマンド ライン ツールを使用しない Mac でクロード コードを起動するたびに開く「コマンド ライン開発者ツールのインストール」ダイアログを修正しました。
  • セルフホスト ランナー: /code-review などの最初のプロンプトがサブエージェントでまだ動作しているセッションを停止する --startup-timeout-min を修正しました。フリーズしたプロセスはまだ停止しています
  • Windows 上で Claude Code 自体が実行する多くの git コマンドの速度が向上しました。すべてのプラットフォームで、git が別の言語に設定されている場合でも、これらのコマンドのエラーが英語で表示されるようになりました。
  • フック モジュールのネストが深すぎてロードできない場合のエラーを改善しました。スタック オーバーフロー メッセージを表示する代わりに、ファイルに名前を付けるようになりました。
  • ディスクがいっぱいになった場合の処理の改善: ディスクがいっぱいになったときに切断された Bash コマンドは、ディスクがいっぱいになったことを示し、解放するフォルダーに名前を付けます。また、完全な一時ボリュームで起動すると、生の ENOSPC エラーではなく明確なメッセージが出力されます。
  • /claude-api スキルを改善し、OpenTelemetry の追加を求められた場合に SDK トレースと並行して API トレースを提供できるようにしました。
  • 機能がサポートされていないと言う前にライブドキュメントをチェックするように /claude-api スキルを改善しました。
  • 自己ホスト型ランナー: 新しいランナーに移行するセッションが改善されました: クロードには、中断され、結果不明としてマークされたツール呼び出しが表示されるようになりました。
  • バンドルされた dataviz スキルを更新して、テキスト コントラストの尺度として APCA を受け入れ (AA 準拠が必要な場合は WCAG 2 比率を維持)、パレット検証スクリプトに apca(text, background) 関数を追加し、色付きチャートの塗りつぶし内のラベルを白か黒に近いかを指定できるようにしました。
  • /claude-api スキルを更新しました。サービス アカウント キーと Workload Identity Federation トークンで OpenTelemetry 宛先を管理できるようになりました。
  • sed -i を変更して、シミュレートされたファイル編集プレビューではなく、標準の Bash プロンプトを取得し、記述どおりに実行するようにしました。他の Bash 編集と同様に、/rewind によって復元されなくなりました。
  • ワークスペース trust を必要とするように claude ultrareview を変更しました。端末上で要求され、それ以外の場合は拒否されます。スクリプトは、値をとらない --trust-workspace を渡すか (その前に PR 番号またはベース ブランチを置きます)、または CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を設定します。
  • デスクトップ アプリと VS Code のバイパス許可モードでの危険な rm および rmdir プロンプトを変更し、書き換えヒントを使用してコマンドをすぐに拒否するようにしたため、無人セッションが続行されます。
  • 設定によりサンドボックスから除外されるコマンドが変更され、サンドボックスが有効になっているが実行できないときに、書き込みリスト パスに書き込む前に確認するようになりました。サンドボックス化されていないフォールバックはそこで拒否されます
  • ワークツリーの作成と再利用が変更され、通常のクローンおよび Bash サンドボックスが構成された部分クローンで git がオンデマンドでオブジェクトをフェッチしなくなりました。このような部分的なクローンは最初にそれらをフェッチします
  • /claude-api スキルを変更して、coordinator ではなく、デフォルトで動的ワークフローがオンになっている multiagent_20261001 で管理対象エージェントのサブエージェント チームを構築しました。
  • [VSCode] TLS 検査プロキシの背後などで、ディクテーションまたは拡張機能自体のリクエストが証明書の検証に失敗した場合の対処方法を示すログ警告を追加しました。
  • [VSCode] エディターがファイルの不完全なコピーをキャッシュした後、クロード パネルが空白のままになる問題を修正しました。現在は自動的に回復するか、何が問題だったのか、その修正方法が表示されます。
  • [VSCode] メッセージを送信せずに新しいセッションを開始するたびに、セッション履歴が空の「無題」セッションでいっぱいになる問題を修正しました。
  • [VSCode] チャット パネルに表示される /goal などの長いスラッシュ コマンド メッセージを修正しました。他のプロンプトと同様に Show の後ろに折りたたまれるようになりました (anthropics/claude-code#97469)
  • [VSCode] チャットパネルを狭くした後、長いメッセージが「もっと見る」の後ろに折りたたまれない問題を修正
  • [VSCode] チャット入力で Ctrl+J が常に改行を挿入する問題を修正しました。 ~/.claude/keybindings.json のチャット コンテキストで "ctrl+j" が null に設定されている場合、これは VS Code と OS に任せられるようになりました。
  • [VSCode] スラッシュ コマンドと @-mention メニューの上に描画されるプロンプトの上にある MOD の「From the … plugin」ラベルを修正しました (anthropics/claude-code#102981)
  • [VSCode] コピーした LaTeX 数式を貼り付けるときに、空のリスト項目、段落またはコード ブロック、および 1 から番号が付け直されるリスト項目を修正しました。
  • [VSCode] 組織がフィードバックを受け入れない場合に HTTP ステータスのみが表示されるフィードバック エラーを修正しました
  • [VSCode] チャット パネルでの編集と書き込みの速度が向上しました。各編集後の新しい問題の待機時間は、ほとんどの場合 0.75 秒になり、1 秒から 1.5 秒に短縮されました。
  • [クラウドセッション] ルーチンフォームの追加コネクタリストで、ロード中に使用可能なコネクタがないと表示される問題を修正しました。
  • [クラウドセッション] クラウド環境エディターで環境変数をシャッフルし、両方の種類の引用符を含む値にバックスラッシュを追加する問題を修正しました。
  • [クラウドセッション] 管理者設定のセルフホスト環境の詳細ダイアログを修正し、コンテンツのみがスクロールしている間、タイトル、タブ、ボタンが表示されたままになるようにしました。
  • [クラウド セッション] 可読ページではなくエスケープされた JSON を表示するクラウド セッションの「ドキュメントを読む」ツールの行を修正しました。
  • [クラウド セッション] クラウド セッションの [変更] ペインが改善され、プッシュされたコミットのみまたはクロードの編集のみがリストされるときに表示されるようになりました。
  • [Claude Tag] Slack のクロードが、チャンネルに承認したドラフトを誤って DM に投稿してしまう問題を修正しました。チャンネルのない投稿は拒否されるようになり、承認されたチャンネルに送信できるようになりました。
  • [Claude Tag] セッションが停止したときに、Slack のクロードの承認カードの許可と拒否が何も行われない問題を修正しました。あなたの回答によりセッションが再開されます
  • [Claude Tag] ワークスペースが別のクロード組織に移動した後、Slack チャネル内のタグなしメッセージをクロードが無視する問題を修正しました (Enterprise Grid の非共有チャネルを含む)
  • [Claude Tag] Slack チャンネルのクロードが、誰かがそのスレッドに追加したばかりの新しいメッセージを読む前にスレッド形式の返信を投稿する問題を修正しました。
  • [Claude Tag] リストの読み込みに失敗したときにワークスペースが接続されていないと表示される Claude Tag 管理設定の Slack ページを修正しました。 「再試行」ボタンとともにエラーが表示されるようになりました
  • [コードレビュー] プルリクエストの作成が失敗したときに、プルリクエストにチェックが入っていないことが表示される完了レビューを修正しました。最後の試行で完了したチェックが追加されるようになりました
  • [コードレビュー] 実行中のレビューの背後でキューに入れられたプッシュが、@claude review stop の後でまだレビューを開始している問題を修正しました。チェックが終了し、その理由が表示されます
