claude-code v2.1.286

パッチ 公開日2026年9月30日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.286

何が変わったのか

  • 複数の許可リクエストが重なった場合に、許可プロンプトに「2/5」などのカウントを追加しました
  • フルスクリーン モードで「N 個以上」行のリストにマウス サポートを追加しました: click 1 つで、ホバーと押された状態でリストの最後にジャンプします
  • gcpAuthRefresh または awsAuthRefresh 認証情報の有効期限が切れたときにログイン ブラウザを開くいくつかのクロード コード プロセスと IDE 拡張機能を修正しました
  • 前のセッションがクラッシュまたは強制終了されたときに、一連の並列ツール呼び出しの後、毎ターン失われることがある claude --resume と --continue を修正しました
  • 再開されたセッションを含め、ツールまたはフックがテキストではなくオブジェクト、数値、またはブール値を返した後の API 400 エラーを修正しました
  • トランスクリプトの読み込み中にコンテナが停止したため、非常に大きな履歴を持つクラウド セッションが起動しない問題を修正
  • クロード アプリ ゲートウェイの支出メーターで、1 時間のプロンプト キャッシュ書き込みをより安価な 5 分料金で価格設定し、Web 検索などのサーバー側ツールを実行するストリーミング ターンでの最初のモデル呼び出しの入力トークンのみをカウントする問題を修正しました。
  • 残った ~/.claude/.credentials.json が存在する場合、別のクロード コード ウィンドウで /login が成功した後でも、macOS セッションに「ログインしていません」または「ログイン期限が切れました」と表示される問題を修正
  • Anthropic API がデフォルトのモデルを拒否するか、モデル エイリアスが解決されると毎ターン失敗する問題を修正しました: クロード コードは同じ Tier の前のモデルで 1 回再試行するようになりました。
  • 組織のポリシーでリモート コントロールがオフになった後も、リモート コントロール セッション (claude remote-control を含む) が接続されたままになる問題を修正しました。彼らは今、通知を出して切断します
  • フォールバック モデルが高速に実行できない場合に失敗する拒否と --fallback-model の再試行を修正しました。インタラクティブ セッションで 1 回限りの通知が行われ、標準速度で実行されるようになりました。
  • MCP 検出キャッシュが有効になっている場合、再認証が成功した後に「MCP サーバーには認証が必要です」というリマインダーが繰り返されるヘッドレス セッションを修正しました。
  • コンソールのサインインに保存されている API キーを claude.ai として報告する claude auth status を修正しました。 api_key が報告され、VS Code 拡張機能はそのセッションを API キー セッションとして扱います。
  • API キーの横に Anthropic プロファイルが両方とも有効であるかのようにリストされる /status を修正しました。プロファイルは未使用としてマークされています
  • リモート コントロール経由で送信されたメッセージに添付されたファイルが到着しなかったときにクロードに通知されず、ファイルの最後のダウンロード試行が 10 秒しかかからない場合がある問題を修正
  • クロード コードが終了中に受信したリモート コントロール メッセージが配信済みとしてマークされ、その後応答されなかった問題を修正しました。セッションの次の実行のためにキューに入れられたままになります。
  • 「Bearer」または「Basic」がキー名の前にある場合に認証情報の値を示す MCP エラー メッセージを修正しました
  • パーセントでエンコードされたベアラー トークンがエラー メッセージ内で部分的にのみマスクされる問題を修正
  • キー名に幅ゼロのスペースなどの非表示文字が含まれているシークレットを示す編集されたログとトランスクリプトを修正しました
  • )、引用符、]、&、または 2 番目の @ などの句読点を含む URL パスワードの一部、または SSH URL で / を超えて [::1] などの括弧で囲まれたホストに至る URL パスワードの一部を示すログとトランスクリプトを修正しました。
  • /feedback がシークレット編集後に無効な JSON 行を含むディスクに保存する zip 内のセッション トランスクリプトを修正しました
  • サーバーが古い MCP ハンドシェイクをドロップした後、最長 1 日間ツールがリストされない MCP コネクタを修正しました。
  • 保留中のサインイン リンクを置き換えるクロードからの繰り返しの MCP サインイン要求を修正しました。これにより、リンクの動作が停止する可能性がありました。
  • /usage が、サーバーがまだ接続中、または接続したばかりのとき (再起動直後など) に行われたツール呼び出しに対して MCP サーバーをクレジットしない問題を修正しました。
  • claude.ai で有効になっているプラグインが、一時的なサーバー エラーの後、セッションのクロード コードから時々失われる問題を修正しました
  • 実行中のサブエージェントに入力されたメッセージが、サブエージェントが読み取った後にトランスクリプトに 2 回表示される問題を修正しました。
  • サブエージェントに登録名がない場合に、エージェント名の代わりに生のタスク ID が表示されるサブエージェント ハンドバック メッセージを修正しました。
  • フォアグラウンド サブエージェントがタスク追跡ツール (TaskCreate/Get/Update/List、TodoWrite) を有効にしているセッションでそれらを欠落することがある問題を修正しました
  • 最初のファイル読み取り時にワークツリーのコピーからプロジェクト CLAUDE.md とそのインポートを 2 回ロードするワークツリー分離で生成されたサブエージェントを修正しました
  • 応答中に接続が数分間停止したときに、ワークフロー ツールのサブエージェントが元のプロンプトから再起動される問題を修正しました
  • メインの会話を静かに実行しているバックグラウンド エージェントまたはチームメイトのトランスクリプトを表示しているときに入力された /compact、/clear、および /rewind を修正しました。ダイアログでターゲットの名前を指定し、最初に質問するようになりました。
  • 承認を待っている間に完了したと表示されるバックグラウンド ジョブを修正しました
  • モデルのフォールバックが 1 ターンしか続かない場合にツール出力内でコミット アトリビューション リマインダーが再送信される問題を修正しました
  • 全画面モードで展開せずに行を強調表示する、折りたたまれた行 (「4 秒考えた」など) の単語間のスペースの click を修正しました。
  • 長い名前のアクション行など、詳細のない行を修正し、リスト画面で 1 行おきの行の詳細を右に押し出しました。
  • 非常に長い名前のファイルがクラウド セッションに添付されたときにクラウド セッションに到達しない問題を修正
  • クロードコードがロードを拒否するマーケットプレイスのプラグインエラーを修正しました。「見つかりません」ではなく、その理由と修正方法が表示されるようになりました。
  • /plugin の [Discover] タブで、その行に既に引用符で囲まれた名前が表示されている場合に、「Checking … for new plugins」行で引用符で囲まれていないマーケットプレイス名が表示される問題を修正しました。
  • コミット ガイダンスの改善: プロジェクトまたはユーザー スキルに verify という名前のものが含まれている場合、ドキュメントのみおよびテストのみのコミットを除き、クロードはコミットする直前にそれを実行するように指示されるようになりました。
  • サブエージェントのビューでの今すぐ送信 (Ctrl+Enter) の改善: サブエージェントの実行中のコマンドがバックグラウンドに移動するため、メッセージがすぐに読み取られます。
  • バックグラウンド エージェントからのメッセージへの返信が改善され、発言内容の別の要約が表示されなくなりました。
  • claude.ai アーティファクト リンクの読み取りの改善: WebFetch は、アーティファクト ツールの読み取りと同じ質問をするようになりました (セッションのネットワーク アクセスがオンの間はアーティファクト プロンプトは表示されず、オフの間はアーティファクトごとに 1 つずつ表示されます)。また、自動モードの [はい] は、ユーザーだけが回答できる場合にはカウントされなくなりました。
  • ファイル編集プロンプトの外観と一致するように、フェッチ、スキル、ファイル読み取り、サンドボックス ネットワーク、Chrome のクロード、ワークフロー スクリプトおよびノートブックの編集権限プロンプトを改善しました。
  • Bash、PowerShell、および Monitor の権限プロンプトが改善され、ファイル編集プロンプトと一致する点線の間にコマンドが表示されるようになりました。
  • フルスクリーン モードでのリスト スクロールバーの改善: ほとんどのリストで、「N 個以上」の行が行き来してもバーが移動しなくなり、click または長押ししてスクロールできる ↑/↓ 矢印が表示されるようになりました。
  • 外部エディターの改善 (Ctrl+G): 行番号を取得するエディターが、プロンプト内でカーソルが置かれている行で開くようになりました。
  • 多くのスキルまたはプラグイン コマンドがインストールされている場合、入力中のスラッシュ コマンドの提案の応答性が向上しました。コマンドの説明は単語の接頭辞で一致するようになりました
  • 出力スタイル ピッカーを改善しました。デフォルトではなく現在のスタイルが開き、名前の下の行に各スタイルの説明が表示されます。数字キーでスタイルが選択されなくなりました
  • /hooksの改善: フックの詳細画面の最後の行に、「それ」ではなく「このフック」と表示されるようになりました。
  • モデルのフォールバック通知と、フォールバックによってコンテキスト ウィンドウが 1M から 200K トークンにドロップされたときに通知するオートコンパクト スラッシング エラーを改善しました。
  • すでに接続されているサーバーに対してホストが MCP サーバーを再送信するときの SDK および -p セッションの応答性の向上
  • クロード アプリ ゲートウェイが /protocol で提供するプロトコル ページを改善しました。未知の入力を拒否しないと表示され、クロード コードが今日送信するものと一致します。
  • 何も実行されていない、またはキューに登録されていないときに送信されるプロンプトを、灰色ではなく通常のテキスト色ですぐに表示するように変更しました。
  • 失敗した API リクエストの再試行方法が変更されました。1 つの制限がモデル呼び出し全体をカバーするようになりました。そのため、デフォルトの再試行設定では、失敗した呼び出しは最大 14 個のリクエストを送信します。
  • コマンド ラインで指定された MCP サーバーのみに接続し、システム リマインダーをモデルに送信せず、バックグラウンド タスクを開始しないように --bare を変更しました。 --bare では、タイムアウトに達したシェル コマンドがバックグラウンドに移動せずに停止するようになりました。
  • 今すぐ送信キー (ctrl+enter) を変更して、スキル自体のシェルコマンドを終了するのではなくバックグラウンドに移動するようにしました。
  • レート制限されたドメインの安全性チェックの WebFetch エラーを変更して、クロードにループ内で再試行しないように指示しました。
  • git リポジトリまたはフォルダーである npm ソースを拒否し、レジストリ パッケージからのみプラグインの依存関係をインストールするようにプラグインのインストールを変更しました。
  • リスト画面(/artifacts、/mcp、/skills、/hooksなど)で、各行の詳細が常に名前の後ろの1列に並ぶように変更しました。
  • リストのオーバーフロー行を、「上に N 個以上」/「下に N 個以上」ではなく、「↑ N 個以上」/「↓ N 個以上」と表示するように変更しました。
  • イベントごとにグループ化された設定済みフックの 1 つのリストで開くように /hooks を変更したため、フックを表示するには Enter キーを 3 回ではなく 1 回必要になります。
  • テーマピッカーを、プレビューを画面外に押し出すのではなく、端末に合わせたスクロールリストに変更しました。数字キーでテーマが選択されなくなりました
  • クロード コードがサーバーとそこで起動したシェルを停止した後に実行されるように /exit のワークツリーの削除を変更しました。これにより、Windows ではフォルダーが削除されなくなる可能性があります。
  • ネットワークが制限された環境を作成するために、claude-api スキルの管理対象エージェントの例を変更しました。
  • /ultrareview および claude ultrareview 出力からブラウザー リンクを削除しました。
  • Windows: trust レコードが異なる大文字で保存されたときに、claude がすでに trust しているフォルダーを拒否する claude --bg とエージェントのビューを修正しました。
  • [VSCode] ブックマークの追加: クロードの応答を保存し、ブックマーク サイド パネルに表示し続ける
  • [VSCode] クロードが尋ねる質問と会話への回答を追加しました。質問カードに回答すると、質問行に各質問が選択して表示されます。
  • [VSCode] チャット パネルの質問カードにオプション プレビューを追加しました。ハイライトされた選択肢のモックアップまたはスニペットがオプションの横または下に表示されます。
  • [VSCode] ターミナル出力、ブラウザーのタブ、ブラウザーの指示、および一緒に送信された選択されたコードを開くメッセージの下に行を追加しました。
  • [VSCode] すでにサイドバーで開いている会話の 2 番目のコピーをタブで開く問題を修正しました。サイドバーがそれに切り替わります
  • [VSCode] Claude Code が 1 MB を超える出力を印刷したときに、再確認せずに保存に失敗したと報告する設定ダイアログを修正しました
  • [VSCode] 拡張機能が応答を停止したときの無限の「テレポート セッション…」スピナーを修正しました
  • [VSCode] プラグインの管理ダイアログを改善しました。オフにしたプラグインが他の設定のためにまだオンになっている場合に表示され、プラグイン フォルダーの衝突について説明されます。
  • [VSCode] 現在のターンのみを終了するように停止とエスケープを変更しました。バックグラウンド エージェントは実行を継続し、エージェント マップから 1 つずつ停止できます
  • [VSCode] ステータスバーの項目「✻クロードコード」をすべてのウィンドウに表示するように変更しました。これにより、ファイルが開いていないときにもクロードを開くことができます
  • [クラウドセッション] クロードがメッセージを送信した後にセッションがアイドル状態になったときに、回答された質問カードまたは承認されたツールの呼び出しに応答がなかった問題を修正しました
  • [クラウド セッション] 管理者設定で組織環境のセットアップ スクリプトをクリアすると、新しいクラウド セッションで古いスクリプトが実行されたままになる問題を修正しました。
  • [クラウドセッション] セルフホスト環境の管理ページのランナーアクションメニューが開いてから数秒後に自動的に閉じる問題を修正しました。
  • [クラウド セッション] クラウド セッションが [実行] ペイン、ルーチンのページ、サイドバーで [成功] として表示され始めなかったルーチンの実行を修正しました。失敗と表示されるようになりました
  • [クラウド セッション] クラウド セッションの出力カードでオーディオまたはビデオ ファイルをロックすると、ファイルを再生する代わりに空のファイル検索が開かれる cli を修正しました。
  • [クラウドセッション] スケジュールされた実行が遅れて開始されていない場合、過去の次回実行時間ではなく、スケジュールされた時間が「期限」と表示されるようにルーチンのページを変更しました。
  • [Claude Tag] 管理者設定の Claude Tag の支出制限ページに [チャンネルを追加] ボタンを追加しました。これにより、チャンネル ID または Slack リンクからプライベートチャンネルを含む任意のチャンネルに制限を設定できるようになりました。
  • [Claude Tag] デフォルトのソネットモデルを使用できない組織で何も見つからないメモリリコールを修正しました。
  • [Claude Tag] Enterprise Grid 管理者が Slack チャネルを別のワークスペースに移動し、その後の最初の投稿でクロードについて言及しないと、Slack チャネルのクロード設定が失われる問題を修正しました。
  • [Claude Tag] Slack スレッドのクロードが、質問されたばかりの質問に返信すると、新しいマシンで最初からやり直され、プッシュされていない作業が失われることがあった問題を修正しました。
  • [Claude Tag] 大規模な組織で生の Slack ID として表示される、管理者設定の Claude Tag の支出制限ページのパブリック チャネル名を修正しました。
  • [Claude Tag] claude.ai に示されているように、Slack から開始されたセッションのタイトルを改善しました。Slack ユーザー ID やエスケープ コードなしで、入力した単語として読み取られるようになりました。
