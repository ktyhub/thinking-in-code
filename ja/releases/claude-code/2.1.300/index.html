claude-code v2.1.300

パッチ 公開日2026年10月14日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.300

何が変わったのか

  • MOD のプロンプト装飾に virtualText を追加しました: プロンプト ボックスに描画され、ドラフトまたは送信されたプロンプトには決して入力されないテキスト
  • cache_creation_5m_tokens および cache_creation_1h_tokens を OpenTelemetry api_request イベントに追加し、キャッシュ書き込みを有効期間ごとに分割しました
  • MOD 用に $.ui.view({ agentId }) を追加: 質問するとメイン ビューにエージェントのトランスクリプトが表示され、$.ui.view({}) は戻ります
  • 右から左へのテキスト用に MOD の Text に dir プロパティを追加しました: Windows と VS Code のターミナルでは、その行はその方向に読み取られ、右揃えに配置されます。
  • AWS の Claude プラットフォームに /advisor を追加しました。 /advisor、advisorModel、または --advisor のいずれかを選択し、CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 で無効にするまで、アドバイザーは実行されません。
  • gen_ai.provider.name、gen_ai.conversation.id、gen_ai.tool.name、error.type などのスパンをトレースするための OpenTelemetry GenAI セマンティック規約属性を追加しました
  • ワークフロー エージェントの prompt および model を agent.spawn mod フックに書き換えるサポートを追加しました。以前はワークフロー エージェントを拒否することしかできませんでした。
  • prompt.change mod フックを追加しました。これは、入力された編集を行わずにプロンプト ボックスのテキストが変更されたときに発生します: 履歴エントリの呼び出し、クリア、元に戻す、またはプラグインの塗りつぶし
  • セッション自身のネットワーク設定がホストをブロックしたときに、組織のポリシーがホストをブロックしたことをクロードに伝えるクラウド セッションを修正しました。
  • より小さい自動圧縮ウィンドウを選択した場合のトークン使用量の多さに関する /autocompact 警告を修正しました
  • バックグラウンド コマンドの実行中に終了すると、SessionEnd フックが実行されないことがある問題を修正しました。
  • --restricted の説明で削除されたツールに名前を付ける claude --help を修正しました
  • いずれかのプル リクエストのデータが不完全に返されたときに、claude agents がプル リクエストのステータスを更新しない問題を修正しました
  • クラウド セッションのコンテナが置き換えられた後、エージェントがすでに再開されているときに、バックグラウンド エージェントが失われたため再開できないとクロードに通知される問題を修正
  • メッセージを入力したサブエージェントが終了直後に /tasks から消え、会話に戻れなくなる問題を修正しました
  • 子を表示しているときに、完了した親エージェントがパンくずリストから削除される問題を修正しました (その子は最上位に再ルートされて表示されます)。
  • 入力がバーストで到着したときに、そのキーに対して「上」、「下」、または「エスケープ」などの入力された単語を取得するエージェント ビューを修正しました。これにより、返信中にピークが移動したり、下書きがクリアされたりする可能性がありました。
  • 自動ツール検索 (ENABLE_TOOL_SEARCH=auto) が会話の途中でオフになる問題を修正しました。たとえば、MCP サーバーが再開後に再接続しているときなどです。
  • forceLoginOrgUUID によってログインが拒否され、拒否された組織のトークンが保存されたままになるか、/login 後に存続する問題を修正しました。
  • クロード デスクトップおよびリモート コントロール セッションの差分ビューが、reftable リポジトリでの競合するチェリーピックまたはリバートに気づかない問題を修正しました。
  • 通話の入力が到着するときに Artifact ツールの冗長な Ctrl+O 行が Artifact("(unprintable path)") と読み込まれる問題を修正しました。その行には、Bash と同じように「待機中…」と「実行中…」が表示されるようになりました。
  • クラッシュによりトランスクリプトの最後の行が短くなった場合、セッションの再開後に書き込まれた最初のトランスクリプト エントリが失われる問題を修正しました。
  • Unicode の行区切り文字または段落区切り文字 (U+2028、U+2029) が含まれている場合に、/branch がメッセージをドロップし、claude purge がサブフォルダー プロジェクトをスキップする問題を修正しました。
  • クロード コードが --worktree で始まるときにプラグイン WorktreeCreate および WorktreeRemove フックが実行されない問題を修正しました (--tmux ではまだ実行されていません)
  • reftable ref ストレージを使用するリポジトリで、git commit -q の後に git_commit_id が欠落する OpenTelemetry tool_result イベントを修正しました
  • OpenTelemetry user_prompt イベントとインタラクション スパン、およびセッション タイトル リクエストで入力されたまま記録されている MOD の prompt.submit フックが書き換えられたか削除されたというプロンプトを修正しました
  • Mod のホットリロードがトランスクリプトに入力したかのように表示されるというクロード向けのメモを修正しました
  • model を無視するエージェント フックを修正しました。haiku のようなエイリアスが解決されるようになり、サブエージェントのモデルがそれをオーバーライドしなくなり、使用できないモデルはアクションを許可する代わりに呼び出し元のモデルにフォールバックします。
  • タグまたはブランチにコミット ID のような名前が付けられている場合に、--worktree セッションが間違ったコミットから開始されることがあり、その開始 git ステータスが新しいワークツリー以外のブランチを名前付けする問題を修正しました。
  • ブランチが「.invalid」と表示され、git の reftable ref storage を使用してリポジトリ内のワークツリーを再度開くことができない --worktree を修正しました。
  • クロードがセッション スクラッチパッド内のファイルにフルパスではなく裸のファイル名または相対パスで命名する問題を修正しました。
  • ロックされたキーチェーンなどの短いサインイン エラーの後に、claude remote-control サーバーが接続の更新を断念する問題を修正しました。再試行し、claude /login を実行する必要がある場合に警告するようになりました。
  • オリジンのデフォルトのブランチをフェッチできない場合に、ベア リポジトリのワークツリーで --worktree が失敗する問題を修正しました。フォールバック ベースはメイン リポジトリではなく、現在のチェックアウトの HEAD になります。
  • VS Code、Cursor、または Devin Desktop 統合ターミナルで Claude Code を開始すると、拡張機能を確認するためにエディターのコマンドライン ツールが 2 回起動される問題を修正しました。一度起動するようになりました
  • chat:newline キーバインド (Ctrl+J、またはリバウンド Enter) で入力された改行に対して MOD の prompt.edit フックが発生しない問題を修正しました。
  • API が MCP ツールの入力スキーマを拒否したときに、毎ターン 400 エラーで会話が失敗する問題を修正しました。 Claude Code は、会話の残りの部分にパラメーターなしでそのツールを送信するようになりました。
  • 圧縮が出力トークン制限での応答カットに続いた場合に、ヘッドレスまたはエージェント SDK セッションを再開すると、圧縮によって保持されていた最近のメッセージが失われる問題を修正しました (このバージョン以降の圧縮)
  • 圧縮後にサーバーが接続を終了したときに、次のツール呼び出しまで MCP サーバーのツールと指示についてクロードが通知されない問題を修正しました。
  • 複数のセッションを同時に処理しているコンピュータ上で、リモート コントロール セッションが実行中に停止としてマークされる問題を修正
  • ヘッドレスまたはエージェント SDK セッションを再開すると、同じターンで再試行または未完了の応答に続いて圧縮が行われた場合、圧縮の概要が失われるか、圧縮前の履歴が戻ってしまう問題を修正しました。
  • クロードがバックグラウンドコマンドの出力ファイルをポーリングしたり、実行中にスリープしたりする問題を修正
  • 証明書が OS 証明書ストアを通じてのみ trusted される TLS 検査プロキシの背後で機能フラグと段階的ロールアウトが古いままになる問題を修正
  • スタックしたバックグラウンド サービスが実行され続けているときに「停止しました」と印刷される claude daemon stop --any を修正しました。待機してサービスを強制終了し、サービスがまだ存在する場合は終了 1 でその旨を通知するようになりました。
  • テレメトリがオフになっている場合、claude daemon stop が出力なしで終了し、セッションが実行中としてリストされたままになる問題を修正しました
  • ファイルが到着しなかった自分のコンピューター上のパスの成功を報告する Cowork クラウド セッションの書き込み、編集、および NotebookEdit を修正しました
  • セッションがリストされていない履歴を再開したときに、会話の早い段階で既にロードされている遅延ツールをクロードが検索する問題を修正しました
  • ダーク ANSI テーマおよび 16 色の端末上で、二次 (薄暗い) テキストが通常のテキストと同じように見える問題を修正しました。
  • 組織のポリシーを読み取ることができない場合、クラウド セッションがターンごとに 5 分間ハングする問題を修正しました。ターンはすぐに終了し、その理由が表示されます
  • 長い応答中にセッションが再起動された後、クラウド セッションで既に応答済みのメッセージが 2 回目に実行されることがある問題を修正しました
  • 自己ホスト型ランナー: 誰も出力を読み取らない間にランナーとオーケストレーターがフリーズする (ポーリングなし、/healthz または SIGTERM がシャットダウンする) 問題を修正しました。ログは最新の 256 KiB を保持し、ドロップをカウントします (Windows では除く)
  • Cowork クラウド セッションの WebFetch を改善し、ページを再度フェッチするのではなく、少し前にページが失敗したことをクロードに通知するようになりました。
  • 組み込みの plugin-authoring スキルでの MOD 共有の改善: クロードは、MOD のファイルを開く前にキーをスキャンし、プロジェクト外のフォルダーをスキャンする前に質問します。
  • クロード 3 モデルが @ で言及された PDF について取得するメモを改善し、それを読まずに回答することが少なくなりました。
  • アーティファクトの更新の改善: クロードは、1 回の呼び出しで小さな変更を適用してアーティファクトを再公開し、1 回の応答内で大規模な編集を行って再公開するようになりました。
  • 設定内の CA バンドル、ツール プロキシ、git TLS、および SSL_CERT_FILE などの git config 変数を無視するように CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST セッションを変更しました。 Claude Desktop の下、プロジェクト設定のみ
  • 終了を要求されてから 1.5 秒後に実行中のバックグラウンド コマンドを強制終了するように終了を変更しました。全画面モードでは、以前は実行したままにすることができました
  • forceLoginGatewayUrl がセッションのホスト名を提供する Anthropic が運用するゲートウェイを指定するときに管理設定を適用するように Claude Desktop の [コード] タブを変更しました。そのゲートウェイは開始時に到達可能でなければなりません
  • クロード デスクトップがゲートウェイから使用できない desktop: ポリシー キーで、キーに名前を付けて開始時に停止するように claude gateway を変更しました。以前は警告が表示されて開始されました。
  • テレメトリが無効な場合でも gzip 圧縮を使用するように、大規模なリクエストを api.anthropic.com に変更しました。 CLAUDE_CODE_GZIP_REQUEST_BODIES=0をオフに設定してください
  • アーカイブまたは削除を要求しない限り、管理対象エージェントのセッションをそのまま残すように claude-api スキルを変更しました。
  • 引き継ぎファイルから実行するのではなく、ワークフロー ツールの承認を通じて実行されたワークフローを再開するようにバックグラウンド セッションを変更しました。
  • 各 API リクエストのシステム プロンプト、ツール、パラメータも記録するようにローカル セッションのトランスクリプトを変更しました。そのため、共有することを選択したトランスクリプトでリクエストを正確に再現できます。
  • /sandbox モード オプションを「Sandbox BashTool」ではなく「Sandbox コマンド」に変更しました。
  • Cowork クラウド セッションの PermissionRequest フックを変更しました。フックの許可内の setMode 更新は無視されるようになりました。残りの承認は引き続き適用されます
  • 変更されたフック: PreToolUse および PermissionRequest フックの updatedInput は、Claude 自身の入力と同様に検証されるようになりました: 不明なキーは削除され、ツールが呼び出しを拒否する入力は拒否されます。
  • 効果のなかった --sandbox および --no-sandbox フラグを claude remote-control から削除しました。どちらかを渡すとエラーで終了するようになりました。設定でsandbox.enabledをサンドボックスセッションに設定します
  • [VSCode] エディターで選択したテキストがメッセージに追加されないようにする claudeCode.attachSelection 設定を追加しました
  • [VSCode] 使用クレジットがなくなった後も高速モードが維持され、各リクエストが拒否されて再送信される問題を修正しました。再びオンにするまでオフになり、エラー通知が表示されるようになりました。
  • [VSCode] 常に考えるモデルで思考トグルがオフに切り替わる問題を修正しました。これらのモデルではトグルが表示されなくなりました
  • [VSCode] 復元されたプロンプト上でファイルまたはコマンド メニューを開くフラグ付きメッセージの「プロンプトの編集」を修正しました。今すぐ入力すると、書かれたとおりに送信されます
  • [VSCode] Windows で Shift キーを押しながらファイルをプロンプトにドラッグすると、作業ディレクトリに対する相対的な言及の代わりに、読み取り不可能な /c:/… パスが挿入される問題を修正しました。
  • [VSCode] VS Code のチャット フォント サイズ設定への変更がウィンドウの再読み込みを必要としたり、テーマの変更によって元に戻されたりする問題を修正しました。差分と計画プレビューもそれらに従うようになりました
  • [VSCode] 「セッションの再開」を修正し、リロード後に復元されたタブが、git ワークツリーに移動された会話ではなく空の新しい会話を開きました
  • [VSCode] 呼び出されたスラッシュ コマンドで ↑ を実行して引数なしで実行する問題を修正しました。編集するまで、呼び出されたプロンプト上でコマンド メニューとファイル メニューが開かなくなりました。
  • [VSCode] Shift キーを押しながらエクスプローラーまたはエディター タブからファイルをプロンプトにドラッグすると、WSL、SSH、および開発コンテナ ウィンドウに何も挿入されない問題を修正しました。
  • [VSCode] Windows および Linux 上で、エクスプローラー、他のツリー ビュー、またはデバッグ コンソールで検索を開く代わりに、Ctrl+Alt+F でフォーカス ビューを切り替える問題を修正しました。
  • [VSCode] macOS 上で追加のプロセスを作成する他のウィンドウまたは端末で開いているセッションのチェックを修正しました。チェックのたびに ps の PATH を検索するのではなく、/bin/ps を直接開始するようになりました。
  • [VSCode] Windows: クラッシュまたは電源喪失の後、Windows が再起動されて古いプロセス ID が別のプログラムに与えられたときに、「まだどこか別の場所で開いている」と表示される会話を修正しました。
  • [クラウド セッション] 組織が「常に許可」をオフにしている場合、コネクタ ツールに対する Cowork の承認プロンプトに「このタスクを許可」が表示されない問題を修正しました (2.1.292 のリグレッション)
  • [クラウドセッション] 2番目のメッセージを送信すると、/メニューのほとんどのコマンドがクラウドセッションで説明を失う問題を修正しました
  • [リモート コントロール] claude.ai のリモート コントロール セッションの差分表示と、削除および名前変更されたファイルが変更されたものとして表示されるデスクトップ アプリを修正しました。マシンにはクロード コード v2.1.296 以降が必要です
  • [Claude Tag] Slack Connect チャネルのサポートを追加しました。オーナーまたは Claude タグの管理者は、Slack のクロードが別の組織と共有されているチャネルで応答できるようにすることができます。デフォルトではオフになっています
  • [Claude Tag] 承認が必要なコネクタ アクション用に、Slack スレッドにプライベートの許可/拒否カードを追加しました。これにより、クロードは拒否する代わりに質問します。他の人はそれがあなたを待っていることしか見ていません
  • [Claude Tag] Slack の Claude で Slack 音声 clips のサポートを追加しました: Slack に clip がある場合、クロードは Slack の clip のトランスクリプトを読みます
  • [Claude Tag] クロード自身がチャンネルに投稿したメッセージの下のスレッドでタグ付けした別のアプリに Slack のクロードが応答しない問題を修正
  • [Claude Tag] 管理者が Slack チャネルにアタッチしたアクセス バンドルを変更し、チャネルが Slack Connect チャネルになった後も適用し続けるようにしました。削除して再アタッチする必要はありません。
  • [コード レビュー] GitHub 組織メンバーシップが非公開である書き込みアクセス権を持つユーザーからの @claude review コメントを無視するコード レビューを修正しました。彼らのコメントがレビューを開始します
  • [コード レビュー] コード レビューの「このリポジトリを一時停止しました」というコメントが管理者にコード レビュー設定を送信する問題を修正しました。誰が修正できるかを示し、Git プロバイダーのページにリンクするようになりました。
