claude-code v2.1.283

パッチ 公開日2026年9月25日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.283

何が変わったのか

  • LLM ゲートウェイが 1 つのユーザー プロンプトに対応するリクエストをグループ化できるように、ゲートウェイ ヒント ヘッダーに x-claude-code-prompt-id を追加しました。 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 でオプトイン
  • availableModelsMatch 管理設定の追加: "exact" では、availableModels エントリはその名前のモデル バージョンのみを許可するため、新しいリリースはリストされるまでブロックされたままになります。
  • availableModels で許可されている場合でも、特定のモデルをブロックするための deniedModels 管理設定を追加しました。
  • OTEL_LOG_TOOL_CONTENT=1 の場合の tool.output OpenTelemetry スパン イベントに MCP ツール、WebFetch、および WebSearch 出力を追加しました。
  • CLAUDE.md ファイル、スキル、エージェント、および古いモデル用に作成されたプロンプト パターンのコマンドを監査するための /doctor prompt-audit (/checkup prompt-audit とも) を追加しました
  • 全画面モードでの他のセッションからの切り詰められたメッセージ用に click-to-expand を追加しました
  • ストリーム json system/init plugin_errors に path から --plugin-dir ロード失敗エントリを追加し、ロードされなかったディレクトリに名前を付けました
  • クロード アプリ ゲートウェイ構成にオプトイン load_test_mode ブロックを追加しました。リクエストは構築および署名されますが、アップストリームには送信されず、client は定型応答を取得するため、デプロイメントの負荷テストが可能です。
  • Amazon Bedrock の Mantle エンドポイントのクロード アプリ ゲートウェイに mantle アップストリーム プロバイダーを追加しました
  • ターンが早期に終了した場合、保留された承認プロンプトがワーカーの再起動後に表示された場合、および非ストリーミング フォールバックの result.usage の場合に、SDK セッションで遅延ツール呼び出しまたは完成したツール結果が失われる問題を修正しました。
  • 長時間実行されるツール呼び出しがバックグラウンドに移動すると、MCP の進行状況通知が破棄される問題を修正しました。バックグラウンドタスクに最新の進行状況が表示されるようになりました
  • stdio MCP サーバーが開始中にセッションが終了した場合に実行されたままになる問題を修正
  • ステートレス リモート MCP サーバー (再デプロイ中のプロキシなど) からの短い HTTP 404 が発生し、そのサーバーが接続されているように表示されたまま残りのセッションで使用できなくなる問題を修正しました。
  • 有効な URL を持たないサーバーへの MCP サインインが不透明な SDK エラーで失敗する問題を修正しました。 /mcp は、そのようなサーバーに対する認証を提供しなくなりました
  • テレメトリが無効になっている場合、/usage と VS Code 使用量メーターに週ごとの Fable 制限が表示されない問題を修正しました
  • ID に日付または -v1:0 サフィックスが付いている場合、プレーン ID が拒否された場合に、/model が Sonnet 4.6 または [1m] を含む Sonnet 5 を受け入れる問題を修正しました。
  • ANTHROPIC_DEFAULT_HAIKU_MODEL が別のモデルをピン留めしたときにハードコードされた Haiku バージョンと価格を表示する /model ピッカーを修正しました
  • モデルのフォールバック中に、構成されたモデルを再試行するのではなく、フォールバック モデル上のすべてのエージェントを実行するときに開始される動的ワークフローを修正しました。
  • Haiku がセッションのメイン モデルである場合、DISABLE_PROMPT_CACHING_HAIKU が効果を持たない問題を修正
  • Claude Code がインストールできないプラグインまたはマーケットプレイス名を受け入れると言う claude plugin validate を修正しました。 marketplace.json 内のそのような名前は検証に失敗するようになりました。
  • outputStyles、themes、monitors、または lspServers パスが見つからないか、プラグイン ディレクトリの外を指しているプラグインを渡す claude plugin validate を修正しました。
  • plugin.json でサーバーを宣言するプラグインに対して 0 MCP サーバーが表示される claude plugin details を修正しました
  • claude plugin marketplace remove がマーケットプレイスでどのプラグインをアンインストールしたかを表示しない問題を修正しました。それらがリストされるようになりました
  • 指定されたプラグインにそのスコープで enabledPlugins エントリがない場合に、オプションとシークレットを含む大文字と小文字のみが異なる ID を持つ 2 つのインストール済みプラグインのうちもう一方を削除する claude plugin uninstall を修正しました。
  • キャッシュされたファイルが見つからない場合、インストールされたものではなく、ソースの最新のコミットでサイレントに復元されるバージョンがないことを宣言するプラグインを修正しました
  • バインドマウントされた開発コンテナなどでホームまたは設定ディレクトリが移動された後、ユーザーがインストールしたプラグインとマーケットプレイスが「キャッシュミス」でロードできない問題を修正
  • 無効なプラグイン ID でレコードを保持しているときにプラグインが表示されない installed_plugins.json を修正しました。そのようなファイルは再度ロードされます
  • このバージョンが読み取れないレコードを保持している場合、installed_plugins.json が書き換えられてレコードが失われる問題を修正しました。 claude plugin コマンドはレコードに名前を付け、回復方法を指示するようになりました。
  • 引用符で囲まれたコマンドとパスをダイアログ独自のテキストであるかのように読み取ってしまうスクリーン リーダー モードの権限ダイアログを修正しました。
  • /context が MCP サーバー命令をカウントしない問題を修正しました。それらは独自の行として表示され、合計にカウントされるようになりました。
  • clickable ハイパーリンクではなくプレーン テキストとしてレンダリングされるワープ ターミナルのマークダウン リンクを修正しました
  • サンドボックス内などでユーザーまたはローカル構成ファイルを書き込めなかった場合に成功を報告する claude mcp add、add-json、および remove を修正しました。
  • クラウド セッションでの返信の最初の言葉が、クロードが返信する際にストリーミングではなく遅れて表示されることがある問題を修正しました
  • コードが 3 秒ではなく 1 秒後にタイムアウトするというクロードの組み込みキーバインディング ガイドと、ほとんどの端末が決して送信しない cmd+ ショートカットを生成する可能性がある cmd を meta のエイリアスと呼ぶ問題を修正しました
  • keybindings.json が ctl+k などのスペルミスの修飾子を黙って受け入れる問題を修正しました。デバッグログで警告し、修正を提案するようになりました。
  • footer:openSelected が keybindings.json でリバウンドまたはアンバインドされた後も、フッター ヒントが「Enter to view」と表示される問題を修正しました。
  • 素早く一緒に入力されたキー (先行入力、キーリピート、ssh または tmux 経由のバースト) が古い状態に対して処理されることがある問題を修正しました。
  • CA 証明書が GIT_CONFIG_COUNT 環境ペアとして git に渡される場合、ワークツリーのチェックアウトで証明書検証が失敗する問題を修正しました (Git LFS ダウンロードなど)。
  • サンドボックス化された git が資格情報ヘルパーにサンドボックス プロキシのログインを保存するよう要求し、「保存に失敗しました」と出力される問題を修正しました。
  • 1 つのネストされた値が無効な場合、マネージド sandbox 設定が完全に無視される問題を修正しました。無効な値はフェイルクローズされ、ブロックの残りの部分は引き続き適用されます。
  • クロード コードが git リポジトリのサブディレクトリで開始されたときに、クロードによる独自の自動メモリ ノートへの編集が機密ファイルの書き込みとしてブロックされる問題を修正しました
  • DISABLE_TELEMETRY または DO_NOT_TRACK でテレメトリがオフになっている場合、有料プランでリモート コントロールが利用できない問題を修正
  • /remote-control メニューが幅の狭い端末で QR コードのヒントを単語の途中でカットする問題を修正しました
  • vim モード . で Shift+Enter 改行が削除され、カーソルがアクセント文字の中に残り、最後の行の 3J またはビジュアルモード J の後に古い変更が繰り返される問題を修正しました。
  • vim モードのカーソル位置を修正しました。通常モードで 10,000 文字を超えるプロンプトを呼び出しても、カーソルが末尾を超えて残されることがなくなり、V の次に p が最初の非空白に配置されるようになりました。
  • Vim モードの J が Vim とは異なる間隔 () の前やタブの後のスペースなど) で行を結合する場合と、最終行の 3J またはビジュアルモード J が Vim のようにカーソルを移動しない問題を修正しました。
  • Windows: cmd /c rd、rmdir、del、または erase がドライブ ルート、ホーム フォルダー、および Remove-Item が拒否するその他のフォルダーを削除できる PowerShell ツールを修正しました。
  • /mcp ツール リストを改善しました。一度により多くのツールを表示し、ページ キーとマウスでスクロールし、組織がブロックしているツールを警告アイコンでマークします。
  • MCP ツールの結果の改善: MCP ツールから返された画像もファイルに保存されるようになり、Bash、Read、およびその他のツールで開くことができるようになりました。
  • /tasks の改善: 行にはステータス アイコン、名前と事実全体が表示され、タイトルとキーのヒントは多くのタスクとともに画面上に表示され、リストにはページング キー、マウス ホイール、click が追加されました。
  • /help、/hooks、/copy、/chrome、/memory、/ide、/release-notes、/rewind、/diff、/remote-env、/plugin、およびページ キー、マウス ホイール、click を備えたその他のピッカーのリストの改善
  • /skills や /artifacts など、検索ボックスの横にあるリストを改善し、検索ボックスにキーがある間はポインターを暗く描画し、1 つのポインターのみが強調表示されるようにしました。
  • 圧縮スピナーを改善しました。圧縮の開始時にタイマーが開始され、ストリーミング時にサマリーのトークンがカウントされ、パーセンテージ バーが置き換えられます。
  • MCP サーバーにサインインした後に表示されるブラウザ ページを改善しました: 中央揃えのレイアウト、ダーク モード、新しいアートワーク
  • スキルがロードに失敗したプラグインに属している場合のスキルツールの応答を改善しました。クロードは、スキルをアンインストールしたと呼び出す代わりに、プラグインをロードできなかったことを通知します。
  • クロード コード構成に関する prompt-audit の改善: 古いパス、古いコマンド、矛盾する命令ファイルがレポートをリードし、クロード コード ドキュメントが保持される思考キーワードが表示されるようになりました。
  • まったく読み取ることができない installed_plugins.json からのリカバリの改善: その内容は再構築される前にその横のファイルに保持され、claude plugin list はそのファイルに名前を付けます
  • アーティファクト データベースの読み取りの改善: ページ全体を返す順序付けされたクエリで、それが 1 ページであり、残りの読み取り方法が表示されるようになりました。
  • 最初の応答のレイテンシの改善: セッションの最初の応答の最後に実行されていたパターン コンパイル ステップが、応答がストリーミングされている間も実行されるようになりました。
  • 事前接続された API 接続を再利用することで、最初のリクエストのレイテンシーが改善されました
  • 起動の改善: claude -p と Claude Code Remote はインタラクティブ UI をロードしなくなり、自動モード分類子のルールとアーティファクト ツールは起動時ではなく最初の使用時にロードされます。
  • 最初の実行時と同様、アーティファクト ツールの機能がまだわかっていない claude.ai アカウントの起動が改善されました。プロンプトはチェックするために 1.5 秒まで待機しなくなりました。最初のメッセージは必要に応じて待機します
  • 許可モードが設定されていない場合、サードパーティプロバイダーでの対話型セッション、またはテレメトリがオフの対話型セッションが自動モードで開始されるように変更されました。 permissions.defaultMode は依然としてそれをオーバーライドします
  • /ultrareview 起動ダイアログを変更して、ローカル ブランチをレビューするとコミットされていない変更が追跡ファイルにアップロードされる可能性があることを示すようにしました
  • /model ピッカーの Opus 行とデフォルト モデルの名前を変更して、Opus にはすでに 1M コンテキスト ウィンドウがある「(1M context)」を削除しました。窓は変わらず
  • 20 回連続で使用されなくなると、ターミナルのプロンプト提案が表示される頻度が低くなるように変更されました。使用すると元に戻ります
  • --system-prompt と --append-system-prompt を、テキストと -file フォームを一緒に受け入れるように変更しました。ファイルのテキストが最初に来ます
  • Claude Desktop がスキルをプラグインとして配信し、Skill(skill:<name>) がスキルのエイリアスと表示名との一致を拒否する場合に、そのスキルもブロックするように Skill(anthropic-skills:<name>) 拒否ルールを変更しました。
  • /rewind および /diff リストを、他のすべてのリストと同じキーバインド アクションで移動するように変更しました (select:*)。 messageSelector:*/diff:* の再バインドは引き続き機能します
  • /workflows 実行リストを他のリストと同じサイズに変更しました。端末の半分がインラインになり、以下のプロンプトが表示されたときにタイトルが画面上に表示されます。
  • git のインストール時に git 2.31 以降を必要とするように claude plugin eval を変更しました。古い git での実行は拒否され、バージョンを示すメッセージが表示されます
  • 変更されたアーティファクトの監視: (要求したものではなく) 自動的に準備された監視は、アクティビティがない状態で 3.5 時間後に終了するようになりました。アーティファクトを再度公開または視聴すると、アーティファクトが再装備されます
  • セルフホスト ランナー: リポジトリの Git LFS pre-push フックをスキップし、書き込み可能なシステム core.hooksPath を無視し、--configure-git なしのコミットに署名しないように、ライフサイクル フックの Git を変更しました。
  • 自己ホスト型ランナー: Anthropic が管理する git の下で GIT_SSL_CAINFO と GIT_SSL_NO_VERIFY を変更しました: ランナー自身の git は常に Anthropic の git ルートを検証し、警告行には何が適用されるかを示します。
  • claude-ai 名の 2.1.282 予約を取り消しました: スキル、コマンド、ワークフロー、MCP サーバーのスキルとその名前のプロンプトが再度ロードされ、Skill(claude-ai:*) ルールは通常のプレフィックス ルールです
  • [VSCode] セッションからの自動切り替えが失敗した後、セッションが自動またはバイパス モードで実行され続けている間、許可モード インジケーターがデフォルトを表示する問題を修正しました。スイッチは着地するまで再試行されるようになりました
  • [VSCode] クロードの作業中に送信されたメッセージがドロップされる Web からテレポートされたセッションを修正しました
  • [VSCode] 古いバージョンで空のローカル コピーが保存されていた場合、Web セッションがセッション リストから非表示のままになり、代わりに空のチャットが開く問題を修正しました。
  • [VSCode] 自動継続など、クロードがターン途中に受け取ったメッセージでターンを分割する再開セッションを修正しました
  • [VSCode] 巻き戻されたターン、または圧縮前の行のみを表示するリロードされたセッションを修正しました
  • [VSCode] 狭いパネル内で、フッターのエージェント ピルがアイコンを中心からずらして描画し、ステータス ドットが端に当たる問題を修正しました。
  • [VSCode] 長いプロンプトに改行で終わる行を貼り付けた後、チャット入力がカーソルの少し下にテキストと選択範囲を表示する問題を修正しました。
  • [クラウド セッション] 実行中のクラウド セッションへのリポジトリの追加が改善されました。GitHub アカウントは読み取り可能ですが、プッシュはできないプライベート リポジトリが読み取り用に接続されるようになりました。
  • [クラウド セッション] サーバー側の再起動から回復した後、クラウド セッションで重複したコメントの投稿やプッシュなど、既に完了したステップがやり直しになることがある問題を修正しました。
  • [クラウド セッション] 新しいルーチンのスケジュールがデフォルトで正時を数分過ぎるように変更されました。ただし、正時に正確に設定されたルーチンは数分遅れて開始される可能性があることに注意してください。
  • [Claude Tag] 「Claude can search」管理設定を追加しました。これは、Claude の Slack 検索を、組織、ワークスペース、またはチャネルごとに設定された、追加されているパブリック チャネルに制限します。
  • [Claude Tag] Claude アカウントを接続した後に表示されるページに、開始したスレッドに戻る [Slack に戻る] ボタンを追加しました。
  • [Claude Tag] チャネルがアタッチ ルールを通じてアクセス バンドルを取得するときに、チャネルの設定ページにコネクタやプラグインが表示されない問題を修正しました。ルールが添付されたバンドルが表示されるようになりました
  • [Claude Tag] 選択されたリポジトリの大規模なリストに限定されている GitHub アプリのインストールで、アクセス バンドル リポジトリの検索で見つからないリポジトリが修正されました。
  • [Claude Tag] 新しいメッセージが返信の途中で中断した場合、クロードが同じ返信を 2 回投稿することがある問題を修正しました。
  • [Claude Tag] Slack Connect 共有後など、Slack チャネル ID が変更された古いプライベート チャネルで実行が停止するチャネル ルーチンを修正しました。
  • [Claude Tag] 「チャンネルのみ」に設定されているチャンネルでの会話が、ゲスト以外のメンバーが参加し、Slack がメンバーシップを確認するのに時間がかかるとすべて終了してしまう問題を修正しました。
  • [コード レビュー] GitHub がプル リクエストを返せなかったときに「@claude review」リクエストがサイレントになる問題を修正しました。リクエストは 1 回再試行され、それでも失敗する場合はコメントで説明されます。
  • [コードレビュー] 何も検証されずに制限時間で停止したレビューの請求を修正しました。レビューは不完全として表示され、請求されず、1 回再試行されるようになりました。
