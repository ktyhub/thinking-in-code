claude-code v2.1.318

パッチ 公開日2026年11月4日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.318

何が変わったのか

  • Claude Code がセッションで書き込む MOD をオンにするように要求したときの回答の記録を追加しました
  • 別の AWS アカウントのロールおよび開発者ごとの AWS コスト帰属のために、Claude アプリ ゲートウェイの mantle アップストリームに assume_role を追加しました。
  • MOD の $.model.fork に effort オプションを追加したため、セッションがどのような労力を費やしても low で簡単なサイド ジョブを実行できます。結果は送信された労力を報告します
  • 保存された claude.ai サインインが終了する日付を claude auth status (loginExpiresAt) および claude -p JSON 結果 (credential_expires_at) に追加しました。
  • 保存された claude.ai サインインが終了する 10 日前から、claude -p テキスト出力に 1 行の標準エラー出力警告を追加しました。
  • 不正なツール呼び出しの再試行が終了した後、--continue が以前の会話を失うことがある問題を修正しました (2.1.314 の回帰)
  • メモリ増加中に多くの Bash コマンドが実行されている macOS セッションが停止する問題を修正
  • メッセージの送信直後、または遅いプロンプトが表示される前に入力されたキーによって許可プロンプトに応答する問題を修正しました。
  • 共有ネットワーク ホーム ディレクトリで構成ファイルを更新できなかった場合に、/logout、claude auth logout、claude mcp remove が成功を報告し、trust への変更、同意または MCP 設定が何も言わずに削除される問題を修正しました。
  • 別の端末またはホストが同じホーム上の同じアカウントおよび組織に再度サインインすると、ジョブが Not logged in で終了する問題を修正しました。
  • ロックなしで構成を書き込む claude mcp add と remove を修正しました。現在は、それを待つか終了 1 を実行しますが、別のジョブの保存によって保存されたサーバーが置き換えられる可能性があります。
  • 低速トークン更新が保存される前に終了する claude plugin コマンドを修正しました。これにより、次回の実行時にサインアウトする可能性がありました。
  • claude plugin marketplace add が拒否するカスタム名付きのマーケットプレイス ファイルを渡す claude plugin validate を修正しました
  • 起動するたびに再プローブされるバージョン プローブで終了する標準出力 MCP サーバーを修正しました。独自の理由で 3 秒以内に停止したサーバーも、7 日間レガシー ハンドシェイクに固定されます
  • 同じマシン上の別のログインが保存した allowedProviders リストによって起動時にセッションが拒否される問題を修正
  • 会話を要約ではない返信に置き換えるアイドル圧縮を修正しました
  • バックグラウンド サブエージェントの実行中に約 30 秒ごとに再表示される「使用量クレジットを使用中」という通知を修正しました
  • 失敗する、またはクロードのみが呼び出すことができ、claude -p および SDK セッションで何も出力されないカスタム スラッシュ コマンドを修正しました。
  • MOD が turn.step をフックしているときに API エラーによって応答が遮断された場合に、claude -p およびエージェント SDK セッションが成功を報告する問題を修正しました。
  • モデル変更の直後に送信されたメッセージが、ヘッドレス セッションで [停止] 後も実行中である問題を修正しました。[今すぐ停止] は、キューに入れられたメッセージと同様にキャンセルまたは停止します。
  • アイドル状態の非対話型セッションが終了したときに、削除されたセッション トランスクリプトが最後のプロンプトとともに再作成される問題を修正しました
  • 更新またはバージョンのクリーンアップによってまだ実行中のプロセスのバイナリが削除された後、claude remote-control ホスト、バックグラウンド デーモン、およびセルフホスト ランナーが新しいセッションの開始に失敗する問題 (spawn ENOENT) を修正しました。
  • 別のユーザーが所有する実行中のクロード コード プロセス (sudo claude が残したものなど) がバージョン クリーンアップによって無効として扱われ、そのバイナリが削除される可能性がある問題を修正しました。
  • 接続に失敗した後にセッションが利用可能であると表示される /remote-control を修正しました
  • リクエストが 404 で失敗した場合に成功を報告する /design revoke を修正しました
  • 自己ホスト型ランナーまたはクラウド セッションの再起動後に、要求されたフォルダーではなく、セッションの開始フォルダーで実行されるシェル コマンドが承認される問題を修正しました。そのフォルダーに入れない場合は実行されません
  • クラウドセッションの再起動後に承認されたコネクタツールが利用できなくなったときにクロードに通知されない問題を修正
  • サービスが数分間アップロードを拒否した場合、ターンの途中でクラウドセッションが停止する問題を修正
  • 一部のクラウド セッションで、Setup フックが CLAUDE_ENV_FILE に書き込む変数が Bash ツールに到達しない問題を修正しました
  • ツール呼び出しで応答が途切れた後、または拒否された画像やドキュメントが削除された後、クラウド セッションの実行中にクラウド セッションのターンが終了したと表示される iPhone アプリを修正しました
  • API エラーで失敗したメッセージを、背後で待機している新しいメッセージより先に再送信する再起動されたセッションを修正しました。
  • クロードが大きな画像を読み込んだか、ツール呼び出しを再試行した直後に再起動が行われた場合、再起動されたセッションが中断されたターンを落とす問題を修正しました
  • NODE_EXTRA_CA_CERTS ファイルが PEM ではなく空である場合、または破損した証明書で開始される場合に失敗するすべての接続を修正しました。読み取り可能な証明書が使用されるようになり、stderr に警告が表示されます。
  • 使用制限後に再開されると、終了したエージェントが再実行されるワークフローを修正しました
  • モデルが使用できないクラウド セッション カウント ツールの /mcp を修正しました。サーバーの行には、利用可能なツールの数が表示されるようになりました
  • クロードが PushNotification 呼び出しからステータス フィールドを離れたときの重複した通知を修正しました
  • 20 枚を超える画像を含むリクエストで大きすぎる画像が常に制限が 2000 ピクセルであると表示されるエラーを修正しました。 API の制限が表示されるようになりました
  • ダイアログが開いている間、バックグラウンドシェルの詳細が更新されないランタイムを修正しました
  • ヘッドレス実行で停止した応答を成功として終了させる MOD の turn.step フックを修正しました
  • ~/.claude.json バックアップなしで claude -p のみを実行するホームを残す保持クリーンアップを修正しました。最後の正常なバックアップを削除する前に、新しいバックアップが取得されるようになりました。
  • ネットワーク ホーム ディレクトリにデータ用の余地が残っていないにもかかわらず、新しいファイルが必要な場合に、保存されたログインが空のファイルに置き換えられる問題を修正しました。
  • トークンが許可された組織に属している場合、setup-token からのトークンが forceLoginOrgUUID を搭載したマシンの起動時に拒否される問題を修正しました
  • 有効な JSON ではない ~/.claude.json をデフォルトで置き換える非対話型起動を修正しました。起動が失敗し、ファイルを復元する方法が表示され、そのままになります (anthropics/claude-code#87551)
  • バックアップのない空の ~/.claude.json が破損していると報告される問題を修正しました。ファイルが見つからない場合と同じようにクロード コードが開始されるようになりました。
  • 破損または欠落している ~/.claude.json に対して出力される復元コマンドで、空またはカットオフのバックアップを指定するか、読み取り専用ファイルで失敗するコマンドを修正しました。
  • 保存された claude.ai ログインが制限時間に達したときのサインインの失敗を修正しました。現在はそのように表示され、claude -p では claude auth login と claude setup-token という名前になります。
  • ~/.claude.json、設定ファイル、および保存されたログインが共有ネットワーク ホーム ディレクトリに保存される方法が改善されました。これらは、削除されたり、一時的に空になったり、空に近いコピーや古いコピーに置き換えられることが少なくなります。
  • ネットワーク ファイル システム上のセッションが改善され、構成ファイルが見つからないと誤って報告された場合に再確認できるようになりました。そのため、MCP サーバーと trusted フォルダーなしで開始されるセッションが少なくなります。
  • MCP ツールのエラーの改善: ツールがロードされる前に行われた呼び出しは、その入力スキーマを返すようになりました。
  • Bash ツールが macOS の組み込み /bin/bash を実行する場合の git コミットとプル リクエスト作成の信頼性が向上しました。
  • 使用量制限メニューの「管理者にさらに使用量を要求する」を改善し、ワンステップでリクエストを送信できるようにしました。
  • 一時停止またはスリープ後のリモート セッションの再接続速度が向上しました
  • ターミナルでのみ機能する「2 を押してください」の代わりに「もう一度試してください」というトーストを知っておく必要があるのを改善しました
  • 自動更新の信頼性の向上: リリースの検証中に短時間のネットワーク障害が発生した場合、次のチェックを待たずにすぐに再試行されるようになりました。
  • 無人実行 (claude -p、SDK アプリ) が改善され、実行のたびに何も変更されなかった場合に ~/.claude.json を書き換えることがなくなりました。
  • IDE ターミナルで起動したときに IDE 拡張機能をインストールまたは更新しないようにクロード コードを変更しました。外部端末またはエディタの拡張機能ビューから /ide を使用します。
  • 「メッセージにフラグが立てられたときにモデルを切り替える」が「毎回確認する」に設定されている場合、モデルを切り替える代わりにサブエージェントを停止するように変更しました。
  • すべてのプロバイダーで 3 分後にシェル コマンドをバックグラウンドに移動するようにバックグラウンド サブエージェントを変更しました。これにより、実行中にプロンプト キャッシュの有効期限が切れなくなります。
  • Bedrock、Vertex、Foundry、またはテレメトリがオフの場合のサブエージェントの進行状況の概要が変更されました。コールド プロンプト キャッシュでは、サブエージェントの保留中の応答を最大 5 分間待つことができるようになりました。
  • prompt.submit で MOD がアタッチする内容を、システム メッセージとして出力されるのではなく、ユーザーのターンに留まるように変更しました。
  • deniedMcpServers URL エントリを変更して、アップストリーム URL が一致する Anthropic 提供のサーバー、およびセッションにコネクタ独自の URL が与えられるクラウド セッションおよび自己ホスト ランナー上のコネクタもブロックするようにしました。それ以外の場合は、コネクタを名前で拒否します
  • /permissions ルールの詳細、組み込みルール、および削除確認ビューを標準ダイアログを使用するように変更しました。 Ctrl+C を 2 回押すと、終了するのではなく戻るかキャンセルされるようになりました。
  • 新しいエージェントの組み込みツールとクイックスタート テンプレートの MCP ツール、auto 権限ポリシー (「危険なアクションを判断する」) をデフォルトで提供し、クロード コンソールと一致するように /claude-api managed-agents-onboard を変更しました。オプトアウトするには「尋ねずに実行する」と言ってください
  • 2.1.286 以前で開始された会話を再開するときにモデルの以前の思考を維持する 2.1.288 修正を削除しました。その考えは今なら捨てられる
  • ゲートウェイ: フェデレーション (external_account) 資格情報ファイルからの Google アクセス トークンの有効期限が近づいている場合のログ警告を追加しました。
  • ゲートウェイ: listen.trusted_proxies に関するログ ヒントを改善しました。接続アドレスを X-Forwarded-For 自体に追加するプロキシのみをリストするようになりました。
  • ゲートウェイ: Amazon Bedrock で AWS CountTokens が失敗した場合の警告を改善しました。ゲートウェイではなくクロード コードであると表示され、501 以降をカウントし、AWS がアクセスを拒否した場合にのみ IAM を指します。
  • 自己ホスト型ランナー: オーケストレーターのスポーンランナーフック環境に CLAUDE_RUNNER_SPAWN_REASON を追加しました: Anthropic がリクエストを送信した理由 (例: runner_lost、resumed)。何も送信されなかった場合は設定が解除されます
  • セルフホストランナー: --release-idle-session-min が値のない最後の引数である (依然として無視される) か、スペースのみの値を持つ (依然として 0 として読み取られる) 場合の起動警告を追加しました。
  • セルフホスト ランナー: オーケストレーターのログ行を変更しました。ok session=… は、標準出力 (デバッグ専用、標準エラー出力) のすべてのログ レベルで jti=… の後の reason=… を出力し、nack session=… は retryable=… の後の reason=… でフィールドを終了します。 retryable=true: または retryable=false: に一致するスクリプトを更新します
  • リモート コントロール: セッションの作業フォルダーが見つからない場合の誤解を招く「スポーン エラー: ENOENT」を修正しました。エラーによりフォルダーに名前が付けられるようになりました
  • リモート コントロール: アプリが設定していない場合にターミナル フォークのフォークが作成されるタイトルを改善しました: 「名前 (フォーク 2)」
  • [VSCode] 組織のサインイン設定により、バックグラウンドでの新しいクロード コード プロセスの開始が毎分拒否されるウィンドウを修正しました
  • [VSCode] チャット パネルのエラー バナー内の長い単語が表示されずに閉じるボタンを押してしまう問題を修正しました。
  • [VSCode] サインイン ステータス チェックが失敗した場合にクロード コードが出力する内容を表示するようにサインイン画面を改善しました。
  • [クラウド セッション] リポジトリなしオプションを追加しました。Anthropic がホストする環境上のクラウド セッションは、リポジトリを選択せずに開始できるようになりました。
  • [クラウド セッション] 通常の Chrome 名をクラウド セッションに追加しました。これにより、Playwright 以外のツールは、google-chrome と CHROME_PATH を通じて組み込みの Chromium を見つけることができます。
  • [クラウド セッション] クラウド セッションの環境が削除されたときに表示されるカードに、メッセージ ボックスが非表示になる新しいセッション ボタンを追加しました
  • [クラウド セッション] クラウド セッションでの GitHub アクション ログの読み取りを修正しました: gh run view --log および gh api ログ リクエストは、ほとんどの環境で、到達不能なリダイレクトではなくログを取得するようになりました。
  • [クラウド セッション] クラウドおよびリモート コントロール セッションでの PR 作成失敗メッセージのほとんどが改善されました。「再試行」というメッセージの代わりに、理由または GitHub へのリンクが表示されるようになりました。
  • [クラウド セッション] コネクタの検索結果を変更して、検索がコネクタ ディレクトリの一部のみをカバーすることをクロードに伝えるようにしました。
  • [リモート コントロール] 環境メニューのリモート コントロール行で、1 つのリポジトリの並列チェックアウトが同一に見える問題を修正しました。それぞれに独自のフォルダー名が表示されるようになりました
  • [Claude Tag] Claude Tag 管理設定におけるキーボード フォーカスとスクリーン リーダーのアナウンスを修正しました。接続フォームで Esc キーを押しても、追加ダイアログが閉じなくなりました。
  • [コード レビュー] サーバーまたはネットワーク障害後に 1 回再試行し、空のカードの代わりに再試行バナーを表示するようにコード レビュー分析ページを改善しました。
