claude-code v2.1.304

パッチ 公開日2026年10月19日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.304

何が変わったのか

  • 最初に実行されるプラグインが MOD のフックの 1 つをスキップするときのトランスクリプト行を追加し、イベントとプラグインに名前を付けました
  • MOD の tool.check 回答に decider: "person" を追加しました。許可ダイアログまたはホストのコールバックのみが質問を承認でき、誰も質問できない MOD の理由で拒否されます。
  • ツール呼び出しが読み取り専用の場合に設定される、MOD の tool.check イベントに e.isReadOnly を追加しました。
  • /auto-mode-setup を追加しました: プロジェクトと最近のセッションを読み取り、環境について自動モードを教えるガイド付きセットアップ。Bedrock、Vertex、Foundry、Claude アプリ ゲートウェイおよびテレメトリが無効なセッションでも利用できるようになりました。
  • 何も変更せずに、管理対象エージェントのエージェント設定と Anthropic が公開しているセキュリティ ガイドを比較する /claude-api managed-agents-secure を追加しました。
  • トランスクリプト ビューの圧縮概要に以前に呼び出したツールの名前を追加しました (Ctrl+O)
  • 非アクティブな会話を再開すると、5 時間の使用制限のかなりの部分が使用される場合、Pro プランと Max プランに警告を追加しました。とにかく再開するか、新しい会話を開始すると、クロードは前の会話を参照できます。
  • 起動時に ANTHROPIC_API_KEY を承認するか、/config で「カスタム API キーを使用する」に切り替えた後、1 時間ごとのチェックが行われるまで組織ポリシーが更新されない問題を修正しました。
  • sandbox.filesystem.denyRead グロブに文字クラスではない括弧 ([user-id] ルート フォルダーなど) が含まれている場合、Linux でサンドボックス コマンドが起動できない問題を修正しました。
  • マウントされたドライブまたは最上位のフォルダー (/Volumes、/media、WSL の /mnt/c) の rm -r で、rm -rf /Applications が受け取る安全性プロンプトが表示されない問題を修正しました。
  • ファイルのトリミング中にディスクがいっぱいになると、保存されたトランスクリプトからメッセージがドロップされる CLAUDE_CODE_TRANSCRIPT_LOCAL_GC を修正しました
  • サブエージェントを生成するか、完了したものを再実行することによって、--max-turns、停止、または終了した入力を超えるヘッドレス実行を維持するプラグインを修正しました
  • 失敗したMODのリロードでロードされたままのバージョンのツールとコマンドが削除され、そのメッセージが間違っているか、前のバージョンがまだロードされているかどうかについて表示されない問題を修正しました。
  • 同じラベルがあり、key がないボタンが変更されずに再描画されると、MOD ボタンの click が失われる問題を修正しました
  • 組み込みのplugin-authoringスキルでのMOD共有が、管理された設定を持つマシンおよびチームおよびエンタープライズプランのシークレットスキャンで停止する問題を修正しました
  • スケジュールされた Cowork クラウド セッションが、WebFetch に URL 承認が必要で誰も与えることができなかったサブエージェントごとに再び 5 分間待機する問題を修正しました。
  • 作業ディレクトリ外のファイルを ../../… として表示する書き込み結果と拒否された編集を修正しました。 ~/… またはフルパスが表示されるようになりました。
  • Cowork クラウド セッションで「/」メニューから選択した場合に、claude.ai ディレクトリ プラグインのスキルがコマンドとして実行されない問題を修正しました
  • 別のアカウントが端末にサインインしたときにリモート コントロールがデスクトップ会話の履歴を永久に保留する問題を修正しました
  • 有料プランで DISABLE_TELEMETRY または DO_NOT_TRACK が設定されている場合、Claude Desktop からリモート コントロールが起動できない問題を修正
  • SDK およびデスクトップ セッションでのコンテキスト使用チェックの背後で待機しているモデルのスイッチ、メッセージ、および割り込みを修正しました
  • LLM ゲートウェイの背後にある context_management: Extra inputs are not permitted エラーを修正しました。 Claude Code はそのフィールドなしでリクエストを再送信するようになりました
  • サーバー管理設定を通じて配信された OpenTelemetry 設定が、初回実行セットアップ中または /logout 後の最初の起動中にサインインした後、セッション全体で無視される問題を修正しました。
  • macOS および Linux 上の Claude Desktop Code タブ セッションのサンドボックス化されていない Bash コマンドで、~/.zshrc などのシェル起動ファイルにエクスポートされた環境変数が表示されない問題を修正しました。
  • サーバーエラー後に消費者規約通知が 1 日以上スキップされる問題を修正
  • ネットワークまたはサーバーのエラー後に適用されない可能性のある選択肢を提供する /privacy-settings を修正しました
  • クロード・コードがAPIが長すぎるとして拒否した会話を圧縮しているときにターンを停止した後の「コンテキスト制限に達しました」または「プロンプトが長すぎます」エラーを修正しました
  • 終了直後にメッセージを受け取ったり再開したりすると、サブエージェントが最新の作業を忘れてしまう場合がある問題を修正
  • 実際の動作と一致するように、--tools、--resume、--debug、--json-schema、--disable-slash-commands、--system-prompt-snapshot、claude update の claude --help テキストを修正しました。
  • HEAD が切り離されたとき、または別のブランチにあるときに、終了時に確認せずにワークツリーとそのブランチを削除する claude --worktree を修正しました。これにより、コミットが失われる可能性がありました。
  • 起動時にプラグインがリロードされるたびにクロードにスキルリスト全体を再度送信する、再開されたクラウドセッションを修正しました
  • アイドル状態のパイプまたはイメージのような名前のデバイスを待機する読み取りが終了しない割り込みを修正しました
  • CLAUDE_CODE_EFFORT_LEVEL が auto または unset でレベルが送信されない場合に、/effort status、/effort ultracode、およびプロンプトの努力レベルを示すプロンプトの努力インジケーターを修正しました。
  • 同じツール呼び出しのエージェント SDK コールバック フックがタイムアウトになったときに、PreToolUse フックの拒否理由がタイムアウト エラーに置き換えられる問題を修正しました。
  • ディスクがいっぱいでない限り、大きなコマンドの出力ファイルをセッションのツール結果フォルダーにコピーできない場合に、Bash と PowerShell がその出力ファイルを削除する問題を修正しました。
  • 約 100 列以下のターミナルでプレビューが「…」で切り取られ、入力された内容が非表示になる、多肢選択の質問に入力されたメモを修正しました (anthropics/claude-code#82768)
  • 1 時間のプロンプト キャッシュが期限切れになった直後に発生する最大 1 時間でスケジュールされたセルフペースの /loop ウェイクアップを修正しました。そのため、これらのウェイクアップは、キャッシュされていない会話を再読み取りしなくなりました。
  • エージェント チームの修正: メイン セッションからのシャットダウン リクエストを承認しても、CLI 全体が終了しなくなりました。
  • スキルの once フックが実行後に別のスキルの同一のフックも削除する問題を修正しました
  • トランスクリプト モードの { および } が、トランスクリプトの最初の行ではなく、一貫性のない行、または画面外にプロンプトを表示する問題を修正しました。
  • 100K ウィンドウをサイレントに設定する CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k を修正しました。変数は --autocompact のような k および M 接尾辞を受け入れるようになり、値が範囲外または無視された場合に警告します。
  • エージェント ビューで Ctrl+C を押すと、マウス ボタンが放される前にテキスト選択がコピーされずにクリアされてしまう問題を修正しました。
  • 使用状況データのレート制限が終了すると、「しばらくしてからもう一度お試しください」ではなく通知するように /usage を改善しました。
  • セッションに書き込まれた MOD がロード、リロード、またはロードに失敗したときに表示される行を改善しました
  • 複数のビューに関するアーティファクトの改善: それらへのリンクを要求すると、クロードは各ビューのリンクを書き出し、ビューを切り替えてもアドレス バーが同じままであることを説明するようになりました。
  • クラウド セッションの改善: サーバーが alwaysLoad: true を設定しない限り、新しい会話の最初のターンは、claude.ai から同期されたプラグインのローカル (stdio) MCP サーバーを待機しなくなりました。
  • サーバーが他のセッション データを伝送するステータス更新を拒否した場合に、リモート セッションがステータスを回復する方法を改善しました。
  • 自動モードでのセッション ファイル サイズの改善: 安全性分類子のコンテキストはリクエストごとに保存されなくなりました。
  • claude -p 無効な設定の警告を改善しました。ロードされなかったファイルには、それを停止したもののみがリストされ、長いリストはファイルごとに制限されます。
  • SDK およびヘッドレス モードでの大規模な圧縮セッションの再開が改善されました。再開後の最初のリクエストがより早く送信されます。
  • 多くのサブエージェントが同時に実行されている場合の応答性とスループットの向上
  • 長い会話または再開された会話でリクエストを送信する際のメモリ使用量が改善されました
  • セルフホストランナー: git ホストがセッションのリポジトリに対して「見つかりません」と応答したときに表示されるエラーを改善しました。リポジトリの名前と問い合わせ先を指定するようになりました。
  • Windows: cmd ランチャー経由ではなく git.exe を直接実行することで、標準の Git for Windows インストールでの git コマンドの起動が改善されました。
  • 各設定レイヤーを受け取り、マージされた設定を書き換えるように MOD の settings.read フックを変更しました。これにより、管理対象 MOD は、リテンション スイープが使用する cleanupPeriodDays を含め、組織の設定を上限にすることができます。
  • 番号付きの選択肢を表示するように /artifacts の削除確認を変更しました。1 または Enter でアーティファクトが保持され、2 で削除されます。y、n、Esc は引き続き機能します。
  • クロードがセッションで書き込む MOD を有効にする質問を、リンクやセッション ID のないプレーン テキストに変更しました。新しいターンが始まっても起動したままになり、オンにすると何がロードされたかをクロードが教えてくれます。
  • ツール検索がカスタム ANTHROPIC_BASE_URL の背後でデフォルトでオンになるように変更されました。ゲートウェイからの 400 または 422 は、それなしで再試行されます。
  • その後クロードにスキルリストを再度送信するようにコンパクションを変更しました。 /reload-skills は新しいスキルまたは変更されたスキルのみを送信するようになりました
  • スキルフックの変更: 1 つのソース (リポジトリ、独自のフォルダー、またはプラグイン) のスキルは、セッションごとに最大 1,024 個のフックと 16,384 個のマッチャー文字を登録できます。
  • プラグインからのフックのみを許可するポリシーに基づいてスキルを変更しました。フックが除外されているメインの会話で使用されるスキルは、allowed-tools を取得しなくなります。
  • SDK またはカールにフォールバックする代わりに、AWS のクロード プラットフォームで ant CLI を使用するように /claude-api スキルを更新しました。
  • MOD のフックが実行される場所を予測するメモを claude plugin validate から削除しました
  • Opus 5.5 の /fast ダイアログ タイトルから「(リサーチ プレビュー)」ラベルを削除しました。
  • [VSCode] LLM ゲートウェイの背後、またはテレメトリがオフになっている Amazon Bedrock、Google Vertex AI、Microsoft Foundry でのセッションのチャット パネルに MOD 描画を追加しました
  • [VSCode] 「サブプロセスの初期化が 60000 ミリ秒以内に完了しませんでした」というメッセージでセッションの開始に失敗する原因の 1 つを修正しました。SessionStart コマンド フックの実行に費やされる時間は、合計で最大 10 分まで制限にカウントされなくなりました。
  • [VSCode] セッションが開始中に終了し、開始が終了するまでクロード コード プロセスを実行し続ける問題を修正しました。
  • [VSCode] 古いクロード コードも実行しているマシンを次にオンにするまで、長時間開いたパネルから MOD の描画が消える問題を修正しました。
  • [VSCode] claudeCode.claudeProcessWrapper が設定されている場合に過去の会話がセッションを非表示にしてしまう問題を修正
  • [VSCode] バックグラウンド サブエージェントを、チャットにすべてのステップをストリーミングするのではなく、エージェント カードの下に 1 つのステータス行として表示するように変更しました。完全なトランスクリプトは /tasks に残ります
  • [クラウド セッション] クラウド セッションで作曲家の @ リスト内のフォルダーに名前が表示されず、フォルダーを選択するとメンションではなくスペースのみが追加される問題を修正しました。
  • [Claude Tag] タスク中にチャネルが Enterprise Grid ワークスペース間で共有されると、スレッド内でクロードが沈黙する問題を修正しました。新しいスレッドで @ メンションするための 1 回限りのメモを投稿するようになりました
  • [Claude Tag] スレッド外で入力された @Claude !fork が目に見える応答を取得しない問題を修正。クロードは、スレッド内から実行するようにというプライベート メモを表示します。
  • [コード レビュー] コード レビューにレビュー レベルを追加しました: 所有者は組織に対してクイック、標準 (デフォルト)、またはディープを選択し、個々のリポジトリに独自のレベルを与えることができます
  • [コード レビュー] コード レビューの管理設定に、GitHub 組織内のすべてのリポジトリ (後で追加されたリポジトリを含む) を 1 つずつ選択せずにレビューできるオプションを追加しました。
  • [コード レビュー] 管理者がコード レビューをオンにしてから 1 ～ 2 分以内に開かれたプル リクエストがサイレント スキップされる問題を修正しました。現在、再試行され、レビューされています
