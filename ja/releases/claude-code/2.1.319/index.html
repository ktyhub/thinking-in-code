claude-code v2.1.319

パッチ 公開日2026年11月6日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.319

何が変わったのか

  • LLM ゲートウェイの背後を含む、テレメトリまたは機能フラグをオフにして自動モードを変更しました。サーバーがチェックできない呼び出しは、組み込み分類子へのフォールバックなしで、質問されるか拒否されます。引き続き使用するには、CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定します (Bedrock、Vertex、Foundry は変更されません)。
  • LLM ゲートウェイの背後で自動モードを変更: CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS が設定されている場合でも、CLAUDE_CODE_AUTO_MODE_SERVER=1 はサーバー側のチェックをオンにします。管理設定で後者を設定する場合は、1 も設定する必要があります
  • ターミナルでの MCP タスクのサポートを追加しました。MCP サーバーがツール呼び出しをタスクとして実行すると、クロード コードはそれをすぐにバックグラウンドに移動し、終了時に結果をクロードに通知します。
  • クロード コードをすぐにバックグラウンドに移動するのではなく、ツール呼び出し内で MCP タスクを待機させるための CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND 環境変数を追加しました。
  • permissions.denyInsteadOfPrompting 設定の追加: ターミナル セッション、サブエージェント、チームメイトで、許可プロンプトを待機するツール呼び出しは拒否され、ターンが続行されます。
  • クロード API コードが人々を待たせ、評価に対してより高速な設定を試行させる場所を見つけるための /claude-api latency-optimize を追加しました。
  • テレメトリをオフにすることなく機能フラグの取得を停止する CLAUDE_CODE_DISABLE_FEATURE_FLAGS 環境変数を追加しました。その後、すべてのフラグが組み込みのデフォルトを使用します
  • ゲートウェイがこのバージョン以降を実行している場合、支出制限のないクロード アプリ ゲートウェイの背後にある開発者向けに、今日、今週、今月の支出を /usage に追加しました
  • クロード アプリ ゲートウェイに admin.pooled_conflict_rule と admin.pooled_priority_order を追加し、複数のグループの開発者に対してどのプールされたグループ予算が最初に支払われるかを設定しました
  • ゲートウェイのブラウザー検証ページと Claude Code のサインイン画面にオペレーター定義のメッセージを表示するオプションの login_notice 設定を Claude アプリ ゲートウェイに追加しました
  • クロード アプリ ゲートウェイに CLAUDE_GATEWAY_LOG_FORMAT=json を追加しました。フィールドからレベルを読み取るログ コレクターの場合、操作ログ行は severity、time、message を含む JSON になります。
  • 別のポリシーの availableModels でも、1 つのポリシーが名前でリストするカスタム モデル ID を許可する場合のクロード アプリ ゲートウェイのブート警告を追加しました。
  • Claude Desktop の 11 月 10 日の変更に先立ち、coworkTabEnabled: false または chatSessionRetentionDays に依存する desktopHome を持たないポリシーに対する起動警告を Claude アプリ ゲートウェイに追加しました。
  • claude.ai ログインが終了し、Claude Code が ant auth login からのサインインを継続する場合の警告を追加しました。これにより、使用量が Claude Console 組織に請求されます。
  • 起動時に、Claude Code が ant auth login からのサインインを使用する場合に請求される Claude Console 組織を指定する行を追加しました。
  • 終了したサブエージェントをリストする「このセッションの初期」行を /tasks に追加したため、サブエージェントがリストから外れた後や再起動した後でも、サブエージェントを再度開いてメッセージを送信できます。
  • クラウド セッションでの /loop 確認に、タイマーがコンテナーとともに停止し、存続するループが提供されるという注記を追加しました。
  • クロード コードが新しいサーバーでのみ使用する拡張機能を宣言したために、古いハンドシェイクで接続に失敗するか、空の結果を返す MCP サーバーを修正しました。
  • claude.ai コネクタで長時間実行される MCP ツール呼び出しが、--resume 後に結果を報告しないことがある問題を修正しました。
  • Claude Code が実行されるフォルダーに HEAD という名前のファイルまたはフォルダーがある場合、claude.ai とモバイル アプリでセッションの差分のロードに失敗する問題を修正しました。
  • git リポジトリの最上位に HEAD という名前のファイルまたはフォルダーがある場合に「Diff unavailable」と表示される /diff を修正しました
  • 64 ターン以上でファイルを編集したセッションで、/diff ペインが空白で開く問題を修正しました。
  • 先頭のスペース、タブ、または改行の後に入力されたスラッシュ コマンドが、実行されずにプレーン テキストとしてクロードに送信される問題を修正しました。
  • 再試行するたびにログインが 401 で更新され、他のセッションで 401 が発生して失敗し続けるリクエストを修正しました
  • /context がその後のターンごとに完全なビジュアル グリッドをクロードに送信する問題を修正。クロードはテーブルのみを読み取るようになりました
  • 安全性チェックが利用できないためにアクションが拒否された場合、自動モードで claude -p が 0 で終了する問題を修正しました。テキストと JSON の出力は 1 で終了するようになりました。
  • クロード コードが、ネットワーク ファイル システム (NFS、SMB、Lustre など) 上のプロジェクトについて、Linux の開始時にすべてのプロジェクト ファイルをリストするケースを修正しました。
  • clientが機種変更とオートモードのリクエストを連続して送信すると、オートモードが誤って拒否される場合がある問題を修正
  • サーバー側のレビューがセッションに到達していない場合、たとえば、ドロップする LLM ゲートウェイの背後で、「自動モード サーバー: 有効」と表示される /status を修正しました。
  • サーバーが組織へのフィードバックを拒否した後も、クロードが起草したフィードバック、アンケート、/feedback が表示され続ける問題を修正
  • サードパーティのゲートウェイで送信できないクロードのドラフト フィードバックを修正しました
  • 許可ルールまたは autoMode 設定が非常に大きい場合に、理由を示さずにアクションを拒否する自動モードを修正しました。説明が表示され、autoMode 拒否ルールが設定されていない限り、ターミナルで質問されるようになりました。
  • Bash の拒否および確認ルールが引用符で書かれたコマンドを見逃していたケースを修正しました
  • 詳細モード以外で展開したときに内部マーカーと来歴メモが表示されるサブエージェント ハンドバック レポートを修正しました
  • MCP サーバーが見つからないときに遅延ツール呼び出しが失われるプロンプトを含む claude -p --resume を修正しました。実行は 1 で終了し、呼び出しを維持し、その後の入力を拒否するようになりました。
  • SDK clients に送信された情報メッセージからテキストが欠落するケースを修正しました
  • ディスクがいっぱいのときに、エージェント SDK ホストが失敗した実行自体のエラー メッセージではなく、一般的な終了コード エラーを受け取るケースを修正しました。
  • セッションが別の許可モードで再開されたときに、プラン モードで中断されたターンを再実行する CLAUDE_CODE_RESUME_INTERRUPTED_TURN を修正しました
  • クロード コードがファイルを書き込んでから数秒以内に設定ファイルを編集すると無視される問題を修正しました。
  • 警告なしでセットアップを隠す従来の名前で残っている設定ファイルを修正しました。家に 2 つの設定ファイルがあり、どちらが使用されている場合、クロード コードは標準エラー出力に表示されるようになりました。
  • ~/.claude.json、読み取り専用フォルダーまたはバインドマウントされたファイルへの保存中にディスクがいっぱいになると、設定および編集されたファイルが空になるか切断される問題を修正しました (一度に 1 つのセッションを保存)
  • 上書きするファイルを読み取れなかった場合、書き込みが拒否としてターンを終了する問題を修正
  • 完了したと報告されている間、ほぼ瞬時に終了して出力が失われるバックグラウンド Bash コマンドを修正しました
  • Bash ツールの変更されたファイルの差分で、コマンドが終了直前に書き込んだファイルが欠落している問題を修正しました。
  • 意図したモデルを提案するのではなく、クロード コードを更新するように指示する、opus-5-5 などのモデル名の入力ミスを修正しました。

  • /login 成功画面で Enter キーを押した後の最大 0.5 秒のハングを修正しました。ダイアログはすぐに閉じられ、ログイン後の更新がバックグラウンドで実行されるようになりました。
  • スクリーン リーダー モードで質問に対する「その他」の回答を入力しているときに、Ctrl+G を押しても外部エディターが開かない問題を修正しました。

  • 呼び出してはならず、決して通過できないツールの max: 0 を示唆する claude plugin eval 警告を修正しました。

  • .claude/skills での MOD のホットリロードで、出現直後に削除されたファイルが欠落し、そのリターンが欠落する問題を修正しました。

  • コンソール Web 設定が管理対象エージェント セッションに適用されないという /claude-api スキルを修正し、資格情報と権限の例を強化しました
  • timeout 30 rg foo などのプレーン timeout DURATION でラップされた読み取り専用コマンドに対する不必要な権限プロンプトを修正しました
  • claude.ai 共有チャット リンクを空のページとして記述する WebFetch を修正しました。共有チャットを読み取ることができないため、代わりに会話を貼り付けるように指示されるようになりました
  • データベースのないアーティファクトに再送信されるアーティファクト データベース呼び出しを修正しました。再公開が役立つかどうかをエラーで示すようになりました
  • フォルダー (out_dir) に保存するアーティファクト データベースの読み取りが拒否されるケースを修正しました。

  • /clear がバックグラウンド エージェント、チームメイト、実行を続けるワークフロー、およびバックグラウンド エージェントとチームメイトのフォアグラウンド サブエージェントの実行コマンドを強制終了する問題を修正しました。

  • 許可プロンプトを待っているバックグラウンド セッションに応答を送信するように見えるエージェント ビューを修正しました。返信はボックスに表示され、セッションを開いて回答するためのヒントが表示されます。

  • /model ピッカーを改善しました。古いモデルは、現在のモデルの後にリストされるのではなく、「その他のモデル」行の下にグループ化されるようになりました。
  • 端末の /context が改善され、クロードが読み取るテーブルが短くなります。各リストは最大 10 行を保持し、オンデマンドでロードされる MCP ツールは呼び出されるまでサーバーごとに 1 行を共有します。
  • クラウド セッションでの /usage の改善: プラン制限が表示できない場合に、claude.ai の [設定] → [使用状況] にリンクするようになりました。
  • [VSCode] プラグイン マーケットプレイスを削除するための確認を改善しました。その時点でどのプラグインがインストールされているかを確認するようになりました。
  • 機能フラグを取得せずに端末で動作するように MCP タスクを変更しました (Bedrock、Vertex、Foundry、LLM ゲートウェイ、DISABLE_TELEMETRY)。 CLAUDE_CODE_DISABLE_MCP_TASKS=1 を設定してオフにします
  • 自動モードを変更し、プロジェクトの設定ファイルまたはプラグインをプロジェクト外でオフにすると、サーバー側のチェックを再度オンにできなくなるようにしました。
  • すべての Bash コマンドのルールに従うようにモニターの WebSocket 監視を変更しました。拒否はそれを拒否し、モニターの許可ルールでは、バイパス モードまたは自動モードでプロンプトがスキップされなくなりました。
  • CLAUDE_CODE_PROXY_RESOLVES_HOSTS を変更し、ホストがネットワークを管理する場所に設定ファイルを設定できないようにしました。プロセス環境に設定します
  • より広範な拒否ルールがコマンドをカバーする場合、セッションの正確な Bash または PowerShell の質問ルールが、質問されずに拒否されるように変更されました。
  • ルックアップ/表示セット外のフラグを使用して which を実行する前に許可を求めるように Bash ツールを変更しました。
  • ディレクトリ自身の trust ダイアログが受け入れられた場合にのみプラグイン マーケットプレイスを登録するように --add-dir ディレクトリを変更しました。
  • ネストされたスキルの読み込みを変更しました。Bash サンドボックスがオンの場合、開始フォルダーの下にある .claude/skills フォルダー内のスキルは、そこで Claude Code または /cd を起動した場合にのみ読み込まれます。
  • フォールバックウェイクアップをスケジュールするのではなく、再スケジュールせずにターンが終了したときに終了するようにセルフペース/loopを変更しました。 CLAUDE_CODE_LOOP_KEEPALIVE=1 を設定して古い動作を維持します
  • 新しいメッセージがターンを中断した後に終了するツール呼び出しで、終了まで最大 10 秒以内に実行する PostToolUse フックを変更しました
  • セーフガードがサブエージェントを停止した後にクロードに伝える内容を変更しました。作業自体を実行する代わりに、より狭いプロンプトで再試行するか、指示してください。
  • 新しいワーカーへの移動時に、拒否ルールと要求ルールをすべて維持できない場合にセッション スコープの許可ルールを削除するようにクラウド セッションを変更しました。そのため、再度要求される可能性があります。
  • TLS 検査プロキシの背後で自動証明書修復を変更しました。ALL_PROXY が唯一のプロキシ変数セットである場合には実行されなくなりました。代わりに、HTTPS_PROXY をプロキシの http:// URL に設定します。
  • 他の人が書き込んだ可能性のある行のアーティファクト データベースの保存を変更しました。各ファイルは非表示のマーカー ファイルを取得し、マーカー ファイルを持たない既存のファイル、その中にある以前のバージョンのエクスポートはそのまま残され、レポートされます。
  • クロード コンソールに一致するように /claude-api managed-agents-onboard テンプレートを更新しました。パフォーマンス チューナーを削除し、2 つの名前を変更し、プロンプトで使用されない 5 つの Web 検索とフェッチをオフにしました。
  • 拡張機能に保存されているショートカットをリストして開始する shortcuts_list と shortcuts_execute を、Chrome ツールの Claude Code の組み込み Claude から削除しました
  • ゲートウェイ: AWS GovCloud と他のアップストリームが混在するアップストリームと、ゲートウェイ環境のベース URL 変数に対する起動警告を追加しました。
  • ゲートウェイ: 管理設定がヘッダーで Amazon Bedrock ガードレールを指定し、ゲートウェイが転送せず、bedrock アップストリームが guardrail を設定しない場合の起動ログ警告を追加しました。
  • ゲートウェイ: すべてのアップストリームが Amazon Bedrock である場合に常に失敗する Web 検索ツールを提供する Claude Desktop を修正しました。
  • 自己ホスト型ランナー: --use-anthropic-git-proxy または --configure-git で開始されたランナーが、起動チェックの失敗により終了する前に登録される問題を修正しました。それが最初に終了するようになりました
  • セルフホスト ランナー: セッション内の各リポジトリが独自のフォルダーを取得するように CLAUDE_RUNNER_CHECKOUT_PATH を変更しました。セッション内ですでに取得されているフォルダー名は最後に -2、-3 などになります。
  • セルフホスト ランナー: セッション終了時のセッションのデバッグ ログのアップロードを削除しました。 --remove-session-state が設定されていない限り、失敗したセッションのログはランナー ホストに残ります。
  • [VSCode] 50,000 文字を超えるプロンプトがサイレントに切り取られる問題を修正しました。プロンプトは通知付きでチャット ボックスに残り、制限を超える貼り付けは通知付きで拒否されます。
  • [VSCode] アンケートまたは「問題を報告」ボタンで未完了のプロンプトが送信される click を修正しました。
  • [VSCode] 拡張機能の [Web] タブから開かれたクラウド セッションが、/clear、または入力されたプロンプトの再試行または編集によって削除されたターンを戻す問題を修正しました。
  • [VSCode] 拡張機能でセッションの名前が変更されたときに、削除されたセッションのファイルが戻ってくる問題を修正しました。
  • [VSCode] ウィンドウのリロード後にクロードが未承認の計画を実行する問題を修正しました。計画モードで中断されたステップは、セッションが別の許可モードに戻ったときに通知とともに停止するようになりました。
  • [VSCode] Claude アプリ ゲートウェイの背後にある「サインインしていません」メッセージを改善しました。エラーのように見え、サインイン リンクが表示されるようになりました。
  • [VSCode] クロードのサインイン、コネクタ、または API アドレスを指すクロードの返信内のリンクが、ブラウザーで開くのではなく、アドレスを含むテキストとして表示されるように変更されました。
  • [VSCode] ドロップされたアイテムのパスに非常に長い「/」文字が含まれている場合にチャット パネルがフリーズする可能性があった問題を修正しました。
  • [VSCode] 開いているすべてのクロード ビューで一度にディクテーションを開始する claude-vscode.toggleDictation コマンドを修正しました。使用しているビュー内でのみ動作し、2 回押すと停止します。
  • [VSCode] それぞれ最後よりも短い、多くの閉じられていない $$ 数学フェンスを含む返信が流れ込むときに、チャット パネルの速度が低下する問題を修正しました。
  • [VSCode] 大規模なワークスペース用のチャット パネルの診断ツールを改善しました。問題のないファイルを除外し、コンパクトな JSON を返し、オプションの最小重大度を受け入れます。
  • [クラウド セッション] スケジュールされたタスクがメモリという名前のコネクタをサイレントにドロップする問題を修正しました。実行されるようになりました。その名前と短いサフィックスの下でマウントされ、それが維持されます。
  • [クラウドセッション] バックグラウンドエージェントの実行を終了するクラウドセッションの待機中のメッセージで今すぐ送信する問題を修正しました。彼らは今も走り続けています
  • [クラウド セッション] セルフホスト環境でのセットアップの停止に関する警告を改善しました。そのリンクは、組織のデフォルトまたはライブ ランナーのある環境を優先し、そのリンクに名前を付けるようになりました。
  • [コード レビュー] GitHub 組織のリンク解除を、コード レビューでの [すべてのリポジトリ] 設定もオフにするように変更しました。再リンク後は再びオンにするまでオフのままです
  • [Claude Tag] チャンネルリストが完全にロードできない場合に起動をブロックするクロードタグのセットアップを修正しました。管理者はチャンネルを選択せずに起動できるようになりました
  • [クロード タグ] クロード タグが接続されているエンタープライズ組織のモデル管理ページにクロード タグ行を追加し、そのモデルのデフォルトが管理される場所にリンクしました。
  • [Claude Tag] Claude Tag 管理設定の自動モード許可ルールの保存が別の管理者の変更を上書きする問題を修正しました。保存はメッセージとともに拒否されるようになりました
