claude-code v2.1.311

パッチ 公開日2026年10月26日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.311

何が変わったのか

  • ホストが実行中のプロセスを報告している間、アイドル セッションを維持するために、--hold-idle-file と --max-hold-min を self-hosted-runner に追加しました。
  • クロードに説明を求めるときに表示される説明出力スタイルのヒントを追加しました
  • CLAUDE.md ファイルに非常に長いリスト項目が含まれている場合、起動時およびファイルの読み取りまたは編集後に長時間フリーズする問題を修正しました。
  • MCPサーバーがリソースの読み取りに応答しなかった場合、またはスキルがまだダウンロード中である場合、タイムアウトになるまでクロードの中断が有効にならない問題を修正
  • リクエストが 200K トークンを超えると、「1M コンテキストには使用量クレジットが必要です」というメッセージが表示されて標準コンテキスト セッションが停止する問題を修正しました。クロード・コードは会話をコンパクトにして続行します
  • ファイル内の数千行を変更すると、書き込みと編集が実行後最大 5 秒間停止し、変更された行が 0 行であると報告される問題を修正しました。
  • サブエージェントの開始後に接続を終了したサーバーからサブエージェントが MCP ツールを使用できない問題を修正
  • これらのファイルがセッションの早い段階で編集されていた場合、自動圧縮の直後に古い MEMORY.md および CLAUDE.md コンテンツがクロードに表示される問題を修正しました。
  • claude -p および SDK セッションでトランスクリプト メッセージが順不同で保存されたり、取り戻されたメッセージが保持されたりする問題を修正しました。
  • 実行中のサブエージェントごとに、終了時に 1 回ではなく、1 分に約 2 回実行される SubagentStop フックを修正しました。
  • git 無視ファイルを再度含める .ignore/.rgignore 否定ルールを無視する @ ファイル ピッカーを修正しました
  • サブエージェントが開始したバックグラウンド サブエージェントがその中でまだ動作している間に、サブエージェントの分離されたワークツリーが削除される問題を修正しました
  • 新しいメイン会話を開始する独自のシェルを待機する自動モードのバックグラウンド エージェントがウェイクオンになるたびに修正されました
  • 呼び出し間で作業ディレクトリが常に保持されると主張する Bash ツールの説明を修正しました。
  • Bash ツールが zsh を使用する場合に、fish などのシェル コマンドが実行されない名前を付ける環境ブロックを修正しました。
  • リポジトリ ルートの下で実行される場合、ローカル スコープのサーバーを保持する ~/.claude.json のプロジェクト エントリではなく、現在のフォルダーに名前を付ける claude mcp add、claude mcp remove、および /mcp を修正しました。
  • 接続に失敗した回線でエラー コードが 2 回表示される claude mcp list および claude mcp get を修正しました (例: ENOENT: ENOENT: …)
  • ネットワーク プロキシが起動リクエストをブロックすると、リモート コントロール セッションが約 2 分間「接続中」のままになる問題を修正
  • クロードがクラウドまたはリモート コントロール セッションに送信するメッセージが、クロード モバイル アプリで独自のメッセージとして表示される問題を修正しました。
  • リモート コントロール経由またはクラウド セッションに送信されたメッセージに添付されたファイルがディスクがいっぱいであるために保存できなかったとき、または最初の 20 個を超えたメッセージの添付ファイルが省略されたときに、クロードに原因が通知されない問題を修正しました。
  • Cowork クラウド セッションで WebFetch と WebSearch が停止した応答でハングする問題を修正しました。未完了のリクエストは 300 秒後に失敗するようになりました
  • バックグラウンドセッションがアタッチされている、固定されている、またはスケジュールされたタスクやウェイクアップが設定されているときに再起動されないターンの間にクラッシュする問題を修正しました
  • 無効化された claude daemon restart を示唆する「バックグラウンド サービスが応答しませんでした」エラーを修正しました。 claude daemon stop --any を提案し、バックグラウンド セッションを終了すると言います。
  • ID に一致するバックグラウンド セッションがないことを報告する前にバックグラウンド サービスを開始する claude respawn <id> を修正しました
  • プラン モデルがセッション モデルと異なる場合、プラン モードでのプロンプト キャッシュ ミスについて警告しない /effort を修正しました。
  • インストールが完了する前、またはインストールが失敗したときに、VS Code 拡張機能がインストールされたと表示される /ide を修正しました
  • 線の幅がターミナルよりも広い場合、書き込みツールのファイル プレビューで行がスキップされ、隠線行が誤って数えられる問題を修正しました。
  • エージェントのチャット タブの ↑ がまだ配信を待っているメッセージを呼び出すため、再送信すると 2 番目のコピーが送信される問題を修正しました
  • プラグインまたは設定で agent という名前が付けられている場合、再起動後にコネクタとほとんどのツールが失われる Cowork クラウド セッションを修正しました。 Cowork クラウド セッションではその設定が無視されるようになりました
  • --resume、--continue、/resume、または --session-id で戻ってきたとき (/clear またはクラッシュ後、および元のセッションのリストに /branch が書き込まれている場合を含む) で空のタスク リストを表示するエージェント チーム セッションを修正しました。
  • ! open /tmp/shot.png や /review look at /tmp/shot.png などの画像ファイルに言及するテキストの貼り付け、画像の添付、プロンプトからのパスのドロップを修正しました。
  • プロンプトにテキストが含まれているときに、これらのキーがカードではなくプロンプトで機能する場合、フィードバック ドラフト カードに 1/2/0 および Esc ショートカットが表示される問題を修正しました。
  • クロードの応答から消える、"\" や (\) などの引用符または括弧内の単一のバックスラッシュを修正しました
  • DISABLE_COMPACT が設定されている場合にエージェントのチームメイトが履歴を圧縮する問題を修正
  • DISABLE_COMPACT設定時の巻き戻しメニュー「ここから要約」「ここまで要約」を修正
  • 完成した/code-review、またはサブエージェントで実行される別のスキルが、クラウドまたはバックグラウンドセッションの再起動時に2回目に実行される問題を修正しました。
  • Google Vertex AI、Microsoft Foundry、AWS の Claude Platform で、エンドポイントが思考の進行状況の更新を送信する際に、長時間隠蔽された思考がアイドル状態として切断される問題を修正しました。
  • 何もインストールされていないときに JetBrains プラグインがインストールされたと表示する /ide を修正しました
  • Claude Pro および Max のサブスクライバーがサブスクリプションを使用できない場合に管理者に問い合わせるよう指示される問題を修正。メッセージは請求設定を指すようになりました
  • ワイドフルスクリーン端末で編集後、表示するものが何もないときに差分ペインが勝手に開く問題を修正しました
  • サーバーがサインインなしで動作している場合、「認証のクリア」後にリモート サーバーが失敗として表示される /mcp を修正しました。
  • クロード コードが資格情報を送信しないリモート サーバーに対して「認証済み」と表示される /mcp を修正しました
  • 空の .mcp.json が一番上にあるときに、プラグインの --plugin-dir フォルダーが 1 つのプラグインとしてロードされる問題を修正しました
  • /usage が「制限使用量の原因は何ですか?」で大きなプロンプト キャッシュ ミスが表示されない問題を修正しました。
  • リンクをサポートする端末からステータス行リンクを開いた後、バックグラウンド セッションでプレーン テキストのままになるステータス行リンクを修正しました
  • 後のメッセージが会話から削除されたときに会話が「分岐される」という /rewind 確認を修正しました
  • 手動編集と Bash 編集はコード復元の影響を受けないという誤った /rewind 警告を修正しました
  • スクリーン リーダー モードで、エスケープで却下したフィードバックを送信する計画の承認を修正しました
  • クロード コードの再試行リクエストを修正し、API が再試行しないようにマークされていたため、ターンが数分間保持されるか、無人再試行モード (CLAUDE_CODE_RETRY_WATCHDOG) では無期限に保持される可能性がありました。
  • Linux: --plugin-dir フォルダーも追加ディレクトリであり、permissions.blockReadsOutsideWorkingDirectories がオンになっている場合、サンドボックス化された Bash コマンドが bwrap: Can't create file で失敗する問題を修正しました。
  • 自己ホスト型ランナー: 追加された読み取り専用リポジトリがレート制限 (HTTP 429、または 75 で終了する git ラッパー) によってブロックされている場合にセッションを開始できない問題を修正しました。そのリポジトリなしで開始されるようになりました
  • 最後のチェックから 1 時間以内の起動時に 2 つのネットワーク リクエストをスキップすることで、Pro および Max アカウントの起動時間を短縮しました。
  • 圧縮されたクラウド セッションが最後の圧縮から読み込まれるときに、要約されたメッセージがローカル コピーにないことを警告するように /teleport および claude --teleport を改善しました。
  • バックグラウンド セッションのプロセスが終了するときに表示されるメッセージを改善しました。メッセージは、予定されていない再起動を約束するものではなくなり、セッションを再開する方法を示します。
  • 複数のビューによるアーティファクトの改善: クロードは各ビューをリンクの #name にルーティングするようになり、ビューを切り替えてもアドレス バーが同じままであると表示されなくなりました。
  • タイムアウトに達したシェル コマンドの改善: 結果にこれまでの出力が表示され、コマンドがまだバックグラウンドで実行中であることが示されるようになりました。
  • 圧縮の改善: モデルの応答に要約が含まれていない場合、クロード コードは通常、会話を置き換える前にもう一度要約を要求するようになりました。
  • ページとドキュメントの間でのアーティファクト ツールの選択が改善されました。説明者とビジュアルまたはインタラクティブな作業がアーティファクト ページになります。ドキュメントは書くためのものであり、人々は編集し続けるか、回覧するためにある
  • claude --model opus など、唯一の引数がオプションとその値である起動の起動時間を改善しました。
  • 「接続が切断されました」API エラーを改善しました。最初にどこを探すべきかを表示するようになりました (使用中のプロキシまたはゲートウェイ、そうでない場合は VPN またはファイアウォール。Anthropic API のみ、Bedrock、Vertex、Foundry は変更ありません)
  • スクリーン リーダー モードの改善: /permissions 内のルールを削除すると、すぐに「許可ルールが削除されました…」と表示されます。
  • 貼り付けたサインイン コードが拒否された場合に表示されるメッセージを改善しました。コードの有効期限が切れているか、使用されている可能性があるため、再度サインインするように指示されるようになりました。
  • Slack コネクタの送信の改善: クロードは、名前を付けていないチャンネルにメッセージを送信する前に、投稿ルールについてチャンネルのトピックをチェックするようになりました。
  • 改善されたスクリーン リーダー モード: クロードの質問は、矢印や記号なしで「質問: カラー (回答済み)、ページ」としてリストされます。
  • Anthropic の API を介して、Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1 で xhigh 努力でターンを実行するように対話型ターミナルの ultrathink を変更しました。クロードの作業中に入力すると、そのターンの残りが発生します
  • ultrathink の虹が、単語が引用符で囲まれている場合やファイル パスの一部ではなく、キーワードが労力を高めることができる場所にのみ表示されるように変更されました。
  • プロンプトに一致するようにエージェント ビューで Ctrl+D を変更しました。空の入力で 2 回押すと終了します。
  • DEL、C1 制御、および Unicode 形式の文字を文字列内に \uXXXX エスケープとして書き込むように --output-format json および stream-json の出力を変更しました。解析された値は変更されません
  • モデル名と ID を変更し、接尾辞が影響を及ぼさないモデルでは [1m] 接尾辞とそのラベルを削除しました。接尾辞はまだ受け入れられます
  • 設定ファイルの権限ルールに関する起動警告が、ルールが変更されるまでユーザーごとに 1 回表示されるように変更されました。
  • /code-review を変更して、クロードに努力レベルを最初に置き、求められた場合にのみ最大値を使用するように指示しました。
  • 設定ファイルと MOD の $.env.set で DISABLE_COMPACT を変更し、コンパクションをオフにするだけでオンに戻すことはできないようにしました。
  • Bedrock、Mantle、Vertex、Foundry のクロード コードを変更し、downloads.claude.ai の署名付きファイルからモデル設定をロードするようにしました。これをオフにするには CLAUDE_CODE_MODEL_CATALOG=off を設定します
  • マシン上の別のセッションがフェッチした最大 10 分前の claude.ai スキル リストを再利用するために、機能フラグのフェッチをオフにして CLAUDE_CODE_SYNC_SKILLS を設定するセッションを変更しました。
  • 全画面リストのスクロールバーの矢印とバーの click が、マウス ボタンが放されたときに動作するように変更されました。そのため、放す前にスクロールバーの外に移動すると、click がキャンセルされます。
  • claude purge を変更して、Anthropic に保存されたデータではなく、このコンピューター上のデータのみを削除するようにしました。
  • [VSCode] ライト、ダーク、ハイコントラストのダークテーマで、クロードの返信のコードブロックに構文の色分けを追加しました。
  • [VSCode] 遅い UserPromptSubmit フックに対する「UserPromptSubmit フックの実行中」スピナー ステータスとスクリーン リーダーのアナウンスを追加しました。
  • [VSCode] VS Code または JetBrains パネルから送信されるカスタム スキルとカスタム スラッシュ コマンドが、通常のメッセージに含まれる開いているファイルまたは選択された行を除外する問題を修正しました (anthropics/claude-code#102799)
  • [VSCode] ログイン シェルが起動ファイルを実行して macOS および Linux 上で PATH を読み取るときに拡張機能ホストがフリーズする問題を修正しました。
  • [VSCode] cli ツールの結果で画像を固定するか、そのプレビューを閉じて、結果のテキストもエディター タブで開く問題を修正しました。
  • [VSCode] [送信] ボタンでメッセージを送信した後も音声ディクテーションが録音され続ける問題を修正しました。ここで送信すると、Enter キーを押すとすでにディクテーションが停止します。
  • [VSCode] VS Code のテレメトリ設定がオフのときに DISABLE_TELEMETRY を設定してクロード コード セッションを開始するように拡張機能を変更しました。そのため、使用状況メトリクスやエラー レポートは送信されず、機能フラグもフェッチされません。
  • [VSCode] 起動時ではなく、Web タブが最初に開かれたときに Web セッションをロードするようにセッション リストのサイド バーを変更しました。
  • [クラウドセッション] Anthropic がホストする環境で、所有者が組織を離れて再参加した後もロックされたままになるルーチンを修正しました。所有者は再びオンにできるようになりました
  • [クラウドセッション] 編集ダイアログがすでに閉じている場合に何も表示されない、失敗したルーチン API トークンの削除または再生成を修正しました。エラートーストが表示されるようになりました
  • [クラウドセッション] 重複した名前を受け入れる、管理者ダイアログを含むクラウド環境ダイアログを修正しました。リストされている別の環境がすでに持っている名前を拒否するようになりました
  • [Claude Tag] クロードが Slack チャネルで添付された各スキルを実行する頻度と未使用になっているスキルを表示するスキル ビューをクロード タグ分析に追加し、管理設定の使用状況リンクを表示しました。
  • [クロード タグ] 新しいセッションで実行されるクロード タグ ルーチンの改善: レポートするものが何もない実行は、チャンネルに捨てメッセージを投稿せずに終了できるようになりました。
  • [Claude Tag] 自分の Slack アカウントが表示できるプライベート Slack チャネルに対して # の代わりにロックを表示するように Claude Tag の管理設定を変更しました。
  • [コード レビュー] モデルが自動再試行で変更を分析できない場合、それ以上の自動レビューは開始されないことを示すようにコード レビューのチェック実行を改善しました。
  • [コード レビュー] コード レビューの信頼性の向上: 一時的なサーバー障害が原因でセッションの開始に失敗したレビューは、自動的に 1 回再試行され、そのチェック実行でその旨が表示されるようになりました。
