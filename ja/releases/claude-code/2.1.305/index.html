claude-code v2.1.305

パッチ 公開日2026年10月20日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.305

何が変わったのか

  • Linux 上のサンドボックス コマンドでユーザー名前空間 (Chromium、ルートレス ポッドマン) を作成できるように sandbox.allowNestedUserNamespaces を追加しました。これにより、サンドボックスのファイル保護を回避できるようになります。
  • CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS を追加したため、無人再試行モード (CLAUDE_CODE_RETRY_WATCHDOG) は、リセット前に解除された使用制限を認識します。
  • エンドポイントまたはゲートウェイがツール検索を拒否した場合、および ToolSearch が禁止されているか --tools から除外されているゲートウェイの背後で (2.1.304 回帰)、Vertex、Bedrock、およびその他のプロバイダーで失敗するすべてのリクエストを修正しました: クロード コードはツール検索なしで再試行するようになりました。
  • モデル名が大文字小文字または [1m] タグによって modelOverrides の値と異なる場合に、/effort および /autocompact の設定が適用されない問題を修正しました。
  • ベア リポジトリ内の新しいワークツリーがデフォルトのブランチではなくローカル HEAD から開始される場合があり、変更されていないサブエージェント ワークツリーがクリーンアップされない場合がある問題を修正しました。
  • 生の ENOSPC ファイル パスで失敗するディスクがいっぱいの Bash コマンドを修正しました。エラーは、ディスクがいっぱいで何も実行されなかったと表示されるようになりました。
  • クラウド セッションまたは SDK の setMcpServers によって渡された MCP サーバーが、セッションの後半で独自の設定の同じ名前のサーバーに置き換えられる問題を修正しました。
  • サブエージェントがフォールバック モデルに切り替えた後、クロードがサブエージェントの作業に対して間違ったモデルに名前を付ける問題を修正しました
  • クラウドセッションとチームメイトが、いつ圧縮で最も古いメッセージを要約から外して適合させる必要があるかをクロードに伝えない問題を修正
  • スケジュールされた Cowork クラウド セッションが、WebFetch で URL 承認を必要とするサブエージェントごとに 5 分間待機するが、誰も与えることができなかったケースをさらに修正しました。
  • 実行のジャーナルからサービスを提供するのではなく、すでに完了した pipeline() および parallel() エージェントを再実行するワークフロー再開を修正しました
  • /resume との会話を切り替えた後、リモコンが /resume に空の「(セッション)」エントリを残す問題を修正
  • 狭いターミナルで /usage 行が切り取られる問題を修正
  • ロゴの上に生のテキストとして印刷される起動警告を修正しました。警告はデバッグ ログに移動し、何も制限しない権限ルールはバナーの下に警告行として表示されます。
  • スクリーン リーダー モードの修正: 検索ボックスでは、記号の代わりに「検索:」と表示されるようになりました。VoiceOver では「電話レコーダー」と読み上げられ、Ctrl+R 検索一致や「ultrathink」などの強調表示されたプロンプト テキストは、単語内にスペースが含まれなくなりました。
  • 自己ホスト型ランナー: TERM が設定されている場合に、標準出力のみをランナーまたはオーケストレーターと共有する開始スクリプトが Resource temporarily unavailable で失敗する問題を修正しました (2.1.300 回帰)
  • セルフホスト ランナー: git 資格情報ヘルパーまたは askpass プログラムが GIT_CONFIG 経由で設定を読み取るときに、2.1.296 以降リポジトリ アクセスが失敗する問題を修正しました。
  • 自己ホスト型ランナー: バックグラウンドで開始されたランナーが出力を開いたままにすると、オーケストレーターがスポーンランナー フックをタイムアウトとして報告する問題を修正しました。
  • /usage の改善: 各警告はそのソース名を示す 1 行の修正となり、f が修正を適用します。同じ修正が VS Code と /doctor にも表示されます
  • MCP 同意ダイアログが改善され、プロンプトに対する Enter キーが同意として受け取られる可能性が低くなりました。
  • iTerm2 3.5 以降でフルスクリーン レンダリングで画像を描画できるように MOD の Image を改善しました。alt テキストのみが表示されました。
  • リモート コントロール: スポーン モード メッセージを改善しました。w を押すと、新しいモードがフォルダーに保存されたことが表示され、保存されたモードを使用するその後の claude remote-control の起動により、そのモードがどこから来たのかが表示されるようになりました。
  • env でのみ ${VAR} を使用する managed-mcp.json stdio サーバーのフィルタリングを停止するように allowedMcpServers を変更しました。除外されたホワイトリストの 1 つがアップグレード時に読み込まれるようになりました。 deniedMcpServers を使用してオフにしてください
  • 組織の管理設定が allowManagedPermissionRulesOnly に設定されている場合に、Claude Desktop がパスによってマウントするプラグインが allowed-tools を保持しないように変更されました。
  • /artifacts の削除確認を、1 または Enter で保持、2 で削除、Esc でキャンセルするように変更しました。 y と n は応答しなくなりました
  • MODのドッキングされたペインがターミナルの幅の45%以内に収まるように変更されました（より広いターミナルからの幅も含む）
  • [VSCode] SessionStart または Setup フックの実行中にスクリーン リーダーのアナウンスを伴う「起動フックの実行中」スピナー ステータスを追加しました。
  • [VSCode] spinnerVerbs 設定で組み込み動詞が短い動詞に置き換えられると、スピナーが「圧縮中...」を切り捨てる問題を修正しました。
  • [VSCode] セッションが時間内に開始せず、フックが実行されていない場合に表示されるメッセージを変更しました。最初にサインインとネットワークを示すのではなく、出力ログと原因のリストが表示されるようになりました。
  • [クラウドセッション] クラウド環境管理ページが「パッケージのインストール」エラーで既存の環境の保存を誤って拒否する問題を修正しました。
  • [クラウド セッション] セルフホスト環境の削除が改善され、ダイアログとエラー メッセージに削除をブロックするものとその影響が示されるようになりました。
  • [Claude Tag] パブリック Slack チャンネルを追加しました クロードはクロード タグ管理者に参加していません プレイス検索を追加して、管理者がそこから設定できるようにします
  • [Claude Tag] クロードタグのアクセスバンドルを修正し、別のGitHubアカウントに移動したリポジトリを再度追加できるようにしました
  • [Claude Tag] Slack DM スレッドで設定されたルーチンが、そのスレッド内の別のルーチンが会話を再開した後に投稿されなくなる問題を修正しました。両方とも今もそこに投稿し続けています
  • [Claude Tag] 会話終了後に投稿せずに成功を報告する Slack スレッドで設定されたルーチンを修正しました。それらの実行はスキップされ、作成者に通知されます。
  • [Claude Tag] 大規模組織の Claude Tag 管理ページが改善され、チャンネル リストの読み込み中にプラグイン、スキル、バンドルの編集が機能するようになりました。
  • [コード レビュー] レビュー中にプル リクエストに複数のプッシュが到達した場合、コード レビューが最新のコミットをレビューしないことがある問題を修正しました。
  • [コード レビュー] コード レビューの再レビューが変更され、以前のブロック検出結果はまだ開いているにもかかわらず、LGTM で開かなくなるようになりました。
