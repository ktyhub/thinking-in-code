claude-code v2.1.317

パッチ 公開日2026年11月3日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.317

何が変わったのか

  • 新しいクラウドのスケジュールされたタスクが要求していないコネクタを取得した場合の警告と、それらの削除方法を /schedule に追加しました
  • Web またはシェル ツールの呼び出しによってアカウントの電子メール アドレスがネットワークに送信される前に確認するチェックを追加しました。
  • エージェント SDK フック コールバックに onFailure: "block" を追加したため、コールバックが失敗するとアクションが実行されずにブロックされるようになりました。
  • 組織のリモート管理設定がセッションに対してロードされていない場合、Claude Desktop の [コード] タブに通知を追加し、ロードされた場合には別の通知を追加しました。
  • 自動モードのチェックでサブエージェントのツール呼び出しに対する応答がない場合の通知を追加しました。以前はメイン ビューに何も残っていませんでした。
  • OTel メトリクス、イベント、スパンに anthropic.plan、anthropic.seat_type、anthropic.provider、anthropic.custom_base_url を追加
  • クロード アプリ ゲートウェイ管理者 API、GET /v1/organizations/analytics/cost にコスト レポートを追加しました。これにより、開発者ごと、日ごと、または IdP グループごとに、日付範囲にわたる合計の過去の支出を読み取ることができます。
  • admin: が設定されたクロード アプリ ゲートウェイ上の各開発者の IdP グループの毎日の記録を追加しました。admin.identity_retention_days まで保持され、コスト レポートではグループ化されます。
  • CLAUDE_CODE_DISABLE_NESTED_SESSION_ID を追加: 以前のバージョンと同様に、セッション内で claude -p がそのセッションの ID とトランスクリプトを使用して実行されるようにするには、セルフホスト ランナーで 1 に設定します。
  • 一部のクロード デスクトップ セッションの最初のターン後にプロジェクトとローカル MCP サーバーが切断される問題を修正
  • ベース URL として設定された LLM ゲートウェイがサーバー側の安全性チェックに 403 または 422 を応答すると、自動モードが毎ターン失敗する問題を修正しました (apiKeyHelper を持つ 403 は変更されません)
  • 遅いトークンの更新が保存される前に終了する claude auth status を修正しました。これにより、次回の実行時にサインアウトする可能性がありました。
  • デスクトップ アプリの [コード] タブの新しいセッションなど、アプリが事前に開始されてからプロジェクト内で開かれるセッションによってプロジェクトの effortLevel 設定が無視される問題を修正しました。
  • リンクされたセッションが最初のページよりも古い場合、多くのセッションを含むプロジェクトで「会話が見つかりません」と報告される claude --from-pr を修正しました
  • claude.ai とモバイル アプリでファイル パスやコマンドが表示されない 2 つの同時許可プロンプトのうち 2 番目のプロンプトを修正しました
  • MOD のツール呼び出しで「もう尋ねない」を提供するリモート コントロールと SDK ホストを修正
  • タイトルの生成中に新しいメッセージまたは停止が到着したときに、クラウドおよび SDK セッションでセッション タイトルが失われる問題を修正しました
  • クロードがフィールドをリクエストから外したときに、セルフペースの /loop ウェイクアップがスケジュールされないことがある問題を修正
  • アーティファクトツールが出力フォルダーを介してファイルをアップロード、データベースに書き込む、または保存するときに承認のために停止するクラウドセッションの自動モードを修正しました
  • claude.ai から同期されたスキルがディスクに書き込めない場合、10 分ごとに失われるか再ダウンロードされる問題を修正
  • /schedule が、クラウド スケジュールされたタスクの作成または更新後に結果から次回の実行時間とリンクを残す問題を修正しました。
  • スクリーン リーダー モードが変更されるたびに、実行中のサブエージェントの経過時間とトークン数を読み上げるスクリーン リーダーを修正しました。
  • サインイン失敗として表示されるリージョンまたはネットワーク ブロック (HTTP 403) を修正しました。エラーはブロックを説明するようになりました
  • 同期されたプラグインに同じサーバーが含まれている場合、動作している claude.ai コネクタには認証が必要か、クラウド セッションで失敗したとクロードが言う問題を修正しました
  • フルディスクまたはクォータがトランスクリプトまたは ~/.claude.json 書き込みを失った場合に 0 で終了する claude -p を修正しました。エラーが出力され、テキストおよび json 出力で終了します。 1. 完全な NFS エクスポートが失われる可能性があります。
  • 起動後の最初の 2 秒程度で行われた設定ファイルの編集が、設定ファイルが再度変更されるまで有効にならない問題を修正しました。
  • --setting-sources を使用した実行など、一部の実行でクリーンアップがスキップされるマシン上で古いトランスクリプトがクリーンアップされない問題を修正
  • 削除されたエージェントチームの受信箱がチームメイトの遅れたメッセージによって再作成される問題を修正
  • 再作成されたエージェントのチームメイトが以前のシャットダウン承認によってチームから削除される問題を修正
  • スケジュールされたタスクがオフになった後、保存されているスケジュールされたタスクを一覧表示または削除できない問題を修正しました
  • 名前を指定せずにガイドを削除するように求められた場合、クロードが最も最近更新された /team-onboarding ガイドを削除する問題を修正しました。
  • サーバーが削除を拒否したときに/team-onboardingガイドが削除されたとクロードが発言する問題を修正
  • Amazon Bedrock の「入力が長すぎます」を隠すクロード アプリ ゲートウェイを修正しました。エラーが発生し、セッションは圧縮されずに「アップストリームがリクエストを拒否しました」というメッセージが表示され、毎ターン失敗することになります。
  • プランが承認を待っている間に再開されると、自己ホスト型ランナーセッションが最近のターンまたは会話全体を失う問題を修正しました
  • 最後に送信されてから非常に大きな CLAUDE.md が変更されたセッションでの自動圧縮後の「プロンプトが長すぎます」を修正しました
  • コマンドを登録する多くのプラグインを使用したヘッドレス セッションでの高いメモリ使用量と起動の遅さを修正しました
  • 環境設定で空の AWS_BEARER_TOKEN_BEDROCK を受信する標準出力 MCP サーバーを修正しました。変数は設定されていないため、サーバーはマシン独自の AWS 認証情報を使用できます。
  • ルート証明書の更新後に一部の TLS 検査プロキシの背後で「ローカル発行者証明書を取得できません」というエラーが発生して失敗する API リクエストを修正しました
  • 圧縮自体のリクエストを短縮する必要があった場合に、非常に長い会話が以前の要約を失う問題を修正
  • PDF 自体のメタデータで、Read および @-mentions がそのページを過小カウントする可能性がある問題を修正しました。
  • DISABLE_PROMPT_CACHING_OPUS および DISABLE_PROMPT_CACHING_SONNET が [1m]、デフォルト モデルの他の地域および日付のないスペルに影響を及ぼさない問題を修正
  • 独自のアーティファクトが 200 以上ある場合に共有アーティファクトが表示されない /artifacts とアーティファクト ツールの共有リストを修正しました
  • 検索が制限時間に達したときに部分的な Grep および Glob の結果を完了として扱うクロードを修正しました
  • 別のエクスポートの進行中に開始すると、プロキシを介した https:// エンドポイントへの OpenTelemetry エクスポートが送信されない問題を修正しました。
  • http:// エンドポイントへの OpenTelemetry エクスポート (HTTP 403) をブロックするプロキシへの接続試行のフラッドを修正しました
  • 応答しないプロキシの背後で OpenTelemetry エクスポートが無期限にハングする問題を修正しました。 10 秒後、または OTEL_EXPORTER_OTLP_TIMEOUT では最大 30 秒後にタイムアウトするようになりました。
  • 再開されたセッションが、すでに知っていたファイルの変更についてクロードに再度伝える問題を修正しました
  • ツールがオフになっていたために以前の通話が失敗した後、再開されたセッションでクロードが組み込みツールを使用しないことがある問題を修正
  • /remote-control が、disableRemoteControl 設定によってリモコンがオフになっていると言う代わりに、「不明なコマンド」と応答する問題を修正しました。
  • リード セッションが手動モードの場合、tmux または iTerm2 ペインのエージェント チームのチームメイトが自動モードで開始する問題を修正
  • バックグラウンド セッションがアップグレードまたはリタイアされたときに、パーミッション モードの直前の変更が失われることがある問題を修正しました。
  • プロンプトで入力されたテキストをクリアするために Ctrl+C を押すと、実行中のすべてのバックグラウンド エージェントが停止する問題を修正しました
  • レポートの送信中に「確認のために入力してください」と表示される/フィードバックを修正しました
  • 停止したシェル コマンドの子プロセスが SIGTERM を 2 回送信されることがあり、一部のプログラムがクリーンアップをスキップする可能性がある問題を修正しました。
  • セッション ID を共有するクラウドまたは自己ホスト型ランナー セッション内で実行される claude -p を修正しました。セッションのトランスクリプトに書き込まれ、再起動すると間違った会話が再開される可能性がありました。
  • クラウドまたは自己ホスト型ランナー セッション内で実行される claude -p が独自のタイトルを生成し、そのセッションに送信する問題を修正しました
  • Azure 認証情報を読み込めないときに Microsoft Foundry に表示されるエラーを改善しました。認証情報を確認または更新するように指示され、cloud_credential_error として報告されるようになりました。
  • /design-sync を改善し、デザイン システムがクロードに移動したときに事前に通知し、アップロードに失敗するのではなくビルド前に停止するようにしました。
  • 必要なクロード アプリ ゲートウェイに到達できない場合の起動エラーを改善しました。サインインではなくネットワークを指し、ゲートウェイの TLS 証明書を検証できない場合にメッセージを表示します。
  • 終了時に表示される「このセッションを再開する」ヒントを改善し、起動したフラグ (--chrome --debug など) を --resume の前に繰り返すようにしました。
  • 自己ホスト型ランナーがサーバーエラーから回復する方法を改善しました。501 または 529 以外の 5xx の後、ランナーの次のポーリングでは、失敗した接続を再利用するのではなく、新しい接続が開かれるようになりました。
  • 自己ホスト型ランナー セッションがサーバー エラーから回復する方法を改善しました。501 または 529 以外の 5xx の後、セッションは失敗した接続を再利用するのではなく、新しい接続を開くようになりました。
  • 接続が応答を停止した場合に自己ホスト型ランナー セッションが回復する方法を改善しました。ハートビートに応答がなかった後、セッションはアイドル状態の接続を順番に試行するのではなく、新しい接続を開くようになりました。
  • 実行中のバックグラウンド エージェントへのメッセージがより早く到着するように SendMessage を変更しました。実行中のコマンドは停止せずにバックグラウンドに移動します。
  • メインの会話とは異なるモデルのサブエージェントとチームメイトが、セッションのエフォート レベルではなく、そのモデルの保存されたエフォート レベルまたはそのデフォルトを使用するように変更されました。
  • プラグイン モニターの「バックグラウンド作業が実行中です」プロンプトをスキップするように終了を変更しました。
  • 組み込みのplugin-authoringスキルを、構築したMODが機能した後に一度提供するように変更し、MODの共有を支援しました
  • 読み取りツールの「最後の読み取り以降変更されていないファイル」スタブを削除しました。変更されていないファイルを再度読み取ると、その内容が返されます。
  • Windows: ネイティブ パス検索が失敗する一部のボリュームですべてのツール呼び出しが拒否される問題を修正しました。作業ディレクトリのチェックでは、代わりにフォルダーの ID が比較されるようになりました。
  • Windows: Claude Desktop によって開始されていないセッションで、プロジェクトのパスの長さに応じて成長するセッション スクラッチパッドとその他の一時パスを修正しました。これにより、それらに複製されたリポジトリが 260 文字のパス制限に達するようになりました。
  • ゲートウェイ: グループのプールされた予算が使い果たされた後、開発者自身の支出制限が 100% 使用済みとして表示されるステータス行と /usage を修正しました。
  • 自己ホスト型ランナー: セッションが新しいランナーに移行し、ターンが CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS より古い場合に、中断されたツール呼び出しがクロードに表示されない問題を修正しました。
  • セルフホスト ランナー: セッション サービスがスイッチの保存を拒否した場合、セッションが新しいマシンに移動した後、スイッチがオフになった MCP サーバーが再びオンになる問題を修正しました。
  • リモート コントロール: アプリがフォーク名を設定していない場合のフォーク名を改善しました。長い名前は「(フォーク)」で終わるようになり、claude remote-control で開始されたセッションでは、「名前 (フォーク)」のフォークは「名前 (フォーク 2)」になります。
  • [VSCode] メッセージがドロップされるフォークされた会話を修正しました。クロードが並行して実行したツール呼び出しのうち 1 つだけが保持され、圧縮によって保持された最後のメッセージが失われ、クロードの回答が質問に答えられずに残る可能性がありました。
  • [VSCode] クロードの起動が時間内に完了しなかったときに失われるメッセージを修正しました。拡張機能は、エラーを表示する前にもう一度クロードを起動するようになりました。
  • [VSCode] 地域またはネットワークでリクエストがブロックされている場合に開くサインイン画面を修正しました
  • [VSCode] 2 番目の単語が小文字のプラン名が表示されるアカウント パネルを修正しました
  • [VSCode] 別のエディター グループではなくチャットの上部に開くクロード タブ内のファイル リンクを修正しました
  • [VSCode] chat.fontSize が上げられたときに、クロード パネルのアタッチメント チップ、メニュー、バナー、ダイアログが小さいままになる問題を修正しました。
  • [VSCode] テレメトリがオフのときにultrathinkがそのターンの努力値を上げない、または虹を表示しない問題を修正
  • [クラウド セッション] クラウド セッションにリンク カードを追加したため、リクエストが表示されなくなる代わりに、MCP サーバーがアクセスを要求するリンクを開いたり、リンクを解除したりできるようになりました。
  • [クラウドセッション] 管理者設定の組織環境ダイアログを個人ダイアログの短いレイアウトに変更しました: 各セクションは行から開き、閉じる前に未保存の入力を尋ねます
  • [クラウドセッション] すでにネットワークシークレットを持っているホストに、それをサイレントに置き換えるネットワークシークレットの追加を修正しました。シークレットの追加フォームが拒否され、既存のシークレットが示されるようになりました。
  • [クラウド セッション] 組織のデフォルト環境を無視する新しいスケジュールされたタスクを修正しました。フォームは、Anthropic がホストするデフォルトの環境ではなく、管理者が選択した環境で開始されるようになりました。
  • [リモート コントロール] 前のメッセージから 1 分以内にメッセージを送信した場合、claude remote-control を再起動した後、アイドル セッションへの次のメッセージが応答されなくなる問題を修正しました。
  • [Claude Tag] Slack に新しく貼り付けたアーティファクトのリンクを変更し、Slack のサイド パネルではなく、Claude でアーティファクトを開く [開く] ボタンのあるシンプルなカードを表示するようにしました。
