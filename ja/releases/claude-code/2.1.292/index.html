claude-code v2.1.292

パッチ 公開日2026年10月6日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.292

何が変わったのか

  • --marketplace <source> を claude plugin install に追加: 必要に応じて、claude plugin marketplace add と同じポリシー チェックの下でマーケットプレイスを追加し、そこからプラグインをインストールします。
  • エージェント ツールに effort パラメータを追加したため、クロードは要求された作業レベルでサブエージェントを実行します。
  • オーバーロードされた (529) リクエストを再試行するときにバックオフの基本遅延を長く設定するための CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS 環境変数を追加しました。
  • prompt.autocomplete を追加しました。MOD がプロンプト ボックスのオートコンプリート リストに独自の行を追加するためにフックするイベントです。
  • MOD の $.model.complete にプロンプト キャッシュを追加しました: prompt と system はテキストのブロックを受け取り、ブロック上の cache: true はそれまでのリクエストをキャッシュします。
  • ワークフロー エージェントを agent.spawn MOD フックに追加し、その実行とインデックスを追加したため、MOD がそれらを拒否できるようになりました。
  • 自動モードが利用できない（設定、サーキットブレーカー、または自動モードをサポートしていないモデルによって無効になっている）場合に、permissionMode: auto が自動モードに入るサブエージェント定義を修正しました。
  • サンドボックス コマンドが ~/.claude/seed-admin でアップロードされた /ultrareview のステージングされたファイル コピーを読み取ることができるように修正しました。
  • セッション中に表示または再ポイントされるマネージド サンドボックスの読み取り拒否パス (およびその横のユーザーのパス) が修正され、その中のプロジェクト許可が削除されたり、対象となるファイルからの認証情報の注入が終了したりしませんでした。
  • macOS および Windows で読み取られたノートブックまたは PDF が、読み取り中に交換されたリンクを通じて、承認された内容以外のファイルを返すことができる問題を修正しました。
  • 設定の取得が失敗したときに、サーバー管理設定のディスク上のキャッシュが改ざんされて、組み込みポリシー プラグインのスイッチをオフにしたり、設定を解除したりできる問題を修正しました。
  • 8.3 の短縮名、またはホーム フォルダーまたはドライブの別の代替 Windows スペルの rm -rf が削除として扱われない問題を修正しました。
  • セキュリティ: ネットワーク (UNC) パスからのファイル読み取りの許可プロンプトをバイパスする PreToolUse フックの承認と自動モードを修正しました。
  • ターンの途中でオートモードまたはプランモードを終了すると、後のターンでスキルまたはスラッシュコマンドのallowed-toolsルールが戻ってくる問題を修正しました
  • HTTPS_PROXY が設定されている場合、クロード コード自体の API リクエスト (サインイン、ポリシー、フィードバック、アーティファクト) に対して NO_PROXY が無視される問題を修正しました。
  • 128 文字を超える名前を持つ MCP ツールがすべてのリクエストを失敗させる問題を修正しました。このツールは現在削除されており、MCP エラーによってその名前が付けられています。
  • 最初の実行時に組織の管理設定が読み込まれる前に実行される marketplace add や install などの claude plugin コマンドを修正しました
  • ワンショット claude -p とエージェント SDK の実行が最終結果の 5 秒後にバックグラウンド コマンドを停止し、ワンショット claude -p の実行がスケジュールされたウェイクアップをドロップする問題を修正しました。どちらも現在待機中です
  • claude --resume セッション ピッカーまたは /resume でセッションを再開するときに、プラン モードが復元されない問題を修正しました。
  • /resume、/branch、または /clear の後に作成された保存済みスケジュール済みタスクが起動しない問題と、ミリ秒間隔でタスク ファイルに 2 回書き込みを行った後、保存済みタスクがその後の作成と削除を無視する問題を修正しました。
  • 保留中のウェイクアップが失われたため、セッションのプロセスが再起動されたとき（クラッシュ後など）、バックグラウンド セッションの /loop がサイレントに停止する問題を修正しました。
  • 指定されたファイルまたはフォルダーを読み取れなかった場合に一致しないと報告する Grep と Glob を修正しました。クロードは一度再試行するか、あなたに通知します
  • PDF の pages が「6,9,15」のようなリストである場合、読み取りツールがエラーなしで最初のエントリのみを返す問題を修正しました。各ページまたは範囲を個別に読み取るように指示するエラーが返されるようになりました。
  • @ で言及された 256KB を超えるテキスト ファイルがサイレントに除外される問題を修正しました。クロードはファイルのサイズを通知され、それを分割して読み取るようになりました。
  • エージェントがすでにメインの会話を停止している制限に失敗した場合に、バックグラウンド エージェントごとに 1 回繰り返される使用制限アラートを修正しました
  • デスクトップ アプリまたは IDE によってホストされるセッションで、リモート コントロール ビューアにバックグラウンド サブエージェントの空のサブエージェント ペインが表示される問題を修正しました。
  • 1 人の受信者として類似した名前を持つ 2 つのセッションを表示するクロスセッション配信通知と、ターミナル セッションでメッセージが失効したときにデスクトップ アプリを非難する有効期限通知を修正しました
  • デスクトップ アプリで今すぐ送信すると、別のメッセージがすでにキューに入れられているときにサブエージェントが順番を待っていたことが終了する問題を修正しました
  • レポートの送信中に Ctrl+O または Ctrl+Z を押すと /bug、/share、/feedback <text> が最初からやり直しになり、送信後にキャンセルされたものとして終了する問題を修正しました。
  • Enter キーをすぐに押したときに、保存されているデフォルト環境が /remote-env で置き換えられる問題を修正しました。デフォルトでリストが開き、デフォルトが有効になっていない場合はどの行にもチェック マークが表示されません。
  • 1 つのプロンプト内で複数の貼り付けが重なった場合に、貼り付けられたテキストが入力されたテキストとしてクロードに到達する問題を修正しました
  • vim モードでカーソルが行末を超えたままになる問題、j/k が短い行で列を失う問題、および f/t/F/T/;/, がプロンプトの別の行の一致にジャンプまたは削除する問題を修正しました。
  • /add-dir パス ボックスを修正して、Shift+Enter またはペーストで改行を追加し、高速入力された「タブ」、「上」、または「下」をそれらのキーとして扱うことができました。
  • プロンプト フッター行が選択されている間、および ! が行を選択したままにしているときに、高速タイピング、入力メソッド テキスト、および分解されたアクセントが削除される問題を修正しました。
  • iTerm2 が検出されたときにウィンドウのサイズ変更と Ctrl+L を押すたびに全画面クリアが送信される全画面モードを修正しました。これが iTerm2 のスクロールバックを古いページで埋め尽くしていた可能性があります。
  • 読み取り拒否ルールが設定されており、作業ディレクトリがシンボリックリンクの下にある場合に、ファイル名を指定しない @-words に対する誤った「検査できませんでした」という注記を修正しました
  • /cd または権限の変更後に古くなったり欠落したりする「命令ファイルがロードされていません」行を修正し、ネストされたものがロードされていない場合のトランスクリプト行を追加しました
  • クロードがユーザー用に予約されているスキルを呼び出せるように/nameを繰り返す圧縮の概要を修正しました
  • MOD が呼び出しを拒否した理由を非表示にする Write、Edit、NotebookEdit、LSP 行、および単一 Read、Grep、Glob 行を修正: 行に理由が表示されるようになりました。
  • ターンが終了したときにワーカーが停止したときにターンが終了しないことを示すクラウドセッションを修正しました
  • 大規模なトランスクリプトを含むクラウド セッションが、承認後に再度許可を要求することがある問題を修正しました
  • クロードがメッセージを読んでいる間にメッセージが再試行または編集されると、クラウド セッションでスケジュールされたタスクやその他のキューに入れられた通知が失われる問題を修正しました
  • セッションのコンテナが再起動されると、クラウド セッションが client で選択された思考設定を忘れる問題を修正しました
  • Anthropic が組織の設定を確認できなかったときに、プロキシがアーティファクトをブロックしたと言う Cowork クラウド セッションを修正しました
  • フック モジュールが 1 つの const を介して多くの $.state 呼び出しを行い、ロードまたは検証に数分かかるプラグインを修正しました
  • エンジンが他の場所から読み取るフック モジュールのマッチャーまたは状態値をリストする claude plugin validate を修正しました
  • 再度宣言または再割り当てされたトップレベルの var を通じて読み取られた $.state 値をリストする claude plugin validate を修正しました。そのようなモジュールは現在拒否されています
  • プラグインが提供する $ メソッドがフック起点を再起動する問題を修正しました。これにより、その上に .catch を持つガード フックが際限なく再度実行される可能性がありました。
  • プラグイン フック ワーカーが他のプラグインが設定したフックなしで実行を再開するときに行われるプラグイン インターフェイス呼び出しを修正しました
  • next(e) を呼び出した後に拒否として応答される MOD の config.set、state.set、env.set、または agent.spawn フックを修正しました。フックは名前で失敗として報告されるようになりました。
  • プラグインの config.set フックが要求される前にテーマを保存する /theme、/config テーマ メニュー、および初回実行テーマ ステップを修正しました
  • プラグインの tool.check フック応答を修正し、ダイアログを表示せずに回答 (質問、計画の承認) を必要とするツールを実行できるようにしました。
  • フックワーカーが置き換えられたときに、MOD の起動プロンプト、コマンド、またはサブエージェントが再度キューに入れられる問題を修正しました
  • next(e) を呼び出し、ターンが中断されている間に失敗して呼び出しを通過させる MOD のフックを修正しました。現在通話は拒否されています
  • 理由が 4,096 文字を超える場合にプラグインのプロンプト ドロップまたは設定拒否が無視される問題を修正しました
  • 組織のプラグインが独自のリロード時、または別のプラグインがクラッシュした後、ユーザーがインストールした MOD が追加した $ 名を返したときにアンロードされる問題を修正しました。代わりにMODがアンロードされるようになりました
  • プラグインフックワーカーの再起動中に行われたツール呼び出しが、プラグインの許可フックなしで応答される問題を修正しました。
  • 誤った名前のパラメーターが修復される前に、プラグイン tool.call フックでいくつかのツール呼び出しが表示される問題を修正しました。フックはツールが実行する引数を参照するようになりました。
  • .catch を含む MOD のガード フックが、ガード自身の $ 呼び出しの下で別の MOD のフックが行う呼び出しに対してサイレントにスキップされる問題を修正しました。 .catch が尋ねられます
  • claude -p および SDK セッションの起動の改善: 最初のターンは、HTTP および SSE MCP サーバーが resources/list に応答するのを待機しなくなりました。
  • 長い箇条書きまたは番号付きの返信のレンダリング速度が向上しました。トランスクリプト (ctrl+o) でストリーミング、サイズ変更、再度開くことがはるかに速くなりました。
  • Ctrl+C ドラフト回復の改善: スラッシュ コマンドまたはメッセージの送信後、クリアされたプロンプトに上キーを押しても到達できるようになりました。
  • フック出力処理の改善: フックの出力に書き込まれた <system-reminder> タグは、クロードに到達する前にエスケープされます。
  • ツール入力処理の改善: Grep は path の file_path を受け入れ、Write、WebFetch、および Read は呼び出しに失敗する代わりに、いくつかの浮遊パラメーターを無視します。
  • 設定ファイルで宣言されたマーケットプレイスに公式の Anthropic マーケットプレイスのような名前が付いている場合に表示される手順を改善しました
  • 改善されたサンドボックス自動許可: ユーザー設定、管理対象設定、または --settings 設定で厳密なサンドボックス モードが設定されている場合、FOO=bar python3 app.py のような env var プレフィックスを持つインタープリター コマンドがプロンプトなしで実行されます。
  • アーティファクト ツールのリストを改善しました。クロードは、公開されているアーティファクトの数を確認し、一度に 50 個ではなく最大 200 個をリストできるようになりました。
  • 再起動後のクラウド セッションの改善: クロードは、ID によって再開できる停止したバックグラウンド エージェントを通知されるようになりました。
  • ブラウザーにアクセスできない場合の claude.ai クラウド セッションの Claude in Chrome メッセージを改善しました。ユーザーが希望する場合は、代替手段で続行できることがクロードに通知されるようになりました。
  • /focus ヒントを改善しました。ターン中にフォーカス ビューを試行するよう促し、元に戻す方法を示します。
  • 新しいプロトコル チェックを無視するローカル (stdio) MCP サーバーでの起動の改善: 1 回の低速接続の後、それらは 7 日間記憶され、待機せずに古い方法で接続されます。
  • Bedrock、Vertex、Foundry を含むすべてのインストールでデフォルトでプロトコル バージョン 2026-07-28 をネゴシエートするようにローカル (stdio) MCP サーバー接続を変更しました。 MCP_PROTOCOL_NEGOTIATION=legacy はオプトアウトします
  • claude plugin test の変更: テストが登録したフック内の失敗した expect、またはエンジンが拒否したスタブ応答は、サイレントで合格するのではなく、テストに失敗するようになりました。
  • claude.ai 設定リンクを https:// で書き込むように使用制限メッセージを変更し、端末とアプリで clickable にできるようにしました
  • 承認を求めずに自分だけが見ることができる新しいアーティファクトを公開するために、スケジュールされたルーチンと今すぐ実行するルーチンの実行を変更しました。コネクタまたはその他のアクセスを要求するアーティファクトは引き続き要求します
  • 最大 256 文字を許可するようにエージェント名を変更しました。長いものは拒否され、それより長いスキルまたはプラグイン ファイルの name は無視されます。
  • [クラウドセッション] ルーチンの実行が終了後数時間も実行中としてリストに表示される場合がある問題を修正
  • [クラウドセッション] ルーチンに保存された通知設定がない場合にプッシュ通知をオフにするルーチンの編集または複製を修正しました
  • [クラウドセッション] SVG、HEIC、TIFF、およびその他のあまり一般的ではない画像ファイルの添付に失敗する問題を修正しました。通常のファイルとして添付されるようになりました
  • [クラウド セッション] 組織が承認を必要とするように設定したコネクタ ツールに対して「常に許可」を提供する承認プロンプトを修正しました。その選択は何の影響も与えなかった
  • [リモートコントロール] 画像のみを受け入れるclaude.ai/codeから開始された新しいリモートコントロールセッションの最初のメッセージを修正しました。 PDF や後のメッセージなどの他のファイルを受け入れるようになりました
  • [Claude Tag] チャネルの [構成] ページの [許可されたドメイン] カードに [編集] ボタンを追加しました。これにより、エンタープライズ管理者は、チャネルのドメインを設定するアクセス バンドルを開くことができます。
  • [Claude Tag] クロードがまだ最初のリクエストを行っている間に Slack スレッドで送信された返信が、そのリクエストが終了するまで保留されるか、数秒間隔で送信された場合に返信が返信されない問題を修正しました。
  • [Claude Tag] 管理者がチャネルまたはワークスペースのデフォルト モデルを変更した後、GitHub プル リクエスト アクティビティまたは元のモデルに留まるルーチンによってのみ起動される Slack スレッドを修正しました
  • [Claude Tag] 組織の使用量クレジットが不足していることが本当の原因である場合に、Claude が Slack に使用量制限通知を投稿することがある問題を修正しました。
  • [Claude Tag] Slack から応答できない許可プロンプトが自動的に拒否された場合、中断されるまでセッションがハングする問題を修正しました。
  • [Claude Tag] チャネル内の @Claude !status を改善し、クロードがタグなしメッセージの読み取りを停止したときとその理由、そして @ メンションによって再び読み取りが開始されることを通知するようにしました。
  • [Claude Tag] !fork で続く Slack スレッドの最初のメッセージを、元のスレッドへのリンクとともに、メッセージの出所、リクエスト、質問者を示すカードに変更しました。
  • [Claude Tag] 管理者設定の Claude Tag の支出制限ページにある組織全体およびデフォルトの支出制限ボックスを、cli 退席時ではなく、Save または Enter を押した場合にのみ保存されるように変更しました。
  • [コード レビュー] コード レビュー分析の PR レビュー チャートに、前期からの変化を含む期間の合計とリポジトリ別の内訳を追加しました。
  • [コードレビュー] プルリクエストが新しいベースブランチに移動し、古いベースブランチが削除されたときにキューに入れられたレビューが失敗する問題を修正しました。コミットはレビューのために再度キューに入れられます
  • [コードレビュー] プルリクエストが CLAUDE.md のファイルを編集するときにそのルールを無視するレビューを修正しました。レビューではベース ブランチのバージョンが使用されるようになりました
