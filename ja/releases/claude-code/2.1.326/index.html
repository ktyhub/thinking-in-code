クロードコード v2.1.326

何が変わったのか

  • エージェント チームが有効になっているときにコード モードをオンにするためのサポートが追加されました。すでにオンにしている場合は、オンのチームとのセッションがコード モードで開始されます。
  • --allowedTools、--disallowedTools、または --tools 値に完全なルールとは思えないエントリがある場合の起動警告を追加しました
  • 管理者がセッション中に managed-mcp.json を追加すると MCP サーバーのロードが停止する理由を説明するメッセージを追加しました
  • プロバイダーまたは DISABLE_TELEMETRY などの環境変数がいつ機能をオフにするかを示す行を /status に追加しました
  • author や homepage などの不正な形式の plugin.json フィールドが無視される場合の注記を /plugin および claude plugin list に追加しました。
  • 非表示の起動通知を表示するために Ctrl+O を追加しました
  • 空のプロンプトに、リクエストが失敗した後に何をすべきかを示すヒントを追加しました。
  • Esc で停止するサブエージェントのビューに esc to stop フッター ヒントを追加しました
  • OpenTelemetry リソース属性に host.name および host.id を含めるために OTEL_RESOURCE_INCLUDE_HOST を追加しました (デフォルトではオフ)
  • MOD の Box に overflowX="scroll" を追加し、Text に maxLines と wrap="clip" を追加しました。
  • ソースのみが Edit 拒否ルールでカバーされている場合に拒否されるファイルの cp を修正しました
  • 検索または読み取りとしてトランスクリプトにまとめられるファイル (find -delete、cat a > b、sort -o) を削除または上書きする Bash コマンドを修正しました
  • クロード コードが確実に読み取れない、rm なしの一部のコマンドの Bash 権限プロンプトに表示される誤解を招く「危険な rm 操作」警告を修正しました
  • クラッシュ後、別のフォルダーから再度開いた後、またはバックグラウンド サービスにそれがない場合に、シェルがエクスポートした LLM ゲートウェイを失うバックグラウンド セッションを修正しました。モデル リクエストの前に停止するようになりました。
  • リスト上のプロセス番号が別のユーザーのプロセスによって再利用されている場合に、SSH ログインなどの独自のプロセスを終了するバックグラウンド サービスを修正しました
  • /permissions またはメイン会話ツール プロンプトで追加されたルール、および /add-dir フォルダーで、設定ファイルを書き込めなかった場合に保存されたように見える問題を修正しました。ターミナルは警告を発し、それに名前を付けます
  • OAuth リフレッシュ トークンが保存されていないほとんどのサーバーで、失敗した MCP headersHelper、または untrusted フォルダーで実行されない MCP を修正し、そのサーバーなしで他のセッションが開始されるようにしました。
  • クロードコードの起動を妨げたり、他の管理ファイルに影響を与えたりする特定のキー名の管理設定を修正しました
  • 数千レベルの深さで値がネストされた設定ファイルがクロード コードをクラッシュさせたり、一部の時間のみ適用したりする問題を修正しました。 64 レベルを超える値は警告とともに削除されるようになりました。
  • セッション中にエラーが発生して保存された設定ファイルがサイレントにスキップされる問題を修正しました。警告によりファイルに名前が付けられるようになりました
  • 管理対象設定で設定されたサブエージェント モデルが Claude Desktop の [コード] タブに適用されない問題を修正しました。これらの設定でプロバイダーまたはゲートウェイも選択しない限り、ターミナルの場合と同様に、独自の設定がオーバーライドされるようになりました。
  • /net へのシンボリックリンクを介してホームまたは設定ディレクトリに到達し、サンドボックス設定がその読み取りを拒否している場合、Linux 上でサンドボックス コマンドが起動できない問題を修正しました。
  • サンドボックス コマンド中にクロード コードが停止されたときに、空のプレースホルダー ファイル (.git/config.lock など) が Linux 上のプロジェクトに残ることがある問題を修正しました。

  • 管理設定の PreToolUse フックが直接ツール呼び出しを拒否したときに OpenTelemetry tool_decision イベントまたは permission_denials エントリを残さない問題を修正しました
  • /sandbox 上で入力された文字、または /permissions で選択範囲を移動する削除の質問を修正しました
  • 前のターンが空の応答で終了した場合、クラッシュ後に再開されたセッションが最近のターンを失う問題を修正
  • クロードコードのメモリが不足したときに再開されたセッションが以前の会話履歴を失う問題を修正

  • 遅いバックアップ コピーがまだ実行されている間に /branch を 2 回実行した後、/rewind が一部のファイルのみを復元する問題を修正しました

  • エージェント ビューを変更し、空の会話で ← を押した後に Ctrl+C を 2 回、Ctrl+D を 2 回押すか、/exit で終了すると、セッションを 5 分間実行したままにするのではなく、終了するようになりました。

  • サブエージェントの計画を承認するためのカードを 2 つの選択肢に変更しました。「はい、このセッションではデフォルトに切り替えます (毎回尋ねる)」と、矢印キーと Enter で選択する「いいえ」です (入力したテキストは「いいえ」に移動します)。

  • [VSCode] 検証コード、Web アドレス、または別のサインイン試行からのコードが貼り付けられたときにサインインが終了する問題を修正しました。代わりに何をペーストするかをパネルに表示するようになりました
  • [VSCode] API キーを使用せずにコンソールにサインインしているときにパネルまたはウィンドウが開くたびにサインイン画面が短く表示される問題を修正しました。

  • [VSCode] 2 番目のクロード コード セッションで、最初のセッションへのエディタ接続がサイレントに失われる /ide を修正しました。最新の接続が優先され、置き換えられたセッションに切り戻す方法が表示されます。
