claude-code v2.1.288

パッチ 公開日2026年10月2日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.288

何が変わったのか

  • MOD 用に $.ui.selection() を追加: フルスクリーン モードで最後に選択したテキストを返し、選択内容が 1 つのトランスクリプト行内にある場合は、その行を返します。
  • 画像に GitHub CLI がないクラウド セッションに組み込みの gh api を追加し、ファイル名からの制御文字、JQ フィルター、または GitHub エラーを端末に送信する組み込みを修正しました
  • Ctrl+C でクリアしたプロンプトのリカバリを追加しました。空のプロンプトで上を押すと、貼り付けたテキストや画像を含む下書きが戻ります。
  • ツール呼び出し中に MCP サーバーが追加の OAuth スコープを要求した場合の再認証プロンプトを追加しました
  • 通常の制限より多いまたは少ない結果を報告するために、--max-findings <n>|all を /code-review に追加しました。 --max-findings default を渡すまで、選択内容が再利用されます。
  • セッションを名前で検索するための Ctrl+F と、エージェント ビューでグループ間を移動するための Alt+↑/↓ を追加しました。両方と名前変更はキーバインドでリバウンドできます。json
  • Shift+Tab を含むプランを承認するときに、新しい権限モードのスクリーン リーダー モードのアナウンスを追加しました。
  • 応答途中の API タイムアウトがターンに失敗する問題を修正しました。非対話型セッションとサブエージェントは部分応答から続行され、思考のみの応答が再試行されるようになりました。
  • 最後の返信でトークン使用量がゼロであると報告された場合に、自動圧縮ではなく「プロンプトが長すぎます」というメッセージが表示されて失敗する長い会話を修正しました
  • --resume が圧縮によって復元されたばかりのファイルやその他のコンテキストを削除することがある問題を修正しました
  • 再開されたセッションでターンの最後の応答が保存されないことがあり、次の --resume でプロンプトが未応答で表示されることがあった問題を修正しました。
  • 同じセッションがロード中にファイルを書き換えたときに、トランスクリプトのロードが中断されることがある再開を修正しました
  • 2.1.286 以前で開始された会話を再開すると、モデルの以前の思考が削除される問題を修正しました
  • Mantle または構造化された出力を拒否するゲートウェイの背後で失敗するセッション タイトル、メモリ リコール、およびプロンプト フックを修正しました。構造化出力をオフにするために CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS を追加しました
  • ブロックされたツールが Bash ではない場合に、Bash 権限ルールをクロードに指摘する自動モード拒否を修正しました
  • WebFetch サマリーや sonnet サブエージェントなど、古いモデルへのリクエスト後にセッションの残りの部分でローカル分類子に切り替わる Bedrock と Mantle の自動モードを修正しました。
  • サーバーが拒否した後、新しく選択されたモデルでそのモデルで応答して再開されるクラウド セッションを修正しました
  • 未承認の URL に対する WebFetch 許可プロンプトが 5 分間応答されなかった後、Cowork クラウド セッションが入力待ちとしてマークされたままになる問題を修正
  • 別のデバイスで開始された Cowork クラウド セッションに参加する電話にプロンプトの提案が表示されない問題を修正
  • クロード コードが再起動される前に描画されたビュー上で MOD のボタンを押すと、別のボタンのアクションが実行されることがある問題を修正しました。
  • 1 つの Code 要素が解析しない差分を保持している場合、プラグインのペインに何も表示されない問題を修正しました。プレーンコードとして描画されるようになりました
  • プラグイン LSP サーバーが、置換値やマニフェストのデフォルトではなく、initializationOptions および settings のリテラル ${user_config.*} および ${CLAUDE_PLUGIN_ROOT} プレースホルダーを受け取る問題を修正しました。
  • Bash が失敗し、ワークツリーで実行されるサブエージェントでファイル検索が間違ったフォルダーを読み取るプラグインの tool.call フックを修正しました。
  • 古い git (2.39 より前、例: Ubuntu 22.04 の 2.34) での git-subdir プラグインのインストールが失敗するか、不完全なプラグインをキャッシュする問題を修正しました。
  • --plugin-dir でロードされたプラグインが /plugin で「オプションの設定」を表示しない問題を修正
  • タイマーまたは読み取りのいずれかがまだ実行中にプラグインがリロードまたは無効化されたときに終了するバックグラウンド セッションを修正しました
  • 本文にプレーンテキストと単純な $VAR 参照のみが含まれている場合、サンドボックスの自動許可の下で実行するたびに承認を求める、引用符で囲まれていない区切り文字 (python3 <<EOF) を含むサンドボックス化されたヒアドキュメントを修正しました。
  • シェルが算術として評価する値をサイレントに許可するのではなく、BASHPID 割り当ての前にプロンプトを表示する Bash ツールの権限チェックを修正しました。
  • プラグインまたは MOD がプロンプトの上に行を表示しているときにバックグラウンド タスク ダイアログを開くと、「回復不能なインターフェイス エラー」が発生して全画面セッションが終了する問題を修正しました
  • クロードが別のセッションにメッセージをそのセッションが保持していたときに配信済みとして報告する問題を修正しました。通知には配信されなかったことが示され、セッションに名前が付けられ、SDK セッションではクロードがターンの途中でメッセージを知ることができるようになりました。
  • -p および SDK セッションおよび PreToolUse フックの承認で unknown ソースまたは決定を報告する OpenTelemetry claude_code.tool.blocked_on_user スパンを修正しました
  • -p または中断されたターンで応答せずに終了し、tool_decision イベントを発行しない許可リクエストを修正しました
  • 履歴がまだ保存されているにもかかわらず、/compact より前に送信されたメッセージを拒否する Cowork クラウド セッションの編集と再試行を修正しました
  • 非常に長い応答ストリームが失敗した後、無人セッション (CLAUDE_CODE_RETRY_WATCHDOG) が数時間にわたって再試行される問題を修正しました。 Claude Code は再びストリーミングするようになりましたが、3 回のタイムアウト後に諦めます
  • 認証情報を安全なストレージに保存できなかった場合に「ログイン成功」と報告する /login を修正しました。失敗を表示し、新しいログインが有効にならなかった場合に再試行を提案するようになりました (anthropics/claude-code#73861)
  • Bedrock 認証情報の検索中に停止し、リクエストを終了する代わりにセッションをフォールバック モデルに移動することがある問題を修正しました。
  • 別の Claude Code プロセスがサインイン中にラップトップがスリープから復帰すると、2 番目の gcpAuthRefresh/awsAuthRefresh ブラウザー サインインが開く問題を修正しました。
  • エージェント チームの修正: 名前によって生成されたプラグイン定義のエージェントは、デフォルトではなく独自のプロンプト、ツール、disallowedTools、およびエフォートで実行されるようになりました。
  • timeout や systemd などのスーパーバイザーが SIGCONT を送信するときに SIGTERM を無視することがあるヘッドレス (-p / SDK) セッションを修正しました。
  • 組織の強制モデルリストが拒否したモデルを復元する再起動されたクラウドセッションを修正しました
  • リモート サーバーの結果が 16 MB を超えていた場合、または解析できなかった場合に、MCP ツール呼び出しが 2 回実行されることがある問題を修正しました。
  • Claude Desktop の [コード] タブのサブエージェントが、memory という名前のユーザー設定 MCP サーバーのツールをまったく取得しない問題を修正しました。
  • 自動モードが利用できない場合（disableAutoMode または古いモデルなど）、許可したサイトですべてのスクリーンショットとページが読み取られる前に Chrome でクロードが尋ねる問題を修正しました。タイピング、ナビゲーション、JavaScript はまだ質問します
  • GitHub SSH キーを持たない macOS および Linux マシン上の GitHub ソース プラグインで claude plugin install が失敗する問題を修正しました。クローンは HTTPS にフォールバックし、通知を出力するようになりました。
  • permissions.blockReadsOutsideWorkingDirectories がオンになっている間、git config ファイルの sandbox.credentials.files エントリが有効にならない問題を修正しました。
  • チームプランおよびエンタープライズプランまたは管理された設定を持つマシンでアーティファクトツールを使用してスライドまたはデザインを開始するときに、クロードが組織のデザインシステムを除外する問題を修正しました
  • クロード コード自体が再起動した後、Windows でキーボードが動作しない問題を修正しました (クロード アプリ ゲートウェイへの最初のサインイン、プロバイダーのセットアップ、/tui)
  • tools: に非常に多くの Agent(...) エントリがリストされているエージェントを起動するときのストールを修正しました。
  • PDF 全体が会話に入った後、Claude 3 Opus と Claude 3 Sonnet のセッションが毎ターン失敗する問題を修正
  • プラットフォーム ネイティブ バイナリのダウンロードに失敗し、プレースホルダー claude スタブのみがインストールされている場合に、npm 自動アップデーターが成功を報告する問題を修正しました。
  • まだ接続されているセッション、または別のクロード コード プロセスによって再接続されたばかりのセッションをアーカイブするリモート コントロールのクリーンアップを修正しました。
  • SSH と HTTPS の両方の取得が失敗した場合に、2 回目の試行のエラーのみが表示される owner/repo プラグイン マーケットプレイスを修正しました。両方のエラーが表示され、最初に試行されたトランスポートが上に表示されます。
  • Write または Edit がスコープ内のファイルを作成または変更するときに、パス スコープの .claude/rules ファイルとネストされた CLAUDE.md ファイルがロードされない問題を修正しました (以前は Read のみがロードしていました)
  • bypassPermissions モードまたはシェル許可ルールの下でプロンプトなしで実行される bash -c または sh -c スクリプト内の危険な rm (/ またはホーム ディレクトリ上のものなど) を修正しました (anthropics/claude-code#96300)
  • 言語サーバーが動的機能登録を使用するか、応答を停止すると、LSP ツール呼び出しが無期限にハングする問題を修正しました。リクエストが 60 秒後にタイムアウトするようになりました (サーバーごとに requestTimeout)
  • バックグラウンド エージェントがまだ実行中に発生する idle_prompt 通知フックを修正しました (anthropics/claude-code#93672)
  • PreToolUse フックと PermissionRequest フックのマッチングが失敗した場合、またはツールの入力を JSON にシリアル化できなかった場合にスキップされる問題を修正しました。現在通話はブロックされています
  • 新しい環境、またはサーバーではなく組み込みの出力制限と自動圧縮ウィンドウを使用したモデル切り替え後の最初のリクエストを修正しました。このリクエストは最大 1.5 秒待機する可能性があります
  • 「クロードは代わりに何をすべきですか?」を修正しました。 Ctrl+Enter を押してキューに入れられたメッセージを送信した後に中断された行にヒントが表示される
  • セッションが決して読み取らないサインインを実行している --bare セッションで、保存されたログインが置き換えられる可能性がある /login を修正しました。どの認証情報が機能するかが表示されるようになりました
  • サブエージェントのファイル アクセスがルールまたはネストされた CLAUDE.md をロードするときに、structsLoaded フックでagent_idとagent_typeが省略される問題を修正しました。ファイル アクセス時にロードされるルールとネストされた CLAUDE.md ファイルも作業量を報告するようになりました。
  • claude mcp serve のエージェント ツールが常に利用可能なエージェントがないと報告し、すべての subagent_type を拒否する問題を修正しました。
  • 全画面トランスクリプト ビューアの検索および /theme のカスタム カラー検索で、入力したテキストに端末のカーソルが従わない問題を修正しました。
  • スクリーン リーダー モードでの /permissions を修正しました。ルールの番号を入力すると、検索ボックスを開く代わりにその番号が選択されるようになりました。
  • 自動モードの改善: 会話が長くなりすぎて client 側の安全分類子がレビューできない場合、すべてのツール呼び出しを要求したり失敗したりするのではなく、会話が圧縮されるようになりました。
  • 改善されたスクリーン リーダー モード: 削除された単語などの短いアナウンスは、次にキーを押すか、画面上の何かが変わるまで画面上に表示され続けるようになりました。
  • スクリーン リーダー モードの改善: 質問ダイアログで回答された質問には、ボックスの横に「回答済み」と表示されるようになりました。
  • 組織が使用クレジット要求をオフにしているチームおよびエンタープライズ メンバーに表示される /usage-credits メッセージを改善しました
  • クラウド セッションの改善: 新しい会話の最初のターンは、設定が alwaysLoad: false である標準出力 MCP サーバーを待機しなくなりました。
  • 決定の責任者に応じて、「知っておくべき」メモを「私たち」、「主なエージェント」、または「あなた」と表示するように改善しました
  • アーティファクト データベースの書き込みがデータベースのサイズ制限で拒否された場合のエラーを改善しました。制限と空き領域が表示されるようになりました。
  • コマンドの一部を実行前にチェックできない場合に短い理由を表示するように Bash 権限プロンプトを改善しました。
  • セルフホスト ランナー: 組み込みの gh api を改善しました。拒否された gh コマンドは同等の gh api を出力するようになり、--paginate はリポジトリのリストのすべてのページに従い、ネストされた claude は削除されなくなりました。
  • 期限切れのサーバー認証情報からの Remote Control の回復の改善: セッションは更新中も接続されたままとなり、サーバー停止後にセッションが中断された場合でも維持されます。
  • バックグラウンド コマンドの時間制限を、無人セッション (-p、エージェント SDK、CI、クラウド) にのみ適用するように変更しました。ターミナル、デスクトップ アプリ、VS Code セッションには制限がありません
  • Claude Sonnet 5.5 または Opus 5.5 という名前の ANTHROPIC_DEFAULT_SONNET_MODEL ピンを無視し、代わりに Claude Sonnet 5 を使用するように client 側の自動モード分類子を変更しました。
  • claude project purge を claude purge に変更しました。古い名前はまだ機能しており、通知が出力されます
  • エージェント ビューの n: フィルター (および Ctrl+F 検索) を変更し、Enter キーを押すと、一番上の行ではなく最もよく一致する名前のセッションが開かれるようになりました。
  • /autocompact を変更して、自動コンパクト ウィンドウをモデルごとに保存するようにしました。これにより、切り替え時に各モデルが独自の設定を維持します。
  • ツールの呼び出しが続行される前に、完了を報告できないサーバーからの MCP URL プロンプトが「完了しました、続行します」を待つように変更され、最初にブラウザーで終了できるようになりました。
  • [VSCode] claude.ai コネクタを認証した後も「認証が必要」のままになる問題を修正しました。MCP サーバー ダイアログに [接続の確認] が表示されるようになりました。
  • [VSCode] 現在いるクロード ビューのみではなく、表示されているすべてのクロード ビューで会話を開始するオプトインの新しい会話ショートカット (Cmd/Ctrl+N) を修正しました。
  • [VSCode] 表示されているセッションをアーカイブした後、次に保存されたセッションが再開されるチャット ビューを修正しました。代わりに新しい会話が開始されるようになりました
  • [クラウドセッション] 無関係なセキュリティ設定の読み込み中または読み込みに失敗している間、クロードコード管理設定のクラウドセッションスイッチがロックオフのままになる問題を修正しました。
  • [クラウドセッション] 自己ホスト型ランナーが開始中に停止を押しても、キューに入れられたメッセージがキャンセルされず、ランナーが起動するとメッセージが実行される可能性がある問題を修正しました。
  • [Claude Tag] 設定が自動的に作成されたチャンネルで常に失敗する「このスコープを削除する」オプションを提供する Claude Tag 管理設定を修正しました
  • [Claude Tag] クロードが、読み取り専用の別のチャネルの関連する Slack スレッドもフォローできるように改善しました。そのため、そこにある更新が、それに依存する会話に届くようになります。
  • [Claude Tag] チャンネルの設定ページの保存エラーを改善しました。長すぎるチャンネルの指示は短くするように指示され、アクセスが失われたために保存が拒否された場合は、再試行するように指示されなくなりました。
  • 古い保存された設定のみを読み取った場合に、MOD がリモートでオフになったと報告する claude plugin test を修正しました
