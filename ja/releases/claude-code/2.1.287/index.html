claude-code v2.1.287

クロードコード v2.1.287

何が変わったのか

  • クロード Mod を追加: プラグインはより深い動作を変更できるようになりました
  • サイドエージェントがあなたの背後を監視し、あなたまたはクロードが見逃している可能性のあるものにフラグを立てる、知っておくべき組み込みMODを追加しました。 /plugin enable cc-plugin-you-should-know@builtin でオンにします (テレメトリがオンになっているファーストパーティ セッションの場合)
  • セッション名とタスクに一致する n:<text> フィルターをエージェント ビューに追加しました。フィルターは折りたたまれたセクションの一致を表示し、Enter キーを押すと最初の一致が開きます
  • prompt_text を OpenTelemetry user_prompt イベントに追加しました。これは、ドット付きキーをネストするバックエンド用の prompt のコピーです。 prompt をドロップまたはマスクした場所にドロップまたはマスクします (anthropics/claude-code#70763)
  • 2025-11-25 プロトコル上の MCP サーバーからの URL プロンプトを追加しました (サインインなど)。この更新後にサーバーが接続しなくなった場合は、MCP 構成エントリに "bareElicitationCapability": true を追加します。
  • Windows: Bash ツールを拒否すると PowerShell ツールもオフになるため、クロードにはシェル ツールが存在しないという起動警告が追加されました。
  • セルフホスト ランナー: GitHub CLI がインストールされていない macOS および Linux マシンで Anthropic 管理の git を使用するセッション用に組み込みの gh api (REST のみ) を追加しました。
  • 組織が許可している場合でも、ユーザー アカウントを持たないエージェントが所有するリモート セッションで高速モードがオフのままになる問題を修正
  • 再接続要求に応答がなかった場合、リモート コントロールが一度に数分間メッセージを受信しない問題を修正しました。 30秒後に諦めて再試行するようになりました
  • asyncRewake で構成されたフックが、フックのスクリプト ファイルが見つからないときに「問題が見つかりました」という通知でクロードを何度も目覚めさせる問題を修正しました。壊れたフックが一度報告されるようになりました
  • データが到着せずモデルの応答ストリームが停止している間、ツールのハートビートが SDK ホストに到達しない問題を修正しました。
  • 強制された availableModels リストを無視する Bedrock および Vertex スタートアップ モデル チェックを修正しました。これにより、/model が 1 つの Opus 行に折りたたまれる可能性がありました。
  • Chrome にアクセスできないときに Chrome ブラウザ ピッカーのクロードで JSON 解析エラーが表示される問題を修正しました
  • 現在のバージョンの ID を保存する claude.ai ログインで /model で Fable を選択する問題を修正しました。そのため、保存されたデフォルトは、Opus や Sonnet のように最新の Fable に従うようになりました。
  • Opus 5.5 と Sonnet 5.5 (/model、opusplan) の間の切り替えを修正し、以前の MCP ツールのアナウンスを書き換え、以前の拡張された思考を放棄する可能性がありました。
  • 返信の途中で到着し、返信が思考から始まったときにガードレールのメッセージではなく API エラーでターンを終了する Amazon Bedrock Guardrails ブロックを修正しました
  • 同じコマンドが出力を ~ またはワイルドカード パスにリダイレクトした場合に、常に確認するセーフガードを失う危険な rm (/ またはホーム ディレクトリ上のものなど) を修正しました。
  • 応答の実行中にモデルが切り替えられた後、以降のメッセージごとにモデル フォールバックを繰り返す claude -p および SDK セッションを修正しました。
  • セッションの再開後または圧縮後にフォルダーの CLAUDE.md が再度添付される問題を修正
  • エージェントが終了し、セッションが開始されたワークツリーを削除した後、claude agents から再度開くことができなかったバックグラウンド セッションを修正しました。
  • /advisor ペアリング チェックを修正: Sonnet 5.5 は Opus 4.7 と 4.8 にアドバイスできるようになり、API が拒否するアドバイザーには黙って削除されるのではなく、前もってフラグが立てられます。
  • わかりやすい説明の代わりに「Contains simple_expansion」などの内部パーサー名を表示する Bash 権限プロンプトを修正しました
  • 長い会話中にスクロールキーを押したままにすると、遅いマシンまたはビジーなマシンでフルスクリーンセッションが「回復不能なインターフェースエラーの後にクロードコードが終了しました」というメッセージで終了する原因を修正しました。
  • __proto__ という名前の MCP ツールに対して組織のツールごとの権限上限がサイレントに削除される問題を修正
  • クロードが、読み取りのオフセットと制限を使用して JSON として保存された大きな MCP 結果をページングするように指示される問題を修正しました。これでは、1 つの長い行を分割できません。
  • 圧縮後のツール結果内で配信されるコミット属性リマインダーを修正しました
  • スクリーン リーダー モードで、検索ボックス (/resume や /permissions など) やサインイン コード フィールドに入力したテキストからカーソルが離れたままになる問題を修正しました。
  • /rewind の要約オプション (追加コンテキストはオプション) に何も入力せずに Enter を拒否するスクリーン リーダー モードを修正しました。
  • 承認プロンプトで「タブで修正する」ヒントが表示されるスクリーン リーダー モードを修正しました。タブでは何も実行されません。
  • スクリーン リーダー モードで、/permissions および /mcp に何もしない矢印キーがリストされ、空のメニューまたは検索ボックスにキーがあるときに「数字で選択」と表示される問題を修正しました。
  • ファイル編集の承認プロンプトやその他の差分で変更された行が省略されるスクリーン リーダー モードを修正しました
  • claude --teleport 進行状況画面と、チェック中の MCP フォーム フィールドをスピナー フレームごとにスクリーン リーダーに再度送信するスクリーン リーダー モードを修正しました。
  • CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS が、Bedrock-backed ゲートウェイが拒否するセッション タイトルおよびプロンプト フック リクエストから構造化出力フォーマットを削除しない問題を修正しました。
  • 前の画面がターミナル ウィンドウよりも高い場合に、2 番目の承認プロンプト、変更された /config 行、または拒否された計画行の先頭行が省略されるスクリーン リーダー モードを修正しました。
  • --include-partial-messages が短縮返信の message_stop を遅刻または送信しない問題を修正し、アプリが返信をまだ進行中として表示できるようにしました。
  • バックグラウンドセッションが待機している許可プロンプトが時々表示されない claude agents を修正しました
  • UTF-16 として保存されたものなど、読み取りできないコミット済みの .gitattributes でアップロードが停止した場合に、.git/info/attributes に関するアドバイスを提供する /ultrareview を修正しました。
  • 誤解を招く「組織の権限を確認してください」エラーにより HTTP プロキシの背後で登録に失敗する claude remote-control を修正しました (anthropics/claude-code#97352)
  • Linux 上のサンドボックス化された Bash コマンドがクロード コード実行可能ファイルのオープン ハンドルを継承する問題を修正しました。
  • 「モーションを減らす」設定をオンにしてもランニング ツールのドットと 3 つのスピナーがまだ動いている問題と、メモを入力している間に /rewind の確認画面が「以前」の時間を更新している問題を修正しました。
  • スクリーン リーダー モードで claude agents の時間が毎秒変化する問題を修正しました。現在では最大でも 10 秒ごとに変更されます
  • 取り消された claude.ai ログインで「OAuth トークンが取り消されました」ではなく一般的な API Error: 401 が表示される問題を修正しました。 -p モードでは、エラーが「認証に失敗しました」で始まるようになりました。
  • リポジトリの設定ファイルで指定された変数を独自のユーザー設定にコピーするようアドバイスする /ultrareview アップロード拒否を修正しました
  • --output-format stream-json と SDK が、スキル ツールのフォークの場合と同様に、プロンプトとして /<skill> と入力して実行される context: fork スキルのターンをストリーミングしない問題を修正しました。
  • /フィードバックと/バグを修正：事前入力されたGitHub問題には最近のエラーメッセージが含まれなくなり、確認画面にレポートの一部としてリストされるようになりました。
  • リポジトリがプレーン http 経由で提供されている場合に、「トランスポート 'http' は許可されていません」というメッセージが表示され、claude plugin marketplace add --sparse および git-subdir プラグインのインストールが失敗する問題を修正しました。
  • クラウドセッションが圧縮中にセッションが再開されると、以前の会話が失われることがある問題を修正
  • スタートアップ --plugin-url ダウンロードと重なってプラグインのリロードが発生し、セッションのキャッシュされたプラグイン アーカイブのコピーが破損する問題を修正しました。
  • クロードデスクトップを開いたときにタイムアウトしたり、出力が多すぎるときに部分的な出力を引用する /desktop を修正しました。エラーによって原因が特定されるようになりました
  • サーバーがサポートする MCP プロトコルのバージョンを変更した場合、MCP コネクタ ツールの呼び出しが時々 2 回実行されるか、再起動するまでコネクタの呼び出しが失敗する問題を修正しました。
  • 同期されたプラグインからの SessionStart フックが新しいクラウド セッションで実行されない問題を修正
  • トランスクリプトの「N フックが実行されました」の概要と、クロード コードの内部コールバックを含む詳細デバッグ ログの一致したフック数を修正したため、1 つの設定済みフックが 2 つとして表示されなくなりました。
  • クロードがクラウドから送信するファイルと、30 秒のタイムアウト直後にアップロードが終了したときに失敗するリモート コントロール セッションを修正しました。現在は 35 秒待機します
  • クロードがディレクトリを変更した後、クラウドのセッション中に追加されたリポジトリと SDK セッションがスキルとプラグインをロードせず、CLAUDE.md を遅くロードする問題を修正しました
  • 片面が 8,000 ピクセルを超える PNG、JPEG、および WebP 画像がリモート セッションから送信できない問題を修正しました。クロードは縮小コピーを送信するようになりました
  • クロード アプリから送信される 17 ～ 20 個の添付ファイルを含むメッセージが最初の 16 個のみを配信する問題を修正
  • 1 回の通話が拒否された後、その後の呼び出しは成功しても、MCP サーバーに認証が必要であると報告するヘッドレス セッションを修正しました。
  • macOS: claude remote-control で開始されたリモート コントロール セッションが、Mac がアイドル スリープになったときにターンの途中で停止する問題を修正しました。
  • Windows: 入力がパイプまたはリダイレクトされると、対話型 claude が「Raw モードはサポートされていません」というメッセージでハングまたはクラッシュする問題を修正しました。理由を表示して終了します (パイプ入力には -p を使用します)。
  • Bedrock、Vertex、Mantle: ANTHROPIC_CUSTOM_HEADERS が反復するときに実際のリクエストとは異なる Authorization ヘッダーを送信する CLAUDE_CODE_SKIP_*_AUTH でのモデルの可用性チェックを修正しました。
  • 改良された /config: 循環表示 ‹ › と ←/→ で双方向にステップする設定、ナローターミナルはラベルの下に各値をスタックし、PgUp/PgDn でリストをページングします。
  • マーケットプレイスが無視または拒否された理由とその対処法をわかりやすい言葉で示すようにプラグイン マーケットプレイス エラーを改善しました
  • プラグインの依存関係がインストールされていない場合に注意するプラグインのリストが改善され、プラグインを更新すると、完了しなかったインストールが再試行されるようになりました。
  • Amazon Bedrock がモデル ID を拒否した場合のクロード アプリ ゲートウェイのエラーを改善しました。開発者はどのモデルが利用できないかを確認できるようになり、ゲートウェイのログには送信された ID の名前が付けられます。
  • SDK セッションが改善され、優先度「今」で送信されたメッセージによって実行中の Web フェッチまたは Web 検索がキャンセルされなくなりました。バックグラウンドで読み込み続けます
  • 改良された /memory: 左右の矢印キーで自動メモリなどの設定のオン/オフを切り替えられるようになりました。
  • メッセージ中に入力された /skill の名前が改善されました。クロードには、disable-model-invocation のものも含め、それらがスキルであると伝えられるようになりました。
  • 明るいテーマでのプロンプト入力境界線と、以前のメッセージの前の ❯ のコントラストを改善しました。
  • クロードがクラウド セッションおよびリモート コントロールから送信するファイルの配信が改善されました。タイムアウト、ネットワーク エラー、または 502、503、または 504 で失敗したアップロードが 1 回再試行されるようになりました。
  • 一時的な理由でファイルを送信できない場合のクロードのメッセージを改善しました。数分後に再度ファイルを要求できると記載されるようになりました。
  • 他のセッションからの保留メッセージのプロンプトを改善し、他の許可プロンプトと一致するように破線の間にメッセージを表示するようにしました。
  • MCP およびその他のツールの権限プロンプトが改善され、ファイル編集プロンプトと一致する点線の間にツール呼び出しが表示されるようになりました。
  • ヘッドレス モードでの MCP 起動の改善: 最初の接続が一時的に失敗したリモート サーバーは、最も遅いサーバーの接続が完了するのを待たずに再試行されるようになりました。
  • クロードがリモート セッションから送信するファイルの改善: 大きなファイルはメモリに読み取られるのではなくディスクからストリーミングされるようになり、サイズ制限を超えるファイルはサーバーの制限によって拒否されます。
  • サーバーがリモート コントロールまたはクラウド セッションから送信したファイル (特大の画像など) を拒否した場合にクロードが与える説明を改善しました
  • 大規模な MCP ツール結果の処理の改善: メモリが減り、セッション ファイルが小さくなり、制限を大幅に超える結果のトークンをカウントするための追加のアップロードが不要になりました。
  • Windows: すべてのコマンドの前に実行されるサブシェルを削除することにより、Bash ツールの速度が向上しました。
  • リポジトリにコミットされたシンボリックリンクを介して機密ファイルに書き込むか、作業ツリーの外に書き込むシェルを変更して、~ ターゲットの行でも、着地する場所に名前を付けて人を待つようにしました。
  • Opus 4.7+ と Fable を、Bedrock、Vertex、Foundry、および Claude アプリ ゲートウェイでデフォルトで 1M コンテキスト ウィンドウを使用するように変更し、[1m] サフィックスなしで (CLAUDE_CODE_DISABLE_1M_CONTEXT=1 は 200K を維持します)
  • claude agents からの返信がキューに入れられたメッセージとして到着するように変更されました。ターンの実行中に送信された /stop 以外のスラッシュ コマンドは、ターン終了時に実行されるようになりました。
  • ツール全体の Bash 許可ルールを変更し、シェルによるファイルへの書き込みを実行ではなくプロンプトするフックを許可する Claude Code のファイル ツールは完全に拒否します (Anthropic プロファイル ストア、ホスト認証情報ファイル)。
  • ボタンを放したときに、Windows と Linux では右の click ペーストが、Linux では中央の click ペーストが行われるように変更されました。放す前にポインタを遠ざけるとキャンセルされます
  • MCP サーバー alwaysLoad: false を変更して、そのサーバーのすべてのツールをツール検索の背後に置くようにしました。
  • スクリーン リーダー モードを変更し、行の先頭でカーソルを置いて一時停止せずに新しい行または変更された行を書き込むようにしました。 CLAUDE_AX_PREPARK_MS=50 を設定して一時停止を復元します
  • 新しいモデルのデフォルトではなく現在の努力レベルを維持するために、フラグ付きメッセージ後の自動モデル切り替えを変更しました。
  • 待機許可プロンプトが最も古いものから順に表示されるように変更されたため、新しいプロンプトが現在読んでいるプロンプトをカバーしなくなりました (プロンプトの上部にはまだカウントダウンが表示されます)
  • [VSCode] 実行中のコマンドまたはサブエージェントに「バックグラウンドで実行」を追加し、バックグラウンドに移動して動作を継続できるようにしました。
  • [VSCode] バックグラウンド シェルとモニターの出力をエージェント マップのカードに追加しました
  • [VSCode] クロード コードの応答が大きすぎて保存を確認できない場合にタイムアウトを引き起こす設定ダイアログを修正しました
  • [VSCode] サイドバーがすでにこのマシンにもたらしたクラウド セッションを新しいタブで再度開く問題を修正しました。代わりにサイドバーが表示されます
  • [VSCode] ウィンドウがロードされた後に開始されたクラウド セッションがリストされないサイド バーの Web タブを修正しました。ロードに失敗すると、「Web セッションがまだありません」ではなく「リモート サーバーが接続されていません」と表示されるようになりました。
  • [VSCode] サイドバーがすでに開いている会話で 2 番目のクロード プロセスを開始するリロード後にタブが復元される問題を修正しました。 「まだどこか別の場所で開いています」という通知が表示されるようになりました
  • [VSCode] プレーンテキストで表示されるツール行ファイルリンク、セッションリストリンク、および 2 つのヒントを修正しました

  • [VSCode] プラグインの管理ダイアログを改善しました。マーケットプレイスの追加、削除、または更新に失敗すると、何が問題だったかが表示されるようになりました。

  • [Claude Tag] GitHub アクティビティなどのバックグラウンド イベントによって起動され、誰も返信を待っていないときに、Claude が Slack スレッドに支出制限通知などの失敗警告を投稿する問題を修正しました。
  • [Claude Tag] 管理者設定の Claude Tag の支出制限ページで、多くのチャネルを持つ組織で最近作成されたプライベート チャネルが除外される問題を修正しました。
  • [Claude Tag] 長い Slack スレッド内のクロードのタスク リストを改善しました。バックグラウンド作業により、それが単独で新しいメッセージとして再投稿されなくなり、スレッドをフォローしている人々には通知されなくなりました。
  • [コードレビュー] コメントの検索とその「フラグが立てられた理由」テキストが文の途中で停止する問題を修正しました。それらは完全な文で終わるようになりました
  • [コード レビュー] 前回のコミットでレビューが 2 回失敗した場合に、新しいプッシュ後にプル リクエストをスキップするコード レビューを修正しました。最新のコミットをレビューするようになりました
  • [コードレビュー] 会話がロックされているプルリクエストの失敗レビューカードを改善しました。ロックによりレビューがブロックされ、何も投稿または請求されなかったことが表示されるようになりました。
