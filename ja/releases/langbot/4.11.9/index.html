LangBot v4.11.9

#ラングボットv4.11.9 LangBot は、オープンソースの AI チャットボットおよびエージェント プラットフォームであり、複数のインスタント メッセージング プラットフォーム、大規模な言語モデル、ナレッジ ベース、プラグインをサポートし、AI アシスタントの構築、展開、管理を支援します。 LangBot は、メッセージング プラットフォーム、大規模な言語モデル、ナレッジ ベース、プラグインを接続して、AI アシスタントの構築、展開、管理を支援するオープンソースの AI チャットボットおよびエージェント プラットフォームです。

ラングボット v4.11.9

Box サンドボックスは Windows ホスト上で実行されるようになり、エージェントはアップロードされたファイルをオンデマンドで読み取り、作成したファイルを公開でき、新規インストールではスキルとアップロードがデータベースに保持されます。 このバージョンでは、Box サンドボックスを Windows ホスト上で実行できます。エージェントは、アップロードされたファイルをオンデマンドで読み取り、独自に生成したファイルを公開できます。新規インストールでは、デフォルトでスキルとアップロードされたコンテンツがデータベースに保存されます。

アップグレードに関するメモ/アップグレードのヒント: このバージョンには、新しいデータベースの移行 (0049 ～ 0053) が含まれています。アップグレードする前に、data/ ディレクトリをバックアップしてください (PostgreSQL を使用する場合は、データベースも同時にバックアップしてください)。ダウングレード時に復元するには、このバックアップを使用する必要があります。 config.yaml に既に展開されているストレージ、スキル、ボックスの設定は変更されません。このリリースでは、データベース移行 0049 ～ 0053 が追加されます。アップグレードする前に、data/ (および使用している場合は PostgreSQL) をバックアップします。ロールバックにはそのバックアップが必要です。既存の展開では、ストレージ、スキル、ボックスの設定が config.yaml に保持されます。

ハイライト

  • Windows ホスト ボックス / Windows ホスト サンドボックス: プラグイン SDK 0.7.26 を使用すると、host バックエンドで Windows をサポートできるようになります。コマンドは最初に Git Bash で実行され、そうでない場合は PowerShell に戻り、最後にプロセス ツリー全体がクリーンアップされます。注: host は分離を実行しません (安全ではありません)。コマンドは、LangBot を実行しているユーザーとして直接実行されます。グループ チャットの信頼できないユーザーが、プロンプト ワード インジェクションを通じてコマンドを実行する可能性があります。これは自動的には選択されないため、config.yaml で明示的に box.backend: host に設定するか、lbctl ネイティブ インストール (lbctl v0.5.14 以降) によって書き込む必要があります。スキルは、box.file_transfer_mode: network の Windows ホスト Box では実行できません。 LangBot と Box が同じマシン上にある場合は、legacy を使用してください (lbctl が自動的に書き込みます)。 host バックエンドは Windows 上で動作するようになりました (Git Bash、PowerShell に戻ります。プロセス ツリー全体がクリーンアップされます)。 host には分離がなく、LangBot ユーザーとしてコマンドを実行するため、untrust グループ チャット ユーザーはプロンプト インジェクションを通じてコマンドを実行できます。これは自動選択されることはありません。box.backend: host を明示的に設定するか、ネイティブ インストール用に lbctl (v0.5.14+) に書き込ませます。スキルは、network 転送モードの Windows ホスト Box では実行できません。 LangBot と Box が 1 台のマシンを共有する場合は、box.file_transfer_mode: legacy を使用します (lbctl がこれを設定します)。
  • エージェント用ファイル / エージェント ファイル: アップロードされたファイルは、アクセス許可付きのファイル アセットとして保存されます。エージェントは最初にファイル参照を取得し、次に必要に応じてツールを通じてテキスト、画像、または PDF をセグメントごとに読み取ります。ランナーは生成されたファイルを指定された受信者に公開でき、実行が完了するかコアが再起動された後でもダウンロードできます。ナレッジ ベース ファイルとプラグイン SDK も、同じファイル資産セットに接続されます。アップロードは承認されたファイル アセットになります。エージェントはツールを通じてオンデマンドで参照を取得し、テキスト、画像、または PDF ページを読み取ります。また、ランナーは、実行終了後またはコアの再起動後もダウンロード可能なままの出力ファイルを公開できます。ナレッジベース ファイルとプラグイン SDK は同じアセットを使用します。
  • デフォルトでデータベースにバックアップされたスキルとアップロード / 新しくインストールされたデフォルトのデータベース ストレージ: 新しくインストールされたスキル (過去のバージョンを含む) とアップロードされたコンテンツは、デフォルトでデータベースに保存されます。 Box は、デフォルトでネットワーク経由でファイルを転送します。 Core と Box はディレクトリを共有する必要がなくなりました。既存のデプロイメントがこのモードに切り替わると、Core は HTTP を開始して開く前に古いスキルとローカル ファイルをインポートしますが、これは中断して復元することができます。インポートが完了すると、古いディレクトリに依存しなくなります。 Docker ネットワーク モードのボックスは、読み取り専用のローカル データ セットをマウントできます。新規インストールでは、スキル (バージョン履歴とともに) が保存され、データベースにアップロードされ、Box は共有ディレクトリではなくネットワーク経由でファイルを移動します。既存のデプロイメントが切り替わると、Core は HTTP を再開する前に古いスキルとローカル ファイルをインポートします。 Docker ネットワーク モード ボックスは、読み取り専用のローカル データセットをマウントできます。
  • オペレーション API / オペレーション API: /api/v1/operations インターフェイス (ディレクトリ、説明、実行、SSE フロー) が追加されました。API キーでもプラグインの権限を確認でき、lbctl などのクライアントは API キーを使用してプラグインの権限を確認できます。新しい /api/v1/operations ルート (カタログ、説明、実行、SSE) と API キーを使用したプラグインのアクセス許可の確認により、lbctl などの API clients でプラグインのアクセス許可を確認できます。
  • WebUI: 更新ダイアログ ボックスには、langbot.app の更新ログが直接表示されます。プラグインの詳細ページにはインストールされているバージョンが表示され、直接アップグレードできます。プラグインをインストールした後、コンポーネントの種類に応じて次の手順に進むよう求められます。更新ダイアログには、langbot.app の release note が表示されます。プラグインの詳細ページには、インストールされているバージョンが表示され、アップグレードが提供されます。プラグインをインストールすると、次のステップが提案されます。
  • 起動/スタートアップ: pip install は、起動時に不足している依存関係を自動的に検出しなくなりましたが、不足しているパッケージを一覧表示し、再インストールして終了するように求めるプロンプトを表示します。 LangBot は起動時に不足しているパッケージを pip インストールしなくなりました。それらのリストが表示され、再インストール手順が表示されて終了します。
  • 修正/修正: プラグイン プロセスの起動に繰り返し失敗すると、後退して再試行され、画面が更新されなくなります。 Telegram ストリーミング編集では、「メッセージは変更されていません」が無視されます。 MulticaAgent は一時的なエラーが発生すると再試行し、再起動中に失われた応答は再発行されます。エンタープライズ WeChat カスタマー サービスは、裸の external_userid にメッセージを送信するときに、open_kfid を自動的に解析します。 LangBot Cloud のアラームは手動で有効のままです。 E2B ワークスペース クォータが有効になります。プラグインのパッケージ化には、仮想環境のディレクトリは含まれません。失敗したプラグインワーカーは撤退します。 Telegram ストリーミングは「メッセージは変更されていません」を無視します。 MulticaAgent は一時的なエラーを再試行し、再起動によって失われた応答を回復します。 WeCom カスタマー サービスは、ベア external_userid ターゲットの open_kfid を解決します。アラートは LangBot Cloud でオプトインのままです。 E2B ワークスペース制限が適用されます。プラグイン パッケージには virtualenvs が含まれません。
  • SDK：langbot-pluginは0.7.25によって0.7.26に固定されています。コアピンlangbot-plugin==0.7.26。

リリースの検証

  • コミット 826bf580ff42bbf10dac52203f1171f63b97b52a をリリースします。テストされた候補 dfa3c743c とはバージョン番号が異なるだけです。すべてのプルリクエスト チェックはリリース PR で渡されました。
  • タグ付けする前に、候補は新しいデータ ディレクトリに 2 回インストールされ、日常的な操作が実行されました。
    • Docker (プラグイン ランタイムと Box を備えた docker compose、候補コミットから構築されたイメージ);
    • uvx (uvx --from <wheel> langbot、PyPI からの依存関係: SDK 0.7.26、SQLAlchemy 2.1.9)。 両方とも合格しました: アカウント設定と WebUI。 LocalAgent、EssentialCommands、WebSearch、LangRAG、および HelloPlugin のマーケットプレイス インストール (権限の確認、パイプラインごとの有効化/無効化、アンインストール付き)。モデルプロバイダーとモデルテスト。 Web 検索ツールの呼び出しを含む、HTTP ボット上の LocalAgent パイプライン。 !help !cmd !func !plugin !version;知識ベースの取り込みと検索。スキルを作成し、エージェントにそれを使用させる。再起動後もデータ、プラグイン、ナレッジベース、スキルはそのまま残ります。 Docker は Box サンドボックス コンテナーでコマンドを実行しました。 uvx は host Box バックエンドを通じて 1 つを実行しました。
  • 同時性: Docker では 1 つのモデルで 8 つの同時会話が完了しました。 uvx (SQLite) では、高負荷のテスト ホスト上で一部の会話が HTTP Bot 60 の応答ウィンドウを超え、いくつかの会話で database is locked がヒットしました。 v4.11.8 は同じ負荷の下で並べて同じように動作するため、これはこのリリースでは新しいことではありません。
  • Windows: リリース ホイールは、Windows 11 (ビルド 26300、コード ページ 936、Python 3.11、Git Bash インストール、SDK 0.7.26、SQLAlchemy 2.1.9) に uvx でインストールされ、8 つの同時会話 (8/8、database is locked なし) を含むローカルのモック モデルで同じチェックリストに合格しました。 box.backend: host および file_transfer_mode: legacy では、エージェントはコマンド (exec) を実行し、Windows ホスト ボックスを介してファイルの書き込みと読み取りを行いました。中国語と絵文字を印刷するプラグインはランタイムの接続を維持し、トークナイザーのダウンロードがブロックされたため、最初の LocalAgent 会話は 2 秒以内に応答しました (count_tokens タイムアウトなし)。
  • データベースの移行: v4.11.8 (リビジョン 0048)、v4.10.11 (0023)、および v4.10.6 (0008、ワークスペースの前) によって作成されたデータベースは、SQLite と PostgreSQL の両方でこのリリースにアップグレードされました。各アップグレードはリビジョン 0053 に達し、2 回正常に開始されました。行は失われず、SQLite の整合性と外部キーのチェックに合格し、シードされたプロバイダー、モデル、ボット、パイプラインがリードバックされました。 3 つの実際の SQLite データベースのコピー (リビジョン 0042、0040、および 0008、最大 33 MB) もきれいにアップグレードされました。アップグレードされたスキーマは、0024 より前に開始されたデータベースでのインデックス名の違いを除き、新規インストールと一致します (v4.11.8 にも同様)。
