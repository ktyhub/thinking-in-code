LangBot v4.11.8

パッチ 公開日2026年11月15日 出典langbot-app/LangBot 英語原文

#ラングボットv4.11.8 LangBot は、オープンソースの AI チャットボットおよびエージェント プラットフォームであり、複数のインスタント メッセージング プラットフォーム、大規模な言語モデル、ナレッジ ベース、プラグインをサポートし、AI アシスタントの構築、展開、管理を支援します。 LangBot は、メッセージング プラットフォーム、大規模な言語モデル、ナレッジ ベース、プラグインを接続して、AI アシスタントの構築、展開、管理を支援するオープンソースの AI チャットボットおよびエージェント プラットフォームです。

ラングボット v4.11.8

WebUI からプロンプト、スキル、MCP サーバー、プラグインを LangBot Space に共有し、ボットやモデルが失敗し続けるとアラートを受け取り、ワークスペースごとにサンドボックス バックエンドを選択します。 Docker の画像は 60% 小さくなります。 このバージョンでは、WebUI から LangBot Space へのプロンプト ワード、スキル、MCP サーバー、プラグインの共有がサポートされ、新しいワークスペース障害アラームが追加され、ワー​​クスペースごとにサンドボックス バックエンドを選択できます。 Docker の画像は約 60% 縮小されます。

アップグレードに関するメモ/アップグレードのヒント: このバージョンには、新しいデータベースの移行 (0047、0048) が含まれています。アップグレードする前に、data/ ディレクトリをバックアップしてください (PostgreSQL を使用する場合は、データベースも同時にバックアップしてください)。ダウングレード時に復元するには、このバックアップを使用する必要があります。このリリースでは、データベース移行 0047 および 0048 が追加されています。アップグレードする前に、data/ (および使用している場合は PostgreSQL) をバックアップしてください。ロールバックにはそのバックアップが必要です。

ハイライト

  • LangBot スペース共有/LangBot スペースへの共有: ダイアログ プロンプト、エージェント プロンプト、スキル、リモート MCP サーバー、およびローカルにインストールされたプラグインを WebUI の LangBot スペースに直接送信します。認証情報は送信前にスキャンされます。プロンプトの単語にキーが含まれている場合、そのキーはブロックされます。リモート MCP の認証ヘッダーとパラメータはプレースホルダーに置き換えられ、ローカル マシンには残りません。新しいプロンプト ワード ライブラリがパイプラインとエージェントのプロンプト ワード入力ボックスの上に追加され、検索、プレビュー、置換、追加が可能で、space.langbot.app のコレクションと同期されます。資格情報スキャンを使用して、プロンプト、スキル、リモート MCP サーバー、およびローカルにインストールされたプラグインを WebUI から LangBot Space に共有します。プロンプト エディターからコミュニティ プロンプトを参照してお気に入りに追加します。
  • ワークスペース アラート: ロボットがオフラインになったり、パイプラインまたはモデルに継続的に障害が発生したりすると、電子メール、LangBot Space、または Webhook 経由で管理者に通知されます。しきい値は調整可能で、回復後に自動的に閉じられます。メール構成は最上位の email セグメント (SMTP または再送信) に移動され、古い workspace.invitations.email は起動時に自動的に移行されます。電子メール、LangBot Space、または Webhook を介したオフライン ボットおよび繰り返されるパイプライン/モデルの障害に関するアラート。電子メール設定は最上位の email セクションに移動され、自動的に移行されます。
  • ワークスペース サンドボックス: 各ワークスペースは、Box バックエンドとして Docker、E2B、または nsjail を選択し、管理者の制限内でリソース制限を設定できます。変更は新しいタスクにのみ影響します。 Box はネットワーク ファイル転送をサポートしており、検証キャッシュを使用してコア、ランナー、サンドボックス間でファイルを転送できます。管理者の制限内でワークスペースごとに Docker、E2B、または nsjail を選択します。 Box は、ネットワーク経由でコア、ランナー、サンドボックス間でファイルを移動できるようになりました。
  • スキル/スキル: スキルはバージョン管理されたパッケージ (付随ファイルを含む) に保存され、Space にエクスポートして共有できます。スキルは、そのアセットとともにバージョン管理されたパッケージとして保存され、エクスポートして共有できます。
  • 小さい Docker イメージ / 小さい Docker イメージ: rockchin/langbot は 768 MB から 308 MB にダウングレードされました (gzip、amd64)。 SeekDB、Milvus、および Valkey Search はオプションになりました。Docker ユーザーは <tag>-seekdb / -milvus / -valkey ミラーを使用し、pip/uvx ユーザーは langbot[seekdb] / [milvus] / [valkey] をインストールします。デフォルトの Chroma、Qdrant、および pgvector の使用は影響を受けません。デフォルトのイメージは 768 MB から 308 MB に減少します。 vdb.use: seekdb、milvus、または valkey_search を使用している場合は、一致するイメージ タグまたはエクストラに切り替えてください。
  • エージェント ランナーのライフサイクル/エージェント ランナーのライフ サイクル: キャンセル、タイムアウト、障害、切断の場合に生成されたトークンの使用状況を保持します。進行状況とキャンセル結果、確認可能なステアリング配信、再試行とキャンセルの確認 (SDK 0.7.25) を追加します。ランナーの実行では、キャンセルと切断を通じて部分的な使用が維持され、進行状況/キャンセルの結果、承認されたステアリングと再試行が行われます (SDK 0.7.25)。
  • LocalAgent: モデルが空の応答を返した場合、次のスタンバイ モデルに切り替えます。スタンバイモデルがない場合はエラーとなります。それはもはや沈黙も応答もありません。モデルに送信されるメッセージは最初のシステム メッセージのみを保持し、役割の交代を保証します。 vLLM/SGLang で Qwen3.5/3.6 を修正し、ナレッジ ベースを切断した後に Invalid request parameters を報告します。空のモデルの回答はフォールバックするか、目に見えて失敗するようになりました。 vLLM/SGLang 上の Qwen3.5/3.6 は、ナレッジ ベースが添付された LocalAgent リクエストを拒否しなくなりました。
  • 修正/修正: n8n ストリーミング ワークフローがエラーを報告しても、ランナーは成功を報告しなくなりました。プラグイン call_tool の結果は JSON としてシリアル化されます。アウトバウンド URL 検証は、すべての非パブリック アドレス (クラウド ベンダーのメタデータ アドレスを含む 100.64.0.0/10 を含む) を拒否します。 DifyAgent は、リクエスト ログにフォーム トークンと署名付き URL を記録しなくなりました。 LangBot Cloud ユーザーは、一時的なサーバー障害が発生したときにログアウトされなくなり、アップロード可能なプラグインの詳細ページにアップロード ボタンが追加されます。
  • SDK: プラグイン SDK は LangBot メイン パッケージ sdk/ に組み込まれており、独立して公開されています。langbot-plugin は 0.7.24 によって 0.7.25 に固定されています。プラグイン SDK は現在、sdk/ の下のこのリポジトリに存在します。コアピンlangbot-plugin==0.7.25。

リリースの検証

  • コミット 9301e0ea3eec6bc3a57ef85475557c6b807ae80e をリリースします。完全にテストされた候補 7e2668682 とはバージョン番号のみが異なります。単体テスト (Python 3.11/3.12/3.13)、PostgreSQL コントラクト テスト、ツリー内 SDK を使用したコア、E2E スタートアップ、コア スモークおよび回帰ツールを含む、その候補に渡されたすべてのプルリクエスト チェック。リリース コミット自体で、uvx インストールはスモーク実行 (プラグイン、モデル、ツール呼び出しによる LocalAgent チャット、コマンド、!version = v4.11.8) を通過し、Docker イメージが正常に開始されました。
  • タグ付けする前に、候補は新しいデータ ディレクトリに 2 回インストールされ、日常的な操作が実行されました。
    • Docker (プラグイン ランタイムと Box を備えた docker compose、リリース コミットから構築されたイメージ; SQLAlchemy 2.0.46);
    • uvx (uvx --from <wheel> langbot、PyPI からの依存関係: SDK 0.7.25、SQLAlchemy 2.1.8)。 どちらもアカウント設定と WebUI という同じチェックに合格しました。 LocalAgent、EssentialCommands、WebSearch、LangRAG、および HelloPlugin のマーケットプレイス インストール (権限の確認、パイプラインごとの有効化/無効化、アンインストール付き)。モデルプロバイダーとモデルテスト。 Web 検索ツールの呼び出しを含む、HTTP ボット上の LocalAgent パイプライン。 !help !cmd !func !plugin !version;知識ベースの取り込みと検索。スキルを作成し、エージェントにそれを使用させる。 1 つのモデルで 8 つの同時会話 (トークン数による拒否なし)。再起動後もデータ、プラグイン、ナレッジベース、スキルはそのまま残ります。 Docker は、Box サンドボックス コンテナーでもコマンドを実行しました。
  • Windows: リリース ホイールは Windows 11 (コード ページ 936、Python 3.11、SDK 0.7.25、SQLAlchemy 2.1.8) に uvx とともにインストールされ、ローカルのモック モデル、さらに中国語と絵文字を印刷するプラグイン (ランタイムは接続されたまま)、およびトークナイザーのダウンロードがブロックされた最初の LocalAgent 会話で同じチェックリストに合格しました (2 秒、いいえ) count_tokens タイムアウト)。
  • データベースの移行: v4.11.7 (リビジョン 0046)、v4.10.11 (0023)、および v4.10.6 (0008、ワークスペースの前) によって作成されたデータベースは、SQLite と PostgreSQL の両方でこのリリースにアップグレードされました。各アップグレードはリビジョン 0048 に達し、2 回正常に開始されました。行は失われず、SQLite の整合性と外部キーのチェックに合格し、シードされたプロバイダー、モデル、ボット、パイプラインがリードバックされました。 3 つの実際の SQLite データベースのコピー (リビジョン 0042、0040、および 0008、最大 33 MB) もきれいにアップグレードされました。アップグレードされたスキーマは、0024 より前に開始されたデータベースのインデックス名の違いを除き、新規インストールと一致します (v4.11.7 にも同様の違いがあります)。
