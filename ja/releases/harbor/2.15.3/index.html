#港v2.15.3

<!-- v2.15.3 の .github/release.yml の構成を使用して生成された Release note -->

[!警告] 重大な変更: 内部アドレスへの Webhook はデフォルトでブロックされます

GHSA-2phj-cp9f-qq6w の修正により、プライベート、ループバック、リンクローカル、およびその他の非パブリック アドレスへの Webhook および Slack 配信がブロックされます。これには、*.svc.cluster.local など、それらに解決されるホスト名が含まれます。アップグレード後、内部エンドポイントへの既存の Webhook は配信できず、新しい Webhook は拒否されます。

再度許可するには、コアとジョブサービスの両方にオプトアウトを設定します。

  • harbor.yml: network.allow_private_network_access: true、次に ./prepare を実行して再起動します。
  • Helm: core.extraEnvVars と jobservice.extraEnvVars の両方に {name: HARBOR_ALLOW_PRIVATE_NETWORK_ACCESS, value: "true"} を追加します。

これにより、保護が完全に無効になります。すべてのプロジェクト管理者を rust にし、ネットワーク レベルで 169.254.169.254 をブロックする場合にのみ使用してください。

[!警告] 重大な変更: コンテンツ trust が適用されると、署名されていないイメージへの署名が失敗します

GHSA-wrw5-gmvj-gf23 の修正により、cosign および notation が署名されていないイメージをプルできるようにするユーザー エージェント ベースの除外が削除されます。署名付きイメージのみを許可するプロジェクトでは、新しい署名されていないイメージ上の cosign sign および notation sign が 412 Precondition Failed で失敗するようになりました。すでに署名のある画像は影響を受けません。

clients に再度署名できるようにするには、core に CONTENT_TRUST_LEGACY_SIGNER_PULL_ENABLED=true を設定します。値は正確に true である必要があります。

  • ヘルム: core.extraEnvVars に追加します。
  • harbor.yml がインストールされます: harbor.yml オプションはありません。 common/config/core/envに追加して再起動します。 ./prepare を再実行すると、そのファイルは上書きされます。

免除は引き続き rusts client のユーザー エージェントに適用されますが、プロジェクトに対するプッシュ権限を持つユーザーまたはロボットのみが対象となります。脆弱なイメージをブロックするプロジェクトにはオプトアウトがありません。署名している client は、脆弱性ポリシーによってブロックされているイメージをプルできなくなります。

[!警告] 既知の問題: AWS ECR などの特定のレジストリでプッシュ レプリケーションが失敗する (GHSA-wjpm-hv5w-gxr6 リグレッション)

GHSA-wjpm-hv5w-gxr6 のセキュリティ修正により、静的に構成されたレジストリ エンドポイント (c.url) に対してアップロード Location ヘッダーが厳密に検証されました。 AWS ECR アダプターは API コントロール プレーン エンドポイント (https://api.ecr.<region>.amazonaws.com) を構成する一方で、リクエストはデータ プレーン ホスト (<account>.dkr.ecr.<region>.amazonaws.com) に書き換えられるため、ECR の応答 Location ヘッダーはクロスオリジン ターゲットとして拒否されます。

回避策/解決策:

修正は PR #24113 で提供されており、次のパッチ リリースでリリースされる予定です。 環境がプッシュ レプリケーションに依存している場合は、次のパッチ リリースまでアップグレードを延期するか、パッチを直接適用することをお勧めします。

  • (中): レジストリ チャンクのアップロードでは、401e73429 の未検証の Location ヘッダー GHSA-wjpm-hv5w-gxr6 が再利用されます。
  • (中): 脆弱性とコンテンツ - 9d255ebe1 の攻撃者制御の User-Agent ヘッダー GHSA-wrw5-gmvj-gf23 経由でバイパス可能な Trust プル ポリシー
  • (中): 攻撃者が制御するページネーションによる SSRF と資格情報の開示 レジストリ レプリケーションのリンク ヘッダー client GHSA-xgp2-5vxg-rgh2 in a01e0c6c5
  • (低): bfd319a92 の AuthMode ルックアップ失敗 GHSA-3x7c-wf86-mjx6 の後もセキュリティ ミドルウェアは継続します。
