#干し草の山 v3.5.0

⭐️ハイライト

🧭 OpenAI Decisions API を使用した分類とルーティング

3 つの新しいコンポーネントは、OpenAI Decisions API を使用して、指示なしでデータを処理する方法を選択します。 OpenAIDecisionsTextRouter はラベルごとに名前付き出力にテキストを送信します。OpenAIDecisionsImageRouter は画像に対しても同じことを行い、信頼性の低い決定をフォールバック ブランチに送信できます。また、OpenAIDecisionsDocumentClassifier はドキュメントに関する選択肢、スコア、はい/いいえの質問に答え、その回答をメタデータに保存します。

from haystack.components.routers import OpenAIDecisionsTextRouter

router = OpenAIDecisionsTextRouter(
    labels={
        "billing": "Payments, invoices, refunds and charges",
        "technical": "Bugs, crashes and errors in the product",
    },
    instructions="Which team should handle this support request?",
    min_confidence=0.6,
)

print(router.run(text="I was charged twice for my subscription."))
# >> {'billing': 'I was charged twice for my subscription.'}

🧱 エージェント向けの構造化された出力

新しい StructuredOutputHook は、Pydantic モデルまたは JSON スキーマに対してエージェントの最終応答を検証し、それを result["structured_output"] の辞書として返します。応答が検証されない場合、フックはエラーをモデルに送り返し、最大 max_retries 回まで再試行させます。

from pydantic import BaseModel

from haystack.components.agents import Agent
from haystack.components.generators.chat import OpenAIResponsesChatGenerator
from haystack.dataclasses import ChatMessage
from haystack.hooks.structured_output import StructuredOutputHook

class CityInfo(BaseModel):
    city: str
    country: str

agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(generation_kwargs={"text_format": CityInfo}),
    state_schema={"structured_output": {"type": dict}},
    hooks={"on_exit": [StructuredOutputHook(schema=CityInfo)]},
)

result = agent.run(messages=[ChatMessage.from_user("Which city is the Eiffel Tower in?")])
print(result["structured_output"])
# >> {'city': 'Paris', 'country': 'France'}

また、エージェント向けの新機能です。実験的な StepBudgetReminderHook は、モデルが max_agent_steps に近づくと残りのステップ数を通知するため、モデルは打ち切られるのではなく答えで終了します。

🎯 マルチベクトル埋め込みと MaxSimRanker

Document には、ColBERT などの遅延インタラクション モデル用の新しい multivector_embedding フィールドがあり、新しい MaxSimRanker は、各クエリ ベクトルをドキュメント ベクトルと比較し、最も一致するものを合計することによって候補を再ランク付けします。 DocumentJoiner(join_mode="merge_embeddings") は、同じドキュメントに対して並列計算された密、疎、およびマルチベクトル埋め込みを結合することもできます。

これは、Haystack (#13257) でのマルチベクトル取得に向けた最初のステップです。マルチベクトル埋め込みを生成するエンベッダー: Sentence Transformers および vLLM は、Haystack Core Integrations で開発中です。

from haystack import Document
from haystack.components.rankers import MaxSimRanker

# Representative multivector embedding for "How do solar panels work?"
query_multivector_embedding = [[1.0, 0.0], [0.0, 1.0]]

documents = [
    Document(content="Wind turbines generate electricity.", multivector_embedding=[[1.0, 0.0], [0.0, 0.2]]),
    Document(content="Solar panels turn sunlight into power.", multivector_embedding=[[0.95, 0.05], [0.15, 0.9]]),
    Document(content="Solar cells absorb light.", multivector_embedding=[[0.9, 0.1], [0.1, 0.9]]),
]

ranker = MaxSimRanker(top_k=2)
result = ranker.run(query_multivector_embedding=query_multivector_embedding, documents=documents)
for document in result["documents"]:
    print(f"{document.score:.2f}: {document.content}")
# >> 1.85: Solar panels turn sunlight into power.
# >> 1.80: Solar cells absorb light.

⚠️ 新しいデフォルト OpenAI モデル

OpenAIChatGenerator、OpenAIResponsesChatGenerator、および LLM ベースのエバリュエーターのデフォルトは、OpenAI が gpt-5-mini の代替として推奨する gpt-5.6-terra になりました。 OpenAI は、2026 年 12 月 11 日に gpt-5-mini をシャットダウンします。model: gpt-5-mini で保存されたパイプラインは引き続き使用するため、それまでに YAML を更新してください。

⬆️ アップグレードに関する注意事項

  • 意思決定 API をサポートするために、サポートされる最小バージョン openai SDK を 2.6.0 から 3.26.0 に引き上げます。

  • サポートされる最小バージョンとして pydantic>=2.12 (Python 3.15 では >=2.14) を宣言しました。 2.11 より前の pydantic リリースでは、create_tool_from_function/@tool、ComponentTool、および PipelineTool のツール パラメーターに対して異なる JSON スキーマが生成されます。

  • read_excel_kwargs で keep_default_na または na_values を設定しない場合、XLSXToDocument は、"NA"、"N/A"、"NULL"、"None" などのセル テキストを欠落しているものとして扱うのではなく、保持するようになりました。したがって、そのようなテキストを含む数値列は浮動小数点に変換されなくなり、CSV 出力ではその整数が 1.0 ではなく 1 としてレンダリングされます。以前の動作を復元するには、read_excel_kwargs={"keep_default_na": True} を渡します。

  • 複数のセンダーに接続された Variadic 入力または list 入力を持つコンポーネントは、センダーが Pipeline.connect() に接続された順序で値を受信するようになりました。以前は、Pipeline.run() は送信側が実行した順序でそれらを渡していたため、DocumentJoiner と weights などの順序依存コンポーネントの結果は変わる可能性があります。値を到着させたい順序で送信側を接続します。 YAML からパイプラインをロードする場合は、connections エントリの順序を確認してください。このリリースより前に保存されたパイプラインは、作成された順序ではなく送信者ごとにグループ化された connections をリストし、エントリの順序によってソケットが値を受け取る順序が決定されるようになりました。例えば、embedding_retriever が connections の bm25_retriever の前にリストされている場合、DocumentJoiner は、以前は BM25 リトリーバーに適用できた weights[0] を埋め込みリトリーバーに適用するようになりました。 Variadic または複数送信側 list ソケットにフィードするエントリを並べ替えて、送信側が期待する順序になるようにします。

  • OpenAIChatGenerator および OpenAIResponsesChatGenerator のデフォルト モデルが gpt-5-mini から、OpenAI が推奨する代替モデルである gpt-5.6-terra に変更されました。 OpenAI は、2026 年 12 月 11 日に gpt-5-mini をシャットダウンします。LLMEvaluator、ContextRelevanceEvaluator、および FaithfulnessEvaluator も新しいデフォルトを使用します。

    この変更より前にシリアル化されたパイプラインは model: gpt-5-mini を保存し、それを使用し続けます。 2026 年 12 月 11 日までに YAML の model 値を更新します。それまで gpt-5-mini を保持するには、明示的に OpenAIChatGenerator(model="gpt-5-mini") を渡します。

  • OpenAIResponsesChatGenerator 応答の reply.reasoning.extra から id、encrypted_content、または status を直接読み取る場合は、代わりに reply.reasoning.extra["reasoning_items"] のエントリから読み取ります。たとえば、最初の項目の reply.reasoning.extra["id"] を reply.reasoning.extra["reasoning_items"][0]["id"] に置き換えるか、リストを反復処理してすべての推論項目を処理します。

  • OpenAIChatGenerator および AzureOpenAIChatGenerator は、ストリーミング時にデフォルトでトークン使用メタデータを要求するようになりました。以前の動作を復元するには、generation_kwargs={"stream_options": {"include_usage": False}} を渡します。

  • max_agent_steps は、Agent の予約済み状態キーになりました。 max_agent_steps という名前のカスタム state_schema キーを定義した場合は、その名前を変更します (例: my_max_agent_steps)。予約キーが再定義されると、エージェントは初期化時に ValueError を生成するようになりました。

🚀 新機能

  • ColBERT などの遅延インタラクション モデルによって生成されたものなどのマルチベクトル表現を格納するには、オプションの multivector_embedding フィールドを Document に追加します。これは、マルチベクター エンベッダー、レトリーバー、ランカーのサポートに向けた最初のステップです。

  • 事前計算されたマルチベクトル埋め込みを使用して、クエリとの類似性によってドキュメントをランク付けするための MaxSimRanker を追加します。 2 段階の検索では、埋め込み検索機能が密な類似性を使用して候補を迅速に選択し、その後 MaxSimRanker がクエリと各候補のコンテンツのより詳細な比較を実行して、最も関連性の高いドキュメントを返します。

  • OpenAI Decisions API を使用してドキュメントに関する選択、スコア、述語の質問に答えるために OpenAIDecisionsDocumentClassifier を追加します。回答はドキュメントのメタデータに保存されます。

  • OpenAIDecisionsImageRouter を追加して、オプションのテキスト コンテキストを使用して、コンテンツに基づいて画像をさまざまなパイプライン ブランチにルーティングします。信頼性の低い決定を含む画像はフォールバック ブランチに送信できます。

  • OpenAI Decisions API を使用してテキストを名前付きカテゴリにルーティングするために OpenAIDecisionsTextRouter を追加します。

  • StructuredOutputHook に haystack.hooks.structured_output を追加しました。 on_exit の下に登録され、エージェントの最終応答を JSON として解析し、Pydantic モデルまたは JSON スキーマに対して検証し、デフォルトで結果を structured_output キーの下に辞書として保存します。キーはエージェントの state_schema で宣言する必要があります。宣言しないと、フックによって実行時にエラーが発生します。

    応答を解析できない場合、フックは検証エラーをモデルに送り返し、エージェントの実行を継続して、応答を最大 max_retries 回 (デフォルトでは 2 回) 修正できるようにします。それでも応答を解析できない場合、またはエージェントが別の終了条件で停止した場合、ZZPH100​​ZZ が保存されます。

    from pydantic import BaseModel

from haystack.components.agents import Agent
from haystack.components.generators.chat import OpenAIResponsesChatGenerator
from haystack.dataclasses import ChatMessage
from haystack.hooks.structured_output import StructuredOutputHook


class CityInfo(BaseModel):
    city: str
    country: str


agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(generation_kwargs={"text_format": CityInfo}),
    state_schema={"structured_output": {"type": dict}},
    hooks={"on_exit": [StructuredOutputHook(schema=CityInfo)]},
)

result = agent.run(messages=[ChatMessage.from_user("Which city is the Eiffel Tower in?")])
print(result["structured_output"])
# {'city': 'Paris', 'country': 'France'}

  • DocumentJoiner は、ドキュメントの embedding フィールドと sparse_embedding フィールドを同じ ID で結合するための join_mode="merge_embeddings" をサポートするようになりました。これにより、密なドキュメント エンベッダーと疎なドキュメント エンベッダーを並行して実行し、その出力を DocumentWriter に渡す前に結合することができます。

  • エージェントの実行が max_agent_steps に近づいたときに残りのステップ数をモデルに伝える before_llm フックである StepBudgetReminderHook (実験的) を追加しました。最後の remind_within_steps LLM 呼び出しの前に、<system-reminder> タグでラップされたユーザー メッセージ (「10 ステップ中 2 ステップが残っています」など) が追加され、最後のステップで最終的な回答を求められます。これにより、エージェントは調査の途中で打ち切られることなく、終了することができます。

    from haystack.hooks.budget import StepBudgetReminderHook

agent = Agent(
    chat_generator=OpenAIChatGenerator(model="gpt-5.4-nano"),
    tools=[search],
    max_agent_steps=20,
    hooks={"before_llm": [StepBudgetReminderHook(remind_within_steps=3)]},
)

    リマインダー メッセージには meta={"system_reminder": True} のマークが付けられます。コンテキスト圧縮はマーカーを認識し、リマインダーをユーザーのタスクとして扱うことはありません。

⚡️ 機能強化に関するメモ

  • 欠落していた delete_by_filter_async() メソッドを InMemoryDocumentStore に追加しました。以前は、ストアの他のメソッドとは異なり、対応する非同期メソッドがあるのとは異なり、同期 delete_by_filter() のみが利用可能でした。新しいメソッドは、ストアのスレッド プール エグゼキュータで delete_by_filter() を実行し、削除されたドキュメントの数を返します。
  • デフォルトの modify_template または BlockingConfirmationStrategy は、ユーザーが変更されたツール呼び出しの結果を使用することを望んでおり、元の引数でツールを再度呼び出すべきではないことを LLM に指示するようになりました。前述の表現では、ユーザーがパラメータを変更した後、モデルは元のツール呼び出しを繰り返すことがよくありました。前のメッセージを保持するには、modify_template を明示的に渡します。
  • DocumentJoiner(join_mode="merge_embeddings") は、同じ ID を持つドキュメントを結合するときに、密埋め込みと疎埋め込みに加えて、マルチベクトル埋め込みをサポートするようになりました。
  • OpenAIChatGenerator には、コードの重複を減らしながら、サブクラスがコンポーネントの動作を簡単にカスタマイズできるようにするいくつかのメソッドが含まれるようになりました。
  • Document オブジェクトのディープ コピーとパイプライン入力が高速になり、以前と同じ結果が得られます。 Document は、要素ごとではなく 1 ステップで embedding リストをコピーする __deepcopy__ を実装するようになりました。 Pipeline は、コンポーネント入力をコピーするときに、他のオブジェクト用のより高価なチェックを実行せずに、文字列や数値などの不変の値を変更せずに返します。コンポーネント間で埋め込みまたは多くの埋め込みドキュメントを渡すパイプラインが最も効果的です。
  • EvaluationRunResult.comparative_detailed_report には、位置ではなく質問 ID や質問自体などの入力列によって 2 つの実行の行を照合するための新しい align_on パラメーターがあります。この比較は、同じ質問を異なる順序で評価した場合や、すべてが同じ質問でなかった場合でも、正しく実行されます。一致しない行は、他の実行のために None で保持されます。
  • HierarchicalDocumentSplitter は、新しい tokenizer_encoding パラメーター (デフォルトは "o200k_base") で設定されたエンコードを使用して、split_by="token" (pip install tiktoken が必要) をサポートするようになりました。新しい warm_up() メソッドは、最初の run() ではなく、前にトークナイザーを読み込みます。
  • PPTXToDocument は、以前はスキップされていたグループ化された図形や表からテキストを抽出するようになりました。テーブルはドキュメント コンテンツに CSV として含まれます。
  • OpenAIChatGenerator および OpenAIResponsesChatGenerator は、OpenAI API の拒否を ChatMessage.meta["refusal"] に保存するようになりました。アプリケーションはこのメタデータを検査して、拒否を検出して処理できます。
  • OpenAIResponsesChatGenerator は、連結された返信テキスト内の引用を見つけるために、整列された annotation_offsets とともにテキスト注釈を reply.meta["annotations"] に保存するようになりました。
  • tokenizer_encoding パラメーターを RecursiveDocumentSplitter に追加して、DocumentSplitter のように、split_unit="token" のときに使用される tiktoken エンコーディングを選択します。デフォルトは "o200k_base" で、これまで使用されていたエンコードです。チャンクがモデルのトークン制限に適合するように、モデルに一致するように設定します (たとえば、OpenAI の text-embedding-3 モデルの場合は "cl100k_base")。
  • RecursiveDocumentSplitter は、初期化時に split_unit を検証し、"word"、"char"、または "token" 以外の値に対して ValueError を生成するようになりました。後で run() 中に失敗するのではありません。
  • ChatMessage のシリアル化と OpenAI 形式の変換を簡素化し、可読性と保守性を向上させます。
  • フックは、たとえば state.get("max_agent_steps") を使用して、内部 max_agent_steps 状態キーからエージェントのステップ制限を読み取ることができるようになりました。これはエージェント出力として返されません。

🐛 バグ修正

  • 後の LLM 呼び出しで使用状況フィールドが null として報告されると、Agent が token_usage のトークン カウントを失う問題を修正しました。たとえば、ある呼び出しでは prompt_tokens_details が報告され、次の呼び出しでは null が報告されました。 null 値は報告されていないものとしてカウントされるようになり、合計は呼び出しの順序に依存しなくなります。

  • FilterRetriever、AutoMergingRetriever、SentenceWindowRetriever、CacheChecker、および DocumentWriter は、同期 API のみを実装するドキュメント ストアで動作するようになりました。 run_async メソッドは、ストアの非同期メソッドが存在する場合はそれを使用し、それ以外の場合は、欠落している非同期メソッドで失敗するのではなく、ワーカー スレッドで同期メソッドを実行します。

  • HierarchicalDocumentSplitter から取得したリーフの深さが異なる場合の AutoMergingRetriever.run() と run_async() を修正しました。浅いリーフは、より深いブランチから昇格された兄弟とマージされるようになり、親のマージの見逃しや、取得されたコンテキストでの親ドキュメントの重複が防止されます。

  • ComponentTool は、カスタム スキーマの追加プロパティや LLM によって追加された引数を含む、不明な呼び出し引数を KeyError を発生させる代わりに、警告とともにスキップするようになりました。不明なプロパティを持つカスタム スキーマも、構築中に警告を生成します。 ValueError は、inputs_from_state を通じて提供されない必須コンポーネント入力がカスタム スキーマで省略されている場合に発生します。自動的に挿入される State 入力は除外されます。これは、カスタム parameters スキーマで messages が省略され、inputs_from_state を通じて提供されない場合の AgentTool にも当てはまります。以前は、構築は成功しましたが、必要な入力が欠落しているため呼び出しは失敗していました。

  • ImageContent.from_dict、FileContent.from_dict、および TextContent.from_dict は、基本クラスの代わりに呼び出しクラスを構築するようになりました。そのため、サブクラスは to_dict / from_dict の往復でも存続します。これは ByteStream.from_dict の動作と一致します。

  • remove_regex が設定されている場合、正規表現が何も一致しないページであっても、DocumentCleaner が各ページの最初と最後のインデントと改行を削除する問題を修正しました。一致しないページは変更されないままになるため、remove_extra_whitespaces、remove_empty_lines、strip_whitespaces が無効な場合でもマークダウンとコードのコンテンツが保持されます。正規表現が一致するページは、以前と同様に削除されます。

  • weights に NaN または無限値が含まれる場合、DocumentJoiner は ValueError を生成するようになりました。以前は、merge および reciprocal_rank_fusion 結合モードではこれらの値が受け入れられ、ドキュメント スコアが NaN に変換されていました。

  • DOCXToDocument は、追跡された挿入、移動されたテキスト、スマート タグ、カスタム XML、単純なフィールド、または入力されたインライン コンテンツ コントロール内に段落が保持しているテキストを読み取るようになりました。以前は、段落の直接ランとハイパーリンクのみが読み取られたため、受け入れられない変更履歴のある文書では、挿入されたすべての単語が失われ、入力されたフォーム フィールドの値も失われていました。削除されたテキスト、移動されたテキストの古い場所、およびプレースホルダー プロンプトがまだ表示されているコンテンツ コントロールは、ドキュメントに表示されないため、除外されます。

  • DocumentRecallEvaluator および DocumentNDCGEvaluator は、TypeError を生成する代わりに、document_comparison_field のリストおよび辞書メタデータ値をサポートするようになりました。ネストされた値がサポートされており、重複したドキュメントでは既存の再現率と関連性のスコアリング動作が保持されます。

  • meta がファイル パスと一緒に渡された場合、FileTypeRouter は検出された MIME タイプを失わなくなりました。

  • マージしきい値を評価するときに重複する子ドキュメントを誤ってカウントする AutoMergingRetriever を修正しました。ドキュメントは結合前に ID によって重複排除されるようになり、同期取得と非同期取得の両方で最高スコアのコピーが保持されます。

  • Windows 上のテキスト結果の行末を変更する FileSystemToolResultStore を修正しました。

  • Pipeline.connect は、出力の各メンバーが入力のメンバーに任意の順序で適合する場合、Union 入力に接続された Union 出力を受け入れるようになりました。たとえば、str | None は str | int | None に接続し、list[Path | ByteStream] は TextFileToDocument などのコンバータの list[str | Path | ByteStream] 入力に接続します。以前はポジション別にメンバーを比較していましたが、これらのつながりでPipelineConnectErrorが上がりました。 Literal タイプは同じ方法で照合されます。Literal["b", "c"] は Literal["a", "b", "c"] に接続されます。

  • OpenAIDocumentEmbedder および AzureOpenAIDocumentEmbedder は、コンポーネントの作成時に batch_size をチェックし、それが 0、-1、または 0.5 (たとえば、ValueError: batch_size must be a positive integer, but got 0) などの正の整数でない場合に ValueError を生成するようになりました。この修正が行われる前は、無効な batch_size がエラーなしで受け入れられました。この問題は、その後、run または run_async が呼び出されたときにのみ発生し、batch_size について言及していない ValueError: n must be at least one などのエラーが発生しました。

  • MultiRetriever、MultiQueryTextRetriever、MultiQueryEmbeddingRetriever、LLMMetadataExtractor、および LLMDocumentContentExtractor は、max_workers が 1 より小さい場合、初期化時に ValueError を生成するようになりました。以前は無効な値が受け入れられていましたが、run は後で ThreadPoolExecutor 内で失敗し、run_async はそれを黙って 1 として扱いました。
