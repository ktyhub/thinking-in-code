DeepTutor v1.3.2

パッチ 公開日2026年4月29日 出典HKUDS/DeepTutor 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディープチューター v1.3.2 #ディープチューター v1.3.2 Release Notes 発売日: 2026.04.29 v1.3.2 は、v1.3.1 の後に安定性を重視したリリースです。埋め込みを引き締めます エンドポイント コントラクトにより、LlamaIndex RAG が古い状態または古い状態からよりきれいに回復されます。 無効なインデックスを削除し、推論モデルのスクラッチパッド出力の漏洩を防ぎます。 長期記憶に。

ハイライト

透過的な埋め込みエンドポイント URL

埋め込み設定では、DeepTutor が呼び出す正確な URL が明示的に示されるようになりました。 これにより、「ベース URL とエンドポイント URL」の隠れたあいまいさが解消され、 成功した設定テストは、ナレッジベースの再インデックスとは異なる動作をします。

  • 設定に埋め込み用のエンドポイント URL が表示されるようになりました - Web 設定ページ 埋め込み URL をエンドポイント URL としてラベル付けし、DeepTutor が次の宛先に投稿することを説明します。 /embeddings または /api/embed を追加せずに、表示される URL を正確に指定します。 リクエストタイム。
  • プロバイダーのデフォルトは完全なエンドポイントです - OpenAI、OpenRouter、Jina、vLLM/LM Studio および SiliconFlow のデフォルトは /embeddings です。オラマのデフォルトは /api/embed; Cohere のデフォルトは /embed です。 DashScope はネイティブを維持します マルチモーダル埋め込みエンドポイント。
  • 従来のベース URL は安全に移行されます - を使用して保存された埋め込みプロファイル https://api.openai.com/v1などのオールドスタイルベース、 https://openrouter.ai/api/v1 または http://localhost:11434 は次のように正規化されます。 完全なエンドポイント フォームがモデル カタログに保持されます。カスタム OpenAI 互換の URL はそのまま残されます。
  • 設定が間違っているエンドポイントは早期に失敗します - 埋め込み client は拒否されるようになりました 実際のパスではなくルート/ベース パスを指す既知のプロバイダー URL インデックス作成を開始する前に、アクション可能なメッセージを含むエンドポイントを埋め込みます。
  • OpenRouter 埋め込みは正確な URL HTTP を使用します - パブリック埋め込みプロバイダーはいいえ OpenAI SDK の非表示のパス追加動作による長いルート。 custom_openai_sdk はレガシー構成で引き続き使用できますが、非表示になります。 [設定プロバイダー] ドロップダウン。
  • 接続テスト診断はランタイム動作と一致します - テストを今すぐ埋め込みます アダプターの動作と一致する「設定に示されているとおりに正確に POST されました」とレポートします。 RAG のインデックス作成と検索で使用されます。

RAG の再インデックスと取得の回復力

LlamaIndex パイプラインは、埋め込み状態をより積極的に更新するようになりました。 無効な永続ベクトルを生の代わりに明確な再インデックス ガイダンスに変換します。 Python または NumPy エラー。

  • キャッシュされたパイプラインが設定の変更を取得 - 初期化、検索、 インクリメンタル追加パスは使用前に LlamaIndex を再構成するため、長寿命です。 パイプラインはモデル、ディメンション、またはエンドポイント設定の埋め込みを維持しません。 古い設定セッション。
  • 構成が変更されると埋め込み clients が更新されます - 共有埋め込み client は、解決されたランタイム構成が変更されると再作成され、 LlamaIndex CustomEmbedding アダプターは、アクティブな構成を事前にフィンガープリントします。 キャッシュされた client を再利用します。
  • 永続的なインデックス ベクトルは取得前に検証されます - LlamaIndex storage は、保存されたベクトル ストアを null、非数値、非有限かどうかチェックするようになりました。 類似性検索を実行する前に、削除されたベクトル、または矛盾したベクトルを削除します。
  • 無効なインデックスは再インデックスのヒントを返します - 次のような既知のエラー unsupported operand type(s) for *: 'NoneType' and 'float'、ベクトル形状 不一致が発生し、新たに検出された無効な永続ベクトルが返されるようになりました。 needs_reindex: true にはユーザー向けの説明が付いています。
  • 埋め込み接続チェックでは同じ検証パスが使用されます - インデックス前のスモーク テストは、同じバッチ バリデーターを使用してプロバイダーの出力を検証します。 インデックス作成と検索の際に使用されます。
  • 修正が知られている場合、RAG エラー ログは静かになります - 無効に分類されました 埋め込み/インデックスの失敗は、ノイズの代わりに実用的な警告として記録されます。 完全なトレースバック。

思考モデルのためのメモリのクリーンアップ

メモリのリフレッシュにより、プライベートな推論ブロックが削除される前に削除されるようになりました。 耐久性のあるユーザーメモリ。

  • 思考タグは書き込み前に削除されます - プロファイルと概要の書き換えが実行されます コードフェンスのクリーンアップ後に共有 clean_thinking_tags() ヘルパーを使用するため、 推論モデルの <think> / <thinking> ブロックは、 PROFILE.md または SUMMARY.md。
  • 既存のメモリ ファイルは読み取り時に自己修復します - 古いメモリ ファイルの場合 すでに閉じられたまたは閉じられていない思考タグが含まれており、スナップショットを読み取るとクリーンになります コンテンツを削除し、可能な場合は修復されたバージョンをディスクに書き込みます。
  • 手動メモリ編集は同じクリーンアップを使用します - 直接メモリ書き込みもパスします クリーナーを通じて、UI の編集、更新、ランタイム読み取りの調整を維持します。

設定とランタイムの洗練

  • 埋め込みプロバイダーの選択により混乱が少なくなります - 設定は提供されなくなりました 既存のパブリック ドロップダウンの従来の custom_openai_sdk プロバイダー 保存されたプロファイルは、下位互換性のために引き続き解決されます。
  • モデル カタログの正規化は永続化されます - カタログのロードは次の場合に保存されるようになりました。 正規化により、アクティブなプロファイル/モデル ID または埋め込みエンドポイント URL が変更されます。 起動するたびに同じ移行が繰り返されるのを防ぎます。
  • OpenAI 互換の埋め込みエラーがより明確になります - 非 JSON または HTML 埋め込み応答は、間違ったエンドポイント/モデルのペアを指すようになりました。 ゲートウェイ固有の原因を 1 つだけ誤って示唆しています。
  • Deep Solve ReAct 呼び出しが再び調整されます - ソルバー ループはなくなりました 古い attachments キーワードを SolverAgent.process() に渡し、 プランナーで添付ファイルの転送を維持しながらランタイム TypeError を実行し、 サポートされている場合は通話を再計画してください。

テスト

  • OpenAI、OpenRouter、Ollama、およびカスタムのエンドポイント移行カバレッジを追加しました プロファイルの埋め込み。
  • 完全なエンドポイント プロバイダーの選択と非表示のための設定 API カバレッジを追加しました custom_openai_sdk。
  • エンドポイント検証、OpenRouter の raw HTTP 用の埋め込み client カバレッジを追加しました アダプター パス、構成変更時の client 更新、および正確な URL の透過性。
  • 古い埋め込みに対する LlamaIndex カバレッジを追加 - client リフレッシュ、繰り返し 設定の再構成、無効な永続ベクトルの検出、およびインデックスの再作成 無効なインデックスのヒント。
  • 閉じられた思考タグと閉じられていない思考タグのメモリ カバレッジを追加し、さらに修復 読み取り中の既存のメモリ ファイル。
  • ソルバーのランタイム配線を対象とした、対象を絞ったディープソルブ/RAG 機能テストを実行 古い attachments 引数の修正後。

アップグレードに関する注意事項

  • 設定での埋め込み URL は完全なエンドポイント URL になるはずです。既存の既知の プロバイダー プロファイルは自動的に移行されますが、カスタム ゲートウェイは移行する必要があります。 標準以外のパスを使用している場合は手動で確認します。
  • ナレッジ ベースの検索でまだ無効な埋め込みベクトルが報告される場合は、インデックスを再作成します。 アクティブな埋め込みプロバイダー、モデル、ディメンションを確認した後、影響を受ける KB およびエンドポイント URL。
  • 古い <think> ブロックを含むメモリ ファイルは、次回の実行時に消去されます。 メモリ ページまたはメモリ サービスがそれらを読み取ります。この読み取りにより、基礎となるものが更新される可能性があります PROFILE.md または SUMMARY.md ファイルを使用して、クリーンアップされたバージョンを永続化します。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.3.1...v1.3.2
