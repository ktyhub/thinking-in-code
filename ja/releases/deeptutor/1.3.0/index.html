#ディープチューターv1.3.0 #ディープチューター v1.3.0 Release Notes 発売日: 2026.04.27

ハイライト

バージョン管理されたナレッジベースのインデックスと再インデックスのワークフロー

ナレッジ ベースでは、1 つの llamaindex_storage/ ディレクトリを全体の真実として扱うのではなく、埋め込み構成ごとにベクトル インデックスを保持するようになりました。新しいインデックス バージョンごとに埋め込み署名とメタデータが記録されるため、モデルを切り替えると以前のインデックスを上書きする必要がなくなり、切り替えて元に戻すと、署名が一致したときに準備済みのバージョンを再利用できます。

  • バージョン管理されたストレージ レイアウト - 新しいインデックスは、meta.json を持つフラットな version-N/ ディレクトリとして書き込まれます。従来のルートおよびネストされた llamaindex_storage レイアウトは、既存のインストールで引き続き読み取り可能です。
  • 埋め込み対応の読み取りと書き込み - RAG 検索、ドキュメントの追加、マネージャー統計、および削除/クリーンアップ パスは、アクティブな埋め込み署名を通じてストレージを解決するようになりました。現在の埋め込みモデルと一致する準備済みバージョンがない場合、取得は後で不透明なストレージ エラーで失敗するのではなく、クリアな needs_reindex 信号を返します。
  • バックグラウンドでのインデックス再作成 API - POST /api/v1/knowledge/{kb_name}/reindex は、アクティブな埋め込み構成に対して KB を再構築し、既存のタスク チャネルを通じてログをストリーミングし、一致する準備完了インデックスが既に存在する場合に noop: true を返します。
  • インデックス ステータスが UI に表示 — KB 概要には、インデックス バージョン メタデータ、アクティブ一致状態、埋め込み不一致フラグ、進行状況、および再インデックスの準備状況が含まれるようになり、フロントエンドが KB の再構築が必要な理由を説明できるようになりました。

ナレッジ管理ページの再構築

ナレッジ ページは、モノリシック画面から、日常の KB 操作に特化したマスター/詳細ワークスペースに分割されました。

  • 専用の KB 詳細タブ - ファイル、ドキュメントの追加、インデックス バージョン、設定が、プロバイダー、埋め込みモデル、デフォルト ステータス、更新時間、ライブ タスク ステータスを示すコンパクトなヘッダーを備えた個別のセクションとして表示されるようになりました。
  • 未加工ファイル ブラウザとインライン プレビュー - 新しい [ファイル] タブには、KB raw/ ディレクトリのドキュメントが一覧表示され、インライン プレビュー ペインで開きます。これにより、PDF、画像、Markdown、コード/テキスト、およびフォールバック ダウンロードのチャット プレビュー パイプラインが再利用されます。ファイル リストを折りたたんで、プレビュー スペースを再利用できます。
  • コントロールとログの再インデックス - [インデックス バージョン] セクションには、アクティブなバージョン、古いバージョン、レガシー バージョン、および非アクティブなバージョンが表示され、1 つの click 再インデックス アクションと再構築タスクのライブ プロセス ログが表示されます。
  • 進行状況および履歴フック - useKnowledgeBases、useKnowledgeProgress、および useKnowledgeHistory は、サーバーの状態をライブ WebSocket/SSE の進行状況とマージし、アクティブな作業を自動更新し、最近の作成/アップロード/再インデックスの結果を表示したままにします。

埋め込みランタイム、プロバイダー カバレッジ、およびディメンション検出

埋め込みスタックは、すべてのサービスが OpenAI のデフォルト エンドポイントのように動作することを前提とするのではなく、プロバイダー固有の動作を中心に強化されました。

  • ハードコーディングされた 3072 デフォルトはもうありません — 埋め込みディメンションは不明/空として開始され、テスト接続が成功した後にプロバイダーの応答から自動入力されるようになりました。テスト プローブは dimensions の送信を意図的に回避するため、マトリョーシカの切り詰めの前にモデルのネイティブ ベクトルの長さを測定します。
  • 完全なエンドポイント URL セマンティクス - httpx ベースの埋め込みアダプターは、呼び出す正確なエンドポイントとして EMBEDDING_HOST / カタログ URL を扱うようになりましたが、新しい openai_sdk アダプターは SDK スタイルの /v1 ベース URL の動作を維持します。 .env.example には、OpenAI、Cohere、Jina、Ollama、SiliconFlow、Aliyun DashScope の具体的なエンドポイントの例が文書化されています。
  • 新しい埋め込みアダプターとバインディング - 公式 OpenAI SDK 埋め込みサポート、Aliyun DashScope ネイティブ マルチモーダル埋め込み、SiliconFlow プリセット、OpenRouter/カスタム OpenAI-SDK プロファイル、プロバイダーのバッチ制限、マルチモーダル プロバイダー フラグ、およびプロバイダーごとの API キー フォールバックを追加しました。
  • マルチモーダル埋め込みリクエスト — EmbeddingRequest は、構造化 contents と DashScope enable_fusion を受け入れるようになりました。 Cohere v2、Jina、OpenAI 互換ゲートウェイ、および DashScope は、独自のアダプター ルールを通じてマルチモーダル ペイロードを処理します。
  • プロバイダー エラーの改善 — 埋め込みエラーではプロバイダーのステータス、本文、モデル、URL コンテキストが保存されるようになり、4xx 応答と非 JSON/HTML ゲートウェイ応答がより明確に処理されます。

LLM 推論ストリームとビジョン アタッチメントの堅牢性

推論トレースと画像添付ファイルは、プロバイダー固有の驚きが少なくなり、より多くのプロバイダー パスを経由するようになりました。

  • 推論デルタ — on_reasoning_delta は、基本 LLM プロバイダー契約、OpenAI 互換ストリーミング、Azure SDK ストリーミング、Anthropic パス、および OpenAI Responses 解析を通じて接続されます。ストリーミング出力では、通常のコンテンツが再開される前に、推論テキストが <think>...</think> でラップされます。
  • DeepSeek 推論のデフォルト — DeepSeek 推論モデル パターンは、呼び出し元が思考出力を表面化するために明示的な切り替えを必要とするプロバイダーを指定していない場合に、高い推論労力を自動的に注入できます。
  • ビジョン URL 機能フラグ — プロバイダー/モデル機能は、「ビジョンをサポートする」ことと「イメージ URL を受け入れる」ことを区別するようになりました。 Moonshot/Kimi ビジョン モデルと Anthropic スタイルのアダプターは、可能な場合、ローカルの添付ファイル URL をインライン Base64 に強制します。
  • ローカル添付ファイル URL 解決 - /api/attachments/... 画像 URL は添付ファイル ストアを通じて解決され、リモート URL フォームを拒否するプロバイダーに Base64 として送信されます。未解決の外部 URL は、送信されたかのように振る舞うのではなく、ドロップされた画像入力としてカウントされます。

スペース ハブ、スキル タグ、パーソナル ライブラリの UX

個人的な学習成果物は、サイドバーの新しい スペース エリアに集められています。

  • スペース ナビゲーション - /space は、/space/notebooks と、共有セクション ヘッダー スタイルを持つ新しいミニ ナビゲーション グループの Notebooks、Question Bank、Skills、および Memory にリダイレクトします。
  • ノートブック セクション - レンダリングされたレコード プレビューを使用して、ノートブックを作成、削除、検索、開き、検査することができます。保存された TutorBot、チャット、リサーチ、共同ライターの出力には個別のバッジが付けられ、メタデータが利用可能な場合は元のチャット セッションにリンクバックできます。
  • 質問バンク セクション — クイズのエントリは、すべて/ブックマーク/間違ったもののみでフィルタリングしたり、カテゴリでグループ化したり、名前を変更したり、カテゴリから削除したり、ブックマークしたり、削除したり、ソース コンテキストで開いたりすることができます。
  • メモリ セクション - メモリ ページは、概要とプロファイルの編集/プレビュー モード、手動保存、セッションからの更新、アクションのクリア、未保存の変更ステータス、およびローカライズされたフィードバックを備えたスペースに移動します。
  • スキル セクション - ユーザーが作成したスキルは、フロントマターのタグと .tags.json 語彙をサポートするようになりました。 API では、タグのリスト/作成/名前変更/削除エンドポイントが追加され、UI では既存の SKILL.md ワークフローを維持しながら、タグによるフィルタリング、タグの管理、スキル名の変更、タグ割り当ての編集が可能です。

依存関係レイヤー、TutorBot のデバッグ、および Windows の起動

インストールのストーリーは pyproject の追加機能を中心に再編成され、要件ファイルは Docker/CI 環境のミラーとして保持されます。これにより、TutorBot のセットアップとチャネルのデバッグも曖昧さがなくなりました。エージェント エンジン、チャネル SDK、Matrix のネイティブ依存関係、およびコア サーバー プロバイダーのインポートは、明確に分離されたレイヤーに存在するようになりました。

  • エクストラ階層 - .[cli] には、RAG、ドキュメント解析、および組み込みプロバイダー SDK が含まれるようになりました。 .[server] は、FastAPI/uvicorn を使用した CLI をベースに構築されています。 .[tutorbot]、.[matrix]、.[math-animator]、.[dev]、および .[all] は、オプション機能を明示的に階層化します。
  • TutorBot の依存関係の境界 — requirements/tutorbot.txt は .[tutorbot] をミラーリングし、server.txt に依存し、cron、MCP、Telegram、Feishu/Lark、DingTalk、Slack、QQ、Socket.IO、socks、メッセージ パック ツールなどのチャネル/エージェントの依存関係を、基本インストールに混合するのではなく、TutorBot レイヤーに保持します。
  • マトリックス チャネルの分割 — マトリックス/要素のサポートには、独自の .[matrix] エクストラと requirements/matrix.txt、matrix-nio[e2e]、マークダウン サニタイズ ヘルパー、およびネイティブ暗号化依存関係用の明示的な libolm セットアップ ノートがあります。
  • ランタイム依存関係の修正 (#391) — loguru および json-repair は、TutorBot が関与する前にプロバイダーコアのインポートで必要となるため、サーバー依存関係レイヤーに移動されました。これにより、モジュールが不足していると以前にクラッシュしたサーバーのクリーン インストールが修正されます。
  • Windows ランチャーの堅牢性 (#391、#398) — scripts/start_web.py はバックエンド/フロントエンドのサブプロセス出力を置換付きの UTF-8 として読み取り、GBK などの Windows ロケールでの UnicodeDecodeError を回避するようになりました。
  • ドキュメントと CLI ヒント - README、中国語 README、CLI README、および CLI エラー メッセージは、古い要件優先コマンドではなく pip install -e ".[cli]" / pip install -e ".[server]" をユーザーに示すようになりました。新しい requirements/matrix.txt は、Matrix エクストラを反映し、ネイティブ libolm の前提条件を文書化します。

バグ修正

  • ナレッジのアップロード/作成診断 (#392、#405) - KB の初期化、アップロード、およびインデックスの再作成のタスクは、タスク ログを通じて障害の詳細とスタック トレースを伝達するようになりました。バックグラウンドでの取り込みが失敗した場合、UI は何も実行していないように見えるのではなく、より豊富なエラーを表示できます。
  • KB 名の検証 - HTTP および CLI 作成パスは、Unicode 対応の名前を維持しながら、パスのような文字または URL で予約された文字を拒否するようになり、無効な KB フォルダーや安全でないルートを防ぎます。
  • 大文字と小文字を区別しないドキュメント検出 - KB ディレクトリ スキャンと CLI ドキュメント コレクションでは共有ファイル ルーターが使用されるようになり、.PDF や .MD などの大文字の拡張子が一貫して受け入れられます。
  • より安全なドキュメント ファイル名 - アップロードされたファイル名は正規化され、パスのフラグメントが削除され、拡張子が小文字化されてから検証および保存されます。
  • Raw ファイル サービスの安全性 - KB RAW ファイル エンドポイントは、厳密に raw/ ディレクトリの下でパスを解決し、トラバーサルの試行を拒否します。
  • モデル カタログ環境オーバーレイ - .env 値は、見た目がまだきれいな状態でのみカタログに同期され、ユーザーが複数のカスタム プロファイルを持っている場合に誤って上書きされるのを防ぎます。
  • リサーチ レポート フォールバック (#404) - レポート エージェントの JSON フォールバック警告では f 文字列が使用されるようになり、% 形式を適用しないロガーでもセクション タイトルがきれいに含まれます。

テストスイートの拡張

  • ナレッジ/RAG - KB の命名、インデックス バージョンの割り当てと読み取り優先順位、レガシー ストレージとフラット ストレージの互換性、LlamaIndex ストレージ レイアウト、RAW ディレクトリの初期化、大文字と小文字を区別しないファイル ルーティング、KB 削除、および API アップロード エッジ ケースを新たにカバーします。
  • 埋め込み/構成 - 新しいテストは、テスト プローブからのディメンションの自動入力、カタログ .env オーバーレイ動作、DashScope および OpenAI SDK アダプター、Qwen3 send_dimensions、URL 透過性、非 JSON プロバイダー応答、およびマルチモーダル埋め込みリクエストをカバーします。
  • LLM/マルチモーダル - 新しいテストは、インライン Base64 イメージを必要とするプロバイダーの推論/ビジョン機能の動作とローカル添付ファイル URL 変換を検証します。
  • CLI と検証 - CLI KB コレクションとドキュメント検証テストでは、大文字の拡張子、中国語のファイル名、Windows スタイルのパス ストリップがカバーされます。
