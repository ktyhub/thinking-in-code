#ディープチューター v1.2.3

ディープチューター v1.2.3 Release Notes

発売日: 2026.04.24

ハイライト

チャットでの文書添付

チャットでは、画像とともに非画像ファイルの添付ファイル (PDF、DOCX、XLSX、PPTX) を受け入れるようになりました。コンポーザーの新しい Paperclip ボタンによりシステム ファイル ピッカーが開き、ドラッグ アンド ドロップ/貼り付けが画像のみからサポートされているすべてのドキュメント タイプに拡張されました。添付ドキュメントは、保留中の添付ファイル バーとメッセージ履歴の両方で、入力されたプレビュー カード (色分けされたアイコン + ファイル名 + サイズ ラベル) として表示されます。バックエンドでは、新しい document_extractor モジュールが PyMuPDF / pypdf / python-docx / openpyxl / python-pptx (すべてオプション、グレースフル フォールバック) を使用してアップロードされたバイトからプレーン テキストを抽出し、その内容を有効なユーザー メッセージの [Attached Documents] セクションに挿入するため、LLM は別の RAG 呼び出しなしでファイルを読み取ることができます。ファイル タイプの分類、ファイルごとおよび合計サイズの制限、および重複名の検出は、フロントエンドの web/lib/doc-attachments.ts とバックエンドの DocumentValidator によって処理されます。

モデル思考ブロックの表示

推論モデル (DeepSeek-R1、拡張思考を備えた Claude、QwQ など) からの応答には、生のテキストとして以前にレンダリングされた <think> / <|thinking|> スクラッチパッド ブロックが含まれることがよくあります。新しい parseModelThinkingSegments パーサー (web/lib/think-segments.ts) は、アシスタントのコンテンツを交互のテキスト セグメントと思考セグメントに分割し、AssistantResponse は各思考セグメントを折りたたみ可能な ModelThinkingCard (デフォルトでは折りたたまれています) としてレンダリングするようになりました。そのため、ユーザーはスクラッチパッドが会話を圧倒することなく、モデルの思考の連鎖を覗くことができます。不完全な (まだストリーミング中の) 思考ブロックはパルス状のインジケーターを表示し、自動的に拡張されます。

埋め込み用トライステート send_dimensions (#368)

一部の OpenAI 互換埋め込みプロバイダーは、OpenAI の text-embedding-3-* モデルに必要な dimensions パラメーターを拒否します。 2 つの部分からなる修正: まず、アダプターは、モデル名が text-embedding-3* と一致する場合にのみ dimensions を送信するようになりました (@jefflv による PR #368)。次に、新しい 寸法の送信 トライステート トグル (自動 / オン / オフ) が設定ページ、.env ストア (EMBEDDING_SEND_DIMENSIONS)、およびモデル カタログに追加され、オペレーターが明示的に制御できるようになりました。 Auto (デフォルト) は #368 ヒューリスティックを保持します。 On は、カスタム モデルでそれを受け入れるプロバイダーにパラメーターを強制します。 Off は無条件に抑制します。トグルはエンドツーエンドで反映されます: カタログ → provider_runtime.ResolvedEmbeddingConfig.send_dimensions → OpenAICompatibleEmbeddingAdapter。

LLM プロバイダーコアのリファクタリング

モノリシック factory.py は、新しい provider_core/ パッケージ (約 3,000 行) を中心に書き直され、各プロバイダー ファミリに独自のモジュール (openai_compat_provider、anthropic_provider、azure_openai_provider、github_copilot_provider、および openai_codex_provider) を提供します。これらはすべて共有 BaseProvider から継承しています。 provider_factory.py は構成から正しいランタイム プロバイダーを解決し、ハードコードされた辞書を維持する代わりに PROVIDERS レジストリからプリセットを動的に導出することにより、factory.py 自体は約 600 行から約 490 行に縮小されました。新しい context_window.py モジュールは、resolve_effective_context_window() を公開します。resolve_effective_context_window() は、max_tokens 出力上限ではなく、モデルの真のコンテキスト ウィンドウに基づいて履歴バジェット計算を行うために ContextBuilder によって使用され、ウィンドウが大きいモデルの長時間の会話履歴の再現を向上させます。

ソウルテンプレートエディター (PR #373)

TutorBot の「ソウル」（システム パーソナリティ）をエージェント ページ内で直接作成できるようになりました。新しいインライン エディターを使用すると、ユーザーは YAML フロントマターを使用して SOUL.md テンプレートを作成、プレビュー、保存できるようになり、ディスク上のファイルを手動で編集する以前のワークフローが置き換えられます。 @srinivasrk による投稿。

共同執筆者 ノートブックに保存

Co-Writer ツールバーに ノートブックに保存 ボタン (📓 アイコン) が追加されました。 Cliこれをチェックすると、新しい co_writer レコード タイプを持つ既存の SaveToNotebookModal が開き、ナレッジ ページの [ノートブック] タブで共同執筆者のドラフトがチャットやクイズのエントリと並んで表示されます。バックエンド: co_writer が、ノートブック レコード タイプ列挙型、要約エージェント プロンプト、および API リテラル タイプに追加されました。

ナレッジベース管理の改善

  • ドラッグ アンド ドロップ アップロード - ナレッジ ページでは、リアルタイムの拡張子/サイズ検証、重複名の検出、アップロード開始前の入力されたファイル選択リストを使用して、KB カード (または作成フォーム) へのファイル ドロップを直接受け入れるようになりました。
  • /supported-file-types エンドポイント - 新しい REST エンドポイントはサーバーの現在のアップロード ポリシー (受け入れられる拡張子、ファイルごとおよび PDF ごとのサイズ制限) を返すため、Web client はハードコーディングなしで同期を保ちます。
  • 豊富な KB カード — 各カードには、作成/最終更新タイムスタンプ、埋め込みモデル名、ディメンション、再インデックスが必要なバッジ、およびインデックス作成中のパーセント読み出し付きライブ進行状況バーが表示されるようになりました。
  • 復元力の削除 (#370) - shutil.rmtree は、読み取り専用ビットをクリアして再試行する onerror ハンドラーを使用するようになり、Docker バインド マウント エラーや Windows 権限エラーによって KB がリストに残るのを防ぎます。
  • 進行状況の永続性 - ProgressTracker は、kb_config.json エントリと一緒にスナップショット ファイルを書き込み、タスク ストリーム イベントを発行するようになりました。そのため、WebSocket サブスクライバーとページのリロードは、メモリ内コールバックに依存せずにライブ インデックス作成状態を回復できます。 KB が ready に達すると、カードが安定したリソースのように見えるように、進行状況 BLOB が構成から削除されます。

質問生成言語の忠実度

言語指示システムをブック エンジンの _language.py から共有 services/prompt/language.py モジュールに抽出しました。 Deep Question エージェント (Generator、IdeaAgent、および FollowupAgent) は、システム プロンプトで append_language_directive() を呼び出すようになり、クイズの質問、回答の選択肢、およびフォローアップの回答が、場合によっては英語になるのではなく、ユーザーの設定言語を尊重するようになりました。

設定ページツアーの再設計

ツアーの実行 ボタンがページの下部から上部のツールバーに移動し、下書きの保存 および 適用 と並んで配置されました。ガイド付きツアー自体は、完全な保存とテストのサイクル (保存→診断→適用) を実行できるように拡張されました。以前の下部領域は、.env に対する model_catalog.json の実行時の優先順位を説明する簡潔な構成メモに置き換えられました。

CLI: ノートブック add-md および replace-md

2 つの新しい deeptutor notebook サブコマンドを使用すると、ユーザーはノートブック レコード内の Markdown コンテンツを端末から直接追加または置換できるため、スクリプト化されたワークフローや CI パイプラインに役立ちます。

バグ修正

  • TutorBot の純粋な CJK ボット名のクラッシュ — 名前に非 ASCII 文字のみが含まれるボットを作成すると、空のスラッグが生成され、API ルートが中断されました。安定した ASCII フォールバック (bot-<hash>) が生成されるようになり、フロントエンドはサイレントに失敗するのではなく、作成エラー トーストを表示します。
  • React 19 I18nProvider レンダリング時の setState 警告 — i18n.init() は、I18nProvider の最初のレンダリング中に同期的に呼び出され、レンダリング フェーズでの状態更新に関する React 19 警告がトリガーされました。初期化はモジュールのロード時に実行されるようになりました。プロバイダー本体は、useEffect を介して document.documentElement.lang のみを同期します。
  • スキルのデフォルトはオフ — skillsAutoMode のデフォルトは false になり、新規ユーザーは意図的に有効にするまで自動スキル挿入に驚かなくなります。
  • ムーンショットのデフォルトのベース URL — プロバイダーの現在の正規エンドポイントに一致するように https://api.moonshot.ai/v1 から https://api.moonshot.cn/v1 に変更され、すべての多言語 README ファイルが更新されました。
  • バージョン バッジの表示 — v1.2.2 のマージ中に発生したサイドバーのバージョン バッジの小さなレンダリングの問題を修正しました。

プロバイダー レジストリの機能強化

  • custom_anthropic — OpenAI-compat ではなく Anthropic バックエンドを介してルーティングする Anthropic-API 互換エンドポイント (AWS Bedrock プロキシなど) の新しいプロバイダー仕様。
  • thinking_style — 新しい ProviderSpec フィールドにより、Volcengine などのプロバイダーが拡張思考モードを通知する方法を宣伝できるようになります。
  • エイリアスの拡張 — lm-studio、anthropic-compatible、openai-compatible (ハイフン付き) が認識されるようになりました。 canonical_provider_name() は、より堅牢な正規化のために to_snake() を使用します。

テストスイートの拡張

15 個の新規または拡張ファイルにわたる正味 +1 900 テスト行: test_document_extractor.py (245)、test_language_prompts.py (156)、think-segments.test.ts (122)、test_provider_runtime.py (103)、test_llm_probe_config.py (116)、test_manager_delete.py (79)、doc-attachments.test.ts (75)、test_context_window_detection.py (60)、 test_progress_tracker.py (58)、quiz-question-type.test.ts (58)、さらに test_factory_provider_exec.py、test_context_builder.py、test_chat_params_config.py、test_config_module.py、test_knowledge_router.py、test_start_tour.py への拡張。
