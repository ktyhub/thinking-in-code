DeepTutor v1.5.9

パッチ 公開日2026年8月4日 出典HKUDS/DeepTutor 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディープチューター v1.5.9 #ディープチューター v1.5.9 Release Notes 発売日: 2026.08.04 v1.5.8 がメモリに関するものであったのに対し、これはプロバイダー (Gemini のネイティブ Embedding 2 エンドポイント、モデルごとの推論エフォート コントロール、Novita AI ゲートウェイ) と、その下にひそかに間違っていたパスについてのものです。つまり、ドキュメントであるかのように埋め込まれたクエリ、思考をオンにする none、空白のメッセージとして届く機能クラッシュなどです。ほとんどのインストールではドロップインですが、docker-compose.ghcr.yml ユーザーは次回の up の前に 1 回限りのデータ移行を実行できます。

新機能

ネイティブ API に対する Gemini Embedding 2

Gemini 埋め込みプロファイルは、x-goog-api-key で認証された gemini-embedding-2 を持つ Google のネイティブ …/models/<model>:batchEmbedContents エンドポイントにデフォルト設定され、エンドポイントは、ゲートウェイ プレフィックスを含む、選択したモデルに従います。既存の gemini-embedding-001 プロファイルは意図的に OpenAI 互換パス上に留まります。ネイティブ ルートは taskType を送信し、戻ってくるものを L2 正規化するため、プロファイルを移動するとドキュメント ベクトルが変更され、そこから構築されたインデックスが暗黙的に無効になります。 base_url にネイティブ URL を指定して、任意のモデルをオプトインします。

クエリはドキュメントとして埋め込まれなくなります

検索埋め込みがその役割を担うようになりました。 LlamaIndex タグはクエリ search_query とパッセージ search_document にタグ付けされ、LightRAG は独自のコンテキスト ヒントを同じ方法でマップし、アダプターは明示的にオプトイン (SUPPORTS_INPUT_TYPE) するため、ロールを送信したことのないバックエンドはロールを送信し続けます。 Cohere (フィールドが必要で、すでにデフォルトで search_document に設定されている) のみが今日変更されます。ドキュメント ベクトルは変更されず、クエリは最終的に適切な役割を獲得します。再インデックスはありません。

モデルごとの推論-労力セレクター

カタログ内の各 LLM モデルは、そのコンテキスト ウィンドウの横にオプションのデフォルト推論深度を取得します。これは、プロバイダーが実際に推論深度をサポートしている場合にのみ提供され、そのプロバイダー独自のボキャブラリーでラベル付けされます (OpenAI スタイル ファミリの場合は最小/低/中/高/x高、それが唯一のオンモードである場合は適応、残りは単純なオン/オフ)。 プロバイダーのデフォルト (自動) はプロバイダーに選択を委ねます。配線に 2 つの人間的なバグが発生しました。none は 4096 トークンの予算で思考を「オン」にし、古い家族に送られた保管済みの adaptive はデフォルトの予算ではなく 400 を引き出しました。

Novita AI と MiniMax を適切なプラットフォームに搭載

Novita AI が LLM ゲートウェイ (novita、https://api.novita.ai/openai) に加わりました。 MiniMax は 2 つの別個のプラットフォームを実行しており、そのキーは交換可能ではなく、デフォルトは中国本土のプラットフォームではなくグローバル プラットフォーム (api.minimax.io) を指すようになりました。 minimax-m3 および minimax-m2.7 コンテキスト ウィンドウが記録され、検出では context_size フィールドも読み取られます。

Compose デプロイでは data/ のすべてが保持されます

docker-compose.ghcr.yml は data/user、data/memory、data/knowledge_bases のみをバインドマウントしたため、data/system (JWT 署名シークレット、アカウント、付与、所有者ごとの Codex トークン)、data/users、data/partners、data/cli-apps はコンテナーの書き込み可能層に存在し、再作成のたびに破棄されました。他の Compose ファイルと一致するように、ツリー全体がマウントされるようになりました。名前付きボリュームとソース ビルドのデプロイメントは影響を受けませんでした。

ローカル コンテナー内での Codex サインイン

デフォルトのローカル Docker および Podman デプロイメントでは、ブラウザーとサーバーが別のループバック ネットワークに配置されるため、OAuth コールバックは到着しません。現在、一時的な compose.codex-oauth.yaml オーバーレイ (および同等の docker/podman コマンド) があり、サインイン中のみポート 1455/1457 を公開します (ティアダウン付き)。そのため、これらのポートは他の Codex client に戻されます。 CONTAINERIZATION.md を参照してください。

以前は何も起こらなかった失敗

発生した機能、または存在しない機能に対するリクエストは、判定なしでストリームを終了し、ターンは空の応答で completed として保持されました。エラーはターミナルとしてマークされ、DONE イベントを通じて伝えられるため、ターンはメッセージとともに failed として保存され、UI には空のバブルの代わりに何が問題だったかが表示されます。

各種詰め合わせ

  • 保存したインターフェイス言語は、最初のロード時に適用されます。これはバックエンドの ui 設定に存在しており、設定ルートのみが読み取られるため、そのブラウザーで再度選択するまで、他のすべてのページは英語で始まります。やはり地元の選択が勝つのです。
  • 解析モデルが列挙型外で render_type または visual_genre を生成しても、ビジュアライズは中止されなくなりました。列挙型外の値は削除され、フィールドはデフォルトに戻ります。
  • 資格情報のようなクエリ パラメーター (key、api_key、token、access_token) は、ウィザード、client、およびエラー メッセージが出力するすべてのエンドポイントで編集されます。

アップグレードに関する注意事項

pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。スキーマは変更されず、インデックスを再作成する必要もありません。

  • docker-compose.ghcr.yml ユーザー: 次の up -d の前に状態をコピーしてください。 新しいツリー全体のマウントは、空のホスト ディレクトリがコンテナーの書き込み可能なレイヤーにあるものをシャドウし、認証シークレットを再生成し (全員をログアウトし)、非管理者アカウントなしで開始することを意味します。 1 つの docker cp ループは CONTAINERIZATION.md → ワンタイム マイグレーション にあります。
  • 中国本土プラットフォームの MiniMax: デフォルトのベース URL がグローバル エンドポイントになりました。 base_url を https://api.minimaxi.com/v1 (または https://api.minimaxi.com/anthropic) に設定し、および 中国プラットフォーム キーを使用します。キーはプラットフォームごとに発行されます。保存されたプロファイルは、すでに持っている URL をそのまま保持します。
  • Gemini 埋め込み: 既存の gemini-embedding-001 プロファイルは意図的にそのままの場所に残されます。新しいプロファイルと gemini-embedding-2 はネイティブ エンドポイントを使用します。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.8...v1.5.9
