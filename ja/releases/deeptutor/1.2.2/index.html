DeepTutor v1.2.2

#ディープチューター v1.2.2 #ディープチューター v1.2.2 Release Notes 発売日: 2026.04.22

ハイライト

ユーザー作成スキル システム

ユーザーが Web UI からカスタム SKILL.md ファイルを作成、編集、アクティブ化できる完全な スキル サブシステムが導入されました。各スキルは、YAML フロントマター (name、description、オプションの triggers) と、アクティブなときにチャット システム プロンプトに逐語的に挿入される Markdown 本体を備えた data/user/workspace/skills/<name>/SKILL.md の下に存在します。

  • バックエンド - SkillService (deeptutor/services/skill/service.py) は、厳密な名前検証 (^[a-z0-9][a-z0-9-]{0,63}$)、フロントマター解析、およびディレクトリ レベルの分離による CRUD + リスト + 選択を提供します。 REST API は GET /list、GET /{name}、POST /create、PUT /{name}、DELETE /{name} とともに /api/v1/skills にマウントされています。
  • フロントエンド — インライン SKILL.md エディターを備えたナレッジ管理ページ (web/app/(utility)/knowledge/page.tsx) の新しい スキル タブと、チャット コンポーザーのスキル ピッカー メニュー。スキルは個別に切り替えることも、自動 モードに設定することもできます (["auto"] をバックエンドに送信します)。 web/lib/skills-api.ts は、キャッシュされた client 側 API レイヤーを提供します。 UnifiedChatContext は、WebSocket ペイロードを通じて skills を伝送します。

チャット入力パフォーマンスのオーバーホール (#351、#360、#362)

ディープステートコロケーションにより、長い会話における入力ラグを排除します。

  • ComposerInput — ChatComposer から独自の memo コンポーネントに抽出されるため、頻繁なキーストロークの再レンダリングがコンポーザーの残りの部分 (機能パネル、リファレンス チップ、ツール メニュー) から分離されます。入力状態のリフティングを回避するために、命令型 ComposerInputHandle (clear()、getValue()) を公開します。
  • SimpleComposerInput — TutorBot チャット ページの軽量バリアントで、@ メンションと機能のオーバーヘッドを完全に削除し、最初のリファクタリング後に報告された残留ラグを修正します。
  • 構成パネルの React.memo - QuizConfigPanel、MathAnimatorConfigPanel、ResearchConfigPanel、および VisualizeConfigPanel は React.memo でラップされるようになりました。 ChatPage の親コールバックは useCallback で安定しました。
  • @-メンション ヘルパーがエクスポートされました - shouldOpenAtPopup および stripTrailingAtMention は、コンポーネント間で再利用できるように名前付きエクスポートとして ComposerInput.tsx に移動されました。

response_format 拒否の自動フォールバック

ランタイム自動回復 パスを使用して、v1.2.1 静的 supports_response_format ガードを拡張しました。プロバイダーが予期せず response_format={"type":"json_object"} に対して HTTP 400 を返した場合 (LM Studio + Gemma/Qwen スタイルのモデルで一般的)、両方の LLM 実行パスがエラーを検出し、フィールドを削除し、1 回再試行するようになりました。

  • aiohttp パス (cloud_provider.py) - _looks_like_unsupported_response_format ヒューリスティックは、_openai_complete および _openai_stream の拒否を検出します。一致した場合、リクエストは response_format なしで再試行され、(バインディング、モデル) ペアがキャッシュされます。
  • OpenAI SDK パス (executors.py) - _create_with_format_fallback は client.chat.completions.create をラップし、BadRequestError をキャッチし、同じ再試行 + キャッシュ ロジックを適用します。
  • ランタイム キャッシュ (capabilities.py) - disable_response_format_at_runtime / is_response_format_disabled_at_runtime レコードはモジュール レベルの set で非互換性を検出したため、後続の呼び出しでは再試行コストを支払うことなく response_format を事前にスキップします。
  • _answer_now.py - stream_synthesis は、response_format を接続する前に supports_response_format をチェックするようになり、高速パス応答フローの最初の場所で 400 が発生するのを防ぎます。

LAN / リモート アクセス修正 (#340)

ローカル ネットワーク上の別のマシンが Web UI を開くと、ビルド時の NEXT_PUBLIC_API_BASE (通常は http://localhost:8001) がサーバーではなくリモート ブラウザー自体のループバックに解決されます。 web/lib/api.ts の新しい resolveBase() ヘルパーは、この不一致を検出し、実行時にホスト名を window.location.hostname に交換するため、どのマシンがページを開いたかに関係なく、apiUrl() と wsUrl() は正しいバックエンドに到達します。

サイドバー バージョン バッジ & GitHub リンク

サイドバーには、ステータス インジケーターの横に現在のビルド バージョンが表示されます。

  • /api/version ルート — api.github.com/repos/HKUDS/DeepTutor/releases/latest (時間ごとの再検証、レート制限ヘッドルーム用のオプションの GITHUB_TOKEN) をクエリし、最新のタグ、名前、URL、公開日を返す Next.js ISR エンドポイント。
  • VersionBadge — NEXT_PUBLIC_APP_VERSION (next.config.js / git describe --tags 経由でビルド時に挿入) をフェッチされた最新リリースと比較します。最新の場合は緑色の点、古い場合はオレンジ色、不明な場合は中立で表示されます。 Clicking はリリース ページに移動します。
  • Dockerfile — 新しい APP_VERSION ビルド引数が Next.js 環境にパイプされるため、Docker ベースのデプロイメントでも正確なバージョンが表示されます。
  • GitHub アイコン — リポジトリへの直接リンクが、サイドバーの折りたたまれた状態と展開された状態の両方に追加されます。

ディープソルブ画像添付ファイルのサポート

DeepSolveCapability は、新しい _first_image_url ヘルパーを介して context.attachments から最初の画像添付ファイル (データ URI または URL) を抽出し、それをプランナー エージェントとソルバー エージェントに渡します。内部的には、PlannerAgent と SolverAgent は、マルチモーダル メッセージ配列を手動で構築する代わりに、BaseAgent の統合マルチモーダル パイプラインを通じて Attachment データクラスを使用するようにリファクタリングされ、2 つの同一の _build_multimodal_messages ヘルパー関数が削除されました。 BaseAgent.stream_llm には、明示的な messages なしで attachments が提供された場合に system_prompt + user_prompt からメッセージを構築するロジックと、非ビジョン モデルで画像が削除されたときのログも追加されました。

エージェント チャット パイプラインの添付ファイルのパススルー

AgenticChatPipeline の _stage_responding および _stage_acting メソッドは、メッセージの作成後に _prepare_messages_with_attachments を呼び出すようになり、最初の思考段階だけでなく、すべてのチャット段階でユーザーがアップロードした画像が LLM に転送されるようになりました。

TutorBot WebSocket の回復力 (#354)

/api/v1/tutorbot/{bot_id}/ws エンドポイントを強化しました。

  • 自動開始 — ボットが構成されているが、WebSocket の接続時に実行されていない場合、エンドポイントは 4004 ですぐに閉じるのではなく、自動的に mgr.start_bot() を呼び出すようになりました。不明なボット ID は、閉じる前に JSON エラー ペイロードを受け取ります。
  • _safe_send ラッパー - すべての ws.send_json 呼び出しは、WebSocketDisconnect / RuntimeError をキャッチするヘルパーを経由し、client が途中でドロップしたときにハンドルされない例外が発生するのを防ぎます。
  • 正常な切断 — _handle_user_messages が receive_text 上の WebSocketDisconnect をキャッチし、きれいに切断します。

設定ページ: API キー マスキング (#355)

[設定] ページの API キー フィールドは、デフォルトで Eye / EyeOff トグル ボタンを使用して type="password" として表示されるようになりました。サービスまたはプロファイルを切り替えると、可視性の状態がリセットされます。

書籍ライブラリ UI のオーバーホール

最小限の「ブックを選択」プレースホルダーを、検索、章/ページ数を含むステータス フィルターされたカード、作成および削除アクション、ステータス バッジ (ドラフト / アウトライン / コンパイル / 準備完了) を備えた完全な BookLibrary コンポーネント (web/app/(workspace)/book/components/BookLibrary.tsx) に置き換えました。 BookSidebar は、「← すべての書籍」戻るボタンを備えた 1 冊の書籍リーダー ビューに簡素化され、書籍ページには現在のビューに基づいて条件付きでライブラリまたはサイドバーが表示されるようになりました。

視覚化フルスクリーン モード

SVG、Mermaid、および ChartJS ビジュアライゼーションには、エスケープして閉じるとグラフィックを全画面オーバーレイで開く 最大化 ボタン (右上) が追加されました。 HTML iframe ビジュアライゼーションは、独自の「新しいタブで開く」アフォーダンスをすでに提供しているため、除外されます。

バグ修正

  • 埋め込みアダプター ConnectError は再試行されません (#353) - OpenAICompatibleEmbeddingAdapter の再試行例外タプルに httpx.ConnectError を追加しました。そのため、埋め込み中の一時的な接続障害は、すぐに発生するのではなく指数バックオフで再試行されます。
  • RAG None 埋め込み強化 — CustomEmbedding._aget_query_embedding および _aget_text_embedding は、プロバイダーが None を返したときに、後の類似度計算でクラッシュするのではなく、明確な ValueError を生成するようになりました。バッチ メソッド _aget_text_embeddings は、兄弟ベクトルまたは構成された dim からフォールバック ゼロ ベクトル次元を決定し、どちらも使用できない場合に発生します (長さ 0 ベクトルのサイレント永続化を防止します)。
  • ディレクトリが見つからない場合の KB 削除のクラッシュ - KnowledgeBaseManager.delete_knowledge_base は、self.base_dir / name を介してパスを直接解決し、ディスク上のフォルダーが既に削除されている場合を処理し、FileNotFoundError を発生させる代わりに孤立した kb_config.json エントリをクリーンアップします。
  • CLI parse_json_object ホワイトスペース — この関数は解析前に先頭/末尾のホワイトスペースを削除するようになり、シェルのパイプからの末尾の改行によって json.JSONDecodeError が発生しなくなります。

テストスイートの拡張

  • TutorBot WebSocket — 停止しているが構成されているボットの自動起動と、不明なボット ID (tests/api/test_tutorbot_router.py) の JSON エラー ペイロードをカバーする 2 つの新しいテスト。
  • CLI ヘルパー — parse_json_object の空白処理と無効な JSON (tests/cli/test_common.py) の 2 つのテスト。
  • ルート パラメーター — 新しい firstParam ユーティリティ (web/tests/route-params.test.ts) の 3 つのテスト。
  • API 解決ベース — LAN ホスト名スワップ ロジック (web/tests/api-resolve-base.test.ts) をテストします。
