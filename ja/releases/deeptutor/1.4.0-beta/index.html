#ディープチューターv1.4.0-beta #ディープチューター v1.4.0-beta Release Notes 発売日: 2026.05.21 v1.4.0-beta は、エージェント ネイティブの書き換え以来最大のリリースです。それは折り畳まれます 既存の機能に加えてエンドツーエンドの 自動モード が搭載されており、 3 層メモリ サブシステム (L1/L2/L3) と専用ワークベンチ、リビルド チャットと同じエージェント エンジン上の詳細な調査/詳細な解決/質問**、 チャット機能 + LlamaIndex RAG パイプラインを中心に再構築します。 セッション累積ソース インベントリ、機能インフラストラクチャを統合 および i18n、Animator メニューを Visualize にマージし、再編成します 設定、環境、およびローカル ランチャー。いくつかの新しいチャット ツール (ask_user、web_fetch、write_note、list_notebook、github_query) プラス 削除、チャット、ターンのフロー、クイズのフォローアップ チャット、GeoGebra ビューアがこのプログラムを完成させます。 解放する。

ハイライト

自動モード — エージェント機能ルーター

新しい auto 機能は既存のモードの上に位置し、適切なモードを選択します。 ユーザーに事前にモードを選択させるのではなく、リクエストごとに 1 つずつ実行します。

  • 3 段階のエージェント ループ — ANALYZING (単一 LLM コール、次のようにストリーミング) 考え中) → DELEGATING (発信するルーター呼び出しの max_iterations まで) delegate_to_<cap> ツール呼び出しまたはアトミック ツール呼び出し) → SYNTHESIZING (最終 インライン回答。ループから渡されるか、終了によって組み立てられます。 LLM コール)。
  • 実際の機能へのルート — deep_solve、deep_question、 deep_research、math_animator、visualize、およびチャットレベルのアトミック ツール (web_search、web_fetch、rag など) は同じルーターの背後にあるため、 LLM は、1 ターンで取得と完全なサブ機能の実行を組み合わせることができます。
  • 制限された再試行とクォータ — ルーター LLM の独立した再試行バジェット エラー、委任ごとの失敗、引数検証フィードバック。構成可能な max_same_capability_calls クォータにより、ループが 1 つのモードで回転することがなくなります。
  • 会話履歴をクリーンにする — サブ機能イベントは forward_events シムは、すべてのコンテンツ イベントに call_id のタグを付けるため、 会話ターンランタイムフィルターは、Auto 自身の最終合成のみを保持します。 保存された履歴。サブランは引き続き UI にライブでストリーミングされます。
  • answer_now 高速パス — ユーザーがパイプラインに「今すぐ応答する」ように要求したとき 分析と委任をスキップし、即時のインライン応答を生成します。

3 層メモリ サブシステム (メモリ v2)

以前のフラット メモリ ページは、構造化された 3 層ストアに置き換えられます。 明示的な統合パイプラインと専用のワークベンチを使用します。

  • L1 / L2 / L3 レイアウト — L1 は生の実行トレースをキャプチャし、L2 は正規化された状態を保持します ドキュメント レコード、L3 はサーフェスごとに厳選されたスロット (チャット、ノートブック、書籍、 チューターボット）。ユーザーごとのパスは PathService を通過するため、マルチユーザー デプロイメントは分離されたままになります。
  • コンソリデータ パイプライン — モジュール式 consolidator/ モジュール (チャンカー、ガード、 解析、参照、実行、モード、ラインドキュメント、メタ) 実行トレースを次のように変換します。 安定した ID を持つバージョン管理された行指向のドキュメント、間の参照 レイヤーとスナップショット履歴。
  • Memory Workbench UI — 新しい /memory ルート (graph、l1、l2、l3、 resolve) ワークベンチ、ハブ、グラフ ビューア、実行機能を備えたスタンドアロン ページとして出荷されます。 パネルとアーカイブされた状態のバナー。再利用可能な MemorySection コンポーネントは次のとおりです。 従来のメモリパネルがあった場所に埋め込まれています。
  • 一流のチャット ツール — read_memory および write_memory が公開されています エージェント ツール (i18n ヒント付き) として使用できるため、チャット/自動でメモリを呼び出して更新できます 別の保存ステップを必要とせずに、ターン内で保存できます。
  • 設定の統合 — メモリの下に独自のページが追加されました。 /settings/memory には、実行コントロール、モード切り替え、およびストレージ ステータスが備わっています。

エージェント エンジンに関する詳細な調査、詳細な解決、および質問

3 つのマルチエージェント パイプラインは、オーケストレーターとして書き直されました。 共有エージェント エンジン プリミティブ、数百の特注プロンプトを削除 ファイルとエージェントごとのクラス。

  • ディープリサーチ → agents/research/pipeline.py — 4 フェーズ (Rephrase、 Decompose、Research blocks、Reporting) ラベル付きステップとして実装 (THINK / TOOL / APPEND / OUTLINE / SECTION / FINISH)。ダイナミックな トピックキューとCitationManagerは保持されます。新しい APPEND ラベルにより、 研究ブロックは、ループを離れることなくフォローアップ トピックをキューに追加します。 ask_user v2 では、複数の質問カードを使用して最大 3 回の言い換えラウンドを実行できます。
  • ディープソルブ → agents/solve/pipeline.py — Pre-retrieve (KB のみ)、 Plan、Solve (ステップごとの THINK / TOOL / FINISH / REPLAN ループ、 解決から計画までのバックエッジ)、および最後の Synthesize ステップ。それぞれのステップの FINISH は次のステップのプロンプト コンテキストに流入するため、答えは次のようになります。 一つの連続した物語。
  • 質問/クイズ — コーディネーター + パイプラインは古い generator / を置き換えます idea_agent / models モジュール;古いプロンプト ディレクトリは 完全に削除されました。
  • 3 つすべてが、従来の agents/ ディレクトリと prompts/ ディレクトリを削除します それぞれのモードで、1 つのパイプライン ファイルと共有のラベル付きステップ プロンプトが残ります。

チャット機能と LlamaIndex RAG リファクタリング

エージェント チャット パイプラインは、セッションの累積を中心に再構築されました。 「添付ソース」マニフェストとよりクリーンな LlamaIndex パイプライン。

  • ブランチ分離ソース在庫 — services/session/source_inventory.py アクティブなブランチの祖先チェーンに接続されているすべてのソースを実体化します。 現在のターンからの新しいソースには完全なプレビューが表示されます。歴史的資料 ID、名前、種類、サイズ、ターン順序を含む 1 行の行を表示します。 彼らは初めて現れました。 LLM は read_source(id) を呼び出して、完全な拡張を行います。 オンデマンドのテキスト。兄弟ブランチが相互にソースを漏洩することはありません。
  • LlamaIndex パイプラインの分割 — 専用 config.py、ingestion.py、 retrievers.py および document_loader.py は、以前のモノリシックを置き換えます。 パイプラインモジュール。ストレージは v1.3 バージョンとの下位互換性を維持します インデックス。
  • 無駄のないエージェント チャット プロンプト — agentic_chat.yaml (EN/ZH) は次のように書き換えられました。 新しいツールの表面とソースと在庫の契約を一致させます。古い 並列ツールのプロンプト スキャフォールディングは廃止されました。
  • 組み込みツール レジストリ — tools/builtin/__init__.py は単一の場所です ここで、チャットにマウントされたツール、ヒント プロンプト、引数拡張ラッパーは次のとおりです。 登録されました。

機能インフラストラクチャの統合

すべての機能が 1 つの共有エンベロープ、1 つの status-i18n ローダーを経由するようになりました。 そして 1 つのコスト追跡面。

  • emit_capability_result ヘルパー — すべての機能が最終的なものを出力します 結果エンベロープ (ラベル、概要、 ペイロード、レンダリング ヒント)、および末尾の使用状況トラッカーの合計が一貫して表示されます。
  • StatusI18n — 機能ステータスのコピーが存在します capabilities/prompts/{en,zh}/<name>.yaml であり、共有経由でロードされます。 StatusI18n アクセサ。ハードコーディングされた英語のステータス文字列が削除されました パイプラインから。
  • UsageTracker コスト面 — トークンの使用量とコストが追跡されます 機能の実行ごとに 1 つのトラッカーが結果エンベロープに公開され、表示されます 新しい /settings/capabilities 管理ページ (ライブ リスト、デフォルト、 機能ごとにオーバーライドを切り替えます)。
  • 非推奨の main.yaml キーが削除されました — 従来の main.yaml 機能 機能ごとのプロンプト ファイルが優先され、コピーは削除されました。

視覚化: アニメーターを 1 つの機能に統合

スタンドアロンの Animator メニューが Visualize に統合され、ユーザーが選択できるようになりました。 一度視覚化すると、システムがレンダラーを選択します。

  • render_type 識別子 — AnalysisAgent は 6 つのレンダリングのうち 1 つを選択します タイプ — svg、chartjs、mermaid、html (テキスト発行、3 段階) パイプライン) または manim_video / manim_image (Manim サブプロセス パイプライン)。の 結果エンベロープには render_type が含まれるため、フロントエンドは 右の視聴者。
  • 単一のサイドバー エントリ - 古い Animator メニュー エントリはなくなりました。現在のユーザー 静的チャートと Manim ビデオの両方に対して Visualize を実行します。の 全画面ビューア/設定パネルはすべてのレンダリング タイプを処理します。

新しいチャット ツール

  • ask_user — 1 ～ 3 つの構造化された質問を単一のペイロードにパッケージ化します。 ユーザーが応答するまで同じターンを一時停止します。フロントエンドはカードをレンダリングします ユーザーが質問をナビゲートし、1 つのバッチで回答を送信できるようにします。の パイプラインは、ツールの結果として答えを配線してターンを再開します。 Deep Research のリフレーズ フェーズで使用され、チャット/自動で利用できます。
  • web_fetch — 読み取り可能なコンテンツ抽出、厳密なスキームを使用した URL フェッチ / プライベート IP / サイズ ガード (フライト前とリダイレクト後の両方に適用)、 出力が上限を超えると、…[truncated] マーカーが表示されます。
  • write_note — 古い save_to_notebook ツールを置き換えます。 2 つのモード: append は新しいレコードを作成します (デフォルトの本文はレンダリングされたトランスクリプトです。 オプションのエージェント作成本文) および edit によって既存のレコードが更新されます。 record_id。
  • list_notebook — アクティブなインデックス/ドリルダウン リストの読み取り専用 ユーザーのノートと記録。ユーザーが実際に持っている場合にのみマウントされます ノートブックなので、空の実行は構造上不可能です。
  • github_query — pr、issue、をカバーする読み取り専用 gh CLI ラッパー run、repo、および GET のみの api フォールバック。突然変異動詞はありません 工具表面から到達可能。クリーンな「ツールが利用できません」を返します gh がインストールされていない場合の結果。

チャット サーフェスの機能

  • チャット ターンの削除 (#443) — メッセージ アイテムには安定した id が含まれるようになりました。 セッション API は deleteMessage を公開し、チャット リデューサーは DELETE_TURN を追加します アクション、および 409 対 404 チェックにより、まだ実行中のターンの削除が拒否されます。 オプティミスティックな一時 ID は、孤立した UI 行を避けるために削除前に解決されます。
  • クイズフォローアップチャットコンポーザー — FollowupChatComposer および QuizFollowupContext により、ユーザーはクイズから直接チャット スレッドを開始できます 質問。作曲家はメインの ChatComposer を再利用しています (ほら、@space ピッカー、KB ピッカー、添付ファイル、LLM セレクター)、ただしルート送信は 専用追従コントローラー。コンパニオン quiz-judge.ts ヘルパー サポート フォローアップの回答をインラインで判断します。
  • クイズ UI の洗練 — クイズの答えのテキストエリアは垂直方向にサイズ変更可能です (#478)。 質問の内容は、単一の改行を Markdown 段落に正規化します (#441)。
  • GeoGebra ビューア — Geogebra.tsx、GeogebraOpenCTA.tsx、および GeogebraTabContext GeoGebra アプレット レンダラを追加します ( 公式 GGB アプレット スクリプト) を使用して、幾何学/代数のスニペットを開くことができます チャットの回答と一緒にインラインで。

マルチユーザーデータの分離

v1.3.x マルチユーザー導入からのいくつかの回帰とギャップがあった。 集中パスで修正されました (#474、#465)。

  • ミドルウェアから分離された認証 — マルチユーザー ID 解決なし グローバルミドルウェアの状態に依存しなくなり、リベース回帰を修正しました。 特定のルーティング順序の下でクロスユーザー データ ブリードが発生しました。
  • 従来のセッション マネージャーのパス キャプチャ — 古いセッション マネージャー アクティブなユーザー スコープを正しく継承したため、そのファイル パスは内部に配置されます。 共有デフォルトの代わりにユーザーごとのワークスペースを使用します。
  • フロントエンドはどこでも apiFetch を使用します - すべての認証された client 呼び出し apiFetch() を通過するようになったので、認証ヘッダーが一貫して付加されます。
  • SSL バイパス スイープ - DISABLE_SSL_VERIFY がコーデックス プロバイダーに到達するようになりました および v1.3.10 以降もまだ存在しなかった 4 つの埋め込みアダプター。

  • runtime/launcher.py — を所有する単一の非同期ランチャー バックエンド + フロントエンドのライフサイクル、ポート検出、readiness プローブ、および 掃除。 Next.js フロントエンドが常に選択するように web/.env.local を生成します。 解決されたバックエンド ポートをアップします。
  • deeptutor/runtime/banner.py — ローカライズされたスタートアップ バナーの共有 deeptutor start と deeptutor init の間。言語を読みます バナーが UI ロケールと一致するように、インターフェイス設定からの設定を変更します。
  • init_wizard.py — プロバイダーを使用した対話型 deeptutor init ウィザード メニュー、API キーの環境変数自動検出、ライブ GET {base_url}/models フェッチ、厳選されたフォールバック リスト、およびオプションの接続プローブの前に 保存します。

Zulip チャネルの統合

  • @mentions のチャンネルを自動購読 — ボットは自分自身を購読できます @メンションを取得して実際にメッセージを受信するチャネル トピックスで。登録チャンネルの警告は情報レベルにダウングレードされるため、 起動ログが成功パスに誤解を招くようなフラグを付けるのをやめます。
  • すべてのメンション フラグ タイプがサポートされています — mentioned、wildcard_mentioned、 topic_wildcard_mentioned および stream_wildcard_mentioned はすべてトリガーされます ボット、チャンネル @ の沈黙を修正しました。
  • 添付ファイル送信の修正 — 再送信された添付ファイルは Zulip を扱わなくなりました パスをローカル ファイルとしてアップロードすると、アップロード ヘルパーがクラッシュしなくなります。 'str' object has no attribute 'name'、ルーティング メタデータが欠落しています _recipient_map から再構築されたため、Message must have recipients エラーが発生します 排除される。
  • 進行状況メッセージの重複除去 — 内部 _tool_hint 進行状況イベントは次のとおりです。 チャンネル送信から除外されるため、ユーザーには重複した「ツール」が表示されなくなります 始まります…」という行。
  • テストカバレッジ — 添付ファイルのアップロードと送信回復のための新しい単体テスト そしてチャンネル登録の動作。

  • Animator メニュー ユーザー — 代わりに Visualize をポイントします。の ユーザーが要求したときに、機能が Manim を自動的に選択するようになりました。 ビデオ/アニメーション。 Manim でレンダリングされた既存のレコードは影響を受けません。
  • メモリ データの移行 - 従来のシングル BLOB メモリ形式は 最初のアクセス時にコンソリデータによって読み取られ、L2 / L3 として書き戻されます 記録。手動の手順は必要ありません。古いスナップショットはディスク上に残ります。
  • 機能作成者 — 経由で結果を出力します capabilities/_shared.emit_capability_result とステータスコピーを入れる capabilities/prompts/{en,zh}/<name>.yaml。ハードコーディングされた英語ステータス 文字列はレビューに失敗します。
  • ベータ版 — このリリースには、実質的な新しいサーフェス (自動、 メモリ v2、設定は分割されています）。まで生産用に v1.4.0-beta にピンを留めます GA カット。新しいモジュールに対するバグレポートは大歓迎です。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.3.10...v1.4.0-beta
