DeepTutor v1.1.1

#ディープチューター v1.1.1 #ディープチューター v1.1.1 Release Notes 発売日: 2026.04.17

ハイライト

ユニバーサル「今すぐ応答」エスケープ ハッチ — 能力ごとの高速パス

「今すぐ応答」をチャットのみのアフォーダンスから、各機能の出力形状を尊重するユニバーサル割り込みに昇格しました。新しい共有ヘルパー deeptutor/capabilities/_answer_now.py は、ゲート (extract_answer_now_context) とプロンプト対応のトレース サマリーを提供し、すべての組み込み機能が run() の先頭に独自の高速パス ブランチを所有するようになりました。

  • chat — 部分トレース (既存の動作) から最終的なマークダウン回答を合成します。
  • deep_solve — 計画や推論を省略して、ライターの作業に直接進みます。
  • deep_question — アイデア/テンプレートをスキップし、1 つの構造化呼び出しで完全なクイズ JSON を発行します (依然として QuizViewer によってレンダリングされます)。
  • deep_research — 言い換え/分解/調査をスキップし、蓄積された証拠から直接レポートを作成します。
  • math_animator — 分析 + 設計 + サマリーをスキップしますが、コード生成 + レンダリングは維持するため、ユーザーは実際のアニメーションを引き続き取得できます。
  • visualize — 分析とレビューをスキップし、1 つの構造化呼び出しで最終的なレンダリング可能なコードを出力します。 各高速パスは、通常のパイプラインと同じ結果エンベロープを保持し (そのため、Quiz/MathAnimator/Visualization ビューアは変更されずにレンダリングされます)、> ⚡ Skipped X stage(s) 通知を先頭に追加して、ベストエフォートの早期終了であることをユーザーに知らせます。オーケストレーターは answer_now を chat に再ルーティングしなくなりました。現在は active_capability が保持され、最初に選択された機能がレジストリから削除された場合にのみ chat に戻ります。フロントエンドは一致します: handleAnswerNow はスナップショットの機能をオーバーライドしなくなり、シングルショットで保護された AnswerNowRow コンポーネントはアクションをストリーミング トレース パネルの下にインラインでレンダリングします。

共同執筆者 — サイズ変更可能な分割と行アンカー付きスクロール同期

Co-Writer ページでは、エディター ペインとプレビュー ペインの間のドラッグ可能なスプリッター (localStorage で比率が維持される) と、ソフトラップされた行を維持する真の双方向スクロール同期が採用されました。各プレビュー ブロックには、マークダウン ソースの開始行 (リマークの AST 位置によって提供される) を指す data-source-line 属性が含まれるようになりました。エディタ側では、非表示のミラー要素がテキストエリアのラップ ジオメトリを模倣するため、すべてのソース行の実際のピクセル y を読み取ることができます。両側がピクセル座標として表現されると、同期はいずれかの方向で単一の区分的線形補間となり、コンテンツまたはラップ幅が変更された場合にのみ無効化されるソースラインごとのキャッシュを使用します。

ノートブックに保存 — メッセージ選択モード

SaveToNotebookModal は、モーダルを「選択モード」に切り替えるオプションの messages プロップを受け入れるようになりました。ユーザーは、どのユーザー/アシスタントを含めるかを正確に選択し、バックエンドに送信されるトランスクリプト + userQuery は、選択されたサブセットから再構築されます。クイック プリセット (「すべて選択」、「最後のターン」、「最後の 3 ターン」) と、最初に選択したユーザー メッセージを追跡する自動生成されたタイトルにより、一般的なケースでのフローが迅速に保たれます。また、モーダルでは Check / MessageSquare / User アイコンを使用して役割を一目で区別できるようになり、保存スピナーとは別にノートブック リストの読み込み状態をレポートします。

スタック全体でのリアル ノートブック システムの導入

残りのすべての Notebook サーフェスを従来のクイズ カテゴリ API から実際の /api/v1/notebook/* エンドポイントに移行しました。新しい web/lib/notebook-api.ts ブロックは、保存されたクイズ専用ヘルパーとともに、型付きヘルパー (listNotebooks、getNotebook、createNotebook、updateNotebook、deleteNotebook、deleteNotebookRecord) をエクスポートします。 [ナレッジ] → [ノートブック] タブ、ガイド ページのノートブック参照ピッカー (useNotebookSelection)、および [ノートブックに保存] モーダルはすべて、UUID をエンドツーエンドで解決するようになったため、共同執筆者、チャット、またはガイド付き学習から保存されたレコードはどこでも参照としてすぐに検出できるようになりました。

統合された折りたたみ可能な設定パネル

以前は ResearchConfigPanel にのみ存在していた折りたたみ可能な「設定」セクションが、共有 CollapsibleConfigSection コンポーネントに抽出されました。 Quiz、Math Animator、および Visualize パネルはまったく同じシェブロン + 概要ヘッダーを共有するようになり、各フォームには summarizeXxxConfig ヘルパーが同梱されるため、折りたたまれた状態で意味のあるワンライナー (例: Custom · 5q · Hard · MCQ または Mimic ·paper.pdf · max 10) が表示されます。チャット ページは、アクティブな機能に対して単一の panelCollapsed 状態を保持し、機能スイッチで自動展開し、メッセージ送信後に自動的に折りたたまれるため、会話中にコンポーザーはコンパクトなままになります。

ストリーミング停止ボタンとコンポーザの洗練

送信ボタン内のスピナーを、ターンのストリーミング中に送信の代わりに表示される専用の 停止 ボタンに置き換えました。かすかなリングがリムの周りをゆっくりと回転し、「まだ動作しています - click をキャンセルします」という信号を送り、前面中央の白い四角形が click のターゲットになっています。メッセージの上のヘッダー (機能ラベル + 保存 / 新しいチャット ボタン) が常にレンダリングされるようになり、メッセージ コンテナーは上部と下部でソフト マスク グラデーションを選択するため、ストリーミング コンテンツはスクロール エッジで clipping ではなくフェードイン/フェードアウトします。 Deep Research モードでは、ツール セレクターで使用されるパターンと一致する、アクティブなピックのコンパクトな概要行を含むドロップダウンにソースが移動しました。

TutorBot Config Manager のリファクタリング

TutorBotManager の構成永続性を小規模なパブリック API (load_bot_config、save_bot_config、merge_bot_config) に書き換え、3 つの意味のある改善を加えました。書き込みは アトミック (書き込み一時 + Path.replace) になったので、強制終了されたプロセスが書きかけの config.yaml を残すことはありません。マージには 明示的クリア セマンティクスがあります。None は「そのままにする」を意味し、空の文字列または空の辞書は意図的なクリアです。そのため、client は説明やチャンネル リストを意図的に消去できます。また、API エンドポイントは model_dump(exclude_unset=True) のみを転送するため、省略されたフィールドはディスク上の値になります。新しい回帰テストでは、アトミック書き込みコントラクト、破損 yaml フォールバック、および 4 つのマージ セマンティクスのケースがカバーされています。

マークダウン レンダラーの改良点

MarkdownRenderer ファミリは、data-source-line 属性をすべてのブロック要素 (見出し、リスト、段落など) に伝播し、行シフト正規化パス (processMarkdownContent、normalizeMarkdownForDisplay) をバイパスする trackSourceLines プロパティを取得しました。これにより、エディター/プレビュー同期コンシューマーに対して AST 位置が忠実に保たれます。 RichCodeBlock は、ラベルなし / text / plaintext フェンスの react-syntax-highlighter を完全にスキップし (Prism の「不明な言語」警告を排除)、整然としたプレーンな等幅ブロックとしてレンダリングします。 Mermaid 検出も拡張され、プリプロセッサによって Mermaid に書き換えられる editor.md スタイル ```flow, ```seq および ```sequence フェンスを認識できるようになりました。

テーマとガイドの UI の更新

デフォルトの光と雪のテーマをより深い前景、より温かみのある境界線、そしてわずかに彩度を高めた --primary (#B0501E) で強化し、新しいカードの表面に対する読みやすさを向上させました。ガイド付き学習ページ (/guide) は、ハードコードされた slate-* / indigo-* パレットからデザイン トークン (var(--card)、var(--primary)、var(--muted-foreground) など) に移行されたため、テーマ スイッチャーが尊重されるようになりました。 HistorySessionPicker も同様に処理され、さらに、秒ではなくミリ秒として扱われていたセッション タイムスタンプ (1970 年の日付が生成された) が修正されました。

システムメッセージレンダリングの修正

バックエンド システム メッセージ (ターン ランタイムによって書き込まれたクイズのフォローアップ グラウンディング コンテキストなど) は、UnifiedChatContext.hydrateMessages 境界でフィルタリングされ、再び ChatMessageList で防御的に除外されるようになりました。そのため、意図したとおり LLM コンテキストに流れ込みながら、UI 内でゴースト チャット バブルとして表面化することはありません。

バグ修正

  • サーバーを再起動するたびに TutorBot チャネル設定が消去される (#332) — create_and_start_bot は呼び出しごとに空のデフォルトを使用して新しい BotConfig を構築していましたが、その後 _save_bot_config は既存の config.yaml 上に存続し、ユーザーが設定したチャネル (例: Telegram) を消去しました。エンドポイントは、最初に既存の構成をロードし、client が提供するフィールドのみをオーバーレイするようになりました。
  • selective_access_log ミドルウェアは、200 以外の応答ごとにクラッシュします (#334 / #335) — ミドルウェアは、5 つ (http_version を省略) を期待する uvicorn の AccessFormatter に 4 つの引数を渡し、エラー応答ごとに ValueError: not enough values to unpack を発生させます。 1.1 フォールバックを使用して ASGI スコープから http_version を読み取るようになりました。
  • 15 npm セキュリティ脆弱性 (#330) — 影響を受けた jspdf 4.0.0 → 4.2.0 (重要な PDF インジェクションを含む 9 つの CVE)、next 16.1.1 → 16.2.3 (HTTP 密輸、CSRF バイパスを含む 8 つの CVE)、mermaid 11.12.2 → 11.14.0、およびそれに一致する eslint-config-next。 npm audit fix は間接チェーン (flatted、lodash-es、minimatch、picomatch、dompurify、ajv、brace-expansion) をスイープアップしました。最終状態: 脆弱性は 0 件、重大な変更はありません。
  • .env.example_CN - プロバイダー リストのコメントにある偶発的な // README サフィックスを削除しました。

テストスイートの拡張

ロード/保存のラウンドトリップ、破損した yaml フォールバック、アトミックな一時ファイルの書き込み、書き込み途中の OSError 後の障害回復、および 4 つの merge_bot_config セマンティクス (既存の設定なし、省略されたフィールドのパススルー、提供されていない None、明示的なクリアとしての空の値) をすべてカバーする新しい tests/services/tutorbot/test_manager_config.py モジュールが追加されました。 tests/api/test_tutorbot_router.py を明示的クリア テスト クラスで拡張しました。新しいコントラクトを固定するために、オーケストレーターの応答即時ルーティング テストを書き直しました。answer_now_context が設定されている場合、ZZPH100​​ZZ は保持されます。オーケストレーターは、元の機能が欠落している場合にのみ chat に戻り、どちらも登録されていない場合は明確なエラーを生成します。共有ヘルパー (extract_answer_now_context、format_trace_summary 切り詰め/i18n、make_skip_notice、labeled_block、join_chunks) とすべての機能ごとの高速パスをカバーする 28 のケースを含む新しい tests/capabilities/test_answer_now.py モジュールを追加しました: chat、deep_solve、deep_question (解析不可能な JSON を含む)フォールバック)、deep_research、visualize (コードフェンスのストリッピングと無効な render_type リカバリを含む)、math_animator (run_code_generation/run_render が * 実行されている間、run_analysis/run_design/run_summary が * 呼び出されないことを検証)。逆テストにより、answer_now_context が存在しない場合でも、機能が通常のパイプラインを使用することが確認されます。
