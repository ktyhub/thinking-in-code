DeepTutor v1.5.7

パッチ 公開日2026年7月30日 出典HKUDS/DeepTutor 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディープチューターv1.5.7 #ディープチューター v1.5.7 Release Notes 発売日: 2026.07.31 v1.5.6 のフォローアップで、DeepTutor には同梱されていないツールを家庭教師に提供します。各人が自分でインストールするホスト型 MCP サービスの厳選されたストアと、チャット エージェントが直接呼び出すことができる CLI-Anything カタログからの 101 個のコマンド ライン アプリです。どちらも、共有デプロイメントに実際に必要な承認と分離を備えています。インストールは特権アクションですが、実行はそうではありません。また、コード サンドボックスが読み取ることができる場所には、ユーザーを承認するものは何も残りません。ドロップイン - 移行はありません。

新機能

自分でインストールする MCP ストア

ラーニング スペース → MCP サービス は、1 つの click に自分で追加する 45 台の厳選されたホスト サーバーと、URL で構成するリモート サーバーのストアです。すべてのカタログ エンドポイントは、実際の MCP initialize を送信することによって検証され、ロゴ CDN は接続されません。さもなければ、ストアがレンダリングすることで、ペイントごとにインストール済みサービス リストがサード パーティに送信されます。 401 (Notion、Linear、Sentry、Asana、monday、Canva、Prisma) に応答するサーバーは、PKCE および動的 client 登録を使用して OAuth 2.1 経由でサインインします。バックグラウンドでの再接続は同意画面でブロックされることはなく、needs_auth を報告するだけなので、UI に [接続] ボタンが表示されます。静的キーは参照によって保存され、接続時にメモリ内で解決されるため、表示される構成ファイル、API によって返される構成ファイル、またはログにコピーされる構成ファイルにトークンが配置されることはありません。 stdio エントリはセルフサービスでは拒否されます。コマンドはアプリ ユーザーとしてホスト実行されます。 MCP は [設定] で構成されなくなりました (/settings/mcp はストアにリダイレクトされます)。また、ツール ピッカーは数百のツールをサービスごとに 1 行に折りたたむようになりました。

家庭教師が実行できる CLI アプリ

ラーニング スペース → CLI アプリ は、2 つの CLI-Anything レジストリからスナップショットされた 101 ツールをカタログ化し、チャット エージェントはインストールされているツールを直接呼び出し、そのアプリ独自の使用ガイドが必要な場合にのみ読み込まれます。 pip install はアプリケーション コンテナ内でパッケージ独自の setup.py を実行するため、インストールは管理者のみが行うことができます。いくら注意してもセルフサービスにはなりません。レジストリの install_cmd は決して実行されません。これは、argv DeepTutor がビルドするプランに解析され (レジストリには既に curl … | bash が含まれています)、npm インストール スクリプトは強制的にオフにされ、ビルドに失敗した更新により作業環境がロールバックされます。 66 個のファーストパーティ ハーネス エントリが 1 つのレビュー済み CLI-Anything コミットに固定されます。別のアップストリームを指すものにはサードパーティというラベルが付けられるため、インストールする場合は十分な情報に基づいた選択が必要です。 アプリは data/cli-apps にそれぞれ 1 つの環境で配置され、サンドボックス ランナーに 読み取り専用でマウントされます。この分割がポイントです。エスケープされたコマンドはアプリのエントリ ポイントを上書きできず、その後のターンごとにすべてのアカウントに対して置換を実行することになります。

サンドボックスが到達できない認証情報

人 を認証するものはすべて data/system (ランナーにバインドマウントされることのないデータ ツリーの 1 つのブランチ) に移動しました。 Codex OAuth トークンは data/system/user-secrets/<owner>/private/openai-codex/ に、ユーザーごとの MCP 構成は data/system/user-mcp/<owner>.json に、MCP トークンと API キーはその隣に存在するようになりました。既存の Codex ログインは最初の使用時に自動的に再配置され、別のアカウントのストアを再配置する危険を冒さずに、シンボリックリンクされたディレクトリを介して移動を実行することを拒否します。 これにより、理論上の危険ではなく実際の危険が解消されます。ランナーが受け取るユーザーごとのマウントはユーザー ルート全体であるため、data/users/<uid>/ の下に保持されている資格情報は、他のすべてのアカウントのサンドボックス シェルから読み取り可能 (および書き込み可能) でした。

プラグインツール、個人ごとに管理

MCP ツールがすでに持っていたのと同じデフォルトで拒否する姿勢を持つ cli_apps ホワイトリストを許可します。インストールされるアプリはサンドボックス内で実行されるサードパーティ コードであり、アプリをインストールする展開は、そのアプリの実行を許可されているすべてのアカウントと同じ決定ではありません。その背後では、ターンごとのレジストリ ビューによって、1 人のユーザーのプロバイダー ツールがプロセス グローバル レジストリから完全に除外されます (サーバーがツール名を共有する 2 つのテナントが相互に破壊することはできなくなります)。 また、テキスト プロトコルのフォールバックにより、提供されたことのない名前が合成される可能性があるため、マニフェストだけでなく、execute で不正なツールを拒否します。

ウィンドウがどのくらい埋まっているかを知らせるコンポーザー

コンポーザーのチップは、このターンが実際にモデルのコンテキスト ウィンドウに入力したものと、再導出されたものではなく、すでに組み立てられたプロンプト ブロック、ツール スキーマ、およびメッセージ リストから測定された、モデルのコンテキスト ウィンドウを満たしているものをレポートします。そのため、読み出しが送信されたものからずれる可能性はありません。長い会話の場合は、履歴を遡るために、トランスクリプトの左側の溝に、質問ごとに 1 つずつ目盛りが表示されます。

電話での DeepTutor

ワークスペースとユーティリティのレイアウトは、デスクトップの 3 ペイン レイアウトをビューポートの端からレンダリングするのではなく、小さな画面上でスライドオーバー サイドバーを備えた 1 列のシェルに折りたたまれるようになりました。

さまざまな修正

  • コンポーザーは送信後もフォーカスを維持し、タブを切り替えて戻るとフォーカスを取り戻します (#720)。
  • リリースされたコンテナ イメージには、出所と SBOM 証明書が含まれます (#722)。
  • git はアプリケーション イメージにインストールされ、ノード ランタイムはランナー イメージにインストールされます。どちらもアプリ インストーラーと npm パッケージ化されたアプリのコンソール スクリプトで必要です。

アップグレードに関する注意事項

v1.5.6 からのドロップイン: pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。スキーマや構成の変更はなく、既存の Codex ログインが引き継がれます。認証情報は、初めて解決されるときに自動的に再配置されます。

  • docker-compose デプロイメントは再起動するだけでなく、再起動する必要があります。ランナー サービスは読み取り専用の ./data/cli-apps マウントを取得し、それがインストールされていないと、CLI アプリはカタログ化されますが、実行できません。
  • [設定] で構成された MCP サーバーはそのまま残ります - 導入全体の mcp.json は変更されず、引き続き管理者が所有します。新しいストアは、アカウントごとに並行して行われます。 /settings/mcp がそれにリダイレクトされるようになりました。
  • CLI アプリのインストールは管理者のみで、割り当ては 2 番目のステップです。 MCP ツールやスキルがすでに機能しているのと同じように、管理者以外のアカウントには、許可によって名前が付けられるまで、インストールされたアプリは表示されません。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.6...v1.5.7
