#ディープチューター v1.2.1

ディープチューター v1.2.1 Release Notes

発売日: 2026.04.21

ハイライト

チャットのステージごとのトークン制限と温度 (#348)

エージェント チャット パイプラインを agents.yaml のファーストクラス構成市民に昇格しました。新しい capabilities.chat ブロックは、ステージごとの max_tokens (responding、answer_now、thinking、observing、acting、react_fallback) および共有 temperature を公開し、services/config/loader.py::get_chat_params() を介して焼き付けられたデフォルトに深くマージされます。 responding と answer_now の予算は、以前のハードコーディングされた 1800 から 8000 にジャンプし、cli の長い回答の途中での切り捨てがなくなりました。内部的には、_ChatLimits.from_config はすべてのレガシー シェイプ (欠落しているキー、辞書ではなくスカラー、部分的なオーバーライド) を安定したデータクラスに強制するため、既存のインストールは YAML に触れることなく動作し続けます。 10 の新しい単体テストは、ローダーの解決、ディープマージの優先順位、データクラスの強制をカバーします。

最後の応答を再生成 — CLI、WebSocket、Web UI (#349)

すべてのエントリ ポイントで均一に動作し、前のユーザー メッセージを その場で 再実行する実際の regenerate フローを追加しました。

  • CLI — deeptutor chat REPL 内の /regenerate (エイリアス /retry)。
  • WebSocket — /api/v1/ws 上の type: "regenerate" メッセージ (capability、tools、knowledge_bases、language、config の場合はオプションの overrides)。
  • Web UI — アシスタントがチャット機能に応答する最後のターンに、メッセージごとの「再生成」ボタン (RefreshCcw アイコン) が表示されます。 バックエンドでは、TurnRuntimeManager.regenerate_last_turn は新しい SQLiteSessionStore.delete_message / get_last_message ヘルパーを介して後続アシスタントをロールバックし、start_turn を _persist_user_message=False および _regenerate=True とともに再利用するため、ユーザー行が重複せず、memory_service.refresh_from_turn が再度実行されることはありません。プリフライト チェックでは、サイレントに失敗するのではなく、致命的ではない regenerate_busy (別のターンが実行中) または nothing_to_regenerate (事前のユーザー メッセージなし) エラーが発生します。 _stage_responding LLM 呼び出しには、モデルがコンテンツを返さない場合に構造化された警告を表示する空応答診断も追加されました。 18 の新しいテストは、削除して再起動するフロー、メモリ更新スキップ コントラクト、および WebSocket ラウンドトリップの 3 つの拒否パスすべてをカバーします。

再生のための UI Harmony ポリッシュ

新しいボタンがチャット UI の残りの部分と一致し、サーバーが拒否された場合でも予想どおりに動作するように、2 つのフォローアップ調整を行いました。

  • i18n — Regenerate キーを web/locales/{en,zh}/app.json (Regenerate / 重新生成) に追加し、ChatMessages.tsx をハードコードされた "Regenerate" 文字列から t("Regenerate") に切り替えて、同じ行の既存の t("Copy") パターンと一致させました。
  • オプティミスティック ポップ ロールバック — サーバーが再生成リクエスト プリフライト (regenerate_busy / nothing_to_regenerate) を拒否した場合、オプティミスティック POP_LAST_ASSISTANT + STREAM_START プレースホルダーは、新しい RESTORE_ASSISTANT リデューサー アクションを介して復元されるようになりました。ポップされたメッセージはキーごとの pendingRegenerateRef に保持され、done または任意の端末結果でクリアされるため、トランスクリプトがユーザーの最後の応答を暗黙的に失うことはありません。

バグ修正

  • 明るいテーマでは読み取れない暗いコード ブロック (#352) — ハードコーディングされた #1f2937 / #292524 コード ブロックの背景を .prose pre (強制 #D6D3D1) および .prose code:not(.md-code-block__code):not(.md-inline-code) (var(--foreground) にオーバーライド) と組み合わせると、明るいモードで黒に近い背景に黒に近いテキストが生成されていました。テーマに関係なく #e5e7eb を固定する、より特異性の高い .md-renderer .md-code-block { ,pre,code } ルールを追加し、RichMarkdownRenderer および SimpleMarkdownRenderer フォールバックの <code> 要素を既存の md-code-block__code クラスでタグ付けして、:not() ガードが作動するようにしました。@DarkGenius に感謝します。
  • どの埋め込みも LlamaIndex パイプラインをクラッシュさせませんでした (#347、修正 #346) — 埋め込みプロバイダーがチャンクのベクトルに対して null を返すと、None がベクトル インデックスに入り、類似性の計算中に np.dot(NoneType) が爆発しました。 2 層の修正: _extract_embeddings_from_response は、get(key, default) の代わりに or [] を使用するようになりました。そのため、明示的な None 値が捕捉され、CustomEmbedding._get_text_embeddings はバッチ結果を検証し、None スロットをゼロ ベクトルに置き換えます。 @kagura-agent に感謝します。
  • Gemma モデルが json_object 応答フォーマットを拒否しました (#345、修正 #344) — LM Studio (および同様のローカル OpenAI 互換サーバー) を通じて提供される Gemma は、response_format={"type": "json_object"} が渡されると 400 "'response_format.type' must be 'json_schema' or 'text'" に応答します。 supports_response_format: False を既存の gemma MODEL_OVERRIDES エントリに追加して、json_object パスがスキップされるようにしました。 Visual エージェントと math-animator エージェントの既存の extract_json_object ユーティリティはすでにプレーン テキストから JSON を解析しているため、すべての呼び出し元はそれ以上変更することなく引き続き動作します。 @octo-patch に感謝します。

テストスイートの拡張

ネット +575 テスト行: チャット パラメータ ローダー / _ChatLimits 強制 (tests/services/config/test_chat_params_config.py) について 10 件、3 つの拒否パスすべてを含む再生成フロー、インプレース削除 + 再起動、メモリ更新スキップ、およびエンドツーエンドの重複ユーザーなしコントラクト (tests/services/session/test_regenerate.py) について 18 件、supports_response_format モデル オーバーライドについて 14 件(tests/services/llm/test_capabilities.py)、および None 埋め込み抽出パス (tests/services/embedding/test_extract_embeddings.py) の回帰テスト。

何が変わったのか

  • fix(rag): https://github.com/HKUDS/DeepTutor/pull/347 の @kagura-agent による LlamaIndex パイプラインの None 埋め込みに対するガード
  • 修正: https://github.com/HKUDS/DeepTutor/pull/345 の @octo-patch により gemma モデルの json_object response_format を無効にする
  • 修正 (Web): https://github.com/HKUDS/DeepTutor/pull/352 の @DarkGenius による明るいテーマの暗いコード ブロックで読みやすいテキストを確保
  • 特技 (チャット): ステージごとのトークン制限と温度をエージェント経由で設定可能にします。yaml by @DarkGenius in https://github.com/HKUDS/DeepTutor/pull/348
  • feat(チャット): https://github.com/HKUDS/DeepTutor/pull/349 の @DarkGenius による最後の応答 (CLI、WebSocket、Web UI) を再生成します
