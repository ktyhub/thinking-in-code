#ディープチューター v1.6.7

ディープチューター v1.6.7 Release Notes

発売日: 2026.09.11 v1.6.7 は、ほぼ完全にコミュニティ レポートとその背後にあるプル リクエストから組み立てられた修正リリースであり、19 件がここに統合されています。推論モデルという 1 つのスレッドがそのほとんどを実行します。空の 1 章として戻ってきた本、質問がまったく出なかったクイズ、モデル独自のスクラッチパッドを含む章本文は、3 つの顔を備えた同じ失敗であることが判明しました。つまり、隠れた思考に費やされたトークンの予算が、答えのための何も残っておらず、そう言う間違いもありません。ドロップイン - 移行はありません。

新機能

本が 1 つの空の章として到着しなくなる

ブック生成は、構成レイヤーが知らない名前でトークン設定を要求したため、agents.yaml を開く前にハードコーディングされた 4096 を返しました。これは、ユーザーが調達できない予算であり、推論モデルがすべて非表示のトークンに費やすことができる予算です。空の応答は空のオブジェクトとして解析され、単一のプレースホルダーの章に分解されます。予算が途中で使い果たされたため、他の報告された形状が作成され、各章の目的は空白のままでした。 Book は構成マップに接続され、12000 でシードされ、要求されたキーなしで返されたラウンドは、より低い推論労力で 1 回再試行されます。この再試行は、以前はブロック ライターに対してのみ存在していました。 4 つのパイプライン ステージすべてがそれを共有するようになりました。

モデルのスクラッチパッドがリーダーに届かなくなる

非ストリーミング パスは、答えが空の場合は常にモデルの推論を答えとして返しました。ストリーミング パスは同じことを明示的に禁止していたため、1 つの決定が 2 つのコード パスにわたって矛盾しました。これとは別に、明示的な「何も考えない」リクエストは、各モデルが実際に受け入れるものに絞り込まれています。gemini-3 と gemini-2.5-pro は none に対する HTTP 400 に応答し、読者に面したブック ブロックはまさに​​それを要求します。

思考モデルはターンを超えて推論を維持します

ラウンドの reasoning_content をプロバイダーにリプレイすることは、deepseek を含むモデル名に基づいて制限されていました。モデル名は、プロバイダーがその方言を発表する方法ではありません。Volcengine Ark はエンドポイント ID を取得し、Doubao、GLM、Qwen、および Kim の思考モデルはそれぞれ独自のモデルを使用します。新しいターンが履歴を再生した瞬間にそれらはすべて失敗しましたが、1 つのターン内の同じラウンドは機能しました。ゲートは、プロバイダーがフィールドを送信したかどうかです。

クイズは何も言わずに何も生成しなくなる

計画ステップには、パイプライン内で最も厳しいトークン バジェットがあり、思考が切り詰められた計画は、何も言わずにモデルと同じ空の文字列を返しました。テンプレートがゼロということは、質問がゼロであり、エラーも発生しないことを意味します。 2 つのケースが区別できるようになり、枯渇した計画はより少ない労力で再試行され、予算は外れ値ではなくなりました。

失敗したツールは何が問題だったかを示します

「rag の実行中に不明なエラーが発生しました。」チャット、調査、質問を通じて、モデルに到達する途中で真の原因を置き換えました。原因はメッセージとともに伝わるようになりました。これは、停止したローカル埋め込みサービスが表示されないという報告されたケースをカバーしています。アダプターは常にエンドポイントと救済策に名前を付けており、テキストはその上のレイヤーで破棄されていました。接続を拒否するセルフホスト型エンドポイントも、2 つの問題のうちどちらが間違っているかを通知するようになりました。つまり、何もリッスンしていない、または localhost がモデルを提供するマシンではないコンテナーです。

数式は、学習者が読んだ場所に表示されます

熟達した質問カード、ask_user カード、推論トレースには、生のテキストとして $G_t = R_{t+1} + \gamma G_{t+1}$ が印刷されました。トレースの最悪の状況は、ガードによってリッチ レンダラーからトレースが除外され、そのレンダラー自体のトレース ブランチが 3 月以来アクセス不能になってしまったということです。サーフェスが数学をレンダリングするかどうかは、どのサーフェスであるかではなく、コンテンツによって決定されるようになりました。そのため、数学のないバブルは依然として安価な方法を選択します。

実際に提出できるカード

多肢選択オプションのないマスタリーの質問では、表示されなかったフィールドから回答が読み取られるため、送信は永久に無効のままになります。そして、ask_user カードに保留されたターンは、応答できるものが何も生きていない状態でセッションを所有したままになる可能性があります。その後のすべてのメッセージは拒否されます。両方の半分は修正されています。放棄されたターンは応答が到着すると再利用され、それらの行を作成したターミナル状態チェック (running のみを受け入れ、人を待つターンは決して受け入れられません) はもう行われません。

読み取り、視覚化、インポート

イマーシブ リーディングには PDF.js デコーダー アセットが同梱されるため、JPEG 2000 および JBIG2 のページ画像が空白になることがなくなりました。 GeoGebra は、既知の致命的なコマンド パターンを評価前に拒否し、これまで飲み込んでいた失敗を表面化し、モデルに到達する前に画像解析がクラッシュすることがなくなりました。 Codex 履歴のインポートは現在のロールアウト形式を読み取り、Codex がそれ自体に挿入するターン (プラグイン マニフェストなど) が最初のメッセージや会話のタイトルになることはなくなりました。

名前を付ける価値のある小さな修正

ストリーミングされたプロバイダー エラーは、アシスタントの回答として配信されるのではなく、発生します。 API キー プールは構成リゾルバーを通過しても残ります。 read_skill は、両方を「スキルが見つかりません」として報告するのではなく、不足しているファイルと不足しているスキルを区別します。コマンド ID は、crypto.randomUUID が未定義のプレーン HTTP デプロイメントで機能します。ルータがどちらのモダリティ ペアもサポートしていない場合、イメージ生成はイメージのみを再試行します。調査ツールのタイムアウトと再試行の設定は、現在はまったく尊重されており、ツールのトリップが遅い場合ではなく、停止したプロバイダーの上限がデフォルトで設定されています。設定の準備状況は読み取り専用ユーザー向けにレンダリングされ、チャットは添付された PDF 用に作成されたツール呼び出しを回復し、監視トランスクリプトはアクティブなキューを画面外に押し出すのではなく追跡します。

アップグレードに関する注意事項

pip install -U deeptutor を実行します。 Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。何も移行する必要はありません。

  • 書籍のトークン バジェットが到達可能になりました。 agents.yaml の capabilities.book の下に存在し、12000 にシードされています。以前は 4096 で到達不能であったため、書籍はデフォルトで非常に長い入力を取得します。
  • リサーチ ツール ポリシーのデフォルトが変更されました — タイムアウト 60 秒 → 240 秒、再試行 3 → 0。リサーチ ツールは本質的に遅いため、再試行すると再び完全なタイムアウトが発生します。以前のバージョンでリサーチ設定を保存した場合は、保存された値が優先されます。新しいデフォルトを選択するには、それらをクリアします。
  • 既知の問題: このアップグレードの前に ask_user ターンが停止しても、セッションを保持できます。それらを作成するパスは閉じられていますが、既存の行は起動時にまだスイープされません。スイープは次のリリースで実行されます。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.6.6...v1.6.7
