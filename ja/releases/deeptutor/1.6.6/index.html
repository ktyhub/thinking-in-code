#ディープチューターv1.6.6

ディープチューター v1.6.6 Release Notes

発売日: 2026.09.08 v1.6.6 は修正リリースであり、珍しく明確なリリースです。 v1.6.5 のフィードバックを調べてみると、人々が報告したもののほとんどは回帰ではないことがわかりました。v1.6.5 では、古い破損を隠していたものがほとんど削除されたため、黙って送信されなかった回答、一度も成功しなかったと報告するコピー ボタン、v1.6.0 以来使用できなかった読み取りアクションがすべて一度に表示されるようになりました。これらは、背後にあるコミュニティのプル リクエストのバッチとともに、ここで修正されています。ドロップイン - 移行はありません。

新機能

送信した回答は実際に届きます

すでにターンが終了した ask_user カードはバックエンドに到達できないため、送信しても何も起こりませんでした。さらに悪いことに、3 人の作曲家は、投稿が拒否されたときに入力した内容を破棄し、エラーでは新しいメッセージを送信するように指示されましたが、それ自体がブロックされていました。どちらも修正されています。未回答のカードを所有している終了したターンはそのアドレスを保持し、拒否された回答は破棄されずに通常のメッセージとして再送信されます。 v1.6.3 以降、回答画像を含むノートブック エントリはまったく保存できませんでした。挿入では 22 の値に対して 23 列がリストされ、毎回 OperationalError が発生しました。

最初の負荷が著しく軽い

生成されたブランド アイコン テーブル (すべての店舗ロゴ、約 95 KB) は、1 つのフッター リンクのために、すべてのルートが共有するアプリシェル チャンクに組み込まれていました。それはリリースされ、サイドバーのセッション編成 UI と Co-Writer ノートブック ピッカーはオンデマンドでロードされるようになり、ホーム ルートは 300 KB の予算に対して 305 KB から 203 KB に減少しました。もう予算を超えるルートはありません。

コピーは実際にコピーします

コピー ボタンは、clipboard に何かが到達したかどうかに関係なく成功を報告し、aria-live を通じて誤った成功を通知しました。そのため、スクリーン リーダー ユーザーには、コピーが機能していないのにコピーが機能したことが知らされました。 Clipboard アクセスは、最初の await の前にプローブされるようになり (ユーザー ジェスチャ許容量の使用が早すぎることが根本的な原因でした)、実際の失敗は 1 つとして表示されます。

ナレッジベース: 名前、アップロード、空のベース

スラッシュを含む名前のナレッジ ベースは作成されても削除されない可能性があります。検証はマネージャー上で実行されるようになったため、8 つの登録エントリ ポイントすべてが検証を共有し、すでに存在する不正な名前を削除できます。転送中に「フェッチに失敗しました」というメッセージが表示されて失敗した大規模なアップロードも機能します。プロキシは client の Expect: 100-continue ヘッダーを再生していましたが、undici はこれを完全に拒否しました。空のナレッジ ベースを作成しても、進行状況エラーが発生しなくなりました。

パートナーは、接続されたナレッジ ベースを使用できます

Obsidian ボールト、リンクされたインデックス、WeKnora、または IMA をパートナーに割り当てると、完全に失敗していました。プロビジョニングではフォルダーをコピーする方法しか知られておらず、ポインターのナレッジ ベースには設計上何もありませんでした。接続されたベースはポインターとして登録され、パートナーのライブラリーに表示されたままになり、再び削除できるようになります。 Obsidian、MarginNote、およびサブエージェント ベースは意図的に declined です。それぞれがパートナーのすべてのターンを引き継ぐ排他的な機能を駆動します。 パートナーがチャットで提示するファイルは、質問した人にダウンロードされ、パートナーの会話にはどのチャットから来たのかが表示されるようになったので、Feishu グループのスレッドとダイレクト メッセージが区別できなくなりました。

チャットが持っていないツールにアクセスできなくなる

read_source は、ループ自体ではなく、応答ループの前に実行されるコンテキスト調査プログラムに属します。プロンプトと添付ソースのマニフェストにはそうではないと書かれていたため、モデルは与えられていないファイル ツールを使用して PDF を再度開こうとし続けました。

推論が欠けていたところに到達する

共有エージェント ループはラウンドの推論をまったくキャプチャしなかったので、その結果タイプにフィールドが存在しなかったので、その上に構築された書籍クイズなどのサーフェスは、コンテンツではなくプロバイダ推論エラーを表面化しました。それは今も貫かれています。

Codex のサインインは Docker 内で終了します

ブラウザーがコンテナーのループバック コールバックに到達できない場合は、ブラウザーが到達したアドレスを貼り付けてサインインを完了できます。貼り付けたアドレスは、その試行に対して登録されたリダイレクト URI と正確に一致する必要があり、重複した OAuth パラメータはあいまいとして拒否されます。これは解析されて破棄され、取得、保存、エコーバックされることはありません。カタログ互換バージョンも引き上げられ、旧バージョンでは省略されていた対象機種も登場するようになりました。

名前を付ける価値のある小さな修正

テキスト選択を必要とする 4 つの読み取りアクションは、v1.6.0 以降、マウスでは使用できなくなりました。click が起動される前に、注釈ポップオーバーによってツールバーが解除されました。講師に別の言語を尋ねることはうまくいき、その好みのブラウザとサーバーのコピーが乖離することはなくなります。 Mastery Path は、パスを再バインドするツールとして mastery_mode を認識します。学習者アカウントはコースを再度開くことができます。不正な形式の ###heading テキストは、コード フェンス内の #include に触れることなく正規化されます。

修正

Moonshot Kim k3 ファミリは、リリースされた ID ごとではなく 1 回名前が付けられるため、k3-256k 以降のバリアントでは温度オーバーライドが維持されます。サポートされていない input[N].status に対して拒否された応答リクエストは、それを使用せずに 1 回再試行し、モデルを記憶します。 LightRAG SDK はリリース候補から 1.5.7 に移動します。 README の概要のスクリーンショットは最新のものです。

アップグレードに関する注意事項

pip install -U deeptutor を実行します。 Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。何も移行する必要はありません。

  • v1.6.4 にロールバックしても、この問題はほとんど修正されません。 これらの欠陥のほとんどは v1.6.5 より前に発生したものです。知識ベースの命名とマスタリー パスの問題のみが真に新しい v1.6.5 表面積を持っています。
  • カスタム プロンプトまたはプラグインが応答ループに read_source を呼び出すように指示した場合、その作業をコンテキスト調査員に移動します。ループはそれをマウントしません。
  • 英語と中国語のガイドを deeptutor.info でまとめて更新しました。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.6.5...v1.6.6
