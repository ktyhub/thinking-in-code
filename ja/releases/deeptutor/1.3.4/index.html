#ディープチューター v1.3.4

ディープチューター v1.3.4 Release Notes

発売日: 2026.05.01 v1.3.4 は、ブック エンジンとチャット ワークスペースをより緊密な学習ループに変えます。 本のページは独自の永続的なチャット セッションを実行できるようになりました。 既存の背表紙から再構築され、定期的なチャット ターンでは選択した本を引用できます スペースコンテキストと並んでいるページ。このリリースでは言語の一貫性も向上しています。 DeepSeek スタイルの推論出力処理、RAG 用のドキュメント抽出、ロギング インフラストラクチャ、および DeepTutor の arXiv 論文に関する公開ドキュメント。

ハイライト

ブック エンジン、ページ チャット、および書籍の参照

本の生成と読書では、ユーザーのコンテキストがより多く保存され、 最初からやり直すことなく、生成されたブックを反復処理することが容易になります。

  • 予約ページのチャットは統合ストリーム プロトコルを使用します - ページ チャット パネルが追加されました 共有 WebSocket client と、メインによって使用されるストリーム イベント レンダラーを使用します。 チャット ワークスペース、つまりツール出力、アシスタント イベント、添付ファイル、および復元 セッション履歴は一貫して動作します。
  • ページ チャット セッションは本のページごとに保持されます - 各ページは、 新しいページチャットセッション API を介してチャット session_id を行い、 リーダーは、利用可能な場合はページの会話を復元します。
  • 承認された背表紙から書籍を再構築できます - 新しい再構築フローがクリアされます 確認したアウトラインを維持したまま、ページのコンテンツと進行状況を生成し、 その構造からコンパイルを再開します。
  • 単一ページの再生成により学習者のメモが保持されます - 強制的に再コンパイルすることができます。 ユーザーが作成したメモブロックとキーを保持しながら、生成されたコンテンツをリセットします 遷移メタデータ。
  • 通常のチャットでは本のページを引用できます - チャット作成者は選択したページを添付できます ブックとページをリクエスト コンテキストとして保持し、ターン スナップショットに保存し、復元します。 セッションがハイドレートすると、それらは取り外し可能なコンテキスト チップとして表示されます。
  • 書籍のコンテキストが推論モデルにとってより明確になりました - 選択された書籍のページは 思考タグが削除される前に、境界付きテキスト参照に変換されます。 チャットまたはページサイドの会話に挿入されます。

チャット言語と推論モデルの動作

チャット ターンは、ユーザーの現在の言語設定により確実に従うようになり、 推論コンテンツを異なる方法で返すプロバイダーに対してより寛容になります。

  • 言語は各チャット ターンの一部です - WebSocket リクエストは 現在の言語、およびエージェント チャットとクラシック チャットの両方に明示的な追加 言語の指示により、回答がアクティブな UI 言語と一致するようになります。
  • 現在のアプリ言語を使用して再生成して応答します - 新しいターンと 再生成されたターンは、のみに依存するのではなく、最新の保存言語を読み取ります。 古いセッション設定。
  • DeepSeek スタイルの空のコンテンツ応答の回復が向上 - OpenAI 互換 モデルが空の値を返した場合、プロバイダーは reasoning_content にフォールバックできます。 content フィールドが表示されます。
  • 本のブロックを書くことで推論の労力を調整できます - LLM 支援のブックブロック 世代が reasoning_effort を通過するようになり、構造化された JSON の再試行が可能になりました。 推論を重視したモデルが解析可能な JSON を返せない場合の労力が軽減されます。

RAG、ドキュメント、ナレッジベースのリカバリ

ドキュメントの取り込みでは、より多くのファイル タイプにわたって同じ抽出パスが使用されるようになりました。 より多くの回復状態で再インデックスを利用できるようになります。

  • Office ファイルはパーサー抽出を通じてルーティングされます - .xlsx および .pptx ファイル スプレッドシートとパーサーを利用したルーティング パスで PDF と DOCX を結合するようになりました。 ダウンストリーム RAG ロジックで使用できるプレゼンテーション カテゴリ。
  • LlamaIndex の読み込みでは共有ドキュメント抽出が使用されます - パーサー経由のファイル extract_text_from_path() を通じて読み取られ、ファイル タイプ固有のサイズが使用されます 制限を設け、インデックス作成時に不必要な文字の切り捨てを回避します。
  • DOCX 抽出には安全なフォールバック パスがあります - python-docx が読み取れない場合 ファイルの場合、エクストラクターは、代わりに defusedxml を通じて OOXML コンテンツを解析できます。 すぐに失敗する。
  • ナレッジ ベースの再インデックス コントロールはそれほど脆弱ではありません - Web UI で公開される可能性があります すでに実行されているものを必要とせずに、エラーおよび不一致状態に対するアクションのインデックスを再作成します。 ソースドキュメントが利用可能な限り、RAG ランタイムが初期化されます。
  • スキャンされたドキュメントまたは空のドキュメントはより明確に失敗します - 抽出と検証 バイト制限、文字制限、空の解析コンテンツ、および サポートされていないパーサーの結果の一貫性が向上しました。

設定、実行時状態、およびログ

このリリースでは、長時間実行されるローカルに必要なインフラストラクチャのクリーンアップが継続されます。 そしてサーバーの展開。

  • 設定では実行時の状態がより明確に表示されます - バックエンド、LLM、埋め込み、検索 ステータスは、オンライン状態、タイムスタンプ、ランタイムを含むサービス カードとして表示されます。 モデルの詳細と適用保留インジケーター。
  • LLM_REASONING_EFFORT は構成可能 - 推論作業を提供できます 環境構成を通じて実行され、実行時の概要に含まれます。
  • ロギングでは標準のロガー サーフェスを使用します - ルーター、エージェント、プロバイダー、RAG コードと TutorBot の統合は古いカスタム ロガー モジュールから移行します。 標準的な logging.getLogger(__name__) の使用に加えて、焦点を絞った Loguru に向けて 橋。
  • 生の RAG デバッグ ログの転送が静かになります - RAG サービスは廃止されました 低レベルのロギング ハンドラー出力をユーザー向けのイベント ストリームに転送します。 デフォルト。
  • CI と lint のカバレッジが更新されました - ワークフローとテストの変更により、 ロギング構成パス、プロセスログストリーミング、および lint の一貫性。

ドキュメントとローカリゼーション

プロジェクトのドキュメントには紙のリリースが反映され、ローカライズされた状態が維持されます。 最新のリリース リズムに合わせた README ファイル。

  • arXiv ペーパーは README からリンクされています - メインの README バッジとニュース セクションは 2604.26962 を指すようになりました。
  • ローカライズされた README が更新されました - 翻訳された README ファイルには、 最新のリリース リスト、arXiv/ニュースの更新、および拡張された言語ナビゲーション。
  • 予約、チャット、設定、コピーの再構築はローカライズされています - 英語と中国語 アプリ文字列は、新しいブックチャット、再構築、言語、添付ファイル、および 実行時状態の表面。

テスト

  • ターンごとの言語ディレクティブに対するチャット言語プロンプトのカバレッジを追加しました。 言語を認識したエージェント チャット動作。
  • ブック コンテキスト抽出、ページ チャット セッション用のブック エンジン カバレッジを追加しました バインディング、再構築制御、強制ページ再コンパイル、および LLM JSON 書き込み。
  • パーサー ルーティング ファイル、Office に対する RAG およびドキュメント ローダーのカバレッジを追加しました。 抽出パス、ファイル サイズ制限、および再インデックス適格性ヘルパー。
  • LLM_REASONING_EFFORT、OpenAI 互換のプロバイダー/ランタイム カバレッジを追加 フォールバック動作の推論、およびプロバイダーのランタイムの概要。
  • 設定、コンテキスト伝播、Loguru ブリッジングのためのログ テストを追加しました。 プロセスログの抽出とタスクログのストリーミング。
  • ドキュメントの添付ファイルの処理、バージョンのレポート、 およびナレッジベースの再インデックスヘルパーの動作。

アップグレードに関する注意事項

  • CLI およびサーバーのインストールでは、アップグレード後に依存関係を更新する必要があります。 CLI 追加の requirements/cli.txt には、より安全のために defusedxml>=0.7.1 が含まれるようになりました。 Office ドキュメント抽出時の XML 解析。
  • カスタム WebSocket client は、順番に book_references および language を渡すことができます メッセージを開始します。 Cliリクエストのスナップショットを保持するentsはブックを保存する必要があります ノート、歴史、スキル、記憶、添付ファイルと並んで参考資料。
  • 推論モデルを使用するデプロイメントでは、LLM_REASONING_EFFORT を調整するように設定できます 世界規模での推論努力。プロファイルごとおよびモデルごとの値は引き続き利用可能です 優先度の低いフォールバックとして。
  • 生の RAG デバッグ ログ イベントを消費する統合は、構造化されたデータに依存する必要があります。 低レベルの転送されたロガー出力の代わりに、ステータスおよびツールのイベントを実行します。
  • 書籍 client は、新しいページ チャット セッションを呼び出し、API を再構築する必要があります。 ページレベルの会話の永続性またはスパインを保存する再生成が必要です。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.3.3...v1.3.4
