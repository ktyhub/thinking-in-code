opentelemetry-java-instrumentation v2.28.0

opentelemetry-java-instrumentation v2.28.0

このリリースは、OpenTelemetry SDK 1.62.0 を対象としています。

多くのアーティファクトには、今後も重大な変更が加えられることを反映して、バージョン番号に -alpha というサフィックスが付いていることに注意してください。詳細については、VERSIONING.md を参照してください。

⚠️ 不安定な API に対する重大な変更

  • 古い ExperimentalInstrumentationModule.injectClasses(ClassInjector) パスで使用されていた古い内部 ClassInjector/ProxyInjectionBuilder API を削除しました。代わりに ExperimentalInstrumentationModule.exposedClassNames() を使用してください。 (#18112)
  • 以前に非推奨になった非安定な API メソッドと、非推奨の opentelemetry-runtime-telemetry-java8 および opentelemetry-runtime-telemetry-java17 ライブラリ エイリアスを削除しました。 (#18136)
  • 以前に非推奨となった captureEventName ライブラリ ビルダー設定を logback-appender-1.0 および log4j-appender-2.17 OpenTelemetryAppender、および対応する otel.instrumentation.{logback-appender,log4j-appender,jboss-logmanager}.experimental.capture-event-name javaagent プロパティから削除しました。代わりに、MDC / コンテキスト データ / キーと値のペア / Logstash マーカー / 構造化引数で otel.event.name キーを使用してください。 (#18223)
  • 以前に非推奨となった実験的な構成プロパティ otel.instrumentation.http.client.experimental.redact-query-parameters および otel.instrumentation.common.experimental.db-sqlcommenter.enabled を削除しました。代わりに otel.instrumentation.sanitization.url.experimental.sensitive-query-parameters および otel.instrumentation.common.db.experimental.sqlcommenter.enabled を使用してください。 (#18229)
  • 非推奨の otel.instrumentation.servlet.experimental.add-trace-id-request-attribute プロパティを削除しました。代わりにotel.instrumentation.servlet.experimental.trace-id-request-attribute.enabledを使用してください。 (#18237)
  • ktor Experimental ヘルパーを companion object のクラスからトップレベルの object に再形成しました。 Kotlin ソース呼び出し元 (Experimental.emitExperimentalTelemetry(...)) は影響を受けませんが、プリコンパイルされたコンシューマーは新しいアーティファクトに対して再コンパイルする必要があります。 (#18343)

🚫 非推奨

  • otel.instrumentation.jaxws-cxf-3.0.enabled を廃止して otel.instrumentation.jaxws-2.0-cxf-3.0.enabled を、otel.instrumentation.jaxws-metro-2.2.enabled を廃止して otel.instrumentation.jaxws-2.0-metro-2.2.enabled を廃止します。 (#18184)

🌟 新しい Javaagent インストルメンテーション

  • RPC client およびサーバー スパンとメトリック用の Apache Thrift 0.13 インストルメンテーションを追加します。 (#18405)

🌟 新しいライブラリのインストルメンテーション

  • RPC client およびサーバー スパンとメトリック用の Apache Thrift 0.13 ライブラリ インストルメンテーションを追加します。 (#18405)

📈 機能強化

  • Couchbase 3.1 javaagent インストルメンテーションは、otel.instrumentation.common.v3-preview が有効な場合、io.opentelemetry.javaagent.couchbase-3.1 ではなく、より従来のインストルメンテーション スコープ名 io.opentelemetry.couchbase-3.1 を発行するようになりました。 (#18426)
  • otel.instrumentation.common.v3-preview が有効な場合、Wicket リソース リクエストはサーバー スパン名でリソース参照クラス名を使用するようになりました。 (#18312、#18775)
  • Javaagent ヘルパー クラスをアプリケーション クラス ローダーに挿入するか、インストルメンテーションで使用されるアドバイス クラスに基づいて分離するかを決定します。 (#17815)
  • 追加の mountinfo レイアウトをサポートし、複数の候補 ID が見つかった場合に警告することで、Podman の cgroup v2 コンテナ ID 検出を改善しました。 (#18272)

🛠️ バグ修正

  • Pekko HTTP および Tapir サーバー ルート トラッキングを修正し、サーバー スパン名と http.route がネストされたディレクティブ、例外、およびタイムアウトにわたって最も具体的に一致したルートを保持するようにしました。これにより、影響を受けるルートのスパン名と http.route 値が変更される可能性があります。 (#16390)
  • Netty から Finagle へのリクエスト変換および twitter-util Future/Promise 非同期境界にわたる Finagle HTTP インストルメンテーションのコンテキスト損失を修正しました。 (#17867)
  • 仮想スレッド上で実行されている弱いマップの古いエントリのクリーンアップによって引き起こされる仮想スレッドの固定を修正します。クリーンアップは代わりにバックグラウンド スレッドから実行されるようになりました。 (#18113)
  • レコードまたはメッセージに伝播ヘッダーがない場合は、バッチ コンシューマ スパンをアンビエント コンシューマ スパンにリンクしないようにします。 (#18154)
  • Reactor 3.1 の resetOnEachOperator() を修正し、インストルメンテーションが無効になっているときにスケジューラ フックも削除されるようにします。 (#18258)
  • RxJava 1.0 サブスクリプションが同期的にスローされるときにスパンを終了します。 (#18265)
  • Spring Boot サービス バージョンの自動検出を修正し、BOOT-INF/classes/ ではなく META-INF/build-info.properties が jar ルートから読み取られるようにしました。 (#18292)
  • Netty 3.8 サーバー計装での応答が終了した後、Netty VirtualField をクリアします。 (#18358)
  • アーカイブおよび埋め込み jar の読み取り中に JarFile ハンドルを閉じるように JarDetails を修正し、ランタイム テレメトリ収集中のリソース リークを防止します。 (#18385)
  • アプリケーション コンテキストが関連付けられていないエージェント コンテキストをアプリケーション コンテキストに変換するときの NullPointerException を修正しました。 (#18444)
  • 不完全なコルーチン コンテキストの復元によって引き起こされる OpenTelemetry コンテキスト リークを防ぐために、Ktor サーバー インストルメンテーションを修正しました。 (#18456)
  • 相対ルート パスの先頭にマウント ポイントを追加することで、Vert.x サブルータ http.route 属性を修正します。これにより、マウントされたサブルートのサーバー スパン名と http.route 値が変更される可能性があります。 (#18462)
  • oshi 7.0.0 による oshi メトリクスの起動と RSS メモリ レポートを修正しました。 (#18478)
  • Play 3.x アプリケーションでの Play MVC および Play WS インストルメンテーションを修正しました。 (#18624)
  • ラップされた Kafka コンシューマー poll() が失敗した場合のエラー受信スパンを記録します。 (#18625)
  • Byte Buddy のインストール前に WeakConcurrentMapCleaner を起動することで、エージェント起動中の弱いマップのクリーンアップを修正しました。 (#18628)
  • ブートストラップが再帰的に失敗することなくセキュリティ マネージャーで動作するように、indy インストルメンテーションを修正しました。 (#18634)
  • computeIfAbsent 中に古いエントリが消去されるときの弱いキャッシュでのデッドロックを回避します。 (#18635)
  • 宣言型構成カスタマイザーは、起動時に NullPointerException をスローせずに、欠落しているプロセッサーと検出器のリストを処理するようになりました。 (#18641)
  • Netty 3.8 および 4.0 インストルメンテーションで HTTP サーバー スパンが正しく終了しない可能性がある競合を修正しました。 (#18645)
  • JDBC URL ポートが null の場合は、NumberFormatException を避けてください。 (#18708)
  • Vert.x TaskQueue および OrderedExecutorFactory タスクの実行を修正し、スパン コンテキストがキューに入れられた実行可能ファイルに伝播されるようにしました。 (#18709)
  • 大きなバッチで db.statement 値が大きくなりすぎないように、Redisson バッチ クエリ テキストの長さを制限します。 (#18744)
  • SAP HANA 管理ステートメントのパスワード句が password 識別子を編集せずに編集されるように SQL クエリのサニタイズを修正しました。 (#18754)
