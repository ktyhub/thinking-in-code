opentelemetry-java-instrumentation v2.32.0

opentelemetry-java-instrumentation v2.32.0

このリリースは、OpenTelemetry SDK 1.66.0 を対象としています。

多くのアーティファクトには、今後も重大な変更が加えられることを反映して、バージョン番号に -alpha というサフィックスが付いていることに注意してください。詳細については、VERSIONING.md を参照してください。

⚠️ 不安定な API に対する重大な変更

  • 非推奨の HostIdResource.REGISTRY_QUERY 定数を削除します。 (#19778)
  • ExperimentalJmxMetricHandler SPI では、実装で getMetricNames() を提供する必要があります。 (#19781)
  • 必要な isRequestStreaming(REQUEST) メソッドを GenAiAttributesGetter に追加します。 (#19879)
  • 実験的な java.common.messaging.headers/development YAML セレクターは、ヘッダー キャプチャを構成しなくなりました。代わりに java.common.messaging.headers を使用してください。 (#20260)

🚫 非推奨

  • otel.jmx.target.system を廃止し、otel.jmx.metrics.experimental.included を採用します。 (#19783)
  • otel.instrumentation.elasticsearch.capture-search-query を廃止。検索クエリ本文が常にキャプチャされる場合、これは 3.0 で削除されます。代替品はありません。 (#19675)
  • otel.instrumentation.opensearch.capture-search-query を廃止。検索クエリ本文が常にキャプチャされる場合、これは 3.0 で削除されます。代替品はありません。サニタイズはデフォルトで有効のままであり、otel.instrumentation.opensearch.query-sanitization.enabled で構成可能です。 (#19837)
  • 他のインストルメンテーション有効化プロパティに合わせて、otel.jmx.enabled を廃止し、otel.instrumentation.jmx.enabled を優先します。 (#19945)
  • インライン Javaagent アドバイスでの VirtualField.find(Class, Class) 呼び出しの自動書き換えを非推奨にします。代わりに、VirtualField を一度検索して、ヘルパー クラスの static final フィールドに格納します。 find メソッド自体は引き続きサポートされます。 (#19980)
  • Elasticsearch REST ライブラリ インストルメンテーションを非推奨にします。 Elasticsearch Java API Client のネイティブ OpenTelemetry サポート、または RestClient を直接使用するには Java エージェントを使用します。 Java エージェントのインストルメンテーションは影響を受けません。 (#19995)
  • otel.instrumentation.messaging.experimental.receive-telemetry.enabled を廃止し、otel.instrumentation.common.messaging.experimental.receive-telemetry.enabled を採用します。ヘッダーについては、otel.instrumentation.messaging.experimental.headers.included および .excluded を otel.instrumentation.common.messaging.headers.included および .excluded に置き換えます。また、otel.instrumentation.messaging.experimental.capture-headers を廃止し、otel.instrumentation.common.messaging.headers.included を採用します。安定したセレクターはリーフごとに優先されます。 (#20060、#20260)
  • 安定した統合された otel.instrumentation.common.logging.structured-attributes.included / .excluded を優先して、otel.instrumentation.log4j-appender.experimental.map-message-attributes、otel.instrumentation.logback-appender.experimental.key-value-pair-attributes、otel.instrumentation.logback-appender.experimental.logstash-marker-attributes、および otel.instrumentation.logback-appender.experimental.logstash-structured-argument-attributes の .included / .excluded プロパティを非推奨にします。 (#20066)
  • otel.instrumentation.couchbase.experimental-span-attributes を非推奨にし、基盤となる Couchbase client の実験的な属性と内部スパンのより広い名前である otel.instrumentation.couchbase.emit-experimental-telemetry を採用します。 (#20117)
  • 代替のない宣言型 rule_based_routing を備えた otel.traces.sampler=linksbased_parentbased_always_on を非推奨にし、構成とマッチング動作が異なる SDK インキュベーター複合/開発 rule_based サンプラーを優先します。 (#20249)
  • コントローラーとビューのテレメトリ構成を安定したプロパティ otel.instrumentation.common.controller-telemetry.enabled および otel.instrumentation.common.view-telemetry.enabled にプロモートし、otel.instrumentation.common.experimental.controller-telemetry.enabled および otel.instrumentation.common.experimental.view-telemetry.enabled を非推奨にします。 (#20258)
  • Java エージェントのスパン抑制構成を安定したプロパティ otel.instrumentation.common.span-suppression-strategy にプロモートし、otel.instrumentation.experimental.span-suppression-strategy を非推奨にします。 (#20259)
  • otel.instrumentation.oshi.experimental-metrics.enabled、ProcessMetrics、およびその registerObservers(...) メソッドを廃止し、jvm.memory.used および jvm.cpu.time を採用します。 (#20323)
  • OSHI ライブラリ インストルメンテーションの SystemMetrics.registerObservers(Meter) を非推奨にし、SystemMetrics.registerObservers(OpenTelemetry) を優先します。 (#20263)
  • 宣言型構成 YAML では、distribution.javaagent.instrumentation.enabled および .disabled リストのドット付きセレクターを非推奨にします。 reactor_3.1 の代わりに reactor_3_1 を使用してください。 otel.instrumentation.reactor-3.1.enabled などのフラット プロパティ名は変更されません。 (#20326)

🌟 新しい Javaagent インストルメンテーション

  • 2.3.0 から 3.25 までのバージョンに Redisson データベース接続プール メトリックを追加します。 (#19152、#19634)
  • Pekko リモーティング用の Java エージェント インストルメンテーションを追加して、トレース コンテキストがリモート呼び出し全体に伝播されるようにします。 (#19823)

📈 機能強化

  • otel.semconv-stability.opt-in=database の背後にある今後の 3.0 データベース セマンティック規則を拡張します。これには、構成されたサーバー ターゲットとスパン名、エンドポイント検証、ネットワーク ピア属性、Redis 名前空間、操作名、エラー タイプ、クエリ テキスト、接続プール メトリック名と、Cassandra、ClickHouse、Couchbase、Elasticsearch、Geode、HBase、JDBC のデータベース ID が含まれます。 Redis clients、MongoDB、OpenSearch、R2DBC、Spymemcached、および Vert.x。 (#19728、#19747、#19749、#19753、#19757、#19795、 #19830、#19831、#19832、#19834、#19838、#19839、 #19844、#19845、#19846、#19848、#19850、#19864、 #19868、#19872、#19877、#19883、#19901、#19902、 #19903、#19904、#19981、#19983、#19986、#19988、 #20008、#20011、#20015、#20017、#20041、#20065、 #20068、#20070、#20071、#20072、#20073、#20074、 #20075、#20076、#20077、#20078、#20080、#20082、 #20084、#20086、#20089、#20105)
  • otel.semconv-stability.opt-in=messaging の背後にある今後の 3.0 メッセージング セマンティック規約を拡張します。これには、操作ベースのスパン、client およびプロセス メトリック、メッセージごとのバッチ作成と伝播、一貫したタイムスタンプ、永続的なサブスクリプション名、および Camel、Kafka Connect、JMS、SQS、および RocketMQ の重複処理の抑制が含まれます。 (#19483、#19485、#19503、#19517、#19915、#20045、 #20067、#20144)
  • クラスターのメタデータが解決されると、Kafka のスパンとメトリックに messaging.kafka.cluster.id が含まれるようになりました。 (#18978)
  • SQL データベース属性を AWS SDK v2 RDS データ API ExecuteStatement および BatchExecuteStatement スパンに追加します。 (#19259)
  • 無効または空の拡張子の場所と失敗した拡張子 JAR ロードの WARNING ログと、正常にロードされた拡張子 JAR の FINE ログを追加します。 (#19584)
  • JMX メトリック ライブラリには、実験的な Kafka ブローカー メトリック ターゲットが含まれるようになりました。 (#19722)
  • kafka.connect.connector.status および kafka.connect.task.status の説明を更新して、リストされているサポートされている状態の値を省略しました。 (#19724)
  • リージョンのプールに構成されたサーバーが 1 つだけある場合、Geode データベース client スパンには server.address と server.port が含まれるようになりました。 (#19748)
  • HBase データベース clients、SofaRPC clients およびサーバー、および otel.semconv.exception.signal.preview=logs を使用した GWT RPC に対する例外ログのサポートを追加します。 (#19750、#20253、#20254)
  • server.address および server.port 属性を Couchbase データベース スパンに追加します。 (#19758)
  • ライブラリ内の otel.jmx.metrics.included および otel.jmx.metrics.excluded、または JmxTelemetryBuilder.setMetrics(IncludeExclude) を使用した JMX メトリクスのメトリクス名フィルタリングを追加します。 (#19782)
  • RabbitMQ スパンには、otel.instrumentation.rabbitmq.experimental-span-attributes=true の場合に messaging.rabbitmq.vhost.name と messaging.rabbitmq.cluster.name が含まれるようになりました。 (#19822)
  • JMX メトリック作成メッセージが INFO ではなく FINE でログに記録されるようになり、デフォルトのログ ノイズが減少します。 (#19825)
  • Akka HTTP サーバー スパンには、ネットワーク ピア アドレス属性にリモート ピア アドレスが含まれるようになりました。 (#19840)
  • Pekko HTTP サーバー スパンには、HTTP/1.1 および HTTP/2 リクエストのソケット ピアからの client.address が含まれるようになりました。 (#19841)
  • Spring WebFlux 5.0 client リクエスト期間メトリクスに network.protocol.version 属性を追加します。 (#19842)
  • Ratpack HTTP client スパンに network.protocol.version 属性が含まれるようになりました。 (#19843)
  • otel.instrumentation.opensearch.query-sanitization.enabled (デフォルトは true) を追加して、キャプチャされた検索クエリ本文をサニタイズするかどうかを制御します。 false に設定すると、そのままキャプチャされます。 (#19869)
  • リクエストがストリーミングを使用する場合、GenAI スパンには gen_ai.request.stream 属性が含まれるようになりました。 (#19879)
  • OpenAI Java 1.1 インストルメンテーションは、使用量の詳細が利用可能な場合、キャッシュされた入力トークン数を gen_ai.usage.cache_read.input_tokens として報告し、推論出力トークン数を gen_ai.usage.reasoning.output_tokens として報告するようになりました。 (#19906)
  • SDK 3.0.x をサポートするために Couchbase Java エージェント インストルメンテーションを拡張します。 (#19996)
  • ガードレール識別子が設定されている場合、aws.bedrock.guardrail.id スパン属性を AWS Bedrock Runtime リクエストに追加します。 (#20040)
  • otel.resource.providers.host-id.enabled=true を使用して、Java エージェントの host.id リソース検出をオプトインにします。 (#20099)
  • モード対応のセマンティック規約スキーマ URL をデータベース、メッセージング、および RPC テレメトリ スコープに追加します。 (#20127)
  • スキーマの対象となるランタイム JVM メトリクスにセマンティック規約スキーマ URL を追加します。 (#20255)
  • GraphQL 操作スパンでは、OpenTelemetry セマンティック規則 v1.44.0 スキーマ URL が使用されるようになりました。 (#20262)
  • semantic-conventions スキーマ URL を OSHI システム メトリクスに追加します。 (#20263)

🛠️ バグ修正

  • クラスローダーロック下での遅延コンテキストストレージ初期化によって引き起こされる Javaagent 起動デッドロックを防止します。 (#19265)
  • 高カーディナリティの NATS JetStream 決済スパン名を修正しました。従来のセマンティック規則に従って $JS.ACK publish を使用します。 (#19396)
  • 末尾委任された Kotlin @WithSpan メソッドのコンテキスト伝播を修正し、そのスパンが正しい呼び出し元コンテキストを保持するようにしました。 (#19446)
  • Camel の非同期送信を修正し、送信を開始したスレッドでコンテキスト スコープが閉じるようにしました。 (#19503)
  • リクエストが sendHead() でフラッシュされ、その後 end() で完了するときの Vert.x HTTP client トレースを修正し、サーバー スパンがエクスポートされた client スパンの親になるようにしました。 (#19547)
  • インストルメンテーションまたは JMX ルール解析間でエラー抽出をハングさせることなく、cyclic 例外原因チェーンを処理します。 (#19625)
  • キャプチャされた Elasticsearch REST Java エージェント検索クエリ本文をデフォルトでサニタイズし、クエリ構造を維持しながらリテラル値を ? に置き換えます。 otel.instrumentation.elasticsearch.query-sanitization.enabled=false でサニタイズを無効にします。 (#19675)
  • 重複した Pulsar リスナー インストルメンテーションを防止し、ネストされた配信中に重複した受信スパンを抑制し、スパンを処理するための親コンテキストを保持します。 (#19699、#20137)
  • Apache HttpAsyncClient パイプライン リクエストは、client スパンを生成するようになりました。 (#19710)
  • 同じ接続上で失敗したリクエストに続く非同期 Thrift サーバー リクエストが、誤ってエラーとして報告されることがなくなりました。 (#19712)
  • 両方のインストルメンテーションが有効になっている場合、Apache DBCP BasicDataSource をサポートするプールの重複する Apache Commons Pool メトリクスを抑制します。 (#19721)
  • otel.spring-starter.debug=true 時の Spring Boot スターター デバッグ ログを修正。 (#19725、#20034)
  • Spring Rabbit、RabbitMQ、Spring Integration 全体で重複した処理スパンとメトリクスを修正し、個別に登録されたコンシューマーと正しく親化されたハンドラー スパンのテレメトリを保持します。 (#19732、#20138、#20200)
  • Oracle UCP プール メトリックでは、生成された UCP 名の代わりに JDBC 由来の名前が使用されるようになり、同じデータベースに接続されているプールが一貫した pool.name 値に統合されます。 (#19745)
  • Lettuce 6.0.0 ～ 6.0.2 を使用する場合、client スパンの Redis コマンド名を設定します。 (#19763)
  • @SpanAttribute の処理を修正し、汎用値と配列がスパン属性として正しく記録されるようにしました。 (#19785)
  • 部分的に初期化された Jedis リクエストを終了するとき、または JSF がサーバー スパン名を導出できないときに、NullPointerExceptions を回避します。 (#19805)
  • クラスローダーのインストルメンテーションを修正し、javaagent がその書き換えられた java.lang.ClassLoader スタブをヘルパーとして挿入しなくなるようにします。 (#19811)

  • AWS Lambda インストルメンテーションは、受信トレースを継続するために Context.getXrayTraceId() から X-Ray トレース ヘッダーを抽出するようになりました。 (#19920)
