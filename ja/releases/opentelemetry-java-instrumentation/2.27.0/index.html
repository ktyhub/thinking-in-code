opentelemetry-java-instrumentation v2.27.0

マイナー 公開日2026年4月21日 出典open-telemetry/opentelemetry-java-instrumentation 英語原文

opentelemetry-java-instrumentation v2.27.0

このリリースは、OpenTelemetry SDK 1.61.0 を対象としています。

多くのアーティファクトには、今後も重大な変更が加えられることを反映して、バージョン番号に -alpha というサフィックスが付いていることに注意してください。詳細については、VERSIONING.md を参照してください。

⚠️ 不安定な API に対する重大な変更

  • AbstractKtorServerTelemetryBuilder.isOpenTelemetryInitialized() を保護 (以前は公開) にします。 (#17509)
  • ヘルパー クラスをアプリケーション クラス ローダーに公開するために、ExperimentalInstrumentationModule.injectClasses(ClassInjector) を exposedClassNames() に置き換えます。 (#17765)
  • WebApplicationContextInstrumentation を spring-web 計測モジュールから spring-webmvc に移動しました。 otel.instrumentation.spring-web.enabled=false で無効にしたユーザーは、otel.instrumentation.spring-webmvc.enabled=false を使用する必要があります。 (#17856)

🚫 非推奨

  • KafkaTelemetryBuilder.setMessagingReceiveInstrumentationEnabled(boolean) を非推奨にし、setMessagingReceiveTelemetryEnabled(boolean) を採用しました。 (#17092)
  • GraphQL ビルダー メソッド setSanitizeQuery() および setAddOperationNameToSpanName() が非推奨になり、設定キー otel.instrumentation.graphql.add-operation-name-to-span-name.enabled が setQuerySanitizationEnabled()、setOperationNameInSpanNameEnabled()、otel.instrumentation.graphql.operation-name-in-span-name.enabled に置き換えられました。 (#17093)
  • JDBC および R2DBC インストルメンテーションの Experimental.setEnableSqlCommenter() を非推奨にし、Experimental.setSqlCommenterEnabled() を優先します。 (#17094)
  • otel.instrumentation.servlet.capture-request-parameters を otel.instrumentation.servlet.experimental.capture-request-parameters に、otel.instrumentation.servlet.add-trace-id-request-attribute を otel.instrumentation.servlet.experimental.trace-id-request-attribute.enabled に名前変更します。古いプロパティ名は廃止されました。 (#17113)
  • 宣言型設定名 statement_sanitizer は query_sanitization に置き換えられ、宣言型設定グループ common.database は common.db に代わって非推奨になりました。 (#17116)
  • GraphQL 宣言型構成名 query_sanitizer を非推奨にし、query_sanitization を採用しました。 (#17455)
  • DB クエリ サニタイズ システム プロパティ名 otel.instrumentation.common.db-statement-sanitizer.enabled、otel.instrumentation.jdbc.statement-sanitizer.enabled、otel.instrumentation.mongo.statement-sanitizer.enabled、および otel.instrumentation.r2dbc.statement-sanitizer.enabled を非推奨にし、対応する *.query-sanitization.enabled 名を優先し、otel.instrumentation.common.experimental.db-sqlcommenter.enabled を非推奨にして otel.instrumentation.common.db.experimental.sqlcommenter.enabled を、otel.instrumentation.graphql.query-sanitizer.enabled を非推奨にして otel.instrumentation.graphql.query-sanitization.enabled に置き換えました。 (#17464)
  • InstrumentationModule.isIndyModule() を廃止します。 indy モードは、モジュールごとのオーバーライドではなく、エージェントの配布設定によって決定されるようになりました。 (#17713)

📈 機能強化

  • otel.instrumentation.common.v3-preview が有効な場合、MapMessage 属性から log4j.map_message. プレフィックスを削除します。 (#13871)
  • otel.instrumentation.common.v3-preview が有効な場合、メッセージング ヘッダー名の正規化 (ダッシュからアンダースコア) が停止されるため、キャプチャされたヘッダー属性キーは元のヘッダー名を保持するようになりました。 (#14554)
  • 安定したデータベース セマンティック規則が有効な場合に、Vertx SQL client インストルメンテーションに db.system.name 属性を追加します (otel.semconv-stability.opt-in=database)。 (#16254)
  • JDBC インストルメンテーションは、安定したデータベース セマンティック規則が有効になっている場合 (otel.semconv-stability.opt-in=database)、安定したセマンティック規則値 (postgresql、oracle.db、ibm.db2、sap.hana など) を持つ db.system.name 属性をサポートするようになりました。 (#16277)
  • 今後の 3.0 の重大な変更を早期に有効にする otel.instrumentation.common.v3-preview フラグを追加します。 (#16459)
  • 初期化時に属性キーを事前計算することにより、jboss-logmanager、log4j、および logback アペンダーでのログイベント MDC 属性マッピングを最適化しました。 (#16765)
  • otel.instrumentation.kafka.experimental-span-attributes が有効な場合、Kafka プロデューサー スパンに messaging.kafka.bootstrap.servers 属性を追加します。 (#17065)
  • otel.instrumentation.common.v3-preview が有効な場合、デフォルトでサーブレット トレース ID 要求属性を無効にします。 (#17173)
  • otel.instrumentation.common.v3-preview が有効な場合、デフォルトでスレッド詳細スパン プロセッサ (otel.javaagent.add-thread-details) が無効になります。 (#17215)
  • 論理和マッチャーを分解することで Javaagent 起動の最適化が改善され、クラスのロード中により多くの変換をスキップできるようになりました。 (#17227)
  • 安定した messaging.kafka.offset 属性を Kafka インストルメンテーションに追加し、otel.semconv-stability.preview=messaging の背後でゲートされます。 (#17785)
  • otel.instrumentation.common.v3-preview が有効な場合、属性キー内のサーブレット リクエスト パラメータ名の元の大文字と小文字が保持されます。 (#17822)
  • Byte Buddy の AgentBuilder.Default.transformations のリフレクション変異を ClassFileTransformer フックに置き換え、リフレクションを介した最終フィールドへの書き込みに関する JDK 26 JEP 500 の警告を回避します。 (#17824)
  • OpenTelemetry、API、1.61 安定メソッド (Tracer.isEnabled()、計量機器 isEnabled()、Logger.setBody(Body) など) に対する Javaagent ブリッジング サポートを追加します。 (#17849)

🛠️ バグ修正

  • OpenTelemetry トレース フィルター/インターセプターがすでに登録されている場合に、ユーザーがカスタマイズしたビルダー Bean が置き換えられないよう、WebClientBeanPostProcessor および RestClientBeanPostProcessor を修正しました。 (#15546)
  • アプリケーション側の計測器がガベージ コレクションされたときにブリッジされた監視可能なメトリック コールバックが閉じられないメモリ リークを修正しました。 (#16219)
  • restoreThreadContext が Ktor コルーチン機構によって常に呼び出されるとは限らないため、Ktor サーバー インストルメンテーションのリクエスト間でスコープがリークする問題を修正しました。 (#16487)
  • 不足していた schemaUrl をサーブレット応答インストルメンタに追加します。 (#16560)
  • クラスの初期化中に GlobalOpenTelemetry.get() を呼び出す OpenTelemetryContextDataProvider を修正しました。これにより、SDK セットアップの順序が妨げられる可能性がありました。 (#16638)
  • ファイバーサスペンド時に呼び出し側スレッドコンテキストを破壊する ZIO インストルメンテーションを修正。これにより、unsafe.run の後に作成されたスパンが親を失う原因となりました。 (#16647)
  • アペンダが別のアペンダ内にネストされている場合に、重複する OpenTelemetry ログバック アペンダを追加する Spring Boot スターターを修正しました。 (#16697)
  • Javaagent API ブリッジを介したスパンおよびログ レコード上の AttributeKey.valueKey() を介して設定された VALUE タイプの属性のブリッジングを修正しました。 (#16750)
  • リモート コード実行につながる可能性がある RMI インストルメンテーションにおける安全でない逆シリアル化を修正しました (CVE-2026-33701、#16986、2.26.1 でもリリースされました)
  • JDK 23+ で安全でないフォールバックの代わりに MethodHandles.Lookup を使用するように、httpurlconnection、methods、および rmi インストルメンテーションのブート ローダー クラス インジェクションを修正しました。 (#17050)
  • preferJfr が有効になっているが JFR が利用できない場合に JMX メトリクスにフォールバックするようにランタイム テレメトリを修正しました。 (#17058)
  • エラー処理中に応答オブジェクトが null の場合のサーブレット インストルメンテーションの NullPointerException を修正しました。 (#17087)
  • 非常に大きなコマンドによる過度のメモリ使用を防ぐために、サニタイズされた Redis コマンドの長さを 32 KB に制限します。 (#17139)
  • Dubbo の拡張ローダーによってフィルターが適切に検出されるように、Apache Dubbo 2.7 インストルメンテーション SPI リソース パスを修正しました。 (#17210)
  • Netty HTTP サーバー応答カスタマイズからの抑制されたエラーを飲み込むのではなく、ログに記録します。 (#17220)
  • Spring WebFlux サーバー ライブラリ インストルメンテーションでのキャンセルされたリクエストのスパン リークを修正しました。 (#17222)
  • 伝播が無効な場合に、setPropagationEnabled(false) を尊重し、メッセージ ヘッダーにトレース コンテキストを挿入しないように、Kafka でラップされたプロデューサーを修正しました。 (#17231)
  • loadClass の呼び出し中に computeIfAbsent がロックを保持することによって引き起こされる IgnoredClassLoadersMatcher のデッドロックを修正しました。 (#17241)
  • triggerListener がラムダにリファクタリングされた新しい Pulsar client バージョンで、Pulsar コンシューマ インストルメンテーションがメッセージ リスナーのインストルメントに失敗する問題を修正しました。 (#17405)
  • ProducerRecord ヘッダーが読み取り専用の場合 (レコードが 2 回目に送信された場合など)、Kafka プロデューサー ラッパーがコンテキスト伝播をサイレントにドロップする問題を修正しました。 (#17530)
  • アクティブ ハンドラーのコンテキスト キーが存在しない場合の Undertow インストルメンテーションの NullPointerException を修正しました。 (#17559)
  • HttpServerResponseCustomizer エラー分離を修正し、失敗したカスタマイザーによって後続のカスタマイザーの実行が妨げられないようになりました。 (#17617)
  • rocketmq-client-4.8 インストルメンテーションが ONEWAY メッセージのスパンを記録しない問題を修正しました。 (#17656)
  • otel.instrumentation.common.default-enabled が false に設定されている場合に内部アプリケーション ロガーがアクティブにならない問題を修正しました。 (#17657)
  • マイクロメーター タイマー ヒストグラム バケット境界をナノ秒からターゲット時間単位に変換する際の浮動小数点精度の問題を修正しました。 (#17715)
  • Spring Boot アクチュエーター メトリック モジュールが Spring Boot 4 のクラスパス上にない場合の MicrometerBridgeAutoConfiguration の ClassNotFoundException を修正しました。 (#17723)
  • RMI コンテキストの伝播制限を Tomcat のデフォルトに合わせて、最大エントリ数を 1000 から 100 に減らし、過度に大きなペイロードを防ぐために合計 8 KB のサイズ制限を追加します。 (#17870)
  • otel.instrumentation.runtime-telemetry.emit-experimental-metrics=true の場合に実験的な JFR ベースのメトリクスを無条件で有効にするランタイム テレメトリを修正しました。これにより、JMX ベースの実験的なメトリクスのみを必要とするユーザーに不要な JFR 記録のオーバーヘッドが課せられる可能性がありました。 JFR ベースの実験的メトリクスは、別の otel.instrumentation.runtime-telemetry.emit-experimental-jfr-metrics プロパティによってゲートされるようになりました。 (#18110)
