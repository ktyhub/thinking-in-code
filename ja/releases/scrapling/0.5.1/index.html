Scrapling v0.5.1

パッチ 公開日2026年11月4日 出典D4Vinci/Scrapling 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

v0.5.1 をスクラップする

小さなバージョンアップ、大きなブラウザアップグレード!このバージョンでは、AI エージェントがモーションを追跡し、ドラッグ アンド ドロップを制御できるようになり、専用のリモート ブラウザ セッションが追加され、解析、スパイダー、プロキシ、シェル全体にわたる修正が行われます 🚀

このアップデートにより、現在の AI モデルの制限が拡張されます 🔥

[!NOTE] 毎日のヒントやコツについては X でフォローしてください

[!警告] このリリースでは、リモート ブラウザ接続に重大な変更が導入されています。リモート ブラウザに接続するには、新しいブラウザ セッション クラスが必要になりました。更新する前に、リモート セッション移行ガイド を確認してください。

🚀 新しいものと生活の質の変化

  • AI エージェントが動きを追跡し、マウスをより細かく制御できるようになりました (ドキュメント を確認してください):

    • 動いているページを観察: 短いビデオを録画し、タイムスタンプ付きの一連のフレームとして共有すると、エージェントがアニメーション、移動コントロール、および 1 つのスクリーンショットでは見逃す可能性のある変更を理解できるようになります。これを既存のアクションを連鎖させる機能と組み合わせてください。
    • ドラッグ、検査、調整、ドロップ: マウス ボタンを押したまま項目またはスライダーを移動し、押したままページを検査し、調整して放します。左、右、中央のボタンをサポートします。
    • ログインしたリモート ブラウザを再利用するか、別のブラウザ コンテキストで開始して、エージェントがジョブに適切なセッションを選択できるようにします。
    • ツールの説明に費やすトークンを減らし、テキストを短くし、ガイダンスの繰り返しを減らします。

  • ログインの再利用を制御する専用のリモート ブラウザ セッション。 RemoteSession および AsyncRemoteSession は、HTTP または WebSocket CDP エンドポイントを介して既存の Chromium ブラウザに接続します。これらは、Cloudflare 解決を含む通常のステルス セッション機能をサポートします。どちらのクラスも対話型シェルでも使用できます。 (ドキュメント を確認してください)

    from scrapling.fetchers import RemoteSession

with RemoteSession(cdp_url="http://localhost:9222", new_context=False) as session:
    page = session.fetch("https://example.com")
    • new_context=False は、ブラウザの既存のデフォルト コンテキストとログイン状態を再利用します。コンテキスト設定は使用されたままになり、スラップリングが切断されても既存のタブは開いたままになります。
    • デフォルトの new_context=True は、別のコンテキストを作成し、セッションの終了時にそれを閉じます。スラップリングは、どちらのモードでも独自のタブを使用します。

  • スパイダーのログ ファイルのエンコーディングを選択します。log_file_encoding="utf-8" または別のエンコーディングを使用します。デフォルトの None は、Python のデフォルトのエンコーディングを保持します。 (ドキュメント を確認してください)

🐛 バグ修正

  • XPath 式は、string()、count()、boolean() などの値を正しく返すようになりました。空の文字列、ゼロ、および false は、#552 の @jayhemnani9910 による通常のセレクター API を通じて引き続き使用できます。

  • ルート要素のない HTML の解析を修正 (ホワイトスペースのみ、コメントのみ、doctype のみの入力を含む) (#536 の @rushilnimbalker250 による)。

  • 参照に比較する属性がない場合の find_similar(similarity_threshold=0) を修正、#539 の @Master-Norna により行われました。

  • 同時リクエストが同じドメインに到達した場合の重複した robots.txt フェッチを修正、#538 の @RayenMlayeh により作成されました。

  • 開発キャッシュの同時書き込み中の一時ファイルの衝突を修正、#546 の @xixihaha-ha により作成されました。

  • 不正なリンクによって、同じページ上の有効なリンクの抽出が停止されなくなりました、#548 の @dajiaohuang により。

  • #551 の @xunguangzlj-cloud により、引用符で囲まれたフィールド内の改行を維持しながら、行区切り文字としてキャリッジ リターンを使用する CSV フィードを修正しました。

  • 切り詰められた、または破損した gzip フィードは、サイトマップ、XML フィード、および CSV フィード スパイダーの通常の警告およびスキップ パスに従うようになりました (#522 の @cangen185-sudo により)。

  • パーセントでエンコードされたユーザー名とパスワードによるブラウザ プロキシ認証を修正、#545 の @kevin9327 により作成されました。

  • セッションのセットアップまたはコンテキストの終了が失敗した場合のブラウザーのクリーンアップが改善されました。借用したリモート コンテキストを開いたままにして、所有されているリソースが解放されます。

  • **#541 の @waw666waw666 により、スペースまたは引用符を含むブラウザー Cookie 値 (後続の Cookie を含む) をドロップするシェルおよび HTTP CLI Cookie の解析を停止しました。 #540を修正しました。

  • Curl 変換は、既存のリダイレクト動作を維持しながら、-L および --location を受け入れるようになりました (#554 の @jayhemnani9910 により)。

  • 文書に記載されているように、scrapling extract fetch --ai-targeted で広告ブロックが有効にならない問題を修正、#527 の @postoso により行われました。
