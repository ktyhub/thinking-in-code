Scrapling v0.4

マイナー 公開日2026年2月15日 出典D4Vinci/Scrapling 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

v0.4 をスクラップする

Scrapling のこれまでで最大のリリース - Spider フレームワーク、プロキシ ローテーション、パーサーの大幅な改善を導入

このリリースでは、完全に非同期のスパイダー/クローリング フレームワーク、インテリジェントなプロキシ管理、およびスクレイピングをより強力で一貫性のあるものにする重要な API の変更が導入されています。アップグレードする前に、重大な変更のセクションをよく読んでください。

🕷️ スパイダーフレームワーク

構造化された大規模な scraping 用に、anyio 上に構築された新しい非同期クローリング フレームワーク:

from scrapling.spiders import Spider, Response

class MySpider(Spider):
  name = "demo"
  start_urls = ["https://example.com/"]

  async def parse(self, response: Response):
      for item in response.css('.product'):
          yield {"title": item.css('h2::text').get()}

MySpider().start()
  • スクレイピーのようなスパイダー API: start_urls、非同期 parse コールバック、Request/Response オブジェクト、および優先キューを使用してスパイダーを定義します。
  • 同時クロール: 同時実行制限、ドメインごとのスロットル、ダウンロード遅延を構成できます。
  • マルチセッション サポート: HTTP リクエスト用の統合インターフェイスと、単一のスパイダー内のステルス ヘッドレス ブラウザ - ID によってリクエストをさまざまなセッションにルーティングします。遅延セッション初期化をサポートします。
  • 一時停止と再開: チェックポイントベースのクロール永続性。 Ctrl+C を押して正常にシャットダウンします。その後、再開して中断したところから再開します。
  • ストリーミング モード: スクレイピングされたアイテムが async for item in spider.stream() 経由で到着すると、リアルタイムの統計情報とともにストリーミングします。UI、パイプライン、長時間実行のクロールに最適です。
  • ブロックされたリクエストの検出: カスタマイズ可能なロジックによるブロックされたリクエストの自動検出と再試行。
  • 組み込みのエクスポート: フックと独自のパイプライン、または組み込みの JSON/JSONL (それぞれ result.items.to_json() / result.items.to_jsonl()) を介して結果をエクスポートします。
  • ライフサイクル フック: クロール ライフサイクルを完全に制御するための on_start()、on_close()、on_error()、on_scraped_item() などのフック。
  • 詳細なクロール統計: リクエスト、応答、バイト、ステータス コード、プロキシ、ドメイン/セッションごとの内訳、ログ レベル数などを追跡します。
  • uvloop サポート: 利用可能な場合は、非同期実行を高速化するために use_uvloop=True を spider.start() に渡します。

詳細を記載した新しいセクションが Web サイトに追加されました。 Clickは【こちら】(https://scrapling.readthedocs.io/en/latest/spiders/architecture.html)

🔄 プロキシのローテーション

  • スレッドセーフ回転を備えた新しい ProxyRotator クラス。すべてのフェッチャーとセッションで動作します。 
    from scrapling import ProxyRotatorrotator = ProxyRotator(["http://proxy1:8080", "http://proxy2:8080"])Fetcher.get(url, proxy_rotator=rotator)
  • カスタム ローテーション戦略: 独自のプロキシ ローテーション ロジックを作成します。
  • リクエストごとのプロキシ オーバーライド: proxy= を個々の get()/post()/fetch() 呼び出しに渡して、そのリクエストのセッション プロキシをオーバーライドします。

🌐 ブラウザフェッチャーの改善

  • ドメイン ブロック: DynamicFetcher/StealthyFetcher の新しい blocked_domains パラメーターにより、特定のドメイン (サブドメインは自動的に一致) へのリクエストをブロックします。
  • 自動再試行: ブラウザ フェッチャーは、retries (デフォルト: 3) および retry_delay (デフォルト: 1 秒) パラメーターを使用して失敗時に再試行するようになりました。プロキシ対応のエラー検出が含まれます。
  • 応答メタデータ: Response.meta dict は、使用されるプロキシを自動的に保存し、要求メタデータをマージします。
  • Response.follow(): スパイダー システム用に設計された自動リファラー フローを使用してフォローアップ Request オブジェクトを作成します。
  • 自動再生なし: ブラウザ セッションは自動再生コンテンツをブロックするようになりました。これにより、以前は問題が発生していました。
  • 速度: ブラウザーのフラグを調整することにより、ステルス性と速度が向上しました。

🔧 バグ修正と改善

  • パーサーの最適化: 反復操作用にパーサーを最適化し、パフォーマンスを向上させました。
  • エラーが発生したページ: ページでエラーが発生したときにブラウザが閉じなくなるバグを修正しました。
  • 空のボディ: 空のボディで応答を処理します。
  • Playwright ループ: CDP 接続が失敗したときに Playwright ループを開いたままにする問題を解決
  • 型安全性: すべての mypy エラーを修正し、型指定されていない関数本体全体に型ヒントを追加しました。 mypy と pyright を CI ワークフローに追加しました。

⚠️重大な変更

  • css_first/xpath_first が削除されました: 代わりに css('.selector').first、css('.selector')[0]、または css('.selector').get() を使用してください。
  • すべての選択が Selectors を返すようになりました: css('::text')、xpath('//text()')、css('::attr(href)')、および xpath('//@href') は、TextHandlers ではなく Selectors (Selector オブジェクト内のテキスト ノードを tag="#text" でラップ) を返すようになりました。これにより、API はすべての選択方法とタイプ ヒントで一貫性を保ちます。
  • Response.body は常に bytes: 以前は str または bytes でしたが、現在は常に bytes を返します。
  • get()/getall() の動作: Selector の場合: get() は TextHandler (シリアル化された HTML またはテキスト値) を返し、getall() は TextHandlers を返します。別名: extract_first = get、extract = getall。 Selectors の古い get_all() が削除されました。
  • Selectors.first/.last: IndexError を呼び出す代わりに Selector | None を返す安全なアクセサー。
  • 内部定数の名前が変更されました: DEFAULT_FLAGS → DEFAULT_ARGS、DEFAULT_STEALTH_FLAGS → STEALTH_ARGS、HARMFUL_DEFAULT_ARGS → HARMFUL_ARGS、DEFAULT_DISABLED_RESOURCES → EXTRA_RESOURCES。

🔨その他の変更点

  • 依存関係の変更: tldextract を tld に置き換え、内部 _html_utils.py を削除して w3lib.html.replace_entities を優先し、typing_extensions をハード要件として追加しました。
  • ドキュメントの全面見直し: MkDocs から Zensical への完全な切り替え、新しいスパイダー ドキュメント セクション、既存のすべてのページの更新、および新しい API リファレンスの追加。
