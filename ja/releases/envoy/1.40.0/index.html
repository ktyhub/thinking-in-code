envoy v1.40.0

マイナー 公開日2026年10月13日 出典envoyproxy/envoy 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#特使v1.40.0

変更の概要

重大な変更

  • ビルド: Envoy は WORKSPACE から bzlmod に切り替えられました。 WORKSPACE ファイルは削除されます。 Envoy、API、およびドキュメントは Bazel モジュール (envoy、envoy_api、envoy-docs) として公開されています。ダウンストリームは MODULE.bazel に移行する必要があり、BCR と一緒に Envoy のカスタム レジストリ (https://raw.githubusercontent.com/envoyproxy/bazel-registry) を追加する必要があります。Envoy の依存関係とパッチ適用済みモジュールの多くはそこでのみ公開されます。
  • build: ハーメティック LLVM/Clang ツールチェーンが 18 から 22 に変更されました。--config=clang と clang-local が削除されました — Clang/libc++ がデフォルトとなり、フラグは必要ありません。 GCC は --config=gcc 経由で残ります。 --@envoy//bazel:libc++/libstdc++ フラグと force_libcpp 定義はなくなりました。ホスト LLVM ツールチェーンを必要とするダウンストリームは、bazel/tests/codeql に従う必要があります。
  • ビルド: Wasm ランタイムは --@proxy-wasm-cpp-host//bazel:engine=<engine> で選択されるようになりました。古い --define wasm=/--define engine= フラグはビルドに失敗します。
  • tls: AWS-LC が選択可能な SSL ライブラリ (--config=aws-lc-fips を含む) から削除されました。 ppc64le ビルドでは --config=openssl を使用する必要があります。
  • mcp_router: ダウンストリーム要求ヘッダーはデフォルトでバックエンドに転送されなくなりました (特に authorization)。新しいバックエンドごとの header_forwarding を使用します (forward_all: true は古い動作を復元します)。
  • 動的モジュール (Rust SDK): HttpFilter フックは、&mut self ではなく &self を使用するようになりました。ストリームごとの可変状態は、内部可変性の背後に移動する必要があります。これで、同期フィルター チェーンの解放後の使用の破棄が終了します。

主な変更点

  • HTTP/3 と QUIC は、アップストリームの HTTP/3 とすべての QUIC 拡張機能を含めて安定しました。 QUIC リスナーは client 証明書 (mTLS) のサポートを取得し、アップストリーム QUIC は client 証明書を取得し、P-384/P-521 ECDSA 曲線がサポートされます。
  • デフォルトでポストクォンタム: X25519MLKEM768 ハイブリッド キー交換が、FIPS ビルドを含むアップストリームおよびダウンストリーム TLS のデフォルト ECDH 曲線に追加されます (envoy.reloadable_features.pqc_default_ecdh_curves 経由で元に戻せます)。
  • 一致後にルーティングが拡張可能になります: 新しい route_specifiers 拡張ポイントは、一致したルートをルート設定、仮想ホスト、およびルート レベルで後処理 (精製、ドロップ、または合成) します。優先グループ クラスター指定子と動的モジュール ルート指定子は、その上に構築されます。
  • 負荷分散: 新しい per_worker_subset ポリシーにより、ワーカーごとのプール サイズがクラスター サイズから切り離されます。新しい load_aware_locality ポリシーは、ORCA 由来のヘッドルームによってローカリティを選択します。 EDS バッチ更新時の合体 LB 再構築がデフォルトで有効になりました。
  • コンテナ対応の CPU 検出は実際にはデフォルトでオンになっています - 1.37 の動作は --cpuset-threads でのみアクティブでした。 --concurrency が設定解除されている場合は常に適用されるようになりました。
  • ドレインはイベント駆動型: ドレインクローズの決定は、応答ごとにポーリングされるのではなく、ドレインの開始時に接続にプッシュされます。これにより、Mongo/Redis/Thrift/汎用プロキシの受信専用ドレインも修正されます。
  • UDP のホット リスタート: 確立された UDP プロキシ セッションは親によって保持され、不明なセッションのデータグラムは子に転送されるため、ドレイン中にコネクションレス リスナーが暗転することがなくなりました。

AI / MCP

  • AI プロトコル マネージャー フィルター (アルファ) は、OpenAI、Anthropic、Gemini の方言 (SSE および JSON) の応答側 LLM トークン使用抽出を取得し、型付き動的メタデータ (envoy.data.ai.v3.TokenUsage) として公開されるほか、リクエスト情報、スキーマ検証、トランスコーディングのサブフィルター、本体の再シリアル化も行います。
  • MCP フィルター: ルートごとの構成、プロトコル バージョンの強制、必須の client 機能、新しいメソッド グループ、no-op モード、およびルーティング可能な場合の早期終了。 JSON/REST ブリッジは、サーバー検出、ヘッダー/プロトコル バージョン検証、および結果タイプを追加し、テンプレート変数を介したパス トラバーサルを防止するようになりました。

動的モジュール

  • 新しい拡張ポイント: クラスター指定子、ルート指定子、ヘッダー フォーマッタ、初期ヘッダー変更、TLS ハンドシェーカー、トランスポート ソケット リレー、構成バリデーター、およびダウンストリーム STARTTLS。
  • 動的モジュール クラスターは、ホストの選択を Envoy の組み込み LB (ROUND_ROBIN、LEAST_REQUEST、RANDOM、RING_HASH、MAGLEV) に委任できるようになりました。
  • 広範な強化: HTTP、ネットワーク、リスナー、およびクラスター LB フィルター状態にわたるライフタイム/ビューの修正の大規模なバッチ、遅延 HTTP フィルターの破棄、Go および C++ SDK のパニック/例外バリア、コールアウトの再入修正、ログに記録されたロード失敗を伴う RTLD_NOW ロード。
  • 型付きメタデータの取得/設定、ランタイム ゲッター、フック全体のトレース スパン、ストリーム タイミング、アップストリーム試行/ピア アドレス アクセサー、および Go SDK 統計/ログレベル ゲッター。

セキュリティと認証

  • 1.39.x セキュリティ修正を引き継ぎます: パス パラメーターの URL 正規化 (CVE-2026-73511/73551)、END_STREAM なしの HTTP/2 トレーラーとドロップされた Host アカウンティング (CVE-2026-73513/73550)、HTTP/3 UAF (CVE-2026-73512)、ext_authzパスレスリクエストのクラッシュと UAF (CVE-2026-73547/50572)、汎用アップグレード本体パイプライン (CVE-2026-73548)、safe_regex Latin1 モード (CVE-2026-73552)、RBAC ignore_path_parameters (CVE-2026-73553)、管理統計名のサニタイズ(CVE-2026-73546)、oauth2/api_key_auth CONNECT のクラッシュ (GHSA-8vc2-jrm4-835w、GHSA-47vj-9r25-wv5j)、Brotli Decompressor の範囲外書き込み (GHSA-3wvj-j6qm-62mr)。
  • TLS: 証明書ごとの TLS パラメータ、証明書セレクターを備えた複数のアップストリーム証明書、SPIFFE アップストリーム SAN 検証、SDS ファイル ポーリング、および SNI によって範囲指定されたアップストリーム セッション キャッシュ。
  • OAuth2 は、認証情報インジェクターのアサーション オーディエンス/キー ID と TLS client 認証を取得します。 JWT 認証はクレーム パスと JWT クレーム レート制限記述子を取得します。 GCP 認証によりスコープ、対象ユーザー、IAM アクセス トークンが取得されます。 ext_authz は、ネットワーク フィルターとルート キャッシュ クリア ヘッダーでシャドウ モードを取得します。

可観測性

  • アクセス ログ: ダウンストリーム ハンドシェイク タイム ポイントと接続 RTT、リスナー名とルート解決時間フォーマッタ、CEL 式フォーマッタ設定、およびナノ秒ヒストグラム単位。
  • OpenTelemetry: リソース ディテクタ、カスタム エクスポータ、インストルメンテーション スコープ、および型指定されたカスタム タグ。 ext_authz と ext_proc は client スパンを発行します。
  • 統計: クラスター/リスナーごとの統計マッチャー、明示的なタグ、および Prometheus ネイティブ ヒストグラム バケット インデックスが 1 ずれている問題の修正。

その他の注目すべき変更点

  • HTTP/1 は RFC 10008 QUERY メソッドを受け入れるようになりました (元に戻すことができます)。 Content-Type のない QUERY はすべてのプロトコルで拒否されます。
  • Redis プロキシ: RESP3 プロトコルのサポート、CLUSTER SHARDS、より厳密な RESP デコード、およびいくつかの use-after-free 修正。
  • 逆トンネル: JWT ハンドシェイク認証、間隔の維持、フェールクローズ識別子の検証、およびハンドシェイク ライフサイクル修正のバッチ。
  • ウォッチドッグ バックトレース アクション、UDP ヘルス チェッカー、マルチ ヘルス チェッカー、TCP プロキシの負荷制限ポイント、およびボディ サイズ制限 HTTP フィルター。
  • RDS アップデート後にワーカー スレッドでルート レベルの設定 (AWS 署名、コンポジット、フィルター チェーン、ローカル レート制限、動的モジュール、SDS シークレット) が破棄される可能性がある競合ファミリーを修正しました。

非推奨

  • envoy.extensions.config.validators ファクトリは URL タイプによってキー設定されます。動的モジュールのログとタイミング情報のコールバック。従来の HTTP フィルター ファクトリの基本クラス。逆方向トンネル auto_close_connections; Wasm プラグインレベルの機能制限。
