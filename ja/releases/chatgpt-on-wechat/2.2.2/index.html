💬 ゲストページ

エージェントをスタンドアロン チャット ページとして共有するか、チャット ウィンドウとして Web サイトに埋め込みます。訪問者はリンクを開いて、サインインせずにチャットを開始します。これは、製品に関する問い合わせ、ナレッジ ベースの Q&A、カスタマー サポート、および同様のシナリオに適しています。

  • スタンドアロン ページ: 各ページには独自のリンクがあり、訪問者はチャット履歴を保持し、名前、アイコン、テーマの色、ウェルカム メッセージ、提案された質問はすべてカスタマイズ可能です。

  • 埋め込みチャット ウィンドウ: 単一のコード スニペットにより Web サイトにページが埋め込まれ、右下隅にチャット ボタンが表示されます。埋め込むことができるサイトを制限し、構成中に結果をプレビューすることができます。 CowAgent Web サイト でライブでお試しください。

<フレーム> <img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/guest-share-embed.png" alt="ページに埋め込む" width="800" /> </フレーム>

  • データ分離: 訪問者に対応するエージェントは、そのページで有効になっているツール、スキル、参照のみを使用できます。メモリ、会話、ワークスペースにアクセスしたり、コマンドを実行したりすることはできず、ネットワーク要求はパブリック アドレスに限定されます。新しいページは、ファイルの書き込み、ファイルの送信、および Web 検索がオフになった状態で開始されます。
  • 参考資料: ナレッジ ベースまたはそのカテゴリの 1 つを読み取り専用の参考資料として選択します。それぞれに、その目的に関するメモが含まれています。
  • アクセス制御: アクセス パスワード、訪問者ごとの 1 日の質問制限、および有効期限をサポートします。会話は訪問者ごとに確認でき、いつでもページのリンクをリセットしたり、ページを一時停止または削除したりできます。

🎨 カスタムテーマ

Web コンソールとデスクトップ client はテーマをサポートするようになり、どちらも 1 つのテーマ フォルダーを共有します。

  • テーマのインポート: テーマの zip またはフォルダーをドラッグして、カスタム カラー、背景の壁紙、新規チャット アイコンをインポートします。テーマは ~/cow/system/themes/ に保存されます。
  • エージェント生成のテーマ: 希望のスタイルを説明するか、参照画像を添付すると、エージェントが色、壁紙、アイコンを生成し、すぐに切り替えることができます。
  • 内蔵テーマ: メドウ、オーシャン、クレイ、サクラ、ラベンダーの 5 つのカラー テーマがあり、それぞれライト モードとダーク モードの両方に適応します。

🖼 メインモデルによる画像の理解の向上

メイン モデルがビジョンをサポートしている場合、画像はマルチモーダル入力としてメイン モデルに直接渡されるため、理解と応答が 1 回の呼び出しで行われます。これにより、画像理解ツールが画像を二次的に説明するときに失われる詳細が回避され、UI の再現やチャート分析などのタスクが大幅に改善されます (感謝 @592774447 #3608)。

  • 適用される場合: ビジョン モデルが「自動」に設定されている場合、またはメイン モデルと同じモデルに設定されており、追加の設定を行わない場合に有効になります。
  • コンテキストコスト: 現在のターンのみが画像を保持します。それより前のターンではそれへの参照が保持されるため、そのトークンは再度カウントされません。画像が原因でリクエストが拒否された場合、テキストのみとして自動的に再試行されます。
  • プロバイダーのサポート: クロード、ジェミニ、クウェンは、独自のネイティブ形式で画像を受信します。
  • 認識精度: 画像圧縮の制限が 3 MB / 3072 ピクセルに引き上げられ、より多くのテキストと詳細が保持されます。

🔗 統合とアクセスアドレス

[構成] ページには、Web コンソールとデスクトップ client の両方に新しい [統合] タブがあり、ゲスト ページ、チャット API、およびアクセス アドレスがまとめられています。

  • アドレス: リッスン IP とポートをオンラインに変更します。サービスは再起動せずに新しいアドレスに切り替わり、新しいアドレスが使用できない場合は前のアドレスに戻ります。本機のLANアドレスが表示され、共有リンクや埋め込みコードの表示アドレスを設定できます。
  • HTTPS とドメイン: 証明書が設定されると、コンソールは HTTPS を直接提供できるようになり、ドキュメントでは nginx リバース プロキシの背後での展開がカバーされるようになりました (@anshlakhera048 #3774、@592774447 #3768 に感謝します)。
  • ログイン保護: 間違ったパスワードを繰り返し入力した client は一時的にロックアウトされます。ローカル アクセスは個別にカウントされるため、外部からのパスワード推測によってこのマシンからロックアウトされることはありません。
  • チャット API: 同じ会話内の同時リクエストは順番に処理されます (@rudycelekli #3751 に感謝)。

🤖 モデルの機能

  • 新しいモデル: kimi-k3.1-pro (Kimi のデフォルト モデル)、MiniMax-M3.1-Flash、gpt-6.1-terra (OpenAI のデフォルト モデル)、claude-sonnet-5-5、claude-haiku-5-5、gemini-4-argon (Gemini のデフォルト モデル) を追加しました (@octo-patch #3791 に感謝)。
  • Xiaomi MiMo: 音声認識用に mimo-v2.5-asr を追加しました。チャット モデルは V2.6 にアップグレードされ、古いモデル ID は自動的にマッピングされます (@592774447 #3788 に感謝します)。
  • モデル表示名: カスタム プロバイダーのモデルには表示名を付けることができ、モデル ピッカーに表示されますが、元のモデル ID は引き続きリクエストに使用されます (感謝 @592774447 #3852)。
  • デフォルト コンテキスト: エージェントのデフォルト コンテキスト制限が 64,000 トークンから 200,000 トークンに引き上げられ、最大ステップが 30 から 100 に、保持ターン数が 20 から 30 に引き上げられます。
  • ストリーミング: クロード ストリーミング中のエラーは、ストリームをサイレントに終了するのではなく、表面化されるようになりました。接続を閉じることで完了を通知するストリームがサポートされています。すべてのプロバイダーのストリーミング接続は、すべての出口パスで適切に解放されます (@rudycelekli #3693、#3822、@a1094174619 #3847 に感謝します)。
  • OpenAI: 応答 API は、拒否、切り捨てられたツール引数、および失敗した応答を正しく処理します。イメージ API の再試行では、カスタム ベース URL が維持されます (@rudycelekli #3691、#3692、#3702、#3706 に感謝します)。
  • 実行中のメッセージ: Zhipu GLM、Qwen、および MiniMax では、ツールの結果後の実行中に追加されたメッセージが維持されます。非オブジェクト ツールの結果は Gemini で正しくラップされます (@rudycelekli #3825、#3826、#3827、@pei711 #3843 に感謝します)。
  • 音声: MiniMax、Google、および OpenAI 音声 API での接続リリース、エラー検出、および URL 構築を修正しました。同じテキストを繰り返し合成しても、以前の出力ファイルが上書きされることはなくなり、click したメッセージ バージョンが手動読み上げで再生されます (@rudycelekli #3688、#3700、#3708、#3710、#3714、#3720、#3803 に感謝します)。転写が無効な場合はエラーが返され、一時ファイルはすべての応答パスで即座にクリーンアップされます (@c020627 #3759、#3835、#3837、@rudycelekli #3815 に感謝します)。
  • その他: Gemini トークンの使用量には思考トークンが含まれており、非ストリーミング応答でも正確なトークン使用量が報告されます (@pcbeingused333 に感謝 #3850、#3855)。 ModelScope ストリーミングは空の choices を含むチャンクを許容し、モデル機能リストは相互に影響しなくなり、画像認識が失敗した場合には一時ファイルがクリーンアップされます (@rudycelekli #3704、#3813、#3821 に感謝します)。

🧩 スキルとツール

  • Web 検索: DeepSeek の公式検索およびフェッチ API を統合し、DeepSeek API キーが設定されると自動的に有効になり、デフォルトの検索プロバイダーとして使用されます (@anshlakhera048 #3776、@592774447 #3775 に感謝)。個々の検索プロバイダーは資格情報を保持したまま無効にできるため、キーレス匿名検索を明示的に有効にする必要があります (@rudycelekli #3705 に感謝)。
  • スキル: デスクトップ client の [スキル] ページには、アイコンとバージョンが表示されます。カスタム スキル リポジトリは、スキルを名前でインストールおよび検索するために skill_hub_url で設定でき、リストされていないスキルはデフォルトのスキル ハブからフェッチされます。チャット内のスキル コマンドは、現在のエージェントにのみ適用されます。
  • スキル管理: 置換インストールが失敗した場合は元のスキルが保持され、有効化または無効化が失敗した場合は以前の状態が復元されます。 BOM とさまざまなメタデータ形式を含むファイルがサポートされており、1 つの破損した構成エントリが他のスキルに影響を与えることはなくなりました (@rudycelekli #3685、#3690、#3695、#3696、#3698、#3711、#3753、#3754、@c020627 #3760 に感謝します)。
  • ターミナル: Windows で出力が生成されないコマンドと複数行の Python コマンドが切り捨てられる問題を修正しました (@keeponlight #3795、@rudycelekli #3811、@Nolan527 #3793 に感謝)。非常に長い行が切り捨てられた後も、完全な出力が保持されます (@rudycelekli #3779 に感謝)。 Windows では、全出力ログにはコマンドの元の改行が保持されているため、指定された行番号から読み戻すと、正しい場所に到達します (@tanishqbaweja #3858 に感謝)。
  • 構文チェック: 書き込み前の構文チェックでは、tsconfig.json、VS Code 設定、Helm テンプレートなどのコメントまたはテンプレート構文を含むファイルが受け入れられますが、package.json などの厳密な JSON ファイルは、修正方法のヒントを含むコメントを依然として拒否します (@tanishqbaweja #3853 に感謝)。
  • ファイルの読み取り/書き込みと検索: ファジーマッチ編集では、置換されたコンテンツの周囲に空白行が追加されなくなり、ファイルを上書きすると、Windows 上ですべての行末を CRLF に変換するのではなく、既存の行末が維持されます (@tanishqbaweja #3854、#3856 に感謝します)。非常に長い行はオフセットによって読み取ることができ、CR 行末とあいまい一致のインデントは保持され、エンコード フォールバックが失敗しても元のファイルは上書きされず、ディレクトリと特殊ファイルの読み取りと書き込みは拒否され、ファイル読み取りレコードのスコープは現在の会話に限定されます。ディレクトリ フィルタは、ripgrep がインストールされていない場合にも適用されます (@rudycelekli #3689、#3715、#3752、#3770、#3772、#3794、#3799、#3810 に感謝します)。
  • ドキュメント解析: Word コンテンツ コントロール、フィールド結果、および結合されたセルは完全に読み取られ、宣言された範囲外の Excel セルは読み取られます (@ningyixi #3786、#3787、@rudycelekli #3773、#3777、#3798 に感謝します)。
  • ブラウザ: スナップショットの範囲を特定の要素に限定でき、スクリーンショットは現在のプロジェクトに保存され、明示的なテキストが提供された場合にのみ入力フィールドが入力されます。ブラウザーのプロファイル ディレクトリは正確に一致するため、同様のパスが使用中であると誤って認識されることはなくなり、Windows でのプロセス検出にはタイムアウトが発生します (@rudycelekli #3724、#3725、#3727、#3802、@c020627 #3769 に感謝します)。
  • ビジョン: 圧縮された画像は元の方向を維持し、モデルが空の結果を返すと次のプロバイダーが試行されます (@rudycelekli #3712、#3726、#3806 に感謝)。
  • MCP およびスケジュールされたタスク: MCP 接続の失敗はツール呼び出しの失敗として返され、破損した認証レコードは無視されます。スケジュールされたタスクの結果は正確な実行にマップされ、実行中に行われたスケジュールの変更は上書きされなくなり、拒否された操作は失敗として報告され、従来のリマインダーの移行の信頼性が向上しました (@rudycelekli #3713、#3745、#3781、#3782、#3807、#3808 に感謝します)。

🤝 マルチエージェントのコラボレーション

  • サブエージェント: 詳細な調査など、必要な場合にのみ委任され、タイムアウトが近づくとそれまでに収集された結果をまとめて返します。ローカル委任は設定されたタイムアウトに従い、無効な引数や読み取り不能なテンプレート ディレクトリによってローカル委任が中止されることはなくなりました (@rudycelekli #3783、@c020627 #3761 に感謝します)。
  • チームのコラボレーション: @メンションは、文末の句読点が直接続く場合に正しく認識されます (@c020627 #3738 に感謝)。
  • コンテキスト: ループ検出ヒントは、コンテキスト内に残るのではなく、モデルが検出すると削除されます (@NotZhu #3851 に感謝します)。コンテキストをクリアした後の新しいメッセージは保持され、チャネル会話の実行ステップの履歴への保存が一時的に失敗しても再試行されるため、ツールのレコードが失われることはなくなりました (@rudycelekli #3734、#3804 に感謝します)。

📡 チャンネル

  • WeChat: QR コード ログインがより安定し、期限切れの QR コードが自動的に更新され、オプションの weixin_proxy を設定できます (@c020627 #3838 に感謝)。送信されたファイルは元の名前とタイプを保持します (@6vision #3817 に感謝)。メディアのダウンロードが失敗したときに接続が解放されない問題を修正しました (@rudycelekli #3750 に感謝)。
  • Feishu: リッチ テキスト メッセージは、ファイルと多言語コンテンツの解析をサポートしています。
  • ファイルの送信: Feishu、DingTalk、WeCom Bot、および WeChat カスタマー サービスは、ファイルを送信するときに元のファイル名を保持します。
  • DingTalk: グループ チャット内のファイルは送信者ごとに分離され、一時メディア ファイルはすぐにクリーンアップされます (@rudycelekli #3762、@c020627 #3828 に感謝)。
  • WeCom / 公式アカウント: WeCom によって保存された画像は元の向きを維持します (@c020627 #3845 に感謝)。チャット プレフィックスが設定されていない場合でも、フォロー時のウェルカム メッセージが公式アカウントに送信されます (@rudycelekli #3707 に感謝)。
  • Telegram / Discord / Slack: リモート URL からファイルを送信できます。グループ チャット内のボットの @メンションは完全なユーザー名と一致し、サイズの大きい添付ファイルはダウンロード前に拒否され、ワー​​クスペース システム通知には返信が返されなくなりました (@rudycelekli #3716、#3764、#3765、#3818、#3819、#3820 に感謝します)。
  • プラグイン: グループ管理者は ID によって正確に一致します (@rudycelekli #3763 に感謝します)。

🛡 セキュリティ強化

  • スケジュールされたタスクの権限: スケジュールされたエージェント タスクは、作成されたセッションの権限モードを保持するため、読み取り専用セッションで作成されたタスクは書き込みを実行できません (感謝 @EddieMurphy89 #3833)。
  • ゲスト リクエストの保護: 訪問者に代わって行われたネットワーク リクエストは常にローカル ネットワーク アドレスとプライベート ネットワーク アドレスをブロックし、ゲスト ページのパスワードをコンソールのパスワードと同じにすることはできません。
  • コンソール パスワード: 新しく設定するパスワードは少なくとも 6 文字でなければならず、入力中に強度のヒントが表示されます。既存のパスワードは影響を受けません。
  • リソース制限: モデルによって返されるファイルのダウンロード サイズには制限があります (@c020627 #3832 に感謝)。
  • セキュリティ ポリシー: セキュリティ ポリシーと脆弱性を報告するためのプライベート チャネルを追加しました。

🛠 UX の改善と修正

  • チャット インタラクション: 返信の生成中は上に自由にスクロールでき、下にスクロール ボタンは入力ボックスに合わせて配置され、上にスクロールすると以前のメッセージが自動的に読み込まれます (@LYLMagui #3785 に感謝)。 cli入力領域の空白部分をクッキングすると、入力ボックスがフォーカスされます (@Rofds #3830 に感謝)。
  • スムーズさ: 返信が一気に届いたときの UI の途切れを修正しました。長時間のセッションでオフスクリーン メッセージが表示されなくなり、入力やスクロールがスムーズになりました (@zkjqd #3792 に感謝)。
  • ワイド スクリーン: デスクトップ client のチャット エリアはウィンドウの幅に適応します (@zkjqd #3844、@592774447 #3839 に感謝します)。
  • セッション: 再起動後もコンテキスト使用状況グラフが保持されます (@xiao115255 #3767、@jiangch1128 #3619 に感謝)。タイトルは、メイン モデルに障害が発生した場合にフォールバック モデルで生成されます。失敗した送信には具体的な理由が示されます。削除に失敗した場合でも会話履歴は保持されます (@rudycelekli #3809 に感謝)。アーティファクトのインデックス作成に失敗しても、会話履歴が重複しなくなりました。
  • ファイル表示: ワークスペース外のファイルは、送信時にワークスペースにコピーされるため、コンソールに正しく表示されます。ロードに失敗した画像にはファイル名が表示されます。デスクトップ client のファイル プレビューでは、フォルダー内のファイルが表示されます。
  • ナレッジ グラフ: タイトルのないノードが残り、すべてのエッジが削除される未解決の相互参照を修正しました。ナレッジ ベースのルートに関連するリンク、裸のファイル名、および山かっこ構文がサポートされており、シンボリック リンクの下のナレッジ ベース フォルダーもサポートされています。
  • コンソール: 保存が失敗しても実行構成は保持され、ワー​​クスペース ファイルを同時に保存すると競合が報告されます。ワークスペース ファイルの更新、エディターのコンテンツの検証、設定の保存、およびリクエストのキャンセルの範囲を修正しました。登録されたエージェント ワークスペース内のアーティファクトにアクセスできるようになり、ナレッジ ベース ドキュメントの置換がより確実になります (@rudycelekli #3733、#3746、#3747、#3748、#3749、#3755、#3784、#3801、#3805 に感謝します)。
  • エージェントの初期化: 空の ID ファイルによってオンボーディングがスキップされなくなり、同時初期化によって既存の設定が上書きされなくなりました (@rudycelekli #3722、#3730 に感謝します)。軌道評価により、予期されるツールと実行ステータスが正しくチェックされます (@xiong-wei1 #3849、#3848 に感謝します)。
  • ログと CLI: ログ ファイルが切り捨てられた後もライブ ログは継続し、データ ディレクトリが書き込み可能でない場合でもコンソール出力は保持されます。このサービスは、バックグラウンドで開始されると標準入力から切り離され、十分なアクセス許可がない場合に失われるプロセス ID と破損した更新ステータス ファイルを修正しました (@rudycelekli #3686、#3687、#3709、#3717、#3719、#3780、#3800、#3812、#3814 に感謝します)。
  • 設定とバックアップ: データ ディレクトリの同時作成は失敗しなくなり、リモートでプッシュされた設定は実際に使用されているデータ ディレクトリに書き込まれ、バックアップが復元された後もスキル スクリプトの実行権限が維持されます (@rudycelekli #3723、#3778、@c020627 #3823 に感謝します)。
  • デスクトップ client: バンドルされたバックエンドのバージョンは client のバージョンと一致します (@592774447 #3839 に感謝)。 Windows のインストール中にファイルのコピーが失敗した場合、ファイルは自動的に再度抽出されます。 client がターミナルまたはランチャーから開かれ、後で終了したときに、ディスクがいっぱいになるまでログ ファイルが増大する問題を修正しました (@ClearloveUzi7 #3860 に感謝)。
