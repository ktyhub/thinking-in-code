logging-log4j2 2.25.0

#logging-log4j2 rel/2.25.0

このマイナー リリースでは、バグ修正、動作の改善、GraalVM ネイティブ イメージ生成の完全なサポートが導入されています。

GraalVM 到達可能性メタデータ

Log4j コアとすべての拡張モジュールに埋め込みが含まれるようになりました
GraalVM 到達可能性メタデータ、
GraalVM を使用すると、すぐに使用できるネイティブ イメージのシームレスな生成が可能になり、手動構成は必要ありません。
詳細については、GraalVM ガイド を参照してください。

[!NOTE]
サードパーティの Log4j プラグインを構築する場合、新しい GraalVmProcessor を使用する
バージョン 2.25.0 で導入された機能は、GraalVM ネイティブ イメージに必要な到達可能性メタデータを自動的に生成します。
ただし、必須の log4j.graalvm.groupId および log4j.graalvm.artifactId パラメータが指定されていない場合、プロセッサはビルドに失敗します。
詳しい手順については、プラグインの登録を参照してください。

パターンレイアウトでの例外処理

パターン レイアウト の例外処理が大幅に書き直されました。
この更新により、いくつかのバグが解決され、すべての例外コンバーターで一貫した動作が保証されます。
主な改善点は次のとおりです。

  • スタック トレースの先頭には、他の空白類ではなく一貫して改行が付けられるようになりました。
  • デフォルトの例外コンバーターが 拡張 から プレーン に変更され、パフォーマンスが向上しました。
  • 例外コンバーターでの {ansi} オプションのサポートは削除されました。

日付と時刻の書式設定

Log4j はこれまで、FixedDateFormat や FastDateFormat など、パフォーマンスを向上させるためのカスタムの日付と時刻のフォーマッタを提供してきました。
これらは現在非推奨となり、Java の標準 DateTimeFormatter が優先されます。

アップグレード後にフォーマットの問題 (特に n または x ディレクティブ) が発生した場合は、log4j2.instantFormatter プロパティを legacy に設定することで、一時的に従来のフォーマッタに戻すことができます。
問題がある場合は、問題トラッカー からご報告ください。

Windows での ANSI サポート

最新の Windows バージョン (10 以降) は、ネイティブ ANSI エスケープ シーケンス サポートを提供します。
その結果、古い JAnsi 1.x ライブラリへの依存関係が削除されました。
詳細については、「Windows の ANSI スタイル設定」(https://logging.apache.org/log4j/2.x/manual/pattern-layout.adoc#jansi) を参照してください。

ジャカルタ JMS アペンダー

JMS Appender の Jakarta 互換バージョンがコア ディストリビューションに含まれるようになりました。

追加されました

  • Google OSS-Fuzz 統合を追加 (#2949)
  • GraalVmProcessor アノテーション プロセッサを追加して、GraalVM 到達可能性メタデータを生成します。 (#3053)
  • MonitorResource 構成オプションを追加して、構成ファイル自体に加えて外部ファイルの監視をサポートします。 (#3074、#3501)
  • 「LoggerConfig.RootLogger.Builder#withtFilter(...)」メソッドのタイプミスを修正しました。修正された新しい 'withFilter()' メソッドを作成し、古いメソッドを廃止しました。 (#3369)
  • MongoDB アペンダーに collectionName および databaseName 引数を追加 (#3467)

変更されました

  • JAnsi ライブラリのサポートを削除します。 Windows 10 コンソールは 2017 年から ANSI エスケープをサポートしています。 (#1736)
  • 例外レンダリング ロジックを統合し、パターン レイアウトでの循環参照サポートを改善しました (#2691、#3123)
  • JAnsi ライブラリなしで動作するように JAnsiTextRenderer を書き換えます。 (#2916)
  • パターン レイアウトのスタック トレースの接頭辞を空白から改行に切り替えます (#3045)
  • デフォルト構成で使用されるレイアウトを変更します。 (#3118)
  • ログ イベント インスタントの日付と時刻のフォーマットに Java の DateTimeFormatter の使用に切り替える (#3121、#2943)
  • デフォルトの例外コンバーターを 拡張例外コンバーター から プレーン例外コンバーター に切り替えます (#3123)
  • バッチ処理のために StringReaders を閉じないでください。 (#3127)
  • ステータス ロガーのスタック トレースの接頭辞を空白から改行に切り替えます (#3149)
  • MongoDb Appender は非推奨の警告を記録すべきではありません (#3149)
  • Null/空のテキストに対する StringMatchFilter の検証を改善しました。 (#3153)
  • SystemClock をオーバーライドすることにより、Java 8 でミリ秒未満の精度が向上しました。 (#3217)
  • 構成にロガー/ルート ロガーがない場合は、構成された構成名を上書きしないでください。 (#3431)
  • GcpLayout.json を更新して、Google Cloud Logging との互換性を向上させます (#3586)
  • リフレクションの代わりに Base64Util で java.util.Base64 を直接呼び出します (#3686)
  • LogEvent.toImmutable()、ReusableMessage.memento() を改善し、ThrowableProxy の使用を削除

非推奨

  • ThrowableProxy とそのすべての使用法 (#2691、#3123)
  • AbstractLogger.checkMessageFactory() (#2936)
  • FixedDateTime、FastDateTime、およびサポートクラス (#3121)
  • LoggerRegistry で Logger へのハード参照を使用します。 (#3143)

修正済み

  • MongoDB テストを Docker (#2229) に切り替えます
  • Jakarta ベースの JMS Appender を追加し、Javax バージョンを非推奨にする (#2995)
  • ロールオーバーが失敗したときにファイルを再度開くように RollingFileManager を修正しました (#2592)
  • パターン レイアウトでの例外レンダリングを修正 (LOG4J2-2170、LOG4J2-3627、#1729、#2691)
