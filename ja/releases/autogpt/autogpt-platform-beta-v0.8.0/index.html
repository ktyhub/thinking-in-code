AutoGPT autogpt-プラットフォーム-ベータ-v0.8.0

⚠️ セルフホスト型インストールのアップグレード — 重大な変更

ENCRYPTION_KEY、UNSUBSCRIBE_SECRET_KEY、および BETTER_AUTH_SECRET は、.env.default の値では出荷されなくなりました。これらはインストールごとに生成され、バックエンドは .env.default に含まれていた値では起動しません。新規インストールには、make init-env (またはインストーラー) 以外は何も必要ありません。独自の値を設定するインストールには何も必要ありません。インストールがデフォルトで実行された場合 (backend/.env に ENCRYPTION_KEY 行がない、または ENCRYPTION_KEY is set to a value that was published… で起動が停止する)、これを autogpt_platform/ から実行します。これにより、接続された統合が失われるのではなく、新しいキーに移動されます。

1.docker compose down 2. データの暗号化に使用したキーを保管します。 export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) (独自のキーを設定しており、それを置き換える場合は、代わりにその値をエクスポートし、チェックアウトの外に backend/.env のコピーを保管してください)。 3. backend/.env で、ENCRYPTION_KEY= と UNSUBSCRIBE_SECRET_KEY= が存在し、= の後に何も存在しないこと、および frontend/.env の BETTER_AUTH_SECRET= が存在することを確認します。次に make init-env (空のシークレットをすべて埋めます。値は決して上書きされません)。 4. 保存されているものを再暗号化します。最初に予行演習を行ってから、以下を適用します。 docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply 5. 古い BETTER_AUTH_SECRET に保存されているトークン署名キーをクリアして、以下を開始します。 docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

完全な手順: アップグレード: シークレットはインストールごとに生成されます。

また、このリリースでは、従来の HS256 JWT 検証パスが削除されたため、backend/.env 内の JWT_VERIFY_KEY は読み取られなくなりました (#14519)。未使用の TrialNotificationDelivery テーブルは移行によって削除されます。
