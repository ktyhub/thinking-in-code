consul v2.0.3

パッチ 公開日2026年8月7日 出典hashicorp/consul 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#領事v2.0.3

2.0.3 (2026 年 8 月 7 日)

セキュリティ:

  • GHSA-rgw5-rvv9-x895 (無制限の中間配列を介した DoS) に対処するために brace-expansion を更新します。 [GH-23786]
  • GHSA-7p8r-x3mc-p8w7 (バックスラッシュ権限イントロデューサによるホストの混乱) に対処するために fast-uri を更新します。 [GH-23786]
  • GO-2026-5970 に対処するために、golang.org/x/text を v0.39.0 に更新します。 [GH-23761]
  • GHSA-hrxh-6v49-42gf に対処するために、google.golang.org/grpc を v1.82.1 に更新します。 [GH-23761]
  • CVE-2026-69185 (ゼロアタッチメント メモリ枯渇) に対処するために socket.io-parser を更新します。 [GH-23786]
  • Go 1.26.5 を使用するようにアップグレードします。これにより脆弱性が解決されます GO-2026-4970 (os)。 GO-2026-5856(crypto/tls)。 [GH-23761]
  • エージェント: GET /v1/agent/connect/ca/roots によるサービス拒否の脆弱性を修正しました。 POST /v1/agent/connect/authorize はエージェント側のキャッシュを無条件に使用しました。 http_config { use_cache = false } がオペレーターによって設定された場合。リモート発信者 この設定をバイパスし、リクエストを変更することでエージェント キャッシュを際限なく拡大する可能性があります。 ACLトークン。 use_cache が有効な場合、両方のエンドポイントがキャッシュをスキップし、直接 RPC を発行するようになりました。 無効になっています。 (SECVULN-50292、SECVULN-50293) [GH-23797]
  • エージェント: ShadowServiceRouterConfigEntry.CheckEnt の nil ポインター逆参照パニックを修正しました。 service-router config エントリに nil Destination のルートが含まれていた場合。細工された このようなエントリを含むスナップショット リストアまたはレプリケーション メッセージは FSM をクラッシュさせる可能性があります デコードパス。 nil ガードは、欠落している宛先を非エンタープライズ データとして扱うようになりました。 安全にデコードを続行します。 (SECVULN-50291) [GH-23797]
  • エージェント: ユーザー指定のパブリック リスナーによるセキュリティ バイパスを修正しました。 (envoy_public_listener_json) HTTP 接続マネージャー フィルターを使用すると、Consul のフィルターがスキップされます。 受信リクエストの正規化のデフォルト。攻撃者が正規化されていないパスを悪用する可能性がある パーセントでエンコードされたパスと同等のものを使用して、L7 インテンション deny ルールをバイパスします。今すぐ領事 パスの正規化を挿入します (メッシュ構成オプションを除く、デフォルトで有効になります) ユーザー提供のすべての HCM フィルター チェーンで InsecureDisablePathNormalization が設定されます) L7 インテンションの強制が適用される前のパブリック リスナー。 (SECVULN-50295) [GH-23797]
  • エージェント: 認証されていないサービス拒否の脆弱性を修正しました。 PUT /v1/agent/check/update/:id、PUT /v1/agent/check/register、 PUT /v1/agent/service/register、POST /v1/agent/connect/authorize 呼び出し元の ACL を解決する前に、無制限の JSON リクエスト本文をデコードしました トークン。認証されていない呼び出し元は、複数の大きな JSON デコーダを保持する可能性があります 各リクエストが実行される前に、Consul プロセス内で同時にバッファを作成します。 HTTP 403 で拒否され、攻撃者が制御するヒープの増加を引き起こします。 4つすべて エンドポイントは、デコードが行われる前にリクエスト本文を 512 KiB に制限するようになりました。 サイズが大きすぎるボディの場合は HTTP 413 を返します。この制限はチャンク化されたものに適用されます 転送エンコードと宣言された Content-Length。 (SECVULN-50418) [GH-23796]
  • エージェント: 外部 gRPC が認証されていないサービス拒否の脆弱性を修正しました。 および gRPC-TLS リスナーは、ソース IP ごとに無制限の数の TCP 接続を受け入れました。 リクエスト処理、ACL チェック、またはレート制限が発生する前に。リモート攻撃者 多くの接続を開くことにより、エージェント ファイル記述子、ゴルーチン、メモリを使い果たす可能性があります gRPC または TLS ハンドシェイクを保留します。新しい client-IP ごとの接続リミッターが追加されました。 gRPC サーバーが接続を監視する前に適用され、新しいサーバーによって制御されます。 limits.grpc_max_conns_per_client 構成オプション (デフォルトは 100)。 gRPC ハンドシェイク タイムアウトもライブラリのデフォルトの 120 秒から 20 秒に短縮されました。 (SECVULN-50294) [GH-23797]

改善点:

  • ui: yadda/Gherkin 受け入れテストをネイティブ QUnit (ハーネス、意図/作成、コンポーネント、設定) に移行 [GH-23741]
  • xds: API ゲートウェイ HTTP リスナーの server 応答ヘッダーを制御するための 2 つの新しいオプトイン ProxyDefaults.spec.config キーを追加します: envoy_suppress_envoy_headers (ヘッダーを完全に削除) と envoy_server_header_name (ヘッダーの名前をカスタム値に変更)。両方が設定されている場合は、抑制が優先されます。 [GH-13027]

バグ修正:

  • エージェント: デバッグ レベルのコンテンツ タイプ ログに生の ACL トークンを記録するのを停止します。 [GH-23731]
  • api-gateway: バックエンド サービスの service-router が検出チェーン合成中に別のサービス、名前空間、またはパーティション内の宛先へのルートを構成したときに、HTTP API ゲートウェイが「一貫性のないプロトコル」エラー (断続的な 503 が発生する) でその構成を拒否する原因となった回帰を修正しました。 [GH-23793]
  • serf: WAN フラッドジョインを修正して、非アライブ宛先メンバー (脱退/離脱/失敗) を無視し、再参加したサーバーが WAN メンバーシップでアライブに回復できるようにします。 [GH-23709]
  • xds: 接続プロキシ受信リスナーの HTTP リクエストと同様の GPRC リクエストへの XFCC ヘッダーの追加 [GH-23744]
