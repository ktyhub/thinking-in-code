go-ethereum v1.17.0

#ゴーイーサリアムv1.17.0

<!-- Eezo インレイド回路 (v1.17.0) -->

これは、過去 3 か月間の開発の蓄積がすべて含まれた機能リリースです。ハイライトについては以下を参照してください。

このリリースには複数の重要なセキュリティ修正と多くのバグ修正が含まれており、すべてのユーザーに推奨されることに注意してください。ただし、アップグレードに慎重な場合は、重要なセキュリティ修正だけを含む v1.16.9 をインストールすることもできます。具体的には、このリリースでは CVE-2026-26313、CVE-2026-26314、CVE-2026-26315 が修正されています。

この更新プログラムをインストールした後、p2p ノード キーを再作成することをお勧めします。これを行うには、geth を再起動する前に DATADIR/geth/nodekey ファイルを削除します。これにより、p2p ノード ID が変更され、静的ピアリング設定が破壊される可能性があることに注意してください。

ハイライト

証明付きのパスベースのアーカイブ ノード

パスベースのアーカイブ ノードは、古いブロックの状態の証明を (eth_getProof 経由で) 提供できるようになりました。

他のアーカイブ状態の可用性から独立して証明をサポートするブロック範囲を構成できます。具体的には、--history.trienode コマンド ライン フラグを使用して、ツリー ノードを追跡するブロックの量を設定できます。

この機能はデフォルトでは無効になっています。状態履歴はブロックの処理によってのみ生成されるため、一度削除すると簡単には復元できないことに注意してください。ただし、トライノード履歴 (および/または状態履歴) をいつでも有効にして、完全なノードを部分的なアーカイブ ノードに変換し、その時点以降の状態を維持することができます。

#32727、#32621、#33551、#32981、#33399、#32913、#33303、#33584、#33329、#33681、#33103、#33098、#33515、#32247

EraE 履歴のサポート

Geth は、マージ後のチェーン履歴のアーカイブ形式である EraE ファイル形式をサポートするようになりました。

#32157、#33827

OpenTelemetry トレース

OpenTelemetry トレースが、分散トレースのサポートを含め、RPC サーバーでサポートされるようになりました。 また、エンジン API (つまり engine_newPayload) を介したブロック処理用のトレース スパンも追加しました。

#33599、#33452、#33780、#33521

すべての変更

ゲス CLI

  • geth version-check サブコマンドは削除されました。このコマンドは、geth Web サイトで署名された脆弱性通知をチェックし、更新が必要かどうかを通知します (#33498)
  • ビルドされたブロックに含まれる BLOB に制限を設定するための --miner.maxblobs コマンドライン フラグが追加されました (#33129、#33302)
  • Geth は、Grafana パイロスコープによる連続プロファイリングをサポートするようになりました (#33623)
  • geth --dev モードでブロックの生成を停止する可能性があるまれなバグが修正されました (#33146)
  • 新しい --rpc.rangelimit フラグは、eth_getLogs の最大ブロック範囲を構成します (#33163)
  • geth --exitwhensynced は finalized および safe ブロックを設定するようになりました (#33038)
  • geth --ethstats は newPayload の処理時間を統計サーバーに報告するようになりました (#33395)
  • Geth のコマンドライン フラグ処理における多くの小さな問題が修正されました (#33379、#33338、#33330、#32999、#33279、#33252)
  • evm blocktest コマンドは、パスが指定されていない場合でも stdin からファイル名を読み取ることができるようになりました (#32824)

フォークの実装

  • EIP-8024: 下位互換性のある SWAPN、DUPN、EXCHANGE (#33095、#33787、#33614、#33361)
  • Engine_getBlobsV3 を実装しました (#33404、#33444)
  • エンジン API は、間違ったペイロード バージョンの呼び出しを拒否するようになりました (#32754、#33322)
  • Fusaka 用の blsync が更新されました (#33349、#33272、#33065、#32674)
  • バイナリ ツリーへの状態の移行に向けたいくつかの作業が完了し、これが Verkle Tree 実装を置き換えます (#33807、#33739、#33694、#32445、#33461)
  • EIP-7928 ブロックレベル アクセス リストの作業中に一部のアクセス リスト セマンティクスが修正されました (#33281、#33637、#33450)

コア

  • crypto/ecies ライブラリでは、応答タイミングの観察により、キー導出に使用される秘密キーを抽出できました。この更新を適用した後、ノード キーをローテーションすることをお勧めします。 (#33669)
  • tx のインデックス解除中に欠落したブロックが発生した場合、Geth は無限ループに入らずに、そのブロックをスキップして先に進むようになりました。 (#33573)
  • Geth は、オプションで状態の合計サイズに関するメトリクスを収集およびエクスポートできるようになりました (#33254、#33376、#33415)
  • 新しい OnStateUpdate フックがあり、ブロックのすべての状態がコミットされた後に呼び出されます。これにより、ブロックの変更セットにアクセスできるようになります。 (#33490)
  • いくつかのマイナーなトレースのバグが修正されました (#32919、#33148、#33644、#33214)
  • フリーザーデータベースのさまざまな小さな問題も修正されました (#33747、#33025、#33203、#33344)
  • setHead 操作は、ロールバックされたブロック範囲がその前に広がっている場合、ファイナライズされたブロックの設定を解除するようになりました。 (#33486)
  • types.Signer の SignatureValues メソッドは、無効な署名サイズのエラーを報告するようになりました (#33647)
  • Geth は、「遅いブロック」(#33655、#33525、#33442、#32812、#33659、#33532) の詳細なログ メッセージを出力します。
  • Pebble 構成が調整され、パフォーマンスが向上しました (#33697、#33353、#33315)
  • REORG 処理に関連したログ インデクサーでの稀なクラッシュが修正されました (#33810)
  • 内部状態差分サイズのアカウンティングが修正されたため、状態差分がディスク ストアにフラッシュされる頻度が減りました (#33505)
  • Ethereum で使用される keccak256 ハッシュ関数のバリアントには標準ライブラリに高速パスが含まれなくなったため、keccak 実装をベンダーからリポジトリに戻しました (#33323)

図書館

  • RLP ライブラリには、デコードされていないリストをより便利な方法で処理するための RawList タイプが追加されました (#33755、#33834、#33840、#33841)
  • 低レベル RLP イテレータとその使用法が改善されました (#33245、#33188、#33820)
  • Clef はセルプルーフを使用して BLOB トランザクションに署名できるようになりました (#32910)
  • メトリクスのエクスポートにおけるいくつかの例外的なバグを修正しました (#33749、#33748)
  • ハードウェア ウォレット ライブラリは Ledger Nano Gen5 をサポートし、サポートされているすべてのバージョンで EIP-712 署名を正しく有効にします。 (#33297、#33113)
  • SignTextWithPassphrase は、サポートされているすべてのハードウェア ウォレットで正しく動作するようになりました (#33138)
  • キーストアの実装でいくつかの小さなバグが修正されました (#33606、#33602、#33090)
  • bitutil.XORBytes 関数は、stdlib パッケージ crypto/subtle を優先して非推奨になりました (#33331)
  • ビーコン チェーン ライト client のメモリ リークが修正されました (#33483)

RPC

  • eth_getTransactionByHash はトランザクション オブジェクトの一部として blockTimestamp を返すようになりました (#33709)
  • eth_simulateV1、eth_getLogs、eth_getStorageAt の一部の条件のエラー コードが改善され、実行 RPC 仕様 (#33007、#33320、#33282) に準拠するようになりました。
  • eth_simulateV1 は、シミュレートされたヘッダーに対して正しいプリコンパイルのセットを選択するようになりました (#33363)
  • eth_sendTransaction と eth_fillTransaction はデフォルトで EIP-1559 になりました (#33058)
  • GraphQL 実装では、解決された項目が見つからない場合に備えていくつかのバグ修正が行われました。 (#33184、#33225)
  • GraphQL では、gasPrice がトランザクション タイプ 0x3 および 0x4 で取得できるようになりました (#33542)
  • RPC サーバーでプレーンテキスト HTTP2 が有効になり、パフォーマンスが向上しました (#33812)
  • RPC client は偽の RST_STREAM HTTP2 フレームを送信しなくなりました (#33122)
  • いくつかのマイナーな JSON エンコーディングのバグが ethclient で修正されました (#33693、#33242、#33464)
  • gethclient には、callTracer (#31510) の新しいラッパーが追加されました。
  • callTracer では、報告されるログに、トランザクション内のログのインデックスである index フィールドが含まれるようになりました (#33629)

P2P ネットワーキング

  • トランザクション プールのハートビート メカニズムで潜在的なリソース リークがいくつか修正されました (#33704)
  • eth および snap プロトコルの実装では、コンテンツをデコードする前にほとんどの p2p メッセージが検証されるようになりました。これにより、場合によってはセキュリティと同期パフォーマンスが向上します。 (#33835)
  • BLOB トランザクション プールはいくつかのバグ修正が行われ、非常に限定された範囲でノンスギャップ トランザクションを受け入れるようになりました (#32717、#33775、#33474、#33352、#33301、#33260)
  • スナップ同期ステータスの追跡が改善され、エンジン API によってスナップ同期が誤ってトリガーされないようになりました (#33157)
  • スナップ同期スケジューラが改善され、ノードがブロックを処理している間の偶発的な突然変異からトライ データベースをより適切に保護できるようになりました。これにより、データベースが破損する可能性があるいくつかの特殊なケースが解決されます (#33428)
  • ヘッダー同期の実装が修正され、同期中の setHead 操作をより適切に処理できるようになりました (#33481)
  • 少数の古いトランザクションの配信はよくあることなので、古いトランザクションを配信するピア接続のペナルティは少なくなります。 (#32725)
  • あるタイプのトランザクションを発表し、別のタイプを配信するピアは、ペナルティとして切断されるようになりました (#33378)
  • 同様に、無効な KZG 証明を提供するピアも切断されます (5b99d2bba4)
  • トランザクション プールには、トランザクションのあるアカウント数に関する新しいメトリクスが追加されました (#33646、#33654)

変更の完全な概要については、Geth 1.17.0 リリース マイルストーンを参照してください。

以前のすべてのリリースと同様に、次のものが見つかります。

  • ダウンロード ページ にあるすべてのプラットフォーム用のビルド済みバイナリ。
  • ethereum/client-go で公開された Docker イメージ (「stable」タグを使用)。
  • Launchpad PPA リポジトリ の Ubuntu パッケージ。
  • Homebrew Tap リポジトリ の macOS パッケージ。
