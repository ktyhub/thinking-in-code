#ナコス3.3.0

Nacos 3.3.0 は、Nacos 3.x シリーズの機能反復リリースです。これにより、プロトコルに依存しないエージェントの管理と検出、共有 AI リソースの検索、統合された MCP ライフサイクル管理が安定版リリースに導入されます。

このリリースは以下に重点を置いています。

  • Agent、AgentSpec、Skill、Prompt、および MCP リソースにわたる AI レジストリ機能。
  • DNS サービスの検出と分散ロック。
  • 動的プラグイン管理と認証はデフォルトで有効になっています。
  • Spring Boot 4 および Jackson 3 との互換性。client とサーバーの信頼性が向上しました。

主な機能の更新内容は次のとおりです。

  • エージェント登録、バージョン管理、ランタイム エンドポイント、RAD 検出、トランスポート ネゴシエーション、Java SDK およびコンソール ワークフローを介したウォッチ/プッシュ。
  • ハイブリッド キーワードとベクトルの取得、アーティファクト アクセス、およびオプションの関連性フィルタリングを使用した共有 AI リソース検索。
  • MCP のドラフト、レビュー、公開、オンライン/オフライン、可視性の管理と、歴史的リソースの移行サポート。
  • UDP および TCP 経由の A、AAAA、および SRV レコードを使用したオプションの DNS 検出。
  • ウォッチドッグの更新と Raft の一貫性を備えた分散リエントラントおよび非リエントラント ロック。

また、安定版リリースでは、バージョン移行全体でスキルのメタデータの一貫性が向上し、可視性プラグイン機能が拡張され、Config SDK の使いやすさ、コンソールの互換性、および Naming の再接続とクラスターの再起動後の回復が強化されています。

これらのメモは累積的であり、3.3.0-BETA および 3.3.0-RC で提供された変更が含まれています。

重大な変更通知

Nacos 3.3.0 は認証のデフォルトを変更し、一部の非推奨の API を無効にし、移行要件を導入します。 BETA または RC の新しいエージェント SDK を使用するアプリケーションも、最終的なサブスクリプション契約を確認する必要があります。

影響を受けるユーザー:

  • 認証情報のない Client API に依存するアプリケーション、または非推奨の Pipeline および MCP インポート エンドポイントに依存するアプリケーション。
  • 従来の構成データ、履歴 AI ストレージ キー、タグなしの Raft ログ、または移行が必要な A2A/MCP リソースを使用したデプロイメント。
  • 組み込みの Prometheus client メトリクスまたは暗黙的な AI リソース可視性のデフォルトに依存するアプリケーション。
  • RAD サブスクリプションを使用するか、オプションの DNS サーバーにリモートでアクセスする BETA/RC アダプター。

推奨されるアップグレード パス:

  • Cli を準備して API 認証情報を入力します。 存在しない nacos.core.auth.enabled は true を意味します。既存の明示的な false 設定は引き続き有効です。必要に応じて、資格情報のプロビジョニング中に認証を明示的に無効にし、client アクセスを確認した後、クラスター全体で一貫して認証を有効にします。管理者およびコンソール認証のデフォルトは変更されません。
  • 非推奨の AI API 呼び出しを移行します。 選択されたレガシー パイプラインおよびコンソール MCP インポート エンドポイントは、デフォルトで HTTP 410 と API_DEPRECATED を返します。パイプライン /list および /detail エンドポイント、および統合 /v3/console/ai/import/validate および /execute エンドポイントを使用します。 nacos.core.api.compatibility.enabled=true は、選択したエンドポイントを一時的に再度開きます。 nacos.ai.resource.import.legacy-mcp-api-enabled は認識されなくなりました。
  • レガシー構成の移行を完了します。 3.0 以前の展開を以前の Nacos 3.x バージョンにアップグレードします。デフォルトの名前空間データを空のテナントから public に移行し、従来のベータ/タグ データを config_info_gray に移行します。 nacos_config AI ストレージ プロバイダーの場合は、影響を受ける過去の非 ASCII または長すぎる構成座標を、確定的な ASCII セーフ マッピングに明示的に移行します。
  • 永続化された Raft ログを確認してください。 Nacos 3.3 は、元々 Nacos 2.0.x によって書き込まれ、中間アップグレードを通じて保持されたエントリを含む、タグなしエントリを再生しなくなりました。アップグレードする前に、互換性のあるバージョンでこれらのログまたはスナップショットを復元して移行します。実行中のバージョンを変更するだけでは、永続化されたログは変換されません。
  • 履歴 A2A および MCP の移行を計画します。 デフォルトの nacos.ai.a2a.compatibility.mode=CANONICAL は履歴 A2A データをスキャンしません。 AUTO の移行と初期の 3.3 プリフライトについては、A2A アップグレード ランブック に従ってください。永続的な正規カットオーバーの後、レガシー専用サーバーは再参加してはなりません。一方向のライフサイクル移行中に、MCP 調整状態とその既存の構成/ネーミング提供データを保持します。
  • クラスター サーバーの ID の一貫性を保ちます。 ネイティブ JRaft 認証は、すべてのメンバーがサポートをアドバタイズした後に強制され、強制は再起動後も持続します。 JRaft 認証情報のサポートがないメンバーへのローリング ダウングレードは、引き続き利用可能であるとは保証されません。
  • BETA/RC エージェント SDK コンシューマを更新します。 新しい RAD subscribeAgent メソッドは void を返すようになりました。初期状態とその後の更新の両方をリスナー経由で受信し、サブスクライブする前にリスナーの状態を準備し、依存するアプリケーションを再コンパイルします。従来の A2A 署名と HTTP/gRPC 電信契約は変更されません。
  • client メトリクスを明示的に構成します。 nacos-client には、必須の Prometheus client 依存関係が含まれなくなりました。メトリックが必要な場合は、NacosClientMetricsProvider の実装をインストールします。これがないと、enableClientMetrics が有効になっている場合でも、録音は何も行われません。
  • MCP のインポートと表示設定を確認してください。 プライベートまたはローカルの MCP インポート ターゲットには nacos.console.ai.mcp.import.allowed-private-addresses が必要であり、リダイレクトは適用されません。組み込みの可視性プラグインは、新しく作成されたエージェントおよび MCP リソースをデフォルトで PUBLIC に設定します。必要に応じてプライベート スコープを明示的に選択します。既存の保存されたスコープとプロンプト/スキルのデフォルトは変更されません。
  • DNS リスナー構成を確認します。 DNS はオプションのままで、デフォルトでは無効になっています。有効にすると、nacos.naming.dns.bind-address はデフォルトで 127.0.0.1 になります。リモート client の目的のリスニング アドレスを構成します。外部転送には、個別の明示的な構成が必要です。
  • 影響を受けるスキルのメタデータを更新します。 解析されたフロントマターのない過去のスキル記述子は、既存のメタデータを保持します。このリリースでは、パッケージを自動的に読み取ったり、不足しているメタデータを埋め戻したりすることはありません。コンテンツを更新するか、影響を受けるスキルを再アップロードしてフロントマターを再生成し、以前に保存された複数行の説明を修正します。
  • バックアップとアップグレードのリハーサルを行います。 データベースと永続化されたサーバー データをバックアップし、ステージングでの認証、データ移行、検出、および client の動作を確認します。 Embedded Derby は 10.16.1.1 にアップグレードされるため、アップグレードの検証には永続化データの読み取り、後続の書き込み、リカバリの再開が含まれます。

影響を受ける履歴データが存在しない展開では、これらのデータ移行は必要ありません。認証のデフォルトと該当する API または SDK の変更はまだ検討する必要があります。
