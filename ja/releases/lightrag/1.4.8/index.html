LightRAG v1.4.8

#ライトラグv1.4.8

メモをインポートする

  1. 生データ クエリ API /query/data を導入しました。これにより、開発者は、きめ細かい処理のために LightRAG によって呼び出された完全な生データを取得できるようになります。
  2. 1 つのバッチ ジョブで数百のドキュメントと数十万の関係を効率的に処理できるようにシステムを最適化し、UI の遅延を解決し、システム全体の安定性を向上させました。
  3. パフォーマンスとクエリ結果に悪影響を与える短い数値名のエンティティを削除します。 2 桁のみを含む名前、6 文字未満の名前、1.1、12.3、1.2.3 などの数字とドットが混在した名前は削除されます。
  4. 小規模なパラメーター モデルのエンティティおよび関係抽出の量と質が大幅に向上し、クエリ パフォーマンスの大幅な向上につながります
  5. Qwen3-30B-A3B-Instruct および gpt-oss-120b モデルのプロンプト エンジニアリングを最適化し、モデル出力に目標とするフォールト トレランスを組み込みました。
  6. 大規模言語モデル (LLM) 応答のエンティティ関係抽出フェーズ中の 過度に長いまたは無限の出力ループを防止するため、max tokens および tempreture 構成を実装しました。
# Increased temperature values may mitigate infinite inference loops in certain LLM, such as Qwen3-30B.
OPENAI_LLM_TEMPERATURE=0.9

# For vLLM/SGLang doployed models, or most of OpenAI compatible API provider
OPENAI_LLM_MAX_TOKENS=9000

# For Ollama Deployed Modeles
OLLAMA_LLM_NUM_PREDICT=9000

# For OpenAI o1-mini or newer modles
OPENAI_LLM_MAX_COMPLETION_TOKENS=9000

max tokens パラメータを設定する目的は、タイムアウトが発生する前に LLM 出力を切り詰め、それによってドキュメント抽出の失敗を防ぐことです。これは、多数のエンティティや関係を含む特定のテキスト ブロック (表や引用など) が、LLM からの過度に長い、または無限ループ出力につながる可能性がある問題に対処します。この設定は、ローカルにデプロイされたパラメータの小さいモデルにとって特に重要です。最大トークン値は次の式で計算できます。 LLM_TIMEOUT * llm_output_tokens/second (つまり 9000 = 180s * 50 tokens/s)
