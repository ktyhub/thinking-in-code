LightRAG v1.4.9.9

パッチ 公開日2025年12月22日 出典HKUDS/LightRAG 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ライトラグv1.4.9.9 #Release Note V1.4.9.9

重要な注意事項

  • パイプライン ステータスとメモリ内ストレージのためのワークスペース分離の追加: 個別のワークスペースを持つ複数の LightRAG インスタンスを同時に作成できるため、単一の LightRAG サーバー内でのシームレスなワークスペース切り替えに向けた大きな進歩が見られます。
  • PostgreSQL および Qdrant のモデル名とディメンションによるワークスペース ベクター データ分離の追加: 以前は、LightRAG は差分埋め込みモデルとディメンションに単一のコレクション/テーブルを使用していました。これにより、マルチワークスペースでディメンションの不一致クラッシュやデータ汚染が発生していました。
  • 次元の選択は OpenAI および Gemini でサポートされています 新しい環境変数が導入された埋め込みモデル: EMBEDDING_SEND_DIM
  • 異なる KV ストレージ間で LLM キャッシュ移行ツールと LLM クエリ キャッシュ クリーンアップ ツールを追加: ユーザーは、キャッシュされた抽出データや概要データを失うことなく、ストレージ バックエンドを切り替えることができます。
  • 強化 強化 テーブル コンテンツ サポートによる DOCX 抽出。
  • セル内の tab および newline 文字を適切に処理することで、XLSX 抽出が強化されました。
  • React サーバー コンポーネントの重大なセキュリティ脆弱性を修正: #2494
  • 埋め込み関数の自動テキスト切り捨てサポートを追加: OpenAI 埋め込み関数は、EmbeddingFunc の max_token_size 値を考慮し、モデル トークンの制限を超えるテキストによって引き起こされる API エラーを防ぐために、入力テキストを自動的に切り捨てるようになりました。

What's Breaking (LightRAG Core 統合のみ)

  • チャンク関数のパラメータの名前を変更: チャンク関数を LightRAG に組み込み、パラメータを名前で渡す場合は、対応するコードの更新が必要です。
def chunking_by_token_size(
    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,
    chunk_overlap_token_size: int = 100,
    chunk_token_size: int = 1200,
) -> list[dict[str, Any]]:
  • wrap_embedding_func_with_attrs を使用して、model_name を持つ embedding_func を LightRAG に挿入します。
@wrap_embedding_func_with_attrs(
    embedding_dim=1536, max_token_size=8192, model_name="text-embedding-3-small"
)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

rag = LightRAG(
      working_dir=WORKING_DIR,
      llm_model_func=llm_model_func,
      embedding_func=embedding_func,
)

シームレスな移行を保証するために、model_name なしで embedding_func を挿入する従来のコードは、接尾辞のない元のベクトル テーブルとのインターフェイスを継続します。
