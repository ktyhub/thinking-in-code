#ファイアクロールv2.7.0

ファイヤークロール v2.7.0 登場!

  • 企業顧客向けの ZDR 検索サポート。
  • ブランディング形式が改善され、検出が向上しました。
  • パートナー統合 API は現在クローズド ベータ版です。
  • より速く、より正確なスクリーンショット。
  • 自己ホスト型の改善

さらに多くの機能強化が施されているので、以下をチェックしてください。

新機能

  • ブランディング抽出の改善
    ロゴと色の検出が改善され、より正確なブランド抽出結果が得られます。

  • NOQ スクレイプ システム (実験的)
    安定性が向上し、同時実行チェックが統合された新しいスクレイピング パイプライン。

  • リダイレクト処理の強化
    より安全なリダイレクト チェーン検出と新しい中止タイムアウトにより、URL はマッピング前に解決されるようになりました。

  • エンタープライズ検索パラメータ
    /search エンドポイントで使用できる新しいエンタープライズ レベルのオプション。

  • 統合ベースのユーザー作成
    参照統合からのユーザーを自動的に作成できるようになりました。

  • minAge スクレイピング パラメータ
    再 scraping までの最小キャッシュ経過時間を要求できるようにします。

  • 請求クレジットの抽出
    抽出ジョブは、他のエンドポイントと同じクレジット請求システムを使用するようになりました。

  • セルフホスト: 構成可能なクロール同時実行
    セルフホスト型の展開では、カスタムの同時実行制限を設定できるようになりました。

  • セントリーの強化
    Vercel AI の統合、構成可能なサンプリング レート、および例外フィルタリングの改善が追加されました。

  • UUIDv7 ID
    すべての新しいリソースは、辞書順に並べ替え可能な UUIDv7 を使用します。

API の改善

  • DNS 解決エラーは 200 を返すようになりました。これにより、より一貫性のある障害処理が可能になります。
  • 改善された URL マッピング ロジック (サイトマップ maxAge の修正、再帰的サイトマップのサポート、Vue/Angular ルーターの正規化、IP アドレスのサブドメイン ロジックのスキップなど)。
  • マルチソース検索の部分的な結果。すべてのソースが失敗するのではありません。
  • ジョブ応答を収集するために 同時実行メタデータが追加されました。
  • 拡張メトリクス (合計待機時間、LLM の使用状況、形式の詳細など)。
  • バッチ スクレイピング アップグレード
    • 欠落していた/v2/batch/scrape/:jobId/errorsエンドポイントを追加しました
    • ページネーションが 1 つずつずれるバグを修正
  • PDF/ドキュメント エンジン、pydantic 解析、Zod 検証、URL 検証、および請求エッジ ケース向けのより堅牢なエラー処理。

SDK の改善

JavaScript SDK

  • 同期メソッドから ジョブ ID を返します。
  • WebSocket document イベントの処理を改善しました。
  • タイプ、Deno WSを修正し、ignoreQueryParameterのサポートを追加しました。
  • 内部クリーンアップによるバージョンアップ。

Python SDK

  • 追加のメタデータ フィールドを追加しました。
  • バッチ検証処理が改善されました。

品質とパフォーマンス

  • ログ ファイル サイズが削減され、tmp ファイルのクリーンアップが改善されました。
  • Express バージョンを更新し、脆弱なパッケージにパッチを適用しました。
  • パフォーマンスを向上させるために、サイトマップ スクレイピングのマークダウン変換を無効にしました。
  • クロール前のロギングとフォーマットの改善。
  • 公開された Google ドキュメントの URL 書き換えをスキップします。
  • Webhook コールバック中に空の Cookie ヘッダーが発生しないようにします。

セルフホストによる改善

  • セルフホスト モードの同時実行制限の強制を無効にしました。
  • ZZPH100​​ZZ 資格情報が環境変数を介して構成できるようになりました。
  • Docker-compose ビルド命令が修正されました。
