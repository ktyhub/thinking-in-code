#ファイアクロールv2.11.0

ファイアクロール v2.11.0

改善点

  • Firecrawl Research Index — エージェント的 AI/ML 研究に特化したインデックスを追加しました。300 万以上の arXiv 論文とその背後にある GitHub コード (毎日更新される問題、マージされた PR、および README) を検索し、論文の詳細または関連作業を取得し、全文に対して主張をチェックします。 arXivQA では最先端のリコールを備えており、同等のコストで次に優れたプロバイダーを 18% 上回っています。 API、SDK、MCP、および CLI 経由で利用可能です。
  • コア エンドポイントのキーレス アクセス — 公式 MCP、CLI、SDK clients の API キーを使用せずに、/scrape、/search、/interact、/parse を使用します。
  • 自動 PII 編集 — スクレイピングされたコンテンツが返される前に、名前、電子メール、電話番号、住所、機密情報などの個人データや機密データを削除する redactPII オプションを追加しました。
  • deterministicJson 形式 — リクエストごとに LLM を実行せずに構造化された JSON を返す形式を追加しました。 Firecrawl はスキーマの再利用可能なエクストラクターを生成し、サイトごとにキャッシュするため、スクレイピングを繰り返す方がコストが低くなり、一貫した結果が返されます。
  • 任意のページでのビデオ検出 — YouTube などのサポートされているプロバイダーだけでなく、任意のページでビデオを検索できるように video 形式を拡張し、各ビデオの URL、タイトル、サムネイル、再生時間などを返します。
  • 独自のブラウザ オートメーションをアタッチ - ブラウザ セッションの応答に CDP WebSocket URL (cdpUrl) が追加されたため、Playwright、Puppeteer、またはその他の CDP client を使用してライブ Firecrawl ブラウザ セッションを直接駆動できます。
  • よりスマートなモニター アラート - モニターに goal を追加しました。これにより、LLM は、検出された各変更を意味のあるもの、または実際に関心のあるものに対するノイズとして判断し、アラート スパムをカットし、重要な変更を概要メールの最初に表示します。
  • モニターのフィールドレベルの JSON 差分 — JSON モードでスクレイピングするモニターは、レンダリングされたページではなく、実行間で実際のフィールド値を比較するようになりました。そのため、レイアウトのシフトによるノイズではなく、どのフィールドが変更されたかを正確に確認できます。
  • モニター電子メ​​ールの確認 — 外部モニター受信者に対して 1-click の購読解除を行うオプトイン確認フローを追加しました。チーム メンバーは自動確認され、Monitor 応答で各受信者のサブスクリプション ステータスが報告されるようになりました。
  • AM/PM モニター スケジュール - 正しい UTC cron 式に変換された、daily at 9am や daily at 5:30pm などの 12 時間スケジュール入力のサポートが追加されました。
  • Webhook 配信ステータスの監視 - 各監視チェックに配信ステータスが追加されたため、Webhook が試行されたか、配信されたか、失敗したか、およびその理由を確認できます。
  • より安定したモニター チェック — モニターは、ページのレンダリングが完了するまで待ってから差分を実行し、部分的に読み込まれたページによって引き起こされる誤ったアラートをカットします。
  • PDF サイズの上限 — PDF のダウンロードおよびスクレイピングのサイズ上限を 30 MB から 50 MB に引き上げました。
  • **Python SDK crawl() スクレープ クワーグ ** — 直接スクレープ クワーグ (formats、headers、include_tags、exclude_tags など) を crawl() および start_crawl() に追加し、ScrapeOptions(...) でラップする必要がなくなりました。
  • 明確な .data エラー — 検索結果で .data にアクセスするときに発生するエラーが改善され、サイレント None を返すのではなく、.web、.news、および .images をそれらのカウントとともにポイントするようになりました。
  • Python 形式のデフォルト - JsonFormat および ChangeTrackingFormat で必要な type= 引数を削除し、ScreenshotFormat のようにデフォルトに設定しました。
  • ChangeTrackingFormat ケーシング — type 形式に change_tracking と changeTracking の両方の受け入れが追加されました。これにより、ペイロードは、snake_case と CamelCase client の間で往復します。

修正

  • axios、esbuild、ws、openssl、およびその他の依存関係をアップグレードすることにより、API および SDK にわたるセキュリティ アドバイザリを解決しました。
  • 以前はジョブのドロップやワーカーの再起動を引き起こしていた、非常に大きな LLM 抽出入力で数十秒間停止するスクレイピング ワーカーを修正しました。
  • ウィキメディア URL の約半分で欠落している metadata.ogImage をウィキペディア スクレイピングで修正しました。
  • クロールとバッチのキャンセルがチームごとの同時実行バックログを排出せず、古い状態を報告しない問題を修正しました。キューに入れられたジョブは削除され、status は直ちに cancelled を報告します。
  • クレジットロックが拒否された場合に請求されるモニター小切手を修正しました。ロックが拒否された場合、チェック skipped_no_credits がマークされ、実行が停止されるようになりました。
  • フィールド値が同一であるが順序が変更されている場合に、JSON モード モニターの差分が偽の changed 判定を返す問題を修正しました。 diff は順序に依存しない等価性を使用するようになりました。
  • JSON モード モニターが空の文字列スクレイピングを入力欠落として扱い、実行のたびに changed を報告する問題を修正しました。
  • 同じチェックのために 2 回ディスパッチされるモニター Webhook を修正しました。
  • クロール/バッチ形状に一致するように配列内の monitor.page および monitor.check.completed ペイロードをラップすることにより、不正な形式としてドロップされるモニター Webhook を修正しました。
  • モニタージャッジがテキストの前後で捏造し、長いページでコンテキストを失う問題を修正しました。現在は完全に統合された diff を唯一の証拠として受け取ります。
  • GET /v2/monitor/:id/checks/:checkId を破壊する破損した、または予期しない保存されたアーティファクトを修正しました。不正なデータは差分なしとして表示されるようになりました。
  • 最初の行に td セルが使用されている場合に、HTML テーブルのヘッダー行が失われる問題を修正しました。マークダウン コンバーターはそれをヘッダーにプロモートするので、列ラベルは document.markdown まで存続します。
  • 特定のスクレイピング パスでバイパスされる PDF サイズの上限を修正し、サイズを超える PDF が一貫して拒否されるようになりました。
  • Python SDK シリアル化ラウンドトリップによってドロップされる ChangeTrackingFormat オプション (modes、prompt、および関連フィールド) を修正しました。

API

  • POST /v2/scrape、/v2/batch/scrape、/v2/crawl、/v2/parse、および /v2/extract で実験的な pii 形式を redactPII (boolean または { mode?, entities?, replaceStyle? }) に置き換えました。有効にすると、document.markdown は編集されたテキストを返します (デフォルトは mode: "accurate"、replaceStyle: "tag")。古い pii 形式と document.pii ブロックは削除され、formats に "pii" を含むリクエストは拒否されるようになりました。
  • deterministicJson 形式 ({ type: "deterministicJson", schema?, prompt? }) が POST /v2/scrape、/v2/batch/scrape、/v2/crawl、/v2/parse、および /v2/extract に追加され、document.json が追加されました。 jsonフォーマットとの組み合わせはできません。
  • document.videos: VideoItem[] (url、sourceURL、source、およびオプションの title、thumbnail、duration、寸法などを含む) を POST /v2/scrape に追加し、video 形式が要求された場合にそのオプションを共有するエンドポイントを追加しました。従来の document.video 文字列は、サポートされているプロバイダー用に残ります。
  • createdAt、completedAt、duration (秒) を GET /v2/crawl/{id} と GET /v2/batch/scrape/{id} に追加しました。 completedAt は終端状態にのみ存在します。
  • /v2/search/research プロキシ (GET /v2/search/research/papers、/papers/:id、/papers/:id/similar、/github) を追加しました。SEARCH_CREDITS に対して 10 結果あたり 2 クレジット (ZDR チームの場合は 10 あたり 10) で請求されます。従来の /v2/research/* マウントは、非推奨のエイリアスとして保持されます。
  • /v2/browser セッション エンドポイントの完全なエイリアスとして ZZPH100​​ZZ/GET /interact、POST /interact/:sessionId/execute、および DELETE /interact/:sessionId を追加しました。動作、レート制限、および 2 クレジットのセッション作成料金は同一です。
  • cdpUrl (Python: cdp_url) を POST /v2/scrape/:jobId/interact および /v2/browser 実行応答に追加し、既存のライブビュー URL とともに生の CDP WebSocket URL を公開します。
  • 共有記録および返金ロジックを使用した検索、スクレイピング、解析、およびマップ ジョブをカバーする POST /v2/feedback を追加しました。従来の POST /v2/search/:jobId/feedback は引き続き動作し、同じストアに書き込みます。
  • POST /v2/parse へのキーレス アクセス、一致するスクレイピングと検索を追加し、キーレス クレジット アカウンティングを強化して、同時リクエストが IP ごとの 1 日の上限内に収まるようにしました。
  • エージェント client が資格情報スキームを検出できるように、/v0、/v1、および /v2 にわたるすべての 401 応答に WWW-Authenticate: Bearer realm="firecrawl" ヘッダーを追加しました。
  • searchZDR 値 "forced-zdr" および "forced-anon" と、非推奨の "forced" (現在は "forced-zdr" の別名) を追加しました。解決済みモードは、請求とルーティングの両方を推進します。
  • goal と judgeEnabled を POST /v2/monitor と PATCH /v2/monitor/:id に追加しました。 goal が設定されている場合、judgeEnabled はデフォルトで true になり、goal: null がそれをクリアします。
  • チェック ページを監視するための judgment、meaningfulChange (変更ごとの reason を含む)、meaningfulChanges[]、構造化 diff オブジェクト (text および/または json)、および snapshot フィールドを追加しました。 JSON モード チェックは、フィールド レベルの差分と現在の値のスナップショットを返します。
  • 認証されていない POST /v2/monitor/email/confirm および POST /v2/monitor/email/unsubscribe (リクエスト本文でのみ受け入れられるトークン) に加えて、各受信者の email、status (pending/confirmed/unsubscribed)、source、および confirmationEmailSent を報告する Monitor 応答の emailRecipientSubscriptions 配列を追加しました。
  • 他の v2 エンドポイントと一致する、ボディの作成/更新を監視するための origin を追加しました。
  • POST /v2/crawl および POST /v1/crawl の delay に対するより厳格な検証を追加しました。非数値、負の値、または 86400 を超える値は、サイレントに適用されるのではなく、スキーマ エラーで拒否されるようになりました。
  • include_domains および exclude_domains を Python SDK の同期 Firecrawl.search() に追加し、非同期 client および /v2/search ペイロードと一致させました。
  • V2 Python および JS client に V1 互換のメソッド エイリアス (scrape_url/scrapeUrl、crawl_url/crawlUrl、batch_scrape_urls、map_url など) を追加しました。エイリアスは DeprecationWarning を発行します。
  • data を配列でラップするようにモニター Webhook ペイロードを変更しました。 monitor.page には、isMeaningful、judgment、および diff オブジェクトが含まれるようになりました。
  • モニター scrapeOptions.formats が正規化されたため、changeTracking json モードは json に書き換えられ、混合 ["json", "git-diff"] フォームは、黙って 1 つにフォールバックするのではなく、両方の差分を実行するようになりました。
