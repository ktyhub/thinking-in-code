#ファイアクロールv2.10

ファイアクロール v2.10

改善点

  • /parse エンドポイント — 最大 50 MB のローカル ファイル (PDF、DOCX、DOC、ODT、RTF、XLSX、XLS、HTML) をアップロードし、クリーンな LLM 対応マークダウン、JSON、または概要を取得します。テーブルと読み取り順序は保持され、エンタープライズ プランではゼロ データ保持が完全にサポートされます。 JS、Python、Go、Rust、Java、.NET、PHP、Ruby、および Elixir SDK で利用可能です。
  • ロックダウン モード - /scrape に lockdown: true を設定すると、デフォルトで送信リクエストもデータ保持もゼロで、Firecrawl のインデックスからのみ結果が提供されます。ゲートされたアウトバウンド パスには、HTTP フェッチ、robots.txt、オーディオ ダウンロード、およびメディアが含まれます。すべての SDK、CLI (--lockdown)、および MCP で利用可能です。
  • question 形式 — 自然言語プロンプトを /scrape に渡すと、根拠のある幻覚のない回答が data.question で返されます。自動フォールバック、XML タグ付けおよびゼロ幅スペース escaping によるプロンプト挿入分離を備えたマネージド モデル チェーン上で実行され、呼び出しあたりのトークンが最大 100 分の 1 に削減されます。
  • highlights 形式 — クエリに一致するページ上の正確な文、コード ブロック、テーブル行を返します。連続した文は段落に再結合され、コード行は元の言語で囲まれたブロックでラップされ、テーブルの行はヘッダー付きの Markdown テーブルに再構築されます。これらはすべてソース ページから行われ、呼び出しごとに使用するトークンの量が最大 100 分の 1 になります。
  • video 形式 — スクレイピング形式に video を追加しました。認証されたダウンロード用の Cookie 転送と明示的なロックダウン ゲートを使用して、サポートされているサイト (YouTube など) の署名付きのダウンロード可能なビデオ URL を返します。
  • /search ドメイン フィルター - 結果の範囲を特定のサイト セットに絞り込むために、includeDomains パラメーターと excludeDomains パラメーターを /search に追加しました。
  • /search フィードバック エンドポイント — POST /v2/search/:jobId/feedback を使用して検索結果に対する評価を送信します。承認された送信ごとに、冪等な再試行で、UTC 日ごとに上限のある 1 クレジットが払い戻されます。
  • カスタム robots.txt ユーザー エージェント - カスタム エージェント文字列に対する robots.txt ルールとクロール遅延を評価するためのクロール リクエストに robotsUserAgent を追加しました。また、ignoreRobots とは独立した個別の customRobotsAgent 組織フラグを追加しました。 JS、Python、および Java SDK で使用できます。
  • 公式 Go SDK — コミュニティ モジュールを置き換える、v2 API 用のファーストパーティ Go SDK を追加しました。コンテキストを認識した再試行バックオフと適切な MapData.Links タイピングが含まれます。
  • Ruby SDK — エンドポイントを完全にカバーし、v2 ネイティブの型指定を備えた公式 Firecrawl Ruby SDK v2 を追加しました。
  • PHP SDK — Laravel サポート、スクレイピング/検索/クロール/マップ/解析のカバレッジ、および公開された firecrawl/firecrawl-sdk Composer パッケージを備えた公式 PHP SDK を追加しました。
  • .NET SDK — v2 API サポート、解析、および firecrawl-sdk NuGet パッケージを備えた公式 .NET SDK を追加しました。
  • Rust SDK v2 — Rust SDK は、スクレイピング、検索、クロール、マップ、エージェント、解析において同等性を備えた公式 v2 SDK に昇格しました。
  • /interact の提案 — actions 配列を渡す /scrape の呼び出しは、ステートフル ブラウザーの自動化について /interact を提案する警告を返すようになりました。
  • PDF サイズの上限 — PDF アップロード サイズの制限が 10 MB から 30 MB に引き上げられました。
  • PDF ページ処理された請求 — 生のページ数ではなく処理されたページを反映するように PDF 請求を更新しました。
  • Docker ハーネス — より長い起動時間を必要とするセルフホスト ユーザー向けに、HARNESS_STARTUP_TIMEOUT_MS から docker-compose を公開しました。
  • Elixir SDK — /parse エンドポイントの Elixir SDK に parse_file/3 を追加しました。
  • JS SDK リクエスト タイムアウト — リクエストのハングを防ぐために、明示的なリクエスト タイムアウト オプションを JS SDK に追加しました。

修正

  • axios、postcss、fast-xml-parser、protobufjs、follow-redirects、langsmith、lodash、fast-uri、fast-xml-builder など、API および SDK にわたる複数の CVE を解決しました。
  • LLM が値を省略した場合にブランド化 colors.secondary が誤って設定される問題を修正しました。secondary はオプションとなり、デフォルトとして適用されなくなりました。
  • Playwright サービスが呼び出し側の User-Agent リクエスト ヘッダーを無視する問題を修正しました。
  • 署名付き URL の有効期限が切れたときにキャッシュ ミスを強制することで、screenshot 署名付き URL がキャッシュから古い結果を返す問題を修正しました。
  • デフォルトでロックダウンをデータ保持ゼロとして扱うことにより、ロックダウン リクエストが ZDR に対して 2 回請求される問題を修正しました。
  • プロキシ出力が発生しない場合に、キャッシュされたスクレイピングに対するプロキシ クレジットが誤って請求される問題を修正しました。
  • 音声のみのスクレイピングおよび音声ダウンロードで実行されている YouTube トランスクリプト スクリプトが CDP Cookie を受信しない問題を修正しました。
  • データ保持ゼロを無視する html-to-md 変換サービスを修正しました。
  • 特定の PDF 出力を処理するときの marked.parse のスタック オーバーフローを修正しました。
  • robotsUserAgent がネイティブ リンク フィルターによって受け入れられず、JS SDK クロール ペイロードに含まれない問題を修正しました。
  • 非 UUID ジョブ ID で 500 を返す /v1 ステータス エンドポイントを修正しました。現在は適切な 400 を返します。
  • 空の actions: [] 配列が機能フラグのアクションとして扱われる問題を修正しました。
  • JS SDK ウォッチャーが重複イベントを発行し、タイムアウトをリークし、ウォッチャー タイムアウトで start() をハングする問題を修正しました。
  • Ruby SDK による credit_usage データ フィールドのアンラップを修正し、デフォルトで skipTlsVerification を false に設定しました。
  • Python、Java、および Go SDK で欠落していた負の制限の検証を修正しました。
  • Java SDK が空の API キーを受け入れ、非同期ライフサイクル メソッドが欠落している問題を修正しました。
  • 請求期間のタイムスタンプ、サブスクリプションの検索、およびプランのクレジット レポートを修正しました。
  • クロールバックログのタイムアウトが制限されていないのを修正しました。現在は 48 時間に制限されています。

API

  • 最大 50 MB のマルチパート ファイルのアップロード用に POST /v2/parse を追加しました。標準のドキュメントを返します。解析時に許可されていないスクレイピング オプション: changeTracking、screenshot、branding、actions、waitFor、location、mobile。 proxy は auto または basic に制限されます。許可されていない入力での PARSE_UNSUPPORTED_OPTIONS のエラー。
  • lockdown: boolean を /scrape に追加しました。キャッシュミスは 404 を SCRAPE_LOCKDOWN_CACHE_MISS で返します。請求: lockdown が有効な場合は +4 クレジット、キャッシュミスの場合は 1 クレジット。すべての SDK で利用可能です。
  • question と highlights を /scrape 形式に追加し、それぞれ data.question と data.highlights を返します。
  • video を /scrape 形式に追加しました。 document.video を署名付き URL として返します。リクエストごとに +4 クレジット。サポートされていない URL では SCRAPE_VIDEO_UNSUPPORTED_URL が発生します。 parse は、video フォーマット client-side およびサーバー側を拒否します。
  • 結果を特定のドメインにスコープするために、/v2/search に includeDomains および excludeDomains 配列を追加しました。
  • 検索結果の評価に POST /v2/search/:jobId/feedback を追加しました。承認された送信ごとに 1 クレジットが払い戻され、UTC 日ごとに SEARCH_FEEDBACK_DAILY_CAP_CREDITS 経由で上限が設定され、冪等な再試行では alreadySubmitted: true が返されます。 SEARCH_FEEDBACK_MAX_AGE_SEC (デフォルトは 120 秒) より古いフィードバックの送信は拒否されます。回答で明らかになったように、検索の請求は ceil(results/10) * 2 クレジットになりました。
  • カスタム エージェント robots.txt 評価用に robotsUserAgent から /v2/crawl crawlerOptions を追加しました。 ignoreRobots 組織旗の後ろでゲートされています。
  • ignoreRobots とは独立した個別の customRobotsAgent 組織フラグを追加したため、チームは robots.txt の適用を無効にすることなくカスタム ユーザー エージェントを出荷できます。
  • ignoreRobots 組織フラグをブール値から disabled / allowed / forced パターンに移行しました。従来の ignoreRobots: boolean リクエスト形式は削除されました。clients は新しいフラグ値を使用する必要があります。
  • /v0/scrape、ZZPH100​​ZZ、/v0/crawl/status/:jobId、DELETE /v0/crawl/cancel/:jobId、/v0/search、/v1/extract、/v1/extract/:jobId、/v2/extract、/v2/extract/:jobId、/v1/deep-research、/v1/deep-research/:jobId、/v1/llmstxt、/v1/llmstxt/:jobIdは非推奨になりました。非推奨のエンドポイントは、Deprecation: true、Warning: 299 - "<message>"、Link; rel="successor-version"、および (構成されている場合) Sunset ヘッダーに加えて、JSON 本文の warnings[] および replacement を発行します。 JS および Python SDK は、これらを client に表面化します。
