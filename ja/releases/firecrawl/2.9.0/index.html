#ファイアクロールv2.9.0

ファイアクロール v2.9.0

改善点

  • /interact エンドポイントを介したブラウザー インタラクション — ページをスクレイピングし、その後 /interact を呼び出してそのページに対するアクションを実行します — click ボタン、フォームへの入力、より深く移動、または動的コンテンツの抽出。 prompt を介して自然言語で必要なものを記述するか、完全な制御のために Playwright コード (Node.js、Python) と Bash (agent-browser) を作成します。セッションは通話をまたいで持続し、リアルタイムのブラウザ ストリーミング用のライブ ビュー URL とインタラクティブ ライブ ビュー URL を使用します。永続的なプロファイルを使用すると、ブラウザの状態 (Cookie、localStorage) をスクレイピング間で保存して再利用できます。 JS、Python、Java、および Rust SDK で使用できます。
  • query 形式 — query 形式を /scrape エンドポイントに追加しました — 自然言語プロンプトを渡し、data.answer で直接応答を返します。
  • audio 形式 — 応答を収集し、オーディオ出力をドキュメント上のフィールドとして返すための audio 形式オプションを追加しました。
  • onlyCleanContent パラメーター - onlyCleanContent パラメーターを /scrape エンドポイントに追加しました。これにより、マークダウン出力からナビゲーション、広告、Cookie バナー、その他の非セマンティック コンテンツが削除されます。
  • PDF 解析モード — PDF 解析モード (fast、auto、ocr) と、抽出深度と OCR 動作を制御する maxPages オプションが追加されました。
  • Java および Elixir SDK — v2 API を完全にサポートする公式 Java および Elixir SDK を追加しました。
  • レガシー .doc ファイルのサポート — レガシー .doc ファイルの解析サポートが追加されました。
  • Wikimedia エンジン - scraping Wikipedia および Wikimedia ページ専用のエンジンを追加し、出力品質が向上しました。
  • 応答のスクレイピングにおける contentType — PDF およびドキュメントの応答のスクレイピングに contentType を追加しました。
  • PDF パイプラインの改善 — テーブル検出、ヘッダー/フッターの除去、混合 PDF の処理、インライン画像解析、マジック バイト検出を強化して PDF パイプラインを改善しました。
  • ブランド抽出 — よりクリーンな出力のために、非表示の DOM 要素をスキップするようにブランド抽出が改善されました。
  • HTML からマークダウンへのパフォーマンス — HTML からマークダウンへの変換パフォーマンスが向上し、変換中にコンテンツが失われるコード ブロックが修正されました。
  • 同時実行キュー — より信頼性の高いジョブ スケジューリングのためのリコンサイラーとバックフィルを備えた新しい同時実行キュー システム。
  • Rust SDK v2 - エージェント サポートを備えた v2 API 名前空間を Rust SDK に追加しました。
  • Python SDK パラメーター timeout、max_retries、および backoff_factor を修正しました。これらは以前は受け入れられていましたが、黙って無視されました。
  • ジョブのタイムアウトを 48 時間に制限し、暴走ジョブによるリソースの消費を防ぎます。
  • スクレイピング ループを防ぐための再試行制限を追加しました。
  • 無駄な処理を避けるために、バイナリ コンテンツ タイプはスクレイピング パイプラインの早い段階で拒否されるようになりました。

修正

  • 抽出ジョブで o3-mini モデルを使用する場合の空の応答を修正しました。
  • 取り消された API キーが削除後も最大 10 分間有効なままになる問題を修正しました。
  • 「ジョブが見つかりません」クラッシュを引き起こす抽出ジョブの競合状態を修正しました。
  • /v1/map の time_taken が常に ~0 を返す問題を修正しました。
  • クロール レベルの障害が発生した場合に、クロール ステータスの応答でエラー メッセージと部分的なデータを含む failed ステータスが表示される問題を修正しました。
  • maxPages が PDF エクストラクターに渡されない問題を修正しました。以前は、制限されたページ数に対してのみ課金され、完全な PDF コンテンツが返されていました。
  • maxCredits しきい値を超えるエージェント ジョブに対して無料リクエスト クレジットが誤って消費され、請求される問題を修正しました。
  • 古い読み取りが原因で誤った同時実行制限が表示されるダッシュボードを修正しました。
  • ブランド colors.secondary が設定されていないのを修正しました。
  • 変圧器パイプラインで deriveDiff の後に実行され、差分の問題を引き起こす removeBase64Images を修正しました。
  • キャッシュ情報ルックアップに間違った行インデックスを使用する GCS フェッチを修正しました。
  • /v1/search コントローラーの未処理の ZodError を修正しました。
  • handlebars、path-to-regexp、fast-xml-parser、rollup (CVE-2026-27606)、undici などの依存関係にわたる複数の CVE を解決しました。
  • SSRF 攻撃に対する Playwright サービスを強化しました。

API

  • カーソルベースのページネーションで最近のスクレイピング、クロール、および抽出ジョブをリストするための GET /v2/team/activity エンドポイントを追加しました (過去 24 時間、ページごとに最大 100 件の結果、エンドポイント タイプでフィルタリング可能)。
  • クエリ パラメータを含む完全な URL に対して includePaths/excludePaths フィルタリングを適用するために、クロール リクエストに regexOnFullURL パラメータを追加しました。 JS、Python、Java、および Elixir SDK で利用可能です。
  • クロール リクエストに deduplicateSimilarURLs パラメーターを追加しました。 JS、Python、Java、および Elixir SDK で利用可能です。
  • extract エンドポイントは非推奨になりました。代わりに /agent エンドポイントを使用してください。 JS の既存の extract メソッドおよび Python SDK は非推奨としてマークされています。
  • ブラウザ/対話リクエストの名前が persistentSession から profile に変更されました (writeMode は saveChanges になりました)。古いパラメータ名は引き続き機能しますが、文書化されなくなりました。
