nanobot v0.1.4.post6

パッチ 公開日2026年3月27日 出典HKUDS/nanobot 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ナノボットv0.1.4.post6 🐈 nanobot v0.1.4.post6 が登場 — 57 人の PR が統合され、27 人の新しいコントリビューターが加わり、表面積を増やすというよりも、その下にあるものを再考するリリースです。 いくつかのリリースでは、何ができるかについて説明されています。これは、どれだけきれいに実行できるかということです。エージェント ランタイムは正式に分解され、主要な依存関係が削除され、ストリーミングがエンドツーエンドになり、セキュリティの脆弱性が解決されました。 v0.1.4.post6 は、長編作品の根底にある構造的な転換点であり、次の リリースを可能にする種類のリリースです。

ハイライト

  • エージェント ランタイムは構成可能な部分に分解されました — 共有 AgentRunner が抽出され、ライフサイクル フックが正式な HookContext に統合され、サブエージェントの進行状況が失敗時でも保持されるようになりました。コマンド ルーティングはプラグインに優しい構造にリファクタリングされ、process_direct は一貫して OutboundMessage を返すように統合されました。これは単なるクリーンアップではなく、プラグイン可能なエージェントの動作、カスタム実行戦略、および次に提供されるサードパーティのライフサイクル統合の基礎となります。 (#2524、#2541、#2388、#2338)
  • litellm はネイティブ OpenAI + Anthropic SDK に置き換えられました — プロバイダー層全体が、litellm を介してルーティングするのではなく、上流の SDK と直接通信するように書き直されました。 Anthropic 向けの迅速なキャッシュ最適化、OpenAI o1 向けの適切な max_completion_tokens 処理、および Gemini の考えた署名の保存はすべて、そのために実現しました。午前 2 時に litellm トレースバックをデバッグしたことがあれば、これがなぜ重要なのか理解できるでしょう。 (#2448、#1109、#2468、#2550、#2453)
  • ストリーミングはエンドツーエンドに — プロバイダーからチャネル、そして CLI まで、ストリーミング出力はファーストクラスのパスとして流れるようになりました。 Feishu は CardKit ストリーミング サポートを獲得し、キューに入れられたストリーム デルタが結合されて API コールが削減され、チャネル マネージャーがストリーム境界を正しく処理します。これが、「ボットが入力している...」ということと、実際にボットが考えているのを見ていることとの違いです。 (#2365、#2545、#2497)
  • セキュリティ脆弱性がパッチされました - 認証検証の欠落による電子メール インジェクションとなりすましが修正されました。受信メールでは、Authentication-Results ヘッダーを通じて SPF/DKIM が検証されるようになり、デフォルトで verify_dkim と verify_spf が有効になります。電子メール本文からの LLM プロンプト挿入を防ぐために、電子メール コンテンツには [EMAIL-CONTEXT] のタグが付けられます。詳細については、アドバイザリを参照してください。 (GHSA-4gmr-2vc8-7qh3)
  • WeChat サポートがフル チャネルとして上陸 — WeChat (Weixin) は、HTTP ロング ポーリング、QR コード ログイン、プラグイン 1.0.3 互換性を備えてチャネル ファミリーに加わりました。これに加えて、Telegram、QQ、WhatsApp、Feishu はすべて、指数バックオフを備えた再試行メカニズムを含むクロスチャネルの機能強化を受けました。 (#2412、#2428、#2386、#2478)
  • プロバイダーの対象範囲は拡大し続けました — Mistral プロバイダーと OVMS プロバイダーが到着し、Step Fun (阶跃星辰) がエコシステムに加わり、カスタム プロバイダーのエラー レポートがより正確になりました。不透明な JSONDecodeError ではなく、生の API エラーが表示されました。 nanobot は、モデルがどこにいてもユーザーと出会い続けます。 (#2199、#2472、#2289、#2139)
  • エージェントはリソースに関してより賢くなりました — セッションごとの同時ディスパッチが可能になり、ネイティブのマルチモーダル感覚機能が追加され、トークン推定がすべてのメッセージ フィールドをカウントするようになり、メモリ統合により完了ヘッドルームが適切に確保されます。エージェント ループは、CancelledError も適切に処理し、サブエージェントの結果を正しいロールで記録します。 (#2393、#2304、#2344、#2378、#2239、#2104)
  • Feishu と Telegram は両方ともレベルアップ — Feishu はストリーミング カード、投稿メッセージのコード ブロック解析、マークダウン レンダリングとメディア タイプの修正を獲得しました。 Telegram は、HTTP(S) URL メディア サポート、プールの枯渇を防ぐための分離された接続プール、およびより静かなネットワーク エラー ログを取得しました。個々は小さくても、一緒にすると充実します。 (#2545、#2246、#1814、#1755、#1793、#2247、#2272)
  • CLI とオンボーディングがより機能的になりました — フル機能のオンボード ウィザードが登場し、--dir は複数のインスタンスを有効にし、/status はランタイム情報を表示し、-h はどこでも動作し、タイムゾーンが構成可能になりました。初めての体験に意図的なものを感じさせるような磨き。 (#2101、#1763、#1985、#2123、#2477、#1136、#2266)
  • 全体的に強化されたインフラストラクチャ — シェル タイムアウトでゾンビ プロセスが取得され、cron ジョブ ストアのスコープがワークスペースに限定され、MCP ツール スキーマが null 許容パラメータを正しく処理し、Docker ビルドに openssh-client が含まれ、テスト スイートがよりクリーンな構造に再編成されました。来月に提出するはずのバグレポートを防ぐような作業です。 (#2362、#2204、#2230、#2287、#1911、#2427、#2367)

コミュニティ

このリリースの 27 人の新しい貢献者を温かく歓迎します。 v0.1.4.post6 は、オープンソースで最も重要な作業が常に最も目立つとは限らないという信念によって形作られています。コアの依存関係を置き換える、ランタイムを分解する、セキュリティ ホールを塞ぐ、これらはどれも派手なデモにはなりませんが、これらすべてにより nanobot は昨日よりも明日より自信を持って構築できるプロジェクトになります。コード、修正、ドキュメント、アイデアを提供してくださった皆様に感謝します。基礎がしっかりしてきています。 フル Changelog: https://github.com/HKUDS/nanobot/compare/v0.1.4.post5...v0.1.4.post6
