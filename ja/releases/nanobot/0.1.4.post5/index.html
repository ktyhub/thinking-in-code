nanobot v0.1.4.post5

パッチ 公開日2026年3月16日 出典HKUDS/nanobot 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ナノボットv0.1.4.post5 🐈 nanobot v0.1.4.post5 が登場 — 57 人の PR がマージされ、29 人の新しいコントリビューターが加わり、リリース サイクルはスペクタクルではなく、より静かなものによって形作られています。最も重要な部分は慎重に改良されています。 これは、プロジェクトが日常的に使用する価値があると感じさせる種類のリリースです。エッジはより滑らかになり、故障モードはよりソフトになり、プラットフォームはより広くなりました。チャネル、プロバイダー、メモリ、MCP、CLI、インフラストラクチャ全体にわたって、nanobot は機能が向上しているだけでなく、信頼性も向上しており、実際に使用できるツールに近づいています。

ハイライト

  • 信頼性が中心的な役割を果たしました — このリリースの多くは、ナノボットをより適切に失敗させることに関するものです。エージェント ループがクラッシュする可能性が低くなり、MCP 接続のキャンセル処理が改善され、孤立したツールの結果が正しく保存され、非同期 CLI/サブエージェント出力がよりクリーンに動作するようになりました。 (#1999、#1953、#2075、#1930、#2039)
  • メモリがより実用的になりました — 非同期バックグラウンド統合が実現し、統合入力がより忠実に渡され、永続化の前にペイロードが検証され、save_memory がより一貫して適用されます。これは、魔法のようなものではなく、より信頼できる記憶への有意義な一歩です。 (#1961、#1962、#1868、#1810、#1909)
  • チャネル層は成熟し続けています — チャネル プラグイン アーキテクチャが到着し、チャネル検出が自動になり、組み込みのチャネル/構成境界がより明確になりました。この種の構造的な作業は重要です。これにより、システムを脆弱にすることなく成長が容易になります。 (#1982、#1888)
  • プロバイダー サポートは外部に拡大し続けています — Ollama サポートがローカル モデルに導入され、VolcEngine と BytePlus がエコシステムに加わり、openrouter/* モデルがサポートされ、Web 検索プロバイダーがフォールバック動作で構成できるようになりました。 nanobot は、ユーザーがすでにいる場所でユーザーと出会うことが増えています。 (#1863、#1608、#2026、#398)
  • 可観測性とツールが強化されました — Langsmith の統合により会話追跡が改善され、組み込みのスキル パッケージが修正され、よりスマートなファイルシステム/シェル ツールによりページネーション、フォールバック マッチング、および出力動作が改善されました。システムは検査しやすくなり、trustも容易になります。 (#1920、#1416、#1895)
  • Feishu は大幅に改良されました — 返信/引用のサポートが追加され、ツール呼び出しがコード ブロックでレンダリングできるようになり、グループ メンションの動作が改善され、Groq Whisper のオーディオ互換性が修正され、広範なマルチメディアの処理が大幅に改善されました。このサイクルの後、フェイシュのサポートは大幅に完全になったと感じます。 (#1963、#1966、#1768、#1741、#2034)
  • グループとメディア ワークフローで Telegram が大幅に改善されました — グループ応答動作が構成可能になり、メッセージへの返信コンテキストがテキストとメディア全体で機能し、メディア ファイル名の衝突バグが解消されました。これらは個別には細かい点ですが、これらを組み合わせることで会話がより自然に感じられます。 (#1389、#1900、#1796)
  • エンタープライズ チャネルとコラボレーション チャネルも改善されました — WeCom チャネルのサポートが開始され、Slack スレッドの動作が明確になり、QQ の従来のプレーンテキスト返信が復元され、DingTalk は音声認識テキスト検索とマルチメディアの両方の改善が行われました。 (#1327、#1784、#1941、#1859、#2034)
  • CLI と実行時の動作がより予測可能になりました — ゲートウェイ ポートのデフォルトは設定を尊重するようになり、再起動フローの移植性が向上し、Windows の互換性が注目を集め、ホーム展開パスやチルダベースのパスに関してシェル/ワークスペースのガードがより厳密になりました。これは、ユーザーが不足していることに初めて気づく種類の作業です。だからこそ、それが重要なのです。 (#1797、#1785、#1958、#1479、#1827、#1845)
  • 多くの鋭いエッジが消えました — 隠しファイルが誤って同期されることはなくなり、非ビジョン モデルは image_url を受信しなくなり、ハートビートと cron のノイズが減り、バージョン ID がログに表示されるようになりました。これらは派手な変更ではありませんが、nanobot がより落ち着いて、より慎重になり、より本番環境に対応できるようになります。 (#1856、#1901、#1973、#2058)

コミュニティ

このリリースでは、29 人の新しい貢献者を大歓迎します。 オープンソースは 2 つの方法で成長します。1 つは大胆な新しいアイデアによるもの、もう 1 つは荒削りな部分に気づいて滑らかにする忍耐強い作業によるものです。 v0.1.4.post5 には両方がたっぷりあります。機能、修正、リファクタリング、ドキュメント、インフラストラクチャの改善に貢献してくれたすべての人々に感謝します。nanobot は一度にではなく、多くの慎重な手によって一緒に前進することで強くなってきています。 フル Changelog: https://github.com/HKUDS/nanobot/compare/v0.1.4.post4...v0.1.4.post5

次は何ですか

今後も、nanobot をよりモジュール化されたプラグイン指向のエコシステムに向けて進めていきます。最初のステップとして、まずチャネル層で実験と反復を行うことを計画しています。チャネルをより拡張可能なアーキテクチャの実験場として使用してから、そのアプローチをプロジェクト全体にさらに拡張します。 また、より迅速なテスト、より早いフィードバック、そして新しいアイデアのより迅速な反復のために、nightly ブランチを引き続き使用します。その未来の形成に貢献することに興味がある場合は、貢献を大歓迎します。貢献ワークフローとガイドラインは CONTRIBUTING.md にあります。 そして、もう 1 つの小さな注意事項: v0.1.4.post5 は、おそらく 0.1.4 ラインの最後のリリースになるでしょう。多くの磨きと苦労して得た安定性でこのサイクルを締めくくり、次に来るもののための余地も作ります。 次のメインバージョンはすでに具体化されており、待つ価値があると考えています。 😉
