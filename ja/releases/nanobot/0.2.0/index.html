nanobot v0.2.0

マイナー 公開日2026年5月16日 出典HKUDS/nanobot 英語原文

#ナノボットv0.2.0 🐈 nanobot v0.2.0 が登場 🎉 — 105 人の PR が統合され、20 人の新しい貢献者が加わりました。エージェントは目標を保持することを学びました。 見出しは/goalです。 long_task を使用してスレッドを持続目標としてマークすると、アクティブな目標は、complete_goal を呼び出すまで、圧縮の存続、長いツールチェーンの存続、モデル自体の忘却の存続など、毎ターンランタイムコンテキストに固定されたままになります。目標がアクティブな間、実測タイムアウトは自動的に延長されます。ストリーミング リクエストはハード ウォールではなくアイドル タイムアウトにフォールバックするため、まだ考えているモデルが途中で強制終了されることはありません。 2 番目のストーリーは WebUI の成長です。ソースのみのプレビューとして数回のリリースを経て、現在は ホイール内 — pip install nanobot-ai として出荷されており、それを手に入れることができます。設定と BYOK は完全に再設計され、スラッシュ パレットはローカライズされ、LAN アクセスはトークンによってゲートされ、推論はチャットにライブ ストリームされ、最新の画像生成ツールは会話を離れることなく「draw me X」をインライン プレビューに変換します。 3 階はエンジンルームです。エージェント ループは実際のリファクタリングを受けました。クリーンな埋め込みのための AgentLoop.from_config()、機能ステート マシンとして書き直された _process_message、KV キャッシュの安定性のためにシステム プロンプトに移動されたアーカイブされたサマリー、自己記述型プラグイン アーキテクチャに変換されたツール、クリーンな代替品を優先して ask_user と GlobTool が廃止されました。 5 つの新しいプロバイダー (AWS Bedrock Converse、NVIDIA NIM、LongCat、Atomic Chat、MiMo) がセーフティ ネットとして fallback_models とともにラインナップに加わり、単一の不安定なエンドポイントがダウンすることはありません。さらに 4 つの [security] 修正 (SSRF、メディア パス制限、ワークスペース境界の緩和)、チャット ネイティブ ペアリングにより、最終的に DM の承認が設定ファイルではなくチャットで行われるようになりました。

ハイライト

  • /goal および長時間実行タスク — なぜ の記憶を持つエージェント — 新しい long_task ツールは、/goal および complete_goal と組み合わせて、スレッドを継続的な目標としてマークします。アクティブな目標は毎ターン ランタイム コンテキストにミラーリングされるため、圧縮後もエージェントは固定されたままになり、WebUI によってチャット ヘッダーに目標が表示されます。また、ゴールがアクティブである間は LLM ウォール タイムアウトが自動的に延長されるため、長い推論パスが思考の途中で強制終了されることはありません。コア エージェントとサブエージェントは両方とも、より長い予算を優先します。ストリーミング リクエストはハード ウォール クロックではなくアイドル タイムアウトにフォールバックするため、まだトークンを発行しているモデルが途中で切断されることはありません。 (#3788、#3855)
  • 画像生成、エンドツーエンド — 新しい画像生成ツールと WebUI 画像モードにより、チャットを離れることなくプロンプトから画像に進むことができます。生成されたイメージは、丸みを帯びたプレビューでインラインでレンダリングされます。リプレイ ウィンドウと重複除去パスが強化され、長いセッションにわたってイメージが二重配信されなくなりました。また、統合パスは履歴を非表示にするときにリプレイ ウィンドウを尊重するようになりました。 (#3695、#3687)
  • WebUI はホイールに同梱されており、さらに 1 年分の磨きがかかっています — pip install nanobot-ai には WebUI がバンドルされています。WebSocket チャネルを有効にし、nanobot gateway を実行し、ブラウザを開きます。 cd webui && bun run buildは必要ありません。 「プレビュー」ラベルの下で数回リリースされた後、WebUI はパッケージ化されたサーフェスになりました。その内部: 再設計された設定と BYOK フロー (BYOK Web 検索を含む)、ローカライズされたスラッシュ パレット、スラッシュ コマンドと設定のリロード間で同期を保つモデル プリセット バッジ、ライブでレンダリングされるストリーミング推論、画像プレビュー、tokenIssueSecret によってゲートされる LAN アクセス、ロード時のデフォルトの新規チャット、設定が戻ったときのスクロール保存、非セキュア コンテキスト LAN の使用のための crypto.randomUUID シム、カットするための Eager Markdown プリロードの削除初回塗装費用。 (#3653、#3661、#3703、#3709、#3656、#3658、#3733、#3759、#3782)
  • 5 つの新しいプロバイダーとフォールバック セーフティ ネット — ネイティブ AWS Bedrock Converse がファーストクラスのプロバイダー (#3574) として登場し、Bedrock ツールの構成を履歴全体にわたって保持するフォローアップ (#3758) が行われます。 NVIDIA NIM (#3707)、OpenAI 互換ルーティング経由の LongCat (#3114)、ローカル OpenAI 互換ターゲットとしての Atomic Chat (#3750)、および適切な思考制御配線を備えた MiMo (#3734、#3851) がラインナップを完成させます。 fallback_models では、より幅広いスタックに加えて、プライマリに障害が発生した場合に引き継ぐセカンダリ モデル (#3756)、DeepSeek 推論履歴がドロップされずにバックフィルされる (#3616、#3560)、Codex プロンプト キャッシュ キーが安定する (#3793)、および長いリクエスト エラーが発生した場合に Anthropic が自動的にストリーミングにフォールバックする (#3579) ことをリストできます。
  • モデル プリセットとランタイム切り替え - ModelPresetConfig を使用すると、構成内でモデルとプロバイダーのバンドルに名前を付け、実行時に /model (または WebUI バッジ) を介してバンドル間で切り替えることができます。プリセットはスラッシュ コマンド、設定のリロード、設定の変更間で同期するため、モデルのバッジは次のターンにヒットするものと常に一致します。 (#3714)
  • コア リファクタリング — よりクリーンなエージェント ループ、より小さなサーフェス — AgentLoop.from_config() はループ アセンブリを一元化し、エンベッダーがプライベートな内部にアクセスするのを防ぎます (#3708)。 _process_message は、ネストされた分岐の代わりに明示的な遷移を備えた機能的なステート マシンとして書き直されました (#3715)。圧縮後も KV キャッシュを安定に保つために、アーカイブされた会話の概要がシステム プロンプトに移動されました (#3711)。ツールは自己記述型のプラグイン アーキテクチャになりました (#3729)。 ask_user は構造化された message ツールの選択肢 (#3757) を優先して削除され、GlobTool は read_file グロブ サポート (#3841) を優先して廃止されました。 Vulture およびカバレッジで検証されたデッド コードが削除されました (#3755、#3719)。ロギングではトレースバックが保存され、チャネル コンテキストが保持されるようになりました (#3651、#3678)。 Ruff F ルールは CI で完全に適用され (#3672)、エージェント テスト スイートは拡張および再構築されました (#3766)。新しい CLAUDE.md および .agent/ ガイドは、AI コントリビューターに安定したオンランプを提供します (#3534、#3860)。
  • ペアリング、DM 承認、セキュリティ強化 — チャットネイティブ ペアリング (#3774) を使用すると、設定を編集する代わりにチャット内から DM を承認できます。安全性の面では、SSRF が DingTalk 送信メディアでブロックされ (#3569)、Feishu がダウンロードしたメディアのファイル名が安全なパスに制限され (#3789)、ローカル メディアの添付ファイルがメッセージ ツール用に制限され (#3842)、SSRF ガードの回復が緩和され、一時的なミスが後続のターンを妨げないように (#3635)、ワークスペースの境界違反にはループがクラッシュする代わりに再試行が抑制されたソフト警告が表示されます。 (#3614)。 Telegram は、エラー応答を漏らす代わりに、不正な送信者を黙って無視します (#3629)。
  • メモリ、ドリーム、およびセッションの耐久性 - Cron jobs.json は破損ストア検出 (#3606) によりアトミック書き込みを実現しました。ドリーム カーソルは完了したバッチでのみ進み (#3631)、再開時にメモリ状態を正しく復元します (#3660)。リプレイ ウィンドウの非表示履歴が適切に統合されるようになりました (#3687)。ワークスペースとツールの状態の変更は、再起動後もエンドツーエンドでより確実に存続します。
  • チャネルとプラットフォームの修正 - Feishu グループ スレッドは返信チェーンとトピック分離を尊重します (#3547、#3704、#3747、#3775)、Matrix は起動前イベントをスキップし、回復不能な認証で同期ループを停止します (#3575、#3578)、WhatsApp 音声メッセージはきれいにダウンロードされます (#3607)、Wecom は実際のファイル名を保持します(#3751)、Telegram は不正な送信者を抑制し (#3629)、Weixin は送信失敗時にメッセージを通知してメッセージがドロップされないようにします (#3659)。 Windows の場合: シェル抽出での UNC パスのサポート (#3764)。 CLI: メッセージ バスの前にサロゲート コード ポイントがサニタイズされ (#3697)、再試行待機メッセージが対話型出力を文字化けしなくなり (#3705、#3609)、nanobot provider logout が適切なコマンドとして実行されます (#3612)。
  • あなたが感じるであろう小さなこと — 構成可能な bot_name / bot_icon (#3730)、構成可能な toolHintMaxLength (#3641)、OpenAI 互換の API で復元された実際の SSE ストリーミング (#3677)、一時的な障害時のウィスパー トランスクリプションの再試行 (#3646)、CPU スピンを停止するためのシーケンシャル MCP サーバー接続(#3640)、接続前の MCP HTTP プローブ (#3740)、レート制限下での Brave 検索バックオフ (#3840)、ユーザー認識応答のためのランタイム コンテキストの sender_id (#3549)、キャッシュの安定性のためにユーザー コンテンツの後に追加されるランタイム コンテキスト (#3844)、origin_message_id アウトバウンド重複排除 (#3561)、および Python SDK RunResult は最終的に tools_used と messages (#3620) を公開します。

コミュニティ

v0.2.0 を出荷してくださった皆様に心からの感謝を申し上げます。105 人の PR、33 人の貢献者、そして 20 人の初めての貢献者を大歓迎します。すべてのレビュー、パッチ、バグレポートが役に立ちました。このリリースは共同の勝利です。 🎉
