#ナノボットv0.3.0

🐈 nanobot v0.3.0 はこちらです: 260 人の PR が統合され、38 人の新しい貢献者。エージェントは代理権を獲得した。

このリリースを体験する最も早い方法は、次の 1 つのコマンドです。

nanobot webui

ローカル WebUI を準備し、ゲートウェイを起動し、ブラウザー ワークベンチを開きます。新規インストールでは、ガイド付きセットアップを使用すると、JSON ファイルで開始することなく、プロバイダーを選択してアクセスを構成できます。公開されたパッケージにはすでに WebUI が含まれているため、別個のフロントエンド ビルドはありません。

製品ストーリーは、ナノボットへの玄関口のように感じられる WebUI です。チャットはトピックとして読み取られます。ドキュメント、引用されたフォローアップ、マルチモーダル ツールの結果、ファイルの差分、コード プレビュー、モデルのフォールバックが会話に表示されます。モデル プリセットはコンポーザーから切り替えることができ、ネイティブ デスクトップ ホストはシステム フォルダー ピッカーを開くことができ、設定は狭い画面やダーク モードでより適切に機能し、インターフェースにはブラジル系ポルトガル語に加えて大幅に改善された繁体字中国語が含まれるようになりました。

その経験の下には、境界を持つエージェンシーがあります。 nanobot は、インライン サブエージェントに問い合わせ、検証を通じて明示的に許可された作業を実行し、より明確なランタイム コンテキストを通じてターン状態をルーティングし、セッションごとにモデル プリセットを切り替えることができます。長時間実行される動作は意図的です。/goal はタスクを継続的に実行することを選択しますが、通常の会話は通常の会話のままです。

基盤は 実際のデプロイメント用に構築されたランタイムです。プロセスを中断することなく構成を再ロードでき、チャネルのパッケージ境界がより明確になり、ゲートウェイの再起動とシャットダウンのパスがより堅牢になり、Docker とレンダーの展開の再現が容易になります。プロバイダー スコープのプロキシ、OpenCode、Kimicoding、ホストされた X Search、Parallel Search、Serper、Mattermost、およびネイティブ Neonize WhatsApp チャネルを備えた Grok OAuth により、nanobot が実行できる場所と到達できる範囲が広がります。

ハイライト

  • ワークベンチへの 1 つのコマンド - nanobot webui は、ローカル チャネルを準備し、ゲートウェイを起動し、ブラウザを開き、初めてのユーザーをガイド付きセットアップに導きます。
  • 強力なブラウザ ワークベンチ - トピック スタイルのチャット、コンポーザー モデルの切り替え、引用されたフォローアップ、ドキュメントの添付ファイル、ネイティブ フォルダーの選択、応答性の高い設定、およびより明確なフォールバック状態。
  • コアのスプロールを伴わないエージェントの調整 - インライン サブエージェントはアクティブなタスク内で参照でき、承認された作業は検証を通じて継続でき、型指定されたランタイム コンテキストはプロバイダー所有の状態をアドホック ループ ロジックの外に保ちます。
  • 明示的な長期実行目標 - 継続的な実行は、より明確な許可、キャンセル、タイムアウト、ハートビート、およびローカル トリガーの動作により、/goal の背後でゲートされます。
  • 検査できるファイルとツールのアクティビティ - 構文が強調表示されたプレビュー、ライブ ファイル編集の差分、より優れたコード コピー動作、構造化されたツール エラー、より豊富な MCP アーティファクト、および保持されたマルチモーダル ツール出力。
  • より運用性の高いランタイム - ライブ構成のリロード、制限されたセッションと実行状態、より安全な再起動/シャットダウン、よりクリーンなキャンセル所有権、より信頼性の高いスケジュールされた作業、およびより高速な CI。
  • より広範なプロバイダーと検索 - OpenCode Zen/Go、Kimicoding、Grok OAuth、プロバイダー スコープのプロキシ、Copilot Enterprise オーバーライド、Parallel Search、Serper、および安定した認証フォールバック。
  • 保守可能な拡張機能としてのチャネル - ネイティブ Neonize WhatsApp、Mattermost、Feishu/Telegram/Discord/Matrix/QQ の動作の改善、オプションのチャネル依存関係、およびより明確なセットアップ フロー。
  • エッジでセキュリティが強化 - 連鎖コマンド許可リストのバイパスがブロックされ、SSRF が検証済みの DNS をピン留めし、資格情報が MCP URL から編集され、リモート API バインドには認証が必要で、添付ファイルの受信は制限されます。
  • ドキュメントと配信が追いつきました - ワークフロー指向のドキュメント、自動化ガイド、1 つの click レンダー展開、より強力な Docker コントロール、コミュニティが管理するプロジェクト言語、および更新された SVG ID。

アップグレードに関する注意事項

  • WhatsApp は、古い Node.js/Baileys ブリッジの代わりに Neonize を使用するようになりました。 bridgeUrl と bridgeToken を削除し、nanobot plugins enable whatsapp を実行し、アカウントを nanobot channels login whatsapp に再度リンクします。古いブリッジ認証データは再利用されません。 allowFrom エントリでは、先頭に + を付けない送信者 ID を使用する必要があります。
  • 継続的な目標が明示的になりました。 タスクが継続ターンにわたって動作し続ける必要がある場合は、/goal を使用します。通常のチャットは、長期にわたる目標の動作を暗黙的に継承しなくなりました。
  • リモート公開には認証が必要です。 ループバックを超えて API または WebUI ゲートウェイをバインドする構成では、対応する API または Web トークンを提供する必要があります。 Localhost のセットアップでは、ガイド付きの有効期間の短いトークン フローが引き続き使用されます。

コミュニティ

v0.3.0 を形作ってくれた皆さんに感謝します。260 のマージ PR、38 人の初貢献者、そしてエージェント コア、WebUI、プロバイダー、チャネル、セキュリティ、ドキュメント、展開にわたる 1 か月にわたる慎重なレビューに感謝します。政府機関のリリースは、ナノボットを制限なく動作させることではありません。それは、小規模で検査可能なエージェントに、意図的に任せた作業の多くを完了させるための調整、証拠、運用規律を与えることです。
