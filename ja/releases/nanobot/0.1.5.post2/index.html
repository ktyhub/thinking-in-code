nanobot v0.1.5.post2

パッチ 公開日2026年4月21日 出典HKUDS/nanobot 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ナノボットv0.1.5.post2 🐈 nanobot v0.1.5.post2 が登場 🎉 — 67 人の PR が統合され、12 人の新しい貢献者が加わりました。エージェントの世界はより大きく、より安定しました。 v0.1.5.post1 がエージェント自身の管理方法を学ぶことに関するものであるとすれば、v0.1.5.post2 はリーチと洗練に関するものです。 Windows と Python 3.14 がサポート対象マトリクスに加わりました。 read_file ツールは、DOCX、XLSX、PPTX を理解できるようになりました。 Microsoft Teams がチャネルとして登場しました。 OpenAI対応APIがSSE経由でストリーミングを開始しました。そして、そのすべての下で、cron、メモリ、再試行、セッション ファイル、プロバイダーの不具合にわたる約 50 の小さな修正が、「動作する」を「安定している」に変え続けました。専用のブラウザ UI もリポジトリ内で形になり始めました (現時点ではソース プレビュー)。

ハイライト

  • Windows + Python 3.14 — ファーストクラスのサポート — Windows ランナーと Python 3.14 をカバーする完全な CI マトリックスがリリースされ、インストール マーカーとこれらのプラットフォームが露呈する問題に対するランタイム修正も含まれています。 「Windows がうまく動作しなかった」という理由で WSL 上で nanobot を実行している場合は、停止しても構いません。 (#3194)
  • Office ドキュメント、ネイティブに読み取り可能 - read_file ツールは、DOCX、XLSX、および PPTX からテキストを抽出するようになりました - テーブルとグループ化された図形が含まれ、ワークブック ハンドルは安全に閉じられます。以前の PDF サポートと組み合わせると、エージェントはコンバータを通過せずに、同僚から電子メールで送信されたあらゆる形式を開くことができます。 (#3336、#3269、#3353)
  • OpenAI 互換 API — SSE ストリーミング — /v1/chat/completions は、stream=true のときに SSE チャンクを発行し、既存の on_stream / on_stream_end コールバックを接続します。 OpenAI API 用に構築された client (LangChain、LlamaIndex、独自のフロントエンド) は、応答全体を待つ代わりに、nanobot からライブ デルタを取得します。また、エンドポイントは、バックエンドの障害後に成功マーカーを付けてストリームを終了することを停止したため、エラーがそのまま表面化します。 (#3222、#3262)
  • Microsoft Teams、MiniMax Thinking、LM Studio、MyTool — Microsoft Teams がチャネルの名簿に加わりました。 MiniMax には、専用の Anthropic スタイルの思考エンドポイントと、reasoning_effort → reasoning_split マッピング修正が追加されました。 LM Studio は、キーを予​​期しないローカル サーバーに対して、null 許容 API キーを介してサポートされるようになりました。新しい MyTool を使用すると、エージェントは自身の実行時設定をイントロスペクトでき、check 出力内の機密性の高いネストされた設定フィールドを非表示にするため、自己検査によって秘密が漏洩することはありません。 (#3197、#3160、#3363、#3186、#3177、#3261)
  • 信頼性 — リリースの地味な部分 — セッション ファイルは破損したファイルの修復を伴うアトミック書き込みを使用するようになったため、不適切なシャットダウンによって履歴が消費されることはなくなりました。メモリ カーソルの回復は、整数以外の破損を処理します。自動圧縮は、アクティブなタスクを含むセッションをスキップし、統合パス全体でサマリー注入を統合します。プロバイダーは、応答 API フォールバック用のサーキット ブレーカーを取得し、ZhiPu 1302 レート制限を認識します。 Cron は中間進捗状況の漏洩を停止し、そのツール スキーマは OpenAI Codex/Responses と連携し、再試行ハートビートがユーザー チャネルに流出することはなくなりました。サブエージェントのフォローアップはセッション履歴に残ります。そのうちの半分は決して気付かないでしょう - それがまさに重要なのです。 (#3312、#3340、#3081、#3304、#3302、#3356、#3320、#3295、#3229、#3242)
  • チャネル — より静かでシャープになった — Telegram は、長い返信のためのミッドストリーム分割と、最新の LLM 出力のためのマークダウン レンダリングの向上を実現しました。 Discord はボット間のメッセージを自己ループとして扱うことをやめ、チャネルベースの許可リストを追加しました。電子メールは、SPF/DKIM で拒否されたメッセージを重複排除してログスパムを阻止し、自己送信メールボックス メッセージを無視します。 WeCom は、混合受信メッセージを正しく解析します。それぞれが小さい。これらを組み合わせると、「なぜ私のボットがそんなことをしたのか」という瞬間が減ります。 (#3329、#3355、#3280、#3171、#3325、#3228、#3161)
  • WebUI — 早期プレビュー、ソースのみ — WebSocket チャット フロー、i18n ロケール スイッチャー、CJK サポートを備えた Apple 風のタイポグラフィ、ライブ ダークモード コードブロック テーマを備えた専用の webui/ がリポジトリに追加されました。基礎となる WebSocket チャネルは、単一の接続上で複数の chat_id を多重化することも学習しました。 注意: これはソース プレビューのみです。WebUI は公開されたホイールには意図的にまだバンドルされていません。 試してみたい場合は、リポジトリのクローンを作成し、webui/ から実行してください。 UX が安定したら、パッケージ版のリリースが続く予定です。 (#3310、#3272、#3314、#3306)

コミュニティ

v0.1.5.post2 は、基礎が完了し、作業を完了し始めるときのリリースの様子です。 @JiajunBernoulli による Windows CI マトリックス。 @aiguozhi123456 からのネイティブ Office ドキュメントの抽出。同じ作成者によるセッション アトミック書き込みにより、実際のデータ損失のエッジ ケースが検出されます。 Telegram のミッドストリーム分割により、長い返信が実際に読みやすくなります。 12 人の新しい寄稿者と、多くの戻ってきた寄稿者が、みんなのウィッシュ リストにあったものを静かに手に入れました。エージェントは Windows 上で実行されます。あなたの文書を読み取ってくれます。電源が点滅しても履歴を保持します。 webui/ では、覗き見したい人のために UI が具体化されています。これは、リリース後の作業を行うリリース後の作業です。その後、いくつかの作業が行われます。
