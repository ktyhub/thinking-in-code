nanobot v0.1.5.post3

パッチ 公開日2026年4月29日 出典HKUDS/nanobot 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ナノボットv0.1.5.post3 🐈 nanobot v0.1.5.post3 が登場 🎉 — 57 人の PR が統合され、12 人の新しい貢献者が加わりました。エージェントはスレッドで話すことを学びました。 v0.1.5.post2 がリーチと洗練を目的とした場合、v0.1.5.post3 はプラットフォームの第一級市民となる会話を目的としています。 Feishu グループのトピックは孤立したセッションを取得します。 Discord スレッドは親ホワイトリストを継承し、独自のコンテキストを保持します。 Telegram はインライン キーボードの選択肢をレンダリングできます。 MSTeam は古い会話参照を削除するので、送信メッセージがサイレントに失敗するのを防ぎます。また、すべてのチャンネルにわたって、sendProgress と sendToolHints をチャンネルごとにオーバーライドできるようになりました。ノイズの多いチャンネルは静かにし、冗長なチャンネルはそのままにします。その下では、DeepSeek-V4 がエンドツーエンドでサポートされています。思考モードと従来のセッションの互換性が一緒に出荷され、不完全な推論履歴と文字列以外のメッセージ コンテンツに対するフォローアップ修正が含まれるため、長いスレッドが安定した状態を維持できます。新しい ask_user ツールを使用すると、エージェントが一時停止し、タスクの途中で選択するよう求められます。 Olostep と Hugging Face がプロバイダーのラインナップに加わり、一対のタイムアウト環境変数 (NANOBOT_LLM_TIMEOUT_S と NANOBOT_OPENAI_COMPAT_TIMEOUT_S) により、ハングしたリクエストがセッションを人質に取られることがなくなります。 WebUI は画像のアップロード、ビデオのレンダリング、ユーザーの選択、モデルの設定など進化を続けましたが、依然としてソース プレビューのみであり、ホイールにはバンドルされていません。

ハイライト

  • あらゆる場所のスレッド - Feishu、Discord、Slack、MSTeams - このリリースでは、各チャネルが成長しました。 Feishu グループのトピックはセッションを分離するようになり、あるトピック内のメッセージが別のトピックに漏洩することはありません。ストリーミング カードとツールのヒントは元のトピックに従います。 Discord スレッドは親チャンネルの allowChannels を継承し、セッション分離を取得します。これは、スラッシュ コマンドが許可リストを尊重することも意味します。 Slack は、プロアクティブな返信でスレッドのコンテキストを失わなくなりました。 MSTeams の会話参照には、TTL ベースのプルーニング (refTtlDays)、Web チャット参照の自動クリーンアップ、およびアクティブな参照を維持するためのタッチ間隔が追加されました。テーマは一貫しています。会話はチャネル全体ではなく、スレッドに属します。 (#3449、#3397、#3440、#3462、#3475、#3447、#3487)
  • チャネルごとの進行およびインタラクションの制御 - sendProgress および sendToolHints は、グローバルなオンまたはオフのスイッチでした。これらを個別のチャネル構成内に配置して、グローバルなデフォルトをオーバーライドできるようになりました。WebSocket は冗長なままですが、Telegram は静かに保ちます。エージェントは、新しい ask_user ツールを使用して、タスク中にユーザーに構造化された質問をすることも学習しました。WebUI では、これらはボタンとして表示され、他のチャネルではテキストに戻ります。 Telegram は、message ツール ボタンの選択肢をレンダリングするためのインライン キーボード (inline_keyboards: true) を入手しました。 /history [n] コマンドを使用すると、スクロールせずに最近のメッセージを確認できます。 (#3487、#2791、#3398、#3454、#3466)
  • DeepSeek-V4 とより広範なプロバイダー スタック - このリリースでは、DeepSeek-V4 が第一級のターゲットになります。思考モードとレガシー セッションの互換性が一度に実装されるため (#3420)、古い会話を放棄することなくエージェントに V4 を向けることができます。現実世界のトランスクリプトにより、専用のフォローアップが行われた 2 つのギャップ、つまり、切り捨てられたまたは不完全な推論履歴 (#3453) と、異種 (文字列以外) のメッセージ コンテンツ (#3458) が明らかになりました。そのため、ツールを多用するセッションが実行中に中断されることはありません。それに加えて、Hugging Face Inference プロバイダーがファーストクラスのプロバイダーとして登場し (#3496)、Olostep が Web 検索に加わり (#3505)、OpenAI 互換エンドポイントが vLLM ガイド付きデコードとそのフレンド用に extraBody を獲得し (#3491)、タイムアウト ペア NANOBOT_LLM_TIMEOUT_S / NANOBOT_OPENAI_COMPAT_TIMEOUT_S が外側のターン制限を内側の HTTP 境界から分割しました (#3428、#3478)。 GitHub Copilot は GPT-5 および o シリーズ モデルを正しくルーティングします (#3380)。 Gemini ルーティングは reasoning_effort="none" と Gemma (#3515) を選択します。
  • メモリとセッションの強化 — consolidationRatio (0.1 ～ 0.95) を使用すると、トークン トリガーによる統合がコンテキストをどの程度積極的に圧縮するかを調整できます。 maxMessages (デフォルトは 120) は、永続性を維持せずに再生ウィンドウに上限を設けます。 History.jsonl は、fsync とディレクトリ同期によるアトミック書き込みを獲得し、予期せぬシャットダウン時の最後のデータ損失ウィンドウを閉じました。 raw_archive の肥大化したパスといくつかのスタック統合エッジが封鎖されました。正常なシャットダウン時にセッションが fsync になるようになりました。その結果、メモリの調整可能性と耐久性が向上します。 (#3285、#3482、#3508、#3369、#3412、#3415、#3459)
  • macOS LaunchAgent と展開 - 新しい docs/deployment.md セクションでは、macOS LaunchAgent として nanobot gateway を展開する手順を説明します。plist、launchctl bootstrap/enable/kickstart、ログ パス、および手動ゲートウェイを停止し忘れた場合に避けられないポート競合の問題について説明します。ログイン時に端末を開いたままにせずにエージェントをオンラインにしたい場合に便利です。 (#3441)
  • セキュリティと信頼性の修正 — Windows 以外のプラットフォームでの path_append を介したシェル インジェクション ベクターが閉じられました。ワークスペース ディレクトリの違反が発生した場合、警告がログに記録されるのではなく、エージェント ループが停止されるようになりました。 resolve_config_env_vars は、除外されたフィールドの削除を停止しました。 tool_result コンテンツ内の Anthropic image_url ブロッ​​クは正しく変換されます。 MCP 機能名は、モデル API との互換性のためにサニタイズされています。 Windows MCP stdio ランチャーは WinError 193 を回避します。構造化されたツール イベント ペイロードにより、チャネルにより豊富な進行状況データが提供されます。ドキュメント パーサーは遅延インポートを行い、コールド スタート時間を短縮します。プロバイダー、チャネル、エージェント ループにわたる 20 あまりの小さな修正がリリースを締めくくります。 (#3366、#3493、#3383、#3387、#3470、#3379、#3399、#3423)

コミュニティ

v0.1.5.post3 を出荷してくださった皆様に心からの感謝を申し上げます。57 人の PR、27 人の寄稿者、そして 12 人の初めての寄稿者を大歓迎します。すべてのレビュー、パッチ、バグレポートが役に立ちました。このリリースは共同の勝利です。 🎉
