#ナノボットv0.3.5

🐈 nanobot v0.3.5 は端末にワークベンチをもたらし、ブラウザ、端末、チャット アプリ間で会話を継続しやすくします。

見出しは、エージェントが 1 人になり、働く場所が増えるです。ネイティブ端末 client の場合は nanobot を実行し、ブラウザの場合は nanobot webui を実行します。どちらも同じゲートウェイと保存された WebSocket 会話を使用します。ターミナル セッションは、別のエージェント ランタイムを構築しなくても、再開、フォーク、検査、および切り離しが可能です。

ブラウザ ワークベンチは、グループ化された会話ペイン、一時チャット、永続的なサイドバーの順序付け、セッション メンション、スキル マーケットプレイス、ポータブル エージェント プラグイン、およびリモート MCP サーバー用のブラウザ OAuth など、実際のマルチタスクを中心に成長してきました。オートメーションには、タスク ビューとカレンダー ビュー、より明確なスケジュール コントロール、および実行ごとの応答が追加されました。モバイルの構成、設定、コンテキスト チャート、アプリのロゴ、ブランドの言及は、さらに集中的に磨きをかけられました。

もう 1 つの話は、検査できる継続性です。コンテキストの使用状況と圧縮が表示され、中断された作業の回復制御がより明確になり、セッション履歴はページネーション、再接続、アップグレードにわたってより耐久性が高くなります。このリリースでは、添付ファイル、プロセス、ワークスペース、電子メール認証の境界も強化されています。既存のインストールを置き換える前に、アップグレードに関する注意事項をお読みください。

ハイライト

  • ネイティブ ターミナル ワークベンチ - nanobot から開始し、セッションを切り替え、サポートされている clipboard イメージを貼り付け、アプリとスキルのリファレンスを完了し、コンテキストとファイルの差分を検査し、フォローアップをキューに入れ、/detach を使用してゲートウェイを実行したままにします。
  • ブラウザーでの会話を並べて表示 - サイズ変更可能なグループに最大 4 つのトピックを配置し、サイドバーの順序を維持し、保存されたセッションをメンションにドラッグし、トピックを永続化したくない場合は一時的なチャットを使用します。
  • 管理が容易になった自動化 — タスク ビューとカレンダー ビューを切り替え、実行応答を検査し、より明確なコントロールでスケジュールを調整します。ジョブを編集すると、保留中の実行が保持されます。削除してもナビゲーションがブロックされたままになることはなくなりました。
  • 可視化されたコンテキストと安定した長時間セッション — ラウンドごとのトークン/キャッシュ チャート、コンテキスト圧縮の進行状況、ページ化された履歴検索、累積的な概要、および実際のモデル コンテキストを対象としたファイル読み取り重複排除。
  • より明確なアイデンティティを持つアプリとスキル — SkillHub の検出、ポータブル エージェント プラグイン、リモート MCP OAuth とトークンの更新、目に見える接続エラー、チャット内の一貫したアプリのロゴとブランド名。
  • より優れた小画面エクスペリエンス — PWA サポートによるホーム画面のインストール、幅の狭いコンポーザ コントロール、ドラッグ可能なコンテキスト シート、タッチ フレンドリーなチャートの詳細、開く方向と一致する設定ナビゲーション。
  • 幅広いモデルと検索の選択肢 — DeepSeek Responses と V4 ビジョンのサポート、Eden AI と OrcaRouter ゲートウェイ、AnySearch、オンライン OAuth モデル カタログ、およびより回復力の高いプロバイダー フォールバックと応答履歴処理。
  • より信頼性の高いチャネルとランタイム境界 — 豊富な Telegram ストリーミング、改善された Feishu オンボーディング、より安全な QQ 添付ファイル、trusted 電子メール認証結果、オプションの macOS シートベルト分離、およびサブプロセス環境での認証情報の漏洩の減少。
  • 埋め込みと操作 - SDK ホスト統合フック、明示的なデスクトップ接続、ゲートウェイ準備状況レポート、およびチェック済みのバージョン一致端末配布。

アップグレードに関する注意事項

  • 構成、ワークスペース、セッションストレージをバックアップします。最初に古いプロセスを停止してください。 セッション JSONL ファイルは、構成ディレクトリの sessions/<workspace-id>/ ツリーの下に存在します。最初のアップグレード開始では、コピーの検証後に既存のワークスペース セッションが移行されます。古いバージョンと新しいバージョンで同じワークスペースを同時に書き込まないでください。ダウングレードする前に、nanobot を停止し、nanobot sessions restore-workspace --config <config.json> --workspace <workspace> を使用します。コマンドは、別の既存ファイルの上書きを拒否します。 セッション ストレージとロールバック ガイド を参照してください。
  • 電子メール検証には明示的な受信者 trust アンカーが必要です。 verifySpf または verifyDkim が有効な場合は、受信メール サービスによって確認された正確な ID を使用して channels.email.trustedAuthservIds を構成します。このサービスは、その ID を主張する偽造ヘッダーを削除し、1 つの統合された認証結果ヘッダーを提供する必要があります。このフィールドのない既存の検証済み電子メール設定は開始されません。設定するまで電子メールを無効にしておきます。回避策として検証を無効にしないでください。 メールアップグレードガイドに従ってください。
  • プレーン nanobot はネイティブ ターミナル UI を開きます。 Python プロンプトには nanobot --classic を、ワンショット使用には nanobot -m "Hello!" を使用します。プラットフォーム ホイールには WebUI と対応する TUI の両方が含まれているため、最初の TUI の起動には Bun も GitHub のダウンロードも必要ありません。サポートされているホイールは、macOS 13 以降 arm64/x64、glibc 2.17+ Linux arm64/x64、および Windows x64 をターゲットとしています。他のプラットフォームおよびソース配布ビルドでは、クラシック プロンプトまたは WebUI を使用できます。編集可能なソース開発には Bun を使用します。
  • 最後に接続された client が、オンデマンド ゲートウェイの有効期間を所有します。 最後の対話型 WebUI/TUI ランチャーを閉じると、そのゲートウェイが停止します。端末で /detach を使用するか、client なしで続行する必要がある作業には nanobot gateway --background を使用します。
  • リモート プロジェクトの選択では、nanobot ホスト上のパスが使用されます。 制限付きアクセスが必要です。ブラウザ デバイスからディレクトリは選択されず、リモート client はフル アクセスを有効にすることができません。
  • ゲートウェイの正常性応答の方が有益です。 有効な WebSocket チャネルが実行されていない場合、/health は HTTP 503 を返すことがあります。モデル、MCP、またはその他のチャネル接続を保証するものではありません。以前はすべてのライブプロセスが 200 を返すと想定していた更新監視。
  • 同時実行性とタイムアウト制限を再確認してください。 NANOBOT_MAX_CONCURRENT_REQUESTS は、正の整数に設定されない限り無制限です。デプロイメントに明示的な上限が必要な場合は、明示的な上限を設定します。サブエージェントの同時実行数はデフォルトで 4 に設定されており、超過した作業は容量を待機します。古い agents.defaults.failOnToolError フィールドと NANOBOT_LLM_TIMEOUT_S は使用されなくなりました。内部タスクを含むモデル ストリームは、固定の合計期間タイムアウトではなく、イベントごとに更新される NANOBOT_STREAM_IDLE_TIMEOUT_S (デフォルトでは 90 秒) を使用します。
