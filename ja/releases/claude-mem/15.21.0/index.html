claude-mem v15.21.0

マイナー 公開日2026年11月17日 出典thedotmack/claude-mem 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロード・メム v15.21.0

claude-mem はクロード コードのコード モードをオフにしなくなりました

  • コード モードは claude-mem が有効な状態で開始します (#6278、ありがとう @naive000; @nasif-naseef によって #6209 で報告されました)。コード モード (実験的、クロード コード 2.1.323 以降) は、プラグインのフック モジュールが tool.call をフックすると開始を拒否します。 claude-mem の自動クリア MOD が機能したため、自動クリアがオフであっても、claude-mem が有効になっている全員に対してコード モードがオフになりました。 MOD は代わりに session.append を通じてツールの結果を読み取るようになりました。自動クリアは、MOD を実行するすべてのクロード コード バージョン (2.1.287 以降) で引き続き機能します。

自動クリアは中断したところから再開します

CLAUDE_MEM_AUTO_CLEAR_ENABLED を true に設定しない限り、オートクリアはオフのままです。オンの場合:

  • 「続行」という裸の単語の代わりに継続プロンプトが表示されて再開されます (#6294)。クリアする前に、クロードは作業状態を最後に保存し、作業中のリスト、完了したばかりのタスク、および全体的な目標に名前を付けます。 /clear の後、自動クリアは次を送信します: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. その保存で 3 つのうちのいずれかが残された場合、以前と同様に「続行」が送信され、その理由が記録されます。
  • コンテキスト ウィンドウの 33% ではなく 40% で開始されます (#6294)。 settings.json で設定した CLAUDE_MEM_AUTO_CLEAR_PERCENT または環境が引き続き優先されます。

新しい接続方法

  • Hermes デスクトップ、MCP 経由で検索して保存 (#6284、感謝 @krishnadobhal; #5940 の一部)。 claude-mem hermes install --mcp-only --project-cwd <absolute-directory> は、claude-mem をメモリ プロバイダーにすることなく、Hermes One および Hermes Desktop の MCP サーバーとして追加します。要求すると、検索と保存が行われます。何もそれ自体がキャプチャされたり注入されたりすることはありません。 claude-mem hermes uninstall は書き込んだ内容のみを削除し、config.yaml をバイトごとに復元します。
  • VS Code の GitHub コパイロット (#6286、ありがとう @krishnadobhal; #5895 の一部)。 npx claude-mem install --ide copilot-vscode は、VS Code の Copilot エージェントが読み取る MCP エントリを書き込みます (~/.copilot/mcp-config.json、Copilot CLI が使用するのと同じファイル)。エントリには "tools": ["*"] が含まれるようになりました。これがないと、VS Code は claude-mem に接続しますが、そのツールをモデルに提供することはありませんでした。自動キャプチャはまだありません。
  • ModelGo プリセット (#6277、ModelGo チームの @lichloe1116-gif に感謝)。 OpenAI 互換プロバイダーには、https://api.modelgo.ai/v1 用の modelgo プリセットがあります。デフォルトのモデルは設定されていないため、キーで使用できるものを選択してください。

こちらも新作

  • 作業状態の書き込みチェック (#6217、ありがとう @vieGPT)。 ~/.claude-mem/work-state-write-guard.json で設定した、選択したリストに書き込む前に、work_state_write にローカル チェック コマンドを実行させることができます。書き込みが拒否されると HTTP 409 が返され、何も保存されません。ファイルがない場合は何も変わりません。
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225、ありがとう @Moep90; #6223)。 JSON オブジェクトは、api エージェントが送信するすべてのリクエストに追加されます (My Work リフレッシュおよび api を持つコーパス エージェント)。 vLLM 上の Qwen モデルの場合、{"chat_template_kwargs":{"enable_thinking":false}} は推論をオフにします。 model、messages、max_tokens などのフィールドは警告とともに削除され、cmem.ai ゲートウェイに送信されることはありません。

私の仕事の更新

  • 独自のモデルからの遅い応答が約 5 分で失敗することがなくなりました (#6224、ありがとう @Moep90; #6222)。 Bun のフェッチは、api エージェントの 10 分間のリクエスト制限が適用される前に、5 分間静かだった接続を放棄しました。今ではその制限が唯一のものです。
  • max_completion_tokens の動作を必要とするエンドポイント (#6242)。エンドポイントが max_tokens を拒否すると、api エージェントは、HTTP 400 ですべての呼び出しを失敗させるのではなく、max_completion_tokens でリクエストをもう一度送信します。
  • 2 回拒否された回答でも更新が停止することがなくなりました (#6212、ありがとう @Moep90)。グループ化、フォーカス、またはレビューを 1 回再試行すると、チェックに失敗した部分が削除され、残りの部分が保存されます。以前は、同じバッチを実行するたびに失敗していました。
  • 構築ストーリーは部分的に書かれています (#6279、ありがとう @0xABCD01; @Moep90 によって #6226 で報告されました)。ストーリー ステップでは、変更されたすべてのレビューが 1 つの質問で送信されました。その疑問はモデルのコンテキスト ウィンドウを超えて大きくなり、その後の更新はすべて失敗しました。他のステップが使用するのと同じ質問予算に適合するパーツが送信されるようになりました。
  • 長い会話は、最初の 10 件ではなく、最新のリクエストごとにグループ化されます (#6243、ありがとう @Afloat16)。
  • git commit --message または --message= で作成されたコミットが認識されます (#6236、ありがとう @Afloat16)。
  • 証拠が 1 つのリポジトリ (#6237、ありがとう @Afloat16) を指定している場合にのみ、コミットは GitHub リンクを取得します。
  • マイ ルールがエージェントを待機している間、API リフレッシュをセットアップするための手順にリンクします (#6214、ありがとう @liuyinchu)。

セットアップ、インポート、エクスポート

  • プロンプト履歴が大量になるとセットアップが終了します (#6280、ありがとう @0xABCD01; #6266; @deserteaglemj によって #6227 で報告されました)。最近のプロンプトが 2 MiB のホストされたアップロード制限を超えると、「最近の作業の検索」でセットアップが 99% で停止し、すべての再試行が同じように失敗しました。これでマシンのセットアップが完了し、その旨が表示されます。同意ステップには、「1 回のアップロードには多すぎます。ツールのチェックを外すか、スキャンをスキップしてください。」も表示されます。選択範囲が適合するまでアップロード ボタンをオフにします。
  • 大規模な輸出インポート (#6261、ありがとう @Afloat16)。ワーカーの 5 MiB リクエスト制限を超えるファイルは、何も保存される前に拒否されました (HTTP 413)。大きなファイルは、完全なコンテンツを含むセッションを最初に分割して送信されるようになりました。
  • インポートされた観測値は、CLAUDE_MEM_DEDUP_ENABLED がオンの場合、ライブ観測値と同じ方法で重複排除によって検出されます (#6263、ありがとう @Afloat16)。
  • プレビューがワーカーを呼び出さないため、claude-mem import --dry-run はワーカー設定が間違っていても停止しなくなりました (#6215、ありがとう @liuyinchu)。
  • 別のエージェントからインポートされた会話 Codex Desktop は、Codex で入力されたプロンプトとしてカウントされなくなりました (#6219、感謝 @rigel905; #6218)。
  • /dev/stdout、/dev/stderr、いずれかへのシンボリックリンク、または FIFO にエクスポートすると、そこにクリーンな JSON が書き込まれ、進行状況行と警告が他のストリームに送られます (#6288、@Afloat16 による #6258 から)。

修正

  • Windows: クロード コードは RULES-AND-TOOLS.md を再度ロードします (#6234、ありがとう @QuantScorpus)。 claude-mem は、@ インポート行をバックスラッシュで記述しました。 Claude Code は何も言わずにそれらをスキップし、claude-mem も命令の他のコピーを省略したため、どちらもモデルに到達しませんでした。行ではスラッシュが使用されるようになりました。フェンスで囲まれたコード例内に表示される @ インポートは、実際のインポートとしてカウントされなくなりました (#6293、@Afloat16 による #6241 から)。
  • claude-mem start はインストールされたワーカー (#6235、@ZedingZhang に感謝; @ExactDoug によって #6228 で報告) を実行しますが、依存関係が欠落している可能性がある古いシェル エイリアスが指すコピーではありません。
  • クロックが戻された後もバックアップには新しいスナップショットが保持されます (#6273、ありがとう @Afloat16)。以前は、クリーンアップによって、保存済みとして報告されたばかりのスナップショットが削除されることがありました。
  • teambrain join は、オプションの共有手順が失敗した場合でも新しい同期接続をオンにします (#6275、ありがとう @Afloat16)。
  • 進行状況のない概要は保存されません (#6202、ありがとう @ShitK)。以前は、タイトルや今後の予定のみを記載した概要が保存され、成功として発表されていました。
  • Claude Code の自動メッセージはリクエストを分割しなくなりました (#6251、ありがとう @Afloat16)。アドバイザーと成果物のスキャンはそれらを新しいリクエストとして扱い、同じターンからの以前のアドバイスとファイルの書き込みを失いました。
  • コーパスは 250,000 を超える観測結果を構築 (#6271、感謝 @Afloat16)。 too many SQL variables で失敗しました。
  • コーデックス: 点線の TOML キーでプラグインをオフにした場合、オフのままになります (#6239、ありがとう @Afloat16) (例: plugins."claude-mem@claude-mem-local".enabled = false)。
  • mem-search スキルのフロントマターは有効な YAML (#6276、ありがとう @Afloat16; #6267 で @orbiutyt によって報告されました)。
  • Aider: インストーラーは、Aider が実際に使用する設定ファイル (最初に作業ディレクトリ、次に git root、次にホーム) (#6289、@Afloat16 による #6230 から) を編集し、read: リスト内で引用されたファイル パスをそのまま保持します (#6290、@Afloat16 による #6231 から)。
  • カーソルおよび Grok コンテキスト ファイルは、2 つの更新が重なった場合、新しいコンテキストを保持します (#6291、@Afloat16 による #6232 から)。
  • セルフホスト サーバー: 取り消されたキーまたはスコープ違反のあるジョブは 3 回ではなく 1 回実行され (#6252)、claude-mem server jobs retry はキューの再試行とバックオフを使用して再パブリッシュされます (#6253)。@HEOJUNFO に感謝します。 OpenRouter プロバイダーは、トークン フィールド エラー (#6238、ありがとう @Afloat16) の応答をチェックするときに最大 64 KiB を読み取ります。 1 つの読み取り不能なエージェント イベントによって、そのテーブルの読み取りが中断されることはなくなりました (#6199、ありがとう @DeryFerd)。

セキュリティ

  • シェル引用 1.11.0 (#6205、ありがとう @manippoudel; #6200 で @lucasbritolubro によって報告されました)。バージョン 1.9.0 は CVE-2026-102422 (クリティカル) の範囲内にあります。 claude-mem 内のコード パスが影響を受けるコードに到達しませんでした。これにより、船からそれが取り出されます。
  • プラグイン ランタイムの adm-zip 0.6.1 および zod 4.6.7、高勧告 (#6220、ありがとう @LeviReisJs; #6211 で @noumanbhatti によって報告)。
  • Gemini API キーはリクエスト URL ではなくヘッダーに含まれる (#6196、ありがとう @DeryFerd) ため、プロキシやアクセス ログには記録されません。
  • 一時ファイルはランダムな名前を取得し、残りのアトミック書き込みサイト (#6198、#6193、ありがとう @DeryFerd) で排他的に作成されるため、植えられたシンボリックリンクは設定ファイルや状態ファイルの書き込みをリダイレクトできません。
  • セルフホスト サーバーの認証されていない /v1/info には状態のみが表示されます (#6195、ありがとう @DeryFerd): 認証モード、スキーマ バージョン、Redis ホストまたはドライバーのエラー テキストはありません。
  • CI: インストール後の許可リスト チェックはすべての直接プラグイン依存関係を検査し (#6197)、スポーン環境チェックはスポーン上で宣言された env ブロックを読み取り、プラグイン ランタイムをスキャンします (#6194)。@DeryFerd に感謝します。

貢献者向け

  • TypeScript 7.0.2 (#6207、ありがとう @krishnadobhal; #6188)。コンパイラー API を使用するスクリプトとテストは、エイリアスを通じて TypeScript 6 を保持します。
  • インポート スモーク テストは、最終スキャンの前に SQLite リーダーを閉じます (#6216、ありがとう @liuyinchu)。
