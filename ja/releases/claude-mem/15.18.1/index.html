claude-mem v15.18.1

パッチ 公開日2026年11月12日 出典thedotmack/claude-mem 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロード・メム v15.18.1

重要な修正

  • 起動時にデータベースがビジー状態の場合でもワーカーの起動に失敗しなくなりました (#6041)。再起動によって [マイ ワーク] 更新レコードが「実行中」のままで、その時点でデータベースがロックされていた場合、修復書き込みがスローされ、ワー​​カーの起動全体がダウンするため、次の再起動までメモリはオフのままになります。修復の失敗がログに記録され、次にスケジュールされたチェックが再試行されます (スケジュールされた更新がオンになっているかどうかに関係ありません)。
  • npx claude-mem update と毎日の自動更新によりセットアップが維持されます (#6045)。これより前は、無人更新によってサーバーまたはサーバーベータ ランタイムがローカル ワーカーにリセットされるため、キャプチャはサーバーから移動されました。プロバイダーが保存されていないレガシー インストールでは、クラウド同期がオフになり、Anthropic 環境キーがクリアされる可能性もあります。更新では、保存されたランタイム、プロバイダー、モデル、エージェントが再利用されるようになりました。ブラウザーのセットアップを再度開いたり、セットアップに関する質問を再度したりすることはなく、Gemini キーまたは OpenRouter キーが不足している場合にのみ要求します。 npx claude-mem install は変更されません。
  • 私の作業サマリーは、使用できないモデル回答の再試行を永久に停止します (#6039、ありがとう @mohitdixit02、#6037 で @adminwat によって報告されました)。モデルの応答が検証に失敗した場合、JSON ではなかった場合、または空で返された場合、同じ変更されていないリクエストが毎分終わりなく再送信されました。あるレポートでは、104,869 件の通話が測定され、一定の負荷により地元のオラマ ランナーは飢えていました。各リクエスト バージョンは最大 3 回の試行を行い、待機時間が長くなり、入力または設定が変更されるまで待機します。カードには実際の理由が示されています。空の答えのケースをテストして見つけてくれた @balabommablock-cpu に感謝します。

修正

  • デフォルトでオブザーバーのコストが低くなります (#6031、@kartik70 に感謝、#5023 を終了)。オブザーバーの会話バジェットは 400,000 文字から 100,000 文字に減少します (問題の測定では 1 ターンあたり約 100,000 から約 26,000 トークン)。古い出荷時のデフォルトがまだ保持されているインストールは、一度移動します。自分で設定した値は保持されます。
  • 編集: Heroku API キーと Atlassian API トークンが保存前に削除されるようになりました (#6046、感謝 @kevin9327)。
  • TeamBrain: 中継されたテキストは、claude-mem 独自の見出し、フェンス、ルール (~~~、***、___、settext ===) として渡すことができなくなりました (#6048、感謝 @kevin9327)。
  • 作業状態: GET /api/work-state/export は、MCP 応答には長すぎる場合にリストの完全な履歴を返し、短縮された MCP 読み取りがそう言ってそれを指すようになりました (#6049、感謝 @Jeremy891102、クローズ #6043)。
  • 私の作品 (@Afloat16 に感謝):
    • 新しい成果物のリビジョンまたは公開された PR によって結果が変更されると、チェックされたリクエストは再びチェック解除されます (#5891)。
    • 長いプロンプト履歴の最初の目標マップは、失敗して繰り返す 1 つの大きな質問ではなく、チェックポイント付きのバッチで実行されます (#6001)。
    • 元のリクエストを解決しても、会話ごとにプロンプ​​ト ウィンドウ全体が再スキャンされなくなりました (#6022)。
  • スマート ファイル読み取り: サポートされているすべての言語で関数シグネチャは実際の本体の境界で終わるため、構造化されていないパラメーターとデフォルト オブジェクトはアウトライン内に残り、検索可能です (#6029、ありがとう @Afloat16)。
  • Gemini CLI: npx claude-mem gemini install は、ワーカーが見つからないと報告するのではなく、プラグイン キャッシュにのみインストールされているワーカーを見つけます (#6032、ありがとう @Kirat0201)。
  • メモリ: 古いネイティブ メモリ ノートを再生すると、書き込みトランザクション内のプロジェクト履歴をスキャンする代わりにインデックスが使用されます (#6016、ありがとう @Afloat16)。

新しい例とドキュメント

  • Obsidian: 選択した思い出を既存の保管庫にオプトインで一方向にエクスポートし、メモを上書きすることはありません (#6051、感謝 @Jeremy891102、クローズ #5943)。
  • Pipecat: 明示的なプロジェクト メモリ パイプラインの例 (#6050、ありがとう @Jeremy891102、クローズ #5946)。
  • elizaOS: 検証済みの明示的メモリの例 (#6035、ありがとう @Kirat0201、クローズ #5914)。
  • ContextForge: プライベート リコール ワークフロー (#6033、ありがとう @Kirat0201、クローズ #5935)。
