claude-mem v16.0.0

メジャー 公開日2026年11月18日 出典thedotmack/claude-mem 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロード・メム v16.0.0

私の仕事はあなたを必要とするものを第一に考えます

[My Work] (エージェントが何を行っているかを表示するページ) は、完全な UI レビュー (#6210、#6304) から再構築されました。必要なものが一番上に表示され、長いリストが折りたたまれ、すべてのページが携帯電話、キーボード、スクリーン リーダーで動作します。

  • 必要なものが最初に来ます。 ホームページでは、あなたを待っている最初のリクエストが上部にあり、画面上に 1 つのオレンジ色のボタンが表示されます。リクエストは 1 行の行です。アイドル状態と出荷済みは、それぞれの数とともに 1 行に折りたたまれます。
  • ページが短くなります。 実際のインストールでは、ホームの高さは 5,138 ピクセルではなく、約 2,600 ピクセルになります。リストは 195 行ではなく 5 行で開きます。私のルールは17,000ピクセル以上ではなく、約4,400ピクセルです。
  • 読んだところに返信します。 リクエストのドロワーは、どの状態でも進行状況ラインのすぐ下に返信ボックスを配置します。返信の途中では、「ここに返信」が待機するため、メッセージが 2 番目の有料ターンとして 2 番目の会話に進むことはできません。
  • 重点分野のページは上から下に続きます。何が必要か、まだ始まっていない質問、そしてボードです。保存に失敗すると、どの変更が失敗したかが示され、その画面でのみ「再試行」が表示されます。過去のフォーカスは、エリアが完了とマークされた日を示します。
  • マイ ルール: 一度に 1 つのルールを決定します。オレンジ色の承認が 1 つあります。電話の場合は、スワイプして決定します。
  • 携帯電話に適合します。 すべてのページは 390 ピクセルの携帯電話では幅 390 ピクセルで、下部には [仕事]、[フォーカス]、[ルール] のバーがあります。
  • キーボードとスクリーン リーダー。 すべてのコントロールには名前があります。ツールチップはタブから開きます。フォーカスは、ダイアログ、ドロワー、閉じるか再試行後の元の場所に戻ります。タッチ時のコントロールは 44 ピクセルです。
  • ロード前のテーマ 明るいか暗いかの選択は、最初のフレームの前に描画され、ロード画面とエラー画面が含まれます。
  • 単純なエラー。 失敗はあなたの言語で書かれた 1 文であり、生の理由は詳細の下に折りたたまれています。自動的に再試行されるものはありません。
  • あなたの言語と時計 時刻は記録された時間からあなたの言語で表示され (フランス語は 24 時間時計を読みます)、別の年の日はその年を示します。新しい文字列はフランス語、韓国語、トルコ語、中国語に翻訳されます。ネイティブスピーカーからの添削は大歓迎です。
  • モーションの削減 ライブ アップデートでは最大 2 つのものが移動しますが、モーションの削減がオンの場合は何も動きません。

観測テレビは削除されました

  • TV ページとその読み取り専用リモート アクセスがオープンソース ワーカー (#6295) から削除されました: /tv、tv.html、および CLAUDE_MEM_TV_TOKEN 設定。クラシック ビューアと [マイ ワーク] は変更されていません。
  • 別のマシンからテレビを視聴した場合: ネットワーク アクセスを保護する CLAUDE_MEM_LOCAL_API_TOKEN を設定し、CLAUDE_MEM_TV_TOKEN を削除します。そうするまで、非ループバック CLAUDE_MEM_WORKER_HOST でローカル API トークンを持たない TV トークンを見つけたワーカーは 127.0.0.1 (IPv6 ホストの場合は ::1) にバインドし、SECURITY エラーをログに記録するため、トークンなしでは完全な API がネットワークに公開されることはありません。
  • フレーミング保護は、ワーカーが提供するすべてのページをカバーするようになりました。

15.20.0 および 15.21.0 ではすでに出荷されています

同じレビューの残りの部分が 15.20.0 で届きました。

  • セットアップ: ステップバー、各画面に戻る、単純なエラー、およびインポートの停止 (#6233)。
  • クラシック ビューア: 1 つのヘッダー行、検索可能なプロジェクト ピッカー、「このセッションで検索」、長いタイムラインの最後に React エラー 185 が発生しません (#6229)。
  • Mem0 および Supermemory からのインポート: 受け入れ修正 (#6206)。
  • 修正: Codex デスクトップ セッションは macOS 上でライブで読み取られ (#6285、@MaxWang007 に感謝)、settings.json が有効な JSON ではない場合にワーカーが開始されます (#6259)。 15.21.0 が続きました: コード モードは claude-mem が有効な状態で開始され (#6278)、自動クリアは継続プロンプトで再開され (#6294)、VS Code の Herme デスクトップと GitHub コパイロットは MCP 経由で接続され (#6284、#6286)、プロンプト履歴が 1 回のアップロードには大きすぎる場合にセットアップが終了します (#6280)。 全音符: 15.20.0 および 15.21.0。

こちらも新作

  • SessionStart バナーは Claude Code 端末のカードです (#6274)。クロードコード 2.1.326 以降では、ルール + ツール行、「以前」とタイムラインが 1 枚の枠付きカードとして描画されます。 Claude アプリにミラーリングされたセッションでは、バナーの各行の前にフック名の代わりに 1 行が表示されます。

修正

  • バックログを処理している間、ワーカーは応答し続けます。 ヘルス チェック、フック、およびビューアはもう待機しません。
    • フック スプール バックログ: ドレインは 64 個の並列バッチでファイルを読み取り (#6260、@Zhong-fan に感謝)、ブロックせずにそれらを削除して要求します (#6296、@Afloat16 による #6254 から)。 #6247 で @soarkit によって報告されました。
    • ワーカー開始時のプロジェクト リスト。すべての行を読み取り、プロジェクト インデックスを読み取ります (#6270; @soarkit によって #6246 で報告されました)。
    • クロード CLI は、コーパス プライムとクエリがキャッシュ ミスで実行されることをチェックします (#6256、ありがとう @Afloat16; @soarkit によって #6250 で報告されました)。
    • Chroma Sync のチェックポイント。行ごとに書き換えられ (2,000 行で約 28 MB の書き込み)、250 ミリ秒に 1 回書き込まれるようになりました (#6204、ありがとう @Zhong-fan; #6203 で @soarkit が報告)。
  • フォルダー CLAUDE.md ファイル: 更新は 1 つずつではなく一度に最大 8 フォルダーを取得し (#6264; @soarkit によって #6248 で報告)、claude-mem generate はフォルダーごとに 1 回ではなくプロジェクトの観察を 1 回読み取ります (#6265; @soarkit によって #6249 で報告)、失敗したフォルダーの更新はそのフォルダーとともにログに記録され、そのフォルダーの次の観察によって再試行されます。 (#6208、ありがとう @0xABCD01)。
  • 長い Bash 出力は終了を維持します (#6292; #6282 で @micronox によって報告されました)。 Claude Code が約 30,000 文字以上の出力を切り取って全文をファイルに保存すると、メモリは最初からのみ得られるため、最後の行 (テストの概要、最終エラー) が失われます。 claude-mem はそのファイルの終わりを読み取ります。
  • ネイティブ メモリ ノート: フロントマターの先頭に type: があるノートはそのカテゴリを保持し (#6244)、トランスクリプトの最初のプロンプトが長い場合にノートのプロジェクトが見つかります (#6272)、ありがとう @Afloat16。
  • 最近のセッションには、採用されたワークツリーが含まれています (#6268、ありがとう @Afloat16)。ワークツリーがその親にマージされた後、OpenClaw の claude-mem-recent は以前のセッションを表示しませんでした。
  • 検索: スペースのない長い単語内の中国語と日本語の用語がコーパス証拠で見つかります (#6213、ありがとう @liuyinchu)。 smart_outline、smart_search、smart_unfold は、exports.read = function … (#6245) など、割り当てによって定義された JavaScript 関数を検索し、各 Java メソッドのオーバーロードは独自に展開されます (#6257)。ありがとう @Afloat16。
  • より静かなエラー レポート: 120 秒のリーダー期限を過ぎたコンテキスト読み取りは、低速読み取りに名前を付け、エラーではなく警告をログに記録します (#6255)。また、Windows では、Windows がロックしたままのスプール エントリには、ドレインごとにエラー レポートの代わりに 1 つの警告が記録されます (#6269)。
  • ドロップされた 2 つの失敗が現在ログに記録されています (#6302): 自動クリアは、作業状態を保存するリクエストをクロードに渡すことができなかったときにトランスクリプトでその旨を示し、サーバーは、/v1/info がベクトル検索ステータスを読み取れなかった理由をログに記録します。
  • トルコ語: 私の仕事の文言がより明確になり、最新のトルコ語 README (#6287、ありがとう @alkank)。

貢献者向け

  • bash 4 を必要とするコミット メッセージ テストは、macOS の bash 3.2 ではスキップされますが、Linux CI では引き続き実行されます (#6297)。
