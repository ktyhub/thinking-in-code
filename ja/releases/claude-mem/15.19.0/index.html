クロード・メム v15.19.0

[私の仕事] からクロード コードまたはコーデックスの会話を続ける

[マイ ワーク] でリクエストを開き、[これの出所] を開きます。各クロード コードまたはコーデックスの会話の下に、メッセージ ボックスが表示されます。メッセージを入力して送信を押すと、同じ会話が始まります。応答はそこに表示されます (#6191; コマンドの形状は #6054 の @wiesenthal の応答コードに従っており、コミットには彼のクレジットが記載されています)。

  • 各会話では、My Work から送信されたメッセージとその返信が順番に保持されます。停止すると実行ターンが終了します。
  • ボックスには、ターンがどのフォルダーで実行されるかが示されています。記録されたフォルダーが存在しなくなった場合 (ワークツリーがクリーンアップされた後は一般的)、ターンはその上にある最も近い既存のフォルダーで実行されます。 ・「コピー再開コマンド」はclaude --resume <id>またはcodex resume <id>をコピーします。 Mac では、「クロードで開く」を選択すると、クロード デスクトップ アプリでクロード コードの会話が開きます。
  • 1 回の送信で、stdin 上のメッセージを含む 1 つのヘッドレス履歴書 (claude --resume <id> -p --output-format json または codex exec resume <id> - --skip-git-repo-check) が開始されます。失敗したターンは失敗として記録され、再試行されることはありません。再生のためにキューに入れられたり保存されたりすることはなく、起動時、タイマー時、再接続時に何も開始されません。
  • ワーカーの再起動またはシャットダウンは、実行中のターンごとに最初に停止するため、再起動されたワーカーが同じ会話の 2 番目の書き込み者になることはありません。停止したターンを再送信するものはありません。
  • ターンは、claude -p --resume が端末で使用するものと同じ、独自のデフォルトの許可モードで実行されます。手動モードでは、承認が必要なツール呼び出しは拒否され、行でカウントされます。権限、モデル、またはサンドボックス フラグが渡されません。
  • 新しいルートはループバックでのみ応答し、他の発信元を拒否します。ローカル API トークン モードをオフにすると、他のすべてのワーカー ルートと同様に、同じコンピューター上の別のプログラムからそれらを呼び出すことができます。共有コンピュータで、ローカル API トークン モードをオンにします。
  • リクエストごとに 1 つの変更: 開いているリクエストの新しいバージョンが読み込まれる間、ドロワーには「リクエストの詳細を読み込み中…」の代わりに、既存のバージョンが表示され続けます。

既知の制限:

  • ページを通る Codex パスは、テスト マシン上でエンドツーエンドで実行されませんでした。コーデックスターンは実機CLIでランナーレベルでチェックしました。
  • Windows では、Stop が .cmd シムの背後にある CLI に到達しない可能性があり、「クロードで開く」は提供されません。
  • 端末内でターン途中の会話でも、「My Work」からターンを取得できます。 Claude Code のドキュメントには、1 つのセッションで 2 人のライターがメッセージを失う可能性があると記載されています。私の作品は、1 つの会話で 2 つのターンをブロックします。
  • ワーカーのクラッシュ (グレースフル リスタートではない) では、実行中のターンを停止できません。それはそれ自体で終わります。
  • CLI が残すヘルパー (ゆっくりと終了する MCP サーバーなど) は、終了するか停止を押すまでターンを実行中としてマークし続けます。

既存の記憶を持ち帰る

npx claude-mem import は、Mem0 プラットフォームまたはスーパーメモリーからメモリーを直接フェッチし、選択したプロジェクトに検索可能な観測値として保存します。エクスポート ファイルもモデル呼び出しもありません (#6106)。

# MEM0_API_KEY in the environment
npx claude-mem import --from mem0 --source-account personal-mem0 --user my-user-id --project imported-memory

# SUPERMEMORY_API_KEY in the environment
npx claude-mem import --from supermemory --source-account personal-supermemory --namespace my_namespace --project imported-memory
  • 最初にワーカーを開始します (npx claude-mem start)。 --dry-run を追加すると、何も書かずにソースをフェッチしてチェックし、カウントを出力します。
  • すべてのソース ページは、何かが書き込まれる前にフェッチされ、チェックされます。期限切れまたは交換された Mem0 メモリ、および忘れられた、または古い Supermemory メモリはスキップされます。スーパーメモリの場合、--documents はメモリの代わりに抽出された文書テキストをインポートします。
  • インポートされたメモリはクロード コード (claude) 用にファイルされているため、メモリ検索でそれらが見つかります。 --platform <host> (たとえば、codex または cursor) は、それらを別のホストにファイルします。各観察では、ソース レコード、ID、タイムスタンプ、メタデータ、アカウント ラベル、スコープが保持されます。
  • 同じコマンドを再度実行しても安全です。すでに保存されているレコードは既存のものとしてカウントされます。バックグラウンド ジョブや自動再試行はありません。
  • これは一方向のインポートであり、同期ではありません。ソースを編集すると、新たな観察が行われます。ソースでの削除と有効期限は引き継がれません。
  • 制限: デフォルトで 10,000 レコード (--max-records は最大 100,000)、ソース応答は 100 MiB、15 秒の要求期限 (--timeout-ms は最大 120,000)、レコードあたり 100,000 文字。サイレントに何も中断されることはありません。サイズが大きすぎるレコードや失敗したリクエストによって実行が停止されます。
  • テストでは、ライブ アカウントではなく、合成 Mem0 および Supermemory 応答が使用されます。

ドキュメント: https://docs.claude-mem.ai/usage/import-providers

Codex: フォークされたスレッドがメモリを取得します

  • フォークされた Codex スレッドは、リコールされたメモリから開始されます (#6101)。 Codex 0.165 は、実験的に接続されたスレッド フォークに fork セッション開始を追加しました。 claude-mem の SessionStart フックが一致しなかったため、フォークされたスレッドがメモリなしで開始されました。フックは fork と一致するようになりました。

    Codex ユーザー: 1 つのフックを再度承認します。 SessionStart フックのマッチャーが変更され、Codex はフックの定義が変更されるたびに再度承認を求めます。

    1. 新しいマッチャーを ~/.codex/hooks.json に入れます。 npx claude-mem update と自動更新は、前回のインストールで Codex を選択したときにこれを実行します。それ以外の場合は、npx claude-mem install を実行し、Codex を選択します。
    2. インタラクティブ Codex を開き、/hooks を実行し、claude-mem の SessionStart フックを承認します。

    承認するまで、Codex セッションは記憶が呼び戻されることなく開始されます。キャプチャは引き続き機能します。新しいマッチャーが hooks.json に組み込まれるまで、npx claude-mem doctor は Codex hooks 行を古いものとして表示します。

こちらも新作

  • サーバー ランタイム: 検索結果には、どのエージェントがメモリを作成したかが示されます (#6100)。サーバー ランタイムはエージェントを各メモリに保存し、セッションの既存のメモリにエージェントを埋め込みます。その MCP 検索行と詳細行には、[via <agent>] (例: #8 — Auth redirect decision (myproject) [via cursor]) が追加されます。エージェントが記録されていないメモリにはタグが表示されません。 /api/sessions/observations は、すべての client をクロード コードとしてラベル付けしなくなりました。ローカル作業員の観察結果にはまだエージェントが搬送されていないため、タグは表示されません。
  • Zed (#6111、ありがとう @AdityaxDeore、#5900 を終了)。 npx claude-mem install (または --ide zed) は、検索、タイムライン、詳細、および明示的な保存のために、claude-mem の MCP サーバーを Zed の context_servers に登録します。 Zed の設定ファイル内のコメントは保持されます。 Zed にはフックやトランスクリプトへのアクセスがないため、自動キャプチャはありません。ドキュメント: https://docs.claude-mem.ai/zed-integration
  • Aider (#6112、ありがとう @AdityaxDeore、クローズ #5893)。プロジェクト内で npx claude-mem aider install を実行します。 .claude-mem/aider-memory.md を .aider.conf.yml の read: リストに追加し、npx claude-mem aider sync がワーカーからそのファイルを更新します。これはプロジェクトごとにオプトインです。npx claude-mem install はこれを提供せず、メモリ ファイルは .git/info/exclude を通じて git から除外され、ホーム フォルダーでの実行を拒否します。自動キャプチャはありません。ドキュメント: https://docs.claude-mem.ai/aider-integration
  • Grok Build はセッション開始時にメモリをリコールします (#6180、ありがとう @krishnadobhal、クローズ #5950)。 Grok Build は SessionStart フックが出力する内容を無視するため、呼び出されたメモはモデルに到達しません。 claude-mem grok install は現在のフォルダーに .grok/rules/claude-mem-context.md を書き込みます。Grok Build はこれを trusted フォルダーからロードします。ワーカーは、各セッションの概要の後に、それをインストールしたフォルダー内でのみ、それを更新します。除外されたプロジェクトには、メモの代わりに「除外された」行が表示されます。キャプチャーは変更なし。ドキュメント: https://docs.claude-mem.ai/grok-build
  • My Work、ビューア、初回実行セットアップ、Observation TV の言語ピッカーの フランス語 (#6107、感謝 @QuantScorpus)。あなたの思い出、ルール、引用は書かれたままになります。
  • OpenAI 互換プロバイダー用の 3 つの新しいプリセット。 メモリ抽出が大量に行われるため、それぞれのデフォルトは小型で高速なモデルです。
    • AtmoRouter、zai/glm-5.3-flash (#6108、ありがとう @BeckleyTenriajeng)
    • TrustedRouter、deepseek/deepseek-v4-flash (#6174、ありがとう @jperla)。 trustedrouter/auto は引き続きオプトインとして利用可能です。リクエストをフロンティア料金のモデルにルーティングできます。
    • HopBase、deepseek-v4.1-flash (#6181、ありがとう @victor-zzh)

修正

プライバシーとセキュリティ

  • claude-mem データ フォルダーは所有者のみです (#6091、ありがとう @DeryFerd)。 macOS および Linux では、~/.claude-mem (データベース、設定、.env、フック スプール、バックアップ) はプレーン mkdir で作成されたため、共通の 022 umask の下でマシン上の他のアカウントがそれを読み取ることができました。これは 0700 として作成され、既存のフォルダーは次回の起動時に強化され、新しいフック スプール エントリは 0600 として書き込まれます。
  • MCP save_memory は CLAUDE_MEM_EXCLUDED_PROJECTS を尊重します (#6105、ありがとう @Zhong-fan、#6098 で @Kirat0201 によって報告されました。@0xABCD01 は #6166 で同じ修正を送信しました)。除外されたチェックアウトからの保存は MCP 経由で保存されましたが、HTTP 経由の同じ保存はスキップされました。現在はスキップされ、「保存されていません: このチェックアウトは CLAUDE_MEM_EXCLUDED_PROJECTS によって除外されています。」という返信が表示されます。 「保存されたメモリ #?: 無題」の代わりに。 Cline および Kilo ガイドにはそのように記載されています (#6190)。
  • サーバー ランタイム: MCP 接続コマンドが使用できないホストを拒否します (#6176、ありがとう @DeryFerd)。 CLAUDE_MEM_PUBLIC_URL を使用しない場合、GET /v1/connect および POST /v1/keys は、リクエストの Host ヘッダーから貼り付け可能なコマンドを構築し、そこに空白、引用符、またはパスをコピーしました。ホストにできない値は 400 InvalidHost を取得し、キーは作成されません。
  • 同期ハブ: FORWARD_ORIGIN は https:// を使用する必要があります (#6175、ありがとう @DeryFerd)。フォワード プロキシは受信 Authorization ヘッダーをターゲットにコピーするため、プレーン http:// オリジンは TLS なしでヘッダーを送信できます。 http:// はループバック ホストにのみ許可されます。使用可能な URL ではない値は、静かに永続オブジェクト パスにフォールバックするのではなく、大声で失敗するようになりました。

インストールとアンインストール

  • アンインストールすると Gemini CLI フックが削除されます (#6088、ありがとう @tanisqbaweja)。 npx claude-mem uninstall はプラグインを削除しましたが、claude-mem の 5 つの Gemini CLI フックを ~/.gemini/settings.json に残したので、Gemini CLI はセッション開始時、プロンプト時、ツール呼び出し時、ターン終了時にフック失敗メッセージを出力しました。アンインストールするとそれらが削除され、独自の設定とフックが保持されます。コメント付きのsettings.jsonはそのままになっているので、そのフックを手で外します。
  • API キー プロンプトをキャンセルしても、クロードに切り替わることはなくなりました (#6161、ありがとう @bulanovk)。 --provider gemini または --provider openrouter でキーが保存されていない場合、キー プロンプトをキャンセルすると CLAUDE_MEM_PROVIDER='claude' が書き込まれ、続行されます。現在はエラーで停止し、何も変わりません。
  • Codex インストーラーのレガシー構成チェックは、claude-mem の残りの部分と同様に、Windows 上でのみ先頭の ~\ を展開します (#6093、ありがとう @DeryFerd)。

ワーカーとストレージ

  • 起動時にデータベースがビジー状態になったワーカーは、数分間 503 に応答せずに再試行します (#6145、感謝 @montjeffrey、参考文献 #3603)。代替作業者は、データベースの起動中に SQLITE_BUSY_SNAPSHOT を 1 回ヒットし、再試行することはなく、手動で再起動するまで (レポートでは約 11 分)、すべてのリクエストに「サービスの初期化中」で応答する可能性があります。スタートアップはビジー エラーを 1、2、4 秒後に 3 回再試行するようになりました。最悪のケース (27 秒) は、フックがワーカーの準備が完了するまで待機する 30 秒の範囲内に収まります。他のエラーは依然として一度に失敗します。
  • データベースを閉じると解放されます (#6090、ありがとう @DeryFerd)。キャッシュされたプリペアド ステートメントは、接続を閉じた後も接続とデータベース ファイルを開いたままにしました。 EPERM または EBUSY による復元スワップと一時フォルダーのクリーンアップをブロックした Windows 上。
  • 削除されたセッションの Chroma クリーンアップはワーカー終了後も存続します (#6163、ありがとう @Afloat16)。キューに入れられたクリーンアップが実行される前にワーカーが終了した場合、削除された行のベクトルは削除されませんでした。クリーンアップは開始前に記録されるようになりました。同じ変更により、不足している行を Bun で復元されたものとして扱うチェックが修正されます。
  • Bun では、同期起動除外テーブルが欠落したデータベースは、空のリストを保持する代わりにテーブルを再構築します (#6189)。
  • 障害が発生した /api/ready サブスクライバが、他のサブスクライバの起動の進行を停止したり、起動失敗になったりすることがなくなりました (#6127、ありがとう @Afloat16)。

メモをキャプチャして記憶する

  • CLAUDE_MEM_SKIP_BASH_PATTERNS は反重力 CLI に適用されます (#6096、ありがとう @tanisqbaweja)。 agy はシェル ツールを run_command として報告しますが、パターン チェックでは読み取れなかったため、除外されたコマンドが保存され、オブザーバーに送信されました。
  • NULL 文字を含む明示的なノートは、それ自体のテキストが保存されていない間に別のノートの ID を取得する可能性がありました (#6170、感謝 @Kirat0201、クローズ #6169)。
  • 説明または metadata.type が変更されたクロード コード メモリ ファイルは、インポート済みとして報告されるのではなく、新しいリビジョンとして保存されます (#6186、感謝 @Kirat0201、クローズ #6171)。
  • 思い出メモ (@Afloat16 に感謝):
    • メモのタイトルは、コード例 (#6156) 内の # comment ではなく、実際の見出しから取得されます。
    • ノートの metadata: の下にネストされたフィールドは、ノート自体のタイプまたはセッションを上書きしなくなり、YAML コメントでブロックが終了することはなくなりました (#6157)。
    • 値のない memory ingest --source または --cwd は、現在のチェックアウトをインポートせずに、使用法エラーで停止します (#6150)。
    • トランスクリプトを再度スキャンしても、近くの 2 つのターンに同じテキストがある場合、インポートされたターンが 2 回挿入されなくなりました (#6149)。
    • CLAUDE_MEM_DEDUP_ENABLED=true では、コード文字 (C++ と C#、src/config.ts と src config ts、バージョン番号) のみが異なるタイトルは 1 つの行にマージされなくなり、2 番目の行 (#6120) が失われました。
    • ファクトまたはファイルが 1 つの文字列として保存されているインポートされた観測値は、再度リコールで表示されます (#6134)。

検索とコンテキスト (特に記載がない限り、@Afloat16 に感謝します)

  • セマンティック検索は、Chroma のコピーではなく、保存された行に対して日付ウィンドウをチェックするため、SQLite で更新されたが Chroma ではまだ行われていない行は、右側のウィンドウに表示されます (#6153)。
  • 日付順のファイル検索は Chroma をスキップするため、Chroma の停止や埋め込みの遅さによって失敗することはなくなりました (#6123)。
  • 複数のタイムスタンプが共有される場合、ファイル コンテキストは最新の観測値を返します (#6118)。
  • コンテキスト キャッシュは、レンダリングが順序どおりに終了しない場合でも正しい無効化スコープを維持するため、採用されたプロジェクトに後から書き込むとリフレッシュされます (#6164)。
  • ディープサーチは子プロセスに実際の残り時間のみを与えるため、NTP 修正などのクロックステップによって早期の空のタイムアウトが発生しなくなりました (#6177、感謝 @DeryFerd)。

メモリプロバイダーとしての Codex (@Afloat16 に感謝)

  • 8 MiB プロトコル制限は、バッファリングされたすべてではなく、各 JSON 行に適用されるため、有効な出力は拒否されなくなりました (#6119)。
  • ターン中に閉じられた stdin パイプが失敗し、escaping ではなく、未処理エラーとして正常にターンします (#6130)。
  • タイムアウトしたリクエストによって、新しいアプリサーバーの次のターンが失敗する可能性がある中止ハンドラーが残されることがなくなりました (#6133)。

スマートなファイル読み取り

  • smart_outline は、[exported] と同じ行のエクスポートの隣に宣言をマークしなくなりました (#6141、ありがとう @liuyinchu)。
  • インデックス付きになりました (@Afloat16 に感謝): 匿名 export default 関数、矢印、クラス (#6151)、Swift プロトコル メソッドと本体のない Scala メソッド (#6154)、Java @interface 宣言とその要素 (#6160)。
  • スマート コード検索は 1 つのハンドルを通じて各ファイルを読み取り、512 KiB の上限で停止するため、サイズ チェック後に置き換えられたファイルは制限を超えることはできません (#6124、ありがとう @Afloat16)。

私の仕事

  • 目標ステップでは実行の言語が使用されています (#6187、@0xABCD01 に感謝、@Fly-onlyone によって報告された #6185 を閉じます)。言語ラインはゴールを除くすべてのステップに到達したため、#6185 では 147 の英語プロンプトがスペイン語のゴールを生成しました。言語が設定されていない最初のゴールのみの実行では、まだ推測することができます。 CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGEが設定します。
  • 私の仕事にもあります (@Afloat16 に感謝):
    • Jev の回答が本文の途中で切れた場合は、そのアイテムの永続的な障害ではなく、機能停止としてカウントされるため、次の更新で再度質問されます (#6158)。
    • 新しい git init、新しいネストされたリポジトリ、または削除された .git は、ワーカーの再起動後だけではなく、次回 My Work がセッションのプロジェクトを処理するときに選択されます (#6165)。
    • 自動クリアは、既に終了したターンまたは会話からの遅延読み取りを無視します (#6152)。
    • オーナー プロンプトには、絵文字や基本プレーン以外のその他の文字が含まれている場合でも、3,000 文字の予算が完全に維持されます (#6162)。
    • オプトイン API コーパス エージェントは、アクセントのある単語、ヒンディー語、ベンガル語、および尖ったヘブライ語の単語に一致します (#6168)。
    • 同じ応答が 2 回保存された場合、セットアップでの Gemini 使用量の合計は完了したトークン数を保持します (#6146)。

ビューア

  • ビューア ウィンドウを開くと、最初のプロジェクト リストとステータスがそのウィンドウにのみ送信され、開いているすべてのビューアには送信されません (#6126、ありがとう @Afloat16)。
  • Cliセッション アクション ボタンを再度クリックすると、メニューが閉じます (#6143、ありがとう @liuyinchu)。

その他

  • Agent-cost-report は、Windows 上でスラッシュを含む CHECKSUMS.txt を書き込みます (#6089、ありがとう @DeryFerd)。

パフォーマンス (@Afloat16 に感謝)

  • 長いトランスクリプト行は、後方リーダー (#6116) とライブ ウォッチャー (#6117) で、読み取りパスごとにコピーされるのではなく、一度組み立てられます。
  • OpenCode プロンプト履歴は一度に 1 メッセージずつ読み取られます (#6121)。
  • 大きなツールのペイロードには上限が設定され、完全なコピーを作成せずにハッシュされます (#6128)。
  • タイムラインは、表示されている行のみをロードします (#6129)。最近のセッションでは、インデックス付きの概要チェック (#6132) が使用されています。日付フォーマッタはレンダリング内で再利用されます (#6125)。
  • プロジェクト スコープのリコールは、最初の未採用行でマージ チェックを停止します (#6131)。プロジェクト カタログはセットを含む重複を削除します (#6135)。長く貼り付けられたクエリは、500 タームの上限に達するとスキャンを停止します (#6147)。
  • スマート ファイル読み取りは、スキャンの代わりにインデックスを使用して各シンボルのコンテナを検索します (#6122)。
  • My Work は、呼び出しごとに 1 回、来歴レコード (#6148)、フォーカス要求メンバーシップ (#6155)、および作業状態アイテムのバージョン (#6159) にインデックスを付けます。

ドキュメント

  • Cline CLI および Kilo CLI ガイド、stdio MCP サーバーを介して思い出を保存および検索するためのガイド (#6097、#6114、ありがとう @Kirat0201)。ドキュメント: https://docs.claude-mem.ai/cline および https://docs.claude-mem.ai/kilo
  • バンドルされたスキルは常にマーカーと必須マーカーをドロップします (#6183、@jcole666 に感謝、#6144 は @scu-lixiao によって報告されました)。
  • CMEM Pro エンドポイント仕様では、フック取り込み用の write:memory OAuth スコープを定義しています (#6099)。

CI とテスト

  • Windows ジョブ (#6092) とメディア ランタイム ワークフロー (#6178) は、残りの CI と同様に Bun 1.4.4 を固定します (@DeryFerd に感謝)。
  • ワークビュースイートは、共有再試行ヘルパーを使用して一時フォルダーを削除します (#6094)。 Windows レーンは両方の Python スイートを実行し、Hermes スイートは修復されました (#6095) (@DeryFerd に感謝)。
  • テストで OpenCode 2.0 イベント名が固定されるため、名前が変更されたアップストリーム イベントが大規模に失敗します (#6102)。
