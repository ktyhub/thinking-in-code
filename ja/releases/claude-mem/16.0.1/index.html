claude-mem v16.0.1

パッチ 公開日2026年11月19日 出典thedotmack/claude-mem 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロード・メム v16.0.1

重要な修正

  • claude-mem の実行中に、Windows で Codex へのサインインが再び機能します (#6332、感謝 @ffe111、クローズ #6331)。 claude-mem のアプリサーバーが使用するプライベート Codex ホームは、実際の ~/.codex/auth.json へのハード リンクを通じて auth.json を取得しました。 Codex は、資格情報ファイルを複数のハード リンク (persist_failed: atomic credential replacement does not support hard-linked files) で置き換えることを拒否するため、ホームが存在する限り、codex login とトークンの更新は失敗します。個人の家はシンボリックリンクを取得し、Codex はそれをたどります。 Windows 上でのみ、シンボリックリンクが許可されていない場合 (開発者モードまたは昇格なし) に限り、代わりにプライベート コピーが取得されます。他のエラーは依然として大音量で失敗します。
  • <skip_summary/> で応答されたプローブはクォータ クールダウンを終了します (#6324、ありがとう @vaibhav375、クローズ #6322)。クォータに達した後、ワーカーはプロバイダーをプローブし、プローブがメモリを保存するとクールダウンをクリアします。プロバイダーが有効な <skip_summary/> で応答したプローブには何も保存されないため、クールダウンはクリアされず、そのセッションがスキップされただけである限り、ワーカーは 5 分ごとに再プローブしました。有効なスキップにより、メモリ セッション ID が判明する前にストア パスと初期パスの両方でクールダウンも解除されるようになりました。オブザーバーヘルスの成功には、依然として実店舗が必要です。

修正

  • Chroma が遅い場合、検索は失敗せず SQLite にフォールバックします (#6327、感謝 @REI-330、クローズ #6323)。 MCP client では検索に 30 秒かかりますが、Chroma の各読み取りは最大 60 秒待機するため、呼び出し元が諦めて SQLite/FTS5 フォールバックが実行されなかったときでも、遅いクエリが実行されていました。検索では、Chroma 読み取り全体で 1 つの 20 秒のバジェットが共有され、それがなくなると正常な Chroma-mcp を再起動せずにフォールバックするようになりました。
  • Chroma のリビルドは何時間もコアを保持しなくなりました (#6299、ありがとう @srieteja)。完全なバックフィルは、各行の書き込み時間の CLAUDE_MEM_CHROMA_BACKFILL_PAUSE_RATIO (デフォルトは 1、0 でオフ) の後に一時停止し、chroma-mcp は Windows の外部では nice (CLAUDE_MEM_CHROMA_PROCESS_NICE、デフォルトは 10) で開始されます。ライブ同期は変更されません。
  • Windows プロセスのクリーンアップは taskkill を正しく読み取ります (#6328、ありがとう @REI-330; #6307)。 taskkill exit 255 は、その文言ではなく、指定されたプロセスがまだ生きているかどうかによって判断されるようになりました。そのため、Chroma のティアダウン中にローカライズされたメッセージがスローされなくなり、プロセスの実行中に混合メッセージが成功を報告しなくなりました。
  • オブザーバーは SQLite ステートメントのリークを停止します (#6306)。オブザーバー ターンを保存するステートメントは、ターンごとに準備されるのではなくキャッシュされるため、SQLite がメモリを使い果たし、ターン全体がロールバックされるまで蓄積される可能性があります。
  • ログイン通知には、オブザーバーがクロード コード ログインを持たない場合に使用できることが記載されています (#6321、refs #6319)。端末が別の資格情報プロファイルにサインインしているときに、/login を実行するように指示する代わりに、ワーカーは、その理由と、ログイン時に読み取った通知名を含む警告をログに記録し、claude setup-token を提案します。
  • 従来の claude-mem シェル エイリアスは、インストールと更新時に検出され、削除されます (#6300、ありがとう @0xABCD01)。 doctor はそれを報告し、ワーカーが解決されたプラグイン ルートの外で実行されると status が警告し、複数行のエイリアスは警告とともにそのまま残され、再インストールをキャンセルしても何も変更されません。
  • /api/health はプローブの状態のみを公開します (#6309、ありがとう @DeryFerd)。認証方法、Redis キュー記述子、絶対インストール パス、または認証されていない呼び出し元との最後の対話は表示されなくなりました。
  • 読み取り不能なマイワーク更新ステータスによってセットアップが中断されることはなくなりました (#6305)。損傷した refresh.json は動作なしと表示され、交換されます。自動アップデーターは依然としてビジーとして扱います。
  • マシンのファイル記述子がなくなると、ローカル作業は一時停止したままになります (#6303)。セットアップ チェックでは、EMFILE/ENFILE が「セットアップがまだアクティブ」として扱われ、エピソードごとに 1 つの警告がログに記録されます。
  • タイムライン ファイルのラベルはどのプラットフォームでも同じに見えます (#6301、ありがとう @POWDER-RANGER)。
  • マイ ワーク フォーカス カードの任意の場所を押すと、そのエリアが開きます (#6315)。同じ修正は、リスト、チーム、エージェント別の行にも適用されます。

新しい

  • Devin クラウド セッションと Devin ボット (#6334)。組織は、plugin/ を Devin プラグインとしてインストールし、すべてのセッションでフック、MCP 検索、およびスキルを取得できます。
  • OpenCode で私の作業を更新 (#6330、ありがとう @REI-330)。 CLAUDE_MEM_WORK_VIEW_AGENT=opencode でオプトインします。そうでなければ何も変わりません。
  • PostgreSQL 検索では、CJK、かな、およびハングル テキスト内の用語が検索されます (#6329、感謝 @REI-330、参照番号 #3982)。
  • 私のワーク カードのタイトルでは、質問の最初の文をコピーするのではなく、5 ～ 7 語でタスクに名前を付けます (#6317)。
  • 画像ビューアが背後のページを暗くしてぼかし、影を落とします (#6313)。
  • インストーラーは、GUI セットアップの前に、仕事用電子メールとターミナル内のメッセージを要求します (#6308)。

テストとドキュメント

  • Grok Bot と Zed のテストは Windows で合格しました (#6311、#6312、ありがとう @Lupin133)。
  • コミュニティ スイープ ワークツリーは bun install (#6325) でインストールされます。
