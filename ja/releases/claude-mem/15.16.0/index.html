claude-mem v15.16.0

マイナー 公開日2026年11月11日 出典thedotmack/claude-mem 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロード・メム v15.16.0

新しい

  • API プロバイダーでのマイ ワークの更新 (オプトイン): すでに選択したプロバイダー (openrouter、openai-compatible、または従来の cmem スペル) でマイ ワークの更新を実行するには、CLAUDE_MEM_WORK_VIEW_AGENT=api を設定します。 Claude Code、Codex、または Gemini CLI がログインしていないインストール (OpenCode または DSH ホストなど) で、My Work を使用できるようになりました。 API プロバイダーを選択し、設定を空にすると、更新はログインしたクロード コードにフォールバックしなくなりました。エージェントを選択するまでエージェントは実行されず、何も消費されません (#5674、ありがとう @bulanovk)。
  • 私の作品の GitHub MCP プル リクエスト: GitHub の公式 MCP create_pull_request ツールを通じて作成されたプル リクエストが、私の作品製品として表示されるようになりました。 URL が要求されたリポジトリと一致する完了した結果のみが受け入れられます (#5809、ありがとう @Afloat16)。
  • UberLLM プリセット: uberllm は、openai-compatible プロバイダー (https://api.uberllm.dev/v1、デフォルト モデル deepseek/deepseek-v4.1-flash) のプリセットになりました (#5706、@PSA-Team-source に感謝)。
  • 調整可能なライブ ハンドオフ タイムアウト: CLAUDE_MEM_HOOK_HANDOFF_TIMEOUT_MS (デフォルト 250) は、フックからワーカーへの単一のライブ ハンドオフのバジェットを設定し、失敗したハンドオフは DEBUG ではなく WARN に記録されるようになりました (#5831、感謝 @mohitdixit02)。

注目すべき修正

  • プラグイン キャッシュのクリーンアップ: ワーカーは、Claude Code のマーケットプレイスの更新によって ~/.claude/plugins/cache/thedotmack/claude-mem/ に残された古いバージョンのフォルダーを削除するようになりました (1 つのレポート: 21 バージョン、約 16 GB)。実行中のコピーと登録されたバージョンを保持し、ブートが安定した後、その後 1 時間ごとにスイープします (#5685、ありがとう @MaxWang007)。
  • Windows ウイルス対策ノイズ: ランチャー フォルダーが既に PATH 上にある場合、インストール、アップデート、およびランチャーの再構築で非表示の PowerShell が開始されなくなりました。これは、Kaspersky がフラグを立てたパターン (#5835、@Ali-Sabri-0 によって報告) です。
  • My Work language: CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE が空の場合、すべての更新ステップでシステム ロケールの言語が書き込まれるため、1 回の実行で言語が混在することはなくなりました (#5669、ありがとう @0xABCD01)。
  • My Work アイドル コスト: アイドル ポーリングは、同期されたすべての行を再スキャンしなくなり、ライブ オーバービュー、フォーカス エリアの結合、および重いパネルの更新ごとの作業量が減りました (#5834)。
  • バックアップ: declined バックアップ実行は失敗を返し、保存されたバックアップは保持エラーとは別に報告され、タイマー制限を超えたバックアップ間隔は尊重され、ワー​​カー テーブルが欠落しているスタンプ付きスナップショットの復元は拒否されます (#5750、#5781、#5784、#5684、ありがとう @Kirat0201)。
  • シェルのセットアップ: ランチャーの PATH ブロックと従来のアンインストール エイリアスはアトミックに書き込まれ、Cowork はホストが設定すると $HOME の下にスプールされたイベントをステージングし、Hermes は永続的な HTTP client エラーをサーキット ブレーカーから遠ざけます (#5680、#5679、#5677、#5678、ありがとう @DeryFerd)。
  • OpenCode: bash ツールは Bash として報告されるため、SKIP_BASH_PATTERNS が適用されます (#5668、ありがとう @ryrenz)。
  • 同期: 削除が再試行された後の Chroma クリーンアップの失敗 (#5673、ありがとう @Zhong-fan)。
  • SessionStart: キャッシュの読み取りと作成のステップは 1 つのボディ バジェットを共有するため、キャッシュされたボディは適合する場合にのみ提供されます (#5686、ありがとう @Varshith-Kali)。

さらに修正

@Afloat16 による、キャプチャ、同期、検索、コンテキスト、インポート、トランスクリプト、メディア、サーバー、Codex、OpenCode、OpenClaw、Hermes、Grok、Kimi、Gemini、Pi、Goose、Notion、Telegram 統合にわたる約 130 件の小規模な修正。ハイライト:

  • 検索とコンテキスト: リテラルのプロジェクト キーとファイル パスは、呼び出し、マージ、キャッシュを通じて保存されます。 Unicode と結合マークは、クエリ語とスニペットの制限に影響を受けません。キャッシュされたコンテキストは、復元と行置換後に期限切れになります。最大の適合タイムライン接頭辞が保持されます。
  • 同期とメモリ: セッション タイトルは送信ボックスの変更をコミットし、受信者の編集を取得します。手動保存と新しいプロンプトはセッションの削除後に機能します。ノートのリビジョンはタイトルの重複を除いて残ります。
  • トランスクリプトとインポート: マルチパート Codex メッセージ、ペアになったパッチ結果、および zstd フレーム シームが正しく読み取られます。推論は最終的な答えにはなりません。 OpenCode、Gemini、および復元されたサマリーは、重複したりプロンプトが失われたりすることなくインポートされます。
  • サーバーとプロバイダー: API キーの導出は要求ループから外されます。キャンセルは再試行と圧縮を通じて伝播します。スプリット トークンの使用量は、互換性のある応答に応じて計測されます。メモリ内容は保存前にサニタイズされます。
  • メディア: 画像の序数、パスのスペルを超えた読み取り証拠、および宣伝された画像の寸法境界は保持されます。インライン許可は、受け入れられた画像に対してのみ課金されます。

@Kirat0201 からも: ファイル履歴はプロジェクト全体のマージに従い、インタラクティブなタイムライン検索はプロジェクト リストを尊重し、統合検索はリテラルの filePath 値 (#5789、#5787、#5785) を保持します。
