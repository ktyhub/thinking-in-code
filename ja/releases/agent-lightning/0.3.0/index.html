agent-lightning v0.3.0

マイナー 公開日2025年12月24日 出典microsoft/agent-lightning 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

エージェントライトニング v0.3.0

Agent-lightning v0.3.0 は、いくつかの新機能とバグ修正を導入するメジャー リリースです。このリリースは、Agent-lightning コア チームとコミュニティとの共同作業です。このリリースを可能にしたすべての貢献者に感謝します。

ハイライト

  • Tinker の統合: 強化学習の代替バックエンドとして Tinker をサポートします (#226 #245 #264 #269 #327)。 コード例、ブログ 1、ブログ 2 を参照してください。
  • Azure OpenAI の統合: LLM 推論および監視付き微調整のバックエンドとして Azure OpenAI をサポートします (#256 #327)。 コード例。
  • MongoDB ベースの Lightning ストア が、Lightning ストアの代替バックエンドとして追加されました (#323)。 ドキュメント。
  • Contrib パッケージ: コミュニティ プロジェクト用の contrib パッケージを追加します。 Search-R1 は投稿レシピとして統合されています。さらに登場します。 (#239 #396 #410 #412 #417)。
  • RESTful API: Lightning ストア用の RESTful API を安定化および文書化します (#241 #275)。 ドキュメント。
  • OTel セマンティック規則。エージェント最適化領域向けに特別に設計されています (#340)。 ドキュメント。
  • [プレビュー] エージェント ライトニング ダッシュボード が利用可能になりました (#288 #289 #291 #296 #371 #375)。これは、Agent-lightning 実験を検査およびデバッグするための公式 Web アプリケーションです。詳細は【こちら】(https://microsoft.github.io/agent-lightning/0.3.0/tutorials/debug/)をご確認ください。
  • [プレビュー] マルチモダリティの例は、ChartQA データセット (#379) 上の VERL と LangGraph エージェントを特徴としています。 コード例。
  • [プレビュー] Claude Code を LitAgent として統合し、SWE-Bench でのトレーニングをサポートします (#332 #346 #348)。 コード例。
  • [プレビュー] Weave トレーサー を AgentOps トレーサー (#277 #411 #420 #423) の代替として使用します。 ドキュメント。
  • [プレビュー] 軌跡レベル集約 により、VERL を使用したより効率的なトレーニングが可能になります。 ブログ および ドキュメント を参照してください。

ストアのベンチマーク

このリリースでは、Lightning Store コアが再設計され、効率とスケーラビリティが大幅に向上しました (#315 #318 #328 #342 #344 #356 #380 #388 #418 #421)。以下のベンチマーク結果はその影響を示しています。多数の同時実行ランナーを使用すると、v0.3.0 は v0.2.2 と比較して最大 15 倍のスループット向上を実現します。

|スループット (#rollout/秒) | v0.2.2 | v0.3.0 (メモリ内) | v0.3.0 (モンゴ) | | :---- | :---- | :---- | :---- | |最小 (バッチ、#runner=32、#turns=6) | 8.73 | 9.06 | 8.71 | |中 (バッチ、#runners=100、#turns=10) | 12.03 | 23.26 | 32.79 | |中～高 (バッチ、#runners=300、#turns=6) | 10.61 | 24.42 | 40.24 | |大 (バッチ、#runners=1000、#turns=3) | 3.36 | 14.60 | 50.05 | |長いキュー (キュー、#runners=256、#turns=4) | 7.42 | 30.86 | 57.01 | |ヘビー トレース (キュー、#runners=512、#turns=20) | 5.93 | 13.28 | 29.41 |

注意:

  1. ベンチマークは、GitHub アクションを介して単一の Standard_D32as_v4 Azure VM (大規模で大量のトレース テストには Standard_D64ads_v5 を使用) で実行されました。
  2. 2 つのアルゴリズム パターンが評価されます。バッチ パターンはロールアウトのグループを送信し、すべてが終了するのを待ってから次のグループを開始します。一方、キュー パターンは実行中のロールアウトの設定数を維持し、容量が解放されたらすぐに新しいロールアウトを送信します。構成の詳細については、こちら をご覧ください。
  3. ターン数は、各ロールアウトが生成するスパンの数に正比例します。

メンテナンスとバグ修正

コア (ストア、インターフェイスなど)

  • client-server 戦略用のトレーナー ポート オプションを追加 (#198)
  • ストアポートの競合処理を修正 (#227)
  • 統合 PythonServerLauncher (#286 #292 #303)
  • ヘルスタイムアウトを構成可能にする (#305)
  • ログのリファクタリング (#306)
  • LightningStore で OTLP をサポート (#313)
  • 一元化されたメトリクスヘルパー (#368)
  • Ctrl+C での冗長なキャンセル トレースバックを修正 (#370)

プロキシ、アダプター、アルゴリズム

  • VERL での処理前後のトレーニング メトリクスを修正 (#145)
  • Anthropic および OpenAI API のストリーミング リクエストを (非ストリーミング リクエストとして) 転送する (#299)
  • VERL の報酬を含むトレースを確認する (#317)
  • LiteLLM ルート スパン (#341) にパッチを適用します。
  • LoRA 互換性のための ref_in_actor フラグの処理 (#386)
  • アルゴリズムで with_llm_proxy および with_store をサポート (#398)
  • TracerTraceToTriplets で画像 URL エクスポートをサポート (#400)
  • TraceTree の match_rewards assign_to 要素を修正 (#403)
  • VERL でのトレーナーとデーモンのカスタマイズをサポート (#407)

ランナー、トレーサー、エージェント

  • トレーサーの初期化をリファクタリング (#321)
  • OpenAI エージェント 0.6 の互換性を修正 (#322)
  • emit_operation、emit_annotation、タグとリンク (#359)
  • サンセット HTTP トレーサー (#402)

例

  • train-first-agent.md のタイプミスを修正 (#263)
  • 常に最初のタスクを実行する room_selector の例を修正 (#270)
  • SQL エージェントの例のタイプミスを修正 (#285)
  • NPU で SQL エージェントをトレーニングするための README とスクリプト ファイルを追加 (#272)
  • カタログおよびリファイン貢献ガイドの例 (#331)
  • LangChain を 1.x にアップグレードします (#364)
  • RAG の例を Agent-lightning v0.2.x (#349) に更新

その他

  • DeepWiki バッジ (#263)
  • AGENTS.md を追加 (#374)
