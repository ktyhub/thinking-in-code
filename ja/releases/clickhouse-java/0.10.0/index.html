#clickhouse-java v0.10.0

リリース移行ガイド

重大な変更

  • [jdbc-v2] ドライバーは、すべての JDBC でサーバー設定 async_insert=0 および wait_end_of_query=0 をハードコードしなくなりました。 接続。これにより、以前は機能しなかった 2 つのシナリオのブロックが解除されます。接続ごとまたは接続ごとにこれらの設定を上書きするというものです。 ステートメントを使用し、SETTINGS のオーバーライドを禁止する読み取り専用プロファイルに対してドライバーを使用します。次の 2 つの結果があります。

    • ドライバーは、これらの設定のサーバー側のデフォルトに従います (注: ClickHouse 26.3、async_insert から始まる) デフォルトは 1 です)。明示的な wait_end_of_query=0 を削除することはサーバーのデフォルトに対して何も行われませんが、ユーザーはオプトインできます。 wait_end_of_query=1。
    • java.sql.Statement.executeUpdate(java.lang.String) (および一致する PreparedStatement によって返される行数) メソッド) は、サーバーが INSERT ステートメントを非同期で実行する場合、そのステートメントの正確性が保証されなくなりました。 INSERT 本文の解析/データ エラーは、SQLException として同期的に発生しない可能性があります。以前はこれらは 挿入は強制的に同期されるため、正確です (https://github.com/ClickHouse/ClickHouse/issues/57768 も参照)。 以前の動作を復元するには、サーバー設定として接続ごとに async_insert=0 (または wait_for_async_insert=1) を設定します。 非同期挿入の詳細: https://clickhouse.com/docs/optimize/asynchronous-inserts.

    (https://github.com/ClickHouse/clickhouse-java/issues/2652, https://github.com/ClickHouse/clickhouse-java/issues/2825)

  • [client-v2] Client.Builder#build() は、代わりに ClientMisconfigurationException をスローするようになりました。 IllegalArgumentException 認証および SSL 構成ミス (資格情報の欠落、競合) 認証方法、SSL 認証が有効な場合に client 証明書が欠落している、および trust ストアが一緒に使用されている client 証明書付き)。これらのケースで build() から IllegalArgumentException をキャッチすることに依存した発信者 ClientMisconfigurationException (ClientException を介して RuntimeException を拡張) をキャッチする必要があります。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] setUsername(...) + setPassword(...) とカスタム Authorization HTTP ヘッダーの組み合わせ ( httpHeader(HttpHeaders.AUTHORIZATION, ...)) は Client.Builder#build() で失敗するようになりました。 ClientMisconfigurationException (HTTP 基本認証が明示的に無効になっていない限り) useHTTPBasicAuth(false)。以前は、この組み合わせが受け入れられ、カスタム Authorization ヘッダーがオーバーライドされました。 リクエスト時のユーザー/パスワード。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] access_token 構成プロパティ (Client.Builder#setAccessToken(String) 経由または直接設定) setOption を通じて) が、実際に Authorization HTTP ヘッダー値として送信リクエストにそのまま適用されるようになりました。 以前は、値は access_token に保存されていましたが、回線上で送信されることはなかったので、値を単独で指定しても効果はありませんでした。 認証について。呼び出し元はスキーム プレフィックス自体 (例: setAccessToken("Bearer <token>")) を含める必要があります。または、次を使用する必要があります。 Bearer の先頭に自動的に付加される useBearerTokenAuth(String)。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client.Builder#useBearerTokenAuth(String) はベアラー トークンを access_token の下に保存するようになりました。 構成キーを http_header_authorization に直接書き込む代わりに、(Bearer プレフィックスを付けて) 構成キーを使用します。の HTTP ワイヤー形式は変更されていませんが、トークンは Client#getReadOnlyConfig() を通じて監視できなくなりました。 http_header_authorizationキー。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client コンポーネントでの executionTimeout パラメーターの矛盾した使用を修正しました。タイムアウトは 以前はミリ秒単位で設定されていましたが、一部の場所で誤って秒単位で取得されて使用されました。今では正しく使用されています 一貫してミリ秒単位。 (https://github.com/ClickHouse/clickhouse-java/issues/2358)

  • [client-v2] パブリック ClickHouseBinaryFormatWriter インターフェイスには、生の String/FixedString バイトを書き込むための 2 つのメソッド setString(String, byte[]) と setString(int, byte[]) が追加されました。インターフェイスを「使用」するだけのコードは影響を受けませんが、ClickHouseBinaryFormatWriter を直接「実装」するサードパーティは、これらのメソッドを追加するまでソースおよびバイナリ互換性がありません (新しいバージョンに対して再コンパイルする必要があります。そうしないと実行時に AbstractMethodError が発生する可能性があります)。

  • [client-v2] HTTP 503 Service Unavailable 応答が接続スタイルの失敗として表示されるようになりました ( java.net.ConnectException) であり、デフォルトで再試行されます。以前は、503 はサーバー エラーとして扱われていました ( ServerException) であり、ServerRetryable 障害原因に該当しました。 ConnectTimeout 障害に移動されました 接続/可用性エラーが他の接続エラーと同様に処理されるように、原因カテゴリを設定します。発信者 503 の再試行を避けるために特に ServerRetryable を除外した場合は、その値を調整する必要があります。 代わりに ConnectTimeout を除外する client_retry_on_failures 構成。

  • [client-v2] 予期しない/不明な HTTP ステータス コード (client が ClickHouse 応答として解釈できないもの) が発生するようになりました ServerException の代わりに ClientException をスローします。 client はこれらの応答を有効に処理できないため、 これらはサーバーに起因するものではなく、client 側のエラーとして報告されます。

新機能

  • [jdbc-v2、client-v2] SSL モード構成を実装しました。 ssl_mode から DISABLED を設定できるようになりました。 TRUST、VERIFY_CA、STRICT。 V1 ユーザー向けの注意: NONE は JDBC ドライバーによってのみサポートされ、TRUST にマップされます。 新しい名前に移行してください。

    • client-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/client-v2/src/main/java/com/clickhouse/examples/client_v2/SSLExamples.java の例
    • jdbc-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/jdbc/src/main/java/com/clickhouse/examples/jdbc/SSLExamples.java の例 (https://github.com/ClickHouse/clickhouse-java/pull/2874, https://github.com/ClickHouse/clickhouse-java/issues/2389, https://github.com/ClickHouse/clickhouse-java/issues/2309, https://github.com/ClickHouse/clickhouse-java/issues/2819)

  • [jdbc-v2、client-v2] (ベータ版) JSONEachRow 用のスタンドアロン リーダーを実装して、 この形式を読んでいます。さらに、JDBC ドライバーを使用して Json 列をカスタム タイプにマップする方法も提供されます。例を見る https://github.com/ClickHouse/clickhouse-java/tree/main/examples/jdbc-v2-json-processors および https://github.com/ClickHouse/clickhouse-java/tree/main/examples/client-v2-json-processors. では (https://github.com/ClickHouse/clickhouse-java/pull/2871)

  • [client-v2] ClickHouse セッション設定をカプセル化して管理するための Session API を追加しました (session_id、 session_check、session_timeout、session_timezone) を再利用可能なオブジェクトとして使用します。 Session インスタンスは以下に適用できます。 applyTo() を使用してリクエスト設定を行い、clearSession() を使用してセッション状態をクリアできます。さらに、追加された resetOption(String) から InsertSettings、QuerySettings、および CommonSettings を使用して、特定の設定を削除できます。 明示的に null に設定された設定はサーバーに送信されません。これは、グローバル設定を上書きする場合に役立ちます。 (https://github.com/ClickHouse/clickhouse-java/pull/2810)

  • [client-v2] Client にランタイム資格情報更新 API を追加しました: updateUserAndPassword(String, String)、 updateAccessToken(String)、updateBearerToken(String)。同じ Client インスタンスに対する後続のリクエストでは、 client を再構築せずに新しい認証情報を使用します。認証方法は構築時に固定されます。に電話をかける 構成されたメソッドと一致しないランタイム アップデーターは ClientMisconfigurationException をスローします。参照 詳細と移行ガイダンスについては、docs/authentication.md を参照してください。 (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [jdbc-v2] KILL QUERY のようなステートメントのターゲット クラスターを指定するための cluster_name 構成プロパティを追加しました。 すべてに対して実行するには ON CLUSTER 句が必要です ノード。 (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [client-v2、jdbc-v2] ClickHouse 25.11+ の ClickHouse Geometry タイプのサポートを追加しました。ここで、Geometry String エイリアスから Variant(Point, Ring, LineString, MultiLineString, Polygon, MultiPolygon) (client) に変更されました 古いバージョンとも互換性があります)。 client 読み取り/書き込み処理と、取得および取得のための JDBC タイプ マッピングが含まれています。 ジオメトリ値を挿入しています。現在の書き込みでは、配列のネストの深さからターゲット ジオメトリ バリアントを推測するため、Ring と LineString および Polygon と MultiLineString は、汎用の Geometry 書き込みではまだ区別できません。 パス。 (https://github.com/ClickHouse/clickhouse-java/pull/2815)

  • [jdbc-v2] ResultSet#getObject(int|String, Map<String, Class<?>>) は ClickHouse タイプ名をマップ キーとして受け入れるようになりました JDBC SQLType 名に加えて、常に受け入れられます。ラップされていない型名のみが検索に使用されます。 Nullable(...) および LowCardinality(...) ラッパーは取り除かれ、解像度には影響しないため、"Int32" のようなキー Int32 列と Nullable(Int32) 列の両方に一致します。 "Nullable(Int32)" のようなキーは認識されません。検索順序は ClickHouseDataType 列挙名 (例: "Int32"、"String"、"DateTime")、次に JDBC SQLType 名 (例: "INTEGER"、"VARCHAR"、"TIMESTAMP");エントリが欠落している場合、値は強制されないままになります。この機能がサポートされているのは、 プリミティブ ClickHouse タイプのみ — Array、Tuple、Map、Nested、およびジオメトリ タイプはサポートされていないため続行します ユーザーが指定したマップに関係なく、ネイティブ形式で返されます。 JDBC SQLType のみをキーとする既存のマップ 名前は変更されずに機能し続けます。 (https://github.com/ClickHouse/clickhouse-java/pull/2865)

  • [jdbc-v2] JDBC 型のカスタム マッピングのサポートを追加しました。主に大きな整数を扱う必要がある場合に使用されます。 文字列として提示されます。 DriverProperties.JDBC_TYPE_MAPPINGS (jdbc_type_mappings) を使用し、必要な型マッピングを設定します key=value[,] リストとして (たとえば、Int32=Long,UInt64=String)。非推奨の通知: V1 プロパティ typeMappings は サポートされていますが、削除される予定です。新しいプロパティに移行してください。 (https://github.com/ClickHouse/clickhouse-java/issues/2858)

  • [client-v2、jdbc-v2] binary_string_support 構成プロパティを通じてオプトイン バイナリ文字列のサポートを追加しました (または Client.Builder#binaryStringSupport(boolean))、デフォルトでは無効になっています。設定は操作ごとに解決されます。 client とクエリ設定が統合されているため、binary_string_support を介して単一のリクエストに対してオーバーライドできます。 動作オプション (例: QuerySettings#setOption(ClientConfigProperties.BINARY_STRING_SUPPORT.getKey(), true)) client レベルのデフォルトとは独立しています。有効にすると、トップレベルの String 列と FixedString 列が読み取られます。 生のバイトを String にデコードするのではなく保持する StringValue に変換し、非 UTF-8/バイナリを許可します。 コンテンツをバイトごとに往復します。 StringValue は toByteArray()/asByteBuffer() 経由でバイトを公開し、 asString() (デフォルトでは UTF-8、または呼び出し元が指定した Charset) を介して String を遅延デコードします。内部にネストされた値 コンテナー (Array、Map、Tuple、Nested、Variant) は、これらのタイプではないため、引き続き String として読み取られます。 大きな文字列/バイナリ文字列を運ぶことが期待されます。 JDBC 側では、ResultSet#getBinaryStream(int) と ResultSet#getBinaryStream(String) が実装されました (以前はサポートされていませんでした)。getBytes(...) と合わせて、 生の列バイトを返します。

  • [client-v2] まだ実行中のリクエストをキャンセルするための Client#cancelTransportRequest(String queryId) を追加しました。 操作設定で指定されたクエリ ID によって識別される、サーバーからの応答を受信しました。これにより、 client 側でのリクエスト (基礎となる IO 操作のキャンセル) が、サーバー上で KILL QUERY を発行しません**。 そのため、すでに実行を開始したクエリはサーバー側で引き続き実行される可能性があります。操作タイムアウトを使用することをお勧めします 可能な場合は設定。この API は、client からの要求を明示的に中止することを目的としています。

改善点

  • [jdbc-v2, client-v2] アンダースコア (_) を含むホスト名のサポートを追加しました。エンドポイントを指定できるようになりました ch_db_01のような。これは主に k8s 環境で使用されます。 (https://github.com/ClickHouse/clickhouse-java/issues/2792, https://github.com/ClickHouse/clickhouse-java/issues/2753)

依存関係を更新しました

  • [テスト] org.postgresql:postgresql を 42.6.1 から 42.7.11 にバンプします

ドキュメントと例

  • [client-v2] client を使用して Apache Arrow ライブラリを操作する例を追加しました。 (https://github.com/ClickHouse/clickhouse-java/pull/2820)

  • [レポ] 投稿ガイドを追加しました。ご確認の上、フィードバックをお送りください。 (https://github.com/ClickHouse/clickhouse-java/pull/2859)

バグ修正

  • [jdbc-v2, client-v2] 404 応答など、ClickHouse エラーではない応答のエラー処理を修正しました。 (https://github.com/ClickHouse/clickhouse-java/issues/2803)

  • [jdbc-v2, client-v2] パスワードとして null を設定するように修正しました。以前は、null リテラルに変換されました。それでもお勧めします 空の文字列を渡します。 (https://github.com/ClickHouse/clickhouse-java/pull/2809)

  • [jdbc-v2, client-v2] ClickHouseBinaryFormatReader::getBigDecimal が大きな整数をサイレントに切り捨てる問題を修正しました。 (https://github.com/ClickHouse/clickhouse-java/issues/2748)

  • [jdbc-v2、client-v2] NULL 値の Variant および Dynamic 列への処理を修正しました。以前のインジケーター NULL の設定および読み取りが行われませんでした。 (https://github.com/ClickHouse/clickhouse-java/issues/2789, https://github.com/ClickHouse/clickhouse-java/issues/2791)

  • [jdbc-v2] ステートメントが内部で実行されているときに Statement.cancel() が SESSION_IS_LOCKED をスローする問題を修正しました。 ClickHouseセッション。ドライバーは、session_id、session_check、および session_timeout をファーストクラスとして受け入れるようになりました。 接続プロパティを変更し、キャンセル中に KILL QUERY を発行するときに接続プロパティを正しく抑制します。これにより、 キャンセルリクエストはセッション外で実行され、セッションで実行中のクエリと競合しなくなりました。 ロック。 (https://github.com/ClickHouse/clickhouse-java/issues/2690, https://github.com/ClickHouse/clickhouse-java/issues/2881)

  • [jdbc-v2] クラスター上での操作にクラスター名を指定するオプションを追加しました。そのうちの 1 つは KILL QUERY .. ON CLUSTER <cluster_name> です。 DriverProperties.CLUSTER_NAME (jdbc_cluster_name) を使用して、このようなクエリで使用されるクラスターの名前を定義します。 (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [jdbc-v2, client-v2] ネストされた Tuple および `Map 値に対する null 許容マーカーの書き込みを修正しました。 (https://github.com/ClickHouse/clickhouse-java/issues/2721)

  • [jdbc-v2] String/FixedString の内部 StringValue ホルダーから漏れる ResultSet.getObject を修正しました binary_string_support が有効な場合の列。 getObject(column, byte[].class) は正確な生のバイトを返すようになりました。 および getObject(column, Object.class) と型なしの getObject(column) オーバーロードはデコードされた String を返すようになりました。 内部ホルダーの代わりに。
