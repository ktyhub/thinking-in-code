#コップv1.37.0

重大な変更や非推奨を含む詳細については、完全な kOps 1.37 release notes を参照してください。

ハイライト

  • Kubernetes 1.37 のサポート、Kubernetes 1.37 クラスターのデフォルトとして etcd 3.7.3 を使用
  • クラウド オブジェクト ストレージ内のプライベート アセット リポジトリ: KOPS_BASE_URL および spec.assets.fileRepository の s3://、gs://、および azureblob:// URL (インスタンス ID を通じて認証されるノードを含む)
  • より小型で回復力の高いノード ブートストラップ: より小さいバイナリ圧縮と xz 圧縮により、ノードアップのダウンロードは約 120 MB から 10 MB 未満に減少し、ブートストラップは失敗したタスクを再試行します
  • コンテナ ランタイム: デフォルトでは、containerd 2.3.6 および runc 1.5.1 (containerd 構成バージョン 4)。 2.1.0 より古いバージョンのcontainerdはサポートされなくなりました
  • Karpenter の拡張: Karpenter v1.15.1、kOps 管理の割り込み処理 (SQS キューと EventBridge ルール)、EC2NodeClass のルート ボリューム設定、instanceRequirements のサポート、および GPU と非 GPU の混合インスタンス グループ
  • インスタンス ロール (Route 53、KMS、EC2、SQS) に対するより狭い AWS IAM 権限、権限を必要としないロールに対するインライン ポリシーなし
  • etcd-manager の変更: イメージ ボリュームとしてマウントされたバンドルされた etcd イメージ、および新しいクラスター上のユーザー指定のイメージからのカスタム etcd バージョンのサポート
  • ネットワーク: ClusterNetworkPolicy への移行を伴う Calico v3.32.3、AWS VPC CNI のネットワーク ポリシー サポート、実験的な nftables ネットワーク ポリシー バックエンドを備えた kube-router v2.12.0、および kindnet v1.0.3
  • Azure: 署名されたインスタンス メタデータ、古い VM の kops rolling-update cluster 検出、および高可用性コントロール プレーン上の 2 つのクラウド コントローラー マネージャー レプリカで認証されたブートストラップ リクエスト
  • Akamai (Linode): 実験的プロバイダーが SSH キー、ネットワーク、サブネット、インスタンス、ブロックストレージ ボリュームを管理するようになりました。
  • コンポーネントの更新: etcd-manager v3.0.20261022 (etcd 3.5.35/3.6.16/3.7.3 付き)、Cilium v1.18.16、AWS VPC CNI v1.23.2、CoreDNS v1.15.0、AWS Load Balancer Controller v3.6.2、cert-manager v1.21.3、cluster-autoscaler v1.37.0
  • 削除: Kubernetes 1.31、ゴシップ DNS (および protokube)、API 用の AWS クラシック ロード バランサー、および Kopeio ネットワーキングのサポート。アップグレード前に kOps 1.36 を使用して移行する
