#ドルイドドルイド-28.0.0

Apache Druid 28.0.0 には、420 を超える新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 57 人の寄稿者による追加のテスト カバレッジが含まれています。

バグ修正などの詳細については、完全な変更セット を参照してください。

Druid 28.0.0 にアップグレードする前に、アップグレードに関する注意事項 と 互換性のない変更 を確認してください。

<a name="28.0.0-important-changes-and-deprecations" href="#28.0.0-important-changes-and-deprecations">#</a> 重要な機能、変更点、非推奨

Druid 28.0.0 では、システムの ANSI SQL 互換性を高めるためにクエリに大幅な改善を加えました。これには、NULL 値とブール値、およびブール ロジックの処理の変更が含まれます。同時に、Apache Calcite ライブラリが最新バージョンにアップグレードされました。既知のクエリ動作の変更点を文書化していますが、アップグレード ノート セクションを注意深くお読みください。広範な運用シナリオに展開する前に、クエリのステータスを注意深く監視しながらアプリケーションをテストします。

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility" href="#28.0.0-important-changes-and-deprecations-sql-compatibility">#</a> SQL の互換性

Druid は、SQL クエリの実行と標準 SQL の動作の一貫性を高め続けます。ただし、必要に応じて古い動作を復元できる機能フラグがあります。

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic">#</a> 3 値ロジック

次のデフォルト設定が適用される場合、Druid ネイティブ フィルターは、デフォルトで Druid の古典的な 2 状態ロジックではなく、SQL 3 値ロジック (true、false、または unknown) を監視するようになりました。

  • druid.generic.useThreeValueLogicForNativeFilters = true
  • druid.expressions.useStrictBooleans = true
  • druid.generic.useDefaultValueForNull = false

#15058

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans">#</a> 厳密なブール値

druid.expressions.useStrictBooleans がデフォルトで有効になるようになりました。 Druid は、1 (true) または 0 (false) を使用してブール値を厳密に処理するようになりました。 以前は、true と false は、それぞれ true と false、あるいは 1 と 0 として表すことができました。 さらに、Druid は、True && NULL のようなブール比較に対して null 値を返すようになりました。

runtime.properties でこのプロパティを明示的に構成しない場合、クラスターは取り込まれたブール値と、変換およびクエリ時の操作のブール関数の出力に LONG 型を使用するようになります。 詳細については、「アップグレード ノートの SQL 互換性」(#sql-compatibility-1) を参照してください。

#14734

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling">#</a> NULL の処理

druid.generic.useDefaultValueForNull はデフォルトで無効になりました。 Druid は空のレコードと null レコードを区別するようになりました。 以前は、Druid は空のレコードを空または null として扱うことがありました。 詳細については、「アップグレード ノートの SQL 互換性」(#sql-compatibility-1) を参照してください。

#14792

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements">#</a> SQL プランナーの改善

Druid は、SQL の計画と最適化に Apache Calcite を使用します。 Druid 28.0.0 以降、Calcite バージョンは 1.21 から 1.35 にアップグレードされました。このアップグレードでは、Calcite からの SQL 計画における多くのバグ修正が導入されています。

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters">#</a> 動的パラメータ

Calcite アップグレードの一環として、動的パラメーターの型推論の動作が変更されました。型の干渉の問題を回避するには、SQL クエリですべての動的パラメーターを特定のデータ型として明示的に CAST にします。たとえば、次のように使用します。

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

以下のものは使用しないでください。

SELECT (1 * ?)/2 as tmp

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage">#</a> 非同期クエリとディープ ストレージからのクエリ

ディープ ストレージからのクエリ は実験的な機能ではなくなりました。ディープ ストレージからクエリを実行すると、より多くのデータを収容するために履歴サービスを拡張する必要がなく、より多くのデータをクエリに使用できます。ディープ ストレージからのクエリが提供するスペースの節約を活用するには、履歴サービスからデータをアンロードするようにロード ルールを構成します。

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats">#</a> 複数の結果形式のサポート

ディープ ストレージからのクエリで複数の結果形式がサポートされるようになりました。 以前は、/druid/v2/sql/statements/ エンドポイントは object 形式の結果のみをサポートしていました。 resultFormat パラメーターで指定された任意の形式で結果を書き込むことができるようになりました。 Druid SQL API でサポートされる結果パラメータの詳細については、「応答」を参照してください。

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-broadened-access-for-queries-from-deep-storage" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-broadened-access-for-queries-from-deep-storage">#</a> ディープ ストレージからのクエリへのアクセスの拡大

STATE 権限を持つユーザーは、ディープ ストレージからのクエリのステータス API を操作できます。以前は、クエリを送信したユーザーのみがこれらの API を使用できました。これにより、Web コンソールでクエリの実行ステータスを監視できるようになります。 STATE 権限を持つユーザーは、クエリ結果にアクセスできます。

<a name="28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource" href="#28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource">#</a> 複数の Kafka トピックから単一のデータソースに取り込む

単一のスーパーバイザを使用して、複数の Kafka トピックからデータソースにストリーミング データを取り込むことができるようになりました。 IO 設定の topicPattern の値として正規表現パターンを使用して、スーパーバイザ仕様のトピックを設定します。正規表現に一致する新しいトピックを Kafka に追加すると、Druid はそれらの新しいトピックからの取り込みを自動的に開始します。

データソースのマルチトピック取り込みを有効にしている場合、ダウングレードするとスーパーバイザーが失敗します。 詳細については、「ダウングレード前に複数の Kafka トピックから取り込むスーパーバイザーを停止する」(#stop-supervisors-that-ingest-from-multiple-kafka-topics-before-downgrading) を参照してください。

<a name="28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening" href="#28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening">#</a> SQL UNNEST と取り込みフラット化

UNNEST 関数は実験的ではなくなりました。

Druid は、SQL ベースのバッチ取り込みとディープ ストレージからのクエリで UNNEST をサポートするようになり、配列を簡単にフラット化できるようになりました。詳細については、UNNEST および 列内の配列のネスト解除 を参照してください。

UNNEST を使用するためにコンテキスト パラメーター enableUnnest: true を含める必要はなくなりました。

<a name="28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest" href="#28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest">#</a> SQL UNNEST の推奨構文

SQL UNNEST の推奨構文が変更されました。優先順位の問題を防ぐために、ほとんどのクエリではカンマの代わりに CROSS JOIN を使用することをお勧めします。たとえば、次のように使用します。

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

以下のものは使用しないでください。

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

Apache Druid で ウィンドウ関数 を使用すると、行のウィンドウ内の 1 つの行と同じウィンドウ内の他の行の関係に基づいて値を生成できます。ウィンドウは、結果セット内の関連する行のグループです。たとえば、特定のディメンションに対して同じ値を持つ行な​​どです。

enableWindowing: true コンテキスト パラメーターを使用して、クエリ内のウィンドウ関数を有効にします。

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29">#</a> 同時追加と置換 (実験的)

Druid 28.0.0 では、同時追加と置換の実験的サポートが追加されています。 この機能を使用すると、データソースの間隔に新しいデータが追加されている間に、その間隔内の既存のデータを安全に置き換えることができます。これの最も一般的な用途の 1 つは、間隔の圧縮がすでに進行中のときに、その間隔に新しいデータを追加することです。 詳細については、「同時追加と置換」(https://druid.apache.org/docs/latest/data-management/automatic-compaction#concurrent-append-and-replace) を参照してください。

セグメント ロックは非推奨となり、設計がはるかにシンプルな同時追加と置換を優先して削除されます。同時追加と置換により、Druid はアクティブなリアルタイム取り込みにより圧縮ジョブをロックアウトしません。

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs">#</a> 追加および置換バッチ取り込みジョブのタスク ロック

追加バッチ取り込みジョブでロックを共有できるようになりました。これにより、内部に対して複数の追加バッチ取り込みジョブを同時に実行できます。置換バッチ取り込みジョブには引き続き排他ロックが必要です。これは、指定された間隔で複数の追加バッチ取り込みジョブと 1 つの置換バッチ取り込みジョブを実行できることを意味します。

APPEND ロックを使用して Kafka および Kinesis から読み取るストリーミング ジョブは、REPLACE ロックで実行される圧縮と同時に取り込むことができるようになりました。ストリーミング ジョブのセグメント粒度は、同時置換ジョブのセグメント粒度以上である必要があります。

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion">#</a> SQL ベースの取り込み

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types">#</a> ARRAY タイプを取り込む機能

SQL ベースの取り込みでは、ARRAY 型の値を ARRAY 型の列 に格納することと、VARCHAR と数値型の配列の両方を格納することがサポートされるようになりました。 以前は、MSQ タスク エンジンは、ARRAY 型の列ではなく、ARRAY 型の値を 複数値ディメンション として保存していました。

MSQ タスク エンジンには、arrayIngestMode クエリ コンテキスト パラメーターが含まれるようになりました。 ARRAY タイプは Druid セグメントに保存されます。 ARRAY タイプを取り込むには、arrayIngestMode クエリ コンテキスト パラメーターを array に設定します。

Druid 28.0.0 では、下位互換性のため arrayIngestMode のデフォルト モードは mvd であり、VARCHAR 型の配列のみをサポートし、複数値の次元として格納します。このデフォルトは将来のリリースで変更される可能性があります。

新しい動作に移行する方法については、アップグレード ノートの ARRAY 型列の取り込みオプション を参照してください。 ARRAY 型付き列の挿入、フィルタリング、およびグループ化の動作については、「配列列」を参照してください。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-upgrade-druid-segments-table" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-upgrade-druid-segments-table">#</a> Druid セグメントのアップグレード表

Druid 28.0.0 は、テーブルの更新を必要とする新しい列を Druid メタデータ テーブルに追加します。

druid.metadata.storage.connector.createTables が true に設定されており、メタデータ ストア ユーザーが DDL 権限を持っている場合、セグメント テーブルは起動時に自動的に更新され、新しい used_status_last_updated 列が含まれます。アップグレードのために追加の作業は必要ありません。

これらの要件のいずれかが満たされていない場合は、アップグレード前の手順が必要です。 Druid 28.0.0 にアップグレードする前にこれらの更新を行う必要があります。そうしないと、コーディネーターとオーバーロードのプロセスが失敗します。

テーブルを手動で変更して新しい used_status_last_updated 列を追加することもできますが、Druid にはそれを行うための CLI ツールも提供されています。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest">#</a> SQL UNNEST の推奨構文

SQL UNNEST の推奨構文が変更されました。優先順位の問題を防ぐために、ほとんどのクエリではカンマの代わりに CROSS JOIN を使用することをお勧めします。たとえば、次のように使用します。

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

以下のものは使用しないでください。

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters">#</a> 動的パラメータ

Apache Calcite バージョンが 1.21 から 1.35 にアップグレードされました。 Calcite アップグレードの一環として、動的パラメーターの型推論の動作が変更されました。型の干渉の問題を回避するには、SQL クエリですべての動的パラメーターを特定のデータ型として明示的に CAST にします。たとえば、次のように使用します。

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

以下のものは使用しないでください。

SELECT (1 * ?)/2 as tmp

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format">#</a> ネストされた列の形式

Druid 28.0.0 で作成された json タイプの列には、26.0.0 より古い Druid バージョンとの下位互換性がありません。 Druid 26.0.0 より前のバージョンからアップグレードしており、json カラムを使用している場合は、Druid 28.0.0 にアップグレードする前に、Druid 26.0.0 にアップグレードしてください。 さらに、Druid 26.0.0 よりも古いバージョンにダウングレードするには、さらにダウングレードする前に、Druid 28.0.0 で作成された新しいセグメントを Druid 26.0.0 または 27.0.0 を使用して再取り込む必要があります。

以前のバージョンからアップグレードする場合、引き続き下位互換性のある形式 (バージョン 4) でネストされた列を書き込むことができます。

従来のバッチ取り込みジョブでは、dimensionsSpec プロパティの dimensions リストに formatVersion を含めます。たとえば:

      "dimensionsSpec": {
        "dimensions": [
          "product",
          "department",
          {
            "type": "json",
            "name": "shipTo",
            "formatVersion": 4
          }
        ]
      },

デフォルトのネストされた列のバージョンを設定するには、共通のランタイム プロパティで目的の形式のバージョンを設定します。たとえば:

druid.indexing.formats.nestedColumnFormatVersion=4

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility">#</a> SQL の互換性

Druid 28.0.0 以降、Druid が null と boolean を処理するデフォルトの方法が変更されました。

null の場合、Druid は空の文字列とデータのないレコード、および空の数値レコードと 0 を区別するようになりました。
druid.generic.useDefaultValueForNull を true に設定すると、以前の動作に戻すことができます。

このプロパティはストレージとクエリの両方に影響し、取り込み時とクエリ時の両方で利用できるようにするには、すべての Druid サービス タイプで設定する必要があります。この設定を古い値に戻すと、再取り込みを行わずに以前の動作が復元されます。

ブール値の場合、Druid は厳密に 1 (true) または 0 (false) を使用するようになりました。以前は、true と false は、それぞれ true と false、あるいは 1 と 0 として表すことができました。さらに、Druid は、True && NULL のようなブール比較に対して null 値を返すようになりました。

druid.expressions.useStrictBooleans を false に設定すると、以前の動作に戻すことができます。 このプロパティはストレージとクエリの両方に影響し、取り込み時とクエリ時の両方で利用できるようにするには、すべての Druid サービス タイプで設定する必要があります。この設定を古い値に戻すと、再取り込みを行わずに以前の動作が復元されます。

クエリのフィルター条件で NULL を使用して、NULL と空の文字列の両方に一致する場合は、空の文字列に対して明示的なフィルター句を追加する必要があります。たとえば、s IS NULL を s IS NULL OR s = '' に更新します。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-count-functions" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-count-functions">#</a> COUNT 個の関数

COUNT(column) は空の文字列をカウントするようになりました。カウントから引き続き空の文字列を除外する場合は、COUNT(column) を COUNT(column) FILTER(WHERE column <> '') に置き換えます。

Null 値が空の文字列と共存できるため、Null 値を含む列に対する GroupBy クエリに追加のエントリを含めることができるようになりました。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60lenientaggregatormerge%60-deprecated" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60lenientaggregatormerge%60-deprecated">#</a> lenientAggregatorMerge は非推奨になりました

セグメント メタデータ クエリの lenientAggregatorMerge プロパティは非推奨になりました。将来のリリースでは削除される予定です。 代わりに aggregatorMergeStrategy を使用してください。 aggregatorMergeStrategy は、lenientAggregatorMerge の strict および lenient ストラテジーに加えて、latest および earliest ストラテジーもサポートします。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-broker-parallel-merge-config-options" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-broker-parallel-merge-config-options">#</a> ブローカーの並列マージ構成オプション

druid.processing.merge.pool.* および druid.processing.merge.task.* のパスは、代わりに druid.processing.merge.* を使用するようにフラット化されました。構成の従来のパスは非推奨となり、将来のリリースでは削除される予定です。古いパスは将来無視されるため、新しいパスを使用するように設定を移行します。

#14695

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns">#</a> ARRAY 型列の取り込みオプション

Druid 28.0.0 以降では、クエリ コンテキスト パラメーター arrayIngestMode を array に設定すると、MSQ タスク エンジンは配列を ARRAY 型の列として検出して取り込むことができます。 arrayIngestMode コンテキスト パラメーターは、ARRAY タイプの値を Druid セグメントに格納する方法を制御します。

arrayIngestMode を array に設定すると (SQL 準拠のために推奨)、MSQ タスク エンジンはすべての ARRAY 型の値を ARRAY 型の列 に格納し、VARCHAR と数値型の配列の両方の格納をサポートします。

下位互換性のため、arrayIngestMode のデフォルトは mvd です。 "arrayIngestMode":"mvd" の場合、Druid は VARCHAR 型配列のみをサポートし、それらを 複数値文字列列 として保存します。

arrayIngestMode を none に設定すると、Druid は任意のタイプの配列を保存しようとすると例外をスローします。

SQL ベースの取り込みを使用して ARRAY 型付き列を取り込む方法の詳細については、「SQL データ型 および 配列列」を参照してください。

<a name="28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> 互換性のない変更

<a name="28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-hadoop-2" href="#28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-hadoop-2">#</a> Hadoop 2 を削除しました

Hadoop 2 のサポートは削除されました。 現在、取り込みに Hadoop 2.x を使用している場合は、SQL ベースの取り込みまたは JSON ベースのバッチ取り込みに移行してください。 Druid の組み込み取り込みに移行できない場合は、Druid 28.0.0 にアップグレードする前に、Hadoop インフラストラクチャを 3.x 以降にアップグレードする必要があります。

#14763

<a name="28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-groupby-v1-" href="#28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-groupby-v1-">#</a> GroupBy v1 を削除しました

GroupBy v1 エンジンは削除されました。代わりに、GroupBy v2 エンジンを使用してください。これは、いくつかのリリースでデフォルトの GroupBy エンジンでした。 クエリには影響はありません。 さらに、AggregatorFactory.getRequiredColumns は非推奨となり、将来のリリースでは削除される予定です。 AggregatorFactory を実装する拡張機能がある場合は、このメソッドを実装から削除する必要があります。

decommissioningMaxPercentOfMaxSegmentsToMove 構成は削除されました。 この構成のユースケースは、デフォルトで有効になっているスマート セグメントの読み込みによって処理されるようになりました。

#14923

<a name="28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-%60cachingcost%60-strategy" href="#28.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-%60cachingcost%60-strategy">#</a> cachingCost 戦略を削除しました

セグメント読み込みの cachingCost 戦略は削除されました。 代わりに、cachingCost と同じ利点がある cost を使用してください。

cachingCost が設定されている場合、システムはこの設定を無視し、自動的に cost を使用します。
