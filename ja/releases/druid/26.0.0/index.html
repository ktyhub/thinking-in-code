#ドルイドドルイド-26.0.0

Apache Druid 26.0.0 には、390 を超える新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 65 人の寄稿者による追加のテスト カバレッジが含まれています。

詳細については、変更の完全なセットを参照してください。

Druid 26.0.0 にアップグレードする前に、アップグレードに関する注意事項と互換性のない変更 を確認してください。

<a name="26.0.0-highlights-auto-type-column-schema-%28experimental%29" href="#26.0.0-highlights-auto-type-column-schema-%28experimental%29">#</a> 自動型列スキーマ (実験的)

新しい「自動」タイプの列スキーマとインデクサーが、ネストされた列機能の次の論理反復としてネイティブ インジェストに追加されました。この自動タイプの列インデクサーは、指定された入力に最も適切な列を生成します。STRING、ARRAY<STRING>、LONG、ARRAY<LONG>、DOUBLE、ARRAY<DOUBLE>、または COMPLEX<json> 列のいずれかを生成し、すべて共通の「ネストされた」形式を共有します。

「auto」によって生成されるすべての列には、(従来の LONG および DOUBLE 列とは異なり) 高速フィルタリングを支援するインデックスがあり、カーディナリティ ベースのしきい値を使用して、(従来の STRING 列とは異なり) クエリを実際に高速化する可能性がある場合にのみこれらのインデックスを利用しようとします。

この「自動」インデクサーによって生成される COMPLEX<json> 列は、単純なスカラー型の配列を 'json' (v4) の対応するものとは異なる方法で格納し、ARRAY 型の列として格納します。これは、JSON_VALUE 関数で配列全体 (例: JSON_VALUE(nested, '$.array' RETURNING BIGINT ARRAY)) を抽出できるようになったということです。現時点では、複雑なオブジェクトの配列の格納方法に変更はありません。

この改善により、Druid に完全に新しい機能である ARRAY 型付き列も追加されます。これは、従来の複数値 STRING 列とは異なり、ARRAY セマンティクスで動作します。現在、これらの列は、すべての値が同じタイプの要素を持つ配列である場合に、「auto」タイプのインデクサーを介してのみ作成できます。

配列データ型は、データベース テーブルの 1 つの列に複数の値を格納できるデータ型です。配列は通常、グループとして簡単にアクセスして操作できる関連データのセットを格納するために使用されます。

このリリースでは、ARRAY<STRING>、ARRAY<LONG>、ARRAY<DOUBLE> などのプリミティブ値の配列を、個別の要素列に分割するのではなく、特殊なネストされた列として格納するためのサポートが追加されました。

<a name="26.0.0-highlights-auto-type-column-schema-%28experimental%29-schema-auto-discovery-%28experimental%29" href="#26.0.0-highlights-auto-type-column-schema-%28experimental%29-schema-auto-discovery-%28experimental%29">#</a> スキーマ自動検出 (実験的)

型推論によるスキーマ自動検出を Druid に追加します。この機能を使用すると、スキーマが使用可能なときに各受信フィールドのデータ型が検出されます。追加、削除、または変更されたフィールドが含まれている可能性がある受信データについては、不適合データを拒否する (「データベースは常に正しい - 不正なデータを拒否する!」) か、スキーマの自動検出によって受信データと一致するようにデータソースを変更する (「データは常に正しい - データベースを変更する!」) かを選択できます。 スキーマの自動検出は、新しいユースケースと取り込みに推奨されます。既存のユースケースでは、Druid が複数値 (MV) 文字列ではなく ARRAY<STRING> 型列として配列のような値 (["tag1", "tag2] など) を取り込むため、スキーマ自動検出への切り替えに注意してください。これにより、MV の動作に応答するダウンストリーム アプリで問題が発生する可能性があります。正式な移行パスが利用可能になるまで、切り替えを控えてください。

この機能を使用するには、タスクまたはスーパーバイザ仕様で spec.dataSchema.dimensionsSpec.useSchemaDiscovery を true に設定するか、コンソールでデータ ローダーを使用している場合は、Configure schema ステップの Explicitly define schema トグルをオフにします。 Druid は、ディメンション リストにディメンションを明示的にリストした場合、スキーマ全体またはその一部を推論できます。

スキーマの自動検出は、ネイティブ バッチおよびストリーミング取り込みで使用できます。

<a name="26.0.0-highlights-unnest-arrays-%28experimental%29-" href="#26.0.0-highlights-unnest-arrays-%28experimental%29-">#</a> UNNEST 配列 (実験的)

UNNEST の優れている点の 1 つは、配列データ型では不可能だった幅広い操作が可能になる点です。 UNNEST 関数 (SQL) または unnest データソース (ネイティブ) を使用して配列のネストを解除できます。

Unnest は、ネストされた配列またはテーブルを個々の行に変換します。 UNNEST 関数は、JSON など、ネストされた配列を含む複雑なデータ型を操作する場合に特に便利です。

たとえば、注文ごとの製品の配列を含む「items」という列を持つ「orders」というテーブルがあるとします。次の SQL 例のように、unnest を使用して個々の製品 (「each_item」) を抽出できます。

SELECT order_id, each_item FROM orders, UNNEST(items) as unnested(each_item)

これにより、各注文の商品ごとに 1 行、注文 ID と個々の商品の列を含む結果セットが生成されます。

左側のテーブル/データソースの後のカンマ (例では orders) に注意してください。それは必須です。

<a name="26.0.0-highlights-sort-merge-join-and-hash-shuffle-join-for-msq" href="#26.0.0-highlights-sort-merge-join-and-hash-shuffle-join-for-msq">#</a> MSQ のソートマージ結合およびハッシュ シャッフル結合

ソートマージアルゴリズムのコンテキストパラメータ sqlJoinAlgorithm を sortMerge に設定するか、ブロードキャスト結合 (デフォルト) を実行するために省略することにより、シャッフル結合を実行できるようになりました。

複数ステージのクエリでは、ソート/マージ結合アルゴリズムを使用できます。このアルゴリズムでは、各ペアワイズ結合が 2 つの入力を持つ独自のステージに計画されます。このアプローチは一般に、ブロードキャストよりもパフォーマンスは劣りますが、スケーラビリティに優れています。

このメソッドを使用するには、コンテキスト パラメーター sqlJoinAlgorithm を sortMerge に設定します。

ブロードキャスト ハッシュ結合は、ネイティブ結合クエリの実行方法と似ています。

<a name="26.0.0-highlights-storage-improvements-on-dictionary-compression--" href="#26.0.0-highlights-storage-improvements-on-dictionary-compression--">#</a> 辞書圧縮におけるストレージの改善

フロントコーディング辞書圧縮 (実験的) の使用に切り替えると、クエリのパフォーマンスにほとんど、またはまったく影響を与えることなく、最大 30% を節約できます。

このリリースでは、新しいセグメント フォーマット バージョンを使用して、indexSpec 上の stringEncodingStrategy タイプの frontCoded がさらに改善されており、通常は読み取り速度が向上し、セグメント サイズが縮小されています。この改善には、Druid 25.0 との下位互換性がありません。新しい formatVersion オプションが追加されました。デフォルトは現在のバージョン 0 です。新しいバージョンの使用を開始するには、formatVersion を 1 に設定します。

Kinesis インデックスサービスの次のフェッチ設定を更新しました。

  • fetchThreads: タスクで使用できるプロセッサーの数の 2 倍。
  • fetchDelayMillis: 0 (フェッチ間の遅延なし)。

<a name="26.0.0-upgrade-notes-and-incompatible-changes--incompatibility-changes-information-schema-now-uses-numeric-column-types-" href="#26.0.0-upgrade-notes-and-incompatible-changes--incompatibility-changes-information-schema-now-uses-numeric-column-types-">#</a> 情報スキーマは数値列タイプを使用するようになりました

Druid システム テーブル (INFORMATION_SCHEMA) では、列に Druid タイプではなく SQL タイプが使用されるようになりました。この変更により、INFORMATION_SCHEMA テーブルはより標準 SQL のように動作するようになります。次のいずれかに依存している場合、予期しない結果を避けるために、次のシナリオでクエリを更新する必要がある場合があります。

  • 数値フィールドは文字列として扱われます。
  • 0 から始まる列の番号付け。列の番号付けは 1 から始まるようになりました。

#13777

<a name="26.0.0-upgrade-notes-and-incompatible-changes--incompatibility-changes-%60frontcoded%60-segment-format-change" href="#26.0.0-upgrade-notes-and-incompatible-changes--incompatibility-changes-%60frontcoded%60-segment-format-change">#</a> frontCoded セグメント形式の変更

新しいセグメント形式バージョンを備えた indexSpec 上の stringEncodingStrategy の frontCoded タイプ。通常、読み取り速度が速くなり、セグメント サイズが小さくなります。この改善には、Druid 25.0 との下位互換性がありません。

詳細については、frontCoded 文字列エンコード戦略のハイライトを参照してください。

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> 開発者向けノート

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-null-value-coercion-moved-out-of-expression-processing-engine-" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-null-value-coercion-moved-out-of-expression-processing-engine-">#</a> Null 値強制は式処理エンジンから移動されました

Druid ネイティブ式処理エンジンに入力および作成された Null 値は、druid.generic.useDefaultValueForNull=true の場合、null をタイプに適切な「デフォルト」値に強制しなくなりました。これはコンシューマに移行されており、内部的にはオペレータが引き続きこのモードのデフォルト値を使用するため、既存の動作には影響しません。ただし、ZZPH100​​ZZ 値の処理に関して動作が微妙に変更される可能性があります。直接呼び出し元は、value() の代わりに ExprEval の新しい valueOrDefault() メソッドを使用してデフォルト値を取得できます。

#13809

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-simplified-dependencies" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-simplified-dependencies">#</a> 依存関係の簡略化

druid-core、extendedset、および druid-hll モジュールは、依存関係を簡素化するために druid-processing に統合されました。これらを参照する拡張機能は、代わりに druid-processing を使用するように更新する必要があります。既存の拡張機能バイナリは、新しいバージョンの Druid で使用した場合でも引き続き正常に機能します。

この変更はエンド ユーザーには影響しません。 Druid の拡張機能を開発する人には影響します。
