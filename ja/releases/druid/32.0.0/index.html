<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> 新しいオーバーロード API

セグメントを使用済みまたは未使用としてマークするための API は、コーディネーターからオーバーロード サービスに移動されました。

  • データソースのすべてのセグメントを未使用としてマークします。 POST /druid/indexer/v1/datasources/{dataSourceName}

  • データソースのすべての (影になっていない) セグメントを使用済みとしてマークします。 DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • 複数のセグメントを使用済みとしてマークします POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • 複数の (影になっていない) セグメントを未使用としてマークします POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • 単一セグメントを使用済みとしてマークします。 POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • 単一セグメントを未使用としてマークします。 DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

この変更の一環として、対応するコーディネーター API は非推奨となり、将来のリリースでは削除される予定です。

  • POST /druid/coordinator/v1/datasources/{dataSourceName}
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}

コーディネーターはこれらのリクエストに応えるためにオーバーロードを呼び出します。

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> 複数値文字列のリアルタイム クエリ処理

リアルタイム クエリ処理では、式の処理中にすべての文字列が複数値の文字列として考慮されなくなり、多くのバグと予期しないエラーが修正されました。これにより、文字列列に対する式のリアルタイム クエリのパフォーマンスも向上します。

この変更は、JSON オブジェクトに欠落しているプロパティなど、データ行が暗黙的に null であるリアルタイム セグメントの topN クエリに影響します。

この変更が行われる前は、これらは null ではなく [] として処理され、リアルタイム セグメントの処理と公開セグメントの間で不一致が発生していました。セグメントを処理するときに、値は [] として扱われ、topN はこれを無視しました。公開後、値は null になりましたが、topN はこれを無視しません。同じクエリでも、永続化の前後で結果が異なる可能性があります。

この変更後、topN エンジンはリアルタイム セグメントを処理するときに [] を null として扱うようになり、これは公開されたセグメントと一貫性があります。

この変更は、リアルタイムであるかどうかに関係なく、実際の複数値文字列列には影響しません。

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> MSQ タスク エンジン クエリの結合ヒント

Druid は、MSQ タスク エンジンを使用する SQL JOIN クエリのヒントをサポートするようになりました。これにより、クエリで結合レベルごとに使用する必要がある JOIN タイプのヒントを提供できるようになります。結合ヒントはサブクエリに再帰的に影響します。

#17541

<a name="32.0.0-changes-and-deprecations" href="#32.0.0-changes-and-deprecations">#</a> 変更と非推奨

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> ANSI-SQL の互換性とクエリ結果

ANSI-SQL に準拠していない古い動作を維持できる構成のサポートは削除されました。

  • druid.generic.useDefaultValueForNull=true
  • druid.expressions.useStrictBooleans=false
  • druid.generic.useThreeValueLogicForNativeFilters=false

クエリ結果には影響しなくなりました。現在は、SQL 準拠の非レガシー動作のみがサポートされています。

構成が従来の動作に設定されている場合、Druid サービスは開始できません。

これらの設定を行わずに引き続き同じ結果を得たい場合は、クエリを更新する必要があります。そうしないと、アップグレード後に結果が不正確になります。

クエリを更新する方法の詳細については、移行ガイド を参照してください。

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> MSQ タスク エンジン クエリの結合ヒント

Druid は、MSQ タスク エンジンを使用する SQL JOIN クエリのヒントをサポートするようになりました。これにより、クエリで結合レベルごとに使用する必要がある JOIN タイプのヒントを提供できるようになります。結合ヒントはサブクエリに再帰的に影響します。

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing">#</a> 公開するために結合するセグメントの数を制御します

スーパーバイザ仕様の maxColumnsToMerge プロパティを使用して、パブリッシュのためにセグメントをマージするときに、単一フェーズでマージするセグメントの数を指定できるようになりました。この制限は、マージするセグメントのセットに存在する列の合計数に影響します。制限を超えると、セグメントのマージが複数のフェーズで発生します。 Druid は、この設定に関係なく、各フェーズで少なくとも 2 つのセグメントをマージします。

<a name="32.0.0-functional-area-and-related-changes-cluster-management" href="#32.0.0-functional-area-and-related-changes-cluster-management">#</a> クラスタ管理

<a name="32.0.0-functional-area-and-related-changes-cluster-management-reduce-metadata-io" href="#32.0.0-functional-area-and-related-changes-cluster-management-reduce-metadata-io">#</a> メタデータ IO を削減する

Overlord ランタイム プロパティ druid.indexer.tasklock.batchAllocationReduceMetadataIO は、バッチ セグメント割り当て中の IO を削減するのに役立ちます。このフラグを true (デフォルト値) に設定すると、オーバーロードはセグメント割り当て中に必要なセグメント ペイロードのみをフェッチできるようになります。

<a name="32.0.0-functional-area-and-related-changes-data-management" href="#32.0.0-functional-area-and-related-changes-data-management">#</a> データ管理

<a name="32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29" href="#32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29">#</a> MSQ タスク エンジンを使用した圧縮のための列の並べ替え (実験的)

MSQ タスク エンジンを使用する圧縮では、時間以外の列を含むセグメントの並べ替えがサポートされるようになりました。 forceSegmentSortByTime が圧縮構成または推論されたスキーマに設定されている場合、次のことが起こります。

  • __time はすでにスキーマの一部として含まれているため、ディメンション スキーマの最初の列として明示的に追加するのをスキップします。
  • 列マッピングがスキーマで指定された順序で __time を伝播するようにする
  • MSQ クエリ コンテキストで forceSegmentSortByTime を設定します。

<a name="32.0.0-functional-area-and-related-changes-data-management-other-data-management-improvements" href="#32.0.0-functional-area-and-related-changes-data-management-other-data-management-improvements">#</a> その他のデータ管理の改善点

  • 同じ列順序の異なる順列が異なるスキーマにならないように集中データソース スキーマを改善しました #17044
  • 列スキーマが明示的に指定されていない場合、常に複数値ディメンションを配列として処理するように圧縮タスクを変更しました #17110

cgroupv2 用の次のモニターが現在利用可能です。

  • CPU: org.apache.druid.java.util.metrics.CgroupV2CpuMonitor
  • ディスク使用量 org.apache.druid.java.util.metrics.CgroupV2DiskMonitor
  • メモリ org.apache.druid.java.util.metrics.CgroupV2MemoryMonitor #16905

<a name="32.0.0-functional-area-and-related-changes-metrics-and-monitoring-other-metrics-and-monitoring-improvements" href="#32.0.0-functional-area-and-related-changes-metrics-and-monitoring-other-metrics-and-monitoring-improvements">#</a> その他のメトリクスと監視の改善

  • ingest/notices/queueSize、ingest/notices/time、ingest/pause/time メトリクスを statsd エミッターに追加しました #17487 #17468
  • statsd-emitter #17320 の coordinator.global.time メトリックのディメンションとしてデューティ グループを追加しました
    • service/heartbeat メトリクスは、Peon #17488 のステータスを報告するようになりました。
  • リアルタイム セグメント メトリクスを、各 FireHydrant ではなく各 Sink のものになるように変更しました。これは、30.0.0 #17170 で行われたリアルタイム クエリのパフォーマンスの改善前の発行動作に戻りました。
  • クエリオブジェクトが切り捨てられた場合でも統計が保持されるように、getNativeQueryLine ロギングの間隔の前にクエリ統計が最初に来るように変更されました #17326

<a name="32.0.0-functional-area-and-related-changes-extensions" href="#32.0.0-functional-area-and-related-changes-extensions">#</a> 拡張機能

<a name="32.0.0-functional-area-and-related-changes-extensions-delta-lake" href="#32.0.0-functional-area-and-related-changes-extensions-delta-lake">#</a> デルタ湖

  • Delta Lake 入力ソースは 10 進データ型をサポートし、double として処理されるようになりました。 値が double 内に収まらない場合は、文字列として取り込みます #17376
  • バージョンが0であっても、スナップショットのバージョンでフィルタリングできるようになりました #17367

<a name="32.0.0-functional-area-and-related-changes-extensions-grpc-queries" href="#32.0.0-functional-area-and-related-changes-extensions-grpc-queries">#</a> gRPC クエリ

新しいコントリビューター拡張機能により、SQL およびネイティブ クエリの gRPC API が有効になりました。これは、gRPC ベースの clients が拡張機能を使用して SQL クエリを発行できることを意味します。単純なクエリにはこの拡張機能を使用します。

詳細については、「Druid 用の gRPC クエリ拡張機能」(https://github.com/apache/druid/tree/master/extensions-contrib/grpc-query) を参照してください。

#15982

<a name="32.0.0-functional-area-and-related-changes-extensions-kubernetes" href="#32.0.0-functional-area-and-related-changes-extensions-kubernetes">#</a> Kubernetes

  • Kubernetes を使用した中間管理者なしの取り込みは、Overlord の再起動に対する回復力が向上しました #17446
  • セレクターベースのポッドテンプレート選択戦略で空の配列を type キーと dataSource キーに渡すことができるようになりました #17400
  • getMaximumCapacity フィールドを公開するように TaskRunner を改善しました #17107

<a name="32.0.0-functional-area-and-related-changes-extensions-iceberg" href="#32.0.0-functional-area-and-related-changes-extensions-iceberg">#</a> 氷山

Iceberg 拡張機能は、AWS Glue Iceberg カタログをサポートするようになりました。

#17392

<a name="32.0.0-functional-area-and-related-changes-documentation-improvements" href="#32.0.0-functional-area-and-related-changes-documentation-improvements">#</a> ドキュメントの改善

ドキュメントには、サポートされているすべての Apache Druid SQL 関数の例が含まれるようになりました。例に沿って各機能の使用方法を簡単に学ぶことができます。これらの例では、Druid に含まれるデータセットを利用しているため、簡単にすぐに始めることができます。

すべての Druid SQL 関数 で例を確認してください。

<a name="32.0.0-upgrade-notes-and-incompatible-changes" href="#32.0.0-upgrade-notes-and-incompatible-changes">#</a> アップグレードに関する注意事項と互換性のない変更点

<a name="32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> 互換性のない変更

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> 開発者向けノート

  • 拡張機能間の依存関係のサポートが改善されました。拡張機能に別の拡張機能への依存関係がある場合、依存関係のクラス ローダーを使用して必要なクラスを検索しようとするようになりました #16973
  • セグメントを使用済みまたは未使用としてマークするためのコーディネーター API は非推奨になり、将来のリリースでは削除される予定です。代わりに、対応する Overlord API を使用してください。完全なリストについては、New Overlord APIs または #17545 を参照してください。

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates">#</a> 依存関係の更新

次の依存関係のバージョンが変更されました。 ※javax.xml.bindは廃止されました。ドルイドは jakarta.xml.bind #17370 を使用するようになりました

  • Web コンソールのいくつかの依存関係が更新されました。完全なリストについては、#17381、#17365、#17363 を参照してください。
  • Web コンソールの file-loader 依存関係を削除 #17346 ※4.2.2から5.1.0へのご案内
  • git-commit-id-maven-plugin 4.9.10 から 9.0.1 #17571
  • Netty バージョン 4.1.108.Final から 4.1.116.Final
