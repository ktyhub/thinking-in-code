重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

Java 11 のサポート

Java 11 のサポートは Druid 32.0 以降非推奨となり、公式サポートは Druid 35.0.0 以降に削除される予定です

Hadoop ベースの取り込み

Hadoop ベースの取り込みは Druid 32.0 以降非推奨となり、Druid 35.0.0 には削除される予定です。 SQL ベースのインジェスト や Kubernetes を使用した MiddleManager レス インジェスト など、Druid でサポートされている他のインジェスト メソッドのいずれかを推奨します。

この変更の一環として、非推奨の index_hadoop タスク タイプの使用をオプトインする必要があります。これを行わないと、Hadoop ベースの取り込みタスクは失敗します。

オプトインするには、common.runtime.properties ファイルで druid.indexer.task.allowHadoopTaskExecution を true に設定します。

#18239

クエリ コンテキスト パラメーターに SET ステートメントを使用する

SET ステートメントを使用して、Druid コンソール または API を通じてクエリのクエリ コンテキスト パラメーターを定義できるようになりました。

#17894 #17974

Druid コンソールの SET ステートメント

Web コンソールは、クエリ コンテキスト パラメーターを指定するための SET ステートメントの使用をサポートするようになりました。たとえば、クエリに SET timeout = 20000; を含めると、タイムアウト クエリ コンテキスト パラメータが設定されます。

SET timeout = 20000;
SELECT "channel", "page", sum("added") from "wikipedia" GROUP BY 1, 2

#17966

API を使用した SET ステートメント

/druid/v2/sql に対して発行される SQL クエリに複数の SET ステートメントを含めて、最終ステートメントのコンテキストを構築できるようになりました。たとえば、次の SQL クエリ結果には、timeout、useCache、populateCache、vectorize、および engine クエリ コンテキスト パラメーターが含まれています。

SET timeout = 20000;
SET useCache = false;
SET populateCache = false;
SET vectorize = 'force';
SET engine = 'msq-dart'
SELECT "channel", "page", sum("added") from "wikipedia" GROUP BY 1, 2

このクエリの API 呼び出しは次のようになります。

curl --location 'http://HOST:PORT/druid/v2/sql' \
--header 'Content-Type: application/json' \
--data '{
  "query": "SET timeout=20000; SET useCache=false; SET populateCache=false; SET engine='\''msq-dart'\'';SELECT  user,  commentLength,COUNT(*) AS \"COUNT\" FROM wikipedia GROUP BY 1, 2 ORDER BY 2 DESC",
  "resultFormat": "array",
  "header": true,
  "typesHeader": true,
  "sqlTypesHeader": true
}'

この改善は、MSQ タスク エンジンを使用する INSERT および REPLACE クエリにも適用されます。 JDBC はサポートされていないことに注意してください。

HTTP エンドポイントの改善

/druid/v2/sql エンドポイントの HTTP 本文で生の SQL を使用できるようになりました。 Content-Type を application/json の代わりに text/plain に設定できるため、エスケープされていない生のテキストを提供できます。

#17937

履歴のクローン作成 (実験的)

動的コーディネーター構成 cloneServers を使用して、履歴のクローンを構成できるようになりました。クローンされたヒストリカルは、ローリング アップデートなど、既存のヒストリカルの代わりに新しいヒストリカルを起動する必要がある場合に便利です。

ターゲット履歴サーバーからソース履歴サーバーへのマップに構成を設定します。

  "cloneServers": {"historicalClone":"historicalOriginal"}

クローンは、通常のセグメントの割り当てやバランシングには参加しません。代わりに、コーディネーターは、元のヒストリカルに行われたセグメント割り当てをクローンに反映し、クローンがソースの正確なコピーになります。クローン履歴上のセグメントもレプリカ数にはカウントされません。元の履歴が消失した場合、クローンは cloneServers 構成から削除されるまで、ソース サーバーの最後の既知の状態のままになります。

ネイティブ クエリ エンジンを使用してデータをクエリする場合、クエリ コンテキスト パラメーター cloneQueryMode を設定することで、クローンを優先 (preferClones)、除外 (excludeClones)、または含めることができます (includeClones)。デフォルトでは、クローンは除外されます。

この変更の一環として、新しいコーディネーター API が利用可能になりました。詳細については、「クローン用コーディネーター APIs」(#coordinator-apis-for-clones) を参照してください。

#17863 #17899 #17956

Overlord に埋め込まれた kill タスク (実験的)

Overlord 自体で直接 Kill タスクを実行できるようになりました。埋め込みの kill タスクにはいくつかの利点があります。彼らは：

  • 対象になるとすぐにセグメントを強制終了します
  • タスクスロットを占有しないでください
  • 最適化されたメタデータ クエリを使用し、新しい JVM を起動しないため、より速く終了します。
  • タスクごとに少数のセグメントを強制終了し、一定の間隔でロックが長時間保持されないようにする
  • 行頭のブロックを避けるために、ロックされた間隔をスキップします
  • 最小限の構成が必要です
  • クラスター内の多数の未使用セグメントに対応できる

この機能は、次の構成によって制御されます。

  • druid.manager.segments.killUnused.enabled - 機能が有効かどうか (デフォルトは false)
  • druid.manager.segments.killUnused.bufferPeriod - セグメントがメタデータおよびディープ ストレージから永久に削除されるまでに未使用でなければならない時間。これは、未使用としてマークされた後にデータが必要になった場合にデータ損失を防ぐためのバッファ期間として機能します (デフォルトは P30D)。

埋め込みの Kill タスクを使用するには、セグメント メタデータ キャッシュを有効にする必要があります。

この機能の一部として、新しいメトリクス が追加されました。

#18028 #18124

優先層の選択

特定の層の履歴を優先するように Broker サービスを構成できるようになりました。これは、アベイラビリティーゾーン全体の展開に役立ちます。 1 つの AZ 内のブローカーは、デフォルトで同じ AZ 内のヒストリカルを選択しますが、同じ AZ 内のヒストリカルが利用できない場合は、別の AZ 内のヒストリカル ノードを選択する機能も引き続き保持します。

有効にするには、ブローカー ランタイム プロパティでプロパティ druid.broker.select.tier を perferred に設定します。次に、各ブローカーが優先する層に druid.broker.select.tier.preferred.tier を構成できます (つまり、AZ1 のブローカーの場合、これを AZ1 履歴サーバーの層名に設定できます)。

#18136

ダーツの改善

Dart クエリ エンジンは、他の SQL クエリ エンジンと同様に /druid/v2/sql エンドポイントを使用するようになりました。以前の Dart 固有のエンドポイントはサポートされなくなりました。クエリに Dart を使用するには、engine クエリ コンテキスト パラメーターを含めて、それを msq-dart に設定します。

#18003 #18003

Dart の有効化は変わりません。broker/runtime.properties および historical/runtime.properties ファイルに次の行を追加します。

druid.msq.dart.enabled = true

さらに、Dart はデフォルトでリアルタイム タスクをクエリするようになりました。 MSQ タスクと同様の方法で、クエリ コンテキスト パラメーター includeSegmentSource を REALTIME (デフォルト) または NONE に設定することで、この動作を制御できます。同期または非同期クエリを実行することもできます。

クラスター管理

サブタスクのタイムアウトを構成可能

index_parallel および compact タイプのタスクのタイムアウトを構成できるようになりました。コンテキスト パラメーター subTaskTimeoutMillis を、サブタスクがキャンセルされるまで待機する最大時間をミリ秒単位で設定します。デフォルトでは、タイムアウトはありません。

この構成を使用すると、親タスクがゾンビのサブタスクの実行中にスタックするのではなく、より早く失敗するようになります。

Hadoop ベースの取り込み

Hadoop ベースの取り込みは Druid 32.0 以降非推奨となり、Druid 35.0.0 には削除される予定です。

SQL ベースのインジェスト や Kubernetes を使用した MiddleManager なしのインジェスト など、Druid でサポートされている他のインジェスト メソッドのいずれかを推奨します。 この変更の一環として、非推奨の index_hadoop タスク タイプの使用をオプトインする必要があります。これを行わないと、Hadoop ベースの取り込みタスクは失敗します。 オプトインするには、common.runtime.properties ファイルで druid.indexer.task.allowHadoopTaskExecution を true に設定します。 #18239

groupBy および topN クエリ

Druid は、グループ化された SQL クエリに対して、topN ではなく groupBy ネイティブ クエリ タイプを使用するようになりました。 同じ列で並べ替え、LIMIT はあり、HAVING はありません。これにより実行が高速化されます groupBy はベクトル化されますが、topN はベクトル化されないため、そのようなクエリは発生しません。

クエリ コンテキスト パラメーター useLexicographicTopN を true に設定すると、以前の動作に戻すことができます。 useApproximateTopN の動作は変更されておらず、デフォルトは true のままです。

#18074

IS_INCREMENTAL_HANDOFF_SUPPORTED 構成が削除されました

バージョン 0.16.0 以降、インクリメンタル パブリッシングがデフォルトの動作になったため、スーパーバイザから IS_INCREMENTAL_HANDOFF_SUPPORTED コンテキスト参照を削除しました。このコンテキストは元々、0.16.0 より前のバージョンで LegacyKafkaIndexTaskRunner へのロールバックをサポートするために導入されましたが、現在は削除されています。

useMaxMemoryEstimates 構成が削除されました

useMaxMemoryEstimates 構成を削除しました。 false に設定すると、Druid は Druid 0.23.0 で導入されたより正確なメモリ推定値を使用します。このより正確な方法が、現在利用できる唯一の方法です。いくつかのリリースでは、設定はデフォルトで false に設定されています。
