druid 25.0.0

#ドルイドドルイド-25.0.0 Apache Druid 25.0.0 には、300 を超える新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 51 人の寄稿者による追加のテスト カバレッジが含まれています。 詳細については、変更の完全なセットを参照してください。

<a name="25-highlights" href="#25-highlights">#</a> ハイライト

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> MSQ タスク エンジンが本番環境に対応しました

SQL ベースの取り込みに使用されるマルチステージ クエリ (MSQ) タスク エンジンが実稼働環境に対応しました。サポートされているワークロードに使用します。詳細については、次のページを参照してください。

  • 摂取
  • SQL ベースの取り込み

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> 簡素化された Druid の導入

新しい start-druid スクリプトにより、単一サーバー上での Druid サービスの任意の組み合わせのデプロイが大幅に簡素化されます。必要な構成があらかじめパッケージ化されており、./start-druid を呼び出すだけで完全に機能する Druid クラスターを起動するために使用できます。経験豊富な Druid の場合、ランタイム プロパティと JVM 引数を完全に制御して、ニーズに正確に適合するクラスターを作成することもできます。 start-druid スクリプトは、start-micro-quickstart や start-nano-quickstart などの既存のプロファイルを非推奨とします。これらのプロファイルは将来のリリースで削除される可能性があります。詳細については、「単一サーバー展開」(https://druid.apache.org/docs/latest/operations/single-server.html) を参照してください。

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> 文字列辞書の圧縮 (実験的)

小さな文字列列に対するフロント コード化された文字列辞書のサポートが追加されました。これにより、ほとんどの Druid クエリでパフォーマンスがわずかに低下するだけでセグメント サイズが削減されます。 これを有効にするには、 IndexSpec.stringDictionaryEncoding を {"type":"frontCoded", "bucketSize": 4} に設定します。ここで、 bucketSize は 128 以下の 2 のべき乗です。 このプロパティを設定すると、指定されたバケット サイズの圧縮辞書を使用してセグメントを書き込むようにインデックス付けタスクに指示されます。

文字列辞書圧縮を使用して書き込まれたセグメントは、古いバージョンの Druid では読み取れません。 詳細については、「フロントコーディング」(https://druid.apache.org/docs/latest/ingestion/ingestion-spec.html#front-coding)を参照してください。 https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Kubernetes ネイティブ タスク

Druid は Kubernetes を使用してタスクを起動および管理できるようになり、中間管理者の必要性がなくなりました。 この機能を使用するには、Overlord プロセスの拡張機能ロード リストで druid-kubernetes-overlord-extensions を有効にします。 https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-compatibility-binary" href="#25-highlights-hadoop-3-compatibility-binary">#</a> Hadoop-3 互換バイナリ

Druid は、Hadoop-3 ユーザー向けの専用バイナリとしてパッケージ化されており、これには Hadoop-3 互換の jar が含まれています。 Druid クラスターで Hadoop-3 を使用しない場合は、引き続きクラシック バイナリを使用できます。

<a name="25-multi-stage-query-task-engine" href="#25-multi-stage-query-task-engine">#</a> マルチステージ クエリ (MSQ) タスク エンジン

<a name="25-msq-docker-enabled" href="#25-msq-docker-enabled">#</a> Docker に対して MSQ が有効になりました

MSQ タスク クエリ エンジンは、Docker に対してデフォルトで有効になりました。 https://github.com/apache/druid/pull/13069

<a name="25-msq-query-history" href="#25-msq-query-history">#</a> クエリ履歴

マルチステージ クエリは [クエリ履歴] ダイアログに表示されなくなりました。これらは引き続き [最近のクエリ タスク] パネルで利用できます。

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> CLUSTERED BY 列の制限

MSQ タスク エンジンを使用してデータを取り込む場合、CLUSTERED BY 句で渡すことができる列の数が 1500 に制限されるようになりました。 https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> 文字列辞書圧縮のサポート

MSQ タスク エンジンは、圧縮を向上させるために文字列辞書のフロント コーディングをサポートしています。これは、クエリ コンテキストで indexSpec を有効な json 文字列に設定することで、INSERT または REPLACE ステートメントに対して有効にできます。 https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> スケッチ結合モード

ワーカーは、パーティション境界の生成に使用される主要な統計を順次または並行して収集できるようになりました。対応するスケッチ結合モードを使用するには、クエリ コンテキストで clusterStatisticsMergeMode を PARALLEL、SEQUENTIAL、または AUTO に設定します。詳細については、「スケッチ結合モード」(https://druid.apache.org/docs/latest/multi-stage-query/reference.html#sketch-merging-mode)を参照してください。 https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> パフォーマンスと運用の改善

  • エラー メッセージ: 特定の種類の許可されていない MSQ 警告については、警告がエラーとして表示されるようになりました。 https://github.com/apache/druid/pull/13198
  • Secrets: 機密キーを含む SQL を含むタスクの場合、Druid はログ作成中にヘルプ正規表現を使用してキーをマスクするようになりました。 https://github.com/apache/druid/pull/13231
  • ダウンサンプリング精度: MSQ タスク エンジンは、データのダウンサンプリング時にキー数ではなくバイト数を使用するようになりました。 https://github.com/apache/druid/pull/12998
  • メモリ使用量: パーティションの境界を決定する際、MSQ によって使用される内部スケッチのヒープ フットプリントは、利用可能なメモリの 10% または 300 MB のいずれか低い方に制限されるようになりました。以前は、上限は厳密に 300 MB でした。 https://github.com/apache/druid/pull/13274
  • タスク レポート: ワーカー レポートにフィールド pendingTasks および runningTasks を追加しました。関連する Web コンソールの変更については、タスク ステータス情報のクエリ を参照してください。 https://github.com/apache/druid/pull/13263

<a name="25-querying" href="#25-querying">#</a> クエリ

<a name="25-querying-enabled-async-reads-for-jdbc" href="#25-querying-enabled-async-reads-for-jdbc">#</a> JDBC の非同期読み取り

バッチのフェッチに時間がかかりすぎる場合に空のバッチを返すことで、長いクエリでの JDBC タイムアウトを防止しました。非同期モデルを使用して、JDBC リクエストと同時に結果フェッチを実行します。 https://github.com/apache/druid/pull/13196

<a name="25-querying-in-filter" href="#25-querying-in-filter">#</a> IN フィルターの値をチェックするアルゴリズムの改善

大きな IN フィルター、または IN フィルターとしてプッシュダウンされた結合から生じる大きな値セットに対応するために、Druid はソートされたマージ アルゴリズムを使用して、より大きな値のセットとディクショナリをマージするようになりました。 https://github.com/apache/druid/pull/13133

<a name="25-querying-context-security" href="#25-querying-context-security">#</a> 強化されたクエリ コンテキスト セキュリティ

druid.auth.authorizeQueryContextParams によって制御されるクエリ コンテキスト セキュリティ モデルを改良する次の構成プロパティが追加されました。

  • druid.auth.unsecuredContextKeys: セキュリティ チェックを必要としないクエリ コンテキスト キーの JSON リスト。
  • druid.auth.securedContextKeys: セキュリティ チェックを必要とするクエリ コンテキスト キーの JSON リスト。 両方が設定されている場合、unsecuredContextKeys は securedContextKeys の例外として機能します。 https://github.com/apache/druid/pull/13071

<a name="25-querying-http-response-headers" href="#25-querying-http-response-headers">#</a> HTTP 応答ヘッダー

SQL クエリの HTTP 応答では、ネイティブ クエリと同様に、応答ヘッダーが正しく設定されるようになりました。 https://github.com/apache/druid/pull/13052

<a name="25-metrics-improvements" href="#25-metrics-improvements">#</a> その他の改善点

  • segmentAllocate、segmentTransactionalInsert などの値を取ることができる新しいディメンション taskActionType。このディメンションは、task/action/run/time および新しい バッチ セグメント割り当て メトリクスに対してレポートされます。 https://github.com/apache/druid/pull/13333
  • グローバル キャッシュ ルックアップのメトリック namespace/cache/heapSizeInBytes は、40 バイトの String オブジェクト オーバーヘッドを考慮するようになりました。 https://github.com/apache/druid/pull/13219
  • jvm/gc/cpu は、ミリ秒ではなくナノ秒を報告するように修正されました。 https://github.com/apache/druid/pull/13383

<a name="25-nested-columns" href="#25-nested-columns">#</a> ネストされた列

<a name="25-nested-columns-nested-columns-performance-improvement" href="#25-nested-columns-nested-columns-performance-improvement">#</a> ネストされた列のパフォーマンスの向上

NestedDataColumnSerializer が改善され、各行の欠損値のフィールド ライターに null 値が明示的に書き込まれなくなりました。代わりに、行カウンターの受け渡しがフィールド ライターに移動され、フィールド ライターが null 値を一括でバックフィルできるようになります。 https://github.com/apache/druid/pull/13101

<a name="25-nested-columns-support-for-more-formats" href="#25-nested-columns-support-for-more-formats">#</a> より多くの形式のサポート

Druid のネストされた列と関連する JSON 変換関数は、Avro、ORC、および Parquet をサポートするようになりました。 https://github.com/apache/druid/pull/13325 https://github.com/apache/druid/pull/13375

<a name="25-nested-columns-refactored-a-datasource-before-unnest-" href="#25-nested-columns-refactored-a-datasource-before-unnest-">#</a> ネスト解除の前にデータソースをリファクタリングしました

処理中にデータの「平坦化」が必要な場合、演算子は配列を取得し、その配列を N (N = 配列の要素数) 行に平坦化し、各行には配列の値の 1 つが含まれます。 https://github.com/apache/druid/pull/13085

<a name="25-ingestion" href="#25-ingestion">#</a> 取り込み

<a name="25-ingestion-improved-filtering-for-cloud-objects" href="#25-ingestion-improved-filtering-for-cloud-objects">#</a> クラウド オブジェクトのフィルタリングの改善

S3 などのクラウド ストレージからのネイティブ バッチ取り込みの ioConfig.inputSource.filter フィールドで glob 構文を使用して、任意のサブフォルダーで停止できるようになりました。 https://github.com/apache/druid/pull/13027

<a name="25-ingestion-async-task-client-for-streaming-ingestion" href="#25-ingestion-async-task-client-for-streaming-ingestion">#</a> ストリーミング取り込み用の非同期タスク client

tuningConfig で chatAsync を true に設定することで、ストリーム スーパーバイザーとインデックス作成タスクの間の非同期通信を有効にできるようになりました。非同期タスク client は独自の内部スレッド プールを使用するため、chatThreads プロパティを無視します。 https://github.com/apache/druid/pull/13354

<a name="25-ingestion-improved-control-for-how-druid-reads-json-data-for-streaming-ingestion" href="#25-ingestion-improved-control-for-how-druid-reads-json-data-for-streaming-ingestion">#</a> ストリーミング取り込みによる JSON データの処理の改善

入力形式仕様で次のフィールドを設定することで、Druid がストリーミング取り込みのために JSON データを読み取る方法をより適切に制御できるようになりました。

  • assumedNewlineDelimited は、JSON の行を個別に解析します。
  • 解析例外が発生したときに複数行の JSON イベントを解析するときに、有効な JSON イベントを保持する useJsonNodeReader。 Web コンソールが更新され、これらのオプションが追加されました。 https://github.com/apache/druid/pull/13089

<a name="25-ingestion-idle-supervisor" href="#25-ingestion-idle-supervisor">#</a> アイドル状態の Kafka ストリームからの取り込み

Kafka ストリームが非アクティブになると、そこから取り込むスーパーバイザーは、新しいインデックス作成タスクの作成を停止するように構成できます。ストリームが再びアクティブになると、スーパーバイザは新しいインデックス作成タスクの作成を自動的に再開します。この動作を有効にするには、それぞれのスーパーバイザ仕様でプロパティ dataSchema.ioConfig.idleConfig.enabled を true に設定するか、オーバーロードで druid.supervisor.idleConfig.enabled を設定します。詳細については、以下を参照してください。

  • オーバーロード構成 【スーパーバイザー仕様】(https://druid.apache.org/docs/latest/development/extensions-core/kafka-supervisor-reference.html#kafkasupervisorioconfig) https://github.com/apache/druid/pull/13144

<a name="25-ingestion-kafka-consumer-improvement" href="#25-ingestion-kafka-consumer-improvement">#</a> Kafka 消費者の改善

Kafka Consumer のカスタム デシリアライザーをインスタンス化後に構成できるようになりました。 https://github.com/apache/druid/pull/13097

<a name="25-ingestion-kafka-supervisor-logging" href="#25-ingestion-kafka-supervisor-logging">#</a> Kafka スーパーバイザーのログ記録

Kafka スーパーバイザ ログのノイズが少なくなりました。スーパーバイザは、INFO レベルではなく DEBUG レベルでイベントをログに記録するようになりました。 https://github.com/apache/druid/pull/13392

<a name="25-ingestion-fixed-overlord-leader-election" href="#25-ingestion-fixed-overlord-leader-election">#</a> オーバーロードのリーダー選挙を修正しました

ロックの再取得の問題によりオーバーロードのリーダー選出が失敗する問題を修正しました。ドルイドはこれらのタスクに失敗し、オーバーロードのリーダー選挙が妨げられないようにすべてのロックをクリアします。 https://github.com/apache/druid/pull/13172

<a name="25-ingestion-support-for-inline-protobuf-descriptor" href="#25-ingestion-support-for-inline-protobuf-descriptor">#</a> インライン protobuf 記述子のサポート

新しい inline タイプ protoBytesDecoder が追加されました。これにより、ユーザーは、Base64 文字列としてエンコードされた Protobuf 記述子ファイルの内容をインラインで渡すことができます。 https://github.com/apache/druid/pull/13192

<a name="25-ingestion-duplicate-notices" href="#25-ingestion-duplicate-notices">#</a> 重複した通知

ストリーミング取り込みの場合、すでにキューにある通知と同じ通知はキューに入れられません。これは、通知キューのサイズを減らすのに役立ちます。 https://github.com/apache/druid/pull/13334

<a name="25-ingestion-sampling-from-stream-input-now- respects-the-configured-timeout" href="#25-ingestion-sampling-from-stream-input-now- respects-the-configured-timeout">#</a> ストリーム入力からのサンプリングでは、設定されたタイムアウトが考慮されるようになりました

ストリームに利用可能なレコードがない場合に、Kafka や Kinesis などのストリーム入力からのサンプリングが設定されたタイムアウトを遵守できない問題を修正しました。エントリ反復子が結果を返す最大時間を設定できるようになりました。 https://github.com/apache/druid/pull/13296

<a name="25-ingestion-streaming-tasks-resume-on-overlord-switch" href="#25-ingestion-streaming-tasks-resume-on-overlord-switch">#</a> Overlord スイッチでストリーミング タスクが再開されます

オーバーロード リーダーがタスクに一時停止を発行した後、ストリーミング インジェスト タスクが期間が経過するまで実行され続ける問題を修正しました。現在、タスクに一時停止を発行した直後にオーバーロードの切り替えが発生すると、オーバーロードの再選出後もタスクは一時停止状態のままになります。 https://github.com/apache/druid/pull/13223

<a name="25-ingestion-fixed-parquet-list-conversion" href="#25-ingestion-fixed-parquet-list-conversion">#</a> 固定された Parquet リスト変換

複雑なオブジェクトのリストが予期せず追加のオブジェクトでラップされ、直接リストではなく [{"element":<actual_list_element>},{"element":<another_one>}...] として表示される可能性がある、Parquet リスト変換に関する問題を修正しました。これにより、構造化オブジェクトのリストに対する寄木細工リーダーの動作が変更され、他の寄木細工論理リスト変換と一貫性が保たれます。データは直接フェッチされ、予想される構造とより厳密に一致するようになりました。 https://github.com/apache/druid/pull/13294

<a name="25-ingestion-introduced-a-tree-type-to- flattenspec" href="#25-ingestion-introduced-a-tree-type-to- flattenspec">#</a> flattenSpec にツリー タイプを導入しました

flattenSpecにtreeタイプを追加。単純な階層検索が必要な場合、tree タイプを使用すると、jq および path 解析タイプよりも高速な JSON 解析が可能になります。 https://github.com/apache/druid/pull/12177

<a name="25-operations" href="#25-operations">#</a> オペレーション

<a name="25-operations-compaction" href="#25-operations-compaction">#</a> 圧縮

圧縮にかかる時間と必要なディスク容量を改善するために、圧縮の動作が変更されました。

  • セグメントを取得する必要がある場合は、セグメントを一度に 1 つずつダウンロードし、Druid がセグメントを使い終わったら削除します。これにはまだ時間がかかりますが、必要なディスク容量は最小限に抑えられます。
  • セグメントが必要でない場合は、メインのコンパクト タスクでセグメントをフェッチしないでください。ユーザーが完全な granularitySpec、dimensionsSpec、metricsSpec を指定した場合、Druid はセグメントのフェッチをスキップします。 詳細については、圧縮 および 自動圧縮 に関するドキュメントを参照してください。 https://github.com/apache/druid/pull/13280

<a name="25-operations-idle-configs-for-the-supervisor" href="#25-operations-idle-configs-for-the-supervisor">#</a> スーパーバイザのアイドル設定

スーパーバイザをアイドル状態に設定できるようになりました。これは、スロットを解放して自動スケーリングをより効果的にする場合に便利です。 アイドル動作を構成するには、次のプロパティを使用します。 |プロパティ |説明 |デフォルト | | - | - | -| |druid.supervisor.idleConfig.enabled| (クラスター全体) true の場合、入力ストリーム/トピックにデータがしばらく存在しない場合、スーパーバイザーはアイドル状態になる可能性があります。|false| |druid.supervisor.idleConfig.inactiveAfterMillis| (クラスター全体) すべての既存データが入力トピックから読み取られ、inactiveAfterMillis ミリ秒間新しいデータが発行されなかった場合、スーパーバイザーはアイドルとしてマークされます。 | inactiveAfterMillis | (個別スーパーバイザー) すべての既存データが入力トピックから読み取られ、inactiveAfterMillis ミリ秒間新しいデータが発行されなかった場合、スーパーバイザーはアイドルとしてマークされます。 |いいえ (デフォルト == 600_000) | https://github.com/apache/druid/pull/13311

<a name="25-operations-segment-loading-and-balancing" href="#25-operations-segment-loading-and-balancing">#</a> セグメントのロードとバランシング

<a name="25-operations-batch-allocation" href="#25-operations-batch-allocation">#</a> バッチ化されたセグメント割り当て

オーバーロードでのセグメント割り当ては完了するまでに時間がかかる場合があり、タスクがセグメントの割り当てを待機している間に取り込みラグが発生する可能性があります。 セグメント割り当てをバッチで実行すると、パフォーマンスの向上に役立ちます。 Druid がセグメント割り当てを実行する方法に影響を与える 2 つの新しいプロパティがあります。 |プロパティ |説明 |デフォルト | | - | - | - | |druid.indexer.tasklock.batchSegmentAllocation| true に設定すると、Druid はセグメント割り当てアクションをバッチで実行して、スループットを向上させ、平均 task/action/run/time を削減します。詳細については、segmentAllocate アクションのバッチ処理 を参照してください。 |druid.indexer.tasklock.batchAllocationWaitTime|Druid が最初のセグメント割り当てアクションをバッチに追加してから、バッチが実行されるまでのミリ秒数。バッチでさらに多くのリクエストを追加し、平均セグメント割り当て実行時間を改善できるようにします。この構成は、batchSegmentAllocation が有効な場合にのみ有効になります。|500| これらのプロパティに加えて、バッチ セグメントの割り当てを追跡するための新しいメトリックがあります。詳細については、「セグメント割り当ての新しいメトリクス」(#new-metrics-for-segment-allocation) を参照してください。 詳細については、以下を参照してください。

  • オーバーロードオペレーション
  • タスクアクションとバッチ処理segmentAllocateアクション https://github.com/apache/druid/pull/13369 https://github.com/apache/druid/pull/13503

<a name="25-operations-segment-loading-and-balancing-cachingcost-balancer-strategy" href="#25-operations-segment-loading-and-balancing-cachingcost-balancer-strategy">#</a> cachingCost バランサー戦略の改善

cachingCost バランサー戦略は、コスト戦略とより似た動作をするようになりました。セグメントをサーバーに移動するコストを計算する場合、次の計算が実行されます。

  • セグメントがターゲットサーバーによってサービスされている場合は、セグメントの自己コストを減算します。
  • 削除するようにマークされているセグメントのコストを減算します。 https://github.com/apache/druid/pull/13321

<a name="25-operations-segment-loading-and-balancing-segment-assignment" href="#25-operations-segment-loading-and-balancing-segment-assignment">#</a> セグメント割り当ての高速化

ラウンドロビン セグメント戦略を使用して、最初のセグメント割り当てを高速化できるようになりました。この機能を有効にするには、コーディネーターの動的構成で useRoundRobinSegmentAssigment を true に設定します。 https://github.com/apache/druid/pull/13367

<a name="25-operations-segment-batch-sampling" href="#25-operations-segment-batch-sampling">#</a> 貸借一致セグメントのバッチ サンプリングがデフォルトになります

バッチ サンプリングは、クラスター内に使用されているセグメントが多数ある場合に代替方法よりも大幅にパフォーマンスが向上するため、バランシング中のセグメントのサンプリングのデフォルトの方法になりました。 この変更の一環として、以下は非推奨となり、将来のリリースでは削除される予定です。

  • コーディネーター動的構成 useBatchedSegmentSampler
  • コーディネーター動的構成 percentOfSegmentsToConsiderPerMove
  • セグメントをサンプリングする古い非バッチ方式

<a name="25-operations-segment-unused-property" href="#25-operations-segment-unused-property">#</a> 未使用のプロパティを削除します

未使用のコーディネーター プロパティ druid.coordinator.loadqueuepeon.repeatDelay は削除されました。 HTTP ベースのセグメント読み込みキューの繰り返し遅延を構成するには、druid.coordinator.loadqueuepeon.http.repeatDelay のみを使用します。 https://github.com/apache/druid/pull/13391

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> デフォルトの HTTP ベースのセグメント検出とタスク管理

デフォルトのセグメント検出方法では、ZooKeeper の代わりに HTTP が使用されるようになりました。 この更新により、次のプロパティのデフォルトが変更されます。 |プロパティ |新しいデフォルト |以前のデフォルト | | - | - | - | | druid.serverview.type セグメント管理用 | http |バッチ | | druid.coordinator.loadqueuepeon.type セグメント管理用 | http |キュレーター | |オーバーロード用druid.indexer.runner.type | httpリモート |ローカル | HTTP の代わりに ZooKeeper を使用するには、プロパティの値を以前のデフォルトに戻します。これらのプロパティの ZooKeeper ベースの実装は非推奨となり、後続のリリースで削除される予定です。 https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> HLL および分位数スケッチ集合の最終処理

HLL および分位数スケッチの集計関数は、ネイティブ クエリ プランのどこにあったかに応じて、完成時にスケッチまたは数値を返しました。 Druid は、次の 2 つの場合にアグリゲータをファイナライズしなくなりました。

  • アグリゲータはクエリの外側のレベルに表示されます。
  • アグリゲータは、式またはファイナライズフィールドアクセスポストアグリゲータへの入力として使用されます。 この変更により、HLL および分位点スケッチの動作がシータ スケッチと調整されます。 以前の動作を復元するには、クエリ コンテキストで sqlFinalizeOuterSketches=true を設定します。 https://github.com/apache/druid/pull/13247

kill タスクを発行すると、明示的に指定されている場合にのみ、Druid は基礎となるセグメントを未使用としてマークします。詳細については、API リファレンス を参照してください。 https://github.com/apache/druid/pull/13104
