#ドルイドドルイド-37.0.0

Apache Druid 37.0.0 には、255 を超える新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 29 人の寄稿者による追加のテスト カバレッジが含まれています。

バグ修正などの詳細については、完全な変更セット を参照してください。

Druid 37.0.0 にアップグレードする前に、アップグレードに関する注意事項 と 互換性のない変更 を確認してください。 複数のバージョンにまたがってアップグレードする場合は、最新の Druid バージョンのアップグレード ノートがリストされている アップグレード ノート ページを参照してください。

重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

Hadoop ベースの取り込み

Hadoop ベースの取り込みのサポートは削除されました。この機能は Druid 34 で非推奨になりました。

SQL ベースの取り込みや、Kubernetes を使用した MiddleManager なしの取り込みなど、Druid でサポートされている他の取り込み方法のいずれかを使用します。

#19109

クエリブロックリスト

ブローカー API (/druid/coordinator/v1/config/broker) を使用してクエリ ブロックリストを作成し、データソース、クエリ タイプ、またはクエリ コンテキストごとにクエリを動的にブロックできるようになりました。ブロックリストは、Druid を再起動しなくても有効になります。ブロック ルールは AND ロジックを使用します。これは、すべての条件が一致する必要があることを意味します。

次の例では、0 と等しい priority のクエリ コンテキスト パラメーターを使用して、wikipedia データソース上のすべての groupBy クエリをブロックします。

POST /druid/coordinator/v1/config/broker
  {
    "queryBlocklist": [
      {
        "ruleName": "block-wikipedia-groupbys",
        "dataSources": ["wikipedia"],
        "queryTypes": ["groupBy"],
        "contextMatches": {"priority": "0"}
      }
    ]
  }

#19011

オーバーロードベースの圧縮のためのマイナー圧縮 (実験的)

既存の圧縮されたセグメントをアップグレードしながら、新しく取り込まれたセグメントのみを圧縮するようにマイナー圧縮を構成できるようになりました。 Druid がセグメントをアップグレードすると、リソースを使用してメタデータを再度圧縮するのではなく、メタデータが更新されます。ネイティブ圧縮エンジンまたは MSQ タスク エンジンを使用できます。

mostFragmentedFirst 圧縮ポリシーを使用して、マイナー圧縮の行ベースまたはバイトベースのしきい値の割合を設定します。

#19059 #19205 #19016

カスケード再インデックス (実験的)

カスケード再インデックスを使用すると、経過時間ベースのルールを定義して、データの経過時間に基づいてさまざまな圧縮構成を自動的に適用できるようになりました。標準の自動圧縮ではデータソース全体に単一のフラットな構成が適用されますが、カスケード再インデックスを使用すると、圧縮設定をデータの特性に合わせて調整できます。

たとえば、最近のデータを時間単位のセグメントに保持しながら、90 日後に自動的に日単位のセグメントにロールアップしてセグメント数を減らすことができます。また、経過時間に基づく行の削除 (古いデータからのボット トラフィックの削除など) を重ねたり、圧縮設定を変更したり、データの経過に応じてより粗いクエリ粒度でロールアップに移行したりすることもできます。ルールはスーパーバイザ仕様でインラインで定義されます。

カスケード再インデックスを使用するには、MSQ タスク エンジンで圧縮スーパーバイザーを使用する必要があります。

#18939 #19213 #19106 #19078

マルチスーパーバイザーの取り込み

マルチスーパーバイザーの取り込みが一般提供されるようになりました。同じデータソースに取り込む複数のストリーム スーパーバイザを実行できます。

#18983

読み取り専用オーソライザー

Druid に ReadOnly オーソライザーを追加しました。これはドルイドの最初の世界的承認者です。オーソライザーは、すべての非読み取り操作にグローバル制限を適用し、個々のユーザーの権限に関係なくそれらの操作を拒否します。この機能を使用すると、特定の承認者のすべてのユーザーが読み取りアクセスに制限されるようにすることができます。

GET /druid/indexer/v1/supervisor など、一部のエンドポイントは現在読み取り専用であるにもかかわらず書き込みアクセスを必要とするという既知の制限があります。これらの操作は失敗します。

#19243

節約入力フォーマット

Thrift コントリビューター拡張機能の一部として、Druid は、InputFormat を使用した Kafka および Kinesis ストリーミング取り込み用の Thrift エンコードされたデータをサポートするようになりました。以前、Druid はパーサーを通じてこれをサポートしていましたが、Druid 37 では削除されました。

#19111

この機能を使用するには、拡張機能ロード リストに druid-thrift-extensions を追加する必要があります。

増分キャッシュ

増分セグメント メタデータ キャッシュ (useIncrementalCache) が一般提供され、デフォルトは ifSynced になります。 Druid は、リーダーになった後、メタデータ ストアと少なくとも 1 回同期するまで、キャッシュからの読み取りをブロックします。

#19252

Kubernetes ベースのタスク管理

この拡張機能は現在一般提供されています。

#19128

動的デフォルトのクエリコンテキスト

デフォルトのクエリ コンテキスト パラメータを動的構成としてブローカーに追加できるようになりました。これにより、展開を再起動したり、複数のクエリを個別に更新したりすることなく、ランタイム プロパティに設定された静的デフォルトをオーバーライドできます。 Druid は、次の優先順位に基づいてクエリ コンテキスト パラメータを適用します。

  1. クエリに含まれるクエリ コンテキスト
  2. ブローカー上で動的構成として設定されたクエリ コンテキスト
  3. ランタイムプロパティに設定されたクエリコンテキストパラメータ
  4. Druid に同梱されるデフォルト

他のブローカーの動的構成と同様、これはベストエフォートであることに注意してください。一部の環境では設定が適用されない場合があります ブローカーが最近開始されたがまだ構成を受け取っていない場合、または ブローカーはコーディネーターに連絡できません。クエリ コンテキスト パラメーターがすべてのクエリにとって重要な場合は、実行時プロパティで設定します。

#19144

sys.queries テーブル (実験的)

新しいシステム クエリ テーブルは、Dart エンジンを使用する現在実行中のクエリと最近完了したクエリに関する情報を提供します。このテーブルはデフォルトではオフになっています。テーブルを有効にするには、次のように設定します。

druid.sql.planner.enableSysQueriesTable = true

この変更の一環として、/druid/v2/sql/queries API は、最近完了したクエリを表示する includeComplete パラメーターをサポートするようになりました。

#18923

圧縮スーパーバイザーによる自動圧縮

圧縮スーパーバイザーを使用した自動圧縮が改善され、一般提供され、デフォルトとして推奨されています。自動圧縮タスクには、coordinator-issued ではなく auto というプレフィックスが付けられるようになりました。

改善の一環として、圧縮状態は中央の場所である新しい indexingStates テーブルに保存されるようになりました。個々のセグメントは、完全な圧縮状態への一意の参照 (indexing_state_fingerprint) を保存するだけで済みます。

単一のデータソース内の多くのセグメントが同じ基礎となる圧縮状態を共有するため、自動圧縮のためのメタデータ ストレージ要件が大幅に軽減されます。

下位互換性のために、Druid は各セグメントの詳細な圧縮状態を保持し続けます。この機能は将来のリリースでは削除される予定です。 クラスター圧縮構成で storeCompactionStatePerSegment を false に設定することで、詳細な圧縮状態の保存を停止できます。これをオフにしてダウングレードする必要がある場合、Druid は構成を変更してから圧縮されたセグメントを再圧縮する必要があります。

この変更は、メタデータ ストレージとメタデータ キャッシュのアップグレードに影響を与えます。詳細については、圧縮スーパーバイザーを使用した自動圧縮のためのメタデータ ストレージ のアップグレード ノートを参照してください。

#19113 #18844 #19252

リアルタイム サーバーのブローカー層の選択

ブローカーに druid.broker.realtime.select.tier および druid.broker.realtime.balancer.type を追加し、リアルタイム サーバーのブローカーの層選択とバランサー戦略をオプションでオーバーライドします。これらのプロパティが設定されていない場合 (デフォルト)、リアルタイム サーバーは、ヒストリカル サーバーとリアルタイム サーバーの両方に適用される既存の druid.broker.select および druid.broker.balancer 構成を引き続き使用します。

#19062

Web コンソールでの手動ブローカー ルーティング

Web コンソールから発行されたクエリにルーターがどのブローカーを使用するかを設定できるようになりました。特定のデータ層を参照できないブローカーがあり、特定の層でのみ利用可能なデータをクエリしていることがわかっている場合は、これを実行するとよいでしょう。

ブローカーを指定するには、次の構成を web-console/console-config.js に追加します。

consoleBrokerService: 'druid/BROKER_NAME'

#19069

領事の内線番号

コントリビューター拡張機能 druid-consul-extensions により、Druid クラスターはサービス検出に Consul を使用できるようになり、 ZooKeeperの代わりにコーディネーター/オーバーロードのリーダー選挙。この拡張機能は、ACL、TLS/mTLS、およびメトリクスをサポートしています。

Consul に切り替える前に、次のことを設定する必要があります。 druid.serverview.type=http および druid.indexer.runner.type=httpRemote クラスター幅。

Druid は、指定された長さを超える文字列を切り捨てます。デフォルトでは、文字列値は切り捨てられません。

クエリを実行する

groupBy クエリ構成

クエリごとに作成される予備ファイルの最大数を制限するために、新しい groupBy クエリ構成プロパティ druid.query.groupBy.maxSpillFileCount を追加しました。制限を超えると、スピル ファイルのマージ中に履歴ノードのメモリ不足が発生するのではなく、クエリは失敗し、明確なエラー メッセージが表示されます。この制限は、クエリ コンテキスト パラメーター maxSpillFileCount を使用してクエリごとにオーバーライドすることもできます。

#19141

ネストされた集計の処理の改善

Druid は、間に投影を使用して 2 つの集約をマージできるようになりました。たとえば、次のクエリ:

SELECT
  hr,
  UPPER(t1.x) x,
  SUM(t1.cnt) cnt,
  MIN(t1.mn) mn,
  MAX(t1.mx) mx
FROM (
  SELECT
    floor(__time to hour) hr,
    dim2 x,
    COUNT(*) cnt,
    MIN(m1 * 5) mn,
    MAX(m1 + m2) mx
  FROM druid.foo
  WHERE dim2 IN ('abc', 'def', 'a', 'b', '')
  GROUP BY 1, 2
) t1
WHERE t1.x IN ('abc', 'foo', 'bar', 'a', '')
GROUP BY 1, 2

次のように単純化できます。

SELECT
  FLOOR(__time TO hour) hr,
  UPPER(dim2) x,
  COUNT(*) cnt,
  MIN(m1 * 5) mn,
  MAX(m1 + m2) mx
FROM druid.foo
WHERE dim2 IN ('abc', 'a', '')
GROUP BY 1, 2

クラスター管理

新しいブローカー層の選択戦略

オペレーターは、2 つの新しいブローカー TierSelectorStrategy 実装を構成できるようになりました。

  • strict - 優先順位が設定されたリストと一致するサーバーのみを選択します。構成例: druid.broker.select.tier=strict および druid.broker.select.tier.strict.priorities=[1]。
  • pooled - 構成された優先順位全体でサーバーをプールし、その中から選択することで、クエリで複数の優先順位層を使用して可用性を向上させることができます。構成例: druid.broker.select.tier=pooled および druid.broker.select.tier.pooled.priorities=[2,1]。

druid.broker.realtime.select.tier を使用して、リアルタイム サーバー用にこれらの戦略を構成することもできます。

データ管理

セグメントごとのタイムアウト設定

動的構成を使用して、特定のデータソース内のセグメントのタイムアウトを設定できるようになりました。

POST /druid/coordinator/v1/config/broker
  {
    "perSegmentTimeoutConfig": {
      "my_large_datasource": { "perSegmentTimeoutMs": 5000, "monitorOnly": false },
      "my_new_datasource": { "perSegmentTimeoutMs": 3000, "monitorOnly": true }
    }
  }

これは、データソースごとに異なるパフォーマンス特性がある場合に便利です。たとえば、大規模なデータセットに対してより長いタイムアウトを許可する場合などです。

#19221

耐久性のあるストレージクリーナー

耐久性のあるストレージ クリーナーは、MSQ クエリ結果の構成可能な時間ベースの保持をサポートするようになりました。以前は、クエリ結果はすべての既知のタスクに対して保持されており、完了したタスクの信頼性が低かった。この変更により、クエリ結果は、タスクの作成時間に基づいて構成可能な期間保持されます。

新しい構成プロパティ druid.msq.intermediate.storage.cleaner.durationToRetain は、クエリ結果の保存期間を制御します。デフォルトの保存期間は 6 時間です。

#19074

  • HDFS ストレージ上の中間ファイルを自動的にクリーンアップするメカニズムを追加しました #19187

メトリクスとモニタリング

buildRevision フィールド

すべての Druid メトリクスには、メトリクスを発行する Druid サーバーの Git ビルド リビジョンを識別するのに役立つ buildRevision フィールドが含まれるようになりました。この情報を使用して、クラスター内のすべてのノードが意図したリビジョンを実行していることを確認できます。

#19123

スーパーバイザ状態の監視

druid.monitoring.monitors で SupervisorStatsMonitor が有効になっている場合の新しい supervisor/count メトリックが追加されました。このメトリックは、Prometheus、StatsD、およびその他のメトリック システムの各スーパーバイザの状態 (RUNNING または SUSPENDED など) を報告します。

メトリクスのフィルタリング

オペレーターは、druid.emitter.logging.shouldFilterMetrics=true を設定して、ロギング エミッターが書き込むメトリックを制限できます。オプションで、キーがメトリック名である druid.emitter.logging.allowedMetricsPath を JSON オブジェクト ファイルに設定できます。カスタム ファイルが見つからない場合は、警告が表示され、バンドルされている loggingEmitterAllowedMetrics.json が使用されます。アラートおよびその他の非メトリック イベントは常にログに記録されます。

拡張機能

Kubernetes

kubernetes-overlord-extensions の Vert.x HTTP client 用の新しい WebClientOptions パススルーを追加しました。オペレーターは、Druid ランタイム プロパティを使用して、基礎となる Vert.x WebClientOptions オブジェクトのプロパティを構成できるようになりました。構成できるオプションには、接続プール サイズ、キープアライブ タイムアウト、アイドル タイムアウトなどがあります。これは、アイドル状態の接続を閉じる中間ロード バランサーを備えた環境で特に役立ちます。ほとんどの Druid 導入では、この構成は必要ありません。

#19071

gRPC

gRPC クエリ拡張機能は、client がキャンセルまたは切断されたときに実行中のクエリをキャンセルするようになりました。

氷山

Iceberg 入力ソースが GCS ウェアハウスをサポートするようになりました。この機能を使用するには、Iceberg 拡張機能に加えて druid-google-extensions 拡張機能をロードする必要があります。 #19137

フィルター

Iceberg 入力ソースを使用するときに、非パーティション列の残差フィルターを構成できるようになりました。 Iceberg 入力ソースの residualFilterMode を次のいずれかに設定します。

  • ignore: (デフォルト) transformSpec でフィルターされない限り、警告ログを含む残りの行を取り込みます。
  • fail: 残留フィルターが検出された場合、取り込みジョブは失敗します。これを使用して、フィルターがパーティション列のみをターゲットにするようにします。

#18982

アップグレードに関する注意事項と互換性のない変更

アップグレードに関する注意事項

Hadoop ベースの取り込み

Hadoop ベースの取り込みのサポートは削除されました。この機能は Druid 34 で非推奨になりました。

SQL ベースの取り込みや、Kubernetes を使用した MiddleManager なしの取り込みなど、Druid でサポートされている他の取り込み方法のいずれかを使用します。

#19109

AWS SDK v2

SDK の v1 がサポート終了になったため、Druid は現在、AWS SDK バージョン 2.40.0 を使用しています。

#18891

セグメント メタデータ キャッシュはデフォルトでオンになります

Druid 37 以降、セグメント メタデータ キャッシュはデフォルトでオンになります。この機能により、ブローカーは、sys.segments テーブルに対するクエリごとにメタデータをフェッチするのではなく、コーディネーターからポーリングされたセグメント メタデータをキャッシュできるようになります。これによりパフォーマンスは向上しますが、ブローカーのメモリ使用量が増加します。

druid.sql.planner.metadataSegmentCacheEnable 構成は、この機能を制御します。

#19075

パーサーの変更

ストリーミング インジェスト parser

Kafka や Kinesis などのストリーミング取り込みタスクでは、非推奨の parser のサポートが削除されました。オペレーターは、スーパーバイザー仕様の ioConfig で inputSource/inputFormat を指定する必要があり、dataSchema でパーサーを指定してはなりません。 Druid 37 以降にアップグレードする前にこれを行ってください。

#19173 #19166

ParseSpec と非推奨のパーサーを削除

ネイティブ バッチ タスクおよびストリーミング インジェスト インデックス サービス用のパーサーは削除されました。可能な場合は、代わりに入力形式を使用してください。 JavascriptParseSpec と JSONLowercaseParseSpec には同等の InputFormat がないことに注意してください。

Druid はカスタム テキスト データ形式をサポートしており、正規表現入力形式を使用してそれらを解析できます。ただし、これを行う場合は注意してください データの解析は、ネイティブ Java InputFormat 拡張機能を作成するか、外部ストリーム プロセッサを使用するよりも効率が低くなります。新しい入力形式の貢献を歓迎します。

#19239

バージョン 0.23 より前の Druid バージョンからのローリング アップグレード

Druid 0.23 より前のバージョンからローリング アップグレードを実行することはできません。

#18961

圧縮スーパーバイザーによる自動圧縮のためのメタデータ ストレージ

スーパーバイザによる自動圧縮には、オーバーロード上の増分セグメント メタデータ キャッシュと新しいメタデータ ストア テーブルが必要です。次の構成のデフォルト設定を使用している場合、アクションは必要ありません。

  • druid.manager.segments.useIncrementalCache
  • druid.metadata.storage.connector.createTables

druid.manager.segments.useIncrementalCache が never に設定されている場合は、ifSynced または always に更新します。構成の詳細については、「セグメント メタデータ キャッシュ」(https://druid.apache.org/docs/latest/configuration/#segment-metadata-cache-experimental) を参照してください。

druid.metadata.storage.connector.createTables 構成を false に設定する場合は、セグメント テーブルを手動で変更し、compactionStates テーブルを作成する必要があります。 Postgres DDL はガイドとして以下に提供されています。

-- create the indexing states lookup table and associated indices
CREATE TABLE druid_indexingStates (
    created_date VARCHAR(255) NOT NULL,
    datasource VARCHAR(255) NOT NULL,
    fingerprint VARCHAR(255) NOT NULL,
    payload BYTEA NOT NULL,
    used BOOLEAN NOT NULL,
    pending BOOLEAN NOT NULL,
    used_status_last_updated VARCHAR(255) NOT NULL,
    PRIMARY KEY (fingerprint),
  );

  CREATE INDEX idx_druid_compactionStates_used ON druid_compactionStates(used, used_status_last_updated);

-- modify druid_segments table to have a column for storing compaction state fingerprints
ALTER TABLE druid_segments ADD COLUMN indexing_state_fingerprint VARCHAR(255);

テーブルの名前付けプレフィックスとメタデータ ストア バックエンドに合わせて構文を調整する必要がある場合があります。

#18844

セグメントのロック

セグメント ロックと NumberedOverwriteShardSpec は非推奨であり、将来のリリースで削除される予定です。代わりにタイムチャンクロックを使用してください。 druid.indexer.tasklock.forceTimeChunkLock をデフォルトの true に設定することで、時間チャンクロックのみが使用されるようにすることができます。

#19050

この構成により、最初のメトリクスが利用可能になる前にスケーリング アクションを開始できるようになりました。

#19028
