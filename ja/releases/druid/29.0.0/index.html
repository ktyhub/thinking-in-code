<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT およびUNPIVOT (実験的)

Druid 29.0.0 は、SQL PIVOT および UNPIVOT 演算子の実験的なサポートを追加します。

PIVOT 演算子は集計を実行し、出力の行を列に変換します。以下は、PIVOT 演算子の一般的な構文です。

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

UNPIVOT 演算子は、既存の列の値を行に変換します。 UNPIVOT 演算子の一般的な構文は次のとおりです。

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> ウィンドウ関数での範囲サポート (実験的)

ウィンドウ関数 (実験的) は、両方のエンドポイントが制限されていない範囲、または現在の行である範囲をサポートするようになりました。範囲は厳密モードで機能します。つまり、Druid はサポートされていないクエリに失敗します。コンテキスト パラメーター windowingStrictValidation を false に設定することで、範囲の厳密モードをオフにできます。

次の例は、RANGE フレーム仕様を使用したウィンドウ式を示しています。

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

Druid は、INNER 結合の任意の結合条件をサポートするようになりました。結合の一部として評価できないサブ条件は、結合後のフィルターに変換されます。結合機能の向上により、Druid は Tableau などのアプリケーションをより効果的にサポートできるようになりました。

配列を含む混合型 auto 列の 等価フィルター は、その提示型としてフィルター処理する必要があります。これは、行が配列である場合 (たとえば、セグメント メタデータと information_schema がその型を何らかの配列型として報告する)、ネイティブ クエリも何らかの配列型であるかのようにフィルター処理する必要があることを意味します。

この変更は、スカラーと配列の両方を含む混合型 auto 列に影響します。 SQL には影響しませんが、SQL には型の表現方法によりすでにこの制限があります。

#15503

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-console-automatically-sets-arrayingestmode-for-msq-queries" href="#29.0.0-upgrade-notes-and-incompatible-console-automatically-sets-arrayingestmode-for-msq-queries">#</a> コンソールは MSQ クエリに対して arrayIngestMode を自動的に設定します

Druid コンソールはデータ読み込みフローで arrayIngestMode パラメータを設定するようになり、その値は手動で更新しない限り [SQL] タブ全体で保持されるようになりました。したがって、Druid Web コンソールに複数値のディメンションまたは配列をロードするときは、データ ソースの同じ列に MVD と配列が誤って混在しないように、arrayIngestMode パラメーターの値に注意してください。

#15588

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-improved-concurrent-append-and-replace-%28experimental%29" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-improved-concurrent-append-and-replace-%28experimental%29">#</a> 同時追加と置換の改善 (実験的)

taskLockType タスク コンテキストで同時追加および置換 (実験的) のタスク ロック タイプを手動で決定する必要がなくなりました。代わりに、Druid が自動的にそれを決定できるようになりました。個々のタスクおよびデータソースに対してコンテキスト パラメーター "useConcurrentLocks": true を使用することも、druid.indexer.task.default.context を使用してクラスター レベルで同時追加と置換を有効にすることもできます。

#15684

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-empty-ingest-queries" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-empty-ingest-queries">#</a> 空の取り込みクエリを有効にしました

MSQ タスク エンジンでは、デフォルトで空の取り込みクエリが許可されるようになりました。出力行を生成しないクエリの場合、MSQ タスク エンジンは、numTotalRows および totalSizeInBytes に対して null ではなくゼロ値を報告します。以前は、データを生成しない取り込みクエリは InsertCannotBeEmpty MSQ エラーで失敗していました。

元の動作に戻すには、MSQ クエリ パラメーター failOnEmptyInsert を true に設定します。

#15495 #15674

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-query-request-queuing-by-default-when-total-laning-is-turned-on" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-query-request-queuing-by-default-when-total-laning-is-turned-on">#</a> トータル レーンニングがオンになっている場合、クエリ リクエストのキューイングがデフォルトで有効になりました

クエリ スケジューラのスレッドがサーバーの HTTP スレッドよりも少ない場合、トータル レーニングがオンになります。 これにより、ヘルスチェックなどのクエリ以外のリクエスト用に一部の HTTP スレッドが予約されます。 以前の合計レーンニングでは、レーン容量を超えるクエリ要求は拒否されていました。 今後は、過剰なリクエストは MIN(Integer.MAX_VALUE, druid.server.http.maxQueryTimeout) に等しいタイムアウトでキューに入れられます。

#15440

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-empty-or-null-array-columns-are-stored" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-empty-or-null-array-columns-are-stored">#</a> 空または null の配列列の格納方法を変更しました

自動列インデクサーで取り込まれた空の配列または null 配列のみを含む列は、COMPLEX<json\> ではなく ARRAY<LONG\> として保存されるようになりました。

#15505

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-druid-allocates-weekly-segments" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-druid-allocates-weekly-segments">#</a> Druid が週次セグメントを割り当てる方法を変更しました

要求された粒度が 1 か月以上であるにもかかわらずセグメントを割り当てることができない場合、Druid は日分割を使用します。 明示的に指定しない限り、Druid はデータ パーティショニングの週単位のセグメントをスキップします。これは、これらのセグメントが月末またはより粗い間隔と一致しないためです。

#15589

<a name="29.0.0-upgrade-notes-and-incompatible-changes-removed-the-%60auto%60-search-strategy" href="#29.0.0-upgrade-notes-and-incompatible-changes-removed-the-%60auto%60-search-strategy">#</a> auto 検索戦略を削除しました

ネイティブ検索クエリから auto 検索戦略を削除しました。 searchStrategy を auto に設定すると、useIndexes と同等になります。

<a name="29.0.0-upgrade-notes-and-incompatible-changes-developer-notes-improved-%60indimfilter%60-reverse-lookup-optimization" href="#29.0.0-upgrade-notes-and-incompatible-changes-developer-notes-improved-%60indimfilter%60-reverse-lookup-optimization">#</a> InDimFilter 逆引き最適化の改善

この改善には次の変更が含まれます。

  • DimFilter#optimize に mayIncludeUnknown パラメータを追加しました。
  • InDimFilter#optimizeLookup が mayIncludeUnknown を処理し、より幅広いケースで逆引き参照を実行できるようになりました。
  • LookupExtractor で unapply メソッドを作成し、呼び出し元を保護し、呼び出し元を unapplyAll に再配置しました。

拡張機能が DimFilter を提供する場合、このリリースとの互換性を確保するために拡張機能を再構築する必要がある場合があります。
