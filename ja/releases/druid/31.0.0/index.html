<a name="31.0.0-important-features-changes-and-deprecations-projections-experimental" href="#31.0.0-important-features-changes-and-deprecations-projections-experimental">#</a> 投影 (実験的)

Druid 31.0.0 には、プロジェクションと呼ばれる新機能の実験的なサポートが含まれています。プロジェクションはグループ化されたセグメントの事前集計であり、処理が必要な行数を減らすことで計算と I/O コストの両方を削減することで、プロジェクションの形状に「適合」するクエリの実行を最適化するためにクエリ時に自動的に使用されます。プロジェクションはデータソースのセグメント内に含まれるため、セグメント サイズが増加します。ただし、辞書エンコードされた列の値辞書などのデータを、基本セグメントの列と共有できます。

現在、プロジェクションは JSON ベースの取り込みのみをサポートしていますが、MSQ タスク エンジンまたは新しい Dart エンジンを使用するクエリで使用できます。将来の開発では、SQL ベースの取り込みの一部としてプロジェクションを作成できるようになる予定です。

今後のリリースでこの機能を改善し続ける計画はたくさんありますが、プロジェクションによってクエリのパフォーマンスが大幅に向上する可能性があるため、ユーザーが実験を開始できるようにこの機能を公開できることに興奮しています。

詳細については、「投影」(#31.0.0-functional-areas-and-related-changes-querying-projections) を参照してください。

<a name="31.0.0-important-features%2C-changes%2C-and-deprecations-low-latency-high-complexity-queries-using-dart-%28experimental%29" href="#31.0.0-important-features%2C-changes%2C-and-deprecations-low-latency-high-complexity-queries-using-dart-%28experimental%29">#</a> Dart を使用した低レイテンシの高複雑なクエリ (実験的)

分散非同期ランタイム トポロジ (Dart) は、アドホックなデータ ウェアハウス ワークロードでよく見られる、大規模な結合、高いカーディナリティのグループ化、サブクエリ、共通テーブル式などの複雑性の高いクエリをサポートするように設計されています。 Spark や Presto などのデータ ウェアハウス エンジンを使用して複雑度の高いクエリを実行する代わりに、Dart を使用できるため、追加のインフラストラクチャの必要性が軽減されます。

詳細については、「ダーツ」を参照してください。

以前は、すべてのサービスとタスクがすべてのブロードキャスト データ ソースをダウンロードしていました。 タスクのストレージ領域を節約し、タスクの起動時間を短縮するために、この変更により、タスクの強制終了と MSQ コントローラー タスクが不要なブロードキャスト データ ソースをダウンロードすることがなくなります。他のすべてのタスクは引き続きすべてのブロードキャスト データ ソースを読み込みます。

Dart は、メモリ内シャッフルを実行するマルチスレッド ワーカーを備えたクエリ エンジンで、低レイテンシーの高複雑なクエリに対する調整可能な同時実行性とインフラストラクチャ コストを提供します。

<a name="31.0.0-functional-areas-and-related-changes-querying-projections" href="#31.0.0-functional-areas-and-related-changes-querying-projections">#</a> 投影

実験的な機能として、プロジェクションはまだ十分に文書化されていませんが、dataSchema の一部としてストリーミング インジェストおよび「クラシック」バッチ インジェスト用に定義できます。取り込み仕様の例については、#17214 のプル リクエストの説明 を参照してください。

仕様の groupingColumns フィールドは、投影内でデータが並べ替えられる順序を定義します。実表のように粒度を明示的に定義する代わりに、仮想列を使用して粒度を定義します。取り込み中に、処理ロジックは timestamp_floor 式である「最も細かい」粒度の仮想列を見つけ、それを射影の __time 列として使用します。予測には時間列を定義する必要はありません。このような場合でも、時間通りにグループ化されていないクエリと一致する可能性があります。

プロジェクションの実験を支援するために、新しいクエリ コンテキスト フラグが追加されました。

  • useProjection は特定のプロジェクション名を受け入れ、そのプロジェクションを使用する必要があることをクエリ エンジンに指示します。プロジェクションがクエリと一致しない場合はクエリが失敗します。
  • forceProjections は true または false を受け入れ、クエリ エンジンに射影を使用する必要があることを指示します。一致する射影が見つからない場合はクエリが失敗します。
  • noProjections は true または false を受け入れ、クエリ エンジンに投影を使用しないように指示します。

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> アップグレードに関する注意事項

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array">#</a> 配列取り込みモードがデフォルトで配列になりました

SQL ベースの取り込みコンテキスト フラグ arrayIngestMode は、デフォルトで mvd ではなく array に設定されるようになりました。これは、SQL VARCHAR ARRAY 型が暗黙的に変換されて VARCHAR 列に格納されなくなり、代わりに VARCHAR ARRAY として格納されることを意味します。この変更により、BIGINT ARRAY や DOUBLE ARRAY などの他の配列型を、mvd モードのように失敗することなく、MSQ を使用してそれぞれの配列列型に挿入できるようになります。

引き続き複数値文字列を格納するには、配列型を ARRAY_TO_MV 演算子でラップするように挿入/置換クエリを変更します。

同じテーブル内で VARCHAR 列と VARCHAR ARRAY 列が混在することを防ぐために検証が行われているため、この変更の影響を受ける取り込みは失敗し、予期しない動作を示すのではなく、説明的なエラー メッセージが表示されます。

none の arrayIngestMode オプションは削除されました。これは、クラスター オペレーターがクエリ作成者にクエリ コンテキストで array または mvd を明示的に設定するよう強制する手段として、テーブル検証ロジックより前に導入されましたが、Druid 31 ではほとんど役に立ちません。

詳細については、次のトピックを参照してください。

  • 複数値文字列を取り込む方法については、複数値ディメンションの取り込み を参照してください。
  • 配列を取り込むための 配列の取り込み。

非推奨のタスク アクションの監査ログは削除されました。この変更には次の更新が含まれます。

  • エンドポイント /indexer/v1/task/{taskId}/segments はサポートされなくなりました。
  • Druid は、メタデータ テーブル druid_taskLog への書き込みや読み取りを行いません。
  • Druid はプロパティ druid.indexer.auditlog.enabled を無視します。
  • ドルイドはメトリック task/action/log/time を発行しません。

これらの変更は、既存のすべてのメタデータ ストレージ拡張機能と下位互換性があります。

フロントコーディングされた辞書は、フロント部分が類似している文字列を最適化することでストレージを削減し、パフォーマンスを向上させます。

この機能を有効にすると、この機能をサポートしていない以前のバージョンに簡単にダウングレードすることはできません。

詳細については、「移行ガイド: フロントコーディング辞書」(https://druid.apache.org/docs/latest/release-info/migr-front-coded-dict) を参照してください。 すでにこの機能を使用している場合は、何もする必要はありません。

Druid 31.0.0 には、下位互換性のないストレージの改善が含まれています。 フレキシブル セグメント ソート または 複雑な列の圧縮 を有効にすると、31.0.0 より前のリリースにダウングレードすることはできません。これらの機能を実稼働クラスターにロールアウトする前に、徹底的にテストしてください。

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> 互換性のない変更

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode">#</a> スキャン クエリ レガシー モードを削除しました

ネイティブ スキャン クエリのレガシー モードは削除されました。これは、スキャン クエリが contrib 拡張機能の一部であった Druid の古いバージョンからのアップグレード中に互換性を維持するために、Druid 0.11 で導入されました。

#16659

ローリング アップグレードまたはダウングレード中のエラーを防ぐために、レガシー モードが削除された後、ハードコーディングされた "legacy":false。

#16793

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading">#</a> ZK ベースのセグメントの読み込み

ZK ベースのセグメントのロードが無効になりました。 ZK servedSegmentsPath は Druid 0.7.1 で非推奨になりました。この従来のパスは liveSegmentsPath に置き換えられました。

Peons、Historicals、Indexers などのセグメント提供プロセスは、ZK loadQueuePath エントリを作成しなくなりました。 druid.zk.paths.loadQueuePath および druid.zk.paths.servedSegmentsPath プロパティは使用されなくなりました。

最初に HTTP ベースのセグメント読み込みに移行してから、バージョン アップグレードを実行します。
