#ドルイドドルイド-35.0.0

Apache Druid 35.0.0 には、229 を超える新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 29 人の寄稿者による追加のテスト カバレッジが含まれています。

バグ修正などの詳細については、完全な変更セット を参照してください。

Druid 35.0.0 にアップグレードする前に、アップグレードに関する注意事項 と 互換性のない変更 を確認してください。 複数のバージョンにまたがってアップグレードする場合は、最新の Druid バージョンのアップグレード ノートがリストされている アップグレード ノート ページを参照してください。

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations" href="#35.0.0-important-features%2C-changes%2C-and-deprecations">#</a> 重要な機能、変更点、および非推奨

Druid 35 は Jetty 12 を使用します。この変更は展開に影響を与える可能性があります。詳細については、Jetty 12 のアップグレード ノート を参照してください。

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-java-support" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-java-support">#</a> Java サポート

Druid は Java 21 をサポートするようになりました。Java 21 の一部のバージョン、特に Java 21.05-21.07 はテスト中に問題が発生したことに注意してください。可能であれば、これらのバージョンは避けてください。

さらに、Java 11 のサポートは削除されました。 Java 17 または 21 にアップグレードします。

予測が改善されました:

  • クエリの粒度は UTC タイムゾーンと一致する可能性があります

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29">#</a> 仮想ストレージ (実験的)

仮想ストレージ ファブリック モードにより、歴史サーバーは物理ディスクが保持できる以上のセグメントにサービスを提供できるようになります。セグメントは、公開時にロードされるのではなく、クエリ中にオンデマンドでロードされます。不要なセグメントはディスクから削除されますが、クエリの処理でその特定のセグメントが必要になると、再度ロードされます。

仮想ストレージを有効にするには、druid.segmentCache.virtualStorage を true に設定します。

この機能は実験的なものであり、いくつかの制限があります。詳細については、プル リクエストを参照してください。

#18176

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format">#</a> 新しい入力形式

Druid は lines 入力形式をサポートするようになりました。 Druid は、入力から各行を UTF-8 テキストとして読み取り、行全体を文字列として含む line という名前の単一の列を作成します。これは、後の処理のために単純な形式で行方向のデータを読み取る場合に使用します。

#18433

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine">#</a> マルチステージ クエリ タスク エンジン

MSQ タスク エンジンは、拡張機能ではなく Druid のコア機能になりました。これは、いくつかのリリースのデフォルトの拡張機能ロード リストに含まれています。

アップグレードする前に、common.runtimes.properties の druid.extensions.loadList から druid-multi-stage-query を削除します。

Druid 35.0.0 は、ロード リストにある拡張子を無視します。 Druid の将来のバージョンでは、拡張機能が見つからないため起動に失敗します。

#18394

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-improved-monitor-loading" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-improved-monitor-loading">#</a> モニターの読み込みの改善

common.runtime.properties でモニターを指定できるようになり、各モニターは該当するサーバー タイプにのみロードされます。以前は、モニターの対象となるサービスに対して特定の runtime.properties ファイルでモニターを定義する必要がありました。

#18321

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-exact-count-extension" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-exact-count-extension">#</a> 正確なカウントの拡張子

新しいコントリビューター拡張機能 (druid-exact-count-bitmap) は、長い列に対するローリング ビットマップを使用した正確なカーディナリティ カウントのサポートを追加します。

#18021

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-improved-%60indexspec%60" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-improved-%60indexspec%60">#</a> indexSpec の改善

ユーザーは、各 JSON 列の形式仕様を個別に指定できるようになりました。これにより、取り込みジョブで定義された IndexSpec がオーバーライドされます。さらに、druid.indexing.formats.indexSpec プロパティを使用して、システム全体のデフォルトの IndexSpec を設定できます。

<a name="35.0.0-functional-area-and-related-changes-web-console-time-zones" href="#35.0.0-functional-area-and-related-changes-web-console-time-zones">#</a> タイム ゾーン

Web コンソールにローカル時刻を表示するか UTC を表示するかを構成できるようになりました。この設定はブラウザーにローカルに保存され、他のユーザーには影響しません。

URL ではクエリ パラメーターが UTC 時間で維持されますが、Druid コンソールはフィルターを自動的に現地時間に変換することに注意してください。

<a name="35.0.0-functional-area-and-related-changes-querying" href="#35.0.0-functional-area-and-related-changes-querying">#</a> クエリ

<a name="35.0.0-functional-area-and-related-changes-querying-segment-timeout" href="#35.0.0-functional-area-and-related-changes-querying-segment-timeout">#</a> セグメント タイムアウト

クエリのセグメント処理のタイムアウトを構成できるようになりました。

タイムアウトを設定するには、この機能を有効にするすべてのデータ ノードで druid.processing.numTimeoutThreads を 3 などの小さい数値に設定します。

次に、perSegmentTimeout クエリ コンテキスト パラメーターをクエリに含めて、ミリ秒単位の値に設定します。

Druid は、スキャン クエリの結果レベルのキャッシュをサポートするようになりました。

デフォルトでは、この動作はオフになっています。有効にするには、druid.*.cache.unCacheable プロパティをオーバーライドします。

Druid は次の式をサポートするようになりました。

  • HLL_SKETCH_ESTIMATE_WITH_ERROR_BOUNDS
  • THETA_SKETCH_ESTIMATE_WITH_ERROR_BOUNDS

これらの推定はスケッチ列で機能し、ポスト アグリゲーターと同じ動作をします。

  • MV_FILTER_PREFIX: 複数値式をフィルタリングして、指定された接頭辞で始まる値のみを含めます。

構成可能な時間枠に基づいて Iceberg データをフィルタリングできるようになりました。

#18531

<a name="35.0.0-functional-area-and-related-changes-extensions-kubernetes" href="#35.0.0-functional-area-and-related-changes-extensions-kubernetes">#</a> Kubernetes

<a name="35.0.0-functional-area-and-related-changes-extensions-http-client" href="#35.0.0-functional-area-and-related-changes-extensions-http-client">#</a> HTTP client

Fabric8 KubernetesClient が k8s サーバー タスクが実行されると通信するために内部で使用する HTTP client ライブラリを構成できるようになりました。デフォルトは、Druid 34 が使用するのと同じ client および構成のままです。現在使用できる追加オプションは、okhttp およびネイティブ JDK HttpClient です。ほとんどの使用例では、デフォルトの client と構成で十分です。

druid.indexer.runner.k8sAndWorker.http.httpClientType 構成を vertx (デフォルト)、okhttp、または jdk に設定します。

#18540

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs">#</a> ポッド ログ

k8s ポッド ログと対話する非同期操作のタイムアウトを設定できるようになりました: druid.indexer.runner.podLogOperationTimeout。

#18587

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs">#</a> タスク ログ

中間マネージャーを使用しない取り込みでは、永続化されたタスク ログが無期限にブロックされる可能性がなくなりました。代わりに、ログの永続化には時間制限があり、これを破ると永続化が断念されます。デフォルトのタイムアウトは 5 分ですが、druid.indexer.runner.logSaveTimeout を PT60S などの期間でオーバーライドすることで構成できます。

さらに、Kubernetes ランナーのタスク ログ ストレージがオプションになりました。

#18444 #18341

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-improved-fault-tolerance" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-improved-fault-tolerance">#</a> フォールト トレランスの向上

タスクの起動と管理に中間マネージャーの代わりに Kubernetes を使用する druid-kubernetes-overlord-extensions は、特定の一時的な障害に対する回復力が向上しました。

#18406

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure">#</a> タスクの失敗の高速化

タスク ポッドは、ポッド作成フェーズ中に失敗した場合に Kubernetes ジョブ イベントを出力するようになり、K8s タスクは回復不可能な状況で高速に失敗します。

#18159

<a name="35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs" href="#35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs">#</a> 追加の構成をマウントする

以前は、環境変数を介して _common にマウントされる追加の構成を指定できましたが、これは Druid プロセスにのみ適用されました。 Kubernetes ジョブ (MiddleManager なしモード) として送信された取り込みタスクにも同じ構成を適用できるようになり、すべてのタスク タイプ間で一貫性が確保されます。

#18447

<a name="35.0.0-upgrade-notes-and-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes">#</a> アップグレードに関する注意事項と互換性のない変更点

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> アップグレードに関する注意事項

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default">#</a> デフォルトでフォールバック ベクトル化がオン

druid.expressions.allowVectorizeFallback のデフォルトは true になりました。さらに、SAFE_DIVIDE はフォールバックとしてベクトル化できるようになりました。

#18549

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-">#</a> 桟橋 12

Druid は Jetty 12 を使用するようになりました。特に URI コンプライアンスと SNI ホスト チェックに関して、デプロイメントが影響を受ける可能性があります。

新しいサーバー構成オプション druid.server.http.uriCompliance が追加されました。 Jetty 12 では、デフォルトで RFC3986 URI 形式が厳密に適用されます。これは Jetty 9 からの変更です。既存の Druid デプロイメントにおける破壊的な変更の可能性を避けるために、この設定はデフォルトで LEGACY に設定され、Jetty 9 で使用されていたより寛容な URI 形式の適用が使用されます。運用しているクラスターにレガシー互換性が必要ない場合は、Druid デプロイメントで上流の Jetty デフォルトの RFC3986 を使用することをお勧めします。詳細については、桟橋のドキュメントを参照してください。

Jetty 12 サーバーは、TLS が有効な場合に厳密な SNI host0 チェックを実行します。 client がサーバーに接続しているホストがキーストア内の内容と一致しない場合、そのキーストアに証明書が 1 つしかない場合でも、400 応答が返されます。これは、何らかの理由で localhost 経由で接続するユーザーなど、一部のユースケースに影響を与える可能性があります。この変更によってデプロイメントが中断される場合は、一部またはすべての Druid サービスの runtime.properties で druid.server.http.enforceStrictSNIHostChecking を false に設定することで、変更をオプトアウトできます。可能な場合は常に設定をオーバーライドするのではなく、jetty のこの変更に対応するように client の動作を変更することをお勧めします。

#18424 #18623

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication">#</a> Kerberos 認証

druid.auth.authenticator.kerberos.cookieSignatureSecret 構成は必須になりました。

#18368

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine">#</a> マルチステージ クエリ タスク エンジン

MSQ タスク エンジンは、拡張機能ではなく Druid のコア機能になりました。これは、いくつかのリリースのデフォルトの拡張機能ロード リストに含まれています。

アップグレードする前に、common.runtimes.properties の druid.extensions.loadList から druid-multi-stage-query を削除します。

Druid 35.0.0 は、ロード リストにある拡張子を無視します。 Druid の将来のバージョンでは、拡張機能が見つからないため起動できなくなります。

#18394

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension">#</a> pac4j 拡張機能

pac4j 4 から 5 へのアップグレードにより、セッションのシリアル化は pac4j の JavaSerializer から標準の Java シリアル化に変更されました。その結果、pac4j 拡張機能を使用するクラスターの client は、ローリング アップグレード中にログアウトされ、再認証が必要になる場合があります。

#18259

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> 互換性のない変更

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed">#</a> Java 11 サポートの削除

Java 17 または 21 にアップグレードします。Java 21 の一部のバージョンでは、テスト中に問題が発生したことに注意してください (特に Java 21.05-21.07)。可能であれば、これらのバージョンは避けてください。

#18424

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> 開発者向けノート

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests">#</a> 組み込みクラスターのテスト

新しい組み込みクラスター テスト フレームワークを使用すると、ロードする拡張機能や ZooKeeper および Derby メタデータ ストアを含む、単一プロセスで実行される完全に機能する Druid クラスターを使用した軽量統合テストを実行できます。 mvn build を実行したり、docker イメージを作成したり、統合テストを実行するために起動スクリプトを実行したりする必要はなくなりました。

#18147

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json">#</a> JSON の特殊な仮想列

ColumnSelector によって返される ColumnHolder は、getColumn() からの BaseColumn ではなく SelectableColumn を返すようになりました。 SelectableColumn は、BaseColumn である場合もあれば、仮想列によって提供される実装である場合もあります。 ColumnSelector から物理列を取得する必要がある拡張機能は、instanceof を使用して列が BaseColumn であるかどうかを確認できます。便宜上、QueryableIndex の getColumnHolder の戻り値の型は BaseColumnHolder に特化されており、常に getColumn() から BaseColumn を返します。 QueryableIndex でこのメソッドを呼び出している拡張機能は、列をキャストする必要を避けるために、結果を BaseColumnHolder 型の変数に格納できます。

#18521

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed">#</a> reset-cluster ツールが削除されました

reset-cluster 開発およびテスト環境指向のツールは削除されました。これは古く、メタデータ ストアを完全に消去できませんでした (Druid 28 と 30 でそれぞれ追加された upgradeSegments テーブルと segmentSchemas テーブルが欠落しています)。このツールは運用環境での使用を目的としていないため、クラスター オペレーターには影響はありません。

#18246

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions">#</a> SQL メタデータ拡張機能の重大な変更

MetadataStorageActionHandler 拡張ポイントには、よりシンプルな API が追加されました。 これは、実際に使用されている SQL メタデータ拡張機能にとって重大な変更です。 PostgreSQL、MySQL、SQLServer の変更はすでに完了しています。 #18479

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed">#</a> DriudLeaderClient が削除されました

DruidLeaderClient は拡張機能から削除され、ServiceClient ベースの実装に置き換えられました。さらに、コーディネーターによって公開される非コア API をクエリするための CoordinatorServiceClient は、druid-server を通じて利用できます。
