重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

Java

Java 21 のサポートは終了しました。 Java 25 にアップグレードする必要があります。

カタログの DDL ステートメント (実験的)

Druid は、カタログ内のメタデータを管理するための CREATE ステートメントと ALTER ステートメントをサポートするようになりました。これらを各取り込み仕様で設定するのではなく、テーブルの列、時間分割、クラスタリング、集計投影、および物理レイアウトを宣言するために使用します。 この機能はデフォルトではオフになっています。有効にするには、druid.sql.planner.enableCatalogDdl を true に設定します。 詳細は【カタログ】(https://druid.apache.org/docs/39.0.0/development/extensions-core/catalog)をご覧ください。 #19830 #20377 #20452 #19770 #19711

Kafka ヘッダーベースのフィルタリング

Kafka スーパーバイザーはヘッダーでレコードをフィルターできるようになりました。これにより、トピックのレコードの一部のみが必要な場合に、取り込みの CPU とメモリの使用量が削減されます。 フィルタを使用するには、スーパーバイザの ioConfig に headerBasedFilterConfig を追加します。 in フィルターを使用します。ここで、dimension はヘッダー名、values は取り込むヘッダー値のリストです。ヘッダー値がリストにないレコードは削除されますが、オフセットは引き続き進みます。 フィルタリングは寛容です。ヘッダーがない場合、ヘッダー値が null、空、デコードできない場合、または評価が失敗した場合、レコードは取り込まれます。 新しい ingest/events/filtered メトリックは、ヘッダー フィルターによってドロップされたレコードの数を報告します。 #18525

型指定されたクエリ コンテキスト パラメータ

クエリ コンテキスト リファレンス および スキャン クエリ にリストされている共通のクエリ コンテキスト パラメーターは、型指定された QueryContextParameter 記述子になりました。次の変更は、クエリ コンテキストの処理に適用されます。

  • 整数パラメータと長整数パラメータは、切り捨てたりラップしたりする代わりに、正確な整数ではない値を拒否します。たとえば、1.5、および範囲外の値です。 5.0 や "5.0" のような整数値は引き続き受け入れられます。無効な値は失敗し、「クエリ コンテキスト パラメータ [x] は ... である必要があります。」というエラー メッセージが表示されるようになりました。
  • クエリ コンテキスト内の null または SET x = NULL は、druid.query.default.context またはブローカーの動的構成で構成されたデフォルトをクリアしなくなりました。デフォルトは、キーが設定されていない場合と同様に適用されます。以前は、組み込みのデフォルトを使用するリーダーに null が到達していました。構成されたデフォルトをオーバーライドするには、明示的な値を設定します。
  • maxSubqueryBytes は、サブクエリ ガードレールと同様に、自動、無効、または負でないバイト数を受け入れる型付き文字列パラメータです。 SET maxSubqueryBytes = TRUE などの無効な値は検証中に失敗し、1e9 などの数値が受け入れられるようになりました。 #20555

Druid JDBC ドライバー

Druid は、/druid/v2/sql/ エンドポイントを使用する独自の JDBC ドライバーを提供するようになりました。 Avatica ドライバーからこのドライバーに切り替えることをお勧めします。新しいドライバーには、スティッキーな負荷分散を必要としないドライバー側の接続管理、結果のストリーミング、SET ステートメントのサポート、および非ネイティブ SQL エンジンのサポートという利点があります。 #19951

Netty 4.2

Druid は現在、HTTP client に Netty 4.2 を使用しています。以前、Druid は Netty 3 を使用していました。これはメモリ特性の大幅な変更です。

  • ダイレクト メモリ: HTTP client は、ダイレクト メモリを消費するようになりました。 -XX:MaxDirectMemorySize の予算に近い事業者は、予算を増やす必要があるかもしれません。
  • プールされたバッファ: バッファがプールされるようになったため、アイドル状態であっても常駐メモリが Netty 3 よりも多く表示される場合があります。これは、プールされたアロケータでは正常です。 HTTP client の動作を制御する新しい構成 (druid.global.http.connectTimeout、druid.global.http.allocator、druid.broker.http.connectTimeout、および druid.broker.http.allocator) があります。一部の Netty 構成を直接設定することもできます。 #19567

コーディネーターのサービス品質フィルタリング

コーディネーターの QoS フィルタリングを有効にして、低速 API 要求のバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぐことができるようになりました。 この機能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))) を構成するには、druid.coordinator.server.maxConcurrentRequests を使用します。オフにするには、このプロパティを 0 に設定します。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサー/モニターは影響を受けません。 #19271

機能領域と関連する変更

このセクションには、領域ごとに分かれた release note の詳細が含まれています。

摂取

  • regex 入力形式の RE2/J 正規表現のサポートを追加しました #19514
  • AWS 推奨の標準再試行ポリシーを使用するように S3 client を変更しました。 druid.s3.retryMode および druid.s3.maxAttempts #19892 を使用して再試行戦略をカスタマイズできます。
  • Protobuf の取り込みでは、オプションとしてマークされていない proto3 フィールドのデフォルト値が保持されるようになりました。以前は、0 を保持する int32 フィールド (または "" を保持する文字列、false を保持する bool、最初の値を保持する enum) は null として取り込まれていました。このようなフィールドは実際の値として取り込まれるようになりました。 #20485

SQL ベースの取り込み

  • ワーカーは、ワーカー コンテキスト全体ではなく、必要なワーカー コンテキストのみをタスク コンテキストに渡すようになりました。 #20650

ストリーミング取り込み

選択したパーティションからの取り込み

Kafka スーパーバイザーは ioConfig.partitionIds を受け入れるようになりました。これにより、トピックの選択されたパーティションのみを取り込むことができます。たとえば、これを独立した診断の取り込みに使用できます。 #20474

コストベースのオートスケーラーの改善
  • Kafka のコストベースのオートスケーラーをシミュレートして、さまざまな量のラグに対する最適なタスク数を決定できるようになりました。 #19687
  • コストベースのオートスケーラーのクリティカルラグしきい値を設定できるようになりました。ラグがしきい値の 75% に達すると、オートスケーラーはスケールアップ境界をバイパスします。ラグが 100% に達すると、オートスケーラーは最大タスク数までスケールアップします。 #19655
  • スーパーバイザのコストベースのオートスケーラーのクールダウンを次の 2 つの方法のいずれかで設定できるようになりました。
    • 高感度: minScaleUpDelay / minScaleDownDelay < taskDuration を設定します。たとえば、minScaleUpDelay = taskDuration / 2 の場合、2 つのタスク ロールオーバー間には最大 1 つのスケーリング イベントが発生します。
    • 低感度 : minScaleUpDelay / minScaleDownDelay > taskDuration を設定します。この場合、クールダウンは事実上無視され、スケーリングはタスクのロールオーバー時にのみ発生します。 #20706
  • コストベースのオートスケーラーは、コストベースのオートスケーラーの決定を行うために、タスク メトリックの瞬間値ではなく移動平均を使用するようになりました。これにより、よりスムーズなスケーリングが可能になりますが、タスクのライフサイクルの終わりに向かって発生するメトリクスの傾向の変化に対する応答がわずかに遅れるという代償が生じる場合があります。トレンドの変化に対する感度を高めるには、minScaleUpDelay および minScaleDownDelay を taskDuration よりも小さく設定します。
その他のストリーミング取り込みの改善
  • Kafka インデックス作成タスクが、サンプルが実際に利用可能になる前に 1.0 (つまり、完全なアイドル状態) のポーリング アイドル率を報告するバグを修正しました。これにより、タスク全体にわたるスーパーバイザー オートスケーラーの平均アイドル率が歪む可能性がありました。 #20783

クエリを実行する

クエリの計画時間

新しい druid.sql.planner.maxPlanningTimeMs ランタイム プロパティを使用して、ブローカーが SQL クエリの計画に費やす時間を制限できるようになりました。 maxPlanningTimeMs クエリ コンテキスト パラメーターを使用してクエリごとに設定することもできます。計画が構成された予算を超えると、ブローカー スレッドが拘束されるのではなく、クエリは HTTP 504 クエリ タイムアウト エラーで失敗します。デフォルト値は 0 で、タイムアウトが無効になります。 #20314

クエリ応答トレーラーによって引き起こされる JDK HTTP client エラーを修正しました

ブローカーとヒストリカルは、リクエストに TE: trailers ヘッダーが含まれている場合にのみ、X-Druid-Response-Complete および X-Error-Message HTTP トレーラーを送信するようになりました。 Cliこれらのトレーラーを読み取るエントは、そのヘッダーを送信する必要があります。これにより、JDK 17.0.21、21.0.13、および 25.0.5 上の Druid JDBC ドライバーを含む java.net.http.HttpClient-based client のクエリ エラー (java.net.ProtocolException: CR expected) が修正されます。 #20717

その他のクエリの改善

  • Dart を使用して、sys スキーマ #19952 などのメタデータ テーブルをクエリできるようになりました。
  • CAST(x AS LONG) が Druid SQL で CAST(x AS BIGINT) のエイリアスとして受け入れられるようになりました #20402
  • datasource フィルター プッシュダウンを sys.segments テーブルに追加 #19718
  • FIRST_VALUE および LAST_VALUE ウィンドウ関数にフレーミング サポートを追加しました #19301
  • 降順で実行される timeseries、timeBoundary、スキャン クエリのパフォーマンスが向上しました #19947
  • COALESCE #18400のパフォーマンスを改善しました
  • 耐久ストレージと MSQ エクスポートを使用した MSQ タスクの S3 API の使用効率が向上 #19893
  • カタログタイプの検証とネイティブタイプ文字列の解析が改善されました #19769
  • Calcite 1.42.0 #19976 #19370 にアップグレード

クラスター管理

Kubernetes ノード ラベル

druid-kubernetes-extensions 拡張機能は、Druid プロセスが実行される Kubernetes ノードのラベルから構成値を解決する k8sNodeLabel 動的構成プロバイダーをサポートするようになりました。 #20404

Peon ポッド テンプレート

新しい GET /druid/indexer/v1/k8s/taskrunner/podTemplates エンドポイントを使用して、Overlord で現在構成されている Peon ポッド テンプレート名を取得できるようになりました。構成された各テンプレートの名前を返します。エンドポイントには CONFIG 読み取り権限が必要で、オーバーロードがカスタム テンプレート ポッド アダプターを使用していない場合は 404 を返します。 #19712

環境変数

environment 動的構成プロバイダーは、NullPointerException を持つ Kafka スーパーバイザーなどのコンシューマーを失敗させる null 値を生成するのではなく、環境内に設定されていない変数を省略するようになりました。スキップされた変数は情報レベルで記録されます。 #20381

接続プール

druid.global.http.poolImplementation を使用して、Druid 接続プールが接続要求を追跡する方法を構成できるようになりました。 デフォルトはretainingです。 retaining を使用すると、プールは開いたすべての接続を保持し、古い接続や壊れた接続を新しい接続に置き換えるので、プールは最高水準点に留まります。 #20542 #20273

HTTP 応答ヘッダー

Druid はオプションで HTTP 応答で X-Druid-Server、X-Druid-Service、X-Druid-Version を返すことができるようになり、オペレーターは直接リクエストまたはルータープロキシリクエストを処理したプロセスとバージョンを識別できるようになります。これらのヘッダーはクラスターのトポロジとバージョン情報を公開するため、すべての client が受信を許可されている場合にのみ有効にします。それらを有効にするには、druid.server.http.enableResponseIdentityHeaders を true に設定します。 #20268

LDAP サポートの改善

memberOf 属性を返さないサーバー (OpenLDAP など) での LDAP グループベースの承認のサポートが追加されました。 LDAP 資格情報バリデーターで groupBaseDn および groupSearch を構成して、グループ メンバーシップを自動的に解決するグループ逆引き参照を有効にします。 #19432

テーブルの可視性

現在、読み取り権限を持たないテーブルにクエリを実行すると、「禁止」エラーではなく「見つからない」エラーが表示されます。 以前の動作を復元するには、druid.sql.planner.authorizeTableVisibility を false に設定します。 さらに、true に設定すると、INSERT と REPLACE にはターゲット テーブルへの READ アクセスと WRITE アクセスの両方が必要になります。このプロパティが false に設定されている場合、必要なのは書き込み権限のみです。このプロパティの値に関係なく、ユーザーがテーブルへの読み取りアクセス権を持っている場合、テーブルは INFORMATION_SCHEMA にのみ表示されます。 これは、必要な権限に影響を与える重大な変更です。詳細については、「SQL ベースの取り込みのアクセス許可の変更」(#permissions-changes-for-sql-based-ingestion) を参照してください。 #20075

Java ホーム変数

中間管理者は、作業ディレクトリに存在する必要がある bin/java スクリプトを使用するときに、JAVA_HOME を優先するようになりました。 ドルイドは次のロジックを使用します

  • コマンドを指定した場合 (config.getJavaCommand が null でない場合など)、それを使用します。
  • bin/run-java が存在する場合は、それを使用します
  • Javaを使用する #19709

コーディネーター エンドポイントの QoS フィルタリングを追加する

設定可能な QoS フィルタリングをコーディネータに追加して、低速 API リクエストのバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぎます。 新しい構成を追加しました: druid.coordinator.server.maxConcurrentRequests (デフォルト: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))、<= 0 を無効に設定)。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサーとモニターは影響を受けません。 #19271

その他のクラスター管理の改善点

  • UnusedSegmentsKiller がアクティブな取り込みで間隔をスキップしないように、組み込みの Kill タスクで使用できる KILL タスク ロック タイプを追加しました #19921
  • PostgreSQL のサポートを export-metadata ツールに追加しました #19698
  • クエリを処理しないタスク (バッチ、圧縮、MSQ タスクなど) を実行しているタスクは、druid.server.http.unannouncePropagationDelay を無視し、待機せずにシャットダウンするようになりました。リアルタイム ストリーミング タスクは引き続き遅延を考慮します #20444
  • ポートバインディングの改善。 Druid ノードは、Jetty を実際のサービス ポートにバインドしながら、ピア検出用に別のプレーンテキスト ポートをアドバタイズできるようになりました #19598
  • ロードされたセグメントのヒープ フットプリントを削減しました #20467
  • Druid 32.0.0 以来 404 エラーを返していた shutdownAllTasks Overlord API (POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks) を修正しました。 #20824

データ管理

圧縮中の間隔をスキップする

自動圧縮では、データソース圧縮構成の skipIntervals 設定がサポートされるようになり、既存の skipOffsetFromLatest の動作に加えて、特定の間隔を圧縮から除外できるようになりました。これは、たとえば、バックフィル ジョブがアクティブに書き込みを行っている間隔や、常に圧縮に失敗する間隔を除外する場合に便利です。 #19792

大規模なセグメント ファイルの可視性の向上

Druid は、範囲またはハッシュ パーティショニング設定により、タイム チャンク内に大きすぎるセグメント ファイル (ホット パーティション) が生成された場合にレポートするようになりました。ハッシュまたは範囲パーティション化を使用したネイティブ バッチ インジェストでは、警告がログに記録され、ingest/segments/oversized メトリクスが生成されるようになりました。このメトリクスは、範囲パーティション化の場合、2 倍を超える maxRowsPerSegment 行、または 3 倍を超える targetRowsPerSegment 行を含むパブリッシュされたセグメントをカウントします。タスク完了レポートには、この数も oversizedSegments として含まれます。 #20173

セグメント検索の高速化

高速間隔検索を有効にすることで、メモリ内タイムラインでのセグメント検索を高速化できるようになりました。この機能は、間隔ツリー インデックスを使用してメモリ内のタイムラインを編成し、セグメントの読み込みと検索を高速化します。 この機能を使用するには、druid.segment.timeline.fastIntervalSearch を true に設定します。 #19138 #19861

部分的なセグメントのロード

Druid は、仮想ストレージの部分セグメント読み込みをサポートするようになりました (デフォルトでオン)。オフにするには、次のいずれかを false に設定します。

  • ランタイムプロパティ druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • クエリコンテキストパラメータ virtualStoragePartialDownloadsEnabled #19739

その他のデータ管理の改善点

  • S3 互換ストレージの MD5 リクエスト チェックサムのサポートを追加しました。この機能を有効にするには、druid.s3.enableLegacyMd5 を true #20055 に設定します。
  • Azure および Google Cloud のディープ ストレージで zip 圧縮を使用しないセグメントのプッシュ、プル、強制終了のサポートを追加しました #20454 #20327 #20382 #20380
  • 仮想ストレージを使用する場合に、リクエストを履歴層全体に分散するようにロード アルゴリズムを改善しました #20155
  • 埋め込みキルタスクの効率を改善しました #19772

メトリクスとモニタリング

階層ストレージのメトリクス

階層ストレージ メトリックにより、仮想ストレージの有無にかかわらず、履歴の可観測性が向上しました。 tier/required/capacity と tier/total/capacity の 2 つのメトリックは非推奨であり、将来のリリースで削除される予定です。代わりに ZZPH100​​ZZ および tier/storage/capacity を使用してください。 #20199

task/run/time メトリック

statsd および prometheus エミッターは、task/run/time で taskStatus の寸法を放射するようになりました。これは重大な変更です。詳細については、「task/run/time のアラート」(#alerts-on-taskruntime) を参照してください。 #20122

その他のメトリクスとモニタリングの改善

  • Kubernetes Overlord 拡張機能を使用するクラスターの Peon タスク メトリックに、podTemplate ディメンションが含まれるようになりました。これにより、さまざまなタスクをさまざまなポッド テンプレートにマッピングするクラスターの監視が容易になります #20001
  • [0.0, 1.0] #19627 の端数として、放出期間中に単一の groupBy クエリがどの程度流出に近づいたかを測定する mergeBuffer/maxSpillProximity を追加しました。
  • さまざまなタスク数メトリックに taskType を追加したため、タスク タイプでフィルターできるようになりました #20123

コントリビューターの拡張機能

氷山

Apache Iceberg の取り込みは、iceberg-arrow によってサポートされるオプトインのベクトル化リーダーをサポートするようになりました。 "useArrowReader": true で有効にします。 arrowBatchSize でバッチ処理を調整します (デフォルトは 1024)。 Arrow パスは、Parquet データ ファイル、辞書でエンコードされた値、スキーマ進化、タイムトラベル スナップショット、列射影、述語プッシュダウンをサポートします。位置削除ファイルまたは等価削除ファイルを含むスナップショットはサポートされておらず、Druid はそれらをエラーで拒否します。これらのスナップショットには標準の削除対応リーダーを使用してください。 Arrow パスは分割できないため、並列バッチ スループットが必要な場合は無効にしてください。デフォルトのリーダーは変更されず、両方のパスが同じ Iceberg 入力ソース タイプの下に共存します。 #19510

オープン ポリシー エージェント

druid-opa-authorizer コントリビューター拡張機能が追加されました。これにより、Open Policy Agent (OPA) を介した認証が可能になります。 Rego ポリシーを作成して、ユーザー ID、アクション、リソース タイプに基づいて Druid リソースへのアクセスを制御できます。この拡張機能は、基本認証と LDAP 認証の両方のワークフローをサポートします。 #19670

アップグレードに関する注意事項と互換性のない変更

アップグレードに関する注意事項

Netty 4.2

Druid は現在、HTTP client に Netty 4.2 を使用しています。以前は、Druid は Netty 3 を使用していました。これはメモリ特性の大幅な変更です。

  • ダイレクト メモリ: HTTP client は、ダイレクト メモリを消費するようになりました。 -XX:MaxDirectMemorySize の予算に近い運用を行っている事業者は、予算を増やす必要があるかもしれません。
  • プールされたバッファ: バッファはプールされるようになったため、アイドル状態であっても常駐メモリが Netty 3 よりも多く表示される場合があります。これは、プールされたアロケータでは正常です。 HTTP client の動作を制御する新しい構成 (druid.global.http.connectTimeout、druid.global.http.allocator、druid.broker.http.connectTimeout、および druid.broker.http.allocator) があります。一部の Netty 構成を直接設定することもできます。 #19567

ダーツワーカー

ヒストリカルのダーツ ワーカーは、新しい DartWorkerService メカニズムを使用してブローカーによって発表され、発見されるようになりました。 Dart を有効にしている場合は、標準のローリング アップグレードの順序に従ってください。アップグレード中は、Broker の前に Historicals を再起動します。ダウングレード中は、履歴の前にブローカーを再起動してください。 #20508

Protobuf の取り込み

  • Protobuf の取り込みでは、オプションとしてマークされていない proto3 フィールドのデフォルト値が保持されるようになりました。以前は、0 を保持する int32 フィールド (または "" を保持する文字列、false を保持する bool、最初の値を保持する enum) は null として取り込まれていました。このようなフィールドは実際の値として取り込まれるようになりました。 #20485

クエリ応答トレーラーによって引き起こされる JDK HTTP client エラーを修正しました

ブローカーとヒストリカルは、リクエストに TE: trailers ヘッダーが含まれている場合にのみ、X-Druid-Response-Complete および X-Error-Message HTTP トレーラーを送信するようになりました。 Cliこれらのトレーラーを読み取るエントは、そのヘッダーを送信する必要があります。これにより、JDK 17.0.21、21.0.13、および 25.0.5 上の Druid JDBC ドライバーを含む java.net.http.HttpClient-based client のクエリ エラー (java.net.ProtocolException: CR expected) が修正されます。 #20717

型指定されたクエリ コンテキスト パラメータ

クエリ コンテキスト リファレンス および スキャン クエリ にリストされている共通のクエリ コンテキスト パラメーターは、型指定された QueryContextParameter 記述子になりました。次の変更は、クエリ コンテキストの処理に適用されます。

  • 整数パラメータと長整数パラメータは、切り捨てたりラップしたりする代わりに、正確な整数ではない値を拒否します。たとえば、1.5、および範囲外の値です。 5.0 や "5.0" のような整数値は引き続き受け入れられます。無効な値は失敗し、「クエリ コンテキスト パラメータ [x] は ... である必要があります。」というエラー メッセージが表示されるようになりました。
  • クエリ コンテキスト内の null または SET x = NULL は、druid.query.default.context またはブローカーの動的構成で構成されたデフォルトをクリアしなくなりました。デフォルトは、キーが設定されていない場合と同様に適用されます。以前は、組み込みのデフォルトを使用するリーダーに null が到達していました。構成されたデフォルトをオーバーライドするには、明示的な値を設定します。
  • maxSubqueryBytes は、サブクエリ ガードレールと同様に、自動、無効、または負でないバイト数を受け入れる型付き文字列パラメータです。 SET maxSubqueryBytes = TRUE などの無効な値は検証中に失敗し、1e9 などの数値が受け入れられるようになりました。 [#20555][https://github.com/apache/druid/pull/20555/]

Java ホーム変数

中間管理者は、作業ディレクトリに存在する必要がある bin/java スクリプトを使用するときに、JAVA_HOME を尊重するようになりました。 ドルイドは次のロジックを使用します

  • コマンドを指定した場合 (config.getJavaCommand が null でない場合など)、それを使用します。
  • bin/run-java が存在する場合は、それを使用します
  • Javaを使用する #19709

コーディネーターのサービス品質フィルタリング

コーディネーターの QoS フィルタリングを有効にして、低速 API 要求のバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぐことができるようになりました。 この機能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))) を構成するには、druid.coordinator.server.maxConcurrentRequests を使用します。オフにするには、このプロパティを 0 に設定します。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサー/モニターは影響を受けません。 #19271

互換性のない変更

SQL ベースの取り込みに対する権限の変更

テーブルの可視性 の変更は、SQL ベースの取り込みに必要な権限に影響します。 INSERT と REPLACE には、ターゲット テーブルに対する (WRITE に加えて) READ アクセスが必要になりました。 以前の動作を復元するには、druid.sql.planner.authorizeTableVisibility を false に設定します。 #20075

task/run/time に関するアラート

statsd および prometheus エミッターは、task/run/time で taskStatus の寸法を放射するようになりました。これは、task/run/time のダッシュボードとアラートの重大な変更です。

  • statsd (非 DogStatsD モード): ディメンション値はドット付きメトリック名に結合されるため、druid.overlord.task.run.time.DATASOURCE.TASKTYPE は druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE になります。古い名前に対するクエリはデータの受信を停止します。
  • statsd (DogStatsD モード): taskStatus タグが追加されます。既存のクエリは引き続き機能し、それを集計します。
  • prometheus: taskStatus ラベルが追加されます。正確なラベル セットを選択するクエリと、古いラベル セットを前提とする記録ルールを更新します。 以前の動作を維持するには、古いディメンション リストを druid.emitter.statsd.dimensionMapPath または druid.emitter.prometheus.dimensionMapPath で固定します。 #20122

SysMonitor が削除されました

SysMonitor は Druid 27 で非推奨となったため削除されました。代わりに OshiSysMonitor を使用してください。 #20200

MariaDB Connector/J 3.x による接続 URI の動作の変更

MariaDB JDBC コネクタが 2.7.3 から 3.5.10 にアップグレードされ、次のような影響があります。

  • druid.metadata.storage.connector.connectURI と org.mariadb.jdbc.Driver の場合は、jdbc:mariadb: を使用します。従来の jdbc:mysql: URI は、permitMysqlScheme が含まれている場合にのみ引き続き使用できます。たとえば、jdbc:mysql://<host>/druid?permitMysqlScheme は、メタデータ ストレージが URI をドライバーに直接渡すためです。
  • MariaDB ベースの SQL 入力ソースとデフォルトの druid.access.jdbc.enforceAllowedProperties=true による JDBC ルックアップの場合は、jdbc:mariadb: を使用します。 Druid の JDBC プロパティ検証では、jdbc:mysql: が Connector/J 3.x パーサーにルーティングされず、permitMysqlScheme はデフォルトの druid.access.jdbc.allowedProperties に含まれていません。オプションを追加するだけでは十分ではありません。
  • Connector/J 2.x を提供し続けるユーザーは、既存の jdbc:mysql: または jdbc:mariadb: URI を変更する必要はありません。 MySQL Connector/J ユーザーは影響を受けません。
  • distribution/docker/Dockerfile.mariadb から再構築されたイメージは Connector/J 3.5.10 をインストールするようになり、上記の 3.x ガイダンスに従う必要があります。 #20036

Web コンソール コード エディター
