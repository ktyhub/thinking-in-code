重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

機能領域と関連する変更

このセクションでは、release note を領域ごとに分けて詳細に説明します。

ドルイドのオペレーター

Druid Operator は、Druid クラスターのライフサイクルを管理する Kubernetes コントローラーです。 Operator は、次のように構成可能なカスタム ロジックを使用して Druid クラスターの管理を簡素化します。 Kubernetes CRD。

#18435

ストリーミング取り込みのためのコストベースの自動スケーリング

Druid は、遅延削減とリソース効率のバランスをとることでタスク数を最適化するストリーミング取り込みのコストベースの自動スケーリングをサポートするようになりました。この自動スケーリング戦略は次の式を使用します。

totalCost = lagWeight × lagRecoveryTime + idleWeight × idlenessCost

これには、バックログをクリアする時間と計算時間が考慮されます。

lagRecoveryTime = aggregateLag / (taskCount × avgProcessingRate) — time to clear backlog
idlenessCost = taskCount × taskDuration × predictedIdleRatio — wasted compute time

#18819

Kubernetes client モード (実験的)

kubernetes-overlord-extensions では、実験的な Kubernetes client モードが追加されました。新しいモードでは、fabric8 SharedInformers を使用して k8s メタデータをキャッシュします。これにより、Overlord と k8s コントロール プレーン間の API トラフィックが大幅に削減されます。次の構成を使用してこの機能を試すことができます。

druid.indexer.runner.useK8sSharedInformers=true

#18599

cgroup v2 のサポート

cgroup v2 がサポートされるようになり、すべての cgroup メトリクスが cgroupversion を発行して、使用されているバージョンを識別するようになりました。

v2 が検出されると、メトリック CgroupCpuMonitor 、CgroupCpuSetMonitor、CgroupDiskMonitor、MemoryMonitor は自動的に v2 に切り替わります。 v2 が検出された場合、CpuAcctDeltaMonitor は正常に失敗します。

さらに、CgroupV2CpuMonitor は cgroup/cpu/shares および cgroup/cpu/cores_quota も放射するようになりました。

#18705

Dart のクエリ レポート

Dart は、実行中のクエリと最近完了したクエリのクエリ レポートをサポートするようになりました。レポートは /druid/v2/sql/queries/<sqlQueryId>/reports エンドポイントから取得できます。

応答の形式は、「query」と「report」という 2 つのキーを持つ JSON オブジェクトです。 「クエリ」キーは、既存の /druid/v2/sql/queries エンドポイントから入手できる情報と同じです。 「レポート」キーは、MSQレポートを含むレポートマップである。 次の構成を使用して、レポートの保持動作を制御できます。

  • druid.msq.dart.controller.maxRetainedReportCount: 保持されるレポートの最大数。デフォルトは 0 で、レポートは保持されないことを意味します。
  • druid.msq.dart.controller.maxRetainedReportDuration: レポートが ISO 8601 期間形式で保持される期間。デフォルトは PT0S で、時間ベースの有効期限がオフであることを意味します。

#18886

新しいセグメント形式

新しいバージョン 10 のセグメント フォーマットはバージョン 9 を改良しています。デフォルトではオフになっており、古いセグメント フォーマットのバージョンと互換性がありません。

新しいフォーマットでセグメントを作成するには、druid.indexer.task.buildV10=true を設定します。

ダウングレードする場合は、サポートされているセグメント形式のバージョンでデータのインデックスを再作成する必要があります。

bin/dump-segment ツールを使用してセグメントのメタデータを表示できます。このツールはシリアル化された JSON を出力します。

#18880 #18901

Web コンソール

Web コンソールで利用可能な新しい情報

Web コンソールには、使用可能なプロセッサの数と合計メモリ (バイナリ バイト単位) に関する情報が含まれるようになりました。

この情報は、sys.servers テーブルからも入手できます。

#18613

その他の Web コンソールの改善点

  • MSQ 実行ステージの非アクティブなワーカーの追跡を追加しました #18768
  • JSON ビューとステージ ビューアーに更新ボタンを追加しました #18768
  • クエリビューで ARRAY タイプのパラメータを定義できるようになりました #18586
  • ネイティブ エンジンを自動的に使用するようにシステム テーブル クエリを変更しました #18857
  • 複数のメジャーをサポートするためにタイム チャートを改善 #18701

摂取

  • AWS InternalError コード再試行のサポートを追加 #18720
  • 摂取が改善され、より弾力性が増しました。タスクログのアップロードが例外で失敗しても、取り込みタスクは失敗しなくなりました #18748
  • データが予想されるタイプと一致しない状況を Druid が処理する方法を改善しました #18878
  • JSON の取り込みが改善され、Druid が辞書またはインデックス構造から JSON 値を直接計算できるようになり、取り込みで永続化された生の JSON データを完全にスキップできるようになりました。これにより、ディスク上のストレージ サイズが削減されます #18589
  • ネストされた列の long/double フィールドに対して、完全な辞書ベースのインデックス作成と null のみのインデックス作成のどちらかを選択できるようになりました #18722

SQL ベースの取り込み

追加の取り込み構成

次の構成を使用して、データの取り込みと保存の方法を制御できるようになりました。

  • maxInputFilesPerWorker: ワーカーごとの入力ファイルまたはセグメントの最大数を制御します。
  • maxPartitions: 単一ステージの出力パーティションの最大数を制御します。これは、取り込み中に生成されるセグメントの数に影響します。

#18826

その他の SQL ベースの取り込みの改善
  • rowsInMemory の代わりに maxRowsInMemory を追加しました。 rowsInMemory は、その構成を提供する代替方法として機能するようになり、maxRowsInMemory が指定されている場合は無視されます。以前は、rowsInMemory のみが存在していました #18832

ストリーミング取り込み

レコードのオフセットとパーティション

KafkaInputFormat を使用して、レコード オフセット (offsetColumnName) とパーティション (partitionColumnName) を取り込むことができるようになりました。デフォルト名はそれぞれ kafka.offset と kafka.partition です。

#18757

その他のストリーミング取り込みの改善
  • スーパーバイザーの停止中にタスクを強制終了できないようにスーパーバイザーを改善しました #18767
  • ストリーミング取り込みのためのラグベースのオートスケーラーを改善しました #18745
  • SeekableStream スーパーバイザ オートスケーラーが改善され、後続のスケール操作を試行する前にタスクが完了するまで待機するようになりました。これは、スーパーバイザ履歴エントリの重複を防ぐのに役立ちます #18715

クエリを実行する

その他のクエリの改善

  • 無効な regex_exp クエリに対するユーザー エクスペリエンスが改善されました。エラーが返されるようになりました #18762

クラスター管理

Kubernetes ベースの展開の動的容量

Druid はタスク ランナーの容量を動的に調整できるようになりました。

/druid/indexer/v1/k8s/taskrunner/executionconfig への POST API 呼び出しに capacity フィールドを含めます。この方法で値を設定すると、druid.indexer.runner.capacity がオーバーライドされます。

#18591

サーバープロパティテーブル

sys.server_properties テーブルは、各 Druid サーバーに設定されたランタイム プロパティを公開します。各行は、特定のサーバーに関連付けられた単一のプロパティのキーと値のペアを表します。

#18692

その他のクラスター管理の改善点

  • ヘルスチェックスレッドがブロックされないように、Overlord のサービス品質フィルタリングを追加しました #18033

データ管理

その他のデータ管理の改善点

  • 圧縮されていない最も小さいセグメントの間隔を優先する mostFragmentedFirst 圧縮ポリシーを追加しました #18802
  • 削除操作中に失敗した場合に部分的なセグメント ファイルが残らないように、セグメント ファイルの削除方法を改善しました #18696
  • 圧縮が改善され、複数値のディメンションを生成できるディメンション スキーマのディメンションを識別できるようになりました #18760
  • セグメントを引っ張るときの信頼性を改善 #18821

メトリクスとモニタリング

タスクのメトリクス

すべてのタスク メトリックは、taskId、dataSource、taskType、groupId、および id のディメンションを出力するようになりました。 id は下位互換性のために発行されることに注意してください。将来のリリースでは、taskId ディメンションを優先して削除される予定です。

#18876

取り込みメトリクス

ストリーミング タスクとバッチ タスクの次のメトリクスは、0 ではなく実際の値を出力するようになりました: ingest/merge/time、ingest/merge/cpu、ingest/persists/cpu。

#18866

statsd メトリクス

次のメトリックが statsd のデフォルト リストに追加されました。

  • task/action/run/time
  • task/status/queue/count
  • task/status/updated/count
  • ingest/handoff/time

#18846

その他のメトリクスとモニタリングの改善

  • reason ディメンションを ingest/events/thrownAway メトリックに追加しました。これにより、特定のイベントが論理的に取り込みから除外される理由の可観測性が向上します #188855

  • ステージのすべてのハンドラーの開始または停止前のログを追加しました。これにより、実行順序を理解するのに役立ちます #18662

  • リクエスト処理スレッド統計を取得するための新しい Jetty スレッド プール メトリクスを追加しました: jetty/threadPool/utilized、jetty/threadPool/ready、jetty/threadPool/utilizationRate #18883

  • tier および priority ディメンションを segments/max メトリックに追加しました #18890

  • GroupByStatsMonitor を追加しました。これには、peons で発行されるメトリクスの dataSource および taskId ディメンションが含まれます #18711

  • task/waiting/time メトリクスを追加しました。これは、タスクがタスク ランナーに配置されてスケジュール設定と実行にかかる時間を測定します #18735

  • 複数のスーパーバイザーが単一のデータソースにデータを取り込む状況を明確にするために、ストリーミング タスク メトリックに supervisorId を追加しました #18803

  • セグメント キャッシュによるストレージと仮想ストレージの使用量を測定するために、StorageMonitor を druid.monitoring.monitors に追加しました #18742

  • Druid は次のログを記録するようになりました。

  • スキャッター/ギャザーの最大バイト制限に達したときに収集される合計バイト数 #18841

    • 失敗したリクエストに対する query/bytes メトリクス #18842

  • メトリック名だけでなくすべてのラベル値の組み合わせを考慮するように、Prometheus エミッター TTL トラッキングを変更しました。 TTL が設定されていない場合、ラベルは追跡されません #18718 #18689

  • ライフサイクル stop() が start() #18640 と一致するように info レベルで記録されるように変更されました。

  • タスクが完了するたびにメトリクスが発行されるように、メトリクス発行のトリガーを変更しました #18766

  • すべてのタスク完了のメトリクスを出力するようにメトリクス エミッタを改善しました #18766

SpectatorHistogram 拡張機能

  • ベクトル化により SpectatorHistogram 拡張機能のパフォーマンスが向上しました #18813

アップグレードに関する注意事項と互換性のない変更

アップグレードに関する注意事項

MSQ コントローラーのタスク

Druid 30 以前からアップグレードする場合、これらの古いバージョンとの下位互換性がない新しいカウンターが追加されるため、ローリング アップデート中に MSQ query_controller タスクが失敗する可能性があります。失敗したクエリは更新の完了後に再試行できます。または、ローリング アップデート中に実行する必要がある MSQ ジョブのクエリ コンテキストで includeAllCounters を false に設定することもできます。または、Druid 36 にアップグレードする前に、まず Druid 31 ～ 35 にアップグレードすることもできます。

#18761

セグメント形式

Druid 36.0.0 はセグメント フォーマット バージョン 10 をサポートしています。Druid の以前のバージョンはバージョン 10 をサポートしていません。ダウングレードする場合は、サポートされているセグメント フォーマット バージョンでデータを再インデックスする必要があります。

#18880

非推奨のメトリクス

以前にタスク ID を表すために JettyMonitor、OshiSysMonitor、JvmMonitor、JvmCpuMonitor、JvmThreadsMonitor、SysMonitor から id ディメンションを出力していた Peons 上のモニターは非推奨となり、将来のリリースでは削除される予定です。代わりに taskId 寸法を使用してください。

#18709

削除されたメトリクス

次の古い指標は削除されました。

  • segment/cost/raw #18846
  • segment/cost/normalized #18846
  • segment/cost/normalization #18846
  • task/action/log/time #18649

開発者向けメモ

セグメント ファイル インターフェイス

新しい SegmentFileBuilder および SegmentFileMapper インターフェイスは、FileSmoosher および SmooshedFileMapper の直接使用を置き換えて、セグメントの構築および読み取りプロセスを抽象化するために定義されました。

カスタム列実装を使用した拡張ライターの開発者に明らかな主な変更点は、Serializer インターフェイスで writeTo メソッドが変更されたことです。

  • FileSmoosher の代わりに SegmentFileBuilder を受け入れるようになりました。
  • ColumnBuilder メソッド getFileMapper は、SmooshedFileMapper ではなく SegmentFileMapper を返すようになりました。

カスタム列の実装を提供しない拡張機能は、これらの変更の影響を受けません。

#18608
