druid 0.21.0

マイナー 公開日2021年4月28日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.21.0 Apache Druid 0.21.0 には、約 120 の新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 36 人の寄稿者による追加のテスト カバレッジが含まれています。詳細については、変更の完全なリストとマイルストーンにタグ付けされたすべての項目を参照してください。

<a name="21-new-features" href="#21-new-features">#</a> 新機能

<a name="21-operation" href="#21-operation">#</a> オペレーション

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Kubernetes に基づくサービス検出とリーダー選出

新しい Kubernetes 拡張機能は、Kubernetes に基づくサービス検出とリーダー選出をサポートします。この拡張機能は、HTTP ベースのサーバー ビュー (druid.serverview.type=http) およびタスク管理 (druid.indexer.runner.type=httpRemote) と連携して動作し、ZooKeeper 依存関係なしで Druid クラスターを実行できるようにします。この拡張機能はまだ実験段階です。詳細については、「Kubernetes 拡張機能」(https://druid.apache.org/docs/latest/development/extensions-core/kubernetes.html) を参照してください。 https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> セグメント バランシングの候補セグメントを見つけるときにセグメント数を制限する新しい動的コーディネーター構成

percentOfSegmentsToConsiderPerMove を設定して、移動する候補セグメントを選択するときに考慮されるセグメントの数を制限できます。候補は最大 maxSegmentsToMove * 2 回検索されます。この新しい構成により、特にクラスター内に使用可能なセグメントが多数ある場合、Druid がセグメントのバランシング プロセスを高速化するために使用可能なすべてのセグメントを反復処理することがなくなります。詳細については、「コーディネーターの動的構成」(https://druid.apache.org/docs/latest/configuration/index.html#dynamic-configuration) を参照してください。 https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> インデクサーの status および selfDiscovered エンドポイント

インデクサーは、status および selfDiscovered エンドポイントをサポートするようになりました。詳細については、「プロセッサ情報 APIs」(https://druid.apache.org/docs/latest/operations/api-reference.html#process-information) を参照してください。 https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> クエリ

<a name="21-grouping-function" href="#21-grouping-function">#</a> 新しい grouping アグリゲーター関数

新しい grouping アグリゲーター SQL 関数を GROUPING SETS または CUBE とともに使用して、現在のグループ化セットにどのグループ化ディメンションが含まれているかを示すことができます。詳細については、「集計関数」(https://druid.apache.org/docs/latest/querying/sql.html#aggregation-functions) を参照してください。 https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> 式および関数における欠落引数の処理を改善しました。

入力が欠落している場合でも式処理をベクトル化できるようになりました。たとえば、存在しない列です。式に引数が欠落している場合、Druid は null 以外の引数に基づいて適切なタイプの結果を推論できるようになりました。たとえば、longColumn + nonExistentColumn の場合、nonExistentColumn は (double) 0.0 ではなく (long) 0 として扱われます。最後に、デフォルトの null 処理モードでは、数学関数は欠落している引数をゼロとして扱うことで出力を適切に生成できます。 https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> TIMESTAMPADD にはゼロピリオドを許可します

TIMESTAMPADD 関数でゼロ期間が許可されるようになりました。この機能は、Tableau などの一部の BI ツールに必要です。 https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> 取り込み

<a name="21-Parallel-ingestion-without-intervals" href="#21-Parallel-ingestion-without-intervals">#</a> ネイティブの並列取り込みに明示的な間隔は必要なくなりました

並列タスクでは、granularitySpec で明示的な間隔を設定する必要がなくなりました。間隔が欠落している場合、並列タスクは、インデックスを作成する間隔を収集する入力サンプリングの追加のステップを実行します。 https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> 古い Kafka バージョンのサポート

Druid は、0.11 よりも古い Apache Kafka をサポートするようになりました。 Kafka の古いバージョンから読み取るには、consumerProperties で isolation.level を read_uncommitted に設定します。このリリースまでにテストされているのは 0.10.2.1 のみです。詳細については、Kafka スーパーバイザ構成 を参照してください。 https://github.com/apache/druid/pull/10551

ネイティブ バッチ インジェストのためのマルチフェーズ セグメント マージ

新しい TuningConfig maxColumnsToMerge は、タスク内で同時にマージできるセグメントの数を制御します。この構成は、マージ中の高いメモリ負荷を回避するのに役立ちます。詳細については、ネイティブ バッチ インジェストの TuningConfig を参照してください。 https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> ネイティブの再取り込みはメモリの使用量が少なくなります

並列タスクは、セグメントをサブタスクに割り当てる前に、ID でセグメントを並べ替えるようになりました。この並べ替えにより、各サブタスクが処理する時間チャンクの数が最小限に抑えられます。その結果、特に長期間にわたるセグメントを再取り込むために単一の並列タスクが発行される場合、各サブタスクで使用されるメモリが少なくなることが予想されます。 https://github.com/apache/druid/pull/10646

<a name="21-web-console" href="#21-web-console">#</a> Web コンソール

<a name="21-refresh-console-style" href="#21-refresh-console-style">#</a> Web コンソール スタイルの更新および改善

新しい Web コンソール スタイルでは、Druid ブランドのカラーがより有効に活用され、全体のパディングとマージンが標準化されています。アイコンと背景色がドルイドのロゴから派生するようになりました。 https://github.com/apache/druid/pull/10515

<a name="21-web-console-partitioning" href="#21-web-console-partitioning">#</a> パーティショニング情報は Web コンソールで確認できます。

Web コンソールには、新しい Segment granularity 列と Partitioning 列に関するデータソース パーティショニング情報が表示されるようになりました。

「Datasources」タブの「Segment granularity」列

「Segments」タブの「Partitioning」列

https://github.com/apache/druid/pull/10533

<a name="21-web-console-dim-ordering" href="#21-web-console-dim-ordering">#</a> Schema テーブルの列の順序は dimensionsSpec と一致します。

Schema テーブルは、dimensionsSpec のディメンションの順序を反映するようになりました。 https://github.com/apache/druid/pull/10588

<a name="21-metrics" href="#21-metrics">#</a> メトリクス

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> コーディネーター デューティ ランタイム メトリック

コーディネーターはいくつかの「義務」タスクを実行します。たとえば、セグメントのバランシング、新しいセグメントのロードなどです。コーディネーターがこれらの業務をどれだけ速く実行しているかを分析するのに役立つ 2 つの新しいメトリクスが追加されました。

  • coordinator/time: 個々の義務が実行される時間
  • coordinator/global/time: 実行可能なタスク全体の実行時間 https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> クエリ タイムアウト メトリック

新しいメトリクスは、タイムアウトしたクエリの数を示します。以前にタイムアウトしたクエリは中断されたものとして扱われ、query/interrupted/count に含まれていました (詳細については、クエリ エラーの HTTP ステータス コードの変更 を参照してください)。 query/timeout/count: 発行期間中にタイムアウトしたクエリの数 https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> バッチ取り込み用のシャッフル メトリクス

2 つの新しいメトリクスは、MiddleManager と Indexer のシャッフル統計を提供します。これらのメトリックには、ディメンションとして supervisorTaskId があります。

  • ingest/shuffle/bytes: 放出期間ごとにシャッフルされたバイト数
  • ingest/shuffle/requests: 放出期間ごとのシャッフル リクエストの数 シャッフル メトリックを有効にするには、druid.monitoring.monitors に org.apache.druid.indexing.worker.shuffle.ShuffleMonitor を追加します。詳細については、「シャッフル メトリクス」(https://druid.apache.org/docs/latest/operations/metrics.md) を参照してください。 https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> 新しいクロックドリフト安全なメトリクス監視スケジューラ

デフォルトのメトリクス モニター スケジューラは、無制限の クロック ドリフト が発生しやすい ScheduledThreadPoolExecutor に基づいて実装されています。新しいモニター スケジューラ ClockDriftSafeMonitorScheduler は、この制限を克服します。新しいスケジューラを使用するには、runtime.properties ファイルで druid.monitoring.schedulerClassName を org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler に設定します。 https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-others" href="#21-others">#</a> その他

<a name="21-rds-password-provider" href="#21-rds-password-provider">#</a> AWS RDS トークンに基づくパスワードプロバイダーの新しい拡張機能

新しい PasswordProvider タイプでは、一時的な AWS トークンを使用して AWS RDS DB インスタンスにアクセスできます。この拡張機能は、RDS が Druid のメタデータ ストアとして使用される場合に役立ちます。詳細については、AWS RDS 拡張機能 を参照してください。 https://github.com/apache/druid/pull/9518

<a name="21-system-table-leader" href="#21-system-table-leader">#</a> sys.servers テーブルにはリーダーが表示されます

sys.servers テーブルの新しい長い型の列 is_leader は、サーバーがリーダーであるかどうかを示します。 https://github.com/apache/druid/pull/10680

<a name="21-https-influxdb" href="#21-https-influxdb">#</a> druid-influxdb-emitter 拡張機能は HTTPS プロトコルをサポートします

新しい構成については、Influxdb エミッタ拡張機能 を参照してください。 https://github.com/apache/druid/pull/9938

<a name="21-small-docker" href="#21-small-docker">#</a> 小さい docker 画像

docker の画像サイズは、不要な重複を排除することで半分に縮小されます。 https://github.com/apache/druid/pull/10506

<a name="21-development" href="#21-development">#</a> 開発

<a name="21-dynamic-config-provider" href="#21-dynamic-config-provider">#</a> 新しい DynamicConfigProvider による拡張可能な Kafka コンシューマー プロパティ

新しいクラス DynamicConfigProvider により、実行時にコンシューマ プロパティを取得できるようになります。たとえば、静的でない場合は、ローカル環境変数などの場所から DynamicConfigProvider フェッチ bootstrap.servers を使用できます。現在、デフォルトではマップベースの構成プロバイダーのみがサポートされています。カスタム構成プロバイダーを実装する方法については、DynamicConfigProvider を参照してください。 https://github.com/apache/druid/pull/10309

<a name="21-bug-fixes" href="#21-bug-fixes">#</a> バグ修正

Druid 0.21.0 には 30 件のバグ修正が含まれています。完全なリストはここ でご覧いただけます。

<a name="21-post-agg-subtotal" href="#21-post-agg-subtotal">#</a> 小計を使用した集計後の計算

0.21.0 より前では、小計を含むポスト アグリゲーターを使用すると、クエリはエラーで失敗します。このバグは修正され、小計で事後集計を使用できるようになりました。 https://github.com/apache/druid/pull/10653

<a name="21-indexer-announce" href="#21-indexer-announce">#</a> インデクサーは自身をセグメント サーバーとしてアナウンスします

0.19.0 および 0.20.0 では、インデクサーは自身をセグメント サーバーとして宣言していないため、ストリーミング データに対するクエリを処理できませんでした。 0.21.0 で自分自身を適切にアナウンスするように修正されました。 https://github.com/apache/druid/pull/10631

<a name="21-historyal-segment-loading" href="#21-historyal-segment-loading">#</a> ヒストリカルのセグメント ファイルの有効性チェック

ヒストリカルは、セグメント ファイルをダウンロードした後に有効性チェックを実行し、それらのファイルがクラッシュした場合は自動的に再ダウンロードするようになりました。 https://github.com/apache/druid/pull/10650

<a name="21-storage-location-selector" href="#21-storage-location-selector">#</a> StorageLocationSelectorStrategy の注入エラーが修正されました

StorageLocationSelectorStrategy の構成の読み取り中の注入エラーが修正されました。 https://github.com/apache/druid/pull/10363

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> 0.21.0 へのアップグレード

Druid 0.20.0 から 0.21.0 にアップグレードする場合は、次の変更と更新を考慮してください。 0.20.0 よりも前のバージョンから更新する場合は、関連する中間バージョンの release note を参照してください。

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> クエリ エラーの HTTP ステータス コードを改善しました

このリリースより前、Druid はほとんどのクエリ エラーに対して「内部エラー (500)」を返しました。 Druid は原因に基づいて異なるエラー コードを返すようになりました。次の表に、エラーとそれに対応する変更されたコードを示します。 例外 |説明|古いコード |新しいコード ------------ | ------------- | ------------- | ------------- Calcite からの SqlParseException と ValidationException |クエリ計画が失敗しました | 500 | 400 クエリタイムアウト例外 |クエリの実行がタイムアウト内に終了しませんでした | 500 | 504 ResourceLimitExceededException |クエリは設定されたしきい値を超えるリソースを要求しました | 500 | 400 不十分なリソース例外 |クエリが送信された時点で利用可能なマージ バッファーがなかったため、クエリをスケジュールできませんでした。 500 | 429、QueryCapacityExceededException にマージされました クエリサポートされていない例外 |サポートされていない機能 | 400 | 501 クエリ タイムアウト エラー用の新しいクエリ メトリックもあります。詳細については、「新しいクエリ タイムアウト メトリック」(#21-query-timeout-metric) を参照してください。 https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> クエリ中断メトリクス

query/interrupted/count は、タイムアウトしたクエリをカウントしなくなりました。これらのクエリは query/timeout/count によってカウントされます。

<a name="21-context-dimension" href="#21-context-dimension">#</a> クエリ メトリックの context ディメンション

context は、すべてのクエリ メトリックに対して出力されるデフォルトのディメンションになりました。 context は、発行されたメトリックが参照するクエリのクエリ コンテキストを含む JSON 形式の文字列です。以前は変更されなかったディメンションを追加すると、Druid によって発行される一部のメトリクスが変更されます。この新しい context ディメンションをメトリクス パイプラインで処理することを計画する必要があります。ディメンションは JSON 形式の文字列であるため、一般的な解決策は、ディメンションを解析して平坦化するか、必要なビットを抽出して完全な JSON 形式の文字列 BLOB を破棄することです。 https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Apache ZooKeeper 3.4 のサポートが廃止されました

ZooKeeper 3.4 はしばらくサポートが終了しているため、ZooKeeper 3.4 のサポートは 0.21.0 で非推奨となり、近い将来削除される予定です。 https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> sys.segments テーブルの一貫したシリアル化形式と列の命名規則

sys.segments テーブル内のすべての列は、他のシステム テーブルとの一貫性を保つために JSON 形式でシリアル化されるようになりました。列名には同じ「スネークケース」規則が使用されるようになりました。 https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> 既知の問題

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Thrift ライブラリの既知のセキュリティ脆弱性

Thrift 拡張機能 は、Thrift 形式のファイルを Druid に取り込むのに役立ちます。ただし、Druid が使用する Thrift ライブラリのバージョンには 既知のセキュリティ脆弱性 があります。この脆弱性は、インデクサーの使用時に悪意を持って作成された Thrift ファイルを取り込むことによって悪用される可能性があります。 trusted ユーザーのみに DATASOURCE WRITE 権限を付与することをお勧めします。

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> docker ベースの Druid クラスターを実行する際の権限の問題

マシンで初めて Druid docker クラスターを実行する場合、0.21.0 イメージを使用すると、root アカウントで内部ディレクトリを作成できます。その結果、権限がないために Druid サービスが失敗する可能性があります。この問題は https://github.com/apache/druid/issues/11166. で報告されています docker compose を使用している場合は、以下のコマンドを使用してこの問題を回避できます。これらのコマンドは、最初に古いイメージを使用して内部ディレクトリを作成し、次に 0.21.0 イメージを使用してサービスを開始します。

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

docker 構成を使用していない場合は、0.21.0 イメージを使用してサービスを開始するときに、/opt/druid/var のボリューム パラメーターを直接渡すことができます。たとえば、以下のコマンドを実行してコーディネーター サービスを開始できます。

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

未解決の問題の完全なリストについては、https://github.com/apache/druid/labels/Bug. を参照してください。
