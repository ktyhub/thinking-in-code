appsmith v2.6.0

マイナー 公開日2026年10月28日 出典appsmithorg/appsmith 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#アプリスミスv2.6.0

⚠️ EE ユーザーの場合、v2.6.0 にアップグレードする前に、v2.5.1 での既存の Temporal ワークフローの実行を終了してください

Appsmith は新しいワークフロー エンジンに移行しています。古い Temporal エンジンで開始された実行は、v2.6.0 にアップグレードした後は再開または終了することができません。

実行は、ワークフローの 1 回の実行です。これには、アクティブに何も処理していない場合でも、ユーザーがリクエストを承認するのを待っている実行が含まれます。

アップグレードする前に行うべきこと:

  1. 以前のバージョンを使用している場合は、まず v2.5.1 にアップグレードします。
  2. 承認待ちのものも含め、Temporal でのすべての実行を終了させます。残りの作業を放棄しても構わない場合にのみ、実行を停止してください。
  3. [管理設定] → [インスタンス] → [管理セントラル] で、v2.5.0 · ワークフロー エンジンの移行 チェックポイントを確認して承認します。 ワークフロー エンジン移行ガイドに従ってください。
  4. v2.6.0 にアップグレードします。

ダウンタイムの可能性: アップグレード チェックにより、古いエンジンからの保留中の承認リクエストが見つかった場合、Appsmith サーバー全体が起動できなくなる可能性があります。アップグレードする前に上記の手順を完了してください。未完了の実行をすべて検出するために起動チェックに依存しないでください。

このチェックポイントによって起動がブロックされた場合は、v2.5.1 に戻り、影響を受ける実行を終了するか意図的に停止し、チェックポイントを完了して、アップグレードを再試行します。

🔐 Brotli セキュリティ修正 (CVE-2026-111497):

Appsmith v2.6.0 には、Node.js Brotli デコーダーの脆弱性の修正が含まれています。悪意を持って作成された Brotli 圧縮データを処理すると、メモリが破損し、サービスのクラッシュが発生したり、プロセス メモリが公開されたり、リモート コードが実行されたりする可能性があります。セルフホストのお客様は、修正プログラムを受け取るために v2.6.0 にアップグレードする必要があります。詳細については、Node.js セキュリティ アドバイザリ を参照してください。

⚠️ アップグレードに関する重要な注意事項

  • カスタマイズされた docker.env ファイルには、解決されたリテラル値が含まれている必要があります。シェル式は編集された診断で起動を停止します。アップグレードする前に、JVM オプションを docker.env から Docker Compose または Helm 環境構成に移動します。文書化されたトレース エクスポーター エンドポイントを含む OTEL_* 名が受け入れられるようになりました。生成されたデフォルトと管理設定の値を変更する必要はありません。 (#42225、#42422)
  • Redis クエリでは静的コマンド名を使用する必要があります。コマンド名のバインディングにより、クエリ構成エラーが返されます。バインディング値は 1 つの引数内に留まります。 (#42465)
  • DynamoDB プラグインは、Java 2.55.9 に対して AWS SDK を使用するようになりました。領域には文字、数字、ハイフンのみを含める必要があり、最大 63 文字にする必要があります。応答には追加のキーを含めることができます。既存のキーと値は変わりません。サーバーが AWS_ENDPOINT_URL、AWS_ENDPOINT_URL_DYNAMODB、AWS_USE_FIPS_ENDPOINT、または AWS_USE_DUALSTACK_ENDPOINT を設定した場合、プラグインはそれらを尊重するようになりました。 (#42346)

🔐 セキュリティ

  • 報告された脆弱性に対処するために、バンドルされた依存関係を更新しました。 (#42444、#42449、#42466、#42475、#42492)
  • エディター モードのページとレイアウトの読み取りには編集権限が必要になり、下書きが返されます。表示モードでも読み取り権限が必要であり、公開されたページが返されます。 (#42425)
  • アプリケーションまたはデータソースを更新すると、それが作成されたワークスペースが保持されるようになりました。 (#42462)
  • ワークスペースの作成では、client が提供する ID、ポリシー、および権限グループが無視されるようになりました。サーバーがそれらを生成します。 (#42478)
  • Redis クエリ バインディングは 1 つのコマンド引数内に留まるため、バインドされた値に追加の引数を追加することはできません。 (#42465)

🛠️ 信頼性

  • Public apps again receive the configured Google Maps key, so Map widgets work for anonymous viewers. (#42440)
  • データソース認証情報を保存すると、すべてのサーバー ポッドでそのデータソースのキャッシュされた接続が削除されるようになりました。 (#42430)
  • エビクトされたデータソース接続を閉じる操作が共有リクエスト スレッドで実行されなくなるため、1 つのデータベースがハングしてもヘルス チェックが停止することがなくなりました。 (#42450)
  • ページビューは、エディターがレイアウト DSL をロードしたときではなく、ページを開いたときに記録されます。 (#42429)
  • トランザクション項目やインデックス設定を含む、ネストされた DynamoDB リクエスト オブジェクトが、毎回同じ方法で構築されるようになりました。 (#42346)

✨ 新機能と機能強化

  • MCP 構造化 SQL フィルターは、isNull および notNull をテストできます。 (#42491)
  • MCP 構造化 SQL フィルターは、anyOf を使用して条件をグループ化できます。これは OR にコンパイルされ、他のフィルターと結合されます。 (#42495)
  • MCP 構造化 SQL like は、含まれるテキスト、プレフィックス、サフィックス、または正確なテキストと一致します。 PostgreSQL クエリでは ilike を使用できます。 (#42496)

🎨 UI とウィジェットの改善

  • In App Settings → Navigation, Show logo and Show application title no longer switch themselves while a save is in progress. (#42488)

🔧 Git、デプロイメント、構成

  • docker.env は、文書化された OpenTelemetry トレース エクスポータ エンドポイントを含む OTEL_* 名を受け入れるようになりました。 An externally set OTEL_* value still overrides the file on restart. (#42422)
  • Browser telemetry is now sent for builders only. Anonymous visitors and end users of published apps are no longer tracked in the browser. (#42353)
