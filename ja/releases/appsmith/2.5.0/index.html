appsmith v2.5.0

#アプリスミスv2.5.0

🗑️ 機能削除のリマインダー - 2026 年 9 月 30 日 - EOL

Appsmith AI は 2026 年 9 月 30 日にサポート終了となりました。

新しい Appsmith AI データソース接続やクエリを追加できなくなりました。アップグレードしたかどうかに関係なく、既存のクエリは機能しなくなりました。

残りの Appsmith AI クエリを、OpenAI、Anthropic、Google AI などの直接プロバイダー データソースに移行します。

⚠️ アップグレードに関する重要な注意事項

  • Git に接続されたアプリケーションは、次に開いたときにサーバー スキーマ 13 に更新されます。これにより、1 回限りのシステム コミットが作成される可能性があります。このリリースからエクスポートされたアプリケーションは、スキーマ 12 のみをサポートする古いサーバーにインポートできません。 (#42322)
  • データソース接続設定を変更する場合は、アクティブな認証、TLS、および SSH 設定の資格情報を再度入力する必要があります。変更されていない接続では、保存された認証情報を引き続き使用できます。 (#42339)
  • Elasticsearch ボディ バインディングは、型指定された JSON 置換を使用するようになりました。シリアル化された JSON を挿入するクエリ、JSON 文字列の一部を構築するクエリ、または動的パスを構築するクエリを確認します。無効なバインディングはクエリ エラーを返すようになりました。 (#42342)

🔐 セキュリティ

  • 報告された脆弱性に対処するために、バンドルされた依存関係を更新しました。 (#42314、#42324、#42331)
  • データソース資格情報の再利用は、保存された接続構成に関連付けられるようになり、データソースのテスト、構造、トリガーのリクエストでは、より厳格な権限チェックが使用されます。 (#42339)
  • 評価環境からのリクエストは、グローバル リクエスト コンストラクターが変更された場合でも、資格情報省略ガードを維持するようになりました。 (#42355)
  • ログイン レート制限では、認証と同じ正規化されたアカウント ID が使用されるようになりました。 (#42337)
  • データソースの更新では、リクエストによって選択されたデータソースの ID が保持されるようになりました。 (#42356)
  • Elasticsearch クエリは、置換された JSON および動的パス値を実行前に検証するようになりました。 (#42342)

🛠️ 信頼性

  • 準備された MySQL ストアド プロシージャ呼び出しを後続のクエリで実行し、バインドされた値をデータとして保持できるようになりました。 (#42329)
  • OAuth2 および SSO ログインが失敗すると、ユーザーはインスタンスのログイン ページに戻されるようになりました。 (#42330)
  • カード、タブ、シート、リスト項目のゾーンは、狭い列に折りたたまれるのではなく、利用可能な幅全体を使用するようになりました。 (#42364)
  • MCP データソースの作成により、サーバーは正しい環境を選択できるようになりました。 (#42341)

✨ 新機能と機能強化

  • アプリケーションには、アプリケーション カードに表示されるオプションの説明を含めることができるようになりました。 (#42312)
  • リスト ウィジェットには、行選択や item-click 動作を必要としないアプリ向けに 選択を無効にする オプションが追加されました。 (#42261)
  • MCP は、構造化 JS オブジェクトの作成と更新、より多くの MongoDB フィルター タイプの使用、より多くのウィジェット設定のパッチ、JS 関数呼び出しの関連付け、一般的なレイアウトの問題の検出ができるようになりました。 (#42311)

🎨 UI とウィジェットの改善

  • テーブル列に、長い列タイトルのオプションの ヘッダー ラッピング 設定が追加されました。 (#42354)
  • テーブルヘッダーは、設定可能なフォントの太さ、斜体テキスト、および下線をサポートするようになりました。 (#42323)
  • [アプリケーション] ページは、欠落しているベース URL バナーの下に留まるため、ワークスペース コントロールは表示されたままになります。 (#42319)

🔧 Git、デプロイメント、構成

  • MCP ログは、各ツール呼び出しの実際の結果を記録し、関連するバックエンド呼び出しの正しいリクエスト ID を保持するようになりました。 (#42350)
