vllm v0.29.0

#v0.29.0

ハイライト

このリリースには、277 人の寄稿者 (91 人が新規) による 594 件のコミットが含まれています。

  • Model Runner V2 はすべてのモデルのデフォルトになりました (#53183)。これにより、モデルのプーリング (#48290) から始まったロールアウトが完了しました。 MRV2 はまた、KV キャッシュの自動サイズ変更のための CUDA グラフ メモリ プロファイリング (#53306)、ステップごとのロジット メモリを 1/TP で削減するバッチ シャーディング サンプリング (#50465)、プロンプト埋め込み (#42963)、extract_hidden_states 投機 (#49811)、仕様デコードの下での均一デコードのためのパディングされた FULL cudagraph ディスパッチ (#53407) も獲得しました。 EAGLE/MTP ドラフト プレフィル前の DP 同期スキップ (#53694)。 MRV1 は、MRV2 がまだサポートしていないいくつかの ROCm モデルおよび機能で引き続き使用されています。
  • 新しいモデル: Hy4 プレビュー、Gated DeepSeek Sparse Attend およびネイティブ MTP を備えた Tencent の 770B/49B アクティブ MoE (#54160); BF16/FP8/NVFP4 および MTP を備えた Qwen3.8-Flash-Next (#53896); GraniteSWA および GraniteMoeSWA (#52706); MTP を使用した NemotronH_Omni_Reasoning_V3 (#52929、#53121);キミ K3 NVFP4 チェックポイント (#53132)。
  • Kimi-K3 と DeepSeek V4 のパフォーマンス: K3 潜在テールでの融合 MXFP4 top-k ファイナライズ (約 5% E2E 遅延、#53152)、1 回の Triton 起動での K3 Mamba メタデータ準備 (6.6-7.6x カーネルの高速化、#52388)、調整された Hopper 低遅延 GEMM (#54088) は SM100 でもディスパッチされるようになりました。 (#53534) および eh_proj (12.9-25.2% カーネルの高速化、#53942)、GEMM-RS の GEMM-AR への拡張 (#53053)、MLA ゲートの QKV-A プロジェクションへのマージ (#54015)、K3 DCP と DSpark (#52188)、および DCP 部分プレフィックス キャッシュ ヒット (#50493) に使用されます。 DeepSeek V4 共有エキスパートは MegaMoE (#53040)、アダプティブ top-k width re-landed (#52823)、Humming MoE 用ネイティブ SwiGLU クランプ カーネル (#53685)、およびオプトイン FlashInfer moe_ep エキスパート バックエンド (#49636) に融合されました。
  • 投機的デコード: --per-request-spec-decode-metrics 経由の OpenAI API 応答におけるリクエストごとの受け入れ統計 (#48915)、logprob に拡張された適応検証 (#52242)、GLM-5.2 用の SM100 スパース MLA (#52783) および SM90 上の DeepSeek V4 (#52795)、Qwen3-Omni DSpark ドラフト(#52560)、PLaMo3 EAGLE-3/DFlash (#54239)、およびスペキュレーター フォーマットからの DFlash2 ロード (#53797)。
  • RL 重み同期: 各ワーカーが NIXL または Ray Direct Transport 経由で TP/EP スライスのみをプルする新しい sharded_rdt P2P バックエンド (#43375)、ランクローカル IPC 重み更新 (#52497)、ネイティブ重みローダーを介したスパース チェックポイント座標更新 (#50723、#53751)、および gpt-oss のルーティングされたエキスパート ロード (#52209)。
  • Mamba プレフィックス キャッシュ: 内部プレフィル チェックポイントにより TTFT が 9% ～ 25% 向上しました (#52789)。 prefix_cache_retention_interval は、デフォルトで 0 に設定される CLI 引数 (#52216) となり、EAGLE/MTP を使用するハイブリッド モデルでは高密度保持が自動的に復元されます (#55760、#55861)。
  • 新しいデフォルト: TP CUDA グループでは FlashInfer all-reduce がデフォルトで有効になっており、VLLM_ALLREDUCE_USE_FLASHINFER=0 (#52998) でオプトアウトします。 prefix-cache NONE_HASH はデフォルトで決定的であるため、分散 KV キャッシュ ユーザーは PYTHONHASHSEED を固定する必要がなくなりました (#51875)。新しい --max-num-queued-reqs / --max-num-queued-tokens アドミッション コントロール フラグ (#49445)。
  • 重大な変更: 10 個の非推奨モデル アーキテクチャが削除されました (#53608)。 FlexOlmo、Olmo3、および Hunyuan V1/VL は、Transformers モデリング バックエンド (#53615) に移行されました。 PyAV ビデオ デコーダー バックエンドが削除されました (#54231)。 python -m vllm.entrypoints.openai.api_server は廃止され、vllm serve (#52131) が採用されました。 VLLM_TEST_FORCE_FP8_MARLIN (#52182) および VLLM_ROCM_USE_AITER_FP4_ASM_GEMM (#53141) が削除されました。

:警告: Model Runner V1 の非推奨

現在、Model Runner V2 がデフォルトで使用されているため、Model Runner V1 の廃止を検討しており、v0.32 を削除の対象としています。 MRV1 固有の改善や最適化をこれ以上受け入れるつもりはありません。

一部の 機能 は MRV2 ではまだサポートされていませんが、これらのギャップは今後 2 ～ 3 週間以内に埋められる予定です。これらには、シーケンス並列処理、デュアルバッチ オーバーラップ、エラスティック エキスパート並列処理、カスタム ロジット プロセッサ、および特定の投機的デコード方法が含まれます。現時点では、これらの機能のいずれかが設定されている場合、vLLM は引き続き MRV1 を使用するようにフォールバックします。
