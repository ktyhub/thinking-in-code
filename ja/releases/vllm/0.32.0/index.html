vllm v0.32.0

#v0.32.0

ハイライト

このリリースには、363 人の寄稿者 (121 人が新規) からの 814 件のコミットが含まれています。

  • 構造化された決定と汎用パーサー: 新しい POST /v1/systemone エンドポイントは、構造化された状態 (#59299) を介して choice、noul、および score の質問に答え、デフォルトで提供され (#60677、#60696)、さらに Cloudflare/clef-omni (#61064)、LiquidAI/d1-3B (#60676)、および DiffusionGemma 上でも実行されます。 (#60466)。新しい hf ツールおよび推論パーサー (--tool-call-parser hf、--reasoning-parser hf) はチェックポイントの response_template を読み取るため、これを出荷するモデルには、Python および Rust フロントエンド (#59005) の両方でモデル固有のパーサー (#58604、#58602) が必要ありません。
  • どこでも低精度の KV キャッシュ: NVFP4 KV キャッシュは SM8x および SM12x (#46963)、SM90 (#60620) で実行され、SM12x (#60452) では XQA デコードを使用して実行され、SM100 (#59300) では MiniMax-M3 スパース アテンションで実行されます。 GLM-5.x はデフォルトで SM100 上の FP8 KV キャッシュを使用し、PR のベンチマーク (#60140、#60281) で 7 ～ 11% の TTFT コストで 2.3-5.5% 高いスループットでランクあたりの KV メモリを半減します。 SM90 上の fp8_ds_mla により、GLM-5.3-Flash の出力スループットが最大 31% 向上します (#59246)。 ROCm は、FP8 (#57057) の約 2 倍の密度で 4 ビット ultraquant_4bit KV キャッシュを獲得します。
  • Model Runner V2: 可変長ドラフト (#40704)、Elastic EP (#53934)、MLA モデルのプリフィルコンテキスト並列処理を備えたパイプライン並列処理 (#59139)、ストック torch.compile モード (#59079)、および MRV2 が ROCm のデフォルトとなり、モデル固有の MRV1 例外が削除されました。 (#56360)。
  • 起動と提供の高速化: vllm download-kernels は、FlashInfer のプリコンパイル済みカーネル (#58765) をインストールします。 vllm preload --preload-autotune は、再起動後も FlashInfer 自動調整テーブルをウォームに保ちます (#60085)。共有メモリ テンソル アリーナは、1 つのコピーで大規模なマルチモーダル テンソルをワーカーにブロードキャストします (#51207)。トークナイザーとプロセッサーはローカル スナップショットからロードされます (#60825)。 --api-server-count が 1 を超えると、各接続は最も負荷の低い API ワーカーに送信され、PR のベンチマーク (#60723) で短いリクエスト (Qwen3-0.6B、32 入力 / 1 出力トークン) でのリクエスト/秒が 43 ～ 85% 増加します。
  • モデルのサポート: 新しい EmbeddingGemma 2 オムニモーダル エンベディング (#60254)、MiniCPM-V 4.7 (#58674)、および Nemotron 3.5 ASR (#59827)。トランスフォーマー モデリング バックエンドのビデオ入力 (#57441); GLM-5.3 スパース MLA インデックス変換はレイヤー間で再利用され (そのカーネル上の 3.5-3.9x、#59464)、融合されたマルチステップ ドラフト デコード (同時実行 1 での 13.3%、#57443)。 HiSparse リクエストごとの常駐キャッシュにより、高同時実行時の長時間の完全 GPU 常駐コンテキストにより、B200 上の GLM-5.3-NVFP4 でスループットが最大 58% 向上します (#60083)。
  • セキュリティ: GHSA-4hhp-h66f-j5j7 (チャット テンプレート リソース枯渇、#50300)、GHSA-q97c-p368-75c4 (トークナイザー max_token_id、#59491)、および GHSA-frvg-qw88-hww9 (P2P ZMQ ソケット枯渇、#51504) を修正。 CORS はデフォルトですべてのオリジンを許可しなくなりました (#61009)。 untrusted イメージはラスター形式に限定されます (#60022)。共有メモリのマルチモーダル キャッシュ ハンドルは署名されています (#59357)。 64 レベルより深くネストされた JSON スキーマは拒否されます (#60036)。
  • 重大な変更: Python 3.10 は削除されました (#60402)。デフォルトの CORS オリジンは制限されています (#61009)。 transformers>=5.16.1,<5.20.0 および tokenizers>=0.23.2 (#57387、#59796); torch.compile シーケンスの並列処理と AsyncTP パスが削除されました (#60517)。カスケード アテンションが削除されました (#61126)。 mamba_cache_mode="all" が削除されました (#58997)。 max_tokens はコンテキスト ウィンドウから予約されなくなりました (#57035)。応答 API 推論ストリーム イベントの名前が変更されました (#59652)。

＃＃ 建てる

  • Python 3.11-3.14 をサポート (#60402)。安定した ABI (#60312) で構築された macOS ホイール。 CUDA ソースのビルドには GCC 13 が必要で、それ以外の場合は早期に失敗します (#60259)。 Docker イメージは、コンテナーの起動を高速化するためにビルド時に Python バイトコードをコンパイルします (#55422)。 VLLM_USE_PRECOMPILED は、最後の 20 コミット内で互換性のある公開ホイールを見つけます (#58871)。ベンダーの DeepGEMM は TORCH_LIBRARY (abi3、#48962) を使用します。

重大な変更と非推奨

  • Python 3.10 はサポートされなくなりました。最小値は Python 3.11 (#60402) です。
  • デフォルトの CORS 起点が * から none に変更されました。ブラウザ clients に --allowed-origins を設定します (#61009)。
  • transformers>=5.16.1,<5.20.0 および tokenizers>=0.23.2 が必要です (#57387、#59796)。
  • torch.compile シーケンスの並列処理と AsyncTP パスは、PassConfig.enable_sp、fuse_gemm_comms、sp_min_token_num とともに削除されました。モデルレベルのシーケンス並列処理は影響を受けません (#60517)。
  • カスケード アテンションが削除されました。 --disable-cascade-attn は引き続き解析しますが、警告のみを行うため、v0.33.0 (#61126) で削除されます。
  • mamba_cache_mode="all" は削除されました。 --mamba-cache-mode all は検証に失敗するようになりました (#58997)。
  • 以前に非推奨となった API は削除されました: wait_for_inflight_requests (mode="wait" を使用)、AsyncLLM.pause_generation()、IOProcessor.output_to_response、vllm.scripts.main()、および vllm bench throughput --dataset (#60923)。 sonnet ベンチマーク データセットは予定どおり削除されました (#60129)。 Tensorizer のサポートは LoRA から削除され (#60024)、PyO3 vllm._rust_tool_parser ブリッジは削除されました (#59744)。
  • API の変更: max_tokens は、コンテキスト ウィンドウから予約されるのではなく、出力の上限として扱われます (#57035)。応答 API ストリーミングでは、response.reasoning_part.added/done の代わりに response.content_part.added/done と part.type="reasoning_text" が使用されます (#59652)。 SamplingParams.prompt_logprob_token_ids は行ごとです (#56984)。 /inference/v1/generate logprobs は整数のトークン ID を使用します (#58181)。 sleep API 応答は標準化されており、無効なレベルは 400 を返します (#52864)。 return_mm_kwargs は非推奨になり、mm_payload (#61427) が優先されます。
  • ウォーターマーク: エンジンにウォーターマークが設定されている場合、省略されたリクエスト フィールドは有効になっていることを意味し、false のみがオプトアウトされます。サポートされていない組み合わせは警告を発し、フォールバックします (#56801)。
  • Rust フロントエンド: qwen3_xml は Qwen3-Coder XML (qwen3_coder のエイリアス) を解析するようになりました。 JSON フォーマットには新しい qwen3_json を使用してください (#60136)。
  • 新しいデフォルト: 共有メモリ テンソル アリーナ (#51207); --kv-cache-dtype auto を搭載した SM100 上の GLM-5.x FP8 KV キャッシュ (#60140、#60281)。 VLLM_DEEPEP_V2_ALLOW_HYBRID_MODE=1 (#57991); SM90 (#56997) ではマーリンよりハミングが好まれます。 sparse_mla_prefill_workspace_factor 2 256K max_model_len (#61023);モデル固有の MRV1 例外が削除された ROCm 上の MRV2 (#56360)。 VLLM_ROCM_AITER_MLA_DCP_VERIFY=auto (#59965); dtype=auto は PowerPC 上で bfloat16 を選択します (#58528)。 W4A4 カーネルが存在しない場合、MXFP4 W4A4 チェックポイントは W4A16 にフォールバックし、警告が表示されます (#60079)。
  • より厳格な検証: 互換性のない --prefix-match-unit (#58021)、max_num_scheduled_tokens=0 (#60714)、cudagraph_mode=FULL を含む HiSparse (#59688)、および負の --device-ids (#49053) は起動時に拒否されます。
