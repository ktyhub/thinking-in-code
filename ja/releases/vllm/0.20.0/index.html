vllm v0.20.0

#vLLM v0.20.0

ハイライト

このリリースには、320 人の寄稿者 (123 人が新規) からの 752 件のコミットが含まれています。

  • DeepSeek V4: DeepSeek V4 の初期サポートが開始されました (#40860)。DSV4/3.2 の DSML トークン漏洩修正 (#40806)、DSA + MTP IMA 修正 (#40772)、共有エキスパートの silu クランプ制限 (#40950) が含まれます。
  • CUDA 13.0 のデフォルト: PyPI および vllm/vllm-openai:v0.20.0 イメージ上のデフォルトの CUDA ホイールが CUDA 13.0 に切り替わりました。アーキテクチャ リストとビルド引数がクリーンアップされ (#39878)、CUDA は PyTorch 2.11.0 (#40669) と一致するように 13.0.2 に変更されました。一般的な経験則として、当社の CUDA バージョン ポリシーは PyTorch のポリシーに従います。 vLLM を uv でインストールし、CUDA 12.9 を使用している場合は --torch-backend=cu129 を使用することを強くお勧めします。
  • PyTorch 2.11 アップグレード (#34644): vLLM は CUDA 用のトーチ 2.11 で出荷され、XPU はトーチ 2.11 (#37947) にも搭載されるようになりました — XPU は 2.10 に固定されなくなりました。これは環境依存性に対する重大な変更です。
  • Python 3.14: サポートされている Python バージョン リスト (#34770) に追加されました。
  • Transformers v5: vLLM は、ビジョン エンコーダー torch.compile バイパス (#30518) を備えた HuggingFace transformers>=5 (#30566) で実行されるようになり、PaddleOCR-VL 画像プロセッサ max_pixels (#38629)、Mistral YaRN 警告 (#37292)、Jina ColBERT ロータリーなどの継続的な v4/v5 互換修正が行われました。 inv_freq の再計算 (#39176)。
  • 新しい大規模モデル: HYV3 推論パーサー (#40713) を備えた Hunyuan v3 (Hy3) プレビュー (#40681)。組み込みマルチモーダル モデルとしての Granite 4.1 Vision (#40282)。
  • デフォルトの MLA プリフィルとしての FlashAttendant 4: FA4 がデフォルトの MLA プリフィル バックエンド (#38819) として再度有効になり、SM90+ でのヘッドディム 512 およびページ KV サポート (#38835) に加えて、アップストリーム FA4 同期 (#38690) が追加されました。
  • TurboQuant 2 ビット KV キャッシュ: 4 倍の容量で 2 ビット KV キャッシュ圧縮を実現する新しい注目のバックエンド (#38479) に、FA3/FA4 プレフィル サポート (#40092) が追加されました。
  • オンライン量子化フロントエンド: 新しいエンドツーエンドのオンライン量子化フロントエンド (#38138)、ドキュメント (#39736) 付き。 Expert_int8 が FP8 オンライン パスに統合されました (#38463)。 MXFP8 オンライン クォントは新しいフロントエンド (#40152) に移動しました。
  • vLLM IR: rms_norm op (#33825)、OOT プラットフォーム カーネル インポート (#38807)、IR 上で再加工された gemma_rms_norm (#39014)、および追加された IR op テスト/ベンチマーク インフラ (#40167) を含む初期 IR スケルトン — 将来のカーネル作業の基盤。
  • Model Runner V2 の進歩: Eagle プレフィル フル CUDA グラフ (#37588)、アテンション バックエンドからの cudagraph モード/サイズの自動解決 (#32936)、融合された確率的拒否サンプル カーネル (#38496)、サポートされていない機能の構成検証 (#38758)、eagle ドラフト デコードの区分的フォールバックの無効化 (#39773)、複数のプロンプトログプローブのサポート (#39937)、プレフィルウォームアップカバレッジ (#40746)、および古いサンプル/ドラフトトークンによって引き起こされる精度の低下の修正 (#39833)。
  • MoE リファクタリング シリーズ: 量子化されていないものは完全な Oracle フローに移行 (#36286)、CT W8A8 から Oracle (#39187)、SharedExperts クラス (#35153)、SharedFusedMoE が削除 (#35782)、DefaultMoERunner 分割 (#35326) され、その後 MoERunnerBase に再結合 (#40560)、共有/融合エキスパート出力合計が MoERunnerBase (#35949) に移動、ZeroExpertFusedMoE が新しいフレームワークに (#35549)、compressed_tensors_moe.py 分割 (#38960)、GPTQMarlinMoEMethod が MK で再加工 (#37990)、XPU と CUTLASS MoE が fused_moe/experts/ に再配置 (#40568、#40574)、 make_expert_params_mapping の名前変更 (#40671)、MoE LoRA リファクタリング (#40338)、MoE DP チャンキングの削除 (#39107)。
  • パフォーマンス: 融合 RMS ノルムによるバッチ不変条件の最適化 — 2.1% E2E レイテンシーの改善 (#40413); seq_lens_cpu GPU→CPU 同期を回避します (#40654)。キャッシュ InductorPass.hash_source (#39328);ウォーム コンパイルを高速化するために、読み込み時に FX グラフの逆シリアル化をスキップします (#40151)。起動時のメモリ アカウンティングをより明確にするために、CUDAGraph メモリ プロファイリングがデフォルトで有効になりました (#38284)。
