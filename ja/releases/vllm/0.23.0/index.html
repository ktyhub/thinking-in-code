vllm v0.23.0

vLLM v0.23.0 Release Notes

Minimax M3 はこのバージョンではまだサポートされていないことに注意してください。 M3 の使用ガイドについては、vLLM レシピ に従ってください。

ハイライト

このリリースには、200 人の貢献者 (63 人が新規) からの 408 件のコミットが含まれています。

  • DeepSeek-V4 はバックエンド全体で成熟します: v0.22.0 での導入に続き、DeepSeek-V4 はさらに大規模な強化および最適化パスを受けました。そのスパースな MLA メタデータは DeepSeek-V3.2 (#44699) から分離され、TRTLLM 世代のアテンション カーネル (#43827)、Mega-MoE の EPLB サポート (#43339)、スライディング ウィンドウ KV キャッシュの選択的プレフィックス キャッシュ保持 (#43447)、および DSA MTP のインデックス共有機能 (#44420) を獲得しました。モデルは torch.compile (#43746、#43891) からも切り離され、そのアテンションおよび RoPE パスがリファクタリングされ (#44569、#44262、#43926)、XPU アテンション デコード パスが追加されました (#42953)。
  • Model Runner V2 はより高密度のモデルに拡張: Qwen3 に加えて Llama および Mistral の高密度モデル (#43458) に対して MRv2 がデフォルトで選択されるようになりました。 FlashInfer サンプラー (#42472)、壊れやすい CUDA グラフ (#44050)、パイプライン並列バブル除去 (#42187)、ハイブリッド モデルのカーネル ブロック サイズ サポート (#38831)、および Gemma 4 MTP (#43241) が追加されました。
  • Rust フロントエンドの成長: 実験的な Rust フロントエンドには、ストリーミング generate エンドポイント (#43779)、動的 LoRA エンドポイント (#43778)、/version (#43854) および /server_info (#43942) エンドポイント、サーバールーター拡張フック (#43774)、リクエスト ID ヘッダーが追加されました。 (#43883)、および多くの新しいツール パーサー (InternLM2 #43481、hy_v3 #43872、Phi-4-mini #44213、Gemma4 #43850)。
  • Gemma 4: エンコーダーフリーの Gemma 4 Unified サポート (#44429) および Gemma 4 MTP (#43241) が追加され、さらに多数の精度と起動の修正が行われました。
  • Transformers v5 の互換性: vLLM は、ベンダーの MiniCPM-V/O プロセッサ (#44282) と Sarvam (#38804) および Voxtral (#44559) の互換性修正を含む Transformers v5 をターゲットにするようになりました。
  • 多層 KV キャッシュ オフロード: オフロード フレームワークには、オブジェクト ストア セカンダリ層 (#41968)、対応コネクタに対してデフォルトで有効化された HMA (#41847)、HMA モデルの階層化サポート (#44287)、および on_new_request ライフサイクル フックによるリクエストごとのオフロード ポリシー (#43205) が追加されました。
  • 統合パーサー: 推論とツール呼び出しの解析は単一の Parser.parse() インターフェイス (#44267) の背後に統合され、応答パーサーはそこに移行されました (#42977)。

モデルのサポート

  • 新モデル: Step-3.7-Flash (#43859)、Cosmos3 Reasoner (#43356)、Gemma 4 Unified エンコーダーなし (#44429)、JetBrains Mellum v2 (#43992)、Granite Speech Plus (#43519)、Cohere Mini Code (#44707)。
  • Gemma 4: エンコーダーフリーの統合サポート (#44429)、MTP (#43241)、ネイティブ ViT リニア レイヤー (#43798)、量子化から除外されたビジョン エンベッダー (#44571)、TP>1 での MTP の修正 (#43909)、同時実行時のブロック テーブルの不一致 (#43982)、トランスフォーマー プロセッサーの起動クラッシュ(#44232)、および CPU 初期化 (#44615)。
  • Transformers v5: ベンダー MiniCPM-V/O プロセッサー (#44282)、Sarvam compat (#38804)、トランス用 Voxtral fetch_audio ≥ 5.10 (#44559)。
  • モデルの修正と機能強化: torch.compile での Qwen3-VL/Qwen3-omni-thinker ディープスタック精度 (#43617)、Qwen3-VL 用 EVS (#44205)、GLM-5.1 PP ローディング (#42944)、GLM-4.1V プロセッサー ロジット (#43575)、GLM-4.6V ビデオ ローダー(#44417)、OlmoHybrid init (#43846)、HyperCLOVAX リモートコード削除 (#43860)、Bailing-MoE 回転係数 (#43770)、Step3 PP 残留 KeyError (#37622)、MiniCPM-V-4.6 ビデオ (#44509)、MiniCPM-O オーディオ アンパディング (#38053)、 MiniCPM-V バッチ前処理 (#44609)、FunASR-Nano init (#44215)、Cohere ルーティング メソッド (#44021)、Kimi-K2.5 FlashInfer ViT メタデータ (#44493)。
  • マルチモーダル: VLM の登録済みビデオ ローダーの自動選択 (#44126)、ステップごとの O(log n) マルチモーダル アイテム処理 (#44212)、ベンチマークでのローカル画像エンコード (#43843)、インターリーブされたカスタム画像ベンチマーク データセット (#43636)。
  • プーリング/分類: プーリング UX の適切な例外 (#44593)、プーラー クラスの extra_repr() (#44805)、LoRA アダプター名のプーリング修正 (#44410)、再設定された生成スコアリング エントリポイント (#44153)、拡張されたプーラー単体テスト (#43818、#44471)。
  • リファクタリング: InternLM2 の AutoWeightsLoader (#38278)。

エンジンコア

  • Model Runner V2: Llama および Mistral 高密度モデルのデフォルト (#43458)、FlashInfer サンプラー (#42472)、ブレーカブル CUDA グラフ (#44050)、Eagle の専用 CUDA グラフ プールの削除 (#44078)、パイプライン並列バブルの削除 (#42187)、ハイブリッド モデルのカーネル ブロック サイズ (#38831)、新規ゼロ化ハイブリッド + FP8 KV キャッシュ用に割り当てられた KV ブロック (#43990)、アテンション メタデータ用の実際のバッチ max_seq_len (#43991)、拒否サンプリング受け入れ率修正 (#40651)、KVConnector + PP クリーンアップ (#43732)、スペキュレーター プリフィル ウォームアップ/キャプチャ (#44253)。
  • 投機的デコード (DFlash): 原因 DFlash (#43445)、適切な先読みスロット割り当て (#43733)、プレフィックス キャッシュ破損の修正 (#42971)。独立したドラフター アテンション バックエンド選択 (#39930)、ドラフト用の num_heads_q によるアテンション グループ分割 (#43543)、SWA プレフィックス キャッシュ マスクでの EAGLE/MTP ルックアヘッド キャッシュ (#44082)。

  • KV キャッシュとスケジューラー: プラグ可能な KVCacheSpec (#37505)、scheduler_block_size が KVCacheManager/Coordinator (#44165) にスレッド化され、max_concurrent_batches が VllmConfig (#44274) に移動、構成検証が 0/負のノブを拒否 (#43794、#44057、 #44207)、KV キャッシュ スケール ボイラープレートが重量読み込みから削除されました (#43167)。
  • コア: モデル初期化後のワーカー内のガベージ コレクターのフリーズ (#44363)、インプレース更新のためのスパース NCCL 重み転送 (#40096)、適切なスピンループ外部ロード障害処理 (#43659)、スケジュールされた関数の非推奨 (#43358)。

大規模なサービス提供と分散

  • KV キャッシュ オフロード: オブジェクト ストア セカンダリ層 (#41968)、対応コネクタ (#41847) および階層化 (#44287) に対してデフォルトで HMA が有効、リクエストごとのオフロード ポリシー (on_new_request) (#43205) および on_schedule_end() フック (#44206)、トークン オフセット選択的オフロード (#39983)、スキップCPU オフロードのデコードフェーズ ブロック (#43797)、ページサイズ ブロック アライメント (#43689)、小型 CPU→GPU swap_blocks_batch 用の Triton 高速パス (#42212)、古くなったスライディング ウィンドウ ブロックの修正 (#42959)。
  • KV コネクタ / 非集約サービング: PP 対応ハンドシェイク集約および中間 PP 出力プラミング (#43720)、複数非同期 KV ロードのデッドロック修正 (#44560)、Nixl Mamba プレフィックス キャッシュ モード (#42554)、NixlConnector kv_both ロールの非推奨サイクル (#43874)、Mooncake の修正(#43742、#44103、#42694)、LMCache LMCacheMPConnector (#42865)、EC コネクターのシャットダウン API (#42423) およびノンブロッキング ルックアップ (#41627)、iteration_tokens_total から除外された KV 転送トークン (#43346)。
  • EPLB: デフォルトの非同期 EPLB (#43219)、DeepSeek-V4 Mega-MoE 用の EPLB (#43339)、Nixl ゼロコピー EPLB 転送 (#41633)。
  • データ並列: 特定のノード上の DP Ray 配置グループ (#44669) およびグループ化されたノードの割り当て修正 (#43998)、DP スーパーバイザーの SSL (#43688)、120 秒に引き上げられた DP コーディネーターの起動タイムアウト (#42343)、GPU ワーカーごとの RDMA NIC の選択 (#42083)。

  • トランスポート暗号化: データ並列スーパーバイザーの SSL/TLS サポート (#43688)。
