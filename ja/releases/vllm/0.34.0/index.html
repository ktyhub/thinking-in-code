vllm v0.34.0

#v0.34.0

412 人の寄稿者から 1,061 件のコミット (新規 120 人)。 ありがとうございます!

##TL;DR

  • 10 の新しいモデル (Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe など!)
  • 拡張可能な KV キャッシュはデフォルトでオンになっています: vLLM は、ウォームアップ後に実際に解放されたメモリから KV キャッシュのサイズを設定するため、ほとんどのモデルでより大きなキャッシュとより多くのスループットが得られます。
  • Model Runner V1 は廃止されました。 Model Runner V2 が唯一の GPU ランナーになりました。
  • Blackwell および MI355X での 大幅な高速化: 最大 1.95 × デコード (GB200 の Step5)、1.6 × スループット (GLM-5.3-Flash)、1.24 ～ 1.40 × より高速なロングプロンプト TTFT (GLM-5.3)。
  • アップグレード チェック: デフォルトのブロック サイズは 64 になり、ROCm 7.2 イメージはなくなり、huggingface_hub >= 2.0.0 が必要になります。 アップグレードする前にを参照してください。

ハイライト

拡張可能な KV キャッシュ、デフォルトでオン

  • CUDA および ROCm では、KV キャッシュのサイズは、推定値ではなく、CUDA グラフのキャプチャとウォームアップの 後 に実際に解放されたメモリに基づいてサイズ設定されます (#56492)。
  • 結果: キャッシュが大きくなるため (例: H200 の MiniMax-M3: 433k → 672k トークン)、高い同時実行性ではスループットが向上し、TTFT が低下します。
  • トレードオフ: 一部のモデルではトークンごとのデコード遅延が増加する可能性があります (同時実行数 128 の一部の H200 モデルでは TPOT +6 ～ 18%)。 --gpu-memory-utilization 0.9 または --no-enable-extensible-kv-cache でオプトアウトします。
  • アロケーターの断片化、起動 OOM、および KV コネクタの修正により強化されました (#67296、#67485、#66731、#66523、#66197、#65137、#66605、#66674)。

モデルランナー V2 のみ

  • Model Runner V1 が削除されました (#63373)。
  • 投機的デコーディングと DCP を含むデュアルバッチ オーバーラップが MRV2 で実行されるようになりました (#61464)。

投機的デコード

  • サフィックス デコード は、GPU スペキュレーターを使用して MRV2 上で実行されます。 Arctic Inference は必要なくなりました (#60339)。
  • カスタム スペキュレーター: 宣言型構成と register_speculative_method プラグイン API (#63205)。
  • MRV2 ドラフト モデル スペキュレーター用 CUDA グラフ (#60989)。
  • アダプティブ検証 は XPress (#65175) で動作します。
  • ドラフト KV キャッシュはターゲットの dtype と一致するため、FP8 ターゲットは FP8 ドラフト キャッシュを取得します (#65198)。

  • リリース画像とホイールは ROCm 10.0 のみ (#61939) です。
  • --all2all-backend mori 経由の MoRI EPv2 (#61361)。
  • MI355X での Kimi-K3 特殊デコード、オプトイン (#61435)。
  • TRITON_ATTN は、RDNA3 および RDNA4 のデフォルトのアテンション バックエンドです (#60418)。

サービスと運営

  • Python と Rust の両方のフロントエンドで、/checkpoint/prepare、/checkpoint/status、および /checkpoint/restore を介した チェックポイント/復元 (CRIU + cuda-checkpoint) (#62570)。
  • フォールトトレラントな DP+EP スケールダウン: デッド ランクが削除され、再起動せずにその専門家 redis がトリビュートされます (#46370)。
  • デフォルトでベストエフォート型 NUMA バインディング がオンになります (#61258)。
  • キャッシュを意識したアドミッション の注文をオプトインします (#54625)。
  • Rust フロントエンド: ステートレス レスポンス API (#63902) および n > 1 (#65625)。
