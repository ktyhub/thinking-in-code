#vLLM v0.27.0 Release Notes

ハイライト

このリリースには、242 人の寄稿者 (64 人が新規) からの 561 件のコミットが含まれています。

  • 1 つのリリースでフルスタックを実現する Kimi K3 サポート: コア モデル ファイルとカーネル (#50089、#50000)、Python (#50093) および Rust (#50104) フロントエンド、AttnRes カーネル (#50090)、DeepGEMM サポート (#50458)、圧縮テンソル量子化チェックポイント(#50500)、DSpark AR fusion (#50242)、共有エキスパートを複製する代わりにシャーディングするオプション (#50656)。
  • その他の新しいモデル: EVS ビデオ トークン プルーニングを備えた Qwen3.5 テキストのみの高密度および MoE モデル (#50210) (#48912)、K-EXAONE-2.0-750B-A37B (#50524)、Transformers モデリング バックエンド経由の VaultGemma (#49803)、および jina-embeddings-v5-text-nano (#50688)。
  • PyTorch 2.13.0 アップグレード、torchvision 0.28.0 および Triton 3.7.1 (#48155) とともに - これは破壊的な環境変更です。 XPU (#48677) と CPU (#50412) も ZZPH100​​ZZ に続きました。
  • SM100 で FlashAttendant 4 の統合が強化: FP8 KV キャッシュ サポート (#42569) と headdim-256 サポート (#42669)。新しい JIT ウォームアップ インフラストラクチャ (#47451) とランナー所有の Triton カーネル ウォームアップ (#49903) によってサポートされ、最初のリクエストのコンパイル ストールを解消します。
  • DeepSeek-V4 パフォーマンスの向上: シーケンス並列処理 (#46789)、空の c128 起動のスキップによるカーネルの最大 2 倍の向上 (#48957)、不要な Topk/ルーターのスキップによる 3.4% E2E TTFT (#49486)、ワークスペースの再利用による 3.9% E2E TTFT (#49236)、冗長フル カーネル (#50298)、アダプティブ トップク幅 (1.0% E2E、#50004)、PP バッファーに保存された 448 MiB GPU メモリ (#50312)、コンパクトな MXFP4 インデクサー KV キャッシュ (#48993)、FlashInfer でのスパース MLA q-head パディングの削除により、カーネルが 1.88 倍になりました >= 0.6.14 (#48047)。
  • Model Runner V2 は非生成ワークロードに拡張: エンコーダーのみのアテンション (#49331)、埋め込み/分類のためのシーケンス プーリング (#48791)、エンコーダー トークン分類 (#50293) およびトークン埋め込み (#50574)、BGE-M3 プーリング (#50661)、CPU 上のマルチモーダル (#50073)、マルチレイヤー MTP スペキュレーター (#48892)、PCP は MRV2 (#50034) を選択するようになりました。
  • 復元力のある大規模サービス: DP+EP 外部ロードバランサー展開 (#44428) およびエラスティック EP スケーリングのための非同期準備 (#47288) のための (簡素化された) フォールト トレランス フレームワーク。
  • ハイブリッド モデルの分解: ハイブリッド MLA+SSM モデルの NIXL P/D (#49762)、ハイブリッド モデルの異種 P/D ブロック サイズ (#49612)、および MoRIIO 異種 TP<->DP プレフィル/デコード読み取りルーティング (#46116)。
  • Rust フロントエンドは、gRPC コントロール プレーンを拡張します: エンジン対応ヘルス レポート (#48992)、中止制御 (#49255)、サーバーおよびモデル検出 (#49491)、KV イベント ソース検出 (#50033)、さらに vllm CLI (#48930) に統合された vllm-bench。
  • 初期の次世代ハードウェアの有効化: SM107 上の NVLink all-reduce パス (#49647) および有効な ROCm gfx1250 アーキテクチャ (#46516) を備えた NVIDIA Rubin の sm_107 ターゲット (#49387)。

モデルのサポート

  • Kim K3: モデル ファイルとカーネル (#50089) を備えた新しいモデル (#50000)、Python フロントエンド (#50093)、Rust フロントエンド (#50104)、AttnRes カーネル (#50090)、DeepGEMM サポート (#50458)、DSpark AR fusion (#50242)、およびオプション共有エキスパートシャーディング (#50656)。
  • 新しいモデル: Qwen3.5 テキストのみのデンスおよび MoE (#50210)、K-EXAONE-2.0-750B-A37B (#50524)、Transformers バックエンド経由の VaultGemma (#49803)、EuroBERT エンコーダー バックボーンを備えた jina-embeddings-v5-text-nano (#50688)。
  • Inkling: llm-compressor NVFP4 重み (#49258) および圧縮テンソル動的 FP8 (#48876)。
  • マルチモーダル: VidCom2 ビデオ トークン プルーニング (#47750)、Qwen3.5 用 EVS (#48912)、Gemma-4 用 ViT CUDA グラフ (#46837)、Cosmos3 FP8 ModelOpt/Diffusers 再マッピング (#48952)、MiniMax-M3 MSA 投機的デコード検証 (#50032)、およびデフォルトのビデオ プロセッサ(#50305)、DeepSeek-OCR-2 TTFT 最適化 (#49531)、MOSS-TD の最大オーディオ継続時間の延長 (#49403)。
  • 拡散モデル: DiffusionGemma の top_k および top_p サンプリング (#45429)。
  • トランスフォーマー モデリング バックエンド: オーディオ モデルのサポート (#39330)、改良された fx トレーサー (#49957)、融合残差加算 + RMSNorm コンパイル パス (#48757)、MLA パディング + グループ化された Topk ルーティング (#49982)、TP 付き MQA (#49987)、および Qwen3-VL M-RoPE の修正(#49292)。

エンジンコア

  • ウォームアップ: 新しい JIT ウォームアップ インフラストラクチャ (#47451)、最初のリクエストの前にウォームアップされたランナー所有の Triton カーネル (#49903)、および適切なレンダラー ウォームアップ (#50408)。
  • 注意: FlashAttendant 4 SM100 FP8 KV キャッシュ (#42569) および headdim-256 (#42669); DeepSeek-V2/R1 および Kim-K2.5 の DCP での MLA デコードのクエリ レプリケーション (#45964)。スパース MLA プレフィル用のマスクされた MHA (#48770)。短い密なプレフィルのスパース インデクサー スコアリングをスキップします (#48407)。 FlexAttendant エピローグ フック (#45841) とエンコーダー ブロック マスク コンパイルの爆発が回避されました (#50339)。アテンション バックエンドは引き続きプレフィックス LM モデルのテキストのみの提供に適格です (#48796)。実行時引数としてのマージ アテンション コンテキスト カウント (#48739);統合マルチパス エンコーダ CUDA グラフのサポート (#49934);エンコーダ キャッシュ拡張フック (#48218)。
  • Model Runner V2: エンコーダーのみのアテンション (#49331)、埋め込みと分類のためのシーケンス プーリング (#48791)、エンコーダー トークン分類 (#50293)、エンコーダー トークンの埋め込み (#50574)、BGE-M3 プーリング (#50661)、CPU 上のマルチモーダル (#50073)、マルチレイヤー MTP スペキュレーター(#48892)、PCP による MRV2 の選択 (#50034)、キャプチャ時に常に構築されるアテンション メタデータ (#49364)、エンコーダー キャッシュ プロファイリング (#47985)、no-op FP32 ロジット マテリアライゼーションのスキップ (#47711)、OOM を回避するためのチャンク化拒否サンプラー (#48630)、ハイブリッド Mamba での GPU<->CPU 同期の削減(#49736)。
  • KV オフロード: ピア ルックアップ/サービングを備えた汎用 P2P セカンダリ層 (#48021)、TierFilter/TierMatcher を使用したリクエストごとの層フィルタリング (#48123)、TieringOffloadingSpec を使用した自己記述型 KV イベント (#48679)、CachePolicyFactory を介したプラグイン可能なエビクション ポリシー (#49114)、重複排除された複製 MLA KV共有 CPU 領域 (#48906)、CPUOffloadingSpec のシングルコピー MLA レイアウト (#50301)、CPUOffloadingSpec を SharedOffloadRegion に移動 (#50094)、TP に依存しないコンパクトなセカンダリ ID (#49858)、ファイルシステム オフロードのバッチ C ストア/ロード (#49152)、サブブロック プロンプトの信頼できる部分末尾オフロード (#49502)、並列処理に依存しないオフロードのためのレイヤーごとの正規 KV ページ マッピング (#48408)。
  • Mamba/ハイブリッド: Mamba2 標準デコードを高速化するための ReplaySSM キャッシュ (#48018)、num_accepted_tokens > 1 によるアライン モードの DS-conv 状態移行の融合 (#49291)、FlashInfer Mamba SSU アルゴリズムの選択 (#50157)、ハイブリッド モデルでの /wake_up クラッシュの修正 (#41602)。
  • 仕様デコード: TP ランク間で複製された DSpark マルコフ ヘッド (#49731)、投機設定からロードされた sample_from_anchor (#48639)、最も早く完了するストップ文字列が選択されました (#49391)。
  • 構造化された出力: 仕様のデコードにより推論の境界を越えて文法が高度化されました (#44993)。
  • 前処理パフォーマンス: レンダリング スレッド プールにオフロードされたレンダリング CPU 作業 (#49396)、AsyncLLM のイベント ループから切り離された raw プロンプト前処理 (#49608)、独自のエグゼキューターで分離されたマルチモーダル前処理 (#49524)、イベント ループから遅延された MM 埋め込み読み込み (#49477)、オンライン プーリングのリクエスト内での並列前処理(#49153)、ソースバイトによってハッシュされたビデオ (#49607)、ImageIO に保存されたオリジナルの画像モード (#49159)。
  • RL: RL ロールアウトのウェイト バージョン タグ付け (#49040)、ステートフル トレーナー送信 IPC (#48981)、ウェイト リロード中の vLLM 設定セット (#45989)、FlashInfer モノリシック MoE カーネルからのルーター リプレイ出力 (#44214)。
  • メモリと堅牢性: CuMem slept-L1 フラグメンテーション アカウンティング (#49208)、すべてのプラットフォームで cgroup メモリ制限が尊重される (#49966)、/dev/shm が小さすぎる場合の高速フェイル (#48879)、shm_broadcast でのゼロコピー テンソル ピクル (#48442)、プレフィックス キャッシュがオフの場合、free_blocks で LRU ハッシュ分割がスキップされる(#48017)、torch.compile キャッシュ要素から除外された場所由来のパス変数 (#47573)、ReLU^2 用にコンパイルされた CustomOp.forward_native (#50244)、HF トークナイザーに使用される HF 設定 (#49907)、ピン留めされたブロック サイズによるバッチ不変 RMSNorm (#48391)。

ハードウェアとパフォーマンス

  • DeepSeek-V4: シーケンス並列処理 (#46789)、空の c128 起動をスキップする最大 2 倍のカーネル (#48957)、デコード時に Topk/ルーターをスキップする 3.4% E2E TTFT (#49486)、3.9% E2E TTFT ワークスペースの再利用 (#49236)、冗長性を削除する 1.88x カーネルフルカーネル (#50298)、アダプティブ Topk 幅 1.0% E2E (#50004)、448 MiB GPU メモリの節約 (#50312)、コンパクトな MXFP4 インデクサー KV キャッシュ (#48993)、FlashInfer >= 0.6.14 のスパース MLA Q ヘッド パディングの削除 (#48047)。
  • カーネル: 1.2–3.1x カーネルの改善による RMSNorm 不連続サポート (#49750)、MoE reduce_scatter 回帰修正により E2E スループットが 5% 回復 (#48763)、非グループ化バイアスレス Topk ルーティングが融合パスにディスパッチ (#49618)、調整された LL BF16 ルーター GEMM (#48774) 非 MoE モデルでウォームアップをスキップ (#49659)、VLLM_TRITON_USE_TD を介した融合 MoE の Triton テンソル記述子パス (#42436)、topk でスキップされた cudagraph/DP パディング (#48979)、Marlin INT4-FP8 AWQ プリプロセス カーネルでの合体 HBM アクセス (#47268)。
  • NVIDIA 次世代: Rubin 用 sm_107 (#49387)、SM107 の NVLink all-reduce パス (#49647)、SM121 でカーネルレス ビルドを生成する CUDA アーチ検出を修正 (#49904)。
  • ROCm: gfx1250 アーキテクチャの有効化 (#46516)、AITER FP8 ViT エンコーダー アテンション (#49937)、Quark DeepSeek-V4 チェックポイントの融合共有エキスパート (#48044)、Quark GLM-5.2 チェックポイント推論の修正 (#48886)、DSv3.2 デコードごとの FillFunctor の起動が削除されました。スパース MLA ホット ループ (#44527)、DSv4 用の B プレシャッフル アテンション FP8 プロジェクション (#46720)、TML Inkling 有効化 (#48841)、MI325X 用に調整された selective_state_update float16 構成 (#50006)、GPT-J スタイルの MRoPE の修正と最適化 (#49906)、キューダグラフ モードでの QuickReduce 精度の修正(#46913)、静的 e8m0 体重計のキャッシュされた fp32 アップキャスト (#47773)、CPU KV キャッシュ ロードのバッチ DMA (#49843)、エラスティック EP スケーリング精度の修正 (#47206)。
  • XPU: QK Norm + RoPE fusion pass (#49394)、fp8_bmm およびロード時間スケール転置を備えた FP8 o_proj (#48334)、DeepSeek-V4 furuse_index_q SYCL カーネル パス (#45991)、バッチ化された MoE GEMM の TD オペランド ロード (#46340)、と統合された RMSNorm カーネルvllm_c (#46981)。
  • CPU: Arm CPU 用の INT8 融合 MoE カーネル (#48637)、oneDNN INT8 GEMM による s390x 推論最適化 (#50219)、投機的デコード用に最適化された GDN 変換パス (#48577)、granite-4 対応 (#47641)、Power 用 FAST_EXP (#49571)、CPU カーネルは最新バージョン (#50387)、macOS ビルド修正 (#49021、#50915)。

大規模なサービス提供と分散

  • DP+EP 外部 LB デプロイメント用のフォールト トレランス フレームワーク (簡素化) (#44428)。
  • Elastic EP: 非同期準備 (#47288) および不連続な重量移動の修正 (#50641)。
  • P/D 分解: ハイブリッド MLA+SSM モデルの NIXL P/D (#49762)、ハイブリッド モデルの NIXL 異種 P/D ブロック サイズ (#49612)、MoRIIO 異種 TP<->DP プレフィル/デコード読み取りルーティング (#46116)、PD デコード時のオプションのルックアップ無効化 (#50498)、プレフィル トークン ID の再利用デコード チャット パス (#48145)、トークン化解除ストリーミング デレンダー (#47301) では、NixlPush は D->P での追加のハンドシェイク ステップをスキップします (#49345)。
  • 修正: P/D プリエンプション レース (#50297)、ワーカー クロックに基づいて再設定された KV リース期限 (#50326)、NIXL ハイブリッド MLA + Mamba 異種 TP (#49297)、内部 LB ロード バランシング (#49204)。
  • Mooncake: KV ロード パス上でベクトル化された prepare_value (#48531)、保存された境界で再導出された完全な外部ヒット (#49481)。
  • エンコーダー キャッシュ コネクタ: has_pending_push_work (#49582)。
  • コミュニケーター: FlashInfer (#46877) 以降のプロセス チェックポイント ライフサイクル フック。

量子化

  • 新機能: 圧縮テンソルの FP4 Qutlass 統合 (#43229)、ReLU2 NVFP4 の CuTeDSL MoE (#49580)、INC での MXFP8 リニア サポート (#47514)、XPU での AutoRound W4A16 MoE および MXFP4 リニア/MoE (#47124)、TurboQuant の KV quant モード(#50533)、SM80 での ModelOpt FP8 エミュレーション (#50019)、ModelOpt W4A16 用の --linear-backend (#50273)。
  • チェックポイント: DeepSeek-V4 (#41276) および Kim-K3 (#50500) の圧縮テンソルのサポート。 find_matched_target は融合名の一致を優先します (#49483)。
  • MoE リファクタリング: FusedMoE は FusedMoEFactory に名前変更 (#44941)、MoeWNA16 は MK oracle スキーム (#44120) に移行、Quark w8a8-int8 (#46765) および MXFP4 aiter/emulation バックエンド (#49348、#48949) はカーネル抽象化に移動 (CT) WNA16 Marlin/MoE メソッドの統合 (#44570)、Quark W4A8 (INT4-FP8) MoE CI カバレッジ (#48050)。

API とフロントエンド

  • Rust フロントエンド: エンジン認識ヘルス レポート (#48992)、中止制御 RPC (#49255)、サーバーとモデルの検出 (#49491)、および KV イベント ソースの検出 (#50033) を備えた gRPC コントロール プレーン。 vllm-bench は、vllm-rs および vllm CLI (#48930) に統合され、vllm bench serve (#50081) のオプトイン Rust 委任が追加されました。ゼロコピーのマルチモーダル テンソル スライシング (#48781)、補助フレームのマルチモーダル テンソル (#49341)、--limit-mm-per-prompt (#49604)、通常のテキスト トークナイザー エンコーディング (#49992)。
  • API: Cohere チャット v2 API サポート (#47189)、Anthropic Messages API の cache_salt (#49498)、GPT-OSS Harmony の厳密なツール呼び出しと制約付きデコード (#45560)、推論とツール呼び出しのための統合エンジンベースの Mistral パーサー (#48947)、リクエストごとのサンプリング パラメータとして公開された stream_interval (#49754)、翻訳用の追加サンプリング パラメータ API (#45839)、MOSS-Transcribe-Diarize 用の diarized_json (#48543)、累積音声からテキストへのチャンク タイムスタンプ (#41131)。
  • マルチモーダル: CLI による mm ハッシュ アルゴリズムの選択 (#49686)、構成可能な PyNvVideoCodec デコーダーの同時実行 (#49753)、base64 データ URL で受け入れられる RFC 2397 パラメーター (#48973)。
  • UX と検証: VLLMError 階層による標準化されたリクエスト エラー処理 (#49665)、起動ログ ノイズの削減 (#50590)、互換性のないネストされたランタイム オーバーライドの拒否 (#49247)、データ並列起動検証の改善 (#49124)、DCP トポロジ検証 (#49777)、非数値 logprob の 500 ではなく 400 (#49144)、Python および Rust パーサーに保存された裸の Inkling テキスト (#50403)。
  • ベンチマーク: vllm bench serve のプローブ リクエスト (#49611)。

依存関係
