#kubernetes-client v8.0.0

バグ

  • 修正 #8105: 再試行アクション、再試行決定、または応答クリーンアップが例外をスローするとリクエストがハングする。
  • 修正 #7374: (crd-generator) 生成された CRD は、client が書き込む内容をプルーニングしたり拒否したりしなくなりました: Object、生の Map、List<Object>、生のコレクション、@JsonUnwrapped および多態性プロパティはその内容を保持し、日付と時刻の型は値が一致する形式を宣言するだけです (Duration、LocalDateTime、および部分型は date-time を失います)。 Optional プロパティは、不明なフィールドを保持する代わりに、その値の型のスキーマを取得します。移行ガイド を参照してください。
  • 修正 #6779: (httpclient-jetty) WWW-Authenticate ヘッダーのない 401 応答 (API サーバーが送信する方法) は、「HTTP プロトコル違反: WWW-Authenticate ヘッダーのない認証チャレンジ」で失敗するのではなく、本文とともに返されます。
  • 修正 #6779: (httpclient-jetty、httpclient-vertx、httpclient-vertx-5) HTTPS リクエストがプロキシ トンネルを介して API サーバーに送信される Proxy-Authorization リクエスト ヘッダーにフォールバックするのではなく、コロンを含むプロキシ パスワード、またはユーザーが含まれパスワードのないプロキシ URL がプロキシでの認証に使用されるようになりました。
  • 修正 #6779: パスワードなしで構成されたプロキシ ユーザー名は、null ではなく空のパスワードとともに送信され、ユーザーが含まれ、パスワードが指定されていないプロキシ URL は、user ではなく user: として送信されます (RFC 7617)
  • 修正 #8134: (httpclient-jetty) 失敗した WebSocket ハンドシェイクはリスナーの onError を呼び出さなくなり、返された Future はすでに失敗します。ハンドシェイクが再試行されると、再試行によって開く前に監視および実行/接続セッションが終了してしまいました。
  • 修正 #8134: (httpclient-jetty) SOCKS5 プロキシの資格情報が送信されます。
  • 修正 #8134: (httpclient-jetty、httpclient-vertx) Basic user:password ではないプロキシ資格情報は、HTTP プロキシが読み取るリクエストに Proxy-Authorization ヘッダーとしてのみ追加されます。 HTTPS および WSS リクエスト、Vert.x トンネルを経由する WebSocket、および SOCKS プロキシを介したリクエストは、それらを API サーバーに運びました。
  • 修正 #8134: (httpclient-vertx-5) Basic user:password ではないプロキシ資格情報は、CONNECT 上でも Vert.x によって HTTP プロキシに送信されるため、HTTPS および WebSocket リクエストはそれらの機能を必要とするプロキシ経由で行われ、API サーバーに到達しなくなります。
  • 修正 #8134: (httpclient-okhttp) API サーバー (たとえば pods/proxy 経由) からの 407 には、プロキシ トンネルを通過したプロキシ資格情報が返されなくなり、プロキシが拒否した資格情報は再送信されなくなりました。
  • 修正 #8140: (httpclient-vertx-5) 書き込む前に接続が閉じられたリクエストは IOException で失敗し、リクエストのタイムアウトまでハングするのではなく、再試行されます (Windows で見られる)
  • 修正 #8134: (httpclient-jetty) 応答によって設定された Cookie は、他の HttpClient 実装と同様に、後のリクエストや WebSocket のアップグレードで送り返されなくなりました。
  • 修正 #8109: yyyy-MM-dd として書かれた java.sql.Date は、UTC 以西の前日ではなくローカル日付として読み取られます。 Year、Month、java.sql.Date、および Locale は 7.x ワイヤー形式を維持します。自分で構築するマッパーには新しい Jackson2JdkTypesModule が必要です。移行ガイド を参照してください。
  • 修正 #8109: (crd-generator) byte[]、ByteBuffer、char[]、Year、および java.sql.Date スキーマは、client が書き込むもの (byte[] および ByteBuffer は format: byte 文字列) と一致するため、API サーバーはそれらを拒否しなくなりました。 LocalDate 上の @PrinterColumn は、<invalid> を示した date 列ではなく、string 列です。
  • 修正 #8008: (httpclient-vertx-5) InputStream ボディと Expect: 100-continue (バイナリ ビルド) を含むリクエストはハングしなくなり、既知の長さの InputStream ボディはチャンク化されずに Content-Length で送信されます。
  • 修正 #8139: (httpclient-okhttp) WebSocket は、リスナーが応答しない場合でもサーバーの Close フレームに応答するため、ポート転送とカスタム リスナーは、サーバーが切断するのを待つ代わりに接続を解放します。
  • 修正 #8152: (httpclient-vertx、httpclient-vertx-5、httpclient-jetty、httpclient-jdk) OkHttp がすでに行っていたように、WebSocket は Config#websocketPingInterval (デフォルトでは 30 秒) ごとに ping を送信するため、アイドル状態の接続を閉じるロード バランサーは静かな監視をドロップしなくなりました。

改善点

  • 修正 #8109: (crd-generator) int/Integer および long/Long プロパティは、controller-gen と同様に format: int32 および format: int64 を取得します。
  • 修正 #7987: (kubernetes-client-api) withShardSelector は、生の式 String の隣にある型指定された ShardSelector (ShardSelector.builder().addShard(0, 4).addShard(2, 4).build()) を受け入れるため、shardRange(...) CEL 文法とその 16 進数の境界を手動で記述する必要がありません。

  • 修正 #8041: Kubernetes 1.37 で追加されたリソースの型付き DSL: certificates().v1().podCertificateRequests()、dynamicResourceAllocation().v1().deviceTaintRules()、storageMigration().v1().storageVersionMigrations() および scheduling().v1beta1() podGroups() および workloads()、さらに certificates().v1beta1().podCertificateRequests() および storageMigration().v1beta1().storageVersionMigrations()。 kubernetes-model-policy には lifecycle.k8s.io/v1alpha1 モデル (Eviction および EvictionRequest) も出荷されます。

注意: 重大な変更

  • 8.0.0 で重大な変更がないか詳細な移行ドキュメントを確認してください。
  • 修正#8041: (kubernetes-client-api) runtimeClasses() および network().ingresses() (および network().ingress()) は、v1beta1 モデルの代わりに v1 モデルを使用します。Kubernetes は提供されなくなりました。移行ガイド を参照してください。
  • 修正 #7374: Jackson 3 (tools.jackson 座標とパッケージ) に移動しました。デフォルトのシリアル化では、カスタム タイプの Jackson 2 の動作が維持されます。移行ガイド を参照してください。
  • 修正 #7987: (kubernetes-client-api) Filterable#withShardSelector は型付き ShardSelector も受け入れるため、リテラル withShardSelector(null) はコンパイルされなくなりました。移行ガイド を参照してください。
  • 修正 #8031: (crd-generator) 非推奨の CRD Generator v1 (crd-generator-api および crd-generator-apt) を削除しました。 Maven プラグイン、CLI ツール、または Gradle ビルド スクリプト レシピ を使用して crd-generator-api-v2 に移行します。[移行] を参照してください。ガイド](./doc/CRD-generator-migration-v2.md)
  • 修正 #8009: Java ベースラインを 11 から 17 に移動しました。ランタイム要件に加えて、Maven プラグイン、Gradle プラグイン、およびアノテーション プロセッサではビルドを実行するために Java 17+ JVM が必要となり、OSGi バンドルは osgi.ee=JavaSE 17 を宣言します。
  • 修正 #8050: (karaf) kubernetes-karaf 機能リポジトリは、独自の scr 機能を定義しなくなりました。 kubernetes-client は、Declarative Services API バンドルと scr:* シェル コマンドを提供する Karaf ディストリビューションによって提供される scr 機能に依存するようになりました。
  • 修正 #8142: (ネイティブ) RevisionSpec を提供すると、workloadRef が schedulingGroup に置き換えられ、Kubernetes 1.37 以降のコア PodSpec のように evictionResponders が追加されます。
  • 修正 #8133: (オープンクラスター管理) DiscoveredClusterSpec は owner をドロップし、DiscoveredClusterCondition は lastUpdateTime をドロップします
  • 修正 #8148: (openshift-model) モデル クラス io.fabric8.openshift.api.model.customresourcestatus.conditions.v1.Condition が削除され、Hive ClusterDeploymentCustomizationStatus 条件では Kubernetes Condition が使用されます。
  • 修正 #8148: (openshift-model-config) ClusterImagePolicySpec および ImagePolicySpec ポリシーは ImageSigstoreVerificationPolicy であり、それらのルートは trust ImagePolicyFulcioCAWithRekorRootOfTrust、ImagePolicyPKIRootOfTrust、および ImagePolicyPublicKeyRootOfTrust です。モデル クラス FulcioCAWithRekor、PKI、Policy、PublicKey が削除されました
  • 修正 #8148: (openshift-model-config) GCPPlatformStatus は serviceEndpoints を削除し、モデルクラス GCPServiceEndpoint は削除されました
  • 修正 #8148: (openshift-model-hive) oVirt サポートの削除: ClusterDeprovisionPlatform、MachinePoolPlatform、Platform で ovirt が削除され、モデルクラス OvirtClusterDeprovision と io.fabric8.openshift.api.model.hive.ovirt.v1 パッケージが削除されました
  • 修正 #8148: (openshift-model-hive) vSphere MachinePool.osDisk はインストーラー io.fabric8.openshift.api.model.installer.vsphere.v1.OSDisk を使用し、モデル クラス io.fabric8.openshift.api.model.hive.vsphere.v1.OSDisk は削除されました。モジュールは openshift-model-installer、openshift-model-machine、openshift-model-operator に依存するようになりました。
  • 修正 #8148: (openshift-model-installer) GCP PSCEndpoint が region を削除する
  • 修正 #8148: (openshift-model-machineconfiguration) v1alpha1 モデル クラス MachineConfigNode、PinnedImageSet およびそれらの関連タイプを削除し、v1 のものを使用します
  • 修正 #8133: (オープンクラスター管理) MultiClusterHubSpec は、customCAConfigmap、enableClusterBackup、enableClusterProxyAddon、hive、ingress、separateCertificateManagement を削除します。モデル クラス BackupConfig、ExternalDNSAWSConfig、ExternalDNSConfig、ExternalDNSGCPConfig、FailedProvisionConfig、HiveConfigSpec、HiveConfigStatus、IngressSpec、VeleroBackupConfig が削除されました
  • 修正#8133: (オープンクラスター管理) オブザーバビリティ PlatformMetricsSpec および UserWorkloadMetricsSpec は collection を default に置き換え (PlatformMetricsCollectionSpec および UserWorkloadMetricsCollectionSpec は削除)、PlatformNamespaceRightSizingRecommendationSpec は PlatformRightSizingRecommendationSpec に名前変更されます。
  • 修正 #8100: (tekton) モデル クラス Template および AffinityAssistantTemplate が、tekton パイプライン 1.16.0 で +versionName=unversioned として宣言されているため、パッケージ io.fabric8.tekton.pod から io.fabric8.tekton.unversioned に移動されました。
  • 修正 #6779: (httpclient-jetty) Jetty 11 から Jetty 12.1 に移動しました。移行ガイド を参照してください。
  • 修正 #8008: kubernetes-client および openshift-client のデフォルトは Vert.x 4 (kubernetes-httpclient-vertx) ではなく Vert.x 5 HttpClient (kubernetes-httpclient-vertx-5) です。移行ガイド を参照してください。
