ディフューザー v0.34.0

📹 新しいビデオ生成パイプライン

ワンVACE

Wan VACE は、制御可能なビデオ生成を実現するさまざまな生成技術をサポートしています。これには 2 つのバリエーションがあります。1 つは高速なイテレーションとプロトタイピング用の 1.3B モデル、もう 1 つは高品質の生成用の 14B です。機能には次のようなものがあります。

  • ビデオのコントロール (深さ、ポーズ、スケッチ、フロー、グレースケール、落書き、レイアウト、境界ボックスなど)。コントロールビデオを取得するためにビデオを前処理するための推奨ライブラリ: huggingface/controlnet_aux
  • 画像/ビデオからビデオ (最初のフレーム、最後のフレーム、開始 clip、終了 clip、ランダム clips)
  • インペイントとアウトペイント
  • 映像の対象（顔、物体、キャラクターなど）
  • ビデオへの合成 (何かを参照、何かをアニメーション化、何かを交換、何かを拡張、何かを移動など) this プル リクエストで入手可能なコード スニペットは、制御性シグナルを使用して動画を生成する方法の例をいくつか示しています。 詳細については、ドキュメント を参照してください。

Cosmos Predict2 Video2World

Cosmos-Predict2 は、物理 AI 用の Cosmos World Foundation Models (WFM) エコシステムの主要なブランチであり、高度な世界モデリングによる将来の状態予測に特化しています。これは、テキストの説明から高品質の画像を作成するためのテキストから画像への生成と、ビデオ入力から視覚的なシミュレーションを作成するためのビデオからワールドへの生成という 2 つの強力な機能を提供します。 Video2World モデルには、2B と 14B のバリエーションがあります。詳細については、ドキュメント を参照してください。

LTX 0.9.7 および蒸留

LTX 0.9.7 とその改良版は、Lightricks がリリースしたモデル ファミリの最新製品です。 詳細については、ドキュメント を参照してください。

Hunyuan ビデオ フレームパックと F1

フレームパック は、長時間のビデオ生成を可能にする新しい方法です。この技術を使用してトレーニングされた Hunyuan Video には 2 つのバージョンがリリースされています。詳細については、ドキュメント を参照してください。

フュージョンX

Wan2.1-14B 上に構築された FusionX ファミリのモデルと LoRA は、すでにサポートされているはずです。モデルをロードするには、from_single_file() を使用します。

from diffusers import WanTransformer3DModel

transformer = WanTransformer3DModel.from_single_file(
    "https://huggingface.co/vrgamedevgirl84/Wan14BT2VFusioniX/blob/main/Wan14Bi2vFusioniX_fp16.safetensors",
    torch_dtype=torch.bfloat16
)

LoRA をロードするには、load_lora_weights() を使用します。

pipe = DiffusionPipeline.from_pretrained(
    "Wan-AI/Wan2.1-T2V-14B-Diffusers",
    torch_dtype=torch.bfloat16
).to("cuda")
pipe.load_lora_weights(
    "vrgamedevgirl84/Wan14BT2VFusioniX", weight_name="FusionX_LoRa/Wan2.1_T2V_14B_FusionX_LoRA.safetensors"
)

AccVideo および CausVid (LoRA のみ)

AccVideo と CausVid は、品質を維持しながらビデオ拡散モデルの生成時間を短縮する 2 つの新しい蒸留技術です。ディフューザーは、抽出された LoRA をそれぞれのモデルでロードすることをサポートします。

量子化とオフロードを組み合わせて、`torch.compile()` で速度を向上させることで、メモリ要件を大幅に削減できます。以下に例を示します。
<詳細>
<summary>コード</summary>
```py
from diffusers import BitsAndBytesConfig as DiffusersBitsAndBytesConfig
from transformers import BitsAndBytesConfig as TransformersBitsAndBytesConfig
from diffusers import AutoModel, FluxPipeline
from transformers import T5EncoderModel

import torch
torch._dynamo.config.recompile_limit = 1000 

quant_kwargs = {"load_in_4bit": True, "bnb_4bit_compute_dtype": torch_dtype, "bnb_4bit_quant_type": "nf4"}
text_encoder_2_quant_config = TransformersBitsAndBytesConfig(**quant_kwargs)
dit_quant_config = DiffusersBitsAndBytesConfig(**quant_kwargs)

ckpt_id = "black-forest-labs/FLUX.1-dev"
text_encoder_2 = T5EncoderModel.from_pretrained(
    ckpt_id,
    subfolder="text_encoder_2",
    quantization_config=text_encoder_2_quant_config,
    torch_dtype=torch_dtype,
)
transformer = AutoModel.from_pretrained(
    ckpt_id,
    subfolder="transformer",
    quantization_config=dit_quant_config,
    torch_dtype=torch_dtype,
)
pipe = FluxPipeline.from_pretrained(
    ckpt_id,
    transformer=transformer,
    text_encoder_2=text_encoder_2,
    torch_dtype=torch_dtype,
)
pipe.enable_model_cpu_offload()
pipe.transformer.compile()

image = pipeline(
    prompt="An astronaut riding a horse on Mars",
    guidance_scale=3.5,
    height=768,
    width=1360,
    num_inference_steps=28,
    max_sequence_length=512,
).images[0]

</詳細> bitsandbytes==0.46.0 以降では、bnb 量子化モデルはグラフ ブレークなしで torch.compile() と完全な互換性を持つ必要があります。これは、bnb 量子化モデルをコンパイルするときに、ユーザーが model.compile(fullgraph=True) を実行できることを意味します。これにより、メモリの利点を維持しながら速度を大幅に向上させることができます。以下の図は、Flux.1-Dev との比較を示しています。詳細については、このベンチマーク スクリプト を参照してください。 4 ビット bnb モデルの場合、コンパイル中に fullgraph=True が指定されている場合、現時点では PyTorch を毎晩インストールする必要があることに注意してください。 PyTorch チームの @anijain2305 と @StrongerXi の素晴らしいサポートに心から感謝します。

PipelineQuantizationConfig

ユーザーは、パイプラインの初期化中に量子化設定を提供できるようになりました。

import torch
from diffusers import DiffusionPipeline
from diffusers.quantizers import PipelineQuantizationConfig

pipeline_quant_config = PipelineQuantizationConfig(
     quant_backend="bitsandbytes_4bit",
     quant_kwargs={"load_in_4bit": True, "bnb_4bit_quant_type": "nf4", "bnb_4bit_compute_dtype": torch.bfloat16},
     components_to_quantize=["transformer", "text_encoder_2"],
)
pipe = DiffusionPipeline.from_pretrained(
    "black-forest-labs/FLUX.1-dev",
    quantization_config=pipeline_quant_config,
    torch_dtype=torch.bfloat16,
).to("cuda")

image = pipe("photo of a cute dog").images[0]

これにより、あまり多くのコードを記述せずに量子化を使用したいと考えているユーザーにとって、参入障壁が軽減されます。 PipelineQuantizationConfig で許可される さまざまな構成 の詳細については、ドキュメントを参照してください。

ディスクによるグループオフロード

前のリリース では、モデル内のブロック/ノードをオフロードして、メモリ消費を最適化できる「グループ オフロード」を出荷しました。また、このオフロードを計算とオーバーラップさせることもできるため、特に VRAM が低い環境では、速度とメモリの適切なトレードオフが実現します。 ただし、オフロードを効果的に機能させるには、依然としてかなりの量のシステム RAM が必要です。したがって、VRAM が低い環境や RAM が少ない環境では依然として動作しません。 このリリース以降、ユーザーは RAM ではなくディスクにオフロードするオプションが追加され、メモリ消費量がさらに削減されます。この機能を有効にするには、offload_to_disk_path を設定します。

pipeline.transformer.enable_group_offload(
    onload_device="cuda", 
    offload_device="cpu", 
    offload_type="leaf_level", 
    offload_to_disk_path="path/to/disk"
)

速度とメモリのトレードオフを比較するには、これらの2表を参照してください。
