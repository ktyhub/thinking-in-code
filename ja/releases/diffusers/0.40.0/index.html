diffusers v0.40.0

マイナー 公開日2026年8月20日 出典huggingface/diffusers 英語原文

ディフューザー v0.40.0

[!ヒント] このリリースには、LTX2.5、MiniMax H3、Wan Animate 2 など、いくつかの新しいパイプラインが含まれています。また、モジュラー ディフューザーを実験段階から卒業し、その安定したサポートを発表しています。さらに、このリリースには、テンソル並列の最小限のサポートが含まれています。このリリースではさらに多くの機能が追加されました。したがって、詳細については注意事項を参照してください。

新しいパイプライン

ミニマックス-H3

MiniMax-H3 はビデオとそのサウンドトラックを一緒に生成します。単一のトランスフォーマーは、テキスト コンディショニング、コンディショニング メディア、ターゲット ビデオ * および * オーディオの潜在要素を含む 1 つのパックされたシーケンスのノイズを除去します。個別のボコーダーやポストホック オーディオ パスはありません。そのコンディショナーは Qwen3VLForConditionalGeneration で、その非正規化 50 デコーダ層の隠れ状態が最後の状態の代わりに読み取られます。

MiniMax-H3 は モジュラー ディフューザー ブロックとしてのみ統合されています。MiniMaxH3Blocks とその MiniMaxH3ModularPipeline が全体の統合です。変換により、両方のチェックポイント パーティションが 1 つのリポジトリに組み込まれ、from_pretrained 時点でプルーニングできる 3 つのワークフロー (t2va、fl2va、ref2va) が公開され、そのタスクのコンポーネントのみが宣言およびダウンロードされます。

ミニマックス ミュージック 3

MiniMax Music 3 は、歌詞と音楽説明から、表現力豊かなボーカルと長距離構造を備えた、最長 5 分の完全な曲を作成します。これは自己回帰ステージと拡散ステージのハイブリッドです。8B Qwen3 ベースのグローバル言語モデルは、フレームごとに 1 つのセマンティック オーディオ トークンを予測し、一方、小さな深さのデコーダーが 7 つの残留 RVQ コードブックを埋め、それらの融合された隠れ状態が、重複するチャンクで Flow-VAE 潜在を生成する 2.4B フローマッチングトランスフォーマーを条件付けます。 DAC スタイルのデコーダは、潜在音を 44.1 kHz ステレオ オーディオに変換します。

安定したオーディオ 3

Stable Audio 3 は、44.1 kHz で高品質のステレオ オーディオを生成する、Stability AI の Text-to-Audio モデルです。これは、フリーズされた T5Gemma テキスト エンコーダー (クロス アテンション経由) と継続時間 (StableAudio3DurationEmbedder によって埋め込まれ、アダプティブ レイヤー ノルムに使用されるフロート) に基づいて条件付けされた整流フロー DiT を使用し、同じエンコーダー (Semantically-Aligned Music Encoder) である AutoencoderSAME でデコードします。

StableAudio3Pipeline、StableAudio3AudioToAudioPipeline、StableAudio3InpaintPipeline の 3 つのパイプラインが出荷されます。

貢献してくれた @buffett0323 に感謝します (https://github.com/huggingface/diffusers/pull/14119)。

LTX-2.5

LTX-2.5 は既存の LTX2Pipeline / LTX2VideoTransformer3DModel / AutoencoderKLLTX2Video クラスを再利用します。個別のパイプライン クラスはありません。ユーザーが目に見える違いはテキスト エンコーダーです。LTX-2.5 は Gemma 4 (gemma4_unified) チェックポイントとペアになっており、変換された LTX-2.5 リポジトリから自動的にロードされます。

Lightricks/LTX-2.5-Diffusers は、蒸留 DiT (transformer/) とフル/SFT DiT (transformer_full/) の両方に加え、2 段階生成に必要なものすべてを同梱しています。このリリースでは、チェックポイントのサポートに加えて、以下が追加されています。

  • LTX2VideoDiffusionDecoderModel および LTX2VideoDiffusionDecodePipeline — 同じ潜在空間上の 2 番目のビデオ デコーダーなので、デコーダー間で潜在を交換できます。
  • テキスト コネクタ出力からショットの長さを予測する duration_head。そのため、ロードされたパイプラインに num_frames がある場合、デフォルトで num_frames が自動予測されます。
  • 個別の既製の google/gemma-4-E2B-it チェックポイント (enable_prompt_enhancement=True) による迅速な機能強化。 ・モジュラーディフ​​ューザー用LTX25AutoBlocks(#14453)。

わんアニメイト-2

Alibaba Wan Team による Wan-Animate-2 は、運転ビデオの動きを使用してリファレンス キャラクター画像をアニメーション化します。運転ビデオは固定長のセグメントで処理されます。各セグメントは、すべてのトランス層で運転セグメントの K/V をキャッシュする参照抽出パスを実行し、そのキャッシュに対してノイズを除去し、ループ内でデコードされます。これは、次のセグメントが前のセグメントのデコードされたテール フレームを条件とするためです。

2 つのプリセットが利用可能です。分類子を使用しないガイダンスを備えた基本チェックポイント サンプルと、分類子を使用しないいくつかのステップで抽出されたチェックポイント サンプルです。ガイダンスはパイプラインのガイダー コンポーネントによって所有されるため、guidance_scale 引数はありません。

統合 (https://github.com/huggingface/diffusers/pull/14413) を作成してくれた @kelseyee に感謝します。

JoyAI-画像編集-プラス

JoyAI-Image-Edit-Plus は、JoyAI-Image ファミリ (16B MMDiT と組み合わせた 8B MLLM) をマルチ画像の命令ガイド付き編集に拡張します。 1 ～ 5 枚の参照画像とテキスト命令を受け入れ、参照からの要素を新しい画像に構成します。

@tangyanf の貢献に感謝します (https://github.com/huggingface/diffusers/pull/14032)。

Cosmos 3 のフォローアップ

Cosmos 3 は 0.39.0 に追加され、このリリースではさらに多くの内容が取り上げられます。

  • Cosmos 3 モジュラー パイプライン (Cosmos3OmniModularPipeline)、事前計算されたコントロール ビデオ (エッジ、ブラー、深度、セグメンテーション、ワールド シナリオ マップ) 用の 転送サポート がチャンク内で自動回帰的に生成され、自動的にステッチされます。 ●【エッジサポート】(https://github.com/huggingface/diffusers/pull/14181)。
  • 抽出された (数ステップの) テキストから画像への変換と画像からビデオへの変換 (Cosmos3DistilledModularPipeline 経由)。 ・【モデル平行度】(https://github.com/huggingface/diffusers/pull/14054)。

貢献してくれた @yzhautouskay と @atharvajoshi10 に感謝します。

モジュラーパイプラインのサポート

モジュラー ディフューザーは 実験的マークが付けられなくなりました (#14525) - API 警告は削除されました。

  • このリリースの 3 つの新しい統合 — MiniMax-H3、MiniMax Music 3、および Wan-Animate-2 – はモジュラー ブロックのみとして出荷され、DiffusionPipeline の半分は付属しません。
  • Cosmos 3 (#14110、#14150、#14177) および Krea 2 (#14083、@Cedric-Perauer のおかげ) はモジュラー パイプラインを獲得し、Anima は獲得しましたimg2img ブロック (#13929、@PreethamNoelP に感謝)。
  • ブランチ固有の入力デフォルト (#14234): ConditionalPipelineBlocks の兄弟ブロックが同じ入力に対して異なるデフォルトを宣言する場合、combine_inputs はデフォルトを None にマージし、ブロックごとのデフォルトを新しい InputParam.defaults_by_block フィールドに記録するようになりました。 get_block_state はブロック自身の宣言されたデフォルトにフォールバックするため、各ブランチは実際の実行時に独自のデフォルトを解決します。 docstring は、競合するデフォルトを次のようにレンダリングします。 「ワークフローに応じて、デフォルトはなしまたは 189」。
  • グループ オフロードが自動オフロードで動作するようになりました、および グループ オフロード デバイスの不一致 が修正されました。
  • 未使用の intermediate_inputs がクリーンアップされました、古い自動ドキュメント文字列が CI で検出されるようになりました、および メロン カスタム ブロックの必須入力処理が修正されました。

コアライブラリ

テンソル並列処理

テンソル並列推論 は、CUDA および AWS Neuron (Trainium/Inferentia) でのモデル推論でサポートされるようになりました。これは、コンテキスト並列処理にすでに使用されているのと同じパブリック API を通じて公開されています。

from diffusers import TensorParallelConfig

pipe.transformer.enable_parallelism(config=TensorParallelConfig(mesh=tp_mesh))

シャーディングはモデルに依存せず、FLUX.1、FLUX.2、および Qwen-Image DiT に追加されたフラット _tp_plan から駆動されます。詳細については、ドキュメント を参照してください。

新しい量子化バックエンド

  • SDNQ — 2 ビットまでの int8、FP8 およびその他の低ビット浮動小数点数形式をサポートするトレーニング不要のバックエンド。オプションで SVD 補正、アダマール回転、量子化された INT8/FP8 matmul を備えています。 CUDA、ROCm、XPU、MPS、CPU 上で動作します。 【SDNQ MiniMax-H3搭載】(https://github.com/huggingface/diffusers/pull/14398)も入荷しました。 @asomoza に感謝します。
  • ヌンチャク ライト、事前量子化チェックポイントをロードするため、融合カーネルのパフォーマンスが文書化。 @rootonchair に感謝します。

注意、カーネルとオフロード

  • カーネルはユーザーが要求した場合にのみダウンロードされます
  • ROCm FlashAttendance は kernels-community/aiter-flash-attn-ck ハブ カーネルを使用するようになりました。aiter の依存関係は削除されました。 @Abdennacer-Badaoui に感謝します。
  • [_flash_3_varlen_hub バックエンドのシーケンス並列サポート] (https://github.com/huggingface/diffusers/pull/13809) および [マスク処理の修正] (https://github.com/huggingface/diffusers/pull/14115)。 @zhtmike に感謝します。
  • 分割デバイス パイプラインの DiffusionPipeline.device 控除
  • フックフォワード署名は保存されます。 @jloftin-nv に感謝します。

CLI

diffusers-cli はエージェント用に再加工され (#13966)、クリーンアップされました (#14381)。 modular_model_index.json はカスタム ブロックを保存するときに書き込まれるため、ModularPipeline.from_pretrained はカスタム ブロックをパイプラインとしてロードして実行でき、自動 CPU オフロードはモジュラー パイプラインで機能し、workflow はモジュラー パイプラインに渡されて出力できます。保存では、マルチモーダル出力 (LTX ビデオ フレーム + オーディオなど) とバッチ化されたビデオを処理します。

スキルは、Makefile ではなく CLI を通じてインストールされるようになりました (#14454)。

diffusers-cli skills list
diffusers-cli skills add <skill name>

🚨 重大な変更と非推奨

  • JAX/Flax サポートは削除されました (#14169) - およそ 12,000 行が削除されました。すべての Flax* クラスと flax の追加機能はなくなりました。
  • アルファ キーのない混合ランク LoRA は、意図したスケールでロードされるようになりました (#14409)。以前の get_peft_kwargs は、ランク辞書の最初のエントリから lora_alpha を取得し、それを再度参照することはなかったので、ランクが最初のキーのランクと異なるすべてのモジュールには、キーの順序に依存する任意のスケールが与えられました。チェックポイントがアルファ情報をもたらさない場合、ランクがアルファにミラーリングされるようになりました (ディフューザー/PEFT 規則: アルファ == ランク、スケール 1.0)。アルファが宣言されているアダプターはそれを保持し、均一ランクのアダプターは影響を受けません。既存の混合ランク、アルファなしの LoRA は、異なる (正しい) 結果を生成するようになります。
  • torch_dtype は、transformers に続き、dtype (#14205、#14313) に代わって非推奨になりました。 torch_dtype は引き続き動作しますが、警告が表示され、1.0.0 では削除される予定です。 torch.dtype エイリアス がドキュメントに追加されました。
  • DDUF は非推奨です (#14141)。 dduf_file は警告を出しますが、0.41.0 で削除されます。

テストとインフラストラクチャ
