LTX ビデオ 0.9.5

LTX ビデオ 0.9.5 は、超高速 LTX ビデオ モデル シリーズのアップデート版です。最新モデルでは、キーフレームベースのアニメーションやビデオ拡張 (前方および後方の両方) などの追加の調整オプションが導入されています。 これらの追加の条件入力をサポートするために、LTXConditionPipeline オブジェクトと LTXVideoCondition オブジェクトを導入しました。 使用法の詳細については、ここ のドキュメントを参照してください。

### グループオフロード
グループ オフロードは、シーケンシャル オフロードとモデル オフロードの中間点です。これは、内部レイヤーのグループ (`torch.nn.ModuleList` または `torch.nn.Sequential`) をオフロードすることで機能し、モデルレベルのオフロードよりもメモリの使用量が少なくなります。また、デバイス同期の数が減るため、順次レベルのオフロードよりも高速になります。 
CUDA デバイスでは、[CUDA Streams](https://pytorch.org/docs/stable/generated/torch.cuda.Stream.html) でレイヤーのプリフェッチの使用を有効にするオプションもあります。現在のレイヤの実行中に、次に実行されるレイヤがアクセラレータ デバイスにロードされるため、VRAM 要件を非常に低く抑えながら推論が大幅に高速化されます。これにより、計算とデータ転送を重複させるというアイデアが導入されます。
注意すべき点の 1 つは、CUDA ストリームを使用すると、CPU RAM の使用量が大幅に急増する可能性があることです。 `use_stream=True` を設定する場合は、利用可能な CPU RAM がモデルのサイズの 2 倍であることを確認してください。 `low_cpu_mem_usage=True` を設定すると、CPU RAM の使用量を削減できます。これにより、使用される CPU RAM がモデルのサイズとほぼ同じに制限されますが、推論プロセスでわずかな遅延が発生します。  
`use_stream=True` を使用するときに `record_stream=True` を使用すると、メモリ使用量がわずかに増加しますが、速度をさらに向上させることもできます。

### `torch>=2.6` による `uintx` TorachAO チェックポイントの読み込みの改善
現在、TorchAO チェックポイントは pickle を使用してシリアル化する必要があります。 `uint4wo` など、`uintx` 形式を使用する一部の量子化 dtype では、サブクラス化された TorchaO Tensor オブジェクトをモデル ファイルに保存する必要があります。これにより、pickle ファイルから任意の Python オブジェクトを逆シリアル化することが許可されていないため、Diffuser を使用してモデルを直接ロードするのが少し難しくなりました。    
Torch 2.6 を使用すると、予期される Tensor を torch セーフ グローバルに追加できるため、これらのオブジェクトを含む TorchAO チェックポイントを直接読み込むことができます。

LoRA

このリリースでは、LoRA の面でいくつかの改善を行いました。 🚨 Flux の非ディフューザー LoRA チェックポイントをロードするためのカバレッジを改善 この PR で導入された重大な変更に注意してください 🚨 特に Flux LoRA を扱う場合は、peft インストールを最新バージョン (pip install -U peft) にアップグレードすることをお勧めします。 再コンパイルをトリガーせずに LoRA をホットスワップする場合の torch.compile() のサポート 複数のアダプターを提供する場合の一般的な使用例は、最初に 1 つのアダプターをロードし、イメージを生成し、別のアダプターをロードし、さらにイメージを生成し、別のアダプターをロードするなどです。このワークフローでは通常、メモリを節約するために load_lora_weights()、set_adapters()、および場合によっては delete_adapters() を呼び出す必要があります。さらに、モデルが torch.compile を使用してコンパイルされている場合、これらの手順を実行するには再コンパイルが必要となり、時間がかかります。 この一般的なワークフローをより適切にサポートするには、LoRA アダプタを「ホットスワップ」して、メモリの蓄積を回避し、場合によっては再コンパイルを回避します。アダプターがすでにロードされている必要があり、新しいアダプターの重みが既存のアダプターの代わりに置き換えられます。 この機能の詳細については、ドキュメント を参照してください。 もう 1 つの大きな変更点は、
