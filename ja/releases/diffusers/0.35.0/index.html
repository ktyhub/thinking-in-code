ディフューザー v0.35.0

このリリースには、新しい画像生成および編集パイプライン、新しいビデオ パイプライン、新しいトレーニング スクリプト、生活の質の向上などが満載されています。楽しい内容を見逃さないように、release note の残りの部分をよく読んでください。

新しいパイプライン 🧨

このリリースでは、新しいパイプラインを歓迎しました。

  • ワン 2.2
  • フラックスコンテキスト
  • クウェンイメージ
  • クウェン-画像-編集

ワン2.2 📹

Wan のこのアップデートにより、ビデオの忠実度、即時遵守、およびスタイルが大幅に向上しました。詳細については、公式ドキュメント をご覧ください。

Flux-Kontext 🎇

Flux-Kontext は、テキスト指示に基づいて画像を編集できる 120 億パラメータの整流フロー トランスフォーマーです。詳細については、公式ドキュメント をご覧ください。

クウェン画像 🌅

言語モデルとビジョン言語モデルの配信が成功した後、Qwen チームは、Apache-2.0 ライセンスを取得した画像生成モデルを携えて戻ってきました。複雑なテキストのレンダリングと正確な画像編集において大幅な進歩を実現します。この強力なモデルの詳細については、ドキュメント を参照してください。 この PR と この PR を通じて Qwen-Image と Qwen-Image-Edit の両方に貢献してくれた @naykun に感謝します。

新しいトレーニング スクリプト 🎛️

トレーニング スクリプトを使用して、これらの新しく追加されたモデルを独自のものにします。

  • コンテキストトレーナー
  • クウェン-イメージトレーナー

単一ファイルのモデリング実装

単一ファイル モデリング実装の 🤗 Transformers の 哲学 に従って、私たちは単一の自己完結型ファイルでモデリング コードの実装を開始しました。磁束変圧器 コード はその一例です。

アテンションのリファクタリング

モデル内で注意を払う方法を大幅にリファクタリングしました。これにより、ライブラリ内のさまざまなアテンション バックエンド (PyTorch ネイティブ scaled_dot_product_attention、Flash アテンション 3、SAGE アテンションなど) のサポートをシームレスに提供できるようになります。 このようにアテンションをサポートすることで、私たちが積極的に取り組んでいるさまざまな並列化メカニズムを統合することもできます。ご興味がございましたら、この PR をフォローしてください。 ユーザーはこれらの変更による影響をまったく受けるべきではありません。問題が発生した場合は、問題を開いてください。

地域別コンパイル

リージョン コンパイルでは、モデルの小さく頻繁に繰り返されるブロック (通常はトランスフォーマー層) のみをコンパイルすることでコールド スタート レイテンシを短縮し、後続の発生ごとにコンパイルされたアーティファクトを再利用できるようにします。多くの拡散アーキテクチャでは、これによりフルグラフ コンパイルと同じ実行時間の高速化が実現し、コンパイル時間が 8 ～ 10 分の 1 に短縮されます。詳細については、このドキュメント を参照してください。 この PR でこの機能を提供してくださった @anijain2305 に感謝します。 また、torch.compile の使用を中心とした多数の投稿も作成しました。以下のリンクで確認できます。

  • Flux の高速提示: H100 で Flux を高速化する
  • torch.compile とディフューザー: 最高のパフォーマンスへの実践ガイド
  • ディフューザーとPEFTを使用したフラックスの高速LoRA推論

パイプラインの読み込みが高速化 ⚡️

ユーザーはパイプラインをアクセラレータ デバイスに直接ロードできるようになり、ロード時間が大幅に短縮されました。これは、Wan や Qwen-Image などの大規模なパイプラインを読み込むときに特に顕著になります。

from diffusers import DiffusionPipeline
import torch 

ckpt_id = "Qwen/Qwen-Image"
pipe = DiffusionPipeline.from_pretrained(
-    ckpt_id, torch_dtype=torch.bfloat16
- ).to("cuda")
+    ckpt_id, torch_dtype=torch.bfloat16, device_map="cuda"
+ )

状態辞書シャードの並列読み込みを有効にすることで、読み込みをさらに高速化できます。これは、Wan や Qwen-Image などの大規模なモデルを操作する場合に特に役立ちます。通常、モデル状態の辞書は複数のファイルにシャーディングされます。

import os
os.environ["HF_ENABLE_PARALLEL_LOADING"] = "yes"

# rest of the loading code
....

GGUF 統合の改善

@Isotr0py は、この PR でネイティブ GGUF CUDA カーネルのサポートに貢献しました。これにより、推論速度が約 10% 向上します。 また、コミュニティが GGUF チェックポイントを簡単に共有できるように、通常のチェックポイントを GGUF に変換するツールにも取り組んでいます。詳細はこちら。 ディフューザー形式の GGUF チェックポイントの読み込みをサポートするようになりました。 これらすべてについて詳しくは、GGUF 公式ドキュメント をご覧ください。

モジュラーディフューザー (実験的)

モジュラー ディフューザーは、個別 パイプライン ブロック を使用して拡散パイプライン パイプラインを構築するためのシステムです。高度にカスタマイズ可能で、特定のワークフローまたは複数のワークフローに適応したり、パイプラインを作成したりするためにブロックを組み合わせて適合させることができます。
API は現在鋭意開発中であり、実験機能としてリリースされています。詳細については、ドキュメント をご覧ください。
