#ミルバスv3.0.4

v3.0.4

発売日：2026年10月26日

|ミルバスのバージョン | Python SDK バージョン | Node.js SDK バージョン | Java SDK バージョン | Go SDK バージョン | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 3.0.4 | 3.0.2 | 3.0.6 | 3.0.10 | 3.0.0 |

Milvus v3.0.4 のリリースを発表できることを嬉しく思います。このリリースでは、一括インポート、圧縮、フィルターおよびグループ化された検索が高速化され、Storage V3 の列グループの遅延読み込みが追加され、インポート、コレクションの読み込み、および部分更新書き込みでのハングが修正され、アクセス制御の問題や CVE もいくつか発生します。

改善点

  • 入力チャンクを並列で読み取り、バイト範囲を熱心にプリフェッチすることにより、ソート圧縮の読み取りスループットが向上しました (#53437)
  • Parquet、Lance、および Vortex ファイルによってサポートされる外部コレクションに事前計算されたスパース ベクトルのサポートを追加しました (#53894)
  • プロキシ DML タスクを専用パッケージにリファクタリングして、タスクの責任を分離しました (#54064)
  • シールされたセグメントの検索のすべての出力フィールドが、検索自体と同じセグメント スナップショットから入力されるようにしました (#54074)
  • 最初のアクセスまで Storage V3 列グループのロードを延期する queryNode.segcore.tieredStorage.lazyColumnGroupEnabled オプション (デフォルトで無効) を追加し、セグメントのロード時間とメモリ使用量を削減しました (#54169)
  • IP メトリクスと BM25 メトリクスに個別にスパース AutoIndex ビルド パラメータを設定するための autoIndex.params.sparse.ip.build と autoIndex.params.sparse.bm25.build を追加し、autoIndex.params.sparse.build (#54212) にフォールバックしました。
  • CheckHealth 中に DataCoord セルフメトリクスを収集しなくなったことにより、大きなセグメントメタデータを持つクラスターでのヘルスチェックのレイテンシーが減少しました (#54214)
  • ジョブ ID でインポート タスクのインデックスを作成することにより、多くのインポート ジョブを含むクラスターの DataCoord インポート スケジューリングのパフォーマンスが向上しました (#54202)
  • 廃止された JSON 統計プレフィックスをセグメントごとに 1 回ではなく GC サイクルごとに 1 回スキャンすることで、ガベージ コレクション中のオブジェクト ストレージ リストのリクエストを削減しました (#54207)
  • 既存の配列チャンク オフセットから長さを読み取ることで、シールされたセグメントでの ARRAY_LENGTH フィルターのパフォーマンスが向上し、顧客のフィルター ワークロードで QPS が 102 から 270 に上昇しました (#54321)
  • grpc-go を v1.84.0 にアップグレードしました。これにより、プロキシはデコード直後に生のリクエスト バッファを解放し、実行中の大規模検索ごとにヒープをリクエスト サイズ全体 (nq=10000, 1536-dim 検索の場合は 61.5 MB) まで節約します (#54271)
  • StreamingNode での部分的な更新に対する比較およびスワップ チェックをオフにする非表示の streaming.partialUpdate.enableCAS オプションを追加しました (デフォルトで有効)。これにより、同時の古い更新に対する保護と引き換えに書き込みオーバーヘッドが低くなります (#54249)
  • プロキシが成功するすべてのクエリにログを記録するという偽の「ステータスが nil」という警告を削除しました (#54247)
  • RESTful V2 挿入および更新/挿入リクエストをデコードする際のメモリ割り当てを削減し、変換失敗時の完全なリクエスト ペイロードのログ記録を停止しました (#54403)
  • 事前インポート後に正確なファイルごとの ID 範囲を割り当てるように一括インポートを再調整しました。これにより、事前にファイルのサイズを設定することなくインポート リクエストがすぐに返され、インポート書き込みの再試行中のログ ID の枯渇が修正されました (#54416)
  • IP および BM25 スパース ベクトル フィールドの暫定インデックス アルゴリズムをオーバーライドする起動設定オプションを追加しました (#54441)
  • CVE-2026-78667、CVE-2026-97031、および CVE-2026-78669 (#54451) に対処するために、Go to 1.26.9 および golang.org/x/net を v0.60.0 にアップグレードしました。
  • 生の JSON を解析する代わりに、JSON シュレッディング統計から VARCHAR、BOOL、および整数グループ キーを読み取ることで、シールされたセグメント内の型付き JSON パスでのグループバイ検索が改善されました (#54456)
  • OpenTelemetry を 1.45.0 に、cilium/ebpf を 0.22.0 にアップグレードし、CVE-2026-81870 および CVE-2026-10722 (#54461) に対処するためにランタイム イメージのcurl、tar、zlib、およびglibcを更新しました。
  • キャッシュミス時にのみ用語を変換することで、インデックス付き ARRAY_CONTAINS フィルターの冗長なクエリ用語変換を削減しました (#54459、#54465)
  • 各バッチが完了するのを待つのではなく、継続的にインポートタスクをスケジュールすることで、インポートのスループットが向上しました (#54471)
  • CDC レプリケーション設定のプライマリ クラスターとセカンダリ クラスターの両方でクラスター ローカルの Flush および FlushAll のサポートを追加しました (#54502)
  • 検索のファンアウト作業 (PK 充填、距離調整、出力フィールドの実体化) を専用のスレッド プールに分離し、検索がフィールドとインデックスの読み込みの後にキューに入れられないようになりました (#54524)

バグ修正

  • 起動中の一時的な etcd 読み取りエラーにより、タイムスタンプ アロケータが以前に割り当てられたタイムスタンプよりも古いタイムスタンプを発行する可能性がある問題を修正しました (#51762)
  • インポート ジョブが永久にハングし、pchannel のチェックポイントをブロックする可能性がある問題を修正しました。以前は手動による etcd 修復と StreamingNode の再起動が必要でした (#54111)
  • Timestamptz または Geometry フィールドを含むコレクションに行を挿入するときの Go SDK パニックを修正しました (#54131)
  • 部分更新の実行時にシャードでの高い書き込みレイテンシーと書き込みバックログが修正され、各部分更新コミットが同じ vchannel 上の他のすべての書き込みをブロックしました。部分的な更新では、同じ主キーにアクセスする書き込みのみがブロックされるようになりました (#54215)
  • セグメントのロードまたはチャネル監視リクエストがスタックしたときに、コレクションのロードが無期限にハングする可能性がある問題を修正しました。 QueryCoord は、タスクステップごとに queryCoord.channelTaskTimeout (デフォルト 2 分) および queryCoord.segmentTaskTimeout (デフォルト 5 分) を適用するようになりました。そのため、個々のセグメントのロードに時間がかかる場合は、セグメントのタイムアウトを増やします (#54217)
  • Storage V3 での L0 圧縮マニフェストのコミットが遅いと、DataCoord でのフラッシュおよびセグメント情報リクエストが停止する可能性がある問題を修正しました (#54186)
  • AWS ランタイムの個別のコピーをバンドルするネイティブ ライブラリによって引き起こされる、AWS S3 ストレージへのアクセス時の潜在的なクラッシュを修正しました (#54192)
  • 優先度の低いセグメントのロード (スケールダウンまたはバランシング中など) が生のフィールド データを高い優先度でロードし、他のロードと競合して検索レイテンシが増加する問題を修正しました (#54335)
  • StorageV3 のパックされたスカラー インデックス (STL_SORT、MARISA) のロードで予算よりも多くのメモリが使用される可能性があり、ロードの失敗によって処理中のダウンロードがすぐに停止されない問題を修正しました (#54359)
  • ORDER BY および LIMIT を使用した GROUP BY 集計クエリが、結果がセグメントおよびノード間でマージされた場合に不完全または不正な集計値を返す可能性がある問題を修正しました (#54393)
  • 認証が有効になっていると、非 root ユーザーが client テレメトリ管理 API にアクセスできる問題を修正しました。これらの API には root ユーザーが必要になりました (#54408)
  • ユーザーが別のデータベースまたは履歴コレクション名を指定することによって、インポート権限のないコレクションのインポート ジョブの詳細を表示できる問題を修正しました (#54449)
  • QueryNode セグメントのロードを待機しているリクエストが無期限にハングし、ロードの完了とキャンセルの両方が失われる可能性がある問題を修正しました (#54452)
  • バケットが切り捨てられた場合、検索集約 top_hits が L2 およびハミング メトリクスに対して最も類似した結果ではなく最も類似性の低い結果を返す可能性がある問題を修正しました (#54458)
  • 出力フィールドが複数のシャードから返された場合、group-by を使用したハイブリッド検索が失敗する可能性がある問題を修正しました (#54457)
  • 新しい主キーが存在する場合、null 許容またはデフォルト値の TIMESTAMPTZ フィールドを省略した部分的な更新/挿入が失敗するか、有効なリクエストを拒否する可能性がある問題を修正しました (#54460、#54464)
  • ワードレベルの MinHash 署名を計算する際のメモリ リークを修正しました (#54463)
  • RESTful v2 検索が、正でない groupSize や strictGroupSize などの明示的なグループバイ パラメーターをサイレントに無視する問題を修正しました。無効な値はデフォルトに戻るのではなく拒否されるようになりました (#54466)
  • 前の書き込みがすでに適用されている後でも、強力な整合性クエリが次の定期的なタイムティックを待機する可能性がある問題を修正しました (#54501)
  • セグメントが成長したままである間に挿入されたデータが永続化された後、TEXT フィールドを含むアイドル コレクションのチャネル チェックポイントの進行が停止する問題を修正しました (#54538)
  • ある Milvus バージョンで書き込まれたスナップショット マニフェストが別のバージョンでデコードできない可能性がある問題を修正しました。スナップショット マニフェストは自己記述型 Avro ファイルになりました (#54549)
  • レプリケーションが設定されていないクラスター上のレプリケート設定のクエリがリクエストがタイムアウトするまでブロックされ、セカンダリがすべてのメッセージを拒否するとレプリケート ストリームがバックオフされる問題を修正しました (#54555)
  • CDC セカンダリ クラスター上の LoadCollection 後に作成されたパーティションがロードされず、セカンダリ上のクエリでデータが失われる問題を修正しました (#54561)
  • アップサートが成功すると、プロキシ メトリクスで報告された値が 2 回カウントされ、報告された量が誇張される問題を修正しました (#54605)
