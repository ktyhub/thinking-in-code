playwright-mcp v0.0.81

パッチ 公開日2026年9月14日 出典microsoft/playwright-mcp 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#劇作家-mcp v0.0.81

新機能

🎉 新しいツール

  • browser_webmcp_list / browser_webmcp_call — WebMCP API を通じてページが登録したツールを一覧表示して呼び出し、UI を駆動する代わりにページに作業を実行させます。ページに WebMCP ツールがある場合、ページのステータスによって、使用可能なツールの数が報告されます (#42613)。 WebMCP は実験的なものです。有効にする方法については、Chrome の WebMCP を参照してください。

その他の変更点

  • 新しい --profile-dir-name <name> オプション (環境 PLAYWRIGHT_MCP_PROFILE_DIR_NAME) は、拡張機能が複数のプロファイルにインストールされている場合に拡張モードで接続する Chrome プロファイルを選択します (例: "Profile 1" (#42527))
  • サーバーによって起動されたヘッドレス ブラウザは、ツールの呼び出しがなければ 1 時間後に閉じられるようになりました。次のツール呼び出しで新しいツールが起動されます。タイムアウトを変更するには、--idle-timeout <ms> (config timeouts.idle、env PLAYWRIGHT_MCP_IDLE_TIMEOUT) を使用します。0 を使用すると、タイムアウトが無効になります。タイムアウトが明示的に設定されない限り、ヘッダー付きブラウザーと接続されたブラウザーは閉じられません (#42663、#42676)
  • --image-responses は only を受け入れます: 画像を含む応答は、テキスト部分を含まず、画像部分のみで構成されます (#42672)

バグ修正

  • browser_close は、ブラウザー コンテキストが共有されている場合 (--shared-browser-context)、呼び出し元の client のセッションを中断するのではなく、エラーを返します。これは、browser_close の後にバックエンドを削除した v0.0.80 の変更 (#42495) に優先します。
  • --shared-browser-context、browser_start_recording / browser_stop_recording (--caps=devtools 経由でオプトイン) を使用すると、1 つの client の記録されたアクションを別の client に配信するのではなく、各 client の記録を個別に保持します (#42622、#42627)
  • ファイル アクセス チェックはシンボリック リンクに従うため、ワークスペース内のシンボリック リンクは、許可されたルート外のファイルの読み取りまたは書き込みに使用できなくなります (#42628)
  • ネストされたディレクトリ (sub/shot.png など) 内の明示的に名前が付けられた出力ファイルは、ENOENT で失敗しなくなりました。 browser_file_upload および browser_drop は、ワークスペースのルートに対する相対パスを解決します (#42540)
  • PLAYWRIGHT_MCP_EXTENSION_TOKEN が設定された拡張モードでは、完了しない接続 (例: トークンが別の Chrome プロファイルに属している) は、ツール呼び出しを永久にハングするのではなく、ヒントとともに 30 秒後に失敗するようになりました (#42525)
  • バンドルされた Chromium ビルドの Linux ではデフォルトで Chromium サンドボックスを無効にします。これには setuid サンドボックス ヘルパーがありません (#42490)
