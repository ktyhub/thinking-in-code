nightingale v9.1.0

マイナー 公開日2026年8月6日 出典ccfos/nightingale 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ナイチンゲールv9.1.0

何が変わったのか

  • 特技: 組み込みの時系列データベース — Categraf によってプッシュされたメトリクスはローカルに保存されるため、開始するために外部の Prometheus / VictoriaMetrics は必要ありません。 embedded-tsdb という名前の Prometheus データソースは、最初の起動時に自動登録されます。既存の設定が尊重されます。有効な Prometheus データソースがすでに存在する場合、データソースは自動作成されません。サンプルは引き続きローカルに書き込まれ、組み込み TSDB を指す Prometheus データソースを追加してクエリを実行できます (#3283)
  • 特技: 1 つの click で Grafana からデータソースをインポートし、データソースごとの結果の概要を表示します (#3295)
  • 特技: データソース ページの刷新 — データソースを保存した後、ナイチンゲールはセンチネル メトリクスを使用してデータソースを調査し、どの組み込みダッシュボード/アラート ルール テンプレートに既にデータがあるかをレポートし、最初のクエリに誘導します (#3301)
  • 特技: サイクルごとのアラート評価レコード — 各ルール評価は、クエリの内容とその判断方法をアラート エンジンのローカル ディスクに保持し、アラート ルール ページのドロワーから検査できます (#3305)
  • 特技: 保存する前に、通知チャネル構成をテストし、メッセージ テンプレートをプレビューできるようになりました (#3302)
  • 特技: Categraf 収集構成ウィザード — 新しい /agents/categraf/collect.sh エンドポイントが、プラグイン テンプレートとコンソールでのメトリック検証を備えたアプライヤー スクリプトを提供します (#3286)
  • 特技: イベント パイプラインは、try-run でのモック イベント、実行レコードの時間範囲フィルタリング、バッチの有効化/無効化、および新しい変更 API (#3281、#3285) をサポートします。
  • 特技: en_US i18n を使用して、統合内の組み込みアラート ルール テンプレートを大幅に拡張および改訂しました (#3282)
  • 特技: MySQL データソースは DSN に追加のパラメータを追加できる (#3299)
  • 特技: Doris データソースは、エッジ プロセスが FE MySQL に到達するために doris.internal_addr をサポートします (#3298)
  • 特技: アラート ルール リストはトリガー タイプによるフィルタリングをサポートします
  • 機能: アクティブなアラート イベント リストはトリガー時の値を表示し、スリーステート タグを追加し、フィルター パネル、自動更新間隔、訪問全体の時間範囲を記憶します。
  • 特技: ログ エクスプローラーは、Loki および VictoriaLogs のクエリ ドキュメント ボタンを追加し、ログ ビューアーからフィールド フィルターを直接追加できるようにし、BCE BLS ドリルダウンをサポートします。
  • 特技: ダッシュボード TableNG パネルは行詳細ドロワーをサポートします
  • 特技: ホスト ページのオンボーディング — 1 つの click ホスト モニタリング パック、テスト アラート アクション、および次のステップ カード
  • 特技: データソース プロキシとログ クエリへのアクセスが、ユーザーとペイロードとともに監査ログに書き込まれるようになりました。
  • 特技: リクエストごとのタイムアウトを強化して、エッジがイベントの永続性をセンターに再試行します。
  • 特技: 通知が正常に配信されたかどうかを確認する新しい API (#3300)
  • perf: 起動時にオンラインで作成される 2 つの新しい notification_record インデックスを利用して、通知レコードのクエリと毎日のクリーンアップを高速化します (#3311)
  • 修正: イベントをキューにプッシュする前にイベントをディープ コピーするため、リカバリ イベントがまだ消費されていないトリガー イベントをその場で上書きしなくなりました。
  • 修正: 空の DingTalk アプリ設定によってグループ ロボット通知が中断されなくなりました (#3309)
  • 修正: ai_* モデルで明示的な列タイプを固定して、これらのテーブルの移行に失敗していた AutoMigrate スキーマのドリフトを停止しました。
  • 修正: 新しい OpenAI モデルの max_completion_tokens をサポート (#3306)
  • 修正: アラート ルール event_relabel_config で無効なラベル名をガード (#3287、#3296)
  • 修正: 組み込みペイロードを収集するために YAML コンテンツを受け入れる (#3307)
  • 修正: ヘルスチェックに失敗したデータソースの強制保存を許可 (#3304)
  • 修正: エンジンごとのクラスター フィルタリングの前に、完全なデータソース リストに対してグローバル デフォルト データソースを調査するため、別のクラスターが所有するデフォルト データソースがクリアされなくなりました。
  • 修正: 正しいアラート ルール単位
  • 修正: 組み込みスキル YAML フロントマターを修復し、チャットでコード検索ツールを公開する
  • 修正: 非同期テーブル移行に独自の gorm セッションを与えるため、1 つの失敗したステートメントが残りのステートメントを汚染しなくなりました。

V9 の新機能

  • 偉業: Nightingale AI の導入 — 組み込みの AI アシスタント、スキル マーケットプレイス、LLM 構成管理、ページ固有のプロンプト推奨事項を備えた
  • 特長: 内蔵の時系列データベース — 箱から出してすぐに動作し、小規模なセットアップには外部の Prometheus / VictoriaMetrics は必要ありません
  • 特技: ナビゲーション メニュー、グローバル レイアウト、テーブル UI の再設計
  • 特技: 通知チャネル管理のリファクタリング
  • 特技: 詳細な実行ビューを備えた新しいイベント パイプライン実行追跡ページ

アップグレードに関するメモ ⚠️

  • 新しい AI アシスタントは Redis ストリームに依存するため、Redis 5.0 以降が必要です (シャード Pub/Sub を有効にするクラスター ユーザーには Redis 7.0+ が推奨されます)。
  • アラート評価レコードは デフォルトで有効になっています。アラート エンジンはそれらを ./evallog のローカル ディスクに書き込み、8 日間保持され、20 GB に制限されます。 [Alert.EvalLog] セクションでこれを調整またはオフにします。新しい etc/config.toml を参照してください。
  • 組み込み TSDB は、インプレース バイナリ アップグレードでは有効ではありません。[EmbeddedTSDB] は新しい etc/config.toml にのみ存在するため、以前のバージョンから引き継がれた構成ファイルではオフのままになります。セクションをコピーして有効にします。これはセンター プロセスによってのみ処理され (n9e-edge / n9e-alert / n9e-pushgw は無視します)、データはその 1 つのセンター インスタンスのローカル ディスクに保存されるため、単一インスタンスの展開に適合します。複数のセンター レプリカがある場合は、代わりに外部 TSDB を使用します。
