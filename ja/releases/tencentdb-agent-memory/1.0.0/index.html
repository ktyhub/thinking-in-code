TencentDB-エージェント-メモリ v1.0.0

[1.0.0] - 2026-06-11

正式版リリース: OpenClaw 専用プラグインから すべてのエージェント向けのユニバーサル メモリ サービスに進化しました。完全なゲートウェイ独立サービス + v2 HTTP API + 公式 TypeScript / Python SDK により、あらゆるエージェント フレームワークが完全な多層メモリおよびコンテキスト圧縮機能にアクセスできます。

⚠️重大な変更

  • クライアント/サーバー アーキテクチャの分割: メモリ エンジンは、OpenClaw 組み込みプラグインから独立したゲートウェイ サービス プロセスに分割され、展開方法とアクセス方法が変更されます。
  • 設定構造の変更: プラグイン設定構造はフラット化されて再構築され、元の gateway フィールドはネストされた server に移行されます。
  • プラグイン エントリ モードの変更: local (プロセス内でローカルに実行、デフォルト) と client (外部メモリ ゲートウェイに接続) の 2 つのアクセス モードをサポートします。

🚀 独立したゲートウェイ サービス (v2 API)

メモリ機能は OpenClaw ホストにバインドされなくなり、独立したサービスとして実行されます。 v2 HTTP API を介して、あらゆるエージェントにメモリの読み書きとパイプライン管理を提供します。

  • フル v2 API: メモリ CRUD、アトミック更新、シーン インデックス作成、パイプライン ステータス クエリなどのすべての操作をカバーする 14 の標準ルート。
  • パイプライン ステータス クエリ (/v2/pipeline/status): L1/L2/L3 の各ステージの実行ステータスと進行状況をリアルタイムで取得します。
  • インスタンス ライフ サイクル管理 (/v2/instance/destroy): メモリ インスタンスをアクティブに作成/破棄する外部システムをサポートします。
  • オプションのベアラー認証 + CORS ホワイトリスト: 外部に公開されている API のセキュリティを保護します。
  • リクエスト本文の検証: 異常なリクエストを防ぐために 1 MiB の上限を適用します。

🚀 公式SDK

  • TypeScript SDK 1.0.0 (@tencentdb-agent-memory/memory-sdk-ts): タイプ セーフで、すべての v2 API をカバーし、npm インストールですぐに使用できます。
  • Python SDK (tencentdb-agent-memory-sdk-python): ピップ ホイールのインストール、同期/非同期デュアル モード、すべての v2 API をカバーします。

🚀 ユニバーサル エージェント フレームワークの適応

  • OpenClaw プラグインの適応: local (プロセス内でローカルに実行、デフォルト) と client (外部メモリ ゲートウェイに接続) の 2 つのアクセス モードをサポートします。 local モードでは、元のエクスペリエンスが維持されます。
  • Hermes エージェント アダプテーション: memory_tencentdb_v2 アダプターは、Hermes フレームワークのマルチテナント シナリオをサポートします。
  • ユニバーサル アクセス: HTTP リクエスト (LangChain、AutoGPT、自社開発フレームワークなど) を送信できるエージェントは、SDK またはベア API 経由でアクセスできます。

🚀 可観測性

  • OpenTelemetry フルリンク トレース: OTLP プロトコル レポートをサポートし、Jaeger / Grafana Tempo などのバックエンドに接続できます。
  • Langfuse 統合: LLM 関連のスパンのみを転送し、メモリ取得品質の評価に適しています。
  • パイプライン評価指標: L1抽出率、重複排除判定分布、各ステージでのトークン消費量、リコール遅延など。

🚀 オフロード サーバー V2

  • L1 / L1.5 / L2 非同期エグゼキューター: 独立したオフロード処理パイプラインで、大規模なセッションの同時実行をサポートします。
  • L3 圧縮プロセッサ: マーメイド トークン化 + コンテキスト バジェット コントロール、インテリジェントなコンテキスト圧縮。
  • MMD インジェクション: マルチモーダル データ インジェクション オフロード プロセスをサポートします。
  • ゲートウェイ統合 /v2/offload/* ルーティング: 統合オフロード API 入口。

📦 導入方法

|方法 |説明 | |------|------| | Dockerコンテナ | docker pull agentmemory/hermes-memory:1.0.0 | |ソースコードを直接実行する | node --import tsx/esm src/gateway/server.ts | | OpenClaw プラグイン | install-openclaw-plugin-v2.sh 経由でインストール | |ヘルメスプラグイン |組み込み memory_tencentdb_v2 Python プラグイン |

⬆️ 0.x からのアップグレード手順

v1.0.0 と 0.x は、並行して維持される 2 つのバージョン ラインです。

  • 0.x (main ブランチ): OpenClaw 組み込みプラグイン。軽量のスタンドアロン シナリオに適しています。
  • 1.x (feat/server ブランチ): 独立したメモリ サービス。マルチエージェント/マルチフレームワーク/サービスベースの展開に適しています。

2 つのコア メモリ エンジンは同じであり (L0→L3 階層化 + BM25/ベクトル ハイブリッド検索 + マーメイド シンボリック短期メモリ)、データ形式に互換性があります。

🐛 修正 (v1.0.0-beta.2 → v1.0.0)

  • Hermes プラグイン install_hermes_tdai_gateway.sh が改善されました: root の自動ユーザー切り替え、古いパスの自動移行、反復インストールをスキップする冪等検出をサポートします。
  • ゲートウェイ構成の最適化: デフォルトのポート 8420、2 つの環境変数 /etc/profile.d/ および ~/.hermes/.env を同期的に書き込みます。
  • SDK ドキュメントの完成: TypeScript / Python SDK README とアクセス例
  • OpenClaw plugin.json 構成の調整: 非推奨のフィールドを削除し、OpenClaw の最新バージョンに適応します。
