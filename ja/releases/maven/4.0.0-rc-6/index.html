maven 4.0.0-rc-6

プレリリース 公開日2026年7月30日 出典apache/maven 英語原文

#maven maven-4.0.0-rc-6

注意事項

Maven 4 のこの新しいリリース候補は、ユーザーからのフィードバックを得るためにリリースされました。 Maven 4 では Maven 3 と比べていくつかの制限があるため、Maven 4 でプロジェクトを試す前に必ず mvnup ツールを実行してください。

RC-5 以降に修正された問題

RC-5 release note で報告されたすべての既知の問題が修正されました。

  • Bean 設定のバグ — フィールドのアクセシビリティ状態がグローバルにキャッシュされ、プラグイン設定の挿入エラーが発生しました。 #11433で修正されました。
  • v4 API の同時実行の問題 — ConcurrentModificationException は #11429 で修正されました。
  • BOM パッケージ化 - BOM プロジェクトのコンシューマ POM 変換で、依存関係のバージョンが正しく保存されるようになりました。 #11464で修正されました。
  • macOS Gatekeeper - Gatekeeper をトリガーした抽出された JLine ネイティブ バイナリはディストリビューションから削除されました (#11997)。 RC-5 の xattr 回避策は必要なくなりました。

既知の互換性の問題

Maven 4 を使用する場合の既知の互換性問題は次のとおりです。 mvnup で構築する前 Maven 4 では、多くの一般的なプラグイン バージョンの問題が自動的に修正されます。問題点 以下は、手動介入またはアップストリーム修正が必要なものです。

より厳格な POM 検証

Maven 4 では、Maven 3 よりも厳格な検証が適用されます。プロジェクトでは、POM を修正する必要がある場合があります。

  • 重複した XML 要素 - 重複した <artifactId>、<properties> などが拒否されるようになりました (Duplicated tag エラー)。ソース POM を修正します。
  • 依存関係宣言の重複 - 2 回宣言された同じ groupId:artifactId は拒否されるようになりました (must be unique)。
  • 補間されていない式 — Maven 3 が黙って受け入れていたリポジトリ URL、配布管理 ID、およびその他のフィールド内の ${...} 式が拒否されるようになりました。
  • 推移的 POM 内の無効な XML - 推移的 POM 内の不正な処理命令または未宣言の名前空間プレフィックスにより、Non-parseable POM エラーが発生します。
  • <module> パスのプロパティ — Maven 4 は、POM 読み取り時に <module> 要素内の ${spark.version} のようなプロパティを補間しなくなりました。
  • CI 対応バージョン - flatten-maven-plugin を使用せずに ${revision} を使用するプロジェクトでは、依存関係バージョンの欠落エラーが発生する可能性があります。
  • 無効な収集リクエスト — 補間されていない ${...} バージョン式を含む推移的な依存関係は拒否されます。

推移的な依存関係解決の変更

Maven 4 の TransitiveDependencyManager は、すべての推移的な深さで dependencyManagement を適用します (Maven 3 は最初のレベルでのみ適用しました)。これは意図的なものですが、解決されたバージョンが変更される可能性があります。

  • クラスパス上の以前の依存関係が消える可能性があります - 明示的な宣言を追加します。 #12302 を参照してください。
  • maven-enforcer-plugin バージョン ルールは、ダウングレードされた推移的バージョンが原因でトリガーされる可能性があります。
  • license-maven-plugin は、許可リストにない新しい推移的な依存関係を報告する場合があります。
  • OSGi バンドルのバージョンの不一致により、Karaf 機能の検証が失敗する場合があります。

プラグインと拡張機能の互換性

一部のプラグインと拡張機能には、Maven 4 の特定のバージョンが必要です。

  • Quarkus — 3.20 より前のバージョンは、Maven 4 の Sisu ベースの DI と互換性のない ServiceLocator/RepositorySystem パターンを使用します。 Quarkus 3.20+ にアップグレードします。
  • Tycho — 5.0 より前のバージョンでは、Maven 4 によって壊れた Guice/Sisu インジェクション パターンが使用されています。Tycho 5.0.3+ にアップグレードしてください。
  • Develocity Maven 拡張機能 — SLF4J クラスローディングの変更 (ClassNotFoundException: SimpleLogger) が原因で初期化に失敗します。
  • pgpverify-maven-plugin — 1.20 より前のバージョンは、Maven 4 のリゾルバーで ClassCastException にヒットしました。 リゾルバー#1957 を参照してください。
  • cyclonedx-maven-plugin — ${revision} CI 対応バージョンを使用すると、Invalid Version Range Request で失敗します。
  • maven-site-plugin — サイト プラグインのバージョンに互換性がない場合、Velocity テンプレートのレンダリングが失敗する可能性があります。
  • maven-shade-plugin — dependency-reduced-pom.xml により The parents form a cycle エラーが発生する可能性があります。
  • commons-release-plugin — clean-staging は Maven 4 では失敗します。

クラスローディングの変更

  • Maven 3 のクラスレルム レイアウトに依存するプラグインでは、「外部インポート」 エラーが発生する可能性があります (例: Quarkus、JAXB プラグイン)。
  • Maven 4 のプレフィックスベースのリポジトリ ルーティングは、/.meta/prefixes.txt と一致しないアーティファクトをブロックする可能性があります。

mvnup 後のフォーマット

  • spotless-maven-plugin および sortpom-maven-plugin は、mvnup が POM ファイルを変更した後、フォーマット違反を報告する場合があります。 mvnup の後にフォーマッタを再実行します。

その他

  • 壊れたアップストリーム POM - 例: hadoop-project 3.1.0 ～ 3.3.0 には無効な XML (<Xlint:-unchecked/>) があり、解析エラーが発生します。これらには、HADOOP-19923 で追跡されるアップストリームの修正が必要です。
  • エンフォーサ POM 要素の順序付け — Maven 4 のモデル ビルダーは、POM 要素を正規の順序に並べ替えます。これにより、要素の順序をチェックするエンフォーサ ルールが破られる可能性があります。
  • SNAPSHOT 処理 — Maven 4 の異なるリゾルバー メタデータ処理では、SNAPSHOT アーティファクトが「存在しますが、利用できません」と表示される場合があります。
