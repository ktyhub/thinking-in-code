#グラフィティv0.29.1

0.29.0 以降、品質と信頼性の向上をカバーするパッチ リリースがリリースされました。

抽出品質

属性幻覚ガード (#1498) — エンティティ属性フィールド (例: 電話、 業界）。 LLM は内部審議を放棄し、スキーマ記述テキストを値にエコーバックしていました。 3 層の防御:

  1. プロンプト レベル: ノードとエッジの両方の extract_attributes プロンプトには、括弧で囲まれた推論、熟議的なフレーズ、候補を禁止する厳格なルールが追加されました。 代替案、スキーマ記述エコー、null/N/A 文の代用。ポジティブ/ネガティブな例が含まれています。
  2. 結合抽出プロンプト: 新しい OUTPUT DISCIPLINE ブロックにより、「トピックとしての人」障害モード (全文エンティティ名) が閉じられ、推論リークが回避されます。 実際の text と relationship_type に変換します。
  3. プロバイダーレベルのプリアンブル: LLMClient の共有 _apply_attribute_extraction_preamble は、OpenAI、Anthropic、Gemini、GLiNER2 全体でシステム メッセージを変更します。 したがって、「フィールドの説明は値ではなく形式仕様です」という指示は、構造化された出力がどのように配線されているかに関係なく、すべてのプロバイダーに届きます。センチネルベース 冪等性。

構造バックストップ — cap_string_attributes: 250 文字を超える文字列属性をグラフに到達する前に削除します。 Pydantic 経由でフィールドごとに構成可能 フィールド(max_length=...)、または GRAPHITI_ATTRIBUTE_MAX_LENGTH 経由でグローバルに。 list[str] (アイテムごと + max_len * 8 の合計上限) も処理します。必須フィールドのカーブアウト 値を削除するのではなく、より大きな警告を付けて保持します (エンティティ全体の ValidationError を回避します)。エッジ書き込みでは、オーバーキャップドロップのみにスコープ付きマージが使用されます — LLM が正当に省略したフィールドはまだクリアされています。 group_id は、テナント相関のログ行に流れます。

複合抽出エンティティとエッジ精度 (#1498) — 6 クラスの低品質エンティティ (複数選択のフラグメント、クロック時間、数量、座標、 必須のヒント フレーズ、スローガン）と 2 つの系統的なエッジ回帰（風景の仲介者による場所の断片化、複数のエピソードの設定の削除） 事実）。

  • エンティティ ルール 6 は、スキップ クラスをカバーする 8 つのサブ箇条書きに拡張されました。教訓/チュートリアルの足場としてエンティティ ルール 9 が追加されました。
  • ファクトルール 4 は、会話エピソードにおける物語の発表、将来の約束、計画、感情的な設定を中心に強化されました。ファクトルール8を追加 風景の仲介物を介した断片化ではなく、話者からターゲットまでの直接のエッジが必要です。
  • 否定例ブロック (A ～ G) に、クラスごとのソースと抽出のペアのガイダンスが追加されました。

Locomo 500 の評価例 (即時変更のみ):

  • エンティティ F1: 0.674 (フラット);精度 -0.028、リコール +0.025
  • エッジボリューム: ベースラインより +7.7%;ゴールドエッジリコール +0.9pp
  • 一致したエッジのファクトテキスト Jaccard: 0.341 → 0.381
  • LME派生サンプルの対象エンティティクラス: 量 -93%、命令的ヒント -40%

佐賀のまとめ

サガのエピソード時間のウォーターマーク (#1498) — サガ (スレッドの概要) のタイムスタンプは、実時間ではなく、元のエピソードの時間を反映するようになりました。今のSagaNode 意図的に異なる 2 つの透かしが含まれています。

  • last_summarized_at (壁時計) — フィルターのウォーターマーク。 summary_saga は、created_at > この値を持つエピソードを選択します。ウォールクロック + created_at の比較 バックフィルされたエピソードを次回の実行時にアクセスできるようにします。

  • last_summarized_episode_valid_at (エピソード時間) — 時間的なウォーターマーク。現在の概要でカバーされているエピソード全体の最大 valid_at。単調に進みます。 パブリック/一時的なコンシューマ (「イベント時にこの概要のコンテンツがどのくらい新しいか?」) は、このフィールドを使用する必要があります。

    saga_get_episode_contents は list[(content, valid_at)] タプルを返すようになったので、呼び出し元はウォーターマークを計算できます。 _get_or_create_saga の名前が今すぐ → created_at に変更されます。 呼び出し元はエピソードの valid_at を渡すので、新しく作成されたサガの created_at がそれを作成したエピソードと一致します。

    Docker / 梱包

    • 修正(mcp): Docker イメージに MCP プロバイダー エクストラをインストールする (#1461)
    • 修正(docker): FalkorDB ボリュームを実際のデータ パスにマウントする (#1462) — 以前のマウント パスが FalkorDB のデータ ディレクトリと一致しなかったため、データは実際には永続化されませんでした コンテナーの再起動後も。
    • chore(deps): 2 つのディレクトリ間で UV グループをバンプする (#1473) — jupyterlab 4.5.7、および jupyter-server 2.18.0、mistune 3.2.1、python-multipart への間接的な更新 0.0.27。

    ドキュメント

    • docs(graphiti): 古い add_episode_bulk 警告を削除 (#1476) — バルク パスがエッジの無効化と日付をスキップすることを警告する古い docstring を削除しました。 抽出。バルク パイプラインがエピソードごとのプリミティブを共有するように書き直されて以来、これは当てはまりません (resolve_extracted_edges、extract_edges はどちらも バルクパス)。

何が変わったのか

  • ドキュメント (グラフィティ): https://github.com/getzep/graphiti/pull/1476 の @prasmussen15 による古い add_episode_bulk エッジ無効化/日付抽出メモを削除
  • https://github.com/getzep/graphiti/pull/1473 の @dependabot[bot] による 4 つの更新を使用して、UV グループを 2 つのディレクトリにバンプします
  • 修正(docker): https://github.com/getzep/graphiti/pull/1462 の @fengfeng-zi によって FalkorDB ボリュームを実際のデータ パスにマウント
  • 修正: https://github.com/getzep/graphiti/pull/1461 の @fengfeng-zi による Docker イメージに MCP プロバイダー エクストラをインストールする
  • フォワードポート: 属性幻覚ガード、複合抽出精度、https://github.com/getzep/graphiti/pull/1498 の @prasmussen15 による物語のエピソード時間ウォーターマーク
  • https://github.com/getzep/graphiti/pull/1499 の @prasmussen15 によってグラファイトコア バージョンを 0.29.1 にバンプ
