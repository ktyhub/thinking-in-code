graphiti v0.29.0

#グラフィティv0.29.0

Release Notes — グラファイトコア 0.29.0

概要

0.29.0 は、取り込みを大幅に安価にし、検索パイプラインを進化しやすくすることに重点を置いた 2 つのリリースのうちの最初のリリースです。見出しが変わります:

より安価な摂取。新しいノード + エッジ抽出パスの組み合わせにより、以前は 2 回かかっていた作業を 1 回の LLM 呼び出しでカバーできるようになり、ノード/エッジ抽出で複数のエピソードを 1 つのプロンプトにまとめて実行できるようになりました。タイムスタンプ解決 (valid_at / valid_at) も独自のステップに分割されているため、構造的事実の抽出と競合しません。 検索パイプラインのやり直し。 graphiti_core/search/search.py​​ の大規模な内部再構成により、今後の検索およびリランカーの変更の基礎が築かれます。公開されている API の変更はありませんが、トレース範囲は大幅に改善されています。 新しい物語の抽象化。 Graphiti の summary_saga(saga_id) API は、SagaNode と更新されたプロンプトをサポートしており、複数のエピソードの物語をまとめる最高の方法を提供します。 生活の質。エピソード タイプのact_triple、フィルタリング用のepisode_metadata、ファーストクラスのフィールドを破壊しない安全な属性マージ、および外部 DB を使用せずに埋め込み FalkorDB に対して実行するポッドキャスト サンプル。 これが開発者に与える影響

デフォルトは変更されません。結合抽出は、extract_nodes_and_edges_bulk で use_combined_extraction=True によってオプトインされます。既存の取り込みコードはそのまま機能し続けます。 エピソード インデックスは 0 から始まるようになりました。 [エピソード N] ヘッダーを解析する場合、または抽出結果からのエピソードインデックスに依存する場合は、それに応じてオフセットを更新してください。 Kuzu ユーザー — スキーマの移行が必要です。 RelatesToNode_ は、reference_time TIMESTAMP 列を期待するようになりました。新しいデータベースはそれを自動的に取得します。既存のストアには、1 回限りの ALTER TABLE RelatesToNode_ ADD Reference_time TIMESTAMP が必要です。 カスタム属性をより安全に設定できるようになりました。ノード/エッジの属性辞書は、ファーストクラスのフィールド (uuid、group_id、created_at、timestamps) を上書きしなくなりました。その上書き動作に依存している場合は、これらのフィールドを直接設定する必要があります。 知っておくべき新しい公開サーフェス: Graphiti.summarize_saga(saga_id)、fact_triple エピソード タイプ、およびカスタム フィルター キー用の EpisodicNode.episode_metadata。 ハイライト

効率: 取り込み中の LLM 呼び出しが減り、よりスマートになります。

ノード + エッジ抽出の組み合わせ (特徴フラグ付き)。単一の LLM 呼び出しで、エピソードのノードとエッジの両方を生成できるようになりました。 use_combined_extraction=True を extract_nodes_and_edges_bulk に渡してオプトインします。デフォルトの動作は変更されません。新しいプロンプト/extract_nodes_and_edges.py および utils/maintenance/combined_extraction.py によってサポートされています。 複数のエピソードのバッチ抽出。 _extract_and_resolve_nodes と extract_edges はエピソードのリストを受け入れ、[エピソード N] ヘッダー (新しい concatenate_episodes ヘルパー) を含む共有プロンプトを構築し、抽出された各ノード/エッジにエピソードインデックスを添付して、呼び出し元が結果をソース エピソードにマッピングできるようになりました。 分離されたタイムスタンプ解決。新しい extract_timestamps / extract_timestamps_batch プロンプトにより、valid_at / valid_at が専用の抽出後のステップで解決されるため、構造的事実の抽出が日付解析と絡まることはなくなりました。 建築

検索パイプラインのやり直し。 graphiti_core/search/search.py​​ の大規模な再構成 (約 1,000 行の変更) と新しいトレース テスト カバレッジにより、今後の検索/リランカーの変更への道が開かれます。 サガ。 Graphiti の新しい summary_saga(saga_id) API に加えて、更新された summary_saga プロンプトとサポート ヘルパー (saga_get_previous_episode_uuid、saga_get_episode_contents)。 顧客定義のフィルタリング キー用の、fact_triple エピソード タイプと EpisodicNode のepisode_metadata dict。 エッジとノードでのより安全な属性マージ — 属性辞書に偶然一致するキーが含まれている場合、ファーストクラス フィールド (uuid、group_id、created_at、timestamps) が上書きされなくなりました。 Reference_time は一括エッジ保存によって保存され、Kuzu RelatesToNode スキーマの列として追加されます。既存の Kuzu ユーザーは、1 回限りの ALTER TABLE RelatesToNode ADD Reference_time TIMESTAMP が必要になる場合があります。 迅速な改善

重複排除 (ノードとエッジ): 範囲が厳しくなり、結合された抽出パスにおける 2 つのエンティティ ルールが緩和されます。 ファクト抽出: 詳細保持ルール、修飾されたオブジェクトの広範なエンティティのキ​​ャプチャ。 summary_sagas プロンプトを更新しました。 事例・DX

Examples/podcast/podcast_runner.py は、外部データベースを使用せずに埋め込み FalkorDB (falkordblite) に対して実行されるようになり、取り込み後のエッジ + ノードのハイブリッド検索を実行します。 注目すべき内部変更

ドライバーはgraph_operations.pyとrecord_parsers.pyで調整されました。 エピソードのインデックス付けは 0 ベースになりました (マルチエピソード抽出の最初の反復では 1 ベースでした)。 pytest は、server/ および mcp_server/ で 9.0.3 にバンプされました。 ロックファイルと依存関係の更新 (uv グループ、voyageai、groq、google-genai、uvicorn、pyright、pytest-asyncio)。 次に来る

次のリリースでは、このアーキテクチャのトラックが継続されます。複合抽出パスがデフォルトの取り込みモード、エッジ解像度と重複除去にわたる追加のバッチ処理、そしてここでの再作業に基づいて構築される後続の検索パイプラインの変更に向けて段階的に移行することが予想されます。
