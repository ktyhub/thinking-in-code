リスク評価 (影響順)

  1. 0.23 シリーズの最初の PyPI 出版物には、以前の移行要件が含まれています

    • リスク: 以前にレビューした移行パスでは **🟢 低 **。 0.22.3 からアップグレードするユーザーには、このパッチだけでなく 0.23.0 の動作変更も適用されます。
    • 証拠: PyPI には 0.23.0 も 0.23.1 もありません。 #5226 の 0.23.0 リリース評価では、厳密なツール、承認の復元、暗号化された履歴、リソースの制限、音声のデフォルト、プロバイダーの変更がカバーされています。この候補はそれらのランタイム パスを変更しません。
    • ファイル: CHANGELOG.md、src/agents/version.py; #5226 で評価された未変更の 0.23.0 ランタイム コントラクト。
    • アクション: 0.23.1 発表の 0.23.0 移行ガイダンス、特に明示的な厳密ツール パラメーター、新しいレガシー承認、trust 暗号化履歴インポート、リソース制限オーバーライド、および明示的な以前の音声モデル オーバーライドを継続します。

  2. パッケージの動作を変更せずにリリース チェックが回復します

    • リスク: 🟢 低。テストループの初期化と必須チェックの所有権は修正されますが、パブリケーションの承認はそのまま残ります。
    • 証拠: OS モックはイベント ループの初期化後にインストールされ、破棄前に復元されます。承認されたレビュー イベントは、現在の PR トリガーの準備状況チェックを置き換えたりキャンセルしたりするのではなく、再実行します。ソース検証、ネイティブ人間による承認、分離ビルド、OIDC パブリッシュは変更されません。
    • ファイル: tests/sandbox/test_unix_local_user_file_io.py、.github/scripts/release_automation.py、.github/workflows/release-readiness-refresh.yml、.github/workflows/release-readiness.yml。
    • アクション: 正確な人間による承認を送信し、更新の準備を許可し、通常の保護を通じてマージし、発行者とアップロードされた出所を確認します。

  3. 外部プロバイダーの適用には明示的な保守者の意図が必要になりました

    • リスク: 既存のオプトイン パスでは **🟢 低 **。デフォルトの統合と自動サンプルの実行では、影響を受ける外部プロバイダーのケースが暗黙的に選択されなくなりました。
  • 証拠: 統合ブートストラップは、継承された有効フラグをリセットし、リストされた外部プロバイダーの資格情報をデフォルトで削除し、オプトインなしの外部モデルのオーバーライドを拒否します。外部ケースはデフォルトでは選択解除されています。自動の例では、拡張されたスキップ リストを使用します。サンプルの手動選択は引き続き利用できます。
    • ファイル: .github/scripts/run_integration_tests.py、integration_tests/conftest.py、Makefile、examples/run_examples.py、integration_tests/README.md。
    • 処置: 直接プロバイダーのカバレッジが目的の場合は、make integration-tests-providers-external を使用し、-- --all を追加します。デフォルトのカバレッジを外部プロバイダーの検証として解釈しないでください。
