#ネットデータv2.10.4

#Release notes

Netdata v2.10.4 は、v2.10.3 以降に発見された問題に対処するパッチ リリースです。

これは、データベース エンジン、ストリーミング、クラウド接続、コレクター全体にわたる安定性、メモリの安全性、クラッシュ耐性に焦点を当てた、通常よりも大規模なパッチ リリースです。また、新しい macOS ハードウェア センサー コレクターを 2.10.x ラインにバックポートします。

このリリースの新機能

  • macOS ハードウェア センサー コレクター: GPU 電力、クロック、温度、SMC および IOHID センサーとファン、電源と熱圧力、NVMe SMART、ndsudo 経由の powermetrics フォールバック、さらにクロス OS sensors 関数と共有温度ヒストグラム コンテキスト (#22475、#23085、 @ktsaou)
  • macOS 上の apps.plugin の境界カーディナリティ プロセス グループ化により、プロセス チャーンが高いホスト上でプロセスごとの監視を意味のあるものに保ちます (#23085、@ktsaou)

データベース エンジンとメタデータ

  • 破損または切り捨てられたデータ ファイルに対する DBENGINE の強化: エクステント ディスク サイズと非圧縮ページ境界の検証、v2 ジャーナル ウォークでの SIGBUS 保護とヘッダー オフセット境界チェック、ジャーナル ファイル アクセス エラー処理の改善、データファイル/ジャーナル デッドロック診断のスピンロック ホルダー識別 (#22324、#22514、 #22310、#22725、@stelfrag #22666、@jmestwa-coder;
  • pgc_page_add および pgc_queue_del でのページ キャッシュの競合、ディメンション作成時のデッドロック、および仮想ノードの引き継ぎ時のクラッシュを修正しました (#22466、#22400、#22417、@stelfrag)
  • 破損したデータベースでのクラッシュを防ぐために SQLite からロードされたデータを検証し、SQLite 関数での UUID 処理とエラー報告を改善しました (#22679、#22233、@stelfrag)
  • ホストがアーカイブされている間、割り当てられたチャート インデックスを維持し、チャート ルックアップでの null ルート インデックスから保護し、クエリ中の null 逆参照を回避します (#23074、#23056、@stelfrag)
  • 非 dbengine ホストでの rrdcontext メタデータ リークを修正しました (#22438、@stelfrag)
  • アクティブなデータファイルをローテーションし、リカバリ不能な書き込みエラーが発生した場合に保留中のエクステントをキューに再登録したため、ディスク障害によってデータベース エンジンが停止することがなくなりました (#23048、@ktsaou)

ストリーミングとレプリケーション

  • レプリケーション クエリのメモリ割り当てサイズを追跡および考慮し、古いチャートでの送信側レプリケーション カウンター リークを修正しました (#22756、#22428、@stelfrag)
  • 特大の ZSTD フレームを拒否し、解凍エラーを適切に処理しました (fatal() の代わりに接続をログに記録して失敗します) (#22830、@stelfrag)
  • 子が切断したときにストリーミング受信機が配信済みのデータを破棄する問題を修正しました (#23118、@ktsaou)

クラウド接続 (ACLK)

  • クラウド接続ループでまれに発生する無制限の 1 コア CPU スピンを防止し、パブリッシュ失敗時に初期化されていない packet_id が返されることを回避しました (#22879、@ktsaou; #22504、@stelfrag)

アラートと機械学習

  • スタックした通知スクリプトが進行をブロックできないようにアラート通知の実行待機を制限し、データベースからアラート情報を復元する際のシャットダウン競合を修正しました (#22626、#22448、@stelfrag)
  • ML データベースの破損に対する保護手段を追加し、回復プロセスを合理化しました (#22478、@stelfrag)

コレクター

  • クエリ後の systemd-journal.plugin メモリ保持とその apps.plugin アカウンティングを修正しました (#23089、@ktsaou)
  • apps.plugin (nfds モニタリングの追加) および eBPF FD PID マップ反復 (#22447、@arch-yunus; #22436、@stelfrag) でのファイル記述子のアカウンティングを修正しました。
  • プラットフォーム コレクターのバッファ オーバーフローとカウンター サイズの問題を修正しました。macOS mach_smi のスタック バッファ オーバーフロー、FreeBSD のカウンター サイズの不一致と freebsd_ipfw とクレーム コードのオフバイ 1、および低いシステム稼働時間での freeipmi.plugin ウォッチドッグ アンダーフロー (#22553、@artem; #23044、@DavidMarec、#22710、@vkalintiris、#22490、@ktsaou;
  • より厳密なサイズチェック、より安全な XML 解析、および堅牢なバリアント処理により、Windows イベントの行レンダリングのクラッシュが修正されました (#22872、@ktsaou)
  • NVIDIA ドライバー 580 XML 出力バリアント (#23047、@copilot-swe-agent) を使用した go.d/nvidia_smi での安定した温度と電力収集を復元しました。
  • Windows ハードウェア検出を修正し、仮想マシンがベア メタルとして報告されなくなるようにしました (#22942、@thiagoftsm) -fail2ban ソケット パスを go.d/fail2ban の ndsudo に移動しました (#22745、@ilyam8)
  • アクティブなコレクターとの pluginsd クリーンアップ競合を修正し、pluginsd パーサーにスロット境界チェックを追加し、ディスクスペース プラグインの低速ワーカーの前にマウントポイントの状態を初期化しました (#22207、#22598、#22298、@stelfrag)

セキュリティと API

  • /api/v3/settings エンドポイントは、HTTP_ACL_NOCHECK ではなく HTTP_ACL_DASHBOARD の背後でゲートされるようになり、接続許可リストが適用され、匿名の状態変更リクエストがブロックされます (#22896、@stelfrag)
  • label-quotes が渡されたときに無効な JSON を出力する csvjsonarray 出力形式を修正しました (#23115、@ktsaou)

コアの安定性とメモリの安全性

  • 内部競合条件の修正: dictionary_destroy() の TOCTOU レース、ARAL アロケーター レース、およびダブルフリー (#22108、#22212、#22294、#22367、@stelfrag)
  • ペイロードのメモリ リーク、JSON オブジェクトの検証と Null キーの処理、simple_pattern の反転空バッファ ガードを修正し、同時致命的なエラーによる最初のバッファのマスク (#22492、#22309、#22326、 #22671、@stelfrag、#22688、@vkalintiris)
  • Coverity および Sonar 監査によって明らかになったメモリの安全性と正確性のバグを修正しました (#22266、#22267、#22268、#22270、#22279、 #22281、#22329、#22330、#22331、#22332、#22333、 #22334、#22335、#22336、#22338、#22339、#22340、 #22835、@stelfrag、#22293、@ktsaou;
  • シャットダウンの堅牢性の向上: ctx_hosts_load の SIGSEGV と ENOENT ケースのパイプ クリーンアップ処理を修正しました (#22419、#22509、@stelfrag)

インストールとパッケージ化

  • Windows: MSI インストーラーの問題を修正し、トークンとルームの両方が提供された場合にのみ要求を実行するようにインストーラーを調整し (より安全なワイド文字処理と上限付き HTTP 要求応答サイズを使用)、複数のバージョンをチェックする Visual Studio ツールの検索を修正しました (#22751、#22754、@thiagoftsm; #22723、@フェロイン)
  • ファイルをフェッチするときの netdata-updater のエラー処理を改善し、curl 出力を沈黙させました (#22422、@Ferroin; #22639、@AJCxZ0)

サポート オプション <a id="v2104-support-options"></a>

当社は成長するにつれて、オープンソース ソリューションを通じてこれまでにない最高のサポートを提供することに尽力し続けます。このリリースで行われた変更または Netdata Agent の機能で問題が発生した場合は、次のいずれかのチャネルを通じてお気軽にお問い合わせください。

  • Netdata Learn: Netdata を使用してシステムを監視およびトラブルシューティングするためのドキュメント、ガイド、参考資料を検索します。
  • GitHub の問題: Netdata リポジトリを利用して、バグを報告したり、新しい機能のリクエストをオープンしたりします。
  • GitHub ディスカッション: Netdata 開発プロセスに関する会話に参加して、参加してください。
  • コミュニティ フォーラム: コミュニティ フォーラムにアクセスし、共同知識ベースに貢献してください。
  • Discord サーバー: Netdata Discord に参加して、志を同じくするシステム管理者、DevOps、SRE、その他のトラブルシューティング担当者と交流しましょう。すでに 2,000 人以上のエンジニアが使用しています。
