#ネットデータv2.12.3

#Release notes

Netdata v2.12.3 は、v2.12.2 以降に発見された問題に対処するパッチ リリースです。

このリリースでは、トラフィックが流れ続けている場合でもエージェントが無効な Netdata クラウド接続を検出できるようになり、子またはプラグインがまだ使用している間に古いノードが削除された場合の use-after-free クラッシュを修正し、parent using h2o で構成された子がすべての接続でクラッシュするのを停止し、アクセス リスト内の否定された IP がホスト名一致よりも優先され、URL 内の不正なパーセント エスケープを拒否し、MCP バッチ リクエストを制限し、グローバル SQLite ストールを削除し、廃止された場合のクラッシュを修正します。チャートは読み取り中にクリーンアップされ、dbengine 層を作成できない場合に起動時にエージェントがハングアップしないようにします。 ram または alloc ストレージ モードを使用している親がギャップ後に子の履歴をシフトしたり、マルチノード メトリック相関でクラッシュしたりしないようにします。 コレクターがレポートを停止したときに SNMP およびその他の仮想ノードを再びオフラインにします。 PowerStore チャートにゼロの代わりにアレイがレポートする値を表示させます。 eBPF を実行します。プラグインは、昇格した特権で実行する場合、環境からのディレクトリ オーバーライドを無視し、エージェントが実際にロードした設定ファイルからホスト ラベルを再ロードします。

ストリーミングとネットデータのクラウド

  • クラウド接続の MQTT キープアライブを修正しました。接続がアイドル状態のときにのみチェックされるため、安定した受信トラフィックがあるリンクでは応答のない ping に気付かず、無期限に停止したままになる可能性があります。 ping と確認応答の期限も実時計に従うため、クロック ステップによって誤った ping タイムアウトや検出の遅延が発生し、RTC 確認応答のないボードでは最初の NTP 同期の前にタイムアウトになることはありませんでした。デッドラインでは単調クロックが使用されるようになり、応答のない ping の 60 秒後に切断された接続が検出されます (#24427、@stelfrag)
  • Netdata Cloud 用のエージェントの HTTPS client は、チャンク化された応答のチャンク サイズを厳密にチェックし、そのような応答の上限を 1 MiB に制限するようになりました。チャンク サイズが不正であるか非常に大きい場合、メモリの割り当て中にエージェントが終了する可能性があります (#24483、@stelfrag)
  • netdatacli remove-stale-node または孤立ホストおよび一時ホストのクリーンアップによって、再接続する子または仮想ノードとして選択されたプラグインによって、まだ使用されているホストが削除された場合の解放後の使用クラッシュを修正しました。削除中に再接続する子は再試行を求められるようになり、プラグインによって選択された仮想ノードはオンラインとして報告され、放置されるようになります (#24353、@stelfrag)
  • [stream] parent using h2o オプションを削除しました。 h2o Web サーバーは v2.7.0 で削除され、v2.8.0 以降、このオプションが有効になっている子は、親に接続しようとするたびにクラッシュしました。依然として設定されている stream.conf は受け入れられ、オプションは無視されます (#24426、@stelfrag)

Web サーバーと API

  • アクセス リスト: IP が否定されたエントリ (allow connections from = !203.0.113.7 * の !203.0.113.7 など) に一致する client は、ホスト名がリストと照合されずに拒否されるようになりました。これは、ワイルドカード (#24404、@ArjunD3456) を含むリストのデフォルトの heuristic モードを含む、DNS チェックが有効になっている場合の netdata.conf のすべてのアクセス リストに適用されます。
  • 不正なパーセント エスケープを含む URL は HTTP 400 で拒否されるようになりました。% の後に 2 つの 16 進数が続く必要がありましたがチェックされず、デコードに失敗した URL はそれまでにデコードされた部分を使用して提供されたため、/api/v1/info%zz は /api/v1/info として応答されました。 ?x=100% など、後に 2 つの 16 進数字が続かないリテラル % を含むリクエストは、400 を取得するようになりました (#24248, @stelfrag)
  • MCP API キーと管理 API キーが一定時間で比較されるようになったため、応答のタイミングによって推測されたキーがどの程度近いかが明らかにならなくなりました (#24418、@ArjunD3456)
  • MCP: JSON-RPC バッチは 64 リクエストと 16 MiB のレスポンスに制限され、WebSocket メッセージは HTTP リクエストと同じ 1 MiB に制限されます。 ID が文字列、数値、または null ではないリクエストは拒否されます (#24425、@stelfrag)
  • X-Forwarded-For: エージェントは、ヘッダーの最初のアドレスのみを、それが有効な IPv4 または IPv6 アドレスである場合にのみ保持するようになりました。これは、アクセス ログおよび動的構成変更の監査エントリに示される、転送された client アドレスです。 unknown などの他の値は削除されます (#24452、@ArjunD3456)
  • レジストリ: netdata_registry_id ID は、クエリ文字列などのリクエスト内の他の場所からではなく、Cookie ヘッダーからのみ読み取られるようになりました。これは、レジストリが有効になっているエージェントのみに影響します。レジストリはデフォルトではオフになっています (#24494、@ArjunD3456)
  • クレーム: 間違ったキーを使用した /api/v2/claim または /api/v3/claim へのリクエストによって、クレーム チャレンジが再生成されなくなりました。そのため、管理者が行っているクレームを中断することはできません。チャレンジは起動時と有効なキー (#24531、@stelfrag) を使用した要求の後でも再生成されます。

データベース

  • エージェント全体で SQLite が停止する問題を修正しました。 SQLite 呼び出しの周りにグローバル ロックが保持されていたため、1 つの遅いステートメントによって、同じデータベース接続 (#24099、@stelfrag) を使用するスレッドだけでなく、SQLite を使用するすべてのスレッドがブロックされました。

  • エージェントの実行中に発生するメタデータ データベースの破損は、クリーン シャットダウン時のみまたはクラッシュ後ではなく、最初のクエリ失敗時に回復対象としてマークされるようになりました。 SQLite クエリ統計では、後に失敗したクエリとして成功したビジー再試行がカウントされなくなりました (#24225、@stelfrag)

  • ram または alloc ストレージ モードを使用している親は、ギャップの後に子のストリーミングおよびレプリケートされた履歴をシフトしなくなりました。すべてのギャップにより、すべての古い値が 1 間隔前に移動され、保持期間が 1 間隔分誇張されました (#24434、@stelfrag)

  • dbengine は、書き込んだ正確な名前を持つデータファイルのみをロードするようになりました。 datafile-1-0000000001.ndf.bak などのコピーが実際のファイルと一緒に 2 度目にロードされ、存在しない datafile-2-*.ndf が起動時にエージェントを停止しました。他の名前は不明なファイルとして報告され、スキップされるようになりました (#24436、@stelfrag)

  • ヘルス変数ルックアップ、Prometheus エクスポート、アラートおよびコンテキスト API リクエストまたはクエリがまだチャートを読み取っている間に、古いチャートのクリーンアップによってチャートまたはそのラベルが解放されたときのクラッシュを修正しました。これらには、巨大なサイズの割り当てで終了するエージェント (#24466、#24474、@stelfrag) が含まれます。

  • dbengine: 層のディレクトリを作成できない場合、または初期化スレッドを開始できない場合に、エージェントが起動時にハングしなくなりました。層 0 より上の層が欠落していると、エージェントはその下の層で実行されたままとなり、層 0 が欠落しているとエラーで起動が停止します (#24435、@stelfrag)

クエリ

  • ram または alloc ストレージ モードを使用する親など、dbengine 層のないエージェント上の 2 つ以上のノードにわたるメトリック相関およびその他の重みクエリのクラッシュを修正しました。このようなエージェントはノードを一度に 1 つずつ処理するようになりました (#24433、@stelfrag)
  • クエリ応答の summary.nodes[] セクションには、欠落していた最後のノードのクエリ時間が含まれるようになりました。 options=percentage では、寸法ビューの異常率が水増しされなくなりました。 /api/v1/data の chart_labels 配列には、次元ごとに 1 つのエントリが含まれるようになりました。null では、チャートにラベル (#24460、#24474、@stelfrag) がありません。

機械学習

  • [ml] dimension anomaly score threshold は 0.01 から 1.00 に制限され、設定値が変更されるとログに警告が記録されます。 5.00 までの値は受け入れられましたが、モデルの異常スコアが 100 を超えることができないため、1.00 を超える値は異常検出を自動的にオフにしました。そのような値は、最も感度の低い設定である 1.00 で実行されるようになりました (#24499、@stelfrag)

コレクター

  • ebpf.plugin および ebpf-go.plugin は setuid root にインストールされます。昇格した特権で実行すると、NETDATA_*_DIR 環境変数を無視し、構築時に使用したプラグイン、構成、およびログ ディレクトリを使用するようになりました。標準インストールは影響を受けません。これらのディレクトリを別の場所に指定する netdata.conf の [directories] オーバーライドは、無視される変数ごとに 1 行のログを記録する eBPF プラグインに到達しなくなります (#24412、@stelfrag)
  • Redfish: 標準として公開されているマネージャー ネットワーク ポート リンク状態や速度を含むポート リソースが収集されるようになりました。それらは拒否され、コレクションは永久に部分的に残されました (#24270、@ilyam8)
  • PAN-OS: panos.ipsec.tunnels は、設定された IPsec トンネルを報告するのではなく、確立された IPsec トンネルをカウントするようになり、キーの再生成中に SA が重複するトンネルは 1 回カウントされます。残りの SA ライフタイムは、変動値または合計値ではなく、トンネルの最長有効ライフタイムを報告するようになりました (#24385、@macmandr197)
  • go.d.plugin: ホストのアイデンティティが同じままでメタデータが変更された場合、Cato Networks などのコレクターがホスト スコープの競合で収集サイクルに失敗する問題を修正しました (#24415、@ktsaou)
  • Cato Networks: トポロジー機能は、各サイトをそのデバイスに接続し、並列の WAN トンネルを結合するのではなく、観察されたすべての WAN トンネルを維持し、トンネルを接続済み、切断済み、または不明としてマークします。サイト、デバイス、トンネルには、HA の役割、損失、ジッター、ラストマイル測定、BGP セッションなどのトラブルシューティングのための詳細情報が含まれており、インベントリ、メトリック、または BGP データが欠落している場合はグラフにメモされます。コレクターは現在、Cato SDK v1.1.0 (#24413、@ktsaou、#24362、@ilyam8) を使用しています。
  • ebpf.plugin: ebpf.monitoring_pid で追跡される PID の数が、有効期間の短いプロセスを持つホスト上で増加し続けることがなくなりました。 /proc エントリが読み取られる前に終了したプロセスは、減算されずに解放されました (#24423、@stelfrag)
  • statsd.plugin: [statsd] set charts as obsolete after を有効にすると (デフォルトではオフ)、アイドル状態のメトリックが初めて削除されたときにエージェントがクラッシュしなくなりました。また、削除によってメトリクスの値が漏洩することはなくなり、合成チャートで使用されるメトリクスは保持されます。プライベート チャートの数がラップアラウンドしなくなり、すべての新しいプライベート チャートがブロックされなくなりました (#24440、@stelfrag)
  • 仮想ノード: SNMP デバイスが使用するようなコレクターによって設定された非アクティブ タイムアウトが再び機能します。これはノードの定義時に破棄されるため、コレクターが仮想ノードの報告を停止した後も仮想ノードがオフラインになることはありません。仮想ノードのストリーミング コピーが停止した後、ローカル コレクターによって再び引き継がれた仮想ノードは、ヘルス チェックと通常の動作を復元しました (#24495、@ilyam8)
  • SNMP: デバイスが要求に応答しなかった場合のポーリングは失敗するようになりました。キャッシュされたメタデータから構築されたプロファイル統計は、デバイスの仮想ノードに関して引き続きレポートされ、測定が停止した後もアクティブなままでした (#24497、@ilyam8)
  • PowerStore: パフォーマンス、イーサネット、および容量のグラフに、アレイが報告する値が表示されるようになりました。コレクターは生のサンプルのフィールド名を読み取りますが、要求する 5 分ロールアップと毎日のロールアップでは異なる名前が使用されるため、これらのチャートにはゼロが表示されるか欠落しています。 CPU は間隔のピーク使用率をパーセンテージで表示し、平均ログイン数はその端数を維持するようになりました (#24448、@ilyam8)
  • log2journal: バックスラッシュ エスケープ内で終了する JSON 行は、行末以降のバイトで解析されるのではなく、拒否されるようになりました (#24365、@ArjunD3456)
  • log2journal: オプションのグループなど、一致に関与しない PCRE2 パターンまたは書き換えルールの名前付きグループでは、パーサーがバッファーの 1 バイト前を読み取ることがなくなりました。出力は変更されません (#24380、@ArjunD3456)
  • log2journal: JSON の解析と出力に関するいくつかの問題を修正しました。指数を含む非常に長い数値は数値バッファーをオーバーフローしたり、プロセスをクラッシュさせる可能性があり、\u000a および \u0009 エスケープは値の残りを削除し、ペアになっていないサロゲートは無効な UTF-8 を生成し、JSON モードと logfmt モードの両方で、解析に失敗した行はそのフィールドを次の行に残します。 --inject は、ログに追加されるのではなくログから読み取られた値を置き換え、独自のキーを参照する書き換えにより元の値が読み取られるようになりました (#24443、@stelfrag)
  • go.d.plugin: ジョブ マネージャーでの 2 つのシャットダウン レースを修正しました。シャットダウンまたは失敗した再起動は、終了せずに期限まで待機する可能性があり、プラグインが停止しているため、すでに受け入れられた関数リクエストが拒否されたと報告される可能性がありました (#24491、@ilyam8)
  • go.d.plugin サービス検出: 検出された名前とアドレスは、検出ルールが生成するジョブ内のデータとしてエンコードされるようになりました。これらはテキストとして YAML に挿入されるため、IPv6 アドレスによりジョブの解析が失敗し、on などの名前がブール値になる可能性があります。ストック ルールは新しい job テンプレート ヘルパー ({{ job "name" .Name "url" .Address }} など) を使用します。これはカスタム ルールでも使用できます。既存のルールと保存された動的構成は引き続き機能します (#24469、@ilyam8)
  • go.d.plugin: コレクターのログとエラー (動的構成チェックによって返されたものを含む) には、コレクターが読み取るファイルの生のコンテンツ (ログ サンプル、構成行、証明書など) が含まれなくなりました。代わりにファイル、行、フィールド、および理由に名前を付けるため、一部のメッセージの詳細はあまり詳しくありません (#24496、@ilyam8)
  • go.d.plugin および ibm.d.plugin: Prometheus および OpenMetrics エンドポイントを含むコレクターによって読み取られる HTTP 応答は、gzip 解凍後に測定されて 64 MiB に制限されるようになりました。応答が大きくなると、メモリが無制限に増加するのではなく、収集が失敗します。 HTTPCheck は、そのような応答を bad_content として報告します。ヘルスチェックにはより小さいエンドポイントを使用します (#24490、@ilyam8)
  • SNMP トラップと S3: これらのコレクターが保持する状態ファイルは、安全に読み書きできるようになりました。シンボリックリンクと特殊ファイルが拒否され、クラッシュによって残された一時ファイルによってその後の書き込みがブロックされなくなりました (#24462、@ilyam8)
  • 株式アラートとメタデータの問題を修正しました。Portcheck portcheck_connection_fails アラートは存在しないディメンションを検索しなくなり、Elasticsearch、OpenSearch、および Unbound メタデータは説明されているチャートと一致するようになり、Unbound および ethtool モジュール チャートのタイトルは「CollectorV1 ...」ではなく再び「Module ...」になりました (#24308、 @ilyam8)

関数

  • 進捗関数は、サーバー エラーで失敗した API 呼び出しをエラーとして表示するようになりました。これらはダッシュボードが認識できない重大度でスタイル設定されており、成功した呼び出しのように見えました (#24185、@ilyam8)

エージェント

  • ホスト ラベルは、起動時および netdatacli reload-labels で、エージェントがロードした構成ファイル (-c で指定されたファイルを含む) から読み取られるようになりました。そのファイルから削除されたラベルは、リロード時にも削除されます (#24117、@stelfrag)
  • クラッシュ レポートには、エージェント自身の致命的なエラー処理の外で発生した SIGABRT のスタック トレースが含まれるようになりました (#24094、@stelfrag)
  • macOS および Linux で libbacktrace なしでビルドすると、エージェントはクラッシュ時にステータス ファイルを再度保存するため、次回の起動時に終了理由とシグナルが報告されます (#24345、@stelfrag)
  • アーカイブされた子を持つ親のコンテキストの読み込みがシャットダウンの待機時間を超えた場合の、シャットダウン時の解放後の使用を修正しました (#24492、@stelfrag)
  • 複数のスレッドが同時に同じリミッターを介してログを記録した場合、レート制限されたログ メッセージが制限よりも頻繁に出力される問題を修正しました (#24249、@stelfrag)
  • [db] update every が 3600 を超える場合、警告は 1 ではなく (3600) にクランプされた値を報告するようになりました。クランプ自体はすでに正しいものでした (#24378、@stelfrag)
  • コレクターが ID なしでディメンションを追加しようとすると、チャートのディメンション インデックスの破壊を非難するのではなく、致命的エラーがそのことを示すようになりました (#24528、@stelfrag)

インストールとパッケージ化

  • インストーラーとアップデーターは、一部のcurlバージョンがプロトコルエラーで返すcurl終了ステータス56を、終了ステータス22や78(#24276、@Ferroin)と同様にダウンロード失敗として扱うようになりました。
  • Windows パッケージには、バンドルされた MSYS2 ベースに加えて、OpenSSL 3.6.5、curl 8.23.0、msys2-runtime 3.6.11 などの更新された MSYS2 パッケージが含まれるようになりました。各アップデートは URL とチェックサムによって固定され、バンドルされたパッケージ データベースは出荷されるファイル (#24473、@stelfrag) と一致します。
  • ソースからのビルドに Go ツールチェーンが必要で、何もインストールされていない場合、インストーラーは 1.27.0 ではなく Go 1.27.3 をダウンロードするようになりました。 Go 1.27.0 以降は引き続きサポートされます (#24411、@ilyam8)

謝辞 <a id="v2123-acknowledgments"></a>

この素晴らしいコミュニティを構成する献身的で才能ある貢献者に感謝したいと思います。時間と専門知識 皆様のボランティア活動が私たちの成功に不可欠です。

  • @ArjunD3456 は、MCP を比較するために、アクセス リスト内の否定された IP をホスト名一致よりも優先させます。 JSON エスケープおよび一致しない PCRE2 グループで log2journal がそのバッファを超えて読み込むのを停止し、締め付けを行うために、一定時間で API キーを管理します。 X-Forwarded-For ヘッダーとレジストリ Cookie がどのように読み取られるか。
  • @macmandr197 PAN-OS IPsec トンネル数とキー再生成の有効期間を修正します。
