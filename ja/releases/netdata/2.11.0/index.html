リリース概要 <a id="v2110-release-summary"></a>

Netdata は常に、ある特定の点で非常に優れています。それは、構成を必要とせずに、1 秒ごとに、 マシンの内部で何が起こっているのか。 v2.11.0 はそれを境界としないリリースです。

ここでは 2 つのことが起こり、それらが合わさって Netdata の「ありよう」が変わります。

まず、Netdata がネットワークを学習します。 新しい ネットワーク モニター ダッシュボードにより、デバイス インベントリ、メトリクス、トポロジ、 流れ、トラップ、アラートを 1 か所に集めます。その背後では、ネットワーク フロー がルーターから NetFlow、IPFIX、および sFlow を受信します。 スイッチとファイアウォールを使用して、生の記録を誰が誰と話しているのかを多面的に把握できるビューに変換します。 ネットワーク トポロジ ウォーク デバイスを SNMP 経由で接続し、レイヤー 2 およびレイヤー 3 マップ (LLDP ネイバー、転送データベース、OSPF および BGP) を描画します。 隣接関係 — アプリケーション依存関係マッピング はソフトウェアに対して同じことを行い、Linux ホストの カーネルを使用して、計測するものを何もせずに、各プロセス、コンテナー、および Kubernetes ワークロードが通信する内容をマッピングします。 SNMP トラップ リスナー は、Netdata をトラップ レシーバーにし、800 以上のベンダー プロファイルからのトラップをデコードします。 生の OID の代わりにグラフと読み取り可能なメッセージを表示します。すべてをフィードすると、SNMP デバイスのカバー範囲は 229 から 273 に増加しました プロフィール。通常の Netdata ルールが引き続き適用されます。プロファイルはすでに書き込まれており、収集と保存は独自に行われます。 インフラストラクチャに組み込まれており、デバイスの場所を Netdata に伝える以外に設定する必要はほとんどありません。ネットワークモニター、ネットワーク フローとネットワーク トポロジは テクニカル プレビュー として出荷されます。今日実行するのに十分な完成度があり、すべての Netdata ユーザーに公開されています プレビュー中も高速に動いています。

2 番目に重要ですが、ログはプラットフォームの第一級の柱になります。 このリリースでは OpenTelemetry が追加されます。 ログ — OTLP ログ レコードは、既に systemd ジャーナルを提供している同じ ログ タブから取り込まれ、保存され、クエリされます。 および Windows イベント、journald、filelog、syslog レシーバー、構成可能な保持、ログからメトリックへの変換 非構造化行の解析。より深い変更はアーキテクチャ上です。現在は同じファセット、高カーディナリティのログ エンジンです。 systemd ジャーナル、Windows イベント、OpenTelemetry ログ、SNMP トラップ、ネットワーク フロー を同様にバックアップします。まったく異なる5つの 信号タイプ、1 つのクエリ サーフェス、すべてが独自のインフラストラクチャに保存されます。

これら 2 つを中心に、このリリースでは、新しい AWS CloudWatch コレクター (これに相当するもの) を備えたメジャー クラウド セットが完成します。 v2.10.0 で追加された Azure Monitor コレクター — 実際の再ラベル付けエンジンを中心に Prometheus コレクター を再構築します アプリケーションプロファイルを使用します。そのすべての下には、これまでに出荷した中で最大の安定性とメモリ安全性への取り組みが組み込まれています。 単一リリース: データベース エンジン、ストリーミング、ACLK、ヘルス、ML、libnetdata にわたる 87 の増分部分。

非推奨の通知 <a id="v2110-deprecation-notice"></a>

このリリースでの変更点

  • Prometheus コレクターの label_prefix オプションは削除されました。新しいものを使用してください 【リラベルエンジン】(https://learn.netdata.cloud/docs/collecting-metrics/prometheus-metric-relabeling) 代わりに。 (#22668)
  • Go sensors コレクターが削除されました。 Linux ハードウェア センサーは、C libsensors モジュールによって収集されています。 v2.2.0 以降は debugfs.plugin なので、アクションは必要ありません。 (#23237)
  • Fedora 42 および openSUSE Leap 15.6 は、アップストリームのサポート終了に伴い、ビルドまたはテストされなくなりました。 (#22239、#22240)
  • systemd-journal.plugin は OpenTelemetry ジャーナルを検出しなくなりました。 otel-plugin がそのパスを所有するようになりました。 Otel ログ 以前と同様に引き続き収集およびクエリが実行されるため、アクションは必要ありません。 (#22572)
  • このリリースから、Netdata は RPM パッケージの生成に CPack の使用に移行し、RPM を導入しました。 これまでの DEB パッケージの扱い方に沿ったパッケージ生成。これは関連性があるだけである必要があります 既存の RPM パッケージ コードを使用して Netdata の独自の RPM パッケージを構築している人向け。古いRPM パッケージ化コードはこのリリース用に保持されていますが、私たちの製品では使用されません。
