netdata v2.11.1

#ネットデータv2.11.1

#Release notes

Netdata v2.11.1 は、v2.11.0 以降に発見された問題に対処するパッチ リリースです。

これは、クエリの正確性、データベース エンジンの安定性、クラウド接続の堅牢性、健全性/アラートの効率、シャットダウンとプロセス存続期間中の安全性に重点を置いた通常よりも大規模なパッチ リリースであり、SQL Server の対象範囲の拡大や Windows CPU とディスクの改善など、コレクタとプラットフォームの多数の修正も含まれています。

クエリエンジン

  • 保存されたポイントが結果行または自動ストレージ層境界にまたがる場合に正確な SUM 値が保存され、増分合計ベースラインが保存されるため、開始サンプルのみを保持するバケットは空のクエリを生成しなくなりました (#23512、#23505、@ktsaou)
  • API タイムスタンプを各エージェントの保持とは独立して保持するため、同じ明示的または相対リクエストはエージェント間で同じ行タイムスタンプを返します (#23507、@ktsaou)
  • Tier-0 RESET と異常証拠を、実際にソース サンプルを含む結果行に帰属させ、2 パス グループバイ クエリの異常率寄与者数を修正しました (#23504、#23508、@ktsaou)
  • 計画切り替え中に受信層からフェッチされたポイントに options=absolute を適用したため、負の値が変更されずに層遷移を通過できなくなりました (#23503、@ktsaou)
  • JSON ラッパーの論理演算子を修正し、すべてのディメンションが要求されない限り、クエリされていないディメンションが期待どおりに除外されるようにしました (#23639、@stelfrag)

データベース エンジン

  • ページの詳細を公開する前にページ キャッシュ参照を取得し、エクステント スピンロック下でマージ エクステント クエリのティアダウンを同期することにより、マージ エクステント クエリにおける use-after-free と致命的な問題を修正しました (#23475、#23521、@stelfrag)
  • ジャーナル v2 移行中の古い MRG メトリクスの二重解放と、シャットダウンまたはデータファイルのローテーションを無期限に待機させる可能性がある空のフラッシュ バッチ カウンター リークを修正しました (#23560、#23699、@stelfrag)
  • ネガティブおよびエポックベースの層保持レポートの防止: 期間のフォーマット時に 32 ビットの切り捨てなし、不明またはゼロの開始時刻は使用不可として扱われ、空のジャーナルは無視され、外挿された保持上限が設定されました (#23648、@stelfrag)
  • 1 日を超える有効なページ ケイデンスを無効として扱い、誤った修復テレメトリを発行するのではなく、受け入れました (#23514、@ktsaou)
  • MRG メトリック ルックアップ中の UUID マップの作成/解放チャーンとパーティション書き込みロックの競合を回避し、PGC 致命的メッセージに完全なキャッシュとページ ID を含めてキャッシュの問題を診断可能にしました (#23538、#23522、@stelfrag)
  • バンドルされている SQLite を 3.53.4 に更新しました (#23511、@stelfrag)
  • NULL ラベル アロケーターでクラッシュした -W createdataset および dbengine ストレス テスト ワークロードを修復し、生成されたすべてのサンプルに要求された時間範囲の代わりに壁時計をスタンプし、ホストのティアダウン時に二重解放された状態を修正しました (#23758、@stelfrag)

クラウド接続 (ACLK)

  • 非セキュアモードの動作を維持しながら、ACLK HTTPS リクエストの TLS ホスト名と IP 検証を追加しました (#23463、@stelfrag)
  • 放棄された自己署名証明書を安全でないモードでの証明書検証の失敗として報告するのを停止したため、後の I/O または HTTP エラーはそのまま報告されます (#23732、@stelfrag)
  • HTTPS および MQTT client を、I/O 進行状況ウォッチドッグを使用した単調なマイクロ秒ベースのタイムアウトに切り替え、CONNACK 前のポーリングを 1 秒に制限したため、静かなピアによるシャットダウンの遅延が最大 60 秒できなくなりました (#23105、#23733、 @stelfrag)
  • 欠落した MQTT PUBACK を成功した確認応答としてカウントするのを停止し、解放された client に触れることなく切断後も保存される専用のタイムアウト カウンターで追跡するようになりました (#23486、#23734、@stelfrag)
  • 圧縮された ACLK 応答のプールされた応答バッファーとそのメタデータが保持され、リング バッファー境界にまたがるペイロードの WebSocket マスキングが修正されました (#23485、@stelfrag)

ヘルスとアラート

  • Windows 10min_cpu_usage アラートが service.*_cpu_utilization チャートに添付され、誤った CRITICAL アラームが発生する問題を修正しました (#23559、@thiagoftsm)
  • ホストごとに名前でアラートのインデックスを作成し、健全性変数解決時のフルホスト アラート スキャンを置き換えます (#23554、@stelfrag)
  • チャートのメタデータが変更されていない場合にアラート プロトタイプの再初期化を回避したため、子チャートの継続的な再登録によって健全性の再評価が繰り返されなくなりました (#23515、@stelfrag)
  • 通知が実際に送信された場合にのみ発生アラート概要を構築し、反復ごとの作業と、チャートの削除に伴う潜在的なロック順序のデッドロックを回避しました (#23544、@stelfrag)
  • ヘルス データベース コード内の SQL ステートメントの準備に関する誤ったエラー チェックを修正し、親データベースのストレージと B ツリーのメンテナンスを減らすために 2 つの未使用の health_log_detail インデックスを削除しました (#23545、#23722、@stelfrag)

メタデータ、ラベル、内部情報

  • 辞書 API の実行中に辞書の破棄を延期し、シャットダウン中の同時破棄に対して set/get/delete およびトラバーサルを安全にします (#23634、@stelfrag)
  • 削除コールバックがコレクタに再入し、ウォークの途中でキャッシュされた後続オブジェクトを解放し、マスターによって削除されたアイテムを残してビュー コレクションを停止したときの辞書ガベージ コレクションの解放後の使用を修正しました (#23819、@stelfrag)
  • 廃止されたチャート リーパーが、別のサブシステムがまだ参照しているチャートを解放するのを停止しました。これにより、インデックスのないチャートが破棄ロックを保持したままになり、まだ書き込みを行っているコレクターが致命的になる可能性がありました (#23761、@stelfrag)
  • すべてのコレクタが停止するまで機械学習ワーカー キューのティアダウンが延期されるため、シャットダウン期限を超えたコレクタは、破棄されたキュー ミューテックスで中止できなくなります (#23757、@stelfrag)
  • 生成された子の SIGPIPE をリセットしてブロックを解除したため、パイプが閉じられている子は EPIPE 上で生き残るのではなく終了します (macOS 上で数百の powermetrics プロセスが立ち往生していました) シグナル配信をサイレントにドロップするのではなく報告し、生成サーバーの回帰テストを決定的にしました (#23751、 #23815、@stelfrag)
  • ページ重複排除を前提とするのではなく、有効にする前に KSM サポートを調査するため、サポートされていないカーネルは KSM エラーを報告しなくなり、KSM マーキングを実際にマージできる dbengine ページ プールに限定しました (#23822、@stelfrag)
  • 繰り返しのチャート登録時に未変更のチャート メタデータのサニタイズと再インターンをスキップし、実際のラベルの突然変異の場合にのみラベル バージョンをインクリメントしました (#23603、#23513、@stelfrag)
  • 同時構成更新中のテキストバッファのクリーンアップの問題と dyncfg ツリーのサイズ競合を修正しました (#23657、@stelfrag)
  • inicfg 数値書式設定で sprintf() を制限付き snprintfz() に置き換え、動的 /proc/net/dev パス書式文字列をリテラル文字列 (#23638、#23450、@stelfrag) に置き換えました。
  • 設定可能なパルス調整された間隔で mallinfo2() 収集を実行し、遅い呼び出しがデューティ サイクルを独占できないように完了後にスタンプすることでパルス オーバーヘッドを削減し、冗長なパルス チャート メタデータのバージョン バンプを停止しました (#23579、#23736、#23650、 @stelfrag)
  • パルス子チャートからチャートごとのラベル プローブを削除し、代わりにホストのラベル バージョン比較に依存しました。 808 個の子を持つ親では、プローブはメイン パルス スレッドの約 23% を占め、発行する netdata.* チャートにギャップが残りました (#23760、@stelfrag)
  • Coverity の検出結果を沈黙させ、子が切断されている間の正常性初期化フラグの動作の文書化を含む、古いコメントと単体テスト診断を修正しました (#23553、#23737、#23541、@stelfrag)

コレクターとエクスポート

  • 最初のカウンタが割り込み ID に結合されている場合の /proc/interrupts 解析を修正しました。これにより、変化するカウンタ値がディメンション ID にプッシュされ、無制限のディメンション増加が発生する可能性がありました (#23651、@stelfrag)
  • ソケットの収集をネットワーク名前空間ごとに 1 回の検証済み試行に制限することで、ヘルパーの失敗によってソケット レコードごとに収集試行が繰り返されることがなくなりました (#23778、@ktsaou)
  • 接続エラーに完全なコマンドを埋め込む go.d UPS コレクターを停止し、PASSWORD 資格情報をクリア テキストで記録しました。 USERNAME および PASSWORD 引数のみが編集されるため、他のコマンドは診断可能なままになります (#23782、@stelfrag)
  • 飽和した SQL COUNT は、int に絞り込む前に ibm.d AS/400 コレクターで発生するため、範囲外のカウントが負にラップされなくなり、カーディナリティ制限がサイレントに変更されなくなります (#23783、@stelfrag)
  • go.d SNMP コレクターの MikroTik ゲージ変換を修正し、go.d チャート エンジンから位置合わせされていないアトミックを削除しました (#23525、#23540、@ilyam8)
  • OpenTSDB Telnet ホスト名とメトリック プレフィックスの有効な句読点を保持しながら、Telnet レコードを破損する可能性のある空白、制御文字、区切り文字を置き換えます (#23749、@stelfrag)
  • 実際の charts.d.conf ではなく charts.d.plugin.conf を指す charts.d.plugin 無効チャート メッセージを修正しました (#23662、@ilyam8)
  • SQL Server: クエリ ストアが利用できないか無効になっている場合の top-queries のプラン キャッシュ フォールバック (sys.dm_exec_query_stats) を追加し、専用の拡張イベント セッションが構成されていない場合は error-info の組み込み system_health セッションにフォールバックするようにしました (#23748、@thiagoftsm)
  • SQL Server: エディション間での関数クエリを強化し、エンジンのエディションとバージョンをインスタンスごとに 1 回調査し、それに応じてサーバー スコープのクエリとデータベース スコープのクエリをルーティングするため、top-queries、deadlock-info、error-info はオンプレミス SQL Server だけでなく Azure SQL Database と Managed Instance でも動作します (#23564、 @ilyam8)
  • SQL Server: SQL Server 2014 以前のデッドロックおよびエラー情報クエリを修正し、製品バージョンではなくカタログ列によってクエリ ストアを検出し、セッション名と一致すると仮定するのではなく、セッション カタログからevent_fileパスを読み取りました (#23460、@thiagoftsm)
  • SQL Server: デフォルトで無効な SQL エージェント ジョブを収集から除外し (collect_disabled_jobs: true を設定して保持する)、有効になっているジョブのジョブ アラートを制御したため、無効なジョブの最後に失敗した実行でアラートが発生し続けなくなりました (#23645、@ilyam8)
  • Windows: Processor Information パフォーマンス オブジェクトから CPU メトリクスを収集し、その NumaNode,NumaIndex インスタンスをプロセッサ トポロジを介して論理 CPU にマッピングするため、64 個を超える論理プロセッサを備えたホストが正しくレポートされます。 Processor Information が利用できない場合は、従来の Processor オブジェクトが引き続き使用されます (#23549、@thiagoftsm)
  • Windows: 不要な論理ボリューム (一時バックアップ マウントなど) がディスク領域の収集から外されるように、[plugin:windows:PerflibStorage] の下に exclude space metrics on paths を追加し、ボリューム serial_number ラベルを追加し、スペルの間違った driver_type ラベルを drive_type に修正しました (#23660、@thiagoftsm)

インストールとパッケージ化

  • Windows: トークンのみが提供された場合の要求を修正し、要求トークンとプロキシを非表示の MSI プロパティとしてマークしたため、詳細なインストーラー ログに表示されなくなりました (#23547、@thiagoftsm; #23735、@stelfrag)
  • eBPF プラグインを 64 ビット ユーザーランドに制限し、カーネル アーキテクチャではなくユーザーランド マシンタイプから Go ツールチェーンを解決しました (#23446、@stelfrag)
  • macOS: IOKit API を直接リンクするのではなく動的に解決し、古い macOS SDK に対してビルドを復元しました (#23421、@stelfrag)

サポート オプション <a id="v2111-support-options"></a>

当社は成長するにつれて、オープンソース ソリューションを通じてこれまでにない最高のサポートを提供することに尽力し続けます。このリリースで行われた変更または Netdata Agent の機能で問題が発生した場合は、次のいずれかのチャネルを通じてお気軽にお問い合わせください。

  • Netdata Learn: Netdata を使用してシステムを監視およびトラブルシューティングするためのドキュメント、ガイド、参考資料を検索します。
  • GitHub の問題: Netdata リポジトリを利用して、バグを報告したり、新しい機能のリクエストをオープンしたりします。
  • GitHub ディスカッション: Netdata 開発プロセスに関する会話に参加して、参加してください。
  • コミュニティ フォーラム: コミュニティ フォーラムにアクセスして、共同知識ベースに貢献してください。
  • Discord サーバー: Netdata Discord に参加して、志を同じくするシステム管理者、DevOps、SRE、その他のトラブルシューティング担当者と交流しましょう。すでに 2,000 人以上のエンジニアが使用しています。
