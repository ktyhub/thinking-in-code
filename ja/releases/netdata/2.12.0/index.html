  • **OpenTelemetry 構成 (v2.10.x 以前からアップグレードする場合): カスタマイズされた otel.yaml を確認してください。 ** OpenTelemetry プラグインは v2.11.0 で書き直され、その構成は厳密です: 不明なキー、不明 NETDATA_OTEL_CFG_* 以前の実験的スキーマ (size_of_journal_file、size_of_journal_file、 number_of_journal_files およびその他のジャーナル ファイル オプション) は、otel-plugin の起動を停止します。以前のログストレージ ストレージ エンジンとそのデフォルトが変更されたため、値は移行されません。プラグインが前者を認識する場合 スキーマの起動エラーでは、古いキーとその置換がリストされます (たとえば、size_of_journal_file は logs.rotation.default.max_file_size; store_otlp_json には代替品がないため、コピーするのではなく新しい値を選択してください 古いもの。 v2.12.0 は、logs と同じ回転および保持オプションを備えたオプションの traces セクションを追加します。 (#22720、#23479)
  • OpenTelemetry リモート ストレージ: ダウンロード キャッシュが移動されました。 remote_storage.enabled では、ログとトレースが共有されるようになりました。 {base_dir}/remote-read に 1 つのダウンロード キャッシュがあり、起動時に既存の {base_dir}/logs/remote-read がそこに移動されます。 新しいパスがすでに存在する場合、または移動が失敗した場合 (古いディレクトリが別のマウントであるなどの理由で)、 代わりに古いキャッシュ ファイルがクリアされるため、キャッシュ マウントを {base_dir}/remote-read に指定します。 (#24088)
  • Ceph: 1 つのチャート コンテキストが置き換えられました。 ceph.cluster_objects_by_status_distribution はなくなりました。オブジェクトの健全性は現在です 個別のオブジェクト コピーの健全性グラフと見つからないオブジェクト グラフによってレポートされます。カスタム ダッシュボード、アラート、または API クエリを更新します。 古いコンテキストを参照します。 (#23357)
  • Ceph: より厳格なジョブ設定とリダイレクト。 method または body を設定する go.d/ceph ジョブ、またはカスタム Authorization、Cookie、または Host ヘッダーは検証に失敗します。それらを削除し、username で認証し、 password または bearer_token_file と併用。コレクターは、次のような別のオリジンへのリダイレクトにも従わなくなりました。 その起点が allowed_redirect_origins にリストされていない限り、アクティブ マネージャを指すスタンバイ マネージャとして。リスト すべてのマネージャーのダッシュボードの起点がそこにあります。 (#23357)
  • Ceph: OSD ごとおよびプールごとのチャートには上限があります。 専用の go.d/ceph コレクターでは、最大 100 個のチャートを選択できるようになりました。 デフォルトでは、OSD と 100 個の選択されたプール。いずれかの制限を超えると、そのグループのみのエンティティごとのメトリックが抑制されます。 そしてコレクターはその理由を記録します。 max_osds または max_pools を上げるか、osd_selector または pool_selector を狭くします。 (#23357)
  • サービス検出: 検出されたジョブのシークレット参照はデフォルトでは解決されなくなりました。 ${env:...}、 サービス検出によって生成されたジョブ内の ${file:...}、${cmd:...}、および ${store:...} はリテラル テキストとして保持されるようになりました。 これには、独自の検出ルールに記述された参照も含まれます。検出パイプラインがそれらに依存している場合は、次のように設定します。 そのパイプラインに trust_discovered_targets: yes を追加するか、動的構成を通じてジョブを採用します。 (#23916、#23918)
  • UNIX 上の go.d ファイルとコマンド シークレットは、プラグインの昇格された権限なしで実行されます。 ${file:...} および ${cmd:...} 参照は、特権のないアカウント (通常は netdata) として nd-run を通じて解決され、フォールバックはなくなりました。 特権アクセス。プラグインの権限によってのみ読み取り可能だった認証情報ファイルは解決されなくなりました。 コマンドは、そのアカウントの USER、LOGNAME、HOME と SHELL=/bin/sh を取得するようになりました。アカウントができることを確認してください これらのファイルを読み取ってコマンドを実行し、古いバージョンに依存するツールに明示的な構成パスを渡します。 環境。 (#23865、#23879、#23884)
  • go.d に対する動的構成の応答では、実行時の健全性ではなく導入について説明します。 受け入れられたジョブ、検出 まだ開始する必要があるパイプラインまたはシークレット ストアの変更は、202 を返す可能性があります。の構成ステータスを読み取ります。 結果。拒否された更新では、以前の構成と実行中のジョブが保持されます。 Cli2xx 応答を処理したエント 「実行中」の場合は、代わりにステータスを確認する必要があります。 (#24011、#24014、#24020)
  • 動的構成によって作成された go.d vnode 名は書き換えられなくなりました。 空白を含む名前、 コロン、=、引用符、バックスラッシュ、または制御文字はエラーで拒否されるようになりました。以前はスペースとコロン 暗黙のうちにアンダースコアに置き換えられました。ジョブは、vnode を正確な名前で参照する必要があります。 ASCII 文字、数字、 ドット、アンダースコア、ハイフンは常に安全です。 (#24024)
  • 中継された子は、親の _net_default_iface ラベルを継承しなくなりました。 以前は、子は、 親は親のアップリンク インターフェイスを運ぶことができます。ラベルを提供する子は、独自の値を保持します。仮想用 ノードとそれを持たない古い子には、ラベルが表示されなくなりました。親のラベル フィルターと一致するラベル フィルターを確認します。 子ノードのインターフェイス。子ホストのラベルの変更は、再接続することなくすべての上流の親にも届くようになりました。 (#24015)
  • 重み付け (メトリック相関) の結果は変更される可能性があります。 現在は /api/v1/weights および /api/v1/metric_correlations URL で選択されたホストにスコアを付けます。すべての API バージョンでの平均異常率の重みは、欠落しているコレクションをカウントします ウィンドウ内のスロットがゼロ異常として認識されるため、スパース メトリクスのスコアが低下し、ランキングが変更される可能性があります。レビュー これらのスコアやランキングを比較する自動化。 (#24080、 #24081)
  • NetFlow: 起動時のポート競合により、再起動ループではなくプラグインが無効になるようになりました。 NetFlow UDP がリッスンする場合 プラグインの初回起動時にポートが取得されると、エージェントは Netdata が再起動するまでそのポートを無効にします。ポートを解放するか変更します リスナーを削除し、Netdata を再起動します。 flows:netflow および netflow.* チャートは起動後にのみ表示されるようになりました。 完了します。 (#24029)
  • SQL Server: 無効になった SQL エージェント ジョブはデフォルトでは収集されなくなりました。 保持するように collect_disabled_jobs: true を設定します。 それらを集めています。これは最初に v2.11.1 で出荷されました。 (#23645)
  • Windows OS のホスト ラベルが変更されました。 OS 名は「Microsoft Windows」になり、_os_marketing_version、_os_release、 _os_edition と _os_build が追加されました。 _os_version は従来の表示値を保持します。ラベルフィルターを確認してください。 古い Windows 文字列と一致しました。 (#23453)
  • HAProxy コレクターは、go.d と python.d の両方で廃止されました。 HAProxy はネイティブ Prometheus エンドポイントを公開し、 Netdata は在庫 haproxy Prometheus プロファイルを出荷するため、HAProxy モニタリングは現在、 【Prometheusコレクター】(https://learn.netdata.cloud/docs/collecting-metrics/prometheus)。 HAProxy Prometheus を有効にする エンドポイント (Prometheus エクスポーターを備えた stats ソケット、または HAProxy 2.0+ の組み込み /metrics) と Prometheus のポイント それのコレクター。 (#23631、 #23632)
  • RHEL 7.x、CentOS 7.x、Amazon Linux 2 および互換プラットフォームのネイティブ パッケージはビルドされなくなりました。 これは、 v2.11.0 release note で発表。 2.11.x シリーズが最後に提供されました。静的ビルドは、 推奨される代替品であり、新規インストールでは自動的にそれらに切り替わります。 (#22930)
  • **Debian 11 および Ubuntu 25.10 は、LTS のアップストリーム終了 (2026 年 8 月 31 日) および それぞれ人生（2026-07-09）。 (#22931、 #23813)
  • 従来の RPM パッケージ コード (netdata.spec.in) は残りますが、未使用で非推奨です。公式 RPM パッケージは v2.11.0 以降と同様に、CPack を通じて構築されています。今後のリリースでは削除される予定です。
