オーマイオープンエージェント v5.1.69

OmO は senpi 2026.11.10-2 上で実行されます。 client は、read_project_file / write_project_file (senpi#6307) を介して RPC 経由でワークスペースの命令ファイルを読み取り、編集できます。構築されたセッションは、claim_session (senpi#6350) を介してパークおよび配布できます。Fable 5.2 プロンプト プリセットは、コードベース所有権センテンスを取得します。 (senpi#6360)、generate_image は bash (senpi#6272) と同様に eval 専用であり、eval セルは tool.<name>(...) および agent()/output() ヘルパーを介してすべての eval 専用ツールに到達し (senpi#6276)、EQ ゴールデンは新しいプロンプトを伝えます (senpi#6355)。 (#13054)

別のエージェントからのメッセージに応答したエージェントは、エンジンが自動的に開始するターン中、プロンプトなしで応答し続けることができます。 消費された配信によって付与される返信許可 (ID または指定された名前による送信者への返信、配信のみで承認される) は、配信が開始された作業中継続するようになりました。つまり、消費ターンとその後のターンごとにエンジンが自動的に開始されます (オープン Todo リマインダー、目標の継続、モニター ウェイク)。もはや和解だけでは終わりではありません。その回答の後に新しいメッセージが作業を開始すると終了します。つまり、個人のメッセージまたは配信であり、その送信者自身が新しいグループに保持されます (実行中の作業に参加する配信は、その送信者を追加します)。カバーされたターンでの応答は次のホップで配信のチェーンを継続するため、チェーン制限によって依然として配信が閉じられます。 (#13042、#12996 の一部) (#13044)

omo remote send は他のすべての送信と同じ配信パイプラインを通過し、--steer はセッションを 1 回読み取ります。 別のデバイス上のセッションへのメッセージは、リレー アドレス帳の <device>/<session> アドレス参照とともに createDeliveryPipeline に入力されるため、CLI は独自のトランスポート呼び出しを構築しなくなりました。リレートランスポートは走行ターンを 1 回読み取り、それを操縦します。CLI は最初に 2 回目を読み取ります。何も実行していないセッションに --steer を送信しても、何も送信されません。未使用の 2 番目のプロンプト実装 (promptRemote) とその引数チェックが削除されました。各デバイスがどの送信者の種類を許可するかは変わりません。 (#13038)

質問を待機しているこのデバイス上のセッションへのメッセージは、別のデバイスへのメッセージと同様に、そのように表示されます。 送信はまだキューに入れられており、その delivery は waiting_on: { kind: "approval", device } を伝送します。 device はこのインストールのアカウント デバイスであり、インストールにデバイス ID がない場合は存在しません。 (#13035)

あるセッションが別のセッションに送信するすべてのメッセージは、このデバイス上でもデバイス間でも同様に、送信元のデバイスに名前を付けるようになり、別のデバイスからのメッセージは、ローカルのメッセージと同じように、受信実行の次の送信の原因としてカウントされます。 デバイス ID を読み取ることができない場合 (デバイス サービスがない場合、または応答しない場合)、メッセージは引き続き送信され、デバイスに名前を付けなかった理由を記録します。 (#13034、#13004 の一部)

別のデバイス上のセッションに送信またはハンドオフされたメッセージは、このデバイス内で送信されたメッセージと同様に、delivery_id、effective_mode、および endpoint を報告するようになりました。 答えはアカウントのセッション リストから得られ、これらのフィールドは削除されました。リレートランスポート自体の配信ファクトを通過させるようになりました。送信者はそのデバイス上のエンドポイントを知らないため、endpoint は null になります。 (#13033) 別のデバイス上のエージェントへの応答は、メッセージ ヘッダーの ID またはその名前によってエージェントに届くようになり、同じアカウントに対するプロンプトは表示されません。 1 つのリゾルバーが、このデバイスのスレッドとアカウントの他のデバイスにわたってスレッドを検索します。つまり、正確な永続 ID、次にアカウント エイリアス、そしてすべてのエントリに対して名前ラダーが判断されます (名前を共有する 2 つのデバイスは、両方のデバイスに名前を付ける曖昧なターゲットであり、サイレント ピックではありません)。 thread_send、thread_handoff、コントロールツール、thread_create (オープンまたはフォーク)、omo thread CLI はすべてこれを使用します。実行が受け取った配信の送信者への返信は、その配信のみから (送信者の永続 ID または指定された名前によって) 承認され、その送信者に解決される必要があります。そうでない場合は、送信せずに reply_target_mismatch として拒否されます。別のデバイス上のスレッドに対して表示される ID は、その永続的な ID です。デバイスがリレー リストを公開すると、リレー リストにそのリストが含まれます。 omo remote 動詞は引き続き、デバイスのセッション キーとして入力した ID によってディスパッチされるため、そのパスが共有リゾルバーに移動するまで、デバイスのリストにある ID を渡します。 (#13000)

別のデバイス上のエージェントへの送信は、このデバイス上のエージェントへの送信と同じ事実を報告するようになりました。 thread_send および thread_handoff は、別のデバイス上のターゲットに対しても delivery_id および effective_mode に応答するため、発信者は、スレッドを保持しているデバイスに関係なく、同じ方法で配信の ID と送信されたレーンを読み取ります。 message_seq と endpoint はこのデバイス上のゲートウェイ行の事実のままであり、device は別のゲートウェイ行を指定します。応答許可 (プロンプトなしで、エージェントの ID または指定された名前によって、配信を受け取ったエージェントに応答する実行) は、同一デバイス配信とクロスデバイス配信で同一であることが証明され、1 つのパリティ テーブルが両方のレッグに対してすべての送信アサーションを実行するようになったため、トランスポートを読み取るルールはユーザーに到達せずにビルドに失敗します。 (#13006、#13000 の上)

タスクの子は、プロセス全体の編集レジストリを拒否した senpi エンジンに対して開始されなくなりました。開始は SenpiEngineRestartRequiredError で失敗し、omo を再起動するように指示されます。 エンジンはインストールしていないレジストリ スロットの隣のロ​​ードを拒否し、その拒否はプロセス全体にわたって続くため、再起動が唯一の解決策です。 (#12991)

omo は、0.1.3 ではなく、署名付きデバイス サービス 0.1.27 をインストールするようになりました。 デバイス サービスのピンは、0.1.3 以降のすべてのデバイス サービス リリースで 0.1.3 のままであり、インストールされた omo はそのピンよりも古いサービスのみを置き換えるため、新しいものを受け取るマシンはありませんでした。 (#12981)

thread_* ツールは、bash と同様に eval 専用になりました。eval ツールが存在する場合、それらはモデルの直接ツール リストには含まれなくなり、eval セル内で tool.thread_*() として呼び出されます。 動作、権限、結果は変更されず、eval がなければ通常の直接ツールのままです。 (#12907、クローズ #12903)

長時間実行されているエンジンは、クラッシュしたワンショット メモリ実行を再利用し続けます。 放棄されたワンショット メモリ実行のメモリ コンポーネントによるクリーンアップは、セッションが開いている外部のエンジン プロセスごとに 1 回実行されますが、再起動を待つ代わりに、デスクトップやデーモン ホストなどの稼働状態にあるエンジンで 1 日に 1 回繰り返されるようになりました。 (#12899) セッションを開いたときにメモリ ルートが再スイープされなくなりました。 放棄されたワンショット実行のメモリ コンポーネントのクリーンアップは、開いているすべてのセッション内ではなく、エンジン プロセスごとに 1 回、最初に開いた直後に実行されるようになりました。クリーンアップが開始される前に終了したセッションは、次のオープンセッションに引き渡されるため、クラッシュした実行は引き続き回収されます。 (#12896)
