オーマイオープンエージェント v5.1.66

omo thread は、インストールが壊れてこのデバイスにのみ残された場合に表示されます。 ロードできないスレッド client サイドカーにより、omo thread read <alias> が黙って not_found: stderr にサイドカー、エラー、および再インストール ステップの名前を付けることがなくなりました。 CLI サインイン自体の警告 (廃止された trust ピン、失敗したデバイス サービスの忘れ) も標準エラー出力に届くようになりました。 (#12936)

ビジー スレッドへのメッセージは、デフォルトで実行中のターンに到達するようになりました。 配信モードなしの thread_send および thread_handoff (および --mode のない omo thread send) は、受信者の実行中のターンを制御し、このデバイスでも別のデバイスでも同様にアイドル状態のときにターンを開始します。メッセージは、呼び出し元が follow_up を要求した場合、またはターンがステアリングを実行できない場合 (待機中の質問、圧縮、ターン エポックがないことを報告するエンジン) にのみ、実行中のターンの後ろにキューに入れられます。その瞬間に終了するターンを誘導する送信は、失敗するのではなく、その時点でターゲットがいたレーンに戻ります。 (#12921、#12879 の一部)

OmO は senpi 2026.11.9-2 上で実行されます。 eval セルが待機するツールは、終了時に実行中のセルを一瞬空白のままにすることがなくなりました。ストリームされた行は、セル自身の出力またはその結果が置き換えられるまで残ります (senpi#6257)。 (#12920)

omo remote send はセッションの thread_send と同じ道を別のデバイスに移動し、別のデバイスからのすべての応答は 1 つのマッピングによって説明されます。 別のデバイスのセッションに送信する端末側の人は、自分自身のプロンプト記録を保持しながら、リレー トランスポート (同じオフライン チェック、実行中のターンに対する同じステア プリフライト、このデバイスのゲートウェイ ストアでのレシート) を通過します。別のデバイス上のコマンドが拒否されたときにユーザーが読み取る内容 (omo remote、アタッチ TUI、スレッド ツール、および SDK) は単一モジュールからのものであるため、応答しなかったデバイス、許可の欠落、または不確実な結果はどこでも同じ内容を読み取ります。 (#12911、#12879 の一部、#12885 を修正)

OmO は senpi 2026.11.9 上で実行されます。 これは senpi の admit_external_message (別のデバイスのセッションから中継されたメッセージは通常の配信として許可されます) を導入し、デバイスがそのメタデータのみに保持された状態で、中継された配信を同じマシンの配信とまったく同じように読み取ります。 1 チャネルのリレー トランスポート (#12879) には両方が必要です。 (#12904)

omo.dev のヘッダーの [インストール] ボタンは、ピルの右端を押したりすり抜けたりしなくなりました。 フローティング ナビゲーション バーは、最後のコントロールに左側のロゴと同じインセットを提供し、1000 ピクセル未満ではセクションのリンクがメニューに移動するため、どの言語でもピルの外側には何もプッシュされません。 (#12893)

エージェントが作成または thread_create でフォークしたスレッドは、ホストのデフォルトではなく、このデバイスでも作成者自身の承認モードで開始されるようになりました。 別のデバイスで作成されたセッションはすでに承認モードで開始されました (#6189)。 2 つのレッグが 1 つの本体を実行するようになりました。スレッドが到達したデバイスに対して名前がチェックされ (そのデバイスがすでにライブでリストしている名前は name_conflict です)、別のデバイスでライブになっているスレッドを開くと、再度開かずにそのスレッドに応答し、作成されたスレッドの事実 (名前、作業ディレクトリ、タイムスタンプ) は両方のデバイス上のエンジンの応答から得られます。 (#12891、#12879 の一部) スレッドの停止、終了、名前変更、再モデリング、推論レベルの変更、またはスレッドの読み取りは、そのスレッドがこのマシンで実行されているか、アカウントの別のデバイスで実行されているかにかかわらず、同じように機能します。 thread_set_reasoning は別のデバイス上のスレッドにも到達し、別の client がまだ保持しているファイルがまだないセッションは、両方で同じ応答を返します。 (#12890、#12879 の一部)

エージェントが別のデバイス上のセッションに送信するメッセージは、1 つのデバイス上のセッション間のメッセージとまったく同じようにそこに到着します。 受信セッションは、同じ送信者行と同じデバイス配信で伝送される権限通知を持つ配信エントリ (決してユーザー メッセージではありません) を取得し、同じキーで重複排除され、同じ方法で受信時に起動します。返信は単なる送り返しです。配信されたテキストには通過したデバイスの名前は何も記載されておらず、端末からの omo remote send は変更されていません。 omo thread send から別のデバイス上のセッションへの送信はデータとして拒否され (エンジンは自身のマシンからのコマンド ライン配信のみを許可します)、omo remote send をポイントします。 (#12889、#12879 の一部、修正 #12882、修正 #12877、修正 #12346、修正 #12865、修正#12857)

別のセッションへのメッセージの送信は、そのセッションがこのマシン上にあるか別のデバイス上にあるかに関係なく、1 つの配信パイプラインを経由するようになりました。 デバイスの違いは、1 つのポートの背後にあるトランスポート モジュールです。このリリースでは、ユーザーには何も変更が表示されません。 (#12887、#12879 の一部)

別のデバイス上のセッションへのメッセージは、同じマシン上のセッションからのメッセージとまったく同じように読み取れるようになりました。 受信側エージェントは、どのデバイスからではなく、どのセッションから送信されたのかを確認し、通常どおりそのセッションによって応答します。 (#12878)

応答を開始するまでに 90 秒以上かかるモデルのサブエージェントは、ランタイム フォールバックによって中止されなくなりました。 runtime_fallback を有効にすると、ファースト プロンプト ウォッチドッグは、固定の 90 秒以内に進捗を示さなかったすべてのサブエージェントをカットし、フォールバック モデルを再プロンプトするため、最初のトークンが強制終了される前に正当に長時間思考する推論重視のモデルは、最初のトークンが強制終了され、プロンプトが 2 回送信されます。ウォッチドッグは、エンジンが使用するのと同じストリーム開始境界で 300 秒待機し、runtime_fallback.first_prompt_timeout_seconds がそれを設定します (0 は無効にします)。 (#11893、#11887を修正)

修正済み

  • このデバイスに保持されているスレッド エイリアスへの omo thread send は、omo thread read と同じ方法で、別のワークスペースから実行されるときに、一致する可視スレッドがないと応答するのではなく、そのスレッドに到達するようになりました。 (#12860)
  • メモリ シャットダウン ドレイン: セッション シャットダウン ワイヤリングは、senpi がハンドラーに制限を設けないと主張しなくなりました。 senpi は 1 つの session_shutdown ハンドラーを独自の警告しきい値、ハンドラーごとのタイムアウト、および合計終了バジェット (出荷時のデフォルトは 2 秒 / 10 秒 / 2 秒、それぞれユーザー調整可能および 0 無効可能) で制限し、1500 ミリ秒のドレイン バジェットはこれらのデフォルトの下でサイズ設定され、インストールされた senpi から値を読み取るテストによって固定されるため、デフォルトをドレイン未満に下げるホスト リリースは失敗します。そこに。 OmO からホストの上限は追加されず、ホストの中止をバイパスするものはありません。バジェットによってジャーナルフラッシュがスキップされた場合でも、エラーレベルのアラームが発生します。 (#12795、参照 #10336)
  • ブラウザ スキルのドキュメントと例では、現在出荷されている omowright (^0.3.0) の BrowserSkill 0.4 共有コントロールについて説明します。すべてのゲート ページ アクションには新しい session.cooperate("sync") のコンテキストが含まれており、cooperation_sync_required の拒否は session.cooperate("wait") を持つ人を待ってから、再同期して再計画します。また、どの呼び出しがゲートされているか、ゲート アクションが未知のオプション キーで TypeError をスローすること (代わりに野良キーを渡す 2 つの呼び出しを含む)、および page.on("dialog") リスナーが応答できる Dialog を受け取ることにも注意します。このリリースに同梱されている omowright には、スパース ページおよびフレームセット ページでの DevToolsActivePort、goto による実行中のブラウザー検出、BrowserSkill IPC チャンク全体の UTF-8 デコード、および一意のみの古い ref リカバリ (@ashmoonori-afk 氏に感謝、code-yonyu/omowright #115 から #118 に感謝)、および独自のウィンドウ内のエージェント タブ (@devxoul に感謝) が含まれています。コードヨンユ/omowright#120)。 (#12494)
  • senpi-task cold-revive 常駐テストは、一律 20 秒の合計ではなく、製品独自の liveness ルールによって制限されるようになりました (#10993 の一部)。起動中にしばらくブロックする Windows の子は、製品も放棄しない限り失敗しなくなり、実際のストールは、到達した最終段階とストールの長さで失敗します。テストの子は senpi の起動フェーズのタイミングも報告するため、次のブロックはそのフェーズに名前を付けます。 (#11706)
