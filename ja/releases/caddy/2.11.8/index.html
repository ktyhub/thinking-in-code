#キャディv2.11.8

このパッチ リリースは、バグ修正とセキュリティ強化の大規模なバッチに加え、いくつかの小さな追加を加えたものです。このリリースは 2.11 メンテナンス ブランチから切り取られたものです。修正はマスターからバックポートされています。 特に PHP を提供している場合、またはファイル パスで {host} を使用している場合は、アップグレードをお勧めします。

リソースを活用してプロジェクトを存続させてくれたスポンサーと、この絶え間ない AI の新時代で精力的にトリアージと支援を行ってくれたメンテナーに多大な感謝を申し上げます。

:警告: アップグレードする前に、以下の重大な変更をお読みください。 それらのほとんどは、見た目とはまったく異なる構成やリクエストを拒否するため、ほとんどのセットアップは気付かないでしょう。

ハイライト

  • アイドル タイムアウト、第 2 ラウンド。 2.11.6 で導入されたアイドル読み取り/書き込みタイムアウトのさらなる修正:
    • ルートごとの timeouts がサーバー全体の read_body_idle / write_idle よりも優先されるようになり、ネストされた timeouts は最も内側の timeouts を使用します。 (#8121)
    • HTTP/2 経由で、リクエスト本文の読み取りを一時停止したハンドラー (遅いアップストリームにアップロードする reverse_proxy など) が本文を失い、502 で失敗することがなくなりました。 (#8125)
    • ハンドラーによって設定された期限が上書きされるのではなく上限として機能するようになり、Mercure の dispatch_timeout や FrankenPHP の request_body_timeout などが再び機能するようになりました。ありがとう@dunglas! (#8145、#8284)
    • HTTP/1.1 アップロードで、本文が少し残ったままタイムアウトしても、エラー応答が送信されずにハングすることがなくなりました。 @SiyXo511 ありがとう！ (#8178)
  • より少ない機能で特権ポートをバインドする (Linux): CAP_NET_BIND_SERVICE が許可されているが有効ではない場合、Caddy は特権ポートをバインドするためだけにこれを発生させます。パッケージャは +ep の代わりに setcap cap_net_bind_service=+p を使用できるため、Caddy は引き続き --cap-drop ALL、OpenShift の restricted-v2、または空の CapabilityBoundingSet= を持つ systemd ユニットで起動します。また、1024 を想定するのではなく、カーネルの ip_unprivileged_port_start に従います。 (#8102、#8253)
  • 小さな追加:
    • 一致するリクエストのアクセス ログ レベルを設定するための新しい log_level ディレクティブ。 log_level @healthchecks DEBUG (#8201)
    • 新しい {time.now.rfc3339} プレースホルダー。ありがとう@steadytao! (#8140)
    • TLS 接続ポリシー用の新しい not マッチャー。ありがとう@simonether! (#8138)
    • tls マッチャーは、CEL expression マッチャー: tls()、tls('complete')、tls('early_data') で使用できます。ありがとう@stackedbyaradhya! (#8088)
  • リバース プロキシ:
    • 自分で設定したヘッダー (header 経由の Strict-Transport-Security など) は、103 Early Hints (#8169) のように、アップストリームが最初に 1xx 応答を送信したときに失われることがなくなりました。
    • リクエスト トレーラーの名前だけでなく、値も転送されます。ありがとう@krishsinghhura! (#8246)
    • lb_retry_match のリクエスト専用 expression は成功した応答を再試行しなくなりました (2.11.3 以来の回帰) (#8168)
    • フォワード プロキシ経由および FastCGI バックエンドへのダイヤル エラーは、他のダイヤル エラーと同様に再試行されます。 @adarshxsh と @zemamba に感謝します! (#8264、#8172)
    • weighted_round_robin は、アップストリームよりもウェイトが少ない場合でもパニックにならなくなり、ウェイトが 1 つしかない場合に利用できないアップストリームを選択することもなくなりました。 random_choose は、すべてがビジー状態の場合に最も負荷の低いホストを選択します (#8159、#8320、#8160)
    • request_buffers / response_buffers unlimited では、途中で失敗したボディは完了したものとして扱われなくなりました (#8207)
    • セットアップ中にプロトコルのアップグレード (WebSocket など) が失敗した場合、または handle_response ステータスが数値でない場合でも、接続とソケットがリークされなくなりました。 @Version2beta と @BenMacha に感謝します! (#8269、#8318)
    • HTTP/3 client のキャンセルは、警告ではなくデバッグ レベルで記録されます。ありがとう@larrasket! (#8135)
  • encode: If-None-Match リストと弱いタグは 304 を適切に取得し (#8128)、HEAD 応答は偽の Content-Length を取得しなくなりました (#8150)。また、複数のヘッダー行に分割された Accept-Encoding / Cache-Control がすべて考慮され、プロキシでのヘッダー処理も高速化されます。 @Indra55、@jayhemnani9910、@dunglas に感謝します。 (#8025)
  • PHP / FastCGI: Status のない Location 応答は、CGI の指定 (#8209) に従って 302 リダイレクトとなり、宣言された Content-Length (ページの後の PHP 警告など) を超える内容を書き込むアプリでも、HTTP/1.1 応答が破損したり、HTTP/2 接続が強制終了されたりすることがなくなりました。ありがとう@Sulaiman-Dauda! (#8212)
  • TLS と ECH:
    • Caddy が暗号化された ClientHello を拒否した場合、再試行構成を送信するようになりました。そのため、古い ECH 構成を持つ clients を回復できます。ありがとう@ビデオ！ (#8142)
    • 独自のサイト ブロックも持つ ECH パブリック名は、そのサイトの TLS 設定を保持します (#8156)
    • client_auth モード request および verify_if_given は、ベリファイアが構成されている場合に証明書のない client を拒否しなくなりました (#8251)
    • 複数のリスナー アドレスにまたがるサイト ブロックでは、あるリスナーの TLS 接続ポリシー (client 認証を含む) が別のリスナーの TLS 接続ポリシーを上書きできなくなりました。ありがとう@steadytao! (#8192)
    • TLS ポリシー match ブロック内で繰り返されるマッチャー行は、最初の行だけでなく、すべて適用されます。ありがとう@simonether! (#8137)
    • マージされた自動化ポリシーにより、特定のドメインのポリシーがワイルドカードのポリシーよりも前に保持され (#8287)、ACME 発行者の network_proxy は再プロビジョニングされても存続します (#8288)
  • キャディファイル:
    • caddy run は、起動に失敗すると、コード 1 でサイレントに終了するのではなく、再度エラーを出力します。@IndraGunawan に感謝します。 (#8180)
    • すでに一致したグループ内のルートはマッチャーを実行しなくなります。 try_files {path} {path}.html?{query} =404 はすべての場合に 404 を返します (#8189)
    • 複数の handle_errors ブロックと vars が Caddyfile の順序に従うようになりました (#8195、#8197)
    • header ブロック内の各 ?Field デフォルトは独自にチェックされ、match が尊重されます (#8217)
    • import は、読み取れないファイルに対する実際の OS エラーを表示し (#8163)、負の {args[...]} インデックスはパニックを起こさなくなり (#8316)、非常に長いヒアドキュメント マーカーは解析クロールを行わなくなりました (#8203、#8249)。
  • file_server: 通常のファイル (/index.php/foo) の下のパスは再び 404 であり、pass_thru (#8131) で動作します。 browse は、エスケープ名 (#8152) と末尾を越えたオフセット (#8213) を持つディレクトリ内のシンボリックリンクを処理します。
  • templates: テンプレート エラーにより、古い Content-Length / Etag ヘッダーが保持されなくなりました (#8149)、本文のない応答が Content-Length: 0 を取得しなくなりました (iOS PWA が壊れました) (#8153)、さらに、コロンと前付が ... で閉じられた humanize 時間レイアウトが修正されました (#8215、 #8259)
  • ログ: 親名前空間の include にはその子モジュールが含まれ (#8221)、dir_mode from_file は使用できないディレクトリを作成しなくなり (#8225)、サイトのロガーへのログ ルーティングはホストの大文字と小文字を無視します (#8176)。
  • 管理者 API: リモート管理者 access_control の場合、最初のアクセス許可エントリ (#8317) だけでなく、いずれかのアクセス許可エントリが許可する場合、リクエストは許可され、Cache-Control: must-revalidate は他のディレクティブと並んで認識されます (#8330)
  • その他の修正: caddy hash-password は Windows の行末と最終改行なしの入力を処理します (#8227)、basic_auth キャッシュ内のデータ競合はなくなりました (#8278)、Windows サービスは START_PENDING でスタックしなくなりました (#8274)、および uri strip_prefix / strip_suffix はパーセントエスケープとリテラルを処理します% は正しく (#8005、#8345)
  • リリース ビルドでは Go 1.27 を使用します (Go 1.26 は依然として Caddy をビルドするための最小限のものです)。 (#8210)

:警告: 重大な変更

  • 無効なホストまたはドットのみのホスト (.. など) を使用したリクエストは、ルートが実行される前に、すべてのプロトコルで 400 で拒否されます。以前は、HTTP/2 と HTTP/3 は、/ または \ を含むホストも受け入れていました。 (#8328)
  • request_body max_size は、本文を何も読み取れなかったとしても、Content-Length が制限を超えるとすぐに 413 によるリクエストを拒否するようになりました。 (#8337)
  • index.php のない php_fastcgi サイト: 存在しないパスに対するリクエストは、文書化された first_exist_fallback 試行ポリシーで常に約束されているように、file_server にフォールスルーして 404 を返すのではなく、index.php として PHP に送信されるようになりました。また、PATH_INFO と DOCUMENT_URI は正規化されたパスから派生するようになりました (繰り返されたスラッシュが結合され、. セグメントが削除されました)。 REQUEST_URIは変更ありません。
  • / で終わる try_files / file 候補はディレクトリのみと一致するため、/foo.txt/ はファイル /foo.txt と一致しなくなります。 (#8326)
  • encode は、リクエスト に Cache-Control: no-transform がある場合でも応答を圧縮するようになり (応答の no-transform は引き続き尊重されます)、エンコードされた可能性のある応答は常に Vary: Accept-Encoding になります。古い動作を維持するには: @transformable not header Cache-Control *no-transform* および encode @transformable。 no-cache; no-transform のような不正な形式で圧縮が無効にならなくなりました。 (#8301、#8025)
  • より厳密な構成検証。 サイレントに受け入れられた (期待どおりの動作をしなかった) 一部の構成がエラーになるようになりました。
    • 同じマッチャー セット内の複数の expression 行 (&& と組み合わせる) (#8183)
    • 未知の TLS curves または protocol_min / protocol_max 名 (tls1.3 ではなく TLS1.3 など)。以前はサイレントに無視されていました (#8266)
    • TLS ポリシー match ブロック内で繰り返される sni_regexp (#8137)
    • ip_mask ログ フィルター サイズが範囲外です (IPv4 の 33 など) (#8241)
    • プレースホルダー展開後に同一になる basic_auth ユーザー名 (#8315)
    • 11 文字を超えるポート (#8277)
  • 評価順序は、ステータス コードを含む handle_errors ブロックおよび非パス マッチャーを含む vars の Caddyfile に従うようになりました。重複するコードがある場合、または同じ変数を 2 回設定した場合は、別のブロックまたは値が優先される可能性があります。 (#8195、#8197)

セキュリティ修正

責任を持って報告し、パッチに協力してくれた皆さんに感謝します。

  • caddyhttp: ドット セグメントまたはスラッシュを含む Host / :authority 値は、root /srv/sites/{host} のようにファイル パスで使用すると、意図したディレクトリをエスケープする可能性があり、php_fastcgi を使用すると、そのディレクトリ外でファイルを実行することもできます。このようなホストは拒否されるようになりました (上記を参照)。ありがとう@dunglas。 (GHSA-r766-rf9f-588h、#8328)
  • fastcgi: SCRIPT_FILENAME は、パス マッチャーが参照するのと同じ正規化されたパスから派生するようになりました。そのため、パス マッチャーで保護されたルートで別のスクリプトを実行することはできません。 /admin.php/../../other.php付き。 php_fastcgi の書き換えも常に実行されます (上記を参照)。ありがとう@pamnario。 (GHSA-f278-mgc7-46j3)
  • ファイルサーバー: file マッチャーは、/.env/./ のようなパスを通常のファイルに解決しなくなり、path *.env などのパス規則がバイパスされました。ありがとう@dunglas。 (GHSA-25cw-38mq-q7m6、#8326)
  • 書き換え: {http.matchers.file.remainder} は書き換え前にエスケープされるようになりました。そのため、パス ルールの実行後に、二重エンコードされたパス情報 (..%252f など) が ../ に変わることはありません。ありがとう@dunglas。 (GHSA-69hv-5jfc-mvmv、#8325)
  • ファイルサーバー: HOME も XDG_DATA_HOME も設定されていない場合、Caddy のデータ ディレクトリは ./caddy にフォールバックし、作業ディレクトリを提供する file_server が証明書と秘密キーを公開する可能性があります。そのディレクトリは常に非表示になりました。ありがとう@dunglas。 (GHSA-jf74-f69g-hcj9、#8327)
  • fastcgi: index.php を持つディレクトリの php_fastcgi 末尾スラッシュ リダイレクトを、別のサイトへのオープン リダイレクトに変換できなくなりました。ありがとう@sam-kota。 (#8285)
  • ファイルサーバー: hide で除外されたファイルは browse リストに表示されなくなり、非表示の precompressed サイドカーは提供されなくなりました。ありがとう@agammann。 (#8155)
  • リバースプロキシ: ホップバイホップ ヘッダーが 1xx 応答と handle_response 内の copy_response_headers から削除され、CVE-2026-55458 の修正が完了しました。 @SssiiiSssii1 と @tomholford に感謝します。 (GHSA-8qx7-j2v2-x6q5、#8256、#8270)
  • ロギング: query ログ フィルターは、サーバーと同様にリクエスト URI を解析するようになりました。そのため、# の後のパラメーターも編集されます。ありがとう@jayhemnani9910。 (#8255)

:警告: アプリケーションがバグのある動作に依存している場合、これらのセキュリティ パッチは壊れる可能性があります。

:rotating_light: Caddy プラグインの管理者への注意: dependabot はおそらく Caddy のセキュリティ修正について警告し、go.mod ファイルでそれをアップグレードするよう促します。プラグインが使用するエクスポートされた API に変更がある場合にのみ、Caddy 依存関係をアップグレードしてください。

このリリースに関わった皆さん、特に 28 名の新たな貢献者に感謝します。 :ただ:

何が変わったのか

  • caddyhttp: https://github.com/caddyserver/caddy/pull/8145 の @dunglas により、ハンドラーの書き込み期限にアイドル書き込みタイムアウトを制限させます
  • ファイルサーバー: https://github.com/caddyserver/caddy/pull/8155 の @agammann によるエントリと事前圧縮されたサイドカーを参照するための非表示ルールを適用します
  • テンプレート: https://github.com/caddyserver/caddy/pull/8149 の @jayhemnani9910 によるテンプレート エラーでファイル ヘッダーを削除
  • fastcgi: https://github.com/caddyserver/caddy/pull/8172 の @zemamba による再試行のためのダイヤル失敗の分類
