caddy v2.11.7

パッチ 公開日2026年10月3日 出典caddyserver/caddy 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#キャディv2.11.7

このパッチ リリースでは、HTTP/2 経由でプロキシする際のクラッシュや 1 分後に切断されるストリームなど、2.11.6 からのリグレッションが修正されています。 2.11.6 を使用している場合は、アップグレードすることをお勧めします。 また、新しい Incremental ヘッダー フィールド (RFC 10036) のサポートも追加されます。

リソースを活用してプロジェクトを存続させてくれたスポンサーと、この絶え間ない AI の新時代で精力的にトリアージと支援を行ってくれたメンテナーに多大な感謝を申し上げます。

ハイライト

  • 修正: 新しいアイドル タイムアウトによって引き起こされるクラッシュとストリームのドロップ。 2.11.6 ではデフォルトのアイドル読み取り/書き込みタイムアウトが導入されており、これによりいくつかの問題が発生しました。

    • 2.11.6 では、リクエスト本文のアイドル期限が、それを設定したハンドラーよりも長く存続する可能性があります。

      • HTTP/2 では、ハンドラーが戻った後もリバース プロキシがまだリクエスト本文を読み取っているときに、Caddy が nil ポインター逆参照でパニックを起こす可能性がありました。 (#8101)
      • HTTP/1.1 では、POST でストリームを開く SSE client など、本文を含むリクエストに対するストリーミング応答は、本文が読み取られてからちょうど 60 秒後に切断されました。 (#8103)

      どちらも #8107 で修正されています。ありがとう@steadytao!

    • HTTP/2 では、静かな SSE ストリームのように、書き込みの間に write_idle (デフォルトでは 1 分) より長く一時停止したストリーミング応答は、ストリーム エラーでリセットされました。文書に記載されているように、ストールした書き込みのみがカウントされます。ありがとう@WeidiDeng! (#8118、#8119)

  • 修正: 欠落した Cookie のプレースホルダーが再び空になります。 2.11.6 以降、respond ヘッダーなど、不明なプレースホルダーを記述どおりに保持する場所では、Cookie がリクエストに含まれていない場合に文字通り {http.request.cookie.*} を出力していました。プレーンな HTTP リクエストの {http.request.tls.*} でも同じことが起こりました。また両方とも空いてしまいました。ありがとう@steadytao! (#8019)

  • 新機能: Incremental ヘッダー フィールド (RFC 10036) のサポート。 これは、NGINX 独自の X-Accel-Buffering ヘッダーの標準的な代替品です。アップストリーム応答に Incremental: ?1 が含まれている場合、reverse_proxy は flush_interval -1 と同じように直ちにそれを転送し、encode はそれを保留する代わりにストリーミングします。 Mercure、SSE、その他のストリーミング アプリに最適です。

    • request_buffers または response_buffers オプションが増分転送を妨げる場合、Caddy は RFC の要求に従ってサイレント バッファリングではなく 501 Not Implemented で応答します。
    • 新しい proxy_status_name オプションは、メッセージが拒否された理由を説明する Proxy-Status ヘッダーを応答に追加します。

    ありがとう@dunglas! (#8020)

  • TLS ハンドシェイクの高速化: 証明書イベントにサブスクライブするものがなく、デバッグ ログがオフになっている場合、CertMagic はハンドシェイクごとにイベント データを構築しなくなります。ハンドシェイクごとの証明書の検索は、割り当てが 15 ではなく 10 になり、約 2 倍速くなります。@u5surf に感謝します。 (#8010)

  • Unix ソケット: リロードによりリスナー (または管理エンドポイント) が Unix ソケットから移動されると、古いソケットがすぐに閉じられ、そのファイルが削除されるようになりました。以前は、古いパスに接続している clients は、次のガベージ コレクション (約 2 分後) までハングしていました。ありがとう@littfed! (#8061)

  • ヘッダー ハンドラー: JSON 構成の set 内の複数の Set-Cookie 値は、client が解析できない 1 つのフィールドにカンマで結合されるのではなく、個別のヘッダー フィールドとして送信されるようになりました。ありがとう@Indra55! (#8080)

  • caddy fmt は、入力の最後にある左中括弧を削除しなくなりました。ありがとう@n0liu! (#8047)

何が変わったのか

  • イベント: https://github.com/caddyserver/caddy/pull/8010 の @u5surf によって発行する価値のあるイベントを CertMagic に伝えます。
  • 功績: @dunglas による Incremental ヘッダー フィールド (RFC 10036) を https://github.com/caddyserver/caddy/pull/8020 に実装
  • caddyfile: https://github.com/caddyserver/caddy/pull/8047 内の @n0liu による入力を終了する左中括弧を保持します。
  • リスナー: UNIX ソケットをすぐに閉じ、https://github.com/caddyserver/caddy/pull/8061 の @littfed によるリロード時にファイルのリンクを解除します
  • リバースプロキシ: https://github.com/caddyserver/caddy/pull/8049 で @steadytao によるハーフクローズ テストを安定化
  • caddyhttp: https://github.com/caddyserver/caddy/pull/8019 の @steadytao により、欠落しているオプションのプレースホルダーを空のままにします
  • ヘッダー: https://github.com/caddyserver/caddy/pull/8080 の @Indra55 によって個別の Set-Cookie 値を保持します。
  • caddyhttp: https://github.com/caddyserver/caddy/pull/8107 の @steadytao によるハンドラーによるリクエスト本文の期限所有権の終了
  • タイムアウト: アイドル ライターを修正し、https://github.com/caddyserver/caddy/pull/8119 の @WeidiDeng による書き込み間の h2 応答ライターを終了します。

新しい貢献者

  • @n0liu が https://github.com/caddyserver/caddy/pull/8047 に初めて投稿しました
  • @littfed が https://github.com/caddyserver/caddy/pull/8061 で最初の投稿を行いました
