#キャディv2.11.6

このパッチ リリースには、多数のマイナーな機能拡張といくつかの顕著な機能拡張とバグ修正が含まれています。このリリースを支援するために責任を持って LLM トークンを寄付または使用していただいた皆様に感謝します。

AI によってあらゆる品質レベルの貢献が安価かつ容易になったため、パイプラインにはまだ多くのプロジェクトがあります。私たちはできる限り迅速かつ効率的にそれらを実行するよう努めます。

リソースを活用してプロジェクトを存続させてくれたスポンサーと、この絶え間ない AI の新時代で精力的にトリアージと支援を行ってくれたメンテナーに多大な感謝を申し上げます。

:警告: アップグレードする前に、以下の重大な変更をお読みください。 それらのほとんどはセキュリティ強化によるもので、ほとんどの構成はそれに気づきません。ただし、古い動作のいずれかに依存している場合は、それについて知りたいと思うでしょう。

ハイライト

  • 新しい url_pattern リクエスト マッチャー: リクエストを URLPattern 標準、ブラウザ (JS) および多くの Web フレームワークで使用されるのと同じ構文と照合します。名前付きグループ、ワイルドカード、および正規表現コンポーネントをサポートします。キャプチャされたグループはプレースホルダー ({http.url_pattern.<component>.<group>}) になり、対応する url_pattern CEL 関数もあります。ありがとう@dunglas! (#7787)
  • Slowloris の軽減: 新しいアイドル読み取り/書き込みタイムアウトは、読み取りまたは書き込みが成功するたびにリセットされます。停止した接続は切断され、まだ進行中の遅い接続は放置されます。オプションの最小転送速度を設定することもできます。また、ルートごとに調整するための新しい timeouts ハンドラー ディレクティブもあります。 (#7913)
  • 新しい tls_automate_names グローバル オプション: 名前の証明書をサイト ブロックで提供せずに管理します。 (#8015)
  • 新しい expected_underscore_headers サーバー オプション: 2.11.4 でアンダースコアを含むヘッダー フィールドを削除するとアプリが壊れた場合、保持する特定のヘッダーをリストできるようになりました。 (#7809)
  • **初期の QUIC パケット サイズが小さいため、Tailscale およびその他の低 MTU リンク上の HTTP/3 が機能するようになりました。 (#7886)
  • リバース プロキシがさらに愛されるようになりました:
    • 部分応答が clients に適切にフラッシュされるようになりました (#7849)
    • TCP ハーフクローズがアップグレードされたストリームに伝播される (#8027)
    • versions 3 アップストリームは tls_trust_pool (#8042) を尊重するようになりました。
    • アクティブなヘルスチェック 状態はチェック構成ごとに個別に保持されるため、1 つのハンドラーのプローブが失敗しても、他のハンドラーに対してアップストリームがダウンとしてマークされることはありません (#7916)
    • random_choose ポリシーが正しく配布されるようになりました (#7873)
  • encode の背後にあるサーバー送信イベントは、バッファリングされずにすぐにストリーミングされるようになりました。 (#7905)
  • 正常なシャットダウン は、以前の構成で残ったサーバーを待機するようになりました。そのため、リロード前に開始された長時間有効な応答が終了時に切断されません。 (#8009)
  • Caddyfile: import は 名前付きルート 内で動作するようになり (#7986)、引用符で囲まれた中括弧はリテラル引数として扱われます (#7875)。
  • ロギング:
    • 新しい set_cookie ログ フィルター (#7888)
    • roll_interval は日数 (d) (#7900) を受け入れます
    • 回復されたハンドラーパニックはエラーレベルでログに記録されます (#7924)
    • 書き込みタイムアウト エラーがアクセス ログに表示される (#7945)
  • パフォーマンス: @jvoisin および @dunglas からのリクエスト ホット パス、エンコード ネゴシエーション、およびリバース プロキシの割り当てが減少します。大規模なディレクトリの場合、ディレクトリの参照がはるかに高速になります。 (#7847、#7903、#7911、#7925、#7926、#7936)
  • その他の新機能:
    • {http.request.proto_name} プレースホルダー (#7782)
    • FastCGI による SERVER_ADDR (#7912)
  • 複数の authentication プロバイダーが互いの応答を妨害しなくなりました (#7904)

:警告: 重大な変更

  • Go 1.26 は、Caddy とプラグインを構築するための最小バージョンになりました。 (#8056)
  • リクエスト ヘッダーはデフォルトで 16 KiB に制限されています。 以前は、Go のデフォルトの 1 MB を使用していました。より大きなヘッダー (巨大な Cookie、特大トークンなど) を持つリクエストは 431 Request Header Fields Too Large を取得するようになりました。さらに必要な場合は、max_header_size サーバー オプションを使用して値を上げてください。
  • デフォルトで新しい 1 分間のアイドル読み取り/書き込みタイムアウト。 リクエスト本文の読み取りまたは応答書き込みがそれより長く停止した (まったく進まなかった) 場合、接続は中止されます。 SSE と同様、書き込みの間の一時停止はカウントされません。 client の中央部が静かになる一部の長時間ストリームは影響を受ける可能性があります。これらは、timeouts サーバー オプションの read_body_idle および write_idle を使用して調整するか、timeouts ディレクティブを使用してルートごとに調整できます。 (#7913)
  • . を含むリクエスト ヘッダー フィールドは、2.11.4 のアンダースコアと同様に削除されます。 PHP は . を _ に折りたたむため、これらは正規のヘッダーを偽装するために使用される可能性があります。特定のものが必要な場合は、新しい expected_dot_headers サーバー オプションを使用して許可してください。
  • ワイルドカード サイトの client_auth は、独自のサイト ブロックを持つより具体的なホスト名には適用されなくなりました。 たとえば、public.example.com は *.example.com から mTLS を継承しなくなりました。その継承を期待している場合は、特定のサイトで client_auth を明示的に構成します。 (#7920)
  • より厳密な構成検証。 以前はサイレントに受け入れられていた (そしておそらく期待どおりに動作しなかった) 一部の構成が、現在はエラーになります。
    • 重複した named_routes (#7800)
    • 重複 forward_auth uri (#7814)
    • 無効な weighted_round_robin 重み (#7807)
    • 非整数 browse file_limit (#7988)
    • 重複または曖昧な map 入力 (#8067)
    • 不正な形式の map 宛先プレースホルダー (#8074)
    • 曖昧な @ バージョン区切り文字を含むモジュール パス (#7974)
  • 管理者 API /load は、構成が無効な場合に、有効な JSON 本文内で警告を含む 400 を返すようになりました。以前は、2 つの JSON オブジェクトが連結された 200 を返していました。 (#7267)
  • method マッチャー値は大文字に正規化されるため、method get は GET リクエストと一致するようになりました。 (#7832)

セキュリティ修正

責任を持って報告し、パッチに協力してくれた皆さんに感謝します。

  • リバースプロキシ: ルートで forward_auth と reverse_proxy の両方が使用されている場合、リクエストが間違ったアップストリーム接続に送信される可能性がありました。 @carlt によって報告され、@WeidiDeng によって修正されました。 (GHSA-6365-7ppr-5r92、#7859)
  • リバースプロキシ: 上流からのホップバイホップ ヘッダーも 101 Switching Protocols 応答から削除されるようになりました。 @jirn073-76 に感謝します。
  • caddyhttp: handle_path および uri strip_prefix/strip_suffix は、結果のパスを正規化するようになり、パスベースの認証をバイパスできなくなりました。ありがとう@steadytao。
  • caddyhttp: PHP/FastCGI バックエンドで forward_auth copy_headers をバイパスしないように、2.11.4 ヘッダー エイリアス フィルターを . (上記を参照) に拡張しました。ありがとう@dunglas。
  • caddyhttp: path_regexp マッチャーは、path マッチャーと同様に Windows のバックスラッシュを正規化するようになりました。これで CVE-2026-52844 の修正は完了です。ありがとう@thientd。 (#7858)
  • ファイルサーバー: Windows 8.3 の短縮名は、最後のパス コンポーネントだけでなく、すべてのパス コンポーネントで拒否されます。ありがとう@DavidCarliez。 (#7952)
  • ファイルサーバー: 変更時間とサイズが異なるファイル間の ETag の衝突を修正しました。ありがとう@dunglas。
  • fastcgi: client の Proxy ヘッダーが HTTP_PROXY (HTTPoxy) としてバックエンドに渡されなくなりました。ありがとう@bzyy1024。 (#7934)
  • reverseproxy: スティッキー セッション Cookie のハッシュが一定時間で比較されます。ありがとう@alhudz。 (#7853)
  • admin: リクエスト パスはリモート管理者アクセス チェックで正規化され、オリジン/ホストの許可リストは大文字と小文字を区別せずに比較されます (多層防御)。 @AmariahAK、@mohammed90、@hktitof に感謝します。 (#7910、#7973、#7993)
  • caddyhttp: プレースホルダーを介して使用される特大のリクエスト本文が正しく 413 を返すようになりました。ありがとう@hktitof。 (#7969)

:警告: アプリケーションがバグのある動作に依存している場合、これらのセキュリティ パッチは壊れる可能性があります。

:rotating_light: Caddy プラグインの管理者への注意: dependabot はおそらく Caddy のセキュリティ修正について警告し、go.mod ファイルでそれをアップグレードするよう促します。プラグインが使用するエクスポートされた API に変更がある場合のみ、Caddy 依存関係をアップグレードしてください。 これを行うには Go 1.26 も必要になることに注意してください。

このリリースに関わった皆さん、特に 40 名の新たな貢献者に感謝します。 :ただ:
