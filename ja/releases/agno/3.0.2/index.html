agno v3.0.2

#アグノv3.0.2 #Changelog

動作の変更

  • 実行メタデータの優先順位: metadata は、Agent、Team、および Workflow のコンポーネント、次にセッション、その後コールサイトとして解決されるようになりました。そのため、run() に渡された metadata= は、コンポーネント値が以前に勝っていた agent.metadata よりも優先されます。実行ではセッション メタデータが共有コンポーネントに割り当てられなくなりました。そのため、実行後にセッション値を監視するために agent.metadata を読み取るコードは、コンストラクターの値を参照するようになりました。セッション層は、ディスパッチがセッションを事前に読み取る場合にのみ適用されるため、Team.arun と async-DB エージェントおよびワークフロー パスは引き続きコンポーネントと呼び出しサイトのみから解決されます。 (#9104)
  • MCPConfig は不明なフィールドを拒否します: MCPConfig/MCPServerConfig は、認識できないキーワード引数を無視するのではなく構築時に発生させるようになりました。そのため、tool= などのタイプミスは、別のツール サーフェイスをサイレントに提供するのではなく、起動時に失敗します。 (#9819)
  • BaseRemote.acancel_run シグネチャ: 抽象メソッドは、キャンセル サーフェスがキーワードによって渡す auth_token パラメータを取得したため、サードパーティの BaseRemote サブクラスはそれを受け入れる必要があります。 (#9819)
  • 推論検出はプロバイダーに問い合わせます: ネイティブ推論検出は、モデル ID 照合にフォールバックする前にプロバイダーに問い合わせるようになりました。そのため、思考用に構成された Gemini または Claude モデルは、プロバイダーが思考がサポートされていないと報告した場合、非推論として分類されます。ルックアップは、推論マネージャーにキャッシュされたブロッキング HTTP 呼び出しであり、Ollama、OpenRouter、および Moonshot パスで 10 秒のタイムアウトが発生します。 ID ベースのフォールバックも変更されました。gpt-5 バリアントは OpenAI と Azure OpenAI で一致し、Groq と Ollama は gpt-oss と qwen3 に一致し、Ollama の qwen2.5-coder は推論モデルとして扱われなくなりました。 (#8616)
  • MCP 構成の名前変更: AgentOS(mcp=...)、MCPConfig、および default_tools は、mcp_server=、MCPServerConfig、および enable_builtin_tools の新しいスペルです。古い名前は、3.1 を対象とした削除によりエイリアスとして機能し続けます。両方のスペルを異なる値で渡すと、値が上がります。 (#9819)

新しい統合

  • Synthorai モデル プロバイダー: Synthorai (agno.models.synthorai) は、OpenAI 互換エンドポイントを介して Synthorai ゲートウェイと通信し、SYNTHORAI_API_KEY を読み取り、デフォルトで https://synthorai.io/v1 を設定します。プロバイダー参照テーブルに登録されているため、model="synthorai:<model-id>" 文字列も解決されます。 (#9788)
  • WaveSpeed 画像およびビデオ生成: WaveSpeedTools (pip install agno[wavespeed]、WAVESPEED_API_KEY からのキー) は、WaveSpeed API を通じてメディアを生成します。 generate_image と generate_video はテキスト プロンプトを受け取り、Image/Video アーティファクトを含む ToolResult を返し、poll_interval と timeout 内で同期的にポーリングします。 (#9620、#9621 を修正)
  • Serply 検索ツールキット: SerplyTools は、Serply API を通じて Google Web、ニュース、および Scholar を検索し、SERPLY_API_KEY と読み取ります。 Web 検索はデフォルトでオンになっています。 search_news、search_scholar、または all=True はその他を有効にします。キーが見つからない場合、またはリクエストが失敗した場合は、発生する代わりに error フィールドが返されます。 (#9780、#9779 を修正)
  • AtomicMail ツールキット: AtomicMailTools はエージェントに独自の受信箱を提供します。 register_inbox は、ドメインの設定や人間による検証を行わずに AtomicMail の Proof-of-Work サインアップを通じてプロビジョニングを行い、send_email と list_inbox は JMAP 上で動作します。資格情報は ~/.atomicmail/credentials.json にキャッシュされるため、後の実行では同じ受信トレイが再利用され、pow_timeout (デフォルトは 300 秒) が解決の上限となります。 (#9130)

改善点

  • MCP ツールとしてのエージェント、チーム、およびワークフロー: MCPConfig.tools は、Agent、Team、および Workflow インスタンス、リモート プロキシ、コンポーネント ファクトリを受け入れ、それぞれを独自の名前付き MCP ツール (run_agent(agent_id="chief") ではなく chief) として公開します。 component.as_tool(name=..., description=...) は、選択した名前と説明で公開します。 continue_run および cancel_run は、default_tools=False であっても公開コンポーネントと一緒に登録されるため、確認時に一時停止した実行は MCP 経由で再開可能です。 (#9819)
  • MCP ツールとしてのツールキット: MCPConfig.tools は Toolkit を受け入れ、登録されたメソッドごとに 1 つの MCP ツールを公開します。以前は TypeError を発行していましたが、ツールキット自体の enable_*/include_tools/exclude_tools によって絞り込まれます。フレームワーク パラメーター (RunContext、Agent、Team、および _agno_* チャネル) は、cli 側向きのスキーマから除外され、サーバー側で埋められます。 ToolResult を返すツールは、MCP コンテンツ ブロック (テキスト、画像、音声、ビデオとファイル バイトの埋め込みリソース、URL のみのアーティファクトの resource_link) としてレンダリングされます。以前に get_app() を停止した **kwargs エントリポイントは、宣言されたスキーマまたは名前付きパラメータを公開するようになりました。 (#9846)
  • MCP ツールのタイトルと動作の注釈: as_tool() および @tool/Function は、AgentOS が公開コンポーネント、カスタム ツール、および 8 つの組み込みツール用に MCP 経由で公開する title および annotations を受け入れるようになりました。公開されたコンポーネントは、何も設定せず、デフォルトで readOnlyHint: False、destructiveHint: True、openWorldHint: True をアサートした場合でも、キーごとにオーバーライドがマージされてタイトルを公開します。不明な注釈キーは、client に移動せずに発生します。 (#9844)
  • コンテキスト プロバイダー query_timeout および write_tools: すべてのコンテキスト プロバイダーは、実行をハングする代わりにエラー チャンクを生成する各 query_<id> ツール呼び出しに適用される実時間の期限である query_timeout を受け入れます。 Python 3.11以降が必要で、それ以下の施工では値上がりします。 5 つの書き込み可能なプロバイダーは、デフォルトの書き込みサブエージェント ツールセットを置き換える write_tools も受け入れます。 (#9104)
  • Wiki GitBackend は PAT をディスクから切り離します: トークンは origin URL にベイクされるのではなく、一時的な資格情報ヘルパーを介して git 呼び出しごとに挿入され、既存のクローンはセットアップ時にベア URL に書き換えられます。これには git 2.31 以降が必要です。 (#9104)
  • Slack 配信オプションとより安全な承認カード: Slack インターフェースに markdown、unfurl_links、unfurl_media が追加され、すべてのメッセージで明示的に送信されるようになりました。承認カードは、モデル生成ツール引数内のバッククォート、改行、および山かっこを不活性にし、インライン コード スパンから抜け出すことができません。 (#9104)
  • ヘッドレス Google OAuth: Google ツールキットは、ヘッドレス ホストでは決して完了しないブラウザ OAuth フローをブロックする代わりに、AuthConfig(interactive=False) または GOOGLE_OAUTH_NONINTERACTIVE=1 を受け入れます。 (#9104)
  • スケジュール リスト: 新しい ScheduleManager.list_all() および alist_all() は、get_schedules の新しい raise_on_error 引数に基づいて、空のカタログを返すのではなく、スケジュール カタログ全体とサーフェス データベース エラーをページングします。リストでは created_at の関係が id までに解消されるようになったため、タイムスタンプを共有する行がページ間でスキップされたり重複したりすることはなくなりました。 (#9104)
  • ムーンショットおよび OpenRouter 推論: MoonShot (Kimi) は、reasoning_content を読み取る同期、非同期、およびストリーミング推論ハンドラーを取得し、OpenRouter は OpenAI 推論パスを通じてルーティングされます。以前は、両方の ID にたまたま deepseek-r1 または minimax-m2/m3 が含まれていた場合にのみ、両方が選択されました。 (#8616)
  • MCP 構成のスコープがゼロ ツールに限定され、警告が表示されるようになりました: デフォルト ツールがオンになっているが、include_tags/exclude_tags ではすべてのタグがスコープ外であり、カスタム tools が渡されなかった場合、MCPConfig は構築時に警告をログに記録します。つまり、/mcp エンドポイントを起動する構成には何もリストされません。設定は引き続き受け入れられ、解決されたツール サーフェスは変更されません。 (#9748)

バグ修正

  • IPython 9.17 の CodeMode(allow_shell=False): IPython 9.17 はスクリプト マジックを遅延登録し、検索時に再作成するため、セル マジック テーブルから bash を削除しても無効になりません。%%bash はシェル アクセスを禁止するように構成されたカーネルで引き続き実行されました。カーネルは、最初にスクリプト マジック プロバイダーを実体化し、遅延テーブルとライブ レジストリの両方から bash を削除するため、%%sh などの兄弟マジックをロードしても再登録できません。
  • スタンドアロン プロセスからのレジストリ MCP ツールキット: StudioTools は、ツールの解決中に、未接続のレジストリ MCP ツールキットをオンデマンドで接続するようになりました。そのため、スクリプト、ノートブック、または評価実行からコンポーネントを作成または編集しても、「ツールキットには機能がないため永続化できません」というメッセージが表示されて失敗することがなくなりました。 eval.suite.cli/acli は、ケースの実行前にこれらのツールキットを接続する新しい mcp_tools=[...] 引数を受け取り、MCPToolbox は close() および失敗したフィルターの client 状態をクリアするため、再接続により toolsets/tool_name が再適用されます。 (#9845)
  • ストリーミング ワークフロー ステップでのエグゼキュータ エラー: Step の Agent または Team エグゼキュータがストリームの途中で失敗すると、ストリーミング パスはエラー イベントを終了したステップとして扱い、空の StepOutput と success=True を発行しました。 Step.execute_stream および Step.aexecute_stream は、ステップとその実行プログラムに名前を付ける RuntimeError を生成するようになりました。そのため、障害は通常のステップ エラー処理を経て、結果の StepOutput には success=False とエラー テキストが含まれます。失敗したストリーミング ステップは、他のステップの失敗と同様に再試行されるようになりました。 (#9138、#7185 を修正)
  • 一時停止実行パネルでのツール引数の切り詰め: 人間参加型パネルは rstrip(", ") を使用して引数リストを構築しました。これにより、接尾辞ではなく一連の文字が削除されるため、最後の引数自体の値に属する末尾のコンマとスペースも取り込まれます。 3 つのブロックはすべて、format_tool_calls がすでに行っていた方法で引数を結合するようになりました。これは表示専用です。ツールに渡される引数は影響を受けませんでした。 (#9246、#9248 を修正)

料理本

  • gpt-4o、gpt-4o-mini、または gpt-5.4-mini を固定したクックブックの例は、355 ファイルにわたって gpt-5.6-luna を使用するようになりました。ゲートウェイの例も書き直されたため、LiteLLM、OpenRouter、AzureOpenAI、AzureAIFoundry、CometAPI、Requesty、LangDB、および AIMLAPI の例は、gpt-5.6-luna を解決するゲートウェイまたは Azure デプロイに依存します。特殊な ID と日付付きスナップショットは変更されません。 (#8939)
