agno v3.1.0

#アグノv3.1.0

新機能

  • ユーザー管理/認可 (RBAC): 新しい agno.os.authz パッケージは、役割ベースのアクセス制御を AgentOS に追加します。これには、役割ストア、スコープ ポリシー、監査ログ、ユーザー ディレクトリ、プラグイン可能な認可エンジン (ネイティブ エンジンときめ細かな fga エンジン) を備えた管理ルーターが含まれます。これを強制するために、スコープと認証ミドルウェアが拡張されました。
  • AgentOS ファイルシステム: agno_fs テーブルに基づく専用の /filesystem ルート (ファイルのリスト/読み取り/管理) を備えた新しい agno.fs ファイルシステム (DbFileSystem)。
  • MCP 構成 / 認証の更新: MCP サーバー構成と組み込みの MCP 認証処理が更新されました。
  • AIMLAPITools: AI/ML API を介した画像、ビデオ、音声、文字起こしのための新しいツールキット。

⚠️重大な変更

  • ファイルシステム テーブルの再キー (agno_fs): v3.1 は、(namespace, user_id, path) によってファイル システム テーブルのキーを設定します。ここで、user_id はユーザー パーティション (共有/非ユーザー パーティションの場合は "") です。以前のリリースで作成されたテーブルは、アップグレードされるまで SchemaOutdatedError で拒否されます。キーの再生成は自動的には実行されません。データベースのスクリプトを使用して、アプリケーションを停止して一度アップグレードします (#10530)。 これは、DbFileSystem を使用している場合にのみ影響します。テーブルはDbFileSystem（独自のスキーマ、裸のdb_urlから構築可能）によって管理されているため、意図的にMigrationManagerの一部ではありません。
python libs/agno/migrations/migrate_filesystem_postgres.py   # PostgreSQL
python libs/agno/migrations/migrate_filesystem_sqlite.py     # SQLite
  • MCP のデフォルトおよびライフサイクル ツールがオプトインになりました: MCPConfig(tools=[...]) は、リストしたツールを正確に公開するようになりました。default_tools と lifecycle_tools のデフォルトは両方とも False です。以前は、tools=[...] 構成は、組み込みのデフォルト ツール (およびライフサイクル continue_run / cancel_run) も提供していました。

バグ修正

  • HITL: background + stream を使用して一時停止した実行を継続しても、一時停止した実行がそれ自体の履歴に複製されなくなりました。
  • OpenAIResponses: 連鎖された (以前の) 応答がなくなったときにリクエストを回復します。
  • DB: 失敗した非同期削除は、存在しなかった実行として報告されなくなりました。この 2 つのケースは区別されます。
  • 構造化出力: JSON フラグメントがリストの前にスカラーを提供する場合でもクラッシュしません。
  • Python ツールの結果: None 値のある結果と欠落している変数を区別します。
  • チャンキング: チャンク サイズ以上の重複を拒否します。
  • CSV リーダー: CR (\r) レコード末尾を処理します。
  • CsvTools: 明示的なゼロ行制限を尊重します。
  • シェル/ワークスペース コマンド ツール: 明示的なゼロ tail を尊重します。
  • GeminiTools: 生のビデオバイトを generate_video アーティファクトに保存します。
  • GithubTools: リポジトリ Web URL (#10509) からブランチ リンクを構築します。 get_file_content は有効な非 ASCII UTF-8 テキストを保持します
  • LocalFileSystemTools: ローカル ファイルを UTF-8 として読み書きします。
  • PubMed: 短い要約のメタデータを保存します。
  • クロードの引用: ヌル値を許容する文書タイトルを保持します。
