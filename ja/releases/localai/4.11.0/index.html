#ローカルAI v4.11.0

🎉 LocalAI 4.11.0 リリース! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.11.0 が登場しました！

このリリースにより、LocalAI は音声の理解、復元力のあるモデルの提供、構造化された意思決定、日常の運用においてさらに便利になります。オーディオ シーンでは、文字起こし、ダイアライゼーション、音声検出、記憶された話者名を組み合わせることができるようになりました。順序付けされたフェイルオーバー チェーンにより、パブリック モデルがローカルおよびリモートのターゲット間で利用可能に保たれますが、新しい Studio ページと操作ページでは、分散モードを必要とせずにこれらの機能が公開されます。

このリリースでは、/v1/systemone、署名付き OCI モデル ギャラリー、Kimodo テキストからアニメーションへのファーストクラスの意思決定モデルも追加されています。これには、243 件のマージされたプル リクエスト、353 件のコミット、79 件の新しいギャラリー エントリ、API とバックエンドにわたる重点的な修正、広範なバックエンド ソースの更新が含まれます。

ハイライト:

  • 🎙️ オーディオ シーンと記憶された話者 - 音声テキスト変換、話者ダイアライゼーション、サウンド イベント検出、話者識別を組み合わせます。 Studio では、録音を日記化し、クリーン間隔をプレビューし、選択したスピーカーを名前で登録できます。
  • 🔀 モデル フェイルオーバー チェーン - ローカル ターゲットとリモート ターゲットを 1 つのモデル名の背後に配置し、応答コミットの前に再試行し、ヘルスとターゲットの切り替えを観察し、API、MCP ツール、または React UI からターゲットを固定します。
  • 🧭 意思決定モデル - decisions のユースケースを宣伝し、検証と専用のギャラリー モデルを使用して、/v1/systemone を通じて構造化された選択、スコア、および noul の質問に答えます。
  • 📦 署名付き OCI ギャラリー - 完全なモデル ギャラリーを OCI アーティファクトとして配布し、Sigstore ポリシーで検証し、ダイジェスト バインドされた最新の既知の有効なキャッシュを使用します。
  • 🕺 Kimodo テキストからアニメーションへ - POST /3d/animate を通じてテキストから骨格モーションを生成し、Studio でプレビューし、バイナリ glTF アニメーションをエクスポートします。
  • 🖥️ このマシンを操作 - 分散モードを有効にせずに、単一の LocalAI ホスト上でリソースとローカルにロードされたモデルを検査し、ログを表示し、モデルを停止します。
  • 🛡️ より安全なギャラリーと API の動作 - パス制限の修正、より厳密な認証情報チェック、プレストリーム エラーの修正、ストリーミングされた応答アイテムの保持、およびより信頼性の高いモデルのインストール。

さらに、チャットでの PDF 添付ファイルの抽出、より詳細な Hugging Face リポジトリの検出、改善されたハードウェア検出、新しいイタリアン パイパーの音声、NeMo ダイアライゼーションと ASR モデル、および大規模なモデル ギャラリー バッチが追加されました。

🚀 新機能と主要な機能強化

🎙️ オーディオ シーン: スピーチ、スピーカー、サウンド

parakeet-cpp は、音声をトランスクリプト単独ではなくシーンとして扱うことができるようになりました。 1 つのモデルは、音声認識、話者ダイアライゼーション、サウンドイベント分類を実行し、定期的およびリアルタイムのリクエストに対して調整された話者と音声の情報を返すことができます。

  • POST /v1/audio/diarization は、ダイアライゼーションのセグメントと話者の概要を返します。
  • include_text=true は、ダイアライゼーションと ASR を組み合わせます。
  • include_speaker_profiles=true は、バージョン管理されたスピーカー プロファイルを明示的に要求します。
  • 転写セグメントは speaker_name を獲得します。トランスクリプトの単語には speaker ラベルを付けることができます。
  • リアルタイム セッションは conversation.item.input_audio_transcription.segment および conversation.item.sound_detection イベントを発行します。
  • シーン モデルは、リアルタイム パイプラインでダイアライゼーションを有効にして、transcription と sound_detection の両方に対応できます。
  • 新しいギャラリー エントリには、Nemotron 3 ダイアライゼーション、ダイアライゼーション プラス ASR、CED サウンド モデル、およびリアルタイム シーン バリアントが含まれています。 話者のプロファイルは機密の生体認証データです。プロファイルのエクスポートはオプトインであり、音声認識の許可が必要ですが、それ自体は個人を登録しません。

🔗 PR: #12335、#12382

🗣️ 発言者の名前を付けて覚えておいてください

LocalAI は、共有音声レジストリに登録されている音声とダイアライズされたセグメントを照合できます。互換性のある parakeet-cpp 構成では、speaker_model、speaker_threshold、および speaker_margin を使用します。既知の音声は匿名ラベルを名前に置き換えますが、未知の音声は SPEAKER_NN のままです。

Studio には、通常の録音から登録するためのダイアライゼーション ページが追加されます。各スピーカーのクリーンな間隔を検出し、オーディオ プレビューを提供し、ユーザーが [名前を付けて記憶する] を選択した場合にのみプロファイルを登録します。プロファイルと記録はブラウザーのストレージには保持されず、関連するリクエスト本文は API トレース キャプチャから除外されます。

現在、レジストリはプロセスローカルで一時的なものです。名前は再起動後に消え、独立したフロントエンド間では同期されません。エンコーダ ID は登録と認識の間で正確に一致する必要があります。

🔀 フェイルオーバー チェーンと localai-proxy のモデル化

1 つのパブリック モデル名が、ローカル ターゲットとリモート ターゲットの順序付けられたチェーンを表すことができるようになりました。

name: assistant-llm
failover:
  targets:
    - model: preferred-local
    - model: remote-localai
      warm: true

LocalAI は、応答コミット前に失敗が発生した場合にのみ、次のターゲットを再試行します。トランスポート エラー、サーバー エラー、OOM、およびレート制限により、ターゲットがトリップする可能性があります。検証エラー、通常の client エラー、および client キャンセルには含まれません。回復プローブと最小フォールバック滞留期間により、rapid ターゲットのフラッピングが防止されます。

リリースには次のように追加されています。

  • GET /api/failover、GET /api/failover/{chain}、GET /api/failover/events。
  • 管理者の固定および固定解除操作。list_failover_chains、pin_failover_target、および unpin_failover_target MCP ツールとしても使用できます。
  • X-LocalAI-Served-Model および X-LocalAI-Failover 応答ヘッダー。
  • リアルタイム セッションの localai.model.failover イベント。
  • フェールオーバー チェーン モデル テンプレート、ライブ ヘルス ストリップ、ピン コントロール、インストール済みモデル バッジ、および 操作 → ランタイム → フェールオーバー ページ。
  • LocalAI REST 機能を別の LocalAI エンドポイントにルーティングするための localai-proxy OCI バックエンド。

🧭 構造化された意思決定とゼロショット抽出

意思決定モデルは、ファーストクラスの LocalAI 機能になりました。モデルは known_usecases: [decisions] を宣言し、Decisions チップとともに表示され、POST /v1/systemone を通じて既存の SystemOne コントラクトを提供します。 LocalAI はこのユースケースを推論しないため、意思決定モデルはチャットやトークン分類モデルとは区別されます。

リクエスト パスでは、64 KiB の本文制限、最大 64 個の質問、状態、ID、オプション数、レベル、noul 基準の検証が適用されるようになりました。 vllm-cpp は、統合された決定 ABI を通じて構造化された結果を伝達し、hf_overrides は、ダウンロードされたスナップショットを変更せずに、必要な最上位モデル構成をマージできます。 ギャラリー エントリには、Laya、GLiNER2.5-Decide、Qwen3-VL、Tev1、kev、Nimble、および CLM 意思決定モデルが追加されています。既存の /permute および /separate エンドポイントは、NER およびトークン分類用に残ります。

🔗 PR: #12247、#12373、#12379、#12391、#12397

📦 署名入り OCI モデル ギャラリー

モデル ギャラリーを自己完結型の OCI アーティファクトとして出荷できるようになりました。アーティファクトには index.yaml および関連モデル構成ファイルが含まれるため、レジストリは別の Web ホスト型インデックスなしで完全なギャラリーを配布できます。

LocalAI は、タグをダイジェストに解決し、そのダイジェストに対して署名を検証し、同じダイジェストを取得し、アーティファクト タイプとレイヤーのメタデータを検証し、レイヤー数とサイズの制限を強制し、抽出されたパスを制限し、完全な抽出と解析後にのみギャラリー キャッシュをプロモートします。検証ポリシーには正確な source_repository URL が必要な場合があり、キャッシュ ID にはアクティブな検証ポリシーが含まれます。

厳密整合性モードでは、検証ブロックのない OCI ギャラリーが拒否されます。署名またはポリシーが失敗しても、古いキャッシュにはフォールバックしません。一時的なネットワーク障害では、同じポリシーに基づいて以前に検証されたコンテンツを使用できます。

🔗 PR: #12167、#12138、#12235、#12238、#12239、#12243

🕺 Kimodo テキストからアニメーションへ

LocalAI は、骨格モーション生成のためのネイティブ kimodocpp バックエンドと Studio ワークフローを追加します。 POST /3d/animate は、UTF-8 prompt を 1 つだけ受け入れ、さらに frames、steps、seed、および text_guidance を受け入れます。 30 FPS でバイナリ glTF アニメーションを生成し、metadata.usage を通じて使用状況を報告します。

バックエンドには、CPU と Vulkan ビルド、複数のモデルと量子化ギャラリー エントリ、トレース、および使用量のアカウンティングがあります。 Studio は、生成コントロール、アニメーション プレビュー、ローカル履歴を提供します。 API は人型メッシュではなくスケルトン アニメーションを生成し、フレーム数は 60 ～ 150 に制限されます。

🔗 PR: #12095、#12162、#12184

🖥️ このマシンを操作する

単一ノードのインストールには、ローカル ホストの操作ページが追加されました。 「操作」→「このマシン」 では、VRAM、RAM、CPU、モデル ディスクのリソース ゲージが表示され、実行中の各モデルとそのバックエンド、常駐メモリ、CPU シェア、稼働時間、および PID がリストされます。

オペレーターは、テーブルの検索と並べ替え、バックエンド ログの表示、確認後のモデルの停止を行うことができます。 「操作の概要」→「現在実行中」 には、最も重い 5 つのモデルが表示され、ランタイム ナビゲーションには実行中のモデルの数が含まれます。分散モードでは、ルートはクラスター ノード ワークベンチを表示し続けます。
