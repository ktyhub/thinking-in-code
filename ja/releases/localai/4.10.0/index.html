LocalAI 4.10.0 登場！

28 日間で 280 件のプル リクエスト。この作業は、フリートの運用、プライベート ソースからのモデルの供給、依存するバックエンドの修正という 3 つの面で行われました。フリート操作ダッシュボードは、フラットなノード リストをクラスター全体の健全性、容量、実行中のモデル、および一括ライフサイクル アクションに置き換えます。資格証明ファイルを使用すると、環境変数間でトークンを分散させることなく、1 つの credentials.yaml で OCI レジストリ、ギャラリー、および直接ダウンロードを認証できます。また、local-ai benchmark は、CLI からのエンドツーエンドの遅延とスループットを測定します。

ds4 バックエンドには、CUDA 上での信頼性を高める 4 つの修正が加えられました。カーネルがターゲット アーキテクチャに合わせて構築されるようになり、放棄された推論がキャンセルされ、世代境界が強制され、事前入力された推論がコンテンツから分離されるようになりました。分散モードでは、ステージング、ライブネス、仮想モデル、およびコントロール プレーン データベースにわたって 7 つの安定化修正が行われました。 4 つの CVE にパッチが適用され、enable_thinking=false がすべてのテキスト バックエンドで受け入れられるようになり、Apple M5 は起動時に SIGSEGV を実行しなくなります。

🚀 新機能と主要な機能強化

📊 フリート運用ダッシュボード

[ノード] ページは、ノードごとのカードのフラット リストでした。何が登録されているかは表示されますが、クラスターが何を実行しているかは表示されません。また、すべてのライフサイクル アクションは一度に 1 つのノードで行われました。

書き換えられたのは、2 つのタブと共有サマリー ポーラーを備えたフリート運用ダッシュボードです。

ClusterOverview が最上位にあります。ヘルスバンドは、ノードを健全なカウント、消耗カウント、注意カウントに分割します。容量ゲージには VRAM、RAM、CPU、ディスクが表示され、それぞれがそのメトリックを報告しないワーカーの数を報告するため、数値はレポート ノードの平均ではなく正確になります。アテンション キューは、承認待ち、オフライン/異常、VRAM 不足、RAM 不足、ディスク不足をフィルタリングし、ヘッドラインの合計を二重にカウントすることなく、アクションが必要なノードを表示します。 NodeFleetTable は並べ替え可能、グループ化 (ラベルまたはタイプ別) が可能で、1 ページあたり 50 行でページ分割され、チェックボックスの選択はフィルターやページ間で保持されます。一括ドレイン、再開、削除は制限された同時実行数 (制限 8) で実行されるため、数千の登録を持つフリートを使用できます。列: ステータス ピル、アドレス、容量 (VRAM + RAM)、CPU、ワークロード、ハートビート。承認ボタンは保留中のノードに表示されます。

[実行モデル] タブ。 正常なワーカーに読み込まれたレプリカのフリート全体のビュー。モデル名、レプリカ数、ノード数、実行中のリクエスト、バックエンド タイプ、最後に使用されたモデルごとにグループ化されます。モデルごとの停止は、POST /backend/shutdown {model} を通じてすべての配置をシャットダウンします。これにより、ローカル プロセスが存在する場合でもリモート アンローダーが起動され、停止メッセージを送信する前にノードが重複排除されます。

インスペクター スライド式の NodeInspector には、健全性、ラベル、リソース バー、CPU、ロードされたモデル数、バックエンド (遅延ロード)、および処理中の状態が、承認/ドレイン/再開アクションとともに表示されます。 ModelInspector には、NodeInspector にドリルダウンする clickable ノード名を使用して、ノードごとにグループ化されたレプリカの配置が表示されます。

従業員は登録時とハートビート時に cpu_logical_cores、cpu_usage_percent、cpu_load_1 を報告するようになりました。ダッシュボードには、CPU の容量と使用率が表示され、アイドル状態のコアは cpu_logical_cores * (1 - cpu_usage_percent / 100) として導出されます。

ライフサイクルの移行はアトミックになりました。 MarkDraining は、SetNodeModel とインターリーブできる個別の操作としてではなく、1 つのトランザクションでステータスを反転し、モデル レコードを削除します。 ResumeNode は条件付きです。正常な状態のみにドレインし、保留中の承認または同時の状態変更の上書きを防ぎます。 HTTP エンドポイントは、一般的な 500 ではなく、適切な 404 (見つからない) と 409 (ステータスの競合) を返します。

🔑 プライベート ソースの認証情報ファイル

バックエンド、モデル、ギャラリー インデックスは、プライベート OCI レジストリ、内部 HTTP サーバー、またはプライベート GitHub リポジトリの背後に存在できます。これまでは、各ダウンロード パスには独自のアドホック認証メカニズムがあり、トークンは環境変数全体に分散していました。

--credentials-file / LOCALAI_CREDENTIALS_FILE によってロードされる 1 つの credentials.yaml ファイルが、それらすべてを認証します。これは、ルールのトップレベル YAML リストです。各ルールには、match URL プレフィックスと、基本 (username + password / ZZPH100​​ZZ / password_file)、ベアラー (bearer / bearer_env / bearer_file)、またはカスタム ヘッダー (header.name + header.value / header.value_env / header.value_file) の 1 つの認証タイプがあります。シークレットごとにプレーン、_env または _file 形式のいずれか 1 つ。不明なキーはエラーであるため、pasword_env のスペルが間違っていると大声で失敗します。

OCI レジストリ (バックエンド イメージ、oci:// および ollama:// モデル、ダイジェスト ルックアップ、範囲再開、コサイン検証) は、最初にストアに問い合わせてから、authn.DefaultKeychain (docker 構成) を問い合わせます。 HTTP ダウンロード、ギャラリー、および github: URI は、要求のクローンに資格情報を置く http.RoundTripper を通じて認証されます。 net/http は元のヘッダーから各リダイレクト ホップを再構築するため、別のホストへのリダイレクトで資格情報が伝達されることはありません。呼び出し元が指定した資格情報 (例: HF_TOKEN) が優先されます。トランスポートでは、既存の Authorization ヘッダーはそのまま残されます。 シークレットはロード時ではなく使用時に読み取られるため、ローテーションされた K8s シークレット マウントは再起動しなくても有効になります。 Credential および Store は String、GoString および LogValue を実装しているため、エクスポートされていないフィールドにネストされている場合を含め、fmt 動詞または slog 呼び出しは機密マテリアルを出力できません。資格情報は https にのみ送信され、ルールで allow_insecure が設定されている場合は http にのみ送信されます。 user:token@、? (署名付き URL にはトークンが含まれる)、または # を含む一致文字列はロード時に拒否されます。 YAML デコード エラーは編集されます。引用符で囲まれたスカラー値 (多くの場合は秘密) が削除され、行番号とパーサーの文言のみが保持されます。

📏 local-ai benchmark CLI コマンド

構成されたテキスト モデルのベンチマーク コマンド。ターミナルを離れることなく、「このハードウェアでのこのモデルの速度はどれくらいか」に答えます。

local-ai benchmark MODEL [MODEL ...] は、構成可能な --runs (デフォルト 3)、--warmup (デフォルト 1)、--max-tokens (デフォルト 128)、および --timeout (デフォルト 5m) を使用して、非ストリーミング POST /v1/chat/completions リクエストを temperature:0 に送信します。モデルごとの最小、平均、最大レイテンシとエンドツーエンド完了トークン/秒をレポートします。

測定された実行全体のスループット メトリックは sum(completion_tokens) / sum(latencies) です。いずれかのサンプルが応答の使用法から completion_tokens を省略している場合、または合計レイテンシがゼロの場合、これは nil/N/A です。このコマンドは、デコードのみの速度や最初のトークンまでの時間を測定しません。これは、HTTP トランスポート、キューイング、プロンプト処理、生成、解析をカバーするエンドツーエンドの client ベンチマークです。

HTTP client はデフォルトでリダイレクトを拒否するため、リダイレクトの背後にあるエンドポイントの構成が間違っていても、黙って成功することはありません。 API キーはエラー メッセージから編集され、資格情報のエコーを避けるために生のトランスポート エラーは HTTP request failed としてマスクされます。完全なレポートは bytes.Buffer にバッファされ、すべてのモデルが成功した後にのみ io.Copy 経由で書き込まれるため、失敗しても部分的な出力は残りません。シグナル処理は、SIGINT/SIGTERM 上のアクティブなリクエストをキャンセルします。

出力は、デフォルトではテーブル、またはサンプルごとのレイテンシーと null 許容トークン数を備えた構造化データの場合は --json です。 API キーは JSON には含まれていません。バックエンドを比較するには、バックエンドごとに個別のモデル エイリアスを構成し、それらのエイリアス名を渡します。

🔧 ロード時の vllm-cpp LoRA 融合

lora_adapters および lora_scales 構成フィールドは、LoRA アダプターの重みファイルとアダプターごとの強度乗数をリストする標準の LocalAI フィールドです。 vllm-cpp ビデオ バックエンドは初めてそれらを消費し、エンジン負荷時に LoRA デルタを DiT (拡散トランス) ウェイトに融合します。

buildLoraExtras は、構成フィールドをインデックス付きの lora_path / lora_strength キーと値のペアに変換します。最初のアダプターには接尾辞がありません。後続のものは、_2、_3 などになります。単数形の lora_adapter が設定されている場合、それは複数形リストの前に最初のアダプターとして追加されます。相対アダプター パスはモデル パスに結合されます。絶対パスは通過します。スケールが指定されていない場合、強度はデフォルトで 1.0 になります。

ペアは ABI v18 エクストラ シームを介してパックされ、vllmVideoEngineLoad に渡されます。 vllm.cpp の ResolveDitLoraSpecs は、負荷時に LoRA デルタを DiT 重みに融合します。エンジンがチェックポイントから DiT ファミリを自動検出するため、1 つの汎用パスが LTX2.5 と MiniMax-H3 の両方に対応します。

アダプターは常にロードされます。このパスではリクエストごとのアクティベーションは行われません。ランタイム プロンプトでアクティブ化される LoRA (punica スタイル <lora:name:strength>) は範囲外であり、個別に追跡されます。

モデル構成上の env: マップは、バックエンド プロセス環境に変数を挿入します。主な使用例は、GPU の配置を制御するためにモデルごとに CUDA_VISIBLE_DEVICES を固定することですが、これは環境変数を読み取るあらゆるバックエンドに適用されます。

マップは pkg/model/process.go の共通プロセス生成層を通じて配信されるため、すべての gRPC バックエンドはバックエンドごとの配線なしでマップを継承します。モデル変数は最後にベース環境の後に追加されるため、同じ名前の継承されたシステム変数をオーバーライドします。 UI は編集可能なキー/値マップをレンダリングします。

💬 template.system_messages_after_first

エージェント フレームワークは、会話中にシステム指示を正当に追加します。通話前のツール パラメータ プロンプトや、結果後の調整プロンプトなどです。 Qwen3.x ファミリのトークナイザー テンプレートでは、最初のターンの後にシステム ロール メッセージに対して Jinja Exception: System message must be at the beginning が発生し、HTTP 500 が返されます。プレーン チャットは正常に見えます。すべてのエージェント タスクは失敗します。

template.system_messages_after_first は、連続した先頭のシステム ブロックの後に表示されるシステム ロール メッセージの処理を制御します。

  • "merge" は、後のシステム メッセージを \n\n セパレータを使用して最初のシステム メッセージに折り込み、元の位置から削除します。
  • "user" は、その位置と内容を維持したまま、各遅延システム メッセージを役割 user に書き換えます。
  • unset (デフォルト) は変更されずに通過します。トークナイザー テンプレートが決定します。

正規化は、stripEmptySystemMessages の後、トークナイザー テンプレート system_prompt インジェクションの前の ChatEndpoint で実行されるため、Jinja テンプレートでは場違いなシステム メッセージが表示されることはありません。モデル設定がオプトインしているリクエストのみに影響するため、デフォルトの動作は変更されません。

"user" はエージェント ワークロードに推奨されるモードです。命令はフレームワークによって配置された場所に留まり、モデルはそれにに従います。
