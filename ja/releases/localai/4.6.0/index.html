#ローカルAI v4.6.0

🎉 LocalAI 4.6.0 リリース! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.6.0 登場！

これは信頼性を重視したリリースです。AMD ROCm バックエンドは GPU 上でフルスピードで実行されるようになり、ワーカーが死亡したときに分散モデルのロードが中断されることはなくなり、リアルタイム セッションは予測どおりにウォームアップします。また、組み込みチャット UI への会話分岐、PII/監査イベント用の Prometheus カウンター、およびモデル ギャラリー用の SSRF 修正も提供されます。

ハイライト:

  • 🔴 AMD ROCm は正しく動作します - ggml オーディオ バックエンドは GPU にオフロードされ、hipBLASLt カーネル チューニング データがバンドルされ (低速な汎用カーネルはなくなりました)、rocm-vllm は適切なホイールをインストールし、ASIC ID テーブルが見つかりました。
  • 🎙️ 予測可能なリアルタイム - セッションはパイプライン全体 (VAD、ASR、LLM、TTS) を前もって熱心にウォームアップするため、最初のターンでモデルごとのコールドスタート ストールが発生しなくなり、さらに新しい POST /backend/load API と [メモリにロード] UI ボタン​​が追加されました。
  • 🌿 チャットの分岐 - 組み込み UI で直接、任意の アシスタントの回答を再試行したり、任意の時点から新しいチャットを分岐したり、会話全体を複製またはコピーしたりできます。
  • 🛡️ 分散強化 - 死んだワーカーはモデルロード勧告ロックを固定できなくなり (約 15 分のウェッジはなくなります)、孤立したバックエンド ワーカーは VRAM を保持する代わりに自己終了します。
  • 📊 PII/監査メトリクス - PII 検出/マスク/ブロックは Prometheus カウンターとしてエクスポートされるため、フィルターの起動が停止したときにアラートを送信できます。
  • 🔒 ギャラリー SSRF 修正 - POST /models/apply config-URL の取得は、プライベート/ループバック/メタデータ アドレスに対して検証されます。

さらに、冪等のバックエンドのインストール、vLLM および Python/MLX バックエンド全体でのツール呼び出しと推論の修正、最新の推論モデルとのクラウド プロキシの互換性、および通常の一連の依存関係の更新。

🚀 新機能と主要な機能強化

🔴 AMD ROCm バックエンドは GPU 上で正しく動作します

4 つの修正を組み合わせることにより、ROCm/hipBLAS バックエンドが CPU や低速の汎用カーネルにサイレントにフォールバックするのではなく、実際に AMD ハードウェア上でフルスピードで実行されるようになります。

  • ggml オーディオ バックエンドの GPU オフロード (#10667): rocm-qwen3-tts-cpp、rocm-omnivoice-cpp、acestep-cpp、および vibevoice-cpp は、Makefile が no-op -DGGML_HIPBLAS=ON (アップストリーム ggml は -DGGML_HIP=ON のみを理解します) を渡し、CMake リンク ループが hip を省略したため、CPU のみでビルドしていました。彼らは現在、llama-cpp と同じ Hipblas レシピを使用し、HIP バックエンドをリンクしています。
  • hipBLASLt カーネル チューニング データ (#10660、#10672): パッケージャーは rocBLAS データをバンドルしましたが、並列の hipBLASLt TensileLibrary_lazy_gfx*.dat ファイルはバンドルしませんでした。そのため、すべてのアーチが静かに遅いカーネルを使用し、Cannot read "TensileLibrary_lazy_gfx*.dat" を記録していました。データはバンドルされ、HIPBLASLT_TENSILE_LIBPATH は llama-cpp および turboquant run.sh によってエクスポートされます。
  • rocm-vllm は正しいホイールをインストールします (#10642、#10651): バックエンドは CUDA 専用 PyPI vllm (AMD では致命的な ModuleNotFoundError: No module named 'vllm') をプルしていました。これで、CPython 3.12 が固定され、ROCm ホイール インデックス (https://wheels.vllm.ai/rocm/) から vLLM がインストールされます。
  • ASIC ID テーブルが見つかりました (#10624、#10627): コンピューティング専用の Hipblas イメージに /opt/amdgpu/share/libdrm/amdgpu.ids がないため、すべてのモデル ロードで警告が表示されました。 Ubuntu の libdrm-common コピーが所定の場所にシンボリックリンクされます。

🔗 PR: #10667、#10672、#10651、#10627

🎙️ リアルタイム: 熱心なパイプラインのウォームアップ + メモリへのロード API

リアルタイム音声セッションは、最初の使用時に各サブモデルを遅延読み込みするのではなく、セッション開始時にパイプライン全体 (VAD、文字起こし、LLM、TTS、サウンド検出、音声認識) を積極的かつブロック的にウォームアップするようになりました。最初のターンではモデルごとのコールド スタート ストールが発生しなくなり、モデル読み込みエラーがストリームの途中ではなくセッション開始時に (model_load_error として) 表面化します。パイプラインのサブモデルは同時に読み込まれるため、セッションは合計ではなく最も遅いステージの時点でウォームアップし、失敗したステージでは結合エラー内のすべての壊れたモデルに名前が付けられます。

これにより、「メモリにロード」UI アクションとして公開される /backend/shutdown の逆である LocalAI ネイティブの POST /backend/load (および /v1/backend/load) と load_model MCP 管理ツールも追加されるため、管理者はオンデマンドで任意のモデル (フル パイプラインを含む) を事前にウォームアップできます。 --load-to-memory 始動フラグは同じエンジンを経由するようになりました。 disable_warmup: true を使用してパイプラインごとにオプトアウトします。

🔗 PR: #10662

🌿 組み込み UI でのチャットのフォーク

React チャット UI には、会話管理ツールが追加されています。つまり、(最後のものだけでなく) 任意の アシスタントの回答を再生成したり、任意の回答から新しいチャットを分岐したり、チャットを独立したコピーに複製したり、会話全体をマークダウンとして clipboard にコピーしたりできます。会話中の回答を再試行すると、DOM とリクエスト ペイロードの両方で、再質問する前に会話が正しく切り詰められます (これにより、会話中の再試行によってダウンストリームがモデルに戻るという潜在的な失効クローズのバグも修正されます)。すべて client 側、バックエンドの変更はありません。

🔗 PR: #10654

🛡️ より堅牢なプロセスと分散ライフサイクル

  • デッドワーカー アドバイザリー ロック ウェッジ (#10600): 負荷が中途半端な分散ワーカーは、モデルごとの PostgreSQL アドバイザリー ロックを固定し、そのモデルに対する後続のすべてのリクエストを 55P03 で約 15 分間失敗させる可能性があります。切り離されたロード コンテキストはモデル ロードの上限によって制限されるようになり、インストール待機は singleflight.DoChan によるキャンセルを尊重し、lock_timeout のスコープはデプロイメント グローバル GUC ではなく呼び出し元のコンテキスト バジェットに限定されます。
  • 親デス セーフティ ネット (#10639): LocalAI がティアダウン前に SIGKILL された場合、生成されたバックエンド ワーカーは再親化されて初期化され、VRAM とそのポートを保持して残留していました。各バックエンドは親 PID をポーリングし、再親化時に自己終了します。 LOCALAI_BACKEND_PARENT_WATCH (デフォルト オン、Windows では自動オフ) および LOCALAI_BACKEND_PARENT_WATCH_INTERVAL (デフォルト 2s) を介して構成できます。 C++ の対象範囲は今のところ llama-cpp です。 Python はすべてのバックエンドをカバーします。
  • より静かなウォッチドッグ (#10602、#10607): オプションの Free() RPC は、多くのバックエンドとフェデレーション プロキシに対して gRPC Unimplemented を返すため、ウォッチドッグはエビクション時に誤解を招く Error freeing GPU resources を記録しなくなりました。新しい grpcerrors.IsUnimplemented ヘルパーは、本物の故障とは区別されます。
  • 冪等なバックエンドのインストール (#10643): POST /backends/apply および LOCALAI_EXTERNAL_BACKENDS ブート ループは、適用/起動のたびに、すでにインストールされているバックエンドを再ダウンロードして再抽出することがなくなりました。 "force": true を渡します (UI のインストール ボタンは引き続き機能し、「再インストール」としても機能します)。

🔗 PR: #10600、#10639、#10607、#10643

📊 Prometheus カウンターとしての PII/監査イベント

PII ミドルウェア/MITM 監査パイプラインは、EventStore.Record チョーク ポイントで計測された単一の単調カウンター localai_pii_events_total{kind, origin, action, direction} を /metrics 上に出力するようになりました。ラベルはカーディナリティによって制限されます (パターンやユーザー ID はありません)。これは、容量制限のある /api/pii/events リング バッファを補完し、重要なことに、サイレント フィルターの障害をアラート可能にします。カウンタの rate() は、PII フィルターが展開後に起動を停止したことを検出します。

🔗 PR: #10641

🔒 ギャラリー SSRF 強化

空の id を指定した POST /models/apply は、指定された url を直接フェッチします。デフォルトの Docker セットアップ (API キーなし) では、到達可能な client が内部サービスまたはクラウド メタデータ (169.254.169.254) をプローブし、ジョブ エラーを介してスライスを抽出する可能性があります。ギャラリー設定の取得は、既存の ValidateExternalURL ガード (CORS プロキシとメディア ダウンロードを保護するものと同じ) を通じて実行されるようになり、プライベート、ループバック、リンクローカル、未指定、およびメタデータ アドレスをブロックします。プレーンな http(s):// のみが検証されます。 huggingface://、github:、oci://、ollama://、および file:// はそのままです。

🔗 PR: #10673

🐛 バグ修正 (要約)

  • fix(vllm): #10351 以降にリグレッションした非ストリーミング ツール呼び出し抽出の復元 (機能フラグが実行状態と誤っていました) - #10638
  • fix(python-backends): チャット テンプレートのツール呼び出し arguments をデコード (MLX/Qwen3.5 エージェント ループを解除) し、モデルが終了 </think> のみを発行する場合の推論を分割 - #10658
  • fix(cloud-proxy): temperature/top_p をドロップし、max_completion_tokens を送信することで、最新の推論モデル (Claude Opus 4.x、GPT-5.x) へのルーティングが 400 を停止します - #10640
  • fix(config): スライディング ウィンドウ アテンション モデルのデフォルトの swa_full:true を元に戻します (メモリを削減した KV キャッシュを復元します。モデルごとの明示的なオプトインとして引き続き利用可能です) - #10674
  • fix(kokoros): AudioTranscriptionLive 特性スタブを実装して、バックエンドが更新されたプロトに対してコンパイルされるようにします - #10612
  • fix(launcher): GUI の作業ディレクトリではなく、デスクトップ ランチャーのデータ/構成を ~/.localai の下に保持します - #10610、#10613
