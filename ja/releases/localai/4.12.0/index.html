#ローカルAI v4.12.0

🎉 LocalAI 4.12.0 リリース! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.12.0 登場！

このリリースでは、Web UI が再設計され、ストリーミング音声応答、ネイティブ決定ルーティング、モデル メモリとプロンプト状態のより詳細な制御が追加されています。また、画像のアップスケーリング、ライブ モーション キャプチャ、Qdrant ストア、認証されたチャット履歴も追加されます。これは、アドオンのサポートを含む次のリリースの準備でもあります。私たちの計画は、いくつかのコンポーネント (Studio、Talk など) を、LocalAI からオンデマンドでインストールできる個別のアドオンに移動することです。

ハイライト:

  • 🖥️ 再設計された Web UI: 共有コントロール、明るいテーマと暗いテーマ、より明確なモデルと Studio ワークフロー、ノード スコープのバックエンド メンテナンス。
  • 🎙️ ストリーミング音声およびバンドルされたオーディオ モデル: LLM フラグメントを Qwen TTS にフィードし、他のエンジンで明示的な句ストリーミングを使用し、Parakeet バンドルを介してオーディオ分析の役割を結合します。
  • 🧭 ネイティブ意思決定ルーティング: 意思決定モデルを使用してリクエストを分類し、述語、選択肢、スコアに新しい /v1/decisions アダプターを使用します。
  • 🖼️ Studio での画像のアップスケーリング: 専用の /v1/images/upscale API を使用して、プロジェクトを離れることなく、アップスケールされた子画像を作成します。
  • 🛡️ プライバシーとツールの構成: 応答 PII フィルタリング、検査不可能なメディアのオプトイン拒否、エイリアス プロファイル、およびリモート MCP サーバーの OAuth2 client 認証情報。
  • 🕺 ライブ GEM-X モーション キャプチャ: CPU または Vulkan 上で、RGB フレームを境界のあるセッションベースのポーズ API にストリーミングします。
  • 🗄️ 永続的な Qdrant ストア: TLS および環境に裏付けられた認証情報を備えた既存のストア API を使用します。
  • 💾 推論コントロール: MoE エキスパート キャッシング、遅延テンソル読み取り、および明示的なスロット プロンプト キャッシュの保存と復元を構成します。

🚀 新機能と主要な機能強化

🖥️ 共有 Web UI とより明確なモデル操作

Web UI は、共有 CSS/SVG キット、インクとティールのテーマ、一貫したコントロール、および権限を認識するビルドおよび操作ハブを使用します。既存の URL は引き続き利用できます。モデルは、モデルの詳細、バリアント、配置情報、およびディスク使用量を公開します。 Studio は、ワークフロー全体で作成、ジョブ、結果、および最近の結果のレイアウトを共有します。

モデルごとのストレージ アカウンティングにより、共有ファイルとモデル固有のファイルが区別されます。集計合計により、共有バイトが重複排除されます。モデルの表示サイズは、削除によって再利用されるスペースであるとは限りません。

リモート手動インポートは、追跡されたギャラリー ジョブとして実行されるようになりました。インポート ページとエディタは取得が成功するまで待機し、失敗またはキャンセルが表示されます。ダウンロードを行わないローカル ファイルのインポートでは、同期動作が維持されます。キューに入れられたインポートでは、推奨される推論のデフォルトを適用できるため、構成を再現するときに重要なパラメーターを明示的に設定します。

バックエンドは、選択した 1 つのノードからの 1 つのコンクリート ビルドの確認済み削除をサポートします。保護チェックと競合ロックにより、競合操作中の削除が防止されます。更新が失敗すると、未検証の空の状態が報告されるのではなく、最後の既知のインベントリが保持されます。

🔗 PR: #12526、#12551、#12587、#12599、#12785。キューに入れられたインポート: バックグラウンド取得 および リゾルバー対応キューイング。

💬 チャット履歴、推論コントロール、および豊富な入力

サインインしているユーザーは、/api/conversations を通じて会話を同期できます。アカウント スコープのキャッシュ、永続的な削除インテント、およびトゥームストーンにより、古い client が削除された会話を復元できなくなります。これには、認証、WebUI の有効化、および chat_history 権限が必要です。匿名セッションとレガシー キーのみのセッションはブラウザーのローカル履歴を保持します。古い共有ブラウザ履歴は、アカウントに自動的に割り当てられません。

1 つのエフォート ピッカーがチャットごとの reasoning_effort リクエストを制御します。 なし は、新しい返信に対して返された推論トレースも非表示にします。 /effort は引き続き入手可能です。個別の /reasoning アクションは削除されました。この UI の選択は、すべてのバックエンドが内部推論計算を抑制することを証明するものではありません。

マイクディクテーションは、インストールされた文字起こしモデルを通じて編集可能なテキストを追加します。テキスト レイヤーなしでスキャンされた PDF は、最初の 10 ページがビジョン対応モデルの画像添付ファイルとしてレンダリングされます。 Canvas は、allow-same-origin を使用せずに、サンドボックス内の独自の CSP を使用して HTML プレビューを提供します。プレビューは 10 分後に期限切れになり、プロセス メモリ内に残ります。許可された外部 HTTPS リソースは読み込めるため、プレビューは必ずしもオフラインである必要はありません。マルチフロントエンド展開には、プレビューを保持するプロセスに到達するルーティングが必要です。

🎙️ ストリーミング音声応答とバンドルされた音声分析

Qwen TTS は、オプションの TTSLive バックエンド RPC を通じて増分テキストを受け入れます。 LLM および TTS ストリーミングを有効にすると、完全な LLM 応答が到着する前に、1 つのネイティブ発話で音声の生成を開始できます。キャンセルとバックプレッシャーはライブ パスを通じて伝播します。失敗した発話は、音声コミット後に再生されません。

pipeline:
  streaming:
    llm: true
    tts: true

非ネイティブ エンジンの場合、pipeline.streaming.clause_chunking: true は境界付き句合成を明示的に有効にします。未設定のままにすると、応答全体の合成が保持されます。ネイティブ Qwen 入力では、この句スプリッターは使用されません。

ギャラリーに qwen3-streaming-assistant、vits-streaming-assistant、piper-streaming-assistant が追加されました。これらのプリセットはパイプライン構成のみをインストールします。コンポーネント LLM、転写モデル、VAD、および TTS モデルを個別にインストールします。

Parakeet バンドルは、ASR、VAD、ダイアライゼーション、サウンド検出、スピーカー エンコーダーなど、複数のオーディオの役割を担うことができます。利用可能なロールはバンドルによって異なります。それらは 1 つの融合された推論パスを意味するものではありません。ダイアライゼーションは、include_sounds を使用して時間指定されたサウンド イベントを返すことができます。

スピーカーを備えた Parakeet モデルは、音声の埋め込みと検証も行うことができます。エンコーダのフィンガープリントは互換性のある重みを識別し、音声ストアは異なる埋め込み次元を区別します。 voice_verify_threshold はコサイン距離を使用し、デフォルトは 0.5 で、0 から 2 までの値を受け入れます。このバックエンドは、スプーフィング対策や音声分析のサポートを追加しません。

リアルタイム応答は、以前の音声コミットが文字起こしを完了するまで待機するようになりました。待機中の応答は、その保留中のコミットがユーザー項目を生成しない場合、そのターンなしで LLM を開始するのではなく、input_not_committed で終了します。 interrupt_response: false は、重複するトランスクリプトと音声イベントを保持しながら、アクティブな応答を保持します。

🔗 PR: #12770、#12455、#12463、#12479、#12491、#12499、#12544、#12446。直接のフォローアップ: Parakeet voice RPC、順序付けされたコミット応答、割り込み制御。

🎵 構造化されたサウンドの拡張と音声コントロール

YuE2 は、audio.cpp サウンド生成パスに参加します。通常の Studio キャプションは、明示的なスタイル パラメーターによってオーバーライドされない限り、そのスタイルを提供します。 YuE2 ウェイトは CC-BY-NC-4.0 を使用しており、非営利使用に限定されています。

Simple Sound はオプションで expansion_model を使用して、短い説明を検証済みの音楽フィールドに変換できます。最終リリースの動作には、use_tokenizer_template: true とネイティブ ツール サポートを備えた llama-cpp モデルが必要です。 LocalAI には厳密な expand_sound 呼び出しが 1 つだけ必要です。散文 JSON および推論テキストはフォールバック引数ではありません。無効な拡張はオーディオ生成前に停止します。

OmniVoice は、音声パラメーターを通じて、制限された継続時間と後処理コントロールを公開します。期間は 30 秒に制限され、生成フレームに量子化されます。これは、正確な最終的な WAV の長さを保証するものではありません。 Pocket TTS は、options: ["language:french"] などのモデルロード言語オプションも受け入れます。

🔗 PR: #12617、#12703、#12772、#12783、#12787、#12790、#12637、#12766。

🖼️ 画像のアップスケーリングと追加の生成制御

POST /v1/images/upscale は、明示的なモデル機能チェックによる専用のアップスケーリングを提供します。 Studio は出力を子イメージとして記録するため、同じプロジェクト内で作業を続けることができます。ネイティブ ESRGAN モードは、拡散コンテキストをロードせずにタイリングをサポートします。要求されたスケールはモデルのネイティブ スケールと一致する必要があります。これは任意スケール補間ではありません。

custom_sigmas は、チェックポイント固有のノイズ除去スケジュールを公開します。新しい Qwen Image アセンブリはこれらのスケジュールを使用します。選択したエンコーダは、これらのエントリをテキストから画像のみに変換します。モデルおよびエンコーダのライセンスは引き続き適用されます。

MiniMax-H3 は、パーティション チェックと制限された入力を使用して、追加の参照画像、参照ビデオ、および WAV オーディオ フィールドを取得します。これらのフィールドは、このリリースでは API のみです。 React はそれらを公開しません。ソース サポートは、すべてのチェックポイントまたはデバイスでエンドツーエンドの生成を確立するわけではありません。

🔗 PR: #12620、#12619、#12668。

🧭 ネイティブ決定ルーティングと /v1/decisions

意思決定モデルは、一般的なチャット応答を分類プロトコルとして使用する代わりに、ルーターへの要求を直接分類できます。ネイティブ パスは、互換性のある形式とプロジェクターを使用した、境界付きインライン画像の決定もサポートします。

POST /v1/decisions は、既存の SystemOne パイプラインを述語、選択肢、スコアに適応させます。最大 64 の質問がサポートされ、入力されたブール値または文字列の選択肢が保持されます。 /v1/systemoneは引き続き入手可能です。

画像入力には、画像対応の意思決定モデルとインライン PNG または JPEG データが必要です。サポートされていない入力は、黙ってテキストのみの決定になるのではなく、失敗します。既存の決定権限と使用量アカウンティングが適用されます。

古いインストール済みの llama.cpp イメージには、サーバーが最新であっても、ネイティブの Decisions サポートが不足している可能性があります。認識された古いバックエンド エラーは、アップグレード指向の 501 を返し、バックエンドにアップグレードのマークを付けるようになりました。この検出自体はイメージを再構築しません。

🔗 PR: #12449、#12603、#12733。

🛡️ プライバシー制御、モデルプロファイル、およびリモート MCP 認証

PII ミドルウェアは、受信した応答命令、テキスト項目、関数の引数、シリアル化されたツール出力をカバーするようになりました。 pii.block_unscanned_media: true は、テキスト検出器が検査できないメディアをオプションで拒否します。 OCR やメディアの転写ではなく、ブロックします。

pii_detection:
  extend_to_next_word: [ZIPCODE]
  extend_to_previous_word: [LASTNAME]
  protected_terms: [Example Supplier]

隣接する単語拡張子と保護用語ファイルにより、NER マスキングに対するオプトイン制御が追加されます。保護された用語は NER にのみ適用され、パターン検出器には適用されません。同じ用語が出現する場合はどこでも通過するため、公開しても安全な値のみをホワイトリストに登録します。拡張機能は過剰にマスクする可能性があります。

これらの変更では、すべてのリクエスト パスにわたる完全なフィルタリングが提供されるわけではありません。エージェントの傍受と解決された履歴応答コンテンツにはギャップが残ります。アクティブな検出器ポリシーを持つ応答 WebSocket は、フィルタリングされずに拒否されます。そのポリシーには HTTP POST を使用します。

エイリアスは、ロードされた 1 つのターゲット モデルを共有しながら、profile.system_prompt、MCP 構成、および client-tool ポリシーを保持できます。 mcp.auto は、インスタンスおよびユーザー権限内でのみ構成されたサーバーをアクティブ化します。オプションの数値証拠メモは警告ヒューリスティックであり、事実の検証ではありません。 リモート MCP サーバーは、環境に裏付けられたシークレットと自動トークン更新を含む OAuth2 client_credentials をサポートします。トークン エンドポイントには、明示的なループバック ホストを除き、HTTPS が必要です。環境変数による資格情報のローテーションでは、接続所有プロセスを再起動する必要があります。従来の SSE 検出は、制約付きフォールバックで引き続き利用可能です。

🔗 PR: #12661、#12660、#12708、#12755、#12711、#12304。直接追加: OAuth2 資格情報、保護された用語、および 前の単語の拡張子。

🕺 GEM-X ライブ モーション キャプチャ

新しい gemxcpp バックエンドは、/api/motion/sessions と二重 WebSocket を介して、ストリーミングされた RGB フレームを人間のポーズに変換します。 Client は、SOMA-77 または SMPL-24 出力を選択し、使い捨てのオリジン バインドのブラウザ チケットを使用できます。

API は、無制限のキャプチャ バックログを蓄積するのではなく、入力とセッションのカウントを制限します。制限には、モデルごとに 1 セッション、ユーザーごとに 4 セッション、フロントエンドごとに 16 セッションが含まれます。 Client はフロー制御クレジットに従う必要があります。

この統合は API のみであり、CPU または Vulkan をサポートします。 macOS はメタル推論ではなく CPU を使用します。ボディ メッシュ、ロボット コントローラー、人物の再識別は提供されません。セッション状態はフロントエンドローカルです。 GEM-X ウェイトには、独自の NVIDIA モデル ライセンス条項が適用されます。

🔗 コミット: GEM-X バックエンドと二重 API、ユーザーごとのセッション境界、および ソケット認証強化。

🗄️ Qdrant が支援するベクター ストア

Qdrant でベクターを永続化するには、既存の /stores/* API を通じて backend: qdrant-store を使用します。構成では、TLS、カスタム認証局、および環境に裏付けられた API キーがサポートされています。 Qdrant の gRPC のデフォルトは、REST ポート 6333 ではなく、ポート 6334 です。

書き込みでは最大 500 ポイントのチャンクが使用され、チャンクごとにタイムアウトが発生します。後のチャンクが失敗した場合でも、以前のチャンクは書き込まれたままになります。セット全体はアトミックではありません。 COSINE がデフォルトのメトリックです。他のメトリクスは、既存のコサインベースのしきい値と一致しない生のスコアを返します。

🔗 コミット: Qdrant バックエンド、制限付き書き込み、および TLS 互換性。

💾 モデルのメモリ コントロールと保存されたプロンプト状態

  • options: ["moe_cache_mib:4096"] は、ホスト常駐の MoE 専門家向けにオプトイン GPU キャッシュ バジェットを設定します。 VRAM を消費し、ワークロードに依存します。サイズが小さいキャッシュはスラッシングする可能性があります。
  • options: ["lazy_mode:on"] は、上流でマークされたテンソルの遅延読み取りを有効にします。 auto は上流の選択ルールを保持します。 off は起動時にそれらをロードします。フィールドのないフォークでは警告が表示され、オプションは無視されます。
  • options: ["slot_save_path:/var/lib/localai/slots"] は、/v1/slots/save および /v1/slots/restore を介して管理スロットの保存/復元を有効にします。保存されたプロンプト状態は、モデルのアンロード後も存続します。互換性のあるモデル、量子化、およびコンテキスト設定を使用します。保存されたファイルは機密データです。

スロットの永続性は POSIX のみで、モデルごとに最大 32 個の保存を保持し、ディレクトリを共有する複数のプロセスを調整しません。ビジースロットはアクティブなリクエストを待ちます。これらの制御は、リリース全体のレイテンシやメモリの改善を意味するものではありません。

🔗 PR: #12729、#12743、#12730。

🔧 分散リカバリとオプトイン診断

PostgreSQL/NATS 導入では、POST /api/models/:id/load-cancel を通じて負荷生成、リース、ワーカー ウォッチドッグ、試行固有のキャンセルが可能になります。まずフロントエンドをアップグレードします。モデル設定の再同期のデフォルトは、--model-config-resync-interval までの 30 秒です。 ルート PostgreSQL コレクション検出では、フロントエンド間で共有レジストリが使用されるようになりました。ユーザーごとのコレクションはその変更の対象外です。ターゲットを絞ったアンロードでは、任意のワーカー バックエンドではなく、指定されたモデルが解放されます。これらは NATS 分散モードの変更であり、libp2p フェデレーション機能ではありません。

管理停止の意図は、構成の再同期によって永続化されません。レプリカ ポリシーは停止したモデルを再開できます。再同期を永続的な停止ポリシーとして扱わないでください。

オプトイン --pprof は、別の数値ループバック専用プロファイラーを公開します。 --request-phase-timing は、ファイルシステム プローブを追加せずにフロントエンド フェーズを記録します。プロファイルには機密データが含まれており、オーバーヘッドが追加される可能性があります。プロファイラーをパブリック Ingress 経由で公開しないでください。これらの測定は、ワーカー上の GPU 推論ではなく、Go フロントエンドを対象としています。

🔗 PR: #12524、#12558、#12536、#12537、#12610、#12616。

🧰 知っておく価値のある小さな機能

  • 独自の API キーを、無期限に、またはタイムスタンプが設定されるまで、削除せずに一時停止および再開します。 #12521。
  • --prefer-development-backends を使用して、対象となるインストール済みの開発バックエンドを優先します。アクティブ化には、フロントエンドの再起動と個別のワーカーの構成/再起動が必要です。 ＃12782。
  • バックエンド OCI ダウンロードでは、構成された --download-staging-path が使用されます。 #12280。
  • タグ付きリリースでは、Thin Linux x86_64 ランチャー AppImage が追加されます。 glibc 2.35+ とホスト グラフィック ライブラリが必要です。サーバー、バックエンド、モデルはバンドルされません。 #12647。
  • Silero VAD のしきい値、サイレンス、およびパディングの設定は、モデル オプションを通じて構成できます。 #12430。

🧠 モデル

ギャラリー インデックスは、トップレベルの名前付きエントリが 1,660 から 1,896 に増加しました (+236)。これは、ネストされたバリアント参照ではなく、個別のトップレベル バリアントをカウントします。

モデル カテゴリには、29 個の PR が含まれています。11 個の追加または集約 PR と 18 個のチェックサム メンテナンス PR です。ギャラリーへの直接コミットにより、さらにバリアントが追加されます。これらは変更の数であり、個別のモデル アーキテクチャの数ではありません。 追加内容には、Fluid Speech Mini、スピーカー サポート付きの多言語 Parakeet バンドル、Moondream VAD スライス、LFM2.5 24B バリアント、MiniCPM-V 4.7 1B バリアント、Iris-3B、FLUX.3 Image Klein、MOSS-Image、実験的な Fish Drama 3 が含まれます。これらのノートの他の場所でのランタイム支援による追加には、Qwen 画像スケジュール、RealESRGAN、ストリーミング アシスタント プリセット、そしてネイティブの意思決定モデル。

重量ライセンス、ハードウェア要件、実験上の制限については、各モデル カードを確認してください。ギャラリーのエントリは、すべてのバックエンドまたはデバイスでの検証を証明するものではありません。
