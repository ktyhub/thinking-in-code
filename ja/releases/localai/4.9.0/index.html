LocalAI 4.9.0 登場！

13 日間と 146 件のプル リクエストは、新しいエンジンではなく、毎日触れる LocalAI の部分に費やされました。認証はデフォルトで拒否されるようになり、チャットはエンドツーエンドのコンテキスト圧縮を獲得し、モデルとバックエンドにはそれぞれ 3 つではなく 1 つの正規ページがあり、vllm-cpp は、実際のオーディオ トラックを備えた MiniMax-H3 を提供するビデオ モダリティを成長させました。

ハイライト:

  • 🔐 認証はデフォルトで拒否されます - 明示的なパブリック レジストリに表示されない限り、すべての HTTP ルートに資格情報が必要です。これにより、/moderations、/models、/backends、/mcp/chat/completions などのプレフィックスのないエイリアスが古い保護プレフィックス リストの外にあったバイパスのクラスが閉じられます。 Naor Yaacov によって報告されました。
  • 🗜️ チャット コンテキスト圧縮 - モデルごとにオプトインし、古い完全なターンは推論前に LocalAI モデルを通じて圧縮され、システム プロンプト、最新のメッセージ、およびツール呼び出しユニット全体が保持されます。比率と期間は、応答のメタデータとメトリクスとして返されます。
  • 🖥️ リソースごとに 1 ページ - /app/models は Explore と Installed を所有し、/app/backends は Catalog と Installed を所有し、ネストされたホスト ビューはなくなりました。古い /app/manage ブックマークは引き続き機能します。
  • 🎬 MiniMax-H3 ビデオ生成 - vllm-cpp は、H3 チェックポイント セットの 2 番目のエンジン ハンドルを開き、ビデオとオーディオを一緒にレンダリングするため、MP4 には実際の AAC トラックが含まれます。プロンプトで音声を要求すると、モデルがそれを口パクします。
  • 🗣️ llama.cpp 上の Qwen3-TTS - アップストリーム独自の GGUF 変換を使用した、テキスト生成用にすでに出荷されているフル アクセラレータ マトリックス (CUDA、ROCm、SYCL、Vulkan、Metal、L4T) でのテキスト読み上げ。
  • 🧭 ファーストクラスルーターとしての KNN - ラベル付きプロンプトの厳選され永続化されたコーパスに対する類似性加重投票。分類子モデルがなく、ラベルが付けられたものとは異なるプロンプトは、推測ではなく決定不可能として扱われます。
  • 📊 グローバル アドミッション コントロールとライブ バックエンド トレース - プロセス全体の HTTP アドミッション境界、実行中のバックエンド操作が実行中に表現され、UI はログに直接リンクします。
  • 🕵️ 可逆 PII 仮名 - マスクされた値はリクエスト スコープの決定論的仮名 (EMAIL_001) になり、JSON および SSE トークン分割書き込みでバックエンドが値をエコーし​​た場合に復元されます。
  • 📦 Hugging Face の並列ダウンロード - スナップショット マテリアライゼーションは、一度に最大 N 個のファイル全体の転送を実行するため、多くのシャードに分割されたリポジトリがファイルごとのレイテンシーで実時間を消費することがなくなります。
  • 🖧 コールド モデル ロードは永続的なジョブです - モデルごとのアドバイザリー ロックは、複数 GB の転送にまたがることがなくなりました。これにより、オペレーター席からは 35.7 GB ロードが永久に壊れているように見えましたが、ステージングは​​その下で正常に進行していました。
  • 🎮 vllm-cpp は所有するカードをカバーします - CUDA ビルドは 1 つまたは 2 つのアーキテクチャから、amd64 では 8 つ、arm64 では 5 つになり、A100、L4、4090、H100/H200、B200、Jetson Orin、Jetson Thor が追加されました。

さらに、リアルタイム用の単一の共有 WebRTC UDP ポート、macOS Stable Diffusion および Parakeet ビルドで実際に有効になっている Metal、デフォルトのログ レベルでのバックエンド クラッシュ診断、およびポルトガル語 (ブラジル) とインドネシア語の UI 翻訳。

🚀 新機能と主要な機能強化

🔐 認証がデフォルトで拒否されるようになりました

以前の分類子は、選択された API スタイルのパスをプレフィックスによってゲートしました。そのリストにないパスはすべてパブリックであり、接頭辞のないエイリアス (/mcp/chat/completions、/moderations、/models、/backends、/import-model) はグローバル認証をバイパスでき、新しく登録されたルートはデフォルトで同じ弱点を継承する可能性があります。

ミドルウェアはメソッドを認識し、デフォルトで拒否するようになりました。ルートは、そのメソッドとパスが明示的なパブリック レジストリに存在する場合にのみパブリックになります。公開されたままなのは、ブートストラップと検出可能にするために必要なセットです。API 命令、Swagger GET ルート、LocalAI の既知のドキュメント、ヘルス、ログイン、OAuth、SPA、資産、ブランディング、およびノー​​ド登録トークンのフローです。テストではルーター全体のカバレッジがアサートされるため、新しいルートが省略によって公開されることはありません。

移行の影響。 データベース認証または従来の API キーが構成されている場合、/version および生成された音声、画像、ビデオ、および 3D URL には資格情報が必要になります。組み込み展開では、ApplicationConfig.PathWithoutAuth 経由でナロー プレフィックスを追加でき、従来の GET 除外フラグは明示的な互換性オーバーライドとして引き続き利用できます。

このクラスの認証バイパスを報告してくれた Naor Yaacov に感謝します。

🗜️ エンドツーエンドのコンテキスト圧縮

長い会話は最終的には合わなくなります。圧縮はモデルごとにオプトインされており、有効にすると、構成された LocalAI モデルを通じて古い完全なターンが切り捨てられるのではなく、推論前に圧縮されます。

触れられないもの: 主要なシステムと開発者の安全性プロンプト、最新のメッセージ、完全なツール呼び出し/結果ユニット。これらは完全に保持されるため、圧縮された履歴が結果なしで呼び出しを残すことはありません。これは、PII フィルタリングの後、およびその後の MCP 反復を含むアシスタント/MCP プロンプト挿入後に実行されるため、圧縮されるのは実際に送信されるプロンプトです。ツール スキーマと完了ヘッドルームは、保守的なオフライン トークン バウンドで考慮されます。 圧縮メタデータは、非ストリーミング応答およびストリーミング使用状況トレーラーで公開され、圧縮イベント、比率、および期間がメトリクスとしてエクスポートされます。 LocalAI は不透明なプロバイダー ペイロードを安全に書き換えることができないため、クラウド プロキシ パススルー構成は圧縮を拒否します。翻訳モードがサポートされています。すでに開始されているストリームでの遅延障害は、帯域内 SSE エラーとして返され、その後に [DONE] が続きます。

🔗 PR: #11556

🖥️ リソースごとに 1 つの正規ページ

モデルにはギャラリーと別個のホスト管理画面がありました。バックエンドには、インストールされたバイナリ用のネストされたホスト ビューがありました。これらの間では、リソースがどこに存在するかは明らかではなく、共通のライフサイクル アクションは必要以上に 1 レベル深い位置にありました。

各リソースには 1 ページが含まれるようになりました。 /app/models は Explore と Installed を所有し、/app/backends は Catalog と Installed を所有し、どちらも URL ベースの検索、状態、選択を備え、バックエンドはバリアント、開発ビルド、およびターゲット ノード スコープを保持します。 Explore では、機能を認識した 開く および インストールの管理 アクションが表示されますが、破壊モデル コントロールはインストール済みのままです。 Operate Overview は、共有サマリー ポーラーからホスト容量を読み取り、ネストされたホストの宛先が削除されます。狭いリスト/詳細ビューでは、詳細ビューから戻ったときにフォーカスが元の行に戻ります。

API は何も変更されておらず、既存の /app/manage ブックマークは、レガシー モデルとバックエンド クエリの状態を保持する置換リダイレクトを通じて機能し続けます。

classifier: knn は、分類子のキャッシュからプライマリ要求ルーターへの KNN 検索をプロモートします。 score や colbert とは異なり、分類子モデルは必要ありません。ラベルの知識は、管理者 API を通じてシードおよびキュレートするラベル付きサンプル プロンプトのコーパス内に存在するため、ルーティングの決定は決定論的で監査可能で、モデルの意見ではなく段階的な経験に基づいています。
