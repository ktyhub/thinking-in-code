gpt-researcher v3.7.0

gpt-研究者 v3.7.0

よりスマートなコンテキスト、埋め込みは不要

GPT Researcher は、類似性ではなく有用性に基づいて、LLM に送信するコンテキストを選択するようになりました。 研究の質問のために収集されたすべての文章は、Jev によって採点されます。 その質問に答えるのにどれだけ役立つかについて考え、役立つ部分だけを残します。

同一のソースで再生された 28 の調査タスクのベンチマーク:

<img width="3200" height="1800" alt="image-1790437831580" src="https://github.com/user-attachments/assets/c2a7b305-2e60-4709-ad9c-8af09e297f9f" />

何も必要はありません。 TYPESAFE_API_KEY を設定すると、Jev が使用されます。何もない場合、または Jev コールがあった場合 失敗すると、GPT Researcher はローカル キーワード (BM25) ランキングに戻るため、 標準的な研究のための埋め込みプロバイダー。レポートチャットでは同じフィルターが使用されます。

  • ドキュメント: https://docs.gptr.dev/docs/gpt-researcher/gptr/context-filter
  • ベンチマーク、メソッド、コード: evals/context_filter/

⚠️ 注意事項の変更点

  • Python 3.12+ が必須になりました。
  • デフォルトのコンテキスト フィルター: TypeSafe キーがない場合、デフォルトはキーワード ランキングではなくキーワード ランキングになります。 埋め込み。ベンチマークのすべてのメジャーでエンベディングと一致するか、それを上回りました。古いものを保つために 動作を変更するには、CONTEXT_FILTER=embeddings を設定します。

このリリースにも含まれています

  • Retriever プラグイン: gpt_researcher.retrievers エントリ ポイント経由で検索プロバイダーを独自のパッケージとして出荷します (#2154)
  • 新しいリサーチ実行時にフロントエンド WebSocket が 2 番目の接続を開く問題を修正しました (#2159)
  • マルチエージェントセクションは互いのコンテンツを繰り返さなくなりました (#2158)
  • 自己ホスト型フロントエンド アセット、サードパーティ CDN なし (#2082)
  • レトリバー、スクレイパー、ディープリサーチにわたる 25 以上のコミュニティ修正
  • ドキュメント: 再設計されたホームページ、現行モデルの幻覚リーダーボード、新規インストール時の修正ビルド

インストール: pip install -U gpt-researcher (0.16.0)
