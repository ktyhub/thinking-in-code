spring-batch v6.0.0

スプリングバッチ v6.0.0

Spring Batch 6.0 は、いくつかの新機能、拡張機能、バグ修正が含まれるメジャー リリースです。このリリースでは、API の重大な変更と非推奨が多数導入されています。変更点の完全なリストについては、移行ガイド を参照してください。

:star: 新機能

  • NULL 可能性制約の JSpecify アノテーションへの移行 #4673
  • 失敗したジョブ実行を回復するための API を追加 #4876
  • Java Flight Recorder #4972 による可観測性のサポートを追加
  • あらゆる種類のステップを外部から停止する機能を追加 #4965
  • 同時実行モデルを再検討する #4955
  • コンテキスト ラムダを使用してバッチ アーティファクトを構成する #4818
  • ローカルチャンキング #5021 のサポートを追加
  • リモートステップ実行のサポートを追加 #5024
  • sigterm #5028 でジョブの実行を正常に停止するためのシャットダウン フックを追加
  • Jackson 3 #4842 のサポートを追加
  • Spring Integration MessageChannel による SEDA のサポート #4719
  • 最新のコマンド ライン バッチ オペレーターを導入 #4899
  • ジョブとステップに Bean 名を使用する機能を追加 #4858
  • アプリケーションコンテキストで定義されたジョブを自動登録できるように MapJobRegistry をスマートにする #4855
  • MessageChannelPartitionHandler を任意のジョブ リポジトリ実装で使用できるようにする #4917
  • メタデータ削除のための楽観的ロックを追加 #4793
  • Job インターフェースを機能インターフェースにする #4966
  • Step インターフェースを機能インターフェースにする #4976
  • StoppableTasklet.stop()にStepExecutionパラメータを追加 #4703
  • Mongo シーケンス インクリメンタを構成する機能を追加 #5018
  • Micrometer のグローバル静的メーター レジストリ #4968 の使用を削除
  • MongoDB DAO での削除操作のサポートを追加 #5060
  • 異なる項目タイプを想定して既存の ItemWriter を CompositeItemWriter とともに使用します #4735
  • ChunkOrientedStepBuilder #5087 で StepExecutionListener だけではなく、ItemHandler を StepListener として自動的に登録します

:ロケット: 機能強化

  • 代替 JobRepository #4718 を構成する際のエクスペリエンスを向上させました。
  • JdbcStepExecutionDao::getStepExecution #4799 のパフォーマンスを向上
  • 楽観的ロックの更新 SQL を改善 #4792
  • プリミティブ型の代わりにドメイン型を使用することで、JobOperator API を改善しました #4845
  • 範囲をジョブ操作のみに縮小することで JobOperator を改善 #4833
  • コア API 簡略化 #4847

  • リスナー API を core.listener パッケージ #4867 の下に移動します

  • コア パーティション API を org.springframework.batch.core.partition #4849 の下に移動します
  • DAO 実装を別のパッケージに移動 #4848
  • JobKeyGenerator インターフェースから不要なジェネリックを削除 #4886
  • JobRegistry`` での JobFactory` の使用を削除 #4854
  • SimpleJobOperator の JobExplorer への依存関係を削除 #4817
  • デフォルトのバッチ構成から JobExplorer Bean 登録を削除 #4825
  • RemoteChunkHandlerFactoryBean #4839 の不要なリフレクションを削除
  • SimpleJobOperator を TaskExecutorJobOperator に名前変更 #4834
  • JobRepositoryFactoryBean を JdbcJobRepositoryFactoryBean に名前変更 #4829
  • FlatFileItemReaderBuilder : ビルド時にチェック例外を発生させます #4757
  • JobOperator を JobLauncher に拡張する #4832
  • JobRepositoryをJobExplorerを拡張する #4824
  • JobExplorer/JobInstanceDao API の冗長メソッド #4821
  • ErrorProne を導入し、コンパイラ警告 #4807 を修正
  • Redis 統合テストを追加 #4892
  • testErrorMessageWhenNoLineTokenizerWasProvided で例外がスローされない場合はテストに失敗します #4883
  • 型安全性を高めるために AOT プロキシ ヒントをリファクタリングする #4881
  • タイプ セーフティ #4783 のために ExitStatus#isRunning をリファクタリング
  • ExitStatus#equals への引数を NULL 可能としてマークします #4823
  • 代わりに ctx::getBean のタイプセーフ バリアントを使用します #4803
  • 必要に応じて jdbcTemplate.queryForStream().findFirst() を使用します #4802
  • 可能な場合は既存の SQL を再利用する #4801
  • チャンク指向の処理モデルの実装を再検討する #3950
  • ステップ ビルダーを介して StepInterruptionPolicy を挿入できるようにします #1641
  • デフォルトのバッチ構成で JobRegistry をオプションにします #4971
  • JobOperatorFactoryBean #4970 でトランザクション マネージャーをオプションにします
  • タスクレットおよびチャンク指向のステップでトランザクション マネージャーをオプションにする #4974
  • サブインターフェースで StepLocator メソッドを分離 #5015
  • インフラストラクチャ API を特定のパッケージに移動 #5014
  • パブリック API の例外宣言を再検討する #5013
  • 組み込みジョブパラメータインクリメンタを org.springframework.batch.core.job.parameters パッケージに移動 #5011
  • ジョブパラメータ属性のカプセル化が壊れている #5010
  • パブリック API 入力の null 可能性定義が正しくありません #4989
  • 明確な null 許容セマンティクスを使用して取得メソッドを更新 #4988
  • AbstractStep のデフォルト コンストラクターが正しくありません #4984
  • ドメイン モデル エンティティを不変にする #1870
  • JdbcStepExecutionDao::getLastStepExecution #4798 のパフォーマンスを向上
  • MongoStepExecutionDao #5061 でのステップ実行カウントの最適化
  • 構成ログ レベルをデバッグ #5055 に変更します。
  • 永続化ドメイン オブジェクト #5054 から未使用の ID を削除します
  • StepExecution#getSummary #5025 にカンマがありません
  • DefaultFieldSet.indexOf() メソッド #4930 のパフォーマンスを向上
  • MessageChannelPartitionHandler::receiveReplies #4776 の改良
  • CommandLineJobOperator の再起動/放棄の状態検証を改善し、ログ記録を強化します #5057
  • パーティション化されたステップ #4732 で ResourcelessJobRepository を使用する場合の不正確なエラー メッセージ
  • メタデータ テーブルの SQL Server DDL は、暗黙的な変換によるパフォーマンスの低下とデッドロックを防ぐために、NVARCHAR を使用する必要があります #5064
  • .getUniqueJobParameters() での潜在的なパラメーター キーの衝突 #5088

:lady_beetle: バグ修正

  • FlatFileItemWriterBuilder の RecordFieldExtractor が names() 設定を反映しない #4916
  • 空のパラメータセットでジョブを開始するときの誤った警告 #4914
  • JobParametersIncrementer #4910 を使用する場合のジョブ パラメーターの誤った処理
  • チャンク処理で書き込みスキップ数が更新されない #4514
  • GraalVM 24 #4937 でのビルド失敗
  • ResourcelessJobRepository #4975 での間違ったステップ実行 ID の生成
  • @AfterChunk/@BeforeChunk アノテーション javadoc 内の情報が現在の実装と矛盾しています #4961
  • コンポーネントがないと RecordFieldSetMapper が Record で失敗する #4900
  • Jackson 3.0 FAIL_ON_TRAILING_TOKENS のデフォルト変更 #5047 により、JsonObjectReader は JSON 配列形式の読み取りに失敗します
  • ChunkOrientedStep: チャンク サイズが項目数 #5048 を超える場合、不必要な ItemReader.read() 呼び出し
  • JobParameter コンストラクターは間違ったパラメーター (名前ではなく値) を検証します #5049
  • JobOperatorTestUtils コンストラクター #5051 の誤ったエラー メッセージ
  • retryLimit() なしで retry() が使用(構成)されている場合、ChunkOrientedStepBuilder は IllegalArgumentException をスローします #5068
  • SkipLimit() なしで Skip() が使用(構成)されている場合、ChunkOrientedStepBuilder は IllegalArgumentException をスローします #5069
  • MongoJobExecutionDao は一時ジョブ パラメーター タイプを正しく処理しません #5063
  • StepExecutionListener#afterStep #4362 の間違ったステップ ステータス
  • JobRepository から TopicPartition を逆シリアル化できません #3797
  • 識別ジョブパラメータがない場合の不正な再起動動作 #4755
  • JobExecutionDao #5062 でジョブ実行を取得するときの順序が正しくない
  • エラーはジョブ実行から伝播されません #808
  • sigterm #4023 の後、Spring バッチが開始ステータスで終了する
  • ジョブ #5006 の起動時に Jdbc Hibernate 接続が途中で閉じられる
  • jobExecutionDao.updateJobExecution(jobExecution) #5022 が原因の OptimisticLockingFailureException
  • StepContext.getJobParameters() #5041 の GraalVM ネイティブ イメージ ヒントがありません
  • コンストラクターの検証と BeanNameAware の間のタイミングの不一致により、StepBuilder(JobRepository) が失敗する #5027
  • 空のコレクション入力 #5023 で RecursiveCollectionLineAggregator.aggregate() が失敗する
  • MongoDB での最後のステップ実行の不正な取得 #4896
  • JdbcJobExecutionDao #5044 の潜在的な NPE を修正
  • メーターレジストリのカスタマイズでのメトリクス登録エラー #4759
  • アクチュエーターのアクティブ化と Prometheus の構成が間違っているため、ログに警告が表示されます #4753
  • ChunkOrientedStepBuilder: 再試行のみが構成されている場合 (AlwaysSkipItemSkipPolicy ではない)、デフォルトの SkipPolicy は NeverSkipItemSkipPolicy である必要があります #5077
  • ChunkOrientedStepBuilder: retry() を使用せずに retryLimit() のみが設定されている場合、すべての Throwable (エラーを含む) が再試行されます #5078
  • ChunkOrientedStep は、skipPolicy.ShouldSkip() が false を返した場合に例外をスローしません #5079
  • ChunkOrientedStepBuilder は StepBuilderHelper プロパティ (allowStartIfComplete、startLimit、stepExecutionListeners) を適用しません #5093
  • ChunkOrientedStep: スキップ資格に関係なく、ItemWriter で再試行が枯渇すると常にチャンク スキャンがトリガーされます #5091
  • JobLauncherTestUtils がバッチ 6 RC2 の getJobLauncher() で NPE をスローする #5090
