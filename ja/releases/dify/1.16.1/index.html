#ディファイ1.16.1

何が変わったのか

新機能

ツール複数選択入力

  • ワークフロー ツール ノードは複数選択ドロップダウン入力をサポートするようになり、ユーザーはツール パラメーターを構成するときに事前定義されたリストから複数の値を選択できるようになります。 (#39346)

ワークフロー ノード ロケーター

  • ワークフロー実行ログまたはエラー メッセージ内の node_id を click して、ワークフロー エディター キャンバス内で対応するノードを見つけて強調表示できるようになりました。 (#38187)

ワークフロー ブロック セレクターの改善

  • ブロック セレクター パネルには、キーボード ナビゲーション、カテゴリ プレビューが改善され、ワークフローにノードを追加する際のより直感的な検索エクスペリエンスが追加されました。 (#39212)

サイドバーからエージェント DSL をエクスポート

  • エージェント アプリをアプリのサイドバー メニューから直接 DSL YAML としてエクスポートできるようになり、エージェント構成のバックアップやバージョン管理が簡単になりました。 (#39299)

知識の追跡

  • ナレッジ/RAG ドキュメント処理操作に可観測性トレースをさらに追加し、インデックス作成パイプラインの可視性を向上させました。 (#38959)

セキュリティの強化

  • エージェントのローカル サンドボックスは、厳格な ACL ルールを備えた専用の Squid フォワード プロキシの背後で実行されるようになり、サンドボックスが内部サービスに直接到達するのを防ぎます。 API 上の /files/ エンドポイントと、agent_backend 上の /agent-stub/ のみが許可され、どちらも有効期間の短いアクセス トークンで保護されます。これにより、エージェント サンドボックスでの任意のコード実行の影響範囲が大幅に減少します。 (#39544)
  • Dify API とエージェント バックエンド間の通信では、DIFY_AGENT_API_TOKEN / AGENT_BACKEND_API_TOKEN を介したトークンベースの認証が使用されるようになり、内部サービス境界が強化されます。 (#39622)
  • Jinja2 テンプレート レンダリングを SandboxedEnvironment を使用するように切り替え、ワークフロー コード ノードでのテンプレート インジェクション攻撃を防止しました (#39609)
  • パッチ適用された React サーバー コンポーネントの DoS 脆弱性 (#39539)
  • 電子メールバリデーターで re.fullmatch を使用して末尾の改行を拒否し、バイパス攻撃を防止しました (#39320)
  • ワークスペースへの招待を受け入れる前にアカウントのステータスを検証しました (#39438)

環境変数の変更

新しい変数

|変数 |デフォルト |説明 | |----------|-----------|---------------| | DIFY_AGENT_API_TOKEN | dify-agent-run-token-for-dev-only | API → Agent_backend 認証用の共有ベアラー トークン。 運用環境ではこれを変更してください。 | | AGENT_BACKEND_API_TOKEN | dify-agent-run-token-for-dev-only |エージェントのバックエンド側でも同じトークン。 DIFY_AGENT_API_TOKEN と一致する必要があります。 | | PLUGIN_MODEL_PROVIDERS_CACHE_ENABLED | true |プラグインが外部にインストールされており、キャッシュを無効にできない場合は、false に設定します。 |

[!重要] DIFY_AGENT_API_TOKEN は、Dify API とエージェント バックエンド間の安全な通信に必要な 新しい必須変数 です。デフォルト値 (dify-agent-run-token-for-dev-only) は安全ではないため、運用環境では置き換える必要があります。以下を使用して生成します。

python -c 'import secrets; print(secrets.token_urlsafe(32))'

エージェントバックエンド側の AGENT_BACKEND_API_TOKEN と同じ値を設定します。

Docker 変更の作成

  • エージェント サンドボックス ネットワーク分離: local_sandbox は default ネットワークから専用の agent_sandbox_network + local_sandbox_proxy_network に移動されます。新しい agent_ssrf_proxy サービス (Squid) が追加されました。
  • ベアラー認証: AGENT_BACKEND_API_TOKEN / DIFY_AGENT_API_TOKEN は、api、worker、および agent_backend サービスに渡されるようになりました。
  • 画像タグが 1.16.1 に更新されました。

アップグレード ガイド

モデルタイプの移行

[!重要]

セルフホスト型アップグレードのための 1 回限りのレガシー モデル タイプの移行

この展開が 1.15.0 より前の Dify バージョンからアップグレードされており、この移行がまだ適用されていない場合は、アップグレード後に実行します。

この移行は flask db upgrade には含まれていません。これがないと、レガシー モデル レコードにより、モデル関連の API リクエストがエラーで失敗し、影響を受けるモデルのロードまたは使用ができなくなる可能性があります。

移行を適用する前にデータベースをバックアップします。コマンドはデフォルトでドライラン モードで実行されます。 --apply を再実行する前に、出力を確認してください。移行は冪等であるため、安全に再実行できます。

Docker 作成する

docker ディレクトリから実行します。

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

ソースコードのデプロイメント

flask db upgrade の完了後、リポジトリのルートから実行します。

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

移行を適用した後、ドライラン コマンドを再度実行します。追加の行の更新または削除が報告されない場合は、関連するサービスを再起動し、既存のモデルを正常にロードして呼び出せることを確認します。

Docker Compose (推奨)

cd docker
docker compose down
git pull origin main
docker compose pull
docker compose up -d

データベースの移行は起動時に自動的に実行されます。

[!重要] .env の新しい DIFY_AGENT_API_TOKEN 変数を確認します。デフォルト値は安全ではありません。実稼働用に安全なトークンを生成します。

python -c 'import secrets; print(secrets.token_urlsafe(32))'

ソースコード

git pull origin main
cd api
flask db upgrade
