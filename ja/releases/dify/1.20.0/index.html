dify 1.20.0

マイナー 公開日2026年11月18日 出典langgenius/dify 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディファイ1.20.0 Dify 1.20.0 はトレースのフローを維持し、ナレッジ ベースをより安全に保ちます。 トレースを OpenTelemetry コレクターにエクスポートし、従来の取り込みエンドポイントの廃止後も Langfuse を動作させ続け、アップロードされたナレッジ ファイルのインデックスが作成される前にマルウェアをスキャンします。チャットフローは、エージェント ツールのアクティビティを発生時に表示でき、個人アクセス トークンにより、スクリプトとエージェントがユーザーに代わって Dify OpenAPI を呼び出すことができます。バンドルされたプラグイン デーモンは 0.6.15-local にアップグレードされます。 新機能 · 構成と統合の変更 · データベースの移行 · アップグレード ガイド

新機能

新しい HITL: チームのメッセージング ツールに承認を導入します

電子メールやチームが既に使用しているメッセージング ツールを介して、人間によるレビューをワークフローに統合します。 新しい HITL では、共有チャネル、一元化された連絡先、通知テンプレート、検証済みの承認フォームが導入されており、チームが受信者を一度構成すれば、それをヒューマン入力ノード全体で再利用できるようになり、デフォルトで有効になりました (NEXT_PUBLIC_ENABLE_HITL_IM=true)。 (#44864、#45945)

  • 職場の承認者に連絡します。 電子メールと IM プラットフォーム (Slack、Feishu/Lark、Microsoft Teams、DingTalk、または WeCom) を構成して、チームの既存のチャネルを通じてワークフロー レビュー リクエストを配信します。
  • 連絡先で受信者を管理します。 IM ディレクトリを同期し、共有連絡先リストから承認者を選択します。ワークフローでは、開始者に対処したり、ワンタイムの動的な電子メール受信者を使用したりすることもできます。
  • カードまたはフォームで承認します。 受信者は、サポートされている IM カードでリクエストを直接確認するか、Dify ログインまたは電子メール認証を使用して身元を確認するスタンドアロン フォームを開いて、リクエストを直接確認できます。
  • ワークフロー コンテキストを使用して通知をカスタマイズします。 テンプレートとワークフロー変数を使用して、通知の件名と本文に重要なコンテキストを含めます。
  • 配信のテストと追跡。 テスト通知を送信して設定を確認し、配信記録を検査して、期待どおりに到着しなかったリクエストのトラブルシューティングを行います。
  • 既存のワークフローに新しい HITL を採用します。 ワークフローの準備ができたら、オプトイン移行を使用して従来の Human Input ノードをアップグレードします。 導入要件は、構成と統合の変更 にリストされています。

トレースを任意の OpenTelemetry コレクターにエクスポートします

Dify 実行トレースを既存の可観測性スタックに取り込みます。新しい OpenTelemetry プロバイダ は、アプリとエージェントのトレースを互換性のあるコレクターにエクスポートし、ワークフロー ステップ、モデル呼び出し、ツール アクティビティを好みのプラットフォームでまとめて追跡できるようにします。これらのトレースを使用して、ベンダー固有の Dify 統合を必要とせずに、リクエストの実行を検査し、障害を診断します。 (#45659) Langfuse トレースは、Langfuse v4 と現在の Langfuse Cloud インジェスト サービスをサポートするようになりました。 既存の Langfuse 構成は引き続き機能します。 (#45606)

[!重要] Langfuse Cloud は、2026 年 11 月 16 日に従来の取り込みエンドポイントを廃止し、自己ホスト型 Langfuse v4 は送信されたイベントを拒否します。 1.20.0 にアップグレードすると、これらの展開にトレースを配信し続けることができます。

ナレッジのアップロードをスキャンしてマルウェアを検出する

アップロードされたファイルが抽出またはインデックス付けされる前に、マルウェアがないかスキャンしてナレッジ ベースを保護します。有効にすると (FILE_SCAN_ENABLED=true)、ワークスペースの所有者と管理者は、統合 → ファイル セキュリティ スキャン でスキャナーを一度構成し、各ナレッジ ベースでスキャナーを使用する方法を定義できます。サポートされているスキャナーには、Cloudmersive、Scanii、OPSWAT MetaDefender Cloud、カスタム エンドポイントが含まれます。 (#46090、#46492)

  • ナレッジ ベースごとに保護を選択します。 スキャナーを選択し、スキャンが利用できない場合、またはファイルをスキャンできない場合のフォールバック動作を構成します。
  • Dify 全体でナレッジ アップロードを保護します。 スキャンでは、クラシック ナレッジ ベース、RAG パイプラインのローカル ファイル ソース、エージェント ナレッジ ベースのアップロードが対象になります。
  • ファイルがブロックされた理由を確認してください。 スキャンの失敗は、確認のためにドキュメント リストに表示されます。

Chatflow でエージェント ツールが動作するのを確認する

チャットフローがタスクをエージェント v2 ノードに委任すると (NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true が必要)、ユーザーはどのツールを呼び出すかをリアルタイムで確認できるようになりました。ツールのアクティビティは、プレビューと公開チャットの両方で応答とともに表示されるため、エージェントの進行状況を追跡しやすくなります。ツール カードを展開して、何を要求し、何を返したかを調べます。 (#46220)

個人アクセス トークンを使用して OpenAPI 呼び出しを自動化する

コンソール セッションを共有せずに、スクリプト、CI ジョブ、パーソナル エージェントにユーザーに代わって Dify OpenAPI へのアクセスを許可します。 アカウント ページから個人用アクセス トークンを作成し、その範囲を特定のワークスペースとリソースに設定します。オプションの有効期限を設定したり、自動化の進行に合わせて有効期限を更新したり、不要になった場合は取り消したりすることができます。 (#45540、#46606)

ツリーから GitHub 知識ソースを選択します

リポジトリ、ディレクトリ、問題、プル リクエストの展開可能なツリーから、ナレッジ ベースに追加する GitHub コンテンツを参照して選択します。新しいナレッジ ベースを作成する場合でも、既存のナレッジ ベースにソースを追加する場合でも、ソース構造を調べてインポートする正確なページを選択します。 (#45990)

小さな画面での検索と移動

すべてに移動 で選択可能な範囲を使用して、コンテンツ全体を検索し、結果を絞り込みます。小さい画面では、現在のページのスペースを確保するために、検索とナビゲーションが引き出し内で開きます。 (#45675、#45650) 直接リンクで、Studio の空のアプリまたはテンプレートの作成フローを開くことができるようになりました。 (#45717)

より柔軟な知識の説明とメタデータ

  • ナレッジ ベースの説明が長くなりました。 説明の長さの制限が増加したことで、各ナレッジ ベースにより多くのコンテキストを提供できるようになりました。 (#45075)
  • 外部ナレッジのメタデータ。 外部ナレッジの取得では、コンテンツとともにドキュメントのメタデータが返されるようになりました。 (#22496)

改善点

データベースと起動のオーバーヘッドの削減。 ノード実行の更新により、保存された行の再ロードが回避され、資格情報ポリシーはプロバイダー構成ごとに 1 回評価され、モデルのデフォルトでは有効期間の短いセッションが使用され、埋め込み呼び出しによってデータベース セッションが開かれたままになることはなくなりました。 Web 機能の依存関係も読み込みが遅くなります。 (#46410、#46441、#45806、#45788、#46145) ドキュメントの失敗がより明確になり、レイアウトが安定しました。 ナレッジ ドキュメントでは、特定の失敗の理由と処理段階がレポートされるようになりました。ダイアログは狭いビューポートに適応し、アカウント、ナレッジ、アプリ、スキル、ワークフロー全体で一貫したライフサイクルを維持します。認証ページの読み込みが速くなり、小さな画面にフィットし、キーボード フォーカスにアクセスしやすくなります。セグメント化されたコントロールは、コンパクトなレイアウトを維持し、モーションを減らした設定を尊重しながら、スムーズにアニメーション化します。 (#45128、#46487、#45686、#45668、#45634、#45600、#45640、#45974)

バグ修正

  • より安全なファイル プレビューと署名付きリンク。 インライン SVG プレビューをサンドボックス化し、期限切れのファイル リンクを更新する前に元の署名を検証します。 (#46505)
  • より強力なアクセス保護。 パブリック ストリームからのノード再試行の詳細を編集し、OAuth コールバックの再利用を防止し、メンバーロールの権限を強制し、ターゲット データセットへのスコープ ベクターを削除します。 (#46517、#46001、#46053、#45586)
  • セキュリティ依存関係の更新。 dify-agent-runtime の github.com/klauspost/compress をアップグレードして CVE-2026-116591 に対処し、ランタイム イメージの Node.js をセキュリティ リリース 24.22.3 に更新します。 (#46544、#46206、#46064)
  • 信頼性の高いブロッキング ワークフロー。 実行前にデータベース接続を解放し、準備エラーをすぐに返します。これにより、接続プールの枯渇やタイムアウトまで待機するリクエストのハングを防ぎます。 (#46254)
  • より安定したワーカー。 Redis BRPOP ビジー ループを解決し、プラグインのアップグレード チェックの重複を防ぎ、ワーカー間での同時実行の上限を 20 チェックに設定します。 (#45940、#46500)
  • Chatflow ストリームを完了します。 直接返信した後にストリームを適切に閉じ、ストリームが再開されたときに再接続バジェットをリセットします。 (#45552、#46110)
  • 正しいエージェント実行。 同じプラグイン ツールへの並列呼び出しを保持し、宣言されたアプリ入力をエージェント実行に渡し、アップロードされた画像をビジョン モデルに配信します。 (#45207、#45425、#45745)
  • 正確なナレッジの取得。 BM25 スコアを返すことで Weaviate キーワード/ハイブリッド結果を復元し、バッチ項目がドロップされたときに埋め込みベクトルを整列させ続けます。 (#45642、#45569)
  • 信頼性の高いカスタム API ツール。 OpenAPI サーバー変数を解決し、パス パラメーターをパーセント エンコードし、OpenAPI 3.1 の null 許容共用体をサポートします。 (#46504、#45965、#45895)

リバースプロキシとワーカーの構成

  • 新しい API ルート: WEBHOOK モードでは、要求パス、生の本文、およびプロバイダー署名ヘッダーを保持して、/callbacks/human-input/v2/im/ を API サービス (Docker Compose の api:5001) に転送します。バンドルされている nginx テンプレートには、このルールがすでに含まれています。カスタム nginx、Ingress、またはその他のリバース プロキシ構成に相当するものを追加します。チャネルの生成されたコールバック URL を使用して IM プロバイダーを構成します。 (#44864)
  • 新しい Celery キュー: 非同期 IM コールバック処理と送信後のカード更新用の human_input_delivery と、IM 連絡先ディレクトリ同期用の human_input_contact_sync が含まれます。デフォルトの Docker ワーカー リストには両方が含まれます。カスタム CELERY_QUEUES、CELERY_WORKER_QUEUES、または Celery --queues リストでは、既存のサブスクリプションとともに各キューのアクティブなコンシューマーを提供する必要があります。 (#44864)

Docker 環境ファイル

docker/envs/core-services/shared.env は ロードされなくなりました。コンテナーを再作成する前に、共通の API、ワーカー、および Beat 設定を api-worker.env に移動します。サービス固有の設定は、そのサービスで使用されるオーバーライド ファイルに保存します。 (#46497) パブリック URL は、新しい envs/core-services/urls.defaults およびオプションの urls.env を通じて、Web、API、およびワーカーによって共有されます。

  • CONSOLE_API_URL
  • CONSOLE_WEB_URL
  • SERVICE_API_URL
  • APP_API_URL
  • APP_WEB_URL ブラウザからアクセス可能なベース URL を、/console/api、/api、または /v1 サフィックスを付けずに設定します。 urls.env の明示的な値は、サービス固有の URL 設定をオーバーライドします。 root docker/.env は両方をオーバーライドします。 Web の内部 SERVER_CONSOLE_API_URL は web.env のままです。これにより、新規インストールで生成されたアイコン リンクが 127.0.0.1:5001 を指す問題も解決されます。 (#46497)

データベースの移行

1.19.0 からアップグレードすると、6 つの移行リビジョンが追加され、移行ヘッドが 53c10126d551 から f8b6e2c4a901 に移動します。通常の移行ランナーを通じて完全な Alembic チェーンを適用します。 |リビジョン |変更 | | --- | --- | | 6b7e2a9c4d10 | NULL 許容の started_by_sys_user_id を human_input_im_sync_runs に追加し、行ごとに開始 ID を 1 つだけ必要とします。 | | b2e4c6d8a013 |個人用アクセス トークンとそのリソース/ワークスペース スコープ テーブルを追加します。 | | 8c2f5d7a1e30 |ファイル スキャナー、スキャン ポリシー、スキャン結果テーブルを追加します。 | | 91f4b2d7c8e0 |評価構成テーブル、実行テーブル、および実行項目テーブルを追加します。 | | c7e4a1b2d9f0 |デフォルト値を使用して「評価フレームワーク」列を追加します。 | | f8b6e2c4a901 |評価ブランチとメイン移行ブランチをマージします。 | CE は評価機能を公開していませんが、評価移行は Community Edition にも適用されます。移行チェーンを適用する際には、これらのリビジョンを含めてください。 6 つのリビジョンのいずれも、個別の手動バックフィル コマンドを必要としません。 (#45945、#45540、#46090、#46141) 新しい HITL では、必要なデータベース スキーマが導入され、追加のコマンドを必要とせずに、既存のアカウントの連絡先 ID が自動的にバックフィルされます。これらの移行はすでに 1.19.0 に含まれています。既存の 1.19.0 展開では何もする必要はありませんが、古いバージョンでは完全な移行チェーンを実行する必要があります。従来の Human Input ノードは自動的に移行されず、オプトインのままになります。

アップグレード ガイド

[!重要] コンテナを再作成する前に、廃止された shared.env から設定を移動します。パブリック URL、カスタム HITL コールバック ルーティング、ワーカー サブスクリプションを確認します。 OpenShell の展開には互換性のあるゲートウェイのアップグレードが必要であり、ホーム スナップショットは復元されなくなりました。バンドルされたプラグイン デーモンが 0.6.15-local に更新されました。

導入の準備

  1. データと構成をバックアップします。 データベース、ベクター ストア データ、アップロードされたファイル、プラグイン デーモン ストレージ、エージェント ワークスペース ストレージ、デプロイメント シークレット、および環境ファイルをバックアップします。単一スタックのアップグレードのメンテナンス期間をスケジュールします。
  2. Dify コンポーネントを一緒にアップグレードします。 プラグイン デーモン 0.6.15-local とともに、一致する 1.20.0 API、ワーカー、Web、エージェント バックエンド、およびローカル サンドボックス イメージを使用します。 SECRET_KEY、構成されている PASSWORD_PEPPER、およびローカル サンドボックス認証トークンは変更しないでください。個人用アクセス トークンは SECRET_KEY に依存します。すべての API レプリカで同じ値が使用されていることを確認します。 1.19.0 より前のバージョンからアップグレードする場合は、1.19.0 アップグレード ガイド も参照してください。
  3. shared.env を移行します。 envs/core-services/api-worker.env が存在しない場合は、envs/core-services/shared.env の名前をそのパスに変更します。両方が存在する場合は、欠落している設定のみをマージし、意図的な空の割り当てを含む既存の api-worker.env 値を保持します。サービス固有の設定を適切なサービス オーバーライド ファイルに保持します。 shared.env を使用しない展開には移行は必要ありません。
  4. パブリック URL を統合します。 envs/core-services/urls.env が存在しない場合にのみ、urls.defaults から envs/core-services/urls.env を作成します。目的のパブリック URL 値をそこに移動し、個々のサービス ファイルから重複した割り当てを削除します。既存のルート .env 値が優先されます。内部 Web API ルーティングを web.env に保持します。
  5. 環境、ルート、およびキューの変更を適用します。 新しい HITL 設定、IM コールバック ルート、および両方の Celery キューを含む、構成と統合の変更 に従います。
  6. プラグイン ストレージの初期化を実行します。 init_permissions はデーモンの UID 1001 に対して ./volumes/plugin_daemon も準備し、デーモンはそれが完了するのを待ちます。 docker compose up -d を使用してデプロイメントを再作成し、init サービスが実行されるようにします。 (#45615)

OpenShell のデプロイメント

OpenShell ゲートウェイと SDK を一緒に サポートされている 0.1.x ライン内の 0.1.3 以降にアップグレードし、Dify API とエージェント バックエンドも一緒にアップグレードします。ゲートウェイは、ZZPH100​​ZZ から派生したサンドボックスごとの認証トークンを保持しながら、ネイティブ サービス公開とベアラー パススルーをサポートする必要があります。マスター シークレットをエージェント バックエンド レプリカ間で同一に保ちます。 (#45862) リリース チェックアウトから OpenShell ランタイム イメージを構築し、DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE をゲートウェイのコンピューティング ノードで使用できる正確なイメージ参照に設定します。画像には shellctl と iproute2 の両方が含まれている必要があります。キャッシュされた古いランタイム イメージには、必要なネットワーク ツールが不足している可能性があります。 以前の展開全体で共有された shellctl トークンからアップグレードする場合は、新しい高エントロピーのマスター シークレットを生成し、すべてのエージェント バックエンド レプリカをまとめて更新します。アクティブな作業を排出し、既存のサンドボックスを停止して再起動すると、shellctl は派生した資格情報で再起動されます。すでに正常なサンドボックスを再取得しても、その資格情報は更新されません。 共有ボリュームのホーム スナップショットと DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH は削除されます。既存の実行中のサンドボックスは停止/再起動サイクル全体にわたってその状態を保持しますが、新しく作成されたバインディングはイメージのデフォルトのホームから開始されます。 DIFY_AGENT_OPENSHELL_DRIVER_CONFIG はオプションになりました。アップグレードする前に、ランタイム イメージの要件を含む OpenShell 導入ガイド を確認してください。他のサンドボックス バックエンドは影響を受けません。

Docker 作成

1.20.0 タグとイメージが公開されたら、デプロイメントを正常に停止し、リリースに切り替え、ローカル構成ファイルを移行して、更新されたサービスをプルして開始します。

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

API 起動移行を有効にしたままにするか (MIGRATION_ENABLED=true)、新しいワーカーを開始する前に、管理された移行プロセスを通じて完全な移行チェーンを適用します。環境ファイルを変更した後は、docker compose up -d を使用してください。通常の再起動ではリロードされません。

ソースのデプロイメント

Python 3.13、Node.js 24.22.3 以降の 24.x 行、pnpm 12.18.0 を使用します。サービスを停止してリリースに切り替えた後、リポジトリ ルートから次のコマンドを実行します。

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Web を再構築し、同じリリースから API、ワーカー、スケジューラ、エージェント サービスを再起動します。スタンドアロン エージェント バックエンドを個別に展開する場合は、そのロックされた依存関係を更新します。既存のワーカー サブスクリプションを保持し、必要に応じて 2 つの HITL キューを追加します。 完全な Changelog: 1.19.0 → 1.20.0
