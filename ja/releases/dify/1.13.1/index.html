#ディファイ1.13.1

🚀 主要な機能変更

データ プラットフォームとデータセットの操作

  • ベクトル検索と全文検索の両方でサポートされるバックエンド オプションとして Hologres を追加しました。
  • データセット ドキュメントのダウンロード用にサービス API エンドポイントを追加しました。
    • 選択したドキュメントのバッチ ZIP ダウンロード。
    • 単一ドキュメントのオリジナル ファイルの署名付き URL のダウンロード。

ワークフローとチャットエクスペリエンスの改善

  • 重大な変更: HITL 電子メール コンテンツは、配信前にマークダウン レンダリングを使用するようになりました。 raw/plain 動作に依存する既存の電子メール テンプレートは、アップグレード後に表示が異なる場合があります。
  • ドラフト変数はアプリ スコープではなくユーザー スコープになりました。アップグレード後は、過去のドラフト変数は使用できなくなります。
  • ワークフロー キャンバスにエッジ コンテキスト メニューのサポート (エッジの直接削除を含む) を追加しました。
  • ワークフロー編集でノード タイプを変更するときに、既存の接続が保持されるようになりました。
  • 埋め込みチャット入力に構成可能な送信キー動作 (Enter と Shift+Enter) を追加しました。
  • メッセージ終了ストリーム応答にファイル ペイロードを追加しました。
  • デフォルトのモデル選択ロジックから GPT-4 固有のハードコーディングされた動作を削除しました。
  • アプリケーション メッセージと関連フィードバックを JSONL.GZ (ローカルまたはクラウド ストレージ) にエクスポートするための新しい export-app-messages CLI コマンドを追加しました。

🔐 セキュリティアップデート

  • 影響を受ける実装でパラメータ化された SQL に切り替えることにより、ベクター ストア クエリ パスでの SQL インジェクションのリスクを防止しました。
  • 強化された HITL 電子メール配信:
    • 件名と本文のコンテンツをサニタイズします。
    • SMTP ヘッダー挿入ベクトルを防ぐために、サブジェクトから CR/LF を削除します。
  • 会話削除 API の所有権チェックを強制しました。
  • 残留認証情報のリスクを軽減するために、プラグインのアンインストール中に古いプロバイダー認証情報をクリアしました。
  • エンタープライズ API エラー処理と、無効または期限切れのライセンス状態に対するライセンス強制の動作が改善されました。

🏗️ 構成、アーキテクチャ、および展開の更新

導入と運用

  • LLM を多用するサマリー生成タスク用に、専用の Celery キュー dataset_summary を追加しました。
    • 概要ジョブのバックログを回避するために、ワーカーがこのキューにサブスクライブしていることを確認します。
  • 保持クリーンアップ タスク (メッセージ/ワークフロー実行) のテレメトリ メトリックと、有効期間の短いコマンド ジョブのフラッシュ動作を追加しました。

構成の変更

  • REDIS_MAX_CONNECTIONSを追加しました。
  • EVENT_BUS_* 設定を優先し、PUBSUB_* イベントバス設定を非推奨にしました。

🛠 その他の注目すべき変更点

  • workflow_runs.started_at が再開時に上書きされる問題を修正。
  • 分割トランザクションのエッジ ケースによって引き起こされるメタデータのバッチ編集のサイレント エラーを修正しました。
  • ナレッジ検索におけるメタデータ フィルター抽出の問題 ({{...}} 条件) を修正しました。
  • 高度なチャット アプリケーションで引用の表示を復元しました。
  • HITL ノード後の会話変数のリセット動作を修正しました。
  • ナレッジ検索ノード構成フローでのページのクラッシュを修正しました。
  • チャット アシスタントが応答モードの動作をブロックする問題を修正しました。
  • 互換性を向上させるために、Weaviate ベクター属性に doc_type 処理を追加しました。
  • コンテキスト切断エラーを解決するために、OpenTelemetry の依存関係をアップグレードしました。

アップグレード ガイド

[!重要] カスタム CELERY_QUEUES を使用する場合は、workflow_based_app_execution が含まれていることを確認してください。
ENABLE_API_TOKEN_LAST_USED_UPDATE_TASK=true の場合は、api_token も含めてください。

背景と詳細については、上記の ⚠️ アップグレードに関する重要な注意事項 および **🔧 運用上の注意事項 ** を参照してください。

Docker デプロイメントの構成

  1. カスタマイズした docker-compose YAML ファイルをバックアップします (オプション)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. メインブランチから最新のコードを取得します。

    git checkout main
git pull origin main

  3. サービスを停止します。 dockerディレクトリで実行してください。

    docker compose down

  4. データのバックアップ

    tar -cvf volumes-$(date +%s).tgz volumes

  5. アップグレードサービス

    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンド サーバーを停止します。

  2. リリース ブランチから最新のコードを取得します。

    git checkout 1.13.1

  3. Python の依存関係を更新します。

    cd api
uv sync

  4. 次に、移行スクリプトを実行しましょう。

    uv run flask db upgrade

  5. 最後に、API サーバー、ワーカー、および Web フロントエンド サーバーを再度実行します。
