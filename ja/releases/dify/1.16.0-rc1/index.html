#ディファイ1.16.0-rc1

Dify Agent の紹介 (実験的): Dify の新しいエージェント エクスペリエンス

[!警告] Dify Agent サービス ⚠️trusted の悪意のないユーザー⚠️ にのみ提供する必要があります。

ご存知の方も多いと思いますが、シェルベースの LLM エージェント パラダイムは、エージェントの機能に大きな飛躍をもたらし、エージェントに対する考え方を変えました。一方、スキルは機能をパッケージ化して配布するための標準化された方法を提供し、強力なエージェントの構築を容易にします。

本日、Dify Agent を実験的に起動します。他の主要なエージェントと同様に、Linux サンドボックスで実行されます。このリリースには以下が含まれます:

  • Dify Agentを作成するためのビルダー

    • UI を通じて Dify エージェントを構築できます。基本プロンプトを設定し、スキルとファイルをアップロードし、Dify エコシステムからツールとナレッジを接続します。
    • Dify エージェントの構築を支援するエージェントも提供します。会話を通じて、Linux サンドボックス環境を構成し、必要なパッケージをインストールし、Dify Agent が後で使用できる新しいスキルとファイルを作成できます。

  • Dify Agent のための Dify ワークフローの統合

    • Dify ワークフローで既存の Dify Agent を使用することも、インライン Dify Agent を一時的に作成することもできます。ワークフロー ノードによって定義されたタスクを実行し、必要な出力を生成して、それを次のノードに渡します。

  • 新しい Web アプリ エクスペリエンス

    • 構築した Dify Agent は、Web アプリとして公開して使用できます。使い慣れたユーザー エクスペリエンスはそのままに、Dify Agent によって強化されています。

ドキュメント: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

制限事項

現在の実験的リリースでは、すべての Dify Agent が同じサンドボックスで実行されることに注意してください。これは次のことを意味します。

  • 通常の状況では、各 Dify Agent は環境を構成し、他のエージェントに干渉することなく独自のワークスペース内でタスクを実行します。
  • ただし、簡単な手順を実行すれば、どの Dify Agent も他の Dify Agent の環境やデータ (ユーザー データを含む) を読み取ったり、干渉したりすることができます。

厳密な分離は将来のリリースで実装される予定です。今のところ、

[!警告] Dify Agent サービス ⚠️trusted の悪意のないユーザー⚠️ にのみ提供する必要があります。

同様に、Dify Agent はまだ完全に準備ができていないため、一部の機能が Dify Agent で使用できない場合があります。たとえば、ワークフローに Dify Agent を参照するノードが含まれている場合、Dify ワークフロー DSL エクスポートは使用できません。

アップグレード ガイド

[!重要]

  • このリリースには、新しいデータベースの移行が含まれています。アップグレードの一部としてそれらを実行します。
  • 環境変数が変更されました。 「環境変数の変更」セクションを確認し、それに応じて .env を更新します。
  • Docker Compose 設定ファイルが変更されました。カスタマイズされた docker-compose.yaml を維持する場合は、変更を確認し、ローカルのカスタマイズを慎重に再適用してください。

Docker デプロイメントの構成

  1. カスタマイズした docker-compose YAML および env ファイルをバックアップします。 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. 1.16.0-rc1 リリースの最新コードを取得します。 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. サービスを停止します (docker ディレクトリ内で実行)。 
    docker compose down
  4. データをバックアップします。 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. env ファイルの変更を確認し、ローカルのカスタマイズを再適用します。
  6. サービスをアップグレードします。 
    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンド サーバーを停止します。
  2. 1.16.0-rc1 リリースの最新コードを取得します。 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Python の依存関係を更新します。 
    cd apiuv sync
  4. データベースの移行を実行します。 
    uv run flask db upgrade
  5. API サーバー、ワーカー、および Web フロントエンド サーバーを再起動します。新しいエージェント機能を試すには、dify-agent とshellctl を起動する必要もあります。 重要:shellctl には組み込み認証が含まれていません。セキュリティのため、コンテナ内で実行することを強くお勧めします。
