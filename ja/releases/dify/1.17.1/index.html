#ディファイ1.17.1

[!警告] バンドルされた Weaviate を使用するセルフホスト展開では、1.17.1 を開始する前に手動の段階的アップグレードを完了する必要があります。 バンドルされた Weaviate サーバーは 1.27.0 から 1.39.2 (12 のマイナー バージョン) に移行し、マイナーのスキップは サポートされていません。プルして再起動すると、ベクター検索がサイレントかつ永久に中断される可能性があります。以下のアップグレード ガイドを参照してください。新規のデプロイメント、外部 Weaviate、およびその他のベクター ストアは影響を受けません。

新機能

データセットを対象としたナレッジ ベース API キー

  • ナレッジ ベース サービス - API キーのスコープはワークスペース全体でした。1 つのキーでテナント内のすべてのナレッジ ベースの読み取りと書き込みができるため、単一のナレッジ ベースへの統合アクセスを許可するということは、そのすべてのナレッジ ベースへのアクセスを許可することを意味します。作成時にワークスペース/このナレッジ ベースのスコープ セレクターを使用して、ナレッジ ベースの API アクセス パネルからキーを特定のナレッジ ベースにバインドできるようになりました。バインドされたキーは、他のデータセット (ドキュメントと検索の両方) およびデータセット ID を持たないエンドポイント (list-all など) に対して 403 を返します。既存のキーはバインドされておらず、ワークスペース全体の動作が維持されるため、アップグレードしても何も変更されません。 (#37569)

ワークフロー ノードとコメントのキーボードの動き

  • ワークフロー キャンバスでは、何かを再配置するにはマウスが必要でした。ノード、複数ノードの選択、コメント マーカー、およびドラフト コメントを矢印キーで移動できるようになりました (Note、Iteration、Loop ノードを含む) より大きなステップを実行するには Shift キーを押したままにします。連続移動はキーのリリースまたはブラーでコミットされるため、キーを押すごとに 1 つではなく 1 つの元に戻すエントリが生成され、読み取り専用モード、コンテナの境界、およびコラボレーションの更新はすべて引き続き尊重されます。 (#41967)

マーケットプレイス クリエイターのプロフィールとホームページの再デザイン

  • プラグイン作成者は現在、/marketplace/creator/<handle> に公開プロフィール ページを開設しており、サイドバーのヘルプ メニューの新しいクリエイター センター エントリからアクセスできる発行者サイドバーに自分の作品がリストされています。マーケットプレイスのホームページは、ヒーロー、バナー カルーセル、スティッキー検索、カタログ タブ、タグ/言語フィルターを中心に再構築され、積み重ねてスワイプ可能なモバイル レイアウトになっています。バンドルがプラグイン カテゴリに混在しなくなりました。 (#41538)

構成可能なマークダウン フォームのフィールド名の長さ

  • Markdown フォームのフィールド名の制限は 128 文字でハードコードされており、生成されたより長いフィールド名に対応する方法がありませんでした。これは、MARKDOWN_FORM_FIELD_NAME_MAX_LENGTH (Docker) または NEXT_PUBLIC_MARKDOWN_FORM_FIELD_NAME_MAX_LENGTH (直接 Web デプロイメント) を通じて構成可能になり、デフォルトは以前の 128 になります。文字検証とプロトタイプ汚染保護は変更されていません。 (#41697)

バグ修正

ナレッジベース

このリリースでは、エラーを報告せずにドキュメントのコンテンツを変更する一連の抽出バグが修正されています。アップグレード後に影響を受けるドキュメントを再インポートします。インデックス付きテキストは遡及的に修復されません。

  • CSV セルは、インデックス付けの前に pandas 型推論を通過しました。 先頭ゼロ コードは浮動小数点数 (00123 → 123.0) になり、空のセルはリテラル文字列 nan になり、NA または NULL を含むセルは欠損値になりました。エクストラクターはすべてをテキストとして読み取り、欠損値の推論を無効にするようになりました。明示的な csv_args は、型付き解析を必要とする呼び出し元に対してこれをオーバーライドします。 (#41922)
  • 概念テーブルの行で列が失われたり、列が増えたりしました。 セル内の各リッチ テキスト セグメントは独自の Markdown 列として出力されるため、書式設定 (太字、リンク、メンション) が混在するセルは余分な列を生成し、テーブルを破損します。一方、空のセルは完全にスキップされ、残りの行が左にシフトされました。セルは、セグメントが連結されて列ごとに 1 つずつ出力されるようになりました。 (#41993)
  • 最初の書式変更時に Notion データベース プロパティが切り詰められました。 rich_text および title プロパティは最初のセグメントのみを読み取るため、world が太字の Hello world というタイトルは、単なる Hello としてインデックス付けされました。すべてのセグメントが結合されました。 (#42050)
  • 二重引用符を含む .xls セルにより行が破損しました。 エクストラクターは "column":"value" ペアを出力します。 .xlsx パスは埋め込まれた引用符をエスケープしましたが、従来の .xls パスは引用符をそのまま補間したため、he said "hi" は "note":"he said "hi"" になりました。両方のエンジンが同じコンテンツに対して同じように動作するようになりました。 (#42049)
  • URL からロードされた PDF はベア AssertionError でクラッシュしました。 テナント コンテキストが PDF エクストラクターに追加された後、load_from_url によって使用されるコード パス (ターゲットが Content-Type: application/pdf を返すたびに組み込みの Web スクレイパーを含む) が、URL ロードでは決して持たないアップロード レコードでアサートされました。テナント コンテキストはオプションになり、画像抽出が存在しない場合はスキップされ、テキスト抽出は再び機能します。 (#41950)
  • 組み込みの Web スクレイパーは、ページ テキストの代わりに Python データ構造を返しました。 readabilipy は、出力テンプレートに直接補間された辞書のリストとして plain_text を返します。そのため、スクレイピングされたすべてのページは、辞書構文、引用符、HTML タグを含む [{'text': '<p>…</p>'}, …] として返されます。項目は読みやすいテキストにフラット化されました。 (#41954)
  • 部分的なセグメントは、ワイプされた添付ファイルを更新します。 attachment_ids を省略したセグメント更新は、「何も置換しない」ものとして扱われ、セグメントの添付ファイル バインディングとマルチモーダル ベクトルが削除されました。 attachment_ids が明示的に指定されない限り、添付ファイルはそのまま残されるようになりました。 [] を渡してもそれらはクリアされます。 (#41777)
  • 無効な Markdown イメージ リンクを持つドキュメントは、インデックス作成キューを停止させる可能性があります。 相対、プロトコル相対、data:、ftp:、および不正なイメージ ターゲットはすべてリモート イメージ フェッチャーに渡され、SSRF 再試行ループに入ったため、多くの不正な参照を持つ 1 つのドキュメントが、その背後にあるすべてをバックアップするのに十分な時間インデックス作成ワーカーを保持する可能性がありました。フェッチ不可能なターゲットは検証され、スキップされるようになりました。 (#41343)
  • コンテンツを削除すると、オブジェクト ストレージに孤立したファイルが残ります。 セグメントの削除、マルチモーダルの再インデックス作成、およびバッチ ドキュメントの削除では、それぞれデータベース行が削除されますが、物理的な添付ファイル オブジェクトは残ります。 3 つのパスすべてで、データベースのコミット後に基になるオブジェクトが削除され、孤立チェックが行われるため、他のセグメントと共有されている添付ファイルは存続します。 (#41400、#41999、#41256)
  • テキスト ファイルのプレビューがバイナリとして誤って報告されました。 プレビューのバイト制限がマルチバイト UTF-8 文字を超えると、厳密なデコードが失敗し、ファイル全体がバイナリとして分類されました。これは、256 KiB 境界に単一の非 ASCII 文字が含まれるデフォルトのプレビューで再現可能でした。プレビューでは最長の完全な UTF-8 プレフィックスが保持されるようになりました。完全に無効なエンコーディングを持つファイルは、依然としてバイナリとして報告されます。 (#41761)

モデルプロバイダー

  • 1.15 以前からのアップグレードでは、モデルが使用できなくなることはなくなり、手動コマンドも必要なくなりました。 1.15 より古いインストールでは、プロバイダー テーブルにレガシー モデル タイプの値 (text-generation、embeddings、reranking) が残っているため、モデル関連の API リクエストが失敗し、影響を受けるモデルがロードされなくなります。 1.16.1 と 1.17.0 の両方で、これは手動で実行する必要がある別個の flask data-migrate legacy-model-types ステップとして出荷されました。これは flask db upgrade の一部として実行されるようになりました。レガシー値は llm / text-embedding / rerank に正規化され、レガシーと正規の行の衝突は資格情報の参照を保持しながら決定論的に解決され、プロバイダー キャッシュの名前空間はローテーションされるため、キャッシュされた古い資格情報が移行された行をシャドウすることはありません。 (#41326、#41294 を修正)
  • 組み込みのファイル アップロード データ ソースは、必要のない承認を要求しました。 RAG Pipeline ナレッジ ベースを作成するときに、ローカル ファイルのアップロードで「最初に承認してください」と表示され、作成チェックリストにフラグが付けられました。これは、資格情報スキーマを宣言しないプロバイダーには保存された資格情報行がないため、常に未承認として報告されるためです。認証情報不要のプロバイダーは、直接承認済みとしてマークされるようになりました。 (#39772)
  • プロバイダー スコープの資格情報検証ルールが適用され、不足しているツール資格情報は不透明に失敗するのではなく、表面化されます。 (#41659、#41726)

ワークフローとトリガー

  • 人による入力フォームは、スタックしているように見えるままワークフローを終了する可能性があります。 1.17.0 の HITL コールバック移行以降、フォームを送信すると承認ボタンが画面上に残り、公開された Web アプリの入力がブロックされました。これは、エンジンが応答パイプラインが予期するフォーム入力イベントやタイムアウト イベントなしで汎用ノード成功イベントを発行したためです。これらのイベントは再構築され、送信されたファイルの値、元のタイムアウト期限、および実行メタデータが保存されます。 (#42082)
  • **1.17.0 にはランタイム サポートが同梱されていますが、反復ノードまたはループ ノード内に人間による入力を配置できませんでした。2 つの古いエディター ガードにより、コンテナー内でのノードの選択、接続、貼り付けが依然としてブロックされていました。 (#40061)
  • 人による入力タイムアウト エッジは、間違ったブランチを起動する可能性があります。 エディターはタイムアウト エッジを __timeout として書き込みますが、バックエンドは __timeout__ と比較するため、実行時にタイムアウトは作成者が描画したタイムアウト ブランチではなくユーザー アクション ブランチを取る可能性があります。 (#40746)
  • 同じ実行内の 2 回目の Human Input 一時停止は再開できなくなる可能性があります。 オブジェクト ストレージが前の一時停止スナップショットの削除を拒否した場合、例外によりトランザクションが中止されました。実行はすでに PAUSED として永続化されていましたが、その唯一の一時停止行は以前の既に再開された行であったため、次の送信は Cannot resume an already resumed pause で失敗しました。スナップショットのクリーンアップはベストエフォートになり、孤立したオブジェクト キーは後のクリーンアップのために記録されるため、実行の永続的な状態は正しいままになります。 (#41581)
  • Workflow-as-Tool は最初の End ノードの出力のみを公開しました。 出力宣言はすべての End ノードから収集されるようになり、それぞれのソース ノードがリストされ、重複または予約された名前の影響を受ける出力ごとに 1 つの警告が表示され、ライブ ドラフト メタデータが利用できない場合は公開されたスキーマへのフォールバックが行われます。 (#41517)
  • ループ ブール ブレーク条件が一致しません。 新しい条件は、ブール値ではなく文字列として "true" / "false" として保存されました。値は実際のブール値として保存および保持されるようになり、従来の文字列値は表示時に正規化されます。 (#41186)
  • トリガー エントリ ワークフローは、Web アプリ、サービス API、OpenAPI、および MCP tools/call から手動で呼び出すことができます。これにより、決して機能しないワークフロー実行が作成されます。これらは、HTTP と MCP JSON-RPC で共有されるビジネス コードを使用して、実行またはログが作成される前に拒否されるようになりました。実際のトリガーの実行、読み取り専用エンドポイント、ID による履歴スタート バージョンの実行は影響を受けません。 (#41519)
  • 単一の不良 LLM ノードにより、エディタ全体がダウンしました。 LLM ノードに model_selector があったワークフローは、ワークフロー スタジオのロード時にクラッシュし、ノードごとのチェックリストがクラッシュし、ページ レベルのエラー境界をトリップし、1 つのノードにフラグを立てるのではなく、キャンバス全体を使用不能にしました。 (#41707)
  • 公開検証で従来のバリデーターを解決できなかったため、エージェント V2 が有効になると、従来のエージェント ノードを含むワークフローを公開できなくなりました。これらは再び公開されますが、従来のエージェント ノードはノード ピッカーから非表示のままになります。 (#41368)
  • ワークフローからツールを作成すると、以前に公開されたバージョンが使用されました。 現在のワークフローが最初に公開され、更新パスがすでに行ったことと一致します。公開が失敗すると、古いバージョンにサイレントにバインドするのではなく、プロバイダーの作成が停止します。 (#41528)
  • Webhook トリガー ノードの削除を元に戻すと、その URL が変更されました。 (#42069)
  • ドキュメントの作成と更新で「1 つ以上のファイルが見つかりません」と報告される場合があります。アップロードがコミットされているにもかかわらず、MySQL で。 MySQL のデフォルトの REPEATABLE READ では、アップロードが別のセッションで行われる前に、要求セッションの読み取りスナップショットが固定されていたため、書き込まれたばかりの行は表示されませんでした。影響を受ける 4 つのエンドポイント (テキストによる作成、ファイルによる作成、テキストによる更新、ファイルによる更新) はすべて、ルックアップの前にスナップショットを更新するようになりました。 PostgreSQL は影響を受けませんでした。 (#41840)
  • 大規模なワークフロー グラフがコラボレーション ソケットを破壊しました。 sync_request ペイロードが Engine.IO のデフォルトの 1 MiB を超えたため、フレームが拒否され、エディターが再接続ループしました。上限は WEBSOCKET_MAX_HTTP_BUFFER_SIZE (デフォルトは 10 MiB) を通じて構成できるようになりました。 (#41347)
  • アクセス ポイント ページには、公開ワークフロー リクエストが単に失敗した場合に「公開バージョンがありません」というガイダンスが表示されなくなり、403 を返したリクエストが再試行されなくなりました。 (#41572)

エージェントとチャット

  • Chatflow Agent V2 はターン間ですべてを忘れてしまいました。 セッションは conversation_id によってキー付けされるようになったため、会話全体にわたってメモリが保持されます。フォローアップでは、会話中に新しいエージェント名簿バージョンを公開すると、新しい設定が以前の参加者とペアになり、世代の検証に失敗するという関連するケースが修正されました。既存の会話は開始時のバージョンに固定されたままとなり、新しい会話のみが現在の会話を選択します。 (#41871、#42105)
  • 完全に「思考」としてレンダリングされた推論モデルからの応答。 GLM-5.3 などのモデルは、思考連鎖を <think> タグでラップしており、</think> が発行される前にツール呼び出しによって生成が頻繁に中断され、応答がまだ開いているタグ内にネストされたままになります。ツール ログがストリームを中断したとき、実際のコンテンツの後で新しい <think> が開始したとき、およびストリームの終了時に、ダングリング タグが閉じられるようになりました。さらに、Markdown プリプロセッサで同じ修復が行われるため、すでに保存されている出力が正しくレンダリングされます。 (#41764)
  • エージェント アプリにアップロードされた画像は、モデルに表示されるのではなく、シェルのダウンロード手順に変換されました。ビジョン対応モデルは、選択した資格情報にバインドされたモデル スキーマから検出されたネイティブ マルチモーダル コンテンツとしてそれらを受信するようになりました。ダウンロード フォールバックは、非画像ファイルおよびビジョン サポートのないモデルに対して保持され、画像 URL と Base64 ペイロードはエージェント バックエンド ログから編集されます。 (#41685)
  • 提案された質問には数分かかるか、ハングする可能性があります。 専用の提案された質問モデルが構成されていない場合、エンドポイントはワークスペースのデフォルトに戻り、reasoning_effort=high、2,560 トークンの出力許容量、およびグローバルな 600 秒のプラグイン タイムアウトなどの高価な設定を継承したため、バックエンドが動作し続けている間、ブラウザーは 100 秒後に諦めました。出力は 256 トークンに制限され、思考は無効になるか、サポートされている最低の労力に設定され、リクエスト スコープの 30 秒のタイムアウトが適用されます。報告された 1 件のケースでは、113 ～ 344 秒から 3 秒未満になりました。使用できないデフォルト モデルは、失敗するのではなく、すぐに空のリストを返すようになりました。 (#41705)
  • E2B 支援エージェントの実行が 502 binding_create_failed で失敗しました。 固定された E2B SDK の古い HTTP/2 接続が、インライン チャットの失敗として表面化しました。 SDK は、影響を受けるトランスポート パスを超えてアップグレードされ、制限付きトランスポートの失敗時に接続/一時停止/キル/スナップショットの削除が 1 回再試行され、プロバイダーの容量が枯渇した場合、作成失敗として報告されるのではなく、429 が返されるようになりました。バインディングとスナップショットの作成はワンショットで行われるため、あいまいな結果が黙って採用されることはありません。 (#41623)
  • エージェント プレビューは、構成と一致しなくなったセッションを再利用しました。 プレビューはドラフトをその場で編集するため、会話では構成レイヤーが追加、削除、または並べ替えられたセッション スナップショットが保持される可能性があり、エージェント バックエンドは内部不一致エラーでそれを拒否しました。これにより、新しい会話を開始する命令を含む 409 agent_session_configuration_changed が返されるようになりました。レイヤ トポロジを変更せずに設定の 値 を変更しても、セッションは再利用されます。 (#41447)

サービス API および OpenAPI

  • 生成されたサービス API コントラクトは、実行時の動作に合わせて再調整されました。Null 非許容フィールドには null のデフォルトが含まれなくなり、コンソールのみの権限メタデータが除外され、エンドポイントが返さないエラー応答が削除され、履歴の 404/503 宣言が復元され、チャット/完了とワークフローの動作が正確に文書化されるようにタスク停止リクエストのスキーマが分割されました。これにより、リクエストの処理ではなく、エクスポートされたコントラクトと生成された client が変更されます。 (#41248、#41274、#41943)
  • サービス API のレート制限の説明が修正されました。 (#41975)

同時実行性とデッドロック

  • 同時ナレッジ取得でデッドロックが発生する可能性があります。 ヒット カウントの更新により、1 つの UPDATE … WHERE id IN (…) 内の一致するすべてのセグメントが増加しました。また、PostgreSQL では、ID が指定された順序で行ロックが取得される保証はありません。重複する同時取得により、異なる順序でロックが取得され、deadlock_detected で失敗する可能性があります。ロックはインクリメント前に安定した ORDER BY id で取得されるようになり、デッドロック エラーを厳密に範囲とした最大 3 回の再試行が行われます。 (#41979)
  • 自動概要生成はワーカーを無期限にハングさせる可能性があります。 Tencent VectorDB は JSON メタデータのブール値を拒否するため、is_summary: true マーカーは概要の生成と埋め込みがすでに成功した後、upsert 時に失敗します。次に、障害パスは 2 番目のデータベース セッションを開いて、呼び出し元のセッションがロックされたままの同じ行にエラーを記録するため、それぞれが他方を待機し、タスクがワーカー スロットを占有しました。マーカーは Tencent のみの整数になり、エラーは呼び出し元が所有するセッションに記録されます。 (#41916)

スキル、プラグイン、トリガー

  • Swagger ツールの承認はページの更新後も存続し、SSR は MARKETPLACE_API_URL を読み取るときに /api/v1 を追加するようになりました。 (#41656、#41824)

アップグレード ガイド

バンドルされた Weaviate サーバー アップグレード

[!警告]

既存のバンドルされた Weaviate 展開には段階的な手動アップグレードが必要です

このリリースでは、バンドルされている Weaviate サーバーが 1.27.0 から 1.39.2 に移動します。マイナー バージョンのスキップはテストもサポートも回避されず、どのリリースでも、前のバージョンが少なくとも 1 回実行されていることが期待されるオンディスク移行が行われる可能性があります。既存のデータ ボリュームは、1 回のステップで 12 のマイナーを超えることはできません。

1.17.1 を引っ張って再起動しないでください。 すべてのマイナー リリースを順番にボリュームを上げ、各段で優雅に停止しながら、それぞれの最新パッチに到達します。

ランブックに従います: Weaviate サーバー アップグレード パス

これは、バンドルされた Weaviate を既存のデータで実行する場合にのみ適用されます。確認してください:

grep -E '^VECTOR_STORE=' docker/.env

新しいデプロイメントは、空のボリュームを持つ 1.39.2 で開始されるため、何も必要ありません。外部の Weaviate サーバーおよびその他のベクター ストアは影響を受けません。

Runbook は、イメージ ラダー、ラングごとの検証コマンド、バックアップ、ロールバックの信頼できる情報源です。手順の概要は次のとおりです。

  1. Dify のリクエスト サービスとワーカー サービスを停止し、最後のラングが通過するまで停止したままにします。
  2. Weaviate ボリュームをバックアップします。
  3. 13 行すべてをステップ実行します (1.27 → 1.28 → … → 1.38 → 最後に、このリリースで固定されているバージョンである 1.39.2 になります)。各行の後に確認します。
  4. 一時的なイメージ編集を元に戻し、以下の通常のアップグレード手順を続行します。

開始する前に、次の 2 つの障害モードを知っておく価値があります。

  • ハードキルは、ベクターリコールをサイレントかつ永久に破壊します。 Weaviate は HNSW インデックスをメモリに保持し、コミット ログを通じて永続化します。 docker kill、docker rm -f、OOM キル、または Docker の猶予期間を超える停止により、ログが不完全なままになる可能性があります。 1.39.2 で測定したところ、ハードキル後のオブジェクト数、オブジェクト リスト、BM25 検索、ID によるフェッチはすべて正常に見えましたが、near_vector では 700 個のオブジェクトのうち 680 個にしか到達できませんでした。何も記録されず、修復されません。唯一の修復はナレッジ ベースのインデックスを再作成することです。必ずdocker compose stop -t -1 weaviateで停止してください。
  • クエリは再起動するたびに数秒間失敗します。 /v1/meta は開始後約 2 秒で応答しますが、1.31 以降、コレクションは 4 ～ 9 秒後にマウントされます。そのウィンドウ内では、/v1/objects は 404 を返し、GraphQL は 422 no graphql provider present … no schema is present を返します。アップグレード中の警告、および誤った警告 - rusting /v1/meta ではなく、実際のコレクション クエリが成功するまで待つかポーリングします。 コレクションのレイアウトは変更されないため、インデックスの再作成は必要ありません。 Dify は引き続き、各データセットを、独自に提供された名前付きベクトル default とサーバーのデフォルトのコサイン メトリックを含む Vector_index_<dataset_id>_Node として保存します。 Python weaviate-client も注意する必要はありません。1.17.0 と 1.17.1 はどちらも 4.22.0 をピン留めしており、ラダー上のすべてのサーバー バージョンに対して機能します。

1.27.0 より古い Weaviate サーバーを実行していますか? それともまだ client v3 を使用していますか? Weaviate v4 移行ガイド から始めて、上記のアップグレード パスに戻ります。

従来のモデル タイプが自動的に移行されるようになりました

[!重要]

1.16.1 および 1.17.0 アップグレード ガイドに記載されている手動の flask data-migrate legacy-model-types 手順は 必要なくなりました。移行 5578e028b2f2 は、flask db upgrade (#41326) の一部として同じ正規化を実行します。

すでに手動コマンドを実行している場合、それらの行の移行は何も行われません。これを実行したことがなく、デプロイメントが 1.15.0 より前のバージョンからアップグレードされている場合、このリリースでは影響を受ける行が修復されます。アップグレード後、モデル プロバイダーがそのモデルをリストしていること、および以前に失敗したモデルをロードして呼び出すことができることを確認してください。

まずデータベースをバックアップします。この移行は元に戻すことはできません。

  • ナレッジ ベースに対してテスト検索を実行します。チャンクを取り戻すと、ベクター インデックスが生き残ったことが確認されますが、オブジェクト数だけではわかりません。
