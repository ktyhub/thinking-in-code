dify 1.17.0

マイナー 公開日2026年8月25日 出典langgenius/dify 英語原文

1.17.0 を変更します

新機能

エージェント: E2B サンドボックス、ホーム スナップショット、およびスキル管理

  • E2B サンドボックス バックエンド: エージェント シェル/コードの実行が、ローカル サンドボックスに加えて E2B クラウド サンドボックスでも実行できるようになりました。 DIFY_AGENT_RUNTIME_BACKEND でバックエンドを選択します。新しい docker-compose.e2b.yaml には E2B スタックが同梱され、E2B トラフィックが認証され、リリース時に E2B テンプレートが同期されます (#39480、#39705、#39873、#39996、#40858、#40871、#40891、#40892)。
  • ビルド時のホーム スナップショット: エージェントのビルドが適用 (公開) されると、エージェントのサンドボックス ホーム ディレクトリ (インストールされたパッケージ、準備されたファイル、動作状態) がキャプチャされ、公開されたエージェントの後続の実行ではそのスナップショットからホーム ディレクトリが復元されるため、エージェントはビルド時の正確なファイル システム状態から開始されます。 (#39702、#40876、#40996)。
  • ワークスペースレベルのスキル管理: スキルは、エージェントが検出して呼び出すことができるコードとツール定義とともにパッケージ化された、再利用可能なバージョン管理された機能です。ドラフト→公開→バージョンのライフサイクルを備えた新しいワークスペース レベルのスキル マネージャーが、Web UI (スキル リスト、ビルダー パネル、ファイル エディター) とともに同梱されています。 (#39675、#39798、#39799、#41180)。
  • コンテキストを意識した履歴の圧縮: エージェントの長い会話がモデルのコンテキスト ウィンドウを超えてしまうことがなくなりました — Dify は各モデルの効果的なウィンドウを解決し、階層化された圧縮 (最初に古いツールの結果をクリアしてから、古い履歴を要約) を行うため、最近のコンテキストを失うことなく実行が予算内に留まります (#40872)。

ワークフローでの再利用可能な LLM 環境変数

  • 共有プロバイダー/モデル/モード/パラメーター構成 (例: for_summarize、for_research) を一度定義し、任意の LLM ノードから参照します。調整されたモデルの変更は、ノードごとにドリフトするのではなく 1 か所で行われるようになり、参照は DSL インポート/エクスポート、スニペット、RAG パイプライン、および共同編集後も存続します (#39125)。

ループと反復における人間の入力

  • 人間参加型フォームがループ ノードと反復ノードの「内部」で動作するようになり、デバッグ アプリとインストール済みアプリの両方でページ更新時に正しく一時停止および再開できるようになり、繰り返しの作業内でレビュー/承認ステップを実行できるようになりました (#39243)。

プロバイダーに依存しない統合トレース

  • オプトイン統合トレース (OPS_TRACE_UNIFIED_ENABLED) は、完全な親子スパン ツリー (ワークフロー、チャットフロー、メッセージ、ノード、ループ、反復、ネストされたワークフロー) をコアで一度アセンブルし、軽量アダプターへのトランスポートのみを委任します。 Phoenix アダプターと LangSmith アダプターが最初に出荷されます。デフォルトでは無効になっており、完全な下位互換性があります (#39451)。
  • 新しい GenAI は、サーフェス LLM TTFT、エージェント ReAct ステップ、ツール呼び出し、および障害が発生した LLM ノードにまたがり、より深い可観測性を実現します (#39339)。

Cloudflare 回転式改札口 (CAPTCHA) のサポート

  • 構成可能なサイト/秘密キーと許可されたホスト名を使用して、認証エンドポイントを悪用から保護するための、サインインおよび電子メール コード ログイン時のターンスタイル チャレンジ (#40494) のオプション。

Azure Key Vault / プラガブル KMS

  • キーのプロビジョニング、暗号化、復号化のための Azure Key Vault サポートを備えた KMS プロバイダーの抽象化と、キーのローテーション構成を導入します。これは、暗号化キーを外部で管理するための一歩です (#39933)。

TiDB ベクトル全文検索およびハイブリッド検索

  • TiDB Vector デプロイメントでは、ベクトル検索と並行して多言語全文インデックスを使用して、全文およびハイブリッド検索 (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH、デフォルトはオフ) を有効にできるようになりました (#38112)。

より広範なモデルとファイル処理

  • LLM ノードとエージェントは、画像ファイルをマルチモーダル モデルに直接渡すことができるようになり、非ビジョン添付ファイルがエージェント チャットからサイレントにドロップされなくなりました (#39848、#40179)。
  • 新しいマルチモーダル検索ガイダンスは、ユーザーが画像を含むナレッジ ベースの埋め込みモデルを正しく選択するのに役立ちます (#40566)。
  • オーディオ ASR が audio/x-m4a を受け入れるようになり、オーディオ MIME タイプがより正確に検証されるようになりました (#40776、#41043)。

任意の項目に移動 (⌘K / Ctrl+K)

  • コンソールの任意の場所で ⌘K (Windows/Linux では Ctrl+K) を押すとコマンド パレットが開き、アプリ、エージェント、スキル、ナレッジ ベース、プラグイン、またはワークフロー ノードにジャンプしたり、スラッシュ コマンドでクイック アクションをトリガーしたりできます。このリリースの新機能: エージェントとスキルが検索可能になり、一貫性を保つためにアイコン コマンド システムがすべてのドメインにわたってリファクタリングされました (#40620、#40621、#40646 ～ #40649、#41160)。

その他の追加事項

  • ODT (OpenDocument Text) ドキュメント抽出のサポート (#39973)。
  • ツールプラグインの新しい date / date-picker パラメータタイプ (#36163)。
  • ラオス (lo-LA) 言語のサポート (#39474)。
  • データ増加を制限するための古い会話 (ENABLE_CONVERSATION_CLEANUP_TASK) の自動クリーンアップ タスク (#40889-era)。
  • マーケットプレイスを統合カテゴリに直接埋め込んで、ツール/プラグインをよりスムーズに発見できるようにしました (#40744)。

改善点

アクセシビリティ (大型 a11y パス)

  • 非常に大規模な変更により、コンソールはキーボードとスクリーン リーダーに使いやすくなっています。多数の対話型コントロールの実際の <button> セマンティクス、アイコンのみのアクション (コピー、閉じる、削除、メニュー) のアクセス可能な名前、認証/インストール ページの主要な見出し、キーボードでアクセス可能なメンバー/ツール セレクター、および正しい ARIA 状態 (#40192 ～ #40377 など)。

ワークフローオーサリング

  • ワークフロー ジェネレーターは、ノードを提案するときに、インストール済みで設定済みのツールを優先するようになりました。そのため、ビルダーは実際に持っているツールに手を伸ばすようになりました (#40611、#39850)。

ワークフローとランタイムの安定性

  • 再現可能な Web ワークフローが実行され、履歴更新後にキャンバスの状態が保持され、更新レンダリング ループがなくなり、SSE ストリームが端末イベントで正常に終了するようになりました (#40010、#40489、#41105、#40042)。
  • stop は非ストリーミング ノード間で尊重されるようになり、一時停止されたワークフローは古いキャンセル信号を正しくクリアします (#41090、#40905、#40972)。
  • APP_MAX_EXECUTION_TIME および WORKFLOW_MAX_EXECUTION_TIME のデフォルトは、長時間実行されるワークフローに対応するために 1200 秒 → 3600 秒 に引き上げられました。

内部品質

  • 単体テストを実際の ORM モデル/SQLite セッションに大規模に移行して、カバレッジの信頼性を高め、移行されたテスト全体での型指定を強化します (多くの #38xxx ～ #39xxx)。ユーザー側の動作の変更はありません。

セキュリティの強化

  • 認証の強化: ログイン/電子メール コード フローでのターンスタイル チャレンジ、試行制限とトークンの有効期限による強化された電子メール コード検証 (EMAIL_CODE_LOGIN_MAX_ATTEMPTS、EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES)、一時停止された電子メール ドメインの処理、および有効期間の短いエージェント認証トークン (#40494、#40960、#41004、#40884)。
  • アクセス制御 / 所有権のスコープ: データセット、ドキュメント、RAG、会話、ワークスペース認証情報、および OAuth-client リソースが、その所有者とアプリのスコープに一貫してバインドされるようになり、いくつかの不正アクセス パス (#40989、#40888、#40790、#40745、#40893、#40786 および関連) が閉じられます。
  • SSRF とアウトバウンドの強化: アウトバウンド HTTP 接続フェーズは制限されており (5 秒)、エージェント/バインディングのダウンロードと実行のタイムアウトは構成可能で、SSRF ブロックされたエラー メッセージは正しい問題を示すようになりました (#40807、#41027、#40605)。

バグ修正 (選択済み)

  • Redis ストリームでの workflow_started イベントのドロップと、置き換えられた実行からの実行のドロップ/重複を防止します (#40964、#40699)。
  • ワークフローのタイムスタンプを単純 UTC に正規化し、失敗、キャンセル、中断された実行のスナップショット/履歴を保存します (#40947、#40876、#40972)。
  • クロス集計チャット会話の切り替えを防止し、エージェント チャットでの非ビジョン添付ファイルのドロップを停止します (#40709、#40179)。
  • 最初にシステム メッセージをマージすることで、Qwen/VL システム メッセージの順序を修正しました (#39136)。
  • Elasticsearch-JA アダプター document_id マッピングと VectorType (#40400) を修正。空の Bedrock スキーマ フィールドを避けてください (#40443)。
  • すべての nginx アップストリームに動的 DNS 解決を使用します (#39155)。テキストアップロード用に UTF-8 バイトサイズを保持します (#40034)。
  • 多数の Web アプリ/UI 修正: 電子メール コードとパスワード フォームの送信の復元、モバイル サインイン オーバーフロー、トースト スタッキング、モデル セレクターの間隔 (#40227、#40222、#40921、#40970、#8d612895)。

アップグレード ガイド

モデルタイプの移行

[!重要]

セルフホスト型アップグレードのための 1 回限りのレガシー モデル タイプの移行

この展開が 1.15.0 より前の Dify バージョンからアップグレードされており、この移行がまだ適用されていない場合は、アップグレード後に実行します。

この移行は flask db upgrade には含まれていません。これがないと、レガシー モデル レコードにより、モデル関連の API リクエストがエラーで失敗し、影響を受けるモデルのロードまたは使用ができなくなる可能性があります。

移行を適用する前にデータベースをバックアップします。コマンドはデフォルトでドライラン モードで実行されます。 --apply を再実行する前に、出力を確認してください。移行は冪等であるため、安全に再実行できます。

Docker 作成

docker ディレクトリから実行します。

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

ソースコードのデプロイメント

flask db upgrade の完了後、リポジトリのルートから実行します。

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

移行を適用した後、ドライラン コマンドを再度実行します。追加の行の更新または削除が報告されない場合は、関連するサービスを再起動し、既存のモデルを正常にロードして呼び出せることを確認します。

[!重要]

  • このリリースには 新しいデータベース移行 が含まれています。アップグレードの一部として実行してください。
  • 環境変数が大幅に変更されました (多数が追加され、エディション変数 名前が変更 EDITION → DEPLOYMENT_EDITION、いくつかのデフォルトが変更されました)。 「環境変数の変更」セクションを確認し、それに応じて .env を更新します。特に、EDITION を設定している場合は、名前を DEPLOYMENT_EDITION に変更してください。
  • Docker Compose 構成が変更され、新しい docker-compose.e2b.yaml が追加されました。カスタマイズされた docker-compose.yaml を維持する場合は、ローカルのカスタマイズを慎重に再適用してください。
  • 移行 add_conversation_cleanup_index は既存のデータにインデックスを構築します。conversations テーブルが大きい場合、実行に時間がかかる可能性があります。

Docker デプロイメントの構成

  1. カスタマイズした構成ファイルと環境ファイルをバックアップします。 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. 最新のコードを取得します。 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. サービスを停止します (docker ディレクトリから)。 
    docker compose down
  4. データをバックアップします。 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. 環境の変更を確認し、ローカルのカスタマイズを再適用します (EDITION → DEPLOYMENT_EDITION を思い出してください)。
  6. アップグレード: 
    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンドを停止します。
  2. 最新のコードを取得します。 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Python の依存関係を更新します。 
    cd apiuv sync
  4. 移行を実行します。 
    uv run flask db upgrade
  5. Web フロントエンドを再構築/再起動し、API サーバーとワーカーを再起動します。
