1.14.1 をディファイします

🚀 v1.14.1 の新機能は何ですか?

v1.14.1 は、セキュリティ強化、ワークフローとナレッジベースの安定性、展開のクリーンアップ、v1.14.0 後の UI プラットフォームの継続的な移行に重点を置いたパッチ リリースです。

🔐 セキュリティ

  • セルフホスト型 SECRET_KEY の強化 - Docker 展開はデフォルトの公開キーに依存しなくなりました。 SECRET_KEY が空のままの場合、API は構成されたストレージ バックエンドを介してランタイム キーを生成および永続化しますが、明示的に構成されたキーは以前と同様に機能し続けます。 #36049 の @laipz8200 に感謝します。
  • 内部メトリクス エンドポイント保護 - /threads および /db-pool-stat は、内部ランタイムとデータベース プールの詳細が認証されていない公開されることを避けるために強化されています。 #35665 の @orbisai0security に感謝します。
  • アカウントとツールの分離 - GET /account/avatar の IDOR の問題を修正し、組み込みツールのデフォルト資格情報のクリーンアップの範囲を現在のテナントに限定しました。 #35771 と #35887 の @NeatGuyCoding と @GareArc に感謝します。
  • 依存関係のセキュリティ - CVE-2026-42208 用に LiteLLM をアップグレードし、urllib3、gunicorn、gitpython、mako、Google SDK パッケージ、ストレージ ライブラリ、OpenTelemetry エクスポーター パッケージなどのいくつかのバックエンド依存関係を更新しました。 @crazywoola に感謝します。#35953、#35779、#35791、#35863、#35864、#35958、 #36011、#36012、#36013、#36017、#36050。

🧩 ワークフロー、HITL、アプリのランタイム

  • ワークフローの安定性 - バックエンド API を介したワークフロー バージョンの読み込みが復元され、大規模なアプリ リストのオンライン ユーザー ポーリングが修正され、プレビューのサイズ変更オブザーバー ループが防止され、トライアル ワークフローでのスキーマ モデルの衝突が回避されました。 #35817、#35786、#35936、および #36061 の @hjlarry と @lyzno1 に感謝します。
  • ワークフロー オーサリングの改良 - サブ変数の変数参照ピッカーの動作、ワークフロー ノード タイトルのオーバーフロー、条件演算子のポップオーバー、ワークフロー チェックリストのセマンティクス、および KB メタデータ フィルター フィールドの選択を修正しました。 #35732、#35740、#35828、#36006、および #34149 の @iamjoel、@hjlarry、@lyzno1、@shawny011717 に感謝します。
  • ワークフロー実行の正確性 - 単一実行入力変数タイプの保持、structured_output_enabled 検証の修正、ノード出力表示でのファイル プレビュー URL 処理の修正、v1.14.0 ワークフローでのブロック解除されたプラグイン モデル セレクター ツール。 #35710、#35747、#34150、および #35794 の @Jingyi-Dify、@fatelei、@shawny011717、@sawyer-shi に感謝します。

アップグレード ガイド

重要な注意事項

  • このリリースには、構成可能な Explore アプリ カテゴリの新しいデータベース移行が含まれています。アップグレードの一環としてデータベースの移行を実行します。
  • Docker Compose 環境変数は、docker/envs/** の下に分類されたファイルに分割されるようになりました。カスタマイズされた docker-compose.yaml または .env を維持する場合は、新しいレイアウトを確認し、ローカルのカスタマイズを慎重に再適用してください。
  • セルフホスト展開の場合、明示的に構成された SECRET_KEY 値が引き続き尊重されます。 SECRET_KEY が空の場合、Dify はランタイム キーを自動的に生成して保持するようになりました。

Docker デプロイメントの構成

  1. カスタマイズした docker-compose YAML および env ファイルをバックアップします。

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. リリース ブランチまたはタグから最新のコードを取得します。

    git fetch --tags
git checkout 1.14.1

  3. サービスを停止します。 dockerディレクトリ内で実行してください。

    docker compose down

  4. データをバックアップします。

    tar -cvf volumes-$(date +%s).tgz volumes

  5. 新しい docker/envs/** env ファイル レイアウトを確認し、ローカルのカスタマイズを再適用します。

  6. サービスをアップグレードします。

    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンド サーバーを停止します。

  2. リリース タグから最新のコードを取得します。

    git fetch --tags
git checkout 1.14.1

  3. Python の依存関係を更新します。

    cd api
uv sync

  4. 移行スクリプトを実行します。

    uv run flask db upgrade

  5. API サーバー、ワーカー、および Web フロントエンド サーバーを再起動します。
