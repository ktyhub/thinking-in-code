#ディファイ1.13.3

🚀 v1.13.3 の新機能は何ですか?

最新のパッチ リリース v1.13.3 は、ワークフローの実行、ストリーミング、ナレッジの取得全体の安定性と正確性に重点を置いています。最も重要なアップデートを簡単に紹介します。

🎬 新機能

  • ワークフロー構成: #33082 の @scdeng により、LLM、質問分類子、および変数抽出ノードのモデル パラメーターに対する変数参照のサポートが追加されました。

🛠️ バグ修正

  • ストリーミングの信頼性: #34030 および #34061 の @QuantumGhost によるフロントエンド/バックエンド イベント配信の安定性を維持するために、StreamsBroadcastChannel のリプレイと同時実行の問題を修正しました。
  • ワークフロー エディターの動作: ループ/反復メタデータを保持する貼り付けられたノードを修正し、#29983 および #34077 で @majiayu000 および @hjlarry によって HumanInput ノードが無効なコンテナーに貼り付けられるのを防ぎました。
  • ランタイム実行: #33666、#33619、および #33688 で、プロンプト メッセージ変換ロジックを復元し、@QuantumGhost、@faterei、および @kurokobo によるエグゼキューター駆動の HTTP リクエスト実行の max_retries=0 処理を修正しました。
  • ナレッジ検索: #33778、#33907、#33757、および #33942 で、Web 応答内の引用メタデータが保持され、データセット アイコンのメタデータが欠落している場合のクラッシュが修正され、ヒット カウント クエリ フィルタリングが修正され、@Theysua、@copilot-swe-agent、および @fatelei によるインデックス付きドキュメント チャンク プレビューが復元されました。

🔧 ボンネットの下

  • パッチの安定性: このリリースでは、v1.13.2 からアップグレードするチーム向けに、ワークフローのランタイム動作、リアルタイム ストリーミング、ナレッジ ベースの使いやすさを対象とした修正を優先しています。

アップグレード ガイド

[!重要] Dify v1.13.3 で使用されるサンドボックス イメージは、次の Python および Node.js パスを想定しています。 古い Docker Compose 展開からアップグレードし、すでに docker/volumes/sandbox/conf/config.yaml を持っている場合は、ホスト マシン上でそれを更新します。

python_path: /opt/python/bin/python3
nodejs_path: /usr/local/bin/node

サンドボックスコンテナ内のファイルを編集しないでください。ディレクトリ docker/volumes/sandbox/conf はコンテナに /conf としてマウントされるため、ホストの変更はコンテナの再起動後も保持されます。

Docker デプロイメントの構成

  1. カスタマイズした docker-compose YAML ファイルをバックアップします (オプション)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. メインブランチから最新のコードを取得します。

    git checkout main
git pull origin main

  3. サービスを停止します。 dockerディレクトリで実行してください。

    docker compose down

  4. データのバックアップ

    tar -cvf volumes-$(date +%s).tgz volumes

  5. アップグレードサービス

    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンド サーバーを停止します。

  2. リリース ブランチから最新のコードを取得します。

    git checkout 1.13.3

  3. Python の依存関係を更新します。

    cd api
uv sync

  4. 次に、移行スクリプトを実行しましょう。

    uv run flask db upgrade

  5. 最後に、API サーバー、ワーカー、および Web フロントエンド サーバーを再度実行します。
