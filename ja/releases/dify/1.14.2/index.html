#ディファイ1.14.2

🚀 v1.14.2 の新機能は何ですか?

v1.14.2 は、v1.14.1 後のセキュリティ強化、ワークフローとナレッジの信頼性、可観測性の修正、エージェントの基礎作業、展開/ランタイムの調整に重点を置いたパッチ リリースです。

🔐 セキュリティと管理

  • テナント スコープの機密エンドポイント — アプリ トレース構成エンドポイントと FilePreview テキスト抽出のテナント分離が強化されました。 #35793 と #35797 の @xr843 に感謝します。
  • ツール資格情報の安全性 - デフォルトの組み込みツール資格情報の更新をワークスペース管理者と所有者に制限し、reset-encrypt-key-pair 中に古いテナント ツール資格情報を削除しました。 #36264 と #35843 の @NeatGuyCoding と @xr843 に感謝します。

🧩 ワークフロー、HITL、アプリのランタイム

  • ワークフロー実行の信頼性 - HITL ワークフロー再開後にトレースが復元され、ワークフロー実行コールバック追跡が改善され、メッセージ更新データベースのラウンドトリップが削減され、Flask コンテキスト外でのメモリ フェッチが修正され、base64 ファイル ルックアップ セッションが正しく閉じられました。 #36064、#36149、#36213、#36253、#36308 の @Blackoutta、@CodingOnStar、@wylswz、@hjlarry、@escape0707 に感謝します。
  • ワークフローとモデル選択の改良 - モデルが選択されていない場合の読み込み動作を修正し、サポートされているパラメーターでモデル プリセットをフィルターし、API 拡張ダイアログ コントロールを改善しました。 #36342、#36339、および #36323 の @iamjoel と @lyzno1 に感謝します。

📚 データ、RAG、知識

  • ナレッジベースの安定性 - ナレッジ ヒット テストのレンダリング、空のナレッジの作成、推奨アプリのカテゴリの順序付け、推奨アプリの詳細取得における null 処理が修正されました。 #36106、#36336、#36161、および #36153 の @FFXN、@laipz8200、@hjlarry、@EvanYao826 に感謝します。
  • RAG およびドキュメント処理 - LLM ノードが取得したナレッジ ファイルにアクセスできるようにし、API 更新後に再生成されたドキュメント概要、パイプライン テンプレートのレンダリングを修正し、RAG パイプラインでの認証情報フェッチの失敗をより適切に処理できるようにしました。 #36175、#36035、#36168、#36165 の @laipz8200、@EvanYao826、@FFXN、@linw1995 に感謝します。

🎨 Web UI と製品エクスペリエンス

  • アプリの作成とオンボーディング — アプリ作成のソースとテンプレート ID、ブラウザーからの初期化されたユーザーのタイムゾーンと言語、および固定された WebApp アイコンと説明の表示を追跡します。 #36369、#36170、#36206、#36209 の @CodingOnStar、@lyzno1、@JzoNgKVO に感謝します。
  • アノテーションとデータセット UI - 0.8 未満のアノテーション応答スコアしきい値を許可し、未承認のナレッジ編集者をデータセットにリダイレクトし、タイプ ペイロードを使用しないタグの名前変更を修正しました。 #36337、#36073、#36182 の @JzoNgKVO、@iamjoel、@lyzno1 に感謝します。
  • UI プラットフォームの移行と洗練 — Checkbox および CheckboxGroup プリミティブを追加し、より多くのコントロールを @langgenius/dify-ui に移行し、ダイアログ オーバーフロー レイアウトを改善し、アカウント アバターとインストール フロー インタラクションを洗練しました。 #36271、#36295、#36255、#36302、#36111、#36199 の @lyzno1 と @CodingOnStar に感謝します。 #36210。

🔎 可観測性とトレース

  • トレースの信頼性 - タスク間の干渉を防ぐために Langfuse v3 SDK トレーサー プロバイダーを分離し、Phoenix 親トレースのフォールバック動作を追加しました。 #36136 と #36290 の @GareArc と @Blackoutta に感謝します。

⚙️ デプロイメント、依存関係、開発者のエクスペリエンス

  • デプロイメントのチューニング - プラグイン デーモンを 0.6.1 にアップグレードし、デフォルトの GraphEngine の最小ワーカー数を増やし、Docker README リファレンスを更新しました。 #36312、#35650、および #36303 の @laipz8200、@kenwoodjw、@RiskeyL に感謝します。
  • バックエンドと CI のメンテナンス - 静的分析を Pyrefly に移行し、Graphon を 0.4.0 にアップグレードし、ホットフィックスのチェリーピック来歴チェックを追加し、生成された契約ワークフローを改善しました。 #36154、#36124、#36340、#36286 の @cqjjjzr さん、@laipz8200 さん、@hyoban さんに感謝します。
  • 依存関係の更新 - authlib、ujson、langsmith、urllib3 などのバックエンドとエージェントの依存関係を更新しました。 #36112、#36121、#36142、#36160 の @dependabot[bot] に感謝します。

アップグレード ガイド

[!重要]

  • このリリースには、構成可能な Explore アプリ カテゴリの新しいデータベース移行が含まれています。アップグレードの一環としてデータベースの移行を実行します。
  • Docker Compose 環境変数は、docker/envs/** の下に分類されたファイルに分割されるようになりました。カスタマイズされた docker-compose.yaml または .env を維持する場合は、新しいレイアウトを確認し、ローカルのカスタマイズを慎重に再適用してください。
  • セルフホスト展開の場合、明示的に構成された SECRET_KEY 値が引き続き尊重されます。 SECRET_KEY が空の場合、Dify はランタイム キーを自動的に生成して保持するようになりました。

Docker デプロイメントの構成

  1. カスタマイズした docker-compose YAML および env ファイルをバックアップします。

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. リリース ブランチまたはタグから最新のコードを取得します。

    git fetch --tags
git checkout 1.14.2

  3. サービスを停止します。 dockerディレクトリ内で実行してください。

    docker compose down

  4. データをバックアップします。

    tar -cvf volumes-$(date +%s).tgz volumes

  5. 新しい docker/envs/** env ファイル レイアウトを確認し、ローカルのカスタマイズを再適用します。

  6. サービスをアップグレードします。

    docker compose up -d

ソースコードのデプロイメント

  1. API サーバー、ワーカー、および Web フロントエンド サーバーを停止します。

  2. リリース タグから最新のコードを取得します。

    git fetch --tags
git checkout 1.14.2

  3. Python の依存関係を更新します。

    cd api
uv sync

  4. 移行スクリプトを実行します。

    uv run flask db upgrade

  5. API サーバー、ワーカー、および Web フロントエンド サーバーを再起動します。
