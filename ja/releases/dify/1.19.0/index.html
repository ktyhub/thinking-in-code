dify 1.19.0

#ディファイ1.19.0

Dify 1.19.0 は、ネストされたワークフロー トレースを可観測性ツールにもたらします。 ワークフローを呼び出してワークフロー ツールに移動し、各呼び出し内のステップを検査し、実行ツリーと並行して LLM コンテキストを保持します。

このリリースでは、ワークフロー ツールをアプリ パッケージで移植できるようになり、スキル ハブの自動化が追加され、エージェント ファイルのアップロードとプレビューが簡単になりました。バンドルされたプラグイン デーモンは 0.6.14-local にアップグレードされます。

リリースハイライト · アップグレードガイド · 詳細な変更点

<a id="リリースハイライト"></a>

リリースのハイライト

ネストされたワークフローのトレース

LLM 呼び出しに至るまで、ワークフロー ツール内で何が起こっているかを確認してください。

1.18.0 で導入されたコンソール ドリルダウンを基にして、新しい外部トレースには、ワークフロー ツールと呼ばれる内部の永続的な実行ステップが含まれるようになりました。子ステップは、それを呼び出したツール スパンの下に表示され、ネストされた繰り返し呼び出し全体で階層が維持されます。 (#44673)

外側のワークフローからネストされた LLM 呼び出しまで: 実行ツリーとフォーマットされたメッセージが Langfuse にまとめられます。 #44673 からのスクリーンショット。

  • 階層に従います。 ワークフロー ツールという名前を展開すると、呼び出し元のツール スパンの下にある内部実行ステップが表示されます。
  • 各呼び出しを理解します。 繰り返しの呼び出しと失敗は、トレース内にその場所を保持します。
  • LLM コンテキストを保持します。 フォーマットされたプロンプトと応答、トークンの使用状況、プロジェクト、トレース、および観察リンクを検査します。

[!NOTE] 保存されたプロバイダー設定は引き続き機能します。 より豊富な階層が新しい実行に適用されます。履歴トレースは埋め戻されません。独立してネストされたワークフロー実行は、親識別子によってリンクされた個別のトレースのままになります。ローリング展開の場合は、以下の トレース キューの移行 に従ってください。

ワークフロー ツールをアプリに組み込む

アプリをエクスポートし、そのワークフロー ツールの背後にあるワークフローを一緒に取り込みます。 .ifpkg パッケージには、推移的な依存関係を含む、バインドされたバージョンのワークフローが含まれています。インポートでは、宛先ワークスペースにすでに存在するツールを再利用し、不足しているツールを再作成、公開、登録し、それらの参照を再マップします。 (#44592)

すべての Dify アプリのエクスポートでは、ワークフロー ツールのないアプリも含め、パッケージ形式 v2 が使用されるようになりました。既存の v1 インポートと明示的な YAML エクスポートは引き続きサポートされます。新しいパッケージを古いインストールにインポートする前に、アップグレード ガイド を参照してください。 (#45353)

一緒にアップロードします。その場でプレビューします。

複数のエージェント構成ファイルを選択またはドロップし、それらを並行してアップロードします。成功したアップロードは 1 つのアトミック バッチにバインドされ、Composer の同時保存では最新のファイルが保持され、プロンプト アップロードでは複数の参照の挿入中にカーソル位置が維持されます。 (#44947)

PDF をインラインで読み取り、構文を強調表示してソース ファイルを検査し、テキストが切り詰められているかどうかを確認します。プレビューには、設定されたファイル、スキル メンバー、作業ディレクトリ ファイルが含まれており、PDF をロードできない場合はダウンロード アクションが実行されます。 (#45032、#45045)

開発者のスポットライト

OpenAPI と difyctl を通じてワークスペース スキルを管理します。 スキルを検索して検査し、ドラフトまたは公開バージョンをエクスポートし、ローカル ファイルをインポートし、コマンド ラインから新しいバージョンを公開します。 (#44941)

<詳細>

<summary><strong>6 つのスキル コマンド</strong></summary>

|コマンド |能力 | | --- | --- | | difyctl get skill |キーワードとタグのフィルターを使用してスキルをリストします。 | | difyctl describe skill |詳細、ドラフト ハッシュ、および最新の公開バージョンを確認します。 | | difyctl get skill version |公開されているバージョンをリストします。 | | difyctl export skill |ドラフトまたは選択した公開バージョンを ZIP 形式でエクスポートします。 | | difyctl import skill --files <dir> |スキルを作成するか、ローカル ファイルから既存のスキルのドラフトを置き換えます。 | | difyctl publish skill |ドラフトを新しいバージョンとして公開します。 |

</詳細>

これらの操作には、アカウント呼び出し元、対応するワークスペース権限、および有効化されているスキルが必要です。 インポートは公開しません。 既存のスキル上でのインポートは破壊的として分類されます。操作カタログと CLI は、読み取り、書き込み、および破壊的な操作を区別するのに役立ちます。 (#44941、#45314、#44587)

<a id="アップグレードガイド"></a>

アップグレード ガイド

[!重要] 展開する前にアップグレード ガイドをお読みください。 Docker Compose には v2.35.0 以降が必要になりました。既存の環境ファイルを保存し、Dify コンポーネントをまとめてアップグレードし、ローリング展開中に新しいトレース キューを使用します。新しいアプリ パッケージは形式 v2 を使用しており、互換性のある宛先インポーターが必要です。バンドルされたプラグイン デーモンは 0.6.14-local に移動します。

互換性と展開

  1. 最初にバックアップします。 データベース、ベクター ストア データ、アップロードされたファイル、エージェント スナップショット/ワークスペース ストレージ、展開シークレット、および環境ファイルを保持します。単一スタックのアップグレードにはメンテナンス期間を使用します。
  2. コンポーネントを一緒にアップグレードします。 プラグイン デーモン 0.6.14-local とともに、一致する 1.19.0 API、ワーカー、Web、エージェント バックエンド、およびローカル サンドボックス イメージを使用します。既存のローカル サンドボックス認証トークンと構成された PASSWORD_PEPPER は変更しないでください。 1.18.0 以前からアップグレードする場合は、1.18.0 アップグレード ガイド も参照してください。
  3. Docker Compose 2.35.0 以降を使用します。 これは、Compose がサービスのデフォルトを解決するときにルート .env オーバーライドが優先される、サポートされる最小バージョンです。 docker compose version でインストールされているバージョンを確認します。 (#45359)
  4. 追跡されるデフォルトをローカル オーバーライドとは別にしてください。 バンドルされた docker/envs/**/*.defaults ファイルは自動的にロードされます。デフォルト ファイルに記載されているオーバーライド パスを使用して、一致するローカル .env ファイルを通じてサービスをカスタマイズします。ルート docker/.env は、デプロイメント入力と明示的なオーバーライドを保持します。既存の .env ファイルを保存し、その場で編集します。アップグレードする前に、古いテンプレートのコピーによって固定された誤って空の割り当てと値を確認してください。 (#45359、#45376)
  5. 既存の shared.env ファイルは引き続きサポートされます。 共通の API、ワーカー、および Beat のカスタマイズは、現在 docker/envs/core-services/api-worker.env に属しています。 Compose は依然として従来の docker/envs/core-services/shared.env を最初に読み取り、次に api-worker.env を読み取るため、両方に矛盾する値が設定されている場合は api-worker.env が優先されます。ルート docker/.env は両方よりも優先されます。 api-worker.defaults の変更されていないコピーは、既存の shared.env カスタマイズを保持します。 Docker 構成ガイド を参照してください。 (#45376)
  6. ローリング アップグレード中にトレース キューを分離します。 新しいタスクのデフォルトは OPS_TRACE_QUEUE=ops_trace_v2 です。 API、労働者、ビートは同意する必要があります。カスタム CELERY_QUEUES、CELERY_WORKER_QUEUES、または --queues リストには、新しいキューが含まれている必要があります。古いプロデューサとそのキューに入れられた作業、アクティブな作業、予約された作業、スケジュールされた作業、および再試行の作業がすべて終了するまで、古いトレース ワーカーを ops_trace 上に保持します。古いキューをパージしたり、廃止された新しいハンドラーにレガシー メッセージをエクスポートするよう要求したりしないでください。 トレース ロールアウト ガイドを参照してください。 (#44673)
  7. 新しいアプリ パッケージをインポートする前に、パッケージの宛先をアップグレードします。 新しいアプリ パッケージは常に形式 v2 を使用します。以前の厳格な v2 ルールを使用したビルドなど、古いインポーターはそれらを拒否する可能性があります。バージョン 1 のインポートは、1.19.0 で引き続きサポートされます。明示的な YAML エクスポートは引き続き利用可能ですが、バンドルされたワークフロー ツールの依存関係は含まれません。 (#44592、#45353)

Docker 作成

1.19.0 リリース タグとイメージが公開されたら、単一スタックのデプロイメントを正常に停止し、リリースに切り替え、構成を保持して確認し、新しいイメージをプルして開始します。

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.19.0
# Merge required configuration changes into existing env files here.
docker compose pull
docker compose up -d

API 起動移行を有効にしたままにするか (MIGRATION_ENABLED=true)、新しいワーカーを開始する前に、管理された移行プロセスを通じて完全な移行チェーンを適用します。ローリング デプロイメントの場合は、古いコンシューマと新しいコンシューマを混在させるのではなく、別のトレース キュー シーケンスに従います。

ルート docker/.env で共有プラグイン資格情報 PLUGIN_DAEMON_KEY および PLUGIN_DIFY_INNER_API_KEY を構成し、デーモンとその client が一致する値を受け取るようにします。ポート、ボリューム パス、プロファイル、およびヘルスチェック スケジュールも、ルート構成入力のままになります。 Docker 構成ガイド を参照してください。 (#45359)

ソースの展開

Python 3.13、Node.js 24.22.1 以降の 24.x 行、および pnpm 12.16.1 を使用します。 pnpm はワークスペース用の Node.js をプロビジョニングしなくなったため、必要な Node.js ランタイムを個別にインストールします。 (#44976、#45094)

リポジトリのルートから:

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Web アプリケーションを再構築し、同じリリースから API、ワーカー、スケジューラ、およびエージェント サービスを再起動します。スタンドアロン エージェント バックエンドを個別に展開する場合は、そのロックされた server 依存関係を更新します。

difyctl

一致する 1.19.0 client をインストールし、difyctl help を使用して現在のサーバー カタログを検出します。インストールされているエージェント スキルを difyctl install skills <dir> で更新します。ワークフローとチャットフローの自動化では、改訂された stop.run 操作を使用する必要があります。メッセージベースのアプリは stop.task を使用します。

<summary><strong>データベースの移行と既存のデータ</strong></summary>

1.18.0 からアップグレードすると、53c10126d551 で終わる 6 つの移行リビジョンが適用されます。通常の移行ランナーを通じて完全なチェーンを適用します。

計画すべき運用上の変更には次のものが含まれます。

  • ストレージ クリーンアップ インデックス (d7e9a1c3f502)。 message_files.upload_file_id、workflow_node_execution_offload.file_id、および workflow_draft_variable_files.upload_file_id に参照インデックスを追加します。 PostgreSQL はこれらを同時に作成しますが、インデックスの構築では依然としてデータがスキャンされ、I/O が消費されます。オンライン アップグレードでは、一致する正常なインデックスが再利用され、競合する定義や無効な定義が拒否されます。再試行する前に、中断された無効なビルドを調査してください。日常的なリカバリとして正常なインデックスを削除しないでください。 (#44982)
  • 構成の一意性のトレース (53c10126d551)。 アプリ/プロバイダーごとに 1 つの構成を保持し、一意のインデックスを追加します。重複が存在する場合、ID がタイムスタンプの関係を破り、最後に更新された行が優先されます。置き換えられた行は削除されます。インデックスをダウングレードしてもそれらは復元されません。データベースのバックアップを保持します。 (#44673)
  • 抽出の変更は、新しく処理されたコンテンツに影響します。 保存されたコンテンツが EPUB、EML、DOCX、CSV、Markdown、または Notion の修正によって影響を受けたドキュメントを再インポートまたは再インデックスします。繰り返し PDF プレビューの修正により、ソースのアップロードで新たに重複したアセットが作成されるのを防ぎます。すでに保存されている重複は削除されません。 (#44836、#44953、#44905、#43505、#43434、#45053、#44684)
  • トレース履歴は再構築されません。 既存のエージェント トレース台帳データは引き続き読み取り可能ですが、以前にエクスポートされたトレースは新しいネストされたスパンを取得しません。 (#44673)

</詳細>

詳細な変更点

<詳細>

<summary><strong>新機能 · トレース、パッケージ、スキル</strong></summary>

トレースとプロバイダーの統合

  • Langfuse、LangSmith、Opik、Weave、Arize、Phoenix、Aliyun、MLflow、Databricks、Tencent の共有プロバイダー インターフェイスを介して配信を統合します。再試行可能なエクスポートでは、決定的な識別子を持つ同じトレース ユニットが再送信されます。 (#44673)
  • 呼び出されたワークフロー ツールの永続実行フレームを、呼び出し元のツール スパンの下の外部エクスポートに含めます。独立してネストされたワークフロー実行は、親識別子によってリンクされた個別のトレースのままになります。 (#44673)
  • トレース資格情報を書き込み専用にしておきます。空白または省略されたシークレットでは、保存された値が保持されます。宛先ホスト、エンドポイント、または URL を変更するには、シークレットを再度入力する必要があります。 (#44673)

ポータブル アプリ パッケージ

  • 推移的な依存関係を含む、呼び出されるワークフロー ツールの背後にあるワークフローをパッケージ化します。デフォルトの最大値は 20 のバンドル ツール ワークフローです。不足している宛先ツールが再作成され、公開されます。既存のツールは再利用されます。不足しているツールを作成するには、ツール管理権限と十分なアプリ割り当てが必要です。 DSL バージョンの確認が必要なパッケージはこのフローでは拒否され、インポートが失敗する前に作成されたアプリはクリーンアップされます。 (#44592)
  • ネストされたパッケージやワークフロー ツールのないパッケージを含む、アプリ パッケージの形式 v2 を常に出力します。これによって、個別の roster-Agent パッケージの形式は変更されません。 (#45353)
  • ワークフローおよび API ツール ID は、エクスポート中に偽の langgenius/<uuid> プラグイン依存関係にならなくなりました。 (#44592)

スキルと OpenAPI

  • アカウント認証されたワークスペース操作を通じて、ドラフトまたは公開されたスキル バージョンをエクスポートし、フォルダーをインポートし、公開します。スキル ID を使用してインポートすると、そのスキルのドラフトが置き換えられます。インポートされた SKILL.md 名は一致する必要があります。オプションの draft_hash チェックでは、古い置換は拒否されますが、2 番目の解像度のタイムスタンプが使用され、同じ 1 秒以内に行われた編集は検出されません。 (#44941)
  • スキルのインポートは、オペレーティング システムのジャンクを削除し、安全でないパスや重複したパスを拒否し、ファイル/サイズ制限を適用し、同一のバイナリ アセットを再利用し、失敗したインポートによって書き込まれたアセットを削除します。スキルフロントマター内のリテラルダッシュは保持されます。 (#44941、#43602) ・各操作の効果は操作カタログで公開しており、CLIヘルプで表示します。ワークフロー/チャットフローの停止には、保存された実行の所有権と状態が使用されます。不明な実行は 404 を返し、終了した実行または停止不可能な実行は 409 を返します。メッセージ アプリを停止しても、タスク ID のセマンティクスは維持されます。 (#44587、#45314)
  • 再利用可能なスキーマ/入力/出力タイプとオプトイン契約互換タイプのサブパスを備えた、型付き API 呼び出しと OpenAPI ソースから推論されたクエリ ヘルパー用の実験版 @dify/openapi-content-mapper パッケージを追加します。これは開発の基礎です。これらの変更は、実稼働コンソールまたはマーケットプレイスの呼び出しを既存の client から移行するものではありません。 (#44627、#44915)

</詳細>

  • より使いやすいプレビュー: 強調表示されたテキスト、オンデマンド PDF レンダリング、安定した開いたプレビュー、エージェント ファイル、スキル、作業ディレクトリ全体にわたる明示的な切り捨てテキスト通知。 (#45032、#45045)
  • 方向とキーボードのサポート: 同期されたロケール方向、より広範な右から左へのレイアウト、フォームおよびフォーカス包含と統合された日付/時刻ピッカー、アクセス可能な名前で保持される表示ラベル、および一貫した読み取り専用コントロール。 (#44621、#43869、#44638、#44650、#44593、#44755、#44772、#44589、#45036、#45375)
  • より安全な編集ダイアログ: 削除、名前変更、メタデータ、注釈、メンバーロール、およびプラグイン設定ダイアログは、セッションと下書きを保持し、保留中のアクションを開いたままにし、完了後にフォーカスを復元します。リクエストが保留されている間、削除の繰り返しの送信はブロックされます。 (#44618、#44623、#44643、#44646、#44698、#44736、#44743、#44810、#44825、#44788、#44715、#44652、#44838、#44830)
  • 明確なフィードバック: フィールド エラーと永続的な通知は、アプリ、ワークフロー、ナレッジ、請求、スキル全体で共有されたアラート表示とともに、それらが関係するコントロールの近くに表示されます。 Cloud Billing では、再試行可能なエラーやアクション固有のエラーに対してローカライズされたプロンプトが使用されます。 (#45151、#45264、#45266、#45267、#45268、#45192)
  • 正確なクラウド クォータ表示: 無制限のカウントと容量ゼロの App Run およびトリガー クォータを区別し、リセット日を Unix 秒として解釈します。価格表示データがライブ使用量の制限を倍加することはなくなりました。 (#45117、#45115)
  • クエリ オーバーヘッドの低減: セグメント ページは子チャンクと添付ファイルをバッチで読み込みます。新しい参照インデックスはアプリ ストレージのクリーンアップをサポートします。 (#45050、#44982)
  • 接続の再利用: Gunicorn の構成可能なキープアライブのデフォルトは 10 秒で、サーバーの短いアイドル時間の後に接続を再利用することによって発生する障害が軽減されます。 (#44839)
  • Docker 構成: サービスとプロバイダーのオーバーライドが、関連するコンテナー、データベース コマンド、ヘルス チェック、および WebSocket 設定に到達するようになりました。ジェネレーターは欠落しているルート .env のみを作成し、オプションのオーバーライドはオペレーターの制御下に残します。 (#45359、#45376)

<summary><strong>セキュリティの強化</strong></summary>
  • ワークスペース コントロール: プロバイダー モデルを有効または無効にするには、所有者または管理者が必要です。電子メールの可用性を確認するには、アカウントへのログインが必要です。 (64fe95667b、76979a1e24)
  • リクエスト スコープの Cookie: プールされた SSRF client は、現在の送信リクエストとそのリダイレクト内にのみ応答 Cookie を保持し、後のリクエストが別のリクエストの Cookie を継承するのを防ぎます。 (#44672)
  • データセット トークンのスコープ: リソース アクセス トークンは、明示的にバインドされたアクティブなデータセットのみをリストできます。 include_all=true ではその範囲を広げることはできません。従来のワークスペース データセット API キーは、挿入された所有者の個人表示フィルターを継承せずに、テナント全体の動作を保持します。 (#44840)
  • アプリ アクセス設定: 既存のアプリに DSL をインポートすると、その Web アプリ アクセス モードが保持され、アプリの変換ではソース アクセス モードが継承されます。 (#44700、#44857)
  • シークレットと出力のトレース: 設定の読み取りでは保存された資格情報が返されなくなり、宛先の変更にはシークレットの再入力が必要となり、プロバイダー トラフィックでは共有アウトバウンド ポリシーが使用されます。 (#44673)
  • 依存関係の強化: Authlib を 1.9.1 に更新し、サポートされているメジャー バージョン内の LiteLLM 1.100.4 以降を必要とし、Agent Pydantic AI を 2.53.0 および Pillow を 13.0.0 に移動し、pypdf を 6.21.4 に更新し、Werkzeug、GitPython、およびその他の依存関係の修正を更新します。スタンドアロン エージェントはファイルロック 4.2.1 を固定します。 Docker ビルド ツールは、UV を 0.13.4 に更新します。これらのソース更新は、外部またはエンタープライズ基本イメージ内のすべての検出結果を解決するとは主張しません。 (#44606、#44793、#44868、#44871、#44886、#45041、#45104、#45215、#45259、#45214、#45260)

<summary><strong>バグ修正、ワークフロー、エージェント、ナレッジ、API、Web アプリ</strong></summary>

ワークフローと実行

  • ネイティブ サポートのないモデルの構造化出力フォールバックを復元し、文字列に変換する代わりに JSON ブール値を保持します。 (#44962)
  • Studio、公開アプリ、API の実行全体で、設定されたファイルとファイル リストのデフォルトを尊重します。明示的なクリアは省略とは区別され、会話をリセットするとデフォルトが復元され、ファイルのデフォルトを保存しても、415 エラーの原因となるブラウザ Blob オブジェクトは送信されなくなりました。 (#44780、#45042)
  • 必須の Studio 入力およびプレビューで数値ゼロを保持し、開始ステートメントでゼロと false の両方を保持します。オブジェクト ファイル参照以外のペイロードは、予期せず失敗するのではなく、元の参照にフォールバックします。 (#45005、#44833、#45088)
  • アプリの同時実行制限に対して、ストリーミング ワークフローおよびチャットフロー リクエストを 1 回だけ許可するため、1 つの制限で 1 つのアクティブなリクエストが受け入れられます。ターミナル チャットフロー イベントは、実行ウォッチドッグを停止し、保持されているコンテキストを解放するようになりました。 (#45038、#45029)
  • スケジュールされたエージェント ファイル アクセスの発信者 ID を保持し、開始ノードの sys.timestamp に UTC クロックを使用し、週次スケジュールのプレビューを日付順に並べます。 Webhook クエリ/フォーム番号は整数の精度を保持し、非有限値を拒否します。 (#44796、#44847、#44718、#44706)
  • 可用性が変化したときに利用可能なワークフロー ノードを更新し、生成されたプロンプトを適用するときに生成された変数を保持し、変数検索の強調表示をエスケープし、変数メタデータが更新されたときにプロンプ​​ト エディターのフォーカスを保持します。 (#44769、#45274、#44625、#44791)
  • 以前に空ではない保存されたドラフトをクリアする場合にのみクリアキャンバスの確認を要求し、長いワークフロー エラー メッセージをラップします。 (#45028、#45106)

エージェント、ツール、スキル

  • 更新された OAuth 資格情報を保持し、ツールとデータソース全体での同時更新をシリアル化し、ローテーション トークンと同時再認証を保護します。一時的な更新に失敗すると、ユーザーに有効な資格情報を修復するよう誤って要求するのではなく、一時的に利用できないという応答が返されます。 (#32195)
  • エージェント ストリームが完了またはキャンセルされた後、遅延する非終端イベントを拒否します。フォーマットではなくコンテンツによってプラグイン JSON 出力の重複を排除し、ReAct 出力の末尾の部分的なアクション/思考プレフィックスを保持します。 (#45080、#45297、#43353)
  • プロンプト履歴全体をすべてのエージェント LLM ゲートウェイ応答チャンクにシリアル化するのをやめます。リクエストのコンテンツ、ツール呼び出し、マルチモーダル コンテンツ、使用状況、およびクォータの決済を保存します。 (#45137)
  • 非記録トレースの親を処理し、同時の Celery トレース コンテキストを分離します。 (#44701、#44803、#45049)
  • Agent v2 で現在の Qwen フラッシュ モデルを許可し、推奨されるモデル パターンを更新します。空のオプションのエージェント変数入力を省略し、複数選択ツール パラメーターの従来のカンマ区切り値を受け入れます。 (#44873、#44748、#45058)
  • 作成者ベースのエージェント編集権限を復元します。スキルおよびスニペットの検索では、ワイルドカード文字が文字通りに扱われ、インポートされた統合バンドルはプラグイン アイコンを保持します。 (#45040、#44922、#44708、#45112)

知識と文書処理

  • インデックス作成中に削除されたドキュメントによって書き込まれたインデックス エントリを削除します。部分的な QA セグメントの更新では、省略された回答とそのカウントへの寄与が保持されます。 (#44364、#44997)
  • メタデータ キーが欠落しているドキュメントをネガティブ メタデータ フィルターに含め、明示的な top_k=0 を尊重し、読み取り時に空白のレガシー取得設定を正規化し、取得プレビューでエコノミー データセットのキーワード取得を使用します。 (#44753、#42980、#45020、#44895)
  • Notion ページのリストとファイルのインポートを復元し、失敗したページの読み込みを再試行可能に保ち、Notion データベースの HTTP エラーを表面化します。 (#45053、#44893)
  • アーカイブ メンバーをディスクに抽出せずに、EPUB の章を宣言された順序で読み取ります。すでにデコードされたEMLテキストを保持します。関係タイプによって DOCX イメージを識別します。数値 CSV 列ラベルをサポートします。 Markdown コード フェンス内の見出しはそのまま保持します。 (#44836、#44953、#44905、#43505、#43434)
  • 抽出された PDF 画像アセットを再利用して、同じソースのアップロードを繰り返しプレビューします。テナント コンテキストが見つからない場合、または元のデータセット作成者が去った場合の復元サービス API ファイル ドキュメントの作成/更新。 (#44684、#44972)
  • ユーザー自身が管理するデータセットをリストに含めます。 (#44795)

API、ファイル、および SDK

  • MCP チャットフロー生成で、トランザクション終了エラーを発生させずに会話セッションをコミットできるようにします。 API ツールのインポートでは、メソッド以外の Swagger パス キーが無視されます。提案された質問の解析では、引用された質問内の括弧が保持され、引用リソースが欠落している場合は空のリストが返されます。 (#44636、#44992、#44916、#43036)
  • リモートの Content-Type 値を正規化し、「その他のファイル タイプ」を通じて受け入れられたアップロード用に検出されたメディア タイプを保存し、リモート アップロードのプリフライト中にメディア固有の制限を適用します。 (#44677、#41292、#44273)
  • プラグイン インストーラーにエラー ページを渡す代わりに、ダウンロード HTTP エラーを報告します。 Squid によって生成された拒否応答とアップストリームの認証エラーを区別し、blob を含む GitHub インポート パスを保持し、互換性のないマルチパート ファイル形式を一貫して拒否します。 (#44333、#44841、#44280、#44903)
  • Node.js SDK は、長いナレッジ ドキュメント テキストを受け入れ、CR/LF/CRLF SSE フレーム化と先頭の BOM を処理し、空のページネーション カーソルを最初のページとして受け入れます。 (#44679、#44263、#44265)
  • PHP SDK は、空のアプリ入力を JSON オブジェクトとしてシリアル化し、ストリーミング ワークフローと text-to-audio 応答のバッファリングを回避し、パブリック メソッドの署名を維持しながら会話のページネーションのために last_id を送信します。 (#44675、#44271、#44659)

Web アプリとワークスペース

  • 新しく作成されたユーザー管理のアプリを Studio に表示したままにし、コンソール ルート全体での主要なナビゲーションを保持します。現在の日付からログ期間の境界を計算します。 (#44929、#44633、#45360)
  • ドキュメント メニューでナビゲート可能なリンクを使用し、新しいタブで発行者のリンク先を開き、ページをリロードせずに統合ツアーの手順を進めます。 (#44694、#44808、#44934、#44944)
  • テンプレートとプラグインのエントリ ポイント全体でマーケットプレイスの可用性を尊重し、推奨カードに絵文字 ID アイコンをレンダリングします。 (#45009、#45027、#45066)
  • 注釈エディタの下書きと音声入力フォーカスを保持し、簡体字中国語のアカウント削除成功メール テンプレートを追加します。 (#44810、#44825、#45169、#43504)

  • GET /console/api/apps/{app_id}/trace-config のカスタム client は、保存されたシークレット値を期待するのではなく、configured_secrets を使用する必要があります。 (#44673)

  • クラウド教育検証は明示的な status: eligible | not_eligible 結果を返します。資格のある結果のみにトークンが含まれます。対応する内部請求サービスは、この応答コントラクトをサポートする必要があります。 (#45165)
