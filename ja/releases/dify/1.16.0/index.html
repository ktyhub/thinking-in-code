#ディファイ1.16.0

Dify Agent (ベータ版) の紹介: Dify の新しいエージェント エクスペリエンス

[!警告] Dify Agent サービス ⚠️trusted の悪意のないユーザー⚠️ にのみ提供する必要があります。

ご存知の方も多いと思いますが、シェルベースの LLM エージェント パラダイムは、エージェントの機能に大きな飛躍をもたらし、エージェントに対する考え方を変えました。一方、スキルは機能をパッケージ化して配布するための標準化された方法を提供し、強力なエージェントの構築を容易にします。

本日、Dify Agent を開始します。他の主要なエージェントと同様に、Linux サンドボックスで実行されます。このリリースには以下が含まれます:

  • Dify Agentを作成するためのビルダー

    • UI を通じて Dify エージェントを構築できます。基本プロンプトを設定し、スキルとファイルをアップロードし、Dify エコシステムからツールとナレッジを接続します。
    • Dify エージェントの構築を支援するエージェントも提供します。会話を通じて、Linux サンドボックス環境を構成し、必要なパッケージをインストールし、Dify Agent が後で使用できる新しいスキルとファイルを作成できます。

  • Dify Agent のための Dify ワークフローの統合

    • Dify ワークフローで既存の Dify Agent を使用することも、インライン Dify Agent を一時的に作成することもできます。ワークフロー ノードによって定義されたタスクを実行し、必要な出力を生成して、それを次のノードに渡します。

  • 新しい Web アプリ エクスペリエンス

    • 構築した Dify Agent は、Web アプリとして公開して使用できます。使い慣れたユーザー エクスペリエンスはそのままに、Dify Agent によって強化されています。

OpenAI GPT-5.6 の互換性に関するお知らせ

OpenAI プラグインは、以前はデフォルトで Chat Completions API を使用していましたが、これは今年初めに OpenAI によって非推奨になり、新しいモデル シリーズに対するサポートがますます不十分になってきました。新しくリリースされた GPT-5.6 ファミリには、チャット コンプリーションで使用する場合、多くの異常でユニークなパラメーターの組み合わせ制限があります。これは、OpenAI が新しいモデルとのチャット コンプリーションに対して最小限の互換性サポートのみを提供しているためです。 これは Dify システムの問題ではありません。

新しい構成のデフォルトの API タイプは、チャット完了から 応答 に変更されました。ただし、以前にカスタム API キーを古いデフォルト (チャット完了) で保存したユーザーはその設定を保持するため、Dify に起因すると思われる予期しないエラーが発生する可能性があります。

以前にカスタム OpenAI API キーを構成したことがある場合は、特に GPT-5.6 以降のモデルを使用している場合は、API タイプの設定を確認し、まだチャット完了に設定されている場合は 応答 に切り替えてください。

新機能

エージェント アプリ (オープン ベータ版)

  • エージェント アプリはオープン ベータ版となり、すべてのユーザーに対してデフォルトで有効になりました。コード実行とシェル コマンド用の組み込みサンドボックス、エージェントがツールと API を呼び出すことができるスキル システム、ワークスペース全体でエージェントを管理および再利用するためのエージェント名簿、およびワークフロー エージェント ノードからの新しいエージェントの参照のサポートが導入されています。

よりスマートな AI ワークフローの生成

  • ⌘K → /create および /refine AI ワークフロー ジェネレーターがエンドツーエンドで強化されました。値の低い「理想的な出力」フィールドが削除され、静的なサンプル チップがワークスペース コンテキストに基づいた AI 生成の提案に置き換えられ、ノード構成の生成が並列化されて結果が高速化されました。構成可能なタイムアウト (WORKFLOW_GENERATION_TIMEOUT_MS、デフォルトは 180 秒) により、長時間実行される世代のハングを防ぎます。 MCP プロトコルのアップグレード
  • MCP としてのワークフロー サーバーは、古い client との下位互換性を維持しながら、バージョン ネゴシエーションと構造化ツール出力を備えた MCP プロトコル 2025-06-18 をサポートするようになりました。 MCPClient 接続は、実行時にプレースホルダー ({{request.headers.X-Custom-Auth}} など) を使用して動的な HTTP リクエスト ヘッダーを挿入できるようになり、リクエストごとの認証パススルーが有効になります。

Web アプリのカスタマイズ

  • アプリ所有者は、チャットボット、エージェント、およびチャットフロー Web アプリのチャット入力プレースホルダー テキスト (最大 64 文字) をカスタマイズできるようになりました。カスタマイズ UI は、より明確な名前 (「カスタム フロントエンド」/「ブランディング」) とより適切なラベル処理によって改良されました。アプリの説明は、入力フォームが画面外に押し出されることを避けるために、チャットおよびテキスト生成アプリの画面に折りたたみ可能なビューで表示されるようになりました。

ワークフローの信頼性と運用

  • ワークフロー実行アーカイブをエクスポートできるようになり、孤立したタスクを防ぐために Celery のウォーム シャットダウン中にアクティブな実行が適切に中止されます。 Redis 接続は、TCP キープアライブ サポートと拡張された再試行範囲により、回復力が向上しています。モデル プロバイダーは、プロバイダー側​​のコスト帰属 (Bedrock requestMetadata、OpenAI メタデータ、Vertex AI ラベルなど) のために app_id を受け取るようになりました。 OAuth および SSO ログイン フローは、失敗した SSO 完了に対する専用のエラー ビューを使用して、リダイレクト URL をより確実に保存するようになりました。

  • ナレッジ検索エラーがユーザーに表示されない問題と、組み込みテンプレートでの出力変数名の衝突を修正しました。

  • 編集アクセスを必要としないトレース構成の変更と、推奨アプリの試用版アプリのアクセス強化を修正しました

モデルとプラグイン

  • 削除時にクリアされないカスタム モデル キャッシュ、モデル プラグインのデバッグの失敗、および Xinference 資格情報コンテキストの処理を修正しました。
  • フォローアップ モデル パラメータで最大トークン パラメータが無効にならない問題を修正
  • プラグイン プロバイダーのキャッシュ スタンピード、マーケットプレイスのインストール コールバック、プラグインの権限設定を修正しました

ウェブと UI

  • Learn Dify からのアプリ作成、ノード検索フィールドの入力、ワークスペース アバターの一貫性、およびナビゲーション プロファイルの表示を修正しました

改善点

パフォーマンス

  • 高度なチャット ワークフローの実行リストと TokenBufferMemory メッセージ ファイルの読み込みにおける N+1 クエリを削除しました
  • 遅延ロードされた Vite プラグインとコンソール コントラクト シャードによるフロントエンドの起動の高速化
  • セットアップ ステータスをキャッシュし、zstd を使用して Redis 内の大きなプラグイン モデル オブジェクトを圧縮し、直接外部キーを介してパブリッシュされたワークフローを取得することにより、データベースの負荷を軽減しました。

アーキテクチャとコードの品質

  • すべてのコンソール API エンドポイントを BaseModel で生成された OpenAPI コントラクトに移行し、フロントエンド コンソール コントラクトを生成されたルートとタイプに移行しました。
  • 一貫性とテスト容易性を実現するために、バックエンド パス全体に明示的なデータベース セッションを伝播します。
  • フロントエンド全体で従来のアプリ コンテキスト プロバイダーを Jotai アトムに置き換えました
  • TypeScript 7 および Vite+ ツールチェーンにアップグレードされ、厳格な ESLint ルールが適用され、コントローラーでの新しい直接 SQLAlchemy が禁止されました。

セキュリティの強化

このリリースには、いくつかのセキュリティ強化修正が含まれており、そのうちのいくつかは 1.16.0-rc1 リリース後に対処されました。

  • SQL インジェクション: SQL インジェクションの脆弱性が解決され、メタデータ キーの検証により SQL クエリの安全性が強化されました。
  • SSRF: API ツール スキーマ フェッチにおける生の httpx.get による SSRF バイパスを修正しました。
  • オープン リダイレクト: ログイン後および認証リダイレクト フローでのオープン リダイレクトの防止
  • サンドボックスの強制: Chatflow API は workflow_id とサンドボックス プランをチェックするようになりました。サンドボックス プランでは特別なワークフローは実行されません
  • ランドロック保護: エージェントの HOME ディレクトリはランドロックで保護されています。より広範なカーネル互換性を実現するために v1 にダウングレードされました
  • CVE 依存関係のアップグレード: httplib2、setuptools、wandb; python-エンジン、python-ソケット;気まぐれ, 枕, click

アップグレード ガイド

モデルタイプの移行

[!重要]

セルフホスト型アップグレードのための 1 回限りのレガシー モデル タイプの移行

この展開が 1.15.0 より前の Dify バージョンからアップグレードされており、この移行がまだ適用されていない場合は、アップグレード後に実行します。

この移行は flask db upgrade には含まれていません。これがないと、レガシー モデル レコードにより、モデル関連の API リクエストがエラーで失敗し、影響を受けるモデルのロードまたは使用ができなくなる可能性があります。

移行を適用する前にデータベースをバックアップします。コマンドはデフォルトでドライラン モードで実行されます。 --apply を使用して再実行する前に、出力を確認してください。移行は冪等であるため、安全に再実行できます。

Docker 作成する

docker ディレクトリから実行します。

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

ソースコードのデプロイメント

flask db upgrade の完了後、リポジトリのルートから実行します。

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

移行を適用した後、ドライラン コマンドを再度実行します。追加の行の更新または削除が報告されない場合は、関連するサービスを再起動し、既存のモデルを正常にロードして呼び出せることを確認します。

[!重要]

  • このリリースには 8 つの新しいデータベース移行が含まれています。アップグレードの一環としてデータベースの移行を実行します。
