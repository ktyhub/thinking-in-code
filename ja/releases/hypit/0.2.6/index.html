hypit v0.2.6

パッチ 公開日2026年9月18日 出典hypit-ai/hypit 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ハイピットv0.2.6

キャプションのタイミング、多重化耐性、および Wan 2.7 画像

このリリースでは、正しい出力を拒否または破損する 2 つの欠陥が修正され、Wan 2.7 イメージ モデルが追加され、README のランタイム プロファイルの例がコピー＆ペースト可能になりました。

キャプションのタイミング

アライナは、各単語の終了位置と次の単語の開始位置をレポートし、tokenFrameSpan はその瞬間が該当するフレームを保持するため、隣接する Word ウィンドウが 1 フレーム分オーバーラップします。キューの境界はその重なりを継承し、単一の位置にキューを描画するレンダラは、同じフレーム上にキューを 2 つ描画しました。ほぼすべての切り替えで中国語の字幕が重なっていました。

@hypit/caption-fine の exclusiveActivationFrames では、Atoms のルールをすでに述べています。次の作成されたユニットが開始されるとすぐに、前のユニットが停止します。ユニット タイミングが構築される場所に 1 回適用されるようになり、最後のユニットで終了するキュー エンベロープから排他的なキュー境界が続きます。タイムラインには、生のトークン測定値が保持されます。 (#300、#297)

最終マルチプレクサ アサーション

ステージングされた WAV は、マルチプレクサの前にサンプルどおりにアサートされるため、最終的なアサーションは AAC 後に存続するものになります。 AAC は任意のサンプル数を伝送できません。エンコーダは 1024 サンプルのフレームを出力し、MP4 マルチプレクサーが編集リストで補正するプライミング遅延を報告するため、提示されたスパンは入力から数サンプル離れた位置に到達します。合成トーンで測定したところ、4,249,584 のサンプルでは 4,249,600 サンプル、4,236,768 のサンプルでは 4,236,800 サンプルでした。タイムラインを整数の AAC フレームにパディングしても、タイムラインは削除されません。

したがって、正確な等価性を要求すると、長さがラウンドトリップの固定点ではない正しいマルチプレクサがすべて拒否され、生成されたすべてのマテリアルがすでに支払われているため、最後のステップで 88.5 の 2 番目のレンダリングが失敗します。アサーションはエンコーダの遅延を許容するようになりました。 (#298、#296)

Wan 2.7 イメージモデル

@hypit/wan@1 には、wan-2.7-image と wan-2.7-image-pro という 2 つの正確なモデルがあります。どちらも、最大 5,000 文字、最大 9 つの参照画像、および 1K または 2K バンドのプロンプトを受け取ります。 Pro バリアントには 4K が追加されます。 count は、最大 4 つの画像をレンダリングするか、最大 12 の画像セットの上限に名前を付けます。モデルが返す数を選択します。

モデルにはアスペクト比はありません。参照が存在する場合、出力は最後の出力に続き、プロンプトのみのリクエストはバンド独自のフレームでレンダリングされます。否定プロンプトフィールドではなく、プロンプトから除外項目を読み取ります。

@hypit/provider-monid は、Monid の alibaba エンドポイントを通じて両方にサービスを提供します。その結果パスは以前は 1 つのビデオを想定していました。ルートは結果のタイプに名前を付け、コレクションは返されたすべてのファイルをダウンロードするため、画像セットはセットとして到着します。参照が解決される前に、2 つのサービス制限が報告されます。4K はプロンプトのみからレンダリングされ、リクエストはイメージ セットの外で最大 4 つの画像をレンダリングします。 (#301)

Windows 資格情報ストレージ

HypiHub OAuth は、JWT アクセス トークンとリフレッシュ トークンを保持する JSON を保存します。また、Windows Credential Locker の PasswordVault は、ブラウザー フローの完了後に、512 文字を超えるパスワードを不透明な書き込みエラーとして拒否します。 Store は PowerShell を起動する前にそのような書き込みを拒否し、メッセージ内のファイルに Store という名前を付けます。 (#294、#291)

ドキュメント

  • プロバイダーの README ランタイム プロファイルのサンプルは完全なプロファイルです。 hypit.runtime.json にコピーすると、以前は auth status で失敗しました。 (#289、#288)
  • HypiHub README ランタイム プロファイルの例は有効な hypit.runtime.json です。format、dataRoot、宣言された資格情報ストアが欠落しており、名前付きストア os が指定されていましたが、runtime init は platform と書き込まれました。 (#295、#292)

更新

グローバル CLI インストールの場合:

npm install -g @hypit/hypit@0.2.6
hypit --version

プロジェクトローカルインストールの場合:

npm install --save-exact @hypit/hypit@0.2.6
npm exec --no -- hypit --version

インストールされた Hypit スキルは、インストールに使用されたツールを通じて個別に更新されます。内部フォーマットと論理モジュール識別子は @1 のままです。スクリプト構文は 0.2.0 から変更されていません。更新しても、保存されたビデオ プロジェクトは移行または書き換えられません。
