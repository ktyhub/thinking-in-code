副操縦士-cli v1.0.109

2026-11-10

  • 設定にサンドボックス ホストの許可ルールと拒否ルールの IPv4/IPv6 CIDR サポートを追加します。
  • 新しいモデルの下のモデルピッカーに Claude Fable 5.2 のサポートを追加
  • コパイロットのヘルプ入力では、シェル入力の開始時にバックスペースを押すと、空のプロンプトだけでなくシェル モードが終了し、入力されたテキストが保持されると表示されるようになりました。
  • /subagents は、その Overridden 列と Status 列をナロー端末でも読み取れるようにし、エージェント名をワイド文字で揃えます。
  • copilot mcp remove または /mcp delete を使用した組み込み MCP サーバーの削除では、代わりにそれを無効にする方法について説明します
  • /cd ~ または /add-dir ~ でホーム ディレクトリの隣のディレクトリを選択すると、正しいフル パスが使用されます。
  • Trust フォルダーとワークツリーの確認では Windows パス区切り文字が保持される
  • 応答に空白のみが含まれている場合、空のアシスタント応答の箇条書きを非表示にします
  • 並列ファイル操作で「次回から要求しない」を選択すると、再度プロンプトを表示することなく、対象となるすべてのリクエストが承認されます。
  • XDG_CONFIG_HOME が設定されている場合、Linux 上の VS Code、Cursor、および Windsurf の正しい場所で /terminal-setup が Shift+Enter を構成するようにします。
  • フッターの AI クレジットは、次のターン後ではなく、/compact が終了するとすぐに更新されるようになりました
  • --output-format json を指定したプロンプト モードでは、実行が早期に失敗した場合でも、終了ステータスを含む最終結果レコードが出力されます。
  • レート制限エラーでは、「自動モデル」ではなく、スイッチ ダイアログと同じモード (Copilot Fusion モードまたは自動モード) の名前が付けられるようになりました。
  • 複数行のプロンプトで、以前の Up/Down 実行の列にジャンプするのではなく、テキストの先頭または末尾で何も作用しない Left、Right、Backspace、Delete、または同様のキーの後のカーソルから Up と Down が開始されるようになりました。
  • 「いいえ、Copilot に通知する」オプションの番号を押して上に戻った後も、シェルおよび URL 承認ダイアログで数字キーが機能し続ける
  • /cd . と /add-dir . は、.git を選択する代わりに、現在のディレクトリを git リポジトリに保持するようになりました。ディレクトリ ピッカーは最初に ./ をリストし、その下に隠しディレクトリが表示されます。
  • ACP モードでは、ask now に応答する preToolUse フックが、ホスト ポリシーとしてツール呼び出しを拒否するのではなく、ツール呼び出しを許可または拒否するように ACP client に要求します。
  • /voice は、一般的なエラーを表示する前に待つのではなく、長すぎるソケット パスとその修正方法をすぐに報告します。
  • ファイルの移動許可プロンプトには、ソース パスと宛先パスの両方が表示され、純粋な名前変更では空の差分が表示されなくなりました。
  • セッション履歴は、別のウィンドウがまだ開いているセッションで 2 番目のウィンドウが作業しているときに毎ターン保持されます。
  • beepOnSchedule 設定の説明では、プロンプトが起動したときのビープ音の代わりに、スケジュールされた /every または /after ターンが終了したとき、および beep がオンの間のみビープ音を制御すると記載されています。
  • companyAnnouncements 設定の説明には、ランダムに選択された 1 つのメッセージが、スタートアップ バナーではなく会社のお知らせ通知としてタイムラインに表示されると記載されています。
  • copilot help config では、compactPaste をオフにするとすべてのペーストが完全に表示されるとは表示されなくなりました。 20 KB を超えるペーストは引き続きワークスペース ファイルに保存されます
  • copilot help config は、ホーム画面のタブに、セッションとエージェントではなく、現在とセッションという表示どおりの名前を付けるようになりました。
  • キーボード ショートカット ヘルプの ctrl+h エントリは、ローカルの Windows 端末で前の単語を削除すると表示され、端末は ctrl+h と ctrl+backspace に同じキーを送信します。
  • footer.showModelEffort 設定の説明では、モデル名の横にある推論努力ラベルのみを切り替え、常に表示され、設定が未設定の場合は変化後に努力が短時間表示されると記載されています。
  • copilot help config は、taskbarPresence、showTipsOnStartup、streamerMode などの譜表のみの設定と内部設定の名前を付けなくなりました。
  • ide.openDiffOnEdit 設定の説明では、編集ごとの差分ではなく、承認を待っているファイル編集のために IDE の差分が開き、それを受け入れるか拒否するかによってプロンプトが表示されると記載されるようになりました。
  • /init の後に入力されたテキストは、生成された命令ファイルの追加のガイダンスとしてモデルに到達し、サイレントにドロップされるのではなく、タイムラインに表示されるようになりました。
  • /init の使用ヒントには、suppress のみをリストするのではなく、/init の後のテキストがその内容をガイドするため、[suppress|<instructions>] が表示されるようになりました。
  • inlineImages 設定の説明では、デフォルトで画像が Sixel グラフィックスでレンダリングされるとは記載されなくなりました。 Sixel は実験的な機能でのみ使用されます。
  • テキスト MIME タイプ (text/plain や application/json など) を持つ Base64 blob リソースとしてテキストを返す MCP ツールの結果が、空の結果としてではなくモデルに到達するようになりました。
  • copilot help providers-env と copilot help environment は、COPILOT_PROVIDER_BEARER_TOKEN が常に COPILOT_PROVIDER_API_KEY よりも優先されるとは言わなくなりました。openai と azure では優先されますが、anthropic は両方を送信します。
  • copilot help providers-env と copilot help environment は、COPILOT_PROVIDER_MODEL_ID と COPILOT_PROVIDER_WIRE_MODEL のデフォルトが COPILOT_MODEL より前の --model 値になり、ワイヤ モデルが COPILOT_PROVIDER_MODEL_ID に戻ると言うようになりました。
  • copilot help providers-env と copilot help environment は、COPILOT_PROVIDER_TRANSPORT=websockets がプロバイダー タイプ openai でのみ機能し、応答ワイヤーが API であると言うようになり、Azure と Anthropic でも機能することを暗示するようになりました。
  • copilot help providers-env は、COPILOT_PROVIDER_API_KEY_COMMAND 出力が常に送信されると表示しなくなりました。COPILOT_PROVIDER_BEARER_TOKEN が設定されている場合、コマンドは実行されず、カスタム資格情報ヘッダーの優先順位はプロバイダーの種類に依存すると表示されます。
  • copilot help providers-env および copilot help environment は、COPILOT_PROVIDERS_CONFIG がファイルに名前を付けない限り、COPILOT_PROVIDER_* 変数が保存された providers.json よりも優先されると言うようになりました。
  • copilot help providers-local は、Copilot がこのマシン上でのみ Ollama を検索し、別のマシン上の OLLAMA_HOST は無視されると表示するようになりました。
  • 同じトピックまたは同じ単語で始まるトピックに対して /research を再度実行すると、以前のレポートを上書きしようとするのではなく、新しいレポートが保存されるようになりました。
  • sandbox.auth.git 設定の説明では、GitHub トークンが挿入されると言うのではなく、サンドボックス git が、その HTTPS オリジンでのみサンドボックス プロキシが実際の認証情報と交換するマスクされた認証情報を取得し、GitHub 以外のホストが独自の git 認証情報ヘルパーを使用すると言うようになりました。
  • sandbox.userPolicy.network.proxy.url 設定の説明では、ホスト ルールのないトラフィックがプロキシを直接使用すると言うのではなく、サンドボックス トラフィックは常に組み込みのローカル プロキシを介して設定されたプロキシに到達すると記載されるようになりました。これにより、プロキシの資格情報がサンドボックス コマンドから遠ざけられます。
  • セッションが閉じられたか、セッション外で破棄されたセッション API は、CLI の組み込み SDK サーバーのメモリに残らなくなりました。
  • 折りたたまれた grep 行または glob 行では、検索で見つかったファイルまたは行のみがカウントされるようになり、大きな結果の概要行や追加の警告はカウントされなくなり、空の検索では「3 ファイルが見つかりました」と表示されました。
  • 検索サブエージェントの semantic_search ツールは、ローカル ワークスペースを検索して小さい場合はその完全な内容を返すと主張するのではなく、リポジトリの GitHub のコード インデックスから最大 5 つの抜粋を返すようにモデルに指示するようになりました。
  • /settings 値列、フッターのモデル名、および無効な allowedUrls または deniedUrls エントリに対する起動警告は、settings.json から端末に制御文字を渡さなくなりました。
  • subagents.maxConcurrency および subagents.maxDepth 設定の説明では、使用量ベースの課金ユーザーにのみ適用されるという代わりに、使用量ベースの課金のない Copilot プランでは設定が無視されると記載されるようになりました。
  • copilot update --help はデフォルトの更新チャネルを安定呼び出しなくなりました。チャネル引数も autoUpdatesChannel 設定もなしで、プレリリース ビルドはプレリリースのままになります。
  • 自分の mcp-config.json でタイプを間違えたサーバーが起動時および mcp リストで報告されるようになり、使用できない mcp-config.json がファイルと実際の問題の名前を示します。
  • Windows では、ターン、セッションの再開、または閉じられたセッションの後にランタイムが解放したメモリは、プロセスにコミットされたままではなくシステムに返されるようになりました。
  • コパイロット ワークフローの実行では、動的ワークフローには実験的な機能 (または無効になっていない拡張モード) が必要であることが説明され、内部エラーで失敗するのではなく、ステータス 2 で終了します。
  • キャンセル、拒否、または失敗したメモリ投票では、タイムラインに「メモリの更新に失敗しました」と表示されるようになりました。
  • 引用符で囲まれていないプロンプトでは、CLI オプションをプロンプト テキストに変える提案なしで、正確な引用ガイダンスが得られます。
  • 長い /skills 問題リストをナビゲートする際に、選択したスキル問題を表示したままにします
  • --prompt/--interactive オプションの入力ミスに対するパーサー エラーと、シェル依存文字を含むプロンプトに対する安全でない -i 提案の代わりにシェル中立的なガイダンスを表示します。
  • リポジトリ設定の警告は、コメントまたは末尾にカンマがあるファイルの実際の構文エラーを示します
  • 展開された JSON ツールの結果内のファイル名、グロブ、リンクを、マークダウンとして解釈するのではなく保持します。
  • エスケープ シーケンスによって端子の色や書式が変更されることなく、検索パターンとツール エラーを簡潔なトランスクリプトで表示します。
  • /settings または /config でネストされた設定を変更するときに、他のセッションによって保存された設定を保持する
  • 別の全画面表示で /help を再度開いた後に Esc キーを押すと、CLI が空白のまま応答しなくなることなくプロンプトに戻ります。
  • MCP ダッシュボードは、ローカル セッション上でランタイム専用サーバーを読み取り専用に保つようになりました。
  • 収集されたデバッグ バンドルにプロセス ログが存在しないか空である場合に警告する
  • /rubber-duck はセッションの開始時からデフォルト モデルで提供され、モデルが選択されると自動で提供され、/model で対象モデルに切り替えた後は提供されます。
  • シェル入力の開始時にバックスペースを押すとシェル モードが終了し、入力したテキストが保持されるため、編集中にシェル モードに入るプロンプトがそこに留まることはなくなりました。
  • ツールの実行中であっても、バックグラウンドの要約が終了すると圧縮インジケーターをクリアします。
  • 選択または保存したモデルが使用できない場合、別のモデルに自動的に切り替えるのではなく、エラーを表示します。
  • Linux 上のサンドボックス拒否パスは、それらのパス内の開発者ツール構成ファイルへのアクセスをブロックするようになりました。
  • .github/agents/ に追加されたカスタム エージェントをセッション中にリロードせずに使用する
  • 大量のローカル セッション履歴がある場合は、--session-id を使用してセッションをより速く開始します
  • 別の CLI セッションが同時に異なる設定を保存するときに、設定の変更を保存します
  • セッションの再開後など、並列サブエージェントが承認を要求するときに、重複したシェル コマンドが保留状態にならないようにします。
  • サンドボックスの境界を越えるなど、CLI が IDE プロセスに信号を送信できない場合でも、IDE の検出と自動接続が機能します。
  • オプションの検出キャッシュ ヒントを省略する MCP サーバーに接続し、そのツールを Copilot で利用できるようにします。
  • MCP サーバーは、--config-dir を必要とせずに、デフォルトのプロファイルに保存されているシークレットを使用できます。
  • 読み取り不能なコード変更行数を持つ以前の CLI バージョンで保存されたセッションを再開する
  • --worktree を使用する場合、チェックアウト後のフックが目的のリポジトリに対して Git コマンドを実行するようにします。
  • Ctrl+C は、進行中の /compact をキャンセルせずにダイアログを閉じるか、逆方向検索を終了します。
  • 名前に特殊文字が含まれている場合でも、--resume または /resume を使用して名前でセッションを再開します
  • リポジトリ スキャンはネストされたファイル システムをスキップし、statx が使用可能な場合に Linux でストールしたマウント終了の遅延を回避します。
  • 組み込みのファイルおよびテキスト検索は、16 KiB または 64 KiB メモリ ページを備えた ARM64 Linux システムで動作します
  • オートパイロットの確認をキャンセルすると、ピッカーが送信したスラッシュ コマンドは実行されず、確認では 1 回だけ実行されます。
  • リポジトリ設定によって無効になっている MCP サーバーは、フォルダーを trust すると停止し、セッションからツールが削除されるようになりました。
  • /mcp 画面では、リポジトリが無効になっているサーバーが考慮され、セッションが無効であるというラベルが付けられなくなりました。
  • Ctrl+O を使用して失敗した検索または診断呼び出しを展開するときにエラーの詳細を表示する
  • セッション クレジット制限ダイアログから続行すると、誤った「セッション制限に達しました」という通知が表示されなくなりました。
  • 自動で Copilot Fusion High または Max を使用する場合、/context およびフッターの不正確なコンテキスト パーセンテージを非表示にします。
  • 大文字と小文字のみを変更してファイルの名前を変更するとき、またはシンボリックリンクされたディレクトリを介してファイルを移動するときに、ファイルの内容を保持します。
  • マークダウン セッションのエクスポートにより、タスクの概要、通知、またはハンドオフの概要に HTML のようなテキストが含まれている場合、後のトランスクリプト エントリが表示されたままになります。
  • ! を停止した後、もう一度 Ctrl+C を押します。シェルコマンドは、CLI をすぐに終了するのではなく、終了警告を表示します。
  • copilot mcp list と copilot mcp get が --additional-mcp-config と --plugin-dir を優先し、セッションで使用されるサーバーと一致するようにします。
  • /tasks からバックグラウンド エージェントを停止すると、そのバックグラウンド エージェントとそのサブエージェントによって開始された接続されたバックグラウンド シェルも停止しますが、分離されたシェルは実行されたままになります。
  • COPILOT_HOME または --config-dir が相対パスの場合、プラグイン フック、MCP サーバー、および拡張機能が機能します。
  • 起動時にモデル カタログへのアクセスが拒否された場合に、ポリシー ガイダンス、設定リンク、およびリクエスト ID を表示します。
  • 現在のセッションのみでフォルダーを trust する場合、リポジトリが無効になっているスキルを /skills で無効のままにします
  • MCP サーバーの認証更新の実行中に Esc および Ctrl+C を押すと、保留中のプロンプトがすぐにキャンセルされます。
  • 端末が OS のライトテーマまたはダークテーマの変更に従う場合でも、CLI の色は同期を保ちます
  • config.json の無関係な設定に無効な値がある場合でも、MCP サーバーが起動します。
  • --context を使用して対話型セッションを再開すると、保存された層を保持するのではなく、要求されたコンテキスト ウィンドウ層が適用されるようになりました。
  • rapid ウィンドウのサイズ変更後、Windows ターミナルを正しいサイズで再描画します
  • ファイル名に ] が含まれる画像ラベルの周囲のテキストを編集するときに、画像を添付したままにする
  • /new ワークツリーの後の Decli フォルダー trust は、CLI を終了せずに元のフォルダーで開いたままにします。
  • 名前を指定せずに /rename を実行すると、生成されたセッション名を適用できない場合にエラーが表示されます
  • 言語サーバーがプロジェクトを遅延ロードする場合、最初の LSP の名前変更または参照検索にファイル間の編集と参照を含めます。

  • --Additional-mcp-config によってオーバーライドされたサーバーを編集するときに、保存された MCP サーバー設定を保持します。

  • 後の継続が失敗した場合でも、セッション履歴と再開されたセッションに長い応答を保存します。
  • 不正な形式のフロントマターがリスト値を行で囲んだり、スコープキーを引用符で囲んだりする場合に、命令スコープを回復します。
  • "additionalContext": null を返す sessionStart または preToolUse フックは、テキスト null をモデルに送信しなくなりました。 null は、userPromptSubmitted と同様に、存在しないものとして扱われます。
  • session.usage_info イベントは、文書化されているように、すべてのメッセージの最初のモデル要求ではなく、セッションの最初の使用状況レポートに対してのみ isInitial を true として報告するようになりました。

  • ターン実行中に SDK アプリが同じトークンでセッションを再開しても、HydraFusion のレビューおよび修復フェーズが即座に失敗しなくなりました。
  • セッション中の/再開では、クラウド履歴セッション ID を再開できない理由が説明されるようになりました
  • client が所有するバックグラウンド タスクの進行状況メッセージが最新の 20 件に制限されるようになりました。そのため、長時間実行される SDK タスクによって session.tasks.getProgress が際限なく増大したり、各進行状況の更新が遅くなったりすることがなくなりました。
  • セッションが存在する前にモデルをリストすると、計画変更後に 421 Misdirected Request で失敗し続けることがなくなりました。アカウントのエンドポイントが再解決され、リストが 1 回再試行されます。
  • persist: true を備えたローカル モデルは、HOME または COPILOT_HOME を使用せずに CLI を起動すると、毎回新しいサーバーを起動するのではなく、実行中のサーバーを再利用します。
  • サーバー名を受け取る /mcp コマンド (enable、disable、get、edit、remove、auth、add) は、サブコマンドの後に入力された名前全体を使用するようになりました。そのため、複数の単語からなる名前を入力ミスすると、最初の単語にちなんで名付けられたサーバーで動作するのではなく、サーバーが見つからなかったことを報告します。
  • 折りたたまれた grep および glob 行は、検索されたツリーの一部が読み取れない場合に、結果として読み取れないファイルに関する警告の行をカウントしなくなりました。
  • Linux では、言語サーバーは、出力ディレクトリを再生成するビルドまたはコード ジェネレーターなど、1 つの簡単な手順で削除および再作成されたワークスペース ディレクトリ内に作成されたファイルについて通知されるようになりました。
  • 貼り付けられたテキストは端末のカラー コードと非表示の制御文字をドロップするため、モデルはプロンプトに表示されるテキストを受け取ります。
  • パッケージ化された CLI は、 --no-warnings などの埋め込み Node.js フラグが引数として返された場合、予期しない引数エラーで失敗するのではなく、これらのフラグを無視します。
  • Linux では、大きなワークスペースに多数のファイルを書き込むビルドによって、言語サーバーがファイルを監視している間、CPU コアが数秒間ビジー状態に維持されることがなくなりました。
  • エージェントからの質問で Ctrl+G を押すと、質問をキャンセルするのではなく、入力した回答または「その他」の回答がエディターで再度開きます。
  • /sandbox では、settings.json に 2 回リストされるパスまたはホスト ルールが 1 行として表示されるようになり、削除しても削除された行が画面上に残されたり、次の削除で別のエントリが削除されたりすることはなくなりました。
  • /pr チーム名に | が含まれる場合、すべてのレビュー担当者が表示されます。最初の | で Reviews 行を切り取る代わりに、マークダウン文字を使用します。
  • /lsp テストは、動作中の stdio 言語サーバーがすぐに終了すると報告しなくなりました。実際の client と同様に、起動チェックでは監視している間サーバーの入力を開いたままにします。
  • リモートで GitHub の SSH-over-443 ホスト (ssh.github.com) を使用するリポジトリは、github.com リポジトリとして認識されるようになりました。そのため、セッションはフォルダーを GitHub の外部として扱うのではなく、そのリポジトリを認識します。
  • /keep-alivebusy は、バックグラウンド セッションの動作中にヘルパーが終了した場合、次のターンまたはセッション切り替え時にスリープ防止を復元します。
  • Git LFS を使用する GitHub または git リポジトリからプラグインをインストールすると、プラグイン独自のフォルダー内の LFS ファイルのみがダウンロードされるようになりました。そのため、サーバーが提供できないリポジトリ内の別の場所にある LFS ファイルによってインストールが失敗することがなくなりました。
  • /agent を使用してカスタム エージェントを選択すると、他の何かが同時にエージェント リストを更新したときに、「エージェント検出入力が置き換えられました」というメッセージが表示されて失敗しなくなりました。
  • web_fetch は、マークアップを削除したり、引用符で囲まれた <meta> 要素が指定するエンコーディングでデコードしたりする代わりに、<html が先頭付近に出現したときに、サーバーが送信したとおりに JSON またはプレーンテキスト応答を返します。
  • インデックス付き検索は、バージョン 1.0.108 より前に書き込まれたものも含め、存在しなくなったリポジトリとワークツリーのキャッシュに残したリポジトリごとのインデックスを削除するようになりました。インデックスは数十ギガバイトにまで増大する可能性があります。
  • web_fetch は、20000 文字の上限を超えてページの最後から読み取るか、最後のページをスキップする名前の継続を行う代わりに、負の start_index と 1 未満の max_length を検証エラーで拒否します。
  • 貼り付け直後に Ctrl+C を押すと、貼り付けたテキストがプロンプトの残りの部分とともに消去されるようになりました。貼り付けた内容はすぐに消去されたプロンプトに表示されます。
  • 言語サーバーをオンまたはオフにしても、lsp-config.json の "disabled": true で手動で無効にした他のサーバーの設定が消去されなくなりました。そのため、後で言語サーバーを再度有効にしても、すべてのユーザー言語サーバーが壊れることはなくなりました。
  • GitHub サインインのないセッションが再開されると、デバイス ポリシー ヘルパーのポリシーが再度適用されるため、リポジトリ フックなど、ロックされている設定はロックされたままになります。
  • HOME または COPILOT_HOME を使用せずに CLI を起動すると、作業ディレクトリ内の .copilot フォルダーではなく、独自の ~/.copilot/config.json に譜表設定が保存されます。
  • モデル プロバイダーが「無効なリクエスト本文」や「不正なリクエスト」などの一般的なエラーでリクエストを拒否し、添付されたイメージの 1 つが破損している場合、破損したイメージは省略され、失敗する代わりに読み取り可能なイメージで順番が再試行されるようになりました。
  • エージェントの動作中にキューに入れられたプロンプトは、モデルの切り替えまたはキューに入れられたコマンドがすぐに続いても、キュー内にその場所を保持するため、送信時に選択されたモデルで実行されます。
  • タイムラインのサブエージェント行では、エージェント タイプとモデルが 1 行のプレーン テキストとして描画されるため、行内のエスケープ シーケンスや改行によって行のスタイルが変更されたり、行の一部が非表示リンクになったり、分割されたりすることがなくなりました。
  • /cd を使用して、あるインデックス付きフォルダーから別のフォルダーにディレクトリを変更しても、前のフォルダーのインデックス サーバーが停止している間、セッションの残りの部分でインデックス付き検索が無効のままになることはなくなりました。
  • /mcp add を使用して OAuth MCP サーバーを追加すると、何かが保存される前に「サーバーが保存されました」と表示されなくなり、サインイン後に構成の保存が失敗した場合、フォームには成功とサーバーの喪失を報告するのではなく、その理由が表示されるようになりました。
  • /settings または /config でスクリーン リーダーの設定を変更すると、CLI が再起動されるか再起動を要求され、--screen-reader で開始するとスクリーン リーダー モードを記憶するように提案されるようになりました。
  • 名前または値が有効な UTF-8 ではない変数が環境に保持されている場合でも、セッションの開始に失敗することがなくなりました。このような変数は、CLI をクラッシュさせる代わりにスキップされます。
  • プロンプトで未完成の添付ラベルの後に移動または削除すると、画像とファイルのラベルが完全なままになります。
  • リポジトリのサブディレクトリから copilot instruction list を実行すると、各プラグイン ルールが 2 回ではなく 1 回リストされます。
  • 中断された --worktree チェックアウトはそのまま残り、ローカルの変更を保存し、Git が停止していることを確認するように指示する手動回復ガイダンスが表示されます。
  • 別のプロセスが共有インデックス キャッシュを一時的に保持するなど、一時的な共有インデックス エラーが発生した後でも、インデックス付き検索が残りのセッションで停止しなくなりました。
  • セッションを再開すると、選択したカスタム エージェントが /resume およびプロンプト モードで復元されるようになりました。
  • セッション サイドバーから名前のないセッションを再開しても、名前が「セッション 1」に変更されることはなくなりました。
  • セッションを切り替えるときに、プラン モードに戻すのではなく、最新のモードの選択を維持します。
  • タイムライン内の完了したサブエージェント行には、ハッシュされたモデル識別子の代わりにモデル名が表示されます。
  • /research の後、フォローアップ リクエストは通常​​のセッション ツール権限を使用します。
  • サンドボックス パス設定は、設定およびエディターで作成された式を保持しながら、環境変数をサポートします。
  • インタラクティブセッションではデフォルトでキャッシュ対応のバックグラウンド待機タイムアウトを使用します
  • ローカル ファイルを保存するときに /share または /export がシンボリックリンクをたどる前に確認を求めます
  • URL 許可プロンプトにより、現在のセッションのすべてのサブドメインを承認できます
  • 読み取り専用のシェル スクリプトが許可を求める頻度が減りましたが、git ref を変更したり、隠しパスを介してファイルを読み取ったりするスクリプトは常にレビューされるようになりました。
