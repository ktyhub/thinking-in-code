copilot-cli v1.0.108

パッチ 公開日2026年11月9日 出典github/copilot-cli 英語原文

副操縦士-cli v1.0.108

2026-11-09

  • Windows の列挙専用ディレクトリ許可の settings.json に sandbox.userPolicy.filesystem.enumeratePaths を追加
  • /index コマンドを追加し、対象となるリポジトリに対してデフォルトで管理された共有 tgrep インデックス作成を有効にします
  • Grok 4.7 および Grok 4.6 の PDF 添付ファイルは、ターンに失敗するのではなく、ファイル参照にフォールバックします。
  • サンドボックスがオンの場合、実行中のローカル MCP サーバーは /cd 後に再起動されるため、セッションが残したディレクトリのパスを保持するのではなく、新しいディレクトリの拒否されたパスに従います。
  • 名前付きパイプ、ソケット、またはデバイスを指す SDK 経由で送信された添付ファイルは、パイプに何かが書き込まれるまでターンを停止させるのではなく、エラーとしてタグ付けされるようになりました。
  • キャンバス ツールは、自由形式と呼ぶのではなく、open_canvas が受け入れるインスタンス ID をモデルに伝えるようになりました。
  • /model は、Copilot が 421 Misdirected Request でモデル リスト リクエストに応答したとき、たとえばプラン変更後、「モデル リストの読み込みエラー」を表示する代わりに、チャット ターンがすでに行っているようにアカウントのエンドポイントを再解決することでモデルをリストするようになりました。
  • OpenAI 互換のチャット補完プロバイダーへのリクエストには、スキルおよびツール メッセージの内部メッセージ フィールドが含まれなくなりました。
  • Ctrl+C は、終了ヒントを表示して CLI を 2 回押すだけで終了するのではなく、Esc Esc と同様に実行中の /compact を停止するようになりました。
  • /config ヘルプでは、リテラルのバックティックが表示されなくなり、モデル リスト外のモデルが例として使用されなくなりました。
  • セッションが以前のモードに留まるのではなく、セッションがまだモデルをロードしている間に起動セッション ピッカーを閉じたときに、defaultMode 設定が適用されるようになりました。 -disabledSkills エントリ、skills.disable および skill.enable は、大文字と小文字が異なる場合に何も実行しないのではなく、スキルの呼び出しと同様に、大文字と小文字のスキル名と一致するようになりました。
  • SDK セッションを作成または再開したり、そのツールを同じ名前の 2 つのカスタム ツールで置き換えたりすると、エラーが発生するようになりました。以前は、モデルには最初の定義が提供され、一部の SDK は最後の定義のハンドラーを実行していました。
  • Copilot ホーム ディレクトリを保持するディスクがいっぱいであるなどの理由で、初回起動タイムスタンプを保存できない場合に、Copilot が起動時に未処理の例外でクラッシュすることがなくなりました。失敗はログに記録され、起動は続行されます。
  • [はじめに] ボックスでは、/init抑制を実行したフォルダー、Copilot 命令がすでに含まれているリポジトリ、または git リポジトリの外にある /init が提案されなくなりました。
  • copilot help config は、.claude/rules 命令ファイルと、CLI が読み取る .claude/settings.json リポジトリ設定に名前を付けるようになりました。
  • コパイロットのヘルプ入力では、esc esc は実行中の /compact も停止し、シェル モードでは空のプロンプトで単一の esc または ctrl+c を押すとシェル モードを終了すると表示されるようになりました。
  • /help は、Windows 上の ctrl+d (空のプロンプトでのみ終了し、それ以外の場合は次の文字を削除する) と ctrl+z を正しく説明し、ctrl+j、ctrl+v、ctrl+y および音声入力キーをリストするようになりました。
  • コパイロットのヘルプ制限は、ローカル セッションで表示されるレート制限プロンプトを「自動モードに切り替えますか?」ではなく「Copilot Fusion モードに切り替えますか?」と引用するようになりました。
  • copilot help mcp は、2 つのファイルがマージされることを暗示するのではなく、同じディレクトリに .mcp.json がある場合、ディレクトリの .github/mcp.json が無視されると表示するようになりました。
  • コパイロットのヘルプ モニタリングでは、重複排除された姿勢の変更だけでなく、あらゆるサンドボックスの決定を種類ごとにカウントするものとして github.copilot.sandbox.operation.count メトリクスを説明するようになりました。
  • Ctrl+U、Ctrl+K、Ctrl+W、または上矢印履歴呼び出しで [image: ...] ラベルをクリアした後に画像パスを再度貼り付けると、プレーン パスを挿入する代わりに画像が再度添付されます。
  • 貼り付け直後に押した Backspace、矢印キー、Ctrl+U、または Shift+Enter は、貼り付けたテキストの前のテキストではなく、貼り付けたテキストの後に動作するようになりました。
  • 追加または編集フォームで番号によって MCP サーバー タイプを選択すると、フォーカスがそのタイプの次のフィールドに移動するようになりました。
  • Autopilot の /permissions デフォルトでは、Autopilot がすべてのツール要求を拒否するのではなく、/permissions マニュアルと同様に、次のプロンプトで権限を処理する方法を再度尋ねるようになりました。
  • 別の側の回答が開いている間に実行される、キューに入れられた /ask または /btw は、Ctrl+Y でコピーするための独自の完成した回答として前の回答を表示するのではなく、まだ考えていることを示すようになりました。
  • copilot --resume <name> および /resume <name> は、セッションが保存されたときのスペルに関係なく、名前にアクセントが事前合成または分解されたセッションを検索するようになりました。
  • /search で、上、下、Enter を押すと、スクロールして離れた後に 1 つの一致がビューに戻り、ターミナルを短くしても現在の一致が画面外に残らなくなりました。
  • /security-review ヘルプでは、ステージングされた変更とステージングされていない変更だけでなく、作業ツリーがクリーンなときにブランチの差分をレビューするようになりました。
  • チェックポイント タイトル、ファイル名、Copilot ホーム パス、および生成されたエージェント名のエスケープ シーケンスによって、/session 情報または /agent ウィザードのスタイルが変更されなくなりました。
  • /session info の長い値 (ログやセッション ファイルのパスなど) は、ラベルの下に戻るのではなく、独自の列の下に折り返されるようになりました。
  • 別のセッションに切り替えると、モデル リストのリロード中にそのセッションのモデルが自動に置き換えられることがなくなりました。
  • /share の使用は、/share のみがマークダウン ファイルをエクスポートすることを意味しなくなりました。これは、ベア パスには /、.、または ~ が含まれている必要があることを示しています。
  • プロンプト内のパスまたは URL ルート (/docs/setup.md など) は、最初のセグメント (docs) にちなんで名付けられたスキルを、そのスキルを呼び出したかのように読み込まなくなりました。
  • /pr、/lsp、/skills、/plugin、/user、および /collect-debug-logs のサブコマンドは、大文字小文字を問わず一致するようになったため、/lsp TEST my-server は使用方法のテキストを表示する代わりにテストを実行します。
  • /experimental および /theme のヘルプでは、/experimental on|off および /theme <mode> が非推奨としてマークされ、/settings を指すようになりました。また、/mcp disable は一時的なものとして説明されなくなり、セッション間で保存されます。
  • /clear <prompt> または /new を実行するリポジトリ sessionStart プロンプト フックは、作成されるセッションごとに別のセッションを開始するのではなく、1 つの新しいセッションを開始するようになりました。
  • サブエージェントに表示される期間には、権限プロンプトでのツール呼び出しに費やされた時間はカウントされなくなりました。
  • /subagents ヘルプでは、デフォルトのサブエージェント モデルが保証されなくなりました。このコマンドにより、各サブエージェントのモデルと設定が構成され、サブエージェントがオンまたはオフになることが示されています。
  • 返信、エラー メッセージ、エージェント名、その他のテキスト内のタブ文字が削除されずにスペースとして表示されるようになったため、タブで区切られた単語が一緒に実行されなくなりました。
  • ツール呼び出しに表示される期間は、権限プロンプトで費やした時間をカウントしなくなり、プロンプトが開いている間は表示されません。
  • /update チャネルの選択肢では、stable または prerelease を選択すると、将来の更新用の更新チャネルとしても保存されると表示されます。
  • ターミナルのサイズを変更するときに、ペーストの後ろにキューに入れられた入力を保持します
  • メモリ インポートは、誤ったサポートされていないホスト エラーを表示せずに、不正なリポジトリ スコープを報告します
  • 選択したカスタム エージェントの構成済みスキルが見つからない場合、またはロードできない場合に警告を表示します。
  • セッション開始、再開、およびモデル変更イベントを -p --output-format json 出力に含めます
  • /agent を開いたり、利用可能なエージェントを更新したりするときに、 --agent で選択した組み込みエージェントをアクティブのままにします
  • 対話型 CLI セッションは、ローカル MCP サーバー環境値を文字通り渡します。 ${NAME} を使用してホスト環境変数を参照します
  • チェックアウトで古い名前がまだ使用されている場合に、セマンティック コード検索で名前変更されたリポジトリを検索できるようにする
  • ルーティング プロファイルで Fusion が選択されている場合、Ctrl+T を使用してファースト パス推論を表示または非表示にします
  • /search または /find を開いたときに、会話の最後にジャンプするのではなく、選択した一致を表示したままにします。
  • /keep-alivebusy を使用する場合、バックグラウンド MCP のリロードが完了した後、システムが再びスリープできるようにします。
  • 空ではないプランが利用可能な場合、フッターのプランヒントを表示したままにする
  • インタラクティブ オートパイロットは、MCP 入力および同意リクエストを自動的に解除するのではなく、ユーザーの応答を待ちます。
  • /mcp Enable は、MCP サーバーを無効にするリポジトリ設定を考慮するようになりました。
  • パッチツールを使用したファイルの名前変更は、内容を変更することなく成功するようになりました。
  • 簡潔なトランスクリプト内のファイルの差分には、ターミナルのエスケープ シーケンスが表示文字として表示され、追加および削除された行の色が保持されます。
  • 言語サーバーがファイルの変更を監視するときに、大規模なワークツリーでのビルド中の CPU 使用率を削減します。
  • ヘッドレス実行では、別の Copilot プロセスが使用中のセッションを再開するときにエラーが報告され、その履歴はそのまま維持されます。
  • MCP 拒否ルールは、サニタイズされた名前だけでなく、MCP サーバーがアドバタイズする名前のツール (server(weather.lookup) など) を、--allow-all-tools を使用した場合でもブロックするようになりました。
  • Linux では、ディレクトリの名前が変更されてすぐに元に戻ったときに、言語サーバーにディレクトリ内のファイルが削除されたことが通知されなくなりました。
  • Linux では、パッケージのインストール中など、ワークスペース内の他のディレクトリが作成および削除されている間に、ディレクトリの名前が変更される (古いファイルが削除され、新しいファイルが作成される) と、言語サーバーに通知されるようになりました。
  • セッションが再開されたときに開いていたキャンバスは、キャンバスが再度開かれている間にその拡張機能が再起動された場合でも、使用できないままになるのではなく、復元されるようになりました。
  • preToolUse フックが複数の並列ツール呼び出しについて尋ねる場合、各呼び出しは再度独自の確認を取得します。1 つに対してフィードバックを付けて「いいえ」と答えると、質問せずに他の呼び出しを拒否することがなくなりました。
  • 空の PDF または Office ドキュメントを添付しても、ドキュメントをネイティブに読み取るモデルの起動に失敗することがなくなりました。代わりに、空のファイルがファイル参照として渡されます。
  • PID ファイルが見つからない場合でも、すでに実行中の /voice サーバーに接続します。
  • /limits unset により、後続のリクエストのセッション AI クレジットの上限がクリアされるようになりました
  • リポジトリ、URL、またはローカル パスからの /plugin install は、copilot plugin install が出力するものと同じ非推奨警告を表示するようになりました。
  • サインインに約 1 秒以上かかる場合でも、起動時に自動更新がスキップされなくなりました
  • /changelog <バージョン> は、CLI にバンドルされていないバージョンの release note を取得できます。
  • セッション イベント ログを書き込めない間に終了したターンは session.idle で終了するため、完了したターンで sendAndWait がタイムアウトすることはなくなりました。
  • grep および glob ツールは、検索パス下のファイルまたはディレクトリを読み取れない場合に、パーミッション エラーだけで失敗するのではなく、スキップされた内容を示すメモとともに、見つかった一致を返すようになりました。
  • 別のプロンプトを待たずに、ツール呼び出し中に行われた推論作業の変更を、サポートされているモデルの次のモデル リクエストに適用します。
  • 1.0.104 以降、Assisted Permissions のジャッジ コールはエージェント リクエストとして送信され、個別のプレミアム リクエストとしてカウントされなくなりました。
  • このビルド独自のドキュメントから Copilot CLI の動作に関する質問に答え、ドキュメントで質問がカバーされていない場合は明確に述べます。
  • 成功したコマンドの出力とファイルの差分は、展開されるまで簡潔なトランスクリプト モードで折りたたまれた状態を維持し、実行中の出力と失敗の詳細は表示されたままになります。
  • 入力の横に MCP フォーム検証エラーを表示し、最初の無効なフィールドに焦点を当て、スクリーン リーダーのラベルとカーソルの位置を改善します。
  • 1.0.106 以降、権限補助付きオートパイロットは権限プロンプトのために停止しなくなりました。エージェントは別のアプローチを試み、実行できなかったアクションを報告します
  • 状態「defaultEnabled」の管理されたプラグインの割り当ては、ユーザーのオーバーライドを維持しながら、デフォルトでプラグインをインストールおよびアクティブ化するようになりました。
