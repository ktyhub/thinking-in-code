概要

このパッチ リリースは、信頼性、データ取り込みの利便性、フロントエンドの洗練に重点を置いています。いくつかの移行、ロギング、来歴の問題が修正され、取り込みツールに小さいながらも便利な API および Docker が追加され、幅広いフロントエンドの更新とバグ修正が含まれています。

ハイライト

  • Docker イメージは追加の「dlt」をインストールするようになり、一般的なデータ取り込みツールがすぐに動作できるようになりました。
  • API 追加エンドポイントは raw_data 文字列と git リポジトリ URL を受け入れ、プログラムによるデータセットの追加を簡素化します。
  • 移行、ロギング、および来歴に対する複数の修正により、アップグレードおよび同時操作時の安定性が向上しました。
  • データセット、ダッシュボード、統合ワークフローを改善するフロントエンドの再編成と多数の UI 修正。
  • セキュリティと安全性の強化: API トークンは起動ログで編集され、ローカル ファイル ルート アクセスはデフォルトで無効になります。

重大な変更

  • 「repositories」パラメータの削除 — 「repositories」パラメータは、影響を受ける API/CLI 呼び出しから削除されました。そのパラメーターに依存していた場合は、統合を新しい呼び出しパターンに更新してください (更新された署名については、OpenAPI または SDK のドキュメントを確認してください)。
  • COGNEE_ALLOWED_LOCAL_FILE_ROOTS のデフォルトが変更されました — COGNEE_ALLOWED_LOCAL_FILE_ROOTS 構成がデフォルトで無効になりました。以前にこれを使用してローカル ファイル アクセスを許可した場合は、構成内で明示的に再度有効にし、許可されたパスを確認します。

新機能

  • Docker イメージの DLT エクストラ — 公式 Docker イメージでは、「dlt」エクストラ (データの読み込みに使用されるオプションのパッケージ セット) がインストールされるようになりました。つまり、追加のパッケージに依存するコネクタまたは取り込みフローは、コンテナーに追加のパッケージを手動でインストールしなくても機能します。
  • エンドポイントの追加は生データとリポジトリ URL を受け入れます — データを追加する API は、raw_data を文字列として受け入れ (テキストを直接 POST できるように)、リポジトリ クローン URL も受け入れるようになりました。これにより、ファイルを事前にアップロードせずに、Git リポジトリまたはインライン テキストからプログラムでデータを追加することが簡単になります。
  • フロントエンドの改良と新しいページ - Web UI は、ダッシュボード、データセット、統合、ビジネス/キャンバス ページ全体にわたって大規模な更新を受けました。これらの変更により、リストとパネルが再編成され、アップロード フローが改善され、オンボーディング手順が強化されて、日常のタスクがより明確かつスムーズになります。

改善点

  • 移行はプロセスごとに 1 回実行される - リレーショナル データベースの移行はプロセスごとに 1 回だけ実行されるようになり、起動時の重複作業や競合状態が軽減されます。
  • ログの初期化の改良 — ログはプロセスごとに 1 回だけ初期化され、混乱を引き起こす冗長/静かなログの切り替えが削除されました。これにより、重複するログ エントリが減り、ログが読みやすくなります。
  • DLT 取り込み区切り文字の処理 - DLT ベースの取り込みパイプラインは、さまざまな区切り文字 (カンマ、タブなど) を使用するファイルを正しく処理できるようになったため、混合ソースの CSV/TSV ファイルがより確実にインポートされます。
  • FastAPI 空データ クラッシュの修正 — 空のリクエスト データでクラッシュする可能性がある FastAPI のバグが修正され、エッジ ケースに対する API の堅牢性が向上しました。
  • デモ CLI は、追加の LLM 呼び出しなしで回答例を表示します — CLI デモ モードでは、言語モデルにアクセスすることなく、保存されているデモの回答が完全に表示されるようになり、デモが高速かつオフラインで使いやすくなりました。
  • LanceDB 述語の引用 — LanceDB 取得述語の ID は、特定の ID 形式でのクエリ エラーを回避するために適切に引用されます。
  • EMBEDDING_API_BASE をエイリアスとして読み取る — EMBEDDING_API_BASE 環境変数がエンドポイント エイリアスとして認識されるようになり、代替エンドポイント構成が簡素化されます。
  • 来歴のクリーンアップ — 来歴処理の修正により、チャンク化されたコンテンツから作成されたエッジの重複所有権が停止され、モデル内で正しいデフォルトが宣言されるため、来歴の移行が一貫して動作します。
  • 更新の承認と所有権の修正 — 増分更新はデータセット ACL (アクセス コントロール リスト) によって承認されるようになり、チャンク予算ルックアップはデータセット所有者として解決され、元のデータセット所有者は完全再構築フォールバックでも保持されます。

パフォーマンス

  • 来歴ロック競合の減少 — チェックポイントが来歴ロックの外に移動され、ロック競合が減少し、多くの操作で来歴メタデータを書き込む際の同時実行性が向上しました。
  • より堅牢な書き込み順序 — ストレージ操作中にグラフがベクトルよりも前に書き込まれるようになり、部分書き込みの可能性が減り、取り込み中の全体的なデータの一貫性が向上します。
  • データベース プロビジョニングの合理化 — データセット データベースはデータセット ID によってのみプロビジョニングされるため、プロビジョニング ロジックが簡素化され、環境セットアップ時のオーバーヘッドが削減されます。

セキュリティ

  • 起動エコーでの API トークンの編集 — エントリーポイントは、起動エコーでプレーンテキスト --api-token を出力しなくなりました。トークンは編集されるため、ログに漏洩しません。
  • ローカル ファイル ルートがデフォルトで無効化 - COGNEE_ALLOWED_LOCAL_FILE_ROOTS 設定がデフォルトで無効になり、ローカル ファイル システム パスがサーバーに誤って公開されることを減らします。
  • ローカル センチネルのテナント権限付与をスキップ — フロントエンド/サーバーは、ローカル センチネル インスタンスの実行時に自動テナント権限付与をスキップするようになり、開発実行時の予期しない権限の変更を防ぎます。

バグ修正

  • 役立つメッセージを抑制し、混乱を引き起こした「静かな」ロギング モードを削除しました。
  • 一部の呼び出しでリポジトリ パラメーターが誤って削除される問題を修正しました。新しい呼び出しパターンに一致するようにコールバック サーフェスが更新されました。
  • 空のデータ ペイロードで発生する FastAPI のクラッシュを修正しました。
  • 起動出力の --api-token 引数を編集しました。
  • 複数のファイル区切り文字を正しく処理できるように dlt 取り込みを修正しました。
  • DTO リファクタリング回帰を修正し、OpenAPI エクストラを実行中のアプリと同期して、ドキュメントと API が一致するようにしました。
  • チャンクで生成された来歴エッジが二重所有である問題を修正。
  • チャンク予算ルックアップが正しいデータセット所有者のコンテキストで解決されることを保証する問題を修正しました。
  • データセット、ダッシュボード、統合ページ (アップロードの進行状況、モーダル、リスト レンダリング、コネクタ) にわたるいくつかのフロントエンドのバグを修正しました。
  • EMBEDDING_API_BASE の読み取り動作を修正し、代替エンドポイント構成が正しく動作するようにしました。

技術的な変更

  • リファクタリングされた移行: 1 つの凍結されたスキーマ モジュールが両方のリビジョンに使用され、方言の選択はデータベース バインドから決定されます。最近のマージ後に単一のヘッドを維持するために、いくつかの移行の再親化が変更されました。
  • 多数の CI とテストの更新: テスト スイートの再編成、夜間/テストの分割、serve() の e2e ルーティング テストの追加。
  • OpenAPI の同期とドキュメントの調整: 小さな宣伝文句の修正と仕様の追加が、実行中のアプリと同期されました。
  • さまざまな内部リファクタリングとクリーンアップ: 再親化エージェントの移行、プロビジョニングの変更、および複数のテスト フィクスチャの修正。
