コグニー v1.6.6rc1

v1.6.6rc1 — 履歴コントロール、コネクタ、同期強化

発売日: 2026-10-23 変更点: v1.6.5.dev0 → v1.6.6rc1

プル リクエスト: #5765、#5850、#5893、#5898、#5938、#5955、#5958、#5961、#6011、#6013、#6014、#6185

概要

このリリースでは、ユーザーがメモリと検索履歴をより明確かつ安全に制御できるようにすること、いくつかの新しいコネクタを追加すること、同期の信頼性を強化することに重点を置いています。主なワークフローの変更には、明示的な履歴消去動作、CLI/API から検索履歴を削除する新しいフラグ、Drive/Asana の同期とインデックス作成をより堅牢にする修正が含まれます。

ハイライト

  • 新しいforget(clean_history=True)オプションにより、他の入力を必要とせずに検索履歴を削除できます。
  • ユーザーは、API およびサーバー エンドポイントを介して自分の検索履歴を削除できるようになりました。
  • 新しいコネクタ: Obsidian (保管庫)、Asana (タスク)、OneNote が追加され、それらの同期が強化されています。
  • 信頼性の向上: Drive と Asana の同期が高速になり、再開可能になりました。グラフとインデックスの操作により、不必要な作業が回避されます。

重大な変更

  • データセットの削除により、関連する検索履歴と会話履歴が削除されるようになりました。データセットを削除すると、関連する履歴がすべて削除されます。必要なアクション: バックアップまたは監査のために保存された検索またはセッション トレースに依存している場合は、データセットを削除する前にそれらをエクスポートまたはバックアップしてください。
  • run_info 構造の変更: run_info メタデータには、取り込みパイプラインが以前に保存した完全な「データ」項目が含まれなくなりました。必要なアクション: 埋め込みデータを想定して run_info を読み取るコードまたはツールは、代わりにデータ ID を介して元のアイテムをフェッチするか、新しいストレージ形状を使用するように更新する必要があります。このリリースには、古いデータ形状を削除する移行が含まれています。
  • 履歴パージ時の失敗: 履歴をパージしようとする削除/忘れ操作は、パージが完了できない場合に失敗するようになりました。必要なアクション: サービスに検索履歴を削除する権限があること、および長時間実行されるパージ操作が完了できることを確認してください。削除 API を呼び出すときの失敗を処理します。
  • 予算/割り当てエラー: 予算の枯渇と支払いが必要なエラーがより一貫して発生します (LLMPaymentRequiredError)。必要なアクション: clients は、LLM 請求パスと対話する場合、これらの例外をキャッチして処理する必要があります。

新機能

  • Forget(clean_history=True):forget コマンドおよび API 用の新しい clean_history フラグにより、他の削除動作を維持しながら、記録された検索履歴を消去できます。機能: 保存されたデータセットまたはユーザーに関連する検索履歴を削除するには、forget(clean_history=True) を呼び出します。重要な理由: 他の削除操作を実行せずにユーザー検索の痕跡を削除できるため、プライバシーとクリーンアップ操作がより明確かつ簡単になります。
  • 自分の検索履歴を削除: サーバーと API には、ユーザーが自分の検索履歴を削除できるルートが含まれるようになりました。機能: エンドユーザーは (API または UI 経由で) 個人的なクエリを削除し、メタデータを検索できます。重要な理由: 個人が検索トレースを直接制御できるようにすることで、ユーザーのプライバシーとコンプライアンスを向上させます。
  • Obsidian コネクタ (ボールト): Obsidian ボールト (ローカル ノートおよびマークダウン ボールト) を取り込む新しいコネクタ。機能: Obsidian Vault に保存されているメモを Cognee にインポートして、検索および呼び出し可能にします。重要な理由: サポートされているソースが拡大されるため、Obsidian に保存された個人的な知識を記憶と検索のワークフローに含めることができます。
  • Asana コネクタ: タスクとイベント用のファーストクラスの Asana コネクタ。機能: Asana のタスクとイベントを Cognee に同期し、検索や呼び出しが可能になります。重要な理由: Asana を使用しているチームは、メモリ主導のワークフローにタスクのコンテキストと履歴を含めることができるようになりました。
  • OneNote コネクタ: 取り込みと同期のための OneNote サポートを追加します。機能: OneNote コンテンツを Cognee に取り込み、ノートブックを検索してメモリにリンクできるようにします。重要な理由: 別の主要なメモ作成ソースを統合して、ユーザーの OneNote コンテンツがメモリと検索に参加できるようにします。
  • リコール ヒットでデータセットとデータ ID を公開: リコール結果には、データセット (ヒットの発生元) と基礎となるデータ ID が含まれるようになりました。機能: 返されるリコール ヒットには、明確にするためにデータセット名と元のアイテム ID が含まれます。重要な理由: 監査やフォローアップのために、回答をソース文書までたどることが容易になります。

改善点

  • CogneeClient.forget を通じて clean_history を転送し、履歴のみのケースに明確に名前を付けることで、client とサーバーの動作が一致し、エラー メッセージが明確になります。
  • ドキュメント: ユーザーが削除セマンティクスをよりよく理解できるように、memory_only (メモリのみの削除) が保持するものとディスクに残すものを明確にしました。
  • 検索コード: 内部の delete_user_search_history ロジックを再利用し、専用の検索履歴削除ルートを追加し、検索履歴アクションの範囲を呼び出し側ユーザーに限定して、ユーザー間での誤った削除を回避します。
  • グラフとインデックス作成: グラフのエッジを add_edges 呼び出しごとに 1 回だけ has_edges で検索して、グラフの更新および取り込み中の冗長な作業を削減します。
  • ドライブ同期: ドライブ同期が高速化および拡張され、中断に対する堅牢性が向上しました (読めない PDF に名前を付ける、再開ロジックが改善されました)。
  • Asana 同期: 再開可能になり、タイムスタンプ処理が改善され、同期のスタックを回避するために繰り返し同期トークンが発生するようになりました。
  • インデックス構築: アップグレード時のベクトル インデックスの信頼性を高めるために、バージョンが変更されるたびにスキップされた HNSW インデックス構築を再試行します。
  • エラー処理: 共有ヘルパーを通じてバジェット枯渇とクォータ/権限エラーを表面化するため、client コードと呼び出しアプリは一貫性のある実用的な例外を受け取ります。

パフォーマンス

  • グラフ更新の高速化: エッジ ルックアップの繰り返しを回避することで、一括 add_edges 操作中の CPU が削減されます (実際的な効果: 大規模なグラフ更新時の取り込みが高速化され、CPU が削減されます)。
  • ドライブ同期の高速化: ファイル同期の実行が速くなり、より広範囲のデータセットを処理できるようになります (実際的な効果: 初期同期と Google ドライブ ソースのキャッチアップが速くなります)。
  • インデックスの再試行の改善: バージョン変更後の HNSW (ベクター インデックス) ビルドの再試行の信頼性が向上し、検索をブロックするインデックスの失敗状態が減少します。

セキュリティ

  • 依存関係の更新: boto3 が aws install extra にリストされるようになったため、ユーザーが aws extras をインストールすると、AWS 統合で互換性のある SDK が取得されます。 TLS の信頼性を向上させるために、certifi バンドルが更新され (certifi 2026.10.19 が必要)、コンテナー CA バンドルが更新されました。
  • 予算/割り当ての失敗に対するエラー伝播がより厳密になり、呼び出し元はサイレント再試行ではなく明示的な支払い/割り当てエラーを受け取ります。これは、予期しない再試行動作の漏洩を回避し、修復が必要であることを明らかにするのに役立ちます。

バグ修正

  • データセットを削除するたびに履歴をパージするので、データセットを削除しても古い検索履歴や会話履歴が残らないようになります。
  • 履歴のパージが失敗した場合、「今すぐ忘れる」は失敗します (そのため、部分的な削除がサイレントに痕跡を残すことはありません)。
  • run_info (内部パイプライン実行メタデータ) 内でのデータ項目の保存を停止 — 保存される run_info では、重複を避けてストレージを削減するために、元の「データ」ペイロードが除外されるようになりました。
  • クォータ エラー時のビジー ループの再試行を防止し、クォータ エラーを即座に返すために、ネイティブ アダプタによるクォータの失敗の再試行を停止します。
  • 修正: 同期および取り込み中に正しく追跡されるように、読み取り不可能なドライブ PDF に名前を付けます。
  • 修正: Asana リストのカットを再開し、Asana リスト/同期を一時的な API エラーやページネーション カットに対してより堅牢にします。
  • 修正: スコープ トレースは呼び出し側ユーザーにまで及ぶため (可観測性)、テレメトリでユーザーが混在しなくなりました。
  • 実際の取り込みの信頼性を向上させるための、さまざまなコネクタの強化とテスト修正 (Drive、OneNote、Gmail、Notion など)。

技術的な変更

  • 大規模なリファクタリングと、新しい同期コードとテストを備えた多くの新規および更新された取り込みコネクタ (Google Drive、Gmail、Notion、Obsidian、Asana、OneNote) が追加されました。
  • コード ドキュメントの抽出、memify グローバル コンテキスト インデックス ビルダー、および内部パイプラインとサンプルで使用されるセッション蒸留部分のための多くのタスク モジュールを追加しました。
  • CI とテスト: 統合ジョブを分割し、検索履歴削除ルート用の新しい API スナップショットを追加し、テスト カバレッジとフィクスチャを更新しました。
  • 内部: 追加/更新された移行 (run_info データ フィールドを削除する移行を含む)、サーバー/client 配管への多数のリファクタリング、および可観測性/トレースの改善。
