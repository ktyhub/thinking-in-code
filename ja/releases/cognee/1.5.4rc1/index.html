コグニー v1.5.4rc1

v1.5.4rc1 — ハイブリッド検索、構造化された証拠、およびより安全な MCP パッケージング

発売日: 2026-09-15 変更点: v1.5.4 → v1.5.4rc1 プル リクエスト: #4339、#4580、#4613、#4630、#4859、#4877、#4886、#4891、#4899、#4928、#4929、#4930、#4931、#4933、#4934、#4935、#4936、#4937、 #4944、#4945、#4950、#5030、#5032、#5034、#5035、#5038

概要

このリリースでは、ハイブリッド検索と証拠の処理が改善され、コンテキスト主導のクエリ分解取得機能が追加され、パッケージ化された拡張機能が PyPI ホイールに確実に同梱され、サーバーとテレメトリの強化が強化されています。これらの変更により、検索結果がより正確かつ追跡可能になり、セットアップの手間が軽減され、マルチコンポーネント展開のセキュリティと信頼性が向上します。

ハイライト

  • 新しい HybridDecompositionRetriever: ハイブリッド検索を改善するためのコンテキスト プライミングのクエリ分解。
  • ハイブリッド補完は、構造化されたコンテキストの証拠 (機械可読な来歴) を返すようになりました。
  • ドキュメントの外部メタデータはチャンクに保存され、ハイブリッド検索中に表示されるため、結果にはソースの詳細が含まれます。
  • リリース ホイールがソース ツリーから構築されるようになったため、バンドルされた拡張機能が pip インストールに含まれます。
  • より安全な展開のための MCP (サービス) 強化、認証修正、テレメトリ編集。 MCP client が PyPI に公開されました。

新機能

  • HybridDecompositionRetriever — 内容: 周囲のコンテキストを使用して、ユーザーの質問をより小さな焦点を絞ったサブクエリに分解する新しいリトリーバー (コンテキスト プライム分解)。機能: サブクエリを検索システムに送信し、その結果を結合します。なぜ重要なのか: 複雑なクエリを分解すると、システムが文書全体からより関連性の高い証拠を見つけやすくなり、複数の部分からなる質問や曖昧な質問に対する回答の質が向上します。
  • HYBRID_COMPLETION からの構造化されたコンテキスト証拠 — 内容: ハイブリッド補完モードは、(テキストだけでなく) 構造化された機械可読形式で証拠を返すようになりました。機能: 発信者は、コンテンツと出所情報を含む豊富な証拠オブジェクトを受け取ります。なぜ重要なのか: client アプリケーションは、信頼できるソース スニペットを表示したり、回答に来歴を添付したり、返された証拠をプログラムでフィルターしてランク付けしたりできます。
  • チャンクにスタンプされたドキュメントの external_metadata — 内容: ドキュメントが検索可能なチャンクに分割されると、ドキュメントの外部メタデータ (ソース、ID、タグなどのユーザー指定フィールド) が各チャンクに保存されます。機能: メタデータが利用可能になり、ハイブリッド検索中に表示されます。なぜ重要なのか: 検索ヒットを元のドキュメントまで追跡し、ソース属性によって結果をフィルタリングし、より透明性の高い UI を構築できます。
  • LLM フリーの GLiNER グラフ抽出バ​​ックエンド — 内容: LLM を呼び出さずに関係抽出を行う新しいオプションのグラフ抽出バ​​ックエンド。機能: グラフ ノード/関係をより安価かつ決定的に抽出します。重要な理由: 構造化情報抽出のコストと遅延を削減します。これは、バッチ パイプラインや LLM 呼び出しが制限されている場合に役立ちます。
  • グラフ内のカスタム モデルの型付きエッジ — 内容: グラフ データ モデルは、カスタム抽出モデルからの型付きエッジ (関係タイプ) をサポートします。機能: 抽出出力でリレーション タイプを宣言できるため、グラフにはより豊富な型付きリレーションシップが格納されます。なぜ重要なのか: 抽出された関係の強力なクエリと視覚化が可能になり、下流の推論とグラフ クエリがより便利になります。

改善点

  • ソース ツリーからのホイール パッケージ化 — 内容: リリース ホイールがソース ツリーから構築されるようになったので、バンドルされた拡張機能 (リポジトリに同梱される追加のプラグイン) が含まれます。機能: パッケージの pip インストールには、これらの拡張機能が自動的に含まれます。重要な理由: インストール後の手動手順を減らし、エンド ユーザーによる拡張機能の欠落エラーを防ぎます。
  • MCP client とサーバーの変更 — 内容: MCP client/server に対する複数の強化と使いやすさの改善 (cognee-mcp の新しい PyPI パッケージを含む)。機能: マルチコンポーネント コントロール プレーンの展開と認証の動作を改善します。重要な理由: MCP を使用する導入では、インストールが簡単になり、運用がより堅牢になります。
  • 権限の検索範囲がテナントに限定される — 内容: ロールと権限の検索がテナントに制限されるようになりました (マルチテナントの範囲)。機能: テナント間の役割の漏洩を防ぎます。重要な理由: マルチテナント インストールのセキュリティと正確性が向上します。
  • LLM 予算とフォールバック動作の保持 — 内容: 予算の詳細 (使用量/コストのメタデータ) を保持し、予算またはポリシーによりリクエストが拒否された場合に構成されたモデルのフォールバックを保持する修正。機能: レポート作成とフォールバック モデルの選択は、より予測どおりに動作します。重要な理由: 予算を正確に把握し、制約された条件下でより信頼性の高いモデルのフォールバックが得られます。
  • 境界付きクエリの検索スコアの修正 — 内容: 境界付きクエリで近傍 ID (隣接する結果) が適切にスコア付けされます。機能: 検索が近傍に限定されている場合のスコアの精度が向上します。重要な理由: グラフ検索やローカル コンテキスト検索などの近隣ベースのクエリに対する検索の関連性が向上します。
  • セッション履歴にすべての QA ターンを記録します — 内容: セッション/QA 履歴に各ターンが確実に記録されるようになりました。機能: 会話ログと履歴には、すべての質問と回答が順番に含まれます。重要な理由: 会話セッションの監査、デバッグ、UI 表示の改善。

パフォーマンス

  • 拡張機能をインストールする際の摩擦の軽減 — ホイールに拡張機能がバンドルされているため、セットアップ時間が短縮され、拡張機能の欠落による実行時の問題が発生する可能性が低くなります。
  • 抽出コスト/遅延の削減オプション — LLM フリーの GLiNER バックエンドは、大規模なバッチ ジョブでのグラフ抽出のための、より高速で安価なパスを提供します。

セキュリティ

  • API モードでの X-Api-Key 認証サポート — 内容: API は、認証スキームとして X-Api-Key をサポートするようになりました。機能: 一部の展開プラットフォームで、より簡単な API キーの使用が可能になります。重要な理由: 標準の API ゲートウェイ設定との相互運用性が向上します。
  • プロバイダー集約のテレメトリ編集 — 内容: 識別子はテレメトリー集約から編集されます。機能: 集約されたテレメトリ内のユーザーまたはテナントの識別子の漏洩を防ぎます。なぜ重要なのか: テレメトリ データのプライバシーとコンプライアンスを向上させます。
  • MCP サーバーの強化とテスト カバレッジ — 内容: いくつかの変更により、MCP サーバーの動作とテストが強化されます。機能: 認証処理とエラーのケースを強化します。なぜ重要なのか: 攻撃対象領域を減らし、運用の信頼性を向上させます。

バグ修正

  • 初回実行時のヒントで「修正」ラベルが繰り返されるのを停止 — 内容: UI/ヘルプ テキストの重複を修正しました。なぜ重要なのか: より明確なオンボーディング メッセージ。
  • 不明なデータセットを忘れた場合に型付き 404 を発生させる — 内容: 存在しないデータセットに対して Forget を呼び出すと、内部エラーではなく型付き 404 が返されるようになりました。重要な理由: データセットの削除を自動化する際のエラーをより明確にします。
  • 再インポートによって破壊された認証の再エクスポートを復元します — 内容: 認証エクスポートに影響を与えたインポートの回帰を修正しました。重要な理由: client に対して予期される認証動作を復元します。
  • 到達可能なベース URL で API 参照プレイグラウンドをポイントする — 内容: ドキュメントが動作中の API プレイグラウンドにリンクするようになりました。それが重要な理由: API を探索する際に、ドキュメントの行き止まりが減ります。
  • サンプルと抽出デモの修正 — 内容: 抽出されたノードまたはコンテナーがドロップされるのを防ぎ、コメントを修正し、パイプラインが期待どおりに実行されるようにするいくつかのサンプルとデモの修正。なぜ重要なのか: 例に従うときの開発者のエクスペリエンスが向上します。
  • ジェミニ フォールバックを保持し、予算枯渇を正しく分類します — 内容: フォールバック モデルの選択と予算エラー タイプが正しく動作するように修正します。なぜ重要なのか: より予測可能な LLM 選択とエラー処理。

技術的な変更

  • API サーフェスの大規模な更新: 多くの新規および更新された API ルートと DTO が追加されました (検索、呼び出し、記憶、同期、更新、視覚化、セッションなど)。これらはハイブリッド検索と Web UI の機能を追加しますが、通常の client に対して下位互換性があります。
  • 多くの CI およびワークフローの更新: 拡張された GitHub アクション ワークフロー、リリース/テスト自動化、およびパッケージ化スクリプト (リリース ホイール ビルド ステップを含む)。
  • 複数の移行にわたってデータベースの移行とスキーマの進化が追加されました。アップグレードには、新しいテーブルとインデックスが含まれる場合があります (サーバーのアップグレードでは一般的)。
  • リファクタリングと内部クリーンアップ: 未使用の Graphiti 統合を削除し、ドキュメント文字列とサンプルを強化し、取得コンポーネントと MCP コンポーネントにわたるテスト カバレッジを改善しました。
