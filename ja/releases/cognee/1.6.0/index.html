コグニー v1.6.0

v1.6.0 — キーレスワークフローとパイプラインの信頼性

発売日: 2026-09-18 変更点: v1.5.4rc1 → v1.6.0 プル リクエスト: #4920、#4994、#5106

概要

このリリースでは、クラウド LLM キーなしで Cognee を実行することがより使いやすく、予測可能になり、パイプラインの起動と回復の動作が強化され、画像/音声/埋め込みモデルのエンドツーエンドの接続が完了します。また、開発者向けの統合ツールも導入され、テレメトリのプライバシーが強化され、取り込み、リコール、CLI 全体にわたる多数のバグが修正されています。

ハイライト

  • キーレス ファースト エクスペリエンス: ローカル モデルのダウンロードが発表され、多くのフローが LLM キーなしで正常に実行されるようになりました。
  • パイプラインの堅牢性: パイプラインの実行は開始時にスタンプされ、クラッシュ後に確実に回復し、完了したドキュメントが保存されます。
  • モデルの配線: 画像と音声の転写モデルはエンドツーエンドで渡され、埋め込みモデルはデータセットごとに記録され、一貫した埋め込みが保証されます。
  • テレメトリとプライバシー: データセット名はホストを離れる前にフィンガープリントされ、エラー テレメトリはより適切な診断のために完全なルートを報告するようになりました。
  • 開発者ツール: Enola 用の新しい cognee-mcp client/server および CLI の組み込みにより、統合とテストのワークフローが改善されます。

重大な変更

  • デフォルトの Docker イメージから GLiNER を削除 — デフォルトの Docker イメージには GLiNER ツールがバンドルされなくなりました。標準イメージに存在する GLiNER に依存している場合は、GLiNER をイメージに追加するか、個別にインストールする必要があります。
  • データベースとアダプターのリファクタリングにはレビューが必要な場合があります - 内部データベースとベクターストア アダプターがリファクタリングされました (Postgres/ハイブリッド アダプターへの変更を含む)。セルフホスト型の展開またはカスタム アダプターの統合では、構成とカスタム アダプター コードの互換性を確認する必要があります。

新機能

  • キーレスの初回使用のダウンロードと通知 — クラウド LLM キーなしで Cognee を実行すると、システムはローカル モデル ファイルをダウンロードする必要がある時期を通知し、何が起こっているかを説明します。これは、初めてのユーザーがローカル モデルのアクティビティを理解し、サイレント/ブロッキング ダウンロードを回避するのに役立ちます。
  • IMAGE_TRANSCRIBE_MODEL 配線 — 画像の転写 (画像をテキストに変換する) が、画像処理を担当する LLM アダプターに渡されるようになりました。これにより、画像ベースのアップロードと文字起こしがエンドツーエンドで一貫して動作するようになります。
  • レガシー アダプターを介したオーディオおよび画像 LLM サポート — オーディオおよび画像モデルの選択はレガシー アダプター層を介して接続されるようになったため、オーディオ トランスクリプションおよび画像タスクはアダプター間で一貫して構成されたモデルを使用します。
  • MCP client/server (cognee-mcp) の追加 — 新しい Python client/server パッケージが追加され、改善された外部統合とリコール/サマリー ワークフローのエンドツーエンド テストをサポートします。このツールセットは、インテグレータが Cognee のリコール/照合機能とプログラムで対話するのに役立ちます。
  • データセットごとに埋め込みモデルを記録する — ベクトルの作成に使用される埋め込みモデルが各データセットに記録されるようになりました (データセットは追加するドキュメントのコレクションです)。 Cognee は、エンベディングの再利用または更新時に同じモデルが使用されていることをチェックし、検索品質を低下させる可能性のあるサイレントな不一致を防ぎます。

改善点

  • キーレス ステージの処理の向上 — LLM キーが存在しない場合、LLM を必要とするパイプライン ステージがきれいにスキップされるようになり、キーレス実行中の部分的なエラーや混乱を招くエラーが防止されます。
  • キーレス時にキーレス トレース コンテキスト抽出をスキップする — セッション コンテキスト抽出は、キーなしで実行しているときに LLM 関連のトレース データを抽出しようとしなくなり、ログ内のノイズとエラーが軽減されます。
  • add() 中の LLM のプローブを停止 — ドキュメントを追加する際に、可用性を検出するためにクラウド LLM をプローブすることがなくなり、応答性が向上し、取り込み中の不要な LLM リクエストが防止されます。
  • 開始時のパイプライン起点スタンプ - パイプライン実行には開始時に起点がスタンプされるため、後続の診断および回復手順で実行アクティビティを正確に特定できます。
  • 解決できないデータセット名での検索/リコールの失敗 — データセット名を解決できない場合、検索とリコールは、間違った仮定に基づいて黙って続行するのではなく、明らかに失敗するようになりました。
  • エージェント プロンプトのリコール本文の範囲をデータセットに設定 — システムにコンテンツのリコールを要求するエージェント プロンプトの範囲が、要求されたデータセットに明示的に設定されるようになり、リコール結果のデータセット間の漏洩が減少します。
  • テレメトリ: データセット ID の渡しとフィンガープリントのマーク — テレメトリ イベントにはデータセット ID (内部識別子) とフィンガープリントされた名前のマークが含まれるようになり、生の名前の漏洩を削減しながら可観測性が向上します。

パフォーマンス

  • より信頼性の高いパイプラインリカバリ — スタートアップリカバリでは、放棄された実行によって完了したドキュメントが保存されるようになり、重複した作業が削減され、クラッシュ後のリカバリ速度が向上しました。
  • 不必要な LLM プローブの削減 — add() およびキーレス実行中の LLM プローブを回避することで、取り込みとローカル フローが高速になり、外部 LLM レイテンシへの依存が少なくなります。

セキュリティ

  • テレメトリのフィンガープリント データセット名 — 人間が判読できるデータセット名は、テレメトリがホストから送信される前にハッシュ化 (フィンガープリント) されます。これにより、イベントを関連付ける機能を維持しながら、テレメトリが収集されるときのプライバシー リスクが軽減されます。
  • エラー テレメトリに完全なルート コンテキストが含まれる - エラーが報告されると、完全な API ルートがテレメトリに含まれるようになり、機密名をフィンガープリントで保護しながらデバッグが高速化されます。

バグ修正

  • データセットのパーミッション拒否コントラクトの調整 — API パーミッション拒否の動作が修正され、client で一貫性のある明示的なパーミッション エラーが発生するようになりました。
  • セッション ブリッジとセッション層のリファクタリングを修正し、LLM キーなしでセッションが実行されるようにします。複数の修正により、セッション関連機能の動作にクラウド LLM キーが必要なくなりました。
  • データセットごとに埋め込みモデルを 1 回記録してチェックする — 一貫性のない埋め込みモデル チェックの繰り返しを回避し、埋め込み/リコールの不一致を防ぎます。
  • ファイルのアップロードに GLiNER が使用されている場合、LLM キー エラーを表示しない — 代替アップロード ツールを使用するアップロード フローは、LLM キー欠落エラーを誤って報告しなくなりました。
  • 更新時にルート スタンプがコンテンツに従うようにする — コンテンツが更新されると、ルート起点スタンプが更新されたコンテンツに従うため、テレメトリと監査証跡は正確なままになります。
  • セッション エントリが CLI で先頭にある場合にグラフ結果を保持する — セッション エントリが先頭項目である場合、CLI リコールはグラフ結果を保持するようになりました。
  • アダプターを介して画像と音声のモデルを接続する - 以前のギャップを修正し、画像と音声のタスクで設定されたモデルを一貫して使用できるようにしました。
  • さまざまなテストの不安定性と CI の問題を修正 — リリースを安定させるために、多くのテストと CI ワークフローが固定または修正されました (Enola CLI、ネストされたリリース テスト、プラットフォーム ルックアップ)。
  • リコール ルーティングと検索タイプのスパン コールを修正 - 取得/ルーティング ロジックとスパン検索タイプのコールが正規化され、いくつかのエッジケースのバグが解決されました。
  • 解決できないデータセット名での検索/リコールの失敗 - データセット名が無効な場合に、より明確なエラーを保証し、予期しない結果を回避します。

技術的な変更

  • セッションとプロンプト処理の大規模なリファクタリング — セッション層が統合され、ユーザー プロンプト表現に移動されました。ユーザー/システム プロンプトが分割され、いくつかのセッション永続モジュールが再編成されました。
  • 主要な「改善」サブシステムの追加 - 段階的な改善、結果の折りたたみ、ゲート、およびグラフ変更の記録のための新しいモジュールが追加され、より充実した自動改善ワークフローをサポートします。
  • 取得と検索の再作業 — 取得コード パスが再編成され (完了リトリーバー、グラフ完了リトリーバー、ハイブリッド リトリーバー)、より明確な RecallScope がセッション認識リコール用に追加されました。
  • 新しいバックグラウンド タスクとパイプライン操作 - パイプラインの実行ライフサイクル (開始、ロギング、エラー処理、スタンピング) とバックグラウンド タスクがリファクタリングされ、実行の回復と診断がより堅牢になりました。
  • MCP およびリコール サマリーの新しいテストとサンプル — 新しい mcp ツールとリコール/サマリー動作をカバーするために、追加のテストとサンプル フィクスチャが追加されました。
