cognee v1.6.8

コグニー v1.6.8

v1.6.8 統合とコネクタ

発売日: 2026-11-12 変更点: v1.6.7 → v1.6.8

プル リクエスト: #5189、#6410、#6417、#6593、#6612、#6634、#6642

概要

このリリースは、統合の拡張と強化 (新しい Slack サポートと多くのコネクタの改善)、および埋め込みとデータ更新のための信頼できるバックグラウンド作業の構築に重点を置いています。新しい Slack コネクタとアプリ、Google/Drive/Gmail/Calendar コネクタの動作の改善、RabbitMQ ベースの埋め込みワーカー オプション、および多くの信頼性と来歴 (監査) の修正により、インポート、更新、削除がより予測どおりに動作するようになります。

ハイライト

  • フル機能の Slack コネクタと @cognee Slack アプリを追加したため、Slack メッセージを Slack から直接質問したり記憶したりできるようになりました。
  • RabbitMQ 上に埋め込みワーカー エンジンを導入したため、バックグラウンドでの埋め込み生成がより堅牢でスケーラブルになりました。
  • 従来のファイル形式の処理や再試行ロジックを含む、Google ファミリ コネクタ (ドライブ、Gmail、カレンダー) の改善により、スキップされるファイルの数が減りました。
  • 更新と来歴に関する多くの信頼性に関する修正: より安全なファイル ロック、同時安全な削除、履歴の紛失や順序の乱れを避けるためのより正確な監査 (台帳) 書き込み。

新機能

  • Slack コネクタと @cognee アプリ: Slack ワークスペースを Cognee に接続する新しい統合により、ユーザーは Slack メッセージから直接情報を質問 (検索) し、記憶 (保存) できるようになります。それが重要な理由: Slack を離れることなく Cognee メモリを操作でき、チームがすでにコミュニケーションしている場所で質問したり、スニペットを保存したり、回答を得ることができます。
  • RabbitMQ 上でのワーカー エンジンの埋め込み: RabbitMQ (メッセージ ブローカー) 上で実行され、バックグラウンドでベクトル埋め込み (セマンティック検索に使用される数値表現) を生成する新しい埋め込みワーカー バックエンドが追加されました。機能: 埋め込み生成をメイン サービスから切り離すことで、独立して拡張し、ワーカーの障害から回復できるようにします。重要な理由: 大規模な取り込みワークロードやバースト的な取り込みワークロードによってメイン サービスがブロックされることがなく、埋め込み作業をより確実に再試行して分散できるためです。
  • Google ドライブ コネクタ: 従来の Office 形式 (古い .xls および .ppt ファイル) の取り込みが改善され、以前の同期で失われたファイルが修正されます。機能: より多くの種類のドライブ ファイルを読み取り、インポートし、以前に失敗したファイルを再検討します。重要な理由: ドキュメントの欠落が減り、Google ドライブからのコンテンツのインデックス作成がより完全になります。
  • Gmail とカレンダーのコネクタの改善: ソース コードと再試行ロジックを更新して、Gmail と Google カレンダーの取り込みをより堅牢にしました。内容: Google API の呼び出し方法と一時的な障害の処理方法を改善します。重要な理由: 手動で再実行することなく、電子メールとカレンダーからより信頼性の高いインポートが可能になります。
  • POST /add が dlt_config を受け入れる: add API は、取り込み中に増分同期オプションを渡すために、POST /add で dlt_config パラメーターを受け入れるようになりました。機能: 呼び出し元がデータを追加するときに増分ローダーを構成できるようにします。重要な理由: 取り込み中にファイルが検出および処理される方法をより詳細に制御できるようになります。
  • コンストラクター引数としてのエージェント ツール出力制限: エージェント取得機能は、ツール出力文字制限をコンストラクター引数として受け入れるようになりました。機能: エージェント ツールが返すことができるテキストの量を設定できるようにします。重要な理由: エージェントを調整して、過度に長い出力を回避したり、必要に応じてより長い応答を許可したりできます。

改善点

  • より堅牢な更新/削除フロー: 更新タスクは、リリースされた (削除された) ファイルを同時にバッチで削除するようになり、クリーンアップを高速化し、ロック競合を軽減します。重要な理由: 更新がより速く完了し、ストレージのクリーンアップによって古いファイルが残される可能性が低くなります。
  • 場所ごとの保存ファイルのロック: ある保存場所での操作が他の保存場所をブロックしないように、更新中に保存ファイルが場所ごとにロックされる方法を修正および強化しました。重要な理由: 複数の更新タスクが異なるストレージ バックエンドにアクセスするときの偶発的な競合を軽減します。
  • 来歴/台帳の精度: 複数の修正により、来歴台帳 (追加/更新/削除の監査証跡) が安全な順序でイベントを書き込み、データ行のみを記録し、ロールバックされたエントリを保持し、削除マーク (廃棄マーク) を最後に書き込むことが保証されます。重要な理由: 監査証跡はより正確で、部分的な障害に対する回復力が高いため、デバッグとデータ回復の信頼性が高まります。
  • 再試行と API の回復力: Google API 再試行ヘルパーが導入され、いくつかの API 呼び出しのタイムアウトや一時的な障害に対する耐性が強化されました。重要な理由: 短期間の Google API エラーによって引き起こされる同期エラーが減少します。
  • コネクタのメタデータがチャンクに組み込まれる: コネクタのタイトルとソース メタデータが、保存されたペイロードとチャンク ペイロードにコピーされるようになりました (チャンクとは、検索に使用されるドキュメントの小さな部分です)。機能: 保存されているコンテンツと一緒に、人間にわかりやすいソース名を保持します。重要な理由: 検索結果と来歴により、返されたコンテンツのソースがより明確に示されます。
  • ソースから NUL 文字を削除: システムは、取り込み中にすべてのドキュメント ソースから NUL 文字を削除するようになりました。重要な理由: ファイルに埋め込まれた NUL によって引き起こされる解析の問題やテキストの破損を防ぎます。
  • テストと CI の強化: 複数のテストと CI の改善 (ワークフローの修正、固定された統合テスト キー) により、リリースと統合テストがより安定し、予測可能になります。

パフォーマンス

  • リリースされたファイルの同時削除: アップデートのクリーンアップでは、削除されたファイルが並行して削除されるようになり、アップデート中にストレージのクリーニングに費やされる合計時間が短縮されます。
  • 増分ウォーク用の専用プール: 増分ファイル ウォーク プロセス (dlt ウォーク、更新中に使用される検出ステップ) は独自のワーカー プールで実行されるため、他の更新タスクとスレッドを競合することがなくなり、大規模な同期のスループットが向上します。

バグ修正

  • ドライブ: 以前の同期によってスキップされたドライブ ファイルが再取り込まれないケースを修正しました。その後の同期中に見逃されるファイルが少なくなります。
  • 追加/更新コピーの修正: スキップされた追加によって保存されたコピーの削除を停止し、新しい追加ではまだコミットされていないファイルを保持するようにしました。重要な理由: 追加の失敗またはスキップ中に、一時コピーが誤って失われることを防ぎます。
  • 無効なチャンク ID をスキップ: ドキュメント ID が UUID ではないチャンクは、不正な形式のデータによるクラッシュを避けるために処理中にスキップされるようになりました。それが重要な理由: 破損したチャンクまたは不正な形式のチャンクによってパイプラインが中断されなくなりました。
  • Slack 回答: チャンク ペイロードから Slack 回答ソースを読み取り、Slack 関連のさまざまなレビュー結果をクローズすることで、Slack 回答の一貫性と追跡性が向上します。
  • NUL バイトの除去: ダウンストリームの解析エラーを回避するために、NUL 文字が埋め込まれたドキュメントが取り込み中に除去されるようになりました。
  • ツール出力制限の検証: システムは、ランタイム エラーの原因となる構成ミスを回避するために、max_tool_output_chars (エージェント ツールが返す最大文字数) を検証します。
  • 来歴/回復の修正: 実行回復におけるいくつかのエッジケースが修正されたため、放棄された実行や重複した実行が正しく処理され、データセットの最新の実行が保存されます。重要な理由: 更新が中断された後、データセットが間違った実行や古い実行を指したままになることはありません。
  • 置換された保存ファイルの削除: 更新中にファイルが置換されると、古い保存ファイルが確実に削除されるようになりました。
  • Slack とレビューの閉鎖: 以前に報告された Slack 関連のレビュー結果を閉鎖するための複数の修正により、インタラクティブな Slack エクスペリエンスが向上しました。

技術的な変更

  • 外部埋め込みワーカーをサポートするために、client/server コードとエラー処理を備えた完全な埋め込みワーカー実装とプロトコル (RabbitMQ ベース) を追加しました。
  • 統合サブシステムの大規模なリファクタリングと追加: 新しいアダプター、スケジュールされた同期、同期ポリシー ストアとティック ロジック、および資格情報管理により、より多くのコネクタと信頼性の高いスケジュールされた同期をサポートします。
  • 来歴サブシステムのオーバーホール: 新しいマネージャー、アンカー、トゥームストーン、ストレージ、およびエッジ証拠のクリーンアップ コードにより、監査証跡がより保守しやすく正確になります。
  • リモート ワーカーと RPC の改善: AMQP RPC と再試行ヘルパーが追加され、堅牢なリモート タスクの実行をサポートします。
  • コネクタ ペイロードのリファクタリング: トレーサビリティを向上させるために、コネクタ タイトルとその他のソース メタデータがペイロードとチャンク ペイロードに一貫してコピーされるようになりました。
  • コードベースの成長に合わせてシステムの安定性を維持するため、コネクタおよびフロントエンド テスト全体にわたる多くのテスト カバレッジと CI ワークフローの更新。
