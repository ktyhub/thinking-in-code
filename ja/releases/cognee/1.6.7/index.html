コグニー v1.6.7

#v1.6.7

発売日: 2026-11-06 変更点: v1.6.6rc1 → v1.6.7

プル リクエスト: #6266、#6337、#6338、#6339、#6340、#6342、#6392、#6404、#6493、#6512、#6540、#6546、#6550、#6564

概要

このリリースでは、取り込みの安全性が強化され、検索と取得の動作とパフォーマンスが改善されます。システム ファイルまたはデータベース接続情報を与える際のより厳格な保護措置、より正確なスコープ検索 (特定のドキュメント タイプまたは名前空間をターゲットとするクエリ)、およびベクトル検索のより高速で効率的なスコアリングが表示されます。

ハイライト

  • より安全な取り込み: 生のデータベース接続文字列と安全でないサーバー/ファイル パスはデフォルトで拒否され、誤って認証情報やサーバーが漏洩するリスクが軽減されます。
  • 検索と呼び出しの正確性: 型付き/スコープ付きクエリ (特定のドキュメント タイプまたはスコープを対象としたクエリ) は、LLM セーフな正しい結果を返すようになり、「ラッキーな感じ」のピックでは無効なデータ型が無視されます。
  • 取得パフォーマンス: PGVector、Turso、LanceDB のバックエンドでは、スコアリング作業をバッチ化および並列化することにより、クエリ スコアリングが大幅に高速化されます。
  • さまざまな堅牢性の修正: LanceDB の圧縮/移行、グラフの更新/挿入、セッション/削除操作、および SDK ユーザー向けのエクスポート ヘッダーの修正。

重大な変更

  • データベースとリモート パスのより厳密な取り込みデフォルト: HTTP 経由の生のデータベース接続文字列とサーバー ファイル パスはデフォルトで拒否されます。影響: 以前にそのような接続文字列を取り込んだワークフローまたはコネクタは、取り込みに失敗し始めます。処置: 意図的にこれらのソースを使用する場合は、取り込み構成とドキュメント内の明示的なオプトイン制御を確認して、これらのソースを許可してください。
  • ACCEPT_LOCAL_FILE_PATH は s3:// 入力もゲートするようになりました。s3:// URI に対して以前の寛容な動作に依存していた場合は、ACCEPT_LOCAL_FILE_PATH を設定するか、文書化されたオプトインに従ってこれらの入力を再度有効にする必要がある場合があります。詳細については、取り込み API ドキュメントを確認してください。

新機能

  • 列グラフ アンカー (DLT): 「グラフ アンカー」(テーブルの行をグラフにリンクし直すのに役立つ小さなポインタ) を格納する台帳/グラフ ストレージに新しい列を追加します。機能: 列の書き込みに関するアンカー情報を記録し、グラフ クエリと下流のプロセスがそれらの行をより確実に参照できるようにします。重要な理由: グラフに基づいた列と元帳照合に依存するワークフローの正確性と追跡可能性が向上します。

改善点

  • より厳密かつ明確な取り込み処理: 取り込みメッセージングが簡素化され、システムには安全でないネットワークまたはデータベース接続入力に対する単一の拒否ルールが設けられるようになったため、ファイルまたは接続が拒否された理由を理解しやすくなりました。重要な理由: 機密性の高い接続文字列やリモート パスの誤った取り込みが減少します。
  • スコープと LLM の個別のルーティング制約: どのドキュメントを言語モデル (LLM) にルーティングするか、どのドキュメントをスコープ (ドキュメント タイプまたは名前空間) ごとにルーティングするかを決定するコードは、個別のルールにリファクタリングされました。機能: 範囲指定された検索と LLM ルーティングの動作がより明確かつ予測可能になります。重要な理由: 特定のドキュメント タイプのみを対象とする場合、または一部の検索を LLM フリーにしたい場合の正確性が向上します。
  • 検索および呼び出しスコープの処理: 型付きスコープ (「タイプ X のドキュメントのみを検索する」というクエリ) は、チャンク検索および引用符付き/スコープ付きクエリで一貫して尊重されるようになり、同じ引用符で囲まれたフレーズによって不必要な LLM ルーティングが回避されます。重要な理由: スコープ付きクエリはより正確で期待される結果を返し、余分な LLM 呼び出しを回避します。
  • ファイル取り込みのエラー コードを修正: 禁止されたリクエストは、415 ではなく 403 を返し、役立つメッセージを返します。重要な理由: より明確なエラー処理により、オペレーターはアクセス許可とゲートの問題をより迅速に診断できます。
  • SDK エクスポートで OMP ヘッダーを保持する: SDK アーティファクト (Cognee X / SDK フローで使用) をエクスポートする場合、OpenMP スタイルのヘッダーが保持されます。重要な理由: SDK エクスポート ワークフロー中の構成/メタデータの損失を回避します。

パフォーマンス

  • バックエンド全体のバッチ スコアリング: PGVector と Turso は、単一のデータベース ステートメントでクエリのバッチ全体をスコアリングするようになり、マルチクエリ リクエストのラウンド トリップとレイテンシが削減されます (実際的な効果: マルチクエリ取得のレイテンシが短縮されます)。
  • LanceDB スコアリングの最適化: LanceDB 上の単一 ID スキャンでクエリのバッチをスコアリングでき、複数のクエリのスコアリングは ID によって並列化されます。実際的な影響: LanceDB をベクター ストアとして使用すると、バッチ検索が高速化されます。
  • PGVector の 1 回の検索で欠落しているベクター コレクションをスキップします。コレクションが存在しない場合の無駄な作業を削減します。実際的な影響: 取得パスが高速化され、一部の障害ケースでの検索が減少します。
  • 忘れ/セッション キャッシュのバッチ削除: セッション関連の削除は、オーバーヘッドを削減するためにバッチ化されます。実際の影響: 大規模な忘れ操作がより高速かつ効率的に行われます。

セキュリティ

  • データベース接続文字列のデフォルトの拒否: 認証情報の誤った取り込みを防ぐために、生のデータベース接続文字列はデフォルトで拒否されます。データベース ソースを意図的に取り込む場合は、明示的にオプトインする必要があります (ドキュメントを参照)。重要な理由: 取り込みによる認証情報漏洩のリスクを軽減します。
  • Cognee 認証情報を含む接続文字列を拒否する: サーバーは、製品自身の認証情報を含む取り込みの試行を拒否するようになります。重要な理由: 誤った自己参照接続や資格情報の再利用を防ぎます。
  • デフォルトで HTTP 経由のサーバー ファイル パスを拒否する: プレーン HTTP 経由のサーバー ファイル パスのように見える入力は、明示的に許可されていない限り拒否されます。重要な理由: untrusted サーバーからの誤ったリモート ファイルの取り込みを防ぎます。
  • ACCEPT_LOCAL_FILE_PATH は s3:// 入力も制御します。ローカル ファイルシステム パスを受け入れるかどうかを制御する既存の環境の切り替えにより、取り込み API の s3:// スタイル入力も制御されるようになりました。重要な理由: ローカル ソースと S3 スタイルのソース間でファイル パス ゲーティングの一貫性を確保します。
  • 権限エラーの修正: API は、ブロックされたファイル取り込み試行に対して、役立つ情報とともに 403 (禁止) を返すようになりました。重要な理由: 権限の問題に対する、より明確で適切なエラー通知。

バグ修正

  • 「ラッキーな気分」から無効なタイプを除外する: ワンショットの「ラッキーな気分」チャンク選択では、無効なドキュメント タイプが無視されるようになり、無関係なヒットが防止されます。
  • スコアリングできないチャンク スコープの拒否: スコアリングできないスコープを持つチャンク検索は早期に拒否されるようになり、混乱を招く、または誤解を招く結果が回避されます。
  • 一致するベクトルがない場合に型付きスコープを保持する: 型付きスコープがベクトルの類似性を返さない場合でも、型付きスコープは保持されるため、ダウンストリーム ロジックは何が要求されたかを認識します。
  • ドキュメント名によるスコープ チャンク検索: ドキュメント名を指定するチャンク レベルの検索では、検索がそのドキュメントに適切に制限されるようになりました。
  • LanceDB の修正: 圧縮中にウィンドウ行を保持し、移行中に書き込まれた行を修復するためのいくつかの修正により、スキーマ変更またはメンテナンス操作後のデータの整合性が向上します。
  • グラフと upsert の修正: upsert_edges は文字列ノード ID を受け入れるようになり、その他のグラフの修正によりグラフ書き込みの堅牢性が向上しました。
  • セッション/忘れの修正: セッション所有者のスコープ設定とセッション削除の一致が強化され、削除されたワークフローやセッション所有者が見つからない場合でもワークフローを忘れたままになります。
  • インデックスのコピーと保存された行: インデックスの行が保存されたものとしてコピーされるようになり、インデックスのメタデータと保存されたデータの間の不一致が回避されます。

技術的な変更

  • リファクタリング: スコープ ルーティングと LLM ルーティング制約を別個のコンポーネントに分割して、ルーティング ロジックを簡素化し、将来の変更のテストを容易にします。
  • 取り込み拒否のリファクタリングとメッセージのクリーンアップ: 取り込みが拒否される理由を 1 か所で決定できるように、拒否メッセージの形式を統一しました。
  • 取得スコアリングの再設計: バックエンドがより少ないステートメントでクエリ バッチをスコアリングできるようにスコアリング パスを再設計し、コレクション対応エンジン用のモック/テストを追加しました。実際の効果: 測定可能なパフォーマンスの向上を伴う、より明確で、より適切にテストされた取得コード。
  • CI とテスト: カバレッジと信頼性を高めるために、多くのテスト (単体、統合、e2e) と CI ワークフローを追加および更新しました。また、コネクタ テスト フィクスチャとアダプタ モックも追加されました。
