コグニー v1.6.6

v1.6.6 — 競合の解決と安定性

発売日: 2026-10-29 変更点: v1.6.6rc1 → v1.6.6

プル リクエスト: #6266、#6337、#6339、#6340

概要

このリリースでは、競合処理の信頼性を高め、管理を容易にすることに重点を置いているほか、安定性、ベクトル、データ レイアウトのいくつかの修正が行われています。新しい耐久性のある競合解決 API、競合する選択肢のより安全な廃止、より高速かつ安全なキャッシュ/削除パス、および再埋め込み作業を節約するベクトル処理の改善が見つかります。

ハイライト

  • 事実の不一致を解決するための新しい耐久性のある API により、データの不一致を API から確実に解決できます。
  • 競合レビューはデフォルトで有効になっており、多くの修正により、編集、削除、再構築時に「選択」(矛盾する事実に関するユーザーの決定) が正しく破棄されることが保証されています。
  • 保存されたベクトルを再埋め込みせずにベクトル ストア間でコピーし、埋め込みを移動/複製する際の時間とコストを節約します。
  • より安全な削除とキャッシュ: Redis リスト/コンテキストの削除はアトミックまたはインプレースで行われるようになり、権限/KMS エラーが表面化されるため、失敗が黙って無視されなくなります。

新機能

  • 永続的な事実の競合解決 API — 永続的な (永続的な) 方法で矛盾する事実間の不一致を解決できる新しい API エンドポイント。機能: 選択した解決策を記録して適用し、システムが解決されたファクトを一貫して使用できるようにします。重要な理由: セッションおよびコンポーネント間のデータの不整合を確実に解決し、古いデータや競合するデータによる不正確な回答や予期しない動作を削減します。
  • デフォルトの競合レビュー ワークフロー — システムはデフォルトで競合をレビューするようになりました (以前はオプションでした)。機能: システムが矛盾する事実 (同じ情報の異なるソースまたはバージョン) を検出すると、レビューのためにそれらを自動的に表示します。重要な理由: 競合検出をすぐに実行できるようにすることで、すり抜ける競合が減り、検索/エージェントがよりクリーンな結果を返します。
  • 再埋め込みを行わずにストア間で保存されたベクトルをコピー — 埋め込みモデルを再実行せずに、あるベクトル ストアから別のベクトル ストアにベクトル 埋め込みを移動またはコピーできるようになりました。内容: 保存された埋め込みの直接コピーを実行します。重要な理由: モデルが再呼び出されないため、移行とレプリケーションが高速化され、コンピューティングとコストが削減されます。
  • DLT 列と日付付きセルの表現の改善 — すべての DLT 列 (変更追跡テーブルで使用される列) はデフォルトで値ノードとして扱われるようになり、日付付きセルはタイムスタンプ値として 1 回表現されます。機能: プラットフォームで変更追跡列を具体的な値として扱い、日付セルの重複を回避します。重要な理由: データセットの行とキーを読み取る際の微妙な正確性と重複の問題を修正し、読み取りとダウンストリーム処理の精度を向上させます。

改善点

  • 選択肢のより安全な廃止 (矛盾する事実についてのユーザーの決定) — 選択肢は、チャンクの編集、コネクタの削除、データセットの削除操作、および再構築によってそれらの選択肢が失われる場合など、適切なタイミングで廃止されます。これにより、データ変更後に残る古い決定が減少します。
  • 無効化および不正なキーのフェイルファスト - 関連する状態の無効化が失敗すると、編集は失敗します。 DLT キーの不正な形式のヒントは、黙ってスキップするのではなく、エラーを発生させるようになりました。これにより、サイレントなデータの不整合が防止されます。
  • 競合解決時に取得コンテキストを保持する — 裏付けとなる証拠を取得するために使用される取得コンテキストが、競合の解決中に保持されるようになりました。そのため、回答は同じコンテキストに基づいたままになります。
  • ベクターを書き込む前にタグをマージおよび検証する — ベクターの更新/挿入の前にタグがマージおよび検証されるようになり、ベクター レコード上の破損または不完全なメタデータが回避されます。
  • マルチセッション スタンプのロールアウトを終了する — セッション スタンプ (セッション間のアクションを追跡するために使用される) がコンポーネント間で一貫してロールアウトされるようになり、セッションの処理と正確さが向上しました。
  • assign() がシールされたオブジェクトの平文ビューを受け入れるようにする — 処理のために開かれた後に、暗号化/シールされたオブジェクトの内容を分類する必要がある場合に便利です。

パフォーマンス

  • 削除された競合ファクトをリタイアする際の取得競合の減少 - 競合状態が低下し、多くの決定が一度にリタイアされるときの応答性が向上します。
  • Redis リストのインプレース削除とアトミック コンテキスト削除 - キャッシュ削除がより効率的かつ一貫性を持ち、レイテンシーと部分削除状態が軽減されました。
  • 行のキー列の直接読み取り - キー列を直接検索することで、行を読み取る際のオーバーヘッドが削減され、テーブルベースのデータセットの読み取りパフォーマンスが向上します。

セキュリティ

  • KMS エラーの透過性 — キー管理システム (KMS) エラーがラップされていない状態で表示されるようになりました。これにより、呼び出し元コードは、暗号化/キーの問題を非表示にするのではなく、確認して正しく処理できるようになります。
  • クリーンアップでの削除権限チェック - クリーンアップ操作で削除権限が検証されるようになり、不正なデータ削除のリスクが軽減されます。

バグ修正

  • 無効化が失敗した場合に編集を失敗する — 関連する無効化を実行できない場合、編集が停止してエラーが報告されるようになり、不整合な状態が回避されます。
  • チャンク編集時および更新時のみに選択肢をリタイアする (認識しない) - 時期尚早なリタイアやリタイアの見逃しを回避するために、適切なライフサイクル段階で選択肢がリタイアされるようにします。
  • 再構築によって失われた、またはファクトがなくなったときに選択を破棄する — 基礎となるファクトが削除または置換された後に、古い選択が残るのを防ぎます。
  • 忘れた場合とコネクタの削除時にユーザーの選択を破棄する — データセットを忘れた場合やコネクタを削除した場合に、ユーザーの決定が確実にクリーンアップされます。
  • プレリュードで指定された選択肢をスキップする — 競合の前処理中に、指定された (静的な) 選択肢を誤って考慮することを回避します。
  • 競合を解決する場合にのみライブ チャンクを引用する — 現在ライブ (削除されていない) チャンクのみを裏付け証拠として使用し、解決中に削除されたデータが使用されるのを防ぎます。
  • メモリのみの削除パスを修正 — 純粋にメモリ内で動作している場合と永続ストレージ内で動作している場合に、以前は動作が異なっていたパスに対処します。
  • Redis コンテキストをアトミックに削除し、リスト エントリをその場で削除する - キャッシュ内の競合状態と部分的な削除を修正します。
  • BROAD モードで、不正な形式の DLT キー ヒントで失敗し、読み取れない DLT テーブル キーで発生します — サイレント スキップを防止し、不正なテーブル/キー入力を明らかにします。
  • タグをマージし、生のベクトルの更新/挿入の前に検証 — ダウンストリーム ツールを破壊する可能性のある無効なベクトル メタデータの書き込みを回避します。
  • assign() にシールされたオブジェクトのプレーンテキスト ビューを表示する - 分析のために開かれたシールされたオブジェクトの分類動作を修正しました。
  • サンプルを実行可能な状態に保ち、Python のバージョンと環境全体での安定性を確保するための、いくつかのテスト、CI、ドキュメントの更新。

技術的な変更

  • リファクタリング: どこでも単一のリストとしてセッションを操作にバインドします。バグを減らし、セッション操作の一貫性を保つために内部セッション処理が簡素化されます。
  • リファクタリング (deps): onnxruntime ピンと関連する依存関係のハウスキーピングを簡素化します。
  • リファクタリング (テレメトリ): インストルメンテーションの動作をより明確にするために、テレメトリの制限を簡素化します。
  • CI とツールの更新: ワークフローの範囲が拡大され、キーレス モデル フェッチ スクリプトの調整、CI での S3 キャッシュの処理、テスト スイートの改善が行われました。
