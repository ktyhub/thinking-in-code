コグニー v1.6.9

v1.6.9 — 新しいコネクタと統合

発売日: 2026-11-18 変更点: v1.6.8 → v1.6.9 プル リクエスト: #6639、#6644、#6739、#6742

概要

このリリースは、統合の拡張と、取り込みと埋め込みの動作の安定化に焦点を当てています。複数の新しいコネクタ (Slack のリワーク、Dropbox、Vercel、Telegram、Evernote、Asana の改善) と hermes エージェントの統合を追加し、さらにいくつかの信頼性と埋め込みの修正を加えたので、データの取り込みと取得の信頼性が高まりました。

ハイライト

  • Slack 統合を改善するための主要なコネクタの追加と Slack ホストのリファクタリング。
  • Hermes エージェントの統合: キャプチャ、リコール、およびランタイム ワークフロー用のパッケージ化されたエージェント。
  • 短い埋め込み応答や制限された保留中のバッチの拒否など、埋め込みとストレージの信頼性に関する修正。
  • 一貫性のない分割を避けるため、簡略化された一貫性のあるドキュメント チャンク (インデックス作成のためにコンテンツを分割するロジック)。

重大な変更

  • Slack 履歴インポートの削除: 古い Slack 履歴インポート パスウェイは削除され、新しい Slack コネクタとホスト モジュールに置き換えられました。これが意味すること: 古い Slack 履歴インポート API に依存していた場合は、新しい Slack コネクタ (コネクタ/スラック) に移行し、新しいホスト/アダプター インターフェイスへのカスタム配線を更新する必要があります。
  • コネクタのパッケージ化とポート: いくつかのコネクタが追加され、Slack 内部の一部が新しいホスト モジュールに移動されました。これが意味すること: コネクタの内部をベンダーまたはパッチする場合は、connector/* レイアウトを確認し、インポートを新しい場所に更新します。

新機能

  • Slack ホストの再加工と新しい Slack ソース: Slack コネクタが新しいホスト モジュールに移植され、新しい直接 Slack ソースが追加され、古い Slack 履歴インポートが置き換えられました。機能: コネクタ パッケージ内で維持される最新の Slack 統合パス (メッセージ同期、メンバー リンク、Webhook) を提供します。重要な理由: Slack の取り込みとインタラクションは、より保守しやすく、テストしやすくなります。削除された Slack 履歴インポートを以前に使用していた場合は、新しい Slack コネクタに移行してください (コネクタ/slack を参照)。
  • Dropbox コネクタ: 新しい Dropbox コネクタ (client、コネクタ、選択 UI およびソース) が追加されました。機能: Dropbox から Cognee にファイルを取り込み、インデックス付けと取得を行うことができます。重要な理由: サポートされているソースを拡張して、Dropbox からドキュメントを取得して記憶したり検索したりできるようにします。
  • Vercel コネクタ: プロジェクト データを取り込むための Vercel コネクタと配線を追加しました。機能: Vercel 関連のアーティファクトをキャプチャするためのソース実装を提供します。重要な理由: Vercel プロジェクト データを Cognee のメモリと検索に含めることができるようになりました。
  • テレグラム コネクタ: テレグラム コネクタを追加しました。機能: Telegram メッセージ ストリームをキャプチャし、Cognee に統合します。重要な理由: チャット プラットフォームの対象範囲を拡大し、Telegram の会話を検索して思い出すことができるようにします。
  • Evernote コネクタ: Evernote コネクタを追加しました。機能: Evernote からメモとノートブックをインポートします。それが重要な理由: Evernote コンテンツを持つユーザーは、それらのメモを Cognee メモリに含めて取得できます。
  • Hermes エージェントの統合: ファーストクラスの hermes エージェント統合が追加されました (プロバイダー、ランタイム、バックエンド、キャプチャ ポリシー、およびツール)。機能: キャプチャ、バッファリング、リコール通知、実行時のオーケストレーションのための独自のエージェントを提供します。重要な理由: 自動化されたキャプチャとリコールのワークフローの実行と、ローカル エージェントベースの Cognee との統合が簡素化されます。

改善点

  • デフォルトのチャンカーが統合され、一度解決される: インデックス作成のためにドキュメントを分割する方法を決定するロジック (「チャンカー」) が 1 か所で解決され、一貫して使用されるようになりました。機能: コード パス間での不一致な分割を防ぎます。重要な理由: 検索と埋め込みの動作がより予測可能になり、より一貫した検索結果が得られます。
  • 可観測性: LLM 呼び出しのキャプチャ: システムは、可観測性を確保するために LLM (大規模言語モデル) 呼び出しを記録するようになりました。機能: ログとテレメトリには、操作中に呼び出される LLM 呼び出しが含まれます。重要な理由: クエリが LLM 呼び出しをトリガーする時期を診断し、使用状況を測定するのに役立ちます。
  • グラフ モデルを JSON スキーマとして受け入れる: cognify パスウェイは、JSON スキーマとして提供されるグラフ モデル定義を受け入れるようになりました。機能: グラフ スタイルのデータ抽出用のスキーマを簡単に提供できるようにします。重要な理由: JSON スキーマ グラフ定義を生成するシステムとの統合が簡素化されます。
  • ドキュメントとドキュメント文字列の強化: 多くの公開 API のドキュメントとドキュメント文字列が明確になりました (検索動作、ドキュメントの詳細の記憶/追加、エラーのケース)。機能: レトリバーがバイパスされるタイミングと権限チェックの動作を明確にします。重要な理由: 予想される動作を理解しやすくなり、統合のバグが軽減されます。
  • テストと CI: テスト スイートが分割されて固定され、多くのコネクタ ユニット/統合テストが追加されて安定しました。機能: リポジトリの継続的統合の信頼性を向上させます。重要な理由: CI の誤った失敗を減らし、安全なリリースを迅速化します。

パフォーマンス

  • Asana のより信頼性の高い取り込み再開: オフセットの有効期限が切れると以前は停止していたリスティングが正しく再開され、取り込み中に見逃されるアイテムが減少します。
  • ストレージ内の保留中のバッチの制限: 書き込みのバッファリング中の無制限のメモリ増加を防ぐために、保留中のバッチ サイズが制限されるようになりました。
  • 冗長なチャンカーの解決の削減: デフォルトのチャンカーを 1 回だけ解決することで、オーバーヘッドが削減され、取り込み中に決定が繰り返されることが回避されます。

セキュリティ

  • このリリースには新しいセキュリティ勧告はありません。注: Slack 統合コードが再編成され、署名検証ユーティリティが Slack ホスト リファクタリングの一部として調整されました。カスタム Slack フックに依存している場合は、新しいコネクタの実装を確認してください。

バグ修正

  • pgvector ストレージの短い埋め込み応答を拒否: 非常に短い、または不正な形式の埋め込み応答は保存されずに拒否され、ベクターの破損やインデックス エラーが防止されます。
  • pgvector フローでスキップされた行を再チェックします。埋め込みインデックスから項目が失われないように、チェック中に以前にスキップされた行が再評価されます。
  • Telegram の失敗を 1 回カウントする: Telegram 取り込みの失敗メトリックが重複排除されたため、失敗カウントが正確になります。
  • オフセットの有効期限が切れたときに Asana のリストを再起動する: Asana の取り込みは、保存されているオフセットの有効期限が切れたリスト ジョブを再開し、取り込みのスタックを回避するようになりました。
  • ハードコードされた接続制限を削除: 一部の環境で接続処理の問題を引き起こしていたハードコードされた接続制限を削除しました。
  • スコープの埋め込みリクエストの分割: 埋め込みリクエストの分割方法を改良し、適切なリクエストが一緒に送信されるようにし、誤ったまたは部分的な埋め込みアップロードを削減します。
  • 最初の行を共有するエラーを区別する: エラー報告が改善され、同じ最初の行メッセージを持つ例外が正しく区別されるようになりました。
  • 失敗した CI インポート エラーを修正し、テストの堅牢性を変更しました。複数のテスト修正により、新しいテストが CI で正しく実行されるようにし、プラットフォーム固有のエラー (例: pytest-timeout SIGALRM の使用) を回避しました。

技術的な変更

  • Slack ホスト モジュールとアダプターの大規模なリファクタリングとコネクタ パッケージへの移植 (新しいモジュール レイアウトとルーター/同期/アダプターの実装)。
  • 主な新しいコネクタ コード ツリーが追加されました: Dropbox、Vercel、Telegram、Evernote、Asana のテスト/コネクタの更新と、これらのコネクタの多くの単体/統合テスト。
  • Hermes-agent: エージェントベースのキャプチャとリコールのワークフローをサポートするための広範な新しいコード (プロバイダー、バックエンド、runtime_env、http_backend、キャプチャ ポリシー、ツール)。
  • テストと CI の再編成: テストはグループに分割され、新しい GitHub ワークフロー ファイルが追加/更新され、統合と e2e テスト カバレッジが向上しました。
  • コードの品質: インポートの並べ替え、docstring の強化、およびより明確なエラー処理と入力の改善のためのいくつかのリファクタリング (例: Asana 認証と入力の再開)。
