コグニー v1.6.10

v1.6.10 信頼性と可観測性の向上

発売日: 2026-11-18 変更点: v1.6.9 → v1.6.10 プルリクエスト: #6744

概要

このリリースでは、Cognee の信頼性を高め、デバッグを容易にすることに焦点を当てています。Postgres 接続プールは強化されて暴走接続と長時間待機が削減され、LLM コール キャプチャはネストされたフォローアップと発信者情報を記録して可観測性が向上し、ドキュメント チャンク パスは不正なチャンクの再利用を避けるために強化されています。不安定性を軽減するために、CI/テストのシャーディングも拡張されました。

ハイライト

  • データセットごとのより安全な Postgres 接続プール: デフォルトのオーバーフローと制限された待機時間を減らし、大規模な接続のスパイクや長時間の停止を回避します。
  • LLM コール キャプチャの改善: フォローアップ (ネストされた) LLM コールを記録し、より明確なデバッグと使用状況分析のための呼び出し元のメタデータを含めます。
  • チャンキングの堅牢性: より厳密な検証とチャンクの集中スタンプにより、保存されたチャンクが確実に識別され、可能な場合には再利用されます。
  • CI はより多くのシャードに分割され、不安定性が軽減され、開発中のテスト フィードバックが高速化されます。
  • 廃止された Anthropic モデル名に関するドキュメントが更新されました (現在は claude-sonnet-5-5 を推奨しています)。

重大な変更

  • データセットごとの Postgres プールの動作: データセットごとの Postgres 接続プールのデフォルトが強化されました (最大オーバーフローが小さくなり、明示的なプール待機動作が行われます)。デプロイメントがデータセットごとのエンジンへの同時書き込みの非常に大規模で短期間のスパイクに依存している場合、より即時に「プール枯渇」エラーが発生する可能性があります。必要なアクション: VECTOR_POOL_ARGS またはデータセット固有のプール設定を確認し、必要に応じて増やすか、ワークロードに合わせて pool_timeout を増やします。

新機能

  • LLM コール キャプチャのフォローアップ: LLM コール キャプチャ機能 (Cognee が行う LLM コールごとに 1 つの JSONL レコードを書き込みます) は、フォローアップ/ネストされた LLM コールと、それらの発信者を記録する (「発信者」フィールド) もキャプチャするようになりました。機能: 元の LLM リクエストと後続の内部呼び出しの両方について、より明確で追跡可能な記録を取得します。重要な理由: デバッグ、コスト分析、および複雑な複数ステップの LLM フローの観察が容易になります。

改善点

  • データセットごとの Postgres プールのデフォルトの厳格化: データセットごとの Postgres プール (pgvector バックエンドおよびその他のデータセットごとの DB エンジンによって使用される) のデフォルトの上限が引き下げられ、各データセットが使用する過剰な接続が減りました。構成コメントでは、pool_timeout 値 (操作が失敗するまでに空き接続を待機する時間) も呼び出すようになりました。機能: 過度に多くの DB 接続が開かれたり、長時間予期せぬ停止が発生したりする可能性が減少します。重要な理由: マルチテナント設定における展開がより予測可能になり、データベース リソースの負荷が軽減されます。
  • より厳密なチャンク チェック: ドキュメント チャンク ロジック (インデックス作成と取得のためにドキュメントをより小さな「チャンク」に分割する) は、チャンクのより厳密な検証を実行するようになりました。機能: 無効なチャンクまたは不一致のチャンクを早期に検出し、更新動作を損なう可能性のあるチャンクをサイレントに受け入れることを回避します。それが重要な理由: ドキュメントを更新する際の、不可解な再構築やデータの不整合が少なくなります。
  • 集中的なチャンク スタンピング: チャンク オブジェクトには、チャンカー識別子 (どのチャンク ルールによってチャンクが生成されたかを示すマーカー) が集中的にスタンプされるようになりました。機能: 分散スタンピングに依存するのではなく、保存されたチャンクがオリジン ID を確実に保持するようにします。重要な理由: 増分更新中に既存のチャンクを再利用できるかどうかをシステムが判断する際の正確性が向上します。
  • ドキュメント: Anthropic モデル名が更新されました: ドキュメント内で、廃止されたモデル名「claude-3-5-sonnet-20241022」への参照が「claude-sonnet-5-5」に置き換えられました。機能: 削除されたモデルを参照することによる混乱を防ぎます。重要な理由: セットアップ手順を正確に保ち、​​Anthropic プロバイダーを構成する際の無駄な時間を削減します。

パフォーマンス

  • データセットごとの Postgres エンジンの接続オーバーヘッドの低減: プールのオーバーフロー上限を削減し、プールのタイムアウトを明確にすることで、一般的なデプロイメントで同時に開かれる DB 接続の数が少なくなります。実際的な影響: DB リソースの使用量が削減され、多くのデータセットを提供するホストでの競合が減少します。極端なスパイクは、長時間ブロックされるのではなく、より早く失敗します。

バグ修正

  • 単体テストと CI の安定性の修正: いくつかの失敗した単体テストが修正され、信頼性を向上させるためにテスト スイートが再編成されました (以下の CI の変更を参照)。
  • チャンク関連のバグ修正: 強化されたチャンカー チェックと集中型スタンピングにより、適切な識別子のないチャンクが更新の失敗や不整合な状態を引き起こす可能性があるケースが解決されました。
  • Postgres プールと待機動作の修正: データセットごとのプールが大きくなりすぎたり、高速に失敗せずに呼び出し元を長期間ブロックしたりする可能性がある問題に対処しました。

技術的な変更

  • CI/テストのシャーディングの増加: 統合テストは再分割され (取得 -> 5 シャード、ドキュメントとタスク -> 6 シャード、インフラストラクチャ -> 4 シャード)、単体テストはクロス OS CI で 4 つのシャードに分割されました。機能: テストの不安定さを軽減し、シャードごとの実行時間を均等化します。重要な理由: 開発者にとって、より速く、より信頼性の高い CI フィードバック。
  • 新規/更新された可観測性の内部: より豊富な LLM 通話レコード (フォローアップを含む) をキャプチャおよび書き込むために追加された新しいモジュール ファイルと、この機能をカバーするために追加された関連テスト。
  • 内部: MCP バージョンが向上し、新しい動作を反映しリグレッションを抑制するために複数のテスト ファイルが調整/追加されました。
