コグニー v1.6.5.dev0

v1.6.5.dev0 — 蒸留、埋め込み、コネクタ強化

発売日: 2026-10-16 変更点: v1.6.4.dev0 → v1.6.5.dev0

プル リクエスト: #5287、#5534、#5620、#5622、#5720、#5721、#5722、#5725、#5726、#5751、#5798、#5898

概要

このリリースでは、メモリ蒸留の信頼性の向上、エンベディングの生成と計測方法の改善、コネクタと LLM 統合の強化に焦点を当てています。これには、いくつかのバグ修正、セキュリティと操作性の改善、および従来の埋め込みサーフェスとローカル キャッシュ レイアウトに関連するいくつかの重大な変更が含まれています。

ハイライト

  • より信頼性の高い蒸留: 蒸留は、必要な QA ターンのみを読み取り、キュレーター バッチごとにエントリを封印し、デフォルトですべての新しいエントリをキュレートするため、蒸留された記憶は正確で一貫性があります。
  • 埋め込みの改善: サポートされている場合は、base64 でエンコードされた埋め込みのリクエストをサポートし、埋め込みトークンの使用量を測定し、安定性のためにデフォルトの埋め込みバッチ サイズを下げ、予測可能なパスの下でローカル モデル キャッシュを維持します。
  • コネクタと LLM の修正: Gmail および Google Calendar コネクタが強化され (クォータ処理とアクセス許可が改善)、litellm および Mistral モデルの処理が改善され、認証の複雑さを軽減するために Azure トークンの処理が共有されます。
  • セキュリティとアラート: Slack への毎日の CVE アラート配信が追加され、チームが最新情報を入手できるようにリポジトリのセキュリティ ドキュメントが更新されました。

重大な変更

  • トリプレット埋め込み/トリプレット memify サーフェスの削除または非推奨 — 古いトリプレット埋め込みサーフェスは非推奨となり、一部が削除されました。 「トリプレット」埋め込みフローに依存している場合は、新しい埋め込みサーフェスと memify パイプラインに移行してください。アップグレードする前に、パイプラインと代替品を確認してください。
  • datamodel-code-generator の最小バージョンが引き上げられました - カスタム グラフ モデルの生成には、datamodel-code-generator >= 0.56.0 が必要です。カスタム グラフ モデルを使用する場合は、この依存関係をアップグレードしてください。
  • Fastembed キャッシュ パスの変更 - FASTEMBED_CACHE_PATH が .env.template から削除され、fastembed はデフォルトで ~/.cognee/models を使用するようになりました。カスタム FASTEMBED_CACHE_PATH に依存していた場合は、環境を更新するか、キャッシュを新しい場所に移動してください。

新機能

  • サポートされている場合は Base64 埋め込みを要求する — 一部の埋め込みプロバイダーは、base64 としてエンコードされたベクトルを返すことができます。プロバイダーが Base64 埋め込みをサポートしている場合、Cognee は Base64 埋め込みを要求するようになりました。重要な理由: Base64 により、特定のプロバイダーやトランスポートとの互換性が向上し、エンコード エラーが減少し、統合が簡素化されます。
  • Slack への毎日の CVE アラート — 新しい自動アラートは、設定された Slack チャネルに毎日のセキュリティ勧告 (CVE サマリー) を投稿します。重要な理由: 依存関係に影響を与える新しい脆弱性をチームが常に認識できるようにすることで、より迅速に対応できるようになります。
  • 取り込み中にリポジトリの選択したブランチを複製する — リポジトリをプルするときに、どのブランチを複製するかを選択できるようになりました。重要な理由: 取り込みを再現可能にし、手動のリポジトリ処理を行わずにブランチ固有のコードまたはドキュメントのインデックスを作成できるようにします。
  • 埋め込みトークン使用量の測定 - システムは、アクティビティごとに使用された埋め込みトークンの数を記録するようになりました。重要な理由: コストの追跡とデバッグのための埋め込みの使用状況を理解し、監査するのに役立ちます。

改善点

  • より焦点を絞った蒸留: 蒸留では (会話全体ではなく) 必要な QA ターンのみが読み取られ、キュレーターはバッチごとに蒸留されたエントリをシールして実行するため、部分的な結果が漏洩することはありません。これにより作業が軽減され、抽出された要約がより決定的になります。
  • デフォルトで蒸留の実行ごとにすべての新しいエントリをキュレーションします。設定を変更しない限り、新しく追加されたすべてのメモリ エントリが蒸留の対象となり、新しいコンテンツがすぐに要約されるようにします。
  • 型付きエントリをセッションのデータセットにバインドします。システムがセッション中に型付き (構造化) メモリ エントリを書き込むと、そのエントリはそのセッションのデータセットに正しく関連付けられるようになりました。重要な理由: データセットの正しい所有権を保持し、データが間違ったデータセットに入るのを防ぎます。
  • remember_skill_run_entry で dataset_id を取得します — 記憶されたスキル出力の明示的なデータセット ルーティングにより、トレーサビリティと正確性が向上します。
  • Fastembed およびローカル モデル キャッシュの変更 — fastembed モデルは、プラットフォーム間で一貫したキャッシュを行うために、デフォルトで ~/.cognee/models の下に保持されるようになりました。 ENV テンプレートは、非推奨の FASTEMBED_CACHE_PATH を公開しなくなりました。それが重要な理由: ローカル モデルをロードする際の予期せぬ事態が減り、マシン間の動作が向上します。
  • デフォルトの埋め込みバッチ サイズの低下 (36 → 32) — メモリのスパイクが減少し、制約のあるマシンでの安定性が向上します。
  • embed_text からプレーン ベクトルを返す — 埋め込み関数は、より多くの場所でラップされたオブジェクトではなく生の数値ベクトルを返すようになり、ダウンストリームでの使用が簡素化されます。

パフォーマンス

  • より安定したエンベディングの使用: デフォルトのエンベディング バッチ サイズを下げ、モデルを一貫したローカル キャッシュに保持することで、エンベディング作成時のメモリとレイテンシーのスパイクが軽減されます。
  • 不必要な蒸留作業の削減: 必要な QA ターンのみを読み取り、バッチごとにシールすることで、蒸留実行中に使用される I/O と CPU が削減されます。
  • 共有カウンターとペーシング: コネクターとバックグラウンド ポーラーは、偶発的な過負荷を回避し、スループットを平滑化するために、必要に応じてカウントとペーシング ロジックを共有します。

セキュリティ

  • Slack への日次 CVE アラート — チームがより迅速に対応できるように、新しい GitHub アクション + Slack フローを通じて依存関係の脆弱性の日次概要が利用できるようになりました。
  • NATURAL_LANGUAGE サーフェスと修復ガイダンスを非表示にする - 安全な展開を支援するために、特定のサーフェスが目立たなくなり、修復メモが追加されました。
  • Azure トークン プロバイダーの共有 — Azure トークンの使用は一元化されているため、偽の資格情報の更新が減り、安全な処理が簡単になります。
  • Google カレンダーと Gmail の強化 — カレンダー コネクタのチェックが厳しくなりました。 Gmail はユーザーごとのクォータ拒否に対する耐性が高く、メールボックス処理全体でペースを共有することで、偶発的なレート制限のスパイクを回避します。

バグ修正

  • 蒸留に必要な QA ターンのみを読み取るため、蒸留ステップで不要な会話ターンが読み込まれなくなります。
  • 改善実行ごとにエージェント トレース バックログを排出し、新しい改善実行で古いトレースが表示されないようにします。
  • 部分的な抽出が表示されないように、キュレーター バッチごとに抽出されたエントリを封印します。
  • デフォルトでは、蒸留の実行ごとにすべての新しいエントリをキュレートし、新しいコンテンツが確実に要約されるようにします。
  • 同時削除/忘れによる競合を避けるために、ロックの下でデータの選択を読み取ります。
  • 可視化権限チェックを修正して、権限スキップ オプションが明示的に要求された場合にのみ適用され、必要に応じてデータセット所有者に対してのみ権限チェックをスキップします。
  • Gmail のユーザーごとのクォータの拒否に耐え、メールボックスごとのペースを共有して操作の失敗を減らします。
  • Cypher (グラフ DB クエリ インターフェイス) が無効になっている場合、一般的なエラーではなく、明確なメッセージを含む 403 を返します。
  • litellm 応答タイプを絞り込み、Mistral の解析されたモデル表現を正しく返すことで、LLM の信頼性と型安全性が向上します。

技術的な変更

  • 検索コンポーネントとコード検索コンポーネントの大規模なリファクタリング - 検索品質と保守性を向上させるために、ブロード リトリーバー、コード リトリーバー、およびハイブリッド検索用の新しいモジュールが追加または再編成されました。
  • Memify パイプラインの再編成 — memify と関連タスクの登録がリファクタリングされました。 SDK クリーンアップの一環として、いくつかの古いタスク モジュール (トリプレット埋め込み) が削除されました。
  • 新しい評価フレームワーク資産 — Locomo ベースの評価アダプター、メトリクス、および多くの参照実行アーティファクトが、内部評価とエンドツーエンドの QA のために追加されました。
  • LLM アダプターとトークン/エンコーディング ユーティリティの改善 - LLM アダプター、Azure ID 処理、埋め込みエンコーディング ユーティリティの改善により、LLM/バックエンド プロバイダー間の互換性が向上しました。
  • セッションとデータ選択の堅牢性 - 忘れ/削除ワークフローとの競合を避けるために、セッション管理とデータ選択ロジックが強化されました (ロックと選択チェック)。
