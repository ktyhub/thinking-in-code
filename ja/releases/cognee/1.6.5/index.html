コグニー v1.6.5

v1.6.5 — 高速なトレース処理と豊富なコードグラフ ドキュメント

発売日: 2026-10-16 変更点: v1.6.4 → v1.6.5

プル リクエスト: #5287、#5534、#5620、#5622、#5720、#5721、#5722、#5725、#5726、#5751、#5798、#5898、#5938、#5955、#5958、#5961

概要

このリリースでは、トレースおよび取り込みパイプラインが高速化され、セッション処理が改善され、コード グラフ内でコード ドキュメントが検索可能になります。また、新しい memify API、より優れた埋め込み互換性 (base64)、およびいくつかのセキュリティとコネクタの強化も追加されています。

ハイライト

  • トレース処理の高速化: トレースは保持され、より少ない大規模な操作で処理されるため、待ち時間が短縮され、データベースへの書き込みが少なくなります。
  • コード グラフ ドキュメント文字列: 関数/クラス ドキュメント文字列はグラフ ドキュメントとして保存され、コードの呼び出しと検索を向上させるためにコード シンボルにリンクされます。
  • 新しい Memify API エンドポイント: API 経由でコンテンツをメモリ エントリに変換し、取り込みとダウンストリーム リコールを簡単にします。
  • Base64 埋め込みのサポート: プロバイダーが互換性を向上させ、トランスポートの問題を軽減することを許可している場合、base64 としてエンコードされた埋め込みをリクエストします。
  • セキュリティとコネクタ: 毎日の CVE Slack アラート、Google カレンダー コネクタの強化、OAuth/トークン共有の改善。

重大な変更

  • datamodel-code-generator の要件が変更されました。カスタムのgraph_model 生成ステップを使用する場合は、datamodel-code-generator >= 0.56.0 が必要です。対処方法: 生成エラーを避けるために、カスタム グラフ モデルを生成するときにその依存関係をアップグレードします。

新機能

  • コード docstring をコード グラフに保存: docstring (関数、クラス、モジュールに添付されたドキュメント文字列) がファーストクラスのグラフ ドキュメントとして保存され、対応するコード シンボルにリンクされるようになりました。機能: コードを取り込むと、人間が判読できるドキュメント文字列にインデックスが付けられ、コード シンボル ノードに接続されます。重要な理由: 検索およびコード認識エージェントは、より豊富でコンテキストを認識した回答を返し、コード参照とともにインライン ドキュメントを表示できます。
  • 新しい Memify API とエンドポイント: 「memify」は、コンテンツ (ファイル、メッセージ、またはその他のデータ) を、システムが保存および呼び出しできるメモリ エントリに変換するプロセスです。機能: サーバー エンドポイントと CLI 配線を追加し、API 経由でメモリ エントリ (memify) を直接作成しました。重要な理由: 生のコンテンツを検索可能で呼び出し可能な記憶に変換して、フローを思い出したり改善したりするために使用することが簡単になります。
  • サポートされている場合は、base64 埋め込みを要求します。一部の埋め込みプロバイダーは、バイナリ トランスポートの問題を回避するために、base64 としてエンコードされた埋め込みを受け入れます。機能: Cognee は、プロバイダーがサポートしている場合、base64 でエンコードされた埋め込み応答を要求します。重要な理由: 特定のプロバイダーとの相互運用性が向上し、バイナリ埋め込みペイロードの送受信時の問題が軽減されます。
  • セッションのトレース バックログを 1 つのドキュメントとして保持します。トレースは、ユーザー セッションからのインタラクション レコード (イベント、ステップ、ログ) です。機能: Cognee は、多数の小さなトレース ドキュメントを作成する代わりに、セッションのバックログを 1 つの統合ドキュメントとして保持できるようになりました。重要な理由: データベースへの書き込みが減り、高トラフィックのセッションのスループットが向上するため、取り込みが高速化され、リソース使用量が削減されます。
  • 1 回の cognify 実行でトレース パス ウィンドウを構築します。「cognify」は、生のトレースをメモリ エントリに変換するパイプライン実行です。機能: パスのトレース ウィンドウ処理は、複数の実行ではなく 1 回の cognify 実行で計算されます。重要な理由: パイプラインの繰り返し実行が減り、トレース処理が高速化されるため、結果がより速く、より一貫して表示されます。

改善点

  • セッション/データセット バインディングの信頼性と速度: バインドされたセッション (特定のデータセット、つまり追加したドキュメントのコレクションに関連付けられたセッション) は、不要な再読み込みをスキップし、スキルの実行をバインドされたデータセットに正しくルーティングするようになりました。これにより、レイテンシが短縮され、古いバインディングまたは不一致のバインディングによってエラーが発生する可能性があるいくつかのエッジ ケースが修正されます。
  • キュレーションと蒸留の修正: 蒸留されたエントリはキュレーター バッチごとに封印され、新しいエントリは蒸留の実行ごとにデフォルトでキュレーションされます。これにより、自動フィルタリングとメモリ エントリの品質管理がより一貫したものになります。
  • 埋め込みトークンの追跡: アクティビティ モデルで埋め込みトークンの使用量が記録されるようになり、アクティビティごとの埋め込みコストを確認できるようになりました。
  • Google と Azure の認証共有: Google と Azure の OAuth とトークン プロバイダー コードが統合されたため、統合で同じアダプターが再利用され、重複が削減され、メンテナンスが向上しました。
  • 蒸留のためのコンテンツ選択の改善: 蒸留中に必要な QA ターンのみが読み取られるため、作業が軽減され、蒸留プロセスが高速化されます。

パフォーマンス

  • トレースの取り込みの高速化: セッション トレースのバックログを 1 つのドキュメントとして保持し、実行ごとにバックログを排出することで、データベースの書き込みとパイプラインのチャーンが減少し、アクティブなセッションのスループットが向上します。
  • 認識実行の削減: トレース パス ウィンドウを構築して 1 回の実行で処理することにより、パイプラインの呼び出しが減り、トレースからメモリへの変換にかかるエンドツーエンドの処理時間が短縮されます。
  • 埋め込み転送のオーバーヘッドの削減: Base64 埋め込みサポートにより、トランスポートの問題が軽減され、一部のプロバイダーとの互換性が向上し、よりスムーズな埋め込みフローが実現します。

セキュリティ

  • Slack への毎日の CVE アラート: 新しい GitHub アクション ジョブは、既知の CVE の毎日の概要を Slack に送信するため、保守者は脆弱な依存関係を追跡できます。
  • Google カレンダー コネクタの強化と共有 OAuth アダプター: 複数の修正により、Google 統合の堅牢性とエラー処理が向上し、OAuth 動作を一元化してセキュリティ リスクを軽減します。
  • 非表示の NATURAL_LANGUAGE 設定と修復ガイダンス: セキュリティに敏感なサーフェスが公開サーフェスから削除され、修復パスが設定されます。

バグ修正

  • 実行ごとにトレース バックログを排出する: 実行間でトレースが未処理のままになる可能性があるバグを修正しました。
  • 支払いエラー時のループの解除: 操作中に支払いエラーが発生した場合の無限ループのリスクに対処しました。
  • 禁止された ID などの古いセッション バインディングを拒否: 古くなった、または無効なセッションとデータセットのバインディングが一貫して拒否されるようになり、データのサイレント ミスルーティングが防止されます。
  • 蒸留に必要な QA ターンのみを読み取ります。蒸留中の不要な読み取りと潜在的なエラーを削減します。
  • 型指定されたエントリの文字列 dataset_id を受け入れ、型指定されたエントリをセッションのデータセットにルーティングします。一部のエントリがデータセットに正しくバインドされない問題を修正しました。

技術的な変更

  • memify、改善、認識パイプラインにわたる大規模な内部リファクタリングにより、タスク レジストリ、蒸留ステージ、グラフ変更操作を統合します。
  • 新しい評価ツール (Locomo) と多くのテスト/CI ワークフローの更新 (CVE アラートと最新ライブラリ チェックの新しいワークフローを含む)。
  • Azure マネージド ID サポートを追加し、Littellm client の動作と種類を強化しました。

依存関係の更新

  • リテルム: >=1.83.7、<1.97.0 → >=1.102.2、<2.0.0
