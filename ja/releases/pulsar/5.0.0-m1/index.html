#パルサーv5.0.0-M1

2026-06-23

Apache Pulsar 5.0.0-M1 は、Apache Pulsar 5.0.0 に向けた最初のマイルストーン リリースであり、一般提供は 2026 年後半になる予定です。これは プレビュー です。5.0 の主要な新機能を手に入れることができる初期のビルドであり、実際のワークロードに対して試して、GA リリースに先立ってフィードバックを送信できます。 実稼働用ではありません。 2 つの変更点が際立っています。スケーラブル トピック (自動的に拡大および縮小する新しいトピック タイプ)、Oxia の Pulsar 推奨メタデータ ストアへの昇格、およびビルド システムの Gradle への移行、IO コネクタの別のリポジトリへの分割、および構造化ログです。

完全なウォークスルーについては、発表を参照してください: Apache Pulsar 5.0.0-M1: 次のメジャー リリースのプレビュー。

ハイライト

スケーラブル トピック (トピック v5)。 固定パーティションを範囲ベースの セグメント に置き換える新しいトピック タイプ。そのため、キーごとの順序を維持しながら、セグメントを透過的に分割および結合することでトピックをスケールアップおよびスケールダウンできます。これにより、通常のパーティション化されたトピックのパーティション数の変更によって生じる順序の乱れや操作上のずれが回避されます。この作業は、ブローカー側コントローラー (PIP-468)、メタデータ駆動型トランザクション (PIP-473)、通常トピックからスケーラブルなトピックへの移行 (PIP-475)、および自動分割/マージ (PIP-483) に及びます。 PIP-460 を参照してください。

新しい V5 Java client API。 スケーラブルなトピック用に特化された白紙の client API。新しい追加の pulsar-client-v5 モジュールとして出荷されます。既存の pulsar-client モジュールと pulsar-client-api モジュールは変更されていないため、現在のアプリケーションは引き続き動作します。これは、従来の Consumer/Reader と 4 つのサブスクリプション タイプを 3 つの専用コンシューマ、すなわち QueueConsumer (デッドレター サポートを備えた並列で個別に確認応答されるワーク キューの消費)、StreamConsumer (順序付けされた累積 ACK)、および CheckpointConsumer (独自の位置を追跡する Flink や Spark などのストリーム プロセッサ用) に置き換えます。 V5 client は、既存のパーティション化されたトピックとパーティション化されていないトピックに対しても機能し、コンシューマーは名前空間全体をサブスクライブできます。 M1 では Java 用に出荷されます。他の言語の SDK は GA の前に続きます。 PIP-466 を参照してください。

Oxia が推奨メタデータ ストアになりました。 Oxia は、5.0 の新しい Pulsar クラスターの推奨メタデータ ストアになり、ストリーミング監視セッションに基づいてルックアップが構築される、スケーラブルなトピックに最適なバックエンドです。 ZooKeeper は引き続き完全にサポートされており、PIP-454 は、データ プレーンが公開および消費し続けている間に、既存のクラスターを ZooKeeper から Oxia に移動する、ライブのゼロ ダウンタイム移行フレームワークを追加します。

ビルド システムは Maven から Gradle に移行されました。 ビルドでは、ローカルおよび CI のビルド時間を大幅に短縮するタスク レベルのキャッシュと並列処理、および依存関係管理のための中央バージョン カタログ (gradle/libs.versions.toml) を備えた mvn ではなく ./gradlew が使用されるようになりました。移行は、公開された Maven アーティファクト、Docker イメージ、およびシェーディングされた client JAR を使用するユーザーに対して透過的です。 PIP-463 を参照してください。

IO コネクタは別のリポジトリに分割されました。 組み込みの Pulsar IO コネクタはコア リポジトリの外に移動され、独自のリリース リズムに従うことができます。 PIP-465 を参照してください。 構造化ログ。 Pulsar は、フラットな JSON / OpenTelemetry ログ出力と形式を簡単に切り替えるための PULSAR_LOG_FORMAT 環境変数を使用して、ブローカー、client、管理対象台帳、関数、およびメタデータ モジュール全体で slog を通じて構造化ログを出力するようになりました。 PIP-467 を参照してください。

API とプラットフォームの最新化。 Pulsar は javax.* から jakarta.* API (PIP-472) に移行し、Protobuf v4 をデフォルトにし、REST API アノテーションを Swagger から OpenAPI 3 に移行し、Java 25 での構築と実行をサポートするようになりました。トピック ポリシーを取得しました。レガシー対応の、メタデータ ストアを利用したルーティング バックエンド (PIP-469)。

セキュリティと依存関係の更新。 このリリースには、Netty、Jetty、log4j、BouncyCastle、Thrift、vert.x、および async-http-client にわたる多数の CVE に対処する大規模な依存関係アップグレード セットがバンドルされており、BookKeeper が 4.18.0 にアップグレードされます。以下の ライブラリの更新 を参照してください。

重要なお知らせ

5.0.0-M1 は、非推奨の機能を削除し、一部の API を変更するメジャー リリースです。アップグレードする前に次の点を確認してください。

  • javax.* → jakarta.* 移行 (PIP-472)。 javax.* パッケージ (javax.ws.rs や javax.servlet など) を参照するカスタム ブローカー プラグイン、インターセプター、認証/認可プロバイダー、またはその他の拡張機能は、対応する jakarta.* パッケージに更新して再コンパイルする必要があります。
  • Etcd メタデータ ストア バックエンドが削除されました (PIP-462)。 Etcd をメタデータ ストアとして使用するデプロイメントは、アップグレードする前に ZooKeeper または Oxia に移行する必要があります。
  • IO コネクタは別のリポジトリ (PIP-465) に移動されました。 コネクタはコア Pulsar リポジトリからリリースされなくなりました。専用コネクタ プロジェクトから入手してください。
  • ビルド システムは Gradle (PIP-463) になりました。 Pulsar をソースからビルドする場合は、mvn の代わりに ./gradlew を使用してください。公開された成果物は変更されません。
  • fastutil 依存関係が削除されました (#25413)。
