重大な変更

  • JUL (java.util.logging) 構成はサーバー側コンポーネントに対して有効ではなくなりました (#26330)

    以前は、JUL を使用するサードパーティ ライブラリ (Jersey/Jetty、gRPC、Guava など) からのログは Pulsar の Log4j2 構成では管理されなかったため、制御が難しくなり、ログ出力の一貫性が失われていました。これを解決するために、サードパーティ ライブラリのログが log4j-jul を介して JUL から Log4j2 にブリッジされるようになりました。これにより、すべてのログが conf/log4j2.yaml の下に統合されますが、次の JUL API と構成は 有効ではなくなります。

    • -Djava.util.logging.config.file=logging.properties — JUL 構成ファイル全体が無視されます
    • java.util.logging.Logger.setLevel() / addHandler() — ノーオペレーションになる
    • java.util.logging.LogManager.reset() — ノーオペレーションになります

    移行: JUL ベースのログ構成を conf/log4j2.yaml に移動します。たとえば、以前に logging.properties で io.grpc.level=SEVERE として構成されていた gRPC ログを抑制するには、conf/log4j2.yaml に次の行を追加します。

    Loggers:
  Logger:
    - name: io.grpc
      level: error

    元に戻す: 標準の JUL 動作を復元するには、次のように設定します。

    PULSAR_EXTRA_OPTS="-Djava.util.logging.manager=java.util.logging.LogManager"
