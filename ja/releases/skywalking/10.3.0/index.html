BanyanDB ストレージ オプションは大規模対応可能です

BanyanDB は、SkyWalking のユースケースに完全に焦点を当てたネイティブ構築の SkyWalking データベースです。 BanyanDB は、パフォーマンスの向上とリソース使用率の最適化において大きな可能性を示します。 1 秒あたり約 200 のサービスと 200 以上のコールを伴う一般的な導入シナリオでは、それぞれ 4 vCPU と 8 GB メモリを搭載した 2 つのリエゾン ノードと 2 つのデータ ノードで構成されたクラスターが、安定した効率的なパフォーマンスを実現します。 BanyanDB は完全なトレース サンプリングもサポートしており、最大 100% のトレース収集機能を提供し、システムの安定性を損なうことなく包括的な可観測性を確保します。

BanyanDB の新しいトレース モデル

BanyanDB 0.9.0 のトレース モデル実装を最適化し、OAP と BanyanDB 間のクエリ頻度を大幅に削減しました。 最新のクエリ機能に基づいた新しいクエリ ビューが導入され、ページの遅延が大幅に短縮されました。

プロジェクト

  • BanyanDB の依存関係バージョン (サーバーと java-client) を 0.9.0 に引き上げました。
  • CVE-2025-54057 を修正し、ウィジェットの URL を制限および検証します。
  • MetricsPersistentWorker を修正し、Hour/Day ディメンション メトリックの永続プロセスから DataCarrier キューを削除します。 これは、メモリ コストを削減し、Hour/Day メトリクスの永続的な遅延を削減するために重要です。
  • [重大な変更] BanyanDB: 新しい Trace モデルをサポート。

OAP サーバー

  • OAPサーバー経由でBanyanDBの自己監視を実装します。
  • BanyanDB: hot/warm/cold ステージ構成をサポートします。
  • ポリシーがすでにキャッシュ内にある場合に、クエリがプロファイリング ポリシーを続行するエラーを修正しました。 *ステータスAPIおよびgraphQL APIでhot/warm/coldステージTTLクエリをサポートします。
  • PromQL サービス: トラフィック クエリは limit と正規表現の一致をサポートします。
  • HashCodeSelector のエッジ ケースを修正しました (Integer#MIN_VALUE により ArrayIndexOutOfBoundsException が発生します)。
  • フリンク監視をサポートします。
  • BanyanDB: メジャー タグの @ShardingKey をサポートします。
  • BanyanDB: メトリクス/トレース/ログのコールド ステージ データ クエリをサポートします。
  • メッセージ キューのアイドル チェック間隔を 200 ミリ秒に増やし、低負荷条件下での CPU 使用率を削減します。
  • Istio ServiceEntry の DNS 解決の最大試行回数を 3 に制限し、DNS がまったく解決できない場合には最初の解決結果を待ちません。
  • Envoy ALS 受信機での分析ウェイポイント メトリクスをサポートします。
  • トポロジーに Ztunnel コンポーネントを追加します。
  • [Break Change] K8SServiceRelation スコープの componentId を componentIds に変更します。
  • eBPF アクセス ログ レシーバーでアンビエント メッシュが検出された場合は、メッシュ メトリックを調整します。
  • /debugging/config/dump ステータス API に対する JSON 形式のサポートを追加します。
  • ステータス API を拡張して、複数の accept ヘッダー値をサポートします。 Accept: application/json; charset=utf-8。
  • ストレージ: SkyWalking トレースと Zipkin トレース用に個別の SpanAttachedEventRecord。
  • [重大な変更]BanyanDB: 新しいグループ ポリシーをセットアップします。
  • commons-beanutils を 1.11.0 にバンプアップします。
  • リファクタリング: Accept http ヘッダー プロセスを簡素化します。
  • [重大な変更] ストレージ: event をメトリクスからレコードに移動します。
  • ZZPH100​​ZZ client の Jackson デシリアライザーの文字列制限を削除します。
  • disable.oal が動作しない問題を修正しました。
  • e2e PHP テストの安定性を強化し、PHP エージェントのバージョンを更新します。
  • dameng JDBC ドライバーのコンポーネント ID を追加します。
  • BanyanDB: ファイル bydb-topn.yml でのカスタム TopN pre-aggregation ルール構成をサポートします。
  • リファクタリング: 拡張性のために SPI を使用して OTEL ハンドラーを実装します。
  • 雑用: StorageID の toString 実装を追加。
  • 雑用: ES への接続に時間がかかりすぎる場合の警告ログを追加します。
  • メタデータ API のクエリ時間範囲を修正しました。
  • OAP gRPC ～ Cli は Health Check をサポートします。
  • [重大な変更] health_check_xx メトリクスでは、応答 1 は正常を表し、0 は異常を表します。
  • grpc を 1.70.0 にバンプアップします。
  • BanyanDB: 新しいインデックス ルール タイプ SKIPPING/TREE をサポートし、レコード log の trace_id IndexType を SKIPPING に更新します。
  • BanyanDB: タグ設定から index-only を削除します。
  • ES ストレージでの分析トレース プロファイリング スパンの失敗を修正。
  • Ruby ランタイム メトリクス用の UI ダッシュボードを追加します。
  • クエリ実行のトレース HTTP API: 引数 service layer をオプションにします。
  • GraphQL API: メタデータ、トポロジ、ログ、トレースは名前によるクエリをサポートします。
  • [Break Change] MQE 関数 sort_values は、単純な時系列値ではなく、集計結果とラベルに従ってソートします。
  • 自己観測性: OAP サーバーの metrics_aggregation_queue_used_percentage および metrics_persistent_collection_cached_size メトリックを追加します。
  • メトリクス集約/永続ワーカーを最適化: OAL ワーカーと MAL ワーカーを分離し、プールを消費します。データフロー信号は新しい MAL コンシューマを駆動し、 次の表は、各ワーカーのプール サイズ、駆動モード、キュー サイズを示しています。

  • commons-lang を 3.18.0 に引き上げます。
  • BanyanDB: 基本認証のグループ replicas および user/password をサポートします。
  • BanyanDB: Zipkin クエリで欠落していたタグ QUERY を修正。
  • IllegalArgumentException: Incorrect number of labels、LogReportServiceHTTPHandler および LogReportServiceGrpcHandler のタグが LogHandler と矛盾しているのを修正。

  • BanyanDB: indexModel 以外のモデルの場合にのみ、BanyanDBMetricsDAO が scan all blocks 情報ログを出力するようにしました。
  • BanyanDB: IndexMode で正しく動作しない BanyanDBMetricsDAO.multiGet を修正。
  • BanyanDB: @StoreIDAsTag を削除し、IndexMode の SeriesID に対して仮想文字列タグ id を自動的に作成します。
  • StorageID からメソッド appendMutant を削除します。
  • otlp ログ ハンドラーの応答エラーと otlp スパン変換エラーを修正しました。
  • mq エントリ スパン分析の service_relation ソース層を修正。
  • ブール修飾子を使用した promql でのメトリクス比較を修正。
  • Zipkin トレース レシーバーにレート リミッターを追加して、1 秒あたりの最大スパンを制限します。
  • 最新の UI 変更により、デフォルトで health-checker モジュールが開きます。デフォルトのチェック期間を 30 秒に変更します。
  • ノードの準備状況をより正確にするために、Kubernetes コーディネーターをリファクタリングします。
  • netty を 4.2.5.Final にバンプアップします。
  • BanyanDB: ログ クエリで条件による順序が欠落している問題を修正し、インスタンス ID またはエンドポイント ID でクエリを実行するときにサービス ID 条件が欠落している問題を修正しました。
  • AlarmStatusQueryHandler の潜在的な NPE を修正。
  • サービス ディメンションごとに上位 N 低速 SQL を集計します。
  • BanyanDB: BanyanDB グループのグループ プレフィックス (名前空間) の追加をサポートします。
  • BanyanDB: @BanyanDB.TimestampColumn を設定すると、列にインデックスが付けられなくなる問題を修正しました。
  • OAP 自己観測性: トレース分析メトリクスをラベル protocol ごとに分離し、Zipkin スパン ドロップ メトリクスを追加します。
  • BanyanDB: データ書き込みロジックを BanyanDB Java Client から OAP に移動し、書き込み操作の監視メトリクスをサポートします。
  • 自己観測性: BanyanDB と ElasticSearch の書き込みレイテンシー メトリックを追加します。
  • L2 集約ワーカーの不明なメタデータによる MAL メトリクスのアラーム機能の誤動作を修正しました。
  • MAL パーセンタイルを OAL パーセンタイル計算と一致させます。
  • OAP 可観測性のために Grafana ダッシュボードを更新します。
  • BanyanDB: インスタンス ID によるクエリ getInstance を修正。
  • go エージェント (0.7.0 リリース) にバンドルされている pprof プロファイリング機能をサポートします。
  • サービスおよび TCPService ソースのサポートは、TLS モードを分析します。
  • Library-pprof-parser: 特技: PprofSegmentParser を追加します。
  • ストレージ: 特技: languageType 列を ProfileThreadSnapshotRecord に追加します。

  • アラーム実行ステータスの取得: クラスター全体の実行ステータスのクエリをサポートします。

  • より短いカスタム期間のオプションを追加することで、非同期プロファイリングを強化します。
  • トレース プロファイリングでの分析に間違ったスパンを選択する問題を修正しました。
  • トレース グラフの凡例のサービス リストを修正。
