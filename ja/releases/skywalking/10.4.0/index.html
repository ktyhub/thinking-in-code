プロジェクト

  • OAL V2 エンジンの導入:
    • スレッドの安全性と予測可能な動作を実現する不変の AST モデル
    • 文字列ベースのフィルター演算子を置き換えるタイプセーフな列挙型
    • ファイル、行、列番号による正確なエラー位置レポート
    • 解析フェーズとコード生成フェーズを明確に分離
    • 解析せずに構築できるモデルによるテスト容易性の強化
  • MAL/LAL/Hierarchy V2 エンジンの導入 — Groovy ベースの DSL ランタイムを ANTLR4 パーサー + Javassist バイトコード生成に置き換えます。
    • OAP バックエンドから Groovy ランタイム依存関係を削除する
    • 起動時のフェイルファストコンパイル — 構文エラーと型エラーは、最初の実行時ではなく即座に捕捉されます。
    • ThreadLocal または共有可変状態のない、スレッドセーフに生成されたクラス
    • 3 つすべての DSL (MAL、LAL、階層ルール) の不変 AST モデル
    • 明示的なコンテキストの受け渡しが Groovy バインディング/クロージャ キャプチャに置き換わります
    • v1 (Groovy) および v2 (ANTLR4+Javassist) クロスバージョン チェッカーは、1,290 以上の式にわたる動作の等価性を検証します。
    • JMH ベンチマークにより、v2 のランタイムの高速化が確認されました。Groovy v1 と比べて、MAL 実行は最大 6.8 倍、LAL コンパイルは最大 39 倍 / 実行は最大 2.8 倍、階層実行は最大 2.6 倍高速になります。
    • 生成されたクラス名は、スタック トレースのトレーサビリティのために、すべての DSL (MAL/LAL/階層) の {yamlFileName}_L{lineNo}_{ruleName} パターンに従います。
  • 重大な変更 — LAL: slowSql {} および sampledTrace {} サブ DSL を文法から削除します。これらは、構成可能な outputType メカニズムによって置き換えられます。
    • YAML config のルール レベルで outputType を設定し、出力エンティティ クラスを指定します。 LALOutputBuilder SPI によって登録された短縮名 (outputType: SlowSQL、outputType: SampledTrace など)、またはフォールバックとして完全修飾クラス名を使用します。
    • LALOutputBuilder 実装は ServiceLoader 経由で検出され、短縮名解決のための name() メソッドを公開します。内蔵タイプ：SlowSQL（DatabaseSlowStatementBuilder）、SampledTrace（SampledTraceBuilder）。
    • 出力フィールド (id、statement、latency など) は、抽出ブロック内の通常のフィールド割り当てになり、サブ DSL ブロックにラップされなくなりました。
    • カスタム出力フィールドは、コンパイル時に出力型のセッターに対して検証されます。
    • データを永続化するには、明示的な sink {} ブロックが必須になりました。 sink {} がない場合、データは保存されません。これは、outputType を使用するルールを含むすべての LAL ルールに適用されます。 v1 では、slowSql {} および sampledTrace {} はエクストラクター内の副作用としてデータをディスパッチしました。 v2 では、永続性は常にシンク パイプラインによって処理されます。
    • 出力タイプの解決順序: ルールごと YAML outputType (SPI または FQCN による短縮名) > LALSourceTypeProvider SPI デフォルト > Log.class。
    • バンドルされているすべての LAL スクリプト (mysql-slowsql.yaml、pgsql-slowsql.yaml、redis-slowsql.yaml、envoy-als.yaml、k8s-service.yaml、mesh-dp.yaml) が更新されました。
    • slowSql {} または sampledTrace {} を使用するカスタム LAL スクリプトを使用するユーザーは、新しい構文に移行する必要があります。 LAL ドキュメント を参照してください。
    • ExtractorSpec の名前を MetricExtractor に変更 - LAL metrics {} ブロックのみを処理するようになりました。標準フィールド セッター (サービス、レイヤー、タイムスタンプなど) は、出力ビルダー上で直接セッター呼び出しとしてコンパイルされます。
  • LAL エクストラクター (およびフィルター レベル) に def ローカル変数サポートを追加します。文字列、マップ、protobuf Struct を Gson JSON オブジェクトに変換するための toJson() および toJsonArray() 組み込み関数をサポートします。変数は、null セーフ ナビゲーション (?.)、コンパイル時の型推論によるメソッド チェーン、および as (組み込み型または完全修飾クラス名、例: def resp = parsed?.response as io.envoyproxy.envoy.data.accesslog.v3.HTTPResponseProperties) を介した明示的な型キャストをサポートします。
    • 重大な変更 — LALOutputBuilder.init() シグネチャが init(LogData, NamingControl) から init(LogData, Optional<Object> extraLog, NamingControl) に変更されました。 extraLog パラメーターは、出力ビルダーがプロトコル固有のフィールドにアクセスできるように、型指定された入力オブジェクト (たとえば、エンボイ アクセス ログの HTTPAccessLogEntry) を運びます。カスタム LALOutputBuilder 実装は、init() メソッド シグネチャを更新する必要があります。

  • E2E テスト メトリクスの検証を修正: メトリクスの値がすべて null の場合に失敗するようにしました。

  • Java 25 でのビルド、テスト、公開をサポートします。

  • プロジェクトの AI アシスタント ガイドとして CLAUDE.md を追加します。

  • JDK 25 動的エージェント読み込み警告を回避するには、Byte Buddy を 1.18.7 にアップグレードし、Surefire で Mockito/Byte Buddy に対して明示的な -javaagent を構成します。

  • OAP バックエンドで Groovy を 5.0.3 にアップグレードします。

  • 最新の UI(booster-ui) コンパイルのために、nodejs を v24.13.0 にバンプアップします。

  • Elasticsearch 7.x (EOL) と OpenSearch 1.x を E2E テストから削除し、すべての ES テストを 8.18.8 にアップグレードし、ECK 8.18.8 を使用するように skywalking-helm を更新します。

  • library-batch-queue モジュールを追加 - タイプベースのディスパッチを備えたパーティション化されたセルフドレイン キュー。 適応型パーティショニング、アイドル バックオフ、およびスループット加重ドレイン リバランス (DrainBalancer)。 高ファンアウト シナリオで DataCarrier を置き換えるように設計されています。

  • L1 メトリクスの集約、L2 メトリクスの永続性、TopN の永続性については、DataCarrier を BatchQueue に置き換えます。 3 つのエクスポーター (gRPC メトリクス、Kafka トレース、Kafka ログ) すべて、および gRPC リモート client。 すべてのメトリック タイプ (OAL + MAL) は、個別の OAL/MAL プールではなく統合キューを共有するようになりました。 各エクスポーターは 1 つのスレッドを持つ独自の専用キューを保持し、元のバッファー戦略を維持します。 8 コア マシンでのスレッド数の比較 (gRPC リモート client は除外 - ピアごとに 1 スレッドは変更なし):

  • L1 アグリゲーションおよび L2 永続キューのスループット加重ドレイン リバランスを有効にします (10 秒間隔)。 メトリック タイプのスループットに偏りがある場合、ドレイン スレッド間でパーティションを定期的に再割り当てし、負荷を均等化します。

  • Kind ベースの Kubernetes 環境、自動スレッド ダンプを備えた benchmarks/ の下にベンチマーク フレームワークを追加 収集と分析。最初のケース: istio-cluster_oap-banyandb 環境の thread-analysis。

  • netty を 4.2.10.Final にバンプアップします。

  • log4j を 2.25.3 に、jackson を 2.18.5 にバンプアップします。

  • PowerMock 依存関係を削除します。 JDK 25+ をサポートするには、すべてのモジュールで Whitebox を ReflectUtil (標準 Java リフレクション + 最終フィールドの sun.misc.Unsafe) に置き換えます。

  • MAL 構成から initExp を削除します。これは内部の Groovy 起動検証メカニズムであり、エンドユーザーの機能ではありませんでした。 v2 ANTLR4 コンパイラは、起動時にフェールファスト検証をネイティブに実行します。

  • 階層ルールのドキュメントを更新: hierarchy-definition.yml の auto-matching-rules は Groovy スクリプトを使用しなくなりました。ルールでは、プロパティ アクセス、文字列メソッド、if/else、比較、論理演算子をサポートする専用の式文法が使用されるようになりました。出荷されたすべてのルールは完全に互換性があります。

  • デフォルトでは、receiver-otel で otlp-traces ハンドラーを有効にします。

  • Istio E2E テスト バージョンを更新: EOL 1.20.0 を削除し、ALS/メトリクス/アンビエント テスト用に 1.25.0 ～ 1.29.0 を追加します。 Istio プロセス テストを使用して Rover を 1.15.0 から Kubernetes 1.28 を使用した 1.28.0 に更新します。

  • Virtual-GenAI モニタリングをサポートします。

  • 無効な DateTimeFormatter パターンを ISO_OFFSET_DATE_TIME に置き換えることにより、オンデマンド ポッド ログの解析エラーを修正しました。
