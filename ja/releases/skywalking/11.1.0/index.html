OTLP トレースからのメトリクスとトポロジ

OpenTelemetry SDK を搭載したアプリケーションでは、サービス ダッシュボード、トポロジ、トレース検索に SkyWalking エージェントが必要なくなりました。 OAP は、到着した OTLP トレースを保存し、新しい Trace Analysis Language (TAL) は、すべてのスパンをサービス、インスタンス、エンドポイントのメトリック、トポロジ、およびサービスが呼び出すデータベース、キャッシュ、メッセージ キューのダッシュボードに変換します。 OpenTelemetry 天文学ショップを 1 つのコマンドでクイック スタートするには、OpenTelemetry Traces in SkyWalking を参照してください。

  • チャネルを使用した RabbitMQ ノード パブリッシャー数からチャネル コンシューマを引いた数を修正しました。 meter_rabbitmq_node_publisher_total は、パブリッシャではなくコンシューマのないチャネルをカウントする rabbitmq_channels - rabbitmq_channel_consumers を計算しました。basic.get ポーリング チャネルはパブリッシャとしてカウントされ、パブリッシュとコンシュームの両方を行うチャネルはカウントされず、複数のコンシューマが含まれるチャネルは値を 0 未満にし、0 として保存されました。これで rabbitmq_global_publishers が読み取られ、RabbitMQ はこれを 3.10.11 と 3.11.3 から正しくカウントします。アップグレード前に保存された値は古い数値を保持しているため、このグラフはアップグレードの段階にあります。
  • MySQL connection-errors-for-max-connections で誤って入力されたエクスポータ ラベルを読み取る問題を修正。 meter_mysql_connection_errors_max_connections / meter_mysql_instance_connection_errors_max_connections は error=max_connection をフィルタリングしますが、mysqld_exporter は Connection_errors_max_connections を error=max_connections として公開するため、ライブ スクレイピングは一致せず、チャートは空のままです。フィルターは max_connections を使用するようになりました。
  • サーバー クラスター server-clusters.yml とその動的構成アイテム core.default.serverClusters を追加して、client が複数のアドレスに到達するメッセージ ブローカー、データベース、またはキャッシュを 1 つのサービスとして表示します。クラスターの members または aliases の下にリストされているアドレス、または Kafka client のブートストラップ サーバーなど、すべての要素が 1 つのクラスターの下に任意の順序でリストされているアドレスのリストは、ネットワーク エイリアスがアドレスをマップしないネイティブ トレース分析と、出荷された新しい TAL 関数 findServerClusterName を介した OpenTelemetry トレース分析によってクラスターに名前変更されます。 tal/otlp-general.yaml はブローカー、データベース、キャッシュを呼び出します。クラスターは、pulsar:// や kinds など、その種類のクラスターにのみ一致するカスタム TAL ルールが findServerClusterName(address, kind) として渡されるようにユーザーが選択した名前である、pulsar:// や kinds などのアドレスの前に、その clients が書き込む scheme を宣言できます。ネイティブ トレース分析と付属の TAL ルールでは種類は使用されません。ファイルはデフォルトでは空であるため、クラスターがリストされるまで名前は変更されません。
  • 出荷された OAP jar の CVE アラートをクリアするためのバンプ依存関係: jackson 2.18.8 → 2.18.12、guava 32.0.1-jre → 33.7.2-jre、マイクロメーター 1.14.4 → 1.16.8、log4j 2.25.4 → 2.25.5、freemarker 2.3.31 → 2.3.35、およびpostgresql 42.7.11 → 42.7.14。マイクロメーター 1.14.x にはオープンソースの修正がなく、Armeria 1.34.2 は古いピンがダウングレードしたマイクロメーター 1.16.0 に対して構築されています。
  • バージョンが BOM または推移的な依存関係から取得されているため、依存関係をバンプして、Dependabot が認識しない出荷済みの OAP jar の CVE をクリアします: netty 4.2.15.Final → 4.2.19.Final (netty-tcnative-boringssl-static 2.0.77.Final → 2.0.84.Final では、バージョン netty 4.2.19.Final がビルドされます) with)、そして、kafka-clients によって引き込まれた、lz4-java 1.10.1 → 1.11.4 および snappy-java 1.1.10.5 → 1.1.10.12。
  • HTTP アラーム フック配信の自己観測性メトリクス、alarm_http_delivery_total、alarm_http_delivery_status_total、および alarm_http_delivery_latency_seconds を telemetry.prometheus に追加し、hook_type および result または status_class というラベルが付けられます。 result は、配信が失敗した理由 (auth_failed、rate_limited、rejected、server_error、token_error、timeout、io_error、interrupted) を指定し、2xx 本文で返されるエラー コード DingTalk、WeCom、Feishu、WeLink を読み取るため、このような拒否されたメッセージは失敗として記録されるようになりました。納品どおりに渡すのではなく。トークンのない WeLink アクセス トークン応答は、空のトークンを使用して送信するのではなく、その Webhook URL のメッセージをスキップするようになりました。 otel-rules/oap.yaml ルールは、meter_oap_instance_alarm_http_delivery_count、meter_oap_instance_alarm_http_delivery_status_count、および meter_oap_instance_alarm_http_delivery_latency_percentile を OAP 自己観測レイヤーに追加し、OAP Grafana ダッシュボードは生のシリーズをグラフ化します。
