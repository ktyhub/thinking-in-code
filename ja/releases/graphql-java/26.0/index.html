グラフql-java v26.0

これは、graphql-java の 26.0 リリースです。ハイライトを以下にまとめます。マージされた PR の完全なリストは最後にあります。

⚠️重大な変更

クエリの複雑さの制限がデフォルトで適用されるようになりました

新しい QueryComplexityLimits 検証では、標準検証の一部として maxDepth (デフォルト 100) および maxFieldsCount (デフォルト 100,000) がチェックされます。これらの制限を超えるクエリは、新しい MaxQueryDepthExceeded / MaxQueryFieldsExceeded 検証エラーで失敗するようになります。

  • QueryComplexityLimits.KEY を使用して、GraphQLContext 経由でカスタム制限を設定します。
  • QueryComplexityLimits.NONE で完全に無効にします。

#4256で紹介されました。

検証ルールのフィルタリング API が変更されました

#4228 では、Validator.validateDocument(...) および ParseAndValidate.parseAndValidate(...) のルール フィルター述語が Predicate<Class<?>> から Predicate<OperationValidationRule> に変更されました。クラスによってフィルター処理された呼び出し元 (例: rule -> rule != NoUnusedFragments.class) は、列挙型 (rule -> rule != OperationValidationRule.NO_UNUSED_FRAGMENTS) に移行する必要があります。 @Internal クラス AbstractRule および RulesVisitor は削除されました。

組み込みディレクティブ処理の統合 (#4229)

  • DirectiveInfo が削除されました。使用法を置き換えます:
    • DirectiveInfo.isGraphqlSpecifiedDirective(...) → Directives.isBuiltInDirective(...)
    • DirectiveInfo.GRAPHQL_SPECIFICATION_DIRECTIVES → Directives.BUILT_IN_DIRECTIVES
    • DirectiveInfo.GRAPHQL_SPECIFICATION_DIRECTIVE_MAP → Directives.BUILT_IN_DIRECTIVES_MAP
  • ディレクティブの順序が一貫しました。7 つの組み込みディレクティブがすべて最初に表示され、その後にユーザー定義のディレクティブが続きます。
  • GraphQLSchema.Builder.clearDirectives() は最初に削除され、その後 #4276 で新しいセマンティクスで再追加されました。これによりすべての additionalDirectives がクリアされますが、組み込みディレクティブは常にビルド時に自動的に再追加されます。

OneOf 居住可能性検証 (#4248)

新しいバリデーターは、有限値を入力できない OneOf 入力タイプ (例: input A @oneOf { a: A }) を拒否します。以前に検証されたスキーマは拒否される可能性があります。

コードで構築されたスキーマの非 null フィールド検証 (#4194)

コードで構築されたスキーマは、SDL で構築されたものと同じ、非推奨の非 null フィールド検証を実行するようになりました。ギャップに依存するスキーマは検証に失敗する可能性があります。

GraphQLSchema.getCodeRegistry() は @Nullable ではなくなりました (#4247)

戻り値の型に誤って null 許容の注釈が付けられました。呼び出し側は冗長な null チェックを削除できるようになりました。ダウンストリームの nullness ツールには変更が反映されます。

JSpecify null 可能性アノテーションが広く展開されました

ウェーブ 2 と 3 (#4184、#4274) に加え、多くの個別の PR が、graphql.analysis、graphql.execution、graphql.language、graphql.schema などの数百のクラスに @NullMarked/@NullUnmarked/@Nullable の注釈を付けました。 Kotlin およびその他の null 認識呼び出し元には、より厳密な null 可能性コントラクトが表示されるようになります。以前は許可されていた署名に依存していたコードは調整が必要になる場合があります。

✨ 新機能

  • GraphQLSchema.FastBuilder (#4197) — より制限的ですが、~5 倍高速なスキーマ ビルダーで、大規模なスキーマの時間とメモリの両方を削減します。
  • クエリの複雑さの制限 (#4256) — 深さ/フィールド数のガードレールが検証に組み込まれました (強制側については、上記の重大な変更を参照してください)。
  • 操作およびドキュメントに関する QueryAppliedDirective (#4297) — 操作/ドキュメント レベルで適用されるディレクティブが QueryAppliedDirective として公開されるようになりました。
  • 例外処理後の結果のための新しいインストルメンテーション フック (#4206、#4207) - DataFetcherExceptionHandler が例外をエラーにマップした後の DataFetcherResult を観察します。 ChainedInstrumentation は新しいフックを正しく委任します。
  • 汎用 DataFetcherResult.newBuilder(T data) (#4254) - 共通の DataFetcherResult.<T>newResult().data(x)... パターンに関する明示的な型監視の必要性を排除します。
  • GraphQLSchema.Builder.clearDirectives() を再追加 (#4276) — GraphQLSchema.transform で非組み込みディレクティブを書き直すのに便利です。組み込みは常に再追加されます。
  • AST 指令ホルダーの toString() (#4195)。

⚡ パフォーマンス

  • 増分 @defer 実行の開始が早くなります (#4174) - 最初の結果が完了するのを待つのではなく、最初の増分呼び出しが検出されるとすぐに、遅延ペイロードの処理を開始します。
  • 検証の統合 (#4228) - すべての操作検証ルールが単一の OperationValidator パスで実行され、検証のオーバーヘッドが大幅に削減されます。
  • 実行ホット パス上の割り当ての削減 (#4252):
    • Async$Many.materialisedList() — ArrayList コピーをゼロコピー Arrays.asList() ラッパーに置き換えました。
    • ResultPath.toStringValue — 遅延計算。文字列形式は最初の toString() に基づいてのみ構築されます (通常はエラー報告時のみ)。
    • 新しい GraphQLCodeRegistry.getDataFetcher(String, String, GraphQLFieldDefinition) オーバーロードにより、フェッチごとの FieldCoordinates 割り当てが回避されます (~54 KB/op 削減)。
  • FastBuilder スキーマ構築用 (#4197) — 「新機能」を参照してください。
  • 適用されたディレクティブ引数および列挙値定義内の型参照も解決するように ShallowTypeRefCollector を修正しました (#4288) — 正確性を修正し、FastBuilder をより多くのスキーマで使用できるようにしました。

🐛 その他の注目すべき変更点

実行/データ取得

  • 複数の @defer フラグメントを使用した DataLoader ディスパッチ (#4270) — 複数の遅延フラグメントが実行されているときに DataLoader が正しくディスパッチされなかった問題を修正します。
  • CompletionStageSubscriber 競合状態 (#4296) — 飛行中の CompletionStage が同時に解決された場合、完了信号が失われる可能性があります。修正は新しい jcstress ストレス テストによって裏付けられています。
  • 非パブリック クラスの PropertyDataFetcher (#4287) — パブリック インターフェイス (TreeMap.Entry など) を実装する非パブリック クラスのプロパティは、パブリック インターフェイスを検索することによって Java 16 以降で正しくフェッチされるようになりました。
  • ExecutableNormalizedField は GraphqlFieldVisibility を尊重します (#4204) — 選択セット API は、型に直接アクセスするのではなく、スキーマの設定された可視性を使用するようになりました。
  • ScheduledDataLoaderRegistry「すべてをディスパッチする」修正 (#4164)。
  • ChainedInstrumentation onExceptionHandled 代表団 (#4207)。

スキーマ/フィールドの可視性

  • 複雑なフィールド可視性トランスフォーマーのケースと、削除がカスケードする場合のスキーマ変換を修正しました (#4203、#4205、#4208、#4209、#4212、#4213、#4275)。
  • 重複フィールドの null 型回帰 が修正されました (#4291)。
  • GraphQLTypeCollectingVisitor は間接的な強参照を再帰的に走査するようになりました (#4213)。
  • SchemaTraverser::depthFirst オーバーロード署名の修正 (#4165)。

ビルド / パッケージ化 / セキュリティ

  • バイトコードで変更されたクラスは、公開された JAR には含まれなくなりました (#4343) — カバレッジ レポート用に挿入された @Generated アノテーションが、公開されたアーティファクトに漏洩していました。 JAR には、そのままのコンパイラ出力が含まれるようになりました。
  • トロイの木馬ソース/ガラスワーム Unicode 検出 (#4344) - コミット前フックと CI ワークフローは、ソース内の危険な BiDi/ゼロ幅/制御文字を拒否するようになりました。
  • Windows 互換性 (#4239) - performance-results/ ファイル名からコロンを削除し、特大の large-schema-5.graphqls を分割し、コミット前 + CI チェックを追加しました。

ツーリング/DX

  • getDataLoader タイプの境界が改善されました (#4180)。
  • Java 25 (#4173、#4330) でビルドしてテストします。
  • リリース全体にわたる多くの依存関係の更新 (Reactor、Jackson、Kotlin、Groovy、Gradle、ByteBuddy、errorprone など)。
