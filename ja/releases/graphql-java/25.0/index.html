グラフql-java v25.0

主要な変更点

データローダー

リファクタリング戦略

既存の PerLevelDataLoaderStrategy がリファクタリングされ、簡素化とパフォーマンスの向上につながりました。

新しい戦略

CHAINED と EXHAUSTED という 2 つの新しい戦略が導入されました。どちらも UnusalConfiguration 経由で設定できます (次のセクションを参照)。

CHAINED を使用すると、レベルごとのディスパッチ戦略を維持しながら、チェーンされた DataLoader を使用できます。

EXHAUSTED は、エンジンがビジー状態でなくなったらディスパッチするという、まったく新しい戦略です。これは JS データ ローダーのディスパッチ戦略を反映していますが、マルチスレッド システムを対象としています。

通常とは異なる構成

「異常な構成」のために、より一般化された構成メカニズムが追加されました。 これは、多くの人が使用することは想定されていないが、より一般的な場所で使用されるようになった場合の構成を意味します。

たとえば、ドキュメント パーサーが受け入れる最大の深さを変更したい場合は、次のメソッドを呼び出すことができます。

        var parserOptions = newParserOptions().maxRuleDepth(99).build()
        GraphQL.unusualConfiguration().parsing().setDefaultParserOptions(parserOptions)

J注釈の指定

チームは、null 値を許容するフィールドと null 値を許容しないフィールドを示す方法として https://jspecify.dev/ アノテーションを採用し始めています。 多くの重要なクラスには、値が null であるかどうかを意味的により明確にするために、これらの注釈が追加されています。

重大な変更

パフォーマンス上の理由から、ラッピング FetchedValue オブジェクトがフィールド フェッチャーで返されるとは限りません。 これは、graphql.execution.instrumentation.parameters.InstrumentationFieldCompleteParameters#getFetchedObject が古い getFetchedValue メソッドを置き換えるために作成され、返されるオブジェクトが FetchedValue である場合もあれば、単純な POJO 値である場合もあることを意味します。

パフォーマンスの向上

ライブラリのメモリ使用量を削減するために、一連のパフォーマンスの向上が行われました。 また、Java .stream() オペレーターは、より直接的なループよりも遅くなる可能性があり、これらの呼び出しの多くはパフォーマンス上の理由から変更されています。

  • https://github.com/graphql-java/graphql-java/pull/3943 の @samuelAndalon による CompletableFuture で実体化された fieldValueObject をラップするのを避ける
  • ExecutionStrategyParameters は、https://github.com/graphql-java/graphql-java/pull/3935 の @bbakerman により、ビルダーなしで直接変換できるようになりました。
  • ExecutionStepInfo は、https://github.com/graphql-java/graphql-java/pull/3934 の @bbakerman により、ビルダーなしで直接変換できるようになりました。
  • FpKit はパフォーマンス上の理由からストリームを使用しなくなりました (https://github.com/graphql-java/graphql-java/pull/3932 の @bbakerman による)
  • https://github.com/graphql-java/graphql-java/pull/3964 の @AlexandreCarlton による DataFetcherResult の toString/hashCode/equals の実装
  • https://github.com/graphql-java/graphql-java/pull/3931 の @bbakerman による .stream() 呼び出しを置き換えるフィルターとマップの命令型メソッドを導入
  • https://github.com/graphql-java/graphql-java/pull/3930 の @bbakerman によりパフォーマンス上の理由から、Optional.map() と .stream() の一部を削除
  • https://github.com/graphql-java/graphql-java/pull/3929 の @bbakerman により、オブジェクトまたはリスト フィールドごとに NonNullableFieldValidator の作成を停止する
