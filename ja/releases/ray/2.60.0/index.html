ray 2.60.0

#レイレイ-2.60.0

ハイライト

  • Ray データのシャッフルと Parquet の読み取り: この Ray リリースでは、シャッフル v2 が結合と集計のデフォルトのシャッフル戦略です (#66260)。 Parquet 読み取りでは、ファイル サイズから推定するのではなく、各ファイルのフッターの行グループ メタデータから読み取りタスクのサイズを決定するようになりました。そのため、読み取りタスクは正確なバイト バジェット (#65596、#65806、#65821) にパックされます。
  • Ray Serve ローリング アップデート: max_surge_percent を追加しました。max_surge_percent は古いレプリカを停止する前に置換レプリカを開始するため、ローリング アップデートによって処理能力が低下しません (#66267)。新しいレプリカが失敗し続けるローリング アップデートは、DEPLOY_FAILED で停止し、すべての正常なレプリカ (#66252、#66290) を置き換えるのではなく、残りの古いレプリカをルーティング可能なままにします。
  • セキュリティ: Ray Data は、外部入力から Arrow データを逆シリアル化するすべてのリーダーで pickle-object 列を拒否するようになり、LeRobot、Databricks、Iceberg、Hugging Face、ClickHouse、BigQuery、および Delta Sharing リーダーでのリモート コード実行パスを閉じます (#66042、#65769)。 eMudhra CA 侵害後のレイ イメージとホイール ビルドはピン certifi 2026.10.19 とピップ 26.2.2 で、aiohttp は CVE-2026-111064 および CVE-2026-111066 (#67295、#67298、#67301、#67304、 #67305、#67350)。

  • DataSourceV2 を再編成して、Parquet 以外のソースや、Iceberg などのカタログベースのソースをその上に構築できるようにします (#65908、#66244、#66066、#66312、#66357、#66390、#66398、#66450、#66478、#66497)

#レイサーブ

🎉 新機能

  • 列指向の自動スケーリング メトリクス。 ルーターは、デフォルトでピクル化された Python オブジェクトではなく、フラットな数値配列としてハンドル メトリック レポートを送信するようになり、コントローラーはそれらを 1 つのベクトル化パスにマージし、ハンドルあたり 64 ～ 4,096 個のレプリカでコントローラー ループ コストを 2.8 ～ 13.5 倍削減します。 RAY_SERVE_COLUMNAR_AUTOSCALING_METRICS=0 を元に戻すように設定します (#64281、#66104、#66105、#66070、#66240)。コントローラーの健全性スキーマは、各制御ループのどれだけがメトリクスの取り込みに費やされるのかも報告します (#66106)。
  • ローリング アップデートの急増。 新しい max_surge_percent 導入オプションは、古いレプリカを停止する前に新しいレプリカを開始し、ローリング アップデート中に容量をターゲットに維持します。デフォルトの 0 では、既存の停止してから開始する動作 (#66267) が維持されます。
  • パック スケジュールのためのノード圧縮。 RAY_SERVE_USE_PACK_SCHEDULING_STRATEGY=1 では、すべてのデプロイメントが安定すると、コントローラーが部分的に使用されているノードからレプリカを移行し、オートスケーラーがそのノードを解放できるようにします。元のノードを停止する前に置換を開始するため、容量が低下することはありません。 RAY_SERVE_NODE_COMPACTION_DELAY_S および関連設定 (#66108) で調整してください。
  • gRPC サーバー リフレクション。 grpcurl、grpcui、Postman などのツールは、ローカル プロト ファイルを使用せずに、gRPC プロキシ経由で Serve gRPC サービスを検出して呼び出すことができるようになりました。反射はデフォルトでオンになっており、gRPCOptions(enable_reflection=False) または --grpc-disable-reflection (#65854) で無効にすることができます。
  • 直接イングレスと RoundRobinRouter のモデル多重化。 直接イングレス展開は、HTTP と gRPC (#65678) の両方で多重化されたモデル ID を受け入れ、RoundRobinRouter は要求されたモデル (#65679) をすでにホストしているレプリカを優先します。
  • カスタム自動スケーリング ポリシーがベータ版に到達しました。 この機能は実験版 (#66058) から卒業し、新しいアルファ版 PrometheusQueryMixin では、PromQL クエリの結果をバックグラウンド スレッドで最新の状態に保つことでポリシーを Prometheus メトリクスに合わせてスケーリングできるため、ネットワーク呼び出しで読み取りがブロックされることはありません (#65884)。

💫 機能強化

  • 同期メソッドはデフォルトでスレッド プールで実行されます。 同期デプロイメント メソッドで同期 I/O をブロックしても、レプリカのイベント ループが停止することはなくなりました。共有状態がスレッドセーフではないデプロイメントでは、RAY_SERVE_RUN_SYNC_IN_THREADPOOL=0 (#66436) を使用して古い動作を復元できます。
  • ノンブロッキング _to_object_ref(). DeploymentResponse._to_object_ref() は、レプリカの結果を待つのではなく、リクエストがレプリカに割り当てられるとすぐに返されるようになりました (#65243)。
  • 失敗したローリング アップデートの安全性が向上しました。 ローリング アップデートが失敗した場合、すべての正常な古いレプリカを置き換えるのではなく、生き残っている古いレプリカがトラフィック (#66252) を処理し続け、更新は起動失敗しきい値で停止し、DEPLOY_FAILED のままになります (コントローラーの再起動後も含む)。 RAY_SERVE_STOP_FAILED_ROLLING_UPDATES=0 (#66290) でオプトアウトします。
  • 実稼働 HAProxy のデフォルト。 接続試行は 5 秒に制限され、ライブ トラフィックはヘルス チェックを待たずにデッド レプリカをダウンとしてマークするため、再試行はより早く正常なレプリカに到達します (#65729)。入力バッファは 256 KiB から 8 MiB に増加するため、ボディアウェア LLM ルーティングでは 100 万トークンのリクエストがすべて認識され、バッファ メモリの上限を設定するために maxconn が 20,000 から 4,096 に減少します (#66360)。
  • 正常な HAProxy レプリカ ドレイン。 登録解除ウィンドウが終了すると、HAProxy の背後にあるドレイン中の直接入力レプリカが HTTP リスナーを閉じるため、古い HAProxy ワーカーからの遅延リクエストは拒否され、飛行中に失敗するのではなく、別のレプリカで再試行されます。これにより、ステージング フリート (#65698) のスポット中断イベントごとに ~40 の client エラーが削除されました。
  • ノード プリエンプションでの正常なドレイン。 コントローラーは、Ray がドレインとしてマークしたノード (たとえば、ray start --block が SIGTERM を受信したとき) を認識するようになりました。そのため、Serve の既存のロジックは、実行中のリクエスト (#65502) を失敗させる代わりに、レプリカを移行し、ノードからプロキシします。
  • コントローラーのみのメトリック集約。 自動スケーリング メトリックは常にコントローラーで集約されるようになりました。これは、ソース間および max/min 集約に対して正しく行われます。 RAY_SERVE_AGGREGATE_METRICS_AT_CONTROLLER フラグが削除され、デフォルトでオフになっているため、デフォルトの動作が変更されます (#65714)。また、コントローラーは、スケーリング ログ行 (#64654) を書き込むためだけにリクエストを再集約することもなくなりました。

🔨修正

  • ASGI 準拠の root_path (破壊)。 root_path は、すべての入力モードで ASGI 仕様に従い、すべてのリクエスト (/-/healthz を含む) に対して 404 を返す直接入力と、プレフィックスを 2 回削除する HAProxy を修正しました。 uvicorn は 0.53 (最小 0.26) にアップグレードされます。 root_path プレフィックスを含むリクエストは 404 を返すようになったので、入力時にそれを削除するか、root_path (#66446) の設定を解除します。
  • jinja2 インポート回帰。 from ray import serve は、jinja2 なしのスリム イメージで失敗しなくなりました (2.57 回帰)。 jinja2 は遅延インポートされ、serve エクストラ (#65542) で宣言されるようになりました。
  • ルーティングで孤立したリクエスト。 ルーティング タスクは、所有するリクエストを割り当てるまで存続するようになりました。以前は、KVAwareRouter (#66325) などの完全一致ルーターでは、早期に終了するとリクエストが永久に待機したままになる可能性がありました。
  • 多重ルーティングの修正。 イングレス リクエスト ルーターを介したルーティングは、モデルの場所のメタデータが伝播する間 (#66170)、HTTP 503 を返す代わりに再試行するようになり、デッド レプリカが多重化モデル マップから削除されるため、リクエストをサイレントに保留する KeyError (#66358) が防止されます。
  • ギャングのスケジュール修正。 ギャングの共有配置グループは、まだサービスを提供していた兄弟を強制終了するのではなく (#66221)、最後のメンバーが停止した場合にのみ削除されるようになり、配置グループのリーク検出中に Ray 状態 API に到達できない場合でも、コントローラーが回復時にクラッシュしなくなりました (#66149)。
  • スケール トゥ ゼロのプロキシ ノードのリリース。 アプリケーションのレプリカが停止した後、イングレス リクエスト ルーター レプリカはプロキシ ノードを維持しなくなりました。そのため、スケール トゥ ゼロ アプリはノードを解放できます (#65824)。
  • 再デプロイとデプロイメント削除の修正。 以前のバージョンがまだ破棄されている間にデプロイメントを再デプロイしても、誤った DeploymentUnavailableError 拒否 (#66323) がトリガーされなくなりました。また、アプリケーション レベルの自動スケーリングを使用してアプリからデプロイメントを削除しても、アプリケーション制御ループを停止させる KeyError が発生しなくなりました。 (#66438)。
  • 構成オーバーライドの削除。 デプロイメントの構成からオプションを削除すると、古いオーバーライド (#66266) を保持するのではなく、コードで定義された値が復元されるようになりました。
  • クロック スキュー セーフなハンドル メトリック。 ハンドル メトリックの古さは、コントローラーがレポートを受信した時点から測定されるようになりました。そのため、ノード間のクロック スキューによって新しいメトリックが早期にドロップされたり、古いハンドルが生きたままになったりすることがなくなりました (#66307)。
  • プロキシ シャットダウン メトリック。 プロキシ シャットダウン期間メトリックは、停止したプロキシごとに記録されるようになり、単一の制御ループの反復 (#66151) ではなく、シャットダウン全体を測定します。
  • grpcio 登録メソッド ハンドラー。 gRPC プロキシは、以前は Serve のリクエスト ルーティング (#66502) をバイパスしていた、grpcio の新しい登録メソッド ハンドラー API を通じて登録されたサービスをルーティングするようになりました。

📖 ドキュメント

  • スタンドアロンで CLI ページを提供します。 serve CLI 参照は、他のライブラリの API 参照の構成方法と一致するように、独自のページに移動されました (#65943)。
  • metrics_interval_s 警告。 自動スケーリング ガイドでは、非常に低い値がコントローラーに過負荷をかける可能性があることを警告するようになり、例ではデフォルト (#65972) が使用されています。
  • ray.io/v1 の KubeRay の例。 Serve フォールト トレランス ガイドを含む例は ray.io/v1alpha1 から移行され、サポートされていない serveConfig フィールドを使用した (したがってデプロイされたアプリケーションがゼロだった) RayService の例が修正されました (#65336)。

🏗 アーキテクチャのリファクタリング:

  • 非同期推論キュー モニターを削除しました。 これにより、未使用の QueueMonitorActor、そのコントローラー側メトリック、および AutoscalingContext.total_pending_async_requests (常に 0) が削除されます。 AsyncInferenceAutoscalingPolicy はすでにブローカーを直接ポーリングしています (#66405)。
  • 完全な serve/_private 型チェック。 mypy と pyrefly は手動で管理されたファイル リストではなく serve/_private ツリー全体をスキャンするようになりました。そのため、新しいモジュールがデフォルトでカバーされます (#65653)。
  • テスト デフレーキング。 スパン ルーティング、メトリック、ギャング スケジューリング、直接入力、および展開テストを修正 (#65654、#65725、#65995、#65811、 #65836、#66000、#66037、#65664、#65822、#66059、 #66101、#66150、#66195、#66317、#66296、#66346、 #66071、#66395、#66206、#66455、#66482、#66495、 #66492、#67165);コントローラー ベンチマークではレプリカごとのメモリも予約されるようになったため、8,192 個のレプリカ チェックポイントが OOM キルにヒットしなくなります (#65847)。
