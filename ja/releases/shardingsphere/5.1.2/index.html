shardingsphere 5.1.2

パッチ 公開日2022年6月17日 出典apache/shardingsphere 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#シャーディングスフィア5.1.2

新機能

  1. カーネル: MySQL および PostgreSQL の SQL 方言変換をサポートするアルファ バージョン
  2. カーネル: PostgreSQL および openGauss のカスタム スキーマをサポート
  3. カーネル: PostgreSQL および openGauss の create/alter/drop view ステートメントをサポート
  4. カーネル: openGauss カーソル ステートメントをサポート
  5. カーネル: システム データベースのカスタマイズの使用をサポート
  6. カーネル: get openGauss および MySQL create SQL をサポート
  7. カーネル: get postgres create SQL をサポート
  8. プロキシ: Helm を使用して、Kubernetes 内の ZooKeeper クラスターを含む ShardingSphere-Proxy クラスターを迅速にデプロイするための公式サポート
  9. JDBC: ShardingSphere JDBC ドライバーのサポート
  10. スケーリング: PostgreSQL 自動作成テーブルをサポート
  11. スケーリング: PostgreSQL および openGauss でカスタマイズされたスキーマを使用したテーブルのスケーリングをサポート
  12. スケーリング: テキスト主キーを持ち、整数主キーを持たないテーブルのスケーリングをサポートします。
  13. モード: レジストリ センターは PG/openGauss の 3 レベル構造をサポートします。
  14. モード: レジストリ センターはデータベース レベルの分散ロックをサポートします。

  1. カーネル: PostgreSQL および openGauss のコピー ステートメントをサポート
  2. カーネル: PostgreSQL のインデックス変更/削除ステートメントをサポート
  3. カーネル: MySQL の更新強制インデックス ステートメントをサポート

  76. カーネル: PostgreSQL DROP EVENT TRIGGER ステートメントへの小さな変更
  77. プロキシ: ShardingSphere-Proxy MySQL は、16 MB を超える MySQL パケットの受信をサポートします
  78. プロキシ: ShardingSphere-Proxy で構成可能な netty パラメータ ChannelOption.SO_BACKLOG をサポートします。
  79. プロキシ: netty の so-reuseaddr を最適化して、ポート占有の問題を解決します。
  80. プロキシ: ShardingSphere-Proxy の Docker イメージは aarch64 プラットフォームをサポートします
  81. プロキシ: ShardingSphere-Proxy MySQL でサーバーのバージョンを構成可能にします
  82. プロキシ: ShardingSphere-Proxy PostgreSQL/openGauss でより多くの文字セットをサポート
  83. プロキシ: ShardingSphere-Proxy でデフォルトのポートを構成可能にします
  84. スケーリング: thread_pool が有効な場合、openGauss:3.0 の HA ポートと互換性があります。
  85. スケーリング: ZooKeeper イベントのブロックを回避するために、PipelineJobExecutor での ZooKeeper イベント処理を最適化します。
  86. スケーリング: プロセス全体でテーブル名の大文字と小文字を区別しないようにします。
  87. スケーリング: PostgreSQL および openGauss のレプリケーション スロットのクリーンアップを改善しました。
  88. スケーリング: ジョブの準備のためのロック保護を改善します。
  89. スケーリング: 更新の競合時に PostgreSQL 挿入をサポート
  90. スケーリング: 共有リソースが閉じる問題を回避するために、GlobalDataSourceRegistry にデータ ソースをキャッシュしないでください。
  91. スケーリング: データ ソース プールをできるだけ再利用して、稼働中のデータベース接続を削減します。
  92. DistSQL: REFRESH TABLE METADATA は PostgreSQL のスキーマの指定をサポートします
  93. DistSQL: ALTER SHARDING TABLE RULE バインディング テーブルの検証を追加
  94. モード: ShardingSphere-JDBC はデータベース接続名の構成をサポートします
  95. 分散トランザクション: DistSQL はトランザクション内での実行が禁止されています
  96. 分散トランザクション: autocommit = 0、DML の DDL 部分が自動的にトランザクションを開きます。

バグ修正

  1. カーネル: PostgreSQL および openGauss の show ステートメントに関する解析エラーを修正
  2. カーネル: PostgreSQL および openGauss の時間抽出関数に関する解析エラーを修正
  3. カーネル: PostgreSQL および openGauss の select mod 関数に関する解析エラーを修正
  4. カーネル: 読み取り書き込みシナリオでマルチスキーマを使用して join ステートメントを実行するときの PSQLException を修正
  5. カーネル: 暗号化シナリオでスキーマ作成ステートメントを実行するときの間違ったルート結果を修正
  6. カーネル: 存在する場合にスキーマを削除するステートメントを実行するときの npe を修正しました。
  7. カーネル: SELECT LAST_INSERT_ID() AS id を実行したときの間違ったルート結果を修正しました。声明
  8. カーネル: データベースにデータソースが含まれていない場合にデータベースを使用する実行時の npe を修正しました。
  9. カーネル: set var を使用した create 関数を修正
  10. プロキシ: PostgreSQLComDescribeExecutor で列の大文字と小文字が一致しないことが原因で発生する NPE を修正
  11. プロキシ: ShardingSphere-Proxy PostgreSQL / openGauss のスキーマ DDL の完全なコマンド タグ
  12. スケーリング: MySQL の符号なし型 NULL 値によりインクリメント タスク中にエラーが発生する問題を修正しました。
  13. スケーリング: ShardingSphere-Scaling で DataSource を作成するときに発生したエラーによるリソース リークを修正しました。
  14. スケーリング: 他のルールを無視した ShardingSphereDataSource の作成を修正しました。
  15. スケーリング: 準備ジョブを停止できなかった問題を修正
  16. スケーリング: データ ソース プロパティの URL と jdbcUrl の互換性を修正
  17. スケーリング: openGauss 論理レプリケーション スロットの作成を修正し、増分データ損失の可能性を回避します。
  18. スケーリング: ジョブ ステータスをレジストリ センターに永続化する前にローカル ジョブ ステータスを更新し、後で上書きされないことを確認します。
  19. スケーリング: PostgreSQL の TestDecodingPlugin での null 値の処理
  20. DistSQL: SET VARIABLE の変更がスタンドアロンおよびメモリ モードで有効にならない問題を修正
  21. DistSQL: SHOW INSTANCE LIST の表示データと実際のデータの不一致を修正
  22. DistSQL: DistSQL のシャーディングにおける capitalization の感度を修正
  23. モード: スケーリングによってテーブル シャーディング ルールが変更された後、新しいバージョンのメタデータが失われたデータを修正します。
  24. 分散トランザクション: カタログを使用した getIndexInfo を修正

API の変更点

  1. DistSQL: EXPORT SCHEMA CONFIG を EXPORT DATABASE CONFIG に変更します。
  2. DistSQL: IMPORT SCHEMA CONFIG を IMPORT DATABASE CONFIG に変更します。
  3. DistSQL: SHOW SCHEMA RESOURCES を SHOW DATABASE RESOURCES に変更します。
  4. DistSQL: COUNT SCHEMA RULES を COUNT DATABASE RULES に変更します。
  5. モード: db-discovery アルゴリズム設定を調整します。
  6. 権限: 権限プロバイダー ALL_PRIVILEGES_PERMITTED が ALL_PERMITTED に更新されました
  7. 権限: 権限プロバイダー SCHEMA_PRIVILEGES_PERMITTED が DATABASE_PERMITTED に更新されました

リファクタリング

  1. スケーリング: JobConfiguration をリファクタリングし、さまざまな種類のジョブの再利用と拡張に備える
  2. モード: レジストリ センターのコンピューティング ノード構造を最適化します。
  3. モード: インスタンス ID として ip@port の代わりに uuid を使用します。
