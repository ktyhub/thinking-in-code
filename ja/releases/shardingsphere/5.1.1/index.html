shardingsphere 5.1.1

パッチ 公開日2022年4月14日 出典apache/shardingsphere 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#シャーディングスフィア5.1.1

新機能

  1. カーネル: PostgreSQL のマテリアライズド ビューの変更をサポート
  2. カーネル: PostgreSQL のサポート宣言
  3. カーネル: PostgreSQL の破棄をサポート
  4. カーネル: PostgreSQL で $$ をサポートするモードをパーサーに追加します。
  5. カーネル: MySQL create tablespace ステートメントの解析をサポート
  6. スケーリング: ソース書き込みの停止とソース書き込みの復元を実装します。
  7. スケーリング: 部分テーブルのスケールアウトをサポート
  8. DistSQL: 新しい DistSQL 構文: SHOW UNUSED RESOURCES
  9. モード: 永続的な XA Recovery Id をガバナンス センターに追加しました
  10. モード: データベース検出により、遅延マスター/スレーブ遅延機能が追加されます。
  11. 分散トランザクション: ShardingSphere プロキシのセーブポイント サポートを追加
  12. 分散トランザクション: PostgreSQL および openGauss のトランザクション ブロックで例外が報告された場合の自動ロールバックをサポート
  13. 分散トランザクション: ナラーヤナで使いやすくする
  14. 分散トランザクション: ShardingSphere-JDBC のセーブポイント サポートを追加

機能強化

  1. カーネル: カーネルをリファクタリングしてパフォーマンスを向上させます。
  2. プロキシ: ShardingSphere-Proxy の Docker イメージ サイズを削減します。
  3. プロキシ: ShardingSphere-Proxy は set names ステートメントをサポートします
  4. プロキシ: ShardingSphere-Proxy MySQL は複数のステートメントをサポートします
  5. スケーリング: プロキシ クラスター内のデータ整合性チェックを実行できるのは 1 つのプロキシ ノードだけです
  6. スケーリング: スケーリング入力および出力構成フィールドのタイプを int から Integer に置き換えます。
  7. スケーリング: MySQL チェックサム SQL を更新します。
  8. スケーリング: ジョブ開始前のリセットおよび進行状況チェックでのスケーリング ジョブの進行状況の削除を改善しました。
  9. スケーリング: ターゲット テーブルにソース テーブルと同じデータが既に存在する場合の FinishCheckJob データ整合性チェックを改善します。
  10. スケーリング: 主キー以降にサポートされていないテーブルがある場合は、できるだけ早くスケーリング ジョブを中断します。
  11. スケーリング: PipelineAPIFactory でプロキシの ClusterPersistRepository を再利用
  12. スケーリング: jobId 生成アルゴリズムを更新し、冪等性をサポートするようにします。
  13. DistSQL: CREATE/ALTER ENCRYPT RULE 時の構成データ型と長さをサポート
  14. DistSQL: SHOW ALL VARIABLESとSHOW VARIABLEの表示結果を統一
  15. DistSQL: DROP BINDING TABLE RULES の場合のバインド順序の影響を削除します。
  16. DistSQL: SHOW INSTANCE LIST の結果に列 mode_type を追加します。
  17. DistSQL: ENABLE/DISABLE INSTANCE の場合のモードに検証を追加します。
  18. DistSQL: DROP READWRITE_SPLITTING RULE のときにルールが使用されているかどうかを確認します。
  19. DistSQL: CREATE READWRITE_SPLITTING RULE の場合に重複するリソース名をチェックする
  20. DistSQL: SHOW READWRITE_SPLITTING READ RESOURCES の結果に列 delay_time を追加します。
  21. DistSQL: DROP RULE の場合に IF EXISTS をサポート
  22. DistSQL: ADD/ALTER RESOURCE 時の接続失敗のプロンプト情報を最適化
  23. モード: スキーマレベルのグローバル分散ロックを追加します。
  24. モード: DistSQL のバッチ実行をサポートするためにスキーマのバージョン番号を追加します。
  25. モード: クラスターモードでの永続的なメタデータの最適化
  26. モード: データベース検出は、ジョブの作成時に schemaName 識別子を追加します。

リファクタリング

  1. カーネル: 暗号化用のテスト ケースをリファクタリングする
  2. カーネル: PostgreSQL データベースとスキーマをサポートするためのメタデータのリファクタリング
  3. スケーリング: パイプライン モジュールの HikariCP 依存関係を削除します。
  4. モード: ガバナンス センターのストレージ ノード構造をリファクタリングします。
  5. モード: ガバナンス センターのメタデータ構造をリファクタリングします。
  6. モード: データベース検出 MGR モジュールを MySQL モジュールに調整します。

バグ修正

  1. カーネル: パラメータのない関数を修正
  2. カーネル: InsertValueContext.getValue キャスト例外を修正
  3. カーネル: 集計個別列エラーを修正
  4. カーネル: スキーマでパラメータを書き換えるときの NPE を修正
  5. カーネル: 読み取り/書き込み分割で GeneratedKeysResultSet が columnName を返さないことが原因で発生する NPE を修正
  6. カーネル: show tables ステートメントが単一テーブルの一部を失う問題を修正しました。
  7. カーネル: 同じサフィックス テーブルが存在する場合の ModShardingAlgorithm の間違ったルート結果を修正
  8. カーネル: 代入句にキーが含まれている場合の SQL 解析エラーを修正し、インデックス解析を最適化します。
  9. カーネル: シャーディングアルゴリズム構成の数値プロパティ時の NumberFormatException を修正
  10. カーネル: 単一の dataSource を読み取り/書き込み分割用に構成する際の間違ったメタデータを修正
  11. カーネル: BatchPreparedStatementExecutor 使用時のステートメントクローズ例外を修正
  12. カーネル: SQL に短縮投影が含まれる場合に小文字ロジックを書き換える問題を修正
  13. カーネル: メモリ モードでプロキシを起動するときの NullPointerException を修正
  14. プロキシ: PostgreSQL/openGauss プロトコルでリテラルが誤って置き換えられる可能性がある問題を修正
  15. プロキシ: マルチスキーマを持つ ShardingSphere-Proxy PostgreSQL が PostgreSQL JDBC ドライバー 42.3.x によって接続できない問題を修正しました。
  16. プロキシ: ShardingSphere-Proxy MySQL で不正確なタイムスタンプ nano を修正
  17. プロキシ: バイナリ形式の数値用の完全な ShardingSphere-Proxy PostgreSQL コーデック
  18. プロキシ: ShardingSphere-JDBC における潜在的なパフォーマンスの問題と OOM のリスク
  19. プロキシ: ShardingSphere-Proxy MySQL で ResultSet が閉じられた後に操作が許可されない問題が時々発生する問題を修正
  20. プロキシ: addBatch を使用しない ShardingSphere-JDBC のexecuteBatch による NPE の原因を修正
  21. スケーリング: プロキシを再起動する以外、失敗または停止したジョブを DistSQL によって開始できなかった問題を修正しました。
  22. DistSQL: CREATE SHARDING TABLE RULE の場合のインライン式の解析例外を修正
  23. DistSQL: パスワードが ADD RESOURCE ステートメントのキーワード password である場合の解析例外を修正
  24. モード: ZooKeeper セッション タイムアウトによる計算ノードの損失を修正しました。
  25. モード: ガバナンス センターのテーブル名の大文字と小文字を修正しました。
  26. モード: DistSQL 有効化、無効化、インスタンスのメモリ内計算ノードのステータスの更新
  27. モード: DistSQL を介してルールを作成できないデータベース検出を修正しました
