#ゼルジv1.0.0-rc.102

Linux のみのリリース。 このリリースには、Linux バイナリ (x86_64 と aarch64、glibc と musl、および両方の glibc ターゲットの .deb) および XERJ Query-1 モデル バンドルが同梱されています。 macOS および Windows ビルドは、このリリースのアップデートに続きます。それまでは、インストーラーと releases/latest はすべてのプラットフォームで v1.0.0-rc.101 を提供し続けます。以下のアセットをダウンロードして、Linux に rc.102 をインストールします。

[1.0.0-rc.102] - 2026-11-06

rc.102: XERJ Query-1 サーブ ルール R8、カウントに対するガード パスが表現できない、rc.102 パブリックウィンドウ。 を含むモデルバンドル このリリースに同梱される candidate_a_s47_r8 は、以下と同じ重量を保持します。 rc.101 の candidate_a_s47 (すべてのウェイト ファイルは同じ sha256 を持ちます) と変更点 回答の提供方法のみ: ルール R8 (詳細は「変更済み」を参照)。 XERJ スコア v2 について (Opus 5.5 = 100 に対して測定されたクレジット)、4 つの開発ファミリーについて teacher_dev、bench_select、s1b_dev、d1_select (各 400 アイテム、 合計 1,600)、シード 47 は 90.29 から 94.69 (+4.40、95% 間隔) +3.32 から +5.64、ペアのワールド クラスター ブートストラップ);シード 11 と 29 は +3.95 を移動します そして+4.17。これらは開発項目であり、R8は以下の診断から選ばれました。 それらと同じ項目であるため、94.69 はサンプル内の番号であり、公開されている番号ではありません。間違っています 答えはシードごとに上がります。シード 47 では 1,600 件中 9 ～ 10 件、シード 11 では 12 ～ 15 件です。 保持されている 1 つの読み取りは fresh_v1 セットで、2026 年 11 月 4 日に 1 回読み取られ、 2 回目の読み取りなしで R8 で再スコア: ネット 0.3333 から 0.3481、右 112 から 118、11 から 12 は間違っています。新しい用語に対する堅牢性とフレッシュセットのカウントは保証されていません。 別途測定。エンジンは、評価されたルールを正確に提供します。 マージされた rc.102 ツリーでは、1,600 個の開発項目すべてに対するエンジンの行により、 評価の Python 行と同じ提供結果 (1,600 のうち 1,600、284 行) 生のステータス (UNKNOWN と UNSUPPORTED) のみが異なり、両方とも declines)。 --facts-model-dir がない場合、ノードは rc.101 のノードになります。

アップグレードに関する注意事項

  • rc.102 バンドルには rc.102 バイナリが必要です。 rc.101 はそのバイナリを拒否します bundle.json (不明なルール decline_v2_r8、モデル状態 unavailable)。 rc.102 バイナリは引き続き rc.101 バンドルをロードし、以下で提供します。 decline_v2 パートナー契約あり、以前と同様にバイト単位で。
  • カウントは R8 の下でパートナーを待たなくなりました。 rc.102 では 質問がカウントにルートされると、バンドルカウントが提供されます。 チェックに合格し、エンジンが応答します。パートナー モデルが実行されない、および partner_agreement は true ではなく null です。 final_statusを読んで、 先ほどと同様にfinal_answer。
  • データ ディレクトリ。 rc.102 は rc.101 のストレージのデフォルトを保持します (ZPS4 投稿、行辞書に保存されたテキスト、ディスク上の形式 4)、つまり rc.101 データ ディレクトリは変更されずに開きます。 rc.100 からの一方向のアップグレードについては、以下で説明します。 rc.101 は、rc.100 が最後に書き込んだディレクトリに引き続き適用されます。これでは行われていません ウィンドウ、および繰り越し: rc.101 は、その保管レーンと摂取レーンは、 rc.102 より前にパブリック main に到達します。彼らはそうではありません。彼らはプライベートにいます ビルド ツリーのみであり、パブリック main からのビルドは引き続きフォーマット 3 を書き込みます。 format-4 ディレクトリを拒否します。
  • 来歴 rc.102 バイナリはプライベート ツリーから構築されます: public 34a2f244 での main (このウィンドウのマージ) と XERJ-Query エンジン レーン さらに、モデルには xerj-infer、xerj-serve、xerj-exec の木箱が含まれています。 プロプライエタリ ライセンスが付与されており、バイナリ + モデル バンドルとしてのみ出荷されます。それらの クレートは Apache-2.0 ではなく、パブリック リポジトリにありません。の Apache-2.0 LICENSE は、main のエンジン ソースをカバーします。
  • XERJ-Query はオプトインのままです。 フラグは --facts-model-dir <DIR> (または XERJ_FACTS_MODEL_DIR);これがないと、すべての /_facts パスは 404 となります。 xerj_query_not_enabled。

追加

  • xerj autoindex <path> --facts <namespace> はテーブル行を XERJ Query-1 として書き込みます 事実: SQLite ファイル、SQL ダンプ、CSV/TSV、および XLSX (#2988)。各行は 1 つの主題です subject_id がキー列 (id、<table>_id、... または --key) である場合、それぞれ 他の列にはその行を引用する事実が入力されているため、カウントの質問が行われます 手書きの事実なし。変更された行のみを書き込み再実行します (古い行は取り消します) バージョン、新しいものを書き込みます)、削除された行を取り消します。変更されていない行は、 ノーオペ。 rc.101 で測定: 0.36 で 1,000 行 → 6,000 ファクト。 「何人 人々はベルリンにオフィスを持っていますか？」 → パートナーとの path: counting 経由の 366 合意（ゴールド 366）。マッピングは行ごとの変更関数です (facts_rows::RowFactMapper::map_change) なので、ストリーミング ソースで再利用できます。
  • ノード内のライブ Postgres ソース (#2984): xerj connect postgres://… は、選択したテーブルを一貫したスナップショットでスナップショットします。 論理的なすべての挿入、更新、削除、切り捨てを適用します。 レプリケーションは再起動後に生き残り、確認された LSN から再開します。 HTTP GET /_xerj/sources、GET|PUT|DELETE /_xerj/sources/{name}; MCPツール xerj_sources (MCP には、ハブ キーなしのツールが 21 個、ハブ キーありのツールが 24 個リストされています)。 x86_64 ラップトップ (32 スレッド) 上の Postgres 16 に対する PR で測定 同じホスト: 54,776 行/秒でスナップショットされた 1,000,000 行のテーブル。 991 で 6,000 サンプル以上の commit-to-readable p50 16.9 ms、p95 26.6 ms コミット数/秒。 kill -9 ミッドストリームの後、27,696 行 = 27,696 ドキュメント、0 欠落している、余分なもの、古いもの、または重複しているもの。 docs/LIVE_SOURCES.mdを参照してください。
  • xerj autoindex は、zip、tar、tar.gz/tgz、tar.zst アーカイブのインデックスを作成します。 レベルが深く、絶対および .. メンバー パス、リンク、特殊パスを拒否します。 ファイル、バイト、メンバー、および拡張率の上限付き (#2982)。 xerj ソース [--json] and docs/SOURCES.md には、データを取得するすべての方法がリストされています。
  • 2 番目の _search 再ランキング プロバイダーとしての Cohere Rerank、"rerank": {"provider": "cohere"}、オペレーターがキーを設定するまでオフ。エンドポイントは ドキュメントのテキストをプライベートCohereデプロイメントに残すことができるように構成可能 (#2985)。 docs/RERANK.mdを参照してください。
  • Cohere の例 (#2983): Cohere の OpenAI 互換のエンベッダー構成 ルート、引用がファイルとファイルに解決される stdlib コマンド RAG の例 ページ、および Cohere Chat v2 ツール スキーマとしての XERJ ツール。リプレイテスト済み モック Cohere API に対して。 Cohere のライブ実行はまだありません。
  • rc.101 ドキュメント セットおよび /get --with-model (#2969): /_facts API、モデル バンドルとクイックスタート ページ、およびインストーラー フラグ バイナリを含むモデル バンドルを取得し、その sha256 をチェックします。

変更されました

  • XERJ Query-1 の起動に関する主張がサイト、README、ドキュメント全体で修正されました。 13 の表面上の 1,370 のステートメントのレビュー (#3023): 待ち時間は応答時間です メッセージ API 時間に対して、CLI の起動はありません。精度の見出し名 その範囲（各質問に与えられた独自の記録、開発セットの質問）。 コーパスには番号の横に名前が付けられます。
  • landing/llms.txt および docs/MODEL_QUICKSTART.md の /_facts 待機ループ ポーリングの代わりに unavailable および xerj_query_not_enabled で停止します 永遠に (#3028)これは問題 #3021 の半分のドキュメントです。スタートアップ半分 開いたままです。

修正済み

  • カウント操作セットで表現できないカウントは提供されなくなりました (部分的) 問題 #3015) を修正しました。 rc.101 「ベルリンまたはミュンヘンには何人いますか?」 (ベルリン x2、ミュンヘン x1) 両方のモデルが or を削除し、合意したため、検証済みのカウントは 1 です。 ミュンヘン単独のプログラム。サーブルールがカウントをサーブするときと、 質問は代替案を or (either … or、nor) で結合するか、尋ねます 量の合計 (「総高さ」) の場合、答えは次のようになります。 カウント パス上の decline: final_status: "UNKNOWN"、reason_code: "COUNT_CONNECTIVE_UNSUPPORTED"、接続詞に名前を付ける理由、および プログラムの sha を withheld_program_sha256 として保留しました。作るだけのor。 しきい値を含む (「12 行以上」、「1990 年 1 月 1 日以降」) は、 演算セットが表現され、まだ提供されているものをカウントします。ガードの方が大事だよ R8 ではパートナー チェックが削除されます。rc.102 リリース バイナリでは次のようになります。 rc.102 バンドル、両方とも「ベルリンまたはミュンヘンには何人いますか?」そして「どうやって ベルリンかミュンヘンにオフィスを構えている人は多いですか？」でサーブポイントに到達した 1 都市プログラム (非公開の SHA は「オフィス ミュンヘン」の SHA および 「オフィス ベルリン」)、declined です。 「ベルリンにオフィスを持っている人は何人ですか?」 回帰テスト: ベルリンまたはミュンヘンの 3 つの調査 (xerj-serve 単体テスト、および実際のモデルに対する HTTP テスト)。何 #3015 では開いたままになります: カウントされたメンバー ID を返します。
  • _search と profile: true は、測定された位相タイミングをレポートします。 0/1 ns プレースホルダーの代わりにナノ秒 (#3029、問題 #3005)。のみ 位相が測定されます。ゼロ以外のブレークダウン タイマーはその位相の合計です ( 上限)、*_count フィールドは測定されず、新しいフィールドは profile.xerj_timingさんはそう言っています。
  • 結合された kNN 近傍はスコアによってランク付けされ、次に seq_no、次に _id の順にランク付けされます。 executor (#3030、issue #3017) であるため、同順位の kNN またはハイブリッド ランキングは インデックス作成プロセス中および再起動後も同様です。合成 5,000 ドキュメントの場合 2,500 の異なる 384-d ベクトルと 160 のクエリを含むセット、インデックス作成プロセス vs restart は同一ランキング 320 件中 234 件から 320 件中 320 件になりました。
  • プロキシ エンベッダーは、アイテムごとの index なしで埋め込み応答を受け入れます。 （CohereのOpenAI互換ルートでは省略されています）ので、semantic_textは次のように書きます このようなルートを経由しても、response parse (#2983) で失敗しなくなりました。
  • aarch64 Linux リリース アセットは、64 KiB jemalloc ページで構築されています 再び (JEMALLOC_SYS_WITH_LG_PAGE=16、問題 #1663)。 rc.101 aarch64-unknown-linux-gnu、aarch64-unknown-linux-musl、および arm64 .deb アセットはそれなしでネイティブに構築されたため (4 KiB ページ)、開始時に中止されます。 16 KiB および 64 KiB ページの aarch64 カーネル上。

rc.102 に依存する場合の既知の制限

特に明記されている場合を除き、rc.101 から変更されていません。カウントは次の場合にのみ実行されます。 カウントされた被験者の事実は、安定した subject_id を保持します。オペセットが設定されました counts (「X に Y がある個数」、オプションで「個別の <フィールド>」、包括的 しきい値);数量の論理和、合計、または合計が declined になりました 狭く提供するのではなく、理由（上記）を付けてください。サーブ数はまだ集計中 一致したセットのメンバーを検索し、質問の名詞はチェックしません。 「ベルリンのオフィスには合計で何台のデバイスがありますか?」 office = Berlin以上 devices 関係のない事実は人数として提供されます。数える 回答には証拠 ID は含まれておらず、プログラムの名前はその sha のみで付けられます。
