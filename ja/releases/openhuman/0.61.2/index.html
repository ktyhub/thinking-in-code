openhuman v0.61.2

#オープンヒューマンv0.61.2

オーケストレーションとワークフローの飛躍

このリリースでは、エージェントの調整、信頼性の高いワークフローの構築、アプリ全体のプライバシー、安定性、可観測性の強化において大きな前進をもたらしました。先へ！ 🚀

ハイライト

オーケストレーション ハブとエージェント フリートの制御 🧠

オーケストレーションは真のコントロール センターへと成熟しました。TinyPlace に重点を置いたハブと専用タブ、承認とブロックされた実行のための注意/「必要」ゾーン、型指定された v2 ハーネス セッション ストリーム、およびセッションを管理するためのマスター チャット コントロール チャネル (DM の取り込み/返信の改善、復号化できないメッセージの安全な処理など)。 これにより、同じ場所に配置されたローカル CLI エージェント、カーソル/ウィンドサーフィン ハーネスのサポート、ホスト型ブレイン client 作業、および新しいデバイス ツール実行フロー (trust ゲートと承認付き) など、調整できる内容も拡張され、強力なアクションを使用可能かつ安全に保つことができます。 (#4588、#4589、#4592、#4609、#4623、#4627、#4652、#4660、 #4693、#4709、#4710、#4712、#4713、#4720、#4722、 #4725、#4738、#4753、#4773、#4775、#4777、#4778、 #4837) — @oxoxDev、@sanil-23、@senamakel、@M3gA-Mind、@CodeGhost21、@YellowSnnowmann に感謝します。

基礎から洗練された UX までのワークフロー (tinyflows) 🔁

ワークフローは rapidly に進化しました。コア エンジンのシームとドメインが確立され、トリガー/再開/履歴、承認と trust、実行検査、リスト + ナビゲーション、キャンバス ビュー、および検出と実行を含む完全なワークフロー ページのオーバーホールが行われました。このビルダーは、ライブ カタログのグラウンディング、より明確な入力処理、より安全なデフォルトとゲート、より優れた診断、失敗した実行に対する「エージェントによる修正」パスなど、大幅な品質アップグレードを実現しました。 その後、条件とルーティングの検証、スケジュール レンダリング、ツール出力パスの処理 (スキーマレス プローブを含む)、より適切な実行誠実性 (警告を含む)、重複排除された出力レンダリング、永続的なコパイロット チャット、およびスケジュールされた/副作用のあるフローの誤った設定に対する保護など、長期にわたる正確性の修正が続きました。 (#4433、#4447、#4449、#4450、#4471、#4472、#4474、 #4477、#4552、#4561、#4570、#4573、#4574、#4578、 #4580、#4586、#4587、#4590、#4591、#4602、#4605、 #4606、#4607、#4608、#4628、#4630、#4636、#4645、 #4647、#4651、#4659、#4662、#4663、#4664、#4665、 #4668、#4670、#4672、#4673、#4674、#4698、#4702、 #4707、#4750、#4822、#4823、#4826、#4834、#4835、 #4836、#4858、#4865、#4869、#4870、#4874、#4876) — ありがとう @graycyrus @senamakel、@CodeGhost21、@YellowSnnowmann!

TinyAgents + エージェント ハーネスの信頼性 (およびより良い回答) 🧩

ハーネスと TinyAgents の移行作業の大きな波が到来しました。チェックポイント/HITL/オブザーバビリティ、移行の完了、構造化されたポリシー ブロック メッセージング、より適切な「最終回答」保証、UI に表示されるツール障害分類、強化されたメモリの読み取り→重複排除→書き込み→インデックス コントラクト (さらに、使用できないツールや進捗のないナッジに関する修正のロングテール) を備えた、agent_graph ステート マシン ハーネスです。 また、ウェッジ ターンの防止とオーケストレーション動作の改善 (タイムアウト、並列ファンアウト、より安全な委任パス、より明確なツール障害のレンダリング、迅速な姿勢調整、スケジューラ/cron の強化など) にも多くの堅牢性への取り組みが行われました。 (#4261、#4362、#4372、#4386、#4399、#4400、#4413、 #4419、#4425、#4430、#4431、#4434、#4443、#4444、 #4445、#4473、#4476、#4478、#4479、#4480、#4481、 #4482、#4483、#4485、#4495、#4502、#4504、#4507、 #4509、#4512、#4524、#4539、#4542、#4601、#4603、 #4658、#4682、#4683、#4686、#4741、#4748、#4751、 #4752、#4757、#4764、#4768) — @senamakel、@M3gA-Mind、@oxoxDev、@sanil-23、@sanil-23、@CodeGhost21 に感謝します。

メモリ エンジンのアップグレード: TinyCortex の移行 🧠📚

メモリは、段階的な TinyCortex 移行によって基礎的なアップグレードが行われました。アダプターの継ぎ目、型の統合、接続の基盤、チャンク ストアの反転 (読み取りパス、バッチ処理、リスト)、そして最後に、パリティ ハーネスの作業と更新されたカバレッジに裏付けられた完全なエンジンの移行です。 その過程で、レンダリング シムの安全性の向上、メモリ ストアの自己修復機能の改善、エラー分類の明確化、Vault の健全性と同期ステータス間の信頼性シグナルの向上など、いくつかの重要な品質修正が行われました。 (#4363、#4526、#4529、#4532、#4534、#4538、#4546、 #4547、#4551、#4555、#4559、#4781、#4785、#4787、 #4788、#4789、#4790、#4794、#4820、#4699、#4700、 #4703、#4340、#4410) — @senamakel、@YellowSnnowmann、@CodeGhost21、@M3gA-Mind、@oxoxDev に感謝します。

プライバシー モードとローカルのみの適用 🔒

プライバシーは最上級になりました。プライバシー モードとローカルのみの推論の強制に加えて、出力記述子 + 開示イベント、プライバシー ステータス サーフェス、アクションごとの開示 UI、および PII/識別リスク検出。 この取り組みにより、ローカルのみの適用が統合やツール全体に拡張され、何かを実行する前に何がマシンから流出するのか (何が流出しないのか) を理解しやすくなります。 (#4446、#4812、#4813、#4849、#4850) — @oxoxDev ありがとうございます!

可観測性と Langfuse トレース (より深く + より安全) 🔭

トレースと可観測性は劇的に拡張されました。豊富な Langfuse メタデータ、ターンごとに 1 つのトレース、実際のコストを伴う世代/ツール/サブエージェントにわたるフルコンテンツ トレース、グラフ/フロー実行のエクスポート (エージェント グラフ ビュー メタデータを含む)。ジャーナル テレメトリは、Langfuse の使用状況/実行に関する洞察を提供するようになり、生成されたサブエージェントのトレース ペアレンティングが正しくリンクされます。 安定性の向上により、チャンク化された取り込みバッチ、ノイズの多い拒否パスの降格、およびいくつかのトレースの正確性の修正 (依存関係バンプによるアップストリームの観察 ID 衝突の修正を含む) が追加されました。 (#4498、#4499、#4506、#4562、#4568、#4676、#4678、 #4864) — @senamakel、@M3gA-Mind、@oxoxDev に感謝します。

デスクトップの安定性、起動時の回復、UX の向上 🖥️

プラットフォーム全体でデスクトップの信頼性が向上しました: Windows 起動時のプロアクティブな古いプロセスのクリーンアップ、macOS/Linux の古いロック reaping とインストーラーのプリインストールの強制終了、エラー処理/ビルドのための Linux リンクの改善、SwiftShader による CEF/Windows GPU ルーティング (さらに、Windows pre-CEF リカバリのより厳密な範囲設定)。 UX の面では、この範囲には、ライブ ステータスを備えたリモート コア接続設定、ウィンドウ ジオメトリの永続性と最小化されたウィンドウの復元動作、より適切なサインイン エラー メッセージング、アプリ全体の一連のヘッダー/ランディングの標準化が追加されています。 (#3793、#4405、#4406、#4643、#4644、#4649、#4817、 #4818、#4851、#4857、#4859、#4860、#4805) — ありがとうございます @sanil-23、@M3gA-Mind、 @senamakel、そして@NgoQuocViet2001!

チャネルとコミュニケーション: 電子メール、電報/WhatsApp、会議 ✉️

OpenHuman は、ネイティブ IMAP/SMTP 電子メール統合を実現し、さらに tinychannels の移行とランタイム境界を介してチャネルでの作業を継続しました。 Telegram のペアリングとツール呼び出しの信頼性が向上し、履歴の取り込みにバックプレッシャーがかかり、WhatsApp の破損処理が Sentry をフラッディングする代わりに回復するようになりました。 ライブトランスクリプト、改善された相関 ID、リコールカレンダーの自動参加と UI の改善、マスコットポーズ用のより豊富なボットの「話す」タグ付け、さらにはマスコットごとの音声とスピーカーの交互によるデュアルマスコットによって会議がレベルアップされました。 (#4367、#4414、#4569、#4549、#4557、#4349、#4350、 #4354、#4391、#4585、#4715、#4740) — @oxoxDev、@senamakel、@graycyrus、@YellowSnnowmann に感謝します。

推論 + コア ランタイムの最新化 ⚙️

推論は、よりクリーンなクレート ネイティブで TinyAgents 駆動のアーキテクチャに移行しました。呼び出し元を tinyagents ChatModel に移行し、ターンごとの状態を分離し、ModelRouter ルーティングを採用し、BYOK クラウド スラッグと OpenAI/コーデックス パスをクレート ネイティブ実装にカットオーバーするための複数の「モーション」ステップを採用しました。同時に、SSE ハング シナリオにも対処し、生の BYOK モデル ID が確実に保持されるようにしました。 プラットフォーム側では、コア ランタイムにプラグ可能性と「フリート ホスト」が追加され、さらに DomainSet 構成とコンパイル時の音声機能ゲートが追加されました。マネージド ファイル ストレージ エージェント ツールや表面化されたストレージ転送ツールにも進歩があります。 (#4393、#4614、#4625、#4629、#4769、#4780、#4782、 #4783、#4784、#4298、#4791、#4808、#4833、#4576、 #4577) — @senamakel さん、@oxoxDev さん、@sanil-23 さん、@YellowSnnowmann さん、ありがとうございます！

品質: CI、テスト、リリース配管 🧪

この範囲は、ビルドとテストの信頼性に重点を置いています。2 レーン CI (ライト/フル)、変更されたファイルのみの PR レーンとフルスイートのリリース レーン、テスト監査と段階的なクリーンアップ/バックフィル、より高速な Rust テスト ビルド、およびプラットフォームとリリースの「テール」にわたる多くの E2E 安定化です。 リリースの仕組みにも注目が集まりました。ワークフロー解析の修正、完全な dist アーティファクトの復元、リリース レーンのブロック解除とタイムアウト、分岐/制限の調整 (キャップの削除を含む)、CodeQL アラート シンクの強化などです。 (#4486、#4488、#4489、#4492、#4494、#4497、#4500、 #4501、#4511、#4519、#4521、#4527、#4530、#4531、 #4533、#4540、#4543、#4548、#4553、#4554、#4556、 #4579、#4646、#4666、#4671、#4701、#4721、#4759、 #4827、#4830、#4838、#4866、#4867、#4871) — @senamakel、@M3gA-Mind、ありがとうございます。 @CodeGhost21、そして@graycyrus!

製品エクスペリエンス: チャット、ペルソナ、特典、設定、ドキュメント 🎁

チャットと会話は大幅にアップグレードされました。ターンごとのプロセス履歴とマルチフェーズのタイムライン リファクタリング、リデューサーでのイベント マージの改善、より信頼性の高いツール結果のレンダリング、タイムラインのアンカー/重複除去の修正、chat-v1 の 1M コンテキスト ウィンドウの調整などです。また、処理タイムラインでのツール呼び出しの失敗の説明や、より安全なキャンセルの範囲設定など、UX の改良も行われています。 その他: 朝のブリーフィングのパーソナライゼーション、ガイド付きペルソナ ビルダー ロール テンプレート、アチーブメント トークン報酬の可視性、フォント サイズの微調整、標準化された分析インタラクション トラッキングに加え、セットアップ/リカバリ ガイドや再編成されたインストール/ワークフロー/オーケストレーション ドキュメントを含む大幅なドキュメントの更新。 (#4373、#4416、#4424、#4612、#4604、#4622、#4626、 #4765、#4711、#4696、#4873、#4407、#4508、#4514、 #4515、#4792、#4493、#4510、#4513、#4516) — ありがとうございます @M3gA-Mind、@senamakel、 @oxoxDev、そして@YellowSnnowmann!

アプリ全体にわたる小規模ながら強力な修正 🛠️

対象を絞った広範な修正により、日常の信頼性が向上しました。API の使用量のフラッディングの停止、アクティブ ユーザー スイッチでの状態の正しい再バインド、/アナウンス/最新の 404 の適切な処理、セントリーのフラッドを防ぐためのオフライン プロバイダーの動作の改善、クラウド モードでのより安全なブート動作です。 また、学習ユーティリティとエージェントワールド ユーティリティ、接続クリーンアップの正確性、MCP カタログの追加、Windows でのシェル実行ルーティング、コンポジオ承認パーキング動作も改善されています。 (#4379、#4417、#4415、#4402、#4484、#4518、#4697、 #4717、#4723、#4758、#4584、#4704、#4819、#4848、 #4298) — @oxoxDev、@mysma-9403、@CodeGhost21、@M3gA-Mind、@sanil-23、@YellowSnnowmann に感謝します。

言語ベースのワークフロー (RLM/Rhai) と「Codex」ベンダーの作業 🧠🧰

言語ベースのワークフローは、計画ドキュメントと広範なベンダー戦略作業に裏付けられた、一流の Rhai .ragsh REPL ツールとその後のドメイン名変更によって具体化されました。 一連の「コーデックス」とベンダー PR も導入されました。これには、TinyJuice/TokenJuice の作業、TinyChannels のランタイム部分とプロバイダーの採用、tiny.place SDK のベンダーリングとペアリングのフロー、スタックの整合性を保つためのさまざまなサブモジュールの更新が含まれます。 (#4528、#4571、#4523、#4400、#4535、#4549、#4557、 #4560、#4575、#4620、#4491、#4563、#4815) — @senamakel ありがとうございます！
