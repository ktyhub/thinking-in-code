openhuman v0.64.3

#オープンヒューマンv0.64.3

信頼性と速度のアップグレード

v0.64.0 → v0.64.3 は、実際のワークロード下で OpenHuman の安定感を向上させることを目的としています。つまり、ループが減り、リカバリが改善され、起動が速くなり、請求/使用状況がより明確になります。発送してください。 🚀

ハイライト

エージェントの安定性とループ制御 🧭

エージェントは (ツールの検索結果が到着した後でも) 最新 のユーザー リクエストに集中し続け、以前の挨拶に引き戻されることを回避し、よりスマートな障害分類と限定された探索により非生産的なツール ループをより早く停止します。その結果、ツールがブロックされた場合でも、ストールや繰り返し呼び出しが減り、より決定的な「部分的ではあるが有用な」結果が得られます。 (#6656、#6660、#6661) — @senamakel ありがとう！

チャットの回復、ストリーミングの回復力、ウォームセッションの正確性 🛠️

このリリースではチャット エクスペリエンスが強化されています。ウォーム セッションの完了により進行状況が適切に最終決定されるようになり、オプションでデバッグ用に成功した推論 SSE 応答を完全にキャプチャできるようになりました。応答を返さない完了したモデル ストリームには、制限付きの 1 回限りの再試行が行われます。また、書き込みの失敗または破損後のトランスクリプト/アプリの状態の回復はより堅牢になり、履歴が保存され、キューに入れられたフォローアップが安定した状態に保たれます。 (#6665、#6685、#6686) — @senamakel ありがとう！

より迅速な統合とスキル発見 🔥

Composio 統合とスキル メタデータのキャッシュとウォーミングにより、ターン/セッション全体で (明確な無効化ルールを使用して) ターンの起動とツールの可用性がよりスムーズに感じられるはずです。これにより、ローカル推論キャプチャ プロキシを介して Socket.IO WebSocket アップグレードも転送され、より一貫性のあるイベント ルーティングが実現します。 (#6684) — @senamakel ありがとうございます!

時間、タイムゾーン、スケジュールの正確さ 🕒

OpenHuman は、より自然な時間表現 (「明日の午前 9 時」、「月曜日から」、「2 時間 30 分以内」など) を理解できるようになり、Composio コネクタの呼び出しにはユーザーの IANA タイム ゾーンが含まれるため、ダウンストリームの結果 (Gmail タイムスタンプなど) がユーザーの実際の意味と一致するようになります。永続サブエージェントは、セッション ID が複数のフィールドに表示される場合にも、より確実に再開されます。 (#6670、#6673、#6674) — @senamakel と @M3gA-Mind に感謝します。

可観測性と開発者テレメトリ 📡

本番環境の Langfuse トレースは、正規の本番環境 API ホストから (未知のホストを閉じたままにしながら) 有効になり、子エージェント ターンは親会話リネージの下にきれいにグループ化されます。より完全な世代メタデータと、二重カウントを避けるための慎重なアカウンティングが使用されます。 (#6677) — @senamakel ありがとうございます!

より明確な請求と使用量の UI 💳

使用量と請求面が現実性を確認しました。「使用量と制限」が「使用量」になり (誤解を招くローカル予算ゲージが削除されました)、プロバイダー呼び出しの使用量ログには、より優れたフィルターと制限されたレコード セマンティクスを備えた専用タブがあり、請求アクセスは、ホストされたダッシュボード リンク (/settings/billing がリダイレクトとして保存される) を持つアカウントの下に統合されます。また、チャットでは、空のモデル応答がクレジット不足であると誤って非難されることはなくなりました。クレジット ガイダンスは、明示的な請求エラーに対してのみ表示されるようになりました。 (#6657、#6679) — @senamakel ありがとうございます!

ツールとプラットフォームのクリーンアップ (Windows + 廃止されたコンポーネント) 🧹

Windows ユーザーには、固定された TinyBus ACL 修正のおかげで、より信頼性の高い TinyMemory モジュールのロードが表示されるはずです。また、廃止された Medulla 統合は完全に削除されました (レガシー構成エイリアスは保持されているため、古い構成は local として安全にロードされます)。オーケストレーター ツールの表面も、未使用のプロンプト ツールとデリゲート エントリを削除することで強化されました。最後に、file_read が解凍され、オーケストレーターはファイル ツール パック全体を開かなくても結果のプレビューを読み取れるようになりました。 (#6680、#6682、#6669、#6666) — @senamakel さんと @M3gA-Mind さん、ありがとうございます！

テストカバレッジとリグレッション ✅

新しいリグレッション カバレッジは、「挨拶 → 延期された Gmail ツールの継続」動作をエンドツーエンドでロックし、エージェントがアクティブなリクエストとツールの結果をまとめて保持し、以前のコンテキストにフォールバックしないようにします。 (#6659) — @senamakel ありがとうございます!
