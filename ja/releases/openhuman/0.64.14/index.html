openhuman v0.64.14

#オープンヒューマンv0.64.14

ファイル、メモリ、音声のパワーアップ

このリリースは、日々の使いやすさにおいて大きな進歩を遂げています。よりクリアなファイルとセッション、大幅なメモリの進化、リアルタイムの音声エージェントに加えて、スタック全体にわたる大量の信頼性とパフォーマンスの向上です。 🎉

ハイライト

ファイルとプロジェクトのワークスペースの明確さ 🗂️

エージェントの出力は表示可能な Files フォルダーに配置されるようになり、そのフォルダーの保存場所を選択できるようになり、アプリは生成されたファイルをその場で直接表示できるため、エージェントが作成したものを見つけて使用することがはるかに簡単になりました。大規模なツール出力もより安全に処理され、プロジェクトを整理整頓された状態に保ちます。 (#6820、#6825、#6833、#6868、#6947) — @M3gA-Mind と @senamakel に感謝します。

メモリ v2、インポート、およびより安全な組織 🧠

メモリは大幅にアップグレードされます。エンジン選択可能なメモリ v2、各ターンのライフサイクル処理の向上、エンジン切り替え時の移植性の強化です。メモリ UI とプロバイダー カードは最新化され (CortexDB を含む)、クレジット/無料期間の動作はより一貫性があり (トップアップ プロンプト付き)、リコールはタイムゾーンを認識するようになりました。

インポートと移行は大幅に強化されており、「建物と空」の状態が明確になり、バッチ処理/再試行がよりスマートになり、再試行制御による障害の可視性が向上し、再開の信頼性が向上し、ドキュメントの取り込みが改善されました (PDF/Office)。また、コネクタ優先のファイリング、GitHub のスコープ設定の改善、送信者へのオプションの帰属、および複数の消去/削除の正確性とプライバシー/セキュリティの修正により、組織も改善されています。 (#6841、#6843、#6855、#6869、#6873、#6874、#6875、 #6892、#6901、#6924、#6949、#6993、#7011、#7012、 #7013、#7014、#7034、#7029、#7035、#7036、#7038、 #7041、#7043、#7063、#7085、#7089、#7090、#7091、 #7094、#7096、#7100、#7102、#7103、#7104、#7105、 #7106、#7107、#7108、#7109、#7110、#7111、#7112、 #7113、#7114、#7122、#7123、#7126、#7128、#7129、 #7130、#7131、#7134、#7137、#7138、#7139、#7142、 #7143、#7144、#7146、#7147、#7149) — @M3gA-Mind、@senamakel、@CodeGhost21、@YellowSnnowmann、@lorenzozanee に感謝します。

ライブ音声エージェントと音声基盤 🎙️

音声エージェントは真のライブになりました。ツール サポート (Gemini Live、イレブンラボ、Sarvam など) を使用してリアルタイムで Tiny と会話できるほか、サービス カード、設定モーダル、アプリ全体のトーストを使用して再設計された音声エージェント エクスペリエンスが提供されます。内部では、音声関連の推論コンポーネントもよりクリーンな基盤のために再編成されました。 (#7046、#7092、#6840) — @senamakel ありがとうございます!

チャット UX のアップグレードとよりスムーズな会話制御 💬

Chat は、作業フォルダーのサポート、モデルごとの思考制御、実際のスレッドのタイトル、より豊富なサイドバー コンテキスト、およびより明確な実行状態の合図など、UI を大幅に改良しました。信頼性も向上します。停止の回復力が向上し、進行状況シンクがなくてもストリーミングが機能し、応答言語ディレクティブが一貫して送信され、Web チャット配信のいくつかのエッジ ケースが修正されています。このアプリはまた、翻訳可能なエラー コピーを追加し、トランスクリプトの保存形式を改善します。 (#7048、#7045、#6916、#7088、#7097、#7098、#6844、 #7087、#6881、#6883) — @senamakel と @M3gA-Mind に感謝します。

エージェント インテリジェンス、ツール ガバナンス、ターンの信頼性 🧰

エージェントはより堅牢で予測可能です。設定によるツール呼び出しのデフォルト (JSON 自動) の改善、「終了」検証の改善、誤った失敗分類の減少、より明確なファイル読み取り動作、およびコンテキストの圧縮、推論範囲、反復上限、およびホストされたパスの正確性/テレメトリに関する複数の修正が行われています。ツール ポリシー/承認ゲートが再加工され、ターンごとのツール保留が追加され、タイムアウトしたコマンドはプロセス グループ全体を終了するようになりました。

これには、Web リサーチの予算、資格情報スクラバーの動作 (コード編集の回避を含む)、HTTP ステータスの適切な処理、およびオーケストレーション動作の改善に関する対象を絞った修正も含まれます。 (#6910、#6909、#6963、#6965、#6966、#6967、#6968、 #6969、#6971、#6972、#6973、#6974、#6975、#6976、 #6977、#6980、#6992、#6889、#6856、#6879、#6884、 #6945、#6946、#7117、#7118、#7119、#7120、#7140、 #6865) — @senamakel さんと @sanil-23 さん、ありがとう！

セッション、スケジュール、コネクタ、統合 🧩

新しいホスト挿入セッション ストアは、エージェントごとの会話をワークスペースの外に移動し、クリーンなリカバリとスロットの所有権を確保するためのフォローアップを行います。スケジュールされた (cron) 実行は、それを要求した会話に出力を返すことができるようになりました。 Composio とコネクタは、直接読み取りパス、モジュール ルーティングの改善、構成可能な無効モードによって合理化され、さらにメモリの進化に合わせて Composio→メモリ同期が意図的に削除されました。 (#7044、#7052、#7049、#6831、#6885、#6897、#6920) — ありがとうございます@セナマケル！

サンドボックス、Windows、プラットフォームの堅牢性 🛠️

Docker サンドボックス フローが再加工され、ローカルの刑務所出力がプロジェクトの外部でキャプチャされ、サンドボックス機能のレポートとホスト スイッチが改善されました (OPENHUMAN_SANDBOX=off を含む)。 Windows では、アクセス許可状態の正規化とサンドボックス化された子への環境転送に関する重要な安定性の修正が行われています。 TinyComputer ブラウザ タスクはアプリから実行できるようになり、完了したタスクで学習した内容を再利用するための追加の改善が加えられました。 (#6862、#6970、#6981、#6988、#6847、#6998、#7008、 #7127) — @senamakel、@ajabaabaa、@YellowSnnowmann ありがとう！

モデル、ルーティング、検索、およびローカル AI の方向 🧭

ルーティングとモデルの選択は、プロバイダーの選択を尊重し、セッションやオフライン プロファイルで使用できないモデル/検索ツールの提供を回避するなど、UI とコンポーザー全体で強化されました。ツール検索パスは TinyHumans プロキシを超えて拡張され、思考レベルの制御がプロバイダーに渡され、アップロードはネイティブのマルチモーダル入力を優先して永続化されます。

ローカル AI ストーリーも簡素化されています。アプリ内モデルのダウンロードと Ollama ライフサイクル管理は削除されましたが、ユーザー実行エンドポイントを介したローカル推論は引き続きサポートされています。 (#6978、#6996、#7004、#7026、#6908、#6911、#6987、 #6858) — @SayrWolfridge、@sx4im、@obchain、@senamakel に感謝します。

国際化とオンボーディングの洗練 🌍

新しいロケール (日本語とトルコ語) が追加され、アラビア語の README ドキュメントが追加されてアラビア語の翻訳が改善され、保守性を考慮して翻訳カタログ全体が大幅に削減されました。ローカル パスのオンボーディングも短縮され、より正確になります。 (#6986、#7039、#7024、#6860、#7009) — @tjm8874、@moersoy、@taljeri、@graycyrus、@senamakel に感謝します。

リリース エンジニアリング、CI の健全性、ビルド パフォーマンス 🚀

この範囲には、大規模な内部最新化が含まれます。つまり、機能を共有の「小さな*」ライブラリに移動するリファクタリングの波、ベンダーピンの衛生管理、および大規模なデッドコード/依存関係のプルーニングです。 CI とテスト (clippy/レイアウト ゲートを含む) が安定し、冗長なテストが削除または統合され、ランタイムとビルド出力の両方でパフォーマンスが向上しました (すべてのプラットフォームでのビルド時のモジュール バンドルを含む)。 リリース固有の作業により、モジュール バンドルの macOS 公証 (署名検証とテスト) も改善され、ヘッドレス展開でのキーリングのサポートが改善されました。クロスハーネス リグやサポートされるランブックやビューアなど、ベンチマーク ツールとドキュメントが大幅に拡張されました。 (#6828、#6829、#6830、#6832、#6834、#6835、#6837、 #6838、#6845、#6846、#6848、#6849、#6850、#6851、 #6852、#6853、#6854、#6857、#6859、#6861、#6863、 #6864、#6866、#6867、#6871、#6872、#6876、#6877、 #6878、#6880、#6882、#6886、#6888、#6890、#6891、 #6894、#6895、#6896、#6898、#6899、#6900、#6903、 #6904、#6906、#6907、#6912、#6913、#6914、#6915、 #6917、#6918、#6919、#6921、#6922、#6923、#6928、 #6929、#6930、#6931、#6935、#6937、#6942、#6943、 #6944、#6948、#6982、#6989、#6995、#7015、#7017、 #7018、#7019、#7021、#7027、#7028、#7031、#7033、 #7054、#7050、#7058、#7060、#7065、#7070、#7072、 #7079、#7081、#7121、#7124、#7125、#7115) — @senamakel、@M3gA-Mind、ありがとうございます。 @fede-kamel、@lord-Rheagar、@shaurya703、@oxoxDev、@obchain、@CodeGhost21!

ドキュメントと保守性の改善 📚

ドキュメントは、Readme、クラウド デプロイメント、ベンチマーク ランブック、GitBook コンテンツにわたって拡張および修正され、同時に、より健全なコードベースを目指してデッド コード、フラグ、アセット、依存関係を取り除く広範なクリーンアップ作業も行われました。 (#6997、#7068、#7069、#7075) — @tjm8874 と @graycyrus ありがとう！
