openhuman v0.57.53

パッチ 公開日2026年6月23日 出典tinyhumansai/openhuman 英語原文

#オープンヒューマンv0.57.53

安定性とフローのアップグレード

このリリースには、チャット、音声、認証、統合にわたる品質の向上と信頼性の修正に加え、エージェント ランタイムのためのいくつかの大きな構成要素が詰め込まれています。よりスムーズな乗り心地をお楽しみください🎉

ハイライト

チャットエクスペリエンスと UI の洗練 ✨

チャットの感触が著しくすっきりしました。スケジュールされた朝のブリーフィングはグループ化されたままになり (見出しと本文が同じバブル内に)、承認プロンプトは不透明な警告面で読みやすくなり、GFM マークダウン テーブルはエージェントの出力で正しく表示されます。また、短いウィンドウでもサイドバーのコンポーザー フッターにアクセスできるなどのエッジケースの UI の問題も修正し、ファイル マーカーが再構築されたメッセージに漏れないよう添付ファイルのフォールバック解析を改善しました。
(#3851、#3790、#3857、#3863、#3795) — @sanil-23、@discolotus、@YOMXXX、@hgunduzoglu、@rsd-darshan に感謝します。

音声と音声の信頼性 🎙️

音声セットアップとハンズフリー フローがより堅牢になりました。プッシュ トゥ トーク コマンドが再度適切にホワイトリストに登録され、ローカルの Whisper/Piper プロバイダーはインストールが実際に完了するまで (ポーリングと進行状態が改善されるまで) 有効にできません。また、セッションの失効した TTS 401 はノイズの多いハード エラーではなくセッションの期限切れとして正しく扱われるようになりました。
(#3842、#3861、#3750) — @oxoxDev と @YOMXXX に感謝します。

認証、セッション、行き止まりの減少 🔐

サインインとセッション処理がよりスマートになりました。一時的な /auth/me のしゃっくりがセッションの永続性を妨げなくなり、従来の /auth Web コールバックが受け入れられ、HashRouter 用に安全に書き換えられました。また、OpenRouter OAuth はループバック リスナーの 実際の バインド ポートを使用するようになりました (「ポート 3000 がビジー」の場合を修正)。複数の 401 パス (統合 + 音声) により、ユーザーはサイレントに失敗するのではなく、クリーンな再ログイン フローに誘導されるようになりました。
(#3746、#3800、#3904、#3749) — @samrusani、@NgoQuocViet2001、@ly-wang19、@oxoxDev に感謝します。

プロバイダー、推論、ルーティングのアップグレード ⚡

プロバイダー向けの一連の改善が実現しました。OpenAI 互換の HTTP タイムアウトが構成可能になり (長い推論ターンが途切れることがなくなりました)、Gemini ツールの呼び出し履歴が thought_signature を正しく保存し、/models 404 のようなユーザー設定ミス エラーが実用的なヒントとともにソースで分類されるようになりました。また、新しいプロバイダー オプション (組み込みのホスト型プロバイダーとしての ModelScope と、エンドポイント + キー資格情報を持つ名前付きローカル プロバイダーとしての OMLX) も追加しました。
(#3864、#3770、#3769、#3773、#3862) — @hgunduzoglu、@oxoxDev、@yrk111222、@hliebscher に感謝します。

エージェント: オーケストレーション、サブエージェント、およびコンテキストのヘッドルーム 🤖

エージェント ランタイムは大幅にアップグレードされました。イベント ドリブンの潜在意識トリガー パイプラインにより、有効期間の長いオーケストレーター セッションが導入され、ツール出力の圧縮によりコンテキストの肥大化が削減され (可逆回復により)、サブエージェントはデフォルトで非同期かつ再利用可能になりました (ライフサイクル ツールを使用)。また、障害の動作も改善されました。エージェント カスケードは、より明確な根本原因による最初の永続的な推論障害で停止するようになり、ローカル コンテキストのオーバーフロー エラーは、具体的なガイダンスとともにディスパッチ前に捕捉されるようになりました。
(#3650、#3869、#3887、#3779、#3771) — @senamakel さん、@sanil-23 さん、@oxoxDev さん、ありがとうございます！

メモリと同期のパフォーマンス (および正確性) 🧠

メモリの高速化と正確性の両方が向上しました。セマンティック リコールは再びクエリに依存し、エピソードの関連性により O(n²) ホット パスが回避され、チャンク スコアリングの重複除去ではより安価な HashSet が使用されるようになりました。メモリ ツリー シーリング パスはより同時実行性が高く、ソース同期 (GitHub) とカレンダー ファンアウトは制限された同時実行性を使用してスループットを向上させます。同期の面では、Composio の増分同期が汎用オーケストレーターの背後に集中化されました (プロバイダーは Notion/GitHub/Linear/ClickUp/Gmail/Slack 間で移行され、キャップ計算は単一の信頼できるソースに移動されました)。
(#3608、#3782、#3638、#3416、#3434、#3472、#3852、 #3860、#3873、#3874、#3924、#3937) — @michaelk1957、@mysma-9403、@sanil-23 ありがとう！

スキル、ツールチェーン、Windows/Linux シェルの品質 🧰

スキル管理がより鮮明になりました。セッション中にスキルをアンインストールすると、ライブ カタログからスキルが取り消されるようになり、組み込みのカタログ エントリが正しく「インストール済み」として表示され、コミュニティ スキルのダウンロードが各エントリの sourceUrl 経由で解決されるようになりました (ポータルのみのソースの場合はより明確なエラーが発生します)。 Windows では、シェル コマンドの生成時にコンソール ウィンドウの点滅をオプションで抑制できます。 Linux では、AppImage ビルドが絶対 RPATH と libxdo のハードガード バンドルをサニタイズして、起動時のクラッシュを防ぐようになりました。
(#3745、#3656、#3844、#3747、#3776) — @obchain、@YonganZhang、@oxoxDev に感謝します。

通知、cron、請求、および「予想されるエラー」の衛生管理 🧾

Cron と請求パスがより正常に動作するようになりました。スケジュールされたジョブは失敗した/空の実行をチャットに投稿しません。朝の簡単なタスクの取得は 24 時間の最新期間に限定され (Todoist に拡張され、古いスラッグが修正されました)、クレジット プロンプトは選択したチャット モード層ごとに適切にゲートされます (そのため、BYO ユーザーが「クレジットを購入する」というナッジを誤って受け取ることはありません)。また、予想されるユーザー状態イベント (請求状態の cron フラッド、ディスクフル フラッド、プロバイダー枯渇の一時的な集計、OpenAI OAuth token_expired、資格情報コンテキストの保存) を正しく分類することで、多くの Sentry ノイズも削減されました。
(#3789、#3872、#3923、#3775、#3913、#3911、#3663、 #3803、#3674) — @sanil-23、@oxoxDev、@Zhang、@CodeGhost21 に感謝します。

エージェント ワールドとタイニー プレイスの拡張 🌍

Agent World は成長を続けています。TinyPlace には、Pixi シティ レンダラーを備えた専用の World ページがあり、ファンアウトを減らすために GraphQL 経由でルーティングされる読み取りが増えています。また、厳選されたエージェントフレンドリーな TinyPlace ツール サーフェスに加え、専用の tinyplace スペシャリスト サブエージェント、改善されたフィードの並べ替え、暗号化された DM セットアップが完了していない場合のより明確なメッセージング UX もあります。
(#3867、#3879、#3876、#3868、#3919) — @senamakel さんと @Felyx-Fu さん、ありがとうございます！

デスクトップ ナビゲーション、フィードバック、チャネル、オンボーディング 🧭

ナビゲーションとコア UX が調整されました。チャット スレッドには安定した /chat/:threadId ルートがあり、プロバイダーの Web ビューはスレッド ルーティングから切り離されています。オンボーディングのウォークスルー ターゲットが最新の UI に合わせて更新されました。そして、完全なアプリ内フィードバック ボードが表示されました (現在は、サイドバーのフッターに「フィードバックの共有」として表示されています)。また、デスクトップ上の Discord と Telegram のメッセージングをエンドツーエンドで修正しました。さらに、時間境界付近のルーチンの「次回実行」ラベルや、アクティブ ユーザーのみを対象とする「アプリ データのクリア」など、小さいながらも重要な UI の正確性の修正も行いました。
(#3896、#3944、#3834、#3945、#3794、#3758) — @senamakel、@YellowSnnowmann、@obchain に感謝します。

国際化と互換性の修正 🌐

i18n は確実に好評です。メモリ同期監査パネルが完全にローカライズされ、AI ルーティング ワークロードのラベル/説明/ヒントがローカライズされ (ドイツ語を完全にカバー)、文字通り {providerName} レンダリングのようなプレースホルダー置換のバグが複数のサーフェスにわたって修正されました。また、レガシー互換性も向上しました。古い RPC メソッド名はエイリアスを介して処理され、設定診断パネルは正規の openhuman.* RPC メソッド (AgentBox およびツール ポリシー診断を含む) を一貫して呼び出すようになりました。
(#3706、#3870、#3792、#3655、#3875、#3926、#3927、 #3928、#3930) — @obchain、@hliebscher、@sanil-23、@Zhang、@YOMXXX、@hgunduzoglu、@oxoxDev に感謝します。

ビルド、CI、CLI、運用強化 🛠️

内部的には、CI はより効率的で信頼性が向上しています。PR CI には安定した最終ゲートとスマートなパスベースのスキップが備わり、従来のワークフローがプルーニングされ、キャンセルにより長い Rust/Tauri サブプロセスが確実に終了されるようになりました。 CLI/ランタイム側では、UNIX では SIGPIPE がデフォルトに復元され (ブロークン パイプ パニックがなくなりました)、Windows の標準エラー出力ブロークン パイプ パニックが外科的に保護され、安全なライブ JSON-RPC キャッシュ診断のための新しいハーネス キャッシュ監査スクリプトが追加されました。
(#3878、#3934、#3935、#3942、#3657、#3772、#3895) — ありがとう @senamakel @Zhang、そして @oxoxDev!

メッセージング、設定、およびエッジケースの正確さ ✅

一連の鋭いエッジ ケースがより適切に処理されるようになりました。ローカル セッションでのマネージド エンベディングはサインインを要求するようになり (ローカライズされたガイダンス付き)、LM Studio エンベディングの設定ミスでは、適切な ID を選択できるように提供されたモデル名がレポートされ、未登録の RPC メソッドの呼び出しによって設定パネルが壊れることはなくなりました。また、空の応答 UX コピーも改善され、そのオプションが存在しない場合に管理ルート ユーザーに「ローカル プロバイダーを確認する」ように指示されないようになりました。
(#3858、#3841、#3415) — @YOMXXX、@sanil-23、@CodeGhost21 に感謝します。

いくつかのより焦点を絞った貢献により、注目に値する修正と改善を対象としたこのリリースが完成します。 (#3640、#3774) — @mysma-9403 と @oxoxDev に感謝します。
