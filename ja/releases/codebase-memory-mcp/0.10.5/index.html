インストールして起動するリリース。 v0.10.4 がインストールを拒否した場合は、書き込みを拒否したことになります。 設定を変更したり、真実ではないことが判明したことを伝えたりした場合は、これを選択してください。

これらのいくつかは、cbm が独自の作業を拒否した (独自のインストーラー ディレクトリ) ケースです。 バイナリが拒否され、自分たちで作成した設定エントリが後で外部と呼ばれ、エラーが発生しました 間違ったディレクトリ名を指定したメッセージが表示され、問題のないファイルを検査するよう人々が送られました。

Windows: インストール自体が拒否されました

インストーラーは独自のバイナリ ディレクトリを作成していましたが、拒否されました。 install.ps1 は New-Item を使用したステージング ディレクトリ。%TEMP% が保持するものはすべて継承します。ダウンロードしたバイナリ は独自のディレクトリを検証し、継承されたクロスアカウントミューテーション許可を拒否します。 先ほど間違えたディレクトリを自分でチェックしてください。 Windows VM: 新しいステージング ディレクトリで測定 5 つの継承された ACE が保護されていない状態で出現しました。現在、所有者専用のエントリが 1 つだけ含まれています。

それがacl-grants-cross-account-mutation to S-1-5-21-…の故障です。 @RoccoZero によって報告されました。 @aecesr、@Kiborgik、@nasodaengineer、彼らの修正により、間違った問題を修正することができなくなりました。 二度のこと — @Kiborgik は、サンドボックス グループの name をキー入力すると、合成された SID が見逃されると警告しました @nasodaengineer は、ACE が実際に存在することを示して、オフバイワン RID 理論を反証しました。 継承された DACL 上で。 @spam0115 は独自に動作するインストーラーを作成しましたが、その決定的な行は次のとおりです。 同じicacls /inheritance:rでしたが、そのまま保管せずに私たちに返却しました。

サンドボックス アプリケーションはデーモンをブロックしなくなりました。 祖先ウォークは、すべてのデーモンを拒否しました。 %LOCALAPPDATA% 上の突然変異許可エントリ (通常のアプリケーションによって残された AppContainer ID を含む) インストールされたソフトウェア。報告されたマシンでは、ブロッキング エントリが出荷時のデスクトップに解決されました アプリケーション — ユーザーが合理的に削除できるものは何もありません。祖先コンポーネントが AppContainer を許容するようになりました パッケージと機能のアイデンティティ。プライベート ランタイム ディレクトリは正確な最新情報を要求し続けます。 ユーザー、変更なし。アプローチと祖先のみの境界は @mlandolfi90 の作業に従います。

セキュリティの検証

以下に公開されているすべてのバイナリは、スモーク アンド ソーク テストの前に VirusTotal によってスキャンされており、正確な出荷バイト数の判定は製品ごとにリンクされています (決定的なエンジン: 60 ～ 66)。 出荷された 1 つのバイナリには、文書化された単一の Microsoft 機械学習 !ml 結果のみが含まれていました。他に悪意のあるエンジンや疑わしいエンジンは報告されていませんでした。

訂正（公開後）。 上の表は当初報告されたものです linux-amd64 は Microsoft !ml 検出機能を搭載しており、darwin-arm64 はクリーンです。それは取られた 事前選択候補スキャンから。正確に出荷されたバイトの最終スキャン、実行分 その後、これら 2 つのファイルに対して 反対 の判定が返され、表にはそのことが反映されています。 最終スキャン。
