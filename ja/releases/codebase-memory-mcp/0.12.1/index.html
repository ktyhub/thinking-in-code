codebase-memory-mcp v0.12.1

コードベースメモリ mcp v0.12.1

#v0.12.1

すべてのインストール パスが再び機能し、Helm チャートがグラフに加わります。

v0.12.1 は、v0.12.0 のパッケージのインストールと、すべてのチャネルをチェックしているときに壊れていることが判明した他のインストール パスを修正します。また、Helm チャートをデプロイ対象にリンクし、グラフがコンテナー イメージのレジストリを作成するのを防ぎます。

アップグレードしていますか? アップグレード後の各既存プロジェクトの最初のインデックスは、1 回完全に再構築されます (イメージ ID が変更されます。以下を参照)。

修正: インストール

  • npm、PyPI、および Go のインストール。 npm i、pnpm add、pip install、および Go ラッパーは、どのプラットフォームにも v0.12.0 をインストールできませんでした。各ラッパーは 256 MiB を超えるアーカイブ メンバーを拒否し、すべての v0.12.0 バイナリは 331 ～ 335 MB です。 3 つのラッパーすべてでサイズ制限がなくなりました。アーカイブは解凍される前にリリースの checksums.txt と照合して検証され、その内容は予期されたファイルとまったく同じである必要があり、バイナリは --version と応答する必要があります。 @hydrplexus さん、正確なレポート (#2657) をありがとう。
  • Homebrew. 式は依然として 0.10.3 であり、Linux では動的にリンクされたビルドがインストールされました。これには glibc 2.38 が必要です (Ubuntu 22.04、Debian 12、および RHEL 9 にはそれがありません)。現在のリリースと、Linux では任意のディストリビューションで実行される静的 -portable ビルドがインストールされます。
  • go install. 固定された go install .../pkg/go/cmd/codebase-memory-mcp@vX.Y.Z は機能せず、@latest は古いバージョンをインストールしました。リリースには pkg/go/vX.Y.Z タグが付けられるようになり、ラッパーは自身のバージョンと一致するリリースをインストールします。
  • npm next. next 分散タグは古いリリース候補を指さなくなりました。安定したリリースで移動します。
  • Docs. winget と Chocolatey はインストール チャネルとしてリストされていますが、公開されていません。それらは削除されるまで削除されます。 Windows arm64 ビルドが出荷され、現在リストに掲載されています。

インストール パスのスモーク テスト。 すべてのプル リクエストとすべてのリリースで、ユーザーのパッケージ マネージャーが行う方法で、実際のリリース アーカイブに対して npm、PyPI、Go ラッパーがインストールされ、それぞれがインストールされているバイナリが実行されます。リリースはこれらのインストールが完了した後にのみ公開されるため、出荷されたものをインストールできないインストーラーはユーザーに到達できなくなります。

グラフ内の Helm チャート

Helm チャートは以前は分離されたノードでした。これで、デプロイされるものにリンクします (#2663):

  • チャート → オブジェクト (DEPLOYS、via: chart): チャートの templates/ からレンダリングされたすべての Kubernetes オブジェクト (サブチャートのオブジェクトはサブチャートに属します)。
  • 値ファイル → チャート (CONFIGURES): Chart.yaml の横にある values.yaml および values-<x>.yaml。
  • チャート → 画像 (DEPLOYS、ref: image): すべての画像には文字通りオブジェクト名が付けられます (テンプレート化された画像には名前がありません)。

HelmRelease → Chart → Deployment → Image が 1 つの通過可能なパスになりました。 20 のインフラストラクチャ リポジトリでは、発信エッジのないチャートが 260 個中 238 個から 109 個に減少し、2,511 個のチャートとオブジェクトのリンクが表示されました。他のエッジはすべて同一のままでした。

イメージはコード名をレジストリに保持します

レジストリ ホストのないイメージは、発明された docker.io/library/... (#2654) の下に保存されていました。 Docker ハブは Docker のデフォルトにすぎません。Podman と CRI-O は検索リストを通じて短縮名を解決し、ミラーはそれらを書き換えます。ローカル ビルド タグはレジストリに存在しない可能性があります。イメージは、ホストが指定されていない場合は registry: unknown と書かれた名前を保持するようになりました。指定されたホストは保持されます (Docker ハブのスペルは docker.io になります)。 FROM nginx と image: docker.io/library/nginx は 2 つのイメージ ノードになりました。これによりイメージ ID が変更されるため、アップグレード後に各プロジェクトが 1 回再構築されます。

アップグレードに関する注意事項

  • アップグレード後の各既存プロジェクトの最初のインデックスは、1 回完全に再構築されます。
  • 指定されたレジストリのないイメージ ノードは、docker.io/library/... の代わりに、registry: unknown と書かれた名前を保持するようになりました。
