コードベースメモリ mcp 0.7.0

📦 アーカイブされたリリース ページ — このバージョンのバイナリは公開されなくなりました。 最新リリース を入手してください。

v0.7.0 — 6 つの言語にわたるハイブリッド LSP、コミュニティへの貢献、フルプラットフォームの検証

🧠 見出し: ハイブリッド LSP

このリリースは、コール グラフが推測ではなくなるものです。

サポートされているすべての言語に対して、ハイブリッド Light-Semantic-Pass LSP (内部 抽出を実行するファイルごとの型認識リゾルバー) を出荷しています。スコープを追跡し、式の型を推論し、インポートを追跡し、継承を追跡し、すべての CALLS エッジで解決された呼び出し先を書き換えます。普通のツリーシッターパスでは構造グラフが得られます。 LSP パスにより、正しい呼び出し先が得られます。 6 つの言語 が恩恵を受けるようになりました。そのうちの 4 つは、このリリースで初めて LSP を取得しました。

Tier 1/2/3 アーキテクチャ (これは、それを扱いやすくする部分です)

LSP の作業は本当にコストがかかります。単純に言えば、すべての解決ワーカーがファイルごとに型付けコンテキストを再構築することになります。代わりに、次の 3 つの層で実行されます。

  • Tier 1 — cbm_extract_file 内のファイルごとの LSP: スコープ、式の型指定、ローカル解決。
  • Tier 2 — 事前に構築された言語ごとのクロス LSP レジストリ: すべてのプロジェクト定義から 1 回構築され、フォールバック ポインターを介してファイルごとのオーバーレイからチェーンされる共有読み取り専用ベース。解決策を従業員が共有します。レジストリ全体をファイルごとに再ウォークする必要はありません。 (現在、6 か国語すべてに接続されています。)
  • Tier 3 — メタデータ主導のクロス LSP (Go): ファイルごとのパスが発行する lsp_unresolved メタデータを消費し、ファイル間の AST 再ウォークを完全にスキップします。

ワイド ファイルで O(n) を作成しました

ファイルごとのすべての LSP ウォーカー (process_node、ast_sweep_shapes、apply_jsdoc_signatures、infer_implicit_returns、*_resolve_calls_in_node、および抽出側の 7 つの DFS ウォーカー) は、for (i=0; i<count; i++) ts_node_child(node, i) イディオムを使用しました。これは、tree-sitter の呼び出しごとに O(i) なので、広いルートでは O(n²) になります。 TypeScript の reallyLargeFile.ts (583k 行、ほぼすべてのコメント) のような備品がこれを壊滅的なものにしました。 新しい cbm_lsp_collect_children O(n) カーソル ヘルパーと抽出 DFS の共有 ts_nstack_push_children が、6 つの LSP すべてとエクストラクターに適用されるようになりました。 ドライラン検証の数値:

|リポ |ファイル | LSP オーバーライド |前 → 後 | |---|---|---|---| |マイクロソフト/TypeScript | 40,689 | 7,432 | 5,100 秒 → 50 秒 (フル);上級100代 | |ドットネット/ロリン | 17,916 | 91,089 |クラッシュ → 46秒 | | kubernetes (ゴー) | 20,650 | 80,818 | — → 51秒 | | WordPress (PHP) | 3,622 | 7,303 | — → 7秒 | | postgres (C) | 4,967 | 44 | — → 8秒 | |トーバルズ/Linux | 88,539 | 4,052 | — → 188 秒 (フル) / 207 秒 (LSP クロスあり) |

lsp_overrides は、「LSP がその呼び出し先を、テキスト リゾルバーが推測したよりも正確なターゲットに再帰した呼び出し」です。豊富に型指定された言語 (C#、Go、TS、PHP) の場合、これは数万件の修正になります。

途中で 2 つの実際のバグが修正されました

  • process_node は、呼び出しの引数カウントによって NULL で終了する param_types[] にインデックスを付けました。関数宣言よりも多くの引数を持つ呼び出しは、ターミネータを超えて読み取られるパラメータ → ガベージ CBMType* の deref → クラッシュ。現在は param_count スキャンによって制限されています。
  • return_type_of は、cbm_type_tuple(NULL, …) 経由でタプルの戻り値の型を構築しました。マルチリターン署名が ctx->arena を通過するようになりました。

常時オン

CBM_MODE_ADVANCED は削除されました。 LSP 解決はすべてのインデックス モード (full、moderate、fast) で実行されます。この時点でウォーカーは O(n) であり、品質 (TS では最大 4%、Go では最大 14%) はレイテンシに見合う価値があります。 "mode":"advanced" リクエストは full にフォールバックします (古い拡張モードと同じ動作のため、重大な変更はありません)。副次的な利点として、LSP ゲート オフ でのインクリメンタル実行によってサイレントに発生した 104 件の test_incremental.c 障害が解消されました。

⚡ パフォーマンス (LSP を超えて)

  • search_graph 正規表現キャッシュ + LIKE プレフィルター + 安価なカウント と、2 ステップの FTS5 サブクエリにより、数分間の search_graph query= レイテンシを排除します。作成者: Austen Constable (@awconstable) (#300 およびフォローアップ)。
  • Verstable v2.2.1 hash table (Jackson Allan による) 新しい CBMHashTable エンジンとしてベンダー化 - ホットパス解決の高速化。 14 のプロダクション呼び出し元 (graph_buffer、レジストリ、パイプライン パス、ウォッチャー、セマンティックなど) が新しい impl を透過的に取得します。
  • 7 つのツリー全体の DFS ウォーカー (呼び出し、チャネル、環境アクセス、インポート、型割り当て、変数) にわたって 抽出 O(n²) が除去されました。LSP を攻撃したのと同じ ts_node_child(node, i) イディオムです。 microsoft/TypeScript フルモード: 5,097 秒 → 50 秒 (102×)。
  • すべての解析パスにおける ツリーシッター ソース バッファ パディング - 解析境界での潜在的な良性のオーバーリードを排除します。

✅ CI とビルド

ドライラン パイプラインは、lint (cppcheck + clang-format-20)、security-static、CodeQL ゲート、テスト、ビルド、スモーク、クイック ソーク - Windows + macOS arm64/intel + linux amd64/arm64 など、すべてのプラットフォームで完全にグリーンです。

🔍 開示 (リリース準備の透明性)

CI グリーン化スイープの一部の変更は判断によるものであり、純粋な修正ではありません。レビュー担当者が再推測できるように、それらにフラグを立てます。

  1. LSP ベンチマーク (pylsp_bench_resolution_ratio、cslsp_bench_resolution_ratio) — 予行演習では CBM_SKIP_PERF の後ろでゲートされます。リリース CI (skip_perf=false) では、ASan 対応の時間予算 (サニタイザーの下で×10) で実行され、将来の予算ミスが漏洩しないようにアサートする前に結果を解放します。 通話解決率の品質は、常に CI で実行される非ベンチ test_py_lsp および test_cs_lsp スイートによっても保証されます。
  2. セキュリティ監査許可リストの拡張機能 (それぞれレビューされ、インラインで文書化されています):
    • URL ホワイトリスト: https://www.sqlite.org/c3ref/c_checkpoint_full.html — ネットワーク呼び出しではなく、store.c コメント内のドキュメント参照。
    • mcp.c ファイル読み取りしきい値が 12 → 13 に引き上げられました。 13 番目の読み取りは、更新チェック HTTP 応答 + HTTP 要求本文であり、両方とも制限されています。検索/ADR/Windows サポートのコミットから既存のもの。
    • fopen("w") 許可リストが src/foundation/diagnostics.c (アトミック .tmp + 名前変更メトリクス ダンプ) を含むように拡張されました。
  3. CBM_MODE_ADVANCED は削除されました。 "mode":"advanced" リクエストは full (常に LSP を実行します) にフォールバックするようになりました。動作は同じなので、既存の呼び出し元は影響を受けません。

⬆️ アップグレード中

"mode":"advanced" を渡す既存の呼び出し元は引き続き動作します (full へのサイレント フォールバック)。 ~/.local/bin/codebase-memory-mcp のバイナリをアップグレードした後、Claude Code を再起動して、MCP サーバーが新しいバイナリを取得できるようにします。
