codebase-memory-mcp v0.5.6

コードベースメモリ mcp v0.5.6

v0.5.6 の新機能

search_code v2 — グラフ拡張コード検索

search_code ツールは、grep 速度とナレッジ グラフ インテリジェンスを組み合わせた 4 フェーズ パイプラインで完全に書き直されました。

  • 3 つの出力モード: compact (デフォルト — 関数名 + 一致行)、full (一致が強調表示された完全な関数本体)、files (一致カウントのあるファイル リスト)
  • グラフのランキング: 結果は構造上の重要度によってランク付けされます (最初に定義、次に人気のある関数、最後にテスト)
  • ブロック拡張: grep 一致は、関数境界を含むものまで自動的に拡張されます。断片化された行スニペットはもうありません。
  • path_filter: 検索範囲を特定のディレクトリに設定します (例: src/ のみ)
  • context 行: フル モードでの一致に関する構成可能なコンテキスト
  • ディレクトリ分布の概要: 一致するディレクトリが含まれるディレクトリを表示します。 プロジェクトにインデックスが作成されていない場合は、生の grep に正常にフォールバックします。

Kubernetes とインデックス作成のカスタマイズ

Kubernetes マニフェストの完全なコードとしてのインフラストラクチャのサポート:

  • デプロイメント、サービス、ConfigMap、Secret、Ingress、CronJob、および 20 以上のリソース タイプを解析します
  • オーバーレイ解像度のカスタマイズ (ベース→オーバーレイ関係)
  • リソース ノードは、ラベル、名前空間、コンテナ仕様とともにナレッジ グラフに表示されます。
  • グラフ スキーマの新しい Resource ノード ラベル

ユーザー定義の拡張マッピング

カスタム ファイル拡張子 → .codebase-memory.json (プロジェクト レベル) または $XDG_CONFIG_HOME/codebase-memory-mcp/config.json (グローバル) による言語マッピング:

{"extra_extensions": {".blade.php": "php", ".mjs": "javascript"}}

プロジェクト設定はグローバル設定よりも優先されます。

セキュリティ修正

  • ストア検索/BFS での SQL インジェクション および HTTP サーバーでの引数インジェクション (#124 — @map588)
  • Use-after-free (handle_manage_adr のパスを取得) (#126 — @halindrome)
  • ゴースト .db ファイルの防止: クエリ ハンドラーは SQLite を開く前にプロジェクトの存在を確認するようになりました — 空のデータベース ファイルが蓄積するのを防ぎます (#120)
  • バイナリ置換: unlink-before-write パターンを備えた新しい cbm_replace_binary は、読み取り専用ターゲットと Windows の名前変更回避フォールバックを処理します (#114)

安定性と互換性の修正

  • MCP stdio バッファリング: 一部の client で tools/list がハングする原因となっていた poll()/getline() FILE* の不一致を修正 (#99 — @halindrome)
  • SQLite WAL Busy_timeout: ロック競合時の SQLITE_BUSY を防ぐために journal_mode=WAL の前に設定 (#117 — @halindrome)
  • インポート パーサー O(N²) → O(N): インデックス付き ts_node_child() ループを TSTreeCursor ウォークに置き換え — インポートが多いファイルの二次関数の速度低下を修正 (#107 — @halindrome)
  • セッション プロジェクト名が一致しません: detect_session はパイプラインとして同じ cbm_project_name_from_path() を使用するようになりました
  • Windows: UI zip ファイル名の修正、setenv/unsetenv 互換ラッパー、HOME が設定されていない場合の USERPROFILE フォールバック
  • Linux: strcasestr の可視性のために -D_GNU_SOURCE を追加 (#111 — @trollkotze)
  • libgit2: -Wmissing-field-initializers ビルド エラーを修正 (#91 — @jsyrjala)
  • メモリ リーク: delete_project の後にリンクされていない .db をクエリすると、resolve_store で SQLite 接続がリークしました。

包括的な煙テスト

4 フェーズから 7 フェーズに拡張され、バイナリ ライフサイクル全体をカバーします。

  • フェーズ 5: MCP stdio トランスポート - ハンドシェイク、ツール/リスト、ツール呼び出しラウンドトリップ、Content-Length フレーミングの初期化 (OpenCode 互換性)
  • フェーズ 6: CLI サブコマンド — --dry-run のインストール/アンインストール/更新、構成の設定/取得/リセット、読み取り専用のエッジ ケースでのバイナリ置換のシミュレート
  • フェーズ 7: MCP 高度なツール呼び出し — search_code v2、JSON-RPC 経由の get_code_snippet スモーク テストは、Docker テスト インフラストラクチャ (test-infrastructure/run.sh smoke) および CI で、10 のプラットフォームとバリアントの組み合わせすべてで実行されるようになりました。

更新コマンドの改善

  • --dry-run フラグ: ファイルをダウンロードまたは変更しない場合に何が起こるかを示します。
  • --standard / --ui フラグ: 対話型バリアント プロンプトをスキップ (CI フレンドリー)
  • アップデート成功後の再起動リマインダー

CI とインフラストラクチャ

  • SHA をコミットするためのピン留めされた GitHub アクション (依存ボット: VirusTotal 5.0.0、setup-node 6.3.0、cosign-installer、attest-build-provenance)
  • Docker テストインフラ: ローカルクロスプラットフォーム煙テスト用の smoke および smoke-amd64 サービス
  • Go 時代のアーティファクトをクリーンアップし、純粋な C プロジェクト用に THIRD_PARTY.md を更新しました
