コードベースメモリ mcp v0.11.0

#v0.11.0

大規模なリリースであり、異常にコミュニティが多いリリース: 171 件のプル リクエスト がマージされて以来 v0.10.8 (そのうち 9 件は依存関係のバンプ)、そのうち 76 件はメンテナー以外の貢献者によるもの。 ありがとう — このリリースは主にあなたの作品です。別の0.10.xではなくマイナーバージョンです インデックス形式が移動し (下記の 1 回の再構築)、ツール出力コントラクトが変更されるため、パッチを適用します。

v0.11.0 が存在する理由は、インストール、アンインストール、デーモン起動の信頼性とメモリです。 インストールを拒否したことがある、完全にアンインストールすることを拒否したことがある、理由を告げずに起動時に停止したことがある、または 大規模なリポジトリのメモリ バジェットを使い果たした場合、これをリリースする必要があります。

アップグレードする前に知っておくべき 2 つのことと、気づくことが 1 つあります。

ハイライト

アップグレード後の最初の実行では、インデックスが 1 回再構築されます

これは予想通りです。これはエラーではなく、何も失われません。

PR #1104 (feb72080、@LA-10 作) により、#1108 からのファイル ノードの変更が完了します: ファイル ノードの 修飾名はそのファイル拡張子を保持するようになり、同じディレクトリ内の auth.py と auth.ts は 最終的には、1 つの名前で衝突するのではなく、個別のノードが生成されます。これにより、ディスク上のインデックス形式が変更されます そのため、v0.10.8 以前で構築されたインデックスには、衝突した古い ID が保持されます。

適切な場所に移行するのではなく、衝突した古いデータベースは失われた兄弟を再構築できません。 cbm は PRAGMA user_version にフォーマットをスタンプし、古いフォーマットのインデックスを 1 つの完全なインデックスから取得します。 インデックスを再構築。 ADR とインデックス メタデータは全体にわたって保存されます (#516)。その 1 回の実行の後、 スタンプは最新であり、増分インデックス作成は通常どおり再開されます。

表示される内容: 実行後の最初の index_repository (または最初のウォッチャー/デーモンによってトリガーされるインデックス) アップグレードには、通常の増分ではなく、そのリポジトリのコールド インデックスと同じくらいの時間がかかります。 秒。大きなモノレポだとそれを感じるでしょう。その後はすべて再び増分されます。

最初の実行では orphan_removed 行が 1 つ表示される場合もあります。これは #2111 の新しいスイープ クリアです。 古いバージョンで強制終了されたワーカーが残したステージング ファイル。無害でもありますが、 一度。

無駄のない、ロスのない出力 — 見つけやすさは維持され、機能は削除されません

PR #1597 (3909e5a0) は、デフォルトで CLI および MCP 応答をコンパクトにします。何について明確にするために これはではありません: どのツールも削除されず、以前にクエリできたフィールドもアクセスできなくなりました。 答えを見つけるのが難しくなりました。変わったのは、運用の詳細が明示的なフラグの背後に移動したことです。 パラメーターがあり、デフォルトの応答にはグラフの応答自体が含まれます。

デフォルトの応答に保持され、常に次のようになります。

  • グラフ行とノード ID
  • 「約 N」ではなく、正確な合計
  • 切り捨て状態なので、いつサブセットが表示されているかを常に知ることができます
  • 省略されたすべての継続カーソル

明示的なオプトインの背後に移動: 診断、証拠列、進行状況のチャット、および JSON 出力。

コンパニオンを2人変更すると契約が完了します。 14c229b1 は ロスレス セマンティック ページネーション を追加します — max_output_tokens は、全体をカットする決定論的でモデル中立のバイト上限として適用されます。 レコードの途中でバイトをスライスする代わりにセマンティック単位を使用し、すべての省略は独立してページング可能です。 カーソルはクエリ引数、結果の状態、インデックス生成にバインドされているため、 カーソルは、別のスナップショットをサイレントにページングするのではなく、失敗して閉じられます。 4a9fcd97 は明示的な スクリプト用の静かな CLI モード。 同じシリアル化された MCP tools/list フィクスチャで測定: 23,075 → 15,071 バイト (−34.7%)、および cl100k / o200k トークン数の -31.4% / −30.7%。パスが繰り返される結果テーブルの場合、応答ローカル ディレクトリプレフィックス圧縮は、38.3% (Unix パス) および 44.5% (Windows パス) によってトークン型出力をカットします。 圧縮しても効果がない入力は圧縮されないままになるため、応答は大きくなりません。

ソース内の無効な UTF-8 は置き換えられるのではなく、元に戻せるように保存され、コード検索が行われるようになりました。 BusyBox/Alpine への移植性を維持するグロブを含む、正規にインデックス付けされたファイルにスコープされます。

メモリ: 予算は尊重され、インデックスに必要なメモリははるかに少なくなります。

PR #2202 は、インデクサーのメモリを 1 つの割り当てコアに移動し、CBM_MEM_BUDGET_MB を ヒントではなく約束。インデックスが予算に近づくと、ファイルごとの完成結果は次のようになります。 ディスク上に保存され、後のパスで読み取られる瞬間だけロードバックされます。その後のフェーズ 抽出されたものをすべて継承するのではなく、フロアから抽出を開始します。の セマンティック パスは、ワーキング セットのサイズを左のヘッドルームに合わせます。予算が動かせないものはグラフです #2112 で説明されているように、グラフ自体のサイズを下回る予算でも完全に失敗します。

v0.10.8 と同じマシンの Linux カーネル (8.5 M ノード) で測定: デフォルトの予算 (24,576 MB) は実行を中止するために使用されます。これでこぼれることなく完成しました。 16,000 MB と 15,000 MB はスピル パスを通じて完了し、充電されたメモリのピークは 14.6 ～ 14.7 GB になります。 そしてグラフは同じです。私たちがベンチマークを行った 10 個の LSP コーパスでは、ピーク メモリが次の期間に低下しました。 40% および 80% (17.2 → 3.9 GB、Java 27.6 → 11.0 GB、C# 27.0 → 11.2 GB、TypeScript 12.0 → 2.5 GB) v0.10.8 より遅いコーパスはありません: C# のインデックス作成には 463 秒ではなく 128 秒、カーネルには 233 秒かかります 295秒の代わりに。

プルーフランと同じリリースで出荷されたものから 3 つのことが除外されました。

  • ファイルごとの CPU バジェットは、解析だけでなくファイル全体をカバーします。 病的なファイル ( ドットネット/ランタイムでの 23 MB の単一式 JIT テスト、いくつかの汎用ネスト ストレス テスト) 作業員を数分間保持して使用状況を確認します。彼らは今、予算内で止まり、以前のものを維持します 抽出され、パスごとに記録されたタイプ認識ウォークをスキップします。
  • 大規模な C/C++ ツリーでのファイル間解決のクラッシュが修正されました: C++ クラス ウォークは ファイルごとのスクラッチ署名を共有タイプ レジストリに保存し、後で別のワーカーがそれを読み取る ファイルのメモリがなくなっていました。 dotnet/runtime 上のサーバーの ASan ビルドで見つかります。の 現在、レジストリはコピーオンライトであり、テストによってコントラクトが保護されています。
  • macOS でのロケールフリーのフォーマット: すべての vsnprintf がプロセス ロケール ロックを取得し、 18 人のワーカーが、その上でシリアル化された型名をフォーマットしています。各スレッドは次のロケールでフォーマットされます。 今はそれ自体です。

デーモンと CLI の動作は変わりません。 3 つのプラットフォームすべてで 30 分間の浸漬 連続した状態でフラット メモリ ライン (Linux 11.6 MB、macOS 17.4 MB、Windows 16.8 MB) を保持します。 クエリ。

アップグレードに関する注意事項

  • 最初の実行時に 1 回の完全なインデックス再構築。 上記を参照してください。インデックスごとに 1 回、ADR が保存されることが予想されます。
  • 新しい <db>.stage.*.lock サイドカーは、インデックスの実行中にデータベースの横に表示されます (#2111)。 これは、cbm が生きているライターと死んだライターを区別するための所有権マーカーです。削除されるとき 走行が終了します。
  • 予算超過インデックスが最初に流出し、その後ソフト オーバーシュートではなく完全に失敗します (#2202、 #2112)。予算に近い場合、完成した結果は残りのディスクの <cache>/spill/ の下に保存されます。 走っても走っても、通常はフロアで終了します。グラフだけで予算を超える指数 reason:"over_memory_budget" と名前付き budget_mb / peak_rss_mb できれいに停止します。 以前に提供していたインデックスはバイト同一のままです。ヒットした場合は CBM_MEM_BUDGET_MB を上げる — メッセージは変数に名前を付けます。
  • 設定ファイルの変更は必要ありません。

インストールと信頼性に関する修正

Windows 10 がまったくインストールできませんでした

#2188 (042a58bb、#1856 の報告者によって報告および診断)。 install.ps1セット 無条件でSecurityProtocol = Tls12 -bor Tls13。 Windows 10 の schannel には TLS 1.3 がありません。 Windows 11 および Server 2022 (ビルド 20348) でリリースされますが、.NET Framework 4.8 は依然として enum 値なので、割り当てはサイレントに成功し、最初の HTTPS リクエストは次のように終了しました。 The request was aborted: Could not create SSL/TLS secure channel。その中のサポートされていないフラグ bitmask はハード障害であり、ダウングレードではありません。 すべての Windows 10 マシンがこれに該当します。 プロトコル セット が計算されるようになりました: TLS 1.2 は常に、TLS 1.3 はビルド 20348 以降でのみ、enum-name プローブを使用します。 スクリプトは .NET Framework 4.7 で引き続き解析されます。

同じ PR により、アクティベーションの拒否がアクション可能になります。以前は「上記のエラーを確認してください」と印刷されていました その上には何もありません。拒否したチェックの名前が表示され、違反した ACE が 継承し、その場合に実際に機能する救済策を提供します (icacls <dir> /inheritance:r /grant:r "%USERNAME%":(OI)(CI)F — /remove:g は、 ACE を継承しているため、拒否が続いているにもかかわらず、古いアドバイスが成功したように見えたのはそのためです)。 安全性チェックは緩和されていません。他のアカウントが書き込み可能なインストール ディレクトリは引き続き拒否されます。 行動できるようになりました。

昇格された非標準の Windows インストール

#2139 (1b067e3b、クローズ #1705、#2023、#1686)。管理者特権によって作成されたランタイム ディレクトリ アカウントの名前が変更された場合でも、プロセスはマシンの組み込み管理者アカウントによって所有されます。 または無効になっています - そして CBM がそれを拒否したため、それらのマシンではインストールとアクティベーションが完全に失敗しました。 CBM このマシン の組み込みの管理者 SID を (ローカル SAM アカウント ドメイン経由で) 解決するようになりました。 trust そうです。意図的に末尾の RID-500 と一致しません: ドメイン管理者の -500 または別のマシンの 管理者はまだ外国人なので拒否されています。これとは別に、以前は所有者trustが拒否していました ベア status -3, os 0 を報告すると、パスに沿って問題のある所有者の SID が指定されるようになりました。

デーモンの起動失敗により、何が起こったかがわかるようになりました

#2113 (91bee4fb、#1828 を終了)。デーモンを開始できませんでした — /tmp がフルです 報告されたケース — 誤解を招く 30 秒の「アクティブまたは開始中」タイムアウトが報告されましたが、原因はありませんでした。毎 リスナーステージには stage=、errno=、path= が含まれるようになりました (たとえば、 stage=pending_publication errno=ENOSPC path=/tmp/cbm-daemon-<uid>/…)、そして運命のスタートが今始まる CBM daemon failed to start: <stage> failed with <errno> at <path> として約 1 秒で表面化します 期限を完全に過ぎてから間違ったことを報告するのではなく。

#2138 (055fbb7d、#1830 を終了)。シングル UID ユーザー名前空間内 (unshare -U --map-current-user、podman --userns=keep-id) ルートが所有するトップレベルの祖先 カーネル オーバーフロー UID によって所有されているように見え、デーモンはその完全に正当な UID での起動を拒否しました。 セットアップ。オーバーフローが所有する 祖先 が受け入れられるようになりましたが、/proc/self/uid_map が本物である場合に限ります。 単一 UID マップとオーバーフロー UID は /proc から読み取られます (ハードコーディングされません)。ディレクトリ 実際にはデータを保持するには依然として厳密な == geteuid() 所有権が必要なので、宛先はもう必要ありません 以前より寛容になりました。環境脱出ハッチはありません。

アンインストールが完了し、何も残らないようになります

#2110 (b790be3d、#1954 の実行可能ファイル/インデックス半分を閉じます)。 uninstall は以前は中断していました 何かを削除する前に、最初の エージェント構成クリーンアップ エラーが発生しました。つまり、拒否された mcp.json が残されました。 約 300 MB のバイナリとディスク上のキャッシュ全体。すべてのエージェントのクリーンアップを実行し、失敗を収集し、 インデックスとバイナリを削除し、ゼロ以外の設定ファイルを正確にリストして終了します。 掃除されるべきです、そしてその理由。

同じ PR により、4 つの構成エディターが ユーザー所有のシンボリックリンクされた構成ファイルに従うことができるため、 stow/dotfiles ~/.cursor/mcp.json -> … は完全に拒否されなくなりました。コミットを書き込みます 親ディレクトリ ハンドル上の renameat であるため、シンボリックリンクは存続します。ターゲットは編集されますが、決して編集されません。 交換されました。他の所有者のリンク、ダングリング リンク、ディレクトリへのリンク、および世界中で書き込み可能な親はそのまま残ります。 拒否した。

#2060 (cc6743e9、@TheStranjer 作、参照番号 #1722) は、同じ問題の半分のディレクトリです。 ユーザー所有のディレクトリのシンボリックリンクである ~/.config/opencode -> /mnt/… により、OpenCode のすべての書き込みが次のように失敗します。 不透明な agent_config エラー。親チェーンのウォークは、呼び出し側が所有するシンボリックリンクをたどるようになりました。 user — Linux カーネルの fs.protected_symlinks が適用されるルールで、到達できないルール ユーザーがまだ直接書き込めなかったもの。同じ PR 内のフォローアップ コミットは、 i ノードに対する所有権の判断は実際に行われ、呼び出しサイトごとに次のようなオプトインを行います。

#2137 (a0dc4183、#2054 を終了)。インデックスの削除 - cbm update、cbm uninstall、および install --reset-indexes — 各 *.db のリンクを解除しましたが、その SQLite -wal / -shm / -journal のリンクは解除しませんでした サイドカーなので、明示的に削除すると孤児が取り残されます。現在、それらはすべて削除されています。 データベースが存続しなくなった孤立した -wal。

また、この領域では、アンインストール時にインストール ディレクトリが Windows ユーザー PATH から削除されます。 (#2117); YAML 構成リムーバーは、すでに存在しない構成に対して OK と応答するため、アンインストールは行わなくなります それを拒否します (#2059、@dgilperez)。 OpenHands の統合は次のように完了します。 settings.json mcp_config とエージェント プロファイル参照 (#2116、参照 #1826)。

OOM によって強制終了されるのではなく、素直に停止されるインデックス作成

#2112 (1d665384、クローズ #1997、#832、および #1973/#1864 の OOM 半分)。インデックスメモリ 予算は勧告でした。バックプレッシャー制限を超えると、パイプラインは soft_overshoot を記録し、維持されました。 カーネルが OOM でワーカーを強制終了するまで作業を許可し、その後スーパーバイザがファイルのせいにしました。 予算超過の試みは 1 回の確認サイクル後に 完全 に失敗し、ステージングが破棄されるようになりました。 reason:"over_memory_budget" を previous_index:"preserved"、budget_mb、peak_rss_mb とともにレポートします そしてCBM_MEM_BUDGET_MBという名前のヒント。以前に提供されていたインデックスはバイト同一であり、 index_status は引き続きサービスを提供します。単独のワーカーが総予算全体を使用できるようになりました。同時 ジョブはそれを分割するため、フェイルホールが単一ジョブのホストに影響を与えることはありません。 Windows では、ワーカーのコミットも次のように制限されます。 その予算のジョブ オブジェクト (#2030、@Subgurim) なので、OS はパイプラインの上限を強制します。 約束。

自身の後にクリーンアップするファイルをステージングする

#2111 (dd454b23、クローズ #1839、#1864)。 1 つの領域に 3 つの欠陥がある: ネストされたパイプライン <db>.stage.A.stage.B パス。実行中にワーカーが死亡したため、ステージング ファイルが残され、何も消去されませんでした。 そして 最初の インデックスは、自身の空の整合性チェック中に恐ろしい invalid_existing_db を出力しました。 プレースホルダー。内部ステージは兄弟となり、すべてのステージは専用の .lock を通じて所有されます。 サイドカー、死んだ作家の孤児は各実行前に一掃されます (生きている作家は保持されます)。 インデックスは no_existing_db として正しくルーティングされます。 invalid_existing_db は現在予約されています。 整合性に欠けるインデックス。

起動とデーモンの安定性

サンドボックスまたは別のホームにインストールしても、実際のデーモンを提供するデーモンが停止しなくなりました (#2115)。アクティベーション ガードは、インストールが実際にどのコホートを置き換えるかを解決するようになりました。 サンドボックスまたは外部ホームのインストールでは、ホストのセッションはドレインされずに実行されたままになります。 以前は、1 つの HOME の下にインストールすると、アクティブな HOME の下から無関係なデーモンが静止する可能性がありました。 エディターセッション。

3 つのフレークの根本原因が隠蔽されるのではなく修正されました。HELLO の寒冷嵐の最中のレーサーは現在、 一時的な世代 (#2179)。ツリーシッター解析は、スレッド CPU 時間によって予算が設定されます。 壁掛け時計なので、ロードされたマシンは暴走した解析のようには見えなくなります (#2180)。および Windows セッション ルートは、ポリシー ルートを書き換えることなく、区切り文字で同等に比較されます。

この領域の貢献者によるさらなる修正: 放棄されたリクエストからのゾンビの生成が含まれ、 ミュート エンドポイント ホルダーには (#1920、#1921、@OhOkThisIsFine) という名前が付けられます。 Unicode セッション ルートは次のとおりです。 Windows で受け入れられます (#1876、@ertankucukoglu)。拒否された UI 構成は報告されなくなりました デーモンの起動に失敗した場合 (#1796、@liuchong); client セレクターがレジストリに適用されます 統合 (#1802、@rarepops); --clients は CLI ヘルプ (#1800、 @kilianpaquier); OMP エージェント ディレクトリが尊重され、指示が保存されます (@DavidHLP)。拡張フックは入力引数を受け取り、ツール検索はサブエージェントで機能します。 (#1933、@Chewji9875); PowerShell 5.1 stderr ラッピングでバージョン プローブが中止されなくなりました (@MasterFede5 により #1255 から蒸留)。

  • インデックス ワーカーのスコープは、デーモンの環境ではなく、リクエストのリポジトリに限定されます (#2076): 複数のリポジトリにサービスを提供するデーモンは、そのリポジトリ独自のスコープで各インデックスを実行します。

162 言語 (v0.10.8 の 158 言語から増加)、client サーフェスは 45 言語 (43 言語から増加)。

新しい言語:

  • Chialisp、ファーストパーティのツリーシッター文法を使用 (#1888)。 PR #919 から蒸留 @darkverbito、これはその CLVM 抽出ロジックに基づいて構築されています。

抽出とカバレッジの改善:

  • CFML タグ方言 — .cfc タグ方言ルーティングと組み込み <cfscript> 内の定義 (#1872)、@allanoepping によって #1412 から蒸留されました。表面上のものではなく、本当のリコールの穴です。
  • Blazor および Razor — .razor ファイルは C# (#1824、@The1nk)、@page として検出されます。 ディレクティブは Route ノード (@The1nk) を発行し、Razor Pages / MVC .cshtml ビューが検出されます そしてルーティングされました。
  • SQL は、FROM/JOIN リネージと dbt モデル リネージを持つファーストクラスのテーブル ノードとビュー ノードを取得します は、Jinja テンプレート SQL を通じて抽出されます (両方とも @alexisperinger-ux を使用)。
  • Pkl は呼び出し、分岐、スロー、デコレータを取得します (#1426、@tthayer)。
  • Svelte、HTML、Astro インライン スクリプト はスキップされるのではなく構造を生成するようになりました。 (#2056、@bmcnaboe)。
  • Go: 空白の識別子構造体フィールドはスキップされ、field_declaration_list が派生します。 a bare reference never binds a struct Field, and USAGE/WRITES/READS are guarded against 言語間のバインド (#1937、#1938、#1940、#1944、#2006、すべて @ilyabrykau-orca)。
  • Swift call arguments are reached through call_suffix (#1896, @CaptainMittens).
  • Elixir は、first_string_arg (#1721、@henry-hz) を設定するように呼び出します。
  • TypeScript dotted import basenames are preserved (#1811, @pcristin).
  • Cross-file base-class resolution in the Python/TypeScript cross-LSP.
  • 散文は、@ShauryaaSharma** を使用して、nodes_fts 本文列を介して BM25** にインデックス付けされます。
  • インデックス時の重要度スコアリング (重み付け度)、@petercoxphoto を使用。
  • アンサンブル運用トポロジ ルーティング (#1063、@isc-tdyar)。
  • VB6 .frm/.cls ファイル は、FORM および Apex 文法に含まれなくなりました (#2074、@Tokarzewski)。
  • Route extraction finds a path wherever it sits in a decorator's arguments and takes the 最初の引数ではなく、最後の引数のハンドラー (#2008、#2009、@CaptainMittens)。
  • Cypher は、間違った回答をする代わりに、受け入れられないもの、つまりパーサーが対応しなかったクエリを拒否します。 fully read, a WITH wider than its binding, a name that is not in scope, and an unnamed head node 変数キャップに対してカウントされるようになりました (#1875、#1918、#1922、#1998、@CaptainMittens)。 variable-length path semantics are enforced (#883, @jstar0).
  • 読めない値がもっともらしい値にならなくなる — 自信、環境設定、そして span timestamp that cannot be read no longer silently become 0.0, a wrong default, or a real 期間 (#1877、#1880、#1881、@CaptainMittens)。
  • AST traversal stacks no longer outlive the file they walk (#2013, @shafty023).
  • Weak Python member calls are suppressed, distilled from #1324 by @Enferlain.

New tooling: a bounded file outline tool and a bounded graph comparison tool, manage_adr mode='set_sections' for splicing ADR sections instead of rebuilding the document, グラフ拡張 Bash ツール検索 (#1337、@abendrothj)、watcher_enabled マスター スイッチ (#1105, @nguiaSoren, closes #335), and artifact hashes reconciled against git on bootstrap.

新しいプラットフォームとサーフェス: CLI、デーモン IPC、およびランタイムにわたる NetBSD サポート (#1342、 @cmeerw); FreeBSD ${LOCALBASE}/bin は sysctl による自己解決を備えた pkg 管理として扱われます (#1777、@ocochard); Grok Build をインストール ターゲットとして使用します。 Oh My Pi (omp) (#1229, @DavidHLP); the OpenCode plugin extended to every documented context surface (#1487, @JCVIDev); UI 埋め込み Nix フレーク パッケージ (#1089、@mipmip) および macOS クロスアーキテクチャ Nix 開発シェル。 the UI showing its serving binary version (#2016, @rarepops) and enumerating cbm processes correctly on Windows (#955, @EightDoor).

パフォーマンス

  • C++ 短縮名の型検索はスキャンではなくインデックス付けされます (#1679、@astandrik)。 2 つの短縮名インデックスを統合するフォローアップ。
  • カバレッジはファイルを再スキャンする代わりにテーブル検索によって行を見つけます。 範囲が重複し、EOF を超えた行 (#1941、#1971、@CaptainMittens、#963 を閉じます)。
  • サフィックス グロブは、検索スコープの構築後ではなく、構築中にフィルタリングされます (#1836, @ertankucukoglu)。
  • 出力圧縮におけるプレフィックス ディレクトリ スコアリングは、パス数において二次関数ではなくなりました。
  • No-op Bash 呼び出しは、拡張フックの ID ハッシュの前にゲートされます (#1337、 @abendrothj)。
  • アイドル メンテナンスはデーモンで 2 回ポーリングしなくなりました。
  • 解析バジェットはスレッド CPU 時間で課金される (#2180) ため、ビジー状態のマシンによってトリップされることはなくなりました。 決して遅くない作業に予算を投入します。
  • ファイルごとのバジェットは、抽出ウォークとタイプ認識ウォークをカバーするようになりました (#2202)。 病理学的ファイルはもはや労働者を数分間保持することができません。 dotnet/runtime 上の C# のインデックス作成は 3.6 倍高速です。
  • SQLite はインデックス ワーカー内の独自のヒープから割り当てます (#2202): カバレッジ パブリッシュ カーネルのステップは 132 秒から 9 秒に、カーネル全体のインデックスは 295 秒から 233 秒に短縮されました。
  • ワーカー グラフ バッファーは ID 空間全体にわたって密な ID テーブルを保持しなくなりました (#2202)。 スピル パスは、キャッシュされたすべての結果を解決前にパークします。 15 GB の予算でカーネルにチャージされたメモリ ピークは 16.8 GB ではなく 14.7 GB になります。

抽出と解決

  • URL ビルダー ヘルパー呼び出しは Route / HTTP_CALLS エッジ (#1010、@CharlesQueiroz) に解決されます。 非 HTTP スラッシュ引数は、偽のルートを生成しなくなりました (#1389、@Yyunozor)。
  • 動的エッジのプロパティは JSON (#1065、@tmonestudio) としてエスケープされます。
  • EOF の末尾の空白行は、欠落した定義ではなく、欠落した改行としてカウントされます (#1773、 @rarepops、#1746 を閉じます); Docker ファイルの末尾の空白 (#1853) についても同様です。
  • Ruby スーパークラス名は裸のままです (#1709、@benrfairless)。
  • Swift プロトコルのメソッド要件はメソッド ノード (#1763) としてインデックス付けされており、Swift try! 文法エントリが独自の型を超えて移動しなくなりました (#1986、@CaptainMittens)。
  • Go クロスパッケージ フィールド チェーン呼び出しは、タイプ ディスパッチ (#1939、@xkchok) を介して解決されます。
  • Rust は Cargo コンテキストを並列解決 (#1850) で維持します。 Python はシャドウイングされたベアコールを抑制します 囲みパラメータ (#1912) によって。
  • 受信側チェーンが矛盾する名前のみのレジストリ一致は拒否されます (#1897、 @CaptainMittens)。
  • シンボリックリンクのスキップは、無視されたファイル分類 (#1822、@AmirF194) およびファイルを通じて報告されます。 そのエクストラクターの終了値が 0 以外であるものは、チャンク全体を中止する代わりに隔離されます (#1438、 @shashwatMishra96)。
  • 複雑さのパスはワーカー ID の順序とは独立しており (#2079)、関数の並べ替えはスキップされます。 グラフに関数がない場合 (#2083)。
