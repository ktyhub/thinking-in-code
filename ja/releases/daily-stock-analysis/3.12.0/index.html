daily_stock_analysis v3.12.0

マイナー 公開日2026年4月1日 出典ZhuLinsen/daily_stock_analysis 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

デイリーストック分析 v3.12.0

リリースのハイライト

  • 📊 新しい「翌日検証」ビューがバックテスト ページに追加されました - AI 予測と翌日の実際の上昇と下落を株価および日付範囲ごとに表示し、過去の分析と 1 日のバックテスト結果を再利用して、分析の精度を迅速に検証できます。
  • 🔧 簡素化された LLM アクセス エクスペリエンス — ユーザー側のコピーライティングは「メイン モデル/代替モデル/モデル チャネル」として統一され、LiteLLM は一般ユーザーにとって習得が必須の概念とは見なされなくなり、既存の構成キーは互換性を維持します。
  • 🐳 Docker / WebUI ランタイムの定常状態の強化 — コンテナ化されたデプロイメントの運用とメンテナンスの負担を軽減するために、システム設定を保存した後に構成が有効にならない、初期起動ログの欠落、事前構築された静的リソースの再利用などの問題を修正しました。
  • 🔒 セキュリティと同時実行の安定性が同時に強化 — Discord インバウンド Webhook は Ed25519 署名検証を完了し、同時実行中に共有ステータスがロックされない、単一共有プッシュ モード通知の同時再利用などの問題を修正します。
  • 🖥️ デスクトップとスケジュールされたタスクの詳細が洗練されました — Windows インストーラーはカスタム インストール ディレクトリをサポートし、組み込みのスケジュールされたスケジューラーは操作中に SCHEDULE_TIME の変更を検出し、市場のタイム ゾーンに基づいてダウンロードを再開します。

新機能

  • 📊 バックテスト ページに新しい「翌日検証 / 1 日ウィンドウ」ビューが追加 - AI 予測、翌日の実際の上昇と下降、銘柄コードと分析日付範囲ごとのスクリーニング範囲の精度を表示し、過去の分析と 1 日のバックテスト結果を再利用できます。
  • 🏷️ 新しいバージョン情報カードが Web 設定ページに追加されました — apps/dsa-web はビルド時にフロントエンド パッケージのバージョンとビルド時間を挿入し、WebUI 版本 / 构建标识 / 构建时间 を表示する新しい読み取り専用の「バージョン情報」ブロックがシステム設定ページに追加されます。 package.json がまだプレースホルダー バージョン 0.0.0 である場合、自動的にビルド ID にフォールバックするため、Docker は現在の静的リソースが再構築後に有効になっているかどうかを迅速に確認できます。
  • 🪟 Windows デスクトップ インストーラーは、自己選択のインストール ディレクトリをサポートします - インストーラーは、インストール ウィザードでのインストール ディレクトリのカスタマイズをサポートするようになりました。デフォルト以外のドライブ文字にインストールした後も、インストール不要の配布方法 win-unpacked を維持しながら、既存のパッケージング ディレクトリ ロジックを使用して、インストール ディレクトリの隣にある .env、data/stock_analysis.db、および logs/desktop.log の読み取りと書き込みが行われます。インストーラーは現在のユーザーのインストールのみをサポートし、管理者権限の昇格が無効になっており (allowElevation: false)、NSIS .onVerifyInstDir を介したシステム保護ディレクトリの選択をブロックします。

改善点

  • 🔎 SerpAPI テキスト取得範囲の収束 - 自然検索結果は、Web ページのテキストを 1 つずつ同期的にクロールしなくなりました。現在では、明らかに不十分な概要を含むごく少数の上位の結果のみが、より短いタイムアウト バジェット内で遅延され、SerpAPI によって返される構造化された概要が優先されることで、検索リンクの末尾の遅延とサイトの増幅が遅くなるリスクが軽減されます。
  • 🤖 簡素化された LLM アクセス エクスペリエンス — ユーザー指向の AI モデルのアクセス コピーは、「メイン モデル / エージェント メイン モデル / 代替モデル / モデル チャネル / アドバンスト モデル ルーティング構成」に統合されました。 Web 設定ページ、構成メタデータ、検証プロンプト、および中国語と英語のドキュメントでは、LiteLLM が一般ユーザーにとって必須のデフォルトの概念とは見なされなくなり、既存の LITELLM_* / LLM_CHANNELS 構成キーは互換性を維持します。

修正

  • 🚀 初期起動が失敗した場合に本当の根本原因を明らかにする — python main.py は stderr を通じて本当の根本原因を公開するようになり、ブートストラップ フェーズではファイル ログがハードコードされた logs/ ディレクトリに書き込まれなくなり、正常な起動時に予期しないパスにログ ファイルが残らないように、config.log_dir が利用可能になるまでファイル ログは延期されます。
  • 🐳 Docker WebUI ランタイムは、事前に構築された静的リソースを優先的に再利用します — prepare_webui_frontend_assets() は、イメージ内の既存の static/index.html が直接再利用できるかどうかを確認します。コンテナーに apps/dsa-web ソース コード ディレクトリが含まれず、npm がインストールされていない場合、「フロントエンド プロジェクトが見つからないため、自動的にビルドできません」という誤った報告が行われず、デプロイ後に Docker の WebUI を開く機能が復元されます。
  • 🐳 Docker WebUI システム設定が保存された後に構成が有効になります - WebUI が Docker シナリオで STOCK_LIST、SCHEDULE_ENABLED、SCHEDULE_TIME、SCHEDULE_RUN_IMMEDIATELY、および RUN_IMMEDIATELY を保存した後、Config は、永続的な .env の新しい値の読み取りを優先して、コンテナが作成されました。
  • 📈 マーケット レビュー LLM max_tokens の改善 — マーケット レビュー生成リンクは、LLM max_tokens を 2048 から 8192 にアップグレードし、MAX_TOKENS により長いレビュー出力が事前に切り捨てられ、不完全なコンテンツになる可能性を減らします。
  • ⏰ 組み込みのスケジュールされたスケジューラが SCHEDULE_TIME の実行時の変更を検知 — スケジューラは、WebUI が実行時に保存された後に SCHEDULE_TIME の変更を検知し、次のチェック ラウンドで毎日のジョブを再バインドします。
  • 🪟 Windows リリース チャネル エディターは MiniMax モデル プレフィックスを保持します — チャネル モードで minimax/<模型名> を入力すると、モデル リストはバックエンドの正規化ページおよび Web 設定ページでの実行時の値をそのまま保持し、誤って openai/minimax/<模型名> として書き換えられることはなくなります。
  • 🤖 Discord インバウンド Webhook は Ed25519 署名検証を補完します — DiscordPlatform は、X-Signature-Ed25519、X-Signature-Timestamp、および元のリクエスト本文に基づいて Discord インタラクション署名を検証します。署名ヘッダーが欠落している場合、公開キーの形式が不正である場合、または署名が一致しない場合は、リクエストを直接拒否します。リプレイ攻撃を防ぐために、タイムスタンプは±5 分のエージング ウィンドウで検証されます。
  • ⚙️ STOCK_GROUP_N / EMAIL_GROUP_N 構成関係の明確化 - STOCK_LIST との関係を明確にし、構成検証中に STOCK_LIST を超える電子メール グループに対して警告を表示します。
  • 🗓️ ブレークポイント再開を市場のタイムゾーンと取引カレンダーに基づいて判断するように変更 (修正#880) - 株式データの存在チェックはサーバーの自然日を直接使用するのではなく、A株/香港株/米国株のそれぞれの市場タイムゾーンに応じて「再利用可能な最新の取引日」を分析します。
  • 📨 単一銘柄プッシュ モードは共有通知インスタンスを同時に再利用しなくなりました — StockAnalysisPipeline.run() は個別銘柄分析の同時実行性を保持しますが、SINGLE_STOCK_NOTIFY=true のインスタント通知をシリアル送信のために結果収集側に移動します。
  • 🔇 リアルタイム市場の格下げプロンプトは 1 つのアラームまで閉じられます — メイン分析プロセスが銘柄名を取得するときに、リアルタイム市場クエリが事前にトリガーされなくなりました。すべてのデータ ソースが利用できない場合にのみ、分析を続行するためにプロンプ​​トが過去の終値にダウングレードされます。
  • 🔍 A-share 中国語情報検索で中国語の優先順位が回復 — 最初のプロバイダーが主に英語情報を返し、同じ結果バッチ内の中国語情報を最前面にランク付けする場合、search_stock_news() は引き続き後続のエンジンを試行します。
  • 🔒 同時実行中の共有状態の統合ロックが完了します — マルチスレッド シナリオでのデータ競合を回避するために、同時実行中に共有状態の統合ロックが欠如している問題を修正しました。

テスト

  • 🧪 補足設定ページのバージョン情報回帰テスト - Web 設定ページのバージョン情報レンダリング アサーションを追加し、ビルド ロゴのロジックに自動的にフォールバックするようにプレースホルダー バージョン 0.0.0 をオーバーライドしました。

🤖 AI と分析

  • 修正: マーケット レビューで生成されたリンクの LLM max_tokens を 2048 から 8192 に増やします… (#863) by @ZhuLinsen in https://github.com/ZhuLinsen/daily_stock_analysis/pull/923
  • 修正: WebUI を SCHEDULE_TIME に変更した後でも実行中のローカル組み込みスケジューラが依然として修正されている... (#819) by @ZhuLinsen in https://github.com/ZhuLinsen/daily_stock_analysis/pull/914
  • 修正: GitHub アクション ワークフローを変更せずに... (#860) by @ZhuLinsen (https://github.com/ZhuLinsen/daily_stock_analysis/pull/931)

📡 データソース

  • 修正: https://github.com/ZhuLinsen/daily_stock_analysis/pull/928 の @ZhuLinsen による同時実行中に共有状態の統合ロックが欠如している問題を修正 (#881)
  • 修正: 誤検知とリアルタイム マーケット リンクの繰り返し呼び出しを減らし、すべてのデータ ソースが利用できない場合にのみ、システムがユーザーに「リアルタイム マーケット情報の取得に失敗しました」というメッセージを表示するようにしました (#792) by @ZhuLinsen in https://github.com/ZhuLinsen/daily_stock_analysis/pull/905

  • 機能: Windows デスクトップ インストール パッケージに「インストール中にターゲット ディレクトリを選択する」機能を追加しました... (#827) by @ZhuLinsen in https://github.com/ZhuLinsen/daily_stock_analysis/pull/918
  • 修正: https://github.com/ZhuLinsen/daily_stock_analysis/pull/934 の @ZhuLinsen による Discord Webhook リクエストの補足署名検証 (#896)
  • 修正: オプションのストックおよびタイミング関連の構成を保存した後、Docker シナリオの WebUI システム設定が有効にならない問題を修正しました... (#765) by @ZhuLinsen in https://github.com/ZhuLinsen/daily_stock_analysis/pull/911
  • 功績: LiteLLM 実装の詳細を非表示にし、ユーザー側のモデル アクセス エクスペリエンスを簡素化 (#875) by @ZhuLinsen (https://github.com/ZhuLinsen/daily_stock_analysis/pull/925)

🧪 テスト

  • 功績: SerpAPI テキストのクローリング範囲の収束、検索リンク末尾の遅延 (#882) の削減 (https://github.com/ZhuLinsen/daily_stock_analysis/pull/898 の @ZhuLinsen による)
