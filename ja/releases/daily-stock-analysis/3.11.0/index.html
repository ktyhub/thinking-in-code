daily_stock_analysis v3.11.0

マイナー 公開日2026年3月27日 出典ZhuLinsen/daily_stock_analysis 英語原文

デイリーストック分析 v3.11.0

リリースのハイライト

  • 🎨 Web ワークベンチは、一連の UI 統合とデュアル テーマのアップグレードを完了しました - ホームページ、在庫照会、バックテスト、位置および設定ページが、統一されたデザイン トークン、入力サーフェス、およびステータス表現にさらに統合されました。完全な明るい色のテーマが追加され、ワンクリックでの明るい/暗い色の切り替えと永続的な保存がサポートされています。
  • 🤖 ボット/エージェントの機能がメイン ブランチに復元されました — /history、/strategies、/research などのコマンドが復元され、/ask は引き続きマルチストランドの比較と組み合わせの観点をサポートします。ディープ リサーチ、イベント モニタリング、およびスケジュール ポーリングのリンクがメイン回線に復元されます。
  • 🔒 セキュリティと実行安定性の同期強化 — X-Forwarded-For の電流制限バイパス リスクを修正し、LiteLLM の公式 PyPI インストール パスを復元し、Tushare の初期化がローカル SDK に依存しなくなり、Docker の脆弱性を軽減し、デスクトップのパッケージ化と環境を再構築します。
  • 🖥️ 毎日の使用方法の詳細は引き続き洗練されます — ホームページでの香港株の自動入力と送信、ログイン ページのホーム画面テーマの点滅、過去の長い株名の重複、Telegram Markdown 解析が失敗した場合の通知全体の送信の中断などの問題を修正しました。

新機能

  • 🎨 新しいライト テーマとデュアル テーマの切り替えはオンラインです - 完全なライト テーマが Web ワークベンチに追加され、サイドバーでのライト モードとダーク モード間のワンクリック切り替えをサポートします。テーマの選択は保持され、ページを更新した後も現在の設定が維持されます。このアップグレードは部分的な色調整ではなく、カード階層、境界線のコントラスト、入力面、ステータス プロンプト、およびページの背景に再描画されるライト テーマの完全なセットです。
  • 🤖 メイン ブランチで不足しているエージェント/ボット機能を補完します — #648 / #649 が再供給されました main: ボットの復元 /history、/strategies、/research、/ask は、マルチストランドの比較と組み合わせの観点を保持します。 Deep Research と Event Monitor の設定は、Web 設定ページ、スケジュールで再び表示および編集できるようになりました。このモードはイベント アラーム ポーリングにも再接続します。

改善点

  • 🖥️ コア ページは同じワークベンチ ビジュアル言語に統合されます — Home / Chat / Backtest / Portfolio / Settings は、共有デザイン トークン、input-surface 入力システム、空/エラー状態式、ドロワー マスク セマンティクスをさらに統合し、視覚的な断片化とページ間のローカル プライベート スタイルのドリフトを軽減します。
  • 💬 株式募集のインタラクション アクセシビリティとフィードバックの強化 — 株式募集ページでは、セッションのエクスポート、通知の送信、メッセージのコピー、履歴の削除、およびフォローアップのコンテキスト プロンプトが強化されました。 AI 応答操作はホバーにあまり依存しなくなり、タッチ スクリーン デバイスや小さな画面のシナリオでもキー ボタンに直接到達できるようになりました。
  • 📊 バックテストと位置のページ サーフェスとステータス式は引き続き標準化されます — バックテスト ページ フィルター コントロール、ブール ステータス、結果テーブル、および概要カードは、共有の入力/ステータス プリミティブに統合されます。ポジション ページのインポート フィードバック、為替レートの更新プロンプト、空のステータス、および警告情報がさらに共有コンポーネントに統合され、ページ レベルの重複が削減されます。
  • 🧭 ナビゲーションとページ シェルの連携最適化 — サイドバーのテーマ切り替え、質問ストック完了コーナー マーク、モバイル ドロワー マスク、メイン コンテンツのスクロール コントラクトがさらに統合され、デスクトップおよびモバイル端末でのホームページ、質問ストック、バックテストのページ切り替えエクスペリエンスがより安定しました。

テスト

  • 🧪 UI ガバナンスとクリティカル パス回帰の強化 - SidebarNav、ChatPage、BacktestPage およびその他のコンポーネントのコンポーネント テストを補足し、対話型要素によるネイティブ title 属性の再導入や古い input-terminal スタイルのリフローを継続的に防止する UI ガバナンス ガードを追加します。テーマのアップグレード後に主要なメインリンクをカバーするために、スモーク/マークダウンドロワー関連の検証を同期的に更新します。

修正

  • 🌗 Web のホーム画面のデフォルトのテーマ プリセットはダークです — apps/dsa-web/index.html は、React がマウントされる前にローカルに保存されたテーマ設定を読み取るようになりました。保存された値がない場合は、すぐに dark を <html> にプリセットし、color-scheme を同期して、最初にホーム ページとログイン ページでライト テーマが点滅するのを回避します。
  • 🔐 ログイン ページの独立したテーマ レイヤーの終了 — ログイン ページの入力ボックス、ラベル、スイッチ ボタン、およびボタンのコピーは、独立した --login-* ビジュアル トークンを使用し、グローバルなライト/ダーク テーマのテキスト カラーを継承しなくなりました。ブラウザーが明るいテーマをキャッシュした場合でも、ログイン ページは安定した暗いビジュアルとシアン色のパスワード入力パフォーマンスを維持し、パスワードのドットやコピーライトが黒くなるのを防ぎます。
  • 🖥️ ホームページの香港株コード入力の修正 — Web ホームページの分析入力ボックスは、香港株コードを正しく受け入れ、選択した香港株項目を自動的に入力し、00700.HK / HK00700 およびその他の形式の認識を完了し、送信時に「有効な株コードまたは株名を入力してください」という誤ったアラームを回避できるようになりました。
  • 🔒 認証電流制限 X-Forwarded-For 値の修正 (CWE-345) (#841 / #842) — get_client_ip() は、攻撃者が最初の回転電流制限バケットを偽造することによってブルート フォース保護をバイパスするのを防ぐために、X-Forwarded-For の左端の値を取ることから右端の値を取るように変更されました。 TRUST_X_FORWARDED_FOR=true と単一層の信頼できるリバース プロキシの展開シナリオにのみ影響します。マルチレベル プロキシ環境は、展開ドキュメントに従って評価および構成する必要があります。
  • 📦 LiteLLM 公式 PyPI インストールを復元し、安全上限をロックします — requirements.txt pip install litellm の公式 PyPI インストール パスを再利用し、>=1.80.10 の歴史的な最小要件を維持しながら、<1.82.7 の安全上限を増やし、削除された危険なバージョンの 1.82.7 / 1.82.8 を誤ってインストールすることを防ぎます。 Windows デスクトップ パッケージ化スクリプトも同期的に標準 pip install -r requirements.txt リンクにフォールバックするため、特別なダウンロード ブランチによって発生するメンテナンス コストが削減されます。
  • 📨 Telegram のマークダウン解析が失敗し、プレーン テキストに戻る (修正 #850) - Telegram が HTTP 400 を返し、can't parse entities / マークダウン解析エラーが含まれている場合、src/notification_sender/telegram_sender.py は自動的に parse_mode を削除し、通知全体の失敗の直接の原因となる *ST やその他のテキスト コンテンツを回避するためにプレーン テキストの送信を再試行します。
  • 🔢 A 株のリアルタイム市場相場は為替プロンプトを保持します (修正 #852) - DataFetcherManager および TushareFetcher は、SZ000001 / 000001.SZ などの明示的な上海-深センのプロンプトを保持するようになります。 Tushare リアルタイム市場ダウングレード ブランチの古いバージョンでは、上海総合指数の深セン 000001 を sh000001 と誤判断することがなくなりました。
  • 🎯 マルチエージェントの最適ではない購入ポイントが理想的な購入ポイントを盲目的にコピーしなくなりました (修正 #851) - マルチエージェントの結果に独立した secondary_buy がない場合、ダッシュボードはフォールバック値を ideal_buy とまったく同じになるようにハードコピーするのではなく、N/A の表示を優先するようになり、誤解を招く二重購入ポイント表示が減少します。
  • 🧩 Tushare の初期化はローカル SDK パッケージに大きく依存しなくなりました — TushareFetcher は組み込みの HTTP client を直接使用して Tushare Pro にアクセスするようになり、起動フェーズ中に初期化するために import tushare を必要としなくなりました。 Docker、デスクトップ パッケージングまたは環境再構築後の Docker、デスクトップ パッケージングまたは環境再構築、tushare パッケージの問題がないために事前に No module named 'tushare' を報告する問題を修正し、対応する回帰テストを追加しました。
  • ⚙️ daily_analysis ワークフローで DEEPSEEK_API_KEY マッピングが完了 — GitHub アクションの日次分析ワークフローは、キーを使用して構成されているものの、実行時に対応する環境変数を取得できないクラウド タスクを回避するために、DEEPSEEK_API_KEY を正しく透過的に送信するようになりました。
  • 🖥️ 履歴リストで長すぎる銘柄名の切り捨てとホバー表示 (修正 #815) - 履歴リストで長すぎる銘柄名は、文字タイプ (英語 15 文字/中国語 8 文字/混合 10 文字) に応じて自動的に切り捨てられるようになり、切り捨て結果がデフォルトで表示され、ホバーすると完全な名前が表示されます。解像度 1920x1080 で、右側のステータス ラベルのテキストに銘柄名が重なる問題を解決しました。 stockName.ts ツール機能を追加し、対応するテストを追加しました。

ドキュメント

  • 🧾 README 寄付の入り口が小紅書 QR コードに更新されました — README のスポンサーシップ入り口と中国語と英語の説明が、同じ表示品質を維持するために小紅書 QR コード資料に更新されました。
