daily_stock_analysis v3.14.0

マイナー 公開日2026年4月26日 出典ZhuLinsen/daily_stock_analysis 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

デイリーストック分析 v3.14.0

リリースのハイライト

  • 📊 大規模な市場レビューが時間外ワークベンチ構造にアップグレードされました — A 株レビューには、市場温度、指数の詳細、セクター上位表、ニュース カタリスト、明日の取引計画、リスク警告の固定出力があり、純粋なテキスト レビューの重複と空虚さが軽減されます。
  • 🖥️ デスクトップ上の新しい GitHub リリース更新リマインダー — Windows/macOS デスクトップは、起動後に新しいバージョンを自動的に検出します。設定ページから手動で確認してダウンロードページにジャンプすることもできます。
  • 🤖 パイプライン エージェントのデータ読み込みのノイズが大幅に削減されました — K-line ツールは DB ファーストに変更され、同じ銘柄に対する HTTP リクエストの繰り返しを避けるために 240 日分の履歴データを予熱します。
  • 🐳 Docker リリース リンクの組織 — リリース ワークフローは、公式リリースと手動再発行の 2 つのパスに収束します。正式な Docker ハブ イメージ名は zhulinsen/daily_stock_analysis に統一されます。
  • 🔧 LLM チャネルと DeepSeek V4 構成の強化 — GitHub アクションのスケジュールされた分析により、マルチチャネル変数の透過的な送信が完了し、DeepSeek 公式チャネルのデフォルトと例が V4 に同期されます。
  • 🧩 デスクトップの静的リソースの整合性検証 - パッケージ化リンクとランタイムの両方が静的リソースの不一致を早期に検出できるため、リリース パッケージのホワイト スクリーンのトラブルシューティングのコストが削減されます。

新機能

  • 🏠 Web ホームページの履歴レポート領域に新しい再分析エントリ — 元のプロンプトに基づいて、同じ日付で同じ銘柄の分析をやり直すことができます。
  • 🖥️ Windows/macOS デスクトップ上の 新しい GitHub リリース更新リマインダー - 起動後に新しいバージョンを自動的に検出し、設定ページからダウンロード ページにジャンプするための手動チェックをサポートします。

改善点

  • 📊 A 株市場レビュー レポートは、構造化された時間外ワークベンチ形式に変更されました - 市場温度、指数の詳細、セクター トップ テーブル、ニュース カタリスト、明日の取引計画の固定出力。
  • 🐳 Docker リリース ワークフローの統合 — 公式リリース リンクと手動再発行リンクをより明確に区別し、公式 Docker ハブ イメージ名を zhulinsen/daily_stock_analysis に統一します。
  • 🤖 エージェントの日次ツールは、ローカル キャッシュの再利用を優先します - 同時に、新しく取得した日次情報とニュース情報を保持して、データ ソースの繰り返しの呼び出しを減らします。

修正

  • 🤖 パイプライン エージェント K ライン ツールの DB 優先読み込み — get_daily_history / analyze_trend / calculate_ma / get_volume_analysis / analyze_pattern がローカル DB を最初に読み取るように変更され、同じ株式に対する 9x5=45 回の HTTP リクエストの繰り返しがなくなりました (修正 #1066)。
  • 🤖 パイプライン エージェントは、実行前にオンデマンドで 240 日間の K-line 履歴を DB にプレヒートします — 通常の状況では、K-line ツール呼び出しにはネットワーク リクエストを繰り返す必要はありません。
  • 🕒 target_date をフリーズし、ContextVar を介してパイプライン エージェント K ライン ツール スレッドに透過的に送信します — 終了境界間の時間ドリフトを排除します。
  • 🪟 Windows デスクトップ バックエンド ログ コピー エンコーディング修復 — stdout/stderr をコピーする場合は UTF-8 が推奨され、中国語ログの文字化けを避けるためにローカル コード ページ フォールバックと互換性があります。
  • ⚙️ GitHub アクションの毎日の分析ワークフローにより、LLM チャネル変数の透過的な送信が完了します — LLM_CHANNELS、マルチキー、および一般的に使用される LLM_<NAME>_* をサポートし、ローカルで利用可能なマルチモデル構成がクラウドのスケジュールされたタスクで無効になるのを防ぎます (修正 #1063、#872)。
  • 📈 履歴レポートの詳細インターフェイスで change_pct 値を修正 — is None を使用して、欠損値として 0.0 (フラット マーケット) を破棄しないように判断し、間違った change_60d ボトムラインを削除し、欠損している場合は元のリアルタイム マーケット フィールドにフォールバックします (修正 #1084)。
  • 🔧 DeepSeek 公式チャンネル プリセットとサンプル構成は V4 に同期されます。レガシー deepseek-chat デフォルト値を保持し、放棄プロンプトを追加します。また、モデル検出後の古いランタイム選択により保存が失敗する問題も修正されます (修正 #1108、#1109)。
  • 🧩 デスクトップ パッケージング リンクの新しい静的リソース整合性チェック — scripts/check_static_assets.py は、index.html によって参照されるリソースがソース static/ および PyInstaller 製品に実際に存在するかどうかを検証します。また、ランタイムは、リリース パッケージを開いた後に白い画面が再び表示されるのを避けるために、不一致の場合にクリアなログを書き込みます (参照 #1064 / #1065 / #1050)。
  • 🧩 バックエンド /assets/* が明示的なルーティング ホスティングに変更されました - リソースが見つからない場合、要求された拡張子に一致する text/javascript / text/css 404 が返され、デフォルトの JSON エラー応答 (参照 #1064) によって引き起こされる誤解を招くトラブルシューティングが軽減されます。
  • 🌙 kimi-k2.6 は固定温度を自動的に使用します — メイン解析、大容量ディスクのレビュー、およびエージェントがモデルを呼び出すときに、モデルがデフォルトの温度要求を拒否するのを避けるために、temperature=1.0 が自動的に使用されます (修正 #1102)。

ドキュメント

  • 🐳 補足の公式 Docker イメージ使用手順 — イメージの取得、docker run の使用法、および .env/データ ディレクトリ マッピングに関する手順を追加しました。これは、Compose デプロイメント パスのみをカバーするものではなくなりました。
  • 📨 Feishu カスタム ロボット Webhook サンプルの修正 — feishu_sender.py のサンプルがインタラクティブ カード JSON に変更され、Feishu 自動 Webhook トリガー設定チュートリアルが補足されます。
  • 📚 ルート README 構造を最適化 — ホームページ レベルの機能機能、テクノロジー スタック、クイック スタート、プッシュ効果、Web、エージェント、スポンサーおよびニュース ソースの入り口を保持し、詳細な設定、トランザクション規律、および基本的なセマンティクスを完全なガイドに閉じ、Docker バッジを公式ミラー ページに向けます。
  • 🌐 英語と繁体字中国語の README の簡略化された入口構造を同期させます — そして、完全ガイド内の LLM の使用法 API とポジション管理の手順を完了します。
  • 🤝 AI コラボレーションと PR テンプレートの README メンテナンス ルールを調整 — README は必要な場合を除き更新されず、詳細は特別なドキュメントで優先されることを明確にします。

テスト

  • 🧪 マーケット レビュー関連テストの LiteLLM スタブ動作の安定化 — テスト コレクションの順序が変更されたときに、ローカルにインストールされた LiteLLM がマーケット レビュー単体テストに影響を与えるのを回避します。
  • 🧪 pytest はデフォルトでフロントエンド依存ディレクトリをスキップします — apps/dsa-web/node_modules がローカルに存在する場合、リリース前に無関係なディレクトリによってゲートが遅くなるのを避けるために、バックエンド テストによって再帰的にスキャンされなくなります。
