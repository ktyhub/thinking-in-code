デイリーストック分析 v3.20.0

リリースのハイライト

  • 特技: AlphaSift 銘柄選択ポータル、自動インストール、安定した適応レイヤーを追加し、Web ポリシーの実行、LLM の再配置表示、およびデフォルトのシャットダウンの制御可能なアクティブ化をサポートします。
  • 特技: 個別の株式履歴、自己選択キュー、市場ステージ、および AnalysisContextPack の可視性を向上させ、Web レポートと API の構造化コンテキスト機能を強化します。
  • 特技: MiniMax のデフォルト モデルが MiniMax-M3 にアップグレードされ、関連する価格、プリセット、テスト カバレッジが完了しました。
  • 修正: ヘルス チェック、Windows デスクトップの更新と初回実行エンコード、ETF の毎日の secid、LLM の Base_url チェック、エージェントの毎日のコンテキストの誤判定などの安定性の問題を修正します。

新機能

  • AlphaSift の銘柄選択タブを追加しました。このタブはデフォルトでは閉じられています。 ALPHASIFT_ENABLED を通じてオープンした後、戦略を読み取り、安定した適応レイヤーを通じて銘柄選択を実行できます。 ・Webトップページの左欄を銘柄ごとに重複して表示する個別銘柄欄に変更し、マーケットレビューを最上位に表示します。個々の銘柄をクリックして最新のレポートをロードし、コード バリアント (.SZ/.SH/.SS) による正規化された重複排除とマージをサポートします。すべての選択、一括削除、および削除確認エントリを保持します。在庫コード API DELETE /api/v1/history/by-code/{stock_code} による一括削除を追加します。
  • 新しい自己選択操作エントリがレポート詳細の右列に追加され、現在の在庫が自己選択キューにあるかどうかの確認、ワンクリックでの追加または削除がサポートされます。マーケットレビューレポートにはこの操作は表示されません。 ・在庫照会ページの入力エリア上部に任意の操作ボタンを追加しました。ユーザーが銘柄コードを含むメッセージを送信すると、自己選択のエントリへの追加/削除が自動的に表示されます。
  • 同じ銘柄の過去の傾向に関する新しいドロワー エントリが Web レポート ページに追加されました。履歴リストの概要は、トレンド、概要、モデル、および分析時間の市場フィールドを補足します。現在の株式による履歴分析の表示と、さらに読み込みをサポートします。
  • AnalysisContextPack P4 の低感度の概要は、履歴の詳細、同期分析応答、完了したタスクのステータス、および Web レポート ページにアクセスし、データ ブロックのステータス、ソース、欠落の理由、および劣化の概要を表示します。
  • #1386 P5 個別銘柄分析レポートに dashboard.phase_decision 日中意思決定ガードレールを追加し、履歴を保存する前に市場段階とデータ品質に基づいて信頼性の高い日中売買の結論を制限します。
  • #1386 P4a は、analysis_phase=auto|premarket|intraday|postmarket API パラメーターを追加し、受け入れられた非同期タスクのリクエスト ステージ、メモリ ステータス、リスト、SSE、分析パイプラインを透過的に送信します。
  • #1386 P4b Web レポート ページには、最終市場ステージのラベルが追加され、タスク パネルにリクエスト ステージが表示され、AnalyticsContextPack の低感度データ品質概要が再利用されます。
  • MiniMax チャネル モデル リストのアップグレード: MiniMax-M3 がデフォルトとして追加され、OpenAI 互換の公式ドキュメントに従って 1M 入力コンテキストをサポートします (プロジェクトは控えめに <=512K 価格範囲として登録されています: context_window 512K、max_tokens 128K、$0.6/M 入力、$2.4/M 出力に対応し、>512K 入力価格範囲はモデル化されていません)、MiniMax-M2.7 は維持され、 MiniMax-M2.7-highspeed、および既存のユーザー構成のコスト見積もりとの互換性のために、MiniMax-M2.5 従来の価格エントリを保持します。 Web 設定ページ MiniMax のデフォルトのモデルと価格は、M3 を押すと更新されます。
  • AnalysisContextPack P1 内部コントラクトと感度を下げたシリアル化テストを追加しました。
  • 市場段階の低感度サマリーは、履歴の詳細、同期分析の応答、および完了したタスクのステータスのレポートのメタデータにアクセスします。

改善点

  • 最初に構成検証を実行して、不足している AI キー、空の STOCK_LIST、電報/電子メールのペア フィールド、および Webhook URL プレフィックス診断を補います。
  • AlphaSift の銘柄選択ポータルは、Web サイドバーの「Ask Stocks」の下に移動され、エージェント/リサーチ アシスタントのワークフローに近くなりました。
  • Docker は、イメージ構築フェーズ中にデフォルトの AlphaSift アダプテーション レイヤーをプリセットします。これにより、デスクトップ リリース パッケージと同様に、実行時の追加インストールが回避されます。
  • AlphaSift のストック選択は、alphasift.dsa_adapter の安定したインターフェイスに依存するように変更されました。 Web 戦略リストは AlphaSift によって動的に提供され、フロントエンドでハードコーディングされなくなりました。
  • AlphaSift の銘柄選択ページには、実行 ID、スナップショット番号、フィルターされた数量、ファクターおよびリスクの詳細が追加され、候補を拡大するときに実際の詳細が表示され、現在サポートされている A 株市場のみが一時的に開きます。
  • 新しい AlphaSift 銘柄選択スイッチ カードが Web 設定ページに追加され、銘柄選択タブを直接オンまたはオフにできます。
  • AlphaSift ストック選択をオンにする場合は、まず ALPHASIFT_ENABLED に切り替えて、アダプテーション レイヤーの可用性を確認します。これが存在しない場合は、制御されたインストール インターフェイスが自動的に呼び出され、ユーザーはインストールするためにさらにクリックする必要がなくなります。
  • AlphaSift がオンになっているが、アダプテーション レイヤーが欠落している場合、戦略リストと銘柄選択インターフェイスがシリアル化され、ソースをロックするために自動的にインストールされ、古い alphasift パッケージを上書きするために再インストールが強制されます。
  • AlphaSift の在庫ピッキング ページは、重複するスナップショット ソース フォールバック プロンプトをマージし、AlphaSift 独自の Tushare 優先スナップショット ソース ロジックを保持します。
  • AlphaSift 銘柄選択ページでは、LLM の再配置および格下げ時に警告/ソース エラー/解析エラーが表示され、誤ってローカル ファクター スコアが LLM 判定として表示されることを回避します。
  • Web 設定ページに、共通のデータ ソース構成項目として ALPHASIFT_ENABLED が繰り返し表示されなくなりました。この値は、「銘柄選択を有効にする」ボタンの背後にある永続的な状態としてのみ使用されます。
  • AlphaSift を閉じると、Web を開いていないユーザーの誤解を避けるために、Web の左側にある「銘柄選択」ナビゲーション エントリが非表示になります。
  • プリセット項目が一致しない場合に誤って「バランス型マルチファクター」を表示することを避けるために、AlphaSift 銘柄選択カスタム戦略表示ロジックを追加しました。
  • コード別にグループ化された一意の株式のリストを返すための GET /api/v1/history/stocks エンドポイントを追加しました。オプションのキューの追加と削除のチェックをサポートするために、GET /api/v1/stocks/watchlist、POST /api/v1/stocks/watchlist/add、および POST /api/v1/stocks/watchlist/remove エンドポイントが追加されました。 STOCK_LIST は、自動正規化を行わずに、そのまま読み取りおよび書き込みを行います。追加/削除中に、同等のコード バリアントを決定するために正規化比較が実行されます。
  • 自己選択キューのフロントエンドステータスを一元管理する useWatchlist フックを追加し、SystemConfigService の STOCK_LIST 設定項目を再利用して永続化を実現します。
  • AnalysisContextPack P5 は、データ品質スコア、fetch_failed ステータス、プロンプト データ制限ブロック、および Web 低感度品質表示を追加します。
  • #1386 P2-full AnalysisContextPack プロンプト データ制限の市場ステージとダウングレード データ間の相互制約を追加し、中国分析プロンプトの段階的市場ラベルを修正します。
  • 通知レポートのデフォルトの送信パスは、変換およびシャーディング ロジックと互換性があるように既存のチャネルに復元され、新しいレンダラー機能は将来の拡張の基礎としてのみ予約されます。
  • 関連するセクションに型データがない場合、列 N/A 全体を含むセクション テーブルが生成されるのを避けるために、セクション名が 1 行で表示されます。
  • Web レポート詳細ページの情報レベルを最適化し、入力データ ブロックと診断をメイン コンテンツの後に折りたたまれた補助情報まで移動します。
  • 日中分析により、リアルタイムの市場取得時間、プロバイダー時間、古いタグ、フォールバックタグ、および入力データ制限をマップするための AnalysisContextPack の部分/推定タグが完成します。

修正

  • エージェント分析パスは、日次行が正常にキャプチャされた後に daily_bars_missing が表示されるのを回避するために、AnalysisContextPack 概要を生成する前にドロップされた日次分析コンテキストを再利用します。
  • /api/v1/health ルートを登録し、認証除外を追加し、ADMIN_AUTH_ENABLED をオンにした後、パスが 404 を返し、ヘルス プローブが 401 を受信する問題を修正します。
  • Windows ローカルの初回実行環境は、非 UTF-8 コンソール出力との互換性をチェックし、requirements.txt コメントを ASCII に変更して、デフォルト コード ページでの依存関係のインストールが失敗する可能性を減らします。
  • AlphaSift DSA アダプテーション レイヤーはデフォルトで LLM 再配置を有効にし、バックエンドは明示的に use_llm=True を要求し、銘柄選択ページには LLM スコア、判断、カバレッジ、および懸念事項が表示されます。
  • AlphaSift は、Web が LLM を構成することを避けるために、DSA を組み込むときに DSA によって解析された LLM モデル、チャネル、およびキー構成を再利用しますが、プロバイダー キーがないため、株式選択 LLM の再配置は依然として低下します。
  • AlphaSift のストック選択が DSA LLM ルーティングを再利用する場合、未宣言のホスティング プロバイダーの代替モデルをフィルタリングし、宣言されたチャネル モデルをフォールバック チェーンに追加して、残りの Gemini フォールバックが利用可能な DSA チャネルをカバーすることを回避します。
  • AlphaSift のデフォルトのインストール ソースは、ロックされたコミットの信頼できる GitHub アドレスに変更されます。デスクトップ モードの自動インストールには管理者セッションは必要ありませんが、非デスクトップ展開には管理者認証セッションが必要であり、引き続きインストール ソースが制限されます。 ・Web上でAlphaSiftを開く際、インストールしてから設定を書き込んでしまうとデフォルトの閉じた状態で開けなくなる問題を修正しました。
  • AlphaSift ステータスとインストール インターフェイスは、install_spec プレーン テキストを返さなくなり、install_spec_is_default などの非機密ステータス フィールドのみが返されます。
  • AlphaSift ステータス検出は、欠落しているオプションの依存関係と予期しない例外を区別します。例外シナリオは警告を記録し、機密性のない診断情報を返します。
  • AlphaSift フィルター呼び出しの互換性の調整: screen は主に max_results に基づいており、従来の max_output キーワードをサポートしながら、フロントエンドの手動ポリシー パラメーターを調整するためのポリシー透過的な送信を可能にします。
  • AlphaSift Web 銘柄選択リクエストは、LLM 再注文が有効になった後の一般的な 30 秒の API タイムアウトによる早期中断を回避するために、独立した長いタイムアウトを使用します。
  • AlphaSift はプリセットされており、デスクトップ パッケージ化フェーズ中にアダプテーション レイヤーが収集されるため、リリース パッケージの実行時に管理者が自動的にインストールする必要がなくなります。
  • AlphaSift 自動インストールは、status が missing_module と診断された場合にのみトリガーされます (モジュール欠落シナリオのみ)。アダプテーション層はインポートできますが、ランタイム例外は自動的に pip install ではなくなりましたが、424 に戻り、診断を保持して、実際のランタイム障害が再インストールとして隠蔽されることを回避します。
  • 中国語の Web インターフェイスに残っている英語のコピーライティングと設定ページのヘルプのギャップを閉じ、バックテスト ページを中国語表示に変更し、Web 設定ページには説明付きの登録済み構成項目のみが表示されるようにします。
  • Windows デスクトップは、サイレント インストール中に現在のインストール ディレクトリを自動的に更新し、カスタム インストール ディレクトリ シナリオでの古いバージョンのファイルのアンインストールの失敗を回避します。
  • Windows インストーラーは、古いアンインストーラーを再試行するときに _?= インストール ディレクトリ パラメーターに引用符を追加し、古いバージョンがスペースを含むパスにインストールされている場合に 2 を返し、自動更新が失敗する問題を修正します。
  • Windows デスクトップ側は、NSIS に渡される /D= ディレクトリ パラメータを自動的に更新し、スペースが含まれる場合はインストール場所レジストリの切り詰めを避けるために引用符を自動的に追加します。
  • 解析の違いによる SSRF バイパスを回避するために、LLM チャネルのbase_url 検証を強化します。
  • 上海 ETF が深セン相場 ID によって照会され、日次行が空になるのを防ぐために、efinance ETF の日次行 Eastmoney secid ルーティングを修正しました。

ドキュメント

  • AlphaSift と LiteLLM の間の互換性境界を明確にします。ブリッジング DSA のみが、呼び出し期間中に挿入されるプロバイダー/モデル/ベース URL を宣言しており、.env に対してプロバイダー/モデルのルート移行は実行されません。フォールバック方法は、AlphaSift を閉じて、元の LITELLM_*/LLM_* 構成を復元することです。
  • AlphaSift は DSA の既存の LLM/LiteLLM 構成セマンティクスのみを再利用し、LITELLM_MODEL、OPENAI_MODEL、OPENAI_BASE_URL、LLM_TIMEOUT_SEC などの新しいモデル セマンティクスは移行しないことを明確にします。障害プロンプトとフォールバック パスは既存のシステム構成リンクを一律に使用します。これは、AlphaSift の在庫ピッキング機能自体にのみ影響します。
  • AlphaSift の自動インストール ソース ロック、missing_module、ランタイム異常動作の境界、および LLM/プロバイダー/ベース URL とカスタム チャネル フォールバック パスを明確にし、問題の追跡と元の LLM 構成へのロールバックを容易にします。
  • 同じ銘柄の履歴トレンドの新しいモデル フィールドが履歴スナップショット表示メタデータであり、実行時の LLM プロバイダー/モデル/ベース URL ルーティングおよび構成移行のクリーンアップに影響を与えないことを明確にします。ロールバック方法は、通常のリリースに従ってこの変更をロールバックすることです。
  • #1311 の互換性境界を明確にします。レンダリング レイヤーは分析結果の model_used 表示フィールドのみを使用し、wechat/slack/feishu/telegram 送信側送信リンクを変更せず、プロバイダー/モデル/ベース URL の互換性移行をトリガーしません。
  • AlphaSift ロック コミットの alphasift.dsa_adapter 契約の基礎と、現在の DSA API/Web 呼び出し構造の互換性境界を明確にします。
  • [設定] ページには LLM 構成のグループ化とフィールド マージのみが表示され、LLM 移行/ロールバック パスの書き換えやトリガーは行われないことを明確にします。既存の LLM 構成の保存およびロールバック セマンティクスと互換性があります。
  • AnalysisContextPack P0 コンテキスト パッケージ化を追加しました。
  • アラーム センター P8 のドキュメントと設定手順を完了して、従来の JSON、高度なルール、Web/API、Docker、GitHub アクションとデスクトップの間の境界を明確にします。

テスト

  • llmProviderTemplates、LiteLLM フォールバック価格設定、および MiniMax プリセット関連の単一テストを同期的に更新して、新しいデフォルト モデルをアサートします。
  • ETF の日次データ ソース ルーティング、入力バリアント、フォールバック、および MA フィールド回帰カバレッジを補足しました。

雑用

  • #1311 オムニチャネル レンダリング適応の基礎を築くために、通知レポート チャネル機能のポートレート、PreparedMessage、および構造を認識した Markdown シャーディング インフラストラクチャを追加しました。
  • エンタープライズ WeChat、Feishu、Telegram、DingTalk、および Slack プラットフォーム用のプリセット レンダラー メタデータ、およびデフォルトのプッシュ レポートの入り口と表示されるレイアウトは、当面は変更されません。
