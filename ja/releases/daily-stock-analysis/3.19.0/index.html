daily_stock_analysis v3.19.0

デイリーストック分析 v3.19.0

新機能

  • 診断を実行するための #1391 フェーズ 1 最小リンクの実装: タスク/SSE は、trace_id を追加し、毎日およびリアルタイムの市場 ProviderRun スナップショットを記録します。
  • アラーム センターは、P7 大規模信号機の構造化ルールを追加し、market_light_status および market_light_score_drop をサポートし、既存のワーカー、トリガー履歴、通知、冷却リンクを再利用します。
  • #1391 フェーズ 2 実行診断概要の実装: ユーザーが読み取り可能な RunDiagnosticsummary を生成し、履歴レポート診断 API と感度を下げたコピー テキストを提供します。
  • #1391 フェーズ 3 の実行診断の可視性の実装: レポートの詳細とタスク パネルはデフォルトで折りたたまれ、実行ステータス、トレース、および複製可能なトラブルシューティング情報が表示されます。バックエンドは、api/v1/history/{record_id}/diagnostics および context_snapshot.diagnostics を通じて履歴リンクのバックフィルを提供します。
  • AnalysisContextPack P1 内部コントラクトと感度を下げたシリアル化テストを追加しました。
  • 共通の分析パイプラインの既存のアーティファクトから内部コンテキスト パッケージを組み立てるために AnalysisContextPack P2 ビルダーを追加しました。
  • Wengu は、デフォルトでオフになっている可視の会話コンテキスト圧縮を追加し、Web スイッチ、エージェントの高度なプリセット、ローリング サマリー、および最近のラウンドのオリジナル テキスト保護をサポートし、長時間のセッション トークンの消費を削減します。
  • ストック オートコンプリート インデックスは、デフォルトでリモート リフレッシュと GitHub メインからローカルへのキャッシュをサポートします。 Web/CLI 分析エントリが失敗すると、自動的に組み込みインデックスにダウングレードされ、首切りや名前変更後に古い略語が分析に混入する可能性が低くなります。
  • 通常の分析とエージェント ランタイム プロンプトは、履歴/API/Web 出力との互換性を維持するために、AnalysisContextPack の低感度サマリーに接続されます。

改善点

  • scripts/fetch_tushare_stock_list.py は、自動補完リフレッシュ プロセスでデフォルトで使用される A 共有のプレフィックス XD/XR/DR/N/C を使用して名前をバックフィルおよび修正できます。
  • Web ルーティング ページがオンデマンドでロードされるように変更され、最初のパケット サイズが削減され、ルートのロード失敗に対する回復プロンプトが追加されます。
  • Web フル レポート マークダウン ドロワーがオンデマンドでロードされるように変更されました。
  • 市場フェーズ推論ベースラインを追加し、市場前、市場内、昼休み、終値近く、市場後、非取引日のセマンティクスを明確にしました。
  • 実行中のマーケットステージのコンテキスト構築と劣化テストを追加しました。
  • 設定ページの構成は、エージェント、バックテスト、レポート、通知ルーティング、システム ランタイム、AI レガシー、データ ソース、通知の詳細構成をカバーする、Web 設定ページの実際の表示/構成可能なフィールドの中国語と英語のバイリンガル コピーライティングを段階的に完了するのに役立ちます。
  • P2-min: LLM プロンプトは市場段階のコンテキストを挿入します。

修正

  • ピンイン フィールドが欠落しているダウングレードされたインデックスの書き込みを避けるために、pypinyin が欠落している場合、ストック オートコンプリート インデックスの生成は直接失敗します。
  • テンセントのリアルタイム市場取引量を株式の水準として正規化し、量エネルギー変化倍数の増幅や誤解を招く分析レポートを回避します。
  • Docker のデフォルトの展開では、WebUI が構成を保存するときにマウント ポイントを更新する os.replace によって Device or resource busy がトリガーされるのを防ぐために、.env の単一ファイル マウントが削除されます。
  • コンバージェンス #1391 フェーズ 0 A シェア コードの所有権境界: SH/SZ プレフィックス シナリオの所有権の一貫性を完了し、data_provider/baostock_fetcher.py、data_provider/pytdx_fetcher.py、および data_provider/tushare_fetcher.py の今回の修復ラウンドの範囲を明確にします。
  • STOCK_LIST がベア A 株コードを使用する場合の Baostock などのデータ ソース フォールバックの内部形式変換を修正し、6 桁の株式番号を使用し続けるためのユーザー設定を維持しました。
  • Windows デスクトップの自動更新は、ユーザーがインストールの再開を確認した後にインストーラーをサイレントに実行し、組み込みバックエンドを停止した後にプロセス参照をクリーンアップするように変更され、インストーラーが「日次在庫分析を終了できません」というメッセージを表示する可能性を減らします。
  • macOS デスクトップは、ランタイム構成をユーザー データ ディレクトリに移行し、古い .app パッケージ内のファイルにまだアクセスできる状態で、.env、データベース、ログを移行します。これにより、その後の交換やアップグレード後の再構成が回避されます。
  • エージェント/履歴互換スナップショットの関連セクションとセクション リンケージ フィールドの抽出を復元し、新しいホームページ レポートで「セクション リンケージ」が欠落する回帰問題を修正しました。
  • Web 設定ヘルプのレガシー アラーム JSON フィールド名とサイレント期間配信セマンティックの説明を修正しました。
  • Web 中国語設定ページのデータ ソース、通知、システム、エージェント領域の設定タイトル、説明、キー ドロップダウン オプションが表示されない問題を修正しました。
  • セッションを切り替えてホームページ タスクに再接続した後も、エージェント/分析タスクの進行中のステータスが残る場合がある問題を修正しました。
  • プロバイダー対応のトレース サブトラックをシングル エージェントに追加し、reasoning_content と DeepSeek V4 思考 + ホイール全体のツール呼び出しのツール プロトコル マテリアルを保持しました。
  • Akshare Sina/Tencent A-share の履歴ボトムアップ インターフェイスにコール レベルのタイムアウトを追加し、Tushare 605xxx 上海株式コード ルーティング回帰テストを完了して、データ ソースの応答なしによるスケジュールされた分析のハングを回避しました。
  • pandas 3 環境で取引カレンダーをインポートする際の Timedelta ユニット T の障害による分析の失敗を回避するために、exchange-calendars 依存関係の下限を 4.13.0 に引き上げます。
  • インタラクティブ コマンド (DingTalk 会話、Feishu 会話、Telegram) によってトリガーされた分析結果は、ソース会話にのみ返され、静的通知チャネルに同時にブロードキャストされなくなりました。
  • 新しいバックエンドにレガシー アクセス トークンがない場合に Longbridge データ ソースが未構成と誤って判断されるのを防ぐために、Longbridge OAuth 2.0 認証とトークン キャッシュの回復に適応しました。
  • Linux/Docker が古い ZZPH100​​ZZ しかインストールできない場合のビルドの失敗を避けるために、現在の SDK が OAuthBuilder / Config.from_oauth をサポートしていない場合、Longbridge OAuth パスはダウングレードを明示的にログに記録します。
  • YFinance の日次行が名前のない日付インデックスを返すシナリオと互換性があり、標準化後の date 列の欠如によって引き起こされる米国株の日次フォールバックの中断を回避します。

ドキュメント

  • #1391 フェーズ 0 実行診断契約文書を追加して、trace_id、診断概要、クリティカル リンク範囲、および感度解除/フェールオープン/保持の境界を明確にしました。
  • アラーム センター P8 のドキュメントと設定手順を完了して、従来の JSON、高度なルール、Web/API、Docker、GitHub アクションとデスクトップの間の境界を明確にします。
  • このデスクトップ修正は、Windows NSIS アップデートのインストール リンクとバックエンド プロセスのライフ サイクル クリーンアップのみをカバーしていることに注意してください。設定項目の保存/モデルランタイムクリーンアップのセマンティクスは変更されません。以前に誤って導入された docker/Dockerfile npm registry の変更を削除し、展開ビルドと更新プログラムの修復の間の責任の分離を復元します。
  • フィールド品質ステータス、既存のステータス マッピング、および最初のバージョン パックの境界を明確にするために、AnalyticsContextPack P0 コンテキスト インベントリを追加しました。
  • #1391 フェーズ 2 の構造化検出アラームが非設定移行信号であることを明確にします。agent_max_steps/agent_orchestrator_timeout_s の不正な値はデフォルトにフォールバックし、ログ アラームが生成されます。新しい診断リンクは、context_snapshot/RunDiagnosticSummary 読み取りおよび書き込みフィールドを追加するだけであり、litellm_model、agent_litellm_model、openai_base_url、LLM チャネル ルーティングまたは構成移行セマンティクスは書き換えられません。
  • 補足 #1391 フェーズ 3 互換性の説明: バックエンド診断永続性、履歴クエリと通知ライトバック リンク変更境界とロールバック戦略、および完全なバックエンド アクセス レベル検証要件を記録します。 ＃＃＃ テスト
  • Convergence #1391 フェーズ 3 バックエンド/API (Web 回帰チェックあり): ./scripts/ci_gate.sh、test_pipeline_market_phase_context.py、test_analysis_api_contract.py、test_analysis_history.py、npm run lint、npm run build。
  • python -c "import exchange_calendars as xcals; xcals.get_calendar('XSHG'); print('ok')" を実行して検証に合格し、インポートと取引カレンダーの初期化の互換性をオーバーライドします。
