daily_stock_analysis v3.6.0

デイリーストック分析 v3.6.0

追加

  • 🗑️ 履歴の一括削除 — Web UI は、分析履歴の複数選択と一括削除をサポートするようになりました。 POST /api/v1/history/batch-delete エンドポイントと ConfirmDialog コンポーネントを追加しました。
  • 🔐 認証設定 API — 実行時に Web 認証を有効または無効にし、必要に応じて初期管理者パスワードを設定するための新しい POST /api/v1/auth/settings エンドポイント
  • openclaw スキル集成指南 — 新增 docs/openclaw-skill-integration.md，说明 openclaw スキル调用 DSA API
  • ⚙️ LLM チャネル プロトコル/テスト UX — .env と Web 設定が同じチャネル形状 (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED) を共有するようになりました。設定ページには、チャネルごとの接続テスト、プライマリ/フォールバック/ビジョン モデルの選択、およびプロトコル対応モデルのプレフィックスが追加されます。
  • 🤖 エージェント アーキテクチャ フェーズ 0+1 — 共有プロトコル (AgentContext、AgentOpinion、StageResult)、抽出された run_agent_loop() ランナー、AGENT_ARCH スイッチ (single/multi)、構成レジストリ エントリ
  • 🔍 ボット NL ルーティング — 2 層の自然言語ルーティング: 安価な正規表現プレフィルター (株式コード + 財務キーワード) → 軽量 LLM インテント解析。 AGENT_NL_ROUTING=true によって制御されます。複数の銘柄と戦略の抽出をサポート
  • 💬 /ask マルチ銘柄分析 — カンマまたは vs で区切られたコード (最大 5 つ)、150 秒のタイムアウトによる並列スレッド実行 (部分的な結果を保持)、上部のマークダウン比較概要表
  • 📋 /history コマンド — {platform}_{user_id}:{scope} 形式によるユーザーごとのセッション分離 (コロン区切り文字によりプレフィックスの衝突が防止されます)。 /chat セッションと /ask セッションの両方をリストします。詳細を表示またはクリアする
  • 📊 /strategies コマンド — 利用可能な戦略 YAML ファイルをカテゴリ (趋势/形态/反转/框架) と✅/⬜ アクティベーション ステータスでグループ化してリストします。
  • 🔧 バックテスト概要ツール — get_strategy_backtest_summary および get_stock_backtest_summary は読み取り専用エージェント ツールとして登録されています
  • ⚙️ エージェント自動検出 — is_agent_available() は LITELLM_MODEL から自動検出します。明示的な AGENT_MODE=true/false が完全に優先されます。
  • 🏗️ マルチエージェント オーケストレーター (フェーズ 2) — 4 つのモード (quick/standard/full/strategy) を備えた AgentOrchestrator; AGENT_ARCH=multi を介した AgentExecutor のドロップイン交換品。 BaseAgent ABC (ツール サブセット フィルタリング、キャッシュ データ インジェクション、構造化 AgentOpinion 出力付き)
  • 🧩 専門エージェント (フェーズ 2 ～ 4) — TechnicalAgent (8 ツール、トレンド/MA/MACD/出来高/パターン分析)、IntelAgent (ニュースとセンチメント、リスクフラグの伝播)、DecisionAgent (意思決定ダッシュボード JSON への統合)、RiskAgent (7 つのリスク カテゴリ、ソフト/ハード オーバーライドによる 2 レベルの重大度)
  • 📈 戦略システム (フェーズ 3) — StrategyAgent (YAML スキルによる戦略ごとの評価)、StrategyRouter (ルールベースの体制検出 → 戦略選択)、StrategyAggregator (バックテスト パフォーマンス係数による加重コンセンサス)
  • 🔬 ディープ リサーチ エージェント (フェーズ 5) — 3 フェーズ アプローチの ResearchAgent (分解 → サブ質問の調査 → レポートの合成)。トークン予算の追跡。エイリアス付きの新しい /research ボット コマンド (/深研、/deepsearch)
  • 🧠 メモリとキャリブレーション (フェーズ 6) — 予測精度追跡、信頼度キャリブレーション (最小サンプルしきい値後にアクティブ化)、過去の勝率に基づく戦略の自動重み付けを備えた AgentMemory
  • 📊 ポートフォリオ エージェント (フェーズ 7) — 複数銘柄ポートフォリオ分析用の PortfolioAgent (ポジションサイジング、セクター集中、相関リスク、市場間連携、リバランス提案)
  • 🔔 イベント駆動型アラート (フェーズ 7) — EventMonitor と PriceAlert、VolumeAlert、SentimentAlert ルール。非同期チェック、コールバック通知、シリアル化可能な永続性
  • ⚙️ 新しい構成エントリ — AGENT_ORCHESTRATOR_MODE、AGENT_RISK_OVERRIDE、AGENT_DEEP_RESEARCH_BUDGET、AGENT_MEMORY_ENABLED、AGENT_STRATEGY_AUTOWEIGHT、AGENT_STRATEGY_ROUTING — すべて config.py + config_registry.py に登録されています (WebUI で構成可能)

変更されました

  • 🔐 認証パスワード状態セマンティクス — 保存されたパスワードの存在は、認証の有効化とは独立して追跡されるようになりました。認証が無効になっている場合、/api/v1/auth/status は passwordSet=false を返しますが、将来の再有効化に備えて保存されたパスワードは保持されます。
  • 🔐 認証設定により強化が再度有効になります - 保存されたパスワードを使用して認証を再度有効にするには、currentPassword が必要になり、セッションの作成に失敗すると、ロックアウトを回避するために認証の切り替えがロールバックされます。
  • ♻️ AgentExecutor のリファクタリング — _run_loop は共有 runner.run_agent_loop() に委任します。重複したシリアル化/解析/思考ラベル コードを削除しました
  • ♻️ 統合エージェント スイッチ — ボット、API、パイプラインはすべて、分岐 config.agent_mode チェックではなく config.is_agent_available() を使用します
  • 📖 README.md — ボット コマンド セクション (ask/chat/strategies/history) を拡張、NL ルーティングに関するメモを追加、エージェント モードの説明を更新
  • 📖 .env.example — AGENT_ARCH および AGENT_NL_ROUTING 構成ドキュメントを追加

修正済み

  • 🐛 Windows でのセッション シークレットのローテーション - アトミック置換を使用するため、.session_secret が既に存在する場合でも認証切り替えにより既存のセッションが無効になります。
  • 🐛 認証のアトミック性の切り替え — セッション シークレットをローテーションする前に ADMIN_AUTH_ENABLED を保持します。ローテーションが失敗した場合は、以前の認証状態にロールバックします。
  • 🔧 LLM ランタイム選択ガードレール — YAML モードのチャンネル エディターは、LITELLM_MODEL / フォールバック / ビジョンをカバーしなくなりました。システム構成検証では、すべてのチャネルが無効になった後のランタイム ソース チェックが追加され、vertexai/... などのプロトコル エイリアス モデルが繰り返しプレフィックスとして付加される問題が修正されています。
  • 🐛 複数銘柄 /ask のフォローアップ回帰 — ポートフォリオ オーバーレイは、銘柄ごとのフェーズと同じタイムアウト バジェットを共有し、ボットの応答をブロックするのではなく、タイムアウト時にスキップされます。 /history は、生のダッシュボード JSON の代わりに、読み取り可能な銘柄ごとの概要を保存するようになりました。圧縮されたマルチストック出力で数値 sniper_points 値がレンダリングされるようになりました。
  • 🐛 意思決定ダッシュボード列挙型の互換性 — マルチエージェント DecisionAgent は、decision_type を従来の buy|hold|sell コントラクト内に保持し、リスク オーバーライド、パイプライン変換、およびダウンストリームの前に、迷走する strong_* 出力を正規化します。
  • 🛟 マルチエージェントの部分結果フォールバック — IntelAgent はダウンストリームでの再利用のために解析された情報をキャッシュするようになり、共有 JSON 解析は軽度の不正なモデル出力を許容し、オーケストレーターは常に 50/观望/未知 に折りたたまれるのではなく、タイムアウトまたは途中のパイプライン解析の失敗時に最小限のダッシュボードを保存/合成します。
  • 🐛 共有 LiteLLM ルーティングが復元されました — ボット NL インテント解析と ResearchAgent 計画/合成は、メインのエージェント フローと同じ LiteLLM アダプター / ルーター / フォールバック / api_base インジェクション パスを再利用するため、LLM_CHANNELS / LITELLM_CONFIG / OpenAI 互換の展開は一貫して動作します。
  • 🐛 ボット チャット セッションの下位互換性 - 古い履歴がすでに存在する場合、/chat は従来の {platform}_{user_id} セッション ID を使用し続けるようになり、/history は引き続き新しい {platform}_{user_id}:chat 形式と並行して移行前のセッションを一覧表示/表示/クリアできます。
  • 🐛 EventMonitor のサポートされていないルールの拒否 - 設定の検証/ランタイムの読み込みでは、モニターが実際にはまだ評価できないアラート タイプを拒否またはスキップするようになりました。そのため、スケジュール モードは永続的な no-op ルールを黙って受け入れなくなりました。
  • 🐛 P0 基本的な集約安定性修正 (#614) - get_stock_info セクターのセマンティック回帰を修正し (belong_boards を追加し、boards 互換エイリアスを保持)、基本的なコンテキストの合理化されたコントロール トークンへのリターンを導入し、基本的なキャッシュに最大限のエントリの削除を追加し、フェールオープンと最小限の侵入を保証するための ETF 全体のステータス集計と NaN セクター フィールド フィルタリングを完了します。
  • 🔧 GitHub Actions 検索エンジン環境変数の追加 — ワークフローにより MINIMAX_API_KEYS、BRAVE_API_KEYS、SEARXNG_BASE_URLS 環境変数マッピングが追加され、GitHub Actions ユーザーが MiniMax、Brave、SearXNG 検索サービスを構成できるようになります (以前の v3.5.0 にはプロバイダー実装が追加されていましたが、ワークフロー構成がありませんでした)
  • 🤖 マルチエージェントのランタイムの一貫性 — AGENT_MAX_STEPS は調整された各サブエージェントに伝播するようになりました。過度に長いパイプラインがさらにカスケードされる前に停止するために、協力的な AGENT_ORCHESTRATOR_TIMEOUT_S 予算を追加しました
  • 🔌 マルチエージェント機能の接続 — AGENT_RISK_OVERRIDE は、ハード リスクの検出結果に基づいて最終ダッシュボードを積極的にダウングレードするようになりました。 AGENT_MEMORY_ENABLED は、最新の分析メモリと信頼度の調整を専門のエージェントに注入するようになりました。マルチストック /ask が PortfolioAgent を実行して、ポートフォリオ レベルの配分と集中のガイダンスを追加するようになりました
  • 🔔 EventMonitor ランタイムワイヤリング — スケジュール モードで、AGENT_EVENT_ALERT_RULES_JSON からアラート ルールをロードし、AGENT_EVENT_MONITOR_INTERVAL_MINUTES でポーリングし、既存の通知サービスを通じてトリガーされたアラートを送信できるようになりました。
  • 🛠️ フォローアップの安定性修正 — マルチストック /ask は、ダッシュボード JSON の解析が失敗した場合に、使用可能なテキスト出力に戻ります。 EventMonitor は、スケジュールの起動を中止する代わりに、意味的に無効なルールをスキップします。バックグラウンド アラート ポーリングは、メインのスケジュールされた分析ループとは独立して実行されるようになりました。
  • 🧪 マルチエージェント回帰カバレッジ — run()、chat()、クリティカル段階の障害、正常な低下、およびタイムアウト処理のオーケストレーター実行テストを追加しました
  • 🧹 PortfolioAgent のクリーンアップ — post_process() は共有 JSON 解析を再利用し、古くなった未使用のインポートを削除しました
  • 🚦 ボットの非同期ディスパッチ — CommandDispatcher が dispatch_async() を公開するようになりました。 NL インテントの解析とデフォルトのコマンドの実行はイベント ループからオフロードされ、DingTalk ストリームは非同期ハンドラーを直接待機し、Feishu ストリームの処理は SDK コールバック スレッドから移動されます。
  • 🌐 非同期 Webhook ハンドラー — 非同期コンテキスト (FastAPI など) から使用するための bot/handler.py の新しい handle_webhook_async() 関数。スレッドブリッジを使用せずに dispatch_async() を直接呼び出します。
  • 🧵 Feishu ストリーム ThreadPoolExecutor — メッセージ バースト時のスレッド爆発を防ぐために、メッセージごとに生成される無制限の Thread を上限付きの ThreadPoolExecutor(max_workers=8) に置き換えました。
  • 🔒 EventMonitor の安全性 — _check_volume() は、None を返す get_daily_data を安全に処理するようになりました (タプル解凍時のクラッシュはありません)。 on_trigger コールバックは、asyncio.to_thread/await を介して同期呼び出し可能と非同期呼び出し可能の両方をサポートします
  • 🧹 ResearchAgent dedup — _filtered_registry() は、フィルタリング ロジックを複製するのではなく、BaseAgent._filtered_registry() に委任するようになりました。
  • 🧹 ボットの末尾の空白のクリーンアップ — bot/handler.py、bot/dispatcher.py、bot/commands/base.py、bot/platforms/feishu_stream.py、bot/platforms/dingtalk_stream.py にわたる W291/W293 の空白の問題を削除しました。
  • 🐛 ディスパッチャー _parse_intent_via_llm の安全性 — JSONDecodeError ハンドラーの未定義変数ガードのために、壊れやすい 'raw' in dir() を 'raw' in locals() に置き換えました。
  • 🐛 入力されていない場合はチップ構造 LLM を完成させる (#589) — DeepSeek および他のモデルが chip_structure を正しく入力しない場合、データ ソースから取得したチップ データを使用して自動的に完成させ、各モデルの表示が一貫していることを確認します。通常の分析とエージェントモードの両方が有効です
  • 🐛 履歴レポートのスナイパー ポイント表示の元のテキスト (#452) — 履歴の詳細ページでは、raw_result.dashboard.battle_plan.sniper_points の元の文字列の表示が優先されるようになり、analysis_history の数値列が間隔、説明テキスト、または複雑なポイントを 1 つの数値に圧縮するのを防ぎます。元の数値列をフォールバックとして保持します
  • 🐛 セッション プレフィックスの衝突 - ユーザー ID 123 は、startswith 経由でユーザー 1234 のセッションを参照できます。 session_id 形式のコロン区切り文字で修正されました
  • 🐛 NL プレフィルターの誤検知 — re.IGNORECASE により、[A-Z]{2,5} は「hello」などの一般的な英語の単語と一致しました。グローバル フラグを削除しました。英語の金融キーワードにはインライン (?i:...) のみを使用してください
  • 🐛 戦略引数内の点線ティッカー — _get_strategy_args() は BRK.B を株式コードとして認識せず、戦略テキスト内に残しました。 TICKER.CLASS 形式を受け入れるようになりました
  • ⏱️ efinance の長時間通話ハング修正 (#660) — すべての efinance API 通話に _ef_call_with_timeout() ラッパーを導入します (デフォルトは 30 秒、EFINANCE_CALL_TIMEOUT 経由で設定可能)。 executor.shutdown(wait=False) を使用して、タイムアウト後にメインスレッドがブロックされないようにして、81 分間のハング問題を完全に排除します。
  • 🛡️ タイプセーフなコンテンツ整合性チェック (#660) — check_content_integrity() は、dict.strip() によるダウンストリーム get_emoji() のクラッシュを回避するために、非文字列型 operation_advice / analysis_summary を欠落フィールドとして扱うようになりました。
  • 📄 レポートの保存と通知の分離 (#660) — _save_local_report() は send_notification フラグ トリガーに依存しなくなり、ローカル レポートは --no-notify モードで通常どおり保存されます。
  • 🔄 operation_advice 辞書の正規化 (#660) — パイプラインと BacktestEngine は、モデル出力形式の変更によるクラッシュを防ぐために、LLM によって返された dict 形式 operation_advice を decision_type (大文字と小文字を区別しない) 経由で標準文字列にマップするようになりました。
  • 🛡️ runner.py の使用法なし保護 (#660) — response.usage が None の場合、AttributeError はスローされなくなり、トークン数 0 にフォールバックします
  • 📋 オーケストレーターのサイレント障害がログ警告に変更されました (#660) — IntelAgent / RiskAgent ステージの障害は、診断を容易にするために、サイレントにスキップする代わりに WARNING をログに記録するようになりました。

注記

  • ⚠️ マルチワーカー認証の切り替え — ランタイム認証の更新はプロセスローカルです。マルチワーカー展開では、認証状態の一貫性を保つためにワーカーを再起動/ロールする必要があります
