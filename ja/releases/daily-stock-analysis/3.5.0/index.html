daily_stock_analysis v3.5.0

マイナー 公開日2026年3月12日 出典ZhuLinsen/daily_stock_analysis 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

デイリーストック分析 v3.5.0

追加

  • 📊 Web UI の完全なレポート ドロワー (修正 #214) — 履歴ページに「完全なレポート」ボタンが追加され、サイド ドロワーに完全な Markdown 分析レポートが表示されます。新しい GET /api/v1/history/{record_id}/markdown エンドポイント
  • 📊 LLM cost tracking — all LLM calls (analysis, agent, market review) recorded in llm_usage table; new GET /api/v1/usage/summary?period=today|month|all endpoint returns aggregated token usage by call type and model
  • 🔍 SearXNG search provider (Fixes #550) — quota-free self-hosted search fallback; priority: Bocha > Tavily > Brave > SerpAPI > MiniMax > SearXNG
  • 🔍 MiniMax Web 検索プロバイダー — サーキット ブレーカー (3 回の失敗 → 300 秒のクールダウン) とデュアル タイム フィルタリングを備えた MiniMaxSearchProvider。 MINIMAX_API_KEYS 経由で設定
  • 🤖 エージェント モデルの検出 API — GET /api/v1/agent/models は、Web UI モデル セレクターの利用可能なモデル デプロイメント (プライマリ/フォールバック/ソース/api_base) を返します。
  • 🤖 Agent chat export & send (#495) — export conversation to .md file;設定された通知チャネルに送信します。新しいPOST /api/v1/agent/chat/send
  • 🤖 エージェントのバックグラウンド実行 (#495) — ページを切り替えても分析が続行されます。完了時のバッジ通知。セッション切り替え時に進行中のストリームを自動キャンセルする
  • 📝 Report Engine P0 — Pydantic schema validation for LLM JSON;レガシーフォールバックを備えた Jinja2 テンプレート (マークダウン/wechat/ブリーフ)。再試行によるコンテンツの整合性チェック。簡易モード (REPORT_TYPE=brief);履歴信号比較
  • 📦 スマート インポート — 画像/CSV/Excel/clipboard からのマルチソース インポート; Vision LLM はコード + 名前 + 信頼度を抽出します。名前→コードリゾルバー (ローカルマップ + ピンイン + AkShare);信頼度段階の確認
  • ⚙️ GitHub Actions LiteLLM config — workflow supports LITELLM_CONFIG/LITELLM_CONFIG_YAML for flexible AI provider configuration
  • ⚙️ Config engine refactor & system API (#602) — unified config registry, validation and API exposure
  • 📖 LLM 構成ガイド — 3 層構成、クイック スタート、ビジョン/エージェント/トラブルシューティングをカバーする新しい docs/LLM_CONFIG_GUIDE.md

修正済み

  • 🐛 analyze_trend は常に履歴データなしを報告します (#600) — 壊れた get_analysis_context の代わりに DB/DataFetcher からフェッチされるようになりました
  • 🐛 Chip structure fallback when LLM omits it (#589) — auto-fills from data source chip data for consistent display across models
  • 🐛 履歴スナイパー ポイントは生のテキストを表示 (#452) — 圧縮された数値よりも元の文字列を優先します
  • 🐛 GitHub アクション ENABLE_CHIP_DISTRIBUTION が構成可能 (#617) — ハードコーディングされなくなり、vars/secrets オーバーライドをサポート
  • 🐛 .env 保存ではコメントと空白行が保持されます — Web 設定により .env の書式設定が破壊されなくなりました
  • 🐛 エージェント モデル検出の修正 — レガシー モードには LiteLLM ネイティブ プロバイダーが含まれています。ランタイムに合わせたソース検出。フォールバック デプロイメントはキーごとに拡張されなくなりました
  • 🐛 Stooq 米国株の前終値セマンティクス — 始値を前終値として誤用しなくなりました
  • 🐛 Stock name prefetch regression — prioritizes local STOCK_NAME_MAP before remote queries
  • 🐛 AkShare の上限/下限計算 (#555) — 固定市場分析統計
  • 🐛 AkShare Tencent ソース フィールド インデックスと ETF 相場マッピング (#579)
  • 🐛 Pytdx ストック名キャッシュ ページネーション (#573) — キャッシュ オーバーフローを防止します
  • 🐛 PushPlus の特大レポートのチャンク化 (#489) — 長いコンテンツを自動分割します
  • 🐛 エージェント チャットのキャンセルと切り替え (#495) — キャンセルが失敗として誤って報告されなくなりました。高速スイッチはストリーム状態を上書きしなくなりました
  • 🐛 /status コマンドの MiniMax 検索ステータス (#587)
  • 🐛 config_registry の重複 BOCHA_API_KEYS — 設定をサイレントに上書きする重複した dict エントリを削除しました

変更されました

  • 🔎 フェッチャー障害の可観測性 — 開始/成功/失敗を経過時間とともに記録し、フェイルオーバー遷移をログに記録します。 Efinance/Akshare にはアップストリーム エンドポイントと分類された障害カテゴリが含まれます
  • ♻️ データ ソースの回復力とクリーンアップ (#602) — フォールバック チェーンの最適化
  • ♻️ 画像抽出 API 応答拡張機能 — 新しい items フィールド (コード/名前/信頼度)。 codes は下位互換性のために保存されています
  • ♻️ インポート解析エラー メッセージ — Excel/CSV の特定の失敗理由。ファイルの種類とサイズによるログ記録の改善

ドキュメント

  • 📖 LLM 構成ガイドをわかりやすくするためにリファクタリングしました (#583)
  • 📖 image-extract-prompt.md 完全なプロンプトドキュメント付き
  • 📖 AkShare フォールバック キャッシュ TTL ドキュメント
