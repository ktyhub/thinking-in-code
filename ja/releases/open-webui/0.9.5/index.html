open-webui v0.9.5

オープンウェブイ v0.9.5

追加

  • 🛡️ リダイレクト ベースの SSRF 保護。 すべてのアウトバウンド HTTP リクエストは、新しい AIOHTTP_CLIENT_ALLOW_REDIRECTS 環境変数を介してデフォルトで 3xx リダイレクトをブロックするようになり、パブリック URL がサイレントに内部アドレス (RFC 1918、ループバック、クラウド メタデータ エンドポイント) にリダイレクトされるリダイレクト ベースの SSRF を防止します。影響を受ける呼び出しサイトには、Web フェッチ、イメージの読み込み、OAuth 検出、ツール サーバーの実行、コード インタープリターのログインが含まれます。 #24491
  • 🛡️ Iframe コンテンツ セキュリティ ポリシー 管理者は、IFRAME_CSP 環境変数を介してすべての srcdoc iframe (アーティファクト、ツール埋め込み、ファイル プレビュー、引用モーダル) に対して Content-Security-Policy を構成できるようになり、LLM で生成された HTML またはユーザーがアップロードした HTML がプレビュー内でロードおよび実行できるものを制限できます。 コミット
  • 🎛️ 詳細なマークダウン レンダリング制御 ユーザーは、インターフェース設定からユーザー メッセージとアシスタント応答のマークダウン レンダリングを個別に無効にできるようになり、マークダウンに依存する文字を含むテキストを貼り付けるときに意図しない書式設定を防ぐことができます。 コミット
  • 🔧 ターミナル プロキシ応答ヘッダー。 管理者は、TERMINAL_PROXY_HEADERS 環境変数 (JSON オブジェクト) を介してカスタム応答ヘッダーをターミナル プロキシ応答に挿入できるようになり、プロキシされたコンテンツのサンドボックス ポリシーなどの展開固有のセキュリティ ヘッダーを有効にすることができます。 コミット
  • 🔌 チャネル ストリーミングとツールのサポート。 チャネル内のモデルに言及すると、応答がリアルタイムでストリーミングされ、ネイティブおよびデフォルトの関数呼び出し、組み込みツール (Web 検索、画像生成)、ユーザー ツール、MCP ツール、フィルター、RAG ナレッジ インジェクションを含む完全なチャット完了パイプラインがサポートされるようになりました。これらの機能は標準チャットで利用できるものと同じです。

修正済み

  • 📝 メモの作成とオープンの信頼性。 新しいメモの作成と既存のメモを開くときに、作成時に is_pinned が SQLAlchemy モデルに渡され、読み取り時に NoteResponse に 2 回渡されることが原因で TypeError が発生して失敗することがなくなりました。 #24484、#24486
  • 🔐 スキルのパブリック共有権限の強制。 スキルの作成または更新で sharing.public_skills 権限を通じてアクセス許可がフィルタリングされるようになり、管理者以外のユーザーが必要な権限なしにスキルを公開してアクセスできないようになりました。 #24494
  • 🔐 カレンダーのパブリック共有権限の強制。 カレンダーを作成または更新すると、新しい sharing.public_calendars 権限を通じてアクセス許可がフィルタリングされるようになり、管理者が明示的に付与した共有権限なしにユーザーがカレンダーをパブリックに読み取りまたは書き込み可能にすることができなくなります。 #24493
  • 🔐 フィードバック ユーザー アトリビューション スプーフィング。 評価フィードバックを送信すると、一括割り当てによって user_id フィールドが偽造できなくなり、認証されたユーザーが評価を他のユーザーに帰属させ、Elo リーダーボード ランキングや管理者フィードバック エクスポートが破損することがなくなります。 #24508
  • 🛡️ 画像 URL リダイレクト ベースの SSRF。 画像 URL を含むチャット メッセージは、base64 変換中に内部アドレスへの 3xx リダイレクトに従わなくなり、特別な権限や機能フラグを必要としない最も到達可能なリダイレクト ベースの SSRF バリアントが閉じられます。 #24524
  • 🛡️ ファイル処理におけるコレクション書き込みアクセス。 process_file および process_files_batch 取得エンドポイントは、コンテンツを埋め込む前にコレクション書き込みアクセス チェックを強制するようになり、認証されたユーザーがファイル コンテンツを別のユーザーのナレッジ ベース コレクションに挿入するのを防ぎます。 #24524
  • 🔐 ツール ソース コードの更新承認。 ツールの Python ソース コードを更新するには、workspace.tools または workspace.tools_import 権限が必要になりました。これにより、書き込みアクセス許可のみを持つユーザーは、メタデータの編集を許可しながら、実行可能ツール コードを上書きできなくなります。 #24513
  • 🔐 チャンネル メッセージの所有権の強制。 グループ チャネルや DM チャネルでメッセージを更新または削除するにはメッセージの所有権が必要になり、チャンネル メンバーが他のメンバーのメッセージを改ざんしたり、サイレントに削除したりすることがなくなりました。 #24506
  • 🔐 チャンネル ピンの書き込み権限。 標準チャネルでのメッセージの固定と固定解除には、読み取り権限ではなく書き込み権限が必要になり、読み取り専用ユーザーが固定されたコンテンツを変更できなくなります。 #24521
  • 🛡️ イメージ生成 URL の検証 生成されたイメージ URL は、フェッチする前に validate_url() によって検証されるようになり、多層防御の姿勢と兄弟のイメージ読み込みパスが調整されます。 #24518
  • 🔐 読み取り専用ユーザーに対するモデル パラメーターの公開。 モデルごとの API エンドポイントは、書き込みアクセス権のない呼び出し元への応答から params dict (システム プロンプトを含む) を削除するようになり、読み取り専用ユーザーが管理者が厳選したモデル構成を表示できなくなります。 #24525
  • 🛡️ URL パーサー SSRF バイパス URL 検証は、ターゲット ホスト上で urllib と request/aiohttp の不一致を引き起こすバックスラッシュ、タブ、CR、および LF 文字を拒否するようになり、パーサーの混乱を招く SSRF バイパスを閉じます。 #24534
  • 🛡️ プロファイル画像の MIME タイプ許可リスト。 データ URI からプロファイル画像を提供すると、厳格な MIME タイプ許可リスト (デフォルトでは PNG、JPEG、GIF、WEBP、PROFILE_IMAGE_ALLOWED_MIME_TYPES 経由で構成可能) が適用され、X-Content-Type-Options: nosniff が設定され、SVG またはその他の実行可能なコンテンツ タイプを介した保存された XSS が防止されます。 コミット
  • 🔐 フォルダーおよびナレッジ添付ファイルのファイル所有権。 フォルダーまたはナレッジ ベースにファイルを添付すると、ファイルごとの読み取りアクセスが検証されるようになり、チャット ミドルウェアのフォルダー ファイル リストは呼び出し元が読み取り可能なエントリにフィルターされ、未承認のファイル コンテンツが RAG コンテキストに挿入されるのを防ぎます。 コミット
  • 🔐 所有者と管理者の共有チャット アクセス。 チャット所有者は、明示的なアクセス許可を必要とせずに自分の共有チャットを表示および複製できるようになり、管理者は任意のチャットの共有チャット アクセス制御を管理できるようになりました。 コミット、コミット
  • 🧵 レガシー チャット履歴の自己修復。 従来の会話を読み込むと、移行されたメッセージ レコード内の壊れた親リンク グラフが自動的に検出され、埋め込まれた JSON 履歴から欠落しているメッセージがマージされ、正規化されたテーブルにバックフィルされるため、今後の読み込みではデータ損失なく高速パスが使用されます。 コミット
  • 🎛️ フィルター セレクターの反応性。 モデル フィルターのチェックボックスは、マウント時に 1 回限りのスナップショットをキャプチャするのではなく、現在のフィルター リストと選択された ID から反応的に状態を取得するようになりました。そのため、実行時にモデル コンテキストまたはフィルター構成が変更されたときに、チェックボックスが正しく更新されます。 コミット
  • 🌐 ポルトガル語 (ブラジル) 翻訳の更新。 新しく追加された UI アイテムの翻訳が、既存のエントリ間の一貫性パスとともに追加されました。 #24503

変更されました

  • 🧹 未認証の取得ステータス エンドポイントが削除されました。 未認証の GET /api/v1/retrieval/ ステータス エンドポイントはデッド コードとして削除されました。取得構成は、認証された管理エンドポイントを通じてすでに利用可能です。 #24497
  • 📋 PR テンプレートの問題要件 プル リクエストには、リンクされた問題またはディスカッションの参照が必要になり、すべての投稿の追跡可能性が向上します。リンクされた問題やディスカッションのない PR は、審査されずに終了される場合があります。
