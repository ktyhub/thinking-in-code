#カウエージェント2.2.0

🌐 英語 | 中文

🧩 能力センター

以前の スキル メニューは 機能 になり、Web コンソールとデスクトップ client の 1 か所で組み込みツール、MCP ツール、およびスキルを管理できます。

  • スキルのインストール: Cow Skill Hub、GitHub、または ClawHub からインストールするか、アーカイブ、SKILL.md、またはフォルダーをアップロードします。すべてのスキルは最初にプレビューされ、確認した後にのみインストールされます。
  • MCP 構成: UI で MCP サーバーを追加、編集、削除し、stdio、SSE、およびストリーミング可能な HTTP トランスポートをカバーします。フォーム編集と JSON 編集の両方が利用可能で、1 つ以上の mcpServers エントリを直接貼り付けることができます。保存すると接続がチェックされ、サーバーのツールが一覧表示されます。変更は再起動しなくても次のメッセージから有効になります。ありがとう@tsumon (#3155)
  • ツール取得診断: MCP ツールがどのようにランク付けされたか、会話中に取得が失敗した理由を確認できるため、ツールが選択されなかった理由を簡単に見つけることができます。ありがとう @zhongjunqi7657 (#3165)

🤝 マルチエージェントのコラボレーション

  • 個別のメッセージとしてのタスクのハンドオフ: エージェントがタスクをチーム メンバーに委任すると、メンバーの応答は、Web コンソールとデスクトップ client の両方に、自分の名前とアバターで独自のメッセージとしてストリーミングされます。
  • チーム セッション管理: コンテキストをクリアすると、チーム セッションのすべての参加者のコンテキストがクリアされるようになりました。グループ チャットでは、最初のメッセージが送信される前にセッション リストにメンバーが表示されます。 @ ピッカーは、セッションを所有するエージェントを選択できます。
  • データ分離: スキル、アップロードされたファイルのプレビュー、および Web サイトのディレクトリは、エージェントごとにスコープが設定されるようになりました。
  • 修正:
    • チームメンバーに代わって応答するエージェントと、更新後にエージェント自身のツール呼び出しが消える問題を修正しました。
    • 削除されたエージェントがメンバー リストに残り、直接チャットでツールを使用できなくなる問題を修正しました (@Frank-zhu0404 #3234 に感謝)。
    • チーム メンバーの構築時およびチャネル チームのクリーンアップ時にデフォルトのエージェントが解決されない問題を修正しました (@c020627 #3205 に感謝)。
    • パラメーターがリクエスト本文のみで送信された場合にエージェントを見つけられない一部のエンドポイントを修正しました (@c020627 #3177 に感謝)。

🖥 コンソールのアップグレード

  • フロントエンドとバックエンドの再構築: Web コンソールのフロントエンド ページとバックエンド API コントローラーが機能モジュールに分割され、保守が困難になっていた大きすぎる単一ファイルが置き換えられます。フロントエンド アセットはモジュールごとにロードされ、キャッシュされるため、更新によってすべてが再度ダウンロードされることはなくなりました。各ページには独自の URL (/agents、/settings、/scheduler など) があり、ブラウザーの前後の動作、更新は現在のページに留まり、古い /chat アドレスは自動的にリダイレクトされます。ありがとう@zkjqd (#3167、#3172)
  • メッセージ ナビゲーター: セッション内の以前の質問にすばやくジャンプします。 Web コンソールはヘッダーのボタンから質問リストを開き、デスクトップ client は右側にナビゲーション レールを追加します。
  • 1 つの click 更新: サイドバーのバージョン メニューは、1 つの click でソース更新をチェックして適用します。ユーザーデータは更新前にバックアップされるため、更新に失敗しても実行中のサービスには影響しません。ありがとう@tsumon (#3154)
  • 返信ステータス: 停止、中断、および進行中の返信には、それぞれラベルが付けられます。サービスの再起動によって切断された応答には明確な通知が表示され、更新後もまだ生成されている応答を追跡し続けることができます。

🧠 記憶と知識ベース

  • 再ランキング: メモリ取得は、精度を高めるために呼び出された結果を再スコアリングするオプションの再ランク モデルをサポートします。デフォルトではオフになっており、rerank_provider によって有効になります。ありがとう@SummerCaptain (#3230)
  • ハイブリッド検索スコアリング: ベクトル検索とキーワード検索がランク正規化スコアによって融合されるようになり、一方にヒットがなく、両者のスコアスケールが一致しない場合に希薄化したスコアが修正されます。ありがとう@SummerCaptain (#3164)
  • ナレッジ ベース インデックス: ドキュメントが削除または移動されると、index.md が更新されます (@alanyz106 #3237 に感謝します)。大きなインデックスでは、会話のコンテキストが過度に占められることを避けるために、タイトルのリストのみが挿入されます。
  • 共有ナレッジ ベース: エージェント ワークスペースの外にある共有ナレッジ ベースの読み取りと同期を修正しました (@lorenzozanee #3182、@Jeremy-xuan #3183 に感謝)。ツールまたはコンソールを通じて行われた編集では、インデックスに更新のマークが付けられるようになりました (@NBSW002 #3184、@c020627 #3206 に感謝します)。
  • 長期記憶: MEMORY.md がその長さ制限を超えると、最新のエントリが最初に保持されます (@SEVEN-us #3244 に感謝します)。
  • ドキュメントのチャンク化: 長い Markdown ドキュメントの最初の見出しの前のコンテンツがインデックス付けされず、見出しレベルがスキップされるとコンテンツが 2 回インデックス付けされる問題を修正しました。 /memory status は、インデックスを再構築するように要求します (@Bdysj #3309 に感謝します)。
  • セッションの読み込み: セッションを開いたときにメモリ スキャンとインデックスの再構築がトリガーされなくなり、新しいセッションの最初のメッセージの応答が速くなります。

関連資料: メモリ

📐 コンテキストとトークンのコスト

  • モデル キャッシュ ヒット率の向上: システム プロンプトには現在の日付のみが表示され、正確な時刻は新しい time ツールから取得されます。システム プロンプトは 1 日を通して安定しているため、モデル キャッシュのヒット率が大幅に向上し、トークンの使用量が減少します。ありがとう @a1094174619 (#3250)
  • コンテキスト トリミング: ターンベースとトークン予算のトリミングが、単一の予算主導のパスに統合されます。予算内ではサマリー呼び出しは行われず、不必要なモデル要求が回避され、前のターンが常に保持されます。 @liuns-yang (#3188)、@Frank-zhu0404 (#3199)、@lorenzozanee (#3185) に感謝します。
  • フォローアップ メッセージ: モデルのストリーミング中に送信したメッセージがすぐに受信されるようになりました (@tsumon #3190 に感謝)。

🤖 モデルの機能

  • 新しいモデル: gpt-6.1-sol、gpt-6-luna、gpt-6-sol が追加され、デフォルトの推奨 OpenAI モデルとして gpt-6.1-sol が追加されました (ツール呼び出しは応答 API を経由します)。デフォルトの推奨クロード モデルとして claude-opus-5-5 を追加しました。
  • コンテキスト ウィンドウ: Claude 5 ファミリ (claude-opus-5-5、claude-opus-5、claude-sonnet-5、claude-fable-5 など) は、以前のフラット 200K ではなく、1M コンテキスト ウィンドウと 128K の最大出力でカウントされるようになりました。クロード4以前は変更ありません。
  • OpenAI Responses API: 新しい open_ai_api_type 設定。 /chat/completions を提供しなくなったエンドポイントに対して応答 API を呼び出すには、これを responses に設定します。デフォルトの auto は既存の動作を維持します。
  • MiniMax: 画像理解で M3 のネイティブ マルチモーダル機能が使用されるようになりました (@octo-patch #3160 に感謝します)。
  • Qwen: qwen3.8-max および qwen3.8-flash はハイブリッド思考モデルとして扱われます。役割プラグインによって設定されたシステム プロンプトを無視する DashScope セッションを修正しました (@Bdysj #3310 に感謝)。
  • 音声認識: 常に whisper-1 を使用するのではなく、構成された ASR モデルを使用します。
  • AnySearch: 返された結果をより厳密に検証する構成可能な検索地域と言語 (@WangPan59 #3153、#3163 に感謝)。

  • ビデオ返信: Discord、Slack、Telegram、Feishu、DingTalk、WeChat カスタマー サービス、および WeChat 公式アカウントは、ローカルで生成されたビデオをドロップしたり、ファイル パスのみを送信したりする代わりに、直接アップロードします (@Lesereingrape #3289、#3299、#3321、@c020627 #3297 に感謝します)。

🛡 安定性とセキュリティ

このリリースでは、タスク実行の信頼性が向上し、外部リソースへのアクセスとローカル ファイルへの書き込みが体系的に強化されます。

  • 永続的な実行: 各ステップのモデル応答、ツール呼び出し、および結果は、ターンの終了時に一度にすべてではなく、ステップが完了するとすぐにセッション データベースに書き込まれます。サービスの再起動または予期しないプロセスの終了後、中断されたターンは完了したステップとともに復元され、そこから次のメッセージを続行できます。ありがとう@liuns-yang (#3191)
  • ダウンロード制限: 外部ダウンロード (チャネル メディア、端末画像、イメージ理解、キーワード ファイルなど) にはファイル サイズと合計時間が制限されているため、サイズが大きすぎるファイルや接続が遅いためにサービスが低下することはありません。イメージ理解により、リダイレクトごとにアドレスが再検証されます。 @rudycelekli (#3255、#3256、#3257、#3264、#3266、#3267、#3268、#3269、#3270、#3271、#3272)、@c020627 (#3219、#3225、#3252、#3300、#3322) に感謝します。
  • リクエストのタイムアウト: モデル、音声、翻訳などに対するすべての外部リクエストにタイムアウトが設定されるようになったため、応答しないアップストリームによって会話がハングすることがなくなりました。ありがとう @c020627 (#3217、#3220、#3240、#3254、#3275)
  • 安全な設定書き込み: config.json、プラグイン設定、モデル リスト、スケジュールされたタスク、スキル設定、認証情報ファイル、MEMORY.md などがアトミックに書き込まれるため、書き込みが途中で失敗しても元のファイルが破損することはありません。破損したスケジュールされたタスク ファイルはバックアップから自動的に復元されます。ありがとう @c020627 (#3223、#3239、#3241、#3242、#3259、#3273、#3274、#3276、#3279、#3280、#3281)、@rudycelekli (#3260)
  • 一時ファイル: チャネルによって受信されるファイル名は一時ディレクトリに限定され、長さが制限されます (@Lesereingrape #3247、#3248、@c020627 #3212、#3301 に感謝);ダウンロードされたメディア、返信の添付ファイル、および合成音声は、所有するエージェントの一時ディレクトリに保存されます (@c020627 に感謝 #3198、#3207、#3208、#3213)。スキル アーカイブの抽出に失敗すると、一時ディレクトリがクリーンアップされます (@Lesereingrape #3325 に感謝)。
  • ログ編集: チャネル認証情報はデバッグ ログでマスクされます (@fuxicodex #3228 に感謝します)。

  • スケジュールされたタスク: 夏時間移行中もローカルの実行時間は維持されます (@liuns-yang #3189、#3204 に感謝)。スケジュールされたスキルの実行によって生成されたファイルは、ファイル パスとしてではなく直接配信されます (@c020627 #3253 に感謝)。

    • README の壊れたリンクとログの文言を修正しました (@yetuge #3194、#3196、#3197 に感謝します)。
