#mlflowv3.14.0

MLflow 3.14.0 には、いくつかの主要な機能と改善が含まれています

主な新機能

  • 🚀 mlflow agent setup によるワンコマンド エージェント オンボーディング: MLflow のインストール、トレースの設定、お気に入りのコーディング エージェント (Claude Code、OpenAI Codex、または OpenCode) に MLflow スキルを渡し、アプリをインストルメント化する操作をすべて 1 つのコマンドから行います。
  • ⚡ クロード コードの耐久性があり、低遅延のトレース: クロード コードのトレースを自信を持ってチーム全体に展開します。ログ先行書き込みにより、エージェントの速度が低下したり、トラッキング サーバーに負荷をかけたり、ネットワーク ブリップやクラッシュでトレースが失われたりすることがなくなります。
  • 📝 トレースのレビュー キュー: トレースをレビュー担当者 (またはエージェント) に割り当て、UI で構造化されたフィードバックとグラウンドトゥルースの注釈を収集します。これらの注釈はトレースに直接書き戻されるため、評価にすぐに使用できます。
  • 🗂️ 改良された評価データセット UI: ソース トレースへの click スルーを使用して、評価データセット レコードを UI で直接参照、検査、編集、一括管理します。
  • 🧪 回帰テストのための Pytest 統合: GenAI 回帰テストを @mlflow.test マーカーを使用したプレーンな pytest 関数として記述し、CI でゲートし、UI でテスト履歴とアサーションごとの判定結果を確認します。
  • 🎛️ LLM Playground: AI Gateway エンドポイントとプロンプト レジストリのバージョンに対して、設定、ツール、構造化出力、テンプレート変数を使用して、ブラウザーのプロンプトを反復処理します。

重大な変更

  • [モデル] mlflow.sklearn serialization_format のデフォルトを cloudpickle から skops に変更 (#23987、@copilot-swe-agent)
  • [モデル] mlflow.pytorch.log_model および mlflow.pytorch.save_model の serialization_format のデフォルトを "pt2" に変更 (#23988、@copilot-swe-agent)
  • [モデル] mlflow.lightgbm log_model/save_model の serialization_format のデフォルトを "skops" に変更 (#23986、@copilot-swe-agent)
