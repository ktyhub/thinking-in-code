Codewhale v0.8.66

コードホエール v0.8.66

CodeWhale は正規のプロジェクト、コマンド、npm パッケージであり、 リリースアセット名。従来の npm パッケージ deepseek-tui は 非推奨となり、今後のリリースはありません。からのユーザー v0.8.x のレガシー deepseek / deepseek-tui 名は移行する必要があります docs/REBRAND.md で。

インストール

推奨 — npm (1 つのコマンド、両方のバイナリ)

npm install -g codewhale

ラッパーは、一致するランタイム バイナリをこのリリースからダウンロードし、同じディレクトリに配置します。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

このイメージには、codewhale ディスパッチャ、codew シム、および codewhale-tui ランタイムが同梱されています。 latest タグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

両方のクレートが必要です。codewhale-cli は codewhale ディスパッチャーと codew シムを生成し、codewhale-tui はディスパッチャーが委任する対話型ランタイムを生成します。クレートを 1 つだけインストールすると、実行時に MISSING_COMPANION_BINARY エラーが発生して失敗します。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale ディスパッチャ、codew シム、codewhale-tui ランタイムに加えて、インストール スクリプトが含まれています。 |プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。 codewhale.exe、codew.exe、および codewhale-tui.exe を %LOCALAPPDATA%\Programs\CodeWhale\bin の下にインストールし、そのディレクトリを現在のユーザーの PATH に追加します。
  • codewhale-windows-x64.zipの抽出
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。 各プラットフォームには、ベア、アーカイブされていない バイナリ (codewhale-<platform>、codew-<platform>、および codewhale-tui-<platform>) が以下に添付されています。npm ラッパーとアプリ内 codewhale update は一致するランタイム バイナリをダウンロードしますが、上記の .tar.gz / .zip アーカイブは推奨される手動ダウンロードであり、さらにインストール スクリプトがバンドルされています。従来の npm パッケージ deepseek-tui は非推奨となり、再公開されません。 v0.8.x のレガシー バイナリ名からの移行については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

v0.8.66 の内容

追加

  • codewhale doctor / codewhale doctor --json レガシーステートを追加 既知の ~/.deepseek 状態パスとその状態パスを比較する診断 ~/.codewhale に対応し、未移行またはデュアルルート データにフラグを立てます (#3727)。
  • 第一級OpenAI対応プロバイダーとしてSakana AI Fuguを追加 sakana/fugu エイリアス、FUGU_API_KEY / SAKANA_API_KEY の検出、 プロバイダーとピッカーの接続、モデルの完成、プロバイダーのドキュメント。から収穫 #3748 @lerugray による。
  • WhaleFlow-to-Fleet の起動形状検証を追加しました: デフォルトのフリート ワークフロー 契約では合計 100 のエージェントと 5 つの再帰リングが許可されます。 起動前に境界付きループ/展開を行い、スロットごとのモデル選択を保持します。
  • 解決済みの読み取り専用 /config ask-rules ビューを追加しました。 permissions.toml パス、ファイル ステータス、ルール数、および構成済み ツール/コマンド/パスの質問ルール。 @greyfreedom によって #3569 から統合されました。
  • プロバイダーレベルの context_window オーバーライドを追加したため、OpenAI と互換性があります ゲートウェイとセルフホステッドプロバイダーは、実際のモデルに基づいて予算を立てることができます コンテキスト ウィンドウ (#3545)。
  • アーカイブ、Windows インストーラー入力をリリースするためのネイティブ codew シムを追加しました。 ローカルのリリース資産の準備とチェックサム検証により、手動インストールが可能になります。 Cargo が build をインストールするのと同じ短いコマンドを受け取ります。
  • 構成を備えたファーストクラスの Anthropic Messages プロバイダーとして OpenModel を追加しました。 CLI、プロバイダー ピッカー、ドキュメント、およびレジストリの範囲。 #3585 から収集 @noaft。
  • WeCom Bridge の導入とセキュリティに関するドキュメントを追加し、同梱されています ランタイム/ブリッジ コマンドと承認タイムアウト環境のガイダンス。収穫された #3640 @pkeging より。
  • オフライン リリース ゲーティング用のトークン/キャッシュ/コスト scorecard コマンドを追加しました。 ベースライン回帰チェックとターンごとのコストの可視化 (#3388)。ストリーム-JSON exec メタデータは保守的な input_analysis も報告するようになりました。 visible_final_answer_chars、ベンチマーク ハーネスでトランスクリプトを測定できる 推測することなく、成長と最終回答の肥大化を実現 (#2956、#2957)。
  • v0.8.66 のリリース証拠台帳を追加し、外部 ACP をオープンしました 公開されたものを検証した後の CodeWhale のレジストリ送信 codewhale@0.8.65 上流のレジストリ チェッカーに対する ACP 認証ハンドシェイク (#3192)。
  • Verifier-preview レーンに型付き [verifier] 構成テーブルを追加しました。 enabled と出荷された verdict_policy = "hunt" のマッピングが文書化されており、 検証済み (#2093)。
  • 決定カードキーを使用したホットバー Alt+1 ～ Alt+8 クイックスロット切り替えを追加しました 曖昧さ回避に加えて、 ホットバー (#3796、#3788)。
  • リリース/ドキュメントの衛生管理: 保護されたパブリック インストール/バージョン スニペットと npm codewhaleBinaryVersion ドリフト防止ポインター、check-docs/check-facts 製 古いスニペットまたはマップされていないプロバイダーで失敗し、sync-changelog が停止しました [Unreleased] のみが存在する場合にリリースをドロップしないようにしました (#3767、#3768、#3769、 ＃3770、＃3771、＃3772）。

変更されました

  • ユーザー側のモード ピッカー、サイクル、ホットバー、/mode からの遅延自動モード コマンド、およびランタイム スレッド モードは、明確なプロンプトが表示されるまでオーバーライドされ、 自動レビュー動作。既存の auto モード テキストがエージェントに折り返されるようになりました 中空モードを選択する代わりに、モーダル コピーの承認は意味を持たなくなりました。 現在のモードは YOLO (#3730、#3733) です。
  • フリートのセットアップ画面とドキュメントを明確にし、フリートが耐久性のあるものとして扱われるようにしました。 WhaleFlow がエージェントによって作成されるのに対し、サブエージェント構成レイヤー フリート スロットを選択して監視するオーケストレーション プラン。
  • 必要な構造を維持しながら、デフォルトの憲法プロンプトをスリム化しました 回帰カバレッジの下にアンカーし、静的プロンプトのフットプリントを削減します。 キャッシュに依存するターン (#2953)。
  • 承認プロンプトを全画面ではなくインラインで下部にアンカー表示するようにしました 引き継ぎのため、ツールが決定を待っている間もコンテキストとコントロールが表示されたままになります。 (#3799)。
  • 明示的にセットアップをオプトインするまで、ホットバーはデフォルトで非表示になりました (#3807)。の インタラクティブ エージェント シェルもデフォルトで共有された承認ゲートオンになります。 ベースライン (#3756)。
  • モード権限は、単一の権限を通じて承認プロンプトを解決するようになりました。 サーフェスごとのチェックではなくソース (#3795)。

修正済み

  • いつでもユーザーに表示される移行通知により、レガシー状態の再配置が表示されます ~/.deepseek/<state> は ~/.codewhale/<state> に移動またはコピーされるため、 アップグレードされたユーザーは、自分のデータが保存され、正規の状態がどこにあるかを知ることができます。 現在は生きています (#3726)。
  • アップグレードされたインストールで従来の .deepseek/sessions の表示を復元しました。 コピーすることにより、空の ~/.codewhale/sessions ディレクトリがすでに存在していました。 プライマリ CodeWhale セッション ストアにレガシー セッション エントリがありません 新しいデータを上書きせずに実行できます (#3724)。
  • 読み取り専用シェルコマンドなどの承認リスク分類を冷静にしました。 codewhale --version、codewhale --help、git status --porcelain なので モーダルは、証明された読み取り専用シェルを破壊的であるとラベル付けしなくなりました (#3730)。
  • /cache ターン テレメトリにプロバイダー/モデル ルート列を追加しました。 キャッシュヒット回帰は自動ルート変更と相関関係がある可能性があります (#3738)。
  • ランタイム API 承認処理が修正され、ワークスペース trust が自動解決されなくなりました 通常のツールの承認。 trust はフルアクセスの再試行にのみ参加するようになりました YOLO/自動承認は承認バイパスのままです (#3736)。
  • モーダル サーフェスを修正し、共有ビュー スタックが前に不透明な背景をペイントするようにしました。 オーバーレイ、プラン/リクエスト入力ポップアップの内部は不透明のままで、プランは 確認フッターにより、狭い端末でもアクションの選択肢が表示されます (#3732)。
  • ファイル書き込みツールと書き込み可能な MCP 用のターン ループ プラン モード ガードを追加しました。 ツールを使用して、Plan の「書き込み禁止」の約束が承認または実行前に強制されるようにします。 サンドボックス/カタログ層 (#3734) だけではありません。
  • パブリッシュのようなシェルアクションのための耐久性のあるレビュー安全フロアを維持しました。 YOLO モード、つまり cargo publish、npm publish、タグ/リリースで強制的にプッシュ サイレント自動承認ではなく承認を行います (#3735)。
  • CodeWhale のターミナル入力ポンプの場所で Ctrl+O 外部エディタがフリーズする問題を修正 Vim/エディターが端末を所有している間、特に次の場合にキーを読み取り続ける可能性がありました。 Windows mintty/cygwin シェル。正確な再現 (#3657) をしてくれた @buko に感謝します。
  • 一時的な貨物レジストリ EOF に対する OHOS 依存関係ドリフト チェックを強化しました。 CI が失敗する前にディペンデンシー グラフ プローブを再試行します。
  • /links プロバイダーのフォールバックを現在の CodeWhale ドキュメント URL に更新しました。 Baidu Qianfan ドキュメントのリンクを追加しました。 @noaft によって #3621 から収集されました。
  • ベンチマーク/実行実行用に強化された CODEWHALE_TOOL_SURFACE=shell-only: シェルのみのサーフェスは、モデルに表示されるカタログからネイティブ ツールを非表示にします。 不明な CODEWHALE_TOOL_SURFACE 値は、静かに低下するのではなく、警告するようになりました。 ツール表面全体に戻ります (#2954)。
  • サブエージェントのファンアウトとロック ホット パス: イベント チャネルのヘッドルームを維持 進行状況イベント (#3783、感謝 @cyq1017)、独立したサブエージェントを開始させます シリアル化の代わりに単一の並列ディスパッチ バッチを結合 (#3801)、レンダリング 制限付きの読み取り専用スナップショットからのサブエージェント サイドバー/ListSubAgents クリーンアップ (#3803)、ListSubAgents の更新にノンブロッキングのベストエフォート送信を使用 クリティカルなイベントを待機している間に (#3802)、サブエージェントの状態を移動しました 永続ディスク I/O はマネージャー書き込みロック (#3805) をオフにし、try_lock を使用しました 非同期 UI パスでのシェルマネージャーの更新用 (#3804)。
  • 来歴: ランタイム継続と SubAgentHandoff が既存の状態を継承するようになりました。 YOLO 権限、MemoryRecall、ImportedTranscript、および AssistantGenerated 入力は保護されたままです (#3817)。
  • 承認の誠実さ: セッションを対象とした承認に正確にラベルを付けます。 「常に」とツールの結果に承認の決定を表示します (#3766)。 このリリースの貢献者のクレジットは、上記の changelog エントリに記載されています — レポート、PR、レビュー、複製によってこの記事を形作ってくれたすべての人に感謝します。 完全なメモについては CHANGELOG.md を、古いリリースについては docs/CHANGELOG_ARCHIVE.md を参照してください。
