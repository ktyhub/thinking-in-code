コードホエール v0.9.5

Codewhale は Shannon Labs の公開製品です。 codewhale コマンド、npm パッケージ、リリースアセット名は技術的に小文字のままです 識別子。従来の npm パッケージ deepseek-tui は非推奨になりました。 今後のリリースは受け付けません。 v0.8.x レガシー deepseek からのユーザー / deepseek-tui 名は docs/REBRAND.md とともに移行する必要があります。

インストール

推奨 — npm (1 つのコマンド、両方のエントリポイント)

npm install -g codewhale

ラッパーは、一致する codewhale および codew コマンド アセットをダウンロードします。 このリリースから。どちらにも同じコンパイル済みランタイムが含まれています。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.5

このイメージは、codewhale と codew の両方と同じランタイムを公開します。の latestタグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli --locked

Cargo パッケージには codewhale がインストールされます。 Cargo は 2 番目のコマンドを作成できません 1 つのバイナリ ターゲットからのエイリアス。スペルを短くしたいユーザーは、 codew は、インストールされた実行可能ファイルへのシンボリックリンクです。 npm、Homebrew、アーカイブ、 シェルインストーラーとコンテナー チャネルは、両方のコマンド名を直接インストールします。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale での同じランタイムが含まれており、 codew コマンド名とインストール スクリプト: |プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。インストールします codewhale.exe および codew.exe の下 %LOCALAPPDATA%\Programs\CodeWhale\bin を実行し、そのディレクトリを 現在のユーザーのパス。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。 各プラットフォームには、ベア、アーカイブされていない codewhale-<platform> と codew-<platform> アセット。 7 つの codewhale-tui-<platform> ファイル名 v0.9.5 に添付されているものは、バイト同一の互換性コピーであり、目的にのみ使用されます。 すでにインストールされている v0.9.4 clients は、この単一バイナリを発見して通過します。 移行。現在のインストーラーは 3 番目のランタイムを公開していません。従来の npm パッケージ deepseek-tui は非推奨であり、再公開されていません。移行用 v0.8.x 従来のバイナリ名からの変更については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

v0.9.5 の内容

Codewhale v0.9.5 はターミナル アプリケーションをコンパイル済みの 1 つに統合します 使い慣れた codewhale および codew コマンドを維持しながらランタイムを実行します。それ また、マネージド ランタイム API も拡張され、セッションとフリートの作業が容易になります。 検査して再開し、隠されたローカル継続バックストップを削除します。 最終的なアシスタントの応答がなければ、生産的な作業が終了する可能性があります。

追加

  • model = "auto" (プロンプトベースの階層選択用): 設定すると、 ディスパッチャーは、TUI に委任する前にユーザーのプロンプトを分析し、 複雑なタスクの場合は deepseek-v4-pro を、単純なタスクの場合は deepseek-v4-flash を選択します タスク (PR #5257)。
  • 永続的な目標、境界付きメモリ検査、MCP のためのランタイム API コントロール サーバーとスキルのライフサイクル管理、および永続的なフリート受領証拠。
  • /tree、/branch、/fork、および追加専用のセッション ツリー履歴 /resume、さらに /rc リモート コントロールと管理されたログイン。
  • 組み込みの派遣態勢とピン留めされたインジケーター用の統合された艦隊名簿 これにより、アクティブなバックグラウンド作業がコンポーザーの上に表示されます。
  • ローカル スナップショットを即時に返す増分 MCP レジストリ更新 バックグラウンドで更新します。
  • Scout および Reviewer エージェントは、制限された直接コマンド証拠シェルを使用して、 読み取り専用ワークスペース、Git、GitHub インスペクションを備え、プライベート作業を維持できます メモは独自の To-Do に記録され、耐久性のあるトランスクリプトは証拠を保持します。

変更されました

  • codewhale-cli にはターミナル ランタイムが直接含まれるようになりました。リリースインストーラー 別個の TUI を使用せずにバイト同一の codewhale および codew コマンドを公開します 実行可能。 v0.9.5 アセット セットのみは非推奨のままです codewhale-tui-* ファイル名はバイト同一の互換コピーとして扱われるため、 インストールされている v0.9.4 client は、このアップグレードを検出して完了できます。
  • スタートアップ リリース チェックは、成功したルックアップを 1 時間キャッシュします。アップデーター プライマリ ランタイムを一度ダウンロードして検証し、既存のランタイムを更新します。 同じバイトからの codew または従来の codewhale-tui コマンド パス。
  • ヘッドレス codewhale exec の実行と検証ベンチマークのロールアウトが行われなくなりました 100 ステップのデフォルトを課します。 --max-turns は明示的なものとして引き続き利用可能です オプトイン上限。フリート従業員は、個別に設定された予算を保持します。
  • 目標トークンと時間予算はデフォルトの停止ではなくテレメトリです 条件があり、自動ゴールの継続はユーザーがしない限り無制限です。 継続上限を明示的に設定します。
  • コマンドパレットとスラッシュ補完のシャドウイングは、エイリアス対応の 1 つを共有するようになりました。 ディスカバリー契約。
  • Web サイトのインストール ガイダンス、ローカライズされた製品コピー、ナビゲーション コントロール、 ソーシャル メタデータと Cloudflare ビルド パイプラインで、 同じ 1 回実行のリリース契約。

修正済み

  • 隠された 20 ステップのユーザー入力不要のバックストップにより、生産的なターンが終了しなくなりました。 ツールの結果、キューに入れられたステアリング、子の完了、REPL フィードバック、および目標 継続はすべて、次のプロバイダーのステップと最終アシスタントに到達できます。 応答;ユーザーが設定した明示的な制限と本物のスタック ループ ガードは残ります。
  • 完全なエラーの詳細は、障害後に直接検査することができます。 端末には、clipped の回復不可能なエラー フラグメントが残ります。
  • 新しく作成された OAuth 認証情報が同じプロバイダー選択で採用されます 2 回目のピッカーの移動を必要とせずに、フローを実現します。
  • 新しいセッション タイトルは、キャッシュされた古くなった New Session プレースホルダーを置き換えることができます。 不明なモデルのコンテキスト制限が大声で失敗し、リリース/ソースインストールのフォールバックが発生する 単一実行時の変換によって削除されたバイナリを要求しなくなりました。
