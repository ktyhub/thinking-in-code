コードホエール v0.9.1

Codewhale は Shannon Labs の公開製品です。 codewhale コマンド、npm パッケージ、リリースアセット名は技術的に小文字のままです 識別子。従来の npm パッケージ deepseek-tui は非推奨になりました。 今後のリリースは受け付けません。 v0.8.x レガシー deepseek からのユーザー / deepseek-tui 名は docs/REBRAND.md とともに移行する必要があります。

インストール

推奨 — npm (1 つのコマンド、3 つのエントリポイントすべて)

npm install -g codewhale

ラッパーは、一致する codewhale、codew、および codewhale-tui をダウンロードします。 このリリースのバイナリをダウンロードし、同じディレクトリに配置します。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.1

このイメージには、codewhale ディスパッチャ、codew シム、および codewhale-tui ランタイムが同梱されています。 latest タグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

両方のクレートが必要です。codewhale-cli は codewhale ディスパッチャーと codew シムを生成し、codewhale-tui はディスパッチャーが委任する対話型ランタイムを生成します。クレートを 1 つだけインストールすると、実行時に MISSING_COMPANION_BINARY エラーが発生して失敗します。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale ディスパッチャー、codew シム、codewhale-tui ランタイムに加えて、インストール スクリプトが含まれています。 |プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。 codewhale.exe、codew.exe、および codewhale-tui.exe を %LOCALAPPDATA%\Programs\CodeWhale\bin の下にインストールし、そのディレクトリを現在のユーザーの PATH に追加します。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。 各プラットフォームには、ベア、アーカイブされていない バイナリが以下に添付されています (codewhale-<platform>、codew-<platform>、および codewhale-tui-<platform>)。npm ラッパーとアプリ内 codewhale update は一致するランタイム バイナリをダウンロードしますが、上記の .tar.gz / .zip アーカイブは推奨される手動ダウンロードであり、さらにインストール スクリプトがバンドルされています。従来の npm パッケージ deepseek-tui は非推奨となり、再公開されません。 v0.8.x のレガシー バイナリ名からの移行については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

  • プロバイダー対応ヒューリスティックおよび分類器で [auto] cost_saving = true を尊重する ルーティング、検証済みの同じプロバイダーの高速兄弟のみを使用し、導出 代替候補を実際のプロバイダーからバックバックするため、Auto は クロスプロバイダーモデル。既知の高速兄弟が存在しないプロバイダーは、 アクティブなモデル (#4486; 部分的な #4405)。
  • SSH 経由で端末 client clipboard の動作を真実にする: OSC 52 を使用する tmux の外側、tmux 内のストック tmux load-buffer -w、およびブラケットで囲まれたペースト client-to-remote テキストの場合。グラフィックテキストと画像へのアクセスには、 信頼できる転送または明示的なオーバーライドにより、トランスポート障害は発生しなくなりました 成功を主張し、ターミナルのテキスト貼り付けとグラフィック貼り付けを区別するのに役立ちます 画像添付ファイル (#4484)。
  • 新しい TUI 作業面が前のセッションのワーカー スナップショットをレンダリングしないようにする または、作成または完了が以前に作成または完了した耐久性のあるタスクの端末受領書 現在のアプリの起動。アクティブな永続タスクは表示されたままになり、履歴が共有されます /tasks およびアーカイブされたエージェント ビューを通じて引き続き利用可能 (#4488; 部分的) #4416)。
  • ドクターとセットアップ出力で静的設定、コマンドを区別できるようにする 可用性、MCP プロトコルの準備状況、バックエンドの健全性の代わりに 設定されたルートを正常な状態として表示します。普通の医者は走らない --probe-local を除く、より長いウェイク ループバック/セルフホステッド プロバイダー 明示的に要求されました (#4485; 部分的 #4406)。
  • テスト専用の構成パスリーダーを一時環境でシリアル化します。 Windows プロバイダー永続マトリックスが他のものを監視できないようにリダイレクトします。 テストの一時的な CODEWHALE_HOME または構成パス (#4483、終了 #4463)。
  • 直接 Moonshot kimi-k3 を文書化された 1,048,576 トークンに復元します ライブを処理する代わりに、コンテキスト ウィンドウと 131,072 トークンの出力制限を適用します。 未知のレガシー 128K ルートとしてモデル化されます。既存の Family Code 階層型 k3 ルートと資格情報の再利用は変更されません (#4481)。
  • 編集前読み取りスナップショットをエンジン セッションに保持し、読み取られたファイルが残るようにする 新しいセッションがまだ開始されている間、ターンとコンテキストの圧縮にわたって有効です 空のトラッカー (#4475 by @Angel-Hair) を使用します。
  • apply_patch が続行中に正規の replace 操作を公開するようにします。 1 つの検証パスを通じて非推奨の changes ペイロードを受け入れるため。混合 パッチ、置換、および互換性モードは、書き込み前に失敗するようになりました (#4476 by @Angel-Hair)。
  • キャッシュ ステータス項目が表示されている場合、フェーズ ストリップにプロンプト キャッシュ ヒット率を表示します。 オーバーフローセーフな丸め整数演算を使用し、コンパクトなままにするか、または 無効ステータスのレイアウトは変更されません (#4474 by @dmitri-0)。
  • Solarized Light の標準 Base3 (#fdf6e3) シェル背景を保持 デフォルトの水中オンブルでグリーングレーに染める代わりに 前景の周囲の生活を維持しながら処理 (#4457 by @AurArtanis; PR #4471 by @nightt5879)。
  • /slop および /canzha を /debt の互換性エイリアスとして登録します。 ディスパッチ、ヘルプ、スラッシュ間でユーザーコマンドの所有権を真実に保つ 補完、エイリアスのコピー、タイプミスの提案 (@nightt5879 による PR #4680)。
  • 従来の Kim CLI 認証情報インポートでのフェールクローズ: Codewhale の認証情報を削除 ハードコーディングされたファーストパーティ-client の偽装と更新リクエスト、決して行われない インポートされた資格情報を自動有効化または書き換えて、互換性をラベル付けします 読み取り専用のインポートされたトークンとしてルートします。明示的に構成された、まだ有効な アクセス トークンは有効期限が切れるまで引き続き使用できます。欠落している、形式が間違っている、有効期限が切れている インポートは、サポートされている Kimi コード API キー ルートを通じて回復されますが、 ファーストクラス OAuth は Codewhale 自身のベンダー登録を待っています (#4417、 部分的に対処されています）。
  • ライブ xAI OIDC に対して xAI/Grok デバイス コード OAuth ログインを復元します。 契約: 発行者/エンドポイントの検証と文書化による検出 フォールバック、ユーザー プリンシパル スコープ セット、RFC 8628 slow_down バックオフの上限 コードの有効期限、制限付き、サニタイズされた拒否、有効期限などのエラー レポート 不正な形式の応答、および CLI と CLI の両方の共有ブロッキング ワーカー境界 TUI ログインなので、reqwest がブロックしている client はプライベートを作成または削除しません Codewhale の Tokio ランタイム内のランタイム (#4410)。
  • FREQ=HOURLY オートメーションを BYHOUR/BYMINUTE で固定して永続化します ローカル カレンダー スロットにより、間隔が DST 全体にわたって壁時計の位相を維持します。 再起動、再開、RRULE 更新、重複スロットの回復、および実行後 進歩。存在しないクロック スロットはスキップされ、あいまいなスロットは次のように実行されます。 最初の出現 (#4381 by @h3c-hexin)。
  • コンテンツウォッチの下書きに正規のアイデンティティを与える: リンクとセマンティックドリフト ウォッチャーは、1 つの正規のドラフト ストレージ キーを使用して書き込みと重複排除を行うようになりました。 決定論的なハッシュサフィックス付き ID、検証およびバインドされたモデル ドリフト出力 KV が書き込む前に、真実の管理者ドラフトラベルを表示するため、変更されません 調査結果の重複を除去し、変更された調査結果は衝突する代わりに再ドラフトされました (#4453)。
  • モデル ポリシー JSON 修復でソース内のオブジェクトと配列のペイロードを考慮するようにします 順序、引用符で囲まれた文字列とエスケープにわたるネストされた区切り文字の照合、および を許可する代わりに、解析した最も早いバランスのとれた候補を返します。 一致しない開始区切り文字またはオブジェクト優先の破損した配列 ペイロード (#4430)。
  • 永続化されたサブエージェントの完了イベントとまだ実行中の制御イベントを 簡潔で権限のない再開チェックポイント、生のランタイムを維持 エンベロープ、センチネル、復元されたモデルと TUI からの再試行命令 会話状態 (#4409)。
  • 失敗した、停止した、古いサブエージェントの結果を 1 回だけ配信します。 ランタイムを閉じる前に親、ライフサイクル メールボックス、および TUI を待機します 状態。今すぐ再起動すると、孤立したキュー/モデル/ツール待機ワーカー レコードが調整されます チェックポイントを保持中に中断され、ワーカーがキャンセルされる TUI で完了したものとして読み取られるようになりました (#4408)。
  • ホスト アプリケーションに MCP OAuth ログインのキャンセル境界を与えます。 プロバイダーのログインが停止または放棄されても、通話セッションがハングしなくなりました (#4380)。
  • Windows プロセスがシェルを強制終了した後、ブロックされたリーダー結合を回避します。 セッションはリーダーをハングさせることができません (#4383)。
  • 標準入力のないオブザーバー フックに即時 EOF を与え、タイムアウトしたフックを含めます プロセスツリーにより、子孫とパイプリーダーが親の後にリークしないようにします シェルが終了します (#4489 by @luismateusvargas)。
  • 折りたたむのではなく、完全な未署名の Windows PTY プロセスのステータスを保持します。 すべての上位ビット例外または NTSTATUS から 2147483647 (10 進数と 10 進数を含む) デバイス再テスト用の 16 進診断メタデータ (#4100 by) @redjade75723）。
  • ホットバー セットアップのアクション リストをキーボード フォーカスと同期させます。 選択範囲は表示されている行を超えて移動します (/export 以降も含む) (#4418)。
  • Windows OpenHarmony Cargo リンクをリポジトリのターゲット認識経由でルーティングします Clang ランチャーを使用して、最後の Rust リンクがターゲット、sysroot、および MUSL を維持するようにします。 フラグを設定し、その契約を保護するために no-SDK リリース ガードを拡張します。これ @shenjackyuanjie の PR #4470 を完了します @shenyongqing のオリジナルと一緒にセットアップ PR #4384 の bindinggen アプローチ。
  • Web サイトのロードマップと現実を調和させる: 廃止された共有リンク 方向性は明確な非目標となり、Workrooms が考慮されます 指示があり、ローカル Web client は英語で進行中であると表示されます。 中国語 (#3418)。
  • システムプロンプトのスキルブロックとスキルロード警告は絶対に埋め込まれなくなりました ホーム/ワークスペースのパス。エントリはワークスペース相対または ~/… をレンダリングするため、 バイト安定プロンプト プレフィックスはプライベート パスを漏らすことはありません。新しい不変テスト プレフィックス内の絶対パス、API キー、およびワークスペース パスを保護します (#4632)。
  • モード/権限のベースライン単体テストは、開発者のライブを読み取らなくなりました。 settings.toml;設定 I/O を一時ディレクトリに分離します (#4628)。
  • Enter キーを押しても送信時にコンポーザーがフリーズしなくなりました。ディスパッチは 1 つに分割されます。 同期準備フェーズ (インスタント履歴 + スピナー) と生成された非同期 フェーズ (自動ルート、プリフライト、エンジン送信)、送信がゲートされている間 ディスパッチが飛行中です (#4605)。
  • 自己ホスト型ルートは不明な場合でもモデルごとの明示的な出力制限を維持します 一般的な 4K フォールバックの代わりにワイヤ エイリアスを使用します (#4655 by @h3c-hexin; PR #4656)。
  • チャット完了のアイドル タイムアウト エラーには、受信バイトと受信バイトが含まれるようになりました。 タイミングテレメトリー、プレフィルストールとミッドストリームを区別 切り詰められたツール呼び出し引数でストールします (#4657 by @h3c-hexin)。
  • set_config プロバイダーの書き込みは、メモリ内のルートを同期して維持するようになりました。 したがって、次のモデルの書き込みは代わりに新しいプロバイダーのテーブルに配置されます。 以前のプロバイダーのルートのdefault_text_modelを上書きする問題 (#4658 @gaord によるもので、フォローアップのルート同期修正も含まれています)。
