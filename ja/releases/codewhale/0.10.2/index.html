コードホエール v0.10.2

v0.10.2 の内容

Codewhale v0.10.2 は、ライブ ターミナル作業であるアニメーション ペット ビュー (/pet on) を追加します ドック、チャットごとのコンポーザー カラー (/color)、および最初の 1 回限りのメモ 何が変更されたかを示すアップデート後に開始します。 3つのセッションを終了します データ損失パスと codewhale web セッション リーク。デフォルトのランタイムを追加します デーモンソケットの場所をサンドボックス拒否リストに追加します。をアップロードする curl または wget を保持します。 資格情報;目に見えない Unicode を含むシェルコマンドを拒否します。を維持します Linux サンドボックスは、非表示の資格情報ディレクトリがシンボリックリンクの場合に動作します。そして アイドル状態の TUI 再描画作業を削減します。 /undo は丸ごと取り戻します 長いプロンプトや複数行のプロンプトを含むリクエスト。 exec --auto が説明します フルアクセスのデフォルト、より厳密なサンドボックスを明示的に尊重し、保存 ツールを有効にした実行とその失敗の受信。ローカル ランタイムは次のように表示されます。 オンボーディング、/diff は Git リポジトリの外部で動作、DeepSeek の応答ルート 再生されたツール履歴を拒否しなくなり、貢献者の修正によりトークンが改善されました アカウンティング、リレー モデル リスト、ローカライズされた応答、および Windows ランチャー 指導。委任された作業は、モデルが考案したターン数や時間の制限なしで継続されます。 また、別の子が失敗した後も、独立したワークフロー ステップを続行できます。

インストール

推奨 — 公式 GitHub リリース

新しい macOS/Linux インストール (このリリースのチェックサム済みバイナリ):

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.2" sh
"$HOME/.local/bin/codewhale" --version

Windows の場合は、以下の対応するインストーラーまたはアーカイブを使用してください。既存の 直接インストールして、codewhale update を実行します。実行可能パスを出力し、 新しいビルドを維持します。インストール ディレクトリが別のビルドによって占有されている場合、 インストール ガイド の新しいディレクトリの移行を使用してください。

二次パッケージング — npm と Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

ラッパーは、一致する codewhale および codew コマンド アセットをダウンロードします。 このリリースから。どちらにも同じコンパイル済みランタイムが含まれています。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/codewhale-hq/codewhale:v0.10.2

このイメージは、codewhale と codew の両方と同じランタイムを公開します。の latestタグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli --locked

Cargo パッケージには codewhale がインストールされます。 Cargo は 2 番目のコマンドを作成できません 1 つのバイナリ ターゲットからのエイリアス。スペルを短くしたいユーザーは、 codew は、インストールされた実行可能ファイルへのシンボリックリンクです。 npm、Homebrew、アーカイブ、 シェルインストーラーとコンテナー チャネルは、両方のコマンド名を直接インストールします。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale での同じランタイムが含まれており、 codew コマンド名とインストール スクリプト:

|プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。インストールします codewhale.exe、codew.exe、および codewhale.bat の下 %LOCALAPPDATA%\Programs\CodeWhale\bin、そのディレクトリを 現在のユーザーの PATH を指定し、優先するスタート メニューのショートカットを作成します。 Windows ターミナル (wt.exe) がインストールされている場合。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • ダブル click codewhale.bat (生の .exe ではありません) を起動します
  • install.bat を実行して、バイナリとランチャーを %USERPROFILE%\bin にコピーします。
  • %USERPROFILE%\bin を PATH に追加します

ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから codewhale.bat を抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。

各プラットフォームには、ベア、アーカイブされていない codewhale-<platform> と codew-<platform> アセット。 7 つの codewhale-tui-<platform> ファイル名 v0.9.5 に添付されているものは、バイト同一の互換性コピーであり、目的にのみ使用されます。 すでにインストールされている v0.9.4 clients は、この単一バイナリを発見して横断します 移行。現在のインストーラーは 3 番目のランタイムを公開していません。従来の npm パッケージ deepseek-tui は非推奨であり、再公開されていません。移行用 v0.8.x の従来のバイナリ名については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing
