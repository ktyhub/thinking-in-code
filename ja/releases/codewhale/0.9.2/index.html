コードホエール v0.9.2

Codewhale は Shannon Labs の公開製品です。 codewhale コマンド、npm パッケージ、リリースアセット名は技術的に小文字のままです 識別子。従来の npm パッケージ deepseek-tui は非推奨になりました。 今後のリリースは受け付けません。 v0.8.x レガシー deepseek からのユーザー / deepseek-tui 名は docs/REBRAND.md とともに移行する必要があります。

インストール

推奨 — npm (1 つのコマンド、3 つのエントリポイントすべて)

npm install -g codewhale

ラッパーは、一致する codewhale、codew、および codewhale-tui をダウンロードします。 このリリースのバイナリをダウンロードし、同じディレクトリに配置します。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.2

このイメージには、codewhale ディスパッチャ、codew シム、および codewhale-tui ランタイムが同梱されています。 latest タグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

両方のクレートが必要です。codewhale-cli は codewhale ディスパッチャーと codew シムを生成し、codewhale-tui はディスパッチャーが委任する対話型ランタイムを生成します。クレートを 1 つだけインストールすると、実行時に MISSING_COMPANION_BINARY エラーが発生して失敗します。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale ディスパッチャー、codew シム、codewhale-tui ランタイムに加えて、インストール スクリプトが含まれています。 |プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。 codewhale.exe、codew.exe、および codewhale-tui.exe を %LOCALAPPDATA%\Programs\CodeWhale\bin の下にインストールし、そのディレクトリを現在のユーザーの PATH に追加します。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。 各プラットフォームには、ベア、アーカイブされていない バイナリが以下に添付されています (codewhale-<platform>、codew-<platform>、および codewhale-tui-<platform>)。npm ラッパーとアプリ内 codewhale update は一致するランタイム バイナリをダウンロードしますが、上記の .tar.gz / .zip アーカイブは推奨される手動ダウンロードであり、さらにインストール スクリプトがバンドルされています。従来の npm パッケージ deepseek-tui は非推奨となり、再公開されません。 v0.8.x のレガシー バイナリ名からの移行については、docs/REBRAND.md を参照してください。

v0.9.2 の内容

これは Codewhale v0.9.2 ソース候補です。公開されたリリースではありません 一致するタグ、パッケージ、チェックサム、リリース アセットが存在するまで。

変更された — 動作

  • レガシー model = auto は、ネットワーク分類子を独自に選択しなくなりました。 DeepSeek API キーを押したままにすると、deepseek-v4-flash がサイレントに選択されます。 すべての自動ターンの分類子 — 誰も求めなかったルートでのターンごとのコスト、 そして 1 つのプロバイダーが残りのプロバイダーよりも特権を与えられます。 Auto はローカルのままで無料になりました ただし、明示的な [auto.router] ブロックでプロバイダーとモデルを指定する場合は除きます。 暗黙的なデフォルトに依存していた場合、それを明示的に復元します。 
    [auto.router]provider = "deepseek"model = "deepseek-v4-flash"

[auto.router] は従来の model = auto 構成のままです。無関係です フリートの Adaptive Reasoning Router に送信します。これは、によって参照される保存されたサービスです。 フリートファイルから名前を取得し、すでに凍結されたルートの難易度のみを決定します と思います。 v0.9.1以来上陸、未発売。によって発見された欠陥のクラスター ポリシー エンジン、MCP プロキシ、セッション インデックスのリードスルー監査、 およびアプリサーバーブリッジ - それらのいくつかのケースでは、間違った結果が発生します 正常に見える応答またはログ行の背後で、サイレントに到達しました。の このリリースでは、オプトイン セッション、推論、ローカリゼーション、および検査可能性も追加されています 表面。以下のエントリが明示的に指定されない限り、既存のデフォルトは安定したままになります。 違うと言う。

追加

  • /permissions は、アクティブなユーザー権限ルールのソース、各ルールのリストを表示するようになりました。 有効なマッチャーとグローバル/リポジトリのスコープ、およびそのスコープが適用されるかどうか 現在のワークスペース内。 /permissions remove <number> プレビューの削除 スナップショットにバインドされた確認トークンが必要なので、同時編集 確認されたインデックスの下に別のルールを移動することはできません。追加と削除 1 つの隣接するロックを共有し、無関係な TOML フォーマットとコメントを保持します。 permissions.toml をアトミックに置き換え、ライブ ユーザー ルールセットをリロードします セッションのみの承認をクリアせずに。 /config ask-rules はそのままです 互換性エントリ。ルールの作成、グロブ/ディレクトリ ルール、および拒否 永続化は範囲外のままです (#1186、@greyfreedom による PR #4960)。
  • /preview-request (別名 /dryrun および /preview_request) は人間専用です。 次のプライマリ ターンのプロバイダーなしの検査。生産派遣と プレビューは、チャット完了全体で 1 つの準備済みリクエストの継ぎ目を共有します、Anthropic メッセージと OpenAI レスポンス、つまりマニフェストは最終的なワイヤー モデルを読み取ります。 推論コントロール、ツールの選択、ツール スキーマ、および同じボディ ハッシュ 価値生産が発信します。 Auto を必要とするルート、ツール、または車体のファクト プロバイダ分類子、MCP 接続、可変フック、圧縮、またはキュー ランタイム インジェクションは利用できないと入力されたままになります。マニフェストは正確に報告します プライマリ ロール/レーン ID、上流のルート ソースの来歴、要求された、および 効果的な推論、正規の JSON サイズ、控えめなオフライン推定、 リクエストが実行されなかったため、プロバイダーは使用状況を使用不可として報告しました。それは決してありません モデルに表示されるツールを追加したり、プロバイダー呼び出しを送信したり、プロンプトやメッセージを出力したりします。 資格情報、エンドポイント パス、またはワークスペース パスの内容。明示的な /preview-request base-prompt モードでは、正確な有効ベースのみが印刷されます。 プロンプト;有効なシステム テキストは、最終ハッシュの背後で保護されたままになります。の 正確な本体には、使用されるのと同じ権限のある一時的な作業/To-do テールが含まれます。 従来の投影よりも新しいグラフに裏付けされた状態を含む実稼働。 プリフライトでは、プロダクションの個別に組み立てられたベースと作業の見積もりが保存されます。 権限のあるプロジェクションが使用できない場合はフェールクローズされます。アン アクティブな目標トークンの予算を使い果たした場合も、型指定された使用できない結果が生成されます アウトバウンドリクエストが構築される前に。 (#1004、#3928; @GTC2080 / TaoMu によって PR #1099 から収集されたドライラン コンセプト。)
  • 同じレーン/フリートのスラッシュ コマンド、ホットバー アクション、および CLI エントリポイント ライフサイクル操作は 1 つの型付きコントロール プレーン コントラクトを共有するようになりました (codewhale-lane::control): 安定した <domain>.<verb> ID、読み取り対書き込み 権限、永続スコープ、正確な同一性ターゲットの選択、再試行可能性、 ライフサイクルの結果、および 1 つの制限されたサニタイズされたレシート。 docs/COMMAND_CONTROL_PLANE.md それを文書化します (#1888)。
  • /lane [list|status|interrupt|restart|resume] — 耐久性のあるレーンコントロール コンポーザーは、同じ実行者 codewhale lane … によってサポートされます。 「コードクジラ」 レーン中断|再開|再開are the matching CLI verbs;レーン停止はそのままになります 互換性のあるスペルは lane interruptです。@<lifecycle-seq>` を レーン ID は、観察した正確な永続世代への書き込みを制限するため、 同時遷移は、実行されるのではなく競合として拒否されます (#1888)。

修正済み
