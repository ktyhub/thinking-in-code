コードホエール v0.9.9

Codewhale は Shannon Labs の公開製品です。 codewhale コマンド、npm パッケージ、リリースアセット名は技術的に小文字のままです 識別子。従来の npm パッケージ deepseek-tui は非推奨になりました。 今後のリリースは受け付けません。 v0.8.x レガシー deepseek からのユーザー / deepseek-tui 名は docs/REBRAND.md とともに移行する必要があります。

インストール

推奨 — npm (1 つのコマンド、両方のエントリポイント)

npm install -g codewhale

ラッパーは、一致する codewhale および codew コマンド アセットをダウンロードします。 このリリースから。どちらにも同じコンパイル済みランタイムが含まれています。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.9

このイメージは、codewhale と codew の両方と同じランタイムを公開します。の latestタグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli --locked

Cargo パッケージには codewhale がインストールされます。 Cargo は 2 番目のコマンドを作成できません 1 つのバイナリ ターゲットからのエイリアス。スペルを短くしたいユーザーは、 codew は、インストールされた実行可能ファイルへのシンボリックリンクです。 npm、Homebrew、アーカイブ、 シェルインストーラーとコンテナー チャネルは、両方のコマンド名を直接インストールします。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale での同じランタイムが含まれています。 codew コマンド名とインストール スクリプト:

|プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。インストールします codewhale.exe および codew.exe の下 %LOCALAPPDATA%\Programs\CodeWhale\bin を実行し、そのディレクトリを 現在のユーザーのパス。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します

ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。

各プラットフォームには、ベア、アーカイブされていない codewhale-<platform> と codew-<platform> アセット。 7 つの codewhale-tui-<platform> ファイル名 v0.9.5 に添付されているものは、バイト同一の互換性コピーであり、目的にのみ使用されます。 すでにインストールされている v0.9.4 clients は、この単一バイナリを発見して通過します。 移行。現在のインストーラーは 3 番目のランタイムを公開していません。従来の npm パッケージ deepseek-tui は非推奨であり、再公開されていません。移行用 v0.8.x のレガシー バイナリ名については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing

v0.9.9 の内容

Codewhale v0.9.9 は真実と回復力を備えたリリースです。シェル ツールでは次のことはできません。 ホストがディスクまたは記述子を使い果たした場合、セッションを中断する時間が長くなります。 未検証のコンテキスト ウィンドウと出力上限は、すべての時点で正直にラベル付けされます。 surface、DeepSeek V4 は公開されたピーク/オフピーク層、SSE に基づいて価格設定されます。 UTF-8 はすべての方言でクローズに失敗し、フリート シャドウイングが表示され、bwrap が取得されます。 コンテナの必需品と追加のルート、dsh スキンがバンドルに含まれています プロファイル、agent ツール スキーマは 12 フィールドまで減少し、README/Web サイト ロケールは 18 と 8 に増加します。

修正済み

  • 小文字の bash ツールは、完全な出力がこぼれたときにウェッジしなくなりました ファイルを作成できません: 一時ボリュームがいっぱいであるか、記述子テーブルが使い果たされています ハーネス内部を使用すると、すべて の通話が失敗していました (echo ok を含む) 「ストリーミング シェル出力の作成に失敗しました」と表示され、 ホストがクリーンアップされました。流出はベストエフォート型になりました (境界のある尾部は それでも返され、切り捨て通知には、完全な出力パスが存在しない理由が示されています。 欠落しています）、残りのスポーン/ストリームの失敗には、枯渇したものに名前が付けられます。 リソース — ディスク、ファイル記述子、メモリ — および次の呼び出しが安全であることを示します 再試行します (#5465; 所有者自身の 0.9.9 セッションを解除したウェッジ)。
  • 具体的なルート/提供する生産量の制限が保守的なものを上回るようになりました カタログ化されていないモデルの場合、8,192 トークンの互換性が推測されます。ルート 出力制限を公開しない、フェールクローズされたまま、文書化されたモデルの上限はそのまま 権限があり、ルート制限によって要求された上限を引き上げることはできません (#5460)。
  • あらゆる面でのコンテキスト ウィンドウの誠実さ (#5239、#5441): コンテキスト ウィンドウ ラダーの model-name hint および fallback ラングは次のとおりです。 推測すると、それをレンダリングするすべてのサーフェスがそのように表示されます - ステータスライン、 /status、/config、コンテキストプレッシャーメッセージ、モデルピッカーチップ、 そして自動ルーターのインベントリ。未検証のウィンドウが依然として実際の予算を押し上げている (圧縮トリガー、コンテキストメーター、出力予約);彼らはただ立ち止まる 誰かがチェックした機能として読み取っています。 _Nk から解析されたウィンドウ モデル名のサフィックス (qwen3-32b-256k → 256K) が独自のものになりました model-name hint は catalog よりも低く、むしろ楽観的であるため 保守的な値よりも、カタログまたはプロバイダーが報告した値がそれを上回ります。の [providers.<name>] context_window オーバーライドはハードフィックスのままであり、 マーカーなしで configured としてレンダリングされます。
  • 出力上限の正直さ (#5440): カタログにある Anthropic ファミリー モデル not description は、64K メッセージ フロアをクランプとして保持し、ChatGPT/ Codex OAuth ルートは 4K ポリシーを維持しますが、OutputCeilingSource は unverified が両方とも鳴ったので、exec-stream の受信とモデル ピッカー documented の代わりに unverified/「想定フロア」というラベルを付けます。クランプ 値は変わりません。
  • デフォルトでオンになっているテレメトリが表示されます (#5441): codewhale doctor の runtime-posture セクションには、telemetry=on (default) スタイルの行が追加されました。 それを決定したソース (cli | env | config |default)、および codewhale config get telemetry は、解決された同意を報告します。 バッチが出荷されるマシン上の key not found の代わりにソースを使用します。真実 変更のみ。解像度と動作は変更されません。
  • 艦隊: 偵察兵の読み取り専用シェル カーブアウト (#5428) が両方で尊重されるようになりました。 ポスチャ ゲートと実行エンベロープなので、git log、find | head、 代わりに、npm view および他の制限付き読み取り専用コマンドがインプレースで実行されます。 「実行」として拒否される問題 (#5426)。代表団は依然として広がらない 権限: 役割分離テストと docs/SUBAGENTS.md による子へのピン留め 親の姿勢を超えることはできません (#5426、#5435)。
  • /rename と /title は最初のターンの途中に適用されるようになりました。セッション ファイルは適用します。 最初の自動保存まで存在しないため、名前の変更は失敗しました 見つかりません;共有パスはセッションごとのチェックポイントを優先するようになり、 ライブでの PTY 回帰テストを使用してアプリの状態から再構築します。 イベントループ (#5430)。

変更されました

  • モデル向きの agent ツールは、正確に 12 フィールド (action) をアドバタイズします。 prompt、type、profile、name、agent_id、message、until、 detached、worktree、write_roots、resume_from — 33 から減少 (#5324、参照番号 #5123)。予算 (max_steps、wall_time_secs、max_depth)、 ルーティング オーバーライド (model、model_strength、thinking)、ワークツリー パス ノブ、意図的/スポーンコントラクトフィールドおよび待機/ステータス/割り込み 余分なものは宣伝されたスキーマから移動されました。削除されたフィールドはすべて残ります 解析で受け入れられ、変更されずに尊重されます (token_budget と同じ規約)。 保存されたトランスクリプト、ACP/MCP clients、およびフリート構成はそのまま再生されます。の #5426/#5435 の封じ込めクランプはそのままです。子の予算が解決されるようになりました 役割のデフォルト (60/120 ターン、1800 秒のウォールタイム、変更されていないクランプ) および 新しい [subagents] キー default_max_steps / default_wall_time_secs。 ツール カタログはセッション固定プロンプト プレフィックスの一部であるため、 (docs/CACHE.md)、アップグレードすると、セッションごとに 1 回 KV プレフィックスが再入力されます。

  • ドキュメント シェルと共有 Web コンポーネントは、ローカライズされたコピーを経由するようになりました。 タイプされた辞書の背表紙。これらは #5337 の 2 つの増分フェーズです。 完全なエピック (#5488、#5490) は完了していません。
