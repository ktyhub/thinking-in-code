新しいメソッド

ロードアド

@ppetrushkov は、#2678 で RoAd: 2D Rotary Adaptation を PEFT に追加しました。 RoAd は、要素ごとの乗算のみを使用して適用される 2D 回転行列を学習するため、マージされていない状態のアダプターで非常に高速な推論が約束されます。

注目すべきことに、LoRA 以外に、混合アダプター バッチ をサポートする PEFT メソッドは RoAd だけです。これは、複数の RoAd アダプターを含むモデルをロードした場合、それらすべてを同じバッチ内の異なるサンプルに使用できることを意味します。これは、バッチ間でアダプターを切り替えるよりもはるかに効率的です。

model = PeftModel.from_pretrained(base_model, <path-to-road-adapter-A>, adapter_name="adapter-A")
model.add_adapter("adapter-B", <path-to-road-adapter-B>)

inputs = ...  # input with 3 samples
# apply adapter A to sample 0, adapter B to sample 1, and use the base model for sample 2:
adapter_names = ["adapter-A", "adapter-B", "__base__"]
output_mixed = model(**inputs, adapter_names=adapter_names)
gen_mixed = model.generate(**inputs, adapter_names=adapter_names)

アロラ

Activated LoRA は、#2609 で @kgreenewald によって因果言語モデル用に追加された手法で、入力内の特定のトークン呼び出しシーケンスに応じて LoRA アダプターを選択的に有効にすることができます。これには、アダプターが応答の一部を生成するためにのみ使用され、その後は基本モデルが再び引き継ぐ場合に、推論中に KV キャッシュの大部分を再利用できるという大きな利点があります。

アローと GenKnowSub

@TheTahaaa は、#2644 でロードされた複数の LoRA 間の動的ルーティング アルゴリズムである Arrow のサポートだけでなく、Arrow に基づいて構築された技術である GenKnowSub にも貢献しました。この技術では、Arrow で利用可能な LoRA の「ライブラリ」が最初に一般知識アダプター (例: Wikipedia のサブセットでトレーニングされたもの) を差し引いて変更され、タスク固有のパフォーマンスが向上します。

ウェーブFT

@Bilican のおかげで、Wavelet Fine-Tuning (WaveFT) が #2560 の PEFT に追加されました。この方法は、残差行列のウェーブレット領域でスパース更新をトレーニングするため、特にパラメーター効率が高くなります。被写体の忠実度を維持しながら多様な出力を生成できるため、画像生成にとっては非常に興味深いものです。

デロラ

Decoupled Low-rank Adaptation (DeLoRA) は @mwbini によって #2780 に追加されました。この新しい PEFT メソッドは、学習されたアダプターの重みの角度と大きさを分離するという点で DoRA に似ています。ただし、DeLoRA は、発散をより効果的に防止することを約束する方法でこれを実装します。さらに、ノルムの上限を課すことにより、学習された重みの偏差を制限します。この上限は、delora_lambda パラメータで調整できます。

OSF

直交微調整 (OSF) は、@NikhilNayak-debug によって #2685 に追加されました。ターゲットの重み行列の高ランクの部分空間を凍結し、勾配の更新を低ランクの部分空間に投影することにより、OSF は継続的な学習タスクで優れたパフォーマンスを実現します。標準的な微調整プロセスではメモリを少し消費しますが、以前に学習したタスクのパフォーマンス低下が懸念されるタスクについては、ぜひチェックしてみる価値があります。

機能強化

テキスト生成ベンチマーク

#2525 では、@ved1beta が テキスト生成ベンチマーク を PEFT に追加しました。これは、さまざまな PEFT メソッドのテキスト生成に関するメトリクスを決定および比較するためのフレームワークです。ランタイムとメモリ使用量。現時点では、このベンチマークには、MetaMathQA ベンチマーク にあるものと同様の、実験的な設定と視覚化がまだ不足しています。これに興味がある場合は、お知らせいただくか、できればこのベンチマークに貢献していただくことをお勧めします。

統合のための信頼できるインターフェース

PEFT は、Transformers や Diffusers などの他のライブラリと統合されています。この統合を促進するために、PEFT は現在、該当する場合に使用する必要がある 安定した機能インターフェイス を提供しています。たとえば、モデルが PeftModel インスタンスでなくても、set_adapter 関数 を使用してモデル上の PEFT アダプターを切り替えることができます。私たちはこれらの関数の下位互換性を維持することに努めているため、他のライブラリをそれらの上に安全に構築できます。

重量縛りの扱い

一部の Transformers モデルでは、重みを固定することができます。これは、埋め込みと LM ヘッドに関して特に顕著です。現時点では、PEFT でこれがどのように処理されるかは明らかではありません。そこで、#2864 で意図された動作を説明するための問題を起草しました。これは私たちの目標を示していますが、まだすべてが実装されているわけではありません。

#2803 では、@romitjain が ensure_weight_tying 引数を LoraConfig に追加しました。この引数を True に設定すると、modules_to_save の対象となるモジュールの重み付けが強制されます。したがって、埋め込みと LM ヘッドが関連付けられている場合、それらは重みを共有することになります。これは、たとえば重みのマージを可能にするために重要です。したがって、ほとんどのユーザーにとって、埋め込みと LM ヘッドを完全に微調整したい場合は、この設定を有効にすることをお勧めします。ただし、下位互換性のため、この設定はデフォルトではオフになっています。

#2864 に従って、将来的には ensure_weight_tying=True の機能が拡張され、トレーニング可能なトークン (#2870) と LoRA (未定) も含まれるようになります。

LoHa および LoKr で Conv1d および 1x1 Conv2 レイヤーをサポート

@grewalsk は、#2515 で、nn.Conv1d レイヤーと 1x1 カーネルの nn.Conv2d をサポートするように LoHa と LoKr を拡張しました。

新しいプロンプトチューニングの初期化

@macmacmacmac のおかげで、プロンプト チューニング、ランダムな離散初期化のための新しい初期化オプションが追加されました (#2815)。 PEFT メソッド比較スイート で実証されているように、このオプションは通常、ランダムな初期化よりもうまく機能するはずです。プロンプトチューニングを使用している場合は、試してみてください。

LoRA アダプターと負の重みの組み合わせ

複数の LoRA アダプターを使用する場合は、model.add_weighted_adapter を使用してそれらを 1 つのアダプターにマージできます。ただし、これまでのところ、これはアダプターごとに正の重みが付いている場合にのみ機能します。 @sambhavnoobcoder と @valteu のおかげで、負の重みも渡すことができるようになりました。

変更点

トランスフォーマーの互換性

この記事の執筆時点では、Transformers v5 のリリースが迫っています。このトランスフォーマーのバージョンは、PEFT < 0.18.0 と互換性がありません。 Transformers v5 を PEFT とともに使用する予定がある場合は、PEFT を 0.18.0+ にアップグレードしてください。

Pythonバージョン

この PEFT バージョンでは、サポートが終了した Python 3.9 はサポートされなくなりました。 Python 3.10+をご使用ください。

OFT の更新

OFT メソッド が更新され、わずかに高速化され、#2805 の数値が安定しました。ただし、これは、PEFT 0.18.0 にアップグレードした後、既存のチェックポイントではわずかに異なる結果が得られる可能性があることを意味します。したがって、OFT を使用する場合は、アダプターを再トレーニングすることをお勧めします。
