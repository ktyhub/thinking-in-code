peft v0.19.0

マイナー 公開日2026年4月14日 出典huggingface/peft 英語原文

#ペフトv0.19.0

ハイライト

この PEFT リリースには、以下に説明する 9 つ以上の新しい PEFT メソッドが含まれています。また、多くのユーザーにとって PEFT をさらに便利にする多数の機能拡張も含まれています。

新しいメソッド

グラロラ

@yeonjoon-jung01 が 「GraLoRA: パラメーター効率の高い微調整のためのきめ細かな低ランク適応」 を PEFT (#2851) に追加しました。この方法では、基本重みをより小さなブロックに分割し、それらに LoRA を適用します。このよりきめ細かい適応により、特に上位ランク (64+) で表現力が向上し、パフォーマンスが向上し、完全な微調整までのギャップが縮まることが期待されます。

BD-LoRA

@Conzel は BD-LoRA に寄稿しました: "Block-Diagonal LoRA for Elimination Communication Overhead in Tensor Parallel LoRA Serving" (#2895)。 BD-LoRA では、LoRA の重みはブロック対角の方法で実装されます。これにより、テンソル並列処理 (TP) を使用する際の通信オーバーヘッドが削減され、より高速な処理が可能になります。

vLLM には BD-LoRA サポートの実験ブランチがあります: vllm-project/vllm#28136。

カートリッジ

@kashif のおかげで、PEFT は カートリッジ (#2953) もサポートするようになりました。このメソッドの主な目的は、長いコンテキストを短いサイズに圧縮するようにプレフィックスをトレーニングし、トークンを節約することです。低いレベルでは、これは プレフィックス チューニング に似ています。 PR は、すぐに始められるように レシピ例 も追加しました。

PVeRA

"PVeRA: Probabilistic Vector-Based Random Matrix Adaptation" は、#2952 で @leofillioux によって PEFT に追加されました。これは VeRA の拡張であり、レイヤ間での重み共有を使用して特にパラメータ効率を高める PEFT 手法です。 PVeRA は、確率的要素を追加し、共有パラメータからサンプリングして、全体的なパフォーマンスの向上を約束することで、その上に構築されます。

PSソフト

@fei407 は #3037 で PSOFT、「主部分空間適応による効率的な直交微調整」 を PEFT に追加しました。 OFT や BOFT などの直交微調整テクニックは、基礎となる基本モデルの構造と機能を維持するのに適しています。 PSOFT は、低ランクの主部分空間への適応を制限することで、この手法の効率を向上させます。

リリー

@yibozhong は #2563 で Lily: "Low-Rank Interconnected Adaptation across Layers" を PEFT に追加しました。 Lily は表面的には LoRA に似ていますが、高度なパラメータ共有スキームを備えています。 A パラメータはブロックごとに共有されます (たとえば、4 つの連続する q_proj レイヤーが同じ A を共有します)。グローバルに共有される B パラメータのプールがあり、実際の B はルーターを通じてデータに依存した方法で選択されます。これにより、リリーはトレーニング可能なパラメーター数を低く抑えながら、LoRA よりも高いランクを使用できるようになります。

ピーナッツ

#3084 では、"PEANuT: Parameter-Efficient Adaptation with Weight-aware Neural Tweakers" が、やはり @yibozhong によって PEFT に追加されました。 PEANuT は、基本モデルに小さなニューラル ネットワーク (いわゆる重み認識ニューラル ツイーカー) を追加します。 LoRA と比較して、これにより、同じトレーニング可能なパラメータ数の表現力が向上するか、表現力を犠牲にすることなくパラメータ数を大幅に減らすことができます。これには、同じパラメータ数に対するメモリ要件の増加と速度の低下という代償が伴います。

タイニーロラ

@kashif にも別の連載寄稿者がいます。彼は #3024 の TinyLoRA: "Learning to Reason in 13 Parameters" にも寄稿しました。これは、LoRA ランク 1 でさえ達成できるものよりもはるかに少ない、非常に少数のパラメーターをトレーニングできる PEFT 手法です。この論文では、特に強化学習では、多くの場合、良い結果を達成するためにわずか数パラメーターをトレーニングするだけで十分であることが示されています。

アダMSS

@LonglongaaaGo は 「AdaMSS: パラメーター効率の高い微調整のための適応型マルチサブスペース アプローチ」 を PEFT に追加しました。この方法では、モデルの基本重みを微調整の対象となる小さな部分空間に分割します。さらに、AdaLoRA が行うのと同様に、トレーニング中に重要度の低い部分空間に低いパラメータ バジェットを動的に割り当てることができます。これにより、同様の PEFT 手法よりも高い表現力と優れた一般化が期待できます。

機能強化

非 LoRA アダプターを LoRA に変換する

#2939 では、[多くの非 LoRA メソッドのチェックポイントを LoRA チェックポイントに変換] (https://huggingface.co/docs/peft/main/en/package_reference/lora_conversion) できるようにする機能を PEFT に追加しました。他の多くのパッケージは LoRA のみをサポートし、他の PEFT メソッドはサポートしないため、これは便利です。 【ディフューザー】(https://huggingface.co/docs/diffusers/v0.37.1/en/api/loaders/lora)と【vLLM】(https://docs.vllm.ai/en/latest/features/lora/)。新しい変換ツールを使用すると、LoRA だけでなく、より多くの PEFT メソッドをこれらのパッケージで使用できるようになります。変換には損失が伴いますが、LoRA ランクが十分に高い場合、誤差はかなり低くなり得ることが経験的テストで示されました。

LoRA-GA

@sambhavnoobcoder は、"LoRA-GA: 勾配近似による低ランク適応" (#2926) を使用して LoRA の重みを初期化する新しい方法を追加しました。これにより、完全な微調整で勾配を揃える方法で LoRA 重みを初期化できるようになり、トレーニングの収束が高速化されるはずです。

侵入者の寸法を縮小する

"LoRA vs Full Fine-tuning: An Illusion of Equivalence" で、著者らは、LoRA の微調整によって、忘却の一因となるいわゆる「侵入者次元」が導入される可能性があることを示しました。 PEFT、reduce_intruder_dimension に 侵入者次元を削除するユーティリティ関数 が追加されました。微調整された LoRA モデルでこれを呼び出すと、微調整されたタスクのパフォーマンスはほぼ同じままでありながら、忘れが減少するはずです。

変圧器エンジン

#3048 で、@balvisio は、NVIDIA の量子化方式である Transformer Engine のサポートを PEFT に追加しました。

Tensor 並列サポート

一連の PR (#3079、#3091、#3096) で、@michaelbenayoun は Tensor Parallelism のサポートを LoRA に追加しました。

ウェイトタイイングの改善

多くの LLM では、パラメータ数を節約するために、埋め込みと LM ヘッドの重みが関連付けられています。ただし、これらのレイヤーを微調整しようとすると、難しい状況が発生する可能性があります。一連の PR (#2803、#2922、#2870、#2879、#3126) を通じて、その際のユーザー エクスペリエンスが向上しました。最も注目すべき点は、ユーザーが ensure_weight_tying=True を PEFT 構成に渡して、重み付けの維持を強制できるようになりました。ウェイト タイイングの現在の処理方法については、PEFT ウェイト タイイング ドキュメント を確認してください。 @romitjain、@sambhavnoobcoder、@Cursx の貢献に感謝します。

低精度フローティングタイプ対応

#3055 により、LoRA は torch.float8_e4m3fn のような非常に低精度の浮動小数点数を使用する基本モデルで動作します。その一例が MiniMax-M2.5 です。

PrefixTuning のゼロ初期化

#3128 では、プレフィックス チューニングにゼロ初期化が導入されており、ベンチマークによると、結果のばらつきが大幅に減少し、迅速なエンジニアリングを必要とせずに良好なタスク精度が得られました。

LoftQ + int8 量子化

#3088 では、LoftQ 実装は、既存の nf4 量子化と並行してアクティベーションしきい値を利用することなく、int8 量子化のエラー修正をサポートするようになりました。

変更点

骨の除去

Bone PEFT メソッドは #3115 で削除されました。ユーザーは代わりに、Bone の改良された代替品である MiSS を使用するように指示されます。古い Bone チェックポイントを移植する場合は、この Bone-to-MiSS 変換スクリプト を使用してください。

AutoGPTQ と AutoAWQ

@ZX-ModelCloud のおかげで、これら 2 つの量子化メソッドはバックエンド (#2932) として GPTQModel を使用するようになりました。

modules_to_save における requires_grad の扱い

以前は、対応する modules_to_save が無効になっている場合、PEFT は元のモジュールで requires_grad を有効にしていました。これはほとんど望ましいことではないため、修正されました。この変更は技術的には下位互換性がありませんが、非常に特殊なケースであるため、ユーザーが悪影響を受けることはないと考えられます。
