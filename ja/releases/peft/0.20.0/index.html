#ペフトv0.20.0

ハイライト

<img width="1250" height="560" alt="peft-v0 20 0" src="https://github.com/user-attachments/assets/6194fae9-f3c3-48ca-b43b-40c774bfe6eb" />

このリリースでは、9 つ以上の新しい PEFT メソッドが追加され、メソッド比較スイートの新しい画像生成ベンチマークの追加やドキュメント構造の大幅な改善など、周囲のインフラストラクチャに多大な労力が費やされています。

新しいメソッド

ヒラ

@hqsiswiliam は "HiRA: 大規模言語モデルのためのパラメーター効率的なアダマール高ランク適応" を PEFT (#2668) に追加しました。 HiRA は、低ランクの積 BA を基本重みに加算する代わりに、固定された基本重みを要素ごとに乗算します (アダマール積)。基本重み自体はフルランクであるため、結果として得られる更新は低ランクに制約されなくなりますが、トレーニング可能なパラメータ数は LoRA と同じままです。

グロラ

@not-lain は #3098 で GLoRA: "One-for-All: Generalized LoRA for Parameter-Efficient Fine-Tuning" を寄稿しました。これは、構成可能な重み、アクティベーション、バイアス適応によって LoRA を拡張する柔軟な PEFT 手法であり、追加の推論コストなしでより豊富な微調整を実現します。レイヤーごとの柔軟性や、バニラ LoRA よりも強力な適応が必要な場合に使用してください。非線形レイヤー (例: Conv/Embedding) の場合、または標準 LoRA ですでに十分であり、シンプルさが重要な場合はスキップしてください。

有利

@whubaichuan が #3195 に 「BEFT: 言語モデルのバイアス効率的な微調整」 を追加しました。 BEFT は、バイアス項を微調整するだけでもデータが少ない状況では競争力があるという観察に基づいていますが、さらに進んで、「すべて」のバイアスをトレーニングするのではなく、デフォルトで値の予測をターゲットにします。これは、著者らがこれが最も効率的であると判断したためです。これにより、トレーニング可能なパラメーターの数が全パラメーターのおよそ 0.01% まで減少します。

モンテクロラ

@victor7246 は #2943 で MonteCLoRA、「低ランク適応のベイジアン再パラメータ化による LLM の堅牢かつ効率的な微調整」 を統合しました。 LoRA は、学習率やバッチ サイズなどのハイパーパラメータの影響を受けやすいことが知られています。この新しい LoRA バリアントは、モンテカルロ推定を使用して低分散の事後推定を取得し、低ランクのパラメーターを点推定ではなく分布として扱うことでこの問題に対処します。これにより、パラメータが O(rank) 追加されるだけで、トレーニングが著しく堅牢になるはずです。

ヴェロラ

@roymiles が #3159 に VeLoRA: 「ランク 1 サブトークン投影を使用したメモリ効率の高いトレーニング」 を追加しました。ほとんどの PEFT メソッドとは異なり、この LoRA バリアントはパラメーター数ではなくアクティベーション メモリをターゲットとしています。中間アクティベーションはサブトークンに分割され、固定ランク 1 プロジェクションで圧縮されてから、バックワード パス用にキャッシュされ、バックプロパゲーション中に再構築されます。概念的には、これは勾配チェックポイントに似ており、メモリの節約量は少なくなりますが、実行速度は速くなります。

ユニロラ

@KaiyangLi1992 は、#3257 に Uni-LoRA: "One Vector is All You Need" を寄稿しました。この論文は、VeRA や VB-LoRA のようなパラメータ効率の高い LoRA バリアントはすべて、完全な LoRA パラメータ空間をはるかに小さな部分空間に投影するものとして説明でき、異なる点は投影の選択のみであることを示しています。 Uni-LoRA は、レイヤーごとの投影ではなく、モデル全体に​​わたって単一のグローバル投影を使用します。これにより、レイヤー間のパラメーター共有が可能になり、パラメーター数が非常に少なくなります。

FRoD

@Bane-Elvin は #3270 に FRoD、"高速収束のための回転角度を使用したフルランクの効率的な微調整" を追加しました。 LoRA のような低ランク デルタを追加する代わりに、共有回転部分空間とスパースなトレーニング可能な係数を使用して、選択された重みを再構築します。これは、高速収束とより高いフルランク容量上限が重要な場合に特に役立ち、その大きな疎な回転部分空間もモデルのマージに有望である可能性があります。主なトレードオフは、コストのかかる結合分解の初期化と、LoRA よりもわずかに遅い前方/後方パスであるため、1 回限りの単一タスクの微調整にはあまり魅力的ではない可能性があります。

ミカ

@sr-networks は #3260 に MiCA、「MiCA Learns More Knowledge Than LoRA and Full Fine-Tuning」 を寄稿しました。 MiCA は、基本重みの SVD から B を初期化し、最小 特異値に属する左特異ベクトルを取得してから、A のみをトレーニングする LoRA バリアントです。この考えは、これらのあまり活用されていない方向を適応させることで、既存の機能への干渉を少なくしながら、支配的な部分空間を適応させるよりも効果的に新しい知識を統合できるというものです。

器用

@MAXNORM8650 は #3342 に DEFT、「テキストから画像へのモデルの分解効率的な微調整」 を追加しました。この PEFT メソッドは、重みの更新を 2 つの学習された低ランク部分に分割します。1 つは固定された重みの部分空間を削除する投影で、もう 1 つはその場所に新しいコンテンツを挿入する低ランクの更新です。 DEFT を使用すると、忘れを最小限に抑えながら基本モデルの指示に従って/編集できる状態を維持しながら、いくつかの画像からテキストから画像へのモデルをパーソナライズできます。基本モデルの他の機能を保持する必要がない場合 (単純な追加アダプターの方が単純です)、または Linear/Conv1D を超えるレイヤーの場合は、あまり適合しません。 DEFTの特殊なケースとしてPaRa方式もサポートされています。

機能強化

LoRA ターゲットの自動選択

@oswaldoludwig は、「ニューラル ユニットにおける情報エンコーディングのためのスケール不変プロキシとしての条件番号」 に基づいて #3106 に KappaTuneSelector を追加しました。 PR には、基本重み行列の条件番号に基づいてどのモジュールをターゲットにするのが最適かを自動的に識別する新しい関数 find_kappa_target_modules が追加されています。これにより、LoRA または他の PEFT メソッドを構成するときに、target_modules を選択する際の推測の一部が排除されます。

より広範な量子化のサポート

#3117 は BOFT、MiSS、および VeRA に汎用量子化サポートを追加し、#3321 は SHiRA に対して同じことを行います。以前は、量子化サポートはメソッドごと、バックエンドごとに実装する必要がありました。より多くのメソッドが、すぐに共通の量子化バックエンドで動作するようになりました。結果として、VeRA は以前のビットサンドバイト量子化バックエンドの代わりに汎用量子化バックエンドを使用するようになったことに注意してください。それが原因で問題が発生した場合は、お知らせください。

target_parameters を備えた複数のアダプター

nn.Parameter を直接ターゲットにできる target_parameters (エキスパートを 1 つのパラメーターに詰め込む MoE モデルに便利) は、複数のアダプターの追加とロードをサポートするようになりました (#3350)。

Conv2d 用 AdaLoRA

@Anai-Guo が #3196 で SVDConv2d を追加したため、AdaLoRA は torch.nn.Conv2d 層をターゲットにできるようになりました。

ドキュメントの再構成

PEFT ドキュメント は #3300 と #3325 で再編成され、PEFT が非常に多くのメソッドをサポートしているため、ナビゲートが大幅に容易になりました。各 PEFT 手法では、PEFT ベンチマークでのパフォーマンスの概要も提供されます。また、このリリースでは、多くの貢献者によるドキュメントの改善がロングテールで行われています。これは、これらに取り組んだすべての人のおかげです。

変更点

AutoGPTQ の非推奨

以前のリリースでバックエンドとして GPT-QModel に切り替えられたことに続き、@Qubitium のおかげで AutoGPTQ は正式に非推奨になりました (#3190)。

ベンチマーク

画像生成ベンチマーク

メソッド比較スイートには、イメージ生成ベンチマーク (#3082) が追加されました。これは既存の MetaMathQA ベンチマークを補完し、まったく異なるタスクで PEFT メソッドを比較できるようになります。これにより、さまざまな PEFT メソッドの機能をより完全に把握できます。結果を確認するには、Gradio Space にアクセスし、左上のタスク「image-gen」を選択します。

メタマスQA

前回のリリース以降、MetaMathQA ベンチマーク にもいくつかの改善を加えました。更新結果はGradio Spaceでご確認ください。コミュニティの協力により、私たちはさらに幅広い実験をカバーできるようになりました。さらに、忘却メトリクスのバグも発見しました。新しい数値は、微調整によって基本モデルの元の知識がどの程度保持されているかを正確に反映するようになりました。

PEFT ショップ

#3317 は、パフォーマンスだけでなく機能 (量子化がサポートされているかどうかなど) に関して、さまざまな PEFT メソッドを非常に簡単に比較できるようにすることを目的として、新しい Gradio Space を追加します。このスペースにアクセスして、どの PEFT 手法があなたのユースケースに最適であるかを確認してください。
