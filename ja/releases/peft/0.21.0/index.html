新しいメソッド

リーマン前提条件付き LoRA オプティマイザー

@smellslikeml によって提供されたリーマン前処理 LoRA オプティマイザー (#3382) は、LoRA-FA や LoRA+ に似た新しい LoRA 固有のオプティマイザーで、勾配にリーマン前処理を適用して特徴学習を改善し、LoRA の A 行列と B 行列の学習率の個別の調整を回避します。

LoRA の亜種: 知識認識特異値適応 (KaSA)

KaSA は、基本重みから知識認識特異値を特定することを目的としています。次に、それらの重みからノイズの多い知識を削除し、タスクに最も関連する特異値を具体的にトレーニングします。 #3446 で @robbiebusinessacc と @iambogeumkim によって実装されました。

スーパーチューニング (#3518)

スーパーチューニング は、キャリブレーション不要の振幅スコアリングを使用して、まばらなチューニング予算を割り当てます。 BottomK を選択すると、Super は、大きな規模の事前トレーニング済み重みをそのままにしつつ、新しいタスクを学習するための自由度を提供するという考えに基づいて、低規模の重みを適応させます。 Supra は、このまばらなアップデートに加えて LoRA を追加します。これは、特に推論が必要な微調整タスクで、より高いランクの適応と並行してスパース性を探索するのに適しています。 @smellslikeml に感謝します。

ShadowPEFT (#3354)

ShadowPEFT は、凍結された基本モデルと並行して小さなシャドウ ネットワークを実行します。 そのシャドウ状態はすべてのデコーダ層で更新されるため、適応は対象となる各線形層 (LoRA など) で個別に低ランクの更新を行うのではなく、スタック全体で共有されます。これは、ダウンストリームまたは OOD のパフォーマンスを重視し、LoRA と同じトレーニング可能なパラメータ範囲に留まりたい場合、またはエッジ上の小さな影とクラウド内のフリーズしたベースが必要な場合に適しています。これは、シャドウ モデルが事前トレーニングされた小さなモデルから始まる場合に最も効果的です。 @SeanLee97 による寄稿。

機能強化

  • MoE ターゲット パラメーターの計算を高速化 (#3577): 1 つのアクティブなアダプターの一般的な使用例では、重みと MoE LoRA デルタの計算が 1 つの baddbmm 操作に組み込まれます。この場合、わずかな数値の違いが予想されます。

  • 新しい Int8Tensor、Float8Tensor などのテンソル サブクラスをサポートすることで、torchao v0.18.0 をサポートします。

  • 直交部分空間微調整 は #3524 で大幅な更新を受け、MetaMathQA ベンチマークに従ってメモリ フットプリントを 22% 削減し、トレーニング時間を 46% 削減しながら、タスクの精度と忘却の安定性を維持しました。特に fp16、bf16 では、若干の数値の違いが予想されます。

  • https://github.com/huggingface/peft/pull/3639: @amogh-nagri-11 のおかげで、プロンプト学習メソッドでアダプターを削除できるようになりました。適応プロンプトについては、他の PEFT メソッドがこれを処理する方法と同様に、2 番目のアダプターを追加またはロードしても自動的にアクティブ化されなくなりました。

変更点

リファクタリングされた状態辞書処理 (#3490)

内部変更により、状態辞書のロード/保存メソッド固有のコード パスがそれぞれのチューナーに移動されました。これはエンドユーザーにとって透過的である必要があり、広範囲にテストされており、以前とまったく同じように動作するはずですが、モデルの動作が異なると思われる場合は、お知らせください。

注入中のアダプターのトレーニング可能性の維持 (#3495)

以前は、2 番目、3 番目などのアダプターをロードまたは追加すると、is_trainable の値に応じて、既存のアダプター (または基本モデル) の requires_grad に影響を与える可能性がありました。 @DaoyuanLi2816 のおかげで、このようなことはもう起こらないはずです。

LoRA アダプター結合のバグ修正 (#3111)

add_weighted_adapter を使用して LoRA アダプターを結合すると、SVD パスにバグがあり、LoRA スケーリングが 2 回適用されてしまいました。これは修正されました。

OFT は汎用量子化バックエンドを使用します (#3355)

OFT をメソッド固有の量子化バックエンドから汎用量子化バックエンドに移行しました。これは、bitsandbytes、GPT-Q などに影響します。既存のチェックポイントには影響しませんが、問題が発生した場合はお知らせください。

アダプターの取り扱いに関するチェックを厳格化

  • #3667: inject_adapter_in_model は、親モデル (VeRA など) に存在する共有状態を持つ PEFT メソッドを、そのような親モデルが存在しないため拒否するようになりました。 @CoralGarden52 からの寄稿。

  • #3534: @LK-maker-007 のおかげで、PEFT は、存在しないレイヤーをターゲットとする add_adapter を使用して 2 番目のアダプターを PEFT モデルに追加するときにエラーをスローするようになりました。以前は、アダプターは何も適応せず、それについて沈黙していました。 peft_model.targeted_module_names と peft_model.targeted_parameter_names には重複が含まれなくなりました。これらは引き続き (セットではなく) 挿入順で並べ替えられます。潜在的なエラーを抑制するには、peft.PeftError をキャッチします。

  • #3504: アダプターを削除するときに、アダプターがマージされているかどうかをチェックするようになりました。マージされている場合、削除してもその効果は除去されないため、エラーが発生します。これは @DaoyuanLi2816 によって寄稿されました。
