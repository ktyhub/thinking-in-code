#ペーパーclip v2026.722.0

#ペーパーclip v2026.722.0

リリース日: 2026-07-22

ハイライト

  • 実行バインドされたエージェント シークレット アクセス — エージェントは、アンビエント環境の挿入のみに依存するのではなく、実行バインド API を通じてオンデマンドで付与されたシークレットを取得できるようになりました。新しい access.* 配信モードは API のみのシークレットを公開し、GET /api/agents/me/secrets はエージェントに付与されたエイリアスのみをリストし、POST /api/agents/me/secrets/:key/value は Cache-Control: no-store を含む値を返します。読み取られたすべての値はセキュリティ監査証跡とオペレーター アクティビティ ログの両方に書き込まれ、低 trust レビュー/スキルテスト トークンは拒否されたままになります。また、新しい シークレット アクセス エディターを使用すると、エージェント設定からエージェントごとの許可を管理できます。 (#9921)
  • ローカル エージェントは Windows 上で実行されます - 組み込み ACPX エンジンは、生成された Bash スクリプトでローカル エージェント コマンドをラップしなくなりました。そのため、Claude、Codex、Gemini、およびカスタム ACP アダプターは、Linux だけでなく Windows でもネイティブに生成されるようになりました。環境変数は ACPX セッション オプションを通じて挿入され、子の標準エラー出力はプロセス内でキャプチャされ、Windows では .cmd npm/pnpm シムが優先され、シンボリックリンク EPERM の失敗はコピーにフォールバックされます。実際の Node ACP スポーン スモークは、Ubuntu と Windows の両方で実行されるようになりました。 (#9980)

改善点

  • ユーザー名付きの PAPERCLIP_* バインディングがエージェントに届くようになりました — ハートビートは以前、解決前に すべての PAPERCLIP_ 接頭辞が付いた環境バインディングを削除したため、意図的に PAPERCLIP_CLOUD_PROD_PROVIDER_RAILWAY_TOKEN などの名前を付けたシークレットはサイレントに削除されました。これで、PAPERCLIP_API_KEY のみが明確に拒否され、ハーネスに割り当てられたランタイム変数が常に優先され、他のすべての PAPERCLIP_* バインディングが実行環境に渡されます。 (#9974)
  • より堅牢なテレメトリ client — テレメトリ client はワイヤ コントラクトと一致するようになりました。ペイロードはチャンク化され、バッチ ID は決定的で、再試行はバックオフでバッチ化され、ローカル ストアは制限されています。サイレント ドロップ ベースラインが固定され、キャップ/バックオフが構成可能なサーフェスになりました。テレメトリは匿名化されたままであり、DO_NOT_TRACK=1 または PAPERCLIP_TELEMETRY_DISABLED=1 で無効にできます。 (#9946、#9906、@nickyleach)
  • スラッシュ名の付いたシークレットはフォルダーとして参照 — 名前にスラッシュが含まれるシークレットは、UI 内でネストされたフォルダーとしてナビゲートされるようになりました。 (#9913)
  • シークレット アクセス用の検索可能なエージェント ピッカー — エージェントごとのシークレット アクセスの付与では、長いフラット リストの代わりに検索可能なエージェント ピッカーが使用されるようになりました。 (#9918)
  • よりクリーンな外部オブジェクト ラベルとスター コントロール — 外部オブジェクト ラベルとその隣にあるスター コントロールが簡素化され、視覚的なノイズが軽減されました。 (#9929)
  • より安全なサンドボックス CODEX_HOME 同期 - codex-local アダプターは、CODEX_HOME をサンドボックスに同期するときに、ホーム ディレクトリ全体をコピーするのではなく、明示的な許可リストを作成するようになりました。 (#9972、@nickyleach)

実験的

これらの機能は実験的設定の背後でゲートされて出荷されるため、実験的設定でアプリを試せるようになります。

  • Connections v3 基盤 — one-click Connected Apps の基礎が完成しました。v3 スキーマ コアは、安定した企業スコープの接続 UID、明示的な所有権/認証/トランスポート フィールド、サブジェクトを認識した connection_grants テーブル、およびマルチキー資格情報 (従来の remote_http トランスポートは mcp_remote に名前変更されました) を追加します。それに加えて、生成された AppDefinition Wave 1 カタログにより、単一の型付きコントラクトの参照とセットアップが可能になり、ランタイム層により、サブジェクトを認識した承認状態、スコープ指定されたキーの処理、および未知のスコープに対してフェールクローズされる OpenAPI に登録された許可ルートが追加されます。 (#9958、#9981、#9982)

修正

  • アーカイブされた受信箱アイテムはアーカイブされたままになります — アーカイブしたアイテムは受信箱に再表示されなくなります。 (#9931)
  • 実行ポリシーの最終承認が正常に終了 — 実行ポリシーの最終ステージを承認すると、ステージ 1 に巻き戻されるのではなく、ポリシーが終了するようになりました。 (#7936、@HKTITAN)
  • Office 問題の添付ファイルを受け入れる — Office ドキュメントの添付ファイル (Word、Excel、PowerPoint) が問題で受け入れられるようになりました。 (#8562、@samrusani)
  • サーバー ログから HTTP Cookie を編集 — Cookie ヘッダーがサーバー ログから編集されるようになったので、セッションの内容がログ出力に漏れることはありません。 (#7977、@nosolosoft)
  • 実行作成されたコメントから 500 秒が発生しない — createdByRunId はコメント挿入時にサニタイズされ、500 クラスのエラーが修正されます。 (#9489、@digitalflanker-ux)
  • 問題リリース時にターミナルステータスを保持 — 問題をリリースしても、ターミナル (完了/キャンセル) ステータスが破壊されなくなりました。 (#7524、@harshkotak)
  • 無効な設定ファイルで大声で失敗する — 無効な設定ファイルは、黙って無視されるのではなく、明確なエラーが表示されるようになりました。 (#9041、@lessbass)
  • clickable ではない承認保留中のガイダンス — 招待画面の承認保留中の管理者ガイダンスは、誤解を招く clickable 要素ではなくなりました。 (#6786、@le-czs)
  • Cron の有効性が radix-ui 1.6.4 で解決される — Cron の有効性の処理と分岐の解決テストが radix-ui 1.6.4 に対して同期されました。 (#9966、@nickyleach)
  • CLI インポート選択の修正 - インポート選択をクリアしても拡張ファイルがドロップされなくなり、欠落している会社マニフェスト フィールドがインポート選択テスト フィクスチャに追加されました。 (#2379、@kevinmanase、#9978、@aaymeloglu)
  • クラウド管理インスタンスがヘルス ゲートを通過 — クラウド管理インスタンスはヘルス ゲートでブートストラップされているものとして扱われるようになったため、起動時に停止することはありません。 (#9912)

アップグレード ガイド

  • このリリースでは、Connections v3 基盤 (0182_connections_v3_schema_core、0183_connection_user_authorization_state) に 2 つの追加データベース移行が追加されており、安定した接続 UID をバックフィルし、デフォルトのワークスペース許可を作成し、remote_http トランスポートの名前を mcp_remote に変更します。移行は起動時に自動的に実行されます。手動での操作は必要ありません。
  • 以前にアダプター/構成環境で静的 PAPERCLIP_API_KEY を設定して実行トークンをオーバーライドした場合、そのオーバーライドは適用されなくなります。ハーネスによって作成された実行トークンが、実行 API キーの唯一のソースになります。他のすべての PAPERCLIP_* という名前のバインディングは、期待どおりに実行環境に送られるようになりました。
  • 接続/アプリは実験設定の背後でゲートされたままです。 Connections v3 サーフェスを試すには、実験的な設定で アプリ を有効にしてください。
