#ペーパーclip v2026.626.0

#ペーパーclip v2026.626.0

リリース日: 2026-06-26

このリリースでは、17 人の寄稿者から 122 件のコミットが行われました。

ハイライト

  • Hermes、現在組み込まれています (ローカルおよびリモート ゲートウェイ) - Hermes は、このリリースのファーストクラスのアダプターです。自分のマシンで実行する hermes_local エージェント、またはゲートウェイを介して リモートで Hermes を実行する hermes_gateway エージェントを雇います。手動でのプラグインのインストールは必要なく、ゲートウェイ URL と API キーの安全なオンボーディング デフォルトが使用されます。外部の Herme パッケージは、アダプター マネージャーを通じて組み込みをオーバーライドまたはシャドウすることができます。 (#8543、@cryppadotta)
  • タスク ウォッチドッグ - ファーストクラスのウォッチドッグ コントロール プレーンを使用すると、自動チェックをタスクにアタッチし、Paperclip にそれを監視させることができます。これにより、長時間実行されるエージェントの世話をするのではなく、ウォッチドッグの状態、結果、未処理の作業を問題スレッド内で直接明らかにすることができます。 (#8339、@cryppadotta)
  • 質問作業モード - 質疑応答タスクの「質問」作業モードで問題を実行できるようになりました。そのため、完全な実行ワークフローを開始することなく、エージェントに質問を指示して回答を得ることができます。 (#8334、@cryppadotta)
  • サンドボックス ランタイムのステータス、スレッド内でライブ - 一時的なサンドボックス ランタイムはステータスを問題のスレッドで直接報告するようになり、Daytona サンドボックス リースは実行全体で再利用されるため、クラウド/サンドボックスでの実行がより可視化され、起動も速くなります。 (#8594、#8593、@devinfoley; #8513、@devinfoley)
  • ワークスペース ファイルのダウンロードと外部オブジェクト参照 - Paperclip から作業成果物を取得します。エージェントが作成したファイルをワークスペースから直接ダウンロードし、問題の表面全体で外部オブジェクト (リンク、アセット) を参照することで、タスクに適切なコンテキストが伝わるようにします。 (#8512、#8229、@cryppadotta)

改善点

  • リフレッシュされたオンボーディング - オンボーディング フローが見直され、UI スタイルのバッチ修正とともに古いクラシック ウィザードが廃止されました。そのため、新しいインスタンスのセットアップがよりわかりやすくなり、デフォルトのタスク UI (作業モードのラベル、ステータスの色、チーム作成のコピー) はそのまま使用しても一貫しています。 (#8628、@cryppadotta)
  • タスク ステータスのアイコンと色 - タスク ステータスが、全体および問題リスト全体の専用のアイコンと色で一目でわかるようになりました。 (#8580、@scottong; #8376、@tonio-alucema)
  • ルーチンの日付変数 - ルーチンは日付変数の制御を取得するため、定期的なルーチンはプロンプトを毎回手動で編集することなく、実行日をパラメータ化できます。 (#8655、@cryppadotta)
  • スキル カテゴリの編集 - 設定でスキル カテゴリを編集できるようになり、インストールされているスキル カタログを整理しやすくなりました。 (#8615、@cryppadotta)
  • Paperclip ページとカプセルの公開 - バンドルされたページ公開スキルを使用すると、エージェントは静的 HTML ページとアセット フォルダーを承認されたホストに公開できます。また、バンドルされたカプセル スキルには、Paperclip カプセル識別ツールキットが同梱されます。 (#8664、#8669、@cryppadotta)
  • 制限されたワークスペースの概要 - ワークスペースの概要エンドポイントが制限されるようになり、大規模なワークスペースを持つインスタンスのペイロードとレイテンシーが大幅に削減されました。 (#8627、@cryppadotta)
  • デフォルトで合理化されたサイドバー - 合理化されたサイドバーがデフォルトのレイアウトになりました。 (#8496、@devinfoley)
  • ソートされたワークスペース ルーチン - ワークスペース ルーチンが名前でソートされるようになったので、ルーチン リストは予測可能なままになります。 (#8666、@cryppadotta)
  • プラグインのインストール ターゲット - CLI は、プラグインのインストール ターゲット ホストを表示し、plugin target コマンドを追加するため、プラグインがどのインスタンスにインストールされているかを常に知ることができます。 (#8575、@cryppadotta)
  • ワークスペース セレクターの検索の改善 - 再利用可能なワークスペース セレクターの検索が改善され、適切なワークスペースをより迅速に選択できるようになりました。 (#8597、@cryppadotta)
  • インスタンス スコープの実行環境 - 実行環境はインスタンス スコープになり、ダイアログを通じて編集できるようになり、[企業環境] 画面でよりクリーンなコピーと整然としたドライバー ドロップダウンが表示されます。 (#8375、#8391、#8400、#8398、#8329、@cryppadotta)
  • ハートビート プリフライトの予算上限 - ハートビートはプリフライトの予算上限を尊重するようになり、1 回のウェイクで費やせる金額に厳しい上限が設けられています。 (#8347、@levineam)
  • 権限によって制御されるスキルの突然変異 - スキルの作成/編集/削除は専用の skills:create 権限の背後で制御されるようになったため、権限の低いプリンシパルはスキルを変更することなく参照できます。 (#8616、@cryppadotta)
  • 監視可能なサンドボックス同期の進行状況 - アダプター ユーティリティがサンドボックス同期の進行状況を報告できるようになったため、サンドボックスへの長時間のファイル同期はブラック ボックスではなくなりました。 (#8395、@cryppadotta)
  • Codex ローカルはホスト ログインを継承します - codex_local エージェントはデフォルトでホスト Codex ログインを継承し、管理された認証を隔離されたホームにシードするため、再認証することなく動作します。 (#8425、#8403、@cryppadotta)
  • Codex ローカル非アクティブ モニター - codex_local アダプターは出力の非アクティブを監視し、ローカル エージェントに対してループバック ランタイム API URL を優先するようになり、長時間のローカル実行の信頼性が向上します。 (#5017、#5102、@neerazz)
  • クロード拒否信号 - claude_local アダプターは、stop_reason 拒否時に errorCode または claude_refusal を発行するため、拒否は第一級の結果として処理されます。 (#8314、@uky333)
  • Claude 4.5 モデル エイリアス - claude_local は、直接 4.5 モデル エイリアスを使用するようになりました。 (#3800、@LeonSGP43)
  • claude_local のエージェント ID ヘッダー - claude_local は、X-Anthropic-Agent-Id ヘッダーを介してエージェント ID をスタンプします。 (#8322、@zenprocess)
  • よりクリーンなエージェント構成と企業コピー - エージェント構成環境セレクターがよりクリーンになり、企業作成コピーが更新され、アダプターのテスト ボタンはテストのみを実行します (誤って保存することはありません)。 (#8504、#8653、#8405、@cryppadotta)
  • 安価なモデルのエージェント構成チェック - エージェント構成チェックは安価なモデルでテストされるようになったため、構成を検証してもプレミアム トークンは消費されません。 (#8632、@cryppadotta)

修正

  • モバイルの問題チャット - モバイルでの問題チャットの間隔、メンション警告の間隔、および小さな画面でのビューポートの水平スクロールを修正しました。 (#8493、#8486、#8370、@cryppadotta)
  • 戻る/進む時のスクロール位置 - メイン コンテンツ領域は、ブラウザーの戻る/進むナビゲーションでのスクロール位置を復元するようになりました。 (#8636、@devinfoley)
  • UI 詳細リグレッション - 一般的な URL リッチオブジェクト ラベルを含む、問題の詳細リグレッションとリッチオブジェクト リグレッションのバッチが修正されました。 (#8613、#8662、@cryppadotta)
  • シークレット参照バインディングの同期 - トップレベルのシークレット参照バインディングは同期を維持し、エージェントのシークレット バインディングはライフサイクル フロー全体で強制されるため、再割り当てまたは再実行されたエージェントは常に正しいシークレットを参照できます。 (#8630、#8307、@cryppadotta)
  • サンドボックスの復元と公開 - サンドボックスの復元インデックスのドリフト、サンドボックス git 公開、大規模なワークスペースのアップロード、およびサンドボックス同期からの一時的な Codex ホーム ディレクトリの除外を修正しました。 (#8595、#8422、#8581、@cryppadotta)
  • デイトナ ディスクとリソース - デイトナ サンドボックスはデフォルトで自動アーカイブされるため、ディスク クォータは残り、リソース オーバーライドはイメージベースのサンドボックスで機能し、環境設定フォームはサイズ プリセットを含む有効なメモリ入力を受け入れます。 (#8561、#8564、#8389、@cryppadotta)
  • よりスマートなリカバリ - 行き詰まった問題のリカバリは、レビュー保留の継続を依存関係の待機に変換し、ルーチンの親の問題を処理不足の引き継ぎから免除するため、エージェントが正当に待機している作業を強制的に削除されません。 (#8371、@cryppadotta; #8157、@BuyWhere)
  • キャンセルされた子ブロッカーは無視されました - アテンションの計算はキャンセルされた子ブロッカーを無視するようになりました。そのため、キャンセルされたサブタスクが親をスタックさせ続けることはなくなりました。 (#7577、@MrBlackTongue)
  • 問題の読み取り承認を発行 - 単一問題のコメントと問題スレッド リストでは読み取り承認が強制されるようになり、メンション付与されたクローズ済みの問題のコメントは再開の意図を尊重するようになりました。 (#8346、#8331、#8350、@nickyleach)
  • CEO 権限の強化 - 同一会社の CEO 権限は、会社間のアクセスに対して強化されます。 (#8276、@cryppadotta)
  • 分離されたリモート クロード構成 - リモート クロード構成はローカル認証情報から分離されているため、サンドボックス化されたクロードの実行ではホスト ログインを取得できません。 (#7676、@lennies)
  • ライブ イベントのソケットの強化 - ライブ イベントのアップグレード ソケットは、不正なアップグレードに対して強化されています。 (#8383、@cryppadotta)
  • Gemini のヘッドレス ストール - ヘッドレスな Gemini 呼び出しのストールを修正しました。 (#8368、@chekos)
  • カーソル ストリーミング テキスト - cursor アダプターは、ストリーミングされたアシスタント テキストをきれいな散文ブロックに結合します。 (#8544、@seb-veto)
  • OpenClaw ゲートウェイのルート パラメータ - OpenClaw ゲートウェイはルートの Paperclip パラメータを転送しなくなりました。 (#4416、@serenakeyitan)
  • エージェントの作成と雇用 UI - エージェント作成時の空白ページを修正し、詳細ページから承認または終了するときに受信トレイの雇用承認がクリアされるようになりました。 (#8336、#8340、@cryppadotta)
  • ルーチン スケジュール エディタ - 中断実行ラベルを含め、ルーチン スケジュール エディタが安定しました。 (#8333、@cryppadotta)
  • HTTP 経由でボタンをコピー - 問題のコピー ボタンは、プレーン HTTP 経由で提供されると再び機能します。 (#8212、@joegalbert-ai)
  • 新しいワークツリーはオリジン/マスターを追跡します - 新しいワークツリーは origin/master に基づいており、未開始の再利用は更新されるため、実行ワークスペースは古いコードから開始されません。 (#8412、@cryppadotta)
  • 永続的なエージェントの一時停止 - エージェントの一時停止は、実行開始時に永続的に維持されるようになりました。 (#8317、@Tattoofamily)
  • CLI ボード認証 - CLI は、ボード認証中にハングするのではなく、ヘッドレス ブラウザーを開く失敗を処理します。 (#8328、@AayushThakur1999)
  • パイプライン配管 - ボンネットの下に設置された多段パイプライン ケースの内部基盤 (ステージ、ケース遷移、ドリフト検出)。それはまだユーザーに面した表面ではありません。 (#7903、@cryppadotta)
