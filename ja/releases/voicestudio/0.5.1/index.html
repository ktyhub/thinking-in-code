VoiceStudio v0.5.1

#ボイススタジオv0.5.1

ハイライト

  • Apple Silicon 上の OmniVoice 生成は、クラッシュから隔離された子で実行されるようになったため、致命的な MPS メモリ終了によってローカル バックエンド (#1697、#1698) がダウンすることはなくなりました。ndntran14 に感謝します。
  • モデルロードの GPU が枯渇すると、サニタイズされた対処可能なダビング エラーが返され、共有モデルのステータスが TTS に正しく帰属するようになりました (#1695)
  • ソースモード開発は、UI を破棄することなく分離されたバックエンド クラッシュを再開するようになりましたが、繰り返されるクラッシュ ループは依然として診断によって大声で停止します (#1690)
  • WebView がプレビュー画像をレンダリングできるが、そのオーディオをデコードできない場合、ダビング再生では可聴コンパニオン ソースが保持されるようになりました (#1692)
  • モデル カタログ エンジンの行は、利用可能なデスクトップの幅を使用するようになり、ID、ランタイム状態、およびアクションが互いに混雑しないようにします (#1689)
  • VoiceStudio はローカル音声プラットフォームとして機能するようになりました。他のアプリはネイティブのディクテーションをトリガーしたり、バージョン管理された HTTP、WebSocket、JSON-RPC、CLI、MCP トランスポート経由で接続したりできます (#1646)
  • タイムアウトしたインプロセス ダブ トランスクリプションでは、放棄されたネイティブ ワーカー上で 2 番目の WhisperX/CTranslate2 呼び出しが開始されなくなり、Windows 0xC0000005 が終了する前に発生した重複アクセスが防止されます (#1669)
  • Windows デバッガ終了コード 0x40010004 がバックエンド クラッシュとして誤って報告されたり、自動再起動回復に対して請求されなくなりました (#1663)
  • Studio は、ページ変更全体で 1 世代の予約を保持するようになり、バックエンドが容量ビジーを報告するか、メモリ不足で強制終了されるまで、再マウントによってネイティブ ジョブがスタックされるのを防ぎます (#1670)
  • アップロードされたダビングビデオはプレビュー前にブラウザーセーフな H.264/AAC に正規化され、有効な VP9、AV1、または Opus メディアが「サポートされているソースがない」という理由で失敗するのを防ぎます (#1644)
  • 吹き替えでは、音声言語とターゲット言語が分離され、セグメントのクリーンアップを通じて翻訳が保存され、バッチを再起動せずに失敗した翻訳を再試行またはスキップできるようになりました (#1654) — Number16BusShelter に感謝します!
  • 置換 SRT 字幕をインポートすると、各行がランダムなデフォルト音声 (#1660) にリセットされるのではなく、各キューが最も重複するソース スピーカーとクローンにバインドされたままになります。invio-a11y に感謝します。
  • ダブ プレビューをアップロードしても、ffmpeg がオーディオを抽出する間、すべてのバックエンド リクエストがブロックされなくなりました (#1667) — ありがとう、tfreyd!
  • Docker クイック スタートでは、保護されたアクションが 403 (#1651) を返す UI を開始する代わりに、コンテナ NAT 経由で必要な管理者キーが必要になりました — wd357dui に感謝します!
  • WSL2 AMD コンテナは、CPU (#1655) にサイレントにフォールバックする代わりに、実用的な GPU 診断を備えた /dev/dxg ROCDXG ブリッジを使用するようになりました — ありがとう、wd357dui!
  • アドホック音声クローン参照は、キャンセルまたはタイムアウトした GPU 作業によって読み取りが実際に停止されるまで存続するようになりました。そのため、削除された一時ファイルで失敗する代わりにプロンプ​​ト キャッシュを完了できます (#1668) — ありがとう、tfreyd!
  • ディクテーションは、開始されたアプリにバインドされたままとなり、サイレント認識機能の出力からローカルに復元されるようになりました (#1175)
  • バックエンドは起動後 1 秒以内に応答し、起動を段階的に説明するようになりました (#1550)
  • 古いビルドからのバグを報告すると、最新リリースが最初に提供されるようになりました (#1547)
  • バックエンドは、実際にサービスを提供できるようになって初めて準備が完了したと発表され、クラッシュ ループの再起動が自動的に行われるようになりました (#1548)
  • 目に見えない透かしがセッションの最初のテイクで停止したり、黙ってスキップしたりしなくなりました (#1615)
  • 吹き替え字幕は、セグメント テーブル (#1612) からいずれかの方向にリタイム、挿入、マージできます。invio-a11y に感謝します。

変更されました

  • モデル カタログは、ネストされたカードやスクロール領域の代わりに、よりシンプルなペインとエンジン ファミリのナビゲーションを備えた 1 つの通気性の高いワークスペース キャンバスを使用するようになりました (#1685)
  • Linux ソース ランチャーは、リンカー エラーや中止された空の WebKit レンダラーを引き起こす前に、欠落している libxdo および GStreamer オーディオ プラグインを検出するようになりました (#1680、#1682)
  • ディクテーションは、ショートカットから最終配信まで 1 つのネイティブ出力セッションを実行し、テキスト、HTML、画像、またはファイルリスト clipboards を未タッチの場合にのみ復元し、現在のフォーカスの挿入が明示的に有効になっていない限り Wayland のコピーセーフを維持し、すでにインストールされているローカル ASR モデルを通じてのみ無音の Sherpa 音声を再試行します (#1175)
  • バックエンドはポートを即座にバインドし、起動の進行状況をライブで報告します。/health は 503-with-step に応答し、PyTorch、API ルート、およびデータベース移行がバックグラウンドで読み込まれる間、新しい /startup/progress エンドポイントがすべてのステップをリストするため、「ステップ X から開始」が「デッド」と間違われることはありません。デスクトップのスプラッシュが各ステップをナレーションします (#1550)

追加

  • バンドルされた Rust ループバック サイドカーは、ディクテーションの開始/停止/切り替え、集中出力セッション、検出、および JSON-RPC を公開します。バックエンドは、バージョン管理されたストリーミング イベントと、Herdr、コーディング エージェント、エディター、デスクトップ アプリ、TUI 用の依存関係のない CLI ブリッジを追加します (#1646)
  • ヘッドレス NVIDIA および ROCm マシンは、公開された UI と永続的なプロトコル v2 登録を持たないワーカー専用の Docker Compose サービスとして参加できるようになりました。再接続する前に両方のマシンを一緒に更新する (#1638) — jkrogers9862 に感謝します!
  • OmniVoice GGUF エンジンの Linux ARM64 (Asahi Apple Silicon) サポート — ツールチェーンで許可されている GGML Vulkan で構築された linux-aarch64 バイナリ。そのため、Apple GPU は、CPU のみにフォールバックするのではなく、オープンソースの Honeykrisp ドライバーを通じて生成を加速します (#1641)
  • すべてのデスクトップ OS に 1 つのコマンドでインストール: curl -fsSL https://voicestudio.sh/install | sh (macOS/Linux/WSL) または irm https://voicestudio.sh/install | iex (Windows) — URL はプラットフォームごとに適切なスクリプトを提供し、Windows は 3-OS CI スモーク (#1626) を含むソース インストーラー (scripts/install.ps1) を取得します。
  • 吹き替えテーブルでの行ごとの字幕管理: 行の終了時間は開始と同時に編集可能 (時間を入力し、タイムラインの端をドラッグすると同じパスを通るようになりました)、行は前の行および次の行とマージされ (Ctrl/Cmd+Shift+M)、任意の行の後のギャップに新しい行を挿入できます (#1612) — invio-a11y に感謝します。
  • CI は、ホット パス上でパフォーマンス回帰バジェットを適用するようになりました。オペレーション カウント テストでは、ストリーミング TTS を文ごとに 1 つの合成に固定し、キャッシュされたダブリミックスを再合成ゼロに固定します。高速パス ガードは、有効になっている場合、ゼロ再デコードと ⌈N/W⌉ ネイティブ バッチ呼び出しをカバーします (#1594)
  • デフォルト エンジンのダビングは、1 行あたり 1 つのコールではなく、順方向パスごとに複数のセグメントを合成するようになりました。幅はホストのデバイス ヘッドルームに従います (CPU および低 VRAM カードでは 1、最大 8)。OMNIVOICE_DUB_BATCH_WIDTH はそれをオーバーライドし、ネイティブ バッチ処理のないエンジンは単一セグメント パスを維持します (#1594)。
  • /ws/tts はリアルタイムのファーストオーディオを報告するようになり、その RTF は合成のみを測定するため、遅い client はそれを拡張できません (#1594)
  • ローカルにキャッシュされた AudioSeal ウォーターマーク ジェネレーターは、起動後約 35 秒でバックグラウンド スレッドでウォームアップします (OMNIVOICE_PRELOAD_WATERMARK=0 はオプトアウトします。=1 を明示的に設定するとダウンロードされる可能性があります)。そのため、最初の合成では、audioseal インポートとモデルのロードがインラインでシリアル化されなくなりました。コールド ファイル システムで約 42 秒で測定され、90 秒の client タイムアウト (#1576) に 3 秒足りませんでした。paoloantitori に感謝します。
  • クローンした音声は、再起動後も「ウォーム」な状態を保ちます。エンコードされたリファレンスはディスク (それぞれ最大 10 KB) に保持されるため、セッションの最初の世代では再エンコードとトランスクリプション パスがスキップされます。 OMNIVOICE_PROMPT_DISK_CACHE=0 がオプトアウト (#1565)
  • CUDA 上のデフォルト エンジンのオプションの FlashInfer アクセラレーション (OMNIVOICE_FLASHINFER=1、測定値 ~2.2 倍) - オプションの flashinfer-python パッケージが必要です。パッケージが見つからない、またはカーネル障害が発生した場合は、その理由がログに記録され、標準パスにフォールバックされます (#1565)
  • バグ レポーターは、古いビルドを使用していることに気づき、ファイルする前に最新のリリースを提供します (「とにかくファイル」エスケープ ハッチを使用して)。また、すべてのレポートに Build status 行をスタンプするので、最新のレポートと古いレポートが区別できます (#1547)
  • [設定] → [パフォーマンスとデバイス] でコンピューティング デバイスのオーバーライドが可能になります (自動 / CUDA / ROCm / XPU / MPS / CPU、または OMNIVOICE_DEVICE) — 自動検出が間違って選択した場合にデバイスを固定します。あなたのマシンが実際に持っているデバイスのみが提供されます (#1557)
  • OMNIVOICE_POCKETTTS_24L 経由で 24 層の PocketTTS チェックポイントをオプトインします。約 2 倍のレンダリング時間 (それでもリアルタイムより速い) で、it/de/es/pt の韻律が向上します。高速 6 層モデルはデフォルトのままです (#1613) — paoloantinori に感謝します!

ドキュメント

  • サポートされているバージョンとインストールのガイダンスでは、安定したデスクトップおよびコンテナーのリリースとして 0.5.1 が識別されるようになりました (#1687)
  • Docker ハブの概要に、現在のエンジン切り替えデモ、モデル カタログ、ギャラリー音声ワークフローが表示されるようになりました (#1593)
  • Docker ハブの概要とインストール ガイドには、廃止された v0.4 と認証なしのガイダンスの代わりに、v0.5 タグと組み込みの API キー/共有 PIN セキュリティ モデルが表示されるようになりました (#1592)
  • README には、ダウンロード ボタンと 3 ステップの最初のクローンのウォークスルーが含まれており、新しいベンチマーク ページでは、リポジトリ内ハーネスでエンジンごと/デバイスごとに測定された数値がアンカーされています (#1555)
  • すべてのエンジンに独自のガイドが追加されました。docs/engines の下に 21 の新しいページと、16 の TTS エンジンと 11 の ASR エンジンすべてをカバーするインデックスがあり、両方の README (#1556) からリンクされています。
  • OmniVoice ガイドでは、スタイル属性と参照 clip の組み合わせ (一貫した命令によりクローン作成が安定します。参照は競合に勝ちます)、インライン発音制御 (ピンイン / CMU 音素) が取り上げられ、デフォルト エンジンでは音声デザインができないという主張が修正されています — 属性からは可能です (#1565)

修正済み

  • ブートストラップ後のシェルが実際にマウントされるときに、ワークスペースの応答幅が測定されるようになりました。そのため、ネイティブ UI スケーリングにより、ダビング デモが読み取れない列に押しつぶされるのではなく、プロジェクトと履歴がリフローされます (#1683)

  • ダビングすると、ローカル ファイルが選択された後もソース言語セレクターが表示されたままになるため、文字起こしを開始する前に ASR を固定できます (#1678) — Lonki-lomki-cloud に感謝します。

  • 初回実行のメディア エンジンのダウンロードは、再起動せずに TTS ですぐに利用できるようになり、失われたメディア プロセスの障害は修復制御を示すようになりました (#1677) — farhataligpt-dev に感謝します。

  • AMD GPU へのソース インストールは OMNIVOICE_TORCH_VARIANT=rocm を尊重します: bun run desktop は、起動するたびに CPU のみの CUDA ビルドに静かに戻るのではなく (#1665)、uv sync の後に ROCm トーチ ホイールを交換し、再同期せずにバックエンドを起動するようになりました (#1665) — uberclokr に感謝します。

  • 新しいクローン上の bun run desktop が「リソース パス ../../frontend/dist が存在しません」で失敗しなくなりました — 開発ランチャーはコンパイル前にプレースホルダー Tauri リソース ディレクトリを作成します (#1664) — uberclokr に感謝します!

  • Python に os.waitid がない場合でも、macOS は最初のリクエスト後に TTS を失わなくなりました。サブプロセスの所有権は、再利用されたプロセス グループを危険にさらすことなく、安全な waitpid フォールバックを使用するようになりました (#1656) — paoloantinori に感謝します!

  • デスクトップの起動、再試行、リセット、アンインストール、シャットダウン、およびクラッシュ回復が 1 つのバックエンド ライフサイクル所有者を共有するようになりました。終了すると、最初に実行されたインストーラーが中断され、正常にドレインされてから完全なバックエンド プロセス ツリーが強制的にクリーンアップされるため、重複によって重複したり孤立したりすることはありません (#1635) — ありがとう、Xohaibxobi!

  • 大規模なストーリーとオーディオブック プロジェクトは、omnivoice.app localStorage エンベロープをオーバーフローさせるのではなく、IndexedDB に保持されるようになり、クォータセーフな移行と秩序ある終了/リロード フラッシュ (#1636) — leodzai に感謝します。

  • OmniVoice とそのクラッシュ分離サブプロセスは、警告を発して CPU にフォールバックするのではなく、AMD ROCm GPU にルーティングされるようになりました (#1629) — ありがとう、j4r3kb!

  • ディクテーションは、キャプチャ ウィジェットが閉じるときに保留中の起動作業、キャプチャ リソース、ソケット、およびタイマーをキャンセルするようになり、破壊された Web ビューに対する遅延作業を防止します (#1645)

  • ストリーミング生成の失敗は、一般的なエラーのみを返すのではなく、認識された回復ガイダンスを表示し、診断に表示されるようになりました (#1607)

  • ワーカー容量トランスポート テストは、独自のセットアップと競合しなくなりました。1 スロット制限は、接続後に client 設定を変更するのではなく、登録ハンドシェイクを通過するようになりました。ここで、サーバーのストリーム オープン ConfigUpdate (登録された容量 2 を運ぶ) がそれを上書きし、過剰受け入れを偽装する可能性があります。 2026 年 8 月 21 日に CI が 2 回失敗しました (#1630)

  • 吹き替えで話者の境界を越えて単語を移動する (2 行を結合して再度分割する) と、後半が最初の話者の声で吹き替えられなくなりました。それぞれの半分には、実際に発言した人の話者、声、方向、利得、言語が保持されるようになりました (#1612) — invio-a11y に感謝します!

  • 16 kHz オーディオ コンテキスト (WKWebView) を拒否する WebView でのディクテーションは、ダウンサンプリングの前にローパスするようになったため、8 kHz を超える周波数が認識エンジンに供給される音声に組み込まれなくなります (#1610)

  • 再開できないマイク コンテキストは、何もキャプチャせずにディクテーション ピルを「リスニング」のままにするのではなく、マイク エラーを報告するようになりました (#1610)

  • ディクテーションでは、サイレント モデルの回復のためにセッション全体の音声が保持されなくなりました。オープン マイクでは、そのバッファが 1 時間あたり最大 115 MB 増加しました。代わりに最近の 2 分間が保持されます (#1610)

  • clipboard の配信ステータスが 21 言語すべてに翻訳されるようになったため、clipboard の配信がデフォルトである Wayland ユーザーには英語の文字列が表示されなくなりました (#1610)

  • あらゆる例外タイプのネイティブ sherpa-onnx ロード失敗は、ディクテーション WebSocket をダウンさせるのではなく、「エンジンが使用不可」に劣化するようになりました (#1610)

  • Dictation が 1 つのクロスプラットフォームのデフォルトとして Whisper Tiny を出荷するようになり、Windows 上での Parakeet の測定された空のデコードを回避しながら、ランタイム フォールバックの背後で Parakeet を選択できるようにしました (#1175)

  • ダブを再ミックスしても、キャッシュされたすべてのセグメントをデコード、書き換え、再読み取りすることはなくなりました。同じレートのキャッシュされたオーディオは直接再利用され（切り捨てられた場合は拒否されます）、タイミング モードの切り替えではスロットで切り捨てられたオーディオをナチュラル レートとして再利用できず、RVC はナチュラル レート モードを尊重します (#1594)

  • PocketTTS フランス語が再び動作します。pocket-tts は 24 層のフランス語モデルのみを出荷し、サイドカーが要求した名前を拒否したため、すべてのフランス語リクエストがモデルのロード時に失敗しました。フランス語は常に french_24l (#1613) をロードするようになりました — paoloantinori に感謝します!

  • IndexTTS 2.5 のインストールがダウンロードの中断を主張して失敗しなくなりました。ウェイト リポジトリには config.yaml が同梱されており、VoiceStudio はアップストリーム リリースに存在しない config_v2_5.yaml を要求しました。どちらの名前も受け入れられるため、手動で名前を変更したチェックアウトは機能し続けます (#1611) — zuiaiyutu に感謝します!

  • IndexTTS 2.5 では、長文生成が 60 秒で強制終了されなくなりました。infer() の実行中、サイドカーは 5 秒ごとに生存を証明するようになり、期限が 900 秒 (OMNIVOICE_INDEXTTS_RECV_TIMEOUT_S) (#1611) に上昇しました。zuiaiyutu に感謝します。

  • OpenAI 互換の /v1/audio/speech ルートは、新しいエンジンを構築する代わりに、明示的な model ID の共有キャッシュ エンジンを再利用するようになりました。また、そのサイドカー/モデルのロード、サブプロセス エンジンの呼び出しごとに最大 28 秒のフロアが、要求ごとに、単一エンジン常駐の /generate と同じ規律 (#1614) を適用します。ありがとう、paoloantinori!

  • セットアップ ウィザードの RAM チェックは、OS が ~7.8 GB が使用可能であると報告する 8 GB マシンをブロックしなくなりました。しきい値は予約メモリを許容するようになり、OMNIVOICE_RAM_PREFLIGHT=0 は本物のブロックを OOM リスクを受け入れるユーザーに対する警告に変えます (#1618)

  • 目に見えないウォーターマークが torch.compile 経由ではなく積極的に実行されるようになりました — AudioSeal の遅延コンパイルは、すべてのセッションの最初の埋め込みを Inductor の C++ codegen に送信しましたが、ツールチェーンがそれを提供できない macOS ホストでは完全に失敗し、30 ～ 40 秒の待機後にマークなしでオーディオが出荷されました。最初の埋め込みは 9.70 秒から 0.26 秒に低下しました (#1615) — paoloantinori に感謝します!

  • macOS アクセシビリティ ブロッカーは、画面上に古い権限プロンプトを表示し続けるのではなく、表示されている間に再チェックし、許可が有効になるとすぐに閉じるようになりました (#1609)

  • 吹き替えエディターのビデオとトランスクリプトの列は、ポインターまたはキーボードでサイズ変更できるようになり、選択した分割は起動後も維持されます (#1571) — invio-a11y に感謝します。

  • CPU のみの合成には 10 分の制限付き実行バジェットが設定され、それを使い果たすレンダリングは、誤解を招く「生成容量がビジーです」キュー圧力 (#1588) ではなく、コンピューティング タイムアウトとして報告されます。ChienNguyen1111 に感謝します。

  • Rapid Launchpad ↔ ダブ ナビゲーションはワークスペース DOM オーナーを完全に置き換えるようになり、遅れたメディア/波形クリーンアップが React の insertBefore クラッシュを引き起こすことはありません (#1590) — nicolas-jacques に感謝します!

  • ウォーターマーク埋め込みの失敗は、例外メッセージだけでなく完全なトレースバックをログに記録するようになりました。そのため、サイレントにマークされていないオーディオ インシデント (設計によりマークされていないオーディオが通過する) は、ログのみから診断可能です (#1576) — paoloantinori に感謝します。

  • ダビングでは、ダイアライゼーションが崩壊したときに rapid の 2 つのスピーカーの交換が回復され、保存されたタイミングの選択を上書きせずに新しいプロジェクトをデフォルトでリップシンクに設定し、狭い画面でもエディターを使用できるようにします (#1584) — victordonat0 に感謝します!

  • OMNIVOICE_ASR_BACKEND=omnivoice は PyTorch ネイティブの Whisper パスを選択するようになったので、文書化された ROCm 脱出ハッチが不明なエンジンとして失敗することはなくなりました (#1582) — patmansk に感謝します。

  • Windows MSI/ポータブル インストールからのネットワーク共有は、LAN デバイスを独自の localhost (#1589) にリダイレクトするのではなく、バンドルされた Web インターフェイスを LAN デバイスに提供するようになりました — TWIISTED-STUDIOS に感謝します!

  • エクスポートされた吹き替えビデオは、オリジナルを明示的な選択として利用可能なままにしつつ、吹き替え言語をデフォルトのオーディオ ストリームとしてマークするようになりました (#1575) — invio-a11y に感謝します!

  • クローン参照によってシステム メモリが使い果たされることはなくなりました。最長 75 秒のトランスクリプトのない clips は 5 つの境界のあるパッセージで検索され、より長い clips はトリミングを要求され、提供されたトランスクリプトはアライメントを維持するために 20 秒に制限されたままになります (#1578) — ありがとう、ACKAPOB!

  • Windows、macOS、Linux、Docker の間でデータ ディレクトリを移動した後、保存されたアーティファクトのサブパスが解決されるようになりましたが、トラバーサルとシンボリックリンクのエスケープはブロックされたままになります (#1559) — Eman-Yousaf に感謝します。

  • API キーが設定されたサーバーの管理者 403 にアクセスするリモート ブラウザは、エンドレス コンソール 403 の代わりに API キーのログイン フォームを取得するようになりましたが、デスクトップおよび PIN のみ/キーなしのサーバーは単純なループバック エラーを維持するため、キーなしで満足できるログインがゲストに提供されることはありません (#1568) — paoloantitori に感謝します。

  • クラッシュ隔離された ASR サイドカーとそのダウンロード プリフライトは、どのモデルをロードするかについて合意するようになりました。共有の高速ウィスパー モデル変数の設定は、サイドカーが別のモデルを静かに使用するのではなく、両方のバリアントに適用されます (#1556)

  • 「準備完了」には、ID プローブだけでなく、ディープ ヘルス プローブ (データベースに基づく有効なルート) が必要になりました。実際のリクエストがすべて失敗する間、インストールが壊れたバックエンドは起動をアナウンスできなくなりました (#1548)

  • クラッシュが繰り返された後のスーパーバイザーの再起動は、連続して再起動するのではなく、バックオフ (即時、その後 5 秒、その後 15 秒) するようになりました。そのため、タイトなクラッシュ ループによって数秒で再起動バジェット全体が消費されることはありません (#1548)

  • Linux デスクトップ クリーンアップ回帰テストはビルド アーティファクトを分離するようになったため、既存の開発者ビルドは結果を変更できなくなりました (#1566)

  • 音声の名前変更、削除、または同意の取り消し (および履歴のスター付け/消去、エクスポートの録音) は、開いているすべてのタブを再びライブ更新するようになりました。同期ルートの WebSocket イベントは静かに削除され、「私の声がすべて消えた」ように見える可能性がありました (#1561) — paoloantinori に感謝します。

###CI

  • プロジェクト エージェントは、skills.sh から固定された Vite および FastAPI スキルを共有するようになりました (#1594)
  • 毎週の全履歴シークレット スキャンで、Ed25519 秘密鍵タイプ名をコミットされた鍵マテリアルと間違えなくなりました (#1591)
