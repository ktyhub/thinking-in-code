#FastGPT v4.16.2

再リリースの手順

ブランチの選択が間違っていたため、リリースするブランチを再選択してください。

📦 アップグレード ガイド

1. ワーカー同時構成の削除

V4.16.2 は、PARSE_FILE_WORKERS、PARSE_FILE_WORKER_MEMORY_LIMIT_MB、HTML_TO_MARKDOWN_WORKERS、および TEXT_TO_CHUNKS_WORKERS を削除します。アップグレード時に、Docker Compose の .env または environment からこれらの変数を削除してください。置換変数を構成する必要はありません。

ファイル解析ワーカーのハード上限は、Node.js によって検出された利用可能な CPU 並列処理に基づいて自動的に設定され、コンテナーの CPU クォータとプロセス アフィニティを考慮して、少なくとも 1 つのワーカーが予約されます。同時に実行されるタスクの実際の数は、ファイル解析メモリのスケジュールによっても制限されます。

HTML から Markdown への変換ワーカーとテキスト ダイシング ワーカーは、利用可能な CPU 並列処理と 5 の小さい方にハード キャップが設定されています。タスクが開始される前に、システムの安全予約の範囲外にスケジュール可能なメモリがあるかどうかがチェックされます。マージンがない場合はキューに入れられ続けます。タスクが完了するとすぐに再試行されます。それでも不十分な場合は、30 秒ごとにチェックされ、最長 30 分間待機します。ワーカーは 60 秒以上アイドル状態になると自動的にリサイクルされ、最大 1 人のワーカーを長時間保持できます。

3. リソース権限データのクリーンアップと移行 (商用バージョンの実行)

このバージョンでは、最初に無効なリソース権限がクリーンアップされ、次にアプリ、データセット、エージェント スキルのリソース権限が完了して、有効な ACL が完成します。アップグレード後に予行運転を実行してください。ドライランでは、権限データの削除や書き込みは行われません。デフォルトではすべてのチームが処理されますが、teamId を介して個々のチームを指定することもできます。

curl -X POST 'https://你的域名/api/admin/4162/initPermission' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true,"teamConcurrency":100}'

migration.errors が空であること、または例外リソースの処理が完了したことを確認した後、正式なクリーンアップと移行を実行します。

curl -X POST 'https://你的域名/api/admin/4162/initPermission' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"teamConcurrency":100}'

teamConcurrency は、ACL 移行によって同時に処理されるチームの数を 1 から 1000 の範囲で制御します。デフォルト値は100です。同じチーム内のアプリ、データセット、エージェント スキルは順番に処理されます。単一チームの特定のタイプのリソースの処理が失敗すると、例外が migration.errors に書き込まれ、他のリソース タイプとチームの処理が続行されます。 sampleLimit は、cleanup.samples によって返される無効な権限サンプルの数を制御します。返される結果は、cleanup と migration の 2 つの部分に分かれています。cleanup には、スキャン、ヒット、および削除の統計が含まれます。 migration.resourceCount はスキャンされたリソースの数、migration.updatedResourceCount は書き込む必要があるリソースの数、migration.skippedResourceCount は親の欠落または異常なツリー構造のためにスキップされたターゲット リソースの数、migration.errors には例外の詳細が含まれます。移行ではリソース自体の所有者と子のアクセス許可が保持され、親リソース チェーンがオンデマンドで読み取られ、継承スイッチが欠落している履歴リソースは継承を有効にすることで処理されます。

ドライランでの移行プレビューは、クリーンアップ前の現在の権限データに基づいています。 cleanup が無効な権限に達した場合、公式クリーンアップ後の移行統計はプレビューと異なる可能性があります。

正式なクリーンアップと移行は安全に繰り返すことができます。完了したら、再度予行運転を行って、cleanup.danglingPermissionCount、migration.updatedResourceCount、および migration.errors がすべて 0 であることを確認します。 migration.errors が存在する場合は、再試行する前に、リソース タイプ、リソース ID、および親 ID に基づいてデータを修復する必要があります。

4. Milvus ベクター ライブラリを使用する場合の全文検索をアップグレードする

現在のベクター ライブラリが Milvus の場合、FastGPT をアップグレードする前に、Milvus を 2.5.16 以降にアップグレードする必要があります。 V4.16.2 は、全文検索を自動的に Milvus BM25 に切り替え、新しい modeldata_v2 コレクションを使用してベクターと全文を保存します。 Milvus のバージョンが低すぎる場合、バージョンが認識できない場合、または BM25 機能の検証に失敗した場合、FastGPT は起動を終了し、MongoDB の全文検索に戻りません。

既存の Milvus デプロイメントをアップグレードする場合は、古いベクター データがまだ存在していることを確認する必要があります。

  • 古い Milvus modeldata コレクションが存在し、データがあります。GET /api/admin/4162/milvus を呼び出して、埋め込みを再生成せずに、MongoDB 内の古いベクトルとインデックス付きテキストを modeldata_v2 にマージして移行します。
  • PG、OceanBase、SeekDB、または openGauss を使用する場合、この手順は必要ありません。全文検索では引き続き MongoDB $text が使用されます。

バックアップ、Milvus イメージのアップグレード、ドライラン、ブレークポイントの再開、結果の検証、古いテーブルのクリーンアップおよびロールバックの手順については、[Milvus BM25 Full Text Search Configuration and Migration] (https://doc.fastgpt.cn/zh-CN/self-host/milvus-bm25) に厳密に従ってください。

🚀 新しいコンテンツ

1.韓国語をサポートします。 2. スキルバージョンを切り替える際に上書きプロンプトを追加しました。 3. アカウントのキャンセルをサポートします。 4. Milvus をベクトル ライブラリとして使用する場合、modeldata_v2 単一テーブルに基づく BM25 全文検索がサポートされます。 5. ドキュメント解析では、DOC、WPS、DOCM、PPT、PPS、POT、PPTM、PPSX、PPSM、XLS、XLSM、XLSB、ODT、ODS、ODP、RTF、EPUB 形式を新たにサポートしました。パーサーによって認識された埋め込み画像は抽出されてオブジェクト ストレージにアップロードされ、画像参照は解析結果に保持されます。認識されない画像フォームは解析可能なテキスト コンテンツに返されます。 6. すべてのノードがツール呼び出しをサポートし、一部のノードの入出力対話が最適化されます。

  2. 管理者ページとモデルプロバイダーのルーティング。
  3. S3 チャンクアップロードネットワークジッターの最適化。
  4. ファイルアップロードエラープロンプトのテキストを統一しました。
  5. スキルを保存するときに、名前と説明の構造化抽出を最適化し、空の説明を許可します。

  9. 拡張 PDF 解析コストを read_files ツール ノードに収集し、ページ番号の詳細を保持します。ナレッジ ベース内の外部ファイルと API ファイルを解析し、それらを usageId に渡して、コスト帰属の損失を回避します。
  10. ツールの構成、バージョンの選択、解析されたドキュメントの表示を最適化し、応答性の高いレイアウト、バージョンの説明、2 列グリッド、長いファイル名の省略プロンプトをサポートします。
  11. コード サンドボックスが JS コードを実行するときのセキュリティの問題を強化します。

🐛 修正

  1. 管理用テンプレートマーケットにおけるアバター表示の問題を修正しました。
  2. システムツールをアンインストールした後、再インストールに失敗しました。
  3. ナレッジ ベースが空であるか、セグメントが 1 つしか含まれていない場合、エクスポートされたバックアップ CSV を再インポートできない問題を修正しました。 4.履歴チャット設定にお気に入りタグがない場合、または履歴メンバー名が空の場合の互換性の問題を修正しました。
  4. カスタマイズしたワークフローツールのアバター設定が期待どおりに表示されない問題を修正し、システムツールのアバター詳細を追加しました。
  5. 管理者パッケージ リストでチームによって削除された孤立したパッケージが見つかった場合、リクエスト全体が失敗する問題を修正しました。
  6. 請求対象リストに注文 ID が欠落し、過去の請求月の形式が一貫性がなく、過去の請求書に連絡先電話番号が欠落しているとリストの検証が失敗する問題を修正しました。
  7. 履歴ナレッジ ベース ブロック パラメーターが数値文字列として保存された場合に検証に合格できず、ナレッジ ベースの詳細がロードされる前に同期リクエストが開始される問題を修正しました。
  8. 旧バージョンのアプリテンプレートの履歴ワークフローフィールドが現在の構造に従って読み込めない問題を修正しました。
  9. ファイル アイコンであいまい接尾辞一致が使用され、マークダウン ファイル名に DOCX などのテキストが含まれている場合に、そのファイル名が誤って DOC アイコンとして表示される問題を修正しました。新しい文書形式のアイコン マッピングを完了し、EPUB 用の独立したアイコンを追加しました。
  10. 履歴アプリ変数の valueType が空または null の場合、チャット設定が検証に合格しない問題を修正しました。チャット設定を読み込んで保存すると、変数入力タイプに応じて valueType が完成します。マッピングできない場合、または値が不正な場合は、any にフォールバックし、保存する前に Zod 検証に合格します。既存のデータに対して追加のクリーニング スクリプトを実行する必要はありません。
  11. 空のパラメーターに対するツール呼び出しで、空の type: object パラメーターが誤って追加されました。

🛠️ コードの最適化

  1. 統合ワークフロー旧バージョンツールパラメータ互換性ソリューション。
  2. アプリ、データセット、エージェント スキルのリソース権限を具体化された有効な ACL に変更し、コラボレーター権限の変更と継承の同期ロジックを統合します。
  3. ナレッジ ベース データ作成インターフェイスは、MongoDB セッションを必須にし、手動データ挿入のトランザクションを完了して、マスター データ、全文検索データ、および画像 TTL ステータスのアトミックな送信を保証します。
  4. XLSX ファイルの解析により、ワークシートの範囲、セルの結合、およびワーカーのメモリ制限が増加し、異常なファイルによる過度のメモリ使用が防止されます。
  5. 支払い方法を切り替えると、支払いポップアップ ウィンドウの内容が即座に更新されます。
  6. 管理者チーム、パッケージ、支払い、ユーザー リストのクエリを最適化し、ユーザー名の検索とページングのパフォーマンスを向上させます。
  7. ファイル解析のメモリと同時実行制御を最適化します。キューに入れられたタスクは軽量ファイル ソースのみを保存し、完全なバッファーを保持しなくなりました。信頼できる S3 ファイルは既知のサイズに従ってリソースを予約し、外部リンクはストリーミング ダウンロード中に実際のバイト数に応じてリソース占有率を更新し、ファイル サイズとシングルタスク メモリのハード制限を適用して、同時解析中の OOM リスクを軽減します。
  8. 統合ファイル解析入力は FileSource で、ファイルの内容はワーカーが実行スロットと初期リソース クォータを取得した後にのみ実体化されます。
    • 信頼できる S3 ソースは、オブジェクト メタデータを通じてファイル サイズを取得し、実体化と解析に必要なリソースを一度に予約します。ビジネス規模の検証はアップロード段階で完了しており、解析中に繰り返し確認されることはありません。
    • 信頼できない外部リンクがキューに追加される場合、パーサーの基本リソースのみが宣言されます。ダウンロード時には、ビジネス ファイルの上限とシングルタスクの永続メモリの上限がチェックされ、ソフト予約は実際にダウンロードされるバイト数に応じて単調増加します。ソフト予約によって現在の空き容量が使い果たされると、後続のタスクの開始が妨げられるだけで、すでに実行中のダウンロードは中断されません。
    • 待機キューにはタスク数や推定リソースの合計に上限が設定されず、30 分のキュー タイムアウトのみが保持されます。未完了のダウンロードは中止され、失敗、タイムアウト、またはワーカーの終了時にすべてのリソース予約が解放されます。
  9. モデル選択データ構造を再構築します。
