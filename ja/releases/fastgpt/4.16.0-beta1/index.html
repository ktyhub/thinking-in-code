#FastGPT v4.16.0-beta1

📦 アップグレード ガイド

1. Agent-sandbox-proxy 環境変数を更新します (オプション)

4.16.0 は、静的リソース プロキシ アクセスのためにプロキシに依存する必要があります。ゲートウェイが同じポートで ws と http をサポートしている場合、開くことができるポートは 1 つだけです。サポートされていない場合は、PREVIEW_PORT を設定することで http アクセス ポートを設定できます。

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

アクセスアドレスはhttp://またはhttps://で始まります。単一ポートを使用して展開する場合、AGENT_SANDBOX_PROXY_URL と同じドメイン名とポートを指すことができますが、プロトコルはそれぞれ HTTP(S) と WebSocket(S) を使用します。構成されたドメイン名と FastGPT メイン サイトでは異なるオリジンを使用することを強くお勧めします。同一オリジン展開では、これらのスクリプトがメイン サイトの同一オリジン セキュリティ境界に侵入し、メイン サイトの資格情報またはインターフェイスにアクセスできる可能性があります。現在、システムは分離のためのオリジンのチェックを強制していません。

https://{{host}}/health にアクセスして、アクセス可能かどうかを確認できます。

2. fastgpt-app 環境変数を更新します (サンドボックスが有効な場合は更新する必要があります)。

変数は、fastgpt-app と fastgpt-pro で同時に変更されます。

  1. 環境変数を追加する
# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. 非推奨のサンドボックス環境変数

AGENT_SANDBOX_DISK_MB、E2B 関連の変数。

  1. 新しいオプションのサンドボックス構成変数

|変数 |デフォルト値 |説明 | | -------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------- | | AGENT_SANDBOX_CPU_COUNT | 1 |エージェント サンドボックス 単一インスタンスの CPU コア制限。 | | AGENT_SANDBOX_MEMORY_MIB | 2048 |エージェント サンドボックスの単一インスタンスのメモリ制限、単位 MiB。 | | AGENT_SANDBOX_STORAGE_SIZE_GI | 1 |エージェント サンドボックスのストレージ容量 (Gi 単位)。 Sealos Devbox のストレージ制限と、OpenSandbox Kubernetes モードでの新しい PVC の作成に使用されます。 | | AGENT_SANDBOX_SUSPEND_MINUTES | 60 |実行中のサンドボックスが非アクティブになった後、自動的に一時停止されるまでの時間 (分単位)。 | | AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS | 7 |一時停止されたサンドボックスは、非アクティブな期間 (日単位) が経過すると、自動的にアーカイブされます。 |

E2B サンドボックス プロバイダーは削除されました。以前に E2B を構成した環境では、opensandbox または sealosdevbox に切り替え、AGENT_SANDBOX_E2B_API_KEY を削除する必要があります。

FastGPT、fastgpt-agent-sandbox-proxy、fastgpt-agent-sandbox のプレビュー プロトコルが同時に変更されました。エージェント サンドボックスを有効にする場合は、このバージョンのサポート イメージを使用する必要があります。古いバージョンと新しいバージョンの混合展開はサポートされていません。

4. エージェント サンドボックス データを移行する

このバージョンでは、App Chat のエージェント サンドボックスが「会話ごとに 1 つのインスタンス」から「同じアプリと同じユーザーによって共有される 1 つのインスタンス」に調整されます。さまざまな会話のファイルはそれぞれ sessions/<chatId> ディレクトリに保存され、公開されたスキルは共有 projects ディレクトリに保存されます。

エージェント サンドボックスが以前に有効になっていた場合は、従来のワークスペースの移行を次の順序で完了する必要があります。エージェント サンドボックスが有効になっていない環境では、このセクションをスキップできます。

最初にドライランを実行して、beta6 サンドボックス フィールドの正規化と古いスキル デバッグ チャットのクリーンアップの保留中の数を表示します。ドライランでは、リソースの作成、オブジェクト ストレージへのアクセス、データの変更は行われません。

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

予行演習の結果を確認した後、正式な移行を実行します。正式な移行では、最初にベータ 6 正規化が実行され、残りの保留数がゼロになった場合にのみ、同じリクエストでワークスペースのアーカイブが継続されます。

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

failures に Sandbox source is missing or deleted のみが含まれており、対応するアプリまたはスキルが存在しないことが確認されている場合は、これらの残りのサンドボックスを明示的にスキップできます。

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError デフォルトは false で、省略しても厳密な移行が維持されます。このスイッチは、ソースが欠落しているか論理的に削除されたグループ全体をスキップするだけであり、その中のサンドボックスはアーカイブ、削除、移行されません。スキップの詳細は、skippedCount および skipped を介して返されます。アーカイブ、オブジェクト ストレージ、プロバイダー、同時実行制御などの他のエラーによっても、移行がブロックされる可能性があります。 移行では、まず V4.15.0-beta6 の完全な事前ロジックが実行されます。つまり、古いサンドボックスの sourceType/sourceId を入力し、レガシー フィールドをクリーンアップし、属性を特定できない孤立したリソースを削除し、sourceType が欠落している古いスキル デバッグ チャットの 3 つのテーブル データと、プライベート バケットとパブリック バケットの古いプレフィックスをクリーンアップします。アプリと同じ ID を持つスキルはチャットのクリーンアップをスキップします。 2 種類のデータを再度記載すると、合計は normalization.pendingCount になります。数量が 0 でない場合、ワークスペース アーカイブには入力されません。ゼロ化後、すべての古いワークスペースを直接アーカイブし、古いコンピューティング リソースをクリーンアップしてからスキルを移行し、最後にアプリとユーザーごとにユーザーレベルのサンドボックスに集約します。アーカイブ段階で障害が発生する限り、インストール段階は開始されません。新しいサンドボックスは、ワークスペースのインストールが完了すると一時停止され、初めて使用するときに通常のプロセスに従って開始されます。スクリプトは安全に再試行でき、完了したアーカイブと移行は再実行されません。古いアーカイブと古い MongoDB レコードは、移行の完了後もバックアップとして保持されます。

normalization.pendingCount、normalizationBlocked、failedCount、failures、skippedCount、skipped の返された結果を確認してください。 normalization.pendingCount と failedCount が両方とも 0 であり、normalizationBlocked が false である場合にのみ、スキップされていないすべてのサンドボックス移行が完了したことを意味します。 skipped のレガシー レコードは保持され、移行されません。

5. HTTP ツールのデータを移行する

このリリースでは、手動モード HTTP ツールの配列パラメーターが標準の JSON スキーマに変更されます。アップグレード前に手動 HTTP ツールを作成した環境では、この移行を実行する必要があります。 OpenAPI モードの HTTP ツールは移行する必要がなく、スクリプトは自動的にスキップされます。

まずドライランを実行して、現在のアプリケーションと過去のバージョンの保留中のデータを表示します。ドライランではデータは変更されません。

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

結果を確認したら、正式な移行を実行します。

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

このスクリプトは、まず HTTP ツール タイプでアプリケーションをフィルタリングし、次にこれらのアプリケーションの appId に基づいて対応する履歴バージョンを移行します。 apiSchemaStr に存在しない手動モードのみが処理され、他のアプリケーションや OpenAPI モードは変更されません。移行はバッチで実行されるため、安全に再試行できます。返された結果の total.changedDocumentCount は、処理対象として見つかったドキュメントの数を示します。正式な実行後、再度ドライランを実行して、値が 0 であることを確認できます。

6. その他の変更 (オプション)

  1. PASSWORD_LOGIN_LOCK_SECONDS 変数を破棄し、1 分あたりのログイン頻度を制御するために使用される PASSWORD_LOGIN_MINUTE_LIMIT_COUNT に変更します。

🚀 新しいコンテンツ

  1. エージェント サンドボックスはアプリのユーザーレベルのインスタンスに変更されます。同じアプリと同じユーザーの複数の会話はサンドボックスを再利用し、独立したセッション ディレクトリを通じて各会話ファイルを分離します。
  2. サンドボックス HTML とファイルは、短期間の読み取り専用リンクを介した直接プレビューをサポートしており、プレビューのためにオブジェクト ストレージに繰り返しアップロードする必要がなくなりました。
  3. アプリ ワークフローは、サンドボックス プロバイダーまたはランタイム イメージが変更されると、ワークスペースを自動的にアーカイブおよび復元し、アップグレード プロセスは現在の実行中にサイレントに完了します。
  4. ワークフロー ツール ノードは、エージェントによる指定された入力パラメータの自動生成をサポートし、固定値、参照、ユーザー入力などの既存の設定を保持します。
  5. ChatAgent がツールを選択するときに、AI のパラメーターを生成するかどうかの手動指定をサポートします。
  6. ナレッジ ベース データは metadata のカスタマイズをサポートし、JSON メタデータは API、CSV、または Excel テンプレートを通じてインポートできます。このフィールドは検索結果とバックアップ エクスポートに保持されます。テンプレート インポートとバックアップ インポートは両方とも、q、a、index、および metadata ヘッダーを使用する .csv および .xlsx ファイルをサポートします。 q、a、および metadata にはそれぞれ 1 つの列があり、index には任意の順序で複数の列を含めることができます。 Excel ファイルは単一のワークシートのみをサポートし、結合されたセルを含めることはできません。 CSV または Excel ファイルを正しく解析できない場合は、ファイル形式の例外が表示されます。
  7. 大きなファイルを分割してアップロードします。
  8. 管理者がシステム ツール キーを設定すると、そのキーは暗号化されます (設定されたキーと互換性があります)。
  9. スキルリストの空ステータス案内とスキル選択時の連携。

⚙️ 最適化

  1. エージェント サンドボックスのライフ サイクルと移行プロセスを再構築します。作成、一時停止、アーカイブ、復元、削除、およびプロバイダーの切り替えは、同時実行保護、ブレークポイントの再開、冪等な再試行をサポートします。
  2. エージェント サンドボックスが使用できない場合、または現在のチーム パッケージでサポートされていない場合、App Chat はサンドボックス機能を自動的に無効にし、他のモデル、ツール、ナレッジ ベース、およびワークフロー ノードは引き続き実行できます。
  3. OpenSandbox の停止後も永続ボリュームを保持し、その後の実行中に再利用できます。一時停止およびアーカイブのしきい値は、環境変数による構成をサポートします。
  4. アプリとスキルはランタイム イメージのアップグレード ステータスを統合しており、スキル編集ページはアップグレード結果を継続的にポーリングできます。
  5. ネストされたパスの書き込み失敗を避けるために、サンドボックス ファイルを書き込む前に親ディレクトリを自動的に作成します。
  6. 古いワークフロー データやツール パラメーターなどの互換性の問題を最適化します。
  7. エージェントの質問 UI。

🐛 修正

  1. OpenSandbox リソースが停止後に正常に解放または再利用されない問題を修正しました。
  2. エージェント サンドボックスの作成、復元、またはランタイム アップグレード中の状態競合と重複操作の問題を修正します。
  3. 親ディレクトリが存在しないために、サンドボックスがネストされたディレクトリにファイルを書き込むことができない問題を修正しました。
  4. エージェント生成と手動入力を切り替えると、数値入力が通常のテキストボックスになってしまう問題を修正しました。
  5. 文字列テキスト入力がドロップダウン選択として誤ってレンダリングされる問題を修正しました。
  6. JSON Editor がワークフロー ツールの設定に誤って追加される問題を修正しました。
  7. エージェント/ワークフロー ツール インターフェイスにツール実行エラーが誤って表示される問題を修正しました。
  8. システムツールリストでアンインストールされたツールが表示される問題を修正しました。
  9. エージェント/エージェント V2 のデフォルトのバージョン選択ロジックを修正し、デフォルトで最新バージョンが選択されるようにしました。
  10. S3 ファイルにスペースがある場合、ファイル内の画像を解析するときにキー例外により 404 エラーが発生します。
  11. MCP SSE モード、ヘッダーが繰り返されます。
  12. Agent V2 システム ツール キーは暗号化されません。

🛠️ コードの最適化

  1. サンドボックス アダプターはライフ サイクル、ファイル システム、コマンド実行、プロバイダー コントラクトごとに再分割され、E2B アダプターは削除されます。
  2. エージェント サンドボックス プロキシと IDE エージェントは、ワークスペースの直接接続のプレビュー、範囲リクエスト、パス エスケープ保護、およびセッション認証を追加します。
  3. ワークフロースキーマの最適化、統合されたツール呼び出しとフォームレンダリング。
  4. より多くのデータ型をサポートするための拡張ツール JSON スキーマ。
  5. 統合サービス ファイルの読み取りタイムアウト。
  6. システムツールのマルチプロセス権限のセキュリティ問題を最適化します。
  7. ログインと認証コードをリファクタリングします。
  8. 電流制限モジュールを再構築します。
