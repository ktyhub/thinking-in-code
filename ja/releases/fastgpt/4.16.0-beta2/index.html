FastGPT v4.16.0-beta2

#FastGPT v4.16.0-beta2

📦 アップグレード ガイド

1. クリーンな履歴システム モデル構成

このバージョンでは、システム モデルの初期化および保存時に厳密なスキーマの使用が開始されます。数値文字列、文字列形式の価格勾配、または以前のバージョンで保存されたフィールドが欠落していると、初期検証が失敗する可能性があります。アップグレード後、最初にドライランを実行して、処理する必要があるモデル構成を表示してください。ドライランではデータの変更やキャッシュの更新は行われません。

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

invalidSamples に手動処理が必要なデータがないことを確認した後、正式なクリーニングを実行します。

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

クリーニングでは、正当な数値文字列が数値に変換され、priceTiers が文字列として配列に変換され、不正なオプションの数値が削除されます。必須の数値が不正または不足している場合は、システムのデフォルト値が使用されます。LLM の maxContext/maxResponse/quoteMaxToken は 16000/16000/13000、埋め込みの defaultToken/maxToken は 500/3000、価格は 0 です。 functionCall はオプションのままで、埋め込みで欠落している weight は 0 に置き換えられます。

正式な実行では、データが均一に書き込まれ、システム モデル キャッシュが即座に更新されます。更新するレコードがない場合でも、ランタイム キャッシュは再構築されます。このインターフェイスは安全に再実行できます。再度予行運転すると、wouldUpdate は 0 になるはずです。現在の完全なモデル スキーマを通過できないレコードは書き込まれず、詳細はすべて invalidSamples で返されます。

🚀 新しいコンテンツ

  1. ワークフロー アプリケーションのシステム構成は、キャンバスの左側のツールバーの独立した構成パネルに移動されます。このパネルは、新しいワークフロー アプリケーションを作成するときに自動的に開きます。
  2. 冒頭のステートメントは、複数のプリセット質問の独立した構成をサポートしており、ドラッグ アンド ドロップで並べ替えることができます。

⚙️ 最適化

  1. リリース チャネル ページを再構成し、ネイティブ チャネルとサードパーティ チャネルごとにグループで表示し、各チャネルの構成数量を表示します。
  2. ツールマーケットのバッチアップデートは、失敗した項目の表示、個別の再試行またはアンインストールをサポートし、インストールされているバージョンとアップデートステータスの表示を改善します。
  3. ポータルページのクイックアプリケーション数の上限が3に調整され、上限を超えた過去の構成も互換になります。
  4. PDF パーサーは、実際のコンテンツの切り抜きを避けるために、固定エッジ トリミングではなく動的エッジ トリミングを使用します。

🐛 修正

  1. 旧バージョンのワークフローHTTPツールの動的パラメータがデフォルトの入力メソッドを正しく復元しない問題を修正しました。
  2. ワークフローアプリケーションを新規作成する際、国際リソースがプリロードされず、初期設定のコピーが異常となる問題を修正しました。
  3. ワークフローツールのパラメータが繰り返し表示される場合がある問題を修正しました。
  4. アプリケーションリリース後、ファイル変数でファイルをアップロードできない問題を修正しました。
  5. 共有ワークフローツールのファイルパラメータでファイルをアップロードできない問題を修正しました。
  6. スペース、%、#、?、スラッシュなどの特殊文字を含む S3 オブジェクト キーとファイル名により、アップロード、解析、プレビュー、またはダウンロードが異常になる可能性がある問題を修正しました。
  7. システム初期化インターフェイスの応答がモデル API キー、要求アドレス、および内部構成を返すのを避けるために、システムのデフォルト モデルが機密情報をフィルタリングしないという問題を修正します。

🛠️ コードの最適化

  1. 監査ログ アーカイブは削除されなくなりますが、S3 コールド アーカイブに転送されます。
  2. 管理構成にデータの検証とクリーニングを追加します。
  3. アカウント/* ページ SSR をキャンセルします。
