#FastGPT v4.17.0

アップグレード手順

**V4.17.0 にアップグレードする前に、まず V4.16.2 にアップグレードし、V4.16.x バージョンで必要な古いアップグレード スクリプトをすべて実行してください。 ** V4.17.0 の自動アップグレード メカニズムは、このバージョン以降に登録された新しいタスクのみを管理し、以前のバージョンの履歴スクリプトは再実行しません。

バージョン 4.17.0 以降、システム アップグレード メカニズムに登録されたタスクは自動的に実行され、リース プリエンプションによってマルチノードの同時実行の問題が回避されます。スクリプトがアクティブかどうかを確認するためのハートビート検出もサポートされています。アップグレード スクリプトのステータスは 管理员 > 版本升级 で確認できます。

デフォルトでは、バッチ移行タスクはバッチごとに 100 レコードを処理します。データ量が多い場合は50～1000～SYSTEM_MIGRATION_BATCH_SIZEまで調整可能です。

AI プロキシ (必須)

V4.17.0 以降、AI プロキシをデプロイまたは接続し、FastGPT アプリとアプリ/サービス構成を再利用する商用バージョンの管理サービスで設定する必要があります。

  • AIPROXY_API_ENDPOINT: アクセス可能な AI プロキシ サービスのルート アドレス (http://aiproxy:3000 など) には、/v1 が付加されません。
  • AIPROXY_API_TOKEN: AI プロキシ サーバー構成と一致する空ではない管理者トークン。

**V4.17.0 以降、OPENAI_BASE_URL および CHAT_API_KEY は非推奨となり削除され、構成後は無効になります。 ** これら 2 つの変数をデプロイメント環境から削除し、代わりに上記の AI プロキシ構成を使用し、管理者のモデル チャネルでモデル サービサーのアドレスとキーを維持してください。古い systemEnv.oneapiUrl/chatApiKey オーバーライド構成も機能しなくなります。

AI プロキシ構成が不足していると起動検証が失敗するため、単一モデルの requestUrl/requestAuth ではこれら 2 つの必須アイテムを置き換えることができません。アップグレードする前に、AI プロキシがアクセス可能であり、管理者トークンがチャネル管理インターフェイスにアクセスできることを確認してください。モデル サービス プロバイダーの API キーを AI プロキシ管理者トークンとして使用しないでください。

CSRF 防御

このバージョンでは、環境変数を使用して HTML タグを防御する新しい CSRF ツールが追加されています。

CSRF_ENABLED=true

コードサンドボックス seccomp 互換構成 (オプション)

Code Sandbox は引き続きデフォルトで seccomp を有効にします。ホスト カーネルがアプリケーション内 seccomp をサポートしていない場合、プロセス プールの初期化は失敗します。削減されたシステム コール分離機能が許容できることを確認した後、それをコード サンドボックスに明示的に設定できます。

SANDBOX_DISABLE_SECCOMP=true

この構成では、seccomp、chroot、no_new_privs のみがオフになり、UID/GID の剥奪は有効のままになります。終了後は、ネットワーク、プロセス、スレッドの作成、バイナリ実行などのシステム コールがカーネル層からブロックされなくなります。 seccompをサポートする環境での使用は推奨されません。

新しいチームのデフォルトの作成権限 (オプション)

DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED=true のセットアップ後、新しいチームを作成すると、デフォルトの全従業員グループにアプリケーション、スキル、およびナレッジ ベースの作成権限が付与されます。デフォルト値は false で、新しいチームにのみ影響し、既存のチームの権限は変更されません。 FastGPT Pro エンタープライズ WeChat 認定チーム構築を含む、それぞれのチーム作成の入り口をカバーするために、FastGPT サービスと管理サービスでこの構成の一貫性を保ってください。

非推奨の指示

モデルのカスタム リクエスト アドレス

モデルのカスタム リクエスト アドレスは、将来のバージョンでは非推奨になる予定です。現在のバージョンでも互換性があります。モデル管理用のチャンネルに変更してください。

🚀 新しいコンテンツ

  1. FastGPT SSO サービスは、組織構造と同期するために新しい LDAP メンバーを追加し、さまざまな SSO プロバイダーの独立した環境変数テンプレートと構成ドキュメントを補足します。
  2. FastGPT SSO サービスは、新しい DingTalk ユーザーを追加し、部門を同期します。
  3. ワークフロー ツールのファイル アップロード フィールドは、エージェントによって生成される設定をサポートします。履歴ファイル フィールドは、アップグレード後の動作の変更を避けるために、デフォルトで手動アップロードを維持します。
  4. 自動システム アップグレード タスク管理が追加されました。これにより、アップグレード ステータス、ステージの進行状況、失敗データと実行結果を表示し、失敗した非ブロッキング タスクを再試行できます。
  5. エージェント V2 は、クローズド ブロードキャスト、ブラウザ ブロードキャスト、またはモデル ブロードキャストをサポートする新しい音声ブロードキャスト (TTS) 構成を追加し、音色の選択、話速の調整、試聴が可能です。設定スタイルは Chat Agent と一致しています。 6.最初のトークン応答時間は、AI対話ノードの応答詳細に追加され、モデルリクエストの開始から最初のテキストまたは思考コンテンツの受信までにかかった時間を測定します。
  6. チームオーナーの移行がマルチチームモードに拡張され、新しいオーナーとしてのチームメンバーの選択をサポートし、入力確認による誤操作のリスクが軽減されます。
  7. 外部システム (特に HTML タグ) が Cookie を運び、インターフェースを直接要求することを防ぐ CSRF 防御。

⚙️ 最適化

  1. 会話の一時停止エクスペリエンスを最適化します。一時停止リクエストは、ワークフローの停止マークを書き込んだ直後に戻ります。クライアントは確認を受信すると、現在のストリーミング要求を積極的に中断し、最大 5 秒間待機する必要がなくなります。
  2. 一時停止後のコンテンツ保持を最適化します。モデルは思考コンテンツのみを出力し、テキストが生成されていない場合は一時停止します。また、既存の思考コンテンツも保持され、更新後も表示できます。
  3. 画像の引用符の表示を最適化します。画像の後に引用符のみが含まれている場合、引用符は画像の下の中央に表示されます。テキスト内のインライン引用符は元のレイアウトを維持します。
  4. 生成競合回復の最適化: 現在の会話がまだサーバー上で生成されている場合、クライアントは競合を特定し、元の生成フローを復元して、空のメッセージやエラー状態の追加を回避します。
  5. 処理中のコンテンツのインタラクションを最適化します。思考またはツール呼び出しの折りたたまれたプレビューは、クリックして展開し、対応する詳細を直接見つけることができます。
  6. 統合ワークベンチのアプリ、スキル、データセット、テンプレート マーケット、ツール、アカウントの使用状況、モデル ダッシュボード、API キー、監査ログ、およびアプリ ログ リストのフィルタリング インタラクション。タイプ、ソース、作成者、メンバー、カテゴリ、時間によるフィルタリングとページによる並べ替えを提供し、長いオプション リストでの検索をサポートします。
  7. アプリ、スキル、データセットのリストには、作成者や作成時間による並べ替えなどのフィルタリング機能が追加されました。過去のアプリとデータセットの作成は、システム アップグレード タスクによって自動的に完了します。
  8. テーブルの複数選択、日付範囲、数値入力、長いリストのスクロール、ポップアップ ウィンドウなどの基本的な操作を統合し、バッチ操作や長いコンテンツの表示のエクスペリエンスを向上させます。
  9. アプリ、データセット、スキルのリストと関連リソース セレクターがページ読み込みに変更され、仮想スクロール、読み込みスケルトン画面、フォルダー ナビゲーションが最適化され、多数のリソースが使用される場合の読み込みと閲覧エクスペリエンスが向上します。
  10. 使用シナリオに応じて、モデルの概要、詳細、および候補リストがロードされます。セレクターを展開すると候補モデルが読み込まれ、読み込み、読み込み失敗、モデル使用不可状態が区別されます。
  11. 統合されたツール記述ロジック: ツール ノードとツール セットのサブツールは、ツール呼び出しの記述としてノードの紹介を使用します。ツールセットのサブツールは、説明の直接編集をサポートし、ツール定義の同期時に上書きされないように履歴のカスタマイズまたはアクティブな消去コンテンツを保持します。
  12. テーブル コンポーネントは、ヘッダーとコンテンツの個別のスクロールをサポートし、仮想スクロールもサポートします。

🐛 修正

  1. アカウントキャンセル確認ポップアップウィンドウの下部のスペースの問題と長文が正しく折り返されない問題を修正し、アカウントキャンセルメールのテンプレートを最適化しました。
  2. 同時実行性に影響を与える接続数の少なさや、リソースの圧迫を引き起こす過剰な構成を避けるために、DB_MAX_LINK を 10 ～ 1000 に制限します。公式の展開テンプレートはデフォルトで 20 を使用します。
  3. チーム プラグインのインストールがオフになった後も、一部のアップロード、URL インストール、およびインストール確認インターフェイスが機能スイッチをバイパスできる問題を修正しました。
  4. XLSX XML スキャンを無効にした後もファイルがスキャンされ続ける可能性がある問題を修正しました。
  5. HTTP/OpenAPIツール入力項目の「手動入力/エージェント生成」モードが保存後に失われ、エージェントツールまたはサブワークフローとして実行すると誤ってリセットされる問題を修正しました。
  6. モデル選択でモデルタイプが厳密に区別されない、モデルの最高温度が空白のままだと検証が失敗する、管理者モデルディレクトリとメンバー利用可能モデルリストの順序が矛盾する問題を修正しました。同時に、サービスの開始フェーズ中にまだ有効なメンバー モデルのキャッシュを誤ってクリアすることを回避します。
  7. FastGPT Pro は、Feishu、Enterprise WeChat、DingTalk、WeChat 公式アカウントなどの公開チャネルを通じて受信した不正なメッセージを調整して、明確なクライアント エラーを返し、リクエスト形式の問題がサーバー障害として誤って報告されるのを防ぎます。
  8. FastGPT Pro は、履歴チーム メンバーの role フィールドが現在の権限計算を上書きする可能性がある問題を修正します。チーム所有者を除いて、放棄されたロール値は権限の決定に参加しなくなりました。
  9. シンプルなアプリケーションと対話エージェントの非表示のマルチモーダル構成により、画像、音声、またはビデオがモデル リクエストに含まれない問題を修正しました。ワークフロー内の明示的なマルチモーダル スイッチを使用したモデル切り替えエントリは、新しいモデルでサポートされていないオプションを一律にクリアし、スイッチバック後に自動的に復元されません。
  10. 同じ名前、エクスチェンジ、またはチェーン マッピングでモデル リクエスト フィールドをマッピングするときに上書きエラーが発生する問題を修正しました。マッピングでは、モデルの機能によって正規化およびフィルター処理されたリクエスト データが使用され、ターゲット フィールドが繰り返されると、明らかにエラーが報告されます。
  11. MCP/HTTP ツール定義の有効期限またはワークフロー スナップショットとのストレージの非互換性の問題を修正しました。ツール定義は実行時に読み取られ、過去のツール構成および認証情報と互換性があります。
  12. OpenAPI インポート ツールがインターフェイス定義に従ってパラメータを送信しなかった問題を修正しました。元のテキストに従ってパラメータをパス、クエリ、ヘッダー、および JSON ボディに割り当て、パスレベルの共有パラメータをサポートし、style / explode に従って配列と浅いオブジェクトをシリアル化し、重複したクエリ パラメータ名と元のデータ型を JSON ボディに保持します。
  13. OpenAPI 定義ブロック要求でオプションの Cookie パラメーターが渡されない問題を修正しました。必須パラメータが欠落している場合、実際には渡されるがサポートされていない Cookie がある場合、またはサポートされていないパラメータ エンコーディングがある場合でも、明確にエラーが報告されます。
  14. ToolCall がサブワークフローのストリーミング出力を一律にオフにし、子ノードの設定が有効にならない問題を修正しました。サブワークフローは親プロセスのストリーミング機能を継承し、独自のフロー禁止設定に従います。また、単純なアプリケーションによって生成された子アプリケーションとワークフロー ツール ノードは引き続き強制的にフローを禁止します。
  15. モデルの非同期ロードにより、ユーザーの選択が上書きされ、アンロードされたモデルが使用できないと誤判断され、エディターが構成を復元するときに誤ってデフォルトのモデルが入力される可能性がある問題を修正しました。
  16. ワークフローのリリース時に、クローズド再配置、質問の最適化、質問したいことの推測、およびモデルのレポート機能が引き続きモデルを検証する問題を修正しました。有効なオプション関数は、モデルが空の場合にのみデフォルト値を入力し、無効な空でないモデル参照は引き続きエラーを明確に報告します。
  17. 古いデータを読み取る際の検証エラーを回避するために、歴史的なチーム メンバーの名前が欠落しており、アプリケーション questionGuide が null であり、ナレッジ ベース モデル参照が空である状況と互換性があります。
  18. ノード間隔が狭い場合にワークフロー接続の角丸やパスが異常に表示される問題と、サイトアイコンが/に設定されている場合にデフォルトアイコンが使用されない問題を修正しました。
  19. プラグイン ワークフロー テンプレートのアバターは、アドレスが書き換えられた後に正しく表示されないように、プラグインによって返された元の URL を保持します。
  20. HTML テーブルを Markdown に変換するときに、ヘッダー列の数がデータ行の数より少なく、一部の列が表示されない問題を修正しました。テーブルヘッダーは変換中に自動的に入力され、テーブルの完全な内容が保持されます。

🛠️ コードの最適化

  1. システム モデル、モデル権限、およびビジネス構成は安定した modelId リファレンスを使用し、自動アップグレード タスクを通じて古いモデル名のリファレンスと互換性があります。
  2. 自動アップグレード タスクは、MongoDB リース、ID 分離およびハートビートの実行を通じて、マルチノード相互排除と障害引き継ぎを実現します。ビッグ データ タスクはバッチ ブレークポイントの継続をサポートします。
  3. コラボレーターのクエリ インターフェイスは、オンデマンドでチーム メンバーのログイン ユーザー名を返すことができ、バッチ クエリによるメンバーごとのリクエストを回避できます。
  4. FastGPT Pro は、クラスター イメージのビルド キャッシュを最適化し、プロキシ キャッシュとキャッシュされたランナーを使用して、繰り返しのプルとビルドのオーバーヘッドを削減します。
  5. デプロイメントスクリプトのアクセスアドレスとホストポート設定の間の混同を修正しました。リバース プロキシのパブリック ネットワーク ポートの誤用を避けるために、FastGPT とサンドボックス プロキシのホスト ポートの独立した構成をサポートしています。
  6. JS または Python コードの実行が失敗すると、コード サンドボックスは例外スタック、例外チェーン、およびキャプチャされたコンソール/印刷出力を返し、警告レベルの応答ログに記録します。エラーの詳細と出力はそれぞれ 16K 文字に制限されており、制限を超えると切り捨てが明示的にマークされます。ワーカーの応答が解析に失敗した場合、ワーカー ID、応答の長さ、およびキャプチャされた標準エラー出力が補足されます。プロセスが強制終了されると、まだ送信されていない出力が失われる可能性があります。
