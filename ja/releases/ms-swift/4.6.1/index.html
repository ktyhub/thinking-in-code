ms-swift v4.6.1

#v4.6.1

新しいモデル

  • NVIDIA-Nemotron-3.5-Super-VL-120B-A12B(#10377)
  • NVIDIA-Nemotron-3.5-Transcribe-30B-A4B(#10458)
  • 無制限-OCR-2(#10448)
  • MiniCPM-OCR-1.0(#10414)
  • オルモ-3-7B-シンク(#10371)
  • フリント(#10482)
  • 埋め込みジェマ-2(#10392)
  • Decision / System-1 ファミリ: THX-02 (#10398)、kev-0.8b/4b/9b (#10407)、laya (#10445) および [StartLux-Decision-v1.1] 4B/9B/27B-AutoThink](https://modelscope.cn/models/StartLuxAI/StartLux-Decision-v1.1-27B-AutoThink) (#10479)。

意思決定タスク (型付き決定 / JEV ファミリー)

  • テンプレート、アライメント テスト、examples/train/decision/*.sh レシピを備えた 4 つの新しいデシジョン ヘッド: THX-02 (#10398)、jaredpalmer/kev-* ポインター ヘッド (#10407)、Laya (#10445)、および StartLux (#10479)。
  • スループット: Clef/Kev 得点ヘッドのバッチ全体転送 (#10551) および Kev の複数質問転送 (#10494)。
  • 正確性とキャリブレーション: 2 段階の JEV 温度キャリブレーション コールバック (#10399)、確実に間違っている予測のために保存される勾配 (#10355)、テキストのみのデータを含むマルチモーダル基本モード (#10420)、ヘッド モジュール ツリーから除外される注入された出力埋め込み (#10540)。
  • THX-02 固有のパッキング チェックは、ModelMeta の汎用 support_padding_free フラグに置き換えられました (#10480)。
  • docs/*/BestPractices/Decision.md はファミリーのエントリーポイントとして書き直されました。

新機能と互換性

  • 新しいベスト プラクティス ドキュメント (Flexble-Quantization-With-Entropack.md) および examples/train/qlora/entropack.sh を使用した、QLoRA スタイルのトレーニング用の Entropack 柔軟な量子化。 (#10415)
  • Megatron 並列引数プリフライト: プロセス グループの初期化の前に、Swift 引数エントリ ポイントで TP/PP/CP/EP/ETP の可分性がチェックされ、対処可能なエラー メッセージが表示されます。トランスフォーマーのバックエンドとメガトロンのエクスポート パスは変更されません。 (#10393)
  • Gemma 4: Megatron バックエンド上のテキストのみのデータのパッキング / padding_free。 (#10542)
  • Huawei Ascend: Megatron トレーニングは、MegatronAdaptor + TENPU を備えた Megatron-Core 0.18 に移行されました (#10087)。スタンドアロン環境チェック スクリプト examples/ascend/check_env.py (#10390)。

メガトロン-SWIFT および MTP

  • --mtp_num_layers はデフォルトで auto になり、モデル チェックポイントに従います。 --mtp_shared_weights は、デフォルトで自動検出になります (チェックポイントに保持される MTP レイヤが構成された深さよりも少ない場合に有効になります)。 MTP を出荷しない基本モデルに MTP を追加するには、--mtp_num_layers N --mtp_allow_random_init true を設定します。 (#10416、mcore-bridge >= 1.7.0 が必要)
  • 最新の Megatron 開発ブランチに対して非同期チェックポイントのインポートが修正されました。 (#10421)

パフォーマンス

  • selective_log_softmax はトークンごとにループするのではなく、チャンク化されました。 (#10337)
  • SFT でのカスタムおよびチャンク化されたクロスエントロピー作業を削減しました。 (#10353)
  • Megatron トレーニングにおける NPU 勾配、RMSNorm、および MoE 順列オーバーヘッドの低減。 (#10513)

セキュリティ

  • チェックポイントの args.json で宣言された external_plugins は、再開時にサイレントに復元されなくなりました。 (#10422)
  • チェックポイント エンジンでの ZMQ 制御メッセージの HMAC 認証。HCCL トランスポートと NCCL トランスポートの両方をカバーするために抽象化されています。 (#10373、#10381)
  • load_file は、ローカル メディア パスを開く前に SafeMediaPath を適用するようになりました。そのため、テンプレート画像/オーディオの読み込みで SWIFT_MEDIA_ALLOWED_DIRS をバイパスできなくなりました。 (#10370)

バグ修正

  • RL: 非同期サーバーのロールアウト中に SP 状態が保存されました (#10426)。ロールアウト レコードの収集/キャッシュによる GRPO ログ (#10427);ライガー負けでoverlong_filterが表彰される(#10404)。ポリシーの勾配は動的チャンク全体で保持されます (#10397)。マルチモーダルな Liger 損失 (#10411) で再利用された前方フック出力。長さの報酬は設定された最大値 (#10500) を超えると飽和します。 PPO コールバック (#9872);サーバーモードロールアウトは、max_length / truncation_strategy をエンジンに出荷し、トレーニングテンプレートに対して検証するため、プロンプトの切り捨てがエンジンの事前入力と一致するようになりました (#10549)。
  • アライメント損失: DPO でのアルファダイバージェンス オーバーフロー (#10394)、安定化した DiscoPOP 変調指数関数 (#10313)、損失に対してローカルに保たれた EXO スムージング (#10323)、評価中に変更されない BCO 実行統計 (#10321)、MuonClip Nesterov 更新順序 (#10341)。
  • テンプレート / エージェント: ツール スキーマを含むエージェント テンプレート (#10522)、エージェント形式全体でツール結果の後に受け入れられるユーザー ターン (#10523)、ユーザー フォローアップを追加するときに各ターンが終了する (#10524)、GLM-5-Next テンプレート (#10509)、引用符または改行を含む Gemma 4 ツール呼び出し引数 (#10456)、白に合成された透明な画像load_image (#10345)。
  • データとメトリクス: 再開履歴に依存しない遅延データセット フォールバック (#10375)、ローカルに保持される分散平均アキュムレータ (#10326)、ラウンドロビン リスト分割で保持されるアイテム (#10324)、トレーニング ログから保持される numpy スカラー (#10474)。
  • インフラ: 構成のロード時に vLLM の AutoConfig オーバーライドがバイパスされ (#10503)、最終 GPTQ チェックポイント形式がエクスポート後に保持され (#10425)、NPU RNG 状態が CUDA/MUSA と一緒にチェックポイントされ (#10406)、SP データローダーと num_input_tokens アカウンティングが調整されました (#10508)。
  • ドキュメント: Megatron-Core / mcore-bridge のバージョン要件を調整 (#10526)、Qwen3.8-Flash-Next パラメーターのアカウンティングを修正 (#10428)、NPU の名前を「Huawei Ascend NPU」に統一 (#10496)、NPU ガイドを更新 (#10356)。

環境の変化

megatron-core >= 0.18 (以前は >= 0.16). (#10481、#10087)

deepspeed >= 0.19.3,< 0.20 (以前は < 0.19)。

transformers < 5.23 (以前は < 5.20). (#10453)

mcore-bridge >= 1.7.0 (以前は >=1.6.5). (#10416)

破壊的な動作の変更

MTP 重みはデフォルトでロードされます。 --mtp_num_layers のデフォルトは None ではなく auto になり、--mtp_shared_weights のデフォルトは False ではなく自動 (None) になります。したがって、MTP レイヤーを配布するチェックポイントは、MTP レイヤーをトレーニングします。 4.6.0 の動作を維持するには、--mtp_num_layers 0 --mtp_shared_weights false を渡します (両方の設定が必要です。そうしないと、反復 MTP 重みを宣言するチェックポイントが mtp_shared_weights=True を解決し、mtp_num_layers > 0 チェックに失敗します)。 MTP を持たないベース チェックポイントに MTP を追加するには、--mtp_num_layers N --mtp_allow_random_init true (#10416) を設定します。

チェックポイントで宣言されたプラグインは復元されなくなりました。 チェックポイントの args.json で見つかった external_plugins は再開時に無視されます。 --external_plugins に依存する場合は、明示的に --external_plugins を渡します (#10422、セキュリティ修正)。
