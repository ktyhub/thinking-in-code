mempalace v3.3.3

パッチ 公開日2026年4月24日 出典MemPalace/mempalace 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#メンパレスv3.3.3

バグ修正

  • インストールのリグレッション — mempalace-mcp コンソール スクリプトは、.claude-plugin/plugin.json の参照とともに pyproject.toml で宣言されるようになりました。 v3.3.2 では、この 2 つは離れていました (plugin.json は、一致するエントリ ポイントが到着する前に新しい "command": "mempalace-mcp" フォームを出荷しました)。そのため、新しい pip install mempalace==3.3.2 はすべて、インストールされていないバイナリを指すクロード コード プラグイン構成を生成しました。 (#1093、#340)
  • クロード コード 2.1.114 client 回帰後にサイレント セーブの可視性を復元します。この PR まで、実稼働トランスクリプトの保存はサイレントに失敗していました。 (#1021)
  • status パスのメタデータ フェッチのページネーションを行うことで、大規模な宮殿が SQLite の変数制限に引っかからないようにします。 (#851)
  • プラットフォーム/プラグインディレクトリのバリエーション全体にわたる Claude プラグイン フック ランナーを解決します。以前は Windows と一部の macOS レイアウトで問題が発生していました。 (#942)
  • MEMPAL_PYTHON オーバーライド パスを使用した .sh フックの実際の python3 解決。 (#833)
  • オプションの wing パラメーターを tool_diary_write / tool_diary_read に追加し、停止フックから書き込むときにクロード コードのトランスクリプト パスからプロジェクトごとのウィングを派生します。異なるプロジェクトからの日記エントリが、共有のデフォルト ウィングに折りたたまれなくなりました。 (#659)
  • mempalace_search wing/room では空の文字列を「フィルターなし」として扱います。すべてのオプション パラメータをデフォルトで "" で埋める LLM エージェントは、must be a non-empty string でバウンスされなくなりました。 (#1097、#1084)
  • _wing_from_transcript_path を拡張して、-Projects- セグメントのないクロード コード プロジェクト フォルダー (例: ~/dev/<parent>/<project>、~/code/<project>) を処理します。プロジェクト名は、エンコードされたフォルダーの最後のダッシュ区切りのトークンから派生するようになりました。そのため、~/Projects/ 以外のコードを持つ Linux ユーザーは、wing_sessions に陥るのではなく、プロジェクトごとの日記のスコープを取得します。 (#1145、#659 のフォローアップ)
  • mempalace_diary_read(wing="") は、#1097「フィルタなしの空文字列」パターンに一致する、このエージェントが書き込んだすべてのウィングからの日記エントリを返すようになりました。以前のデフォルトは wing_<agent> で、フックがプロジェクト派生のウィングに書き込んだエントリをサイロ化していました。 (#1145)
  • mempalace mine は生成された entities.json ファイルをスキップするようになり、その内容がプロジェクト コンテンツとして再取り込まれなくなります。 (#1175)

改善点

  • 確定的なフックの保存。 保存フックはサイレント Python API パスを使用するようになりました。そのため、連続したフックの呼び出しにより再現可能な結果が得られ、ホット パス上でデータ損失が発生しません。 (#673)
  • build_graph() 内の 書き込み無効化を備えたグラフ キャッシュ — ウォーム パス呼び出しはリクエストごとにパレス グラフを再構築しなくなりました。 (#661)
  • mempalace init エンティティ検出のオーバーホール。 正規プロジェクト名は、散文から推測されるのではなく、パッケージ マニフェスト (package.json、pyproject.toml、Cargo.toml、go.mod) から取得され、実際の名前は git commit 作成者から取得されます。名前/電子メール エイリアスにわたるユニオン検索による重複排除、@users.noreply.github.com の人間を維持するボット フィルタリング、貢献シェアによる自動「地雷」フラグ設定が含まれます。 (#1148)
  • 正規表現検出器の精度。 CamelCase 抽出により、MemPalace、ChromaDB、OpenAI が断片化されません。より厳密なバージョン管理/ハイフン付きパターンにより、context-manager / multi-word の誤検知が排除されます。ダイアログ ^NAME:\s には 2 件以上のヒットが必要なので、Created: <date> メタデータはフィールド名を人物として分類しなくなります。一般的な英語の分詞と記述子の拡張ストップワード。代名詞の高い信号は、不確実なものにダンプするのではなく、人物として分類します。 (#1148)
  • 初期化→マイナーのワイヤアップ。 確認されたエンティティは初期化時に ~/.mempalace/known_entities.json にマージされ、マイナーはエンティティ フィルター検索用のタグ ドロワー メタデータに読み取ります。以前は、init の出力はマイナーによって消費されませんでした。プロジェクトごとの entities.json が監査証跡として保存されます。 (#1157)
  • 大文字と小文字を区別しないプロジェクトの重複除去 をマニフェスト、git、および convo ソース間で行うため、同じプロジェクト名の大文字と小文字の区別が 1 つのレビュー エントリにまとめられます。 (#1175)

追加

  • i18n: ベラルーシ語の翻訳。 (#1051)
  • i18n: ドイツ語、スペイン語、およびフランス語のロケールのエンティティ検出。 (#1001)
  • i18n: 繁体字 + 簡体字中国語エンティティ検出。 (#945)
  • mempalace init --llm: オプションの LLM 支援エンティティ分類。デフォルトはローカル Ollama (ゼロ API) です。また、OpenAI 互換エンドポイント (LM Studio、llama.cpp サーバー、vLLM、OpenRouter など) および Anthropic Messages API もサポートします。進行状況インジケーターを使用して対話的に実行します。 Ctrl-C を押すと完全にキャンセルされ、部分的な結果が返されます。正規表現検出が困難な散文の多いフォルダー (日記、トランスクリプト、研究ノート) に役立ちます。オプトインのみ — デフォルトの初期パスはゼロ API のままです。 (#1150)
  • クロード コード会話スキャナ ~/.claude/projects/<slug>/ ディレクトリは、各セッションの信頼できる cwd メタデータを使用してプロジェクト エンティティを提供するようになり、スラッグ デコードの曖昧さを回避します。 (#1150)

既知 — v3.3.4 に延期

  • コレクション作成時に hnsw:num_threads が設定されていない場合、HNSW は SIGSEGV を並列挿入します (#974) — 開発中は #976 として修正され、開発に対するリベースを待機します。

インストール

pip install --upgrade mempalace==3.3.3

過去のリリースについては、完全な changelog を参照してください。
