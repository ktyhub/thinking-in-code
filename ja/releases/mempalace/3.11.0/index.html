#メンパレスv3.11.0

宮殿はガイド付きの手順で監査および修復できるようになり、EmbeddingGemma 2 はネイティブの画像、音声、ビデオ検索を備えたオプトイン エンベッダーとして提供されます。すべての宮殿は、それを構築した埋め込みモデルを記録し、別のモデルで開くことを拒否します。会話マイニングは、テキスト、ステータス、検索、ウェイクアップの破棄を停止し、ハブ マイニングは大規模な宮殿でも応答性を維持します。また、3.11 レビューによる一連の正確性修正により、メタデータの更新、回復、HTTP 検証が強化されます。

アップグレードに関する注意事項

  • アップグレード後の最初の会話マイニングは、対象となる各会話ファイルを 1 回ずつ再マイニングします。 交換チャンカーはテキストを破棄しなくなりました (#2591)。そのため、3.11 より前にファイルされた会話ドロワーは古いものとしてカウントされ、ディスク上にまだあるトランスクリプトから再チャンクされて再埋め込まれます。ディスク上に存在しないトランスクリプトは引き出しを保持します。プロジェクト ファイルは再マイニングされません。ハードウェアに応じて、ドロワー 100 万個あたり約 40 分から 3 時間かかると予想されます。大規模なパレスでは、最初にバックアップし、静かな時間にバッチで実行します (例: mempalace mine <dir> --mode convos --limit 200)。中断された実行は停止した場所から再開されます。
  • 宮殿は、それを構築したモデルとは異なる埋め込みモデルで開くことを拒否します。 検索、マイニング、および MCP 書き込みは、修正名を示すメッセージで停止します。embedding_model (config.json または MEMPALACE_EMBEDDING_MODEL) を宮殿が構築されたモデルに戻すか、mempalace repair rebuild-index で再埋め込みします。記録されたモデルのないパレスは、設定されたモデルと mempalace palace set-embedder という名前の警告で開きます。 (#2694、#2717)
  • EntityRegistry.research() と confirm_research() は削除されました。 これらは、CLI、MCP サーバー、マイナー、またはフックの何も呼び出されない、オプトインのデフォルトでオフの Wikipedia ルックアップでした。 entities.json 内の既存の wiki_cache エントリは、引き続き lookup() によって読み取られます。 (GHSA-mrj5)

EmbeddingGemma 2 とエンベッダー ID

  • EmbeddingGemma 2 はオプトイン エンベッダーとして利用できます。 embedding_model: embeddinggemma2 を設定し、メディア (Python 3.10+、PyTorch) に mempalace[embeddinggemma2] または mempalace[multimodal] をインストールします。 CUDA (存在する場合)、Apple MPS、または CPU 上で実行され、768/512/256/128 次元をサポートします。 CUDA のメモリ不足エラーが発生すると、バッチが半分になり、再試行されます。 (#2694、#2717)
  • ネイティブ画像、オーディオ、およびビデオの取得。 組み込みの media ソース アダプターは、元のファイルを別の mempalace_assets コレクションに埋め込み、オプトインの CLI/MCP メディア検索は、一致するドロワーとともに入力されたローカル アセット参照を返します。ファイルレベルの取得は実験段階です。 (#2694)
  • オプトインしない限り、既存の宮殿は変更されません。 デフォルトの MiniLM パスは変更されず、何も再埋め込まれません。未知の embedding_model は MiniLM フォールバックを維持しますが、既知の名前のニアミスはサイレント フォールバックではなく拒否されます。 (#2717)
  • すべての宮殿は、どの埋め込み者がそれを構築したかを記録し、すべての書き込みパスは不一致で失敗して閉じられます。 CLI、MCP、私のもの、および repair は、記録された ID をチェックします。 repair rebuild-index および --mode from-sqlite は、検証された再構築後に再度記録します。新しい Qdrant と pgvector Palace がそれを記録しています。 MCP は Chroma のデフォルトのエンベダーに戻るのではなく、拒否します。 (#2717; #2709 を修正)

宮殿の監査とガイド付き修理

  • mempalace audit は、具体的な調査結果、--json 出力、および cron または CI の --fail-under を使用して、5 つのレイヤー (部屋、翼、トンネル、廊下、ナレッジ グラフ) にわたって宮殿がどの程度うまく組織されているかをスコアします。これは読み取り専用で、MCP サーバーがサービスを提供しているパレスに対して実行されます。 (#2576)
  • ガイド付き修復ツール: mempalace instructions audit は、エージェントとユーザーに調査結果を説明します。 rooms propose / apply は翼に密室セットを与えます。 wings split は、マシンレベルのトランスクリプトウィングをプロジェクトごとに 1 つのウィングに変換します。 tunnels propose / prune および hallways --rebuild / --prune-spellings はノイズの多いリンクをクリーンアップします。 kg normalize は、1 回限りの述語を閉じた語彙にマッピングします。 --yes まではすべて予行演習であり、中断された実行は再試行で終了します。 LLM でサポートされるステップはデフォルトでローカル エンドポイントになり、それ以外の場合は --accept-external-llm が必要です。 (#2576、#2655、#2656、#2657、#2664、#2668、#2669)
  • SQLite バックエンドでのメタデータのみの更新は最大 6000 倍高速です。そのため、大規模な宮殿での棟や部屋の移動は数秒で完了します。 (#2576)

3.11 レビューからの正確性の修正

  • メタデータ対応の更新と更新/挿入により、埋め込みに使用される入力が保護されます。 ドキュメントまたはメタデータの同時変更は公開前に拒否され、削除されたフィールドは埋め込みメタデータから省略されます。 (#2734)
  • ドロワー リストはメタデータとページ プレビューを 1 つの復元されたスナップショットに保持します。復元が保留されている間は Chroma にフォールバックします。 (#2734)
  • 部屋の回復では、変更を適用する前に破損したジャーナルが拒否されます。承認されたトンネルの提案は完全なスペル コンテキストを保持します。 (#2734)
  • 不正な形式の HTTP ツール名は、ディスパッチ中に失敗するのではなく、通常の JSON-RPC 検証エラーを返します。 (#2734)

パフォーマンスと大きな宮殿

  • 大規模なパレスでもステータス、検索、ウェイクアップの応答性は維持されます。 カウント キャッシュが使用前に期限切れになることはなくなり (360k ドロワー パレスでは 8 ～ 12 秒から約 1 ミリ秒に短縮)、MCP サーバーはほぼすべての呼び出しでベクトル インデックスのリロードを停止し、ウェイクアップは SQLite から最近のドロワーを読み取り、マイニングは 2 次ページングでパレスを再スキャンしなくなりました。 (#2593)
  • 非常に大規模な宮殿上の鉱山では、冗長な作業がはるかに少なくなります。また、HTTP ハブ上の鉱山では、ファイル間のキューに入れられたリクエストが処理されます。 (#2567、#2593、#2688、#2689、#2690、#2691)
  • **すでに行がある場合、日記読み取りと単一引き出しルックアップは SQLite から読み取ります。 (#2650)

バグ修正

  • 会話マイニングは、--- マークダウン ルールの後、最初のユーザー ターンの前、または短い交換でテキストを破棄しなくなりました。 (#2591)
  • mempalace_reconnect は実行中の鉱山では実行されなくなりました。 最大 10 秒待機してから MineInProgress を返し、一部のファイルに失敗した鉱山では MineFileErrors が発生して 1 が終了します。 (#2701、#2705)
  • インプロセス SQLite 読み取りにより Chroma のロックが維持されるため、ステータス、分類、BM25、整合性チェックで読み取りが中断されるリスクがなくなりました。 (#2506、#2573、#2652、#2658)
  • event_list および event_wait は、発信者が独自の from_agent を渡したため、別のエージェントのリクエストを非表示にしなくなりました。 (#2616)
  • ハブとデーモンのルートは --include-ignored と --include-subagents を保持し、 相対パス sweep / sync は呼び出し元のディレクトリに対して解決されます。 (#2582、#2583、#2584、#2733)
  • sync --apply は、マウントおよびバインド マウントの背後でまだディスク上にあるファイルのドロワーを削除しなくなりました。 (#2368、#2564)
  • stdio MCP サーバーは、解析不可能な回線やハブがなくなった場合でも稼働し続け、応答します。 (#2534、#2555、#2557)
  • また: mempalace.yml は init (#2699、#2704) によって受け入れられ、更新されます。 .al および .ps1 ソースがマイニングされます (#2702、#2706)。ケースのみの棟/部屋の名前変更が適用されます (#2426)。 KG 書き込みにはピアライター リースが必要なくなりました (#2423)。レガシー repair は宮殿の錠 (#2569) を保持しています。 EmbeddingGemma の q8 メモリ爆発は修正されました (#2693)。 DirectML セッションはシリアルに実行されます (#2687)。その他 — 以下の完全なリストをご覧ください。

セキュリティと依存関係

  • ChromaDB テレメトリは、沈黙するだけでなく、明示的に無効になります。サポートされている 1.x 回線では何も送信されませんでした。 (GHSA-8h77、#2524)
  • 未使用の Wikipedia ルックアップが削除されたため、local-first はデフォルトの引数ではなくコードのプロパティです。 (GHSA-mrj5、#2526、#2527)
  • Pillow 12.3.0、chromadb 1.5.9、およびルーチン ロック バンプ。 Pillow 12.3.0 には Python 3.10+ が必要であるため、Python 3.9 のインストールは Pillow 11.3.0 に留まり、これは 12.3.0 で修正された Pillow アドバイザリの影響を受けます。 SECURITY.md は Chroma HTTP サーバーを公開しないように警告するようになりました。 (#2719)
  • 読み取り専用 MCP ツールは annotations.readOnlyHint をアドバタイズするため、プラン モードと読み取り専用サブエージェントはホスト側の許可リストなしでメモリ検索を使用できます。 (#2610、#2640)

インストール/アップグレード

pip install --upgrade mempalace        # or: uv tool upgrade mempalace / pipx upgrade mempalace

オプションの EmbeddingGemma 2 およびメディア検索 (Python 3.10+): pip install -U "mempalace[embeddinggemma2]" または "mempalace[multimodal]"、その後、新しい宮殿に embedding_model: embeddinggemma2 を設定します。 docs/embeddinggemma2.mdを参照してください。

オプションのネイティブ正確ベクトル検索: mempalace_native_core ホイールとスタンドアロン mempalace-native 実行可能ファイルがこのリリースに付属しています (crates/README.md を参照)。

ご協力いただいた皆様に心より感謝申し上げます。このリリースには、79 個のマージされた PR が含まれています。内訳は 11 人の寄稿者からの 76 個で、そのうちの 3 個は初めてのもので、さらに 3 個の dependabot バンプが含まれています。
