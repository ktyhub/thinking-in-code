mempalace v3.7.1

#メンパレスv3.7.1

v3.7.1 — 鉱山の完全性、再接続の整合性、クリーンなシャットダウン

3.7.0 以降の整合性パッチ: 非正規ファイルで取り込みがハングしなくなり、不完全な鉱山が永久にスキップされる代わりに再試行可能になり、chromadb 再接続で HNSW インデックスが巻き戻されなくなり、MCP が SIGTERM/SIGHUP でライターのリースを解放します。

バグ修正

  • 取り込みコマンドが名前付きパイプでハングしなくなりました。 os.walk と glob は FIFO を通常のファイル名としてリストし、MemPalace はサフィックスから何を読み取るかを決定します。そのため、マイニングされたディレクトリ内の notes.md というパイプがカーネル内の mine に永遠に固定されます。読み取りのために FIFO を開くと、到着しないライターを待機することになり、次の行に書かれた S_ISREG 拒否が発生する可能性があります。決して走らないでください。 mine --mode convos、sweep、init、compress、split は、それぞれのリーダーを通じて同様にブロックされました。影響を受ける 4 つのオープンは O_NONBLOCK を通過するようになり、既存の型チェックに到達できるようになります (ライブ ライターの有無にかかわらず、パイプはそのモードで拒否されます)。また、ディスカバリー ウォークでは SKIP: <name> (not a regular file) 行を持つ非正規のエントリがドロップされるため、プレーンな open() を使用するリーダーには決して表示されません。通常のファイルはバイト同一で読み取られます。フラグが不活性でない 1 つのケースでは、リーダーが書き込みリースを解除し、ファイル タイプを再チェックし、ファイルをドロップするのではなく、ファイル タイプを使用せずに再試行します。 mine --mode extract は、ゼロ サイズ ゲートによってすでに免疫を受けていました。 (#2221)
  • Project re-mine は、部分ファイルまたは中断されたファイルをサイレントにスキップしなくなりました。 process_file の 4 つの関連ギャップ: (1) マルチバッチ更新/挿入により、すべてのドロワーに chunk_total がスタンプされるようになりました。これにより、file_already_mined は、「コミットされた N 個のうち N 個」と「バッチ 1 後にクラッシュした」を区別できるようになります。 (2) source_mtime は読み取られたコンテンツと同じ fstat に由来するため、読み取りとその後の再統計の間の追加では新しい末尾を永久に隠すことはできません。 (3) 古いドロワーのパージに失敗すると、ファイルが半分上書きされるのではなく中止されます。 (4) リマイニングが引き出しゼロで終了した場合でも、クローゼットはパージされます。ファイルの更新/挿入が途中で失敗すると、再起動する前にそのソースの部分的なドロワーとクローゼットも削除されるため、次のマイニングは不完全なセットを完全なものとして扱う代わりに再試行します。 (#2088、#2122、#2151)
  • 会話鉱山の完全性はプロジェクト パスと一致します。 会話引き出しには chunk_total のスタンプが付けられます。バッチの更新/挿入が途中で失敗すると、再起動する前にそのソースの部分的なドロワーが削除されます。 prefetch_mined_set は不完全なグループを省略するため、一括の「すでにファイルされた」スキップによって、中断されたトランスクリプト マイニングから失われた交換が永久に取り残されることはありません。 (#2183)
  • 古い chromadb システム キャッシュはパレス再接続時にクリアされます。 ピアまたは再構築によってディスク上の chroma.sqlite3 が変更された後、mcp_server._get_client と ChromaBackend._client の両方が、再度開く前に chromadb のパスキー付き SharedSystemClient キャッシュを削除します。そうしないと、古いメモリ内 HNSW セグメントが再利用され、ピアの書き込みに対して古いインデックスが保持される可能性があります (インデックス カウントが逆方向に進みます)。 (#2002、#2028、#2026、#2032)
  • MCP は、SIGTERM/SIGHUP でパレス ライター リースをリリースします。 リースは atexit 経由でのみリリースされ、CPython はこれらの信号のデフォルトの処理をスキップします。したがって、SSH 切断 (SIGHUP) とコンテナー/systemd 停止 (SIGTERM) は、競合他社の活性チェックによって再利用されるまで、デッド PID に名前を付けた mine_palace_*.lock を残します。 main() は、sys.exit を介して終了するハンドラーをインストールするようになりました。そのため、既存の atexit リリース パスが実行されます。 (#2205)
