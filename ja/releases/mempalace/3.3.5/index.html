mempalace v3.3.5

パッチ 公開日2026年5月10日 出典MemPalace/mempalace 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#メンパレスv3.3.5 3.3.5 は修正リリースです。 ユーザー向けの新しい機能はありません。このサイクルのエネルギーはデータの整合性、回復、およびクロスプロセスの正確さに注がれました。大きな鉱山の後で宮殿が Internal error: Error finding id に達したことがある場合、ナレッジ グラフ トリプルが音もなく虚空に消えた場合、または Windows またはマルチテナント ホストで実行している場合、このリリースはあなたのためのものです。 見出しの修正:

  • mempalace repair --mode from-sqlite は、apply_logs でスタックしたパレスを回復します。 ChromaDB の HNSW セグメント ライターがウェッジするとき (破損クラスはアップストリームと #1308 で報告されました)、--mode legacy とインライン修復は両方とも最初の読み取りとして Collection.count() を呼び出します。これはまさに呼び出される呼び出しです。古い障害モードは、SQLite テーブルが完全に損なわれていないにもかかわらず、Cannot recover — palace may need to be re-mined from source files を出力する修復でした。新しいモードは、メタデータ セグメント結合を介して chroma.sqlite3 から (id, document, metadata) を直接読み取り、破損したパレスに対して chromadb client を開くことはなく、構成された埋め込み関数の下ですべてを新しいパレスに再更新します。 52,300 行の現実世界の腐敗した宮殿でエンドツーエンドで検証されました。 (#1308)
  • ナレッジ グラフ内の 2 つのサイレント損失クラスが書き込み時エラーになりました。 valid_to < valid_from を含むトリプルは以前は永続的に保存されていましたが、到達できませんでした (時間フィルターは as_of に一致しませんでした)。 add_triple() は書き込み時に反転間隔を拒否するようになりました。また、SQLite に転送される日付文字列は、sanitize_iso_temporal() (エイリアス sanitize_iso_date()) によって事前に検証されます。これは、YYYY-MM-DD および標準 UTC 日付時刻 (YYYY-MM-DDTHH:MM:SSZ / +00:00) を受け入れ、その他すべてを拒否します。"yesterday" のような自然言語入力は、空の結果セットを黙って生成しなくなりました。 動作変更: 3.3.4 ("2026"、"2026-05") では機能していた部分日付入力がエラーになるようになりました。代わりに、完全な日付または正規の UTC 日時を渡します。 (#1214、#1164、#1167、#1374、#1417)
  • EntityRegistry.save() はクラッシュ セーフになりました。 人/プロジェクト マップは数か月分のマイニング データであり、古いコードは非アトミック Path.write_text() を実行していました。電源損失、OOM、またはトランケートとフルフラッシュの間の kill -9 が発生すると、黙ってマップが消去されます (レジストリの load() は JSONDecodeError を飲み込みます)。 「保存」により、兄弟一時ファイル fsyncs および os.replace()s が適切な場所に書き込まれます。以前のレジストリは、名前変更が戻る前にクラッシュしてもそのまま残ります。 (#1215)
  • MCP tool_search は、バルク マイニング後の HNSW フラッシュ ウィンドウを通過します。 CLI マイニングの後、ChromaDB の HNSW セグメント メタデータは約 30 ～ 60 秒間フラッシュされないことがあります。翼を対象とした MCP 検索は、そのウィンドウ全体で Internal error: Error finding id をヒットしていました。 tool_search はこの特定の過渡現象を検出し、パレスの MCP ローカル キャッシュと共有バックエンド キャッシュの両方を削除し、2 秒スリープして 1 回再試行します。成功した再試行には index_recovered: true のタグが付けられるため、呼び出し元は再試行がいつ実行されたかを観察できます。より広範な #1315 クラスターの部分修正 — tool_check_duplicate およびその他のインデックス操作ツールには引き続き同じラッパーが必要です。 (#1396)
  • Windows およびマルチテナント ホストでのクロスプロセスの正確性。 ChromaBackend.close_palace() は ChromaDB の rust 側 SQLite ファイル ロックを適切に解放するようになりました。shutil.rmtree が SQLITE_READONLY_DBMOVED で失敗しなくなった後、同じパレス パスを再度開きます。また、MCP サーバーの _kg はモジュール レベルのシングルトンではなくなりました。ツール呼び出し間で MEMPALACE_PALACE_PATH をローテーションするマルチテナント ホストは、パスごとの遅延キャッシュを介して適切な SQLite ファイルにヒットするようになりました。 (#1067、#1105、#1136、#1160)
  • Windows stdio は全面的に UTF-8 です。 mempalace search > out.txt およびパイプされたファクトチェッカー呼び出しは、プロセス境界でキリル文字/CJK ドロワー テキストを文字化けしなくなりました。 mcp_server、hooks_cli、および cli/fact_checker はすべて同じように再構成されます。 (#1282)
  • モノリポジトリの miner.detect_room ルーティング修正。 部分文字列チェックは双方向だったので、ルーム名の部分文字列であるトークン、またはその逆のトークンが一致しました。"views" in "interviews" が最初に一致したため、views/billing-page/src/Foo.test.tsx は interviews ルームにルーティングされました。区切り文字で区切られたトークン マッチング (-、_、.、/) が使用されるようになりました。 (#1004、#1002を閉じる)
  • mempalace compress は、約 32,000 個の引き出しを超える宮殿でクラッシュしなくなりました。 引き出しのフェッチは、miner.py の #851 修正を反映して、ページ分割されるようになりました。 (#1073、#1107) 内部: テストの信頼性も合格しました — tests/test_palace_locks.py と tests/test_chroma_collection_lock.py は、サブプロセスの生成のために fork から spawn に切り替わりました (Python 3.13 + マルチスレッドの親 = fork でデッドロック、macOS は CoreFoundation 経由での実行なしのフォークを禁止しています)。また、いくつかのテスト ファイルが sqlite3.connect(...) を contextlib.closing() でラップするようになりました。失敗パスでもリリースします。 (#1430、#1431) 約束は変わっていない。すべての単語が正確に保存されます。すべてがマシン上に残ります。テレメトリーはありません。説明しなかったクラウド API へのフォールバックはありません。リリースごとに、すでにあるものに磨きをかけます。
