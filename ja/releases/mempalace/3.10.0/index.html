mempalace v3.10.0

#メンパレスv3.10.0

エージェントは、Palace Query Language を備えた 3 ツールの MCP サーバー、host:harness:project ID の共有頭脳ルール、およびオプションのネイティブの正確なベクトル検索により、より軽量な方法を実現します。新規インストールは XDG に従い、ストレージの修正により、サイレント書き込み損失パス、macOS 整合性の拒否、およびいくつかのハングが解消されます。

アップグレードに関する注意事項

  • mempalace rules は --agent を受け入れなくなりました。 --host、--harness、および --project を渡してから、インストールされている共有ブレイン ブロックを再レンダリングします。 (#2508)
  • get_collection() は、MemPalace が決して読み取らない名前を拒否します。 構成されたドロワー コレクションまたは mempalace_closets 以外の名前では、CollectionNameMismatchError が発生します。メンテナンス スクリプトは _skip_name_check=True を渡すことができます。 (#2446)
  • カーソルが指定されていない場合、MCP イベント リストは最新のイベントを最初に返します。 mempalace_event_list および palace_coordinate は、since_event_id または order が渡されない限り、デフォルトで最新のものが最初になります。 mempalace logstream list と Logstream.list_events() は引き続きデフォルトで古い順になります。 (#2497)
  • 新規インストールでは、設定と宮殿が ~/.config/mempalace (または $XDG_CONFIG_HOME/mempalace) の下に保持されます。既存の ~/.mempalace インストールは変更されません。 (#148)

パフォーマンスとアーキテクチャ (デュアルトラック Rust エンジン)

  • オプションのネイティブ Rust 正確ベクトル加速 (rust_exact)。 既存の SQLite 形式を連続した float バッファに読み込み、Rayon を使用します 大規模スキャン向けに、Python GIL をリリースします。ローカルおよび外部書き込み ネイティブキャッシュを無効にします。読み込みはコレクションスコープで行われ、BLOB をデコードします 安全に。シリアルスキャンとパラレルスキャンでは、決定的な結合順序が維持されます。 複雑なフィルターとネイティブ拡張機能が存在しない場合は、Python にフォールバックします。

  • スタンドアロン ネイティブ ベクター CLI およびオプションのホイール。 GitHub リリースには、ネイティブ ホイールとプラットフォーム実行可能ファイルが含まれています。 CLI --vector または stdin 経由で JSON 埋め込みベクトルを受け入れます。埋め込まれていません テキストを入力するか、Python が必要です。プラットフォーム ランタイム ライブラリが引き続き必要になる場合があります。

  • NumPy top-k の最適化。 選択したデータを並べ替える前に、ベクトル ノルムと分割距離をキャッシュします。 結果は、カットオフでの行順序の関係を維持します。

  • 読み取り専用の検索操作は、宮殿ライターのリースとの競合を停止します。 searcher.py および _open_search_collection は、read_only=True を使用してコレクションを明示的に開くようになりました。読み取り専用クエリは、スキーマの初期化やライターのリース ロックを試行せずに SQLite WAL リーダー モードで接続するため、CLI およびエージェントの検索を、MineAlreadyRunning を発生させることなくアクティブなバックグラウンド MCP サーバーまたはライター プロセスと同時に実行できます。

リファクタリング

  • MCP サーバーはパッケージであり、8,000 行のモジュールではありません。 mempalace.mcp_server はパブリック インポート パスのままです (TOOLS、handle_request、main、すべての tool_* ハンドラー、およびプロセス グローバル名テスト モンキーパッチ)。実装は mempalace/mcp_server/ の下のドメイン ファイルに存在するため、PR は 1 つのゴッド ファイルと衝突することなく、ドロワー、KG、調整、プロトコル、または HTTP をターゲットにできます。フラグメントはパッケージ名前空間に実行されます。これは動作の変更ではなく、物理的な分割です。
  • CLI はパッケージであり、4,000 行のモジュールではありません。 mempalace.cli はパブリック インポート パスのままです (main、すべての cmd_* ハンドラー、および名前テスト モンキーパッチ)。実装は mempalace/cli/ の下のドメイン ファイルに存在するため、PR は 1 つのゴッド ファイルと衝突することなく、init、mine、search、repair、logstream、または argparse をターゲットにできます。フラグメントはパッケージ名前空間に実行されます。これは動作の変更ではなく、物理的な分割です。
  • MCP サーバー テストはドメインごとに分割されています。 tests/test_mcp_server.py は tests/mcp/ (プロトコル、読み取り、検索、書き込み、日記、KG、ガード、古いライブラリ) になったので、コミュニティ MCP PR は 1 つの 8 600 行のテスト ファイルで衝突しません。共有ヘルパーは tests/_mcp_server_helpers.py に住んでいます。
  • Searcher はパッケージであり、2 200 行のモジュールではありません。 mempalace.searcher はパブリック インポート パス (search、search_memories、SearchError、およびヘルパー テストのモンキーパッチ) のままです。実装は mempalace/searcher/ (ランキング、フィルター、sqlite BM25、候補、クエリ、CLI、レンダリング) の下で行われるため、PR は 1 つのシームをターゲットにできます。フラグメントはパッケージ名前空間に実行されます。これは動作の変更ではなく、物理的な分割です。
  • Palace ops はパッケージであり、1 800 行のモジュールではありません。 mempalace.palace はパブリック インポート パスのままです (get_collection、mine_lock、mine_palace_lock、クローゼット ヘルパー、および名前テスト モンキーパッチ)。実装は mempalace/palace/ (コレクション、バックエンド、クローゼット、鉱山ロック、採掘セット) の下にあるため、PR は 1 つのシームをターゲットにできます。フラグメントはパッケージ名前空間に実行されます。これは動作の変更ではなく、物理的な分割です。

機能

  • 共有ブレイン ルールは host:harness:project ID を使用し、いずれかの MCP ツール サーフェスに名前を付けることができます。 mempalace rules は、--agent の代わりに --host、--harness、--project (安定した小文字トークン) に加えて --mcp full|light を使用します。 full (デフォルト) は 45 ツールの名前を mempalace-mcp ツールに、light はpalace_query / palace_exec / palace_coordinate 同一の散文を持つトライアド。レンダリングされたブロックでは、エージェントが現在のワークスペースから ID を構成し、セッション開始時にウォッチャーを準備する代わりにコラボレーションを開始するときに受信トレイをスイープし、タスクの要求後または委任後、リッスンを求められた場合にのみ logstream watch を準備します。 logstream watch --agent は、--state-file を ~/.mempalace/watch/<agent>.json にデフォルト設定し、_ を 2 倍にし、: を _ にサニタイズするようになりました。そのため、Windows host:harness:project ID にはプライベート パスが必要ありません。 (#2508)
  • mempalace-light-mcp: Palace Query Language を備えた 3 ツール MCP サーバー。 palace_query、palace_exec、palace_coordinate は、45 ツール スキーマの約 4 分の 1 で、検索、分類、KG、グラフ、日記、ドロワー、マイニング、トンネル、および RFC 003 調整を、一行 PQL 文字列 (FIND "oauth" IN backend/auth LIMIT 5) または構造化辞書を通じてカバーします。 (10.6 KB と 41.6 KB)。書き込みは同じサニタイズ ハンドラーを経由するため、ドロワー テキストはそのまま残ります。検索ランキングは変更されず、stdio はハブ優先で、--read-only は palace_exec と palace_coordinate を拒否します。 claude mcp add mempalace-light -- mempalace-light-mcp の代わりにフルサーバーの横に登録します。 (#2412)
  • 新規インストールでは、構成は XDG ベース ディレクトリ仕様に従います。 解決順序は、$MEMPALACE_CONFIG_DIR、次に config.json、people_map.json、または palace/chroma.sqlite3 を保持する既存の ~/.mempalace、次に $XDG_CONFIG_HOME/mempalace (絶対値のみ)、次に ~/.config/mempalace です。既存のインストールでは ~/.mempalace が維持され、palace_path のデフォルトは <config_dir>/palace になります。 (#148)
  • CLI は、デーモンの書き込みルーティング ポリシーに従って書き込みます。 mine、sweep、sync、および init のセットアップ後の鉱山は、config.json の MEMPALACE_CLI_WRITE_ROUTING または write_routing.cli からの direct / prefer / require に続き、--daemon / --direct が続きます。コマンドごとのオーバーライド。デフォルトは direct のままであるため、オプトインしない限り何も変更されません。ジョブがデーモンに送信されると、デーモンがすでに受け入れている可能性があるため、エラー時に直接再実行されることはありません。 sweep はデーモン ジョブになりました。 (#2033)
  • pgvector フリートは、マシン間で 1 つのテーブル セットを共有できます。 オプトイン pgvector_shared_namespace (構成キー、MEMPALACE_PGVECTOR_SHARED_NAMESPACE、または shared_namespace バックエンド オプション) は、テーブル プレフィックスのパレス パス ハッシュを置き換えるため、異なるローカル パレス パスを持つノードは同じテーブルを読み書きします。設定を解除すると、プレフィックスはバイトごとに変更されません。値は厳密に正規化され、バックエンド マーカーに記録されます。 (#2167)
  • ハイブリッド ランク ウェイトは設定可能です。 MEMPALACE_HYBRID_VECTOR_WEIGHT / MEMPALACE_HYBRID_BM25_WEIGHT、または config.json の hybrid_rank_vector_weight / hybrid_rank_bm25_weight。デフォルトは 0.6 / 0.4 のままで、不正な値はそれらに戻ります。 (#2430)
  • 引き出しトラック last_modified。 新しい引き出しは filed_at から設定されます。 filed_at が作成時間を保持している間、コンテンツ、ウィング、またはルームを変更するすべての update_drawer はそれを新たにスタンプします。従来のドロワーは、filed_at を last_modified として報告します。 (#2147)
  • 検索結果には日付の由来が示されています。 ベクトル、共用体、および字句のみのヒットでは、filed_at、authored_at_source、content_date、content_date_source (filename、frontmatter、body、mtime、または unknown) が返されます。出所は私の作成時に記録され、レガシー引き出し用に再構築されることはありません。 (#2453)
  • mempalace_kg_timeline はページ付けします。 limit / offset は list_drawers 規則に従います。ハードコードされた最初の 100 の上限はなくなりました。 (#2406)
  • カーソルが指定されていない場合、ログストリームのリストはデフォルトで最新のイベントを表示します。 mempalace_event_list および palace_coordinate は、order が省略され、since_event_id が渡されない場合、最初に最新のイベントを返し、カーソルから再開するときに昇順を維持します。明示的な order が常に優先され、大文字と小文字は区別されません。ライト サーバーの palace_coordinate スキーマは、order、limit、preview、および since_created_at を公開するようになりました。 (#2497)
  • dynamics.effective_strength() は読み取り時に接続減衰を計算します。 これは純粋であるため、強度を読み取っても変更できず、メンテナンス パスを繰り返しても apply_decay のように減衰を増大させることはできません。モジュールの docstring は、廊下やトンネルがすでに強化または減衰していると主張しなくなりました。 (#2416)
  • DeepSeek ハーネス (.dsh-plugin/) 用の MemPalace プラグイン。 DSH 0.1.5 拡張ポイントに対して構築された 3 行の DSH バンドル プラグイン。 mempalace-recall は、最初のモデル呼び出しから各トップレベル セッションのシステム プロンプトにプロジェクトのウィングとして mempalace wake-up を配置します。 DSH は、プラグインが他の処理を待機する前にプロンプ​​ト テキストを解決するため、行には最初のアセンブリのみが一定時間保持され、ステップが失敗することはありません。 mempalace-autosave は、$DSH_HOME/mempalace/transcripts/ の下でセッションごとに追加専用のトランスクリプトを保持し、ユーザーが書いた内容とアシスタントのテキストのみを保持し (コンテキスト、ツールの結果、推論、または圧縮の要約は決して利用しない)、新しい dsh ハーネスを介して MemPalace 独自の stop、precompact、および session-end フックを実行します。 mempalace-mcp は、DSH 独自の MCP client と mempalace-light-mcp を通じて宮殿にサービスを提供します。その 3 つのツールのコストは、モデル ステップごとに約 2,100 スキーマ トークンですが、45 ツール サーバーの場合は約 7,700 です。 node --test スイートはプラグインをカバーし、tests/test_dsh_plugin.py はそれを pytest の下で実行します。

改善点

  • repair は、インプレース FTS5 修復がいつ行われるかを示し、決定した SQLite に名前を付けます。 Declining は 2 つのパス上でサイレント return であったため、オペレーターには再構築が考慮された兆候のない ABORT バナーが表示されました。 --dry-runも同様の説明を差し控えた。すべてのユーザーがそれを印刷するようになり、--dry-run のコピーはプレビューとしてマークされるため、予測している実行として読み取ることができなくなります。 sqlite3.sqlite_version には、これらのパスの状態 (中止バナー、両方の --dry-run ブランチ、修復の結果行、リカバリ後チェック、MCP 整合性ペイロードの 3 つの形状すべて、ツール拒否ペイロード、整合性ログ行、MineValidationError のメッセージ) のすべての判定が伴います。これは、特定の FTS5 障害を検出できないビルドからのクリーンな結果は、特定の FTS5 障害を検出できないビルドからの結果とまったく同じであるためです。できる。ポストマインバリデーターは、info ではなく warning でレポートします。これは、ロギングを構成しない mempalace mine パス上で存続するレベルです。 (#2240、#2254)
  • スキップされた起動整合性プローブは、クリーンな判定として報告されなくなりました。 MEMPALACE_STARTUP_INTEGRITY_MAX_MB を超えると、quick_check は実行されませんが、MCP ペイロードは checked: true, ok: true と応答しました。 reason としてスキップを伴う適用不可の形状を返すようになりました。その理由は、報告する比較を示すのに十分正確なサイズを示しています。つまり、1 MB 制限に対する 1.4 MB データベースは、「1 MB であり、1 MB 制限を超えています」と解釈されていました。書き込みツールは、ok ではなく記録されたエラーに基づいてゲートするため、新たに拒否されるものは何もありません。また、/statusz が欠落判定を失敗にまとめることがなくなりました。ok は、チェックがダーティに戻った場合にのみ false になります。これにより、非クロマ バックエンドが自身を異常であると報告することもなくなります (#1931)。 (#2240、#2254)
  • FTS5 分類子は、quick_check 行の先頭に固定されています。 sqlite_integrity_errors は、失敗したプローブを PRAGMA quick_check failed: <error> として報告し、固定されていない一致は、そのような行を分離された FTS5 障害として読み取り、状態が確立されていないデータベースの再構築を許可します。 SQLite 3.51.2 が出力する fts5: checksum mismatch は、意図的に一致しないままになっています。どちらの側が破損しているかは指定されておらず、再構築はコンテンツ テーブルから読み取ります。 (#2240、#2254)
  • list_drawers と graph_stats は、1 つのスクロールで Qdrant コレクションを参照します。 BaseCollection.get_all_rows() は、ID を保持する一括読み取りとして get_all_metadata() に加わります。デフォルトの静止画ページは get(limit=, offset=) を通過し、Qdrant はオフセット ループのコストが 126k 引き出しのパレスで 275 秒と 292 秒かかる単一のスクロールでそれをオーバーライドします。埋め込みラッパーは呼び出しを転送し、オーバーライドに達します。 (#2452、#2474)
  • 廊下の再計算は、採掘された翼のみを読み取ります。 compute_hallways_for_wing は、各鉱山の宮殿内のすべての引き出しを取得しました。 #1619 可変制限保護を維持しながら、境界付きページで get(where={"wing": ...}) をページングするようになりました。そのため、コストは宮殿ではなく翼に従います。 Qdrant では、get() がページごとに offset + limit 行をスクロールしますが、1 ページより大きいウィングは以前のページを再読み取りします。 (#2466、#2477)
  • CLI status は、SQLite の直接集計が利用できない場合、バックエンド メタデータを 1 パスで読み取ります。 Chroma Palace は引き続き chroma.sqlite3 から直接集計されます。 Qdrant などのバックエンドによって使用されるコレクション パス上で、status() はコレクションが公開するときに get() でページングする代わりに get_all_metadata() を呼び出すようになりました: 160k 引き出しの Qdrant パレスでは 1 分 46 秒から 3.4 秒まで短縮されました。 (#2153、#2154)

バグ修正

  • トランスクリプト パスのフォールバックは、すべての git ワークツリーに独自のウィングを与えなくなりました。 _wing_from_transcript_path のプライマリ パス (JSONL から cwd を読み取る) は、ウィングを導出する前にすでに <project>/.claude/worktrees/<wt> セグメントを折りたたんでいます。 cwd が存在しない場合に使用されるフォールバック パスには同等のストリップがなかったため、フラット化された --claude-worktrees-<wt> セグメントがウィング名に残りました。そこに同じ崩壊を適用しました。 (#2388、#2454)
  • mempalace mine --daemon は、呼び出し元の作業ディレクトリではなく、デーモン自身の作業ディレクトリをマイニングしなくなりました。 デーモンは、起動時に発生した cwd を保持する長寿命のバックグラウンド プロセスであるため、それに送信された相対ソース (mempalace mine .) は、CLI 呼び出しが実際に実行されたディレクトリではなく、その古い cwd に対して解決され、後続のフック駆動呼び出しごとに間違ったプロジェクトを間違ったウィングに黙ってマイニングします。 cmd_mine は、デーモン ジョブ ペイロードに入る前にソースを絶対パスに解決するようになり、_forward_mine_to_hub がハブ転送パスに対してすでに行っている解決と一致します。 (#2441、#2467)
