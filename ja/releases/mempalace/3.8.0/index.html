#メンパレスv3.8.0

v3.8.0 — 高速で大規模なパレス、無駄のない MCP プロキシ、ウェイクアブル エージェント

3.8.0 では、大きな宮殿は高速化され、小さなままになります。 Chroma メタデータ ツールは HNSW をコールドロードしなくなり、sqlite_exact は一般的な読み取りのためにパレス全体のスキャンとハイドレートを停止し、長時間実行されている Chroma サーバーは独自の書き込みで client を再構築することを停止し、プロキシされた MCP セッションは決して使用しないストレージ スタックをインポートしなくなりました。また、エージェントは永続的な logstream watch プリミティブを取得できるため、5 分間の繰り返し待機に依存することなく、調整によってハーネスをウェイクアップできます。

パフォーマンス

  • クロマ メタデータ読み取りはベクトル インデックスをスキップします。 1.7 GB / 165k ドロワー パレスでは、翼スコープの list_drawers(limit=20) は 2.31 および 1148 MB のピーク RSS から 0.01 および 86 MB に減少しました。 list_drawers とトンネル読み取りは、Chroma の SQLite メタデータを直接クエリし、フィルターを SQL にプッシュし、要求されたプレビューのみをハイドレートするようになりました。 (#2314)
  • sqlite_exact の一般的な読み取りが宮殿全体を歩くことはなくなりました。 ライブ 167k 引き出し / 166k クローゼットの宮殿では、mempalace_status は 6997 ミリ秒から 1045 ミリ秒に低下し、暖かい mempalace_search は 6364 ミリ秒から 210 ～ 1600 ミリ秒に低下しました。ベクトルランキングはバッチ化されてキャッシュされ、上位 k のドキュメントは後でハイドレートされ、等価フィルターは SQL でページ分割され、分類結果はキャッシュされ、wing / room / hall は、1.6 GB 埋め込みテーブルを書き換えることなく、インデックス付き生成列を取得します。 (#2308、#2311、#2313)
  • 長時間実行されている Chroma サーバーは、独自の書き込み時に HNSW をリロードするのではなく、フラットな状態を保ちます。 8 回の検索にわたって、測定された RSS は 951 MB → 3522 MB before から **940 MB → 965 MB after **に変化しました。置換された client は閉じられますが、本物の外部データベースの変更により再構築がトリガーされます。 (#2307)
  • ハブプロキシされた MCP セッションはシンです。 プレーン stdio プロキシは、ローカル フォールバックが必要な場合にのみ、転送パスのみをインポートし、サーバー全体を遅延ロードするようになりました。プロキシ セッションは約 17 MB で実行され、インポート重量は約 80 MB から 24 MB** に減少します。これにより、50 のエージェント フリート全体で約 3.9 GB が回避されます。 (#2312)

エージェントの調整

  • mempalace logstream watch は、耐久性のあるウェイクアップ ループを提供します。 カーソルの前進を所有し、繰り返しタイプのフィルター、エージェントの自己排他、永続的な状態ファイル、アイドル終了、および NDJSON フォロー モードをサポートします。カーソルなしの最初の実行はライブチップから始まります。再起動によりイベントが再生される可能性がありますが、黙ってイベントを見逃すことはありません。 (#2315)
  • 監視プロトコルでは、安全な再開カーソルが文書化されるようになりました。 クロスレプリカ イベントは到着順に追加されるため、壁時計のタイムスタンプではなく、since_event_id が再開可能な最高水準点となります。ツールの説明と共有調整プロトコルにより、エージェントが使用する場所にそのルールが配置されるようになりました。 (#2315)

整合性と運用

  • sync --apply は、ソース ファイルに到達できなかったドロワーを削除しなくなりました。 1 つの Path.exists() は削除から分離されているため、読み取り不能なディレクトリ、通常のファイルであるパス コンポーネント、およびマウントされていないボリュームはすべて削除と同じ結果になります。マウントされたボリュームからマイニングされたプロジェクトは、ボリュームが離れている間にすべてのドロワーを 1 つの sync --apply に失い、空に戻る可能性があります。削除にはプローブではなく確認が必要になります。そのパスにないファイルは、宮殿が同じディレクトリ内にある独自のソース (通常のファイル) をまだ参照できる場合にのみ削除できます。検証されていないものはすべて新しい unresolved バケットに配置され、剪定も削除も行われずに報告されます。 (#2320)
  • EmbeddingGemma は、Apple Silicon 上の CoreML 自動選択を介して NaN またはゼロ ベクトルをサイレントに保存することはできません。 自動モードでは、影響を受けるプロバイダーとモデルのペアが回避され、すべてのベクトルは使用前に有限の非ゼロ ノルムがチェックされます。 CUDA、DirectML、その他のモデルに変更はありません。 (#2283)
  • FTS5 自動修復は、インデックスを再構築する前にコンテンツ テーブルを検証して修復します。 可能な場合は Chroma のメタデータ コピーを権限として使用し、整合性が確立できない場合は declines を推測して使用します。 (#2279)
  • メッシュ ステータスはトランスポート間で一貫しています。 ハブはトークン不要の、最後に正常に動作した状態のスナップショットを公開するため、mempalace_mesh_peers は HTTP だけでなく標準入出力からの到達可能性とプロファイルを報告できます。 (#2309)
  • ファイルシステムのエッジケースは安全に失敗します。 sweep は失敗した統計を報告し、init は読み取り不能なマニフェスト パスを処理し、split は FIFO またはシンボリックリンクの出力ターゲットをブロックまたは書き込みする代わりに拒否します。 (#2244)
  • 公開されたコンテナは来歴と SBOM 証明書を取得します。 リリース ドキュメントには、Termux PRoot インストール ガイダンス、KG の置き換え例、明確化されたフック書き込みルーティング スコープも追加されています。 (#2097、#2139、#2059、#2123)

何が変わったのか

  • 修正 (ベンチマーク): https://github.com/MemPalace/mempalace/pull/1382 の @jphein による 3 兄弟ランナー用の Windows 上の UTF-8 エンコーディング + ASCII 印刷 Chrome

  • fix(chroma): https://github.com/MemPalace/mempalace/pull/2307 の @igorls による独自の書き込みで無効化する client キャッシュを停止します。

  • 修正(メッシュ): https://github.com/MemPalace/mempalace/pull/2309 の @igorls によってすべてのトランスポートが報告できるように資産を公開します
  • 修正(sqlite_exact): https://github.com/MemPalace/mempalace/pull/2311 の @igorls による残りの宮殿全体の読み取りパスをカット

  • 修正(sqlite_exact): https://github.com/MemPalace/mempalace/pull/2313 の @igorls による構造化アクセスのためのインデックスウィング/ルーム/ホール
  • fix(chroma): sqlite から list_drawers とトンネルを読み取り、https://github.com/MemPalace/mempalace/pull/2314 の @igorls によって HNSW をスキップ
