#メンパレスv3.5.0

v3.5.0 — ローカル書き込みデーモン、オプトイン HTTP トランスポート、パレス クリーンアップ ツール

このサイクルにより、MemPalace の書き込みパスを実行する 2 つの新しい方法と、パレスをクリーンに保つためのツール セットが追加されます。オプトイン ローカル デーモン は、パレス ハンドルを争うのではなく、単一のプロセスを通じてバックグラウンド マイニング、日記の保存、フック取り込みをシリアル化します。また、オプトイン HTTP トランスポート により、MCP サーバーは、ホスト/オリジン DNS リバインディング ガードとオプションのベアラー トークンを備えた、長寿命の HTTP client/プロキシ (ループバック デフォルト) の背後で実行できます。 3 つの新しい MCP ツールが同時に提供されます: mempalace_checkpoint (セッション全体を 1 つの保存にバッチ化)、mempalace_delete_by_source (マイニングされたベンチマーク/評価汚染 — ドロワー * および * そのインデックス エントリを外科的にパージ)、およびスコープ検索用の source_file フィルター。新しいトランスクリプト パーサー (Continue.dev、Gemini CLI、Pi) と C#/PHP/Swift/Kotlin/Java のマイナー カバレッジにより、マイニングできる範囲が広がり、一連の大規模なパフォーマンスと信頼性の修正がリリースを締めくくります。

機能

  • キュー書き込み用のローカル デーモンをオプトインします。 mempalace daemon は、すべてのパレス書き込みを 1 つのローカル プロセスを通じてシリアル化するため、バックグラウンド作業によるパレス ハンドルの競合が停止します。オプトインおよびローカルのみ。 (#1826)
  • MCP サーバーのオプトイン HTTP トランスポート。 mempalace-mcp --transport http は、プロキシ/長期有効展開のために POST /mcp (GET /healthz を使用) で JSON-RPC を提供します。 stdio はデフォルトのままです。 HTTP パスは 127.0.0.1 をバインドし、Host を固定し、非ループバック Origin (DNS リバインディング ガード) を拒否し、オプションの MEMPALACE_MCP_HTTP_TOKEN ベアラー トークンをサポートします。 (#1801、#1806)
  • mempalace_checkpoint バッチ保存ツール。 冪等の追加/削除パスを再利用して、複数の add_drawer 呼び出しとオプションの日記エントリを単一の MCP ラウンドトリップで逐語的にファイルします。 (#1851)
  • mempalace_delete_by_source 一括クリーンアップ ツール。 source_file のすべてのドロワー * およびそのクローゼット/AAAK インデックス エントリ* の完全一致、デフォルトでのドライラン削除 - ベンチマーク/評価ファイルが実際のウィングにマイニングされる場合の手段。ドライランでは爆発範囲がレポートされます。コミットにより、WAL 監査エントリが書き込まれます。 (#1722、#1729)
  • mempalace_search のオプションの source_file フィルター。 保存されている正確なパスを検索範囲にします。すべての検索パスを通過するため、黙って一致を削除することはありません。 (#1815、#1817)
  • 新しいトランスクリプト パーサー - Continue.dev セッション (#731)、Gemini CLI / AI Studio (#204)、および Pi エージェント JSONL (#169)。
  • より幅広いマイナー言語をカバー — C#/.NET、PHP (#1819)、Swift/Kotlin (#1368)、および Java プロジェクトの検出 (含む)ルートレスサブプロジェクト (#1720)。
  • Claude プラグイン SessionEnd の最後の鉱山なので、セッション終了時に最後のやり取りがキャプチャされます。 (#1814、#1820)

パフォーマンス

  • SQLite アグリゲートからの概要/ステータスと graph_stats の回答 — 大規模な宮殿のタイムアウトを修正します。 (#1748、#1379)
  • エンベッダーは ONNX ランタイムの運用内スレッドを制限します。そのため、バックグラウンド マイニングがすべてのコアを固定することはなくなります。 (#1068)
  • sqlite_exact (#1842) および pgvector (#1840) の **SQL プッシュダウン ページネーション **、および Qdrant (#1832) のシングルスクロール バルク メタデータ。

バグ修正

  • pgvector は敵対的な転写バイトを許容します — 単独のサロゲート (#1833) または NUL バイト (#1829) によって鉱山全体が中止されることはなくなりました。
  • 再マイニングではなく、repair --mode from-sqlite の分岐インデックス回復ポイント - MCP によって追加されたドロワーと日記エントリをサイレントにドロップした再マイニング。 (#1843、#1847、#1849)
  • 古い ChromaDB HNSW 分岐は、読み取りに失敗する代わりに SQLite フォールバックにルーティングされます。 (#1816、#1822)
  • MCP サーバーは、HNSW ハンドルを競合させるのではなく、同じパレスに対する 2 番目のライターを拒否します。 (#1818、#1823)
  • Windows フック マイナーは CREATE_NO_WINDOW で生成されます - コンソール フラッシュはありません。 (#1783、#1848)
  • パーセントでエンコードされた SQLite 読み取り専用 URI なので、スペースのある/特殊文字のパレス パスが開きます。 ###CI
  • test-windows は一時的な ChromaDB HNSW 圧縮フレークのみを再試行します (--only-rerun)。 Linux/macOS は再実行をゼロに保つため、実際のリグレッションは大きく残ります。 (#1854) このサイクルに貢献していただいた皆様に多大な感謝を申し上げます。これらの機能や修正の多くは、初めての貢献者も含め、コミュニティから提供されました。全員が以下にクレジットされています。
