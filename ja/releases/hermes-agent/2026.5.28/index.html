エルメスエージェント v2026.5.28

#エルメスエージェント v0.15.0(v2026.5.28) 発売日: 2026 年 5 月 28 日 v0.14.0 以降: コミット数 1,302 · マージされた PR 747 · 変更されたファイル 1,746 · 挿入 282,712 · 削除 36,699 · クローズされた 560 以上の問題 (P0 15、P1 65、セキュリティタグ付き 19) · コミュニティ寄稿者 321 名 (共著者を含む)

ベロシティ リリース エルメスは、開始、実行、作業の出荷、および成長が劇的に速くなります。 16,083 行の run_agent.py は、14 個のまとまった agent/* モジュール全体で 3,821 (-76%) に縮小します。 Kanban は、オーケストレーターの自動分解、swarm トポロジ、スケジュールされたタスク、タスクごとのワークツリー、タスクごとのモデル オーバーライドなど、104 の PR にわたる実際のマルチエージェント プラットフォームに成長しました。コールド スタート パフォーマンスの波は続いています。起動がさらに 1 秒短縮され、会話ごとの関数呼び出しが 47% 減少し、hermes --version が Codex CLI との直接ベンチマークを逆転しました。 session_search は 4,500 倍高速で、現在は無料です。 Promptware 防御は、Brainworm クラスの攻撃に対抗します。 Bitwarden Secrets Manager は、プロバイダーごとに N 個の API キーを 1 つのブートストラップ トークンに置き換えます。スキル バンドルを使用すると、1 つのスラッシュ コマンドでワークフロー全体を読み込むことができます。 Ink TUI にはマルチセッション オーケストレーターが搭載されています。 2 つの新しい image_gen プロバイダー (Krea 2 Medium + Large、プラグインに移植された FAL)、インタラクティブ ピッカーを備えた Nous 承認の MCP カタログ、OpenHands オーケストレーション スキル、23 番目のメッセージング プラットフォームとしての ntfy、および深い xAI 統合ラウンド (Web 検索プラグイン、xai-oauth hermes proxy アップストリーム、5 月 15 日に廃止されたモデル検出 + hermes migrate xai、自然な TTS 音声タグ一時停止、base_url)リーク ガード、Grok 用の OpenAI スタイルの実行ガイダンス)。 15 個の P0 + 65 個の P1 クロージャーが並んでいます。

✨ ハイライト

  • 大規模なリファクタリング — run_agent.py は 16,000 行ではなくなりました — Hermes の中心となるファイル (エージェントの会話ループ) は、16,083 行から 3,821 (-76%) に削減され、抽出されたコード redis は agent/ の下の 14 のまとまったモジュールに分散されました。動作は変更されていません。すべての抽出で AIAgent にシン フォワーダーが保持され、すべてのテスト パッチ パスが引き続き機能し、すべての外部呼び出し元に互換性があります。あなたが気にする理由: 将来の Herme 開発はより速く進み、プラグイン作成者は最終的にコードベースを grep できるようになり、エディターでロードするのに 90 秒かかったファイルが一瞬で開きます。 (#27248)
  • Kanban は実際のマルチエージェント プラットフォームに成長しました — 104 の PR がエンドツーエンドで利用可能 — トリアージは、1 つのタスクをサブタスクのツリーに自動分解します。 hermes kanban swarm は、ルート、並列ワーカー、ゲート ベリファイア、ゲート シンセサイザー、共有黒板など、完全な Swarm v1 グラフを 1 つのコマンドで作成します。タスクは、タスクごとのモデルのオーバーライド (ボイラープレート用の安価なモデル、ハードなサブタスク用の高価なモデル)、ボードレベルのデフォルトのワークディレクトリ、タスクごとのワークツリーのパスとブランチ、スケジュールされた開始時間、構成可能なクレーム TTL、フィンガープリンティングの再試行、古いタスクの検出、リスポーン ガード、およびドラッグして削除できるゴミ箱ゾーンをサポートします。ワーカーは、/workers/active、/runs/{id}、および /inspect エンドポイントを通じて報告します。 (#27572、#28443、#28364、#28394、#28462、#28384、 #28467、#28455、#28452、#28432、#28468、#28420)
  • コールド スタート パフォーマンス ウェーブは続行 — さらに 1 秒短縮、ターンごとの関数呼び出しが 47% 減少 — 3 つの新しい最適化ラウンド: openai._base_client インポートの延期 (CLI 呼び出しごとに -240 ミリ秒 / -17MB)、ホットパスの最適化により会話ごとの関数呼び出しの 47% 削減 (31 ターンのチャットで 399k → 213k)、延期圧縮実現可能性チェック (エージェント構築ごとに -170 ～ -290 ミリ秒)、適応サブプロセス ポーリング (ツール呼び出しごとに -195 ミリ秒、ターンごとに 1 秒以上)。 Termux のコールド スタートは 2.9 秒から 0.8 秒に短縮されました。 hermes --version コールド ドロップは 63% (701 ミリ秒 → 258 ミリ秒)、Codex CLI に対する直接ベンチマークを 5/11 の勝利から 6/11 に逆転しました。 (#28864、#28866、#28957、#29006、#29419、#30121、 #30609、#31968)
  • session_search の再構築 — LLM なし、コストなし、4,500 倍の高速化 — 古い session_search は補助 LLM を利用したツールで、通話あたりのコストは ~$0.30 かかり、3 つのセッションを要約するのに ~30 秒かかり、適切なセッションが FTS5 ヒット リストにない場合には混乱が生じることがありました。新しい形状は、引数の設定に基づいて推論される 3 つのモード (ディスカバリー、スクロール、ブラウズ) を持つ 1 つのツールです。mode パラメーター、aux-LLM、設定ノブ、コンパニオン スキルはありません。検出時間は 90 秒ではなく 20 ミリ秒です。スクロールは約 1 ミリ秒です。過去のセッションのコンテキストを無料で瞬時に検索できるようになりました。 (#27590)
  • プロンプトウェア防御 — ブレインワーム クラスの攻撃は 3 つのチョークポイントでブロック — 最近のブレインワーム / プロンプトウェア キル チェーンの研究 (Origin HQ、arxiv 2601.09625) に触発され、Hermes はツール出力、リコールされたメモリ、または保存されたスキルを介してエージェントをハイジャックしようとするプロンプト インジェクション攻撃からコンテキスト ウィンドウを防御するようになりました。約 15 の新しい Brainworm/C2 パターンを備えた単一の信頼できる情報源 (tools/threat_patterns.py)。呼び出されたメモリはロード時にスキャンされます。ツールの結果には区切りマーカーが付けられるため、悪意のあるファイルやリモート サービスが Hermes 自身のシステム コンテンツになりすますことができません。危険なコードの書き込みをパターンマッチングする新しい security-guidance プラグインと組み合わせます。 (#32269、#33131、#9151)
  • Bitwarden Secrets Manager — 1 つのブートストラップ トークンがプロバイダーごとのすべての API キーを置き換えます — ~/.hermes/.env にプレーンテキストの API キーを保持するのをやめます。 Bitwarden Secrets Manager (bws は最初の使用時に遅延して自動インストールされます) をインストールし、1 つのブートストラップ トークン (BWS_ACCESS_TOKEN) で Hermes を指定すると、必要なすべての資格情報が起動時に Bitwarden から取得されます。 Bitwarden Web アプリでキーを回転すると、その回転が実際に有効になります。Bitwarden はデフォルトで真実の情報源となるため、起動時にその値が一致する環境変数を上書きします。 secrets.bitwarden.override_existing: falseを反転すると反転します。 EU クラウドおよびセルフホスト型 Bitwarden サーバー URL がサポートされています。検出された資格情報にはソースのラベルが付けられるようになり、どのキーが Bitwarden から来たのか、ローカル環境から来たのかが一目でわかるようになりました。 (#30035、#31378、#30364)
  • 23 番目のメッセージング プラットフォームとしての ntfy — アカウントなしのプッシュ通知 — ntfy は、サインアップも API キーもなく、トピック URL のみを使用する自己ホスト可能なプッシュ通知サービスです。現在、Hermes はプラットフォーム プラグインとしてこれに適応しているため (コアへの編集は不要)、エージェントは任意の cron ジョブ、かんばんタスクの完了、またはチャット send_message からのプッシュ通知を携帯電話、時計、デスクトップ、ホームラボに送信できます。 (サルベージ #30625 → 元は #4043) (#30867)
  • スキル バンドル — /<name> は複数のスキルを一度にロードします — スキル バンドルは、1 つのスラッシュ コマンドですべてをまとめてロードする、名前付きのスキルのグループです。 「執筆日」バンドル (ヒューマナイザー + イデエーション + 黒曜石 + YouTube コンテンツ) を設定すると、/writing-day はセッション中に 4 つすべてを有効にします。 Skills Hub には、ヘルスチェック、鮮度バッジ、およびウォッチドッグ cron が追加されました。 3 つの新しいオプション スキルが追加されました: code-wiki (Karpathy の LLM-Wiki、永続的なインデックス付き開発 Wiki)、openhands (並列コーディング エージェント用の OpenHands へのデリゲート)、および web-pentest (OWASP スタイルの Web ペンテスト レシピ)。 (#28373、#32345、#32240、#32261、#32265)
  • TUI セッション オーケストレーター — 1 つの TUI ウィンドウでの複数のライブ セッション — Ink TUI には、アクティブ セッション スイッチャー オーバーレイが追加されました。 TUI を離れることなく、複数のライブ プロセス ローカル セッションを一覧表示し、切り替え、更新し、閉じることができます。セッションスコープのモデルピッカーを使用して新しいセッションをディスパッチします。さらに、TUI の洗練の波 - マウス追跡 DEC モード プリセット、ブランチと termux 間でのスクロールバックの保存、スラッシュ ドロップダウンの修正、x.com リンク レンダリング、および CJK / IME 入力レンダリングの改善。 (サルベージ #27642) (#32980、#30084)
  • 2 つの新しい image_gen プロバイダー — Krea 2 Medium + Large、プラグインに移植された FAL — Krea は組み込みプラグインとして image_gen ラインナップに加わりました: Krea 2 Medium ($0.03) および Krea 2 Large ($0.06)。自動検出され、hermes tools → Image Generation → Krea で選択可能です。ネイティブ Krea プラグインと FAL.ai カタログの両方から利用できます。 FAL.ai バックエンドはモノリシック画像生成ツールから plugins/image_gen/fal/ に取り出され、Web、ブラウザ、video_gen によってすでに確立されている 4 方向のアーキテクチャ上の同等性が完成しました。新しい画像プロバイダーはフォークではなく 1 つのファイルになりました。 (#33236、#30380、#33506)
  • インタラクティブ ピッカーを備えた Nous 承認の MCP カタログ — Nous が精査した MCP サーバーの厳選されたカタログで、オプション スキルの形状を反映しています。 hermes mcp を実行すると、対話型ピッカーが表示されます。 1 回のキーストロークでインストールでき、インストール時に資格情報が要求され、~/.hermes/.env に書き込まれます。 n8n マニフェストが最初に同梱されます。ユーザーが trusted MCP サーバーを探すために GitHub を探し続けていた検出ギャップを埋めます。 (#30870)
  • OpenHands オーケストレーション スキル - optional-skills/autonomous-ai-agents/openhands/ の新しいオプション スキルにより、エージェントはコーディング タスクを claude-code、codex、opencode と並んで OpenHands CLI に委任できます。 OpenHands はそのファミリーのモデルに依存しないメンバーです。LiteLLM がサポートするプロバイダー (OpenAI、Anthropic、OpenRouter、独自のもの) はどれも動作するため、サブタスクをそれを完了できる最も安価なモデルにルーティングできます。カンバン swarm および /delegate フローのドロップイン ワーカー。 (クローズ #477) (#32261)
  • ディープ xAI 統合ラウンド — Web 検索プラグイン、OAuth プロキシ アップストリーム、5 月 15 日の廃止検出、自然な TTS、セキュリティ強化 — 6 つの連動する xAI の改善:
    • xAI Web Search は、Brave / Tavily / Exa / SearXNG / DDGS / Firecrawl と並ぶ plugins/web/xai/ プロバイダーとして登場します。既存の Grok OAuth または XAI_API_KEY 資格情報を再利用し、新しい環境変数は必要ありません。 (#29042)
    • hermes proxy は xAI アップストリームを取得 — ローカルの OpenAI 互換エンドポイントは SuperGrok OAuth によってサポートされるようになり、client に PKCE リフレッシュ コードを記述する必要はありません。 (#28356)
  • 5 月 15 日のモデル廃止の検出 — grok-4、grok-4-fast{,-reasoning,-non-reasoning}、grok-3、grok-code-fast-1、grok-imagine-image-pro などがドクターおよびチャットの起動時に検出され、hermes migrate xai によりサポートされているモデルへの設定がワンショットで移行されます。引退日以降、サイレント 404 はもうありません。 (#29277)
    • xAI TTS の オプトイン auto_speech_tags — より自然な音声応答を実現するために、段落と文の間に軽い [pause] タグを挿入します。デフォルトはオフです。 (#29376)
    • xai-oauth base_url を x.ai オリジンに固定 — XAI_BASE_URL が OAuth 認証された推論を攻撃者が制御するホストに再ポイントする可能性があるサイレント資格情報漏洩ベクトルを閉じます。 (#28952)
    • OpenAI スタイルの実行ガイダンスを Grok モデルに適用 — Grok と xai-oauth は、GPT/Codex が持つのと同じファミリー固有の実行規律ブロックを取得するようになりました。そのため、モデルはツール呼び出しなしで完了を主張することを停止し、既存のツールを使用する代わりに回避策を提案することを停止します。 (#27797)
    • さらに、x_search の劣化結果の表面化、API キー フォールバックを備えた階層ゲート 403、PKCE code_challenge ラウンドトリップ修正、端末リフレッシュ失敗時のデッド トークン隔離、リクエストごとの MiniMax スタイルのショート トークン リフレッシュ、および両方の分類子サイトでの WKE=unauthenticated 優先。 (#29484、#28351、#27560、#28116、#30619、#30872)
