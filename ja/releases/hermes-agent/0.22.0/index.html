#エルメスエージェント v0.22.0

発売日: 2026 年 10 月 13 日 v0.21.0 以降: ~24,200 コミット · ~6,080 マージ PR · ~15,600 ファイル変更 · ~2,045,000 挿入 · ~1,140,000 削除 · ~7,180 件クローズ · ~2,520 人の寄稿者

敷居の解放。 ヘルメスは敷居、つまり戸口、交差点、境界石の神でした。 v0.21.0 はパンテオンを組み立てました。 v0.22.0 はドアを通過するところです。新しいデスクトップのインストールは、無料試用モデルで実行されるガイド付きセットアップ チャットで開かれるようになりました。そのため、初心者は API キーを所有する前に Hermes と会話することになります。コネクタは、アカウントを開始する必要がなく、すでに使用しているアプリにエージェントを運びます。ローカル モデルは、1 つの click llama.cpp ランタイムを使用して、それを独自のハードウェアに持ち帰ります。そして、しきい値自体もより強力になりました。テスト済みの SemVer 安定版リリースは、デフォルトでインストールされ、署名されたデスクトップ パッケージ (Microsoft Store を含む) と、すべての下に 1 つのパッケージ マネージャーが続きます。その背骨の周りには、600 のプラグイン カタログ、Claude 5.5 / GPT-6 モデル ウェーブ、ブラウザーのパスワード マネージャー サインイン、引き継ぐことができるボット画面、プロファイルごとに 1 つのバックエンドと 1 つのゲートウェイ、そして 3 分の 1 小さいコードベースがあります。これは、Hermes が出荷した最大の期間であり、v0.21.0 サイクルの約 2.5 倍であり、v0.21.1 ～ v0.21.7 パッチ リリースをまとめて完全に文書化しています。

⚠️ アップグレードに関する注意事項

  • Python 3.14 は、管理インストール用のランタイムです (パッケージ マネージャーがインストールします)。 KittenTTS は 3.14 では使用できません。 (#102765)
  • Windows デスクトップは MSIX のみで、Windows 11 22H2 以降が必要です。 NSIS/MSI インストーラーはなくなりました。 macOS アプリはデフォルトのビルドでのみ Apple Silicon です。 (#102765、#136603)
  • マシンごとに 1 つのゲートウェイがデフォルトです。 何も競合しない場合、hermes update はプロファイルごとのゲートウェイを多重化されたデフォルトに組み込みます。 (#112854)
  • チャットはアイドル/デイリー タイマーでリセットされなくなりました。 session_reset アイドル/デイリー モードは廃止されました (依然として設定されている設定では警告が記録されます)。 /new または /reset は新たに開始します。 (#105021、#126244)
  • 古いセッションは自動的に削除されます。 sessions.auto_prune はデフォルトでオンになり、90 日間非アクティブで終了したセッションは起動時に削除されます。固定されたセッションと開いているセッションには決して触れません。 sessions.auto_prune: false を設定してすべてを保持します。
  • メモリ プロバイダーはカタログ プラグインに移行 (Honcho、Supermemory、Hindsight、Mem0、OpenViking、Holographic)、Home Assistant、Spotify、Langfuse も同様です。既存のユーザーは、データがそのままの状態で更新時または初回起動時に移行されます。 ByteRover と RetainDB はバンドルされたままになります。
  • プラグイン作成者: 古いプラグイン互換性インポート層がなくなり (#126164)、hermes sync (スキル同期) が削除され (#132465)、バンドルされた tirith スキャナーが削除されました (#133832)。いくつかのツールの名前が変更されました (todo → todo_list、cronjob → cronjob_manage、process → process_manage)。古い名前はまだ機能します。 (#97979)

コネクタ

  • 独自のローカル サーバー - LM Studio にはプロバイダー プロファイルがあり、Ollama ピッカーがちらつきなくなり、自己起動された llama.cpp サーバーが /model に表示され、デスクトップ管理モデルへのフォールバックが機能します。 (#134320、#113129、#116679、#131795 — @kshitijk4poor、@DaxLee9988、@fangliquanflq、@Finn763、@albeight)

統合パッケージマネージャー

  • hermes pm (ハイライトを参照): 固定され、ハッシュ チェックされた Python 3.14、uv、Node、ripgrep、FFmpeg、Chromium、および Windows 上の Git/Bash (hermes pm doctor|status|repair|gc を使用)。寄稿者は source ./activate (または .ps1/.fish) を使用します。
  • 依存関係環境は世代です - 新しい環境は使用前にチェックされるため、インストールが失敗しても動作し続けます。更新と hermes pm gc は古い更新を再利用します (1 つのホストで 92 GB から 18 GB)。 (#124968、#133808 — @JoaoMarcos44)
  • 初回使用時にオプション機能がインストールされます - オプトイン SDK (Anthropic、Bedrock) は再起動せずにセッション中にロードされます。 security.allow_lazy_installs: false はこれをオフにします。 (#122221 — @ethernet8023)
  • プラグインは Python の依存関係を宣言します - プロファイル全体のコアで解決されます。競合は拒否され、適合しなくなったプラグインは更新により無効になります。 Hindsight、Honcho、Supermemory、Mem0、Home Assistant はカタログに移動され、使用されている場合は自動インストールされます。 (#113851、#122103、#114569、#132469 — @ethernet8023)

インストールとアップデート

  • アップデートを半分まで適用することはできません (ハイライトを参照)。強制終了されたアップデートは、次回の起動時に自動的に修復されます。 (#132361、#120339)
  • 高速な更新、小規模なチェックアウト - 更新では変更された部分のみが再構築され (macOS の 16.5 と 32.5 )、クローンはブロブレスで、部分クローン .git の増加は修正されます。 (#135092、#133016、#131679 — @kshitijk4poor、@ethernet8023、@liuhao1024、@whyyagswhy)
  • 小規模なハッシュチェック済みインストーラー - install.sh/install.ps1 は固定された UV と Git を検証し、PM に引き継ぎ、logs/install.log にログを記録し、musl Linux (Alpine、Void)、Windows 10、および Unicode Windows パスで動作するようになりました。 (#124964、#125598、#132430 — @JoaoMarcos44、@kshitijk4poor、@Finn763、@OutThisLife)
  • 失敗は理由を示す — オプトイン テレメトリでは、インストール、更新、スキル、プラグインの失敗が理由を記録します。 (#133809)

Docker / Nix / Termux / Windows

  • Docker — フル Chromium を使用した固定 Debian 13 ベース。 stable/latest は公開されたリリースでのみ移動します。ベイクインされたエクストラは再起動後に戻ります。 (#135726、#135084 — @unsupportedpastels)

🏗️ コアエージェント、セッション、メモリ

エージェント ループと信頼性

  • 停止したターンの回復 — ウォッチドッグ (agent.turn_liveness.timeout_s、デフォルトは 600 秒) が進行しないターンを中断し、セッションを解放します。トランスクリプトの修復を繰り返すと、1 つのエラーと通知が発生するようになりました。 (#99758、#99687 — @kshitijk4poor、@Finn763、@HexLab98)
  • ストリームの失敗が少なく、正直にレポートします — テキストのないデッド ストリームは再試行され、繰り返しループはカットされ、中断されたターンは完了として報告されません。 (#113135、#130551、#112272 — @kshitijk4poor)

圧縮とコンテキスト

  • 実際のトークン数に基づいて圧縮がトリガーされます — バイト/4 ではなく、プロバイダーによって報告された使用量。保護されたテールの上限は 20% であるため、小窓モデルはコンパクトになります。 (#104555、#117957 — @686f6c61)
  • 不適切な要約はコンテキストを消去できません — 拒否と過負荷の要約プロバイダーはトランスクリプトをそのままにし、コミットされていない圧縮は何も変更しません。 (#118920、#115906、#136083 — @kshitijk4poor、@fangliquanflq、@mnajafian-nv)
  • 新しいノブ — プロバイダー スコープの compression.model_thresholds キーおよび auxiliary.<task>.no_progress_timeout。 (#108061、#115804 — @chelsealong)

セッションと state.db

  • state.db の信頼性 — ロック タイムアウトにより保持プロセスに名前が付けられ、データベースがビジー状態になってもターンが終了することがなくなり、兄弟 PID 名前空間がリースを盗むことがなくなりました。 (#116967、#134577、#132161 — @kshitijk4poor、@686f6c61)
  • state.db の成長が停止します - 自動プルーンはデフォルトでオンになっており (セッションは 90 日間で終了)、古い cron/kanban/subagent セッションは閉じられます。 VACUUM は、25% が再利用可能な場合にのみ実行されます。 (#101316、#100903 — @stepanov1975)
  • 修復コマンド — hermes sessions set-journal-mode delete|wal、repair-profiles (交差プロファイル)、および repair-prompts。 (#117684、#115689、#124200 — @kshitijk4poor、@JoaoMarcos44)
  • よりクリーンなセッション リスト - ワンショット実行はピッカーから除外され、sessions.show_subagents リストにはサブエージェント チャットというタイトルが付けられ、メッセージはコンテキスト エンジンの安定した ID を取得します。 (#113826、#122304、#126687 — @OutThisLife、@kshitijk4poor、@100yenadmin)

メモリ

プロファイルと構成
