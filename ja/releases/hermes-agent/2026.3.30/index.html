エルメスエージェント v2026.3.30

#エルメスエージェント v0.6.0(v2026.3.30) 発売日: 2026 年 3 月 30 日

マルチインスタンス リリース — 分離されたエージェント インスタンスを実行するためのプロファイル、MCP サーバー モード、Docker コンテナ、フォールバック プロバイダー チェーン、2 つの新しいメッセージング プラットフォーム (Feishu/Lark および WeCom)、Telegram Webhook モード、Slack マルチワークスペース OAuth、2 日間で 95 の PR、および 16 件の問題が解決されました。

✨ ハイライト

  • プロファイル – マルチインスタンス Herme – 同じインストールから複数の分離された Herme インスタンスを実行します。各プロファイルは、独自の構成、メモリ、セッション、スキル、およびゲートウェイ サービスを取得します。 hermes profile createで作成、hermes -p <name>で切り替え、エクスポート/インポートして共有します。完全なトークンロック分離により、2 つのプロファイルが同じボット資格情報を使用することが防止されます。 (#3681)
  • MCP サーバー モード - hermes mcp serve 経由で、Hermes の会話とセッションを MCP 互換の client (クロード デスクトップ、カーソル、VS コードなど) に公開します。会話の閲覧、メッセージの読み取り、セッション全体の検索、添付ファイルの管理はすべてモデル コンテキスト プロトコルを通じて行われます。標準入出力とストリーミング可能な HTTP トランスポートの両方をサポートします。 (#3795)
  • Docker コンテナ — コンテナ内で Herme エージェントを実行するための公式 Docker ファイル。ボリュームマウント構成で CLI モードとゲートウェイ モードの両方をサポートします。 (#3668、クローズ #850)
  • 順序付けされたフォールバック プロバイダー チェーン — 自動フェイルオーバーを使用して複数の推論プロバイダーを構成します。プライマリ プロバイダーがエラーを返すか、接続できない場合、Hermes はチェーン内の次のプロバイダーを自動的に試みます。 config.yaml の fallback_providers 経由で設定します。 (#3813、クローズ #1734)
  • Feishu/Lark プラットフォームのサポート — イベント サブスクリプション、メッセージ カード、グループ チャット、画像/ファイル添付、およびインタラクティブ カード コールバックを備えた Feishu (飞书) および Lark 用の完全なゲートウェイ アダプター。 (#3799、#3817、クローズ #1788)
  • WeCom (Enterprise WeChat) プラットフォーム サポート — テキスト/画像/音声メッセージ、グループ チャット、およびコールバック検証を備えた WeCom (企业微信) 用の新しいゲートウェイ アダプター。 (#3847)
  • Slack マルチワークスペース OAuth — OAuth トークン ファイルを介して、単一の Herme ゲートウェイを複数の Slack ワークスペースに接続します。各ワークスペースは独自のボット トークンを取得し、受信イベントごとに動的に解決されます。 (#3903)
  • Telegram Webhook モードとグループ コントロール - ポーリングの代わりに Webhook モードで Telegram アダプターを実行します。これにより、応答時間が短縮され、リバース プロキシの背後での運用展開に適しています。新しいグループのメンション ゲート制御は、ボットが応答するときに常に、@メンションされたときのみ、または正規表現トリガー経由で制御します。 (#3880、#3870)
  • Exa 検索バックエンド — Firecrawl や DuckDuckGo と並ぶ代替 Web 検索およびコンテンツ抽出バックエンドとして Exa を追加します。 EXA_API_KEY を設定し、優先バックエンドとして構成します。 (#3648)
  • リモート バックエンドのスキルと資格情報 - スキル ディレクトリと資格情報ファイルをモーダル コンテナと Docker コンテナにマウントします。これにより、リモート ターミナル セッションはローカル実行と同じスキルとシークレットにアクセスできます。 (#3890、#3671、クローズ #3665、#3433)

🏗️ コアエージェントとアーキテクチャ

プロバイダーとモデルのサポート

  • 順序付けされたフォールバック プロバイダー チェーン — 構成された複数のプロバイダーにわたる自動フェイルオーバー (#3813)
  • プロバイダー スイッチの api_mode を修正 — hermes model 経由でプロバイダーを切り替えると、chat_completions をハードコーディングする代わりに古い api_mode が正しくクリアされ、Anthropic 互換エンドポイントを持つプロバイダーの 404 が修正されました (#3726、#3857、クローズ #3685)
  • サイレント OpenRouter フォールバックを停止 — プロバイダーが設定されていない場合、Hermes はサイレントに OpenRouter にルーティングする代わりに明確なエラーを生成するようになりました (#3807、#3862)
  • Gemini 3.1 プレビュー モデル — OpenRouter および Nous Portal カタログに追加 (#3803、終了 #3753)
  • Gemini ダイレクト API コンテキスト長 — ダイレクト Google AI エンドポイントの完全なコンテキスト長解決 (#3876)
  • gpt-5.4-mini が Codex フォールバック カタログに追加されました (#3855)
  • プローブが返すモデルが少ない場合、ライブ API プローブよりも 厳選されたモデル リストが優先されます (#3856、#3867)
  • ユーザーフレンドリーな 429 レート制限メッセージ (再試行後のカウントダウン付き) (#3809)
  • **認証要件のないローカル サーバー用の 補助 client プレースホルダー キー (#3842)
  • 補助プロバイダー解決のための INFO レベルのログ (#3866)

エージェントのループと会話

  • サブエージェント ステータス レポート - 概要が存在する場合、一般的な障害ではなく completed ステータスをレポートします (#3829)
  • 圧縮中にセッション ログ ファイルが更新されました — コンテキスト圧縮後の古いファイル参照を防止します (#3835)
  • 空のツール パラメーターを省略 — 空の場合、None ではなく tools パラメーターを送信せず、厳密なプロバイダーとの互換性を修正します (#3820)

プロファイルとマルチインスタンス

  • プロファイル システム — hermes profile create/list/switch/delete/export/import/rename。各プロファイルは、分離された HERMES_HOME、ゲートウェイ サービス、CLI ラッパーを取得します。トークン ロックは、資格情報の衝突を防ぎます。プロファイル名のタブ補完。 (#3681)
  • プロファイル対応の表示パス - 正しいプロファイル ディレクトリを表示するために、ユーザー向けのすべての ~/.hermes パスが display_hermes_home() に置き換えられました (#3623)
  • Lazy display_hermes_home imports — モジュールが古いバイトコードをキャッシュする場合、hermes update 中に ImportError を防止します (#3776)
  • 保護されたパスの HERMES_HOME — .env 書き込み拒否パスは、ハードコードされた ~/.hermes ではなく、HERMES_HOME を尊重するようになりました (#3840)
