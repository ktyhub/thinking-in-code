エルメスエージェント v2026.6.19

#エルメスエージェント v0.17.0(v2026.6.19) 発売日: 2026 年 6 月 19 日 v0.16.0 以降: ~1,475 コミット · ~800 マージ PR · 1,693 ファイル変更 · 235,390 挿入 · 50,730 削除 · 300 以上の問題解決 · 245 コミュニティ貢献者

The Reach リリース。 v0.16.0 は、Hermes をデスクトップに置きます。 v0.17.0 は、そのリーチがどこまで広がるか、つまり、新しい場所で会話したり、すでに使用しているツールの奥深くまで、そしてチームのために Hermes を実行している人々にまで及ぶかどうかを表します。 Hermes は 2 つの新しいチャネル (Photon 経由の iMessage、および Raft エージェント ネットワーク) に到達し、デスクトップ アプリには実質的な新機能が追加され、サブエージェントはバックグラウンドで実行できるようになり、画像生成は編集することを学習し、xAI Grok サブスクリプションを通じて Cursor の Composer モデルにアクセスできるようになりました。ダッシュボードには完全なプロファイル ビルダーと安全なログインが追加され、スキル ハブ ブラウザーは再構築され、memory ツールは大幅にアップグレードされ、キュレーターはルーチンの実行ごとに補助モデルの予算を費やすのをやめました。 300 件以上の問題がクローズされ、セキュリティ ラウンドも行われます。

✨ ハイライト

  • Hermes が iMessage に到達 — Photon Spectrum、Mac リレーは不要 — Photon のマネージド ライン プール上に iMessage プラットフォーム プラグインが構築されました。 hermes photon login を実行し、デバイス コードで認証すれば、Hermes は iMessage を送受信できるようになります。クローゼットの中に置いてリレーを実行している Mac も、子守りをする BlueBubbles ブリッジも必要ありません。これは BlueBubbles の後継として位置付けられており、無料で開始でき、自己ホストする必要はありません。あなたの友人や家族が青い泡に住んでいるなら、エルメスも今そこに住んでいます。 (#32348、#42582、#44713 — @teknium1)
  • Raft — Herme がゲートウェイ チャネルとして Raft エージェント ネットワークに参加します — 新しいバンドルされた Raft プラットフォーム アダプターにより、Hermes はウェイク チャネル ブリッジを介して外部エージェントとして Raft に接続できます。 RAFT_PROFILE を設定し、ブリッジを実行すると、Raft がメッセージを処理するために Herme を起動できるようになります。これは、ウェイク ペイロードがメタデータ (イベント ID、タイムスタンプ) のみを保持し、メッセージ本文を保持しない契約によるプライバシー設計を採用しています。エルメスが現れて仕事をすることができるもう一つの表面。 (#48210 — @xxchan、@teknium1)
  • 大幅に機能が向上したデスクトップ アプリ — v0.16.0 にはデスクトップ アプリが同梱されました。 v0.17.0 は、数十の PR にわたってそれを深めました。再バインド可能なキーボード ショートカット、タイプごとの切り替えを備えたネイティブ OS 通知、委任されたエージェントのアクティビティを独自のペインにストリーミングするライブ サブエージェント ウォッチ ウィンドウ、モデルごとのプリセットを備えたコンポーザー モデル セレクター、自動 RTL/BIDI テキスト方向、サイズ変更可能な VS Code テーマのターミナル ペイン、スレッドごとのコンポーザー ドラフト、任意の VS Code Marketplace テーマをアプリに直接インストールする機能。デスクトップは現在、プレビューではなく、日常の重要な推進力となっています。 (#45866、#40660、#47060、#46959、#43292、#44596 — @OutThisLife、@teknium1)
  • バックグラウンド/非同期サブエージェント - 作業を委任して続行 - delegate_task(background=true) は、バックグラウンドで実行され、すぐにハンドルを返すサブエージェントをディスパッチするようになりました。あなたとモデルは、モデルが動いている間も作業を続け、完了した瞬間に完全な結果が新しいターンとして会話に再び入ります。長い調査や複数ステップの構築を開始してから、立ち止まって待っているのではなく、別のことに取り組んでください。 (#40946、#46968 — @teknium1)
  • 画像を生成するだけでなく編集する - image_generate の画像から画像へ - image_generate は、ソース画像を最初から作成するだけでなく、編集および変換できるようになりました。既存のイメージとプロンプトを渡すと、サポートされているすべてのイメージ プロバイダーにわたって、バックエンドの編集エンドポイント (video_generate と同じツール、同じパターン) にルーティングされます。 「このロゴを青にする」、「背景を削除する」、「このスケッチをレンダリングに変換する」など、すべてすでに使用しているツールから実行できます。 (#48705 — @teknium1)
  • オートメーション ブループリント — cron を学習せずにスケジュールを設定 — オートメーションを名前で選択すると、Hermes が必要なものを尋ねます。cron 構文や slot=value の入力は必要ありません。 1 つのブループリント定義は、ダッシュボードのフォーム、CLI/TUI/メッセンジャーのスラッシュ コマンド、エージェントとの会話、ドキュメント カタログのエントリなど、あらゆる面でネイティブにレンダリングされます。 「毎日午前8時のニュースブリーフィング」は、0 8 * * *を暗記するのではなく、質問に答えることで設定するものになります。 (#41309 — @teknium1)
  • xAI Grok サブスクリプションを介したカーソルの Composer モデル — grok-composer-2.5-fast が xAI OAuth モデル ピッカーに表示され、そのコンテキスト ウィンドウは 200k まで調整されています。 Composer は Cursor の背後にある高速コーディング モデルです。xAI Grok サブスクリプションをお持ちの場合は、個別の API キーを必要とせずに、OAuth 経由で直接 Hermes を指定できるようになります。 Grok プラン、Hermes のエージェント ループ、Composer のコーディング速度。 (#47908、#6f89e17 — @teknium1)
  • ダッシュボードの完全なプロファイル ビルダー - config.yaml を手動で編集することなく、ブラウザから完全な Herme プロファイルを構築します。モデルを選択し、スキルを選択し、MCP サーバーを接続します。また、ダッシュボードでは、グローバル プロファイル スイッチャーを使用してマルチプロファイル管理を 1 つのマシン全体のビューに統合したため、すべてのプロファイルを 1 か所から管理できます。 (#39084、#44007 — @teknium1)
  • スキル ハブ ブラウザの再構築 — ダッシュボードのスキル ハブは根本的に作り直されました。接続されたハブ、注目セクション、インストール前の完全なスキル プレビュー、および各スキルのセキュリティ スキャンです。 trusted タップ (OpenAI、Anthropic、HuggingFace、NVIDIA) からのスキルの参照とインストールは、フラットなリストではなく、実際の参照エクスペリエンスになりました。 (#40384、#43398 — @teknium1)
  • memory ツールはメジャー アップグレードされました - アトミックなバッチ操作 - memory ツールは、*最終的な文字バジェットに対して**アトミックに編集の追加/置換/削除のバッチを適用する operations 配列を追加しました。このモデルはスペースを解放し、1 回の呼び出しで新しいエントリを追加できます (追加だけでは予算をオーバーする場合でも)。これまで脆弱だったマルチターン ダンスを 1 回の信頼できる操作に集約します。メモリの更新が高速になり、編集中に失敗する可能性が大幅に低くなりました。 (#48507 — @teknium1)
  • 安全なダッシュボード ログイン — ダッシュボードの認証が強化されました。トークンが必要なすべてのエンドポイントが OAuth ゲートの背後で 401 を正しく返すようになり、WebSocket 認証では提供されたダッシュボード トークンが使用され、public_url オーバーライドがサイレントに拒否されると警告が表示されます。デフォルトでは、ダッシュボードをネットワークに公開する方が安全です。 (#42578、#42578 — @benbarclay、@teknium1)
  • 公式 WhatsApp Business Cloud API アダプター — 既存の Baileys ブリッジと並んで、Hermes は 公式 WhatsApp Business Cloud API — Meta のファーストパーティ、ホスト型、ブリッジプロセスのないパスを使用できるようになりました。 Business API 認証情報をポイントすると、Hermes はサポートされているチャネルを通じて WhatsApp と通信します。QR スキャン ブリッジ プロセスを維持する必要はありません。 (#44331、#43921 — @jquesnelle、@teknium1)
  • Telegram のリッチ テキスト — ボット API 10.1 リッチ メッセージ — Telegram の返信は、Bot API 10.1 経由で適切なリッチ メッセージとしてレンダリングされるようになりました。書式設定が改善され、よりクリーンな長いメッセージ処理が行われ、フラット化されたテキストではなくネイティブ マークアップが行われます。これはデフォルトでオプトアウト付きでオンになっているため、設定をしなくても Telegram の会話は本来のとおりに表示されます。 (#44829、#45584、#45953 — @teknium1)
  • キュレーター コストの最適化 — ルーチンの実行に補助モデルの支出が不要 — スキル キュレーターはデフォルトで古いスキルを削除しますが、オプトイン (curator.consolidate: true または hermes curator run --consolidate) しない限り、LLM を利用した統合パスは実行されなくなりました。確定的な非アクティビティ スイープは無料で実行され続けます。独断的で補助モデルに支出する「傘スキルの構築」フォークはデフォルトでオフになりました。定期的なバックグラウンド キュレーションには トークンはかかりません。 (#47840 — @teknium1)

🔧 ツール システム、スキル、MCP

  • すべてのバックエンドにわたる image_generate の 画像間 / 編集;プロバイダーの寸法制限まで画像を縮小 (#48705、#45979 — @teknium1)
  • MCP: カタログ内の公式 Unreal Engine 5.8 MCP サーバー。 引き出しハンドラ。これにより、MCP サーバーは、セッションを所有するサーフェス (CLI/TUI/Telegram/Slack) でツール呼び出し中の確認 (支払い/OAuth) を求めることができます。ターン間で遅延接続 MCP ツールをエージェントに公開します (キャッシュセーフ)。短い TTL HTTP セッションのキープアライブ ping。 exfil 形状の / 疑わしい stdio 構成をプローブ前にブロックします。機能ゲート tools/list なので、プロンプトのみのサーバーが接続します。 stdio argv パススルー + Windows 環境変数を保持 (#48397、#49203、#49208、#49221、#46083、 #44550、#44324 — @teknium1、@lgalabru)
  • スキル: simplify-code スキル (3 エージェントの並列コード レビューとクリーンアップ) + Chesterton's Fence を使用したリスク階層化アプリケーション。ユーザーが変更したバンドルされたスキルを検索および比較します。オプションの 支払い スキル (Stripe Link、MPP、プロジェクト)。 CLIベースのショップスキル。ソースごとのライブ閲覧進行状況 (#41691、#49070、#48286、#31343、#47309、#43398 — @teknium1、 @コリンレンストライプ)
  • キュレーター: スキル統合をオプトインにする (プルーンはデフォルトでオンのまま) (#47840 — @teknium1)
  • プラグイン: リポジトリ内のサブディレクトリからインストールします。ブラウザーで貼り付けられた GitHub URL を hermes plugins install で受け入れます。エージェント:開始/終了コンテキスト内の session:compress ライフサイクル イベント + thread_id/chat_type (#42963、#33539、#47252、#41672 — @teknium1)
  • メモリ/スキル 書き込み承認 ゲート (デフォルト オフ) — ブール値 write_approval がトライステート write_mode を置き換えます (#38199、#43354 — @teknium1)
