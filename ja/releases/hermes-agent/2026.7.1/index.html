エルメスエージェント v2026.7.1

#エルメスエージェント v0.18.0(v2026.7.1) 発売日: 2026 年 7 月 1 日 v0.17.0 以降: ~1,720 コミット · 998 マージ PR · 2,215 ファイル変更 · ~251,000 挿入 · ~41,000 削除 · 949 件の問題が解決されました · 370 人以上のコミュニティ貢献者

判決のリリース。 過去 1 週間半にわたり、チームはほぼすべての努力を 1 つの目標に費やしました。すべての P0 および P1 の問題と、Hermes Agent リポジトリ全体の PR を解決することです。** — そしてこのリリースの時点で、それらの 100% はクローズされています。 オープン P0 はゼロです。開いている P1 はゼロです。これは、~1,950 件の合計問題の一部としてクリアされ、PR がこの期間を終了した ~700 件の最も優先度の高いアイテムです。今後は P0/P1 をゼロに保つつもりです。

v0.18.0 は、そのクリーンなスイープに加えて、Hermes がどのように よく考えているのか、そしてどのようにして *仕事が実際に完了したのかをどのように認識しているのかについて述べています。 Mixture-of-Agents は、他のモデルと同様に選択できるモデルの名前付きアンサンブルであり、すべての参照モデルの推論が表示され、アグリゲーターの回答がライブでストリーミングされる、第一級市民になりました。エージェントは雰囲気ではなく証拠に照らして自分の仕事を検証することを学び、/goal は完了契約を獲得し、/learn + /journey は自己改善を目に見えて操縦できるものに変えました。その下で、ゲートウェイは真に大規模に展開可能 (ゼロへのスケール、ドレイン調整)、デスクトップは一流のコーディング プロジェクトと再生可能なメモリ グラフを成長させ、サブエージェントはバックグラウンドでファンアウトできるようになりました。

🎯 P0/P1 クリーン スイープ — 100% 解決

これがリリースの見出しです。 1 週間半にわたり、チームは昼夜を問わず優先度の高いバックログを処理し、リポジトリ全体のすべての P0 と P1 が現在クローズされています。 |優先順位 |終了した問題 | PR が統合されました | |---|---|---| | P0 (重大) | 3 | 8 | | P1 (高) | 493 | 188 | | 合計 | 496 | 196 | これは、12 日間で ~692 個の最も優先度の高いアイテムが解決されたことになります。そして、スイープが完了した瞬間、オープン P0/P1 数はリポジトリ全体で 0 に達しました。 最後に発生したクラスターは、割り込み保護された圧縮兄弟フォークのバグ (問題 #56391) とその修正 (#56416) で、このリリースの直前に徹夜でクローズされました。 @kshitijk4poor に特別なエールを送ります。彼はコア チームとともに昼夜を問わず優先バックログを消化しました。cron の信頼性の波、圧縮フォークの修正、認証情報の Exfil の強化、および P1 クロージャの大部分は彼のものです。 今後は P0/P1 を 0 に維持します。 🫡

✨ ハイライト

  • エージェントの混合は選択できる最上級のモデルになりました — 以前は MoA を切り替えるモードでした。すべての名前付き MoA プリセットが、moa プロバイダーの下で選択可能なモデルとして、すべてのモデル ピッカー (CLI、TUI、デスクトップ、ゲートウェイ) で Claude、GPT、Grok と並んで表示されるようになりました。他のモデルを選択するのと同じ方法で「my-council」を選択すると、Hermes はそのアンサンブルを通じてプロンプトを自動的にルーティングします。あらゆる面で、最も難しい質問を検討するフロンティア モデルのアンサンブルが、あと 1 つ選択するだけで完成します。 (#46081、#53548、#53561 — @teknium1)
  • すべてのモデルの推論を確認してから、応答ストリームを監視 — MoA アンサンブルが実行されると、各参照モデルの完全な出力が独自のラベル付きブロックとしてレンダリングされるようになりました。アグリゲーターがそれらを 1 つの応答に合成する前に、GPT-5 が何を考えたか、Claude が何を考えたか、Grok が何を考えたかを読み取ることができます。そして、その最終的な答えは、長い沈黙の後に一度に現れるのではなく、ライブでストリーミングされるようになりました。これは、CLI、TUI、およびデスクトップ アプリで機能します。評決を読むだけでなく、委員会の審議を見ることができます。 (#53793、#53855、#55625、#56101 — @teknium1)
  • エージェントは自身の作業を検証します。「完了」とは、主張ではなく証明されたことを意味します。Hermes はコーディング作業の検証証拠を記録し、成功を宣言するのではなく、実際にプロジェクトのチェックを実行することによって作業が終了したと判断できるようになりました。 /goal は 完了契約 を獲得しました。「完了」がどのようなものかを明示すると、スタンディング ゴール ループは、モデルがその気になれば停止するのではなく、その証拠に照らして完了を判断します。カスタム チェックでの配線用の pre_verify フックと、デフォルトを適切に調整する 1 回限りの移行があります。 「修正できたと思います」と「テストに合格しました。これが証拠です」の違い。 (#50501、#52285、#55413、#53552 — @teknium1、@OutThisLife)
  • /learn — 記述することであらゆるものを再利用可能なスキルに変換します — /learn <anything> を実行すると、Hermes は、ディレクトリ、URL、または 5 分前に実行したワークフローなど、指定したものから再利用可能なスキルを抽出します。 CONTRIBUTING.md の標準に従ってスキルが自動的に書き込まれます。次回そのワークフローが必要になるときには、それはすでに存在しています。ヘルメスに新しいトリックを教えるのは、手動のスキル作成セッションではなく、単一のコマンドになりました。 (#51506、#52372 — @teknium1)
  • /journey — ヘルメスがあなたについて学んだすべての再生可能なタイムライン — CLI と TUI は、ヘルメスが時間の経過とともに蓄積した記憶とスキルを示す学習タイムラインである /journey を取得しました。これらはいずれもビューから直接編集または削除できます。これをデスクトップの新しい メモリ グラフ (トップダウンで再生可能な、記憶とスキルの放射状タイムライン) と組み合わせることで、エージェントが何を知っているかを実際に 確認し、その成長を観察し、問題を取り除くことができるようになります。エージェントの記憶はブラックボックスではなくなります。 (#55555、#55859、#55226 — @OutThisLife)
  • 山積みの作業を委任して作業を続ける - バックグラウンド ファンアウト - delegate_task は、すべて バックグラウンド で実行される複数のサブエージェントをファンアウトできるようになりました。チャットがブロックされることはなく、すべてのサブエージェントが終了すると、その結果が 1 つの統合されたターンとして返されます。 「これら 5 つの競合他社を並行して調査する」または「これら 3 つのモジュールを監査する」を開始し、小規模なフリートが機能している間に別の作業を続けます。すべて完了すると、いちいち面倒をみることなく、きれいな要約が 1 つ得られます。 (#49734 — @teknium1)
  • デスクトップ アプリの最上級のコーディング プロジェクト — デスクトップ アプリには、実際のプロファイルごとの プロジェクト - コードベースのサイドバー、コーディング レール、レビュー ペイン、git ワークツリー管理、エージェント向けプロジェクト ツールがすべて適切な project → repo → lane モデルによってサポートされています。分散したチャット セッションの代わりに、コーディング作業はエージェントが理解し、実行できるプロジェクトに編成されます。デスクトップが実際のコーディング コックピットに変わります。 (#49037、#54385、#54517 — @OutThisLife)
  • Hermes を大規模に実行 — ゼロへのスケールとドレイン調整 — ゲートウェイは、アイドル時には休止状態になり、再起動、移行、または自動更新の前に、処理中の会話を中断することなく完全に静止できるようになりました。ホスト型またはリレー専用の Hermes は、誰も話しかけていないときにゼロにスケールし、オンデマンドで起動し、破壊的なライフサイクル アクションによって外部の排水が調整されるため、ターンの途中で切断されることはありません。チームまたはホストされたサービスとして Herme を実行すると、実稼働グレードが大幅に向上します。 (#52243、#52937、#54824 — @teknium1、@benbarclay)
  • 低コストの自己改善 — よりスマートな背景レビュー — ターン後の自己改善フォーク (記憶またはスキルを保存するかどうかを決定するフォーク) は補助モデルにルーティングされ、会話全体を再生するのではなくコンテキストを消化し、リズムを調整するようになりました。そのため、ターン後に実行される「今起こったことから学ぶ」ループのコストは、以前の何分の 1 かになりました。自己改善を継続し、そのためにメインモデルの全額を支払うのをやめます。 (#49252 — @teknium1)
  • エディターで次のプロンプトを作成します — /prompt — /prompt は $EDITOR を開くので、1 行の入力ボックスと格闘する代わりに、実際のマークダウンで長い複数行のプロンプトを手書きできるようになります。詳細な仕様、構造化された質問、または大きなペーストを作成して保存すると、次のメッセージとしてキューに追加されます。一度に 1 文以上のエルメスを書く人にとっては、小さなことですが、生活の質が大きく向上します。 (#50509 — @teknium1)
  • Google Vertex AI — GCP サービス アカウントを介した Gemini、静的キーなし – Vertex AI は、Vertex の OpenAI 互換エンドポイントを介した Gemini モデルのファーストクラス プロバイダーになりました。プレーンなカスタム プロバイダーのセットアップがセッション中に常に終了する理由は、Vertex に静的な API キーがないためです。すべてのリクエストには、サービス アカウント JSON またはアプリケーションのデフォルト資格情報から作成された、有効期間の短い OAuth2 アクセス トークン (~1 時間の TTL) が必要です。 Herme はこれらのトークンを作成して自動更新するようになりました。そのため、組織で Google Cloud 経由で Gemini を実行している場合は、Hermes にサービス アカウントを指定するだけで機能します。トークンの貼り付けやセッション中の有効期限はありません。 (#56363 — @teknium1、@slawt)
  • セキュリティ ラウンド — このウィンドウはいくつかの面を強化しました。MCP 構成永続性攻撃面のロックダウン、プロバイダー資格情報の漏洩の可能性がある cron base_url オーバーライドのブロック、ファイル読み取りのプレフィックス シークレットに対する再利用不可能なセンチネル、Slack アプリレベル (xapp-) トークンの編集、すべてのバックエンドで強制されるブラウザ クラウド メタデータ フロア、および aiohttp CVE フロアです。遅延メッセージング パスを介して。プロンプト挿入または誤って設定されたセッションによって資格情報が漏洩する方法が少なくなります。 (#50476、#56196、#54166、#56227、#52349、#56237 — @teknium1、 @kshitijk4poor、@claudlos)

🧠 混合薬剤 (MoA)

MoA は、このウィンドウでモードからモデル システムのファーストクラスの部分に卒業しました。

  • 選択可能な仮想モデルとしてのプリセット - 名前付きの各 MoA プリセットは、プロバイダー moa の下にモデルとして表示されます。任意のモデル ピッカーで選択すると、Hermes がアンサンブルを通じてルート化されます (#46081、#53561、#53775 — @teknium1)
  • /moa はワンショット シュガーになりました。デフォルトのプリセットを使用して 1 つのプロンプトを実行し、その後モデルを復元します。永続的な切り替えはモデル ピッカーを経由します (#53548 — @teknium1)
  • 参照モデルの出力は、CLI、TUI、デスクトップでラベル付きブロックとして表示 — アグリゲーターの合成前に各モデルの推論を読んでください (#53793、#53855 — @teknium1)
  • アグリゲーターの応答は、沈黙の後に完全に表示されるのではなく、ライブでストリーミングされます (#55625 — @teknium1)
  • 参照はツールの完全な状態を参照し、ユーザー/ツールの応答ごとに起動します。アドバイザリー参照はユーザーターンで終了し、参照ロールシステムプロンプトを取得します (#54016、#54007 — @teknium1)
  • デバッグと評価のために JSONL (moa.save_traces) へのフルターン トレース永続性をオプトインします (#56101 — @teknium1)
  • 信頼性: プロバイダーの実際のルートを通じて呼び出される参照 + アグリゲーター モデル。アグリゲーターから解決されたコンテキスト ウィンドウ (256K のデフォルトではありません)。補助タスクはアグリゲーターに解決されます。仮想プロバイダーは参照/アグリゲーター スロットとしてブロックされます。手動編集されたプリセット構成 (#53580、#53780、#53827、#53281、#53275、#53556 を許容します — @teknium1)
  • 単一の call_llm チョークポイントで統合された MoA スロット プロバイダー ID。 HermesBench の結果が文書化されました (#55991、#53206 — @teknium1)

  • ワンショット LLM ヘルパー + llm.oneshot ゲートウェイ RPC;コーディング コンテキスト プロジェクトの事実を公開する (project.facts RPC) (#51261、#51259 — @OutThisLife)

  • インプレース圧縮オプション (単一セッション ID)。ガード修正により in_place のデフォルトを True に切り替えます (#49739、#52658 — @teknium1)

プロバイダーとモデル

  • OpenAI 互換エンドポイントを介した Gemini 用 Google Vertex AI ファーストクラス プロバイダー - サービス アカウント JSON / ADC (静的キーなし) から有効期間の短い OAuth2 トークンを自動生成および更新します。 @slawt による #8427 のサルベージと近代化 (#56363 — @teknium1、@slawt)
  • 管理された Nous サブスクリプション ゲートウェイ経由の Krea。 Z.AI エンドポイント ピッカー (グローバル/中国/コーディング プラン); Ollama クラウド推論_努力配線。 google-gemini-cli + google-antigravity OAuth プロバイダーを削除します (#52647、#52364、#51494、#50492 — @teknium1、@kshitijk4poor)

🌐 ゲートウェイ、フリート、リレー

ゼロへのスケールとドレイン

  • ゼロへのスケール アイドル検出 + 休止静止 (フェーズ 0);強化された休眠ガード。アームゲートカウントが無効になったプレースホルダープラットフォームを修正 (#52243、#52359、#52831 — @teknium1、@benbarclay)
  • 外部ドレン調整 (安全シャットダウン フェーズ 2);フラグが立てられたドレインでのホームチャネルシャットダウンブロードキャストを抑制します。再起動/シャットダウンのドレインタイムアウト時に飛行中のトランスクリプトを保持します。安全なライフサイクルアクションのためのビジー/アイドル読み取り (#52937、#54824、#50312、#50131 — @teknium1、@benbarclay、@kshitijk4poor)
  • systemd クラッシュ ループを停止するには、デフォルトの restart_drain_timeout を 0 に設定します。ドレイン/劣化で立ち往生したゲートウェイを自己修復 (#54066、#55397 — @teknium1)

リレー (フェーズ 5 / 6)

  • ウェイクプリミティブ (ゲートウェイ側);アイドル状態/バッファーフリッププリミティブ。 WS 経由の passthrough_forward。エージェントごとのマルチプラットフォーム ID + フレームごとの出力。自己プロビジョニング時の前方安定インスタンス ID。コネクタへの関連性ポリシーを宣言します (#51595、#51572、#50702、#52830、#50772、#51248 — @benbarclay)
  • source.platform ではなく、配信によってリレー配信イベントを承認します。 scope_idワイヤーキーを採用。パージ プラットフォーム固有のスコープ用語 (#52306、#55289、#56016 — @benbarclay)

ゲートウェイ コアとレンダリング

  • 入力された送信エラー分類 (SendResult.error_kind);プラットフォームごとの typing_indicator 切り替え。 /usage のカテゴリごとのコンテキストの内訳 (#50342、#55394、#55204 — @teknium1)
  • API サーバー: DoS を防ぐための構成可能な同時実行上限。実行 ID 別のスコープ実行承認 (#50007、#56129 — @teknium1)

📱 メッセージング プラットフォーム

  • Cron 継続 — 継続可能な cron ジョブ (DM ミラー フォールバックを使用したスレッド優先継続)。 Slack 向けのフラットなチャネル内継続可能な cron 配信。 cron create/list でゲートウェイが実行されていない場合に警告する (#52250、#56254、#51696 — @teknium1)
  • Telegram: 設定可能なコマンド メニュー + デフォルトの上限が引き上げられ、スキルが表示されたままになります。リッチなドラフトプレビューを個別にゲートします。再試行前のプールタイムアウト時に一般送信プールをドレインします (#51716、#52088、#54121 — @teknium1、@helix4u)
  • Slack: エージェント メッセージのブロック キット レンダリングをオプトインします。マニフェスト生成用の --no-assistant フラグ (#56102、#51487 — @teknium1)
  • Discord: display.reasoning_style 経由で推論を -# サブテキストとしてレンダリング (#51168 — @teknium1)
  • Baileys ブリッジ経由のネイティブ WhatsApp メディア配信。チームネイティブ send_video/send_voice/send_document;フォトン サイドカーがタップバック相関を備えた spectrum-ts v8 にアップグレードされました。 Raft ゲートウェイ セットアップ ウィザード (#53598、#49308、#53451、#56230 — @teknium1)
  • 信号: AAC ボイスノート リマックス + 共有マークダウン形式 (#49530 — @kshitijk4poor) -lack/dingtalk/whatsapp/matrix/feishu/telegram/wecom/email/sms アダプターをバンドルに移行 (#49408 — @teknium1)

🔧 ツール システム、スキル、MCP

  • MCP: 構成永続性の攻撃面が強化されました。ブロックbase_url exfil;短い TTL セッション用のキープアライブ (「セキュリティ」を参照) — 加えて、v0.17.0 から引き継がれたカタログと UX
  • スキル: /learn 蒸留 (自己改善を参照); cloudflare-temporary-deploy オプションスキル; Creative-ideation v2.1.0 メソッド ライブラリ (#50849、#42402 — @teknium1、@SHL0MS)
  • カンバン: タスクのライフサイクル プラグイン フック (要求/完了/ブロック)。型指定されたブロック理由 + ブロック解除ループ ブレーカー。ハンドオフ鮮度スタンピング (#50349、#52848、#53973 — @teknium1)

  • コールド スタート: 遅延ロード ゲートウェイ プラットフォーム アダプター。 libyaml CSafeLoader を使用して構成 + プラグイン マニフェストを解析します (#54448、#54486 — @teknium1)
  • 状態: FTS5 セグメント + handoff_state インデックスをマージして、書き込みロックの競合を抑制します。シングルパス list_profiles エイリアス マップ + スキルカウント キャッシュ + イベント ループ オフロード (#54752、#54770 — @kshitijk4poor、@teknium1)

🔒 セキュリティと信頼性

  • MCP 構成永続性の攻撃対象領域を強化します。プロバイダーの資格情報を漏洩する cron base_url オーバーライドをブロックします。ファイル読み取り内のプレフィックス シークレットの再利用不可能なセンチネル (#50476、#56196、#54166 — @teknium1、@kshitijk4poor)
  • Slack アプリレベル (xapp-) トークンを編集します。すべてのバックエンドのブラウザ クラウド メタデータ フロア (CDP 非ローカル)。 browser_back ナビゲーション後にプライベート ネットワーク ガードを再確認します。範囲 /resume および /sessions を呼び出し元 (IDOR) に設定します。 aiohttp 3.14.1 遅延メッセージング パス全体の CVE フロア + ピン ドリフト ガード (#56227、#52349、#56526、#56378、#56237 — @teknium1、@claudlos、@kshitijk4poor)
  • Cron 信頼性ウェーブ: 固定されていないジョブのプロバイダーがドリフトするとフェールクローズされます。猶予期間を逃したジョブを永久に延期するのではなく、一度実行します。 BaseException + ハートビート認識ステータスでティッカーを維持します。有効な MCP サーバーをジョブごとのツールセットにレイヤー化します。ガード cron モデル ツール パス + 自動再開ループ ブレーカー (#51051、#50062、#50016、#50117、#56240 — @kshitijk4poor、@teknium1)
  • Windows: コンソールのフラッシュを抑制し、ゲートウェイの再起動を強化します。 PATH フォールバックでは cmd npm shim を優先します。 GUI の更新後にゲートウェイをウィンドウレスで再起動します。 whatsapp/デスクトップの管理対象ノードを優先します (#52340、#50398、#52239 — @helix4u、@teknium1)
