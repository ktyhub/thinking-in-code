#ナマケモノv0.1.911-beta

このリリースでは、スケジュールされたタスク、FLUX-3 編集サポート、パフォーマンスの改善などが追加されています。また、新機能: MiniMax-M3.1-Flash、画像の顔修正、Mac での高速パフォーマンス + チャット。

ハイライト

  • スケジュールされたタスク: ローカル モデルまたは API を使用して、スケジュールに従ってプロンプトを実行します。
  • MiniMax-M3.1-Flash: MiniMax の 428B MoE (23B アクティブ) ガイド
  • FLUX 3 編集: FLUX 3 は、プロンプト付きの画像編集をサポートするようになりました。
  • パフォーマンスの向上: Mac のパフォーマンスが大幅に向上し、遅延が減少し、バイナリ サイズが減少しました。
  • 保存されたプリセット: 実行設定を各モデルの名前付きプリセットとして保存します。

スケジュールされたタスク

  • サイドバーの「その他」メニューから「スケジュール」を開き、プロンプトを 1 回、毎日、平日、毎週、または毎月実行します。各回答は新しいチャットとして保存されます。
  • 各タスクは、ロードされたモデル、デバイス上のモデル、または接続された API プロバイダーからのモデルで実行できます。
  • タスクのモデルがロードされていない場合、不在時に自動的に切り替える をオンにしない限り、Unsloth はモデルをロードする前に質問します。
  • 各タスクは、実行のたびに通知することも、失敗した場合にのみ通知することも、まったく通知しないこともできます。
  • タスクは、Unsloth の実行中にのみ実行され、ツールや Web 検索は使用されません。

UI + UX

  • モデルピッカーの実行設定を各モデルの名前付きプリセットとして保存し、名前変更、削除、またはプリセット間の切り替えを行います。
  • 最後に選択したプリセットは、API を介したロードを含め、次回そのモデルにロードされるものになります。
  • チャット設定では、モデルのサンプリング設定を記憶したり、モデルの推奨値にリセットしたりできます。
  • GGUF チャットでは、長いプロンプトの処理中に応答が開始される前に、進行状況と残り時間が表示されるようになりました。
  • API ページには、提供される各モデルのコンテキストの使用状況、速度、リクエスト数が表示されるようになりました。
  • 各種のボタンとアイコンがアプリ内のどこでも同じように見えるようになりました。
  • [設定] の [ライブラリ] ページと [システム] ページには、モデル、キャッシュ、空き領域に分割された使用状況バーとしてストレージが表示されます。

マック

  • MLX チャットは、ドラフト モデルを使用すると最大 16% 速く返信できるようになりました。
  • 組み込みのドラフト モデルが同梱されている MLX モデルは、別途ダウンロードすることなく、自動的にそれを使用するようになりました。
  • 画像とビデオのレンダリングに必要なメモリは最後にはるかに少ないため、メモリの少ない Mac ではスワップによって速度が低下することはほとんどありません。
  • Apple Silicon では、Z-Image GGUF はデフォルトで MLX エンジン (1.5-2x) を使用してテキストから画像を作成するようになり、以前よりも高速になりました。

画像 + ビデオ

  • ビデオ ページで NVIDIA の Cosmos3-Edge を使用してテキストまたは画像からビデオを作成します。
  • 画像ページで、Detailer をオンにして、顔、手、またはその他の指定したものを高解像度で再描画します。 SAM 3 と修復可能なモデルが必要です。
  • RTX 30 シリーズよりも古い NVIDIA GPU では、Wan2.1 1.3B テキストからビデオへの clips レンダリングが約 5 倍高速になります。
  • NVIDIA GPU では、Unsloth が最初の読み込み時にビルドしたバージョンを保存するため、多くの画像およびビデオ モデルの初回以降の読み込みが速くなります。
  • FLUX.3 Klein は、写真の寸法を維持したまま、[画像] > [編集] で写真を編集できるようになりました。

トレーニング

  • LoRA および QLoRA トレーニング用にモデルの各レイヤーを GPU に分割して、各 GPU が保持する量を減らします。UNSLOTH_TP_SIZE を GPU の数に設定し、torchrun で起動します。
  • Unsloth の 4 ビット gpt-oss チェックポイントを微調整しても、最初のトレーニング ステップでクラッシュしなくなりました。
  • vLLM で生成される GRPO は、NVIDIA GPU を搭載した Linux 上の 16 ビット LoRA により、ステップごとに最大 1.9 倍高速に実行されます。
  • vLLM を使用せずに生成された GRPO は、NVIDIA GPU 上の Llama および Qwen3 でステップごとに最大 4.4 倍高速に実行されます。

コーディング エージェント + API

  • Unsloth API キーを使用するアプリは、サンドボックス外で実行する独自の Python または端末呼び出しを承認できなくなりました。
  • Unsloth はデフォルトで rusts が client IP を転送しなくなりました。独自のリバース プロキシの背後で UNSLOTH_STUDIO_TRUST_FORWARDED=1 を設定するか、すべてのユーザーが 1 つのログイン レート制限を共有します。

モデル + ハードウェア

  • 最大 100 万個のコンテキスト トークンを使用して、コーディング、ツールの使用、エージェント ワークフロー用の MiniMax の MoE モデルである MiniMax-M3.1-Flash を実行します。 GGUF
  • 1 ビットでは、MiniMax-M3.1-Flash には少なくとも 130 GB の RAM と VRAM が必要です。
  • 一部の Windows PC では、GGUF モデルが「llama-server failed to start」で毎回失敗するのではなく、再度ロードされます。
