unsloth v0.1.913-beta

#ナマケモノv0.1.913-beta

カスタム背景と改善された UI/UX を使用して、Unsloth を自分のものにしましょう。このリリースでは、VRAM が制限されている場合でも、アプリの更新時間が短縮され、Linux アプリと Qwen-Image の生成が高速化されます。 また、新機能: Unsloth Dynamic v3.1 GGUF の DeepSeek-V4.1-Flash-1017 (プレビュー)、低 RAM マシン上の FLUX.2-klein-9B、よりスムーズなチャット、バッチ化された MoE 微調整。

ハイライト

  • カスタム背景でチャットをパーソナライズ (+ コンポーザーを一番下に移動 - さらなるカスタマイズは来週予定)
  • DeepSeek-V4.1-Flash-1017 新しい Unsloth Dynamic v3.1 GGUF (プレビュー)、ほぼすべてのベンチマークでサイズが最も正確 ブログ
  • Unsloth の 14 の新しい言語
  • アプリのアップデートは 2 倍の速さで完了します
  • Linux 遅延が大幅に減少し、パフォーマンスが向上
  • Qwen-Image は、16 GB の VRAM 制限の下で最大 2 倍高速にレンダリングします
  • インターフェイスを更新し、一貫性とクリーンな UI を実現
  • MoE 微調整 は互換性のある API ジョブを一緒に実行します

カスタマイズとインターフェース

  • [設定] > [チャット] で、Composer を一番下にして、チャット ボックスを新しいチャットの一番下に移動します。
  • 挨拶を完全に非表示にして、新規チャット画面をシンプルにします。
  • ライブラリでは、チャット カードが短くなり、ツールチップが明確になり、並べ替えとフィルターのアイコンが一貫して表示されます。
  • 入力スロット間で画像をコピーするには、入力スロットを空のスロットにドラッグします。
  • ピン留めされたモデルは、Unsloth Desktop を再起動しても保存され続けます。
  • 各ブラウザ タブには、独自の未送信メッセージが保持されます。
  • NVIDIA、X11、ドライバー 610+ を搭載した Linux では、長いチャットのスクロールがよりスムーズになります。高解像度テストでは、約 17 fps から 60 fps に向上しました。

画像とビデオ

  • FLUX.2-klein-9B は、12.7 GB のシステム RAM とサポートされている GPU を備えた Linux 上でロードおよびレンダリングできるようになりました。
  • Qwen-Image-2512 は、16 GB VRAM 制限の下で最大 2 倍高速にレンダリングします。
  • Qwen-Image-Edit-2511 は、同じ制限の下で約 1.3 倍高速にレンダリングします。
  • MiniMax-H3 clips は、メモリ制限のある NVIDIA テストで約 1.7 倍高速に終了します。

パフォーマンス

  • Python プリコンパイルをスキップすると、アプリの更新にかかる時間が約半分になります。その代わり、v0.1.912 以前と同様に、その後の初回起動が長くなります。
  • 長い返信は、数学的フォーマットが未完成であっても、よりスムーズにストリーミングされます。野良 $$ を含む 83 KB の応答の解析には、71 秒ではなく 0.7 秒かかりました。
  • 1 GB のローカル Parquet ファイルをプレビューすると、1.5 GB から約 300 MB のピーク メモリが使用されます。
  • Unsloth は、トランスフォーマーと MLX モデルの読み込みが完了しても応答性を維持します。

チャットと API

  • ラマサーバーのクラッシュ後、GGUF モデルがバックグラウンドでリロードされます。
  • GGUF ダウンロードが失敗またはキャンセルされた場合、現在のモデルがロードされたままになります。
  • 非常に長い GGUF チャットは圧縮されて続行できます。
  • ローカル GGUF に直接接続されたクロード コードは、新しいセッション間でキャッシュされたプロンプトを再利用します。
  • 拒否された GGUF リクエストには、一般的なエラーではなく、llama-server の説明が表示されます。

マック

  • Claude Code、Codex、および OpenCode リクエストは MLX バッチを共有できます。私たちのテストでは、4 つの同時リクエストが最大 2.3 倍速く完了しました。
  • 実験的な Neural Engine Prefill プロセスは、M3 Max での Qwen3.8-27B-4bit テストでプロンプトを最大 31% 高速化しました。オプトインなので、返信を若干変更することができます。
  • 自動コンテキストは、65,536 トークン以下で GGUF モデルを開始し、事前のメモリ使用量を削減します。さらに大きなコンテキストを手動で設定することもできます。
  • MLX で LFM3-Audio または LFM3-Omni に音声 clip を送信し、テキストとともにその応答を聞きます。

トレーニング

  • Qwen3.6-35B-A3B などの MoE モデル上の互換性のある LoRA および QLoRA ジョブは、それぞれ独自のアダプターを備えた微調整 API を通じて一緒にトレーニングされます。
  • [トレイン] ページの API 経由で使用すると、セットアップ用の Python、JavaScript、およびカールのサンプルが開きます。
  • 単一列のテキスト データセットは自動的に認識され、手動で列をマッピングする必要はありません。
