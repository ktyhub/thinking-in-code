#ナマケモノv0.1.907-beta

Unsloth のパフォーマンスが大幅にアップグレードされました。

ハイライト

  • 大きなパフォーマンスの向上: すべての Unsloth UI/UX が高速化 - 複数のチャットで最大 10 倍
  • 最大 5 倍高速な推論: 95% のキャッシュ ヒット率、MoE Strata スタイルの修正、速度低下の修正
  • 圧縮の向上 - すべての API で動作 + UI 処理の向上
  • ファイルのドラッグ アンド ドロップ: デスクトップは 3 倍以上のサポート対象ファイルで再び動作します
  • スクリプトでのブラウザの使用: click、マウスを移動、ドラッグし、承認されたスクリプトを実行し、サイトごとのブラウザ ルールを設定します。
  • LTX-2.5 + Wan2.2 + より高速な画像 LoRA トレーニング: 新しいビデオ生成、画像からビデオへの変換、およびより高速な画像トレーニング。
  • NVIDIA RTX Spark: Windows ARM64 ダウンロード可能ファイルでサポートされるようになりました
  • Unsloth ワークフローの主要なアップグレード: ファイル、チャット履歴、ブラウザ エージェント、ドキュメント処理が改善されました。
  • ハードウェア互換性の向上: Windows AMD、Intel XPU、CUDA/PyTorch の修正。
  • アスペクト バケット、AdamW の融合、FP8/MXFP8 サポートの改善による より高速な画像 LoRA トレーニング。

パフォーマンス

  • 大規模なチャットとトレーニング履歴は小さなバッチで読み込まれ、起動データとメモリの使用量が少なくなります。
  • 多くのツール呼び出しを伴う会話を含む、長い GGUF チャットでは、フォローアップの返信がより早く開始されます。
  • LTX-2.5 生成は、メモリが許せばデフォルトの 2 段階設定でより高速に実行されます。
  • Qwen3.5、Qwen3.6、および Qwen3.8 は、MLX を使用してプリフィルと投機的デコードを高速化します。

ブラウザの使用

  • モデルは、キャンバスなどのラベルのないターゲットを含む、ある点で click したり、マウスを移動したり、ページ要素をドラッグしたりできます。
  • 毎回承認を得てページ上でスクリプトを実行するか、[設定] > [ブラウザ] で [スクリプトの実行] を [実行しない] に設定します。
  • ラベルのない click に対してサイトごとのルールを設定します (trust を使用するサイトを常に許可するなど)。
  • 圧縮ページ、client 側のナビゲーション、Web UI での遅延コンテンツの処理が改善されました。モデルは日付と時刻のフィールドに入力することもできます。
  • フォーム内で Enter キーを押すと、cli の送信ボタンをクリックするのと同じ承認チェックが行われます。

画像 + ビデオ

  • LTX-2.5 を使用して、テキストまたは開始画像から同期音声付きのビデオを生成します。 GGUF
  • Wan2.2-TI2V-5B、LTX-2、または LTX-2.3 を使用して開始フレームを追加し、同じロードされたモデル上の画像をアニメーション化します。
  • 画像ページで SDXL サンプラーとスケジュールを選択し、v 予測チェックポイントを正しくロードします。
  • 生成前に画像入力をトリミングします。大きな写真のアップロードと通常のビデオ フレームのアップロードでは、サイズが自動的に変更されます。

トレーニング

  • 画像 LoRA トレーニングは、NVIDIA GPU 上でデフォルトで融合された AdamW を使用し、新しくサポートされる実行にはアスペクト比バケットが使用されます。
  • FLUX および Z-Image の FP8 LoRA トレーニングでは、NVIDIA Ada、Hopper、Blackwell GPU で使用するメモリが少なくなります。 MXFP8 は、互換性のある torchao スタックを使用して Blackwell 上のアスペクト バケットを処理します。
  • サポートされている画像トレーニング中および実行履歴でプレビュー画像を表示するには、[トレーニング] タブで [サンプル間隔] を設定します。
  • 画像の [トレイン] タブで、キャプション ドロップアウト、LoRA ドロップアウト、チェックポイント保持を設定します。ランダムな反転がオプトインになりました。
  • Transformers 5 と GPTQModel を使用して LoRA で AWQ モデルを微調整し、量子化された重みとして INT4 QAT モデルをエクスポートします。

チャット + デスクトップ

  • 他の Office ドキュメント、テンプレート、EPUB、README ファイル、ドットファイル、メディアなどのファイルをデスクトップ チャットに再度ドラッグします。
  • Web UI でサポートされている PDF および Office ドキュメントを最大 200 MB アップロードします。
  • リンクされたフォルダーは共通の .gitignore ルールに従います。ブラウザからフォルダーをプロジェクト ソースにアップロードし、失敗したアップロードを再試行して、完成したソースを開きます。
  • /rewind と入力するか、メッセージの [その他] メニューから [巻き戻し] を選択して、会話、チャット フォルダー内の追跡ファイル、またはその両方を復元します。変更をプレビューし、復元を元に戻します。
  • 次のメッセージのコンテキストを圧縮するツールをサポートする、保存された GGUF または MLX チャットで /compact を使用します。インラインディバイダーは圧縮をマークします。
  • ツールの結果からモデル作成ファイルをダウンロードし、バックグラウンド応答が終了したときの通知を有効にします。

モデル + 設定

  • unsloth start vscode との VS Code Copilot Chat でローカル モデルを使用します。
  • コーディング エージェントは、アカウント API キーを使用して Unsloth over MCP を使用して、モデルの読み込み、生成、トレーニング、エクスポートを行うことができます。
  • モデルのダウンロード フォルダーを選択し、LM Studio、Ollama、および独自のフォルダーからリストされたモデルを公開または削除します。

ハードウェアの互換性

  • Windows AMD システムでの PyTorch/Triton 起動エラーを修正。
  • Intel XPU は、Intel-ocloc なしでサポートされている Arc および Data Center GPU 上のネイティブ BF16 を認識し、シングルタイル Linux ホストでの GPU 選択が改善されました。
  • CUDA システムで Python バージョンを切り替えた後の古い Triton ランチャー エラーを回避します。
  • Windows および WSL でのホスト メモリ オフロードを含む、低 VRAM Gemma 4 E2B ロードの改善。
