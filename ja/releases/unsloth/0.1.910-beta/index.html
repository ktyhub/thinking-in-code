#ナマケモノv0.1.910-beta

Recursive の Flint、MOSS-Image、NVIDIA の Nemotron Bolt 4B が登場しました。 Unsloth でローカルに実行します。また、チャット専用の Unsloth デスクトップ インストール、Mac のメモリより大きい MLX MoE モデル、および OpenAI 互換の微調整 API も新機能です。

ハイライト

  • Mac 上のより大きな MoE モデル: MLX MoE モデルはメモリに対して大きすぎるため、エキスパートは SSD を使用し続けるため、Qwen3.8-Flash-Next は 32 GB Mac で実行されます。
  • チャット専用インストール: GGUF チャット用のはるかに小さい Unsloth デスクトップ。後で設定でトレーニングを追加します。
  • Flint: Recursive の 40B コーディング エージェント MoE、3 ビットで 24 GB で実行 ガイド
  • MOSS-Image: 最上位世代向けに設計された 5.1B イメージ モデル GGUF + FP8
  • NVIDIA Nemotron 3.5 Bolt E4B: NVIDIA の新しい Gemma 4 E4B 微調整、Tau2-Bench の 63.2 とオリジナルの 38.7 ガイド
  • MoE エキスパートの枝刈り: REAP を使用して、最も有用性の低いエキスパートの 25% または 50% を削除して、より小規模な MoE モデルをエクスポートします。
  • UI のオーバーホール: Unsloth 全体でより一貫性のある新しい UI (API、丸みなど)

画像 + ビデオ

  • OpenMOSS の 5.1B MOSS-Image、SFT、または Base を使用して、英語または中国語のテキストを含む画像を生成します。 【GGUF】(https://huggingface.co/unsloth/MOSS-Image-SFT-GGUF)・【ベースGGUF】(https://huggingface.co/unsloth/MOSS-Image-Base-GGUF)
  • 新しいイメージ モデルである MOSS-Image は、16 GB GPU で実行されます。その GGUF は、サポートされている GPU のない Mac やコンピュータでも実行できます。
  • 1 つの GPU には大きすぎるほとんどの画像およびビデオ モデルは、システム メモリからストリーミングするのではなく、適合する場合は NVIDIA GPU 全体に分割されるようになりました。
  • 新しい Hires 修正は、SDXL、FLUX.1、Qwen-Image、Z-Image でワンステップでレンダリングをアップスケールおよび洗練します。
  • 新しい比較グリッドは、ラベル付きグリッドでシード、CFG、LoRA 重みなど、最大 3 つの設定を変更しながら 1 つのプロンプトをレンダリングします。
  • SDXL セーフテンサーは、AUTOMATIC1111 スタイルのプロンプト重み付け、CLIP スキップ、CFG 再スケール、バリエーション シード、テキスト反転を取得します。
  • AUTOMATIC1111、Forge、または Civitai パラメータ ブロックを貼り付けて、[イメージ] ページの設定を埋めます。
  • SAM 3 がまだダウンロードされていない場合、テキストからマスク ツールは SAM 3.1 を使用するようになりました。SAM 3.1 は小さく、Hugging Face ログインはありません。

チャット + デスクトップ

  • はるかに小規模なインストールのために Unsloth Desktop を初めて起動するときに、チャットのみ (GGUF) を選択します。後で設定でトレーニングを追加します。
  • [設定] > [チャット] で、Unsloth がすべてのチャットに送信する思い出メモを表示、編集、クリア、またはオフにできるようになりました。
  • 文書検索チャットでは、「パッセージを表示」はモデルが取得した正確なテキストをリストし、各パッセージをそのページで開きます。
  • オーディオ ページでは、OpenAI やローカル サーバーなどの保存された API 接続を介して音声を読み上げたり文字起こししたりできます。
  • Unsloth のインストール、アップデート、pip install -U unsloth は、攻撃者が Web サイトになりすますことを可能にする eMudhra の侵害された emSign 証明書を拒否するようになりました。オプションの vLLM および SGLang エンジンは依然として trust です。

フリント

  • Recursive の Flint を実行します。これは、推論、ツールの使用、および 256K のコンテキストを備えたコーディング エージェント用の 2.5B アクティブ パラメーターを備えた 40B MoE モデルです。 【ガイド】(https://unsloth.ai/docs/models/flint)・【GGUF】(https://huggingface.co/unsloth/flint-GGUF)
  • 3 ビットでは、Flint は短いコンテキストで 24 GB に収まります。
  • SWE-bench Pro v2 では、フリントが 89.7 をスコアし、対クウェン 3.6 が 73.8 を記録しました。

NVIDIA Nemotron 3.5 ボルト E4B

  • ツールの呼び出しと指示に従うための Gemma 4 E4B 推論調整である NVIDIA の Gemma Nemotron 4B を実行して微調整します。
  • Gemma Nemotron 4B は、21 回の NVIDIA テスト中 16 回で Gemma 4 E4B を上回り、ツールの使用とマルチターン チャットで最も多くの成果を上げました。
  • Gemma Nemotron 4B を含む Gemma 4 E2B および E4B の DPO はクラッシュしなくなりました。

＃＃ トレーニング

  • FastModel を使用した Whisper、Canary、Moonshine、Dia、および CTC 音声モデルの微調整が失敗しなくなりました。
  • インコ、カナリア、CTC の音声トレーニングでは、メモリ使用量が最大 55% 削減されます。
  • データ レシピの新しいブックとドキュメントからテキストへのレシピは、電子ブックとドキュメントを事前トレーニング テキスト データセットに変換します。モデルは必要ありません。
  • Windows および Linux では、エクスポート ページで、ある程度の品質コストを払って、MOE モデルの最も役に立たないエキスパートの 25% または 50% を REAP で削除できるようになりました。
  • Python では、reap_prune は、llm-compressor よりも最大 54 倍の速度で REAP エキスパート プルーニングを実行します。
  • unsloth train は視覚と、Mac を除くオーディオ モデルをトレーニングするようになりました。
  • Unsloth は OpenAI の微調整 API をサポートするようになりました。そのため、OpenAI の SDK はデータセットをアップロードし、ローカル モデルの監視付き微調整を実行できます。

パフォーマンス

  • MLX MoE モデルが Mac には大きすぎるため、専門家は SSD を使用し続け、応答が遅くなります。 Qwen3.8-Flash-Next は 32 GB Mac に適合します。 DeepSeek-V4-Flash と GLM-5.3-Flash は、そのサイズよりもはるかに少ないメモリを必要とします。
  • DPO およびシーケンスをパディングするその他のトレーニングは、NVIDIA Ampere 以降で少ないメモリで最大 3.8 倍高速に実行されます。
  • bf16 を使用しない GPU での Qwen3-MoE、Gemma 3 および Gemma 4 トレーニングでは、2.13 以前のトーチを使用すると、アテンション メモリの使用量が最大 7 倍少なくなります。

コーディング エージェント + API

  • チャットでは、モデルはツールを使用するだけでなく、接続された MCP サーバー上のテキスト ファイルやドキュメントを読み取ることができるようになりました。
  • コーディング エージェントを起動するときに、unsloth start は Unsloth API キーを HTTP プロキシ経由でローカル Unsloth にプレーン テキストで送信しなくなりました。
  • Windows では、unsloth start は起動時にクロード コード フックや Codex サインインを中断しなくなりました。
  • Unsloth API キーを使用したリクエストでは、Python とターミナル ツールをサンドボックス化せずに実行できなくなりました。それを許可できるのは Unsloth UI だけです。
  • チャット設定の新しい [このモデルに保存] ボタンにより、サンプリング設定が新しいチャットおよび API リクエストのモデルのデフォルトになります。

モデル + ハードウェア

  • load_in_4bit = True がロードされた BF16 gpt-oss チェックポイントは、ランダムなエキスパートとルーターの重みを取得しなくなります。
  • モデル ピッカーを使用すると、環境変数を使用せずに Ryzen AI 300 シリーズ以降の NPU でモデルを実行できるようになります。
  • システム全体の ROCm を備えた一部の Linux AMD PC では、CPU 上で実行されていた GGUF が再び GPU 上で実行されるようになりました。
