mybatis-3 mybatis-3.5.12

「大掃除」

ユーザーに影響を与える変更

  • #2703 名前によるコレクション パラメーターの参照が #2693 の修正に失敗する

  • #2709 マップされたテーブルの構築中に他のスレッドがマッパー メソッドを呼び出すことによって引き起こされる競合状態を修正

  • #2727 XMLConfigBuilder にカスタム構成を提供する機能を有効にする

  • #2731 JPMS ではマッパーの追加が失敗する可能性がある

  • #2741 @Select、@SelectProvider、<select /> に 'affectedData' 属性を追加

  • #2767 resultType と resultMap が指定されていない場合は、名前空間と ID によって resultType を解決します。

  • #2804 コンストラクター引数の型を名前で解決するときに読み取り可能なプロパティを検索する

  • 軽微な修正: 'boolean' を null (プリミティブ) にすることはできません。

  • 一般的なライブラリの更新

  • コンパイラのパラメータ オプションを使用するようになりました (spring boot 3 で必要) (リフレクションの必要性のため)

コードのクリーンアップ

  • #2816 オープン リライトを使用して Java コードを部分的にクリーンアップする
  • #2817 オープンリライトごとにプライベートコンストラクターを追加
  • #2819 オープンリライトごとに必要に応じて Final を追加
  • #2825 if ステートメントが壊れた場合のクリーンアップ/リターン ロジック
  • #2826 Eclipse ベースのクリーンアップ

ビルドする

  • #2820 GH-Actions でのより直接的な使用を優先してテスト ci グループ プロファイルを削除し、README.md の概要に沿って非推奨のsurefire を更新します。
  • シェーディングされた ognl と javassist が警告をスローしないようにビルドを調整しました
  • jdk 21-ea を使用してビルドするようになりました
  • さまざまなテストのクリーンアップ、更新、追加
  • コードブロック内で必要な場合にフォーマットをスキップするための Readme の寄稿者へのメモを含む、すべての Java コードの自動フォーマットをオンにします。
  • テストでは jdk 8 ランタイムを維持しながら jdk 11 を使用できるようになりました
  • POM のクリーンアップ / パラメーターの明確化

ドキュメント

  • さまざまなドキュメントの更新

貢献者向け:

  • Mybatis は現在、コード ベースの自動フォーマットを使用しています。 注釈や書式設定ルールと競合する特定の javadoc など、コントリビューションに特別な書式設定が必要な場合は、書式設定時に無視されるコード ブロックの周囲に // @formatter:off および // @formatter:on を使用します。 javadoc 内の場合は、コメント タイプであるため、全体が影響を受けるため、これを javadoc 全体にラップするだけです。 読みやすくするために、非書式設定ブロック内のコードが適切に書式設定されていることを確認してください。
