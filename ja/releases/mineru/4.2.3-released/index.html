MinerU 4.2.3-released

#MinerU マイネル-4.2.3-released

4.2.3

  • 単一ファイルの実行タイムアウトと管理されたリカバリを追加しました。 WebUI、ルーター、および API サーバーは --task-timeout をサポートします。デフォルトは 3600 秒で、解析クォータが取得された時点から開始され、解析とサーバー側の製品パッケージ化がカバーされます。タイムアウト タスクは task_timeout を返し、独立した API は新しいタスクの受信を停止し、デプロイヤはサービスを再構築します。ルーターは、親プロセスを通じてタイムアウト ワーカーとモデルの子プロセスのリサイクルを監視し、サービスを再起動します。実行スレッド、イベント ループ、またはクリーンアップの一時停止がキャンセルされた場合でも、回復をトリガーできます。
  • WebUI の回復エクスペリエンスとプロセスのクリーニングを改善。ローカル WebUI はルーターによって唯一のワーカーとしてホストされ、回復中にステータスが表示され、まだ送信されていないキューに入れられたリクエストはサービスの準備ができた後も続行されます。古いワーカー上のその他の未処理のリクエストは worker_restarted を返し、問題のあるファイルは手動で再試行できます。 Windows プロセス ツリー、一時ディレクトリ、および制御チャネルのリサイクルを改善し、モデルのプリロードの失敗を明確に報告し、3 回連続して起動回復に失敗した場合の自動再試行を停止します。
  • 画像ロードにより混雑する Doclib 全文検索を修正。検索テキストを作成するときは、テキスト、数式、グラフの説明を抽出し、埋め込み画像の Base64 コンテンツがインデックスを埋めてテキストが欠落するのを防ぐために文字数バジェットを適用します。アップグレード後、既存のインデックスが解析キャッシュから再構築され、クロスページ コンテンツが保持されます。キャッシュが不完全なドキュメントには、移行の理由が記録されます。キャッシュを埋めるか再解析した後、Doclib を再起動して移行を続行します。
  • vLLM と Transformers の互換性を事前に確認してください。エンジンを始動する前に vllm<0.29.0 と transformers>=5.23.0 の互換性のない組み合わせを特定し、vLLM をアップグレードするか、Transformers のバージョン範囲を調整するための明確なプロンプトを表示して、モデルの読み込み段階で特定するのが難しい障害を減らします。
  • DocVortex の依存関係を更新。最小バージョンは 0.6.24 にアップグレードされ、ネイティブ ドキュメントの解析機能と共有レンダリング機能が同時に向上します。

設定のヒント。ルーターの--worker-tierはデフォルトでautoとなっており、各作業者が自身の設備環境に応じてギアの上限を決定します。固定の上限が必要な場合は、flash、basic、standard、または advanced を明示的に指定できます。 --task-timeout は正の整数でなければなりません。アップロード、キューイング、クライアントのダウンロード、モデル起動のプリロードはそれぞれ、独立した待機設定とライフサイクル設定を使用します。

4.2.3

  • ファイルごとの実行タイムアウトと管理されたリカバリを追加。 WebUI、ルーター、および API サーバーは --task-timeout をサポートし、解析とサーバー側アーティファクトのパッケージ化を通じて実行スロットを取得してからのデフォルトは 3600 秒です。タイムアウトしたタスクは task_timeout を返します。スタンドアロン API は新しい作業の受け入れを停止し、デプロイメント ホストに依存してサービスを再作成します。ルーターは、親プロセスからローカル ワーカーを監視し、タイムアウトしたワーカーとモデルのサブプロセスを再利用し、実行スレッド、イベント ループ、またはキャンセル クリーンアップが停止した場合でもサービスを再起動します。
  • WebUI の回復とプロセスのクリーンアップを改善。ローカル WebUI は Router を使用して単一のワーカーを管理し、回復ステータスを表示し、サービスの準備ができたら送信を待つキューに入れられたリクエストを再開します。置き換えられたワーカー上の他の未完了のリクエストは worker_restarted を返し、影響を受けるファイルは手動で再試行できます。 Windows のプロセス ツリー、一時ディレクトリ、およびコントロール チャネルのクリーンアップを改善し、モデルのプリロード障害を表面化し、3 回連続して起動に失敗した後の自動回復を停止します。
  • 画像ペイロードを Doclib フルテキスト インデックスから除外します。文字バジェットを適用する前に、本文のコンテンツ、数式、図や表の説明から検索テキストを作成し、埋め込まれた画像の Base64 データが検索可能なテキストに押し寄せるのを防ぎます。アップグレード中に、ページ間の継続を維持しながら、キャッシュされた解析結果から既存のインデックスを再構築します。キャッシュが不完全なドキュメントには移行理由が記録され、キャッシュを復元または再解析して Doclib を再起動した後に移行を再開できます。
  • 起動前に vLLM と Transformers の互換性を確認してください。エンジンの初期化前に、vllm<0.29.0 と transformers>=5.23.0 の互換性のない組み合わせを検出し、vLLM をアップグレードするか、互換性のある Transformers シリーズを選択するための実用的なガイダンスを提供します。
  • DocVortex を更新します。ネイティブ ドキュメントの解析と共有レンダリングの改善のために、最小バージョンを 0.6.24 に上げます。

設定メモ。ルーターはデフォルトで --worker-tier から auto に設定され、各ワーカーがデバイス環境から階層の上限を選択できるようになりました。固定天井の場合は、flash、basic、standard、または advanced をご指定ください。 --task-timeout には正の整数が必要です。アップロード、キューイング、client ダウンロード、およびモデルの起動プリロードでは、独自の待機設定とライフサイクル設定が使用されます。

アップグレード/アップグレード

pip install -U "mineru==4.2.3"
