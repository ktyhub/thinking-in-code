MinerU 4.2.2-released

#MinerU マイネル-4.2.2-released

4.2.2

  • ローカル VLM エンジンの障害の伝播とライフサイクル管理を改善します。 LMDeploy、vLLM、llama.cpp、MLX の公衆衛生および無効化契約を統合します。エンジン障害を確認した後、キャッシュ インスタンスの再利用を停止し、グローバル障害が通常の識別障害とみなされることによるサイレント劣化を回避するように関連ホストに通知します。通常のシングルチップ認識が失敗した場合でも、既存のフォールバックが引き続き保持されます。
  • 解析サービスのヘルス チェックとタスク クリーニングを強化。ヘルスチェックをサポートするロードされたランタイムを定期的に検出します。一時的に利用できない場合は新しい推論を拒否し、正常な場合は再開します。エンジンの停止が確認されると、健全性と機能のインターフェイスは明確なエラーを返し、実行中のタスクとキューに入れられたタスクは既存の境界に従ってクリーンアップされ、回復はホストによって管理されます。シャットダウン時の転送中の検出、キャンセル、リソース解放の順序を改善します。
  • バッチ解析の入力およびエラー処理を修正。コンテンツの署名とコンテナーの識別を使用してファイルを検証し、Office ロック ファイルによって後続のドキュメントがブロックされるのを防ぎ、~$ で始まる名前の正当なドキュメントを保持します。明示的な破損、暗号化、リソース制限、入力不足、権限エラーは単一の失敗として記録され、続行されます。エンジン、サービス、または出力に障害が発生すると、後続の処理が停止します。概要では成功、スキップ、失敗、未処理の数がそれぞれ報告され、一部の失敗ではゼロ以外の終了コードが返されます。
  • バッチ出力パス判定を修正。ディレクトリおよび複数ファイルの入力では常にディレクトリ出力が使用され、ドキュメントが 1 つしかない場合でも同じセマンティクスが維持されます。既存または新規作成された results.v1、results.md、およびその他のドット付きディレクトリをサポートし、既存の通常のファイルへのバッチ結果の書き込みを拒否します。明示的な単一ファイル出力は、ターゲット ファイルの上書きを引き続きサポートします。
  • 読み取りとエクスポートに対する明確な責任。 mineru read の Markdown 出力は、プログレッシブ読み取り、標準出力、JSON および継続プロンプトの保持に使用されます。 --output PATHは写真のみに使用されます。リダイレクトまたは SDK を使用して現在のテキスト フラグメントを保存し、mineru parse ... -o ... を使用して指定されたページ範囲を完全にエクスポートして、完全な製品の読み取り予算によって制限されているフラグメントを間違えることを避けることができます。
  • サービスの起動と終了のエクスペリエンスを向上させます。サービスが正常に監視されると、直接アクセス可能な API ドキュメント アドレスが出力されます。通常の Ctrl+C 終了では、割り込みスタックが表示されなくなります。未実装の Webhook 機能宣言と対応するドキュメントを削除します。
  • ランタイムの依存関係を更新します。この公開ライフサイクル契約に従って、最小バージョンは mineru-llama-cpp 0.2.1 および mineru-vl-utils 2.0.9 に調整されています。

互換性に関するヒント。保存するには、元の mineru read <locator> -o part.md を stdout リダイレクトまたは SDK に変更する必要があります。完成品が必要な場合はmineru parse <path> --pages <range> -o result.mdをご使用ください。一括呼び出し元は、新しい結果の概要と終了コードに基づいて、完全な成功、部分的な失敗、全体的な中止を区別する必要があります。

4.2.2

  • ローカル VLM 障害の伝播とライフサイクル管理を改善します。 LMDeploy、vLLM、llama.cpp、および MLX の共有ヘルスおよび障害コントラクトを使用します。エンジン障害が確認されると、キャッシュされたインスタンスが無効になり、そのホストに通知され、グローバルな停止がサイレントにローカル認識フォールバックになるのを防ぎます。通常の作物ごとの失敗では、既存のフォールバック動作が維持されます。
  • 解析サーバーのヘルスチェックとタスクのクリーンアップを強化。ヘルスチェックをサポートする初期化されたランタイムを定期的に調査します。一時的に利用できなくなると、健全性が回復するまで新しい推論が拒否されます。エンジンの停止が確認されると、明示的な健全性と機能のエラーが発生し、既存のライフサイクル境界を通じて実行中のタスクとキューに入れられたタスクがクリーンアップされます。回復は依然としてホストの責任です。シャットダウン時のアクティブなプローブ、キャンセル、リソースの解放の順序を改善します。
  • バッチ入力検証とエラー処理を修正。 ~$ で始まる有効なドキュメントは引き続きサポートされながら、Office ロック ファイルによって後続のドキュメントが停止されないように、ファイル コンテンツの署名とコンテナーを検証します。既知の破損、暗号化、リソース制限、欠落、またはアクセス不能の入力を個別の失敗として報告し、続行します。エンジン、サービス、出力に障害が発生すると、バッチが停止します。概要は、成功した入力、スキップされた入力、失敗した入力、および未処理の入力を区別します。部分的に失敗すると、ゼロ以外の終了コードが返されます。
  • バッチ出力パスの処理を修正。ディレクトリおよび複数ファイルの入力では、ドキュメントが 1 つだけ残っている場合でも、常にディレクトリ出力が生成されます。 results.v1 や results.md などの既存および新規のドット付きディレクトリ名を受け入れ、既存の通常のファイルをバッチ宛先として拒否します。明示的な単一ファイル出力は、出力先の上書きを引き続きサポートします。
  • 読み取りとエクスポートを明確にします。 mineru read からのマークダウンは、継続ヒントを含むプログレッシブ stdout または JSON 読み取りのままです。 --output PATH は画像用に予約されています。リダイレクトまたは SDK を使用して現在のテキスト フラグメントを保存し、mineru parse ... -o ... を使用して、読み取り予算なしで完全なページ範囲をエクスポートします。
  • サービスの起動とシャットダウンを改善します。バインドが成功した後に直接アクセス可能な API ドキュメント URL を出力し、通常の Ctrl+C シャットダウン時の中断トレースバックを回避し、未実装の Webhook 機能宣言とドキュメントを削除します。
  • ランタイムの依存関係を更新します。共有ライフサイクル コントラクトには、mineru-llama-cpp 0.2.1 および mineru-vl-utils 2.0.9 以降の互換性のあるバージョンが必要です。

互換性に関する注意事項。 mineru read <locator> -o part.md を標準出力リダイレクトまたは SDK 保存に置き換えます。完全なエクスポートには、mineru parse <path> --pages <range> -o result.md を使用します。バッチ呼び出し元は、結果の概要と終了コードを解釈して、完全な成功、部分的な失敗、中止されたバッチを区別する必要があります。
