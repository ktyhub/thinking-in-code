コンポジオ @composio/core@0.26.0

マイナーな変更

  • e08c84f: @composio/client 2.0.0-rc.18 が必要です。 SDK は、デフォルトのヘッダーに配置するのではなく、API client にその資格情報を client の auth オプションとして渡し、その組織とプロジェクトを scope として渡すようになりました。 apiKey、userApiKey、orgApiKey、orgId、および projectId オプション、その環境フォールバック、および各リクエストで送信される資格情報は、1 つの例外を除いて変更されていません。apiKey: null および組織 API キー (orgApiKey オプション、COMPOSIO_ORG_API_KEY、または x-org-api-key デフォルト ヘッダー) のみの場合、すべてのリクエストに x-org-api-key が含まれるようになり、トリガーも同様になります。チャネル認証と session.mcp.headers。以前は、組織所有者の操作のみが実行され、他のすべてのリクエストは資格情報なしで送信されました。 defaultHeaders または createSession({ headers }) の資格情報ヘッダーとスコープ ヘッダーは機能し続けますが、SDK はそれらを転送するのではなく独自のオプションに折りたたみます。x-user-api-key または x-org-api-key エントリはすべてのリクエストに含まれる資格情報になり、x-api-key エントリはプロジェクト キーになり、x-org-id / x-project-id エントリは orgId / projectId になります。 getConfig() は折り畳まれた値 (たとえば、x-user-api-key エントリの apiKey: null と userApiKey) をレポートし、それらのエントリは defaultHeaders の下にリストされなくなります。 x-api-key、x-user-api-key、x-org-api-key の複数を設定すると、ComposioError がスローされるようになりました。 API はそのような要求をすべて拒否しました。 getClient()、apiKey、userApiKey、および orgApiKey によって返される client では、読み取り専用で非推奨になり (getConfig() からキーを読み取るか、client から authMode および scope を読み取ります)、呼び出しごとの headers オプションで資格情報またはスコープ ヘッダーを指定できなくなります。 API client は環境自体を読み取らなくなりました。SDK は依然として COMPOSIO_ALLOW_INSECURE_HTTP=1 を尊重し、COMPOSIO_CUSTOM_HEADERS を適用しなくなりました。代わりに defaultHeaders を渡します。 非推奨の customConnectionData では、API と同様に、S2S_OAUTH2 の代わりに val.access_token が必要になります。
  • 57de614: @composio/client 2.0.0-rc.19 が必要です。 SDK は、client の削除された Logger インターフェイスの代わりに、Console 形状のオブジェクトを通じて API client のログ行を転送します。何がログに記録され、どの SDK レベルで記録されるかは変更されません。 rc.19 では、getClient() によって返される client には apiKey、userApiKey、orgApiKey、logger がなくなり、その baseURL、maxRetries、timeout、logLevel は読み取り専用になります。getConfig() からキーを読み取り、次のコマンドで client を派生します。他はwithOptions()に変更します。

パッチの変更

  • 9d26fb8: OpenAPI nullable を厳密なツール スキーマの型に折りたたむ toStrictJsonSchema は OpenAPI nullable を通過しなくなりました。 Anthropic strict ツールを使用すると、オブジェクト スキーマでリクエスト全体が 400 で拒否されます。 nullable: true を持つノードは、ツールの引数の検証方法と一致して、type (["object", "null"]) または null ブランチを介して null を受け入れるようになり、書き換えは nullable-converted の変更として報告されます。 nullable: false は、unsupported-keyword-stripped の変更として削除されました。 omitNullToolArguments は、type に null が含まれるプロパティに対して既に保持しているのと同様に、nullable: true とマークされたプロパティに対して null を保持するようになりました。
  • 3dd9a2c: OpenAI 構造化出力が厳密なツール スキーマから拒否する文字列 format 値を削除します toStrictJsonSchema は、date-time、time、date、duration、email、hostname、ipv4、ipv6、または uuid のいずれかでない限り、文字列スキーマ上の format を削除するようになりました。 OpenAI は、Strict モードで他の文字列形式をリクエスト全体に対して 400 で拒否するため、format: "uri"、repo.nwo などのカスタム形式、またはファイルのアップロードで追加される format: "path" を含む 1 つのツールでは、すべての strict リクエストが失敗します。この削除は、unsupported-keyword-stripped の変更として報告されます。 API は数値スキーマと整数スキーマの形式をチェックしないため、それらの形式は保持されます。
  • 04fdb41: contentEncoding が base64 の場合にのみ、文字列ツール パラメーターを Base64 としてチェックします。 format: "binary" (OpenAPI の生オクテット) および base16 などの他のエンコーディングは Base64 として検証されたため、Vercel、LangChain、LlamaIndex、および Claude Agent SDK プロバイダーは、これらのフィールドにプレーン テキストまたは 16 進数を含むツール呼び出しを拒否し、モデルに送信されたスキーマはそれらを contentEncoding: "base64" として記述しました。これらのフィールドはプレーン文字列になりました。 contentEncoding: "base64" はチェックを維持し、format: "byte" はチェックを解除したままになります。
  • be12ce1: API が ZZPH100​​ZZ 応答ヘッダーを通じてツールキットを非推奨として報告したときに、ツールキットのバージョンごとに 1 回警告します。警告には、バージョン、廃止日、および新しいバージョンを固定する方法が記載されています。 logLevel: 'error' または COMPOSIO_LOG_LEVEL=error で消音します。
  • 依存関係を更新 [f119f05]
  • 依存関係を更新 [04fdb41]
