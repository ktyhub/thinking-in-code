bookkeeper release-4.17.0

リリース 公開日2024年5月25日 出典apache/bookkeeper 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#簿記リリース-4.17.0

リリース 4.17.0 には、複数の重要な機能、改善、バグ修正、およびいくつかの依存関係 CVE 修正が含まれています。

このリリースの技術的な詳細は以下にまとめられています。

重大な変更

重大な変更はありません。一部のデフォルトは異なりますが、全体的には互換性の問題はありません。

機能

  • BP-62 一括読み取り API

注目すべき変更点

  • bk client のリオーダー読み取りシーケンスをデフォルトで有効にする PR #4139
  • 型情報のない prometheus client によって生成される一部のメトリクスを修正 PR #3927
  • httpServerEnabled による任意のファイルのアップロードの脆弱性を修正 PR #3982
  • log4j 設定で kv ログを有効にする PR #3986
  • DefaultEntryLogger と DirectEntryLogger の間で互換性を持たせる PR #4041

ブッキー

  • 負の JournalQueueSize のバグを修正 PR #4077
  • 圧縮スロットルの不正確さを修正 PR #3192
  • 複数の台帳ディレクトリを構成したときに失われるデータを修正 PR #3329
  • 圧縮時にファイル名を変更する場合は、jdk api を使用してハードリンクを作成してみてください。 PR #3876
  • [機能] [サーバー] エントリを先読みするときに dbStorage_readAheadCacheBatchBytesSize プロパティを追加 PR #3895
  • ledgersToDelete が空の場合の EntryLocationIndex でのキー リークを修正 PR #3903
  • ランタイム例外によってブロックされたガベージ コレクションを修正 PR #3901
  • 変更がない場合は RocksDB の同期をスキップ PR #3904
  • PCBC completedObjects autoShrink を有効にしてメモリ使用量と gc を削減 PR #3913
  • [修正] さまざまな例外が発生したときに読み取り/書き込み要求を削除することをリサイクルする PR #3912
  • 台帳の複製に失敗したブロックのブックの廃止プロセスを修正 PR #3917
  • 返信ジャーナル ステージでの無効なジャーナル レコードのスキップをサポート PR #3956
  • 余分なフラッシュをトリガーする圧縮を避ける DbLedgerStorage PR #3959
  • ダイレクト メモリ エントリ ロガーのダイレクト メモリのメモリ リークを修正しました。 PR #3983
  • DirectIO コンポーネントの ByteBufAllocator を統合 PR #3985
  • 圧縮の進行状況を印刷 PR #4071
  • ブックの廃止チェック待機間隔を最適化 PR #4070
  • トリガー GC が機能しない問題を修正 PR #3998
  • 単一のrocksdbバッチで最大操作数を設定できるようにする PR #4044 ※台帳チェッカーの読み取り失敗ログを追加しました。 PR #4010
  • エグゼキュータが RejectedExecutionException をスローしたときの読み取り書き込みリクエストのリークを修正 PR #4024
  • DefaultEntryLogger の読み取りパフォーマンスが向上しました。 PR #4038

Client

  • [バグ] 常に 1 つの孤立元帳が作成される PR #3813
  • ペイロードが ReaderIndex > 0 の CompositeByteBuf である場合のチェックサム計算のバグを修正 PR #4196
  • すべての BK のラックをリセットした後に既知のブックキーが存在しない問題を修正 PR #4128
  • client での実行時の古い grpc バージョンとのバイナリ互換性の問題を修正 PR #3997
  • エントリ書き込みサポートのローカル ノード領域認識配置ポリシー PR #4063
  • Rackaware 配置ポリシーは、ホスト名によるローカル ノードの認識をサポート PR #4057
  • netty ライブラリのバージョンを調整するには netty-bom を使用し、linux-aarch_64 の epoll を追加します PR #4204

自動回復

  • AutoRecover で StickyReadS をデフォルトとして有効にします。 PR #4125
  • 自動回復のための再試行ロジックをサポート PR #3799 0
  • 監査者選出者実行者のブロック問題を修正。 PR #4165
  • エントリフェンス追加エラーによる自動リカバリ失敗レプリケートを修正 PR #4163
  • 監査スレッドのリーク問題を修正。 PR #4162
  • 自動回復はバッチ読み取りをサポート PR #4211

その他

  • ブックキーなしで状態ストア サービスを開始する CLI コマンドを追加 PR #2648
  • 配置ポリシーに準拠するアンサンブル再配置コマンドを追加 PR #2931
  • プールの同時実行性の調整 PR #3432
  • 問題 4136: docker イメージでログ設定が壊れている問題を修正 PR #4137
  • [リリース] リリースのビルドに Linux/amd64 の使用を強制する PR #4060

依存関係の変更

以下を含む重要な依存関係とアドレス CVE がアップグレードされました。

  • 複数の CVE に対処するために snappy-java をアップグレード PR #3993
  • CVE-2023-32732 PR #3992 に対処するために grpc と protobuf をアップグレードします。
  • CVE-2023-44981 PR #4112 に対処するために、Zookeeper を 3.8.3 にアップグレードします。
  • Netty を 4.1.107.Final に、io_uring を 0.0.25.Final にアップグレード PR #4224
  • org.apache.commons:commons-compress を 1.21 から 1.26.0 にバンプ PR #4214
  • データスケッチのバージョンを 0.8.3 から 3.2.0 に更新 PR #3264
  • 問題 3567: チェックサムの不一致エラーを回避するために、rocksdb のバージョンをアップグレードする PR #3568
  • 修正(秒): コモンズ コーデックを 1.13 にアップグレード PR #3508
  • CVE-2019-10202、CVE-2023-1370、および CVE-2022-45685 を解決するには、avro、hadoop-auth、および Jersey-json の依存関係を hadoop-common から削除します PR #3911
  • CVE-2023-0286 PR #3916 を解決するには、docker 基本イメージをアップグレードします。
  • CVE-2022-45146 PR #3915 を修正するには、bc-fips を 1.0.2.4 にアップグレードします。
  • 桟橋バージョンを 9.4.51.v20230217 PR #3937 にアップグレード
  • バンプグアババージョン 31.0.1-jre から 32.0.1-jre PR #4008
