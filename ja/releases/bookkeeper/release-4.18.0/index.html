bookkeeper release-4.18.0

#簿記リリース-4.18.0

リリース 4.18.0 はメジャー機能リリースです。全体にわたって構造化されたロギングを導入します。 コード ベース (BP-69)、ワイヤ プロトコルのシリアル化を LightProto およびネイティブ I/O に移行します。 ライブラリを Rust に変更し、最低限必要な Java バージョンを 17 に引き上げます。また、多くのものが含まれています。 改善、バグ修正、依存関係/CVE の更新。

Apache BookKeeper ユーザーは、4.18.0 にアップグレードすることをお勧めします。を確認してください。 アップグレードする前に、以下の重大な変更と既知の問題を確認してください。

ハイライト

  • 構造化ログ (BP-69) — すべての BookKeeper ログは SLF4J から変換されました 文字列を slog (各イベントが型指定されたキー/値を運ぶ構造化ログ API) にフォーマットします。 属性 (例: ledgerId、entryId)。ロガー コンテキストは client を通じて伝播されます これにより、同じ台帳に関連するすべてのイベントが自動的にタグ付けされます。 属性は、log4j2 によってプレーンテキスト出力と JSON 出力の両方でレンダリングされます。例を示します。 OpenTelemetry 互換の JSON ログの構成。 PR #4751、 #4754、 #4755、 #4756、 #4757、 #4758、 #4765、 #4766、 #4767、 #4770
  • LightProto シリアル化 — BookKeeper ワイヤ プロトコル、メタデータ形式、およびストリーム ストレージ プロトは protobuf-java から LightProto に移行されました。 中間割り当てなしで Netty バッファ上で直接シリアル化し、GC 圧力を軽減します。 ホットな道で。 PR #4779、 #4780、 #4781、 #4783
  • Rust で書き直されたネイティブ I/O ライブラリ — native-io ライブラリは、直接 I/O に使用されます。 ブックキーは C から Rust に移行されました。 PR #4738
  • Java 17 ベースライン - BookKeeper を構築して実行するには Java 17 以降が必要になりました。 PR #4446
  • Bookie の廃止により Cookie (BP-68) がクリーンアップされます — 現在、廃止管理者 API メタデータ ストアからブックキー Cookie を削除するため、廃止されたブック ID は 手動クリーンアップなしで再利用されます。 PR #4500、 #4592
  • ZooKeeper 再レプリケーション中の読み取りスロットル (BP-66) — 再レプリケーションでできるようになりました。 ZooKeeper の読み取りを抑制し、大量の読み取りが発生した場合の読み取りストームからメタデータ ストアを保護します。 台帳が回収されつつある。 PR #4258
  • 未確認エントリのバッチ読み取り (BP-62) — batchReadUnconfirmedAsync は現在 ReadHandle で公開されます。 PR #4739

重大な変更

  • BookKeeper の構築と実行には Java 17 以降が必要です (以前の Java 11) PR #4446
  • readOnlyModeOnAnyDiskFullEnabled のデフォルト値が true に変更されました: 現在はブックメーカーです すべてのディスクが満杯になった場合のみではなく、いずれかの台帳ディスクが満杯になるとすぐに読み取り専用に移行します。 いっぱいです。以前の動作を復元するには、これを false に戻します。 PR #4520
  • bookkeeper-slogger モジュールは削除され、スログ構造に置き換えられました。 ロギング API (BP-69) PR #4764
  • 非推奨のスペルミスのあるメソッド setAllocatorPoolingConcurrenncy を削除しました — 使用してください 代わりに setAllocatorPoolingConcurrency PR #4431
  • 非推奨クラス MathUtils PR #4274 を削除しました。

既知の問題

  • PR #4730 (スレッド ブロックの修正を読み取り このリリースに含まれている sendResponseAndWait) がデッドロックを引き起こす可能性があることが判明しました。 ブックメーカーの読み取りパスにあります。に戻されました PR #4830、4.18.1の一部になります。

特徴

  • ブックサーバーの TCP キープアライブ構成をサポート PR #4762
  • BookKeeper client がメタデータ サービスに接続されているかどうかを確認する新しい client API PR #4342
  • Yahoo DataSketches から Apache DataSketches への移行 7.0.1 (KLL) PR #4774
  • log4j2 AsyncLogger の構成を許可 PR #4269

改善点

ブッキー

  • total_entry_log_space_bytes メトリックを追加 PR #4507
  • GC メトリクスを強化して、GC の動作と各フェーズに費やされた時間をより適切に分析 PR #4384
  • ボトルネックの特定に役立つ RocksDB getLastEntryInLedger のメトリクスを追加 PR #4529
  • EntryLoggerAllocator で Executor の ThreadFactory を設定する PR #4562
  • ネイティブ ライブラリの temp dir プロパティを追加 PR #4533
  • WRITE_BUFFER_WATER_MARK 設定をブックキー Netty サーバーの子チャンネルに適用する PR #4337
  • 書き込みロックが保持されている場合、SingleDirectoryDbLedgerStorage での無駄なオプティミスティック キャッシュ挿入をスキップします PR #4306
  • BookieServer 起動時に上書きされた構成設定のみをログに記録します PR #4768
  • 未使用のジャーナル時間追跡を削除 PR #4006

Client

  • LedgerHandle.getLength() での不要な同期を削除 PR #4516
  • エントリ数を予測することで、制限されたバッチ読み取りを最適化します PR #4741
  • ブック ID のホスト アドレス解決ロジックを改善 PR #4588
  • client 高優先度スレッド プールの名前を変更 PR #4496

ツール

  • readledger コマンドは、最初と最後のエントリ ID が指定されていない場合、ブックキーからすべてのエントリを読み取ります PR #4692
  • ListActiveLedgers コマンドの最適化 PR #4602
  • --help オプションのブックキー CLI の使用情報を改善 PR #4241

バグ修正

ブッキー

  • IOException: Recovery log <id> is missing PR #4740 によって引き起こされるブックキーの起動エラーを修正
  • SingleDirectoryDbLedgerStorage での競合状態によるダブル フラッシュの防止 PR #4305
  • Windows での RocksDB 設定パスの処理を修正 PR #4407
  • BufferedChannel 読み取りの無限ループを修正 PR #4506
  • ConcurrentLongHashMap の ArrayIndexOutOfBoundsException を修正 PR #4771
  • Java 17 サポートによる ZOOKEEPER-3825 (複数の数値 IP に解決される数値 IP と DNS 名) の回避策を追加 PR #4719
  • ブックキーの起動に失敗したときに非同期ログ アペンダーがエラー ログを読み込む問題を修正 PR #4475
  • drainTo が進行中でキューが空のときに新しいタスクを拒否するように SingleThreadExecutor を修正 PR #4488

Client

  • ダイジェスト不一致の再試行が無視された後にバッチ読み取りがハングする問題を修正 PR #4789
  • シーケンス読み取りにおける WriteSet の use-after-recycle を修正 PR #4788
  • recycling 後に clientCtx が null の場合の PendingAddOp.maybeTimeout() の NPE を修正 PR #4760
  • タイムアウト チェック中の V3 応答処理における競合状態 NPE を修正 PR #4737
  • Bookie WatchTask がスタックする問題を修正 PR #4481
  • asyncBatchReadEntries の健全性チェックを修正 PR #4579
  • アドバタイズされたアドレスに対する厳密なホスト名解決とループバック チェックを追加 PR #4595
  • LedgerHandle.batchReadUnconfirmedAsync のインスタンス スログ ロガーを使用する PR #4782
  • バッチ読み取りでのパラメーター チェックのログ レベルをデバッグに変更 PR #4485

その他

  • ComponentStarter シャットダウン フックの IllegalThreadStateException を修正 PR #4733
  • 潜在的な Jetcd-core シェーディング問題を修正 PR #4526
  • Jetcd-core-shaded シェーディング プロセス中の潜在的なクラス競合を修正 PR #4532
  • getHttpServerTrustStorePassword の間違った構成キーを修正 PR #4301
  • RocksdbKVStore の例外メッセージの形式を修正 PR #4448
  • Docker 画像の権限拒否エラーを修正 PR #4464
  • 無視される健全性テスト コマンドのオプションを修正 PR #4691
  • DistributedLog getLogSegmentNames 内の重複した ZooKeeper 呼び出しを修正 PR #4050
  • bookkeeper-daemon.sh の開始/停止における PID チェックを修正 PR #3113

ビルド、CI、テスト

  • PR コメント経由で CI ワークフローの実行を制御する /bkbot コマンドを導入 PR #4673、#4674、#4746
  • Web サイトを Node 24 で構築された Docusaurus 3 にアップグレード PR #4723
  • Java 21 (LTS) 互換性チェックと Java 21/Windows デイリー ビルドを追加 PR #4350、#4292
  • CI にタイプミス チェックを追加し、既存のタイプミスを修正 PR #4375
  • 古いリリースのダウンロードと Maven アーティファクトの CI キャッシュを改善し、エラー ログを改善 PR #4722
  • CI から OWASP 依存関係チェックを削除 PR #4717
  • pom のみのシェーディング モジュールに対する Javadoc サポートを追加 PR #4787

依存関係の更新

  • Netty を 4.2.14.Final にアップグレードし、CVE PR #4744、#4775、#4799 に対処します。
  • CVE-2026-6860 PR #4790 に対処するために、Vert.x を 4.5.25 にアップグレードします。
  • 桟橋を 9.4.57 から 12.1.7 にアップグレード PR #4710
  • RocksDB を 9.9.3 PR #4580 にアップグレードします
  • ZooKeeper を 3.9.3 から 3.9.5 にアップグレード PR #4667、#4721
  • protobuf と gRPC を最新バージョンにアップグレードします。 grpc-bom 経由の gRPC 依存関係のスコープ PR #4716、#4784
  • OpenTelemetry ライブラリを 1.61.0 / 2.27.0 にアップグレード PR #4773
  • jctools を 4.0.6 (jctools-core-jdk11) PR #4656、#4776 にアップグレードします。
  • Java 22 サポートのために Lombok を 1.18.32 にアップグレード PR #4267
  • BouncyCastle を 1.75 から 1.78 に、bc-fips を 1.0.2.4 から 1.0.2.5 にアップグレード PR #4295、#4366
  • commons-io を 2.7 から 2.17.0 にアップグレード PR #4509
  • dependencyManagement で slf4j-bom と log4j-bom を使用する PR #4346
  • 未使用の commons-lang 依存関係を削除 PR #4654
  • RISC-V 64 をサポートするために os-maven-plugin をアップグレード PR #4515
