#ズベックv0.6.0

🚀 ズベック v0.6.0 Release Notes

📦 新機能

  • ターボ量子化器の抽象化: 将来の量子化器 (int8 ユニフォーム、int8 レコード、PQ、RaBitQ など) が実装できる統一インターフェイスを備えたプラグイン可能な量子化器抽象化がターボ モジュールに導入され、インデックス ビルダーやサーチャーから量子化ロジックが分離されました。最初の具体的な Fp32Quantizer 実装とスカラー FP32 距離カーネルが含まれています。 (#546)
  • INT8/INT4 量子化のランダム回転: オプションのランダム回転機能を INT8/INT4 量子化に追加し、分散をベクトル次元全体に均等に分散して量子化エラーを削減し、再現率を向上させます。 cohere-1m について: HNSW INT8 リコールは 0.9285 → 0.9397 に、フラット INT8 は 0.9695 → 0.9881 に改善されました。 INT4 リコールが劇的に向上しました (HNSW 0.2114 → 0.7117)。 (#483)
  • グループ別検索: Zvec は、コア インターフェイス、アルゴリズム、DB レイヤー全体でグループ別検索 (別名グループ別重複排除) をサポートするようになりました。ユーザーは、フラット、HNSW、HNSW-RaBitQ、およびスパース インデックスでの fetch_vector、is_linear、および bf_pks クエリ モードのサポートにより、グローバルではなくグループごとに上位 K の結果を取得できます。 Group-by は Python API でも公開されるようになりました。 (#527、#561)
  • ゼロコピー Python ベクトル クエリ: serialize_vector memcpy を numpy バッファを直接指す VectorViewClause に置き換え、Python 高密度ベクトル クエリの冗長なメモリ コピーを排除しました。 (#517)
  • UTF-8 トークナイザーと ASCII 折りたたみ: utf8proc 2.11.3 を統合し、完全な Unicode サポートで FTS テキスト分析パイプラインをアップグレードします。Unicode 対応の単語境界検出、コードポイント対応の小文字変換、および Unicode 文字を同等の ASCII 文字に変換する新しい ASCII 折りたたみトークン フィルターです。 (#515)
  • 標準トークナイザー (UAX #29): 以前の一般カテゴリのトークナイザーを、公式 Unicode データから生成された Unicode 17 UAX #29 単語境界テーブルに置き換え、英数字、数字、表意文字、ひらがな、カタカナ、ハングル、東南アジア、地域インジケーター、一般的な絵文字シーケンスに対する Lucene スタイルのトークン選択を実装しました。 (#547)
  • ステマー トークン フィルター: Snowball 3.1.1 に基づく FTS 用のステマー トークン フィルターを追加し、extra_params の stemmer_lang 経由で構成可能な 34 以上の言語をサポートし、単語をルート形式に削減します。 (#513)
  • DiskANN C API: 既存の HNSW/FTS パターンに従って、インデックス パラメータのセッター/ゲッター、CRUD 操作を伴うクエリ パラメータ、ベクトル クエリ / グループ化ベクトル クエリ / サブクエリのクエリ ワイヤリングを含む、完全な DiskANN C API インターフェイスを追加しました。 (#495)

🚀 パフォーマンスの向上

  • FTS 結合クエリの高速化: ブロック最大スキップとスコア早期終了を ConjunctionIterator に追加しました。ブロック最大スコアの上限をチェックして非競合ブロック全体 (128 ドキュメント) をスキップし、残りの上限がしきい値を超えられない場合はスコアの累積をショートします。ベンチマーク (500k ドキュメント、quora データセット): AND クエリは 22 ～ 38% 高速になり、フレーズ クエリは 33% 高速になりました。 (#441)
  • IVF インデックスの最適化: IVF インデックス内部のその他の最適化。 (#528)

🐞 バグ修正

  • FTS の正確性: 再オープン時に書き込まれないセグメント統計、ゼロマッチ フィルター セマンティクス、圧縮中のグローバル ドキュメント ID のギャップ、フラッシュなしのスナップショット読み取り専用インデックスを修正しました。 (#566、#584、#588、#569)
  • インデックスの安定性: DiskANN および HNSW スパース ビルダーの進行ループ、IVF nprobe 選択リスト スキャン、およびその他の IVF インデックスのバグでのウェイクアップ損失の競合を修正しました。 (#530、#544、#524)
  • SQL エンジン: SQL エンジンで誤用されていた group_count / group_topk を修正しました。 (#531)
  • コレクション: コレクションが読み取り専用の場合に読み取り専用で開くように LOCK ファイルを修正し、CreateIndex/DropIndex DDL エラーが発生してもライブ書き込みセグメントを保持するようにしたため、永続化セグメント タスクによってアクティブ セグメントが破損することがなくなりました。 (#541、#574)
  • Python バインディング: 無効なクエリを早期に検出するために、実行中にクエリ検証を追加しました。 (#538)
  • ビルドの修正: コンパイラ設定を Arrow ExternalProject に伝達し、CMAKE_C_COMPILER を LZ4 に伝達し、C API の重複および不一致の定義を修正し、iOS Arrow ビルドで Xcode 26.5 の名前変更された libtool バージョン文字列を受け入れました。 (#542、#551、#525、#581)
  • その他の修正: .pyi スタブ内の一致しないドキュメント文字列を修正し、作成パスの存在エラーを明確にし、Query を使用するための README サンプルを修正しました。 (#529、#559、#558)

🔧 リファクタリングとクリーンアップ

  • API クリーンアップ: QueryParams::set_type() を削除し、ドキュメント内のマルチクエリの文言を明確にしました。 (#518、#590)
  • コード品質: ターゲットを絞った bugprone の乱雑な整理チェックを有効にし、ダーティ サブモジュール ワークツリーを無視し、IVF サーチャー テストのタイプミスを修正しました。 (#500、#523、#526)
  • DiskANN I/O 分離: 個別の DiskANN プラグイン .so と libaio-dev へのハード ビルド時の依存関係を、実行時に dlopen が libaio.so を実行し、syscall ポインターをキャッシュするスレッド セーフ シングルトンに置き換えました。 libaio が存在しない場合は、警告付きで同期 pread() にフォールバックし、ビルドとデプロイメントのストーリーを簡素化します。 (#532)

🤖 CI とビルドの改善

  • ビルド強化: 64 ビットのみの Python サポートを宣言および強制しました。 (#576)
  • CI スケジュール: RISC-V ビルドは PR ごとではなく毎週実行されるようになりました。 (#577)
  • 依存関係のバンプ: actions/cache 5→6。 (#537)

📝 ドキュメント

  • README を更新し、WeChat QR コードのリンクを修正し、マルチクエリの文言を明確にしました。 (#589、#575、#590)
