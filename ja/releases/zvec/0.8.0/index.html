zvec v0.8.0

#ズベックv0.8.0

🚀 ズベック v0.8.0 Release Notes

Zvec v0.8.0 は、より高速なクエリ、より低いインデックス構築コスト、およびより広範なプラットフォームのサポートを実現します。量子化器と距離カーネルの改善により、INT4 と Linux ARM64 で大きなメリットが得られ、複数のフォーマットとメトリクスにメリットがもたらされます。このリリースでは、IVF/DiskANN ビルド中のピーク メモリも削減され、HNSW RaBitQ 構築が高速化され、組み込み Jieba リソースで中国の FTS を使用できるようになります。プラットフォームの対象範囲はデスクトップとモバイルに拡大され、同時読み取り、インデックスの再構築、フィルタリングの正確性に関する修正も行われています。

⚠️ 重大な変更とアップグレードに関する注意事項

  • Jieba グローバル辞書構成が削除されました: デフォルトの辞書と HMM モデルがネイティブ ライブラリに埋め込まれるようになりました。 Python ユーザーは、init(jieba_dict_dir=...) を削除し、set_default_jieba_dict_dir() / get_default_jieba_dict_dir() を呼び出す必要があります。対応する C 構成アクセサー、C デフォルト ディレクトリ API、および C++ グローバル構成フィールドと登録 API も削除されました。メインディクショナリをオーバーライドするには、フィールドの FtsIndexParam.extra_params.jieba_dict_dir または ZVEC_JIEBA_DICT_DIR を使用します。フィールド設定が優先されます。ビジネス用語を追加するには、user_dict_path を使用します。 (#807)

📦 新機能

  • Intel Mac および Windows ARM64 サポート: macOS x86_64 ビルドと MSVC による Windows ARM64 サポートを追加しました。リリース ワークフローには、Windows ARM64 SDK パッケージとネイティブ Python 3.11 ～ 3.14 ホイールが含まれるようになりました。 (#713、#352、#824)
  • Windows およびモバイル上の DiskANN: I/O 完了ポートを介した非同期でバッファーのない Windows 読み取りと、Android および iOS 用のポータブル pread サポートが追加されました。 (#625、#656)
  • Windows x86_64 上の RaBitQ: RaBitQ インデックスに対する Windows x86_64 サポートを追加しました。 (#780)
  • 埋め込み中国語 FTS 辞書: デフォルトの Jieba 辞書と HMM モデルを、Python ホイールおよびネイティブ SDK 用の LZ4 圧縮リソースとして埋め込みました。解析されたデフォルトは共有されますが、カスタム ユーザー辞書はトークナイザー インスタンス間で分離されたままになります。 (#807)
  • より柔軟な識別子: ドキュメント ID は最大 1,024 バイトの有効な UTF-8 を受け入れ、コレクション名は禁止されている制御文字と区切り文字を除く、1 ～ 256 バイトの有効な UTF-8 を受け入れるようになりました。フィールド名は ASCII 文字セットを保持し、64 バイトに拡張され、予約された内部名は拒否されます。 (#756)
  • コレクション内の均一な量子化: 均一な UINT4 量子化が追加され、均一な UINT4/UINT7/UINT8 量子化器がデータベース層および HNSW と統合されました。量子化範囲を共有すると、クエリ中のデータポイントごとのスコアの再構築が回避され、検索が高速化されます。すべてのインデックス付きポイントで共有の最小値/最大値を使用すると、量子化エラーが増加し、リコールが減少する可能性があります。 (#698、#754)
  • Turbo PQ および FastScan: PQ-INT4 およびパック ブロック スキャンを備えた 4 ビット PQ FastScan 実装が、SIMD およびスカラー距離カーネルおよび IVF 用の事前計算された残差距離テーブルとともに追加されました。 (#664)
  • OPQ 前処理: 最適化された積量子化ローテーションを Turbo フレームワークに追加し、PQ 量子化器全体で共通のトレーニングとシリアル化ロジックを統合しました。 (#717、#765)
  • ベクトル インデックスの共有ページ キャッシュ: バッファー バック ストレージを追加し、共有ページ キャッシュを備えた HNSW、IVF、および DiskANN を統合しました。この実装では、ピン留め読み取り、バッチ ページ アクセス、およびキャッシュ圧力下での DiskANN ダイレクト I/O フォールバックがサポートされています。 (#708、#742、#766)

🚀 パフォーマンスの向上

  • IVF および DiskANN ビルド メモリの削減: 構築および最適化中のピーク メモリを削減するために、冗長なベクター コピー、ストリーミング マージ入力、制限された一時エンコード バッファーを削減し、完了したビルダーと入力を早期にリリースしました。 (#733、#762)
  • より高速な HNSW RaBitQ 構築: ネイバー プルーニングおよびバッチ処理されたフラット プロバイダー ルックアップおよびセグメント ロック中に生のベクトルを再利用し、繰り返しの読み取りとロック取得を削減します。 (#755、#813)
  • インデックス ファミリ間のターボ距離計算: Flat、HNSW、IVF、DiskANN の距離計算または量子化パスを Turbo に移行し、AVX2、AVX512、AVX512-FP16、SSE、ARM NEON カーネルとランタイム ディスパッチを拡張しました。この量子化器と距離計算の広範なリファクタリングにより、量子化形式と距離メトリック全体のパフォーマンスが向上し、INT4 カーネルと Linux ARM ワークロードで大幅な向上が得られます。 (#716、#735、#773、#678、#687、#710、#689、#718)
  • Vamana 検索の改善: 分割された連続パック レイアウト、最適化された候補状態とプリフェッチ、および修正された medoid 選択が導入されました。グラフの品質を向上させるために、2 パス グラフの構築がデフォルトで有効になるようになりました。 (#701、#727、#738、#749、#761)
  • 変換とロックのオーバーヘッドの削減: ドキュメントのバッチ変換、CRC32C および FP16 ディスパッチの改善、フラット クエリ メタデータ アクセスをセグメント キャッシュ ロックから分離しました。 (#647、#700、#825)
  • リファインメントのオーバーヘッドの削減: 最適化されたリファインメント カーネルと候補のハンドオフ/エクスポート。 Collection.query_internal_ids() は、読み取り専用コレクションの絞り込み中の ID ルックアップのオーバーヘッドを削減します。 HNSW と Vamana は、候補予算を scale_factor で制御して、FP16 または UINT8 ベクトルを使用して絞り込むことができるようになりました。 (#677、#740、#748、#761、#821)

🐞 バグ修正

  • 同時読み取りとセグメント切り替え: fetch() または query() がセグメント スイッチまたはフラッシュ、書き込みセグメントの同期読み取りと競合するときのクラッシュと行の欠落を修正し、フラット キャッシュの同期とキーマップ イテレーターの有効期間を修正しました。 (#715、#722、#726、#779)
  • インデックスの再構築とトレーニングの正確性: 削除された行を含むインデックスを再構築するときにベクトルから行へのマッピングが保持され、IVF n_iters が正しく伝播され、マージ トレーニング中にターボ ソースがデコードされ、丸められた値を使用するように INT4 スコアリング メタデータが修正されました。 (#731、#730、#763、#777)
  • 同時実行制御の最適化: ビルダーの最適化スレッド プールを再利用し、ネストされた RaBitQ および DiskANN トレーニングで構成された最適化同時実行を尊重しました。 (#757、#775)
  • SQL とフィルタリングされた取得: バランスの取れた深い OR 式ツリー、LIKE でのプレフィックス/サフィックスの重複一致の防止、逆インデックス サフィックスと空の配列クエリの修正、フィルタリングされた IVF クエリの主キー ブルート フォース検索の有効化。 (#694、#745、#752、#816)
  • 正確な浮動小数点範囲境界: 逆インデックス条件を順方向フィルターに変換するときに FLOAT および DOUBLE 境界を保持し、排他的比較で境界に等しい値が引き続き除外されるようにします。 (#818)
  • FTS の永続性とリカバリ: サイドカラムファミリーを削除し、強化された WAL リカバリ、スキーマ処理、およびデコードを行う前に、シールされたフルテキスト投稿を永続化しました。 (#759、#756)
  • ARM FP16 ディスパッチ: ARM NEON FP16 カーネルのコンパイル時の検出とランタイムの選択を修正しました。 (#723)

🔧 リファクタリングと開発者ツール

  • ストレージ読み取り有効期間: インデックス ストレージ読み取りが MemoryBlock に移行され、インデックス実装間で有効期間安全な借用およびバッチ アクセスが拡張されました。 (#812)
  • SQL フィルターの計画: 拡張可能なフィルターセットの書き換えを追加し、フィルター検証を実行バインディングから分離しました。 (#690、#769)
  • RaBitQ 依存関係の更新: RaBitQ-Library を v0.3.8 から v0.7.0 にアップグレードし、アップストリームのモジュラー コア/FastScan ターゲットを採用しました。 (#780、#814)
  • コア ツールと静的分析: コア ベンチマーク/ビルド ツールにターボ クオンタイザーのサポートを追加し、clang-tidy プリコミット フックを導入し、最新化と識別子の命名チェックを拡張しました。 (#684、#571、#734、#751、#764)

🤖 CI とビルドの改善

  • 競合する MSVC デバッグ フラグ、テスト中の MSVC ARM64 コンパイラ クラッシュ、利用できないレガシー Android SDK ツール、およびビルド警告を修正しました。未使用の Thrift OpenSSL サポートを無効にし、Android の事​​前構築済み SDK ライブラリからデバッグ シンボルを削除しました。 (#692、#795、#753、#720、#819、#702)
  • actions/setup-python、actions/setup-java、softprops/action-gh-release を更新 (#712、#750、#725)
