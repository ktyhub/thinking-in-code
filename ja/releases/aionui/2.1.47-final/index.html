#アイオンウイv2.1.47-final

これは、GitHub リリースを通じて配布される最後の AionUi ビルドです。 これ以降、インストーラーとアップデートは公式 Web サイトから入手します。これがあなた、あなたのデータ、オープンソース リポジトリにとって何を意味するかについては、下部にある 配布に関する注意事項 を参照してください。

ハイライト

アプリ内ブラウザ、エージェントによって制御可能

  • Web ページがプレビュー パネルのタブとして開き、エージェントと 1 つの永続セッションを共有します。一度手動でサインインすると、エージェントはそのセッションを次の動作に引き継ぎます。
  • エージェントは、新しい組み込み MCP サーバー (aionui-browser) を介してブラウザに到達するため、独自にナビゲートし、click し、データを取得できます。
  • 安全性について: エージェントに Chromium を駆動させる明白な方法は --remote-debugging-port ですが、このスイッチはアプリケーション全体に適用され、ターゲットごとの ACL はありません。メイン ウィンドウとそのプリロード ブリッジを含む「すべて」の Web コンテンツが、認証なしでローカル プロセスに公開されることになります。代わりに、ブラウザ ビューのみを公開する単一ターゲット CDP ブリッジが同梱されます。 config やデータベースには何も書き込まれません。ブリッジのポートとアクセス トークンはプロセス継承チェーンを移動するため、複数のアプリ インスタンスがワイヤーを通過することはありません。

会話の分岐

  • メッセージ ホバー行の分岐矢印は、そのメッセージでの会話を新しいメッセージに分岐させ、そのメッセージにドロップします。元のメッセージを妨げずに別のパスを探索するのに役立ちます。
  • エントリが表示される場所は、バックエンドが実際に実行できる内容に従います。Codex はいつでもフォークでき、Claude エージェントと ACP エージェントは最新のメッセージでのみフォークします (そのため、コピーされた履歴はフォークされたセッションが実際に記憶している内容と一致します)、フォーク サーフェスのないエージェントにはエントリがまったく表示されません。

エージェント主導の会話の名前付け

  • これをサポートするエージェントは、会話のタイトルを自動的に提案するようになりました。自分で設定した名前は決して上書きされず、デフォルト名と派生名のみが置き換え可能です。

修正と改善

  • v2.1.46 で導入されたメッセージ アンカー レールは、メッセージ テキストを避け、完全な会話履歴をカバーするようになりました。
  • データベースの再構築は 2 回目の確認の後にゲートされるため、misclick によってローカル データが消去されることはありません。
  • GPU プロセスのクラッシュ ノイズが抑制され、ハードウェア アクセラレーションが自動的に無効になったときにアプリが通知するようになりました。根本的なクラッシュは、コードの回帰ではなく、非常に古いドライバーを使用したサポート終了した GPU に起因しており、誤解を招くクラッシュ レポートにより、それを確認することが困難になりました。
  • ワークスペースのトグルは、それが属しているタイトル バーに残ります。
  • チーム実行状態は、省略されたスロット作業に混乱することなく処理します。
  • ChatFileRef /content エンドポイントに移行されたプレビュー ファイル I/O。 PDF はストリーム URL 経由で読み込まれるようになり、Office ファイルは ChatFileRef 経由で解決されます。

エンジンのアップデート (AionCore v0.1.57 → v0.1.58)

  • 会話のフォークとエージェント主導のセッション命名は、ここでエンドツーエンドでサポートされています。これは、上記の両方の機能のバックエンドの半分です。
  • クロード セッション コストは、リセットされるのではなく、プロセスが再生成されるまで累積的に維持されるようになりました。
  • 進行状況カードは、セッションのティアダウンと再開を通じて正しく設定されます。以前は、基礎となる作業が実行され続けている間にアイドル リーパーが途中でタスクを削除した場合、保存された行は running のままになり、すでに成功したタスクの上で [ステップの表示] スピナーが何時間も回転したままになりました。
  • 再開された会話では、思考レベルの選択が維持されます。
  • 管理対象ノードのバージョン プローブは、最初の失敗を諦めるのではなく、一時的な失敗を再試行するようになりました。

配布に関する注意事項

AionUi とその商用版はパッケージ名を共有していますが、異なる署名を使用しており、オペレーティング システムは署名を越えた上書きインストールを拒否します。アプリ内アップデートでは単にユーザーを移動させることができないため、このビルドは「廃止モード」で出荷されます。起動時の自動チェックは停止され、手動アップデート チェックでは代わりに公式 Web サイトを指す移行レターが開きます。 移動する場合:

  • 会話とファイルはローカルに残ります。 エージェントは自分のマシン上で実行されます。コンテンツが当社のサーバーにアップロードされることはありません。
  • ローカル データはそのまま引き継がれます。 最初のサインイン後、新しいバージョンは既存の会話、設定、API キーを適切に継承します。再構成は必要ありません。これは 1 回限りの移行です。完了すると、新しいバージョンがそのデータを所有し、このビルドはそのエントリ ポイントではなくなります。
  • ペイウォールは付属しません。 現在どのように使用しても、今後も使用し続けることができます。今日無料のものは今後も無料です。
  • オープンソース リポジトリは更新され続けます。 コア機能は常に同期されており、オープンソースの精神は変わりません。 新しいバージョンにはサインインが必要です (Google は現在、より多くの方法を開発中です)。この変更の背後にある理由も同じです。インストーラーが一度公開されると、再度アクセスすることはできないため、修正は決して到着せず、新しいスキルやアシスタントは同期できません。また、多くのユーザーが求めていた、複数のアカウント、データ同期、より安全なモバイル コラボレーションなどには、すべてその下に適切なサービス層が必要です。 次はまだオープンソースです: チームボード (マルチエージェントコラボレーションのグローバルビュー)、会話アーカイブ、デバイス間でのデータ同期、およびより広範な組織コラボレーション。 それはまだあなたの選択です。 AionUi が毎日のワークフローの一部である場合は、新しいバージョンに移行することをお勧めします。新しい機能が最初に搭載されます。ローカル DIY を好む場合は、このリポジトリをプルして自分で構築し続けてください。まだアップグレードしない場合でも、このバージョンは引き続き動作します。アップデートを受信できないだけです。 AionUi をここまで読んでいただきありがとうございます。

  • 偉業（プレビュー）: ストリーム URL + office ChatFileRef 経由の PDF + #3837 の @tcp404 によるドロップ fs/resolve
  • 修正(デスクトップ): #3838 の @piorpua による GPU プロセスのクラッシュ ノイズとサーフェスの HW アクセル自動無効化を静める
  • 修正(レンダラー): #3840 の @piorpua による 2 回目の確認の背後でゲート データベースを再構築しました。
  • feat(会話): #3839 の @kaizhou-lab によるエージェント自動命名用の name_source で派生タイトルをタグ付け
  • ドキュメント (readme): #3846 の @IceyLiu により、キミ キャンペーン track_id を API プラットフォーム リンクに追加します。
  • 修正（レンダラー）: #3845 の @tcp404 によりタイトルバーのワークスペース切り替えを維持
  • 修正(チーム): #3847 の @tcp404 による実行状態で省略されたスロット作業を処理します。
  • 偉業(会話): #3843の@kaizhou-labによる機能ゲート型可視性を備えたメッセージレベルのフォークエントリ
  • 特技(更新): #3730の@kaizhou-labによるアプリ内アップデートの中止と公式ウェブサイトへの移行の案内
  • 修正(会話): アンカー レールにテキストが入らないようにし、#3848 の @IceyLiu による完全な履歴をカバーします。
  • 偉業(プレビュー): #3826 の @IceyLiu により、単一ターゲット CDP ブリッジ上にエージェント制御可能なアプリ内ブラウザを追加します。
