#パドルOCR v3.2.0

2025.8.21 v3.2.0 をリリースしました

  • 重要なモデルの追加:

    • PP-OCRv5 認識モデルのトレーニング、推論、展開を英語、タイ語、ギリシャ語で導入しました。 PP-OCRv5 英語モデルは、メインの PP-OCRv5 モデルと比較して英語シナリオで 11% 向上し、タイ語とギリシャ語の認識モデルはそれぞれ 82.68% と 89.28% の精度を達成しました。

  • 展開機能のアップグレード:

    • PaddlePaddle フレームワーク バージョン 3.1.0 および 3.1.1 を完全にサポートします。
    • PP-OCRv5 C++ ローカル展開ソリューションの包括的なアップグレード。現在、Linux と Windows の両方をサポートしており、Python 実装と同等の機能と同一の精度を備えています。
    • 高パフォーマンス推論が CUDA 12 をサポートするようになり、パドル推論または ONNX ランタイム バックエンドを使用して推論を実行できるようになりました。
    • 安定性の高いサービス指向展開ソリューションが完全にオープンソース化され、ユーザーは必要に応じて Docker イメージと SDK をカスタマイズできます。
    • 安定性の高いサービス指向展開ソリューションは、手動で構築された HTTP リクエストによる呼び出しもサポートしており、あらゆるプログラミング言語での client 側のコード開発が可能です。

  • ベンチマークのサポート:

    • すべての生産ラインがきめ細かいベンチマークをサポートするようになり、エンドツーエンドの推論時間だけでなく、レイヤーごとおよびモジュールごとの遅延データを測定して、パフォーマンス分析を支援できるようになりました。
    • ドキュメントが更新され、推論レイテンシやメモリ使用量など、主流のハードウェアで一般的に使用される構成の主要なメトリクスが含まれ、ユーザーに展開のリファレンスが提供されました。

  • バグ修正:

    • モデルのトレーニング中にログの保存に失敗する問題を解決しました。
    • 新しいバージョンのアルバムメンテーション依存関係との互換性のために数式モデルのデータ拡張コンポーネントをアップグレードし、マルチプロセス シナリオでトークナイザー パッケージを使用する場合のデッドロック警告を修正しました。
    • 他のパイプラインと比較した、PP-StructureV3 構成ファイル内のスイッチ動作 (use_chart_parsing など) の不一致を修正しました。

  • その他の機能強化:

    • コアとオプションの依存関係を分離しました。基本的なテキスト認識には最小限のコア依存関係のみが必要です。必要に応じて、ドキュメントの解析と情報抽出のための追加の依存関係をインストールできます。
    • Windows での NVIDIA RTX 50 シリーズ グラフィックス カードのサポートが有効になりました。ユーザーは、対応する PaddlePaddle フレームワーク バージョンのインストール ガイドを参照してください。
    • PP-OCR シリーズ モデルは、単一文字の座標を返すことをサポートするようになりました。
    • AIStudio、ModelScope、およびその他のモデル ダウンロード ソースが追加され、ユーザーがモデル ダウンロードのソースを指定できるようになりました。
    • PP-Chart2Table モジュールを介したチャートからテーブルへの変換のサポートが追加されました。
    • ドキュメントの説明を最適化し、使いやすさを向上させました。

2025.8.21 v3.2.0 発信

  • 重要なモデルの新機能：

    • PP-OCRv5 和文、泰文、希腊文承認モデルの計画、駐在、配置が新しくなりました。** PP-OCRv5 和文モデルよりも PP-OCRv5 主モデルが英文场景で上昇 11%、泰文承認モデル精度 82.68%、希腊文承認モデル精度89.28%。**

  • 配備能力升级：

    • 飞桨フレーム 3.1.0 および 3.1.1 バージョンを全面的にサポートします。
    • 完全昇級 PP-OCRv5 C++ のこの配置方式は、Linux、Windows をサポートし、機能および精度の効果は Python 方式と一致しています。
    • 高性能メモリサポート CUDA 12、パドル推論、ONNX ランタイム後端メモリを使用可能。
    • **高安定性サービス化配置スキームは全面的に提供されており、ユーザーのニーズに応じた Docker イメージおよび SDK の定型化変更をサポートします。

  • 安定性の高いサービスベースの展開ソリューションは、HTTP リクエストを手動で構築することによる呼び出しをサポートします。これにより、クライアント コードを任意のプログラミング言語で記述することができます。

  • ベンチマークのサポート:

    • **すべての生産ラインは、生産ラインのきめ細かいベンチマークをサポートしています。これにより、生産ラインのエンドツーエンドの推論時間だけでなく、レイヤーごとおよびモジュールごとに時間のかかるデータを測定でき、生産ラインのパフォーマンス分析を支援するために使用できます。 **
    • **このドキュメントは、推論時間やメモリ使用量など、主流のハードウェア上の各生産ラインで一般的に使用される構成の主要な指標を補足し、ユーザー導入の参考を提供します。 **

  • バグ修正:

    • モデルトレーニング中にトレーニングログの保存に失敗する問題を修正しました。
    • 数式モデルのデータ拡張部分は、アルバムの依存関係の新しいバージョンに適応するためにバージョン互換性のためにアップグレードされ、トークナイザーの依存関係パッケージを複数のプロセスで使用するときに表示されるデッドロック警告が修正されました。 ・PP-StructureV3設定ファイルのuse_chart_parsing等のスイッチの動作が他の生産ラインと一致しない問題を修正しました。

  • その他のアップグレード:

    • **必要な依存関係とオプションの依存関係を分離します。基本的なテキスト認識機能を使用する場合、いくつかのコア依存関係のみをインストールする必要があります。ドキュメントの解析や情報抽出などの機能が必要な場合、ユーザーは必要に応じて追加の依存関係をインストールすることを選択できます。 **
    • **Windows ユーザーによる NVIDIA 50 シリーズ グラフィックス カードの使用をサポートし、インストール ドキュメントに従って対応するバージョンのパドル フレームワークをインストールできます。 **
    • **PP-OCR シリーズ モデルは、単一のテキスト座標を返すことをサポートしています。 **
    • AIStudio や ModelScope などの新しいダウンロード ソースがモデルに追加されました。関連するダウンロード ソースを指定して、対応するモデルをダウンロードできます。
    • チャートからテーブルへの変換 PP-Chart2Table 単機能モジュール推論機能をサポートします。 ・一部の使用説明書の記述を最適化し、使いやすさを向上しました。
