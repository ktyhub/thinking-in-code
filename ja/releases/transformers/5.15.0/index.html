メタミューズグリマー

本日リリースされた Muse Glimmer は、特にエージェントの使用例向けに設計された Meta の新しいマルチモーダル モデルです。 Muse から 30B パラメータに抽出され、Apache 2.0 ライセンスに基づいてリリースされているため、コーディング、ドキュメント分析、パーソナル アシスタント、Claw または Hermes のようなセットアップなど、プライバシーを意識したアプリケーションのローカル セットアップに導入できます。

Muse Glimmer は、以下で構成される高密度の 30B パラメーター モデルです。

  • 2B ViT スタイルの視覚用エンコーダー (Perception Encoder)
  • 28Bパラメータテキストデコーダ

これについては、次のブログ投稿で説明しています: http://hf.co/blog/muse-glimmer

重大な変更

リニア アテンション モデル (Mamba、GDN、Conv-only など) ではカーネルが必須ではなくオプトインになりました。そのため、自動カーネル選択に依存していたユーザーは、以前の動作を維持するためにカーネルを明示的に有効にする必要があります。

  • 🚨 [Kernels] すべての線形 attn モデルとネイティブ カーネル フォールバックをリファクタリング (#47630) by @vasqu

キャッシュ クロッピング API は、絶対サイズではなく負の値 (相対オフセット) のみを受け入れるようになりました。そのため、クロップ メソッドを直接呼び出すユーザーは、それに応じて負の値を渡すようにコードを更新する必要があります。

  • 🚨 [キャッシュ] トリミングは負の値でのみ実行できます (#47720) by @Cyrilvallez

T5 とそのモデル ファミリ (MT5、LongT5 など) は、ALL_ATTENTION_FUNCTIONS 経由で SDPA およびその他のアテンション バックエンドをサポートするようになりました。つまり、デフォルトのアテンションの実装は変更される可能性があり、以前の Eager-Only パスに依存するユーザーは、必要に応じて明示的に attn_implementation="eager" を設定する必要があります。

  • 🚨 T5 の SDPA (およびその他のアテンション バックエンド) を有効にし、@jiqing-feng によって T5 ファミリ (#47014) に伝播します。

いくつかの小さなプライベート ヘルパー関数 (_is_url、_build_image_tokens など) がマルチモーダル プロセッサ ファイルから削除されたため、これらのプライベート関数を直接インポートしたユーザーまたはダウンストリーム ライブラリは、それらの参照を削除または置換する必要があります。

  • :rotating_light: プロセッサーは残り (#46556) を @zucchini-nlp によって更新します

カーネル

⚠️ kernels python パッケージは、近い将来、transformers[torch] に必須の依存関係になる可能性が非常に高くなります。これは、すべてのユーザーに最大のパフォーマンスを提供するのに役立ちます。カーネルは、HF チームによって手動で承認された trusted パブリッシャーからのみダウンロードされます。統合を強化するために、直面している問題があれば事前にお知らせください。

レイヤー リポジトリを使用するように関数処理をリファクタリングし、HfApi を介したカーネル ダウンロード用の CI EROFS フォールバック パッチを修正し、causal_conv1d_fn での位置引数の衝突を解決し、NaN を防ぐために FP8 カーネル バージョンをバンプすることにより、カーネル統合の堅牢性が向上しました。
