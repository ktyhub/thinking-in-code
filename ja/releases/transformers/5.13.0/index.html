kimiK 2.5、2.6、2.7

<img width="1097" height="400" alt="image" src="https://github.com/user-attachments/assets/c24d2232-a9b4-413b-a2c8-58d013b6dfbd" />

このリリースには、2.5-2.7 によって使用される Kimi 2.5 のアーキテクチャが含まれています。

Kimi K2.5 は、長期的なコーディング、コーディング駆動設計、プロアクティブな自律実行、およびスウォームベースのタスク オーケストレーションにおける実用的な機能を向上させる、オープンソースのネイティブ マルチモーダル エージェント モデルです。このモデルは Kimi K2.5: Visual Agentic Intelligence で提案され、[Kimi K2.6: Advancing Open-Sourcecoding](Kimi K2.5: Visual Agentic Intelligence) でさらに改良されました。

Kimi K2.5 は、複雑なエンドツーエンドのコーディング タスクを大幅に改善し、プログラミング言語 (Rust、Go、Python) およびフロントエンド、DevOps、パフォーマンス最適化にまたがる領域にわたって堅牢に汎用化します。このモデルは、単純なプロンプトと視覚的入力を実稼働対応のインターフェイスと軽量のフルスタック ワークフローに変換し、構造化されたレイアウト、インタラクティブな要素、および意図的に美的精度を備えた豊富なアニメーションを生成することができます。

MiMo-V2-フラッシュ

<img width="6900" height="904" alt="image" src="https://github.com/user-attachments/assets/8bd8d5f0-0381-4f8c-8ada-0203e11ff494" />

MiMo-V2-Flash は、Xiaomi MiMo チームによって開発された Mixture-of-Experts (MoE) 言語モデルです。このモデルは、ロングコンテキストのモデリング機能と推論効率の間の新たなバランスを確立するように設計されており、複雑な推論やエージェントタスクで優れたパフォーマンスを発揮できるように構築されています。ネイティブ 32k シーケンス長の 27T トークンでトレーニングされた MiMo-V2-Flash は、拡張された 256K コンテキスト ウィンドウをシームレスにサポートしながら、標準のグローバル アテンション モデルと比較して KV キャッシュ ストレージを大幅に削減します。

ネモトロン 3.5 ASR

<img width="1632" height="735" alt="image" src="https://github.com/user-attachments/assets/597bbb9c-b046-4e47-b9fd-f242e0a5b04d" />

Nemotron 3.5 ASR は、NVIDIA の 600M パラメータの多言語音声認識モデルで、ネイティブの句読点と capitalization を備えた、低遅延ストリーミングと高スループットのバッチ設定の両方で高品質の文字起こしを行うために構築されています。ストリーミングの場合、構成可能なチャンク サイズ (80 ミリ秒、160 ミリ秒、560 ミリ秒、1120 ミリ秒) が提供され、ユーザーはアプリケーションに合わせて遅延と精度をトレードオフできます。キャッシュ対応の FastConformer-RNNT アーキテクチャは、この機能の中心です。重複するオーディオ ウィンドウを繰り返し再処理する従来のバッファリングされたストリーミングとは異なり、このモデルは、以前のチャンクからキャッシュされたエンコーダー コンテキストを再利用しながら、新しい受信チャンクのみを処理します。これにより、冗長な計算が排除され、効率が大幅に向上し、精度を犠牲にすることなくエンドツーエンドの遅延が最小限に抑えられるため、リアルタイムの文字起こしワークロードに適しています。

ビデオプリズム

VideoPrism モデルは、Google DeepMind による論文 VideoPrism: A Foundational Visual Encoder for Video Understanding で提案されました (ブログ投稿)。

VideoPrism は、単一のフリーズされたモデルで多様なビデオ理解タスクに取り組む汎用ビデオ エンコーダーです。このモデルは、3600 万の高品質ビデオとキャプションのペアと、ノイズの多い並列テキスト (ASR トランスクリプトなど) を含む 58200 万のビデオ clips を含む大規模な異種コーパスで事前トレーニングされています。事前トレーニング アプローチは、セマンティック ビデオ埋め込みのグローバル ローカル蒸留とトークン シャッフル スキームを通じてマスクされた自動エンコーディングを改善し、ビデオに関連付けられたテキストを活用しながら、モデルが主にビデオ モダリティに焦点を当てることができるようにします。 VideoPrism は、Web ビデオの質問応答から科学用のコンピューター ビジョンまで、4 つの広範なタスク グループにわたる 33 のビデオ理解ベンチマークのうち 31 で最先端のパフォーマンスを達成します。

MiniCPM3

MiniCPM3 は、OpenBMB の第 3 世代 MiniCPM 高密度言語モデルです。 4B バリアント (openbmb/MiniCPM3-4B) は多くの 7B ～ 9B オープンよりも優れたパフォーマンスを発揮します デバイス上での使用に十分な軽量性を維持しながら、標準ベンチマークのモデルを実現します。

MiniCPM3 は、いくつかのアーキテクチャ上のアイデアを組み合わせています。

  • DeepSeek-V2 の マルチヘッド潜在アテンション (MLA)。キー/値キャッシュを圧縮します。 の一部にロータリー埋め込みを使用しながら、低ランクの潜在表現に変換します。 クエリ/キーヘッド。
  • 標準 SwiGLU MLP (MoE なし)。
  • 信号の流れを制御する 3 つのスカラー スケーリング係数:
    • scale_emb — 入力エンベディングをスケーリングします。
    • scale_depth / sqrt(num_hidden_layers) — 残りの接続をスケーリングします。
    • hidden_size / dim_model_base — 言語モデルの先頭の前に隠れた状態をスケーリングします。

重大な変更

レイヤー宣言、マスク/キャッシュ構築、およびハイブリッド アテンション処理を標準化するために広範なモデリング変更が行われ、多くのモデルがきれいにエクスポート可能 (ONNX、torch.export、ExecuTorch) でフルグラフ コンパイル可能になりました。内部モデリング API に依存しているユーザーは、それに応じてコードを更新する必要がある場合があります。

  • 🚨 エクスポート、コンパイル、およびハイブリッド アテンションの標準化のためのモデリングの変更 (#46738) by @IlyasMoutawwakel

Gemma 3/4 モデルのイメージ トークンのアテンション マスキングは、ローカル レイヤーのスライディング ウィンドウ境界を正しく尊重するように修正されました。これにより、モデルの動作が変更され、以前の結果の再現性に影響を与える可能性があります。

  • 🚨 [gemma 3/4] スライディング ウィンドウの境界を越える双方向アテンション マスキングを修正 (#46850) by @douglas-reid

Expert Parallelism (EP) ルーター契約が多くのモデルにわたって修正され、FP8 スケール形式の処理が修正されたため、影響を受けるモデルで EP または FP8 量子化を使用するユーザーは、構成を確認し、場合によっては変換マッピングを更新する必要があります。

  • 🚨 EP: 多くのモデルの EP ルーター契約を修正 + FP8 スケール形式 (#46818) を尊重 (@IlyasMoutawwakel による)

Kernels 統合は最新バージョンに同期されています。これには、モデル タイプのリポジトリがカーネル インターフェイスで受け入れられなくなるという重大な変更が含まれています。ユーザーは、更新されたテストに示されているように、更新されたカーネル リポジトリ形式に移行する必要があります。

HfExporters: PyTorch / ONNX / ExecuTorch のネイティブ統合エクスポート

<img alt="サムネイル" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

ネイティブの Transformers 内のエクスポート パイプライン — 1 つの基本クラス (HfExporter)、重要なランタイムの 3 つのサブクラス、1 つの統合 API:

|輸出業者 |出力 |ランタイム | |---|---|---| | DynamoExporter | ExportedProgram |任意の PyTorch ランタイム、AOT コンパイル | | OnnxExporter | ONNXProgram |任意の ONNX ランタイム (ORT、TensorRT、OpenVINO など) | | ExecutorchExporter | ExecutorchProgramManager |モバイルとエッジ (ExecuTorch) | 3 つすべてで同じコール形状。デフォルトでは動的シェイプ。生成スタイルのモデルは、プリフィル + デコード (+ VLM のビジョン/オーディオ サブエンコーダー) に自動的に分割されます。

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

1 行を別のランタイム (DynamoExporter() / DynamoConfig または ExecutorchExporter() / ExecutorchConfig(backend=...)) に交換します。

生成モデルの場合、プリフィル/デコード分割は自動的にキャプチャされます。

from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-LlamaForCausalLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")

artifacts = OnnxExporter().export_for_generation(model, inputs, config=OnnxConfig(dynamic=True))
# {"prefill": ONNXProgram, "decode": ONNXProgram}
# For VLMs: also vision_encoder, audio_encoder, multi_modal_projector, language_model, lm_head
