ミューズスパークオープン

<img width="2400" height="1296" alt="image" src="https://github.com/user-attachments/assets/bf34ea27-0edf-4ded-ba6f-905b04096126" />

Muse Spark Open は、テキスト、画像、オーディオ、ビデオを入力として受け取り、テキストを生成する、Meta のマルチモーダル専門家混合モデルです。合計 816B のパラメータ (トークンあたり 42B がアクティブ) と、モダリティ間で共有される最大 1,048,576 個のトークンのコンテキスト ウィンドウがあります。複数ファイルの編集、デバッグ、ツールの使用などのエージェント コーディング タスク向けにトレーニングされています。チェックポイントは、BF16 および NVFP4 形式で使用できます。

リン 3.0

Ling 3.0 Flash は、InclusionAI のハイブリッド専門家混合言語モデルです。そのデコーダは、5 つのキミ デルタ アテンション (KDA) レイヤーを 1 つのマルチヘッド レイテント アテンション (MLA) レイヤーとグループ化します。 MLA ブロックはインターリーブされたロータリー エンベディングとヘッドワイズ出力ゲートを使用し、フィードフォワード ブロックはルーティングされたエキスパートと共有エキスパートを組み合わせます。 Transformers では BailingHybridForCausalLM としてネイティブにサポートされているため、trust_remote_code=True なしでロードされます。

コリブリ1

Kolibri 1 は、ドイツ語と英語に重点を置いた、Aleph Alpha の専門家混合推論モデルです。その 50 の各レイヤーは、シグモイド ルーティングを使用してすべてのトークンを 384 人のエキスパートのうち 6 人にルーティングし、1 人の共有エキスパートを追加します。 4 つのスライディング ウィンドウ アテンション レイヤーと 1 つのフル アテンション レイヤーが交互に配置され、RoPE はスライディング ウィンドウ レイヤーにのみ適用されます。

MiniCPM-V 4.7

MiniCPM-V は、OpenBMB によって開発された一連の効率的なマルチモーダル大規模言語モデルです。 MiniCPM-V 4.6 と同様、MiniCPM-V 4.7 アーキテクチャは、ウィンドウ アテンション マージを備えた SigLIP ビジョン エンコーダと Qwen3.5 言語モデル バックボーンを組み合わせ、4 倍と 16 倍のビジュアル ダウンサンプリング モードをサポートします。

4.6 に対する主な追加点は キャンバス M-RoPE です。単一の 1-D シーケンスに沿ってビジュアル トークンに番号を付ける代わりに、モデルはすべての画像を 2-D キャンバス上にレイアウトし、各ビジュアル トークンに (temporal, height, width) 位置を割り当てます。そのため、同じ画像のスライスは空間的関係を維持し、ビデオ フレームは時間的順序を維持します。

UnlimitedOcr

UnlimitedOcr は、Baidu の単一 3B パラメータ OCR モデルで、標準的な 32,768 トークンのコンテキスト長を備えています。これは DeepSeek OCR に基づいて構築されており、すべてのデコーダ アテンション レイヤーを Reference Sliding Window Attendant (R-SWA) に置き換えます。これにより、デコード中に KV キャッシュが一定に保たれるため、モデルは 1 回の順方向パスで数十ページを転写できます。 「ガンダム」モード (動的クロッピングを備えた 640x640 タイル) と「ベース」モード (単一の 1024x1024 ビュー) をサポートし、境界ボックスを使用して領域検出を出力できます。

ウルトラバート

UltraBERT は、分類および検索タスクのためにマスキング率、プルーニング、蒸留を組み合わせてトレーニングされた双方向テキスト エンコーダー ファミリです。リリースされたエンコーダーは、最大 32,768 個のトークンのシーケンスをサポートします。これらは、回転位置埋め込み、RMSNorm、SwiGLU フィードフォワード層、および交互のローカル アテンションとグローバル アテンション (3 層ごとにグローバル) を使用します。チェックポイントには、マスクされた言語モデリングと微調整用の UltraBERT-150M および UltraBERT-380M、テキスト埋め込み用の UltraBERT-Embed-150M が含まれます。

MOSS-Transcribe-Diarize

MOSS-Transcribe-Diarize 0.9B は、複数話者の長文文字起こし、話者ダイアライゼーション、およびタイムスタンプのためのエンドツーエンドの音声理解モデルです。これは、Whisper スタイルのエンコーダー、4x フレーム マージ ステップ、マルチモーダル プロジェクター、および Qwen3 言語モデルを組み合わせています。 [start][S01]text[end] としてフォーマットされたセグメントを使用して、単一パスで共同転写とダイアライゼーションを生成します。プロセッサーのウィスパー ウィンドウ チャンキングによる長文オーディオ、ホットワード バイアスによるプロンプト文字起こし、および 50 以上の言語をサポートします。

重大な変更

🚨 EP による推論には速度の低下があるという一般的な速報。できるだけ早くこの問題を修正できるよう取り組んでいます。 🚨

非推奨のチェックとメソッドは cache_utils.py から削除されたため (minimax_m3_vl や pi0 などのモデルに影響)、これらの非推奨のキャッシュ メソッドをまだ呼び出しているコードは、現在のキャッシュ API に切り替える必要があります。

  • 🚨 @guarin による非推奨のキャッシュ ユーティリティ メソッド (#49605) を削除

他のモデルからの偶発的なインポートはいくつかのモデル ファイル (embedding_gemma2、ijepa、lightglue など) から削除され、モジュラー コンバーターはそのようなモデル間インポートの追加を回避するようになりました。これらのモデル モジュールを通じてこれらの名前をインポートした場合は、代わりに元のモジュールからインポートしてください。

  • 🚨 他のモデルからのインポートを削除 (#49473) by @guarin

kernels の最小バージョンは 0.17.2 になり、use_fallback=KernelizeFallback.ALL が許可されるため、失敗したカーネル ロードはエラーを発生させる代わりに元の実装にフォールバックします。 kernels を 0.17.2 以降にアップグレードします。

  • 🚨 フォールバックを改善するために最小カーネルを 0.17.2 にバンプ (#49235) by @SunMarc

新しい SubConfigSpec はサブ構成の初期化を集中管理するため、デフォルトのサブ構成はクラスをインスタンス化する代わりにデータクラス フィールドから収集され、これは構成ユーティリティと多くのモデル構成に影響します。このメカニズムを通じてサブ構成を宣言するには、カスタムまたは既存のネストされた構成を更新する必要がある場合があります。

  • :rotating_light: @zucchini-nlp によるサブ構成の集中初期化用の SubConfigSpec (#48282)

LUKE および mLUKE トークナイザーは、デコード時に通常の語彙トークンと同じ間隔を維持しながら、<ent> などのエンティティ特殊トークンを特殊トークン (分割されず、skip_special_tokens によって尊重され、正規化されたもの) として扱うようになりました。したがって、これらのトークンに関連するトークン化とデコード出力は以前とは異なる可能性があるため、古い動作に依存するコードまたは保存された出力を確認してください。

輸出業者

Transformers エクスポーターは、Dynamo、ONNX、OpenVINO、および ExecuTorch にわたるエクスポート中に直接量子化をサポートするようになりました。新しい統合量子化 API は、PT2E、ONNX ランタイム、および NNCF 量子化器を統合し、構成可能なキャリブレーション ワークフローにより、静的および動的量子化と重みのみの圧縮 (INT8/INT4) を可能にします。これにより、さまざまなバックエンド間で効率的な推論を行うために最適化されたモデルをエクスポートしやすくなります。

詳細については、ドキュメントを参照してください: https://huggingface.co/docs/transformers/exporters_quantization
