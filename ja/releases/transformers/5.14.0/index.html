#トランスフォーマーv5.14.0

v5.14.0 をリリース

新しいモデルの追加

Inkling (Thinking Machines からの新鮮): 合計 975B、アクティブ 41B

  • @molbap @Cyrilvallez @eustlb および @zucchini-nlp による Inkling モデル #47347 を追加
<img width="3840" height="2160" alt="image" src="https://github.com/user-attachments/assets/051f819a-512f-4987-9bee-6e2fa2af3db7" />

Inkling は、テキスト、画像、音声入力を受け入れる汎用マルチモーダル モデルです。 テキスト出力を生成します。英語やその他の言語での使用を目的としています。 複数のコーディング言語。このモデルは、AI を構築する開発者が使用するように設計されています。 エージェントおよびツール使用システム、コーディングアシスタント、チャットボットなどの強化されたアプリケーション 検索拡張生成システムであり、汎用の会話型言語に適しています。 使用、指示に従う、その他の自然言語およびマルチモーダルなタスク。で発売されます 研究、微調整、サードパーティ製品への統合をサポートするオープンウェイト 下流の開発者。

:rotating_light: 重大な変更

GPTNeoX は embed_out を lm_head に再マッピングするようになり、GPTBigCode では vLLM 互換性のために _supports_attention_backend = True が有効になりました。これらのモデルの以前の重み付けまたはアテンション バックエンド動作に依存しているユーザーは、それに応じてコードを更新する必要があります。

  • :rotating_light: vLLM のトランスフォーマー モデリング バックエンドの GPTBigCode と GPTNeoX を修正 (#47198) by @hmellor

カーネル

ベンチマーク ワークフローで kernels の依存関係を互換性のあるバージョンに固定すること、廃止予定の package_name 引数を LocalLayerRepository から削除すること、CUDA_HOME が設定されていない場合や構成が間違っている場合の DeepGEMM Triton フォールバックをより堅牢にすることなど、カーネル関連のいくつかの修正と改善が行われました。さらに、SDPA プレフィルが更新され、StaticCache で FlashAttendant カーネルを利用するようになり、パフォーマンスが大幅に向上しました (入力サイズが大きい場合は最大 260% 高速化)。

  • ベンチマーク ワークフロー (#47339) でカーネルを互換性のあるバージョンに固定 ([#47339] の @tarekziade による)
  • [修正] @remi-or による kernels 呼び出し (#47100) から非推奨の引数を削除 [#47100]
  • [修正] DeepGEMM triton フォールバックをより堅牢にする (#47126) @remi-or の [#47126]
  • [sdpa] プリフィルで StaticCache を使用した FA カーネルの使用を許可 (#47094) @Cyrilvallez [#47094]

世代

生成の改善には、マルチトークン予測 (MTP) デコードサポートの追加、ドラフトトークン受け入れ率を向上させるための投機的デコードのための静的アンサンブル検証、およびさまざまなトークナイザーを使用したグリーディアシスト生成でのクラッシュの修正が含まれます。連続バッチ モードでの synced_gpus の誤解を招く二重否定警告メッセージも修正されました。

  • [世代] 連続バッチ処理における誤解を招く synced_gpus 警告 (#47158) を修正 (@Partha-Shankar による [#47158])
  • [生成] 適切な MTP サポート (#46229) を追加 (@Cyrilvalez による [#46229])
  • [#46936] の @Sunt-ing による、さまざまなトークナイザーを使用した貪欲な支援生成でのクラッシュを修正 (#46936)
  • [生成] 非可逆投機的復号化のための静的アンサンブル検証を追加 (#45979) @kasakh による [#45979]

パフォーマンス

Qwen3-VL などのモデルに影響を与える Flash アテンションのパフォーマンス回帰を修正し、グループ化からバッチ化への行列乗算スイッチがサブモデル (ネストされたテキスト構成を持つ VLM など) に常駐するエキスパートに適用されなかった MoE デコード最適化のバグを解決しました。

  • [#47134] の @andreasgoulas による FA パフォーマンスの回帰 (#47134) を修正
  • [#47107] の @IlyasMoutawwakel によるサブモデル内に存在するエキスパート向けの MoE デコード最適化を修正 (#47107)
  • ドキュメントのビルドを高速化 (#47099) @mishig25 による [#47099]

キャッシュ

キャッシュ ディスパッチ ロジックは、スライディング レイヤーとスタティック レイヤーに明示的なレイヤー タイプ マッピングを導入することで簡素化され、キャッシュ ルーティングの複雑さが軽減されました。さらに、CPU CI 環境での読み取り専用キャッシュの障害と、Apple Silicon での可変長バッチ トレーニング中の MPS グラフ キャッシュの増加が修正されました。

  • [#47043] の @ydshieh による conftest (#47043) のcached_files にパッチを適用することで、CI 読み取り専用キャッシュのエラーを修正
  • トレーナー: torch_empty_cache_steps 経由で MPS グラフ キャッシュをクリア (#45818) @anagnorisis2peripeteia による [#45818]
  • [キャッシュ] [#47118] の @Cyrilvallez による、layer_types (#47118) に基づいてキャッシュのディスパッチを簡素化しました。
