#トランスフォーマーv5.21

v5.21.0 をリリース

新しいモデルの追加

MiniCPM-OCR

MiniCPM-OCR は、OpenBMB の MiniCPM-V ファミリのドキュメント理解モデルです。 SigLIP ビジョン エンコーダーとウィンドウ アテンション マージを Qwen3.5 言語モデルと組み合わせた MiniCPM-V 4.6 アーキテクチャが維持されています。スキャンしたページ、スクリーンショット、領収書、表などのテキストの多い画像の読み取りに特化しています。

フリント

<img width="3200" height="1800" alt="flint_benchmarks_nvfp4" src="https://github.com/user-attachments/assets/c45955fb-dfcc-4266-8223-b0d70efb9a5b" />

Flint は、Recursive の専門家混合言語モデルです。 Qwen3-MoE などの標準 SwiGLU MoE トランスフォーマーと比較して、ハイブリッド アテンション (ほとんどのレイヤーで現在のトークンと以前の 512 トークンに対する回転埋め込みを使用したスライディング ウィンドウ アテンション、および残りのレイヤーで位置エンコーディングを使用しない完全なアテンション) を使用します。また、GPT-OSS と同様に、ヘッドごとの RMS 正規化クエリとキーを使用してアテンション シンクも学習しました。各疎層は、シグモイド スコアによって 256 人のエキスパートのうち 6 人にトークンをルーティングし、ゲートされていない共有エキスパートを追加します。最初の 2 つの層は密です。

リンク: ドキュメント

  • Flint モデルのサポートを追加。 (#49824) #49824 @lovishmadaan により

UltraVBert

UltraVBert は、UltraBERT テキスト エンコーダと SigLIP ビジョン エンコーダを組み合わせて、ドキュメントを視覚的に理解して検索できるようにすることで、ModernVBert を拡張します。その画像プロセッサは、各ページを 512 ピクセルのタイルとグローバル ビューに分割します。コネクタはビジョン パッチの各 4 x 4 ブロックを 1 つのトークンにマージするため、タイルは 64 個のイメージ トークンになり、UltraBERT のトークン埋め込みのスケールに合わせて RMS 正規化されます。 max_image_tiles 設定 (デフォルトでは 27) により、ページごとのタイル数が制限されます。

グラジウムフォノン TTS

Gradium Phonon TTS は、Pocket TTS レシピでトレーニングされた Gradium のオンデバイス テキスト読み上げモデル ファミリです。コーザル トランスフォーマーは音声プロンプトとテキストを読み取り、ワン ステップ フロー ヘッドを介して 12.5 Hz でステップごとに 1 つの連続 32 次元音声潜在を放出し、スピーチ終了ヘッドが発話の終了時期を決定します。潜在音は、Pocket TTS オーディオ トークナイザーによって 24 kHz オーディオにデコードされます。 Pocket TTS とは異なり、音声コンディショニングでは、別の未リリースのスピーカー コーデックからの 512 次元の潜在を使用するため、音声は事前に計算された潜在として提供され、録音から複製することはできません。

ポケット TTS

Pocket TTS は、Kyutai の 100M パラメータのテキスト読み上げモデルであり、CPU 上でリアルタイムよりも高速に実行される連続音声言語モデルとして構築されています。因果変換器は、ワンステップ フロー ヘッドを介してフレームごとに 1 つの連続音声潜在 (12.5 Hz) を放射し、音声終了ヘッドがいつ停止するかを決定します。 Mimi ベースのオーディオ トークナイザーは、音声プロンプトをエンコードし、生成された潜在情報を 24 kHz オーディオにデコードします。ラグランジュ自己蒸留 (デフォルト) とドリフトの 2 つのフロー ヘッドが解放され、音声を録音から複製したり、事前計算された潜在として渡したり、キャッシュされた KV 状態からロードしたりできます。 リンク: ドキュメント | [論文](https://huggingface.co/papers/2509.06926 (連続オーディオ言語モデルの論文、arXiv 2509.06926)。これはドキュメントにリンクされている唯一の論文であり、Pocket TTS が属するアーキテクチャ ファミリについて説明しています。ドキュメントでは別の Pocket TTS 技術レポートは引用されていません。) [ブログ投稿](なし。ドキュメントには公式ブログ投稿へのリンクはありません。https://github.com/kyutai-labs/pocket-tts. にあるオリジナルのコード リポジトリのみを参照しています)

Pocket TTS オーディオ トークナイザー

Pocket TTS オーディオ トークナイザーは、Pocket TTS で使用されるコーデックです。 Mimi のアーキテクチャ (SEANet 畳み込みと両側の小さな因果変換器) を備えていますが、その残差ベクトル量子化器は、連続 32 次元のボトルネックである連続オーディオ言語モデルの VAE-GAN に置き換えられています。 24 kHz オーディオを 12.5 Hz の潜在音に変換し、それらをデコードしてオーディオに戻します。これは、PocketTTSProcessor の audio_tokenizer として機能し、音声プロンプトをエンコードし、生成された潜在情報をデコードします。また、そのエンコーダーとデコーダーは、単独でロードすることもできます。

重大な変更

Gemma4 プロセッサーのインポート (Gemma4、Gemma4 統合プロセッサー、および EmbeddingGemma2 プロセッサー) を修正したため、PIL はあるが torch は存在しない環境で from transformers import * が失敗しなくなりました。ユーザーによるアクションは必要ありません。

  • :rotating_light: torch なしではあるが PIL があるとインポートが失敗するという gemma4 相互インポートを修正 (#49748) by @Sai-Suraj-27

quanto および hqq と並んで、"fp8" バックエンドを QuantizedCache に追加しました。これは、テンソルごとに 1 つのスケールで KV 状態を torch.float8_e4m3fn に保存します。 cache_implementation="quantized" および cache_config={"backend": "fp8"} で有効にします。

  • 🚨@jiqing-feng により FP8 バックエンドを QuantizedCache (#48677) に追加

テンソル並列処理には専用の埋め込みスタイルがあり、デフォルトですべてのモデルの入力埋め込みをシャーディングし、TP サイズで割り切れない幅をサポートするため、ColwiseParallel と RowwiseParallel は線形層にのみ適用されるようになりました。埋め込みに適用したカスタム TP プランは、新しい埋め込みスタイルに切り替える必要があります。

  • 🚨 TP: 埋め込みに独自のスタイルを与え、デフォルトでシャード入力埋め込みを与え、TP サイズで分割されないシャード幅 (#49570) by @IlyasMoutawwakel

現在、MoE のすべての TP および EP 計画では専門家が細分化されているため、モデルはすべてのランクにすべての専門家を保持することはなくなり、新しい test_moe_parallel_plans_shard_experts テストでこれが強制されます。カスタムまたはダウンストリームの MoE 並列プランでは、それを通過させ、メモリの無駄を避けるために、エキスパート シャーディングを追加する必要があります。

  • 🚨 MoE: すべての TP/EP 計画の専門家をシャーディングし、それをテストする (#49206) by @IlyasMoutawwakel

量子化

量子化は、DeepSeek-V4.1 の FP4 エキスパートを正しく処理するようになりました。FineGrainedFP8Config は、FP8 エキスパートを FP8 として割り当てる代わりに、FP8 エキスパートが読み取る expert_dtype オプション (デフォルトでは「fp8」または「fp4」) を取得します。 TimesFM 2.5 は、bitsandbytes 4/8 ビットなどの量子化を使用してロードされたときに、float 入力を整数重み dtype にキャストしなくなりました。より広範なクリーンアップ
