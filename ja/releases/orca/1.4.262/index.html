orca v1.4.262

パッチ 公開日2026年11月17日 出典stablyai/orca 英語原文

#シャチv1.4.262 以前のリリース: 1.4.261: パフォーマンスが大幅に向上し、カーソル チャットとカスタマイズ可能な + メニューが追加されました。

チャットの切り替えが速くなり、メモリ使用量が減り、git の責任が軽減されます ✨

macOS と Linux ではメモリを減らしてより多くの会話を開いたままにし、非表示のビューで発生する作業を減らしてチャット間を移動できます。このアップデートにより、ターミナル セッションが中断したところから再開され、回線履歴がエディタに直接表示されるようになります。

  • ⚡ 多くのチャット間で作業: チャット UI は、macOS および Linux で軽量のヘルパーを使用します。非表示のチャット ビューは更新を一時停止しますが、下書き、閲覧位置、編集者の状態を保持して戻ってくることができます。エージェントは働き続けます。
  • 🧹 ディスク容量の再利用: [設定] → [ワークスペース クリーンアップ] を選択すると、削除されたワークスペースから Orca、Claude Code、および Codex チャットを削除できます。デフォルトではオフになっています。有効にすると確認が求められ、以前に削除されたワークスペースが含まれます。削除したチャットは復元できません。
  • ⌨️ 同じターミナル フォルダーに戻る: ペインは、フォルダー ワークスペースを含め、再起動後も最後にディレクトリを変更した場所を記憶します。 Windows は、ビジーなペインに戻った後も、消えた文字を修正します。
  • 🔍 行を変更した人を確認する: Git の非難ステータス項目には、カーソル行の作成者と日付が表示されます。リポジトリ ワークスペースでは、click してコミットを開きます。コードの横にある注釈の [設定] → [エディター] で Inline gitblame を有効にします。
  • 👤 アカウントの切り替えをより明確にします: 保存された Claude アカウントと Codex アカウントに名前を付け、最後に確認された計画を確認します。 [再起動] を受け入れるか、[常に再起動] を使用すると、ビジー状態のクロード ターミナル セッションは、現在の作業が終了するのを待たずに、選択したアカウントで再開されます。

ハイライト

  • 1 つのカードでエージェントを設定します: エージェント、モデル、サポートされている作業または高速オプションを一緒に選択し、チャットとして開く または ターミナルとして開く を使用します。 デフォルト の作業量が提供されている場合、エージェントは独自のレベルを選択できます。
  • 制御割り込み: ワークスペースを右クリックして、未読ドットを維持したまま通知をミュートします。スリープ状態のワークスペースは再起動後もスリープ状態を維持し、ワークスペース カードのプレビューでさまざまなスタイルを試すことができます。
  • 言語とプラグインを使用します: 設定またはオンボーディングでコミュニティ翻訳を見つけてください。プラグイン更新レビューでは、追加されたアクセスに名前を付け、承認をグループ化できます。対象となるアップデートは通知から承認できます。
  • 後で使用するためにリモート ファイルを保存する: リモート ファイル リンクで ダウンロード… を選択すると、別のアプリを開かずにファイルを保存できます。 Windows は、WSL ディストリビューションにマップされたドライブ文字上のプロジェクト フォルダーも認識します。
  • ブロックされた Codex アクションを解決する: チャットで自動レビューの拒否について説明し、そのアクションに対する 1 回承認を提案します。

互換性とアップグレードに関する注意事項

  • コーデックス履歴の共有: 共有を有効にすると、アカウントは次回起動する前に 1 つの会話ストアに移動します。これにより、最初の起動が遅れ、使用中のアカウントは後で移行される可能性があります。共有をオフにすると、共有履歴が残ります。共有を再開する必要がある間に、長い会話が始まりました。 Windows のダウングレード後、再度更新するまで、追加のアカウントはデフォルトの Codex サインインに戻ります。
  • Windows ターミナル: 既存のターミナルを閉じて再度開き、迷子文字の修正を取得します。
  • リポジトリのセットアップ手順: 以前の orca.yaml 承認は、そのリポジトリのセットアップ コマンドの将来のバージョンでは trust としてカウントされるようになりました。 VM の作成とホスト間で ID を共有するリポジトリは、バージョンごとの承認を維持します。
