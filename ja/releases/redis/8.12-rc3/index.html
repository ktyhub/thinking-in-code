redis 8.12-rc3

マイナー 公開日2026年11月12日 出典redis/redis 英語原文

#redis 8.12-rc3

これは、Redis オープン ソースの Redis 8.12 の 3 番目のリリース候補です。

リリース候補は、機能が完全に揃ったプレリリースです。プレリリースは実稼働環境での使用には適していません。

セキュリティ修正

  • #16127 TLS セッションは、別のリスナー (client ポート対クラスター バス)、または tls-auth-clients または tls-expected-peer-name の変更後、新しい設定のチェックなしで再開できます。

新機能

  • #16135 新しいコマンド: ZMOVE、BZMOVE、ZMOVEMEMBER で、COUNT バッチ処理と NX/XX 宛先条件を使用して、どちらかの端から、スコア範囲別、または名前別に、ソートされたセット間でメンバーをアトミックに移動します。
  • #15907 SLOWLOG GET は、各遅いコマンドの CPU 時間をレポートするようになり (新しい 8 番目のフィールド)、CPU が不足しているコマンドとは別に、ゆっくり実行されたコマンドを示します。新しい構成パラメータ: off-cpu-tracking

モジュール API

  • #16105 RedisModule_GetUsedMemoryRatioEstimate - RedisModule_GetUsedMemoryRatio と似ていますが、GIL を保持せずにモジュール スレッドから呼び出すことができます

バグ修正

  • #16098 出力バッファーのソフトリミットを超えて遅延したレプリカは、repl-backlog-size が大きい場合でも切断されました
  • #16176 宛先がコマンドを拒否した場合、アトミック スロット移行中にキーが失われる可能性がありました (例: min-replicas-to-write による -NOREPLICAS)
  • #16210 アトミック スロット移行中に宛先でセット メンバーが誤って期限切れになる可能性がある
  • #16096 EX または PX オプションが繰り返された MSETEX が無効なコマンドとしてレプリカと AOF に伝播され、キーが失われます
  • #16175 AOF 書き込みエラー (ディスクがいっぱいなど) の後に AOF 再書き込みが開始された場合、AOF ロード時にコマンドが 2 回再実行される可能性がありました。
  • #15955 IDMP を含む XADD エントリが AOF リプレイまたは遅延レプリカで失われる可能性があり、XIDMPRECORD が遅延レプリカをクラッシュさせる可能性があります
  • #15930 エントリがないと主張した XCLAIM または XAUTOCLAIM によって作成されたコンシューマがレプリカまたは AOF に伝播されませんでした
  • #16121 一部のキー更新では、キースペースのサイズ変更中に値または TTL が別のキーに適用される可能性がありました
  • #16042 getkeys-api または getchannels-api を使用するモジュール コマンドを実行すると、Redis が io-threads > 1 でクラッシュする可能性があります
  • #16165 モジュールがキースペース通知から ZPOPMIN/ZPOPMAX によって空にされたソートセットを読み取ると、Redis がクラッシュする可能性がありました
  • #16125 key-memory-histograms または cluster-slot-stats-enabled が有効な場合、同じソース キーと宛先キーを持つ ZRANGESTORE により解放後の使用が発生する可能性がある
  • #16167 ZRANGESTORE ソースが順序付けされていないペイロードからロードされたリストパックである場合、スコア順序が壊れたソート セットを作成できる可能性がありました。
  • #16164 sanitize-dump-payload なしで復元されたソート セットは、B+tree エンコーディングへの変換後に重複メンバーを 2 回保存する可能性がありました。
  • #16146 不正な形式の RESTORE ペイロードまたは RDB ファイルによりメモリが破損する可能性があります (主要なメタデータ クラスを登録するモジュールの場合のみ)
  • #16142 A が設定されている場合、CONFIG GET および CONFIG REWRITE は notify-keyspace-events の n、o、および c フラグをドロップしたため、再起動後にこれらのイベントが停止しました
  • #16120 DELEX は、lazyfree-lazy-user-del の代わりに lazyfree-lazy-server-del を尊重しました
  • #16203 非常に深い文字列パターンを持つ Lua スクリプトはスタックを使い果たす可能性があります。このようなパターンは pattern too complex で失敗するようになりました。
  • #16233 AOF および 1024 バイト以上の作業ディレクトリで preload-file を使用すると、Redis がクラッシュする可能性がある
  • #16062 FreeBSD では、バンドルされた jemalloc が libc の malloc フックを引き継ぎ、マルチスレッド ツール (redis-benchmark --threads など) をクラッシュさせ、fork() 後にデッドロックする可能性がありました。
  • #16117 redis-cli は、極端なアリティ値を含む COMMAND 応答から過剰なヘルプ エントリを生成する可能性がありました
  • #15823 redis-cli --keystats キーが見つからない場合に空の統計を出力しました

パフォーマンスとリソース使用率の改善

  • #15622 SORT および SORT_RO は、リストパックでエンコードされたソート セットを B+tree に変換しなくなり、メモリ使用量が増加しました (読み取り専用レプリカでも)
  • #16163 ソートセットを B+tree に変換する ZADD は、メモリを無駄にし、ZSCAN を遅くする特大メンバーインデックスを残さなくなりました。
  • #16069 Client メモリ (tot-mem、mem_clients_normal、maxmemory-clients) には、監視されているキーの名前と、Pub/Sub チャネルとパターンの名前が含まれるようになりました。
  • #16126 大規模な REV ランク範囲の ZRANGESTORE の高速化
  • #16156 B+ツリーソートセットで大きなプラスカウントを持つ高速なZRANDMEMBER
  • #15420 ハッシュテーブルでエンコードされたセットの正のカウントによる SRANDMEMBER の高速化
  • #15901 リストパックでエンコードされたハッシュのフィールド有効期限の HEXPIRE および HSETEX 更新の高速化
