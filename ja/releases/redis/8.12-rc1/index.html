#redis 8.12-rc1

これは、Redis オープン ソースの Redis 8.12 の最初のリリース候補です。

リリース候補は、機能が完全に揃ったプレリリースです。プレリリースは実稼働環境での使用には適していません。

見出し:

Redis 8.12 には、新機能とパフォーマンスの向上が導入されています。

テスト対象のオペレーティング システム Redis 8.12

  • Ubuntu 22.04 (Jammy Jellyfish)、24.04 (Noble Numbat)、26.04 (Resolute Raccoon)
  • ロッキー リナックス 8.10、9.7、10.1
  • AlmaLinux 8.10、9.7、10.1
  • Debian 12.13 (本の虫)、Debian 13.4 (Trixie)
  • アルパイン 3.23
  • macOS 14.8.4 (Sonoma)、15.7.4 (Sequoia)、26.3 (Tahoe) - Intel と ARM の両方用

セキュリティ修正

  • RediSearch/RediSearch#10073 インデックス付き値のハッシュが衝突耐性を持つようになり、敵対的な入力による HashDoS スタイルのインデックスの劣化を防ぎます。 (MOD-14459)
  • RediSearch/RediSearch#11202 不完全な UTF-8 文字がインデックス付き TEXT フィールドの範囲外に読み取られることがなくなりました。 (MOD-18088)

新機能

  • #15331 圧縮ビットマップ — メモリ使用量を削減し、ビットマップ操作を高速化するために、redis-roaring を Redis コアに統合しました。 この機能に貢献してくれた redis-roaring のオリジナル作成者である Antonio に感謝します。 https://redisroaring.com/redis-merge/#/1;
  • #15986 新しいコマンド: redis-roaring の R.RANGEINTARRAY に相当する BITRANGEINTARRAY、指定された範囲内で設定されたビット オフセットを返す
  • #15938 個々のセットメンバーに有効期限を設定します。新しいコマンド: 有効期限を設定するための SEXPIRE、SPEXPIRE、SEXPIREAT、SPEXPIREAT、および残りの TTL または有効期限のタイムスタンプを取得するための STTL、SPTTL、SEXPIRETIME、SPEXPIRETIME
  • #15649 キーを祝福: 指定されたキーの削除を回避します。新しいコマンド: BLESS
  • #15829 CLUSTER MIGRATION STATUS は、スナップショットと増分移行フェーズの両方の進行状況をレポートするようになりました。
  • #15556 TLS 名前付きグループを tls-groups を使用して構成できるようになりました
  • RedisBloom/RedisBloom#1063 Count-min-sketch 拡張機能: メモリ使用量を削減するためのオプションの CELL_SIZE サポートを CMS.INITBYDIM および CMS.INITBYPROB に追加し、CMS.INCRBY での負の増分によるカウントの減分、および CMS.INFO でのセル サイズレポートを追加しました。
  • RedisJSON/RedisJSON#1640 JSON ディープ パスの自動作成
  • RediSearch/RediSearch#10151 EXPLAINSCORE が FT.HYBRID でサポートされるようになりました。 (MOD-10044)
  • RediSearch/RediSearch#11330 SQ8 の新しい圧縮が HNSW ベクトル フィールドで利用できるようになりました。 (MOD-6132)
  • RediSearch/RediSearch#10247 ローカル FT.HYBRID 実行で RETURN_STRICT タイムアウト処理が有効になりました。 (MOD-16492)
  • RediSearch/RediSearch#11278 FT.ALTER は、スキーマ追加中の不必要なドキュメントの再インデックス作成を回避します。 (MOD-18171)
  • RediSearch/RediSearch#11384 スコア/ペイロードのみのハッシュ更新により、インデックスの再作成が回避されます。 (MOD-18182)
  • RediSearch/RediSearch#11230 ベクトル インデックス付きフィールドがタッチされていない場合、ハッシュ ドキュメントのインデックスが再作成されなくなりました。 (MOD-17688)

  • #15618 共有テンプレートを使用したハッシュのバッチ更新がより効率的に実行されるようになりました。
  • #15018 サポートされる x86 システムは、タイミング オーバーヘッドを削減するためにランタイム キャリブレーションを使用して、デフォルトでプロセッサ ベースの単調クロックを使用するようになりました。
  • #15782 RDB および AOF のロードでは、ロード効率を向上させるためにオペレーティング システムにシーケンシャル読み取りヒントが提供されるようになりました。
  • RediSearch/RediSearch#10169 フィールド レベルの有効期限 (HEXPIRE) を使用したインデックスの検索が高速になります。 (MOD-16350)
  • RediSearch/RediSearch#10981、RediSearch/RediSearch#11065 コーディネーター フィールドの検索と行応答のシリアル化オーバーヘッドが削減されます。 (MOD-17924)
  • RediSearch/RediSearch#11055、RediSearch/RediSearch#11056、RediSearch/RediSearch#11057 クラスター応答の変換、結果の破棄、および GROUPBY クリーンアップのオーバーヘッドが削減されました。 (MOD-17908、MOD-17909、MOD-17910)
  • RediSearch/RediSearch#11507、RediSearch/RediSearch#11506 クエリ応答は、snprintf なしで整数値をフォーマットし、応答コレクションの長さを前もって宣言するようになりました。 (MOD-18800、MOD-18799)
  • RediSearch/RediSearch#11509 RETURN および LOAD のハッシュ フィールドの読み込みでは、フィールドごとの割り当てが必要なくなりました。 (MOD-18811)
  • RediSearch/RediSearch#10246 ベクトル範囲クエリ中に同時書き込みが許可されるようになりました。 (MOD-16437)
  • RediSearch/RediSearch#10515 コーディネーター要求はメインスレッドに割り当てられるようになり、CoordRequestCtx が削除されました。 (MOD-16990)
  • RediSearch/RediSearch#11018 クエリの使用が管理インデックス操作から分離されるようになりました。 (MOD-17536)
  • RediSearch/RediSearch#10066 FT.AGGREGATE WITHCOUNT の非同期反復子枯渇コールバックを優先して、シャード応答バリアが削除されました。 (MOD-16210)
  • RedisJSON/RedisJSON#1645 共有文字列のメモリ使用量レポートがより正確になりました: メモリ使用量は、すべての参照への割り当て全体を請求するのではなく、ヘッダーとパディングを含む共有文字列の割り当ての各参照の比例配分を考慮するようになりました。
  • J1660 オブジェクト メモリ消費量の削減: JSON 解析では、コンパクト オブジェクト割り当てを使用して、JSON オブジェクトの保存に必要な実際のメモリを削減するようになりました。
  • RedisJSON/RedisJSON#1661 パーサーのバックトラッキング、一時的な割り当て、および反復的な走査を削減することにより、JSONPath の解析と評価が改善されました。最適化には、フィルター候補全体でのルートパス オペランドのキャッシュ、最初の一致での存在チェックの停止、正規表現一致と文字列比較のオーバーヘッドの削減が含まれます。

設定パラメータ

  • Redis-roaring:bitmap-default-roaring - 新しい轟音ビットマップ タイプを有効にします。デフォルトでは無効になっています。
  • RedisJSON/RedisJSON#1657 構成可能な RDB の深さの検証: RDB からまたは RESTORE を通じて JSON をロードするときに最大ネストの深さ 128 を強制するために、デフォルトで無効になっている json-legacy-rdb-depth-limit を追加しました。
  • RedisJSON/RedisJSON#1640 json-auto-create-deep-paths が追加されました。デフォルトでは無効になっており、ロード時にのみ構成できます。値が異なるとデータの相違が生じる可能性があるため、シャードのすべてのノードと AOF ファイルを再生するときに同じ値を使用します。

  • #15682 ストリームの可観測性 – ストリームごとのコンシューマ グループ、グループごとの保留中のエントリ、およびグループごとのコンシューマのデータベースごとのヒストグラムを含む INFO STREAMS を追加しました。 stream-stats で有効にする Yes (デフォルトでは無効)
  • RediSearch/RediSearch#10097 FT.INFO はデフォルトの EF_RUNTIME を公開するようになりました。 (MOD-16147)
  • RediSearch/RediSearch#10107 ディスク GC bytes_collected およびサイクル統計が FT.INFO でレポートされるようになりました。 (MOD-14621)
  • RediSearch/RediSearch#10464 コーディネーターの FT.INFO は、リデューサーを介してフィールドごとのディスク メトリックを集計するようになりました。 (MOD-14859)
  • RediSearch/RediSearch#10204 Redis INFO は、クエリ タイムアウト メトリックをパイプライン ステージごとに分類するようになりました。 (MOD-13192)
  • RediSearch/RediSearch#11521 無関係な INFO セクションのインデックス メトリックが収集されなくなりました。 (MOD-18033)
  • RediSearch/RediSearch#10536 FT.PROFILE ローダー フィールドのタイミング分解能が向上しました。 (MOD-17132)

行動の変化

  • RediSearch/RediSearch#10109 FT.CREATE は、RAM モードの HNSW ベクトル フィールドで RERANK を拒否します。 (MOD-16015)
  • RediSearch/RediSearch#10200 ディスク インデックスは DIALECT 4 および WITHOUTCOUNT を拒否します。 (MOD-15997)
  • RediSearch/RediSearch#10082 COLLECT には、フィールド名に @ 接頭辞が必要です。 (MOD-16233)
  • RediSearch/RediSearch#11106 JSON HIGHLIGHT/SUMMARIZE 複数値 JSONPath フィールドは拒否されるようになりました。 (MOD-16530)
  • RediSearch/RediSearch#10208 キャッシュ不可能なコマンドが dont_cache でマークされるようになりました。 (MOD-16175)
  • RediSearch/RediSearch#10699 数値コマンド引数が厳密に解析されるようになりました。 (MOD-17409)
  • RediSearch/RediSearch#11335 検索モジュールをロードするには、Redis 8.9.241 以降が必要になりました。 (MOD-15868)
  • RedisBloom/RedisBloom#1063 拒否された CMS.INCRBY アイテムの更新により、オーバーフロー時にカウンターが飽和するのではなく、カウンターと合計数が変更されないままになります。複数項目のコマンドは部分的には成功する可能性があります。
  • RedisBloom/RedisBloom#1063 CMS.MERGE では、宛先とすべてのソースにわたってセル サイズを一致させる必要があります。

モジュール API

  • #15517 モジュールは、RM_GetClusterNodeInfo() の新しい REDISMODULE_NODE_PORT_TLS フラグを使用してクラスター ノードの TLS ポートを取得できるようになりました。
  • RedisJSON/RedisJSON#1623 プリコンパイルされた JSONPath を評価するための getWithPath が共有 API V9 に追加され、呼び出し元がパスを一度コンパイルしてドキュメント間で再利用できるようになりました。
  • RedisJSON/RedisJSON#1666 Redis コンテキストまたは割り当てられたエラー メッセージなしで JSONPath をコンパイルするために、共有 API V10 に pathParseNoErrorMsg を追加しました。成功した場合はコンパイルされたハンドルを返し、失敗した場合は NULL を返します。
  • RedisJSON/RedisJSON#1653 プリコマンドフックをオプションにし、実行前に JSON コマンドを中止するフックエラーを許可しました。フックは RedisResult<()> を返すようになりました。共有 C API 呼び出しは引き続きフック エラーを無視します。
  • RedisJSON/RedisJSON#1640 欠落しているパスの構築をサポートするために、clone_value および create_object を使用して Rust Manager インターフェイスを拡張しました。カスタム実装では、これらのメソッドを実装し、所有値に関する新しい Borrow<Self::V> 要件を満たす必要があります。
