dubbo-go v3.1.0

マイナー 公開日2023年7月27日 出典apache/dubbo-go 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ダボ号v3.1.0

重大な変更

3.0.x 以前からアップグレードするユーザーの場合、3.1.0 のデフォルトのサービス検出モデルが、Dubbo3 のアプリケーション レベルの検出モデルを表す registry-type: instance に変更されていることに注意してください。

下位バージョンのインスタンスを検出できるようにするには、dubbogo.yml または API を使用して、3.1.0 インスタンスの registry-type を interface に設定してください。

dubbo:
  registries:
     zk: 
       protocol: zookeeper
       address: 127.0.0.1:2181
       registry-type: interface

機能

  • nacos および zookeeper 用の RemoveConfig API の実装
  • 構成 api の TLSConfig を公開
  • 任意の値を購読する
  • 条件ルーティングの基本機能を実装し、関連するテストを完了する
  • 動的ルーティングの実装
  • タグルート静的設定
  • nacos 2.x のアップグレード
  • 登録されたプロバイダーとコンシューマーのログを印刷
  • リクエスト処理の合計メトリクスとリクエスト成功の合計メトリクスを追加
  • RTに関する指標を追加
  • メトリクスベース api インターフェイスの追加
  • スライディング ウィンドウと rt 分位数メトリクス

バグ修正

  • 修正: Java プロバイダーの呼び出しで、トリプル プロトコルでグループ + バージョンを使用するエラーが発生する
  • 修正: Tripe 使用時にインスタンス プロトコル情報を Polaris に登録する
  • 修正: カスタム トリプル サーバー メッセージ サイズ
  • 修正: サブスクライブ時に新しいルーチンを開始する
  • 修正: hessian2 をアップグレードして Java ラッパー オブジェクトのデコードのバグを修正
  • 修正: Polaris サービス検出による nil パニック
  • 修正: メタデータ呼び出し側の破棄が早すぎます
  • 修正: メトリクス モジュールのインポートの形式
  • 修正: ポインタを使用して構成ブール フィールドのゼロ値のバグを解決
  • 修正: 代わりにデフォルトでメトリック フィルターを無効にする

機能強化

  • アプリケーションサービス検出のためのserviceMappingListenerの追加
  • config.WithPathメソッドのioutil.ReadFileの引数をconf.pathに変更
  • java ラッパー型をサポートするために hessian2 をアップグレード
  • テーブルライト cli ショー
  • リファクタリング: Polaris 使用時にプロバイダーを削除し、プレフィックスを追加
  • ログ設定は他のフレームワークをサポートし、ログ ファイルの生成ディレクトリとファイル サイズを設定できます
  • ノードが存在しないエラー メッセージを無視して再試行を続行
  • リファクタリング: メトリクス モジュールを複数のファイルに分割
  • プロバイダー/コンシューマーのメタデータを保存するときに、すでに存在する zk ノードを無視する
  • ノードが既に存在する場合は値の更新を試行
  • リファクタリング: promauto と promhttp を使用する
  • 雑務: fmt.Sprintf の不要な使用
  • 雑務: パッケージを複数回インポートしました
