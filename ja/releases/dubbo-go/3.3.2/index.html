dubbo-go v3.3.2

#ダボ号v3.3.2

3.3.2

概要

Apache Dubbo-go 3.3.2 は、API の統合、トリプル プロトコル機能、アプリケーション レベルのメタデータ、サービス ガバナンス、同時実行の安全性、およびリリース ツールに重点を置いた実稼働対応リリースです。従来の config パッケージの削除が完了し、プロジェクトのベースラインが Go 1.25 に移動され、汎用呼び出しと HTTP 対応のトリプル機能が拡張され、生成されたプロジェクトのワークフローが更新され、複数の競合、古いスナップショットの問題、およびリソース リークが修正されます。

重大な変更とアップグレードに関する注意事項

  • Go 1.25 が必要になりました。 モジュールとプロジェクト ツールチェーンは Go 1.24 から Go 1.25 に移動しました。 #3469
  • レガシー dubbo.apache.org/dubbo-go/v3/config パッケージは削除されました。 これを直接インポートしたアプリケーションは、global の下のインスタンス/オプション API および構成タイプに移行する必要があります。ルート互換性ブリッジも削除されました。 #3372 #3448 #3449
  • 低レベル triple_protocol.Client API の直接ユーザーは、RPC メソッドを明示的に渡す必要があります。 より高レベルの client.Client および生成された client API は変更されません。 #3086
  • Hystrix フィルターは apache/dubbo-go-extensions に移動しました。 既存のユーザーは拡張機能の実装をインポートし、登録されたフィルター名を使用し続ける必要があります。 #3253
  • 従来の gRPC および Dubbo3 プロトコル実装と IDL モード スイッチは、将来の削除に備えて非推奨になりました。 #3469

新機能

  • ジェネリック呼び出しのサポートを拡張します。 トリプル ジェネリック呼び出しは、新しい protobuf-json および bean ジェネラライザー、型付き呼び出し、クラス メタデータ、および例外クラス処理を使用して、生成されたスタブなしで相互運用できるようになりました。 #3154 #3170 #3171 #3174 #3175 #3183
  • HTTP およびクラウド ネイティブ ワークロード向けに Triple を強化します。 このリリースでは、CORS、REST OpenAPI サポート、プローブとクールダウンによるステートフル HTTP/3 ネゴシエーション、トリプル リスナーへの既存の HTTP ハンドラーのマウント、および呼び出しオプションによる単項応答ヘッダー/トレーラー キャプチャが追加されています。 #3090 #3280 #3281 #3301 #3443 #3446
  • Kubernetes ヘルス プローブを追加します。 アプリケーションは、稼働状況、準備状況、および起動チェックを公開できます。 #3213
  • 正常なシャットダウンを再構築します。 シャットダウン ライフサイクルは、統合された実装と構成可能なシャットダウン状態を通じて、コンシューマー、プロバイダー、レジストリ、確認応答を調整するようになりました。 #3235 #3293 #3386 #3388
  • アプリケーション レベルのメタデータを強化します。 このリリースでは、ローカル メタデータ ライフサイクルが完了し、メタデータ状態の同時実行安全性が向上し、メタデータ レポートの選択が明確になり、リビジョンが正規化され、更新とガベージ コレクションが追加され、レポートから RPC へのフォールバックと競合を意識したサービスからアプリケーションへのマッピング更新によりリモート読み込みが強化されます。 #3357 #3362 #3367 #3369 #3370 #3371 #3373 #3395
  • ルーティングとガバナンスを改善します。 静的ルーター構成の挿入、スクリプトルーター登録、ルーターチェーンスナップショットキャッシュ、および追加のルーティングコンテキストがサポートされるようになりました。 #3215 #3224 #3252 #3305
  • 可観測性の向上。 コンテキスト認識型ロガー インターフェイスにより、トレース フィールドが Logrus および Zap と統合され、ロガーの初期化によりパブリック Dubbo-go ファサードが同期され、トリプル メトリクスにより追加の RPC 障害状態が識別されます。 #3189 #3195 #3345
  • 解決されたインスタンス構成を検査する必要があるアプリケーションのために、CustomConfig および InstanceOptions のスナップショットを公開します。 #3481

バグ修正と信頼性

  • URL クローン作成、共有拡張機能レジストリ、メタデータ状態、プロトコル ライフサイクル、Nacos とディレクトリ状態、コンシステント ハッシュ、ラウンドロビン ロード バランシング、スティッキー インボーカー、およびサービス検出リスナー間の競合を修正します。 #3160 #3264 #3265 #3269 #3270 #3271 #3307 #3317 #3367 #3435 #3439 #3442
  • トリプル HTTP/2 接続をダイヤルする際のキャンセルとタイムアウトを尊重し、SSL を有効にする前に Getty サーバーの TLS 構成を検証します。 #3156 #3165
  • サービス メタデータを複製したり汚染したりしない、大文字と小文字を区別しないメソッド ルーティングにより、Go/Java Triple の相互運用性を維持します。 #3277
  • コンテキストの添付ファイル、プロバイダー タグ、アプリケーション名と URL 属性、アフィニティ ルーターの初期化、および無効なスクリプト ルーター構成の更新のルーティングの正確さを修正します。 #3164 #3185 #3208 #3216 #3256 #3417
  • 呼び出し側の同時破棄中のパニックを防止し、Serve でのブロック中にサーバー ロックを保持することによって引き起こされるサーバー起動のデッドロックを回避します。 #3184 #3238
  • 現在のレジストリ スナップショットが到着したときに古いプロバイダーが削除されるように、Nacos と Polaris の初期サブスクリプション状態を調整します。 #3479 #3482
  • 保持された URL 状態を修正し、リクエスト エラーやハートビート タイムアウト時の保留中のリモート応答をクリーンアップして、メモリの増加を防ぎます。 #3282 #3440
  • 複数の Nacos プロバイダーとルーティング可能な環境メタデータを保持し、アプリケーション タグを MetadataInfo に保持し、構成センター アドレスを構築するときに Apollo コンテキスト パスを保持します。 #3309 #3331 #3400
  • OpenTelemetry traceparent 値を保持し、トレースの伝播を妨げたメタデータ サプライヤーのタイプの不一致を修正します。 #3285 #3433
  • トリプル ストリーム レスポンス クロージャを非ブロッキングにし、プロトコルの初期化、メタデータ ヘッダー、トレーラーの添付ファイル、Getty 書き込みエラーの処理を強化します。 #3307 #3418 #3428 #3434 #3466
  • 可変個引数メソッドの汎用呼び出しを修正し、サポートされていない、またはあいまいな可変個引数 RPC 定義に対する警告を追加します。 #3284 #3294
  • サポートされていないコンテンツ タイプおよび欠落しているエクスポーターに対する JSON-RPC nil-pointer パニックを防止します。 #3298 #3312
  • 構成された hash.arguments インデックスを使用して一貫性のあるハッシュを作成し、パニックにならずに文字列以外のリクエスト引数を受け入れます。 #3430 #3432
  • Nacos サブスクリプションおよびフェールバック クラスターの再試行に制限付きの指数バックオフ再試行を追加します。 #3178 #3180

パフォーマンスとエンジニアリング

  • 低レベル トリプル client をメソッドごとに 1 つの client からサービスごとに 1 つの client にリファクタリングし、マネージド client インスタンスをサービスごとに O(メソッド) から O(1) に削減します。 #3086
  • common.URL クローン作成、文字列レンダリング、等価性チェック、マップ変換、およびキー構築における割り当てを削減します。 #3399 #3403 #3404 #3412 #3488
  • 負荷分散およびサービス検出ホット パスでの一時的な割り当てを削減し、トリプル コンテンツ タイプの正規化のための高速パスを追加します。 #3410 #3414 #3415 #3416
  • Viper の依存関係を削除し、ランタイム コンポーネントを従来の構成内部から切り離し続けます。 #3323 #3449
  • Linux/RISC-V ビルド チェックを追加し、セキュリティに敏感なネットワーク依存関係を更新します。 #3244 #3368 #3467 #3470

ツーリング

  • リリース用にコンパニオン ツールのバージョンを更新します: protoc-gen-go-triple および protoc-gen-triple-openapi 3.3.2、dubbogo-cli 1.0.1、および imports-formatter 1.0.11。トリプル ジェネレーターは、デフォルトで最新の NewXxx および RegisterXxxHandler API スタイルを出力し、生成されたファイルにジェネレーターと protoc のバージョンを記録し、useOldVersion=true の背後にレガシー出力を保持するようになりました。 #3585
  • CLI スキャフォールドを再加工して、生成されたファイルを埋め込む代わりに、make proto-gen を通じて protobuf および Triple ソースを生成します。新しいプロジェクトは、安定した Dubbo-go v3.3.1 依存関係を持つ Go 1.25 を使用し、ラップされた EOF を通常のストリーム完了として扱い、Linux CI でエンドツーエンドでコンパイルされます。 #3585 #3587

ドキュメントと CI

  • トリプル ヘッダーとトレーラー API、およびジェネリック コール応答添付ファイルを読み取るための移行パスを文書化します。フィルタのドキュメントを更新し、古い README リンクを修復します。 #3158 #3365 #3380 #3381 #3447
  • 維持されているツールの英語と中国語のドキュメントを更新し、現在の構成スキーマと例を更新し、廃止された variadic-RPC コントラクト チェッカーを削除します。 #3585
  • デフォルトおよびリリース ブランチにデフォルトの保護ルールを追加し、Codecov アクションをアップグレードし、Linux/RISC-V ビルド ワークフローを追加します。 #3325 #3375 #3470
