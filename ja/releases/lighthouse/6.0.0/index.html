lighthouse v6.0.0

メジャー 公開日2020年5月19日 出典GoogleChrome/lighthouse 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#灯台v6.0.0 生のコミット changelog このリリースは Chrome 84 の DevTools に同梱される予定です。

注目すべき変更点

とてもたくさん！詳細については、Lighthouse 6.0: What's New ブログ投稿 を参照してください。

🆕 新しい監査

  • 最大コンテンツフル ペイント (LCP) は、ナビゲーションからビューポート内の最大のコンテンツ要素がレンダリングされるまでの時間を測定する新しいメトリックです (#9905、#10213、#10452、#10529)。
    • largest-contentful-paint-element は、LCP をトリガーした要素に関する情報を提供するコンパニオン監査です (#10517、#10713)。
  • 累積レイアウト シフト (CLS) は、ページの読み込み時のコンテンツの予期しない移動の量を測定する新しい指標です (#9037、#10427、#10495、#10570、 #10728)。
    • layout-shift-elements は、ページのロード時にシフトされた要素に関する情報を提供する別のコンパニオン診断です (#10702)。
  • unused-javascript はしばらくの間使用されてきた監査ですが、現在はデフォルトで有効になっています。これは、ロードされたもののページのロード中に実行されなかった JavaScript を考慮し、コード分割、デッド コードの削除、または削除キー (#9854) の賢明な使用によって節約できるロード時間を推定します。
  • PWA maskable-icon はホーム画面上で見栄えが良くなるだけなので、この新しい監査ではマニフェストで少なくとも 1 つを使用できるようにすることが推奨されます (#10370)。
  • timing-budget は、予算アサーション を拡張して、すべてのパフォーマンス メトリック (#9901、#9925) に設定できるようにしました。
  • 新しい charset 監査は、ページ コンテンツ (#10284、#10389、#10689) の適切な文字エンコーディングを保証します。
  • image-size-responsive は、画像のアスペクト比と解像度がページ上での表示方法とよく一致しているかどうかをチェックします (#10460)。
  • axe-core の最新バージョンに更新すると、多数の新しいアクセシビリティ監査のロックが解除されます: aria-hidden-body、aria-hidden-focus、aria-input-field-name、aria-toggle-field-name、duplicate-id-active、 duplicate-id-aria、form-field-multiple-labels、heading-order (#9798)。

⚗️ 実験的監査

これらの監査はまだデフォルトの Lighthouse エクスペリエンスの一部ではありませんが、ページの JavaScript バンドルの分析に基づいてパフォーマンスに関するアドバイスを提供します。これらは、--preset=experimental フラグを使用してコマンド ラインで今すぐテストできます。

  • legacy-javascript はバンドルを調べて、不要なポリフィルとバンドラー変換 (#10303、#10568、#10564) を探します。
  • duplicated-javascript は、ページの JavaScript を調べて、バンドル内または複数のバンドル間で重複したコードを探します (#10314)。
  • unused-javascript は (前述したように) デフォルトで実行されるようになりましたが、experimental で実行すると、監査ではソース マップを使用して、実行されず、延期または削除される可能性のある_オリジナル_ ソース コードを示すことができます (#10090)。

💥 重大な変更

  • ユーザーの読み込みエクスペリエンスをより適切に反映するために、パフォーマンス メトリック スコアが 再加重されました (#9949)。
  • デスクトップ Lighthouse テストの実行時に、より高速な接続と CPU を考慮してメトリクス スコア曲線が更新されました (#9911、#10756)。
  • frameNavigated イベントはリダイレクトの追跡に使用されるようになりました。つまり、実行の finalUrl (#10339) を決定するときに JS リダイレクトが考慮されるようになりました。
  • エミュレートされたモバイル デバイスは Nexus 5x から Moto G4 に移行されました (ただし、既存の DPR は変更されません) (#10191、#10749)。
  • mixed-content プリセットは、広く使用されておらず、デフォルトの Lighthouse エクスペリエンス (#10159、#10750) に追加するには時間がかかりすぎるため、削除されました。
  • full プリセットは、そこにあるコードがデフォルトでは実行できる状態になっていない可能性があることを示すために、experimental という名前に変更されました (#9930、#10311、#10333、#10585)。
  • エミュレートされた Chrome UA 文字列が Chrome 80 (#9967) に更新されました。
  • installable-manifest: インストール可能とみなされるには、Web アプリ マニフェスト内のアイコンがフェッチ可能である必要があります (#10168、#10320)

🤖💥 プログラマティック ユーザー向けの重大な変更

これらの変更がエンド ユーザーに影響を与える可能性はほとんどありませんが、カスタム構成、プラグインを作成する場合、または Lighthouse JSON 出力を処理する場合には重要になる可能性があります。

  • 監査に渡された LH.Audit.Context は不変として扱われるようになりました。以前にコードがトップレベルの警告を取得するために context.LighthouseRunWarnings にプッシュされていた場合、今後はそれを監査の製品の runWarnings に戻す必要があります (#10555)。
  • Audit.computeLogNormalScore は、中央値と p10 点を持つ対数正規曲線を指定するように再定義されました (「収穫逓減点」を削除)。既存の監査はこの新しい定義に移動され、スコアの変更は発生しません (#10715)。
  • ページの読み込みが失敗した場合の動作を制御するために、loadFailureMode 設定が Config パスに追加されました。以前は、これは暗黙的に制御されていました (例: 利用可能なオフライン ページがなくてもエラーは発生しませんでした) (#9987)
  • 監査による測定内容をより適切に反映するために、time-to-first-byte は server-response-time に名前変更されました (#10735)。
  • resource-summary: わかりやすくするために、details.items.size は transferSize に名前変更されました (#10700、#10743)。

改善、バグ修正、説明

次の変更は、監査対象の内容により適合するためのバグ修正または更新であると考えられますが、変更により監査スコアや動作が調整される可能性があります。
