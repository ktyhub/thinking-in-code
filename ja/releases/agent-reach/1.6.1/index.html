Agent-Reach v1.6.1

パッチ 公開日2026年11月1日 出典Panniantong/Agent-Reach 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#エージェントリーチ v1.6.1

中国語:

  • ネットワーク検索全体、Reddit、Xiaohongshu、B サイト 1.6.0 で「確認できるのにエラーが報告される」または「表示は成功するが中身が空である」という現象が複数発生します。このバージョンではすべて修正されています。
  • コンピュータ上の他のソフトウェアがブラウザのポートを占有している場合、そのソフトウェアを終了せずにポートを変更できます。
  • コピーログインが失敗した場合、真実が告げられ、成功したふりをすることはなくなります。
  • Windows 上の小紅書で特殊な記号が含まれるリンクは正常に開くことができます。

英語:

  • コンテンツにアクセスできるにもかかわらず、Web 検索、Reddit、Xiaohongshu、または Bilibili が失敗する、または空のコンテンツで成功が報告されるいくつかの 1.6.0 ケースが修正されました。
  • コンピュータ上の別のプログラムがブラウザ ポートを使用している場合、Agent Reach は別のポートを使用できます。そのプログラムを閉じる必要はありません。
  • 失敗したログイン コピーでは、成功を報告するのではなく、その旨が表示されるようになりました。
  • Windows では、特殊文字を含む小紅書リンクが正しく開きます。

中国語 (技術的な詳細):

  • ネットワーク全体を検索: Exa 保護 (#877) によって傍受されるのを避けるために、リクエストはすべて agent-reach/<版本号> ロゴでマークされる必要があります。
  • Reddit: オンサイト ツールが一時的に失敗した場合 (データの代わりに Web ページが返されるなど)、自動的に公開 Web ページの検索と読み取りに切り替わります (#880)。
  • Xiaohongshu: OpenCLI 2.0 の戻り形式に適応され、読み取りは「成功したが内容は空」ではなくなりました。検索とコメントは、結果がない場合に空のデータを返さなくなりました (#861、#895)。
  • ステーション B: QR コードをスキャンした後に有効なログインが保存されていない場合、ログイン成功は表示されなくなります。プロンプトは agent-reach login bilibili (#866、#883) を実行するように変更されます。
  • 専用ブラウザ ポートを agent-reach configure browser-port <端口> に変更できます。9222 が他のソフトウェアによって占有されている場合に使用されます (#848)。
  • ログインのコピー: ブラウザのバックグラウンド プログラムが開いていない場合、「0 個のアイテムがコピーされました」は記録されなくなりました。 login <渠道> --import-existing 項目が手動でコピーされない場合、エラーが明確に報告されます (#879)。
  • Windows: リンク内に & が含まれる小紅書ノートは通常どおり読み、表示できます (#860)。

英語 (技術):

  • Web 検索: すべてのリクエストは自身を agent-reach/<version> として識別するため、Exa の Cloudflare フロントはリクエストをブロックしなくなりました (#877)。
  • Reddit: サイト ツールが一時的に失敗した場合 (たとえば、データの代わりに HTML を返す場合)、検索と読み取りはパブリック Web にフォールバックします (#880)。
  • Xiaohonshu: OpenCLI 2.0 の結果がマップされるため、空のフィールドでは読み取りが成功しなくなりました。検索とコメントは、結果がない場合に 1 つの空の行を返さなくなりました (#861、#895)。
  • Bilibili: 使用可能な認証情報を保存していない QR ログインは成功として報告されなくなり、ヒントには agent-reach login bilibili (#866、#883) と表示されるようになりました。
  • 専用ブラウザのポートは、別のツールが 9222 (#848) を保持している場合に備えて、agent-reach configure browser-port <port> で構成できます。
  • ログインの再利用: ブラウザのブリッジがダウンしている場合、「コピーされた 0 Cookie」の記録はありません。何もコピーしない明示的な login <channel> --import-existing は明らかに失敗するようになりました (#879)。
  • Windows: & を含む小紅書ノートのリンクを読み取り、そのコメントを読み込むことができます (#860)。
