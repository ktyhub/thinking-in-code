#DeepTutor v1.5.8

DeepTutor v1.5.8 Release Note

Fecha de lanzamiento: 2026.08.02 Una versión de mantenimiento con un objetivo: memoria que permanece en lugar de climbing. Una implementación de fuente v1.5.7 superó los 14 GB antes de que V8 se abandonara a mitad de sesión, y las causas resultaron ser independientes: un servidor de desarrollo frontend cuyo límite de almacenamiento dinámico nunca alcanzó el proceso que contiene la memoria, cachés en proceso ilimitados y un HTTP client nuevo creado para cada turno. Acceso directo: no hay migraciones, pero el pago de origen ahora comienza de manera diferente.

¿Qué hay de nuevo?

El servidor de desarrollo nunca estuvo limitado

next dev se procesa en un trabajador que él mismo genera, y los indicadores V8 en argv no son heredados por los procesos secundarios, por lo que el antiguo node --max-old-space-size=4096 …/next dev nunca llegó al proceso que contiene la memoria. Al no encontrar límite en NODE_OPTIONS, Next sustituyó el 50% de la RAM total: un montón de 12 GB en una máquina de 24 GB, que V8 realmente intentó llenar antes de morir en Ineffective mark-compacts near heap limit después de 63 segundos dentro de un compacto de una sola marca. web/scripts/dev.mjs ahora pasa el techo a través de NODE_OPTIONS, que el trabajador hereda y Next honra: fijado a 4 GB y dimensionado según el límite de cgroup dentro de un contenedor en lugar de la RAM del host.

Las instalaciones de origen sirven para una compilación de producción

deeptutor start desde una compra ahora construye la interfaz una vez en .next-deeptutor y ofrece la salida independiente, reutilizando esa compilación hasta que una entrada realmente cambia (una huella digital sobre el árbol web/, el archivo de versión y la configuración pública del tiempo de compilación). La recarga en caliente pasa a deeptutor start --dev, que sigue usando .next: directorios separados, por lo que ningún modo invalida la salida del otro mientras se está ejecutando. Una implementación de larga duración ya no paga por las cachés de un compilador de desarrollo.

LLM clients limitados en lugar de uno por turno

Cada uno de los canales de chat, investigación y preguntas creó un nuevo client compatible con OpenAI, y con él un nuevo grupo de conexiones HTTP, en cada paso. Tanto el agente client como el proveedor de capa de servicios ahora provienen de un pequeño grupo de 2 LRU locales de bucle de eventos, codificados en enlace, modelo, credenciales y URL base, cerrados al apagar y retirados cuando cambian las configuraciones. Solo se importa el SDK del backend seleccionado.

Cachés con techo

Los flujos de registro de tareas de conocimiento ahora limitan los eventos y los bytes por tarea, caducan una hora después de que finaliza una tarea y dejan una pequeña lápida de finalización para que un suscriptor tardío aún sepa que la tarea ha finalizado. La tabla de tareas completadas contiene 256 entradas. La caché del índice LlamaIndex cae de 8 entradas a 2 y expulsa todo lo que esté inactivo durante 10 minutos. El tiempo de ejecución de un libro se libera una vez que su cola se agota en lugar de vivir durante el proceso.

Reclamando lo que ya fue liberado

Después de un turno, un trabajo de libro terminado o una tarea de base de conocimientos completada, DeepTutor recopila ciclos y, en Linux, llama a malloc_trim para que las páginas del montón de manos libres se recuperen en lugar de retener arenas que hacen que RSS parezca permanentemente anclado. Los contenedores y deeptutor start también establecen MALLOC_ARENA_MAX=2 y un umbral de ajuste inferior, ambos anulables por un operador que haya sintonizado el suyo propio.

Una carrera para mantener la vida que surgió como 500

web/proxy.ts avanza al backend a través del http.globalAgent de Node, que cosecha sockets inactivos en un temporizador de 5 segundos, idéntico al valor predeterminado de uvicorn. Ambos extremos armaron el mismo temporizador en el mismo enchufe y corrieron para cerrarlo; cuando el FIN del servidor aterrizó en un socket que el grupo estaba entregando simultáneamente a una nueva solicitud, esa solicitud murió con ECONNRESET y llegó a la interfaz de usuario como "Error al cargar las sesiones". Cada lanzamiento de uvicorn ahora configura --timeout-keep-alive 300, dejando a client como el único lado que retira una conexión inactiva.

Surtido

  • deeptutor.agents, deeptutor.core.agentic, el paquete principal del proveedor, las bibliotecas del analizador del extractor de documentos (PyMuPDF, pypdf, python-docx, openpyxl, python-pptx) y las reglas de mapeo de errores de LLM se resuelven en el primer uso en lugar de en el momento de la importación.
  • python -m deeptutor.api.run_server ya no comienza con --reload; exporte DEEPTUTOR_DEV_RELOAD=1 para ello. Reload ejecuta un supervisor más un trabajador y retiene el estado de vigilancia de archivos, que es una maquinaria de desarrollo. deeptutor serve --reload no ha cambiado.

Notas de actualización

Acceso directo desde v1.5.7: pip install -U deeptutor; Los usuarios de Docker extraen ghcr.io/hkuds/deeptutor:latest. Sin cambios de esquema o configuración.

  • Los pagos de origen se crean antes de publicarse. El primer deeptutor start después de la actualización ejecuta npm run build y tarda más tiempo; Luego se inicia y lo reutiliza hasta que cambie la fuente. Utilice deeptutor start --dev para el bucle de recarga en caliente anterior. El nuevo directorio de compilación web/.next-deeptutor/ se ignora por git.
  • python -m deeptutor.api.run_server ya no se recarga de forma predeterminada. Exporta DEEPTUTOR_DEV_RELOAD=1 para restaurarlo. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.5.7...v1.5.8
