#DeepTutor v1.2.1

DeepTutor v1.2.1 Release Note

Fecha de lanzamiento: 2026.04.21

Destacados

Límites de tokens por etapa y temperatura para el chat (n.º 348)

Promovió el canal de chat agente a un ciudadano de configuración de primera clase en agents.yaml. Un nuevo bloque capabilities.chat expone max_tokens por etapa (responding, answer_now, thinking, observing, acting, react_fallback) y un temperature compartido, profundamente fusionado sobre los valores predeterminados integrados a través de services/config/loader.py::get_chat_params(). Los presupuestos responding y answer_now saltan del anterior 1800 codificado a 8000, eliminando el truncamiento a mitad de frase que cli contenía respuestas largas. Internamente, _ChatLimits.from_config convierte cada forma heredada (claves faltantes, escalar en lugar de dict, anulaciones parciales) en una clase de datos estable para que las instalaciones existentes sigan funcionando sin tocar su YAML. Diez nuevas pruebas unitarias cubren la resolución del cargador, la precedencia de fusión profunda y la coerción de clases de datos.

Regenerar la última respuesta: CLI, WebSocket, interfaz de usuario web (n.º 349)

Se agregó un flujo regenerate real que vuelve a ejecutar el mensaje de usuario anterior en el lugar, funcionando de manera uniforme en todos los puntos de entrada:

  • CLI — /regenerate (alias /retry) dentro del deeptutor chat REPL.
  • WebSocket — Mensaje type: "regenerate" en /api/v1/ws, con overrides opcional para capability, tools, knowledge_bases, language, config.
  • UI web: un botón Regenerar por mensaje (ícono RefreshCcw) en el último turno del asistente para respuestas con capacidad de chat. En el backend, TurnRuntimeManager.regenerate_last_turn revierte el asistente de seguimiento a través de los nuevos ayudantes SQLiteSessionStore.delete_message/get_last_message, luego reutiliza start_turn con _persist_user_message=False y _regenerate=True para que la fila de usuario no se duplique y memory_service.refresh_from_turn no se ejecute por segunda vez. Las comprobaciones previas al vuelo generan errores no fatales regenerate_busy (se está ejecutando otro turno) o nothing_to_regenerate (sin mensaje de usuario previo) en lugar de fallar silenciosamente. La llamada _stage_responding LLM también obtuvo diagnósticos de respuesta vacía que muestran una advertencia estructurada cuando el modelo no devuelve contenido. 18 nuevas pruebas cubren las tres rutas de rechazo, el flujo de eliminación y reinicio, el contrato de omisión de actualización de memoria y el viaje de ida y vuelta de WebSocket.

UI Harmony Polish para regenerar

Dos ajustes de seguimiento para que el nuevo botón coincida con el resto de la interfaz de usuario del chat y se comporte de manera predecible ante el rechazo del servidor:

  • i18n: se agregaron claves Regenerate a web/locales/{en,zh}/app.json (Regenerate / 重新生成) y se cambió ChatMessages.tsx de una cadena "Regenerate" codificada a t("Regenerate"), coincidiendo con el patrón t("Copy") existente en la misma fila.
  • Reversión de pop optimista: cuando el servidor rechaza una solicitud de regeneración previa al vuelo (regenerate_busy / nothing_to_regenerate), el marcador de posición optimista POP_LAST_ASSISTANT + STREAM_START ahora se restaura mediante una nueva acción reductora RESTORE_ASSISTANT. El mensaje emergente se guarda en un pendingRegenerateRef por clave y se borra en done o en cualquier resultado de terminal, por lo que la transcripción nunca pierde silenciosamente la última respuesta del usuario.

Corrección de errores

  • Bloques de código oscuro ilegibles en tema claro (#352): el fondo de bloque de código codificado #1f2937 / #292524 combinado con .prose pre (forzando #D6D3D1) y .prose code:not(.md-code-block__code):not(.md-inline-code) (anulando a var(--foreground)) estaba produciendo texto casi negro sobre fondos casi negros en modo claro. Se agregó una regla .md-renderer .md-code-block { ,pre,code } de mayor especificidad que fija #e5e7eb independientemente del tema y etiquetó los elementos <code> en los respaldos RichMarkdownRenderer y SimpleMarkdownRenderer con la clase md-code-block__code existente para que la protección :not() entre en acción. Gracias @DarkGenius.
  • Ninguna incrustación bloqueó la canalización LlamaIndex (#347, correcciones #346): cuando un proveedor de incrustación devuelve null para el vector de un fragmento, el None terminó en el índice del vector y explotó np.dot(NoneType) durante el cálculo de similitud. Corrección de dos capas: _extract_embeddings_from_response ahora usa or [] en lugar de get(key, default), por lo que se capturan los valores explícitos de None y CustomEmbedding._get_text_embeddings valida el resultado del lote y sustituye un vector cero por cualquier ranura de None. Gracias @kagura-agent.
  • Los modelos de Gemma rechazaron el formato_respuesta json_object (#345, correcciones #344) — Gemma atendida a través de LM Studio (y servidores locales similares compatibles con OpenAI) responde 400 "'response_format.type' must be 'json_schema' or 'text'" cuando se le entrega response_format={"type": "json_object"}. Se agregó supports_response_format: False a la entrada gemma MODEL_OVERRIDES existente para que se omita la ruta json_object; Las utilidades extract_json_object existentes en los agentes de visualización y animación matemática ya analizan JSON a partir de texto plano, por lo que todas las personas que llaman continúan trabajando sin más cambios. Gracias @octo-patch.

Expansión del conjunto de pruebas

Net +575 líneas de prueba: 10 casos para el cargador de parámetros de chat/coerción _ChatLimits (tests/services/config/test_chat_params_config.py), 18 casos para el flujo de regeneración que incluye las tres rutas de rechazo, eliminación + reinicio in situ, omisión de actualización de memoria y contrato de usuario sin duplicados de extremo a extremo (tests/services/session/test_regenerate.py), 14 casos para anulaciones del modelo supports_response_format (tests/services/llm/test_capabilities.py) y un prueba de regresión para la ruta de extracción de incrustación None (tests/services/embedding/test_extract_embeddings.py).

¿Qué ha cambiado?

  • corrección (trapo): protección contra ninguna incrustación en el canal LlamaIndex por @kagura-agent en https://github.com/HKUDS/DeepTutor/pull/347
  • corrección: deshabilite json_object Response_format para modelos Gemma por @octo-patch en https://github.com/HKUDS/DeepTutor/pull/345
  • corrección (web): garantiza texto legible en bloques de código oscuro en tema claro por @DarkGenius en https://github.com/HKUDS/DeepTutor/pull/352
  • hazaña (chat): hacer que los límites de tokens por etapa y la temperatura sean configurables a través de agentes. yaml por @DarkGenius en https://github.com/HKUDS/DeepTutor/pull/348
  • hazaña (chat): regenerar la última respuesta (CLI, WebSocket, Web UI) por @DarkGenius en https://github.com/HKUDS/DeepTutor/pull/349
