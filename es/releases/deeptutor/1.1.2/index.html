#DeepTutor v1.1.2

DeepTutor v1.1.2 Release Note

Fecha de lanzamiento: 2026.04.18

Destacados

Pestaña Canales basados en esquemas con revelación de tokens (n.º 338)

La pestaña Canales en la página Agentes ya no está codificada para Telegram. Ahora descubre automáticamente todos los canales (Telegram, Slack, Discord, Matrix, Email, Feishu,…) y genera un formulario directamente desde el esquema de configuración de Pydantic de cada canal; no se requiere código de interfaz por canal. Los campos secretos (tokens, contraseñas, claves API) se representan como entradas enmascaradas con un interruptor ocular para revelación explícita. Un banner last_reload_error advierte cuando los oyentes en vivo no pudieron reiniciarse después de un cambio de configuración.

Enmascaramiento secreto del canal

Las respuestas de API ya no exponen secretos del canal sin procesar. Los tokens y las contraseñas se reemplazan por *** de forma predeterminada; el formulario de edición del administrador usa ?include_secrets=true para recuperar texto sin formato cuando sea necesario. Las respuestas de creación y actualización también están enmascaradas.

Validación de configuración de canal y refuerzo de recarga

PATCH /tutorbot/{bot_id} ahora valida las cargas útiles del canal por adelantado y devuelve un 422 con errores estructurados en lugar de persistir silenciosamente una mala configuración. reload_channels se serializa con un bloqueo por instancia para evitar escuchas duplicadas, y cualquier falla se registra en last_reload_error para que la interfaz de usuario pueda mostrarla.

RAG simplificado a una sola tubería

Se eliminaron ~2600 líneas de andamios RAG no utilizados (fragmentadores, incrustadores, indexadores, analizadores, recuperadores, orquestador de canalizaciones, definiciones de tipos) que existían como marcadores de posición para backends que nunca se enviaron. El servicio RAG ahora es una envoltura delgada sobre el único canal LlamaIndex. Los valores heredados de rag_provider (por ejemplo, lightrag) se fuerzan silenciosamente a llamaindex y la KB se marca para volver a indexarse.

Enrutamiento de tipo de archivo centralizado

Clasificación consolidada de tipos de archivos en un único módulo FileTypeRouter con un API plano (get_document_type, classify_files, get_supported_extensions, etc.). Los antiguos asistentes de extensión por proveedor ya no existen: solo hay un proveedor. Las extensiones desconocidas aún no llegan al rastreo de contenido antes de ser rechazadas.

No más bases de conocimientos fantasmas

Cerré todas las rutas de código que podían llamar silenciosamente a RAG contra una base de conocimiento inexistente:

  • deep_solve: elimina la herramienta rag cuando no hay KB adjunto y advierte al usuario.
  • deep_research: elimina kb de las fuentes, advierte y cancela si no quedan fuentes.
  • SolveToolRuntime: devuelve una observación elegante de "no se seleccionó KB" en lugar de fallar, lo que mantiene vivo el bucle ReAct.
  • ResearchPipeline: devuelve un evento estructurado "omitido" en lugar de recurrir al antiguo marcador de posición DE-all.
  • DecomposeAgent: ya no tiene el valor predeterminado ai_textbook; deshabilita RAG cuando no se proporciona KB.

Avisos de chat externalizados

Se movieron todas las cadenas zh/en codificadas de AgenticChatPipeline a archivos editables YAML (agentic_chat.yaml para cada idioma). Las etiquetas de etapa, las indicaciones del sistema, las plantillas de usuario y los avisos de la interfaz de usuario ahora se pueden configurar sin cambios de código. Retrocede con gracia si falta el YAML.

LÉAME tailandés (#337)

Se agregó README_TH.md con documentación en idioma tailandés.

Corrección de errores

  • El proceso de investigación falló sin una KB: la KB alternativa DE-all ya no existe en la mayoría de las instalaciones; ahora cortocircuitos con un evento de salto estructurado.
  • El agente de descomposición probó RAG contra ai_textbook: reemplazó el valor predeterminado codificado con None y un guardia defensivo.
  • La configuración incorrecta del canal persistió en silencio: ahora se rechaza en el límite API con un 422 antes de llegar al disco.
  • El reload_channels simultáneo creó oyentes duplicados: serializados mediante un bloqueo asíncio; La falla deja al bot sin canal con un error claro en lugar de estar medio reconstruido.
  • Tokens de canal filtrados en las respuestas de API: ahora están enmascarados de forma predeterminada en todos los puntos finales.

Conjunto de pruebas

Se agregaron 6 nuevos módulos de prueba (1042 líneas en total): enrutamiento de tipo de archivo, migración de configuración de KB, introspección de esquema de canal, enmascaramiento de secreto de canal, coherencia RAG/KB en la capa de capacidad y seguridad de RAG en el canal de investigación. Se ampliaron las pruebas existentes para los módulos de tiempo de ejecución de herramientas, enrutador de conocimientos, enrutador TutorBot y canalización RAG.
