#DeepTutor v1.3.1

DeepTutor v1.3.1 Release Note

Fecha de lanzamiento: 2026.04.28 v1.3.1 es una versión de estabilidad posterior a v1.3.0. Se centra en un enrutamiento RAG más seguro, validación de incrustación más sólida, reinicios de Docker/TutorBot más confiables y un conjunto de correcciones pequeñas pero importantes de Web UX.

Destacados

Enrutamiento más seguro de RAG y base de conocimientos

  • La KB seleccionada ahora tiene el estado del sistema trusted - Las llamadas de chat RAG ya no permiten que LLM inventar o anular kb_name; el modelo solo ve un query y DeepTutor lo enruta a la KB seleccionada en la interfaz de usuario/sesión.
  • No hay respaldo silencioso cuando RAG no tiene KB - si RAG está habilitado pero no hay KB seleccionado, el turno omite la recuperación de KB con un mensaje de progreso claro en su lugar. de consultar accidentalmente el estado obsoleto/predeterminado.
  • Los alias de KB predeterminados se manejan de manera consistente - default, current, selected y sus equivalentes chinos se resuelven en la KB predeterminada configurada para llamadas a herramientas, listado de archivos y reindexación de API, mientras que una base de conocimiento real llamada default todavía gana sobre el alias.
  • Las adiciones incrementales de documentos usan la capa de servicio - ahora se agregan archivos a través de RAGService.add_documents, manteniendo activado el comportamiento de agregar/buscar/reindexar el mismo proveedor y ruta de versión de índice.
  • Los componentes internos de RAG son más fáciles de mantener - el proceso de LlamaIndex se dividió en módulos enfocados para carga, integración, almacenamiento, errores y orquestación; La recuperación inteligente de consultas múltiples ahora se encuentra en SmartRetriever.

Incrustación y confiabilidad del índice

  • Las respuestas incrustadas se validan antes de su uso - DeepTutor ahora rechaza vectores eliminados, valores nulos, valores no numéricos, valores no finitos y dimensiones inconsistentes antes de que lleguen a LlamaIndex.
  • Las pruebas de conexión analizan el comportamiento del lote - Las pruebas de humo integradas ahora envían un lote pequeño, capturando proveedores que solo devuelven un vector o cambio dimensiones entre entradas.
  • Los índices incorrectos fallan con mensajes procesables - El vector nulo o la forma no coinciden Los errores de recuperación ahora devuelven una sugerencia de reindexación en lugar de exponer archivos de bajo nivel. Errores de estilo NoneType * float.
  • El estado del índice es menos ruidoso durante las escrituras - versión vacía en progreso Los directorios ya no marcan los KB nuevos como needs_reindex y fallaron al vaciarlos. Las carpetas de la versión se limpian cuando es posible.
  • Se aclararon los ejemplos de incrustación - services/embedding/.env.example ahora documenta la semántica completa de URL de punto final y ejemplos concretos de proveedores para OpenAI, SiliconFlow, Ollama, Cohere, Jina, vLLM, Azure OpenAI, DashScope y Puertas de enlace estilo OpenAI-SDK.

Docker, memoria y tiempo de ejecución de TutorBot

  • Las imágenes Docker pueden exponer la versión de la aplicación - Se pasa APP_VERSION a variables de entorno de ejecución tanto de backend como de frontend.
  • La memoria compartida tiene su propio volumen Docker - ahora se montan los archivos de redacción ./data/memory:/app/data/memory; Se actualizaron los documentos de persistencia README.
  • La migración de memoria es más segura - Los archivos heredados SUMMARY.md y PROFILE.md son copiado en data/memory incluso cuando el directorio de destino ya existe, mientras Los archivos de destino existentes se conservan.
  • Las actualizaciones de memoria se serializan - reescrituras simultáneas de perfil/resumen ahora corre bajo un candado para evitar escrituras aceleradas.
  • Se conserva la intención de reinicio de TutorBot - El cierre correcto del servidor mantiene cada uno La bandera auto_start del bot está intacta para el próximo reinicio de Docker/host, mientras que es manual se detiene aún desactiva el inicio automático.
  • TutorBot comparte memoria a largo plazo - Los agentes de bot iniciados ahora reciben la directorio de memoria compartida en lugar de ejecutarse sin él.

Correcciones de UX de creación y web

  • Envío de mensajes seguro para IME: los redactores de chat ya no envían mensajes cuando se pulsa Enter. se utiliza para confirmar candidatos IME chinos/japoneses/coreanos.
  • La lista de conocimientos se mantiene actualizada en el chat: la página de chat recarga los metadatos de KB en cambios de enfoque, presentación de página y visibilidad, por lo que las KB recién creadas o reindexadas aparecen sin una actualización completa.
  • La vista previa de Markdown protege las pseudoetiquetas: etiquetas desconocidas similares a HTML, como <think> tienen caracteres de escape para su visualización y al mismo tiempo se conservan los recuentos de líneas de origen para editor/sincronización de vista previa.
  • Etiquetas de razonamiento de tiras de salida del coautor: cerradas, con alias, atribuidas y Los bloques <think> / <thinking> no cerrados se eliminan de la salida de edición final.
  • La inicialización del tema se ejecuta antes de la hidratación - se representa el script del tema del servidor para que se aplique la preferencia oscuro/claro antes de que React se hidrate.
  • La retroalimentación de la interfaz de usuario de conocimiento es más clara - Los chips de la versión de índice tienen etiquetas más limpias, Se explican los índices activos vacíos fallidos y los errores 404 de la interfaz de usuario más nueva frente a la anterior El backend de Docker ahora sugiere extraer/recrear el contenedor.
  • Los comentarios de la página de memoria son más claros - Las llamadas de actualización distinguen "marcado, no actualizaciones a largo plazo" de fallos reales.

Inicio y robustez de Windows

  • CLI/las secuencias del servidor toleran páginas de códigos heredados - scripts de inicio y API Los corredores utilizan secuencias de texto seguras para el reemplazo para evitar fallos de Unicode en Windows. configuraciones regionales como GBK/CP936.
  • Los procesos secundarios heredan una codificación más segura - Se establecen rutas de inicio web/tour PYTHONIOENCODING=utf-8:replace.
  • Los archivos env de frontend generados son UTF-8 - start_web.py ahora escribe web/.env.local con codificación UTF-8 explícita.
  • GHCR Compose obtiene imágenes más frescas - docker-compose.ghcr.yml ahora usa pull_policy: always para la imagen publicada.
  • Se actualizaron los documentos/configuraciones regionales - Se actualizaron las notas de persistencia README, el Se agregó el enlace LÉAME polaco y falta la copia de la interfaz de usuario en inglés/chino etiquetas para conocimiento, memoria, plantillas de alma de TutorBot y borradores de coautores.

Pruebas

  • Cobertura agregada/actualizada para enrutamiento de KB de RAG de chat, alias de KB predeterminados, conocimiento archivo/reindexación APIs, incorporación de validación por lotes, vector no válido LlamaIndex fallas, estado de la versión del índice en progreso, diseño de almacenamiento de adición incremental, TutorBot inicio automático/memoria compartida, migración de memoria, codificación Windows CLI, Manejo del teclado IME, etiqueta de rebajas escaping y limpieza de etiquetas de razonamiento.

Notas de actualización

  • Los usuarios de Docker deben extraer y recrear el contenedor para que la interfaz de usuario web y el backend conocimiento Los API permanecen sincronizados.
  • Si una base de conocimiento se indexó con un proveedor de incrustación roto o modificado, use Vuelva a indexar desde la página de Conocimiento después de corregir la configuración de incrustación.
  • Si conserva los datos manualmente, agregue el nuevo montaje de memoria compartida: ./data/memory:/app/data/memory. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.3.0...v1.3.1
