código-claude v2.1.318

¿Qué ha cambiado?

  • Se agregó un registro de tu respuesta cuando Claude Code te pide activar los mods que escribe en una sesión.
  • Se agregó assume_role en mantle en sentido ascendente de la puerta de enlace de aplicaciones de Claude, para un rol en otra cuenta de AWS y para la atribución de costos de AWS por desarrollador.
  • Se agregó una opción effort al $.model.fork de un mod, para que se pueda ejecutar un trabajo secundario rápido en low independientemente del esfuerzo que utilice la sesión; el resultado informa el esfuerzo enviado
  • Se agregó la fecha en que finaliza un inicio de sesión almacenado en claude.ai en claude auth status (loginExpiresAt) y en los resultados de claude -p JSON (credential_expires_at).
  • Se agregó una advertencia estándar de una línea a la salida de texto claude -p, que comienza 10 días antes de que finalice un inicio de sesión almacenado en claude.ai.
  • Se corrigió que --continue a veces perdiera la conversación anterior después de que se agotaran los reintentos de una llamada a una herramienta con formato incorrecto (regresión en 2.1.314).
  • Se corrigieron sesiones de macOS con muchos comandos Bash en ejecución que se detenían mientras la memoria crecía.
  • Se corrigieron las solicitudes de permiso que se respondían mediante teclas escritas justo después de enviar un mensaje o antes de que apareciera un mensaje lento.
  • Se corrigió el éxito de los informes de /logout, claude auth logout y claude mcp remove, y los cambios en trust, el consentimiento o la configuración de MCP se eliminaron sin ninguna palabra, cuando el archivo de configuración no se pudo actualizar en un directorio de inicio de red compartido.
  • Se corrigieron los trabajos que salían con Not logged in cuando otra terminal o host inicia sesión nuevamente en la misma cuenta y organización en la misma casa.
  • Se corrigió que claude mcp add y remove escribieran la configuración sin su bloqueo: ahora esperan o salen 1, aunque guardar otro trabajo aún puede reemplazar un servidor guardado.
  • Se corrigieron los comandos claude plugin que salían antes de que se guardara una actualización lenta del token, lo que podía cerrar sesión en la siguiente ejecución.
  • Se corrigió que claude plugin validate pasara un archivo de mercado con nombre personalizado que claude plugin marketplace add rechaza
  • Se corrigieron los servidores stdio MCP que salían en la prueba de versión y se volvían a probar en cada inicio; un servidor que muere en menos de 3 segundos por su propia razón también queda anclado al protocolo de enlace heredado durante 7 días
  • Se corrigió que las sesiones fueran rechazadas al inicio por una lista allowedProviders que otro inicio de sesión en la misma máquina había almacenado
  • Se corrigió la compactación inactiva reemplazando una conversación con una respuesta que no era un resumen
  • Se corrigió el aviso "Ahora usando créditos de uso" que reaparecía aproximadamente cada 30 segundos mientras se ejecutaba un subagente en segundo plano.
  • Se corrigieron los comandos de barra diagonal personalizados que fallan, o que solo Claude puede invocar, imprimiendo nada en las sesiones claude -p y SDK.
  • Se corrigieron las sesiones de claude -p y del Agente SDK que informaban de éxito cuando un error de API cortaba una respuesta mientras un mod conectaba a turn.step.
  • Se corrigió un mensaje enviado justo después de un cambio de modelo que aún se ejecuta después de Detener en sesiones sin cabeza: Detener ahora lo cancela o lo detiene como lo haría con un mensaje en cola
  • Se corrigió una transcripción de sesión eliminada que se recreaba con su último mensaje cuando se salía de una sesión inactiva no interactiva.
  • Se corrigieron los hosts claude remote-control, el demonio en segundo plano y los ejecutores autohospedados que no podían iniciar nuevas sesiones (spawn ENOENT) después de que una actualización o limpieza de la versión eliminó el binario de un proceso que aún se estaba ejecutando.
  • Se corrigió que un proceso de Claude Code en ejecución propiedad de otro usuario (por ejemplo, uno dejado por sudo claude) fuera tratado como inactivo por la limpieza de versiones, lo que podría eliminar su binario.
  • Se corrigió /remote-control que mostraba una sesión como disponible después de una conexión fallida.
  • Se corrigió el éxito del informe /design revoke cuando la solicitud fallaba con un 404
  • Se corrigió un comando de shell aprobado después de que un ejecutor autohospedado o una sesión en la nube se reiniciaran ejecutándose en la carpeta de inicio de la sesión, no en la carpeta en la que se solicitó; si no se puede ingresar a esa carpeta, no se ejecuta
  • Se corrigió que a Claude no se le informara cuando una herramienta de conector aprobada no estaba disponible después de reiniciar una sesión en la nube.
  • Se corrigió que las sesiones en la nube se detuvieran en medio de un turno cuando el servicio rechazaba las cargas durante varios minutos.
  • Se corrigieron las variables que un gancho Setup escribe en CLAUDE_ENV_FILE y no llegan a la herramienta Bash en algunas sesiones en la nube.
  • Se corrigió la aplicación de iPhone que mostraba el turno de una sesión en la nube como finalizado mientras seguía ejecutándose, después de que se cortaba una respuesta en una llamada de herramienta o se eliminaba una imagen o documento rechazado.
  • Se corrigió una sesión reiniciada que reenviaba un mensaje que fallaba con un error API, delante del mensaje más nuevo esperando detrás de él.
  • Se corrigió una sesión reiniciada que dejaba su turno interrumpido cuando el reinicio se producía justo después de que Claude leyera una imagen grande o volviera a intentar una llamada de herramienta.
  • Se corrigió cada falla de conexión cuando el archivo NODE_EXTRA_CA_CERTS está vacío, no es PEM, o comienza con un certificado dañado: ahora se usan certificados legibles, con una advertencia en stderr.
  • Se corrigieron los flujos de trabajo que volvían a ejecutar agentes terminados cuando se reanudaban después de un límite de uso.
  • Se corrigió /mcp en sesiones de nube contando herramientas que el modelo no puede usar; La fila de un servidor ahora muestra cuántas de sus herramientas están disponibles.
  • Se corrigió una notificación duplicada cuando Claude dejaba el campo de estado fuera de una llamada PushNotification.
  • Se corrigió el error de una imagen demasiado grande en una solicitud con más de 20 imágenes y siempre decía que el límite era 2000 px; ahora muestra el límite del API
  • Se corrigió el tiempo de ejecución en los detalles del shell en segundo plano que no se actualizaban mientras el cuadro de diálogo estaba abierto.
  • Se corrigió el gancho turn.step de un mod que hacía que una respuesta detenida terminara como un éxito en ejecuciones sin cabeza.
  • Se corrigió la limpieza de retención que dejaba una casa que solo ejecuta claude -p sin copia de seguridad de ~/.claude.json: ahora requiere una copia de seguridad nueva antes de eliminar la última buena.
  • Se corrigió el inicio de sesión almacenado que se reemplazaba por un archivo vacío cuando un directorio de inicio de red no tiene espacio para datos pero aún acepta archivos nuevos.
  • Se corrigió que los tokens de setup-token fueran rechazados al inicio en máquinas con forceLoginOrgUUID, cuando el token pertenece a una organización permitida.
  • Se corrigieron lanzamientos no interactivos reemplazando un ~/.claude.json que no es válido JSON con valores predeterminados; el inicio ahora falla, dice cómo restaurar el archivo y lo deja como está (anthropics/claude-code#87551)
  • Se corrigió un ~/.claude.json vacío sin que se informara que ninguna copia de seguridad estaba dañada; Claude Code ahora se inicia como lo hace cuando falta el archivo
  • Se corrigió el comando de restauración impreso para un ~/.claude.json dañado o faltante que nombraba una copia de seguridad vacía o cortada, o fallaba en un archivo de solo lectura.
  • Se corrigió el error de inicio de sesión cuando un inicio de sesión almacenado en claude.ai alcanza su límite de tiempo: ahora lo dice, y en claude -p los nombres claude auth login y claude setup-token
  • Se mejoró la forma en que ~/.claude.json, los archivos de configuración y el inicio de sesión almacenado sobreviven en los directorios de inicio compartidos de la red: con menos frecuencia se eliminan, se vacían brevemente o se reemplazan por una copia casi vacía o más antigua.
  • Sesiones mejoradas en sistemas de archivos de red para volver a mirar cuando se informa erróneamente que falta el archivo de configuración, por lo que menos personas inician sin sus servidores MCP y carpetas trusted
  • Errores de herramienta MCP mejorados: una llamada realizada antes de que se cargue la herramienta ahora devuelve su esquema de entrada
  • Se mejoró la confiabilidad de las confirmaciones de git y la creación de solicitudes de extracción cuando la herramienta Bash ejecuta el /bin/bash integrado de macOS.
  • Se mejoró "Pídele más uso a tu administrador" en el menú de límite de uso para enviar la solicitud en un solo paso.
  • Se mejoró la rapidez con la que las sesiones remotas se reconectan después de una pausa o de suspensión.
  • Mejorado Deberías saber cómo decir "inténtalo de nuevo" en lugar de "presiona 2", lo cual solo funciona en la terminal.
  • Confiabilidad de actualización automática mejorada: una breve falla de red mientras se verifica una versión ahora se vuelve a intentar de inmediato en lugar de esperar la siguiente verificación
  • Ejecuciones desatendidas mejoradas (aplicaciones claude -p, SDK) para dejar de reescribir ~/.claude.json en cada ejecución cuando nada en él cambia
  • Se modificó Claude Code para que ya no instale ni actualice la extensión IDE cuando se inicia en una terminal IDE; use /ide desde una terminal externa o la vista de extensiones de su editor
  • Se cambiaron los subagentes para que se detengan en lugar de cambiar de modelo cuando "Cambiar de modelo cuando se marca un mensaje" está configurado en "Preguntar cada vez".
  • Se cambiaron los subagentes en segundo plano para mover un comando de shell al fondo después de 3 minutos en todos los proveedores, de modo que el caché del mensaje no caduque mientras se ejecuta.
  • Se cambiaron los resúmenes de progreso del subagente en Bedrock, Vertex, Foundry o con la telemetría desactivada: en un caché de avisos en frío, ahora se puede esperar hasta 5 minutos por la respuesta pendiente del subagente.
  • Se cambió lo que un mod adjunta en prompt.submit para permanecer en el turno del usuario en lugar de aparecer como un mensaje del sistema.
  • Se cambiaron las entradas de URL deniedMcpServers para bloquear también los servidores proporcionados por Anthropic cuya URL ascendente coincida y los conectores en sesiones en la nube y en corredores autohospedados, donde la sesión recibe la propia URL del conector; de lo contrario, denegar un conector por su nombre
  • Se cambiaron los detalles de la regla /permissions, las reglas integradas y las vistas de confirmación de eliminación para usar el diálogo estándar; Al presionar Ctrl+C dos veces, ahora se retrocede o se cancela en lugar de salir.
  • Se modificó /claude-api managed-agents-onboard para brindar a las herramientas integradas de un nuevo agente y a las herramientas MCP de una plantilla de inicio rápido, la política de permisos auto ("Juzgar acciones riesgosas") de forma predeterminada, que coincide con la Consola Claude; diga "ejecutar sin preguntar" para optar por no participar
  • Se eliminó la corrección de 2.1.288 que mantenía el pensamiento anterior del modelo al reanudar una conversación iniciada en 2.1.286 o antes; ese pensamiento ahora puede ser abandonado
  • Puerta de enlace: se agregó una advertencia de registro cuando el token de acceso de Google de un archivo de credenciales de federación (external_account) está a punto de caducar.
  • Puerta de enlace: se mejoraron las sugerencias de registro sobre listen.trusted_proxies: ahora dicen que se incluya solo un proxy que agrega la dirección de conexión al propio X-Forwarded-For.
  • Puerta de enlace: se mejoró la advertencia cuando AWS CountTokens falla en Amazon Bedrock: dice Claude Code, no la puerta de enlace, cuenta después del 501 y apunta a IAM solo cuando AWS niega el acceso.
  • Ejecutor autohospedado: se agregó CLAUDE_RUNNER_SPAWN_REASON al entorno de enlace de spawn-runner del orquestador: por qué Anthropic envió la solicitud (por ejemplo, runner_lost, resumed); desarmado cuando no se envió ninguno
  • Ejecutor autohospedado: se agregó una advertencia de inicio cuando --release-idle-session-min es el último argumento sin valor (aún ignorado) o tiene un valor de solo espacios (aún se lee como 0).
  • Ejecutor autohospedado: se cambiaron las líneas de registro del orquestador: ok session=… ahora imprime en cada nivel de registro en stdout (era solo depuración, stderr) con reason=… después de jti=…, y nack session=… finaliza sus campos con reason=… después de retryable=…; actualizar scripts que coincidan con retryable=true: o retryable=false:
  • Control remoto: se corrigió un "error de generación: ENOENT" engañoso cuando faltaba la carpeta de trabajo de una sesión; el error ahora nombra la carpeta
  • Control remoto: se mejoró el título con el que se crea una bifurcación de una terminal cuando la aplicación no configura una: "Nombre (bifurcación 2)"
  • [VSCode] Se corrigió una ventana en la que la configuración de inicio de sesión de la organización rechazaba iniciar un nuevo proceso de Claude Code en segundo plano cada minuto.
  • [VSCode] Se corrigió una palabra larga en el banner de error del panel de chat al presionar el botón de cerrar fuera de la vista.
  • [VSCode] Se mejoró la pantalla de inicio de sesión para mostrar lo que Claude Code imprimió cuando falla la verificación del estado de inicio de sesión.
  • [Sesiones en la nube] Se agregó una opción sin repositorio: una sesión en la nube en un entorno alojado en Anthropic ahora puede comenzar sin elegir un repositorio
  • [Sesiones en la nube] Se agregaron los nombres habituales de Chrome a las sesiones en la nube, para que otras herramientas además de Playwright puedan encontrar el Chromium integrado a través de google-chrome y CHROME_PATH.
  • [Sesiones en la nube] Se agregó un botón Nueva sesión a la tarjeta que se muestra cuando se eliminó el entorno de una sesión en la nube, donde el cuadro de mensaje está oculto.
  • [Sesiones en la nube] Se corrigió la lectura de registros de acciones GitHub en sesiones en la nube: las solicitudes de registro gh run view --log y gh api ahora obtienen el registro en la mayoría de los entornos, no una redirección inalcanzable
  • [Sesiones en la nube] Se mejoró la mayoría de los mensajes de falla de creación de relaciones públicas en la nube y sesiones de control remoto: ahora dan el motivo o un enlace a GitHub en lugar de decir Inténtalo de nuevo.
  • [Sesiones en la nube] Se cambiaron los resultados de búsqueda del conector para indicarle a Claude que la búsqueda cubre solo una parte del directorio del conector.
  • [Control remoto] Se corrigieron las cajas en paralelo de un repositorio que parecían idénticas en las filas de Control remoto del menú de entorno; cada uno ahora muestra su propio nombre de carpeta
  • [Claude Tag] Se corrigió el enfoque del teclado y los anuncios del lector de pantalla en la configuración de administración de Claude Tag; Al presionar Escape en el formulario de conexión ya no se cierra el cuadro de diálogo Agregar.
  • [Revisión de código] Se mejoró la página de análisis de Revisión de código para volver a intentarlo una vez después de una falla del servidor o de la red y luego mostrar un banner Intentar nuevamente en lugar de tarjetas vacías.
