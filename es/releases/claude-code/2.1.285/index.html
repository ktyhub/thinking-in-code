código-claude v2.1.285

¿Qué ha cambiado?

  • Se agregó la variable de entorno CLAUDE_CODE_DISABLE_WEB_FETCH para desactivar la herramienta WebFetch.
  • Se agregó claude --desktop para abrir la aplicación de escritorio de Claude en el directorio actual o en una sesión con --continue/--resume <id>.
  • Se agregó claude plugin configure <plugin> para mostrar las opciones de un complemento y cuáles no están configuradas, o guardar nuevos valores leídos desde stdin con --values-stdin
  • Se agregó <server>.<key>=<value> a claude plugin install --config, por lo que la configuración propia del servidor MCP .mcpb incluido se puede establecer en el momento de la instalación y se inicia sin visitar /plugin → Configurar
  • Se agregó la configuración administrada allowedProviders para limitar qué proveedores de API puede usar una máquina (Anthropic API, un punto final personalizado, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform en AWS o una puerta de enlace en la nube)
  • Se agregó la variable de entorno CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES para limitar los reenvíos de una solicitud alternativa que no es de transmisión y que expiró el tiempo de espera.
  • Se corrigió claude -p con CLAUDE_CODE_FORK_SUBAGENT=1: la llamada de Agente del propio subagente ahora se ejecuta en primer plano, por lo que el subagente obtiene el resultado del niño.
  • Se corrigieron las instalaciones y actualizaciones de complementos y mercados a través de SSH ignorando el programa ssh configurado en GIT_SSH o en core.sshCommand de su configuración de Git.
  • Se corrigió que Claude Code se negara a iniciarse cuando el sistema operativo niega leer el archivo de configuración administrado; ahora advierte y comienza sin las políticas de ese archivo. Otros errores de lectura y archivos no analizables detienen cada sesión
  • Se corrigieron las sesiones en la nube que se reiniciaban después de que se compactara su conversación y rechazaban la siguiente actualización de un artefacto que la sesión ya había leído o publicado.
  • Se corrigió claude plugin disable y enable con una identificación completa de name@marketplace cambiando una entrada de configuración en otra letra mayúscula en lugar de la propia del complemento instalado.
  • Se corrigieron los archivos adjuntos a un mensaje enviado a través de Control remoto que se omitían después de una única descarga fallida; un error de red, tiempo de espera o error del servidor ahora se reintenta hasta dos veces
  • Se corrigió el cambio de modelos a mitad de sesión con una solicitud set_model (como el setModel del Agente SDK) dejando el nuevo modelo en el límite de token de salida incorporado y la ventana de autocompacto hasta el reinicio.
  • Se corrigieron registros y transcripciones redactados que mostraban parte de una contraseña de URL que contiene @, o toda ella cuando la URL escribe su @ como %40.
  • Se corrigió la frase de contraseña SSH y los mensajes de nuevo host del árbol de trabajo y las recuperaciones /teleport que se hacen cargo de la terminal; estas recuperaciones ahora fallan rápidamente en lugar de preguntar
  • Se corrigió el apagado de un servidor MCP agregado a mitad de sesión en las sesiones SDK y -p dejando sus herramientas disponibles
  • Se corrigió claude -p --permission-prompt-tool: la solicitud de permiso de un subagente en segundo plano ahora va a la herramienta de solicitud en lugar de ser denegada automáticamente.
  • Se corrigió claude mcp list y claude mcp get, y el error no encontrado de claude mcp remove, login y logout, imprimiendo saltos de línea y secuencias de escape de terminal de nombres y valores del servidor MCP.
  • Se corrigió el permiso automático de Sandbox para solicitar aprobación en cada ejecución de muchos scripts en línea (python3 -c, node -e) solo porque contienen =.
  • Se corrigió que los subagentes de la bifurcación no mantuvieran el modo de plan de sesión o el modo dontAsk: una bifurcación ahora se ejecuta bajo el modo de permiso de su padre y no puede salir del modo de plan.
  • Se corrigió claude remote-control --help diciendo que --[no-]chrome tiene por defecto la configuración /chrome de la máquina; las sesiones generadas mantienen a Claude en Chrome desactivado a menos que se pase --chrome
  • Se corrigieron los subagentes en segundo plano en el modo automático que provocaban una segunda respuesta redundante después de cada informe.
  • Se corrigió la creación de sesiones en la nube y /remote-env leyendo solo los 20 entornos más nuevos de una cuenta.
  • Se corrigió que el control remoto marcara un mensaje como leído tan pronto como llegaba en lugar de cuando Claude comenzó a leerlo, y perdía un mensaje que aún estaba en cola cuando el terminal se cerraba (ahora llega en la siguiente reanudación).
  • Se corrigió la instalación de un complemento con claude plugin install o /plugin colocándolo en la caché o carpeta de datos de un complemento instalado cuando sus identificadores difieren solo en ., -, @ o (macOS, Windows) capitals; la instalación ahora es rechazada
  • Se corrigieron los ganchos y las devoluciones de llamadas de permiso SDK que veían un plan faltante o desactualizado en ExitPlanMode cuando el plan se escribió en la misma respuesta.
  • Se corrigió la primera respuesta en sesiones en la nube que llegaba con decenas de milisegundos de retraso, una regresión en 2.1.283
  • Se corrigieron las sesiones que se autenticaban con ANTHROPIC_AUTH_TOKEN contra el Anthropic API nunca cargando la política de la organización.
  • Se corrigió una llamada fallida a agent(), parallel() o pipeline() que un script de flujo de trabajo espera más tarde, o no espera, y se trata como un rechazo de promesa no controlado, que podría finalizar una sesión en segundo plano.
  • Se corrigieron los ganchos sincrónicos que colgaban Claude Code mientras un proceso en segundo plano iniciado por el gancho (por ejemplo, some-daemon &) mantenía su salida abierta; el gancho ahora finaliza poco después de que sale su propio proceso
  • Se corrigió que WebFetch informara una verificación de seguridad de dominio con velocidad limitada como un bloqueo de política empresarial o de red.

  • Se corrigió que /autofix-pr y /schedule dijeran que la aplicación Claude GitHub no está instalada en un repositorio cuyo estado de instalación aún no se había verificado.

  • Se corrigió una regla de permiso Artifact ("no volver a preguntar") que permitía a la herramienta Artifact publicar un archivo fuera de los directorios de trabajo sin preguntar; agregue la carpeta del archivo con --add-dir para que la regla lo cubra
