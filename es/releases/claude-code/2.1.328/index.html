código-claude v2.1.328

¿Qué ha cambiado?

  • Se agregó modo automático para Claude Opus 4.6 y Sonnet 4.6 en Amazon Bedrock, la plataforma de agentes de Google Cloud, Microsoft Foundry y la puerta de enlace de aplicaciones Claude; Las sesiones interactivas sin modo de permiso comienzan en él.
  • Se agregó "onFailure": "block" para los ganchos mcp_tool, al igual que para los ganchos de comando y HTTP: un gancho cuya llamada falla bloquea la acción
  • Se agregó una advertencia cuando una sesión en la nube puede retener y descartar un mensaje de una sesión que omite las solicitudes de permiso.
  • Se agregó un aviso en /status y claude doctor cuando un exportador OpenTelemetry no tiene un punto final y sus datos probablemente se perderían.
  • Se agregó CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME, que permite a un host impedir que claude -p --resume y --continue ejecuten una llamada de herramienta que un gancho aplazó.
  • Se agregó soporte para aplicaciones que incorporan Claude Code para activar la opción allowManagedModsOnly del complemento de políticas; la configuración administrada por un administrador aún gana
  • Se agregó una advertencia de inicio a la puerta de enlace de aplicaciones de Claude cuando el maxEffortLevel de una política no es un nivel de esfuerzo válido.
  • Ejecutor autohospedado: se agregó --repository-folder para nombrar la carpeta que usan las sesiones para un repositorio en --capacity 1, en lugar de su ruta en la carpeta base, que no puede ser un enlace simbólico.
  • Ejecutor autohospedado: se agregó una advertencia de inicio cuando la configuración del host. json establece un modo de permiso predeterminado que las sesiones ignoran
  • Ejecutor autohospedado: se agregó --hook-label a claude self-hosted-runner orchestrator, para seleccionar manualmente etiquetas de sesión en el gancho spawn-runner.
  • Ejecutor autohospedado: se agregó --metadata key=value a claude --environment, para etiquetar una sesión para el gancho spawn-runner.
  • Ejecutor autohospedado: se agregó claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds al /metrics del orquestador, por lo que la espera de una sesión reabierta se puede diferenciar de la de una nueva.
  • Ejecutor autohospedado: se agregó una métrica de orquestador, claude_code_self_hosted_orchestrator_sessions_given_up_total, que cuenta por causa la frecuencia con la que Anthropic abandonó el inicio de un ejecutor para una sesión.
  • Se corrigieron los comandos Bash en zsh que se detenían con un error "no encontrado" en una palabra que comienza con =, como echo ==== o [ a == b ]; =cmd ya no se expande a la ruta de un comando
  • Se corrigió la compactación automática al reutilizar el indicador del sistema anterior de la sesión en lugar de reconstruirlo como lo hace /compact.
  • Se corrigió la congelación del procesamiento de rebajas en algunas entradas muy largas o mal formadas.
  • Se corrigieron congelaciones de pantalla raras.
  • Se corrigió que Esc a menudo se perdiera en un mensaje de permiso o pregunta cuando se escribía inmediatamente después; en terminales que envían Alt como Esc y una tecla, una tecla Alt u Opción no utilizada ahora declines allí
  • Se corrigió que se escribiera un pegado o la respuesta de una terminal en el mensaje cuando una conexión lenta lo cortaba en dos.
  • Se corrigió que al guardar una tarea programada se borraran las otras tareas guardadas del proyecto cuando el archivo de tareas programadas no se puede leer, en proveedores externos o con la telemetría o los indicadores de funciones desactivados.
  • Se corrigió una tarea programada con un error tipográfico en el archivo de tareas programadas del proyecto que se eliminaba la próxima vez que se guardaba ese archivo.
  • Se corrigió un caso en el que una sesión reanudada en la nube podía perder su resumen de compactación o mensajes recientes cuando un mensaje se guardaba tarde.
  • Se corrigió el conteo de tokens en el control giratorio y para los subagentes que contaban una respuesta reintentada dos veces, omitían respuestas que no fueron transmitidas y permanecían quietos mientras Claude pensaba.
  • Se corrigió el error que se muestra cuando los créditos de uso se agotan a mitad de la respuesta, que nombraba un límite de tasa
  • Se corrigió que el modo automático fallara en cada turno fuera de Claude Desktop con CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS configurado detrás de una puerta de enlace que rechazaba versiones beta, en Bedrock, Agent Platform, Foundry o Claude Apps Gateway.
  • Se corrigió que CLAUDE_STREAM_IDLE_TIMEOUT_MS no extendiera el límite de conexión de 5 minutos en puertas de enlace, URL base personalizadas y proveedores de nube.
  • Se corrigieron algunas sesiones de Claude Desktop en proveedores externos, distintas de las tareas programadas, que terminaban definitivamente con "El mensaje es demasiado largo" después de resultados de herramientas grandes; los más grandes ahora quedan fuera
  • Se corrigieron las herramientas MCP cuyo esquema de entrada comienza con anyOf, oneOf o allOf que desaparecían en proveedores externos o con telemetría o indicadores de funciones desactivados.
  • Se corrigió una herramienta MCP con un esquema de entrada no válido que fallaba en solicitudes de proveedores externos o con telemetría o indicadores de funciones desactivados; la herramienta ahora se omite y se le dice a Claude por qué
  • Se corrigió el esfuerzo que se desactivaba para el modelo de un subagente para la sesión si Bedrock, la plataforma de agentes de Google Cloud o Foundry rechazaban la configuración de esfuerzo de su resumen de progreso (regresión en 2.1.327).
  • Se corrigió el modo de código que detenía una secuencia de comandos cuando una solicitud de permiso fuera del modo automático o de derivación, la aprobación de un plan o una pregunta permanecían abiertas durante diez minutos.
  • Se corrigieron los scripts del modo de código en los modos automático y de omisión de permisos que no podían llamar a un servidor MCP que se había conectado mientras se ejecutaba el script anterior.
  • Se corrigieron los scripts del modo de código que no se ejecutaban en segundo plano en el modo automático o en el modo de omisión de permisos en una sesión elegida en el selector claude --resume.
  • Modo de código fijo que perdía una habilidad cargada, un contexto de enlace o una nota escrita con una aprobación de permiso al reanudar una sesión en la que una respuesta ejecutaba varios scripts.
  • Se corrigió que a Claude no se le dijera que un script del modo de código se cortaba cuando se reanudaba la sesión desde el selector o en un modo que solicitaba permiso.
  • Se corrigió el modo de código usando silenciosamente undefined para variables de nivel superior que un script fallido anterior nunca configuró
  • Se corrigió que los scripts del modo de código no avisaran cuando se cortaba la salida larga de un comando fallido.

  • Se modificó /bug para preguntar Sí o No antes de enviar, por lo que las entradas repetidas ya no envían un informe ni abren GitHub.
