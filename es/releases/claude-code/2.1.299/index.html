código-claude v2.1.299

¿Qué ha cambiado?

  • Se agregó la variable de entorno CLAUDE_CODE_DISABLE_FILE_MENTIONS: Claude obtiene las rutas de las menciones del archivo @ para leer con sus herramientas de archivos, no con el contenido de los archivos.
  • Se agregó compactación inactiva en la terminal: una conversación de más de 200 000 tokens que se deja inactiva durante aproximadamente 54 minutos se compacta antes de que caduque su caché de mensajes de una hora, por lo que su próximo mensaje no lo reprocesa todo.
  • Se agregó CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS para cambiar el mínimo de 200 000 tokens de compactación inactiva; "idleCompaction": false en configuración. json lo apaga. Ambos necesitan v2.1.290 o posterior
  • Se agregó $.prompt.media para que un enlace prompt.submit de un mod instalado mediante la configuración administrada pueda leer los bytes de una imagen o documento adjunto al mensaje.
  • Se agregó $.session.identity() para mods instalados mediante configuraciones administradas: cómo se inicia sesión en la sesión y su organización y correo electrónico cuando se administra forceLoginOrgUUID enumera esa organización
  • Se agregaron size, weight, mono y tabular al Text de un mod y se nombraron pasos de espaciado (xs a xl) a su Box; bold está en desuso en favor de weight
  • Se agregó --shutdown-drain-sec a claude self-hosted-runner orchestrator: en SIGTERM detiene el sondeo y realiza el sondeo en vuelo y ejecuta ganchos de generación hasta esa cantidad de segundos para finalizar.
  • Se agregó el frontmatter de la habilidad, la fuente, el nombre del complemento y la ruta del archivo a lo que recibe el gancho skill.prompt de un mod.
  • Se agregaron /effort y /fast en la vista del agente para establecer con qué comienzan las nuevas sesiones; un /model, /effort o /fast desnudo ahora se abre un selector
  • Se agregó una línea de "modo seguro" al panel de vista de los agentes para las sesiones en segundo plano iniciadas con --safe-mode.
  • Se agregó una nota única cuando el modo de plan no preguntará antes de la mayoría de las ediciones o comandos porque los permisos de omisión están disponibles
  • Se agregaron --disallow-tools y un campo de caso disallowed_tools a claude plugin eval para mantener herramientas integradas específicas, como Agent, fuera de las ejecuciones de evaluación.
  • Se agregó soporte para desactivar el bloque de atribución en la pestaña Código de Claude Desktop: establezca CLAUDE_CODE_ATTRIBUTION_HEADER=0 en el env de la política code de una puerta de enlace de aplicaciones de Claude.
  • Se agregó un campo al bloque de atribución en las sesiones de Claude Code detrás de una puerta de enlace de aplicaciones de Claude; quitar el bloque con CLAUDE_CODE_ATTRIBUTION_HEADER=0

  • Se agregó una nota en /plugin y claude plugin validate que nombra los ganchos de un mod que se omiten cuando una organización administra Claude Code.
  • Se agregaron advertencias /usage para máximo esfuerzo, flujos de trabajo, contexto siempre activo y resultados de herramientas grandes.

  • Se mejoraron los pasos de la habilidad de creación de complementos para compartir un mod: Claude pregunta público o privado y verifica los archivos antes de crear un repositorio GitHub.
  • Se mejoró el error "Habilidad desconocida" de la herramienta Habilidad para sugerir el nombre listado de una habilidad cuando Claude le agrega incorrectamente el prefijo anthropic-skills:.
  • Se mejoró /reload-skills para decir que vuelve a enviar la lista completa de habilidades a Claude, que explica cómo recuperar las habilidades después de la compactación.
  • Se mejoró el error que se muestra cuando no se puede crear un árbol de trabajo porque su confirmación base no se resuelve: ahora dice cómo finalizó la búsqueda y los motivos probables, como un repositorio sin una confirmación.
  • Se mejoró el error al crear un árbol de trabajo en la raíz del diseño de un repositorio básico: ahora explica el diseño en lugar de un error de git no relacionado.
  • Observación de artefactos mejorada: una sesión local ahora puede ver hasta 25 artefactos publicados a la vez, en lugar de 10
  • Notificaciones mejoradas del agente en segundo plano: ahora dicen cuando un agente solo está esperando su propio trabajo en segundo plano, recibió un mensaje demasiado tarde para su resultado o fue detenido por un límite de uso.
  • Se cambiaron los enlaces de complementos y los scripts de flujo de trabajo para rechazar los valores que devuelven y que anidan a más de 28 000 niveles, con un error al nombrar el límite (los scripts de flujo de trabajo permitieron 100 000).
  • Se cambiaron las acciones que un gancho de complemento puede bloquear para ser rechazadas, no permitidas, cuando el gancho no se les puede entregar o no se puede devolver su respuesta; una herramienta que ya se ejecutó tiene su resultado retenido
  • Se cambiaron las solicitudes al proxy del conector de claude.ai y a los servidores MCP alojados en Anthropic para que ya no sigan las redirecciones HTTP; las redirecciones realizadas por el propio servidor de un conector no se ven afectadas
  • Se cambiaron las solicitudes de MCP en sesiones de ejecución en la nube y autohospedadas para que ya no sigan redirecciones HTTP desde el proxy MCP de la sesión.
  • Habilidad modificada y carga de comandos: uno cuyo nombre de archivo o carpeta tiene caracteres ocultos, que cambian de dirección o que parecen espacios en blanco, < o > ya no se ofrecen hasta que se les cambie el nombre; tal name: se ignora
  • Se cambiaron los árboles ui.render en claude plugin test: el cuadro o la raíz de texto de cada mod ahora lleva el nombre part: { plugin } del mod, por lo que las afirmaciones del árbol exacto deben incluirlo.
  • Se cambiaron las lecturas de la página WebFetch para elegir su esfuerzo como lo hacen las búsquedas web: el nivel de la persona que llama en el propio modelo de la persona que llama; de lo contrario, la configuración de nivel proporciona el modelo pequeño.
  • Se modificó claude plugin test para fallar una llamada al método servido $ de un mod que no respondió en diez segundos, como lo hace una sesión.
  • El MCP modificado permite que las reglas lleguen solo al servidor que nombren: mcp__a ya no permite un servidor llamado a__b o a_; escriba mcp__<server>__* con el nombre completo normalizado del servidor
  • Se cambiaron las listas de agentes tools: para tomar solo las herramientas del servidor MCP nombrado; enumerar un servidor cuyo nombre contiene __ como mcp__<whole name>__*
  • Se modificó Claude en Chrome en sesiones de nube de Cowork fuera del modo automático: una acción de sitio aprobado que el clasificador de seguridad marca ahora le solicita en lugar de ser rechazada, a menos que se apliquen configuraciones administradas.
  • Se cambiaron los conectores MCP de sesión en la nube y de control remoto para negociar la versión 2026-07-28 del protocolo MCP de forma predeterminada en instalaciones que no obtienen indicadores; MCP_PROTOCOL_NEGOTIATION=legacy opta por no participar
  • Se cambiaron las descripciones de las herramientas MCP y las instrucciones del servidor de los servidores MCP propios de Anthropic en api.anthropic.com para llegar a Claude en su totalidad en lugar de reducirse a 4096 caracteres.
  • Se modificó el modo automático en las sesiones de nube de Cowork: un gancho PermissionRequest ya no puede aprobar comandos de shell o subagentes; esas indicaciones esperan o son denegadas
  • Se modificó el comando de reanudación impreso al salir: nombra la sesión por su ID y ya no por su nombre, de modo que nada en el nombre de una sesión pueda ejecutarse cuando se pega la línea.
  • Se modificó el comando de reanudación impreso al salir de una sesión del árbol de trabajo: usa -w y -r si las banderas largas no se ajustan al terminal. Si ninguno de los dos se ajusta a un árbol de trabajo mantenido, las filas superiores indican dónde ejecutarlo.
  • Se cambiaron las preguntas secundarias de /btw en sesiones no interactivas para devolver un error de tiempo de espera cuando aún no se ha respondido después de 11 minutos.
  • Se cambiaron los ganchos UserPromptSubmit para que se ejecuten antes de que una habilidad o un comando de barra personalizada se expanda, por lo que un gancho que bloquea el mensaje ahora también detiene sus comandos de shell integrados.
  • Se cambió el gancho UserPromptSubmit de una habilidad para que se ejecute primero en el mensaje después del que invoca la habilidad.
  • Se cambió el gancho de modificación turn.start para escuchar también los turnos de los subagentes y compañeros de equipo, no solo los del bucle principal; diferenciarlos mediante e.agentId (ausente en el bucle principal)
  • Se cambiaron los errores que se muestran cuando /ultrareview no puede cargar un repositorio para dejar de sugerir git add ., lo que podría preparar o confirmar archivos sin seguimiento como .env.
  • Se modificó el aviso de protección cibernética para que ya no se solicite a las personas que se postulen al Programa de verificación cibernética.

  • [VSCode] Tiempo de inicio mejorado en espacios de trabajo sin un entorno Python al iniciar Claude mientras se carga la extensión Python
  • [VSCode] Inicio mejorado: el selector de modelo y el menú de comando de barra ahora se completan inmediatamente en una nueva ventana en una carpeta que haya abierto antes
  • [Sesiones en la nube] Se corrigió un pico de memoria que podía bloquear una sesión cuando muchos de sus archivos de salida existentes se reenviaban a la vez.
  • [Sesiones en la nube] Se corrigió guardar una rutina editada moviéndola silenciosamente a un entorno diferente cuando la suya se había eliminado o no estaba en la lista; La rutina ahora mantiene su entorno.
  • [Sesiones en la nube] Se corrigió la búsqueda de sesiones en los detalles de administrador de un entorno autohospedado y no se encontraba nada al pegar el ID de la sesión desde el enlace de una sesión.
  • [Sesiones en la nube] Se corrigieron las listas de Sesiones y Corredores en los detalles de administrador de un entorno autohospedado que decían que la lista está vacía cuando una búsqueda simplemente no tiene coincidencias.
  • [Sesiones en la nube] Se mejoró el comando de implementación que se muestra cuando se crea un entorno autohospedado o una clave de entorno: se muestra completo, se ajusta entre argumentos y tiene un botón de copia visible.
  • [Sesiones en la nube] Se modificó la eliminación de un entorno autohospedado para desactivar sus rutinas de inmediato, con el motivo mostrado en cada rutina, en lugar de dejar que sus ejecuciones fallen.
