código-claude v2.1.325

¿Qué ha cambiado?

  • Se solucionó un problema de seguridad en cómo se decodifican las respuestas comprimidas con zstd.
  • Se agregó un consejo giratorio en VS Code y terminales integrados similares sobre cómo volver a ejecutar una celda de notebook, que se muestra una vez que Claude ha leído o editado un notebook de Jupyter.
  • Se agregó una línea debajo del error que se muestra cuando la política de su organización bloquea una solicitud, que indica cómo continuar: ejecute /rewind y cambie el mensaje, o ejecute /clear
  • Se agregó una nota para Claude cuando un git checkout, git stash o un autostash pull en espacio aislado no pueden actualizar archivos protegidos como los de .claude.
  • Se corrigieron los comandos git en línea de /security-review y skills que se detenían con un error en los árboles de trabajo de los repositorios básicos, las comprobaciones de --separate-git-dir y las comprobaciones de repo de Android.
  • Se corrigió que los subagentes con su propio modelo se movieran al modelo en modo plan cuando la configuración del modelo es opusplan o haiku.
  • Se corrigieron las lecturas de archivos de tamaño de los subagentes en un modelo diferente y los resultados de MCP con el modelo de la sesión principal.
  • Se corrigieron sesiones en muchas puertas de enlace de terceros y Foundry se detenía con un error de longitud de contexto en cada turno en lugar de compactarse.
  • Se corrigieron turnos recientes que a veces desaparecían de una sesión reanudada después de que Claude Code se detuviera sin una salida limpia.
  • Se corrigieron los comandos de shell que se ejecutaban en el directorio de inicio después de que se eliminara el directorio de trabajo; el comando ahora falla con un mensaje y se puede volver a emitir
  • Se corrigió que una edición del plan aprobado se perdiera cuando la carpeta plansDirectory no podía aceptarla: el plan ahora se guarda en la carpeta de planes predeterminada y una advertencia dice dónde y por qué.
  • Se corrigió una configuración guardada del modelo sonnet[1m] que se reescribía en una nueva instalación en una identificación de modelo que el API rechaza.
  • Se corrigió la vista de enfoque que ocultaba la respuesta a su mensaje cuando una tarea programada respondía después.
  • Se corrigió el mensaje que a veces faltaba en la vista de un subagente en segundo plano cuando la pantalla completa estaba apagada.
  • Se corrigieron opciones largas en listas y solicitudes de permiso que se sobrescribían parcialmente cuando se ajustaban, y que las pantallas de primera ejecución perdían líneas en terminales angostas.
  • Se corrigieron las advertencias de inicio sobre las reglas de permiso y el aviso "Los servidores N MCP necesitan autenticación" que se registraban como se veían cuando se desplazaban fuera de la vista.
  • Se corrigió el encabezado de bienvenida que muestra caracteres de control o se divide en líneas cuando el nombre de un agente o la carpeta de trabajo los contiene o un salto de línea.
  • Se corrigió el error rojo que se muestra cuando Claude intenta un comando que solo tú puedes ejecutar: una línea tenue ahora dice que se ejecuta solo cuando lo escribes en el símbolo del sistema.
  • Se corrigió /stats que mostraba un total de días activos que era un día demasiado alto.
  • Se corrigió que /insights dijera que un informe estaba listo cuando ninguna sesión calificaba para el análisis y escribía dos valores en su informe HTML sin escaping.
  • Se corrigió que /voice dijera que el modo de voz cambiaba cuando la configuración administrada, --settings o .claude/settings.json o .claude/settings.local.json del proyecto lo mantenían como estaba; ahora dice lo que lo sostiene
  • Se corrigió el cuadro de diálogo de bienvenida del IDE que mostraba Cmd+Esc para inicio rápido en Windows y Linux.
  • Se corrigieron los consejos de la aplicación Slack que muestran cuando la política de su organización niega sesiones en la nube.
  • Se corrigió que claude purge se colgara silenciosamente cuando no había una terminal para leer las claves, y su selector de proyectos y -i indicaban que ignoraban el teclado cuando se canalizaba la entrada estándar.
  • Se corrigió claude plugin eval --output-dir '' escribiendo el informe en la carpeta actual; ahora sale con un error
  • Se corrigió la salida de texto claude -p en una terminal que pasaba secuencias de control distintas al estilo de texto; Las tuberías y los archivos no se modifican.
  • Se corrigieron los archivos sobrantes de .oauth_refresh.lock.owner.tmp.* que se acumulaban en el directorio de configuración.
  • Se corrigió /fast que decía "Su organización deshabilitó el modo rápido" en el inicio de sesión sin llave de la consola, donde Claude Code no había preguntado al servidor.
  • Se corrigió /model que decía que su organización restringe un modelo cuando Claude Code no podía verificar eso, por ejemplo sin red.
  • Se corrigió "Iniciar sesión con su cuenta de consola" en /login reemplazando su inicio de sesión existente cuando presionaba Esc justo después del paso del navegador.
  • Se corrigió el navegador que mostraba la página de inicio de sesión exitoso en algunos casos donde el inicio de sesión fallaba o se cancelaba.
  • Se corrigió claude auth status y otros comandos cortos que dejaban un bloqueo en un perfil de la consola, lo que hacía que la siguiente sesión se bloqueara durante aproximadamente un minuto.
  • Se corrigieron las sesiones en segundo plano iniciadas en su inicio de sesión en claude.ai usando (y facturando) una clave o token API del shell que inició el servicio en segundo plano.
  • Se corrigieron más casos en los que una sesión se movía a otro inicio de sesión en segundo plano; Estos movimientos ahora se rechazan, con un mensaje que dice lo que funciona.
  • Se corrigió una segunda entrada en el cuadro de diálogo de salida que detenía el trabajo en segundo plano después de que se rechazaba el movimiento al fondo.
  • Se corrigió el recuento de tokens en Amazon Bedrock que enviaba la conversación a Bedrock cuando la configuración administrada allowedProviders no lo permite.
  • Se corrigieron los errores de los asistentes de AWS credential_process y de las credenciales predeterminadas de Google Cloud cuando Claude Code se inicia sin una variable de entorno HOME.
  • Se corrigió una sesión que a veces volvía a un modo de permiso anterior después de que se aprobara el plan de un subagente.
  • Se corrigió un valor no válido en una llamada del Agente SDK applyFlagSettings() descartando silenciosamente todas las configuraciones de llamadas anteriores; una llamada que haría esto ahora se rechaza con un error
  • Se corrigió que las sesiones aparecieran como en espera de entrada cuando una solicitud de extracción finalizada solo necesitaba su propia revisión o fusión.
  • Se corrigió un valor de configuración de teammateMode no reconocido que se ignoraba sin una advertencia: claude -p, la advertencia de inicio y claude doctor ahora lo enumeran como una entrada omitida (aún no se aplica)
  • Se corrigió que --worktree omitiera un gancho WorktreeCreate de un complemento en CLAUDE_CODE_PLUGIN_SEED_DIR en la primera ejecución en un nuevo directorio de inicio.
  • Se corrigieron sesiones de modo breve, como Dispatch, que enviaban una respuesta nuevamente después de que el turno ya había respondido.
  • Se corrigió que Claude dijera que un conector Atlassian, Asana o Sentry en funcionamiento había fallado en sesiones en la nube cuando un complemento lo enumeraba en una URL diferente.
  • Se corrigieron las sesiones de Claude Desktop y SDK que enumeraban los servidores MCP propios de una carpeta (.mcp.json, local) como agregados por el host o no los conectaban en absoluto, y no conectaban los de WebSocket, después de un movimiento de carpeta o un inicio precalentado.
  • Se corrigió que /mcp aún incluyera el servidor MCP de un complemento después de que una recarga del complemento lo eliminara mientras se estaba conectando.
  • Se corrigió que un servidor MCP permaneciera "necesita autenticación" y sus ganchos mcp_tool se omitieran, después de una actualización del token que se rechazó solo por un momento.
  • Se corrigió que las solicitudes de obtención de MCP se cancelaran sin preguntar en modo sin cabeza después de que se reemplazara la conexión de un servidor durante una llamada de herramienta.
  • Se corrigieron las llamadas de la herramienta MCP desde un host SDK que respondía "No conectado" después de que una llamada de la herramienta había reconectado el servidor MCP.
  • Se corrigió que una tarea de MCP se atascara después de que su pregunta se cerrara con Esc o se volviera a preguntar: el pie de página ahora dice que necesita su entrada y Enter en /tasks muestra la pregunta nuevamente.
  • Se corrigieron las tareas de MCP en segundo plano que dejaban de actualizarse después de que otra llamada al mismo servidor perdía la conexión, cuando una llamada posterior se reconectaba
  • Se corrigió la pregunta de una tarea de MCP en segundo plano que se abría sobre un mensaje que todavía estabas escribiendo; ahora espera hasta que envíes o borre el borrador, y la rueda giratoria y el cronómetro siguen funcionando
  • Se corrigió worktree.sparsePaths y algunos complementos y clones de mercado que omitían los archivos raíz del repositorio en versiones anteriores de git, como 2.34.
  • Se corrigieron sesiones de ejecución autohospedadas en las que varios repositorios no podían usar un repositorio agregado a mitad de sesión.
  • Se corrigió que Claude pidiera permiso antes de leer tu propio artefacto o sus datos.
  • Se corrigieron las reglas y enlaces de denegación y solicitud de permiso para la herramienta Artifact que no se aplicaban en algunas sesiones en la nube.
  • Se corrigieron los scripts del modo de código que ignoraban un árbol de trabajo ingresado con EnterWorktree, escribían rutas de acceso ~ en el proyecto y dejaban /mcp mostrando un servidor MCP como conectado después de que expirara su inicio de sesión.
  • Se corrigieron las palabras escritas con un Sí en un diálogo de permiso o aprobación de un plan que no llegaban a Claude en el modo Código.
  • Se corrigió que Claude comenzara a trabajar por sí solo cuando reanudabas una sesión que finalizaba durante un script en Modo Código; ahora espera su siguiente mensaje
  • Se corrigió un evento OpenTelemetry user_prompt faltante para un mensaje enviado mientras se ejecutaban llamadas a herramientas. El evento tiene delivery.mode: "mid_turn" y el turno en carrera prompt.id.
  • Se corrigió el evento OpenTelemetry user_prompt que omitía el texto de mensajes anteriores cuando los mensajes en cola se fusionaban en un turno en VS Code, o cuando un mensaje tenía una imagen.
  • Se corrigieron las concesiones allowed-tools de un comando de barra que se aplican a los agentes en segundo plano que se despiertan durante o después de su turno.
  • Se corrigió que /feedback y /bug cargaran otras sesiones solo cuando fueron grabadas por la cuenta u organización que inició sesión.
  • Se corrigieron las reglas relativas de denegación y solicitud de permiso (por ejemplo, Read(./.env)) que ya no cubren el proyecto después de un cd; ahora también se aplican en directorios agregados
  • Se corrigieron las reglas de denegación y solicitud de permiso que comenzaban con mcp__plugin_*_ y faltaban el servidor MCP o la herramienta del complemento escritos en otra letra mayúscula.
  • Se corrigió que las reglas de denegación no se aplicaran a la aprobación de un permiso que llega después de que se reinicia Claude Code, en el corredor autohospedado y en las sesiones claude remote-control.
  • Se corrigió un caso en el que un .claude/settings.local.json confirmado podía ser tratado como propio del usuario cuando Claude Code se iniciaba en ciertas subcarpetas de un repositorio.
  • Se corrigieron algunas reglas de denegar y preguntar que no se aplicaban a ciertos comandos de Bash.
  • Se corrigió una brecha en las comprobaciones de permisos de Bash donde algunos comandos compuestos podían ejecutarse sin preguntar; estos ahora piden permiso
  • Se corrigió un caso en el que una regla de permiso de Bash podía ejecutar un programa diferente al que nombra.
  • Se corrigió el mensaje de aprobación de una herramienta de conector en sesiones en la nube que se respondía automáticamente mientras los complementos aún se estaban cargando.
  • Se corrigió que algunos subagentes cambiaran un artefacto que las personas fuera de su organización pueden ver, o cargaran archivos en él, sin preguntar primero cuándo se estableció una regla de permiso o cuándo se aprobaron las cargas antes.
  • Se corrigieron algunas publicaciones de artefactos que omitían la confirmación de las páginas que las personas fuera de su organización pueden ver cuando se había elegido "no volver a preguntar" para Artifact.
  • Se corrigió el modo automático que juzgaba solo el primer cambio en un artefacto que las personas ajenas a su organización pueden ver; Su sí ahora cubre ese cambio solo.
  • Se corrigió un bloqueo administrado strictPluginOnlyCustomization en agentes y habilidades que no surtía efecto en sesiones que ya se estaban ejecutando.
  • Se corrigieron los comandos de espacio aislado que podían escribir en la carpeta de descarga del actualizador nativo en algunos casos.
  • Se corrigió un caso en el que el entorno limitado de Bash no protegía completamente la configuración y los ganchos de un árbol de trabajo.
  • Se corrigió un caso en el que el entorno limitado de Bash no protegía completamente la carpeta git compartida de un árbol de trabajo vinculado.
  • Se corrigió la elección de alijo de /teleport en algunos estados inusuales de git: ahora se detiene y dice qué hacer.
  • Windows: se corrigió un problema de inicio que podía durar alrededor de un segundo cuando una entrada PATH se encuentra debajo de una carpeta que su cuenta no puede abrir.
  • Se corrigió /resume en Windows que rechazaba u ocultaba sesiones cuya carpeta estaba grabada con una letra de unidad diferente o barras diagonales.
  • Se corrigió un /resume en la sesión en Windows que dejaba caer el trust guardado de un proyecto cuando la sesión se grababa con una letra de unidad diferente.
  • Linux: Se corrigieron los comandos Bash de espacio aislado que fallaban con bwrap: Can't create file cuando el directorio de trabajo estaba debajo de una carpeta allowRead dentro de un denyRead, como en un directorio de inicio con enlace simbólico.
  • Se corrigió que las implementaciones de terceros de Claude Desktop permanecieran en "Detención" hasta que finalizara la renovación del token (una vez que incluye esta versión).
  • Subagentes mejorados cortados en el límite de token de salida: ahora se les pide la respuesta completa nuevamente, más brevemente, en lugar de devolver solo el final.
  • Inicio mejorado con un inicio de sesión sin llave en la Consola u otro inicio de sesión de perfil Anthropic: un token que aún es válido se lee sin esperar a que se bloqueen las credenciales
  • Se mejoró la verificación de correo electrónico de la cuenta: ahora también rechaza su correo electrónico como identidad de client en scripts que ejecuta un comando, escribe archivos, recupera la web y llama a MCP.
  • Se mejoró el mensaje HTTPS authentication failed para mercados privados de complementos: ahora dice que las indicaciones del terminal de git y los programas Askpass están deshabilitados, y también aparece con las versiones más recientes de git.
  • Se mejoraron las confirmaciones de add-marketplace, las indicaciones de recomendación de complementos y la advertencia de instalación de complementos para indicar que los complementos pueden ejecutar código en su computadora, con acceso a sus archivos y shell.
  • Se mejoró el error de inicio de sesión claude --desktop para nombrar la clave, el proveedor o la configuración API que impide que funcione el inicio de sesión de una cuenta de Claude.
  • Se mejoró el mensaje "No se detectó audio" de /voice en macOS y Windows: ahora dice dónde elegir el micrófono
  • Tareas de MCP mejoradas: ahora se le avisa a Claude cuando una tarea está esperando su respuesta y puede indicarle /tasks.
  • claude remote-control mejorado: ahora sale con el estado 4 cuando se detiene solo (las ejecuciones de sesión única aún salen 0) y 69 cuando no puede registrarse, por lo que un administrador de servicios puede iniciarlo nuevamente.
  • Se mejoraron los mensajes que se muestran cuando una sesión en segundo plano no puede usar la clave o token API de su sesión: ya no sugieren agregar la clave a la configuración.
  • Se mejoraron los consejos de parte a todo de la habilidad de visualización de datos incluida para imágenes estáticas y para partes con un orden natural, como bandas de edad.
  • Se cambiaron los comandos Bash en el espacio aislado para seguir el flujo de permisos normal de forma predeterminada; configure sandbox.autoAllowBashIfSandboxed: true para seguir ejecutándolos sin avisos
  • Se cambiaron las configuraciones administradas que activan la zona de pruebas: para mantener los comandos ejecutándose sin avisos, configure sandbox.autoAllowBashIfSandboxed: true en su fuente administrada de mayor rango
  • Se cambiaron los comandos de git de solo lectura para preguntar primero en un repositorio que no es el del proyecto o uno que usted trusted; asígnele el nombre --add-dir, no la configuración additionalDirectories, para ejecutarlos sin indicaciones
  • Se cambiaron las tareas programadas y /loop para preguntar antes de ejecutar una habilidad que declara allowed-tools o ganchos; agregue Skill(name) a permissions.allow para ejecutarlo sin supervisión
  • Se modificó "Permitir siempre" en los hosts de escritorio, IDE y SDK: solo se ofrece una regla cuando al guardarla se permitiría ese comando nuevamente, por lo que una tarea programada que dependía de una ahora puede esperar por usted.
  • Se cambió la zona de pruebas para rechazar escrituras en la zona de pruebas en configuraciones, habilidades, agentes, comandos y enlaces de .claude en directorios agregados, como lo hace en la carpeta de inicio.
  • Se modificó el aislamiento del árbol de trabajo: ahora se rechazan los comandos de configuración de git bisect run, git maintenance register|start y scalar a una sesión o agente de árbol de trabajo aislado, y se le indica lo que aún funciona.
  • Se cambiaron los paquetes MCP de complementos (.mcpb, .dxt) para descomprimirlos en el directorio de complementos, no .mcpb-cache en la carpeta del complemento, por lo que se cargan las carpetas de complementos de solo lectura; uno obtenido mediante descargas de URL nuevamente una vez
  • Se modificaron los complementos de un mercado remoto que declara, habilita y enumera las configuraciones administradas en prependPlugins o appendPlugins para que cuenten como de la organización; pluginDigests está en desuso y se ignora
  • Se modificó la carga del complemento para omitir y claude plugin validate para informar algunas rutas y enlaces inseguros en la carpeta de un complemento.
  • Se modificó la carga de habilidades anidadas: las carpetas .claude/skills en los complementos --plugin-dir ya no se cargan desde una sesión iniciada encima de ellas; En su lugar, inicie Claude Code en la carpeta de complementos.
  • Se modificó EnterWorktree para rechazar una ruta de enlace WorktreeCreate que pasa por un enlace simbólico dentro del proyecto; haz que el gancho imprima el camino real
  • Se cambiaron los compañeros de equipo de tmux e iTerm2, y las nuevas sesiones desde la vista de agentes se abrieron con ←, para comenzar en la carpeta de la sesión en lugar de donde se ejecutó el shell por última vez cd
  • Se cambiaron las sugerencias de mensajes en la terminal para que se actualicen con menos frecuencia después de 8 turnos seguidos iniciados por tareas programadas o en segundo plano, lo que ahorra uso hasta que presione una tecla o regrese a la terminal.
  • Se cambió Esc en la pregunta de una tarea MCP en segundo plano para "responder más tarde": no se envía nada al servidor y la pregunta permanece en /tasks.
  • Se modificó CLAUDE_CODE_MAX_CONTEXT_TOKENS para configurar también la ventana contextual de ID de modelo no reconocidos que comienzan con claude-, como el claude-sonnet-latest de una puerta de enlace.
  • Se modificó /login para solicitar permiso para cambiar su configuración de privacidad.
  • Se cambiaron /cost, $.session.usage(), --max-budget-usd y las métricas de costo y token para contar las llamadas $.model.complete y $.model.classify de un mod.
  • Se cambiaron los programas que el sandbox de Claude Code inicia para su propio uso, como su puente de red, para que se ejecuten sin los tokens de inicio de sesión de Claude Code y las claves API en su entorno.
  • Se cambiaron ripgrep, los comandos locales de git y los propios programas auxiliares del tiempo de ejecución de la zona de pruebas para que se ejecuten sin la contraseña de la clave mTLS client en su entorno.
  • Control remoto: Se cambiaron /resume y /teleport para desconectarse primero cuando la sesión conectada tiene un enlace compartido, o cuando eso no se puede verificar; ejecute /remote-control para conectarse nuevamente
  • Se modificó Claude Code en la web, tareas programadas en la nube y sesiones de nube de Cowork para que se inicien a pesar de sandbox.failIfUnavailable: el contenedor alojado no tiene zona de pruebas de comandos.
  • Se cambiaron las solicitudes de configuración, reglas de permiso, enlaces o estado a través de una nube o de una conexión de sesión autohospedada para devolver menos o ser rechazadas; lo que se aplica en la sesión no cambia
  • Se modificó claude -p sin datos de cuenta almacenados en caché para esperar esos datos antes de su primera solicitud, de modo que una primera ejecución en un entorno limpio pueda comenzar unos segundos más tarde.
  • Se cambiaron las instrucciones de Claude para mantener los archivos que querrás fuera de su carpeta temporal de bloc de notas, que se puede borrar.
  • Se modificó el mercado ref para aceptar la identificación completa de cualquier confirmación en una rama o etiqueta; clients anteriores a esta versión no pueden clonar dicho pin, por lo que un mercado anclado de esta manera deja de cargarse allí
  • Se modificó el mercado de complementos y las descargas de complementos para usar un túnel CONNECT cuando ALL_PROXY es el único conjunto de proxy; un proxy que rechaza CONNECT ahora les falla
  • Se modificaron las ejecuciones de -p y SDK en un árbol de trabajo o submódulo montado en un contenedor para aplicar reglas de permiso .claude/settings.local.json solo una vez que la carpeta esté trusted.
  • Se cambiaron los ejecutores autohospedados para rechazar una sesión cuya carpeta de sesión o ruta del repositorio sea un enlace simbólico, que no sea el pago del gancho checkout.
  • Se eliminó "pídale a su administrador que lo aumente" del límite de gasto y de los errores de presupuesto compartido en sesiones en la nube y en Control remoto
  • [VSCode] Se agregaron sugerencias de mensajes dondequiera que el terminal las muestre: Tab acepta el siguiente mensaje sugerido; promptSuggestionEnabled: false en la configuración de Claude Code. json los desactiva
  • [VSCode] Se agregó un inicio de sesión en la consola que no crea ninguna clave API
  • [VSCode] Se agregó un campo para pegar la URL de redireccionamiento al iniciar sesión en un servidor MCP desde el panel en SSH, WSL y ventanas de contenedor.
  • [VSCode] Se corrigió la marca de verificación del selector de modelo que permanecía en el modelo anterior después de que Claude Code se reiniciaba en otro modelo o el modelo se cambiaba a Control remoto.
  • [VSCode] Se corrigió el selector de esfuerzo que ofrece niveles por encima del límite de esfuerzo establecido por su organización o la configuración maxEffortLevel
  • [VSCode] Se corrigió la pantalla de inicio de sesión que ofrecía inicios de sesión que la configuración administrada allowedProviders rechaza
  • [VSCode] Se corrigió el mensaje de permiso para las herramientas MCP que no decía por qué Claude Code pregunta cuando una verificación de seguridad plantea la pregunta.
  • [VSCode] Se corrigió el mensaje para la configuración de la organización que no se podía cargar diciendo que se ejecutara un comando nuevamente; ahora dice intentarlo de nuevo, coincidiendo con el enlace Reintentar de la pestaña
  • [VSCode] Se mejoró la nota que se muestra para una carpeta untrusted: ahora dice por qué la extensión está desactivada y cómo activarla
  • [VSCode] Se mejoró el error que se muestra cuando el sistema se niega a ejecutar Claude Code: ahora dice que su equipo de TI puede permitir un programa bloqueado
  • [VSCode] Se mejoró la tarjeta de inicio de sesión para decir qué hacer cuando el navegador muestra un error de conexión para localhost
  • [VSCode] Se cambió el botón de confirmación del mercado del enlace de instalación a "Mercado Trust y continuar".
  • [Claude Code en la web] Se corrigieron nuevas sesiones en la nube que cortaban las descripciones de las herramientas MCP cargadas a través de la búsqueda de herramientas en 4096 caracteres; el límite es ahora 16.384, como en otras sesiones del Código Claude
  • [Etiqueta de Claude] Se corrigieron los enlaces de artefactos pegados en Slack que no obtenían ninguna tarjeta cuando el inicio de sesión de Claude del usuario había expirado en un espacio de trabajo que su organización no administra; ahora aparece una tarjeta simple
