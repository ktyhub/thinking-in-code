código-claude v2.1.305

¿Qué ha cambiado?

  • Se agregó sandbox.allowNestedUserNamespaces para que los comandos de espacio aislado en Linux puedan crear espacios de nombres de usuario (Chromium, podman sin raíz); esto les permite eludir las protecciones de archivos del sandbox
  • Se agregó CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS para que el modo de reintento desatendido (CLAUDE_CODE_RETRY_WATCHDOG) detecte un límite de uso que se eliminó antes de su reinicio.
  • Se corrigieron todas las solicitudes que fallaban en Vertex, Bedrock y otros proveedores cuando el punto final o una puerta de enlace rechaza la búsqueda de herramientas, y detrás de puertas de enlace con ToolSearch no permitido o excluido de --tools (una regresión 2.1.304): Claude Code ahora reintenta sin él.
  • Se corrigieron las configuraciones de /effort y /autocompact que no se aplicaban cuando el nombre del modelo difería de un valor de modelOverrides por letra mayúscula o etiqueta [1m].
  • Se corrigieron nuevos árboles de trabajo en un repositorio básico que a veces comenzaban desde HEAD local en lugar de la rama predeterminada, y los árboles de trabajo de subagente sin cambios a veces no se limpiaban
  • Se corrigieron los comandos Bash en un disco lleno que fallaban con una ruta de archivo sin formato ENOSPC: el error ahora dice que el disco está lleno y que no se ejecutó nada.
  • Se corrigió que un servidor MCP pasado por una sesión en la nube o por el setMcpServers del SDK fuera reemplazado más adelante en la sesión por un servidor con el mismo nombre desde su propia configuración.
  • Se corrigió que Claude nombrara el modelo incorrecto para el trabajo de un subagente después de que el subagente cambiara a un modelo alternativo.
  • Se corrigieron sesiones en la nube y compañeros de equipo que no le decían a Claude cuando una compactación tenía que dejar los mensajes más antiguos fuera de su resumen para que encajaran.
  • Se corrigieron más casos de sesiones programadas en la nube de Cowork que esperaban cinco minutos para cada subagente cuyo WebFetch necesitaba una aprobación de URL que nadie estaba allí para dar.
  • Se corrigió el currículum del flujo de trabajo que volvía a ejecutar los agentes pipeline() y parallel() ya completados en lugar de atenderlos desde el diario de ejecución.
  • Se corrigió que el control remoto dejara las entradas "(sesión)" vacías en /resume después de cambiar de conversación con /resume.
  • Se corrigió que las filas /usage se cortaran en terminales angostas.
  • Se corrigieron las advertencias de inicio que se imprimían como texto sin formato encima del logotipo: ahora van al registro de depuración y las reglas de permiso que no restringen nada se muestran como filas de advertencia debajo del banner.
  • Modo de lector de pantalla fijo: los cuadros de búsqueda ahora dicen "Buscar:" en lugar de un símbolo. VoiceOver se lee como "grabadora telefónica" y el texto emergente resaltado, como coincidencias de búsqueda Ctrl+R y "ultrathink", ya no tiene espacios dentro de las palabras.
  • Ejecutor autohospedado: se corrigió un script de inicio que comparte solo su salida estándar con el ejecutor o el orquestador que fallaba con Resource temporarily unavailable cuando se configura TERM (una regresión 2.1.300).
  • Ejecutor autohospedado: se corrigió el error de acceso al repositorio desde 2.1.296 cuando un asistente de credenciales git o un programa Askpass lee su configuración a través de GIT_CONFIG.
  • Ejecutor autohospedado: se corrigió que el orquestador informara que un gancho de generación de corredor había expirado cuando un ejecutor iniciado en segundo plano mantenía su salida abierta.
  • /usage mejorado: cada advertencia ahora es una solución de una línea que nombra su fuente y f aplica las correcciones; las mismas correcciones aparecen en VS Code y /doctor
  • Se mejoraron los cuadros de diálogo de consentimiento de MCP para que sea menos probable que una entrada destinada al mensaje se tome como Aceptar.
  • Se mejoró el Image de un mod para dibujar su imagen en iTerm2 3.5 y posteriores con renderizado en pantalla completa, donde mostraba solo su texto alt.
  • Control remoto: se mejoraron los mensajes del modo de generación: al presionar w ahora se dice que el nuevo modo está guardado para la carpeta, y un inicio posterior de claude remote-control que usa el modo guardado dice de dónde vino.
  • Se modificó allowedMcpServers para dejar de filtrar servidores stdio managed-mcp.json que usan ${VAR} solo en env: uno que su lista de permitidos dejó fuera ahora se carga en la actualización; use deniedMcpServers para mantenerlo apagado
  • Se modificaron los complementos que Claude Desktop monta por ruta para que ya no mantengan su allowed-tools cuando la configuración administrada de su organización establece allowManagedPermissionRulesOnly.
  • Se cambió la confirmación de eliminación de /artifacts para tomar 1 o Enter para conservar, 2 para eliminar y Esc para cancelar; y y n ya no contestan
  • Se cambió el panel acoplado de un mod para permanecer dentro del 45% del ancho del terminal, incluido un ancho mantenido para un terminal más ancho.
  • [VSCode] Se agregó el estado giratorio "Ejecutando enlaces de inicio", con un anuncio en el lector de pantalla, mientras se ejecutan los enlaces SessionStart o Configuración.
  • [VSCode] Se corrigió el control giratorio que cortaba "Compactar..." cuando la configuración de spinnerVerbs reemplaza los verbos integrados por verbos cortos.
  • [VSCode] Se cambió el mensaje que se muestra cuando una sesión no se inicia a tiempo y no se ejecuta ningún enlace: ahora muestra los registros de salida y enumera las causas en lugar de apuntar primero al inicio de sesión y a la red.
  • [Sesiones en la nube] Se corrigió que la página de administración de entornos en la nube se negara erróneamente a guardar un entorno existente con un error de "instala paquetes".
  • [Sesiones en la nube] Se mejoró la eliminación de un entorno autohospedado para que el cuadro de diálogo y los mensajes de error indiquen qué bloquea la eliminación y qué afectará.
  • [Claude Tag] Se agregaron canales públicos de Slack. Claude no se ha unido al administrador de Claude Tag. Agregar búsqueda de lugar, para que los administradores puedan configurar uno desde allí.
  • [Claude Tag] Se corrigieron los paquetes de acceso a Claude Tag para que un repositorio que se movió a otra cuenta GitHub se pueda agregar nuevamente
  • [Claude Tag] Se corrigió una rutina configurada en un hilo de DM de Slack que ya no se publicaba después de que otra rutina en ese hilo reiniciaba la conversación; Ambos ahora siguen publicando allí.
  • [Claude Tag] Se corrigieron rutinas configuradas en un hilo de Slack que informaba el éxito sin publicar después de que finalizó la conversación; esas ejecuciones ahora se omiten y se le dice al creador
  • [Claude Tag] Se mejoraron las páginas de administración de Claude Tag en organizaciones grandes para que las ediciones de complementos, habilidades y paquetes funcionen mientras la lista de canales aún se está cargando.
  • [Revisión de código] Se corrigió que la revisión de código a veces no revisara la confirmación más reciente cuando varios envíos llegaban a una solicitud de extracción durante una revisión.
  • [Revisión de código] Se cambiaron las re-revisiones de revisión de código para que ya no se abran con LGTM mientras que los resultados de bloqueo anteriores todavía están abiertos
