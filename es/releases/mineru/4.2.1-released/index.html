MinerU 4.2.1-released

#MinerU mineru-4.2.1-released

##4.2.1

  • Se corrigió el contenido que faltaba en el truncamiento de Doclib y continuó leyendo. Cuando el documento Markdown o una sola página se lee en context=0, después de alcanzar el límite de longitud, continuará leyendo el contenido restante de la página actual hasta next_request.locator y next_request.after, y luego sugerirá la siguiente página después de leer. La marca de continuación CLI y el documento SDK se actualizan simultáneamente.
  • Mejorar la recuperación de fallas del servicio de resolución alojado. Detenga los reintentos automáticos después de que los fallos de inicio continuo o reinicio alcancen el límite superior y limpie los procesos restantes. Puede intentar la recuperación nuevamente después de restablecer el modo o equipo de alojamiento y reiniciar el servicio de biblioteca de documentos. Mejorar el reciclaje de procesos antiguos y canales de control al cambiar de modo, marcha y cierre de servicios.
  • Reparar la sonda del puerto del servicio de alojamiento de Windows. Verifique el puerto de acuerdo con el comportamiento de enlace real del servicio y omita los puertos ocupados o reservados por el sistema en modo de puerto no estricto para reducir el problema de no poder iniciarse después de una detección exitosa.
  • Mejorar la salida elegante del servicio de biblioteca de documentos. La limpieza del ciclo de vida se realiza mediante devoluciones de llamadas de apagado del host, lo que permite que el proceso de apagado de Windows también recicle tareas en segundo plano, procesos de análisis administrados y recursos de bases de datos.
  • Se corrigió la información faltante de la memoria de la GPU de Windows. Mejore la coincidencia de direcciones PCI entre DXGI y el inventario de hardware, conserve la coherencia de la memoria de video y los atributos del dispositivo cuando haya ambigüedades en las entradas de dispositivos del mismo modelo y mejore la integridad de la información de diagnóstico del hardware.
  • Corregir texto faltante en PDF nativo. Acepte orientaciones de texto normales cercanas a 360° debido a errores de punto flotante para evitar que el texto horizontal se filtre incorrectamente cuando se rellena el texto nativo.

Consejos de integración. El host Doclib integrado necesita configurar la devolución de llamada shutdown para admitir el cierre de la interfaz y devolver service_unavailable cuando falta la devolución de llamada. La entrada estándar mineru server tiene configurada esta devolución de llamada.

##4.2.1

  • Continuación completa de Doclib después del truncamiento. Los documentos Markdown y las lecturas de una sola página con context=0 usan next_request.locator y next_request.after para reanudar la página sin terminar después de alcanzar el límite de salida y luego sugieren la página siguiente. Los marcadores de continuación CLI y la documentación SDK siguen el mismo contrato.
  • Recuperación del servidor de análisis administrado vinculado. Detenga los reintentos automáticos después de repetidos errores de inicio o reinicio y limpie los procesos restantes. Configurar nuevamente el modo o nivel administrado, o reiniciar el servidor de la biblioteca de documentos, permite que se reanude la recuperación. Mejore la limpieza del proceso y del canal de control durante los cambios de modo, los cambios de nivel y el apagado.
  • Corregir el sondeo de puertos administrados de Windows. Haga coincidir el comportamiento de enlace real del servidor y omita los puertos ocupados o reservados por el sistema cuando el modo de puerto estricto está deshabilitado, lo que reduce las fallas de inicio después de un sondeo de puerto exitoso.
  • Cierre elegante de la biblioteca de documentos. Utilice una devolución de llamada de apagado del host para ejecutar la limpieza del ciclo de vida, incluidas tareas en segundo plano, procesos de análisis administrados y recursos de bases de datos en Windows.
  • Restaurar la información de la memoria de la GPU de Windows. Mejore la coincidencia de direcciones PCI entre DXGI y el inventario de hardware, y conserve propiedades consistentes de memoria y dispositivo cuando las entradas del mismo modelo tengan identidades ambiguas.
  • Conservar el texto del cuerpo del PDF nativo. Acepte direcciones de texto normales cercanas a 360° debido a un error de punto flotante, lo que evita que el texto horizontal se filtre durante la restauración del texto nativo.

Nota de integración. Los hosts Doclib integrados deben proporcionar una devolución de llamada shutdown para admitir el punto final de apagado. Una devolución de llamada faltante devuelve service_unavailable. El punto de entrada estándar mineru server ya proporciona la devolución de llamada.
