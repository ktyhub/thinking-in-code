MinerU 4.2.2-released

#MinerU mineru-4.2.2-released

##4.2.2

  • Mejorar la propagación de fallas y la gestión del ciclo de vida del motor VLM local. Unificar los contratos de salud pública y de invalidación de LMDeploy, vLLM, llama.cpp y MLX; deje de reutilizar instancias de caché después de confirmar la falla del motor y notifique al host asociado para evitar una degradación silenciosa debido a que las fallas globales se consideren fallas de identificación ordinarias. Si falla el reconocimiento ordinario de un solo chip, se conservará el respaldo existente.
  • Mejorar la verificación de estado y la limpieza de tareas del servicio de análisis. Detecta periódicamente tiempos de ejecución cargados que admiten comprobaciones de estado; rechaza nuevas inferencias cuando no está disponible temporalmente y vuelve a abrir cuando está en buen estado. Cuando se confirma la muerte del motor, la interfaz de estado y capacidad devuelve un error claro, las tareas en ejecución y en cola se limpian de acuerdo con los límites existentes, y el host administra la recuperación. Mejore el orden de detección, cancelación y liberación de recursos en tránsito durante el cierre.
  • Se corrigió el manejo de entradas y errores del análisis por lotes. Verifique los archivos mediante la firma de contenido y la identificación de contenedores para evitar que los archivos de bloqueo de Office bloqueen documentos posteriores y, al mismo tiempo, preserve los documentos legítimos con nombres que comienzan con ~$. La corrupción explícita, el cifrado, las restricciones de recursos, la falta de entradas y los errores de permisos se registran como fallas únicas y continúan; Las fallas del motor, del servicio o de la salida detienen el procesamiento posterior. El resumen informa los recuentos de éxito, omisión, error y no procesados ​​respectivamente, y algunos errores devuelven un código de salida distinto de cero.
  • Se corrigió el juicio de ruta de salida de lotes. La entrada de directorio y de varios archivos siempre utiliza la salida de directorio y se mantiene la misma semántica cuando solo hay un documento. Admite results.v1, results.md y otros directorios punteados existentes o recién creados, y rechaza escribir resultados por lotes en archivos normales existentes; La salida explícita de un solo archivo continúa admitiendo la sobrescritura de archivos de destino.
  • Responsabilidades claras para leer y exportar. La salida Markdown de mineru read se utiliza para lectura progresiva, retención de salida estándar, JSON y mensajes de continuación; --output PATH sólo se utiliza para imágenes. Puede usar la redirección o SDK para guardar el fragmento de texto actual y usar mineru parse ... -o ... para exportar completamente el rango de páginas especificado para evitar confundir fragmentos limitados por el presupuesto de lectura con productos completos.
  • Mejorar la experiencia de inicio y salida del servicio. Una vez que el servicio se haya monitoreado exitosamente, se imprimirá la dirección del documento API directamente accesible; La salida normal Ctrl+C ya no mostrará la pila de interrupciones. Elimine las declaraciones de capacidad de webhook no implementadas y la documentación correspondiente.
  • Actualizar dependencias del tiempo de ejecución. Las versiones mínimas se ajustan a mineru-llama-cpp 0.2.1 y mineru-vl-utils 2.0.9, de conformidad con este contrato público de ciclo de vida.

Consejo de compatibilidad. El mineru read <locator> -o part.md original debe cambiarse a redirección estándar o SDK para guardar; utilice mineru parse <path> --pages <range> -o result.md cuando se requiera un producto completo. Los llamadores masivos deben distinguir entre éxito total, fracaso parcial y aborto global según el nuevo resumen de resultados y el código de salida.

##4.2.2

  • Mejorar la propagación de fallas de VLM local y la gestión del ciclo de vida. Consuma contratos compartidos de salud y fallas para LMDeploy, vLLM, llama.cpp y MLX. La falla confirmada del motor invalida las instancias almacenadas en caché y notifica a sus hosts, evitando que una interrupción global se convierta silenciosamente en una alternativa de reconocimiento local. Las fallas ordinarias por cultivo mantienen el comportamiento de reserva existente.
  • Fortalecer las comprobaciones de estado del servidor de análisis y la limpieza de tareas. Pruebe periódicamente los tiempos de ejecución inicializados que admiten comprobaciones de estado. La indisponibilidad temporal rechaza nuevas inferencias hasta que se recupere la salud. La muerte confirmada del motor produce errores explícitos de salud y capacidad y limpia las tareas en ejecución y en cola a través de los límites del ciclo de vida existente; la recuperación sigue siendo responsabilidad del anfitrión. Mejore el orden de las sondas activas, la cancelación y la liberación de recursos durante el apagado.
  • Validación correcta de entradas por lotes y manejo de errores. Valide las firmas y los contenedores del contenido de los archivos para que los archivos bloqueados de Office no detengan los documentos posteriores, mientras que los documentos válidos que comienzan con ~$ siguen siendo compatibles. Informe las entradas conocidas corruptas, cifradas, con recursos limitados, faltantes o inaccesibles como fallas individuales y continúe. Las fallas del motor, el servicio y la salida detienen el lote. Los resúmenes distinguen entradas exitosas, omitidas, fallidas y no procesadas; el fallo parcial devuelve un código de salida distinto de cero.
  • Manejo correcto de la ruta de salida de lotes. Las entradas de directorio y de múltiples archivos siempre producen una salida de directorio, incluso cuando solo queda un documento. Acepte nombres de directorios con puntos nuevos y existentes, como results.v1 y results.md, y rechace archivos normales existentes como destinos por lotes. La salida explícita de un solo archivo sigue admitiendo la sobrescritura de su destino.
  • Aclarar lectura y exportación. Markdown de mineru read sigue siendo una lectura estándar progresiva o JSON con sugerencias de continuación; --output PATH está reservado para imágenes. Guarde el fragmento de texto actual mediante la redirección o SDK, y use mineru parse ... -o ... para exportar un rango de páginas completo sin el presupuesto de lectura.
  • Mejorar el inicio y apagado del servicio. Imprima las URL de documentación de API a las que se puede acceder directamente después de un enlace exitoso, evite los rastreos de interrupciones en el cierre normal de Ctrl+C y elimine las declaraciones y documentación de capacidad de webhook no implementadas.
  • Actualizar dependencias del tiempo de ejecución. Requiere mineru-llama-cpp 0.2.1 y mineru-vl-utils 2.0.9 o versiones compatibles más recientes para los contratos de ciclo de vida compartido.

Nota de compatibilidad. Reemplace mineru read <locator> -o part.md con redirección estándar o guardado SDK. Para exportaciones completas, utilice mineru parse <path> --pages <range> -o result.md. Los llamadores de lotes deben interpretar el resumen de resultados y el código de salida para distinguir el éxito total, el fracaso parcial y un lote abortado.
