LangBot v4.11.9

LangBot es una plataforma de agente y chatbot de IA de código abierto que admite múltiples plataformas de mensajería instantánea, grandes modelos de lenguaje, bases de conocimiento y complementos para ayudarlo a crear, implementar y administrar asistentes de IA. LangBot es una plataforma de agentes y chatbot de IA de código abierto que conecta plataformas de mensajería, grandes modelos de lenguaje, bases de conocimiento y complementos para ayudarlo a crear, implementar y administrar asistentes de IA.

LangBot v4.11.9

El entorno de pruebas de Box ahora se ejecuta en hosts de Windows, los agentes pueden leer los archivos cargados a pedido y publicar los archivos que producen, y las nuevas instalaciones mantienen las habilidades y las cargas en la base de datos. Esta versión permite que Box Sandbox se ejecute en hosts de Windows; el Agente puede leer archivos cargados a pedido y publicar sus propios archivos generados; Las nuevas instalaciones guardan las habilidades y el contenido cargado en la base de datos de forma predeterminada.

Nota de actualización/Consejo de actualización: Esta versión contiene una nueva migración de base de datos (0049–0053). Haga una copia de seguridad del directorio data/ antes de actualizar (haga una copia de seguridad de la base de datos al mismo tiempo cuando utilice PostgreSQL); debe utilizar esta copia de seguridad para restaurar al degradar. Las configuraciones de almacenamiento, habilidades y caja ya implementadas en config.yaml permanecen sin cambios. Esta versión agrega las migraciones de bases de datos 0049–0053. Haga una copia de seguridad de data/ (y PostgreSQL, si se usa) antes de actualizar; retroceder necesita esa copia de seguridad. Las implementaciones existentes mantienen la configuración de almacenamiento, Skill y Box en su config.yaml.

Destacados

  • Windows host Box / Windows host sandbox: el complemento SDK 0.7.26 permite que el backend de host sea compatible con Windows: el comando se ejecuta primero con Git Bash; si no, regresa a PowerShell y todo el árbol de procesos se limpia al final. Nota: host no realiza ningún aislamiento (INSEGURO). El comando se ejecuta directamente como el usuario que ejecuta LangBot. Los usuarios que no son de confianza en el chat grupal pueden ejecutar el comando mediante la inyección de palabras. No se selecciona automáticamente y debe configurarse explícitamente en box.backend: host en config.yaml, o escribirse mediante la instalación nativa de lbctl (lbctl v0.5.14 en adelante). La habilidad no se puede ejecutar en el host Box de Windows bajo box.file_transfer_mode: network; utilice legacy cuando LangBot y Box estén en la misma máquina (lbctl escribirá automáticamente). El backend de host ahora funciona en Windows (Git Bash, recurriendo a PowerShell; se limpia todo el árbol de procesos). host no tiene aislamiento y ejecuta comandos como usuario de LangBot, por lo que los usuarios de chat grupal no rusted pueden ejecutar comandos mediante inyección rápida. Nunca se selecciona automáticamente: configure box.backend: host explícitamente o deje que lbctl (v0.5.14+) lo escriba para instalaciones nativas. Las habilidades no se pueden ejecutar en una caja host de Windows en el modo de transferencia network; cuando LangBot y Box comparten una máquina, use box.file_transfer_mode: legacy (lbctl configura esto por usted).
  • Archivos para agentes/archivos de agentes: los archivos cargados se guardan como activos de archivos con permisos. El Agente primero obtiene la referencia del archivo y luego lee el texto, la imagen o el PDF segmento por segmento a través de la herramienta cuando es necesario; Runner puede publicar el archivo generado en el destinatario designado y aún se puede descargar después de que se completa la ejecución o se reinicia el Core. Los archivos de la base de conocimientos y el complemento SDK también están conectados al mismo conjunto de recursos de archivos. Las cargas se convierten en activos de archivos autorizados: los agentes obtienen referencias y leen texto, imágenes o páginas PDF a pedido a través de herramientas, y los corredores pueden publicar archivos de salida que permanecen descargables después de que finaliza la ejecución o se reinicia el Core. Los archivos de la base de conocimientos y el complemento SDK utilizan los mismos recursos.
  • Habilidades y cargas respaldadas por bases de datos de forma predeterminada/Almacenamiento de base de datos predeterminado recién instalado: las habilidades recién instaladas (incluidas las versiones históricas) y el contenido cargado se almacenan en la base de datos de forma predeterminada. Box transfiere archivos a través de la red de forma predeterminada. Core y Box ya no necesitan compartir directorios. Cuando una implementación existente se cambia a este modo, Core importará la Skill antigua y los archivos locales antes de iniciar y abrir HTTP, que se pueden interrumpir y restaurar. Una vez completada la importación, ya no dependerá del directorio anterior. Docker Box en modo de red puede montar conjuntos de datos locales de solo lectura. Las nuevas instalaciones almacenan Skills (con su historial de versiones) y cargas en la base de datos, y Box mueve archivos a través de la red en lugar de un directorio compartido. Cuando una implementación existente cambia, Core importa habilidades antiguas y archivos locales antes de servir HTTP, probablemente. Las cajas en modo de red Docker pueden montar conjuntos de datos locales de solo lectura.
  • Operaciones API / Operación API: Se agregó la interfaz /api/v1/operations (directorio, descripción, ejecución, flujo SSE), la clave API también puede confirmar los permisos del complemento y los clientes como lbctl pueden usar la clave API para confirmar los permisos del complemento. Nuevas rutas /api/v1/operations (catalogar, describir, ejecutar, SSE) y confirmación de permisos de complementos con una clave API, para que API clients como lbctl puedan confirmar los permisos de complementos.
  • WebUI: el cuadro de diálogo de actualización muestra directamente el registro de actualización en langbot.app; la página de detalles del complemento muestra la versión instalada y se puede actualizar directamente; Después de instalar el complemento, se le solicita el siguiente paso según el tipo de componente. El cuadro de diálogo de actualización muestra release note de langbot.app; las páginas de detalles del complemento muestran la versión instalada y ofrecen actualizaciones; La instalación de un complemento sugiere el siguiente paso.
  • Inicio/Inicio: pip install ya no detecta automáticamente las dependencias que faltan al inicio, pero enumera los paquetes que faltan y solicita reinstalarlos y luego salir. LangBot ya no instala con pip los paquetes faltantes al inicio; los enumera y sale con instrucciones de reinstalación.
  • Correcciones/Correcciones: Los procesos de complemento que fallan repetidamente al iniciarse retrocederán y volverán a intentarlo y ya no actualizarán la pantalla; La edición de streaming de Telegram ignora "el mensaje no se modifica"; MulticaAgent volverá a intentarlo cuando encuentre un error temporal y las respuestas perdidas durante el reinicio se volverán a emitir; el servicio al cliente empresarial de WeChat analiza automáticamente open_kfid al enviar mensajes a external_userid desnudo; las alarmas en LangBot Cloud aún deben habilitarse manualmente; E2B La cuota del espacio de trabajo entra en vigor; El paquete del complemento excluye el directorio del entorno virtual. Los trabajadores que fallan en el complemento retroceden; La transmisión de Telegram ignora "el mensaje no se modifica"; MulticaAgent reintenta errores transitorios y recupera respuestas perdidas al reiniciar; El servicio de atención al cliente de WeCom resuelve open_kfid para objetivos external_userid básicos; las alertas permanecen activas en LangBot Cloud; Se aplican los límites del espacio de trabajo E2B; Los paquetes de complementos excluyen virtualenvs.
  • SDK：langbot-plugin 由 0.7.25 固定到 0.7.26。Pasadores centrales langbot-plugin==0.7.26.

Verificación de liberación

  • Liberar compromiso 826bf580ff42bbf10dac52203f1171f63b97b52a. Se diferencia del candidato probado dfa3c743c sólo en el número de versión; todas las comprobaciones de solicitud de extracción pasaron en el PR de liberación.
  • Antes de etiquetar, el candidato se instaló dos veces en directorios de datos nuevos y se ejecutó mediante operaciones de rutina:
    • Docker (docker compose con el tiempo de ejecución del complemento y Box, imagen creada a partir de la confirmación del candidato);
    • uvx (uvx --from <wheel> langbot, dependencias de PyPI: SDK 0.7.26, SQLAlchemy 2.1.9). Ambos aprobaron: configuración de cuenta y WebUI; Instalación en Marketplace de LocalAgent, EssentialCommands, WebSearch, LangRAG y HelloPlugin con confirmación de permiso, habilitar/deshabilitar por canalización y desinstalar; proveedor de modelos y prueba de modelos; una canalización de LocalAgent a través de HTTP Bot, incluida una llamada a una herramienta de búsqueda web; !help !cmd !func !plugin !version; ingesta y recuperación de bases de conocimientos; crear una Habilidad y hacer que el agente la utilice; y los datos, complementos, base de conocimientos y habilidades intactos después de un reinicio. Docker ejecutó un comando en un contenedor Sandbox de Box; uvx ejecutó uno a través del backend de host Box.
  • Simultaneidad: 8 conversaciones simultáneas en un modelo completadas en Docker. En uvx (SQLite), algunas conversaciones excedieron la ventana de respuesta de HTTP Bot 60 en un host de prueba muy cargado y algunas alcanzaron database is locked; v4.11.8 se comportó de la misma manera uno al lado del otro bajo la misma carga, por lo que esto no es nuevo en esta versión.
  • Windows: la rueda de lanzamiento se instaló con uvx en Windows 11 (compilación 26300, página de códigos 936, Python 3.11, Git Bash instalado; SDK 0.7.26, SQLAlchemy 2.1.9) y pasó la misma lista de verificación con un modelo simulado local, que incluye 8 conversaciones simultáneas (8/8, no database is locked). Con box.backend: host y file_transfer_mode: legacy, el agente ejecutó un comando (exec) y escribió y leyó un archivo a través del host Box de Windows. Un complemento que imprime chino y emoji mantuvo el tiempo de ejecución conectado y, con las descargas del tokenizador, se bloqueó la primera conversación de LocalAgent que respondió en 2 s (sin tiempo de espera de count_tokens).
  • Migraciones de bases de datos: las bases de datos creadas por v4.11.8 (revisión 0048), v4.10.11 (0023) y v4.10.6 (0008, antes de los espacios de trabajo) se actualizaron a esta versión tanto en SQLite como en PostgreSQL. Cada actualización llegó a la revisión 0053 y comenzó dos veces de manera limpia; no se perdió ninguna fila, se aprobaron las comprobaciones de integridad de SQLite y de clave externa, y se volvió a leer el proveedor, el modelo, el bot y la canalización inicializados. Las copias de tres bases de datos SQLite reales (revisiones 0042, 0040 y 0008, hasta 33 MB) también se actualizaron limpiamente. Los esquemas actualizados coinciden con una instalación nueva, aparte de las diferencias en los nombres de los índices en las bases de datos que comenzaron antes de 0024, que también tiene v4.11.8.
