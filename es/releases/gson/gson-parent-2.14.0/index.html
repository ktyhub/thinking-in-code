¿Qué ha cambiado?

  • Agregar adaptadores de tipo para clases java.time por @eamonnmcmanus en https://github.com/google/gson/pull/2948

    Cuando java.time API está disponible, Gson puede leer y escribir automáticamente instancias de clases como Instant y Duration. El formato que utiliza esencialmente congela la representación JSON que ReflectiveTypeAdapterFactory estableció de forma predeterminada, en función de los campos privados de las clases java.time. No es una gran representación, pero es comprensible. Cambiarlo a cualquier otro alteraría la compatibilidad con los sistemas que esperan el formato actual.

    Con este cambio, Gson ya no intenta acceder a campos privados de estas clases mediante la reflexión. Por lo tanto, ya no es necesario ejecutar --add-opens para estas clases en JDK recientes.

  • Elimina com.google.gson.graph de @eamonnmcmanus en https://github.com/google/gson/pull/2990.

    Este paquete no formaba parte de ningún artefacto publicado y dependía de los componentes internos de Gson de formas potencialmente problemáticas.

  • Validar que las cadenas que se analizan como números enteros constan de caracteres ASCII por @eamonnmcmanus en https://github.com/google/gson/pull/2995

    Anteriormente, las cadenas podían contener dígitos Unicode no ASCII y aun así analizarse como números enteros. Esto es inconsistente con la forma en que se tratan los números JSON.

  • Se corrigió la detección de claves duplicadas cuando el primer valor es nulo por @andrewstellman en https://github.com/google/gson/pull/3006

    Esto podría potencialmente romper el código que dependía del comportamiento incorrecto. Por ejemplo, esta cadena JSON se aceptaba anteriormente pero ya no será: {"foo": null, "foo": bar}.

  • Eliminar Serializable de las clases de implementación internas de Type. por @eamonnmcmanus en https://github.com/google/gson/pull/3011

    Las clases anidadas ParameterizedTypeImpl, GenericArrayTypeImpl y WildcardTypeImpl en GsonTypes son implementaciones de los tipos correspondientes (sin Impl) en java.lang.reflect. Por alguna razón, eran serializables, aunque las implementaciones de java.lang.reflect no lo son. Tener clases innecesariamente serializables podría posiblemente haber sido un problema de seguridad si fueran parte de un exploit más grande que utiliza la serialización. (No consideramos que este sea un escenario probable y no sugerimos que necesite actualizar Gson solo para obtener este cambio).

  • Añadir LegacyProtoTypeAdapterFactory. por @eamonnmcmanus en https://github.com/google/gson/pull/3014

    Esto no es parte de ningún artefacto publicado, pero puede ser útil al intentar arreglar el código que actualmente accede a las partes internas de las clases de protobuf a través de la reflexión.

  • Haga que AppendableWriter se vacíe y cierre si el objeto de delegación es compatible con @MukjepScarlet en https://github.com/google/gson/pull/2925

Otros cambios menos visibles
