Cambios más importantes

  • Se agregaron reglas predeterminadas de ProGuard/R8 (@Marcono1234, #2397, #2420; @sgjesse, #2448; @sfreilich)
    Si está utilizando ProGuard o R8 (por ejemplo, para proyectos de Android), es posible que ya no necesite ninguna configuración especial de Gson si sus clases tienen un constructor sin argumentos y usan @SerializedName para sus campos.
  • En Android, Gson ahora requiere API nivel 21 o posterior
  • Se agregó el nuevo Strictness API (@marten-voorberg y compañeros de estudios, #2437)
    Algunos de los API de Gson siguen siendo indulgentes de forma predeterminada, pero ahora puede usar los métodos recién agregados GsonBuilder#setStrictness, JsonReader#setStrictness y JsonWriter#setStrictness con Strictness.STRICT para anular este comportamiento y, en su lugar, cumplir estrictamente con la especificación JSON al analizar.
  • Nueva clase FormattingStyle para permitir configurar saltos de línea en la salida JSON (@mihnita, #2231)
    Se puede configurar usando GsonBuilder#setFormattingStyle y JsonWriter#setFormattingStyle.
  • TypeToken ya no puede capturar variables de tipo de forma predeterminada (@Marcono1234, #2376)
    Anteriormente, esta era una fuente común de problemas. La excepción recién lanzada hace referencia a un [artículo de la Guía de solución de problemas] (https://github.com/google/gson/blob/main/Troubleshooting.md#typetoken-type-variable) que explica esto con más detalle y proporciona sugerencias para actualizar el código afectado.
  • Se agregó soporte de serialización para clases locales y anónimas con un adaptador personalizado (@Marcono1234, #2498)
    Esto afecta, por ejemplo, a las implementaciones de List devueltas por bibliotecas como Guava, que se implementan como clases anónimas y que anteriormente se serializaron como null. Las clases anónimas y locales sin un adaptador personalizado seguirán serializándose como null.
  • Se agregó dependencia de com.google.errorprone:error_prone_annotations
    Su proyecto puede usar exclusiones de dependencia de Maven o Gradle para eliminar la dependencia transitiva error_prone_annotations de Gson. O si mantiene manualmente las dependencias como JAR en su proyecto, puede omitir error_prone_annotations. Y aún debería funcionar correctamente.
    Pero el propio Gson lo declara como una dependencia requerida, y si no realiza ninguna configuración personalizada, Maven o Gradle intentarán descargarlo y usarlo de forma predeterminada.
  • Muchos mensajes de excepción ahora se refieren a la Guía de solución de problemas (@Marcono1234, #2357)
    ¡Se agradecen los comentarios sobre la Guía de solución de problemas!
  • Se documentó oficialmente que es posible que los lenguajes JVM distintos de Java no sean totalmente compatibles; consulte README.
  • Garantizar que JsonElement#toString produzca una salida JSON (@Marcono1234, #2659)

Otros cambios

Corrección de errores

  • Se corrigieron resultados incorrectos de JsonPrimitive#equals para valores grandes de BigInteger (@MaicolAntali, #2311)
  • Se corrigieron resultados incorrectos de JsonPrimitive#equals para valores grandes de BigDecimal (@MaicolAntali, #2364)
  • Se corrigió que JsonReader arrojara NumberFormatException en lugar de MalformedJsonException para secuencias de escape Unicode mal formadas (@MaicolAntali, #2337)
  • Se corrigió que TypeToken#getParameterized devolviera ParameterizedType falso para tipos no genéricos (@Marcono1234, #2447)
  • Se corrigió que el adaptador de grabación Java no funcionara para la imagen nativa GraalVM (@eamonnmcmanus, #2465)
  • Se corrigió que JsonWriter#name no arrojara una excepción cuando no se estaba escribiendo ningún objeto JSON (@shivam-sehgal, #2475; @Marcono1234, #2476)
  • Se corrigió que Gson#getDelegateAdapter no funcionara correctamente para @JsonAdapter (@Marcono1234, #2435)
    Tenga en cuenta que null ya no está permitido como valor skipPast, lo que anteriormente estaba permitido pero no estaba documentado.
  • Se corrigió que GsonBuilder no rechazara los adaptadores de tipo para Object y JsonElement, cuyos adaptadores predeterminados no se pueden anular (@sachinp97; #2479).
  • Se corrigió que no se aplicaran límites al deserializar BigDecimal y BigInteger (@Marcono1234, #2510)
    Los nuevos límites evitan posibles problemas de rendimiento cuando el código de usuario utiliza números deserializados. El propio Gson se vio ni se ve afectado por estos problemas de rendimiento. Los límites deben ser lo suficientemente altos como para no causar problemas en la mayoría de los casos de uso, pero se agradecen los comentarios.
  • Se corrigió que GsonBuilder#setDateFormat no rechazara formatos de fecha no válidos (@Carpe-Wang, #2538)
  • Se corrigió que GsonBuilder#setDateFormat no rechazara estilos de fecha no válidos (@Marcono1234, #2545)
  • Se corrigió GsonBuilder#setDateFormat ignorando el estilo PREDETERMINADO parcial (@Marcono1234, #2556)
  • Se corrigió que TypeToken#isAssignableFrom arrojara AssertionError en algunos casos (@Marcono1234, #2544)
  • Se corrigieron los adaptadores de fecha que no restauraban la zona horaria después del análisis (@Carpe-Wang, #2549)
  • Se corrigió que TypeToken#equals devolviera erróneamente false para parámetros de tipo genérico iguales en algunos casos (@d-william, #2599)
  • Se corrigieron URL heredadas incorrectas en pom.xml (@Marcono1234, #2351)

Mejoras de rendimiento

  • Reducir ligeramente el uso de memoria para el adaptador basado en reflexión (@sembseth, #2325; @Marcono1234, #2440)
  • Velocidad de análisis mejorada de ToNumberPolicy#LONG_OR_DOUBLE (@ctasada, #2674)

Mantenimiento de Gson

  • Se cambiaron muchas pruebas unitarias para usar Truth en lugar de JUnit para afirmaciones (@MaicolAntali, #2299, #2304)
  • Error configurado propenso a buscar errores automáticamente al compilar (@MaicolAntali, #2308)
  • Manejo simplificado de excepciones esperadas en las pruebas (@elevne, #2454)
  • Se agregó prueba de integración para la imagen nativa GraalVM (@Marcono1234, #2466)
  • Formateé el código según la Guía de estilo de Google y configuré Spotless (@MaicolAntali, #2531, #2537)
  • Se hizo reproducible la compilación de Maven (@Marcono1234, #2543)
  • Se eliminó la clase interna DateTypeAdapter para reducir la duplicación de código (@Marcono1234, #2546)
  • Dependencias y complementos actualizados por Dependabot

repositorio GitHub

  • Se cambió el nombre de la rama predeterminada de master a main
  • Se han habilitado Discusiones GitHub
    Para preguntas, ideas, consejos...
  • Se agregó la plantilla de solicitud de extracción GitHub (@Marcono1234, #2326)
  • Se agregó verificación de compatibilidad con Android API (@Marcono1234, #2431)

Otro

  • Se agregó @CanIgnoreReturnValue según corresponda a los métodos Gson (@eamonnmcmanus, #2369)
    Esto es útil si habilita CheckReturnValue de Error Prone en su proyecto al compilar; sin embargo, Gson no lo habilita de forma predeterminada.
  • Varias mejoras en documentación y pruebas y correcciones de errores tipográficos (@False-Mask; @avimathur009; @elevne; @0o001; @Codegass; @33nya)

Muchas gracias a @ Marcono1234 por redactar estos release note.
