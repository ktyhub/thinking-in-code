TencentDB-Agente-Memoria v1.0.0

[1.0.0] - 2026-06-11

Versión oficial lanzada: Evolucionó del complemento exclusivo de OpenClaw a servicio de memoria universal para todos los Agentes. Servicio independiente de puerta de enlace completo + v2 HTTP API + TypeScript / Python SDK oficial, cualquier marco de agente puede acceder a capacidades completas de compresión de contexto y memoria multicapa.

⚠️ Cambios importantes

  • División de arquitectura cliente/servidor: el motor de memoria se divide del complemento integrado OpenClaw en un proceso de servicio de puerta de enlace independiente, y los métodos de implementación y acceso cambian.
  • Cambio de estructura de configuración: la estructura de configuración del complemento se aplana y reconstruye, y el campo gateway original se migra al anidamiento server.
  • Cambio de modo de entrada del complemento: Admite dos modos de acceso: local (ejecutándose localmente dentro del proceso, predeterminado) y client (conectándose a una puerta de enlace de memoria externa).

🚀 Servicio de puerta de enlace independiente (v2 API)

La capacidad de memoria ya no está vinculada al host de OpenClaw y se ejecuta como un servicio independiente. Proporciona lectura y escritura de memoria y administración de canalizaciones para cualquier Agente a través de HTTP v2 API:

  • Full v2 API: 14 rutas estándar que cubren todas las operaciones como memoria CRUD, actualizaciones atómicas, indexación de escenas, consulta de estado de canalización, etc.
  • Consulta de estado de canalización (/v2/pipeline/status): obtenga el estado de ejecución y el progreso de cada etapa de L1/L2/L3 en tiempo real.
  • Gestión del ciclo de vida de la instancia (/v2/instance/destroy): admite sistemas externos para crear/destruir activamente instancias de memoria.
  • Autenticación de portador opcional + lista blanca de CORS: proteja la seguridad de API expuesto al mundo exterior.
  • Verificación del cuerpo de la solicitud: aplique un límite superior de 1 MiB para evitar solicitudes anormales.

🚀 Oficial SDK

  • TypeScript SDK 1.0.0 (@tencentdb-agent-memory/memory-sdk-ts): Tipo seguro, que cubre todos los API v2, listo para usar con instalación npm.
  • Python SDK (tencentdb-agent-memory-sdk-python): instalación de rueda de pip, modo dual síncrono/asíncrono, que cubre todos los API v2.

🚀 Adaptación del marco del Agente Universal

  • Adaptación del complemento OpenClaw: admite dos modos de acceso: local (ejecutándose localmente en el proceso, predeterminado) y client (conectándose a una puerta de enlace de memoria externa). El modo local mantiene la experiencia original.
  • Adaptación del agente Hermes: adaptador memory_tencentdb_v2, compatible con el escenario multiinquilino del marco Hermes.
  • Acceso universal: cualquier agente que pueda enviar solicitudes HTTP (LangChain, AutoGPT, marco de desarrollo propio, etc.) puede acceder a través de SDK o API.

🚀 Observabilidad

  • OpenTelemetry full-link Trace: admite informes del protocolo OTLP y se puede conectar a backends como Jaeger/Grafana Tempo.
  • Integración de Langfuse: reenvía solo intervalos relacionados con LLM, adecuados para evaluar la calidad de recuperación de memoria.
  • Indicadores de evaluación de canalización: tasa de extracción L1, distribución de decisiones de deduplicación, consumo de tokens en cada etapa, retraso en la recuperación, etc.

🚀 Descargar servidor V2

  • ** Ejecutor asíncrono L1 / L1.5 / L2 **: canal de procesamiento de descarga independiente, que admite sesiones simultáneas a gran escala.
  • Procesador de compresión L3: tokenización de sirena + control de presupuesto de contexto, compresión de contexto inteligente.
  • Inyección MMD: Admite el proceso de descarga de inyección de datos multimodal.
  • Enrutamiento /v2/offload/* integrado de puerta de enlace: entrada unificada Offload API.

📦 Método de implementación

| Método | Descripción | |------|------| | Contenedor Docker | docker pull agentmemory/hermes-memory:1.0.0 | | Ejecute el código fuente directamente | node --import tsx/esm src/gateway/server.ts | | Complemento OpenClaw | Instalado a través de install-openclaw-plugin-v2.sh | | Complemento de Hermes | Complemento memory_tencentdb_v2 Python incorporado |

⬆️ Instrucciones de actualización desde 0.x

v1.0.0 y 0.x son dos líneas de versión mantenidas en paralelo:

  • 0.x (rama main): complemento integrado de OpenClaw, adecuado para escenarios autónomos livianos
  • 1.x (rama feat/server): servicio de memoria independiente, adecuado para implementación multiagente/multiframework/basada en servicios

Los motores de memoria central de los dos son los mismos (capas L0 → L3 + recuperación híbrida BM25/vectorial + memoria simbólica a corto plazo de Mermaid) y los formatos de datos son compatibles.

🐛 Arreglar (v1.0.0-beta.2 → v1.0.0)

  • Se ha mejorado el complemento Hermes install_hermes_tdai_gateway.sh: admite cambio automático de usuario raíz, migración automática de rutas antiguas, detección idempotente para omitir instalaciones repetidas
  • Optimización de la configuración de la puerta de enlace: puerto predeterminado 8420, escriba sincrónicamente dos variables de entorno /etc/profile.d/ y ~/.hermes/.env
  • Finalización del documento SDK: TypeScript / Python SDK README y ejemplo de acceso
  • Ajuste de configuración del complemento OpenClaw.json: eliminar el campo obsoleto y adaptarlo a la última versión de OpenClaw
