TencentDB-Agente-Memoria v0.3.6

[0.3.6] - 2026-05-28

🚀 Nuevas funciones

  • Recuperar control de presupuesto de contexto (#71 / #70): Se agregaron configuraciones recall.maxCharsPerMemory y recall.maxTotalRecallChars para podar entradas demasiado largas en orden fraccionario y descartar partes desbordadas para evitar que sesiones largas desplacen el contexto debido a la expansión de la memoria.
  • Las palabras de los mensajes L1/L2/L3 se adaptan según el idioma de entrada del usuario (#38): los campos de texto libre de los cuatro mensajes l1-extraction, l1-dedup, scene-extraction y persona-generation ahora están escritos en el idioma de los mensajes del usuario, sin configurar locale.
  • Incrustación de sendDimensions opcionalmente cerrada: se agregó un elemento de configuración de embedding.sendDimensions. Cuando se establece en false, se omite el campo dimensions en el cuerpo de la solicitud, que se puede conectar a modelos de dimensiones fijas como BGE-M3.
  • Autenticación de portador opcional de puerta de enlace + lista blanca de CORS: se agregaron server.apiKey / TDAI_GATEWAY_API_KEY y server.corsOrigins / TDAI_CORS_ORIGINS. Después de habilitarlas, las rutas que no son /health deben llevar un token de portador y una comparación de tiempo constante para evitar ataques de tiempo. La sincronización del cliente Hermes Python es compatible con MEMORY_TENCENTDB_GATEWAY_API_KEY.
  • Descarga del modo collect: se agregó offload.mode: "collect", que solo realiza la recopilación de datos sin activar la compresión L3. Es adecuado para escenarios de depuración o acumulación de datos puros.

🐛 Arreglar

  • La falla de L2 LLM hace que se borre scene_blocks/ (#88): restaurar automáticamente scene_blocks/ desde la última copia de seguridad cuando LLM arroja un error, diseño de falla suave.
  • El nombre del archivo de escena contiene espacios, lo que hace que la referencia de navegación de escena de Persona deje de ser válida: se agregó filename-normalizer.ts y se normalizó automáticamente el nombre del archivo en SceneExtractor.extract.
  • api.runtime.state provoca una falla en el registro para undefined (#78 / #85 / #79): agrega cadena opcional + respaldo, admite degradación de tres niveles runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw.
  • El ID de la ranura contextEngine no coincide con el nombre del complemento: cámbielo a memory-tencentdb para evitar que openclaw doctor --fix reinicie la ranura.
  • La liquidación de L1.5 nunca regresa, lo que hace que L2 se congele: agregue un tiempo de espera de 60 segundos y fuerce la liquidación automáticamente cuando la ranura del motor de contexto no esté configurada.
  • La tarea de texto independiente aún expone herramientas (#58 / #59): la lista de herramientas no se transmite en absoluto en enableTools=false.
  • L2 inicio en frío omitir actualización falsa l2LastRunTime: solo actualiza la marca de tiempo cuando realmente se ejecuta.
  • sanitizeText elimina por error caracteres que no son BMP, como emoji/CJK/Math Bold (#30 / #31): agregue la bandera u al patrón regular para que coincida solo con el sustituto aislado.
  • Truncado de emergencia bloqueado bajo el rechazo de MIN_KEEP: se agregó _emergencyTruncateOversized, eliminación forzada y limpieza de emparejamiento.
  • Consumo de tiempo acumulado de múltiples rondas de compresión agresiva: cambió de 6 rondas de cantidad total de tiktoken a un único punto de corte preciso, 615 mensajes 84s → 14s.
  • FP-HEAD-DELETE borra accidentalmente un mensaje nuevo: use FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP en su lugar, reproduzca la escena 38s→122ms.
  • El primer ensamblaje es lento: agregue un circuito previo al cortocircuito de estimación rápida del token, 29 s→1,4 s.
  • Precisión del cálculo del token: details se agrega a INTERNAL_KEYS; l3TiktokenEncoding se cambia a cl100k_base de forma predeterminada.
  • Dockerfile.hermes generó config.yaml y falta api_key (#77 / #81): escribe sincrónicamente model.api_key.
  • Múltiples problemas con el script de instalación (#18 / #19 / #20 / #54 / #55): admite la sobrescritura de HERMES_AGENT_DIR, la raíz ya no recurre a su, el entorno systemd utiliza el nodo de rutas absolutas.
  • Refuerzo de seguridad más limpio: rechazar cortes no válidos, expired/total > 80% evitar eliminación, barandilla de retención mínima.

✨ Mejoras

  • l3TiktokenEncoding se cambia a cl100k_base de forma predeterminada, coincidiendo con los segmentadores de palabras de modelo doméstico/de código abierto convencionales.
  • Descarga de degradación del registro: AGGRESSIVE / EMERGENCY, etc. se degradan a depuración y se emite WARN después de solo 10 segundos.
  • El documento Docker complementa los pasos previos de cd docker/opensource; Agrega una plantilla de preguntas/problemas de consulta.

⚠️ Cambios en elementos de configuración (compatibilidad con versiones anteriores)

| Clave | Valor predeterminado | Descripción | |---|---|---| | recall.maxCharsPerMemory | 0 | 0/No establecido = Sin recorte | | recall.maxTotalRecallChars | 0 | 0/No establecido = Sin recorte | | embedding.sendDimensions | true | false no lleva dimensions, adecuado para BGE-M3, etc. | | l3TiktokenEncoding | cl100k_base (anteriormente o200k_base) | La anulación manual solo es necesaria cuando se confía explícitamente en o200k_base |
