Papelclip v2026.1023.0

Publicado: 2026-10-23

Paperclip v2026.1023.0 incluye 200 confirmaciones, promovidas desde 2026.1012.1-beta.0. El titular es trabajo privado: una tarea o proyecto ahora se puede marcar como privado y compartir con personas y agentes designados; todos los demás no pueden abrirlo, encontrarlo en listas de tareas o realizar búsquedas, leer las transcripciones de ejecución o acceder a él a través de un complemento. En torno a eso: los agentes pueden ejecutar su propio modelo de puerta de enlace (OpenRouter, Amazon Bedrock, Google Gemini o cualquier punto final de respuestas OpenAI, mensajes antrópicos o finalización de chat), los bots de Slack se configuran a través del manifiesto API de Slack, el bot de revisión GitHub obtiene una configuración de dos pantallas y una verificación de estado real de Paperclip Review, los costos se convierten en un libro de contabilidad exacto que también muestra la suscripción mensual. tarifas y asistentes conectados pueden editar tareas, cargar archivos y configurar agentes a través de MCP. Debajo, OpenAI Dot y Pi 1.0 se unen al Runner experimental, el OpenCode nativo se transmite a medida que escribe, cada agente obtiene una identidad criptográfica persistente y las instancias inactivas dejan de sondear la base de datos cada segundo.

Cambios importantes

  • Los operadores ahora pueden editar la empresa. El rol preestablecido de Operador aumenta de una concesión (tasks:assign) a catorce: creación y configuración de agentes, habilidades, entornos, invitaciones, asignación de tareas, canales, conexiones, administración y uso de herramientas y lecturas de auditoría. Los operadores existentes obtienen las subvenciones faltantes a través de la siembra inicial normal; Se mantienen los alcances de concesión personalizados. La aprobación para unirse y la administración de permisos de miembros permanecen fuera de los ajustes preestablecidos, e invitar a un administrador ahora requiere aprobación para unirse, mientras que invitar a un propietario también requiere administración de permisos de miembros. Revise sus roles de miembro si los Operadores estuvieran destinados a ser de lectura mayoritaria. (#15377)
  • Los robots de revisión GitHub se mueven detrás de su propia configuración experimental. La entrada del catálogo Bot de revisión de código GitHub, su configuración y sus pantallas de administración aparecen solo mientras Configuración → Experimental → Bots de revisión GitHub (enableGitHubReviewBots, desactivado de forma predeterminada) está activado; Los bots existentes siguen ejecutándose mientras está apagado. Las antiguas pantallas de método de configuración y agente delegado desaparecieron, y los indicadores de ejecución automática por persona se reemplazan por filtros de inclusión/exclusión de autor (los valores people[].automaticReviews heredados se leen pero se ignoran). (#15416)
  • Los presupuestos retienen el uso sin precio de forma predeterminada. Cada política de presupuesto obtiene una configuración de uso sin precio que de forma predeterminada es block: si bien el uso de una ejecución no tiene un precio confiable, la política cuenta como en su límite hasta que el cargo se resuelve a través del flujo de ajuste de costos auditado. Establezca la política en allow para seguir ejecutándose con un uso sin precio. (#14997)

Destacados

  • Tareas y proyectos privados: marca una tarea como privada cuando la creas o haz que un proyecto sea privado con su propia lista de miembros; Se crea un proyecto personal privado para usted en el primer uso. El trabajo privado solo es legible por su usuario responsable, creador, cesionario actual, beneficiarios designados y miembros del proyecto privado, y esa regla se aplica a las listas de tareas y recuentos de tareas, búsquedas, actividades, detalles de ejecución, transcripciones, eventos y registros, documentos, archivos adjuntos, productos de trabajo y todos los complementos leídos. Dos superficies se mantienen en toda la empresa a propósito: los totales del panel y la barra lateral pueden contar el trabajo privado sin exponer un título o identificador, y la lista de ejecución de la empresa muestra una fila bloqueada para la ejecución de una tarea privada con solo los campos de agente, estado, tiempo, token y costo, por lo que la supervisión del presupuesto sigue funcionando. La privacidad llega hasta los niños; Compartir a un niño nunca expone a sus padres o hermanos. Los propietarios y administradores no ven las tareas privadas de forma predeterminada y deben solicitar ?breakGlass=true, que escribe una fila de auditoría y un aviso de advertencia sobre la tarea. El acceso de los agentes se cruza con el usuario responsable de la ejecución, por lo que la reutilización de un agente no conlleva los permisos de otra persona. (#14717, #10633, #14718)
  • Traiga su propio modelo de puerta de enlace: los conectores ganan filas para OpenRouter, Amazon Bedrock, Google Gemini y respuestas genéricas API, mensajes API, finalizaciones de chat API y puntos finales locales. Las URL, el protocolo, la región y las credenciales residen en la conexión; La página Arnés/Tiempo de ejecución del agente selecciona una Conexión compatible de un menú desplegable y el selector de modelo acepta identificaciones manuales. Codex (heredado y Runner) enruta a OpenRouter o puntos finales de Respuestas personalizados, Claude (heredado y Runner) a OpenRouter, puntos finales de Mensajes personalizados o Bedrock, y OpenCode y Hermes a OpenRouter o puntos finales de Finalización de Chat personalizados. Las conexiones de OpenRouter sin una lista de modelos explícita cargan el catálogo público de OpenRouter. (#14970, #15341)
  • Los bots de Slack se configuran solos: los nuevos borradores del bot de Slack tienen configuración predeterminada de forma automática: pegue un token de configuración de aplicación temporal, Paperclip crea la aplicación a través del manifiesto API de Slack, la instala a través de OAuth, vincula su cuenta de Slack, carga el avatar del agente y verifica la entrega en un asistente de cuatro pantallas sin Slack CLI involucrado. (#15413). Una nueva configuración Requerir mención evita que las respuestas de los hilos activen al agente sin una mención explícita (#15612); un seguimiento enviado después de una Slack Stop inicia un nuevo giro en lugar de detenerse (#15737); y los agentes de Slack ahora conocen el comando de barra diagonal guardado que las personas usan para vincular sus cuentas, vincular cada tarea que crean e informar resultados y revisar solicitudes en el hilo de origen (#15576, #15579, #15611).
  • Un robot de revisión de GitHub de dos pantallas: la configuración ahora es Elegir agente y luego Conectar GitHub en una cuenta u organización personal; GitHub solicita consentimiento de creación e instalación, y Paperclip almacena los secretos de la aplicación localmente, importa el acceso al repositorio y verifica la entrega. Cada solicitud aceptada recibe un comentario de progreso propiedad de la aplicación editable y las evaluaciones de revisión publican una RevisiónPaperclip para la confirmación revisada con una puntuación de aprobación configurable (1 a 5) que puede requerir la protección de sucursales. Una instancia autohospedada necesita una aprobación de Paperclip Cloud antes de su primera conexión GitHub administrada, porque Cloud aloja la devolución de llamada fija de OAuth y la bandeja de entrada del webhook firmado; Los tokens están sellados en su instancia. (#15416)
  • Costos que puede conciliar: la contabilidad ahora es un libro de contabilidad exacto y duradero: los recibos de uso se sincronizan y se reproducen después de fallas, los reintentos liquidan un cargo, los montos mantienen centavos decimales y cada evento se marca como reportado, estimado o sin precio en lugar de cero silenciosamente (#14991, #14997). La página Costos informa la tarifa mensual de cada suscripción a ChatGPT o Claude conectada una vez junto con el gasto de API, le permite ingresar el precio real y mantiene los planes ambiguos sin precio (#15634); las lecturas de cuota se limitan a cuentas de empresa autorizadas (#14994); las brechas de costos se enumeran por agente con enlaces a las ejecuciones afectadas, se registra el modelo que el tiempo de ejecución realmente seleccionó y aparece un reintento solo cuando la evidencia guardada está lista (#15948); y las brechas históricas de precios se muestran como una nota neutral debajo de los totales en lugar de un error rojo (#15459).
  • Asistentes que pueden hacer más a través de MCP: un Claude Code, Codex u otro asistente de MCP conectado ahora puede editar tareas, finalizarlas o bloquearlas, escribir documentos y revisiones, registrar entregables, cargar archivos a través de tickets que vencen y, con un alcance de configuración consentido por separado, administrar configuraciones e instrucciones del agente, proyectos, repositorios y habilidades (#15380). Las conexiones reciben el nombre del propietario y client ("conexión del Codex de Dotta") con el avatar de la persona que autoriza, las filas revocadas desaparecen y la invitación copiada es más corta (#15411).
  • Dieciséis aplicaciones más en el catálogo: Gauge (#15596), Superagent (#15394), Búsqueda web Telem.AI (#15379), Enterpret (#13906), Calendly, Exa, Firecrawl, GSC Wizard, Parallel Search, Tavily y Windsor.ai (#15621) y Bitly, Context7, Hugging Face y Resend (#15686) se unen como conexiones MCP alojadas verificadas. El inicio de sesión de Sentry descubre OAuth a través de sus metadatos de recursos MCP, por lo que la configuración ya no solicita un ID y un secreto de client (#15837), y las concesiones de OAuth ahora registran si cada alcance proviene del proveedor o de la solicitud de Paperclip (#14059).
  • Nuevos proveedores de Runner: OpenAI Dot se une como una opción de agente experimental independiente: empareje su Dot con un código de un solo uso y Runner entrega tareas a través de eventos MCP mientras Dot usa sus propias herramientas e informa (#15402, #15414, #15581, #15734). Pi 1.0 se ejecuta a través del Runner experimental con selección explícita de proveedor y modelo (#14921), y la integración de Cursor Runner se consolida en el comportamiento de recuperación de la línea principal con una ruta de instalación pública (#15075).
  • Codex y OpenCode que recién comienzan: Native Codex usa el Codex CLI instalado y acepta versiones utilizables más antiguas o más nuevas, por lo que una instalación limpia de npm ya no necesita un comando global (#15555); un modelo para el que el Codex CLI del sandbox es demasiado antiguo se cambia por uno compatible con una advertencia visible en lugar de fallar en cada turno (#15399, #15519); las ejecuciones guardadas sobreviven a las actualizaciones del servidor (#15518); y las variables de entorno de tareas llegan a turnos y comandos de herramientas posteriores (#15451). OpenCode nativo transmite texto a medida que llega (#15708), se inicia sin el script posterior a la instalación que los administradores de paquetes omiten (#15702) y selecciona los activos de Linux incluidos para ejecuciones remotas sin anulaciones de rutas (#15721).
  • Informes que puede abrir en la tarea: los archivos adjuntos HTML y los archivos del espacio de trabajo .html se representan en un entorno limitado de origen opaco con controles de visualización y descarga de código fuente (#15447), y los archivos CSV se abren como tablas con números de fila, encabezados fijos y recuentos de registros (#15445).
  • Procedencia y esperas de tareas más claras: una tarea de seguimiento que crea un agente mientras trabaja en una tarea ahora tiene como valor predeterminado esa tarea como principal, y la página de la tarea muestra "Creada a partir de <tarea> por <agente>" (#15762); los agentes nativos pueden programar su propio monitor de tareas de una sola vez y ceder hasta que se active (#15446); la tarjeta del monitor recibe una X con una confirmación (#15735); y una solicitud de extracción guardada permanece visible en Propiedades con su solicitud de revisión y una acción Verificar estado incluso cuando falla la búsqueda del proveedor (#15375).
  • Su agente principal: cada persona obtiene un agente principal por empresa, que se muestra con una corona en la lista y se utiliza como respaldo para nuevas tareas y chat cuando no hay una opción reciente; el primer agente que cree se convierte en principal automáticamente y se puede cambiar en el perfil del agente (#15470).
  • Modelos de decisión de la empresa y respuestas rápidas: la configuración de la empresa puede vincular una conexión OpenAI u OpenRouter API compartida para decisiones de modelos escritos pequeños, con comprobaciones de permisos, reservas de presupuesto y un historial de Costos → Decisiones (#15473). Además, Respuestas rápidas experimentales publica un breve comentario de reconocimiento a los tres segundos de un mensaje humano mientras el agente inicia su ejecución normal, en tareas, Chat del agente y subprocesos de Slack y GitHub (#15748).

Correcciones

  • Espacios de trabajo y entornos limitados: una falla transitoria en la copia de seguridad del entorno limitado se reintenta hasta tres veces antes de que la tarea se retenga para su reparación, y las retenciones restantes explican lo que sucedió en lenguaje sencillo (#15920); una zona de pruebas remota cuya copia requerida falló se mantiene, con sus archivos, detrás de una decisión de reparación explícita en lugar de eliminarse mediante limpieza (#15479, #15790); el apagado del servidor espera la exportación del espacio de trabajo de un adaptador heredado antes de liberar su arrendamiento de espacio aislado (#15857); un árbol de trabajo guardado reutilizado mantiene su repositorio original cuando cambia la configuración del proyecto (#15528); un resultado nativo aceptado ya no se confunde con trabajo perdido por parte del reaper huérfano después de un reinicio (#15718); OpenCode se ejecuta en el espacio de trabajo realizado a través de --dir (#11438); Las sesiones de Daytona OpenCode mantienen sus plazos (#15905); y los tiempos de espera de OpenCode ya no indican que la fecha límite configurada expiró (#15789).
  • Ejecuciones, recuperación y preguntas: un reintento ya no se quema mientras el entorno de una ejecución detenida todavía se está limpiando, y las instrucciones de reparación establecidas dejan de reaparecer en reactivaciones posteriores (#15463); una espera de revisión cuya reparación automática tampoco deja rastro ahora registra una decisión de la junta en lugar de sentarse en silencio (#15764); un padre se despierta nuevamente cuando un niño termina las revisiones solicitadas (#15372); Las ejecuciones nativas se reanudan limpiamente después de las decisiones de aprobación de la conexión y se conserva el uso final (#15471, #15420, #15514); una solicitud de herramienta pendiente caduca por sí sola cuando el usuario ya ha conectado el servicio en Aplicaciones (#15856); los agentes dejan de volver a hacer preguntas que pasaron al historial de noticias en tiempo real (#15392); archivar una tarea durante su finalización ya no genera bloqueos (#15615); y una política de tareas con un monitor pero sin etapas ya no bloquea la página de tareas (#15593).
  • Adaptadores: las sesiones de Claude CLI se reanudan en copias de archivos del agente por ejecución (#15437); Hermes obtiene instrucciones administradas a través de la superposición de su sistema en lugar de una copia en cada turno de usuario reanudado (#15439); y a los agentes externos como Dot se les dice que utilicen sus propias herramientas cuando falta una aplicación Paperclip (#15734).
  • Conexiones y MCP: una respuesta de MCP de gran tamaño o con formato incorrecto falla solo en esa llamada en lugar de bloquear toda la conexión en un estado de error (#15462); las devoluciones de llamadas remotas de MCP mantienen una selección de agente vacía guardada explícitamente, el intercambio de tokens envía Accept: application/json y los borradores de proveedor oculto guardados se reanudan desde Finalizar la configuración (#15686); Airtable, Calendly y otros proveedores verificados obtienen las correcciones de registro y formulario que se encuentran en las pruebas en vivo (#15621); y la barra lateral mantiene sus últimos elementos de complemento en silencio cuando no se puede acceder al servidor (#15588).

Mejoras

  • La contratación, aprobación, pausa, reanudación y terminación se ejecutan a través de un ciclo de vida duradero del agente con estados explícitos: las contrataciones propuestas permanecen pendientes hasta la aprobación, las contrataciones aprobadas se preparan y se verifica su configuración de arnés antes de trabajar, los complementos requeridos reciben devoluciones de llamada en cada paso y la página del agente muestra el progreso del ciclo de vida con una acción de reintento (#15631, #15391); los complementos pueden consumir un diario duradero del ciclo de vida de los recursos con reconocimientos, iniciado con una base única de agentes y proyectos existentes, y archivar y restaurar proyectos, ahora escribir eventos del diario (#15343, #15371).
  • Cada agente obtiene un par de claves Ed25519 persistente, creado durante la contratación o en su siguiente ejecución administrada, cifrado en reposo y entregado a procesos administrados como PAPERCLIP_AGENT_KEY_ID, PAPERCLIP_AGENT_PUBLIC_KEY y PAPERCLIP_AGENT_PRIVATE_KEY; la clave pública aparece en la descripción general del agente (#15352).
  • Los agentes pueden presentar quejas y sugerencias sobre sus herramientas en la tabla agent_commentary de la instancia a través de las nuevas habilidades complain y suggestion-box o las herramientas nativas submit_complaint y submit_suggestion, manteniendo esos comentarios fuera de los subprocesos de tareas (#15367).
  • Las instancias inactivas se silencian: entrega de chat, acción del proveedor, sincronización de Slack, correo electrónico, limpieza del uso del navegador y cinco colas de entrega del servidor ahora se activan a partir de escrituras comprometidas y fechas límite conocidas en lugar de escanear la base de datos cada segundo o tres (#15625, #15750, #15757, #15802, #15808, #15822); los hosts que estacionan instancias inactivas obtienen un informe de seguridad durante el período de inactividad que delimita el trabajo aceptado, drena a los trabajadores de complementos y trata los inicios de sesión finalizados, los reintentos consumidos y el historial de entrega verificado como historial en lugar de trabajo pendiente (#15522, #15599, #15761, #15851, #15897, #15907), con un punto de control de respaldo final opcional antes de dormir (#15629).
  • Las notificaciones de tareas muestran el nombre y el avatar del actor y ocultan sus propias acciones (#15695); los comentarios de otras personas en el chat de tareas aparecen a la izquierda con su nombre y avatar, y solo los tuyos están a la derecha en azul (#15494); un agente bloqueado por una conexión de IA que su usuario responsable no puede usar muestra un error ampliado que nombra el agente y la conexión con un enlace a su configuración de IA (#15741); y un compañero de equipo sin la cuenta personal de IA requerida del agente puede conectar la suya desde dentro del chat y reanudar el mensaje (#15376).
  • El compositor de tareas mantiene estable la etiqueta de su modelo mientras el control deslizante de esfuerzo se mueve y el control deslizante es más grande (#15444), los selectores anidados se desplazan con la rueda y tocan (#15374), el selector de proyectos siempre ofrece Sin proyecto (#15382), las descripciones de rutina mantienen pegados de bloques de código en el bloque de código y obtienen un control de copia (#15773), las tarjetas de confirmación apilan el mensaje encima de la píldora de destino y ocultan claves de máquina sin etiquetar (#15895), las tarjetas de conexión de chat y recuperación comparten una superficie (#15771), el selector de chat o herramientas de Slack obtiene íconos (#15574), el filtro del espacio de trabajo abandona la tarea y menús de filtro de bandeja de entrada (#15788), y los botones de estrella y salir abandonan el índice de agentes (#15400).
  • Las tareas cuya rama inicial no existe en el repositorio muestran una tarjeta de reparación de rama que ofrece la rama predeterminada del control remoto o una rama escrita y reintenta a través de las puertas de admisión normales (#15726); una referencia GitHub que las credenciales de la instancia no pueden ver se informa como inaccesible y se vuelve a verificar en lugar de congelarse como "No encontrada" (#15906); y la habilidad Paperclip incluye su propio asistente de actualización de problemas y cumple con el pago del arnés en lugar de exigir un segundo (#15554, #15548).
  • Los trabajos del espacio de trabajo que salen de un valor distinto de cero devuelven 422 workspace_job_failed con la salida propia del trabajo en lugar de 500 (#15941); los lanzadores de código fuente personalizados obtienen el transporte Runner WebSocket nativo del constructor del servidor HTTP compartido (#15682); una conexión local Hermes Gateway rechazada explica qué host verificar (#15520); y el error de modelo no disponible de pi-local ya no volca el catálogo de modelos (#13628).
  • Los informes de fallas contienen evidencia limitada de tiempos de espera de adquisición de Daytona y estado del proveedor, resolución de referencia base del espacio de trabajo, errores de transferencia y sincronización de la zona de pruebas, pérdida de procesos huérfanos, marcos de terminales de puente ACP, inspección del árbol de trabajo de Git y rechazos de navegadores sin pila (#15946, #15736, #15719, #15637, #15481, #15475, #15478, #15525, #15940), mientras que bloqueadores de configuración probados, como un secreto de usuario faltante, una cuenta de IA no elegida, un una credencial no compartida con el usuario responsable, un proyecto de directorio local con una política de árbol de trabajo o una interrupción de un servicio externo permanecen fuera de Sentry (#15472, #15618, #15714, #15521, #15590).

Guía de actualización

  • Migraciones 0306–0333 ejecutadas durante la actualización: 0306 permite google en las comprobaciones del proveedor predeterminado de la cuenta AI; 0307 reescribe la restricción de acción del evento del ciclo de vida; 0308 agrega agent_identity_keys; 0309 agrega plugin_lifecycle_acknowledgments, indexa el diario del ciclo de vida y genera un evento de referencia único por agente y proyecto existente; 0310 agrega agent_commentary; 0311 agrega tablas de tickets de archivo y carga de archivos adjuntos de MCP; 0312 agrega tablas de recibos contables, reservas, ajustes, facturas e instantáneas de proveedores, amplía las columnas de costos a numeric y agrega la política de uso sin precio del presupuesto (valor predeterminado block); 0313 agrega issue_access_grants y project_access_members, agrega visibility a tareas y proyectos (open predeterminado) y rellena los bordes principales de privacidad y ejecuta enlaces en lotes de 1000 filas; 0314 vincula imágenes históricas en borrador en línea a su primera tarea; 0315 agrega user_company_preferences y reemplaza a un agente principal de la historia; 0316 agrega tablas de modelos de decisión; 0317 agrega tablas de asignaciones, buzones de correo y enlaces OpenAI Dot; 0318 agrega chat_slack_registrations; 0319 hace que los tokens de actualización del agente Dot no caduquen; 0320 agrega columnas del ciclo de vida del agente y deriva lifecycle_state del estado actual de cada agente; 0321 agrega chat_endpoints.require_at_mention; 0322 agrega cuentas de suscripción de IA y tablas de precios; 0323 agrega columnas de propietario de registro GitHub; 0324–0330 agrega las tablas de sesiones de voz experimentales; 0331 agrega tablas de respuesta rápida y issue_comments.origin; 0332 agrega un índice de historial de preguntas al mismo tiempo; 0333 agrega índices de calidad de datos de costos. 0313 y 0314 se ejecutan fuera de una sola transacción y confirman cada lote, por lo que una actualización interrumpida los deja pendientes y seguros para volver a ejecutarlos; Es de esperar que tarden más en instancias con historiales de ejecución extensos.
  • Nuevas variables de entorno, no se requiere ninguna: PAPERCLIP_ISSUE_PRIVACY_MODE (enforce predeterminado; shadow registra decisiones de denegación sin aplicarlas, off deshabilita el predicado) (#10633); PAPERCLIP_DB_BACKUP_IDLE_CHECKPOINT_ENABLED=1 opta por una instancia con copias de seguridad automáticas para que realice una copia de seguridad final verificada antes del estado de inactividad (desactivado de forma predeterminada) (#15629); PAPERCLIP_RESPONSIBLE_USER_AUTHZ_CACHE_TTL_MS limita la instantánea de permisos del usuario responsable (5000 predeterminado) (#10633).
  • Nuevas configuraciones experimentales, todas desactivadas de forma predeterminada: Bots de revisión GitHub (enableGitHubReviewBots) muestra la configuración y administración del bot GitHub (#15416); OpenAI Dot (enableOpenAiDot) agrega Dot como opción de agente y requiere Conexiones de asistente (MCP), inicio de sesión autenticado y un HTTPS PAPERCLIP_PUBLIC_URL (#15414); Respuestas rápidas experimentales (enableFastResponses) revela Configuración de la empresa → Conexiones y permite comentarios de reconocimiento (#15748). La configuración del modelo de decisión se encuentra en Configuración de la empresa → General hasta que se activen las respuestas rápidas (#15473).
  • Miembros de operadores de revisión (#15377): los operadores ahora cuentan con subvenciones de edición, invitación, conexión, herramientas y auditoría de la empresa después de la inicialización. Degradar a los miembros que no deben configurar agentes ni conectar cuentas.
  • Políticas de presupuesto y uso sin precio (#14997): las políticas existentes obtienen unpricedUsagePolicy: block. Si sus agentes trabajan con proveedores cuyos precios Paperclip no puede determinar, establezca la política en allow o resuelva eventos sin precio a través del flujo de ajuste de costos para que el presupuesto no los retenga.
  • Adaptadores personalizados y procesos administrados (#15352): las ejecuciones administradas ahora reciben PAPERCLIP_AGENT_KEY_ID, PAPERCLIP_AGENT_PUBLIC_KEY y PAPERCLIP_AGENT_PRIVATE_KEY; los valores de clave son cadenas PEM de varias líneas y la clave privada no debe registrarse. La clave de ajuste es PAPERCLIP_SECRETS_MASTER_KEY o el archivo de clave maestra de secretos locales; una clave maestra incorrecta falla la ejecución en lugar de regenerar el par de claves.
  • Llamantes de tareas privadas (#10633): lecturas directas de una tarea privada por parte de un no miembro que devuelve 404; los propietarios y administradores deben aprobar ?breakGlass=true para una lectura de emergencia auditada; Los complementos son principios que no son miembros y no ven contenido privado.
  • Borradores de Slack y GitHub: los borradores del bot de Slack existentes sin un método de configuración guardado permanecen en la configuración manual (#15413); Los bots GitHub existentes, los webhooks directos y la recuperación manual de aplicaciones existentes siguen funcionando, pero sus configuraciones están ocultas hasta que se habiliten los bots de revisión GitHub (#15416).
  • Los pasadores del arnés no se modifican para Codex, Claude y OpenCode. Native Codex ahora prefiere el Codex CLI instalado con el paquete del servidor y tolera la variación de versiones; una imagen de espacio aislado cuyo Codex CLI es demasiado antiguo para el modelo seleccionado se cambia a un modelo compatible con una advertencia (#15555, #15519).
  • Ninguna otra configuración o cambios de API requieren acción.
