#JecgBoot v3.9.3

Registro de actualización

Actualización importante: el backend está completamente adaptado a Spring Boot 4, el frontend finalmente se actualiza a Vite 8 y las dependencias centrales como Pinia 3, Vue Router 5, Shiro 3.0, MyBatis-Plus 3.5.16, Nacos 3.2.2, XXL-JOB 3.4.2, etc. se actualizan simultáneamente; El código bajo de IA ingresa al segmento de escenario 2.0, admite sistemas de generación de lenguaje natural, formularios, procesos, informes y pantallas grandes, y al mismo tiempo lanzó JimuChatBI 1.0; Además, también completó informes básicos, inicio del microservicio Docker, rendimiento de inicialización de la base de datos y optimización de la carga de dependencias pesadas del front-end, y reparó problemas como eco de selección múltiple, PopupDict, llamadas de IA, mejora de JS y vulnerabilidades SSRF almacenadas, mejorando aún más la seguridad, la estabilidad y la experiencia de desarrollo del sistema.

Actualización de arquitectura y dependencia

  • La arquitectura backend se actualizó a Spring Boot 4 y se completó la adaptación de compatibilidad relevante.
  • La herramienta de compilación de front-end finalmente se actualizó a Vite 8 y el complemento del tema se migró a local.
  • Actualizar Pinia 3, Vue Router 5.
  • Actualice Jeecg Starter a 3.9.4.
  • Actualice Shiro a 3.0.0 y adáptese a la nueva versión de shiro-redis.
  • Actualice MyBatis-Plus a dependencias básicas como 3.5.16 y Druid.
  • Actualice XXL-JOB a 3.4.2.
  • Actualice el panel Sentinel a 1.8.10.
  • Actualice Nacos a 3.2.2, agregue la configuración del puerto de administración.
  • Actualice LangChain4j a 1.17.2.
  • Actualizar dependencias como Apache Tika, CommonMark, AutoPoi, Commons IO y MinIO.
  • Retire lodash y use lodash-es uniformemente.
  • Informes de bloques de construcción actualizados y componentes de pantalla grande para que sean compatibles con Spring Boot 4 y admitan la nueva versión del asistente AI.

Inteligencia artificial y capacidades de código bajo

  • Las capacidades de IA de código bajo se han actualizado a 2.0, lo que admite la generación de sistemas, formularios, procesos, informes y pantallas grandes en lenguaje natural.
  • Se lanzó JimuChatBI 1.0, que proporciona capacidades de interrogación numérica inteligente Chat2BI conversacional de código abierto.
  • Proporcionar AI Flow adaptado a Spring Boot 4.
  • El modelo de IA predeterminado se ajusta a DeepSeek V4 Pro.
  • Se corrigió la anomalía en la llamada del modelo después de la búsqueda en línea de DeepSeek V4 Flash.
  • Se solucionó el problema por el cual las operaciones comerciales de acoplamiento de chat de IA no estaban disponibles.
  • Se solucionó el problema por el cual la página de diseño del proceso de IA no se podía mostrar correctamente.

Correcciones de funciones

  • Se solucionó el problema por el cual los ecos de selección múltiple de la posición del usuario del sistema se mostraban como 1,2,3 (#9420).
  • Se solucionó el problema de que el componente PopupDict no se verificaba correctamente al abrirlo por segunda vez.
  • Se solucionó el problema de la ejecución repetida de funciones en updateSchema (#9612).
  • Se solucionó un problema que causaba excepciones de página después de errores de configuración del código de mejora de JS (#9699).
  • Se corrigió un error causado por la configuración predeterminada del modelo AI cuando se inicia Docker (#9635).
  • Se solucionó el problema de que tinycolor2 no se puede analizar cuando se inicia la interfaz (#9698).
  • Se solucionó el problema de la pantalla en blanco y la carga lenta cuando el entorno de desarrollo Vite 8 accede a páginas muy dependientes como Tinymce, ECharts, VXE-Table, etc. por primera vez (#9782).
  • Elimina la advertencia de compatibilidad al iniciar el servidor de desarrollo Vite 8.
  • Se corrigieron problemas de compatibilidad como Swagger, pruebas unitarias y conflictos de dependencia de Redis después de la actualización de Spring Boot 4.

Correcciones de seguridad

  • Se corrigió la vulnerabilidad SSRF almacenada en WordUtil.addImage (CWE-918).

Implementación y optimización del rendimiento

  • Proporcionar script de inicio rápido de microservicio.
  • Optimice el proceso de inicio del microservicio Docker, la puerta de enlace espera a que Nacos esté listo antes de comenzar.
  • Se ajustó la secuencia de inicio de la consola Nacos y la Web, y se mejoró la exposición del puerto de administración.
  • Optimice la configuración de Nginx de front-end única y admita la resolución dinámica de la dirección de back-end a través del DNS integrado de Docker.
  • Optimice la primera inicialización de la base de datos, adopte el envío por lotes y reduzca los registros no válidos y mejore la velocidad de inicialización.
  • Se solucionó el problema por el cual la puerta de enlace y el front-end no podían acceder a la instancia del servicio cuando la inicialización demoraba mucho tiempo.
  • Optimice la configuración de puertos para reducir el riesgo de conflictos de puertos en el entorno Docker.
