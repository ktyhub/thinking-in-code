agno v3.1.0

Menor Publicado1 oct 2026 Fuenteagno-agi/agno original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

año v3.1.0

Nuevas características

  • Administración/autorización de usuarios (RBAC): un nuevo paquete agno.os.authz agrega control de acceso basado en roles a AgentOS: un almacén de roles, una política de alcance, un registro de auditoría, un directorio de usuarios y un enrutador de administración, con motores de autorización conectables (un motor nativo más un motor detallado fga ). Se ampliaron los alcances y el middleware de autenticación para aplicarlo.
  • Sistema de archivos AgentOS: un nuevo sistema de archivos agno.fs (DbFileSystem) con rutas /filesystem dedicadas (listar/leer/administrar archivos) respaldadas por una tabla agno_fs .
  • Actualizaciones de configuración/autenticación de MCP: configuración del servidor MCP actualizada y manejo de autenticación de MCP integrado.
  • AIMLAPITools: nuevo conjunto de herramientas para imágenes, videos, voz y transcripción a través de AI/ML API.

⚠️ Cambios importantes

  • Nueva clave de la tabla del sistema de archivos (agno_fs): v3.1 clave la tabla del sistema de archivos con (namespace, user_id, path), donde user_id es la partición del usuario ("" para la partición compartida/sin usuario). Una tabla creada en una versión anterior se rechaza con SchemaOutdatedError hasta que se actualiza; la nueva clave nunca se ejecuta automáticamente. Actualice una vez, con la aplicación detenida, usando el script para su base de datos (#10530): Esto solo te afecta si usas DbFileSystem. La tabla es administrada por DbFileSystem (su propio esquema, compilable a partir de un db_url básico), por lo que deliberadamente no forma parte de MigrationManager.
python libs/agno/migrations/migrate_filesystem_postgres.py   # PostgreSQL
python libs/agno/migrations/migrate_filesystem_sqlite.py     # SQLite
  • Las herramientas predeterminadas y de ciclo de vida de MCP ahora están habilitadas: MCPConfig(tools=[...]) ahora publica exactamente las herramientas que usted enumera; tanto default_tools como lifecycle_tools tienen el valor predeterminado False. Anteriormente, una configuración tools=[...] también servía para las herramientas predeterminadas integradas (y el ciclo de vida continue_run / cancel_run).

Corrección de errores

  • HITL: continuar una ejecución pausada con background + stream ya no duplica la ejecución pausada en su propio historial.
  • OpenAIResponses: recupera solicitudes cuando la respuesta encadenada (anterior) desaparece.
  • DB: una eliminación asíncrona que falló ya no se informa como una ejecución que no estaba allí ; se distinguen los dos casos.
  • Salida estructurada: no falla cuando un fragmento JSON proporciona un escalar antes de una lista.
  • Resultados de la herramienta Python: distingue los resultados valorados None de las variables faltantes.
  • Fragmento: rechaza una superposición que no sea menor que el tamaño del fragmento.
  • Lectores CSV: manejan finales de registros CR (\r).
  • CsvTools: respeta los límites explícitos de fila cero.
  • Herramientas de comando de Shell/espacio de trabajo: respetan un cero explícito tail.
  • GeminiTools: almacena bytes de vídeo sin procesar en el artefacto generate_video .
  • GithubTools: crear enlaces de sucursales desde la URL web del repositorio (#10509); get_file_content conserva texto UTF-8 no ASCII válido
  • LocalFileSystemTools: lee y escribe archivos locales como UTF-8.
  • PubMed: preserva los metadatos para resúmenes breves.
  • Citas de Claude: conserva los títulos de los documentos que admiten valores NULL.
