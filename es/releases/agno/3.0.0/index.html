agno v3.0.0

Mayor Publicado24 ago 2026 Fuenteagno-agi/agno original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

año v3.0.0

⚠️ Última versión. Se requiere una migración de la base de datos antes de que v3.0 atienda el tráfico. Lea primero la Guía de migración v3 y consulte la v3.0 Changelog completa para cada cambio.

Nuevas funciones

  • Descarga de resultados de herramientas: Agent(offload_tool_results=True) / Team(...) escribe cualquier resultado de herramienta de más de 16 000 caracteres en AgentFS y deja un sobre corto (vista previa, tamaño, result_id) en el mensaje; el agente obtiene read_result / search_result (+ async) para recuperar el resto. No hay llamada de modelo en la ruta de escritura. Sintonízalo a través de ResultStore(threshold_chars=..., ttl_seconds=...). (#9436, #9684)
  • Descarga de medios: media_storage=S3MediaStorage(bucket=...) en un agente/equipo/flujo de trabajo carga imágenes, audio, vídeo y archivos al disco local, S3 o GCS antes de la persistencia; la fila mantiene un pequeño MediaReference en lugar de base64 (un JPEG de 113 KB cae de ~151 000 caracteres a 2897). Ningún cambio de esquema. (#9340) Documentos
  • CodeMode: CodeMode(tools=[...]) intercambia un esquema de herramienta amplio por un kernel IPython programable que persiste durante una sesión: el modelo escribe Python y llama a las herramientas como identificadores en espera, componiéndolos (variables, bucles, ayudantes) sin recorrer la transcripción.
  • FinanceTools: un conjunto de herramientas financieras unificadas con proveedores de datos intercambiables.
  • Modelo RampRouter: Nuevo proveedor de modelo para Ramp Router (router.com).
  • SuperGrok OAuth: autenticación de código de dispositivo para el modelo xAI.

Base de datos

  • Las ejecuciones tienen su propia tabla: cada ejecución es una fila en agno_runs con columnas reales (session_id, run_type, agent_id, team_id, workflow_id, user_id, parent_run_id, status, run_index) + carga útil de JSON. Lleva la amplificación de escritura de sesión de O(N²) a O(N) y elimina el límite de tamaño de elemento de DynamoDB/Firestore. Las rutas de sesión de session.get_messages(), get_chat_history(), db.get_session() y AgentOS no se modifican (las ejecuciones se vuelven a adjuntar al leer). (#8350)
    • API de ejecución directa: db.get_run(), db.get_runs(session_id=..., status=..., limit=..., page=...), db.upsert_run(), db.delete_run(), db.delete_runs() (sincronización + asíncrono); db.get_session(runs_limit=N) y db.get_sessions(include_runs=False). (#8350)
    • Migración de una línea: MigrationManager(db).up() crea el almacén de ejecuciones y copia las ejecuciones heredadas, de forma no destructiva e idempotente, en 12 backends sincronizados + 4 asíncronos; Las bases de datos no migradas aún funcionan (lee la tabla de ejecuciones de combinación con el blob heredado). Versiones de esquema rastreadas en cada adaptador. (#8350)
    • Errores escritos en base de datos obsoleta: MigrationRequiredError / SchemaMismatchError nombra ambas soluciones; AgentOS lleva error_id: "migration_required_error" en el cuerpo de JSON. (#9669, #9631)
    • Tres tablas nuevas: agno_runs, agno_jobs (cola de fondo duradera), agno_tool_results (índice de descarga): todas creadas automáticamente.

Aislamiento por usuario

  • Se extiende más allá de las sesiones a métricas, programaciones, evaluaciones, conocimientos, componentes, memoria de entidades y 17 bases de datos vectoriales. Las métricas se agregan por usuario por día; Los componentes/conocimientos sin propietario se comparten (legibles para todos, editables por el administrador), por lo que habilitar el aislamiento no constituye 404 bloques de construcción previos al aislamiento. (#8245, #8262)

AgentOS y Estudio

  • Ejecución duradera en segundo plano: AgentOS(queue=QueueConfig(durable=True)): las ejecuciones aceptadas son filas confirmadas que sobreviven a fallos, reinicios o implementaciones, ejecutadas por cualquier réplica. Simultaneidad limitada (predeterminada 32, AGNO_BACKGROUND_MAX_CONCURRENCY), cancelable mientras está en cola, Idempotency-Key desduplicación, 429 en cola llena. Superficie REST de cola (GET /queue/jobs, .../{job_id}, POST .../requeue, GET /queue/stats). Redis es coordinación opcional, nunca verdad. (#9079, #9504)
  • Studio 3.0 — catálogo gobernado: create_* escribe un BORRADOR que no sirve a nadie hasta publish_component; comparar y configurar guardias (tipo 409), eliminaciones desechadas, archivar/restaurar, seguimiento de dependientes. StudioTools devuelve un sobre legible por máquina ({ok, status, data, error{...}, warnings}) en ~31 herramientas. (#9604)

Herramientas

  • Herramientas de generación de vídeo MiniMax. (#9529)
  • Los kits de herramientas ahora tienen un id estable utilizado por AgentOS para hacer referencia a las herramientas.

Actualizaciones de modelo

  • Cerebras/CerebrasOpenAI por defecto gpt-oss-120b (antes llama-4-scout-17b-16e-instruct). (#9244)
  • Gemini valores predeterminados actualizados a 3.7 Flash. (#9666)
  • Groq: se reemplazó llama-3.3-70b-versatile obsoleto por openai/gpt-oss-120b. (#9588)
  • OpenAI: reasoning_effort, reasoning_summary, service_tier, verbosity aceptan el conjunto de valores completo de API (tipos ampliados; sin interrupciones de llamada).
  • Claude funciona con anthropic 1.0.0 (#9686): actualización compatible con SDK para los modelos Claude

⚠️ Cambios importantes

Todos los usuarios de 2.x deben leer esto. Se requiere una migración de la base de datos antes de que v3.0 atienda el tráfico.

Almacenamiento y migraciones

  • Las ejecuciones ya no son un blob JSON en la tabla de sesiones; residen en agno_runs. Ejecute MigrationManager(db).up() (o AgentOS POST /databases/all/migrate) antes de publicar. La migración v2→v3 conserva la columna heredada runs como copia de seguridad; reclámelo con db.cleanup_legacy_runs_column() (SQL) / db.cleanup_legacy_runs_field() (document/KV) después de verificar.
  • Las bases de datos obsoletas/no migradas generan errores escritos en lugar de comportarse mal silenciosamente.
  • Paginación: page sin limit (o page < 1) ahora genera ValueError en lugar de devolver resultados ilimitados/negativos.

AgenteOS

  • JWT: secret_key eliminado de JWTMiddleware y authorization_config - use verification_keys (una lista).
  • Rutas de metadatos: GET /models eliminado (los datos del modelo se movieron a GET /config en available_models); GET / devuelve una respuesta de aterrizaje mínima; GET /info es el único punto final de metadatos no autenticados.
  • Configuración del servidor MCP: AgentOS(enable_mcp_server=..., mcp_config=...) eliminado; en su lugar, pase un único mcp_server= .
  • La ejecución en segundo plano requiere un db en el componente (devuelve 400 sin uno). Los agentes de marco externo (LangGraph, Claude, DSPy, etc.) transmiten en línea para background=true y no se pueden reanudar.

Agentes

  • Parámetros renombrados:
    • enable_user_memories → update_memory_on_run
    • search_session_history → search_past_sessions
    • num_history_sessions → num_past_sessions_to_search
    • num_past_session_runs → num_past_session_runs_in_search
  • reasoning=True eliminado: establece reasoning_model=<native reasoning model> explícitamente.
  • continue_run / acontinue_run: updated_tools eliminado: pase requirements (lista de RunRequirement de la salida de ejecución en pausa).
  • Función cultural eliminada: enable_agentic_culture, add_culture_to_context, CulturalKnowledge, herramientas culturales y la tabla agno_culture . Utilice Knowledge para obtener información compartida entre usuarios.

Equipos y flujos de trabajo

  • El constructor Workflow es solo para palabras clave: Workflow(name=..., steps=[...]). Team no ha cambiado: Team([agent_1, agent_2]) aún funciona, aunque se prefiere Team(members=[...]) .
  • Se eliminaron kwargs HITL planos en Paso/Pasos/Bucle/Condición/Enrutador (requires_confirmation, confirmation_message, on_reject, requires_user_input, user_input_message, user_input_schema, requires_output_review, output_review_message, requires_iteration_review, iteration_review_message, on_error, hitl_max_retries, hitl_timeout, on_timeout). Utilice human_review=HumanReview(...) (de agno.workflow.types); los nombres no cambian excepto hitl_max_retries → max_retries, hitl_timeout → timeout.

Herramientas

  • MultiMCPTools eliminado (junto con allow_partial_failure): use un MCPTools por servidor.
  • MCPToolbox: auth_tokens / auth_headers eliminados: use auth_token_getters.
  • DuckDuckGoTools.duckduckgo_search → web_search, duckduckgo_news → search_news (ahora integrado en WebSearchTools).
  • Módulos planos de herramientas de Google eliminados (agno.tools.gmail, googlesheets, googlecalendar, google_maps, google_drive, google_bigquery): importación desde agno.tools.google.*.
  • Herramientas de Google: creds_path / auth_port → credentials_path / oauth_port; Hojas enable_read_sheet etc. → nombres de métodos básicos.
  • FileTools.check_escape → Toolkit._check_path (LocalFileSystemTools.check_escape no afectado).
  • SQLTools: enable_list_tables / enable_describe_table / enable_run_sql_query → nombres de métodos básicos.
  • Seltz: max_documents → max_results.
  • StudioTool alias eliminado: utilice StudioTools.
  • BrightData.get_screenshot: output_path sin usar, eliminado. PgVector.enable_prefix_matching eliminado (ayudante muerto).

Bases de datos de conocimiento y vectores

  • Knowledge.add_content / add_content_async / add_contents_async eliminado → use insert() / ainsert() / ainsert_many().
  • GDriveContextProvider renombrado → GoogleDriveContextProvider.
  • LanceDB: use_tantivy eliminado/ignorado.
  • La búsqueda en una tabla de vectores anterior a la versión 3 con user_id genera ValueError (lo dirige a la migración de la base de datos vectorial) en lugar de devolver resultados vacíos.

Programador

  • update_schedule ahora está en la lista permitida (solo name, description, method, endpoint, payload, cron_expr, timezone, timeout_seconds, max_retries, retry_delay_seconds, enabled, next_run_at, disabled_reason); cualquier otra tecla genera ValueError. La propiedad/procedencia/estado de bloqueo ya no se pueden escribir a través de la ruta genérica. Nuevas columnas de procedencia agregadas por la migración v3.0.0.
  • La clave única del programa cambia de name a (user_id, name). Si existen nombres de programación duplicados en el mismo usuario, la migración se cancela: elimine los duplicados antes de migrar.

Evaluaciones

  • eval_id → run_id (#9739): las clases de evaluación ya no incluyen eval_id; cada ejecución tiene su propio run_id. store_result_in_file cambia el nombre del parámetro eval_id a run_id, el marcador de posición {eval_id} en las plantillas file_path_to_save_results ya no se acepta (use {run_id}) y POST /eval-runs devuelve la identificación con la que se almacenó realmente la fila (run_id). Las repeticiones ya no se sobrescriben entre sí.

Modelos y aprendizaje

  • Mistral: mistralai v1 se eliminó la capa de compatibilidad: agno[mistral] requiere mistralai>=2.0.0 (y está de nuevo en el models extra).
  • Módulo agno.models.metrics y alias Metrics eliminados → importar desde agno.metrics (RunMetrics).
  • Model.classify_error eliminado → usar ModelProviderError.classify(error).
  • La memoria de entidad en namespace="user" ahora está aislada por usuario (las teclas de fila incorporan un resumen user_id ); filas anteriores a la versión 3 con nuevas claves mediante la migración v3.0.0 (agno.learn.migrations.rekey_user_entity_learnings); EntityMemoryStore.delete/get requieren una palabra clave user_id en ese espacio de nombres.
  • Se eliminaron los alias de aprendizaje: MemoriesConfig → UserMemoryConfig; MemoriesStore → UserMemoryStore; Decision → DecisionLog.

Obsoleto (aún funciona)

  • knowledge_retriever(dependencies=...) → prefiera run_context. Un recuperador cuya firma todavía se llama dependencies sigue funcionando a través de una rama explícita de compatibilidad con versiones anteriores; run_context gana cuando ambos están presentes.
  • Alcances: system:read / system:write → config:read / config:write. Los nombres antiguos siguen siendo alias válidos y los tokens existentes siguen funcionando.
  • RedisDB (base de datos vectorial) → RedisDb. Nota RedisVectorDb también aún se exporta para eliminar la ambigüedad del adaptador de almacenamiento agno.db.redis.

Referencia rápida sobre migración

Documentos: guía paso a paso, migración de bases de datos y un mensaje para pegar en su agente de codificación

import asyncio
from agno.db.migrations.manager import MigrationManager

# Step 1: run before serving v3.0 traffic (up() is async)
asyncio.run(MigrationManager(db).up())

# Step 2: VERIFY the runs landed before any cleanup
assert len(db.get_runs(limit=5)) > 0, "Migration copied nothing - do NOT clean up"

# Step 3 (optional, destructive): reclaim the legacy blob column.
# The migration preserves it as a backup, so force=True is required.
db.cleanup_legacy_runs_column(force=True)   # SQL adapters
# db.cleanup_legacy_runs_field(force=True)  # document / KV adapters

En AgentOS: POST /databases/all/migrate. Detalles completos en los documentos v3.0 changelog.
