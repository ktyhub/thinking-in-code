ragflow v0.26.2

Parche Publicado29 jun 2026 Fuenteinfiniflow/ragflow original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

flujo de trapo v0.26.2

Resumen

Publicado el 29 de junio de 2026.

Nuevas funciones

  • Canales de chat:
    • Integra WhatsApp mediante un escaneo de código QR. #16238
    • Integra DingTalk mediante credenciales del bot API. #16183
    • Integra WeCom mediante conexión WebSocket. #16175
  • Análisis de archivos: agrega lógica alternativa para PP-OCRv6 y modelos de reconocimiento de texto similares, e integra el análisis de imágenes dentro del proceso PaddleOCR. #16150

Mejoras

  • Conjuntos de datos
    • Agrega una verificación de casos extremos a la lógica de ingesta de archivos para vincular de forma segura carpetas vacías a un conjunto de datos. #16296
    • Agrega paginación al método get_flatted_meta_by_kbs() para evitar fallas CRUD relacionadas con conjuntos de datos con más de 10,000 documentos. #16095
  • Canales de chat: garantiza que los historiales de conversaciones del usuario final persistan durante los reinicios, pero aún estén separados cuando un canal está vinculado a un nuevo diálogo. #16274

i18n

  • Amplía la cobertura de i18n y perfecciona las traducciones para la interfaz de usuario coreana. #16203；
  • Agrega traducciones al francés que faltan para canales de chat, validación de nombres de usuario y edición de modelos. #16217

Corrección de errores

  • Análisis de archivos:
    • Se generó un ValueError durante el análisis de .docx en los estilos de 'Encabezado'. #16284
    • El analizador de documentos de leyes eliminó silenciosamente las tablas en los archivos .docx. #16155
    • Los encabezados de Lone Markdown se separaron de sus secciones posteriores cuando se estableció un delimitador de DeepDoc. #16109
    • Las tablas de rebajas aparecieron dos veces en los resultados de fragmentos, una vez como un fragmento independiente y otra vez dentro de un fragmento de texto normal. #16143 -MCP
    • El servidor MCP se colgaba indefinidamente cuando encontraba páginas de documentos vacías; la última página de los documentos se eliminó silenciosamente debido a una paginación defectuosa. #16285
    • La conexión MCP y el proceso de descubrimiento del conjunto de datos fallaron porque el límite de recuperación codificado del servidor excedió la restricción page_size introducida. #16148
  • Flujo de datos
    • Restaura el punto final de repetición del flujo de datos y garantiza que la respuesta de ingesta incluya la carga útil DSL para representar de manera confiable la línea de tiempo y las vistas del analizador. #16292
    • Restaura los valores predeterminados del analizador de flujo de datos y devuelve la carga útil de SSE real, lo que garantiza que la canalización se ejecute correctamente, muestre los ID de los mensajes y las actualizaciones de registros. #16290
  • LLM: no se pudo utilizar el nuevo modelo gemini-3.5-flash a través del proveedor de Google Cloud (Vertex AI) utilizando el punto final de la región eu o us. Esto se resuelve mediante solicitudes de enrutamiento explícitas de múltiples regiones a los dominios aiplatform.<region>.rep.googleapis.com requeridos en lugar de hosts <region>-aiplatform.googleapis.com sintetizados. #15990
  • UI/UX: el modal de adición de metadatos envió valores vacíos al backend. #15229
