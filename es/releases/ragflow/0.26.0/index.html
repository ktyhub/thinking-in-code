ragflow v0.26.0

Menor Publicado11 jun 2026 Fuenteinfiniflow/ragflow original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

flujo de trapo v0.26.0

Resumen

Nuevas funciones

  • Proveedores de modelos
    • Implementa listas de modelos que se completan automáticamente para múltiples proveedores, eliminando la necesidad de escribir los nombres de los modelos manualmente. Esta función actualmente es compatible con: Ollama, OpenRouter, vLLM, OpenAI-API-Compatible, LM-Studio, VolcEngine, Xinference, LocalAI, BaiduYiyan, GPUStack y Fish Audio.
    • Permite configurar múltiples claves API para el mismo modelo de proveedor. #14595
    • Completa dinámicamente los menús desplegables de selección de modelos en la interfaz de usuario al obtener los modelos actualmente disponibles directamente de proveedores de modelos remotos. #15711
  • Conectores de fuentes de datos: implementa nuevos conectores de fuentes de datos para Outlook, OneDrive, Microsoft Teams, Slack, SharePoint, Salesforce y Azure Blob Storage. #15333#15330#15332#15188#15190#15462#15466
  • Conjunto de datos: implementa una función de punto de control y reanudación para la extracción de la comunidad y la resolución de entidades, las partes más caras y que consumen más tiempo del proceso de indexación de GraphRAG. #15518#15523

Mejoras

  • Elimina el almacenamiento en búfer de texto <think> para garantizar que los modelos con capacidad de razonamiento se sientan más rápidos y transparentes durante las interacciones. #15891
  • Marca las migraciones MySQL como aplicadas. #15504

Soporte de modelo

  • Cuatro nuevos modelos SiliconFlow #15383
  • Modelo MiniMax-M3 #15513
  • Últimos modelos Anthropic #15516
  • Familia de modelos Voyage 4 #15516
  • Lista de modelos Cohere. #15576

i18n

  • Completa la traducción al coreano. #15863
  • Completa la traducción al italiano. #15729

Corrección de errores

  • El modo de pensamiento de los modelos MiniMax no estaba habilitado correctamente. #15496
  • Se activaron bucles infinitos cuando se habilitó el modo de pensamiento para los modelos Qwen3.5 y Qwen3.6. #15101
  • Las respuestas transmitidas se duplicaban al utilizar el punto final API de finalización de chat compatible con OpenAI. #15286#15443
  • Se produjeron errores de serialización durante la finalización del chat cuando se pasaron puntuaciones numéricas no válidas como NaN (Not-a-Number) o Inf (Infinity) al codificador JSON. #15245#15266
  • La finalización del chat utilizando proveedores LiteLLM fallaba porque los parámetros de configuración internos no reconocidos no se filtraban antes de llegar a los API externos. #15427#15432
  • Las finalizaciones de chat compatibles con OpenAI API utilizaban de forma predeterminada respuestas transmitidas. #15356#15394
  • Los resultados vacíos de AND se eliminaron incorrectamente durante el filtrado de metadatos. #15477
  • El analizador MinerU extrajo incorrectamente el cromo de página repetitivo, como encabezados y pies de página, como texto principal. #15335#15387
  • Faltaban títulos de gráficos en inglés durante la extracción de documentos en el módulo DeepDoc. #15481
  • TitleChunker devolvió salidas vacías para los formatos ascendentes json y chunks #14247#15396
  • Faltaba un mensaje de error cuando fallaba el intento de carga de un archivo .tsv. #15284
  • Los tokens API a los que les faltaban valores beta provocaron errores de recuperación de tokens. #15405
  • Limita el tamaño máximo de página para corregir fallos del sistema o ralentizaciones debido a consultas grandes. #15292
  • Los errores de Client fueron causados ​​por la finalización del chat compatible con OpenAI API que utilizaba incorrectamente las respuestas transmitidas de forma predeterminada. #15356#15394
  • Se activaron errores del servidor interno HTTP 500 en lugar de los errores estándar 4xx client cuando los usuarios intentaron descargar archivos faltantes desde el backend de almacenamiento. #15369#15371
  • Se rompió la clasificación de entidades GraphRAG. #15795#15797
