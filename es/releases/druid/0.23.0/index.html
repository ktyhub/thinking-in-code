{"timestamp": "2011-01-14T00:00:00.000Z", "tags": []}                #row4

{
  "queryType": "groupBy",
  "dataSource": "test",
  "intervals": [
    "1970-01-01T00:00:00.000Z/3000-01-01T00:00:00.000Z"
  ],
  "granularity": {
    "type": "all"
  },
  "virtualColumns" : [ {
    "type" : "expression",

<a name="0.23.0-new-features-streaming-ingestion-kinesis-ingestion---improvements" href="#0.23.0-new-features-streaming-ingestion-kinesis-ingestion---improvements">#</a> Ingestión de Kinesis: mejoras

Hemos realizado las siguientes mejoras en la ingestión de kinesis.

  • La nueva fragmentación puede afectar y ralentizar la ingestión ya que se crean muchos fragmentos vacíos intermedios. Estos fragmentos se asignan a tareas que provocan un desequilibrio en la asignación de carga. Puede configurar skipIgnorableShards en true en la configuración de ajuste de ingesta de Kinesis para ignorar dichos fragmentos. (#12235)
  • Actualmente, la ingestión de Kinesis utiliza DescribeStream para recuperar la lista de fragmentos. Esta llamada está en desuso y es más lenta. En esta versión, puede cambiar a un API listShards más nuevo configurando useListShards en true en la configuración de ajuste de ingesta de Kinesis. (#12161)

Hasta la versión 0.22.1, si emitías una consulta SQL no compatible, Druid arrojaba mensajes de error muy crípticos e inútiles. <a name="0.23.0-security-fixes" href="#0.23.0-security-fixes">#</a> Correcciones de seguridad

<a name="0.23.0-security-fixes-support-for-access-control-on-setting-query-contexts" href="#0.23.0-security-fixes-support-for-access-control-on-setting-query-contexts">#</a> Soporte para control de acceso en la configuración de contextos de consulta

Hoy en día, los usuarios pueden acceder a cualquier parámetro de contexto. Esto puede causar 1) una mala experiencia de usuario si el parámetro de contexto aún no está maduro o 2) incluso una falla en la consulta o una falla del sistema en el peor de los casos si se abusa de un parámetro sensible, por ejemplo, maxSubqueryRows. Druid ahora tiene la capacidad de limitar los parámetros de contexto por función de usuario. Eso significa que una consulta fallará si tiene un parámetro de contexto establecido en la consulta que no está permitido. La autorización del parámetro de contexto se puede habilitar usando Druid.auth.authorizeQueryContextParams. Esto está deshabilitado de forma predeterminada para permitir una experiencia de actualización más fluida. (#12396)

<a name="0.23.0-upgrading-to-0.23.0" href="#0.23.0-upgrading-to-0.23.0">#</a> Actualización a 0.23.0

Considere los siguientes cambios y actualizaciones al actualizar de Druid 0.22.x a 0.23.0. Si está actualizando desde una versión anterior a 0.22.1, consulte los release note de las versiones intermedias relevantes.

<a name="0.23.0-upgrading-to-0.23.0-autokill" href="#0.23.0-upgrading-to-0.23.0-autokill">#</a> Eliminación automática de segmentos

En 0.23.0, la eliminación automática de segmentos ahora está habilitada de forma predeterminada (#12187). Los nuevos valores predeterminados deberían eliminar todos los segmentos no utilizados que tengan más de 90 días. Si los usuarios no desean este comportamiento en una actualización, deben desactivarlo explícitamente. Este es un cambio arriesgado ya que, según el intervalo, los segmentos se eliminarán inmediatamente después de marcarse como no utilizados. Este comportamiento se revertirá o cambiará en la próxima versión de druida. Consulte (#12693) para obtener más detalles.

<a name="0.23.0-upgrading-to-0.23.0-other-changes" href="#0.23.0-upgrading-to-0.23.0-other-changes">#</a> Otros cambios

  • La ingestión de Kinesis requiere acceso listShards API a la transmisión.
  • Las bibliotecas Kafka clients se han actualizado a 3.0.0 (#11735)
  • La configuración del coordinador dinámico, percentOfSegmentsToConsiderPerMove, ha quedado obsoleta y se eliminará en una versión futura de Druid. Está siendo reemplazada por una nueva estrategia de selección de segmentos introducida en (#11257). Esta nueva estrategia actualmente está desactivada de forma predeterminada, pero se puede activar si establece la configuración del coordinador dinámico useBatchedSegmentSampler en verdadero. Configurar esto como tal deshabilitará el uso del obsoleto percentOfSegmentsToConsiderPerMove. En una versión futura, useBatchedSegmentSampler será permanentemente verdadero. (#11960)

<a name="0.23.0-developer-notices" href="#0.23.0-developer-notices">#</a> Avisos para desarrolladores

<a name="0.23.0-developer-notices-updated-airline-dependency-to-2.x" href="#0.23.0-developer-notices-updated-airline-dependency-to-2.x">#</a> actualizó la dependencia de la aerolínea a 2.x

https://github.com/airlift/airline ya no recibe mantenimiento, por lo que druid se ha actualizado a https://github.com/rvesse/airline (Aerolínea 2) para utilizar activamente versión mantenida, minimizando al mismo tiempo los cambios importantes. Este es un cambio incompatible con versiones anteriores y las extensiones personalizadas que dependen del punto de extensión CliCommandCreator también deberán actualizarse. 12270

<a name="0.23.0-developer-notices-return-404-instead-of-400-for-unknown-supervisors-or-tasks" href="#0.23.0-developer-notices-return-404-instead-of-400-for-unknown-supervisors-or-tasks">#</a> Devuelve 404 en lugar de 400 para supervisores o tareas desconocidos

El supervisor anterior/punto final de tarea devuelve 400 cuando no se encuentra un supervisor o una tarea. Este código de estado no es amigable y confuso para el tercer sistema. Y según la definición de código de estado HTTP, 404 es el código correcto para tal caso. Por eso hemos cambiado el código de estado de 400 a 404 para eliminar la ambigüedad. Cualquier clients de estos puntos finales debería cambiar el manejo del código de respuesta en consecuencia. 11724

<a name="0.23.0-developer-notices-return-400-instead-of-500-when-sql-query-cannot-be-planned" href="#0.23.0-developer-notices-return-400-instead-of-500-when-sql-query-cannot-be-planned">#</a> Devuelve 400 en lugar de 500 cuando no se puede planificar la consulta SQL

Cualquier consulta SQL que Druid no pueda planificar no se considera una mala solicitud. Para este tipo de consultas, ahora devolvemos 400. Los desarrolladores que utilizan SQL API deben cambiar el manejo del código de respuesta si es necesario. 12033

<a name="0.23.0-developer-notices-responsecontext-refactoring" href="#0.23.0-developer-notices-responsecontext-refactoring">#</a> Refactorización de ResponseContext

0.23.0 cambia el ResponseContext y sus teclas de forma radical. La versión anterior del contexto de respuesta sugería que las claves se definieran en una enumeración y luego se registraran. Esta versión sugiere que las claves se definan como objetos y luego se registren. Consulte la clase ResponseContext para obtener más detalles. (#11828)

<a name="0.23.0-developer-notices-other-changes" href="#0.23.0-developer-notices-other-changes">#</a> Otros cambios

  • Se ha eliminado SingleServerInventoryView. (#11770)
  • LocalInputSource no permite ingerir el mismo archivo varias veces. (#11965)
  • getType() en PostAggregator está en desuso en favor de getType(ColumnInspector) (#11818)
