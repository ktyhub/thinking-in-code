druida druida-25.0.0

Apache Druid 25.0.0 contiene más de 300 funciones nuevas, correcciones de errores, mejoras de rendimiento, mejoras de documentación y cobertura de pruebas adicionales de 51 contribuyentes. Consulte el conjunto completo de cambios para obtener detalles adicionales.

<a name="25-highlights" href="#25-highlights">#</a> Destacados

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> El motor de tareas MSQ ya está listo para producción

El motor de tareas de consulta multietapa (MSQ) utilizado para la ingesta basada en SQL ya está listo para producción. Úselo para cualquier carga de trabajo compatible. Para obtener más información, consulte las siguientes páginas:

  • Ingestión
  • Ingestión basada en SQL

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Implementaciones de druidas simplificadas

El nuevo script start-druid simplifica enormemente la implementación de cualquier combinación de servicios Druid en un único servidor. Viene preempaquetado con las configuraciones necesarias y se puede utilizar para iniciar un clúster Druid completamente funcional simplemente invocando ./start-druid. Para los druidas experimentados, también brinda control total sobre las propiedades del tiempo de ejecución y los argumentos JVM para tener un clúster que se ajuste exactamente a sus necesidades. El script start-druid desaprueba los perfiles existentes, como start-micro-quickstart y start-nano-quickstart. Es posible que estos perfiles se eliminen en versiones futuras. Para obtener más información, consulte Implementación de un único servidor.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> Compresión de diccionario de cadenas (experimental)

Se agregó soporte para diccionarios de cadenas codificados frontalmente para columnas de cadenas más pequeñas, lo que lleva a tamaños de segmento reducidos con solo menores penalizaciones de rendimiento para la mayoría de las consultas Druid. Esto se puede habilitar estableciendo IndexSpec.stringDictionaryEncoding en {"type":"frontCoded", "bucketSize": 4}, donde bucketSize es cualquier potencia de 2 menor o igual a 128. Al configurar esta propiedad, se indica a las tareas de indexación que escriban segmentos utilizando diccionarios comprimidos del tamaño de depósito especificado.

Cualquier segmento escrito utilizando la compresión del diccionario de cadenas no es legible en versiones anteriores de Druid. Para obtener más información, consulte Codificación frontal. https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Kubernetes-tareas nativas

Druid ahora puede usar Kubernetes para iniciar y administrar tareas, eliminando la necesidad de mandos intermedios. Para usar esta función, habilite las druid-kubernetes-overlord-extensions en la lista de carga de extensiones para su proceso Overlord. https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-compatible-binary" href="#25-highlights-hadoop-3-compatible-binary">#</a> Binario compatible con Hadoop-3

Druid ahora viene empaquetado como un binario dedicado para usuarios de Hadoop-3, que contiene archivos jar compatibles con Hadoop-3. Si no utiliza Hadoop-3 con su clúster Druid, puede continuar usando el binario clásico.

<a name="25-multi-stage-query-task-engine" href="#25-multi-stage-query-task-engine">#</a> Motor de tareas de consulta multietapa (MSQ)

<a name="25-msq-docker-enabled" href="#25-msq-docker-enabled">#</a> MSQ habilitado para Docker

El motor de consulta de tareas MSQ ahora está habilitado para Docker de forma predeterminada. https://github.com/apache/druid/pull/13069

<a name="25-msq-query-history" href="#25-msq-query-history">#</a> Historial de consultas

Las consultas de varias etapas ya no aparecen en el cuadro de diálogo Historial de consultas. Todavía están disponibles en el panel Tareas de consulta recientes.

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> Límite en columnas CLUSTERED BY

Cuando se utiliza el motor de tareas MSQ para ingerir datos, el número de columnas que se pueden pasar en la cláusula CLUSTERED BY ahora está limitado a 1500. https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> Compatibilidad con la compresión del diccionario de cadenas

El motor de tareas MSQ admite la codificación frontal de diccionarios de cadenas para una mejor compresión. Esto se puede habilitar para declaraciones INSERT o REPLACE configurando indexSpec en una cadena json válida en el contexto de consulta. https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> Modo de fusión de bocetos

Los trabajadores ahora pueden recopilar estadísticas clave, utilizadas para generar límites de partición, ya sea de forma secuencial o en paralelo. Establezca clusterStatisticsMergeMode en PARALLEL, SEQUENTIAL o AUTO en el contexto de consulta para utilizar el modo de combinación de bocetos correspondiente. Para obtener más información, consulte Modo de combinación de bocetos. https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> Mejoras operativas y de rendimiento

  • Mensajes de error: para advertencias MSQ no permitidas de ciertos tipos, la advertencia ahora aparece como error. https://github.com/apache/druid/pull/13198
  • Secretos: para tareas que contienen SQL con claves confidenciales, Druid ahora enmascara las claves mientras inicia sesión con las expresiones regulares de ayuda. https://github.com/apache/druid/pull/13231
  • Precisión de reducción de resolución: el motor de tareas MSQ ahora usa la cantidad de bytes en lugar de la cantidad de claves al reducir la resolución de datos. https://github.com/apache/druid/pull/12998
  • Uso de memoria: al determinar los límites de la partición, la huella del montón de bocetos internos utilizados por MSQ ahora tiene un límite del 10% de la memoria disponible o 300 MB, lo que sea menor. Anteriormente, el límite era estrictamente de 300 MB. https://github.com/apache/druid/pull/13274
  • Reportes de tareas: Se agregaron los campos pendingTasks y runningTasks al reporte del trabajador. Consulte Consultar información sobre el estado de la tarea para conocer los cambios relacionados con la consola web. https://github.com/apache/druid/pull/13263

<a name="25-querying" href="#25-querying">#</a> Consultando

<a name="25-querying-enabled-async-reads-for-jdbc" href="#25-querying-enabled-async-reads-for-jdbc">#</a> Lecturas asíncronas para JDBC

Se evitaron tiempos de espera de JDBC en consultas largas al devolver lotes vacíos cuando la recuperación de un lote tarda demasiado. Utiliza un modelo asíncrono para ejecutar la búsqueda de resultados simultáneamente con las solicitudes JDBC. https://github.com/apache/druid/pull/13196

<a name="25-querying-in-filter" href="#25-querying-in-filter">#</a> Algoritmo mejorado para verificar los valores de un filtro IN

Para acomodar conjuntos de valores grandes que surgen de filtros IN grandes o de uniones presionadas como filtros IN, Druid ahora usa un algoritmo de combinación ordenada para fusionar el conjunto y el diccionario para valores más grandes. https://github.com/apache/druid/pull/13133

<a name="25-querying-context-security" href="#25-querying-context-security">#</a> Seguridad de contexto de consulta mejorada

Se agregaron las siguientes propiedades de configuración que refinan el modelo de seguridad del contexto de consulta controlado por druid.auth.authorizeQueryContextParams:

  • druid.auth.unsecuredContextKeys: una lista JSON de claves de contexto de consulta que no requieren una verificación de seguridad.
  • druid.auth.securedContextKeys: una lista JSON de claves de contexto de consulta que requieren una verificación de seguridad. Si se configuran ambos, unsecuredContextKeys actúa como excepción a securedContextKeys. https://github.com/apache/druid/pull/13071

<a name="25-querying-http-response-headers" href="#25-querying-http-response-headers">#</a> encabezados de respuesta HTTP

La respuesta HTTP para una consulta SQL ahora establece correctamente los encabezados de respuesta, al igual que una consulta nativa. https://github.com/apache/druid/pull/13052

<a name="25-ingestion-idle-supervisor" href="#25-ingestion-idle-supervisor">#</a> Ingesta desde una secuencia Kafka inactiva

El supervisor reanuda automáticamente la creación de nuevas tareas de indexación una vez que la secuencia vuelve a estar activa. Establezca la propiedad dataSchema.ioConfig.idleConfig.enabled en verdadero en la especificación del supervisor respectivo o configure druid.supervisor.idleConfig.enabled en el señor supremo para habilitar este comportamiento. Consulte lo siguiente para obtener más detalles:

<a name="25-ingestion-fixed-overlord-leader-election" href="#25-ingestion-fixed-overlord-leader-election">#</a> Se corrigió la elección del líder de Overlord

Se solucionó un problema por el cual la elección del líder Overlord fallaba debido a problemas de readquisición de bloqueos. Druid ahora falla en estas tareas y borra todos los bloqueos para que no se bloquee la elección del líder Overlord. https://github.com/apache/druid/pull/13172

<a name="25-ingestion-duplicate-notices" href="#25-ingestion-duplicate-notices">#</a> Avisos duplicados

Para la ingesta de streaming, los avisos que sean iguales a los que ya están en cola no se pondrán en cola. Esto ayudará a reducir el tamaño de la cola de notificaciones. https://github.com/apache/druid/pull/13334

<a name="25-ingestion-sampling-from-stream-input-now-respects-the-configured-timeout" href="#25-ingestion-sampling-from-stream-input-now-respects-the-configured-timeout">#</a> El muestreo de la entrada del flujo ahora respeta el tiempo de espera configurado

Se solucionó un problema por el cual el muestreo de una entrada de transmisión, como Kafka o Kinesis, no respetaba el tiempo de espera configurado cuando la transmisión no tenía registros disponibles. Ahora puede establecer la cantidad máxima de tiempo en la que el iterador de entrada devolverá resultados. https://github.com/apache/druid/pull/13296

<a name="25-ingestion-streaming-tasks-resume-on-overlord-switch" href="#25-ingestion-streaming-tasks-resume-on-overlord-switch">#</a> Las tareas de transmisión se reanudan en Overlord Switch

Se solucionó un problema por el cual las tareas de ingesta de transmisión continuaban ejecutándose hasta que transcurría su duración después de que el líder Overlord había emitido una pausa para las tareas. Ahora, cuando el cambio de Overlord ocurre justo después de haber emitido una pausa para la tarea, la tarea permanece en un estado de pausa incluso después de la reelección de Overlord. https://github.com/apache/druid/pull/13223

<a name="25-ingestion-fixed-parquet-list-conversion" href="#25-ingestion-fixed-parquet-list-conversion">#</a> Conversión de lista de parquet fija

Se solucionó un problema con la conversión de la lista Parquet, donde las listas de objetos complejos podían inesperadamente incluirse en un objeto adicional, apareciendo como [{"element":<actual_list_element>},{"element":<another_one>}...] en lugar de la lista directa. Esto cambia el comportamiento del lector de parquet para que las listas de objetos estructurados sean coherentes con otras conversiones de listas lógicas de parquet. Los datos ahora se obtienen directamente, coincidiendo más estrechamente con su estructura esperada. https://github.com/apache/druid/pull/13294

<a name="25-ingestion-introduced-a-tree-type-to-flattenspec" href="#25-ingestion-introduced-a-tree-type-to-flattenspec">#</a> Introdujo un tipo de árbol para flattenSpec

Se introdujo un tipo tree en flattenSpec. En caso de que se requiera una búsqueda jerárquica simple, el tipo tree permite un análisis JSON más rápido que los tipos de análisis jq y path. https://github.com/apache/druid/pull/12177

<a name="25-operaciones" href="#25-operaciones">#</a> Operaciones

<a name="25-operaciones-compactación" href="#25-operaciones-compactación">#</a> Compactación

El comportamiento de compactación ha cambiado para mejorar la cantidad de tiempo y el espacio en disco necesarios:

  • Cuando sea necesario recuperar segmentos, descárgalos uno a la vez y elimínalos cuando Druid haya terminado con ellos. Esto todavía lleva tiempo pero minimiza el espacio en disco requerido.
  • No recuperar segmentos en la tarea compacta principal cuando no sean necesarios. Si el usuario proporciona granularitySpec, dimensionsSpec y metricsSpec completos, Druid omite la búsqueda de segmentos. Para obtener más información, consulte la documentación sobre Compactación y Compactación automática. https://github.com/apache/druid/pull/13280

La opción HttpPostEmitter ahora tiene un retroceso. Esto significa que debería haber menos ruido en los registros y un menor uso de la CPU si utiliza esta opción para iniciar sesión. https://github.com/apache/druid/pull/12102

  • Operaciones de Overlord

<a name="25-operatives-segment-loading-and-balancing-cachingcost-balancer-strategy" href="#25-operatives-segment-loading-and-balancing-cachingcost-balancer-strategy">#</a> Estrategia mejorada del balanceador de costos de almacenamiento en caché

La estrategia del balanceador cachingCost ahora se comporta de manera más similar a la estrategia de costos. Al calcular el costo de mover un segmento a un servidor, se realizan los siguientes cálculos:

  • Reste el costo propio de un segmento si está siendo atendido por el servidor de destino.
  • Reste el costo de los segmentos que están marcados para eliminarse. https://github.com/apache/druid/pull/13321

<a name="25-operaciones-segment-loading-and-balancing-segment-assignment" href="#25-operatives-segment-loading-and-balancing-segment-assignment">#</a> Asignación de segmentos más rápida

Ahora puede utilizar una estrategia de segmento por turnos para acelerar las asignaciones de segmentos iniciales. Configure useRoundRobinSegmentAssigment en true en la configuración dinámica del Coordinador para habilitar esta función. https://github.com/apache/druid/pull/13367

<a name="25- Operations-segment-batch-sampling" href="#25-operatives-segment-batch-sampling">#</a> El valor predeterminado es el muestreo por lotes para equilibrar segmentos

El muestreo por lotes es ahora el método predeterminado para muestrear segmentos durante el equilibrio, ya que funciona significativamente mejor que la alternativa cuando hay una gran cantidad de segmentos utilizados en el grupo. Como parte de este cambio, lo siguiente ha quedado obsoleto y se eliminará en versiones futuras:

  • configuración dinámica del coordinador useBatchedSegmentSampler
  • configuración dinámica del coordinador percentOfSegmentsToConsiderPerMove
  • antiguo método no por lotes de muestreo de segmentos

<a name="25-operatives-segment-unused-property" href="#25-operatives-segment-unused-property">#</a> Eliminar propiedad no utilizada

Se ha eliminado la propiedad del coordinador no utilizada druid.coordinator.loadqueuepeon.repeatDelay. Utilice solo druid.coordinator.loadqueuepeon.http.repeatDelay para configurar el retraso de repetición para la cola de carga de segmentos basada en HTTP. https://github.com/apache/druid/pull/13391

<a name="25- Operations-segment-replication" href="#25- Operations-segment-replication">#</a> Evite la replicación excesiva de segmentos

Se mejoró el proceso de verificación del inventario del servidor para evitar la replicación excesiva de segmentos durante el equilibrio de segmentos. https://github.com/apache/druid/pull/13114

<a name="25- Operations-provided-service-specific-log4j-overrides-in-containerized-deployments" href="#25- Operations-provided-service-specific-log4j-overrides-in-containerized-deployments">#</a> Anulaciones de log4j específicas del servicio proporcionado en implementaciones en contenedores

<a name="25-upgrade" href="#25-upgrade">#</a> Actualizando a 25.0.0

Considere los siguientes cambios y actualizaciones al actualizar de Druid 24.0.x a 25.0.0. Si está actualizando desde una versión anterior, consulte los release note de las versiones intermedias relevantes.

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> Descubrimiento de segmentos y administración de tareas predeterminados basados en HTTP

El método de descubrimiento de segmentos predeterminado ahora utiliza HTTP en lugar de ZooKeeper. Esta actualización cambia los valores predeterminados de las siguientes propiedades: | Propiedad | Nuevo valor predeterminado | Predeterminado anterior | | - | - | - | | druid.serverview.type para gestión de segmentos | http | lote | | druid.coordinator.loadqueuepeon.type para gestión de segmentos | http | curador | | druid.indexer.runner.type para el Señor Supremo | httpRemoto | locales | Para utilizar ZooKeeper en lugar de HTTP, cambie los valores de las propiedades a los valores predeterminados anteriores. Las implementaciones basadas en ZooKeeper para estas propiedades están obsoletas y se eliminarán en una versión posterior. https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> Finalización de agregados de bocetos de HLL y cuantiles

Las funciones de agregación para bocetos de cuantiles y HLL devolvieron bocetos o números cuando se finalizaron, dependiendo de dónde se encontraban en el plan de consulta nativo. Druid ya no finaliza agregadores en los dos casos siguientes:

  • los agregadores aparecen en el nivel externo de una consulta
  • Los agregadores se utilizan como entrada para una expresión o post-agregador de acceso al campo final. Este cambio alinea el comportamiento de HLL y los bocetos de cuantiles con los bocetos theta. Para restaurar el comportamiento anterior, puede configurar sqlFinalizeOuterSketches=true en el contexto de consulta. https://github.com/apache/druid/pull/13247

<a name="25-upgrade-kill-tasks-mark-unused" href="#25-upgrade-kill-tasks-mark-unused">#</a> Eliminar tareas marca segmentos como no utilizados solo si se especifica

Cuando ejecutas una tarea de eliminación, Druid marca los segmentos subyacentes como no utilizados solo si se especifica explícitamente. Para obtener más información, consulte la referencia API https://github.com/apache/druid/pull/13104

<a name='25-upgrade-incompatible' href='#25-upgrade-incompatible'>#</a> Cambios incompatibles

<a name='25-upgrade-incompatible-curator' href='#25-upgrade-incompatible-curator'>#</a> Actualizar curador a 5.3.0

Apache Curator actualizado a la última versión, 5.3.0. Esta versión deja de ser compatible con ZooKeeper 3.4, pero Druid ya ha eliminado oficialmente el soporte para 0.22. En 5.3.0, Curator eliminó la compatibilidad con Exhibitor, por lo que se eliminaron todas las configuraciones y pruebas relacionadas. https://github.com/apache/druid/pull/12939

<a name="25-upgrade-incompatible-parquet" href="#25-upgrade-incompatible-parquet">#</a> Conversión de lista de parquet fija

El comportamiento del lector de parquet para listas de objetos estructurados se ha cambiado para que sea coherente con otras conversiones de listas lógicas de parquet. Los datos ahora se obtienen directamente, coincidiendo más estrechamente con su estructura esperada. Consulte conversión de lista de parquet para obtener más detalles. https://github.com/apache/druid/pull/13294
