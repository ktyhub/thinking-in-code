<a name="26.0.0-highlights-auto-type-column-schema-%28experimental%29" href="#26.0.0-highlights-auto-type-column-schema-%28experimental%29">#</a> Esquema de columnas de tipo automático (experimental)

Se agregó un nuevo esquema de columna de tipo "automático" e indexador a la ingesta nativa como la siguiente iteración lógica de la funcionalidad de columna anidada. Este indexador de columnas de tipo automático produce la columna más apropiada para las entradas dadas, produciendo columnas STRING, ARRAY<STRING>, LONG, ARRAY<LONG>, DOUBLE, ARRAY<DOUBLE> o COMPLEX<json>, todas las cuales comparten un formato "anidado" común.

Todas las columnas producidas por 'auto' tienen índices para ayudar en el filtrado rápido (a diferencia de las columnas clásicas LONG y DOUBLE) y utilizan umbrales basados ​​en cardinalidad para intentar utilizar estos índices solo cuando es probable que realmente aceleren la consulta (a diferencia de las columnas STRING clásicas).

Las columnas COMPLEX<json> producidas por este indexador 'automático' almacenan matrices de tipos escalares simples de manera diferente a sus contrapartes 'json' (v4), almacenándolas como columnas de tipo ARRAY. Esto significa que la función JSON_VALUE ahora puede extraer matrices enteras, por ejemplo JSON_VALUE(nested, '$.array' RETURNING BIGINT ARRAY). No hay cambios en la forma en que se almacenan las matrices de objetos complejos en este momento.

Esta mejora también agrega una funcionalidad completamente nueva a Druid, las columnas escritas ARRAY, que a diferencia de las columnas clásicas de valores múltiples STRING se comportan con la semántica ARRAY. Actualmente, estas columnas solo se pueden crear a través del indexador de tipo "automático" cuando todos los valores son matrices con el mismo tipo de elementos.

Un tipo de datos de matriz es un tipo de datos que le permite almacenar múltiples valores en una sola columna de una tabla de base de datos. Las matrices se utilizan normalmente para almacenar conjuntos de datos relacionados a los que se puede acceder y manipular fácilmente como grupo.

Esta versión agrega soporte para almacenar matrices de valores primitivos como ARRAY<STRING>, ARRAY<LONG> y ARRAY<DOUBLE> como columnas anidadas especializadas en lugar de dividirlas en columnas de elementos separados.

Estos cambios afectan a dos nuevas funciones adicionales disponibles en 26.0: descubrimiento automático de esquemas y desanidado.

<a name="26.0.0-highlights-auto-type-column-schema-%28experimental%29-schema-auto-discovery-%28experimental%29" href="#26.0.0-highlights-auto-type-column-schema-%28experimental%29-schema-auto-discovery-%28experimental%29">#</a> Descubrimiento automático de esquemas (experimental)

Estamos agregando descubrimiento automático de esquemas con inferencia de tipos a Druid. Con esta característica, el tipo de datos de cada campo entrante se detecta cuando el esquema está disponible. Para los datos entrantes que pueden contener campos agregados, eliminados o modificados, puede optar por rechazar los datos no conformes (“la base de datos siempre es correcta, ¡rechazando datos incorrectos!”), o puede permitir que el descubrimiento automático del esquema altere la fuente de datos para que coincida con los datos entrantes (“los datos siempre son correctos, ¡cambie la base de datos!”). Se recomienda el descubrimiento automático de esquemas para nuevos casos de uso e ingestas. Para los casos de uso existentes, tenga cuidado al cambiar al descubrimiento automático de esquemas porque Druid ingerirá valores similares a matrices (por ejemplo, ["tag1", "tag2]) como columnas de tipo ARRAY<STRING> en lugar de cadenas de valores múltiples (MV), esto podría causar problemas en las aplicaciones posteriores que responden al comportamiento de MV. Espere el cambio hasta que esté disponible una ruta de migración oficial.

Para usar esta función, configure spec.dataSchema.dimensionsSpec.useSchemaDiscovery en true en su tarea o especificación de supervisor o, si usa el cargador de datos en la consola, desmarque la opción Explicitly define schema en el paso Configure schema. Druid puede inferir el esquema completo o parte de él si enumera explícitamente las dimensiones en su lista de dimensiones.

El descubrimiento automático de esquemas está disponible para la ingesta de streaming y lotes nativos.

<a name="26.0.0-highlights-unnest-arrays-%28experimental%29-" href="#26.0.0-highlights-unnest-arrays-%28experimental%29-">#</a> Matrices UNNEST (experimentales)

Parte de lo bueno de UNNEST es que permite una gama más amplia de operaciones que no eran posibles en los tipos de datos Array. Puede desanidar matrices con la función UNNEST (SQL) o la fuente de datos unnest (nativa).

Unnest convierte matrices o tablas anidadas en filas individuales. La función UNNEST es particularmente útil cuando se trabaja con tipos de datos complejos que contienen matrices anidadas, como JSON.

Por ejemplo, suponga que tiene una tabla llamada "pedidos" con una columna llamada "artículos" que contiene una serie de productos para cada pedido. Puede utilizar unnest para extraer los productos individuales ("cada_elemento") como en el siguiente ejemplo de SQL:

SELECT order_id, each_item FROM orders, UNNEST(items) as unnested(each_item)

Esto produce un conjunto de resultados con una fila para cada artículo en cada pedido, con columnas para el ID del pedido y el artículo individual.

Tenga en cuenta la coma después de la tabla/fuente de datos de la izquierda (orders en el ejemplo). Es necesario.

<a name="26.0.0-highlights-sort-merge-join-and-hash-shuffle-join-for-msq" href="#26.0.0-highlights-sort-merge-join-and-hash-shuffle-join-for-msq">#</a> Combinación de clasificación y combinación y combinación aleatoria de hash para MSQ

Ahora podemos realizar uniones aleatorias configurando el parámetro de contexto sqlJoinAlgorithm en sortMerge para el algoritmo de clasificación y fusión u omitiéndolo para realizar uniones de transmisión (predeterminado).

Las consultas de varias etapas pueden utilizar un algoritmo de combinación de clasificación y combinación. Con este algoritmo, cada unión por pares se planifica en su propia etapa con dos entradas. Este enfoque generalmente tiene menos rendimiento pero es más escalable que la transmisión.

Establezca el parámetro de contexto sqlJoinAlgorithm en sortMerge para utilizar este método.

Las uniones hash de difusión son similares a cómo se ejecutan las consultas de unión nativa.

Cambiar al uso de compresión de diccionario de codificación frontal (experimental) puede ahorrar hasta un 30% con poco o ningún impacto en el rendimiento de las consultas.

<a name="26.0.0-additional-features-and-improvements-security-support-for-the-http-strict-transport-security-response-header-" href="#26.0.0-additional-features-and-improvements-security-support-for-the-http-strict-transport-security-response-header-">#</a> Compatibilidad con el encabezado de respuesta HTTP Strict-Transport-Security

Se agregó soporte para el encabezado de respuesta HTTP Strict-Transport-Security. Druid no incluye este encabezado de forma predeterminada. Debe habilitarlo en las propiedades del tiempo de ejecución configurando druid.server.http.enableHSTS en true.

#13489

<a name="26.0.0-additional-features-and-improvements-security-add-jwt-authenticator-support-for-validating-id-tokens-%2313242" href="#26.0.0-additional-features-and-improvements-security-add-jwt-authenticator-support-for-validating-id-tokens-%2313242">#</a> Agregar compatibilidad con el autenticador JWT para validar tokens de identificación #13242

Amplía la autenticación basada en OIDC en Druid agregando un autenticador JWT que valida los tokens de identificación asociados con una solicitud. El autenticador pac4j existente funciona para autenticar a los usuarios web mientras acceden a la consola, mientras que este autenticador sirve para validar las solicitudes de Druid API realizadas por Direct clients. Los servicios que ya admiten OIDC pueden adjuntar sus tokens de identificación a las solicitudes de Druida. bajo el encabezado Solicitud de autorización.

<a name="26.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-real-time-tasks" href="#26.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-real-time-tasks">#</a> Tareas en tiempo real

<a name="26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes" href="#26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes">#</a> Cambios incompatibles

<a name="26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes-firehose-ingestion-removed" href="#26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes-firehose-ingestion-removed">#</a> Se eliminó la ingestión de mangueras contra incendios

Se elimina la especificación firehose/parser utilizada por los formatos de transmisión Druid heredados. La ingesta de Firehose quedó obsoleta en la versión 0.17 y la compatibilidad con esta ingesta se eliminó en la versión 24.0.

#12852

<a name="26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes-information-schema-now-uses-numeric-column-types-" href="#26.0.0-upgrade-notes-and-incompatible-changes--incompatible-changes-information-schema-now-uses-numeric-column-types-">#</a> El esquema de información ahora usa tipos de columnas numéricas

La tabla del sistema Druid (INFORMATION_SCHEMA) ahora usa tipos SQL en lugar de tipos Druid para las columnas. Este cambio hace que la tabla INFORMATION_SCHEMA se comporte más como SQL estándar. Es posible que deba actualizar sus consultas en los siguientes escenarios para evitar resultados inesperados si depende de cualquiera de los siguientes:

  • Los campos numéricos se tratan como cadenas.
  • Numeración de columnas que comienza en 0. La numeración de columnas ahora está basada en 1.

#13777

<a name="26.0.0-upgrade-notes-and-incompatible-changes--cambios-incompatibles-%60frontcoded%60-segment-format-change" href="#26.0.0-upgrade-notes-and-incompatible-changes--cambios-incompatibles-%60frontcoded%60-segment-format-change">#</a> Cambio de formato de segmento frontCoded

El tipo frontCoded de stringEncodingStrategy en indexSpec con una nueva versión de formato de segmento, que normalmente tiene velocidades de lectura más rápidas y un tamaño de segmento reducido. Esta mejora es incompatible con versiones anteriores de Druid 25.0.

Para obtener más información, consulte la estrategia de codificación de cadenas frontCoded resaltada.

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notas del desarrollador

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-null-value-coercion-moved-out-of-expression-processing-engine-" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-null-value-coercion-moved-out-of-expression-processing-engine-">#</a> La coerción de valor nulo se sacó del motor de procesamiento de expresiones

Los valores nulos ingresados y creados por el motor de procesamiento de expresiones nativo Druid ya no obligan a null al valor 'predeterminado' apropiado del tipo si es druid.generic.useDefaultValueForNull=true. Esto no debería afectar el comportamiento existente, ya que se ha trasladado al consumidor e internamente los operadores seguirán usando valores predeterminados en este modo. Sin embargo, puede haber cambios sutiles de comportamiento en torno al manejo de los valores null. Las personas que llaman directamente pueden obtener valores predeterminados utilizando el nuevo método valueOrDefault() de ExprEval, en lugar de value().

#13809

<a name="26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-simplified-dependencies" href="#26.0.0-upgrade-notes-and-incompatible-changes-developer-notes-simplified-dependencies">#</a> Dependencias simplificadas

Los módulos druid-core, extendedset y druid-hll se han consolidado en druid-processing para simplificar las dependencias. Cualquier extensión que haga referencia a estos debe actualizarse para usar druid-processing en su lugar. Los binarios de extensión existentes deberían continuar funcionando normalmente cuando se usan con versiones más nuevas de Druid.

Este cambio no afecta a los usuarios finales. Afecta a cualquiera que desarrolle extensiones para Druid.
