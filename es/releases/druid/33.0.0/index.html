Ahora puede aumentar la velocidad a la que se cargan los segmentos en un histórico proporcionando una lista de servidores para la configuración dinámica del Coordinador turboLoadingNodes. <a name="33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29" href="#33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29">#</a> Ingestión de lotes programada (experimental)

Ahora puede programar ingestas por lotes con el motor de tareas MSQ mediante el supervisor de lotes programado. Puede especificar la programación utilizando la sintaxis cron estándar de Unix o la sintaxis cron de Quartz configurando el campo type en unix o quartz. Unix también admite expresiones macro como @daily y otras.

Envíe las especificaciones de su supervisor al punto final /druid/v2/sql/task/.

El siguiente ejemplo de especificación de supervisor de lotes programado envía una consulta REPLACE cada 5 minutos:

{
    "type": "scheduled_batch",
    "schedulerConfig": {
        "type": "unix",
        "schedule": "*/5 * * * *"
    },
    "spec": {
        "query": "REPLACE INTO foo OVERWRITE ALL SELECT * FROM bar PARTITIONED BY DAY"
    },
    "suspended": false
}

<a name="33.0.0-important-features%2C-changes%2C-and-deprecations-improved-s3-upload-" href="#33.0.0-important-features%2C-changes%2C-and-deprecations-improved-s3-upload-">#</a> Carga de S3 mejorada

Druid ahora puede utilizar AWS S3 Transfer Manager para cargas de S3, lo que puede reducir significativamente el tiempo de carga de segmentos. Esta función está activada de forma predeterminada y se controla con las siguientes configuraciones en common.runtime.properties:

    druid.storage.transfer.useTransferManager=true
    druid.storage.transfer.minimumUploadPartSize=20971520
    druid.storage.transfer.multipartUploadThreshold=20971520

<a name="faster-segment-metadata-operaciones" href="#faster-segment-metadata-operaciones">#</a> Operaciones de metadatos de segmentos más rápidas

Habilite el almacenamiento en caché de metadatos de segmentos en Overlord con la propiedad de tiempo de ejecución druid.manager.segments.useCache. Esta característica está desactivada de forma predeterminada.

Puede establecer la propiedad en los siguientes valores:

  • never: la caché está deshabilitada (predeterminado)
  • always: Las lecturas siempre se realizan desde la caché. El inicio del servicio se bloqueará hasta que la caché se haya sincronizado con el almacén de metadatos al menos una vez. Las transacciones se bloquean hasta que el caché se haya sincronizado con el almacén de metadatos al menos una vez después de convertirse en líder.
  • ifSynced: las lecturas se realizan desde el caché solo si ya se ha sincronizado con el almacén de metadatos. Este modo no bloquea el inicio del servicio ni las transacciones a diferencia de la configuración always.

Como parte de este cambio, se han introducido métricas adicionales. Para obtener más información sobre estas métricas, consulte Métricas de caché de metadatos de segmento.

#17653 #17824

<a name="33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval" href="#33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval">#</a> Intervalo de tarea de finalización automática

Opcionalmente, el Coordinador puede emitir tareas de eliminación para limpiar segmentos no utilizados. A partir de esta versión, las tareas de eliminación individuales se limitan a procesar 30 días o menos de segmentos por tarea de forma predeterminada. Esto mejora el rendimiento de las tareas de eliminación individuales.

El comportamiento anterior (sin límite de intervalo por tarea de eliminación) se puede restaurar configurando druid.coordinator.kill.maxInterval = P0D.

Las tareas de eliminación automática ahora están limitadas a 30 días o menos de segmentos por tarea. El comportamiento anterior (sin límite de intervalo por tarea de eliminación) se puede restaurar configurando druid.coordinator.kill.maxInterval = P0D.

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kubernetes-deployments" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kubernetes-deployments">#</a> Implementaciones de Kubernetes

De forma predeterminada, la imagen Docker ahora usa el nombre de host canónico para registrar servicios en ZooKeeper para comunicación interna si está ejecutando Druid en Kubernetes. De lo contrario, utiliza la dirección IP. #17697.

Puede configurar la variable de entorno DRUID_SET_HOST_IP en 1 para restaurar el comportamiento anterior.

Si necesita degradar a una versión donde Druid no admite el caché de metadatos del segmento, debe configurar la configuración druid.manager.segments.useCache en falsa o eliminarla antes de la actualización.

Esta característica se introduce en Druid 33.0.
