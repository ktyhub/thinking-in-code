<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> Nuevo Overlord API

Los API para marcar segmentos como usados o no utilizados se han movido del servicio Coordinador al servicio Overlord:

  • Marcar todos los segmentos de una fuente de datos como no utilizados: POST /druid/indexer/v1/datasources/{dataSourceName}

  • Marcar todos los segmentos (no eclipsados) de una fuente de datos como utilizados: DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • Marcar múltiples segmentos como usados POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • Marcar múltiples segmentos (no sombreados) como no utilizados POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • Marcar un solo segmento como usado: POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • Marcar un solo segmento como no utilizado: DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

Como parte de este cambio, los Coordinadores API correspondientes han quedado obsoletos y se eliminarán en una versión futura:

  • POST /druid/coordinator/v1/datasources/{dataSourceName}
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}

El Coordinador ahora llama al Overlord para atender estas solicitudes.

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> Procesamiento de consultas en tiempo real para cadenas de valores múltiples

El procesamiento de consultas en tiempo real ya no considera todas las cadenas como cadenas de valores múltiples durante el procesamiento de expresiones, lo que corrige una serie de errores y fallas inesperadas. Esto también debería mejorar el rendimiento de las consultas en tiempo real de expresiones en columnas de cadena.

Este cambio afecta las consultas topN para segmentos en tiempo real donde las filas de datos son implícitamente nulas, como las de una propiedad que falta en un objeto JSON.

Antes de este cambio, estos se manejaban como [] en lugar de nulos, lo que generaba inconsistencia entre el procesamiento de segmentos en tiempo real y los segmentos publicados. Al procesar segmentos, el valor se trató como [], que topN ignora. Después de la publicación, el valor pasó a ser nulo, lo que topN no ignora. La misma consulta podría tener resultados diferentes antes y después de persistir

Después de este cambio, el motor topN ahora trata [] como nulo cuando procesa segmentos en tiempo real, lo cual es consistente con los segmentos publicados.

Este cambio no afecta las columnas de cadenas de valores múltiples reales, independientemente de si son en tiempo real.

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> Unir sugerencias en consultas del motor de tareas MSQ

Druid ahora admite sugerencias para consultas SQL JOIN que utilizan el motor de tareas MSQ. Esto permite que las consultas proporcionen sugerencias para el tipo JOIN que debe usarse en cada nivel de unión. Las sugerencias de unión afectan de forma recursiva a las subconsultas.

<a name="32.0.0-changes-and-deprecations" href="#32.0.0-changes-and-deprecations">#</a> Cambios y obsolescencias

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> Compatibilidad ANSI-SQL y resultados de consultas

Se eliminó la compatibilidad con las configuraciones que le permitían mantener un comportamiento anterior que no era compatible con ANSI-SQL:

  • druid.generic.useDefaultValueForNull=true
  • druid.expressions.useStrictBooleans=false
  • druid.generic.useThreeValueLogicForNativeFilters=false

Ya no afectan los resultados de su consulta. Ahora solo se admite el comportamiento no heredado compatible con SQL.

Si las configuraciones están configuradas con el comportamiento heredado, los servicios de Druid no podrán iniciarse.

Si desea seguir obteniendo los mismos resultados sin esta configuración, debe actualizar sus consultas o sus resultados serán incorrectos después de la actualización.

Para obtener más información sobre cómo actualizar sus consultas, consulte la guía de migración.

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> Unir sugerencias en consultas del motor de tareas MSQ

Druid ahora admite sugerencias para consultas SQL JOIN que utilizan el motor de tareas MSQ. Esto permite que las consultas proporcionen sugerencias para el tipo JOIN que debe usarse en cada nivel de unión. Las sugerencias de unión afectan de forma recursiva a las subconsultas.

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

Utilice la nueva configuración opcional tryParseNumbers para formatos de entrada CSV y TSV para controlar cómo se tratan los números. Si está habilitado, cualquier número presente en la entrada se analizará de la siguiente manera:

  • tipo de datos largos para tipos enteros y
  • doble para números de coma flotante

De forma predeterminada, esta configuración está establecida en falso, por lo que las cadenas numéricas se tratarán como cadenas.

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion">#</a> Ingestión de streaming

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing">#</a> Controla cuántos segmentos se fusionan para su publicación

Ahora puede usar la propiedad maxColumnsToMerge en su especificación de supervisor para especificar la cantidad de segmentos que se fusionarán en una sola fase al fusionar segmentos para su publicación. Este límite afecta el número total de columnas presentes en un conjunto de segmentos para fusionar. Si se excede el límite, la fusión de segmentos se produce en varias fases. Druida fusiona al menos 2 segmentos en cada fase, independientemente de esta configuración.

<a name="32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29" href="#32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29">#</a> Clasificación de columnas para compactación con el motor de tareas MSQ (experimental)

La compactación que utiliza el motor de tareas MSQ ahora admite la clasificación de segmentos con columnas que no son de tiempo. Si forceSegmentSortByTime está configurado en la configuración de compactación o en el esquema inferido, sucede lo siguiente:

  • Omita agregar __time explícitamente como la primera columna del esquema de dimensiones, ya que ya forma parte del esquema.
  • Asegúrese de que las asignaciones de columnas se propaguen __time en el orden especificado por el esquema.
  • Configure forceSegmentSortByTime en el contexto de consulta MSQ.

  • Los coordinadores API para marcar segmentos como usados o no utilizados ahora están obsoletos y se eliminarán en una versión futura. Utilice en su lugar los Overlord API correspondientes. Para obtener una lista completa, consulte Nuevo Overlord APIs o #17545

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates">#</a> Actualizaciones de dependencia

Se han modificado las versiones de las siguientes dependencias:

  • javax.xml.bind ya no se utiliza. Druida ahora usa jakarta.xml.bind #17370
  • Se han actualizado varias dependencias para la consola web. Para obtener una lista completa, consulte #17381, #17365, #17363
  • Se eliminó la dependencia de file-loader para la consola web #17346
  • Guía de 4.2.2 a 5.1.0
  • git-commit-id-maven-plugin de 4.9.10 a 9.0.1 #17571
  • Netty de la versión 4.1.108.Final a 4.1.116.Final
