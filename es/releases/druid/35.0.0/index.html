druida druida-35.0.0

Apache Druid 35.0.0 contiene más de 229 funciones nuevas, correcciones de errores, mejoras de rendimiento, mejoras de documentación y cobertura de pruebas adicionales de 29 contribuyentes.

Consulte el conjunto completo de cambios para obtener detalles adicionales, incluidas correcciones de errores.

Revise las notas de actualización y los cambios incompatibles antes de actualizar a Druid 35.0.0. Si está actualizando varias versiones, consulte la página [Notas de actualización] (upgrade-notes.md), que enumera las notas de actualización para las versiones más recientes de Druid.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-java-support" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-java-support">#</a> Soporte de Java

Druid ahora es compatible con Java 21. Tenga en cuenta que algunas versiones de Java 21 encontraron problemas durante la prueba, específicamente Java 21.05-21.07. Si es posible, evite estas versiones.

Además, se eliminó la compatibilidad con Java 11. Actualice a Java 17 o 21.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29">#</a> Almacenamiento virtual (experimental)

El modo de estructura de almacenamiento virtual permite que los servidores históricos atiendan más segmentos de los que puede contener su disco físico. En lugar de cargar segmentos cuando se publican, los segmentos se cargan según demanda durante las consultas. Todos los segmentos innecesarios se eliminan del disco, pero se cargan nuevamente cuando el procesamiento de una consulta requiere ese segmento en particular.

Para habilitar el almacenamiento virtual, configure druid.segmentCache.virtualStorage en true.

Esta característica es experimental y tiene varias limitaciones. Para obtener más información, consulte la solicitud de extracción:

<a name="35.0.0-important-features%2C-cambios%2C-y-deprecaciones-nuevo-formato-de-entrada" href="#35.0.0-important-features%2C-cambios%2C-y-deprecaciones-nuevo-formato-de-entrada">#</a> Nuevo formato de entrada

Druid ahora admite un formato de entrada lines. Druid lee cada línea de una entrada como texto UTF-8 y crea una única columna llamada line que contiene la línea completa como una cadena. Utilícelo para leer datos orientados a líneas de forma sencilla para su posterior procesamiento.

#18433

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-multi-stage-query-task-engine">#</a> Motor de tareas de consulta de varias etapas

El motor de tareas MSQ es ahora una capacidad central de Druid en lugar de una extensión. Ha estado en la lista de carga de extensiones predeterminada durante varias versiones.

Elimine druid-multi-stage-query de druid.extensions.loadList en common.runtimes.properties antes de actualizar.

Druid 35.0.0 ignorará la extensión si está en la lista de carga. Las versiones futuras de Druid no podrán iniciarse porque no pueden localizar la extensión.

#18394

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-improved-monitor-loading" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-improved-monitor-loading">#</a> Carga de monitor mejorada

Ahora puede especificar monitores en common.runtime.properties y cada monitor se cargará solo en los tipos de servidor aplicables. Anteriormente, era necesario definir monitores en el archivo runtime.properties específico para el servicio al que está destinado el monitor.

#18321

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-exact-count-extension" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-exact-count-extension">#</a> Extensión de recuento exacto

Una nueva extensión de colaborador (druid-exact-count-bitmap) agrega soporte para el conteo de cardinalidad exacta usando Roaring Bitmap en una columna larga.

#18021

<a name="35.0.0-important-features%2C-cambios%2C-y-deprecaciones-mejoradas-%60indexspec%60" href="#35.0.0-important-features%2C-cambios%2C-y-deprecaciones-mejoradas-%60indexspec%60">#</a> indexSpec mejorado

Los usuarios ahora pueden especificar una especificación de formato para cada columna JSON individualmente, lo que anulará el IndexSpec definido en el trabajo de ingesta. Además, se puede configurar un IndexSpec predeterminado para todo el sistema utilizando la propiedad druid.indexing.formats.indexSpec.

<a name="35.0.0-functional-area-and-related-changes-ingestion-dimension-schemas" href="#35.0.0-functional-area-and-related-changes-ingestion-dimension-schemas">#</a> Esquemas de dimensiones

En el momento de la ingesta, los esquemas de dimensiones en dimensionsSpec ahora se validan estrictamente con respecto a los tipos permitidos. Anteriormente, un tipo no válido volvería a la dimensión de cadena. Ahora, tales valores son rechazados. Los usuarios deben especificar un tipo que sea uno de los tipos permitidos. Al omitir el tipo, el valor predeterminado sigue siendo cadena, lo que preserva la compatibilidad con versiones anteriores.

<a name="35.0.0-functional-area-and-related-changes-querying" href="#35.0.0-functional-area-and-related-changes-querying">#</a> Consultando

<a name="35.0.0-functional-area-and-related-changes-querying-segment-timeout" href="#35.0.0-functional-area-and-related-changes-querying-segment-timeout">#</a> Tiempo de espera del segmento

Ahora puede configurar el tiempo de espera para el procesamiento de segmentos de una consulta.

Para establecer un tiempo de espera, configure druid.processing.numTimeoutThreads en un número bajo, como 3, en todos los nodos de datos donde desee habilitar esta función.

Luego, incluya el parámetro de contexto de consulta perSegmentTimeout en su consulta y configúrelo en un valor en milisegundos.

#18148

<a name="35.0.0-functional-area-and-related-changes-querying-caching-scan-query-results" href="#35.0.0-functional-area-and-related-changes-querying-caching-scan-query-results">#</a> Almacenamiento en caché de los resultados de la consulta de análisis

Druid ahora admite el almacenamiento en caché a nivel de resultados para consultas de escaneo.

De forma predeterminada, este comportamiento está desactivado. Para habilitarlo, anule la propiedad druid.*.cache.unCacheable.

#18568

<a name="35.0.0-functional-area-and-related-changes-querying-new-expressions-for-sketches" href="#35.0.0-functional-area-and-related-changes-querying-new-expressions-for-sketches">#</a> Nuevas expresiones para bocetos

Druid ahora admite las siguientes expresiones:

  • HLL_SKETCH_ESTIMATE_WITH_ERROR_BOUNDS
  • THETA_SKETCH_ESTIMATE_WITH_ERROR_BOUNDS

Estas estimaciones funcionan en una columna de boceto y tienen el mismo comportamiento que los agregadores de publicaciones.

Druid ahora admite las siguientes funciones de valores múltiples:

  • MV_FILTER_PREFIX: filtra una expresión de valores múltiples para incluir solo valores que comienzan con el prefijo especificado

Ahora puede escribir las excepciones que Druid encuentre como una fila y luego verificar si se espera la excepción. Para utilizar esta función, establezca el parámetro de contexto de consulta writeExceptionBodyAsResponseRow en true.

<a name="35.0.0-functional-area-and-related-changes-extensions-kubernetes" href="#35.0.0-functional-area-and-related-changes-extensions-kubernetes">#</a> Kubernetes

<a name="35.0.0-functional-area-and-related-changes-extensions-http-client" href="#35.0.0-functional-area-and-related-changes-extensions-http-client">#</a> HTTP client

Ahora puede configurar qué biblioteca HTTP client usa internamente el Fabric8 KubernetesClient para comunicarse con las tareas del servidor k8s en las que se ejecutan. El valor predeterminado sigue siendo el mismo client y la configuración que usa Druid 34. Las opciones adicionales que ahora están disponibles son okhttp y un JDK HttpClient nativo. El valor predeterminado client y la configuración deberían ser suficientes para la mayoría de los casos de uso.

Establezca la configuración de druid.indexer.runner.k8sAndWorker.http.httpClientType en vertx (predeterminado), okhttp o jdk.

#18540

#18587

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs">#</a> Registros de tareas

Para la ingesta sin el administrador intermedio, los registros de tareas persistentes ya no tienen el potencial de bloquearse indefinidamente. En cambio, existe un límite de tiempo para los registros persistentes que, si se incumple, dará como resultado que se abandone la persistencia. El tiempo de espera predeterminado es de 5 minutos, pero se puede configurar anulando druid.indexer.runner.logSaveTimeout con una duración, como PT60S.

Además, el almacenamiento del registro de tareas para el ejecutor Kubernetes ahora es opcional.

#18444 #18341

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-improved-fault-tolerance" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-improved-fault-tolerance">#</a> Tolerancia a fallos mejorada

El druid-kubernetes-overlord-extensions que utiliza Kubernetes para iniciar y administrar tareas en lugar de los gerentes intermedios ahora es más resistente contra ciertas fallas transitorias.

#18406

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-faster-task-failure">#</a> Fallo de tarea más rápido

Los pods de tareas ahora generarán eventos de trabajo Kubernetes cuando fallen durante la fase de creación del pod, y las tareas de K8 fallarán rápidamente en condiciones irrecuperables.

#18159

<a name="35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs" href="#35.0.0-functional-area-and-related-changes-extensions-mount-additional-configs">#</a> Montar configuraciones adicionales

Anteriormente, podía especificar una configuración adicional para montar en _common mediante una variable de entorno, pero esto solo se aplicaba al proceso Druid. Ahora también puede aplicar la misma configuración a las tareas de ingesta enviadas como trabajos Kubernetes (modo sin MiddleManager), lo que garantiza la coherencia en todos los tipos de tareas.

El druid.expressions.allowVectorizeFallback ahora tiene como valor predeterminado true. Además, SAFE_DIVIDE ahora puede vectorizar como alternativa.

#18549

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-">#</a> Embarcadero 12

Druid ahora usa Jetty 12. Su implementación puede verse afectada dependiendo, específicamente, en lo que respecta al cumplimiento de URI y las comprobaciones de host SNI.

Se ha agregado una nueva opción de configuración del servidor: druid.server.http.uriCompliance. Jetty 12 de forma predeterminada aplica estrictamente el formato URI RFC3986. Este es un cambio con respecto a Jetty 9. Para evitar posibles cambios importantes en las implementaciones de Druid existentes, esta configuración tiene como valor predeterminado LEGACY, que utiliza la aplicación del formato URI más permisivo que usaba Jetty 9. Si el clúster que opera no requiere compatibilidad heredada, le recomendamos utilizar el valor predeterminado de Jetty ascendente de RFC3986 en su implementación de Druid. Consulte la documentación del embarcadero para obtener más información.

Los servidores Jetty 12 realizan comprobaciones estrictas de SNI host0 cuando TLS está habilitado. Si el host con el que su client se conecta al servidor no coincide con lo que hay en el almacén de claves, incluso si solo hay un certificado en ese almacén de claves, devolverá una respuesta 400. Esto podría afectar algunos casos de uso, como las personas que se conectan a través de localhost por cualquier motivo. Si este cambio interrumpirá su implementación, puede optar por no participar configurando druid.server.http.enforceStrictSNIHostChecking en falso en runtime.properties para algunos o todos sus servicios Druid. Se recomienda modificar el comportamiento de client para adaptar este cambio en jetty en lugar de anular la configuración siempre que sea posible.

#18424 #18623

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication">#</a> Autenticación Kerberos

La configuración druid.auth.authenticator.kerberos.cookieSignatureSecret ahora es obligatoria.

#18368

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine">#</a> Motor de tareas de consulta de varias etapas

El motor de tareas MSQ es ahora una capacidad central de Druid en lugar de una extensión. Ha estado en la lista de carga de extensiones predeterminada durante varias versiones.

Elimine druid-multi-stage-query de druid.extensions.loadList en common.runtimes.properties antes de actualizar.

Druid 35.0.0 ignorará la extensión si está en la lista de carga. Las versiones futuras de Druid no podrán iniciarse porque no pueden localizar la extensión.

#18394

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension">#</a> extensión pac4j

Debido a la actualización de pac4j 4 a 5, la serialización de sesiones cambió del JavaSerializer de pac4j a la serialización estándar de Java. Como resultado, es posible que se cierre la sesión de clients de los clústeres que utilizan la extensión pac4j durante las actualizaciones continuas y sea necesario volver a autenticarse.

#18259

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Cambios incompatibles

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed">#</a> Se eliminó la compatibilidad con Java 11

Actualice a Java 17 o 21. Tenga en cuenta que algunas versiones de Java 21 encontraron problemas durante la prueba, específicamente Java 21.05-21.07. Si es posible, evite estas versiones.

#18424

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notas del desarrollador

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests">#</a> Pruebas de clúster integradas

Puede utilizar el nuevo marco de prueba de clúster integrado para ejecutar pruebas de integración ligeras utilizando un clúster Druid completamente funcional que se ejecuta en un único proceso, incluidas las extensiones que desee cargar, así como el almacén de metadatos ZooKeeper y Derby. Ya no necesita ejecutar mvn build, crear una imagen docker o incluso ejecutar scripts de inicio para realizar pruebas de integración.

#18147

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json">#</a> Columnas virtuales especializadas para JSON

El ColumnHolder devuelto por ColumnSelector ahora devuelve un SelectableColumn en lugar de un BaseColumn de getColumn(). El SelectableColumn puede ser un BaseColumn o puede ser una implementación proporcionada por una columna virtual. Las extensiones que necesitan recuperar columnas físicas de un ColumnSelector pueden verificar si la columna es un BaseColumn usando instanceof. Para mayor comodidad, el tipo de devolución de getColumnHolder en QueryableIndex se ha especializado en BaseColumnHolder, que siempre devuelve BaseColumn de getColumn(). Las extensiones que llaman a este método en QueryableIndex pueden almacenar el resultado en una variable de tipo BaseColumnHolder para evitar la necesidad de convertir la columna.

#18521

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed">#</a> Herramienta reset-cluster eliminada

Se ha eliminado la herramienta orientada al entorno de desarrollo y pruebas reset-cluster. Estaba desactualizado y no lograba borrar completamente el almacén de metadatos (faltan las tablas upgradeSegments y segmentSchemas agregadas en Druid 28 y 30 respectivamente). Esta herramienta no estaba destinada a casos de uso de producción, por lo que no debería haber ningún impacto para los operadores de clústeres.

#18246

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions">#</a> Cambio importante para las extensiones de metadatos SQL

El punto de extensión MetadataStorageActionHandler ahora tiene API más simples. Este es un cambio importante para cualquier extensión de metadatos SQL disponible. Los cambios para PostgreSQL, MySQL y SQLServer ya están completos. #18479

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed">#</a> DriudLeaderClient eliminado

DruidLeaderClient se eliminó de las extensiones y se reemplazó con una implementación basada en ServiceClient. Además, CoordinatorServiceClient para consultar API no principales expuestos por el Coordinador está disponible a través de druid-server.
