<a name="31.0.0-important-features-changes-and-deprecations-projections-experimental" href="#31.0.0-important-features-changes-and-deprecations-projections-experimental">#</a> Proyecciones (experimentales)

Druid 31.0.0 incluye soporte experimental para una nueva función llamada proyecciones. Las proyecciones son agregados previos agrupados de un segmento que se utilizan automáticamente en el momento de la consulta para optimizar la ejecución de cualquier consulta que "se ajuste" a la forma de la proyección al reducir tanto el cálculo como el costo de E/S al reducir el número de filas que deben procesarse. Las proyecciones están contenidas dentro de segmentos de una fuente de datos y aumentan el tamaño del segmento. Pero pueden compartir datos, como diccionarios de valores de columnas codificadas en diccionario, con las columnas del segmento base.

Actualmente, las proyecciones solo admiten la ingesta basada en JSON, pero pueden usarse en consultas que utilizan el motor de tareas MSQ o el nuevo motor Dart. El desarrollo futuro permitirá que se creen proyecciones como parte de la ingesta basada en SQL.

Tenemos muchos planes para seguir mejorando esta función en las próximas versiones, pero estamos entusiasmados de lanzarla para que los usuarios puedan comenzar a experimentar, ya que las proyecciones pueden mejorar drásticamente el rendimiento de las consultas.

Para obtener más información, consulte Proyecciones.

<a name="31.0.0-important-features%2C-cambios%2C-y-desaprobaciones-consultas-de-baja-latencia-alta-complejidad-usando-dart-%28experimental%29" href="#31.0.0-important-features%2C-changes%2C-and-deprecations-low-latency-high-complexity-queries-using-dart-%28experimental%29">#</a> Consultas de baja latencia y alta complejidad utilizando Dart (experimental)

La topología de tiempo de ejecución asincrónica distribuida (Dart) está diseñada para admitir consultas de alta complejidad, como uniones grandes, grupos de alta cardinalidad, subconsultas y expresiones de tablas comunes, que se encuentran comúnmente en cargas de trabajo de almacenamiento de datos ad-hoc. En lugar de utilizar motores de almacenamiento de datos como Spark o Presto para ejecutar consultas de alta complejidad, puede utilizar Dart, lo que alivia la necesidad de infraestructura adicional.

Para obtener más información, consulte Dardo.

<a name="31.0.0-functional-areas-and-related-changes-querying" href="#31.0.0-functional-areas-and-related-changes-querying">#</a> Consultando

<a name="31.0.0-functional-areas-and-related-changes-querying-dart" href="#31.0.0-functional-areas-and-related-changes-querying-dart">#</a> Dardo

Dart es un motor de consultas con trabajadores de subprocesos múltiples que realiza mezclas en memoria para proporcionar simultaneidad ajustable y costos de infraestructura para consultas de alta complejidad y baja latencia.

Para probar Dart, configure druid.msq.dart.enabled en true en sus propiedades de tiempo de ejecución comunes. Luego, puede seleccionar Dart como motor de consulta en la consola web o mediante API /druid/v2/sql/dart, que acepta la misma carga útil JSON que /druid/v2/sql. Dart es totalmente compatible con las formas de consulta actuales de Druid y el formato de almacenamiento de Druid. Eso significa que puede probar Dart con sus consultas y fuentes de datos existentes.

<a name="31.0.0-functional-areas-and-related-changes-querying-projections" href="#31.0.0-functional-areas-and-related-changes-querying-projections">#</a> Proyecciones

Como característica experimental, las proyecciones aún no están bien documentadas, pero se pueden definir para la ingesta de streaming y la ingesta por lotes "clásica" como parte del dataSchema. Para obtener un ejemplo de especificación de ingesta, consulte la descripción de la solicitud de extracción para #17214.

El campo groupingColumns en la especificación define el orden en que se ordenan los datos en la proyección. En lugar de definir explícitamente la granularidad como para la tabla base, la define con una columna virtual. Durante la ingesta, la lógica de procesamiento encuentra la columna virtual de granularidad "más fina", que es una expresión timestamp_floor y la utiliza como columna __time para la proyección. No es necesario que las proyecciones tengan definida una columna de tiempo. En estos casos, aún pueden coincidir con consultas que no se agrupan a tiempo.

Se han agregado nuevos indicadores de contexto de consulta para ayudar en la experimentación con proyecciones:

  • useProjection acepta un nombre de proyección específico e indica al motor de consulta que debe usar esa proyección y fallará la consulta si la proyección no coincide con la consulta.
  • forceProjections acepta verdadero o falso e indica al motor de consulta que debe usar una proyección y fallará la consulta si no puede encontrar una proyección coincidente.
  • noProjections acepta verdadero o falso e indica a los motores de consulta que no utilicen ninguna proyección.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Notas de actualización

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array">#</a> El modo de ingesta de matriz ahora está predeterminado en matriz

El indicador de contexto de ingesta basado en SQL arrayIngestMode ahora tiene como valor predeterminado array en lugar de mvd. Esto significa que los tipos SQL VARCHAR ARRAY ya no se traducen ni se almacenan implícitamente en columnas VARCHAR, sino que se almacenan como VARCHAR ARRAY. Este cambio permite que otros tipos de matriz, como BIGINT ARRAY y DOUBLE ARRAY, se inserten con MSQ en sus respectivos tipos de columnas de matriz en lugar de fallar como lo hacen en el modo mvd.

Para continuar almacenando cadenas de valores múltiples, modifique cualquier consulta de inserción/reemplazo para ajustar los tipos de matriz con el operador ARRAY_TO_MV.

Se implementó una validación para evitar mezclar columnas VARCHAR y VARCHAR ARRAY en la misma tabla, por lo que cualquier ingesta afectada por este cambio fallará y proporcionará un mensaje de error descriptivo en lugar de mostrar un comportamiento inesperado.

Se ha eliminado la opción arrayIngestMode de none. Se introdujo antes de la lógica de validación de tablas como un medio para que los operadores de clúster obligaran a los redactores de consultas a configurar explícitamente array o mvd en sus contextos de consulta, pero proporciona poca utilidad en Druid 31.

Consulte los siguientes temas para obtener más información:

  • [Ingerir dimensiones de valores múltiples] (https://druid.apache.org/docs/latest/querying/multi-value-dimensions#sql-based-ingestion) para saber cómo ingerir cadenas de valores múltiples.
  • Ingesta de matrices para la ingesta de matrices.

#16789

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-task-action-audit-logging" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-task-action-audit-logging">#</a> Se eliminó el registro de auditoría de acciones de tareas

Se eliminó el registro de auditoría de acciones de tareas en desuso. Este cambio incluye las siguientes actualizaciones:

  • El punto final /indexer/v1/task/{taskId}/segments ya no es compatible.
  • Druid no escribe ni lee la tabla de metadatos druid_taskLog.
  • Druida ignora la propiedad druid.indexer.auditlog.enabled.
  • Druida no emite la métrica task/action/log/time.

Estos cambios son compatibles con todas las extensiones de almacenamiento de metadatos existentes.

#16309

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-firehose-and-firehosefactory" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-removed-firehose-and-firehosefactory">#</a> Se eliminaron Firehose y FirehoseFactory

Se eliminaron Firehose y FirehoseFactory y las implementaciones restantes. Apache dejó de admitir soporte para mangueras contra incendios Druid en la versión 0.17. La compatibilidad con la ingestión de mangueras contra incendios se eliminó en la versión 26.0.

#16758

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-front-coded-dictionaries" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-front-coded-dictionaries">#</a> Diccionarios codificados frontalmente

<!--Continúa esto hasta el 32. Luego muévelo a cambios incompatibles -->

Los diccionarios codificados frontalmente reducen el almacenamiento y mejoran el rendimiento al optimizar las cadenas donde la parte frontal es similar.

Una vez que esta función esté activada, no podrá degradar fácilmente a una versión anterior que no la admita.

Para obtener más información, consulte Guía de migración: diccionarios codificados frontalmente. Si ya estás utilizando esta función, no necesitas realizar ninguna acción.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-storage-improvement-features" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-storage-improvement-features">#</a> Funciones de mejora del almacenamiento

Druid 31.0.0 incluye mejoras de almacenamiento que no son compatibles con versiones anteriores. Una vez que habilite clasificación de segmentos flexibles o compresión para columnas complejas, no podrá degradar a una versión anterior a 31.0.0. Pruebe minuciosamente estas funciones antes de implementarlas en su clúster de producción.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Cambios incompatibles

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-the-scan-query-legacy-mode">#</a> Se eliminó el modo heredado de consulta de escaneo

Se eliminó el modo heredado de consulta de escaneo nativo. Se introdujo en Druid 0.11 para mantener la compatibilidad durante una actualización de versiones anteriores de Druid donde la consulta de escaneo era parte de una extensión contrib.

#16659

"legacy":false codificado después de la eliminación del modo heredado para evitar errores durante las actualizaciones o degradaciones continuas.

#16793

<a name="31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading" href="#31.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-zk-based-segment-loading">#</a> Carga de segmentos basada en ZK

La carga de segmentos basada en ZK ahora está deshabilitada. ZK servedSegmentsPath quedó obsoleto en Druid 0.7.1. Esta ruta heredada ha sido reemplazada por liveSegmentsPath.

Los procesos de servicio de segmentos como Peones, Históricos e Indexadores ya no crean entradas ZK loadQueuePath. Las propiedades druid.zk.paths.loadQueuePath y druid.zk.paths.servedSegmentsPath ya no se utilizan.

Primero pase a la carga de segmentos basada en HTTP y luego realice la actualización de la versión.

<a name="31.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#31.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notas del desarrollador

  • Se corrigió la advertencia hibernate-validator que se muestra durante la compilación de maven #16746
  • Se reemplazó la interfaz StorageAdapter por la interfaz CursorHolder #17024

<a name="31.0.0-upgrade-notes-and-incompatible-changes-%60storageadapter%60-changes" href="#31.0.0-upgrade-notes-and-incompatible-changes-%60storageadapter%60-changes">#</a> StorageAdapter cambios

Si escribe extensiones personalizadas, específicamente motores de consulta o cualquier otra cosa que involucre la interfaz StorageAdapter, 31.0.0 incluye cambios en los API de bajo nivel que pueden afectarlo. Todos los métodos en StorageAdapter ahora arrojan una excepción de Druida.

Prepárese para estos cambios antes de actualizar a 31.0.0 o posterior. Para obtener más información, consulte las siguientes solicitudes de extracción:

  • #16985
  • #16849
  • #16533
