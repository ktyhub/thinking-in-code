druida druida-29.0.0

Apache Druid 29.0.0 contiene más de 350 funciones nuevas, correcciones de errores, mejoras de rendimiento, mejoras de documentación y cobertura de pruebas adicionales de 67 contribuyentes.

Consulte el conjunto completo de cambios para obtener detalles adicionales, incluidas correcciones de errores.

Revise las notas de actualización antes de actualizar a Druid 29.0.0. Si está actualizando varias versiones, consulte la página [Notas de actualización] (upgrade-notes.md), que enumera las notas de actualización para las versiones más recientes de Druid.

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT y DESPIVOT (experimental)

Druid 29.0.0 agrega soporte experimental para los operadores SQL PIVOT y UNPIVOT.

El operador PIVOT realiza una agregación y transforma filas en columnas en la salida. La siguiente es la sintaxis general del operador PIVOT:

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

El operador UNPIVOT transforma los valores de las columnas existentes en filas. La siguiente es la sintaxis general del operador UNPIVOT:

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> Soporte de rango en funciones de ventana (experimental)

Las funciones de ventana (experimentales) ahora admiten rangos donde ambos puntos finales son ilimitados o son la fila actual. Los rangos funcionan en modo estricto, lo que significa que Druid fallará en las consultas que no sean compatibles. Puede desactivar el modo estricto para rangos configurando el parámetro de contexto windowingStrictValidation en false.

El siguiente ejemplo muestra una expresión de ventana con especificaciones de marco RANGE:

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

#15703 #15746

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-improved-inner-joins" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-improved-inner-joins">#</a> Uniones INNER mejoradas

Druid ahora admite condiciones de unión arbitrarias para la unión INNER. Cualquier subcondición que no se pueda evaluar como parte de la unión se convierte en un filtro posterior a la unión. Las capacidades de unión mejoradas permiten a Druid admitir aplicaciones como Tableau de manera más efectiva.

#15302

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-improved-concurrent-append-and-replace-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-improved-concurrent-append-and-replace-%28experimental%29">#</a> Concurrente mejorado agregar y reemplazar (experimental)

Ya no es necesario determinar manualmente el tipo de bloqueo de tarea para agregar y reemplazar simultáneamente (experimentalmente) con el contexto de tarea taskLockType. En cambio, Druid ahora puede determinarlo automáticamente. Puede usar el parámetro de contexto "useConcurrentLocks": true para tareas y fuentes de datos individuales o habilitar la adición y reemplazo simultáneos a nivel de clúster usando druid.indexer.task.default.context.

#15684

<a name="29.0.0-important-features%2C-cambios%2C-y-desaprobaciones-primer-y-último-agregador-para-tipos-de-datos-dobles%2C-float%2C-y-largos" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-first-and-last-aggregators-for-double%2C-float%2C-and-long-data-types">#</a> Primeros y últimos agregadores para tipos de datos dobles, flotantes y largos

Druid ahora admite el primer y último agregador para los tipos doble, flotante y largo en especificaciones de ingesta nativas y MSQ y consultas MSQ. Anteriormente, solo eran compatibles con consultas nativas. Para obtener más información, consulte Primer y último agregador.

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-support-for-logging-audit-events" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-support-for-logging-audit-events">#</a> Soporte para el registro de eventos de auditoría

Se agregó soporte para registrar eventos de auditoría y cobertura mejorada de puntos finales REST API auditados. Para habilitar el registro de eventos de auditoría, establezca la configuración druid.audit.manager.type en log tanto en Coordinator como en Overlord o en common.runtime.properties. Cuando configura druid.audit.manager.type en sql, los eventos de auditoría se conservan en el almacén de metadatos.

En ambos casos, Druid audita los siguientes eventos:

  • Coordinador
    • Actualizar reglas de carga
    • Actualizar búsquedas
    • Actualizar la configuración dinámica del coordinador
    • Actualizar la configuración de autocompactación
  • Señor supremo
    • Enviar una tarea
    • Crear/actualizar un supervisor
    • Actualizar la configuración del trabajador
  • Extensión de seguridad básica
    • Crear usuario
    • Eliminar usuario
    • Actualizar credenciales de usuario
    • Crear rol
    • Eliminar rol
    • Asignar rol al usuario
    • Establecer permisos de roles

#15542

<a name="29.0.0-functional-area-and-related-changes-general-ingestion-kill-task-improvements" href="#29.0.0-functional-area-and-related-changes-general-ingestion-kill-task-improvements">#</a> Mejoras en la tarea de eliminación

Tareas de eliminación mejoradas de la siguiente manera:

  • Se resolvió un problema por el cual la función de eliminación automática no respetaba el período de búfer especificado. Esto ocurría cuando varios segmentos no utilizados dentro de un intervalo se marcaban como no utilizados en diferentes momentos.
  • Puedes enviar tareas de eliminación con un parámetro opcional maxUsedStatusLastUpdatedTime. Cuando se establece en una fecha y hora, la tarea de eliminación considera los segmentos en el intervalo especificado marcados como no utilizados a más tardar en esta hora. El comportamiento predeterminado es eliminar todos los segmentos no utilizados en el intervalo, independientemente del momento en que los segmentos se marcaron como no utilizados.

#15710

<a name="29.0.0-functional-area-and-related-changes-general-ingestion-segment-allocation-improvements" href="#29.0.0-functional-area-and-related-changes-general-ingestion-segment-allocation-improvements">#</a> Mejoras en la asignación de segmentos

El filtro de igualdad en columnas auto de tipo mixto que contienen matrices ahora se debe filtrar como su tipo de presentación. Esto significa que si alguna fila es una matriz (por ejemplo, los metadatos del segmento y information_schema informan el tipo como algún tipo de matriz), entonces las consultas nativas también deben filtrar como si fueran algún tipo de matriz.

La consola Druid ahora configura el parámetro arrayIngestMode en el flujo de carga de datos y su valor puede persistir en la pestaña SQL a menos que se actualice manualmente. Por lo tanto, al cargar dimensiones o matrices de valores múltiples en la consola web de Druid, tenga en cuenta el valor del parámetro arrayIngestMode, para evitar mezclar MVD y matrices en la misma columna de una fuente de datos accidentalmente.
