Funciones importantes, cambios y obsolescencias

Esta sección contiene información importante sobre funciones nuevas y existentes. ###Java Se ha eliminado la compatibilidad con Java 21. Debe actualizar a Java 25.

Declaraciones DDL para el catálogo (experimental)

Druid ahora admite declaraciones CREATE y ALTER para administrar metadatos en el catálogo. Úselos para declarar las columnas de una tabla, la partición de tiempo, la agrupación, las proyecciones agregadas y el diseño físico, en lugar de configurarlos en cada especificación de ingesta. Esta característica está desactivada de forma predeterminada. Para habilitarlo, configure druid.sql.planner.enableCatalogDdl en true. Para obtener más información, consulte Catálogo. #19830 #20377 #20452 #19770 #19711

Filtrado basado en encabezados de Kafka

Los supervisores de Kafka ahora pueden filtrar registros por sus encabezados. Esto reduce el consumo de CPU y memoria cuando solo se necesitan algunos de los registros de un tema. Para usar el filtro, agregue headerBasedFilterConfig al ioConfig del supervisor. Utilice un filtro in donde dimension es el nombre del encabezado y values enumera los valores del encabezado que se van a ingerir. Los registros cuyo valor de encabezado no está en la lista se eliminan y las compensaciones siguen avanzando. El filtrado es permisivo: los registros se incorporan si no tienen el encabezado, si el valor del encabezado es nulo, está vacío o no se puede decodificar, o si la evaluación falla. La nueva métrica ingest/events/filtered informa cuántos registros se eliminó el filtrado de encabezados. #18525

Parámetros de contexto de consulta escritos

Los parámetros de contexto de consulta comunes enumerados en Referencia de contexto de consulta y Consultas de análisis ahora se escriben como descriptores QueryContextParameter. Los siguientes cambios se aplican al manejo del contexto de consulta:

  • Los parámetros enteros y largos rechazan valores que no son enteros exactos en lugar de truncarlos o ajustarlos. Por ejemplo 1.5 y valores fuera de rango. Todavía se aceptan valores integrales como 5.0 o "5.0". Los valores no válidos ahora generan un mensaje de error: "El parámetro de contexto de consulta [x] debe ser..."
  • Un valor nulo en el contexto de consulta, o SET x = NULL, ya no borra un valor predeterminado configurado con druid.query.default.context o la configuración dinámica del Broker. El valor predeterminado se aplica como si la clave no estuviera configurada. Anteriormente, el valor nulo llegaba a los lectores, que utilizaban el valor predeterminado incorporado. Para anular un valor predeterminado configurado, establezca un valor explícito.
  • maxSubqueryBytes es un parámetro de cadena escrito que acepta un número de bytes automático, deshabilitado o no negativo, como lo hace la barandilla de subconsulta. Los valores no válidos como SET maxSubqueryBytes = TRUE ahora fallan durante la validación y ahora se aceptan números como 1e9. #20555

Controlador JDBC druida

Druid ahora proporciona su propio controlador JDBC que utiliza el punto final /druid/v2/sql/. Le recomendamos que cambie del controlador Avatica a este controlador. El nuevo controlador proporciona los siguientes beneficios: administración de conexiones del lado del controlador que no requiere equilibrio de carga fijo, transmisión de resultados, soporte para declaraciones SET y soporte para motores SQL no nativos. #19951

Netty 4.2

Druid ahora usa Netty 4.2 para su HTTP client. Anteriormente, Druid usaba Netty 3. Este es un cambio sustancial en las características de la memoria:

  • Memoria directa: HTTP client ahora consume algo de memoria directa. Es posible que los operadores que se acerquen a su presupuesto -XX:MaxDirectMemorySize deban aumentarlo.
  • Búfers agrupados: los búferes ahora están agrupados, por lo que la memoria residente puede aparecer más alta que en Netty 3, incluso cuando está inactiva. Esto es normal para un asignador agrupado. Hay nuevas configuraciones que controlan el comportamiento de HTTP client: druid.global.http.connectTimeout, druid.global.http.allocator, druid.broker.http.connectTimeout y druid.broker.http.allocator. También puede configurar algunas configuraciones de Netty directamente. #19567

Filtrado de calidad de servicio para Coordinador

Ahora puede habilitar el filtrado de QoS para el Coordinador para evitar que una ráfaga de solicitudes API lentas agote el grupo de subprocesos y bloquee las comprobaciones de estado. Utilice druid.coordinator.server.maxConcurrentRequests para configurar esta función (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Establezca esta propiedad en 0 para desactivarla. Los puntos finales con estado de líder están excluidos del límite, por lo que los balanceadores/monitores de carga no se ven afectados. #19271

Área funcional y cambios relacionados

Esta sección contiene release note detallados separados por áreas.

Ingestión

  • Se agregó soporte para expresiones regulares RE2/J para el formato de entrada regex #19514
  • Se modificó el S3 client para utilizar la política de reintento estándar recomendada por AWS. Puede personalizar la estrategia de reintento usando druid.s3.retryMode y druid.s3.maxAttempts #19892
  • La ingesta de Protobuf ahora mantiene el valor predeterminado de los campos proto3 que no están marcados como opcionales. Anteriormente, un campo int32 que contenía 0 (o una cadena que contenía "", un bool que contenía false, un enum que contenía su primer valor) se ingería como nulo. Estos campos ahora se incorporan como su valor real. #20485

Ingestión basada en SQL

  • Los trabajadores ahora solo pasan el contexto de trabajo necesario en lugar de todo el contexto de trabajo al contexto de tarea. #20650

Ingestión de streaming

Ingesta de particiones seleccionadas

Los supervisores de Kafka ahora aceptan ioConfig.partitionIds, que le permite ingerir solo particiones seleccionadas de un tema. Por ejemplo, puede utilizarlo para la ingesta de diagnóstico independiente. #20474

Mejoras en el escalador automático basado en costos
  • Ahora puede simular el escalador automático basado en costos para Kafka para ayudar a determinar el recuento óptimo de tareas para diferentes cantidades de retraso. #19687
  • Ahora puede establecer un umbral de retraso crítico para el escalador automático basado en costos. Cuando el retraso alcanza el 75% del umbral, el escalador automático pasa por alto el límite de escalamiento. Cuando el retraso alcanza el 100 %, el escalador automático aumenta hasta el recuento máximo de tareas. #19655
  • Ahora puede optar por configurar el tiempo de reutilización para el escalador automático basado en costos para un supervisor de una de dos maneras:
    • Alta sensibilidad: Establezca minScaleUpDelay / minScaleDownDelay < taskDuration. Por ejemplo, si es minScaleUpDelay = taskDuration / 2, habrá como máximo 1 evento de escalado entre 2 transferencias de tareas.
    • Baja sensibilidad: Establezca minScaleUpDelay / minScaleDownDelay > taskDuration. En este caso, el tiempo de reutilización se ignora de manera efectiva y el escalado se produce únicamente al transferir la tarea. #20706
  • El escalador automático basado en costos ahora utiliza promedios móviles en lugar de valores instantáneos de métricas de tareas para tomar decisiones para el escalador automático basado en costos. Esto conduce a un escalamiento más fluido, pero a veces puede tener el costo de respuestas ligeramente retrasadas al cambio en las tendencias métricas que ocurren hacia el final del ciclo de vida de la tarea. Para una mayor sensibilidad a las tendencias cambiantes, configure minScaleUpDelay y minScaleDownDelay para que sean más pequeños que taskDuration.
Otras mejoras en la ingesta de streaming
  • Se corrigió un error por el cual una tarea de indexación de Kafka reportaba un índice de inactividad de sondeo de 1.0 (es decir, completamente inactivo) antes de que cualquier muestra estuviera realmente disponible, lo que podía sesgar el índice de inactividad promedio del escalador automático del supervisor entre tareas. #20783

Consultando

Tiempo de planificación de consultas

Ahora puede limitar cuánto tiempo dedica el Broker a planificar una consulta SQL con la nueva propiedad de tiempo de ejecución druid.sql.planner.maxPlanningTimeMs. También puede configurarlo por consulta utilizando el parámetro de contexto de consulta maxPlanningTimeMs. Cuando la planificación excede el presupuesto configurado, la consulta falla con un error de tiempo de espera de consulta HTTP 504 en lugar de bloquear un subproceso del Broker. El valor predeterminado es 0, que desactiva el tiempo de espera. #20314

Se corrigieron fallas de JDK HTTP client causadas por avances de respuesta de consulta

Los corredores e históricos ahora envían los avances HTTP X-Druid-Response-Complete y X-Error-Message solo cuando la solicitud incluye el encabezado TE: trailers. Clients que lean estos avances deben enviar ese encabezado. Esto corrige fallas de consulta (java.net.ProtocolException: CR expected) en java.net.http.HttpClient-based clients, incluido el controlador Druid JDBC, en JDK 17.0.21, 21.0.13 y 25.0.5. #20717

Otras mejoras en las consultas

  • Ahora puede utilizar Dart para consultar tablas de metadatos como las del esquema sys #19952
  • CAST(x AS LONG) ahora se acepta como alias para CAST(x AS BIGINT) en Druid SQL #20402
  • Se agregó el filtro datasource a la tabla sys.segments #19718
  • Se agregó soporte de marco a las funciones de ventana FIRST_VALUE y LAST_VALUE #19301
  • Se mejoró el rendimiento de las consultas de series temporales, límites de tiempo y escaneo que se ejecutan en orden descendente #19947
  • Se mejoró el rendimiento de COALESCE #18400
  • Se mejoró la eficiencia de uso de S3 API para tareas MSQ usando almacenamiento duradero y exportación MSQ #19893
  • Validación mejorada para tipos de catálogo y análisis de cadenas de tipos nativos #19769
  • Actualizado a Calcita 1.42.0 #19976 #19370

Gestión de clústeres

Etiquetas de nodo Kubernetes

La extensión druid-kubernetes-extensions ahora admite un proveedor de configuración dinámica k8sNodeLabel, que resuelve los valores de configuración de las etiquetas del nodo Kubernetes en el que se ejecuta un proceso Druid. #20404

Plantilla de pod de peón

Ahora puede recuperar los nombres de las plantillas de pods de Peon configurados actualmente en Overlord utilizando el nuevo punto final GET /druid/indexer/v1/k8s/taskrunner/podTemplates. Devuelve el nombre de cada plantilla configurada. El punto final requiere permiso de lectura CONFIG y devuelve 404 cuando Overlord no está utilizando el adaptador de módulo de plantilla personalizado. #19712

Variables de entorno

El proveedor de configuración dinámica environment ahora omite las variables que no están configuradas en el entorno en lugar de producir un valor nulo que falla a los consumidores, como el supervisor de Kafka con un NullPointerException. Una variable omitida se registra en el nivel de información. #20381

Grupos de conexiones

Ahora puede configurar cómo el grupo de conexiones Druid rastrea la demanda de conexión usando druid.global.http.poolImplementation. El valor predeterminado es retaining. Con retaining, la piscina mantiene cada conexión que abre y reemplaza cada conexión obsoleta o rota por una nueva, de modo que la piscina se mantiene en su nivel máximo de agua. #20542 #20273

encabezados de respuesta HTTP

Druid ahora puede devolver opcionalmente X-Druid-Server, X-Druid-Service y X-Druid-Version en respuestas HTTP, lo que permite a los operadores identificar el proceso y la versión que atendió una solicitud directa o proxy del enrutador. Estos encabezados exponen la topología del clúster y la información de la versión, por lo que solo habilítelos si todos los clients tienen permiso para recibirlos. Para habilitarlos, configure druid.server.http.enableResponseIdentityHeaders en true. #20268

Soporte LDAP mejorado

Se agregó soporte para la autorización basada en grupos LDAP en servidores que no devuelven el atributo memberOf (como OpenLDAP). Configure groupBaseDn y groupSearch en el validador de credenciales LDAP para habilitar una búsqueda inversa de grupos que resuelva las membresías de grupos automáticamente. #19432

Visibilidad de la tabla

Los usuarios que consultan tablas para las que no tienen permiso de LECTURA por ahora ven un error "no encontrado" en lugar de un error "prohibido". Para restaurar el comportamiento anterior, configure druid.sql.planner.authorizeTableVisibility en false. Además, cuando se establece en true, INSERT y REPLACE requieren acceso de LECTURA y ESCRITURA a la tabla de destino. Si esta propiedad está configurada en false, solo requieren permiso de ESCRITURA. Independientemente del valor de esta propiedad, las tablas solo aparecen en INFORMACIÓN_SCHEMA si el usuario tiene acceso de LECTURA a ellas. Este es un cambio importante que afecta los permisos que necesita. Para obtener más información, consulte cambios de permisos para la ingesta basada en SQL. #20075

Variable de inicio de Java

Los mandos intermedios ahora respetan JAVA_HOME cuando utilizan el script bin/java, que debería estar presente en el directorio de trabajo. Druida usa la siguiente lógica

  • Si especificó un comando (por ejemplo, si config.getJavaCommand no es nulo), utilícelo.
  • Si bin/run-java existe, úselo
  • Usa java #19709

Agregar filtrado de QoS para puntos finales del Coordinador

Se agregó filtrado de QoS configurable al Coordinador para evitar que una ráfaga de solicitudes lentas de API agote el grupo de subprocesos y bloquee las comprobaciones de estado. Se agregó una nueva configuración: druid.coordinator.server.maxConcurrentRequests (predeterminada: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8)), configure <= 0 para deshabilitar). Los puntos finales con estado de líder están excluidos del límite, por lo que los monitores y balanceadores de carga no se ven afectados. #19271

Otras mejoras en la gestión de clústeres

  • Se agregó un tipo de bloqueo de tareas KILL que pueden usar las tareas de eliminación integradas para que el UnusedSegmentsKiller no omita intervalos con ingestas activas #19921
  • Se agregó soporte para PostgreSQL a la herramienta export-metadata #19698
  • Los peones que ejecutan tareas que no atienden consultas (por ejemplo, tareas por lotes, de compactación y MSQ) ahora ignoran druid.server.http.unannouncePropagationDelay y cierran sin esperar. Las tareas de transmisión en tiempo real aún respetan el retraso #20444
  • Enlace de puerto mejorado. Los nodos Druid ahora pueden anunciar un puerto de texto sin formato diferente para el descubrimiento de pares mientras vinculan Jetty al puerto de servicio real #19598
  • Se redujo la huella del montón de segmentos cargados #20467
  • Se corrigió el shutdownAllTasks Overlord API (POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks), que devolvía un error 404 desde Druid 32.0.0. #20824

Gestión de datos

Saltar intervalos durante la compactación

La compactación automática ahora admite una configuración skipIntervals en la configuración de compactación de la fuente de datos, lo que permite excluir intervalos específicos de la compactación además del comportamiento skipOffsetFromLatest existente. Esto es útil, por ejemplo, para excluir un intervalo en el que se escribe activamente un trabajo de relleno o uno en el que falla constantemente la compactación. #19792

Mejor visibilidad para archivos de segmentos grandes

Druid ahora informa cuando su configuración de partición de rango o hash produce archivos de segmento demasiado grandes (particiones activas) en un período de tiempo. La ingesta de lotes nativa con partición de rango o hash ahora registra una advertencia y emite la métrica ingest/segments/oversized. La métrica cuenta los segmentos publicados con más del doble de filas maxRowsPerSegment o más del triple de targetRowsPerSegment para la partición de rangos. El informe de finalización de la tarea también incluye este recuento como oversizedSegments. #20173

Búsquedas de segmentos más rápidas

Ahora puede acelerar las búsquedas de segmentos en la línea de tiempo en memoria habilitando la búsqueda de intervalos rápidos. Esta función utiliza un índice de árbol de intervalos para organizar la línea de tiempo en la memoria para una carga y búsqueda de segmentos más rápida. Para utilizar esta función, configure druid.segment.timeline.fastIntervalSearch en true. #19138 #19861

Carga parcial del segmento

Druid ahora admite la carga parcial de segmentos para almacenamiento virtual (activada de forma predeterminada). Para desactivarlo, configure cualquiera de las siguientes opciones en false:

  • la propiedad de tiempo de ejecución druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • el parámetro de contexto de consulta virtualStoragePartialDownloadsEnabled #19739

Otras mejoras en la gestión de datos

  • Se agregó soporte para sumas de verificación de solicitud MD5 para almacenamiento compatible con S3. Para habilitar esta función, configure druid.s3.enableLegacyMd5 en true #20055
  • Se agregó soporte para empujar, extraer y eliminar segmentos en el almacenamiento profundo de Azure y Google Cloud sin compresión zip #20454 #20327 #20382 #20380
  • Se mejoró el algoritmo de carga para distribuir mejor las solicitudes entre niveles históricos cuando se usa almacenamiento virtual #20155
  • Se mejoró la eficiencia de las tareas de eliminación integradas #19772

Métricas y seguimiento

Métricas de almacenamiento por niveles

Las métricas de almacenamiento por niveles ahora brindan una mejor observabilidad de los históricos, con o sin almacenamiento virtual. Dos métricas, tier/required/capacity y tier/total/capacity, están obsoletas y se eliminarán en una versión futura. Utilice tier/storage/required y tier/storage/capacity en su lugar. #20199

Métrica task/run/time

Los emisores statsd y prometheus ahora emiten la dimensión taskStatus en task/run/time. Este es un cambio radical. Para obtener más información, consulte alertas sobre task/run/time. #20122

Otras métricas y mejoras de seguimiento

  • Las métricas de tareas de peón para clústeres que usan la extensión Overlord Kubernetes ahora incluyen una dimensión podTemplate. Esto facilita el monitoreo de clústeres que asignan diferentes tareas a diferentes plantillas de pod #20001
  • Se agregó mergeBuffer/maxSpillProximity, que mide qué tan cerca estuvo cualquier grupo por consulta de derramarse durante el período de emisión, como fracción en [0.0, 1.0] #19627
  • Se agregó taskType a las diversas métricas de recuento de tareas, para que pueda filtrarlas por tipo de tarea #20123

Extensiones de colaborador

Iceberg

La ingestión de Apache Iceberg ahora admite un lector vectorizado opcional respaldado por iceberg-arrow. Habilítelo con "useArrowReader": true; ajuste el procesamiento por lotes con arrowBatchSize (predeterminado 1024). La ruta Arrow admite archivos de datos Parquet, valores codificados en diccionario, evolución de esquemas, instantáneas de viajes en el tiempo, proyección de columnas y inserción de predicados. Las instantáneas que contienen archivos de eliminación posicional o de igualdad no son compatibles y Druid las rechaza con un error; utilice el lector estándar con reconocimiento de eliminación para esas instantáneas. La ruta de flecha no se puede dividir, por lo tanto, manténgala deshabilitada cuando se requiera un rendimiento por lotes paralelo. El lector predeterminado permanece sin cambios y ambas rutas coexisten bajo el mismo tipo de fuente de entrada Iceberg. #19510

Agente de políticas abiertas

Se agregó la extensión de colaborador druid-opa-authorizer, que permite la autorización a través de Open Policy Agent (OPA). Puede escribir políticas de Rego para controlar el acceso a los recursos de Druid según la identidad del usuario, la acción y el tipo de recurso. La extensión admite flujos de trabajo de autenticación básica y de autenticación LDAP. #19670

Ahora puede habilitar el filtrado de QoS para el Coordinador para evitar que una ráfaga de solicitudes API lentas agote el grupo de subprocesos y bloquee las comprobaciones de estado. Utilice druid.coordinator.server.maxConcurrentRequests para configurar esta función (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Establezca esta propiedad en 0 para desactivarla. Los puntos finales con estado de líder están excluidos del límite, por lo que los balanceadores/monitores de carga no se ven afectados. #19271

Cambios incompatibles

Cambios de permisos para la ingesta basada en SQL

Los cambios en visibilidad de la tabla afectan los permisos necesarios para la ingesta basada en SQL. INSERT y REPLACE ahora requieren acceso de LECTURA (además de ESCRITURA) en la tabla de destino. Para restaurar el comportamiento anterior, configure druid.sql.planner.authorizeTableVisibility en false. #20075

Alertas en task/run/time

Los emisores statsd y prometheus ahora emiten la dimensión taskStatus en task/run/time. Este es un cambio importante para los paneles y alertas en task/run/time:

  • statsd (modo no DogStatsD): los valores de dimensión se unen en el nombre de la métrica con puntos, por lo que druid.overlord.task.run.time.DATASOURCE.TASKTYPE se convierte en druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE. Las consultas con el nombre anterior dejan de recibir datos.
  • statsd (modo DogStatsD): Se agrega una etiqueta taskStatus. Las consultas existentes siguen funcionando y se agregan sobre ellas.
  • prometheus: Se añade una etiqueta taskStatus. Actualice cualquier consulta que seleccione un conjunto de etiquetas exacto y cualquier regla de grabación que asuma el conjunto de etiquetas anterior. Para mantener el comportamiento anterior, fije la lista de dimensiones anterior con druid.emitter.statsd.dimensionMapPath o druid.emitter.prometheus.dimensionMapPath. #20122

SysMonitor eliminado

SysMonitor se eliminó después de quedar obsoleto en Druid 27. Utilice OshiSysMonitor en su lugar. #20200

MariaDB Connector/J 3.x cambia el comportamiento del URI de conexión

El conector MariaDB JDBC se actualizó de 2.7.3 a 3.5.10, lo que tiene el siguiente impacto:

  • Para druid.metadata.storage.connector.connectURI con org.mariadb.jdbc.Driver, utilice jdbc:mariadb:. Un URI jdbc:mysql: heredado sigue siendo utilizable solo si incluye permitMysqlScheme. Por ejemplo, jdbc:mysql://<host>/druid?permitMysqlScheme, porque el almacenamiento de metadatos pasa el URI directamente al controlador.
  • Para fuentes de entrada SQL respaldadas por MariaDB y búsquedas JDBC con el druid.access.jdbc.enforceAllowedProperties=true predeterminado, utilice jdbc:mariadb:. La validación de propiedades JDBC de Druid no enruta jdbc:mysql: al analizador Connector/J 3.x, y permitMysqlScheme no está en el druid.access.jdbc.allowedProperties predeterminado. Agregar la opción por sí sola no es suficiente.
  • Los usuarios que continúen suministrando Connector/J 2.x no necesitan cambiar los URI jdbc:mysql: o jdbc:mariadb: existentes. Los usuarios de MySQL Connector/J no se ven afectados.
  • Las imágenes reconstruidas desde distribution/docker/Dockerfile.mariadb ahora instalan Connector/J 3.5.10 y deben seguir la guía 3.x anterior. #20036

Notas del desarrollador

Editor de código de consola web

Los editores de código de la consola web pasaron de Ace (ace-builds y react-ace) a Code Mirror 6. Todos los editores ahora comparten un único componente CodeEditor, incluido el banco de trabajo, las entradas SQL de la vista de exploración, las entradas JSON, los cuadros de diálogo de especificaciones y valores, el historial y la explicación. Dos gramáticas de Lezer, una para DruidSQL y otra para Hjson, controlan el resaltado y las terminaciones. #20507

Actualizaciones de dependencia

Druid 39.0.0 incluye una variedad de actualizaciones para dependencias como Calcite. Para obtener una lista completa, consulte Área - Etiqueta de dependencias en el hito.
