Funciones importantes, cambios y obsolescencias

Esta sección contiene información importante sobre funciones nuevas y existentes.

Área funcional y cambios relacionados

Esta sección contiene release note detallados separados por áreas.

Operador druida

Druid Operador es un controlador Kubernetes que gestiona el ciclo de vida de sus clústeres Druid. El operador simplifica la gestión de clústeres de Druidas con su lógica personalizada que se puede configurar a través de CRD Kubernetes.

#18435

Escalado automático basado en costos para la ingestión de streaming

Druid ahora admite el escalado automático basado en costos para la ingestión de streaming que optimiza el recuento de tareas al equilibrar la reducción del retraso con la eficiencia de los recursos. Esta estrategia de escalado automático utiliza la siguiente fórmula:

totalCost = lagWeight × lagRecoveryTime + idleWeight × idlenessCost

que representa el tiempo para eliminar el trabajo pendiente y el tiempo de cálculo:

lagRecoveryTime = aggregateLag / (taskCount × avgProcessingRate) — time to clear backlog
idlenessCost = taskCount × taskDuration × predictedIdleRatio — wasted compute time

#18819

Kubernetes climodo de exposición (experimental)

En kubernetes-overlord-extensions se agregó un modo experimental Kubernetes client. El nuevo modo utiliza fabric8 SharedInformers para almacenar en caché los metadatos de k8. Esto reduce en gran medida el tráfico API entre Overlord y el plano de control de k8s. Puede probar esta función utilizando la siguiente configuración:

druid.indexer.runner.useK8sSharedInformers=true

#18599

soporte de cgroup v2

Ahora se admite cgroup v2 y todas las métricas de cgroup ahora emiten cgroupversion para identificar qué versión se está utilizando.

Las siguientes métricas cambian automáticamente a v2 si se detecta v2: CgroupCpuMonitor, CgroupCpuSetMonitor, CgroupDiskMonitor,MemoryMonitor. CpuAcctDeltaMonitor falla correctamente si se detecta v2.

Además, CgroupV2CpuMonitor ahora también emite cgroup/cpu/shares y cgroup/cpu/cores_quota.

#18705

Consultar informes para Dart

Dart ahora admite informes de consultas para consultas en ejecución y completadas recientemente. Los informes se pueden recuperar desde el punto final /druid/v2/sql/queries/<sqlQueryId>/reports.

El formato de la respuesta es un objeto JSON con dos claves, "consulta" e "informe". La clave de "consulta" es la misma información que está disponible en el punto final /druid/v2/sql/queries existente. La clave "informe" es un mapa de informes que incluye un informe MSQ. Puede controlar el comportamiento de retención de informes utilizando las siguientes configuraciones:

  • druid.msq.dart.controller.maxRetainedReportCount: Número máximo de informes que se conservan. El valor predeterminado es 0, lo que significa que no se conservan informes.
  • druid.msq.dart.controller.maxRetainedReportDuration: Durante cuánto tiempo se conservan los informes en el formato de duración ISO 8601. El valor predeterminado es PT0S, lo que significa que la caducidad basada en el tiempo está desactivada.

#18886

Nuevo formato de segmento

El nuevo formato de segmento de la versión 10 mejora la versión 9. Está desactivado de forma predeterminada y no es compatible con versiones de formato de segmento anteriores.

Configure druid.indexer.task.buildV10=true para crear segmentos en el nuevo formato.

Si baja de categoría, deberá volver a indexar sus datos con una versión de formato de segmento compatible.

Puede utilizar la herramienta bin/dump-segment para ver los metadatos del segmento. La herramienta genera JSON serializado.

#18880 #18901

Consola web

Nueva información disponible en la consola web

La consola web ahora incluye información sobre la cantidad de procesadores disponibles y la memoria total (en bytes binarios).

Esta información también está disponible a través de la tabla sys.servers.

#18613

Otras mejoras de la consola web

  • Se agregó seguimiento para trabajadores inactivos para las etapas de ejecución de MSQ #18768
  • Se agregó un botón de actualización para vistas JSON y visores de escenario #18768
  • Ahora puede definir parámetros de tipo ARRAY en la vista de consulta #18586
  • Se modificaron las consultas de la tabla del sistema para que ahora utilicen automáticamente el motor nativo #18857
  • Gráficos de tiempo mejorados para admitir múltiples medidas #18701

Ingestión

  • Se agregó soporte para reintentos de código AWS InternalError #18720 *Mejora la ingestión para ser más resiliente. Las tareas de ingesta ya no fallan si falla la carga del registro de tareas con una excepción #18748
  • Se mejoró la forma en que Druid maneja situaciones en las que los datos no coinciden con el tipo esperado #18878
  • Se mejoró la ingesta de JSON para que Druid pueda calcular los valores de JSON directamente desde estructuras de diccionario o índice, lo que permite que la ingesta omita por completo los datos persistentes sin procesar de JSON. Esto reduce el tamaño de almacenamiento en disco #18589
  • Ahora puede elegir entre indexación completa basada en diccionario e indexación solo de valores nulos para campos largos/dobles en una columna anidada #18722

Ingestión basada en SQL

Configuraciones de ingesta adicionales

Ahora puede utilizar las siguientes configuraciones para controlar cómo se ingieren y almacenan sus datos:

  • maxInputFilesPerWorker: Controla el número máximo de archivos de entrada o segmentos por trabajador.
  • maxPartitions: controla el número máximo de particiones de salida para cualquier etapa, lo que afecta la cantidad de segmentos que se generan durante la ingesta.

#18826

Otras mejoras en la ingesta basada en SQL
  • Se agregó maxRowsInMemory para reemplazar rowsInMemory. rowsInMemory ahora funciona como una forma alternativa de proporcionar esa configuración y se ignora si se especifica maxRowsInMemory. Anteriormente, solo existía rowsInMemory #18832

Ingestión de streaming

Compensación y partición de registro

Ahora puede ingerir el desplazamiento del registro (offsetColumnName) y la partición (partitionColumnName) utilizando KafkaInputFormat. Sus nombres predeterminados son kafka.offset y kafka.partition respectivamente.

#18757

Otras mejoras en la ingesta de streaming
  • Supervisores mejorados para que no puedan finalizar tareas mientras el supervisor se detiene #18767
  • Se mejoró el escalador automático basado en retrasos para la ingesta de streaming #18745
  • Se mejoró el escalador automático del supervisor SeekableStream para esperar a que se completen las tareas antes de intentar operaciones de escala posteriores. Esto ayuda a evitar entradas duplicadas del historial del supervisor #18715

Consultando

Otras mejoras en las consultas

  • Se mejoró la experiencia del usuario para consultas regex_exp no válidas. Se devuelve un error ahora #18762

Gestión de clústeres

Capacidad dinámica para implementaciones basadas en Kubernetes

Druid ahora puede ajustar dinámicamente la capacidad del ejecutor de tareas.

Incluya el campo capacity en una llamada POST API a /druid/indexer/v1/k8s/taskrunner/executionconfig. Establecer un valor de esta manera anula druid.indexer.runner.capacity.

#18591

Tabla de propiedades del servidor

La tabla sys.server_properties expone las propiedades de tiempo de ejecución configuradas para cada servidor Druid. Cada fila representa un único par clave-valor de propiedad asociado con un servidor específico.

#18692

Otras mejoras en la gestión de clústeres

  • Se agregó filtrado de calidad de servicio para Overlord para que los hilos de verificación de estado no se bloqueen #18033

Gestión de datos

Otras mejoras en la gestión de datos

  • Se agregó la política de compactación mostFragmentedFirst que prioriza intervalos con los segmentos más pequeños sin compactar #18802
  • Se mejoró la forma en que se eliminan los archivos de segmentos para evitar que queden archivos de segmentos parciales en caso de una falla durante una operación de eliminación #18696
  • Compactación mejorada para que identifique dimensiones de valores múltiples para esquemas de dimensiones que pueden producirlas #18760
  • Se mejoró la confiabilidad al tirar de segmentos #18821

Métricas y seguimiento

Métricas de tareas

Todas las métricas de tareas ahora emiten las siguientes dimensiones: taskId, dataSource, taskType, groupId y id. Tenga en cuenta que id se emite por compatibilidad con versiones anteriores. Se eliminará en favor de la dimensión taskId en una versión futura.

#18876

Métricas de ingesta

Las siguientes métricas para tareas de streaming y por lotes ahora emiten los valores reales en lugar de 0: ingest/merge/time, ingest/merge/cpu y ingest/persists/cpu.

#18866

Métricas de statsd

Se han agregado las siguientes métricas a la lista predeterminada para statsd:

  • task/action/run/time
  • task/status/queue/count
  • task/status/updated/count
  • ingest/handoff/time

#18846

Otras métricas y mejoras de seguimiento

  • Se agregó la dimensión reason a la métrica ingest/events/thrownAway. Esto permite una mayor observabilidad sobre por qué ciertos eventos se excluyen lógicamente de la ingesta #188855

  • Se agregó registro para todos los controladores de una etapa antes de que comiencen o se detengan, lo que puede ayudarlo a comprender el orden de ejecución #18662

  • Se agregaron nuevas métricas del grupo de subprocesos Jetty para capturar estadísticas de subprocesos de servicio de solicitudes: jetty/threadPool/utilized, jetty/threadPool/ready y jetty/threadPool/utilizationRate #18883

  • Se agregaron las dimensiones tier y priority a la métrica segments/max #18890

  • Se agregó GroupByStatsMonitor, que incluye dimensiones dataSource y taskId para métricas emitidas en peones #18711

  • Se agregó la métrica task/waiting/time, que mide el tiempo que tarda una tarea en colocarse en el ejecutor de tareas para su programación y ejecución #18735

  • Se agregó supervisorId a las métricas de tareas de transmisión para ayudar a aclarar situaciones en las que varios supervisores ingieren datos en una única fuente de datos #18803

  • Se agregó StorageMonitor a druid.monitoring.monitors para medir el almacenamiento y el uso del almacenamiento virtual por caché de segmento #18742

  • Druida ahora registra lo siguiente:

  • total de bytes recopilados cuando se alcanza el límite máximo de bytes de dispersión y recopilación #18841

    • Métrica query/bytes para solicitudes fallidas #18842

  • Se modificó el seguimiento TTL del emisor Prometheus para considerar todas las combinaciones de valores de etiquetas en lugar de solo el nombre de la métrica. Las etiquetas no se rastrean cuando el TTL no está configurado #18718 #18689

  • Se modificó el ciclo de vida stop() para que se registre en el nivel info para que coincida con start() #18640

  • Se cambió el activador de emisión de métricas para que las métricas se emitan cada vez que se completa una tarea #18766

  • Se mejoró el emisor de métricas para que emita métricas para todas las tareas completadas #18766

Extensiones

Extensión SpectatorHistogram

  • Se agregaron funciones SQL SPECTATOR_COUNT y SPECTATOR_PERCENTILE #18885
  • Se mejoró el rendimiento de la extensión SpectatorHistogram mediante vectorización #18813

Notas de actualización y cambios incompatibles

Notas de actualización

Tareas del controlador MSQ

Al actualizar desde Druid 30 o una versión anterior, las tareas de MSQ query_controller pueden fallar durante una actualización continua debido a la adición de nuevos contadores que no son compatibles con estas versiones anteriores. Puede volver a intentar cualquier consulta fallida una vez completada la actualización; o puede configurar includeAllCounters en false en el contexto de consulta para cualquier trabajo MSQ que deba ejecutarse durante la actualización continua; o puedes actualizar primero a Druid 31–35 antes de actualizar a Druid 36.

#18761

Formato de segmento

Druid 36.0.0 admite la versión 10 del formato de segmento. Las versiones anteriores de Druid no admiten la versión 10. Si baja a una versión inferior, debe volver a indexar sus datos con una versión de formato de segmento compatible.

#18880

Métricas obsoletas

Los monitores de peones que anteriormente emitían la dimensión id de JettyMonitor, OshiSysMonitor, JvmMonitor, JvmCpuMonitor, JvmThreadsMonitor y SysMonitor para representar el ID de la tarea están en desuso y se eliminarán en una versión futura. Utilice la dimensión taskId en su lugar.

#18709

Métricas eliminadas

Se han eliminado las siguientes métricas obsoletas:

  • segment/cost/raw #18846
  • segment/cost/normalized #18846
  • segment/cost/normalization #18846
  • task/action/log/time #18649

Notas del desarrollador

Interfaces de archivos de segmento

Se han definido nuevas interfaces SegmentFileBuilder y SegmentFileMapper para reemplazar los usos directos de FileSmoosher y SmooshedFileMapper para abstraer el proceso de construcción y lectura de segmentos.

Los principales cambios visibles para los desarrolladores para los escritores de extensiones con implementaciones de columnas personalizadas es que la interfaz Serializer ha cambiado el método writeTo:

  • Ahora acepta un SegmentFileBuilder en lugar de un FileSmoosher
  • El método ColumnBuilder getFileMapper ahora devuelve SegmentFileMapper en lugar de SmooshedFileMapper.

Las extensiones que no proporcionan implementaciones de columnas personalizadas no deberían verse afectadas por estos cambios.

#18608

Otras mejoras para desarrolladores

  • Se agregó la capacidad de anular la imagen Kafka predeterminada para realizar pruebas #18739
  • Se cambió fastDecompressor a safeDecompressor #18930
  • Las extensiones ahora pueden proporcionar implementaciones de kits de consulta #18875
  • Se eliminaron las anulaciones de versiones en archivos pom individuales. Para obtener una lista completa, consulte la solicitud de extracción #18708
