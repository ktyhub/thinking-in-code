opentelemetry-java v1.68.0

API

  • Agregar protecciones nulas y registro de uso de API para seguimiento, métricas, propagación y contexto de API (#8913, #8968)
  • Agregar utilidades estables io.opentelemetry.api.impl.Base16EncodingUtils y TemporaryBuffers (#8929, #8955)
  • Corregir ejemplos de Javadoc no compilables en el contexto APIs (#8934)

Incubando

*Evitar advertencias de tipo falso en DeclarativeConfigProperties.toMap() (#8921)

Extensiones

  • Propagadores de seguimiento: Maneja escapes de URL con formato incorrecto en encabezados de Jaeger (#8912)
  • Propagadores de seguimiento: incluya el encabezado de depuración B3 en campos de propagación de encabezados múltiples (#8930)
  • Propagadores de seguimiento: se corrigió el análisis de indicadores hexadecimales en los encabezados de Jaeger (#8975)

SDK

  • Elimina las dependencias de utilidades internas entre módulos del recurso y vuelve a intentar el código (#8916)
  • Agregar compatibilidad experimental con SdkResourceProvider compartida por proveedores de rastreadores, medidores y registradores (#8865)

Rastros

  • Conservar vínculos de intervalo no válidos con atributos o estado de seguimiento (#8917)

Métricas

  • Utilice un trabajador de exportación dedicado en PeriodicMetricReader, ponga en cola vaciados simultáneos y agregue setExporterTimeout() con un valor predeterminado igual al intervalo de exportación (#8827)

Exportadores

  • Registro: vuelve a la marca de tiempo observada en SystemOutLogRecordExporter cuando la marca de tiempo no está configurada (#8944)
  • OTLP: cierre el cuerpo de la respuesta HTTP JDK en Content-Encoding no compatible (#8962)
  • OTLP: haga coincidir el encabezado Host sin distinguir entre mayúsculas y minúsculas en el remitente gRPC del canal administrado (#8957)
  • OTLP: corrige los atributos del servidor de métricas del exportador para hosts que java.net.URI no puede analizar (#8941)
  • OTLP: pasa la excepción original a la devolución de llamada de error del remitente HTTP JDK (#8963)
  • OTLP: reintente las exportaciones OkHttp gRPC en el hilo actual para evitar el rechazo por parte de los ejecutores limitados (#8965)
  • OTLP: restaurar el registro de reintento por intento en el remitente OkHttp gRPC (#8967)
  • OTLP: Javadoc correcto del generador de exportadores (#8996)
  • OTLP: Acepte 0 como sin límite para el tamaño máximo del cuerpo de la solicitud y del mensaje (#8945)
  • OTLP: la telemetría interna del exportador gRPC utiliza rpc.status_code en lugar de rpc.response.status.code cuando InternalTelemetryVersion está configurado en LATEST (#9007)
  • Prometheus: otorga prioridad a los ejemplos trace_id y span_id sobre los atributos filtrados (#8959)

Extensiones

  • ÚLTIMA HORA Incubadora: cambie SamplingIntent.create() y getTraceStateUpdater() de Function a BiFunction aceptando el SamplingDecision final y corrija casos de esquina de muestreo consistentes (#8952)
  • Configuración automática: haga coincidir las variables de entorno para las claves de configuración que contienen guiones bajos (#8933, #8951)
  • Configuración automática: admite tamaños de lote PeriodicMetricReader hasta otel.metric.export.max.batch.size (#8935)
  • Configuración automática: Javadoc SPI correcto (#8900)

Pruebas

  • Agregue afirmaciones fluidas de puntos métricos a MetricAssert (#8994)
  • Agregar un constructor que admita selectores de temporalidad de agregación a InMemoryMetricExporter (#8993)
