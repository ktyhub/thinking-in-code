appsmith v2.6.0

⚠️ Para usuarios de EE, antes de actualizar a v2.6.0, finalice la ejecución del flujo de trabajo temporal existente en v2.5.1

Appsmith se está moviendo hacia un nuevo motor de flujo de trabajo. No se puede confiar en que las ejecuciones que comenzaron en el antiguo motor Temporal se reanuden o finalicen después de actualizar a v2.6.0.

Una ejecución es una ejecución de un flujo de trabajo. Esto incluye ejecuciones en espera de que una persona apruebe una solicitud, incluso cuando no esté procesando nada activamente.

Qué hacer antes de actualizar:

  1. Actualice primero a v2.5.1 si tiene una versión anterior.
  2. Deje que finalicen todas las ejecuciones en Temporal, incluidas las que estén en espera de aprobación. Detenga una ejecución sólo si está dispuesto a abandonar el trabajo restante.
  3. En Configuración de administración → Instancia → Central de administración, revise y reconozca el punto de control v2.5.0 · Transición del motor de flujo de trabajo. Siga la guía de transición del motor de flujo de trabajo.
  4. Actualice a v2.6.0.

Posible tiempo de inactividad: la verificación de actualización puede impedir que se inicie todo el servidor Appsmith si encuentra solicitudes de aprobación pendientes del motor anterior. Complete los pasos anteriores antes de actualizar; No confíe en la verificación de inicio para encontrar todas las ejecuciones inacabadas.

Si este punto de control bloquea el inicio, regrese a v2.5.1, finalice o detenga deliberadamente las ejecuciones afectadas, complete el punto de control y vuelva a intentar la actualización.

🔐 Corrección de seguridad de Brotli (CVE-2026-111497):

Appsmith v2.6.0 incluye la solución para una vulnerabilidad en el decodificador Brotli Node.js. El procesamiento de datos comprimidos con Brotli creados con fines malintencionados puede dañar la memoria y provocar potencialmente una falla del servicio, exponer la memoria del proceso o permitir la ejecución remota de código. Los clientes autohospedados deben actualizar a v2.6.0 para recibir la solución. Consulte el aviso de seguridad Node.js para obtener más detalles.

⚠️ Notas importantes de actualización

  • Los archivos docker.env personalizados deben contener valores literales resueltos. Las expresiones de Shell detienen el inicio con un diagnóstico redactado. Mueva las opciones de JVM de docker.env a Docker Compose o la configuración del entorno Helm antes de actualizar. Ahora se aceptan los nombres OTEL_*, incluidos los puntos finales del exportador de seguimiento documentados. Los valores predeterminados generados y los valores de configuración de administrador no necesitan cambios. (#42225, #42422)
  • Las consultas Redis deben utilizar un nombre de comando estático. Un enlace en el nombre del comando devuelve un error de configuración de la consulta. Los valores vinculantes permanecen dentro de un único argumento. (#42465)
  • El complemento DynamoDB ahora utiliza AWS SDK para Java 2.55.9. Una región debe contener solo letras, dígitos y guiones, y tener como máximo 63 caracteres. Las respuestas pueden incluir claves adicionales; Las claves y los valores existentes permanecen iguales. Si el servidor configura AWS_ENDPOINT_URL, AWS_ENDPOINT_URL_DYNAMODB, AWS_USE_FIPS_ENDPOINT o AWS_USE_DUALSTACK_ENDPOINT, el complemento ahora los respeta. (#42346)

🔐 Seguridad

  • Dependencias empaquetadas actualizadas para abordar las vulnerabilidades reportadas. (#42444, #42449, #42466, #42475, #42492)
  • Las lecturas de páginas y diseños en modo editor ahora requieren permiso de edición y devuelven el borrador. El modo de visualización aún requiere permiso de lectura y devuelve la página publicada. (#42425)
  • La actualización de una aplicación o fuente de datos ahora mantiene el espacio de trabajo en el que se creó. (#42462)
  • La creación de un espacio de trabajo ahora ignora la identificación, las políticas y los grupos de permisos proporcionados por client. El servidor los genera. (#42478)
  • Los enlaces de consulta Redis permanecen dentro de un argumento de comando, por lo que un valor enlazado no puede agregar argumentos adicionales. (#42465)

🛠️ Confiabilidad

  • Las aplicaciones públicas vuelven a recibir la clave configurada de Google Maps, por lo que los widgets de mapas funcionan para espectadores anónimos. (#42440)
  • Al guardar las credenciales de la fuente de datos ahora se elimina la conexión en caché de esa fuente de datos en cada módulo del servidor. (#42430)
  • El cierre de una conexión de origen de datos desalojada ya no se ejecuta en el hilo de solicitud compartido, por lo que una base de datos bloqueada ya no detiene las comprobaciones de estado. (#42450)
  • Las vistas de página se registran cuando se abre una página, no cuando el editor carga el diseño DSL. (#42429)
  • Los objetos de solicitud anidados de DynamoDB, incluidos los elementos de transacción y la configuración de índice, ahora se crean de la misma manera siempre. (#42346)

✨ Nuevas funciones y mejoras

  • Los filtros SQL estructurados de MCP pueden probar isNull y notNull. (#42491)
  • Los filtros SQL estructurados de MCP pueden agrupar condiciones con anyOf, que se compila en OR y se combina con los otros filtros. (#42495)
  • SQL estructurado MCP like puede coincidir con contenido, prefijo, sufijo o texto exacto. Las consultas PostgreSQL pueden utilizar ilike. (#42496)

🎨 Mejoras en la interfaz de usuario y los widgets

  • En Configuración de la aplicación → Navegación, Mostrar logotipo y Mostrar título de la aplicación ya no cambian entre sí mientras se guarda. (#42488)

🔧 Git, implementación y configuración

  • docker.env ahora acepta nombres OTEL_*, incluidos los puntos finales del exportador de trazas documentados OpenTelemetry. Un valor OTEL_* establecido externamente aún anula el archivo al reiniciar. (#42422)
  • La telemetría del navegador ahora se envía solo a los constructores. Los visitantes anónimos y los usuarios finales de las aplicaciones publicadas ya no son rastreados en el navegador. (#42353)
