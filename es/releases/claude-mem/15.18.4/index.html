claude-mem v15.18.4

Correcciones

  • Claude Code obtiene las reglas y herramientas de claude-mem una vez (#6179). Antes de esto, una sesión de Claude Code recibía la misma guía de hasta tres lugares: las instrucciones del servidor MCP, un bloque de memoria que el script de activación local escribió en CLAUDE.md y una línea de puntero a RULES-AND-TOOLS.md (cuya leyenda de la línea de tiempo nunca se cargó). Ahora hay un camino. MY-RULES.md, que su CLAUDE.md ya importa, finaliza con una importación de RULES-AND-TOOLS.md, y Claude Code lo carga desde allí.
    • Cuando esa cadena de importación se completa en Claude Code, el servidor MCP no envía instrucciones y el enlace SessionStart elimina la línea del puntero Access Claude-Mem Rules + Tools:. El servidor sólo omite sus instrucciones cuando el archivo importado contiene exactamente el texto que enviaría.
    • Otros anfitriones y usuarios de Claude Code que nunca configuraron Mis reglas no cambian.
    • El trabajador agrega la importación a un MY-RULES.md existente una vez al inicio, por lo que los usuarios actuales la obtienen sin hacer nada. Nunca crea el archivo. Escribir MY-RULES.md también garantiza que RULES-AND-TOOLS.md exista, por lo que la importación nunca apunta a un archivo faltante.
    • scripts/activate-progressive-memory-local.mjs ya no escribe el bloque de memoria en el CLAUDE.md de Claude. El Codex AGENTS.md lo mantiene porque AGENTS.md no tiene importaciones.
  • Los puntos finales del listado de trabajadores se detienen en el desplazamiento 10 000 (#6083, gracias @xunguangzlj-cloud). /api/observations, /api/summaries, /api/prompts, los feeds de sesión y /api/tool-uses solían pasar cualquier desplazamiento directamente a SQLite, donde un desplazamiento profundo hace que la base de datos escanee y descarte cada fila omitida. Ahora responden a 400 por encima de 10.000 con el mismo mensaje que utiliza la lista de trabajos. En cambio, los feeds del espectador marcan su última página, por lo que el espectador muestra "esta lista se detiene en los 10.000 elementos más recientes" en lugar de un error.
  • Las carpetas cuyos nombres comienzan con dos puntos permanecen dentro de los directorios excluidos (#6062, gracias @Afloat16). Una carpeta secundaria llamada ..cache se confundió con una ruta de directorio principal, por lo que pasó por alto las exclusiones para las sesiones de observador, el caché del complemento y el tiempo de ejecución del mercado, y un marcador debajo de la carpeta de configuración de Claude podría convertirse en una raíz del proyecto.
  • El informe de costos utiliza su nombre, no el del mantenedor (#6085, gracias @MaxWang007). Las comprobaciones restantes basadas en nombres ("Bloqueado en <nombre>", relés, detección de revisión humana) toman el nombre de --owner-name, luego ACR_OWNER_NAME, luego git config user.name, y usan patrones sin nombre cuando no hay ninguno configurado. Un nombre por sí solo también coincide, y los nombres no latinos funcionan.

Rendimiento

  • Listas de sesiones filtradas por proyectos más rápidas en el visor (#6053, gracias @Afloat16). Un nuevo índice de proyecto, hora de inicio e identificación permite al espectador leer una página de un largo historial de proyectos sin ordenar cada sesión. Las bases de datos existentes obtienen el índice en el siguiente inicio del trabajador.
  • Reducción de la memoria máxima durante el barrido casi duplicado (#6052, gracias @Afloat16). El conteo de pares ahora funciona un título a la vez en lugar de mantener en la memoria cada par de títulos compartidos. Los resultados son los mismos.

Documentos y ejemplos

  • Ejemplo de Vercel Chat SDK para memoria explícita de proyecto (#6084, gracias @Kirat0201). Un chat local autenticado por el portador puede guardar una nota, buscar su proyecto y recuperar una observación. Sin modelo y sin captura automática. Necesita configurar CLAUDE_MEM_WORKER_URL y la guía muestra cómo encontrar el puerto de su trabajador.
  • Marca del logotipo README actualizada (#6104).
