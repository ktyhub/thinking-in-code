claude-mem v15.19.0

Continuar una conversación de Claude Code o Codex desde Mi trabajo

Abra una solicitud en Mi trabajo, luego abra "De dónde vino esto". Debajo de cada conversación de Claude Code o Codex ahora hay un cuadro de mensaje. Escribe un mensaje y presiona Enviar, y esa misma conversación tomará el turno. La respuesta se muestra allí mismo (n.° 6191; las formas del comando siguen el código de respuesta de @wiesenthal en el n.° 6054 y la confirmación lo acredita).

  • Cada conversación mantiene en orden los mensajes que enviaste desde Mi Trabajo y sus respuestas. Parar finaliza un giro en carrera.
  • El cuadro indica en qué carpeta se ejecuta el turno. Cuando la carpeta grabada ya no existe (común después de que se limpia un árbol de trabajo), el turno se ejecuta en la carpeta existente más cercana encima de ella.
  • "Copiar comando de reanudación" copia claude --resume <id> o codex resume <id>. En una Mac, "Abrir en Claude" abre una conversación de Claude Code en la aplicación de escritorio de Claude.
  • One Send inicia un currículum sin cabeza (claude --resume <id> -p --output-format json o codex exec resume <id> - --skip-git-repo-check) con su mensaje en stdin. Un giro fallido se registra como fallido y nunca se vuelve a intentar. Nada se pone en cola ni se guarda para su reproducción, y nada se inicia al inicio, en un temporizador o al volver a conectarse.
  • El reinicio o apagado de un trabajador detiene primero cada turno en ejecución, por lo que un trabajador reiniciado nunca se convierte en un segundo escritor en la misma conversación. Nada vuelve a enviar un giro detenido.
  • Un turno se ejecuta en tu propio modo de permiso predeterminado, el mismo que usa claude -p --resume en tu terminal. En el modo Manual, las llamadas a herramientas que necesitan aprobación se rechazan y la fila las cuenta. No se pasa ningún permiso, modelo o bandera de zona de pruebas.
  • Las nuevas rutas responden únicamente en loopback y rechazan otros orígenes. Con el modo de token local API desactivado, otro programa en la misma computadora puede llamarlos, al igual que cualquier otra ruta de trabajador. En una computadora compartida, active el modo de token local API.
  • Un cambio por cada solicitud: mientras se carga una versión más nueva de una solicitud abierta, el cajón sigue mostrando la versión que ya tiene en lugar de "Cargando detalle de la solicitud…".

Límites conocidos:

  • La ruta del Codex a través de la página no se ejecutó de extremo a extremo en la máquina de prueba. Los giros del Codex se comprobaron a nivel de corredor con el CLI real.
  • En Windows, es posible que Stop no llegue a un CLI detrás de una cuña .cmd y no se ofrece "Abrir en Claude".
  • Una conversación que está a mitad de turno en una terminal aún puede obtener un turno desde Mi Trabajo. Los documentos de Claude Code dicen que dos escritores en una sesión pueden perder mensajes. My Work bloquea dos de sus propios turnos en una conversación.
  • Un accidente de trabajador (no un reinicio ordenado) no puede detener un turno en marcha. Termina solo.
  • Un ayudante que el CLI deja atrás, como un servidor MCP de salida lenta, mantiene el turno marcado como en ejecución hasta que sale o presiona Detener.

Trae tu memoria existente

npx claude-mem import recupera recuerdos directamente de Mem0 Platform o Supermemory y los guarda como observaciones con capacidad de búsqueda en un proyecto que elija. Sin archivo de exportación ni llamadas de modelo (#6106).

# MEM0_API_KEY in the environment
npx claude-mem import --from mem0 --source-account personal-mem0 --user my-user-id --project imported-memory

# SUPERMEMORY_API_KEY in the environment
npx claude-mem import --from supermemory --source-account personal-supermemory --namespace my_namespace --project imported-memory
  • Iniciar el trabajador primero (npx claude-mem start). Agregue --dry-run para buscar y verificar la fuente e imprimir los recuentos sin escribir nada.
  • Cada página fuente se busca y verifica antes de escribir algo. Se omiten las memorias Mem0 vencidas o reemplazadas y las memorias Supermemory antiguas o olvidadas. Para Supermemory, --documents importa texto de documento extraído en lugar de recuerdos.
  • Las memorias importadas se archivan para Claude Code (claude), por lo que su búsqueda de memoria las encuentra. --platform <host> (por ejemplo codex o cursor) los archiva en otro host. Cada observación conserva el registro de origen, el ID, las marcas de tiempo, los metadatos, la etiqueta de la cuenta y el alcance.
  • Ejecutar el mismo comando nuevamente es seguro: los registros ya guardados se cuentan como existentes. No hay trabajo en segundo plano ni reintento automático.
  • Esta es una importación unidireccional, no una sincronización. Las ediciones en la fuente generan nuevas observaciones. Las eliminaciones y vencimientos en la fuente no se transfieren.
  • Límites: 10.000 registros por defecto (--max-records hasta 100.000), 100 MiB de respuestas de origen, una fecha límite de solicitud de 15 segundos (--timeout-ms hasta 120.000) y 100.000 caracteres por registro. Nada se interrumpe de forma silenciosa: un registro de gran tamaño o una solicitud fallida detiene la ejecución.
  • Las pruebas utilizan respuestas sintéticas de Mem0 y Supermemory, no cuentas reales.

Documentos: https://docs.claude-mem.ai/usage/import-providers

Codex: los hilos bifurcados obtienen memoria

  • Los hilos bifurcados del Codex comienzan con la memoria recuperada (#6101). Codex 0.165 agregó un inicio de sesión fork para sus bifurcaciones de subprocesos adjuntos experimentales. El gancho SessionStart de claude-mem no coincidía, por lo que se inició un hilo bifurcado sin memoria. El gancho ahora coincide con fork.

    Usuarios de Codex: aprueben un gancho nuevamente. El comparador del gancho SessionStart cambió y Codex solicita aprobación nuevamente cada vez que cambia la definición de un gancho.

    1. Introduzca el nuevo comparador en ~/.codex/hooks.json. npx claude-mem update y la actualización automática hacen esto cuando su última instalación seleccionó Codex. De lo contrario, ejecute npx claude-mem install y seleccione Codex.
    2. Abra el Codex interactivo, ejecute /hooks y apruebe el enlace SessionStart de claude-mem.

    Hasta que usted lo apruebe, las sesiones del Codex comienzan sin memoria recuperada. La captura sigue funcionando. Hasta que el nuevo comparador esté en hooks.json, npx claude-mem doctor muestra la fila Codex hooks como desactualizada.

También nuevo

  • Tiempo de ejecución del servidor: los resultados de la búsqueda dicen qué agente creó una memoria (#6100). El tiempo de ejecución del servidor ahora almacena el agente en cada memoria y lo completa con las memorias existentes de su sesión. Sus líneas de detalle y búsqueda de MCP agregan [via <agent>], por ejemplo #8 — Auth redirect decision (myproject) [via cursor]. Los recuerdos sin agente registrado no muestran etiqueta. /api/sessions/observations ya no etiqueta cada client como Claude Code. Los resultados de la observación del trabajador local aún no incluyen al agente, por lo que no muestran ninguna etiqueta.
  • Zed (#6111, gracias @AdityaxDeore, cierra #5900). npx claude-mem install (o --ide zed) registra el servidor MCP de claude-mem en context_servers de Zed, para búsqueda, línea de tiempo, detalles y guardados explícitos. Los comentarios en el archivo de configuración de Zed se conservan. No hay captura automática porque Zed no tiene ganchos ni acceso a transcripciones. Documentos: https://docs.claude-mem.ai/zed-integration
  • Aider (#6112, gracias @AdityaxDeore, cierra #5893). Ejecute npx claude-mem aider install dentro de un proyecto. Agrega .claude-mem/aider-memory.md a la lista read: en .aider.conf.yml y npx claude-mem aider sync actualiza ese archivo desde el trabajador. Es una suscripción voluntaria por proyecto: npx claude-mem install no lo ofrece, el archivo de memoria se mantiene fuera de git a través de .git/info/exclude y se niega a ejecutarse en su carpeta de inicio. Sin captura automática. Documentos: https://docs.claude-mem.ai/aider-integration
  • Grok Build recupera la memoria al inicio de la sesión (#6180, gracias @krishnadobhal, cierra #5950). Grok Build ignora lo que imprimen los ganchos SessionStart, por lo que las notas recuperadas nunca llegaron al modelo. claude-mem grok install escribe .grok/rules/claude-mem-context.md en la carpeta actual, que Grok Build carga desde las carpetas trusted. El trabajador lo actualiza después de cada resumen de sesión, solo en las carpetas en las que lo instaló. Un proyecto excluido obtiene una línea "excluida" en lugar de notas. La captura no ha cambiado. Documentos: https://docs.claude-mem.ai/grok-build
  • Francés en el selector de idioma para Mi trabajo, el visor, la configuración de primera ejecución y Observation TV (#6107, gracias @QuantScorpus). Tus recuerdos, reglas y citas permanecen tal como están escritas.
  • Tres nuevos ajustes preestablecidos para el proveedor compatible con OpenAI. Cada uno tiene por defecto un modelo pequeño y rápido, porque la extracción de memoria es de gran volumen:
    • AtmoRouter, zai/glm-5.3-flash (#6108, gracias @BeckleyTenriajeng)
    • TrustedRouter, deepseek/deepseek-v4-flash (#6174, gracias @jperla). trustedrouter/auto permanece disponible como suscripción voluntaria. Puede dirigir una solicitud a un modelo con un precio de frontera.
    • HopBase, deepseek-v4.1-flash (#6181, gracias @victor-zzh)

Correcciones

Privacidad y seguridad

  • La carpeta de datos claude-mem es solo del propietario (#6091, gracias @DeryFerd). En macOS y Linux, ~/.claude-mem (base de datos, configuración, .env, carrete de gancho, copias de seguridad) se creó con un mkdir simple, por lo que bajo la máscara de usuario común 022 otras cuentas de la máquina podrían leerlo. Ahora se crea como 0700, una carpeta existente se ajusta en el siguiente inicio y las nuevas entradas del carrete de anzuelo se escriben como 0600.
  • MCP save_memory honra a CLAUDE_MEM_EXCLUDED_PROJECTS (#6105, gracias @Zhong-fan, informado por @Kirat0201 en #6098; @0xABCD01 envió la misma solución en #6166). Un guardado de un pago excluido se almacenó a través de MCP, mientras que el mismo guardado a través de HTTP se omitió. Ahora se omite y la respuesta dice "No guardado: CLAUDE_MEM_EXCLUDED_PROJECTS excluye este pago". en lugar de "¿Núm. de memoria guardada?: Sin título". Las guías Cline y Kilo ahora lo dicen (#6190).
  • Tiempo de ejecución del servidor: el comando de conexión MCP rechaza un host inutilizable (#6176, gracias @DeryFerd). Sin CLAUDE_MEM_PUBLIC_URL, GET /v1/connect y POST /v1/keys crearon el comando listo para pegar a partir del encabezado Host de la solicitud y copiaron espacios en blanco, comillas o rutas en él. Un valor que no puede ser un host ahora obtiene 400 InvalidHost y no se genera ninguna clave.
  • Centro de sincronización: FORWARD_ORIGIN debe usar https:// (#6175, gracias @DeryFerd). El proxy de reenvío copia el encabezado Authorization entrante en el destino, por lo que un origen http:// simple podría enviarlo sin TLS. http:// sólo está permitido para hosts de loopback. Un valor que no es una URL utilizable ahora falla ruidosamente en lugar de volver silenciosamente a la ruta del objeto duradero.

Instalar y desinstalar

  • La desinstalación elimina los ganchos Gemini CLI (#6088, gracias @tanishqbaweja). npx claude-mem uninstall eliminó el complemento pero dejó los cinco ganchos Gemini CLI de claude-mem en ~/.gemini/settings.json, por lo que Gemini CLI imprimió un mensaje de gancho fallido en cada inicio de sesión, aviso, llamada de herramienta y final de turno. Desinstalar ahora los elimina y conserva sus propias configuraciones y enlaces. Un settings.json con comentarios no se modifica, así que retire esos ganchos con la mano.
  • Cancelar el mensaje de la tecla API ya no te cambia a Claude (#6161, gracias @bulanovk). Con --provider gemini o --provider openrouter y sin clave guardada, al cancelar el mensaje de clave se escribió CLAUDE_MEM_PROVIDER='claude' y continuó. Ahora se detiene con un error y no cambia nada.
  • La verificación de configuración heredada del instalador del Codex expande un ~\ líder solo en Windows, como el resto de claude-mem (#6093, gracias @DeryFerd).

Trabajador y almacenamiento

  • Un trabajador que encuentra una base de datos ocupada al inicio vuelve a intentarlo en lugar de responder 503 durante minutos (#6145, gracias @montjeffrey, referencias #3603). Un trabajador de reemplazo podría presionar SQLITE_BUSY_SNAPSHOT una vez durante el inicio de la base de datos, no volver a intentarlo nunca y responder a todas las solicitudes con "Inicialización del servicio" hasta un reinicio manual (aproximadamente 11 minutos en el informe). El inicio ahora reintenta un error de ocupado 3 veces, después de 1, 2 y 4 segundos. El peor de los casos (27 s) se sitúa dentro de los 30 s que el gancho espera a que el trabajador esté listo. Otros errores siguen fallando a la vez.
  • Cerrar la base de datos la libera (#6090, gracias @DeryFerd). Las declaraciones preparadas en caché mantuvieron la conexión y el archivo de la base de datos abiertos después del cierre. En Windows que bloqueó los intercambios de restauración y la limpieza de carpetas temporales con EPERM o EBUSY.
  • La limpieza de croma para sesiones eliminadas sobrevive a la salida de un trabajador (#6163, gracias @Afloat16). Si el trabajador salió antes de que se ejecutara la limpieza en cola, los vectores de las filas eliminadas nunca se eliminaron. La limpieza ahora se registra antes de que comience. El mismo cambio corrige una verificación que trataba una fila faltante como restaurada en Bun.
  • En Bun, una base de datos cuya tabla de exclusiones de inicio de sincronización desapareció la reconstruye en lugar de mantener una lista vacía (#6189).
  • Un suscriptor fallido de /api/ready ya no detiene el progreso de inicio de los demás ni se convierte en un error de inicio (#6127, gracias @Afloat16).

Captura y notas de memoria.

  • CLAUDE_MEM_SKIP_BASH_PATTERNS se aplica a Antigravity CLI (#6096, gracias @tanishqbaweja). agy informa su herramienta de shell como run_command, que la verificación del patrón no leyó, por lo que los comandos excluidos se almacenaron y enviaron al observador.
  • Una nota explícita que contenga un carácter nulo podría obtener el ID de otra nota mientras su propio texto no se haya guardado (#6170, gracias @Kirat0201, cierra #6169).
  • Un archivo de memoria de Claude Code cuya descripción o metadata.type cambió se almacena como una nueva revisión en lugar de informarse como ya importado (#6186, gracias @Kirat0201, cierra #6171).
  • Notas de memoria (gracias @Afloat16):
    • El título de una nota proviene de sus encabezados reales, no de un # comment dentro de un código de ejemplo (#6156).
    • Los campos anidados bajo metadata: de una nota ya no sobrescriben el tipo o sesión de la nota, y un comentario YAML ya no finaliza el bloque (#6157).
    • memory ingest --source o --cwd sin valor se detiene con un error de uso en lugar de importar el pago actual (#6150).
    • Al escanear una transcripción nuevamente ya no se inserta un turno importado dos veces cuando dos turnos cercanos tienen el mismo texto (#6149).
    • Con CLAUDE_MEM_DEDUP_ENABLED=true, los títulos que difieren sólo en caracteres de código (C++ y C#, src/config.ts y src config ts, números de versión) ya no se fusionan en una fila, lo que perdió la segunda (#6120).
    • Las observaciones importadas cuyos hechos o archivos se almacenaron como una cadena se muestran nuevamente en la memoria (#6134).

Búsqueda y contexto (gracias @Afloat16 a menos que se indique lo contrario)

  • La búsqueda semántica compara las ventanas de fecha con las filas guardadas, no con la copia de Chroma, por lo que una fila actualizada en SQLite pero aún no en Chroma aparece en la ventana derecha (#6153).
  • Las búsquedas de archivos ordenadas por fecha omiten Chroma, por lo que una interrupción de Chroma o una incrustación lenta ya no fallan (#6123).
  • El contexto del archivo devuelve las observaciones más recientes cuando varios comparten una marca de tiempo (#6118).
  • El caché de contexto mantiene el alcance de invalidación correcto cuando los renderizados terminan fuera de orden, por lo que una escritura posterior en un proyecto adoptado lo actualiza (#6164).
  • La búsqueda profunda le da a su proceso hijo solo el tiempo realmente restante, por lo que un paso del reloj como una corrección NTP ya no causa un tiempo de espera de vacío anticipado (#6177, gracias @DeryFerd).

Codex como proveedor de memoria (gracias @Afloat16)

  • El límite del protocolo de 8 MiB se aplica a cada línea JSON, no a todo lo almacenado en el búfer, por lo que la salida válida ya no se rechaza (#6119).
  • Una tubería estándar cerrada durante un giro falla y gira limpiamente en lugar de escaping como un error no controlado (#6130).
  • Una solicitud con tiempo de espera agotado ya no deja atrás un controlador de aborto que podría fallar en el siguiente turno en un nuevo servidor de aplicaciones (#6133).

Lectura inteligente de archivos

  • smart_outline ya no marca declaraciones junto a una exportación en la misma línea que [exported] (#6141, gracias @liuyinchu).
  • Ahora indexados (gracias @Afloat16): funciones, flechas y clases anónimas de export default (#6151), métodos de protocolo Swift y métodos Scala sin cuerpo (#6154) y declaraciones de Java @interface y sus elementos (#6160).
  • La búsqueda de código inteligente lee cada archivo a través de un identificador y se detiene en el límite de 512 KiB, por lo que un archivo reemplazado después de la verificación de tamaño no puede superar el límite (#6124, gracias @Afloat16).

Mi trabajo

  • El paso de objetivos utiliza el idioma de la ejecución (#6187, gracias @0xABCD01, cierra #6185 reportado por @Fly-onlyone). La línea de idiomas alcanzó todos los pasos excepto los objetivos, por lo que en #6185 147 indicaciones en inglés produjeron objetivos en español. Una primera carrera de solo objetivos sin idioma establecido todavía puede adivinar. CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE lo configura.
  • También en Mi Trabajo (gracias @Afloat16):
    • Una respuesta de Jev cortada en la mitad del cuerpo cuenta como una interrupción, no como una falla permanente para ese elemento, por lo que la siguiente actualización pregunta nuevamente (#6158).
    • Un nuevo git init, un nuevo repositorio anidado o un .git eliminado se selecciona la próxima vez que Mi trabajo resuelve el proyecto de una sesión, en lugar de hacerlo solo después de un reinicio del trabajador (#6165).
    • El borrado automático ignora las lecturas tardías de un turno o conversación que ya finalizó (#6152).
    • Las indicaciones del propietario mantienen su presupuesto total de 3000 caracteres cuando contienen emoji y otros caracteres fuera del plano básico (#6162).
    • El agente de corpus opcional API coincide con palabras acentuadas, hindi, bengalí y hebreas puntiagudas (#6168).
    • Los totales de uso de Gemini en la configuración mantienen el recuento de tokens completados cuando la misma respuesta se guardó dos veces (#6146).

Visor

  • Al abrir una ventana de visor se envía su primera lista de proyectos y su estado solo a esa ventana, no a todos los visores abiertos (#6126, gracias @Afloat16).
  • Cli Al pulsar nuevamente el botón de acciones de la sesión se cierra el menú (#6143, gracias @liuyinchu).

Otro

  • informe-costo-agente escribe CHECKSUMS.txt con barras diagonales en Windows (#6089, gracias @DeryFerd).

Rendimiento (gracias @Afloat16)

  • Las líneas largas de transcripción se ensamblan una vez en lugar de copiarse en cada pasada de lectura, en el lector inverso (#6116) y en el observador en vivo (#6117).
  • El historial de mensajes de OpenCode se lee un mensaje a la vez (#6121).
  • Las cargas útiles de herramientas grandes están limitadas y codificadas sin copias completas (#6128).
  • Las líneas de tiempo cargan solo las filas que muestran (#6129). Las sesiones recientes utilizan una verificación de resumen indexada (#6132). Los formateadores de fecha se reutilizan dentro de una representación (#6125).
  • La recuperación en el ámbito del proyecto detiene una verificación de combinación en la primera fila no adoptada (#6131). El catálogo de proyectos elimina duplicados con conjuntos (#6135). Las consultas pegadas durante mucho tiempo dejan de escanearse cuando se alcanza el límite de 500 términos (#6147).
  • La lectura inteligente de archivos encuentra el contenedor de cada símbolo con un índice en lugar de un escaneo (#6122).
  • Mi trabajo indexa registros de procedencia (#6148), membresías de solicitudes de enfoque (#6155) y versiones de elementos de estado de trabajo (#6159) una vez por llamada.

Documentos

  • Guías Cline CLI y Kilo CLI para guardar y encontrar recuerdos a través del servidor stdio MCP (#6097, #6114, gracias @Kirat0201). Documentos: https://docs.claude-mem.ai/cline y https://docs.claude-mem.ai/kilo
  • Las habilidades incluidas caen SIEMPRE y los marcadores OBLIGATORIOS (#6183, gracias @jcole666, cierra #6144 reportado por @scu-lixiao).
  • La especificación del punto final CMEM Pro define un alcance OAuth write:memory para la ingesta de enlaces (#6099).

CI y pruebas

  • Los trabajos de Windows (#6092) y el flujo de trabajo en tiempo de ejecución de medios (#6178) fijan Bun 1.4.4 como el resto de CI (gracias @DeryFerd).
  • Las suites de vista de trabajo eliminan las carpetas temporales con el asistente de reintento compartido (#6094). El carril de Windows ejecuta ambas suites Python y la suite Hermes está reparada (#6095) (gracias @DeryFerd).
  • Una prueba fija los nombres de los eventos OpenCode 2.0, por lo que un evento ascendente renombrado falla ruidosamente (#6102).
