claude-mem v15.18.3

Correcciones críticas

  • Codex sigue grabando después de las actualizaciones de claude-mem (#6058, gracias @wiesenthal). Codex aprueba un gancho que se envía dentro de un complemento con una huella digital de toda la carpeta del complemento. Cada actualización de claude-mem reescribe esa carpeta, por lo que después de cada actualización, Codex desactivó los siete ganchos de claude-mem ("el contenido del complemento cambió; se requiere aprobación del gancho") y las sesiones de Codex dejaron de guardarse, sin ningún mensaje. El instalador ahora registra los ganchos Codex de claude-mem en su propio ~/.codex/hooks.json, y cada gancho ejecuta el iniciador on-PATH claude-mem, que encuentra la instalación más reciente por sí solo. El Codex trust tiene un gancho en hooks.json por su propia definición y posición, por lo que una aprobación ahora dura entre actualizaciones. Los ganchos de otras herramientas en ese archivo se mantienen en su lugar, una segunda instalación no cambia nada, un hooks.json que no se puede analizar se rechaza y se deja intacto, y la desinstalación elimina solo las entradas de claude-mem. Desactivar el complemento claude-mem en Codex aún detiene la captura. npx claude-mem doctor tiene una nueva fila Codex hooks que advierte cuando el complemento está activado pero faltan sus ganchos en hooks.json.

    Usuarios de Codex: hagan esto una vez después de la actualización.

    1. Ejecute npx claude-mem install y seleccione Codex. npx claude-mem update y la actualización automática no mueven los ganchos porque los instaladores más antiguos no guardaron ninguna selección de agente. El instalador imprime Registered 7 claude-mem hooks in <codex home>/hooks.json.
    2. Abra el Codex interactivo, ejecute /hooks y apruebe los siete ganchos claude-mem. codex exec no puede solicitar aprobación, así que hágalo primero en el Codex interactivo.

    Después de eso, las actualizaciones no necesitan una nueva aprobación. Codex vuelve a preguntar solo cuando cambia la definición de un gancho de claude-mem, cuando claude-mem agrega un gancho o cuando se elimina el gancho de otra herramienta enumerada antes de claude-mem.

Mejoras

  • Token API local opcional para el trabajador API y transporte HTTP MCP (#6056, gracias @kartik70, cierra #5141). Esto es para máquinas con más de un usuario de sistema operativo. Está desactivado de forma predeterminada y nada cambia a menos que lo configures. Configure CLAUDE_MEM_LOCAL_API_TOKEN en ~/.claude-mem/settings.json y reinicie el trabajador y el servidor HTTP MCP. Después de eso, el trabajador API y el transporte HTTP MCP rechazan cualquier solicitud que no lleve el token (X-Claude-Mem-Token o Authorization: Bearer), excepto las comprobaciones de estado. Abra el visor como /?token=... o /viewer?token=.... El token solo se puede configurar en el archivo: la configuración API no puede configurarlo ni borrarlo, y queda enmascarado cuando se lee. omp, hermes y openclaw aún no envían el token. Consulte "Token API local" en los documentos de configuración.
  • La advertencia de reserva de cuota nombra a ambos proveedores (#6071, gracias @bulanovk). Cuando la reserva de cuota mueve el trabajo de memoria a otro proveedor, el registro del trabajador ahora nombra el proveedor que seleccionó y el que realmente hace el trabajo, indica cuándo el sustituto gasta su cuenta de Anthropic y nombra CLAUDE_MEM_QUOTA_FALLBACK_PROVIDER=off para desactivarlo. El respaldo predeterminado no se modifica.
  • flujo de trabajo n8n para guardar y encontrar recuerdos (#6066, gracias @Kirat0201, cierra #5923). Un flujo de trabajo n8n importable guarda una nota, verifica que el trabajador haya confirmado el guardado y luego la busca y la recupera dentro del proyecto elegido. Está inactivo hasta que lo ejecuta y no agrega captura automática. La configuración se encuentra en la nueva página de documentos de n8n.

Correcciones

  • lectura inteligente (gracias @Afloat16):
    • Los captadores y definidores con el mismo nombre ahora se despliegan por separado (#6060).
    • Los niveles de encabezado de rebajas se mantienen tal como están escritos (#6064).
    • Los cuerpos de rutina Pascal se encuentran incluso cuando el caso de la declaración difiere (#6063).
  • Las cadenas de documentación Python mantienen sus rangos de declaración (#6057).
    • La fuente capturada se analiza en lotes nativos (#6059).
  • El analizador de observación acepta espacios en blanco XML antes de los delimitadores de etiquetas (#6065, gracias @Afloat16).
  • Las exclusiones de Globstar ahora también se aplican a rutas que contienen terminadores de línea (#6061, gracias @Afloat16).
  • Informe de costos: las ganancias en todo el repositorio se buscan solo cuando se solicitan explícitamente (#6081) y se reconocen los relés de dirección con nombre (#6082) (gracias @Kirat0201).
  • La guía de instalación enumera los mínimos reales de Node.js y Bun (#6076, gracias @DeryFerd).

CI y pruebas

  • Los trabajos de publicación y nativos de ods fijan a Bun en lugar de usar la versión más reciente (#6075), y CI ahora ejecuta las comprobaciones de gancho-io y spawn-env (#6074) (gracias @DeryFerd).
  • Correcciones de pruebas de Windows: reintentos de limpieza del directorio temporal, rutas de memoria por plataforma y casos de enlace de canal en pausa omitidos donde Node no puede ejecutarlos (#6072, #6073, gracias @DeryFerd). El código auxiliar de prueba del centro de sincronización se escribe para que el paquete verifique el tipo (#6077, gracias @DeryFerd).
  • La prueba env-fallback #4689 ya no depende de un inicio de sesión real de Claude en la máquina (#6068, gracias @bulanovk).
