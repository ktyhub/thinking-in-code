Firecrawl v2.10

Mejoras

  • Punto final /parse: cargue archivos locales (PDF, DOCX, DOC, ODT, RTF, XLSX, XLS, HTML) de hasta 50 MB y obtenga Markdown limpio, listo para LLM, JSON o un resumen. Se conservan las tablas y el orden de lectura, con soporte completo de retención de datos cero para planes empresariales. Disponible en JS, Python, Go, Rust, Java, .NET, PHP, Ruby y Elixir SDK.
  • Modo de bloqueo: configure lockdown: true en /scrape para ofrecer resultados exclusivamente del índice de Firecrawl con cero solicitudes salientes y cero retención de datos de forma predeterminada. Las rutas de salida cerradas incluyen recuperaciones HTTP, robots.txt, descargas de audio y medios. Disponible en todos los SDK, CLI (--lockdown) y MCP.
  • Formato question: pase un mensaje en lenguaje natural a /scrape y obtenga una respuesta fundamentada y sin alucinaciones en data.question. Se ejecuta en una cadena de modelo administrada con respaldo automático, aislamiento de inyección rápida mediante etiquetado XML y escaping de espacio de ancho cero, y hasta 100 veces menos tokens por llamada.
  • Formato highlights: devuelve las oraciones, bloques de código y filas de tabla exactos en una página que coinciden con su consulta. Las oraciones consecutivas se vuelven a unir en párrafos, las líneas de código se agrupan en bloques cercados con su idioma original y las filas de la tabla se reconstruyen en tablas de Markdown con encabezados, todo desde la página de origen, utilizando hasta 100 veces menos tokens por llamada.
  • Formato video: se agregó video a los formatos scrape. Devuelve una URL de vídeo descargable firmada para sitios compatibles (por ejemplo, YouTube), con reenvío de cookies para descargas autenticadas y bloqueo de bloqueo explícito.
  • Filtros de dominio /search: se agregaron los parámetros includeDomains y excludeDomains a /search para determinar el alcance de los resultados en un conjunto específico de sitios.
  • Punto final de comentarios /search: envíe una calificación sobre un resultado de búsqueda con POST /v2/search/:jobId/feedback. Cada envío aceptado reembolsa 1 crédito, limitado por día UTC, con reintentos idempotentes.
  • Agente de usuario de robots.txt personalizado: se agregó robotsUserAgent a las solicitudes de rastreo para evaluar las reglas de robots.txt y los retrasos de rastreo en comparación con una cadena de agente personalizada, y un indicador de organización customRobotsAgent independiente de ignoreRobots. Disponible en JS, Python y Java SDK.
  • Go SDK oficial: se agregó un Go SDK propio para el API v2, reemplazando el módulo comunitario. Incluye reintento posterior según el contexto y escritura MapData.Links adecuada.
  • Ruby SDK: se agregó el Firecrawl Ruby SDK v2 oficial con cobertura completa de endpoints y escritura nativa v2.
  • PHP SDK: se agregó el PHP SDK oficial con soporte para Laravel, cobertura de scrape/search/crawl/map/parse y un paquete firecrawl/firecrawl-sdk Composer publicado.
  • .NET SDK: se agregó el .NET SDK oficial con soporte para API v2, análisis y un paquete NuGet firecrawl-sdk.
  • Rust SDK v2: el Rust SDK ha sido ascendido a SDK v2 oficial con paridad en raspado, búsqueda, rastreo, mapa, agente y análisis.
  • Sugerencia /interact: las llamadas a /scrape que pasan una matriz actions ahora devuelven una advertencia que sugiere /interact para la automatización del navegador con estado.
  • Límite de tamaño de PDF: aumentó el límite de tamaño de carga de PDF de 10 MB a 30 MB.
  • Facturación procesada por páginas PDF: facturación PDF actualizada para reflejar las páginas procesadas en lugar del recuento de páginas sin procesar.
  • Arnés Docker: HARNESS_STARTUP_TIMEOUT_MS a docker-compose expuesto para usuarios autohospedados que necesitan ventanas de inicio más largas.
  • Elixir SDK: se agregó parse_file/3 al Elixir SDK para el punto final /parse.
  • Tiempo de espera de solicitud de JS SDK: se agregó una opción de tiempo de espera de solicitud explícita al JS SDK para evitar solicitudes que se cuelguen.

Correcciones

  • Se resolvieron múltiples CVE en los modelos API y SDK, incluidos axios, postcss, fast-xml-parser, protobufjs, follow-redirects, langsmith, lodash, fast-uri y fast-xml-builder.
  • Se corrigió que la marca colors.secondary se completara incorrectamente cuando el LLM omitía un valor: secondary ahora es opcional y ya no se aplica de forma predeterminada.
  • Se corrigió que el servicio Playwright ignorara el encabezado de solicitud User-Agent de la persona que llama.
  • Se corrigieron las URL firmadas por screenshot que devolvían resultados obsoletos del caché al forzar una pérdida de caché cuando la URL firmada había expirado.
  • Se corrigió que las solicitudes de Lockdown se facturaran dos veces por ZDR al tratar Lockdown como retención de datos cero de forma predeterminada.
  • Se corrigió la facturación de proxy para raspados almacenados en caché que cobraban incorrectamente créditos de proxy cuando no se producía ninguna salida de proxy.
  • Se corrigieron los scripts de transcripción de YouTube que se ejecutan en raspados de solo audio y descargas de audio que no reciben cookies CDP.
  • Se corrigió el servicio de conversión html-to-md ignorando la retención de datos cero.
  • Se corrigió un desbordamiento de pila en marked.parse al manejar ciertas salidas de PDF.
  • Se corrigió que robotsUserAgent no fuera respetado por el filtro de enlace nativo y no se incluyera en las cargas útiles de rastreo de JS SDK.
  • Se corrigieron los puntos finales de estado /v1 que devolvían 500 en ID de trabajo que no son UUID; ahora devuelven un 400 adecuado.
  • Se corrigió que las matrices actions: [] vacías se trataran como acciones en los indicadores de funciones.
  • Se corrigió que el observador JS SDK emitiera eventos duplicados, filtrara tiempos de espera y colgara start() en los tiempos de espera del observador.
  • Se corrigió el desenvolvimiento de Ruby SDK de los campos de datos credit_usage y el valor predeterminado de skipTlsVerification a false.
  • Se corrigió la validación de límite negativo que faltaba en Python, Java y Go SDK.
  • Se corrigió que Java SDK aceptara claves API vacías y faltaran métodos de ciclo de vida asíncronos.
  • Marcas de tiempo fijas del período de facturación, búsquedas de suscripciones e informes de crédito del plan.
  • Se corrigieron los tiempos de espera de rastreo atrasado que eran ilimitados, ahora con un límite de 48 h.

##API

  • Se agregó POST /v2/parse para cargas de archivos de varias partes de hasta 50 MB. Devuelve un documento estándar. Opciones de raspado no permitidas en el análisis: changeTracking, screenshot, branding, actions, waitFor, location, mobile; proxy está restringido a auto o basic. Errores con PARSE_UNSUPPORTED_OPTIONS en entradas no permitidas.
  • Se agregó lockdown: boolean a /scrape. La caché pierde el retorno 404 con SCRAPE_LOCKDOWN_CACHE_MISS. Facturación: +4 créditos cuando lockdown está habilitado, 1 crédito en caso de pérdida de caché. Disponible en todos los SDK.
  • Se agregaron question y highlights a los formatos /scrape, devolviendo data.question y data.highlights respectivamente.
  • Se agregaron formatos video a /scrape. Devuelve document.video como una URL firmada. +4 créditos por solicitud. Las URL no admitidas generan SCRAPE_VIDEO_UNSUPPORTED_URL; parse rechaza el formato video client- y del lado del servidor.
  • Se agregaron matrices includeDomains y excludeDomains en /v2/search para determinar el alcance de los resultados en dominios específicos.
  • Se agregó POST /v2/search/:jobId/feedback para calificar los resultados de búsqueda. Cada envío aceptado reembolsa 1 crédito, limitado por día UTC a través de SEARCH_FEEDBACK_DAILY_CAP_CREDITS, y los reintentos idempotentes devuelven alreadySubmitted: true. Se rechazan los envíos de comentarios anteriores a SEARCH_FEEDBACK_MAX_AGE_SEC (predeterminado 120). La facturación de búsqueda ahora es de créditos ceil(results/10) * 2, como apareció en las respuestas.
  • Se agregó robotsUserAgent a /v2/crawl crawlerOptions para la evaluación de robots.txt de agente personalizado. Cerrado detrás de la bandera de la organización ignoreRobots.
  • Se agregó un indicador de organización customRobotsAgent independiente de ignoreRobots, para que los equipos puedan enviar agentes de usuario personalizados sin deshabilitar la aplicación de robots.txt.
  • Se migró el indicador de organización ignoreRobots de un patrón booleano a un patrón disabled / allowed / forced. Se eliminó la forma de solicitud heredada ignoreRobots: boolean: clients debe usar los nuevos valores de bandera.
  • /v0/scrape, /v0/crawl, /v0/crawl/status/:jobId, DELETE /v0/crawl/cancel/:jobId, /v0/search, /v1/extract, /v1/extract/:jobId, /v2/extract, /v2/extract/:jobId, /v1/deep-research, /v1/deep-research/:jobId, /v1/llmstxt y /v1/llmstxt/:jobId están en desuso. Los puntos finales obsoletos emiten encabezados Deprecation: true, Warning: 299 - "<message>", Link; rel="successor-version" y (cuando están configurados) Sunset, además de warnings[] y replacement en el cuerpo de JSON. JS y Python SDK los presentan a clients.
