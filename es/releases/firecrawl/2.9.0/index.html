Firecrawl v2.9.0

Mejoras

  • Interacción del navegador a través del punto final /interact: extraiga una página y luego llame a /interact para realizar acciones en ella; cli marque botones, complete formularios, navegue más profundamente o extraiga contenido dinámico. Describe lo que deseas en lenguaje natural a través de prompt, o escribe código Playwright (Node.js, Python) y Bash (agent-browser) para un control total. Las sesiones persisten a lo largo de las llamadas, con visualización en vivo y URL interactivas de visualización en vivo para transmisión en tiempo real desde el navegador. Los perfiles persistentes le permiten guardar y reutilizar el estado del navegador (cookies, almacenamiento local) en todos los scraps. Disponible en JS, Python, Java y Rust SDK.
  • Formato query: se agregó el formato query al terminal /scrape: pase un mensaje en lenguaje natural y obtenga una respuesta directa en data.answer.
  • Formato audio: se agregó la opción de formato audio para extraer respuestas y devolver la salida de audio como un campo en el documento.
  • Parámetro onlyCleanContent: se agregó el parámetro onlyCleanContent al punto final /scrape, que elimina la navegación, los anuncios, los banners de cookies y otro contenido no semántico de la salida de rebajas.
  • Modos de análisis de PDF: se agregaron modos de análisis de PDF (fast, auto, ocr) y una opción maxPages para controlar la profundidad de extracción y el comportamiento de OCR.
  • Java y Elixir SDK: se agregaron Java y Elixir SDK oficiales con soporte completo v2 API.
  • Compatibilidad con archivos .doc heredados: se agregó soporte para analizar archivos .doc heredados.
  • Motor Wikimedia: se agregó un motor dedicado para páginas scraping de Wikipedia y Wikimedia con calidad de salida mejorada.
  • contentType en respuestas raspadas: se agregó contentType para respuestas raspadas de archivos PDF y documentos.
  • Mejoras en la canalización de PDF: canalización de PDF mejorada con mejor detección de tablas, eliminación de encabezados y pies de página, manejo de PDF mixto, análisis de imágenes en línea y detección de bytes mágicos.
  • Extracción de marca: extracción de marca mejorada para omitir elementos DOM ocultos y obtener resultados más limpios.
  • Rendimiento de HTML a Markdown: se mejoró el rendimiento de la conversión de HTML a Markdown y se corrigieron los bloques de código que perdían contenido durante la conversión.
  • Cola de simultaneidad: nuevo sistema de cola de simultaneidad con conciliador y reposición para una programación de trabajos más confiable.
  • Rust SDK v2: se agregó el espacio de nombres v2 API con soporte de agente al Rust SDK.
  • Se corrigieron los parámetros Python SDK timeout, max_retries y backoff_factor; estos se aceptaron previamente pero se ignoraron silenciosamente.
  • Limitó los tiempos de espera de los trabajos a 48 horas para evitar que los trabajos fuera de control consuman recursos.
  • Se agregaron límites de reintento para evitar bucles de raspado.
  • Los tipos de contenido binario ahora se rechazan en las primeras etapas del proceso de extracción para evitar un procesamiento desperdiciado.

Correcciones

  • Se corrigieron respuestas vacías al usar el modelo o3-mini en trabajos de extracción.
  • Se corrigieron las claves API revocadas que permanecen válidas por hasta 10 minutos después de la eliminación.
  • Se corrigió una condición de carrera en trabajos de extracción que causaba fallas de "Trabajo no encontrado".
  • Se corrigió time_taken en /v1/map que siempre devolvía ~0.
  • Se corrigieron las respuestas de estado de rastreo que ahora muestran un estado failed con un mensaje de error y datos parciales cuando ocurre una falla en el nivel de rastreo.
  • Se corrigió que maxPages no se pasara al extractor de PDF; anteriormente, se devolvía el contenido completo del PDF y solo se cobraba por el recuento limitado de páginas.
  • Se corrigieron los créditos de solicitud gratuita que se consumían y facturaban incorrectamente en trabajos de agentes que excedían el umbral maxCredits.
  • Se corrigió el panel que mostraba límites de concurrencia incorrectos debido a lecturas obsoletas.
  • Se corrigió que la marca colors.secondary no se completara.
  • Se corrigió que removeBase64Images se ejecutara después de deriveDiff en la tubería del transformador, lo que causaba problemas de diferenciación.
  • Se corrigió la recuperación de GCS usando un índice de fila incorrecto para las búsquedas de información de caché.
  • Se corrigió el ZodError no controlado en el controlador /v1/search.
  • Se resolvieron múltiples CVE en dependencias, incluidas handlebars, path-to-regexp, fast-xml-parser, rollup (CVE-2026-27606), undici y otras.
  • Se fortaleció el servicio Dramaturgo contra ataques de la SSRF.

##API

  • Se agregó el punto final GET /v2/team/activity para enumerar trabajos recientes de raspado, rastreo y extracción con paginación basada en cursor (últimas 24 horas, hasta 100 resultados por página, filtrables por tipo de punto final).
  • Se agregó el parámetro regexOnFullURL en las solicitudes de rastreo para aplicar el filtrado includePaths/excludePaths en la URL completa, incluidos los parámetros de consulta. Disponible en JS, Python, Java y Elixir SDK.
  • Se agregó el parámetro deduplicateSimilarURLs en las solicitudes de rastreo. Disponible en JS, Python, Java y Elixir SDK.
  • El punto final extract quedó obsoleto; en su lugar, utilice el punto final /agent. Los métodos extract existentes en JS y Python SDK están marcados como obsoletos.
  • Se cambió el nombre de persistentSession a profile en solicitudes de navegación/interacción (writeMode ahora es saveChanges). El antiguo nombre del parámetro sigue siendo funcional pero ya no está documentado.
