bookkeeper release-4.17.0

Versión Publicado25 may 2024 Fuenteapache/bookkeeper original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

liberación del contable-4.17.0

La versión 4.17.0 incluye varias funciones importantes, mejoras, correcciones de errores y algunas dependencias CVE.

Los detalles técnicos de esta versión se resumen a continuación.

Cambios importantes

Sin cambios importantes. Algunos valores predeterminados son diferentes, pero en general no hay problemas de compatibilidad.

Características

  • BP-62 Lectura por lotes API

Cambios notables

  • Habilitar secuencia de lectura de reordenamiento para bk client de forma predeterminada PR #4139
  • Se corrigieron algunas métricas generadas por prometheus client sin información de tipo PR #3927
  • Soluciona la vulnerabilidad de carga de archivos arbitrarios con httpServerEnabled PR #3982
  • Habilitar registros kv en la configuración log4j PR #3986
  • Hacer compatible entre DefaultEntryLogger y DirectEntryLogger PR #4041

corredor de apuestas

  • Corrección del error de JournalQueueSize negativo PR #4077
  • Arreglar la imprecisión del acelerador de compactación PR #3192
  • Corregir datos perdidos al configurar varios directorios del libro mayor PR #3329
  • Intente utilizar jdk api para crear un vínculo físico al cambiar el nombre del archivo al compactarlo. PR #3876
  • [característica] [servidor] agrega propiedades dbStorage_readAheadCacheBatchBytesSize cuando lee las entradas con anticipación PR #3895
  • Se corrigió la pérdida de claves en EntryLocationIndex cuando ledgersToDelete está vacío PR #3903
  • Se corrigió la recolección de basura bloqueada por una excepción de tiempo de ejecución PR #3901
  • Omitir la sincronización de RocksDB cuando no haya cambios PR #3904
  • Habilite PCBC completeObjects autoShrink para reducir el uso de memoria y gc PR #3913
  • [Solución] Reciclar eliminando solicitudes de lectura y escritura cuando ocurrieron varias excepciones PR #3912
  • Se corrigió el proceso de desmantelamiento del corredor de apuestas de bloques fallidos replicados en el libro mayor PR #3917
  • Admite omitir registro de diario no válido en la etapa de diario de respuesta PR #3956
  • Evite la compactación para desencadenar descargas adicionales DbLedgerStorage PR #3959
  • Reparar la pérdida de memoria de la memoria directa en el registrador de entrada de memoria directa. PR #3983
  • Unificar ByteBufAllocator para el componente DirectIO PR #3985
  • Imprimir progreso de compactación PR #4071
  • Optimizar el intervalo de espera de verificación de desmantelamiento de las casas de apuestas PR #4070
  • Arreglar el disparador GC no funciona PR #3998
  • Permitir establecer números máximos de operaciones en un solo lote de rocksdb PR #4044
  • Agregar registro de lectura fallida para el verificador de contabilidad. PR #4010
  • Se corrigió la pérdida de solicitud de lectura y escritura cuando el ejecutor lanza RejectedExecutionException PR #4024
  • Mejorar el rendimiento de lectura de DefaultEntryLogger. PR #4038

Client

  • [Error] Siempre se crea un libro mayor huérfano PR #3813
  • Se corrigió el error de cálculo de la suma de verificación cuando la carga útil es CompositeByteBuf con ReaderIndex > 0 PR #4196
  • No se corrigieron casas de apuestas conocidas después de restablecer los bastidores para todos los BK PR #4128
  • Se solucionó el problema con la compatibilidad binaria con versiones anteriores de grpc en tiempo de ejecución en client PR #3997
  • Política de colocación consciente de la región del nodo local de soporte de escritura de entrada PR #4063
  • La política de ubicación de Rackaware admite el reconocimiento de nodos locales por nombre de host PR #4057
  • Utilice netty-bom para alinear las versiones de la biblioteca netty, agregue epoll para linux-aarch_64 PR #4204

Autorrecuperación

  • Haga que la recuperación automática habilite stickyReadS de forma predeterminada. PR #4125
  • Admite lógica de reintento para recuperación automática PR #3799 0
  • Soluciona el problema del bloqueo del auditor elector ejecutor. PR #4165
  • Se corrigió el error de replicación fallida de recuperación automática mediante el error de agregar entrada vallada PR #4163
  • Solucionar el problema de fuga del hilo del auditor. PR #4162
  • La recuperación automática admite lectura por lotes PR #4211

Otros

  • Se agregó el comando CLI para iniciar el servicio de tienda estatal sin un corredor de apuestas PR #2648
  • Agregar comando de reubicación de conjunto que cumple con la política de ubicación PR #2931
  • Simultaneidad del grupo de ajuste PR #3432
  • Problema 4136: Las configuraciones de registro de reparación no funcionan en la imagen docker PR #4137
  • [lanzamiento] Forzar el uso de linux/amd64 para compilar la versión PR #4060

Cambios de dependencia

Dependencias notables actualizadas y direcciones CVE, que incluyen:

  • Actualice snappy-java para abordar múltiples CVE PR #3993
  • Actualice grpc y protobuf para abordar CVE-2023-32732 PR #3992
  • Actualice Zookeeper a 3.8.3 para abordar CVE-2023-44981 PR #4112
  • Actualice Netty a 4.1.107.Final y io_uring a 0.0.25.Final PR #4224
  • Recuperar org.apache.commons:commons-compress de 1.21 a 1.26.0 PR #4214
  • Actualizar la versión de los bocetos de datos de 0.8.3 a 3.2.0 PR #3264
  • Problema 3567: actualice la versión de rocksdb para evitar errores de discrepancia en la suma de comprobación PR #3568
  • corrección (segundo): actualice el códec común a 1.13 PR #3508
  • Elimina las dependencias avro, hadoop-auth y jersey-json de hadoop-common para resolver CVE-2019-10202, CVE-2023-1370 y CVE-2022-45685 PR #3911
  • Actualice la imagen base de docker para resolver CVE-2023-0286 PR #3916
  • Actualice bc-fips a 1.0.2.4 para corregir CVE-2022-45146 PR #3915
  • Actualice la versión del embarcadero a 9.4.51.v20230217 PR #3937
  • Versión mejorada de guayaba de 31.0.1-jre a 32.0.1-jre PR #4008
