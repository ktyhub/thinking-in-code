bookkeeper release-4.18.0

Versión Publicado10 jun 2026 Fuenteapache/bookkeeper original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

liberación del contable-4.18.0

La versión 4.18.0 es una versión de funciones importantes. Introduce el registro estructurado en todo el base de código (BP-69), migra la serialización del protocolo de cable a LightProto y la E/S nativa biblioteca a Rust y eleva la versión mínima requerida de Java a 17. También incluye muchos mejoras, correcciones de errores y actualizaciones de dependencias/CVE.

Se recomienda a los usuarios de Apache BookKeeper que actualicen a 4.18.0. Por favor revise el cambios importantes y problemas conocidos a continuación antes de actualizar.

Destacados

  • Registro estructurado (BP-69): todos los registros de BookKeeper se han convertido desde SLF4J formatear cadenas en slog, un registro estructurado API donde cada evento lleva clave/valor escrito atributos (por ejemplo, ledgerId, entryId). El contexto del registrador se propaga a través de client operaciones, por lo que todos los eventos relacionados con el mismo libro mayor se etiquetan automáticamente. Los atributos son representados por log4j2 tanto en texto plano como en salida JSON, con un ejemplo configuración para registros JSON compatibles con OpenTelemetry. PR #4751, #4754, #4755, #4756, #4757, #4758, #4765, #4766, #4767, #4770
  • Serialización de LightProto: protocolo de conexión, formatos de metadatos y transmisión de BookKeeper Los protos de almacenamiento se han migrado de protobuf-java a LightProto, que analiza y serializa directamente en buffers Netty sin asignaciones intermedias, lo que reduce la presión del GC en el camino caliente. PR #4779, #4780, #4781, #4783
  • Biblioteca de E/S nativa reescrita en Rust: la biblioteca native-io utilizada para E/S directa en el corredor de apuestas ha migrado de C a Rust. PR #4738
  • Línea base de Java 17: ahora se requiere Java 17 o posterior para compilar y ejecutar BookKeeper. PR #4446
  • El desmantelamiento de la casa de apuestas limpia la cookie (BP-68) — El administrador de desmantelamiento API ahora elimina la cookie de la casa de apuestas del almacén de metadatos, por lo que se puede almacenar una identificación de la casa de apuestas fuera de servicio. reutilizado sin limpieza manual. PR #4500, #4592
  • ZooKeeper limitación de lectura durante la replicación repetida (BP-66) — Ahora se puede volver a replicar acelera sus lecturas ZooKeeper, protegiendo el almacén de metadatos de tormentas de lectura cuando muchas Se están recuperando los libros de contabilidad. PR #4258
  • Lecturas por lotes de entradas no confirmadas (BP-62) — batchReadUnconfirmedAsync ahora es expuesto en ReadHandle. PR #4739

Cambios importantes

  • Se requiere Java 17+ para compilar y ejecutar BookKeeper (anteriormente Java 11) PR #4446
  • El valor predeterminado de readOnlyModeOnAnyDiskFullEnabled cambió a true: ahora un corredor de apuestas pasa a solo lectura tan pronto como cualquier disco del libro mayor esté lleno, en lugar de solo cuando todos los discos están llenos. Vuelva a configurarlo en false para restaurar el comportamiento anterior. PR #4520
  • El módulo bookkeeper-slogger ha sido eliminado, reemplazado por el slog estructurado. registro API (BP-69) PR #4764
  • Se eliminó el método obsoleto y mal escrito setAllocatorPoolingConcurrenncy: use setAllocatorPoolingConcurrency en su lugar PR #4431
  • Se eliminó la clase obsoleta MathUtils PR #4274

Problemas conocidos

  • PR #4730 (lea la corrección de bloqueo de subprocesos en sendResponseAndWait), incluido en esta versión, podría causar un punto muerto en la ruta de lectura del corredor de apuestas. Ha sido revertido en PR #4830, que será parte de 4.18.1.

Características

  • Admite la configuración de mantenimiento de conexión TCP para el servidor de apuestas PR #4762
  • Nuevo client API para verificar si BookKeeper client está conectado al servicio de metadatos PR #4342
  • Migrar de Yahoo DataSketches a Apache DataSketches 7.0.1 (KLL) PR #4774
  • Permitir configurar log4j2 AsyncLogger PR #4269

  • Enriquecer las métricas de GC para analizar mejor el comportamiento de GC y el tiempo invertido en cada fase PR #4384

  • Establecer ThreadFactory para el ejecutor en EntryLoggerAllocator PR #4562
  • Agregar propiedad de directorio temporal para la biblioteca nativa PR #4533
  • Aplicar la configuración WRITE_BUFFER_WATER_MARK a canales secundarios en el servidor de apuestas Netty PR #4337
  • Omitir la inserción de caché optimista desperdiciada en SingleDirectoryDbLedgerStorage cuando se mantiene el bloqueo de escritura PR #4306
  • Registre solo los ajustes de configuración anulados al iniciar BookieServer PR #4768
  • Eliminar el seguimiento del tiempo del diario no utilizado PR #4006

Client

  • Elimina la sincronización innecesaria en LedgerHandle.getLength() PR #4516

  • El comando readledger lee todas las entradas de una casa de apuestas cuando no se proporcionan los ID de la primera y la última entrada PR #4692

  • Arreglar que el corredor de apuestas WatchTask se atasque PR #4481

  • Se corrigió el formato de mensajes de excepción en RocksdbKVStore PR #4448
