go-ethereum v1.17.0

<!-- Circuito con incrustaciones Eezo (v1.17.0) -->

Este es un lanzamiento de funciones, con todo el desarrollo acumulado de los últimos 3 meses. Vea a continuación los aspectos más destacados.

Tenga en cuenta que esta versión contiene varias correcciones de seguridad críticas, así como muchas correcciones de errores, y se recomienda para todos los usuarios. Sin embargo, si tiene cuidado con las actualizaciones, también puede instalar v1.16.9, que solo tiene las correcciones de seguridad críticas. Específicamente, esta versión corrige CVE-2026-26313, CVE-2026-26314, CVE-2026-26315.

Recomendamos recrear su clave de nodo p2p después de instalar esta actualización, lo que puede hacer eliminando el archivo DATADIR/geth/nodekey antes de reiniciar geth. Tenga en cuenta que esto provocará un cambio en el ID del nodo p2p, lo que puede interrumpir las configuraciones de emparejamiento estático.

Destacados

Nodo de archivo basado en rutas con pruebas

El nodo de archivo basado en rutas ahora puede ofrecer pruebas (a través de eth_getProof) del estado de bloques más antiguos.

Puede configurar el rango de bloques que admita la prueba independientemente de la disponibilidad de otros estados de archivo. Específicamente, puede usar el indicador de línea de comando --history.trienode para establecer la cantidad de bloques para los cuales se rastrearán los nodos del árbol.

Esta característica está deshabilitada de forma predeterminada. Tenga en cuenta que el historial de estado no se puede recuperar fácilmente una vez eliminado, ya que solo se puede generar procesando bloques. Sin embargo, puede habilitar el historial de trienodos (y/o el historial de estado) en cualquier momento para convertir un nodo completo en un nodo de archivo parcial, manteniendo el estado desde ese momento en adelante.

#32727, #32621, #33551, #32981, #33399, #32913, #33303, #33584, #33329, #33681, #33103, #33098, #33515, #32247

Soporte de historial de EraE

Geth ahora admite el formato de archivo EraE, un formato de archivo para el historial de la cadena posterior a la fusión.

#32157, #33827

OpenTelemetry Seguimiento

El servidor RPC ahora admite el rastreo OpenTelemetry, incluido el soporte para el rastreo distribuido. También hemos agregado algunos tramos de seguimiento para el procesamiento de bloques mediante el motor API, es decir, engine_newPayload.

#33599, #33452, #33780, #33521

Todos los cambios

Geth CLI

  • Se ha eliminado el subcomando geth version-check. Este comando verificó el sitio web geth en busca de avisos de vulnerabilidad firmados y le indicaría si son necesarias actualizaciones (#33498)
  • Ahora hay un indicador de línea de comandos --miner.maxblobs para establecer un límite de blobs incluidos en bloques construidos (#33129, #33302)
  • Geth ahora admite la creación de perfiles continuos con el piroscopio Grafana (#33623)
  • Se solucionó un error poco común que podía detener la producción de bloques en el modo geth --dev (#33146)
  • Un nuevo indicador --rpc.rangelimit configura el rango máximo de bloques para eth_getLogs (#33163)
  • geth --exitwhensynced ahora configurará el bloque finalized y safe (#33038)
  • geth --ethstats ahora informa el tiempo de procesamiento de la nueva carga útil al servidor de estadísticas (#33395)
  • Se han solucionado muchos problemas menores en el procesamiento de indicadores de línea de comandos de Geth (#33379, #33338, #33330, #32999, #33279, #33252)
  • El comando evm blocktest ahora puede leer nombres de archivos desde la entrada estándar cuando no se proporciona ninguna ruta (#32824)

Implementación de bifurcación

  • EIP-8024: SWAPN, DUPN, EXCHANGE compatibles con versiones anteriores (#33095, #33787, #33614, #33361)
  • Hemos implementado Engine_getBlobsV3 (#33404, #33444)
  • El motor API ahora rechaza llamadas con una versión de carga útil incorrecta (#32754, #33322)
  • blsync se ha actualizado para Fusaka (#33349, #33272, #33065, #32674)
  • Se han realizado algunos trabajos para la migración del estado a un árbol binario, y esto reemplaza la implementación del árbol Verkle (#33807, #33739, #33694, #32445, #33461)
  • Se ha corregido parte de la semántica de la lista de acceso mientras se trabajaba en las listas de acceso a nivel de bloque EIP-7928 (#33281, #33637, #33450)

Núcleo

  • La biblioteca crypto/ecies permitió la extracción de la clave privada utilizada para la derivación de claves mediante la observación del tiempo de respuesta. Recomendamos rotar la clave de nodo después de aplicar esta actualización. (#33669)
  • Cuando se encuentra un bloque faltante durante la desindexación de tx, Geth ahora lo omitirá y seguirá adelante en lugar de entrar en un bucle infinito. (#33573)
  • Geth ahora recopila y exporta opcionalmente métricas sobre el tamaño total del estado (#33254, #33376, #33415)
  • Hay un nuevo gancho OnStateUpdate, que se llama después de que se haya confirmado todo el estado de un bloque. Esto da acceso al conjunto de cambios del bloque. (#33490)
  • Se han solucionado algunos errores menores de rastreo (#32919, #33148, #33644, #33214)
  • También se han solucionado varios problemas menores en la base de datos del congelador (#33747, #33025, #33203, #33344)
  • La operación setHead ahora desarma el bloque finalizado, en los casos en que el rango del bloque revertido se extiende antes de él. (#33486)
  • El método SignatureValues de types.Signer ahora informa un error por tamaños de firma no válidos (#33647)
  • Geth imprime mensajes de registro detallados para 'bloques lentos' (#33655, #33525, #33442, #32812, #33659, #33532)
  • La configuración de Pebble se ha modificado para mejorar el rendimiento (#33697, #33353, #33315)
  • Se ha solucionado un fallo poco común en el indexador de registros relacionado con el manejo de reorganización (#33810)
  • Se ha corregido la contabilidad del tamaño de las diferencias de estado internas, por lo que las diferencias de estado ahora se enviarán al almacén de disco con menos frecuencia (#33505)
  • Dado que la variante de la función hash keccak256 utilizada por Ethereum ya no tiene una ruta rápida en la biblioteca estándar, hemos proporcionado la implementación de keccak nuevamente en nuestro repositorio (#33323).

Biblioteca

  • La biblioteca RLP ahora tiene un tipo RawList para tratar listas no decodificadas de una manera más conveniente (#33755, #33834, #33840, #33841)
  • Se han mejorado el iterador RLP de bajo nivel y sus usos (#33245, #33188, #33820)
  • Clef ahora puede firmar transacciones de blobs con pruebas de celda (#32910)
  • Se corrigieron algunos errores en las esquinas en la exportación de métricas (#33749, #33748)
  • La biblioteca de billetera de hardware ahora es compatible con Ledger Nano Gen5 y habilita correctamente la firma EIP-712 para todas las versiones compatibles. (#33297, #33113)
  • SignTextWithPassphrase ahora funciona correctamente con todas las carteras de hardware compatibles (#33138)
  • Se corrigieron algunos errores menores en la implementación del almacén de claves (#33606, #33602, #33090)
  • La función bitutil.XORBytes ha quedado obsoleta en favor del paquete stdlib crypto/sutil (#33331)
  • Se solucionó una pérdida de memoria en la cadena de luz de baliza client (#33483)

RPC

  • eth_getTransactionByHash ahora devuelve blockTimestamp como parte del objeto de transacción (#33709)
  • Los códigos de error para algunas condiciones en eth_simulateV1, eth_getLogs, eth_getStorageAt se han mejorado para cumplir mejor con la especificación RPC de ejecución (#33007, #33320, #33282)
  • eth_simulateV1 ahora selecciona el conjunto correcto de precompilaciones para el encabezado simulado (#33363)
  • eth_sendTransaction y eth_fillTransaction ahora tienen el valor predeterminado EIP-1559 (#33058)
  • La implementación GraphQL recibió algunas correcciones de errores en los casos en los que no se encuentra un elemento resuelto. (#33184, #33225)
  • En GraphQL, el gasPrice ahora se puede recuperar para los tipos de transacción 0x3 y 0x4 (#33542)
  • El servidor RPC ahora habilita HTTP2 de texto sin formato para mejorar el rendimiento (#33812)
  • El RPC client ya no envía tramas HTTP2 RST_STREAM falsas (#33122)
  • Se han solucionado algunos errores menores de codificación de JSON en ethclient (#33693, #33242, #33464)
  • El gethclient tiene una nueva envoltura del callTracer (#31510)
  • En callTracer, los registros reportados ahora contienen un campo index que es el índice del registro dentro de la transacción (#33629)

Redes P2P

  • El mecanismo de latido del grupo de transacciones tuvo algunas correcciones para posibles fugas de recursos (#33704)
  • Las implementaciones de los protocolos eth y snap ahora validan la mayoría de los mensajes p2p antes de decodificar su contenido. Esto mejora la seguridad y el rendimiento de sincronización en algunos casos. (#33835)
  • Se han corregido algunos errores en el grupo de transacciones de blobs y ahora acepta transacciones sin intervalos de forma muy limitada (#32717, #33775, #33474, #33352, #33301, #33260).
  • El estado de sincronización instantánea ahora se rastrea mejor, lo que garantiza que el motor API (#33157) no active accidentalmente una sincronización instantánea.
  • Se mejoró el programador de sincronización instantánea para proteger mejor la base de datos trie contra mutaciones accidentales mientras el nodo procesa bloques. Esto resuelve algunos casos extremos en los que la base de datos podría estar dañada (#33428)
  • Se corrigió la implementación de sincronización del encabezado para manejar mejor las operaciones setHead durante la sincronización (#33481)
  • Las conexiones entre pares que entreguen transacciones obsoletas se verán menos penalizadas, ya que la entrega de algunas transacciones obsoletas es algo común. (#32725)
  • Los pares que anuncian transacciones de un tipo y entregan un tipo diferente ahora se desconectan como penalización (#33378)
  • De manera similar, los pares que entreguen pruebas KZG no válidas ahora serán desconectados (5b99d2bba4)
  • El grupo de transacciones tiene nuevas métricas para la cantidad de cuentas con transacciones (#33646, #33654)

Para obtener un resumen completo de los cambios, consulte el hito de lanzamiento de Geth 1.17.0.

Como con todos nuestros lanzamientos anteriores, puede encontrar:

  • Binarios prediseñados para todas las plataformas en nuestra [página de descargas] (https://geth.ethereum.org/downloads/).
  • Imágenes Docker publicadas bajo ethereum/client-go (use la etiqueta "estable").
  • Paquetes de Ubuntu en nuestro [repositorio PPA de Launchpad] (https://launchpad.net/~ethereum/+archive/ubuntu/ethereum).
  • Paquetes de macOS en nuestro repositorio Homebrew Tap.
