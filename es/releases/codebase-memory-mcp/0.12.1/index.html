#v0.12.1

Cada ruta de instalación vuelve a funcionar y los gráficos de Helm se unen al gráfico.

v0.12.1 corrige las instalaciones de paquetes de v0.12.0 y las otras rutas de instalación que encontramos rotas al verificar cada canal. También vincula los gráficos de Helm con lo que implementan y evita que el gráfico invente un registro para imágenes de contenedores.

¿Actualizando? El primer índice de cada proyecto existente después de la actualización es una reconstrucción completa, una vez (las identidades de las imágenes cambiaron; ver más abajo).

Corregido: instalaciones

  • Instalaciones de npm, PyPI y Go. npm i, pnpm add, pip install y el contenedor Go no pudieron instalar v0.12.0 en ninguna plataforma. Cada contenedor rechazó un miembro de archivo superior a 256 MiB, y cada binario v0.12.0 tiene entre 331 y 335 MB. Los límites de tamaño han desaparecido de los tres envoltorios. El archivo aún se verifica con el checksums.txt de la versión antes de descomprimirlo, su contenido debe ser exactamente los archivos esperados y el binario debe responder --version. Gracias, @hidroplexus, por el informe preciso (#2657).
  • Homebrew. La fórmula todavía estaba en 0.10.3, y en Linux instaló la compilación vinculada dinámicamente, que necesita glibc 2.38 (Ubuntu 22.04, Debian 12 y RHEL 9 no la tienen). Ahora instala la versión actual y, en Linux, la compilación estática -portable que se ejecuta en cualquier distribución.
  • go install. Un go install .../pkg/go/cmd/codebase-memory-mcp@vX.Y.Z fijado nunca funcionó y @latest instaló una versión obsoleta. Las versiones ahora llevan etiquetas pkg/go/vX.Y.Z y el contenedor instala la versión que coincide con su propia versión.
  • npm next. La etiqueta dist next ya no apunta a una versión candidata anterior; un lanzamiento estable lo mueve.
  • Documentos. Winget y Chocolatey figuraron como canales de instalación, pero no están publicados; se retiran hasta que estén. Windows arm64 se construye y ahora está en la lista.

Pruebas de humo de ruta de instalación. Cada solicitud de extracción y cada versión ahora instala los contenedores npm, PyPI y Go, de la misma manera que lo hace el administrador de paquetes de un usuario, en los archivos de la versión real, y ejecuta el binario de cada uno de ellos instalado. Una versión se publica solo después de que se realizan estas instalaciones, por lo que un instalador que no pueda instalar lo que enviamos ya no podrá comunicarse con usted.

Gráficos de timón en el gráfico

Un gráfico de Helm solía ser un nodo aislado. Ahora se vincula a lo que implementa (#2663):

  • Gráfico → objetos (DEPLOYS, via: chart): cada objeto Kubernetes renderizado a partir del templates/ del gráfico (los objetos de un subgráfico pertenecen al subgráfico).
  • archivo de valores → Gráfico (CONFIGURES): values.yaml y values-<x>.yaml junto a Chart.yaml.
  • Gráfico → imágenes (DEPLOYS, ref: image): cada imagen tiene el nombre de sus objetos literalmente (una imagen con plantilla no nombra ninguno).

HelmRelease → Chart → Deployment → Image es ahora un camino transitable. En 20 repositorios de infraestructura, los gráficos sin borde de salida cayeron de 238 de 260 a 109, y aparecieron 2.511 enlaces de gráfico a objeto; todos los demás bordes permanecieron idénticos.

Las imágenes mantienen en el registro los nombres en clave

Una imagen sin un host de registro solía almacenarse en un docker.io/library/... inventado (#2654). Docker Hub es solo el valor predeterminado de Docker: Podman y CRI-O resuelven nombres cortos a través de una lista de búsqueda, los espejos los reescriben y es posible que no exista una etiqueta de compilación local en ningún registro. Una imagen ahora mantiene su nombre tal como está escrito, con registry: unknown cuando no se indica ningún host; se mantiene un host indicado (la ortografía de Docker Hub se convierte en docker.io). FROM nginx y image: docker.io/library/nginx ahora son dos nodos de imagen. Esto cambia las identidades de las imágenes, razón por la cual cada proyecto se reconstruye una vez después de la actualización.

Notas de actualización

  • El primer índice de cada proyecto existente después de la actualización es una reconstrucción completa, una vez.
  • Los nodos de imagen sin un registro establecido ahora llevan registry: unknown y el nombre tal como está escrito, en lugar de docker.io/library/....
