Novedades de v0.5.6

search_code v2: búsqueda de código aumentada con gráficos

La herramienta search_code ha sido completamente reescrita con un proceso de 4 fases que combina velocidad grep con inteligencia de gráficos de conocimiento:

  • 3 modos de salida: compact (predeterminado: nombres de funciones + líneas coincidentes), full (cuerpos de funciones completos con coincidencias resaltadas), files (lista de archivos con recuentos de coincidencias)
  • Clasificación de gráficos: resultados clasificados por importancia estructural (definiciones primero, funciones populares después, pruebas al final)
  • Expansión de bloque: las coincidencias de grep se expanden automáticamente para contener los límites de la función; no más fragmentos de línea fragmentados
  • path_filter: búsquedas de ámbito en directorios específicos (p. ej., solo src/)
  • Líneas context: contexto configurable alrededor de partidos en modo completo
  • Resumen de distribución de directorios: muestra qué directorios contienen coincidencias Vuelve con gracia a grep sin formato cuando el proyecto no está indexado.

Kubernetes y personalización de indexación

Soporte completo de infraestructura como código para manifiestos Kubernetes:

  • Analiza implementaciones, servicios, ConfigMaps, secretos, ingresos, cronjobs y más de 20 tipos de recursos.
  • Personalizar la resolución de superposición (base → relaciones de superposición)
  • Los nodos de recursos aparecen en el gráfico de conocimiento con etiquetas, espacios de nombres y especificaciones de contenedor.
  • Nueva etiqueta de nodo Resource en el esquema gráfico.

Asignaciones de extensiones definidas por el usuario

Extensión de archivo personalizada → asignaciones de idiomas a través de .codebase-memory.json (nivel de proyecto) o $XDG_CONFIG_HOME/codebase-memory-mcp/config.json (global):

{"extra_extensions": {".blade.php": "php", ".mjs": "javascript"}}

La configuración del proyecto tiene prioridad sobre la configuración global.

Correcciones de seguridad

  • Inyección SQL en búsqueda de tienda/BFS e inyección de argumentos en servidor HTTP (#124 — @map588)
  • Usar después de liberar en handle_manage_adr obtener ruta (#126 — @halindrome)
  • Prevención de archivos Ghost .db: los controladores de consultas ahora verifican que el proyecto existe antes de abrir SQLite; evita que se acumulen archivos de bases de datos vacíos (#120)
  • Reemplazo binario: nuevo cbm_replace_binary con patrón de desvinculación antes de escribir, maneja destinos de solo lectura y reserva de cambio de nombre de Windows (#114)

Correcciones de estabilidad y compatibilidad

  • Búfer estándar MCP: se corrigió la discrepancia en el ARCHIVO poll()/getline()* que causaba que tools/list se bloqueara en algunos clients (#99 — @halindrome)
  • SQLite WAL ocupado_timeout: configurado antes de journal_mode=WAL para evitar SQLITE_BUSY en contención de bloqueo (#117 — @halindrome)
  • Importar analizador O(N²) → O(N): se reemplazó el bucle ts_node_child() indexado con el recorrido TSTreeCursor: corrige la desaceleración cuadrática en archivos con muchas importaciones (#107 — @halindrome)
  • No coincide el nombre del proyecto de sesión: detect_session ahora usa el mismo cbm_project_name_from_path() como canalización
  • Windows: corrección del nombre del archivo zip de la interfaz de usuario, envoltorios de compatibilidad setenv/unsetenv, respaldo de USERPROFILE cuando se desarma HOME
  • Linux: agregue -D_GNU_SOURCE para visibilidad de strcasestr (#111 — @trollkotze)
  • libgit2: corrige el error de compilación -Wmissing-field-initializers (#91 — @jsyrjala)
  • Pérdida de memoria: resolve_store filtró una conexión SQLite al consultar .db desvinculado después de delete_project

Pruebas de humo completas

Ampliado de 4 fases a 7, cubriendo el ciclo de vida binario completo:

  • Fase 5: transporte estándar de MCP: inicializa el protocolo de enlace, herramientas/lista, llamada de herramienta de ida y vuelta, encuadre de longitud de contenido (compatibilidad con OpenCode)
  • Fase 6: subcomandos CLI: instalar/desinstalar/actualizar --dry-run, configurar/obtener/restablecer configuración, reemplazo binario simulado con mayúsculas y minúsculas de solo lectura
  • Fase 7: llamadas a herramientas avanzadas de MCP: search_code v2, get_code_snippet a través de JSON-RPC Las pruebas de humo ahora se ejecutan en la infraestructura de prueba Docker (test-infrastructure/run.sh smoke) y en CI en las 10 combinaciones de plataforma x variante.

Actualizar mejoras en los comandos

  • Bandera --dry-run: muestra lo que sucedería sin descargar o modificar archivos
  • Banderas --standard / --ui: omita el mensaje de variante interactiva (compatible con CI)
  • Reiniciar recordatorio después de una actualización exitosa

CI e infraestructura

  • Acciones GitHub fijadas para confirmar SHA (bot dependiente: VirusTotal 5.0.0, nodo de configuración 6.3.0, instalador cosign, attest-build-procedencia)
  • Infraestructura de prueba Docker: servicios smoke y smoke-amd64 para pruebas de humo locales multiplataforma
  • Se limpiaron los artefactos de la era Go, se actualizó THIRD_PARTY.md para el proyecto C puro.
