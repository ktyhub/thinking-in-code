código base-memoria-mcp 0.8.0

📦 Página de lanzamiento archivada: los archivos binarios de esta versión ya no se publican. Obtenga la última versión.

El titular: tres nuevos motores LSP con reconocimiento de tipos. Java, Kotlin y Rust ahora obtienen resolución LSP híbrida completa: resolución de llamadas con reconocimiento de tipos a través de jerarquías de clases, vinculación de anotaciones/atributos, coincidencia de sobrecarga con reconocimiento de firmas, manejo de genéricos e inferencia de tipos entre archivos, uniéndose a C/C++, Python, TypeScript/JavaScript, Go, C# y PHP para 9 lenguajes bajo LSP híbrido.

Inteligencia de arquitectura

  • Detección de comunidad de Leiden: get_architecture ahora muestra comunidades de Leiden de varios niveles (reemplazando a Louvain de un solo nivel): límites reales de módulo en gráficos del tamaño de un kernel, calculados en segundos en lugar de minutos.
  • Métricas de cuello de botella de cálculo consultables: las funciones conllevan métricas de complejidad, profundidad de bucle y patrón de escaneo en el gráfico; ahora puede consultar con cifrado su base de código para sus propios puntos de acceso algorítmicos. (Usamos exactamente esto para encontrar y arreglar varios de los nuestros, ver más abajo).
  • Compatibilidad con Helm: plantillas de gráficos, vinculación de llamadas include y bordes de dependencia Chart.yaml; Etiquetas de bloques HCL plegadas en nombres de nodos; Las macros del preprocesador C/C++ ahora son nodos de macros de primera clase (2,3 millones de ellos en el kernel de Linux).

Estabilidad: el mayor esfuerzo de endurecimiento hasta el momento

La flota de versiones ahora indexa 16 grandes repositorios OSS de extremo a extremo: el kernel de Linux (4,8 millones de nodos), elasticsearch, kubernetes, el compilador TypeScript, bitcoin, zig, Symfony y más, con puertas de validez a nivel de base de datos. Esa búsqueda, además de excelentes informes de la comunidad, cerró una larga lista de fallos:

  • Se eliminó la familia de fallas de C++/código plantilla: matrices de argumentos de plantilla no inicializadas, búsquedas de parámetros fuera de límites, recursividad de resolución ilimitada, explosiones de evaluación de expresiones: reportados en #424, #427/#428/#432, #312, #322/#323, #336, #344, #355, #360, #385.
  • Unificación del asignador (#424): todo el binario (tree-sitter suministrado, SQLite, libgit2) ahora se ejecuta bajo un asignador, poniendo fin a una clase de corrupción del montón de asignadores cruzados en C++ complejo.
  • Se solucionó el bucle de bloqueo de inicio (#235, #439): un desbordamiento del búfer de pila en la ruta de error de la lista de proyectos podría SIGABRT el servidor para todos los proyectos; Una base de datos de caché corrupta ya no cancela todas las sesiones.
  • Integridad de la base de datos, de extremo a extremo: las claves de índice de gran tamaño ahora se extienden correctamente a las páginas desbordadas, todas las propiedades JSON se escapan y se validan en el productor, el índice url_path siempre coincide con su columna generada y los archivos WAL se controlan al cerrar/iniciar (#387). Todas las bases de datos de la flota de 16 repositorios pasan limpiamente PRAGMA integrity_check.
  • Ciclo de vida del servidor: los servidores stdio salen con su padre a través de un dispositivo de vigilancia de muerte (#406), se admite MCP ping (#354), los identificadores de cadena JSON-RPC se conservan (#253), el nivel de registro se puede configurar a través de CBM_LOG_LEVEL (#413).
  • Windows: API de caracteres anchos para rutas que no son ASCII (#386), pase de historial de git compatible con cmd.exe (#324), sondeo PATHEXT (#221), bloqueo de empaquetado arreglado: el conjunto de pruebas completo está en verde en Windows.
  • Además: rutas fantasma gRPC (#294), modo moderate que elimina silenciosamente subárboles (#411) con directorios excluidos que ahora se informan en los resultados de indexación, nombres de proyectos seguros para el validador (#349), diagnósticos de indicadores de UI (#350).

Rendimiento a escala de kernel

  • Reelaboración de la memoria: streaming del escritor de volcados de SQLite, internación de cadenas, recuperación de páginas del asignador y contrapresión de extracción: el kernel de Linux completo se indexa en aproximadamente 4 minutos en una computadora portátil, dentro de un presupuesto de memoria limitado; La detección de CPU/memoria compatible con cgroup y una anulación de CBM_WORKERS (#364/#365) hacen que el comportamiento del contenedor sea predecible.
  • Se eliminaron las rutas activas cuadráticas, varias de las cuales se encontraron apuntando las nuevas métricas de cuello de botella a nuestra propia base de código: resolución de sobrecarga entre LSP de C/C++ (#410), construcción de registro y rutas de búsqueda en los solucionadores PHP/Python/Java/Kotlin y cálculo de límites de arquitectura. Los monorrepositorios grandes de PHP y Java ven índices completos de orden de magnitud más rápidos (symfony 35x, elasticsearch 9x frente a las primeras compilaciones de este ciclo).
  • La calidad de los gráficos mejoró a través de estas correcciones: la cobertura de resolución y la fidelidad de los bordes son mejores en todos los idiomas admitidos.

Capa de consulta

  • Cypher: predicados EXISTS {} en WHERE, COUNT(DISTINCT) (n.° 239), alternancia de etiquetas (n:A|B) (n.° 242), pruebas de etiquetas en WHERE (n.° 241), WITH DISTINCT (n.° 238), funciones de introspección de cadena/escalar/entidad, escalares de múltiples argumentos y la sintaxis no compatible ahora falla ruidosamente en lugar de devolver vacíos silenciosos. (#373).
  • search_code: errores de expresiones regulares no válidos en lugar de resultados vacíos (#283), & en rutas, sincronización en las respuestas, file_pattern sin comodines como subcadena (#200), .mjs/.cjs/.mts/.cts indexados (#197), plantillas Blade asignadas (#258), importaciones R box::use()/library() (#218/#219).

Una red de seguridad mucho mayor

  • Nuevo conjunto de regresión por gramática en las 159 gramáticas más conjuntos de sondas para extracción, creación de bordes y resolución LSP: el conjunto ahora ejecuta más de 5500 pruebas bajo una estricta política de no omitir (los omisiones son fallas graves).
  • Las reproducciones de fallos se ejecutan como pruebas aisladas de subprocesos con afirmaciones de señal de salida; ASan/LSan corren por la suite; la parte de compilación de macOS Intel ahora está bloqueando, por lo que darwin-amd64 siempre se envía.

Distribución e integraciones

  • Publicado en el Registro oficial de MCP y el directorio Glama; binario estático portátil de Linux en todas las rutas de instalación/actualización.
  • Recibos legibles por máquina install --plan antes de cualquier mutación de configuración (n.° 388), detección de cursor IDE (n.° 222), manejo de PATH nativo de peces (n.° 319), $CLAUDE_CONFIG_DIR respetado (n.° 321), ganchos SessionStart para Codex, Gemini CLI y Antigravity (n.° 330), almacenamiento ADR unificado entre las herramientas MCP y la interfaz de usuario (n.° 256).
