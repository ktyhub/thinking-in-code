Cambios notables

¡Tantos! Consulte la Lighthouse 6.0: Novedades entrada del blog para obtener una descripción detallada.

🆕 Nuevas auditorías

  • Pintura con contenido más grande (LCP) es una nueva métrica que mide el tiempo desde la navegación hasta que se representa el elemento de contenido más grande en la ventana gráfica (#9905, #10213, #10452, #10529).
    • largest-contentful-paint-element es una auditoría complementaria que brinda información sobre qué elemento activó el LCP (#10517, #10713).
  • Cambio de diseño acumulativo (CLS) es una nueva métrica que mide la cantidad de movimiento inesperado de contenido a medida que se carga una página (#9037, #10427, #10495, #10570, #10728).
    • layout-shift-elements es otro diagnóstico complementario que brinda información sobre los elementos que cambiaron a medida que se cargaba la página (#10702).
  • unused-javascript es una auditoría que ha estado funcionando durante algún tiempo pero que recién ahora está activada de forma predeterminada. Tiene en cuenta lo que se cargó JavaScript pero nunca se ejecutó durante la carga de la página y estima el tiempo de carga que podría ahorrarse mediante la división del código, la eliminación del código inactivo o el uso sensato de la tecla de eliminación (#9854).
  • Una PWA maskable-icon simplemente se ve mejor en su pantalla de inicio, por lo que esta nueva auditoría lo alienta a tener al menos una disponible en su manifiesto (#10370).
  • timing-budget expande afirmaciones de presupuesto para que ahora se puedan configurar en todas las métricas de rendimiento (#9901, #9925).
  • La nueva auditoría charset garantiza una codificación de caracteres adecuada para el contenido de la página (#10284, #10389, #10689).
  • image-size-responsive comprueba que las imágenes tengan una relación de aspecto y una resolución que coincidan bien con la forma en que se muestran en una página (#10460).
  • La actualización a la última versión de axe-core ha desbloqueado una serie de nuevas auditorías de accesibilidad: aria-hidden-body, aria-hidden-focus, aria-input-field-name, aria-toggle-field-name, duplicate-id-active, duplicate-id-aria, form-field-multiple-labels, heading-order (#9798).

⚗️ Auditorías experimentales

Estas auditorías aún no forman parte de la experiencia predeterminada de Lighthouse, pero brindarán consejos de rendimiento basados en el análisis de los paquetes JavaScript de una página. Se pueden probar hoy en la línea de comando con el indicador --preset=experimental.

  • legacy-javascript hurga en tus paquetes en busca de polyfills y transformaciones de paquetes que no son necesarios o están desactualizados (#10303, #10568, #10564).
  • duplicated-javascript también se sumerge en JavaScript de una página en busca de código que terminó duplicado dentro de paquetes o en varios paquetes (#10314).
  • unused-javascript ahora se ejecuta de forma predeterminada (como se mencionó anteriormente), pero cuando se ejecuta bajo experimental, la auditoría puede usar mapas de origen para mostrar qué código fuente original nunca se ejecutó y podría posponerse o eliminarse (#10090).

💥 Cambios importantes

  • Las puntuaciones de las métricas de rendimiento se han reponderado para reflejar mejor la experiencia de carga del usuario (#9949).
  • Las curvas de puntuación métrica se han actualizado al ejecutar una prueba Lighthouse de escritorio para tener en cuenta la conexión y la CPU más rápidas (#9911, #10756).
  • Los eventos frameNavigated ahora se usan para rastrear redirecciones, lo que significa que las redirecciones JS ahora se tienen en cuenta al determinar el finalUrl de la ejecución (#10339).
  • El dispositivo móvil emulado se trasladó del Nexus 5x al Moto G4 (pero el DPR existente no se modificó) (#10191, #10749).
  • El ajuste preestablecido mixed-content se eliminó porque no se usaba ampliamente y tarda demasiado en agregarse a la experiencia predeterminada de Lighthouse (#10159, #10750).
  • El valor predeterminado full ha cambiado de nombre a experimental para indicar que es posible que el código no esté listo para ejecutarse de forma predeterminada (#9930, #10311, #10333, #10585).
  • La cadena Chrome UA emulada se actualizó a Chrome 80 (#9967).
  • installable-manifest: los íconos en el manifiesto de la aplicación web deben poder recuperarse para que se consideren instalables (#10168, #10320)

🤖💥 Cambios importantes para usuarios programáticos

Es poco probable que estos cambios afecten a los usuarios finales, pero pueden ser importantes si está escribiendo configuraciones personalizadas, complementos o procesando la salida de Lighthouse JSON.

  • LH.Audit.Context pasado a auditorías ahora se trata como inmutable. Si el código se enviaba anteriormente a context.LighthouseRunWarnings para obtener una advertencia de nivel superior, ahora debería volver a pasarla a runWarnings en el producto de auditoría (#10555).
  • Audit.computeLogNormalScore se ha redefinido para especificar curvas log-normales con mediana y puntos p10 (eliminando el "punto de rendimientos decrecientes"). Las auditorías existentes se han trasladado a esta nueva definición para que no se produzcan cambios en la puntuación (#10715).
  • Se ha agregado una configuración loadFailureMode a los pases Config para controlar el comportamiento en caso de falla en la carga de la página. Anteriormente, esto se controlaba implícitamente (por ejemplo, ninguna página sin conexión disponible no causaba un error) (#9987)
  • Se ha cambiado el nombre de time-to-first-byte a server-response-time para reflejar mejor lo que mide la auditoría (#10735).
  • resource-summary: details.items.size ha sido renombrado a transferSize para mayor claridad (#10700, #10743).
