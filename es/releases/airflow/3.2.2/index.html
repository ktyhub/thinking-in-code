Cambios significativos

  • La actualización SMTP STARTTLS realizada mediante la llamada airflow.utils.email.send_email now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the starttls() se realizó sin un contexto SSL, por lo que se aceptó cualquier certificado. Las implementaciones que apuntan intencionalmente Airflow a un servidor SMTP con un certificado autofirmado o que no se valida y necesitan preservar el comportamiento anterior deben establecer la ruta email.ssl_context = "none" in airflow.cfg. The "default" value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the SMTP_SSL; ahora también se aplica a la ruta STARTTLS. (#65346)

  • En el n.° 64963, la interfaz de usuario de Airflow cambió de los parámetros *_pattern REST API query parameters to the new index-friendly *_prefix_pattern parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (LIKE 'term%' via a range scan) instead of substring-based (ILIKE '%term%'), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing *_pattern y todavía se comportan exactamente como antes. En el n.º 66015, se agregó un interruptor "Coincidir en cualquier lugar" por barra de búsqueda para que los usuarios que confiaban en el comportamiento de la subcadena anterior puedan volver a utilizarlo desde la interfaz de usuario. Cada entrada de búsqueda y cada píldora de filtro de texto ahora tiene un pequeño ícono de expresión regular al lado del valor; al encenderlo se cambia la entrada desde *_prefix_pattern to *_pattern. (#66015)

  • Se corrigió la condición de carrera del activador y el punto muerto que causaba que las tareas diferidas se detuvieran indefinidamente.

    Activadores que llaman a métodos SDK sincrónicos (por ejemplo, get_task_states usado por safe_to_cancel en varios operadores proveedores de Google) podría bloquear el disparador subproceso interno. El desencadenante entonces continuaría latiendo normalmente. aparecer saludable para el programador, mientras procesa silenciosamente cero activadores, causando cada tarea aplazada tiene un tiempo de espera. Esto se informó por primera vez en el número 64620; un Se envió una solución parcial en Airflow 3.2.1 (#64882) pero se introdujo un nuevo punto muerto. con el mismo síntoma visible bajo carga.

    Ambos problemas se solucionan reemplazando la serialización basada en bloqueo con respuesta Multiplexación: cada solicitud ahora lleva una identificación única y la respuesta se enruta de regreso a la persona que llama correcta, por lo que las solicitudes simultáneas de los subprocesos desencadenantes ya no compiten o punto muerto independientemente de cuántos activadores se estén ejecutando o qué métodos SDK llamen.

    Nuevo: mecanismo de vigilancia del subproceso activador

    Incluso con la carrera arreglada, un disparador que bloquea el bucle de eventos (por ejemplo, llamando time.sleep() or performing blocking I/O directly in async def run()) sería previamente deje que el desencadenante parezca saludable indefinidamente.

    Una nueva opción de configuración [triggerer] runner_health_check_threshold (predeterminada: 30 segundos) agrega un perro guardián: si el subproceso activador permanece en silencio por más tiempo que el umbral, el proceso principal deja de actualizar el latido para que el programador pueda detectar el bloqueo y reasigne los activadores en lugar de esperar a que expiren su tiempo de espera individualmente. Establecer la opción a 0 para desactivar el mecanismo de vigilancia. (#66412)

  • Apriete [core] allowed_deserialization_classes_regexp para requerir coincidencias de cadena completa

    Los patrones en [core] allowed_deserialization_classes_regexp ahora coinciden contra todo el nombre de clase usando re.fullmatch() instead of re.match(). Anteriormente un patrón como airflow\.models\.Variable admitía no sólo la clase deseada pero también los nombres que comenzaron con ella (por ejemplo, airflow.models.Variable_Malicious), because re.match solo anclajes al inicio de la cadena.

    El valor predeterminado de esta opción está vacío, por lo que las implementaciones listas para usar son no afectado. Implementaciones que configuraron esta opción con patrones basados en semántica de coincidencia de prefijo; por ejemplo, airflow\.models\. significa "cualquier clase bajo airflow.models" — must add .* al patrón (airflow\.models\..*) para conservar el comportamiento anterior. (#66499)

  • Las clases de referencia de fecha límite personalizadas ahora deben registrarse a través del nuevo deadline_references attribute on AirflowPlugin, matching the existing pattern for custom timetables and custom partition mappers. To use a custom DeadlineReference subclass, register it in a plugin's deadline_references list. Custom references that are not registered will raise DeadlineReferenceNotRegistered en la deserialización. (#66737)
