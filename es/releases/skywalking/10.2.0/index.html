Aviso

No descargue códigos fuente de esta página. Siga documento de compilación si desea crear códigos fuente usted mismo.

Sin H2, más BanyanDB

  • Agregar compatibilidad con BanyanDB 0.8.0.
  • La opción de almacenamiento de H2 se elimina permanentemente.

Proyecto

  • Agregue doc_values para los campos que deben ordenarse o agregarse en Elasticsearch y deshabilite todos los demás.
    • Este cambio no afectaría la implementación existente ni su función para nuestros usuarios de la versión oficial.
    • Advertencia Si hay complementos de consulta personalizados para nuestros índices Elasticsearch, este cambio podría interrumpirlos ya que se bloquean las consultas de clasificación y las consultas de agregación que utilizan campos inesperados.
  • [Cambio importante] Cambie el nombre del módulo debugging-query a módulo status-query. Los API relativamente expuestos están SIN CAMBIOS.
  • [Cambio importante] Todos los archivos jar de skywalking-oap-server ya no se publican a través de maven central. Solo publicaremos el tar fuente y el tar binario en la página de descarga del sitio web y las imágenes docker en el concentrador docker.
    • Advertencia Si está utilizando skywalking-oap-server como una dependencia en su proyecto, debe descargar el archivo tar fuente del sitio web y publicarlo en su repositorio privado de Maven.
  • [Cambio importante] Eliminar H2 como opción de almacenamiento de forma permanente. BanyanDB 0.8 (se requiere OAP 10.2) es fácil, estable y está listo para producción. Ya no necesito H2 como almacenamiento predeterminado.
  • [Cambio importante] Aumente la versión del servidor BanyanDB a 0.8.0. Esta versión no es compatible con las versiones anteriores. Actualice el servidor BanyanDB a 0.8.0 antes de actualizar OAP a 10.2.0.
  • Actualice nodejs a v22.14.0 para la última compilación de UI (booster-ui).
  • Migrar tj-actions/changed-files a dorny/paths-filter.

Servidor OAP

  • Omita el procesamiento de puntos de datos de métricas de OTLP con el indicador FLAG_NO_RECORDED_VALUE, lo que genera un resultado excepcional.
  • Agregue métricas de autoobservabilidad para consultas GraphQL, graphql_query_latency.
  • Reducir el recuento del índice de proceso y agregar un rango de tiempo al consultar el índice de proceso.
  • Aumente Apache commons-io a 2.17.0.
  • Pulir las métricas so11y de eBPF y agregar un recuento de errores para las métricas de consulta.
  • Lista de puntos finales de consulta de soporte con parámetro de duración (opcional).
  • Cambie endpoint_traffic a actualizable para la columna adicional last_ping.
  • Agregue ID de componente (5023) para el marco GoZero.
  • Admite monitoreo de Kong.
  • Admite agregar atributos adicionales [0-5] para métricas de nivel de servicio/punto final.
  • Admite la función de perfilador asíncrono para análisis de rendimiento.
  • Agregar propietario del valor de métricas para el resultado de la consulta topN de métricas.
  • Agregar control de nombres para EndpointDependencyBuilder.
  • Se elimina el tipo de índice BanyanDB.IndexRule.IndexType#TREE. Todos los índices utilizan IndexType#INVERTED ahora.
  • Agregue configuraciones de tamaño máximo de consulta a BanyanDB.
  • La solución "BanyanDBTraceQueryDAO.queryBasicTraces" no admite consultas mediante "trace_id".
  • Distribuidor de datos de malla polaco: no genere métricas de instancia/punto final si están vacías.
  • Adaptar la nueva estandarización de metadatos en Istio 1.24.
  • Aumente netty a 4.1.115, grpc a 1.68.1, aburrido a 2.0.69.
