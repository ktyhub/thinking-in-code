Proyecto

  • Arreglado Duplicate class found debido al objetivo delombok.

Servidor OAP

  • Se corrigió la capa incorrecta de métrica user error en el monitoreo de DynamoDB.
  • El almacenamiento ElasticSearch no verifica los tipos de campos cuando OAP se ejecuta en modo no-init.
  • Soporte para vincular el estado de TLS como parte del componente para la topología del servicio.
  • Soluciona el error de prioridad de ID del componente.
  • Se corrigió la superposición de ID de componente de topología debido a errores en la capa de almacenamiento.
  • [Cambio importante] Mejore el almacenamiento JDBC fusionando tablas y administrando la rotación de tablas por día.
  • [Cambio importante] Las implementaciones y pruebas de Sharding-MySQL se eliminan debido a que tenemos el mecanismo de avance diario de forma predeterminada.
  • Se corrigió la regla de otel k8s-cluster para agregar una dimensión de espacio de nombres para el cálculo de agregación MAL (estado de implementación, réplicas de especificaciones de implementación)
  • Admite la función de creación de perfiles continuos.
  • Soporte para recopilar métricas relacionadas a nivel de proceso.
  • La solución K8sRetag lee el servicio k8s incorrecto del caché debido a una posible discrepancia en el espacio de nombres.
  • [Cambio importante] Admite perfiles de seguimiento entre subprocesos. Se cambian la estructura de datos y la consulta API.
  • Se corrigió la respuesta PromQL HTTP API /api/v1/labels que faltaba la etiqueta service.
  • Se corrigió posible NPE al inicializar IntList.
  • La expresión PromQL de análisis de soporte tiene etiquetas vacías entre llaves para la consulta de metadatos.
  • Admite métrica de alarma OP !=.
  • La consulta de métricas de soporte indica si el valor == 0 representa en realidad cero o ningún dato.
  • Se corrigió NPE al consultar los índices de series que no existen en el almacenamiento ElasticSearch.
  • Admite la recopilación de métricas de memoria caché/buff en el monitoreo de VM.
  • PromQL: elimine los valores vacíos del resultado de la consulta, corrija el parámetro /api/v1/metadata que limit podría causar que se salga del límite.
  • Soporte para monitorear el número total de métricas de k8s StatefulSet y DaemonSet.
  • Admite monitoreo de puerta de enlace Amazon API.
  • Mejora graphql-java para arreglar cve.
  • Mejora Kubernetes Java client.
  • Admite monitoreo Redis.
  • Agregue ID de componente para amqp, amqp-producer y amqp-consumer.
  • Admite modo sin proxy para el receptor aws-firehose
  • Sube armeria a 1.23.1
  • Admite monitoreo Elasticsearch.
  • Se corrigió la respuesta PromQL HTTP API /api/v1/series que faltaba la etiqueta service al coincidir con la métrica.
  • Soporte ServerSide TopN para BanyanDB.
  • Agregar ID de componente para Jersey.
  • Elimine la compatibilidad con OpenCensus, los códigos y documentos relacionados como [está desapareciendo] (https://opentelemetry.io/blog/2023/sunsetting-opencensus/).
  • Admite configuración dinámica de searchableTracesTags
  • Soporte exportErrorStatusTraceOnly para exportar los segmentos de seguimiento del estado de error a través del canal Kafka.
  • Agregar ID de componente para Grizzly.
  • Se corrigió el posible NPE en el receptor Zipkin cuando al Span le faltan algunos campos.
  • Filtrar datos de métricas de Unknown_cluster.
  • Admite monitoreo RabbitMQ.
  • Admite la recopilación de registros lentos Redis.
  • Corregir la pérdida de datos al consultar el registro de tareas de creación de perfiles continuos.
  • Adaptar la consulta de tareas de creación de perfiles continuos GraphQL.
  • Admite expresión de consulta de métricas (MQE) y permite a los usuarios realizar cálculos simples en la etapa de consulta a través de la expresión.
  • Protocolo v2 de consulta de métricas obsoleto.
  • Protocolo de consulta de registros obsoleto.
  • Agregue ID de componente para go-redis.
  • Agregue OpenSearch 2.8.0 al caso de prueba.
  • Agregar módulo ai-pipeline.
  • Admite formato HTTP URI a través de ai-pipeline para realizar reconocimiento de patrones.
  • Agregar un nuevo motor de agrupación de URI HTTP con punto de referencia.
  • [Cambio importante] Utilice el nuevo motor de agrupación de URI HTTP para reemplazar el antiguo mecanismo basado en expresiones regulares.
  • Soporta sumLabeled en MAL.
  • Migrar de kubernetes-client/java a fabric8 client.
  • Las métricas de relación generadas por Envoy ALS consideran que los códigos de estado http >= 400 tienen un error en el lado client.
  • Agregar campo de mensaje de causa al consultar una tarea de creación de perfiles continua.

interfaz de usuario

  • Revertir: función cpm5d. Esta característica se cancela desde el backend.
  • Solución: alertar sobre roturas de enlaces en la topología.
  • Refactorizar el widget de topología para hacerlo más jerárquico.
    1. Elija User como primer nodo.
    2. Si el nodo User está ausente, elija el nodo más ocupado (que tiene la mayor cantidad de llamadas de todos).
    3. Realice un proceso de flujo de izquierda a derecha.
    4. En el mismo nivel, enumere los nodos de arriba a abajo en orden alfabético.
  • Se corrige el ID del filtro cuando la métrica ReadRecords se asocia con el seguimiento.
  • Agregue el menú de puerta de enlace AWS API.
  • Cambiar el protocolo de creación de perfiles de seguimiento.
  • Agregar menú Redis.
  • Optimizar los tipos de datos.
  • Admite el indicador isEmptyValue para consultas de métricas.
  • Agregar menú elasticsearch.
  • [Limpiar plantillas de interfaz de usuario antes de actualizar] Configure showSymbol: true y haga que el punto de datos se muestre en el gráfico de líneas. Limpie el índice ui_template en el almacenamiento elasticsearch o la tabla en el almacenamiento JDBC.
  • [Limpiar plantillas de UI antes de actualizar] Plantillas de UI: simplifique el nombre de la métrica con la etiqueta.
  • Agregar menú MQ.
  • Agregar el ícono de Jeysey.
  • Solución: configure correctamente los selectores de punto final y de instancia con parámetros de URL.
  • Aumentar las dependencias de las versiones de iconos: vue 1.1.4, element-plus 2.1.0, nanoid 3.3.6, postcss 8.4.23
  • Agregue soporte para el protocolo de registro OpenTelemetry.
  • [Cambio importante] La clave de configuración enabledOtelRules pasa a llamarse enabledOtelMetricsRules y la variable de entorno correspondiente pasa a llamarse SW_OTEL_RECEIVER_ENABLED_OTEL_METRICS_RULES.
  • Agregar ícono de oso pardo.
  • Solución: error de visualización de datos de la lista de instancias.
  • Solución: establezca el tipo topN en Número.
  • Admite expresión de consulta de métricas (MQE) y permite a los usuarios realizar cálculos simples en la etapa de consulta a través de la expresión.
  • Aumente la dependencia de zipkin ui a 2.24.1.
  • Sube la invitación a 4.0.5.
  • Aplicar MQE en plantillas de interfaz de usuario de capas General y Virtual-Database.

Documentación

  • Agregar documentación relacionada con la creación de perfiles.
  • Agregue SUM_PER_MIN a la documentación MAL.
  • Haga que los documentos relativos al registro sean más claros y más fáciles para admitir más formatos.
  • Actualice los documentos de administración de clústeres e implementación avanzada.
