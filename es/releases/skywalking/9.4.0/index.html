Proyecto

  • Aumente la dependencia de la interfaz de usuario de lentes Zipkin y Zipkin a 2.24.0.

  • Aumentar la versión de Java a 11.
  • Sube la serpiente yaml a 2.0.

Servidor OAP

  • Agregue ServerStatusService en el módulo principal para proporcionar una nueva forma de exponer el estado de inicio a otros módulos.
  • Agrega Micrómetro como nuevo componente.(ID=141)
  • Refactorizar el caché de sesión en MetricsPersistentWorker.
  • Mejora de la caché: no lea nuevas métricas de la base de datos en dimensiones diminutas.
    // When
    // (1) the time bucket of the server's latest stability status is provided
    //     1.1 the OAP has booted successfully
    //     1.2 the current dimensionality is in minute.
    //     1.3 the OAP cluster is rebalanced due to scaling
    // (2) the metrics are from the time after the timeOfLatestStabilitySts
    // (3) the metrics don't exist in the cache
    // the kernel should NOT try to load it from the database.
    //
    // Notice, about condition (2),
    // for the specific minute of booted successfully, the metrics are expected to load from database when
    // it doesn't exist in the cache.
  • Eliminar el desplazamiento del tiempo de espera de la sesión métrica según la secuencia de creación del trabajador.
  • Corregir declaraciones de anotaciones MetricsExtension en entidades manuales.
  • Soportar la prioridad de los ID de los componentes en las métricas de relación de procesos.
  • Elimina la lógica de abandono en MergableBufferedData, lo que provocó una falta de actualización inesperada.
  • Se corrigió el error establecido LastUpdateTimestamp que provocó que la sesión de métricas expirara.
  • Cambie el nombre de la regla MAL spring-sleuth.yaml a spring-micrometer.yaml.
  • Se corrigió la pérdida de memoria en Zipkin API.
  • Eliminar la dependencia de refresh_interval de los índices ElasticSearch de la configuración de elasticsearch/flushInterval. Ahora, en su lugar, utiliza core/persistentPeriod + 5s como refresh_interval para todos los índices.
  • Cambie elasticsearch/flushInterval a 5 s (antes 15 s).
  • Optimice flushInterval del ElasticSearch BulkProcessor para evitar descargas periódicas adicionales en los flujos masivos continuos.
  • Se agrega un punto inesperado cuando exp es un nombre de métrica pura y expPrefix != null.
  • Soporte de monitoreo MariaDB.
  • Elimina la configuración de intervalos específicos de medida/transmisión en BanyanDB.
  • Agregue configuraciones globales específicas utilizadas para anular configuraciones globales (por ejemplo, segmentIntervalDays, blockIntervalHours) en BanyanDB.
  • Utilice la configuración de intervalo controlada por TTL para el grupo measure-default en BanyanDB.
  • Se corrigió el grupo incorrecto de metadatos no relacionados con el tiempo en BanyanDB.
  • Refactor StorageData#id al nuevo objeto StorageID desde un tipo String.
  • Admite múltiples ID de componentes en el nivel de topología del servicio.
  • Agregue la anotación ElasticSearch.Keyword para declarar el tipo de campo de destino como keyword.
  • [Cambio importante] La columna component_id de service_relation_client_side y service_relation_server_side ha sido reemplazada por component_ids.
  • Admite la definición priority en component-libraries.yml.
  • Mejorar la consulta de topología del servicio. Cuando se detectan varios componentes desde el lado del servidor, El tipo de componente del nodo estaría determinado por la prioridad, que era aleatoria en la versión anterior. *Eliminar component_id de service_instance_relation_client_side y service_instance_relation_server_side.
  • Hacer que la prueba satelital E2E sea más estable.
  • Agregue Istio 1.16 a la matriz de prueba.
  • Registre ValueColumn como etiqueta para registro en el complemento de almacenamiento BanyanDB.
  • Aumente Netty a 4.1.86.
  • Elimine columnas adicionales innecesarias cuando el almacenamiento esté en modo de fragmentación lógica.
  • El mecanismo de vigilancia de soporte del coordinador del clúster para notificar a RemoteClientManager y ServerStatusService.
  • Se corrigió que ServiceMeshServiceDispatcher sobrescribiera el archivo de depuración de ServiceDispatcher cuando se abre SW_OAL_ENGINE_DEBUG.
  • Utilice los operadores groupBy y in para optimizar la consulta de topología para el complemento de almacenamiento BanyanDB.
  • Admite el observador del estado del servidor para MetricsPersistentWorker para verificar las métricas si se requiere inicialización.
  • Corrija que el valor del medidor no sea correcto cuando se usa la función MAL sumPerMinLabeld o sumHistogramPercentile.
  • La solución no puede mostrar eventos adjuntos cuando se utilizan seguimientos de consulta de la interfaz de usuario de Zipkin Lens.
  • Elimine time_bucket para los tipos Stream y Measure en el complemento BanyanDB.
  • Fusionar TIME_BUCKET de Metrics y Record en StorageData.
  • No admite layer en la consulta listServices.
  • Se corrigió time_bucket de ServiceTraffic que no estaba configurado correctamente en slowSql de MAL.
  • Corregir la consulta de registro TopN DAO de BanyanDB.
  • Modificar la configuración de intervalos de BanyanDB.
  • Soporte de monitoreo de AWS Cloud EKS.
  • Bump BanyanDB Java client a 0.3.0-rc1. *Eliminar la etiqueta id de las medidas.
  • Agregue Banyandb.MeasureField para marcar una columna como campo de medida de BanyanDB.
  • Agregue BanyanDB.StoreIDTag para almacenar la identificación de un proceso para realizar búsquedas.
  • [Cambio importante] La versión compatible de ShardingSphere-Proxy se actualiza de 5.1.2 a 5.3.1. Debido a los cambios del API de ShardingSphere, las versiones anteriores a 5.3.1 no son compatibles.
  • Agregue la prueba E2E de perfilado de red eBPF en el almacenamiento.
  • Arreglar las instancias del servicio TCP por la falta de propiedades de instancia como pod y namespace, lo que hace que el registro del Pod no funcione para cargas de trabajo TCP.
  • Agregue el ID del componente del módulo happybase Python HBase (94).
  • La alarma Fix gRPC no puede actualizar la configuración desde la fuente de configuración dinámica.
  • Agregue la configuración batchOfBytes para limitar el tamaño de la descarga masiva.
  • Agregue el ID del componente del módulo Websocket Python (7018).
  • [Opcional] Optimice el rendimiento de las consultas de seguimiento único personalizando el enrutamiento en ElasticSearch. Los segmentos de traza SkyWalking y los tramos Zipkin utilizan ID de traza para el enrutamiento. Esto está APAGADO de forma predeterminada, controlado por storage/elasticsearch/enableCustomRouting.
  • Mejorar el servidor HTTP OAP para admitir HTTPS
  • Eliminar el escaneo del controlador en el receptor del hotel, en su lugar inicialización manual
  • Agregue aws-firehose-receiver para admitir la recopilación de métricas de AWS CloudWatch (formato OpenTelemetry). Aviso, no hay configuración HTTPS/TLS apoyo. Al seguir la solicitud de AWS Firehose, utiliza solicitud de proxy (https://... en lugar de /aws/firehose/metrics), debe haber un proxy (Nginx, Envoy, etc.).
  • Evite que las versiones de las dependencias de Antlr puedan ser diferentes en el tiempo de compilación y en el tiempo de ejecución.
  • Ahora PrometheusMetricConverter#escapedName también admite la conversión de / a _.
  • Agregar métricas de rendimiento TCP faltantes.
  • Refactorizar la anotación @Column, intercambiar Column#name y ElasticSearch.Column#columnAlias y cambiar el nombre de ElasticSearch.Column#columnAlias a ElasticSearch.Column#legacyName.
  • Agregue el ID del componente del módulo HTTPX Python (7019).
  • Migrar pruebas de junit 4 a junit 5.
  • Refactorizar complementos de alarma basados en http y extraer lógica común a HttpAlarmCallback.
  • Admite monitoreo de métricas de Amazon Simple Storage Service (Amazon S3)
  • Proceso de soporte Suma de métricas con el caso AGGREGATION_TEMPORALITY_DELTA
  • Admite monitoreo de Amazon DynamoDB.
  • Admite prometheus HTTP API y promQL.
  • Scope en la Entidad de Métricas consulta el protocolo v1 no es necesario y se corrige automáticamente. El alcance se determina en función de la propia métrica.
  • Agregue ReadTimeout explícito para ConsulConfigurationWatcher para evitar IllegalArgumentException: Cache watchInterval=10sec >= networkClientReadTimeout=10000ms.
  • Se corrige el exceso de DurationUtils.getDurationPoints, cuando startTimeBucket es igual a endTimeBucket.
  • Proceso de soporte OpenTelemetry Métricas de histograma exponencial
  • Agregue el ID del componente FreeRedis (3018).
