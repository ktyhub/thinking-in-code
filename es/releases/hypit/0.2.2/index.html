hipit v0.2.2

Corrección del entorno multimedia de Windows y del almacén de credenciales

Esta versión incluye correcciones de ejecución de Windows y un cambio en la selección del directorio de credenciales. 0.2.2 rechaza los perfiles existentes con una ruta de almacenamiento de archivo o plataforma fuera de la raíz del estado del host; este es un cambio de comportamiento de 0.2.1. La nueva selección de Tienda inicial se aplica solo a los perfiles recién inicializados.

Ejecución de medios de Windows

ffmpeg y ffprobe se inician con una lista blanca de variables de entorno para que el entorno del Host se mantenga alejado de los medios secundarios. Esa lista blanca fue escrita para POSIX, por lo que los niños de Windows no recibieron ni %TEMP% ni %TMP% y no pudieron crear sus archivos temporales. Tanto la ruta de procesamiento de HyperFrames como la ruta de ejecución de medios compartidos ahora llevan una lista de Windows junto con la de POSIX. Los secretos del anfitrión todavía se mantienen ocultos. (#259, #260)

Almacenamiento de credenciales

  • runtime init escribe un perfil inicial que selecciona @hypit/credential-store-platform, por lo que el perfil que produce se abre y escribe en Linux, así como en macOS y Windows. macOS y Windows mantienen el casillero de la plataforma bajo el mismo servicio y clave, por lo que aún se encuentra una credencial existente. os, file y env siguen siendo seleccionables por nombre. (#247)
  • El config.path de un perfil para los almacenes de archivos y plataformas se resuelve con la raíz del estado del host y se verifica su contención. Una ruta que escapa de esa raíz se rechaza cuando se abre la Tienda. Anteriormente se aceptaba una ruta absoluta fuera de la raíz y ahora no. (#265)
  • Las lecturas y reposiciones de un documento credencial se suceden dentro de un proceso. resolve mantiene el documento abierto durante toda la lectura mientras que put lo reemplaza con un cambio de nombre, y la implementación de cambio de nombre de Windows de Node usa MoveFileExW, que puede rechazar el reemplazo mientras el destino está abierto. El ordenamiento local del proceso reduce esta superposición dentro de un proceso; no coordina procesos separados CLI y Worker. Las fallas de reemplazo entre procesos permanecen en 0.2.2. Las llaves permanecen independientes. (#276)
  • El asistente del Administrador de credenciales de Windows está limitado al mismo tiempo de espera de 10 segundos que la llamada security(1) de macOS, por lo que falla un casillero atascado en lugar de colgar el CLI. (#261)

Tiempo de ejecución y CLI

  • programs down trata un programa sin Hypit PID válido ni comando start como si no tuviera nada que detener, e informa No external programs to stop en lugar de salir 1. Los perfiles iniciales media.local y hyperframes.local declaran solo probe(), por lo que una sonda lista significa que la herramienta está instalada, no que se está ejecutando un proceso. Un programa iniciable que esté listo sin un PID Hypit todavía informa not-ours. (#272)
  • La ayuda general enumera programs prepare|up|status|down, y programs y runtime sin un perfil seleccionado informan la misma sentencia de recuperación que build, pricing, auth y los comandos de ejecución ya usan. (#266)
  • Tres paquetes declaran los paquetes del espacio de trabajo que importan sus fuentes. (#253)

Documentación

  • La sección de flujo de trabajo de compilación del inicio rápido en inglés incluye la preparación de dependencias, .gitignore, la biblioteca de recursos compartidos y el material de comando de archivo que su contraparte china ya tenía. (#275)
  • Los ejemplos auth status llevan el argumento de punto final requerido. (#254)

Actualización

npm install -g @hypit/hypit@0.2.2
hypit --version

Para una instalación local de proyecto:

npm install --save-exact @hypit/hypit@0.2.2
npm exec --no -- hypit --version

Los identificadores de formato interno y módulo lógico siguen siendo @1. La sintaxis del script no ha cambiado desde 0.2.0.
