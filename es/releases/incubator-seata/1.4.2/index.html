incubadora-seata v1.4.2

Lanzamiento del Seata 1.4.2.

Seata es una solución de transacciones distribuidas de código abierto, fácil de usar y de alto rendimiento.

La versión se actualiza de la siguiente manera:

característica:

  • [#2933] agregar antlr para sqlparser mysql
  • [#3228] admite complemento de serialización personalizado
  • [#3172] admite el modo de compresión undo_log en AT
  • [#3372] El soporte de Saga personaliza si se actualiza el último registro de reintento
  • [#3411] admite la configuración de parámetros del grupo de subprocesos del servidor seata
  • [#3348] admite el modo de almacenamiento centinela redis en TC
  • [#2667] admite el descifrado de contraseña cuando se utiliza el modo de almacenamiento db y redis
  • [#3427] agregar interfaz de bloqueo distribuido
  • [#3443] admite enviar el registro seata-server a logstash o kafka
  • [#3486] agregar grupo de servicios de transacciones para métrica
  • [#3317] soporte para obtener múltiples configuraciones a través de un solo nodo al usar zookeeper como centro de configuración
  • [#3516] admite token acl cuando se utiliza cónsul como centro de registro y configuración
  • [#3116] admite la configuración del servicio de configuración y el clúster de Apollo
  • [#3468] ejecución de bucle de soporte de saga en estado
  • [#3447] admite la impresión del contexto de transacciones en el marco de registro

corrección de errores:

  • [#3258] soluciona el posible problema de OOM de AsyncWorker

  • [#3293] corrige la caché de configuración y obtiene una excepción de discrepancia de tipo de valor

  • [#3241] uso prohibido orden por o límite en multi sql

  • [#3406] corrige el valor que no se puede enviar a nacos cuando hay un conjunto de caracteres especial en config.txt

  • [#3418] corrige getGeneratedKeys puede obtener el historial pk

  • [#3408] soluciona el problema NPE del modo de ejecución jar cuando la tercera dependencia está en un paquete separado

  • [#3431] Es posible que el bean de propiedad de corrección no se inicialice al leer la configuración

  • [#3413] corrige la lógica de revertir al punto de guardado y liberar al punto de guardado

  • [#3367] cuando la rama xa se revierte, no se puede ejecutar debido al estado inactivo

  • [#3448] reduce la competencia innecesaria y elimina los candados faltantes

  • La solución [#3451] establece la confirmación automática en verdadero cuando no se utilizan transacciones locales. Si no se compite por un bloqueo, la transacción global se cerrará, lo que invalidará el bloqueo de fila global y la escritura sucia de los datos.

  • [#3481] soluciona el error de actualización del nodo seata debido a que el cónsul client genera excepciones

  • [#3491] corrige error tipográfico en README.md

  • [#3531] corrige el NPE de RedisTransactionStoreManager al obtener transacciones de sucursal

  • [#3500] corrige Oracle y postgreSQL no puede consultar la información de la columna

  • [#3560] soluciona el problema de que la tarea asincrónica de las transacciones en el estado de confirmación no tiene umbral de tiempo y no puede recuperar la transacción

  • [#3555] no llama a setBlob para invalidar la excepción jdbc

  • [#3540] repara los archivos faltantes de distribución del servidor

  • [#3597] arregla el posible NPE

  • [#3568] soluciona el agente de origen de datos automático causado por el problema de interbloqueo de ConcurrentHashMap.computeIfAbsent

  • [#3402] soluciona el problema de que la columna actualizada no se puede resolver porque el nombre del campo en el SQL actualizado contiene el nombre de la base de datos.

  • [#3464] corrige el caso de prueba NPE y el registro de StackTraceLogger.
