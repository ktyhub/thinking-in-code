repomix v1.18.1

¡Esta versión de parche soluciona un problema de seguridad en el manejo de git del CLI, junto con el bloqueo de Windows .gitignore y un conjunto de correcciones de errores de los contribuyentes!

Solución de seguridad 🔒

La configuración de Git a nivel de repositorio ya no se ejecuta (GHSA-4p5g-gh74-q524)

Repomix ejecuta git log en el directorio de destino para ordenar archivos por frecuencia de cambio, y git diff/git log para --include-diffs/--include-logs. Git respeta la configuración del propio .git/config del repositorio que nombra un ejecutable, como gpg.program, diff.external, controladores textconv y core.fsmonitor. Por lo tanto, un directorio enviado con un .git diseñado (por ejemplo, dentro de un archivo zip) podría ejecutar comandos arbitrarios cuando se invocara Repomix dentro de él. Un git clone normal no lleva el .git/config del control remoto y el --remote elimina el .git del clon antes del procesamiento, por lo que esas rutas no se vieron afectadas.

Todos los comandos de git que Repomix ejecuta en un directorio de destino ahora desactivan estas configuraciones. La salida de un repositorio normal no se modifica.

Consulte el aviso de seguridad para obtener más detalles. ¡Gracias a @kinehoo77-debug por el informe! 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-4p5g-gh74-q524

Corrección de errores 🐛

Fallo de Windows en .gitignore con barras de escape invertidas (#1765, #1775)

En Windows, el empaquetado falló con path should be a `path.relative()`d string when a .gitignore mezclando una regla con barra invertida con escape y una regla de negación. El error estaba en globby y se solucionó en globby 16.2.3, que se recoge en esta versión. ¡Gracias a @iki por el informe y por seguir adelante! 🙏

--remove-comments ya no daña los archivos Shell y YAML (#1752)

Los archivos Shell y YAML fueron eliminados del perfil Perl, que trata cada # sin comillas como un comentario. En estos idiomas, # solo inicia un comentario al principio de una línea o después de un espacio en blanco, por lo que se cortaban construcciones como ${name##*/}, $# y fragmentos de URL. Shell y YAML ahora usan un controlador dedicado que respeta esta regla, heredocs y bloques escalares. ¡Gracias @serhiizghama!

--include-full-directory-structure mantiene archivos no incluidos (#1749)

Cuando se combina con --include, la sección Estructura del directorio está destinada a mostrar todo el árbol del repositorio mientras empaqueta solo el contenido de los archivos incluidos. Los archivos no incluidos se estaban eliminando del árbol. ¡Gracias @serhiizghama!

La salida dividida muestra el árbol de directorios propio de cada parte (#1815, #1822)

Con --split-output, cada parte enumeraba el árbol de directorios de la salida completa en lugar de los archivos de esa parte. Cada parte ahora representa solo sus propios archivos. ¡Gracias @Elioooon!

URL remotas cuyo nombre de repositorio comienza con un punto (#1772)

https://github.com/microsoft/.github y repositorios de perfiles de organizaciones similares fueron rechazados por no ser válidos. ¡Gracias @serhiizghama!

Parámetros de URI de datos conservados al truncar Base64 (#1819, #1820)

El truncamiento de cargas útiles largas en base64 mantuvo solo el último ;param antes de ;base64,, eliminando los demás. ¡Gracias @cyphercodes!

Pequeñas correcciones de CLI (#1808, #1809, #1810)

  • Los tamaños --split-output que se redondean a cero bytes (como 0.5b) ahora se rechazan en lugar de repetirse para siempre.
  • Las rutas de salida y de habilidades se clasifican según los límites del directorio real, por lo que un directorio hermano con un prefijo coincidente ya no se trata como si estuviera dentro de la base.
  • Los nombres de las habilidades remotas se derivan del propietario y del repositorio de las URL de GitHub.

¡Gracias @Whxuan0701!

Cómo actualizar

npm update -g repomix
