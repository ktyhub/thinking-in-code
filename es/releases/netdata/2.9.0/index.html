Qué puedes hacer:

  • Identificar acaparadores de recursos: ordenar por tiempo total de ejecución, tiempo de CPU o E/S
  • Detectar consultas frecuentes: encuentre consultas con un alto número de llamadas que puedan beneficiarse del almacenamiento en caché
  • Depuración en tiempo real: vea las consultas actualmente en ejecución y qué client las inició.
  • No se necesitan herramientas adicionales: todos los análisis se realizan en la pestaña Superior del panel de Netdata

[!IMPORTANTE] Algunas funciones requieren una configuración específica de la base de datos (por ejemplo, habilitar Query Store, pg_stat_statements o profiling).

Consulte la documentación de cada recopilador para conocer los requisitos previos.

Recopilador de Microsoft SQL Server (Ir) <a id="v290-highlight-mssql-go"></a>

Hemos reconstruido el recopilador de Microsoft SQL Server desde cero en Go, reemplazando la implementación C heredada. Esto brinda monitoreo integral de SQL Server con capacidades de análisis de consultas en tiempo real.

Lo que obtienes:

| Característica | Detalles | |-------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------| | Cobertura métrica completa | Conexiones, solicitudes por lotes, administrador de búfer, memoria, estadísticas de espera, bloqueos, transacciones por base de datos, latencia de E/S, tamaños de archivos y estado del trabajo del Agente SQL | | Función de consultas principales | Vista en tiempo real de sus consultas que consumen más recursos directamente en el panel: vea el tiempo de ejecución, CPU, E/S, concesiones de memoria y métricas de paralelismo | | Configuración de interfaz de usuario | Cree y administre trabajos de monitoreo a través del panel de Netdata: no se requiere edición manual del archivo de configuración | | Monitoreo de replicación | Seguimiento del estado de replicación, latencia y advertencias para publicaciones transaccionales/fusionadas | | Autenticación flexible | Autenticación SQL, autenticación integrada de Windows, instancias con nombre y servidores remotos |

Consultas principales: identificar cuellos de botella en el rendimiento

La nueva función Consultas principales extrae datos del almacén de consultas de SQL Server para mostrar:

  • Consultas que consumen la mayor cantidad de tiempo total de ejecución o CPU.
  • Patrones de E/S (lecturas lógicas, lecturas físicas, escrituras)
  • Concesiones de memoria y uso de tempdb
  • Paralelismo (DOP) entre ejecuciones

[!IMPORTANTE] Requiere Almacén de consultas habilitado en bases de datos monitoreadas (SQL Server 2016+).

El texto de la consulta puede contener datos confidenciales: garantice controles de acceso adecuados al panel.

OpenTelemetry Ingestión de registros <a id="v290-highlight-otel-logs-ingestion"></a>

¡Estamos ampliando nuestro soporte para OpenTelemetry! Siguiendo el soporte de métricas agregado en v2.7.0, el complemento otel ahora ingiere registros OpenTelemetry a través del mismo punto final OTLP gRPC.

Qué hay de nuevo

  • Ingestión de registros: envíe registros desde su recopilador OpenTelemetry o aplicaciones instrumentadas directamente a Netdata.
  • Almacenamiento personalizado: los registros se almacenan en archivos de diario compatibles con systemd\ mediante una implementación Rust (no se requiere dependencia de libsystemd).
  • Interfaz unificada: vea los registros de OpenTelemetry junto con los registros del sistema en la pestaña Registros con capacidades completas de búsqueda y filtrado.

Configuración y retención

Controle su almacenamiento de registros con políticas de retención configurables:

  • Establecer límites por uso del disco, recuento de archivos o antigüedad
  • Definir ubicaciones de almacenamiento personalizadas
  • Ajustar el tamaño del archivo y la configuración del intervalo de tiempo

Disponibilidad

Disponible en agentes de Linux (beta), y pronto habrá soporte para plataformas adicionales.

[!NOTA]
Esta característica está en versión beta. ¡Agradecemos sus comentarios!

Aviso de obsolescencia <a id="v290-deprecation-notice"></a>

Cambiado en esta versión

Cambios importantes en la próxima versión menor

MS SQL Server Collector: eliminación de la versión C

El recopilador heredado de MS SQL Server basado en C (parte de windows.plugin) se eliminará en la próxima versión menor. El recopilador basado en Go (go.d/mssql) es ahora la opción predeterminada y recomendada.

La versión Go ofrece importantes ventajas:

  • Más funciones: incluye la nueva función Consultas principales para el análisis de consultas en tiempo real.
  • Soporte para múltiples trabajos: monitoree múltiples instancias de SQL Server desde un solo agente.
  • Conexiones remotas: conéctese a instancias de SQL Server a través de la red, no solo al host local.
  • Configuración de UI: cree y administre trabajos de monitoreo directamente desde el panel de Netdata.
  • Mantenimiento más sencillo: se beneficia de la infraestructura compartida del marco go.d y de ciclos de desarrollo más rápidos. Si actualmente utiliza el recopilador de C, consulte el recopilador de Go [documentación de configuración] (https://learn.netdata.cloud/docs/collecting-metrics/databases/microsoft-sql-server#setup) para obtener instrucciones de configuración.

Cambios importantes en la próxima versión importante

Componentes obsoletos

| Tipo de componente | Versiones en desuso | |----------------|---------------------------| | API | v1, v2 |

Qué significa esto

A partir de la próxima versión principal, solo se admitirán la versión 3 API y la versión 3 Dashboard. Estas versiones más nuevas ofrecen rendimiento mejorado, funciones mejoradas y mayor seguridad.

Opciones de soporte <a id="v290-support-options"></a>

A medida que crecemos, mantenemos nuestro compromiso de brindar el mejor soporte jamás visto en una solución de código abierto. Si encuentra algún problema con cualquiera de los cambios realizados en esta versión o cualquier función del Agente Netdata, no dude en contactarnos a través de uno de los siguientes canales:

  • Soporte Premium: Los clientes que deseen tener un canal directo con Netdata y soporte priorizado con SLA definidos pueden contactarnos.
  • Netdata Learn: encuentre documentación, guías y material de referencia para monitorear y solucionar problemas de sus sistemas con Netdata.
  • Problemas GitHub: utilice el repositorio de Netdata para informar errores o abrir una solicitud de nueva función.
  • Discusiones sobre GitHub: Únase a la conversación sobre el proceso de desarrollo de Netdata y sea parte de él.
  • Foros de la comunidad: visite los foros de la comunidad y contribuya a la base de conocimientos colaborativos.
  • Servidor de Discord: acceda a Netdata Discord y interactúe con administradores de sistemas, DevOps, SRE y otros solucionadores de problemas con ideas afines. ¡Más de 2000 ingenieros ya lo están utilizando!
