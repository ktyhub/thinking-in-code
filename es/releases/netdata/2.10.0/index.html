Aspectos destacados de la versión <a id="v2100-release-highlights"></a>

Gestión de secretos <a id="v2100-highlight-secrets-management"></a>

Mantenga las credenciales del recopilador fuera de los archivos de configuración de texto sin formato. Netdata ahora le permite hacer referencia a secretos en configuraciones de recopiladores en lugar de almacenarlos directamente. Las contraseñas, tokens y claves API se resuelven en tiempo de ejecución desde la fuente que elija.

Resolutores

Netdata proporciona cuatro tipos de resolución, desde simples hasta de nivel empresarial:

| solucionador | Sintaxis | Mejor para | |:---------------------------------|:----------------------------------|:----------------------------------------------------------------------------------------------| | Variable de entorno | ${env:VAR_NAME} | Secretos ya inyectados en el entorno del servicio Netdata | | Archivo | ${file:/absolute/path} | Secretos almacenados en archivos locales en el disco (Secretos Docker, Secretos Kubernetes montados como volúmenes) | | Comando | ${cmd:/absolute/path args} | Secretos devueltos por un comando local trusted (por ejemplo, 1Password CLI, scripts personalizados) | | Tienda secreta | ${store:<kind>:<name>:<operand>} | Secretos gestionados de forma centralizada en proveedores de nube o Vault |

Backends compatibles con Secretstore

Para las organizaciones que gestionan secretos de forma centralizada, Netdata se integra con cuatro backends de secretstore:

| Servidor | Amable | Formato de operando | Modos de autenticación | |:------------------------------------------------------------------------------------------------------------------------------|:-----------|:------------------------------------|:--------------------------------------------------------------| | Administrador de secretos de AWS | aws-sm | secret-name[#key] | Credenciales de entorno, rol de tarea de ECS, perfil de instancia EC2 | | Bóveda de claves de Azure | azure-kv | vault-name/secret-name | Entidad de servicio, Identidad administrada, Cadena de credenciales predeterminada | | Administrador secreto de Google | gcp-sm | project/secret[/version] | Servidor de metadatos, archivo de cuenta de servicio | | Bóveda de HashiCorp | vault | path#key | Ficha, archivo de ficha |

Configure los almacenes secretos a través de la UI de configuración dinámica de Netdata (Collectors → go.d → SecretStores) o mediante archivos de configuración en /etc/netdata/go.d/ss/.

Ejemplo

Un recopilador MySQL que hace referencia a su contraseña de HashiCorp Vault:

# /etc/netdata/go.d/mysql.conf
jobs:
  - name: mysql_prod
    dsn: "netdata:${store:vault:vault_prod:secret/data/netdata/mysql#password}@tcp(127.0.0.1:3306)/"

Puede mezclar tipos de resolución libremente. Por ejemplo, lea el nombre de usuario de una variable de entorno y la contraseña de un almacén secreto en el mismo valor de configuración:

jobs:
  - name: mysql_prod
    dsn: "${env:MYSQL_USER}:${store:vault:vault_prod:secret/data/netdata/mysql#password}@tcp(127.0.0.1:3306)/"

Cómo funciona

  • Los secretos se resuelven cada vez que se inicia o reinicia un trabajo de recopilador.
  • La actualización de un almacén secreto reinicia automáticamente los trabajos de recopilación que lo utilizan para obtener nuevas credenciales.
  • Los valores de configuración de Secretstore también admiten los solucionadores ${env:...}, ${file:...} y ${cmd:...}, por lo que tampoco es necesario almacenar las credenciales de backend en texto sin formato.

[!CONSEJO] Para obtener una configuración detallada, guías de autenticación específicas de backend y solución de problemas, consulte la [Documentación de administración de secretos] (https://learn.netdata.cloud/docs/collecting-metrics/secrets-management).

Recopilador de complementos de Nagios <a id="v2100-highlight-nagios-plugins"></a>

Ejecute [complementos compatibles con Nagios] (https://www.nagios-plugins.org/) y scripts personalizados directamente dentro de Netdata con el nuevo [recolector de complementos de Nagios] (https://learn.netdata.cloud/docs/collecting-metrics/collectors/synthetic-testing/nagios-plugins). Cualquier ejecutable que siga el [formato de salida del complemento de Nagios] (https://nagios-plugins.org/doc/guidelines.html) funciona de inmediato: complementos de Nagios empaquetados, scripts de shell personalizados o archivos binarios compilados.

Lo que obtienes

| Característica | Detalles | |:----------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------| | Verificar monitoreo de estado | Realiza un seguimiento de los estados OK, ADVERTENCIA, CRÍTICO y DESCONOCIDO del código de salida del proceso | | Gráficos automáticos de datos de rendimiento | Los valores de los datos de rendimiento de Nagios se analizan y grafican automáticamente | | Alertas basadas en umbrales | Cuando perfdata incluye umbrales de advertencia/críticos, Netdata deriva un gráfico de estado de umbral (correcto/advertencia/crítico) y crea alertas integradas | | Métricas de ejecución | Mide la duración de la ejecución, el tiempo de CPU y el uso de memoria de cada comprobación | | Programación estilo Nagios | Intervalos de verificación configurables, intervalos de reintento, intentos máximos de verificación y períodos de tiempo | | Lógica de estado blando/duro | Los resultados no correctos se reintentan en retry_interval hasta max_check_attempts antes de activar alertas, evitando falsas alarmas por fallas transitorias |

Alertas integradas

El coleccionista se envía con cuatro alertas de stock:

| Alerta | Desencadenantes cuando | |:----------------------------------------------------|:-------------------------------------------------| | nagios_job_execution_state_warn | Un cheque está en estado ADVERTENCIA duro | | nagios_job_execution_state_crit | Un cheque está en estado CRÍTICO | | nagios_job_perfdata_threshold_state_warn | Una métrica de perfdata supera su umbral de advertencia | | nagios_job_perfdata_threshold_state_crit | Una métrica de perfdata supera su umbral crítico |

Todas las alertas de stock suprimen los estados de reintento suave. Las alertas se activan solo después de los fallos consecutivos configurados en max_check_attempts.

Ejemplo

# /usr/local/lib/netdata/checks/check_api.sh
#!/bin/sh
resp=$(curl -s -o /dev/null -w "%{http_code} %{time_total}" --max-time 5 "$1" 2>/dev/null)
code=$(echo "$resp" | cut -d' ' -f1)
time=$(echo "$resp" | cut -d' ' -f2)

[ "$code" -ge 500 ] && echo "CRITICAL - HTTP $code | response_time=${time}s;~:2;~:5" && exit 2
[ "$code" -ne 200 ] && echo "WARNING - HTTP $code | response_time=${time}s;~:2;~:5" && exit 1
echo "OK - HTTP $code | response_time=${time}s;~:2;~:5"
exit 0

# /etc/netdata/scripts.d/nagios.conf
jobs:
  - name: api_health
    plugin: /bin/sh
    args: ["/usr/local/lib/netdata/checks/check_api.sh", "http://localhost:8080/health"]
    check_interval: 1m
    retry_interval: 15s
    max_check_attempts: 3

Esto produce gráficos de estado de verificación, métricas de ejecución y, debido a que el script emite datos de rendimiento con umbrales (response_time con advertencia >2 s/crit >5 s), un gráfico de tiempo de respuesta automático con un gráfico de estado de umbral y alertas integradas.

[!CONSEJO] Para obtener la guía de configuración completa, el tutorial de scripts personalizados y la configuración del período de tiempo, consulte la [documentación del recopilador de complementos de Nagios] (https://learn.netdata.cloud/docs/collecting-metrics/collectors/synthetic-testing/nagios-plugins).

Recopilador de Azure Monitor <a id="v2100-highlight-azure-monitor"></a>

Supervise toda su infraestructura de Azure desde Netdata con el nuevo [recolector de Azure Monitor] (https://learn.netdata.cloud/docs/collecting-metrics/collectors/cloud-and-devops/azure-monitor). Recopila métricas de plataforma de Azure Monitor Metrics API con descubrimiento automático de recursos: apúntelo a sus suscripciones, encuentra sus recursos, los compara con perfiles integrados (conjuntos de métricas preconfigurados) y comienza a recopilar métricas.

[!IMPORTANTE] Esta es una función alfa. El formato de configuración puede cambiar en próximas versiones.

Lo que obtienes

| Característica | Detalles | |:---------------------------------|:-----------------------------------------------------------------------------------------------------------| | 38 perfiles de servicio integrados | Más de 1300 métricas en computación, bases de datos, redes, almacenamiento, IA/ML, análisis, contenedores y más | | Descubrimiento automático | Descubre recursos a través de Azure Resource Graph y habilita perfiles coincidentes sin configuración por recurso | | Suscripción múltiple | Supervisar recursos en varias suscripciones de Azure en un único trabajo de recopilador | | Alcance de descubrimiento flexible | Limite la detección por grupos de recursos, regiones o etiquetas, o use una consulta KQL personalizada de Azure Resource Graph | | Alertas integradas | Alertas preconfiguradas para condiciones críticas de recursos de Azure | | Configuración de interfaz de usuario | Configure a través de la interfaz de usuario de configuración dinámica de Netdata sin editar archivos |

Servicios compatibles

| Categoría | Servicios a través de Perfiles | |:------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| | Calcular | Máquina virtual, Conjunto de escalado de máquinas virtuales, Servicio de aplicaciones (incluidas funciones), Aplicaciones de contenedor, Instancias de contenedor | | Kubernetes | AKS | | Bases de datos | Base de datos SQL, Grupo elástico SQL, Instancia administrada SQL, MySQL flexible, PostgreSQL flexible, Cosmos DB, Caché para Redis | | Redes | Balanceador de carga, Puerta de enlace de aplicaciones, Puerta principal, Firewall, Puerta de enlace NAT, Puerta de enlace VPN, Circuito ExpressRoute, Puerta de enlace ExpressRoute | | Almacenamiento y análisis | Cuenta de almacenamiento, Explorador de datos, Fábrica de datos, Stream Analytics, Synapse Analytics, Log Analytics | | Mensajería | Centros de eventos, Bus de servicio, Event Grid, IoT Hub | | IA y aprendizaje automático | Servicios cognitivos, Aprendizaje automático, Application Insights | | Integración | Administración de API, Aplicaciones lógicas, Bóveda de claves, Registro de contenedor |

[!CONSEJO] Para obtener instrucciones de configuración detalladas, opciones de autenticación, perfiles personalizados y ajustes, consulte la [guía de configuración del recopilador de Azure Monitor] (https://learn.netdata.cloud/docs/collecting-metrics/collectors/cloud-and-devops/azure-monitor#setup).

Opciones de soporte <a id="v2100-support-options"></a>

A medida que crecemos, mantenemos nuestro compromiso de brindar el mejor soporte jamás visto en una solución de código abierto. Si encuentra algún problema con cualquiera de los cambios realizados en esta versión o cualquier función del Agente Netdata, no dude en contactarnos a través de uno de los siguientes canales:

  • Soporte Premium: Los clientes que deseen tener un canal directo con Netdata y soporte priorizado con SLA definidos pueden contactarnos.
  • Netdata Learn: encuentre documentación, guías y material de referencia para monitorear y solucionar problemas de sus sistemas con Netdata.
  • Problemas GitHub: utilice el repositorio de Netdata para informar errores o abrir una solicitud de nueva función.
  • Discusiones sobre GitHub: Únase a la conversación sobre el proceso de desarrollo de Netdata y sea parte de él.
  • Foros de la comunidad: visite los foros de la comunidad y contribuya a la base de conocimientos colaborativos.
  • Servidor de Discord: acceda a Netdata Discord y interactúe con administradores de sistemas, DevOps, SRE y otros solucionadores de problemas con ideas afines. ¡Más de 2000 ingenieros ya lo están utilizando!
