mlflow v3.18.0

MLflow 3.18.0 lo ayuda a reutilizar la experiencia de los agentes, encontrar regresiones antes del envío y monitorear la calidad en la producción.

Nuevas características importantes

  • Detección automática de problemas: convierta las fallas recurrentes del agente en problemas que pueda investigar y solucionar. La pestaña dedicada a Problemas agrupa problemas relacionados y vincula los hallazgos para rastrear evidencia; Programe la detección para seguir comprobando el tráfico nuevo. (#27193, #26751, #26754, #26791, #26919, #26955, #26961, #26967, #27009, #27002, #27003, #27006, #27137, #27181, #27249, @tanghaoji; #27070, @B-Step62)
  • Registro de habilidades: comparta la experiencia de su equipo entre agentes y proyectos con un catálogo central de habilidades reutilizables. Descubra las habilidades existentes y elija la versión o alias a utilizar en cada agente. Experimental. (#26736, @mprahl; #26900, @bardenr; #27088, @Rohitkanithi)
  • Evaluación renovada y comparaciones de seguimiento para encontrar regresiones: encuentre las regresiones ocultas detrás de las puntuaciones agregadas antes de enviar una actualización del agente. La interfaz de usuario de comparación rediseñada lo lleva desde los cambios de puntaje hasta las entradas, las conversaciones y los pasos de seguimiento detrás de ellos. Un Python API experimental agrega comparaciones estadísticas para ayudar a distinguir las mejoras del ruido. (#26991, #26733, #26739, #26740, #26770, #26771, #26782, #26783, #26784, #26927, #26799, #26803, #26808, #26868, #26880, #26889, #26896, #27011, #27014, #27015, @joshuawong-db; #27332, @filip-urbanski #26396, @AbdulAliMamnun)
  • Evaluación en línea: detecte regresiones de calidad de producción con comprobaciones personalizadas basadas en códigos que evalúan automáticamente nuevos seguimientos y conversaciones de varios turnos a medida que llegan. La evaluación en línea basada en código es experimental y requiere un servidor autohospedado configurado con contenedores de trabajos. (#26689, #26430, #26684, #26685, #26687, @kriscon-db)

Cambios importantes

  • [Seguimiento] Filtrar y ordenar las métricas search_logged_models por el paso más alto, luego por la última marca de tiempo, en las tiendas SQL; aplicar datasets tanto para filtrar como para ordenar (#27215, @agtzrubio)
  • [Registro de modelo] Deje de agregar registered_model_meta a las descargas de models:/; los lectores personalizados deben usar el URI o el Registro de modelos (#27173, @sunilmehta-si)
  • [Seguimiento] Hacer que la identidad de la versión del servidor MCP distinga entre mayúsculas y minúsculas en MySQL y SQL Server; corregir las referencias que no coinciden entre mayúsculas y minúsculas antes de actualizar (#25920, @LobsterQBA)

Actualización de la base de datos: Realice una copia de seguridad del backend de SQL y planifique una ventana de mantenimiento. Detenga los servidores MLflow y otros escritores, ejecute mlflow db upgrade <database-url> con MLflow 3.18.0 y reinicie en la nueva versión. La migración de la versión MCP comprueba las referencias de MySQL y SQL Server para detectar coincidencias de casos exactos y se detiene antes de que su propio esquema cambie si se requiere corrección. En bases de datos que no distinguen entre mayúsculas y minúsculas, los permisos de registro y MCP ahora utilizan nombres de recursos almacenados. Vuelva a guardar las concesiones en mayúsculas y minúsculas diferentes según la ortografía almacenada. Siga la guía de actualización de la base de datos.
