shardingsphere 5.3.2

Parche Publicado30 mar 2023 Fuenteapache/shardingsphere original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

fragmentación de esfera 5.3.2

API Cambios

  1. Proxy: agregue la propiedad system-log-level, admita el cambio dinámico del nivel de registro mediante DistSQL.
  2. DistSQL: elimine DistSQL relacionado con Hint; los usuarios pueden usar SQL Hint en su lugar

Nuevas funciones

  1. Escalado: admite cualquier tipo de tabla de claves únicas de columna

Mejoras

  1. Escalado: utilice consultas de flujo para volcar el inventario y verificar la coherencia de los datos
  2. Escalado: compatible con el tipo de columna VARBINARY en el análisis binlog MySQL
  3. Escalado: Refactorizar AbstractSimplePipelineJob.execute para bloquear
  4. Escalado: mejorar el cálculo del recuento de registros de la tabla
  5. Escalado: no se admite la regla de fragmentación de proxy para el trabajo de migración
  6. Escalado: agregue useServerPrepStmts=false para el trabajo de canalización en MySQL
  7. Escalado: mejorar el análisis de fecha y hora para el binlog MySQL
  8. Escalado: agregar estado global para la etapa de preparación
  9. Escalado: agregue netTimeoutForStreamingResults para el trabajo de canalización en MySQL
  10. Autoridad: admite la especificación del método de autenticación de contraseña
  11. Autoridad: agregue soporte de autenticación md5 para el protocolo openGauss
  12. Agente: agregue más métricas para JDBC
  13. Kernel: la configuración del controlador ShardingSphere es compatible con Apollo
  14. Kernel: ajuste la sugerencia SKIP_ENCRYPT_REWRITE SQL a SKIP_SQL_REWRITE para admitir más escenarios
  15. Núcleo: compatible con openGauss EXPLAIN PERFORMANCE
  16. Cifrar: Like admite la función concat

Corrección de errores

  1. Escalado: corrige caracteres Unicode y decodificación de caracteres especiales para la tarea incremental PostgreSQL
  2. Escalado: Reparar la migración no es compatible con el tipo PostgreSQL json
  3. DistSQL: CREATE SHARDING TABLE RULE admite la estrategia NONE
  4. Kernel: corrige el error de uso de la base de datos del sistema cuando las fuentes de datos están vacías
  5. Kernel: La reparación del conjunto de ID de trabajador no tiene efecto en el modo independiente
  6. Kernel: borre la información del nodo de almacenamiento al eliminar las reglas de descubrimiento de base de datos y división de lectura y escritura
  7. Kernel: solucione el problema anormal del índice de columna fuera de rango en una consulta compleja de una sola tabla
  8. Kernel: corrige PostgreSQL como si fallaran las minúsculas.
  9. Kernel: se corrigió la excepción de la recopilación de datos de la metabase integrada cuando los tipos de base de datos frontal y posterior eran inconsistentes
  10. Kernel: soluciona el problema de enrutar informes de errores bajo ciertos nombres de tablas
  11. Kernel: corrige el error de análisis del procedimiento de creación MySQL
  12. Kernel: Se corrigió el nombre de la tabla de extractos de unión NPE
  13. Kernel: corrige el error de restricción de tabla en mayúsculas y no reescribe
  14. Kernel: La solución no pudo analizar PostgreSQL/openGauss SQL contiene el tipo de dinero
  15. Kernel: Corrige la regla del parámetro posicional PostgreSQL/openGauss
  16. Kernel: Se corrigió PostgreSQL / openGauss no pudo analizar const con tipo de conversión
  17. Kernel: se corrige la excepción de codificación de caracteres chinos al ejecutar la selección con el motor de federación SQL
  18. Kernel: corrige IndexOutOfBoundsException cuando se ejecuta la instrucción set variable en el adaptador jdbc
  19. Kernel: Corregir el índice no existe excepción cuando se ejecuta la declaración de caída del índice
  20. Proxy: Manejar adecuadamente el inicio de sesión numérico en el protocolo binario MySQL Proxy
  21. Proxy: Fix PostgreSQL Proxy no pudo manejar el tipo de datos bytea
  22. Proxy: Fix PostgreSQL Proxy no pudo analizar el valor de tiempo en microsegundos
  23. Proxy: corrige el códec del protocolo PostgreSQL para el tipo de fecha en formato binario
  24. Proxy: Arreglar posible CCE PostgreSQLInt2BinaryProtocolValue
  25. Proxy: corrige un posible error cuando client pasa el conjunto de caracteres entre comillas a PostgreSQL/openGauss Proxy

  1. HITO
