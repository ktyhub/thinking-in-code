Corrección de errores

  1. Solucionar el error de actualización de metadatos de una sola tabla causado por el filtrado DataSourceContainedRule
  2. Se corrigió la excepción de análisis causada por el valor nulo del tipo de blob MySQL.
  3. Solucione el error de análisis de la declaración de reinicio de PostgreSQL/openGauss
  4. Corrija la reescritura de parámetros incorrectos cuando se usa fragmentación y cifrado
  5. Solucione la conversión fallida de clases relacionadas con el mes en IntervalShardingAlgorithm
  6. Se corrige NullPointerException cuando la ejecución de la declaración de unión selecta contiene una subconsulta
  7. Corrija el resultado incorrecto de reescritura de cifrado debido al orden incorrecto de los metadatos
  8. Solucione el error de análisis de la función de recorte MySQL
  9. Corrija los valores de inserción de MySQL con el error de análisis binario
  10. El error de sintaxis de MySQL no se puede enviar a client
  11. Evite el bloqueo de EventLoop debido al cierre de recursos JDBC
  12. Corregir los indicadores de estado del servidor devueltos por el proxy MySQL
  13. Solucione un posible problema de fuga de conexión si el Proxy client se desconectaba en la transacción
  14. Se solucionó un posible problema de coherencia con la declaración que se ejecuta cuando el Proxy client está desconectado.
  15. Evite que la conexión agrupada se contamine al ejecutar declaraciones SET 1.Hacer que MOSTRAR TABLAS DE funcione en ShardingSphere-Proxy
  16. La solución PostgreSQL DDL no se pudo ejecutar mediante consulta extendida
  17. La solución MOSTRAR VARIABLES no se pudo ejecutar en el proxy PostgreSQL sin recursos
  18. Corrija FileNotFoundException cuando use el controlador ShardingSphere con SpringBoot fatjar
  19. Escalado: solucione el problema de que la tabla contiene tanto la clave principal como el índice único en la migración del inventario.
  20. Escalado: mejore la migración incremental, admita la última posición en medio del evento de inserción por lotes
  21. Escalado: corrija el error causado por el valor del campo nulo en la migración incremental de openGauss
  22. DistSQL: corrige el nombre de estrategia incorrecto como resultado de SHOW SHARDING TABLE RULES
  23. DistSQL: la configuración de la regla actual se modifica por adelantado cuando ALTER SHARDING TABLE RULE
  24. DistSQL: soluciona la fuga de conexión cuando ALTER RESOURCE
  25. DistSQL: la solución CREATE TRAFFIC RULE falló cuando el algoritmo de equilibrio de carga es nulo
  26. Se corrigió que la tarea de monitoreo de latidos no se detuviera cuando se descubrió la base de datos y se eliminó la biblioteca lógica.
  27. Arreglar el modo de clúster ShardingSphere-JDBC carga toda la base de datos lógica
  28. La identificación del trabajador generada por SnowflakeKeyGenerateAlgorithm en modo clúster puede exceder el valor máximo.
  29. Se corrigió DistSQL agregando una excepción de algoritmo de sombra sin fuente de datos de sombra
  30. Solucione la confusión de fuentes de datos entre bases de datos causada por el mismo nombre de fuente de datos en múltiples bases de datos lógicas.
  31. Solucionar el error de ejecución de RUL DistSQL en la transacción
  32. Se corrigió el inicio de PostgreSQL y openGauss.
  33. Agente: se corrigió el error de valor nulo en contextManager al recopilar datos de métricas

API Cambios

  1. Eliminar la función de transferencia de SQL a la fuente de datos
  2. Agregue un nuevo AssistedQueryEncryptorName y elimine la interfaz QueryAssistedEncryptAlgorithm.
  3. Refactorice la división de lectura y escritura api para mejorar la experiencia del usuario
  4. Eliminar la configuración habilitada para verificar tablas duplicadas
  5. Eliminar el elemento de configuración inútil show-process-list-enabled
  6. Escalado: cambiar la palabra clave para parte de la migración de datos DistSQL
  7. Escalado: rediseño de parte de la migración de datos DistSQL
  8. DistSQL: unificar la especificación del tipo de parámetro
  9. DistSQL: dividir SHOW INSTANCE MODE en SHOW MODE INFO y SHOW INSTANCE INFO
  10. DistSQL: cambie DROP SCALING jobId a CLEAN MIGRATION jobId
  11. DistSQL: Eliminar COUNT INSTANCE RULES
  12. Al agregar la base de datos se encontró que la alta disponibilidad permite que todas las bibliotecas esclavas se desconecten y la biblioteca principal realiza la configuración del tráfico de lectura.
  13. SnowflakeKeyGenerateAlgorithm admite la configuración de ID de trabajador en modo independiente
  14. Reemplace sourceDataSourceName con productionDataSourceName en la configuración Shadow API
  15. Autoridad: eliminar el proveedor de autoridad nativo obsoleto

Refactorizar

  1. Refactorización de metadatos de ShardingSphere para dividir metadatos reales y metadatos lógicos
  2. Utilice ConnectionContext, QueryContext para eliminar ThreadLocal en FetchOrderByValueQueuesHolder, TrafficContextHolder, SQLStatementDatabaseHolder y TransactionHolder
  3. Modifique el valor predeterminado de la versión ShardingSphere-Proxy en el gráfico de timón.
  4. El contenedor Docker se cerrará si ShardingSphere-Proxy no se inicia
  5. Los gráficos de timón en el repositorio de ShardingSphere se transfieren al subproyecto shardingsphere-on-cloud
  6. Escalado: mucha refactorización para una mejor reutilización del código
  7. DistSQL: agregue una nueva categoría llamada RUL
  8. Refactorice el módulo de programación y divídalo en programación de clúster y programación independiente.
  9. Elimine el modo de memoria, mantenga el modo independiente y el modo de clúster
  10. Refactorización de la lógica de carga y la lógica de persistencia de la tabla de metadatos
  11. Refactorización de bloqueos distribuidos para conservar el diseño de interfaz más conciso
  12. Refactor: unifique la creación de contenedores proxy en TI a partir de módulos ENV
  13. Refactor: unificar la configuración del contenedor creado por testcontainer
