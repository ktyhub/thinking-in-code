#LightRAG v1.4.9.9

Release Note V1.4.9.9

Notas importantes

  • Agregar aislamiento de espacio de trabajo para estado de canalización y almacenamiento en memoria: se pueden crear simultáneamente múltiples instancias de LightRAG con distintos espacios de trabajo, lo que marca un avance significativo hacia la conmutación perfecta de espacios de trabajo dentro de un único servidor LightRAG.
  • Agregar aislamiento de datos vectoriales del espacio de trabajo por nombre de modelo y dimensión para PostgreSQL y Qdrant: anteriormente, LightRAG usaba una única colección/tabla para el modelo y la dimensión de incrustación de diferencias, lo que provocaba fallas de coincidencia de dimensiones o contaminación de datos en espacios de trabajo múltiples.
  • La selección de dimensiones es compatible con OpenAI y Gemini Modelo de incrustación con nueva var env introducida: EMBEDDING_SEND_DIM
  • Agregue herramientas de migración de caché de LLM y limpieza de caché de consultas de LLM entre diferentes almacenamientos KV: permite a los usuarios cambiar de backend de almacenamiento sin perder datos de resumen y extracción en caché.
  • Mejorado Mejorado Extracción DOCX con soporte de contenido de tabla.
  • Extracción XLSX mejorada con manejo adecuado de caracteres tab y newline dentro de las celdas.
  • Solucionar vulnerabilidad crítica de seguridad en los componentes del servidor React: #2494
  • Agregar compatibilidad con truncamiento automático de texto para funciones de incrustación: la función de incrustación de OpenAI ahora respeta el valor max_token_size en EmbeddingFunc y trunca automáticamente el texto de entrada para evitar errores API causados por textos que exceden los límites de token del modelo.

Qué está pasando (solo para la integración de LightRAG Core)

  • Cambiar el nombre de los parámetros de la función de fragmentación: si incorpora la función de fragmentación en LightRAG y pasa los parámetros por nombre, se requieren las actualizaciones de código correspondientes.
def chunking_by_token_size(
    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,
    chunk_overlap_token_size: int = 100,
    chunk_token_size: int = 1200,
) -> list[dict[str, Any]]:
  • Inyecte una embedding_func con model_name en LightRAG usando wrap_embedding_func_with_attrs:
@wrap_embedding_func_with_attrs(
    embedding_dim=1536, max_token_size=8192, model_name="text-embedding-3-small"
)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

rag = LightRAG(
      working_dir=WORKING_DIR,
      llm_model_func=llm_model_func,
      embedding_func=embedding_func,
)

Para garantizar una transición perfecta, el código heredado que inyecta embedding_func sin model_name seguirá interactuando con las tablas de vectores originales sin sufijos.
