#LightRAG v1.5.0

Mejoras importantes

  • 🎉✨Característica: LightRAG ahora admite el procesamiento de documentos multimodal y puede aprovechar al máximo las imágenes, tablas y fórmulas dentro de los documentos para responder consultas. Todas las capacidades de procesamiento multimodal de RagAnything se fusionan en LightRAG; (RagAnything ya no recibirá actualizaciones de funciones principales ni mantenimiento en el futuro)
  • ✨🎉Característica: Completamente actualizado el proceso de procesamiento de documentos, con soporte para usar MinerU y Docling para analizar y extraer contenido de archivos, integrándose perfectamente con el análisis de contenido multimodal y la extracción de relaciones entre entidades.
  • 💡✨Característica: LightRAG ahora presenta Native Parsing, lo que permite la extracción de contenido de alta calidad de documentos DOCX. Admite la reconstrucción precisa de la numeración automática de Word, así como la extracción de imágenes, tablas y fórmulas, lo que proporciona una integración perfecta con el análisis de contenido multimodal y la extracción de relaciones entre entidades. Próximamente se ampliará la compatibilidad con el formato para Native Parser.
  • 💡🧠Característica: Se introdujeron cuatro estrategias de fragmentación de texto seleccionables: Fix, Recursive, Vector y Paragraph. Los parámetros para cada estrategia de fragmentación se pueden configurar a través de variables de entorno.
  • 💡🎯Característica: La canalización de procesamiento de archivos admite seleccionar el motor de análisis de archivos y la estrategia de fragmentación de texto, ya sea en función de las extensiones de archivo o por archivo. Para obtener instrucciones de uso detalladas, consulte FileProcessingPipeline.md.
  • 🚀⚡Rendimiento: optimizó la lógica de persistencia del almacenamiento de vectores al diferir los cálculos de vectores hasta el final de cada lote de procesamiento de archivos, lo que permite el cálculo masivo centralizado. Esto redujo significativamente la cantidad de invocaciones de modelos vectoriales y mejoró significativamente la velocidad de inserción de todas las bases de datos vectoriales compatibles con LightRAG.
  • Habilite la compatibilidad con la incrustación basada en tareas para modelos asimétricos, incluidos voyage-3, text-embedding-004, embed-multilingual-v3.0 y jina-embeddings-v3.
  • Confiabilidad de extracción de entidad/relación mejorada al introducir la salida estructurada LLM JSON; establezca ENTITY_EXTRACTION_USE_JSON=true para habilitarlo.
  • Introduzca ENTITY_TYPE_PROMPT_FILE para brindar a los usuarios una guía mejorada para el reconocimiento y extracción de tipos de entidades impulsado por LLM.
  • Totalmente compatible con los modelos Amazon y Anthropic en AWS Bedrock API.
  • 🎯✨🎉Característica: Se implementó soporte para configuración LLM específica de roles, introduciendo cuatro roles distintos: EXTRACTO, CONSULTA, PALABRAS CLAVE y VLM, cada uno con configuraciones LLM independientes. Se recomienda configurar la función KEYWORDS con un modelo de alta velocidad, sin razonamiento y con parámetros pequeños para optimizar la latencia de las consultas; la función EXTRACT con un modelo no razonado de parámetros medios para equilibrar la precisión y el rendimiento; y la función QUERY con un modelo de razonamiento de parámetros grandes para mejorar la calidad de la consulta. Para obtener instrucciones de uso detalladas, consulte RoleSpecificLLMConfiguration.md.

¿Qué está roto?

  • 💥Advertencia: Las actualizaciones requieren una planificación cuidadosa para los usuarios que actualmente utilizan OpenSearch y el almacenamiento de gráficos MongoDB, ya que la migración de datos y los reinicios del sistema pueden provocar interrupciones prolongadas del servicio.
  • ⚠️La variable de entorno ENTITY_TYPES ha quedado obsoleta; Reemplácelo con ENTITY_TYPE_PROMPT_FILE antes de iniciar esta nueva versión.
  • 💔Campo obsoleto eliminado: QueryParam.model_func eliminado de lightrag/base.py
  • Para versiones de OpenSearch anteriores a 3.3.0, actualice OpenSearch antes de actualizar LightRAG (consulte https://github.com/HKUDS/LightRAG/pull/2991).
  • ⚠️Mover eliminar_entidad/eliminar_relación del documento API al gráfico API
