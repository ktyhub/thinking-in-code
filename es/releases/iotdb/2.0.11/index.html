iotdb v2.0.11

#iotdbv2.0.11

Cambio de pausa

  • Esta versión eleva la versión mínima requerida de JDK a 17.

Funciones y mejoras

  • Metadatos: SHOW TIMESERIES admite la clasificación por nombre de medición.
  • Consulta: admite declaraciones SQL que contienen solo una cláusula SELECT.
  • Región: admite la reparación manual de tablas particionadas mediante SQL.
  • Vistas: admite vistas lógicas.
  • Metadatos: agregue la declaración COUNT DATABASE para el modelo de tabla.
  • IoTConsensus: admite múltiples directorios cuando IoTConsensus recibe instantáneas.
  • Región: las sintaxis EXTEND REGION y REMOVE REGION admiten una lista de ID de región, lo que permite procesar varias regiones a la vez.
  • Consulta: EXPLAIN ANALYZE admite el formato de salida JSON.
  • Mods: fortalece el control de la memoria para consultas que involucran mods. El uso de la memoria también debe ser controlable para un único archivo mods2 grande de nivel GB.
  • Ingestión de datos: al eliminar datos, envíe solicitudes solo al grupo de regiones al que pertenece la tabla actual.
  • Capa de protocolo: agregue control de memoria en la capa de protocolo.
  • UDF: Agregue una interfaz InternalSession a la UDF API.
  • Pipe: modifica la lógica de definición de datos en tiempo real.
  • Funciones: Admite el llenado de valores posteriores.
  • Cláusulas SQL: GROUP BY y ORDER BY admiten alias definidos con AS en la cláusula SELECT.
  • Configuración de parámetros: admite recarga en caliente de configuraciones de tiempo de ejecución del clúster.
  • Cifrado de comunicación: admite autenticación mutua para comunicaciones cifradas client.
  • Consulta: admite la escritura de resultados de consultas en un TsFile en una ruta especificada utilizando SQL.
  • Alta disponibilidad: admite alta disponibilidad para administración de tablas, administración de dispositivos, administración de vistas de escritura, administración de TTL, administración de bases de datos y privilegios de usuario.
  • Client: admite un Node.js client. Sólo se admite la versión 2.x.
  • Edge Edition: para facilitar el uso en dispositivos perimetrales con memoria limitada, introduzca una Edge Edition que limite el uso de memoria combinado de ConfigNode y DataNode a 512 MB. La carga de trabajo objetivo es de aproximadamente 10 000 mediciones operando a 1 Hz para cargas de trabajo de lectura y escritura. La primera versión ajustará principalmente ciertos parámetros de configuración predeterminados y del JVM; Las versiones futuras pueden continuar evolucionando hacia una arquitectura DataNode-ConfigNode más integrada.

Errores

  • Consulta: en los modelos de árbol y tabla, las comparaciones entre valores enteros y de punto flotante en las condiciones del filtro de consulta se comportan de manera inconsistente.
  • Escalado: durante la validación de escalado, IoTConsensusQueue en Memoria utilizada de IoTConsensus en el panel de monitoreo muestra un valor negativo.
  • Cargar TsFile: cuando el extremo receptor tiene privilegios de escritura, LOAD TSFILE falla sin permisos para esta operación, agregue el privilegio SISTEMA y los datos no se sincronizan.
  • SSL: Corrección de NullPointerException: No se puede invocar "String.contains(java.lang.CharSequence)" porque el valor de retorno de "java.lang.Throwable.getMessage()" es nulo.
  • SSL: mejore el mensaje de error que se muestra cuando SSL está habilitado en el paquete de seguridad pero el CLI se conecta al clúster sin especificar SSL, lo que hace que el mensaje sea más explícito.
  • Gestión del clúster: durante la validación del problema 0228, se encontró un nuevo problema: después de reiniciar el clúster, un nodo permaneció en el estado Desconocido y no produjo registros de disfrute, lo que indica que el hilo principal estaba bloqueado. Sin embargo, el nodo aún podría realizar la compactación con normalidad.
  • Escalado: durante el escalado, el campo CompressionRatio para una región de datos en el estado Agregar muestra un valor negativo en MOSTRAR REGIONES.
  • Región: conserve dos decimales para el campo CompressionRatio en los resultados de MOSTRAR REGIONES.
  • Escalado: durante el escalado horizontal, después de reiniciar el clúster, el campo CompressionRatio para la mayoría de las regiones de datos en MOSTRAR REGIONES es NaN, aunque tenía un valor antes del reinicio.
  • ConfigNode: corrige una fuga de hilo de ConfigNode. En una implementación de IoTV2 3C3D con tres réplicas, la ejecución de SQL que cubre casos de prueba de modelo de árbol provocó que la cantidad de subprocesos del procesador ConfigNodeRPC alcanzara los 3000. Ya no se pudo conectar el clúster y ConfigNode/DataNode informó NullPointerExceptions.
  • Consulta: Corregir un error en CAST(1.1 AS FLOAT): java.lang.UnsupportedOperationException: org.apache.tsfile.read.common.block.column.DoubleColumn. Se espera que la operación tenga éxito.
  • DataNode: PipeTsFileEpochProgressIndexKeeper retiene más de 50.000 TsFileResources, lo que provoca que el DataNode se quede sin memoria. En una implementación IoTV2 3C3D con dos réplicas, se realizaron lecturas, escrituras y eliminaciones simultáneas mientras un DataNode estaba detenido; Después de 54 horas de prueba, un DataNode se quedó sin memoria y generó un volcado OOM de 23 GB con ON_HEAP_MEMORY="20G".
  • Gestión de usuarios: la ejecución simultánea de LIST USER, CREATE USER y DROP USER puede dar lugar a 301: la solicitud de Ratis falló Desconocido. El registro de ConfigNode muestra Causado por: java.util.ConcurrentModificationException: nulo.
  • IoTConsensus: en una implementación 3C3D con dos réplicas, se realizaron lecturas, escrituras y eliminaciones simultáneas mientras un DataNode estaba detenido. Un proceso de DataNode salió y generó un archivo de volcado de 25 GB.
  • Metadatos: Prohibir la creación de dispositivos sobre medidas de plantilla y sus subtrayectos.
  • Región: un error en el tamaño del marco, el tamaño del marco (69670459) mayor que el tamaño máximo de protección (67108864), puede provocar que una consulta se cuelgue. En su lugar, el sistema debería devolver un mensaje de error apropiado.
