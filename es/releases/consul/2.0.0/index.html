cónsul v2.0.0

2.0.0 (22 de mayo de 2026)

SEGURIDAD:

  • conectar: actualice la versión del enviado a 1.37.2 y versiones más recientes [GH-23469]
  • go: actualiza la versión go a 1.26 [GH-23493]
  • agente: aumento de los tiempos de espera predeterminados del servidor HTTP para evitar interrumpir consultas de bloqueo de sondeos prolongados. read_timeout y write_timeout ahora están configurados en 15 minutos (en lugar de 30 segundos), mientras que read_header_timeout (10 s) y idle_timeout (120 s) aún brindan protección contra los ataques de Slowloris. Todos los tiempos de espera siguen siendo configurables a través del bloque http_config. [GH-23267]
  • api-gateway, terminating-gateway: aplique la normalización de la ruta de solicitud HTTP en los oyentes HTTP de la puerta de enlace api y de la puerta de enlace de terminación para evitar la omisión de RBAC de intención L7 a través de rutas no normalizadas (CVE-2024-10005). [GH-23534]
  • docker: actualiza la imagen base de ubi a ubi9-minimal:9.7. [GH-23553]
  • docker: actualice curl a >= 8.20.0 desde Alpine Edge en la imagen del contenedor para abordar CVE-2026-6429, CVE-2026-4873, CVE-2026-5773, CVE-2026-6253, CVE-2026-6276, CVE-2026-7168, CVE-2026-5545. La estable Alpine 3.23 aún no lleva la versión parcheada. [GH-23750]
  • docker: Actualización de la imagen base de UBI a 9.8 para corregir [CVE_2026-2100] [GH-23588]

CARACTERÍSTICAS:

  • (Solo Enterprise) actualización a go-licensing/v4 y go-census/v3 para adaptarse a nuevas licencias de PAO.
  • Limitador de velocidad global: (solo Enterprise) un nuevo tipo de entrada de configuración de "límite de velocidad" que permite una limitación de velocidad RPC dinámica en todo el clúster almacenada en Raft y replicada automáticamente en todos los servidores. Esto permite a los operadores aplicar o ajustar límites de velocidad globales en tiempo de ejecución sin reiniciar los servidores Consul, una capacidad crítica para escenarios de emergencia donde el clúster está bajo una carga excesiva.
  • api-gateway: se agregó compatibilidad con certificados SDS para los oyentes de la puerta de enlace API, incluidos los certificados TLS predeterminados a nivel de oyente y las anulaciones de SDS TLS del servicio de ruta HTTP/TCP. Las anulaciones de servicios heredan el clúster SDS del oyente cuando se omiten, y la validación de la puerta de enlace/generación de xDS ahora rechaza las asignaciones de anulaciones conflictivas para mantener la selección de certificados determinista. [GH-23354]
  • api-gateway: agregue soporte para límites ascendentes predeterminados a nivel de puerta de enlace y anulaciones de límites de nivel de servicio de ruta para MaxConnections, MaxPendingRequests y MaxConcurrentRequests. [GH-23396]
  • api: Se agregó el nuevo API "/v1/internal/rpc/methods" que enumera todos los nombres de los métodos RPC. Requiere un operador: lea el token ACL. Esto resulta útil cuando los usuarios desean configurar límites de velocidad que excluyen puntos finales RPC específicos. [GH-23329]
  • ca: (Solo para empresas) Se agregó un nuevo proveedor Connect CA para Cyberark WIM (connect.ca_provider = "pan-distributed-issuer"), lo que permite a Consul emitir certificados a través de Cyberark WIM.
  • servidor: (solo Enterprise) agregue una identidad de clúster estable y sincronización de registro global controlada por líder para la publicación de resúmenes de servicios.
  • telemetría: (solo Enterprise) Telemetría de producto para Consul autoadministrado con informes de uso anónimos y opcionales.
  • mesh: (Solo Enterprise) Introduce soporte para servicios multipuerto (puerto con nombre) en Consul, incluida la capacidad de especificar y enrutar el tráfico usando nombres de puerto, así como también recuperar IP virtuales para puertos de servicio específicos. También exige que ciertas funciones multipuerto avanzadas solo estén disponibles en Consul Enterprise e incluye nuevas funciones de utilidad para la denominación de clústeres y la generación de protocolos ALPN.

MEJORAS:

  • agente: (Solo para empresas) Agregue caché en segundo plano eventualmente consistente para métricas de uso empresarial, reduciendo la latencia GET /v1/operator/usage de O(PNK) a O(1) y reduciendo la presión de CPU/memoria durante scraping de alta frecuencia a través de una rutina de mantenimiento controlada por reloj.
  • mesh: (Solo Enterprise) Introduce soporte para servicios multipuerto (puerto con nombre) en Consul, incluida la capacidad de especificar y enrutar el tráfico usando nombres de puerto, así como también recuperar IP virtuales para puertos de servicio específicos. También exige que ciertas funciones multipuerto avanzadas solo estén disponibles en Consul Enterprise e incluye nuevas funciones de utilidad para la denominación de clústeres y la generación de protocolos ALPN.
  • puerta de enlace de terminación: se actualizó el tls ascendente del clúster para usar sds en lugar de certificados estáticos, lo que permite actualizaciones dinámicas de certificados sin necesidad de reiniciar la puerta de enlace de terminación. [GH-23288]
  • telemetría: agregue monitoreo de vencimiento de certificados con métricas Prometheus (etiquetadas con centro de datos/partición/espacio de nombres), registro estructurado con umbrales de gravedad configurables y Connect CA API mejorado para incluir el campo NotAfter para certificados raíz e intermedios. [GH-23147]
  • departamentos: actualice github.com/hashicorp/vault/sdk de v0.7.0 a v0.25.1 y github.com/hashicorp/vault/api de v1.12.2 a v1.16.0. [GH-23574]
  • test-integ: actualice testcontainers-go (v0.22.0->v0.40.0) y docker/docker (v24.0.5->v28.5.1) en el módulo de prueba de integración. Esto elimina opencontainers/runc como una dependencia de Go del marco de prueba. Estas son dependencias de infraestructura de prueba únicamente y no tienen ningún impacto en el binario del cónsul ni en la implementación del cónsul. [GH-23573]
  • xds: agregue los campos Consecutive5xx, ConsecutiveGatewayFailure y EnforcingConsecutiveGatewayFailure a PassiveHealthCheck, lo que permite a los operadores configurar umbrales de detección de valores atípicos de Envoy para respuestas 5xx y fallas de puerta de enlace (502/503/504) en los valores predeterminados ascendentes.

CORRECCIÓN DE ERRORES:

  • registro de auditoría: (solo Enterprise) Se corrigió el error de desclasificación JSON cuando se pasa una matriz de obj para el cuerpo auditReq.
  • cli: mensajes de error mejorados en el comando consul config write para proporcionar orientación práctica cuando las entradas de configuración no se pueden modificar debido a referencias de puertas de enlace o enrutadores. [GH-22921]
  • xds: Se corrigió el paquete XDS para generar terminales correctos y configuraciones de clúster para las puertas de enlace API cuando se emparejan, y se actualizó el controlador de actualización de la puerta de enlace API para propagar la configuración de la puerta de enlace de malla a sus canales ascendentes. [GH-23454]
  • XDS: soluciona el problema con la puerta de enlace de malla en modo remoto en AWS EKS, ya que los nombres de host DNS se asignan a los NLB de AWS en lugar de a las IP y la validación del punto final EDS del enviado espera que la dirección sea una IP. Ahora la asignación de carga de EDS se omite para destinos de gateway de malla remotos no pares con gateways basados ​​en nombres de host que mantienen CDS/EDS sincronizado. [GH-23543]
  • api-gateway: resuelve subconjuntos de servicios para rutas durante la síntesis de la cadena de descubrimiento de la puerta de enlace API. [GH-23294]
  • ui: Reparar enlaces de documentación rotos [GH-23578]
