clickhouse-java v0.9.7

Notas importantes

  • Se cambió el comportamiento de Client.Builder.addEndpoint(String): ahora guarda la ruta base de la URL (más en https://github.com/ClickHouse/clickhouse-java/issues/2344). Anteriormente, este método ignoraba la ruta base. Preste atención a que este método aún ignora los parámetros de consulta. El punto final NO es como la URL de JDBC. Client ha designado un método de creación para establecer la configuración.

Cambios importantes

  • [client-v2] Client.Builder#build() ahora genera ClientMisconfigurationException cuando se pasa una propiedad de configuración desconocida. Anteriormente, las propiedades desconocidas se ignoraban silenciosamente, lo que provocaba comportamientos y problemas inesperados. Para restaurar el comportamiento anterior, agregue ignore_unknown_config_key=true a las propiedades de client. Las propiedades exclusivas del controlador JDBC (por ejemplo, ssl) ya no se reenvían al client subyacente. (https://github.com/ClickHouse/clickhouse-java/issues/2658)

  • [client-v2] Las columnas Date/Date32 ahora se decodifican como LocalDate sin ningún ajuste de zona horaria. Anteriormente, los valores Date podían devolverse como ZonedDateTime. Las aplicaciones que necesitan un ZonedDateTime deben construirlo a partir del LocalDate devuelto utilizando su propio contexto de zona horaria. Más información sobre esto: https://clickhouse.com/docs/integrations/language-clients/java/jdbc_date_time_guide (https://github.com/ClickHouse/clickhouse-java/pull/2727)

Mejoras

  • [client-v2] Se agregó una opción para enviar parámetros de consulta en el cuerpo de la solicitud HTTP mediante codificación de formulario de varias partes. Habilitado a través de la nueva propiedad de configuración client.http.use_form_request_for_query (o Client.Builder#useHttpFormDataForQuery()). Útil cuando los parámetros de consulta exceden los límites de longitud de la URL. (https://github.com/ClickHouse/clickhouse-java/issues/2324)

  • [client-v2] QueryResponse, InsertResponse y CommandResponse ahora exponen getServerDisplayName() para recuperar el valor del encabezado de respuesta HTTP X-ClickHouse-Server-Display-Name. Se puede acceder a un mapa completo de encabezados de respuesta incluidos en la lista blanca a través de getResponseHeaders(). (https://github.com/ClickHouse/clickhouse-java/issues/2347)

  • [client-v2] Se agregó getObjectArray() a ClickHouseBinaryFormatReader y GenericRecord para leer columnas Array(...) como Object[], incluido el soporte recursivo para matrices anidadas. getStringArray() ahora también maneja Array(Enum*) devolviendo nombres de enumeración. (https://github.com/ClickHouse/clickhouse-java/issues/2738)

  • [jdbc-v2] Se agregó soporte para leer y escribir byte[] para columnas String/FixedString. PreparedStatement#setBytes() codifica el valor como una expresión ClickHouse unhex() para preservar los bytes sin formato; ResultSet#getBytes() devuelve los bytes UTF-8 del valor de cadena. (https://github.com/ClickHouse/clickhouse-java/pull/2734)

  • [client-v2] Preservar la parte de la ruta de la URL pasada al método del constructor `addEndpoint() (https://github.com/ClickHouse/clickhouse-java/pull/2691)

Manejo de fecha y hora

  • [docs] Se agregó un documento que explica cómo el controlador maneja diferentes valores de fecha/hora.

  • [client-v2, jdbc-v2] Se corrigió la escritura de valores Date/Time/Timestamp para que las conversiones de zona horaria se realicen explícitamente. Anteriormente, la codificación que no utilizaba zonas horarias provocaba errores de precisión y de turnos de día, especialmente cuando se utilizaba una zona horaria Calendar o JVM no predeterminada. (https://github.com/ClickHouse/clickhouse-java/issues/2701, https://github.com/ClickHouse/clickhouse-java/issues/2065, https://github.com/ClickHouse/clickhouse-java/issues/2496, https://github.com/ClickHouse/clickhouse-java/issues/1220, https://github.com/ClickHouse/clickhouse-java/issues/1117, https://github.com/ClickHouse/clickhouse-java/issues/1048, https://github.com/ClickHouse/clickhouse-java/issues/2381, https://github.com/ClickHouse/clickhouse-java/issues/1735, https://github.com/ClickHouse/clickhouse-java/issues/2542, https://github.com/ClickHouse/clickhouse-java/issues/2557)

  • [client-v2, jdbc-v2] Se corrigió la lectura de los valores Date/Time/DateTime para que sean consistentes y correctos. Date/Date32 ahora se decodifican como LocalDate (sin zona horaria), mientras que Time/Time64 se decodifican como LocalDateTime basado en UTC. Nuevo getLocalTime() API agregado a los lectores para acceso LocalTime. También se corrigió la lectura de fecha/hora de las columnas Dynamic y Variant. (https://github.com/ClickHouse/clickhouse-java/pull/2727)

  • [jdbc-v2] DatabaseMetaDataImpl#getTypeInfo() ahora devuelve información de tipo en orden alfabético determinista, coincidiendo con el comportamiento del controlador v1. (https://github.com/ClickHouse/clickhouse-java/pull/2733)

Analizador SQL (jdbc-v2)

  • [jdbc-v2] Se corrigió que el analizador SQL no pudiera manejar las palabras clave ClickHouse utilizadas como nombres de tablas o alias de columnas (por ejemplo, AS value, FROM date). Tanto el analizador ANTLR4 como el JavaCC ahora mantienen una lista de palabras clave no reservadas permitidas en las posiciones de los identificadores. También se corrigió el análisis del operador DESCRIBE (SELECT ...), IN en SELECT y el acceso a la matriz entre corchetes en las expresiones. (https://github.com/ClickHouse/clickhouse-java/issues/2718)

  • [jdbc-v2] Analizadores SQL actualizados para reconocer nuevas palabras clave ClickHouse (ABI, ARGUMENTS, DRY, LANGUAGE, RETURNS, RUN) introducidas en compilaciones recientes de ClickHouse HEAD. Anteriormente, las consultas que utilizaban estas palabras clave como identificadores no se podían analizar. (https://github.com/ClickHouse/clickhouse-java/pull/2761)

  • [jdbc-v2] Se corrigió el error del analizador SQL en declaraciones que contenían el operador ^ (intercalación), como toJSONString(data.^header_index). Ahora se reconoce y permite un nuevo token CARET en cadenas de identificadores de puntos. (https://github.com/ClickHouse/clickhouse-java/issues/2768)

Manejo de matrices y colecciones

  • [jdbc-v2] Se corrigió DataTypeConverter que causaba NPE al convertir matrices anidadas en cadenas (por ejemplo, ResultSet#getString() en una columna Array(Array(...))). El convertidor ahora es seguro para el reentrada. Anteriormente estaba lanzando NullPointerException. (https://github.com/ClickHouse/clickhouse-java/issues/2723)

  • [client-v2, jdbc-v2] Se corrigió la conversión de valores de matriz/List multidimensionales en matrices Java. Las dimensiones de la matriz secundaria ahora se calculan correctamente a partir del nivel de profundidad principal. Anteriormente, la conversión de List<List<T>> o estructuras similares producía resultados incorrectos. (https://github.com/ClickHouse/clickhouse-java/issues/2741)

  • [client-v2] Se corrigió la decodificación de matriz binaria cuando el primer elemento de una matriz es un Map o List vacío. Anteriormente, esto provocaba un error de discrepancia de tipos durante el llenado de la matriz. (https://github.com/ClickHouse/clickhouse-java/issues/2499, https://github.com/ClickHouse/clickhouse-java/issues/2657, https://github.com/ClickHouse/clickhouse-java/issues/2703)

Corrección de errores

  • [jdbc-v2] Se corrigió que DatabaseMetaDataImpl#getJDBCMajorVersion() y getJDBCMinorVersion() devolvieran la versión del controlador ClickHouse en lugar de la versión de especificación JDBC compatible. Ahora devuelve correctamente 4 y 2 (JDBC 4.2). (https://github.com/ClickHouse/clickhouse-java/pull/2736)

  • [jdbc-v2] Se agregó mapeo para todos los motores de tablas ClickHouse conocidos a tipos de tablas JDBC. Se agregó MATERIALIZED VIEW como nuevo tipo de tabla. getTables() ahora informa correctamente las tablas de motores remotos/externos que antes eran invisibles. (https://github.com/ClickHouse/clickhouse-java/issues/2664)

  • [jdbc-v2] Se corrigió NullPointerException en metadatos de tipo JDBC para columnas de tipo Map, IPv4, IPv6, UUID, BFloat16, Decimal256, Geometry, todos los tipos Interval*, JSON, LowCardinality, Nullable, Variant, Dynamic y otros. Anteriormente, estos tipos no tenían asignación de clases Java. (https://github.com/ClickHouse/clickhouse-java/issues/2711)

  • [jdbc-v2] Los códigos de error del servidor ClickHouse ahora se propagan a SQLException#getErrorCode(). Anteriormente, SQLException se creaba sin el código de error del proveedor, lo que hacía imposible distinguir los tipos de error mediante programación. (https://github.com/ClickHouse/clickhouse-java/issues/2717)

  • [client-v2] Se corrigió que max_execution_time no se enviara correctamente al servidor. Anteriormente, se trataba como una opción client y ClickHouse la ignoraba; ahora se transmite como una configuración del servidor. (https://github.com/ClickHouse/clickhouse-java/issues/2750)

  • [client-v2] Se corrigió que hasValue(columnName) arrojara una excepción cuando el nombre de la columna no existe. Anteriormente, hacer referencia a una columna desconocida o a un índice fuera de rango a través de hasValue() arrojaría; ahora devuelve false. (https://github.com/ClickHouse/clickhouse-java/issues/2755)

  • [jdbc-v2] Se corrigió que PreparedStatement informara parámetros faltantes usando índices basados en 0 en el mensaje de error. Las posiciones de los parámetros JDBC están basadas en 1; el mensaje de error ahora refleja esto correctamente. (https://github.com/ClickHouse/clickhouse-java/pull/2749)

  • [jdbc-v2] Propiedades de conexión JDBC v1 heredadas trasladadas (CUSTOM_HTTP_PARAMS, CUSTOM_SETTINGS, HTTP_CONNECTION_PROVIDER, REMEMBER_LAST_SET_ROLES, USE_SERVER_TIME_ZONE_FOR_DATES) a JDBC v2. Requerido para integraciones que comparten código de configuración JDBC v1/v2. Los valores custom_http_params y custom_settings se convierten automáticamente a la configuración del servidor. (https://github.com/ClickHouse/clickhouse-java/pull/2757)

  • [client-v2, jdbc-v2] Se corrigió que las propiedades de configuración con el prefijo custom_ no se reenviaran al servidor como configuraciones personalizadas cuando se usaba el prefijo custom_. También se corrigieron propiedades exclusivas del controlador (por ejemplo, ssl) que se reenviaban incorrectamente al HTTP client. (https://github.com/ClickHouse/clickhouse-java/issues/2658)
