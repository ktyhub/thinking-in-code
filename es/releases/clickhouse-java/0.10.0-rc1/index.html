clickhouse-java v0.10.0-rc1

Guía de migración de versiones

Cambios importantes

  • [jdbc-v2] El controlador ya no codifica las configuraciones del servidor async_insert=0 y wait_end_of_query=0 en cada JDBC conexión. Esto desbloquea dos escenarios que antes no funcionaban: anular estas configuraciones por conexión o por declaración y usar el controlador contra perfiles de solo lectura que no permiten anulaciones de SETTINGS. Hay dos consecuencias:

    • El controlador ahora sigue los valores predeterminados del lado del servidor para estas configuraciones (nota: comenzando con ClickHouse 26.3, async_insert por defecto es 1). Eliminar el wait_end_of_query=0 explícito no es una operación contra los valores predeterminados del servidor, pero permite a los usuarios optar por wait_end_of_query=1.
    • El recuento de filas devuelto por java.sql.Statement.executeUpdate(java.lang.String) (y el PreparedStatement correspondiente método) ya no se garantiza que sea preciso para las declaraciones INSERT cuando el servidor las ejecuta de forma asincrónica, y Es posible que los errores de análisis/datos en el cuerpo INSERT no aparezcan sincrónicamente como SQLException. Anteriormente estos eran preciso porque las inserciones se vieron obligadas a ser sincrónicas (consulte también https://github.com/ClickHouse/ClickHouse/issues/57768). Para restaurar el comportamiento anterior, configure async_insert=0 (o wait_for_async_insert=1) por conexión como configuración del servidor. Lea más sobre la inserción asíncrona: https://clickhouse.com/docs/optimize/asynchronous-inserts.

    (https://github.com/ClickHouse/clickhouse-java/issues/2652, https://github.com/ClickHouse/clickhouse-java/issues/2825)

  • [client-v2] Client.Builder#build() ahora lanza ClientMisconfigurationException en lugar de IllegalArgumentException para autenticación y configuración incorrecta de SSL (credenciales faltantes, conflicto métodos de autenticación, falta el certificado client cuando la autenticación SSL está habilitada y el almacén trust se usa en conjunto con certificado client). Personas que llamaban confiaban en capturar IllegalArgumentException de build() para estos casos debe capturar ClientMisconfigurationException (que extiende RuntimeException a través de ClientException). (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Combinando setUsername(...) + setPassword(...) con un encabezado HTTP Authorization personalizado ( httpHeader(HttpHeaders.AUTHORIZATION, ...)) ahora falla en Client.Builder#build() con ClientMisconfigurationException a menos que la autenticación HTTP básica esté explícitamente deshabilitada mediante useHTTPBasicAuth(false). Anteriormente, esta combinación se aceptaba y se anulaba el encabezado personalizado Authorization. el usuario/contraseña en el momento de la solicitud. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] La propiedad de configuración access_token (establecida a través de Client.Builder#setAccessToken(String) o directamente a través de setOption) ahora se aplica literalmente a las solicitudes salientes como el valor del encabezado HTTP Authorization. Anteriormente, el valor se almacenaba en access_token pero nunca se enviaba por cable, por lo que proporcionarlo por sí solo no tenía ningún efecto. sobre autenticación. Las personas que llaman deben incluir el prefijo del esquema (por ejemplo, setAccessToken("Bearer <token>")) o utilizar useBearerTokenAuth(String) que antepone Bearer automáticamente. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client.Builder#useBearerTokenAuth(String) ahora almacena el token de portador en access_token clave de configuración (con el prefijo Bearer ) en lugar de escribirla directamente en http_header_authorization. el El formato del cable HTTP no ha cambiado, pero el token ya no es observable a través de Client#getReadOnlyConfig() bajo el Tecla http_header_authorization. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Se corrigió el uso inconsistente del parámetro executionTimeout en el componente Client. El tiempo de espera fue previamente configurado en milisegundos pero recuperado y utilizado por error en segundos en algunos lugares. Ahora usa correctamente milisegundos consistentemente. (https://github.com/ClickHouse/clickhouse-java/issues/2358)

Nuevas funciones

  • [jdbc-v2, client-v2] Configuración de modos SSL implementados. Ahora es posible configurar ssl_mode a DISABLED, TRUST, VERIFY_CA y STRICT. Nota para usuarios de V1: NONE solo es compatible con el controlador JDBC y está asignado a TRUST. Migre al nuevo nombre.

  • Ejemplos para client-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/client-v2/src/main/java/com/clickhouse/examples/client_v2/SSLExamples.java

    • Ejemplos para jdbc-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/jdbc/src/main/java/com/clickhouse/examples/jdbc/SSLExamples.java (https://github.com/ClickHouse/clickhouse-java/pull/2874, https://github.com/ClickHouse/clickhouse-java/issues/2389, https://github.com/ClickHouse/clickhouse-java/issues/2309, https://github.com/ClickHouse/clickhouse-java/issues/2819)

  • [jdbc-v2, client-v2] (beta) Se implementaron lectores independientes para JSONEachRow para proporcionar un andamio para leyendo este formato. Además, ofrece una forma de asignar columnas Json a tipos personalizados utilizando el controlador JDBC. Ver ejemplos en https://github.com/ClickHouse/clickhouse-java/tree/main/examples/jdbc-v2-json-processors y https://github.com/ClickHouse/clickhouse-java/tree/main/examples/client-v2-json-processors. (https://github.com/ClickHouse/clickhouse-java/pull/2871)

  • [client-v2] Se agregó Session API para encapsular y administrar la configuración de sesión de ClickHouse (session_id, session_check, session_timeout, session_timezone) como objeto reutilizable. La instancia Session se puede aplicar a cualquier configuración de solicitud usando applyTo() y el estado de la sesión se pueden borrar a través de clearSession(). Además, agregó resetOption(String) a InsertSettings, QuerySettings y CommonSettings para permitir eliminar configuraciones específicas. Las configuraciones establecidas explícitamente en null no se enviarán al servidor, lo cual es útil para anular la configuración global. (https://github.com/ClickHouse/clickhouse-java/pull/2810)

  • [client-v2] Se agregó la actualización de credenciales de tiempo de ejecución API en Client: updateUserAndPassword(String, String), updateAccessToken(String) y updateBearerToken(String). Solicitudes posteriores en el mismo uso de instancia Client las nuevas credenciales sin reconstruir el client. El método de autenticación se fija en el momento de la construcción; llamando a un El actualizador en tiempo de ejecución que no coincide con el método configurado arroja ClientMisconfigurationException. Ver docs/authentication.md para obtener detalles y orientación sobre migración. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [jdbc-v2] Se agregó la propiedad de configuración cluster_name para especificar un clúster de destino para declaraciones como KILL QUERY que requieren una cláusula ON CLUSTER para ejecutarse en todos nodos. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [client-v2, jdbc-v2] Se agregó soporte para el tipo ClickHouse Geometry para ClickHouse 25.11+, donde Geometry cambiado de un alias String a Variant(Point, Ring, LineString, MultiLineString, Polygon, MultiPolygon) (client todavía compatible con versiones anteriores). Incluye manejo de lectura/escritura client y mapeo de tipo JDBC para recuperar y Insertar valores de geometría. Las escrituras actuales infieren la variante de geometría de destino a partir de la profundidad de anidamiento de la matriz, por lo que Ring vs LineString y Polygon frente a MultiLineString aún no se distinguen mediante la escritura genérica Geometry camino. (https://github.com/ClickHouse/clickhouse-java/pull/2815)

  • [jdbc-v2] ResultSet#getObject(int|String, Map<String, Class<?>>) ahora acepta nombres de tipos ClickHouse como claves de mapa además de los nombres JDBC SQLType que siempre ha aceptado. Para la búsqueda solo se utilizan nombres de tipos no empaquetados: Los contenedores Nullable(...) y LowCardinality(...) están eliminados y no afectan la resolución, por lo que una clave como "Int32" coincide con las columnas Int32 y Nullable(Int32); Teclas como "Nullable(Int32)" no se reconocen. El orden de búsqueda es el nombre de enumeración ClickHouseDataType (p. ej., "Int32", "String", "DateTime") y luego el nombre JDBC SQLType (p. ej. "INTEGER", "VARCHAR", "TIMESTAMP"); una entrada faltante deja el valor sin coerción. La función es compatible con Solo tipos primitivos ClickHouse: Array, Tuple, Map, Nested y los tipos de geometría no son compatibles y continúan se devolverán en su formato nativo independientemente del mapa proporcionado por el usuario. Mapas existentes codificados únicamente por JDBC SQLType Los nombres continúan funcionando sin cambios. (https://github.com/ClickHouse/clickhouse-java/pull/2865)

    • [jdbc-v2] Se agregó soporte de mapeo personalizado para tipos JDBC. Se utiliza principalmente en casos en los que se deben utilizar números enteros grandes. presentado como una cuerda. Utilice DriverProperties.JDBC_TYPE_MAPPINGS (jdbc_type_mappings) y establezca la asignación de tipos necesaria como lista key=value[,] (por ejemplo, Int32=Long,UInt64=String). Aviso de obsolescencia: la propiedad V1 typeMappings es compatible pero será eliminado. Migre a la nueva propiedad. (https://github.com/ClickHouse/clickhouse-java/issues/2858)

Mejoras

  • [jdbc-v2, client-v2] Se agregó soporte para nombres de host con guión bajo (_). Ahora es posible especificar el punto final como ch_db_01. Esto se usa principalmente en el entorno k8s. (https://github.com/ClickHouse/clickhouse-java/issues/2792, https://github.com/ClickHouse/clickhouse-java/issues/2753)

Dependencias actualizadas

  • [pruebas] Bump org.postgresql:postgresql de 42.6.1 a 42.7.11

Documentos y ejemplos

  • [client-v2] Se agregó un ejemplo de cómo trabajar con la biblioteca Apache Arrow usando client. (https://github.com/ClickHouse/clickhouse-java/pull/2820)

  • [repo] Se agregó una guía de contribución. Por favor revise y envíenos sus comentarios. (https://github.com/ClickHouse/clickhouse-java/pull/2859)

Corrección de errores

  • [jdbc-v2, client-v2] Se corrigió el manejo de errores para respuestas que no son un error ClickHouse, como la respuesta 404. (https://github.com/ClickHouse/clickhouse-java/issues/2803)

  • [jdbc-v2, client-v2] Se corrigió la configuración de null como contraseña. Anteriormente se convertía al literal null. Aún así recomendamos pasando una cadena vacía. (https://github.com/ClickHouse/clickhouse-java/pull/2809)

  • [jdbc-v2, client-v2] Se corrigió que ClickHouseBinaryFormatReader::getBigDecimal truncara silenciosamente un entero grande. (https://github.com/ClickHouse/clickhouse-java/issues/2748)

  • [jdbc-v2, client-v2] Se corrigió el manejo de los valores NULL en las columnas Variant y Dynamic. Anteriormente indicador de NULL no fue configurado ni leído. (https://github.com/ClickHouse/clickhouse-java/issues/2789, https://github.com/ClickHouse/clickhouse-java/issues/2791)

  • [jdbc-v2] Se corrigió que Statement.cancel() arrojara SESSION_IS_LOCKED cuando la declaración se ejecutaba dentro de un ClickSesión de casa. El conductor ahora acepta session_id, session_check y session_timeout como primera clase propiedades de conexión y las suprime correctamente al emitir un KILL QUERY durante la cancelación. Esto asegura la la solicitud de cancelación se ejecuta fuera de la sesión y ya no compite con la consulta en ejecución para la sesión bloquear. (https://github.com/ClickHouse/clickhouse-java/issues/2690, https://github.com/ClickHouse/clickhouse-java/issues/2881)

  • [jdbc-v2] Se agregó una opción para especificar el nombre del clúster para operaciones en el clúster. Uno de ellos es KILL QUERY .. ON CLUSTER <cluster_name>. Utilice DriverProperties.CLUSTER_NAME (jdbc_cluster_name) para definir el nombre del clúster que se utilizará en dichas consultas. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [jdbc-v2, client-v2] Se corrigió la escritura del marcador anulable para Tuple anidado y valores `Map. (https://github.com/ClickHouse/clickhouse-java/issues/2721)
