Código ballena v0.9.2

Codewhale es el producto público de Shannon Labs. El codewhale Los nombres de comando, paquete npm y activos de lanzamiento permanecen en minúsculas técnicas identificadores. El paquete npm heredado deepseek-tui está en desuso y no recibe más comunicados. Usuarios provenientes del legado v0.8.x deepseek / Los nombres deepseek-tui deben migrar con docs/REBRAND.md.

Instalar

Recomendado: npm (un comando, los tres puntos de entrada)

npm install -g codewhale

El contenedor descarga los codewhale, codew y codewhale-tui coincidentes. binarios de esta versión y los coloca en el mismo directorio.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.2

La imagen incluye el despachador codewhale, la cuña codew y el tiempo de ejecución codewhale-tui. La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Se requieren ambas cajas: codewhale-cli produce el despachador codewhale y la cuña codew, mientras que codewhale-tui produce el tiempo de ejecución interactivo en el que delega el despachador. La instalación de solo una caja fallará en tiempo de ejecución con un error MISSING_COMPANION_BINARY.

Cada plataforma también tiene binarios básicos y sin archivar adjuntos a continuación (codewhale-<platform>, codew-<platform> y codewhale-tui-<platform>): el contenedor npm y el codewhale update en la aplicación descargan los binarios de tiempo de ejecución coincidentes, mientras que los archivos .tar.gz / .zip anteriores son la descarga manual recomendada y, además, incluyen un script de instalación.   • /fleet status lee los subagentes de la sesión TUI actual mientras codewhale estado de la flota read the durable .codewhale/fleet.jsonl libro mayor - dos diferentes cosas que llevan un nombre, por lo que una carrera iniciada por codewhale fleet run nunca apareció en la TUI. /fleet status ahora lee el libro mayor duradero a través del misma ruta de código que el CLI; la vista de sesión mantiene su propio nombre como /fleet workers (/subagents y n todavía funcionan). Cuando un espacio de trabajo no tiene libro mayor, ambas superficies informan un motivo no_fleet_ledger escrito en lugar de un "todo claro", y ninguno de los dos crea el libro mayor como efecto secundario de leyéndolo (#4022).
  • codewhale fleet status (y list/interrupt/resume) creados .codewhale/fleet.jsonl como efecto secundario de abrir el administrador, luego informó no_fleet_ledger para el archivo que acababa de crear, por lo que el segundo La invocación mostró una flota vacía donde no existía ninguna. El CLI ahora se niega se construyen esos verbos antes del administrador, que coinciden con /fleet (#4022).
  • fleet resume <run-id> aceptó cualquier cadena. Una identificación ausente del libro mayor No concilió nada, pero aun así escribió un registro de estado de ejecución codificado por lo que fuera escrito y reportado no_change. Los identificadores desconocidos ahora se rechazan como not_found antes de cualquier escritura duradera (#4022).
  • lane interrupt informó transitioned incluso cuando no cambió nada - La parada de otro proceso se parecía a la nuestra. El backend de Runtime ahora informa si esta llamada realizó la transición y una operación no operativa es no_change. La valla @<lifecycle-seq> también se evalúa dentro del carril por carril del registro. bloquear en lugar de antes, por lo que una valla obsoleta se niega sin ejecutar Runtime desmontaje en lugar de correr entre el control y la parada (#1888).
  • /lane ya no ejecuta el desmontaje en tiempo de ejecución en el hilo del compositor de TUI. Sigue leyendo la superficie de barra omite la reconciliación (que prueba tmux y toma un bloqueo) y dígalo en el recibo en lugar de dar a entender que está fresco; lane interrupt es CLI: solo hasta que el trabajo se ejecute fuera del subproceso y se informe surface_not_supported nombrando codewhale lane interrupt (#4022).
  • La barra de acceso rápido ya no se modela como una tercera superficie de control. Una ranura une un comando de barra diagonal y lo activa sin argumentos, por lo que se ejecuta como la barra diagonal superficie; el contrato ahora declara qué verbo alcanza realmente una prensa desnuda (hotbar_bare_dispatch, válido solo para lane.list) en lugar de publicidad verbos que toman objetivos como accesibles mediante barra de acceso rápido (#1888).
  • codewhale lane list --json y lane status --json siguen emitiendo el LaneRecord forma que siempre tienen; el recibo no la reemplazó. el La salida humana lane status también recuperó branch, session, socket, attach y log, que el primer corte del DTO compartido había eliminado (#1888).
  • Ninguna superficie anuncia un backend que no tiene. lane restart y lane resume no tiene implementación: un carril es recreado por codewhale lane start y la sesión de ejecución de Lane detenida desapareció, por lo que todo tres superficies los rechazan con backend_not_implemented y dicen por qué. fleet restart completa el ciclo del administrador, lo que solo el CLI se ejecuta, por lo que /fleet restart informa surface_not_supported y nombra el CLI ordenar en lugar de hacer silenciosamente algo más pequeño (#1888).
  • Las reglas de denegación en permissions.toml ya no pierden un comando debido a un bandera interviniente: denegar coincidencia se basa en tokens con omisión de bandera y retrocediendo, por lo que una regla git push aún captura git -c foo=bar push. Caso de pliegues de coincidencia de caminos solo en plataformas cuyo Los sistemas de archivos no distinguen entre mayúsculas y minúsculas y la rama de aprobación predeterminada no ya no propone el directorio de trabajo como host de red.
  • Las llamadas a la herramienta MCP se ejecutan una vez. Una llamada fallida ya no se reintenta como si Si la búsqueda falla, la resolución de nombres calificados recopila todas las coincidencias y informa una ambigüedad en lugar de tomar lo que arrojó el mapa hash primero, y registrar un servidor cuyo nombre colisiona con uno existente después de la desinfección ahora es un error en lugar de una sobrescritura silenciosa. La dirección de reparación equivalente de llamada única provino del PR #4756 cerrado por @adity982.
  • El índice de la sesión sobrevive a una línea rota: se omite una entrada que no se puede analizar en lugar de abortar toda la lectura, los anexos llevan sus datos a disco, y los agregados y la compactación comparten un bloqueo, por lo que una compactación no puede Ya no corre y agrega un registro perdido.
  • Edit cuenta como una herramienta de escritura para la elevación del flujo de trabajo y la TUI. La clasificación de escritura/shell ahora delega a una lista de permitidos compartida en lugar de que quedarse con una segunda copia que podría desviarse.
  • Un app/config/set rechazado sigue sin funcionar. Anteriormente un valor no válido todavía derribó el puente de tiempo de ejecución en caché, matando el tiempo de ejecución secundario y dejando huérfanos a todos los demás hilos de stdio en vuelo detrás de una respuesta que Fallo reportado correctamente.
  • Un proyecto config.toml con formato incorrecto ya no es indistinguible de sin tener configuración de proyecto. Porque la configuración de un proyecto sólo puede apretar política de aprobación y zona de pruebas, descartar silenciosamente una rota dejó caer una las restricciones del repositorio vuelven a los valores predeterminados de usuario más flexibles; la configuración El asistente ahora lo dice, nombrando el archivo pero nunca citando su contenido.
  • Un árbol de trabajo de carril caducado ya no deja su rama atrás, lo que hizo La reutilización del mismo nombre de carril falla con "la sucursal ya existe". una sucursal aún llevar confirmaciones no fusionadas se mantiene: la caducidad de un TTL no es consentimiento eliminar el trabajo de alguien.
  • Se puede detener un viraje thread/message en vuelo. El bucle stdio mantiene leyendo mientras se transmite un turno, por lo que la nueva solicitud thread/interrupt (y shutdown) puede llegar a un giro fuera de control en lugar de esperar en el mismo giro. estaban destinados a detenerse.
  • La precedencia se establece únicamente en la sección de la constitución "Cuya palabra gana". La higiene de la memoria ya no incluye una lista de niveles invertida que pone el constitución por encima de la solicitud actual del usuario; aprobación, compactación y las superposiciones de personalidad describen el comportamiento sin vocabulario de rango; y el La autoridad recapitula los puntos en una sola fuente en lugar de reformular una segunda escalera.
  • <turn_meta> lleva datos (modo, postura, modelo, espacio de trabajo), no modo Los ensayos de doctrina o preguntas sobre permiso reafirmaban cada mensaje de usuario.
  • El paquete de contexto del proyecto (árbol de espacio de trabajo bastante impreso) está desactivado de forma predeterminada. y regístrese a través de [context] project_pack = true. La ley del lenguaje está comprimida. manteniendo el contrato de constitución en inglés / respuesta en idioma de usuario.
  • Las listas modales y los selectores de configuración envuelven la selección en ambos extremos (más allá del la última fila vuelve a la parte superior). Se prefiere la resolución del directorio de inicio HOME/USERPROFILE a través de effective_home_dir en los sitios de llamadas restantes para que Las pruebas de Windows que simulan que las variables de entorno del hogar coinciden con las rutas de producción. el El barrido equivalente del directorio personal provino del PR #4760 cerrado por @EvanProgramming.

Cambiado

  • Las entradas del catálogo de herramientas de caché de prefijo almacenan solo el resumen SHA-256, no el cadena de catálogo unida. Se eliminan los ayudantes de validación de transición de plan no utilizados.
  • Las secciones de configuración ahora contienen solo lo que afirman (#4751). La flota mantiene Preocupaciones sobre la flota/miembros; /goal se trasladó a una sección Sesión y flujo de trabajo orquestación en su propia sección Flujo de trabajo. El inerte DeepSeek-only El respaldo default_model se movió de la configuración del modelo a un modo explícito Sección Legacy: los usuarios de flotas exactas cambian de flota, no de modelos alternativos; el campo de configuración se conserva porque el tiempo de ejecución todavía lo lee. esto es Solo presentación: las claves persistentes (goal_command, workflow, default_model), sus valores, alcances y comportamiento de tiempo de ejecución no cambian.
  • El enrutamiento del modelo automático tiene como alcance el proveedor activo. el clasificador El inventario ya no revela las rutas ejecutables de otros proveedores (o el hecho que sus credenciales existen), una respuesta del clasificador nombrando a otro proveedor es rechazado, la heurística local ya no recurre a un proveedor diferente cuando el activo es inutilizable y el clasificador implícito DeepSeek-flash se omite en sesiones que no son de DeepSeek. Recibos de automóviles y el selector de modelos La sugerencia informa el alcance de solo proveedor activo en lugar de "proveedores ejecutables". Auto entre proveedores está disponible solo a través del [auto] persistente cross_provider = true opt-in (an explicit [auto.router] la ruta sigue siendo su propia suscripción para la llamada del clasificador). Selección fuerte/rápida del mismo proveedor y [auto] cost_saving no han cambiado.
  • El arnés de aceptación del pseudoterminal QA ahora analiza marcos con rio-vt detrás de su marco neutro/superficie de color existente, conservando las afirmaciones mientras se elimina la dependencia vt100 (PR #4931 por @raphamorim).
  • La apertura de la transmisión de mensajes antrópicos y respuestas de OpenAI ahora comparte el Costura client/stream_entry.rs ya utilizada por Chat Completions: una delimitada espera de encabezado de respuesta, selección de política compartida dual/HTTP-1.1, como máximo una Respaldo HTTP/1.1 en un bloqueo de encabezado HTTP/2 clasificado y tiempo de espera de inactividad común diagnóstico. Autenticación, encabezados, puntos finales, decodificación y El comportamiento del límite de velocidad permanece en cada borde del adaptador. La colocación del tiempo de espera El diagnóstico y la dirección de reparación provienen del PR #4743 cerrado por @vibecoding-habilidades.

Seguridad

  • Los contenedores de lanzamiento ahora publican una certificación SBOM y fijan el modo máximo procedencia explícitamente para que los metadatos de la cadena de suministro no puedan debilitarse silenciosamente con un cambio predeterminado del constructor (PR #4958 por @kobihikri).
