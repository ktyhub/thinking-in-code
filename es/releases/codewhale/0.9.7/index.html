código ballena v0.9.7

Codewhale es el producto público de Shannon Labs. El codewhale Los nombres de comando, paquete npm y activos de lanzamiento permanecen en minúsculas técnicas identificadores. El paquete npm heredado deepseek-tui está en desuso y no recibe más comunicados. Usuarios provenientes del legado v0.8.x deepseek / Los nombres deepseek-tui deben migrar con docs/REBRAND.md.

Instalar

Recomendado: npm (un comando, ambos puntos de entrada)

npm install -g codewhale

El contenedor descarga los recursos de comando codewhale y codew coincidentes. de esta versión. Ambos contienen el mismo tiempo de ejecución compilado.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.7

La imagen muestra el mismo tiempo de ejecución que codewhale y codew. el La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli --locked

El paquete Cargo instala codewhale. Cargo no puede crear un segundo comando alias de un objetivo binario; los usuarios que quieran una ortografía más corta pueden agregar una Enlace simbólico codew a ese ejecutable instalado. El npm, Homebrew, archivo, El instalador de shell y los canales de contenedor instalan ambos nombres de comando directamente.

Descarga manual: archivos de plataforma (recomendado)

Cada archivo a continuación contiene el mismo tiempo de ejecución bajo codewhale y Nombres de los comandos codew, además de un script de instalación:

| Plataforma | Archivo | Instalar script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | MacOS x64 | codewhale-macos-x64.tar.gz | install.sh | | BRAZO macOS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (instalador) | CodeWhaleSetup.exe | Configuración de NSIS | | Ventanas x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portátil) | codewhale-windows-x64-portable.zip | — | | Ventanas ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (portátil) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux/macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Para la ruta del instalador, ejecute CodeWhaleSetup.exe; se instala codewhale.exe y codew.exe bajo %LOCALAPPDATA%\Programs\CodeWhale\bin y agrega ese directorio al RUTA del usuario actual.
  • Extraiga el archivo de su máquina: codewhale-windows-x64.zip o codewhale-windows-arm64.zip
  • Ejecute install.bat (copias a %USERPROFILE%\bin)
  • Añade %USERPROFILE%\bin a tu RUTA

El archivo portátil de Windows omite el script de instalación: extráigalo y ejecútelo desde cualquier directorio. El instalador de NSIS actualmente no está firmado y puede activar Windows SmartScreen hasta que se conecte un certificado de firma al proceso de lanzamiento.

Cada plataforma también tiene codewhale-<platform> desnudo y sin archivar y Activos codew-<platform>. Los siete nombres de archivos codewhale-tui-<platform> adjuntas a v0.9.5 son copias de compatibilidad de bytes idénticos que se utilizan solo para permitir v0.9.4 clients ya instalado descubre y cruza este binario único transición; Los instaladores actuales no exponen un tercer tiempo de ejecución. El legado de la npm El paquete deepseek-tui está en desuso y no se vuelve a publicar. Para la migración de los nombres binarios heredados v0.8.x, consulte docs/REBRAND.md.

¿Qué hay en v0.9.7?

Codewhale v0.9.7 mantiene el catálogo normal. Grok 4.6 aterriza como catálogo normal fila en lugar de una pila de casos especiales en forma de proveedor, OrcaRouter se une como un proveedor nombrado, y un aviso de seguridad de pánico en lru se elimina levantando el pin que lo causó en lugar de vivir a su alrededor.

Agregado

  • Grok 4.6 es el xAI predeterminado directo, con el alias grok moviéndose hacia él y grok-4.5 aún se puede seleccionar explícitamente. Su contexto de 500K, entrada de texto/imagen, herramienta y soporte de salida estructurada, razonamiento low/medium/high/xhigh (predeterminado high) y la búsqueda web del lado del servidor provienen del Catálogo en forma de Models.dev en lugar de código específico del modelo. reasoning_effort llega al cable solo en la ruta exacta https://api.x.ai/v1 propia, y el límite de precios de 200.000 tokens que tiene en cuenta el uso tiene como objetivo dirigir xAI para que Las rutas del agregador que reutilizan el modelo slug no pueden heredar la facturación xAI.
  • OrcaRouter es un proveedor con nombre de primera clase: ORCAROUTER_API_KEY, base predeterminada URL https://api.orcarouter.ai/v1, deepseek/deepseek-v4-pro predeterminada, Enrutamiento orcarouter/auto, selector CLI --provider y entradas de selector TUI (#5321).

Cambiado

  • Normalización del esfuerzo de razonamiento y el selector de modelos lee la publicación de un modelo. lista reasoning_options del catálogo en lugar de contraer cada ruta a la histórica escalera Baja/Media. Cualquier fila del catálogo que publique una lista de esfuerzos. mantiene su propio vocabulario.
  • Los documentos graban la etiqueta backend DeepSeek-V4-Pro-0813 en vivo de DeepSeek mientras que el El ID invocable de API permanece en deepseek-v4-pro. No se reasignan alias ni Se envía el selector deepseek-v4-pro[1m].

Fijo

  • Copiar un mensaje de usuario o asistente toma su contenido canónico en lugar de líneas de transcripción reserializadas, manteniendo glifos de roles, rieles de continuación y envoltura visual del tablero cli preservando el Unicode creado, Rebajas y saltos de línea estrictos. Las células de herramientas y de pensamiento permanecen en lo existente ruta de la transcripción completa (#5319).
  • load_session ya no ejecuta recuperación de fallas en cada lectura. Lecturas instantáneas van a través de un load_session_snapshot libre de efectos secundarios y la recuperación es explícita a través de recover_session_for_resume, por lo que un host integrado que inspecciona un dispositivo duradero La sesión mientras una herramienta aún se está ejecutando ya no recibe una reparación de fallo falsa. (#5320).

Seguridad

  • lru se mueve a 0.18 para borrar RUSTSEC-2026-0253, donde estaba LruCache::pop(). no es seguro para el pánico y podría dejar sugerencias en la lista pendientes. El ratatui-core El pin =0.1.0 que forzó transitivamente lru ^0.16 se levanta, por lo que ColorCompatBackend ahora responde get_cursor_position() desde el cursor rastreado estado: la solución alternativa recomendada por los desarrolladores para la carrera inicial de RCP (ratatui/ratatui#2483, ratatui/ratatui#2640) que el pin funcionó originalmente alrededor. El propio ratatui permanece fijado en =0.30.0, por lo que la superficie API es sin cambios.

Problemas conocidos

  • La prueba de integración exec_persistent_service::failed_exec_kills_pending_service_and_exits_nonzero es un error confirmado bajo carga paralela ("el archivo pid de servicio nunca apareció"). Pasa de forma aislada y no está relacionada con ningún cambio de v0.9.7.
