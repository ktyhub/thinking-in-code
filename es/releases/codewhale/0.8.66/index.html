Codewhale v0.8.66

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

Código ballena v0.8.66

CodeWhale es el proyecto canónico, el comando, el paquete npm y nombre del activo de liberación. El paquete npm heredado deepseek-tui es está en desuso y no recibe más versiones. Usuarios provenientes de Los nombres v0.8.x heredados deepseek / deepseek-tui deben migrar con docs/REBRAND.md.

Instalar

Recomendado: npm (un comando, ambos binarios)

npm install -g codewhale

El contenedor descarga los archivos binarios de tiempo de ejecución coincidentes de esta versión y los coloca en el mismo directorio.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

La imagen incluye el despachador codewhale, la cuña codew y el tiempo de ejecución codewhale-tui. La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Se requieren ambas cajas: codewhale-cli produce el despachador codewhale y la cuña codew, mientras que codewhale-tui produce el tiempo de ejecución interactivo en el que delega el despachador. La instalación de solo una caja fallará en tiempo de ejecución con un error MISSING_COMPANION_BINARY.

Descarga manual: archivos de plataforma (recomendado)

Cada archivo a continuación contiene el despachador codewhale, el shim codew y el tiempo de ejecución codewhale-tui, además de un script de instalación: | Plataforma | Archivo | Instalar script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | MacOS x64 | codewhale-macos-x64.tar.gz | install.sh | | BRAZO macOS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (instalador) | CodeWhaleSetup.exe | Configuración de NSIS | | Ventanas x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portátil) | codewhale-windows-x64-portable.zip | — | Unix (Linux/macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Para la ruta del instalador, ejecute CodeWhaleSetup.exe; instala codewhale.exe, codew.exe y codewhale-tui.exe en %LOCALAPPDATA%\Programs\CodeWhale\bin y agrega ese directorio a la RUTA del usuario actual.
  • Extracto codewhale-windows-x64.zip
  • Ejecute install.bat (copias a %USERPROFILE%\bin)
  • Añade %USERPROFILE%\bin a tu RUTA El archivo portátil de Windows omite el script de instalación: extráigalo y ejecútelo desde cualquier directorio. El instalador de NSIS actualmente no está firmado y puede activar Windows SmartScreen hasta que se conecte un certificado de firma al proceso de lanzamiento. Cada plataforma también tiene binarios básicos y sin archivar adjuntos a continuación (codewhale-<platform>, codew-<platform> y codewhale-tui-<platform>): el contenedor npm y el codewhale update en la aplicación descargan los binarios de tiempo de ejecución coincidentes, mientras que los archivos .tar.gz / .zip anteriores son la descarga manual recomendada y, además, incluyen un script de instalación. El paquete npm heredado deepseek-tui está obsoleto y no se vuelve a publicar. Para la migración desde nombres binarios heredados v0.8.x, consulte docs/REBRAND.md.

Verificar (recomendado)

Descargue los manifiestos de suma de comprobación de esta versión y verifique:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

¿Qué hay en v0.8.66?

Agregado

  • Se agregó el estado heredado de codewhale doctor / codewhale doctor --json diagnósticos que comparan las rutas de estado conocidas de ~/.deepseek con sus ~/.codewhale y marcar datos no migrados o de doble raíz (#3727).
  • Se agregó Sakana AI Fugu como proveedor de primera clase compatible con OpenAI con Alias sakana/fugu, descubrimiento FUGU_API_KEY/SAKANA_API_KEY, cableado del selector de proveedores, terminaciones de modelos y documentos del proveedor. Cosechado de #3748 de @lerugray.
  • Se agregó la validación de la forma de lanzamiento de WhaleFlow-to-Fleet: el flujo de trabajo predeterminado de Fleet El contrato permite hasta 100 agentes en total y 5 anillos recursivos, requiere bucles limitados/se expande antes del lanzamiento y conserva la selección de modelo por ranura.
  • Se agregó una vista /config ask-rules de solo lectura para los resueltos. Ruta permissions.toml, estado del archivo, recuento de reglas y configuración Reglas de solicitud de herramienta/comando/ruta. Fusionado del n.° 3569 por @greyfreedom.
  • Se agregaron anulaciones de context_window a nivel de proveedor para que sean compatibles con OpenAI Las puertas de enlace y los proveedores autohospedados pueden presupuestar según su modelo real. ventana contextual (#3545).
  • Se agregó la cuña nativa codew para liberar archivos, entradas del instalador de Windows, preparación de activos de lanzamiento local y verificación de suma de verificación para instalaciones manuales Reciba el mismo comando corto que Cargo instala la compilación.
  • Se agregó OpenModel como proveedor de mensajes antrópicos de primera clase, con configuración, CLI, selector de proveedores, documentos y cobertura de registro. Cosechado del n.° 3585 por @noaft.
  • Se agregó documentación de seguridad e implementación de WeCom Bridge, con envío comandos de tiempo de ejecución/puente y orientación sobre el entorno de tiempo de espera de aprobación. Cosechado del n.° 3640 de @pkeging.
  • Se agregó un comando token/caché/costo scorecard para la activación de la versión fuera de línea. comprobaciones de regresión de referencia y visibilidad de costos por turno (#3388). Corriente-JSON Los metadatos ejecutivos ahora también informan conservadores input_analysis y visible_final_answer_chars, para que los arneses de referencia puedan medir la transcripción crecimiento y aumento de la respuesta final sin adivinar (n.° 2956, n.° 2957).
  • Se agregó un libro de evidencia de liberación para v0.8.66 y se abrió el ACP externo. envío de registro para CodeWhale después de validar lo publicado codewhale@0.8.65 Protocolo de enlace de autenticación de ACP contra el verificador de registro ascendente (#3192).
  • Se agregó una tabla de configuración [verifier] escrita para el carril de vista previa del verificador, con enabled y el mapeo verdict_policy = "hunt" enviado documentado y validado (#2093).
  • Se agregó el cambio rápido de ranura Hotbar Alt+1–Alt+8 con tecla de tarjeta de decisión desambiguación, además de una tarjeta introductoria que explica y puede descartar la Barra de acceso rápido (n.° 3796, n.° 3788).
  • Higiene de versiones/documentos: instalación pública protegida/fragmentos de versión y npm codewhaleBinaryVersion puntero contra deriva, fabricado check-docs/check-facts falló en fragmentos obsoletos o proveedores no asignados y detuvo sync-changelog de descartar una versión cuando solo existe [Unreleased] (#3767, #3768, #3769, #3770, #3771, #3772).

Cambiado

  • Modo automático diferido desde el selector de modo de cara al usuario, ciclo, barra de acceso rápido, /mode comando y el modo de subproceso en tiempo de ejecución se anula hasta que tenga un mensaje distinto y comportamiento de revisión automática; El texto del modo auto existente ahora se pliega nuevamente al Agente. en lugar de seleccionar un modo hueco, y la copia modal de aprobación ya no implica el modo actual es YOLO (#3730, #3733).
  • Se aclaró la superficie de configuración de la flota y los documentos para que la flota se trate como algo duradero. capa de configuración de subagente, mientras que WhaleFlow es la capa creada por el agente Plan de orquestación que selecciona y monitorea los espacios de la flota.
  • Se redujo el mensaje constitucional predeterminado manteniendo su estructura estructural requerida. anclajes bajo cobertura de regresión, lo que reduce la huella de aviso estático para giros sensibles al caché (#2953).
  • Se hizo el mensaje de aprobación en línea y anclado en la parte inferior en lugar de una pantalla completa. Toma de control, por lo que el contexto y los controles permanecen visibles mientras una herramienta espera una decisión. (#3799).
  • La barra de acceso rápido ahora está oculta de forma predeterminada hasta que se active la configuración explícita (#3807); el El shell del Agente interactivo también tiene como valor predeterminado el control de aprobación con un servidor compartido. línea de base (#3756).
  • La autoridad de modo ahora resuelve las solicitudes de aprobación a través de una única autoridad. fuente en lugar de verificaciones por superficie (#3795).

Fijo

  • Reubicación del estado heredado emergido con un aviso de migración visible para el usuario siempre que sea ~/.deepseek/<state> se mueve o copia en ~/.codewhale/<state>, por lo que Los usuarios actualizados saben que sus datos se conservaron y dónde se encuentra el estado canónico. ahora vive (#3726).
  • Visibilidad restaurada del .deepseek/sessions heredado para instalaciones actualizadas donde ya existía un directorio ~/.codewhale/sessions vacío, copiando faltan entradas de sesión heredadas en el almacén de sesiones principal de CodeWhale sin sobrescribir datos más nuevos (#3724).
  • Clasificación de riesgo de aprobación tranquila para comandos de shell de solo lectura como codewhale --version, codewhale --help y git status --porcelain, por lo que el modal ya no etiqueta el shell de solo lectura probado como destructivo (#3730).
  • Se agregaron columnas de ruta de proveedor/modelo a /cache para activar la telemetría para que DeepSeek Las regresiones de aciertos de caché se pueden correlacionar con los cambios de ruta automáticos (#3738).
  • Se corrigió el manejo de aprobación del tiempo de ejecución API para que el espacio de trabajo trust ya no se resuelva automáticamente. aprobaciones de herramientas ordinarias; trust ahora solo participa en el reintento de acceso completo decisiones mientras que YOLO/aprobación automática sigue siendo la omisión de aprobación (#3736).
  • Se corrigieron las superficies modales para que la pila de vista compartida pinte un fondo opaco antes cualquier superposición, mientras que los interiores emergentes del Plan/solicitud de entrada permanecen opacos y el Plan El pie de página de confirmación mantiene las opciones de acción visibles en terminales angostas (#3732).
  • Se agregó una protección en modo Plan de bucle giratorio para herramientas de escritura de archivos y MCP con capacidad de escritura. herramientas para que la promesa de "no escrituras" de Plan se cumpla antes de la aprobación o ejecución, no solo por la capa sandbox/catálogo (#3734).
  • Se preservó el piso de seguridad de revisión duradero para acciones de proyectiles tipo publicación en Modo YOLO, por lo que cargo publish, npm publish y etiqueta/liberación empujan la fuerza aprobación en lugar de aprobación automática silenciosa (#3735).
  • Se corrigió que el editor externo Ctrl+O se congelara donde la bomba de entrada del terminal de CodeWhale podría seguir leyendo claves mientras Vim/editor fuera dueño del terminal, especialmente en Conchas mintty/cygwin de Windows. Gracias @buko por la reproducción precisa (#3657).
  • Se fortaleció la verificación de deriva de dependencia de OHOS contra los EOF transitorios del registro de carga. reintentando la sonda del gráfico de dependencia antes de que falle la CI.
  • Se actualizó el respaldo del proveedor /links a la URL actual de los documentos de CodeWhale y Se agregó un enlace de documentos de Baidu Qianfan. Cosechado del n.° 3621 por @noaft.
  • CODEWHALE_TOOL_SURFACE=shell-only reforzado para ejecuciones comparativas/ejecutivas: el La superficie de solo caparazón oculta las herramientas nativas del catálogo visible del modelo, y Los valores desconocidos de CODEWHALE_TOOL_SURFACE ahora advierten en lugar de caer silenciosamente. de nuevo a la superficie completa de la herramienta (#2954).
  • Distribución de subagentes y rutas activas de bloqueo: se conserva el margen de maniobra del canal de eventos para eventos de progreso (#3783, gracias @cyq1017), permite que se inicie el subagente independiente unirse a un único lote de envío paralelo en lugar de serializar (#3801), renderizado la barra lateral del subagente/ListSubAgents desde una instantánea de solo lectura con límites limpieza (#3803), se utilizaron envíos de mejor esfuerzo sin bloqueo para la actualización de ListSubAgents mientras aún se esperan eventos críticos (#3802), se movió el estado de subagente E/S de disco de persistencia fuera del bloqueo de escritura del administrador (#3805) y usé try_lock para la actualización del administrador de shell en rutas de interfaz de usuario asíncronas (#3804).
  • Procedencia: las continuaciones en tiempo de ejecución y SubAgentHandoff ahora heredan el estado. autoridad YOLO, mientras que MemoryRecall, ImportedTranscript y Las entradas AssistantGenerated permanecen protegidas (#3817).
  • Honestidad en la aprobación: aprobaciones etiquetadas en el ámbito de la sesión con precisión en lugar de "siempre" y mostró decisiones de aprobación en los resultados de la herramienta (#3766). Los créditos de los contribuyentes para este lanzamiento se encuentran en la entrada changelog anterior: Gracias a todos cuyos informes, relaciones públicas, reseñas y reproducciones le dieron forma.
