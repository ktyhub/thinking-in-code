#graphql-java v25.0

Cambios clave

Cargador de datos

Estrategia de refactorización

La PerLevelDataLoaderStrategy existente se ha refactorizado, lo que conduce a simplificaciones y mejoras de rendimiento.

Nuevas estrategias

Se introdujeron dos nuevas estrategias: ENCADENADO y AGOTADO. Ambos se pueden configurar a través de UnusalConfiguration (consulte la siguiente sección).

CHAINED permite el uso de DataLoaders encadenados manteniendo estrategias de despacho por nivel.

AGOTADO es una estrategia completamente nueva que funciona sobre la base de despachar una vez que el motor no está ocupado. Refleja la estrategia de envío del cargador de datos JS, pero para un sistema de subprocesos múltiples.

Configuración inusual

Se ha agregado un mecanismo de configuración más generalizado para la "configuración inusual". Con esto nos referimos a la configuración que no esperamos que mucha gente use, pero si lo hacen ahora será en un lugar más común.

Por ejemplo, si desea cambiar la profundidad máxima que aceptará el analizador de documentos, puede llamar a los siguientes métodos.

        var parserOptions = newParserOptions().maxRuleDepth(99).build()
        GraphQL.unusualConfiguration().parsing().setDefaultParserOptions(parserOptions)

JEspecificar anotaciones

El equipo está empezando a adoptar las anotaciones https://jspecify.dev/ como forma de indicar campos que aceptan valores NULL y no. A muchas clases importantes se les han agregado estas anotaciones para ayudar a que quede más semánticamente claro cuándo un valor puede ser nulo o no.

Cambios importantes

Un objeto envolvente FetchedValue no siempre se devuelve en los captadores de campos por motivos de rendimiento. Esto significa que graphql.execution.instrumentation.parameters.InstrumentationFieldCompleteParameters#getFetchedObject se creó para reemplazar el método getFetchedValue anterior y el objeto devuelto a veces puede ser un FetchedValue o, a veces, un valor POJO simple.

Mejoras de rendimiento

Se han realizado una serie de mejoras de rendimiento para reducir el uso de memoria de la biblioteca. Además, el operador Java .stream() puede ser más lento que un bucle más directo y muchas de estas llamadas se han cambiado por motivos de rendimiento.
