dify 1.14.2

🚀 ¿Qué hay de nuevo en v1.14.2?

v1.14.2 es una versión de parche centrada en el fortalecimiento de la seguridad, la confiabilidad del flujo de trabajo y del conocimiento, correcciones de observabilidad, trabajo preliminar de los agentes y ajuste de implementación/tiempo de ejecución después de v1.14.1.

🔐 Seguridad y administración

  • Puntos finales confidenciales con ámbito de inquilino: aislamiento de inquilinos reforzado para puntos finales de configuración de seguimiento de aplicaciones y extracción de texto FilePreview. Gracias @xr843 en #35793 y #35797.
  • Seguridad de las credenciales de la herramienta: restringió las actualizaciones de credenciales de la herramienta integrada predeterminada para los administradores y propietarios del espacio de trabajo, y limpió las credenciales obsoletas de la herramienta del inquilino durante reset-encrypt-key-pair. Gracias @NeatGuyCoding y @xr843 en #36264 y #35843.

🧩 Flujo de trabajo, HITL y tiempo de ejecución de la aplicación

  • Confiabilidad de ejecución del flujo de trabajo: seguimiento restaurado después de la reanudación del flujo de trabajo HITL, seguimiento de devolución de llamada de ejecución de flujo de trabajo mejorado, viajes de ida y vuelta de la base de datos de actualización de mensajes reducidos, recuperaciones de memoria fijas fuera del contexto de Flask y sesiones de búsqueda de archivos base64 cerradas correctamente. Gracias @Blackoutta, @CodingOnStar, @wylswz, @hjlarry y @escape0707 en #36064, #36149, #36213, #36253 y #36308.
  • Pulido de flujo de trabajo y selección de modelo: comportamiento de carga fijo cuando no se selecciona ningún modelo, ajustes preestablecidos de modelo filtrados por parámetros admitidos y controles de diálogo de extensión API mejorados. Gracias @iamjoel y @lyzno1 en #36342, #36339 y #36323.

📚 Datos, RAG y conocimiento

  • Estabilidad de la base de conocimientos: representación fija de pruebas de aciertos de conocimientos, creación de conocimientos vacíos, ordenación de categorías de aplicaciones recomendadas y manejo de valores nulos en la recuperación de detalles de aplicaciones recomendadas. Gracias @FFXN, @laipz8200, @hjlarry y @EvanYao826 en #36106, #36336, #36161 y #36153.
  • RAG y procesamiento de documentos: permitió a los nodos LLM acceder a archivos de conocimiento recuperados, resúmenes de documentos regenerados después de las actualizaciones de API, representación de plantillas de canalización fija y manejo de fallas de obtención de credenciales en canales de RAG con mayor elegancia. Gracias @laipz8200, @EvanYao826, @FFXN y @linw1995 en #36175, #36035, #36168 y #36165.

🎨 Interfaz de usuario web y experiencia del producto

  • Creación e incorporación de aplicaciones: seguimiento de la fuente de creación de la aplicación y del ID de la plantilla, zona horaria e idioma del usuario inicializados desde el navegador, y visualización fija del icono y la descripción de la aplicación web. Gracias @CodingOnStar, @lyzno1 y @JzoNgKVO en #36369, #36170, #36206 y #36209.
  • IU de anotaciones y conjuntos de datos: permitió umbrales de puntuación de respuesta de anotaciones por debajo de 0.8, redirigió a editores de conocimientos no autorizados a conjuntos de datos y corrigió el cambio de nombre de etiquetas sin carga útil de tipo. Gracias @JzoNgKVO, @iamjoel y @lyzno1 en #36337, #36073 y #36182.
  • Migración y pulido de la plataforma UI: se agregaron primitivas Checkbox y CheckboxGroup, se migraron más controles a @langgenius/dify-ui, se mejoraron los diseños de desbordamiento del diálogo y se refinaron las interacciones del flujo de instalación y el avatar de la cuenta. Gracias @lyzno1 y @CodingOnStar en #36271, #36295, #36255, #36302, #36111, #36199, y #36210.

🔎 Observabilidad y rastreo

  • Confiabilidad de rastreo: proveedores de rastreo Langfuse v3 SDK aislados para evitar interferencias entre tareas y se agregó el comportamiento de respaldo de rastreo principal de Phoenix. Gracias @GareArc y @Blackoutta en #36136 y #36290.

⚙️ Implementación, dependencias y experiencia del desarrollador

  • Ajuste de implementación: se actualizó el demonio del complemento a 0.6.1, se aumentó el recuento mínimo de trabajadores predeterminado de GraphEngine y se actualizaron las referencias README de Docker. Gracias @laipz8200, @kenwoodjw y @RiskeyL en #36312, #35650 y #36303.
  • Mantenimiento de backend y CI: se trasladó el análisis estático a Pyrefly, se actualizó Graphon a 0.4.0, se agregaron revisiones de procedencia selectivas y se mejoraron los flujos de trabajo de contratos generados. Gracias @cqjjjzr, @laipz8200 y @hyoban en #36154, #36124, #36340 y #36286.
  • Actualizaciones de dependencia: dependencias de backend y agentes actualizadas, incluidas authlib, ujson, langsmith y urllib3. Gracias @dependabot[bot] en #36112, #36121, #36142 y #36160.

Guía de actualización

[!IMPORTANTE]

  • Esta versión incluye una nueva migración de base de datos para categorías de aplicaciones de Exploración configurables. Ejecute migraciones de bases de datos como parte de la actualización.
  • Docker Las variables de entorno de redacción ahora se dividen en archivos categorizados en docker/envs/**. Si mantiene un docker-compose.yaml o .env personalizado, revise el nuevo diseño y vuelva a aplicar las personalizaciones locales con cuidado.
  • Para implementaciones autohospedadas, se siguen respetando los valores SECRET_KEY configurados explícitamente. Si SECRET_KEY está vacío, Dify ahora genera y conserva una clave de tiempo de ejecución automáticamente.

Docker Redactar implementaciones

  1. Haga una copia de seguridad de sus archivos personalizados docker-compose YAML y env.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Obtenga el código más reciente de la rama o etiqueta de lanzamiento.

    git fetch --tags
git checkout 1.14.2

  3. Detenga el servicio. Ejecute en el directorio docker.

    docker compose down

  4. Haga una copia de seguridad de los datos.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Revise el nuevo diseño del archivo env docker/envs/** y vuelva a aplicar las personalizaciones locales.

  6. Servicios de actualización.

    docker compose up -d

Implementaciones de código fuente

  1. Detenga el servidor API, el trabajador y el servidor frontend web.

  2. Obtenga el código más reciente de la etiqueta de lanzamiento.

    git fetch --tags
git checkout 1.14.2

  3. Actualice las dependencias de Python.

    cd api
uv sync

  4. Ejecute el script de migración.

    uv run flask db upgrade

  5. Reinicie el servidor API, el trabajador y el servidor frontend web.
