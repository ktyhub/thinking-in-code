dify 1.16.0-rc1

Presentamos Dify Agent (Experimental): una nueva experiencia de agente en Dify

[!ADVERTENCIA] Debe proporcionar los servicios de Dify Agent ⚠️solo a usuarios trusted y no maliciosos⚠️.

Como muchos de ustedes saben, el paradigma del agente LLM basado en shell ha supuesto un salto importante en las capacidades de los agentes y ha cambiado nuestra forma de pensar sobre los agentes. Mientras tanto, Skills proporciona una forma estandarizada de empaquetar y distribuir capacidades, lo que facilita la creación de agentes potentes.

Hoy estamos lanzando experimentalmente Dify Agent. Al igual que otros agentes líderes, se ejecuta en un entorno limitado de Linux. Esta versión incluye:

  • Un constructor para crear agentes Dify.

    • Puede crear agentes de Dify a través de la interfaz de usuario: establezca un mensaje base, cargue habilidades y archivos, y conecte herramientas y conocimientos del ecosistema de Dify.
    • También proporcionamos un agente que lo ayuda a crear agentes Dify. A través de la conversación, puede configurar el entorno sandbox de Linux, instalar los paquetes necesarios y crear nuevas habilidades y archivos que su agente Dify puede usar más adelante.

  • Integración de Dify Workflow para Dify Agent

    • Puede utilizar un Agente Dify existente en un flujo de trabajo Dify o crear temporalmente un Agente Dify en línea. Ejecutará la tarea definida por el nodo de flujo de trabajo, generará el resultado requerido y lo pasará al siguiente nodo.

  • Una nueva experiencia de aplicación web

    • El Agente Dify que cree se puede publicar y utilizar como una aplicación web. Si bien la experiencia del usuario sigue siendo familiar, ahora funciona con Dify Agent.

Documentos: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

Limitaciones

Tenga en cuenta que en la versión experimental actual, todos los agentes Dify se ejecutan en el mismo entorno limitado. Esto significa:

  • En circunstancias normales, cada Agente Dify configura su entorno y ejecuta tareas dentro de su propio espacio de trabajo sin interferir con los demás.
  • Sin embargo, con instrucciones simples, cualquier Agente Dify puede leer o interferir con los entornos y datos de otros Agentes Dify, incluidos los datos del usuario.

Se implementará un aislamiento estricto en una versión futura. Por ahora,

[!ADVERTENCIA] Debe proporcionar los servicios de Dify Agent ⚠️solo a usuarios trusted y no maliciosos⚠️.

De manera similar, debido a que Dify Agent aún no está completamente listo, es posible que algunas funciones no estén disponibles para Dify Agent. Por ejemplo, la exportación DSL del flujo de trabajo de Dify no está disponible cuando el flujo de trabajo contiene nodos que hacen referencia al Agente Dify.

Guía de actualización

[!IMPORTANTE]

  • Esta versión incluye nuevas migraciones de bases de datos. Ejecútelos como parte de la actualización.
  • Las variables de entorno cambiaron. Revise la sección Cambios de variables de entorno y actualice su .env en consecuencia.
  • Docker Los archivos de configuración de redacción cambiaron. Si mantiene un docker-compose.yaml personalizado, revise los cambios y vuelva a aplicar las personalizaciones locales con cuidado.

Docker Redactar implementaciones

  1. Haga una copia de seguridad de sus archivos personalizados docker-compose YAML y env. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Obtenga el código más reciente para la versión 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Detenga los servicios (ejecútelos dentro del directorio docker). 
    docker compose down
  4. Haga una copia de seguridad de los datos. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Revise cualquier cambio en el archivo env y vuelva a aplicar las personalizaciones locales.
  6. Servicios de actualización. 
    docker compose up -d

Implementaciones de código fuente

  1. Detenga el servidor API, el trabajador y el servidor frontend web.
  2. Obtenga el código más reciente para la versión 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Actualice las dependencias de Python. 
    cd apiuv sync
  4. Ejecute migraciones de bases de datos. 
    uv run flask db upgrade
  5. Reinicie el servidor API, el trabajador y el servidor frontend web. Para experimentar con la nueva función del agente, también necesita iniciar dify-agent y shellctl. Importante: shellctl no incluye autenticación integrada; por seguridad, se recomienda ejecutarlo dentro de un contenedor.
