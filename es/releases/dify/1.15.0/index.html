Dificar 1.15.0 Release Note

¿Qué ha cambiado?

Mejoras en la experiencia de usuario y la interfaz de usuario

<img width="1920" height="1044" alt="录屏2026-06-25 21 12 33" src="https://github.com/user-attachments/assets/c3ac7394-2ccf-4a66-873a-b7224a16897a" />
  • Aterrizaje/incorporación rediseñados para una experiencia de primera ejecución más sencilla (#37433, #37844, #37800)
  • Navegación más rápida: paleta mejorada "ir a cualquier cosa" y entradas de búsqueda con enfoque automático (#32130, #37175)
  • Eliminaciones más seguras: confirmación one-click antes de eliminar una aplicación (#37263)
  • Editor de flujo de trabajo más limpio con paneles plegables (#37276)
  • Notificaciones más claras: notificaciones consistentes que muestran errores largos completos (#37382, #37581)
  • Más accesible: sugerencias de permisos para complementos, menú de contacto restaurado, enlace para saltar navegación y pulido de enfoque del teclado (#37310, #37774, #37644)

Nuevas funciones

difyctl — controla Dify desde la línea de comando (Docs)

  • difyctl es una línea de comandos client para Dify: ahora puede ejecutar aplicaciones y flujos de trabajo directamente desde su terminal, de modo que los agentes personales, scripts y canalizaciones de CI puedan invocar flujos de trabajo de Dify sin abrir la interfaz de usuario web (#37036)
  • Instálelo en cualquier plataforma (macOS, Linux, Windows) con un solo comando y sin token de acceso: los archivos binarios se publican como versiones públicas con verificación de suma de comprobación (#37036, #37454)
  • Pase variables de entorno de ámbito a las ejecuciones de la herramienta CLI y obtenga mensajes de error más claros y consistentes (incluido el manejo amigable del límite de velocidad) tanto en difyctl como en /openapi/v1 API (#37324, #37285, #37313, #36896)

Ver CoT en Flujo de trabajo y Chatflow y CLI

  • Chat Flow/Workflow ahora puede transmitir el razonamiento del modelo a un panel de "pensamiento" en vivo dedicado mientras mantiene la respuesta final limpia y legible. El razonamiento se conserva, por lo que sigue ahí después de actualizar la página, y el mismo razonamiento es visible en CLI y en las vistas previas de ejecución del flujo de trabajo (#37460, #37828).

Formas más ricas de Human-in-the-Loop

  • Cuando un flujo de trabajo se detiene para pedirle a una persona su opinión, el formulario ahora puede incluir selecciones desplegables y cargas de archivos/varios archivos, no solo texto libre, para que las personas puedan responder con opciones estructuradas y archivos adjuntos (#36322)

Soporte para modelos lentos y de larga duración

  • Los flujos de trabajo ahora pueden usar modelos de generación que tardan mucho en responder (como la generación de imágenes o videos) a través de un mecanismo de sondeo: el nodo espera pacientemente el resultado final en lugar de agotar el tiempo (#37462).

Conocimiento de hojas de cálculo más completas

  • Las imágenes incrustadas en archivos de Excel ahora se extraen durante la importación de conocimientos, por lo que el contenido de la hoja de cálculo que se basa en imágenes (diagramas, capturas de pantalla, cuadros) ya no se pierde (#37104)

Observabilidad más profunda

  • Establezca su propia identificación de sesión de seguimiento para Phoenix de modo que los seguimientos se alineen con las sesiones de su aplicación y siga los pasos de recuperación de documentos en los seguimientos para comprender cómo se produjeron los resultados de RAG (#37056, #37283)

Pulido de creación de flujo de trabajo

  • Un nodo de inicio actualizado deja más claro cómo comienza un flujo de trabajo, y un nodo de salida más inteligente le brinda más control sobre lo que devuelve un flujo de trabajo (#37348, #35511)
  • Errores más amigables cuando una ID de aplicación o espacio de trabajo tiene un formato incorrecto, en lugar de fallas confusas (#37212)

El complemento se instala más rápido en ciertas regiones

  • El demonio del complemento ahora detecta automáticamente su región al inicio y, cuando la conectividad de red a PyPI es deficiente, selecciona automáticamente un espejo de paquete cercano, por lo que la instalación de complementos es más rápida y confiable sin ninguna configuración manual. Aún puedes fijar un espejo específico si lo prefieres (dify-plugin-daemon#750)

Actualizaciones de seguridad

Esta versión soluciona un problema de recorrido de ruta en el reenvío de demonios de complementos (cve-2026-41948).

Corrección de errores

  • HTTP saliente reforzado con tiempos de espera limitados para solicitudes de Firecrawl, Jina, Watercrawl, Nacos y Marketplace, y salida de proxy SSRF predeterminada reforzada (#37638, #37637, #37515, #37444, #37424, #36332)
  • Se corrigieron errores del almacén de vectores Lindorm causados por la actualización opensearch-py (#37862) y la compatibilidad de credenciales de Tongyi (#37942)
  • Caché de credenciales no validada después de la actualización de OAuth (#37630)
  • Se mejoró el manejo de errores de ejecución del flujo de trabajo, se validaron con entusiasmo las conversaciones para evitar que se cuelguen y se evitó que la parada heredada interrumpiera las ejecuciones de GraphEngine (#37919, #37224, #37129)
  • Se resolvió DetachedInstanceError mediante refactorización de gestión de sesión (n.° 37847) e hidratación del estado de implementación estabilizada (n.° 37818).
  • Se corrigió la validación de la longitud de la descripción de la variable de conversación para evitar el truncamiento de varchar(255) (#33038) y se almacenó el chino como Unicode para que la búsqueda funcione (#37446)
  • Numerosas correcciones de pulido de la interfaz de usuario web y accesibilidad/anillo de enfoque.

Mejoras

  • Gestión de sesiones refactorizada en todos los servicios para aceptar db.session explícitamente mediante inyección de dependencia para lograr coherencia (#37639, #37832, #37695, #37694 y relacionados)
  • Escritura modernizada (se eliminaron type: ignore/cast redundantes, se convirtieron ABC a Protocol, se reemplazaron cadenas isinstance con match-case)
  • Se redujo la latencia de inicio del flujo de trabajo para Chatflow (#36773) y se redujo la latencia de finalización del flujo de trabajo para que detener una ejecución surta efecto más rápido (#37106, #37129)
  • Dependencias actualizadas para correcciones CVE (Bleach, PyJWT, starlette, grupo de almacenamiento) (#37860, #37008, #37076, #37861)

Migraciones de bases de datos

Esta versión incluye nuevas migraciones de bases de datos. Ejecute flask db upgrade (o uv run --project api flask db upgrade) después de actualizar el código. Adiciones de esquema notables:

  • Tokens de acceso OAuth (ENABLE_OAUTH_BEARER)
  • Visibilidad de credenciales
  • Tablas de carga de entrada humana y enlace de conversación.
  • Estrategia de actualización automática de complementos con ámbito de categoría (add_plugin_auto_upgrade_category)
  • Estrellas de aplicaciones, marcas de aprendizaje/solo en la nube en aplicaciones recomendadas
  • Tipo de usuario final heredado normalizado

Guía de actualización

Migración de tipo de modelo

[!IMPORTANTE]

Migración única del tipo de modelo heredado para actualizaciones autohospedadas

Si esta implementación se actualizó desde una versión de Dify anterior a 1.15.0 y esta migración aún no se ha aplicado, ejecútela después de la actualización.

Esta migración no está incluida en flask db upgrade. Sin él, los registros de modelos heredados pueden provocar que las solicitudes API relacionadas con el modelo fallen con errores, lo que impide que se carguen o utilicen los modelos afectados.

Haga una copia de seguridad de la base de datos antes de aplicar la migración. El comando se ejecuta en modo de prueba de forma predeterminada; revise el resultado antes de volver a ejecutarlo con --apply. La migración es idempotente y se puede volver a ejecutar de forma segura.

Docker Redactar

Ejecute desde el directorio docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implementación del código fuente

Ejecute desde la raíz del repositorio después de completar flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Después de aplicar la migración, ejecute nuevamente el comando de ejecución en seco. Si no informa actualizaciones o eliminaciones de filas adicionales, reinicie los servicios relevantes y verifique que los modelos existentes se puedan cargar e invocar correctamente.

[!IMPORTANTE]

  • Esta versión incluye nuevas migraciones de bases de datos. Ejecútelos como parte de la actualización.
  • La actualización automática del complemento ahora está configurada por categoría de complemento. Después de ejecutar flask db upgrade, también DEBE ejecutar flask backfill-plugin-auto-upgrade para migrar la configuración de actualización automática de los inquilinos existentes al nuevo modelo con alcance de categoría. Si omite este paso, la configuración de actualización automática del complemento que los usuarios configuraron previamente puede dejar de surtir efecto.
  • Las variables de entorno cambiaron (19 agregadas, 2 eliminadas, 1 modificada). Revise la sección Cambios de variables de entorno y actualice su .env en consecuencia.
  • Docker Los archivos de configuración de redacción cambiaron. Si mantiene un docker-compose.yaml personalizado, revise los cambios y vuelva a aplicar las personalizaciones locales con cuidado.
