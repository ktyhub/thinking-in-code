dify 1.17.0

Nuevas características

Agente: E2B Sandbox, Home Snapshots y Gestión de habilidades

  • Backend del entorno limitado de E2B: la ejecución de código/shell del agente ahora se puede ejecutar en entornos limitados de nube E2B además del entorno limitado local. Seleccione el backend con DIFY_AGENT_RUNTIME_BACKEND; un nuevo docker-compose.e2b.yaml envía la pila E2B, el tráfico E2B se autentica y la plantilla E2B se sincroniza en el momento del lanzamiento (#39480, #39705, #39873, #39996, #40858, #40871, #40891, #40892).
  • Instantáneas de inicio en tiempo de compilación: cuando se aplica (publica) la compilación de un agente, se captura el directorio de inicio de la zona de pruebas del agente (paquetes instalados, archivos preparados, estado de funcionamiento) y las ejecuciones posteriores del agente publicado restauran su directorio de inicio a partir de esa instantánea, de modo que el agente comienza desde el estado exacto del sistema de archivos que tenía en el momento de la compilación. (#39702, #40876, #40996).
  • Gestión de habilidades a nivel de espacio de trabajo: las habilidades son capacidades versionadas y reutilizables empaquetadas con código y definiciones de herramientas que los agentes pueden descubrir e invocar. Un nuevo administrador de habilidades a nivel de espacio de trabajo con ciclo de vida de borrador → publicación → versión se incluye junto con una interfaz de usuario web (lista de habilidades, panel de creación, editor de archivos). (#39675, #39798, #39799, #41180).
  • Compactación del historial según el contexto: las conversaciones largas con los agentes ya no pasan de la ventana de contexto del modelo: Dify resuelve la compactación de niveles y ventanas efectivas de cada modelo (borra primero los resultados de las herramientas antiguas y luego resume el historial anterior) para que las ejecuciones se mantengan dentro del presupuesto sin perder el contexto reciente (#40872).

Variables de entorno LLM reutilizables en flujos de trabajo

  • Defina una configuración de proveedor/modelo/modo/parámetro compartido una vez (por ejemplo, for_summarize, for_research) y haga referencia a ella desde cualquier nodo LLM. Los cambios coordinados del modelo ahora ocurren en un solo lugar en lugar de ir a la deriva nodo por nodo, y las referencias sobreviven a la importación/exportación DSL, fragmentos, canalizaciones RAG y edición colaborativa (#39125).

Aportación humana en bucles e iteraciones

  • Los formularios Human-in-the-loop ahora funcionan dentro de los nodos de bucle e iteración, pausando y reanudando correctamente las actualizaciones de página tanto para las aplicaciones instaladas como para las de depuración, lo que permite los pasos de revisión/aprobación dentro del trabajo repetido (#39243).

Seguimiento unificado neutral del proveedor

  • El seguimiento unificado opcional (OPS_TRACE_UNIFIED_ENABLED) ensambla el árbol de distribución completo entre padres e hijos (flujos de trabajo, flujos de chat, mensajes, nodos, bucles, iteraciones, flujos de trabajo anidados) una vez en el núcleo y delega solo el transporte a adaptadores livianos. Los adaptadores Phoenix y LangSmith se envían primero; deshabilitado de forma predeterminada y totalmente compatible con versiones anteriores (#39451).
  • La nueva GenAI abarca TTFT de LLM de superficie, pasos de ReAct del agente, llamadas a herramientas y nodos de LLM fallidos para una observabilidad más profunda (#39339).

Compatibilidad con Cloudflare Turnstile (CAPTCHA)

  • Desafío Turnstile opcional en el inicio de sesión y el inicio de sesión con código de correo electrónico para proteger los puntos finales de autenticación contra abusos, con claves secretas/de sitio configurables y nombres de host permitidos (#40494).

Azure Key Vault/KMS conectable

  • Introduce una abstracción de proveedor KMS con compatibilidad con Azure Key Vault para el aprovisionamiento, el cifrado y el descifrado de claves, además de la configuración de rotación de claves: un paso hacia las claves de cifrado administradas externamente (#39933).

Búsqueda híbrida y de texto completo vectorial TiDB

  • Las implementaciones de TiDB Vector ahora pueden permitir la recuperación híbrida y de texto completo (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH, desactivado por defecto), utilizando un índice de texto completo multilingüe junto con la búsqueda vectorial (#38112).

Modelo más amplio y manejo de archivos

  • Los nodos y agentes de LLM ahora pueden pasar archivos de imágenes directamente a modelos multimodales, y los archivos adjuntos que no son de visión ya no se eliminan silenciosamente de los chats de agentes (#39848, #40179).
  • La nueva guía de recuperación multimodal ayuda a los usuarios a elegir correctamente los modelos de incrustación para las bases de conocimiento con imágenes (#40566).
  • Audio ASR ahora acepta audio/x-m4a y los tipos de audio MIME se validan con mayor precisión (#40776, #41043).

Ir a Cualquier cosa (⌘K / Ctrl+K)

  • Presione ⌘K (Ctrl+K en Windows/Linux) en cualquier lugar de la consola para abrir la paleta de comandos y saltar a aplicaciones, agentes, habilidades, bases de conocimientos, complementos o nodos de flujo de trabajo, o activar acciones rápidas mediante comandos de barra diagonal. Nuevo en esta versión: se pueden buscar agentes y habilidades, y el sistema de comando de íconos se refactorizó en todos los dominios para lograr coherencia (#40620, #40621, #40646–#40649, #41160).

Otras adiciones

  • Soporte de extracción de documentos ODT (OpenDocument Text) (#39973).
  • Nuevo tipo de parámetro date / date-picker para complementos de herramientas (#36163).
  • Soporte de idioma Lao (lo-LA) (#39474).
  • Tarea de limpieza automática de conversaciones antiguas (ENABLE_CONVERSATION_CLEANUP_TASK) para limitar el crecimiento de datos (#40889-era).
  • Marketplace integrado directamente en las categorías de integración para un descubrimiento más fluido de herramientas/complementos (#40744).

Mejoras

Accesibilidad (pase grande para 11 años)

  • Un conjunto muy grande de cambios hace que la consola sea fácil de usar con el teclado y el lector de pantalla: semántica real de <button> para docenas de controles interactivos, nombres accesibles para acciones de solo íconos (copiar, cerrar, eliminar, menús), encabezados principales en páginas de autenticación/instalación, selectores de miembros/herramientas accesibles mediante teclado y estados ARIA correctos (#40192–#40377 y muchos otros).

Autoría de flujo de trabajo

  • El generador de flujo de trabajo ahora prefiere herramientas ya instaladas y configuradas cuando sugiere nodos, por lo que los constructores recurren a las herramientas que realmente tienen (#40611, #39850).

Estabilidad del flujo de trabajo y del tiempo de ejecución

  • Ejecuciones de flujo de trabajo web reproducibles, estado del lienzo preservado después de las actualizaciones del historial, no más ciclos de procesamiento de actualización y las transmisiones SSE ahora finalizan limpiamente en eventos de terminal (#40010, #40489, #41105, #40042).
  • stop ahora se respeta entre nodos que no son de transmisión y los flujos de trabajo en pausa borran correctamente las señales de cancelación obsoletas (#41090, #40905, #40972).
  • Los valores predeterminados de APP_MAX_EXECUTION_TIME y WORKFLOW_MAX_EXECUTION_TIME aumentaron de 1200 → 3600 para adaptarse a flujos de trabajo de ejecución más prolongada.

Calidad interna

  • Gran migración de pruebas unitarias a modelos ORM reales/sesiones SQLite para una cobertura más confiable, además de una tipificación más sólida en las pruebas migradas (muchas #38xxx–#39xxx). No hay cambios en el comportamiento de cara al usuario.

Mejoras de seguridad

  • Reforzamiento de la autenticación: Desafío de torniquete en los flujos de inicio de sesión/código de correo electrónico, verificación reforzada de código de correo electrónico con límites de intentos y vencimiento de tokens (EMAIL_CODE_LOGIN_MAX_ATTEMPTS, EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES), manejo de dominios de correo electrónico suspendidos y tokens de autorización de agente de corta duración (#40494, #40960, #41004, #40884).
  • Control de acceso/alcance de propiedad: el conjunto de datos, el documento, el RAG, la conversación, la credencial del espacio de trabajo y los recursos OAuth-client ahora están vinculados consistentemente a sus propietarios y al alcance de la aplicación, cerrando varias rutas de acceso no autorizado (#40989, #40888, #40790, #40745, #40893, #40786 y relacionadas).
  • SSRF y refuerzo de salida: las fases de conexión HTTP salientes están limitadas (5 s), los tiempos de espera de ejecución y descarga del agente/enlace son configurables, y el mensaje de error bloqueado por SSRF ahora apunta al problema correcto (#40807, #41027, #40605).

Corrección de errores (seleccionados)

  • Evite eventos workflow_started descartados en secuencias Redis y ejecuciones descartadas/duplicadas de ejecuciones reemplazadas (#40964, #40699).
  • Normalice las marcas de tiempo del flujo de trabajo a UTC ingenuo y conserve las instantáneas/el historial de ejecución para ejecuciones fallidas, canceladas e interrumpidas (#40947, #40876, #40972).
  • Evite el cambio de conversación de chat entre tabulaciones y deje de soltar archivos adjuntos que no sean de visión en el chat del agente (#40709, #40179).
  • Corregir el orden de los mensajes del sistema Qwen/VL fusionando primero los mensajes del sistema (#39136).
  • Se corrigió el mapeo del adaptador Elasticsearch-JA, document_id y VectorType (#40400); Evite los campos vacíos del esquema Bedrock (#40443).
  • Utilice resolución DNS dinámica para todos los flujos ascendentes de nginx (#39155); preservar el tamaño de bytes UTF-8 para cargas de texto (#40034).
  • Numerosas correcciones de aplicaciones web/UI: restauración de envíos de formularios de contraseñas y códigos de correo electrónico, desbordamiento de inicio de sesión móvil, apilamiento de notificaciones, espaciado del selector de modelos (#40227, #40222, #40921, #40970, #8d612895).

Guía de actualización

Migración de tipo de modelo

[!IMPORTANTE]

Migración única del tipo de modelo heredado para actualizaciones autohospedadas

Si esta implementación se actualizó desde una versión de Dify anterior a 1.15.0 y esta migración aún no se ha aplicado, ejecútela después de la actualización.

Esta migración no está incluida en flask db upgrade. Sin él, los registros de modelos heredados pueden provocar que las solicitudes API relacionadas con el modelo fallen con errores, lo que impide que se carguen o utilicen los modelos afectados.

Haga una copia de seguridad de la base de datos antes de aplicar la migración. El comando se ejecuta en modo de prueba de forma predeterminada; revise el resultado antes de volver a ejecutarlo con --apply. La migración es idempotente y se puede volver a ejecutar de forma segura.

Docker Redactar

Ejecute desde el directorio docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implementación del código fuente

Ejecute desde la raíz del repositorio después de completar flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Después de aplicar la migración, ejecute nuevamente el comando de ejecución en seco. Si no informa actualizaciones o eliminaciones de filas adicionales, reinicie los servicios relevantes y verifique que los modelos existentes se puedan cargar e invocar correctamente.

[!IMPORTANTE]

  • Esta versión incluye nuevas migraciones de bases de datos; ejecútelas como parte de la actualización.
  • Las variables de entorno cambiaron sustancialmente (se agregaron muchas, variable de edición renombrada EDITION → DEPLOYMENT_EDITION, varios valores predeterminados cambiaron). Revise la sección Cambios de variables de entorno y actualice su .env en consecuencia. En particular, cambie el nombre de EDITION a DEPLOYMENT_EDITION si lo configura.
  • Docker Se cambió la configuración de redacción y se agregó un nuevo docker-compose.e2b.yaml. Si mantiene un docker-compose.yaml personalizado, vuelva a aplicar las personalizaciones locales con cuidado.
  • La migración add_conversation_cleanup_index crea un índice sobre los datos existentes, lo que podría tardar más en ejecutarse si la tabla conversations es grande.

  2. Obtenga el código más reciente: 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Actualice las dependencias de Python: 
    cd apiuv sync
  4. Ejecute migraciones: 
    uv run flask db upgrade
  5. Reconstruya/reinicie la interfaz web, luego reinicie el servidor y el trabajador API.
