dify 1.14.1

🚀 ¿Qué hay de nuevo en v1.14.1?

v1.14.1 es una versión de parche centrada en el refuerzo de la seguridad, el flujo de trabajo y la estabilidad de la base de conocimientos, la limpieza de la implementación y la migración continua de la plataforma de interfaz de usuario después de v1.14.0.

🔐 Seguridad

  • Reforzamiento de SECRET_KEY autohospedado: las implementaciones de Docker ya no dependen de una clave pública predeterminada. Cuando SECRET_KEY se deja vacío, el API genera y conserva una clave de tiempo de ejecución a través del backend de almacenamiento configurado, mientras que las claves configuradas explícitamente continúan funcionando como antes. Gracias @laipz8200 en #36049.
  • Protección de endpoints de métricas internas: /threads y /db-pool-stat están reforzados para evitar la exposición no autenticada del tiempo de ejecución interno y los detalles del grupo de bases de datos. Gracias @orbisai0security en #35665.
  • Aislamiento de cuenta y herramienta: se solucionó un problema de IDOR en GET /account/avatar y se aplicó la limpieza de credenciales predeterminadas de la herramienta integrada al inquilino actual. Gracias @NeatGuyCoding y @GareArc en #35771 y #35887.
  • Seguridad de dependencia: se actualizó LiteLLM para CVE-2026-42208 y se actualizaron varias dependencias de backend, incluidos los paquetes urllib3, gunicorn, gitpython, mako, Google SDK, bibliotecas de almacenamiento y paquetes exportadores OpenTelemetry. Gracias @crazywoola en #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017 y #36050.

🧩 Flujo de trabajo, HITL y tiempo de ejecución de la aplicación

  • Estabilidad del flujo de trabajo: se restauró la carga de la versión del flujo de trabajo a través del backend API, se corrigió el sondeo de usuarios en línea para listas de aplicaciones grandes, se evitaron los bucles de observadores de cambio de tamaño de vista previa y se evitaron colisiones de modelos de esquema en flujos de trabajo de prueba. Gracias @hjlarry y @lyzno1 en #35817, #35786, #35936 y #36061.
  • Pulido de creación de flujo de trabajo: comportamiento fijo del selector de referencia de variable para subvariables, desbordamiento de título de nodo de flujo de trabajo, ventanas emergentes de operador de condición, semántica de lista de verificación de flujo de trabajo y selección de campo de filtro de metadatos de KB. Gracias @iamjoel, @hjlarry, @lyzno1 y @shawny011717 en #35732, #35740, #35828, #36006 y #34149.
  • Corrección de la ejecución del flujo de trabajo: tipos de variables de entrada de ejecución única conservados, validación fija de structured_output_enabled, manejo fijo de URL de vista previa de archivos en la visualización de salida del nodo y herramientas de selección de modelos de complementos desbloqueadas en flujos de trabajo v1.14.0. Gracias @Jingyi-Dify, @fatelei, @shawny011717 y @sawyer-shi en #35710, #35747, #34150 y #35794.
  • Aportación humana: valores de acción seleccionados expuestos para flujos humanos en el circuito. Gracias @Blackoutta en #35451.
  • Clasificador de preguntas: se agregaron etiquetas de clase editables. Gracias @Blackoutta en #35430.

📚 Datos, RAG y conocimiento

  • Representación de imágenes de la base de conocimientos: se corrigieron fallas en la representación de imágenes en la base de conocimientos. Gracias @FFXN en #35914.
  • Indexación de documentos: omita los documentos vacíos antes de incrustar vectores y valide las técnicas de indexación de texto faltantes. Gracias @princepal9120 y @juyua9 en #35763 y #35941.
  • Deduplicación RAG: use doc_id como clave de deduplicación en todos los proveedores, no solo en los proveedores alojados en Dify. Gracias @ki3nd en #35759.
  • Filtros de metadatos del conjunto de datos: conserva los filtros de metadatos del conjunto de datos en las rutas API y corrige la selección del campo del filtro de metadatos de KB. Gracias @princepal9120 y @shawny011717 en #35700 y #34149.
  • Manejo de nombres de archivos de carga: limpie los nombres de archivos de carga analizados desde las URL y evite puntos duplicados al estandarizar las extensiones de archivos de fuentes de datos. Gracias @jonathanchang31 y @Beandon13 en #35706 y #35808.

🎨 Interfaz de usuario web y sistema de diseño

  • Migración de la interfaz de usuario de Dify: migración continua desde superposiciones heredadas, información sobre herramientas, cajones, selecciones, etiquetas y selectores de búsqueda a primitivas @langgenius/dify-ui, incluida la nueva compatibilidad con cajones, pestañas, grupos de alternancia, autocompletar y cuadros combinados.   • Confiabilidad de superposición y navegación: la navegación de la aplicación restaurada crea interacción de submenú, visualización desplegable del espacio de trabajo de transferencia fija, control de superposición normalizado, migración de CSS Tailwind v4 alineada, nonce CSP reenviado al script del tema e íconos desplegables de filtro de etiquetas alineados.   • Flujos de lanzamiento y editor: manejo mejorado del cuadro de diálogo de confirmación del editor y corrección de copia no coincidente en descripciones de lanzamiento de aplicaciones web precargadas. Gracias @CodingOnStar y @iamjoel en #35701 y #35964.
  • Comportamiento de audio y transcripción: reanuda explícitamente AudioContext y reproduce audio en la primera carga TTS, y pasa end_user.external_user_id correctamente para transcribir ASR. Gracias @ki3nd en #35901 y #35898.

Guía de actualización

Notas importantes

  • Esta versión incluye una nueva migración de base de datos para categorías de aplicaciones de Exploración configurables. Ejecute migraciones de bases de datos como parte de la actualización.
  • Docker Las variables de entorno de redacción ahora se dividen en archivos categorizados en docker/envs/**. Si mantiene un docker-compose.yaml o .env personalizado, revise el nuevo diseño y vuelva a aplicar las personalizaciones locales con cuidado.
  • Para implementaciones autohospedadas, se siguen respetando los valores SECRET_KEY configurados explícitamente. Si SECRET_KEY está vacío, Dify ahora genera y conserva una clave de tiempo de ejecución automáticamente.

Docker Redactar implementaciones

  1. Haga una copia de seguridad de sus archivos personalizados docker-compose YAML y env.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Obtenga el código más reciente de la rama o etiqueta de lanzamiento.

    git fetch --tags
git checkout 1.14.1

  3. Detenga el servicio. Ejecute en el directorio docker.

    docker compose down

  4. Haga una copia de seguridad de los datos.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Revise el nuevo diseño del archivo env docker/envs/** y vuelva a aplicar las personalizaciones locales.

  6. Servicios de actualización.

    docker compose up -d

Implementaciones de código fuente

  1. Detenga el servidor API, el trabajador y el servidor frontend web.

  2. Obtenga el código más reciente de la etiqueta de lanzamiento.

    git fetch --tags
git checkout 1.14.1

  3. Actualice las dependencias de Python.

    cd api
uv sync

  4. Ejecute el script de migración.

    uv run flask db upgrade

  5. Reinicie el servidor API, el trabajador y el servidor frontend web.
