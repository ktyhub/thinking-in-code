daily_stock_analysis v3.19.0

análisis_de_stock_diario v3.19.0

Nuevas funciones

  • Se implementó el enlace mínimo #1391 Fase 1 para ejecutar el diagnóstico: la tarea/SSE agrega trace_id y registra instantáneas de ProviderRun del mercado diarias y en tiempo real.
  • El centro de alarmas agrega reglas estructuradas de semáforo a gran escala P7, admite market_light_status y market_light_score_drop y reutiliza trabajadores existentes, historial de activación, notificaciones y enlaces de enfriamiento.
  • Implementado #1391 Resumen de diagnóstico de ejecución de fase 2: genera RunDiagnosticSummary legible por el usuario, proporcionando diagnóstico de informe histórico API y copia de texto no sensible.
  • Implementación #1391 Fase 3 de visibilidad de diagnóstico de ejecución: los detalles del informe y los paneles de tareas están contraídos de forma predeterminada para mostrar el estado de ejecución, el seguimiento y la información de solución de problemas replicable; el backend proporciona relleno de enlaces históricos a través de api/v1/history/{record_id}/diagnostics y context_snapshot.diagnostics.
  • Se agregó el contrato interno de AnalysisContextPack P1 y las pruebas de serialización insensibilizadas.
  • Se agregó el constructor AnalysisContextPack P2 para ensamblar paquetes de contexto internos a partir de artefactos existentes en canales de análisis comunes.
  • Wengu ha agregado compresión de contexto de conversación visible que está desactivada de forma predeterminada, admite cambio web, ajuste preestablecido avanzado del agente, resumen continuo y protección de texto original de ronda reciente, lo que reduce el consumo de tokens de sesiones largas.
  • El índice de autocompletar de stock admite actualización remota y caché desde GitHub principal a local de forma predeterminada. Cuando falla la entrada del análisis Web/CLI, se degradará automáticamente al índice incorporado, lo que reducirá la probabilidad de que la abreviatura anterior contamine el análisis después de la decapitación y el cambio de nombre.
  • El análisis ordinario y el indicador de tiempo de ejecución del agente están conectados al resumen de baja sensibilidad de AnalysisContextPack para mantener la compatibilidad con el historial/API/salida web.

Mejoras

  • scripts/fetch_tushare_stock_list.py puede rellenar y corregir nombres con el prefijo XD/XR/DR/N/C en acciones A para uso predeterminado en el proceso de actualización de finalización automática.
  • La página de enrutamiento web se cambia para cargar bajo demanda, se reduce el tamaño del primer paquete y se agrega un mensaje de recuperación para fallas en la carga de la ruta.
  • El cajón de Markdown de informes completos web cambió para cargarse bajo demanda.
  • Se agregaron líneas de base de inferencia de la fase de mercado y se aclaró la semántica de los días previos a la comercialización, dentro del mercado, pausa para el almuerzo, cerca del cierre, después de la comercialización y sin negociación.
  • Se agregaron pruebas de degradación y construcción del contexto de la etapa del mercado en ejecución.
  • La configuración de la página de configuración ayuda a completar gradualmente la redacción bilingüe en chino e inglés de los campos de visualización/configurables reales de la página de configuración web, que cubren el Agente, las pruebas retrospectivas, los informes, el enrutamiento de notificaciones, el tiempo de ejecución del sistema, el legado de IA, las fuentes de datos y la configuración avanzada de notificaciones.
  • P2-min: LLM Prompt inyecta contexto de etapa de mercado.

Arreglar

  • La generación del índice de autocompletado de acciones fallará directamente cuando falte pypinyin para evitar escribir índices degradados con campos pinyin faltantes.
  • Normalizar el volumen de operaciones de mercado en tiempo real de Tencent como calibre de acciones para evitar la amplificación de los múltiplos de cambio de energía del volumen y los informes de análisis engañosos.
  • La implementación predeterminada de Docker elimina el montaje de archivo único de .env para evitar que Device or resource busy se active cuando os.replace actualiza el punto de montaje cuando la WebUI guarda la configuración.
  • Convergencia #1391 Fase 0 Límite de propiedad del código compartido A: completar la coherencia de propiedad de los escenarios de prefijo SH/SZ y aclarar el alcance de esta ronda de reparaciones para data_provider/baostock_fetcher.py, data_provider/pytdx_fetcher.py y data_provider/tushare_fetcher.py.
  • Se corrigió la conversión de formato interno de fuentes de datos alternativas como Baostock cuando STOCK_LIST usa códigos de acciones A simples, manteniendo la configuración del usuario para continuar usando números de acciones de 6 dígitos.
  • Las actualizaciones automáticas del escritorio de Windows se cambiarán para ejecutar el instalador de forma silenciosa después de que el usuario confirme el reinicio de la instalación y limpiar las referencias del proceso después de detener el backend integrado, lo que reduce la probabilidad de que el instalador indique "No se puede cerrar el análisis de stock diario".
  • El escritorio macOS migra la configuración del tiempo de ejecución al directorio de datos del usuario y migra .env, la base de datos y los registros mientras los archivos del antiguo paquete .app aún son accesibles, para evitar la reconfiguración después de reemplazos y actualizaciones posteriores.
  • Se restauró la extracción de secciones asociadas y campos de enlace de sección en instantáneas compatibles históricas/Agente y se solucionó el problema de regresión de la falta de "vínculo de sección" en el nuevo informe de la página de inicio.
  • Se corrigió el nombre del campo de la alarma heredada JSON y la descripción semántica de entrega del período de silencio en la ayuda de configuración web.
  • Se solucionó el problema por el cual faltaban el título de configuración, la descripción y las opciones desplegables clave en las áreas de fuente de datos, notificación, sistema y agente de la página de configuración web en chino.
  • Se solucionó un problema por el cual el estado de Agente/tarea de análisis en progreso podía permanecer después de cambiar de sesión y volver a conectarse a la tarea de la página de inicio.
  • Se agregó una subpista de seguimiento compatible con el proveedor para un solo agente y se conservaron reasoning_content y los materiales del protocolo de herramientas del pensamiento DeepSeek V4 + llamada de herramientas entre ruedas.
  • Se agregó un tiempo de espera a nivel de llamada a la interfaz ascendente histórica de acciones A de Akshare Sina/Tencent y se completó la prueba de regresión de enrutamiento del código de acciones de Shanghai Tushare 605xxx para evitar que el análisis programado se cuelgue debido a la falta de respuesta de la fuente de datos.
  • Elevar el límite inferior de dependencia de exchange-calendars a 4.13.0 para evitar fallas en el análisis debido a la falla de la unidad Timedelta T al importar el calendario comercial en el entorno pandas 3.
  • Los resultados del análisis activados por comandos interactivos (conversaciones de DingTalk, conversaciones de Feishu, Telegram) solo se devuelven a la conversación de origen y ya no se transmiten simultáneamente a canales de notificación estáticos.
  • Adaptado a la autenticación Longbridge OAuth 2.0 y recuperación de caché de token para evitar que la fuente de datos de Longbridge se juzgue erróneamente como no configurada cuando el nuevo backend no tiene un token de acceso heredado.
  • La ruta Longbridge OAuth registra explícitamente las degradaciones cuando el SDK actual no es compatible con OAuthBuilder/Config.from_oauth para evitar fallas de compilación cuando Linux/Docker solo puede instalar SDK anterior.
  • Compatible con el escenario en el que la línea diaria de YFinance devuelve un índice de fecha sin nombre, para evitar la interrupción del retroceso diario de las acciones estadounidenses causada por la falta de la columna date después de la estandarización.

Documentación

  • Se agregó el documento de contrato de diagnóstico de ejecución de fase 0 n.° 1391 para aclarar trace_id, resumen de diagnóstico, rango de enlaces críticos y límites de desensibilización/apertura fallida/retención.
  • Complete la documentación y las instrucciones de configuración de Alarm Center P8 para aclarar los límites entre JSON heredado, reglas avanzadas, acciones Web/API, Docker, GitHub y escritorio.
  • Tenga en cuenta que esta solución de escritorio solo cubre el enlace de instalación de la actualización de Windows NSIS y la limpieza del ciclo de vida del proceso back-end; la semántica de limpieza del tiempo de ejecución del modelo/guardado del elemento de configuración no se modifica. Elimine los cambios de docker/Dockerfile npm registry que se introdujeron por error anteriormente y restablezca la separación de responsabilidades entre las compilaciones de implementación y las reparaciones de actualizaciones.
  • Se agregó el inventario de contexto de AnalysisContextPack P0 para aclarar el estado de calidad del campo, el mapeo de estado existente y los límites del paquete de la primera versión.
  • Aclarar que la alarma de detección estructurada en #1391 Fase 2 es una señal de migración sin configuración: los valores ilegales de agent_max_steps/agent_orchestrator_timeout_s volverán a los valores predeterminados y generarán alarmas de registro. El nuevo enlace de diagnóstico solo agrega campos de lectura y escritura context_snapshot/RunDiagnosticSummary, y no reescribe la semántica de migración de configuración o enrutamiento de canales litellm_model, agent_litellm_model, openai_base_url, LLM.
  • Descripción complementaria de compatibilidad de la fase 3 n.° 1391: registrar la persistencia del diagnóstico de backend, los límites de cambio de enlaces de reescritura de consultas y notificaciones históricas y las estrategias de reversión, y completar los requisitos de verificación del nivel de acceso de backend.
