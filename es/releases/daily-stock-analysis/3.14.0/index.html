daily_stock_analysis v3.14.0

Menor Publicado26 abr 2026 FuenteZhuLinsen/daily_stock_analysis original en inglés

análisis_de_stock_diario v3.14.0

Aspectos destacados de la versión

  • 📊 La revisión del mercado grande se actualiza a una estructura de banco de trabajo fuera de horario: la revisión de acciones A tiene resultados fijos de la temperatura del mercado, detalles del índice, tabla superior del sector, catalizador de noticias, plan comercial de mañana y advertencia de riesgo, lo que reduce la duplicación y el vacío de la revisión de texto puro.
  • 🖥️ Recordatorio de actualización de la nueva versión de GitHub en el escritorio: el escritorio de Windows/macOS detectará automáticamente la nueva versión después del inicio. También puede verificar manualmente y saltar a la página de descarga desde la página de configuración.
  • 🤖 La carga de datos del Pipeline Agent se ha reducido considerablemente en ruido: la herramienta K-line se cambia a DB-first y precalienta 240 días de datos históricos para evitar solicitudes HTTP repetidas para el mismo stock.
  • 🐳 Organización del enlace de lanzamiento Docker: el flujo de trabajo del lanzamiento converge en dos caminos: lanzamiento oficial y reedición manual. El nombre oficial de la imagen del Docker Hub está unificado a zhulinsen/daily_stock_analysis.
  • 🔧 Mejora de la configuración del canal LLM y DeepSeek V4: el análisis programado de acciones GitHub completa la transmisión transparente de variables multicanal, y los valores predeterminados y ejemplos del canal oficial de DeepSeek se sincronizan con V4.
  • 🧩 Verificación de la coherencia de los recursos estáticos del escritorio: tanto el enlace de empaquetado como el tiempo de ejecución pueden detectar discrepancias en los recursos estáticos antes, lo que reduce el costo de la resolución de problemas de pantalla blanca para los paquetes de lanzamiento.

Nuevas funciones

  • 🏠 Nueva entrada de reanálisis en el área de informe histórico de la página de inicio web: admite rehacer el análisis de la misma acción en la misma fecha según el mensaje original.
  • 🖥️ Recordatorio de actualización de la nueva versión de GitHub en el escritorio de Windows/macOS: detecta automáticamente la nueva versión después del inicio y admite la verificación manual desde la página de configuración para saltar a la página de descarga.

Mejoras

  • 📊 El informe de revisión del mercado de acciones A se ha cambiado a un formato estructurado de banco de trabajo fuera de horario: salida fija de la temperatura del mercado, detalles del índice, tabla principal del sector, catalizador de noticias y plan comercial de mañana.
  • 🐳 Convergencia del flujo de trabajo de lanzamiento de Docker: distingue más claramente entre los enlaces de lanzamiento oficial y de reedición manual, y unifica el nombre de la imagen oficial del centro Docker como zhulinsen/daily_stock_analysis.
  • 🤖 La herramienta diaria del agente da prioridad a la reutilización del caché local - Al mismo tiempo, conserva la información diaria y de noticias recién obtenida para reducir las llamadas repetidas a fuentes de datos.

Arreglar

  • 🤖 Primera carga de la base de datos de la herramienta Pipeline Agent K-line: get_daily_history / analyze_trend / calculate_ma / get_volume_analysis / analyze_pattern cambió para leer la base de datos local primero, eliminando 9x5 = 45 solicitudes HTTP repetidas para el mismo stock (correcciones n.° 1066).
  • 🤖 Pipeline Agent precalienta el historial de K-line de 240 días en la base de datos a pedido antes de la ejecución: en circunstancias normales, las llamadas a la herramienta K-line no requieren solicitudes de red repetidas.
  • 🕒 Congele target_date y transmítalo de forma transparente al hilo de la herramienta Pipeline Agent K-line a través de ContextVar: elimine la deriva del tiempo a través de los límites de cierre.
  • 🪟 Reparación de codificación de copia de registro de backend de escritorio de Windows: se prefiere UTF-8 al copiar stdout/stderr y es compatible con la página de códigos local para evitar registros chinos confusos.
  • ⚙️ El flujo de trabajo de análisis diario de acciones GitHub completa la transmisión transparente de variables del canal LLM: admite LLM_CHANNELS, multiclave y LLM_<NAME>_* de uso común para evitar que las configuraciones multimodelo disponibles localmente se invaliden en las tareas programadas en la nube (correcciones n.° 1063, n.° 872).
  • 📈 La interfaz de detalles del informe histórico corrige el valor change_pct: utilice is None para juzgar y evitar descartar 0.0 (mercado plano) como valor faltante, eliminar el resultado final incorrecto de change_60d y volver al campo de mercado original en tiempo real cuando falte (correcciones n.º 1084).
  • 🔧 Los ajustes preestablecidos del canal oficial de DeepSeek y las configuraciones de muestra están sincronizados con V4: conserva el valor predeterminado heredado de deepseek-chat y agrega un mensaje de abandono, y también corrige el problema por el cual la selección de tiempo de ejecución anterior después del descubrimiento del modelo hace que falle el guardado (Correcciones #1108, #1109).
  • 🧩 Nueva verificación de coherencia de recursos estáticos para enlaces de paquetes de escritorio: scripts/check_static_assets.py verificará si los recursos a los que hace referencia index.html realmente existen en los productos fuente static/ y PyInstaller. El tiempo de ejecución también escribirá registros claros en caso de discrepancias para evitar que vuelva a aparecer la pantalla blanca después de abrir el paquete de versión (Refs #1064 / #1065 / #1050).
  • 🧩 El backend /assets/* se cambia a alojamiento de enrutamiento explícito: cuando falta el recurso, se devuelve text/javascript / text/css 404 que coincide con la extensión solicitada, lo que reduce la solución de problemas engañosa causada por la respuesta de error predeterminada JSON (Refs #1064).
  • 🌙 kimi-k2.6 usa automáticamente una temperatura fija — temperature=1.0 se usa automáticamente cuando el análisis principal, la revisión de discos grandes y el Agente llaman al modelo para evitar que el modelo rechace la solicitud de temperatura predeterminada (Correcciones #1102).

Documentación

  • 🐳 Instrucciones oficiales complementarias de uso de la imagen Docker: se agregaron instrucciones para la extracción de imágenes, el uso de docker run y el mapeo del directorio de datos/.env, que ya no cubren solo la ruta de implementación de Compose.
  • 📨 Corrección del ejemplo de Webhook del robot personalizado de Feishu: el ejemplo en feishu_sender.py se cambia a la tarjeta interactiva JSON y se complementa el tutorial de configuración del activador de Webhook automatizado de Feishu.
  • 📚 Optimice la estructura README raíz: conserve las características funcionales a nivel de página de inicio, la pila de tecnología, el inicio rápido, el efecto push, la web, el agente, el patrocinador y la entrada de fuentes de noticias, cierre la configuración detallada, la disciplina de transacciones y la semántica fundamental de la guía completa, y apunte la insignia Docker a la página espejo oficial.
  • 🌐 Sincronice la estructura de entrada simplificada del README en inglés y chino tradicional y complete el uso de LLM API y las instrucciones de gestión de puestos en la guía completa.
  • 🤝 Ajuste las reglas de mantenimiento del archivo README en las plantillas de relaciones públicas y colaboración con IA: deje claro que el archivo README no se actualizará a menos que sea necesario y que se dará prioridad a los detalles en documentos especiales.

Prueba

  • 🧪 Estabilizar el comportamiento del código auxiliar de LiteLLM para pruebas relacionadas con la revisión del mercado: evite que LiteLLM instalado localmente afecte las pruebas unitarias de revisión del mercado cuando cambia el orden de recopilación de pruebas.
  • 🧪 pytest omite el directorio dependiente del front-end de forma predeterminada: cuando apps/dsa-web/node_modules existe localmente, la prueba del back-end ya no lo escaneará de forma recursiva para evitar que directorios irrelevantes ralenticen la puerta antes del lanzamiento.
