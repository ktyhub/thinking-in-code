#Moby docker-v29.9.0

##29.9.0

Para obtener una lista completa de las solicitudes de extracción y los cambios en esta versión, consulte los hitos relevantes de GitHub:

  • hito docker/cli, 29.9.0
  • moby/moby, hito 29.9.0

Seguridad

La actualización del tiempo de ejecución de Go corrige las siguientes vulnerabilidades de seguridad en el motor Docker:

  • CVE-2026-97032: Un HTTP/2 client podría bloquear el demonio al cambiar el tamaño de la tabla de encabezado HPACK al enviar solicitudes. golang/go#81867
  • CVE-2026-78659: Un HTTP/2 client podría agotar la memoria del demonio al declarar una gran cantidad de campos en un encabezado Trailer, evitando los límites de tamaño del encabezado. golang/go#81857
  • CVE-2026-78663: Un HTTP/2 client podría eludir el límite de control de flujo a nivel de conexión restableciendo los flujos, lo que hace que el demonio almacene en el buffer más datos de solicitud de los que permite el límite. golang/go#81743
  • CVE-2026-78669: Un HTTP/2 client podría provocar un uso excesivo de la CPU del demonio al abrir muchas secuencias y cambiar repetidamente el tamaño de la ventana inicial. golang/go#81742
  • CVE-2026-56857: En Windows, el demonio podría crear un directorio fuera de su raíz de datos si alguien con acceso de escritura a la raíz de datos hubiera colocado una unión allí. golang/go#81739

La actualización golang.org/x/net a v0.60.0 aplica las mismas correcciones HTTP/2 al punto final obsoleto /grpc y al servidor gRPC que BuildKit ejecuta para contenedores frontend, como imágenes a las que hace referencia una directiva # syntax=.

Corrección de errores y mejoras

  • almacén de imágenes en contenedor: agregue la función de demonio lazy-pull para controlar si docker pull omite la descarga del contenido de la capa que el snapshotter ya proporciona. Las extracciones diferidas están habilitadas de forma predeterminada para los creadores de instantáneas remotos conocidos (nydus, overlaybd, soci, stargz). moby/moby#53877
  • Almacén de imágenes en contenedores: se corrigieron extracciones que omitían los blobs de capas requeridos cuando ya existen capas desempaquetadas, lo que deja las imágenes ejecutables pero incompletas para exportar o enviar. moby/moby#53615
  • Se corrigió docker container create --name que informaba un error de validación engañoso que mencionaba caracteres no válidos en lugar de una longitud de nombre no válida. moby/moby#53484
  • Se corrigió una fuga de conexión al socket RootlessKit API en cada solicitud GET /version en modo sin raíz. moby/moby#53836
  • Mejorar la limpieza de registros y cancelaciones de servicios de Windows, lo que incluye hacer que la cancelación de registros de servicios (--unregister-service) sea idempotente. moby/moby#53845

Actualizaciones de embalaje

  • Actualice BuildKit a v0.34.0. moby/moby#53882
  • Actualice el tiempo de ejecución de Go a 1.26.9. docker/cli#7363
  • Actualización de contenedores (binarios estáticos) a v2.4.1. moby/moby#53773

Redes

  • Permitir el descubrimiento de vecinos IPv6 entre contenedores en una red puente con la comunicación entre contenedores deshabilitada, coincidiendo con el comportamiento IPv4 existente. moby/moby#53723
  • Se corrigió que docker ps y GET /containers/json omitieran los puertos publicados para redes que usan el modo de puerta de enlace enrutada. moby/moby#53693
  • Se corrigió un error por el cual un demonio reiniciado podía eliminarse del descubrimiento de servicios y el equilibrio de carga de un par hasta que se volviera a unir al grupo de chismes. moby/moby#53688
  • Se corrigió que un puerto publicado fuera inaccesible desde otro contenedor en la misma red cuando la comunicación entre contenedores está deshabilitada, incluidos los servicios Swarm publicados a través de la malla de enrutamiento. moby/moby#53723
  • Se solucionó un problema por el cual los errores al programar el kernel para cifrar el plano de datos de la red superpuesta podían, en algunas circunstancias, provocar que el tráfico de la red superpuesta cifrada a algunos nodos se transmitiera en texto sin cifrar. Como el par receptor descartaría paquetes de texto sin cifrar para redes superpuestas cifradas como falsificadas, la pérdida de confidencialidad se limita a flujos unidireccionales (por ejemplo, consultas DNS UDP) e intentos de protocolo de enlace que nunca proceden (por ejemplo, TCP SYN). moby/moby#53420
  • Se corrigió la conexión de contenedores restaurados en vivo con una asignación host-gateway implícita a redes adicionales. moby/moby#53093
  • Se corrigió que los pares superpuestos se volvieran inalcanzables después de que un nodo se reincorpora al clúster o se vuelve a implementar un servicio, cuando el dispositivo VXLAN ya había aprendido una entrada FDB dinámica para el par. moby/moby#53663
  • Se corrigió el rechazo de tareas de Swarm en redes superpuestas cuando el demonio no puede escribir en /var/lib/docker. moby/moby#53848
  • Los puertos de servicio Swarm publicados son accesibles en las direcciones IPv6 del host cuando el proxy del área de usuario está habilitado. Por cierto, un cambio introducido en v29.8.0 habilitó esta funcionalidad; es una característica probada y compatible a partir de v29.9.0. moby/moby#53727
  • Liberar las asociaciones y políticas de seguridad IPsec de un nodo cuando el último contenedor abandona una red superpuesta cifrada, en lugar de filtrarlas hasta que se reinicie el demonio. moby/moby#53420
  • Restaurar la lógica para eliminar la cadena de iptables vacía DOCKER-INGRESS y la regla FORWARD que salta a ella, dejada por el motor Docker, 28.0.0 y anteriores. moby/moby#53825

Sin raíces

  • Actualización RootlessKit (3.2.0). moby/moby#53607
