#Moby docker-v29.10.0

##29.10.0

Para obtener una lista completa de las solicitudes de extracción y los cambios en esta versión, consulte los hitos relevantes de GitHub:

  • Hito docker/cli, 29.10.0
  • moby/moby, hito 29.10.0

⚠️ Posible cambio importante: conexiones de registro local

Si configura explícitamente insecure-registries en daemon.json o usa --insecure-registry, el motor Docker ya no trata automáticamente las direcciones de loopback (127.0.0.0/8 y ::1/128) como registros inseguros.

[!ADVERTENCIA] Después de la actualización, las extracciones y envíos a registros locales que utilizan certificados HTTP o TLS untrusted pueden fallar a menos que esos registros se incluyan explícitamente en su configuración de registro inseguro. Configure TLS con un certificado trusted o agregue solo las direcciones de registro locales requeridas, como localhost:5000, a su configuración de registro insegura existente.

Cuando se omite insecure-registries, los registros de bucle invertido permanecen inseguros de forma predeterminada. Configurar "insecure-registries": [] en daemon.json deshabilita todos los registros inseguros predeterminados. moby/moby#53868

🧻 La especificación del motor API pasa a OpenAPI 3.2

La especificación Engine API ahora usa OpenAPI 3.2 como formato fuente, en api/openapi.yaml. Una especificación Swagger 2.0 generada a partir de él todavía está publicada para herramientas existentes, en api/swagger.yaml. Para la transición, esta versión también incluye una copia de Swagger 2.0 fijada a API v1.57, en api/docs/v1.57-swagger.yaml. Las versiones futuras de API no obtendrán una copia de Swagger 2.0 por versión, por lo tanto, actualice las herramientas que dependen de estos archivos para usar las especificaciones OpenAPI 3.2. moby/moby#53630

📦 Paquetes para AlmaLinux, Oracle Linux y Rocky Linux

Los paquetes del motor Docker están disponibles para AlmaLinux, Oracle Linux y Rocky Linux. Para obtener instrucciones de instalación, consulte AlmaLinux, Oracle Linux y Rocky Linux.

Nuevo

  • Agregue soporte experimental para trabajos: ejecute cargas de trabajo únicas y programadas cron administradas de forma nativa por el demonio, como una extensión incorporada habilitada con --enable-extension org.mobyproject.jobs.v0. moby/moby#53485
  • Agregue soporte para personalizar el contenedor integrado de Docker usando archivos de configuración en /etc/docker/containerd.d/. moby/moby#53946
  • Introduzca el atributo restarting para los eventos die para que el consumidor sepa que el contenedor se reiniciará. moby/moby#50908

Corrección de errores y mejoras

  • Bloquear familias de sockets obsoletas en los perfiles predeterminados de AppArmor y seccomp. moby/moby#54093
  • almacén de imágenes en contenedor: Se corrigió que docker image inspect y docker image ls informaran una imagen vacía cuando no se extrae la plataforma host de una imagen multiplataforma, pero sí otra plataforma. moby/moby#54040
  • No espere el tiempo de espera de exportación de telemetría cuando el punto final OTLP rechace las conexiones. docker/cli#7495
  • Se corrigió docker <unknown-command> --version imprimiendo la versión CLI en lugar de un error de "comando desconocido". docker/cli#7408
  • Se corrigió que docker cp imprimiera un mensaje "Copiado exitosamente" cuando falla la copia. docker/cli#7515
  • Se corrigió que docker manifest annotate rechazara plataformas válidas no incluidas en su lista predefinida de combinaciones de sistema operativo/arquitectura, como linux/loong64. docker/cli#7448
  • Se corrigió que docker ps imprimiera una columna NAMES vacía cuando todos los nombres de un contenedor contienen una barra, como cuando se conecta a un Swarm API clásico. docker/cli#7481
  • Se corrigió el demonio que eliminaba la interfaz docker0 al reiniciar cuando estaba configurada con un puente administrado por el usuario y grupos de direcciones predeterminados. moby/moby#54157
  • Reparar las exportaciones de capas de Windows que contienen archivos dispersos NTFS. moby/moby#53745
  • Solución: incluya códigos de estado HTTP en los errores de transmisión de JSON para permitir que clients clasifique correctamente las fallas. moby/moby#54133
  • Mejorar la selección de imágenes en hosts Linux ARM64 para preferir la variante de imagen más alta admitida por la CPU del host. moby/moby#53910
  • anotación de manifiesto: agregue finalización de shell para --os y --arch. docker/cli#7449
  • Rechazar recuentos de GPU duplicados de forma consistente cuando se combinen opciones de recuento abreviado y explícito. docker/cli#7312
  • Deje de tratar automáticamente los registros de bucle invertido como inseguros cuando insecure-registries esté configurado explícitamente y permita deshabilitar los registros inseguros predeterminados configurando "insecure-registries": [] en daemon.json. moby/moby#53868
  • Actualice runc (en binarios estáticos) a v1.5.3. moby/moby#54183

Actualizaciones de embalaje

  • Actualice BuildKit a v0.35.0. moby/moby#54180
  • Actualice el tiempo de ejecución de Go a 1.27.4. moby/moby#54176, docker/cli#7506

Redes

  • Los motores que utilizan el servidor de firewall de nftables ahora pueden unirse a un Swarm. (Experimental). moby/moby#53125
  • Se corrigió docker network ls --filter type=builtin --filter type=custom que enumera un subconjunto aleatorio de redes. moby/moby#54127
  • Se corrigió un error de "existe regla" al publicar más de un puerto de host para el mismo puerto de contenedor con el servidor de firewall de nftables y el proxy de usuario deshabilitado. moby/moby#54031
  • Se corrigió un contenedor que comenzaba sin conexión de red después de que un inicio anterior fallara debido a un error de red, como que un puerto publicado ya estuviera en uso. moby/moby#52480
  • Se corrigió la resolución de DNS en redes definidas por el usuario cuando falta el /etc/resolv.conf del host o no contiene servidores de nombres válidos. moby/moby#54140
  • Se corrigieron las reglas de iptables y una cadena DOCKER vacía que quedaba cuando el demonio cambia al backend del firewall de nftables después de que una versión anterior a 28.0.1 se ejecutara con iptables. moby/moby#54129
  • Se corrigió que las reglas de iptables no se restauraran después de detener o iniciar firewalld después del demonio. moby/moby#54012
  • Se corrigieron errores del controlador de red superpuesto cuando un contenedor obtiene la dirección IP de un contenedor que acaba de eliminarse en otro nodo. moby/moby#53833
  • Se corrigió que las redes superpuestas no pudieran reconvergir después de una partición de red cuando se reemplazó un administrador de Swarm en una nueva dirección. moby/moby#53715
  • Se corrigió que los servicios de enjambre filtraran una dirección IP virtual en sus otras redes cada vez que falla la asignación en una red, lo que podría agotar las subredes de esas redes. moby/moby#54148
  • Se corrigió que las tareas de Swarm no pudieran llegar al puerto publicado de un servicio a través de la dirección de su propio nodo cuando un firewall de host, como ufw, descarta tráfico entrante no solicitado. moby/moby#54006
  • Se corrigió que la MTU de las interfaces de red superpuestas fuera 20 bytes demasiado grande cuando la ruta de datos de Swarm es IPv6. moby/moby#54067
  • Reduzca la sobrecarga de publicación de puertos de nftables agrupando actualizaciones de firewall por punto final y familia de direcciones. moby/moby#54011
  • Evite que los nodos de un clúster Swarm intercambien el estado de la red superpuesta completa con cada administrador una vez por minuto cuando el clúster está en buen estado. moby/moby#53715

Sin raíces

  • Permitir el controlador de almacenamiento overlay2 en modo sin raíz cuando SELinux está habilitado. moby/moby#54048
  • Se corrigió el error de docker cp con "remount-ro... operación no permitida" en modo sin raíz en contenedores con un montaje de enlace de solo lectura desde un sistema de archivos nosuid o nodev. moby/moby#53981

API

  • Actualice la versión API a 1.57. moby/moby#53972
