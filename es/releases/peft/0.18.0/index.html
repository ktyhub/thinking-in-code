Nuevos métodos

Carretera

@ppetrushkov agregó RoAd: Adaptación rotativa 2D a PEFT en el n.° 2678. RoAd aprende matrices de rotación 2D que se aplican utilizando únicamente la multiplicación de elementos, lo que promete una inferencia muy rápida con adaptadores en estado no fusionado.

Sorprendentemente, además de LoRA, RoAd es el único método PEFT que admite lotes de adaptadores mixtos. Esto significa que cuando haya cargado un modelo con múltiples adaptadores RoAd, puede usarlos todos para diferentes muestras en el mismo lote, lo cual es mucho más eficiente que cambiar adaptadores entre lotes:

model = PeftModel.from_pretrained(base_model, <path-to-road-adapter-A>, adapter_name="adapter-A")
model.add_adapter("adapter-B", <path-to-road-adapter-B>)

inputs = ...  # input with 3 samples
# apply adapter A to sample 0, adapter B to sample 1, and use the base model for sample 2:
adapter_names = ["adapter-A", "adapter-B", "__base__"]
output_mixed = model(**inputs, adapter_names=adapter_names)
gen_mixed = model.generate(**inputs, adapter_names=adapter_names)

ALORA

LoRA activado es una técnica agregada por @kgreenewald en el n.° 2609 para modelos de lenguaje causal, que permite habilitar selectivamente adaptadores LoRA según una secuencia de invocación de token específica en la entrada. Esto tiene el principal beneficio de poder reutilizar la mayor parte del caché KV durante la inferencia cuando el adaptador solo se usa para generar parte de la respuesta, después de lo cual el modelo base vuelve a tomar el control.

Flecha y GenKnowSub

@TheTahaaa contribuyó no solo con soporte para Arrow, un algoritmo de enrutamiento dinámico entre múltiples LoRA cargados en #2644, sino también GenKnowSub, una técnica basada en Arrow donde la 'biblioteca' de LoRA disponible para Arrow se modifica primero restando adaptadores de conocimiento general (por ejemplo, entrenados en subconjuntos de Wikipedia) para mejorar el rendimiento de tareas específicas.

OndaFT

Gracias a @Bilican, se agregó Wavelet Fine-Tuning (WaveFT) a PEFT en el n.° 2560. Este método entrena actualizaciones dispersas en el dominio wavelet de matrices residuales, lo que es especialmente eficiente en parámetros. Es muy interesante para la generación de imágenes, ya que promete generar diversos resultados preservando la fidelidad del sujeto.

DeLoRA

@mwbini agregó [Adaptación de rango bajo desacoplada] (https://arxiv.org/abs/2503.18225) (DeLoRA) en el n.° 2780. Este nuevo método PEFT es similar a DoRA en la medida en que desacopla el ángulo y la magnitud de los pesos del adaptador aprendidos. Sin embargo, DeLoRA implementa esto de una manera que promete prevenir mejor la divergencia. Además, limita la desviación del peso aprendido imponiendo un límite superior de la norma, que se puede ajustar mediante el parámetro delora_lambda.

OSF

@NikhilNayak-debug agregó [Ajuste fino ortogonal] (https://huggingface.co/papers/2504.07097) (OSF) en el n.° 2685. Al congelar el subespacio de alto rango de las matrices de peso objetivo y proyectar actualizaciones de gradiente a un subespacio de bajo rango, OSF logra un buen rendimiento en tareas de aprendizaje continuo. Si bien requiere un poco de memoria para los procesos de ajuste estándar, definitivamente vale la pena comprobar las tareas donde la degradación del rendimiento de las tareas aprendidas previamente es una preocupación.

Mejoras

Punto de referencia de generación de texto

En el n.º 2525, @ved1beta agregó el punto de referencia de generación de texto a PEFT. Este es un marco para determinar y comparar métricas con respecto a la generación de texto de diferentes métodos PEFT, p. tiempo de ejecución y uso de memoria. En este momento, a este punto de referencia todavía le faltan configuraciones experimentales y una visualización, análogas a las que tenemos en el [punto de referencia MetaMathQA] (https://github.com/huggingface/peft/tree/main/method_comparison/MetaMathQA). Si esto es algo que le interesa, le animamos a que nos lo haga saber o, mejor aún, a que contribuya a este punto de referencia.

Interfaz confiable para integraciones

PEFT tiene integraciones con otras bibliotecas como Transformers y Diffusers. Para facilitar esta integración, PEFT ahora proporciona una [interfaz estable de funciones] (https://huggingface.co/docs/peft/package_reference/functional) que debe usarse si corresponde. Por ejemplo, la función set_adapter se puede utilizar para cambiar entre adaptadores PEFT en el modelo, incluso si el modelo no es una instancia de PeftModel. Nos comprometemos a mantener estas funciones compatibles con versiones anteriores, por lo que es seguro que otras bibliotecas creen sobre ellas.

Manejo del atado de peso

Algunos modelos de Transformers pueden tener pesos atados. Esto es especialmente frecuente cuando se trata de la incrustación y el cabezal LM. Actualmente, la forma en que se maneja esto en PEFT no es obvia. Por lo tanto, redactamos un problema para ilustrar el comportamiento previsto en el n.° 2864. Esto muestra cuál es nuestro objetivo, aunque todavía no todo está implementado.

En el n.° 2803, @romitjain agregó el argumento ensure_weight_tying a LoraConfig. Este argumento, si se establece en True, impone la vinculación de peso de los módulos objetivo con modules_to_save. Por lo tanto, si la incrustación y el cabezal LM están vinculados, compartirán pesos, lo cual es importante para permitir, por ejemplo, la fusión de pesos. Por lo tanto, para la mayoría de los usuarios, recomendamos habilitar esta configuración si desean ajustar completamente la incrustación y el cabezal LM. Sin embargo, para compatibilidad con versiones anteriores, la configuración está desactivada de forma predeterminada.

Tenga en cuenta que, de acuerdo con el n.° 2864, la funcionalidad de ensure_weight_tying=True se ampliará para incluir también tokens entrenables (n.° 2870) y LoRA (por determinar) en el futuro.

Admite capas Conv1d y 1x1 Conv2 en LoHa y LoKr

@grewalsk amplió LoHa y LoKr para admitir capas nn.Conv1d, así como nn.Conv2d con núcleos 1x1, en el n.° 2515.

Nueva inicialización de ajuste de aviso

Gracias a @macmacmacmac, ahora tenemos una nueva opción de inicialización para un ajuste rápido, inicialización discreta aleatoria (#2815). Esta opción generalmente debería funcionar mejor que la inicialización aleatoria, como se corrobora en nuestro conjunto de comparación de métodos PEFT. Pruébelo si utiliza el ajuste rápido.

Combinando adaptadores LoRA con pesos negativos

Si utiliza varios adaptadores LoRA, puede fusionarlos en un solo adaptador usando model.add_weighted_adapter. Sin embargo, hasta ahora esto sólo funcionaba con pesos positivos por adaptador. Gracias a @sambhavnoobcoder y @valteu, ahora también es posible pasar pesos negativos.

Cambios

Compatibilidad de transformadores

Al momento de escribir este artículo, el lanzamiento de Transformers v5 es inminente. Esta versión de Transformers será incompatible con PEFT < 0.18.0. Si planea utilizar Transformers v5 con PEFT, actualice PEFT a 0.18.0+.

Versión Python

Esta versión PEFT ya no es compatible con Python 3.9, que ha llegado al final de su vida útil. Utilice Python 3.10+.

Actualizaciones de OFT

El método OFT se ha actualizado para hacerlo un poco más rápido y estabilizar los números en el n.° 2805. Sin embargo, esto significa que los puntos de control existentes pueden dar resultados ligeramente diferentes después de actualizar a PEFT 0.18.0. Por lo tanto, si utiliza OFT, le recomendamos volver a entrenar el adaptador.
