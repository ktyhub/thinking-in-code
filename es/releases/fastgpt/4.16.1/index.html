#FastGPT v4.16.1

📦 Guía de actualización

Actualizar las variables de entorno de Agent Sandbox y la imagen en ejecución

Al habilitar Agent Sandbox, verifique la siguiente configuración en fastgpt-app y fastgpt-pro simultáneamente. 4.16.1 utiliza la dirección completa de la imagen en ejecución:

# 普通非 root 镜像，默认配置
AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.3.1

Si el sandbox necesita instalar dependencias apt, debe cambiar a la imagen raíz; si es necesario, puede configurar la fuente de imagen adecuada:

AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox-root:v0.3.1
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu

Para obtener una lista completa de las fuentes espejo de China continental y las fuentes espejo globales, la selección de espejos raíz/no raíz y la configuración personalizada de fuentes de dependencia, consulte [Configuración de OpenSandbox] (../../config/sandbox/opensandbox).

Herramienta de migración JSON Formato de almacenamiento de esquemas

Realice la migración estrictamente en el siguiente orden de versión:

  1. Después de asegurarse de que se ejecute la versión 4.16.0 del script initHttpToolSchema, convierta los parámetros de la matriz histórica de la herramienta HTTP manual al esquema estándar JSON.
  2. Después de actualizar a 4.16.1, ejecute initToolJsonSchemaStorage en esta sección.

4.16.1 verificará la aplicación de la herramienta HTTP y su versión histórica responsable de 4.16.0; Si los datos todavía contienen tipos de matrices antiguos, la interfaz se negará a ejecutarse para evitar que los datos antiguos se conviertan directamente en cadenas. La migración solo maneja aplicaciones de herramientas MCP/HTTP y sus versiones históricas, no aplicaciones de flujo de trabajo ordinarias.

4.16.1 unifica el esquema JSON de herramientas MCP/HTTP en almacenamiento de cadenas. Puede ejecutar un ensayo en seco primero para comprobar los cambios:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Luego de confirmar total.changedDocumentCount, realice la migración oficial:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

🚀 Nuevo contenido

  1. Canales de publicación de terceros, que admitan archivos multimodales, transcripción de audio y citas (si corresponde)
  2. Apoyar al equipo para instalar complementos del sistema (modo de proceso, existen ciertos riesgos de seguridad, las versiones futuras admitirán operaciones aisladas sin servidor).
  3. La zona de pruebas admite fuentes aptas personalizadas.

⚙️ Optimización

  1. Nomenclatura de clave S3, cancele el nombre del archivo original como clave para evitar que sea demasiado largo.
  2. El esquema MCP/HTTP json utiliza almacenamiento de tipo Cadena para evitar que los objetos personalizados entren en conflicto con las reglas de Mongo.

🐛 Arreglar

  1. En la configuración de la variable global del flujo de trabajo, el nombre del campo es demasiado largo y se desborda.
  2. AgentV2 llama al subflujo de trabajo y el contenido de salida del flujo dentro del flujo de trabajo no está deshabilitado.
  3. Enlace de invitación al equipo, puede recibir la misma invitación al equipo repetidamente.
  4. Usando registros, el seleccionador de fechas tendrá un día más.

🛠️ Optimización de código

  1. Complete todos los documentos de la interfaz devapi.
  2. Inicialización y optimización de registros concurrentes del sistema de complemento.
  3. Se solucionó el problema por el cual los errores durante la operación del complemento se presentaban como errores del sistema.
  4. Se solucionó el problema causado por la política --allow-net que no se configuraba cuando la versión del complemento Node.js es superior a v25.
