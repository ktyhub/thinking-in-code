#FastGPT v4.17.0

Instrucciones de actualización

**Antes de actualizar a V4.17.0, actualice primero a V4.16.2 y ejecute todos los scripts de actualización antiguos requeridos por la versión V4.16.x. ** El mecanismo de actualización automática de V4.17.0 solo gestiona las nuevas tareas registradas a partir de esta versión y no volverá a ejecutar scripts históricos de versiones anteriores.

A partir de la versión 4.17.0, las tareas registradas en el mecanismo de actualización del sistema se ejecutarán automáticamente y se evitarán problemas de concurrencia de múltiples nodos mediante la preferencia de arrendamiento. También se admite la detección de latidos para comprobar si el script está activo. El estado del script de actualización se puede ver en 管理员 > 版本升级.

De forma predeterminada, la tarea de migración por lotes procesa registros 100 por lote. Cuando la cantidad de datos es grande, se puede ajustar de 50 ~ 1000 a SYSTEM_MIGRATION_BATCH_SIZE.

Proxy AI (obligatorio)

A partir de V4.17.0, AI Proxy debe implementarse o conectarse y configurarse en la aplicación FastGPT y la versión comercial del servicio de administración que reutiliza la configuración de la aplicación/servicio:

  • AIPROXY_API_ENDPOINT: dirección raíz del servicio AI Proxy accesible, como http://aiproxy:3000, no agregue /v1.
  • AIPROXY_API_TOKEN: un token de administrador no vacío coherente con la configuración del servidor AI Proxy.

**A partir de V4.17.0, OPENAI_BASE_URL y CHAT_API_KEY han quedado obsoletos y eliminados y ya no tendrán efecto después de la configuración. ** Elimine estas dos variables del entorno de implementación, utilice en su lugar la configuración de AI Proxy anterior y mantenga la dirección del administrador del modelo y la clave en el canal del modelo del administrador. La antigua configuración de anulación de systemEnv.oneapiUrl/chatApiKey tampoco funciona.

La falta de cualquier configuración de AI Proxy hará que falle la verificación de inicio y el modelo único requestUrl/requestAuth no puede reemplazar estos dos elementos requeridos. Antes de actualizar, confirme que se pueda acceder al AI Proxy y que el token de administrador pueda acceder a la interfaz de administración de canales; no utilice la clave API del proveedor de servicios modelo como token de administrador de AI Proxy.

Defensa CSRF

Esta versión agrega una nueva herramienta CSRF que utiliza variables de entorno para defenderse de las etiquetas HTML.

CSRF_ENABLED=true

Configuración compatible con Code Sandbox seccomp (opcional)

Code Sandbox continúa habilitando seccomp de forma predeterminada. Si el kernel del host no admite seccomp en la aplicación, la inicialización del grupo de procesos fallará; Después de confirmar que la capacidad reducida de aislamiento de llamadas al sistema es aceptable, puede configurarla explícitamente para Code Sandbox:

SANDBOX_DISABLE_SECCOMP=true

Esta configuración solo desactiva seccomp, chroot, no_new_privs y la privación de UID/GID permanecen habilitadas. Después del cierre, las llamadas al sistema, como la red, la creación de procesos, subprocesos y la ejecución binaria, ya no se bloquearán desde la capa del núcleo. No se recomienda utilizarlo en un entorno que admita seccomp.

Permisos de creación predeterminados para nuevos equipos (opcional)

Después de configurar DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED=true, al crear un nuevo equipo, al grupo predeterminado de todos los empleados se le otorgarán permisos de creación de aplicaciones, habilidades y bases de conocimientos. El valor predeterminado es false, que solo afecta a los equipos nuevos y no modifica los permisos de los equipos existentes. FastGPT Pro Mantenga esta configuración coherente en FastGPT y los servicios de administración para cubrir sus respectivas entradas de creación de equipos, incluida la creación de equipos empresariales autorizados por WeChat.

Instrucciones de desuso

Dirección de solicitud personalizada del modelo

La dirección de solicitud personalizada del modelo quedará obsoleta en versiones futuras. La versión actual sigue siendo compatible. Cámbielo a un canal para la gestión de modelos.

🚀 Nuevo contenido

  1. El servicio FastGPT SSO agrega nuevos miembros LDAP para sincronizar con la estructura organizacional y complementa las plantillas de variables de entorno independientes y los documentos de configuración de diferentes proveedores de SSO.
  2. El servicio FastGPT SSO agrega nuevos usuarios de DingTalk y sincroniza departamentos.
  3. El campo de carga de archivos de la herramienta de flujo de trabajo admite la configuración que generará el Agente; el campo del archivo histórico aún mantiene la carga manual de forma predeterminada para evitar cambios de comportamiento después de la actualización.
  4. Se agregó administración automática de tareas de actualización del sistema, que le permite ver el estado de la actualización, el progreso de la etapa, los datos de fallas y los resultados de la ejecución, y reintentar tareas fallidas sin bloqueo.
  5. Agent V2 agrega una nueva configuración de transmisión de voz (TTS), que admite transmisión cerrada, transmisión de navegador o transmisión de modelo, y puede seleccionar timbre, ajustar la velocidad del habla y la audición; el estilo de configuración es consistente con Chat Agent.
  6. El tiempo de respuesta del primer token se agrega a los detalles de respuesta del nodo de diálogo de IA, que mide el tiempo transcurrido desde que se inicia la solicitud del modelo hasta que se recibe el primer texto o contenido de pensamiento.
  7. La transferencia del propietario del equipo se extiende al modo de varios equipos, lo que respalda la selección de miembros del equipo como nuevos propietarios y reduce el riesgo de mal funcionamiento mediante la confirmación de entrada.
  8. Defensa CSRF para evitar que sistemas externos (especialmente etiquetas HTML) transporten cookies para solicitar directamente la interfaz.

⚙️ Optimización

  1. Optimice la experiencia de pausa de la conversación: la solicitud de pausa regresa inmediatamente después de escribir la marca de parada del flujo de trabajo; Después de que el cliente recibe la confirmación, interrumpe activamente la solicitud de transmisión actual y ya no espera hasta 5 segundos.
  2. Optimice la retención de contenido después de la pausa: el modelo solo genera el contenido de pensamiento y se detiene cuando el texto no se ha generado. También mantendrá el contenido de pensamiento existente y aún podrá verse después de la actualización.
  3. Optimice la visualización de citas de imágenes: cuando solo se incluyen comillas después de la imagen, las comillas se muestran en el centro debajo de la imagen; las citas en línea en el texto mantienen el diseño original.
  4. Optimice la recuperación del conflicto de generación: cuando la conversación actual aún se genera en el servidor, el cliente identificará el conflicto y restaurará el flujo de generación original para evitar agregar mensajes en blanco o estados de error.
  5. Optimice la interacción del contenido durante el procesamiento: la vista previa plegada de llamadas de pensamiento o herramientas admite hacer clic para expandir y ubicar directamente los detalles correspondientes.
  6. Aplicación de banco de trabajo unificado, habilidad, conjunto de datos, mercado de plantillas, herramientas, uso de cuentas, panel de modelo, clave API, registro de auditoría e interacción de filtrado de lista de registros de aplicaciones; proporciona filtrado por tipo, fuente, creador, miembro, categoría, hora y clasificación por página, y admite búsquedas en largas listas de opciones.
  7. Las listas de aplicaciones, habilidades y conjuntos de datos tienen capacidades de filtrado adicionales, como ordenar por creador y hora de creación; el tiempo de creación de aplicaciones y conjuntos de datos históricos se completa automáticamente con la tarea de actualización del sistema.
  8. Unifique las interacciones básicas, como la selección múltiple de tablas, el rango de fechas, la entrada numérica, el desplazamiento de listas largas y las ventanas emergentes para mejorar la experiencia de las operaciones por lotes y la visualización de contenido extenso.
  9. Las listas de aplicaciones, conjuntos de datos y habilidades y los selectores de recursos relacionados se cambian a carga paginada, y el desplazamiento virtual, la pantalla de esqueleto de carga y la navegación por carpetas se optimizan para mejorar la experiencia de carga y navegación cuando se utiliza una gran cantidad de recursos.
  10. El resumen del modelo, los detalles y la lista de candidatos se cargan según los escenarios de uso. Los modelos candidatos se cargan cuando se expande el selector y se distinguen los estados de carga, falla de carga y modelo no disponible.
  11. Lógica unificada de descripción de herramientas: los nodos de herramientas y las subherramientas del conjunto de herramientas utilizan introducciones de nodos como descripciones de llamadas de herramientas; Las subherramientas del conjunto de herramientas admiten la edición directa de descripciones y conservan la personalización histórica o el contenido de borrado activo para evitar que se sobrescriban al sincronizar las definiciones de herramientas.
  12. El componente de tabla admite el desplazamiento por separado del encabezado y el contenido, y también admite el desplazamiento virtual.

🐛 Arreglar

  1. Se solucionó el problema del espacio en la parte inferior de la ventana emergente de confirmación de cancelación de cuenta y el problema de que el texto largo no se podía ajustar correctamente, y se optimizó la plantilla de correo electrónico de cancelación de cuenta.
  2. Limite DB_MAX_LINK a 10~1000 para evitar una cantidad baja de conexiones que afecten la simultaneidad o una configuración excesiva que cause presión de recursos; la plantilla de implementación oficial usa 20 de forma predeterminada.
  3. Se solucionó el problema de que después de desactivar la instalación del complemento del equipo, algunas interfaces de carga, instalación de URL y confirmación de instalación aún pueden omitir el interruptor de función.
  4. Se solucionó un problema por el cual los archivos podían continuar analizándose después de deshabilitar el escaneo XLSX XML.
  5. Se solucionó el problema por el cual el modo "Entrada manual/Generación de agente" del elemento de entrada de la herramienta HTTP/OpenAPI se perdía después de guardar y se restablecía incorrectamente cuando se ejecutaba como herramienta de agente o subflujo de trabajo.
  6. Se solucionó el problema de que la selección de modelo no distingue estrictamente entre tipos de modelo, la verificación falla cuando la temperatura máxima del modelo se deja en blanco y el orden del directorio de modelos del administrador y la lista de modelos disponibles para miembros es inconsistente; al mismo tiempo, evita borrar accidentalmente la caché del modelo de miembro aún válido durante la fase de inicio del servicio.
  7. FastGPT Pro ajusta los mensajes ilegales recibidos a través de canales de publicación como Feishu, Enterprise WeChat, DingTalk y las cuentas oficiales de WeChat para devolver errores claros del cliente y evitar que los problemas de formato de solicitud se informen erróneamente como fallas del servidor.
  8. FastGPT Pro soluciona el problema de que el campo role de los miembros históricos del equipo puede sobrescribir el cálculo de permisos actual: excepto el propietario del equipo, los valores de roles abandonados ya no participan en la determinación de permisos.
  9. Se solucionó el problema por el cual la configuración multimodal oculta de aplicaciones simples y agentes de diálogo provocaba que imágenes, audio o videos no se incluyeran en las solicitudes de modelo; Las entradas de cambio de modelo con cambios multimodales explícitos en el flujo de trabajo borran uniformemente las opciones que no son compatibles con el nuevo modelo y no se restaurarán automáticamente después de volver a cambiar.
  10. Se solucionó el problema de sobrescritura de errores al mapear campos de solicitud de modelo con el mismo nombre, intercambio o mapeo de cadena; El mapeo utiliza datos de solicitud que han sido normalizados y filtrados por las capacidades del modelo, y los campos de destino repetidos informarán claramente un error.
  11. Se solucionó el problema de la caducidad de la definición de la herramienta MCP/HTTP o la incompatibilidad de almacenamiento con las instantáneas del flujo de trabajo. La definición de la herramienta se lee en tiempo de ejecución y es compatible con la configuración histórica de la herramienta y la información de autenticación.
  12. Se solucionó el problema por el cual la herramienta de importación OpenAPI no enviaba parámetros de acuerdo con la definición de la interfaz: asigne parámetros a Ruta, Consulta, Encabezado y Cuerpo de JSON de acuerdo con el texto original, admita parámetros compartidos a nivel de ruta y serialice matrices y objetos superficiales de acuerdo con style / explode, conservando nombres de parámetros de consulta duplicados y los tipos de datos originales en el cuerpo de JSON.
  13. Se solucionó el problema por el cual los parámetros de cookies opcionales no se pasaban en las solicitudes de bloque de definición de OpenAPI; Los parámetros requeridos que faltan, las cookies que realmente se pasan pero no son compatibles o la codificación de parámetros que no es compatible seguirán informando claramente un error.
  14. Se solucionó el problema por el cual ToolCall desactivaba uniformemente la salida de streaming de los subflujos de trabajo, lo que provocaba que la configuración del nodo secundario no surtiera efecto; el subflujo de trabajo hereda las capacidades de transmisión del proceso principal y sigue su propia configuración de prohibición de flujo, y las aplicaciones secundarias y los nodos de herramientas de flujo de trabajo generados por la aplicación simple aún se ven obligados a prohibir el flujo.
  15. Se solucionó el problema de que la carga asincrónica de modelos podía sobrescribir las selecciones del usuario, juzgar erróneamente los modelos descargados como no disponibles y completar accidentalmente el modelo predeterminado cuando el editor restaura la configuración.
  16. Se solucionó un problema por el cual las funciones de reorganización cerrada, optimización de preguntas, adivinar lo que desea preguntar y de informes del modelo aún verifican el modelo cuando se lanza el flujo de trabajo; las funciones opcionales habilitadas solo completan el valor predeterminado cuando el modelo está vacío, y las referencias de modelos no vacíos no válidos seguirán informando claramente errores.
  17. Compatible con la situación en la que falta el nombre del miembro histórico del equipo, la aplicación questionGuide es null y la referencia del modelo de la base de conocimientos está vacía, para evitar fallas de verificación al leer datos antiguos.
  18. Se corrigió la visualización anormal de esquinas redondeadas y rutas de conexiones de flujo de trabajo cuando el espacio entre nodos es pequeño, y el problema de que el ícono predeterminado no se usa cuando el ícono del sitio está configurado como /.
  19. El avatar de la plantilla de flujo de trabajo del complemento conserva la URL original devuelta por el complemento para evitar que la dirección se muestre correctamente después de reescribirse.
  20. Se solucionó un problema por el cual al convertir una tabla HTML a Markdown, la cantidad de columnas de encabezado era menor que la cantidad de filas de datos, lo que provocaba que algunas columnas no se mostraran; el encabezado de la tabla se completó automáticamente durante la conversión, conservando el contenido completo de la tabla.

🛠️ Optimización de código

  1. Los modelos del sistema, los permisos de los modelos y las configuraciones comerciales utilizan la referencia estable modelId y son compatibles con las referencias de nombres de modelos antiguos mediante tareas de actualización automática.
  2. La tarea de actualización automática realiza la exclusión mutua de múltiples nodos y la toma de control de fallas mediante el arrendamiento de MongoDB, ejecutando aislamiento de ID y latidos; Las tareas de big data admiten la continuación del punto de interrupción por lotes.
  3. La interfaz de consulta del colaborador puede devolver los nombres de usuario de inicio de sesión de los miembros del equipo a pedido y evitar solicitudes miembro por miembro a través de consultas por lotes.
  4. FastGPT Pro optimiza la caché de compilación de imágenes del clúster y utiliza caché proxy y Runner en caché para reducir la sobrecarga repetida de extracción y compilación.
  5. Se corrigió la confusión entre la dirección de acceso del script de implementación y la configuración del puerto del host. Admite la configuración independiente de los puertos de host de FastGPT y Sandbox Proxy para evitar el uso indebido del puerto de red pública del proxy inverso.
  6. Code Sandbox devuelve la pila de excepciones, la cadena de excepciones y la salida de impresión/consola capturada cuando falla la ejecución del código JS o Python, y registra en el registro de respuestas de nivel de advertencia. Los detalles y la salida del error están limitados a 16 KB de caracteres, y el truncamiento se marca explícitamente cuando se excede el límite; cuando la respuesta del trabajador no se puede analizar, se complementan el ID del trabajador, la longitud de la respuesta y el stderr capturado. Cuando un proceso finaliza por la fuerza, es posible que aún se pierda la salida que aún no se ha enviado.
