redis 8.12-rc1

Esta es la primera versión candidata de Redis 8.12 en código abierto Redis.

Las versiones candidatas son versiones preliminares con funciones completas. Los prelanzamientos no son adecuados para uso en producción.

Titulares:

Redis 8.12 presenta nuevas funciones y mejoras de rendimiento.

Sistemas operativos en los que probamos Redis 8.12

  • Ubuntu 22.04 (Jammy Jellyfish), 24.04 (Noble Numbat), 26.04 (Resolute Raccoon) -Rocky Linux 8.10, 9.7, 10.1 -AlmaLinux 8.10, 9.7, 10.1
  • Debian 12.13 (ratón de biblioteca), Debian 13.4 (Trixie)
  • Alpino 3.23
  • macOS 14.8.4 (Sonoma), 15.7.4 (Sequoia), 26.3 (Tahoe) - para Intel y ARM

Correcciones de seguridad

  • RediSsearch/RediSsearch#10073 El hash de valores indexados ahora es resistente a colisiones, lo que evita la degradación del índice estilo HashDoS debido a entradas adversas. (MOD-14459)
  • RediSsearch/RediSsearch#11202 Los caracteres UTF-8 incompletos ya no se leen fuera de los límites en los campos de TEXTO indexados. (MOD-18088)

Nuevas funciones

  • #15331 Mapas de bits comprimidos: rugido redis integrado en el núcleo Redis para un menor uso de memoria y operaciones de mapas de bits más rápidas. ¡Un agradecimiento especial a Antonio, el creador original de redis-roaring, por contribuir con esta capacidad! https://redisroaring.com/redis-merge/#/1;
  • #15986 Nuevo comando: BITRANGEINTARRAY equivalente al R.RANGEINTARRAY de redis-roaring, para devolver desplazamientos de bits establecidos dentro de un rango específico
  • #15938 Establecer vencimiento para un miembro del conjunto individual; Nuevos comandos: SEXPIRE,SPEXPIRE,SEXPIREAT,SPEXPIREAT para establecer la caducidad y STTL, SPTTL, SEXPIRETIME,SPEXPIRETIME para recuperar los TTL restantes o las marcas de tiempo de caducidad.
  • #15649 Bless Keys: evita el desalojo de llaves especificadas; Nuevo comando: BLESS
  • #15829 CLUSTER MIGRATION STATUS ahora informa el progreso de las fases de migración instantánea y incremental.
  • #15556 TLS los grupos con nombre ahora se pueden configurar usando tls-groups
  • RedisBloom/RedisBloom#1063 Extensiones Count-min-sketch: se agregó compatibilidad opcional con CELL_SIZE a CMS.INITBYDIM y CMS.INITBYPROB para un menor uso de memoria, incrementos negativos en CMS.INCRBY para disminuir los recuentos e informes de tamaño de celda en CMS.INFO.
  • RedisJSON/RedisJSON#1640 Creación automática de ruta profunda JSON
  • RediSsearch/RediSsearch#10151 EXPLAINSCORE ahora es compatible con FT.HYBRID. (MOD-10044)
  • RediSsearch/RediSsearch#11330 La nueva compresión SQ8 ahora está disponible para campos vectoriales HNSW. (MOD-6132)
  • RediSsearch/RediSsearch#10247 El manejo del tiempo de espera de RETURN_STRICT ahora está habilitado para la ejecución local de FT.HYBRID. (MOD-16492)
  • RediSsearch/RediSsearch#11278 FT.ALTER evita la reindexación innecesaria de documentos durante las adiciones de esquemas. (MOD-18171)
  • RediSsearch/RediSsearch#11384 Las actualizaciones de hash de puntuación/carga útil únicamente evitan la reindexación. (MOD-18182)
  • RediSsearch/RediSsearch#11230 Los documentos hash ya no se vuelven a indexar cuando no se toca ningún campo indexado por vectores. (MOD-17688)

Corrección de errores

  • #15569 Los cambios realizados por XDELEX DELREF para entradas de flujo ya eliminadas podrían no propagarse a las réplicas o al AOF.
  • #15508 Las operaciones que utilizan el recorrido aleatorio del árbol de base podrían comportarse incorrectamente al comenzar desde ciertos nodos de hoja
  • #15604 El uso de memoria podría calcularse incorrectamente para hashes usando plantillas compartidas
  • #15489 Los archivos RDB no pudieron cargarse después de que XSETID redujera el contador de entradas agregadas de una transmisión.
  • #15626 SET podría calcular un tiempo de vencimiento incorrecto cuando se le da un TTL relativo excesivamente grande
  • #15628 La desfragmentación activa podría manejar incorrectamente el registro de plantilla compartida utilizado por hash compactos
  • #15530 Después de la conmutación por error, una réplica podría permanecer conectada a otra réplica en lugar de a la nueva principal
  • #15733 Se podrían aceptar rangos de ranuras de clúster no válidos después de fusionarlos en un rango válido
  • #15756 RESTORE podría calcular un tiempo de vencimiento incorrecto cuando se le da un TTL relativo excesivamente grande
  • #15699 El crecimiento de la memoria podría contabilizarse incorrectamente cuando SETBIT o BITFIELD expandieron una cadena
  • #15815 XTRIM podría dejar una secuencia en un estado que impedía que se cargara un archivo RDB que la contenía.
  • #15795 Clients podía no recibir un error de protocolo cuando llegaba un comando con formato incorrecto a través de múltiples lecturas de red.

  • #15916 Los datos se podían perder cuando se actualizaba un archivo AOF heredado antes de que se completara la carga.

Mejoras en el rendimiento y la utilización de recursos

  • #15618 Las actualizaciones por lotes de hash usando plantillas compartidas ahora se ejecutan de manera más eficiente
  • #15018 Los sistemas x86 compatibles ahora usan el reloj monótono basado en procesador de forma predeterminada, con calibración de tiempo de ejecución para reducir la sobrecarga de tiempo.
  • #15782 La carga de RDB y AOF ahora proporciona sugerencias de lectura secuencial al sistema operativo para mejorar la eficiencia de carga
  • RediSsearch/RediSsearch#10169 Las búsquedas en índices que utilizan la caducidad a nivel de campo (HEXPIRE) son más rápidas. (MOD-16350)
  • RediSearch/RediSearch#10981, RediSearch/RediSsearch#11065 Se reduce la sobrecarga de serialización de fila y respuesta de campo del coordinador. (MOD-17924)
  • RediSearch/RediSearch#11055, RediSearch/RediSearch#11056, RediSearch/RediSsearch#11057 La conversión de respuestas de clúster, la destrucción de resultados y la limpieza de GROUPBY han reducido los gastos generales. (MOD-17908, MOD-17909, MOD-17910)
  • RediSearch/RediSearch#11507, RediSearch/RediSsearch#11506 Las respuestas a las consultas ahora dan formato a valores numéricos integrales sin snprintf y declaran las longitudes de la colección de respuestas por adelantado. (MOD-18800, MOD-18799)
  • RediSsearch/RediSsearch#11509 La carga de campos hash para RETURN y LOAD ya no requiere asignaciones por campo. (MOD-18811)
  • RediSsearch/RediSsearch#10246 Ahora se permiten escrituras simultáneas durante consultas de rango vectorial. (MOD-16437)
  • RediSsearch/RediSsearch#10515 Las solicitudes de coordinador ahora se asignan en el hilo principal, eliminando CoordRequestCtx. (MOD-16990)
  • RediSsearch/RediSsearch#11018 El uso de consultas ahora está separado de las operaciones de índice administrativo. (MOD-17536)
  • RediSsearch/RediSsearch#10066 Se eliminó la barrera de respuesta de fragmentos en favor de la devolución de llamada de agotamiento del iterador asíncrono para FT.AGGREGATE WITHCOUNT. (MOD-16210)
  • RedisJSON/RedisJSON#1645 Informes de uso de memoria más precisos para cadenas compartidas: el uso de memoria ahora representa la parte proporcional de cada referencia de la asignación de una cadena compartida, incluido su encabezado y relleno, en lugar de cobrar la asignación completa a cada referencia.
  • J1660 Consumo de memoria de objetos reducido: el análisis JSON ahora utiliza la asignación de objetos compactos para reducir la memoria real necesaria para almacenar objetos JSON
  • RedisJSON/RedisJSON#1661 Se mejoró el análisis y la evaluación de JSONPath al reducir el retroceso del analizador, las asignaciones temporales y el recorrido repetido. Las optimizaciones incluyen el almacenamiento en caché de los operandos de la ruta raíz entre los candidatos de filtro, detener las comprobaciones de existencia en la primera coincidencia y reducir la sobrecarga en las coincidencias de expresiones regulares y comparaciones de cadenas.
  • RedisJSON/RedisJSON#1631 Acceso mejorado a elementos de matriz mecanografiada mediante indexación directa, evitando iteraciones repetidas y trabajo cuadrático durante escaneos indexados completos
  • RedisBloom/RedisBloom#1049 Se mejoró el rendimiento de la compresión t-digest para entradas que contienen muchos valores duplicados. La clasificación ahora está limitada a O (n log n), evitando el comportamiento cuadrático en entradas patológicas

Parámetros de configuración

  • Redis-roaring:bitmap-default-roaring - para habilitar el nuevo tipo de mapas de bits rugientes, deshabilitado de forma predeterminada
  • RedisJSON/RedisJSON#1657 Validación de profundidad de RDB configurable: se agregó json-legacy-rdb-depth-limit, deshabilitado de forma predeterminada, para imponer una profundidad de anidamiento máxima de 128 al cargar JSON desde RDB o mediante RESTORE
  • RedisJSON/RedisJSON#1640 Se agregó json-auto-create-deep-paths y está deshabilitado de forma predeterminada y solo se puede configurar en el momento de la carga. Utilice el mismo valor en cada nodo de un fragmento y cuando reproduzca archivos AOF, ya que valores diferentes pueden provocar divergencias en los datos.

Métricas

  • #15374 INFO Los histogramas de tamaños de claves ahora incluyen secuencias, lo que proporciona visibilidad de los tamaños de claves de secuencias.
  • #15682 Observabilidad de transmisiones: se agregó INFO STREAMS con histogramas por base de datos de grupos de consumidores por transmisión, entradas pendientes por grupo y consumidores por grupo. Habilitar con estadísticas de transmisión sí (deshabilitado de forma predeterminada)
  • RediSsearch/RediSsearch#10097 FT.INFO ahora expone el EF_RUNTIME predeterminado. (MOD-16147)
  • RediSsearch/RediSsearch#10107 Disk GC bytes_collected y las estadísticas de ciclo ahora se informan en FT.INFO. (MOD-14621)
  • RediSsearch/RediSsearch#10464 FT.INFO en el coordinador ahora agrega métricas de disco por campo a través del reductor. (MOD-14859)
  • RediSsearch/RediSsearch#10204 Redis INFO ahora desglosa las métricas de tiempo de espera de consultas por etapa de canalización. (MOD-13192)
  • RediSsearch/RediSsearch#11521 Las métricas de índice ya no se recopilan para secciones INFO no relacionadas. (MOD-18033)
  • Se ha mejorado la resolución de sincronización del campo del cargador RediSsearch/RediSsearch#10536 FT.PROFILE. (MOD-17132)

Cambios de comportamiento

  • RediSsearch/RediSsearch#10109 FT.CREATE rechaza RERANK en campos vectoriales HNSW en modo RAM. (MOD-16015)
  • RediSsearch/RediSsearch#10200 Los índices de disco rechazan DIALECT 4 y WITHOUTCOUNT. (MOD-15997)
  • RediSsearch/RediSsearch#10082 COLLECT requiere un prefijo @ para los nombres de campo. (MOD-16233)
  • Los campos RediSsearch/RediSsearch#11106 JSON HIGHLIGHT/SUMMARIZE con JSONPath de múltiples valores ahora se rechazan. (MOD-16530)
  • RediSsearch/RediSsearch#10208 Los comandos que no se pueden almacenar en caché ahora están marcados con dont_cache. (MOD-16175)
  • RediSsearch/RediSsearch#10699 Los argumentos de los comandos numéricos ahora se analizan estrictamente. (MOD-17409)
  • RediSsearch/RediSsearch#11335 El módulo de búsqueda ahora requiere Redis 8.9.241 o posterior para cargar. (MOD-15868)
  • RedisBloom/RedisBloom#1063 Las actualizaciones de elementos CMS.INCRBY rechazadas ahora dejan los contadores y el recuento total sin cambios en lugar de saturar los contadores cuando se desbordan. Los comandos de varios elementos aún pueden tener éxito parcialmente.
  • RedisBloom/RedisBloom#1063 CMS.MERGE ahora requiere tamaños de celda coincidentes en el destino y en todas las fuentes.

Módulos API

  • #15517 Los módulos ahora pueden recuperar el puerto TLS de un nodo del clúster usando el nuevo indicador REDISMODULE_NODE_PORT_TLS en RM_GetClusterNodeInfo()
  • RedisJSON/RedisJSON#1623 Se agregó getWithPath en API V9 compartido para evaluar un JSONPath precompilado, lo que permite a quienes llaman compilar una ruta una vez y reutilizarla en todos los documentos.
  • RedisJSON/RedisJSON#1666 Se agregó pathParseNoErrorMsg en API V10 compartido para compilar JSONPaths sin un contexto Redis o un mensaje de error asignado. Devuelve un identificador compilado en caso de éxito o NULL en caso de error.
  • RedisJSON/RedisJSON#1653 Se hicieron opcionales los enlaces de precomando y se permitieron errores de enlace para abortar los comandos JSON antes de la ejecución. Los ganchos ahora devuelven RedisResult<()>; Las llamadas compartidas C API continúan ignorando los errores de enlace.
  • RedisJSON/RedisJSON#1640 Se amplió la interfaz del Administrador Rust con clone_value y create_object para admitir la construcción de rutas faltantes. Las implementaciones personalizadas deben implementar estos métodos y satisfacer el nuevo requisito Borrow<Self::V> para valores propios.
