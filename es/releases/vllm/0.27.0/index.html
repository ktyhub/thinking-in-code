vLLM v0.27.0 Release Note

Destacados

¡Esta versión presenta 561 confirmaciones de 242 contribuyentes (64 nuevos)!

  • Compatibilidad con Kimi K3 con un aterrizaje de pila completa en una versión: archivos de modelo central y kernels (#50089, #50000), interfaces Python (#50093) y Rust (#50104), kernels AttnRes (#50090), soporte DeepGEMM (#50458), puntos de control cuantificados de tensores comprimidos (#50500), fusión DSpark AR (#50242) y una opción para fragmentar el experto compartido en lugar de replicarlo (#50656).
  • Más modelos nuevos: modelos Qwen3.5 de solo texto denso y MoE (#50210) con poda de token de video EVS (#48912), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma a través del backend de modelado de Transformers (#49803) y jina-embeddings-v5-text-nano (#50688).
  • Actualización de PyTorch 2.13.0 junto con torchvision 0.28.0 y Triton 3.7.1 (#48155): este es un cambio radical en el entorno; XPU (#48677) y CPU (#50412) siguieron para quemar 2.13 también.
  • La integración de FlashAttention 4 se profundiza en SM100: compatibilidad con caché FP8 KV (#42569) y compatibilidad con headdim-256 (#42669), respaldada por una nueva infraestructura de preparación JIT (#47451) y una preparación del kernel Triton propiedad del corredor (#49903) que elimina los bloqueos de compilación en la primera solicitud.
  • Mejora del rendimiento de DeepSeek-V4: paralelismo de secuencia (#46789), mejora ~2x del kernel al omitir lanzamientos de c128 vacíos (#48957), 3.4% E2E TTFT al omitir topk/enrutador innecesario (#49486), 3.9% E2E TTFT de la reutilización del espacio de trabajo (#49236), kernel 1.88x al eliminarlo un kernel completo redundante (n.° 50298), ancho de topk adaptable (1.0% E2E, n.° 50004), memoria de GPU de 448 MiB guardada en el búfer PP (n.° 50312), un caché KV indexador MXFP4 compacto (n.° 48993) y eliminación del relleno de cabezal q de MLA disperso en FlashInfer >= 0.6.14 (n.° 48047).
  • Model Runner V2 se expande a cargas de trabajo no generativas: atención solo codificador (#49331), agrupación de secuencias para incrustación/clasificación (#48791), clasificación de tokens de codificador (#50293) e incrustación de tokens (#50574), agrupación BGE-M3 (#50661), multimodal en CPU (#50073), especulador MTP multicapa (#48892), y PCP ahora selecciona MRV2 (#50034).
  • Servicio resistente a gran escala: un marco de tolerancia a fallas (simplificado) para implementaciones de balanceadores de carga externos DP+EP (#44428) y preparación asíncrona para el escalado elástico de EP (#47288).
  • Desagregación para modelos híbridos: NIXL P/D para modelos híbridos MLA+SSM (n.° 49762), tamaños de bloque P/D heterogéneos para modelos híbridos (n.° 49612) y enrutamiento de lectura de precarga/decodificación TP<->DP heterogéneo MoRIIO (n.° 46116).
  • La interfaz Rust amplía un plano de control gRPC: informes de estado del motor (#48992), control de abortos (#49255), descubrimiento de servidores y modelos (#49491), descubrimiento de fuentes de eventos KV (#50033), además de vllm-bench integrado en vllm CLI (#48930).
  • Habilitación temprana de hardware de próxima generación: objetivo sm_107 para NVIDIA Rubin (#49387) con rutas NVLink all-reduce en SM107 (#49647) y arquitectura ROCm gfx1250 habilitada (#46516).

Soporte de modelo

  • Kimi K3: nuevo modelo (#50000) con archivos de modelo y kernels (#50089), interfaz Python (#50093), interfaz Rust (#50104), kernels AttnRes (#50090), compatibilidad con DeepGEMM (#50458), DSpark AR fusion (#50242) y fragmentación compartida por expertos opcional (#50656).
  • Nuevos modelos: Qwen3.5 de solo texto denso y MoE (#50210), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma a través del backend de Transformers (#49803), jina-embeddings-v5-text-nano con codificador troncal EuroBERT (#50688).
  • Insinuación: pesos NVFP4 del compresor llm (#49258) y FP8 dinámico de tensores comprimidos (#48876).
  • Multimodal: poda de token de video VidCom2 (n.° 47750), EVS para Qwen3.5 (n.° 48912), gráfico ViT CUDA para Gemma-4 (n.° 46837), reasignación de modelos/difusores Cosmos3 FP8 (n.° 48952), verificación de decodificación especulativa MiniMax-M3 MSA (n.° 50032) y procesador de video predeterminado (n.° 50305). Optimización TTFT de DeepSeek-OCR-2 (#49531), mayor duración máxima de audio para MOSS-TD (#49403).
  • Modelos de difusión: muestreo top_k y top_p para DiffusionGemma (#45429).
  • Backend de modelado de Transformers: soporte de modelo de audio (n.° 39330), rastreador fx mejorado (n.° 49957), adición residual fusionada + pase de compilación RMSNorm (n.° 48757) y correcciones para relleno MLA + enrutamiento topk agrupado (n.° 49982), MQA con TP (n.° 49987) y Qwen3-VL M-RoPE (n.° 49292).

Núcleo del motor

  • Calentamiento: nueva infraestructura de calentamiento JIT (#47451), kernels Triton propiedad del corredor calentados antes de la primera solicitud (#49903) y calentamiento adecuado del renderizador (#50408).
  • Atención: caché FlashAttention 4 SM100 FP8 KV (#42569) y headdim-256 (#42669); replicación de consultas para decodificación MLA bajo DCP para DeepSeek-V2/R1 y Kimi-K2.5 (#45964); MHA enmascarado para precargas escasas de MLA (#48770); omita la puntuación escasa del indexador para precargas cortas y densas (#48407); Se evitó la explosión de compilación del gancho de epílogo FlexAttention (#45841) y de la máscara de bloque del codificador (#50339); los backends de atención siguen siendo elegibles para la publicación de solo texto de modelos de prefijo LM (#48796); el contexto de atención de fusión cuenta como argumento de tiempo de ejecución (#48739); soporte de gráfico CUDA del codificador multiruta unificado (#49934); Ganchos de extensión de caché del codificador (#48218).
  • Model Runner V2: atención solo de codificador (#49331), agrupación de secuencias para incrustación y clasificación (#48791), clasificación de token de codificador (#50293), incrustación de token de codificador (#50574), agrupación BGE-M3 (#50661), multimodal en CPU (#50073), especulador MTP multicapa (#48892), PCP selecciona MRV2 (#50034), metadatos de atención siempre creados en el momento de la captura (#49364), perfilado de caché del codificador (#47985), materialización de logits FP32 no operativos omitidos (#47711), muestreador de rechazo fragmentado para evitar OOM (#48630), menos sincronizaciones de GPU<->CPU en Mamba híbrido (#49736).
  • Descarga de KV: nivel secundario P2P genérico con búsqueda/servicio de pares (#48021), filtrado de niveles por solicitud con TierFilter/TierMatcher (#48123), eventos KV autodescriptivos con TieringOffloadingSpec (#48679), políticas de desalojo conectables a través de CachePolicyFactory (#49114), MLA KV replicado y deduplicado en la región de CPU compartida (#48906), diseño MLA de copia única para CPUOffloadingSpec (#50301), CPUOffloadingSpec movido a SharedOffloadRegion (#50094), identidad secundaria compacta independiente de TP (#49858), carga/almacenamiento C por lotes para descarga del sistema de archivos (#49152), descarga parcial confiable para mensajes de subbloque (#49502), asignaciones de páginas KV canónicas por capa para Descarga independiente del paralelismo (#48408).
  • Mamba/híbrido: almacenamiento en caché de ReplaySSM para una decodificación estándar de Mamba2 más rápida (n.° 48018), migración de estado DS-conv en modo de alineación fusionada con num_accepted_tokens > 1 (n.° 49291), selección del algoritmo FlashInfer Mamba SSU (n.° 50157), se corrigió el bloqueo de /wake_up en modelos híbridos (n.° 41602).
  • Decodificación de especificaciones: cabeza de DSpark Markov replicada en los rangos de TP (n.° 49731), sample_from_anchor cargado desde la configuración de especuladores (n.° 48639), cadena de parada que se completó primero (n.° 49391).
  • Salidas estructuradas: gramática avanzada a través del límite del razonamiento con decodificación de especificaciones (#44993).
  • Rendimiento de preprocesamiento: trabajo de CPU de renderizado descargado al grupo de subprocesos del renderizador (#49396), preprocesamiento sin procesar fuera del bucle de eventos en AsyncLLM (#49608), preprocesamiento multimodal aislado en su propio ejecutor (#49524), carga de incrustaciones de MM diferida fuera del bucle de eventos (#49477), preprocesamiento paralelo dentro de una solicitud de agrupación en línea (#49153), videos con hash por bytes de origen (#49607), modo de imagen original conservado en ImageIO (#49159).
  • RL: etiquetado de versión de peso para implementaciones de RL (#49040), IPC de envío de entrenador con estado (#48981), configuración de vLLM establecida durante la recarga de peso (#45989), salida de reproducción del enrutador desde el kernel MoE monolítico FlashInfer (#44214).
  • Memoria y robustez: contabilidad de fragmentación CuMem durmiente-L1 (n.° 49208), límites de memoria de cgroup respetados en todas las plataformas (n.° 49966), falla rápida cuando /dev/shm es demasiado pequeño (n.° 48879), decapado de tensor de copia cero en shm_broadcast (n.° 48442), división de hash de LRU omitida en free_blocks cuando el almacenamiento en caché de prefijo está desactivado (n.° 48017), vars de ruta derivadas de la ubicación excluidas de los factores de caché de torch.compile (n.° 47573), CustomOp.forward_native compilado para ReLU^2 (n.° 50244), configuración HF utilizada para tokenizadores HF (n.° 49907), RMSNorm invariante por lotes mediante tamaño de bloque fijado (n.° 48391).

Hardware y rendimiento

  • DeepSeek-V4: paralelismo de secuencia (#46789), kernel ~2x omitiendo lanzamientos c128 vacíos (#48957), 3.4% E2E TTFT omitiendo topk/router en decodificación (#49486), 3.9% E2E TTFT reutilización del espacio de trabajo (#49236), kernel 1.88x eliminando un kernel completo redundante (#50298), ancho superior adaptable 1.0% E2E (#50004), 448 MiB de memoria de GPU guardada (#50312), caché KV del indexador MXFP4 compacto (#48993), relleno de cabezal q MLA disperso eliminado para FlashInfer >= 0.6.14 (#48047).
  • Núcleos: soporte no contiguo de RMSNorm con mejora del kernel 1.2–3.1x (n.° 49750), corrección de regresión MoE reduce_scatter que restaura el rendimiento E2E del 5 % (n.° 48763), enrutamiento topk sin polarización no agrupado enviado a la ruta fusionada (n.° 49618), enrutador GEMM LL BF16 sintonizado (n.° 48774) con calentamiento omitido modelos que no son MoE (#49659), ruta de descriptor de tensor Triton para MoE fusionado a través de VLLM_TRITON_USE_TD (#42436), relleno cudagraph/DP omitido en topk (#48979), acceso fusionado a HBM en el núcleo de preproceso Marlin INT4-FP8 AWQ (#47268).
  • NVIDIA de próxima generación: sm_107 para Rubin (n.° 49387), rutas NVLink totalmente reducidas en SM107 (n.° 49647), detección de arco CUDA fija que produce compilaciones sin kernel en SM121 (n.° 49904).
  • ROCm: arquitectura gfx1250 habilitada (n.° 46516), atención del codificador AITER FP8 ViT (n.° 49937), experto compartido fusionado para puntos de control Quark DeepSeek-V4 (n.° 48044), correcciones de inferencia de puntos de control Quark GLM-5.2 (n.° 48886), lanzamientos de FillFunctor por decodificación de DSv3.2 eliminados en el bucle activo disperso de MLA (#44527), proyecciones B-preshuffled de atención FP8 para DSv4 (#46720), TML Inkling habilitado (#48841), configuración de float16 de select_state_update ajustada para MI325X (#50006), MRoPE estilo GPT-J arreglado y optimizado (#49906), corrección de precisión de reducción rápida en modo cudagraph (#46913), actualización de fp32 en caché de básculas de peso estáticas e8m0 (#47773), DMA por lotes para cargas de caché KV de CPU (#49843), corrección de precisión de escalado de EP elástico (#47206).
  • XPU: pase de fusión QK Norm + RoPE (n.° 49394), FP8 o_proj con fp8_bmm y transposición de escala de tiempo de carga (n.° 48334), ruta del kernel DeepSeek-V4 fuse_index_q SYCL (n.° 45991), cargas de operandos TD para MoE GEMM por lotes (n.° 46340), núcleos RMSNorm unificados con vllm_c (n.° 46981).
  • CPU: núcleo MoE fusionado INT8 para CPU Arm (#48637), optimización de inferencia s390x con oneDNN INT8 GEMM (#50219), ruta de conversión GDN optimizada para decodificación especulativa (#48577), granito-4 habilitado (#47641), FAST_EXP para Power (#49571), núcleos de CPU actualizados a la última versión (#50387), correcciones de compilación de macOS (#49021, #50915).

Servicio y distribución a gran escala

  • Marco de tolerancia a fallos (simplificado) para implementaciones de LB externo DP+EP (#44428).
  • Elastic EP: preparación asíncrona (#47288) y corrección de transferencia de peso no contigua (#50641).
  • Desagregación de P/D: NIXL P/D para modelos híbridos MLA+SSM (#49762), tamaños de bloques de P/D heterogéneos NIXL para modelos híbridos (#49612), enrutamiento de lectura de precarga/decodificación de TP<->DP heterogéneo de MoRIIO (#46116), desactivación de búsqueda opcional en decodificación de PD (#50498), ID de token de precarga reutilizados en la ruta de chat de decodificación (#48145), destokenización de procesamiento de transmisión (#47301), NixlPush omite un paso de protocolo de enlace adicional en D->P (#49345).
  • Correcciones: carrera de preferencia de P/D (#50297), fechas límite de arrendamiento de KV rebasadas en el reloj del trabajador (#50326), TP heterogéneo NIXL híbrido MLA+mamba (#49297), equilibrio de carga interno de LB (#49204).
  • Mooncake: prepare_value vectorizado en la ruta de carga KV (#48531), visitas externas completas redirigidas en límites almacenados (#49481).
  • Conectores de caché de codificador: has_pending_push_work (#49582).
  • Comunicadores: enlaces de ciclo de vida de puntos de control de procesos, comenzando con FlashInfer (#46877).

Cuantización

  • Nuevas capacidades: integración FP4 Qutlass para tensores comprimidos (#43229), CuTeDSL MoE para ReLU2 NVFP4 (#49580), soporte lineal MXFP8 en INC (#47514), AutoRound W4A16 MoE y MXFP4 lineal/MoE en XPU (#47124), modo cuantitativo KV para TurboQuant (#50533), emulación ModelOpt FP8 en SM80 (#50019), --linear-backend premiado por ModelOpt W4A16 (#50273).
  • Puntos de control: soporte de tensores comprimidos para DeepSeek-V4 (#41276) y Kimi-K3 (#50500); find_matched_target prioriza las coincidencias de nombres fusionados (#49483).
  • Refactorización de MoE: FusedMoE renombrado a FusedMoEFactory (#44941), MoeWNA16 migró al esquema de Oracle MK (#44120), Quark w8a8-int8 (#46765) y los backends MXFP4 aiter/emulation (#49348, #48949) se movieron a abstracciones del kernel, CT WNA16 Métodos Marlin/MoE fusionados (#44570), cobertura de CI de Quark W4A8 (INT4-FP8) MoE (#48050).

API y interfaz

  • Interfaz Rust: plano de control gRPC con informes de estado del motor (n.° 48992), RPC de control de abortos (n.° 49255), descubrimiento de servidores y modelos (n.° 49491) y descubrimiento de fuentes de eventos KV (n.° 50033); vllm-bench integrado en vllm-rs y vllm CLI (#48930) con delegación opcional de Rust para vllm bench serve (#50081); corte de tensor multimodal de copia cero (#48781), tensores multimodales en marcos auxiliares (#49341), --limit-mm-per-prompt (#49604), codificación de tokenizador de texto ordinario (#49992).
  • APIs: soporte Cohere chat v2 API (#47189), cache_salt en Anthropic Messages API (#49498), llamadas estrictas a herramientas y decodificación restringida para GPT-OSS Harmony (#45560), analizador Mistral basado en motor unificado para llamadas de razonamiento y herramientas (#48947), stream_interval expuesto como parámetro de muestreo por solicitud (#49754), parámetros de muestreo adicionales para la traducción API (#45839), diarized_json para MOSS-Transcribe-Diarize (#48543), marcas de tiempo acumulativas de fragmentos de voz a texto (#41131).
  • Multimodal: selección del algoritmo hash mm a través de CLI (#49686), simultaneidad del decodificador PyNvVideoCodec configurable (#49753), parámetros RFC 2397 aceptados en URL de datos base64 (#48973).
  • UX y validación: manejo de errores de solicitud estandarizado con una jerarquía VLLMError (#49665), ruido de registro de inicio reducido (#50590), anulaciones de tiempo de ejecución anidadas incompatibles rechazadas (#49247), validación mejorada de inicio de datos paralelos (#49124), validación de topología DCP (#49777), 400 en lugar de 500 para logprobs no numéricos (#49144), básico Texto insinuante conservado en los analizadores Python y Rust (#50403).
  • Puntos de referencia: solicitudes de sondeo en vllm bench serve (#49611).

Dependencias

  • PyTorch 2.13.0, torchvision 0.28.0, Triton 3.7.1 (#48155); Antorcha 2.13 para XPU (#48677) y CPU (#50412).
  • Transformers 5.14.1 (#49223), FlashInfer 0.6.15 (#48914) luego 0.6.16.post3 (#50892), AITER 0.1.16.post5 (#48683) luego 0.1.19 (#49361), NCCL 2.30.7 habilitando DeepEPv2 en la imagen vllm/vllm-openai (#45321), tpu-inference v0.25.0 (#49431) luego v0.26.0 (#50522), Helion 1.4.0 (#50307), NIXL y UCX actualizados en ROCm (#49251).
  • Compilación: vllm-flash-attn pasó a una confirmación compatible con C++ 20 para torch-nightly (#49326), pin de compilación FA2 estable ABI (#50474).

Depreciaciones y eliminaciones

  • Modelos eliminados: Plamo2 (#49729), Ouro (#49786).
  • Se eliminaron los argumentos max_num_partial_prefills y max_long_partial_prefills que ya no son compatibles (#49244).
