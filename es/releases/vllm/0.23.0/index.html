vllm v0.23.0

vLLM v0.23.0 Release Note

Tenga en cuenta que Minimax M3 aún no es compatible con esta versión. Siga la receta vLLM para obtener guías de uso para M3.

Destacados

¡Esta versión presenta 408 confirmaciones de 200 contribuyentes (63 nuevos)!

  • DeepSeek-V4 madura en todos los backends: tras su introducción en v0.22.0, DeepSeek-V4 recibió otro gran paso de fortalecimiento y optimización. Sus escasos metadatos MLA ahora están desacoplados de DeepSeek-V3.2 (#44699), obtuvo un núcleo de atención de generación TRTLLM (#43827), soporte EPLB para Mega-MoE (#43339), retención selectiva de caché de prefijo para caché KV de ventana deslizante (#43447) y una función de índice compartido para DSA MTP (#44420). El modelo también se separó de torch.compile (#43746, #43891), se refactorizaron sus rutas de atención y RoPE (#44569, #44262, #43926) y se agregó una ruta de decodificación de atención XPU (#42953).
  • Model Runner V2 se expande a modelos más densos: MRv2 ahora está seleccionado de forma predeterminada para modelos densos Llama y Mistral (#43458), además de Qwen3. Obtuvo una muestra FlashInfer (#42472), gráficos CUDA rompibles (#44050), eliminación de burbujas paralelas a tuberías (#42187), soporte de tamaño de bloque de kernel para modelos híbridos (#38831) y Gemma 4 MTP (#43241).
  • La interfaz Rust crece: La interfaz experimental Rust agregó un punto final de transmisión generate (#43779), puntos finales dinámicos LoRA (#43778), puntos finales /version (#43854) y /server_info (#43942), un enlace de extensión de servidor-enrutador (#43774), encabezados de ID de solicitud (#43883), y muchos analizadores de herramientas nuevos (InternLM2 #43481, hy_v3 #43872, Phi-4-mini #44213, Gemma4 #43850).
  • Gemma 4: Se agregó soporte para Gemma 4 Unified sin codificador (#44429) y Gemma 4 MTP (#43241), además de numerosas correcciones de precisión y de inicio.
  • Compatibilidad con Transformers v5: vLLM ahora apunta a Transformers v5, con procesadores MiniCPM-V/O suministrados (#44282) y correcciones de compatibilidad para Sarvam (#38804) y Voxtral (#44559).
  • Descarga de caché KV de varios niveles: el marco de descarga obtuvo un nivel secundario de almacén de objetos (#41968), HMA habilitado de forma predeterminada para conectores compatibles (#41847), compatibilidad con niveles para modelos HMA (#44287) y una política de descarga por solicitud a través del enlace de ciclo de vida on_new_request (#43205).
  • Analizador unificado: el razonamiento y el análisis de llamadas a herramientas ahora están unificados detrás de una única interfaz Parser.parse() (#44267), con el analizador de respuestas migrado a ella (#42977).

Soporte de modelo

  • Nuevos modelos: Step-3.7-Flash (#43859), Cosmos3 Reasoner (#43356), Gemma 4 Unified sin codificador (#44429), JetBrains Mellum v2 (#43992), Granite Speech Plus (#43519), Cohere Mini Code (#44707).
  • Gemma 4: soporte unificado sin codificador (n.° 44429), MTP (n.° 43241), capas lineales ViT nativas (n.° 43798), incrustador de visión excluido de la cuantificación (n.° 44571) y correcciones para MTP en TP>1 (n.° 43909), falta de coincidencia de tablas de bloques en concurrencia (n.° 43982), falla de inicio del procesador de transformadores (n.° 44232) y Inicio de CPU (#44615).
  • Transformadores v5: procesadores MiniCPM-V/O del proveedor (#44282), compatibilidad con Sarvam (#38804), Voxtral fetch_audio para transformadores≥5.10 (#44559).
  • Correcciones y mejoras del modelo: precisión del deepstack de Qwen3-VL/Qwen3-omni-thinker bajo torch.compile (#43617), EVS para Qwen3-VL (#44205), carga de PP GLM-5.1 (#42944), logits del procesador GLM-4.1V (#43575), cargador de video GLM-4.6V (#44417), Inicio OlmoHybrid (n.° 43846), eliminación de código remoto HyperCLOVAX (n.° 43860), factor giratorio Bailing-MoE (n.° 43770), error de clave residual de PP Step3 (n.° 37622), video MiniCPM-V-4.6 (n.° 44509), desagregación de audio MiniCPM-O (n.° 38053), preprocesamiento por lotes MiniCPM-V (#44609), inicio de FunASR-Nano (#44215), método de enrutamiento Cohere (#44021), metadatos de Kimi-K2.5 FlashInfer ViT (#44493).
  • Multimodal: cargador de video registrado con selección automática para VLM (#44126), manejo de elementos multimodal O(log n) por paso (#44212), codificación de imágenes locales en puntos de referencia (#43843), conjuntos de datos de referencia de imágenes personalizadas intercaladas (#43636).
  • Agrupación/Clasificación: excepciones adecuadas para la agrupación de UX (#44593), extra_repr() para clases de agrupación (#44805), corrección de agrupación de nombre de adaptador LoRA (#44410), punto de entrada de puntuación generativa reajustado (#44153), pruebas unitarias de agrupación ampliadas (#43818, #44471).
  • Refactor: AutoWeightsLoader para InternLM2 (#38278).

Núcleo del motor

  • Model Runner V2: predeterminado para modelos densos Llama y Mistral (#43458), muestreador FlashInfer (#42472), gráficos CUDA rompibles (#44050), grupo de gráficos CUDA dedicado de Eagle eliminado (#44078), eliminación de burbujas paralelas a tuberías (#42187), tamaño de bloque de kernel para modelos híbridos (#38831), puesta a cero de bloques KV recién asignados para caché KV híbrido + FP8 (#43990), lote real max_seq_len para metadatos de atención (#43991), corrección de tasa de aceptación de muestreo de rechazo (#40651), limpieza de KVConnector + PP (#43732), calentamiento/captura de relleno previo del especulador (#44253).
  • Decodificación especulativa (DFlash): DFlash causal (#43445), asignación adecuada de ranuras de anticipación (#43733), corrección de corrupción de caché de prefijo (#42971); selección independiente de backend de atención del redactor (#39930), grupo de atención dividido por num_heads_q para borradores (#43543), almacenamiento en caché de anticipación de EAGLE/MTP en la máscara de caché de prefijo SWA (#44082).
  • Atención e híbrido/Mamba: FlexAttention/FlashAttention diseños de bloques numéricos primero (#42095), registro de backend de relleno previo de OOT MLA (#43325), sincronización ascendente de FlashAttention (#44065), refactorización del módulo de atención LINEAR de Mamba (#43556), corrección de atención lineal + MLA corrupta (#43961), unificación de estado de conversión de KDA (n.° 44539) y fusión de puerta/cumsum (n.° 43667), Mamba SSD do_not_specialize (n.° 43803), enrutamiento dividido de precarga+decodificación mixto Qwen3.5 (n.° 44700), kernel de puerta MiniMax-M2 (n.° 38445).
  • Caché y programador de KV: KVCacheSpec conectable (#37505), scheduler_block_size insertado en KVCacheManager/Coordinator (#44165), max_concurrent_batches movido a VllmConfig (#44274), validación de configuración que rechaza 0/perillas negativas (#43794, #44057, #44207), escala de caché KV texto estándar eliminado de la carga de peso (#43167).
  • Núcleo: Congelar el recolector de basura en los trabajadores después del inicio del modelo (#44363), transferencia escasa de peso NCCL para actualizaciones locales (#40096), manejo elegante de fallas de carga externa de spinloop (#43659), desuso de funciones programadas (#43358).

Seguridad

  • Cifrado de transporte: compatibilidad con SSL/TLS para el supervisor de datos paralelos (#43688).
  • Untrusted-input hardening: Rechaza ID de tokens fuera de vocabulario antes de que alcancen la ruta de prueba de registro de GPU (#44042) y corrige un pánico de límite de caracteres UTF-8 en el detokenizador incremental Rust en entradas con formato incorrecto (#44620), los cuales previenen fallas provocadas por solicitudes.
  • Validación de parámetros: Rechaza valores thinking_token_budget no válidos (#43402), perillas enteras ParallelConfig no positivas (#44057), campos de configuración con valor cero (#43794) y max_num_scheduled_tokens fuera de rango (#44207).
