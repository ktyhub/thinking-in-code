vllm v0.22.0

Destacados

¡Esta versión presenta 459 confirmaciones de 230 contribuyentes (63 nuevos)!

  • Madurez de DeepSeek V4: DeepSeek V4 recibió un paso de endurecimiento importante en este ciclo: el modelo se reorganizó en un paquete vllm/models/deepseek_v4/ dedicado (#43004, #43039, #43073, #43077, #43149), obtuvo soporte MoE fusionado con NVFP4 (#42209), gráfico CUDA completo + por partes (#42604) y decodificación especulativa de MTP. (#43385). Un gran conjunto de núcleos fusionados (MegaMoE, mhc, Q-norm, indexador, MLA disperso) y correcciones de paridad ROCm llegaron junto con correcciones de precisión (#42810, #43710).
  • Model Runner V2 avanza hacia el valor predeterminado: MRv2 ahora es el valor predeterminado para los modelos densos Qwen3. vLLM recurrirá a MRv1 para funciones que aún no son compatibles con MRv2 (#39337). recarga de peso en modo de suspensión (#42673), update_config (#42783) y capas de caché KV compartidas (#35045), además de muchas correcciones de corrección.
  • Interfaz experimental Rust: se implementó una nueva integración de front-end Rust (n.° 40848), con la implementación trasladada al árbol (n.° 43283) y un supervisor DP para el servicio de datos en paralelo (n.° 40841).
  • Invariancia de lotes, más rápido: la inferencia invariante de lotes obtuvo soporte de Cutlass FP8 para una **mejora de latencia de extremo a extremo 28.9% (#40408), soporte de modo de compilación en SM80 (#42456) y una ruta lineal de NVFP4 Cutlass (#39912).
  • Descarga de caché KV de múltiples niveles: un nuevo marco de descarga de caché KV de múltiples niveles (#40020) con un sistema de archivos de nivel secundario Python (#41735), compatibilidad con DSv4 (#43142) y descarga de disco Mooncake (#42689) extiende la descarga más allá de la memoria de la CPU.

Soporte de modelo

  • Nuevas arquitecturas: MiniCPM-V 4.6 (#41254), InternS2 Preview (#42705), OpenVLA (#42654), MolmoWeb hf_overrides docs (#42163); EXAONE-4.5 alineado con la actualización de Transformers (#42246).
  • Decodificación especulativa: backend de proponente invocable personalizado (#39487), especuladores EAGLE-3 post-norma (#42764), especuladores peagle (#41826), modelos de atención híbrida en extract_hidden_states (#39949), especulación sin MTP para NemotronH (#43130), pesos MTP compartidos en MRv2 (#42538).
  • DeepSeek V4: NVFP4 MoE (n.° 42209), gráfico CUDA completo/por partes (n.° 42604), MTP (n.° 43385), refactorización del paquete de modelos (n.° 43004, n.° 43039, n.° 43073, n.° 43077), refactorización del compresor MLA + disperso (n.° 43149, n.° 43710), movimiento del kernel de preparación de entrada MegaMoE (#43632).
  • Qwen3.5/3.6: aplanamiento de proyección de salida de GDN (#42311), corrección de GatedDeltaNet Marlin TP≥2 (#36329), gráfico CUDA completo de ViT (#42151), carga de peso de runai-streamer para Qwen3.5/MTP/Qwen3-VL (#42521, #42716), semántica de exp2 de precarga de fragmentos de KDA (#43195).
  • Gemma3/Gemma4: corrección de fallos de procesamiento por lotes de imágenes de resolución mixta (n.º 42217), corrección de cierre de enrutamiento MoE (n.º 42250), corrección de corrupción flotante del analizador de herramientas (n.º 42128), codificador de visión por lotes para imágenes/vídeo (n.º 43169), corrección de GPU múltiple (n.º 42630).
  • Kimi-K2.5: omite la conversión de tipo d vision-tower bajo cuantización (#42869), corrección de tipo d mm_projector (#42081).
  • Cohere: habilite Cohere MoE (#43143), paralelismo de canalización para Cohere Vision (#42819).
  • Llamada de herramientas: analizador de herramientas Apertus (n.° 41154), reajuste de resolución Qwen3Coder anyOf/oneOf/$ref (n.° 37831), coerce_to_schema_type compartido en los analizadores MiniMax-M2 / DeepSeek-V3.2 / Seed-OSS (n.° 43006, n.° 43019, n.° 43140).
  • Gráfico ViT CUDA: Qwen2-VL (#41736), codificador Step3-VL (#42224), Qwen3.5 (#42151), metadatos FlashInfer para atención de visión Qwen2.5-VL (#42787).

Núcleo del motor

  • Model Runner V2: Oracle Qwen3 denso por defecto (n.° 39337), pesos de recarga en modo de suspensión (n.° 42673), update_config (n.° 42783), capas de caché KV compartidas (n.° 35045), muestreo de gumbel FP32 (n.° 41775), respaldo automático a MRv1 con conectores (n.° 42955), corrección de logprob_token_ids (n.° 43125, n.° 41761), corrección del tamaño de Prompt-logprobs (n.° 42778).
  • Descarga de KV: marco de varios niveles (#40020), nivel secundario del sistema de archivos Python (#41735), compatibilidad con DSv4 (#43142), seguimiento de descarga de niveles (#42529), preferencia del diseño HND (#41928), reset_cache() (#41956), seguimiento por solicitud (#42507), solución de aplazamiento de almacenamiento (#41945).
  • Refactorización MoE: ExpertMapManager (#41046), los expertos se trasladaron a experts/ (#42334), alias RoutedExperts para FusedMoE (#40735), refactorización EPLB para FusedMoE (#41055).
  • Mamba: refactorización del módulo de atención (n.° 41126), calentamiento del kernel SSD de Mamba2 (n.° 39822), caché bf16 SSM (n.° 41680), kernel fusionado con posprocesamiento de estado del lado de la GPU (n.° 40172), ejecución de extensiones de token único como decodificaciones (n.° 42430).
  • Eventos KV: emite metadatos de caché KV (#40984).
  • Asignador: habilitación manual del asignador de cumem (#33648), devolución de llamada gratuita con reconocimiento de flujo (#43020).
  • elastic-EP: etapa/compromiso del método cuantitativo MoE en la reconfiguración (#40881).

Hardware y rendimiento

  • NVIDIA Blackwell / SM12x: FlashInfer b12x MoE + FP4 GEMM para SM120/121 (#40082), FP8 CUTLASS por tensor en SM12.1 (#41215), head_dim=512 para atención FlashInfer TRTLLM (#38822), precarga de FlashInfer Blackwell GDN (#40717), núcleo precargado de GDN para SM100 (#43273).
  • Rendimiento: Cutlass FP8 invariante por lotes (+28.9% E2E) (#40408), preprocesamiento de relleno CutlassFP8 (+13.5% TTFT) (#42651), núcleo cuantitativo NVFP4 acolchado (+2.4–5.7% E2E) (#42774), eliminación de sincronización GPU<->CPU 1/n (#41429) y 4/n (#42347), RoPE fusionado+KVCache+q_concat para MLA (#40392), optimizaciones MLA compute_prefill_context / _v_up_proj (#42460, #42561), penalizaciones del kernel Triton (#40657), do_not_specialize en FP8 RoPE fusionado (#42849), CUDA COMPLETO captura de gráfico para decodificación TRITON_MLA (#42885).
  • AMD ROCm: funcionalidad DSV4 + correcciones de precisión (#42810, #43679 Tilelang MHC), kernels MLA Triton dispersos flash (#41812), logits MQA paginados con gluon en gfx950/MI355X (#42062), fusión RMSNorm+Quant para gfx950 (#41825), limpieza de backend de AITER FA (#41942), backend XGMI para conector MoRI (#41753), anulación de tamaño mínimo QuickReduce (#41675), DSV4 MTP (#43385).
  • CPU/RISC-V: núcleos de atención optimizados para RVV para RISC-V Vector Extension (#40119) con VLEN=256 (#42943), GDN fusionado para CPU AMX (#42707), MXFP4 W4A16 MoE (#41922), Triton experimental + MRv2 en CPU (#43225), utilización mejorada de subprocesos de CPU (#42666), --cpu-distributed-timeout-seconds (#42968).
  • Intel XPU: soporte GPTQ int4 (#37844), mxfp8 MoE (#41918), cuantificación escalada en bloques FP8 (#42952), comportamiento colectivo de operaciones personalizadas (#41354), múltiples núcleos de atención dispersa (#37888), enrutamiento MoE topk + respaldo MXFP4 (#42951), ruta CT W4A4 MXFP4 (#38896), reducción de la sobrecarga del host XPU MoE (#42915).
  • Kernel ABI: migración continua a ABI estable de libtorch: 5/n (#42339), 6/n (#42663), 7/n (#43209).
  • Experimental: gráfico CUDA rompible (#42304).

Servicio a gran escala

  • Servicio desagregado (NIXL): TTL de renovación de arrendamiento para bloques KV en P (n.° 41383), cumplimiento de la política de fallas de protocolo de enlace (n.° 40364), soporte de GDN para PD con NIXL (n.° 41869), solución de TP>8 de múltiples nodos (n.° 39907), solución de selección de host de canal lateral (n.° 41806).
  • Mooncake: descarga de disco en MooncakeStoreConnector (#42689), compatibilidad con HMA para DSV4 (#42828), métricas de operación (#43392), propagación de fallas de carga (#42788), aciertos completos alineados con bloques (#43494), manejo de finalización después de la preferencia (#43281).
  • Datos paralelos: Supervisor DP (n.° 40841), recuentos de solicitudes de publicación en el inicio del paso del motor (n.° 41626), reenvío del encabezado X-data-parallel-rank (n.° 42330).
  • EPLB: cambie el comunicador EPLB predeterminado (n.° 43110), corrección de inicio del contenedor VLM (n.° 39805), elimine el torch.accelerator.synchronize() inactivo (n.° 40733).
  • LoRA: kernel Triton de un solo disparo para MoE LoRA (#42290), adaptadores MoE LoRA 2D y 3D simultáneos (#42242), memoria de peso 2D reducida bajo EP (#42737), corrección de cuadrícula de alineación del núcleo MoE LoRA (#40131).

Cuantización

  • MXFP4: capas lineales + integración de tensores comprimidos (#41664), CPU W4A16 MoE (#41922), XPU mxfp8 MoE (#41918).
  • NVFP4: DeepSeek V4 MoE fusionado (#42209), ModelOpt W4A16 NVFP4 MoE fusionado + envío de precisión mixta (#42566), NVFP4 Cutlass lineal invariante por lotes (#39912), solución de enrutamiento MoE monolítico FlashInfer TRTLLM NvFP4 (#43223), solución de fragmentación de MoE TRTLLM NVFP4 (#43599).
  • Quark: carga los puntos de control Quark NVFP4 (#35859), corrección de salida de basura W8A8 INT8 en Step-3.5-Flash (#41892), refactorización de Oracle W4A4 (#41436).
  • AutoRound: compatibilidad con W4A16 (#39778).
  • ModelOpt: Mapeo de prefijos cuantificados VLM Qwen3.5/3.6 (#42546).
  • Marco: reelaboración de quantization_config para usar QuantKey con anulación de activación (#41566), MoE W4A8 CT migrado a Oracle (#42680), AWQ Marlin MoE a Oracle modular WNA16 (#42483), consolidación de GPTQ (gptq_marlin → auto_gptq) (#38288).

API y interfaz

  • Interfaz Rust: integración (#40848), movimiento de código en el árbol (#43283), nuevo tipo de ID de llamada de utilidad (#43405), extracción de ruta simplificada AuthenticationMiddleware (#43426).
  • Respuestas API: compatibilidad con chat_template_kwargs (#42272), solución de fusión de mensajes (#42189), solución de armonía de canal/destinatario vacío (#35540).
  • Completaciones: compatibilidad con thinking_token_budget (#42116) con corrección de condición invertida (#41674); mapa reasoning_effort a enable_thinking (#43401).
  • Frontend: lado truncado para terminales OpenAI (#43260), normalización de reasoning_content → reasoning (#42664), integración de fastokens reelaborada (#43168), puntos de entrada consolidados de voz a texto (#42370, #42274), consolidación de búsqueda de haz a través de BeamSearchMixin (#42946), plantilla de chat de puntuación/reclasificación instrucciones (#42412).
  • Auth: autorización de clave API para terminales /v2 (#42594).
  • API sin conexión: agrupación de API sin conexión dividida en PoolingOfflineMixin (n.° 42267), división de inferencia sin conexión API/utils (n.° 43553).

Construcción y dependencias

  • Las compilaciones de ruedas CUDA 12.9 cambiaron a la base PyTorch manylinux_2_28 (#41668).
  • FlashInfer pasó a v0.6.11.post2 (#41711); nvidia-cutlass-dsl a 4.5.2 (#42991, #43230, #43745); Guía para 1.7 (#42150); triton_kernels degradado a v3.5.1 para gpt-oss (#43135).
  • Compilación de interfaz Rust: dependencia de setuptools-rust (#43287, #43377), protoc anclado en las etapas de compilación de rust (#43292).
  • Docker: destino vllm-openai no root (n.° 40275), compilación mooncake-transfer-engine desde el origen (n.° 42114), compatibilidad con AINIC y Thor NIC (n.° 40453); La instalación exclusiva del Python se ha hecho opcional (#42293).
  • vllm-tpu: deshabilita el aislamiento de compilación para departamentos CUDA (#43038), solución de compilación tpu-inference docker (#43360).
  • Se agregó la dependencia de backend de humming MoE, se revirtió y luego se restauró con la corrección del tiempo de ejecución de CuPy (#42540, #43492, #43530).

Depreciaciones y eliminaciones

  • Se eliminaron ubicaciones antiguas de get_tokenizer y resolve_hf_chat_template (#35024).
  • Las variables de entorno marcadas ahora están cubiertas por --moe-backend / --linear-backend (#43148).
  • Se eliminaron los argumentos de precarga de MLA obsoletos (#42555).
  • Se eliminaron los kernels CUDA muertos y el código muerto (#42767, #42889, #43144).
