vllm v0.21.0

Destacados

¡Esta versión presenta 367 confirmaciones de 202 contribuyentes (49 nuevos)!

  • Transformers v4 en desuso: esta versión desaproba formalmente la compatibilidad con transformers v4 (#40389). Los usuarios deben migrar a transformers v5.
  • Requisito de compilación de C++20: vLLM ahora requiere un compilador compatible con C++20 para ser compatible con PyTorch (#40380). Este es un cambio de compilación importante.
  • Descarga KV + Asignador de memoria híbrida (HMA): el subsistema de descarga KV ahora se integra con el Asignador de memoria híbrida, incluida la compatibilidad con grupos de ventanas deslizantes del lado del programador y la habilitación completa de HMA (#41228, #41445, #39571).
  • Decodificación especulativa con presupuesto de pensamiento: la decodificación especulativa ahora respeta los presupuestos de razonamiento/pensamiento, lo que permite una decodificación de especificaciones correcta para los modelos de razonamiento (#34668).
  • Backend TOKENSPEED_MLA en Blackwell: un nuevo backend de atención TOKENSPEED_MLA está disponible para precarga y decodificación de DeepSeek-R1/Kimi-K25 en GPU Blackwell (#41778).

Soporte de modelo

  • Nuevas arquitecturas: MiMo-V2.5 (#40967), Laguna XS.2 (#41129, #41880), Moondream3 (#32325), Qianfan-OCR (#40136), Cohere MoE (#40817), Cohere Eagle (#42078).
  • Decodificación especulativa: EAGLE para Mistral (#41024), Gemma4 MTP (#41745), MTP para MiMo-V2.5 (#41905), Cohere Eagle (#42078).
  • DeepSeek V4: compatibilidad con AMD/ROCm (n.° 40871), paralelismo de canalización (n.° 41694), esfuerzo de razonamiento max (n.° 40982), correcciones de entrega desagregadas (n.° 41957).
  • Llamada de herramientas: analizadores de herramientas y razonamiento Cohere (#40422), analizador de herramientas LFM2/2.5 (#39243).
  • Gemma3/Gemma4: compatibilidad con la variante hidden_act (#40588), corrección de paralelismo de canalización (#40786), correcciones de MoE (#41206, #41574, #41401), corrección de fallas del analizador de herramientas (#41991, #42188).
  • Model Runner V2: compatibilidad con el modelo híbrido Qwen3.5/Mamba (n.° 35520), compatibilidad con logprob_token_ids (n.° 40559).
  • Gráfico CUDA: compatibilidad con gráficos ViT CUDA para Qwen2.5-VL (#40830).
  • Compatibilidad: Proveedor HCXVisionConfig para Transformers v5 (#38447), soporte de punto de control heredado rope_type (#41734).

Núcleo del motor

  • Descarga de KV + HMA: grupos de ventanas deslizantes del lado del programador (#41228), habilitación completa de HMA (#41445), HMA multiconector (#39571), finalización de almacenamiento por trabajo (#39186), compatibilidad con DCP/PCP en OffloadingConnector (#41549), MooncakeStoreConnector para descarga distribuida de KV (#40900).
  • Decodificación especulativa: soporte de pensamiento presupuestario (n.° 34668), selección de backend de atención del redactor independiente (n.° 39930), soporte de modelo multimodal con advertencia (n.° 41752), eliminación de asignación por paso (n.° 41043).
  • Model Runner V2: corrección de la tasa de aceptación de muestreo de rechazo (n.° 40651), omitir la reconstrucción de metadatos antes del borrador previo (n.° 40410), reconstruir los metadatos entre los pasos de decodificación del borrador (n.° 41162), soporte híbrido Qwen3.5/Mamba (n.° 35520).
  • Enrutamiento: reemplace la reproducción de enrutamiento con caché del dispositivo y canalización D2H asíncrona (#39917).
  • Ray: RayExecutorV2 habilitado de forma predeterminada (#41421), corrección de colisión de nombre de actor para DP > 1 (#40398).
  • Estabilidad: pausa de dos fases para evitar el punto muerto del programador (#39366), envoltorios de tokenizadores HF seguros para subprocesos (#41181), prevención de OOM a través de max_split_size_mb durante la carga del modelo (#41268).
  • Compatibilidad con IndexCache para modelos DSA (#37735).

Hardware y rendimiento

  • NVIDIA Blackwell: backend TOKENSPEED_MLA para DSR1/Kimi-K25 (#41778), núcleo empaquetado cuantitativo de grupo FP8 por token más rápido (#41326), FP8 en NVIDIA Thor/SM110 (#39712), CUTLASS escalado en mm para tamaños no compatibles (#41868).
  • Rendimiento: muestreo FlashInfer top-k/top-p habilitado de forma predeterminada (#40376), atención FlashInfer FP8 para ViT (#38065), buffers dequant compartidos TurboQuant (#40941), AllPool.forward 51% más rápido (#41163), eliminación de sincronización GPU<->CPU en pooling (#41433) y atención (#41434), numpy serialización de incrustación de copia cero (#41681), omisión de procesador multimodal para solo texto (#41246), fusión de TP asíncrona FlashInfer FP8 (#39505), fusión GEMM all-gather NVFP4 para AsyncTP (#41882), volver a habilitar la fusión allreduce+RMS para DP/PP (#41458), DeepSeek bf16→fp32 vía torch.mm (#41300), MLA persistente para backend disperso (#41990), captación previa de punto de control de tensores de seguridad configurables (#41499), kernel mhc_post_pre fusionado (#41536), kernel cuantitativo de grupo W8W8 de cuadrícula 2D (#42153), ordenamiento de memoria relajado para intercambios de caché KV (#39306).
  • AMD ROCm: ROCm 7.2.2 (n.° 41386), DBO (optimización dinámica por lotes) (n.° 34726), AITER Fusioned Allreduce+RMSNorm (n.° 37646), Fusioned Shared Expert (FSE) para Qwen3-Next (n.° 39280), DeepSeek V3.2 TP4 AITER MLA (n.° 41835), atención lineal de GDN fusion (#40711), eliminar copias redundantes del buffer MoE en AITER (#41713), soporte de descarga de CPU (#40549), actualización de DeepEP API (#39721), limitar el tamaño del bloque de atención paginado de Triton para corregir el OOM de memoria compartida (#38502).
  • CPU: Atención FP8 para AMX/AVX-512 (#39445), FP8 W8A16 lineal (#41186), FP8 W8A16 MoE (#41314), DNNL AVX2 W8A8 Int8 (#41318), Atención DeltaNet cerrada para Qwen 3.5/3.6 (#41025), Encuadernación automática de subprocesos RISC-V OMP (#40569).
  • Intel XPU: kernel de muestra Top-k/top-p (#39285), reducción total fuera de lugar (#41808), compatibilidad con LoRA (#38206).
  • IBM Power: backend de atención VSX (#40451).
  • FlexAttention: reactivado para el modo invariante por lotes (#40842).
  • MLA: backends de precarga de MLA resumidos, se eliminó la dependencia de cuDNN (#32623).

Servicio a gran escala

  • Servicio desagregado: transferencias de caché KV bidireccionales entre P y D (n.° 32553), rediseño de transferencia NIXL (n.° 40731), optimización de la sobrecarga de memoria EPLB (n.° 40013), conector NIXL elevado a 1.x (n.° 42364), Mooncake KVConnectorStats para observabilidad de transferencia (n.° 40414), notificación de rechazo de admisión previa del nodo P NIXL (n.° 41269), liberación de bloque KV para se saltó los rangos P (#40449).
  • DCP: Salida del paquete y LSE en DCP A2A (#41160).
  • MoE: interfaz PluggableLayer para corredores MoE fuera del árbol (#35178).
  • LoRA: compatibilidad inicial con paralelo experto (EP) (n.° 40867), corrección de fusión Qwen3.5 LoRA (n.° 37912).

Cuantización

  • NVFP4: compatibilidad con caché KV (#40177), núcleos de emulación Triton dequant/QDQ para Hopper y AMD (#40033), GELU en TRT-LLM NvFP4 MoE fusionado para Gemma4 (#41050), ModelOpt NVFP4 W4A16 (#41769), fusión GEMM all-gather de NVFP4 para AsyncTP (#41882), Corrección de carga de GLM4-MoE NVFP4 (#41755).
  • MXFP4: Tarareando el backend de MXFP4 MoE (#41083), corrección de FlashInfer CUTLASS MXFP4-MXFP8 MoE (#42089).
  • TurboQuant: modelo híbrido y soporte de cuantificación uniforme (#39931).
  • Tensores comprimidos: permitir configuraciones con ignoraciones no explícitas (#41965).
  • FP8: Corrección de carga sesgada (#41424), autoajuste de FlashInfer deshabilitado temporalmente para mayor corrección (#41524).
  • DSV4: Kernel cuantitativo Indexer Q fusionado mejorado (#41428).

API y interfaz

  • Respuestas API: Llamada de función/herramienta de transmisión con required (n.° 40700) y opción de función/herramienta con nombre (n.° 41110), reenvío de elementos de salida con campos faltantes (n.° 41355).
  • Compatibilidad con OpenAI: campo system_fingerprint en las respuestas (n.° 40537), compatibilidad con partes de contenido prompt_embeds (n.° 40720), compatibilidad con defer_loading y tool_reference (n.° 40190), texto de solicitud renderizado en la respuesta de finalización del chat (n.° 42052), tolera contenido vacío en la elección forzada de herramientas (n.° 40148).
  • Llamada de herramientas: XGrammar 0.2.0 con etiquetas estructurales para llamada estricta de herramientas + razonamiento (#40894), analizadores de herramientas/razonamiento Cohere (#40422), analizador de herramientas LFM2/2.5 (#39243).
  • Tokenizer: Compatibilidad con Fastokens (#41741).
  • RLHF: /start_weight_update y /finish_weight_update API explícitos (#39212).
  • ASR: Solicitud de motor abortada al cancelarse (#41266).
  • Configuración: VLLM_SKIP_MODEL_NAME_VALIDATION env var (#34676), seguimiento de carga de pesos de modelo configurable (#41086), monitor de compilación Triton JIT (#40137).

Construcción y dependencias

  • Última hora: se requiere C++20 para la compatibilidad con PyTorch (#40380).
  • Última hora: Transformers v4 está obsoleto (#40389).
  • Tamaño de imagen Docker reducido en ~2.5 GB mediante descarga diferida de FlashInfer cubin (#41134).
  • Las ruedas CUDA 13.0 cambiaron a la base PyTorch manylinux_2_28 (#41416).
  • Rueda incluida DeepGEMM construida según Python para compatibilidad con CPython (#41516).
  • Metadatos de procedencia de la imagen del contenedor integrados (#40653).
  • tpu-inference actualizado a v0.19.0 (#41844).
  • El conector NIXL pasó a 1.x (#42364). *ROCm 7.2.2 (#41386).
