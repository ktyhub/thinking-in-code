#vllmv0.26.0

vLLM v0.26.0 Release Note

Destacados

¡Esta versión presenta 411 confirmaciones de 212 contribuyentes (61 nuevos)!

  • Nueva familia de modelos Inkling con una pila de soporte completo: modelado base (n.° 48799), compatibilidad con gráficos CUDA por partes (n.° 48822), atención relativa Hopper FA4 (n.° 48858), decodificación especulativa MTP=1 (n.° 48869), LoRA (n.° 48884) y cuantificación ModelOpt NVFP4 estándar (n.° 48990).
  • Impulso de rendimiento de DeepSeek-V4 entre proveedores: un kernel de enrutamiento especializado (2.94% E2E TPOT, #48660), fused_topk_bias (1.5–2x kernel, #47463) y eliminación de repetición/copia redundante (1.8% E2E TPOT, #48137), además de un compresor de dos etapas ROCm para precarga de HCA (#47718), disperso optimizaciones de decodificación/precarga (#48519, #48788, #46275) y decodificación especulativa de DSpark en AMD (#47419) y XPU (#47677).
  • fp32 lm_head para modelos de generación a través de head_dtype (#48390), extendido a la ruta LoRA (#48525) y con una ruta rápida ROCm torch.mm (#48688), lo que mejora la precisión de los cabezales de generación.
  • Backends de atención flexible: el backend de atención ahora se puede seleccionar por grupo de caché KV (#48012), y la compatibilidad con ventanas deslizantes ahora es una capacidad de backend explícita (#48011), lo que mejora la compatibilidad con modelos híbridos.
  • Descarga de KV y almacenamiento secundario por niveles maduró sustancialmente: descarga de métricas (#45958, #47666, #47679), manejo de eventos de propiedad de niveles (#46544, #47923), nivel secundario de almacenamiento de objetos con identidad de carga de trabajo (#47063, #47274, #48150), niveles con reconocimiento de réplica DP (#47987) y Conectores de caché de codificador (EC) que incluyen descarga de CPU (#42433, #47423).
  • La interfaz Rust obtuvo video multimodal (#47959) y audio (#48554), un analizador de herramientas Seed-OSS (#47741) y un puerto vllm-bench nativo (#48107).
  • Transformers 5.13.0 (#47867) con más modelos migrados al backend de modelado de Transformers: Olmo/Olmo2 (#48100), MistralLarge3 (#48153) y HunyuanVL (#47872).

Soporte de modelo

  • Nuevos modelos: Familia Inkling (#48799, #48822, #48858, #48869, #48884, #48990), BertForMaskedLM (#48463), RobertaForTokenClassification / XLMRobertaForTokenClassification (#47991), incrustación de n-gram LongCat-Flash-Lite (#47857), Cosmos3 Edge Registro de Reasoner (#48291) y Cosmos3-Super (#48211), TranslateGemma-12b-it (#41599).
  • Migraciones de backend de Transformers: Olmo/Olmo2 (#48100), MistralLarge3 a AutoWeightsLoader (#48153), procesador de transformadores nativo HunyuanVL para transformadores 5.13 (#47872).
  • GLM5.2: migre el soporte de secuencia paralela de MoE a la ruta no compilada con antorcha (#47881).
  • LoRA: FlashInfer MoE LoRA para modelos BF16 (#48632), LoRA para torre/conector en LlavaNextVideo (#48594), fp32 lm_head en la ruta LoRA (#48525), TrtLlmLoRAExperts optimizado (#48759).
  • Multimodal: respaldo automático al paralelismo de datos ViT cuando TP no está disponible (#49046).
  • Correcciones: puntuaciones de agrupación correctas para precarga fragmentada en torch.compile (#48901).

Núcleo del motor

  • fp32 lm_head para modelos de generación vía head_dtype (#48390); menor memoria para capturar tamaños de gráficos CUDA grandes (#48483); opción de persistencia y reutilización del resultado del perfil de memoria en todos los arranques (#47388); Carga mejorada de InstantTensor (#46868).
  • Atención: seleccione un backend de atención diferente por grupo de caché KV (#48012); ventana deslizante como una capacidad de backend explícita (#48011); Refactorización del diseño de caché KV que empaqueta K/V en el contenido atenuado en los backends (#44455); PCP de lote virtual MRV2 para MLA (#46570).
  • Decodificación especulativa: actualización de peso del borrador en tiempo de ejecución (#46725), borradores híbridos (SWA + atención completa) DFlash (#47914), soporte SWA para qwen-eagle3 (#47568), modelo borrador Gemma4-12B DSpark (#47216), DSv4 DSpark en AMD (#47419), kv_cache_dtype separado para speculative_config (#48787).
  • Descarga de KV: métricas de descarga básicas (n.° 45958), uso de caché dividido de la CPU en indicadores de lectura/escritura (n.° 47666) y retraso de búsqueda en niveles en histogramas de sincronización/asíncrono (n.° 47679), manejo de eventos de propiedad de niveles y eventos BlockStored (n.° 46544, n.° 47923), nivel secundario de almacenamiento de objetos con identidad de carga de trabajo (n.° 47063, #47274, #48150), niveles con reconocimiento de réplica DP (#47987), configuración blocks_per_chunk para grupos KV heterogéneos (#48878), variables de entorno de puerto/host predeterminado P2P (#47636).
  • Almacenamiento en caché: acierto parcial de caché de prefijo para modelos híbridos (n.° 46384), retención selectiva de caché híbrida (n.° 47782), informes de bloques reutilizados de caché de prefijo en modo de informe completo (n.° 45261).
  • Razonamiento: optimice TPOT para pensar en el presupuesto cuando se usa con decodificación especulativa (#46662).
  • RLHF: abstracciones de envío de entrenador con estado (#48042).
  • Correcciones: pérdida de memoria del host debido a new_block_ids no agotado (#44490), DSv3.2 + MTP + precisión de secuencia paralela (#48036).

Hardware y rendimiento

  • DeepSeek-V4: kernel de enrutamiento especializado (2.94% E2E TPOT, #48660), fused_topk_bias 1.5–2x (#47463), eliminación de copias/repeticiones redundantes (1.8% TPOT, #48137).
  • GEMM de enrutador MoE: GEMM de enrutador BF16x3 (#47973), GEMM de enrutador FP32 (#48335), GEMM de enrutador CuteDSL LL BF16 genérico (#42562); Núcleo modular TRTLLM BF16 MoE (#45182); escriba FlashInfer combine en la salida final (#47156).
  • Qwen: fusionar más RMSNorm + all-reduce en Qwen3.5 (#46998), reemplazar MoE all-reduce con reduce-scatter (#47006), optimización Qwen3.5 H20 (#48350), expandir la cobertura de calentamiento de Triton (#47546).
  • MLA: ruta MHA densa para secuencias cortas de MLA dispersas (#47327); Indexador de decodificación de contexto largo MiniMax-M3 en sm100 (#48582).
  • Kernels: kernel CUDA para ReLUSquaredActivation / relu^2 (#39058), registro diferido del kernel Helion (#48264), vectorizar _copy_mamba_state_block a uint64 (#48110), detener la conversión de logits a fp32 en el sampler (#48641).
  • ROCm: ruta rápida fp32 head_dtype torch.mm (#48688), kernel de compresor de dos etapas DSv4 (#47718), optimizaciones de precarga/decodificación dispersa (#48519, #48788, #46275), heurística de división MLA KV dispersa de DSv3.2 (#46832) y modo de gráfico MTP CUDA (#45149), MXFP8 GEMM para MiniMax-M3 (#46117), atención paginada escasa de AITER + decodificación de especificaciones para MiniMax-M3 (#47287, #47984), norma QK fusionada MiniMax-M2 + reducción total a través de AITER (#44849), kernel lineal HybridW4A16 (#40977), Qwen3-30B-A3B Fusión de tiempo de ejecución QK-Norm+RoPE+KV (#42749).
  • XPU: núcleos invariantes por lotes (#41934), soporte de diseño HND KV (#47975), decodificación de especificaciones DSpark para DSv4 (#47677), publicación de imágenes nocturnas/de lanzamiento (#47880, #48126).
  • CPU: decodificación especulativa DFlash para modelos GDN en CPU (n.° 46090), topología NUMA s390x (n.° 40714), compilaciones de rueda de CPU ARM64 nativas de macOS (n.° 48289); Optimización de la función matemática POWER VSX (n.° 47321) y compilaciones de IBM Power docker utilizando ruedas prediseñadas (n.° 46017).
  • Fusión distribuida: fusión cuantitativa RMS totalmente reducida FlashInfer MNNVL (#48064).
  • Compilación/ajuste automático: compilaciones de imágenes arm64 Blackwell SM10x/SM110 (#48041); omita el ajuste automático de CuTeDSL fp4_gemm de forma predeterminada (#48268).

Servicio y distribución a gran escala

  • Decode Context Parallel (DCP): soporte de atención híbrida (#40996), DCP + Eagle para backends Tokenspeed MLA (#48180).
  • Desglose de PD: precarga de canalización paralela de NIXL en modo push (#45880).
  • Conectores de caché de codificador: parámetros de transferencia EC (#42433) y conector EC de descarga de CPU (#47423).

Cuantización

  • Tarareando w[2-7]a[4,8] inferencia de solo peso con tensores comprimidos (#46390); cuantización int4 para el backend de emulación MoE (#48451); INT2 XPU lineal cuantitativo de solo peso (#47521).
  • NVFP4/MXFP4: Cuantización MoE en línea nvfp4_per_token (#48538), cuantización CuTe-DSL FlashInfer MXFP4 (#48417); memoria máxima limitada al reempaquetar los pesos de MoE FP4 para Marlin (#47851) y para la carga de peso de MoE NVFP4 (#46276).
  • MLA: soporte kv_cache_dtype_skip_layers (#47309).
  • ROCm: Núcleo lineal HybridW4A16 (#40977).

API y interfaz

  • Interfaz Rust: video multimodal (#47959) y audio (#48554), analizador de herramientas Seed-OSS (#47741), puerto nativo vllm-bench (#48107), manejo de continue_final_message con renderizador centinela (#47844).
  • Compatibilidad con OpenAI: bad_words en /v1/completions (n.° 46793), exponer logprob_token_ids en puntos finales OpenAI Python (n.° 43463), parámetro include_reasoning para modelos que no son Harmony (n.° 44301), completar num_cache_creation_tokens en respuestas de mensajes (n.° 48535).
  • Marco de complementos de endpoint (#47454); /abort_requests en el enrutador RLHF dev API (#47173); Backend de decodificación de video Deepstream (#42424); superposición de preprocesamiento y cálculo para agrupar modelos en inferencia fuera de línea (#47699).
  • UX: enteros legibles por humanos para más argumentos CLI (n.° 47608), barra de progreso de compilación CuTeDSL (n.° 48881), alcance/anotaciones de configuración del perfilador de GPU expandidos (n.° 37524), código de salida del trabajador de registro cuando un proceso finaliza inesperadamente (n.° 38641).
  • Estabilidad/corrección: maneja fallas de compilación de gramática sin bloquear el motor (n.° 47312), corrige la colisión de cadenas de tokens de logprobs desde espacios SentencePiece (n.° 48674).

Seguridad

  • Reemplace el caché de disco para eliminar la deserialización de pickle (#44549).
  • Se corrigió una carrera concurrente escasamente invariante que omitió la corrección de CVE (#48583).
  • Agregar validación de límites de recursos para eliminar los puntos finales (#47260); desinfectar las rutas de los archivos del servidor de las respuestas de error de validación (#46415); vinculó la lista de mensajes de finalización para evitar una distribución ilimitada del motor (#47845); guarde la compilación de expresiones regulares de lm-format-enforcer con un tiempo de espera (#47595).

Dependencias

  • Transformadores 5.13.0 (#47867), FlashInfer 0.6.14 (#47669), NIXL 1.3.1 (#47559), tpu-inference v0.24.0 (#47835), nvidia-cutlass-dsl 4.6.0 (#47442), vllm_xpu_kernels v0.1.11.1 (#48942).
  • FlashAttention 3 fijado al compromiso ABI estable de la antorcha (#47995); Compilación FlashMLA estable con ABI (#48174).

Depreciaciones y eliminaciones

  • Modelos eliminados: TeleChat (#47989), Persimmon y Fuyu (#48096).
