vLLM v0.25.0 Release Note

Destacados

¡Esta versión presenta 558 confirmaciones de 232 contribuyentes (64 nuevos)!

  • Model Runner V2 ahora es el predeterminado para todos los modelos densos (#44443). Basado en el soporte del modelo cuantificado de la versión anterior, MRv2 es ahora la ruta de ejecución estándar, con nuevo soporte para EVS (#46535), incrustaciones en tiempo real (#46762), almacenamiento en caché de prefijos para modelos híbridos Mamba (#42406), atención bidireccional de prefijo multimodal (#46942) y decodificación especulativa dinámica compatible con gráficos CUDA completos (#45953).
  • Se ha eliminado PagedAttention (#47361). La implementación de atención heredada se elimina ahora que los backends V1/MRv2 son la ruta estándar.
  • El backend de modelado de Transformers ahora es tan rápido como el vLLM nativo (#47187) y obtuvo compatibilidad con FP8 MoE (#46820), gráficos CUDA + correcciones de escalado integrado (#48010) y migración de GPTBigCode/Starcoder2 (#30966) y RoBERTa (#47452).
  • Nuevos modelos: LLaVA-OneVision-2 (#44785), Unlimited OCR (#46564, #47102), MOSS-Transcribe-Diarize (#47729), openai/privacy-filter (#41026) y Hy3 (#47192). GLM-5/DeepSeek-V3.2 aterrizó en el zoológico modelo (#46808) con ajuste GLM-5.2, y MiniMax-M3 obtuvo paralelismo de canalización (#45810) y compatibilidad con NVFP4 (#46756).
  • Nuevo Streaming Parser Engine (#46610): un marco unificado de análisis de razonamiento/llamada de herramientas, con un nuevo analizador Kimi k2.5/k2.6/k2.7 y puertos de seed_oss (#46314) y DeepSeek V4 (#45877). La interfaz Rust continúa madurando con HTTPS/mTLS (#45890), un supervisor DP (#47076) y rutas de control del perfilador (#46306).
  • Decodificación especulativa universal para vocabularios heterogéneos (TLI) (#38174), además de nuevos redactores DSpark (#46995) y DFlash (#46770, #46853).

Soporte de modelo

  • Nuevos modelos: LLaVA-OneVision-2 (#44785), Unlimited OCR (#46564) con un backend Triton R-SWA (#47102), MOSS-Transcribe-Diarize (#47729), openai/privacy-filter (#41026), Hy3 con sufijo de token y soporte de matriz de esquema JSON (#47192).
  • Familia GLM-5: GLM-5 / DeepSeek-V3.2 agregado al zoológico modelo (n.° 46808), puerta GLM-5.2 FP32 (n.° 47410), corrección posterior a la norma final de GLM MTP (n.° 47448), corrección de inicio de GLM4V (n.° 47155).
  • MiniMax-M3: paralelismo de canalización (#45810), análisis de razonamiento de transmisión (#45718) y tok_sparse_select de MSA que reemplaza los núcleos Triton (#47502).
  • Backend de Transformers: ahora tan rápido como vLLM nativo (n.º 47187), corrección FP8 MoE (n.º 46820), escalado de incrustación + corrección de gráfico CUDA (n.º 48010), migración de GPTBigCode/Starcoder2 (n.º 30966) y RoBERTa (n.º 47452), corrección M-RoPE mm_token_type_ids (n.º 46552), corrección de incrustación vinculada lm_head.bias (#46835).
  • Voxtral: migró al audio 1.11.5 común de mistral API (#46705) y corrección de bloqueo de retroalimentación de token en tiempo real (#44461).
  • Familia Gemma: correcciones de atención FA4/ventana deslizante de Gemma4 (#47217, #47332), corrección de quant_config de Gemma4 MTP (#47091); Paralelismo tensor de DiffusionGemma (#45719) y semántica de ventana de estabilidad HF (#45965).
  • Otras correcciones: LoRA central del lenguaje MiniCPM-V 4.6 (#46740) y corrección de cuadrícula de marcador de posición (#45918), tamaño de ventana deslizante Whisper agrupado (#47071, #47437), corrección de fallas del punto de control Mamba/Mamba2 sin architectures (#46037), correcciones de tamaño oculto de DeepSeek-V2 y estado oculto auxiliar (#46986, #46973).

Núcleo del motor

  • Model Runner V2: predeterminado para todos los modelos densos (#44443); EVS (n.° 46535), incrustaciones en tiempo real (n.° 46762), almacenamiento en caché de prefijo híbrido de Mamba (n.° 42406), atención bidireccional de prefijo multimodal (n.° 46942), correcciones de tabla de bloques/calentamiento de atención cruzada (n.° 46753, n.° 47308), corrección de fallas de Mamba2 (n.° 47428), contabilidad de espacios de programación (n.° 46974), limpieza de referencia de modelo en apagado (#47483), memoria limitada para solicitudes de problemas de registro grandes (#46746).
  • Decodificación especulativa: decodificación de especificaciones universales para vocabularios heterogéneos (TLI) (#38174); DSpark Drafter + soporte para puntos de control de especuladores (#46995, #47093); Selección de backend DFlash (n.° 46770), fusión RMSNorm por capa (n.° 46761), compatibilidad con CPU (n.° 44029), SWA+DFlash para MiMo (n.° 46104), dibujante Laguna XS.2.1 (n.° 46853); MTP para modelos híbridos Bailing (#44880); verificación de bloque para muestreo de rechazo (#46781); comunicación TP reducida para tokens de borrador (#46448).
  • Modo de suspensión: abstracción de backend en modo de suspensión conectable (RFC #34303, #44074) con indicadores de capacidad independientes del comunicador (#47243).
  • Atención: Se eliminó la restricción de tamaño de bloque de FlashAttention para modelos híbridos (#36701), backend FLASH_ATTN_MLA_SPARSE Hopper sparse-MLA (#46189), caché DCP + FP8 KV en decodificación MLA (#44044), núcleos de decodificación XQA (#43232).
  • Descarga de KV: plomería métrica por niveles (n.° 45959), solicitud de corrección del ciclo de vida (n.° 46284), búsqueda por lotes en C (n.° 46713), enumeración LookupResult (n.° 46363).
  • Varios: VLLM_GPU_SYNC_CHECK env var (#44800), infraestructura de semáforo VRAM (#44465), omisión de detokenización en la búsqueda de haz en línea (#46422), varias correcciones de desbordamiento de int32 en núcleos de muestra/atención (#46560, #47383, #47671).

Hardware y rendimiento

  • GLM-5.2 / DeepSeek: kernel fused_indexer_q_rope_quant Triton (1.9–3.3% rendimiento E2E) (#46862), reducción-dispersión MoE all-reduce (3.1–3.2% E2E) (#46635), fusión de operaciones para GLM5/DSV3.2 (#46876), caché token_to_req_indices para DSv4 (aceleración del kernel de 5 a 6 veces) (#47474), mejor kernel DSv4 MXFP8 (#47229), eliminación de operaciones redundantes (#47198, #46651).
  • NVIDIA/Blackwell: FlashInfer fusionado con reducción total ajustado para world_size=16 en GB300 (n.° 46392), NVFP4 restaurado con inicio cero de escala swizzled para recuperar el rendimiento de decodificación de Blackwell (n.° 45739), infraestructura de calentamiento CuTeDSL/FA4-MLA (n.° 46182), omitir top-K cooperativo en SM120 (n.° 47164), backend B12x para no controlado Ministerios de Educación (#43328).
  • Núcleos: Helion fused_qk_norm_rope (#44010) y silu_and_mul_per_block_quant (#43994), espacio de trabajo logits Triton MLA (#46819), optimización swap-AB para MoE fusionado (#36559), fp32 moe_sum vectorizado que admite cualquier top-k (#46643), bloqueo de eventos CUDA para evitar que el controlador esté ocupado (#47081).
  • AMD/ROCm: movido a antorcha ABI estable 2.11 (#47128); AITER FlashAttention MLA backend de precarga ROCM_AITER_FA (#45033); experto compartido fusionado para GLM-4.5/6/7 (#44313) y MiniMax-M3 (#46474, #46545); Optimización AITER MoE para DeepSeek-V4 (#46122); Reducción total personalizada de AITER en CudaCommunicator (#46065); Cuantización INT3 para reducción rápida (#45666).
  • Intel XPU: kernel lineal W8A8 FP8 con cuantificación de granularidad múltiple (n.° 43645), corrección de precisión de canalización paralela (n.° 47253), gráfico CUDA de lotes uniformes para FA2 (n.° 46555), ruta de modelos de prefijo mm a la atención de Triton (n.° 47688), C++ get_memory_info (n.° 47134).
  • CPU: MoE acelerado no cuantificado para AArch64 (#46353), corrección de bloqueo de macOS/Apple Silicon a través de OpenMP (#46769) y corrección de instalación rota (#47457), tensor comprimido w8a8 int8 MoE (#42920), Mamba ShortConv (#35059), precarga fragmentada + almacenamiento en caché de prefijo para Qwen3.5 (#46202), gelu más rápido a través de tanh AOR (#44639).
  • RISC-V: ruta RVV para W4A8 INT4 GEMM (#45269), BF16 en hardware VLEN=256 (#45243), presión LMUL reducida en INT4 LUT dequant (#47538). ENERGÍA: compatibilidad con fp16 en PowerPC (#46135).
  • Plataforma: get_memory_info independiente del acelerador (#44825).

Servicio y distribución a gran escala

  • Paralelismo de secuencia sin necesidad de DP, mejora del rendimiento de E2E % 1.9–5.0 (#47070).
  • Distribuido: memoria simétrica NCCL extendida a AllGather y ReduceScatter (#46703), FlashInfer all-reduce valores predeterminados a MNNVL en un solo nodo (#47219, #47589), backend de tolerancia a fallas para detectar fallas de todos los pares y evitar salidas corruptas (#43637).
  • Datos paralelos: precargas del acelerador basadas en el trabajo de precarga local (n.° 46532), rotación del desempate del balanceador de carga para evitar el sesgo del motor (n.° 47420), supervisor de DP a través de la interfaz Rust (n.° 47076), corrección de bloqueo de DP MTP (n.° 40589).
  • Desagregación de PD: implementación de nivel secundario (n.° 42285), compatibilidad con conector Mooncake GDN (Qwen3.5) + MLA (DeepSeek-V4-Flash) (n.° 46807), compatibilidad con NIXL Mamba1 (n.° 45019), fusión de MultiConnector kv_transfer_params (n.° 46777), campo de uso expuesto para servicio desagregado (n.° 42748).
  • DCP: compatibilidad con FlashInfer MLA (n.° 43729), compatibilidad con FLASHINFER_MLA_SPARSE (n.° 46076), correcciones de la base de registros de LSE (n.° 47079); Carga KV paralelizada de Mooncake (#45971) y corrección de búsqueda DCP>1 (#46855).
  • ROCm: DBO estabilizado de alto rendimiento para DP+EP (#46990), EPLB para Quark OCP MXFP4 MoE (#47220).

Cuantización

  • Inferencia de solo peso cuantificada por paquete de 2/3/5/6/7 bits (Humming) (#46389), cuantificación de caché KV por cabeza de token Triton INT4 (#40835).
  • NVFP4: descuantización de peso fusionada con cálculo en el kernel MoE MLP Triton (#44667), caché NVFP4 KV con ventana deslizante de salto de capas (#42890), compatibilidad con MiniMax-M3 ModelOpt NVFP4 (#46756).
  • FP8: relleno de pesos para cuantificación en línea por bloque (#44763); dejó obsoleta la antigua clase de cuantificación MoE en línea del FP8 (#44514).
  • Marlin: relleno de mosaico de hilo extendido a MoE (WNA16 + FP8/MXFP8) (#45703), int8 agrupado WNA16 MoE (#47154); FlashInfer MXINT4 MoE para SiLU cerrada (#46518).
  • Correcciones: regresión de selección de esquema int-quant de W8A8 (n.° 46860), incrustaciones cuantificadas vinculadas para ModelOpt Gemma4 (n.° 45544), falla de NVFP4+MTP en Qwen3Next (n.° 46316), precisión mixta de ModelOpt para configuraciones dispersas (n.° 47318), ruta CPU w4a8_int8 MoE (n.° 46739), error procesable en El tamaño del grupo y el TP no coinciden (#46230).

API y interfaz

  • Streaming Parser Engine (#46610): análisis de razonamiento/llamada de herramienta unificada con un nuevo analizador Kimi k2.5/k2.6/k2.7; Seed_oss portado (#46314) y DeepSeek V4 (#45877).
  • Compatibilidad con OpenAI: herramientas de espacio de nombres de respuestas API (n.° 47024), campo metrics de sincronización por solicitud en respuestas de chat/finalizaciones (n.° 46768), compensaciones de tokens en puntos finales de procesamiento (n.° 44226), return_loss_mask para generación de datos de entrenamiento (n.° 46846), HTTP 422 para URL de imágenes no procesables (n.° 47165).
  • gpt-oss/Harmony: renderizador de Harmony dedicado (#46800), descarga process_eos() (#46437), recuperación de salida sin formato en análisis no terminal (#47062, #47379).
  • Interfaz Rust: HTTPS estático y mTLS para HTTP y gRPC (#45890), supervisor DP (#47076), rutas de control del perfilador (#46306), parámetro de muestreo repetition_detection (#46684), interfaz de analizador unificado/combinado (#46583), copias de tensor multimodal reducidas (#47581), además de muchos analizadores y validaciones. arreglos.
  • Video: TorchCodec agregado como backend de decodificación de video (#46609).
  • CLI/UX: Impresión TTFT y TPS en vllm chat (#46775), model_class_overrides para desarrollo/depuración (#47148).
  • Herramientas/validación: muchas correcciones del analizador de herramientas (Kimi K2 ID #46344, PoolsideV1 #46486/#47311, argumentos no ASCII #46308, reingreso de thinking_token_budget #43757); rechazo de valores de configuración no válidos (#44070, #44002, #46612) y structured_outputs degenerado que bloquea EngineCore (#45346).

Seguridad

  • Evitar la denegación de servicio OOM de bomba de descompresión de imágenes (#47010).
  • Evite un bucle infinito en split_audio con muestras de audio NaN (#46463).
  • El tokenizador vinculado funciona cuando se configura un truncation_side explícito (#47007).
  • Bloquear la selección de backend de video GPU a nivel de solicitud (#47259).
  • Documente la interfaz gRPC como insegura, solo para uso privado (#45903).

Dependencias

  • FlashInfer 0.6.13 (#46683), tpu-inference v0.23.0 (#46568), aiter 0.1.16.post2 (#46692), vllm_xpu_kernels v0.1.10.1 (#46607), huggingface-hub v1.22.0 (#47551).
  • DeepGEMM actualizado para habilitar la compatibilidad con SM120 (#47304), FlashAttention 3 construido contra el estable de antorcha API (#46644), el TLS frontal de Rust cambió de rustls a nativo-tls/OpenSSL (#46696).

Depreciaciones y eliminaciones

  • Atención paginada eliminada (#47361).
  • Modelos eliminados: Baichuan (#46362), Aquila (#46605), Grok (#46706), Tarsier / Tarsier2 (#47143), AyaVision / MusicFlamingo (#47263), Mantis (#46806).
  • Desaprobada la antigua clase de cuantificación MoE en línea del FP8 (#44514); el api_server.py heredado se movió al directorio de ejemplos (#46783); gptq_marlin se eliminó de los esquemas cuantitativos ROCm admitidos (#46655).
