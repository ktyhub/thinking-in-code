vLLM v0.20.0

Destacados

¡Esta versión presenta 752 confirmaciones de 320 contribuyentes (123 nuevos)!

  • DeepSeek V4: compatibilidad inicial con DeepSeek V4 (n.º 40860), con corrección de fuga de token DSML en DSV4/3.2 (n.º 40806), corrección de DSA + MTP IMA (n.º 40772) y un límite de abrazadera de silu en el experto compartido (n.º 40950).
  • CUDA 13.0 predeterminado: la rueda CUDA predeterminada en PyPI y la imagen vllm/vllm-openai:v0.20.0 cambiaron a CUDA 13.0; Se limpiaron las listas de arquitectura y los argumentos de compilación (#39878), y CUDA pasó a 13.0.2 para que coincida con PyTorch 2.11.0 (#40669). Como regla general, nuestra política de versión CUDA sigue la de PyTorch. Recomendamos encarecidamente instalar vLLM con uv y usar --torch-backend=cu129 si está en CUDA 12.9.
  • Actualización de PyTorch 2.11 (#34644): vLLM se envía en la antorcha 2.11 para CUDA, y XPU ahora también está en la antorcha 2.11 (#37947). XPU ya no está anclado a 2.10. Este es un cambio radical para la dependencia del medio ambiente.
  • Python 3.14: Agregado a la lista de versiones compatibles de Python (#34770).
  • Transformers v5: vLLM ahora se ejecuta en HuggingFace transformers>=5 (#30566), con bypass de torch.compile del codificador de visión (#30518) y correcciones continuas de compatibilidad v4/v5 que incluyen el procesador de imágenes PaddleOCR-VL max_pixels (#38629), la advertencia Mistral YaRN (#37292) y el recálculo rotatorio inv_freq de Jina ColBERT. (#39176).
  • Nuevos modelos grandes: vista previa de Hunyuan v3 (Hy3) (#40681) con analizador de razonamiento HYV3 (#40713); Granite 4.1 Vision como modelo multimodal incorporado (#40282).
  • FlashAttention 4 como precarga de MLA predeterminada: FA4 se volvió a habilitar como backend de precarga de MLA predeterminada (#38819) con soporte para head-dim 512 y KV paginado en SM90+ (#38835), además de una sincronización FA4 ascendente (#38690).
  • Caché KV de 2 bits TurboQuant: Nuevo backend de atención que ofrece compresión de caché KV de 2 bits con capacidad 4× (#38479), ahora con soporte de precarga FA3/FA4 (#40092).
  • Interfaz de cuantificación en línea: Nueva interfaz de cuantificación en línea de extremo a extremo (#38138), con documentos (#39736); expert_int8 consolidado en la ruta en línea del FP8 (#38463); El cuantificador en línea MXFP8 se trasladó a la nueva interfaz (#40152).
  • vLLM IR: esqueleto de IR inicial con operación rms_norm (#33825), importaciones de kernel de plataforma OOT (#38807), gemma_rms_norm reelaborado en IR (#39014) e infraestructura de pruebas/evaluación comparativa de operaciones de IR agregada (#40167): base para el trabajo futuro del kernel.
  • Avances de Model Runner V2: Eagle precompletar gráfico CUDA completo (#37588), modo/tamaños de cudagraph de resolución automática desde el backend de atención (#32936), kernels de muestra de rechazo probabilístico fusionados (#38496), validación de configuración para funciones no compatibles (#38758), respaldo por partes deshabilitado para decodificaciones de borrador de Eagle (#39773), compatibilidad con múltiples logprobs de aviso (#39937), cobertura de preparación previa al llenado (#40746) y una solución para la regresión de precisión causada por tokens de muestra/borrador obsoletos (#39833).
  • Serie de refactorización MoE: No cuantificado migrado a Full Oracle Flow (#36286), CT W8A8 a Oracle (#39187), clase SharedExperts (#35153), SharedFusedMoE eliminado (#35782), DefaultMoERunner dividido (#35326) y luego combinado nuevamente en MoERunnerBase (#40560), suma de salida de experto compartida/fusionada movida a MoERunnerBase (#35949), ZeroExpertFusedMoE en un nuevo marco (#35549), compressed_tensors_moe.py dividido (#38960), GPTQMarlinMoEMethod reelaborado con MK (#37990), XPU y CUTLASS MoE reubicados a fused_moe/experts/ (#40568, #40574), make_expert_params_mapping renombrado (#40671), refactor MoE LoRA (#40338) y se eliminó la fragmentación de DP del MoE (#39107).
  • Rendimiento: Optimice el invariante por lotes con la norma rms fusionada: mejora de latencia E2E % 2.1 (#40413); evite la sincronización seq_lens_cpu GPU→CPU (#40654); caché InductorPass.hash_source (#39328); omita la deserialización del gráfico FX al cargar para una compilación en caliente más rápida (#40151); Perfilado de memoria CUDAGraph habilitado de forma predeterminada para una contabilidad de memoria de inicio más clara (#38284).

  • Tasa de aceptación sintética unificada para V1 y V2 (#40662); SpecDecodeBaseProposer se mudó de eagle.py (#40732); Corrección de DSA + MTP IMA (#40772).

Seguridad

  • Corrección de SSRF en el ejecutor por lotes download_bytes_from_url (#38482).

Dependencias

  • PyTorch 2.11 para CUDA (#34644) y XPU (#37947): XPU ya no está anclado a 2.10.
  • CUDA 13.0 predeterminado con listas de arquitectura actualizadas y argumentos de compilación limpios (#39878); CUDA pasó a 13.0.2 para coincidir con PyTorch 2.11.0 (#40669); sm_110 (Supersónico Thor) agregado (#39233).
  • Python 3.14 agregado a las versiones compatibles (#34770).
  • Transformers v5 (#30566), con bypass de compilación de torch.compile del codificador de visión (#30518) y correcciones continuas de compatibilidad v4/v5.
  • FlashAttention 4 sincronización ascendente (#38690) y comportamiento de enlace simbólico durante la instalación (#38814).
  • FlashInfer pasó a 0.6.8 (#39959).
  • AITER triton BUFFER_OPS corrección + actualizaciones de versión (#38580), AITER volvió a v0.1.10.post3 (#39509); Nixl pasó a 0.10.1 (#39922) y se fijó según CUDA principal en CI (#39851); DeepGEMM integrado en la rueda a través de CMake (#37980); tensores fastsafe agregados al archivo NVIDIA Docker (#38950); Helion chocó con 0.3.2 → 0.3.3 (#38062).
  • Eliminado/movido: Se eliminó la dependencia de resampy (n.° 39524), se eliminó la dependencia directa de librosa (n.° 39079), pyav y soundfile se trasladaron a requisitos comunes (n.° 39997).

Cambios importantes

  1. PyTorch 2.11 + CUDA 13.0(.2) predeterminado: cambio de dependencia del entorno, ahora aplicado también a XPU.
  2. Transformers v5 es la línea base compatible (#30566).
  3. Reelaboración de métricas: vllm:prompt_tokens_recomputed eliminado (#38709); num_cached_tokens / num_external_computed_tokens reemplazado por PrefillStats (#37460).
  4. Cambio de nombre de configuración del pooler: logit_bias/logit_scale → logit_mean/logit_sigma (#39530).
  5. La programación asíncrona está desactivada de forma predeterminada para los modelos de agrupación (#39592).
  6. El perfil de memoria CUDAGraph ahora está activado de forma predeterminada (#38284): cambios en la contabilidad de la memoria de inicio.
  7. Se eliminó la cuantificación de Petit NVFP4 (#32694); LLM.reward está en desuso, use LLM.encode (#40688); cprofile / cprofile_context en desuso (#39100); V0 accept output buffer en desuso (#39125).

V0 en desuso

  • Petit NVFP4 (#32694), accept output buffer en atención (#39125), cprofile / cprofile_context (#39100), LLM.reward fuera de línea API (#40688).
