componer v5.7.0

¿Qué ha cambiado?

ℹ️ Aviso para los usuarios de Compose como biblioteca: Up ahora ejecuta sus fases de creación e inicio como un plan único sobre una sola instantánea de demonio, para up -d (#14290) y up interactivo (#14305), como ya lo hacen scale, las reconstrucciones de relojes y start. (#14291, #14296). El CLI se comporta como antes. Si llamas a api.Compose.Up desde tu propio programa:

  • Up ahora valida sus opciones primero, con las mismas reglas que las banderas CLI: UpOptions.Validate() devuelve un *api.IncompatibleOptionsError (errors.Is(err, api.ErrIncompatibleOptions)) para Start.Wait combinado con Start.Attach, y para un Up separado (sin Start.Attach) combinado con OnExit, ExitCodeFrom o Watch. Esas combinaciones solían ser ignoradas silenciosamente (#14306).
  • Up trabaja en el proyecto que se le asigna e ignora StartOptions.Project.
  • El demonio no se vuelve a observar entre las dos fases: un contenedor que sale después de que se construye el plan no se reinicia, y uno eliminado en el medio hace que su inicio falle en lugar de omitirse. Un error de planificación de la fase de Inicio ahora falla antes de que se cree cualquier contenedor.
  • Un Up en primer plano ahora le da a un servicio use_api_socket su /run/secrets/docker/config.json, como lo hace up -d, y muestra la salida de los ganchos pre_start.
  • El menú del teclado de un up interactivo ya no lo crea la biblioteca: configure NavigationMenu: true y pase una implementación con compose.WithNavigationMenu(...); de lo contrario, no se muestra ningún menú y aparece una advertencia (#14324).

Otros cambios en la superficie de la biblioteca en esta versión: DownOptions.Images ahora es un api.ImagePruneMode (las constantes sin tipo aún se compilan, una variable string necesita una conversión) y un valor no válido se rechaza antes de que Down elimine algo (#14149); compose.ServiceHash, compose.NetworkHash y compose.VolumeHash ya no se exportan, los ayudantes se han movido a un paquete interno (#14405); api.Compose ahora se ensambla a partir de seis interfaces más pequeñas, con el mismo conjunto de métodos (#14322); Se agrega PushOptions.IgnoreMissing.
