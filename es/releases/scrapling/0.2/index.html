Scrapling v0.2

Menor Publicado11 nov 2024 FuenteD4Vinci/Scrapling original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

Desguace v0.2

¿Qué ha cambiado?

Nuevas funciones

  1. ¡Presentamos la función Fetchers con 3 nuevos tipos principales para que Scrapling busque páginas con MUCHAS opciones!
    • La clase Fetcher para solicitudes HTTP básicas.
    • La clase StealthyFetcher es un buscador completamente sigiloso que utiliza una versión modificada sigilosa de Firefox.
    • ¡La clase PlayWrightFetcher que permite realizar solicitudes basadas en navegador con Vanilla PlayWright, PlayWright con modo sigiloso creado por mí, navegadores reales a través de CDP y NSTBrowser docker sin navegador!
  2. ¡Se agregaron los métodos find_all/find completamente nuevos para encontrar elementos fácilmente en la página con magia oscura!
  3. Se agregaron los métodos filter y search a la clase Adaptors para facilitar las operaciones masivas en los grupos de objetos Adaptor.
  4. Se agregaron los métodos css_first y xpath_first para facilitar su uso.
  5. Se agregó el nuevo tipo de clase TextHandlers que se usa para operaciones masivas en objetos TextHandler como la clase Adaptors.
  6. Se agregaron los métodos generate_full_css_selector y generate_full_xpath_selector.

Errores eliminados

  1. Ahora la versión de clase Adaptors de re_first devuelve el primer resultado que coincide con todos los objetos Adaptor internos en lugar de la lógica defectuosa de devolver los resultados de re_first de todos los objetos Adaptor.
  2. Ahora, si el usuario selecciona un contenido de tipo texto que se devolverá a partir de elementos seleccionados (como la función css ::text) con cualquier método como .css o .xpath. El objeto Adaptor devolverá la clase TextHandlers en lugar de devolver una lista de cadenas como antes. Ahora puedes hacer page.css('something::text').re_first(r'regex_pattern').json() en lugar de page.css('something::text')[0].re_first(r'regex_pattern').json().
  3. Ahora los argumentos Adaptor/Adaptors re/re_first son consistentes con los de TextHandler. Ahora tienes los argumentos clean_match y case_sensitive.
  4. Ahora el argumento auto_match está habilitado de forma predeterminada en la inicialización de Adaptor pero aún debe habilitarlo mientras selecciona elementos si desea habilitarlo. (No es un error sino una decisión de diseño)
  5. Muchas correcciones de anotaciones tipográficas aquí y allá para una mejor experiencia de autocompletado mientras codifica con Scrapling.

Cambios en la calidad de vida

  1. Se cambiaron los nombres de los métodos css_selector y xpath_selector a generate_css_selector y generate_xpath_selector para mayor claridad y para no interrumpir el autocompletado durante la codificación.
  2. Se reestructuró la mayor parte del código antiguo en un subpaquete core y otras decisiones de diseño para un mantenimiento más limpio y sencillo en el futuro.
  3. Se reestructuró la carpeta de pruebas en una estructura más limpia y se agregaron pruebas para las nuevas funciones. Además, ahora los entornos tox se almacenan en caché en GitHub para realizar pruebas automatizadas más rápidas con cada confirmación.
