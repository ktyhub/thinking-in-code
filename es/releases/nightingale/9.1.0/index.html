ruiseñor v9.1.0

¿Qué ha cambiado?

  • hazaña: base de datos de series temporales incorporada: las métricas impulsadas por Categraf se almacenan localmente, por lo que no se requiere Prometheus / VictoriaMetrics externo para comenzar; una fuente de datos Prometheus denominada embedded-tsdb se registra automáticamente en el primer inicio. Se respetan las configuraciones existentes: si alguna fuente de datos Prometheus habilitada ya está presente, la fuente de datos no se crea automáticamente; las muestras aún se escriben localmente y puede agregar una fuente de datos Prometheus que apunte a la TSDB incorporada para consultarlas (#3283)
  • hazaña: importar fuentes de datos de Grafana en un click, con un resumen de resultados por fuente de datos (#3295)
  • hazaña: renovación de la página de fuente de datos: después de guardar una fuente de datos, Nightingale la analiza con métricas centinela para informar qué paneles integrados/plantillas de reglas de alerta ya tienen datos y lo guía a su primera consulta (#3301)
  • hazaña: registros de evaluación de alertas por ciclo: cada evaluación de reglas conserva lo que consultó y cómo lo juzgó en el disco local del motor de alertas, inspeccionable desde un cajón en la página de reglas de alertas (#3305)
  • hazaña: las configuraciones del canal de notificación se pueden probar y las plantillas de mensajes se pueden obtener una vista previa antes de guardarlas (#3302)
  • hazaña: Asistente de configuración de recopilación de Categraf: un nuevo punto final /agents/categraf/collect.sh sirve el script del aplicador, con plantillas de complementos y verificación de métricas en la consola (#3286)
  • hazaña: la canalización de eventos admite eventos simulados en la ejecución de prueba, filtrado de rango de tiempo en registros de ejecución, activación/desactivación por lotes y un nuevo cambio API (#3281, #3285)
  • hazaña: plantillas de reglas de alerta integradas en integraciones ampliadas y revisadas en gran medida, con en_US i18n (#3282)
  • hazaña: las fuentes de datos MySQL pueden agregar parámetros adicionales al DSN (#3299)
  • hazaña: las fuentes de datos de Doris admiten doris.internal_addr para que el proceso de borde alcance FE MySQL (#3298)
  • hazaña: la lista de reglas de alerta admite el filtrado por tipo de activador
  • hazaña: la lista de eventos de alerta activa muestra el valor en el momento de activación, agrega etiquetas de tres estados y recuerda el panel de filtro, el intervalo de actualización automática y el rango de tiempo entre visitas
  • hazaña: el explorador de registros agrega un botón de consulta de documentos para Loki y VictoriaLogs, le permite agregar un filtro de campo directamente desde el visor de registros y admite el desglose de BCE BLS
  • hazaña: el panel TableNG del tablero admite un cajón de detalle de fila
  • hazaña: incorporación de la página de host: paquete de monitoreo de host one-click, acción de alerta de prueba y tarjetas de pasos siguientes
  • hazaña: el proxy de origen de datos y el acceso a consultas de registro ahora se escriben en el registro de auditoría con el usuario y la carga útil
  • hazaña: el borde reintenta la persistencia del evento en el centro, con un tiempo de espera por solicitud ajustado
  • hazaña: nuevo API para comprobar si alguna notificación se entregó correctamente (#3300)
  • perf: acelera las consultas de registros de notificaciones y la limpieza diaria, respaldado por dos nuevos índices notification_record creados en línea al inicio (#3311)
  • solución: copia profunda de los eventos antes de enviarlos a la cola, por lo que un evento de recuperación ya no sobrescribe un evento desencadenante aún no consumido.
  • solución: una configuración en blanco de la aplicación DingTalk ya no interrumpe las notificaciones del robot grupal (#3309)
  • solución: fijar tipos de columnas explícitos en los modelos ai_* para detener la deriva del esquema de AutoMigrate, que había fallado en la migración de esas tablas
  • solución: soporte max_completion_tokens para modelos OpenAI más nuevos (#3306)
  • solución: protege nombres de etiquetas no válidos en la regla de alerta event_relabel_config (#3287, #3296)
  • solución: acepte contenido YAML para recopilar cargas útiles integradas (#3307)
  • solución: permite guardar a la fuerza una fuente de datos que no pasa su verificación de estado (#3304)
  • solución: compare la fuente de datos predeterminada global con la lista completa de fuentes de datos antes del filtrado del clúster por motor, por lo que una fuente de datos predeterminada propiedad de otro clúster ya no se borra
  • solución: corregir las unidades de reglas de alerta
  • solución: reparar la habilidad incorporada YAML frontmatter y exponer herramientas de búsqueda de código en el chat
  • solución: proporcione a la migración de la tabla asíncrona su propia sesión gorm, de modo que una declaración fallida ya no envenene al resto

Nueva característica V9

  • hazaña: presenta Nightingale AI: asistente de IA integrado, mercado de habilidades, administración de configuración de LLM, con recomendaciones rápidas específicas de la página
  • hazaña: base de datos de series temporales incorporada: funciona de inmediato, no se necesita Prometheus / VictoriaMetrics externo para configuraciones a pequeña escala
  • hazaña: menú de navegación rediseñado, diseño global y interfaz de usuario de tabla
  • hazaña: Gestión de canales de notificación refactorizada
  • hazaña: Nueva página de seguimiento de ejecución de canalización de eventos con vista de ejecución detallada

Nota de actualización ⚠️

  • El nuevo asistente de IA se basa en Redis Streams, por lo que se requiere Redis 5.0 o posterior (se recomienda Redis 7.0+ para que los usuarios del clúster habiliten Pub/Sub fragmentado).
  • Los registros de evaluación de alertas están habilitados de forma predeterminada. El motor de alertas los escribe en su disco local en ./evallog, los retiene durante 8 días y tiene un límite de 20 GB. Sintonice o desactive esto con la sección [Alert.EvalLog]; consulte el nuevo etc/config.toml.
  • La TSDB incorporada no está habilitada mediante una actualización binaria local: [EmbeddedTSDB] solo existe en el nuevo etc/config.toml, por lo que un archivo de configuración transferido de una versión anterior lo deja desactivado. Copie la sección para habilitarla. Lo maneja únicamente el proceso central (n9e-edge / n9e-alert / n9e-pushgw lo ignoran) y almacena datos en el disco local de esa instancia central, por lo que se adapta a implementaciones de instancia única; con múltiples réplicas centrales, use una TSDB externa en su lugar.
