mempalace v3.4.1

v3.4.1 — Compatibilidad con IDE de cursor y antigravedad

Ahora tenemos soporte para dos editores más: un complemento Cursor con ganchos nativos y soporte Google Antigravity de primera clase; ambos brindan el guardado automático, la recuperación de inicio de sesión y la minería de transcripciones textuales de MemPalace al mismo estándar que ya se incluye para Claude Code y Codex. Dos correcciones de confiabilidad completan el ciclo: embeddinggemma ya no elimina con OOM las reintegraciones grandes y las copias de seguridad de migrate / repair dejan de acumularse hasta que llenan el disco.

Características

  • Complemento IDE de cursor (.cursor-plugin/). Registra automáticamente el servidor mempalace-mcp, cinco comandos de barra diagonal (/mempalace-help, /mempalace-init, /mempalace-mine, /mempalace-search, /mempalace-status) y una habilidad invocable por modelo; sin edición manual de ~/.cursor/mcp.json. Instálelo desde un clon local ahora o desde el mercado de Cursor una vez publicado. (#1632)
  • Enganches IDE del cursor (stop / preCompact / sessionStart). Guardado automático en segundo plano cada N turnos del agente, minería de transcripciones sincrónica antes de que el cursor se compacte y recuperación de la memoria de inicio de sesión con alcance en el ala del espacio de trabajo. Instalador de un solo comando en hooks/cursor/install.sh (--scope user|project, --variant full|minimal, --dry-run, --uninstall): idempotente y libre de dependencias.
  • Soporte IDE de primera clase para Antigravity (Google). Nuevo paquete .antigravity-plugin/ e instalador idempotente que registra MemPalace como un complemento Antigravity: servidor MCP, habilidad y dos enlaces de ciclo de vida (minería en segundo plano en Stop, inyección de memoria palabra por palabra en la primera llamada del modelo). bash 3.2/compatible con macOS, comparte el mismo directorio ~/.mempalace/hook_state/ que los ganchos Claude Code/Codex/Cursor y respeta todos los interruptores de apagado existentes. (#1633, #1771)
  • Resolución de intérprete de configuración cero para ganchos. Los ganchos ahora resuelven Python desde el script de consola mempalace-mcp antes de recurrir a python3, arreglando la minería silenciosa sin operación bajo diseños uv tool install / pipx donde el sistema python3 no puede importar mempalace.

Corrección de errores

  • embeddinggemma ya no elimina las reincrustaciones masivas con OOM. El integrador ONNX ejecutó una sola pasada sobre toda su entrada, por lo que un lote de escala de reparación (~5000 documentos) asignó buffers de atención mucho más allá de la RAM disponible y el kernel finalizó el proceso silenciosamente. La incrustación ahora se ejecuta en sublotes de 32 documentos; los vectores por documento no cambian. (#1770)
  • Retención de copias de seguridad para evitar el uso ilimitado del disco. mempalace migrate y mempalace repair max-seq-id escribieron una copia de seguridad nueva de tamaño completo en cada ejecución y nunca la limpiaron: se encontró un palacio con cientos de GB de copias de seguridad obsoletas además de unos cientos de MB de datos activos. Una nueva configuración de max_backups (10 predeterminada; 0 conserva todo) ahora elimina la más antigua después de escribir cada nueva copia de seguridad. (#1697) Un gran agradecimiento a todos los que contribuyeron en este ciclo: tanto las integraciones de IDE como varias de estas correcciones provinieron de la comunidad, incluidos varios contribuyentes nuevos. Todos están acreditados a continuación.
