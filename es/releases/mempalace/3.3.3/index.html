mempalace v3.3.3

Corrección de errores

  • Instalar regresión: el script de consola mempalace-mcp ahora se declara en pyproject.toml junto con la referencia de .claude-plugin/plugin.json al mismo. En v3.3.2 los dos se separaron (plugin.json envió el nuevo formulario "command": "mempalace-mcp" antes de que llegara el punto de entrada correspondiente), por lo que cada pip install mempalace==3.3.2 nuevo produjo una configuración del complemento Claude Code que apuntaba a un binario que no estaba instalado. (#1093, #340)
  • Restaurar la visibilidad del guardado silencioso después de la regresión de Claude Code 2.1.114 client: los guardados de transcripciones de producción fallaban silenciosamente hasta este PR. (#1021)
  • Paginar los metadatos de ruta status para que los palacios grandes no traspasen los límites de variables de SQLite. (#851)
  • Resolver el corredor de enlace del complemento Claude en las variaciones de plataforma/directorio de complemento; Anteriormente se rompió en Windows y algunos diseños de macOS. (#942)
  • Resolución real python3 para ganchos .sh con una ruta de anulación MEMPAL_PYTHON. (#833)
  • Agregue el parámetro wing opcional a tool_diary_write / tool_diary_read y derive el ala por proyecto de la ruta de transcripción del Código Claude al escribir desde el gancho de parada: las entradas del diario de diferentes proyectos ya no colapsan en un ala predeterminada compartida. (#659)
  • Trate la cadena vacía como "sin filtro" en mempalace_search wing/room; Los agentes LLM que de forma predeterminada completan todos los parámetros opcionales con "" ya no son devueltos con must be a non-empty string. (#1097, #1084)
  • Amplíe _wing_from_transcript_path para manejar carpetas de proyectos de Claude Code sin un segmento -Projects- (por ejemplo, ~/dev/<parent>/<project>, ~/code/<project>). El nombre del proyecto ahora se deriva del token final separado por guiones de la carpeta codificada, por lo que los usuarios de Linux con código fuera de ~/Projects/ obtienen el alcance del diario por proyecto en lugar de pasar a wing_sessions. (#1145, seguimiento del #659)
  • mempalace_diary_read(wing="") ahora devuelve entradas del diario de cada ala en la que este agente ha escrito, coincidiendo con el patrón #1097 "cadena vacía como sin filtro". Anteriormente, el valor predeterminado era wing_<agent>, lo que aislaba las entradas que los ganchos escribían en alas derivadas del proyecto. (#1145)
  • mempalace mine ahora omite el archivo entities.json generado para que su contenido no se vuelva a ingerir como contenido del proyecto. (#1175)

Mejoras

  • Guardados de gancho deterministas. El gancho de guardado ahora utiliza una ruta silenciosa Python API, por lo que las invocaciones sucesivas de gancho producen resultados reproducibles y cero pérdida de datos en la ruta activa. (#673)
  • Caché de gráficos con invalidación de escritura dentro de build_graph(): las llamadas de ruta cálida ya no reconstruyen el gráfico de palacio por solicitud. (#661)
  • Revisión de detección de entidades mempalace init. Los nombres de proyectos canónicos ahora provienen de manifiestos de paquetes (package.json, pyproject.toml, Cargo.toml, go.mod) y las personas reales provienen de autores de confirmaciones de git, en lugar de inferirse de la prosa. Incluye deduplicación de búsqueda de unión entre alias de nombre/correo electrónico, filtrado de bots que mantiene a @users.noreply.github.com como humanos y marcación automática de "mina" por participación en la contribución. (#1148)
  • Precisión del detector de expresiones regulares. Extracción CamelCase para que MemPalace, ChromaDB, OpenAI no estén fragmentados; el patrón con versiones/guiones más estrictos elimina los falsos positivos context-manager / multi-word; el diálogo ^NAME:\s requiere ≥2 visitas, por lo que los metadatos de Created: <date> dejan de clasificar los nombres de los campos como personas; palabras vacías ampliadas para participios y descriptores comunes en inglés; La señal de pronombre alto clasifica como persona en lugar de arrojarla a la incertidumbre. (#1148)
  • Init → conexión del minero. Las entidades confirmadas se fusionan en ~/.mempalace/known_entities.json en el inicio, que el minero lee para etiquetar los metadatos del cajón para la búsqueda filtrada por entidades. Anteriormente, el minero no consumía la salida de init; el entities.json por proyecto se mantiene como registro de auditoría. (#1157)
  • Deduplicación de proyectos que no distingue entre mayúsculas y minúsculas en fuentes de manifiesto, git y convo, de modo que las variantes de mayúsculas y minúsculas del mismo nombre de proyecto colapsan en una entrada de revisión. (#1175)

Agregado

  • i18n: traducción al bielorruso. (#1051)
  • i18n: detección de entidades para las configuraciones regionales alemana, española y francesa. (#1001)
  • i18n: Detección de entidades en chino tradicional + simplificado. (#945)
  • mempalace init --llm: clasificación de entidades asistida por LLM opcional. El valor predeterminado es Ollama local (cero-API); también admite cualquier punto final compatible con OpenAI (LM Studio, servidor llama.cpp, vLLM, OpenRouter, etc.) y Anthropic Messages API. Se ejecuta de forma interactiva con un indicador de progreso; Ctrl-C cancela limpiamente y devuelve resultados parciales. Útil para carpetas con mucha prosa donde el detector de expresiones regulares tiene problemas (diarios, transcripciones, notas de investigación). Optar únicamente: la ruta de inicio predeterminada sigue siendo cero-API. (#1150)
  • Escáner de conversaciones de Claude Code. Los directorios ~/.claude/projects/<slug>/ ahora contribuyen con entidades de proyecto utilizando los metadatos autorizados de cwd de cada sesión, evitando la ambigüedad de la decodificación de slugs. (#1150)

Conocido: diferido a v3.3.4

  • SIGSEGV de inserción paralela de HNSW cuando hnsw:num_threads no está configurado en la creación de la colección (#974): se corrige en vuelo como #976, en espera de rebase contra desarrollo.

Instalar

pip install --upgrade mempalace==3.3.3
