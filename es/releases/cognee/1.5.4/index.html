Resumen

Esta versión de parche se centra en la confiabilidad, la conveniencia de la ingesta de datos y el pulido del front-end. Soluciona varios problemas de migración, registro y procedencia, agrega pequeñas pero útiles comodidades API y Docker para herramientas de ingesta e incluye un amplio conjunto de actualizaciones de interfaz y correcciones de errores.

Destacados

  • La imagen Docker ahora instala el extra 'dlt' para que las herramientas comunes de ingesta de datos funcionen de inmediato.
  • API add endpoint acepta cadenas raw_data y URL de repositorio git para simplificar la adición de conjuntos de datos mediante programación.
  • Múltiples correcciones en migraciones, registros y procedencia para mejorar la estabilidad durante las actualizaciones y operaciones simultáneas.
  • Reorganizaciones del frontend y numerosas correcciones de la interfaz de usuario que mejoran el conjunto de datos, el panel y los flujos de trabajo de integración.
  • Seguridad y refuerzo de la protección: los tokens API se redactan en los registros de inicio y el acceso a la raíz del archivo local está deshabilitado de forma predeterminada.

Cambios importantes

  • Se eliminó el parámetro 'repositorios': el parámetro 'repositorios' se eliminó de las llamadas API/CLI afectadas. Si confió en ese parámetro, actualice sus integraciones al nuevo patrón de llamada (consulte los documentos OpenAPI o SDK para obtener la firma actualizada).
  • COGNEE_ALLOWED_LOCAL_FILE_ROOTS predeterminado cambiado: la configuración COGNEE_ALLOWED_LOCAL_FILE_ROOTS ahora está deshabilitada de forma predeterminada. Si anteriormente usó esto para permitir el acceso a archivos locales, vuelva a habilitarlo explícitamente en su configuración y verifique las rutas permitidas.

Nuevas características

  • DLT extra en la imagen Docker: la imagen oficial Docker ahora instala el extra 'dlt' (un conjunto opcional de paquetes utilizados para la carga de datos). Esto significa que los conectores o flujos de ingesta que dependen de ese extra funcionarán sin necesidad de instalar manualmente paquetes adicionales en su contenedor.
  • Agregar punto final acepta datos sin procesar y URL de repositorio: el API que agrega datos ahora acepta raw_data como una cadena (para que pueda PUBLICAR texto directamente) y también acepta URL clonadas del repositorio. Esto hace que sea más fácil agregar datos mediante programación desde un repositorio de git o texto en línea sin cargar archivos previamente.
  • Mejoras en la interfaz y nuevas páginas: la interfaz de usuario web recibió grandes actualizaciones en el panel, los conjuntos de datos, las integraciones y las páginas comerciales/lienzo. Estos cambios reorganizan listas y paneles, mejoran los flujos de carga y mejoran los pasos de incorporación para que las tareas diarias sean más claras y fluidas.

Mejoras

  • Las migraciones se ejecutan una vez por proceso: las migraciones de bases de datos relacionales ahora se realizan solo una vez para un proceso, lo que reduce el trabajo duplicado y las condiciones de carrera durante el inicio.
  • Inicialización de registro refinada: el registro se inicializa exactamente una vez por proceso y se eliminaron las alternancias de registro detallado/silencioso que causaban confusión. Esto reduce las entradas de registro duplicadas y hace que los registros sean más fáciles de leer.
  • Manejo del delimitador de ingesta DLT: la canalización de ingesta basada en DLT ahora maneja correctamente archivos que usan diferentes delimitadores (comas, tabulaciones, etc.), por lo que los archivos CSV/TSV de fuente mixta se importan de manera más confiable.
  • Se corrigió el bloqueo de datos vacíos de FastAPI: se corrigió un error de FastAPI que podía fallar con datos de solicitud vacíos, lo que mejora la solidez de API para casos extremos.
  • La demostración CLI muestra respuestas de ejemplo sin llamadas LLM adicionales: el modo de demostración CLI ahora muestra completamente las respuestas de demostración almacenadas, sin recurrir a modelos de lenguaje, lo que hace que las demostraciones sean más rápidas y fáciles de usar sin conexión.
  • Citación de predicados de LanceDB: los ID en los predicados de recuperación de LanceDB se citan correctamente para evitar errores de consulta para ciertos formatos de identificación.
  • Leer EMBEDDING_API_BASE como alias: la variable de entorno EMBEDDING_API_BASE ahora se reconoce como un alias de punto final, lo que simplifica las configuraciones de puntos finales alternativos.
  • Limpieza de procedencia: las correcciones en el manejo de procedencia detienen la propiedad duplicada de los bordes creados a partir de contenido fragmentado y declaran los valores predeterminados correctos en el modelo para que las migraciones de procedencia se comporten de manera consistente.
  • Correcciones de propiedad y autorización de actualización: las actualizaciones incrementales ahora están autorizadas por la ACL (lista de control de acceso) del conjunto de datos, la búsqueda del presupuesto fragmentado se resuelve como el propietario del conjunto de datos y el propietario del conjunto de datos original se conserva en las reservas de reconstrucción completa.

Rendimiento

  • Contención de bloqueo de procedencia reducida: el punto de control se sacó del bloqueo de procedencia, lo que redujo la contención de bloqueo y mejoró la concurrencia cuando muchas operaciones escriben metadatos de procedencia.
  • Orden de escritura más sólido: el gráfico ahora se escribe antes que los vectores durante las operaciones de almacenamiento, lo que reduce la posibilidad de escrituras parciales y mejora la coherencia general de los datos durante la ingesta.
  • Aprovisionamiento de bases de datos optimizado: las bases de datos de conjuntos de datos se aprovisionan únicamente por ID de conjunto de datos, lo que simplifica la lógica de aprovisionamiento y reduce la sobrecarga durante la configuración del entorno.

Seguridad

  • Redacción del token API en el eco de inicio: el punto de entrada ya no imprime texto sin formato --api-token en su eco de lanzamiento; los tokens están redactados para que no se filtren en los registros.
  • Raíces de archivos locales deshabilitadas de forma predeterminada: la configuración COGNEE_ALLOWED_LOCAL_FILE_ROOTS ahora está deshabilitada de forma predeterminada para reducir la exposición accidental de las rutas del sistema de archivos local al servidor.
  • Omitir la concesión de permiso de inquilino para el centinela local: el frontend/servidor ahora omite una concesión automática de permiso de inquilino cuando ejecuta una instancia de centinela local, lo que evita cambios inesperados en los permisos en las ejecuciones de desarrollo.

Corrección de errores

  • Se eliminó un modo de registro "silencioso" que suprimía mensajes útiles y causaba confusión.
  • Se solucionó un problema por el cual el parámetro de repositorios se eliminaba incorrectamente en algunas llamadas: las superficies de devolución de llamadas se actualizaron para coincidir con el nuevo patrón de llamadas.
  • Se corrigió el bloqueo de FastAPI en cargas útiles de datos vacías.
  • Se eliminó el argumento --api-token en la salida de inicio.
  • Se corrigió la ingesta de dlt para manejar correctamente múltiples delimitadores de archivos.
  • Se corrigieron las regresiones de refactorización DTO y se sincronizaron los extras de OpenAPI con la aplicación en ejecución para que los documentos y API coincidan.
  • Se corrigió que los bordes de procedencia producidos en trozos fueran de doble propiedad.
  • Se solucionó un problema que garantizaba que la búsqueda de presupuesto parcial se resuelva con el contexto correcto del propietario del conjunto de datos.
  • Se corrigieron varios errores de interfaz en el conjunto de datos, el panel y las páginas de integración (progreso de carga, modales, representación de listas y conectores).
  • Se corrigió el comportamiento de lectura de EMBEDDING_API_BASE para que la configuración del punto final alternativo se comporte correctamente.

Cambios técnicos

  • Migraciones refactorizadas: se utiliza un módulo de esquema congelado para ambas revisiones y la elección del dialecto se decide desde el enlace de la base de datos; varios cambios migratorios para volver a ser padres para mantener un solo jefe después de fusiones recientes.
  • Numerosas actualizaciones de prueba y CI: reorganización de conjuntos de pruebas, divisiones nocturnas/de prueba y pruebas de enrutamiento e2e agregadas para servicio().
  • Ajustes en la documentación y sincronización de OpenAPI: se sincronizaron pequeñas correcciones publicitarias y especificaciones adicionales con la aplicación en ejecución.
  • Varios refactores internos y limpieza: migraciones de agentes de reparentalización, cambios de aprovisionamiento y múltiples correcciones de dispositivos de prueba.
