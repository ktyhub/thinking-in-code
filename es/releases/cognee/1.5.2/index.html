#cognee v1.5.2

v1.5.2 — Mejoras de estabilidad y búsqueda

Fecha de lanzamiento: 2026-08-22 Cambios: v1.5.2 → principal

Resumen

Este lanzamiento de parche se centra en hacer que Cognee sea más confiable y mejorar la relevancia de la búsqueda para las consultas cotidianas. Incluye correcciones de errores específicas, mensajes de error más claros, mejoras en el rendimiento de la ingesta y la búsqueda, y refuerzo interno para un comportamiento más seguro de API.

Destacados

  • Se mejoró la relevancia de la búsqueda para consultas breves y ambiguas para que las respuestas sean más útiles.
  • Ingestión de datos más rápida y confiable para grandes cargas e importaciones masivas.
  • Mensajes de error y registros más claros para facilitar la depuración y la integración.
  • Múltiples correcciones de errores y refuerzo interno para reducir fallas y bloqueos de sincronización.

Cambios importantes

  • No hay cambios importantes en v1.5.2. Las actualizaciones deben ser seguras para todos los usuarios, pero recomendamos probar los flujos de trabajo de ingesta y búsqueda en etapa de preparación antes de implementarlas en producción.

Nuevas características

  • No se agregaron módulos de funciones nuevas importantes en v1.5.2. Esta versión se centra en mejoras orientadas al usuario: la búsqueda ahora interpreta mejor las consultas breves (por lo que obtendrá resultados más relevantes cuando busque con frases breves) y las rutas de ingesta se reforzaron para completar importaciones grandes de manera más confiable.

Mejoras

  • Relevancia de búsqueda: el ajuste de la lógica de clasificación de búsqueda mejora los resultados para consultas cortas o ambiguas, lo que significa que verá documentos más directamente relevantes y menos coincidencias ruidosas.
  • Confiabilidad de la ingesta: los procesos de carga e importación masiva son más sólidos contra interrupciones y errores transitorios, lo que reduce la posibilidad de importaciones de conjuntos de datos parciales o fallidas.
  • Experiencia del desarrollador: los mensajes de error devueltos por API y SDK se han aclarado para incluir sugerencias prácticas (qué salió mal y los siguientes pasos comunes), lo que agiliza el diagnóstico de los problemas de integración.
  • Registro y observabilidad: los registros internos proporcionan marcadores más claros para la sincronización del conjunto de datos y los eventos del ciclo de vida de las consultas, por lo que el soporte y la depuración son más fáciles.

Rendimiento

  • Latencia reducida para consultas de búsqueda en escenarios comunes (mejora notable para consultas cortas/frases), por lo que las búsquedas interactivas devuelven respuestas más rápido.
  • Manejo de memoria mejorado durante la ingesta de archivos grandes para evitar picos que anteriormente podrían causar tiempos de espera o reintentos.

Seguridad

  • La validación de entradas y el manejo de errores en los puntos finales públicos API se reforzaron para reducir la posibilidad de que solicitudes con formato incorrecto causen estados inconsistentes. Esto mejora la solidez general al integrar fuentes de datos de terceros.

Corrección de errores

  • Se corrigió una condición que podía causar que la sincronización del conjunto de datos se detuviera después de interrupciones intermitentes de la red.
  • Se resolvieron fallas poco comunes durante trabajos de ingesta de alta concurrencia.
  • Se corrigieron mensajes de error API engañosos que hacían que algunas fallas transitorias parecieran permanentes.
  • Se solucionó un problema por el cual las consultas pequeñas o breves a veces arrojaban resultados de menor relevancia.

Cambios técnicos

  • Refactorizaciones internas para la sincronización del conjunto de datos y el código de ingestión para simplificar el comportamiento de reintento y mejorar la mantenibilidad.
  • Actualizaciones de dependencia y pulido menor de SDK para un comportamiento más sólido de client durante fallas de red.
  • Pruebas unitarias y de integración mejoradas en torno al ranking de búsqueda y la sincronización de conjuntos de datos.
