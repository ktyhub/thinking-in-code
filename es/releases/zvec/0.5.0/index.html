zvec v0.5.0

🚀 Zvec v0.5.0 Release Notes

📦 Nuevas funciones

  • Búsqueda de texto completo (FTS): Zvec ahora admite de forma nativa la búsqueda de texto completo: adjunte un índice FTS a cualquier campo de cadena y consúltelo con expresiones estructuradas o en lenguaje natural, con administración de índice a través de Collection::CreateIndex / DropIndex. (#408, #445)
  • Recuperación híbrida: Combine la recuperación de texto completo, de vector denso y de vector disperso en una única llamada de consulta, con filtrado escalar y reclasificación; La ejecución nativa de consultas múltiples y la reclasificación ahora se comportan de manera consistente en Python, Go, Rust y C++. (#459, #405)
  • Índice DiskANN: Se agregó un nuevo índice DiskANN que mantiene la mayor parte del índice en el disco en lugar de en la RAM, lo que reduce drásticamente el uso de memoria para conjuntos de datos de miles de millones de escala y hace factible la búsqueda de ANN a gran escala en máquinas con memoria limitada. (#369)
  • Selección de campos de salida: fetch() ahora acepta un parámetro output_fields para controlar qué campos se devuelven. (#358)

🌐 Ecosistema

Más allá del motor central, el ecosistema Zvec se expande con el nuevo lenguaje oficial SDK y una herramienta de gestión visual:

  • Go SDK oficial (zvec-go): enlaces cgo que envuelven libzvec_c_api, con bibliotecas prediseñadas para Linux (x64/ARM64), macOS (ARM64) y Windows (x64).
  • Oficial Rust SDK (zvec-rust): Enlaces Rust idiomáticos y seguros con administración de recursos RAII, constructor API y manejo de errores Result<T>; admite macOS (x86_64/ARM64), Linux (x86_64/ARM64) y Windows (x86_64/MSVC).
  • Zvec Studio (zvec-studio): Una herramienta de administración visual para la base de datos vectorial integrada de Zvec: explore datos, pruebe consultas y administre esquemas sin escribir código. Instálelo a través de pip install zvec-studio o descargue la aplicación de escritorio para macOS/Linux/Windows.

🚀 Mejoras de rendimiento

  • Optimización más rápida: Reutilice el primer archivo de índice vectorial como base de combinación durante la optimización. (#440)
  • Liberación de GIL en enlaces: Libere GIL en enlaces de colección para una mejor concurrencia de Python. (#363)

🐞 Corrección de errores

  • Corrección de los datos: Se corrigió SIGABRT de columna anulable en colecciones de múltiples segmentos, fuga nula a través de filtros escalares anulables, sincronización de esquema de consulta después de DDL y contaminación cruzada del optimizador SQL a través de QueryInfo por segmento. (#415, #416, #410, #429, #449)
  • Estabilidad del índice: DiskANN reforzado (entrada medoide, falla de compilación simultánea, calidad de poda), RaBitQ (fusión de vectores sin procesar durante la optimización, ruta del convertidor, validación ex_bits), ordenamiento de resultados de FIV y denominación de índices vectoriales. (#433, #456, #425, #436, #422, #421)
  • Correcciones varias: Conflicto de macros de Windows, especificadores de formato uint64_t, recuperación de contexto HNSW y pruebas unitarias Python. (#435, #374, #386, #401)

🔧 Refactorización y limpieza

  • Consulta unificada API: Se eliminó VectorQuery, consulta unificada de destino único en SearchQuery y se cambió la reclasificación a una interfaz basada en vectores. (#428, #431, #458, #267)
  • Limpieza de base de código: Se aplicó modernize-use-override, se aclararon los ID de fila local del segmento, se ajustó la compilación de DiskANN, se cambió a una lista blanca de CPU x86 explícita, se eliminaron la métrica de Hamming y el Administrador de búfer, y se revisaron los mensajes de error. (#442, #419, #432, #475, #258, #365, #437, #400)

🤖 CI y mejoras de compilación

  • Refuerzo de compilación: Se habilitó -Werror en todas las plataformas CI, se corrigió RISC-V FastPFOR a través de SIMDe, se marcaron inclusiones de terceros como SISTEMA y se corrigieron las rutas de DiskANN CMake. (#460, #470, #413, #464)
  • CI más rápido: Se agregó ccache/sccache (incluido Windows), pruebas en paralelo, se aceleró clang-tidy, se amplió el flujo de trabajo principal y se redujo CRoaring a una amalgama (~292M → ~1MB). (#360, #439, #454, #384, #412, #417, #418, #438, #396, #448, #381)
  • Bumps de dependencia: actions/cache 4→5 y codecov/codecov-action 6→7. (#466, #467)
