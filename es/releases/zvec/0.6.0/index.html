zvec v0.6.0

🚀 Zvec v0.6.0 Release Note

📦 Nuevas funciones

  • Abstracción de cuantificador turbo: Se introdujo una abstracción de cuantificador conectable en el módulo Turbo con una interfaz uniforme que los cuantificadores futuros (int8 uniforme, registro int8, PQ, RaBitQ,…) pueden implementar, desacoplando la lógica de cuantificación de los creadores de índices y los buscadores. Incluye la primera implementación concreta de Fp32Quantizer y núcleos de distancia escalares FP32. (#546)
  • Rotación aleatoria para cuantización INT8/INT4: Se agregó una función de rotación aleatoria opcional a la cuantización INT8/INT4, distribuyendo la variación uniformemente entre las dimensiones vectoriales para reducir el error de cuantización y mejorar la recuperación. En cohere-1m: recuperación de HNSW INT8 mejorada de 0.9285 → 0.9397, Flat INT8 de 0.9695 → 0.9881; La recuperación de INT4 mejoró drásticamente (HNSW 0.2114 → 0.7117). (#483)
  • Búsqueda por grupo: Zvec ahora admite la búsqueda por grupo (también conocida como deduplicación por grupo) en la interfaz principal, el algoritmo y las capas de base de datos. Los usuarios pueden recuperar los mejores resultados por grupo en lugar de globalmente, con soporte para los modos de consulta fetch_vector, is_linear y bf_pks en índices planos, HNSW, HNSW-RaBitQ y dispersos. El grupo por ahora también está expuesto en el Python API. (#527, #561)
  • Consulta de vector Python de copia cero: Se reemplazó serialize_vector memcpy con VectorViewClause que apunta directamente al búfer numpy, eliminando copias de memoria redundantes para consultas de vectores densos Python. (#517)
  • Tokenizer UTF-8 y plegado ASCII: Utf8proc 2.11.3 integrado para actualizar el proceso de análisis de texto FTS con compatibilidad total con Unicode: detección de límites de palabras con reconocimiento Unicode, conversión de minúsculas con reconocimiento de punto de código y un nuevo filtro de token plegable ASCII que convierte caracteres Unicode en equivalentes ASCII. (#515)
  • Tokenizer estándar (UAX #29): Se reemplazó el tokenizador de categoría general anterior con tablas de límites de palabras Unicode 17 UAX #29 generadas a partir de datos oficiales de Unicode, implementando la selección de tokens estilo Lucene para secuencias alfanuméricas, numéricas, ideográficas, hiragana, katakana, hangul, del sudeste asiático, indicador regional y emoji comunes. (#547)
  • Filtro de token Stemmer: Se agregó un filtro de token Stemmer para FTS basado en Snowball 3.1.1, que reduce las palabras a su forma raíz con soporte para más de 34 idiomas configurables a través de stemmer_lang en extra_params. (#513)
  • DiskANN C API: Se agregaron interfaces DiskANN C API completas que incluyen establecedores/obtenedores de parámetros de índice, parámetros de consulta con operaciones CRUD y cableado de consultas para consultas vectoriales/consultas vectoriales agrupadas/subconsultas, siguiendo los patrones HNSW/FTS existentes. (#495)

🚀 Mejoras de rendimiento

  • Consultas de conjunción FTS más rápidas: Se agregó la salida anticipada de puntaje y omisión máxima de bloque a ConjunctionIterator: omita bloques completos no competitivos (128 documentos) verificando los límites superiores de puntuación máxima de bloque y la acumulación de puntaje de cortocircuito cuando el límite superior restante no puede superar el umbral. Punto de referencia (500.000 documentos, conjunto de datos de quora): consultas AND entre un 22 % y un 38 % más rápidas, consultas de frases un 33 % más rápidas. (#441)
  • Optimización del índice de FIV: Optimizaciones diversas en los componentes internos del índice de FIV. (#528)

🐞 Corrección de errores

  • Corrección FTS: Se corrigieron estadísticas de segmentos que no se escriben al volver a abrir, semántica de filtro de coincidencia cero, brechas de identificación de documentos globales durante la compactación e índices instantáneos de solo lectura sin vaciado. (#566, #584, #588, #569)
  • Estabilidad del índice: Se corrigió la carrera de activación perdida en los bucles de progreso dispersos del constructor DiskANN y HNSW, el escaneo de la lista seleccionada de IVF nprobe y varios errores de índice de IVF. (#530, #544, #524)
  • Motor SQL: Se corrigió el mal uso de group_count / group_topk en el motor SQL. (#531)
  • Colección: Se corrigió el archivo LOCK para abrir en modo de solo lectura cuando la colección es de solo lectura y se conservó el segmento de escritura en vivo en las fallas de DDL CreateIndex/DropIndex para que las tareas de segmentos persistentes ya no corrompan el segmento activo. (#541, #574)
  • Enlaces Python: Se agregó validación de consultas durante la ejecución para detectar consultas no válidas con anticipación. (#538)
  • Correcciones de compilación: Se propagó la configuración del compilador a Arrow ExternalProject, se propagó CMAKE_C_COMPILER a LZ4, se corrigieron definiciones duplicadas y no coincidentes de C API y se aceptó la cadena de versión renombrada de libtool de Xcode 26.5 en la compilación de iOS Arrow. (#542, #551, #525, #581)
  • Correcciones varias: Se corrigieron cadenas de documentos que no coincidían en los resguardos de .pyi, se aclaró el error de existencia de la ruta de creación y se corrigieron los ejemplos README para usar Query. (#529, #559, #558)

🔧 Refactorización y limpieza

  • Limpieza API: Se eliminó QueryParams::set_type() y se aclaró la redacción de consultas múltiples en los documentos. (#518, #590)
  • Calidad del código: Se habilitaron comprobaciones clang-tidy bugprone específicas, se ignoraron los árboles de trabajo de submódulos sucios y se corrigieron errores tipográficos en las pruebas del buscador de FIV. (#500, #523, #526)
  • Desacoplamiento de E/S de DiskANN: Se reemplazó el complemento DiskANN independiente .so y la dependencia de tiempo de compilación estricta en libaio-dev con un singleton seguro para subprocesos que dlopen conecta con libaio.so en tiempo de ejecución y almacena en caché los punteros de llamada al sistema. Vuelve al pread() sincrónico con una advertencia cuando libaio está ausente, lo que simplifica la historia de compilación e implementación. (#532)

🤖 CI y mejoras de compilación

  • Refuerzo de compilación: Soporte Python declarado y aplicado solo para 64 bits. (#576)
  • Programación de CI: La compilación de RISC-V ahora se ejecuta semanalmente en lugar de por PR. (#577)
  • Golpes de dependencia: actions/cache 5→6. (#537)

📝 Documentación

  • README actualizado, enlace de código QR de WeChat corregido y redacción de consultas múltiples aclarada. (#589, #575, #590)
