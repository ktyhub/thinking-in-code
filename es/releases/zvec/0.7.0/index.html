zvec v0.7.0

🚀 Zvec v0.7.0 Release Notes

⚠️ Cambios importantes

  • C++ público API cambiado a Snake_case: Todas las interfaces públicas de C++ SDK (Index, Collection, etc.) se han movido de PascalCase a Snake_case. Por ejemplo, Open() → open(), Search() → search(), Query() → query() y Insert() → insert(). Los usuarios de C++ SDK deberán actualizar sus sitios de llamadas al realizar la actualización. Los nombres C API y Python API permanecen sin cambios. (#683)

📦 Nuevas funciones

  • Índice IVF RaBitQ: Se agregó soporte de cuantificación RaBitQ para índices IVF, extendiendo RaBitQ a escenarios de recuperación de vectores más densos. Se incluyen fijaciones C y Python y cobertura de prueba. (#540)
  • Marco de preprocesador Turbo: Se introdujo un componente de preprocesador opcional en el módulo cuantificador Turbo. La rotación Fast Hadamard Transform (FHT) se implementa ahora, con la rotación OPQ y la reducción de dimensionalidad planificadas para futuras versiones. (#548)
  • Cuantizador Turbo PQ-INT8: Se agregó un cuantificador INT8 basado en PQ en el marco Turbo, que cubre métricas de distancia L2, coseno y producto interno para usuarios que necesitan una mayor compresión. (#554)
  • Cuantizadores de registros Turbo: Se migró la cuantificación de registros INT8/INT4 y los cuantificadores FP16 al marco Turbo, se agregaron núcleos de distancia escalar portátiles para objetivos que no son SIMD y se modificó el registro de distribución del núcleo para que cada tipo de cuantificación se asigne a una ruta de backend explícita. (#624)
  • Cuantización uniforme de uint7/uint8: Se expuso uint7 uniforme y se agregaron opciones de cuantización de uint8 uniforme, lo que brinda a los usuarios más flexibilidad al intercambiar recuperación contra compresión. (#608)
  • Despacho de AVX2/AVX512 en tiempo de ejecución de RaBitQ: HNSW-RaBitQ ahora selecciona implementaciones de AVX2 o AVX512 en tiempo de ejecución según la CPU del host, lo que elimina la necesidad de codificar un conjunto de instrucciones en el momento de la compilación. (#632)
  • Soporte multiplataforma de DiskANN: DiskANN se amplió de Linux x86_64 a Linux ARM64 y macOS ARM64 (Apple Silicon). Ahora selecciona el mejor backend de E/S disponible (io_uring, libaio o pread) y recurre de forma segura. macOS usa F_NOCACHE y deshabilita la lectura anticipada de archivos DiskANN. (#557, #599)
  • Construcción de gráfico de dos pasos de Vamana: Se agregó una ruta de creación de gráfico de dos pasos opcional para Vamana, lo que mejora la calidad del gráfico en algunos conjuntos de datos. (#634)
  • Creación de gráficos HNSW a partir de vectores originales: HNSW ahora puede crear el gráfico a partir de vectores originales sin procesar proporcionados por un proveedor mientras la búsqueda aún se ejecuta en los vectores almacenados en el índice, lo que mejora la calidad del gráfico cuando los vectores almacenados tienen pérdidas. (#657)
  • Tokenizador de ngram de FTS: Se agregó un tokenizador de ngram para búsqueda de texto completo, útil para coincidencias a nivel de caracteres, como texto corto, código o pinyin. (#593)
  • DocIterator para recorrido completo de la colección: Se agregó DocIterator para transmitir recorrido completo de la colección en C++, C y Python. El iterador toma una instantánea, por lo que las escrituras y eliminaciones posteriores son invisibles, y el Python API admite with collection.iter_docs(). (#597)
  • ruedas musllinux: Se agregaron compilaciones de ruedas x86_64 y arm64 Python para entornos musl libc, además de correcciones de compatibilidad para pilas de subprocesos musl, vida útil del registrador singleton y sobrelecturas del montón DiskANN. (#649)
  • Canal de lanzamiento de SDK prediseñado: PR #628 propone un canal de lanzamiento de GitHub que crea y publica paquetes C/C++ SDK prediseñados para Linux (glibc y musl, x86_64 y arm64), macOS ARM64, Windows x86_64, Android arm64 y iOS XCFrameworks siempre que exista un v*. se empuja la etiqueta.

🚀 Mejoras de rendimiento

  • Superposición de E/S asíncrona de DiskANN y haz dinámico: Se modificó la búsqueda de haz de DiskANN para superponer el trabajo de la CPU con la E/S del disco y se introdujo el ancho del haz dinámico, lo que reduce la latencia de las consultas en cargas de trabajo vinculadas al disco. (#617)
  • Bibliotecas dinámicas más pequeñas: Se redujo el tamaño de las bibliotecas dinámicas prediseñadas al controlar la visibilidad de los símbolos, permitir la eliminación de códigos muertos y eliminar la dependencia de compilación de protobuf/protoc. En macOS ARM64, libzvec_c_api.dylib bajó de 37.21 MB a 22.06 MB (-40.7%) y libzvec.dylib bajó de 36.96 MB a 23.37 MB (-36.8%). El código de búsqueda principal permanece compilado con -O3, por lo que el rendimiento de las consultas no se ve afectado. (#627)

🐞 Corrección de errores

  • Estabilidad del índice y del almacenamiento: Se corrigió un bloqueo cuando el escritor de la tienda directa no se podía abrir; habilitado optimizar después de la recuperación de fallos sin abrir el WAL; registros de segmentos de escritura persistentes de solo eliminación; manejó grandes fragmentos finales de IPC en la tienda mmap; limpió directorios de segmentos huérfanos después de la recuperación tras un fallo; y limpié los directorios de segmentos retirados después de optimizar en Windows. (#579, #600, #618, #645, #674, #676)
  • DiskANN: Cableado DiskANN a la biblioteca central de zvec correctamente; hizo que el respaldo AIO de Linux fuera seguro para operaciones parciales; Se corrigió una lectura excesiva del montón en add_vector y una lectura de uno por uno en convert_pivot_data. (#602, #615)
  • Vamana/HNSW: Vamana ahora respeta las métricas de consulta asimétricas; se solucionaron problemas relacionados con HnswExternalStreamerEntity; se corrigió el error pq_int8 en ARM NEON; y normalización del centroide de medias K esféricas corregidas y pesos de muestreo K-MC2. (#635, #607, #682, #654, #655)
  • Búsqueda y filtrado: Se corrigió la validación del filtro y el restablecimiento del estado del filtro obsoleto; aislado igual o reescrito a través de AND en el motor SQL; evitó que se omitieran las invariantes del montón; y se solucionaron problemas de ASan, incluido un visit_filter off-by-one. (#663, #679, #633, #650)
  • Vinculaciones Python: Valide la consulta topk y los nombres de campo, rechace consultas FTS vacías, agregue un método close() en las colecciones y normalice los vectores de documentos numerosos para que los usuarios obtengan errores más claros en lugar de un mal comportamiento silencioso. (#616, #612, #640, #567, #653)
  • Concurrencia de mantenimiento de colecciones: Las lecturas y escrituras ahora pueden continuar mientras se ejecuta Optimize; También se corrigieron límites de lotes escalares que no coincidían. (#614, #639)
  • Compilación y control de versiones: El C API ya no informa una versión falsa de 0.2.1 cuando faltan etiquetas git; Las rutas UTF-8 se manejan correctamente en Windows; las exportaciones de DLL todo en uno son limitadas; Se corrigieron las advertencias de ANTLR4 MSVC D9025 y los errores de captura lambda de ThreadQueue; Se limpian los marcadores de parches de submódulos obsoletos y los árboles de trabajo de protobuf sucios. (#629, #666, #611, #693, #688, #675, #671)

🔧 Refactorización y limpieza

  • La afinidad de CPU del grupo de subprocesos ahora es opcional: El grupo de subprocesos ya no fija subprocesos a los núcleos de la CPU de forma predeterminada, lo que evita sorpresas en contenedores u otros entornos sensibles a la programación. La afinidad aún se puede habilitar explícitamente. (#623)
  • Componentes redundantes eliminados: Se eliminaron las palabras clave IndexLogger redundante y virtual innecesarias para reducir la superficie de mantenimiento. (#652, #631)
  • Estabilización de prueba: Se estabilizaron las pruebas del buscador DiskANN y IVF, se hicieron las esperas de ThreadQueue deterministas y se actualizaron las pruebas de recuperación de colecciones para los nuevos API. (#637, #680, #686)

🤖 CI y mejoras de compilación

  • Compilaciones de Windows/MSVC: Se refactorizó la compilación del codegen de Snowball a CMake para compatibilidad con MSVC, se agregó soporte para nmake y se corrigieron problemas de advertencia de captura lambda de MSVC y ANTLR4, lo que hizo que el desarrollo de Windows fuera más fluido. (#668, #661, #688, #693)
  • Bloques de dependencia y acción: Actualizado actions/setup-python (6→7), actions/setup-java (5→5.6.0→5.7.0) y mozilla-actions/sccache-action (0.0.10→0.0.11). (#620, #641, #667, #642)
  • Comportamiento de CI: Las comprobaciones ahora se ejecutan cuando un borrador de PR está listo; pyproject.toml agrega un marcador python_version para cibuildwheel e incluye el pytest-xdist que falta en [dev]. (#670, #560)

📝 Documentación

  • Se actualizó el archivo README a v0.6.0 y se corrigió el enlace del código QR de WeChat. (#606, #610, #651)
