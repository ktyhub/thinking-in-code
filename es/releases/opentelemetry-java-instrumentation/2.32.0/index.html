opentelemetry-instrumentación-java v2.32.0

Esta versión está dirigida al OpenTelemetry SDK 1.66.0.

Tenga en cuenta que muchos artefactos tienen el sufijo -alpha adjunto a su número de versión, lo que refleja que seguirán teniendo cambios importantes. Consulte VERSIONING.md para obtener más detalles.

⚠️ Cambios importantes en los API no estables

  • Eliminar la constante HostIdResource.REGISTRY_QUERY en desuso. (#19778)
  • El SPI ExperimentalJmxMetricHandler ahora requiere implementaciones para proporcionar getMetricNames(). (#19781)
  • Agregue el método isRequestStreaming(REQUEST) requerido a GenAiAttributesGetter. (#19879)
  • El selector experimental java.common.messaging.headers/development YAML ya no configura la captura de encabezado. Utilice java.common.messaging.headers en su lugar. (#20260)

🚫 Depreciaciones

  • Desaprobar otel.jmx.target.system en favor de otel.jmx.metrics.experimental.included. (#19783)
  • Desaprobar otel.instrumentation.elasticsearch.capture-search-query. Se eliminará en 3.0, cuando siempre se capturan los cuerpos de las consultas de búsqueda. No hay reemplazo. (#19675)
  • Desaprobar otel.instrumentation.opensearch.capture-search-query. Se eliminará en 3.0, cuando siempre se capturan los cuerpos de las consultas de búsqueda. No hay reemplazo. La desinfección permanece habilitada de forma predeterminada y configurable con otel.instrumentation.opensearch.query-sanitization.enabled. (#19837)
  • Desaprobar otel.jmx.enabled en favor de otel.instrumentation.jmx.enabled para alinearlo con otras propiedades de habilitación de instrumentación. (#19945)
  • Desaprobar la reescritura automática de llamadas VirtualField.find(Class, Class) en los consejos de javaagent incorporados. En su lugar, busque el VirtualField una vez y guárdelo en el campo static final de una clase auxiliar. El método find sigue siendo compatible. (#19980)
  • Dejar de utilizar la instrumentación de la biblioteca REST Elasticsearch. Utilice el soporte nativo OpenTelemetry de Elasticsearch Java API Client o el agente Java para el uso directo de RestClient. La instrumentación del agente Java no se ve afectada. (#19995)
  • Desaprobar otel.instrumentation.messaging.experimental.receive-telemetry.enabled en favor de otel.instrumentation.common.messaging.experimental.receive-telemetry.enabled. Para los encabezados, reemplace otel.instrumentation.messaging.experimental.headers.included y .excluded con otel.instrumentation.common.messaging.headers.included y .excluded. También desaprobar otel.instrumentation.messaging.experimental.capture-headers a favor de otel.instrumentation.common.messaging.headers.included. Los selectores estables tienen prioridad por hoja. (#20060, #20260)
  • Dejar de usar las propiedades .included/.excluded en otel.instrumentation.log4j-appender.experimental.map-message-attributes, otel.instrumentation.logback-appender.experimental.key-value-pair-attributes, otel.instrumentation.logback-appender.experimental.logstash-marker-attributes y otel.instrumentation.logback-appender.experimental.logstash-structured-argument-attributes en favor de las propiedades estables y unificadas otel.instrumentation.common.logging.structured-attributes.included/.excluded. (#20066)
  • Desaprobar otel.instrumentation.couchbase.experimental-span-attributes en favor de otel.instrumentation.couchbase.emit-experimental-telemetry, un nombre más amplio para atributos experimentales y tramos internos del Couchbase client subyacente. (#20117)
  • Desaprobar otel.traces.sampler=linksbased_parentbased_always_on sin reemplazo y rule_based_routing declarativo en favor del muestreador compuesto/desarrollo rule_based de incubadora SDK, cuya configuración y comportamiento de coincidencia difieren. (#20249)
  • Promocionar el controlador y ver la configuración de telemetría a las propiedades estables otel.instrumentation.common.controller-telemetry.enabled y otel.instrumentation.common.view-telemetry.enabled, desaprobando otel.instrumentation.common.experimental.controller-telemetry.enabled y otel.instrumentation.common.experimental.view-telemetry.enabled. (#20258)
  • Promocionar la configuración de supresión de intervalo del agente Java a la propiedad estable otel.instrumentation.common.span-suppression-strategy, desaprobando otel.instrumentation.experimental.span-suppression-strategy. (#20259)
  • Desaprobar otel.instrumentation.oshi.experimental-metrics.enabled, ProcessMetrics y sus métodos registerObservers(...) en favor de jvm.memory.used y jvm.cpu.time. (#20323)
  • Desaprobar SystemMetrics.registerObservers(Meter) en la instrumentación de la biblioteca OSHI en favor de SystemMetrics.registerObservers(OpenTelemetry). (#20263)
  • En la configuración declarativa YAML, desaprobar los selectores de puntos en las listas distribution.javaagent.instrumentation.enabled y .disabled. Utilice reactor_3_1 en lugar de reactor_3.1. Los nombres de propiedades planas como otel.instrumentation.reactor-3.1.enabled no cambian. (#20326)

🌟 Nueva instrumentación javaagent

  • Agregar métricas del grupo de conexiones de la base de datos Redisson para las versiones 2.3.0 a 3.25. (#19152, #19634)
  • Agregue instrumentación del agente Java para la comunicación remota de Pekko para que el contexto de seguimiento se propague a través de llamadas remotas. (#19823)

📈 Mejoras

  • Ampliar las próximas convenciones semánticas de la base de datos 3.0 detrás de otel.semconv-stability.opt-in=database, incluidos destinos de servidores configurados y nombres de tramos, validación de puntos finales, atributos de pares de red, espacios de nombres Redis, nombres de operaciones, tipos de errores, texto de consulta y nombres de métricas de grupos de conexiones e identidad de bases de datos para Cassandra, ClickHouse, Couchbase, Elasticsearch, Geode, HBase, JDBC, Redis. clients, MongoDB, OpenSearch, R2DBC, Spymemcached y Vert.x. (#19728, #19747, #19749, #19753, #19757, #19795, #19830, #19831, #19832, #19834, #19838, #19839, #19844, #19845, #19846, #19848, #19850, #19864, #19868, #19872, #19877, #19883, #19901, #19902, #19903, #19904, #19981, #19983, #19986, #19988, #20008, #20011, #20015, #20017, #20041, #20065, #20068, #20070, #20071, #20072, #20073, #20074, #20075, #20076, #20077, #20078, #20080, #20082, #20084, #20086, #20089, #20105)
  • Ampliar las próximas convenciones semánticas de mensajería 3.0 detrás de otel.semconv-stability.opt-in=messaging, incluidos intervalos basados en operaciones, client y métricas de proceso, creación y propagación de lotes por mensaje, marcas de tiempo consistentes, nombres de suscripción duraderos y supresión de procesamiento duplicado para Camel, Kafka Connect, JMS, SQS y RocketMQ. (#19483, #19485, #19503, #19517, #19915, #20045, #20067, #20144)
  • Los intervalos y métricas de Kafka ahora incluyen messaging.kafka.cluster.id una vez que se resuelven los metadatos del clúster. (#18978)
  • Agregue atributos de base de datos SQL a los intervalos de datos RDS AWS SDK v2 API ExecuteStatement y BatchExecuteStatement. (#19259)
  • Agregue registros WARNING para ubicaciones de extensión vacías o no válidas y cargas JAR de extensión fallidas, además de registros FINE para JAR de extensión cargados correctamente. (#19584)
  • La biblioteca de métricas JMX ahora incluye el objetivo de métricas del corredor Kafka experimental. (#19722)
  • Actualice las descripciones de kafka.connect.connector.status y kafka.connect.task.status para omitir los valores de estado admitidos enumerados. (#19724)
  • Los tramos de la base de datos Geode client ahora incluyen server.address y server.port cuando el grupo de la región tiene exactamente un servidor configurado. (#19748)
  • Agregue soporte de registro de excepciones para la base de datos HBase clients, SofaRPC clients y servidores, y GWT RPC con otel.semconv.exception.signal.preview=logs. (#19750, #20253, #20254)
  • Agregue los atributos server.address y server.port a los tramos de la base de datos de Couchbase. (#19758)
  • Agregue filtrado de nombres de métricas para métricas JMX con otel.jmx.metrics.included y otel.jmx.metrics.excluded, o JmxTelemetryBuilder.setMetrics(IncludeExclude) en la biblioteca. (#19782)
  • Los tramos de RabbitMQ ahora incluyen messaging.rabbitmq.vhost.name y messaging.rabbitmq.cluster.name cuando otel.instrumentation.rabbitmq.experimental-span-attributes=true. (#19822)
  • Los mensajes de creación de métricas JMX ahora se registran en FINE en lugar de INFO, lo que reduce el ruido de registro predeterminado. (#19825)
  • Los servidores HTTP de Akka ahora incluyen la dirección del par remoto en los atributos de la dirección del par de la red. (#19840)
  • Los servidores HTTP de Pekko ahora incluyen client.address del par de socket para solicitudes HTTP/1.1 y HTTP/2. (#19841)
  • Agregue el atributo network.protocol.version a las métricas de duración de la solicitud Spring WebFlux 5.0 client. (#19842)
  • Los tramos Ratpack HTTP client ahora incluyen el atributo network.protocol.version. (#19843)
  • Agregue otel.instrumentation.opensearch.query-sanitization.enabled (true predeterminado) para controlar si los cuerpos de las consultas de búsqueda capturadas se desinfectan; configúrelo en false para capturarlos palabra por palabra. (#19869)
  • Los intervalos de GenAI ahora incluyen el atributo gen_ai.request.stream cuando la solicitud utiliza transmisión. (#19879)
  • La instrumentación OpenAI Java 1.1 ahora informa los recuentos de tokens de entrada almacenados en caché como gen_ai.usage.cache_read.input_tokens y los recuentos de tokens de salida de razonamiento como gen_ai.usage.reasoning.output_tokens cuando los detalles de uso están disponibles. (#19906)
  • Ampliar la instrumentación del agente Java de Couchbase para admitir SDK 3.0.x. (#19996)
  • Agregue el atributo span aws.bedrock.guardrail.id a las solicitudes de AWS Bedrock Runtime cuando se configure un identificador de barandilla. (#20040)
  • Optar por la detección de recursos host.id para el agente Java con otel.resource.providers.host-id.enabled=true. (#20099)
  • Agregue URL de esquema de convenciones semánticas que tengan en cuenta el modo a los ámbitos de telemetría de base de datos, mensajería y RPC. (#20127)
  • Agregue la URL del esquema de convenciones semánticas a las métricas de tiempo de ejecución JVM cubiertas por el esquema. (#20255)
  • Los intervalos de operación de GraphQL ahora utilizan la URL del esquema de convenciones semánticas OpenTelemetry v1.44.0. (#20262)
  • Agregar la URL del esquema de convenciones semánticas a las métricas del sistema OSHI. (#20263)

🛠️ Corrección de errores

  • Los intervalos de Lettuce 5.1 client para fallas de comando Redis ahora tienen estado de error. (#19075)
  • Evitar bloqueos en el inicio de Javaagent causados por una inicialización diferida del almacenamiento de contexto bajo bloqueos del cargador de clases. (#19265)
  • Se corrigieron los nombres de intervalo de liquidación NATS JetStream de alta cardinalidad. Utilice $JS.ACK publish según las convenciones semánticas heredadas. (#19396)
  • Se corrigió la propagación de contexto para los métodos Kotlin @WithSpan delegados en la cola para que sus intervalos conserven el contexto correcto de la persona que llama. (#19446)
  • Se corrigieron los envíos asincrónicos de Camel para que los ámbitos de contexto se cierren en el hilo que inició el envío. (#19503)
  • Se corrigió el seguimiento de Vert.x HTTP client cuando una solicitud se vacía con sendHead() y luego se completa con end(), de modo que el intervalo del servidor se relaciona con el intervalo de client exportado. (#19547)
  • Manejar cadenas de causa de excepción cyclic sin extracción de errores bloqueados en instrumentaciones o análisis de reglas JMX. (#19625)
  • Sanitiza los cuerpos de consulta de búsqueda del agente Java REST Elasticsearch capturados de forma predeterminada, reemplazando los valores literales con ? y preservando al mismo tiempo la estructura de la consulta. Desactive la desinfección con otel.instrumentation.elasticsearch.query-sanitization.enabled=false. (#19675)
  • Evite la instrumentación duplicada del oyente Pulsar y suprima los intervalos de recepción duplicados durante las entregas anidadas, preservando el contexto principal para los intervalos de procesamiento. (#19699, #20137)
  • Las solicitudes canalizadas de Apache HttpAsyncClient ahora producen intervalos client. (#19710)
  • Las solicitudes del servidor Async Thrift después de una solicitud fallida en la misma conexión ya no se informan incorrectamente como errores. (#19712)
  • Suprimir métricas duplicadas de Apache Commons Pool para grupos que respaldan un Apache DBCP BasicDataSource cuando ambas instrumentaciones están habilitadas. (#19721)
  • Se corrigió el registro de depuración del iniciador Spring Boot cuando otel.spring-starter.debug=true. (#19725, #20034)
  • Se corrigieron métricas y tramos de procesamiento duplicados en Spring Rabbit, RabbitMQ y Spring Integration, preservando la telemetría para consumidores registrados por separado y tramos de controladores correctamente parentales. (#19732, #20138, #20200)
  • Las métricas del grupo de Oracle UCP ahora usan un nombre derivado de JDBC en lugar del nombre de UCP generado, consolidando los grupos conectados a la misma base de datos bajo un valor pool.name consistente. (#19745)
  • Complete los nombres de los comandos Redis para los intervalos client cuando utilice Lettuce 6.0.0–6.0.2. (#19763)
  • Se corrigió el manejo de @SpanAttribute para que los valores genéricos y las matrices se registren correctamente como atributos de intervalo. (#19785)
  • Evite NullPointerExceptions al finalizar solicitudes Jedis parcialmente inicializadas o cuando JSF no pueda derivar un nombre de extensión del servidor. (#19805)
  • Se corrigió la instrumentación del cargador de clases para que el agente java ya no inyecte su código auxiliar java.lang.ClassLoader reescrito como ayuda. (#19811)
  • Ahora se rastrean las solicitudes del servidor Pekko HTTP/2. (#19817)
  • Manejar índices de elección negativos en las finalizaciones de chat de transmisión OpenAI. (#19827)
  • Las solicitudes HTTP de Pekko rechazadas durante el análisis ahora producen tramos de servidor con su estado de respuesta y encabezados de respuesta personalizados. (#19829)
  • Los intervalos de finalización del chat de OpenAI ahora utilizan el tipo de intervalo CLIENT. (#19858)
  • Se corrigió la falta de intervalos de consumo de mensajes de RocketMQ para una sobrecarga adicional del constructor ConsumeService. (#19860)
  • Se corrigió la propagación de contexto para las tareas por lotes de Pekko para que los intervalos creados dentro de futuros programados conserven su padre correcto. (#19862)
  • Limite los cuerpos de consulta capturados de OpenSearch a 32.768 caracteres, coincidiendo con el límite de captura de consultas Elasticsearch. (#19870)
  • La captura del cuerpo de la consulta OpenSearch ahora utiliza el proveedor JSON configurado, preservando la configuración de serialización específica del asignador. (#19875)
  • La instrumentación del servidor de segunda mano omite los campos repetidos de propagación de contexto después de iniciar el período de solicitud. (#19895)
  • Se corrigió una carrera en la captura de la versión del protocolo Ratpack para que los intervalos registren la versión correcta del protocolo. (#19911)
  • La instrumentación de AWS Lambda ahora extrae el encabezado del seguimiento de rayos X de Context.getXrayTraceId() para continuar el seguimiento entrante. (#19920)
  • Se corrigió una fuga de alcance de contexto en el procesamiento de solicitudes del servidor Thrift. (#19925)
  • Permitir que el agente Java procese la clase org.h2.command.dml.Update$$Lambda de H2. (#19993)
  • El agente Java ahora se inicia cuando su JAR ya está en la ruta de clase de arranque sin agregar el JAR a la búsqueda de arranque nuevamente. (#20001)
  • El JDBC OpenTelemetryDriver ahora respeta otel.instrumentation.jdbc.query-sanitization.enabled, por lo que la desinfección de consultas específicas de JDBC puede anular la configuración común. (#20020)
  • Corrija duraciones inexactas para los intervalos de interceptores de productores y consumidores de Kafka finalizándolos inmediatamente, ya que los interceptores no pueden medir el tiempo de envío o sondeo del corredor. (#20044)
  • Los intervalos de consultas Vert.x SQL client 5 ahora informan db.name, server.address y server.port para conexiones configuradas con proveedores connectingTo. (#20050)
  • Mantenga el agente Java y los personalizadores de configuración declarativa Spring Boot funcionando con OpenTelemetry SDK 1.66.0. (#20109)
  • Evite que el truncamiento de la base de datos desinfectada y las consultas de búsqueda divida los pares sustitutos Unicode. (#20123)
  • Evite tramos de procesamiento de Kafka duplicados en Kafka Connect, Kafka Streams, Reactor Kafka y Vert.x, incluidas las transferencias asincrónicas, sin suprimir lotes no relacionados. (#20139, #20142, #20143)
  • Evite tramos de procesamiento JMS duplicados en las capas de escucha JMS, Spring JMS, Camel y SJMS. (#20140)
  • La instrumentación del servidor Apache ShenYu ya no genera resultados cuando los metadatos de la ruta son nulos, lo que permite que el procesamiento de solicitudes continúe sin un valor de ruta. (#20148)
  • Registre las excepciones manejadas por los controladores de errores de Spring Rabbit en el intervalo de procesamiento de mensajes. (#20178)
  • Se corrigió la detección del sistema de base de datos para los grupos Vert.x SQL client empaquetados por Vert.x 5.2. (#20191)
  • La instrumentación del reactor ahora propaga valores de contexto a través de devoluciones de llamada del editor impulsadas externamente incluso cuando el contexto capturado no tiene un intervalo válido. (#20192)
  • Los períodos de procesamiento de Spring Cloud AWS SQS ahora finalizan cuando se completan los oyentes asincrónicos, registrando sus eventuales fallas o estado de cancelación. (#20193)
  • Los períodos de procesamiento de AWS SDK v1 SQS ahora finalizan con fallas de devolución de llamada y restauran el contexto anterior cuando se activan los controladores forEach o forEachRemaining. (#20194)
  • Evite intervalos de procesamiento SQS duplicados cuando los controladores anidados de AWS Lambda procesan el mismo evento. (#20195)
  • Los servidores Spring MVC para los puntos finales del actuador Spring Boot ahora incluyen el atributo http.route. (#20216)
  • Se corrigieron sugerencias de reflexión faltantes para los campos del interceptor de escucha Spring Kafka y las clases JWT portadoras de OAuth en imágenes nativas GraalVM. (#20332)
