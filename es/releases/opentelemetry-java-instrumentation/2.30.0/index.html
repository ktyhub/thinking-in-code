opentelemetry-instrumentación-java v2.30.0

Esta versión está dirigida al OpenTelemetry SDK 1.64.0.

Tenga en cuenta que muchos artefactos tienen el sufijo -alpha adjunto a su número de versión, lo que refleja que seguirán teniendo cambios importantes. Consulte VERSIONING.md para obtener más detalles.

⚠️ Cambios importantes en los API no estables

  • Quitar ExperimentalInstrumentationModule#getModuleGroup(). Los módulos invokedynamic integrados ahora comparten un único InstrumentationModuleClassLoader y cada extensión está aislada por sí sola. (#18859)
  • Eliminar el obsoleto InstrumentationModule.isIndyModule(); Ahora el agente determina si un módulo utiliza invokedynamic en lugar de declararlo por módulo. (#19140)
  • Eliminar los API obsoletos relacionados con consultas de SqlClientAttributesGetter, CassandraRequest y Experimental. (#19165)
  • Eliminar los API de captura de atributos Enduser* obsoletos de la biblioteca Spring Security 6.0; utilice los reemplazos User* en su lugar. (#19168)

🚫 Depreciaciones

  • Desaprobar únicamente el bean de compatibilidad inicial Spring Boot ConfigProperties utilizado con la configuración declarativa experimental, en favor del nuevo bean ConfigProvider; se eliminará en 3.0. El bean ConfigProperties sigue siendo compatible con configuraciones no declarativas. (#19175)
  • Desaprobar DeclarativeConfigPropertiesBridge y DeclarativeConfigPropertiesBridgeBuilder. Utilice DeclarativeConfigProperties directamente o DeclarativeConfigBridge en su lugar. Se eliminará en 3.0. (#19202)
  • Desaprobar ConfigPropertiesBackedConfigProvider en favor de DeclarativeConfigBridge. Se eliminará en 2.31.0. (#19220)

🌟 Nueva instrumentación javaagent

  • Agregar instrumentación Javaagent para HBase client 1.4. (#19087)

🌟 Nueva instrumentación de biblioteca

  • Agregar instrumentación de biblioteca (ThriftTelemetry) para el servidor asíncrono Apache Thrift 0.13. (#19062)

📈 Mejoras

  • Agregar seguimiento de servidor asíncrono a la instrumentación del agente java Apache Thrift 0.13; Los controladores de servidor asíncronos anteriormente no estaban instrumentados. (#18994)
  • Admite database= como alias para databaseName al extraer db.name de las URL de MSSQL JDBC. (#19029)
  • Agregar soporte de operación por lotes a la opción de convención semántica de base de datos estable experimental (otel.semconv-stability.opt-in=database) en todas las instrumentaciones de bases de datos, incluidos los nombres de tramos de lotes, db.operation.batch.size (incluidos los lotes vacíos) y db.query.summary. (#19034, #19037, #19054, #19055, #19056, #19057, #19143, #19147, #19161, #19162, #19164, #19172, #19189, #19199)
  • Agregue seguimiento para los comandos reactivos de Lettuce 4.0, incluida la finalización y cancelación excepcionales. (#19071)
  • Agregar el sistema de destino de métricas experimental Cassandra JMX. (#19080)
  • Agregar métricas experimentales jvm.thread.virtual.pinned y jvm.thread.virtual.submit_failed basadas en JFR para subprocesos virtuales Java 19+; habilitar con otel.instrumentation.runtime-telemetry.emit-experimental-jfr-metrics=true. (#19092)
  • Capture valores de objetos personalizados pasados a PreparedStatement.setObject() en los atributos de los parámetros de consulta. (#19093)
  • InstrumentationModule ahora expone injectedClassNames() y exposedClassNames() para instrumentaciones independientes, por lo que los autores de módulos ya no necesitan ExperimentalInstrumentationModule para esas declaraciones de clase auxiliar. (#19142)
  • Agregar opciones captureTemplate y captureArguments a las instrumentaciones de registro log4j, java-util-logging y jboss-logmanager, capturando la plantilla de mensaje de registro y los argumentos como atributos log.body.template/log.body.parameters separados; Logback ya admitía estas opciones (#15423). (#19154)
  • Agregue los atributos server.address y server.port a los tramos Redisson client. (#19191)
  • Agregue los atributos server.address y server.port a los tramos de Lettuce Redis client. (#19192)
  • Agregue los atributos server.address y server.port a los tramos Rediscala client. (#19193)
  • Configure server.address en Dubbo client respaldado por registro que abarca la dirección de registro más el destino del servicio (registry://host:port/interface:version:group) y deje server.port sin configurar, cerrado detrás de la opción estable de rpc semconv (otel.semconv-stability.opt-in=rpc); el host y el puerto del proveedor resuelto se mantienen en el semconv predeterminado. (#17244, #19285)

🛠️ Corrección de errores

  • Se corrigió una advertencia falsa duplicada cuando el puente del registrador de aplicaciones se instala varias veces durante el inicio. (#19088)
  • Se corrigieron los valores de MySQL y MariaDB db.connection_string para que los hosts IPv6 permanezcan entre corchetes en lugar de volverse ambiguos. (#19078)
  • Se corrigieron los consumidores Pulsar de múltiples temas para que la recepción interna en segundo plano ya no cree un intervalo de recepción adicional falso. (#19095)
  • SpringConfigProperties.getMap() ya no evalúa los valores de propiedades del mapa como expresiones SpEL; Las propiedades de mapas que no están en mayúsculas y minúsculas ahora se analizan como pares key=value delimitados por comas a través del DefaultConfigProperties del SDK, por lo que configuraciones como otel.instrumentation.common.peer-service-mapping funcionan sin sintaxis SpEL. (#19113)
  • Se corrigió la extracción de destino JMS para que un destino ilegible ahora deje messaging.destination.name sin configurar en lugar de reportarlo como unknown. (#19115)
  • Se corrigieron las métricas JMX Metric Insight jvm.class.loaded y jvm.class.unloaded para usar instrumentos de contador. (#19141)
