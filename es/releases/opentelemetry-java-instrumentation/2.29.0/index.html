opentelemetry-instrumentación-java v2.29.0

Esta versión está dirigida al OpenTelemetry SDK 1.63.0.

Tenga en cuenta que muchos artefactos tienen el sufijo -alpha adjunto a su número de versión, lo que refleja que seguirán teniendo cambios importantes. Consulte VERSIONING.md para obtener más detalles.

⚠️ Cambios importantes en los API no estables

  • Cambiar el tipo de devolución para JmxTelemetry.start(...) API. (#18782)
  • La telemetría del paquete de tiempo de ejecución experimental ahora emite valores package.checksum_algorithm=SHA-256 y package.checksum de 64 caracteres en lugar de sumas de comprobación SHA1. (#18846)

🚫 Depreciaciones

  • Cambie el nombre de las claves de contexto de registro comunes a otel.instrumentation.common.logging.trace-id-key, otel.instrumentation.common.logging.span-id-key y otel.instrumentation.common.logging.trace-flags-key, manteniendo los nombres de propiedades anteriores en desuso. (#18851)
  • Cambie el nombre de los sistemas de destino JMX kafka-broker y kafka-connect a experimental-kafka-broker y experimental-kafka-connect; los nombres antiguos todavía funcionan por ahora y registran una advertencia. (#18971)

🌟 Nueva instrumentación javaagent

  • Agregar instrumentación SOFARPC 5.4 que emite RPC client y spans y métricas del servidor. (#15589)
  • Agregar instrumentación Javaagent para HBase client 2.0.0 hasta 2.5.0. (#18253)

📈 Mejoras

  • Agregue soporte de suscripción para emitir excepciones de solicitudes HTTP como señales de registro con otel.semconv.exception.signal.preview=logs. (#16259)
  • Agregar instrumentación Javaagent opentelemetry-api-1.63 para OpenTelemetry API 1.63 y opentelemetry-api-incubator 1.63. (#18911)
  • Agregue otel.semconv-stability.v3-preview como alternativa para la configuración de estabilidad semconv declarativa de v3_preview. (#18936)
  • Actualice la opción de convención semántica de la base de datos estable experimental (otel.semconv-stability.opt-in=database) en todas las instrumentaciones de la base de datos, incluidos los nombres de tramo y los atributos db.*. (#18808, #18853, #18920, #18922, #18926, #18930, #18970, #18979, #18980, #18984, #18985, #18986, #18987, #18989, #18990, #18992, #18993, #19004, #19005)
  • Captura de texto de consulta y parametrización para declaraciones por lotes de Cassandra. (#18964)
  • Mantenga opentelemetry-api y opentelemetry-instrumentation-annotations habilitados en otel.instrumentation.common.v3-preview incluso cuando default-enabled=false. (#18792)
  • Cuando otel.instrumentation.common.v3-preview está habilitado, los instrumentos afectados emiten atributos de identidad user.* en lugar de enduser.*. (#18795)
  • Deshabilitar las métricas de Kafka client de forma predeterminada cuando otel.instrumentation.common.v3-preview=true. (#18828)
  • Reconocer los prefijos de URL JDBC del contenedor de Amazon Aurora DSQL y AWS al analizar los metadatos de la conexión JDBC. (#18831)
  • Establecer versiones de instrumentación en alcances de medidores emitidos. (#18866)
  • Ejecute la instrumentación @WithSpan después de otras instrumentaciones para que otros consejos puedan adjuntar atributos al tramo activo. (#18874)
  • Emitir fallas de base de datos client como registros db.client.operation.exception cuando otel.semconv.exception.signal.preview está habilitado. (#18889)
  • Emitir excepciones RPC como registros de registro cuando otel.semconv.exception.signal.preview=logs está habilitado. (#18890)
  • Emitir excepciones de mensajes como registros de registro en otel.semconv.exception.signal.preview. (#18891)
  • Emitir registros de registro faas.invocation.exception para excepciones de FaaS cuando otel.semconv.exception.signal.preview=logs está habilitado. (#18892)
  • Emitir registros de gen_ai.client.operation.exception para fallas de incrustaciones y chat OpenAI cuando otel.semconv.exception.signal.preview=logs está habilitado. (#18893)
  • Emitir errores de solicitud de AWS SDK como registros de registro rpc.client.call.exception cuando otel.semconv.exception.signal.preview=logs está habilitado. (#18894)
  • La configuración declarativa ahora admite la selección de convenciones semánticas por dominio utilizando las configuraciones semconv.version, semconv.experimental y semconv.dual_emit. (#18908)
  • Cuando otel.instrumentation.common.v3-preview esté habilitado, use otel.semconv-stability.preview en lugar de otel.semconv-stability.opt-in para optar por las convenciones semánticas no estables service.peer y rpc. (#18914)
  • Deshabilite la instrumentación de las corrutinas Kotlin @WithSpan de forma predeterminada cuando otel.instrumentation.common.v3-preview=true. (#18919)
  • Utilice la ruta compatible con resumen en SqlQueryAnalyzer.analyze() cuando otel.instrumentation.common.v3-preview esté habilitado. (#18921)
  • Cuando otel.instrumentation.common.v3-preview está habilitado, los nombres de configuración de saneamiento JDBC/db obsoletos se ignoran en favor de db.query_sanitization.enabled. (#18934)
  • Incluir jvm.gc.cause en las métricas de duración de GC cuando otel.instrumentation.common.v3-preview esté habilitado. (#18967)
  • Emitir métricas de duración para las operaciones de transacciones JDBC COMMIT y ROLLBACK. (#19003)
  • Utilice una clase InstrumentationVersion generada en OkHttp 3.0 en lugar de leer las propiedades de la versión integrada, evitando violaciones de lectura de disco de Android StrictMode. (#19006)
  • Agregue atributos de extensión de detalles de hilo para la configuración declarativa de Spring Starter cuando se establece distribution.spring_starter.thread_details_enabled. (#19008)

🛠️ Corrección de errores

  • Preservar el contexto actual para futuras ejecuciones de comandos Redisson para que las operaciones asíncronas continúen el seguimiento activo. (#18701)
  • Evite que el agente Pulsar cree intervalos de recepción duplicados para consumidores de múltiples temas. (#18771)
  • Se corrigió un bloqueo en las solicitudes de transmisión de Ktor client para que los intervalos finalicen rápidamente con Ktor 3.5.0. (#18781)
  • Se corrigió un Bedrock converseStream NullPointerException cuando una llamada a una herramienta tiene argumentos vacíos. (#18783)
  • Capture el ID del mensaje Pulsar antes para que los grupos de productores puedan registrarlo de manera confiable. (#18803)
  • Se corrigió la declaración JDBC de SQLite y la instrumentación de declaraciones preparadas para que las conexiones SQLite produzcan intervalos de SQL y captura de parámetros. (#18885)
  • Se corrigieron las claves de configuración declarativa de Logback MDC para que la configuración de otel.instrumentation/development.java.* se aplique correctamente. (#18924)
  • Se corrigió la desinfección de contraseñas de SQL para destinos DDL de mayúsculas y minúsculas como create table y alter table. (#18927)
  • Los registros emitidos a través de registradores Log4j asíncronos ahora mantienen el OpenTelemetry Context del subproceso de la aplicación en lugar de recurrir a la recuperación de solo intervalo. (#18937)
  • Evite errores de instrumentación al cargar redis.clients.jedis.Jedis, BinaryJedis y UnifiedJedis. (#19000)
  • Ejecute devoluciones de llamadas asíncronas de OpenSearch con el contexto principal de la solicitud. (#19027)
