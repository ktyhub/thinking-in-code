opentelemetry-instrumentación-java v2.26.0

Esta versión está dirigida al OpenTelemetry SDK 1.60.1.

Tenga en cuenta que muchos artefactos tienen el sufijo -alpha adjunto a su número de versión, lo que refleja que todavía tienen calidad alfa y seguirán teniendo cambios importantes. Consulte VERSIONING.md para obtener más detalles.

⚠️ Cambios importantes en los API no estables

  • Eliminar los envoltorios obsoletos de AWS Lambda v2.2 y la sobrecarga de forceFlush(int, TimeUnit) (#16170)
  • Eliminar los métodos de servidor/HTTP client obsoletos (#16167)
  • Eliminar métodos y clases de instrumentación de bases de datos obsoletos (#16164)
  • Eliminar la asignación obsoleta de servicios de pares API (#16165)
  • Hacer que las clases obsoletas de telemetría en tiempo de ejecución sean ahora internas (#16173)
  • Eliminar AttributesExtractorUtil (#16152)
  • Eliminar interfaz de marcador de SqlClientAttributesGetter (#16205)
  • Fusionar métodos captadores de red/servidor en captadores de atributos de base de datos (#16264, #16268)
  • Cambiar el nombre de las clases de desinfectante SQL a analizador SQL (#16269)
  • Cambie el nombre de los paquetes de módulos comunes internos para seguir la nueva convención de nomenclatura (#16284, #16308, #16327, #16341, #16373)

🚫 Depreciaciones

  • Se desaprobaron las clases de módulos de telemetría de tiempo de ejecución individuales en favor del módulo unificado (#16087)
  • Se desaprobaron los antiguos métodos de parámetros de consulta del servidor HTTP a favor del manejo de parámetros de consulta sensibles (#16097)
  • Se desaprobaron los antiguos métodos de captación de atributos RPC en favor de otros nuevos que admitan convenciones semánticas estables (#16130)
  • Métodos de instrumentación antiguos de ClickHouse obsoletos como parte de la simplificación (#16206)
  • Se desaprobaron los métodos antiguos de R2DBC en favor de los que admiten db.system.name (#16251)
  • Métodos DbClientAttributesGetter antiguos obsoletos; agregado getErrorType() con implementaciones (#16276)
  • Se desaprobaron los antiguos métodos de métricas RPC en favor de aquellos que soportan convenciones semánticas estables (#16298)
  • Métodos DbClientAttributesGetter antiguos obsoletos; se agregó getDbName() para admitir mejor la división semconv antigua/estable (#16318)

📈 Mejoras

  • Agregar dirección de servidor y atributos de puerto para Spymemcached (#15242)
  • Agregue Kafka Connect como destino de métricas JMX integrado (#15561)
  • Convertir la instrumentación de Lettuce para usar Instrumenter (#15838)
  • OpenSearch Java client: captura cuerpos de consultas de búsqueda desinfectados (#15634)
  • Aplicar convenciones semánticas estables a las métricas de Camel JMX (#16088)
  • Agregar métrica jvm.file_descriptor.limit (#16174)
  • Ejecutar devoluciones de llamada gRPC client con contexto principal (#16175)
  • Resumen de SQL: manejar declaraciones EXPLAIN (#16184)
  • Simplifique la instrumentación de InfluxDB (#16207)
  • Actualizar depósitos de histograma para db.client.operation.duration (#16222)
  • Resumen de SQL: admite la sintaxis dblink de Oracle (#16230)
  • Agregar instrumentación para la ruta del servidor HTTP ZIO (#16232)
  • Eliminar atributos de red bajo el indicador semconv estable de la base de datos (#16257)
  • Soporte Javalin 7 (#16261)
  • gRPC: soporte inicial estable de semconv (#16304)
  • Completar el atributo de recurso os.version (#16311)
  • Camel: no emite intervalos de base de datos en semconv estable (#16275)
  • Dubbo: soporte estable para semconv (#16352)
  • Actualice la versión OpenTelemetry SDK a 1.60.0 (#16407)
  • Utilice el nuevo LogRecordBuilder.setException() estable (#16423)
  • Configurar semconv-stability.opt-in con la configuración declarativa API (#16443)
  • Soporte otel.event.name (#16220)

🛠️ Corrección de errores

  • El desinfectante SQL ahora trata los fragmentos entre comillas dobles como cadenas literales de forma predeterminada (#15582)
  • Borrar excepción registrada cuando se completa la solicitud (#16138)
  • Borrar el estado de la conexión URL después de finalizar el intervalo (#16155)
  • Se corrigió la configuración declarativa de Spring con sustitución de variables de entorno (#15775)
  • Se corrigió el manejo de errores de canalización de envío del servidor Ktor (#16192)
  • Agregadores de registro: los atributos KeyValue deben tener prioridad sobre MDC (#16239)
  • Crear nuevo PekkoRouteHolder para cada solicitud (#16258)
  • Tomcat JMX: ignora los límites de sesiones y subprocesos negativos (#16355)
  • Se requiere server.port en los intervalos HTTP client (#16388)
  • Se corrigió la instrumentación del servidor Ktor resolviendo la dirección del par (#16392)
  • Se corrigió la excepción de conversión de clase en la instrumentación de servlet (#16403)
  • Se corrigió el cuerpo de respuesta vacío en Jetty HttpClient 9.4.24–9.4.43 (#16406)
