opentelemetry-instrumentación-java v2.31.0

Esta versión está dirigida al OpenTelemetry SDK 1.65.0.

Tenga en cuenta que muchos artefactos tienen el sufijo -alpha adjunto a su número de versión, lo que refleja que seguirán teniendo cambios importantes. Consulte VERSIONING.md para obtener más detalles.

⚠️ Cambios importantes en API no estables

  • Elimine el ConfigPropertiesBackedConfigProvider obsoleto y su compatibilidad con create(ConfigProperties) API del puente de configuración declarativa. (#19305)
  • Dejar de exponer opentelemetry-instrumentation-api-incubator en las rutas de clase de compilación de instrumentación de la biblioteca. (#19612)

🚫 Depreciaciones

  • Desaprobar otel.instrumentation.experimental.span-suppression-strategy en favor de Experimental.setSpanSuppressionStrategy(...). (#19180)
  • Desaprobar HostIdResource.REGISTRY_QUERY en favor de la búsqueda de ruta absoluta reg.exe utilizada por HostIdResource. (#19293)
  • Desaprobar MessageOperation en favor de MessagingOperationType y las sobrecargas de MessageOperation de MessagingAttributesExtractor, MessagingConsumerMetrics, MessagingProducerMetrics, MessagingSpanKindExtractor y MessagingSpanNameExtractor en favor de los MessagingOperationType API correspondientes. (#19357)
  • Desaprobar otel.traces.exporter=zipkin en favor de otel.traces.exporter=otlp y otel.exporter.zipkin.endpoint en favor de otel.exporter.otlp.traces.endpoint. (#19400)
  • Desaprobar OpenTelemetryMeterRegistryBuilder#setMicrometerHistogramGaugesEnabled(boolean) en favor de Experimental#setMicrometerHistogramGaugesEnabled(OpenTelemetryMeterRegistryBuilder, boolean). (#19404)
  • Desaprobar las propiedades de captura de parámetros de solicitud de servlet, encabezado de mensajes y metadatos gRPC heredados y API en favor de la configuración .included/.excluded basada en selectores y IncludeExclude API. (#19494, #19522, #19523, #19638)
  • Desaprobar otel.instrumentation.runtime-telemetry.experimental.prefer-jfr en favor de otel.instrumentation.runtime-telemetry.experimental.jfr-metrics.included y setPreferJfrMetrics(...) en favor de setJfrMetrics(RuntimeTelemetryBuilder, IncludeExclude). (#19495)
  • Desaprobar la configuración booleana y de lista de captura para datos MDC/contexto, mensajes de mapa, pares clave-valor, contexto de registrador, marcadores Logstash y argumentos estructurados a favor de los selectores .included/.excluded y IncludeExclude API. (#19519, #19520, #19521, #19599, #19600, #19605, #19609, #19610)
  • Desaprobar el campo de configuración declarativa general.semconv_stability.opt_in en favor de general.stability_opt_in_list y general.sanitization.url.sensitive_query_parameters/development en favor de general.sanitization.url.sensitive_query_parameters. (#19561)
  • Desaprobar otel.instrumentation.graphql.add-operation-name-to-span-name.enabled en favor de otel.instrumentation.graphql.operation-name-in-span-name.enabled y otel.instrumentation.runtime-telemetry.package-emitter.enabled/jars-per-second en favor de otel.instrumentation.runtime-telemetry.experimental.package-emitter.enabled/jars-per-second. (#19573)
  • Desaprobar los métodos de creación de encabezados de respuesta y solicitudes capturadas en las instrumentaciones de la biblioteca HTTP en favor de los requestHeaders(IncludeExclude) y responseHeaders(IncludeExclude) API basados en selectores. (#19598, #19601, #19602, #19603, #19604, #19606, #19607, #19608)
  • Desaprobar otel.instrumentation.micrometer.histogram-gauges.enabled en favor de otel.instrumentation.micrometer.experimental.histogram-gauges.enabled. (#19613)

🌟 Nueva instrumentación javaagent

  • Agregar instrumentación Apache Commons Pool 2 para métricas del grupo de objetos. (#19091)
  • Agregar instrumentación del agente java Apache HBase client 1.0. (#19243)
  • Agregue métricas del grupo de conexiones Redisson para 3.26+. (#19392)
  • Agregar soporte para métricas de incubadora OpenTelemetry API 1.65 en el agente Java. (#19456)
  • Agregar instrumentación javaagent Tomcat DBCP 8.0 para métricas del grupo de bases de datos. (#19472)

📈 Mejoras

  • Agregue metadatos del paquete OSGi opcional para la instrumentación seleccionada, los artefactos de extensión API y SDK para que puedan consumirse directamente en los tiempos de ejecución de OSGi. (#18995)
  • Agregue medidores cassandra.compaction.progress.completed y cassandra.compaction.progress.size para compactaciones Cassandra en vuelo. (#19290)
  • Obtenga una vista previa de las próximas convenciones semánticas de mensajería 3.0 detrás de otel.semconv-stability.opt-in=messaging en AWS SQS y Lambda, JMS, Kafka, NATS, Pulsar, RabbitMQ, RocketMQ, Spring Integration y las instrumentaciones de mensajería Spring. (#19347, #19348, #19349, #19350, #19351, #19353, #19354, #19355, #19356, #19476, #19477, #19478, #19479, #19480, #19481, #19482, #19486, #19487, #19499, #19500, #19504, #19505, #19507, #19508, #19535, #19544, #19565, #19567, #19639, #19640)
  • Según las próximas convenciones semánticas RPC 3.0 detrás de otel.semconv-stability.opt-in=rpc, las solicitudes de Dubbo a servicios desconocidos emiten intervalos de servidor incluso cuando la decodificación falla antes de DubboProtocol.getInvoker() y registran el método original en rpc.method_original. (#16668)
  • Los datos de contexto de Log4j ahora incluyen entradas baggage.* incluso cuando no hay un intervalo actual. (#19378)
  • Cuando otel.instrumentation.common.v3-preview=true, el puente micrométrico ya no exporta calibres .max para Timer y DistributionSummary. (#19397)
  • Agregue el selector IncludeExclude API a opentelemetry-instrumentation-api para hacer coincidir cadenas con patrones globales incluidos y excluidos. (#19451)
  • Emitir atributos de consistencia, coordinador, tamaño de página, idempotencia y ejecución especulativa del controlador Cassandra 3. (#19629)
  • Ampliar las próximas convenciones semánticas de la base de datos 3.0 detrás de otel.semconv-stability.opt-in=database, incluidos nombres de operaciones, espacios de nombres, nombres de colecciones, parámetros de operación, telemetría por lotes y tipos de errores para Couchbase, Redis clients, Elasticsearch, R2DBC, JDBC, ClickHouse, MongoDB y HBase. (#19616, #19623, #19664, #19665, #19668, #19670, #19704, #19705, #19706, #19707, #19708)
  • Agregue otel.instrumentation.influxdb.query-sanitization.enabled para controlar la desinfección de consultas de InfluxDB, teniendo prioridad sobre otel.instrumentation.common.db.query-sanitization.enabled. (#19703)

🛠️ Corrección de errores

  • Utilice nombres de métricas estables derivados de bases de datos para grupos de conexiones sin nombre de Alibaba Druid, c3p0, Tomcat JDBC, HikariCP y Vibur. (#19108, #19159, #19173, #19470, #19471)
  • Las métricas de Apache DBCP 2.0 ahora se registran cuando el grupo se inicia incluso sin registro JMX y se cancelan el registro en close(). (#19160)
  • Omita la instrumentación de herramientas JDK iniciadas desde $JAVA_HOME/bin a menos que esté configurado otel.javaagent.enabled=true. (#19203)
  • Se corrigieron las métricas de Jetty JMX para emitir jetty.select.count en lugar de jetty.io.select.count para recuentos de llamadas selectas. (#19249)
  • Se corrigió que el grupo de conexiones Redisson permitiera fugas cuando se cancela un comando asíncrono en espera. (#19340)
  • Se corrigió la detección de ruta de Spring WebFlux para que los tramos del controlador mantengan un nombre de ruta legible en JDK 21+. (#19365)
  • Normalizar los valores IPv6 JDBC server.address a direcciones simples en lugar de literales entre corchetes. (#19366)
  • Reparar la instrumentación de Lettuce 5.1 con indy inyectando io.lettuce.core.protocol.OtelCommandArgsUtil como clase auxiliar. (#19373)
  • Agregue un tiempo de espera de 2 segundos a la detección de recursos de host.id para que los comandos de búsqueda lenta ya no bloqueen el inicio de SDK. (#19377)
  • Se corrigió la instrumentación de Azure Core para que las aplicaciones que no usan OpenTelemetry API aún obtengan el seguimiento de Azure SDK. (#19387)
  • El análisis de URL MySQL JDBC ahora maneja hosts, puertos y parámetros de consulta en formatos de URL no estándar de manera más confiable. (#19394)
  • Precargue MethodHandle$1 durante el inicio del agente para evitar ClassCircularityError en JDK 17 que puede romper el enlace del sitio de llamada dinámica de invocación. (#19398)
  • Redactar datos confidenciales de los parámetros de consulta de AWS SigV4, las URL REST de AWS Lambda API Gateway y Elasticsearch, credenciales de URL integradas y líneas de comando de proceso. (#19422, #19424, #19425, #19514)
  • Corrija los nombres de los medidores personalizados de Micrometer y evite que las descripciones de métricas se filtren entre instrumentos o registros relacionados. (#19463, #19466, #19467)
  • Se corrigió activemq.destination.temp.utilization para convertir valores % a una fracción sin unidades. (#19512)
  • Se corrigió jetty.thread.queue.size para usar la unidad {job} en lugar de {thread}. (#19513)
  • Se corrigieron los puntos finales de métricas del actuador Spring Boot cuando el registro del micrómetro OpenTelemetry forma parte de un registro compuesto o no puede devolver valores métricos. (#19515, #19541)
  • Las direcciones IPv6 en los encabezados Host ahora se analizan correctamente, incluidos los puertos entre corchetes. (#19540)
  • Se corrigieron los intervalos de recepción de Pulsar según las convenciones semánticas de mensajería heredadas para evaluar la supresión en comparación con el contexto del productor extraído cuando la telemetría de recepción está deshabilitada. (#19592)
  • Preservar el tipo ClusterInvoker de Dubbo al capturar la dirección de registro del consumidor. (#19568)
  • Dejar de advertir sobre configuraciones de captura basadas en selectores obsoletas cuando también se configura el reemplazo correspondiente de .included o .excluded. (#19571)
  • Preservar el caso original del nombre de la base de datos configurada en db.name heredado y db.namespace estable para tramos R2DBC. (#19615)
  • Capture intervalos para consultas preparadas explícitas en Vert.x SQL client para que la ejecución de PreparedStatement.query() mantenga las opciones de conexión y db.system correctas. (#19619)
  • Se corrigió la desinfección de Cassandra 3 SimpleStatement para que los valores vinculados se detecten y oculten en db.statement. (#19620)
  • Emitir eventos de excepción y registros para operaciones fallidas de JDBC commit y rollback. (#19621)
  • Borrar el estado de telemetría de lotes de JDBC después de executeBatch() y executeLargeBatch() para que los intervalos de lotes posteriores ya no informen sobre contenidos de lotes obsoletos. (#19622)
  • Mantenga server.address y server.port para operaciones fallidas de Cassandra 3 extrayendo el coordinador de CoordinatorException. (#19627)
  • El texto de la consulta SQL ahora se desinfecta con db.system.name, por lo que los identificadores entre comillas dobles permanecen intactos para las bases de datos que los tratan como identificadores. (#19632)
  • Reparar la instrumentación de AWS Lambda RequestHandler para que los métodos handleRequest que devuelven void se manejen correctamente. (#19714)
