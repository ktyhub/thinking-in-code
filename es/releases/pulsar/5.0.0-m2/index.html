Cambios importantes

  • La configuración de JUL (java.util.logging) ya no es efectiva para los componentes del lado del servidor (#26330)

    Anteriormente, los registros de bibliotecas de terceros que usaban JUL (por ejemplo, Jersey/Jetty, gRPC, Guava) no eran administrados por la configuración Log4j2 de Pulsar, lo que dificultaba su control y provocaba una salida de registro inconsistente. Para resolver esto, el registro de bibliotecas de terceros ahora está conectado desde JUL a Log4j2 a través de log4j-jul. Esto unifica todos los registros en conf/log4j2.yaml, pero significa que las siguientes configuraciones y configuraciones de JUL API ya no tienen efecto:

    • -Djava.util.logging.config.file=logging.properties: se ignora todo el archivo de configuración JUL
    • java.util.logging.Logger.setLevel() / addHandler(): se convierten en no operativos
    • java.util.logging.LogManager.reset(): se vuelve no operativo

    Migración: mueva cualquier configuración de registro basada en JUL a conf/log4j2.yaml. Por ejemplo, para suprimir los registros gRPC que se configuraron previamente como io.grpc.level=SEVERE en logging.properties, agregue lo siguiente a conf/log4j2.yaml:

    Loggers:
  Logger:
    - name: io.grpc
      level: error

    Revertir: Para restaurar el comportamiento del stock JUL, configure:

    PULSAR_EXTRA_OPTS="-Djava.util.logging.manager=java.util.logging.LogManager"
