🎯 Principales fonctionnalités

🕵️ Prise en charge des navigateurs non détectés

Percez les systèmes sophistiqués de détection de robots grâce à nos nouvelles capacités furtives :

from crawl4ai import AsyncWebCrawler, BrowserConfig

# Enable stealth mode for undetectable crawling
browser_config = BrowserConfig(
    browser_type="undetected",  # Use undetected Chrome
    headless=True,              # Can run headless with stealth
    extra_args=[
        "--disable-blink-features=AutomationControlled",
        "--disable-web-security"
    ]
)

async with AsyncWebCrawler(config=browser_config) as crawler:
    # Successfully bypass Cloudflare, Akamai, and custom bot detection
    result = await crawler.arun("https://protected-site.com")
    print(f"✅ Bypassed protection! Content: {len(result.markdown)} chars")

Ce qu'il permet :

  • Accéder aux sites et bases de données d'entreprise précédemment bloqués
  • Recueillir les données des concurrents à partir de sources protégées
  • Surveiller les prix sur les sites de commerce électronique avec des mesures anti-bot
  • Collecter des actualités et du contenu sur les réseaux sociaux malgré les systèmes de protection

🎨 Système de configuration multi-URL

Appliquez automatiquement différentes stratégies d'exploration à différents modèles d'URL :

from crawl4ai import CrawlerRunConfig

# Define specialized configs for different content types
configs = [
    # Documentation sites - aggressive caching, include links
    CrawlerRunConfig(
        url_matcher=["*docs*", "*documentation*"],
        cache_mode="write",
        markdown_generator_options={"include_links": True}
    ),
    
    # News/blog sites - fresh content, scroll for lazy loading
    CrawlerRunConfig(
        url_matcher=lambda url: 'blog' in url or 'news' in url,
        cache_mode="bypass",
        js_code="window.scrollTo(0, document.body.scrollHeight/2);"
    ),
    
    # API endpoints - structured extraction
    CrawlerRunConfig(
        url_matcher=["*.json", "*api*"],
        extraction_strategy=LLMExtractionStrategy(
            provider="openai/gpt-4o-mini",
            extraction_type="structured"
        )
    ),
    
    # Default fallback for everything else
    CrawlerRunConfig()
]

# Crawl multiple URLs with perfect configurations
results = await crawler.arun_many([
    "https://docs.python.org/3/",      # → Uses documentation config
    "https://blog.python.org/",        # → Uses blog config  
    "https://api.github.com/users",    # → Uses API config
    "https://example.com/"             # → Uses default config
], config=configs)

Parfait pour :

  • Sites à contenus mixtes (blogs, docs, téléchargements)
  • Exploration multi-domaines avec des besoins différents par domaine
  • Élimination de la logique conditionnelle complexe dans le code d'extraction
  • Optimiser les performances en donnant à chaque URL exactement ce dont elle a besoin

🧠 Surveillance et optimisation de la mémoire

Suivez et optimisez l’utilisation de la mémoire lors d’opérations à grande échelle :

from crawl4ai.memory_utils import MemoryMonitor

# Monitor memory during crawling
monitor = MemoryMonitor()
monitor.start_monitoring()

# Perform memory-intensive operations
results = await crawler.arun_many([
    "https://heavy-js-site.com",
    "https://large-images-site.com", 
    "https://dynamic-content-site.com"
] * 100)  # Large batch

# Get detailed memory report
report = monitor.get_report()
print(f"Peak memory usage: {report['peak_mb']:.1f} MB")
print(f"Memory efficiency: {report['efficiency']:.1f}%")

# Automatic optimization suggestions
if report['peak_mb'] > 1000:  # > 1GB
    print("💡 Consider batch size optimization")
    print("💡 Enable aggressive garbage collection")

Avantages :

  • Prévenir les plantages liés à la mémoire dans les services de production
  • Ressources de serveur de bonne taille en fonction des modèles d'utilisation réels
  • Identifier les goulots d'étranglement pour l'optimisation des performances
  • Planifier une mise à l'échelle horizontale en fonction des besoins en mémoire

📊 Extraction de table améliorée

Conversion directe de pandas DataFrame à partir de tables Web :

result = await crawler.arun("https://site-with-tables.com")

# New streamlined approach
if result.tables:
    print(f"Found {len(result.tables)} tables")
    
    import pandas as pd
    for i, table in enumerate(result.tables):
        # Instant DataFrame conversion
        df = pd.DataFrame(table['data'])
        print(f"Table {i}: {df.shape[0]} rows × {df.shape[1]} columns")
        print(df.head())
        
        # Rich metadata available
        print(f"Source: {table.get('source_xpath', 'Unknown')}")
        print(f"Headers: {table.get('headers', [])}")

# Old way (now deprecated)
# tables_data = result.media.get('tables', [])  # ❌ Don't use this

Améliorations :

  • Transition plus rapide des données Web vers des DataFrames prêts pour l'analyse
  • Intégration plus propre avec les pipelines de traitement des données
  • Extraction de table simplifiée pour un reporting automatisé
  • Meilleure préservation de la structure de la table

🐳 Flexibilité du fournisseur Docker LLM

Basculez entre les fournisseurs LLM sans reconstruire les images :

# Option 1: Direct environment variables
docker run -d \
  -e LLM_PROVIDER="groq/llama-3.2-3b-preview" \
  -e GROQ_API_KEY="your-key" \
  -p 11235:11235 \
  unclecode/crawl4ai:0.7.3

# Option 2: Using .llm.env file (recommended for production)
docker run -d \
  --env-file .llm.env \
  -p 11235:11235 \
  unclecode/crawl4ai:0.7.3

Créez le fichier .llm.env :

LLM_PROVIDER=openai/gpt-4o-mini
OPENAI_API_KEY=your-openai-key
GROQ_API_KEY=your-groq-key

Remplacer par demande si nécessaire :

# Use cheaper models for simple tasks, premium for complex ones
response = requests.post("http://localhost:11235/crawl", json={
    "url": "https://complex-page.com",
    "extraction_strategy": {
        "type": "llm",
        "provider": "openai/gpt-4"  # Override default
    }
})

Docker Images

docker pull unclecode/crawl4ai:0.7    # Minor version

Notes de migration

  • result.tables remplace result.media.get('tables')
  • Le navigateur non détecté nécessite browser_type="undetected"
  • Multi-config utilise le paramètre url_matcher dans CrawlerRunConfig
