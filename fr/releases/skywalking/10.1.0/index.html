skywalking v10.1.0

Mineure Publié29 sept. 2024 Sourceapache/skywalking Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

marche en parachute v10.1.0

Télécharger

https://skywalking.apache.org/downloads/

Avis

Ne téléchargez pas les codes sources à partir de cette page. Veuillez suivre build document, si vous souhaitez créer des codes sources par vous-même.

Une version PERFORMANCE

  • Énorme amélioration des performances de l'interface utilisateur. Les requêtes des widgets de métriques sont regroupées en exploitant les fonctionnalités de GraphQL.
  • Prise en charge des requêtes parallèles dans le moteur GraphQL. Améliorez les performances des requêtes.
  • Améliore considérablement les performances du gestionnaire de métriques OTEL. Réduisez les coûts CPU et GC dans les processus de métriques OTEL.
  • Avec l'adoption de BanyanDB 0.7, les performances et la stabilité des bases de données natives sont améliorées.

Projet

  • E2E : remplacez la version du collecteur opentelemetry par 0.102.1.
  • Transférez l'image docker du générateur de données d'instantané vers ghcr.io.
  • Augmentez skywalking-infra-e2e pour contourner GHA en supprimant docker-compose v1.
  • Augmentez les actions CodeQL GitHub.
  • Correction d'une mauvaise phase du plugin Delombok pour réduire les avertissements de build.
  • Utilisez la révision ci-friendly pour définir la version du projet.

Serveur OAP

  • Correction d'indices erronés dans les modèles liés au profilage eBPF.
  • La prise en charge exclut le trafic d'espaces de noms spécifiques dans le récepteur du journal d'accès eBPF.
  • Ajoutez Golang comme langue prise en charge pour Elasticsearch.
  • Supprimez les journaux de vidage BanyanDB inutiles (infos).
  • Augmentez SW_CORE_GRPC_MAX_MESSAGE_SIZE à 50 Mo.
  • Prise en charge des métriques de relation d'interrogation via PromQL.
  • Prise en charge de la requête trace MQE pour le débogage.
  • Ajoutez l'ID de composant (158) pour le framework Solon.
  • Correction de la balise de métriques dans le gestionnaire HTTP du plugin récepteur du navigateur.
  • Augmentez la longueur de la colonne alarm_record#message de 200 à 2 000.
  • Supprimez l'indexation des colonnes alarm_record#message.
  • Ajoutez Python comme langue prise en charge pour Pulsar.
  • Créez des compartiments d'histogramme plus appropriés pour le persistence_timer_bulk_prepare_latency, Métriques persistence_timer_bulk_execute_latency et persistence_timer_bulk_all_latency dans PersistenceTimer.
  • [Break Change] Mettez à jour la version de Nacos vers 2.3.2. Le serveur Nacos 1.x ne peut pas servir de coordinateur de cluster et de serveur de configuration.
  • Prise en charge des requêtes de trace de traçage (SkyWalking et Zipkin) pour le débogage.
  • Correction de la requête de métriques BanyanDB : utilisation du mauvais type Downsampling pour trouver le schéma.
  • Prise en charge de la récupération du flux de cils pour surveiller le trafic réseau entre les services de cils.
  • Prise en charge de la fonction labelCount dans le moteur OAL.
  • Prise en charge du suivi de l'exécution des requêtes de mesure interne de BanyanDB.
  • Configuration BanyanDB client : augmentez la valeur par défaut de maxBulkSize à 10 000, ajoutez flushTimeout et définissez la valeur par défaut sur 10 s.
  • Polonais le groupe BanyanDB et la logique de création de schéma pour résoudre le problème d'échec de la création de schéma dans des conditions de concurrence distribuée.
  • Prise en charge de la requête de topologie de traçage pour le débogage.
  • Correction de l'expression du graphique Current QPS dans le tableau de bord MySQL.
  • Prise en charge de la requête des journaux de traçage pour le débogage.
  • BanyanDB : correction du stockage et des requêtes de données de saisie semi-automatique des balises.
  • Prise en charge des opérateurs d'agrégation dans la requête PromQL.
  • Mettez à jour l'unité source des métriques liées à la latence HTTP kubernetes de ns à ms.
  • Prise en charge du traçage de l'exécution des requêtes de flux interne BanyanDB.
  • Correction des fautes de frappe et des expressions manquantes dans les tableaux de bord Elasticsearch, MySQL, RabbitMQ.
  • BanyanDB : le module Zipkin définit le service comme entité pour améliorer les performances des requêtes.
  • MQE : vérifiez la valeur des métriques avant d'effectuer une opération binaire pour améliorer la robustesse.
  • Remplacez la solution de contournement par le chemin de contexte pris en charge natif d'Armeria.
  • Ajoutez un wrapper de point de terminaison http pour le contrôle de santé.
  • Augmentez Armeria et les dépendances transitives.
  • BanyanDB : si la colonne modèle est déjà un @BanyanDB.TimestampColumn, définissez @BanyanDB.NoIndexing dessus pour réduire les index.
  • BanyanDB : requête de tri par flux time, utilisation de séries temporelles internes plutôt que index pour améliorer les performances de la requête.
  • Passez graphql-java à 21.5.
  • Ajouter un nœud inconnu lorsque l'adresse du homologue Kubernetes reçu n'est pas connue dans le cluster actuel.
  • Correction de l'augmentation simultanée de CounterWindow provoquant NPE par PriorityQueue
  • Correction du formatage du nom du point de terminaison avec une chaîne vide.
  • Prise en charge de la requête asynchrone pour la requête composite GraphQL.
  • Obtenez l'ordre de la liste des points de terminaison par description d'horodatage.
  • Prise en charge des requêtes de tri sur les métriques générées par le récepteur eBPF.
  • Correction de la compatibilité avec Grafana 11 lors de l'utilisation des variables de requête label_values.
  • Nacos en tant que serveur de configuration et coordinateur de cluster prend en charge la configuration contextPath.
  • Mettez à jour le format du nom du point de terminaison en <Method>:<Path> dans le récepteur de journaux d'accès eBPF.
  • Ajoutez des métriques d'auto-observabilité pour le récepteur OpenTelemetry.
  • Prise en charge de l'agrégation des métriques de niveau de service en cas d'absence de contexte de pod dans le récepteur de journaux d'accès eBPF.
  • Correction de la requête getGlobalTopology qui lève une exception lorsqu'elle ne trouve aucun service par la couche donnée.
  • Correction du résultat d'analyse précédent manquant dans l'analyseur ALS k8s-mesh.
  • La requête Fix findEndpoint nécessite keyword lors de l'utilisation de BanyanDB.
  • Prise en charge de l'analyse de l'adresse IP mappée par ztunnel et du mode mTLS dans le récepteur de journal d'accès eBPF.
  • Adapter BanyanDB Java Client 0.7.0.
  • Ajouter le tableau de bord d'auto-observabilité de SkyWalking Java Agent.
  • Ajoutez l'ID de composant (5022) pour le framework GoFrame.
  • Augmentez les dépendances Java de Protobuf vers 3.25.5.
  • BanyanDB : prise en charge de la recherche de termes natifs pour keyword dans les requêtes findEndpoint et getAlarm.
  • BanyanDB : prend en charge la connexion et la configuration TLS.
  • Service PromQL : la requête API prend en charge le format d'heure RFC3399.
  • Améliorer les performances du gestionnaire de métriques OTEL.
  • Service PromQL : correction du résultat des opérateurs manquant l'indicateur rangeExpression.
  • BanyanDB : utilisez TimestampRange pour améliorer la requête "événements" pour BanyanDB.
  • Optimisez la table network_address_alias pour réduire le numéro de l'index.
  • Service PromQL : prise en charge de l'opérateur de parenthèses rondes.
  • Prise en charge de l'étiquette de message d'alarme de requête pour la saisie semi-automatique.

interface utilisateur

  • Mettez en surbrillance les mots-clés du journal de recherche.
  • Ajoutez l'URL d'erreur dans le journal du navigateur.
  • Ajoutez une icône SolonMVC.
  • Ajout de l'icône de cil et de i18n pour le menu.
  • Correction de l'inadéquation entre l'unité et le calcul du widget "Utilisation de la bande passante réseau" dans le tableau de bord des services Windows.
  • Créez un maximum de 20 entités par requête dans les widgets de liste de services/instances/points de terminaison.
  • Polonais les nœuds d'erreur dans le widget de trace.
  • Introduire le graphique de flamme dans le profilage des traces.
  • Corriger les services et les instances lors de la modification des numéros de page.
  • Améliorez les requêtes métriques pour rendre l'ouverture des pages plus rapide.
  • Augmentez les dépendances pour corriger les CVE.
  • Ajouter une vue de chargement pour la page d'initialisation.
  • Correction d'un bug pour les sélecteurs lorsque cliclique sur l'icône d'actualisation.
  • Correction du contrôle de santé du backend OAP.
  • Ajoutez le transitaire de tableau de bord Service, ServiceInstance, Endpoint aux topologies Kubernetes.
  • Correction de la pagination pour les widgets de liste de services/instances.
  • Ajoutez des requêtes pour les balises d'alarme.
  • Ajouter un menu d'auto-observabilité de l'agent Java Skywalking.

Documentation

  • Mettez à jour la description de la version prise en charge par le récepteur Zabbix.
  • Déplacez les documents du tableau de bord officiel vers les documents du marché.
  • Ajoutez des documents d'introduction au marché dans le menu quick start pour réduire la confusion liée à la recherche de documents de fonctionnalités.
  • Mettre à jour les métriques Windows (Swap -> Mémoire virtuelle)
