hyperframes v0.9.56

HyperFrames v0.9.56

Sorti le 2026-11-16.

L'aperçu de Studio et les serveurs locaux n'agissent désormais que pour leurs propres pages. Le CLI conserve son cache, son historique et ses restaurations à l'intérieur du projet. L'image arm64 Lambda fournit uniquement la version ffmpeg révisée, et les grands aperçus sont créés plus rapidement.

Correctifs

  • Studio Server : Les serveurs de fichiers de composition ne servent plus les fichiers d'informations d'identification ou d'état des outils (014326b40, #7889).
  • Studio Server : Lint et sonde s'exécutent uniquement pour les requêtes provenant des propres pages de Studio (bbac8900e, #7894).
  • Studio Server : Une restauration de l'historique reste à l'intérieur du projet et utilise uniquement des copies intactes (478313ba0, #7902).
  • Studio : Prenez les œuvres en lecture pour un aperçu rendu opaque par son serveur (1e542956d, #7815).
  • Studio : Le cadre d'aperçu conserve l'origine du bac à sable et son ensemble d'hôtes (b650d0d19, #7886).
  • Studio : Les decks présents s'ouvrent uniquement sur leur propre site et l'aperçu ne lit que les messages de son propre cadre (4067efc45, #7877).
  • Core : Le pont d'exécution vérifie chaque message de contrôle avant d'agir dessus (97d8f26e7, #7892).
  • CLI : render --docker conserve la restriction de réseau de pages de l'hôte à l'intérieur du conteneur (5d8605eb8, #7890).
  • CLI : preview --stop arrête uniquement le processus signalé par le système détenant le port (ace8a78dc, #7882).
  • CLI : Le cache de contrôle est enregistré uniquement en tant qu'enregistrement de projet, jamais via un fichier lié (7801e3ff3, #7884).
  • CLI : Les identifiants de tour d'historique lus dans le dossier du projet sont vérifiés et envoyés codés (6efa6b635, #7883).
  • CLI : Le rattrapage répertorie uniquement les tours ajoutés par l'application après le transfert (0f23f40f8, #7874).
  • CLI : Un enregistrement de fichiers reçus dans un dossier sous le projet compte pour un rendu (1c159c550, #7900).
  • CLI : Media-use copie uniquement les effets sonores de ses noms d'index groupés (ed93a1312, #7895).
  • Utilisation des médias : Les modèles locaux démarrent à partir d'un dossier extérieur au projet (756c2c6c1, #7888).
  • Moteur : Un navigateur en cache est utilisé uniquement lorsque ses fichiers correspondent à la version épinglée (56a2d0c53, #7865).
  • Moteur : Les prédictions d'images de la chronologie restent dans les images du rendu (f5a74a567, #7885).
  • Moteur : Chaque extraction de sur-ensemble fonctionne dans son propre dossier (a4139e9ea, #7901).
  • Parseurs : La lecture de la largeur et de la hauteur d'un échafaudage de canevas prend le même temps sur n'importe quelle entrée (b856a1d63, #7873).
  • Lint : Les scènes et effets sonores créés par l'agent restent sur une seule ligne temporelle (98208241e, #7775).
  • Compétences : Les installations autonomes exécutent également le CLI via son lanceur (3fc3050bc, #7879).
  • AWS Lambda : Une version expédie le ffmpeg arm64 uniquement lorsqu'il correspond au résumé validé à côté de sa version (d9488119b, #7872).

Performances

  • Core : Une version d'aperçu lit une grande page sans la copier à chaque passage (082d63683, #7878).
  • Producteur : Les analyses de balises de compilation et de rendu de télémétrie prennent du temps en fonction de la taille de la page (82fdf406c, #7896).

Interne

  • Publier : Chaque publication npm attend l'approbation de la publication npm (a54de748e, #7870).
  • Publier : Les archives tar prédéfinies sont publiées à partir d'un travail qui n'exécute aucun code de la validation de version (af0560c85, #7869).
  • CI : Les workflows de publication s'exécutent uniquement pour le principal (7bd6b9daf, #7875).
  • CI : Les appareils de test ne ressemblent plus à de vraies clés HeyGen, et CI rejette celui qui ressemble (5dc3b336a, #7876).
