opentelemetry-java v1.61.0

###API

  • Stabilisez isEnabled() sur Tracer, Logger et les instruments métriques (#8200)

Incubation

  • BREAKING Mettre à jour la normalisation des clés EnvironmentGetter et EnvironmentSetter pour refléter les changements de spécifications (#8233)

###SDK

Traces

  • Conserver le contexte propagé lors de la génération d'ID de trace aléatoires (#8263)
  • Ajouter un journal d'avertissement à débit limité lorsque BatchSpanProcessor perd des plages (#8167)

Métriques

  • Suivre l'heure de début de la série par agrégateur plutôt qu'au moment de la création de SdkMeterProvider (#8180)
  • Capturez le chargeur de classe de contexte lors de l'enregistrement du rappel asynchrone (#8091)
  • Faire fonctionner correctement l'inclusion/exclusion avec des listes vides (mais non nulles) (#8185)

Journaux

  • Correction de la condition d'enregistrement des métriques de traitement des journaux réussi (#8226)

Exportateurs

  • OTLP : ajoutez des limites configurables à la lecture du corps de la réponse (#8224, #8277)
  • OTLP : lève uniquement une exception de réponse non valide lorsque la taille de la réponse gRPC < 5 octets (#8194)
  • OTLP : supprime la journalisation des erreurs de niveau FINEST en double dans l'exportateur gRPC (#8216)
  • Profils OTLP : nettoyer les exportateurs de signaux de profil pour plus de cohérence (#8172)

Extensions

  • BREAKING Configuration automatique : supprimez la classe obsolète ComponentLoader (utilisez plutôt io.opentelemetry.common.ComponentLoader) (#8243)
  • Configuration déclarative : correction du javadoc DeclarativeConfigProperties pour ne pas lever d'exceptions (#8079)
  • Configuration déclarative : le filtrage des attributs de ressources doit inclure les attributs par défaut (#8177)
  • Configuration déclarative : appliquer IncludedExcludeModel .inclus et .exclus ne sont pas vides (#8266)
  • Configuration automatique : restructurez l'incubateur SDK pour ne pas dépendre des composants internes configurés automatiquement (#8242)

Outillage de projet

  • Désactivez le cache de build Gradle sur les versions pour atténuer les risques liés à la chaîne d'approvisionnement (#8254)
