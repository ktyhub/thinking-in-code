d2 v0.8.2

Cette page est traduite automatiquement. Le texte anglais original fait foi.

#d2v0.8.2

Fonctionnalités 🚀

  • exportations : les exportations gif fonctionnent avec le mot-clé animate: true #2663

Améliorations 🧹

  • versions : supprimez les binaires natifs, créez et testez les six archives dans CI, produisez des archives reproductibles avec des sommes de contrôle, une provenance signée et des attestations SBOM, et vérifiez les téléchargements autonomes lorsque GitHub fournit un résumé
  • plugins : rendre le post-traitement du rendu facultatif et le rendre obsolète pour suppression après un cycle de compatibilité de protocole ; Les anciennes commandes externes postprocess restent prises en charge pendant la transition.
  • api : obsolètes constantes de fonctionnalité de mise en page, ponts bruts WASM ELK/ordre d'objet, wrappers publics inutilisés et aides à la comparaison, à la validation et à la journalisation pour les tests uniquement ; les points d'entrée de compatibilité restent appelables pour une version tandis que les appelants dans le référentiel utilisent des remplacements pris en charge ou internes
  • maintenance : mettre à jour la chaîne d'outils Go vers 1.27.0 et actualiser Go, d2.js, CI, les dépendances de version et les instantanés sensibles à la compression
  • rendus : mettre à jour la coloration syntaxique et migrer les polices archivées et les dépendances PDF vers des remplacements maintenus
  • d2dagre : remplacez le runtime JavaScript intégré par Go Dagro natif et mettez à jour sa surface de mise en page utilisée par D2 de Dagre 0.8.5 au comportement Dagre 3.1.1. Cela modifie intentionnellement l'ordre et les coordonnées des nœuds, les itinéraires de bord, les boucles automatiques et le dimensionnement des composés dans certains diagrammes ; régénérer et examiner les instantanés SVG ou board-JSON stockés
  • d2sketch : mise à jour du moteur de rendu natif de Rough.js 4.0.4 vers le comportement 4.6.6. Les traits d'esquisse prédéfinis, les remplissages, les pointes de flèches et les chemins SVG peuvent changer ; régénérer et examiner les instantanés SVG d'esquisse stockés
  • d2elk : remplacez le runtime ELK.js 0.8.2 intégré par Go elk-go natif et mettez à jour le profil de mise en page ELK de D2 vers le comportement ELK.js 0.12.0. Il s'agit d'une mise à jour du comportement de la mise en page, et non d'un échange d'exécution compatible avec la sortie :
    • les diagrammes ELK existants peuvent recevoir différentes coordonnées et ordres de nœuds, itinéraires de bord et d'étiquettes et emballage de composants ; régénérer et examiner les instantanés SVG ou board-JSON stockés
    • Les enfants des graphes composés imbriqués peuvent être réorganisés car ELK 0.12 ne peut pas appliquer en toute sécurité le profil d'ordre de modèle imbriqué précédent de D2.
    • Les modes --elk-algorithm autres que ceux par défaut peuvent également produire une géométrie différente ; l'algorithme DisCo facultatif est supprimé car l'amont ne le regroupe plus
  • d2latex : remplacez le runtime MathJax JavaScript intégré par le port natif Go mathjax-go sans modifier les formules rendues
  • performances : les migrations natives du moteur Go réduisent considérablement le temps médian de conversion D2 vers SVG de bout en bout dans les benchmarks Apple M4 :
    • Dagre est 7 à 9 fois plus rapide
    • ELK est 40 à 53 fois plus rapide
    • LaTeX est 21.6× plus rapide sur un diagramme à quatre formules
  • performances : supprimez les goulots d'étranglement du compilateur superlinéaire et de la mise en page dans les grands globes, les importations répétées, les diagrammes imbriqués, les graphiques Dagre composés, les mises en page ELK lourdes et les planches de scénarios/étapes de style uniquement [#2827] (https://github.com/d2lang/d2/pull/2827). Les références médianes de stress synthétique à processeur unique Apple M4 pour ces cliffs ciblés, plutôt que les moyennes de conversion à l'échelle du corpus, s'améliorent de :
    • Global leader appliqué à 1 000 champs : 1,59 s à 12 ms (~ 133 fois plus rapide)
    • 100 références dans le même fichier d'importation de 100 champs : 54 ms à 12 ms (~4.6× plus rapide)
    • 4 000 champs plats : 67 ms à 7 ms (~9.6× plus rapide)
    • 3 200 arêtes distinctes : 200 ms à 19 ms (~10.6× plus rapide)
  • Base de 32 nœuds avec 8 scénarios de style uniquement et 8 étapes (17 cartes au total) : 40 ms à 7,3 ms (~5.5× plus rapide)
    • Disposition D2 Dagre imbriquée de 340 objets : 1,30 s à 0,88 s (~ 32 % plus rapide)
    • Disposition composée Dagro profondeur 100 : 3,60 s à 0,90 s (~ 4 fois plus rapide)
    • Disposition ELK à 250 nœuds et 1 000 bords : 337 ms à 238 ms (~ 30 % plus rapide) -d2ascii :
    • Les formes de classe sql_table et uml sont prises en charge #2623
    • les nouvelles lignes sont gérées #2626
    • les colonnes vides de gauche sont rognées #2626
  • exportations :
    • Le téléchargement de Chromium via CLI pour les exportations PNG est demandé #2655
    • animate-interval n'est plus requis, la valeur par défaut est 1000 ms pour les gifs #2663
  • rend :
    • les images distantes sont récupérées de manière plus fiable #2659

Corrections de bugs ⛑️

  • d2dagre : conserve les bords parallèles dans la même direction et les itinéraires en boucle automatique finis lors de l'utilisation du comportement Dagre 3.1.1
  • d2svg : rejeter le remplissage qui produirait des dimensions SVG négatives non valides
  • d2elk : acheminer les connexions d'ancêtre à descendant autour de conteneurs intermédiaires
  • d2elk : empêche les étiquettes de plusieurs boucles automatiques de se chevaucher dans les mises en page dirigées vers la droite, y compris le cas de régression ent2d2_right
  • d2svg : rendu des dégradés à guichet unique avec des décalages SVG finis
  • compilateur : faire en sorte que les suffixes globs correspondent uniquement aux noms avec le suffixe demandé
  • compilateur : rejette les valeurs d'opacité non finies avec un diagnostic source
  • d2svg : préserver les liens de connexion sur LaTeX, Markdown et les étiquettes de code
  • d2lib : préserve les remplacements de thèmes clairs et sombres fournis par l'appelant par rapport à la configuration source
  • compilateur : indexe les connexions équivalentes de manière cohérente lorsque la notation du point de terminaison est inversée
  • exports : pptx suit de plus près les standards, répondant aux avertissements de certains logiciels Powerpoint #2645
  • d2sequence : correction du cas limite des diagrammes de séquence invalides #2660
  • d2svg : Le texte peut dépasser les limites de la légende lorsque la police à espacement fixe est utilisée #2674

Pour les dernières modifications de d2.js, voir changelog séparé.
