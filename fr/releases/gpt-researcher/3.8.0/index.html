gpt-researcher v3.8.0

chercheur-gpt v3.8.0

Une nouvelle interface utilisateur et des rapports détaillés en moins de 4 minutes

<a href="https://github.com/user-attachments/assets/4d3f26cf-8ccc-413a-b17c-80aa9e1b52d1"> <img src="https://github.com/user-attachments/assets/3a56a008-fcbd-4373-9e40-8d6027120cfb" alt="Chercheur GPT transformant une question en rapport cité" width="800"> </a>

L'application Next.js a une nouvelle conception de papier qui correspond à gptr.dev. Les paramètres sont regroupés dans un seul modal avec des onglets pour Recherche, MCP, Documents et Backend ; une exécution affiche un flux en langage clair et la marge des sources glisse une fois l'écriture commencée. L'interface utilisateur précédente est toujours disponible sur /classic.

Les rapports détaillés se terminent désormais en 3 :27 au lieu de 9 :11. Les sections sont recherchées en parallèle et le rédacteur par défaut est désormais gpt-6-sol, qui commence à écrire en quelques secondes au lieu de raisonner d'abord pendant près d'une minute par section. Les mesures et la comparaison des modèles se trouvent dans le #2272.

⚠️ Modifications à noter

  • Modèle d'écrivain par défaut : SMART_LLM est désormais openai:gpt-6-sol (auparavant openai:gpt-5.4). Réglez SMART_LLM pour conserver le modèle précédent.
  • Délai d'inactivité LLM : un appel LLM qui n'envoie rien pendant 300 secondes échoue désormais avec une erreur claire au lieu de suspendre l'exécution. Réglez-le avec LLM_TIMEOUT (0 le désactive). (#2220)
  • Docker : la racine .env n'est plus copiée dans les images. docker compose le charge au moment de l'exécution (nécessite Compose 2.24+) ; avec docker run, passez --env-file .env. Si vous avez déjà poussé une image que vous avez créée localement, faites pivoter les clés qui se trouvaient dans votre .env.
  • generate_report se déclenche désormais lorsque chaque tentative LLM échoue, au lieu de renvoyer un rapport vide. (#2219)

Également dans cette version

  • Images Docker prédéfinies pour linux/amd64 et linux/arm64 sur GHCR : ghcr.io/assafelovic/gpt-researcher et ghcr.io/assafelovic/gpt-researcher-frontend-nextjs, étiquetées avec la version et latest (#1517)
  • Observateur de recherche : un observateur de cycle de vie facultatif pour les intégrations qui souhaitent des événements de progression structurés (#2232)
  • Fournisseurs régionaux MiniMax et valeurs par défaut Flash (#1924), une URL de base TypeSafe configurable (#2243) et Déployer sur le rendu avec un plan render.yaml (#2184)
  • Les commentaires de révision de plan multi-agent provenant de l'interface utilisateur Web fonctionnent à nouveau et l'écrivain multi-agent utilise SMART_TOKEN_LIMIT et REASONING_EFFORT (#2272)
  • La recherche approfondie respecte les budgets de raisonnement, compte les tentatives et les chercheurs imbriqués dans les coûts, et maintient les apprentissages cités à la limite des mots (#2260, #2209, #2208)
  • La recherche MCP ne bloque plus la boucle d'événements et le plafond max_tools est appliqué (#2262, #2263)
  • Configuration : reasoning_effort à partir des fichiers de configuration JSON, les remplacements d'environnement DOC_PATH / REPORT_SOURCE, les fichiers de configuration UTF-8 et les paramètres de génération d'images sont tous à nouveau honorés (#2230, #2248, #2249, #2199, #2246).
  • Corrections du récupérateur, du scraper et du chargeur de documents sur Exa, Google, Bing, Bocha, PubMed Central, arXiv, les documents en ligne et les fichiers texte Windows
  • Plugins Retriever : une liste communautaire avec Keenable et Sciverse (#2176, #2225)

53 demandes de tirage de la communauté ont été intégrées à cette version. Merci à tous ceux qui ont contribué.

Installer : pip install -U gpt-researcher (0.17.0)
