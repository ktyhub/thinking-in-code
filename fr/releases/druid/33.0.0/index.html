<a name="33.0.0-important-features%2C-changes%2C-and-deprecations-increase-segment-load-speed" href="#33.0.0-important-features%2C-changes%2C-and-deprecations-increase-segment-load-speed">#</a> Augmenter la vitesse de chargement du segment

Vous pouvez désormais augmenter la vitesse à laquelle les segments sont chargés sur un historique en fournissant une liste de serveurs pour la configuration dynamique du coordinateur turboLoadingNodes. Pour ces serveurs, le coordinateur ignore druid.coordinator.loadqueuepeon.http.batchSize et utilise à la place la valeur du numLoadingThreads respectif. Veuillez noter que mettre un historique en mode de chargement turbo peut affecter les performances des requêtes, car davantage de ressources seraient utilisées par les threads de chargement du segment.

<a name="33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29" href="#33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29">#</a> Ingestion planifiée par lots (expérimental)

Vous pouvez désormais planifier des ingestions par lots avec le moteur de tâches MSQ à l'aide du superviseur de lots planifié. Vous pouvez spécifier la planification à l'aide de la syntaxe cron Unix standard ou de la syntaxe cron Quartz en définissant le champ type sur unix ou quartz. Unix prend également en charge les expressions macro telles que @daily et autres.

Soumettez les spécifications de votre superviseur au point de terminaison /druid/v2/sql/task/.

L'exemple de spécification de superviseur de lots planifié suivant soumet une requête REPLACE toutes les 5 minutes :

{
    "type": "scheduled_batch",
    "schedulerConfig": {
        "type": "unix",
        "schedule": "*/5 * * * *"
    },
    "spec": {
        "query": "REPLACE INTO foo OVERWRITE ALL SELECT * FROM bar PARTITIONED BY DAY"
    },
    "suspended": false
}

Druid peut désormais utiliser AWS S3 Transfer Manager pour les téléchargements S3, ce qui peut réduire considérablement le temps de téléchargement des segments. Cette fonctionnalité est activée par défaut et contrôlée avec les configurations suivantes dans common.runtime.properties :

    druid.storage.transfer.useTransferManager=true
    druid.storage.transfer.minimumUploadPartSize=20971520
    druid.storage.transfer.multipartUploadThreshold=20971520

<a name="faster-segment-metadata-operations" href="#faster-segment-metadata-operations">#</a> Opérations de métadonnées de segment plus rapides

Activez la mise en cache des métadonnées de segment sur Overlord avec la propriété d'exécution druid.manager.segments.useCache. Cette fonctionnalité est désactivée par défaut.

Vous pouvez définir la propriété sur les valeurs suivantes :

  • never : le cache est désactivé (par défaut)
  • always : Les lectures se font toujours depuis le cache. Le démarrage du service sera bloqué jusqu'à ce que le cache soit synchronisé au moins une fois avec le magasin de métadonnées. Les transactions sont bloquées jusqu'à ce que le cache soit synchronisé avec le magasin de métadonnées au moins une fois après être devenu leader.
  • ifSynced : les lectures sont effectuées à partir du cache uniquement s'il a déjà été synchronisé avec le magasin de métadonnées. Ce mode ne bloque pas le démarrage du service ni les transactions contrairement au paramètre always.

Dans le cadre de ce changement, des mesures supplémentaires ont été introduites. Pour plus d'informations sur ces métriques, consultez Métriques du cache de métadonnées de segment.

#17653 #17824

<a name="33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval" href="#33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval">#</a> Intervalle automatique des tâches d'élimination

Le coordinateur peut éventuellement émettre des tâches d'arrêt pour nettoyer les segments inutilisés. À partir de cette version, les tâches d'arrêt individuelles sont limitées par défaut au traitement de 30 jours ou moins de segments par tâche. Cela améliore les performances des tâches de mise à mort individuelles.

Le comportement précédent (pas de limite d'intervalle par tâche de mise à mort) peut être restauré en définissant druid.coordinator.kill.maxInterval = P0D.

useMaxMemoryEstimates est désormais défini sur false pour les tâches du moteur de tâches MSQ. De plus, la propriété est obsolète et sera supprimée dans une prochaine version. Définir cette valeur sur false permet une meilleure estimation de la mémoire sur le tas.

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-automatic-kill-tasks-interval" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-automatic-kill-tasks-interval">#</a> Intervalle automatique des tâches d'élimination

Les tâches de suppression automatique sont désormais limitées à 30 jours ou moins de segments par tâche. Le comportement précédent (pas de limite d'intervalle par tâche de mise à mort) peut être restauré en définissant druid.coordinator.kill.maxInterval = P0D.

#17680

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kubernetes-deployments" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kubernetes-deployments">#</a> Déploiements Kubernetes

Par défaut, l'image Docker utilise désormais le nom d'hôte canonique pour enregistrer les services dans ZooKeeper pour la communication interne si vous exécutez Druid dans Kubernetes. Sinon, il utilise l'adresse IP. #17697.

Vous pouvez définir la variable d'environnement DRUID_SET_HOST_IP sur 1 pour restaurer l'ancien comportement.

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-updated-configs" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-updated-configs">#</a> Configurations mises à jour

#17776

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-metadata-cache-configs" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-metadata-cache-configs">#</a> Configurations du cache de métadonnées de segment

Si vous devez rétrograder vers une version dans laquelle Druid ne prend pas en charge le cache de métadonnées de segment, vous devez définir la configuration druid.manager.segments.useCache sur false ou la supprimer avant la mise à niveau.

Cette fonctionnalité est introduite dans Druid 33.0.
