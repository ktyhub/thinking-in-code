Fonctionnalités, modifications et dépréciations importantes

Cette section contient des informations importantes sur les fonctionnalités nouvelles et existantes.

Domaine fonctionnel et changements associés

Cette section contient des release note détaillés séparés par zones.

Opérateur druide

Druid Operator est un contrôleur Kubernetes qui gère le cycle de vie de vos clusters Druid. L'opérateur simplifie la gestion des clusters Druid avec sa logique personnalisée configurable via CRD Kubernetes.

#18435

#### Autoscaling basé sur les coûts pour l'ingestion de streaming

Druid prend désormais en charge l'autoscaling basé sur les coûts pour l'ingestion de streaming qui optimise le nombre de tâches en équilibrant la réduction du décalage et l'efficacité des ressources. Cette stratégie d'autoscaling utilise la formule suivante :

totalCost = lagWeight × lagRecoveryTime + idleWeight × idlenessCost

ce qui représente le temps nécessaire pour éliminer le retard et le temps de calcul :

lagRecoveryTime = aggregateLag / (taskCount × avgProcessingRate) — time to clear backlog
idlenessCost = taskCount × taskDuration × predictedIdleRatio — wasted compute time

#18819

Kubernetes cliMode ent (expérimental)

Dans kubernetes-overlord-extensions, un mode expérimental Kubernetes client a été ajouté. Le nouveau mode utilise le fabric8 SharedInformers pour mettre en cache les métadonnées k8s. Cela réduit considérablement le trafic API entre le plan de contrôle Overlord et k8s. Vous pouvez essayer cette fonctionnalité en utilisant la configuration suivante :

druid.indexer.runner.useK8sSharedInformers=true

#18599

prise en charge du groupe de contrôle v2

cgroup v2 est désormais pris en charge et toutes les métriques de cgroup émettent désormais cgroupversion pour identifier la version utilisée.

Les métriques suivantes passent automatiquement à la version v2 si la version v2 est détectée : CgroupCpuMonitor , CgroupCpuSetMonitor, CgroupDiskMonitor,MemoryMonitor. CpuAcctDeltaMonitor échoue normalement si la v2 est détectée.

De plus, CgroupV2CpuMonitor émet désormais également cgroup/cpu/shares et cgroup/cpu/cores_quota.

#18705

Interroger des rapports pour Dart

Dart prend désormais en charge les rapports de requêtes pour les requêtes en cours d'exécution et récemment terminées. Les rapports peuvent être récupérés à partir du point de terminaison /druid/v2/sql/queries/<sqlQueryId>/reports.

Le format de la réponse est un objet JSON avec deux clés, « requête » et « rapport ». La clé « requête » est la même information disponible à partir du point de terminaison /druid/v2/sql/queries existant. La clé « report » est une carte de rapport comprenant un rapport MSQ. Vous pouvez contrôler le comportement de conservation des rapports à l'aide des configurations suivantes :

  • druid.msq.dart.controller.maxRetainedReportCount : nombre maximum de rapports conservés. La valeur par défaut est 0, ce qui signifie qu'aucun rapport n'est conservé
  • druid.msq.dart.controller.maxRetainedReportDuration : durée pendant laquelle les rapports sont conservés au format de durée ISO 8601. La valeur par défaut est PT0S, ce qui signifie que l'expiration basée sur le temps est désactivée.

#18886

Nouveau format de segment

Le nouveau format de segment version 10 améliore la version 9. Il est désactivé par défaut et n'est pas compatible avec les anciennes versions de format de segment.

Définissez druid.indexer.task.buildV10=true pour créer des segments dans le nouveau format.

Si vous rétrogradez, vous devez réindexer vos données avec une version de format de segment prise en charge.

Vous pouvez utiliser l'outil bin/dump-segment pour afficher les métadonnées des segments. L'outil produit un JSON sérialisé.

#18880 #18901

###Console Web

Nouvelles informations disponibles dans la console web

La console Web inclut désormais des informations sur le nombre de processeurs disponibles et la mémoire totale (en octets binaires).

Ces informations sont également disponibles via la table sys.servers.

#18613

Autres améliorations de la console Web

  • Ajout du suivi des travailleurs inactifs pour les étapes d'exécution MSQ #18768
  • Ajout d'un bouton d'actualisation pour les vues JSON et les visionneuses de scène #18768
  • Vous pouvez désormais définir les paramètres de type ARRAY dans la vue requête #18586
  • Modification des requêtes de table système pour utiliser désormais automatiquement le moteur natif #18857
  • Graphiques temporels améliorés pour prendre en charge plusieurs mesures #18701

Ingestion

  • Ajout de la prise en charge des tentatives de code AWS InternalError #18720
  • Ingestion améliorée pour être plus résilient. Les tâches d'ingestion n'échouent plus si le téléchargement du journal des tâches échoue avec une exception #18748
  • Amélioration de la façon dont Druid gère les situations où les données ne correspondent pas au type attendu #18878
  • Amélioration de l'ingestion de JSON afin que Druid puisse calculer les valeurs de JSON directement à partir de structures de dictionnaire ou d'index, permettant ainsi à l'ingestion d'ignorer entièrement les données brutes persistantes de JSON. Cela réduit la taille de stockage sur disque #18589
  • Vous pouvez désormais choisir entre une indexation complète basée sur un dictionnaire et une indexation nulle uniquement pour les champs longs/doubles dans une colonne imbriquée #18722

Ingestion basée sur SQL

Configurations d'ingestion supplémentaires

Vous pouvez désormais utiliser les configurations suivantes pour contrôler la façon dont vos données sont ingérées et stockées :

  • maxInputFilesPerWorker : contrôle le nombre maximum de fichiers ou de segments d'entrée par travailleur.
  • maxPartitions : contrôle le nombre maximum de partitions de sortie pour n'importe quelle étape, ce qui affecte le nombre de segments générés lors de l'ingestion.

#18826

Autres améliorations de l'ingestion basée sur SQL
  • Ajout de maxRowsInMemory pour remplacer rowsInMemory. rowsInMemory fonctionne désormais comme un autre moyen de fournir cette configuration et est ignoré si maxRowsInMemory est spécifié. Auparavant, seul rowsInMemory existait #18832

Ingestion de flux

Enregistrer le décalage et la partition

Vous pouvez désormais ingérer le décalage d'enregistrement (offsetColumnName) et la partition (partitionColumnName) à l'aide du KafkaInputFormat. Leurs noms par défaut sont respectivement kafka.offset et kafka.partition.

#18757

Autres améliorations de l'ingestion de streaming
  • Superviseurs améliorés afin qu'ils ne puissent pas tuer des tâches pendant que le superviseur s'arrête #18767
  • Amélioration de l'autoscaler basé sur le décalage pour l'ingestion de streaming #18745
  • Amélioration de l'autoscaler du superviseur SeekableStream pour attendre que les tâches soient terminées avant de tenter des opérations de mise à l'échelle ultérieures. Cela permet d'éviter les entrées en double de l'historique du superviseur #18715

Interrogation

Autres améliorations des requêtes

  • Amélioration de l'expérience utilisateur pour les requêtes regex_exp non valides. Une erreur est renvoyée maintenant #18762

Gestion des clusters

Capacité dynamique pour les déploiements basés sur Kubernetes

Druid peut désormais ajuster dynamiquement la capacité de l'exécuteur de tâches.

Incluez le champ capacity dans un appel POST API à /druid/indexer/v1/k8s/taskrunner/executionconfig. Définir une valeur de cette façon remplace druid.indexer.runner.capacity.

#18591

Tableau des propriétés du serveur

La table sys.server_properties expose les propriétés d'exécution configurées pour chaque serveur Druid. Chaque ligne représente une paire clé-valeur de propriété unique associée à un serveur spécifique.

#18692

Autres améliorations de la gestion des clusters

  • Ajout d'un filtrage de qualité de service pour Overlord afin que les threads de vérification de l'état ne soient pas bloqués #18033

Gestion des données

Autres améliorations de la gestion des données

  • Ajout de la politique de compactage mostFragmentedFirst qui donne la priorité aux intervalles avec les plus petits segments non compactés #18802
  • Amélioration de la façon dont les fichiers de segments sont supprimés pour empêcher les fichiers de segments partiels de rester en cas d'échec lors d'une opération de suppression #18696
  • Compactage amélioré afin qu'il identifie les dimensions à valeurs multiples pour les schémas de dimensions qui peuvent les produire #18760
  • Amélioration de la fiabilité lors du tirage des segments #18821

Métriques et surveillance

Métriques de tâches

Toutes les métriques de tâches émettent désormais les dimensions suivantes : taskId, dataSource, taskType, groupId et id. Notez que id est émis pour des raisons de compatibilité ascendante. Elle sera supprimée au profit de la dimension taskId dans une prochaine version.

#18876

Métriques d'ingestion

Les métriques suivantes pour les tâches de streaming et par lots émettent désormais les valeurs réelles au lieu de 0 : ingest/merge/time, ingest/merge/cpu et ingest/persists/cpu.

#18866

Métriques statsd

Les métriques suivantes ont été ajoutées à la liste par défaut pour statsd :

*task/action/run/time *task/status/queue/count *task/status/updated/count *ingest/handoff/time

#18846

  • Ajout de la dimension reason à la métrique ingest/events/thrownAway. Cela permet une meilleure observabilité des raisons pour lesquelles certains événements sont logiquement exclus de l'ingestion #188855

  • Ajout de la journalisation pour tous les gestionnaires d'une étape avant leur démarrage ou leur arrêt, ce qui peut vous aider à comprendre l'ordre d'exécution #18662

  • Ajout de nouvelles métriques du pool de threads Jetty pour capturer les statistiques des threads de traitement des requêtes : jetty/threadPool/utilized, jetty/threadPool/ready et jetty/threadPool/utilizationRate #18883

  • Ajout des dimensions tier et priority à la métrique segments/max #18890

  • Ajout de GroupByStatsMonitor, qui inclut les dimensions dataSource et taskId pour les métriques émises sur les péons #18711

  • Ajout de la métrique task/waiting/time, qui mesure le temps nécessaire pour qu'une tâche soit placée sur l'exécuteur de tâches pour la planification et l'exécution #18735

  • Ajout du supervisorId aux métriques de tâches de streaming pour aider à clarifier les situations dans lesquelles plusieurs superviseurs ingèrent des données dans une seule source de données #18803

  • Ajout de StorageMonitor à druid.monitoring.monitors pour mesurer l'utilisation du stockage et du stockage virtuel par cache de segments #18742

  • Druid enregistre désormais les éléments suivants :

  • Modification du suivi TTL de l'émetteur Prometheus pour prendre en compte toutes les combinaisons de valeurs d'étiquette au lieu de simplement le nom de la métrique. Les étiquettes ne sont pas suivies lorsque la durée de vie n'est pas définie #18718 #18689

  • Modification du cycle de vie stop() pour qu'il soit enregistré au niveau info afin de correspondre à start() #18640

  • Modification du déclencheur d'émission des métriques afin que les métriques soient émises à chaque fois qu'une tâche est terminée #18766

  • Amélioration de l'émetteur de métriques afin qu'il émette des métriques pour toutes les tâches terminées #18766

## Notes de mise à niveau et modifications incompatibles

Notes de mise à niveau

Tâches du contrôleur MSQ

Lors de la mise à niveau à partir de Druid 30 ou d'une version antérieure, les tâches MSQ query_controller peuvent échouer lors d'une mise à jour continue en raison de l'ajout de nouveaux compteurs qui ne sont pas rétrocompatibles avec ces anciennes versions. Vous pouvez soit réessayer toutes les requêtes ayant échoué une fois la mise à jour terminée ; ou vous pouvez définir includeAllCounters sur false dans le contexte de requête pour toutes les tâches MSQ devant être exécutées pendant la mise à jour propagée ; ou vous pouvez d'abord passer à Druid 31-35 avant de passer à Druid 36.

#18761

Format des segments

Druid 36.0.0 prend en charge la version 10 du format de segment. Les versions précédentes de Druid ne prennent pas en charge la version 10. Si vous rétrogradez, vous devez réindexer vos données avec une version de format de segment prise en charge.

#18880

Métriques obsolètes

Les moniteurs sur les péons qui émettaient auparavant la dimension id à partir de JettyMonitor, OshiSysMonitor, JvmMonitor, JvmCpuMonitor, JvmThreadsMonitor et SysMonitor pour représenter l'ID de tâche sont obsolètes et seront supprimés dans une version ultérieure. Utilisez plutôt la dimension taskId.

#18709

Métriques supprimées

Les métriques obsolètes suivantes ont été supprimées :

*segment/cost/raw #18846 *segment/cost/normalized #18846 *segment/cost/normalization #18846 *task/action/log/time #18649

Notes du développeur

Interfaces de fichiers de segments

De nouvelles interfaces SegmentFileBuilder et SegmentFileMapper ont été définies pour remplacer les utilisations directes de FileSmoosher et SmooshedFileMapper afin d'abstraire le processus de création et de lecture de segments.

Les principaux changements visibles par les développeurs pour les rédacteurs d'extensions avec des implémentations de colonnes personnalisées sont que l'interface Serializer a modifié la méthode writeTo :

  • Il accepte désormais un SegmentFileBuilder au lieu d'un FileSmoosher
  • La méthode ColumnBuilder getFileMapper renvoie désormais un SegmentFileMapper au lieu de SmooshedFileMapper.

Les extensions qui ne fournissent pas d'implémentations de colonnes personnalisées ne devraient pas être affectées par ces modifications.

#18608

Autres améliorations des développeurs

  • Ajout de la possibilité de remplacer l'image Kafka par défaut pour les tests #18739
  • Changement de fastDecompressor en safeDecompressor #18930
  • Les extensions peuvent désormais fournir des implémentations de kits de requêtes #18875
  • Suppression des remplacements de version dans les fichiers pom individuels. Pour une liste complète, consultez la demande d'extraction #18708
