druid 25.0.0

druide druide-25.0.0

Apache Druid 25.0.0 contient plus de 300 nouvelles fonctionnalités, corrections de bugs, améliorations des performances, améliorations de la documentation et couverture de tests supplémentaire de 51 contributeurs. [Voir l'ensemble complet des modifications pour plus de détails] (https://github.com/apache/druid/milestone/48).

<a name="25-highlights" href="#25-highlights">#</a> Faits saillants

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> Le moteur de tâches MSQ est désormais prêt pour la production

Le moteur de tâches de requêtes multi-étapes (MSQ) utilisé pour l'ingestion basée sur SQL est désormais prêt pour la production. Utilisez-le pour toutes les charges de travail prises en charge. Pour plus d’informations, consultez les pages suivantes :

  • Ingestion
  • Ingestion basée sur SQL

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Déploiements Druid simplifiés

Le nouveau script start-druid simplifie grandement le déploiement de toute combinaison de services Druid sur un seul serveur. Il est livré pré-emballé avec les configurations requises et peut être utilisé pour lancer un cluster Druid entièrement fonctionnel en appelant simplement ./start-druid. Pour les druides expérimentés, il donne également un contrôle complet sur les propriétés d'exécution et les arguments JVM pour disposer d'un cluster qui correspond exactement à vos besoins. Le script start-druid rend obsolètes les profils existants tels que start-micro-quickstart et start-nano-quickstart. Ces profils pourront être supprimés dans les versions futures. Pour plus d'informations, voir Déploiement sur un seul serveur.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> Compression de dictionnaire de chaînes (expérimental)

Ajout de la prise en charge des dictionnaires de chaînes codées au premier plan pour les colonnes de chaînes plus petites, entraînant une réduction de la taille des segments avec seulement des pénalités de performances mineures pour la plupart des requêtes Druid. Cela peut être activé en définissant IndexSpec.stringDictionaryEncoding sur {"type":"frontCoded", "bucketSize": 4} , où bucketSize est n'importe quelle puissance de 2 inférieure ou égale à 128. La définition de cette propriété demande aux tâches d'indexation d'écrire des segments à l'aide de dictionnaires compressés de la taille de compartiment spécifiée.

Tout segment écrit à l'aide de la compression par dictionnaire de chaînes n'est pas lisible par les anciennes versions de Druid. Pour plus d'informations, voir [Codage avant] (https://druid.apache.org/docs/latest/ingestion/ingestion-spec.html#front-coding). https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Tâches natives Kubernetes

Druid peut désormais utiliser le Kubernetes pour lancer et gérer des tâches, éliminant ainsi le besoin de cadres intermédiaires. Pour utiliser cette fonctionnalité, activez le druid-kubernetes-overlord-extensions dans la liste de chargement des extensions pour votre processus Overlord. https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-compatible-binary" href="#25-highlights-hadoop-3-compatible-binary">#</a> Binaire compatible Hadoop-3

Druid est désormais fourni sous forme de binaire dédié aux utilisateurs de Hadoop-3, qui contient des fichiers jar compatibles Hadoop-3. Si vous n'utilisez pas Hadoop-3 avec votre cluster Druid, vous pouvez continuer à utiliser le binaire classique.

<a name="25-multi-stage-query-task-engine" href="#25-multi-stage-query-task-engine">#</a> Moteur de tâches de requêtes multi-étapes (MSQ)

<a name="25-msq-docker-enabled" href="#25-msq-docker-enabled">#</a> MSQ activé pour Docker

Le moteur de requête de tâches MSQ est désormais activé par défaut pour Docker. https://github.com/apache/druid/pull/13069

<a name="25-msq-query-history" href="#25-msq-query-history">#</a> Historique des requêtes

Les requêtes à plusieurs étapes n'apparaissent plus dans la boîte de dialogue Historique des requêtes. Elles sont toujours disponibles dans le panneau Tâches de requête récentes.

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> Limite sur les colonnes CLUSTERED BY

Lors de l'utilisation du moteur de tâches MSQ pour ingérer des données, le nombre de colonnes pouvant être transmises dans la clause CLUSTERED BY est désormais limité à 1 500. https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> Prise en charge de la compression du dictionnaire de chaînes

Le moteur de tâches MSQ prend en charge le codage frontal des dictionnaires String pour une meilleure compression. Cela peut être activé pour les instructions INSERT ou REPLACE en définissant indexSpec sur une chaîne json valide dans le contexte de requête. https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> Mode de fusion d'esquisses

Les utilisateurs peuvent désormais collecter des statistiques clés, utilisées pour générer des limites de partition, séquentiellement ou en parallèle. Définissez clusterStatisticsMergeMode sur PARALLEL, SEQUENTIAL ou AUTO dans le contexte de requête pour utiliser le mode de fusion d'esquisses correspondant. Pour plus d'informations, voir [Mode de fusion d'esquisses] (https://druid.apache.org/docs/latest/multi-stage-query/reference.html#sketch-merging-mode). https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> Améliorations des performances et des opérations

  • Messages d'erreur : pour les avertissements MSQ non autorisés de certains types, l'avertissement apparaît désormais comme l'erreur. https://github.com/apache/druid/pull/13198
  • Secrets : Pour les tâches contenant du SQL avec des clés sensibles, Druid masque désormais les clés lors de la journalisation à l'aide des expressions régulières. https://github.com/apache/druid/pull/13231
  • Précision du sous-échantillonnage : le moteur de tâches MSQ utilise désormais le nombre d'octets au lieu du nombre de clés lors du sous-échantillonnage des données. https://github.com/apache/druid/pull/12998
  • Utilisation de la mémoire : lors de la détermination des limites de partition, l'empreinte du tas des croquis internes utilisés par MSQ est désormais plafonnée à 10 % de la mémoire disponible ou à 300 Mo, selon la valeur la plus faible. Auparavant, le plafond était strictement de 300 Mo. https://github.com/apache/druid/pull/13274
  • Rapports de tâches : Ajout des champs pendingTasks et runningTasks au rapport du travailleur. Voir Requête des informations sur l'état de la tâche pour connaître les modifications associées à la console Web. https://github.com/apache/druid/pull/13263

<a name="25-querying-context-security" href="#25-querying-context-security">#</a> Sécurité améliorée du contexte de requête

  • druid.auth.securedContextKeys : une liste JSON de clés de contexte de requête qui nécessitent un contrôle de sécurité. Si les deux sont définis, unsecuredContextKeys fait office d'exception à securedContextKeys. https://github.com/apache/druid/pull/13071

<a name="25-querying-http-response-headers" href="#25-querying-http-response-headers">#</a> En-têtes de réponse HTTP

La réponse HTTP pour une requête SQL définit désormais correctement les en-têtes de réponse, comme pour une requête native. https://github.com/apache/druid/pull/13052

<a name="25-ingestion-streaming-tasks-resume-on-overlord-switch" href="#25-ingestion-streaming-tasks-resume-on-overlord-switch">#</a> Les tâches de streaming reprennent sur le commutateur Overlord

Désormais, lorsque le changement d'Overlord se produit juste après avoir émis une pause dans la tâche, la tâche reste dans un état en pause même après la réélection d'Overlord. https://github.com/apache/druid/pull/13223

<a name="25-ingestion-fixed-parquet-list-conversion" href="#25-ingestion-fixed-parquet-list-conversion">#</a> Conversion de la liste de parquet fixe

Correction d'un problème avec la conversion de liste Parquet, où des listes d'objets complexes pouvaient être enveloppées de manière inattendue dans un objet supplémentaire, apparaissant sous la forme [{"element":<actual_list_element>},{"element":<another_one>}...] au lieu de la liste directe. Cela modifie le comportement du lecteur Parquet pour les listes d'objets structurés afin qu'il soit cohérent avec les autres conversions de listes logiques Parquet. Les données sont désormais récupérées directement, correspondant plus étroitement à leur structure attendue. https://github.com/apache/druid/pull/13294

<a name="25-opérations" href="#25-opérations">#</a> Opérations

<a name="25-Operations-compaction" href="#25-Operations-compaction">#</a> Compactage

Le comportement du compactage a changé pour améliorer le temps et l'espace disque nécessaires :

  • Lorsque des segments doivent être récupérés, téléchargez-les un par un et supprimez-les lorsque Druid en a terminé avec eux. Cela prend encore du temps mais minimise l'espace disque requis.
  • Ne récupérez pas les segments de la tâche compacte principale lorsqu'ils ne sont pas nécessaires. Si l'utilisateur fournit un granularitySpec, un dimensionsSpec et un metricsSpec complets, Druid ignore la récupération des segments. Pour plus d'informations, consultez la documentation sur Compaction et Compactage automatique. https://github.com/apache/druid/pull/13280

L'option HttpPostEmitter dispose désormais d'un délai d'attente. Cela signifie qu'il devrait y avoir moins de bruit dans les journaux et une utilisation moindre du processeur si vous utilisez cette option pour la journalisation. https://github.com/apache/druid/pull/12102

<a name="25-Operations-segment-loading-and-balancing" href="#25-Operations-segment-loading-and-balancing">#</a> Chargement et équilibrage de segments

<a name="25-Operations-batch-allocation" href="#25-Operations-batch-allocation">#</a> Allocation de segments par lots

L'allocation de segments sur Overlord peut prendre un certain temps, ce qui peut entraîner un retard d'ingestion pendant qu'une tâche attend que les segments soient alloués. L’allocation de segments par lots peut contribuer à améliorer les performances. Il existe deux nouvelles propriétés qui affectent la manière dont Druid effectue l'allocation des segments : | Propriété | Descriptif | Par défaut | | - | - | - | |druid.indexer.tasklock.batchSegmentAllocation| S'il est défini sur true, Druid effectue des actions d'allocation de segment par lots pour améliorer le débit et réduire le task/action/run/time moyen. Voir traitement par lots des actions segmentAllocate pour plus de détails.|false| |druid.indexer.tasklock.batchAllocationWaitTime|Nombre de millisecondes après que Druid ajoute la première action d'allocation de segment à un lot, jusqu'à ce qu'il exécute le lot. Permet au lot d’ajouter plus de demandes et d’améliorer la durée d’exécution moyenne de l’allocation de segment. Cette configuration ne prend effet que si batchSegmentAllocation est activé.|500| En plus de ces propriétés, il existe de nouvelles mesures permettant de suivre l'allocation des segments par lots. Pour plus d'informations, consultez Nouvelles métriques pour l'allocation de segment. Pour plus d’informations, consultez les éléments suivants :

  • Opérations Overlord
  • [Actions de tâches et actions de traitement par lots segmentAllocate] (https://druid.apache.org/docs/latest/ingestion/tasks.html#task-actions) https://github.com/apache/druid/pull/13369 https://github.com/apache/druid/pull/13503

<a name="25-Operations-segment-loading-and-balancing-cachingcost-balancer-strategy" href="#25-Operations-segment-loading-and-balancing-cachingcost-balancer-strategy">#</a> Amélioration de la stratégie d'équilibrage des coûts de mise en cache

La stratégie d'équilibrage cachingCost se comporte désormais de manière plus similaire à la stratégie de coûts. Lors du calcul du coût de déplacement d'un segment vers un serveur, les calculs suivants sont effectués :

  • Soustraire le coût propre d'un segment s'il est servi par le serveur cible
  • Soustraire le coût des segments marqués pour être supprimés https://github.com/apache/druid/pull/13321

<a name="25-operations-segment-loading-and-balancing-segment-assignment" href="#25-operations-segment-loading-and-balancing-segment-assignment">#</a> Affectation de segment plus rapide

Vous pouvez désormais utiliser une stratégie de segmentation à tour de rôle pour accélérer les attributions initiales de segments. Définissez useRoundRobinSegmentAssigment sur true dans la configuration dynamique du coordinateur pour activer cette fonctionnalité. https://github.com/apache/druid/pull/13367

<a name="25-Operations-segment-batch-sampling" href="#25-Operations-segment-batch-sampling">#</a> Par défaut, échantillonnage par lots pour l'équilibrage des segments

L'échantillonnage par lots est désormais la méthode par défaut pour échantillonner les segments lors de l'équilibrage, car il fonctionne nettement mieux que l'alternative lorsqu'il y a un grand nombre de segments utilisés dans le cluster. Dans le cadre de ce changement, les éléments suivants sont obsolètes et seront supprimés dans les prochaines versions :

  • coordinateur config dynamique useBatchedSegmentSampler
  • coordinateur config dynamique percentOfSegmentsToConsiderPerMove
  • ancienne méthode non batch d'échantillonnage des segments

<a name="25-operations-segment-unused-property" href="#25-operations-segment-unused-property">#</a> Supprimer la propriété inutilisée

La propriété de coordinateur inutilisée druid.coordinator.loadqueuepeon.repeatDelay a été supprimée. Utilisez uniquement druid.coordinator.loadqueuepeon.http.repeatDelay pour configurer le délai de répétition pour la file d'attente de chargement de segment basée sur HTTP. https://github.com/apache/druid/pull/13391

<a name="25-Operations-segment-replication" href="#25-Operations-segment-replication">#</a> Éviter la sur-réplication des segments

Amélioration du processus de vérification de l'inventaire du serveur pour éviter la réplication excessive des segments lors de l'équilibrage des segments. https://github.com/apache/druid/pull/13114

<a name="25-Operations-provided-service-Specific-log4j-overrides-in-containerized-deployments" href="#25-Operations-provided-service-Specific-log4j-overrides-in-containerized-deployments">#</a> Remplacements log4j spécifiques au service fourni dans les déploiements conteneurisés

Fourni une option pour remplacer la configuration des configurations log4j au niveau des répertoires de niveau de service afin qu'elle fonctionne avec les déploiements basés sur les opérateurs Druid. https://github.com/apache/druid/pull/13020

<a name="25-Operations-Divers-docker-improvements" href="#25-Operations-Divers-docker-improvements">#</a> Diverses améliorations du Docker

  • Mise à jour de Docker pour fonctionner avec JRE 11 par défaut.
  • Mise à jour de Docker pour utiliser l'image gcr.io/distroless/java11-debian11 comme base par défaut.
  • Activation du cache du buildkit Docker pour accélérer la construction.
  • Téléchargé bash-static sur l'image Docker afin que les scripts nécessitant bash puissent être exécutés.
  • Image du constructeur déplacée de 3.8.4-jdk-11-slim à 3.8.6-jdk-11-slim.
  • Passage de la boîte d'occupation de amd64/busybox:1.30.0-glibc à busybox:1.35.0-glibc.
  • Ajout de la prise en charge pour créer une image basée sur arm64. https://github.com/apache/druid/pull/13059

<a name="25-operations-enabled-cleaner-json-for-divers-input-sources-and-formats" href="#25-operations-enabled-cleaner-json-for-divers-input-sources-and-formats">#</a> Nettoyeur activé JSON pour diverses sources et formats d'entrée

Ajout de JsonInclude à diverses propriétés, pour éviter le remplissage des valeurs par défaut dans JSON sérialisé. https://github.com/apache/druid/pull/13064

<a name="25-operations-improved-direct-memory-check-on-startup" href="#25-operations-improved-direct-memory-check-on-startup">#</a> Vérification directe de la mémoire améliorée au démarrage

Amélioration de la vérification directe de la mémoire au démarrage en fournissant une meilleure prise en charge de Java 9+ dans RuntimeInfo et des messages de journal plus clairs en cas d'échec de la validation. https://github.com/apache/druid/pull/13207

<a name="25-operations-improved-the-run-time-of-the-markasunusedovershadowedsegments-duty" href="#25-operations-improved-the-run-time-of-the-markasunusedovershadowedsegments-duty">#</a> Amélioration du temps d'exécution du devoir MarkAsUnusedOvershadowedSegments

Amélioration du temps d'exécution du devoir MarkAsUnusedOvershadowedSegments en itérant sur tous les segments éclipsés et en marquant les segments comme inutilisés par lots. https://github.com/apache/druid/pull/13287

<a name="25-upgrade" href="#25-upgrade">#</a> Mise à niveau vers 25.0.0

Tenez compte des modifications et mises à jour suivantes lors de la mise à niveau de Druid 24.0.x vers 25.0.0. Si vous effectuez une mise à jour à partir d'une version antérieure, consultez les release note des versions intermédiaires concernées.

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> Découverte de segments basée sur HTTP par défaut et gestion des tâches

La méthode de découverte de segments par défaut utilise désormais HTTP au lieu de ZooKeeper. Cette mise à jour modifie les valeurs par défaut des propriétés suivantes : | Propriété | Nouveau défaut | Valeur par défaut précédente | | - | - | - | | druid.serverview.type pour la gestion des segments | http | lot | | druid.coordinator.loadqueuepeon.type pour la gestion des segments | http | conservateur | | druid.indexer.runner.type pour l'Overlord | httpÀ distance | locale | Pour utiliser ZooKeeper au lieu de HTTP, modifiez les valeurs des propriétés aux valeurs par défaut précédentes. Les implémentations basées sur ZooKeeper pour ces propriétés sont obsolètes et seront supprimées dans une version ultérieure. https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> Finalisation des agrégats d'esquisse HLL et quantiles

Les fonctions d'agrégation pour les esquisses HLL et quantiles ont renvoyé des esquisses ou des nombres lorsqu'ils sont finalisés en fonction de leur emplacement dans le plan de requête natif. Druid ne finalise plus les agrégateurs dans les deux cas suivants :

  • les agrégateurs apparaissent au niveau externe d'une requête
  • les agrégateurs sont utilisés comme entrée dans une expression ou comme post-agrégateur d'accès au champ de finalisation Ce changement aligne le comportement des esquisses HLL et quantiles avec les esquisses thêta. Pour restaurer l'ancien comportement, vous pouvez définir sqlFinalizeOuterSketches=true dans le contexte de requête. https://github.com/apache/druid/pull/13247

<a name="25-upgrade-kill-tasks-mark-unused" href="#25-upgrade-kill-tasks-mark-unused">#</a> Les tâches d'arrêt marquent les segments comme inutilisés uniquement si spécifié

Lorsque vous émettez une tâche kill, Druid marque les segments sous-jacents comme inutilisés uniquement s'ils sont explicitement spécifiés. Pour plus d'informations, consultez la référence API https://github.com/apache/druid/pull/13104

<a name='25-upgrade-incompatible' href='#25-upgrade-incompatible'>#</a> Modifications incompatibles

<a name='25-upgrade-incompatible-curator' href='#25-upgrade-incompatible-curator'>#</a> Mettre à niveau le conservateur vers 5.3.0

Apache Curator a été mis à niveau vers la dernière version, 5.3.0. Cette version abandonne la prise en charge de ZooKeeper 3.4 mais Druid a déjà officiellement abandonné la prise en charge de 0.22. Dans 5.3.0, Curator a supprimé la prise en charge de l'exposant, de sorte que toutes les configurations et tests associés ont été supprimés. https://github.com/apache/druid/pull/12939

<a name="25-upgrade-incompatible-parquet" href="#25-upgrade-incompatible-parquet">#</a> Correction de la conversion de la liste des parquets

Le comportement du lecteur Parquet pour les listes d'objets structurés a été modifié pour être cohérent avec les autres conversions de listes logiques Parquet. Les données sont désormais récupérées directement, correspondant plus étroitement à leur structure attendue. Voir conversion de liste de parquet pour plus de détails. https://github.com/apache/druid/pull/13294
