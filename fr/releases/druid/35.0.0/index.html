druide druide-35.0.0

Apache Druid 35.0.0 contient plus de 229 nouvelles fonctionnalités, corrections de bogues, améliorations des performances, améliorations de la documentation et couverture de tests supplémentaire de 29 contributeurs.

Consultez l'ensemble complet de modifications pour plus de détails, y compris les corrections de bogues.

Consultez les notes de mise à niveau et les modifications incompatibles avant de procéder à la mise à niveau vers Druid 35.0.0. Si vous effectuez une mise à niveau sur plusieurs versions, consultez la page [Notes de mise à niveau] (upgrade-notes.md), qui répertorie les notes de mise à niveau pour les versions de Druid les plus récentes.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29">#</a> Stockage virtuel (expérimental)

Le mode Fabric de stockage virtuel permet aux serveurs historiques de servir plus de segments que ce que leur disque physique peut contenir. Au lieu de charger les segments lors de leur publication, les segments sont chargés à la demande lors des requêtes. Tous les segments inutiles sont supprimés du disque mais sont à nouveau chargés lorsque le traitement d'une requête nécessite ce segment particulier.

Pour activer le stockage virtuel, définissez druid.segmentCache.virtualStorage sur true.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-new-input-format">#</a> Nouveau format d'entrée

Druid prend désormais en charge un format d'entrée lines. Druid lit chaque ligne d'une entrée sous forme de texte UTF-8 et crée une seule colonne nommée line qui contient la ligne entière sous forme de chaîne. Utilisez-le pour lire des données orientées ligne sous une forme simple pour un traitement ultérieur.

Le moteur de tâches MSQ est désormais une fonctionnalité essentielle de Druid plutôt qu'une extension. Il figure dans la liste de chargement des extensions par défaut depuis plusieurs versions.

Supprimez druid-multi-stage-query de druid.extensions.loadList dans common.runtimes.properties avant de procéder à la mise à niveau.

Druid 35.0.0 ignorera l'extension si elle figure dans la liste de chargement. Les futures versions de Druid ne pourront pas démarrer car elles ne pourront pas localiser l'extension.

Vous pouvez désormais configurer le délai d'expiration pour le traitement des segments d'une requête.

Pour définir un délai d'attente, définissez druid.processing.numTimeoutThreads sur un nombre faible, tel que 3, sur tous les nœuds de données sur lesquels vous souhaitez activer cette fonctionnalité.

Ensuite, incluez le paramètre de contexte de requête perSegmentTimeout dans votre requête et définissez-le sur une valeur en millisecondes.

<a name="35.0.0-functional-area-and-related-changes-extensions-http-client" href="#35.0.0-functional-area-and-related-changes-extensions-http-client">#</a> HTTP client

Vous pouvez maintenant configurer la bibliothèque HTTP client que le Fabric8 KubernetesClient utilise sous le capot pour communiquer avec les tâches du serveur k8s exécutées. La valeur par défaut reste la même client et la même configuration que Druid 34 utilise. Les options supplémentaires désormais disponibles sont okhttp et un JDK natif HttpClient. Le client et la configuration par défaut devraient suffire pour la plupart des cas d'utilisation.

Définissez la configuration druid.indexer.runner.k8sAndWorker.http.httpClientType sur vertx (par défaut), okhttp ou jdk.

#18587

<a name="35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs" href="#35.0.0-functional-area-and-related-changes-extensions-pod-logs-task-logs">#</a> Journaux de tâches

Pour l’ingestion sans Middle Manager, les journaux de tâches persistants ne peuvent plus être bloqués indéfiniment. Au lieu de cela, il existe une limite de temps pour les journaux persistants, qui, en cas de violation, entraîne l'abandon de la persistance. Le délai d'expiration par défaut est de 5 minutes, mais peut être configuré en remplaçant druid.indexer.runner.logSaveTimeout par une durée telle que PT60S.

De plus, le stockage du journal des tâches pour le programme d'exécution Kubernetes est désormais facultatif.

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Notes de mise à niveau

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-fallback-vectorization-on-by-default">#</a> Vectorisation de repli activée par défaut

Le druid.expressions.allowVectorizeFallback est désormais par défaut true. De plus, le SAFE_DIVIDE peut désormais vectoriser comme solution de repli.

#18549

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-">#</a> Jetée 12

Druid utilise désormais Jetty 12. Votre déploiement peut être impacté en fonction, notamment en ce qui concerne la conformité des URI et les vérifications des hôtes SNI.

Une nouvelle option de configuration du serveur a été ajoutée : druid.server.http.uriCompliance. Par défaut, Jetty 12 applique strictement le format URI RFC3986. Il s'agit d'un changement par rapport à Jetty 9. Pour éviter d'éventuelles modifications brutales dans les déploiements Druid existants, cette configuration est par défaut LEGACY, qui utilise l'application de format d'URI plus permissive utilisée par Jetty 9. Si le cluster que vous exploitez ne nécessite pas de compatibilité héritée, nous vous recommandons d'utiliser la valeur par défaut de Jetty en amont de RFC3986 dans votre déploiement Druid. Consultez la documentation de la jetée pour plus d'informations.

Les serveurs Jetty 12 effectuent des vérifications SNI host0 strictes lorsque TLS est activé. Si l'hôte avec lequel votre client se connecte au serveur ne correspond pas à ce qui se trouve dans le magasin de clés, même s'il n'y a qu'un seul certificat dans ce magasin de clés, il renverra une réponse 400. Cela pourrait avoir un impact sur certains cas d'utilisation, tels que les personnes se connectant via localhost pour une raison quelconque. Si cette modification interrompt votre déploiement, vous pouvez vous désinscrire en définissant druid.server.http.enforceStrictSNIHostChecking sur false dans le fichier runtime.properties pour tout ou partie de vos services Druid. Il est recommandé de modifier le comportement de votre client pour tenir compte de ce changement dans jetty au lieu de remplacer la configuration autant que possible.

#18424 #18623

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication">#</a> Authentification Kerberos

La config druid.auth.authenticator.kerberos.cookieSignatureSecret est désormais obligatoire.

#18368

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine">#</a> Moteur de tâches de requête à plusieurs étapes

Le moteur de tâches MSQ est désormais une fonctionnalité essentielle de Druid plutôt qu'une extension. Il figure dans la liste de chargement des extensions par défaut depuis plusieurs versions.

Supprimez druid-multi-stage-query de druid.extensions.loadList dans common.runtimes.properties avant de procéder à la mise à niveau.

Druid 35.0.0 ignorera l'extension si elle figure dans la liste de chargement. Les futures versions de Druid ne pourront pas démarrer car elles ne pourront pas localiser l'extension.

#18394

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension">#</a> extension pac4j

En raison de la mise à niveau de pac4j 4 vers 5, la sérialisation de session est passée du JavaSerializer de pac4j à la sérialisation Java standard. Par conséquent, les clients des clusters utilisant l'extension pac4j peuvent être déconnectés lors des mises à niveau propagées et doivent se réauthentifier.

#18259

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Modifications incompatibles

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed">#</a> Prise en charge de Java 11 supprimée

Mettez à niveau vers Java 17 ou 21. Notez que certaines versions de Java 21 ont rencontré des problèmes lors du test, en particulier Java 21.05-21.07. Si possible, évitez ces versions.

#18424

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notes des développeurs

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests">#</a> Tests de cluster intégrés

Vous pouvez utiliser le nouveau framework de test de cluster intégré pour exécuter des tests d'intégration légers à l'aide d'un cluster Druid entièrement fonctionnel qui s'exécute sur un seul processus, y compris toutes les extensions que vous souhaitez charger ainsi que le magasin de métadonnées ZooKeeper et Derby. Vous n'avez plus besoin d'exécuter mvn build, de créer une image docker ou même d'exécuter des scripts de démarrage pour effectuer des tests d'intégration.

#18147

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json">#</a> Colonnes virtuelles spécialisées pour JSON

Le ColumnHolder renvoyé par ColumnSelector renvoie désormais un SelectableColumn plutôt que BaseColumn de getColumn(). Le SelectableColumn peut être un BaseColumn ou peut être une implémentation fournie par une colonne virtuelle. Les extensions qui doivent récupérer des colonnes physiques d'un ColumnSelector peuvent vérifier si la colonne est un BaseColumn à l'aide de instanceof. Pour plus de commodité, le type de retour de getColumnHolder sur QueryableIndex a été spécialisé en BaseColumnHolder, qui renvoie toujours BaseColumn à partir de getColumn(). Les extensions qui appellent cette méthode sur QueryableIndex peuvent stocker le résultat dans une variable de type BaseColumnHolder pour éviter d'avoir à convertir la colonne.

#18521

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed">#</a> Outil reset-cluster supprimé

L'outil orienté environnement de développement et de test reset-cluster a été supprimé. Il était obsolète et ne parviendrait pas à vider complètement le magasin de métadonnées (tables upgradeSegments et segmentSchemas manquantes ajoutées respectivement dans Druid 28 et 30). Cet outil n'est pas destiné aux cas d'utilisation en production, il ne devrait donc y avoir aucun impact pour les opérateurs de cluster.

#18246

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions">#</a> Modification radicale des extensions de métadonnées SQL

Le point d'extension MetadataStorageActionHandler dispose désormais de API plus simples. Il s’agit d’un changement radical pour toutes les extensions de métadonnées SQL dans la nature. Les modifications pour PostgreSQL, MySQL et SQLServer sont déjà terminées. #18479

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed">#</a> DriudLeaderClient supprimé

DruidLeaderClient a été supprimé des extensions et remplacé par une implémentation basée sur ServiceClient. De plus, CoordinatorServiceClient pour interroger les API non essentiels exposés par le coordinateur est disponible via druid-server.
