<a name="32.0.0-important-features" href="#32.0.0-important-features">#</a> Fonctionnalités importantes

Cette section contient des informations importantes sur les fonctionnalités nouvelles et existantes.

<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> Nouveaux Overlord API

Les API permettant de marquer les segments comme utilisés ou inutilisés ont été déplacés du service Coordinateur vers le service Overlord :

  • Marquer tous les segments d'une source de données comme inutilisés : POST /druid/indexer/v1/datasources/{dataSourceName}

  • Marquer tous les segments (non éclipsés) d'une source de données comme étant utilisés : DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • Marquer plusieurs segments comme utilisés POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • Marquer plusieurs segments (non éclipsés) comme inutilisés POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • Marquer un seul segment comme utilisé : POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • Marquer un seul segment comme inutilisé : DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

Dans le cadre de ce changement, les coordinateurs API correspondants sont obsolètes et seront supprimés dans une prochaine version :

-POST /druid/coordinator/v1/datasources/{dataSourceName} -POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed -POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused -POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId} -DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId} -DELETE /druid/coordinator/v1/datasources/{dataSourceName}

Le coordinateur appelle maintenant l'Overlord pour répondre à ces demandes.

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> Traitement des requêtes en temps réel pour les chaînes à valeurs multiples

Le traitement des requêtes en temps réel ne considère plus toutes les chaînes comme des chaînes à valeurs multiples lors du traitement des expressions, corrigeant ainsi un certain nombre de bugs et d'échecs inattendus. Cela devrait également améliorer les performances des requêtes en temps réel des expressions sur les colonnes de chaîne.

Ce changement affecte les requêtes topN pour les segments en temps réel où les lignes de données sont implicitement nulles, comme celles provenant d'une propriété manquante dans un objet JSON.

Avant ce changement, ceux-ci étaient traités comme [] au lieu de null, entraînant une incohérence entre le traitement des segments en temps réel et les segments publiés. Lors du traitement des segments, la valeur était traitée comme [], ce que topN ignore. Après la publication, la valeur est devenue nulle, ce que topN n'ignore pas. La même requête peut avoir des résultats différents avant et après sa persistance

Après ce changement, le moteur topN traite désormais [] comme null lors du traitement des segments en temps réel, ce qui est cohérent avec les segments publiés.

Cette modification n’a pas d’impact sur les colonnes de chaînes à valeurs multiples réelles, qu’elles soient ou non en temps réel.

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> Rejoignez les astuces dans les requêtes du moteur de tâches MSQ

Druid prend désormais en charge les astuces pour les requêtes SQL JOIN qui utilisent le moteur de tâches MSQ. Cela permet aux requêtes de fournir des indications sur le type JOIN qui doit être utilisé à chaque niveau de jointure. Les indices de jointure affectent de manière récursive les sous-requêtes.

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> Compatibilité ANSI-SQL et résultats des requêtes

La prise en charge des configurations qui vous permettaient de conserver un comportement plus ancien qui n'était pas conforme à ANSI-SQL a été supprimée :

-druid.generic.useDefaultValueForNull=true -druid.expressions.useStrictBooleans=false -druid.generic.useThreeValueLogicForNativeFilters=false

Ils n'affectent plus les résultats de votre requête. Seul le comportement non hérité conforme à SQL est désormais pris en charge.

Si les configurations sont définies sur le comportement hérité, les services Druid ne pourront pas démarrer.

Si vous souhaitez continuer à obtenir les mêmes résultats sans ces paramètres, vous devez mettre à jour vos requêtes, sinon vos résultats seront incorrects après la mise à niveau.

Pour plus d'informations sur la façon de mettre à jour vos requêtes, consultez le guide de migration.

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> Rejoignez les astuces dans les requêtes du moteur de tâches MSQ

Druid prend désormais en charge les astuces pour les requêtes SQL JOIN qui utilisent le moteur de tâches MSQ. Cela permet aux requêtes de fournir des indications sur le type JOIN qui doit être utilisé à chaque niveau de jointure. Les indices de jointure affectent de manière récursive les sous-requêtes.

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

<a name="32.0.0-functional-area-and-related-changes-ingestion" href="#32.0.0-functional-area-and-related-changes-ingestion">#</a> Ingestion

<a name="32.0.0-functional-area-and-related-changes-ingestion-numbers-for-csv-and-tsv-input-formats" href="#32.0.0-functional-area-and-related-changes-ingestion-numbers-for-csv-and-tsv-input-formats">#</a> Numéros pour les formats d'entrée CSV et TSV

Utilisez la nouvelle configuration facultative tryParseNumbers pour les formats d'entrée CSV et TSV afin de contrôler la façon dont les nombres sont traités. S'il est activé, tous les nombres présents dans l'entrée seront analysés de la manière suivante :

  • type de données long pour les types entiers et
  • double pour les nombres à virgule flottante

Par défaut, cette configuration est définie sur false, donc les chaînes numériques seront traitées comme des chaînes.

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion">#</a> Ingestion de flux

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing">#</a> Contrôler le nombre de segments fusionnés pour la publication

Vous pouvez désormais utiliser la propriété maxColumnsToMerge dans votre spécification de superviseur pour spécifier le nombre de segments à fusionner en une seule phase lors de la fusion de segments pour la publication. Cette limite affecte le nombre total de colonnes présentes dans un ensemble de segments à fusionner. Si la limite est dépassée, la fusion des segments se produit en plusieurs phases. Druid fusionne au moins 2 segments à chaque phase, quel que soit ce paramètre.

<a name="32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Modifications incompatibles

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notes des développeurs

  • Prise en charge améliorée des dépendances entre les extensions. Lorsqu'une extension a une dépendance sur une autre extension, elle essaie désormais d'utiliser le chargeur de classes de la dépendance pour trouver les classes requises #16973
  • Les coordonnateurs API pour marquer les segments comme utilisés ou inutilisés sont désormais obsolètes et seront supprimés dans une prochaine version. Utilisez plutôt les Overlord API correspondants. Pour une liste complète, voir New Overlord APIs ou #17545

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates">#</a> Mises à jour des dépendances

Les versions des dépendances suivantes ont été modifiées :

  • javax.xml.bind n'est plus utilisé. Druide utilise désormais jakarta.xml.bind #17370
  • Plusieurs dépendances de la console Web ont vu leurs dépendances mises à jour. Pour une liste complète, voir #17381, #17365, #17363
  • Suppression de la dépendance file-loader pour la console Web #17346
  • Guide de 4.2.2 à 5.1.0
  • git-commit-id-maven-plugin de 4.9.10 à 9.0.1 #17571
  • Netty de la version 4.1.108.Final à 4.1.116.Final
