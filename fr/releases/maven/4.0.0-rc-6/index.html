maven 4.0.0-rc-6

Pré-version Publié30 juil. 2026 Sourceapache/maven Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

maven maven-4.0.0-rc-6

Remarques

Cette nouvelle version candidate de Maven 4 est publiée pour recueillir les commentaires des utilisateurs. Maven 4 a restreint certaines choses par rapport à Maven 3, alors assurez-vous d'exécuter l'outil mvnup avant d'essayer votre projet avec Maven 4.

Problèmes résolus depuis RC-5

Tous les problèmes connus signalés dans les RC-5 release note ont été résolus :

  • Bogue de configuration du bean — l'état d'accessibilité des champs était mis en cache globalement, provoquant des échecs d'injection de configuration du plugin. Corrigé dans #11433.
  • Problème de concurrence dans la v4 API — un ConcurrentModificationException a été corrigé dans #11429.
  • Packaging BOM — La conversion POM grand public pour les projets BOM préserve désormais correctement les versions de dépendances. Corrigé dans #11464.
  • macOS Gatekeeper — les binaires natifs JLine extraits qui ont déclenché Gatekeeper ont été supprimés de la distribution (#11997). La solution de contournement xattr de RC-5 n'est plus nécessaire.

Problèmes de compatibilité connus

Voici les problèmes de compatibilité connus lors de l'utilisation de Maven 4. mvnup avant de construire avec Maven 4 résoudra automatiquement de nombreux problèmes courants de version du plugin. Les problèmes Vous trouverez ci-dessous ceux qui nécessitent une intervention manuelle ou des correctifs en amont.

Validation POM plus stricte

Maven 4 applique une validation plus stricte que Maven 3. Les projets devront peut-être corriger leurs POM :

  • Éléments XML en double — les doublons <artifactId>, <properties>, etc. sont désormais rejetés (erreur Duplicated tag). Corrigez le POM source.
  • Déclarations de dépendance en double — le même groupId:artifactId déclaré deux fois est désormais rejeté (must be unique).
  • Expressions non interpolées — Les expressions ${...} dans les URL de référentiel, les ID de gestion de distribution et d'autres champs acceptés silencieusement par Maven 3 sont désormais rejetés.
  • XML non valide dans les POM transitifs — des instructions de traitement illégales ou des préfixes d'espace de noms non déclarés dans les POM transitifs provoquent des erreurs Non-parseable POM.
  • Propriétés dans les chemins <module> — Maven 4 n'interpole plus les propriétés telles que ${spark.version} dans les éléments <module> au moment de la lecture du POM.
  • Versions compatibles CI — les projets utilisant ${revision} sans flatten-maven-plugin peuvent rencontrer des erreurs de version de dépendance manquante.
  • Demande de collecte invalide — les dépendances transitives avec des expressions de version ${...} non interpolées sont rejetées.

Modifications de la résolution des dépendances transitives

Le TransitiveDependencyManager de Maven 4 applique dependencyManagement à toutes les profondeurs transitives (Maven 3 ne l'a appliqué qu'au premier niveau). Ceci est intentionnel mais peut modifier les versions résolues :

  • Les dépendances précédemment sur le chemin de classe peuvent disparaître — ajoutez des déclarations explicites. Voir #12302.
  • Les règles de la version maven-enforcer-plugin peuvent se déclencher en raison de versions transitives dégradées.
  • license-maven-plugin peut signaler de nouvelles dépendances transitives ne figurant pas dans la liste verte.
  • La vérification des fonctionnalités de Karaf peut échouer en raison de non-concordances de version du bundle OSGi.

Compatibilité des plugins et des extensions

Certains plugins et extensions nécessitent des versions spécifiques pour Maven 4 :

  • Quarkus — les versions antérieures à 3.20 utilisent des modèles ServiceLocator/RepositorySystem incompatibles avec la DI basée sur Sisu de Maven 4. Passez au Quarkus 3.20+.
  • Tycho — les versions antérieures à 5.0 utilisent des modèles d'injection Guice/Sisu rompus par Maven 4. Mise à niveau vers Tycho 5.0.3+.
  • Extension Develocity Maven — ne parvient pas à s'initialiser en raison de modifications de chargement de classe SLF4J (ClassNotFoundException: SimpleLogger).
  • pgpverify-maven-plugin — versions antérieures à 1.20 qui frappent un ClassCastException avec le résolveur de Maven 4. Voir résolveur n°1957.
  • cyclonedx-maven-plugin — échoue avec Invalid Version Range Request lors de l'utilisation de versions compatibles CI de ${revision}.
  • maven-site-plugin — Le rendu du modèle Velocity peut échouer avec des versions de plugin de site incompatibles.
  • maven-shade-plugin — dependency-reduced-pom.xml peut provoquer l'erreur The parents form a cycle.
  • commons-release-plugin — clean-staging échoue sous Maven 4.

Modifications du chargement des classes

  • Les plugins s'appuyant sur la disposition classrealm de Maven 3 peuvent rencontrer des erreurs "importations étrangères" (par exemple, Quarkus, plugins JAXB).
  • Le routage du référentiel basé sur le préfixe de Maven 4 peut bloquer les artefacts ne correspondant pas à /.meta/prefixes.txt.

Formatage post-mvnup

  • spotless-maven-plugin et sortpom-maven-plugin peuvent signaler des violations de formatage après que mvnup ait modifié les fichiers POM. Réexécutez le formateur après mvnup.

Autre

  • POM en amont cassés — par exemple, hadoop-project 3.1.0–3.3.0 a un code XML non valide (<Xlint:-unchecked/>) provoquant des erreurs d'analyse. Ceux-ci nécessitent des correctifs en amont suivis dans HADOOP-19923.
  • Ordre des éléments POM Enforcer — Le générateur de modèles de Maven 4 réorganise les éléments POM dans un ordre canonique, ce qui peut enfreindre les règles d'application vérifiant l'ordre des éléments.
  • Gestion SNAPSHOT — Les artefacts SNAPSHOT peuvent apparaître comme « présents, mais indisponibles » dans le cadre des différentes gestions des métadonnées du résolveur de Maven 4.
