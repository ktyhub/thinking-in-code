Remarques

Cette nouvelle version candidate de Maven 4 est publiée pour recueillir les commentaires des utilisateurs. Maven 4 a quelques éléments restreints par rapport à Maven 3, alors assurez-vous d'exécuter l'outil mvnup avant d'essayer de projeter avec Maven 4.

Bogue de configuration du bean

Un bug a été trouvé dans le système de configuration du bean où l'état d'accessibilité des champs est mis en cache globalement. Cela peut entraîner l'échec de l'injection de configuration du plugin lorsque le même champ de configuration est accédé plusieurs fois ou dans des contextes différents au cours d'une construction. Cela affecte particulièrement les tests unitaires du plugin.

Cela sera corrigé par #11433 dans la prochaine version.

Problème de concurrence dans la v4 API

Un problème de concurrence a été trouvé dans le Maven 4 API (toujours en mode aperçu) et sera corrigé par #11428 dans la prochaine version.

Emballage de nomenclature

Un autre bug a été trouvé dans la façon dont les projets de nomenclature sont traités. Lorsqu'un projet utilise un packaging BOM, le POM consommateur n'est pas correctement converti en packaging POM standard et les versions de dépendance peuvent être perdues dans certains cas.

Cela sera corrigé par #11427 dans la prochaine version.

macOS : la bibliothèque native JLine peut être bloquée par Gatekeeper lors de la première utilisation

Sur macOS (en particulier Apple Silicon), la première invocation de mvn peut ne pas réussir à charger la bibliothèque de terminal native JLine avec une erreur telle que :

java.lang.UnsatisfiedLinkError: .../libjline-native/Mac/arm64/libjlinenative.jnilib: dlopen(...): code signature ... not valid for use in process: library load disallowed by system policy

Cela se produit lorsque la distribution binaire est téléchargée via un navigateur Web, qui applique l'attribut com.apple.quarantine extended.

Solution de contournement (correctif unique) :

xattr -r -d com.apple.quarantine /path/to/apache-maven-4.0.0-rc-5/lib/jline-native

Méthode de téléchargement recommandée (évite complètement le problème) :

curl -L -O https://archive.apache.org/dist/maven/maven-4/4.0.0-rc-5/binaries/apache-maven-4.0.0-rc-5-bin.tar.gz
tar -xzf apache-maven-4.0.0-rc-5-bin.tar.gz

Il s'agit d'un problème connu n° 10747 qui sera résolu dans une prochaine version.
