"Le grand nettoyage"

Modifications impactantes pour l'utilisateur

  • #2703 Le référencement du paramètre de collection par son nom échoue dans la correction #2693

  • #2709 Correction d'une condition de concurrence provoquée par d'autres threads appelant des méthodes de mappage pendant la construction des tables mappées

  • #2727 Activer la possibilité de fournir une configuration personnalisée à XMLConfigBuilder

  • #2731 L'ajout du mappeur pouvait échouer sous JPMS

  • #2741 Ajout de l'attribut 'affectedData' à @Select, @SelectProvider et <select />

  • #2767 Résoudre resultType par espace de noms et identifiant lorsqu'ils ne sont pas fournis resultType et resultMap

  • #2804 Rechercher une propriété lisible lors de la résolution du type d'argument du constructeur par nom

  • Correction mineure : 'booléen' ne peut jamais être nul (primatif)

  • Mises à jour générales de la bibliothèque

  • Utilise désormais l'option de paramètres pour le compilateur (nécessaire par spring boot 3) (pour les besoins de réflexion)

Construire

  • #2820 Supprimez le profil du groupe test ci en faveur d'une utilisation plus directe sur GH-Actions et mettez à jour le surefire obsolète dans la présentation dans README.md
  • Ajustements pour construire de manière à ce que ognl et javassist ombrés ne génèrent plus d'avertissements
  • Construisez également avec jdk 21-ea maintenant
  • Divers nettoyages de tests, mises à jour et ajouts
  • Activez le formatage automatique de tout le code Java, y compris la note aux contributeurs sur le fichier Lisez-moi pour ignorer le formatage si nécessaire dans les blocs de code
  • Les tests peuvent désormais utiliser jdk 11 tout en conservant le runtime jdk 8
  • Nettoyage Pom / meilleure clarification des paramètres

Documentation

  • Diverses mises à jour de la documentation

Pour les contributeurs :

  • Mybatis utilise désormais le formatage automatique de la base de code. Si la contribution nécessite un formatage spécial tel que des annotations ou des javadocs spécifiques qui entrent en conflit avec les règles de formatage, utilisez // @formatter:off et // @formatter:on autour du bloc de code à ignorer lors du formatage. Si dans un javadoc, puisqu'il s'agit d'un type de commentaire, l'ensemble est affecté, alors enroulez-le simplement autour de l'intégralité du javadoc. Essayez de vous assurer que le code à l’intérieur du bloc non formaté est correctement formaté pour faciliter la lisibilité.
