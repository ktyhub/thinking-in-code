#nacos 2.5.5

Nacos 2.5.5 Release Note

Nacos 2.5.5 est principalement une version de correction de bugs et d'amélioration de l'expérience pour la série 2.x.

Cette version se concentre sur :

  • Renforcement des chemins de disque du serveur et vérifications de l'état HTTP actives.
  • Prévention de la perte d'instance de service lors des redémarrages complets du cluster.
  • Correction de la corruption du frame gRPC tout en préservant la compatibilité Java 8.
  • Amélioration de la gestion des requêtes HTTP et de la cohérence des membres du cluster.

Modifications détaillées dans cette version :

Amélioration/Refactorisation

  • #15809 Renforcez la validation du chemin du disque du serveur pour le stockage de configuration, les règles TPS locales et l'extraction ZIP afin d'empêcher l'accès en dehors des répertoires prévus.
  • #15828 Renforcez les vérifications de l'état HTTP actives en validant les cibles de requête et les en-têtes personnalisés et en limitant les vérifications à la cible de l'instance enregistrée.

Correction de bugs

  • #15857 Correction de la perte permanente d'instance de service lors des redémarrages complets du cluster en excluant les clients basés sur la connexion des instantanés de distribution qui peuvent écraser les nouveaux enregistrements.
  • #15865 Correction de la recherche de méthode de contrôleur pour les requêtes HTTP HEAD en les résolvant selon les mappages GET correspondants.
  • #15951 Correction du hachage incohérent des membres du cluster en alignant hashCode() avec la comparaison basée sur l'adresse utilisée par equals().

Dépendances

  • #15936 Mettez à niveau gRPC vers 1.78.0 pour corriger la corruption de trame provoquant de fausses erreurs de taille de message et de fin de flux au milieu de la trame, tout en conservant Guava 33.3.1-android pour la compatibilité Java 8.

Notes de mise à niveau

Cette version renforce la validation des chemins de disque et les vérifications de l'état HTTP actives. Avant la mise à niveau, vérifiez les configurations suivantes :

  • Les champs d'identité de configuration ne doivent pas être exactement . ou ... Les noms de règles TPS locales doivent être des noms de fichiers valides sans séparateurs de chemin ni composants de traversée de répertoire.
  • Les cibles de contrôle de santé HTTP doivent utiliser des références URI relatives, telles que /health avec des paramètres de requête facultatifs, sans schéma, autorité ou fragment. Les en-têtes personnalisés doivent être valides et ne doivent pas inclure Content-Length ou Transfer-Encoding.

Les vérifications d'état HTTP existantes qui échouent à la nouvelle validation sont ignorées sans envoyer de requêtes ni modifier l'état d'intégrité de l'instance. Mettez à jour les configurations concernées pour restaurer la vérification de l'état.

Les déploiements utilisant des identifiants valides et des configurations de vérification de l'état ne nécessitent aucune modification pour ces mises à jour de validation.

Configuration requise pour la version Java

Nacos 2.5.5 conserve la base de référence Java 8 utilisée par la série 2.x.

| Module | Java requis | |--------|--------------| | Nacos-Serveur / Nacos-Console | Java8 | | Nacos-Client | Java8 |
