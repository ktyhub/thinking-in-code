printemps-ai-alibaba v1.1.2.2

Intégration AgentScope

AgentScope Java est un cadre de programmation orienté agent pour créer des applications basées sur LLM.

  • AgentScope – AgentScopeAgent encapsule [AgentScope ReActAgent en tant que BaseAgent à utiliser dans les workflows graphiques] (https://github.com/alibaba/spring-ai-alibaba/tree/main/examples/agentscope).
# Add the following dependency to ochestrate AgentScope using SAA Graph
<dependency>
  <groupId>com.alibaba.cloud.ai</groupId>
  <artifactId>spring-ai-alibaba-starter-agentscope</artifactId>
  <version>1.1.2.2</version>
</dependency>

Modèles multi-agents

  • Subagent – L'orchestrateur principal délègue des tâches à des sous-agents spécialisés (explorateur de base de code, chercheur Web, etc.) via les outils Task/TaskOutput ; prend en charge les sous-agents définis par Markdown et API.
  • Superviseur – L'agent de supervision central transforme les agents de calendrier et de messagerie en outils (AgentTool), les invoque à la demande et synthétise les résultats.
  • Compétences – Un seul agent utilise read_skill pour charger le contenu des compétences à la demande ; L'invite du système affiche uniquement les descriptions des compétences pour une divulgation progressive et un contexte plus restreint.
  • Routage
    • Routing (simple) – LlmRoutingAgent classe la requête utilisateur, invoque des agents spécialisés (GitHub, Notion, Slack) en parallèle, puis synthétise une réponse unique.
    • Routing (graph) – LlmRoutingAgent en tant que nœud StateGraph avec prétraitement/post-traitement et un nœud de fusion interne pour le routage et la synthèse des résultats.
  • Transferts
    • Transferts (agent unique) – Un ReactAgent avance les étapes via l'état (par exemple current_step) ; un ModelInterceptor injecte une invite système et des outils spécifiques à une étape par tour.
    • Handoffs (multi-agent) – Agents de vente et de support en tant que nœuds graphiques ; Les outils de transfert mettent à jour active_agent et l'acheminement des bords conditionnels entre les agents.
  • Workflow – Exemples de workflow personnalisés : RAG (réécriture → récupération → préparation → agent) et agent SQL (list_tables → get_schema → run_query) en tant que flux basés sur des graphiques.

Agent multimodal et vocal

  • Voice Agent – Architecture sandwich (STT → ReactAgent → TTS) : voix en temps réel basée sur WebSocket avec DashScope ASR et CosyVoice TTS, plus saisie de texte ; l'agent utilise des outils de commande sandwich et diffuse les événements (stt_chunk, agent_chunk, tts_chunk).
  • Multimodal – Vision (entrée/sortie d'image) et TTS : modèles de vision DashScope pour la compréhension des images et ReactAgent avec entrée multimédia ; génération d'images via des outils (Wanx), TTS via DashScopeAudioSpeechModel ; ToolMultimodalResult pour les réponses structurées des outils (url/base64).
