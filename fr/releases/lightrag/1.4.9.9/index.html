LightRAG v1.4.9.9

#Release Note V1.4.9.9

Remarques importantes

  • Ajoutez une isolation de l'espace de travail pour l'état du pipeline et le stockage en mémoire : plusieurs instances LightRAG avec des espaces de travail distincts peuvent être créées simultanément, marquant une avancée significative vers une commutation transparente des espaces de travail au sein d'un seul serveur LightRAG.
  • Ajouter une isolation des données vectorielles de l'espace de travail par nom de modèle et dimension pour PostgreSQL et Qdrant : auparavant, LightRAG utilisait une seule collection/table pour l'intégration des différences entre le modèle et la dimension, ce qui provoquait des plantages d'incompatibilité de dimension ou une pollution des données dans plusieurs espaces de travail.
  • La sélection des dimensions est prise en charge pour OpenAI et Gemini Modèle d'intégration avec une nouvelle variable d'environnement introduite : EMBEDDING_SEND_DIM
  • Ajoutez des outils de migration du cache LLM et de nettoyage du cache de requêtes LLM entre différents stockages KV : permettant aux utilisateurs de changer de backend de stockage sans perdre l'extraction en cache et les données récapitulatives.
  • Amélioré Extraction DOCX améliorée avec prise en charge du contenu des tableaux.
  • Extraction XLSX améliorée avec gestion appropriée des caractères tab et newline dans les cellules.
  • Correction d'une vulnérabilité de sécurité critique dans les composants du serveur React : #2494
  • Ajouter la prise en charge de la troncature automatique du texte pour les fonctions d'intégration : la fonction d'intégration OpenAI respecte désormais la valeur max_token_size dans EmbeddingFunc et tronque automatiquement le texte d'entrée pour éviter les erreurs API causées par des textes dépassant les limites des jetons de modèle.

What's Breaking (pour l'intégration LightRAG Core uniquement)

  • Renommer les paramètres de la fonction de segmentation : Si vous intégrez la fonction de segmentation dans LightRAG et transmettez les paramètres par nom, des mises à jour du code correspondantes sont requises.
def chunking_by_token_size(
    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,
    chunk_overlap_token_size: int = 100,
    chunk_token_size: int = 1200,
) -> list[dict[str, Any]]:
  • Injectez un embedding_func avec model_name dans LightRAG en utilisant wrap_embedding_func_with_attrs :
@wrap_embedding_func_with_attrs(
    embedding_dim=1536, max_token_size=8192, model_name="text-embedding-3-small"
)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

rag = LightRAG(
      working_dir=WORKING_DIR,
      llm_model_func=llm_model_func,
      embedding_func=embedding_func,
)

Pour garantir une transition transparente, le code existant injectant embedding_func sans model_name continuera à s'interfacer avec les tables vectorielles d'origine sans suffixe.
