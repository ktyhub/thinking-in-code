LightRAG v1.4.7

Remarques importantes

  • La fonctionnalité de filtrage de blocs basée sur l'identifiant de document est supprimée du stockage vectoriel PostgreSQL.
  • Le modèle d'invite a été mis à jour, invalidant tous les caches LLM
  • La valeur par défaut de la variable d'environnement FORCE_LLM_SUMMARY_ON_MERGE a été modifiée de 4 à 8. Cet ajustement réduit considérablement le nombre d’appels LLM pendant la phase d’indexation de la documentation, raccourcissant ainsi le temps global de traitement des documents.
  • Ajout de la prise en charge de plusieurs fournisseurs de reclassement (Cohere AI, Jina AI, Aliyun Dashscope). Si le reclassement a été précédemment activé et qu'une nouvelle variable d'environnement doit être définie pour activer à nouveau le reclassement :
RERANK_BINDING=cohere
  • Introduit une nouvelle variable d'environnement, LLM_TIMEOUT, pour contrôler spécifiquement le délai d'expiration du Large Language Model (LLM). La variable TIMEOUT existante gère désormais exclusivement le timeout du travailleur Gunicorn. Le délai d'expiration LLM par défaut est défini sur 180 secondes. Si vous comptiez auparavant sur la variable TIMEOUT pour la configuration du délai d'expiration LLM, veuillez mettre à jour vos paramètres pour utiliser LLM_TIMEOUT à la place :
LLM_TIMEOUT=180
  • Ajoutez des paramètres complets de variables d'environnement pour les liaisons OpenAI et Ollama Large Language Model (LLM). La variable d'environnement générique TEMPERATURE pour le contrôle de la température LLM est obsolète. Au lieu de cela, la température LLM est désormais configurée à l'aide de variables d'environnement spécifiques à la liaison :
# Temperature setting for OpenAI binding
OPENAI_LLM_TEMPERATURE=0.8

# Temperature setting for Ollama binding
OLLAMA_LLM_TEMPERATURE=1.0

Pour atténuer les boucles de sortie sans fin et éviter un décodage gourmand pour Qwen3, définissez le paramètre de température sur une valeur comprise entre 0.8 et 1.0. Pour désactiver le mode « Réflexion » du modèle, veuillez vous référer à la configuration suivante :

### Qwen3 Specific Parameters depoly by vLLM
# OPENAI_LLM_EXTRA_BODY='{"chat_template_kwargs": {"enable_thinking": false}}'

### OpenRouter Specific Parameters
# OPENAI_LLM_EXTRA_BODY='{"reasoning": {"enabled": false}}'

Pour obtenir la liste complète des options de support, utilisez la commande suivante :

lightrag-server --llm-binding openai --help
lightrag-server --llm-binding ollama --help
lightrag-server --embedding-binding ollama --help
  • Une liste complète des nouvelles variables d'environnement ajoutées ou des nouvelles valeurs par défaut :
# Timeout for LLM requests (seconds)
LLM_TIMEOUT=180

# Timeout for embedding requests (seconds)
EMBEDDING_TIMEOUT=30

### Number of summary segments or tokens to trigger LLM summary on entity/relation merge (at least 3 is recommended)
FORCE_LLM_SUMMARY_ON_MERGE=8

### Max description token size to trigger LLM summary
SUMMARY_MAX_TOKENS = 1200

### Recommended LLM summary output length in tokens
SUMMARY_LENGTH_RECOMMENDED=600

### Maximum context size sent to LLM for description summary
SUMMARY_CONTEXT_SIZE=12000

### RERANK_BINDING type:  null, cohere, jina, aliyun
RERANK_BINDING=null

### Enable rerank by default in query params when RERANK_BINDING is not null
# RERANK_BY_DEFAULT=True

### chunk selection strategies
###     VECTOR: Pick KG chunks by vector similarity, delivered chunks to the LLM aligning more closely with naive retrieval
###     WEIGHT: Pick KG chunks by entity and chunk weight, delivered more solely KG related chunks to the LLM
###     If reranking is enabled, the impact of chunk selection strategies will be diminished.
KG_CHUNK_PICK_METHOD=VECTOR

### Entity types that the LLM will attempt to recognize
ENTITY_TYPES=["person", "organization", "location", "event", "concept"]
