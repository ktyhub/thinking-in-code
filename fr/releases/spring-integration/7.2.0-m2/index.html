spring-integration v7.2.0-M2

Pré-version Publié24 sept. 2026 Sourcespring-projects/spring-integration Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

intégration à ressort v7.2.0-M2

:star: Nouvelles fonctionnalités

  • Ajouter l'adaptateur de canal grand public de partage Kafka #11413
  • Supprimez la dépendance et l'utilisation d'Apache Derby #11387
  • Créez Function<MimeMessage, ?> comme CheckedFunction dans Mail Java DSL #11280
  • Utilisation de FullyQualifiedType trouvée par une nouvelle vérification de style de contrôle #11275

## :lady_beetle : corrections de bugs

  • Les sources des messages entrants des fichiers restent running après un échec de start() #11420
  • TcpNioServerConnectionFactory.stop() enregistre "Sélecteur fermé" en cas d'ERREUR lors d'un arrêt normal (régression de INT-3473) #11418
  • AmqpClientInboundGateway corrompt les noms de file d'attente de réponse AMQP 1.0 codés en pourcentage #11414
  • RedisLockRegistry et JdbcLockRegistry : lock(Duration) ne restaure pas l'état interrompu #11409
  • Correction d'une course dans FileWritingMessageHandler stop() perdant la trace d'un flush en vol #11386
  • Redémarrez Apache Commons Tailer si son thread d'arrière-plan meurt #11381
  • AdviceMessage.equals() renvoie true pour les messages avec des charges utiles différentes #11377
  • FileWritingMessageHandler : un close() défaillant est avalé et le fichier tronqué est toujours promu #11352
  • Le AbstractMailMessageTransformer perd les en-têtes en amont #11281
  • TcpNioClientConnectionFactory.stop() enregistre "Sélecteur fermé" à ERREUR à chaque arrêt normal en raison de l'ordre de fermeture du sélecteur/d'indicateur actif #11269
  • ReactiveStreamsConsumer sur PollableChannel peut perdre silencieusement un message sur stop() #11262

## :notebook_with_decorative_cover : Documentation

  • Section de l'historique des modifications polonaises #11402
  • corvée : correction d'une faute de frappe dans un exemple de documentation #11397
  • Mettre à jour les liens du registre de verrouillage JDBC dans l'historique des modifications #11366
