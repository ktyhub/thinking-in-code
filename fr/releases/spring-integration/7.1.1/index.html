spring-integration v7.1.1

Correctif Publié20 août 2026 Sourcespring-projects/spring-integration Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

intégration à ressort v7.1.1

:star: Nouvelles fonctionnalités

  • Ne convertissez pas les messages erronés dans le JmsOutboundGateway.onMessageSync() uniquement pour la journalisation du débogage #11197
  • Ne pas avertir que le serveur Redis 7 ne prend pas en charge DELEX #11137

## :lady_beetle : corrections de bugs

  • CVE-2026-47856 : JsonToObjectTransformer résout l'en-tête de message json__TypeId__ en une classe arbitraire sans liste verte #11340

  • CVE-2026-47859 : allocation de mémoire illimitée dans RFC6587SyslogDeserializer (cadrage par octets) – DoS distant #11338

  • CVE-2026-47862 : ZipTransformer utilise l'en-tête file_name pour créer le chemin workDirectory sans désinfection #11334

  • CVE-2026-47864 : Désérialisation Java non sécurisée dans SerializingHttpMessageConverter — exécution de code à distance #11332

  • CVE-2026-59324 : Correction d'une fuite d'en-tête de message croisé dans fluxTransform() sous concurrence #11329

  • CVE-2026-59321 : Correction de AbstractScriptExecutor pour les moteurs non thread-safe #11326

  • CVE-2026-59322 : remplacez la valeur par défaut d'EmbeddedHeadersJsonMessageMapper par aucun en-tête #11323

  • CVE-2026-59311 : Empêcher les transformateurs zip d'écrire des fichiers temporaires dans un lien symbolique #11320

  • CVE-2026-59292 : Ajouter un contrôle des autorisations des fichiers du magasin de métadonnées #11317

  • CVE-2026-59307 : JdbcMessageStore : nouveau mapper sur setBeanClassLoader #11313

  • CVE-2026-59293 : définissez la version par défaut de SMB sur SMB202 #11310

  • CVE-2026-59274 : Ajout d'options de contrainte de taille à UnzipTransformer #11308

  • CVE-2026-47880 : Ignorer les propriétés par défaut dans toHeaders #11305

  • CVE-2026-47861 : l'adaptateur UDP envoie un accusé de réception à l'hôte : port fourni par l'attaquant analysé à partir du corps du paquet, même lorsque l'accusé de réception = faux [#11302] (https://github.com/spring-projects/spring-integration/issues/11302)

  • FileWritingMessageHandler : la création automatique simultanée du même répertoire de destination échoue avec "Le répertoire de destination [...] n'a pas pu être créé." #11257

  • JdbcMetadataStore putIfAbsent peut rester bloqué dans la boucle while sur la base de données MySQL. #11255

  • Correction de l'isolement des tests ZookeeperLockRegistry et de la gestion des interruptions #11245

  • L'enregistrement Dynamic IntegrationFlow ignore l'injection de dépendances pour les composants supplémentaires et internes #11196

  • Condition de concurrence concurrentielle dans le AcceptOnceFileListFilter #11185

  • KafkaMessageDrivenChannelAdapter en mode batch ne génère pas d'ID de message, provoquant l'échec du séparateur #11183

  • Les verrous Redis ne sont pas uniques #11180

  • Ajuster la capacité du cache dans le JdbcLockRegistry #11172

  • Marquer le type de retour de fonction @Nullable pour lockKey et waitLockDuration #11168

  • Les verrous JDBC ne sont pas uniques #11157

  • Renvoie une erreur générique du AbstractWebServiceInboundGateway au client #11147

  • JdbcLockRegistry & RedisLockRegistry - Le ReentrantLock partagé de DefaultLockRegistry entraîne la non suppression de l'entrée APP_LOCK lors du déverrouillage lorsque deux clés de verrouillage différentes correspondent au même compartiment #11146

  • Le BaseIntegrationFlowDefinition.REFERENCED_REPLY_PRODUCERS est accessible simultanément #11127

  • Correction du décalage de l'en-tête de réception multioctet dans DatagramPacketMessageMapper #11115

  • Le PartitionedDispatcher.dispatch() échoue avec le IndexOutOfBoundsException lorsque le code de hachage est le Integer.MIN_VALUE #11114

  • Empêcher l'expulsion des verrous détenus du registre ZooKeeper #11113

  • La spécification du nom du canal pour les composants JMS entrants dans Java DSL provoque un échec de démarrage en raison de l'absence de BeanFactory #11107

  • Correction de FileReadingMessageSource pour gérer les fichiers canoniques #11103 ## :notebook_with_decorative_cover : Documentation

  • Inclure RedisHeaders.COMMAND dans les métadonnées sensibles #11201

  • Documenter les implications en matière de sécurité pour le storedProcedureNameExpression #11200

  • Document FileHeaders.ORIGINAL_FILE en tant que métadonnées sensibles #11199

  • Mentionner un problème de sécurité pour le contrôleur de bus de contrôle #11198

  • Le Javadoc FileWritingMessageHandler.trigger() doit mentionner ReDoS #11132
