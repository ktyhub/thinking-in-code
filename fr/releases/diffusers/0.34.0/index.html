diffuseurs v0.34.0

📹 Nouveaux pipelines de génération vidéo

Wan VACE

Wan VACE prend en charge diverses techniques de génération permettant d'obtenir une génération vidéo contrôlable. Il est disponible en deux variantes : un modèle 1.3B pour une itération et un prototypage rapides, et un modèle 14B pour une génération de haute qualité. Certaines des capacités incluent :

  • Contrôle de la vidéo (profondeur, pose, croquis, flux, niveaux de gris, gribouillage, mise en page, cadre de délimitation, etc.). Bibliothèque recommandée pour le prétraitement des vidéos afin d'obtenir des vidéos de contrôle : huggingface/controlnet_aux
  • Image/Vidéo vers vidéo (première image, dernière image, début de clip, fin de clip, clips aléatoire)
  • Inpainting et Outpainting
  • Sujet à la Vidéo (visages, objet, personnages, etc.)
  • Composition en vidéo (référencer n'importe quoi, animer n'importe quoi, échanger n'importe quoi, développer n'importe quoi, déplacer n'importe quoi, etc.) Les extraits de code disponibles dans this pull request montrent quelques exemples de la façon dont des vidéos peuvent être générées avec des signaux de contrôlabilité. Consultez les docs pour en savoir plus.

Cosmos Predict2 Vidéo2Monde

Cosmos-Predict2 est une branche clé de l'écosystème Cosmos World Foundation Models (WFMs) pour l'IA physique, spécialisée dans la prédiction de l'état futur grâce à une modélisation avancée du monde. Il offre deux fonctionnalités puissantes : la génération de texte en image pour créer des images de haute qualité à partir de descriptions textuelles et la génération de vidéo en monde pour produire des simulations visuelles à partir d'entrées vidéo. Le modèle Video2World est disponible en variantes 2B et 14B. Consultez les docs pour en savoir plus.

LTX 0.9.7 et distillé

Le LTX 0.9.7 et ses variantes distillées sont les derniers de la famille de modèles commercialisés par Lightricks. Consultez les docs pour en savoir plus.

Framepack vidéo Hunyuan et F1

Framepack est une nouvelle méthode permettant de générer de longues vidéos. Il existe deux variantes publiées de Hunyuan Video entraînées à l'aide de cette technique. Consultez les docs pour en savoir plus.

FusionX

La famille de modèles et LoRA FusionX, construite sur Wan2.1-14B, devrait déjà être prise en charge. Pour charger le modèle, utilisez from_single_file() :

from diffusers import WanTransformer3DModel

transformer = WanTransformer3DModel.from_single_file(
    "https://huggingface.co/vrgamedevgirl84/Wan14BT2VFusioniX/blob/main/Wan14Bi2vFusioniX_fp16.safetensors",
    torch_dtype=torch.bfloat16
)

Pour charger les LoRA, utilisez load_lora_weights() :

pipe = DiffusionPipeline.from_pretrained(
    "Wan-AI/Wan2.1-T2V-14B-Diffusers",
    torch_dtype=torch.bfloat16
).to("cuda")
pipe.load_lora_weights(
    "vrgamedevgirl84/Wan14BT2VFusioniX", weight_name="FusionX_LoRa/Wan2.1_T2V_14B_FusionX_LoRA.safetensors"
)

AccVideo et CausVid (uniquement LoRA)

AccVideo et CausVid sont deux nouvelles techniques de distillation qui accélèrent le temps de génération des modèles de diffusion vidéo tout en préservant la qualité. Les diffuseurs prennent en charge le chargement de leurs LoRA extraits avec leurs modèles respectifs.

VisualClose

  1. Prise en charge de diverses tâches dans le domaine
  2. Généralisation à des tâches invisibles grâce à l'apprentissage en contexte

  4. Prise en charge des conditions de rétro-ingénierie à partir des images cibles Consultez les docs pour en savoir plus. Merci à @lzyhha pour cette contribution dans ce PR !

Meilleur support torch.compile

Nous avons travaillé avec l'équipe PyTorch pour améliorer la façon dont nous fournissons la compatibilité torch.compile() dans toute la bibliothèque. Plus précisément, nous testons maintenant les modèles largement utilisés comme Flux pour tout problème de recompilation et de rupture de graphique qui peut empêcher de tirer pleinement parti des avantages de torch.compile(). Reportez-vous aux liens suivants pour en savoir plus : -https://github.com/huggingface/diffusers/pull/11085 -https://github.com/huggingface/diffusers/issues/11430 De plus, les utilisateurs peuvent combiner le déchargement et la compilation pour obtenir un meilleur compromis vitesse-mémoire. Vous pouvez réduire considérablement les besoins en mémoire en combinant quantification et déchargement, puis en améliorant la vitesse avec `torch.compile()`. Ci-dessous un exemple :

from diffusers import AutoModel, FluxPipeline
from transformers import T5EncoderModel

import torch
torch._dynamo.config.recompile_limit = 1000

    ckpt_id,
    subfolder="text_encoder_2",

    ckpt_id,

    torch_dtype=torch_dtype,

    ckpt_id,
    transformer=transformer,
    text_encoder_2=text_encoder_2,

)

    prompt="An astronaut riding a horse on Mars",
    guidance_scale=3.5,
    height=768,

PipelineQuantizationConfig

Les utilisateurs peuvent désormais fournir une configuration de quantification lors de l'initialisation d'un pipeline :

import torch
from diffusers import DiffusionPipeline
from diffusers.quantizers import PipelineQuantizationConfig

pipeline_quant_config = PipelineQuantizationConfig(
     quant_backend="bitsandbytes_4bit",
     quant_kwargs={"load_in_4bit": True, "bnb_4bit_quant_type": "nf4", "bnb_4bit_compute_dtype": torch.bfloat16},
     components_to_quantize=["transformer", "text_encoder_2"],
)
pipe = DiffusionPipeline.from_pretrained(
    "black-forest-labs/FLUX.1-dev",
    quantization_config=pipeline_quant_config,
    torch_dtype=torch.bfloat16,
).to("cuda")

image = pipe("photo of a cute dog").images[0]

Cela réduit la barrière à l’entrée pour nos utilisateurs désireux d’utiliser la quantification sans avoir à écrire trop de code. Reportez-vous à la documentation pour en savoir plus sur les [différentes configurations] (https://huggingface.co/docs/diffusers/main/en/quantization/overview#pipeline-level-quantization) autorisées via PipelineQuantizationConfig.

Déchargement de groupe avec disque

Dans la [version précédente] (https://github.com/huggingface/diffusers/releases/tag/v0.33.0), nous avons fourni le « déchargement de groupe » qui vous permet de décharger des blocs/nœuds au sein d'un modèle, optimisant ainsi sa consommation de mémoire. Il vous permet également de superposer ce déchargement avec le calcul, offrant ainsi un bon compromis vitesse-mémoire, en particulier dans les environnements à faible VRAM. Cependant, vous avez toujours besoin d’une quantité considérable de RAM système pour que le déchargement fonctionne efficacement. Ainsi, les environnements à faible VRAM et RAM ne fonctionneraient toujours pas. À partir de cette version, les utilisateurs auront en outre la possibilité de décharger leurs fichiers sur le disque plutôt que sur la RAM, réduisant ainsi davantage la consommation de mémoire. Réglez le offload_to_disk_path pour activer cette fonctionnalité.

pipeline.transformer.enable_group_offload(
    onload_device="cuda", 
    offload_device="cpu", 
    offload_type="leaf_level", 
    offload_to_disk_path="path/to/disk"
)

Reportez-vous à ces deux tableaux pour comparer les compromis en matière de vitesse et de mémoire.
