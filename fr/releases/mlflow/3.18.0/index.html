mlflow v3.18.0

MLflow 3.18.0 vous aide à réutiliser l'expertise des agents, à rechercher des régressions avant l'expédition et à surveiller la qualité en production.

Nouvelles fonctionnalités majeures

  • Détection automatique des problèmes : transformez les échecs récurrents des agents en problèmes que vous pouvez enquêter et résoudre. L'onglet Problèmes dédié regroupe les problèmes liés et relie les résultats aux preuves ; planifier la détection pour continuer à vérifier le nouveau trafic. (#27193, #26751, #26754, #26791, #26919, #26955, #26961, #26967, #27009, #27002, #27003, #27006, #27137, #27181, #27249, @tanghaoji ; #27070, @B-Step62)
  • Registre de compétences : partagez l'expertise de votre équipe entre les agents et les projets avec un catalogue central de compétences réutilisables. Découvrez les compétences existantes et choisissez la version ou l'alias à utiliser dans chaque agent. Expérimental. (#26736, @mprahl ; #26900, @bardenr ; #27088, @Rohitkanithi)
  • Évaluation et comparaisons de traces remaniées pour la recherche de régressions : recherchez les régressions cachées derrière les scores globaux avant d'envoyer une mise à jour d'agent. L'interface utilisateur de comparaison repensée vous emmène des modifications de score aux entrées, conversations et étapes de suivi derrière elles. Un Python expérimental API ajoute des comparaisons statistiques pour aider à distinguer les améliorations du bruit. (#26991, #26733, #26739, #26740, #26770, #26771, #26782, #26783, #26784, #26927, #26799, #26803, #26808, #26868, #26880, #26889, #26896, #27011, #27014, #27015, @joshuawong-db ; #27332, @filip-urbanski #26396, @AbdulAliMamnun)
  • Évaluation en ligne : détectez les régressions de la qualité de production avec des contrôles personnalisés basés sur du code qui évaluent automatiquement les nouvelles traces et les conversations à plusieurs tours dès leur arrivée. L'évaluation en ligne basée sur le code est expérimentale et nécessite un serveur auto-hébergé configuré avec des [conteneurs de travaux] (https://mlflow.org/docs/latest/self-hosting/job-containers/). (#26689, #26430, #26684, #26685, #26687, @kriscon-db)

Modifications radicales

  • [Suivi] Filtrez et triez les métriques search_logged_models par l'étape la plus élevée, puis par le dernier horodatage, sur les magasins SQL ; appliquer datasets au filtrage et au tri (#27215, @agtzrubio)
  • [Registre des modèles] Arrêtez d'ajouter registered_model_meta aux téléchargements models:/ ; les lecteurs personnalisés doivent utiliser l'URI ou le registre de modèles (#27173, @sunilmehta-si)
  • [Suivi] Rendre l'identité de la version du serveur MCP sensible à la casse sur MySQL et SQL Server ; corriger les références qui ne correspondent pas à la casse avant la mise à niveau (#25920, @LobsterQBA)

Mise à niveau de la base de données : Sauvegardez le backend SQL et planifiez une fenêtre de maintenance. Arrêtez les serveurs MLflow et autres rédacteurs, exécutez mlflow db upgrade <database-url> avec MLflow 3.18.0 et redémarrez sur la nouvelle version. La migration de la version MCP vérifie les références MySQL et SQL Server pour les correspondances exactes et s'arrête avant que son propre schéma ne change si une correction est nécessaire. Sur les bases de données insensibles à la casse, les autorisations de registre et MCP utilisent désormais les noms de ressources stockées. Réenregistrez les subventions dans une casse différente sous l'orthographe stockée. Suivez les [conseils de mise à niveau de la base de données] (https://mlflow.org/docs/latest/self-hosting/architecture/backend-store/).
