opentelemetry-java-instrumentation v2.32.0

Mineure Publié3 oct. 2026 Sourceopen-telemetry/opentelemetry-java-instrumentation Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

opentelemetry-java-instrumentation v2.32.0

Cette version cible le OpenTelemetry SDK 1.66.0.

Notez que de nombreux artefacts ont le suffixe -alpha attaché à leur numéro de version, ce qui indique qu'ils continueront à subir des modifications importantes. Veuillez consulter VERSIONING.md pour plus de détails.

⚠️ Modifications interrompues apportées aux API non stables

  • Supprimez la constante obsolète HostIdResource.REGISTRY_QUERY. (#19778)
  • Le SPI ExperimentalJmxMetricHandler nécessite désormais que les implémentations fournissent getMetricNames(). (#19781)
  • Ajoutez la méthode isRequestStreaming(REQUEST) requise à GenAiAttributesGetter. (#19879)
  • Le sélecteur expérimental java.common.messaging.headers/development YAML ne configure plus la capture d'en-tête. Utilisez plutôt java.common.messaging.headers. (#20260)

🚫 Dépréciations

  • Déprécier otel.jmx.target.system au profit de otel.jmx.metrics.experimental.included. (#19783)
  • Déprécier otel.instrumentation.elasticsearch.capture-search-query. Il sera supprimé dans 3.0, lorsque les corps des requêtes de recherche seront toujours capturés. Il n'y a pas de remplacement. (#19675)
  • Déprécier otel.instrumentation.opensearch.capture-search-query. Il sera supprimé dans 3.0, lorsque les corps des requêtes de recherche seront toujours capturés. Il n'y a pas de remplacement. La désinfection reste activée par défaut et configurable avec otel.instrumentation.opensearch.query-sanitization.enabled. (#19837)
  • Déprécier otel.jmx.enabled au profit de otel.instrumentation.jmx.enabled pour s'aligner sur d'autres propriétés d'activation de l'instrumentation. (#19945)
  • Déprécier la réécriture automatique des appels VirtualField.find(Class, Class) dans les conseils Javaagent intégrés. Au lieu de cela, recherchez le VirtualField une fois et stockez-le dans le champ static final d'une classe d'assistance. La méthode find elle-même reste prise en charge. (#19980)
  • Déprécier l'instrumentation de la bibliothèque REST Elasticsearch. Utilisez la prise en charge native OpenTelemetry de Elasticsearch Java API Client, ​​ou l'agent Java pour une utilisation directe de RestClient. L'instrumentation de l'agent Java n'est pas affectée. (#19995)
  • Déprécier otel.instrumentation.messaging.experimental.receive-telemetry.enabled au profit de otel.instrumentation.common.messaging.experimental.receive-telemetry.enabled. Pour les embases, remplacez otel.instrumentation.messaging.experimental.headers.included et .excluded par otel.instrumentation.common.messaging.headers.included et .excluded. Dépréciez également otel.instrumentation.messaging.experimental.capture-headers au profit de otel.instrumentation.common.messaging.headers.included. Les sélecteurs stables sont prioritaires par feuille. (#20060, #20260)
  • Déprécier les propriétés .included / .excluded sous otel.instrumentation.log4j-appender.experimental.map-message-attributes, otel.instrumentation.logback-appender.experimental.key-value-pair-attributes, otel.instrumentation.logback-appender.experimental.logstash-marker-attributes et otel.instrumentation.logback-appender.experimental.logstash-structured-argument-attributes au profit des propriétés otel.instrumentation.common.logging.structured-attributes.included / .excluded stables et unifiées. (#20066)
  • Déprécier otel.instrumentation.couchbase.experimental-span-attributes au profit de otel.instrumentation.couchbase.emit-experimental-telemetry, un nom plus large pour les attributs expérimentaux et les étendues internes du Couchbase sous-jacent client. (#20117)
  • Déprécier le otel.traces.sampler=linksbased_parentbased_always_on sans remplacement et déclaratif du rule_based_routing en faveur de l'échantillonneur composite/développement de l'incubateur SDK rule_based, dont la configuration et le comportement d'appariement diffèrent. (#20249)
  • Promouvoir la configuration du contrôleur et de la télémétrie vers les propriétés stables otel.instrumentation.common.controller-telemetry.enabled et otel.instrumentation.common.view-telemetry.enabled, dépréciant ainsi otel.instrumentation.common.experimental.controller-telemetry.enabled et otel.instrumentation.common.experimental.view-telemetry.enabled. (#20258)
  • Promouvoir la configuration de suppression d'étendue de l'agent Java vers la propriété stable otel.instrumentation.common.span-suppression-strategy, dépréciant ainsi otel.instrumentation.experimental.span-suppression-strategy. (#20259)
  • Déprécier otel.instrumentation.oshi.experimental-metrics.enabled, ProcessMetrics et ses méthodes registerObservers(...) au profit de jvm.memory.used et jvm.cpu.time. (#20323)
  • Déprécier SystemMetrics.registerObservers(Meter) dans l'instrumentation de la bibliothèque OSHI au profit de SystemMetrics.registerObservers(OpenTelemetry). (#20263)
  • Dans la configuration déclarative YAML, déprécier les sélecteurs en pointillés dans les listes distribution.javaagent.instrumentation.enabled et .disabled. Utilisez reactor_3_1 au lieu de reactor_3.1. Les noms de propriétés plates tels que otel.instrumentation.reactor-3.1.enabled restent inchangés. (#20326)

🌟 Nouvelle instrumentation javaagent

  • Ajoutez les métriques du pool de connexions à la base de données Redisson pour les versions 2.3.0 à 3.25. (#19152, #19634)
  • Ajoutez une instrumentation d'agent Java pour Pekko remoting afin que le contexte de trace se propage à travers les appels distants. (#19823)

(#19728, #19747, #19749, #19753, #19757, #19795, #19830, #19831, #19832, #19834, #19838, #19839, #19844, #19845, #19846, #19848, #19850, #19864, #19868, #19872, #19877, #19883, #19901, #19902, #19903, #19904, #19981, #19983, #19986, #19988, #20008, #20011, #20015, #20017, #20041, #20065, #20068, #20070, #20071, #20072, #20073, #20074, #20075, #20076, #20077, #20078, #20080, #20082, #20084, #20086, #20089, #20105)

(#19483, #19485, #19503, #19517, #19915, #20045, #20067, #20144)
  • Les étendues et métriques Kafka incluent désormais messaging.kafka.cluster.id une fois les métadonnées du cluster résolues. (#18978)
  • Ajoutez des attributs de base de données SQL aux étendues AWS SDK v2 RDS Data API ExecuteStatement et BatchExecuteStatement. (#19259)
  • Ajoutez les journaux WARNING pour les emplacements d'extension non valides ou vides et les chargements de JAR d'extension ayant échoué, ainsi que les journaux FINE pour les JAR d'extension chargés avec succès. (#19584)
  • La bibliothèque de métriques JMX inclut désormais la cible expérimentale de métriques du courtier Kafka. (#19722)
  • Mettez à jour les descriptions de kafka.connect.connector.status et kafka.connect.task.status pour omettre les valeurs d'état prises en charge répertoriées. (#19724)
  • Les étendues de la base de données Geode client incluent désormais server.address et server.port lorsque le pool de la région a exactement un serveur configuré. (#19748)
  • Ajout de la prise en charge du journal des exceptions pour la base de données HBase clients, SofaRPC clients et les serveurs, et GWT RPC avec otel.semconv.exception.signal.preview=logs. (#19750, #20253, #20254)
  • Ajoutez les attributs server.address et server.port aux étendues de la base de données Couchbase. (#19758)
  • Ajoutez un filtrage par nom de métrique pour les métriques JMX avec otel.jmx.metrics.included et otel.jmx.metrics.excluded, ou JmxTelemetryBuilder.setMetrics(IncludeExclude) dans la bibliothèque. (#19782)
  • Les étendues RabbitMQ incluent désormais messaging.rabbitmq.vhost.name et messaging.rabbitmq.cluster.name lorsque otel.instrumentation.rabbitmq.experimental-span-attributes=true. (#19822)
  • Les messages de création de métriques JMX sont désormais enregistrés à FINE au lieu de INFO, réduisant ainsi le bruit de journalisation par défaut. (#19825)
  • Les étendues du serveur HTTP Akka incluent désormais l'adresse du homologue distant dans les attributs d'adresse du homologue réseau. (#19840)
  • Les étendues de serveur HTTP Pekko incluent désormais client.address du homologue socket pour les requêtes HTTP/1.1 et HTTP/2. (#19841)
  • Ajoutez l'attribut network.protocol.version aux métriques de durée de requête Spring WebFlux 5.0 client. (#19842)
  • Les étendues Ratpack HTTP client incluent désormais l'attribut network.protocol.version. (#19843)
  • Ajoutez otel.instrumentation.opensearch.query-sanitization.enabled (true par défaut) pour contrôler si les corps de requête de recherche capturés sont nettoyés ; réglez-le sur false pour les capturer textuellement. (#19869)
  • Les spans GenAI incluent désormais l'attribut gen_ai.request.stream lorsque la requête utilise le streaming. (#19879)
  • L'instrumentation OpenAI Java 1.1 signale désormais le nombre de jetons d'entrée mis en cache comme gen_ai.usage.cache_read.input_tokens et le jeton de sortie de raisonnement compte comme gen_ai.usage.reasoning.output_tokens lorsque les détails d'utilisation sont disponibles. (#19906)
  • Étendre l'instrumentation de l'agent Java Couchbase pour prendre en charge SDK 3.0.x. (#19996)
  • Ajoutez l'attribut span aws.bedrock.guardrail.id aux requêtes AWS Bedrock Runtime lorsqu'un identifiant de garde-corps est configuré. (#20040)
  • Activez la détection des ressources host.id pour l'agent Java avec otel.resource.providers.host-id.enabled=true. (#20099)
  • Ajoutez des URL de schéma de conventions sémantiques sensibles au mode aux étendues de base de données, de messagerie et de télémétrie RPC. (#20127)
  • Ajoutez l'URL du schéma des conventions sémantiques aux métriques d'exécution JVM couvertes par le schéma. (#20255)
  • Les étendues d'opération GraphQL utilisent désormais l'URL de schéma des conventions sémantiques OpenTelemetry v1.44.0. (#20262)
  • Ajoutez l'URL du schéma des conventions sémantiques aux métriques du système OSHI. (#20263)

🛠️ Corrections de bugs

  • Les étendues de laitue 5.1 client pour les échecs de commande Redis ont désormais un statut d'erreur. (#19075)
  • Empêche les blocages de démarrage de Javaagent causés par une initialisation paresseuse du stockage de contexte sous les verrous du chargeur de classe. (#19265)
  • Correction des noms d'étendue de règlement NATS JetStream à haute cardinalité. Utilisez $JS.ACK publish selon les conventions sémantiques héritées. (#19396)
  • Correction de la propagation du contexte pour les méthodes Kotlin @WithSpan déléguées par la queue afin que leurs étendues conservent le contexte d'appelant correct. (#19446)
  • Correction des envois asynchrones de Camel afin que les étendues de contexte se ferment sur le thread qui a démarré l'envoi. (#19503)
  • Correction du traçage Vert.x HTTP client lorsqu'une requête est vidée avec sendHead() et complétée plus tard avec end(), de sorte que l'étendue du serveur est associée à l'étendue client exportée. (#19547)
  • Gérez les chaînes de causes d'exception cyclic sans suspendre l'extraction d'erreurs entre les instrumentations ou l'analyse des règles JMX. (#19625)
  • Désinfectez les corps de requête de recherche d'agent Java REST Elasticsearch capturés par défaut, en remplaçant les valeurs littérales par ? tout en préservant la structure de la requête. Désactivez la désinfection avec otel.instrumentation.elasticsearch.query-sanitization.enabled=false. (#19675)
  • Empêchez les instruments d'écoute Pulsar en double et supprimez les plages de réception en double lors des livraisons imbriquées, en préservant le contexte parent pour le traitement des plages. (#19699, #20137)
  • Les requêtes pipelined Apache HttpAsyncClient produisent désormais des étendues client. (#19710)
  • Les requêtes du serveur Async Thrift suite à un échec de requête sur la même connexion ne sont plus signalées à tort comme des erreurs. (#19712)
  • Supprimez les métriques Apache Commons Pool en double pour les pools prenant en charge un Apache DBCP BasicDataSource lorsque les deux instrumentations sont activées. (#19721)
  • Correction de la journalisation du débogage du démarreur Spring Boot lorsque otel.spring-starter.debug=true. (#19725, #20034)
  • Correction des étendues de traitement et des métriques en double dans Spring Rabbit, RabbitMQ et Spring Integration, en préservant la télémétrie pour les consommateurs enregistrés séparément et les étendues de gestionnaire correctement parentales. (#19732, #20138, #20200)
  • Les métriques de pool Oracle UCP utilisent désormais un nom dérivé de JDBC au lieu du nom UCP généré, consolidant les pools connectés à la même base de données sous une valeur pool.name cohérente. (#19745)
  • Renseignez les noms de commande Redis pour les étendues client lors de l'utilisation de Lettuce 6.0.0–6.0.2. (#19763)
  • Correction de la gestion de @SpanAttribute afin que les valeurs génériques et les tableaux soient correctement enregistrés en tant qu'attributs span. (#19785)
  • Évitez les NullPointerExceptions lors de la fin des requêtes Jedis partiellement initialisées ou lorsque JSF ne peut pas dériver un nom d'étendue de serveur. (#19805)
  • Correction de l'instrumentation du chargeur de classe afin que javaagent n'injecte plus son stub java.lang.ClassLoader réécrit en tant qu'assistant. (#19811)
  • Les requêtes du serveur Pekko HTTP/2 sont désormais tracées. (#19817)
  • Gérer les indices de choix négatifs dans les complétions de chat en streaming OpenAI. (#19827)
  • Les requêtes HTTP Pekko rejetées lors de l'analyse produisent désormais des étendues de serveur avec leur statut de réponse et des en-têtes de réponse personnalisés. (#19829)
  • Les délais d'achèvement du chat OpenAI utilisent désormais le type de délai CLIENT. (#19858)
  • Correction des délais de consommation de messages RocketMQ manquants pour une surcharge supplémentaire du constructeur ConsumeService. (#19860)
  • Correction de la propagation du contexte pour les tâches par lots Pekko afin que les étendues créées dans les futurs planifiés conservent leur bon parent. (#19862)
  • Limiter les corps de requête OpenSearch capturés à 32 768 caractères, ce qui correspond à la limite de capture de requête Elasticsearch. (#19870)
  • La capture du corps de requête OpenSearch utilise désormais le fournisseur JSON configuré, préservant les paramètres de sérialisation spécifiques au mappeur. (#19875)
  • L'instrumentation du serveur Thrift ignore les champs de propagation de contexte répétés après le démarrage de la durée de la requête. (#19895)
  • Correction d'une course dans la capture de la version du protocole Ratpack afin que les spans enregistrent la version correcte du protocole. (#19911)
  • L'instrumentation AWS Lambda extrait désormais l'en-tête de trace X-Ray de Context.getXrayTraceId() pour poursuivre la trace entrante. (#19920)
  • Correction d'une fuite de portée contextuelle dans le traitement des requêtes du serveur Thrift. (#19925)
  • Autoriser l'agent Java à traiter la classe org.h2.command.dml.Update$$Lambda de H2. (#19993)
  • L'agent Java démarre désormais lorsque son JAR est déjà sur le chemin de classe d'amorçage sans ajouter à nouveau le JAR pour amorcer la recherche. (#20001)
  • Le JDBC OpenTelemetryDriver honore désormais otel.instrumentation.jdbc.query-sanitization.enabled, de sorte que la vérification des requêtes spécifiques à JDBC peut remplacer le paramètre commun. (#20020)
  • Corrigez les durées inexactes des délais d'interception des producteurs et des consommateurs Kafka en y mettant fin immédiatement, car les intercepteurs ne peuvent pas mesurer le temps d'envoi ou d'interrogation du courtier. (#20044)
  • Les étendues de requêtes Vert.x SQL client 5 signalent désormais db.name, server.address et server.port pour les connexions configurées avec les fournisseurs connectingTo. (#20050)
  • Conservez l'agent Java et les personnalisateurs de configuration déclarative Spring Boot fonctionnant avec OpenTelemetry SDK 1.66.0. (#20109)
  • Empêcher la troncature de la base de données nettoyée et les requêtes de recherche de diviser les paires de substitution Unicode. (#20123)
  • Empêchez les traitements Kafka en double sur Kafka Connect, Kafka Streams, Reactor Kafka et Vert.x, y compris les transferts asynchrones, sans supprimer les lots non liés. (#20139, #20142, #20143)
  • Évitez les traitements JMS en double sur les couches d'écoute JMS, Spring JMS, Camel et SJMS. (#20140)
  • L'instrumentation du serveur Apache ShenYu ne lance plus lorsque les métadonnées de route sont nulles, permettant au traitement des requêtes de continuer sans valeur de route. (#20148)
  • Enregistrez les exceptions gérées par les gestionnaires d'erreurs Spring Rabbit sur l'étendue de traitement des messages. (#20178)
  • Correction de la détection du système de base de données pour les pools Vert.x SQL client encapsulés par Vert.x 5.2. (#20191)
  • L'instrumentation Reactor propage désormais les valeurs de contexte via des rappels d'éditeur pilotés en externe, même lorsque le contexte capturé n'a pas d'étendue valide. (#20192)
  • Les délais de traitement Spring Cloud AWS SQS se terminent désormais lorsque les écouteurs asynchrones sont terminés, enregistrant leurs éventuels échecs ou leur statut d'annulation. (#20193)
  • Les délais de traitement SQS AWS SDK v1 se terminent désormais par des échecs de rappel et restaurent le contexte précédent lorsque les gestionnaires forEach ou forEachRemaining sont lancés. (#20194)
  • Empêchez les périodes de traitement SQS en double lorsque les gestionnaires AWS Lambda imbriqués traitent le même événement. (#20195)
  • Les étendues de serveur Spring MVC pour les points de terminaison de l'actionneur Spring Boot incluent désormais l'attribut http.route. (#20216)
  • Correction des indices de réflexion manquants pour les champs d'intercepteur d'écoute Spring Kafka et les classes JWT du porteur OAuth dans les images natives GraalVM. (#20332)
