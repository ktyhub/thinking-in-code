opentelemetry-java-instrumentation v2.29.0

Mineure Publié19 juin 2026 Sourceopen-telemetry/opentelemetry-java-instrumentation Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

opentelemetry-java-instrumentation v2.29.0

Cette version cible le OpenTelemetry SDK 1.63.0.

Notez que de nombreux artefacts ont le suffixe -alpha attaché à leur numéro de version, ce qui indique qu'ils continueront à subir des modifications importantes. Veuillez consulter VERSIONING.md pour plus de détails.

⚠️ Modifications interrompues apportées aux API non stables

  • Modifiez le type de retour pour les JmxTelemetry.start(...) API. (#18782)
  • La télémétrie du package d'exécution expérimental émet désormais des valeurs package.checksum_algorithm=SHA-256 et package.checksum à 64 caractères au lieu des sommes de contrôle SHA1. (#18846)

🚫 Dépréciations

  • Renommez les clés contextuelles de journalisation communes en otel.instrumentation.common.logging.trace-id-key, otel.instrumentation.common.logging.span-id-key et otel.instrumentation.common.logging.trace-flags-key, tout en conservant les anciens noms de propriété obsolètes. (#18851)
  • Renommez les systèmes cibles JMX kafka-broker et kafka-connect en experimental-kafka-broker et experimental-kafka-connect ; les anciens noms fonctionnent toujours pour le moment et enregistrent un avertissement. (#18971)

🌟 Nouvelle instrumentation javaagent

  • Ajoutez l'instrumentation SOFARPC 5.4 qui émet le RPC client ainsi que les étendues et métriques du serveur. (#15589)
  • Ajoutez l'instrumentation Javaagent pour HBase client 2.0.0 à 2.5.0. (#18253)

📈 Améliorations

  • Ajoutez la prise en charge opt-in pour l'émission d'exceptions de requête HTTP en tant que signaux de journal avec otel.semconv.exception.signal.preview=logs. (#16259)
  • Ajoutez l'instrumentation Javaagent opentelemetry-api-1.63 pour OpenTelemetry API 1.63 et opentelemetry-api-incubator 1.63. (#18911)
  • Ajoutez otel.semconv-stability.v3-preview comme solution de secours pour le paramètre de stabilité déclaratif v3_preview semconv. (#18936)
  • Mettre à jour l'opt-in de convention sémantique de base de données expérimentale stable (otel.semconv-stability.opt-in=database) sur les instruments de base de données, y compris les noms d'étendue et les attributs db.*. (#18808, #18853, #18920, #18922, #18926, #18930, #18970, #18979, #18980, #18984, #18985, #18986, #18987, #18989, #18990, #18992, #18993, #19004, #19005)
  • Capturez le texte de la requête et le paramétrage des instructions batch Cassandra. (#18964)
  • Gardez opentelemetry-api et opentelemetry-instrumentation-annotations activés sous otel.instrumentation.common.v3-preview même lorsque default-enabled=false. (#18792)
  • Lorsque otel.instrumentation.common.v3-preview est activé, les instrumentations concernées émettent des attributs d'identité user.* au lieu de ceux enduser.*. (#18795)
  • Désactivez les métriques Kafka client par défaut lorsque otel.instrumentation.common.v3-preview=true. (#18828)
  • Reconnaître les préfixes d'URL JDBC du wrapper Amazon Aurora DSQL et AWS lors de l'analyse des métadonnées de connexion JDBC. (#18831)
  • Définir les versions d'instrumentation sur les oscilloscopes de compteur émis. (#18866)
  • Exécutez l'instrumentation @WithSpan après d'autres instrumentations afin que d'autres conseils puissent attacher des attributs à la travée active. (#18874)
  • Émettre des échecs de la base de données client sous forme de journaux db.client.operation.exception lorsque otel.semconv.exception.signal.preview est activé. (#18889)
  • Émettre des exceptions RPC sous forme d'enregistrements de journal lorsque otel.semconv.exception.signal.preview=logs est activé. (#18890)
  • Émettez des exceptions de messagerie sous forme d'enregistrements de journal sous otel.semconv.exception.signal.preview. (#18891)
  • Émettez des enregistrements de journal faas.invocation.exception pour les exceptions FaaS lorsque otel.semconv.exception.signal.preview=logs est activé. (#18892)
  • Émettez des journaux gen_ai.client.operation.exception pour les échecs de discussion et d'intégration OpenAI lorsque otel.semconv.exception.signal.preview=logs est activé. (#18893)
  • Émettre des échecs de requête AWS SDK sous forme d'enregistrements de journal rpc.client.call.exception lorsque otel.semconv.exception.signal.preview=logs est activé. (#18894)
  • La configuration déclarative prend désormais en charge la sélection de conventions sémantiques par domaine à l'aide des paramètres semconv.version, semconv.experimental et semconv.dual_emit. (#18908)
  • Lorsque otel.instrumentation.common.v3-preview est activé, utilisez otel.semconv-stability.preview au lieu de otel.semconv-stability.opt-in pour adhérer aux conventions sémantiques non stables service.peer et rpc. (#18914)
  • Désactivez l'instrumentation des coroutines Kotlin @WithSpan par défaut lorsque otel.instrumentation.common.v3-preview=true. (#18919)
  • Utilisez le chemin d'accès récapitulatif dans SqlQueryAnalyzer.analyze() lorsque otel.instrumentation.common.v3-preview est activé. (#18921)
  • Lorsque otel.instrumentation.common.v3-preview est activé, les noms de configuration de nettoyage JDBC/db obsolètes sont ignorés au profit de db.query_sanitization.enabled. (#18934)
  • Incluez jvm.gc.cause dans les métriques de durée GC lorsque otel.instrumentation.common.v3-preview est activé. (#18967)
  • Émettre des métriques de durée pour les opérations de transaction JDBC COMMIT et ROLLBACK. (#19003)
  • Utilisez une classe InstrumentationVersion générée dans OkHttp 3.0 au lieu de lire les propriétés de la version intégrée, évitant ainsi les violations de lecture de disque Android StrictMode. (#19006)
  • Ajoutez des attributs d'étendue de détails de thread pour la configuration déclarative du démarreur Spring lorsque distribution.spring_starter.thread_details_enabled est défini. (#19008)

🛠️ Corrections de bugs

  • Préserver le contexte actuel pour les futures exécutions de commandes Redisson afin que les opérations asynchrones continuent la trace active. (#18701)
  • Empêchez l'agent Pulsar de créer des intervalles de réception en double pour les consommateurs multi-sujets. (#18771)
  • Correction d'un blocage dans les requêtes de streaming Ktor client afin que les plages se terminent rapidement avec Ktor 3.5.0. (#18781)
  • Correction d'un Bedrock converseStream NullPointerException lorsqu'un appel d'outil a des arguments vides. (#18783)
  • Capturez l'ID du message Pulsar plus tôt afin que les intervalles de production puissent l'enregistrer de manière fiable. (#18803)
  • Correction de l'instruction SQLite JDBC et de l'instrumentation des instructions préparées afin que les connexions SQLite produisent des étendues SQL et une capture de paramètres. (#18885)
  • Correction des clés de configuration déclaratives Logback MDC afin que les paramètres otel.instrumentation/development.java.* s'appliquent correctement. (#18924)
  • Correction de la désinfection des mots de passe SQL pour les cibles DDL à casse mixte comme create table et alter table. (#18927)
  • Les journaux émis via les enregistreurs asynchrones Log4j conservent désormais le OpenTelemetry Context du thread d'application au lieu de revenir à la récupération en span uniquement. (#18937)
  • Évitez les erreurs d'instrumentation lors du chargement de redis.clients.jedis.Jedis, BinaryJedis et UnifiedJedis. (#19000)
  • Exécutez les rappels asynchrones OpenSearch avec le contexte parent de la requête. (#19027)
