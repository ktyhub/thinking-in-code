opentelemetry-java-instrumentation v2.31.0

Mineure Publié20 août 2026 Sourceopen-telemetry/opentelemetry-java-instrumentation Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

opentelemetry-java-instrumentation v2.31.0

Cette version cible le OpenTelemetry SDK 1.65.0.

Notez que de nombreux artefacts ont le suffixe -alpha attaché à leur numéro de version, ce qui indique qu'ils continueront à subir des modifications importantes. Veuillez consulter VERSIONING.md pour plus de détails.

⚠️ Modifications interrompues apportées aux API non stables

  • Supprimez le ConfigPropertiesBackedConfigProvider obsolète et sa compatibilité create(ConfigProperties) API du pont de configuration déclaratif. (#19305)
  • Arrêtez d'exposer opentelemetry-instrumentation-api-incubator sur les chemins de classe de compilation d'instrumentation de bibliothèque. (#19612)

🚫 Dépréciations

  • Déprécier otel.instrumentation.experimental.span-suppression-strategy au profit de Experimental.setSpanSuppressionStrategy(...). (#19180)
  • Déprécier HostIdResource.REGISTRY_QUERY en faveur de la recherche de chemin absolu reg.exe utilisée par HostIdResource. (#19293)
  • Déprécier MessageOperation au profit de MessagingOperationType, et les surcharges MessageOperation de MessagingAttributesExtractor, MessagingConsumerMetrics, MessagingProducerMetrics, MessagingSpanKindExtractor et MessagingSpanNameExtractor au profit des MessagingOperationType API correspondants. (#19357)
  • Déprécier otel.traces.exporter=zipkin au profit de otel.traces.exporter=otlp, et otel.exporter.zipkin.endpoint au profit de otel.exporter.otlp.traces.endpoint. (#19400)
  • Déprécier OpenTelemetryMeterRegistryBuilder#setMicrometerHistogramGaugesEnabled(boolean) au profit de Experimental#setMicrometerHistogramGaugesEnabled(OpenTelemetryMeterRegistryBuilder, boolean). (#19404)
  • Déprécier les anciennes métadonnées gRPC, l'en-tête de messagerie et les propriétés de capture des paramètres de requête de servlet et les API au profit de la configuration .included / .excluded basée sur un sélecteur et des IncludeExclude API. (#19494, #19522, #19523, #19638)
  • Déprécier otel.instrumentation.runtime-telemetry.experimental.prefer-jfr au profit de otel.instrumentation.runtime-telemetry.experimental.jfr-metrics.included, et setPreferJfrMetrics(...) au profit de setJfrMetrics(RuntimeTelemetryBuilder, IncludeExclude). (#19495)
  • Déprécier la configuration booléenne et de liste de capture pour les données MDC/contexte, les messages de carte, les paires clé-valeur, le contexte de l'enregistreur, les marqueurs Logstash et les arguments structurés en faveur des sélecteurs .included / .excluded et IncludeExclude API. (#19519, #19520, #19521, #19599, #19600, #19605, #19609, #19610)
  • Déprécier le champ de configuration déclaratif general.semconv_stability.opt_in au profit de general.stability_opt_in_list, et general.sanitization.url.sensitive_query_parameters/development au profit de general.sanitization.url.sensitive_query_parameters. (#19561)
  • Déprécier otel.instrumentation.graphql.add-operation-name-to-span-name.enabled au profit de otel.instrumentation.graphql.operation-name-in-span-name.enabled, et otel.instrumentation.runtime-telemetry.package-emitter.enabled / jars-per-second au profit de otel.instrumentation.runtime-telemetry.experimental.package-emitter.enabled / jars-per-second. (#19573)
  • Déprécier les méthodes de création d'en-têtes de requête et de réponse capturées dans les instrumentations de la bibliothèque HTTP en faveur des requestHeaders(IncludeExclude) et responseHeaders(IncludeExclude) API basés sur des sélecteurs. (#19598, #19601, #19602, #19603, #19604, #19606, #19607, #19608)
  • Déprécier otel.instrumentation.micrometer.histogram-gauges.enabled au profit de otel.instrumentation.micrometer.experimental.histogram-gauges.enabled. (#19613)

🌟 Nouvelle instrumentation javaagent

  • Ajoutez l'instrumentation Apache Commons Pool 2 pour les métriques du pool d'objets. (#19091) -Ajouter l'instrumentation javaagent Apache HBase client 1.0. (#19243)
  • Ajoutez les métriques du pool de connexions Redisson pour 3.26+. (#19392)
  • Ajout de la prise en charge des métriques de l'incubateur OpenTelemetry API 1.65 dans l'agent Java. (#19456)
  • Ajoutez l'instrumentation javaagent Tomcat DBCP 8.0 pour les métriques du pool de bases de données. (#19472)

📈 Améliorations

  • Ajoutez des métadonnées opt-in du bundle OSGi pour les artefacts d'instrumentation sélectionnés, d'extension API et SDK afin qu'ils puissent être consommés directement dans les environnements d'exécution OSGi. (#18995)
  • Ajoutez les jauges cassandra.compaction.progress.completed et cassandra.compaction.progress.size pour les compactages Cassandra en vol. (#19290)
  • Prévisualisez les prochaines conventions sémantiques de messagerie 3.0 derrière otel.semconv-stability.opt-in=messaging dans AWS SQS et Lambda, JMS, Kafka, NATS, Pulsar, RabbitMQ, RocketMQ, Spring Integration et les instruments de messagerie Spring. (#19347, #19348, #19349, #19350, #19351, #19353, #19354, #19355, #19356, #19476, #19477, #19478, #19479, #19480, #19481, #19482, #19486, #19487, #19499, #19500, #19504, #19505, #19507, #19508, #19535, #19544, #19565, #19567, #19639, #19640)
  • Dans le cadre des prochaines conventions sémantiques RPC 3.0 derrière otel.semconv-stability.opt-in=rpc, les requêtes Dubbo adressées à des services inconnus émettent des étendues de serveur même lorsque le décodage échoue avant DubboProtocol.getInvoker() et enregistrent la méthode d'origine dans rpc.method_original. (#16668)
  • Les données contextuelles Log4j incluent désormais les entrées baggage.* même lorsqu'il n'y a pas de span actuel. (#19378)
  • Lorsque otel.instrumentation.common.v3-preview=true, le pont Micromètre n'exporte plus les jauges .max pour Timer et DistributionSummary. (#19397)
  • Ajoutez le sélecteur IncludeExclude API à opentelemetry-instrumentation-api pour faire correspondre les chaînes aux modèles globaux inclus et exclus. (#19451)
  • Émet les attributs de cohérence, de coordinateur, de taille de page, d'idempotence et d'exécution spéculative du pilote Cassandra 3. (#19629)
  • Développez les prochaines conventions sémantiques de la base de données 3.0 derrière otel.semconv-stability.opt-in=database, y compris les noms d'opérations, les espaces de noms, les noms de collections, les paramètres d'opération, la télémétrie par lots et les types d'erreurs pour Couchbase, Redis clients, Elasticsearch, R2DBC, JDBC, ClickHouse, MongoDB et HBase. (#19616, #19623, #19664, #19665, #19668, #19670, #19704, #19705, #19706, #19707, #19708)
  • Ajoutez otel.instrumentation.influxdb.query-sanitization.enabled pour contrôler la désinfection des requêtes InfluxDB, en prenant priorité sur otel.instrumentation.common.db.query-sanitization.enabled. (#19703)

🛠️ Corrections de bugs

  • Utilisez des noms de métriques stables dérivés de la base de données pour les pools de connexions sans nom Alibaba Druid, c3p0, Tomcat JDBC, HikariCP et Vibur. (#19108, #19159, #19173, #19470, #19471)
  • Les métriques Apache DBCP 2.0 s'enregistrent désormais lorsque le pool démarre même sans enregistrement JMX, et elles se désenregistrent sur close(). (#19160)
  • Ignorer les outils JDK d'instrumentation lancés à partir de $JAVA_HOME/bin à moins que otel.javaagent.enabled=true ne soit défini. (#19203)
  • Correction des métriques Jetty JMX pour émettre jetty.select.count au lieu de jetty.io.select.count pour le nombre d'appels sélectionnés. (#19249)
  • Correction du pool de connexions Redisson qui permet une fuite lorsqu'une commande asynchrone en attente est annulée. (#19340)
  • Correction de la détection de route Spring WebFlux afin que les étendues de contrôleur conservent un nom de route lisible sur JDK 21+. (#19365)
  • Normalisez les valeurs IPv6 JDBC server.address en adresses nues au lieu de littéraux entre crochets. (#19366)
  • Correction de l'instrumentation Lettuce 5.1 avec indy en injectant io.lettuce.core.protocol.OtelCommandArgsUtil comme classe d'assistance. (#19373)
  • Ajoutez un délai d'attente de 2 secondes à la détection des ressources du host.id afin que les commandes de recherche lentes ne bloquent plus le démarrage du SDK. (#19377)
  • Correction de l'instrumentation Azure-Core afin que les applications qui n'utilisent pas le OpenTelemetry API obtiennent toujours le traçage Azure SDK. (#19387)
  • L'analyse d'URL JDBC MySQL gère désormais de manière plus fiable les hôtes, les ports et les paramètres de requête dans les formulaires d'URL non standard. (#19394)
  • Préchargez MethodHandle$1 lors du démarrage de l'agent pour éviter ClassCircularityError sur JDK 17 qui peut interrompre la liaison du site d'appel dynamique. (#19398)
  • Rédigez les données sensibles des paramètres de requête AWS SigV4, de la passerelle AWS Lambda API et des URL REST Elasticsearch, des informations d'identification d'URL intégrées et des lignes de commande de processus. (#19422, #19424, #19425, #19514)
  • Corrigez la dénomination des compteurs personnalisés Micrometer et empêchez les descriptions de métriques de fuir entre des instruments ou des registres associés. (#19463, #19466, #19467)
  • Correction de activemq.destination.temp.utilization pour convertir les valeurs % en fraction sans unité. (#19512)
  • Correction de jetty.thread.queue.size pour utiliser l'unité {job} au lieu de {thread}. (#19513)
  • Correction des points de terminaison des métriques de l'actionneur Spring Boot lorsque le registre du micromètre OpenTelemetry fait partie d'un registre composite ou ne peut pas renvoyer de valeurs métriques. (#19515, #19541)
  • Les adresses IPv6 dans les en-têtes Host sont désormais analysées correctement, y compris les ports entre crochets. (#19540)
  • Correction des étendues de réception Pulsar selon les conventions sémantiques de messagerie héritées pour évaluer la suppression par rapport au contexte du producteur extrait lorsque la télémétrie de réception est désactivée. (#19592)
  • Préservez le type ClusterInvoker de Dubbo lors de la capture de l'adresse du registre des consommateurs. (#19568)
  • Arrêtez l'avertissement concernant les paramètres de capture obsolètes basés sur un sélecteur lorsque le remplacement .included ou .excluded correspondant est également configuré. (#19571)
  • Conservez la casse d'origine du nom de la base de données configurée dans l'ancien db.name et le stable db.namespace pour les étendues R2DBC. (#19615)
  • Capturez les étendues pour les requêtes préparées explicites dans Vert.x SQL client afin que l'exécution de PreparedStatement.query() conserve le db.system et les options de connexion corrects. (#19619)
  • Correction de la désinfection de Cassandra 3 SimpleStatement afin que les valeurs liées soient détectées et masquées dans db.statement. (#19620)
  • Émettre des événements d'exception et des journaux pour les opérations JDBC commit et rollback ayant échoué. (#19621)
  • Effacer l'état de télémétrie par lots JDBC après executeBatch() et executeLargeBatch() afin que les périodes de lots suivantes ne signalent plus le contenu des lots obsolètes. (#19622)
  • Conservez server.address et server.port pour les opérations Cassandra 3 ayant échoué en extrayant le coordinateur de CoordinatorException. (#19627)
  • Le texte de la requête SQL est désormais nettoyé avec db.system.name, de sorte que les identifiants entre guillemets restent intacts pour les bases de données qui les traitent comme des identifiants. (#19632)
  • Correction de l'instrumentation AWS Lambda RequestHandler afin que les méthodes handleRequest renvoyant void soient gérées correctement. (#19714)
