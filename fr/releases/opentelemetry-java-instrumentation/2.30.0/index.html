opentelemetry-java-instrumentation v2.30.0

Mineure Publié22 juil. 2026 Sourceopen-telemetry/opentelemetry-java-instrumentation Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

opentelemetry-java-instrumentation v2.30.0

Cette version cible le OpenTelemetry SDK 1.64.0.

Notez que de nombreux artefacts ont le suffixe -alpha attaché à leur numéro de version, ce qui indique qu'ils continueront à subir des modifications importantes. Veuillez consulter VERSIONING.md pour plus de détails.

⚠️ Modifications interrompues apportées aux API non stables

  • Supprimez ExperimentalInstrumentationModule#getModuleGroup(). Les modules d'invocation dynamique intégrés partagent désormais un seul InstrumentationModuleClassLoader, et chaque extension est isolée dans la sienne. (#18859)
  • Supprimez le InstrumentationModule.isIndyModule() obsolète ; si un module utilise Invokedynamic est désormais déterminé par l'agent plutôt que déclaré par module. (#19140)
  • Supprimez les API obsolètes liés aux requêtes de SqlClientAttributesGetter, CassandraRequest et Experimental. (#19165)
  • Supprimez les API obsolètes de capture d'attributs Enduser* de la bibliothèque Spring Security 6.0 ; utilisez plutôt les remplacements User*. (#19168)

🚫 Dépréciations

  • Déprécier uniquement le bean de compatibilité starter Spring Boot ConfigProperties utilisé avec une configuration déclarative expérimentale, au profit du nouveau bean ConfigProvider ; il sera supprimé dans 3.0. Le bean ConfigProperties reste pris en charge pour la configuration non déclarative. (#19175)
  • Déprécier DeclarativeConfigPropertiesBridge et DeclarativeConfigPropertiesBridgeBuilder. Utilisez DeclarativeConfigProperties directement ou DeclarativeConfigBridge à la place. Sera supprimé dans 3.0. (#19202)
  • Déprécier ConfigPropertiesBackedConfigProvider au profit de DeclarativeConfigBridge. Il sera supprimé dans 2.31.0. (#19220)

🌟 Nouvelle instrumentation javaagent

  • Ajouter l'instrumentation Javaagent pour HBase client 1.4. (#19087)

🌟 Nouvelle instrumentation de la bibliothèque

  • Ajout d'une instrumentation de bibliothèque (ThriftTelemetry) pour le serveur asynchrone Apache Thrift 0.13. (#19062)

📈 Améliorations

  • Ajouter le traçage du serveur asynchrone à l'instrumentation javaagent Apache Thrift 0.13 ; Les gestionnaires de serveurs asynchrones n'étaient auparavant pas instrumentés. (#18994)
  • Prise en charge de database= comme alias pour databaseName lors de l'extraction de db.name à partir d'URL MSSQL JDBC. (#19029)
  • Ajoutez la prise en charge des opérations par lots à l'opt-in de convention sémantique de base de données stable expérimentale (otel.semconv-stability.opt-in=database) dans les instruments de base de données, y compris les noms d'étendue de lots, db.operation.batch.size (y compris les lots vides) et db.query.summary. (#19034, #19037, #19054, #19055, #19056, #19057, #19143, #19147, #19161, #19162, #19164, #19172, #19189, #19199)
  • Ajout d'un traçage pour les commandes réactives Lettuce 4.0, y compris l'achèvement et l'annulation exceptionnels. (#19071)
  • Ajout du système cible expérimental de métriques Cassandra JMX. (#19080)
  • Ajoutez des métriques expérimentales jvm.thread.virtual.pinned et jvm.thread.virtual.submit_failed basées sur JFR pour les threads virtuels Java 19+ ; activer avec otel.instrumentation.runtime-telemetry.emit-experimental-jfr-metrics=true. (#19092)
  • Capturez les valeurs d'objet personnalisées transmises à PreparedStatement.setObject() dans les attributs des paramètres de requête. (#19093)
  • InstrumentationModule expose désormais injectedClassNames() et exposedClassNames() pour les instrumentations indépendantes, donc les auteurs de modules n'ont plus besoin de ExperimentalInstrumentationModule pour ces déclarations de classes d'assistance. (#19142)
  • Ajoutez les options captureTemplate et captureArguments aux instrumentations de journalisation log4j, java-util-logging et jboss-logmanager, en capturant le modèle de message de journal et les arguments en tant qu'attributs log.body.template / log.body.parameters distincts ; logback prenait déjà en charge ces options (#15423). (#19154)
  • Ajoutez les attributs server.address et server.port aux travées Redisson client. (#19191)
  • Ajoutez les attributs server.address et server.port aux travées Lettuce Redis client. (#19192)
  • Ajoutez les attributs server.address et server.port aux travées Rediscala client. (#19193)
  • Définissez server.address sur Dubbo client basé sur le registre et s'étend sur l'adresse de registre plus la cible du service (registry://host:port/interface:version:group) et laissez server.port non défini, protégé par l'opt-in rpc semconv stable (otel.semconv-stability.opt-in=rpc) ; l'hôte et le port du fournisseur résolus sont conservés sous le semconv par défaut. (#17244, #19285)

🛠️ Corrections de bugs

  • Correction d'un faux avertissement en double lorsque le pont de l'enregistreur d'application est installé plusieurs fois au démarrage. (#19088)
  • Correction des valeurs MySQL et MariaDB db.connection_string afin que les hôtes IPv6 restent entre crochets au lieu de devenir ambigus. (#19078)
  • Correction des consommateurs Pulsar multi-sujets afin que la réception en arrière-plan interne ne crée plus une période de réception supplémentaire parasite. (#19095)
  • SpringConfigProperties.getMap() n'évalue plus les valeurs des propriétés de carte en tant qu'expressions SpEL ; Les propriétés de carte sans casse particulière sont désormais analysées sous forme de paires key=value délimitées par des virgules via le DefaultConfigProperties du SDK, de sorte que des paramètres tels que otel.instrumentation.common.peer-service-mapping fonctionnent sans syntaxe SpEL. (#19113)
  • Correction de l'extraction de destination JMS afin qu'une destination illisible laisse désormais messaging.destination.name non défini au lieu de la signaler comme unknown. (#19115)
  • Correction des métriques JMX Metric Insight jvm.class.loaded et jvm.class.unloaded pour utiliser des instruments de comptage. (#19141)
