opentelemetry-java-instrumentation v2.28.0

Mineure Publié19 mai 2026 Sourceopen-telemetry/opentelemetry-java-instrumentation Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

opentelemetry-java-instrumentation v2.28.0

Cette version cible le OpenTelemetry SDK 1.62.0.

Notez que de nombreux artefacts ont le suffixe -alpha attaché à leur numéro de version, ce qui indique qu'ils continueront à subir des modifications importantes. Veuillez consulter VERSIONING.md pour plus de détails.

⚠️ Modifications interrompues apportées aux API non stables

  • Suppression du ClassInjector/ProxyInjectionBuilder interne obsolète API utilisé par l'ancien chemin ExperimentalInstrumentationModule.injectClasses(ClassInjector) ; utilisez plutôt ExperimentalInstrumentationModule.exposedClassNames(). (#18112)
  • Suppression des méthodes API non stables précédemment obsolètes et des alias de bibliothèque opentelemetry-runtime-telemetry-java8 et opentelemetry-runtime-telemetry-java17 obsolètes. (#18136)
  • Suppression du paramètre de générateur de bibliothèque captureEventName précédemment obsolète de logback-appender-1.0 et log4j-appender-2.17 OpenTelemetryAppender, ainsi que des propriétés javaagent otel.instrumentation.{logback-appender,log4j-appender,jboss-logmanager}.experimental.capture-event-name correspondantes. Utilisez plutôt la clé otel.event.name dans MDC / données contextuelles / paires clé-valeur / marqueurs Logstash / arguments structurés. (#18223)
  • Removed previously deprecated experimental config properties otel.instrumentation.http.client.experimental.redact-query-parameters and otel.instrumentation.common.experimental.db-sqlcommenter.enabled; utilisez plutôt otel.instrumentation.sanitization.url.experimental.sensitive-query-parameters et otel.instrumentation.common.db.experimental.sqlcommenter.enabled. (#18229)
  • Suppression de la propriété obsolète otel.instrumentation.servlet.experimental.add-trace-id-request-attribute ; utilisez plutôt otel.instrumentation.servlet.experimental.trace-id-request-attribute.enabled. (#18237)
  • Remodelage de l'assistant ktor Experimental d'une classe avec un companion object à un object de haut niveau. Kotlin source callers (Experimental.emitExperimentalTelemetry(...)) are unaffected, but pre-compiled consumers must be recompiled against the new artifact. (#18343)

🚫 Dépréciations

  • Deprecate otel.instrumentation.jaxws-cxf-3.0.enabled in favor of otel.instrumentation.jaxws-2.0-cxf-3.0.enabled, and otel.instrumentation.jaxws-metro-2.2.enabled in favor of otel.instrumentation.jaxws-2.0-metro-2.2.enabled. (#18184)

🌟 Nouvelle instrumentation javaagent

  • Ajoutez l'instrumentation Apache Thrift 0.13 pour RPC client ainsi que les étendues et métriques du serveur. (#18405)

🌟 Nouvelle instrumentation de la bibliothèque

  • Add Apache Thrift 0.13 library instrumentation for RPC client and server spans and metrics. (#18405)

📈 Améliorations

  • L'instrumentation javaagent Couchbase 3.1 émet désormais le nom de portée d'instrumentation plus conventionnel io.opentelemetry.couchbase-3.1 au lieu de io.opentelemetry.javaagent.couchbase-3.1 lorsque otel.instrumentation.common.v3-preview est activé. (#18426)
  • Les demandes de ressources Wicket utilisent désormais le nom de la classe de référence de ressources dans le nom de l'étendue du serveur lorsque otel.instrumentation.common.v3-preview est activé. (#18312, #18775)
  • Décidez si les classes d'assistance Javaagent sont injectées dans le chargeur de classes d'application ou isolées en fonction des classes de conseils utilisées par une instrumentation. (#17815)
  • Améliorez la détection des ID de conteneur Cgroup v2 pour Podman en prenant en charge des mises en page mountinfo supplémentaires et en avertissant lorsque plusieurs ID candidats sont trouvés. (#18272)

🛠️ Corrections de bugs

  • Correction du suivi de l'itinéraire du serveur Pekko HTTP et Tapir afin que les noms d'étendue de serveur et http.route préservent l'itinéraire correspondant le plus spécifique à travers les directives imbriquées, les exceptions et les délais d'attente ; cela peut modifier les noms de travées et les valeurs http.route pour les itinéraires concernés. (#16390)
  • Correction de la perte de contexte dans l'instrumentation HTTP Finagle lors de la conversion de requête Netty vers Finagle et des limites asynchrones twitter-util Future/Promise. (#17867)
  • Fix virtual-thread pinning caused by weak-map stale-entry cleanup running on virtual threads; cleanup now runs from the background thread instead. (#18113)
  • Avoid linking batch consumer spans to the ambient consumer span when records or messages have no propagation headers. (#18154)
  • Correction de resetOnEachOperator() pour le Reactor 3.1 afin qu'il supprime également le hook du planificateur lorsque l'instrumentation est désactivée. (#18258)
  • Terminez les périodes lorsque les abonnements RxJava 1.0 sont lancés de manière synchrone. (#18265)
  • Correction de la détection automatique de la version du service Spring Boot afin que META-INF/build-info.properties soit lu à partir de la racine du fichier jar au lieu de BOOT-INF/classes/. (#18292)
  • Effacez le Netty VirtualField après avoir terminé une réponse dans l'instrumentation du serveur Netty 3.8. (#18358)
  • Correction de JarDetails pour fermer les handles JarFile lors de la lecture des archives et des fichiers jar intégrés, empêchant ainsi les fuites de ressources lors de la collecte de télémétrie d'exécution. (#18385)
  • Correction d'un NullPointerException lors de la conversion d'un contexte d'agent sans contexte d'application associé en contexte d'application. (#18444)
  • Correction de l'instrumentation du serveur Ktor pour éviter les fuites de contexte OpenTelemetry causées par une restauration incomplète du contexte de coroutine. (#18456)
  • Correction des attributs http.route du sous-routeur Vert.x en ajoutant le point de montage au chemin de route relatif ; cela peut modifier les noms d'étendue du serveur et les valeurs http.route pour les sous-routes montées. (#18462)
  • Correction du démarrage des métriques oshi et des rapports de mémoire RSS avec oshi 7.0.0. (#18478)
  • Correction de l'instrumentation Play MVC et Play WS sur les applications Play 3.x. (#18624)
  • Enregistrez une période de réception d'erreur lorsqu'un consommateur Kafka encapsulé poll() échoue. (#18625)
  • Correction du nettoyage des cartes faibles lors du démarrage de l'agent en démarrant WeakConcurrentMapCleaner avant l'installation de Byte Buddy. (#18628)
  • Correction de l'instrumentation Indy afin qu'elle fonctionne avec le gestionnaire de sécurité sans échecs d'amorçage récursifs. (#18634)
  • Évitez un blocage dans les caches faibles lorsque les entrées périmées sont supprimées pendant computeIfAbsent. (#18635)
  • Les personnalisateurs de configuration déclaratifs gèrent désormais les listes de processeurs et de détecteurs manquants sans lancer NullPointerException au démarrage. (#18641)
  • Correction d'une course qui pourrait empêcher les étendues de serveur HTTP de se terminer correctement dans les instrumentations Netty 3.8 et 4.0. (#18645)
  • Évitez NumberFormatException lorsqu'un port URL JDBC est nul. (#18708)
  • Correction de l'exécution des tâches Vert.x TaskQueue et OrderedExecutorFactory afin que le contexte span se propage aux exécutables en file d'attente. (#18709)
  • Limitez la longueur du texte de la requête par lots Redisson pour éviter les valeurs db.statement surdimensionnées pour les gros lots. (#18744)
  • Correction de la désinfection des requêtes SQL afin que les clauses de mot de passe dans les déclarations administratives SAP HANA soient supprimées sans supprimer les identifiants password. (#18754)
