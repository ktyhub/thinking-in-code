bookkeeper release-4.18.0

Version Publié10 juin 2026 Sourceapache/bookkeeper Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

version du comptable-4.18.0

La version 4.18.0 est une version de fonctionnalités majeures. Il introduit la journalisation structurée dans l'ensemble base de code (BP-69), migre la sérialisation du protocole filaire vers LightProto et les E/S natives bibliothèque à Rust, et élève la version Java minimale requise à 17. Elle comprend également de nombreux améliorations, corrections de bugs et mises à jour de dépendances/CVE.

Les utilisateurs d'Apache BookKeeper sont encouragés à passer à 4.18.0. Veuillez consulter le Modifications majeures et problèmes connus ci-dessous avant la mise à niveau.

Faits saillants

  • Journalisation structurée (BP-69) — Toute la journalisation BookKeeper a été convertie à partir de SLF4J formater les chaînes en slog, une journalisation structurée API où chaque événement transporte une clé/valeur typée attributs (par exemple ledgerId, entryId). Le contexte de l'enregistreur est propagé via client opérations, de sorte que tous les événements liés au même grand livre sont automatiquement balisés. Les attributs sont rendus par log4j2 en texte brut et en sortie JSON, avec un exemple configuration pour les journaux JSON compatibles OpenTelemetry. PR #4751, #4754, #4755, #4756, #4757, #4758, #4765, #4766, #4767, #4770
  • Sérialisation LightProto — Le protocole filaire BookKeeper, les formats de métadonnées et le flux les protos de stockage ont été migrés de protobuf-java vers LightProto, qui analyse et sérialise directement sur les tampons Netty sans allocations intermédiaires, réduisant ainsi la pression du GC sur le chemin chaud. PR #4779, #4780, #4781, #4783
  • Bibliothèque d'E/S native réécrite dans Rust — La bibliothèque native-io utilisée pour les E/S directes sur le bookmaker a été migré de C vers Rust. PR #4738
  • Java 17 de base — Java 17 ou version ultérieure est désormais requis pour créer et exécuter BookKeeper. PR #4446
  • La mise hors service de Bookie nettoie le cookie (BP-68) — L'administrateur de mise hors service API maintenant supprime le cookie du bookmaker du magasin de métadonnées, de sorte qu'un identifiant de bookmaker mis hors service peut être réutilisé sans nettoyage manuel. PR #4500, #4592
  • Limitation de lecture ZooKeeper pendant la réplication (BP-66) — La réplication peut désormais limiter ses lectures ZooKeeper, protégeant le magasin de métadonnées des tempêtes de lecture lorsque de nombreuses les grands livres sont en cours de récupération. PR #4258
  • Lectures par lots d'entrées non confirmées (BP-62) — batchReadUnconfirmedAsync est maintenant exposé sur ReadHandle. PR #4739

Modifications radicales

  • Java 17+ est requis pour créer et exécuter BookKeeper (anciennement Java 11) PR #4446
  • La valeur par défaut de readOnlyModeOnAnyDiskFullEnabled a été modifiée en true : un bookmaker maintenant passe en lecture seule dès qu'un disque du grand livre est plein, au lieu de seulement lorsque tous les disques sont pleins. Remettez-le sur false pour restaurer le comportement précédent. PR #4520
  • Le module bookkeeper-slogger a été supprimé, remplacé par le slog structuré journalisation API (BP-69) PR #4764
  • Suppression de la méthode obsolète et mal orthographiée setAllocatorPoolingConcurrenncy — utilisez setAllocatorPoolingConcurrency à la place PR #4431
  • Suppression de la classe obsolète MathUtils PR #4274

Problèmes connus

  • PR #4730 (lire le correctif de blocage de thread dans sendResponseAndWait), inclus dans cette version, s'est avéré potentiellement provoquer un blocage sur le chemin de lecture du bookmaker. Il a été inversé dans PR #4830, qui fera partie de 4.18.1.

Fonctionnalités

  • Prise en charge de la configuration TCP keep-alive pour le serveur bookie PR #4762
  • Nouveau client API pour vérifier si le BookKeeper client est connecté au service de métadonnées PR #4342
  • Migrer de Yahoo DataSketches vers Apache DataSketches 7.0.1 (KLL) PR #4774
  • Autoriser la configuration de log4j2 AsyncLogger PR #4269

Améliorations

  • Enrichir les métriques GC pour mieux analyser le comportement du GC et le temps passé dans chaque phase PR #4384
  • Ajouter une métrique pour RocksDB getLastEntryInLedger pour aider à identifier les goulots d'étranglement PR #4529
  • Définissez ThreadFactory pour l'exécuteur dans EntryLoggerAllocator PR #4562
  • Ajouter la propriété temp dir pour la bibliothèque native PR #4533
  • Appliquez le paramètre WRITE_BUFFER_WATER_MARK aux chaînes enfants dans le serveur bookmaker Netty PR #4337
  • Ignorer l'insertion inutile du cache optimiste dans SingleDirectoryDbLedgerStorage lorsque le verrou en écriture est maintenu PR #4306
  • Enregistrez uniquement les paramètres de configuration remplacés au démarrage de BookieServer PR #4768
  • Supprimer le suivi du temps du journal inutilisé PR #4006

Client

  • Améliorer la logique de résolution d'adresse d'hôte pour l'identifiant du bookmaker PR #4588
  • Renommez le pool de threads haute priorité client PR #4496

Outils

  • La commande readledger lit toutes les entrées d'un bookmaker lorsque les identifiants de la première et de la dernière entrée ne sont pas fournis PR #4692
  • Optimiser ListActiveLedgersCommand PR #4602
  • Améliorer les informations d'utilisation du bookmaker CLI pour l'option --help PR #4241

  • Correction de la gestion du chemin de configuration RocksDB sous Windows PR #4407
  • Correction d'une boucle sans fin dans la lecture de BufferedChannel PR #4506
  • Correction de l'exception ArrayIndexOutOfBoundsException dans ConcurrentLongHashMap PR #4771

  • Correction des journaux d'erreurs de l'appender de journal asynchrone avalant lorsque le bookmaker ne parvient pas à démarrer [PR #4475] (https://github.com/apache/bookkeeper/pull/4475)
  • Correction de SingleThreadExecutor pour rejeter les nouvelles tâches pendant qu'un drainTo est en cours et que la file d'attente est vide PR #4488

Client

  • Correction de la condition de concurrence NPE dans la gestion des réponses V3 lors de la vérification du délai d'attente PR #4737
  • Correction du blocage de WatchTask du bookmaker PR #4481

  • Ajoutez une résolution stricte du nom d'hôte et une vérification de bouclage pour l'adresse annoncée PR #4595
  • Utilisez l'enregistreur de journaux d'instance dans LedgerHandle.batchReadUnconfirmedAsync PR #4782
