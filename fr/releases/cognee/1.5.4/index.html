Résumé

Cette version de correctif se concentre sur la fiabilité, la commodité de l'ingestion de données et le perfectionnement du front-end. Il corrige plusieurs problèmes de migration, de journalisation et de provenance, ajoute des fonctionnalités API et Docker petites mais utiles pour les outils d'ingestion, et comprend un large ensemble de mises à jour frontales et de corrections de bogues.

Faits saillants

  • L'image Docker installe désormais le supplément 'dlt' afin que les outils d'ingestion de données courants fonctionnent immédiatement.
  • API add endpoint accepte les chaînes raw_data et les URL de dépôt git pour simplifier l'ajout d'ensembles de données par programme.
  • Plusieurs correctifs concernant les migrations, la journalisation et la provenance pour améliorer la stabilité lors des mises à niveau et des opérations simultanées.
  • Réorganisations du frontend et nombreux correctifs d'interface utilisateur qui améliorent les flux de travail des ensembles de données, des tableaux de bord et des intégrations.
  • Renforcement de la sécurité et de la sûreté : les jetons API sont rédigés dans les journaux de démarrage et l'accès à la racine du fichier local est désactivé par défaut.

Modifications radicales

  • Suppression du paramètre 'repositories' — Le paramètre 'repositories' a été supprimé des appels API/CLI concernés. Si vous vous êtes appuyé sur ce paramètre, mettez à jour vos intégrations avec le nouveau modèle d'appel (consultez la documentation OpenAPI ou SDK pour la signature mise à jour).
  • COGNEE_ALLOWED_LOCAL_FILE_ROOTS par défaut modifié — La configuration COGNEE_ALLOWED_LOCAL_FILE_ROOTS est désormais désactivée par défaut. Si vous l'avez déjà utilisé pour autoriser l'accès aux fichiers locaux, réactivez-le explicitement dans votre configuration et vérifiez les chemins autorisés.

Nouvelles fonctionnalités

  • Extra DLT dans l'image Docker — L'image officielle Docker installe désormais l'extra 'dlt' (un ensemble facultatif de packages utilisés pour le chargement des données). Cela signifie que les connecteurs ou les flux d'ingestion qui dépendent de cet extra fonctionneront sans que vous ayez à installer manuellement des packages supplémentaires dans votre conteneur.
  • L'ajout d'un point de terminaison accepte les données brutes et les URL de dépôt — Le API qui ajoute des données accepte désormais raw_data sous forme de chaîne (vous pouvez donc POSTER du texte directement) et accepte également les URL de clonage de référentiel. Cela facilite l'ajout par programme de données à partir d'un dépôt git ou d'un texte en ligne sans pré-télécharger de fichiers.
  • Affinements du frontend et nouvelles pages — L'interface utilisateur Web a reçu des mises à jour importantes sur le tableau de bord, les ensembles de données, les intégrations et les pages métier/canevas. Ces modifications réorganisent les listes et les panneaux, améliorent les flux de téléchargement et améliorent les étapes d'intégration pour rendre les tâches quotidiennes plus claires et plus fluides.

Améliorations

  • Les migrations s'exécutent une fois par processus — Les migrations de bases de données relationnelles ne sont désormais effectuées qu'une seule fois pour un processus, réduisant ainsi le travail en double et les conditions de concurrence lors du démarrage.
  • Initialisation de la journalisation affinée — La journalisation est initialisée exactement une fois par processus et les bascules de journalisation verbeuse/silencieuse qui provoquaient la confusion ont été supprimées. Cela réduit les entrées de journal en double et rend les journaux plus faciles à lire.
  • Gestion des délimiteurs d'ingestion DLT — Le pipeline d'ingestion basé sur dlt gère désormais correctement les fichiers qui utilisent différents délimiteurs (virgules, tabulations, etc.), de sorte que les fichiers CSV/TSV à sources mixtes sont importés de manière plus fiable.
  • Correction d'un crash de données vides de FastAPI — Un bug de FastAPI qui pouvait planter sur des données de requête vides a été corrigé, améliorant ainsi la robustesse de API pour les cas extrêmes.
  • La démo CLI affiche des exemples de réponses sans appels LLM supplémentaires — Le mode démo CLI affiche désormais entièrement les réponses de démonstration stockées, sans recourir aux modèles de langue, ce qui rend les démos plus rapides et conviviales hors ligne.
  • Citation des prédicats LanceDB — Les identifiants dans les prédicats de récupération LanceDB sont correctement cités pour éviter les erreurs de requête pour certains formats d'identifiant.
  • Lire EMBEDDING_API_BASE en tant qu'alias — La variable d'environnement EMBEDDING_API_BASE est désormais reconnue comme un alias de point de terminaison, simplifiant ainsi les configurations alternatives de point de terminaison.
  • Nettoyage de provenance — Les correctifs apportés à la gestion de la provenance arrêtent la propriété en double des bords créés à partir du contenu fragmenté et déclarent les valeurs par défaut correctes dans le modèle afin que les migrations de provenance se comportent de manière cohérente.
  • Correctifs d'autorisation de mise à jour et de propriété — Les mises à jour incrémentielles sont désormais autorisées par l'ACL de l'ensemble de données (liste de contrôle d'accès), la recherche de budget en bloc est résolue en tant que propriétaire de l'ensemble de données et le propriétaire de l'ensemble de données d'origine est conservé lors des solutions de secours de reconstruction complète.

Performances

  • Réduction des conflits de verrouillage de provenance — Le point de contrôle a été déplacé hors du verrouillage de provenance, réduisant ainsi les conflits de verrouillage et améliorant la concurrence lorsque de nombreuses opérations écrivent des métadonnées de provenance.
  • Ordre d'écriture plus robuste — Le graphique est désormais écrit avant les vecteurs pendant les opérations de stockage, réduisant ainsi le risque d'écritures partielles et améliorant la cohérence globale des données lors de l'ingestion.
  • Approvisionnement de base de données rationalisé : les bases de données d'ensembles de données sont provisionnées uniquement par identifiant d'ensemble de données, ce qui simplifie la logique d'approvisionnement et réduit les frais généraux lors de la configuration de l'environnement.

Sécurité

  • Rédaction du jeton API dans l'écho de démarrage — Le point d'entrée n'imprime plus le texte en clair --api-token dans son écho de lancement ; les jetons sont expurgés afin qu'ils ne soient pas divulgués dans les journaux.
  • Racines de fichiers locaux désactivées par défaut — Le paramètre COGNEE_ALLOWED_LOCAL_FILE_ROOTS est désormais désactivé par défaut pour réduire l'exposition accidentelle des chemins du système de fichiers local au serveur.
  • Ignorer l'octroi d'autorisations de locataire pour la sentinelle locale — Le frontend/serveur ignore désormais l'octroi automatique d'autorisations de locataire lors de l'exécution d'une instance de sentinelle locale, empêchant ainsi les modifications d'autorisation inattendues lors des exécutions de développement.

Corrections de bugs

  • Suppression d'un mode de journalisation « silencieux » qui supprimait les messages utiles et provoquait la confusion.
  • Correction d'un problème où le paramètre de référentiels était supprimé de manière incorrecte dans certains appels - surfaces de rappel mises à jour pour correspondre au nouveau modèle d'appel.
  • Correction d'un crash de FastAPI sur des charges utiles de données vides.
  • Rédaction de l'argument --api-token dans la sortie de démarrage.
  • Correction de l'ingestion dlt pour gérer correctement plusieurs délimiteurs de fichiers.
  • Correction des régressions du refactor DTO et synchronisation des extras OpenAPI avec l'application en cours d'exécution afin que les documents et API correspondent.
  • Correction des bords de provenance produits en morceaux étant en double propriété.
  • Correction d'un problème garantissant que la recherche de budget en morceaux est résolue avec le contexte correct du propriétaire de l'ensemble de données.
  • Correction de plusieurs bugs frontend dans les pages d'ensemble de données, de tableau de bord et d'intégration (progression du téléchargement, modaux, rendu de liste et connecteurs).
  • Correction du comportement de lecture pour EMBEDDING_API_BASE afin que la configuration alternative du point de terminaison se comporte correctement.

Modifications techniques

  • Migrations refactorisées : un module de schéma gelé est utilisé pour les deux révisions et le choix du dialecte est décidé à partir de la liaison de base de données ; plusieurs changements de reparentage migratoires pour conserver un seul chef après les récentes fusions.
  • Nombreuses mises à jour de CI et de tests : réorganisation des suites de tests, répartitions nocturnes/tests et ajout de tests de routage e2e pour serve().
  • Ajustements de synchronisation et de documentation d'OpenAPI : de petits correctifs de présentation et des extras de spécifications ont été synchronisés avec l'application en cours d'exécution.
  • Divers refactors et nettoyages internes : re-parenting des migrations d'agents, modifications de l'approvisionnement et plusieurs correctifs de dispositifs de test.
