claude-code v2.1.318

Correctif Publié4 nov. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.318

Qu'est-ce qui a changé

  • Ajout d'un enregistrement de votre réponse lorsque Claude Code demande d'activer les mods qu'il écrit dans une session
  • Ajout de assume_role sur mantle en amont de la passerelle d'applications Claude, pour un rôle dans un autre compte AWS et pour l'attribution des coûts AWS par développeur
  • Ajout d'une option effort au $.model.fork d'un mod, afin qu'un travail secondaire rapide puisse s'exécuter sur low quel que soit l'effort utilisé par la session ; le résultat rend compte de l'effort envoyé
  • Ajout de la date de fin d'une connexion claude.ai stockée à claude auth status (loginExpiresAt) et aux résultats claude -p JSON (credential_expires_at)
  • Ajout d'un avertissement stderr d'une ligne à la sortie texte claude -p, commençant 10 jours avant la fin d'une connexion claude.ai stockée
  • Correction de --continue perdant parfois la conversation précédente après l'épuisement des tentatives d'appel d'un outil mal formé (régression dans 2.1.314)
  • Correction des sessions macOS avec de nombreuses commandes Bash en cours d'exécution bloquées alors que la mémoire augmentait
  • Correction des invites d'autorisation auxquelles répondaient les touches tapées juste après l'envoi d'un message ou avant l'apparition d'une invite lente
  • Correction du succès des rapports /logout, claude auth logout et claude mcp remove et des modifications apportées au trust, le consentement ou les paramètres MCP étant supprimés sans mot, lorsque le fichier de configuration ne pouvait pas être mis à jour sur un répertoire personnel de réseau partagé
  • Correction des tâches quittant avec Not logged in lorsqu'un autre terminal ou hôte se reconnecte au même compte et à la même organisation sur la même maison
  • Correction de claude mcp add et remove écrivant la configuration sans son verrou : ils l'attendent maintenant ou quittent 1, bien que la sauvegarde d'un autre job puisse toujours remplacer un serveur enregistré
  • Correction des commandes claude plugin se terminant avant qu'une actualisation lente du jeton ne soit enregistrée, ce qui pourrait vous déconnecter lors de la prochaine exécution.
  • Correction de claude plugin validate transmettant un fichier de marché nommé personnalisé que claude plugin marketplace add rejette
  • Correction des serveurs MCP stdio qui se terminent lors de la sonde de version et qui sont réexaminés à chaque démarrage ; un serveur qui meurt en moins de 3 secondes pour sa propre raison est également épinglé à l'ancienne poignée de main pendant 7 jours
  • Correction des sessions refusées au démarrage par une liste allowedProviders qu'un autre login sur la même machine avait stockée
  • Correction du compactage inactif remplaçant une conversation par une réponse qui n'était pas un résumé
  • Correction de l'avis « Utilisation des crédits d'utilisation maintenant » réapparaissant toutes les 30 secondes environ lorsqu'un sous-agent en arrière-plan est en cours d'exécution.
  • Correction des commandes slash personnalisées qui échouent, ou que seul Claude peut invoquer, n'imprimant rien dans les sessions claude -p et SDK
  • Correction des sessions claude -p et Agent SDK signalant le succès lorsqu'une erreur API coupait une réponse alors qu'un mod accrochait turn.step
  • Correction d'un message envoyé juste après un changement de modèle toujours en cours après l'arrêt dans les sessions sans tête : Stop l'annule ou l'arrête désormais comme il le ferait pour un message en file d'attente
  • Correction d'une transcription de session supprimée étant recréée avec sa dernière invite lorsqu'une session inactive non interactive se terminait
  • Correction des hôtes claude remote-control, du démon d'arrière-plan et des exécuteurs auto-hébergés qui ne parvenaient pas à démarrer de nouvelles sessions (spawn ENOENT) après une mise à jour ou un nettoyage de version, supprimant le binaire d'un processus toujours en cours d'exécution.
  • Correction d'un processus Claude Code en cours d'exécution appartenant à un autre utilisateur (par exemple celui laissé par sudo claude) étant traité comme mort par le nettoyage de version, ce qui pouvait supprimer son binaire
  • Correction de /remote-control affichant une session comme disponible après un échec de connexion
  • Correction du succès du rapport /design revoke lorsque la requête échouait avec un 404
  • Correction d'une commande shell approuvée après le redémarrage d'un exécuteur auto-hébergé ou d'une session cloud exécuté dans le dossier de démarrage de la session, et non dans le dossier dans lequel elle a été demandée ; si ce dossier ne peut pas être saisi, il n'est pas exécuté
  • Correction de Claude qui n'était pas informé lorsqu'un outil de connecteur approuvé n'était pas disponible après le redémarrage d'une session cloud
  • Correction des sessions cloud étant arrêtées au milieu d'un tour lorsque le service refuse les téléchargements pendant plusieurs minutes
  • Correction des variables qu'un hook Setup écrit dans CLAUDE_ENV_FILE n'atteignant pas l'outil Bash dans certaines sessions cloud
  • Correction de l'application iPhone affichant le tour d'une session cloud comme terminée alors qu'elle continuait à s'exécuter, après qu'une réponse ait été coupée lors d'un appel d'outil ou qu'une image ou un document refusé ait été supprimé
  • Correction d'une session redémarrée renvoyant un message qui échouait avec une erreur API, avant le message le plus récent qui attendait derrière lui.
  • Correction d'une session redémarrée perdant son tour interrompu lorsque le redémarrage survenait juste après que Claude ait lu une grande image ou réessayé un appel d'outil
  • Correction de chaque échec de connexion lorsque le fichier NODE_EXTRA_CA_CERTS est vide, pas PEM, ou démarre avec un certificat endommagé : des certificats lisibles sont désormais utilisés, avec un avertissement sur stderr
  • Correction des workflows réexécutant les agents terminés lors de leur reprise après une limite d'utilisation
  • Correction de /mcp dans les outils de comptage de sessions cloud que le modèle ne peut pas utiliser ; la ligne d'un serveur indique désormais combien de ses outils sont disponibles
  • Correction d'une notification en double lorsque Claude quittait le champ d'état en dehors d'un appel PushNotification
  • Correction de l'erreur d'une image trop grande dans une requête avec plus de 20 images indiquant toujours que la limite était de 2000px ; il affiche maintenant la limite du API
  • Correction du temps d'exécution dans les détails du shell en arrière-plan qui ne se mettait pas à jour lorsque la boîte de dialogue est ouverte
  • Correction du hook turn.step d'un mod faisant qu'une réponse arrêtée se termine comme un succès dans les exécutions sans tête
  • Correction du nettoyage de rétention laissant une maison qui exécute uniquement claude -p sans sauvegarde ~/.claude.json : il faut désormais une nouvelle sauvegarde avant de supprimer la dernière bonne.
  • Correction du remplacement de la connexion stockée par un fichier vide lorsqu'un répertoire personnel du réseau n'a plus de place pour les données mais prend toujours de nouveaux fichiers
  • Correction des jetons de setup-token étant refusés au démarrage sur les machines avec forceLoginOrgUUID, lorsque le jeton appartient à une organisation autorisée
  • Correction des lancements non interactifs remplaçant un ~/.claude.json qui n'est pas un JSON valide par les valeurs par défaut ; le démarrage échoue maintenant, indique comment restaurer le fichier et le laisse tel quel (anthropics/claude-code#87551)
  • Correction d'un ~/.claude.json vide sans qu'aucune sauvegarde ne soit signalée comme corrompue ; Claude Code démarre désormais comme lorsque le fichier est manquant
  • Correction de la commande de restauration imprimée pour un ~/.claude.json endommagé ou manquant nommant une sauvegarde vide ou coupée, ou échouant sur un fichier en lecture seule
  • Correction de l'échec de connexion lorsqu'une connexion claude.ai stockée atteint sa limite de temps : il l'indique désormais, et dans claude -p, les noms claude auth login et claude setup-token
  • Amélioration de la façon dont ~/.claude.json, les fichiers de paramètres et les identifiants stockés survivent aux sauvegardes sur les répertoires personnels du réseau partagé : ils sont moins souvent supprimés, brièvement vidés ou remplacés par une copie presque vide ou plus ancienne.
  • Amélioration des sessions sur les systèmes de fichiers réseau pour vérifier à nouveau lorsque le fichier de configuration est signalé à tort comme manquant, donc moins de démarrages sans vos serveurs MCP et vos dossiers trusted
  • Amélioration des erreurs de l'outil MCP : un appel effectué avant le chargement de l'outil renvoie désormais son schéma d'entrée
  • Amélioration de la fiabilité des commits git et de la création de requêtes d'extraction lorsque l'outil Bash exécute le /bin/bash intégré à macOS
  • Amélioration de « Demandez à votre administrateur une utilisation supplémentaire » dans le menu de limite d'utilisation pour envoyer la demande en une seule étape
  • Amélioration de la rapidité avec laquelle les sessions à distance se reconnectent après une pause ou une mise en veille
  • Amélioré Vous devriez connaître les toasts pour dire "essayez à nouveau" au lieu de "appuyez sur 2", qui ne fonctionne que dans le terminal
  • Fiabilité améliorée de la mise à jour automatique : une brève panne de réseau lors de la vérification d'une version est désormais réessayée immédiatement au lieu d'attendre la prochaine vérification
  • Amélioration des exécutions sans surveillance (applications claude -p, SDK) pour arrêter de réécrire ~/.claude.json à chaque exécution lorsque rien n'a changé
  • Modification du code Claude pour ne plus installer ou mettre à jour l'extension IDE au démarrage dans un terminal IDE ; utilisez /ide depuis un terminal extérieur ou depuis la vue des extensions de votre éditeur
  • Modification des sous-agents pour qu'ils s'arrêtent au lieu de changer de modèle lorsque "Changer de modèle lorsqu'un message est signalé" est défini sur "Demander à chaque fois".
  • Modification des sous-agents d'arrière-plan pour déplacer une commande shell en arrière-plan après 3 minutes sur tous les fournisseurs, afin que le cache d'invite n'expire pas pendant son exécution.
  • Modification des résumés de progression des sous-agents sur Bedrock, Vertex, Foundry ou avec la télémétrie désactivée : sur un cache d'invites froides, on peut désormais attendre jusqu'à 5 minutes la réponse en attente du sous-agent
  • Modification de ce qu'un mod attache à prompt.submit pour rester au tour de l'utilisateur plutôt que de disparaître comme message système
  • Modification des entrées d'URL deniedMcpServers pour bloquer également les serveurs fournis par Anthropic dont l'URL en amont correspond, ainsi que les connecteurs dans les sessions cloud et sur les exécuteurs auto-hébergés, où la session reçoit la propre URL du connecteur ; sinon, refusez un connecteur par son nom
  • Modification des détails de la règle /permissions, des règles intégrées et des vues de confirmation de suppression pour utiliser la boîte de dialogue standard ; appuyer deux fois sur Ctrl+C revient maintenant en arrière ou annule au lieu de quitter
  • Modification de /claude-api managed-agents-onboard pour donner aux outils intégrés d'un nouvel agent et aux outils MCP d'un modèle de démarrage rapide, la politique d'autorisation auto ("Juger les actions risquées") par défaut, correspondant à la console Claude ; dites "courir sans demander" pour vous désinscrire
  • Suppression du correctif 2.1.288 qui conservait la réflexion antérieure du modèle lors de la reprise d'une conversation commencée sur 2.1.286 ou avant ; cette réflexion peut maintenant être abandonnée
  • Passerelle : ajout d'un avertissement de journal lorsque le jeton d'accès Google d'un fichier d'informations d'identification de fédération (external_account) est sur le point d'expirer
  • Passerelle : amélioration des astuces de journalisation concernant listen.trusted_proxies : elles indiquent désormais de répertorier uniquement un proxy qui ajoute l'adresse de connexion à X-Forwarded-For lui-même
  • Passerelle : amélioration de l'avertissement en cas d'échec d'AWS CountTokens sur Amazon Bedrock : il indique Claude Code, et non la passerelle, compte après le 501, et pointe vers IAM uniquement lorsque AWS refuse l'accès
  • Runner auto-hébergé : ajout de CLAUDE_RUNNER_SPAWN_REASON à l'environnement de hook spawn-runner de l'orchestrateur : pourquoi Anthropic a envoyé la demande (par exemple runner_lost, resumed) ; désactivé alors qu'aucun n'a été envoyé
  • Exécuteur auto-hébergé : ajout d'un avertissement de démarrage lorsque --release-idle-session-min est le dernier argument sans valeur (toujours ignoré) ou a une valeur composée uniquement d'espaces (toujours lu comme 0)
  • Exécuteur auto-hébergé : modification des lignes de journal de l'orchestrateur : ok session=… s'imprime désormais à chaque niveau de journal sur stdout (auparavant, debug uniquement, stderr) avec reason=… après jti=…, et nack session=… termine ses champs avec reason=… après retryable=… ; mettre à jour les scripts qui correspondent à retryable=true: ou retryable=false:
  • Contrôle à distance : correction d'une "erreur d'apparition : ENOENT" trompeuse lorsque le dossier de travail d'une session est manquant ; l'erreur nomme maintenant le dossier
  • Contrôle à distance : amélioration du titre avec lequel un fork d'un terminal fork est créé lorsque l'application n'en définit pas : "Nom (fork 2)"
  • [VSCode] Correction d'une fenêtre dont les paramètres de connexion de l'organisation refusaient de démarrer un nouveau processus Claude Code en arrière-plan toutes les minutes
  • [VSCode] Correction d'un long mot dans la bannière d'erreur du panneau de discussion en poussant son bouton de fermeture hors de vue
  • [VSCode] Amélioration de l'écran de connexion pour afficher ce que Claude Code a imprimé lorsque sa vérification de l'état de connexion échoue
  • [Sessions Cloud] Ajout d'une option Aucun référentiel : une session cloud sur un environnement hébergé par Anthropic peut désormais démarrer sans choisir de référentiel
  • [Sessions cloud] Ajout des noms Chrome habituels aux sessions cloud, afin que des outils autres que Playwright puissent trouver le Chromium intégré via google-chrome et CHROME_PATH
  • [Sessions cloud] Ajout d'un bouton Nouvelle session sur la carte affichée lors de la suppression de l'environnement d'une session cloud, où la boîte de message est masquée
  • [Sessions cloud] Correction de la lecture des journaux d'actions GitHub dans les sessions cloud : les requêtes de journal gh run view --log et gh api obtiennent désormais le journal dans la plupart des environnements, et non une redirection inaccessible.
  • [Sessions cloud] Amélioration de la plupart des messages d'échec de création de PR dans les sessions cloud et de contrôle à distance : ils donnent désormais la raison ou un lien vers GitHub au lieu de dire Réessayez
  • [Sessions Cloud] Modification des résultats de recherche du connecteur pour indiquer à Claude que la recherche ne couvre qu'une partie du répertoire du connecteur
  • [Contrôle à distance] Correction des extractions côte à côte d'un référentiel semblant identiques dans les lignes de contrôle à distance du menu d'environnement ; chacun affiche maintenant son propre nom de dossier
  • [Claude Tag] Correction du focus du clavier et des annonces du lecteur d'écran dans la configuration d'administration de Claude Tag ; appuyer sur Échap dans le formulaire de connexion ne ferme plus également la boîte de dialogue Ajouter
  • [Code Review] Amélioration de la page d'analyse de Code Review pour réessayer une fois après une panne de serveur ou de réseau, puis afficher une bannière Réessayer au lieu de cartes vides.
