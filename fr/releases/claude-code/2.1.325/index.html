claude-code v2.1.325

Correctif Publié13 nov. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.325

Qu'est-ce qui a changé

  • Correction d'un problème de sécurité dans la façon dont les réponses compressées zstd sont décodées
  • Ajout d'une astuce dans VS Code et terminaux intégrés similaires concernant la réexécution d'une cellule de notebook, affichée une fois que Claude a lu ou modifié un notebook Jupyter
  • Ajout d'une ligne sous l'erreur affichée lorsque la politique de votre organisation bloque une demande, indiquant comment continuer : exécutez /rewind et modifiez le message, ou exécutez /clear.
  • Ajout d'une note pour Claude lorsqu'un pull git checkout, git stash ou autostash en bac à sable ne peut pas mettre à jour les fichiers protégés tels que ceux de .claude
  • Correction de l'arrêt des commandes git en ligne de /security-review et des compétences avec une erreur dans les arbres de travail des référentiels nus, les extractions --separate-git-dir et les extractions Android repo
  • Correction des sous-agents avec leur propre modèle étant déplacés vers le modèle en mode plan lorsque le paramètre du modèle est opusplan ou haiku
  • Correction des sous-agents sur un modèle différent, dimensionnant les lectures de fichiers et les résultats MCP avec le modèle de la session principale
  • Correction des sessions sur de nombreuses passerelles tierces et Foundry s'arrêtant avec une erreur de longueur de contexte à chaque tour au lieu de compacter
  • Correction de tours récents manquant parfois lors d'une reprise de session après l'arrêt de Claude Code sans sortie propre.
  • Correction des commandes shell exécutées dans le répertoire de lancement après la suppression du répertoire de travail ; la commande échoue désormais avec un message et peut être réexécutée
  • Correction d'une modification de plan approuvée étant perdue lorsque le dossier plansDirectory ne peut pas la prendre : le plan est désormais enregistré dans le dossier des plans par défaut, et un avertissement indique où et pourquoi
  • Correction d'un paramètre de modèle sonnet[1m] enregistré en cours de réécriture lors d'une nouvelle installation sur un identifiant de modèle rejeté par le API.
  • Correction de la vue de mise au point masquant la réponse à votre invite lorsqu'une tâche planifiée répondait après celle-ci
  • Correction de l'invite parfois manquante dans la vue d'un sous-agent en arrière-plan lorsque le plein écran est désactivé
  • Correction des options longues dans les listes et des invites d'autorisation étant partiellement écrasées lors de leur retour à la ligne, et des écrans de première exécution perdant des lignes sur les terminaux étroits
  • Correction des avertissements de démarrage concernant les règles d'autorisation et l'avis "Les serveurs N MCP ont besoin d'une authentification" enregistrés comme indiqué lorsqu'ils défilaient hors de vue.
  • Correction de l'en-tête de bienvenue affichant des caractères de contrôle ou répartis sur plusieurs lignes lorsque le nom d'un agent ou le dossier de travail en contient ou un saut de ligne.
  • Correction de l'erreur rouge affichée lorsque Claude essaie une commande que vous seul pouvez exécuter : une ligne grisée indique désormais qu'elle ne s'exécute que lorsque vous la tapez à l'invite.
  • Correction de /stats affichant un total de jours actifs qui était un jour trop élevé
  • Correction de /insights indiquant qu'un rapport était prêt lorsqu'aucune session n'était qualifiée pour l'analyse et écrivant deux valeurs dans son rapport HTML sans les escaping
  • Correction de /voice indiquant que le mode vocal était modifié lorsque les paramètres gérés, --settings, ou que le .claude/settings.json ou .claude/settings.local.json du projet le gardait tel quel ; il dit maintenant ce qui le retient
  • Correction de la boîte de dialogue de bienvenue de l'IDE affichant Cmd+Esc pour un lancement rapide sous Windows et Linux
  • Correction des astuces de l'application Slack indiquant lorsque la politique de votre organisation refuse les sessions cloud
  • Correction de claude purge qui se bloque silencieusement lorsqu'il n'y a pas de terminal à partir duquel lire les clés, et son sélecteur de projet et ses invites -i ignorent le clavier lorsque stdin est diffusé
  • Correction de claude plugin eval --output-dir '' écrivant le rapport dans le dossier actuel ; il se termine maintenant avec une erreur
  • Correction de la sortie de texte claude -p sur un terminal passant des séquences de contrôle autres que le style de texte ; les tuyaux et les fichiers sont inchangés
  • Correction des fichiers .oauth_refresh.lock.owner.tmp.* restants qui s'accumulent dans le répertoire de configuration
  • Correction de /fast indiquant "Le mode rapide a été désactivé par votre organisation" sous la connexion à la console sans clé, où Claude Code n'avait pas demandé au serveur
  • Correction de /model indiquant que votre organisation restreint un modèle alors que Claude Code ne pouvait pas le vérifier, par exemple sans réseau
  • Correction de "Connectez-vous avec votre compte console" dans /login en remplaçant votre connexion existante lorsque vous appuyiez sur Echap juste après l'étape du navigateur
  • Correction du navigateur affichant la page de réussite de la connexion dans certains cas où la connexion échouait ou était annulée
  • Correction de claude auth status et d'autres commandes courtes laissant un verrou sur un profil de console, ce qui faisait suspendre la session suivante pendant environ une minute.
  • Correction des sessions en arrière-plan démarrées sur votre connexion claude.ai en utilisant (et en facturant) une clé ou un jeton API du shell qui a démarré le service en arrière-plan
  • Correction de davantage de cas de déplacement d'une session vers une autre connexion en arrière-plan ; ces mouvements sont désormais refusés, avec un message indiquant ce qui fonctionne
  • Correction d'une seconde entrée dans la boîte de dialogue de sortie arrêtant le travail en arrière-plan après le refus du passage en arrière-plan
  • Correction du jeton comptant sur Amazon Bedrock envoyant la conversation à Bedrock lorsque le paramètre géré allowedProviders ne le permet pas
  • Correction des assistants AWS credential_process et des informations d'identification par défaut de Google Cloud qui échouaient lorsque Claude Code est démarré sans variable d'environnement HOME
  • Correction d'une session revenant parfois à un mode d'autorisation antérieur après l'approbation du plan d'un sous-agent
  • Correction d'une valeur invalide dans un appel de l'agent SDK applyFlagSettings(), supprimant silencieusement tous les paramètres des appels précédents ; un appel qui ferait cela est maintenant refusé avec une erreur
  • Correction des sessions affichées comme en attente de saisie lorsqu'une demande d'extraction terminée ne nécessitait que votre propre révision ou fusion.
  • Correction d'une valeur de paramètre teammateMode non reconnue ignorée sans avertissement : claude -p, l'avertissement de démarrage et claude doctor la répertorient désormais comme une entrée ignorée (toujours non appliquée)
  • Correction de --worktree sautant un hook WorktreeCreate depuis un plugin dans CLAUDE_CODE_PLUGIN_SEED_DIR lors de la première exécution dans un nouveau répertoire personnel
  • Correction des sessions en mode bref, telles que Dispatch, envoyant à nouveau une réponse après que le tour ait déjà répondu
  • Correction de Claude disant qu'un connecteur Atlassian, Asana ou Sentry fonctionnel avait échoué dans les sessions cloud lorsqu'un plugin le répertoriait à une URL différente
  • Correction des sessions Claude Desktop et SDK répertoriant les propres serveurs MCP d'un dossier (.mcp.json, local) comme étant ajoutés par l'hôte ou pas du tout, et ne connectant pas ceux WebSocket, après un déplacement de dossier ou un démarrage préchauffé
  • Correction de /mcp répertoriant toujours le serveur MCP d'un plugin après qu'un rechargement du plugin l'ait supprimé pendant sa connexion
  • Correction d'un serveur MCP restant "nécessite une authentification", et ses hooks mcp_tool étant ignorés, après un rafraîchissement de jeton qui n'était refusé que pendant un instant
  • Correction des demandes d'élicitation MCP annulées sans demande en mode sans tête après le remplacement de la connexion d'un serveur lors d'un appel d'outil
  • Correction des appels d'outil MCP provenant d'un hôte SDK répondant "Non connecté" après qu'un appel d'outil ait reconnecté le serveur MCP
  • Correction d'une tâche MCP qui restait bloquée après que sa question ait été fermée avec Esc ou posée à nouveau : le pied de page indique maintenant qu'elle a besoin de votre saisie, et Enter dans /tasks affiche à nouveau la question
  • Correction des tâches MCP en arrière-plan qui arrêtaient la mise à jour après un autre appel au même serveur perdaient la connexion, lorsqu'un appel ultérieur se reconnectait
  • Correction d'une question d'une tâche MCP en arrière-plan s'ouvrant sur un message que vous étiez encore en train de taper ; il attend maintenant que vous envoyiez ou effaciez le brouillon, et la roulette et la minuterie continuent de fonctionner
  • Correction de worktree.sparsePaths et des clones de plugins et de places de marché clairsemés laissant de côté les fichiers racine du référentiel sur les anciennes versions de git, telles que 2.34
  • Correction des sessions d'exécution auto-hébergées avec plusieurs référentiels incapables d'utiliser un référentiel ajouté en cours de session
  • Correction de Claude demandant la permission avant de lire votre propre artefact ou ses données
  • Correction des règles de refus et de demande d'autorisation et des hooks pour l'outil Artifact ne s'appliquant pas dans certaines sessions cloud
  • Correction des scripts en mode Code ignorant un arbre de travail entré avec EnterWorktree, écrivant les chemins ~ dans le projet et laissant /mcp affichant un serveur MCP comme connecté après l'expiration de sa connexion.
  • Correction des mots tapés avec un Oui dans une boîte de dialogue d'autorisation ou une approbation de plan n'atteignant pas Claude en mode Code
  • Correction de Claude démarrant tout seul le travail lorsque vous repreniez une session qui se terminait lors d'un script Mode Code ; il attend maintenant votre prochaine invite
  • Correction d'un événement OpenTelemetry user_prompt manquant pour un message envoyé lors de l'exécution des appels d'outils. L'événement a delivery.mode: "mid_turn" et le tour en cours prompt.id
  • Correction de l'événement OpenTelemetry user_prompt laissant de côté le texte des messages précédents lorsque les messages en file d'attente étaient fusionnés en un seul tour dans VS Code, ou lorsqu'un message avait une image
  • Correction des subventions allowed-tools d'une commande slash s'appliquant aux agents d'arrière-plan réveillés pendant ou après son tour
  • Correction de /feedback et /bug pour télécharger d'autres sessions uniquement lorsqu'elles ont été enregistrées par le compte ou l'organisation connecté.
  • Correction des règles de refus relatif et de demande d'autorisation (par exemple Read(./.env)) ne couvrant plus le projet après un cd ; ils s'appliquent désormais également dans les répertoires ajoutés
  • Correction des règles de refus et de demande d'autorisation commençant par mcp__plugin_*_ manquant le serveur MCP d'un plugin ou un outil orthographié dans une autre casse
  • Correction des règles de refus qui ne s'appliquaient pas à une approbation d'autorisation arrivant après le redémarrage de Claude Code, dans les sessions runner auto-hébergées et claude remote-control
  • Correction d'un cas où un .claude/settings.local.json validé pouvait être traité comme celui de l'utilisateur lorsque Claude Code était démarré dans certains sous-dossiers d'un référentiel
  • Correction de certaines règles de refus et de demande ne s'appliquant pas à certaines commandes Bash
  • Correction d'une lacune dans les contrôles d'autorisation Bash où certaines commandes composées pouvaient s'exécuter sans demander ; ceux-ci demandent maintenant la permission
  • Correction d'un cas où une règle d'autorisation Bash pouvait exécuter un programme différent de celui qu'elle nomme
  • Correction de l'invite d'approbation d'un outil de connecteur dans les sessions cloud recevant une réponse automatique pendant que les plugins étaient encore en cours de chargement
  • Correction de certains sous-agents modifiant un artefact que les personnes extérieures à votre organisation peuvent voir, ou y téléchargeant des fichiers, sans demander au préalable quand une règle d'autorisation est définie ou si les téléchargements ont été approuvés plus tôt.
  • Correction de certaines publications d'artefacts ignorant la confirmation des pages que les personnes extérieures à votre organisation peuvent voir lorsque "ne plus demander" a été choisi pour l'artefact.
  • Correction du mode automatique ne jugeant que la première modification apportée à un artefact que les personnes extérieures à votre organisation peuvent voir ; son oui couvre désormais à lui seul ce changement
  • Correction d'un verrou géré strictPluginOnlyCustomization sur les agents et les compétences ne prenant pas effet dans les sessions déjà en cours
  • Correction des commandes en bac à sable pouvant écrire dans le dossier de téléchargement du programme de mise à jour natif dans certains cas
  • Correction d'un cas où le bac à sable Bash ne protégeait pas entièrement les paramètres et les hooks d'un arbre de travail
  • Correction d'un cas où le bac à sable Bash ne protégeait pas entièrement le dossier git partagé d'un arbre de travail lié
  • Correction du choix de cache de /teleport dans certains états inhabituels de Git : il s'arrête maintenant et dit quoi faire
  • Windows : correction d'un blocage de démarrage qui pouvait durer environ une seconde lorsqu'une entrée PATH se trouvait sous un dossier que votre compte ne pouvait pas ouvrir
  • Correction de /resume sous Windows refusant ou masquant les sessions dont le dossier a été enregistré avec une casse de lettre de lecteur ou des barres obliques différentes
  • Correction d'un /resume en session sous Windows supprimant le trust enregistré d'un projet lorsque la session était enregistrée avec un cas de lettre de lecteur différent
  • Linux : Correction des commandes Bash en bac à sable qui échouaient avec bwrap: Can't create file lorsque le répertoire de travail se trouvait sous un dossier allowRead à l'intérieur d'un denyRead, par exemple sous un répertoire personnel lié par un lien symbolique.
  • Correction des déploiements tiers de Claude Desktop restant sur "Arrêt" jusqu'à la fin d'un renouvellement de token (une fois qu'il inclut cette version)
  • Amélioration des sous-agents coupés à la limite des jetons de sortie : il leur est désormais demandé à nouveau la réponse complète, plus brièvement, au lieu de renvoyer uniquement sa fin.
  • Démarrage amélioré avec une connexion à la console sans clé ou une autre connexion au profil Anthropic : un jeton encore valide est lu sans attendre le verrouillage des informations d'identification
  • Amélioration de la vérification des e-mails du compte : elle refuse désormais également votre e-mail en tant qu'identité d'un client dans les scripts exécutés par une commande, les écritures de fichiers, les récupérations Web et les appels MCP
  • Amélioration du message HTTPS authentication failed pour les marchés de plugins privés : il indique désormais que les invites du terminal de git et les programmes Askpass sont désactivés, et il apparaît également avec les versions plus récentes de git.
  • Amélioration des confirmations d'ajout de place de marché, des invites de recommandation de plugin et de l'avertissement d'installation du plugin pour indiquer que les plugins peuvent exécuter du code sur votre ordinateur, avec accès à vos fichiers et à votre shell.
  • Amélioration de l'erreur de connexion claude --desktop pour nommer la clé, le fournisseur ou le paramètre API qui empêche la connexion à un compte Claude de fonctionner
  • Amélioration du message /voice "Aucun audio détecté" sur macOS et Windows : il indique désormais où choisir votre microphone
  • Tâches MCP améliorées : Claude est désormais informé lorsqu'une tâche attend votre réponse et peut vous diriger vers /tasks
  • claude remote-control amélioré : il se termine désormais avec le statut 4 lorsqu'il s'arrête tout seul (les exécutions en monosession sortent toujours à 0) et 69 lorsqu'il ne peut pas s'enregistrer, afin qu'un gestionnaire de service puisse le redémarrer
  • Amélioration des messages affichés lorsqu'une session en arrière-plan ne peut pas utiliser la clé ou le jeton API de sa session : ils ne suggèrent plus d'ajouter la clé aux paramètres
  • Amélioration des conseils partie-total de la compétence de visualisation de données groupée pour les images statiques et pour les parties avec un ordre naturel, telles que les tranches d'âge
  • Modification des commandes Bash en bac à sable pour suivre le flux d'autorisation normal par défaut ; configurez sandbox.autoAllowBashIfSandboxed: true pour continuer à les exécuter sans invite
  • Modification des paramètres gérés qui activent le bac à sable : pour que les commandes continuent de s'exécuter sans invite, définissez sandbox.autoAllowBashIfSandboxed: true dans votre source gérée la mieux classée.
  • Modification des commandes git en lecture seule pour les demander d'abord dans un référentiel qui n'est pas celui du projet ou celui que vous avez trust ; nommez-le avec --add-dir, pas le paramètre additionalDirectories, pour les exécuter sans invite
  • Modification des tâches planifiées et de /loop pour demander avant d'exécuter une compétence qui déclare allowed-tools ou des hooks ; ajoutez Skill(name) à permissions.allow pour l'exécuter sans surveillance
  • Modification de "Toujours autoriser" dans les hôtes Desktop, IDE et SDK : une règle seule est proposée uniquement lorsque la sauvegarde autoriserait à nouveau cette commande, donc une tâche planifiée qui en dépendait peut désormais vous attendre
  • Modification du bac à sable pour refuser les écritures en bac à sable dans les paramètres, compétences, agents, commandes et hooks du .claude dans les répertoires ajoutés, comme c'est le cas dans le dossier de lancement
  • Modification de l'isolation de l'arbre de travail : une session ou un agent isolé de l'arbre de travail se voit désormais refuser les commandes de configuration de git bisect run, git maintenance register|start et scalar, et est informé de ce qui fonctionne toujours.
  • Modification des bundles MCP du plugin (.mcpb, .dxt) pour les décompresser dans le répertoire des plugins, et non .mcpb-cache dans le dossier du plugin, donc les dossiers de plugin en lecture seule se chargent ; celui récupéré par URL télécharge à nouveau une fois
  • Modification des plugins d'un marché distant que les paramètres gérés déclarent, activent et répertorient dans prependPlugins ou appendPlugins pour compter comme ceux de l'organisation ; pluginDigests est obsolète et ignoré
  • Modification du chargement du plugin pour ignorer et claude plugin validate pour signaler certains chemins et liens dangereux dans le dossier d'un plugin
  • Modification du chargement des compétences imbriquées : les dossiers .claude/skills dans les plugins --plugin-dir ne se chargent plus à partir d'une session démarrée au-dessus d'eux ; démarrez plutôt Claude Code dans le dossier plugin
  • Modification d'EnterWorktree pour refuser un chemin de hook WorktreeCreate qui passe par un lien symbolique à l'intérieur du projet ; demande au crochet d'imprimer le vrai chemin
  • Modification des coéquipiers tmux et iTerm2, et des nouvelles sessions de la vue des agents ouvertes avec ←, pour démarrer dans le dossier de la session au lieu de l'endroit où le shell a exécuté pour la dernière fois cd
  • Modification des suggestions d'invite dans le terminal pour s'actualiser moins souvent après 8 tours consécutifs démarrés par des tâches en arrière-plan ou planifiées, économisant ainsi l'utilisation jusqu'à ce que vous appuyiez sur une touche ou retourniez au terminal.
  • Modification de l'Esc sur la question d'une tâche MCP en arrière-plan pour "répondre plus tard" : rien n'est envoyé au serveur, et la question reste dans /tasks
  • Modification de CLAUDE_CODE_MAX_CONTEXT_TOKENS pour définir également la fenêtre contextuelle des ID de modèle non reconnus commençant par claude-, comme le claude-sonnet-latest d'une passerelle.
  • Modification de /login pour demander l'autorisation de modifier vos paramètres de confidentialité
  • Modification de /cost, $.session.usage(), --max-budget-usd ainsi que des métriques de coût et de jeton pour compter les appels $.model.complete et $.model.classify d'un mod.
  • Modification des programmes que le bac à sable de Claude Code démarre pour son propre usage, tels que son pont réseau, pour qu'ils s'exécutent sans les jetons de connexion et les clés API de Claude Code dans leur environnement
  • Modification de ripgrep, des commandes git locales et des propres programmes d'assistance du runtime sandbox pour qu'ils s'exécutent sans la phrase secrète de la clé mTLS client dans leur environnement
  • Télécommande : modification de /resume et /teleport pour qu'ils se déconnectent d'abord lorsque la session connectée dispose d'un lien de partage, ou lorsque cela ne peut pas être vérifié ; exécutez /remote-control pour vous reconnecter
  • Modification du Code Claude sur le web, des tâches planifiées cloud et des sessions cloud Cowork pour démarrer malgré sandbox.failIfUnavailable : le conteneur hébergé n'a pas de sandbox de commandes
  • Modification des demandes de paramètres, de règles d'autorisation, de hooks ou de statut sur une connexion cloud ou de session auto-hébergée pour renvoyer moins ou être refusée ; ce qui s'applique dans la séance est inchangé
  • Modification de claude -p sans données de compte mises en cache pour attendre ces données avant sa première requête, afin qu'une première exécution dans un environnement propre puisse démarrer quelques secondes plus tard
  • Modification des instructions de Claude pour conserver les fichiers dont vous aurez besoin en dehors de son dossier temporaire du bloc-notes, qui peut être effacé
  • Modification du marché ref pour accepter l'ID complet de tout commit sur une branche ou un tag ; clients avant cette version ne peut pas cloner une telle épingle, donc une place de marché épinglée de cette façon cesse de se charger là-bas
  • Modification du marché des plugins et des téléchargements de plugins pour utiliser un tunnel CONNECT lorsque ALL_PROXY est le seul ensemble de proxy ; un proxy qui refuse CONNECT leur fait désormais défaut
  • Modification de l'exécution de -p et SDK dans un arbre de travail ou un sous-module monté dans un conteneur pour appliquer les règles d'autorisation .claude/settings.local.json uniquement une fois que le dossier est trust.
  • Modification des exécuteurs auto-hébergés pour refuser une session dont le dossier de session ou le chemin du référentiel est un lien symbolique, autre que l'extraction d'un hook checkout
  • Suppression de "demandez à votre administrateur de l'augmenter" des erreurs de limite de dépenses et de budget partagé dans les sessions cloud et sous contrôle à distance
  • [VSCode] Ajout de suggestions d'invite partout où le terminal les affiche : l'onglet accepte l'invite suivante suggérée ; promptSuggestionEnabled: false dans les paramètres de Claude Code.json les désactive
  • [VSCode] Ajout d'une connexion à la console qui ne crée aucune clé API
  • [VSCode] Ajout d'un champ pour coller l'URL de redirection lors de la connexion à un serveur MCP depuis le panneau dans les fenêtres SSH, WSL et conteneur
  • [VSCode] Correction de la coche du sélecteur de modèle restant sur l'ancien modèle après le redémarrage de Claude Code sur un autre modèle ou le basculement du modèle sur la télécommande
  • [VSCode] Correction du sélecteur d'effort proposant des niveaux supérieurs au plafond d'effort défini par votre organisation ou au paramètre maxEffortLevel.
  • [VSCode] Correction de l'écran de connexion proposant des connexions que le paramètre géré allowedProviders refuse
  • [VSCode] Correction de l'invite d'autorisation pour les outils MCP qui n'expliquait pas pourquoi Claude Code demande lorsqu'un contrôle de sécurité soulève la question
  • [VSCode] Correction du message pour les paramètres d'organisation qui ne pouvaient pas se charger, demandant d'exécuter à nouveau une commande ; il dit maintenant de réessayer, correspondant au lien Réessayer de l'onglet
  • [VSCode] Amélioration de la note affichée pour un dossier untrusted : elle indique désormais pourquoi l'extension est désactivée et comment l'activer
  • [VSCode] Amélioration de l'erreur affichée lorsque le système refuse d'exécuter Claude Code : il indique désormais que votre équipe informatique peut autoriser un programme bloqué
  • [VSCode] Amélioration de la carte de connexion pour indiquer quoi faire lorsque le navigateur affiche une erreur de connexion pour localhost
  • [VSCode] Modification du bouton de confirmation de la place de marché du lien d'installation en "Place de marché Trust et continuer".
  • [Claude Code sur le Web] Correction de nouvelles sessions cloud coupant les descriptions d'outils MCP chargées via la recherche d'outils à 4 096 caractères ; la limite est désormais de 16 384, comme dans les autres sessions Claude Code
  • [Claude Tag] Correction des liens d'artefacts collés dans Slack qui n'obtenaient aucune carte lorsque la connexion Claude de l'affiche avait expiré dans un espace de travail que leur organisation ne gère pas ; une carte simple apparaît maintenant
