code-claude v2.1.285

Qu'est-ce qui a changé

  • Ajout de la variable d'environnement CLAUDE_CODE_DISABLE_WEB_FETCH pour désactiver l'outil WebFetch
  • Ajout de claude --desktop pour ouvrir l'application de bureau Claude sur le répertoire courant, ou sur une session avec --continue / --resume <id>
  • Ajout de claude plugin configure <plugin> pour afficher les options d'un plugin et celles qui ne sont pas définies, ou enregistrer les nouvelles valeurs lues depuis stdin avec --values-stdin
  • Ajout de <server>.<key>=<value> à claude plugin install --config, afin que les propres paramètres d'un serveur MCP .mcpb groupé puissent être définis au moment de l'installation et qu'il démarre sans visiter /plugin → Configurer
  • Ajout d'un paramètre géré allowedProviders pour limiter les fournisseurs API qu'une machine peut utiliser (Anthropic API, un point de terminaison personnalisé, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform sur AWS ou une passerelle Cloud)
  • Ajout de la variable d'environnement CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES pour limiter les réenvois d'une demande de secours sans streaming qui a expiré
  • Correction de claude -p avec CLAUDE_CODE_FORK_SUBAGENT=1 : le propre appel d'agent d'un sous-agent s'exécute désormais au premier plan, de sorte que le sous-agent obtient le résultat de l'enfant.
  • Correction des installations et mises à jour du plugin et du marché via SSH ignorant le programme ssh défini dans GIT_SSH ou dans core.sshCommand de votre configuration git
  • Correction de Claude Code refusant de démarrer lorsque le système d'exploitation refuse de lire le fichier de paramètres gérés ; il avertit maintenant et démarre sans les politiques de ce fichier. D'autres erreurs de lecture et fichiers non analysables arrêtent chaque session
  • Correction des sessions cloud qui redémarraient après que leur conversation ait été compactée, refusant la prochaine mise à jour d'un artefact que la session avait déjà lu ou publié
  • Correction de claude plugin disable et enable avec un identifiant name@marketplace complet modifiant une entrée de paramètres dans une autre casse au lieu de celle du plugin installé
  • Correction des fichiers joints à un message envoyé via la télécommande qui étaient laissés de côté après un seul échec de téléchargement ; une erreur réseau, un délai d'attente ou une erreur de serveur est désormais réessayé jusqu'à deux fois
  • Correction du changement de modèle en cours de session avec une requête set_model (telle que setModel de l'agent SDK), laissant le nouveau modèle sur la limite de jeton de sortie intégrée et la fenêtre de compactage automatique jusqu'au redémarrage
  • Correction des journaux et des transcriptions expurgés affichant une partie du mot de passe d'une URL contenant @, ou la totalité lorsque l'URL écrit son @ sous la forme %40.
  • Correction de la phrase secrète SSH et des invites de nouvel hôte à partir de l'arbre de travail et des récupérations /teleport prenant le contrôle du terminal ; ces récupérations échouent désormais rapidement au lieu de demander
  • Correction de la désactivation d'un serveur MCP ajouté en milieu de session dans les sessions SDK et -p laissant ses outils disponibles
  • Correction de claude -p --permission-prompt-tool : la demande d'autorisation d'un sous-agent en arrière-plan est désormais transmise à l'outil d'invite au lieu d'être automatiquement refusée.
  • Correction de claude mcp list et claude mcp get, ainsi que de l'erreur non trouvée de claude mcp remove, login et logout, lors de l'impression des sauts de ligne et des séquences d'échappement de terminal à partir des noms et valeurs du serveur MCP.
  • Correction de l'autorisation automatique du bac à sable demandant l'approbation à chaque exécution de nombreux scripts en ligne (python3 -c, node -e) simplement parce qu'ils contiennent =
  • Correction des sous-agents du fork ne conservant pas le mode plan de la session ou le mode dontAsk : un fork s'exécute désormais sous le mode autorisation de son parent et ne peut pas quitter le mode plan
  • Correction de claude remote-control --help indiquant que --[no-]chrome est par défaut le paramètre /chrome de la machine ; les sessions générées maintiennent Claude dans Chrome désactivé à moins que --chrome ne soit transmis
  • Correction des sous-agents d'arrière-plan en mode automatique invitant une seconde réponse redondante après chaque rapport
  • Correction de la création de session cloud et /remote-env lisant uniquement les 20 environnements les plus récents d'un compte
  • Correction de la télécommande marquant un message comme lu dès son arrivée au lieu du moment où Claude commençait dessus, et perdant un message encore en file d'attente lorsque le terminal se quittait (il arrive désormais au prochain CV)
  • Correction de l'installation d'un plugin avec claude plugin install ou /plugin en le plaçant dans le cache ou le dossier de données d'un plugin installé lorsque leurs identifiants diffèrent uniquement dans ., -, @ ou (macOS, Windows) capitals ; l'installation est maintenant refusée
  • Correction des hooks et des rappels d'autorisation SDK voyant un plan manquant ou obsolète sur ExitPlanMode lorsque le plan était écrit dans la même réponse
  • Correction de la première réponse dans les sessions cloud arrivant avec des dizaines de millisecondes en retard, une régression dans 2.1.283
  • Correction des sessions qui s'authentifient avec ANTHROPIC_AUTH_TOKEN contre Anthropic API ne chargeant jamais la politique de l'organisation
  • Correction d'un échec d'appel agent(), parallel() ou pipeline() qu'un script de workflow attend plus tard, ou pas du tout, étant traité comme un rejet de promesse non géré, ce qui pourrait mettre fin à une session en arrière-plan.
  • Correction de hooks synchrones qui bloquaient Claude Code alors qu'un processus en arrière-plan lancé par le hook (par exemple some-daemon &) gardait sa sortie ouverte ; le hook se termine maintenant peu de temps après la fin de son propre processus
  • Correction de WebFetch signalant une vérification de sécurité de domaine à débit limité en tant que bloc de stratégie de réseau ou d'entreprise
  • Correction de la transcription plein écran ctrl+o qui se figeait brièvement lorsqu'elle était ouverte lors de tours avec des centaines de lectures ou de recherches de fichiers ; les appels d'outils toujours en cours à l'ouverture de la transcription affichent désormais leurs résultats une fois terminés
  • Correction des erreurs modelTimeoutException et serviceUnavailableException en milieu de flux d'Amazon Bedrock affichant un corps brut JSON au lieu du message d'erreur
  • Correction de /autofix-pr et /schedule indiquant que l'application Claude GitHub n'est pas installée sur un référentiel dont le statut d'installation n'a pas encore été vérifié
  • Correction du rejet d'une ligne (x) dans /artifacts, dissociant son fichier de l'artefact, donc la publication à nouveau du même fichier créait un nouvel artefact au lieu de le mettre à jour
  • Correction de l'outil Artefact publiant après un rembobinage de conversation (Esc Esc) écrasant le contenu plus récent d'un fichier que Claude avait lu uniquement lors des tours de rembobinage ; la publication est désormais refusée jusqu'à ce que Claude relise le fichier
  • Correction d'une règle d'autorisation Artifact ("ne plus demander") permettant à l'outil Artifact de publier un fichier en dehors des répertoires de travail sans demander ; ajoutez le dossier du fichier avec --add-dir pour que la règle le couvre
  • Correction des /cost et SDK modelUsage signalant un virage sous le mauvais modèle lorsque le serveur répondait à un refus avec un modèle de secours différent de celui attendu par le client
  • Correction de l'outil Artefact afin que la publication d'une page ne permette plus à Claude d'écraser son fichier source sans le relire lorsque la lecture précédente de Claude a été interrompue ou que le fichier a changé depuis
  • Correction du mode automatique ignorant son classificateur pour les téléchargements d'actifs de l'outil Artefact et les lectures de l'artefact de quelqu'un d'autre lorsque vous aviez approuvé cet artefact plus tôt dans un autre mode d'autorisation.
  • Correction d'une erreur trompeuse "core.worktree is set" de /ultrareview lorsque le dossier du projet ne pouvait pas être lu brièvement
  • Correction de /ultrareview sur macOS et Linux qui ne parvenait pas à télécharger l'arborescence de travail à partir d'un arbre de travail git dont la configuration par arbre de travail définit core.longpaths
  • Correction de l'outil Artifact signalant parfois une publication comme un conflit avec une autre session après une nouvelle tentative d'erreur de serveur temporaire, alors que la première tentative avait effectivement réussi
  • Correction des téléchargements /ultrareview incluant les modifications non validées des fichiers d'informations d'identification dont le nom comporte deux points avant l'extension, comme server:8443.key
  • Correction d'un échec d'authentification rare lorsque deux sessions récupèrent simultanément un verrou d'actualisation de connexion laissé par un processus en panne.
  • Correction de la vérification des autorisations de l'outil PowerShell ignorant les règles de refus et de demande, et mettant en cache cet échec pour des vérifications ultérieures, lorsque son analyseur de commandes ne parvenait pas à démarrer (par exemple lorsque la machine manquait de mémoire)

  • Correction d'une commande shell ou d'un hook annulé qui démarrait toujours et s'exécutait jusqu'à sa fin lorsque l'annulation arrivait pendant sa configuration.

  • Correction des plugins ignorant silencieusement un serveur MCP .mcpb fourni qui nécessite encore une configuration : /plugin, le message d'installation et claude plugin install le disent maintenant et pointent vers Configurer

  • [Claude Tag] Correction du paramètre de modèle par défaut dans les paramètres d'administration et dans la page de configuration d'un canal proposant des modèles que votre organisation ne peut pas utiliser, ce qui entraînait l'échec des sauvegardes ou des nouvelles sessions.
  • [Claude Tag] Correction de la note sous les messages Slack de Claude indiquant qu'elle répondait sur un modèle de secours, et pourquoi, disparaissant lorsque Claude a ensuite modifié ce message
  • [Code Review] Correction du menu d'organisation dans la boîte de dialogue « Ajouter un référentiel » de Code Review affichant uniquement quelques-unes de vos organisations GitHub ; il se charge désormais davantage à mesure que vous faites défiler
  • [Code Review] Amélioration de la vérification de Code Review pour indiquer quand REVIEW.md de votre référentiel n'a pas été appliqué, par exemple sur une très grande demande d'extraction ou lorsque REVIEW.md est un lien symbolique
