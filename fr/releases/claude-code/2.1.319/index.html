code-claude v2.1.319

Qu'est-ce qui a changé

  • Modification du mode automatique avec désactivation des indicateurs de télémétrie ou de fonctionnalité, y compris derrière les passerelles LLM : les appels que le serveur ne peut pas vérifier sont interrogés ou refusés, sans recours au classificateur intégré ; configurez CLAUDE_CODE_AUTO_MODE_SERVER=0 pour continuer à l'utiliser (Bedrock, Vertex et Foundry sont inchangés)
  • Modification du mode automatique derrière une passerelle LLM : CLAUDE_CODE_AUTO_MODE_SERVER=1 active la vérification côté serveur même avec CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS défini ; si les paramètres gérés définissent ce dernier, ils doivent également définir le 1
  • Ajout du support des tâches MCP dans le terminal : lorsqu'un serveur MCP exécute un appel d'outil en tant que tâche, Claude Code le déplace immédiatement en arrière-plan et indique à Claude le résultat une fois terminé.
  • Ajout de la variable d'environnement CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND pour que Claude Code attende une tâche MCP dans son appel d'outil au lieu de la déplacer immédiatement en arrière-plan
  • Ajout du paramètre permissions.denyInsteadOfPrompting : un appel d'outil qui attendrait une invite d'autorisation est refusé et le tour continue, dans les sessions de terminal, les sous-agents et les coéquipiers
  • Ajout de /claude-api latency-optimize pour trouver où votre code Claude API fait attendre les gens et essayer des réglages plus rapides par rapport à votre évaluation
  • Ajout de la variable d'environnement CLAUDE_CODE_DISABLE_FEATURE_FLAGS, qui arrête la récupération des indicateurs de fonctionnalités sans désactiver la télémétrie ; chaque drapeau utilise ensuite sa valeur par défaut intégrée
  • Ajout des dépenses pour aujourd'hui, cette semaine et ce mois-ci à /usage pour les développeurs derrière une passerelle d'applications Claude qui n'ont aucune limite de dépenses, lorsque la passerelle exécute cette version ou une version ultérieure.
  • Ajout de admin.pooled_conflict_rule et admin.pooled_priority_order à la passerelle des applications Claude, pour définir quel budget de groupe mutualisé paie en premier pour un développeur dans plusieurs groupes
  • Ajout d'un paramètre facultatif login_notice à la passerelle des applications Claude qui affiche un message défini par l'opérateur sur la page de vérification du navigateur de la passerelle et sur l'écran de connexion de Claude Code
  • Ajout de CLAUDE_GATEWAY_LOG_FORMAT=json à la passerelle des applications Claude : les lignes de log opérationnelles deviennent JSON avec severity, time et message, pour les collecteurs de logs qui lisent le niveau d'un champ
  • Ajout d'un avertissement de démarrage de la passerelle d'applications Claude pour le cas où le availableModels d'une autre stratégie autorise également un identifiant de modèle personnalisé qu'une stratégie répertorie par son nom.

  • [VSCode] Correction de la commande claude-vscode.toggleDictation démarrant la dictée dans chaque vue Claude ouverte à la fois ; il n'agit désormais que dans la vue que vous utilisez, et une seconde pression l'arrête
  • [VSCode] Correction du ralentissement du panneau de discussion lorsqu'une réponse avec de nombreuses clôtures mathématiques $$ non fermées, chacune plus courte que la précédente, est diffusée
  • [VSCode] Amélioration de l'outil de diagnostic du panneau de discussion pour les grands espaces de travail : il laisse de côté les fichiers sans problème, renvoie un JSON compact et accepte une gravité minimale facultative.
  • [Sessions Cloud] Correction des tâches planifiées supprimant silencieusement un connecteur nommé mémoire : les exécutions le conservent désormais, monté sous ce nom plus un court suffixe
  • [Sessions cloud] Correction de l'envoi maintenant d'un message en attente dans les sessions cloud mettant fin à l'exécution des agents en arrière-plan ; ils continuent maintenant à courir
  • [Sessions Cloud] Amélioration de l'avertissement de configuration bloquée sur les environnements auto-hébergés : son lien préfère désormais celui par défaut de votre organisation ou un environnement avec un exécuteur en direct, et le nomme
  • [Code Review] Modification de la dissociation d'une organisation GitHub pour désactiver également son paramètre Tous les référentiels dans Code Review ; il reste éteint après votre reconnexion jusqu'à ce que vous le rallumiez
  • [Claude Tag] Correction du lancement de la configuration de Claude Tag bloquant lorsque la liste des chaînes ne pouvait pas être complètement chargée ; les administrateurs peuvent désormais lancer sans choisir de chaîne
  • [Claude Tag] Ajout d'une ligne Claude Tag à la page d'administration des modèles pour les organisations d'entreprise avec Claude Tag connecté, établissant un lien vers l'endroit où les valeurs par défaut de son modèle sont gérées.
  • [Claude Tag] Correction du mode de sauvegarde automatique permettant aux règles dans les paramètres d'administration de Claude Tag d'écraser les modifications d'un autre administrateur ; la sauvegarde est maintenant refusée avec un message
