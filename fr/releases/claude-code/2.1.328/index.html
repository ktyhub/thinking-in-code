claude-code v2.1.328

Correctif Publié19 nov. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.328

Qu'est-ce qui a changé

  • Ajout du mode automatique pour Claude Opus 4.6 et Sonnet 4.6 sur Amazon Bedrock, la plateforme d'agent de Google Cloud, Microsoft Foundry et la passerelle d'applications Claude ; des sessions interactives sans mode d'autorisation y démarrent
  • Ajout de "onFailure": "block" pour les hooks mcp_tool, comme pour les hooks de commande et HTTP : un hook dont l'appel échoue bloque l'action
  • Ajout d'un avertissement lorsqu'un message d'une session qui ignore les invites d'autorisation peut être conservé et supprimé par une session cloud
  • Ajout d'un avis dans /status et claude doctor lorsqu'un exportateur OpenTelemetry n'a pas de point de terminaison et que ses données seraient probablement perdues
  • Ajout de CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME, qui permet à un hôte d'empêcher claude -p --resume et --continue d'exécuter un appel d'outil différé par un hook.
  • Ajout de la prise en charge des applications qui intègrent Claude Code pour activer l'option allowManagedModsOnly du plugin de stratégie ; les paramètres gérés par un administrateur gagnent toujours
  • Ajout d'un avertissement de démarrage à la passerelle des applications Claude lorsque le maxEffortLevel d'une stratégie n'est pas un niveau d'effort valide
  • Exécuteur auto-hébergé : Ajout de --repository-folder pour nommer le dossier que les sessions utilisent pour un référentiel sur --capacity 1, à la place de son chemin sous le dossier de base, qui ne peut pas être un lien symbolique
  • Runner auto-hébergé : ajout d'un avertissement de démarrage lorsque les paramètres de l'hôte sont définis. json définit un mode d'autorisation par défaut que les sessions ignorent
  • Exécuteur auto-hébergé : ajout de --hook-label à claude self-hosted-runner orchestrator, pour transmettre les étiquettes de session choisies au hook spawn-runner
  • Runner auto-hébergé : ajout de --metadata key=value à claude --environment, pour étiqueter une session pour le hook spawn-runner
  • Exécuteur auto-hébergé : ajout de claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds au /metrics de l'orchestrateur, afin que l'attente d'une session rouverte puisse être différenciée de celle d'une nouvelle.
  • Coureur auto-hébergé : ajout d'une métrique d'orchestrateur, claude_code_self_hosted_orchestrator_sessions_given_up_total, qui compte en fonction de la fréquence à laquelle Anthropic a abandonné le démarrage d'un coureur pour une session.
  • Correction des commandes Bash dans zsh s'arrêtant avec une erreur « introuvable » à un mot commençant par =, tel que echo ==== ou [ a == b ] ; =cmd ne s'étend plus au chemin d'une commande
  • Correction du compactage automatique réutilisant l'invite système précédente de la session au lieu de la reconstruire comme le fait /compact
  • Correction du gel du rendu des démarques sur certaines entrées très longues ou mal formées
  • Correction de rares blocages d'écran
  • Correction de la perte fréquente de l'Esc lors d'une invite d'autorisation ou d'une question lorsque vous tapiez juste après ; dans les terminaux qui envoient Alt comme Echap et une touche, une touche Alt ou Option inutilisée y est désormais declines
  • Correction d'un collage ou d'une réponse d'un terminal tapé dans l'invite lorsqu'une connexion lente la coupait en deux
  • Correction de l'enregistrement d'une tâche planifiée effaçant les autres tâches enregistrées du projet lorsque le fichier des tâches planifiées ne peut pas être lu, sur des fournisseurs tiers ou avec des indicateurs de télémétrie ou de fonctionnalité désactivés
  • Correction d'une tâche planifiée avec une faute de frappe dans le fichier de tâches planifiées du projet qui était supprimée la prochaine fois que ce fichier était enregistré
  • Correction d'un cas où une session cloud reprise pouvait perdre son résumé de compactage ou ses messages récents lorsqu'un message était enregistré tardivement.
  • Correction du nombre de jetons sur le spinner et pour les sous-agents comptant deux fois une réponse réessayée, manquant les réponses qui n'étaient pas diffusées et restant immobiles pendant que Claude réfléchissait
  • Correction de l'erreur affichée lorsque les crédits d'utilisation sont épuisés au milieu d'une réponse, qui nommait une limite de débit
  • Correction du mode automatique qui échouait à chaque tour en dehors de Claude Desktop avec CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS défini derrière une passerelle rejetant les versions bêta, sur la passerelle des applications Bedrock, Agent Platform, Foundry ou Claude.
  • Correction de CLAUDE_STREAM_IDLE_TIMEOUT_MS n'allongeant pas la limite de connexion de 5 minutes sur les passerelles, les URL de base personnalisées et les fournisseurs de cloud
  • Correction de certaines sessions Claude Desktop sur des fournisseurs tiers, autres que les tâches planifiées, se terminant définitivement par "L'invite est trop longue" après des résultats d'outils volumineux ; les plus gros sont désormais laissés de côté
  • Correction des outils MCP dont le schéma d'entrée commence par anyOf, oneOf ou allOf disparaissant sur les fournisseurs tiers ou avec des indicateurs de télémétrie ou de fonctionnalité désactivés
  • Correction d'un outil MCP avec un schéma d'entrée invalide qui échouait dans les requêtes auprès de fournisseurs tiers ou avec des indicateurs de télémétrie ou de fonctionnalité désactivés ; l'outil est maintenant laissé de côté et on explique à Claude pourquoi
  • Correction de l'effort désactivé pour le modèle d'un sous-agent pour la session si Bedrock, la plateforme d'agent de Google Cloud ou Foundry refusait le paramètre d'effort de son résumé de progression (régression dans 2.1.327)
  • Correction du mode Code arrêtant un script lorsqu'une invite d'autorisation en dehors du mode automatique ou de contournement, une approbation de plan ou une question restait ouverte pendant dix minutes
  • Correction des scripts en mode code en modes d'autorisation automatique et de contournement qui ne parvenaient pas à appeler un serveur MCP qui s'était connecté pendant l'exécution du script précédent.
  • Correction des scripts du mode Code ne s'exécutant pas en arrière-plan en mode auto ou contournement des autorisations dans une session choisie dans le sélecteur claude --resume
  • Correction du mode Code perdant une compétence chargée, un contexte de hook ou une note saisie avec une approbation d'autorisation lors de la reprise d'une session dans laquelle une réponse exécutait plusieurs scripts
  • Correction de Claude n'étant pas informé qu'un script du Mode Code était coupé lors de la reprise de la session depuis le sélecteur ou dans un mode qui demande la permission
  • Correction du mode code en utilisant silencieusement undefined pour les variables de niveau supérieur qu'un script précédent ayant échoué n'avait jamais défini
  • Correction des scripts du mode Code qui n'étaient pas informés lorsque la longue sortie d'une commande défaillante était coupée
  • Correction du mode Code refusant les scripts valides commençant par un bloc {
  • Correction du mode Code refusant les scripts utilisant à la fois un await de niveau supérieur et un return de niveau supérieur
  • Correction d'un petit fichier mentionné par @ qui n'était pas joint en mode Code après qu'un script l'ait lu ou écrit
  • Mode code fixe offrant write() et edit() aux sous-agents en lecture seule qui ne peuvent pas les appeler
  • Correction de Claude démarrant tout seul un tour en Mode Code lorsque Esc était suivi d'une commande telle que /model
  • Correction de Claude en mode Code qui ne se voit pas demander d'exécuter des workflows uniquement lorsque vous le demandez, ou la taille du workflow que vous avez définie dans /config
  • Correction de la télécommande répétant le même message de déconnexion et vous demandant de réessayer une session qui ne peut pas se reconnecter
  • Correction d'une invite d'autorisation d'attente perdue et sa réponse ignorée lorsqu'une session à distance redémarrait alors que le service était lent
  • Correction des sessions cloud reprenant une conversation effacée après un rembobinage suivi de /clear
  • Correction d'une session à distance perdant les appels et les résultats d'un tour lorsque son exécutant ou son travailleur était perdu après qu'un flux de modèle abandonné ait été réessayé.
  • Correction des sessions cloud et de contrôle à distance qui viennent de démarrer, ou qui ont un @ dans leur titre, étant inaccessibles dans la messagerie inter-sessions à partir d'une session avec contrôle à distance activé.
  • Correction du message indiquant à Claude que les sessions cloud ne pouvaient jamais répondre ; il apprend maintenant quand une réponse peut arriver et comment obtenir le résultat autrement
  • Correction de /diff, du volet Modifications des sessions de contrôle à distance et du diff à côté d'une modification laissant de côté le travail validé après le déplacement d'une commande dans un autre référentiel
  • Correction du contrôle à distance n'affichant pas les agents d'un workflow en cours d'exécution lorsqu'une session exécutée par une extension IDE ou une autre application SDK est ouverte plus d'une heure après la dernière progression du workflow
  • Contrôle à distance : correction d'une session inactive de bureau ou de VS Code affichée comme étant en cours d'exécution après l'activation du contrôle à distance.
  • Correction du modèle indiquant que les agents en arrière-plan étaient toujours en cours d'exécution après qu'une interruption SDK les ait arrêtés
  • Correction d'Envoyer maintenant dans l'application de bureau et les hôtes SDK informaient Claude qu'une recherche Web arrêtée n'avait trouvé aucun résultat
  • Correction de Cmd+lettre tapée dans l'invite dans les terminaux qui signalent Cmd
  • Correction de Ctrl+click ouvrant un lien deux fois dans le terminal GNOME, les boutons latéraux de la souris agissant comme des clicks, et la première encoche de la molette dans l'autre sens étant ignorée après une pause, en mode plein écran
  • Correction des raccourcis Shift+Enter dans Konsole en dehors de tmux et ssh, et Alt sur les dispositions de clavier non latines dans les terminaux qui parlent le protocole Kitty Keyboard
  • Linux : Correction du blocage du collage dans d'autres applications lorsque Claude Code est suspendu avec Ctrl+Z, lorsque xclip ou wl-copy est installé
  • Linux : Correction de Ctrl+V manquant l'image clipboard, collant une ancienne ou bloquée
  • Correction du texte copié en mode plein écran, y compris la barre de citation, perdant des espaces aux retours à la ligne lorsqu'un glissement défilait vers le haut, ou des mots manquants sous la pilule "Aller vers le bas".
  • Correction d'un chemin d'image collé dans une commande ! devenant une pièce jointe
  • Correction de Ctrl+C n'affichant aucun avertissement de sortie lorsque la liste des raccourcis ? est ouverte
  • Correction de la recherche Ctrl+R en mode plein écran et de l'éditeur de couleurs /theme sélectionnant la mauvaise ligne lorsque les clés arrivent ensemble, et les clés étant déposées là et dans la recherche de /config et /plugin
  • Correction des couleurs incorrectes ou manquantes dans l'écran GNU
  • Correction de nombreuses notifications en arrière-plan coupant la bordure supérieure des boîtes de dialogue ouvertes en mode plein écran
  • Correction d'un message envoyé à un agent en arrière-plan affichant un long chemin de fichier à la place d'une image collée
  • Correction de /goal supprimant le crochet d'arrêt d'une compétence ou se terminant plus tôt sur le résultat d'un autre crochet, lorsque les deux avaient le même libellé.
  • Correction de /bug disant annulé après l'envoi du rapport

  • Correction du /hooks qui perdait sa place au retour
  • Correction de /export écrivant un fichier nommé .txt lorsque le nom était laissé vide
  • Correction de /terminal-setup dans Zed remplaçant un keymap.json lié symboliquement par un fichier simple
  • Correction de /install-github-app ajoutant un workflow de révision de code lorsqu'on lui a demandé de mettre à jour le fichier de workflow existant
  • Correction de /plugin rouvrant une compétence ou fermant la page ouverte lorsqu'une sauvegarde ou une suppression lente se terminait après votre retour
  • Correction de /plugin demandant de désinstaller le mauvais plugin, ou ignorant Esc, après avoir quitté un plugin alors qu'une modification était encore en cours
  • Correction de la saisie et des touches fléchées ne fonctionnant pas sur l'onglet /plugin Installé après une recherche sans résultat ou un click sur la ligne de l'onglet
  • Correction du maintien de Enter dans /plugin désactivant plusieurs plugins installés
  • Correction du total du plugin /usage s'arrêtant à 2 000 jetons sur 1 million de modèles de contexte et des estimations de jetons faibles dans /usage et /plugin lorsqu'aucun modèle n'est sélectionné
  • Correction de l'Esc sur l'étape des touches d'accès Bedrock fermant /login au lieu de revenir en arrière
  • Correction de /exit et Ctrl+D décrivant différemment le travail en cours, et /exit avertissant d'un flux de travail arrêté
  • Correction de Claude appelant un artefact privé après en avoir lu un dans un dossier partagé ou publié dans celui d'une autre organisation, et indiquant que seules les personnes nommées peuvent en ouvrir un lorsque les personnes de son dossier le peuvent également.
  • Correction du toast d'un plugin affichant parfois le texte d'un autre plugin
  • Correction d'un mod sauvegardé juste après le début d'un tour, parfois rechargé en milieu de tour plutôt qu'à la fin du tour.
  • Correction d'une entrée OTEL_RESOURCE_ATTRIBUTES mal formée supprimant les autres étiquettes de la variable des points métriques, des événements et des étendues. Maintenant, seule cette entrée est laissée de côté
  • Correction des hooks d'agent dépassant leur délai d'attente lors du compactage après qu'une requête ait été refusée car trop volumineuse
  • Correction d'un crash au démarrage lorsque FORCE_COLOR est réglé sur un nombre négatif
  • Correction d'un crash dans le masquage secret lorsque la machine est presque à court de mémoire
  • Correction du sandbox Bash sous Linux renommant .git/HEAD après chaque commande lorsque le nom de branche n'est pas valide UTF-8
  • Exécuteur auto-hébergé : correction de l'arrêt de toutes les sessions en cours lorsqu'un proxy ou un filtre Web répondait à un sondage avec HTTP 200 et un corps tel que {} ; le coureur réessaye maintenant un tel sondage
  • Runner auto-hébergé : Correction de la suppression des objets ou références d'un clone conservé, et des commits qui n'existaient que là, après une erreur de disque temporaire ; ce démarrage échoue maintenant à la place
  • Correction des coureurs auto-hébergés s'arrêtant lorsque leur jeton était épuisé sur un hôte dont l'horloge est lente ou était en retard
  • Exécuteur auto-hébergé : correction des sessions avec git géré par Anthropic perdant l'accès git à GitHub après qu'un script ou un hook dans la session ait à nouveau exécuté claude
  • Correction des coureurs auto-hébergés avec git géré par Anthropic incapables de récupérer ou de pousser là où la configuration git de la machine définit http.proactiveAuth
  • Exécuteur auto-hébergé : correction d'un exécuteur qui se quittait sans informer le serveur en cas d'échec de l'installation après son enregistrement ; il se désenregistre maintenant avec une raison et un coureur à la demande signale l'échec du démarrage
  • Exécuteur auto-hébergé : correction de l'archivage ou de la remise en file d'attente d'une session ne prenant pas effet pendant qu'elle attendait une autre session pour préparer le même référentiel (--capacity au-dessus de 1)
  • Coureur auto-hébergé : correction d'une session avec un .claude.json endommagé échouant à chaque démarrage ultérieur sous --trust-workspace false ; il démarre maintenant par défaut, avec les serveurs MCP éteints et réactivés
  • Coureur auto-hébergé : correction d'un message de démarrage échoué, perdant les mots indiquant ce qui a échoué lorsqu'un hook de paiement ou un git imprimait beaucoup
  • Correction du runner auto-hébergé sautant son hook post-session lorsqu'un disque bloquait pendant quelques secondes ; sur un disque mort, la fin d'une session peut prendre 25 secondes de plus par défaut
  • Correction des runners auto-hébergés : une session qui reprend dans un nouveau répertoire de config Claude ne perd plus sa liste de tâches
  • Correction de Claude qui n'est pas informé du démarrage d'une session auto-hébergée sans l'un de ses référentiels, et pourquoi
  • Runner auto-hébergé : Correction de --correlation-id de claude --environment n'atteignant pas le hook spawn-runner
  • Correction du conseil de rotation des clés de l'assistant de configuration du coureur auto-hébergé, qui avertit désormais que la révocation d'une clé arrête les sessions exécutées sous celle-ci.
  • Sessions claude -p et SDK améliorées pour récupérer les plugins de paramètres gérés qui ont leur propre référentiel git, en arrière-plan, pour une session ultérieure
  • Amélioration de la rapidité avec laquelle les plugins de paramètres gérés d'un marché Git se chargent sur une nouvelle machine dans les sessions claude -p, SDK et Claude Desktop ; une courte course peut se terminer jusqu'à 30 secondes plus tard
  • Amélioration du temps de reprise des grandes sessions
  • Amélioration de l'utilisation de la mémoire lors de la reprise d'une session avec de nombreuses images
  • Amélioration de l'utilisation de la mémoire et du temps de réponse dans les longues sessions SDK et de bureau qui exécutent des commandes ou des outils lents
  • Amélioration de la vitesse du mode Code dans les modes d'autorisation automatique et de contournement en supprimant une seconde pause 0.75 après la plupart des scripts
  • Amélioration de la mise en cache des invites pour les nouvelles sessions en mode Code comportant des serveurs MCP, et Claude est désormais informé lorsqu'un serveur est toujours en cours de connexion et lorsque la liste des serveurs change
  • Utilisation améliorée des jetons du mode Code avec des descriptions d'outils plus courtes
  • Mode Code amélioré pour afficher la commande qu'un script est en cours d'exécution et sa sortie pendant son exécution
  • Modifications améliorées en mode Code : une modification qui ne change rien n'arrête plus un script, et Claude est informé de l'endroit où une modification échouée correspond ou s'en rapproche le plus.
  • Mode Code amélioré : Claude sait désormais quels appels d'outils étaient encore en cours d'exécution lorsqu'un script a échoué
  • Amélioration de la façon dont Claude démarre les serveurs de développement dans les modes automatique et contournement du mode Code : Claude est invité à les exécuter en tant que tâches en arrière-plan qui s'affichent dans /tasks
  • Windows : Mode Code amélioré en indiquant à Claude que les commandes shell des scripts s'exécutent dans Git Bash et que les alias PowerShell s'exécutent à la place des fonctions du même nom
  • Amélioration du démarrage simultané de plusieurs coéquipiers en cours : beaucoup moins d'échecs avec "Le fichier de verrouillage est déjà détenu"
  • Amélioration de la boîte de dialogue d'approbation de l'utilisation de l'ordinateur : elle affiche désormais le niveau d'accès de chaque application et des avertissements plus clairs
  • Messagerie inter-session améliorée : Claude explique désormais que le contrôle à distance est désactivé lorsqu'une session cloud ou un autre ordinateur n'est pas répertorié
  • Amélioration de la sortie texte claude -p pour indiquer sur stderr lorsqu'un message d'une autre session est mis en attente ou supprimé, et comment l'autoriser
  • Amélioration des réponses de Claude sur qui peut ouvrir un artefact qu'il a publié : il est désormais demandé à Claude de vérifier à nouveau l'artefact au lieu de répéter la réponse de la dernière publication.
  • Amélioration de la reprise des sessions de coureur auto-hébergées : Claude vérifie désormais si son travail antérieur est toujours là et dit ce qui manque
  • Modification du mode plan et des invites Bash pour Opus 4.6 et Sonnet 4.6 sur les fournisseurs tiers afin d'utiliser et de proposer le mode automatique, comme sur les modèles plus récents ; disableAutoMode éteint les deux
  • Modification du mode Code pour ne plus exécuter les hooks UserPromptSubmit, y compris ceux gérés, sur la sortie des scripts ; pour rédiger cette sortie, utilisez un hook PostToolUse avec updatedToolOutput
  • Modification de /code-review sur la plupart des modèles pour signaler uniquement les bugs et les violations CLAUDE.md ; exécutez /simplify pour des nettoyages de réutilisation, de simplification et d'efficacité
  • Modification de /code-review pour marquer chaque résultat Important, Préexistant ou Nit sur la plupart des modèles, et pour terminer chaque résumé par une suggestion de correctif ; la liste d'une révision propre indique désormais « La révision du code n'a trouvé aucun problème. »
  • Modification des entrées deniedMcpServers du formulaire claude.ai <name> pour s'appliquer également à ce connecteur dans les sessions cloud et les sessions d'exécution auto-hébergées.
  • Modification des hooks gérés PostToolUse pour ne plus se déclencher pour les appels refusés avant leur exécution : pas d'entrée de journal, de réécriture, de blocage ou d'arrêt à cet endroit ; PostToolBatch obtient le maximum, mais n'est pas marqué comme refusé
  • Modification de /bug pour demander Oui ou Non avant l'envoi, donc les entrées répétées n'envoient plus de rapport ni n'ouvrent GitHub
  • Modification des sous-agents dans claude -p, l'agent SDK, le bureau et VS Code pour attendre leurs propres sous-agents par défaut lorsque CLAUDE_CODE_FORK_SUBAGENT=0 est défini
  • Remplacement de claude -p par CLAUDE_CODE_FORK_SUBAGENT=0 pour compter un sous-agent d'arrière-plan et ceux qu'il attend contre une attente de 10 minutes ; soulever le CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS pour des chaînes plus longues
  • Modification d'une commande shell réécrite par un hook PermissionRequest en une commande exclue du bac à sable pour s'exécuter en dehors du bac à sable
  • Modification de l'écran d'accueil de Claude dans Chrome et de /chrome pour indiquer que Claude Code demande avant que Claude n'agisse sur un site, à moins que votre mode d'autorisation ou une règle dans /permissions ne réponde
  • Modification des sessions Claude Desktop et Agent SDK sur des fournisseurs tiers ou avec des indicateurs de télémétrie ou de fonctionnalité désactivés pour terminer le tour lorsqu'il est fermé avec une question ouverte, au lieu de continuer sans réponse
  • Modification du texte collé pour qu'il soit marqué pour Claude comme collé, sur des fournisseurs tiers ou avec la télémétrie ou les indicateurs de fonctionnalité désactivés
  • Modification des résumés de progression des sous-agents dans les sessions de terminal sur l'Anthropic API pour qu'ils soient écrits par le petit modèle rapide par défaut à partir de notes courtes, également avec la télémétrie désactivée, en utilisant beaucoup moins de jetons
  • Modification de la façon dont un bac à sable qui ne peut pas démarrer est signalé, à moins que sandbox.failIfUnavailable ne soit défini : la prochaine commande Bash en bac à sable est refusée et indique que le bac à sable est désactivé pour la session.
  • Modification de /list-agents pour afficher sa liste uniquement pour vous ; Claude répertorie lui-même les séances en cas de besoin
  • Exécuteur auto-hébergé : modification du gh api intégré pour qu'il soit désactivé par défaut, les paramètres protégeant les outils GitHub de Claude par leur nom ; --use-anthropic-gh true l'allume
  • Exécuteur auto-hébergé : modification d'un claude qu'un script wrapper exécute avant que le propre claude de la session ne soit opérationnel, ou après sa fin, pour qu'il n'y ait pas de git géré par Anthropic.
  • Coureur auto-hébergé : modification de CLAUDE_RUNNER_SESSION_UUID et CLAUDE_CODE_REMOTE_SESSION_UUID pour qu'ils soient tous deux définis pour la session et ses hooks checkout, post-session et spawn-runner
  • Modification des exécuteurs auto-hébergés sur --capacity 1 pour refuser une session plus tôt lorsque le chemin d'un référentiel vers lequel il pousse est un lien symbolique
  • [VSCode] Ajout d'une notification lorsqu'un message d'une autre session est mis en attente, avec un lien vers le fichier de paramètres qui peut l'autoriser
  • [VSCode] Correction de l'invite d'autorisation coupant son bouton Non, son champ de réponse ou son titre lorsque le panneau est bas ou qu'une commande, une URL ou une description est longue
  • [VSCode] Correction des appels d'outils échoués ou bloqués ne montrant aucune raison ou une raison interrompue, et Glob et Grep comptant une erreur comme résultats
