Faits saillants

Cette version contient 762 commits de 315 contributeurs (104 nouveaux) !

  • Nouveaux modèles : DeepSeek-V4.1-Flash (#56214, #56228, #56208) avec l'intégralité du KV stocké dans MXFP8 via l'enregistrement FlashMLA V4.1 sur SM100 (#56893), DeepGEMM Mega-mHC (#56962) et prélecture asynchrone d'Engram avec partitionnement Engram DP (#56512) ; DeepSeek-V4-Flash-Vision-Exp (#54566), également sur ROCm (#55107) et avec LoRA (#55897) ; GLM-5.3-Flash (#53906) avec EPLB (#55119) ; K2-Horizon (#55063) ; Boussole Cohere (n° 54774) ; Mise en liberté sous caution V3 VL (#55921) ; Nanbeige4.2 via le backend Transformers (#56071) ; et un backend CPU DeepSeek-V4 avec des noyaux MLA, indexeur, mHC et compresseur clairsemés AVX512/AMX (#55355).
  • Démarrage rapide : un démon de cache de poids persistant par GPU conserve les poids post-quantifiés et fragmentés TP dans la mémoire GPU afin que les moteurs de redémarrage les mappent sur CUDA IPC avec --load-format ipc_cache au lieu de recharger à partir du disque (#54921), couvrant désormais les points de contrôle FP4 (#55465) et les TP multi-nœuds (#55468).
  • Filigrane : génération et détection de filigranes Gumbel-max avec un PRF à clé, désinscription par demande et un exemple de point final de détection (#54053) ; le Gumbel-max à double clé le rend compatible avec le décodage spéculatif (#56122) ; l'interface Rust transmet les contrôles par requête (#56338).
  • HiSparse : un niveau hôte-résident pour le décodage MLA clairsemé qui transmet les pages KV à la mémoire hôte épinglée sous la pression du GPU et sert les k échecs d'un tampon chaud GPU par requête, activé via HiSparseConnector (#53781), avec des compteurs Prometheus (#56061), un cache d'hôte partagé entre les rangs TP (#56629) et la configuration d'attention déduite du connecteur. (#57041).
  • Model Runner V2 : chevauchement de deux lots en mode impatient (#50945) et avec graphiques FULL CUDA pour les étapes microbatch (#51700) ; Décodage spéculatif MTP (#46994) et EAGLE3/DFlash/DSpark (#50514) sous parallélisme de pipeline ; vérification adaptative pour chaque spéculateur de projet de modèle via un estimateur d'acceptation en ligne (# 52228) ; gc gelé pendant la capture du graphique, réduisant la capture de 12 s à 2 s et l'initialisation du moteur de 28,9 s à 8,2 s sur H200 (#54646) ; --return-sampling-mask compacté sur GPU, corrigeant une régression pas à pas d'environ 2x RL (#54901).
  • Performances Qwen3.8-Flash-Next : noyaux d'indexeur QSA de pré-remplissage et de décodage séparés (#54513), noyaux PLE fusionnés (#54517), cache d'indexeur FP8 (#54890), saut d'index rembourré dans GQA clairsemé (#54873), résiduel PLE fusionné et porte de sortie QSA (#55309), déchargement UVA PLE et parallélisme du tenseur Engram via --engram-config (#54371) et torch.compile ont été supprimés de l'implémentation NVIDIA afin que FP8 s'adapte à un seul GB300 (#55272).
  • Performances Kimi K3 : natif CUDA AttnRes par défaut sur SM100 (#54261), collecte/diffusion de lots mixtes KDA supprimées (débit 5.2-7.7% E2E, #56159), insertion de cache MLA FP8 groupée (accélération du noyau 4 à 6x pour les petits lots, #55356), GEMM à faible latence DSV3 sur les tenseurs striés (12-81 % accélération du noyau, #54565), projections TP8 KDA superposées (#54697), noyaux FlashInfer KDA (#55364), points de contrôle de préfixes internes avec mise en cache partielle des préfixes et décodage spéculatif (#53614) et désagrégation DCP symétrique pour les modèles hybrides Mamba (#55531).
  • Service à grande échelle : PCP+DCP sur les modèles MLA clairsemés (#56157), PCP avec MTP à module unique et DSpark répliqué (#56107) et graphiques FULL CUDA en décodage uniquement (#53867), Elastic EP réutilisant les graphiques CUDA lors de la reconfiguration (#54985), une réduction totale FlashInfer PCIe IPC optionnelle pour les boîtiers sans NVLink. (#53576), DeepEP v2 async finalise les experts partagés qui se chevauchent avec Combine (#52781), le partage TP hétérogène Mooncake Store (#53129), un adaptateur KVCR de niveau secondaire (#53624) et le partage de cache d'encodeur sur NIXL (#47941) et Mooncake (#41567).
  • Quantisation : quantification en ligne ciblée via quantization_config.targets (#51285) et sur des points de contrôle partiellement pré-quantifiés de n'importe quelle méthode quant (#51392), W4A16 DSA avec le cache KV nvfp4_fp8_ds_mla (#51724), FlashInfer CuTeDSL NVFP4 W4A16 par défaut sur Marlin sur SM100/103 (#53014), NVFP4 dans le backend de la torche linéaire (#53319), remplacements de backend linéaires par quantification (#51204), AutoRound 2/3/5/6/7 bits sur CUDA (#52890) et DeepSelect top-k pour l'indexeur clairsemé DSA (#56464).

Dernières modifications et dépréciations

  • Les points de terminaison évolutifs (/render, /derender, /inference/v1/generate) ne sont plus enregistrés sur vllm serve simple, à moins que --enable-scale-out ne soit transmis ; VLLM_ENABLE_SCALE_OUT_ENDPOINTS a été supprimé. vllm launch render et vllm serve --tokens-only les enregistrent toujours (#54579, #55176).
  • Ordre d'activation dynamique/groupe GPTQ supprimé : g_idx est ignoré et les noyaux Marlin, GPTQ, CPU et RDNA3 associés ont disparu (#54809).
  • Éléments obsolètes pour 0.29 supprimés : variables d'environnement VLLM_PREFIX_CACHE_RETENTION_INTERVAL et VLLM_MM_HASHER_ALGORITHM (utilisez les champs de configuration), l'alias use_fp4_indexer_cache (utilisez indexer_kv_dtype), la solution de secours CUDA_VISIBLE_DEVICES sur ROCm (utilisez HIP_VISIBLE_DEVICES) et les propriétés des métadonnées d'attention seq_lens_cpu / num_computed_tokens_cpu. (#55353).
  • Le mode cache all Mamba est obsolète et revient à Model Runner V1 (#55041).
  • python -m vllm.entrypoints.grpc_server est obsolète ; utilisez le vllm serve --grpc (#56746). sse_keep_alive a été déplacé vers vllm.entrypoints.serve.utils (#56369).
  • YaRN aligné sur Transformers : les alias YaRN du fournisseur ne multiplient plus max_position_embeddings par le facteur une seconde fois, donc le max_model_len dérivé chute pour certains modèles (TeleChat3-36B-Thinking 131072 à 32768, sarvam-105b 5242880 à 131072) ; attn_factor et extrapolation_factor sont ignorés au profit de mscale/attention_factor (#56446).
  • Attention, les implémentations doivent déclarer explicitement la prise en charge de DCP ; DCP avec l'attention standard ROCm, Triton, FlexAttention ou TurboQuant échoue désormais lors de la sélection du backend (#55780).
  • Le mode WRITE du connecteur MoRI-IO avec groupes de cache KV hybrides nécessite désormais --disable-hybrid-kv-cache-manager ; sinon, utilisez le mode READ (#53721).
  • Le rééchantillonneur audio par défaut est passé de PyAV à torchaudio (#52598) ; le décodage audio est sélectionnable par le backend avec le fichier son en premier dans auto (#51826, #55642).
  • Nouveaux paramètres par défaut : FlashInfer CuTeDSL NVFP4 W4A16 sur Marlin sur SM100/103 (#53014), W4A4 NVFP4 sur les noyaux à poids uniquement sur SM120/121 (#55170), routeur BF16x3 GEMM sur SM100 (#55899), DeepEP v2 combine le chevauchement avec VLLM_DEEPEP_V2_COMBINE_OVERLAP=0 pour désactiver (#52781), AITER personnalisé AG/RS activé pour l'attention DP + experts TP avec VLLM_ROCM_USE_AITER_CUSTOM_AR=0 à désactiver (#48247), CUDA AttnRes natif pour Kimi-K3 sur SM100 (#54261) et VLLM_USE_BREAKABLE_CUDAGRAPH=1 ne remplaçant plus les graphiques COMPLETS sur MRV1 (#56312).
