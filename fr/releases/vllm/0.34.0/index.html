TL;DR

  • 10 nouveaux modèles (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, et plus encore !)
  • Le cache KV extensible est activé par défaut : vLLM dimensionne le cache KV à partir de la mémoire réellement libre après le préchauffage, de sorte que la plupart des modèles bénéficient d'un cache plus grand et d'un débit plus élevé.
  • Model Runner V1 a disparu. Model Runner V2 est désormais le seul exécuteur GPU.
  • Grandes accélérations sur Blackwell et MI355X : jusqu'à 1.95× décodage (étape 5 sur GB200), débit 1.6× (GLM-5.3-Flash), 1.24–1.40× TTFT à invite longue plus rapide (GLM-5.3).
  • Contrôle de mise à niveau : la taille de bloc par défaut est désormais de 64, les images ROCm 7.2 ont disparu et huggingface_hub >= 2.0.0 est requis. Voir Avant de mettre à niveau.

Faits saillants

Cache KV extensible, activé par défaut

  • Sur CUDA et ROCm, le cache KV est dimensionné à partir de la mémoire réellement libre après la capture et l'échauffement du graphique CUDA, et non à partir d'une estimation (#56492).
  • Résultat : un cache plus grand (par exemple MiniMax-M3 sur H200 : 433 000 → 672 000 jetons), donc le débit est plus élevé et le TTFT inférieur à une simultanéité élevée.
  • Compromis : la latence de décodage par jeton peut augmenter sur certains modèles (TPOT +6 à 18 % sur certains modèles H200 avec une simultanéité de 128). Désactivez-vous avec --gpu-memory-utilization 0.9 ou --no-enable-extensible-kv-cache.
  • Renforcé avec des correctifs pour la fragmentation de l'allocateur, les MOO de démarrage et les connecteurs KV (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Modèle Runner V2 uniquement

  • Le modèle Runner V1 est supprimé (#63373).
  • Le chevauchement double lot s'exécute désormais sur MRV2, y compris avec le décodage spéculatif et DCP (#61464).

Décodage spéculatif

  • Le décodage des suffixes fonctionne sur MRV2 avec un spéculateur GPU ; L'inférence arctique n'est plus nécessaire (#60339).
  • Spéculateurs personnalisés : configurations déclaratives plus un plugin register_speculative_method API (#63205).
  • Graphiques CUDA pour les spéculateurs du projet de modèle MRV2 (#60989).
  • La vérification adaptative fonctionne avec XPress (#65175).
  • Le cache Draft KV correspond au type de la cible, donc une cible FP8 obtient un cache Draft FP8 (#65198).

  • Les images de sortie et les roues sont ROCm 10.0 uniquement (#61939). -MoRI EPv2 via --all2all-backend mori (#61361).
  • Décodage spécialisé Kimi-K3 sur MI355X, opt-in (#61435).
  • TRITON_ATTN est le backend d'attention par défaut sur RDNA3 et RDNA4 (#60418).

Service et opérations

  • Point de contrôle/restauration (CRIU + cuda-checkpoint) via /checkpoint/prepare, /checkpoint/status et /checkpoint/restore, dans les interfaces Python et Rust (#62570).
  • Réduction DP+EP tolérante aux pannes : les rangs morts sont supprimés et leurs experts redis sont rendus sans redémarrage (#46370).
  • Au mieux Liaison NUMA activée par défaut (#61258).
  • Commande opt-in admission avec prise en charge du cache (#54625).
  • Frontend Rust : sans état Réponses API (#63902) et n > 1 (#65625).
