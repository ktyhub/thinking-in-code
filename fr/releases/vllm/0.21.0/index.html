#vllm v0.21.0

Faits saillants

Cette version contient 367 commits de 202 contributeurs (49 nouveaux) !

  • Transformers v4 obsolète : cette version abandonne officiellement la prise en charge de transformers v4 (#40389). Les utilisateurs doivent migrer vers transformers v5.
  • Exigence de build C++20 : vLLM nécessite désormais un compilateur compatible C++20 pour la compatibilité avec PyTorch (#40380). Il s'agit d'un changement de build révolutionnaire.
  • Déchargement KV + allocateur de mémoire hybride (HMA) : le sous-système de déchargement KV s'intègre désormais à l'allocateur de mémoire hybride, y compris la prise en charge des groupes de fenêtres coulissantes côté planificateur et l'activation complète de HMA (#41228, #41445, #39571).
  • Décodage spéculatif avec budget de réflexion : le décodage spéculatif respecte désormais les budgets de raisonnement/de réflexion, permettant un décodage de spécifications correct pour les modèles de raisonnement (#34668).
  • Backend TOKENSPEED_MLA sur Blackwell : Un nouveau backend d'attention TOKENSPEED_MLA est disponible pour le pré-remplissage + décodage DeepSeek-R1/Kimi-K25 sur les GPU Blackwell (#41778).

Prise en charge des modèles

  • Nouvelles architectures : MiMo-V2.5 (#40967), Laguna XS.2 (#41129, #41880), Moondream3 (#32325), Qianfan-OCR (#40136), Cohere MoE (#40817), Cohere Eagle (#42078).
  • Décodage spéculatif : EAGLE pour Mistral (#41024), Gemma4 MTP (#41745), MTP pour MiMo-V2.5 (#41905), Cohere Eagle (#42078).
  • DeepSeek V4 : prise en charge d'AMD/ROCm (#40871), parallélisme de pipeline (#41694), effort de raisonnement max (#40982), correctifs de service désagrégés (#41957).
  • Appel d'outils : raisonnement Cohere et analyseurs d'outils (#40422), analyseur d'outils LFM2/2.5 (#39243).
  • Gemma3/Gemma4 : prise en charge des variantes hidden_act (#40588), correctif de parallélisme de pipeline (#40786), correctifs MoE (#41206, #41574, #41401), correctif de crash de l'analyseur d'outils (#41991, #42188).
  • Model Runner V2 : prise en charge du modèle hybride Qwen3.5/Mamba (#35520), prise en charge logprob_token_ids (#40559).
  • Graphique CUDA : prise en charge du graphique ViT CUDA pour Qwen2.5-VL (#40830).
  • Compatibilité : fournisseur HCXVisionConfig pour Transformers v5 (#38447), prise en charge du point de contrôle rope_type hérité (#41734).

Noyau du moteur

  • Déchargement KV + HMA : groupes de fenêtres coulissantes côté planificateur (#41228), activation HMA complète (#41445), HMA multi-connecteurs (#39571), achèvement du magasin par tâche (#39186), prise en charge DCP/PCP dans OffloadingConnector (#41549), MooncakeStoreConnector pour le déchargement KV distribué (#40900).
  • Décodage spéculatif : soutien budgétaire de réflexion (#34668), sélection back-end d'attention du rédacteur indépendant (#39930), prise en charge du modèle multimodal avec avertissement (#41752), élimination de l'allocation par étape (#41043).
  • Model Runner V2 : correctif du taux d'acceptation de l'échantillonnage de rejet (#40651), ignorer la reconstruction des métadonnées avant le pré-remplissage du brouillon (#40410), reconstruire les métadonnées entre les étapes de décodage du brouillon (#41162), prise en charge hybride Qwen3.5/Mamba (#35520).
  • Routage : remplacez la relecture de routage par le cache de périphérique et le pipeline D2H asynchrone (# 39917).
  • Ray : RayExecutorV2 activé par défaut (#41421), correctif de collision de nom d'acteur pour DP > 1 (#40398).
  • Stabilité : pause en deux phases pour éviter les blocages du planificateur (#39366), wrappers de tokenizer HF thread-safe (#41181), prévention MOO via max_split_size_mb pendant le chargement du modèle (#41268).
  • Prise en charge d'IndexCache pour les modèles DSA (#37735).

Matériel et performances

  • NVIDIA Blackwell : backend TOKENSPEED_MLA pour DSR1/Kimi-K25 (#41778), noyau quantitatif de groupe FP8 par jeton plus rapide (#41326), FP8 sur NVIDIA Thor/SM110 (#39712), CUTLASS mis à l'échelle en mm pour les tailles non compatibles (#41868).
  • Performances : échantillonneur FlashInfer top-k/top-p activé par défaut (#40376), attention FP8 FlashInfer pour ViT (#38065), tampons dequant partagés TurboQuant (#40941), AllPool.forward 51 % plus rapide (#41163), élimination de la synchronisation GPU<->CPU dans le pooling (#41433) et attention (#41434), numpy zéro-copie intégration de la sérialisation (#41681), saut de processeur multimodal pour le texte uniquement (#41246), fusion TP asynchrone FlashInfer FP8 (#39505), fusion GEMM all-gather NVFP4 pour AsyncTP (#41882), réactivation de la fusion allreduce+RMS pour DP/PP (#41458), DeepSeek bf16→fp32 via torch.mm (#41300), MLA persistant pour le backend clairsemé (#41990), prélecture du point de contrôle des tenseurs de sécurité configurables (#41499), noyau mhc_post_pre fusionné (#41536), noyau quant de groupe W8W8 à grille 2D (#42153), ordre de mémoire assoupli pour les échanges de cache KV (#39306).
  • AMD ROCm : ROCm 7.2.2 (#41386), DBO (optimisation par lots dynamiques) (#34726), AITER Fused Allreduce+RMSNorm (#37646), Fused Shared Expert (FSE) pour Qwen3-Next (#39280), DeepSeek V3.2 TP4 AITER MLA (#41835), GDN linéaire fusion d'attention (#40711), élimination des copies redondantes de tampon MoE dans AITER (#41713), prise en charge du déchargement du processeur (#40549), mise à jour DeepEP API (#39721), limitation de la taille du bloc d'attention paginé Triton pour corriger le MOO de la mémoire partagée (#38502).
  • CPU : attention FP8 pour AMX/AVX-512 (#39445), FP8 W8A16 linéaire (#41186), FP8 W8A16 MoE (#41314), DNNL AVX2 W8A8 Int8 (#41318), Gated DeltaNet Attention pour Qwen 3.5/3.6 (#41025), RISC-V Liaison automatique du fil OMP (#40569).
  • Intel XPU : exemple de noyau Top-k/top-p (#39285), réduction totale déplacée (#41808), prise en charge LoRA (#38206).
  • IBM Power : backend d'attention VSX (#40451).
  • FlexAttention : réactivé pour le mode invariant par lots (#40842).
  • MLA : backends de pré-remplissage MLA abstraits, dépendance cuDNN éliminée (#32623).

Service à grande échelle

  • Service désagrégé : transferts de cache KV bidirectionnels entre P et D (#32553), refonte du transfert NIXL (#40731), optimisation de la surcharge de mémoire EPLB (#40013), connecteur NIXL passé à 1.x (#42364), Mooncake KVConnectorStats pour l'observabilité des transferts (#40414), notification de rejet de pré-admission du nœud P NIXL (#41269), libération du bloc KV pour les sauts. Rangs P (# 40449).
  • DCP : Pack sortie et LSE dans DCP A2A (#41160).
  • MoE : interface PluggableLayer pour les exécuteurs MoE hors arborescence (#35178).
  • LoRA : prise en charge initiale du parallèle expert (EP) (#40867), correctif de fusion Qwen3.5 LoRA (#37912).

Quantification

  • NVFP4 : prise en charge du cache KV (#40177), noyaux d'émulation Triton dequant/QDQ pour Hopper et AMD (#40033), GELU sur TRT-LLM NvFP4 fusionné MoE pour Gemma4 (#41050), ModelOpt NVFP4 W4A16 (#41769), fusion GEMM all-gather NVFP4 pour AsyncTP (#41882), Correctif de chargement de GLM4-MoE NVFP4 (#41755).
  • MXFP4 : backend Humming MXFP4 MoE (#41083), correctif FlashInfer CUTLASS MXFP4-MXFP8 MoE (#42089).
  • TurboQuant : modèle hybride et prise en charge de la quantification uniforme (#39931).
  • Tenseurs compressés : autoriser les configurations avec des ignorés non explicites (#41965).
  • FP8 : correctif de chargement de biais (#41424), réglage automatique de FlashInfer temporairement désactivé pour des raisons d'exactitude (#41524).
  • DSV4 : noyau quantitatif fusionné amélioré de l'Indexer Q (#41428).

API et interface frontale

  • Réponses API : appel d'outil/fonction de streaming avec required (#40700) et choix d'outil/fonction nommé (#41110), soumission à nouveau des éléments de sortie avec des champs manquants (#41355).
  • Compatibilité OpenAI : champ system_fingerprint dans les réponses (#40537), prise en charge des parties de contenu prompt_embeds (#40720), prise en charge de defer_loading et tool_reference (#40190), rendu du texte d'invite dans la réponse de fin de chat (#42052), tolérance du contenu vide dans le choix d'outil forcé (#40148).
  • Appel d'outils : XGrammar 0.2.0 avec balises structurelles pour l'appel d'outils strict + raisonnement (#40894), raisonnement Cohere/analyseurs d'outils (#40422), analyseur d'outils LFM2/2.5 (#39243).
  • Tokenizer : prise en charge de Fastokens (#41741).
  • RLHF : /start_weight_update et /finish_weight_update API explicites (#39212).
  • ASR : Abandon de la demande du moteur en cas d'annulation (#41266).
  • Configuration : variable d'environnement VLLM_SKIP_MODEL_NAME_VALIDATION (#34676), suivi du chargement des poids de modèle configurable (#41086), moniteur de compilation Triton JIT (#40137).

Construction et dépendances

  • Rupture : C++20 requis pour la compatibilité PyTorch (#40380).
  • Rupture : Transformers v4 obsolète (#40389).
  • Taille de l'image Docker réduite de ~2.5 Go via le téléchargement différé de FlashInfer cubin (#41134).
  • Les roues CUDA 13.0 sont passées à la base PyTorch manylinux_2_28 (#41416).
  • Roue fournie DeepGEMM construite par-Python pour la compatibilité CPython (#41516).
  • Métadonnées de provenance de l'image du conteneur intégrées (#40653).
  • Inférence TPU mise à niveau vers v0.19.0 (#41844).
  • Le connecteur NIXL est passé à 1.x (#42364). *ROCm 7.2.2 (#41386).
