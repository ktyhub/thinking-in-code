#vllm v0.22.0

Faits saillants

Cette version contient 459 commits de 230 contributeurs (63 nouveaux) !

  • ** Maturité DeepSeek V4 ** : DeepSeek V4 a reçu une passe de durcissement majeure ce cycle : le modèle a été réorganisé en un package vllm/models/deepseek_v4/ dédié (#43004, #43039, #43073, #43077, #43149), a obtenu la prise en charge MoE fusionnée NVFP4 (#42209), un graphique CUDA complet + par morceaux (#42604) et un MTP spéculatif. décodage (#43385). Un large ensemble de noyaux fusionnés (MegaMoE, mhc, Q-norm, indexer, sparse MLA) et de correctifs de parité ROCm ont été ajoutés aux côtés de correctifs de précision (#42810, #43710).
  • Model Runner V2 avance vers la valeur par défaut : MRv2 est désormais la valeur par défaut pour les modèles denses Qwen3. vLLM reviendra à MRv1 pour les fonctionnalités qui ne sont pas encore prises en charge dans MRv2 (#39337). rechargement du poids en mode veille (#42673), update_config (#42783) et couches de cache KV partagées (#35045), ainsi que de nombreux correctifs d'exactitude.
  • Frontend expérimental Rust : une nouvelle intégration frontale Rust a été lancée (#40848), avec l'implémentation déplacée dans l'arborescence (#43283) et un superviseur DP pour le service parallèle de données (#40841).
  • Invariance par lots, plus rapide : l'inférence invariante par lots a obtenu la prise en charge de Cutlass FP8 pour une **amélioration de la latence de bout en bout de 28.9% (#40408), la prise en charge du mode compilation sur SM80 (#42456) et un chemin linéaire NVFP4 Cutlass (#39912).
  • Déchargement de cache KV à plusieurs niveaux : un nouveau cadre de déchargement de cache KV à plusieurs niveaux (#40020) avec un niveau secondaire de système de fichiers Python (#41735), la prise en charge de DSv4 (#43142) et le déchargement de disque Mooncake (#42689) étend le déchargement au-delà de la mémoire du processeur.

Prise en charge des modèles

  • Nouvelles architectures : MiniCPM-V 4.6 (#41254), InternS2 Preview (#42705), OpenVLA (#42654), documentation MolmoWeb hf_overrides (#42163) ; EXAONE-4.5 aligné sur la mise à jour Transformers (#42246).
  • Décodage spéculatif : backend de proposant appelable personnalisé (#39487), spéculateurs post-norme EAGLE-3 (#42764), spéculateurs peagle (#41826), modèles d'attention hybride dans extract_hidden_states (#39949), spéculation non MTP pour NemotronH (#43130), poids MTP partagés dans MRv2 (#42538).
  • DeepSeek V4 : NVFP4 MoE (#42209), graphique CUDA complet/par morceaux (#42604), MTP (#43385), refactorisation du package de modèles (#43004, #43039, #43073, #43077), refactorisation MLA + compresseur clairsemée (#43149, #43710), déplacement du noyau de préparation d'entrée MegaMoE. (#43632).
  • Qwen3.5/3.6 : aplatissement de la projection de sortie du Réseau Display de Google (#42311), correctif GatedDeltaNet Marlin TP≥2 (#36329), graphique CUDA complet ViT (#42151), chargement du poids runai-streamer pour Qwen3.5/MTP/Qwen3-VL (#42521, #42716), sémantique KDA chunk-prefill exp2 (#43195).
  • Gemma3/Gemma4 : correctif de crash de co-batching d'images à résolution mixte (#42217), correctif de fermeture de routage MoE (#42250), correctif de corruption flottante de l'analyseur d'outils (#42128), encodeur de vision par lots pour image/vidéo (#43169), correctif multi-GPU (#42630).
  • Kimi-K2.5 : ignorer la conversion du type de tour de vision sous quantification (#42869), correctif du type mm_projector (#42081).
  • Cohere : activez Cohere MoE (#43143), le parallélisme de pipeline pour la vision Cohere (#42819).
  • Appel d'outil : analyseur d'outil Apertus (#41154), re-landing de résolution Qwen3Coder anyOf/oneOf/$ref (#37831), coerce_to_schema_type partagé entre les analyseurs MiniMax-M2 / DeepSeek-V3.2 / Seed-OSS (#43006, #43019, #43140).
  • Graphique ViT CUDA : Qwen2-VL (#41736), encodeur Step3-VL (#42224), Qwen3.5 (#42151), métadonnées FlashInfer pour l'attention visuelle Qwen2.5-VL (#42787).

Matériel et performances

  • NVIDIA Blackwell / SM12x : FlashInfer b12x MoE + FP4 GEMM pour SM120/121 (#40082), FP8 CUTLASS par tenseur sur SM12.1 (#41215), head_dim=512 pour FlashInfer TRTLLM attention (#38822), pré-remplissage FlashInfer Blackwell GDN (#40717), noyau de pré-remplissage GDN pour SM100 (#43273).
  • Performances : Cutlass FP8 invariant par lot (+28.9% E2E) (#40408), prétraitement de remplissage CutlassFP8 (+13.5% TTFT) (#42651), noyau quantitatif NVFP4 rembourré (+2.4–5.7% E2E) (#42774), élimination de la synchronisation GPU<->CPU 1/n (#41429) et 4/n (#42347), RoPE+KVCache+q_concat fusionnés pour MLA (#40392), optimisations MLA compute_prefill_context / _v_up_proj (#42460, #42561), pénalités du noyau Triton (#40657), do_not_specialize dans RoPE FP8 fusionné (#42849), capture de graphe FULL CUDA pour le décodage TRITON_MLA (#42885).
  • AMD ROCm : fonctionnalité DSV4 + correctifs de précision (#42810, #43679 Tilelang MHC), noyaux Flash Sparse MLA Triton (#41812), logits MQA paginés aux gluons sur gfx950/MI355X (#42062), fusion RMSNorm+Quant pour gfx950 (#41825), nettoyage du backend AITER FA (#41942), backend XGMI pour le connecteur MoRI (#41753), remplacement de la taille minimale QuickReduce (#41675), DSV4 MTP (#43385).
  • CPU / RISC-V : noyaux d'attention optimisés pour RVV pour l'extension vectorielle RISC-V (#40119) avec VLEN=256 (#42943), GDN fusionné pour CPU AMX (#42707), MXFP4 W4A16 MoE (#41922), Triton expérimental + MRv2 sur CPU (#43225), utilisation améliorée des threads du CPU (#42666), --cpu-distributed-timeout-seconds (#42968).
  • Intel XPU : prise en charge de GPTQ int4 (#37844), mxfp8 MoE (#41918), quantification à l'échelle des blocs FP8 (#42952), comportement collectif personnalisé (#41354), plusieurs noyaux à attention fragmentée (#37888), routage MoE topk + repli MXFP4 (#42951), chemin CT W4A4 MXFP4 (#38896), réduction de la surcharge de l'hôte XPU MoE (#42915).
  • Kernel ABI : migration continue vers ABI stable de libtorch — 5/n (#42339), 6/n (#42663), 7/n (#43209).
  • Expérimental : graphique CUDA sécable (#42304).

Service à grande échelle

  • Mooncake : déchargement de disque dans MooncakeStoreConnector (#42689), prise en charge HMA pour DSV4 (#42828), métriques d'opération (#43392), propagation des échecs de chargement (#42788), accès complets alignés sur les blocs (#43494), gestion de la fin après préemption (#43281).
  • Données parallèles : superviseur DP (#40841), nombre de demandes de publication au démarrage du moteur (#41626), transfert d'en-tête X-data-parallel-rank (#42330).
  • EPLB : modification du communicateur EPLB par défaut (#43110), correctif d'initialisation du VLM-wrapper (#39805), suppression du torch.accelerator.synchronize() mort (#40733).
  • LoRA : noyau Triton one-shot pour MoE LoRA (#42290), adaptateurs MoE LoRA 2D et 3D simultanés (#42242), mémoire 2D réduite sous EP (#42737), correctif de grille d'alignement du noyau MoE LoRA (#40131).

  • NVFP4 : MoE fusionné DeepSeek V4 (#42209), MoE fusionné ModelOpt W4A16 NVFP4 + répartition à précision mixte (#42566), NVFP4 Cutlass linéaire invariant par lot (#39912), correctif de routage MoE monolithique FlashInfer TRTLLM NvFP4 (#43223), correctif de segmentation MoE TRTLLM NVFP4 (#43599).

Construction et dépendances

  • Les versions de roues CUDA 12.9 sont passées à la base PyTorch manylinux_2_28 (#41668).
  • FlashInfer est passé à v0.6.11.post2 (#41711) ; nvidia-cutlass-dsl à 4.5.2 (#42991, #43230, #43745) ; llguide vers 1.7 (#42150) ; triton_kernels rétrogradé en v3.5.1 pour gpt-oss (#43135).
  • Version frontale Rust : dépendance setuptools-rust (#43287, #43377), protoc épinglé dans les étapes de construction rust (#43292).
  • Docker : cible vllm-openai non root (#40275), build mooncake-transfer-engine à partir des sources (#42114), prise en charge d'AINIC et Thor NIC (#40453) ; Installation uniquement du Python rendue facultative (#42293).
  • vllm-tpu : désactivez l'isolation de build pour les dépôts CUDA (#43038), correctif de build tpu-inference docker (#43360).
  • Dépendance backend humming MoE ajoutée, annulée, puis restaurée avec le correctif d'exécution CuPy (#42540, #43492, #43530).

  • Suppression des arguments de pré-remplissage MLA obsolètes (#42555).
  • Suppression des noyaux CUDA morts et du code mort (#42767, #42889, #43144).
