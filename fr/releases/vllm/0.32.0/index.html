#vllm v0.32.0

#v0.32.0

Faits saillants

Cette version contient 814 commits de 363 contributeurs (121 nouveaux) !

  • Décisions structurées et analyseurs génériques : le nouveau point de terminaison POST /v1/systemone répond aux questions choice, noul et score sur un état structuré (#59299), est servi par défaut (#60677, #60696) et s'exécute également sur Cloudflare/clef-omni (#61064), LiquidAI/d1-3B (#60676) et DiffusionGemma. (#60466). Le nouvel outil hf et l'analyseur de raisonnement (--tool-call-parser hf, --reasoning-parser hf) lisent le response_template du point de contrôle, de sorte que les modèles qui l'expédient n'ont pas besoin d'analyseur spécifique au modèle (#58604, #58602), dans les interfaces Python et Rust (#59005).
  • Cache KV de basse précision partout : le cache KV NVFP4 fonctionne désormais sur SM8x et SM12x (#46963), SM90 (#60620) et avec décodage XQA sur SM12x (#60452), et sur MiniMax-M3 avec une attention éparse sur SM100 (#59300) ; GLM-5.x utilise par défaut un cache KV FP8 sur SM100, réduisant de moitié la mémoire KV par rang avec 2.3-5.5 % de débit en plus à un coût TTFT de 7 à 11 % dans le benchmark du PR (#60140, #60281) ; fp8_ds_mla sur SM90 donne au GLM-5.3-Flash jusqu'à 31 % de débit de sortie en plus (#59246) ; ROCm gagne le cache ultraquant_4bit KV 4 bits avec environ 2 fois la densité de FP8 (#57057).
  • Model Runner V2 : un spéculateur GPU n-gram avec des brouillons de longueur variable (#40704), Elastic EP (#53934), un parallélisme de pipeline avec parallélisme de contexte de pré-remplissage pour les modèles MLA (#59139), un mode stock torch.compile (#59079) et MRV2 est désormais la valeur par défaut sur ROCm avec les exceptions MRV1 spécifiques au modèle supprimées (#56360).
  • Démarrage et service plus rapides : vllm download-kernels installe les noyaux précompilés de FlashInfer (#58765) ; vllm preload --preload-autotune maintient la table de réglage automatique FlashInfer au chaud lors des redémarrages (#60085) ; une arène de tenseurs à mémoire partagée diffuse de grands tenseurs multimodaux aux travailleurs avec une seule copie (#51207) ; les tokeniseurs et les processeurs se chargent à partir de l'instantané local (#60825) ; et avec --api-server-count au-dessus de 1, chaque connexion va au travailleur API le moins chargé, pour 43 à 85 % de requêtes/s en plus sur les requêtes courtes (Qwen3-0.6B, 32 jetons d'entrée / 1 jeton de sortie) dans le benchmark du PR (#60723).
  • Prise en charge du modèle : nouvelles intégrations omnimodales EmbeddingGemma 2 (#60254), MiniCPM-V 4.7 (#58674) et Nemotron 3.5 ASR (#59827) ; entrée vidéo dans le backend de modélisation Transformers (#57441) ; Conversions d'index MLA clairsemées GLM-5.3 réutilisées sur plusieurs couches (3.5-3.9x sur ce noyau, #59464) et décodage de brouillon en plusieurs étapes fusionné (13.3% à la concurrence 1, #57443) ; Mise en cache de résidence HiSparse par requête pour un débit jusqu'à 58 % plus élevé sur GLM-5.3-NVFP4 sur B200 avec des contextes longs entièrement résidents sur GPU avec une simultanéité élevée (#60083).
  • Sécurité : correctifs pour GHSA-4hhp-h66f-j5j7 (épuisement des ressources du modèle de discussion, #50300), GHSA-q97c-p368-75c4 (tokenizer max_token_id, #59491) et GHSA-frvg-qw88-hww9 (épuisement du socket P2P ZMQ, #51504) ; CORS n'autorise plus toutes les origines par défaut (#61009) ; Les images untrusted sont limitées aux formats raster (#60022) ; Les handles de cache multimodal à mémoire partagée sont signés (#59357) ; et les schémas JSON imbriqués à plus de 64 niveaux sont rejetés (#60036).
  • Modifications récentes : Python 3.10 supprimé (#60402) ; Origines CORS par défaut restreintes (#61009) ; transformers>=5.16.1,<5.20.0 et tokenizers>=0.23.2 (#57387, #59796) ; Le parallélisme de séquence torch.compile et les passes AsyncTP ont été supprimés (#60517) ; attention en cascade supprimée (# 61126); mamba_cache_mode="all" supprimé (#58997) ; max_tokens n'est plus réservé depuis la fenêtre contextuelle (#57035) ; Réponses Événements de flux de raisonnement API renommés (#59652).

Sécurité

  • GHSA-4hhp-h66f-j5j7 : les modèles de discussion sont validés de manière statique et rendus sous un délai d'attente (VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT), le chat_template fourni par l'utilisateur dans les réponses chat_template_kwargs est rejeté et l'exécution du modèle de majuscules frontales Rust (#50300).
  • GHSA-q97c-p368-75c4 : tokenizer max_token_id corrigé un par un (#59491).
  • GHSA-frvg-qw88-hww9 : les sessions homologues P2P ZMQ sont limitées par VLLM_P2P_MAX_PEERS (128 par défaut), VLLM_P2P_HANDSHAKE_TIMEOUT_S (30 par défaut) et VLLM_P2P_IDLE_TIMEOUT_S (300 par défaut), de sorte que les adresses homologues uniques ne peuvent plus épuiser les sockets ZMQ (#51504).
  • Les paramètres CORS par défaut n'autorisent plus toutes les origines dans les interfaces Python et Rust ; définissez --allowed-origins pour autoriser les origines du navigateur (# 61009).
  • Les images Untrusted sont ouvertes avec une liste autorisée au format raster (ALLOWED_IMAGE_FORMATS), refusant EPS/PostScript et WMF (#60022) ; Les handles de cache multimodal à mémoire partagée sont signés par HMAC et les handles contrefaits sont rejetés (#59357).
  • Les schémas JSON à sortie structurée imbriqués sur plus de 64 niveaux renvoient 400 (#60036) ; les requêtes /v1/embeddings fragmentées conservent cache_salt (#47696) ; L'audio Phi-4 MM ne contient plus de matrices d'attention multi-Gio (#60614) ; Les tenseurs de pixels à somme nulle DeepSeek-OCR ne tuent plus EngineCore (# 59417).
  • Problèmes de dépendance de sécurité : aiohttp>=3.14.3, pillow>=12.3.0, cryptographie, urllib3, pyjwt et autres (#59249, #59315, #59427).

Dépendances

  • transformers>=5.16.1,<5.20.0 (minimum augmenté de 5.10.4, #57387, #59762) et tokenizers>=0.23.2 (#59796).
  • NIXL 1.5.0 (#56907), CuTe DSL 4.8.0 API à grande échelle (#59480), humming-kernels==0.1.17 avec prise en charge initiale de Rubin (#61556, #61858), InstantTensor 0.2.2 (#61167) et flashinfer-jit-cache exclus de la roue install_requires. (#60052).
  • ROCm : AITER 0.1.24.post1 (#59794) et MoRI v1.2.3.post1 (#56073). XPU : librairie automatique 0.16.0 (#60976). TPU : tpu-inférence v0.31.0 (#60190).

Construire

  • Python 3.11-3.14 pris en charge (#60402) ; Roues macOS construites avec l'ABI stable (#60312) ; Les builds sources CUDA nécessitent GCC 13 et échouent prématurément sinon (#60259) ; Les images Docker compilent le bytecode Python au moment de la construction pour un démarrage plus rapide du conteneur (#55422) ; VLLM_USE_PRECOMPILED trouve une roue publiée compatible au cours des 20 derniers commits (#58871) ; le DeepGEMM vendu utilise TORCH_LIBRARY (abi3, #48962).

Dernières modifications et dépréciations

  • Python 3.10 n'est plus pris en charge ; le minimum est Python 3.11 (#60402).
  • Les origines CORS par défaut sont passées de * à aucune ; définissez --allowed-origins pour le navigateur clients (#61009).
  • transformers>=5.16.1,<5.20.0 et tokenizers>=0.23.2 sont requis (#57387, #59796).
  • Le parallélisme de la séquence torch.compile et les passes AsyncTP ont été supprimés, ainsi que PassConfig.enable_sp, fuse_gemm_comms et sp_min_token_num ; le parallélisme des séquences au niveau du modèle n'est pas affecté (#60517).
  • L'attention en cascade a été supprimée ; --disable-cascade-attn analyse toujours mais avertit uniquement et sera supprimé dans v0.33.0 (#61126).
  • mamba_cache_mode="all" a été supprimé ; --mamba-cache-mode all échoue désormais à la validation (#58997).
  • Les API précédemment obsolètes ont été supprimés : wait_for_inflight_requests (utilisez mode="wait"), AsyncLLM.pause_generation(), IOProcessor.output_to_response, vllm.scripts.main() et vllm bench throughput --dataset (#60923). L'ensemble de données de référence sonnet a été supprimé comme prévu (#60129). Le support du tensoriseur a été supprimé de LoRA (#60024) et le pont PyO3 vllm._rust_tool_parser a été supprimé (#59744).
  • Modifications de API : max_tokens est traité comme une limite supérieure sur la sortie plutôt que réservé à partir de la fenêtre contextuelle (#57035) ; Réponses Le streaming API utilise response.content_part.added/done avec part.type="reasoning_text" au lieu de response.reasoning_part.added/done (#59652) ; SamplingParams.prompt_logprob_token_ids est par ligne (#56984) ; Les logprobs /inference/v1/generate utilisent des ID de jeton entiers (#58181) ; les réponses sleep API sont standardisées et les niveaux non valides renvoient 400 (#52864) ; return_mm_kwargs est obsolète au profit de mm_payload (#61427).
  • Filigrane : lorsque le moteur a configuré le filigrane, un champ de requête omis signifie activé et seul false se désinscrit ; les combinaisons non prises en charge avertissent et reviennent (#56801).
  • Frontend Rust : qwen3_xml analyse désormais le XML Qwen3-Coder (alias de qwen3_coder) ; utilisez le nouveau qwen3_json pour le format JSON (#60136).
  • Nouveaux paramètres par défaut : arène de tenseur de mémoire partagée activée (#51207) ; Cache GLM-5.x FP8 KV sur SM100 avec --kv-cache-dtype auto (#60140, #60281) ; VLLM_DEEPEP_V2_ALLOW_HYBRID_MODE=1 (#57991); Humming préféré à Marlin sur SM90 (#56997) ; sparse_mla_prefill_workspace_factor 2 au-dessus de 256K max_model_len (#61023) ; MRV2 sur ROCm avec les exceptions MRV1 spécifiques au modèle supprimées (#56360) ; VLLM_ROCM_AITER_MLA_DCP_VERIFY=auto (#59965); dtype=auto choisit bfloat16 sur PowerPC (#58528) ; Les points de contrôle MXFP4 W4A4 reviennent à W4A16 avec un avertissement lorsqu'aucun noyau W4A4 n'existe (#60079).
  • Validation plus stricte : les --prefix-match-unit incompatibles (#58021), max_num_scheduled_tokens=0 (#60714), HiSparse avec cudagraph_mode=FULL (#59688) et les --device-ids négatifs (#49053) sont rejetés au démarrage.
