#vllm v0.20.0

vLLM v0.20.0

Faits saillants

Cette version contient 752 commits de 320 contributeurs (123 nouveaux) !

  • DeepSeek V4 : prise en charge initiale de DeepSeek V4 (#40860), avec correctif de fuite de jeton DSML dans DSV4/3.2 (#40806), correctif DSA + MTP IMA (#40772) et une limite de serrage silu sur l'expert partagé (#40950).
  • CUDA 13.0 par défaut : roue CUDA par défaut sur PyPI et image vllm/vllm-openai:v0.20.0 commutée sur CUDA 13.0 ; les listes d'architecture et les arguments de construction ont été nettoyés (# 39878), et CUDA est passé à 13.0.2 pour correspondre à PyTorch 2.11.0 (# 40669). En règle générale, notre politique de version CUDA suit celle de PyTorch. Nous vous recommandons fortement d'installer vLLM avec uv et d'utiliser --torch-backend=cu129 si vous êtes sur CUDA 12.9.
  • Mise à niveau de PyTorch 2.11 (#34644) : vLLM est livré sur la torche 2.11 pour CUDA, et XPU est désormais également sur la torche 2.11 (#37947) — XPU n'est plus épinglé sur 2.10. Il s’agit d’un changement radical pour la dépendance à l’environnement.
  • Python 3.14 : ajouté à la liste des versions Python prises en charge (#34770).
  • Transformers v5 : vLLM fonctionne désormais sur HuggingFace transformers>=5 (#30566), avec contournement de torch.compile de l'encodeur de vision (#30518) et correctifs de compatibilité v4/v5 continus, notamment le processeur d'image PaddleOCR-VL max_pixels (#38629), l'avertissement Mistral YaRN (#37292) et le recalcul rotatif inv_freq de Jina ColBERT. (#39176).
  • Nouveaux grands modèles : aperçu Hunyuan v3 (Hy3) (#40681) avec analyseur de raisonnement HYV3 (#40713) ; Granite 4.1 Vision comme modèle multimodal intégré (#40282).
  • FlashAttention 4 comme pré-remplissage MLA par défaut : FA4 réactivé en tant que backend de pré-remplissage MLA par défaut (#38819) avec head-dim 512 et prise en charge du KV paginé sur SM90+ (#38835), plus une synchronisation FA4 en amont (#38690).
  • Cache KV TurboQuant 2 bits : nouveau backend d'attention offrant une compression de cache KV 2 bits avec une capacité 4× (#38479), désormais avec prise en charge du pré-remplissage FA3/FA4 (#40092).
  • Frontend de quantification en ligne : Nouvelle interface de quantification en ligne de bout en bout (#38138), avec documentation (#39736) ; experts_int8 consolidé dans le chemin en ligne du FP8 (#38463) ; Le quant en ligne MXFP8 a été déplacé vers la nouvelle interface (#40152).
  • vLLM IR : squelette IR initial avec opération rms_norm (#33825), importations de noyau de plate-forme OOT (#38807), gemma_rms_norm retravaillé sur IR (#39014) et ajout d'une infrastructure de test/benchmarking d'opération IR (#40167) — base pour les futurs travaux du noyau.
  • Modèle Runner V2 avancé : Eagle pré-remplit le graphique CUDA complet (#37588), résolution automatique du mode/tailles du cudagraph à partir du backend d'attention (#32936), exemples de noyaux de rejet probabiliste fusionné (#38496), validation de la configuration pour les fonctionnalités non prises en charge (#38758), repli par morceaux désactivé pour les décodages de brouillon d'Eagle (#39773), prise en charge de plusieurs invites de journalisation (#39937), couverture d'échauffement de pré-remplissage (#40746) et correctif pour la régression de précision causée par des jetons échantillonnés/brouillons périmés (#39833).
  • Série de refactors MoE : non quantifié migré vers Full Oracle Flow (#36286), CT W8A8 vers Oracle (#39187), classe SharedExperts (#35153), SharedFusedMoE supprimé (#35782), division DefaultMoERunner (#35326) puis recombiné dans MoERunnerBase (#40560), somme de sortie experte partagée/fusionnée déplacée dans MoERunnerBase (#35949), ZeroExpertFusedMoE dans le nouveau framework (#35549), compressed_tensors_moe.py divisé (#38960), GPTQMarlinMoEMethod retravaillé avec MK (#37990), XPU & CUTLASS MoE transférés vers fused_moe/experts/ (#40568, #40574), make_expert_params_mapping renommé (#40671), refactor MoE LoRA (#40338) et le découpage MoE DP supprimé (#39107).
  • Performances : optimisation des invariants par lots avec la norme RMS fusionnée – amélioration de la latence 2.1 % E2E (#40413) ; évitez la synchronisation GPU → CPU seq_lens_cpu (# 40654); cache InductorPass.hash_source (#39328) ; ignorer la désérialisation du graphique FX lors du chargement pour une compilation à chaud plus rapide (#40151) ; Profilage de la mémoire CUDAGraph activé par défaut pour une comptabilité plus claire de la mémoire de démarrage (#38284).

  • FlashAttention 4 synchronisation en amont (#38690) et comportement du lien symbolique lors de l'installation (#38814).
  • FlashInfer est passé à 0.6.8 (#39959).
  • AITER correctif triton BUFFER_OPS + mises à jour de version (#38580), AITER est revenu à v0.1.10.post3 (#39509) ; Nixl est passé à 0.10.1 (#39922) et épinglé par majeure CUDA dans CI (#39851) ; DeepGEMM intégré à la roue via CMake (#37980) ; fastsafetensors ajouté au fichier NVIDIA Docker (#38950) ; Helion a heurté 0.3.2 → 0.3.3 (#38062).
  • Supprimé/déplacé : la dépendance resampy a été supprimée (#39524), la dépendance directe librosa a été supprimée (#39079), pyav et soundfile ont été déplacés vers des exigences communes (#39997).

Modifications radicales

  1. PyTorch 2.11 + CUDA 13.0(.2) par défaut — changement de dépendance d'environnement, désormais également appliqué à XPU.
  2. Transformers v5 est la référence prise en charge (#30566).
  3. Refonte des métriques : vllm:prompt_tokens_recomputed supprimé (#38709) ; num_cached_tokens / num_external_computed_tokens remplacé par PrefillStats (#37460).
  4. Renommer la configuration du pooler : logit_bias/logit_scale → logit_mean/logit_sigma (#39530).
  5. Planification asynchrone désactivée par défaut pour les modèles de pooling (#39592).
  6. Le profilage de la mémoire CUDAGraph est désormais activé par défaut (#38284) — modifications de la comptabilité de la mémoire de démarrage.
  7. Quantification Petit NVFP4 supprimée (#32694) ; LLM.reward est obsolète, utilisez LLM.encode (#40688) ; cprofile / cprofile_context obsolète (#39100) ; V0 accept output buffer obsolète (#39125).

### Dépréciation V0

  • Petit NVFP4 (#32694), accept output buffer en attention (#39125), cprofile / cprofile_context (#39100), LLM.reward hors ligne API (#40688).
