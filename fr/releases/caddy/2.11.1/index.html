caddy v2.11.1

Correctif Publié23 févr. 2026 Sourcecaddyserver/caddy Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

chariot v2.11.1

Notre communauté est heureuse d'annoncer le Caddy 2.11 ! Il convient de noter les nouvelles fonctionnalités, de nombreuses corrections de bugs, dont plusieurs correctifs de sécurité, et diverses améliorations de la qualité de vie (« qualité de vie »).

Il n’y a aucun changement de code par rapport à v2.11.0 autre que celui d’un travail CI. En raison d'un récent changement externe qui a interrompu notre processus de publication, la première version de 2.11 est v2.11.1.

Remerciement spécial du sponsor

Un grand merci à nos sponsors majeurs :

  • ZéroSSL
  • Rayure
  • Chemin de fer

Ils, avec des dizaines de petits sponsors, rendent ce projet et les nouvelles versions possibles, en collaboration avec notre équipe de responsables. Merci à tous !

Changements notables

  • Les clés cryptées ClientHello (ECH) tournent automatiquement.
  • Options de chronométrage pour les journaux.
  • SIGUSR1 peut désormais recharger la configuration si elle a été initialement chargée à partir d'un fichier sur la ligne de commande et n'a pas été modifiée via le API.
  • Le proxy inverse réécrit désormais automatiquement l'en-tête Host à l'adresse de l'amont lorsque l'amont est HTTPS (#7454)
  • log_append peut désormais enregistrer les corps de requêtes et de réponses, utiles pour le débogage.
  • Notre projet met désormais en œuvre et nécessite des divulgations d'assistance (pour les AI/LLM) sur les problèmes, les PR, les commentaires, les réponses, les avis, etc.
  • De très nombreuses autres améliorations mineures et corrections de bugs.

Merci à tous ceux qui ont participé à cette version !

:avertissement : correctifs de sécurité

  • fastcgi : CVE-2026-27590 par @dunglas et @AbdrrahimDahmani - L'expansion de la longueur de pliage Unicode provoque un index split_path incorrect (confusion SCRIPT_NAME/PATH_INFO) dans le transport FastCGI.
  • admin : CVE-2026-27589 par @1seal - Les requêtes d'origine croisée tentées avec le mode no-cors pourraient entraîner la réussite de certaines requêtes API ; ces demandes sont désormais bloquées. (Pour que cela soit pratiquement exploitable, un navigateur Web exécutant une page Web malveillante doit s'exécuter localement sur un processus Caddy de production.)
  • caddyhttp : CVE-2026-27588 par Asim Viladi Oglu Manizada - Le Host Matcher devient sensible à la casse pour les grandes listes d'hôtes (> 100), permettant le contournement de la route/authentification basé sur l'hôte.
  • caddyhttp : CVE-2026-27587 par Asim Viladi Oglu Manizada - Le Path Matcher ignore la normalisation de la casse pour les séquences d'échappement, permettant ainsi le contournement de l'itinéraire/auth basé sur le chemin.
  • caddytls : CVE-2026-27586 par @moscowchill - L'authentification TLS client échoue silencieusement lorsque le fichier de certificat CA est manquant ou mal formé.
  • caddyhttp : CVE-2026-27585 par @parrot409 - Une mauvaise désinfection des caractères globaux dans le matcher de fichiers peut conduire à contourner les protections de sécurité.

:rotating_light : Avis destiné aux responsables du plugin Caddy : Dependabot vous alertera probablement des correctifs de sécurité dans Caddy et vous invitera à le mettre à niveau dans votre fichier go.mod. Veuillez mettre à niveau UNIQUEMENT la dépendance Caddy s'il y a une modification dans un API exporté que votre plugin utilise. (Ensuite, [désactivez Dependabot] (https://words.filippo.io/dependabot/).)
