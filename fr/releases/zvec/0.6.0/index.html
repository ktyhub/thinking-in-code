#zvec v0.6.0

🚀 Zvec v0.6.0 Release Note

📦 Nouvelles fonctionnalités

  • Abstraction Turbo Quantizer : Introduction d'une abstraction Quantizer enfichable dans le module Turbo avec une interface uniforme que les futurs quantificateurs (int8 uniform, int8 record, PQ, RaBitQ, …) peuvent implémenter, découplant la logique de quantification des constructeurs d'index et des chercheurs. Comprend la première implémentation concrète de Fp32Quantizer et les noyaux de distance scalaires FP32. (#546)
  • Rotation aléatoire pour la quantification INT8/INT4 : Ajout d'une fonction de rotation aléatoire facultative à la quantification INT8/INT4, répartissant la variance uniformément sur les dimensions vectorielles pour réduire l'erreur de quantification et améliorer le rappel. Sur cohere-1m : rappel HNSW INT8 amélioré de 0.9285 → 0.9397, Flat INT8 de 0.9695 → 0.9881 ; Le rappel INT4 s'est considérablement amélioré (HNSW 0.2114 → 0.7117). (#483)
  • Recherche groupée : Zvec prend désormais en charge la recherche groupée (c'est-à-dire la déduplication groupée) sur l'interface principale, l'algorithme et les couches de base de données. Les utilisateurs peuvent récupérer les meilleurs résultats par groupe plutôt que globalement, avec la prise en charge des modes de requête fetch_vector, is_linear et bf_pks sur les index Flat, HNSW, HNSW-RaBitQ et clairsemés. Group-by est désormais également exposé dans le Python API. (#527, #561)
  • Requête vectorielle Python sans copie : Remplacement de la mémoire serialize_vector par VectorViewClause qui pointe directement sur le tampon numpy, éliminant les copies de mémoire redondantes pour les requêtes vectorielles denses Python. (#517)
  • Tokenizer UTF-8 et pliage ASCII : Intégré utf8proc 2.11.3 pour mettre à niveau le pipeline d'analyse de texte FTS avec une prise en charge complète d'Unicode — Détection des limites de mots prenant en charge Unicode, conversion des minuscules prenant en compte les points de code et un nouveau filtre de jeton pliable ASCII qui convertit les caractères Unicode en équivalents ASCII. (#515)
  • Standard Tokenizer (UAX #29) : Remplacement de l'ancien tokenizer de catégorie générale par des tableaux de limites de mots Unicode 17 UAX #29 générés à partir de données Unicode officielles, implémentant la sélection de jetons de style Lucene pour les séquences alphanumériques, numériques, idéographiques, hiragana, katakana, hangul, d'Asie du Sud-Est, d'indicateur régional et d'emoji communes. (#547)
  • Filtre de jetons Stemmer : Ajout d'un filtre de jetons Stemmer pour FTS basé sur Snowball 3.1.1, réduisant les mots à leur forme racine avec prise en charge de plus de 34 langues configurables via stemmer_lang dans extra_params. (#513)
  • DiskANN C API : Ajout d'interfaces complètes DiskANN C API, y compris les setter/getters de paramètres d'index, les paramètres de requête avec les opérations CRUD et le câblage des requêtes pour les requêtes vectorielles/requêtes vectorielles groupées/sous-requêtes, suivant les modèles HNSW/FTS existants. (#495)

🚀 Améliorations des performances

  • Requêtes de conjonction FTS plus rapides : Ajout du saut de bloc maximum et de la sortie anticipée du score à ConjunctionIterator - sautez des blocs non compétitifs entiers (128 documents) en vérifiant les limites supérieures du score maximum du bloc et court-circuitez l'accumulation de score lorsque la limite supérieure restante ne peut pas dépasser le seuil. Benchmark (500 000 documents, ensemble de données quora) : requêtes AND 22 à 38 % plus rapides, requêtes de phrases 33 % plus rapides. (#441)
  • Optimisation de l'index FIV : Optimisations diverses dans les composants internes de l'index FIV. (#528)

🐞 Corrections de bugs

  • Correction FTS : Correction des statistiques de segment non écrites à la réouverture, sémantique de filtre de correspondance nulle, lacunes d'identifiant de document global pendant le compactage et index en lecture seule d'instantanés sans vidage. (#566, #584, #588, #569)
  • Stabilité de l'index : Correction d'une course au réveil perdu dans les boucles de progression du générateur clairsemé DiskANN et HNSW, de l'analyse de la liste sélectionnée par la sonde IVF et de divers bogues d'index FIV. (#530, #544, #524)
  • SQL Engine : Correction de group_count / group_topk mal utilisés dans le moteur SQL. (#531)
  • Collection : Correction du fichier LOCK pour qu'il s'ouvre en lecture seule lorsque la collection est en lecture seule et préservation du segment d'écriture en direct lors des échecs CreateIndex/DropIndex DDL afin que les tâches de segment persistant ne corrompent plus le segment actif. (#541, #574)
  • Liaisons Python : Ajout de la validation des requêtes pendant l'exécution pour détecter rapidement les requêtes non valides. (#538)
  • Corrections de build : propagation des paramètres du compilateur vers Arrow ExternalProject, propagation de CMAKE_C_COMPILER vers LZ4, correction des définitions dupliquées et incompatibles de C API et acceptation de la chaîne de version libtool renommée de Xcode 26.5 dans la version iOS Arrow. (#542, #551, #525, #581)
  • Corrections diverses : Correction des chaînes de documentation incompatibles dans les stubs .pyi, clarification de l'erreur d'existence du chemin de création et correction des exemples README pour utiliser Query. (#529, #559, #558)

🔧 Refactorisation et nettoyage

  • Nettoyage API : Suppression de QueryParams::set_type() et formulation clarifiée des requêtes multiples dans la documentation. (#518, #590)
  • Qualité du code : Activation des contrôles ciblés du bugprone, ignoré les arbres de travail des sous-modules sales et correction des fautes de frappe dans les tests du chercheur de FIV. (#500, #523, #526)
  • Découplage d'E/S DiskANN : Remplacement du plugin DiskANN séparé .so et de la dépendance matérielle au moment de la construction sur libaio-dev par un singleton thread-safe qui dlopen libaio.so au moment de l'exécution et met en cache les pointeurs d'appel système. Revient au pread() synchrone avec un avertissement lorsque libaio est absent, simplifiant ainsi l'histoire de construction et de déploiement. (#532)

🤖 Améliorations de CI et de construction

  • Build Hardening : Prise en charge déclarée et appliquée de Python 64 bits uniquement. (#576)
  • CI Scheduling : La version RISC-V s'exécute désormais chaque semaine au lieu de par PR. (#577)
  • Augments de dépendance : actions/cache 5→6. (#537)

📝Documentation

  • README mis à jour, lien de code QR WeChat corrigé et formulation multi-requêtes clarifiée. (#589, #575, #590)
