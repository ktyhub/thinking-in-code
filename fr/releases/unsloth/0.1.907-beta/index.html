unsloth v0.1.907-beta

Pré-version Publié13 oct. 2026 Sourceunslothai/unsloth Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

le paresseux v0.1.907-beta

Unsloth a obtenu des améliorations de performances majeures !

Faits saillants

  • Gains de performances importants : tous les Unsloth UI/UX plus rapides - jusqu'à 10x pour plusieurs chats
  • Inférence jusqu'à 5 fois plus rapide : taux de réussite du cache de 95 %, correctifs de style MoE Strata, correctifs de ralentissement
  • Meilleur compactage - fonctionne pour tous les API + meilleure gestion de l'interface utilisateur
  • Faites glisser et déposez des fichiers : Desktop fonctionne à nouveau avec plus de 3 fois plus de fichiers pris en charge
  • Utilisation du navigateur avec des scripts : click, déplacez la souris, faites glisser, exécutez des scripts approuvés et définissez des règles de navigateur par site.
  • LTX-2.5 + Wan2.2 + Formation LoRA d'image plus rapide : nouvelle génération vidéo, image vers vidéo et formation d'image plus rapide.
  • NVIDIA RTX Spark : désormais pris en charge avec nos téléchargeables Windows ARM64
  • Mises à niveau majeures du flux de travail Unsloth : fichiers améliorés, historique des discussions, agent de navigateur et gestion des documents.
  • Compatibilité matérielle améliorée : correctifs Windows AMD, Intel XPU et CUDA/PyTorch.
  • Formation LoRA d'image plus rapide avec compartiments d'aspect, AdamW fusionné et prise en charge améliorée de FP8/MXFP8.

Performances

  • Les grands historiques de discussion et de formation se chargent par lots plus petits, utilisant moins de données de démarrage et de mémoire.
  • Les réponses de suivi commencent plus tôt dans les longues discussions GGUF, y compris les conversations avec de nombreux appels d'outils.
  • La génération LTX-2.5 s'exécute plus rapidement avec les paramètres par défaut en deux étapes lorsque la mémoire le permet.
  • Qwen3.5, Qwen3.6 et Qwen3.8 obtiennent un pré-remplissage et un décodage spéculatif plus rapides avec MLX.

Utilisation du navigateur

  • Les modèles peuvent click en un point, déplacer la souris et faire glisser les éléments de la page, y compris les cibles sans étiquette telles que les toiles.
  • Exécutez des scripts sur une page avec votre approbation à chaque fois, ou définissez Exécuter les scripts sur Jamais dans Paramètres > Navigateur.
  • Définissez des règles par site pour les clicks non étiquetés, y compris Toujours autoriser un site que vous trust.
  • Meilleure gestion des pages compressées, navigation côté client et contenu retardé dans l'interface utilisateur Web. Les modèles peuvent également remplir les champs de date et d'heure.
  • Appuyer sur Entrée dans un formulaire obtient le même contrôle d'approbation que cli cliquer sur son bouton d'envoi.

Images + vidéo

  • Générez des vidéos avec le LTX-2.5 à partir de texte ou d'une image de départ, avec audio synchronisé. GGUF
  • Ajoutez une image de démarrage avec Wan2.2-TI2V-5B, LTX-2 ou LTX-2.3 pour animer une image sur le même modèle chargé.
  • Choisissez les échantillonneurs et les planifications SDXL sur la page Images et chargez correctement les points de contrôle de prédiction v.
  • Recadrer les entrées d'image avant la génération. Les téléchargements de photos volumineuses et les téléchargements d'images vidéo ordinaires sont automatiquement redimensionnés.

Formation

  • La formation Image LoRA utilise AdamW fusionné par défaut sur les GPU NVIDIA, avec des compartiments de rapport hauteur/largeur pour les nouvelles exécutions prises en charge.
  • La formation FP8 LoRA pour FLUX et Z-Image utilise moins de mémoire sur les GPU NVIDIA Ada, Hopper et Blackwell. MXFP8 gère les seaux d'aspect sur Blackwell avec une pile torchao compatible.
  • Définissez Sample each dans l'onglet Train pour voir les images d'aperçu pendant la formation des images prises en charge et dans l'historique des exécutions.
  • Définissez l'abandon des légendes, l'abandon LoRA et la rétention des points de contrôle dans l'onglet Train de l'image. Le retournement aléatoire est désormais optionnel.
  • Affinez les modèles AWQ avec LoRA à l'aide de Transformers 5 et GPTQModel, et exportez les modèles INT4 QAT sous forme de poids quantifiés.

Chat + Bureau

  • Faites glisser à nouveau les fichiers dans le chat de bureau, y compris davantage de documents Office, de modèles, d'EPUB, de fichiers README, de fichiers dot et de médias.
  • Téléchargez des documents PDF et Office pris en charge jusqu'à 200 Mo dans l'interface utilisateur Web.
  • Les dossiers liés respectent les règles communes de .gitignore. Téléchargez des dossiers dans les sources du projet à partir de votre navigateur, réessayez les téléchargements ayant échoué et ouvrez les sources terminées.
  • Tapez /rewind ou choisissez Rewind dans le menu Plus d'un message pour restaurer la conversation, les fichiers suivis dans le dossier de discussion, ou les deux. Prévisualisez les modifications et annulez une restauration.
  • Utilisez /compact dans les discussions GGUF ou MLX enregistrées qui prennent en charge les outils permettant de compacter le contexte du message suivant. Des séparateurs en ligne marquent le compactage.
  • Téléchargez les fichiers créés par le modèle à partir des résultats de l'outil et activez les notifications lorsqu'une réponse en arrière-plan se termine.

Modèles + paramètres

  • Utilisez des modèles locaux dans VS Code Copilot Chat avec unsloth start vscode.
  • Les agents de codage peuvent utiliser Unsloth sur MCP avec une clé de compte API pour charger des modèles, générer, entraîner et exporter.
  • Choisissez un dossier de téléchargement de modèles et révélez ou supprimez les modèles répertoriés de LM Studio, Ollama et de vos propres dossiers.

Compatibilité matérielle

  • Correction de l'erreur de démarrage PyTorch/Triton sur les systèmes Windows AMD.
  • Intel XPU reconnaît le BF16 natif sur les GPU Arc et Data Center pris en charge sans Intel-ocloc, avec une sélection de GPU améliorée sur les hôtes Linux à tuile unique.
  • Évitez les erreurs obsolètes du lanceur Triton après avoir changé de version Python sur les systèmes CUDA.
  • Amélioration du chargement Gemma 4 E2B à faible VRAM, y compris le déchargement de la mémoire hôte sous Windows et WSL.
