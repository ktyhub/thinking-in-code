unsloth v0.1.911-beta

paresseux v0.1.911-beta

Cette version ajoute des tâches planifiées, la prise en charge de l'édition FLUX-3, des améliorations des performances et bien plus encore. Autre nouveauté : MiniMax-M3.1-Flash, retouches du visage pour les images et performances plus rapides + chats sur Mac.

Faits saillants

  • Tâches planifiées : exécutez une invite selon un planning avec un modèle local ou un API
  • MiniMax-M3.1-Flash : 428B MoE de MiniMax (23B actifs) Guide
  • Édition FLUX 3 : FLUX 3 prend désormais en charge l'édition d'images avec des invites
  • Améliorations des performances : gains de performances Mac importants, moins de décalage, tailles binaires réduites
  • Préréglages enregistrés : enregistrez vos paramètres d'exécution en tant que préréglages nommés pour chaque modèle

Tâches planifiées

  • Ouvrez Programmé dans le menu Plus de la barre latérale pour exécuter une invite une fois, quotidiennement, en semaine, hebdomadairement ou mensuellement ; chaque réponse est enregistrée en tant que nouvelle discussion.
  • Chaque tâche peut s'exécuter sur le modèle chargé, un modèle sur votre appareil ou un modèle d'un fournisseur API connecté.
  • Lorsque le modèle d'une tâche n'est pas chargé, Unsloth vous le demande avant de le charger, sauf si vous activez Changer automatiquement lorsque je suis absent.
  • Chaque tâche peut vous avertir après chaque exécution, uniquement en cas d'échec, ou jamais.
  • Les tâches s'exécutent uniquement pendant l'exécution d'Unsloth, sans outils ni recherche sur le Web.

UI + UX

  • Enregistrez les paramètres d'exécution dans le sélecteur de modèle en tant que préréglages nommés pour chaque modèle, puis renommez, supprimez ou basculez entre eux.
  • Le préréglage que vous avez choisi en dernier correspond à ce que ce modèle chargera la prochaine fois, y compris les chargements via le API.
  • Les paramètres de discussion peuvent mémoriser vos paramètres d'échantillonnage pour un modèle ou les réinitialiser aux valeurs recommandées du modèle.
  • Les discussions GGUF affichent désormais la progression et le temps restant lors du traitement d'une longue invite, avant le début de la réponse.
  • La page API affiche désormais l'utilisation du contexte, la vitesse et le nombre de requêtes de chaque modèle servi.
  • Chaque type de bouton et d'icône est désormais identique partout dans l'application.
  • Les pages Bibliothèque et Système dans Paramètres affichent le stockage sous forme de barre d'utilisation, divisée en modèles, caches et espace libre.

## Mac

  • Les chats MLX répondent désormais jusqu'à 16 % plus rapidement avec les brouillons de modèles.
  • Les modèles MLX livrés avec un modèle de brouillon intégré l'utilisent désormais automatiquement, sans téléchargement séparé.
  • Les rendus d'images et de vidéos nécessitent beaucoup moins de mémoire à la fin, donc les Mac à faible mémoire ralentissent rarement lors de l'échange.
  • Sur Apple Silicon, les Z-Image GGUF créent désormais des images à partir de texte avec le moteur MLX par défaut, 1.5-2x plus rapidement qu'avant.

Images + vidéo

  • Créez des vidéos à partir de texte ou d'une image avec Cosmos3-Edge de NVIDIA sur la page Vidéo.
  • Sur la page Images, activez Detailer pour redessiner les visages, les mains ou d'autres éléments que vous nommez avec une résolution plus élevée ; il a besoin de SAM 3 et d'un modèle capable de peindre.
  • Sur les GPU NVIDIA antérieurs à la série RTX 30, le rendu texte-vidéo Wan2.1 1,3B clips est environ 5 fois plus rapide.
  • Sur les GPU NVIDIA, de nombreux modèles d'images et de vidéos se chargent plus rapidement après la première fois, car Unsloth enregistre la version qu'il construit lors du premier chargement.
  • FLUX.3 Klein peut désormais éditer des photos dans Images > Modifier, en conservant les dimensions de la photo.

Formation

  • Divisez chaque couche d'un modèle entre les GPU pour la formation LoRA et QLoRA, afin que chaque GPU contienne moins : définissez UNSLOTH_TP_SIZE sur le nombre de GPU et lancez avec torchrun.
  • Le réglage fin des points de contrôle gpt-oss 4 bits d'Unsloth ne plante plus lors de la première étape de formation.
  • GRPO généré avec vLLM s'exécute jusqu'à 1,9 fois plus rapidement par étape avec LoRA 16 bits sous Linux avec les GPU NVIDIA.
  • GRPO qui génère sans vLLM s'exécute jusqu'à 4,4 fois plus rapidement par étape pour Llama et Qwen3 sur les GPU NVIDIA.

Agents de codage + API

  • Les applications utilisant une clé Unsloth API ne peuvent plus approuver leurs propres appels Python ou de terminal pour s'exécuter en dehors du bac à sable.
  • Unsloth ne transmet plus les adresses IP des trust aux client par défaut ; derrière votre propre proxy inverse, définissez UNSLOTH_STUDIO_TRUST_FORWARDED=1 ou tous les utilisateurs partagent une limite de taux de connexion.

Modèles + matériel

  • Exécutez MiniMax-M3.1-Flash, le modèle MoE de MiniMax pour le codage, l'utilisation des outils et les flux de travail des agents, avec jusqu'à 1 million de jetons de contexte. GGUF
  • À 1 bit, MiniMax-M3.1-Flash a besoin d'au moins 130 Go de RAM et de VRAM combinés.
  • Sur certains PC Windows, les modèles GGUF se chargent à nouveau au lieu d'échouer à chaque fois avec "llama-server failed to start".
