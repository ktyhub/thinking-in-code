API Changement

  1. Repenser la syntaxe DistSQL liée à la découverte de bases de données
  2. Dans DistSQL, le mot-clé GENERATED_KEY est ajusté à KEY_GENERATE_STRATEGY
  3. Le fournisseur d'autorité natif est marqué comme obsolète et sera supprimé dans une prochaine version.
  4. Mise à l'échelle : déplacez la configuration de mise à l'échelle de server.yaml vers config-sharding.yaml
  5. Mise à l'échelle : renommez clusterAutoSwitchAlgorithm SPI en complétionDetector et paramètre de méthode de refactorisation
  6. Mise à l'échelle : vérification de la cohérence des données, renommage de la méthode API et changement de type de retour
  7. Module de découverte de base de données Refactorisation API
  8. Le fractionnement en lecture-écriture prend en charge la configuration statique et dynamique
  9. Shadow DB supprime la configuration d'activation
  10. Type d'algorithme Shadow modifié

Amélioration

  1. Améliorer les performances de chargement de plusieurs tables uniques
  2. Supprimer la clause de commande ajoutée automatiquement par clé primaire
  3. Optimiser la logique de routage de la table de liaison sans partitionner la colonne en condition de jointure
  4. Prise en charge de la clé de partitionnement de mise à jour lorsque le résultat du routage de partitionnement reste le même
  5. Optimiser les performances du moteur de réécriture
  6. Prise en charge des déclarations select union/union all... par le moteur de fédération
  7. Prise en charge de l'insertion sur la colonne de partitionnement de mise à jour de clé en double lorsque le contexte de route reste le même
  8. Utilisez Union All pour fusionner les unités de route SQL pour une sélection simple afin d'améliorer les performances
  9. Prend en charge la validation automatique dans ShardingSphere-Proxy
  10. ShardingSphere openGauss Proxy prend en charge la méthode d'authentification sha256
  11. Supprimez la propriété java.net.preferIPv4Stack=true du script de démarrage du proxy
  12. Supprimez la vérification des règles nulles pour JDBC
  13. Optimiser les performances d'exécution de la liaison par lots openGauss
  14. Désactivez le détecteur de fuite de ressources Netty par défaut
  15. Les supports décrivent l'instruction préparée dans PostgreSQL / openGauss Proxy
  16. Optimiser les performances d'exécution des insertions par lots PostgreSQL
  17. Ajoutez instance_id au résultat de SHOW INSTANCE LIST
  18. Prise en charge de l'utilisation de instance_id pour effectuer des opérations lors de l'activation/désactivation d'une instance proxy
  19. Prise en charge de l'algorithme de création automatique lorsque CREATE SHARDING TABLE RULE, réduisant ainsi les étapes de création de règles
  20. Prise en charge de la spécification d'un KeyGenerator existant lors de la création d'une règle de table de partage
  21. DROP DATABASE prend en charge l'option SI EXISTE
  22. DATANODES dans SHARDING TABLE RULE prend en charge les expressions en ligne énumérées
  23. CREATE/ALTER SHARDING TABLE RULE prend en charge un algorithme de partitionnement complexe
  24. SHOW SHARDING TABLE NODES prend en charge les scénarios non-inline (plage, heure, etc.)
  25. Lorsqu'il n'y a qu'une seule source de données en lecture dans la règle de fractionnement en lecture-écriture, elle ne peut pas être désactivée
  26. Mise à l'échelle : ajout d'une prise en charge de base de la vérification de la cohérence des données de streaming fragmentées
  27. Optimisation de la logique de décision de l'algorithme Shadow pour améliorer les performances
