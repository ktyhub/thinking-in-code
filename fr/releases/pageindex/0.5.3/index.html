PageIndex v0.5.3

Correctif Publié5 nov. 2026 SourceVectifyAI/PageIndex Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

Indice de page v0.5.3

  • Moins cher que le vecteur RAG : pour l'index et la requête.
  • Plus rapide : les arbres sont créés à partir des statistiques de mise en page.
  • Unifié SDK : RAG sans vecteur. Local ou cloud, pour l'index et le chat.
  • Fonctionne avec votre abonnement Claude.

Index, pour discuter, pour l'intégration d'agents, un client. Le mode local ne nécessite aucun serveur, aucune base de données vectorielle, aucune clé PageIndex API.

client = PageIndexClient()
client.submit_document("report.pdf")
client.chat("What does the report conclude?")

Faits saillants

  • Moteur Flash : la valeur locale par défaut (mode="standard" conserve le pipeline LLM classique). Les signets intégrés sont consommés lorsque trustworthy et l'optimisation de l'arborescence est activée par défaut - optimize="merge" pour le passage déterministe sans LLM, "full" (par défaut) ajoute l'expansion LLM, qui exécute une vague de nœuds simultanément au lieu d'un aller-retour à la fois.
  • Une surface complète, locale et cloud : PageIndexLocalClient(storage_path=...) est le même client que le cloud : les outils de soumission, d'arborescence, de contenu de page, de chat et d'agent sont tous présents dans les deux modes, de sorte que le code se déplace entre eux sans changement.
  • Documents cloud, votre propre modèle : api_key décide de l'emplacement de vos documents ; un modèle de chat configuré décide qui répond – et les deux se combinent. PageIndexClient(api_key="pi-...", chat_model="openai/gpt-5.2") exécute le même moteur d'assurance qualité des documents en cours sur l'ensemble d'outils cloud en direct. Le contenu de la page circule tout au long de votre processus jusqu'à votre fournisseur sur vos informations d'identification ; doc_id cible au niveau de l'invite ; enable_citations reste avec le chat géré.
  • Intégration d'agent : le contrat de l'outil cloud MCP, en cours – client.agent_tools() (fonctions simples), as_openai_tools(), as_anthropic_tools(), as_claude_mcp(), plus les bundles openai_agent_config() / anthropic_runner_config() / claude_agent_config() à appel unique et agent_instructions() pour l'invite système. Cloud clients obtient l'ensemble d'outils de serveur en direct via le pont MCP (point de terminaison en lecture seule par défaut) ; Les clients locaux obtiennent le sous-ensemble en cours avec les mêmes schémas et enveloppes — le port des invites de l'agent reste inchangé.
  • Surfaces de discussion : chat() — question posée, réponse, sur n'importe quel backend ; chat(stream=True) montre l'exécution telle qu'elle se produit, les réflexions et les appels d'outils intégrés au texte, ou sous forme d'événements saisis via .events ; chat(protocol="responses" | "messages") pilote les réponses OpenAI ou les messages anthropiques API de manière native avec les propres formes de ce protocole, et chat_completions() conserve l'enveloppe compatible OpenAI, le tout avec le ciblage, le streaming, la comptabilité d'utilisation honnête et la continuité du cache d'invite d'un tour à l'autre doc_id. Les transcriptions s'ajoutent textuellement : la sortie d'une voie de protocole revient inchangée dans la requête suivante.
  • Modèle et boutons de connexion : index_model / chat_model, index_backend / chat_backend (et par appel backend) transmis textuellement à chaque voie - fournisseurs acheminés par LiteLLM, serveurs compatibles OpenAI sans clé, Azure/Bedrock/Vertex inclus.
  • index= / chat= slots : l'orthographe groupée des arguments plats — un raccourci de chaîne ou un mappage (index={"model": ..., "storage_path": ...}, chat={"model": ..., "backend": ...}). "cloud" / "local" nomment un côté, un mode= en option le vérifie et PageIndexLocalClient / PageIndexCloudClient prennent les mêmes emplacements. PageIndexCloudClient() lit PAGEINDEX_API_KEY ; un PageIndexClient() nu reste local, quel que soit l'environnement.
  • Formes de configuration typées : IndexConfig / CloudIndexConfig / LocalIndexConfig / ChatConfig, avec py.typed expédié pour que votre vérificateur de type les voie.
  • Rien n'échoue tranquillement : les clés inconnues, les faces mixtes, les valeurs vides et les conflits mode/contenu refusent la construction avec le vocabulaire juridique du message ; les informations d'identification mortes ou un modèle manquant échouent à l'exécution de l'indexation au lieu de stocker un document avec des résumés vierges ; chaque erreur cloud porte son statut HTTP.
  • Dépendances : Python >= 3.10 ; openai-agents dans l'installation de base (le moteur de discussion) ; Extras [anthropic] et [claude] pour ces SDK. Pillow >= 9.0 est désormais une dépendance obligatoire pour highlight_region.

Également dans 0.5.3

  • Résumés moins chers et plus rapides. Les résumés de nœuds s'exécutent désormais avec le moins de réflexion nécessaire pour chaque modèle : "none", sinon "minimal", sinon "low", et sur Claude ses propres interrupteurs d'arrêt. Sur un rapport de revenus de 22 pages, les résumés de gpt-5-nano coûtent un dixième et se terminent en 9 s au lieu de 64 s, et ceux de o3 coûtent moins de la moitié.
  • L'indexation arrête de payer pour les écritures de cache qu'elle ne lit jamais. Sur les modèles qui facturent une écriture de cache d'invite au-dessus de l'entrée, tels que GPT-5.6 et versions ultérieures, l'indexation n'écrit aucun cache : gpt-6-luna indexe 1 000 pages pour $0.164 au lieu de $0.184. index_backend={"prompt_cache_options": {"mode": "implicit"}} conserve la propre mise en cache du modèle, ce qui permet à un document réindexé dans les 30 minutes de lire le cache de la première exécution.
  • ** RUPTURE : un effort de raisonnement que vous choisissez arrive comme choisi. ** Un summary_reasoning_effort ou un index_backend reasoning_effort que le modèle ne prend pas était abandonné sans être vu (gpt-5-nano étant donné que "none" fonctionnait à sa pensée par défaut complète, 7 fois plus lentement que de le laisser non défini). Il se déclenche désormais avant tout appel de modèle et indique quoi transmettre à la place.

Également dans 0.5.2 :

  • Flash sur PageIndex Cloud. client.submit_document("report.pdf", mode="flash") crée l'arborescence d'un document cloud avec Flash, comme le fait le mode local.
  • BREAKING : le cloud mode ne prend que "flash" ou rien. "standard" reste local uniquement, et toute autre valeur, y compris "mcp", augmente au lieu d'être transmise au serveur.

Également dans 0.5.1 :

  • Flash analyse les gros PDF avec beaucoup moins de mémoire. Sur une machine équipée d'un ou deux processeurs, ou pour un document avec des polices de type 3, l'analyseur de Flash contient désormais une page à la fois au lieu du document entier : un manuel de 1 665 pages culmine à 434 Mo au lieu de 3.1 Go. L'arbre est inchangé.
  • Une carte de police endommagée ne bloque plus Flash. Un ), { ou } parasite dans la carte ToUnicode d'une police a effectué une boucle d'analyse jusqu'à épuisement de la mémoire ; ces PDF sont désormais indexés.

Également dans 0.5.0 :

  • Les modèles de raisonnement conservent leur raisonnement. Chaque requête d'un chat, et chaque tour qui suit, renvoie au modèle son propre raisonnement, sur chaque itinéraire : la pensée de Claude, le reasoning_content de Kimi, GLM, Qwen et autres, le reasoning_details d'OpenRouter, les éléments de raisonnement de GPT, les signatures de pensée de Gemini et le raisonnement crypté de Bedrock. Claude, via une passerelle telle qu'OpenRouter, lit désormais également le cache d'invites.
  • reasoning_effort="none" désactive la réflexion de Claude, dans chat() et dans les résumés d'index, où c'est la valeur par défaut (le Sonnet 5.5 réfléchit toujours entre les appels d'outils). Sur les Opus 5.5 et Fable, qui ne peuvent pas l'éteindre, et sur n'importe quel modèle claude-code/, un "none" explicite se déclenche et le résumé par défaut les exécute au niveau bas.
  • Les modèles plus récents que le modèle de carte de LiteLLM fonctionnent, tels que bedrock/global.openai.gpt-6.1-terra : là où LiteLLM en refuse un, PageIndex récupère une fois la carte publiée de LiteLLM et l'envoie à nouveau. LITELLM_LOCAL_MODEL_COST_MAP=True désactive cette fonction.
  • Les tentatives suivent les SDK officiels OpenAI et Anthropic sur l'indexation, le chat et le cloud API : une limite de débit attend le temps que le serveur demande, jusqu'à 60 s, une clé OpenAI manquante échoue immédiatement, et 402, 413 et 422 ne sont pas réessayées. Les résumés Flash s'exécutent au nombre de 128 à la fois, de sorte que l'étape de résumé est environ un quart plus rapide sur les documents volumineux.
  • L'indexation des abonnements Claude s'exécute comme un seul workflow Claude Code, jusqu'à 64 résumés à la fois au lieu de 16. PAGEINDEX_CLAUDE_CODE_WORKFLOW=0 revient à un processus par appel.
  • Les travailleurs forkés ne se bloquent plus. Un travailleur provenant d'un processus avec un client (multiprocessing sous Linux, gunicorn --preload, Celery) ne se bloque plus ou ne lit plus les réponses d'un autre processus.
  • BREAKING : extra_body atteint tous les fournisseurs. Les champs uniquement pris par OpenAI, tels que store et verbosity, ont été abandonnés sans être vus sur Claude et Gemini et augmentent désormais ; litellm.drop_params = True les laisse tomber à nouveau. extra_body refuse reasoning_effort, qui a son propre argument.
  • BREAKING : un délai d'attente de lecture dans le cloud génère le ConnectionError des requêtes après ses tentatives au lieu de ReadTimeout, donc except requests.Timeout ne l'attrape plus.
  • L'historique Gemini enregistré sans model, tel que 0.4.5 à 0.4.7 l'a renvoyé, envoie des appels d'outils Gemini antérieurs sans leur propre signature de pensée. L'historique enregistré avec model les conserve.

Également dans 0.4.7 :

  • Lire et modifier les champs de métadonnées d'un dossier. get_metadata_schema(folder_id) renvoie les champs qui s'appliquent aux documents d'un dossier (ceux de son dossier de niveau supérieur, sinon ceux du compte), et delete_metadata_schema(folder_id) supprime ceux déclarés par le dossier, afin qu'ils puissent être à nouveau déclarés avec create_metadata_schema(). Les documents conservent leurs métadonnées. Nuage uniquement.

Également dans le 0.4.6 :

  • La voie Messages fonctionne avec anthropic 2.2. anthropic 2.2.0 exécute son outil d'exécution sur un thread détenu par le serveur par défaut, donc derrière un proxy tel que le point de terminaison Anthropic d'OpenRouter, le deuxième appel de modèle a échoué et le messages renvoyé a répété la réponse finale. chat(protocol="messages") envoie désormais l'intégralité de la conversation à chaque tour, comme dans les versions anthropiques précédentes, et messages transmet chaque tour une fois.

Également dans 0.4.5 :

  • Le chat multi-tours conserve le cache des invites. Avec un modèle de chat API, chat_completions() et chat(protocol="chat_completions") renvoient les nouveaux messages de l'exécution (appels d'outil, résultats d'outil, réponse) sous messages (streaming avec stream_metadata=True : sur le bloc d'utilisation de clôture). Ajoutez-les, history += r["messages"], et le tour suivant renvoie exactement ce que le modèle a vu, de sorte que le cache d'invite continue de fonctionner. Responses déplace également sa transcription vers messages ; items lit toujours, avec un DeprecationWarning, jusqu'à ce qu'une version ultérieure le supprime.
  • Les résultats se lisent comme les SDK officiels. Les voies de protocole renvoient ChatObject : toujours un dict, et également lisible par attribut de la même manière que le SDK officiel lit les mêmes JSON, r.choices[0].message.content. Un flux Messages se termine par get_final_message() / get_final_text(), et un flux Réponses s'ouvre par response.created puis response.in_progress.
  • Utilisation du jeton, échecs inclus. L'indexation locale renvoie usage et le chat propre au modèle usage répertorie chaque appel de modèle (un modèle claude-code/ rapporte le total). Une exécution échouée rapporte ce qu'elle a dépensé sur PageIndexAPIError.usage, et une réponse raccourcie (longueur, filtre de contenu, refus) soulève au lieu de renvoyer une demi-réponse, avec le texte jusqu'à présent sur partial_answer.
  • create_metadata_schema(folder_id, fields) déclare les champs de métadonnées que les documents d'un dossier peuvent contenir ; Les filtres de recherche de métadonnées du chat, les trie et les comptent. Nuage uniquement.
  • Les outils d'agent local se décrivent comme le serveur cloud MCP, donc une invite écrite sur l'un lit le même texte d'outil sur l'autre.
  • BREAKING : les événements du flux de messages sont des dicts. chat(protocol="messages", stream=True) génère des dicts ChatObject au lieu des objets d'événement Anthropic SDK. event.type, event["type"] et event.model_dump() fonctionnent tous, mais isinstance / match ne correspondent plus aux classes d'événement du SDK, et la définition d'un attribut (event.delta.text = ...) laisse l'événement inchangé : modifiez le dict (event["delta"]["text"] = ...).
  • BREAKING : extra_body ne prend plus model, folder_id ou api_base. Passez plutôt model=, folder_id= ou backend=.
  • litellm 1.105.1 ou plus récent, inférieur à 1.106, jusqu'à ce que l'importation mcp de 1.106 soit corrigée. pip install -U pageindex choisit une version correspondante.

Également dans 0.4.4 :

  • Un identifiant manquant indique comment se connecter. L'indexation sur un modèle claude-code/ sans identifiant Claude, ou avec un identifiant expiré, échoue désormais avec une courte erreur qui se termine par le correctif : exécutez claude, puis /login. Les erreurs liées aux appels de synchronisation submit_document() et chat(), sur n'importe quel modèle, n'affichent plus un RuntimeError: no running event loop sans rapport au-dessus d'eux.

Également dans 0.4.3 :

  • Claude fonctionne plus silencieusement. Sur Python 3.12 et versions antérieures, claude-code/ s'exécute et les applications utilisant as_claude_mcp() n'impriment plus l'avertissement "… signalera le code de retour 255" d'asyncio.
  • Un ancien agent SDK le dit. Avec un claude-agent-sdk plus ancien que le 0.2.166, les modèles claude-code/ s'arrêtent désormais d'emblée avec la commande qui le corrige, pip install -U "pageindex[claude]".
  • Un exemple d'abonnement. cookbook/pageindex-claude-subscription.py indexe un article avec claude-code/haiku et diffuse une réponse de claude-code/opus.

Également dans 0.4.2 :

  • Exécutez votre abonnement Claude. Réglez index_model ou chat_model sur un modèle claude-code/, par ex. chat="claude-code/opus", et indexation et chat() appellent les modèles Claude via Claude Code : l'utilisation est couverte par votre forfait, et aucune clé API n'est nécessaire (pip install -U "pageindex[claude]"). L'indexation locale s'exécute en mode Flash.

Également dans 0.4.1 :

  • Flash lit correctement les dépôts. Le lien "Table des matières" en haut de chaque page ne masque plus les titres d'un dépôt (un AmEx 10-K avait ses 131 premières pages dans un seul nœud et indexe désormais environ 30 % moins cher). Des notes numérotées de 20 et suivantes rejoignent le plan, deux rapports d'audit portant le même titre conservent chacun un titre et une diapositive construite page par page constitue une section.
  • Développez-vous dans n'importe quel script. L'expansion de l'arborescence divise désormais les sections intitulées en chinois, japonais, arabe, hindi et autres scripts, demande à nouveau après une réponse qu'il ne peut pas analyser et conserve le texte d'un nœud court jusqu'à la longueur du résumé (summary_max_words) plutôt que 200 jetons fixes.
  • Plus de fournisseurs. Les résumés de nœuds désactivent le raisonnement sur les modèles que LiteLLM ne signale pas, OpenRouter parmi eux, et chat(protocol="responses" | "messages") envoie le nom du modèle tel que vous l'avez écrit, donc les services compatibles OpenAI et Anthropic tels que OpenRouter fonctionnent sur ces voies.

Également dans 0.4.0 :

  • Indexation Flash moins chère. Une feuille résume uniquement son propre texte, la description du document lit les résumés de niveau supérieur, les résumés de nœuds sont par défaut reasoning_effort="none" sur les modèles qui l'acceptent (summary_reasoning_effort choisit une autre valeur), et développe les demandes une fois par section et se divise uniquement lorsque les morceaux sont moins chers à lire que le tout.
  • Nouveaux modèles par défaut. Le mode local indexe avec gpt-6-luna et répond avec gpt-6-sol lorsqu'aucun modèle n'est défini. Un cloud client sans modèle de chat utilise toujours le chat géré.
  • litellm 1.105.0 ou plus récent, la première version connaissant gpt-6-luna. pip install -U pageindex le met à niveau.

Également dans le 0.2.22 :

  • Flash conserve les mots entiers. Les espaces entre les mots sont mesurés à partir de la largeur de police de chaque code de caractère, de sorte que le texte et les titres des pages ne divisent plus les mots comme « inférence », et un titre de chapitre correspond à nouveau à son signet.
  • Arbres Flash plus stables. L'indexation n'échoue plus avec "supprimé ou modifié après avoir été marqué comme final", un en-tête en cours d'exécution ne coupe plus une introduction ou la préface d'une page plus tôt, et le développement ne conserve que les sous-sections imprimées à l'intérieur d'un nœud. Le optimize_tree(pdf_path) et le tree_optimize CLI lisent les pages à deux colonnes dans l'ordre de mise en page et n'ont plus besoin de pymupdf.
  • Mode standard. La division en grande section ne boucle plus indéfiniment lorsque le modèle répertorie un titre au-dessus de celui de la section (une « PARTIE II » au-dessus du « Chapitre 3 »), et un élément de la table des matières ne se termine jamais avant d'avoir commencé.

Également dans 0.2.21 :

  • BREAKING : une forme d'arbre, local et cloud. Les nœuds get_tree transportent start_index, end_index et summary dans les deux modes ; page_index et prefix_summary ont disparu. Dans un document nouvellement indexé, la plage et le résumé d'un parent couvrent toute sa section, et les pages précédant sa première sous-section deviennent un nœud "<title> (intro)". Les documents indexés précédemment conservent leurs propres plages et résumés.
  • Local get_ocr(format="node") renvoie le propre texte de chaque nœud. Le texte d'un parent s'arrête à la page sur laquelle commence sa première sous-section et est vide lorsqu'un nœud d'introduction contient cette ouverture ; les nœuds d'introduction apparaissent comme leurs propres entrées. Les documents indexés précédemment se lisent également de cette façon, sans réindexation.
  • Navigation par nœuds. get_node, get_node_parent, get_node_path et get_node_map dans pageindex.utils prennent l'arbre de get_document_structure() et le parcourent localement, donc une récupération sert à un nombre illimité de recherches.
  • Le mode standard résume comme Flash. Chaque résumé de section démarre dès que ses sous-sections sont terminées, et les nœuds courts conservent leur propre texte.

Également dans 0.2.20 :

  • Indexation Flash plus rapide. Les résumés de nœuds exécutent d'abord le nœud le plus profond et démarrent pendant que l'expansion de l'arborescence est encore en train de décider, de sorte que les canaux du modèle ne restent jamais inactifs : un rapport de 222 pages indexe en 73 s au lieu de 98 s, un livre de 758 pages en 137 s au lieu de 174 s. Chaque résumé est désormais limité à summary_max_words (150 par défaut), ce qui réduit l'étape de résumé d'un tiers ou de moitié.
  • Boutons d'indexation sur le client. summary_max_words, summary_concurrency, use_embedded_toc et optimize sont réglables sur le PageIndexClient(...) ou dans le slot index= (mode Flash local), et --summary-max-words / --summary-concurrency rejoignent le CLI. Le summary_concurrency abaisse toute la voie d'indexation en même temps pour une limite de débit serrée.
  • Les voies anthropiques prennent votre modèle tel qu'écrit. chat(protocol="messages"), anthropic_runner_config() et claude_agent_config() utilisent le chat_model que vous avez défini, donc model= n'est plus nécessaire. Le préfixe choisit l'itinéraire : bedrock/, vertex_ai/ et azure_ai/ vont à Bedrock, Vertex AI et Azure AI Foundry, tout le reste directement à Anthropic. Le supplément [anthropic] nécessite désormais anthropic>=0.122.0.
  • list_documents accepte le limit jusqu'à 10 000 (au lieu de 100), et les clients locaux acceptent le folder_id="root".

Également dans 0.2.19 :

  • BREAKING : resolve_citations renommé get_citations. La méthode de retour de liste fournie dans 0.2.17 est désormais client.get_citations(answer, doc_id=...). Mêmes arguments, même résultat.
  • resolve_citations renvoie des citations prêtes à être affichées. client.resolve_citations(answer, doc_id=...) renvoie désormais {"answer": ..., "citations": [...]} — le texte de réponse avec chaque balise de citation remplacée par un lien de démarque numéroté [[1]](#pageindex-citation-01), et les données complètes de chaque citation dirigées par anchor et index.
  • highlight_region dessine une surbrillance translucide sur une région de cadre englobant sur une image de page. Accepte une image PIL ou des octets bruts, renvoie une nouvelle image PIL. Importable à partir du pageindex.
  • get_page_image et get_document_image renvoient des URL de courte durée vers des images de page et des images intégrées extraites par OCR. Nuage uniquement.
  • get_document_path, get_folder_path, get_folder_id traduisent entre les identifiants et les chemins lisibles comme "Research/Papers/attention.pdf".
  • get_document_id accepte un chemin : client.get_document_id("Research/Papers/report.pdf") supprime automatiquement la partie dossier.
  • list_documents(recursive=True) renvoie les documents dans des sous-dossiers.
  • Règles de dénomination partagées pour le téléchargement de documents et la création de dossiers, alignées sur Chat et Compute.

Également dans le 0.2.18 :

  • get_document_id(name) recherche l'ID d'un document par son nom d'affichage en un seul appel API, utile pour résoudre les noms de documents de citation en ID.
  • Alignement des invites : les invites locales de citation et de découverte du SDK correspondent désormais au serveur de chat MCP – le pied de page "Sources" inventé est supprimé, une étape de persistance de reformulation et de nouvelle tentative manquante est restaurée et le didacticiel de pagination uniquement du SDK est supprimé des instructions de découverte.

Également dans 0.2.17 :

  • Les citations sont résolues en coordonnées de page. client.get_citations(answer, doc_id=...) lit les balises de citation dans une réponse citée (les balises <cite doc="…" page="…" block="…"/> écrites par chat(citations=True) et les balises <doc=…;page=…;block=…> écrites par le chat géré) et renvoie une entrée par citation avec l'identifiant du document ; pour une citation au niveau du bloc sur un document cloud indexé avec beta_headers=["block_reference"], l'entrée contient également la page, le cadre de délimitation, le type et le texte du bloc. Transmettez doc_id= (ce que chat(doc_id=...) a pris) pour étendre la recherche de nom, ou omettez-la pour la résoudre par rapport à votre bibliothèque.
  • Un bloc, un appel. client.get_block(doc_id, block_id) renvoie un seul bloc de mise en page tel que le API le sert — {doc_id, page, block_id, bbox, block_type, text}, bbox comme [x0, y0, x1, y1] en millièmes de largeur et de hauteur de la page (0-1000), origine en haut à gauche. Cloud uniquement ; le contenu de la page locale n'a aucun blocage.
  • Flash indexe chaque document, dans chaque script. La mise en page décide de l'arborescence, jamais du script : les petits documents, les jeux de diapositives et les PDF japonais, arabes, hébreux, indiens, thaïlandais et à script mixte qui étaient auparavant refusés ou perdaient leurs titres sont désormais indexés, et la même mise en page donne les mêmes titres dans chaque script. Lorsqu'aucune hiérarchie n'est détectée, l'arborescence revient à un nœud par page (toc_source="pages") ; les pages précédant un premier titre tardif obtiennent un nœud Preface, donc chaque page est accessible à partir d'un nœud ; toc_source figure sur chaque résultat (detected, bookmarks, hybrid, pages, unreadable).
