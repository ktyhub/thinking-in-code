PageIndex v0.2.17

Index des pages v0.2.17

  • Le PageIndex SDK, local ou cloud — RAG sans vecteur, basé sur le raisonnement, de bout en bout.
  • Indexation beaucoup plus rapide — le moteur PageIndex Flash récupère l'arborescence à partir des statistiques de mise en page : aucun LLM n'est impliqué pour la génération de la structure elle-même, les LLM écrivent uniquement les résumés des nœuds et l'expansion de l'arborescence propose une vague de nœuds simultanément.
client = PageIndexClient()
client.submit_document("report.pdf")
client.chat("What does the report conclude?")

Index, pour discuter, pour l'intégration d'agents, un client. Le mode local ne nécessite aucun serveur, aucune base de données vectorielle, aucune clé PageIndex API.

Faits saillants

  • Moteur Flash : la valeur locale par défaut (mode="standard" conserve le pipeline LLM classique). Les signets intégrés sont consommés lorsque trustworthy et l'optimisation de l'arborescence est activée par défaut - optimize="merge" pour le passage déterministe sans LLM, "full" (par défaut) ajoute l'expansion LLM, qui exécute une vague de nœuds simultanément au lieu d'un aller-retour à la fois.
  • Une surface complète, locale et cloud : PageIndexLocalClient(storage_path=...) est le même client que le cloud : les outils de soumission, d'arborescence, de contenu de page, de chat et d'agent sont tous présents dans les deux modes, de sorte que le code se déplace entre eux sans changement.
  • Documents cloud, votre propre modèle : api_key décide de l'emplacement de vos documents ; un modèle de chat configuré décide qui répond – et les deux se combinent. PageIndexClient(api_key="pi-...", chat_model="openai/gpt-5.2") exécute le même moteur d'assurance qualité des documents en cours sur l'ensemble d'outils cloud en direct. Le contenu de la page circule tout au long de votre processus jusqu'à votre fournisseur sur vos informations d'identification ; doc_id cible au niveau de l'invite ; enable_citations reste avec le chat géré.
  • Intégration d'agent : le contrat de l'outil cloud MCP, en cours – client.agent_tools() (fonctions simples), as_openai_tools(), as_anthropic_tools(), as_claude_mcp(), plus les bundles openai_agent_config() / anthropic_runner_config() / claude_agent_config() à appel unique et agent_instructions() pour l'invite système. Cloud clients obtient l'ensemble d'outils de serveur en direct via le pont MCP (point de terminaison en lecture seule par défaut) ; Les clients locaux obtiennent le sous-ensemble en cours avec les mêmes schémas et enveloppes — le port des invites de l'agent reste inchangé.
  • Surfaces de discussion : chat() — question posée, réponse, sur n'importe quel backend ; chat(stream=True) montre l'exécution telle qu'elle se produit, les réflexions et les appels d'outils intégrés au texte, ou sous forme d'événements saisis via .events ; chat(protocol="responses" | "messages") pilote les réponses OpenAI ou les messages anthropiques API de manière native avec les propres formes de ce protocole, et chat_completions() conserve l'enveloppe compatible OpenAI, le tout avec le ciblage doc_id, le streaming, la comptabilité d'utilisation honnête et la continuité du cache d'invite d'un tour à l'autre. Les transcriptions s'ajoutent textuellement : la sortie d'une voie de protocole revient inchangée dans la requête suivante.
  • Modèle et boutons de connexion : index_model / chat_model, index_backend / chat_backend (et par appel backend) transmis textuellement à chaque voie - fournisseurs acheminés par LiteLLM, serveurs compatibles OpenAI sans clé, Azure/Bedrock/Vertex inclus.
  • index= / chat= slots : l'orthographe groupée des arguments plats — un raccourci de chaîne ou un mappage (index={"model": ..., "storage_path": ...}, chat={"model": ..., "backend": ...}). "cloud" / "local" nomment un côté, un mode= en option le vérifie et PageIndexLocalClient / PageIndexCloudClient prennent les mêmes emplacements. PageIndexCloudClient() lit PAGEINDEX_API_KEY ; un PageIndexClient() nu reste local, quel que soit l'environnement.
  • Formes de configuration typées : IndexConfig / CloudIndexConfig / LocalIndexConfig / ChatConfig, avec py.typed expédié pour que votre vérificateur de type les voie.
  • Rien n'échoue tranquillement : les clés inconnues, les faces mixtes, les valeurs vides et les conflits mode/contenu refusent la construction avec le vocabulaire juridique du message ; les informations d'identification mortes ou un modèle manquant échouent à l'exécution de l'indexation au lieu de stocker un document avec des résumés vierges ; chaque erreur cloud porte son statut HTTP.
  • Dépendances : Python >= 3.10 ; openai-agents dans l'installation de base (le moteur de discussion) ; Extras [anthropic] et [claude] pour ces SDK.

Également dans 0.2.17

  • Les citations sont résolues en coordonnées de page. client.resolve_citations(answer, doc_id=...) lit les balises de citation dans une réponse citée (les balises <cite doc="…" page="…" block="…"/> écrites par chat(citations=True) et les balises <doc=…;page=…;block=…> écrites par le chat géré) et renvoie une entrée par citation avec l'identifiant du document ; pour une citation au niveau du bloc sur un document cloud indexé avec beta_headers=["block_reference"], l'entrée contient également la page, le cadre de délimitation, le type et le texte du bloc. Transmettez doc_id= (ce que chat(doc_id=...) a pris) pour étendre la recherche de nom, ou omettez-la pour la résoudre par rapport à votre bibliothèque.
  • Un bloc, un appel. client.get_block(doc_id, block_id) renvoie un seul bloc de mise en page tel que le API le sert — {doc_id, page, block_id, bbox, block_type, text}, bbox comme [x0, y0, x1, y1] en millièmes de la largeur et de la hauteur de la page (0-1000), origine en haut à gauche. Cloud uniquement ; le contenu de la page locale n'a aucun blocage.
  • Flash indexe chaque document, dans chaque script. La mise en page décide de l'arborescence, jamais du script : les petits documents, les jeux de diapositives et les PDF japonais, arabes, hébreux, indiens, thaïlandais et à script mixte qui étaient auparavant refusés ou perdaient leurs titres sont désormais indexés, et la même mise en page donne les mêmes titres dans chaque script. Lorsqu'aucune hiérarchie n'est détectée, l'arborescence revient à un nœud par page (toc_source="pages") ; les pages précédant un premier titre tardif obtiennent un nœud Preface, donc chaque page est accessible à partir d'un nœud ; toc_source figure sur chaque résultat (detected, bookmarks, hybrid, pages, unreadable). Changelog complet : https://github.com/VectifyAI/PageIndex/compare/v0.2.16...v0.2.17
