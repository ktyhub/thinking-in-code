#hermès-agent v0.22.0

Agent Hermès v0.22.0

Date de sortie : 13 octobre 2026 Depuis v0.21.0 : ~24 200 commits · ~6 080 PR fusionnés · ~15 600 fichiers modifiés · ~2 045 000 insertions · ~1 140 000 suppressions · ~7 180 problèmes résolus · ~2 520 contributeurs

Le Seuil de Libération. Hermès était le dieu des seuils : la porte, le passage, la borne. v0.21.0 a assemblé le panthéon ; v0.22.0 consiste à franchir la porte. Une nouvelle installation de bureau s'ouvre désormais sur une discussion de configuration guidée qui fonctionne sur un modèle d'essai gratuit, de sorte qu'un nouveau venu parle à Hermes avant de posséder une clé API. Les connecteurs transportent l'agent dans les applications que vous utilisez déjà, sans qu'aucun compte ne soit nécessaire pour démarrer. Les modèles locaux l'intègrent à votre propre matériel avec un runtime one-click llama.cpp. Et le seuil lui-même est devenu plus solide : les versions stables testées de SemVer qui s'installent par défaut, les packages de bureau signés (y compris le Microsoft Store) et un gestionnaire de packages sous tout. Autour de cette colonne vertébrale : un catalogue de 600 plugins, la vague de modèle Claude 5.5 / GPT-6, une connexion avec un gestionnaire de mots de passe pour le navigateur, un écran de robot que vous pouvez prendre en charge, un backend et une passerelle pour chaque profil, et une base de code un tiers plus petite. Il s'agit de la plus grande fenêtre livrée par Hermes, environ 2,5 fois le cycle v0.21.0, et elle regroupe et documente entièrement les versions de correctifs v0.21.1 – v0.21.7.

✨ Points forts

  • Un premier lancement qui s'installe tout seul — Ouvrez l'application de bureau sur un ordinateur sur lequel vous n'avez jamais utilisé Hermes et elle démarre une courte discussion de configuration au lieu d'un écran de paramètres. Une carte à la fois, il vous demande votre nom, une couleur d'accent et une mise en page, les applications à connecter, les plugins à installer, puis vous donne un aperçu rapide et propose jusqu'à quatre premières tâches sélectionnées pour vous. Il fonctionne sur un modèle d'essai gratuit (nous/welcome, une fois par utilisateur du système d'exploitation), il n'a donc besoin d'aucune clé ; Ignorer la configuration y met fin et Paramètres → Exécuter à nouveau l'intégration le ramène. L'agent a également obtenu set_theme, donc "le rendre violet, mode sombre" fonctionne dans n'importe quelle discussion de bureau. (#137429, #137522, #137807, #134209, #105258 — @alt-glitch, @OutThisLife, @ethernet8023, @rewbs)

  • Connecteurs : Hermes fonctionne dans vos applications — L'agent peut désormais agir dans des applications hébergées telles que Linear et Notion via la passerelle d'outils Nous : demandez une application, connectez-vous une fois dans votre navigateur et les outils sont utilisables en même temps. Vous n'avez pas besoin d'un compte Nous pour démarrer ; la première fois que vous utilisez une application, Hermes crée une identité gratuite uniquement composée de connecteurs. Le bureau dispose d'une nouvelle page Connecteurs qui regroupe les applications hébergées et vos serveurs MCP dans une seule liste (elle remplace l'onglet MCP), la même carte de configuration apparaît dans le TUI et le CLI, et vous pouvez connecter plusieurs comptes nommés d'une application (un compte work et un compte home) et les gérer avec /connectors ou hermes connectors. (#106842, #111008, #119074, #135143, #135072, #135097, #135151, #135173, #137426 — @alt-glitch, @rewbs)

  • Modèles locaux dans un seul click — Hermes peut désormais exécuter des modèles ouverts entièrement sur votre machine sans que rien ne la quitte : pas de compte, pas de clé API. Il installe et maintient llama.cpp avec le moteur adapté à votre matériel (CPU, CUDA, Metal, Vulkan ou ROCm), évalue chaque modèle de catalogue par rapport à votre GPU et à votre RAM et sélectionne la version de la plus haute qualité qui correspond. Les téléchargements s'interrompent et reprennent, le serveur démarre et s'arrête avec Hermes et les mises à jour du moteur sont un click. Commencez par Paramètres → Fournisseurs → Modèles locaux sous Windows, macOS et Linux, ou hermes model → Modèles locaux dans un terminal. Le catalogue comprend Qwen3.8 27B, Qwen3.8 Flash Next (avec sa tête spéculative MTP), Qwen3.6 35B-A3B et DeepSeek V4 Flash, ainsi que n'importe quel GGUF de Hugging Face. (#100667, #101823, #128768, #111423, #133111, #134116 — @jquesnelle, @ethernet8023)

  • Canaux de publication stables — Hermes livre désormais des versions testées de SemVer. Chaque version transmet les sources CI, Docker, Nix, les versions de bureau signées et les exécutions d'installation/mise à niveau sur chaque système d'exploitation avant d'être publiée, et les installations sources se déplacent désormais d'une version à l'autre par défaut au lieu de suivre chaque validation sur main. Vous préférez l'avant-garde ? hermes update --set-channel main, ou le nouveau commutateur de chaîne dans Desktop Paramètres → À propos. Le passage à une version plus ancienne est qualifié de restauration et ne se produit jamais sans demande, et les réexécutions du programme d'installation vous maintiennent sur le canal que vous avez choisi. (#102765, #135847, #135949, #136313, #137780 — @ethernet8023, @KoNit-K)

  • Packages de bureau signés, le Microsoft Store et un gestionnaire de packages — L'application de bureau est désormais un package scellé et signé qui contient ses propres Python et Node et se met à jour lui-même, donc le premier lancement ne crée rien. Windows obtient un MSIX signé (x64 et ARM64) via App Installer ou le Microsoft Store ; macOS obtient une version signée et notariée pour Apple Silicon. En dessous, un nouveau gestionnaire de packages unifié (hermes pm) possède chaque outil épinglé et vérifié par hachage et l'environnement Python : les mises à jour créent un nouvel environnement et ne changent qu'une fois la vérification réussie, de sorte qu'une mise à jour échouée ou supprimée ne peut plus vous laisser à moitié appliqué. (#102765, #132361, #132386, #120339, #122221 — @ethernet8023)

  • Le catalogue de plugins : 600 plugins examinés — Le catalogue de plugins a lancé ce cycle et est passé à 600 entrées, chacune épinglée sur un commit révisé et installable depuis Hermes Desktop ou le CLI. Parcourez par catégorie et classement par étoiles avec une page par plugin et par auteur ; les règles du catalogue empêchent les plugins répertoriés de corriger les composants internes d'Hermes ou d'expédier des binaires non analysables. Les fournisseurs de mémoire vivent désormais avec leurs créateurs (Honcho, Supermemory, Hindsight, Mem0, OpenViking, Holographic), tout comme Home Assistant, Spotify et Langfuse : les utilisateurs existants sont migrés automatiquement et l'installation par défaut est devenue plus simple. (#69446, #111415, #117808, #113381, #114732, #131267, #132476, #136436 — @itpartypattaya, @happy5318 et plus de 400 auteurs de plugins)

  • La vague de modèles Claude 5.5 et GPT-6 — Claude Fable 5.1, Opus 5.5, Sonnet 5.5 et Haiku 5.5, GPT-6 Astra, Sol et Luna plus GPT-6.1 Sol et Gemini 4 Argon peuvent être sélectionnés sur Nous Portal, OpenRouter et les itinéraires natifs lorsqu'ils sont proposés. Le raisonnement antérieur est désormais rejoué par défaut sur chaque fournisseur capable de le lire, à travers le CV, les branches et le compactage, afin que le long travail en plusieurs étapes garde le fil de la pensée. Et lorsqu'un fournisseur a une mauvaise heure, Hermes attend les 503/529/timeouts transitoires dans des cycles visibles et délimités au lieu de mettre fin à votre tour. (#100577, #119304, #126842, #134759, #128248, #137955, #136358, #116353 — @kshitijk4poor, @unsupportedpastels, @100yenadmin, @mssteuer, @xxxigm)

  • Connectez-vous aux sites Web avec votre gestionnaire de mots de passe — L'agent de navigateur peut se connecter à des sites avec des connexions provenant de 1Password, Bitwarden ou du propre coffre-fort crypté d'Hermes, et le modèle ne voit jamais le mot de passe. Si rien n'est enregistré, vous recevez une invite masquée dans le CLI, le TUI ou le bureau pour l'enregistrer, les codes à usage unique sont remplis sans entrer dans la conversation, et les remplissages de carte et d'adresse à la caisse nécessitent votre confirmation. (#106480, #107585, #137084)

  • Écran du bot : regardez votre bot travailler, prenez le relais quand il a besoin de vous – Un bot fonctionnant sur une passerelle Linux peut avoir son propre bureau qu'Hermes Desktop diffuse en direct. Lorsqu'il atteint une connexion, une invite 2FA ou un CAPTCHA, vous prenez l'écran, terminez l'étape vous-même et reprenez le contrôle pendant que le bot poursuit votre session. Avec un backend Docker, SSH ou Singularity, l'écran du bot, l'utilisation de l'ordinateur et le navigateur s'exécutent dans le bac à sable, jamais sur votre hôte. (#108914, #121169, #121110)

  • Un backend et une passerelle pour chaque profil — Hermes exécute désormais une seule passerelle de messagerie et un seul backend de bureau par machine qui dessert tous vos profils, au lieu d'un seul processus par profil. La création d'un profil permet à ses robots de vivre sans redémarrage, chaque profil conserve ses propres informations d'identification, listes autorisées, tâches cron et sessions, et hermes update migre automatiquement les configurations existantes par profil. Moins de processus, pas de conflits de jetons, une seule chose à démarrer et à arrêter. (#112854, #108928, #118273, #117983, #118246, #118027)

  • Voir et diriger vos sous-agents en direct — Les sous-agents en cours d'exécution restent désormais visibles au-dessus du compositeur dans le CLI (F6), l'interface utilisateur (Ctrl+T) et le bureau avec la tâche de chaque enfant, le temps écoulé et la transcription en direct, ainsi que les boutons Piloter et Arrêter. /stop atteint les enfants en arrière-plan et leur rend leur travail partiel, et delegate_task peut transmettre des captures d'écran et des simulations aux enfants capables de vision. (#105593, #115616, #97689)

  • Un sélecteur de modèles qui connaît vos projets — Mettez en vedette vos modèles préférés, voyez un abonnement qui devient faible ("17 % restants · réinitialisé à 15h00") et lorsqu'une limite de débit augmente directement dans le sélecteur, et choisissez l'effort de raisonnement dans le cadre du choix d'un modèle dans hermes model, /model (/model X --reasoning high) et Desktop. Vous changez avant de toucher le mur plutôt qu'après. (#126535, #133392, #133408, #110346, #113117 — @OutThisLife, @anotherchu)

  • Hermes dans votre langue, partout — Chaque chaîne destinée à l'utilisateur dans le CLI, la passerelle de messagerie, TUI et Desktop passe désormais par un seul catalogue de traduction avec une couverture complète dans les 16 langues regroupées. De nouvelles langues peuvent être livrées sous forme de plugins, et n'importe quel profil peut remplacer des chaînes individuelles par un petit fichier YAML. (#126296)

  • Plus léger dans tous les sens — L'ensemble de la base de code a été simplifiée sans aucun changement de comportement : la source est passée d'environ 1,06 M à 698 000 lignes (−34 %) et gateway/run.py est passé de 34 847 lignes à 5 512. Les invites sont également devenues plus légères : environ 19 outils rarement utilisés se chargent désormais uniquement lorsque l'agent les recherche, ce qui réduit de moitié environ le schéma de l'outil de bureau envoyé à chaque appel, et environ 2,1 000 jetons supplémentaires sont sortis de l'invite fixe. Les modèles locaux se préremplissent moins à chaque tour. (#102117, #97979, #106676, #137084 — @alt-glitch)

  • Petits conforts qui s'additionnent — Clés vim d'activation dans l'invite CLI, un champ de branche git dans la barre d'état, une cloche et une notification sur le bureau lorsque Hermes vous attend, Ctrl+C qui efface votre brouillon au lieu de tuer le tour, un /queue modifiable et hermes --native pour laisser votre propre terminal gérer le défilement et la recherche TUI. Sur le bureau, un nouveau mode Simple transforme l'application en une simple fenêtre de discussion, et les erreurs indiquent désormais ce qui n'a pas fonctionné avec un correctif one-click. (#106412, #106434, #101284, #101320, #137065, #95999, #121035, #118587, #111601 — @saforem2, @TurgutKural, @glitchbunny0, @harshmoney123, @pierrenode, @abhinav11082001-stack, @OutThisLife)

⚠️ Notes de mise à niveau

  • Python 3.14 est le moteur d'exécution pour les installations gérées (le gestionnaire de packages l'installe pour vous). KittenTTS n'est pas disponible sur 3.14. (#102765)
  • Le bureau Windows est uniquement MSIX et nécessite Windows 11 22H2 ou une version ultérieure ; les installateurs NSIS/MSI ont disparu. L'application macOS est Apple Silicon uniquement dans les versions par défaut. (#102765, #136603)
  • Une passerelle par machine est la valeur par défaut. hermes update intègre les passerelles par profil dans la valeur par défaut multiplexée lorsque rien n'est en conflit. (#112854)
  • Les discussions ne sont plus réinitialisées sur une minuterie inactive/quotidienne. Les modes inactif/quotidien du session_reset sont supprimés (les configurations qui les définissent toujours enregistrent un avertissement) ; /new ou /reset repart à zéro. (#105021, #126244)
  • Les anciennes sessions sont automatiquement élaguées. sessions.auto_prune est désormais activé par défaut : les sessions terminées et inactives pendant 90 jours sont supprimées au démarrage. Les sessions épinglées et ouvertes ne sont jamais touchées ; réglez sessions.auto_prune: false pour tout conserver.
  • Les fournisseurs de mémoire ont migré vers les plugins de catalogue (Honcho, Supermemory, Hindsight, Mem0, OpenViking, Holographic), tout comme Home Assistant, Spotify et Langfuse. Les utilisateurs existants sont migrés lors de la mise à jour ou du premier démarrage, avec les données intactes. ByteRover et RetainDB restent groupés.
  • Auteurs du plugin : l'ancienne couche d'importation de compatibilité du plugin a disparu (#126164), hermes sync (Skill Sync) a été supprimé (#132465) et le scanner tirith fourni a été supprimé (#133832). Plusieurs outils ont été renommés (todo → todo_list, cronjob → cronjob_manage, process → process_manage) ; les anciens noms fonctionnent toujours. (#97979)

Niveau gratuit Nous

  • Un modèle gratuit pour votre premier lancement de bureau — Une première installation de bureau sans fournisseur ni compte Nous obtient le modèle nous/welcome gratuit en tant qu'essai unique (une fois par utilisateur du système d'exploitation), donc l'intégration ne nécessite aucune clé.   • Connectez-vous et conservez vos applications — hermes auth upgrade, ou /login dans n'importe quel chat ou messagerie DM, met à niveau l'identité gratuite vers un compte Nous complet avec vos applications connectées. (#105259, #105261 — @alt-glitch)
  • Effacer les limites — La limite de taux libre termine le tour immédiatement avec le temps de réinitialisation ; chaque échec du niveau gratuit a un code et une phrase simple ; l'application gère la vérification du navigateur du service de compte ; les utilisateurs du niveau gratuit voient un avis de conditions et de confidentialité. Les comptes Nous sans crédits peuvent sélectionner des modèles facturés sur un abonnement qu'ils détiennent et bénéficier d'une recherche Web rapide et gérée gratuitement. (#134049, #111970, #133824, #117079 — @alt-glitch, @kshitijk4poor, @rewbs)

Connecteurs

Les outils de connecteur peuvent également envoyer vos fichiers locaux sous forme de pièces jointes et enregistrer les fichiers qu'ils renvoient. nous.guest: false désactive l'identité des invités ; Le tools.connectors.enabled: false désactive les connecteurs. (#111238, #138014 – @alt-glitch)
  • Un flux de connexion partout — Les applications hébergées et les serveurs MCP locaux partagent une seule carte de configuration (boîte de dialogue de bureau, légende TUI ou panneau CLI), et l'agent peut utiliser de nouveaux outils en même temps. Sur le bureau, manage_connections peut afficher un répertoire d'applications consultable. (#111008, #109517, #137426 — @alt-glitch)

📦 Versions stables, packages de bureau et gestionnaire de packages

Versions stables et canaux de mise à jour

  • Test des versions stables de SemVer et du changement de canal (voir Points forts). v0.21.6 et v0.21.7 ont été les premiers à franchir la nouvelle porte ; les forks restent sur main, et une installation avant la dernière version attend la suivante.
  • Contrôles de mise à jour plus légers — un appel GitHub API par jour remplace git fetch toutes les 30 minutes. (#107648)

Offres groupées de bureau et Microsoft Store

  • Packages de bureau scellés et signés (voir Points forts). Dans un package, hermes update pointe vers le bon programme de mise à jour (App Installer, Store ou macOS). (#134911)
  • Les installations packagées fonctionnent de bout en bout — le terminal de l'agent exécute hermes, la désinstallation explique la suppression du système d'exploitation et les plugins de dépendance Python s'installent dans MSIX. (#134051, #135333 — @alt-glitch)

Gestionnaire de packages unifié

  • hermes pm (voir Points forts) : Python épinglé et vérifié par hachage, 3.14, uv, Node, ripgrep, FFmpeg, Chromium et Git/Bash sous Windows, avec hermes pm doctor|status|repair|gc. Les contributeurs utilisent source ./activate (ou .ps1/.fish).
  • Les environnements de dépendance sont des générations — les nouveaux sont vérifiés avant utilisation, donc une installation échouée conserve celle qui fonctionne ; les mises à jour et hermes pm gc récupèrent les anciennes (92 Go à 18 Go sur un hôte). (#124968, #133808 — @JoaoMarcos44)
  • Fonctionnalités facultatives installées lors de la première utilisation — les SDK opt-in (Anthropic, Bedrock) se chargent en milieu de session sans redémarrage ; security.allow_lazy_installs: false désactive cette fonction. (#122221 — @ethernet8023)
  • Les plugins déclarent des dépendances Python — résolues avec le noyau dans tous les profils ; les conflits sont refusés, et les mises à jour désactivent un plugin qui ne rentre plus. Hindsight, Honcho, Supermemory, Mem0 et Home Assistant ont été déplacés vers le catalogue et installés automatiquement là où ils sont utilisés. (#113851, #122103, #114569, #132469 — @ethernet8023)

Installer et mettre à jour

  • Les mises à jour ne peuvent pas s'appliquer à moitié (voir Points forts). Une mise à jour tuée se répare au prochain lancement. (#132361, #120339)
  • Mises à jour plus rapides, extractions plus petites — les mises à jour reconstruisent uniquement ce qui a changé (16.5 contre 32.5 sur macOS), les clones sont sans tache et la croissance des clones partiels .git est corrigée. Docker / Nix / Termux / Windows

⏰ Cron, Kanban & Délégation

### Cron

  • Les tâches suivent votre modèle principal — Les tâches non épinglées utilisent le modèle configuré au moment du lancement ; pinned en verrouille un. (#113679)
  • Planifications d'auto-réparation — Un incendie qui n'a jamais atteint le modèle (par exemple après le réveil) se réexécute après 5, 15 et 30 minutes, une fenêtre du fournisseur « réessaye après » gare la tâche en silence et un emplacement manqué lors d'un redémarrage se déclenche une fois. (#108731, #115843)
  • Alertes plus silencieuses — Une alerte par incident plus un rappel tous les cron.failure_repeat_alert_hours ; failure_deliver redirige ou coupe les avis de panne ; un agent peut échouer son exécution avec [CRON_FAILURE]. (#114807, #101373, #113155) — @victor-kyriazakos
  • Nouvelles options de travail — --paused crée un travail sans arme ; --interpreter exécute des scripts sur votre propre venv. (#104984, #125392) — @M1racleShih
  • Profils et livraison — Une passerelle multiplexée exécute les tâches de chaque profil avec l'environnement et les secrets de ce profil ; la livraison a besoin de preuves positives, les résultats sont rédigés en secret partout et les diffusions tardives ou satellites sont étiquetées. (#118027, #100908, #112830) — @yoniebans

Kanban

  • Les travailleurs surmontent les problèmes du fournisseur — Les tours ayant échoué, réessayez en place avec le contexte ; limites de débit ou mise en file d'attente 5xx au lieu de tentatives de gravure. (#112318, #112500) — @EvgenyMettsler, @dmelkk-secondbrain
  • Un tableau qui s'explique tout seul — Les cartes montrent le dernier résultat du travailleur en cas d'échec ; La dépêche indique pourquoi une carte est retenue. (#112618) — @chelsealong
  • Workflow et outils — Une définition de workflow gère les colonnes ; les travailleurs reçoivent kanban_schedule ; kanban create --body-file ; Desktop suit les commutateurs de passerelle. (#134340, #130455, #116791, #119054) — @benbarclay, @unsupportedpastels, @fangliquanflq

  • Sous-agents en direct, images et /stop (voir Points forts). (#105593)
