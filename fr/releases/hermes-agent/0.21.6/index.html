#hermès-agent v0.21.6

Agent Hermès v0.21.6

Date de sortie : 8 octobre 2026

Sortie du correctif. Cette balise regroupe les environ 2 100 PR fusionnés depuis v0.21.5 dans une version stable étiquetée pour Docker et Hermes Cloud. Notes complètes pour cette fenêtre livrée avec v0.22.0.

<!-- HERMES_BUILDS_TABLE -->

À propos de cette version

Il s'agit de la première version supprimée par le nouveau pipeline de versions stables : une référence de tentative, une image Docker testée et une balise de réception lors de la publication. Il expédie le tag, cette version GitHub et l'image Docker. L'application de bureau, les packages Termux et le Microsoft Store restent pour le moment sur leur version actuelle et évoluent avec la prochaine version groupée.

Mesurée lors de la validation 818c13be1dc4fd28987e1e881a9408224afd4535, la fenêtre depuis v0.21.5 contient 8 867 validations sans fusion sur 8 342 fichiers modifiés (+772 490 / −225 600), 2 106 PR fusionnés et 3 027 problèmes fermés.

Egalement dans la fenêtre, volontairement non documentée ici : transcription en direct pendant que vous parlez sur CLI, TUI et Desktop (stt.streaming) ; la voix parlée est acheminée vers son propre modèle (auxiliary.voice_chat) avec le raisonnement désactivé par défaut ; plugins tiers exécutés dans un hôte de plugin par profil (plugins.isolation: host) et un Paramètres ▸ Accueil des plugins pour leurs pages de paramètres ; les modèles favoris et épinglés en haut du sélecteur de bureau, une puce d'utilisation avant qu'un abonnement n'atteigne son mur et des fournisseurs à débit limité qui indiquent pourquoi et jusqu'à quand ; modèles locaux dans hermes model plus llama.cpp CUDA sous Linux x64 et arm64 ; des modules linguistiques enfichables et superposés sur Core, Desktop et TUI ; un premier résumé hermes status (--short, --full) ; un sélecteur de portée de comparaison dans le volet de révision (Non engagé/Branche/Dernier tour) et une fonction de maintien qui suit le tour ; cron, doctor et avertissements du canal domestique lorsque le magasin cron devient illisible ; indicateurs d'approbation pour les téléchargements d'informations d'identification et Unicode invisible dans les commandes du terminal ; une configuration Discord qui vérifie le jeton du bot et imprime le lien d'invitation ; une définition de workflow Kanban unifiée ; activate.fish; GPT-6.1 Sol et Claude Sonnet 5.5 / Haiku 5.5 dans les catalogues ; et des dizaines de nouveaux plugins communautaires.

Les release note entièrement sélectionnés pour cette fenêtre sont livrés avec v0.22.0, qui documentera tout à partir de v0.21.0 : les points forts, les zones de fonctionnalités et les crédits complets des contributeurs. Rien dans cette fenêtre n'est ignoré.

Mise à jour

  • Docker / Hermès Cloud : nousresearch/hermes-agent:stable (ou :latest).
  • CLI (installations git) : hermes update, ou réexécutez le programme d'installation en une seule ligne.
  • Application de bureau et Termux : aucun changement dans cette version ; ils sont mis à jour avec la prochaine version groupée.

Correctifs de sécurité

Renforcement de l'authentification du tableau de bord

  • Les en-têtes X-Forwarded-For usurpés pourraient réinitialiser la limite de taux de connexion par mot de passe et contourner le plafond par IP lors de la connexion native (#133367)
  • Les demandes de connexion non authentifiées pouvaient écrire des valeurs illimitées dans le journal d'audit d'authentification (#133369)
  • Les routes publiques /auth/ n'avaient pas de limite de taille de corps de requête (#133370)
  • La connexion native pouvait envoyer des codes de connexion vers une redirection sans bouclage, ce qui permettait la reprise de session (#130685)

Merci à Tenable Research d'avoir signalé les quatre problèmes (TRA-725, TRA-726, TRA-727, TRA-728). Le problème de redirection de connexion native a également été signalé indépendamment et résolu par @Froraut. Le correctif X-Forwarded-For s'appuie sur le travail communautaire de @hinotoi-agent et @BearHuddleston (#40285).

** Renforcement du filtre git du référentiel **

  • Les appels Git automatiques (instantané de l'espace de travail de session, arbres de travail de sous-agent, kanban, nettoyage de l'arbre de travail, hermes -w) pouvaient exécuter des programmes de filtrage clean/smudge/process définis par la propre configuration d'un référentiel untrusted, avant la première invite (#130661).

Merci à 燕涛 d'avoir signalé cela en privé. Cela a également été signalé et corrigé publiquement par @jonpol01 (#126017, #126019) et @JoaoMarcos44 (#126075).

Renforcement des expéditeurs de la passerelle de messagerie

  • Un nom d'affichage cité dans l'en-tête From (par exemple "Victim <victim@example.com>" <attacker@evil.test>) pourrait faire en sorte que le message d'un attaquant passe la liste blanche des e-mails en tant qu'expéditeur autorisé (#125212)

Merci à Daniel Steele (@keeltrace) d'avoir signalé ce problème et écrit le correctif (#124322).
