#hermès-agent v0.23.0

Agent Hermès v0.23.0

Date de sortie : 5 novembre 2026 Depuis v0.22.0 : ~10 080 commits · ~1 950 PR fusionnés · ~8 720 fichiers modifiés · ~725 200 insertions · ~201 400 suppressions · ~850 problèmes résolus · 666 contributeurs

The Hearth Release. Dans les anciens hymnes, Hermès gardait le seuil et Hestia gardait le foyer, et les deux étaient honorés côte à côte. v0.22.0 a fait franchir la porte aux nouveaux arrivants ; v0.23.0 construit le feu autour duquel ils se rassemblent. Le titre : l'ensemble de votre espace de travail Desktop s'ouvre désormais dans un onglet de navigateur, servi par votre propre passerelle. En dessous, chaque conversation réside au même endroit : une seule passerelle possède chaque session, et le CLI, le TUI, le bureau, les éditeurs, les robots et le cron sont tous assis à la même table au lieu de chacun exécuter son propre agent. À partir de ce foyer, Desktop maintient toutes les machines sur lesquelles vous exécutez Hermes connectées en même temps, les discussions de groupe acheminent leurs propres conversations et le terminal dessine enfin vos images en ligne et vous permet de rembobiner une conversation. Autour de cela : des plugins qui se tiennent à jour, des étiquettes de prix et des limites de dépenses pour les outils MCP payants, une délégation enfichable, un catalogue de plugins qui est passé d'environ 600 à plus de 1 050 entrées, un ensemble de compétences intégrées plus légères et un long travail de mémoire et de latence pour les passerelles de longue durée. Cette version regroupe et documente entièrement les versions de correctifs v0.22.1 – v0.22.7.

✨ Points forts

  • Votre espace de travail de bureau dans un onglet de navigateur — La nouvelle application Web dessert l'intégralité de l'espace de travail de bureau à partir de votre propre passerelle : les mêmes discussions, discussions de groupe, plugins et paramètres, dans n'importe quel navigateur de votre réseau ou derrière une URL publique avec connexion. L'image Docker et le package Nix l'expédient. Il est désactivé par défaut ; allumez-le avec webapp.enabled ou Web Access dans Paramètres. (#141864, #145598, #145536, #145072, #145153 — @jquesnelle, @BearHuddleston, @IAvecilla, @Adolanium)

  • Une passerelle possède chaque conversation — Avant, le CLI, le TUI, le bureau, les éditeurs (ACP), les robots de messagerie et le cron pouvaient chacun exécuter leur propre copie de l'agent sur le même chat, c'est ainsi que les messages étaient écrits deux fois ou disparaissaient entre les surfaces. Désormais, chaque machine exécute une passerelle qui possède chaque session, et chaque surface s'y attache en tant que client : une discussion que vous ouvrez n'importe où est la même discussion, avec une file d'attente et un historique. Vous pouvez même diriger ou modifier une invite en file d’attente depuis le bureau sans qu’elle ne s’exécute deux fois. (#106742, #140334 — @unsupportedpastels, @kshitijk4poor)

  • Images dans le terminal — Lorsque vous collez une image ou qu'un outil prend une capture d'écran, le CLI et TUI la dessinent désormais directement dans le chat au lieu d'imprimer un chemin de fichier : de vrais pixels dans Kitty et Ghostty (CLI et TUI) et dans iTerm2, WezTerm et Konsole (CLI), des blocs de couleur partout ailleurs et une pleine résolution dans le terminal de VS Code lorsque sa prise en charge d'image est activée. (#147293, #148874 – @Adolanium)

  • Rembobiner une conversation — Appuyez deux fois sur Échap ou tapez /rewind dans le TUI ou CLI classique, choisissez un message précédent, puis modifiez-le et renvoyez-le ou créez une nouvelle session à partir de ce point. La session originale reste exactement telle qu'elle était. Le TUI peut également démarrer /new alors qu'un tour est encore en cours ; l'ancien continue de fonctionner en arrière-plan. (#144937, #148880 — @SaguaroDev)

  • Chaque machine dans une fenêtre de bureau : Desktop maintient désormais toutes vos passerelles connectées en même temps, ce qui permet de basculer instantanément entre cet ordinateur et une passerelle SSH ou distante. Les onglets du terminal s'exécutent sur l'hôte sur lequel ils ont été ouverts, et une discussion de groupe peut mélanger des robots de différentes machines. (#147681, #147708, #148418 — @dskwe, @janviernine)

  • Chats de groupe qui s'exécutent automatiquement — Les salles en mode Bot peuvent permettre à un robot principal ou à un routeur automatique de choisir qui répond à un message qui ne nomme personne. Les tâches planifiées peuvent être publiées dans une salle, les salles conservent un objectif et des notes partagées, et les robots ne se cinglent plus en boucles sans fin. Les salles ressemblent également désormais à un chat Hermès normal, et chaque robot montre ce qu'il fait en direct ("scout · terminal · 7s"). (#144833, #148417, #148888, #148903, #148422 — @KoNit-K)

  • Plugins qui se tiennent à jour — hermes plugins update met tout à jour en même temps, et un commutateur de mise à jour automatique opt-in (CLI, chat, bureau et tableau de bord) maintient le catalogue et les plugins git à jour. Les mises à jour qui pourraient interrompre votre configuration sont retenues au lieu d'être appliquées. Le catalogue lui-même est passé d'environ 600 à plus de 1 050 entrées, et un nouveau niveau vérifié marque les plugins construits par le fournisseur lui-même. (#141513, #85794, #143468, #144257 — @charan-rathore, @YS-OH-CORE)

- Étiquettes de prix et limites de dépenses pour les outils payants – Les outils MCP payants, tels que la génération 3D ou multimédia, peuvent déclarer le coût d'un appel. L'invite d'approbation indique le prix de chaque appel et le total cumulé du chat, et Hermes demande avant qu'un chat ne dépasse sa limite, même en mode YOLO. (#142470, #143780, #143795, #143787 — @liuhao1024, @fangliquanflq)

  • Nouveaux plugins officiels et un noyau plus petit — Meshy (texte et image en 3D), ElevenLabs Music and Sound Effects, X Chat, REA (ingénierie inverse) et un bac à sable bubblewrap sont désormais des installations en une seule commande. Camofox, mcp-serve, les importateurs d'agents et Singularity sont passés du noyau à des plugins qui s'installent automatiquement pour tous ceux qui les utilisent. (#142619, #146294, #139725, #143484, #139983)

  • Choisissez comment les sous-agents sont exécutés — La délégation est désormais connectable : conservez la valeur par défaut ou installez le plugin officiel advanced-delegation pour envoyer chaque tâche de sous-agent à un modèle nommé ou dans un profil distinct. Commutez avec /delegation. (#142563, #142564, #143423)

  • Plus léger et plus rapide, en particulier lorsque Hermes s'exécute toute la journée — Les tâches cron récurrentes partagent un cache d'invites, les exécutions ponctuelles envoient environ 1 570 jetons d'invite de moins par appel et patch/write_file reviennent en millisecondes avec LSP activé. Les passerelles de longue durée abandonnent désormais la mémoire des sessions fermées et la barre latérale du bureau ne ralentit plus à mesure que les sessions s'accumulent (un magasin avec environ 35 000 exécutions cron est passé d'une actualisation de 121 s à une actualisation instantanée). (#139876, #144177, #140387, #147863, #137087, #147819, #144940 — @kshitijk4poor)

  • Un ensemble de compétences plus simples que vous pouvez verrouiller — Les compétences intégrées sont passées de 58 à 44, avec Word, PowerPoint et Excel fusionnés en une seule compétence microsoft-office. hermes curator lock empêche l'agent de réécrire une compétence que vous avez sélectionnée manuellement, via n'importe quel outil, même en mode YOLO. (#147557 — @daviseford)

  • Gestionnaires de mots de passe et clé de coffre-fort de trousseau — Les plugins de gestion de mots de passe vérifiés peuvent transmettre au navigateur vos identifiants sans voir ceux de quelqu'un d'autre, et la clé du coffre-fort du navigateur peut désormais résider dans le trousseau de votre système d'exploitation. (#143964, #144246 — @Jesssullivan)

  • Arrêter une tâche cron en cours — Annulez une tâche en cours d'exécution depuis le CLI, le bureau, le API ou l'agent lui-même, et définissez par tâche ce qu'il advient des exécutions manquées pendant qu'Hermes était éteint. (#144801 — @kokhlo, @fangliquanflq, @LeonSGP43)

⚠️ Notes de mise à niveau

  • Les anciens outils de navigateur intégrés ont disparu. L'automatisation du navigateur fonctionne uniquement sur browser_exec ; agent-browser et les dix outils browser_* (browser_navigate, browser_click, ...) ont été supprimés. Les maisons qui ont utilisé Camofox obtiennent automatiquement le plugin camofox. Si vos propres invites, compétences ou listes d'outils nomment les anciens outils, remplacez-les par browser_exec. (#143146)
  • Le bureau nécessite macOS 13+ et Windows 64 bits. L'application a été déplacée vers Electron 44, qui ne fonctionne plus sur macOS 11, macOS 12 ou Windows 32 bits. (#142727 — @OutThisLife, @Adihaliem)
  • hermes mcp serve est maintenant hermes mcp-serve (il est devenu un plugin). Les MCP clients qui lancent Hermes en tant que serveur doivent mettre à jour leur commande ; rien ne le réécrit pour vous.
  • Les compétences Word, PowerPoint et Excel constituent désormais une compétence microsoft-office. Les anciennes copies restent sur le disque jusqu'à ce que vous les supprimiez.
  • L'application Web est désactivée par défaut. Rien n'est envoyé à un navigateur tant que vous n'avez pas activé webapp.enabled ou Web Access.

Boucle et sessions d'agent

  • Réduction des coûts de jeton d'invite et de cache — Chaque lancement de la même tâche cron partage désormais une clé de cache d'invite. Les appels ponctuels en arrière-plan (résumés, titres, /moa) ne paient plus pour les écritures en cache. Les exécutions ponctuelles envoient 1 570 jetons d’invite de moins par appel, et quatre schémas d’outils sont plus courts de 319 jetons. Les tours d’objectif et de battement de cœur de la passerelle, les tours après compactage et les actualisations MCP entre tours ne réécrivent plus le préfixe mis en cache. (#139876, #140478, #144177, #144173, #139865, #139851 — @100yenadmin, @jonpol01, @chelsealong, @AdrianBinDC)
  • Compactage préparé par opt-in — Avec compression.prepare_ahead: true, le résumé suivant est écrit en arrière-plan lorsqu'une session approche du déclencheur, de sorte que le compactage ne met plus le tour en pause pendant l'écriture du résumé. Les messages qui arrivent entre-temps restent mot pour mot dans la queue. Désactivé par défaut. (#144684, #144886 — @kshitijk4poor)
  • Le compactage est plus honnête et plus difficile à bloquer — Les résumés répertorient les réclamations incertaines sur les lignes UNVERIFIED:, donc une supposition ne revient pas comme un fait. La solution de secours du modèle principal utilise la route principale, /stop ferme un flux récapitulatif et les messages en file d'attente et /steer survivent à une réinitialisation d'épuisement du contexte. (#86019, #139872, #144825, #139783, #139923 — @helix4u, @thehugegatsby)
  • hermes sessions refresh-prompts — Les sessions continues récupèrent un SOUL.md modifié, des compétences ou des fichiers contextuels lors de leur prochain tour sans /new. L'historique est conservé et chaque session nécessite un échec de cache. (#143581 — @victor-kyriazakos)
  • Plafond de durée de vie du flux opt-in — agent.stream_max_lifetime (désactivé par défaut) coupe un flux qui ne se termine jamais. Les erreurs de délai d'attente nomment désormais la phase qui a échoué et le paramètre à augmenter. (#80701, #80873 — @krzsda)
  • Les questions de suivi sur une photo voient toujours la photo — Cela s'applique après la poursuite de la session du serveur --resume, API et le redémarrage de la passerelle. (#139873 — @Alexbob0)
  • Stockage de session — L'élagage automatique est à nouveau activé et Hermes demande une fois lorsque le disque est faible. hermes sessions optimize-storage montre les progrès et termine un vrai magasin environ 18 fois plus rapidement. Le démarrage n'attend plus l'élagage de zéro et les échecs de hermes sessions quittent 1. (#139762, #144630, #144625, #144767)

Plateformes de messagerie (passerelle)

  • Une passerelle possède désormais chaque session locale — Depuis v0.22.0, les classiques CLI, TUI, Desktop, API, les éditeurs ACP, les robots et cron exécutent tous leurs sessions via une seule passerelle. Ce cycle a corrigé ce qui cassait : les commandes slash, /retry, /refine, /review, les cartes de clarification, l'affichage du raisonnement, l'utilisation et les sessions ACP fonctionnent à nouveau, et les modifications de configuration atteignent la reprise des sessions. (#139149, #139577, #139884, #140249, #140595, #141916, #144005, #138719 — @unsupportedpastels, @yoniebans, @drzxk, @fangliquanflq)
  • Mémoire et réactivité de la passerelle — Le gel d'environ une fois par minute pendant les réductions de mémoire a disparu, les sessions fermées quittent la mémoire, les arènes malloc glibc sont limitées à 4 et les bloqueurs de boucles d'événements mesurés sont retirés de la boucle. (#147840, #147831, #147810, #144911, #137156 — @kouyichi, @ygd58, @zwmaupin, @kshitijk4poor)
  • Cycle de vie de la passerelle plus sûr — hermes gateway stop/restart refuse pendant que les sessions sont en direct et n'agit jamais sur le service d'une autre maison. Une passerelle démarrée à partir du terminal d'un agent ne se prend plus pour le service launchd, et lorsque chaque plateforme échoue au démarrage, la passerelle reste dégradée. (#142041, #145930, #144592, #140922 — @salch-cred)
  • ** Discussions de groupe en mode bot ** — Les tâches Cron peuvent être publiées dans une salle (deliver: room:<id>@<profile>), réveillant uniquement les robots qu'ils @mentionnent. Les salles ont un objectif et des notes partagées, et deux modes d'inscription choisissent qui répond à un message qui ne nomme personne (un robot principal ou un routage auto). message_agent réveille le demandeur une fois à chaque réponse. (#144833, #148417, #148888, #144789 — @rorsch, @OutThisLife)
  • Fin des boucles de robot à robot — Les robots ne reçoivent jamais de notifications d'exécution et un échange est limité à max_hops (4 par défaut) après le dernier message humain. hermes peer dm <peer>/hermes atteint le bot par défaut du homologue. (#148903, #144900 — @KoNit-K)
  • Telegram — Le nouvel opt-in dm_topic_auto_transfer ouvre un nouveau sujet pour les messages root-DM. Le premier message d'un nouveau sujet y arrive, les notes vidéo parviennent à l'agent et les messages de groupe non adressés au bot peuvent rester silencieux. (#141347, #141751, #147572, #147144 — @KoNit-K, @PRELVAS94, @sharpnotebot, @Horizont367, @diegoasanch)
  • Slack, Feishu, Discord — Le contexte du fil de discussion Slack inclut les réactions emoji et un nouvel opt-in thread_followup_silence couvre les réponses du fil de discussion non adressées. Feishu obtient des cartes de clarification et un sélecteur de choix sur lequel vous appuyez. Discord respecte les délais d'attente d'approbation plus longs et envoie de l'audio brut en pièce jointe. Les chambres peuvent opter pour un silence intentionnel. (#80882, #139586, #82170, #145948, #143800, #147143 — @hackartists, @helix4u, @liuhao1024, @nicodoggie)
  • Chaque adaptateur de messagerie est désormais un plugin — Signal, Weixin, BlueBubbles, QQ Bot, Yuanbao et WhatsApp Cloud sont désormais livrés sous forme de plugins de plateforme groupés. Rien ne change pour les utilisateurs. (#139843, #140168 — @karljohannisson, @sprmn24)
  • Les réponses diffusées en continu fournissent des images — Les images Markdown dans une réponse diffusée en continu arrivent sous forme d'images et les arguments de progression de l'outil sont affichés dans des blocs de code. (#144041, #139759 — @686f6c61, @sambouli)

Outils, navigateur et terminal

  • patch et write_file reviennent en millisecondes avec LSP activé — Une édition propre de TypeScript est passée des 10.1 à environ 0.06. Les erreurs de type atteignent toujours le modèle. (#140387)
  • Processus d'arrière-plan plus intelligents — Une commande se terminant par un seul & s'exécute comme un processus d'arrière-plan suivi au lieu d'être refusée. Au lieu d'interroger un processus silencieux, l'agent est averti lorsqu'il se termine. Les tâches qui se terminent pendant un tour chargé reviennent en un seul tour. (#140317, #140330, #147678 — @lucasfdale, @suhanrain)
  • Gestionnaires de mots de passe dans browser_vault — Les plugins de catalogue groupés ou vérifiés/officiels peuvent ajouter leurs propres identifiants via ctx.register_login_backend, et chacun ne peut toucher que ses propres entrées. La clé du coffre-fort peut être déplacée vers le trousseau du système d'exploitation (opt-in vault.key_storage: keychain). Les mots de passe enregistrés sont remplis sur les pages Camofox. (#143964, #144246, #146240, #139203 — @Jesssullivan, @WillPlatnick)
  • Génération de médias — Génération et édition d'images Krea 3 via la passerelle Nous ou le Krea API, et le modèle d'image par défaut pour les abonnés payants qui n'en ont pas choisi. Vidéo Wan 2.7 sur FAL. L'agent peut rechercher et sélectionner les voix ElevenLabs dans text_to_speech. (#142155, #87464, #144633 — @entropidelic)
  • Backends de terminal — Les backends de sandboxing peuvent définir uses_host_filesystem = False afin que les outils de fichiers s'exécutent à l'intérieur du sandbox, et les backends de plugins peuvent définir leur répertoire de démarrage. Singularity a migré vers son plugin. Le résultat de la commande ne disparaît plus une fois qu'un processus comporte plus de 1 024 descripteurs de fichiers ouverts. (#143756, #142225, #142561, #142299 — @unsupportedpastels, @aholten, @MohamadKanso)
  • Fiabilité du navigateur : le paramètre de profil réel continue de fonctionner lorsque Chrome verrouille le profil. Les données de page imbriquées ne font plus planter les outils et les captures d'écran des onglets masqués ne se bloquent plus. (#139245, #140562, #146082 — @cmaldonado80)

Cron, Délégation & Multi-Agent

  • Backends de délégation enfichables — delegation.backend choisit comment chaque tâche delegate_task devient une exécution enfant, et la stratégie par défaut est désormais un plugin fourni. Le plugin officiel advanced-delegation ajoute une carte de modèle et un routage par profil. /delegation <mode> enregistre pour la session suivante et --now l'applique immédiatement. Un delegation.prefix_stagger_seconds opt-in permet aux sous-agents par lots de réutiliser le cache d'invites. (#142563, #142564, #143423, #86553)
  • Arrêtez une tâche cron en cours — hermes cron cancel, un bouton d'arrêt du bureau, les API et cronjob_manage arrêtent une exécution en direct et la suppression d'une tâche l'annule. Chaque tâche sélectionne sa propre politique d'exécution manquée (--catch-up on|off). Une exécution manuelle ne consomme plus un seul coup et les invites indiquent le temps de tir. (#144801, #146113, #82826 — @kokhlo, @fangliquanflq, @LeonSGP43)
  • Les sous-agents d'arrière-plan survivent et font rapport — Arrêter un tour ne tue plus les sous-agents d'arrière-plan comme /review. /bg et les discussions acheminées attendent leurs délégations, et les finalisations perdues sont à nouveau proposées à partir du grand livre. (#144759, #147745, #147753, #147748 — @professorpalmer, @nateEc, @rungmc357)
  • Les travailleurs Kanban sont à nouveau utilisables — delegate_task et session_search fonctionnent à l'intérieur des cartes, les tentatives mortes libèrent leur emplacement, un travailleur dont le socket tombe reprend la même tentative et les tours des travailleurs ne sont plus enregistrés dans vos souvenirs. (#141944, #141906, #145954, #144861 — @tmaarcxs, @nonkun12, @calvinnwq)

Sécurité et fiabilité

  • Davantage de formes secrètes sont masquées — Les secrets cités, les chaînes de connexion, les secrets collés et passés par un indicateur, les clés Azure, les clés privées non PEM et les mots de passe SMB sont désormais masqués et les pages JSON ne sont plus mutilées. (#149435, #148862, #149470 — @r266-tech, @liuhao1024, @mtp-44, @arbianshkodra, @Baophan00)
  • La porte d'approbation en capture plus — La porte demande désormais des tuyaux curl … | sudo bash, des suppressions PowerShell ultérieures ou abrégées et des téléchargements d'informations d'identification cachés derrière une règle approuvée. Une carte d'approbation périmée ne peut plus approuver la demande suivante. (#87362, #148865, #141377, #87554 — @Baophan00, @liuhao1024, @VaughnValle)
  • ** Limites du réseau ** — Les URL dont l'hôte analyse différemment les clients sont refusées, et sans jeton, A2A refuse les requêtes des navigateurs et des en-têtes Host étrangers. (#145578, #145310 — @unsupportedpastels)
  • Consentement Shell-hook — Une passerelle sans surveillance ignore un hook non approuvé au lieu de se bloquer. Un consentement enregistré prend effet dans un délai d'environ 30 secondes. (#140984, #141034 — @arcabotai, @WYSTAF, @liuhao1024)

🖥️ Bureau, application Web, CLI et installation

Application de bureau

  • Chaque passerelle enregistrée reste connectée — La commutation entre cet appareil, un hôte SSH ou une passerelle URL est désormais instantanée, sans boîte de dialogue de confirmation ni liste de sessions vide. Les sessions de chaque passerelle restent visibles dans la barre latérale et les épingles restent associées à la passerelle qui les possède. Une passerelle SSH exécute un backend distant pour tous ses profils, de sorte que chaque profil SSH est répertorié au lancement et que la commutation prend bien moins d'une seconde. (#147681, #147735, #147741, #147957, #147711 — @dskwe, @Bridgerz, @kenpritchard, @kshitijk4poor)
  • Les onglets de terminal appartiennent à leur hôte — Chaque onglet de terminal intégré à l'application s'exécute sur la passerelle sur laquelle il a été ouvert et affiche cet hôte dans son étiquette. "Nouveau terminal sur…" ouvre un shell sur cet appareil ou sur n'importe quelle passerelle SSH, côte à côte. Desktop peut également se connecter aux hôtes Windows SSH. (#147708, #143898 — @janviernine, @addelh, @yoniebans)
  • Les discussions de groupe ont grandi — Les discussions de groupe peuvent désormais être renommées et dissoutes et prennent en charge les @mentions, le collage de pièces jointes, le glisser-déposer et les aperçus d'images en ligne. Les salles peuvent à nouveau accueillir des robots de différentes machines et montrer quel robot fonctionne. Desktop et Webapp partagent une liste de salles. (#143607, #148418, #142904, #145629, #141928, #145973 — @unsupportedpastels, @HootRock, @Thrymheim, @Ehsan-hash)
  • Paramètres de délégation dans l'application — Paramètres → Modèle → Sous-agents utilise désormais les listes déroulantes des fournisseurs et des modèles au lieu des zones de texte libre. Une nouvelle section Routage sélectionne le mode de délégation (par défaut, routes de modèle, routes de profil ou backend de plugin) et modifie les routes en place. (#141312, #143126 — @abundantbeing, @e-macgregor, @SecBySagar)
  • Catalogue de capacités repensé — Les compétences et les plugins sont parcourus sous forme d'étagères de cartes classées par niveau (Officiel, Vérifié, Communauté). L'installation est désormais un bouton + à sens unique : les entrées installées reçoivent un interrupteur marche/arrêt et la désinstallation passe à la vue détaillée. (#138820, #142708 — @austinpickett)
  • Plugin SDK : accès aux fichiers et badges Kanban — Le nouveau ctx.files permet à un plugin Desktop de lire et d'écrire son propre dossier de données et tout dossier que vous accordez via le sélecteur de l'application, et rien d'autre. Un emplacement pour badge de carte Kanban permet aux plugins d'étiqueter les cartes sans toucher au balisage du tableau. (#143688, #143673)
  • Erreurs et questions plus claires — Les tours échoués affichent une carte d'erreur repensée qui marque l'échec comme bloquant ou dégradé et propose une action (Continuer, Ouvrir les paramètres du fournisseur, Guide de configuration…). Il affiche la véritable exception au lieu de « Quelque chose s'est mal passé ». Un clarify avec plusieurs questions est désormais un formulaire avec une seule soumission. (#146776, #146803, #144392, #146881 — @kshitijk4poor)
  • Commodités du workflow — Vous pouvez faire glisser des sessions pour les épingler ou les désépingler, épingler des tableaux Kanban en tant qu'onglets à changement rapide, ouvrir Bot Chats dans de nouveaux onglets et compacter une conversation à partir du panneau contextuel. /loop affiche un compte à rebours en direct et /usage affiche les limites du fournisseur avant le premier message. (#142672, #148179, #143129, #148871, #139187, #141047 — @austinpickett, @unsupportedpastels, @kvarnelis, @jerrygooch, @aydnOktay)
  • Le consentement MCP montre ce qui va s'exécuter — La carte d'installation/activation/autorisation MCP affiche désormais la commande ou l'URL exacte que chaque serveur exécutera ou contactera, avec des secrets masqués. Les invites d'approbation sur chaque surface révèlent désormais l'Unicode caché, les octets de contrôle et le remplissage. (#85775, #81403)
  • Plus rapide sur les longues discussions — La saisie ne ralentit plus lors du chargement de l'historique ; les sessions pleines de modifications de fichiers changent sans remettre en surbrillance chaque différence. Les diagrammes de sirène sont rendus via Pele, un moteur de rendu beaucoup plus petit, au lieu de mermaid.js. Les fenêtres réduites et inactives effectuent moins de travail de streaming. (#144903, #144991, #147974, #146602, #146600 — @kshitijk4poor, @ghgoodreau)
  • Messages et réponses que vous pouvez trust — Un message envoyé juste avant la fermeture de la fenêtre n'est plus perdu et les brouillons survivent aux sauts d'horloge et aux rétrogradations. Les réponses sont tirées une fois lors des reconnexions, des rechargements et des tours arrêtés. Les connexions saines ne sont plus interrompues lors de la mise au point ou du réveil. Les anciennes discussions sur les applications téléphoniques peuvent être poursuivies au lieu de s'ouvrir en lecture seule. (#145018, #145528, #144899, #146843, #147802)
  • Les packs de langues s'appliquent réellement — Le coréen et d'autres langues uniquement disponibles dans les packs se chargent désormais sur une passerelle froide, et le sélecteur masque les langues que l'application ne peut pas afficher. (#147515 — @kshitijk4poor)

Webapp et Hermès Cloud

  • La Webapp : Bureau dans un onglet de navigateur, servi par votre passerelle — Avec webapp.enabled: true, la passerelle dessert l'espace de travail Desktop sur son propre écouteur. hermes webapp l'ouvre et Paramètres du Bureau → Accès Web le diffuse sur votre réseau ou sur une URL publique derrière la connexion. Il est désactivé par défaut. L'application Web est mono-utilisateur : un onglet de connexion agit comme vous, de sorte que ses sessions et discussions de groupe sont les mêmes que celles affichées sur le bureau natif, et les paramètres d'affichage vous suivent sur tous les appareils sur la même machine. (#141864, #145598, #145536, #148408 — @jquesnelle, @BearHuddleston, @IAvecilla)
  • Plugins de bureau dans le navigateur — Les plugins de bureau installés se chargent dans un onglet Webapp, et les plugins de bureau uniquement peuvent être installés à partir de l'onglet, épinglés au commit affiché dans la boîte de dialogue. (#145072, #145853, #146178 — @Adolanium, @DECRUX9812)
  • Peaufinage du téléphone et du navigateur — Lorsqu'une discussion a besoin de vous, le titre de l'onglet clignote et le favicon reçoit un point. Les notifications du navigateur opt-in ouvrent le bon chat. Un seul clic concentre le compositeur sur l'iPhone et le sélecteur d'onglets du téléphone atteint le menu de chaque onglet. Les fichiers et les médias sont résolus dans le bac à sable Docker ou l'espace de travail SSH d'une session. (#146882, #145569, #145788, #144741 — @Sn0wfly, @unsupportedpastels)
  • Renforcement de l'application Web — Les liens de lancement sont privés pour l'utilisateur connecté et la page envoie une politique de sécurité du contenu ; un /api/status déconnecté ne révèle aucun nom de profil. La Webapp, le tableau de bord et le hermes serve trust disposent uniquement de leur propre port de bouclage lié pour CORS et WebSockets. (#144721, #145573, #145931, #146636 — @unsupportedpastels, @dokterdok, @Froraut)
  • Les agents Hermes Cloud cessent de proposer des mises à jour dans l'application — Desktop et l'application Web n'affichent plus « Mettre à jour maintenant » pour un agent que seul le Cloud peut mettre à jour. (#149436)

CLI & TUI

  • Une passerelle possède chaque session locale — Les classiques CLI, TUI, Desktop, serveur API, ACP, robots et cron s'attachent désormais à la passerelle unique de chaque profil au lieu d'exécuter leurs propres agents sur la même base de données. Un chat est une conversation avec une file d'attente et un rédacteur. Les suivis acheminent les commandes classiques CLI (/model, /cron, /queue, /save, /snapshot, /resume, todos) à travers celui-ci. (#106742, #138717, #141105, #141501, #141962, #140676 — @unsupportedpastels, @kshitijk4poor, @kassdinzheng123)
  • Retourner à une invite précédente — Dans le TUI et le CLI classique, /rewind (ou Esc Esc sur une invite vide) répertorie vos messages précédents. Vous pouvez en modifier un et le renvoyer, ou créer une nouvelle session juste avant. Les invites d'approbation obtiennent "Non, et dites à Hermès quoi faire à la place". (#144937 — @SaguaroDev)
  • TUI : /new à mi-tour et pâtes extensibles — /new pendant qu'Hermès est occupé ouvre une nouvelle session et maintient celle en cours d'exécution en arrière-plan (Ctrl+X revient en arrière). Ctrl+P développe un collage réduit afin que vous puissiez le lire ou le modifier. (#148880, #148883)
  • Nouvelle mise en page classique du CLI — Le classique CLI imprime désormais une transcription qui survit aux redimensionnements du terminal, avec un glyphe par ligne et la ligne d'état sous le compositeur. display.cli_layout: classic restaure l'ancien look. (#139241, #141879)
  • Noyau plus petit, importations de configuration — hermes mcp serve passe au plugin officiel mcp-serve (hermes mcp-serve). hermes import-agent et la migration OpenClaw migrent vers le plugin agent-importateurs. Pour la première fois, hermes setup propose désormais d'importer depuis OpenClaw, Claude Code, Codex CLI ou Cursor lorsqu'il en trouve un. (#142556, #142547)
  • hermes --cpu-profile PATH — Écrit un profil CPU de n'importe quelle exécution d'Hermes, ainsi qu'un résumé textuel des principales fonctions. (#87545)

Installation, mise à jour et packaging

  • Les nouvelles installations démarrent sur stable — install.sh, install.ps1 et Hermes-Setup consultent désormais la dernière version stable au lieu de la pointe de main. (#139311)
  • Les mises à jour du bureau sont plus rapides et en disent plus — Une mise à jour ignore la reconstruction du bureau lorsqu'aucune entrée du bureau n'est modifiée et la fenêtre de mise à jour nomme son étape actuelle. (#147632, #147954, #147958, #140023, #138420, #144507)

  • Gestionnaire de paquets — hermes pm install --without EXTRA dépose un supplément transporté et le conserve. Un package mis en cache corrompu ne bloque plus chaque installation et pm update peut ignorer une cible en retard. 🧩 Plugins, compétences et MCP

###Plugins

  • Les plugins se tiennent à jour — hermes plugins update sans nom répertorie tous les plugins installés qui ont une mise à jour, les demande une fois et les met tous à jour (--yes pour les scripts). Une action Mettre à jour tout et un commutateur de mise à jour automatique (plugins.auto_apply, désactivé par défaut) existent désormais dans le CLI et le TUI (/plugins update, /plugins auto-update), le bureau et le tableau de bord Web. Les installations du catalogue sont désormais également mises à jour et hermes update vous indique quand le nouveau catalogue contient des mises à jour. Une mise à jour dont l'analyse revient en guise d'avertissement vous montre les résultats et vous permet de continuer (--force dans le CLI, une boîte de dialogue dans Desktop). (#141513, #85794, #141894 — @alt-glitch)
  • Les mises à jour n'interrompent plus votre configuration — lorsque hermes update doit désactiver un plugin, il conserve votre fournisseur de mémoire, rallume le plugin une fois qu'il est à nouveau installé et chaque surface l'affiche comme éteint. Les plugins dont les dépendances n'ont pas de roues pour un OS que vous n'exécutez pas (mnemosyne, torch) ne sont plus désactivés à chaque mise à jour. Un plugin répertorié comme activé et désactivé est désormais signalé par le chargeur et hermes doctor. (#144257, #144220, #144394 — @charan-rathore, @YS-OH-CORE, @renleding, @liuhao1024)
  • Les niveaux de version du catalogue sont appliqués — le requires_hermes d'une entrée bloque désormais les installations sur un Hermes trop ancien, et le update ne déplacera pas un plugin vers une broche nécessitant une version plus récente. Plugins qui utilisent une clé de manifeste provenant d'une installation Hermes plus récente avec un avertissement au lieu d'échouer. (#143468, #139225)
  • Nouveau niveau Vérifié dans le catalogue — Nous attribue ce niveau aux plugins réalisés par l'entreprise dont ils intègrent le produit. Cua Spaces, NVIDIA App, NVIDIA Broadcast, TinyFish et CoreWeave Inference sont les premiers. Les pages du plugin placent désormais les informations dans leur propre section en bas, et les cartes montrent ce que fait le plugin. (#139983, #142165, #141742, #142184)
  • Plus de fonctionnalités laissent le noyau aux plugins officiels — Camofox, hermes mcp serve (maintenant hermes mcp-serve, avec un nouveau mode --tools), hermes import-agent (ajoute les importateurs Cursor, Grok Bot et OpenBot) et le backend Singularity/Apptainer sont tous migrés vers les plugins. Les maisons qui utilisent Camofox, Singularity ou import-agent installent automatiquement le plugin ; Les utilisateurs MCP clients doivent changer leurs arguments en mcp-serve. (#143484, #142545, #142538, #147799, #142536)
  • Nouveaux plugins officiels — REA (ingénierie inverse), X Chat (X DM cryptés comme plate-forme de passerelle), Meshy (génération 3D), ElevenLabs Sound Effects, ElevenLabs Music (chansons, paroles, stems, partitions vidéo), délégation avancée et bubblewrap (un bac à sable Linux pour les commandes de terminal et de code). Hermes Labs ajoute hermes inbox, hermes record (enregistrement du flux de travail qui masque les mots de passe) et la recherche de brevets Patsnap. (#138225, #139725, #142619, #143744, #146294, #143265, #142548, #142523, #142519, #85138)
  • Nouveau plugin APIs — les plugins peuvent désormais publier un message dans le chat en cours et le modifier sur place (ctx.post_message), poser une question au propre agent de la session après un tour (ctx.side_question, qui nécessite votre consentement), bloquer un tour avant qu'il n'atteigne le modèle (bloc pre_llm_call) et retenir le streaming jusqu'à ce qu'un hook de réécriture soit exécuté (hold_stream). Nouveaux crochets : post_compaction et on_session_delete. Les commandes Slash reçoivent désormais la session d'appel, et les plugins de plate-forme et les recherches de compétences de plugin obtiennent des aides publiques. (#141005, #143791, #81434, #144266, #141017, #140995, #140997, #140624, #140978 — @curiouscleo, @Halldrix, @Baophan00, @Finn763, @pieralukasz, @ewtillman, @nekwo)
  • Les plugins peuvent vous connecter à des API tiers sans voir le jeton — un plugin déclare un OAuth client, hermes auth add <plugin>:<id> exécute la connexion au navigateur et Hermes attache le jeton uniquement sur les requêtes adressées aux hôtes déclarés par le plugin. (#141510 — @bablobanov)
  • Bigger Desktop plugin SDK — Les plugins de bureau peuvent ajouter des lignes au menu droit du compositeur click et des mots au correcteur orthographique, restituer les médias à partir de leurs propres outils, publier des cartes dans leur propre chat et créer un script pour le navigateur d'aperçu une fois qu'ils ont déclaré la fonctionnalité et que vous l'avez autorisée pour ce site. Les plugins portables reçoivent un formulaire Paramètres ▸ Plugins et une clé API nouvellement enregistrée atteint leur serveur MCP sans redémarrage. (#143678, #143980, #143776, #143668, #141533 — @Schildkrote)
  • Les plugins se comportent de la même manière sur une passerelle partagée — les commandes classiques du plugin CLI et pre_command s'exécutent désormais dans la passerelle avec le reste du plugin, et la désactivation d'un plugin ferme également ses websockets.   • Backend de configuration à distance pour les flottes (opt-in) : un agent de flotte tel que celui sur Hermes Cloud peut charger le config.yaml de chaque profil à partir d'un service central et les administrateurs peuvent verrouiller les clés.   • Démarrage plus rapide — à partir d'une extraction git, chaque commande hermes démarre environ 1 s plus rapidement, car les plugins du fournisseur et la vérification du redémarrage n'exécutent plus git à chaque fois (15 appels git jusqu'à 2). (#144640 — @100yenadmin)

MCP

  • Coûts des outils et limites de dépenses par chat — Les serveurs MCP, à partir de packages de plugins ou config.yaml, peuvent déclarer le coût de chaque outil et une limite de dépenses par chat.
