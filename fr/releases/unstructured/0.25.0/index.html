non structuré 0.25.0

Améliorations

  • Partition arbitraire de JSON et NDJSON : partition_json() et partition_ndjson() gèrent désormais toute charge utile JSON/NDJSON valide, et pas seulement la sortie non structurée sérialisée. Les tableaux (et les fichiers NDJSON) d'éléments sérialisés continuent de se réhydrater comme avant ; toute autre charge utile valide (objets nus, tableaux d'enregistrements, lignes NDJSON, scalaires) devient des éléments Text contenant le JSON joliment imprimé au lieu d'être augmenté. Les pré-portes de schéma dans partition() sont supprimées en conséquence, un objet compact JSON sur une seule ligne est désormais détecté comme FileType.JSON plutôt que NDJSON (la désambiguïsation JSON/NDJSON examine au plus le premier Mo du fichier), et une entrée mal formée génère toujours ValueError (les documents vides ou contenant uniquement des espaces ne produisent aucun élément). Un cas dégradé : NDJSON dont le premier enregistrement dépasse à lui seul la limite de désambiguïsation de 1 Mio est désormais classé comme JSON et échoue partition() avec ValueError (l'appel direct de partition_ndjson() le gère toujours). La réhydratation est choisie par un prédicat de forme explicite, avec ces conséquences : une charge utile en forme d'élément dont le contenu ne peut pas être réhydraté (par exemple, metadata corrompu) génère ValueError avec l'erreur sous-jacente enchaînée, et un tableau (ou un fichier NDJSON) mélangeant des éléments en forme d'élément et arbitraires partitionne l'ensemble comme JSON arbitraire - pas de réhydratation partielle qui supprime silencieusement les éléments arbitraires. Un objet JSON vide génère un Text contenant {} (un tableau vide ne génère aucun élément). Une note de routage prévue : un fichier d'éléments sérialisés à un enregistrement (un seul objet, pas un tableau) acheminé via partition()/detect_filetype() émet désormais un Text joliment imprimé avec des clés alphabétiques au lieu de se réhydrater, puisque la réhydratation s'applique uniquement aux tableaux (le comportement direct de partition_ndjson() est inchangé).
  • Les éléments TableChunk sérialisés se réhydratent désormais : elements_from_dicts() (et avec lui partition_json() et partition_ndjson()) supprimait auparavant les éléments TableChunk sérialisés en silence car le type n'est pas dans la carte de type d'élément partagée ; il est désormais dans un boîtier spécial comme CheckBox. Ceci complète la fonctionnalité de reconstruction de table (#4291), dont reconstruct_table_from_chunks() attend des morceaux désérialisés et dispose désormais d'un chemin de désérialisation pour l'alimenter. Changement de comportement : les charges utiles de sortie fragmentée sérialisée contenant des tables fractionnées renvoient désormais les éléments TableChunk (auparavant omis des résultats).
  • is_json_processable() et is_ndjson_processable() sont obsolètes : le partitionnement et la détection du type de fichier ne transitent plus par ces assistants de détection de préfixes. Ils continuent de fonctionner sans changement pour les appelants en aval - émettant désormais un DeprecationWarning - et seront supprimés dans une prochaine version.
