Baleine-code v0.9.6

Codewhale est le produit public de Shannon Labs. Le codewhale Les noms des commandes, des packages npm et des actifs de version restent techniques en minuscules identifiants. L'ancien package npm deepseek-tui est obsolète et ne reçoit aucune autre version. Utilisateurs issus de l'héritage v0.8.x deepseek / Les noms deepseek-tui doivent migrer avec docs/REBRAND.md.

Installer

Recommandé – npm (une commande, les deux points d'entrée)

npm install -g codewhale

Le wrapper télécharge les ressources de commande codewhale et codew correspondantes de cette version. Les deux contiennent le même runtime compilé.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.6

L'image expose le même runtime que codewhale et codew. Le La balise latest est également mise à jour lors de la sortie.

Cargaison (Linux / macOS)

cargo install codewhale-cli --locked

Le package Cargo installe codewhale. Cargo ne peut pas créer de deuxième commande alias d'une cible binaire ; les utilisateurs qui souhaitent une orthographe plus courte peuvent ajouter un Lien symbolique codew vers cet exécutable installé. Le npm, Homebrew, archive, Shell-installer et les canaux de conteneur installent directement les deux noms de commande.

Téléchargement manuel — archives de la plateforme (recommandé)

Chaque archive ci-dessous contient le même runtime sous le codewhale et Noms des commandes codew, plus un script d'installation :

| Plateforme | Archives | Script d'installation | |---|---|---| | Linuxx64 | codewhale-linux-x64.tar.gz | install.sh | | LinuxARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | MacOS BRAS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installateur) | CodeWhaleSetup.exe | Configuration du NSIS | | Windowsx64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — | | WindowsARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (portable) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux/MacOS) :

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Fenêtres :

  • Pour le chemin du programme d'installation, exécutez CodeWhaleSetup.exe ; il installe codewhale.exe et codew.exe sous %LOCALAPPDATA%\Programs\CodeWhale\bin et ajoute ce répertoire au CHEMIN de l'utilisateur actuel.
  • Extrayez l'archive de votre machine : codewhale-windows-x64.zip ou codewhale-windows-arm64.zip
  • Exécutez install.bat (copie dans %USERPROFILE%\bin)
  • Ajoutez %USERPROFILE%\bin à votre CHEMIN

L'archive Windows portable ignore le script d'installation : extrayez-la et exécutez-la à partir de n'importe quel répertoire. Le programme d'installation NSIS n'est actuellement pas signé et peut déclencher Windows SmartScreen jusqu'à ce qu'un certificat de signature soit connecté au pipeline de publication.

Chaque plate-forme dispose également de codewhale-<platform> nus et non archivés et Actifs codew-<platform>. Les sept noms de fichiers codewhale-tui-<platform> attachés au v0.9.5 sont des copies de compatibilité à octets identiques utilisées uniquement pour permettre v0.9.4 déjà installé clients découvre et traverse ce binaire unique transition; les installateurs actuels n’exposent pas de troisième runtime. L'héritage NPM le package deepseek-tui est obsolète et n’est pas republié. Pour migrer à partir des noms binaires hérités v0.8.x, voir docs/REBRAND.md.

Qu'y a-t-il dans v0.9.6

Codewhale v0.9.6 est une version soustractive : moins de gardes d'exécution, un stable des terminaisons de fournisseur rapides et véridiques et un chemin de compactage plus petit qui préserve le cache du fournisseur. Les modifications ont été fondées sur le Terminal-Bench 2.1 correspondant fonctionne contre Pi 0.8.41 et par dogfooding, compactage manuel répété.

Ajouté

  • web_search est par défaut Firecrawl Cloud sans clé API ; demandes sans clé sont sans en-tête et limités par des quotas, tandis qu'une clé utilisateur facultative augmente les limites.
  • Les versions Web vertes sur main émettent désormais un rappel de déploiement manuel exploitable, donc les modifications du site ne peuvent pas apparaître discrètement expédiées tant que Cloudflare sert toujours un révision plus ancienne.
  • Mistral AI est un itinéraire de fournisseur de premier ordre, comprenant les modèles Codestral, prise en charge du raisonnement de première partie, authentification, entrées de sélecteur et alias.
  • Le Bash sans tête peut transférer les services Unix persistants explicitement demandés à partir d'une exécution exécutive, avec les reçus de propriété et de nettoyage.
  • /remote-env ouvre le travail hébergé à partir de la pointe actuelle de la branche GitHub ou CNB et indique exactement quel état non poussé, sale, ignoré, secret et de session reste locale.
  • La version Linux ARM64 et les ressources nocturnes sont des versions musl statiques avec natif lancer des chèques.
  • Les responsables peuvent signaler les installations actives quotidiennes observées du même anonyme, ensemble de données de télémétrie agrégée ; aucune donnée supplémentaire client n'est collectée.
  • Membres envoyés par la flotte sous un plafond de preuves en lecture seule (sans réseau) désormais conserver les actions search et fetch en lecture seule de l'outil Web — parité avec un éclaireur ordinaire - tandis que chaque surface atteignant (web.run, fetch_url, github, MCP) reste refusé et l'enveloppe de capacités soutenue par les sentinelles reste le filet de sécurité en cas de faillite.
  • /fleet setup peut afficher un rôle-modèle facultatif, déterministe et non ratifié avis construit uniquement à partir d’itinéraires prêts configurés. Accepter, modifier et rejeter tous restent à l’intérieur de la limite de sauvegarde du profil existant examiné par l’homme ; le Advisory ne lance jamais de flotte ni n'écrit une deuxième configuration.
  • /update recherche une version plus récente de Codewhale et l'installe de l'intérieur le TUI, tandis que tui_help donne aux agents la même commande et la même carte de touches que les utilisateurs voient.
  • Les chemins de fichiers Markdown s'affichent sous forme de liens OSC 8 là où le terminal les prend en charge, et chaque ligne d'agent peut ouvrir directement la transcription de cet agent.
  • Les sessions de l'éditeur ACP peuvent exécuter des fichiers multi-tours, des recherches, Git, des correctifs et Appels d'outils shell explicitement activés via le registre d'exécution partagé. L'accès au Shell nécessite à la fois la capacité du terminal du client et celle de Codewhale. l'adhésion au shell sans tête et l'annulation arrête un outil en vol avant le le tour revient (#5225 par @rafaelcavalheri).
  • read minuscule renvoie les résultats PNG, JPEG, GIF et WebP typés limités à Routes de discussion, de réponses, anthropiques et ACP compatibles avec les images. Itinéraires en texte uniquement recevoir un reçu d'omission explicite ; les octets d'image ne se répandent jamais dans l'ordinaire transcription, exportation, compactage ou relais de texte.

Modifié

  • Le comptage des utilisations anonymes est activé par défaut pour les nouvelles installations et divulgué dans un modal Codewhale natif de première exécution avec une désinscription immédiate. Avant declines restent éteints. Codewhale ne collecte pas les conversations, le code, les invites, les fichiers, noms de dépôt ou de branche, informations d'identification, contenu du modèle ou activité par tour délais.
  • Les terminaux larges utilisent une toile océanique réactive en plein écran avec des gouttières : la prose garde une mesure lisible tandis que les outils, les différences, les surfaces de travail, le compositeur et Status Chrome peuvent utiliser la largeur disponible. Tour et majeur les coutures d'activité respirent sans compléter chaque appel à l'intérieur d'un groupe d'outils.
  • L'aide de Root CLI décrit directement les actions du produit au lieu d'exposer les informations internes. Couches TUI/runtime.
  • Bash action="wait" bloque désormais par défaut lorsqu'une attente est demandée ; appelants peut toujours demander un instantané non bloquant et la propriété persistante du service reste explicite.
  • Le compactage est une requête récapitulative stable dans le cache suivie d'une requête validée. un résumé de remplacement et une queue de message récent limitée. Sessions enregistrées plus anciennes Restaurer toujours.
  • Demander, Travailler, Révision automatique et Accès complet partagent une invite de base stable. Modes continuent de différer grâce aux autorisations et au catalogue d'outils en direct ; l'ancien L'étiquette Act est désormais Work dans l'ensemble du produit et des paramètres régionaux expédiés.
  • L'accès complet approuve désormais automatiquement les outils non contournables de manière cohérente, et le Le choix par défaut affiché sur les cartes d'approbation ordinaires est configurable.
  • Rapport sur les reçus de génération de modèle, de fenêtre contextuelle, de nom de répartition et d'agent imbriqué l'itinéraire et les limites réellement utilisés plutôt que de substituer silencieusement un identité devinée.
  • L'agent enfant lance un reçu d'itinéraire immuable avant l'admission et préservez-le à travers le statut, l'interruption, l'achèvement, la reprise, le graphique de travail, et les projections du grand livre, afin que l'attribution du fournisseur/modèle ne puisse pas dériver (#5305).
  • Les courses vers les objectifs ne s'arrêtent plus en raison d'une continuation interne, d'un écart répété ou gardes aux questions sans réponse. Limites d'utilisateurs explicites et états d'objectif du terminal restent faisant autorité.
  • La télécommande /rc appartenant au compte conserve désormais la propriété exclusive et un journal de livraison récupérable sur incident jusqu'à ce que le serveur accuse réception du terminal, approbation, échec et état de l’instantané.
  • todo_write est une surface de progression optionnelle plutôt qu'un modèle requis cérémonie.
  • Les nouveaux tours utilisent une petite boîte à outils stable : read, write, edit, bash, agent, todo_write et tool_search. L'outil de progression facultatif reste visible comme mémoire de travail familière ; natif spécialisé, Web, MCP, plugin, les outils de mémoire, de tâches et de vérification sont filtrés par politique et consultables ; les schémas activés restent dans un cache limité par conversation. Chaque sous-agent conserve sa propre recherche et son propre cache, y compris la recherche Web autorisée par les règles, tandis que Le contexte forké et les activations parentales restent des démarrages à chaud plutôt que des listes autorisées.
  • Les schémas de fichiers directs et de shell suivent le contrat volontairement petit de Pi : lectures de lignes complètes délimitées, écritures sans hachage, édition multiple sans ambiguïté avec Préservation BOM/CRLF et correspondance floue conservatrice, et un premier plan Commande bash avec une queue de sortie chronologique limitée. Changement de mode autorité d'exécution, pas ces noms primitifs.
  • Codewhale ne réitère plus la liste de tâches au modèle. Le modèle apprend ce qui est sur la liste du résultat de l'outil, son propre appel todo_write renvoyé, qui est un historique de conversation ordinaire – de la même manière que fonctionne To-do de Pi. Le bloc transitoire <codewhale:work_state> qui chevauchait la queue de chaque La demande d'étape de boucle de tour parent et de sous-agent a disparu, ainsi que l'écurie le préfixe système est perturbé par les changements de liste. Un instantané est toujours affiché une fois, où une personne l'a demandé : le <codewhale:fork_state> bloque un nouveau fourchu le sous-agent est remis, les instructions de transfert du /relay et la carte d'agent. Le La tâche terminée reste visible dans l'interface utilisateur. Un test structurel affirme la réalité Les corps de demande du fournisseur sortant ne portent pas la liste.
  • Scout et Reviewer nomment les rôles d'enquêteur en lecture seule. Les deux exposent exactement un point d'entrée du shell - minuscule canonique bash, délimité par le strict classificateur en lecture seule — et l'ancien alias Bash reste refusé dans le catalogue et à l'expédition. Auparavant, une correspondance de nom insensible à la casse permettait d'épeler un appel Bash s'exécute via cette exclusion, renvoyant le shell brut à un rôle en lecture seule.

Fixé

  • L'envoi de plus de contexte pendant l'exécution d'une commande bash minuscule se déplace désormais la commande à /jobs et renvoie un reçu d'exécution réussi au lieu de signalant faussement Command exited with code -1 ; le processus continue de fonctionner et son achèvement arrive toujours via l'événement d'exécution normal.

  • La divulgation de l'utilisation de première exécution s'ouvre désormais en tant que modal Codewhale natif au lieu d'un questionnaire shell avant le démarrage de l’application. La télémétrie reste désarmée jusqu'à ce que le choix natif soit fait et qu'un choix Désactiver en mémoire régisse le session en cours même si sa préférence ne peut pas être enregistrée.

  • Les résultats d'achèvement, d'échec, de mise en file d'attente, de duplication et de boîte aux lettres du /compact sont des reçus de transcription durables au lieu de toasts de courte durée. Un terminal errant l'événement ne peut plus laisser chaque compactage ultérieur bloqué comme étant déjà en cours d'exécution.

  • Le compactage suit désormais la forme simple de la transcription du Codex : contexte utilisateur récent suivi d'un point de contrôle historique ordinaire. Il n'ajoute jamais le résumé, la liste de tâches ou l'état volatile du shell/travailleur à l'invite système permanente ; les rechargements migrent le transporteur persistant vers exactement un élément de l'historique.

  • Le compactage automatique utilise un pourcentage de la fenêtre de contexte réelle, fixé à le plafond utilisable de l'itinéraire. La pression vient de la route parent actuelle rapide, pas de facturation cumulative ni d'utilisation du modèle enfant.

  • Compactage, revue, vérification, routage, configuration, Flotte, MCP, RLM, vision, traduction, et les appels de sous-agent héritent de la sortie normale de la route résolue, échantillonnage et politique de raisonnement. Les petits plafonds de jetons de tâches internes ne sont plus des parcours de réflexion tronqués ou des prestataires individuels spécialisés dans des cas particuliers.

  • Les réponses incomplètes des fournisseurs échouent honnêtement au cours des tours ordinaires et à chaque consommateur de modèle interne. Le texte partiel reste interrompu, les appels d'outils en attente le font ne s'exécute pas et l'utilisation facturée est conservée.

  • Les espaces réservés (reasoning omitted) réservés au transport uniquement n'entrent plus dans les nouveaux transcriptions et sont filtrés des sessions restaurées. Raisonnement développer/réduire les actions restent attachées à la cellule exacte rendue, y compris après remplacement, restaurer, filtrer et redimensionner (#5291).

  • L'épuisement du budget par étape est un échec typé et ne peut débloquer un en attente service persistant. L'annulation après utilisation du terminal facture toujours le tour.

  • Les outils différés préservent désormais un résultat complet lorsqu'un fournisseur réutilise son ID d'appel d'outil lors de la nouvelle tentative, empêchant les appels de plugin réussis de entrer dans une boucle d’exécution répétée.

  • Configuration du site Web, fournisseur, diagnostics, flotte et réclamations à exécution unique maintenant correspondre au candidat source.

  • L'ouverture du registre des sous-agents ne masque plus la liste des tâches : les Agents Le panneau montre le registre complet et la liste de contrôle durable ensemble, et le l'en-tête de registre est une porte bidirectionnelle qui renvoie aux tâches sur un deuxième click.

  • L'accord de détails ⌥V / Alt+V ouvre la ligne de la surface de travail sélectionnée inspecteur au lieu de la cellule outil la plus proche de la transcription, donc une sélection La ligne de tâches affiche son propre contenu plutôt que le dernier raisonnement.

  • La divulgation d'utilisation de première exécution pose désormais une question claire : "Aidez à améliorer Baleine codée ?" — avec sans ambiguïté "Oui, conserver les décomptes anonymes" / "Non, désactiver suivi" des choix dans chaque région expédiée, et indique la désinscription persistante commande. La sémantique du consentement reste inchangée : la télémétrie reste désarmée jusqu'à ce qu'une le choix est fait.

  • Les captures d'écran macOS référencées dans un message sont copiées sur un répertoire de pièces jointes stable au moment où le message est reçu, et le la référence est réécrite dans le chemin stable, donc l'image existe toujours lorsque l'agent le lit. Uniquement les fichiers sous une capture d'écran "Éléments temporaires" le répertoire est touché ; les copies sont idempotentes et une copie ratée conserve le référence originale.

  • Le /compact manuel pendant un tour actif est désormais mis en file d'attente même lorsque le moteur est à l'arrêt. La boîte aux lettres opérationnelle délimitée est saturée. La demande reporte client-side, réessaye comme les emplacements de boîte aux lettres sont libres et ne peuvent pas se verrouiller car ils sont déjà en cours d'exécution une fois installés.

  • Les chemins de sélection interactifs /load, démarrage --resume et /resume sont préservés le fournisseur persistant, le point de terminaison et l'identité du modèle ; le sélecteur reprend également laisse un reçu de relevé de notes durable.

  • Les valeurs relatives de mcp_config_path ne dépendent plus du répertoire de lancement ou charger silencieusement un pool de serveurs vide : Codewhale avertit et revient au configuration MCP globale de l'utilisateur. Les chemins absolus explicites restent faisant autorité.

  • Alibaba Model Studio qwen3.8-max et qwen3.8-max-preview diffusent toujours leur raisonnement actuel, mais ne rejoue plus l'historique reasoning_content que ces itinéraires n'acceptent pas. La répétition du raisonnement historique est désormais limitée par le fournisseur exact/API/modèle de contrat, donc des sosies *-thinking inconnus échec fermé pendant la documentation de Qwen, Kimi, DeepSeek, Mistral, Anthropic et Les règles de continuité des réponses restent intactes.

  • Les appels de fichiers/correctifs de compatibilité conservent des protections de hachage de contenu facultatives lorsqu'un l'appelant les fournit. Les nouveaux schémas directs write et edit n'exposent pas hachage ou cérémonie de lecture préalable.

  • Les aperçus du shell retiennent les séquences UTF-8 incomplètes au lieu de les émettre les caractères de remplacement et les reçus de compactage signalent les deltas des jetons.

  • Les agents imbriqués peuvent restreindre mais ne peuvent jamais élargir leur budget de profondeur hérité (#5317 par @ousamabenyounes).

  • La publication du conteneur assemble désormais les images AMD64 et ARM64 en parallèle sur exécuteurs natifs à partir des binaires de version statique déjà vérifiés, puis publie et vérifie un manifeste multi-architecture. Il ne se reconstruit plus les deux cibles grâce au seul travail QEMU de longue durée qui a perdu son coureur.

Supprimé

  • La garde sans progression, la garde à lecture répétée et la stratégie d'erreur d'outil injectée encadrement. Sondages productifs, inspections répétées et récupération propriétaire du modèle ne sont plus interrompus par les heuristiques d’exécution.
  • Carte de décision, liaison de touches, survol, exécution de shell, fonctionnement du moteur et Les chemins du script de version ont été supprimés afin que le runtime pris en charge ait une seule route pour chaque comportement.
