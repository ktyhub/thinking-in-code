Codewhale v0.8.66

Baleine-code v0.8.66

CodeWhale est le projet canonique, la commande, le package npm et nom de l'actif de version. L'ancien package npm deepseek-tui est obsolète et ne reçoit aucune autre version. Utilisateurs venant de Les noms hérités v0.8.x deepseek / deepseek-tui devraient migrer avec docs/REBRAND.md.

Installer

Recommandé — npm (une commande, les deux binaires)

npm install -g codewhale

Le wrapper télécharge les binaires d'exécution correspondants à partir de cette version et les place dans le même répertoire.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

L'image contient le répartiteur codewhale, la cale codew et le runtime codewhale-tui. La balise latest est également mise à jour lors de la sortie.

Cargaison (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Les deux caisses sont requises : codewhale-cli produit le répartiteur codewhale et la cale codew, tandis que codewhale-tui produit le runtime interactif auquel le répartiteur délègue. L'installation d'une seule caisse échouera au moment de l'exécution avec une erreur MISSING_COMPANION_BINARY.

Téléchargement manuel — archives de la plateforme (recommandé)

Chaque archive ci-dessous contient le répartiteur codewhale, le shim codew et le runtime codewhale-tui, ainsi qu'un script d'installation : | Plateforme | Archives | Script d'installation | |---|---|---| | Linuxx64 | codewhale-linux-x64.tar.gz | install.sh | | LinuxARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | MacOS BRAS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installateur) | CodeWhaleSetup.exe | Configuration du NSIS | | Windowsx64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — | Unix (Linux/MacOS) :

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Fenêtres :

  • Pour le chemin du programme d'installation, exécutez CodeWhaleSetup.exe ; il installe codewhale.exe, codew.exe et codewhale-tui.exe sous %LOCALAPPDATA%\Programs\CodeWhale\bin et ajoute ce répertoire au PATH de l'utilisateur actuel.
  • Extraire codewhale-windows-x64.zip
  • Exécutez install.bat (copie dans %USERPROFILE%\bin)
  • Ajoutez %USERPROFILE%\bin à votre CHEMIN L'archive Windows portable ignore le script d'installation : extrayez et exécutez à partir de n'importe quel répertoire. Le programme d'installation NSIS n'est actuellement pas signé et peut déclencher Windows SmartScreen jusqu'à ce qu'un certificat de signature soit connecté au pipeline de publication. Chaque plate-forme contient également des binaires nus et non archivés joints ci-dessous (codewhale-<platform>, codew-<platform> et codewhale-tui-<platform>) — le wrapper npm et le codewhale update intégré à l'application téléchargent les binaires d'exécution correspondants, tandis que les archives .tar.gz / .zip ci-dessus constituent le téléchargement manuel recommandé et regroupent en outre un script d'installation. L'ancien package npm deepseek-tui est obsolète et n'est pas republié. Pour la migration à partir des anciens noms binaires v0.8.x, voir docs/REBRAND.md.

Vérifier (recommandé)

Téléchargez les manifestes de somme de contrôle de cette version et vérifiez :

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

Qu'y a-t-il dans v0.8.66

Ajouté

  • Ajout de l'état hérité codewhale doctor / codewhale doctor --json des diagnostics qui comparent les chemins d'état connus du ~/.deepseek avec leurs Homologues du ~/.codewhale et indicateur des données non migrées ou à double racine (#3727).
  • Ajout de Sakana AI Fugu en tant que fournisseur compatible OpenAI de première classe avec Alias sakana/fugu, découverte FUGU_API_KEY / SAKANA_API_KEY, Câblage du sélecteur de fournisseur, complétions de modèles et documents du fournisseur. Récolté à partir de #3748 par @lerugray.
  • Ajout de la validation de la forme de lancement WhaleFlow-to-Fleet : le workflow de flotte par défaut le contrat autorise jusqu'à 100 agents au total et 5 anneaux récursifs, nécessite boucles/expansions limitées avant le lancement et préserve la sélection de modèle par emplacement.
  • Ajout d'une vue /config ask-rules en lecture seule pour les résolus Chemin permissions.toml, état du fichier, nombre de règles et configuration outil/commande/chemin demande des règles. Fusionné à partir du #3569 par @greyfreedom.
  • Ajout des remplacements context_window au niveau du fournisseur afin d'être compatible avec OpenAI les passerelles et les fournisseurs auto-hébergés peuvent budgétiser par rapport à leur modèle réel fenêtre contextuelle (#3545).
  • Ajout de la cale native codew pour libérer les archives, les entrées de l'installateur Windows, préparation des actifs de version locale et vérification de la somme de contrôle pour des installations manuelles recevez la même commande courte que celle que Cargo installe.
  • Ajout d'OpenModel en tant que fournisseur de messages anthropiques de première classe, avec configuration, CLI, sélecteur de fournisseur, documents et couverture du registre. Récolté à partir du #3585 par @noaft.
  • Ajout de la documentation sur le déploiement et la sécurité de WeCom Bridge, avec la livraison commandes d'exécution/pont et conseils sur l'environnement de délai d'approbation. Récolté à partir du #3640 par @pkeging.
  • Ajout d'une commande token/cache/cost scorecard pour le déclenchement des versions hors ligne, contrôles de régression de base et visibilité des coûts par tour (#3388). Flux-JSON Les métadonnées exec rapportent désormais également les conservateurs input_analysis et visible_final_answer_chars, pour que les harnais de référence puissent mesurer la transcription croissance et ballonnement de la réponse finale sans deviner (#2956, #2957).
  • Ajout d'un registre des preuves de version pour v0.8.66 et ouverture de l'ACP externe soumission au registre pour CodeWhale après avoir validé la publication Prise de contact d'authentification ACP codewhale@0.8.65 avec le vérificateur de registre en amont (#3192).
  • Ajout d'une table de configuration [verifier] typée pour la voie d'aperçu du vérificateur, avec enabled et le mappage verdict_policy = "hunt" expédié documenté et validé (#2093).
  • Ajout de la commutation rapide des emplacements Hotbar Alt+1 – Alt+8 avec clé de carte de décision homonymie, plus une carte d'introduction qui explique et peut rejeter le Barre de raccourcis (#3796, #3788).
  • Hygiène des versions/documents : extraits d'installation/version publics protégés et npm Pointeur codewhaleBinaryVersion contre la dérive, fabriqué check-docs/check-facts échoue sur des extraits de code obsolètes ou des fournisseurs non mappés et a arrêté sync-changelog de supprimer une version alors que seul [Unreleased] existe (#3767, #3768, #3769, #3770, #3771, #3772).

Modifié

  • Mode automatique différé à partir du sélecteur de mode orienté utilisateur, cycle, barre de raccourcis, /mode commande, et le mode runtime-thread remplace jusqu'à ce qu'il ait une invite distincte et comportement de révision automatique ; Le texte du mode auto existant se replie désormais sur l'agent au lieu de sélectionner un mode creux, et la copie modale d'approbation n'implique plus le mode actuel est YOLO (#3730, #3733).
  • Clarification de la surface de configuration de la flotte et de la documentation afin que la flotte soit traitée comme le durable couche de configuration du sous-agent tandis que WhaleFlow est la couche créée par l'agent plan d'orchestration qui sélectionne et surveille les créneaux horaires de la flotte.
  • Réduction de l'invite de Constitution par défaut tout en conservant la structure requise ancres sous couverture de régression, réduisant ainsi l'empreinte d'invite statique pour tours sensibles au cache (#2953).
  • L'invite d'approbation a été intégrée en ligne et ancrée en bas au lieu d'être affichée en plein écran. prise de contrôle, afin que le contexte et les contrôles restent visibles pendant qu'un outil attend une décision (#3799).
  • La Hotbar est désormais masquée par défaut jusqu'à l'inscription explicite de la configuration (#3807) ; le Le shell de l'agent interactif est également par défaut activé avec approbation avec un partage référence (n° 3756).
  • L'autorité de mode résout désormais les invites d'approbation via une seule autorité source au lieu de contrôles par surface (#3795).

Corrigé

  • Relocalisation de l'état hérité avec un avis de migration visible par l'utilisateur à chaque fois ~/.deepseek/<state> est déplacé ou copié dans ~/.codewhale/<state>, donc les utilisateurs mis à niveau savent que leurs données ont été conservées et où se trouve l'état canonique vit maintenant (#3726).
  • Visibilité héritée .deepseek/sessions restaurée pour les installations mises à niveau où un répertoire ~/.codewhale/sessions vide existait déjà, en copiant entrées de session héritées manquantes dans le magasin de sessions CodeWhale principal sans écraser les données plus récentes (#3724).
  • Classification du risque d'approbation calmée pour les commandes shell en lecture seule telles que codewhale --version, codewhale --help et git status --porcelain donc le modal ne qualifie plus le shell en lecture seule éprouvé comme destructeur (# 3730).
  • Ajout de colonnes de route fournisseur/modèle au /cache pour activer la télémétrie afin de DeepSeek les régressions d'accès au cache peuvent être corrélées aux changements de route automatiques (# 3738).
  • Correction de la gestion des approbations d'exécution API afin que l'espace de travail trust ne se résolve plus automatiquement approbations d'outils ordinaires ; Le trust participe désormais uniquement à la nouvelle tentative d'accès complet décisions tandis que YOLO/auto-approve reste le contournement d’approbation (#3736).
  • Correction des surfaces modales afin que la pile de vues partagées peint une toile de fond opaque avant toute superposition, tandis que les intérieurs contextuels du plan/de demande de saisie restent opaques et que le plan le pied de page de confirmation maintient les choix d'action visibles sur les terminaux étroits (# 3732).
  • Ajout d'une protection en mode Plan en boucle de tour pour les outils d'écriture de fichiers et MCP capable d'écrire des outils afin que la promesse de « non-écriture » de Plan soit appliquée avant l'approbation ou l'exécution, pas seulement par la couche sandbox/catalogue (#3734).
  • Préservation du plancher de sécurité de révision durable pour les actions shell de type publication dans Mode YOLO, donc cargo publish, npm publish et tag/release poussent la force approbation au lieu d’une approbation automatique silencieuse (#3735).
  • Correction de l'éditeur externe Ctrl+O qui se bloque là où la pompe d'entrée du terminal de CodeWhale pouvait continuer à lire les clés pendant que Vim/éditeur possédait le terminal, en particulier dans Coquilles Windows Mintty/cygwin. Merci @buko pour la repro précise (#3657).
  • Renforcement du contrôle de dérive de dépendance OHOS par rapport aux EOF transitoires du registre Cargo en réessayant la sonde du graphe de dépendances avant d'échouer CI.
  • Mise à jour du fournisseur /links de secours vers l'URL actuelle de la documentation CodeWhale et ajout d'un lien vers la documentation Baidu Qianfan. Récolté à partir du #3621 par @noaft.
  • CODEWHALE_TOOL_SURFACE=shell-only durci pour les exécutions de benchmark/exec : le la surface shell uniquement masque les outils natifs du catalogue visible par le modèle, et Les valeurs inconnues de CODEWHALE_TOOL_SURFACE avertissent désormais au lieu de tomber silencieusement retour à la surface complète de l'outil (#2954).
  • Distribution des sous-agents et verrouillage des chemins chauds : marge de canal d'événement préservée pour événements de progression (#3783, merci @cyq1017), laissez le sous-agent indépendant démarrer rejoindre un seul lot de répartition parallèle au lieu de sérialiser (#3801), rendu la barre latérale du sous-agent/ListSubAgents à partir d'un instantané en lecture seule avec des limites nettoyage (# 3803), utilisé des envois au mieux non bloquants pour l'actualisation des ListSubAgents en attendant toujours des événements critiques (#3802), état de sous-agent déplacé E/S de disque de persistance hors du verrou d'écriture du gestionnaire (#3805) et utilisé try_lock pour l'actualisation du gestionnaire de shell dans les chemins d'interface utilisateur asynchrones (#3804).
  • Provenance : les suites d'exécution et SubAgentHandoff héritent désormais du statut Autorité YOLO, tandis que MemoryRecall, ImportedTranscript et Les entrées AssistantGenerated restent gardées (#3817).
  • Honnêteté de l'approbation : étiquetées avec précision les approbations à l'échelle de la session au lieu de "toujours" et les décisions d'approbation ont fait surface dans les résultats de l'outil (#3766). Crédits des contributeurs pour cette version en direct dans l'entrée changelog ci-dessus — merci à tous ceux dont les rapports, les relations publiques, les critiques et les reproductions l'ont façonné. Voir CHANGELOG.md pour les notes complètes et docs/CHANGELOG_ARCHIVE.md pour les anciennes versions.
