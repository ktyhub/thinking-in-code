Baleine Code v0.9.7

Codewhale est le produit public de Shannon Labs. Le codewhale Les noms des commandes, des packages npm et des actifs de version restent techniques en minuscules identifiants. L'ancien package npm deepseek-tui est obsolète et ne reçoit aucune autre version. Utilisateurs issus de l'héritage v0.8.x deepseek / Les noms deepseek-tui doivent migrer avec docs/REBRAND.md.

Installer

Recommandé – npm (une commande, les deux points d'entrée)

npm install -g codewhale

Le wrapper télécharge les ressources de commande codewhale et codew correspondantes de cette version. Les deux contiennent le même runtime compilé.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.7

L'image expose le même runtime que codewhale et codew. Le La balise latest est également mise à jour lors de la sortie.

Cargaison (Linux / macOS)

cargo install codewhale-cli --locked

Le package Cargo installe codewhale. Cargo ne peut pas créer de deuxième commande alias d'une cible binaire ; les utilisateurs qui souhaitent une orthographe plus courte peuvent ajouter un Lien symbolique codew vers cet exécutable installé. Le npm, Homebrew, archive, Shell-installer et les canaux de conteneur installent directement les deux noms de commande.

Téléchargement manuel — archives de la plateforme (recommandé)

Chaque archive ci-dessous contient le même runtime sous le codewhale et Noms des commandes codew, plus un script d'installation :

| Plateforme | Archives | Script d'installation | |---|---|---| | Linuxx64 | codewhale-linux-x64.tar.gz | install.sh | | LinuxARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | MacOS BRAS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installateur) | CodeWhaleSetup.exe | Configuration du NSIS | | Windowsx64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — | | WindowsARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (portable) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux/MacOS) :

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Fenêtres :

  • Pour le chemin du programme d'installation, exécutez CodeWhaleSetup.exe ; il installe codewhale.exe et codew.exe sous %LOCALAPPDATA%\Programs\CodeWhale\bin et ajoute ce répertoire au CHEMIN de l'utilisateur actuel.
  • Extrayez l'archive de votre machine : codewhale-windows-x64.zip ou codewhale-windows-arm64.zip
  • Exécutez install.bat (copie dans %USERPROFILE%\bin)
  • Ajoutez %USERPROFILE%\bin à votre CHEMIN

L'archive Windows portable ignore le script d'installation : extrayez-la et exécutez-la à partir de n'importe quel répertoire. Le programme d'installation NSIS n'est actuellement pas signé et peut déclencher Windows SmartScreen jusqu'à ce qu'un certificat de signature soit connecté au pipeline de publication.

Chaque plate-forme dispose également de codewhale-<platform> nus et non archivés et Actifs codew-<platform>. Les sept noms de fichiers codewhale-tui-<platform> attachés au v0.9.5 sont des copies de compatibilité à octets identiques utilisées uniquement pour permettre v0.9.4 clients déjà installé découvre et traverse ce binaire unique transition; les installateurs actuels n’exposent pas de troisième runtime. L'héritage NPM le package deepseek-tui est obsolète et n’est pas republié. Pour migrer à partir des noms binaires hérités v0.8.x, voir docs/REBRAND.md.

Qu'y a-t-il dans v0.9.7

Codewhale v0.9.7 garde le catalogue ordinaire. Grok 4.6 débarque comme un catalogue normal rangée au lieu d'une pile de cas spéciaux en forme de fournisseur, OrcaRouter se joint en tant que fournisseur nommé, et un avis de sécurité panique dans lru est effacé en levant le l'épingle qui l'a causé plutôt que de vivre autour d'elle.

Ajouté

  • Grok 4.6 est la valeur par défaut directe de xAI, avec l'alias grok se déplaçant dessus et grok-4.5 toujours explicitement sélectionnable. Son contexte 500K, sa saisie texte/image, support d'outils et de sorties structurées, raisonnement low/medium/high/xhigh efforts (high par défaut) et la recherche Web côté serveur proviennent tous du Catalogue en forme de Models.dev plutôt que code spécifique au modèle. reasoning_effort atteint le fil uniquement sur l'itinéraire exact du premier parti https://api.x.ai/v1, et la limite de tarification de 200 000 jetons tenant compte de l'utilisation est conçue pour diriger xAI afin Les routes d'agrégation réutilisant le slug de modèle ne peuvent pas hériter de la facturation xAI.
  • OrcaRouter est un fournisseur nommé de première classe : ORCAROUTER_API_KEY, base par défaut URL https://api.orcarouter.ai/v1, deepseek/deepseek-v4-pro par défaut, Routage orcarouter/auto, sélecteur CLI --provider et entrées de sélecteur TUI (#5321).

Modifié

  • Normalisation de l'effort de raisonnement et le sélecteur de modèle lit la publication d'un modèle reasoning_options du catalogue au lieu de réduire chaque itinéraire en l’échelle historique Low/Medium. Toute ligne de catalogue qui publie une liste d'efforts garde son propre vocabulaire.
  • Docs enregistre le label backend DeepSeek-V4-Pro-0813 en direct de DeepSeek pendant que le L'ID API appelable reste deepseek-v4-pro. Aucun alias n'est remappé et aucun Le sélecteur deepseek-v4-pro[1m] est envoyé.

Corrigé

  • Copier un message utilisateur ou assistant prend son contenu canonique au lieu de lignes de transcription resérialisées, conservant les glyphes de rôle, les rails de continuation et emballage visuel du clipboard tout en préservant l'Unicode d'origine, Markdown et sauts de ligne durs. Les cellules d’outils et de réflexion restent sur l’existant chemin de la transcription complète (#5319).
  • load_session n'exécute plus de récupération après incident à chaque lecture. Les lectures instantanées sont terminées grâce à un load_session_snapshot sans effets secondaires et la récupération est explicite via recover_session_for_resume, donc un hôte d'intégration inspectant un durable la session alors qu'un outil est toujours en cours d'exécution ne fait plus l'objet d'une fausse réparation en cas de crash (#5320).

Sécurité

  • lru se déplace vers 0.18 pour effacer RUSTSEC-2026-0253, là où se trouvait LruCache::pop() pas de panique et pourrait laisser des pointeurs de liste en suspens. Le ratatui-core La goupille =0.1.0 qui a forcé transitivement lru ^0.16 est levée, donc ColorCompatBackend répond désormais à get_cursor_position() à partir du curseur suivi state - la solution de contournement recommandée en amont pour la course au démarrage CPR (ratatui/ratatui#2483, ratatui/ratatui#2640) que la goupille fonctionnait à l'origine autour. ratatui lui-même reste épinglé sur =0.30.0, donc la surface API est inchangé.

Problèmes connus

  • Le test d'intégration exec_persistent_service::failed_exec_kills_pending_service_and_exits_nonzero est un flocon confirmé sous charge parallèle ("le fichier pid de service n'est jamais apparu"). Il passe de manière isolée et n'est lié à aucun changement de v0.9.7.
