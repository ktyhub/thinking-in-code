Installer

Recommandé — version officielle du GitHub

Nouvelle installation macOS/Linux (binaires avec somme de contrôle de cette version) :

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.9.13" sh
"$HOME/.local/bin/codewhale" --version

Pour Windows, utilisez le programme d'installation ou l'archive correspondant ci-dessous. Pour un existant installation directe, exécutez codewhale update ; il imprime le chemin de l'exécutable et conserve les versions plus récentes. Si le répertoire d'installation est occupé par une autre build, utilisez la migration d'un nouveau répertoire dans [le guide d'installation] (https://github.com/Hmbown/CodeWhale/blob/main/docs/INSTALL.md).

Emballage secondaire — npm et Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

Le wrapper télécharge les ressources de commande codewhale et codew correspondantes de cette version. Les deux contiennent le même runtime compilé.

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \

L'image expose le même runtime que codewhale et codew. Le La balise latest est également mise à jour lors de la sortie.

Cargaison (Linux / macOS)

cargo install codewhale-cli --locked

Le package Cargo installe codewhale. Cargo ne peut pas créer de deuxième commande alias d'une cible binaire ; les utilisateurs qui souhaitent une orthographe plus courte peuvent ajouter un Lien symbolique codew vers cet exécutable installé. Le npm, Homebrew, archive, Shell-installer et les canaux de conteneur installent directement les deux noms de commande.

L'explicite Le convertisseur hors ligne prend en charge certaines compétences portables et Streamable statique Déclarations HTTP MCP d'OpenCode et DSH. Hooks exécutables non pris en charge, Les configurations automatiques OAuth et portant sur des politiques sont refusées ; généré les bundles nécessitent toujours une installation native, une révision et un trust. ESS hérité le repli n'est pas reproduit (#5827, demandé par @giancarlocp).

  • Les faits signés sur le modèle cloud peuvent actualiser les capacités et les prix des fournisseurs tout en préserver les données mises en cache vérifiées en cas d'échec d'une actualisation. Une demande expédiée conserve son instantané de prix sélectionné afin que les mises à jour ultérieures du catalogue ne puissent pas modifier son coût enregistré (#5752).

  • Les sessions enregistrées préservent les itinéraires exacts du fournisseur. Les appels de modèles auxiliaires sont réglés leur utilisation une fois par rapport à l'instantané d'itinéraire et de prix qui les a exécutés, y compris la récupération, plutôt que de fixer un nouveau prix à l'achèvement (#5726, #5848).

  • [tui].posture_bar et [tui].metrics_line acceptent full, compact ou hidden, également disponible via /config. Compact préserve l’existant champs essentiels des lignes ; Hidden renvoie leur espace à la transcription (#5973).

  • Désactivation facultative de la rédaction de la sortie de l'outil liée au modèle, avec deux démarrages explicites des confirmations et un reçu lié au contenu lisible de la configuration et heure de modification. Les requêtes non confirmées maintiennent le masquage activé ; routage et les résumés d'objectifs stockés restent expurgés (# 5982, merci @SparkofSpike).

  • La fonction cargo rusty-alloc sur codewhale-tui et codewhale-cli opte les binaires dans l'allocateur global rusty_alloc (le mimalloc Architecture v2.4.5 refaite en pur Rust — pas de compilateur C ni de script de construction sur ce chemin) au lieu du mimalloc par défaut. Il est désactivé par défaut et la version par défaut est inchangée ; construire avec cargo build -p codewhale-tui --features rusty-alloc (#5872).

  • Le sélecteur /theme découvre désormais les custom:<name> valides créés par l'utilisateur. superpositions, prévisualise leurs couleurs, met en évidence la superposition active et préserve lorsque le sélecteur est ouvert et validé sans navigation (#5901).

  • Le compactage a deux boutons debout à côté de [context] dans config.toml : [compaction] summary_instructions (ajouté à l'invite du résumé sur chaque passage manuel et automatique ; /compact <focus> compose toujours après il) et [compaction] retained_user_message_tokens (par défaut 20 000, fixé à 2 000..=200 000) pour le budget des messages utilisateur verbatim. Les deux sont absent par défaut et absent désigne le comportement préexistant. Le Le reçu /compact indique le budget effectif et indique si l'opérateur instructions appliquées (#5956).

  • [tools] user_input_max_questions (par défaut 6, 1..=10) et [tools] user_input_max_options (par défaut 4, 2..=10) remplace le code codé en dur Limites request_user_input ; le validateur, le schéma de l'outil et son la description lit une valeur, les enfants engendrés héritent des plafonds des parents, et une charge utile rejetée nomme le plafond qu'elle a atteint et la clé à augmenter (#5949).

  • Le menu slash affiche la ligne d'utilisation d'une commande et ses sous-commandes dès que un espace est tapé après le verbe, filtré par ce qui suit, donc Tab complète /workspace wor à /workspace worktrees ; /help indique le focus utilisation de la commande dans son emplacement de détail (#5952).

  • Les trois vues /fleet (liste, travailleurs en direct, équipes enregistrées) n'en font qu'une pile rétronavigable : Esc dans les travailleurs ou les équipes enregistrées revient à la liste avec son curseur intact et ferme toujours la fenêtre à la racine ou en direct entrée; l'indice de pied de page Esc indique back ou close en conséquence (#5954).

  • /fleet présente son noyau prioritaire (members, setup, teams, workers, help); tout autre verbe reste dispatchable et est documenté sous des groupes explicites dans /fleet help. La liste ne montre plus le Alias general intégré intact à côté de worker (# 5888).

  • Fournisseur codewhale : accès au modèle basé sur le compte via les clés du fournisseur a client connecté à son compte Codewhale. Une URL de base (https://api.codewhale.net/v1, remplaçable par CODEWHALE_API_BASE ; HTTPS requis sauf sur bouclage), une clé API du compte cwc_key_… avec le Lunette models:infer (CODEWHALE_API_KEY) et un fil par modèle choisi parmi le GET /v1/models authentifié du compte : les identifiants sont provider/model et chaque ligne indique chat-completions (/v1/chat/completions) ou anthropic-messages (/v1/messages). Les deux protocoles s'authentifient avec Authorization: Bearer, jamais x-api-key. La clé est lue depuis CODEWHALE_API_KEY, l'emplacement du magasin secret codewhale, ou [providers.codewhale] api_key / api_key_env, et une clé manquante échoue avant toute demande au lieu d'expédier des produits non authentifiés. Si le catalogue ne peut pas être récupéré, la route revient à trois identifiants d'amorçage et le dit.

  • codewhale account api-keys create --scope accepte désormais models:infer aux côtés de account:read et agent:run, et un --scope omis envoie tout trois explicitement. --use enregistre le nouveau secret en tant que local de cette machine Identifiant du fournisseur codewhale dans le même magasin secret codewhale auth utilisations; rien n'est téléchargé.

  • Git développe une action commit_plan : un planificateur à propositions uniquement qui divise le arbre de travail en commits atomiques ordonnés (# 3999). Il regroupe des fichiers entiers - verrouiller les fichiers avec leur manifeste, les tests avec la source qu'ils nomment - ordonne les groupes afin qu'un commit qui définit un symbole atterrisse avant le commit qui l'utilise et refuse l'ensemble du plan lorsque ce graphe de dépendances a un cycles. Il lit git diff HEAD plus la liste des fichiers non suivis et écrit rien : pas de git add -N, pas de git apply --cached, pas de git commit, donc mise en scène et engagement du séjour avec le shell ordinaire git add / git commit chemin où la porte d’approbation s’applique déjà. Merci @goransh-walia pour l'original implémentation (PR #5870, correctifs #3999).

Remarques

  • DeepSeek V4 Pro continue après le 14 septembre. Le fournisseur a annulé son préavis de départ à la retraite. Codewhale préserve les sélections Pro et les tarifs Pro ; deepseek-flash reste la valeur par défaut pour les nouvelles configurations DeepSeek directes.
  • Mise à niveau depuis 0.9.12 avec Computer Use trusted et activé : le Le hachage du contenu du bundle change avec l'actualisation 0.2.1, donc le plugin se désactive et demande une nouvelle révision - c'est le conçu chemin fermé en cas d'échec pour un plugin de pilotage de bureau. Re-trust du Page des plugins.
  • Le correctif de collage multiligne restaure le comportement de v9.11 sur les terminaux qui accepte EnableBracketedPaste mais livre les pâtes sous forme de frappes au clavier (rapporté sur Windows 11 / PowerShell). Vérifié à l'entrée-contrat niveau et en CI ; une vérification de collage manuelle sur un vrai terminal Windows est toujours le bienvenu — veuillez commenter #5981 avec votre terminal si quelque chose se comporte toujours mal.
