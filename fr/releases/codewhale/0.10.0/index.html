Baleine Code v0.10.0

Codewhale est le produit public de Shannon Labs. Le codewhale Les noms des commandes, des packages npm et des actifs de version restent techniques en minuscules identifiants. L'ancien package npm deepseek-tui est obsolète et ne reçoit aucune autre version. Utilisateurs provenant de l'héritage v0.8.x deepseek / Les noms deepseek-tui doivent migrer avec docs/REBRAND.md.

Installer

Recommandé — version officielle du GitHub

Nouvelle installation macOS/Linux (binaires avec somme de contrôle de cette version) :

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.0" sh
"$HOME/.local/bin/codewhale" --version

Pour Windows, utilisez le programme d'installation ou l'archive correspondant ci-dessous. Pour un existant installation directe, exécutez codewhale update ; il imprime le chemin de l'exécutable et conserve les versions plus récentes. Si le répertoire d'installation est occupé par une autre build, utilisez la migration d'un nouveau répertoire dans [le guide d'installation] (https://github.com/Hmbown/CodeWhale/blob/main/docs/INSTALL.md).

Emballage secondaire — npm et Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

Le wrapper télécharge les ressources de commande codewhale et codew correspondantes de cette version. Les deux contiennent le même runtime compilé.

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \

L'image expose le même runtime que codewhale et codew. Le La balise latest est également mise à jour lors de la sortie.

Cargaison (Linux / macOS)

cargo install codewhale-cli --locked

Le package Cargo installe codewhale. Cargo ne peut pas créer de deuxième commande alias d'une cible binaire ; les utilisateurs qui souhaitent une orthographe plus courte peuvent ajouter un Lien symbolique codew vers cet exécutable installé. Le npm, Homebrew, archive, Shell-installer et les canaux de conteneur installent directement les deux noms de commande.

Sécurité

  • Les enfants n'héritent jamais d'outils de bureau ou de contrôle informatique. Le contrôle du bureau est la capacité la plus étendue à l'ensemble de la machine du catalogue et un enfant vérificateur en a hérité par défaut : le 17/09/2026, on a ouvert le terminal hôte et on a tapé une commande shell bloquée dans la session en direct de l'utilisateur. Un classificateur familial maintenant supprime ces outils lors de la création du registre d'un enfant, ils ne sont donc ni désireux ni consultable, et execute_full refuse la famille lors de l'expédition pour chaque rôle d'enfant - la visibilité est une subvention, et se cacher n'est pas la seule défense (#6296).

  • Les environnements d'exécution peuvent être limités à la liste autorisée des plugins d'une organisation. Une politique maîtrisée document (managed-policy.json à côté de state.json, ou CODEWHALE_MANAGED_POLICY_PATH) répertorie les identifiants de plugin qu'un Runtime peut exécuter, avec un indicateur allow_unlisted et une version de schéma vérifiée exactement comme PluginStateFile. L'application se trouve à l'intérieur de apply_state, donc un plugin activé avant l'arrivée de la politique - ou modifié manuellement dans enabled: true - ne revient jamais activé, et enable() relit le document donc une politique l'atterrissage après découverte refuse avec une raison qui le nomme. Un malformé le document échoue fermé plutôt que de se dégrader et de devenir non appliqué. Sans politique Aujourd’hui, le comportement est petit à petit ce qu’il était. C'est l'application primitif seulement; l'autorité qui décide de la liste blanche est toujours locale, il lie donc un Runtime coopérant, pas hostile.

  • L'approbation d'un apply_patch "pour la session" est désormais limitée au fichier que vous approuvé. La clé de regroupement qui étend l'attribution d'une session a été créée par un second, analyseur de correctifs plus faible qui lit uniquement les en-têtes +++ b/ et le tableau replace : il n'a vu aucune cible pour le apply_patch{path, patch} documenté remplacement, pour les différences --no-prefix, ou pour les différences avec suppression uniquement, et réduit chacun d’entre eux sur une seule clé partagée. Un agrément donc pré-approuvé chaque patch ultérieur de cette forme, dans n'importe quel fichier, sans carte ni avis. Le la clé provient désormais du même résolveur que l'exécuteur et le chemin d'autorisation déjà utilisé, et une entrée qui ne peut pas être résolue obtient sa propre clé à la place qu'un partagé (#6247).

NewTaskRequest, TaskRecord et TaskSummary transporte un name en option, stocké comme indiqué et omis lorsque absent, donc les files d'attente reviennent toujours aux titres dérivés des invites ; une course commencée par une automatisation hérite du nom de l'automatisation. Le schéma de l'outil tasks s'étend de manière rétrocompatible et les enregistrements hérités sont décodés via les valeurs par défaut de Serde (APPS-153).

Les appels imbriqués doivent être en lecture seule et approuvés automatiquement ; le L'outil est masqué dans Plan et refusé sous l'autorité du travailleur. Activer avec [features] code_mode.

  • Les compétences sont accessibles en un seul appel. L'index épinglé ## Skills indiquait au modèle appeler load_skill, mais l'outil a été reporté derrière tool_search, donc il n'a jamais été dans le tableau d'outils à côté duquel l'instruction était imprimée : en utilisant un la compétence coûte un saut de découverte, un aller-retour name="list" et un change:tool_surface réépingle tout le préfixe mis en cache. load_skill est maintenant désireux du parent et des enfants — +244B de catalogue épinglé, mesuré, contre un re-pré-remplissage évité à chaque fois qu'une compétence est utilisée - et cela prend un query qui recherche des noms et des descriptions, donc un index tronqué n'est plus oblige à extraire tout le catalogue pour trouver une compétence. La ligne d'utilisation indique maintenant pour charger la compétence correspondante par son nom avant de commencer le travail.

  • Une voie rapide que le routeur ne peut pas desservir le dit désormais. provider_router_candidates répond cheap: None pour toute paire ses tables ne connaissent pas, et un L'enfant Faster/Auto sur une telle paire courait sur le modèle du parent et prix sans reçu et aucun moyen de distinguer "un niveau unique par conception" de mauvaise configuration. La solution de repli reste — le routeur ne doit pas inventer de modèle — mais le reçu d'apparition porte désormais un fallback_note nommant la voie non desservie, le même champ que la solution de secours du fournisseur épinglé utilise déjà. Inherit et les voies desservies restent tranquilles : cela signale un repli, cela ne harcèle pas.

  • Le runtime API raconte une soumission rejouée en dehors d'une nouvelle admission : POST /v1/threads/{id}/turns répond à 200 avec idempotent_replay: true lorsque la touche d'opération était déjà utilisée, et 201 pour une nouvelle admission, donc un client qui réessaye après une réponse abandonnée ne peut plus en créer une seconde tourner. Le drapeau est absent sur une nouvelle admission, donc réponses existantes clients déjà analysés sont inchangés (# 76).

  • Les flux d'événements reprennent là où ils s'étaient arrêtés : les cadres de journal portent leur durable seq comme événement SSE id:, Last-Event-ID est honoré comme curseur lorsque aucun since_seq explicite n'est demandé et RuntimeCapabilities fait de la publicité event_stream_resume afin qu'un client puisse activer ses commandes de reconnexion sur le capacité au lieu de la découvrir à partir d’un identifiant manquant (#76).

  • Le TTFT et le débit de sortie moyen restent visibles dans le pied de page de travail compact lorsque l'espace le permet. /statusline les contrôle désormais séparément ; existant Les paramètres session_metrics fonctionnent toujours.

  • Le catalogue de codage actuel de StepFun comprend l'aperçu de l'étape 5, l'étape 3.7 Flash, Étape 3.5 Flash et sa version 2603, avec contrôles de raisonnement publiés et Tarifs par répartition. Le routage du plan Step existant reste basé sur un abonnement.

  • Les réponses read indiquent désormais toujours la taille en octets du fichier, le nombre de lignes et si la sortie a été tronquée et les pieds de page de troncature indiquent la taille totale à côté du décalage de continuation - donc la pagination dans un fichier volumineux est délibéré au lieu d’une surprise (#6283).

  • Les modifications de fichiers sont analysées avant l'écriture : Rust passe par syn::parse_file pour un line:column grammaticalement exact, et .toml / .json via les analyseurs déjà vendus. Une modification est refusée uniquement lorsque le fichier analysé avant et n'analyserait pas après — réparant un système déjà cassé Le fichier est la raison la plus courante de modifier la source, donc une casse préexistante et les nouveaux fichiers ne s'ouvrent pas. La vérification précède l'écriture, donc un rejet laisse le fichier reste intact et apply_patch ne peut pas s'appliquer à moitié (#6204, #6206, #6151).

  • Les fichiers Rust qui étaient déjà rustfmt-clean sont re-normalisés après une édition, donc les ancres du prochain patch correspondent toujours. Les fichiers formatés manuellement ne sont jamais réécrit, et chaque chemin d'échec saute et laisse l'édition atterrir (#6205, #6151).

  • Les clients natifs peuvent terminer la configuration du fournisseur sans passer au CLI : DELETE /v1/providers/{id}/key efface un identifiant appartenant à Codewhale via le même propriétaire commun que codewhale auth clear et GET /v1/providers porte désormais credentialSource / credentialWritable (plus une raison), donc un client désactive son contrôle avec une explication véridique au lieu de laisser un échec d'écriture en retard. Un identifiant que Codewhale ne possède pas - une clé littérale dans un fichier de configuration, ou un consentement externe actif — refuse les deux verbes avec 409 plutôt que de donner l'impression de réussir contre une source qui gagne quand même heure de la demande (#6179).

Omis ou 0 conservé l'attente illimitée d'aujourd'hui, donc rien ne change à moins que vous ne vous y inscriviez (#6101).

  • La sélection par glisser-transcription copie la source Markdown par défaut : chaque cellule la sélection touche les sérialisations via le même chemin canonique Ctrl-Y et Utilisation de /copy, jointe à des lignes vides, et le toast nomme la cellule copiée compter. Une sélection qui ne couvre pas toutes les cellules touchées, des copies de bout en bout à la place, le fragment exact rendu : arrondir une sélection précise à des cellules entières signifiaient copier un message modèle entier (#6228). tui.selection_copy_markdown = false conserve la charge utile du texte rendu (#6156).

  • Le Runtime API sert les fichiers de l'espace de travail qu'un client natif parcourt et édite : GET /v1/workspace/files répertorie un répertoire, GET /v1/workspace/files/read renvoie une fenêtre d'octets délimitée avec une révision SHA-256 du fichier entier, et PUT /v1/workspace/files écrit atomiquement à travers l'ouvreur confiné avec écrasements vérifiés par révision (409 sur dérive). .git n'est jamais servi et les liens symboliques ne sont jamais suivis. Les sorties d'outils surdimensionnées d'une session enregistrée sont servi d'artefacts à GET /v1/sessions/{id}/artifacts et GET /v1/sessions/{id}/artifacts/{artifact_id}. (#6163)

Les courses sans tête ne tiraient auparavant aucun crochet. tool_call_before vous pouvez toujours refuser et shell_env s'applique toujours ; un crochet ask résout fermé sans terminal. Les sous-processus des travailleurs de la flotte ne s'engagent jamais, et Les règles typées permissions.toml sont inchangées (#6099).

Une épingle n'est signalée que lorsqu'un nouveau live mis en cache la liste pour cet itinéraire exact existe et l'omet - obsolète, échouée ou absente les rosters ne prouvent rien et sont comptés comme unverifiable plutôt que de lever un faux avertissement. Modifié

  • Les résultats SearXNG sont classés en fonction du score renvoyé par l'instance plutôt que par arrivée commande. Les entiers, les flottants et les chaînes numériques sont acceptés ; autre chose, incluant NaN et l'infini, devient 0.0 et les lignes sont triées de manière stable et décroissante avant le plafond de résultats, donc des scores égaux maintiennent l'ordre des instances. Les documents épellent maintenant l'exigence d'auto-hébergement : le processus distinct doit exposer search.formats: [json] — une instance HTML uniquement répond à 403 — et se lie à bouclage ou un hôte autorisé par la politique, sans aucune instance par défaut découverte.

  • Les compétences regroupées passent à une nouvelle génération. les médias sociaux et la santé quittent le pack expédié (flux de travail d'exportation par téléphone plutôt que compétences quotidiennes), commentaires passe à docs/skills/ à côté de l'intégration des contributeurs, et exactement plus tôt le corps est conservé, donc seule la mise à niveau des compétences expédiées non modifiées – une compétence que vous possédez édité est laissé en place. Scopes Google OAuth et configuration de client, exportations de photos, oubli des limites, les conseils de lecture Spotify et de rechargement du plugin ont été corrigés dans le même passage.

  • auto est une valeur par défaut déclarée, et non une supposition sur votre formulation. Raisonnement l'effort ne mappe plus le vocabulaire de la requête aux niveaux (débogage/erreur sur Max, recherche à Low) et le routage automatique ne déduit plus le bon marché par rapport au gros à partir de la formulation : les deux résolvent la valeur par défaut configurée, avec [auto] cost_saving comme opt-in explicite. La même invite coûte désormais deux fois la même chose.

  • Le budget de jetons partagé d'un workflow est opt-in. [workflow] default_token_budget appliqué un plafond silencieux de 120 000 jetons à une exécution et à tous ses enfants, et une distribution est morte à la limite sans retour ; la valeur par défaut est maintenant 0, ce qui signifie pas de plafond partagé.

  • La route deepseek-flash expédiée parle du point de terminaison des réponses et xhigh l'effort correspond à high selon la table du fournisseur.

  • Le texte diffusé est rythmé à un rythme constant plutôt que d'hériter du rythme du fournisseur. Segmentation SSE, de sorte que la sortie s'affiche à un rythme lisible plutôt qu'en rafales.

  • L'élargissement de l'accès au shell pour une conversation nécessite désormais une conversation inactive et rejette une vérification d'espace de travail obsolète avant sa validation. Les moteurs annoncent un Capacité thread_shell_consent, de sorte qu'un moteur plus ancien se lit comme non pris en charge pour un consentement natif client au lieu d'accepter silencieusement.

  • Appuyez deux fois sur Entrée pour envoyer désormais chaque suivi en file d'attente dans le tour en cours, le plus ancien en premier. La deuxième Entrée permet de piloter uniquement le message le plus récent et laissez les plus âgés faire la queue ; un échec de direction restaure le message d'échec plus tout ce qui n'a pas été tenté dans l'ordre d'origine, donc rien n'est perdu ou réorganisé.

  • Seule l'invite envoyée la plus récemment comporte l'arrière-plan de la surface surélevée maintenant ; chaque invite plus ancienne s'affiche sur le sol nu. Le remplissage utilisé pour s'asseoir derrière chaque ligne utilisateur (striping), puis derrière aucune ; le plus récent conserve uniquement le oeil sur le tour de jeu. L'envoi d'une nouvelle invite déplace la surbrillance et ne met pas en avant son prédécesseur.

  • Les lignes différentes sont entièrement teintées : les numéros de ligne ajoutés/supprimés partagent désormais le vert de la ligne. / fond rouge au lieu d'être assis nu à côté d'un corps peint. Contexte les rangées restent sur le sol nu.

  • Les connexions MCP sont désormais supervisées : une tâche en arrière-plan remarque un mort serveur en un seul balayage, se reconnecte sur l'échelle d'attente existante et signale chaque transition, de sorte que les lignes d'extensions s'inversent avec vivacité à la place de stationnement sur un véhicule rassis ou silencieux [reconnexion]. Cinq consécutifs les échecs garent le serveur avec un avis nommé /mcp retry ; un explicite réessayez ou une nouvelle connexion reprend le visionnage. Les appels d'outils réessayent également une fois sur un tuyau/socket mort (pas seulement des sessions obsolètes), et un la reconnexion qui échoue signale les deux erreurs au lieu d'avaler le original (#6187 ; l'actualisation du catalogue list_changed reste ouverte).

  • Un directeur dont le moteur n'a jamais été livré n'est plus signalé comme envoyé. Le temps d'exécution API a conservé l'élément de direction comme déjà Completed et a émis turn.steered + item.completed au moment où le texte est entré dans le moteur boîte aux lettres - avant que le moteur ne décide quoi que ce soit. Le moteur rejette une direction dont le tour est passé, et un tour interrompu ou raté laisse tomber quoi que ce soit était en file d'attente, donc une interface graphique pouvait afficher "Conseils envoyés", effacer le compositeur et perdre les mots de l'utilisateur. Le moteur renvoie désormais un verdict pour chaque direction sur chaque chemin de sortie, l'élément règle completed ou canceled pour correspondre, un drop le direction émet turn.steer_dropped et répond à 409 afin qu'un client puisse renvoyer, et steer_count compte les bouvillons du modèle réellement reçu (#6276).

  • Les suggestions <recommended_plugins> cessent de harceler : un identifiant de plugin est maintenant injecté au plus une fois par durée de vie du moteur, et un plugin dont le nom la compétence chargée couvre déjà n'est jamais suggérée - la compétence locale possède le domaine, donc le coup de pouce était du bruit. Les licenciements s'appliquent toujours, et le le fragment reste en ajout uniquement au tour de l'utilisateur (# 6274).

  • Une exécution d'automatisation annulée est désormais réglée avec un reçu de transcription qui nomme l'annulation (par demande, annulation du délai d'attente ou arrêt) au lieu de disparaissant silencieusement du groupe live. Le reçu porte de l'encre d'attention et n'allume jamais la demande d'échec ; le dossier d'exécution conserve l'annulation raison comme détail de l'erreur. (#6162)

  • Une exécution de workflow échouée ne s'installe plus silencieusement : son échec terminal déclenche un toast d'erreur persistant en nommant la cause (répartition, schéma ou script) erreurs), aux côtés de l’état du panneau existant (#5528).

  • La reconnexion à MCP OAuth force désormais l'écran de consentement du fournisseur : déconnexion uniquement efface le jeton local, donc sans invite, le fournisseur silencieusement j'ai réattribué le même compte/espace de travail et une reconnexion ne pourrait jamais changer ça. /mcp logout et codewhale mcp logout indiquent également clairement qu'ils effacer les informations d'identification locales uniquement (#6040).

  • La rétention de session ne supprime plus les transcriptions une fois que le magasin atteint le cap : la session active la plus ancienne est archivée — toujours ouvrable depuis le vue archivée du sélecteur - au lieu d'être dissociée, et les enregistrements archivés asseyez-vous à l’extérieur du capuchon jusqu’à ce qu’ils soient taillés (#6136).

  • Les talons "Nouvelle session" vides créés automatiquement sont plafonnés séparément (les dix les plus récents sont conservés) et ne peuvent plus occuper un véritable emplacement de relevé de notes dans le casquette de session (#6137).

  • Un échec de reprise ou de chargement de session est désormais une erreur de transcription durable d'une ligne d'état que la prochaine mise à jour du pied de page remplace, donc un CV qui ne peut pas restaurer sa cible ne ressemble plus à une nouvelle session silencieuse (#6138).

  • Le compactage ne conserve plus un résultat d'outil dont l'appel d'outil a été résumé loin : un tour plus ancien qui mélange du texte avec un résultat d'outil conserve son texte et supprime les blocs de résultats orphelins, que les fournisseurs rejettent catégoriquement (#6119).

  • Les exécutions d'automatisation qui nécessitent l'approbation d'un outil ne sont plus aussi silencieuses annulation du délai d'inactivité : une approbation en attente suspend le chien de garde inactif pour son fenêtre de décision, et une fenêtre sans réponse règle l'exécution. Échec avec le motif enregistré au lieu d'un Annulé silencieux (#6118).

  • /mcp ne fige plus la console pendant qu'un tour est en cours : le panel s'ouvre immédiatement à partir du dernier instantané MCP connu avec un nom de reçu l'attente, et les mutations live-pool indiquent que leur actualisation est différée au lieu de garer la boucle d'événements de l'interface utilisateur derrière le tour en cours (# 6159).

  • La connexion MCP OAuth n'échoue plus avec « Réponse du serveur d'autorisation manquante émetteur requis" par rapport aux serveurs qui implémentent la RFC 9207, tels que Le mcp.cloudflare.com de Cloudflare. L'écouteur de rappel local conserve désormais le iss de la redirection et le transmet à l'échange de jetons afin que le le rappel est lié à l'émetteur découvert ; serveurs qui n'envoient pas de iss continuez à travailler sans changement. (#6157)
