Firecrawl v2.10

Firecrawl v2.10

Améliorations

  • Point de terminaison /parse — Téléchargez des fichiers locaux (PDF, DOCX, DOC, ODT, RTF, XLSX, XLS, HTML) jusqu'à 50 Mo et récupérez du Markdown, JSON ou un résumé propre et prêt pour LLM. Les tableaux et l’ordre de lecture sont préservés, avec une prise en charge complète de Zero Data Retention pour les forfaits d’entreprise. Disponible en JS, Python, Go, Rust, Java, .NET, PHP, Ruby et Elixir SDK.
  • Mode de verrouillage — Définissez lockdown: true sur /scrape pour qu'il diffuse exclusivement les résultats de l'index de Firecrawl avec zéro requête sortante et zéro rétention de données par défaut. Les chemins sortants sécurisés incluent les récupérations HTTP, les robots.txt, les téléchargements audio et les médias. Disponible dans tous les SDK, CLI (--lockdown) et MCP.
  • Format question — Transmettez une invite en langage naturel à /scrape et obtenez une réponse fondée et sans hallucination dans data.question. Fonctionne sur une chaîne de modèles gérés avec repli automatique, isolation par injection rapide via le balisage XML et escaping sans espace de largeur, et jusqu'à 100 fois moins de jetons par appel.
  • Format highlights — Renvoie les phrases exactes, les blocs de code et les lignes de tableau d'une page qui correspondent à votre requête. Les phrases consécutives sont regroupées en paragraphes, les lignes de code sont enroulées dans des blocs clôturés avec leur langue d'origine et les lignes du tableau sont reconstruites en tableaux Markdown avec des en-têtes, le tout à partir de la page source, en utilisant jusqu'à 100 fois moins de jetons par appel.
  • Format video — Ajout de video pour gratter les formats. Renvoie une URL de vidéo téléchargeable signée pour les sites pris en charge (par exemple YouTube), avec transfert de cookies pour les téléchargements authentifiés et verrouillage explicite.
  • Filtres de domaine /search — Ajout des paramètres includeDomains et excludeDomains à /search pour étendre les résultats à un ensemble spécifique de sites.
  • Point de terminaison de commentaires /search — Soumettez une note sur un résultat de recherche avec POST /v2/search/:jobId/feedback. Chaque soumission acceptée rembourse 1 crédit, plafonné par jour UTC, avec des tentatives idempotentes.
  • Agent utilisateur robots.txt personnalisé — Ajout de robotsUserAgent pour analyser les requêtes afin d'évaluer les règles robots.txt et les délais d'analyse par rapport à une chaîne d'agent personnalisée, ainsi qu'un indicateur d'organisation customRobotsAgent distinct indépendant de ignoreRobots. Disponible en JS, Python et Java SDK.
  • Official Go SDK — Ajout d'un Go SDK propriétaire pour le API v2, remplaçant le module communautaire. Inclut une interruption des nouvelles tentatives contextuelles et une saisie MapData.Links appropriée.
  • Ruby SDK — Ajout du Firecrawl Ruby SDK v2 officiel avec une couverture complète des points de terminaison et un typage natif v2.
  • PHP SDK — Ajout du PHP SDK officiel avec prise en charge de Laravel, couverture scrape/search/crawl/map/parse et publication d'un package firecrawl/firecrawl-sdk Composer.
  • .NET SDK — Ajout du .NET SDK officiel avec la prise en charge de la v2 API, l'analyse et un package NuGet firecrawl-sdk.
  • Rust SDK v2 — Le Rust SDK a été promu au rang de SDK v2 officiel avec parité en matière de scrape, de recherche, d'exploration, de cartographie, d'agent et d'analyse.
  • Suggestion /interact — Les appels à /scrape qui transmettent un tableau actions renvoient désormais un avertissement suggérant /interact pour l'automatisation du navigateur avec état.
  • Taille maximale du PDF — Augmentation de la taille limite de téléchargement des PDF de 10 Mo à 30 Mo.
  • Facturation PDF traitée par page — Facturation PDF mise à jour pour refléter les pages traitées au lieu du nombre de pages brutes.
  • Faisceau Docker — HARNESS_STARTUP_TIMEOUT_MS exposé à docker-compose pour les utilisateurs auto-hébergés qui ont besoin de fenêtres de démarrage plus longues.
  • Elixir SDK — Ajout de parse_file/3 à l'Elixir SDK pour le point de terminaison /parse.
  • Délai d'expiration de la demande JS SDK — Ajout d'une option de délai d'expiration de la demande explicite au JS SDK pour éviter les demandes suspendues.

Correctifs

  • Résolution de plusieurs CVE sur les API et SDK, notamment axios, postcss, fast-xml-parser, protobufjs, follow-redirects, langsmith, lodash, fast-uri et fast-xml-builder.
  • Correction du marquage colors.secondary qui était incorrectement renseigné lorsque le LLM omis une valeur — secondary est désormais facultatif et n'est plus appliqué par défaut.
  • Correction du service Playwright ignorant l'en-tête de requête User-Agent de l'appelant.
  • Correction des URL signées screenshot renvoyant des résultats périmés du cache en forçant un échec du cache lorsque l'URL signée a expiré.
  • Correction des demandes de verrouillage facturées deux fois pour ZDR en traitant le verrouillage comme une rétention de données nulle par défaut.
  • Correction de la facturation proxy pour les scrapes mises en cache, facturant incorrectement les crédits proxy lorsqu'aucune sortie proxy ne s'est produite.
  • Correction des scripts de transcription YouTube exécutés sur des extraits audio uniquement et des téléchargements audio ne recevant pas de cookies CDP.
  • Correction du service de conversion html-to-md ignorant la rétention de données nulle.
  • Correction d'un débordement de pile dans marked.parse lors de la gestion de certaines sorties PDF.
  • Correction de robotsUserAgent n'étant pas honoré par le filtre de lien natif et n'étant pas inclus dans les charges utiles d'analyse JS SDK.
  • Correction des points de terminaison d'état /v1 renvoyant 500 sur les ID de travail non UUID - renvoie désormais un 400 approprié.
  • Correction des tableaux actions: [] vides traités comme des actions dans les indicateurs de fonctionnalité.
  • Correction de l'observateur JS SDK émettant des événements en double, des fuites de délais d'attente et du blocage de start() lors des délais d'attente de l'observateur.
  • Correction du déballage Ruby SDK des champs de données credit_usage et de la valeur par défaut de skipTlsVerification sur false.
  • Correction de la validation de limite négative manquante dans les Python, Java et Go SDK.
  • Correction de Java SDK acceptant les clés API vides et les méthodes de cycle de vie asynchrone manquantes.
  • Correction des horodatages des périodes de facturation, des recherches d'abonnement et des rapports de crédit du plan.
  • Correction des délais d'attente du crawl-backlog étant illimités - désormais plafonnés à 48h.

##API

  • Ajout de POST /v2/parse pour les téléchargements de fichiers en plusieurs parties jusqu'à 50 Mo. Renvoie un document standard. Options de scrape non autorisées lors de l'analyse : changeTracking, screenshot, branding, actions, waitFor, location, mobile ; proxy est limité à auto ou basic. Erreurs avec PARSE_UNSUPPORTED_OPTIONS sur une entrée non autorisée.
  • Ajout de lockdown: boolean à /scrape. Le cache manque de renvoyer 404 avec SCRAPE_LOCKDOWN_CACHE_MISS. Facturation : +4 crédits lorsque lockdown est activé, 1 crédit en cas de manque de cache. Disponible sur tous les SDK.
  • Ajout des formats question et highlights aux formats /scrape, renvoyant respectivement data.question et data.highlights.
  • Ajout des formats video aux formats /scrape. Renvoie document.video sous forme d'URL signée. +4 crédits par demande. Les URL non prises en charge génèrent SCRAPE_VIDEO_UNSUPPORTED_URL ; parse rejette le format video cli côté ent et côté serveur.
  • Ajout des tableaux includeDomains et excludeDomains sur /v2/search pour étendre les résultats à des domaines spécifiques.
  • Ajout de POST /v2/search/:jobId/feedback pour les résultats de recherche d'évaluation. Chaque soumission acceptée rembourse 1 crédit, plafonné par jour UTC via SEARCH_FEEDBACK_DAILY_CAP_CREDITS, avec des tentatives idempotentes renvoyant alreadySubmitted: true. Les soumissions de commentaires antérieures à SEARCH_FEEDBACK_MAX_AGE_SEC (120 s par défaut) sont rejetées. La facturation des recherches s'effectue désormais en crédits ceil(results/10) * 2, comme l'indiquent les réponses.
  • Ajout de robotsUserAgent à /v2/crawl crawlerOptions pour l'évaluation robots.txt de l'agent personnalisé. Fermé derrière le drapeau de l'organisation ignoreRobots.
  • Ajout d'un indicateur d'organisation customRobotsAgent distinct, indépendant de ignoreRobots, afin que les équipes puissent expédier des agents utilisateurs personnalisés sans désactiver l'application du fichier robots.txt.
  • Migration du drapeau d'organisation ignoreRobots d'un booléen vers un modèle disabled / allowed / forced. L'ancienne forme de requête ignoreRobots: boolean a été supprimée : clients doit utiliser les nouvelles valeurs d'indicateur.
  • /v0/scrape, /v0/crawl, /v0/crawl/status/:jobId, DELETE /v0/crawl/cancel/:jobId, /v0/search, /v1/extract, /v1/extract/:jobId, /v2/extract, /v2/extract/:jobId, /v1/deep-research, /v1/deep-research/:jobId, /v1/llmstxt et /v1/llmstxt/:jobId sont obsolètes. Les points de terminaison obsolètes émettent des en-têtes Deprecation: true, Warning: 299 - "<message>", Link; rel="successor-version" et (si configurés) Sunset, plus warnings[] et replacement dans le corps JSON. JS et Python SDK les transmettent aux clients.
