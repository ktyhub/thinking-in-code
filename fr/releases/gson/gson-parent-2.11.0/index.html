gson gson-parent-2.11.0

Changements les plus importants

  • Ajout des règles ProGuard / R8 par défaut (@Marcono1234, #2397, #2420; @sgjesse, #2448; @sfreilich)
    Si vous utilisez ProGuard ou R8 (par exemple pour les projets Android), vous n'aurez peut-être plus besoin d'une configuration Gson spéciale si vos classes ont un constructeur sans argument et utilisent @SerializedName pour leurs champs.
  • Sur Android, Gson nécessite désormais API niveau 21 ou plus récent
  • Ajout du nouveau Strictness API (@marten-voorberg et camarades étudiants, #2437)
    Certains API de Gson sont toujours indulgents par défaut, mais vous pouvez désormais utiliser les méthodes nouvellement ajoutées GsonBuilder#setStrictness, JsonReader#setStrictness et JsonWriter#setStrictness avec Strictness.STRICT pour remplacer ce comportement et adhérer strictement à la spécification JSON lors de l'analyse.
  • Nouvelle classe FormattingStyle pour permettre la configuration des sauts de ligne dans la sortie JSON (@mihnita, #2231)
    Peut être réglé à l’aide de GsonBuilder#setFormattingStyle et JsonWriter#setFormattingStyle.
  • TypeToken ne peut plus capturer les variables de type par défaut (@Marcono1234, #2376)
    C’était auparavant une source courante de problèmes. L'exception nouvellement levée fait référence à un [article du Guide de dépannage] (https://github.com/google/gson/blob/main/Troubleshooting.md#typetoken-type-variable) qui explique cela plus en détail et fournit des suggestions pour mettre à jour le code concerné.
  • Ajout du support de sérialisation pour les classes anonymes et locales avec un adaptateur personnalisé (@Marcono1234, #2498)
    Cela affecte par exemple les implémentations de List renvoyées par des bibliothèques telles que Guava qui sont implémentées en tant que classe anonyme, qui étaient auparavant sérialisées sous le nom de null. Les classes anonymes et locales sans adaptateur personnalisé seront toujours sérialisées sous le nom null.
  • Ajout d'une dépendance sur com.google.errorprone:error_prone_annotations
    Votre projet peut utiliser les exclusions de dépendances Maven ou Gradle pour supprimer la dépendance transitive error_prone_annotations de Gson. Ou si vous gérez manuellement les dépendances sous forme de fichiers JAR dans votre projet, vous pouvez omettre error_prone_annotations. Et cela devrait toujours fonctionner correctement.
    Mais Gson lui-même le déclare comme dépendance obligatoire, et si vous n'effectuez aucune configuration personnalisée, Maven ou Gradle essaieront par défaut de le télécharger et de l'utiliser.
  • De nombreux messages d'exception font désormais référence au [Guide de dépannage] (https://github.com/google/gson/blob/main/Troubleshooting.md) (@Marcono1234, #2357)
    Les commentaires concernant le guide de dépannage sont appréciés !
  • Il est officiellement documenté que les langages JVM autres que Java peuvent ne pas être entièrement pris en charge, voir le README.
  • Garantissez que JsonElement#toString produit une sortie JSON (@Marcono1234, #2659)

Autres changements

Corrections de bugs

  • Correction des résultats JsonPrimitive#equals incorrects pour les grandes valeurs BigInteger (@MaicolAntali, #2311)
  • Correction des résultats JsonPrimitive#equals incorrects pour les grandes valeurs BigDecimal (@MaicolAntali, #2364)
  • Correction de JsonReader lançant NumberFormatException au lieu de MalformedJsonException pour les séquences d'échappement Unicode mal formées (@MaicolAntali, #2337)
  • Correction de TypeToken#getParameterized renvoyant un faux ParameterizedType pour les types non génériques (@Marcono1234, #2447)
  • Correction de l'adaptateur d'enregistrement Java ne fonctionnant pas pour l'image native GraalVM (@eamonnmcmanus, #2465)
  • Correction de JsonWriter#name ne lançant pas d'exception lorsqu'aucun objet JSON n'est en cours d'écriture (@shivam-sehgal, #2475; @Marcono1234, #2476)
  • Correction de Gson#getDelegateAdapter ne fonctionnant pas correctement pour @JsonAdapter (@Marcono1234, #2435)
    Notez que null n'est désormais plus autorisé en tant que valeur skipPast, ce qui était auparavant autorisé mais non documenté.
  • Correction de GsonBuilder ne rejetant pas les adaptateurs de type pour Object et JsonElement, dont les adaptateurs par défaut ne peuvent pas être remplacés (@sachinp97; #2479)
  • Correction d'aucune limite appliquée lors de la désérialisation de BigDecimal et BigInteger (@Marcono1234, #2510)
    Les nouvelles limites évitent les problèmes de performances potentiels lorsque le code utilisateur utilise les numéros désérialisés. Gson lui-même n'a pas été et n'est pas affecté par ces problèmes de performances. Les limites doivent être suffisamment élevées pour ne pas poser de problèmes dans la plupart des cas d'utilisation, mais les commentaires sont appréciés.
  • Correction de GsonBuilder#setDateFormat ne rejetant pas les formats de date invalides (@Carpe-Wang, #2538)
  • Correction de GsonBuilder#setDateFormat ne rejetant pas les styles de date invalides (@Marcono1234, #2545)
  • Correction de GsonBuilder#setDateFormat ignorant partiellement le style DEFAULT (@Marcono1234, #2556)
  • Correction de TypeToken#isAssignableFrom lançant AssertionError dans certains cas (@Marcono1234, #2544)
  • Les adaptateurs de date fixe ne restaurent pas le fuseau horaire après l'analyse (@Carpe-Wang, #2549)
  • Correction de TypeToken#equals renvoyant par erreur false pour des paramètres de type générique égaux dans certains cas (@d-william, #2599)
  • Correction des URL héritées incorrectes dans pom.xml (@Marcono1234, #2351)

Améliorations des performances

  • Réduisez légèrement l'utilisation de la mémoire pour l'adaptateur basé sur la réflexion (@sembseth, #2325; @Marcono1234, #2440)
  • Vitesse d'analyse améliorée de ToNumberPolicy#LONG_OR_DOUBLE (@ctasada, #2674)

Maintenance Gson

  • Modification de nombreux tests unitaires pour utiliser Truth au lieu de JUnit pour les assertions (@MaicolAntali, #2299, #2304)
  • Configuration d'Error Prone pour vérifier automatiquement les bugs lors de la compilation (@MaicolAntali, #2308)
  • Gestion simplifiée des exceptions attendues dans les tests (@elevne, #2454)
  • Ajout d'un test d'intégration pour l'image native GraalVM (@Marcono1234, #2466)
  • Formaté le code selon le Google Style Guide et configuré Spotless (@MaicolAntali, #2531, #2537)
  • Rendre la version Maven reproductible (@Marcono1234, #2543)
  • Suppression de la classe interne DateTypeAdapter pour réduire la duplication de code (@Marcono1234, #2546)
  • Dépendances et plugins mis à jour par Dependabot

Dépôt GitHub

  • Branche par défaut renommée de master à main
  • Discussions GitHub ont été activées
    Pour des questions, des idées, des conseils...
  • Ajout du modèle de demande d'extraction GitHub (@Marcono1234, #2326)
  • Ajout d'une vérification de la compatibilité Android API (@Marcono1234, #2431)

Autre

  • Ajout de @CanIgnoreReturnValue selon les besoins aux méthodes Gson (@eamonnmcmanus, #2369)
    Ceci est utile si vous activez le CheckReturnValue d'Error Prone dans votre projet lors de la compilation, cependant Gson lui-même ne l'active pas par défaut.
  • Diverses améliorations de la documentation et des tests et corrections de fautes de frappe (@False-Mask; @avimathur009; @elevne; @0o001; @Codegass; @33nya)

Un grand merci à @Marcono1234 pour la rédaction de ces release note.
