hypit v0.2.6

Synchronisation des sous-titres, tolérance multiplex et images Wan 2.7

Cette version corrige deux défauts qui ont rejeté ou gâché la sortie correcte, ajoute les modèles d'image Wan 2.7 et rend les exemples de profil d'exécution dans les fichiers README copiables.

Durée des sous-titres

Un aligneur signale que chaque mot se termine là où le suivant commence, et tokenFrameSpan a conservé le cadre dans lequel tombe l'instant, de sorte que les fenêtres Word adjacentes se chevauchent par un cadre. Les limites des repères héritées se chevauchent, et un moteur de rendu qui dessine des repères à une seule position en a dessiné deux sur la même image. Les sous-titres chinois se chevauchaient à presque chaque transition.

exclusiveActivationFrames dans @hypit/caption-fine énonçait déjà la règle pour les atomes : dès que la prochaine unité créée démarre, la précédente s'arrête. Il est désormais appliqué une seule fois là où les timings des unités sont construits, de sorte que les limites exclusives des Cue suivent l'enveloppe du Cue se terminant à sa dernière unité. La chronologie conserve les mesures brutes des jetons. (#300, #297)

Assertion finale du multiplexeur

Le WAV mis en scène est affirmé à l'échantillon près avant le multiplexeur, donc l'assertion finale concerne ce qui survit à l'AAC. AAC ne peut pas transporter un nombre d'échantillons arbitraire : l'encodeur émet des trames de 1 024 échantillons et signale un retard d'amorçage que le multiplexeur MP4 compense avec une liste d'édition, de sorte que l'étendue présentée atterrit à quelques échantillons de l'entrée. Mesurés sur un ton synthétique, 4 249 600 échantillons présentaient 4 249 584 et 4 236 800 présentaient 4 236 768. Le fait de remplir la chronologie d'un nombre entier d'images AAC ne la supprime pas.

Exiger une égalité exacte a donc rejeté tout multiplexeur correct dont la longueur n'est pas un point fixe de cet aller-retour, échouant un deuxième rendu 88.5 à sa dernière étape avec tout le matériel généré déjà payé. L'assertion tolère désormais le retard de l'encodeur. (#298, #296)

Modèles d'image Wan 2.7

@hypit/wan@1 propose deux modèles exacts, wan-2.7-image et wan-2.7-image-pro. Les deux acceptent une invite contenant jusqu'à 5 000 caractères, jusqu'à neuf images de référence et une bande 1K ou 2K ; la variante Pro ajoute 4K. count restitue jusqu'à quatre images, ou nomme le plafond d'un ensemble d'images comprenant jusqu'à douze, où le modèle choisit le nombre qu'il renvoie.

Le modèle ne prend aucun rapport hauteur/largeur : avec les références présentes, la sortie suit la dernière et une requête rapide uniquement est rendue au cadrage propre du groupe. Il lit les exclusions de l'invite plutôt que d'un champ d'invite négative.

@hypit/provider-monid sert les deux via les points de terminaison alibaba de Monid. Son chemin de résultat supposait auparavant une vidéo ; les routes nomment désormais leur type de résultat et la collection télécharge chaque fichier renvoyé, de sorte qu'un ensemble d'images arrive sous forme d'ensemble. Deux limites de service sont signalées avant qu'une référence ne soit résolue : 4K est restitué à partir d'une seule invite et une requête restitue au maximum quatre images en dehors d'un ensemble d'images. (#301)

Stockage des informations d'identification Windows

HypiHub OAuth stocke le JSON portant des jetons d'accès et d'actualisation JWT, et le PasswordVault de Windows Credential Locker rejette les mots de passe de plus de 512 caractères avec un échec d'écriture opaque une fois le flux du navigateur terminé. Le Store refuse désormais une telle écriture avant de générer PowerShell et nomme le fichier Store dans le message. (#294, #291)

###Documentations

  • Les exemples de profils d'exécution README du fournisseur sont des profils complets. Copiés dans hypit.runtime.json, ils échouaient auparavant dans auth status. (#289, #288)
  • L'exemple de profil d'exécution README HypiHub est un hypit.runtime.json valide : il manquait format, dataRoot et un magasin d'informations d'identification déclaré, et nommé magasin os tandis que runtime init écrit maintenant platform. (#295, #292)

Mise à jour

Pour une installation globale du CLI :

npm install -g @hypit/hypit@0.2.6
hypit --version

Pour une installation locale du projet :

npm install --save-exact @hypit/hypit@0.2.6
npm exec --no -- hypit --version

La compétence Hypit installée est mise à jour séparément via l'outil utilisé pour l'installer. Le format interne et les identifiants du module logique restent @1. La syntaxe du script est inchangée par rapport à 0.2.0. La mise à jour ne migre ni ne réécrit les projets vidéo enregistrés.
