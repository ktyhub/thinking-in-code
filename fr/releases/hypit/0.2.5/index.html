hypit v0.2.5

MiniMax H3 sur Monid

@hypit/provider-monid dessert désormais @hypit/minimax-h3@1#minimax-h3 via minimax /v1/video/minimax-h3 de Monid, aux côtés des quatre points de terminaison ByteDance Seedance déjà cartographiés. Le modèle dispose d'un troisième fournisseur de passerelle groupé à côté de HypiHub, HiAPI, Pollo et TokenDance. (#286)

H3 prend le même tableau ModelArk content étiqueté par rôle que les points de terminaison Seedance, nomme son modèle dans le corps et ne porte ni le champ generate_audio ni le champ web_search qu'ils prennent. Trois différences sont gérées au niveau de l'itinéraire :

  • resolution est requis par le point de terminaison alors que le port du modèle est facultatif, donc une requête indiquant aucun est envoyée à 2K, la résolution sélectionnée par le fournisseur HypiHub.
  • Le point final ne prend aucun rapport adaptive pour le texte sur vidéo, tandis que le mode image résout le cadrage de l'image téléchargée et les valeurs par défaut de référence à la vidéo en adaptatif. Une demande de texte vers vidéo ne portant pas de aspect-ratio est signalée comme non prise en charge avant que toute référence ne soit résolue ; les deux autres modes sont envoyés comme adaptive.
  • H3 renvoie sa vidéo au content.url plutôt qu'au ModelArk video_url.

Monid adresse un point de terminaison par fournisseur et chemin, de sorte que chaque mappage porte désormais le fournisseur qui le relaie au lieu de chaque exécution en supposant bytedance.

Le reste du catalogue de Monid ne contient aucun autre modèle décrit par cette distribution. Ses points de terminaison ElevenLabs sont basés sur l'identification vocale, tandis que @hypit/elevenlabs-speech@1#eleven_ttv_v3 est une conception vocale et nécessite une description vocale pour laquelle ils n'ont pas de champ, et les variantes H3 Fast, Max et Max Turbo déclarent différents modèles avec leurs propres domaines de valeurs.

Mise à jour

Pour une installation globale du CLI :

npm install -g @hypit/hypit@0.2.5
hypit --version

Pour une installation locale du projet :

npm install --save-exact @hypit/hypit@0.2.5
npm exec --no -- hypit --version

La compétence Hypit installée est mise à jour séparément via l'outil utilisé pour l'installer. Le format interne et les identifiants du module logique restent @1. La syntaxe du script est inchangée par rapport à 0.2.0. La mise à jour ne migre ni ne réécrit les projets vidéo enregistrés.
