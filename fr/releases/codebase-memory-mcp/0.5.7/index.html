codebase-memory-mcp v0.5.7

v0.5.7 — Révision des tests de stabilité, d'installation et d'endurance

53 commits, 3 PR fusionnés, 10 bugs résolus. La version de stabilité la plus importante depuis la réécriture Go→C.

Correctif de concurrence de base de données (critique)

  • Cause racine trouvée : trois threads (gestionnaire MCP, autoindex, observateur) pourraient corrompre la base de données — rename(.db.tmp, .db) sur des connexions SQLite ouvertes a produit plus de 48 000 lignes inutiles.
  • Changement d'architecture : rename() entièrement éliminé. L'indexation écrit directement, la réindexation supprime d'abord l'ancienne base de données, les upserts incrémentiels inchangés
  • Le verrouillage du pipeline sérialise les exécutions simultanées ; Base de données corrompue détectée et nettoyée automatiquement

Installer et mettre à jour

  • install.sh + install.ps1 inclus dans chaque archive de version avec l'indicateur --skip-config (#145)
  • Tue les serveurs MCP obsolètes, supprime la quarantaine macOS, signe le binaire ad hoc
  • Actualise les 10 configurations d'agent à chaque mise à jour
  • Extraction zip en mémoire — aucun unzip nécessaire sous Windows
  • Gestion du chemin Windows .exe corrigée lors de l'installation, de la mise à jour et de la désinstallation

Normalisation du chemin Windows (PR #146)

  • Séparateurs de chemins mixtes normalisés en barres obliques à tous les points d'entrée
  • cbm_normalize_path_sep() fonctionne sur TOUTES les plateformes (fichiers DB multiplateformes)

Suite de tests de trempage (nouveau)

  • Trempage rapide (10 min), trempage ASan (15 min), endurance hebdomadaire (4h) — le tout par plateforme
  • Suivi RSS, dérive FD, latence des requêtes, récupération après crash (kill -9 + redémarrage propre)
  • Tous les niveaux de trempage sont des portes de largage — aucun vaisseau de largage sans passer

Corrections de bugs

  • #139 Débordement de pile dans l'indexation automatique — pile de threads par défaut de 8 Mo (merci @theron-sapp pour le rapport de crash détaillé avec les adresses de pile, le tableau de fréquence et la solution de contournement !)
  • #140 index_repository échoue sous Windows — ce rapport de @Flipper1994 a déclenché la refonte complète de l'architecture de concurrence !
  • #137 detect_changes échoue sur les chemins avec des espaces (merci @shekthesnek pour l'observation précise selon laquelle 12 outils ont fonctionné mais 1 n'a pas fonctionné !)
  • #135 macOS Gatekeeper bloque le binaire (merci @heraque pour l'analyse approfondie de xattr/spctl/codesign !)
  • #133 search_code rejette la barre oblique inverse de Windows (merci @ckelly8 d'avoir identifié la cause première !)
  • #130 Les extracteurs d'importation O(N²) se bloquent sur des fichiers volumineux (merci @halindrome pour le problème ET le correctif dans PR #131 !)
  • #127 Connexion fermée en permanence — tous les chemins de crash corrigés (merci @kingofthebongo2008 !)
  • #145 Ignorer la configuration de l'agent dans les scripts d'installation (merci @sherif-fanous — implémenté le jour même !)
  • Débordement de tampon Arena, lacunes de détection de test, fuites de mémoire, CodeQL TOCTOU, auto-kill taskkill, traduction de chemin MSYS2 python3, tre ssize_t vendu

Tests

  • 2 586 tests unitaires (contre 2042), zéro ignoré, zéro fuite de mémoire
  • Plus de 480 nouveaux tests couvrant l'arène, le FQN, le tampon graphique, la répartition MCP, le pipeline, le magasin, YAML, l'observateur
  • Suite de fumée en 15 phases sur toutes les plateformes, y compris Windows
  • Tests d'immersion en tant que porte de libération - endurance vérifiée avant chaque libération

Sécurité

  • Installer des scripts dans l'analyse VirusTotal aux côtés des binaires (délai d'expiration de 120 minutes, tous les fichiers doivent passer)
  • system() éliminé de tout le code de production
  • Sommes de contrôle d'intégrité des dépendances du fournisseur appliquées
