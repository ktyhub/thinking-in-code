Quoi de neuf dans v0.5.6

search_code v2 — Recherche de code augmentée par graphique

L'outil search_code a été entièrement réécrit avec un pipeline en 4 phases qui combine la vitesse de grep avec l'intelligence des graphes de connaissances :

  • 3 modes de sortie : compact (par défaut : noms de fonctions + lignes de correspondance), full (corps de fonction complets avec correspondances en surbrillance), files (liste de fichiers avec nombre de correspondances)
  • Classement graphique : résultats classés par importance structurelle (les définitions en premier, les fonctions populaires ensuite, les tests en dernier)
  • Extension de bloc : les correspondances grep sont automatiquement étendues pour contenir les limites des fonctions — plus d'extraits de ligne fragmentés
  • path_filter : étendue des recherches à des répertoires spécifiques (par exemple, src/ uniquement)
  • Lignes context : contexte configurable autour des matchs en mode complet
  • Résumé de la distribution des répertoires : indique quels répertoires contiennent des correspondances Revient gracieusement au grep brut lorsque le projet n'est pas indexé.

Kubernetes et indexation personnalisée

Prise en charge complète de l'infrastructure en tant que code pour les manifestes Kubernetes :

  • Analyse les déploiements, les services, les ConfigMaps, les secrets, les entrées, les CronJobs et plus de 20 types de ressources
  • Personnaliser la résolution de superposition (relations base → superposition)
  • Les nœuds de ressources apparaissent dans le graphique de connaissances avec des étiquettes, des espaces de noms et des spécifications de conteneur
  • Nouvelle étiquette de nœud Resource dans le schéma graphique

Mappages d'extensions définis par l'utilisateur

Extension de fichier personnalisée → mappages de langues via .codebase-memory.json (au niveau du projet) ou $XDG_CONFIG_HOME/codebase-memory-mcp/config.json (global) :

{"extra_extensions": {".blade.php": "php", ".mjs": "javascript"}}

La configuration du projet est prioritaire sur la configuration globale.

Correctifs de sécurité

  • Injection SQL dans la recherche en magasin/BFS et injection d'arguments dans le serveur HTTP (#124 — @map588)
  • Utilisation après libération dans le chemin d'obtention de handle_manage_adr (#126 — @halindrome)
  • Prévention des fichiers Ghost .db : les gestionnaires de requêtes vérifient désormais l'existence du projet avant d'ouvrir SQLite — empêche l'accumulation de fichiers de base de données vides (#120)
  • Remplacement binaire : nouveau cbm_replace_binary avec modèle de dissociation avant écriture, gère les cibles en lecture seule et le remplacement de renommage de Windows (#114)

Correctifs de stabilité et de compatibilité

  • Mise en tampon stdio MCP : correction de l'inadéquation poll()/getline() FILE* qui provoquait le blocage de tools/list sur certains clients (#99 — @halindrome)
  • SQLite WAL busy_timeout : défini avant journal_mode=WAL pour empêcher SQLITE_BUSY en cas de conflit de verrouillage (#117 — @halindrome)
  • Import analyseur O(N²) → O(N) : remplacement de la boucle indexée ts_node_child() par TSTreeCursor walk — corrige le ralentissement quadratique sur les fichiers avec de nombreuses importations (#107 — @halindrome)
  • Incompatibilité de nom de projet de session : detect_session utilise désormais le même cbm_project_name_from_path() comme pipeline
  • Windows : correction du nom de fichier zip de l'interface utilisateur, wrappers de compatibilité setenv/unsetenv, repli de USERPROFILE lorsque HOME n'est pas défini
  • Linux : ajoutez -D_GNU_SOURCE pour la visibilité de strcasestr (#111 — @trollkotze)
  • libgit2 : correction de l'erreur de build -Wmissing-field-initializers (#91 — @jsyrjala)
  • Fuite de mémoire : resolve_store a perdu la connexion SQLite lors de l'interrogation de .db non lié après delete_project

Tests de fumée complets

Extension de 4 phases à 7, couvrant le cycle de vie binaire complet :

  • Phase 5 : transport MCP stdio — initialisation de la poignée de main, outils/liste, aller-retour des appels d'outils, cadrage Content-Length (compatibilité OpenCode)
  • Phase 6 : sous-commandes CLI — installer/désinstaller/mettre à jour --dry-run, définir/obtenir/réinitialiser la configuration, remplacement binaire simulé avec cas limite en lecture seule
  • Phase 7 : appels d'outils avancés MCP — search_code v2, get_code_snippet via JSON-RPC Les tests de fumée s'exécutent désormais dans l'infrastructure de test Docker (test-infrastructure/run.sh smoke) et dans CI sur les 10 combinaisons plateforme × variante.

Améliorations des commandes de mise à jour

  • Indicateur --dry-run : montre ce qui se passerait sans télécharger ou modifier des fichiers
  • Indicateurs --standard / --ui : ignorer l'invite de variante interactive (compatible CI)
  • Redémarrez le rappel après une mise à jour réussie

CI et infrastructures

  • Actions GitHub épinglées pour valider les SHA (dépendabot : VirusTotal 5.0.0, nœud de configuration 6.3.0, cosign-installer, attest-build-provenance)
  • Infra-test de test Docker : services smoke et smoke-amd64 pour les tests de fumée multiplateformes locaux
  • Nettoyage des artefacts de l'ère Go, mise à jour de THIRD_PARTY.md pour le projet C pur
