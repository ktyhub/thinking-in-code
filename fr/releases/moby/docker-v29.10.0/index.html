⚠️ Modification avec rupture potentielle : connexions au registre local

Si vous configurez explicitement insecure-registries dans daemon.json ou utilisez --insecure-registry, le moteur Docker ne traite plus automatiquement les adresses de bouclage (127.0.0.0/8 et ::1/128) comme des registres non sécurisés.

[!AVERTISSEMENT] Après la mise à niveau, les extractions et les transmissions vers les registres locaux qui utilisent des certificats HTTP ou TLS non rusted peuvent échouer à moins que ces registres ne soient explicitement inclus dans votre configuration de registre non sécurisée. Configurez TLS avec un certificat trusted ou ajoutez uniquement les adresses de registre local requises, telles que localhost:5000, à votre configuration de registre non sécurisée existante.

Lorsque insecure-registries est omis, les registres de bouclage restent non sécurisés par défaut. La définition de "insecure-registries": [] dans daemon.json désactive tous les registres non sécurisés par défaut. moby/moby#53868

🧻 La spécification du moteur API passe à OpenAPI 3.2

La spécification Engine API utilise désormais OpenAPI 3.2 comme format source, dans api/openapi.yaml. Une spécification Swagger 2.0 générée à partir de celle-ci est toujours publiée pour les outils existants, dans api/swagger.yaml. Pour la transition, cette version inclut également une copie Swagger 2.0 épinglée sur API v1.57, dans api/docs/v1.57-swagger.yaml. Les futures versions de API ne recevront pas de copie Swagger 2.0 par version, donc mettez à jour les outils qui dépendent de ces fichiers pour utiliser les spécifications OpenAPI 3.2. moby/moby#53630

📦 Packages pour AlmaLinux, Oracle Linux et Rocky Linux

Les packages Docker Engine sont disponibles pour AlmaLinux, Oracle Linux et Rocky Linux. Pour les instructions d'installation, voir AlmaLinux, Oracle Linux et Rocky Linux.

Nouveau

  • Ajoutez une prise en charge expérimentale des tâches : exécutez des charges de travail ponctuelles et planifiées par cron, gérées de manière native par le démon, en tant qu'extension intégrée facultative activée avec --enable-extension org.mobyproject.jobs.v0. moby/moby#53485
  • Ajout de la prise en charge de la personnalisation du conteneur intégré de Docker à l'aide des fichiers de configuration dans /etc/docker/containerd.d/. moby/moby#53946
  • Introduisez l'attribut restarting pour les événements die afin d'informer le consommateur que le conteneur va redémarrer. moby/moby#50908

Corrections de bugs et améliorations

  • Bloquer les familles de sockets obsolètes dans les profils AppArmor et seccomp par défaut. moby/moby#54093
  • magasin d'images conteneurd : correction de docker image inspect et docker image ls signalant une image vide lorsque la plate-forme hôte d'une image multiplateforme n'est pas extraite mais qu'une autre plate-forme l'est. moby/moby#54040
  • N'attendez pas l'expiration du délai d'exportation de la télémétrie lorsque le point de terminaison OTLP refuse les connexions. docker/cli#7495
  • Correction de docker <unknown-command> --version imprimant la version CLI au lieu d'une erreur "commande inconnue". docker/cli#7408
  • Correction de docker cp affichant un message "Copié avec succès" lorsque la copie échoue. docker/cli#7515
  • Correction de docker manifest annotate rejetant les plates-formes valides non incluses dans sa liste prédéfinie de combinaisons OS/architecture, telles que linux/loong64. docker/cli#7448
  • Correction de docker ps affichant une colonne NAMES vide lorsque tous les noms d'un conteneur contiennent une barre oblique, comme lorsqu'il est connecté à un Swarm API classique. docker/cli#7481
  • Correction du démon supprimant l'interface docker0 au redémarrage lorsqu'elle est configurée avec un pont géré par l'utilisateur et des pools d'adresses par défaut. moby/moby#54157
  • Correction des exportations de couches Windows contenant des fichiers fragmentés NTFS. moby/moby#53745
  • Correction : Incluez les codes d'état HTTP dans les erreurs de streaming JSON pour permettre à clients de classer correctement les échecs. moby/moby#54133
  • Améliorez la sélection d'images sur les hôtes Linux ARM64 pour préférer la variante d'image la plus élevée prise en charge par le processeur hôte. moby/moby#53910
  • Annotation du manifeste : ajoutez la complétion du shell pour --os et --arch. docker/cli#7449
  • Rejetez systématiquement les décomptes de GPU en double lorsque les options de décompte abrégé et explicite sont mélangées. docker/cli#7312
  • Arrêtez de traiter automatiquement les registres de bouclage comme non sécurisés lorsque insecure-registries est explicitement configuré et autorisez la désactivation des registres non sécurisés par défaut en définissant "insecure-registries": [] dans daemon.json. moby/moby#53868
  • Mettre à jour runc (dans les binaires statiques) vers v1.5.3. moby/moby#54183

Mises à jour des emballages

  • Mettez à jour BuildKit vers v0.35.0. moby/moby#54180
  • Mettre à jour le runtime Go vers 1.27.4. moby/moby#54176, docker/cli#7506

Réseautage

  • Les moteurs utilisant le backend du pare-feu nftables peuvent désormais rejoindre un Swarm. (Expérimental). moby/moby#53125
  • Correction de docker network ls --filter type=builtin --filter type=custom répertoriant un sous-ensemble aléatoire de réseaux. moby/moby#54127
  • Correction d'une erreur « une règle existe » lors de la publication de plusieurs ports hôtes pour le même port de conteneur avec le backend du pare-feu nftables et le proxy de l'espace utilisateur désactivés. moby/moby#54031
  • Correction d'un conteneur démarrant sans réseau après l'échec d'un démarrage antérieur avec une erreur réseau, telle qu'un port publié déjà utilisé. moby/moby#52480
  • Correction de la résolution DNS sur les réseaux définis par l'utilisateur lorsque le fichier /etc/resolv.conf de l'hôte est manquant ou ne contient aucun serveur de noms valide. moby/moby#54140
  • Correction des règles iptables et d'une chaîne DOCKER vide laissée lorsque le démon passe au backend du pare-feu nftables après qu'une version antérieure à 28.0.1 ait été exécutée avec iptables. moby/moby#54129
  • Correction des règles iptables qui n'étaient pas restaurées après l'arrêt de pare-feu ou le démarrage après le démon. moby/moby#54012
  • Correction des erreurs du pilote réseau de superposition lorsqu'un conteneur obtient l'adresse IP d'un conteneur qui vient d'être supprimé sur un autre nœud. moby/moby#53833
  • Correction du réseau superposé qui ne parvient pas à reconverger après une partition réseau lorsqu'un gestionnaire Swarm a été remplacé à une nouvelle adresse. moby/moby#53715
  • Correction des services Swarm qui divulguent une adresse IP virtuelle sur leurs autres réseaux à chaque échec d'allocation de temps sur un réseau, ce qui pourrait épuiser les sous-réseaux de ces réseaux. moby/moby#54148
  • Correction des tâches Swarm qui ne parviennent pas à atteindre le port publié d'un service via l'adresse de leur propre nœud lorsqu'un pare-feu hôte, tel que ufw, abandonne le trafic entrant non sollicité. moby/moby#54006
  • Correction du MTU des interfaces réseau superposées étant trop grand de 20 octets lorsque le chemin de données Swarm est IPv6. moby/moby#54067
  • Réduisez la surcharge de publication de port nftables en regroupant les mises à jour du pare-feu par point de terminaison et par famille d'adresses. moby/moby#54011
  • Empêchez les nœuds d'un cluster Swarm d'échanger l'état du réseau de superposition complet avec chaque gestionnaire une fois par minute lorsque le cluster est sain. moby/moby#53715

Sans racines

  • Autoriser le pilote de stockage overlay2 en mode sans racine lorsque SELinux est activé. moby/moby#54048
  • Correction de l'échec de docker cp avec "remount-ro ... opération non autorisée" en mode sans racine sur les conteneurs avec un montage de liaison en lecture seule à partir d'un système de fichiers nosuid ou nodev. moby/moby#53981
