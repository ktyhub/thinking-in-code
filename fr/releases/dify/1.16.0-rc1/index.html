modifier 1.16.0-rc1

Présentation de Dify Agent (Expérimental) : une nouvelle expérience d'agent dans Dify

[!AVERTISSEMENT] Vous devez fournir les services Dify Agent ⚠️uniquement aux utilisateurs trusted et non malveillants⚠️.

Comme beaucoup d’entre vous le savent, le paradigme des agents LLM basés sur un shell a apporté une avancée majeure dans les capacités des agents et a changé notre façon de penser les agents. Parallèlement, les compétences offrent un moyen standardisé de regrouper et de distribuer des fonctionnalités, facilitant ainsi la création d'agents puissants.

Aujourd'hui, nous lançons expérimentalement Dify Agent. Comme d’autres agents de premier plan, il s’exécute dans un bac à sable Linux. Cette version comprend :

  • Un constructeur pour créer des agents Dify

    • Vous pouvez créer des agents Dify via l'interface utilisateur : définissez une invite de base, téléchargez des compétences et des fichiers, et connectez les outils et les connaissances de l'écosystème Dify.
    • Nous fournissons également un agent qui vous aide à créer des agents Dify. Grâce à la conversation, il peut configurer l'environnement sandbox Linux, installer les packages requis et créer de nouvelles compétences et fichiers que votre agent Dify pourra utiliser ultérieurement.

  • Intégration de Dify Workflow pour Dify Agent

    • Vous pouvez utiliser un agent Dify existant dans un workflow Dify ou créer temporairement un agent Dify en ligne. Il exécutera la tâche définie par le nœud de workflow, générera la sortie requise et la transmettra au nœud suivant.

  • Une nouvelle expérience d'application Web

    • L'agent Dify que vous créez peut être publié et utilisé comme application Web. Bien que l'expérience utilisateur reste familière, elle est désormais optimisée par Dify Agent.

Documents : https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

Limites

Veuillez noter que dans la version expérimentale actuelle, tous les agents Dify s'exécutent dans le même bac à sable. Cela signifie :

  • Dans des circonstances normales, chaque agent Dify configure son environnement et exécute des tâches dans son propre espace de travail sans interférer avec les autres.
  • Cependant, avec des instructions simples, n'importe quel agent Dify peut lire ou interférer avec les environnements et les données d'autres agents Dify, y compris les données utilisateur.

Un isolement strict sera mis en œuvre dans une prochaine version. Pour l'instant,

[!AVERTISSEMENT] Vous devez fournir les services Dify Agent ⚠️uniquement aux utilisateurs trusted et non malveillants⚠️.

De même, étant donné que Dify Agent n'est pas encore entièrement prêt, vous constaterez peut-être que certaines fonctionnalités ne sont pas disponibles pour Dify Agent. Par exemple, l'exportation DSL de Dify Workflow n'est pas disponible lorsque le flux de travail contient des nœuds faisant référence à Dify Agent.

Guide de mise à niveau

[!IMPORTANT]

  • Cette version inclut de nouvelles migrations de bases de données. Exécutez-les dans le cadre de la mise à niveau.
  • Les variables d'environnement ont été modifiées. Consultez la section Modifications des variables d'environnement et mettez à jour votre .env en conséquence.
  • Docker Les fichiers de configuration de Compose ont été modifiés. Si vous conservez un docker-compose.yaml personnalisé, examinez les modifications et réappliquez soigneusement les personnalisations locales.

Déploiements de composition Docker

  1. Sauvegardez vos fichiers docker-compose YAML et env personnalisés. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Obtenez le dernier code pour la version 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Arrêtez les services (exécutez-les dans le répertoire docker). 
    docker compose down
  4. Sauvegardez les données. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Vérifiez toutes les modifications apportées au fichier env et réappliquez les personnalisations locales.
  6. Services de mise à niveau. 
    docker compose up -d

Déploiements de code source

  1. Arrêtez le serveur API, le Worker et le serveur frontal Web.
  2. Obtenez le dernier code pour la version 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Mettez à jour les dépendances de Python. 
    cd apiuv sync
  4. Exécutez les migrations de bases de données. 
    uv run flask db upgrade
  5. Redémarrez le serveur API, le Worker et le serveur frontal Web. Pour expérimenter la nouvelle fonctionnalité d'agent, vous devez également démarrer dify-agent et shellctl. Important : shellctl n'inclut pas l'authentification intégrée — pour des raisons de sécurité, il est fortement recommandé de l'exécuter dans un conteneur.
