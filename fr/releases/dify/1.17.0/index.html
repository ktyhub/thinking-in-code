modifier 1.17.0

Nouvelles fonctionnalités

Agent : E2B Sandbox, instantanés d'accueil et gestion des compétences

  • Backend sandbox E2B : l'exécution du shell/code de l'agent peut désormais s'exécuter sur les sandbox cloud E2B en plus du sandbox local. Sélectionnez le backend avec DIFY_AGENT_RUNTIME_BACKEND ; un nouveau docker-compose.e2b.yaml expédie la pile E2B, le trafic E2B est authentifié et le modèle E2B est synchronisé à la sortie (#39480, #39705, #39873, #39996, #40858, #40871, #40891, #40892).
  • Instantanés personnels au moment de la construction : lorsqu'une version d'agent est appliquée (publiée), le répertoire personnel du bac à sable de l'agent (packages installés, fichiers préparés, état de fonctionnement) est capturé et les exécutions ultérieures de l'agent publié restaurent leur répertoire personnel à partir de cet instantané, de sorte que l'agent démarre à partir de l'état exact du système de fichiers qu'il avait au moment de la construction. (#39702, #40876, #40996).
  • Gestion des compétences au niveau de l'espace de travail : les compétences sont des fonctionnalités réutilisables et versionnées, regroupées avec des définitions de code et d'outils que les agents peuvent découvrir et invoquer. Un nouveau gestionnaire de compétences au niveau de l'espace de travail avec le cycle de vie brouillon → publication → version est livré avec une interface utilisateur Web (liste de compétences, panneau de création, éditeur de fichiers). (#39675, #39798, #39799, #41180).
  • Compactage de l'historique contextuel : les longues conversations d'agent ne dépassent plus la fenêtre contextuelle du modèle — Dify résout le compactage efficace de la fenêtre et des niveaux de chaque modèle (effacez d'abord les anciens résultats de l'outil, puis résumez l'historique plus ancien) afin que les exécutions restent dans les limites du budget sans perdre le contexte récent (#40872).

Variables d'environnement LLM réutilisables dans les flux de travail

  • Définissez une fois une configuration de fournisseur/modèle/mode/paramètre partagé (par exemple for_summarize, for_research) et référencez-la à partir de n'importe quel nœud LLM. Les modifications coordonnées du modèle se produisent désormais au même endroit au lieu de dériver nœud par nœud, et les références survivent à l'importation/exportation DSL, aux extraits de code, aux pipelines RAG et à l'édition collaborative (#39125).

Entrée humaine dans les boucles et les itérations

  • Les formulaires Human-in-the-loop fonctionnent désormais à l'intérieur des nœuds de boucle et d'itération, s'arrêtant et reprenant correctement lors des actualisations de page pour les applications de débogage et installées — permettant des étapes de révision/approbation dans le cadre d'un travail répété (#39243).

Traçage unifié indépendant du fournisseur

  • Le traçage unifié opt-in (OPS_TRACE_UNIFIED_ENABLED) assemble l'arborescence complète parent-enfant (workflows, chatflows, messages, nœuds, boucles, itérations, workflows imbriqués) une fois dans le noyau et délègue uniquement le transport à des adaptateurs légers. Les adaptateurs Phoenix et LangSmith sont expédiés en premier ; désactivé par défaut et entièrement rétrocompatible (# 39451).
  • Le nouveau GenAI couvre le LLM TTFT de surface, les étapes de l'agent ReAct, les appels d'outils et les nœuds LLM défaillants pour une observabilité plus approfondie (# 39339).

Prise en charge du tourniquet Cloudflare (CAPTCHA)

  • Défi Turnstile facultatif lors de la connexion et de la connexion par code e-mail pour protéger les points de terminaison d'authentification contre les abus, avec des clés de site/secrètes configurables et des noms d'hôtes autorisés (#40494).

Azure Key Vault / KMS enfichable

  • Présente une abstraction de fournisseur KMS avec la prise en charge d'Azure Key Vault pour l'approvisionnement, le chiffrement et le déchiffrement des clés, ainsi que la configuration de la rotation des clés : une étape vers des clés de chiffrement gérées en externe (#39933).

Recherche vectorielle en texte intégral et hybride TiDB

  • Les déploiements TiDB Vector peuvent désormais permettre la récupération de texte intégral et hybride (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH, désactivé par défaut), en utilisant un index de texte intégral multilingue parallèlement à la recherche vectorielle (#38112).

Modèle plus large et gestion des fichiers

  • Les nœuds et les agents LLM peuvent désormais transmettre des fichiers image directement aux modèles multimodaux, et les pièces jointes non visuelles ne sont plus supprimées silencieusement des discussions des agents (#39848, #40179).
  • De nouveaux conseils de récupération multimodale aident les utilisateurs à choisir correctement les modèles d'intégration pour les bases de connaissances contenant des images (#40566).
  • L'ASR audio accepte désormais audio/x-m4a et les types audio MIME sont validés avec plus de précision (#40776, #41043).

Aller à n'importe quoi (⌘K / Ctrl+K)

  • Appuyez sur ⌘K (Ctrl+K sous Windows/Linux) n'importe où dans la console pour ouvrir la palette de commandes et accéder aux applications, agents, compétences, bases de connaissances, plugins ou nœuds de flux de travail, ou déclencher des actions rapides via des commandes slash. Nouveau dans cette version : les agents et les compétences sont consultables et le système d'icônes-commandes a été remanié dans tous les domaines pour plus de cohérence (#40620, #40621, #40646-#40649, #41160).

Autres ajouts

  • Prise en charge de l'extraction de documents ODT (OpenDocument Text) (#39973).
  • Nouveau type de paramètre date / date-picker pour les plugins d'outils (#36163).
  • Prise en charge de la langue lao (lo-LA) (# 39474).
  • Tâche de nettoyage automatique des anciennes conversations (ENABLE_CONVERSATION_CLEANUP_TASK) pour limiter la croissance des données (ère n° 40889).
  • Marketplace intégrée directement dans les catégories d'intégration pour une découverte plus fluide des outils/plugins (#40744).

Améliorations

Accessibilité (grand pass a11y)

  • Un très grand ensemble de modifications rend la console conviviale pour le clavier et les lecteurs d'écran : une véritable sémantique <button> pour des dizaines de commandes interactives, des noms accessibles pour les actions utilisant uniquement des icônes (copier, fermer, supprimer, menus), des titres principaux sur les pages d'authentification/installation, des sélecteurs de membres/outils accessibles au clavier et des états ARIA corrects (#40192–#40377 et bien d'autres).

Création de flux de travail

  • Le générateur de workflow préfère désormais les outils déjà installés et configurés lors de la suggestion de nœuds, afin que les constructeurs utilisent les outils dont ils disposent réellement (#40611, #39850).

Stabilité du flux de travail et de l'exécution

  • Exécutions de flux de travail Web reproductibles, état du canevas préservé après les mises à jour de l'historique, plus de boucles de rendu d'actualisation et les flux SSE se terminent désormais proprement sur les événements de terminal (#40010, #40489, #41105, #40042).
  • stop est désormais honoré entre les nœuds sans streaming et les flux de travail en pause effacent correctement les signaux d'annulation obsolètes (#41090, #40905, #40972).
  • Les valeurs par défaut de APP_MAX_EXECUTION_TIME et WORKFLOW_MAX_EXECUTION_TIME sont passées de 1 200 s à 3 600 s pour s'adapter aux flux de travail à exécution plus longue.

Qualité interne

  • Migration importante de tests unitaires vers de vrais modèles ORM/sessions SQLite pour une couverture plus fiable, ainsi qu'un typage plus fort dans les tests migrés (nombreux #38xxx–#39xxx). Aucun changement de comportement face à l'utilisateur.

Améliorations de la sécurité

  • Renforcement de l'authentification : défi Turnstile sur les flux de connexion/code de messagerie, vérification renforcée du code de messagerie avec limites de tentatives et expiration des jetons (EMAIL_CODE_LOGIN_MAX_ATTEMPTS, EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES), gestion des domaines de messagerie suspendus et jetons d'autorisation d'agent de courte durée (#40494, #40960, #41004, #40884).
  • Contrôle d'accès/portée de propriété : les ressources d'ensemble de données, de document, de RAG, de conversation, d'espace de travail et OAuth-client sont désormais systématiquement liées à leurs propriétaires et à la portée de l'application, fermant plusieurs chemins d'accès non autorisés (#40989, #40888, #40790, #40745, #40893, #40786 et associés).
  • SSRF et renforcement sortant : les phases de connexion HTTP sortantes sont limitées (5 s), les délais d'attente de téléchargement et d'exécution de l'agent/liaison sont configurables et le message d'erreur bloqué par SSRF pointe désormais vers le problème correct (#40807, #41027, #40605).

Guide de mise à niveau

Migration des types de modèles

[!IMPORTANT]

Migration unique du type de modèle hérité pour les mises à niveau auto-hébergées

Si ce déploiement a été mis à niveau à partir d'une version de Dify antérieure à 1.15.0 et que cette migration n'a pas déjà été appliquée, exécutez-la après la mise à niveau.

Cette migration n'est pas incluse dans flask db upgrade. Sans cela, les enregistrements de modèles existants peuvent entraîner l'échec des requêtes API liées au modèle avec des erreurs, empêchant ainsi le chargement ou l'utilisation des modèles concernés.

Sauvegardez la base de données avant d'appliquer la migration. La commande s'exécute en mode d'exécution à sec par défaut ; examinez la sortie avant de la réexécuter avec --apply. La migration est idempotente et peut être réexécutée en toute sécurité.

Docker Composer

Exécuté à partir du répertoire docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Déploiement du code source

Exécutez à partir de la racine du référentiel après avoir terminé flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Après avoir appliqué la migration, exécutez à nouveau la commande d'exécution à sec. S'il ne signale aucune mise à jour ou suppression de lignes supplémentaires, redémarrez les services concernés et vérifiez que les modèles existants peuvent être chargés et appelés avec succès.

[!IMPORTANT]

  • Cette version inclut de nouvelles migrations de bases de données — exécutez-les dans le cadre de la mise à niveau.
  • Les variables d'environnement ont été considérablement modifiées (beaucoup ajoutées, variable d'édition renommée EDITION → DEPLOYMENT_EDITION, plusieurs valeurs par défaut modifiées). Consultez la section Modifications des variables d'environnement et mettez à jour votre .env en conséquence. En particulier, renommez EDITION en DEPLOYMENT_EDITION si vous le définissez.
  • La configuration du Docker Compose a été modifiée et un nouveau docker-compose.e2b.yaml a été ajouté. Si vous conservez un docker-compose.yaml personnalisé, réappliquez soigneusement les personnalisations locales.
  • La migration add_conversation_cleanup_index construit un index sur des données existantes, ce qui peut prendre plus de temps à s'exécuter si la table conversations est volumineuse.

    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Obtenez le dernier code : 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Arrêtez les services (à partir du répertoire docker) : 
    docker compose down
  4. Sauvegardez les données : 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Vérifiez les modifications d'environnement et réappliquez les personnalisations locales (rappelez-vous EDITION → DEPLOYMENT_EDITION).
  6. Mise à niveau : 
    docker compose up -d

  1. Arrêtez le serveur API, le Worker et l'interface Web.
  2. Obtenez le dernier code : 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Mettez à jour les dépendances de Python : 
    cd apiuv sync
  4. Exécutez des migrations : 
    uv run flask db upgrade
  5. Reconstruisez/redémarrez l'interface Web, puis redémarrez le serveur API et Worker.
