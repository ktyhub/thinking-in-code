dify 1.13.1

Correctif Publié17 mars 2026 Sourcelanggenius/dify Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

modifier 1.13.1

🚀 Changements fonctionnels majeurs

Opérations sur la plateforme de données et les ensembles de données

  • Ajout de Hologres en tant qu'option backend prise en charge pour la récupération vectorielle et la recherche en texte intégral.
  • Ajout des points de terminaison du service API pour les téléchargements de documents d'ensemble de données :
    • Téléchargement ZIP par lots pour les documents sélectionnés.
    • Téléchargement d'URL signée pour les fichiers originaux d'un seul document.

Améliorations du workflow et de l'expérience de chat

  • Modification radicale : Le contenu des e-mails HITL utilise désormais le rendu markdown avant la livraison. Les modèles d'e-mails existants qui reposaient sur un comportement brut/simple peuvent s'afficher différemment après la mise à niveau.
  • Les variables de brouillon sont désormais limitées à l'utilisateur au lieu de l'application. Les variables de brouillon historiques ne seront pas disponibles après la mise à niveau.
  • Ajout de la prise en charge du menu contextuel des bords dans le canevas de flux de travail, y compris la suppression directe des bords.
  • Connexions existantes préservées lors de la modification des types de nœuds dans l'édition du flux de travail.
  • Ajout d'un comportement de clé d'envoi configurable (Enter vs Shift+Enter) pour la saisie de chat intégrée.
  • Ajout de charges utiles de fichiers dans les réponses du flux de fin de message.
  • Suppression du comportement codé en dur spécifique à GPT-4 de la logique de sélection de modèle par défaut.
  • Ajout d'une nouvelle commande export-app-messages CLI pour exporter les messages d'application et les commentaires associés vers JSONL.GZ (stockage local ou cloud).

🔐 Mises à jour de sécurité

  • Prévention des risques d'injection SQL dans les chemins de requête du magasin vectoriel en passant au SQL paramétré dans les implémentations concernées.
  • Envoi d'e-mails HITL renforcé :
    • Désinfecter le sujet et le contenu du corps.
    • Supprimez les CR/LF des sujets pour empêcher les vecteurs d'injection d'en-tête SMTP.
  • Vérifications de propriété forcées pour la suppression des conversations API.
  • Suppression des informations d'identification obsolètes du fournisseur lors de la désinstallation du plugin afin de réduire le risque résiduel lié aux informations d'identification.
  • Amélioration de la gestion des erreurs API d'entreprise et du comportement d'application des licences pour les états de licence invalides/expirés.

🏗️ Mises à jour de configuration, d'architecture et de déploiement

Déploiement et opérations

  • Ajout d'une file d'attente Celery dédiée : dataset_summary pour les tâches de génération de résumés lourdes en LLM.
    • Assurez-vous que les travailleurs s'abonnent à cette file d'attente pour éviter le retard dans les travaux de synthèse.
  • Ajout de métriques de télémétrie pour les tâches de nettoyage de rétention (messages/exécutions de flux de travail), ainsi que d'un comportement de vidage pour les tâches de commande de courte durée.

Modifications de la configuration

  • Ajout de REDIS_MAX_CONNECTIONS.
  • Paramètres de bus d'événements PUBSUB_* obsolètes au profit des paramètres EVENT_BUS_*.

🛠 Autres changements notables

  • Correction de workflow_runs.started_at écrasé lors de la reprise.
  • Correction des échecs silencieux de modification par lots de métadonnées causés par des cas extrêmes de transactions fractionnées.
  • Correction de problèmes d'extraction de filtre de métadonnées lors de la récupération de connaissances (conditions {{...}}).
  • Visibilité des citations restaurée dans les applications de chat avancées.
  • Correction du comportement de réinitialisation des variables de conversation après les nœuds HITL.
  • Correction d'un crash de page dans le flux de configuration du nœud de récupération de connaissances.
  • Correction de l'assistant de chat bloquant le comportement du mode réponse.
  • Ajout de la gestion doc_type dans les attributs vectoriels Weaviate pour une meilleure compatibilité.
  • Dépendances OpenTelemetry mises à niveau pour résoudre les erreurs de détachement de contexte.

Docker Composer Déploiements

  1. Sauvegardez votre fichier docker-compose YAML personnalisé (facultatif)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Obtenez le dernier code de la branche principale

    git checkout main
git pull origin main

  3. Arrêtez le service. Veuillez exécuter dans le répertoire docker

    docker compose down

  4. Sauvegarder les données

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Services de mise à niveau

    docker compose up -d
