🚀 Quoi de neuf dans v1.13.3 ?

Notre dernière version de correctif, v1.13.3, se concentre sur la stabilité et l'exactitude de l'exécution des flux de travail, du streaming et de la récupération des connaissances. Voici un aperçu rapide des mises à jour les plus importantes :

🎬 Nouvelles fonctionnalités

  • Configuration du workflow : ajout de la prise en charge des références de variables pour les paramètres de modèle dans les nœuds LLM, Question Classifier et Variable Extractor par @scdeng dans #33082.

🛠️ Corrections de bugs

  • Fiabilité du streaming : correction des problèmes de relecture et de concurrence de StreamsBroadcastChannel pour maintenir la diffusion des événements frontend/backend stable par @QuantumGhost dans #34030 et #34061.
  • Comportement de l'éditeur de workflow : correction des nœuds collés conservant les métadonnées de boucle/itération et empêchant les nœuds HumanInput d'être collés dans des conteneurs non valides par @majiayu000 et @hjlarry dans #29983 et #34077.
  • Exécution d'exécution : restauration de la logique de transformation des messages d'invite et correction de la gestion de max_retries=0 pour l'exécution de requêtes HTTP pilotées par l'exécuteur par @QuantumGhost, @fatelei et @kurokobo dans #33666, #33619 et #33688.
  • Récupération de connaissances : préservation des métadonnées de citation dans les réponses Web, correction des plantages lorsque les métadonnées des icônes d'ensemble de données sont manquantes, correction du filtrage des requêtes par nombre d'accès et restauration des aperçus de morceaux de documents indexés par @ Theysua, @copilot-swe-agent et @fatelei dans #33778, #33907, #33757 et #33942.

🔧 Sous le capot

  • Stabilité des correctifs : cette version donne la priorité aux correctifs ciblés pour le comportement d'exécution du flux de travail, le streaming en temps réel et la convivialité de la base de connaissances pour les équipes effectuant une mise à niveau à partir de v1.13.2.

Guide de mise à niveau

[!IMPORTANT] L'image Sandbox utilisée par Dify v1.13.3 attend les chemins Python et Node.js suivants. Si vous avez effectué une mise à niveau à partir d'un ancien déploiement Docker Compose et que vous disposez déjà de docker/volumes/sandbox/conf/config.yaml, mettez-le à jour sur la machine hôte :

python_path: /opt/python/bin/python3
nodejs_path: /usr/local/bin/node

Ne modifiez pas le fichier à l'intérieur du conteneur sandbox. Le répertoire docker/volumes/sandbox/conf est monté dans le conteneur sous le nom /conf, de sorte que les modifications d'hôte persistent après le redémarrage du conteneur.

Déploiements de composition Docker

  1. Sauvegardez votre fichier docker-compose YAML personnalisé (facultatif)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Obtenez le dernier code de la branche principale

    git checkout main
git pull origin main

  3. Arrêtez le service. Veuillez exécuter dans le répertoire docker

    docker compose down

  4. Sauvegarder les données

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Services de mise à niveau

    docker compose up -d

Déploiements de code source

  1. Arrêtez le serveur API, le Worker et le serveur Web frontal.

  2. Obtenez le dernier code de la branche release :

    git checkout 1.13.3

  3. Mettez à jour les dépendances de Python :

    cd api
uv sync

  4. Ensuite, exécutons le script de migration :

    uv run flask db upgrade

  5. Enfin, exécutez à nouveau le serveur API, le Worker et le serveur Web frontal.
