🚀 Quoi de neuf dans v1.14.1 ?

v1.14.1 est une version de correctif axée sur le renforcement de la sécurité, la stabilité du flux de travail et de la base de connaissances, le nettoyage du déploiement et la migration continue de la plate-forme d'interface utilisateur après v1.14.0.

🔐 Sécurité

  • Durcissement SECRET_KEY auto-hébergé — Les déploiements Docker ne reposent plus sur une clé publique par défaut. Lorsque SECRET_KEY est laissé vide, le API génère et conserve une clé d'exécution via le backend de stockage configuré, tandis que les clés explicitement configurées continuent de fonctionner comme avant. Merci @laipz8200 dans #36049.
  • Protection interne des points de terminaison des métriques — /threads et /db-pool-stat sont renforcés pour éviter toute exposition non authentifiée des détails du runtime interne et du pool de bases de données. Merci @orbisai0security dans #35665.
  • Isolement des comptes et des outils — correction d'un problème d'IDOR dans GET /account/avatar et étendue du nettoyage des informations d'identification par défaut de l'outil intégré au locataire actuel. Merci @NeatGuyCoding et @GareArc dans #35771 et #35887.
  • Sécurité des dépendances — LiteLLM mis à niveau pour CVE-2026-42208 et actualisé plusieurs dépendances backend, notamment urllib3, gunicorn, gitpython, mako, les packages Google SDK, les bibliothèques de stockage et les packages d'exportateur OpenTelemetry. Merci @crazywoola dans #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017 et #36050.

🧩 Workflow, HITL et exécution de l'application

  • Stabilité du workflow : restauration du chargement de la version du workflow via le backend API, correction de l'interrogation des utilisateurs en ligne pour les grandes listes d'applications, prévention des boucles d'observateur de redimensionnement de l'aperçu et évitement des collisions de modèles de schéma dans les workflows d'essai. Merci @hjlarry et @lyzno1 dans #35817, #35786, #35936 et #36061.
  • Peaufinage de la création de workflow : correction du comportement du sélecteur de références de variables pour les sous-variables, dépassement du titre du nœud de workflow, popovers des opérateurs de condition, sémantique de la liste de contrôle du workflow et sélection des champs de filtre de métadonnées de la base de connaissances. Merci @iamjoel, @hjlarry, @lyzno1 et @shawny011717 dans #35732, #35740, #35828, #36006 et #34149.
  • Correction de l'exécution du workflow — types de variables d'entrée à exécution unique préservés, validation structured_output_enabled corrigée, gestion des URL d'aperçu de fichier corrigées dans l'affichage de sortie du nœud et outils de sélection de modèle de plug-in débloqués sur les workflows v1.14.0. Guide de mise à niveau

Remarques importantes

  • Cette version inclut une nouvelle migration de base de données pour les catégories d'applications Explore configurables. Exécutez les migrations de bases de données dans le cadre de la mise à niveau.
  • Les variables d'environnement Docker Compose sont désormais divisées en fichiers catégorisés sous docker/envs/**. Si vous conservez un docker-compose.yaml ou un .env personnalisé, examinez la nouvelle disposition et réappliquez soigneusement les personnalisations locales.
  • Pour les déploiements auto-hébergés, les valeurs SECRET_KEY explicitement configurées continuent d'être respectées. Si SECRET_KEY est vide, Dify génère et conserve désormais automatiquement une clé d'exécution.

Déploiements de composition Docker

  1. Sauvegardez vos fichiers docker-compose YAML et env personnalisés.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Obtenez le dernier code de la branche ou de la balise de publication.

    git fetch --tags
git checkout 1.14.1

  3. Arrêtez le service. Veuillez exécuter dans le répertoire docker.

    docker compose down

  4. Sauvegardez les données.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Vérifiez la nouvelle présentation du fichier d'environnement docker/envs/** et réappliquez toutes les personnalisations locales.

  6. Services de mise à niveau.

    docker compose up -d

Déploiements de code source

  1. Arrêtez le serveur API, le Worker et le serveur Web frontal.

  2. Obtenez le dernier code de la balise de version.

    git fetch --tags
git checkout 1.14.1

  3. Mettez à jour les dépendances de Python.

    cd api
uv sync

  4. Exécutez le script de migration.

    uv run flask db upgrade

  5. Redémarrez le serveur API, le Worker et le serveur Web frontal.
