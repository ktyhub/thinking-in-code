graphql-java v25.0

Changements clés

Chargeur de données

Stratégie de refactorisation

Le PerLevelDataLoaderStrategy existant a été refactorisé, ce qui a conduit à des simplifications et à des améliorations de performances.

Nouvelles stratégies

Deux nouvelles stratégies ont été introduites : ENCHAÎNÉ et ÉPUISÉ. Les deux peuvent être configurés via UnusalConfiguration (voir section suivante).

CHAINED permet d'utiliser des DataLoaders chaînés tout en conservant des stratégies de répartition par niveau.

EXHAUSTED est une toute nouvelle stratégie qui fonctionne sur la base de la répartition une fois que le moteur n'est pas occupé. Il reflète la stratégie de répartition du chargeur de données JS, mais pour un système multithread.

Configuration inhabituelle

Un mécanisme de configuration plus généralisé a été ajouté pour les « configurations inhabituelles ». Nous entendons par là la configuration que nous ne nous attendons pas à ce que beaucoup de gens utilisent, mais s'ils le font maintenant dans un endroit plus commun

Par exemple, si vous souhaitez modifier la profondeur maximale acceptée par l'analyseur de documents, vous pouvez appeler les méthodes suivantes.

        var parserOptions = newParserOptions().maxRuleDepth(99).build()
        GraphQL.unusualConfiguration().parsing().setDefaultParserOptions(parserOptions)

JSpécifier les annotations

L'équipe commence à adopter les annotations https://jspecify.dev/ comme moyen d'indiquer les champs nullables et non nullables. De nombreuses classes importantes ont vu ces annotations ajoutées pour aider à rendre plus clair sémantiquement quand une valeur peut être nulle ou non.

Changements révolutionnaires

Un objet d'encapsulation FetchedValue n'est pas toujours renvoyé sur les récupérateurs de champs pour des raisons de performances. Cela signifie que graphql.execution.instrumentation.parameters.InstrumentationFieldCompleteParameters#getFetchedObject a été créé pour remplacer l'ancienne méthode getFetchedValue et que l'objet renvoyé peut parfois être un FetchedValue ou parfois une simple valeur POJO.

Améliorations des performances

Une série d'améliorations de performances ont été apportées pour réduire l'empreinte mémoire de la bibliothèque. De plus, l'opérateur Java .stream() peut être plus lent qu'une boucle plus directe et bon nombre de ces appels ont été modifiés pour des raisons de performances.
