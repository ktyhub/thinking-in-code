#claude-mem v15.19.0

Poursuivre une conversation Claude Code ou Codex depuis Mon travail

Ouvrez une demande dans Mon travail, puis ouvrez "D'où cela vient". Sous chaque conversation Claude Code ou Codex, il y a désormais une boîte de message. Tapez un message et appuyez sur Envoyer, et cette même conversation prend le relais. La réponse s'affiche ici (#6191 ; les formes de commande suivent le code de réponse de @wiesenthal dans #6054, et le commit le crédite).

  • Chaque conversation conserve dans l'ordre les messages que vous avez envoyés depuis Mon travail et leurs réponses. Stop termine un tour en cours.
  • La case indique dans quel dossier le tour s'exécute. Lorsque le dossier enregistré n'existe plus (ce qui est courant après le nettoyage d'un arbre de travail), le tour s'exécute dans le dossier existant le plus proche au-dessus de lui.
  • "Copier la commande de reprise" copie claude --resume <id> ou codex resume <id>. Sur un Mac, « Ouvrir dans Claude » ouvre une conversation Claude Code dans l'application de bureau Claude.
  • One Send démarre un CV sans tête (claude --resume <id> -p --output-format json ou codex exec resume <id> - --skip-git-repo-check) avec votre message sur stdin. Un tour échoué est enregistré comme échoué et n'a jamais été réessayé. Rien n'est mis en file d'attente ou enregistré pour la relecture, et rien ne démarre au démarrage, sur une minuterie ou à la reconnexion.
  • Un redémarrage ou un arrêt d'un travailleur arrête d'abord chaque tour en cours, de sorte qu'un travailleur redémarré ne devient jamais un deuxième rédacteur dans la même conversation. Rien ne renvoie un virage arrêté.
  • Un tour s'exécute dans votre propre mode d'autorisation par défaut, le même que celui utilisé par claude -p --resume dans votre terminal. En mode manuel, les appels d'outils nécessitant une approbation sont refusés et la ligne les compte. Aucun indicateur d'autorisation, de modèle ou de bac à sable n'est transmis.
  • Les nouvelles routes répondent uniquement en bouclage et refusent les autres origines. Lorsque le mode jeton local API est désactivé, un autre programme sur le même ordinateur peut les appeler, comme il le peut pour n'importe quel autre itinéraire de travail. Sur un ordinateur partagé, activez le mode jeton API local.
  • Un changement pour chaque requête : pendant le chargement d'une version plus récente d'une requête ouverte, le tiroir continue d'afficher la version qu'il possède déjà au lieu de "Chargement des détails de la requête…".

Limites connues :

  • Le chemin Codex à travers la page n'a pas été exécuté bout à bout sur la machine de test. Les virages du Codex ont été vérifiés au niveau du coureur avec le vrai CLI.
  • Sous Windows, Stop ne peut pas atteindre un CLI derrière une cale .cmd, et "Ouvrir dans Claude" n'est pas proposé.
  • Une conversation en cours dans un terminal peut toujours bénéficier d'un tour depuis Mon travail. Les documents de Claude Code indiquent que deux rédacteurs sur une même session peuvent perdre des messages. Mon travail bloque deux de ses propres tours sur une conversation.
  • Un crash de travailleur (et non un redémarrage en douceur) ne peut pas arrêter un tour en cours. Cela se termine tout seul.
  • Un assistant laissé par le CLI, tel qu'un serveur MCP à sortie lente, maintient le virage marqué comme étant en cours d'exécution jusqu'à ce qu'il se termine ou que vous appuyiez sur Stop.

Apportez votre mémoire existante

npx claude-mem import récupère les souvenirs directement depuis la plateforme Mem0 ou Supermemory et les enregistre sous forme d'observations consultables dans un projet de votre choix. Aucun fichier d'exportation et aucun appel de modèle (#6106).

# MEM0_API_KEY in the environment
npx claude-mem import --from mem0 --source-account personal-mem0 --user my-user-id --project imported-memory

# SUPERMEMORY_API_KEY in the environment
npx claude-mem import --from supermemory --source-account personal-supermemory --namespace my_namespace --project imported-memory
  • Démarrez d'abord le travailleur (npx claude-mem start). Ajoutez --dry-run pour récupérer et vérifier la source et le nombre d'impressions sans rien écrire.
  • Chaque page source est récupérée et vérifiée avant que quoi que ce soit ne soit écrit. Les mémoires Mem0 expirées ou remplacées et les mémoires Supermemory oubliées ou plus anciennes sont ignorées. Pour Supermemory, --documents importe le texte du document extrait au lieu des mémoires.
  • Les mémoires importées sont archivées pour Claude Code (claude), donc sa recherche en mémoire les trouve. --platform <host> (par exemple codex ou cursor) les classe sous un autre hôte. Chaque observation conserve l'enregistrement source, l'ID, les horodatages, les métadonnées, l'étiquette du compte et la portée.
  • Réexécuter la même commande est sécurisé : les enregistrements déjà enregistrés sont comptés comme existants. Il n'y a pas de travail en arrière-plan ni de nouvelle tentative automatique.
  • Il s'agit d'une importation unidirectionnelle, pas d'une synchronisation. Les modifications à la source génèrent de nouvelles observations. Les suppressions et les expirations à la source ne sont pas reportées.
  • Limites : 10 000 enregistrements par défaut (--max-records jusqu'à 100 000), 100 Mo de réponses source, un délai de requête de 15 secondes (--timeout-ms jusqu'à 120 000) et 100 000 caractères par enregistrement. Rien n'est coupé en silence : un enregistrement surdimensionné ou une requête échouée arrête l'exécution.
  • Les tests utilisent des réponses synthétiques Mem0 et Supermemory, et non des comptes réels.

Documents : https://docs.claude-mem.ai/usage/import-providers

Codex : les threads fourchus obtiennent de la mémoire

  • Les fils de discussion Forked Codex commencent par la mémoire rappelée (#6101). Le Codex 0.165 a ajouté un démarrage de session fork pour ses fourches de fil expérimentales attachées. Le hook SessionStart de Claude-mem ne correspondait pas, donc un thread forké a démarré sans mémoire. Le crochet correspond désormais à fork.

    Utilisateurs du Codex : approuvez à nouveau un hook. Le correspondant du hook SessionStart a changé et le Codex demande à nouveau l'approbation chaque fois que la définition d'un hook change.

    1. Introduisez le nouveau matcher dans ~/.codex/hooks.json. npx claude-mem update et la mise à jour automatique le font lorsque votre dernière installation a sélectionné Codex. Sinon, exécutez npx claude-mem install et sélectionnez Codex.
    2. Ouvrez le Codex interactif, exécutez /hooks et approuvez le hook SessionStart de Claude-mem.

    Jusqu'à ce que vous l'approuviez, les sessions Codex démarrent sans mémoire rappelée. La capture continue de fonctionner. Jusqu'à ce que le nouveau matcher soit dans hooks.json, npx claude-mem doctor affiche la ligne Codex hooks comme étant obsolète.

Aussi nouveau

  • Exécution du serveur : les résultats de la recherche indiquent quel agent a créé une mémoire (#6100). Le runtime du serveur stocke désormais l'agent sur chaque mémoire et le remplit pour les mémoires existantes de leur session. Ses lignes de recherche et de détail MCP ajoutent [via <agent>], par exemple #8 — Auth redirect decision (myproject) [via cursor]. Les mémoires sans agent enregistré ne présentent aucune balise. /api/sessions/observations n'étiquete plus chaque client comme Claude Code. Les résultats d'observation du travailleur local ne contiennent pas encore l'agent, ils ne montrent donc aucune étiquette.
  • Zed (#6111, merci @AdityaxDeore, ferme le #5900). npx claude-mem install (ou --ide zed) enregistre le serveur MCP de Claude-mem dans le context_servers de Zed, pour la recherche, la chronologie, les détails et les sauvegardes explicites. Les commentaires dans le fichier de paramètres de Zed sont conservés. Il n'y a pas de capture automatique, car Zed n'a pas de hooks ni d'accès à la transcription. Documents : https://docs.claude-mem.ai/zed-integration
  • Aider (#6112, merci @AdityaxDeore, ferme le #5893). Exécutez npx claude-mem aider install dans un projet. Il ajoute .claude-mem/aider-memory.md à la liste read: dans .aider.conf.yml et npx claude-mem aider sync actualise ce fichier à partir du travailleur. C'est une option par projet : npx claude-mem install ne le propose pas, le fichier mémoire est conservé hors de git via .git/info/exclude et il refuse de s'exécuter dans votre dossier personnel. Pas de capture automatique. Documents : https://docs.claude-mem.ai/aider-integration
  • Grok Build obtient une mémoire rappelée au début de la session (#6180, merci @krishnadobhal, ferme le #5950). Grok Build ignore ce que les hooks SessionStart impriment, donc les notes rappelées n'ont jamais atteint le modèle. claude-mem grok install écrit .grok/rules/claude-mem-context.md dans le dossier actuel, que Grok Build charge à partir des dossiers trusted. Le travailleur l'actualise après chaque résumé de session, uniquement dans les dossiers dans lesquels vous l'avez installé. Un projet exclu reçoit une ligne « exclu » au lieu de notes. La capture est inchangée. Documents : https://docs.claude-mem.ai/grok-build
  • Français dans le sélecteur de langue pour My Work, la visionneuse, la configuration de première diffusion et Observation TV (#6107, merci @QuantScorpus). Vos souvenirs, règles et citations restent tels qu'écrits.
  • Trois nouveaux préréglages pour le fournisseur compatible OpenAI. Chacun est par défaut un modèle petit et rapide, car l'extraction de mémoire est un volume élevé :
    • AtmoRouter, zai/glm-5.3-flash (#6108, merci @BeckleyTenriajeng)
    • TrustedRouter, deepseek/deepseek-v4-flash (#6174, merci @jperla). trustedrouter/auto reste disponible en option. Il peut acheminer une demande vers un modèle tarifé aux tarifs frontières.
    • HopBase, deepseek-v4.1-flash (#6181, merci @victor-zzh)

Correctifs

Confidentialité et sécurité

  • Le dossier de données claude-mem est réservé au propriétaire (#6091, merci @DeryFerd). Sous macOS et Linux, ~/.claude-mem (base de données, paramètres, .env, hook spool, sauvegardes) a été créé avec un simple mkdir, donc sous le umask 022 commun, d'autres comptes sur la machine pourraient le lire. Il est maintenant créé sous le nom 0700, un dossier existant est resserré au prochain démarrage et les nouvelles entrées de la bobine de crochet sont écrites sous le nom 0600.
  • MCP save_memory honore CLAUDE_MEM_EXCLUDED_PROJECTS (#6105, merci @Zhong-fan, rapporté par @Kirat0201 dans #6098 ; @0xABCD01 a envoyé le même correctif dans #6166). Une sauvegarde d'une extraction exclue a été stockée sur MCP tandis que la même sauvegarde sur HTTP a été ignorée. Il est désormais ignoré et la réponse indique « Non enregistré : cette extraction est exclue par CLAUDE_MEM_EXCLUDED_PROJECTS. » au lieu de "Mémoire enregistrée #? : Sans titre.". Les guides Cline et Kilo le disent désormais (#6190).
  • Serveur runtime : la commande MCP connect refuse un Host inutilisable (#6176, merci @DeryFerd). Sans CLAUDE_MEM_PUBLIC_URL, GET /v1/connect et POST /v1/keys ont construit la commande prête à coller à partir de l'en-tête Host de la requête et y ont copié des espaces, des guillemets ou des chemins. Une valeur qui ne peut pas être un hôte obtient désormais 400 InvalidHost et aucune clé n'est créée.
  • Hub de synchronisation : FORWARD_ORIGIN doit utiliser https:// (#6175, merci @DeryFerd). Le proxy direct copie l'en-tête Authorization entrant vers la cible, de sorte qu'une simple origine http:// puisse l'envoyer sans TLS. http:// est autorisé uniquement pour les hôtes de bouclage. Une valeur qui n'est pas une URL utilisable échoue désormais bruyamment au lieu de revenir silencieusement au chemin de l'objet durable.

Installer et désinstaller

  • La désinstallation supprime les hooks Gemini CLI (#6088, merci @tanishqbaweja). npx claude-mem uninstall a supprimé le plugin mais a laissé les cinq hooks Gemini CLI de Claude-mem dans ~/.gemini/settings.json, donc Gemini CLI a imprimé un message d'échec de hook à chaque début de session, invite, appel d'outil et fin de tour. La désinstallation les supprime maintenant et conserve vos propres paramètres et hooks. Un settings.json avec des commentaires n'est pas touché, alors retirez ces crochets à la main.
  • L'annulation de l'invite de la touche API ne vous fait plus passer à Claude (#6161, merci @bulanovk). Avec --provider gemini ou --provider openrouter et aucune clé enregistrée, l'annulation de l'invite de clé a écrit CLAUDE_MEM_PROVIDER='claude' et a continué. Cela s'arrête maintenant avec une erreur et ne change rien.
  • La vérification de configuration héritée du programme d'installation du Codex étend un ~\ principal uniquement sous Windows, comme le reste de claude-mem (#6093, merci @DeryFerd).

Ouvrier et stockage

  • Un travailleur qui rencontre une base de données occupée au démarrage réessaye au lieu de répondre au 503 pendant quelques minutes (#6145, merci @montjeffrey, réf. #3603). Un travailleur de remplacement pourrait frapper SQLITE_BUSY_SNAPSHOT une fois lors du démarrage de la base de données, ne jamais réessayer et répondre à chaque demande avec « Initialisation du service » jusqu'à un redémarrage manuel (environ 11 minutes dans le rapport). Le démarrage réessaye désormais une erreur d'occupation 3 fois, après 1, 2 et 4 secondes. Le pire des cas (27 s) correspond aux 30 s pendant lesquelles le crochet attend que le travailleur soit prêt. Other errors still fail at once.
  • La fermeture de la base de données la libère (#6090, merci @DeryFerd). Les instructions préparées mises en cache maintenaient la connexion et le fichier de base de données ouverts après la fermeture. Sous Windows, qui a bloqué les échanges de restauration et le nettoyage des dossiers temporaires avec EPERM ou EBUSY.
  • Le nettoyage Chroma des sessions supprimées survit à la sortie d'un travailleur (#6163, merci @Afloat16). Si le travailleur se terminait avant l'exécution du nettoyage en file d'attente, les vecteurs des lignes supprimées n'étaient jamais supprimés. The cleanup is now recorded before it starts. Le même changement corrige une vérification qui traitait une ligne manquante comme restaurée sur Bun.
  • Sur Bun, une base de données dont la table d'exclusions de lancement de synchronisation a disparu la reconstruit au lieu de garder une liste vide (#6189).
  • Un abonné /api/ready défaillant n'arrête plus la progression du démarrage des autres ou se transforme en échec de démarrage (#6127, merci @Afloat16).

Capture and memory notes

  • CLAUDE_MEM_SKIP_BASH_PATTERNS s'applique à Antigravity CLI (#6096, merci @tanishqbaweja). agy signale son outil shell comme run_command, que la vérification des modèles n'a pas lu, donc les commandes exclues ont été stockées et envoyées à l'observateur.
  • Une note explicite contenant un caractère nul pouvait obtenir l'identifiant d'une autre note alors que son propre texte n'était pas enregistré (#6170, merci @Kirat0201, ferme le #6169).
  • Un fichier mémoire Claude Code dont la description ou metadata.type a changé est stocké comme nouvelle révision au lieu d'être signalé comme déjà importé (#6186, merci @Kirat0201, ferme le #6171).
  • Memory notes (thanks @Afloat16):
    • Le titre d'une note provient de ses véritables en-têtes, et non d'un # comment dans un exemple de code (#6156).
    • Les champs imbriqués sous le metadata: d'une note n'écrasent plus le type ou la session de la note, et un commentaire YAML ne termine plus le bloc (#6157).
    • memory ingest --source ou --cwd sans valeur s'arrête avec une erreur d'utilisation au lieu d'importer la caisse en cours (#6150).
    • Scanner à nouveau une transcription n'insère plus deux fois un tour importé lorsque deux tours proches ont le même texte (#6149).
    • Avec CLAUDE_MEM_DEDUP_ENABLED=true, les titres qui diffèrent uniquement par les caractères de code (C++ et C#, src/config.ts et src config ts, numéros de version) ne sont plus fusionnés en une seule ligne, qui perdait la seconde (#6120).
    • Les observations importées dont les faits ou les fichiers ont été stockés sous la forme d'une seule chaîne les affichent à nouveau en rappel (#6134).

Recherche et contexte (merci @Afloat16 sauf indication contraire)

  • La recherche sémantique vérifie les fenêtres de date par rapport aux lignes enregistrées, et non à la copie de Chroma, donc une ligne mise à jour dans SQLite mais pas encore dans Chroma atterrit dans la fenêtre de droite (#6153).
  • Les recherches de fichiers classées par date sautent Chroma, donc une panne de Chroma ou une intégration lente ne les fait plus échouer (#6123).
  • Le contexte de fichier renvoie les observations les plus récentes lorsque plusieurs partagent un horodatage (#6118).
  • Le cache contextuel conserve la bonne portée d'invalidation lorsque les rendus se terminent dans le désordre, donc une écriture ultérieure dans un projet adopté le rafraîchit (#6164).
  • La recherche approfondie donne à son processus enfant uniquement le temps réellement restant, donc un pas d'horloge tel qu'une correction NTP ne provoque plus un délai d'attente vide anticipé (#6177, merci @DeryFerd).

Codex en tant que fournisseur de mémoire (merci @Afloat16)

  • La limite de protocole de 8 Mio s'applique à chaque ligne JSON, et non à tout ce qui est mis en mémoire tampon, donc une sortie valide n'est plus rejetée (#6119).
  • Un tube stdin fermé pendant un tour échoue et ne tourne pas proprement au lieu de escaping comme une erreur non gérée (#6130).
  • Une requête expirée ne laisse plus derrière elle un gestionnaire d'abandon qui pourrait échouer au prochain tour sur un nouveau serveur d'applications (#6133).

Lecture intelligente du fichier

  • smart_outline ne marque plus les déclarations à côté d'un export sur la même ligne que [exported] (#6141, merci @liuyinchu).
  • Maintenant indexés (merci @Afloat16) : fonctions, flèches et classes anonymes export default (#6151), méthodes du protocole Swift et méthodes Scala sans corps (#6154), et déclarations Java @interface et leurs éléments (#6160).
  • La recherche de code intelligente lit chaque fichier via une seule poignée et s'arrête à la limite de 512 Ko, donc un fichier remplacé après la vérification de la taille ne peut pas dépasser la limite (#6124, merci @Afloat16).

Mon travail

  • L'étape des objectifs utilise le langage de la course (#6187, merci @0xABCD01, ferme le #6185 rapporté par @Fly-onlyone). La ligne linguistique atteignait chaque étape sauf les buts, donc dans #6185, 147 invites en anglais produisaient des buts en espagnol. Une première course avec des objectifs uniquement, sans définition de langue, peut encore deviner. CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE le règle.
  • Également dans Mon travail (merci @Afloat16) :
    • Une réponse de Jev coupée au milieu du corps compte comme une panne, et non comme un échec permanent pour cet élément, donc la prochaine actualisation demande à nouveau (#6158).
    • Un nouveau git init, un nouveau référentiel imbriqué ou un .git supprimé est récupéré la prochaine fois que My Work travaille sur le projet d'une session, et non seulement après le redémarrage d'un travailleur (#6165).
    • L'effacement automatique ignore les lectures tardives d'un tour ou d'une conversation déjà terminée (#6152).
    • Les invites du propriétaire conservent leur budget complet de 3 000 caractères lorsqu'elles contiennent des emoji et d'autres caractères en dehors du plan de base (#6162).
    • L'agent de corpus opt-in API correspond aux mots accentués, hindi, bengali et hébreu pointus (#6168).
    • Les totaux d'utilisation de Gemini dans la configuration conservent le nombre de jetons terminés lorsque la même réponse a été enregistrée deux fois (#6146).

Visionneuse

  • L'ouverture d'une fenêtre de visualisation envoie sa première liste de projets et son statut uniquement à cette fenêtre, pas à chaque visionneuse ouverte (#6126, merci @Afloat16).
  • Clicliquez à nouveau sur le bouton d'actions de session pour fermer son menu (#6143, merci @liuyinchu).

Autre

  • agent-cost-report écrit CHECKSUMS.txt avec des barres obliques sous Windows (#6089, merci @DeryFerd).

Performances (merci @Afloat16)

  • Les longues lignes de transcription sont assemblées une seule fois au lieu d'être copiées à chaque passe de lecture, dans le lecteur arrière (#6116) et l'observateur en direct (#6117).
  • L'historique des invites OpenCode est lu un message à la fois (#6121).
  • Les charges utiles d'outils volumineux sont plafonnées et hachées sans copies complètes (#6128).
  • Les timelines chargent uniquement les lignes qu'elles affichent (#6129). Les sessions récentes utilisent une vérification récapitulative indexée (#6132). Les formateurs de date sont réutilisés dans un rendu (#6125).
  • Le rappel à l'échelle du projet arrête une vérification de fusion à la première ligne non adoptée (#6131). Le catalogue du projet supprime les doublons avec les ensembles (#6135). Les requêtes collées depuis longtemps arrêtent l’analyse au plafond de 500 termes (#6147).
  • La lecture intelligente de fichiers trouve le conteneur de chaque symbole avec un index au lieu d'une analyse (#6122).
  • Mon travail indexe les enregistrements de provenance (#6148), les adhésions aux demandes de focus (#6155) et les versions des éléments d'état de travail (#6159) une fois par appel.

Documents

  • Guides Cline CLI et Kilo CLI pour sauvegarder et retrouver des souvenirs via le serveur stdio MCP (#6097, #6114, merci @Kirat0201). Documents : https://docs.claude-mem.ai/cline et https://docs.claude-mem.ai/kilo
  • Les compétences groupées tombent TOUJOURS et les marqueurs OBLIGATOIRES (#6183, merci @jcole666, ferme le #6144 rapporté par @scu-lixiao).
  • La spécification du point de terminaison CMEM Pro définit une portée OAuth write:memory pour l'ingestion de hook (#6099).

CI et tests

  • Les suites Work-View suppriment les dossiers temporaires avec l'assistant de nouvelle tentative partagée (#6094). La voie Windows exécute les deux suites Python et la suite Hermes est réparée (#6095) (merci @DeryFerd).
  • Un test épingle les noms d'événements OpenCode 2.0, donc un événement en amont renommé échoue bruyamment (#6102).
