claude-mem v15.18.4

#claude-mem v15.18.4

Correctifs

  • Claude Code récupère une fois les règles et outils de Claude-mem (#6179). Avant cela, une session Claude Code recevait les mêmes conseils à partir de trois endroits maximum : les instructions du serveur MCP, un bloc de mémoire écrit par le script d'activation local dans CLAUDE.md et une ligne de pointeur vers RULES-AND-TOOLS.md (dont la légende de la chronologie n'a jamais été réellement chargée). Il n'y a désormais qu'un seul chemin. MY-RULES.md, que votre CLAUDE.md importe déjà, se termine par un import de RULES-AND-TOOLS.md, et Claude Code le charge à partir de là.
    • Lorsque cette chaîne d'importation est terminée dans Claude Code, le serveur MCP n'envoie aucune instruction et le hook SessionStart supprime la ligne de pointeur Access Claude-Mem Rules + Tools:. Le serveur ignore ses instructions uniquement lorsque le fichier importé contient exactement le texte qu'il enverrait.
    • Les autres hébergeurs, ainsi que les utilisateurs de Claude Code n'ayant jamais configuré Mes Règles, restent inchangés.
    • Le travailleur ajoute l'importation à un MY-RULES.md existant une fois au démarrage, afin que les utilisateurs actuels l'obtiennent sans rien faire. Il ne crée jamais le fichier. L'écriture de MY-RULES.md garantit également que RULES-AND-TOOLS.md existe, de sorte que l'importation ne pointe jamais vers un fichier manquant.
    • scripts/activate-progressive-memory-local.mjs n'écrit plus le bloc mémoire dans le CLAUDE.md de Claude. Le Codex AGENTS.md le conserve, car AGENTS.md n'a aucune importation.
  • Les points de terminaison de la liste des travailleurs s'arrêtent au décalage de 10 000 (#6083, merci @xunguangzlj-cloud). /api/observations, /api/summaries, /api/prompts, les flux de session et /api/tool-uses étaient utilisés pour transmettre tout décalage directement dans SQLite, où un décalage profond permet à la base de données d'analyser et de supprimer chaque ligne ignorée. Ils répondent désormais à 400 au-dessus de 10 000 avec le même message que celui utilisé par la liste d'emplois. Les flux du spectateur marquent plutôt leur dernière page, de sorte que le spectateur affiche « cette liste s'arrête aux 10 000 éléments les plus récents » plutôt qu'une erreur.
  • Les dossiers dont les noms commencent par deux points restent dans les répertoires exclus (#6062, merci @Afloat16). Un dossier enfant nommé ..cache a été confondu avec un chemin de répertoire parent, il a donc dépassé les exclusions pour les sessions d'observateur, le cache du plugin et le runtime du marché, et un marqueur sous le dossier de configuration de Claude pourrait devenir une racine de projet.
  • Le rapport de coûts utilise votre nom, pas celui du responsable (#6085, merci @MaxWang007). Les vérifications basées sur le nom restantes (« Bloqué sur <nom> », relais, détection par examen humain) prennent le nom de --owner-name, puis ACR_OWNER_NAME, puis git config user.name, et utilisent des modèles sans nom lorsqu'aucun n'est défini. Un prénom seul correspond également, et les noms non latins fonctionnent.

Performances

  • Listes de sessions filtrées par projet plus rapides dans la visionneuse (#6053, merci @Afloat16). Un nouvel index sur le projet, l'heure de début et l'identifiant permet au spectateur de lire une page d'un long historique de projet sans trier chaque session. Les bases de données existantes obtiennent l'index au prochain démarrage du travailleur.
  • Mémoire de pointe inférieure lors du balayage quasi-dupliqué (#6052, merci @Afloat16). Le comptage par paires fonctionne désormais un titre à la fois au lieu de conserver en mémoire chaque paire de titres partagés. Les résultats sont les mêmes.

Documents et exemples

  • Exemple Vercel Chat SDK pour la mémoire de projet explicite (#6084, merci @Kirat0201). Un chat local authentifié par le porteur peut enregistrer une note, rechercher son projet et récupérer une observation. Pas de modèle et pas de capture automatique. Il nécessite le jeu CLAUDE_MEM_WORKER_URL et le guide montre comment trouver le port de votre travailleur.
  • Marque du logo README mise à jour (#6104).
