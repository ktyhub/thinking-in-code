#claude-mem v15.18.3

Correctifs critiques

  • Le Codex continue d'enregistrer après les mises à jour de claude-mem (#6058, merci @wiesenthal). Le Codex approuve un hook fourni dans un plugin par rapport à une empreinte digitale de l'ensemble du dossier du plugin. Chaque mise à jour de claude-mem réécrit ce dossier, donc après chaque mise à jour, le Codex a désactivé les sept hooks claude-mem (« contenu du plugin modifié ; approbation du hook requise ») et les sessions Codex ont cessé d'être enregistrées, sans message. Le programme d'installation enregistre désormais les hooks Codex de claude-mem dans votre propre ~/.codex/hooks.json, et chaque hook exécute le lanceur on-PATH claude-mem, qui trouve lui-même la dernière installation. Le Codex trust est un crochet dans hooks.json par sa propre définition et position, donc une approbation dure désormais entre les mises à jour. Les crochets des autres outils dans ce fichier sont conservés, une deuxième installation ne change rien, un hooks.json qui ne peut pas être analysé est refusé et laissé intact, et la désinstallation supprime uniquement les entrées de Claude-mem. La désactivation du plugin claude-mem dans le Codex arrête toujours la capture. npx claude-mem doctor a une nouvelle ligne Codex hooks qui avertit lorsque le plugin est activé mais que ses hooks sont absents de hooks.json.

    Utilisateurs du Codex : effectuez cette opération une fois après la mise à jour.

    1. Exécutez npx claude-mem install et sélectionnez Codex. npx claude-mem update et la mise à jour automatique ne déplacent pas les points d'ancrage, car les anciens installateurs n'enregistraient aucune sélection d'agent. Le programme d'installation imprime Registered 7 claude-mem hooks in <codex home>/hooks.json.
    2. Ouvrez le Codex interactif, exécutez /hooks et approuvez les sept hooks claude-mem. codex exec ne peut pas demander d'approbation, alors faites-le d'abord dans le Codex interactif.

    Après cela, les mises à jour ne nécessitent plus de nouvelle approbation. Le Codex demande à nouveau uniquement lorsque la définition d'un hook claude-mem change, lorsque claude-mem ajoute un hook ou lorsque le hook d'un autre outil répertorié avant celui de claude-mem est supprimé.

Améliorations

  • Jeton API local facultatif pour le travailleur API et le transport HTTP MCP (#6056, merci @kartik70, ferme le #5141). Ceci concerne les machines avec plus d’un utilisateur de système d’exploitation. Il est désactivé par défaut et rien ne change sauf si vous le définissez. Définissez CLAUDE_MEM_LOCAL_API_TOKEN dans ~/.claude-mem/settings.json et redémarrez le travailleur et le serveur HTTP MCP. Après cela, le travailleur API et le transport HTTP MCP refusent toute requête ne portant pas le token (X-Claude-Mem-Token ou Authorization: Bearer), à l'exception des contrôles de santé. Ouvrez le visualiseur sous le nom /?token=... ou /viewer?token=.... Le token ne peut être défini que dans le fichier : les paramètres API ne peuvent pas le définir ou l'effacer, et il est masqué lors de la lecture. omp, hermes et openclaw n'envoient pas encore le token. Voir « Jeton API local » dans la documentation de configuration.
  • L'avertissement de repli de quota nomme les deux fournisseurs (#6071, merci @bulanovk). Lorsque le remplacement du quota déplace le travail de mémoire vers un autre fournisseur, le journal des travailleurs nomme désormais le fournisseur que vous avez sélectionné et celui qui effectue réellement le travail, indique quand le remplaçant dépense votre compte Anthropic et nomme CLAUDE_MEM_QUOTA_FALLBACK_PROVIDER=off pour le désactiver. La solution de secours par défaut reste inchangée.
  • flow de travail n8n pour sauvegarder et retrouver des souvenirs (#6066, merci @Kirat0201, ferme le #5923). Un flux de travail n8n importable enregistre une note, vérifie que le travailleur a confirmé la sauvegarde, puis la recherche et la récupère dans le projet choisi. Il est inactif jusqu'à ce que vous l'exécutiez et n'ajoute aucune capture automatique. La configuration se trouve dans la nouvelle page de documentation n8n.

Correctifs

  • lecture intelligente (merci @Afloat16) :
    • Les getters et setters portant le même nom se déplient désormais séparément (#6060).
    • Les niveaux de rubrique Markdown sont conservés tels qu'écrits (#6064).
    • Les corps de routine Pascal sont trouvés même lorsque la casse de la déclaration diffère (#6063).
  • Les docstrings Python conservent leurs plages d'instructions (#6057).
    • La source capturée est analysée par lots natifs (#6059).
  • L'analyseur d'observation accepte les espaces XML avant les délimiteurs de balises (#6065, merci @Afloat16).
  • Les exclusions Globstar s'appliquent désormais également aux chemins contenant des terminateurs de ligne (#6061, merci @Afloat16).
  • Rapport sur les coûts : les gains à l'échelle du référentiel ne sont recherchés que lorsque cela est demandé explicitement (#6081), et les relais de pilotage nommés sont reconnus (#6082) (merci @Kirat0201).
  • Le guide d'installation répertorie les vrais minimums Node.js et Bun (#6076, merci @DeryFerd).

CI et tests

  • Les tâches de publication et ods natives épinglent Bun au lieu d'utiliser la version la plus récente (#6075), et CI exécute désormais les vérifications hook-io et spawn-env (#6074) (merci @DeryFerd).
  • Correctifs de test Windows : tentatives de nettoyage du répertoire temporaire, chemins de mémoire par plate-forme et cas de hook de canal en pause ignorés là où Node ne peut pas les exécuter (#6072, #6073, merci @DeryFerd). Le talon de test du hub de synchronisation est saisi de manière à ce que le type du package soit vérifié (#6077, merci @DeryFerd).
  • Le test #4689 env-fallback ne dépend plus d'un vrai login Claude sur la machine (#6068, merci @bulanovk).
