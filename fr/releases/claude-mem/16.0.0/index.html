claude-mem v16.0.0

#claude-mem v16.0.0

Mon travail donne la priorité à ce dont vous avez besoin

Mon travail, la page qui montre ce que font vos agents, a été reconstruite à partir d'un examen complet de l'interface utilisateur (#6210, #6304). Ce dont vous avez besoin se trouve en haut, les longues listes se replient et chaque page fonctionne sur un téléphone, au clavier et avec un lecteur d'écran.

  • Ce dont vous avez besoin passe en premier. Sur la page d'accueil, la première requête qui vous attend est en haut, avec le seul bouton orange sur l'écran. Les requêtes sont des lignes sur une seule ligne ; Les dossiers Idle et Shipped se replient sur une seule ligne chacun, avec leur nombre.
  • Pages plus courtes. Sur une installation réelle : la maison mesure environ 2 600 px de haut au lieu de 5 138 ; la Liste s'ouvre sur 5 lignes au lieu de 195 ; Mes règles font environ 4 400 px au lieu de plus de 17 000.
  • Répondez là où vous lisez. Le tiroir d'une requête place la boîte de réponse juste sous sa ligne de progression, dans chaque état. Pendant qu'une réponse est en cours, « Répondre ici » attend, de sorte qu'un message ne peut jamais être dirigé vers une deuxième conversation comme un deuxième tour payant.
  • La page d'un domaine d'intervention se lit de haut en bas : ce qui a besoin de vous, les demandes qui n'ont pas encore commencé, puis le tableau. Un échec de sauvegarde indique quelle modification a échoué et propose de réessayer sur cet écran uniquement. Le focus passé indique le jour où une zone a été marquée comme terminée.
  • Mes règles : une règle à décider à la fois, avec une orange Approuver. Sur un téléphone, faites glisser votre doigt pour décider.
  • Convient à un téléphone. Chaque page mesure 390 px de large sur un téléphone de 390 px, avec une barre inférieure pour Mon travail, Ma concentration et Mes règles.
  • Clavier et lecteurs d'écran. Chaque contrôle a un nom ; les info-bulles s'ouvrent à partir de l'onglet ; le focus revient là où vous étiez après une boîte de dialogue, le tiroir, Ignorer ou Réessayer ; les commandes sont de 44 pixels au toucher.
  • Thème avant chargement. Votre choix clair ou sombre est dessiné avant la première image, écrans de chargement et d'erreur inclus.
  • Erreurs simples. Un échec correspond à une phrase dans votre langue, avec la raison brute repliée sous Détails. Rien ne réessaye tout seul.
  • Votre langue et votre horloge. Les heures s'affichent dans votre langue à partir de l'heure enregistrée (le français lit une horloge de 24 heures) et un jour d'une autre année affiche son année. Les nouvelles chaînes sont traduites en français, coréen, turc et chinois ; les corrections des locuteurs natifs sont les bienvenues.
  • Moins de mouvement. Une mise à jour en direct déplace au maximum deux choses, et rien ne bouge avec un mouvement réduit.

La télévision d'observation est supprimée

  • La page TV et son accès à distance en lecture seule ont disparu du travailleur open-source (#6295) : /tv, tv.html et le paramètre CLAUDE_MEM_TV_TOKEN. La visionneuse classique et Mon travail restent inchangés. - Si vous avez regardé la télévision depuis un autre appareil : définissez CLAUDE_MEM_LOCAL_API_TOKEN, qui protège désormais l'accès au réseau, et supprimez CLAUDE_MEM_TV_TOKEN. Jusqu'à ce que vous le fassiez, un travailleur qui trouve toujours le jeton TV avec un CLAUDE_MEM_WORKER_HOST sans bouclage et aucun jeton API local se lie à 127.0.0.1 (::1 pour un hôte IPv6) et enregistre une erreur SECURITY, de sorte que le API complet n'est jamais ouvert au réseau sans jeton.
  • La protection du cadrage couvre désormais chaque page desservie par le travailleur.

Déjà expédié en 15.20.0 et 15.21.0

Le reste du même avis vous est parvenu dans 15.20.0 :

  • Configuration : une barre d'étapes, Retour sur chaque écran, erreurs simples et Arrêter l'importation (#6233).
  • Visionneuse classique : une ligne d'en-tête, un sélecteur de projet consultable, "Rechercher dans cette session" et aucune erreur React 185 à la fin d'une longue chronologie (#6229).
  • Importer depuis Mem0 et Supermemory : correctifs d'acceptation (#6206).
  • Corrections : Les sessions Codex Desktop sont lues en direct sur macOS (#6285, merci @MaxWang007), et le travailleur démarre lorsque settings.json n'est pas valide JSON (#6259). 15.21.0 a suivi : le mode Code démarre avec claude-mem activé (#6278), l'effacement automatique reprend avec une invite de continuation (#6294), Hermes Desktop et GitHub Copilot dans VS Code se connectent via MCP (#6284, #6286) et la configuration se termine lorsque votre historique d'invite est trop volumineux pour un téléchargement (#6280). Notes complètes : 15.20.0 et 15.21.0.

Aussi nouveau

  • La bannière SessionStart est une carte dans les terminaux Claude Code (#6274). Sur Claude Code 2.1.326 ou version ultérieure, la ligne Règles + Outils, « Précédemment » et la chronologie sont dessinées comme une seule carte encadrée. Une session reflétée dans l'application Claude affiche une ligne au lieu du nom du crochet devant chaque ligne de la bannière.

Correctifs

  • Le travailleur continue de répondre pendant qu'il travaille sur un retard. Les contrôles de santé, les hooks et le spectateur n'attendent plus :
    • un backlog de hook spool : le drain lit les fichiers par lots parallèles de 64 (#6260, merci @Zhong-fan) et les supprime et les revendique sans blocage (#6296, à partir de #6254 par @Afloat16) ; rapporté dans #6247 par @soarkit ;
    • la liste des projets au démarrage du travailleur, qui lit chaque ligne et lit désormais les index du projet (#6270 ; rapporté dans #6246 par @soarkit) ;
    • le Claude CLI vérifie que l'amorçage du corpus et la requête s'exécutent en cas d'échec du cache (#6256, merci @Afloat16 ; rapporté dans #6250 par @soarkit) ;
    • Le point de contrôle de Chroma sync, qui a été réécrit pour chaque ligne (environ 28 Mo d'écritures pour 2 000 lignes) et est désormais écrit une fois toutes les 250 ms (#6204, merci @Zhong-fan ; rapporté dans #6203 par @soarkit).
  • Fichiers CLAUDE.md de dossier : les mises à jour récupèrent jusqu'à 8 dossiers à la fois au lieu d'un par un (#6264 ; signalé dans #6248 par @soarkit), claude-mem generate lit les observations d'un projet une fois au lieu d'une par dossier (#6265 ; signalé dans #6249 par @soarkit), et une mise à jour de dossier ayant échoué est enregistrée avec son dossier et réessayée par l'observation suivante pour ce dossier (#6208, merci @0xABCD01).
  • La sortie Long Bash garde sa fin (#6292 ; rapporté dans #6282 par @micronox). Lorsque Claude Code découpait une sortie sur environ 30 000 caractères et enregistrait le texte intégral dans un fichier, la mémoire venait uniquement du début, donc les dernières lignes (résumés des tests, erreurs finales) étaient perdues. claude-mem lit maintenant la fin de ce fichier.
  • Notes de mémoire native : une note avec type: en haut de son frontmatter conserve sa catégorie (#6244), et le projet d'une note est trouvé lorsque la première invite de la transcription est longue (#6272), merci @Afloat16.
  • Les sessions récentes incluent les arbres de travail adoptés (#6268, merci @Afloat16). Après la fusion d'un arbre de travail avec son parent, le claude-mem-recent d'OpenClaw n'a montré aucune session précédente.
  • Recherche : Les termes chinois et japonais à l'intérieur de mots non espacés plus longs se trouvent dans les preuves du corpus (#6213, merci @liuyinchu). smart_outline, smart_search et smart_unfold trouvent les fonctions JavaScript définies par affectation, telles que exports.read = function … (#6245), et chaque surcharge de méthode Java se déroule d'elle-même (#6257), merci @Afloat16.
  • Rapports d'erreurs plus silencieux : une lecture contextuelle qui dépasse le délai de lecture de 120 secondes nomme la lecture lente et enregistre un avertissement, pas une erreur (#6255), et sous Windows, une entrée de spool que Windows maintient verrouillée reçoit un avertissement au lieu d'un rapport d'erreur à chaque drain (#6269).
  • Deux échecs qui ont été abandonnés sont maintenant enregistrés (#6302) : l'effacement automatique le dit dans la transcription lorsqu'il n'a pas pu transmettre à Claude sa demande de sauvegarde de l'état de travail, et le serveur enregistre pourquoi /v1/info n'a pas pu lire l'état de recherche de vecteur.
  • Turc : une formulation My Work plus claire et un README turc à jour (#6287, merci @alkank).

Pour les contributeurs

  • Le test de message de validation qui nécessite bash 4 est ignoré sur le bash 3.2 de macOS et s'exécute toujours sur Linux CI (#6297).
