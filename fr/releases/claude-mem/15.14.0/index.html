claude-mem v15.14.0

Mineure Publié9 nov. 2026 Sourcethedotmack/claude-mem Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

#claude-mem v15.14.0

Nouveau

  • Domaines d'intervention dans Mon travail : Mon travail s'ouvre désormais sur un aperçu de vos domaines d'intervention. Chaque zone reçoit une carte avec des illustrations conceptuelles groupées, son objectif et le nombre de demandes en direct ; ouvrez-en un pour voir ses demandes. L’écran de révélation de configuration utilise la même vue. Les illustrations peuvent être définies comme complètes, compactes ou désactivées, et les images sont livrées avec le plugin, donc rien n'est généré ou récupéré au moment de l'exécution (#5652).
  • claude-mem peut se mettre à jour : le travailleur vérifie une fois par jour la version promue dans releases/promoted-release.json et installe uniquement une version plus récente que npm affiche comme publiée par le workflow de publication avec provenance, uniquement pendant votre absence pendant un certain temps. Un échec de mise à jour rétablit la version précédente. npx claude-mem doctor affiche une ligne de mise à jour automatique. Éteignez-le avec CLAUDE_MEM_AUTO_UPDATE=false ; Les propres commutateurs de mise à jour de Claude Code (DISABLE_AUTOUPDATER et amis) le désactivent également. Les nouvelles installations enregistrent le marché avec la mise à jour en arrière-plan de Claude Code désactivée, de sorte qu'un seul programme de mise à jour s'exécute. Voir la nouvelle page de documentation de mise à jour automatique (#5500).
  • Le contexte de démarrage est uniquement la chronologie : le message SessionStart est désormais constitué des lignes d'en-tête suivies de la chronologie, se terminant par l'entrée la plus récente. Les instructions plus longues sur l'état de travail et l'utilisation de la mémoire ont été déplacées vers les instructions du serveur MCP claude-mem. La bannière du terminal a la même forme (#5487).
  • Hooks plus rapides : les hooks s'exécutent à partir d'un petit bundle de hooks uniquement au lieu du bundle de travail complet. Un hook prend environ la moitié du temps et de la mémoire ; une douzaine de hooks parallèles utilisent environ un quart du CPU (#5541, merci @bulanovk).
  • Recherche de preuves d'outils bruts (opt-in, local) : avec CLAUDE_MEM_TOOL_USES_SEARCH_ENABLED=true, un search local avec deep: true examine les entrées et sorties de l'outil stocké lorsque la recherche d'observation ne trouve rien et renvoie les identifiants #T pour get_tool_uses (#5167, merci @ShitK).
  • UI coréenne : la visionneuse, Mon travail, la configuration et Observation TV peuvent être affichés en coréen (#5522, merci @BaeJinSeop).

Confidentialité et sécurité

  • Contexte : les filtres de confidentialité s'appliquent désormais également aux réponses de session précédente affichées au démarrage (#5626).
  • Sauvegardes : Les instantanés SQLite sont créés et lisibles uniquement par vous (#5642).
  • Médias : les téléchargements dans le cloud cessent de démarrer après votre désinscription (#5622).
  • Rédaction : les valeurs d'en-tête des cookies sont expurgées, correspondant à la cale Cowork (#5591, merci @DeryFerd), et la cale Cowork rédige désormais textuellement les formes clés qu'elle a encore envoyées (#5543, merci @DeryFerd).
  • Worker : les routes de lecture qui résolvent un projet depuis cwd sont gardées (#5590, merci @DeryFerd).
  • Auth : les jetons d'accès stockés qui ne sont pas des chaînes sont rejetés (#5506, merci @Kirat0201).
  • Lanceur : La signature macOS est vérifiée avant la mise en place du lanceur (#5503, merci @Kirat0201).
  • Télémétrie : un choix de consentement enregistré est conservé lors de la création des identifiants (#5629).

Installateurs et intégrations

  • Écrit la configuration atomique : Les fichiers de configuration et de hook Codex, OpenCode, OpenClaw, Kimi, Antigravity, Hermes, Grok Bot et OMP sont écrits de manière atomique, donc une installation interrompue ne peut pas laisser un fichier cassé (#5592, #5593, #5594, #5595, #5596, #5597, #5598, #5599, merci @DeryFerd).
  • Curseur : uninstall supprime les hooks et le serveur MCP ajoutés par install --ide cursor (#5584, merci @tanishqbaweja).
  • Installer : les sondes de version de l'outil, les demandes de travail de configuration du navigateur et les processus enfants npm sont limités, et les descendants npm sont terminés en cas d'expiration (#5634, #5638, #5644).
  • Installateur : les installations hôtes existantes sont trouvées dans leurs dossiers configurés, les chemins non exécutables sont ignorés lors de la découverte de l'exécution, le Roo Code est détecté par son ID de marché et un arborescence compatible sur PATH est utilisé lors de la réparation (#5552, #5556, #5560, #5576, merci @Kirat0201).
  • Hooks : les hooks sont distribués via le résolveur de plugin installé (#5504, merci @Kirat0201).
  • OpenCode : un transfert d'observateur en direct limité (#5621). Les résultats de l'outil Pi : sont normalisés à des fins de preuve (#5605). Goose : les chemins des exécutables sont cités dans la configuration YAML (#5606). Devin : seules ses propres entrées de carte d'outils sont traduites (#5512, merci @Kirat0201). Télégramme : les envois sont limités (#5636).
  • Adaptateurs : les échecs explicites des outils sont conservés comme preuve (#5620).
  • DSH : Les résultats d'erreur MCP du travailleur sont transmis et les échecs lors des lectures du corps de la réponse sont correctement classés (#5604, #5619).

Mon travail

  • Les listes sont classées par heure d'activité d'origine, les objectifs du propriétaire sont rejoués dans l'ordre des événements et les titres des conversations sont adaptés à leur plate-forme (#5580, #5589, #5561).
  • Les preuves de groupe obsolètes sont supprimées lorsque les conversations sont déplacées, les entrées de fichiers d'observation non valides sont ignorées, les produits de la branche Git sont attribués à des mises à jour à distance confirmées et les dossiers temporaires Windows supprimés sont reconnus (#5587, #5585, #5533, #5554).
  • Les historiques et catalogues volumineux restent sous les limites de SQLite, les résultats de publication profondément imbriqués sont gérés, les instantanés du grand livre utilisent des écritures atomiques isolées et les révisions livrables qui partagent un hachage court sont conservées (#5588, #5549, #5579, #5582, #5536).
  • La page de règles vide explique qu'elle attend un agent, la première requête en direct est annoncée après une liste vide, et les cartes de recherche en mémoire de configuration montrent l'agent enregistré (#5575, merci @Kirat0201 ; #5564, #5574).

Recherche, contexte et mémoire

  • La recherche intelligente limite la mémoire source et accepte les filtres de chemin portables ; Le classement de l'historique des fichiers et les pages d'index sont plus rapides (#5534, #5586, #5602).
  • La recherche conserve les titres multilignes dans une ligne de tableau, conserve les limites de date de valeur nulle, propage les échecs SQLite avant de remplacer les corpus et conserve les résultats DSH distincts (#5583, #5520, merci @Kirat0201 ; #5610, #5548).
  • Le contexte sélectionne les lignes à temps égal de manière cohérente, applique des filtres de mode sur le serveur, respecte les noms de fichiers littéraux préfixés par ~ et + dans les lectures du shell (#5608, #5623, #5633, #5510, merci @Kirat0201).
  • Les corpus de connaissances conservent les preuves sources et les identités, les opérations qui se chevauchent ne peuvent pas écraser l'état enregistré et les requêtes annulées ne sont pas enregistrées (#5528, #5612, #5648).
  • La navigation intelligente affiche les traits, les implémentations et les définitions de données de Rust (#5531).
  • Les lectures de déduplication sont limitées et le modèle IDF est reconstruit à partir d'un instantané verrouillé (#5632, #5613).
  • CLAUDE.md honore un nombre d'observations nul et claude-md clean conserve l'indentation créée (#5508, merci @Kirat0201 ; #5566).

Sauvegarde, restauration, importation et synchronisation

  • La restauration refuse les instantanés de schéma plus récents et les restaurations effectuées par des travailleurs distants avant de toucher aux données en direct, signale les échanges validés malgré les erreurs de nettoyage, conserve les paires de récupération endommagées et protège le point de restauration sélectionné de la rétention (#5649, #5562, #5624, #5630, #5532).
  • Compte de sauvegarde des pages WAL sur le volume d'instantané (#5627).
  • L'importation conserve la provenance des observations et l'historique du renforcement, accepte une nomenclature UTF-8, indexe les listes héritées de manière cohérente et quitte une valeur différente de zéro lorsque les lignes sont rejetées (#5609, #5518, #5514, #5516, merci @Kirat0201).
  • Sync supprime les vecteurs de réplique après les pierres tombales distantes, actualise les métadonnées vectorielles après les remappages du projet, met en quarantaine les numéros hors plage, rejette les ports mal formés et protège les dossiers exclus dans les répertoires obsolètes du marché (#5647, #5645, #5611, #5573, #5525).
  • Chroma persiste les points de contrôle pour les projets nommés prototypes (#5607). Les exportations Notion restent dans les limites de requête UTF-8 (#5529). L'export de mémoire respecte sa date limite via le corps de la réponse (#5547).

Serveur et CLI

  • Serveur : les achèvements de génération sont mesurés une fois, les corrections de raisonnement restent dans la limite d'envoi payé de la tâche, les changements d'état de génération de l'opérateur sont verrouillés, les routes d'ingestion héritées bénéficient de protections d'utilisation, l'interrogation des événements s'arrête à la déconnexion, le nettoyage d'arrêt se termine après des erreurs et les lectures d'état de la file d'attente sont limitées pendant les pannes Redis (#5640, #5615, #5650, #5641, #5651, #5628, #5617).
  • PostgreSQL : la politique TLS explicite est conservée, les connexions de pool ayant échoué sont récupérées, les écritures idempotentes ignorent l'inférence, les événements relivrés sont liés et le nombre de tâches étendues n'est pas comparé aux totaux globaux (#5637, #5537, #5538, #5546, #5559).
  • CLI : les tâches de génération terminées ne sont pas réessayées, la rotation des clés s'arrête lorsque la recherche de clé précédente échoue, les pools de tâches appartenant à la commande se ferment, les enfants terminés par un signal signalent un échec et la recherche peut interroger un travailleur sans plugin local (#5603, #5618, #5639, #5569, #5568).
  • MCP : le serveur npm MCP se lance lors de la vérification invoquant, un port explicite vide est rejeté, le serveur MCP clients ne voit pas les opérations locales indisponibles et le programme d'installation imprime le point de terminaison MCP du serveur (#5553, #5571, #5551, #5563).
  • Les handles SQLite sont fermés lorsque l'initialisation échoue ; les promesses d'exécution des travailleurs rejetées sont respectées ; Les lectures transitoires du cloud multimédia restent réessayables (#5635, #5616, #5614).
  • Corrections plus petites : les horodatages SQLite hérités affichent la bonne année, Unicode survit au raccourcissement de l'historique des invites, les raisons de saut entre guillemets simples sont acceptées, le pitch d'essai Pro est ignoré pour les comptes déjà en cours d'essai ou Pro, les queues de journal sont diffusées correctement et la génération de contexte de dossier signale un travail incomplet (#5557, #5550, #5558, #5545, #5526, #5565, #5572).

Documents

  • Les README traduits ont des liens et des titres corrigés (#5527, merci @vietmy1711), et deux anciens release note décrivent désormais correctement la synchronisation cloud et la télémétrie (#5577, merci @Kirat0201).

Merci à @Afloat16 pour la grande majorité des correctifs de cette version.
