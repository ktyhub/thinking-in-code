claude-mem v15.13.0

Mineure Publié9 nov. 2026 Sourcethedotmack/claude-mem Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

#claude-mem v15.13.0

Correctif critique

  • Résumés du curseur : Les sessions de curseur n'obtenaient aucun résumé sous Windows natif, ou lorsque le chemin de l'espace de travail contenait un _, un espace ou un dossier de points. claude-mem recherche maintenant la transcription dans le dossier du projet que le curseur nomme, donc ces sessions reçoivent à nouveau des résumés (#5544, merci @tanishqbaweja ; le même symptôme a été signalé pour la première fois dans #2248 par @wbingli).

Nouveau

  • Effacement automatique à 33 % du contexte (désactivé par défaut) : activez-le avec CLAUDE_MEM_AUTO_CLEAR_ENABLED=true. Lorsqu'une conversation Claude Code atteint un tiers de la fenêtre contextuelle, Claude enregistre son état de travail, claude-mem exécute /clear et envoie continue, et la nouvelle conversation reprend le travail. Aucune sauvegarde signifie pas d'effacement (#5486).
  • Standard Compute preset pour le fournisseur compatible openai (#5492, merci @henrikdukefoss).
  • Préglage PopNow pour le fournisseur compatible openai (#5434, merci @kyuminjo).

Correctifs

  • Chroma : la suppression de plusieurs observations à la fois n'accumule plus les nettoyages qui verrouillent chroma-mcp pendant des heures ; ils s'exécutent désormais un par un (#5496, merci @xunguangzlj-cloud ; rapporté dans #5495 par @voyvodka).
  • CLI : claude-mem --help, -h et une utilisation d'impression de commande mal saisie au lieu de démarrer un travailleur de premier plan (#5491, merci @ryrenz ; signalé dans #5490 par @ukdataservices-admin).
  • CLI : --flag=value fonctionne dans server api-key, memory ingest et adopt, donc --scope=memories:read constitue vraiment une clé en lecture seule (#5469, merci @rudycelekli).
  • Docteur : npx claude-mem doctor ne plante plus à la sortie sous Windows (#5465, merci @tng7576650-commits).
  • Connexion CMEM Pro : lorsque cmem.ai refuse un démarrage de connexion sans message, le programme d'installation affiche l'état HTTP au lieu des conseils de connectivité (#5498, merci @xunguangzlj-cloud).
  • Caviardage : les clés du fournisseur imprimées au début d'une ligne dans la sortie de l'outil sont désormais rédigées (#5521).
  • Cowork : la cale Cowork rédige les clés NVIDIA, Runcrate, Groq, xAI et Perplexity que le travailleur rédige déjà (#5483, merci @DeryFerd).
  • Windsurf : l'installateur écrit hooks.json et le fichier de règles de manière atomique, donc une installation interrompue ne peut pas quitter Windsurf avec un fichier de hooks cassé (#5542, merci @DeryFerd).
  • Serveur : les points de terminaison du flux de visualisation sont liés au offset qu'un client peut envoyer (#5485, merci @DeryFerd).
  • Installer : Les fichiers de configuration OpenCode, Kimi et Antigravity enregistrés avec une nomenclature UTF-8 sont lus correctement (#5472, merci @rudycelekli).
  • Lanceur : un ~ au début de CLAUDE_MEM_DATA_DIR est développé lors de l'enregistrement d'une charge utile de hook vide, au lieu de créer un dossier ~ dans le projet (#5473, merci @rudycelekli).
  • Importer : la réimportation d'une exportation conserve les fusions de projets (merged_into_project) (#5471, merci @rudycelekli).
  • DSH : les mémoires d'outils ingérées conservent le platformSource configuré (#5470, merci @rudycelekli).
  • CLAUDE.md : dans un monorepo, les lignes du dossier CLAUDE.md sont dirigées par un fichier qui se trouve dans ce dossier (#5468, merci @rudycelekli).
  • My Work : les commits effectués avec git commit -m "$(cat <<'EOF' ...)" et chaque formulaire de titre gh pr sont lus correctement (#5480, merci @rudycelekli).
  • Recherche : les filtres de fichiers correspondent si les chemins utilisent / ou \ (#5466, merci @liuyinchu).
  • Hermes : les points de terminaison mal formés et les réponses tronquées retombent proprement, les sessions se terminent même lorsque l'événement final échoue et le rappel sur les invites longues s'arrête à la limite de la requête (#5462, merci @Afloat16).
