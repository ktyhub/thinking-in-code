airflow 1.20.0

Mineure Publié22 mars 2026 Sourceapache/airflow Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

Tableau de pilotage du flux d'air/1.20.0

Changements importants

La prise en charge des anciennes versions d'Apache Airflow <2.11 a été supprimée (#61018)

La version minimale prise en charge d'Apache Airflow est désormais 2.11.0. Si vous souhaitez déployer un ancienne version d'Apache Airflow, veuillez utiliser la dernière version publiée du graphique 1.19.0.

Sections workers specific sections have been moved to workers.celery / workers.kubernetes

Veuillez mettre à jour votre configuration en conséquence :

  • workers.command command is now deprecated in favor of workers.celery.command/workers.kubernetes.command (#60067).
  • workers.securityContexts command is now deprecated in favor of workers.celery.securityContexts/workers.kubernetes.securityContexts (#60396).
  • workers.containerLifecycleHooks command is now deprecated in favor of workers.celery.containerLifecycleHooks/workers.kubernetes.containerLifecycleHooks (#61369).
  • workers.kerberosSidecar section is now deprecated in favor of workers.celery.kerberosSidecar/workers.kubernetes.kerberosSidecar (#61881).
  • workers.kerberosInitContainer section is now deprecated in favor of workers.celery.kerberosInitContainer/workers.kubernetes.kerberosInitContainer (#60751).
  • workers.terminationGracePeriodSeconds command is now deprecated in favor of workers.celery.terminationGracePeriodSeconds/workers.kubernetes.terminationGracePeriodSeconds (#61892).
  • workers.nodeSelector command is now deprecated in favor of workers.celery.nodeSelector/workers.kubernetes.nodeSelector (#61957).
  • workers.podDisruptionBudget section is now deprecated in favor of workers.celery.podDisruptionBudget. Veuillez mettre à jour votre configuration en conséquence. (#61414)
  • workers.keda section is now deprecated in favor of workers.celery.keda. Veuillez mettre à jour votre configuration en conséquence. (#61820)
  • workers.resources section is now deprecated in favor of workers.celery.resources and workers.kubernetes.resources. Veuillez mettre à jour votre configuration en conséquence. (#61890)

Les options de configuration précédentes fonctionnent toujours, mais sont obsolètes et seront supprimées dans une prochaine version.

Comme Git-Sync n'est pas un objet de type service, la sonde de préparation sera supprimée. (#62334)

Pour activer le comportement des fonctionnalités, définissez « dags.gitSync.recommendedProbeSetting`` to ``true ». La section elle-même sera supprimée dans les prochaines versions afin de ne pas interrompre les configurations lors des mises à niveau.

Comme Git-Sync dispose d'un service d'activité dédié, le comportement de la sonde d'activité sera modifié. Pour activer le comportement des fonctionnalités, définissez « dags.gitSync.recommendedProbeSetting`` to ``true ».

Veuillez mettre à jour votre configuration en conséquence.

Variables d'environnement automatiques supprimées de container_extra_envs and custom_airflow_environment (#60750)

L'ajout automatique de préfixe pour les variables d'environnement et les secrets de l'exécuteur Kubernetes a été supprimé des deux fonctions d'assistance container_extra_envs and custom_airflow_environment.

Ce qui a changé :

Auparavant, lorsque vous ajoutiez des variables d'environnement à des configurations spécifiques aux composants (par exemple, la section .Values.scheduler.env), the chart automatically created an additional environment variable (to specified in the env section) with the AIRFLOW__KUBERNETES_ENVIRONMENT_VARIABLES__ prefix for Kubernetes Executor worker pods. After this change, only the variable specified in env était créée. De plus, pour les valeurs spécifiées sous « .Values.secret`` section, the ``AIRFLOW__KUBERNETES_SECRETS__`` prefix is no longer automatically added. Secrets are now passed as-is via ``secretKeyRef » sans la copie préfixée pour les pods de travail.

Pourquoi ce changement :

  • Empêchez l'exposition involontaire de données sensibles telles que « client_secret`` information. Previously, due to prefix, it was recognized as internal Airflow configuration leading to unintended exposure in Airflow UI (under Admin -> Configuration), even when ``AIRFLOW__API__EXPOSE_CONFIG`` is set to ``non-sensitive-only ».
  • Évitez la propagation involontaire de l'environnement aux travailleurs : les configurations d'environnement spécifiques aux composants sont destinées strictement à des composants spécifiques. Le comportement précédent entraînait la transmission de ces variables aux pods de travail, ce qui pouvait entraîner des conflits de configuration et des effets secondaires inattendus.

Migration requise :

Si vous devez transmettre des variables d'environnement spécifiquement aux pods de travail Kubernetes Executor, utilisez l'une des approches suivantes :

Option 1 : Utilisez .Values.env

.. bloc de code : yaml

env :
  - nom : ma_var
    valeur : "ma_valeur"

Les variables d'environnement spécifiées sous .Values.env sont désormais transmises telles quelles sans le préfixe automatique (même comportement que l'environnement spécifique au composant).

Option 2 : Utilisez .Values.config.kubernetes_environment_variables

.. bloc de code : yaml

configuration :
  kubernetes_environment_variables :
    ma_var : "ma_valeur"

L'image Airflow par défaut est mise à jour vers 3.1.8 (#63392)

L'image Airflow par défaut utilisée avec le graphique est désormais « 3.1.8``, previously it was ``3.1.7 ».
