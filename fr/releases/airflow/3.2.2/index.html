débit d'air 3.2.2

Changements importants

  • La mise à niveau SMTP STARTTLS effectuée par l'appel airflow.utils.email.send_email now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the starttls() a été effectuée sans contexte SSL, donc tout certificat a été accepté. Les déploiements qui pointent intentionnellement Airflow vers un serveur SMTP avec un certificat auto-signé ou non valide et qui doivent conserver le comportement précédent doivent définir le chemin email.ssl_context = "none" in airflow.cfg. The "default" value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the SMTP_SSL ; cela s'applique désormais également au chemin STARTTLS. (#65346)

  • Dans #64963, l'interface utilisateur d'Airflow est passée des paramètres de correspondance complète *_pattern REST API query parameters to the new index-friendly *_prefix_pattern parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (LIKE 'term%' via a range scan) instead of substring-based (ILIKE '%term%'), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing *_pattern se comportent toujours exactement comme avant. Dans #66015, une bascule « Match n'importe où » par barre de recherche a été ajoutée afin que les utilisateurs qui s'appuyaient sur le comportement de sous-chaîne précédent puissent y revenir à partir de l'interface utilisateur. Chaque entrée de recherche et chaque pilule de filtre de texte ont désormais une petite icône d'expression régulière à côté de la valeur ; en l'inversant sur les commutateurs qui entrent depuis *_prefix_pattern to *_pattern. (#66015)

  • Correction de la condition de concurrence critique du déclencheur et du blocage qui provoquait le blocage indéfini des tâches différées

    Déclencheurs qui appellent des méthodes synchrones SDK (par exemple get_task_states utilisé par safe_to_cancel chez plusieurs opérateurs de fournisseurs Google) pourrait faire planter le déclencheur sous-processus interne. Le déclencheur continuerait alors à battre normalement – semblant sain pour le planificateur - tout en traitant silencieusement zéro déclencheur, provoquant chaque tâche différée expire. Cela a été signalé pour la première fois dans le numéro 64620 ; un correctif partiel livré dans Airflow 3.2.1 (#64882) mais a introduit un nouveau blocage avec le même symptôme visible sous charge.

    Les deux problèmes sont résolus en remplaçant la sérialisation basée sur le verrouillage par une réponse multiplexage : chaque requête porte désormais un identifiant unique et la réponse est renvoyée vers le bon appelant, donc les requêtes simultanées des threads déclencheurs ne sont plus en conflit ou blocage, quel que soit le nombre de déclencheurs en cours d'exécution ou les méthodes SDK qu'ils appellent.

    Nouveau : chien de garde du sous-processus du déclencheur

    Même si la course est corrigée, un déclencheur qui bloque la boucle d'événements (par exemple en appelant time.sleep() or performing blocking I/O directly in async def run()) serait laissez auparavant le déclencheur apparaître sain indéfiniment.

    Une nouvelle option de configuration [triggerer] runner_health_check_threshold (par défaut : 30 secondes) ajoute un chien de garde : si le sous-processus déclencheur reste silencieux pendant une durée supérieure au seuil, le processus parent arrête de mettre à jour le battement de cœur afin que le planificateur puisse détecter le blocage et réaffectez les déclencheurs plutôt que d'attendre qu'ils expirent individuellement. Définir l'option à 0 pour désactiver le chien de garde. (#66412)

  • Resserrez [core] allowed_deserialization_classes_regexp pour exiger des correspondances de chaînes complètes

    Les modèles dans [core] allowed_deserialization_classes_regexp correspondent désormais contre le nom de classe entier en utilisant re.fullmatch() instead of re.match(). Auparavant, un modèle tel que airflow\.models\.Variable admettait non seulement la classe prévue mais aussi les noms qui commencent par elle (par exemple, airflow.models.Variable_Malicious), because re.match ancre uniquement au début de la chaîne.

    La valeur par défaut de cette option est vide, les déploiements prêts à l'emploi sont donc non affecté. Déploiements qui ont configuré cette option avec des modèles s'appuyant sur sémantique de correspondance de préfixe — par exemple airflow\.models\. pour signifier "n'importe quelle classe sous airflow.models" — must add .* au motif (airflow\.models\..*) pour conserver le comportement précédent. (#66499)

  • Les classes de référence de date limite personnalisées doivent désormais être enregistrées via le nouveau « deadline_references`` attribute on ``AirflowPlugin``, matching the existing pattern for custom timetables and custom partition mappers. To use a custom ``DeadlineReference`` subclass, register it in a plugin's ``deadline_references`` list. Custom references that are not registered will raise ``DeadlineReferenceNotRegistered » lors de la désérialisation. (#66737)
