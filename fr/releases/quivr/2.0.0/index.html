quivr v2.0.0

Quivr 2.0.0

Quivr est un moteur open source pour du contenu qui arrive sans cesse. Votre application, ou les sources de Quivr (RSS, boîtes mail Microsoft 365, listes X), lui envoient des documents. Quivr conserve chaque version de chaque document et le rend consultable en quelques secondes, par mots-clés, par signification, ou les deux. Il vérifie également chaque nouveau document par rapport à vos alertes enregistrées. Quivr n'a pas d'interface utilisateur : votre application lui communique via un HTTP API et les agents IA l'utilisent via quivr mcp.

2.0.0 est la première version stable du Quivr réécrit. Les alphas étaient destinés à l'évaluation. À partir de cette version, Quivr fait des promesses sur lesquelles vous pouvez vous appuyer.

Ce que promet le 2.0

  • Un API stable. Le HTTP API conserve le chemin /v0 pour chaque version 2.x. Une version 2.x n'y ajoute que : de nouveaux points de terminaison, des champs facultatifs, des champs de réponse et des valeurs d'énumération. Un changement qui pourrait interrompre le fonctionnement d'un client attend la prochaine version majeure.
  • Mises à niveau qui conservent vos données. Une mise à niveau d'une version 2.x à une autre exécute quivr migrate, puis lance le Worker et le API, avec vos données en place.
  • Plugins qui vérifient leur compatibilité. Un plugin déclare les versions du Plugin API qu'il supporte, et Quivr refuse d'en activer une qu'il ne peut pas exécuter.
  • État clair pour chaque fonctionnalité. Tout dans la documentation est stable dans 2.x à l'exception d'une courte liste de fonctionnalités expérimentales, chacune marquée sur sa page : outils de mesure de recherche, alertes de reclassement Jev et de jugement Jev, l'hôte vectoriel dédié et le binaire quivr-autoscaler.

[Versions et compatibilité] (https://docs.quivr.thevibecompany.co/reference/compatibility) contient les détails. Limites connues répertorie ce que 2.0 ne fait pas encore : il recherche uniquement du texte, n'a pas d'OCR, n'a pas de compte utilisateur et a des limites de taille par document et par recherche.

Commencer

  • Essayez-le localement : clonez le référentiel, lancez make dev, puis suivez le Quickstart, une quinzaine de minutes.
  • Installez-le sur un serveur à partir des images de version signées (linux/amd64) : voir Exécuter Quivr sur une machine ou Déployer et configurer Quivr pour Railway et Kubernetes.
  • Comprenez-le d'abord : Concepts de base et Comment fonctionne Quivr.

Provenant d'un alpha 2.0.0

La mise à niveau d'une installation alpha sur place n'est pas prise en charge. Démarrez une nouvelle installation de 2.0.0 ou exportez vos documents depuis l'alpha et envoyez-les vers la nouvelle.

Depuis 2.0.0-alpha.7

  • Sécurité :
    • Quivr et ses images sont construits avec Go 1.27.3, pour CVE-2026-111943 ;
    • golang.org/x/net, certifi, pillow et curl et brotli de l'image SeaweedFS sont corrigés.
  • Search récupère après un redémarrage de la base de données, avec ses tampons restaurés et son travail d'hydratation limité.
  • Importations :
    • le nombre de files d'attente reste disponible pendant les importations continues ;
    • L'autoscaler ajoute des Bulk Workers pour les importations de connecteurs.
  • Documentation :
    • réécrit pour les nouveaux arrivants, avec de nouvelles pages : Fonctionnement de Quivr, un glossaire, Versions et compatibilité, et Limites connues ;
    • les avertissements "étape d'évaluation" ont disparu.

La liste complète des modifications depuis la première version alpha se trouve dans CHANGELOG.md.
