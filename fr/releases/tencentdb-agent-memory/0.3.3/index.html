TencentDB-Agent-Mémoire v0.3.3

[0.3.3] - 2026-05-08

🚀 Nouvelles fonctionnalités

  • Compression de mémoire à court terme (Déchargement de contexte) : Ajout du module de déchargement pour prendre en charge la compression de contexte et le déchargement de mémoire dans les scénarios de dialogue longs
  • Reconstruction de l'architecture : adaptation noyau + multi-framework : refactorisée en couche principale + mode adaptateur indépendant de l'hôte TdaiCore, découplage des dépendances du framework OpenClaw ; nouvelle interface abstraite HostAdapter / LLMRunner
  • Hermes Gateway Adaptation : ajout de l'adaptateur Hermes Gateway (memory_tencentdb Hermes Plugin) pour prendre en charge un fonctionnement indépendant via le framework Hermes ; Découverte automatique de passerelle sans configuration
  • Patch automatique de déchargement : appliquez automatiquement le correctif after_tool_call lorsque le déchargement démarre et désactivez automatiquement le déchargement lorsque le correctif échoue.
  • L0 Capture Filter : exclut les blocs de contexte MMD injectés par déchargement pour éviter de stocker par erreur les produits intermédiaires de compression en mémoire.
  • Optimisation de l'injection de rappel (compatible avec le cache) : le rappel L1 est déplacé de appendSystemContext vers prependContext pour éviter une interruption du cache d'invite causée par des modifications des mots d'invite du système à chaque tour.
  • Délai d'expiration du scénario d'intégration : ajout de embedding.recallTimeoutMs / embedding.captureTimeoutMs, le délai d'expiration du rappel est automatiquement rétrogradé vers une recherche par mot clé pure
  • Auto-réparation de la passerelle : Le plug-in Hermes ajoute un mécanisme de surveillance + sonde paresseuse pour récupérer automatiquement lorsque la passerelle est anormale.
  • Outil de gestion des opérations et de la maintenance : Ajout de l'outil de gestion en ligne de commande memory-tencentdb-ctl, prenant en charge deux modes de fonctionnement : autonome et hermes.
  • Compatible avec la politique d'autorisation de hook OpenClaw v2026.4.23+ : Ajout de ensurePluginHookPolicy() pour détecter et compléter automatiquement la configuration de allowConversationAccess
  • Support Docker : Ajout de l'image Docker intégrée Hermes + Memory, une ligne de commandes pour démarrer l'agent Hermes avec capacité de mémoire

✨ Améliorations

  • Le répertoire de données et le répertoire d'installation sont unifiés en ~/.memory-tencentdb/
  • Introduire la variable d'environnement $HERMES_HOME et supprimer le chemin ~/.hermes codé en dur
  • CleanContextRunner remplace le mot d'invite système par défaut par systemPromptOverride, économisant ainsi environ 4 500 jetons d'entrée pour chaque appel L1/L2/L3
  • L'invite L2/L3 est divisée en systemPrompt + userPrompt, avec une division des rôles plus claire
  • Réglage des paramètres par défaut du pipeline : l1IdleTimeoutSeconds 60→600s, l2MinIntervalSeconds 300→900s, l2MaxIntervalSeconds 1800→3600s
  • Les scripts d'exploitation et de maintenance restent dans l'archive tar mais ne sont plus enregistrés en tant que commandes bin, réduisant ainsi la pollution globale des commandes.
  • journal du cycle de vie d'initialisation/destroy rétrogradé au niveau de débogage
  • Ajout de la configuration de build tsdown pour générer dist/index.mjs afin de répondre à la nouvelle version de vérification de l'installation d'OpenClaw
  • L'instruction activation.onStartup garantit que le plugin est chargé au démarrage de la passerelle
  • Déclarer contracts.tools pour enregistrer le nom de l'outil et répondre aux exigences du contrat d'enregistrement de l'outil

🐛 Correction

  • Correction du problème de condition de concurrence sous les appels simultanés de ensureSchedulerStarted
  • Correction de l'erreur /session/end lors de la destruction du planificateur global (changé en portée session_key)
  • Correction du problème de ne pas attendre la fin de la tâche de déclenchement et d'oubli en arrière-plan lors de la fermeture du magasin
  • Correction du problème selon lequel disable_offload ne supprimait pas correctement la configuration slots.contextEngine
  • Logique de détection d'occupation des emplacements fixe : rejeter uniquement lorsque l'exception ok=false, API ne sera plus considérée à tort comme un conflit
  • Correction du problème où la compression agressive/d'urgence restait bloquée lorsque le message utilisateur était en tête de la file d'attente.
  • Correction du problème de blocage de la compression des messages après un grand nombre de déchargements
  • Correction du conflit de concurrence pullProfilesToLocal provoquant l'erreur ENOTEMPTY
  • Correction d'une rupture de liaison de données originalUserMessageCount empêchant l'enregistreur L0 de localiser les messages utilisateur contaminés.
  • Correction du champ prependContext manquant dans la définition du type RecallResult
  • Correction du problème qui provoquait la fermeture du script lorsque ((VAR++)) dans l'environnement set -e avait VAR=0 -Correction du problème selon lequel le processus enfant Gateway ne se terminait pas à la sortie d'Hermes
  • Logique de décision de version de hook-policy renforcée, les versions non standard seront ignorées pour éviter les erreurs d'écriture des configurations

♻️ Refactorisation

  • Logique de détection de correctif unifiée : déléguez toujours au script de correctif et déterminez le résultat par code de sortie
  • TdaiCore fournit un API unifié : handleBeforeRecall() / handleTurnCommitted() / searchMemories()
  • La propriété du répertoire de données est passée du plugin à la gestion de la couche passerelle
