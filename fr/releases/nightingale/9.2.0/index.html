nightingale v9.2.0

Mineure Publié11 oct. 2026 Sourceccfos/nightingale Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

#rossignol v9.2.0

Ce qui a changé

  • exploit : les canaux de notification natifs Jira, Discord, JSM Alert, Slack et Mattermost (#3408) et les configurations des canaux de notification peuvent référencer des variables utilisateur (#3349)
  • exploit : les panneaux du tableau de bord peuvent mélanger les sources de données — chaque cible de requête porte sa propre source de données, soutenue par une nouvelle requête par lots multi-sources de données v2 API avec prise en charge KQL (#3292)
  • exploit : liens de partage de tableau de bord anonymes et limités dans le temps, plus une vue plein écran en lecture seule avec des commutateurs d'URL pour masquer l'en-tête et les variables (#3345)
  • exploit : réécriture de l'importation du tableau de bord Grafana – un rapport de conversion montre ce qui a été migré et ce qui n'est pas pris en charge avant d'enregistrer
  • exploit : les variables de requête du tableau de bord prennent en charge les options d'étiquette/valeur et les macros temporelles Doris SQL ; Les tableaux de bord Grafana (iframe) intégrés synchronisent la plage de temps et l'intervalle d'actualisation
  • exploit : les comptes utilisateurs peuvent être désactivés et réactivés sans perdre leurs rôles, équipes et autorisations (#3395)
  • exploit : la connexion OAuth2 peut attribuer des équipes par défaut aux nouveaux utilisateurs (#3406), et /login?sso=xxx redirige directement vers le fournisseur SSO donné
  • exploit : le contenu intégré prend en charge des langages arbitraires ; ja / ru / pt-BR / es / id / ko / fr ajouté sur le backend, et pt-BR / es / id / ko / fr ajouté à la console (#3352)
  • exploit : noms de gravité d'alerte personnalisés, vue en direct en plein écran pour les événements d'alerte actifs et filtrage des événements d'alerte historiques par hachage (# 3392)
  • exploit : une page Nightingale AI agrégée avec des conversations renommables et partageables (#3325) ; l'assistant IA peut distribuer des tâches de script via ibex (#3378)
  • exploit : guide d'intégration du centre d'intégration (modèle de collecte → tableau de bord → règle d'alerte) ; nouvelle intégration x509_cert, modèle de collecte Rabbitmq_exporter et règles d'alerte d'état de l'appareil SNMP (#3394, #3348)
  • exploit : 403 réponses s'affichent sur place au lieu de rediriger vers /403, donc l'URL survit et le retour fonctionne
  • exploit : entrée de connexion à la démo sans mot de passe pour les sites de démonstration publics, désactivée par défaut (#3426) — voir Notes
  • performances : le chat AI rend la démarque de manière incrémentielle et l'amplification de l'écriture du magasin de tâches A2A est réduite d'environ 30 x (#3413)
  • sécurité : fermez un contournement de garde SSRF via 6to4 / NAT64 / adresses IPv6 locales du site (#3364), rédigez les informations d'identification intégrées dans les URL de source de données (#3424), validez les noms de base de données/table TDengine (#3423), resserrez la portée du jeton de partage du tableau de bord (#3368) et mettez à niveau les dépendances vulnérables (#3419, #3422)
  • correctif : l'initialisation de la clé de configuration converge désormais entre les instances, corrigeant une boucle 401/login dans les déploiements multi-instances (#3385)
  • correctif : un modèle cron de règle non planifiable ne plante plus n9e / n9e-edge / n9e-alert à chaque redémarrage, et les modèles cron sont validés à la sauvegarde (#3407)
  • correctif : les alertes muettes qui ne sont pas encore actives sont désormais synchronisées dans le cache du moteur (#3386), et les balises muettes vides sont normalisées (#3425)
  • correctif : renseigner le temps de récupération avant de distribuer les événements d'alerte (#3382)
  • correctif : les canaux de rappel peuvent notifier sans modèle de message (#3350)
  • correctif : les sources de données désactivées peuvent toujours être interrogées et sont maintenues hors des cibles d'écriture
  • correctif : une ligne VictoriaLogs surdimensionnée n'échoue plus toute la requête (#3344)
  • correctif : les sources de données PostgreSQL utilisent la base de données configurée lors de l'initialisation du client (#3367)

points forts de la v9

  • Présentation de Nightingale AI : un assistant IA intégré, un marché de compétences, une gestion de la configuration LLM et des recommandations rapides basées sur les pages
  • Une base de données de séries chronologiques intégrée qui fonctionne immédiatement, de sorte que les configurations à petite échelle n'ont plus besoin d'un Prometheus/VictoriaMetrics séparé
  • Menu de navigation repensé, disposition globale et interface utilisateur des tableaux
  • Règle d'alerte / règle de mise en sourdine / règle d'abonnement / formulaires de règle de notification entièrement reconstruits
  • Gestion des canaux de notification retravaillée
  • Une nouvelle page de suivi de l'exécution du pipeline d'événements qui montre le traitement en détail
  • Une nouvelle génération d'explorateur de journaux avec prise en charge unifiée de Elasticsearch, Loki et VictoriaLogs

Étapes de mise à niveau

Remplacez le binaire et le répertoire integrations, puis redémarrez. Pour récupérer les nouvelles descriptions de métriques dans les langues ajoutées, remplacez également etc/metrics.yaml.

Modifications du schéma (ignorez ceci si votre compte de base de données peut créer des tables)

Nightingale les applique pour vous au démarrage. Si le compte de base de données auquel Nightingale se connecte ne peut pas modifier les tables, exécutez-les manuellement : le DDL est à https://github.com/ccfos/nightingale/blob/main/docker/migratesql/migrate.sql.

ALTER TABLE `source_token` ADD COLUMN `note` varchar(255) NOT NULL DEFAULT '' COMMENT 'note';
ALTER TABLE `source_token` ADD KEY `idx_source_token_token` (`token`);
ALTER TABLE `users` ADD COLUMN `disabled` int NOT NULL DEFAULT 0 COMMENT '0:enabled 1:disabled';

PostgreSQL :

ALTER TABLE source_token ADD COLUMN note varchar(255) NOT NULL DEFAULT '';
CREATE INDEX idx_source_token_token ON source_token (token);
ALTER TABLE users ADD COLUMN disabled int NOT NULL DEFAULT 0;

Remarques

  • Le nouvel assistant IA s'appuie sur Redis Streams, donc Redis 5.0 ou version ultérieure est requis (Redis 7.0+ recommandé pour les utilisateurs de cluster, pour activer Pub/Sub fragmenté)
  • Remplacer uniquement le binaire n'active pas le TSDB intégré : la section [EmbeddedTSDB] n'existe que dans le nouveau etc/config.toml, donc le transfert d'un ancien fichier de configuration laisse la fonctionnalité désactivée - copiez la section sur vous-même. Il est géré uniquement par le processus central (n9e-edge / n9e-alert / n9e-pushgw l'ignore et enregistre un avertissement), et les données se trouvent sur le disque local de cette instance centrale, elles conviennent donc uniquement aux déploiements à instance unique ; avec plusieurs répliques centrales, utilisez plutôt une TSDB externe
  • Les utilisateurs de Telegraf doivent ajouter ignore_host=false à l'adresse d'écriture des métriques, sinon les hôtes exécutant Telegraf ne s'inscriront plus dans la liste des hôtes.
  • Si vous exécutez n9e-edge ou n9e-pushgw, mettez-les à niveau avec n9e
