Papierclip v2026.1023.0

Sortie : 2026-10-23

Paperclip v2026.1023.0 comporte 200 commits, promus à partir de 2026.1012.1-beta.0. Le titre est travail privé : une tâche ou un projet peut désormais être marqué comme privé et partagé avec des personnes et des agents nommés ; tout le monde ne peut pas l'ouvrir, le trouver dans les listes de tâches ou effectuer une recherche, lire ses transcriptions d'exécution ou y accéder via un plugin. À ce sujet : les agents peuvent utiliser votre propre passerelle modèle (OpenRouter, Amazon Bedrock, Google Gemini ou tout autre point de terminaison OpenAI Responses, Anthropic Messages ou Chat Completions), les robots Slack se configurent via le manifeste API de Slack, le robot d'évaluation GitHub bénéficie d'une configuration à deux écrans et d'une véritable vérification de l'état Paperclip Review, les coûts deviennent un registre exact qui indique également les frais d'abonnement mensuels, et les assistants connectés peuvent modifier des tâches, télécharger des fichiers et configurer des agents via MCP. En dessous, OpenAI Dot et Pi 1.0 rejoignent le Runner expérimental, les flux OpenCode natifs au fur et à mesure de sa saisie, chaque agent obtient une identité cryptographique persistante et les instances inactives cessent d'interroger la base de données toutes les secondes.

Modifications radicales

  • Les opérateurs peuvent désormais modifier l'entreprise. Le préréglage du rôle d'opérateur passe d'une subvention (tasks:assign) à quatorze : création et configuration d'agents, compétences, environnements, invitations, affectation de tâches, pipelines, connexions, gestion et utilisation des outils et lectures d'audit. Les opérateurs existants récupèrent les subventions manquantes via le démarrage normal ; les étendues de subvention personnalisées sont conservées. L'approbation de l'adhésion et la gestion des autorisations des membres restent en dehors des préréglages, et l'invitation d'un administrateur nécessite désormais l'approbation de l'adhésion, tandis que l'invitation d'un propriétaire nécessite également la gestion des autorisations des membres. Passez en revue vos rôles de membre si les opérateurs étaient destinés à être principalement lus. (#15377)
  • Les robots d'évaluation GitHub se déplacent derrière leur propre paramètre expérimental. L'entrée de catalogue GitHub Code Review Bot, sa configuration et ses écrans de gestion apparaissent uniquement lorsque Paramètres → Expérimental → Bots d'évaluation GitHub (enableGitHubReviewBots, désactivé par défaut) est activé ; les robots existants continuent de fonctionner pendant qu'il est éteint. Les anciens écrans de méthode de configuration et d'agent délégué ont disparu, et les indicateurs d'exécution automatique par personne sont remplacés par des filtres d'inclusion/exclusion d'auteur (les anciennes valeurs people[].automaticReviews sont lues mais ignorées). (#15416)
  • Les budgets sont maintenus par défaut sur une utilisation non tarifée. Chaque stratégie budgétaire bénéficie d'un paramètre d'utilisation non tarifée qui est par défaut block : même si l'utilisation d'une exécution n'a pas de prix fiable, la stratégie compte comme à sa limite jusqu'à ce que les frais soient résolus via le flux d'ajustement des coûts audité. Définissez la stratégie sur allow pour continuer à fonctionner avec une utilisation non tarifée. (#14997)

Faits saillants

  • Tâches et projets privés — Marquez une tâche comme privée lorsque vous la créez, ou rendez un projet privé avec sa propre liste de membres ; un projet privé personnel est créé pour vous dès la première utilisation. Le travail privé n'est lisible que par son utilisateur responsable, son créateur, son cessionnaire actuel, ses bénéficiaires nommés et ses membres du projet privé, et cette règle s'applique aux listes de tâches et au nombre de tâches, à la recherche, à l'activité, aux détails d'exécution, aux transcriptions, aux événements et aux journaux, aux documents, aux pièces jointes, aux produits de travail et à chaque plug-in lu. Deux surfaces restent intentionnellement à l'échelle de l'entreprise : les totaux du tableau de bord et de la barre latérale peuvent compter le travail privé sans exposer de titre ou d'identifiant, et la liste d'exécution de l'entreprise affiche une ligne verrouillée pour l'exécution d'une tâche privée avec uniquement les champs d'agent, de statut, de timing, de jeton et de coût, afin que la surveillance budgétaire continue de fonctionner. La vie privée se répercute sur les enfants ; partager un enfant n’expose jamais ses parents ou ses frères et sœurs. Les propriétaires et les administrateurs ne voient pas les tâches privées par défaut et doivent demander ?breakGlass=true, qui écrit une ligne d'audit et un avis d'avertissement sur la tâche. L'accès des agents est croisé avec l'utilisateur responsable de l'exécution, donc la réutilisation d'un agent n'entraîne pas les autorisations d'une autre personne. (#14717, #10633, #14718)
  • Apportez votre propre passerelle de modèle — Les connecteurs gagnent des lignes pour OpenRouter, Amazon Bedrock, Google Gemini et les réponses génériques API, les messages API, les terminaisons de chat API et les points de terminaison locaux. Les URL, le protocole, la région et les informations d'identification sont en direct sur la connexion ; la page Harnais/Exécution de l'agent sélectionne une Connexion compatible dans une liste déroulante et le sélecteur de modèle accepte les ID manuels. Codex (hérité et Runner) achemine vers les points de terminaison OpenRouter ou les réponses personnalisées, Claude (hérité et Runner) vers OpenRouter, les points de terminaison de messages personnalisés ou Bedrock, et OpenCode et Hermes vers OpenRouter ou les points de terminaison de complétion de chat personnalisés. Les connexions OpenRouter sans liste de modèles explicite chargent le catalogue public d'OpenRouter. (#14970, #15341)
  • Les robots Slack se configurent eux-mêmes — Le nouveau robot Slack utilise par défaut la configuration automatique : collez un jeton de configuration d'application temporaire, Paperclip crée l'application via le manifeste API de Slack, l'installe via OAuth, associe votre compte Slack, télécharge l'avatar de l'agent et vérifie la livraison dans un assistant à quatre écrans sans impliquer Slack CLI. (#15413). Un nouveau paramètre Require at-mention empêche les réponses du thread de réveiller l'agent sans mention explicite (#15612) ; un suivi envoyé après un Slack Stop démarre un nouveau virage au lieu de caler (#15737) ; et les agents Slack connaissent désormais la commande slash enregistrée que les gens utilisent pour lier leurs comptes, lier chaque tâche qu'ils créent, et rapporter les résultats et réviser les demandes dans le fil de discussion d'origine (#15576, #15579, #15611).
  • Un robot d'évaluation du GitHub à deux écrans — La configuration consiste désormais à choisir un agent, puis à connecter le GitHub sous un compte personnel ou une organisation ; GitHub demande le consentement de création et d'installation, et Paperclip stocke les secrets de l'application localement, importe l'accès au référentiel et vérifie la livraison. Chaque demande acceptée reçoit un commentaire de progression modifiable appartenant à l'application, et les évaluations de révision publient une vérification Paperclip Review pour la validation examinée avec une note de réussite configurable (1 à 5) que la protection des succursales peut exiger. Une instance auto-hébergée nécessite une approbation Paperclip Cloud avant sa première connexion GitHub gérée, car Cloud héberge le rappel OAuth fixe et la boîte de réception du webhook signé ; les jetons sont scellés sur votre instance. (#15416)
  • Coûts que vous pouvez rapprocher — La comptabilité est désormais un grand livre durable et exact : les reçus d'utilisation sont synchronisés et rejoués après des échecs, les nouvelles tentatives de règlement d'une charge, les montants conservent les centimes décimaux et chaque événement est marqué comme signalé, estimé ou sans prix au lieu de zéro silencieusement (#14991, #14997). La page Coûts indique les frais mensuels de chaque abonnement ChatGPT ou Claude connecté une fois à côté des dépenses API, vous permet de saisir le prix réel et maintient les forfaits ambigus sans prix (#15634) ; les lectures de quotas sont limitées aux comptes d'entreprise autorisés (#14994) ; les écarts de coûts sont répertoriés par agent avec des liens vers les exécutions concernées, le modèle que le runtime réellement sélectionné est enregistré et une nouvelle tentative apparaît uniquement lorsque les preuves enregistrées sont prêtes (#15948) ; et les écarts de prix historiques apparaissent sous la forme d'une note neutre sous les totaux plutôt que d'une erreur rouge (#15459).
  • Des assistants capables de faire plus via MCP — Un assistant Claude Code, Codex ou autre MCP connecté peut désormais modifier des tâches, les terminer ou les bloquer, rédiger des documents et des révisions, enregistrer des livrables, télécharger des fichiers via des tickets expirant et, avec une étendue de configuration autorisée séparément, gérer les paramètres et les instructions de l'agent, les projets et les référentiels, ainsi que les compétences (#15380). Les connexions sont nommées par le propriétaire et client (« connexion Codex de Dotta ») avec l'avatar de la personne autorisant, les lignes révoquées disparaissent et l'invitation copiée est plus courte (#15411).
  • Seize applications supplémentaires dans le catalogue — Gauge (#15596), Superagent (#15394), recherche Web Telem.AI (#15379), Enterpret (#13906), Calendly, Exa, Firecrawl, GSC Wizard, Parallel Search, Tavily et Windsor.ai (#15621) et Bitly, Context7, Hugging Face et Resend (#15686) se joignent en tant que connexions MCP hébergées vérifiées. La connexion Sentry découvre OAuth via ses métadonnées de ressources MCP, de sorte que l'installation ne demande plus un identifiant et un secret client (#15837), et les autorisations OAuth enregistrent désormais si chaque étendue provient du fournisseur ou de la demande de Paperclip (#14059).
  • Nouveaux fournisseurs Runner — OpenAI Dot rejoint OpenAI Dot en tant qu'agent expérimental autonome : associez votre Dot à un code à usage unique, et Runner délivre des missions sur les événements MCP tandis que Dot utilise ses propres outils et rend compte (#15402, #15414, #15581, #15734). Pi 1.0 exécute le Runner expérimental avec une sélection explicite de fournisseur et de modèle (#14921), et l'intégration de Cursor Runner est consolidée sur le comportement de récupération principal avec un chemin d'installation public (#15075).
  • Codex et OpenCode qui viennent de démarrer — Native Codex utilise le Codex CLI installé et accepte les versions utilisables, anciennes ou plus récentes, donc une installation propre de npm n'a plus besoin d'une commande globale (#15555) ; un modèle pour lequel le Codex CLI du bac à sable est trop ancien est remplacé par un modèle compatible avec un avertissement visible au lieu d'échouer à chaque tour (#15399, #15519) ; les exécutions enregistrées survivent aux mises à niveau du serveur (#15518) ; et les variables d'environnement de tâche atteignent des tours ultérieurs et des commandes d'outils (#15451). L'OpenCode natif diffuse le texte dès son arrivée (#15708), démarre sans le script de post-installation ignoré par les gestionnaires de packages (#15702) et sélectionne les actifs Linux fournis pour les exécutions à distance sans remplacement de chemin (#15721).
  • Rapports que vous pouvez ouvrir sur la tâche : les pièces jointes HTML et les fichiers .html de l'espace de travail s'affichent dans un bac à sable d'origine opaque avec des contrôles d'affichage de la source et de téléchargement (#15447), et les fichiers CSV s'ouvrent sous forme de tableaux avec des numéros de ligne, des en-têtes collants et un nombre d'enregistrements (#15445).
  • Provenance et attentes de tâches plus claires — Une tâche de suivi qu'un agent crée alors qu'il travaille sur une tâche est désormais par défaut cette tâche comme parent, et la page de la tâche affiche « Créé à partir de <tâche> par <agent> » (#15762) ; les agents natifs peuvent planifier leur propre moniteur de tâches ponctuelles et céder jusqu'à ce qu'il se déclenche (#15446) ; la carte moniteur reçoit un X avec une confirmation (#15735) ; et une demande d'extraction enregistrée reste visible dans Propriétés avec sa demande de révision et une action Vérifier l'état même lorsque la recherche du fournisseur échoue (#15375).
  • Votre agent principal — Chaque personne reçoit un agent principal par entreprise, affiché avec une couronne sur la liste et utilisé comme solution de secours pour les nouvelles tâches et le chat lorsqu'il n'y a pas de choix récent ; le premier agent que vous créez devient automatiquement principal et peut être modifié sur le profil d'agent (#15470).
  • Modèles de décision d'entreprise et réponses rapides — Les paramètres de l'entreprise peuvent lier une connexion partagée OpenAI ou OpenRouter API pour de petites décisions de modèle typées, avec des contrôles d'autorisation, des réservations budgétaires et un historique des coûts → Décisions (#15473). De plus, Réponses rapides expérimentales publie un court commentaire d'accusé de réception dans les trois secondes suivant un message humain pendant que l'agent démarre son exécution normale, dans les tâches, la conversation d'agent et les threads Slack et GitHub (#15748).

Correctifs

  • Espaces de travail et bacs à sable : un échec transitoire de copie du bac à sable est tenté jusqu'à trois fois avant que la tâche ne soit mise en attente pour réparation, et les mises en attente restantes expliquent ce qui s'est passé en langage clair (#15920) ; un bac à sable distant dont la copie requise a échoué est conservé, avec ses fichiers, derrière une décision de réparation explicite au lieu d'être supprimé par nettoyage (#15479, #15790) ; l'arrêt du serveur attend l'exportation de l'espace de travail d'un adaptateur existant avant de libérer son bail sandbox (#15857) ; un arbre de travail enregistré réutilisé conserve son référentiel d'origine lorsque les paramètres du projet changent (#15528) ; un résultat natif accepté n'est plus confondu avec du travail perdu par le faucheur orphelin après un redémarrage (#15718) ; OpenCode s'exécute dans l'espace de travail réalisé via --dir (#11438) ; Les sessions Daytona OpenCode gardent leurs délais (#15905) ; et les délais d'attente OpenCode ne prétendent plus que le délai configuré a expiré (#15789).
  • Exécutions, récupération et questions — Une nouvelle tentative ne se brûle plus pendant que l'environnement d'une exécution arrêtée est toujours en train de nettoyer, et les instructions de réparation réglées cessent de réapparaître dans les sillages ultérieurs (#15463) ; une attente de révision dont la réparation automatique ne laisse également aucun chemin de sillage enregistre désormais une décision du conseil d'administration au lieu de rester silencieuse (#15764) ; un parent est à nouveau réveillé lorsqu'un enfant termine les révisions demandées (#15372) ; les exécutions natives reprennent proprement après les décisions d'approbation de connexion avec l'utilisation finale conservée (#15471, #15420, #15514) ; une demande d'outil en attente expire d'elle-même lorsque l'utilisateur a déjà connecté le service dans Apps (#15856) ; les agents arrêtent de poser à nouveau des questions qui ont été transférées dans l'historique du flux (#15392) ; l'archivage d'une tâche lors de son achèvement ne provoque plus de blocages (#15615) ; et une stratégie de tâche avec un moniteur mais sans étapes ne fait plus planter la page des tâches (#15593).
  • Adaptateurs — Les sessions Claude CLI reprennent sur les copies de fichiers d'agent par exécution (#15437) ; Hermes obtient des instructions gérées via sa superposition système au lieu d'une copie à chaque tour d'utilisateur repris (#15439) ; et les agents externes tels que Dot sont invités à utiliser leurs propres outils lorsqu'une application Paperclip est manquante (#15734).
  • Connexions et MCP — Une réponse MCP surdimensionnée ou mal formée échoue uniquement à cet appel au lieu de verrouiller l'ensemble de la connexion dans un état d'erreur (#15462) ; les rappels MCP à distance conservent une sélection d'agent vide explicitement enregistrée, l'échange de jetons envoie Accept: application/json et les brouillons de fournisseur caché enregistrés reprennent à partir de la fin de la configuration (#15686) ; Airtable, Calendly et d'autres fournisseurs vérifiés obtiennent les correctifs d'enregistrement et de formulaire trouvés lors des tests en direct (#15621) ; et la barre latérale garde ses derniers éléments de plugin silencieux lorsque le serveur est inaccessible (#15588).

Améliorations

  • L'embauche, l'approbation, la pause, la reprise et la résiliation s'effectuent tout au long d'un cycle de vie d'agent durable avec des états explicites : les embauches proposées restent en attente jusqu'à l'approbation, les embauches approuvées sont préparées et leur configuration de harnais est vérifiée avant le travail, les plugins requis sont rappelés à chaque étape et la page de l'agent affiche la progression du cycle de vie avec une action de nouvelle tentative (#15631, #15391) ; les plugins peuvent consommer un journal de cycle de vie des ressources durable avec des accusés de réception, alimenté par une base de référence unique d'agents et de projets existants, et archiver et restaurer le projet en écrivant maintenant les événements du journal (#15343, #15371).
  • Chaque agent reçoit une paire de clés Ed25519 persistante, créée lors de son embauche ou lors de sa prochaine exécution gérée, chiffrée au repos et transmise aux processus gérés tels que PAPERCLIP_AGENT_KEY_ID, PAPERCLIP_AGENT_PUBLIC_KEY et PAPERCLIP_AGENT_PRIVATE_KEY ; la clé publique apparaît sur l'aperçu de l'agent (#15352).
  • Les agents peuvent déposer des réclamations et des suggestions concernant leurs outils dans la table agent_commentary de l'instance via les nouvelles compétences complain et suggestion-box ou les outils natifs submit_complaint et submit_suggestion, en gardant ces commentaires hors des threads de tâches (#15367).
  • Les instances inactives deviennent silencieuses : la livraison par chat, l'action du fournisseur, la synchronisation Slack, la messagerie électronique, le nettoyage de l'utilisation du navigateur et cinq files d'attente de livraison du serveur se réveillent désormais des écritures validées et des délais connus au lieu d'analyser la base de données toutes les secondes ou trois (#15625, #15750, #15757, #15802, #15808, #15822); les hôtes qui garent des instances inactives reçoivent un rapport de sécurité en veille qui clôture le travail accepté, draine les travailleurs du plugin et traite les connexions terminées, les tentatives consommées et l'historique de livraison vérifié comme un historique plutôt que comme un travail en attente (#15522, #15599, #15761, #15851, #15897, #15907), avec un point de contrôle de sauvegarde final opt-in avant la mise en veille (#15629).
  • Les notifications de tâches affichent le nom et l'avatar de l'acteur et masquent vos propres actions (#15695) ; les commentaires des autres personnes dans le chat de tâches apparaissent à gauche avec leur nom et leur avatar, et seuls les vôtres sont à droite en bleu (#15494) ; un agent bloqué par une connexion IA que son utilisateur responsable ne peut pas utiliser affiche une erreur développée nommant l'agent et la connexion avec un lien vers ses paramètres IA (#15741) ; et un coéquipier ne disposant pas du compte IA personnel requis par l'agent peut se connecter au sien depuis le chat et reprendre le message (#15376).
  • Le compositeur de tâches maintient son étiquette de modèle stable pendant que le curseur d'effort se déplace et que le curseur est plus grand (#15444), les sélecteurs imbriqués défilent avec la molette et touchent (#15374), le sélecteur de projet propose toujours Aucun projet (#15382), les descriptions de routine conservent les collages de blocs de code dans le bloc de code et obtiennent un contrôle de copie (#15773), les cartes de confirmation empilent l'invite au-dessus de la pilule cible et masquent les clés machine sans étiquette (#15895), les cartes de connexion au chat et de récupération partagent une surface (#15771), le sélecteur de chat ou d'outils Slack obtient des icônes (#15574), le filtre de l'espace de travail quitte la tâche et les menus de filtrage de la boîte de réception (#15788) et les boutons étoile et quitter quittent l'index de l'agent (#15400).
  • Les tâches dont la branche de départ n'existe pas dans le référentiel affichent une carte de réparation de branche qui propose la branche par défaut de la télécommande ou une branche tapée et réessaye par les portes d'admission normales (#15726) ; une référence GitHub que les informations d'identification de l'instance ne peuvent pas voir est signalée comme inaccessible et revérifiée au lieu d'être gelée comme « Introuvable » (#15906) ; et la compétence Paperclip est livrée avec son propre assistant de mise à jour des problèmes et honore une vérification de harnais au lieu d'en exiger une deuxième (#15554, #15548).
  • Les tâches de l'espace de travail dont la sortie est différente de zéro renvoient 422 workspace_job_failed avec la propre sortie de la tâche au lieu de 500 (#15941) ; les lanceurs de source personnalisés obtiennent le transport natif Runner WebSocket du constructeur du serveur HTTP partagé (#15682) ; une connexion Hermes Gateway locale refusée explique quel hôte vérifier (#15520) ; et l'erreur de modèle indisponible de pi-local ne vide plus le catalogue de modèles (#13628).
  • Les rapports d'échec contiennent des preuves limitées des délais d'attente d'acquisition Daytona et de l'état du fournisseur, de la résolution de la référence de base de l'espace de travail, des erreurs de transfert et de synchronisation du bac à sable, de la perte de processus orphelins, des trames de terminal de pont ACP, de l'inspection de l'arbre de travail Git et des rejets du navigateur sans pile (#15946, #15736, #15719, #15637, #15481, #15475, #15478, #15525, #15940), tandis que des bloqueurs de configuration éprouvés tels qu'un secret utilisateur manquant, un compte AI non choisi, un les informations d'identification non partagées avec l'utilisateur responsable, un projet de répertoire local avec une stratégie d'arbre de travail ou une panne de service externe restent en dehors de Sentry (#15472, #15618, #15714, #15521, #15590).

attendez-vous à ce qu'ils prennent plus de temps sur les instances avec un historique d'exécution important.
  • Nouvelles variables d'environnement, aucune n'est requise : PAPERCLIP_ISSUE_PRIVACY_MODE (enforce par défaut ; shadow enregistre les décisions qui refuseraient sans les appliquer, off désactive le prédicat) (#10633) ; PAPERCLIP_DB_BACKUP_IDLE_CHECKPOINT_ENABLED=1 choisit une instance avec des sauvegardes automatiques pour effectuer une sauvegarde finale vérifiée avant la mise en veille inactive (désactivée par défaut) (#15629) ; PAPERCLIP_RESPONSIBLE_USER_AUTHZ_CACHE_TTL_MS limite l'instantané d'autorisation de l'utilisateur responsable (5000 par défaut) (#10633).
  • Nouveaux paramètres expérimentaux, tous désactivés par défaut : Les robots d'examen GitHub (enableGitHubReviewBots) montrent la configuration et la gestion du robot GitHub (#15416) ; OpenAI Dot (enableOpenAiDot) ajoute Dot comme choix d'agent et nécessite des Connexions d'assistant (MCP), une connexion authentifiée et un HTTPS PAPERCLIP_PUBLIC_URL (#15414) ; Réponses rapides expérimentales (enableFastResponses) révèle les paramètres de l'entreprise → Connexions et permet les commentaires d'accusé de réception (#15748). La configuration du modèle de décision se trouve sous Paramètres de l'entreprise → Général jusqu'à ce que les réponses rapides soient activées (#15473).
  • Membres des opérateurs d'examen (#15377) : les opérateurs bénéficient désormais de subventions d'édition, d'invitation, de connexion, d'outil et d'audit d'entreprise après l'amorçage du démarrage. Rétrograder les membres qui ne doivent pas configurer d'agents ou connecter des comptes.
  • Politiques budgétaires et utilisation non tarifée (#14997) : les politiques existantes obtiennent unpricedUsagePolicy: block. Si vos agents travaillent avec des fournisseurs dont Paperclip ne peut pas déterminer les prix, définissez la stratégie sur allow ou résolvez les événements non tarifés via le flux d'ajustement des coûts afin que le budget ne les retienne pas.
  • Adaptateurs personnalisés et processus gérés (#15352) : les exécutions gérées reçoivent désormais PAPERCLIP_AGENT_KEY_ID, PAPERCLIP_AGENT_PUBLIC_KEY et PAPERCLIP_AGENT_PRIVATE_KEY ; les valeurs de clé sont des chaînes PEM multilignes et la clé privée ne doit pas être enregistrée. La clé d'encapsulage est PAPERCLIP_SECRETS_MASTER_KEY ou le fichier de clé principale des secrets locaux ; une mauvaise clé principale fait échouer l'exécution plutôt que de régénérer la paire de clés.
  • Appelants de tâches privées (#10633) : lectures directes d'une tâche privée par un retour non-membre 404 ; les propriétaires et les administrateurs doivent réussir ?breakGlass=true pour une lecture d'urgence auditée ; les plugins sont des directeurs non membres et ne voient aucun contenu privé.
  • Brouillons Slack et GitHub : les brouillons de robots Slack existants sans méthode de configuration enregistrée restent en configuration manuelle (#15413) ; Les robots GitHub existants, les webhooks directs et la récupération manuelle des applications existantes continuent de fonctionner, mais leurs paramètres sont masqués jusqu'à ce que les bots d'examen GitHub soient activés (#15416).
  • Les broches du harnais sont inchangées pour Codex, Claude et OpenCode. Le Codex natif préfère désormais le Codex CLI installé avec le package serveur et tolère la dérive de version ; une image sandbox dont le Codex CLI est trop ancien pour le modèle sélectionné est basculée vers un modèle compatible avec un avertissement (#15555, #15519).
  • Aucune autre configuration ou modification du API ne nécessite d'action.
