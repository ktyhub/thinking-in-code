Papierclip v2026.1012.0

Sortie : 2026-10-12

Paperclip v2026.1012.0 comporte 130 commits, promus à partir de 2026.1006.0-beta.0. Le titre est que des assistants extérieurs peuvent désormais rejoindre votre équipe : Claude Code, Codex, OpenCode et n'importe quel MCP client peuvent se connecter à Paperclip en tant que personne connectée, réviser le travail et déléguer des tâches, le tout dans un cadre expérimental. Autour de cela : Chat mène la navigation avec les tâches et les artefacts de chaque agent à côté de la conversation, le catalogue de connexions récupère les comptes que vous avez déjà liés dans Composio et Arcade, les connexions contiennent des instructions d'utilisation qui parviennent automatiquement à vos agents, Claude Sonnet 5.5 et GPT-6.1 Sol arrivent avec des harnais actualisés et les agents peuvent mettre à jour en toute sécurité les compétences de l'entreprise. En dessous, les exécutions du Codex survivent aux redémarrages du serveur et aux erreurs de capacité du modèle, les verrous de restauration de l'espace de travail sont déplacés vers des verrous de fichiers SQLite sécurisés en cas de panne et les instructions de l'agent par défaut sont réduites à une fraction de leur ancienne taille.

Modifications radicales

  • Protocole de changement des verrous de restauration de l'espace de travail ; arrêtez tous les anciens processus avant la mise à niveau. Les verrous de restauration et de collecte de fichiers d'agent sont désormais des verrous de fichiers SQLite sauvegardés par le système d'exploitation sous <instance root>/locks/directory-merge/, libérés par le noyau lorsqu'un processus plante. Les anciennes et les nouvelles versions ne doivent pas écrire simultanément sur la même racine d'instance : drainez et arrêtez tous les anciens processus de serveur et de travail (y compris les autres hôtes ou conteneurs) avant la mise à niveau ou la restauration, puis déplacez tous les répertoires <hash>.lock/ hérités restants vers un emplacement de travail. Ne supprimez ou ne déplacez jamais les nouveaux fichiers .lock.sqlite. Voir doc/workspace-restore-locks.md. (#14869)
  • Les subventions aux outils stockés sont appliquées telles qu'écrites. Une subvention dont la liste scope.allow ne correspond pas à un outil, une connexion ou une application ne relève plus d'une politique plus large ; les subventions avec des sélecteurs inconnus ou des restrictions mal formées refusent désormais l'accès. Examinez les autorisations personnalisées après la mise à niveau si un agent perd un outil qu'il utilisait précédemment. (#14915)

Faits saillants

  • Les assistants rejoignent votre équipe via MCP — Une nouvelle carte « Assistant Connection (MCP) » dans Connections permet à Claude Code, Codex, OpenCode et aux MCP clients génériques de se connecter à Paperclip via OAuth du navigateur ou le consentement du code de l'appareil et d'agir en tant qu'utilisateur connecté : lire et rechercher des tâches, créer et déléguer du travail, laisser des commentaires humains, lire des documents et des livrables et suivre les résultats via des webhooks d'événements signés. (#14846). Le consentement affiche le client et l'organisation, l'accès en écriture peut être désactivé, les demandes peuvent être épinglées à une seule entreprise et une connexion à un appareil paperclip mcp CLI relie les stdio locaux clients ; il est désactivé par défaut derrière Paramètres → Expérimental → « Connexions assistant (MCP) » et nécessite un HTTPS PAPERCLIP_PUBLIC_URL (#14933).
  • Chat ouvre la voie — Avec Agent Chat activé dans l'interface utilisateur simplifiée (le shell par défaut), Chat est la première ligne de la navigation Travail, le rail de discussion répertorie tous les agents éligibles et le panneau latéral affiche les tâches et artefacts récents de cet agent ; un nouveau paramètre expérimental « Boîte de réception combinée + liste des tâches » transforme la boîte de réception en tâches sous forme de vues (#15100). Les instances qui ont désactivé l'interface utilisateur simplifiée conservent l'ancienne navigation et ne voient pas ces modifications. L'entrée Chat rouvre la dernière conversation que vous avez visitée (#14848) et l'en-tête du chat affiche l'avatar de l'agent (#14726).
  • Un catalogue pour chaque compte — Le catalogue Connections Apps découvre les comptes déjà connectés en amont dans Composio, Arcade et les passerelles Executor prises en charge et les regroupe avec des comptes natifs sous une seule carte d'application, avec des puces sources, une recherche et une pagination (#15254). AgentMail est une connexion par défaut avec des cartes de configuration en ligne dans Agent Chat (#14772), Neon rejoint le catalogue avec une connexion par clé OAuth ou API (#14980), Asana fonctionne à nouveau avec une « Connexion avec Asana » par défaut (#14756), et les comptes IA bénéficient d'une action « Vérifier l'utilisation » qui lit le courant limites du fournisseur pour Codex, Claude, Grok et OpenRouter (#14936).
  • Les connexions contiennent des instructions pour les agents : une connexion peut contenir des instructions d'utilisation modifiables qui sont transmises à chaque agent autorisé via l'exécuteur natif, les adaptateurs hérités et les contrats HTTP/processus. Honcho, Mem0, Zep, Supermemory et Cognee sont livrés par défaut, l'éditeur apparaît dans la configuration et dans le panneau Autorisations, et les instructions de l'agent affichent une section « À partir des connexions » en lecture seule (#15216).
  • Nouveaux modèles, harnais actualisés — Claude Sonnet 5.5 est sélectionnable pour les agents Claude Code avec un effort faible à maximum, et le temps d'exécution Claude qualifié passe à Claude Code 2.1.286 (#14993) ; GPT-6.1 Sol rejoint l'adaptateur Codex avec le mode Rapide et Ultra effort, Bedrock gagne Sonnet 5.5 et les broches partagées sont déplacées vers Codex 0.160.0 et OpenCode 1.18.34 (#14942). Les menus des modèles Claude et Codex répertorient désormais les modèles dans le même ordre que les applications Claude et ChatGPT (#14917, #14918).
  • Les agents maintiennent les compétences de l'entreprise — Les agents natifs disposent d'un outil update_skill qui réécrit une compétence de l'entreprise avec une vérification de version et des tentatives sécurisées, enregistrées dans l'historique des versions et le journal d'audit ; le fichier de compétences API gagne les champs facultatifs expectedVersionId et idempotencyKey (#15049). Les agents nouvellement créés reçoivent un ensemble par défaut d'autorisations de configuration afin qu'ils puissent terminer la configuration des agents, des outils, des compétences et des tâches sans travail d'autorisation manuel (#15283).
  • Les exécutions de Codex qui survivent aux redémarrages et aux limites de capacité — Un tour de Codex natif interrompu par un redémarrage du serveur reprend dans la même conversation une fois que l'ancien processus s'est avéré disparu (#15297) ; un modèle à capacité affiche une carte "Modèle à capacité" et réessaye automatiquement après une puis deux minutes (#15347) ; un modèle que le compte ChatGPT ne peut pas utiliser affiche « Modèle indisponible » avec des conseils au lieu d'une récupération générique (#15299, #15304) ; et Codex conserve son invite de base de stock, recevant le contexte de Paperclip sous forme d'instructions additives du développeur (#14920).
  • Une boîte de dialogue Nouvelle tâche reconstruite — La boîte de dialogue est construite sur le compositeur de tâches partagé avec une barre de projet et d'arbres de travail, le destinataire, le projet et l'effort mémorisés, ainsi que les mentions de tâches dans les suggestions ; les contrôles de statut, de réviseur, d'approbateur et de surveillance sortent de la boîte de dialogue vers les propriétés de la tâche, et les nouvelles tâches sont attribuées par défaut au dernier responsable utilisé (#15091). Les tâches créées sans titre obtiennent un titre provisoire en texte brut (#15047).
  • Instructions par défaut beaucoup plus courtes — Les nouvelles entreprises et les nouvelles recrues reçoivent des descriptions de rôle au lieu de manuels de procédures : les instructions par défaut du PDG passent d'environ 1 900 mots à 20 (#14985), les nouvelles recrues non-PDG reçoivent un manuel par défaut d'une phrase (#14948), et les compétences de planification groupées se réduisent à environ 400 mots combinés et ne forcent plus une matrice de tâches enfants. (#15296). Les manuels enregistrés existants et les offres personnalisées restent inchangés.

Correctifs

  • Native runner and sessions — Une exécution dont la réponse finale a été enregistrée mais dont l'arrêt a échoué atteint son état final correct, et l'outil de l'agent list_projects renvoie des résumés paginés au lieu de dépasser la limite de commande (#15217) ; les tâches arrêtées lors de la préparation native sur une ancienne version réessayent et acceptent les nouveaux messages (#15020, #15022); une continuation annulée par la porte de révision d'exécution en file d'attente est traitée comme une attente de révision au lieu d'une attente d'exécution inconnue (#15024) ; Nouvelle tentative et travail de récupération des messages enregistrés sur les bases de données SQL_ASCII (#15033) ; une exécution héritée poursuivie par l'utilisateur et qui expire peut être réessayée automatiquement (#14987) ; une exécution terminée ne signale plus « Échec de l'exécution » lorsque le nettoyage du fichier d'instructions expire par la suite (#14945) et ce nettoyage ne bloque plus la libération du bail (#14866) ; write_document et d'autres appels d'outils sémantiques n'échouent plus lorsqu'un document traite simplement des informations d'identification (#14937) ou contient du texte ressemblant à des informations d'identification (#15301) ; Les noms d'outils MCP connectés de longue durée sont dotés d'alias pour s'adapter aux limites du fournisseur et l'avis de récupération explique pourquoi une exécution a été annulée avec une option Continuer (#14951) ; les agents conservent leur contexte de tâche lorsqu'une connexion à un outil change en cours de tâche (#14963) ; les passerelles MCP natives rejettent les jetons d'exécution de tout agent autre que leur propriétaire (#14914) ; et les avertissements « informations sur le fournisseur non liées ignorées » du programme d'exécution du Codex restent dans le journal d'exécution au lieu du chat (#14929).
  • Sandbox et espaces de travail — Les exécutions de sandbox n'échouent plus avec workspace_restore_failed après qu'un agent rebase ou modifie sa branche (#15268) ; le pilote Daytona récupère la sortie d'un socket de journal qui devient silencieux (#14889) ; les commandes de contrôle de la passerelle sont limitées à 30 secondes et les passages actifs sont signalés comme suspects après 5 minutes de silence et critiques après 15 (#14979) ; validations aller-retour de projets multi-référentiels sur les environnements d'exécution SSH (#14782) ; tâches d'arbre de travail isolé sur le référentiel Paperclip lui-même configurées sans configuration de départ locale (#14810) ; et l'image Docker standard regroupe le pack du fournisseur distant afin que les exécutions OpenCode et ACPX à distance n'échouent plus avec runner_remote_provider_artifact_incompatible (#14854).
  • Interface utilisateur de discussion et de tâche — Piloter et interrompre affichent votre message immédiatement et le transmettent à l'exécution active même après un changement de modèle ou d'effort, et un démarrage natif arrêté propose une nouvelle tentative (#15015) ; un message envoyé après l'échec d'une exécution native ne se bloque plus et est délivré exactement une fois (#14857) ; Les marqueurs obsolètes « Échec de l'exécution », « Arrêté » et « En attente de reprise » disparaissent une fois qu'une tentative ultérieure les remplace (#14874) ; les questions des agents renvoyés restent dans le flux de tâches et restent auxquelles il est possible de répondre (#15229) ; les cartes de confirmation affichent « Préparation de l'approbation… » jusqu'à ce que l'espace de travail source soit prêt au lieu d'une erreur sur click (#14893) ; une conversation d'agent non enregistrée n'interroge plus le panneau du navigateur avec un brouillon d'identifiant toutes les trois secondes (#15298) ; le thread n'appelle plus une action d'envoi ou d'annulation obsolète (#14863) ; les pages de tâches mobiles bénéficient d'un pied de page opaque, d'un défilement plus stable, d'un panneau de document pleine hauteur et de liens de document sur place (#15228), la nouvelle sortie restant au-dessus du compositeur (#15282) ; le curseur du travail terminé se trouve à côté de son étiquette (#15048), les étiquettes du compositeur utilisent la largeur disponible (#15050), les artefacts de branche sans lien distant le disent (#15051), le tableau de bord affiche chaque tâche une fois (#14847) et un abonnement enregistré sélectionné peut être utilisé sans clicliquez sur la vignette du fournisseur (#14996).
  • Connexions et accès — Les paramètres de l'agent peuvent reconnecter un compte AI personnel indisponible, et un compte nouvellement connecté devient le compte par défaut de l'utilisateur (#14916) ; le MCP OAuth générique demande offline_access lorsqu'il est proposé afin que l'accès survive à l'expiration du jeton (#14950) ; La découverte de l'outil MCP utilise une fraction de la mémoire et interroge les catalogues volumineux, limite les listes simultanées avec un tool_discovery_busy 503 sous charge et répond à GET sur les points de terminaison sans état avec 405 (#14864) ; Les agents low-trust peuvent créer un travail auto-attribué dans leur portée autorisée et mettre à jour leur propre AGENTS.md géré à partir du chat du propriétaire (#14870) et accepter les messages directs de leur propriétaire et les tâches assignées par l'homme en dehors d'une limite d'admission (#14775) ; les importations de compétences d'entreprise à partir d'une extraction de projet gérée par le serveur n'échouent plus avec skill_workspace_boundary_denied (#10329) ; et le lanceur git/gh géré réessaye une demande de courtier d'informations d'identification ayant échoué avant de continuer sans informations d'identification gérées (#14856).
  • Résilience du serveur — Les lectures du tableau de bord (#14873), les requêtes de lecture étendues (#15248) et la liste d'exécution des tâches (#15300) réessayent les déconnexions transitoires de PostgreSQL au lieu d'échouer la demande, et les routes de routine renvoient 404 pour les identifiants mal formés au lieu d'une erreur de base de données. (#15313).

Améliorations

  • Les pools de connexions IA expérimentaux alternent les nouvelles tâches entre les comptes IA enregistrés tandis que chaque tâche reste épinglée sur son compte, derrière le paramètre enableAiConnectionRouters désactivé par défaut et un plugin de routeur (#14967) ; le fournisseur de bac à sable exe.dev peut cloner une « VM source » préparée au lieu d'en créer une nue (#14975) ; le démon runner natif accepte n'importe quel --listen-port afin que plusieurs runners en écoute puissent partager un hôte (#15353) ; le serveur tient un journal de cycle de vie durable des événements d'embauche, de pause, de reprise et de fin d'agent et des événements de création et de mise à jour de projet comme base pour les hooks de plugin (#15280, #15306) ; Les invites Slack, GitHub, MCP, d'invitation, de routine et de transfert partagent un contrôle animé « invite de copie » (#14862) et l'invite de configuration de Slack correspond au flux actuel (#14965) ; la boîte de dialogue Test par action affiche les résultats MCP sous forme de tableaux et de cartes lisibles (#14859) ; les agents peuvent créer des fiches de questions à partir d'un seul ensemble de questions canoniques (#14946) et recevoir des conseils identiques sur les outils de complétion dans Codex, Claude et OpenCode (#14961) avec un texte de procédure moins répété et un lien canonique de write_document (#15151) ; et les restaurations échouées et les délais d'attente d'arrêt enregistrent quelle étape a échoué et pourquoi dans les résultats d'exécution et le contexte Sentry (#15005, #15291, #14990, #14986).

Guide de mise à niveau

  • Les migrations 0294–0305 s'exécutent lors de la mise à niveau : 0294 ajoute un index d'expiration tool_mcp_gateway_tokens ; 0295 et 0296 ajoutent un instantané de compte d'agrégateur et des tables de synchronisation ; 0297 ajoute resource_lifecycle_events et 0300 réécrit sa contrainte de vérification d'action ; 0298 ajoute tool_connections.agent_instructions et remplit les instructions par défaut pour les connexions Honcho, Mem0, Zep, Supermemory et Cognee existantes ; 0299 ajoute un pool de connexions AI, un curseur de routeur et des tables de broches de tâches ainsi que company_secrets.ai_session_epoch ; 0301 à 0305 ajoutent les tables publiques MCP OAuth client, ​​d'octroi, de jeton, de reçu, d'abonnement à un événement, de flux d'appareil et d'admission. Tous sont additifs ; 0298 est le seul à mettre à jour les lignes existantes.
  • Arrêtez tous les anciens processus avant la mise à niveau (#14869) : le nouveau protocole de verrouillage de restauration SQLite ne peut pas coexister avec les anciens verrous de répertoire. Videz tous les serveurs et travailleurs qui écrivent à la racine de l'instance, déplacez les répertoires <hash>.lock/ hérités restants hors de <instance root>/locks/directory-merge/, puis démarrez la nouvelle version. La même chose s'applique à la restauration.
  • Réviser les subventions d'outils personnalisés (#14915) : les subventions avec des sélecteurs de portée inconnus ou des restrictions mal formées sont désormais refusées au lieu d'échouer.
  • Nouveaux paramètres expérimentaux, tous désactivés par défaut : "Connexions assistant (MCP)" (enablePublicMcp) expose le point de terminaison MCP public et nécessite que PAPERCLIP_PUBLIC_URL soit une origine HTTPS (#14933) ; « Boîte de réception combinée + liste de tâches » (enableCombinedInboxTasks) regroupe la boîte de réception en tâches et ne prend effet que lorsque « l'interface utilisateur simplifiée » est activée (#15100) ; enableAiConnectionRouters active les pools de connexions et n'a pas de bascule d'interface utilisateur (#14967).
  • Instructions de connexion pour les adaptateurs personnalisés (#15216) : les adaptateurs HTTP reçoivent un champ connectionInstructions de niveau supérieur dans le corps de la requête, soit un objet { text, digest }, soit null lorsqu'aucune instruction ne s'applique ; les adaptateurs de processus reçoivent PAPERCLIP_CONNECTION_INSTRUCTIONS_FILE, le chemin d'accès à un fichier privé JSON contenant le même objet { text, digest }, et la variable est définie sur une chaîne vide (pas un chemin) lorsqu'aucune instruction ne s'applique. Les adaptateurs doivent ajouter le text de l'objet à l'invite du modèle plutôt que de transmettre l'objet. Les harnais intégrés ne nécessitent aucun changement.
  • Les broches du harnais ont été déplacées vers Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286) et OpenCode 1.18.34 (#14942, #14993). Les images sandbox personnalisées construites avec Claude Code antérieures à 2.1.284 doivent être reconstruites avant que Sonnet 5.5 ne fonctionne sur le chemin CLI, et le contrôleur et l'exécuteur doivent être déployés avant de promouvoir une image sandbox avec les nouvelles broches ; Le Codex distant accepte désormais 0.149.0 jusqu'à 0.161.0 exclu.
  • Nouveaux paramètres par défaut : les agents standard nouvellement créés reçoivent des autorisations de configuration par défaut, tandis que les agents existants restent inchangés (#15283) ; le --listen-port du coureur est toujours par défaut 43127 (#15353) ; les exécutions actives silencieuses sont signalées après 5 et 15 minutes au lieu de 1 et 4 heures, sans annulation automatique (#14979).
  • Aucune autre configuration ou modification du API ne nécessite d'action.
