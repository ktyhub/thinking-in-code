papierclip v2026.722.0

Papierclip v2026.722.0

Sortie : 2026-07-22

Faits saillants

  • Accès secret d'agent lié à l'exécution — Les agents peuvent désormais récupérer les secrets qui leur ont été accordés à la demande via un API lié à l'exécution, au lieu de s'appuyer uniquement sur l'injection dans l'environnement ambiant. Un nouveau mode de livraison access.* expose uniquement les secrets API, GET /api/agents/me/secrets répertorie uniquement les alias accordés à un agent et POST /api/agents/me/secrets/:key/value renvoie une valeur avec Cache-Control: no-store. Chaque valeur lue est écrite à la fois dans la piste d'audit de sécurité et dans le journal d'activité de l'opérateur, les jetons d'examen/test de compétences à faible trust restent refusés et un nouvel éditeur Accès secret vous permet de gérer les autorisations par agent à partir des paramètres de l'agent. (#9921)
  • Les agents locaux s'exécutent sous Windows — Le moteur ACPX intégré n'encapsule plus les commandes d'agent local dans un script Bash généré, de sorte que les adaptateurs Claude, Codex, Gemini et ACP personnalisés apparaissent désormais de manière native sous Windows ainsi que Linux. Les variables d'environnement sont injectées via les options de session ACPX, l'enfant stderr est capturé en cours de processus, les cales .cmd npm/pnpm sont préférées sous Windows et les échecs du lien symbolique EPERM reviennent aux copies. Une véritable fumée d'apparition de Node ACP fonctionne désormais à la fois sur Ubuntu et Windows. (#9980)

Améliorations

  • Les liaisons PAPERCLIP_* nommées par l'utilisateur atteignent désormais vos agents — Le battement de cœur avait précédemment supprimé chaque liaison d'environnement préfixée par PAPERCLIP_ avant la résolution, donc un secret que vous avez délibérément nommé quelque chose comme PAPERCLIP_CLOUD_PROD_PROVIDER_RAILWAY_TOKEN a été supprimé en silence. Désormais, seul PAPERCLIP_API_KEY est catégoriquement rejeté, les variables d'exécution attribuées par le faisceau gagnent toujours et toutes les autres liaisons PAPERCLIP_* sont transmises à l'environnement d'exécution. (#9974)
  • Télémétrie plus robuste client — La télémétrie client correspond désormais au contrat de fil : les charges utiles sont fragmentées, les ID de lot sont déterministes, les tentatives sont regroupées avec interruption et le magasin local est limité. Une ligne de base silencieuse est épinglée et les majuscules/retraits sont désormais une surface configurable. La télémétrie reste anonymisée et peut être désactivée avec DO_NOT_TRACK=1 ou PAPERCLIP_TELEMETRY_DISABLED=1. (#9946, #9906, @nickyleach)
  • Les secrets nommés par des barres obliques naviguent désormais sous forme de dossiers — Les secrets dont les noms contiennent des barres obliques naviguent désormais sous forme de dossiers imbriqués dans l'interface utilisateur. (#9913)
  • Sélecteur d'agent consultable pour l'accès secret — L'octroi d'un accès secret par agent utilise désormais un sélecteur d'agent consultable au lieu d'une longue liste plate. (#9918)
  • Étiquettes d'objets externes et contrôles en étoile plus propres — Les étiquettes d'objets externes et les contrôles en étoile qui se trouvent à côté d'eux ont été simplifiés pour réduire le bruit visuel. (#9929)
  • Synchronisation plus sûre du bac à sable CODEX_HOME — L'adaptateur codex-local met désormais en place une liste d'autorisation explicite lors de la synchronisation de CODEX_HOME dans le bac à sable, plutôt que de copier l'intégralité du répertoire personnel. (#9972, @nickyleach)

Expérimental

Ces fonctionnalités sont livrées avec des paramètres expérimentaux : activez les applications sous paramètres expérimentaux pour les essayer.

  • Fondation Connections v3 — Les bases des applications connectées one-click ont ​​été lancées : un noyau de schéma v3 ajoute un UID de connexion stable à l'échelle de l'entreprise, des champs de propriété/authentification/transport explicites, une table connection_grants sensible au sujet et des informations d'identification multi-clés (avec l'ancien transport remote_http renommé mcp_remote). En plus de cela, un catalogue AppDefinition Wave 1 généré permet de parcourir et de configurer un contrat typé unique, et une couche d'exécution ajoute un état d'autorisation sensible au sujet, une gestion des clés étendues et des routes d'octroi enregistrées par OpenAPI qui échouent fermées pour des étendues inconnues. (#9958, #9981, #9982)

Correctifs

  • Les éléments archivés de la boîte de réception restent archivés — Les éléments que vous avez archivés ne réapparaissent plus dans la boîte de réception. (#9931)
  • L'approbation finale de la politique d'exécution se termine proprement — L'approbation de la dernière étape d'une politique d'exécution met désormais fin à la politique au lieu de la ramener à l'étape 1. (#7936, @HKTITAN)
  • Accepter les pièces jointes aux problèmes Office : les pièces jointes aux documents Office (Word, Excel, PowerPoint) sont désormais acceptées pour les problèmes. (#8562, @samrusani)
  • Expurger les cookies HTTP des journaux du serveur — Les en-têtes de cookies sont désormais supprimés des journaux du serveur afin que le matériel de session ne s'échappe pas dans la sortie du journal. (#7977, @nosolosoft)
  • Plus de 500 pour les commentaires créés par l'exécution — createdByRunId est nettoyé lors de l'insertion de commentaires, corrigeant une classe de 500 erreurs. (#9489, @digitalflanker-ux)
  • Préserver le statut du terminal lors de la publication d'un problème — La publication d'un problème n'entrave plus le statut du terminal (terminé/annulé). (#7524, @harshkotak)
  • Échec bruyant sur des fichiers de configuration non valides — Un fichier de configuration non valide fait désormais apparaître une erreur claire au lieu d'être ignoré en silence. (#9041, @lesbass)
  • Instructions d'approbation en attente non clickable — Les instructions d'administration en attente d'approbation sur l'écran d'invitation ne sont plus un élément clickable trompeur. (#6786, @le-czs)
  • La validité Cron est réglée avec radix-ui 1.6.4 — La gestion de la validité Cron et un test de branchement ont été synchronisés pour radix-ui 1.6.4. (#9966, @nickyleach)
  • Corrections de sélection d'importation CLI — Les sélections d'importation effacées ne suppriment plus le fichier d'extension et les champs manquants du manifeste d'entreprise ont été ajoutés au dispositif de test de sélection d'importation. (#2379, @kevinmanase, #9978, @aaymeloglu)
  • Les instances gérées dans le cloud passent le contrôle de santé : les instances gérées dans le cloud sont désormais traitées comme étant amorcées dans le contrôle de santé afin qu'elles ne se bloquent pas au démarrage. (#9912)

Guide de mise à niveau

  • Cette version ajoute deux migrations de bases de données additives pour la fondation Connections v3 (0182_connections_v3_schema_core, 0183_connection_user_authorization_state), qui remplissent les UID de connexion stables, créent des autorisations d'espace de travail par défaut et renomment le transport remote_http en mcp_remote. Les migrations s'exécutent automatiquement au démarrage : aucune action manuelle n'est requise.
  • Si vous avez précédemment défini un PAPERCLIP_API_KEY statique dans adapter/config env pour remplacer le jeton d'exécution, ce remplacement ne s'applique plus — le jeton d'exécution créé par le faisceau est désormais la seule source de la clé d'exécution API. Toutes les autres liaisons nommées PAPERCLIP_* sont désormais transmises à l'environnement d'exécution comme prévu.
  • Les connexions/applications restent bloquées derrière des paramètres expérimentaux. Activez Applications dans les paramètres expérimentaux pour essayer les surfaces Connections v3.
