Papierclip v2026.916.0

Sortie : 2026-09-16

Paperclip v2026.916.0 comporte 503 commits, promus à partir de 2026.916.0-beta.0 publié le même jour. Le titre est le train Connections : les informations d'identification d'exécution de l'IA - abonnements Claude et Codex, clés API, comptes partagés - résident désormais dans Connections avec les mêmes autorisations et limites d'autorisation que tous les autres comptes, suivent la personne responsable tout au long de l'embauche et de l'exécution des tâches, et peuvent être connectées ou réparées en ligne à partir de la tâche qui en a besoin. Autour de cela : les agents obtiennent leurs propres adresses e-mail via AgentMail, les connecteurs de chat expérimentaux intègrent les conversations Slack, Discord, Telegram, Microsoft Teams et (via Photon) iMessage dans les tâches, l'accès GitHub devient des identités individuelles durables au lieu d'un jeton partagé, les annonces arrivent sous forme de cartes natives dans l'application et le Paperclip Runner expérimental est passé des bases de la dernière version à un moteur d'exécution complet - avec la porte désormais ouverte par défaut sur les auto-hébergés. installations pour les agents explicitement configurés.

Modifications radicales

  • Les profils de modèles bon marché sont supprimés. Le deuxième mode d'exécution qui permettait la récupération et les remplacements de s'exécuter sur un modèle moins cher a disparu des métadonnées de l'adaptateur, de la configuration d'exécution de l'agent, des remplacements de tâches, des règles de récupération, des API et de l'interface utilisateur de la carte ; La migration 0236 supprime les blocs modelProfiles stockés des configurations d'agent. Il existe désormais un seul chemin de sélection de modèle pour le travail normal et le travail de récupération. (#12683)
  • Les agents API ne renvoient plus d'informations d'identification en texte brut. Chaque point de terminaison qui sérialise un agent (lectures détaillées, liste des agents de l'entreprise et itinéraires de création/mise à jour/cycle de vie) était utilisé pour faire écho à adapterConfig.env tel qu'il est stocké, de sorte que les liaisons plain (clés API, jetons) sont revenues textuellement à tout appelant capable de lire l'agent, y compris l'agent lui-même via GET /api/agents/me. Les trois familles de réponses passent désormais par un seul présentateur de rédaction. Les intégrations qui ont supprimé les informations d’identification en direct de ces réponses cesseront de fonctionner – c’était la fuite. (#9860, @glovario)
  • Les évaluations automatiques de productivité sont supprimées. Le détecteur qui transformait le nombre d'exécutions, le nombre de commentaires et le temps écoulé en tâches d'évaluation de la direction est supprimé ainsi que ses mises en attente de continuation : des pannes d'infrastructure pourraient satisfaire à ses règles et produire des travaux. La récupération limitée, les budgets, les bloqueurs explicites et les étapes normales de révision demeurent tous ; les enregistrements de tâches existants restent lisibles et inchangés. (#13263)
  • X-Forwarded-Host n'est honoré qu'à partir d'un proxy trusted. Le garde de même origine acceptait un hôte transféré de n'importe quel client direct, permettant à un appelant de promouvoir son propre en-tête dans l'ensemble d'origine trusted. L'hôte transféré ne compte désormais que lorsque l'homologue immédiat transmet le paramètre TRUST_PROXY de l'opérateur : les déploiements derrière un proxy inverse doivent confirmer que TRUST_PROXY est configuré, ou l'hôte transféré du proxy est ignoré en faveur de l'en-tête brut Host. (#12832)
  • L'ancienne option de connexion REST d'Anthropic a disparu et les connexions de l'outil REST sont validées comme REST. Le chemin de configuration REST obsolète est supprimé au profit du flux de compte AI pris en charge, et la validation stdio ne laisse plus passer une connexion REST non prise en charge (ou échoue avec une erreur templateId trompeuse) — les connexions existantes non prises en charge reçoivent désormais un rejet précis. (#13346)

Faits saillants

  • Les informations d'identification IA sont désormais disponibles dans Connections — Les connexions du fournisseur cessent d'être une configuration par agent et deviennent des comptes gérés avec la propriété, les subventions et les autorisations d'accès que Connections applique déjà : les agents réutilisent le compte de l'utilisateur responsable ou un compte partagé autorisé, et la sélection du modèle/faisceau reste indépendante de la sélection des informations d'identification, les anciens agents conservant leur authentification existante jusqu'à ce qu'ils adoptent explicitement une connexion gérée (#13247). Les mêmes composants de connexion sont réutilisés lors de l'intégration, de la configuration de l'agent et de la page Connecteurs au lieu d'un deuxième assistant de connexion (#13248). Les agents embauchés héritent des références d'informations d'identification du fournisseur de l'agent de recrutement afin qu'un coéquipier délégué puisse s'authentifier dès sa première exécution (#13268), et les connexions suivent les embauches parmi les exécuteurs anciens et natifs : un compte manquant met la tâche en pause et propose le formulaire de connexion en ligne au lieu d'échouer (#13438). Chaque utilisateur responsable reçoit une valeur par défaut par fournisseur, de sorte que le même agent peut s'exécuter sur l'abonnement d'une personne et sur la clé API d'une autre (#13351). Le train s'est également durci à l'atterrissage : la connexion par abonnement fonctionne sur des instances auto-hébergées authentifiées sans exposer le compte CLI de l'opérateur du serveur (#13344), les baux d'informations d'identification survivent au regroupement de transactions au lieu de signaler une "connexion occupée" fantôme (#13347), une connexion d'abonnement Anthropic prend en charge les exécutions simultanées - seules les informations d'identification sauvegardées sur fichier sont toujours sérialisées. (#13445), et les sondes de connexion, la réutilisation des comptes enregistrés et les transferts de tâches ont obtenu des notes de fiabilité (#13404, #13161).
  • Les agents reçoivent leur propre e-mail — Les connexions AgentMail (expérimentales) donnent à un agent une boîte de réception dédiée : les e-mails entrants se voient attribuer un travail dans une tâche, les envois sont des actions d'agent explicites authentifiées via Paperclip, et les commentaires internes sur les tâches ne peuvent jamais être divulgués sous forme de courrier sortant par accident. La clé du fournisseur reste dans le coffre-fort du serveur et le tableau suit chaque conversation à partir d'une carte e-mail de tâche. (#13256)
  • Atteignez vos agents à partir de vos outils de chat — Des connecteurs de chat natifs expérimentaux lient une identité de robot Slack, Discord, Telegram, Microsoft Teams ou GitHub à un agent et chaque conversation externe admise à une tâche, avec des files d'attente, des questions, des progrès, des fichiers et des accusés de réception durables par conversation — les commentaires du forum restent internes sauf s'ils sont explicitement envoyés au canal, et le raisonnement brut, les journaux et les informations d'identification ne sont jamais envoyés du tout. (#13100, #13038). iMessage rejoint via le canal Photon expérimental : DM Pro partagés ou numéros dédiés, photos incluses, Paperclip conservant la propriété des tâches et l'autorité d'approbation (#13299). Dans l'application elle-même, Agent Chat expérimental donne à chaque personne une conversation persistante avec chaque agent - soutenue par des tâches réelles et une gouvernance normale, et non par un magasin de discussion parallèle - et chaque agent de l'entreprise est joignable depuis la barre latérale Chats via un sélecteur consultable (#13284, #13420).
  • L'accès GitHub devient des identités, pas un jeton partagé — Les identités basées sur l'application GitHub avec actualisation durable, contrôles d'accès au référentiel et livraison de webhook remplacent les jetons ad hoc, construits sur les connexions gérées existantes et les autorisations chiffrées (#12843). Lorsque plusieurs personnes dirigent un agent, les outils Git gérés, gh et GitHub résolvent les informations d'identification de la personne responsable selon les instructions acceptées - avec des règles de continuation durables et sans repli sur l'accès d'un coéquipier (#13005), et cette identité se projette également dans les exécuteurs sandbox (#12907). Autour du noyau : parcourez l'accès au référentiel dans les organisations (#12998), sélectionnez plusieurs référentiels sources par projet (#13010), les connexions en double au même compte GitHub se résolvent proprement (#13022), et l'état de connexion et l'accès au référentiel connecté sont visibles et simplifiés dans l'interface utilisateur. (#12993, #13047, #12893).
  • Les annonces arrivent dans l'application — Une carte d'annonce native restitue un flux JSON validé avec des composants natifs (le héros peut être une image statique ou une animation HTML/CSS isolée), donc la publication ou le retrait d'une carte ne nécessite aucune version de l'application. Les licenciements persistent par compte sur l'instance (une carte fermée reste fermée dans toutes les entreprises et tous les navigateurs) et les flux de préparation nommés permettent aux auteurs de tester le contenu avant la production. Activé par défaut sur le flux hébergé ; le guide de mise à niveau comporte la possibilité de se désinscrire. (#13403)
  • L'intégration se dirige directement vers un agent actif — L'étape de connexion s'ouvre sous la forme d'une question source modèle avec connexion du fournisseur intégrée — une séquence continue sur une seule carte, entrée de clé API incluse, avec le code de connexion collé conservé à l'écran et répondu immédiatement (#12440, #12863, #12801, #12820, #12613, #13193). Votre première tâche s'ouvre désormais sous la forme d'une conversation avec un chef de cabinet qui attend votre réponse au lieu de s'enfuir tout seul, et le recrutement du chef de cabinet est fiable (#13068, #13317). La création d'agents ultérieurs emprunte les mêmes contrôles de connexion dans un assistant simplifié avec des pages de configuration réorganisées (#13011), et les connexions de modèle enregistrées sont réutilisées lors de la configuration au lieu de vous demander de vous reconnecter (#13161).

Améliorations

  • Les applications et le catalogue de connecteurs ont grandi : les applications quittent leur porte expérimentale, la configuration de la connexion est plus courte et l'accès géré à Google fonctionne sur une installation auto-hébergée propre avec une origine par défaut sûre (#12728). En dessous : autorisations de connexion et identités déléguées (#12341), connecteurs MCP externes gérés (#12346), configuration MCP et PostHog à distance sécurisée (#12339), connecteurs Composio et Gmail (#12342), un catalogue libre-service étendu avec configuration (#12344, #12347, #12345), flux Postman et Shopify affinés (#12357) et gestion consolidée des connecteurs (#12684). La configuration de Google Workspace a ensuite été réparée de bout en bout : le catalogue et la création utilisent les mêmes règles de disponibilité, les choix de propriété survivent aux changements de fonctionnalités et Paperclip est la méthode d'authentification Google par défaut avec OAuth personnalisé à un lien (#13289, #12619, #12623). Les agents peuvent également demander de nouvelles connexions de service à partir de flux de tâches natifs, avec des actions de connexion examinées à partir de la tâche (#13058, #13063).
  • Mises à jour du modèle et du fournisseur — Claude Fable 5.1 est sélectionnable dans l'adaptateur Claude avec des ID de profil d'inférence anthropique et Bedrock directs (#12730) ; Le Codex gagne GPT-6 Astra avec ses commandes spécifiques au modèle (#12851) ; Les modèles Claude non définis se résolvent en Opus 5 partout, avec la valeur par défaut visible dans la configuration de l'agent (#13055). Grok rejoint le panneau de connexion des appareils sandbox avec un répertoire d'informations d'identification privé à l'échelle de l'entreprise, organisé en exécutions d'abonnement à distance et en informations d'identification actualisées copiées sur l'hôte (#12469, #12618, #12696). Chaque compte Codex possède son propre secret d'accueil et de chemin d'accès, et un agent peut se lier à une connexion Codex autre que celle par défaut de l'entreprise (#12709, #13067).
  • Le Paperclip Runner natif fait désormais tout le travail — et les installations auto-hébergées ouvrent la porte par défaut — Les bases de la dernière version sont devenues un moteur d'exécution expérimental complet derrière l'indicateur enableNativeRunner, qui est désormais activé par défaut pour les instances auto-hébergées** (les instances gérées dans le cloud le maintiennent désactivé) (#13068) : exécution Codex native et un runtime Claude ACPX plus un runtime OpenCode qualifié (#12616, #12590, #12588, #12691), backends de fournisseurs gérés (#12699), un substrat d'exécution à distance avec transport sécurisé (#12638, #12639), administration et observabilité (#12641), et tours natifs projetés dans le chat de tâches (#12617). Le contrôle est un indicateur unifié qui contrôle chaque chemin de configuration (#12656, #12666). La valeur par défaut ouverte déverrouille uniquement la porte : les agents locaux Codex, OpenCode et ACPX qualifiés explicitement configurés peuvent utiliser le programme d'exécution, l'intégration reste sur les adaptateurs existants, rien ne bascule automatiquement et la désactivation de enableNativeRunner dans les paramètres expérimentaux le referme.
  • Contrôles pour les opérateurs — Un indicateur expérimental géré, enableIsolatedWorkspacesByDefault, fait que chaque projet sans sa propre politique utilise des arbres de travail git isolés par tâche, donc une flotte par défaut ne signifie plus éditer chaque projet à la main (#13444). Les nouveaux agents trust standard peuvent embaucher d'autres agents par défaut — les agents trust faible conservent la valeur par défaut désactivée (#12814). La surveillance Sentry est divisée en SENTRY_DSN_FRONTEND et SENTRY_DSN_BACKEND, l'ancien SENTRY_DSN fonctionnant toujours comme solution de secours (#12678). La page des paramètres expérimentaux supprime les contrôles morts et regroupe les outils de développement (#12681), et PAPERCLIP_HIDDEN_SETTINGS est également honoré dans le menu du sélecteur de production (#12788).
  • La surface des tâches actualisée — Une base de navigation simplifiée avec des surfaces de tâches et d'espace de travail raffinées, un comportement de survol/survol/espacement cohérent, ainsi qu'un tableau de bord compact et des cartes Live-runs que vous pouvez réellement numériser (#12746, #12747, #12748, #12854, #12793, #13269). Les produits de travail reçoivent des cartes riches et un inventaire d'artefacts d'exécution sur l'onglet Artefacts de la tâche (#12717), un lien profond du document viewer=full ouvre le volet latéral agrandi directement à partir d'une notification externe (#12812), le compositeur obtient un contrôle d'arrêt avec des contrôles de tâches simplifiés, des badges d'état et la suppression du bloqueur en ligne (#13104, #13097), les questions à choix unique avancent lors de la sélection (#13234), l'activité du coureur se condense en résumés par groupe partagés dans les vues en direct et enregistrées (#13255, #13274, #13421), tâches créées à partir d'une tâche sont affichés par projet (#13241), les discussions de tâches longues restent réactives pendant la diffusion (#13229, #13228), et le mobile obtient de véritables feuilles de sélection d'entités, des arborescences de tâches pleine largeur et des passes d'espacement (#13343, #13250, #13304, #13122).
  • Recherche de tâches qui trouve la tâche — La recherche complète et rapide s'unifie autour de la couverture des termes PostgreSQL avec des bandes de pertinence explicites et une récupération conservatrice des fautes de frappe, jugées par rapport à un corpus noté. (#13335)
  • Essayez-le sans toucher à vos données — Une commande test-drive CLI au premier plan uniquement démarre une instance isolée avec son propre répertoire de données et un PDG soutenu par le fournisseur, avec des garanties de réutilisation et des entrées d'informations d'identification restaurées (#12894, #12898) ; le démarrage du serveur n'ouvre plus un navigateur sauf demande explicite (#12435).
  • Les exécutions Sandbox sont devenues plus rapides et plus robustes — Les espaces de travail Daytona chaleureux persistent à travers les tours, l'espace de travail hôte restant la limite de durabilité (#12904, #12901), le pont sandbox HTTP/2 transporte les corps binaires et les routes de pièces jointes (#12923), l'étape de compétences sélectionnées dans les exécutions Claude ACP à distance (#13196), et un canal de contrôle de bac à sable perdu fait échouer le tour rapidement au lieu de le suspendre (#13158).

Correctifs

  • Sécurité et exactitude du serveur — Les limites des serveurs privilégiés sont renforcées (#12776), les identifiants d'objectif du projet sont validés pour exister et appartenir à l'entreprise (#12779), listComments n'a plus 500 sur un afterCommentId non-UUID (#8695, @Maxxsong7), et le démarrage rapide du Docker fait passer le PAPERCLIP_ALLOWED_HOSTNAMES (#6846, @rsclafani).
  • Le pool de base de données guérit au lieu de se coincer — Les connexions inactives sont récupérées, le pool est nommé et terminé à l'arrêt — fermant la boucle de redémarrage qui a empilé les backends jusqu'à ce que PostgreSQL refuse chaque démarrage (#12956, @stubbi) — et une requête dont l'écriture du socket a échoué sur une connexion poolée recyclée est relue au lieu d'échouer la requête (#13417).
  • L'étape de connexion à l'intégration montre son travail — La connexion du fournisseur lors de l'intégration affiche désormais la progression de la vérification et confirme l'abonnement avant de continuer, au lieu de paraître bloquée (#13499), et un fichier d'informations d'identification Claude périmé ou expiré sur la machine est ignoré lors de la lecture du jeton au lieu d'interrompre la connexion (#13505).
  • Plus de fiabilité des connexions — La découverte de l'authentification MCP personnelle est débloquée (#13497) et une connexion d'abonnement OpenAI ou xAI prend en charge les exécutions simultanées d'agents, correspondant au correctif Anthropic de cette version (#13452).
  • Récupération et réveils — Les problèmes cachés sont exclus de la récupération bloquée et des réveils de continuation (#5648, @im0xMagnus), les réveils bloqués attendent sans générer d'exécutions répétées (#13236), les réveils de continuation périmés sont rejetés (#13173), les messages que vous avez envoyés pendant l'arrêt d'une exécution sont enregistrés et livrés après la récupération au lieu de disparition (#13327, #13270, #13405), les messages utilisateur peuvent continuer une tâche native arrêtée (#13239), les événements de nouvelle tentative d'épuisement n'épuisent plus la mémoire d'alimentation d'attention (#13451), les exécutions de démarrage survivent aux déploiements qui se chevauchent (#13285), et l'amplification de l'interrogation et de l'inspection de l'espace de travail est réduite (#13174).
  • Sandbox et espaces de travail — Un plugin sandbox bloqué bloque l'exécution visible et les plugins groupés erronés sont réactivés au démarrage (#12957, @stubbi), le démarrage bloqué du bac à sable s'annule sans attendre la fin de l'installation (#13352), la configuration de l'espace de travail récupère et réessaye (#13353), l'ancien démarrage de Daytona les échecs de récupération à partir de la tâche et de la boîte de réception (#13272), tous les référentiels d'un projet sont provisionnés pour les tâches locales et sandbox (#13442), les analyses d'amorçage de l'espace de travail transitoires sont récupérées au lieu d'échouer l'exécution (#13481), les fichiers sandbox sont publiés sur les exécuteurs hérités et natifs (#13493) et les charges utiles d'événement d'exécution conservent les caractères NUL (#13325).
  • L'application Web — Le service worker reçoit un identifiant par build afin que les déploiements atteignent réellement les onglets parqués (#12725), les notifications prêtes pour l'espace de travail s'affichent sous forme de notifications système compactes au lieu de bulles d'agent (#12716), les cartes de flux sont entièrement clickable (#13294), le le raccourci d'archivage des pages de tâches est de retour (#13253), les instructions des agents ne sont plus enregistrées faussement (#12502), la navigation dans l'entreprise est limitée aux adhésions accessibles (#13039), les tâches récentes ne font plus écho aux commentaires de stockage dans les onglets (#13402) et les transitions plan-auto ne se produisent que selon le plan. (#12695).
  • Adaptateurs — Le message de limite d'utilisation Claude sans qualificatif est détecté dans la classification des quotas (#12475), la connexion au Codex et le test d'environnement s'accordent sur les informations d'identification utilisées par une exécution (#13064), le démarrage du Codex trust, les lectures de l'historique et la reprise de l'utilisation sont corrigés (#13110), Grok met en scène son test d'environnement à partir d'un répertoire hôte et survit à un espace de travail absent (#13416), et le repli involontaire du moteur est évité tout en préservant les paramètres d'exécution par défaut utilisables (#13105).

Guide de mise à niveau

  • Aucune nouvelle exigence de plate-forme : le plancher Node.js 24.11.0 de v2026.831.0 est inchangé.
  • Migrations : cette version ajoute 49 migrations de bases de données (0231 à 0279). Ils s'exécutent automatiquement au démarrage. Par train : nettoyage des lignes redondantes du profil de l'outil de connexion d'application créées automatiquement (0231), des autorisations de connexion et des identités déléguées (0232), des connecteurs MCP externes gérés (0233), des traces du fournisseur d'exécution natif, de l'unicité de l'événement d'exécution, des backends, de la récupération de session et des objectifs de session (0234–0235, 0237–0238, 0248), suppression de profils de modèles bon marché stockés (0236), identités GitHub durables et contextes d'identité d'exécution par personne (0239–0245), connexion de services et examen des actions de connexion à partir de tâches (0246–0247, 0249), récupération de tâche durable (0250–0254), fournisseur de chat et fondation de données (0255–0270), liaisons de connexion Codex par agent (0271), boîtes de réception AgentMail (0272), démarrages sécurisés pour le déploiement (0273), chat d'agent (0274), iMessage Photon (0275), connexion IA et paramètres par défaut du fournisseur par utilisateur (0276-0277) et état de rejet de l'annonce (0278-0279). Seuls les modèles 0231 et 0236 suppriment les données : le profil d'outil redondant inclut respectivement les lignes et les profils de modèle bon marché supprimés ; tout le reste est additif.
  • Nouvelles variables d'environnement facultatives :
    • SENTRY_DSN_FRONTEND / SENTRY_DSN_BACKEND — surveillance séparée des erreurs du navigateur et du serveur ; l'ancien SENTRY_DSN fonctionne toujours comme solution de repli pour l'un ou l'autre. (#12678)
    • PAPERCLIP_ANNOUNCEMENTS_ENABLED — les annonces dans l'application sont activées par défaut ; définissez-le sur false pour vous désinscrire. PAPERCLIP_ANNOUNCEMENTS_FEED_URL remplace l'alimentation (par défaut https://pages.paperclip.ing/announcements/v1/current.json). (#13403)
    • PAPERCLIP_TOKEN_BROKER_ALLOWED_HOSTS — hôtes supplémentaires séparés par des virgules que le courtier de jetons sandbox peut atteindre, pour les configurations MCP distantes (par défaut : aucun). (#12339)
    • PAPERCLIP_DISABLE_CWD_ENV_FILE — défini sur true pour empêcher le serveur de charger un fichier .env à partir de son répertoire de travail (par défaut : il se charge). (#12894)
  • Surface API supprimée : modelProfiles a disparu des métadonnées de l'adaptateur, de la configuration d'exécution de l'agent et des remplacements de tâches (#12683) ; Les valeurs env en texte brut dans les réponses des agents sont expurgées (#9860) ; L'option de configuration de connexion REST héritée d'Anthropic est supprimée (#13346).
  • Modifications de comportement à noter : la porte expérimentale Paperclip Runner enableNativeRunner est désormais activée par défaut pour les instances auto-hébergées – agents explicitement configurés uniquement, rien ne change automatiquement, les instances gérées dans le cloud restent désactivées (#13068) ; les nouveaux agents standard-trust peuvent embaucher d'autres agents par défaut (#12814), les modèles Claude non définis se résolvent en Opus 5 (#13055), les applications ne sont plus derrière une porte expérimentale (#12728) et X-Forwarded-Host nécessite le proxy trust (voir Dernières modifications).
