Papierclip v2026.1005.0

Sortie : 2026-10-05

Paperclip v2026.1005.0 comporte 179 commits, promus à partir de 2026.1002.0-beta.0. Le titre est des agents qui transportent plus avec eux : Grok Build s'exécute sur le programme d'exécution natif, les agents conservent leurs propres fichiers entre les tâches, les compétences de l'entreprise sont synchronisées à partir des référentiels GitHub et Browser Use Cloud offre aux agents un navigateur en direct que les utilisateurs peuvent regarder et prendre en charge. Autour de ceux-ci : la plupart des connecteurs sont désormais configurés dans un click avec les agrégateurs MCP activés par défaut, les conversations Slack aller-retour entre le tableau et le fil de discussion, Agent Chat obtient sa propre navigation et termine le travail sur la conversation, et le compositeur de tâches choisit le modèle et l'effort par message. En dessous, une longue passe de fiabilité renforce le programme d'exécution natif, le transport sandbox et le planificateur de battements de cœur, y compris un correctif pour une boucle de crash du serveur provoquée par une exécution en file d'attente rejetée définitivement.

Modifications radicales

  • L'injection d'extraits de code de l'interface utilisateur de l'opérateur est supprimée. Les paramètres PAPERCLIP_CLOUD_UI_SNIPPET et PAPERCLIP_CLOUD_UI_SNIPPET_B64 n'injectent plus de code HTML dans les pages statiques ou de développement. Les opérateurs qui comptaient sur eux doivent déplacer l'intégration vers une contribution d'interface utilisateur de plugin avant la mise à niveau. (#13789)
  • Les raccourcis clavier sont toujours activés et leurs paramètres ont disparu. La bascule Général à l'échelle de l'instance et la préférence de profil par utilisateur sont toutes deux supprimées, ainsi que les routes GET/PATCH /api/auth/preferences ; PATCH /api/instance/settings/general n'accepte plus keyboardShortcuts. Chaque utilisateur connecté dispose désormais de raccourcis activés. (#14141, #14643)
  • La mention @ d'un agent ne démarre plus une exécution. Les mentions dans les commentaires de tâche sont conservées comme contexte pour le responsable ; seules les demandes explicites d’affectation et de révision commencent à fonctionner. Les workflows qui utilisaient une mention pour attirer un deuxième agent sur une tâche doivent plutôt attribuer ou demander une révision. (#14577)

Faits saillants

  • Grok Build sur le runner natif — Grok Build rejoint le Paperclip Runner via ACP pour l'exécution locale et Daytona, avec une connexion par abonnement séparée et des chemins d'identification de clé API et des outils gouvernés (#13882) ; il est livré dans les installations publiques avec des binaires appartenant au bac à sable plutôt qu'un téléchargement au moment de l'installation (#14024). Les environnements d'exécution du faisceau partagé sont déplacés vers Codex 0.156.0, Claude Agent SDK 0.3.280 et OpenCode 1.18.32 (#13838), les catalogues de modèles et les contrôles de raisonnement sont actualisés sur les adaptateurs Claude, Codex, Grok, Gemini, Cursor, Kimi et OpenCode (#13829) et les adaptateurs natifs distants. Le Codex accepte les versions compatibles de 0.149.0 au lieu d'une broche exacte (#13853).
  • Les agents conservent leurs propres fichiers — Le répertoire d'un agent (AGENTS.md et ses fichiers de support) persiste désormais entre les tâches et les sessions et est partagé avec l'éditeur d'instructions ; les exécutions simultanées appliquent uniquement les fichiers qu'elles ont modifiés et les nouvelles sauvegardes ne créent plus d'historique de révision (#14420), en plus d'un nouveau transport de synchronisation de répertoire simple avec contrôle en amont des conflits (#14416). Les sessions Codex natives chaleureuses survivent à la collecte de fichiers gérés en vérifiant uniquement les fichiers modifiés après chaque tour (#14735).
  • Compétences synchronisées depuis le GitHub — Les compétences gagnent un onglet Sources : choisissez un référentiel via une connexion GitHub existante, choisissez les dossiers de compétences à importer et actualisez à la demande. Les instantanés installés signifient que les agents ne récupèrent jamais GitHub en cours d'exécution, et un échec d'actualisation laisse la dernière bonne version en place (#14713).
  • Browser Use Cloud, live in the task — Un nouveau connecteur Browser Use Cloud offre aux agents une automatisation du navigateur gouvernée, et les tâches affichent des onglets de navigateur interactifs où les utilisateurs peuvent suivre, reprendre la page et conserver le navigateur une fois l'exécution terminée, avec des coûts enregistrés pour l'exécution (#14627).
  • Connexions configurées dans un click — La configuration du connecteur se réduit à un seul écran qui indique ses valeurs par défaut et place le reste derrière « Modifier » et l'onglet Autorisations (#14811). Les agrégateurs MCP Zapier, Arcade, Composio Connect et Executor sont activés par défaut avec la bascule expérimentale supprimée (#13964), et ils peuvent être configurés à partir des cartes de tâches en ligne (#13879). La recherche de connexion préfère les applications natives, demande à l'utilisateur de choisir un fournisseur externe avant la configuration (#13941) et comprend les requêtes en langage naturel (#14725). Nouveau dans le catalogue : des lucioles avec des routines prêtes pour le résumé (#13890), cinq fournisseurs de mémoire expérimentaux (Mem0, Zep, Supermemory, Cognee, Honcho) derrière le paramètre enableMemoryConnectors désactivé par défaut, ainsi que des outils MCP attribués fournis au Codex natif distant (#13942) et le robot de révision de code GitHub en tant que sa propre carte distincte de Outils GitHub (#14750). Les informations d'identification personnelles collées sont validées de la même manière lors de la configuration, de la vérification de l'état et de l'appel, et les nouvelles connexions demandent les étendues d'écriture dont leurs actions ont besoin (#14739).
  • Slack va dans les deux sens : les réponses saisies sur le tableau atteignent le fil de discussion Slack lié et reprennent la même conversation, et les agents affectés obtiennent leurs outils Slack pendant les tâches ordinaires et les routines planifiées (#13920). Les tâches d'origine Slack bénéficient d'outils gouvernés pour lire la discussion environnante, créer des suivis et collaborer via le bot invitant (#13828), et une conversation avec réponse se met en veille au lieu de s'attarder en cours (#13809).
  • Agent Chat grandit — Une barre latérale de chat secondaire et une page de destination donnent aux conversations leur propre espace (#14706) ; les tâches déléguées depuis un chat lui renvoient durablement leur achèvement (#14408) ; une approbation claire tapée dans le chat résout la carte en attente et les questions sans réponse sont transférées dans l'historique où il est possible d'y répondre plus tard (#14613) ; et une discussion continue après la perte de son travailleur natif (#13813).
  • Un compositeur qui sélectionne l'exécution — Le compositeur de tâches obtient un modèle par message et un sélecteur d'effort qui suit l'agent sélectionné, garde les cartes en attente visibles au-dessus de lui et fonctionne sur mobile (#14322) ; les options d'effort correspondent à ce que chaque adaptateur exécute réellement, y compris le Codex sur le programme d'exécution natif (#14568, #14576). Les tâches peuvent être créées à partir d'une seule invite et l'agent affecté les nomme (#14761). Les artefacts reçoivent des cartes riches avec des aperçus (#14469), une galerie d'images et de vidéos avec des liens sur une ligne complète (#13825) et des pièces jointes Markdown et texte ouvertes dans les onglets de tâches avec des vues de rendu, brutes et de téléchargement (#14297).
  • Outils API régis, activés par défaut — Les outils search_api et call_api du coureur natif sont activés sans variable d'environnement (#14186) ; un grand flux de réponses API sur le disque jusqu'à 1 Gio et le texte enregistré est lisible dans des pages délimitées (#14301) ; et lorsqu'un catalogue d'applications attribué pousse le contrat d'outil au-delà de sa limite, les agents accèdent toujours à ces outils via la recherche et l'appel (#14218).

Correctifs

  • Native runner et sessions — Les résultats de l'outil survivent à l'arrêt et au redémarrage au lieu d'enregistrer un faux échec (#14734) ; Les sessions chaudes échouées sont retirées avant l'arrêt de leur bac à sable (#14747) et le nettoyage récupéré honore le résultat final de l'exécution (#14767) ; le passage d'une tâche à un cycle de vie chaud acquiert un bail réutilisable (#14187) ; le flux d'événements OpenCode reste ouvert d'un tour à l'autre (#14582) et délivre son règlement d'arrêt (#14668) ; Les notifications de compte Codex n'interrompent plus un tour (#13902) ; L'épuisement des quotas Claude et Codex est classé pour la réduction appropriée (#13831, #13945) ; Les échecs du terminal ACP conservent leurs diagnostics de fournisseur expurgés (#14573) et les gardes d'identité nomment le contrôle échoué (#14481) ; la limite native de lecture du journal est de 256 Mio partout (#14711) ; en attente de finalisation d'un résultat accepté est protégé contre le balayage de verrouillage obsolète (#14219) ; les adaptateurs exposent un arrêt de fournisseur vérifié avant la restauration de l'espace de travail (#14311) ; les sessions chaleureuses continuent de s'exécuter sous un accès géré GitHub (#13815) ; et une exécution qui rencontre un échec d'authentification du fournisseur offre une carte de connexion en ligne dans la tâche afin que l'utilisateur puisse réparer et continuer (#14629).
  • ** Bacs à sable et espaces de travail ** : les commandes Daytona restent actives après la fermeture du socket de journal (#14799), la perte confirmée du conteneur est reconnue lors de la reprise des baux (1f3ff75d), les allocations ayant échoué sont nettoyées (#13979) et les délais d'expiration d'acquisition du fournisseur respectent les valeurs par défaut du pilote. (#14097). Les tentatives de livraison d'entrée ACP après une passerelle 502 sans duplication d'entrée (#14485), les charges utiles de lancement surdimensionnées et le contexte de réveil dupliqué n'échouent plus avec E2BIG (#13793, #13891), les proxys de processus se ferment après la sortie à distance (#13777), et les liens symboliques relatifs dans les référentiels secondaires sont préservés (#13953). Les exportations de l'espace de travail sont finalisées et récupérées en toute sécurité (#14402), les échecs de restauration conservent le résultat de l'adaptateur et enregistrent ce qui a échoué (#14035, #14064), les instantanés Git volumineux sont diffusés via les manifestes de disque au lieu d'atteindre une limite de sortie de 1 Mio (#14194, #14253), les contrôles de préparation acceptent une sortie d'état plus importante (#14414), les analyses en arrière-plan arrêtent d'actualiser l'index Git (#14666), les remplacements de tâches partielles conservent les commandes de configuration du projet (#14502) et les tâches low-tbigint sans référentiel obtiennent un répertoire privé (#14766).
  • Planificateur et récupération — Une exécution en file d'attente dont la réclamation est définitivement rejetée est annulée au lieu de planter le serveur en boucle (#14738) ; les sillages qui arrivent pendant une vidange restent en file d'attente et les exécutions correctives interrompues font l'objet d'une nouvelle tentative transitoire (#14028) ; un problème dont l'exécution a dépensé son budget de nouvelle tentative est transmis à un état bloqué visible plutôt que ignoré pour toujours (#14046) ; les budgets de continuation et de nouvelle tentative utilisent l'état persistant (#13888) ; la propriété des tâches est revendiquée de manière atomique avec les exécutions en file d'attente (#13973) ; les continuations obsolètes sont annulées avant expédition (#13761) ; une réponse d'état qui répertorie toujours les travaux bloquants maintient la tâche en mouvement (#14626) ; Les tâches terminées et annulées conservent leur responsable à la sortie (#14561) ; les suites d'interaction restent limitées à leur tâche (ded156a9) et les destinataires des questions sont dérivés et validés (#14742) ; Les tâches d'origine Slack et Discord qui perdent leur chemin de révision sont récupérées avec leurs liaisons de message intactes au lieu d'échouer à la vérification de l'autorisation de récupération (#13818) ; Les exécutions de Grok à distance s'arrêtent avant que les messages en file d'attente ne continuent (#14100) ; les verrous d'identité d'exécution ne sont plus bloqués avec les insertions d'audit (#14478) ; et les déconnexions ambiguës de la base de données ne sont plus rejouées (#14773).
  • Connexions et applications : les défis de connexion OAuth et les états de reconnexion renvoient 422 au lieu d'être signalés comme des plantages (#13786, #13794) ; La configuration de MCP OAuth explique l'échec ou l'annulation du consentement (#13855) ; une application Slack MCP désactivée obtient des instructions de configuration exploitables (a7d3b17a) ; les échecs du courtier et d'AgentMail conservent les codes de raison sur la liste autorisée (#14098, #14768) ; Google Chat et les profils Docs, Sheets, Slides et Calendar nécessitent moins de portées (#13820, #14740) ; Les produits de travail valident leur référence d'espace de travail d'exécution (#14063) ; et les ID de défi d'authentification CLI mal formés renvoient 400 (#14095).
  • Board UI — La carte récupère lors du redémarrage du serveur avec un message de connexion et des tentatives, en gardant les éditeurs ouverts montés (#14560), et propose un écran de nouvelle tentative lorsque l'application échoue avant le démarrage de React (#13970). La surbrillance du code ne plante plus en cas d'incompatibilité de version de Lezer (a3749aac), les boutons de confirmation destructifs sont lisibles dans le thème clair (#14328), les sélecteurs mobiles restent visibles au-dessus du clavier et défilent au toucher (#14022, #14249, #14250, #14599), les brouillons les plus récents survivent au nettoyage des reçus (#14332), les échecs d'exécution des autres utilisateurs restent en dehors du mien (#14572), "Récupération nécessaire" se distingue de "Récupération en cours". (#14326) et une nouvelle tentative trompeuse n'apparaît plus lorsque la récupération est bloquée (#13775), les nouveaux artefacts enregistrent un onglet sans ouvrir le panneau (#14193), le panneau Tâches affiche les ancêtres (#13823) et le contenu des tâches apparaît plus tôt avec les lectures du serveur parallèle. (#14727). En outre : les icônes de propriété s'alignent sur les avatars (#13319), les commentaires du coureur s'alignent sur les réponses (#14716), les indicateurs de sauvegarde de projet s'empilent sous leur étiquette (#14765), l'archivage d'une entreprise s'éloigne (#13846), les paramètres expérimentaux sont classés par ordre alphabétique avec des groupes vides masqués. (#13905), et l'adaptateur de curseur sélectionne la véritable erreur sur un avis de trace (#14636).
  • Observabilité — Les erreurs du navigateur transportent SENTRY_ENVIRONMENT (#13784) et le contexte de composant limité (#13904) ; les erreurs d'exécution sont isolées des exceptions ultérieures et un en-tête de capacité d'exécution est rédigé (#13826) ; et les rapports d'échec d'exécution conservent les détails de sortie, les piles, les causes, l'activité d'exécution et la classification de restauration (#14575, #14585, #14665, #14639, #14787).

Améliorations

  • Le menu du compte supprime ses lignes de profil pour un lien d'en-tête et obtient un raccourci d'invitation (#14480) ; les plugins peuvent fournir un sélecteur d'organisation (#13832, #13854) ; PAPERCLIP_HIDDEN_SETTINGS accepte un caractère générique avec des exceptions nommées afin que les nouveaux indicateurs expérimentaux restent automatiquement masqués (#13980) et une clé workspaces.isolation masque les contrôles d'isolement (#13907) ; le coureur natif obtient une base de transport riche-ACP partagée pour les prochains fournisseurs Cursor, GitHub Copilot et Pi (#14430) ; les agents natifs peuvent embaucher des coéquipiers via une action hire_agent gouvernée qui hérite de la configuration d'exécution de l'appelant à partir d'une liste verte fermée (#13852) ; la compétence de coordination ne dit plus aux agents de passer par les managers au lieu de demander à l'humain qui peut agir (#14188) ; les échecs de la source de départ de l'arbre de travail expliquent les configurations prises en charge (#14795) ; Les connecteurs Google Workspace sont temporairement masqués de la page Connexions pendant que la vérification Google OAuth est en attente, les connexions enregistrées et l'accès à l'exécution restant intacts (#14774) ; et le README est actualisé avec les harnais actuels, des liens de guide et un démarrage rapide npx-first (#14741, #14744).

Guide de mise à niveau

  • Les migrations 0284–0293 s'exécutent lors de la mise à niveau : 0284 ajoute et 0289 supprime la colonne keyboard_shortcuts par utilisateur ; 0285 élargit assets.byte_size à bigint ; 0286 ajoute les réservations de capture de réponse API ; 0287 ajoute des têtes d'instructions d'agent, des révisions et des copies de travail pour les fichiers d'agent persistants ; 0288 ajoute les livraisons d'achèvement de chat et les transferts de tâches ; 0290 ajoute des sessions, des exécutions et des navigateurs Browser Use Cloud ; 0291–0292 ajoutent des sources et des entrées de compétences de l'entreprise, et 0291 adopte également des compétences existantes importées de github.com (une source par référentiel et référence de suivi, une entrée par compétence et legacySkillSourceId / skillSourcePath estampillé dans les métadonnées de chaque compétence ; les compétences importées depuis les hôtes GitHub Enterprise, les compétences regroupées et les compétences de catalogue sont laissées telles quelles, et aucune demande de fournisseur ni réécriture de contenu arriver); 0293 ajoute issues.title_needs_generation.
  • Les extraits de l'interface utilisateur de l'opérateur sont supprimés (#13789) : PAPERCLIP_CLOUD_UI_SNIPPET et PAPERCLIP_CLOUD_UI_SNIPPET_B64 sont ignorés. Déplacez l’intégration vers une contribution de l’interface utilisateur du plugin avant la mise à niveau.
  • Les paramètres de raccourci clavier sont supprimés (#14643) : supprimez toute automatisation qui appelle /api/auth/preferences ou envoie keyboardShortcuts vers la route des paramètres généraux.
  • Les mentions d'agent ne sont plus réparties (#14577) : utilisez une affectation ou une demande de révision pour amener un autre agent sur une tâche.
  • Nouveaux paramètres par défaut : les outils API du coureur natif sont activés sauf si PAPERCLIP_RUNNER_API_TOOLS_ENABLED est défini sur autre chose que true ; PAPERCLIP_RUNNER_API_TOOLS_COMPANY_IDS les réduit toujours (#14186). Les agrégateurs MCP sont disponibles sans l'ancien indicateur enableMcpAggregators (#13964).
  • Nouvelles variables d'environnement, toutes facultatives : PAPERCLIP_RUNNER_API_COMPANY_CAPTURE_MAX_BYTES limite les octets de réponse API capturés par entreprise (20 Gio par défaut, minimum 1 Gio ; #14301) ; PAPERCLIP_WORKSPACE_GIT_SNAPSHOT_TIMEOUT_MS limite la durée de l'instantané de l'espace de travail (30 minutes par défaut, 24 heures maximum) et PAPERCLIP_WORKSPACE_MANIFEST_MIN_FREE_BYTES définit la réserve de disque libre pour les manifestes d'instantané (256 Mio par défaut, 64 Mio minimum ; #14253). Les exécutions Codex ACP acceptent CODEX_API_KEY comme alternative à OPENAI_API_KEY (#14322).
  • Les broches du harnais ont été déplacées vers Codex 0.156.0, Claude Agent SDK 0.3.280 et OpenCode 1.18.32 (#13838) ; les installations partagées doivent actualiser les CLI de leur fournisseur pour qu'ils correspondent.
  • Aucune autre configuration ou modification du API ne nécessite d'action.
