Papierclip v2026.1106.0

Sortie : 2026-11-06

Paperclip v2026.1106.0 comporte 515 commits, promus à partir de 2026.1023.0-beta.0. Le titre est que le Paperclip Runner est désormais la valeur par défaut pour les nouveaux agents : les nouveaux agents Claude, Codex, OpenCode et Pi démarrent sur le Runner natif sur des hôtes macOS et Linux qualifiés, les agents existants bénéficient d'une action unique click "Mettre à niveau le coureur" et GitHub Copilot se joint en tant que harnais natif. Autour de cela : des référentiels de projets qui deviennent automatiquement des sources de compétences, une prévention des injections rapides basée sur un modèle, l'observabilité des agents vers Braintrust ou tout autre point de terminaison OTLP, une connexion Google Workspace unifiée, des modifications groupées sur la liste des agents, des espaces de travail qui se compactent et expirent eux-mêmes avec des points de restauration cryptés, et Grok Bot et Muse en tant que fournisseurs expérimentaux de Runner. En dessous, le serveur redémarre, le rapport est prêt plus tôt, l'image Docker démarre à partir d'un ensemble précompilé, les pages de tâches se chargent plus rapidement et davantage de services d'arrière-plan arrêtent d'interroger la base de données.

Modifications radicales

  • L'expérience Pipelines est supprimée. Les tableaux de pipeline, les paramètres de scène, l'automatisation des cas, les files d'attente de révision, les commandes pipelines CLI, l'autorisation pipelines:write, le paramètre enablePipelines et le champ linkedCases sur les détails de la tâche ont disparu ; Les cas et les routines demeurent. Les tables et enregistrements de pipeline existants sont conservés intacts et une valeur enablePipelines stockée est ignorée. (#16834)
  • Les échecs d'exécution n'atteignent plus Sentry par défaut. Un DSN backend à lui seul ne signale plus les échecs d'exécution de l'agent. Définissez PAPERCLIP_SENTRY_RUN_FAILURES=unexpected pour conserver la stratégie filtrée précédente ou all pour signaler chaque exécution ayant échoué ou expiré ; la valeur par défaut est off. (#16300)
  • La liste de l'historique d'exécution est limitée. GET /api/companies/{companyId}/heartbeat-runs renvoie 200 lignes par défaut et au maximum 1 000 ; Les clients qui s'appuient sur un tableau illimité doivent transmettre un limit explicite. (#16286)
  • paperclipai agent instructions-file:delete nécessite --yes comme les autres commandes destructrices du CLI ; les scripts qui l'appellent doivent ajouter le drapeau. (#11504)

Faits saillants

  • Le Paperclip Runner est la valeur par défaut — Nouveaux agents Claude sur Apple Silicon, Intel macOS et Linux x64 (#15993, #15997), nouveaux agents Codex sur Apple Silicon, Intel macOS, Linux x64 et Linux ARM64 (#15683) et nouveaux agents OpenCode et Pi sur macOS et Linux x64 (#17120, #17142) démarre désormais sur le Runner natif au lieu de l'adaptateur existant, à travers l'intégration, les API et CLI, les embauches, les intégrés, les plugins et les importations ; Linux a besoin de GNU libc 2.39 ou version ultérieure, un remplacement de "Legacy runner" se trouve sous Advanced et les agents existants conservent leur runner actuel. Les agents Claude et Codex existants sur les cibles qualifiées affichent une action Mise à niveau du coureur qui les convertit en un seul click, en conservant le modèle, le compte et les instructions et en répertoriant tous les paramètres qui n'ont pas pu être convertis (#17122). Les agents Claude Runner démarrent avec leurs outils de tâches de base préchargés, mesurés environ 20 % plus rapidement sur des tâches simples (#16885), effectuent le niveau d'effort choisi jusqu'aux CV (#15994) et démarrent sous Linux ARM64 (#16372).
  • GitHub Copilot en tant que harnais natif — Connectez le GitHub Copilot via des applications/connexions AI avec un jeton GitHub enregistré ; la liste de modèles de l'agent est découverte à partir du compte authentifié et Copilot (CLI 1.0.88) exécute Paperclip Runner avec les mêmes limites d'instructions, d'autorisations et d'achèvement que les autres fournisseurs natifs, y compris le manifeste du fournisseur Linux nécessaire pour les bacs à sable Daytona (#15705, #15701, #15706).
  • Les référentiels de projet deviennent des sources de compétences — Les référentiels GitHub attachés à un nouveau projet sont automatiquement importés en tant que sources de compétences : Paperclip importe leurs compétences, revérifie la branche configurée toutes les cinq minutes avec la connexion GitHub de la personne chargée de l'installation et installe de nouvelles compétences sauf si elles sont exclues ; les projets existants bénéficient d'une action « adopter les référentiels » dans Compétences → Sources, les mises à jour automatiques peuvent être suspendues, les compétences dérivées du projet héritent de l'accès au projet et chaque exécution épingle les versions de compétences avec lesquelles elle a commencé (#16066). Les importations conservent l'instantané complet du référentiel lors de la validation analysée afin que les compétences qui dépendent de scripts partagés ou de compétences frères fonctionnent après la livraison, répertorient chaque compétence avec son dossier et ignorent les fichiers non pris en charge ou surdimensionnés avec un avertissement au lieu d'échouer (#15731, #16308). Les sources bénéficient d'un sélecteur de branche qui charge les branches du référentiel, marque la valeur par défaut et valide la référence avant de sauvegarder (#16288) ; une source dont la branche suivie a disparu montre une action de réparation de branche (#16256) ; chaque source enregistrée est répertoriée une fois avec des erreurs d'actualisation groupées (#16310) ; et déconnecter une source la supprime réellement, avec un choix de conservation ou de suppression pour les compétences importées (#16150).
  • Prévention des injections d'invite basées sur un modèle — Paramètres → Connexions permet à un gestionnaire de connexions de choisir une connexion et un modèle OpenRouter partagés (openai/gpt-oss-safeguard-20b par défaut) pour classer les résultats de l'outil avant qu'ils n'atteignent un agent, remplaçant le verdict regex et autorisant un code inoffensif qui ressemble simplement à une attaque ; les coûts apparaissent dans Coûts et une action « Test model checks » vérifie deux échantillons fixes. Éteint jusqu'à ce qu'il soit configuré. (#16976)
  • Observabilité de l'agent sur votre propre backend — Paramètres de l'entreprise → Général → L'observabilité de l'agent envoie les journaux et les traces natifs du Codex et Claude Code à Braintrust (États-Unis) ou à un point de terminaison HTTP OTLP personnalisé, avec des informations d'identification conservées dans les secrets de l'entreprise et une action de test ; désactivé par défaut (#16874). Braintrust rejoint également le catalogue d'applications avec la connexion aux États-Unis et dans l'UE ou les méthodes de clé API (#17141).
  • Une connexion Google Workspace unifiée : une entrée Google Workspace remplace les configurations de services Google distinctes : choisissez Gmail, Drive (Docs, Sheets, Slides) et Calendrier, chacun étant facultativement en lecture seule, et le consentement et l'accès aux outils sont liés à cette sélection ; les connexions Google existantes continuent de fonctionner (#15545). Gmail bénéficie d'une fonctionnalité d'archivage facultative (#16331).
  • Espaces de travail qui se nettoient après eux-mêmes — Une heure après la fin d'une arborescence de tâches, le récupérateur d'espace de travail du terminal supprime les répertoires régénérables tels que node_modules, dist et target que le propre .gitignore du référentiel ignore, en conservant la branche et toutes les modifications de source ; le temps de recharge de l'archive passe de 7 jours à 1 (#16304). L'expiration du cache Git par opt-in supprime les arbres de travail terminés appartenant à Paperclip et les clones de base privés 24 heures après la fin de l'arborescence des tâches et les restaure à la validation exacte lorsqu'une tâche rouvre (#16457, #16691) ; avec les points de restauration activés, les arbres de travail fermés qui contiennent encore des validations non poussées ou des fichiers non validés sont d'abord enregistrés dans un point de restauration chiffré et restaurés exactement lorsque le travail reprend, les problèmes ouverts inactifs sont garés de la même manière après sept jours, les extractions multi-référentiels imbriquées obtiennent leurs propres points de restauration et une tâche dont le point de restauration a expiré rouvre sur un nouvel espace de travail avec une note au lieu d'échouer (#17248, #17271, #17257, #17269). Les versions de compétences matérialisées inutilisées sont supprimées toutes les heures et reconstruites à la demande (#16433), et les sauvegardes de basculement côté hôte des sessions sandbox distantes expirent une semaine après la fermeture de leurs problèmes (#16866).
  • Tâches avec leur propre espace de travail — Une tâche qui nécessite des fichiers mais n'a pas de source configurée obtient désormais un répertoire d'entreprise/tâche stable au lieu d'hériter du dossier personnel de l'agent, les agents peuvent inspecter, sélectionner et demander des référentiels pour leur espace de travail via de nouveaux outils d'exécution, et les connexions de discussion peuvent définir les paramètres par défaut du projet et de l'espace de travail (#15749) ; une nouvelle tâche obtient son propre clone lorsque l'extraction par défaut du projet contient un arbre de travail que l'agent ne peut pas lire (#16095), avec un click Réessayez sur une extraction propre lorsque l'installation est bloquée de cette façon (#16909).
  • Modifications groupées sur la liste des agents — Sélectionnez les lignes et filtrez par faisceau pour modifier la connexion IA, le modèle par défaut, ou les deux pour plusieurs agents à la fois, avec un aperçu et une nouvelle tentative en cas d'échec des mises à jour ; le sélecteur de statut de la liste est supprimé et les agents en pause affichent un badge au lieu d'être grisé (#17215). La vue d'ensemble de l'agent indique qui a créé un agent dans les entreprises comptant plus d'une personne (#16055).
  • Grok Bot et Muse, tous deux expérimentaux — Grok Bot vous permet d'inviter un Grok Bot existant en tant qu'agent qui reçoit des missions via une routine webhook et travaille via une connexion agent-OAuth MCP dédiée, avec une configuration guidée, des codes d'appariement, des progrès, des questions, des documents et des fichiers renvoyés dans la tâche, ainsi que des contrôles d'arrêt et de récupération ; les dépenses des prestataires ne sont pas déclarées (#16219, #16338, #16274, #16305). Muse associe une Meta Muse personnelle via un récepteur de réveil uniquement et un OAuth soutenu par Vault avec un ticket à usage unique de dix minutes, avec des commandes de préparation, d'expiration des informations d'identification et de déconnexion dans la boîte de dialogue d'invitation (#16444, #16447, #16448, #16450).
  • Parler à un agent avec Speko — Une entrée Speko dans le catalogue d'applications connecte un personnage Speko à un agent existant afin que vous puissiez lui parler par la voix du navigateur ou par téléphone à partir d'une tâche, avec des transcriptions, des contrôles d'appel, des paramètres de ligne entrante, des rappels téléphoniques et des entrées d'appel dans Activité ; affiché lorsque le paramètre expérimental Connecteurs de chat est activé (#15728).
  • Bots Slack affinés — Les paramètres de connexion Slack sont simplifiés autour de « Ouvrir la configuration Slack » et d'une ligne « Envoyer un message de test », avec « Utiliser votre propre application » sous Avancé (#15679) ; Les messages directs simples démarrent ou continuent toujours à fonctionner même lorsque Exiger une mention est activé pour les threads de canal (#16151) ; et la réaction des yeux apparaît dès qu'une mention est acceptée, y compris dans les messages directs (#16491, #16494).
  • Un robot de révision GitHub plus robuste — Le robot maintient un commentaire principal de relations publiques mis à jour lors des push, ignore les messages adressés à d'autres robots et marque avec précision l'arrêt du travail (#16901) ; les commentaires récapitulatifs portent le nom d'affichage du bot afin que plusieurs robots sur un PR puissent être distingués (#16212) ; tentatives de publication via GitHub 503/429 avec un délai d'attente limité et survit aux redémarrages sans commentaires ni vérifications en double (#16284, #16883) ; Les outils de robot GitHub obtiennent le maximum de 60 secondes de la passerelle, donc submit_review n'expire plus (#16275) ; et les paramètres affichent un avis « Reconnecter GitHub » avec reconnecter l'application enregistrée comme première option (#16856).
  • Plus d'applications dans le catalogue — Daytona, avec des informations d'identification de clé API personnelles ou partagées et 274 actions générées pour les bacs à sable, les instantanés, les volumes, les fichiers, Git et les commandes (#16483) ; Unikraft Cloud, avec des actions générées à partir de ses spécifications OpenAPI et un métro par défaut par connexion (#17139) ; et Idem (#16472). Une carte fournisseur avec plusieurs connexions les regroupe derrière une ligne "N connexions" (#16097).
  • Commentaire d'agent dans Audit — Les plaintes et suggestions que les agents déposent concernant leurs outils disposent désormais d'un onglet Commentaire avec des filtres d'agent et de type, une recherche de texte, une pagination et des liens partageables (#16884), lisibles par tous les rôles humains via une nouvelle autorisation commentary:view (#16903).

Correctifs

  • Espaces de travail et bacs à sable — Un bac à sable distant dont l'exécution a échoué avant l'exportation, dont le bail a été nettoyé avec du travail non exporté ou dont la tâche a été annulée avant la reconstruction est conservé avec ses fichiers derrière une décision de réparation explicite au lieu d'être supprimé par le nettoyage (#16397, #16583, #16700) ; une tâche dont le bac à sable a été détruit avant l'exportation propose une action "Continuer à partir des sources enregistrées" uniquement sur le tableau (#16690) ; les fichiers laissés dans le bac à sable d'une exécution arrêtée sont récupérés automatiquement et les suivis enregistrés sont livrés une seule fois (#16906) ; une exportation d'espace de travail au moment de l'arrêt conserve sa propriété via le drain du finaliseur (#16843) ; une longue copie ne perd plus son verrouillage en raison du délai d'attente de transaction inactive de PostgreSQL (#16340, #16956) ; la reprise d'un bac à sable réutilisable arrêté respecte le délai d'expiration de démarrage de l'environnement au lieu d'un délai fixe de 60 secondes (#16802) ; un seul contrôle de santé expiré ne remplace plus un Runner distant (#16835) ; s'exécute sur des référentiels avec des milliers d'espaces de travail historiques qui ne restent plus en "préparation" pendant des heures (#16372, #16334, #16342, #16963) ; une caisse partagée ne reste plus bloquée par un lecteur dont l'identité a disparu (#16928) et un espace de travail bloqué par l'arbre de travail restreint d'une autre tâche reçoit un avis de configuration clair au lieu d'un 403 opaque (#16545, #16895) ; une tâche enfant héritant d'un espace de travail partagé occupé attend au lieu d'échouer avec une erreur de secrets trompeurs (#16371) ; et la création d'une tâche avec le sélecteur d'isolement masqué n'échoue plus la configuration (#16220).
  • Exécutions, récupération et nouvelle tentative : les tâches conservées derrière un espace de travail conservé ou après un échec d'exécution bénéficient d'une nouvelle tentative fiable au niveau de la tâche qui préserve les fichiers, règle les résultats acceptés ou démarre un espace de travail indépendant (#16965, #17053, #16894, #16104) ; L'arrêt empêche la poursuite automatique jusqu'à la reprise (#17105, #14180) ; un redémarrage du serveur ne bloque plus les exécutions natives sur des mises en attente permanentes, ne répète plus les achèvements enregistrés ou n'écrase plus les arrêts de l'opérateur définis entre-temps (#16349, #16962, #16403, #15824) ; Les exécutions héritées supprimées ou perdues avant l'envoi sont réessayées au lieu d'être réglées comme ayant échoué (#16355, #16358), un achèvement lent ne fait plus échouer un contrôleur actif (#16622), et les requêtes lentes non liées ne coûtent plus aux exécutions héritées leur bail (#17032) ; un commentaire normal sur une tâche en cours n'annule plus sa nouvelle tentative d'exécution (#16855), et l'arrêt d'une exécution en file d'attente avant qu'elle ne démarre conserve son suivi enregistré au lieu de l'exécuter quand même (#16357) ; les messages pour les agents en pause ou pour un agent autre que le propriétaire de la tâche sont délivrés une seule fois au lieu d'être en échec ou différés pour toujours (#16679, #16673) ; un agent bloqué marqué « en cours d'exécution » est réparé après un délai de grâce de cinq minutes (#16791) ; une exécution Claude (ACP) avec un appel d'outil bloqué échoue après 30 minutes au lieu de s'exécuter jusqu'au délai d'expiration de quatre heures, et les appels MCP obtiennent un délai d'attente de 15 minutes (#16671, #16360) ; un épuisement de tours maximum n'est plus classé à tort comme modèle manquant (#13885) ; et une réponse Codex « modèle à capacité » est réessayée comme étant transitoire (#16407).
  • Interface utilisateur de discussion et de tâche — Le rejet d'une demande au-dessus du compositeur efface le badge, survit au rechargement et ne bloque plus la nouvelle tentative (#17218) ; un message adressé à un agent Runner n'échange plus brièvement son avatar contre une ligne générique "Working" (#16989) ; un suivi consommé quitte la file d'attente en attente (#16317) ; la réponse finale d'une tâche worktree n'est plus remplacée par la notification "espace de travail prêt" (#16400) ; un fichier joint avant que le premier message Agent Chat ne survive à la création de la tâche (#16896) ; les toasts de tâches dans une entreprise multi-utilisateurs apparaissent uniquement pour les personnes impliquées dans la tâche (#16153) ; le chargement d'une liste de tâches n'ajoute plus de tâches terminées sans rapport avec votre boîte de réception (#16063) ; répond par défaut au dernier agent qui vous a assigné la tâche (#15594) ; les languettes du panneau latéral conservent une largeur constante (#17068, #14949) ; Les éditeurs Markdown n'affichent plus les modifications non enregistrées lors du chargement (#13915) ; et une tâche Slack qui donne lieu à une continuation planifiée renvoie son résultat au thread d'origine (#17045).
  • Coûts et budgets — Un budget à son seuil d'avertissement s'affiche sous la forme d'un avertissement au lieu d'une fausse bannière « AGENT HARD STOP » (#16201), et les contrôles budgétaires ne s'adaptent plus au nombre d'agents inactifs non liés dans l'entreprise (#17046).
  • Connexions et MCP — Un appel MCP distant échoué ne rend plus indisponibles tous les outils frères sur cette connexion (#16890) ; un fournisseur 403 sur une opération de chat ne désactive plus l'ensemble de la connexion Slack, GitHub ou Discord (#16847, #16138) ; Les outils de canal GitHub et Slack restent disponibles lors des exécutions ultérieures de la même tâche (#16806) ; plusieurs réponses au fil de révision GitHub reçoivent chacune leur propre exécution de suivi (#17054) et les descripteurs d'outils identiques sont répertoriés une fois (#16281) ; une actualisation importante du catalogue MCP ne répertorie plus un outil deux fois ou ne se bloque plus avec un rappel OAuth (#16602) ; les résultats d'outils attribués sur environ 500 Ko renvoient une référence limitée et un outil read_tool_result au lieu de se bloquer (#16980) ; les anciennes commandes shell du Codex peuvent voir les secrets de service explicitement attribués (#17216) ; le coureur natif call_api suit les propres autorisations de la route sans liste de refus supplémentaire (#16040) ; et les agents en bac à sable peuvent lire l'historique d'exécution, les pièces jointes, les fichiers de compétences et les enregistrements de récupération et envoyer le jeton de pont sous la forme X-API-Key (#16575, #16892, #12785).
  • Adaptateurs et CLI — Une exécution illimitée de Claude ne fait plus échouer sa sonde CLI après une seconde (#15329) ; Les exécutions simultanées à distance de Claude d'un agent n'interrompent plus la mise en scène des compétences de chacun (#17061) ; une tâche Claude isolée avec les outils MCP attribués démarre (#17149) ; un bac à sable dont le Claude CLI préinstallé est plus ancien que ce dont le modèle sélectionné a besoin obtient la version requise installée en privé lors de l'installation au lieu d'échouer à la vérification de version (#17259) ; l'installation d'un serveur Claude (ACP) n'échoue plus car le pont ACP manquait dans le package du serveur (#15912) ; un tour Runner OpenCode survit à des événements SSE surdimensionnés (#16401) et utilise les informations d'identification GitHub gérées de l'exécution dans les commandes shell (#16488) ; Hermes rappelle à l'URL API configurée par l'adaptateur (#9425) ; Les journaux d'exécution de pi_local sont environ 150 fois plus petits (#10249) ; paperclipai install et update fonctionnent avec npm 12 et Node 26 (#14000) ; paperclipai service install n'écrit plus un service qui plante en boucle sur une cale gérée manquante (#13985) ; et la connexion au navigateur CLI honore les en-têtes Retry-After à limite de débit (#16482).
  • Serveur et Docker — Le démarrage n'échoue plus sur les anciennes bases de données SQL_ASCII (#16958) ou ne plante plus sur un publicBaseUrl sans schéma (#13727) ; un serveur derrière un proxy inverse avec des recherches PTR lentes ne cesse plus de répondre pendant quelques minutes après la mise à niveau (#16333, #16335) ; une connexion groupée abandonnée n'échoue plus aux contrôles d'autorisation, à la préparation de l'espace de travail ou au Reaper (#16857, #16859) ; Docker démarre avec de nombreux fichiers sur le volume de données ou un USER_UID/USER_GID autre que celui par défaut ne parcourt plus tout le volume (#15992, #16475) ; les deux fichiers Compose expédiés transmettent PAPERCLIP_TOOL_ACTION_SIGNING_SECRET (#15202) ; un Stop qui dure plus longtemps que la synchronisation renvoie un 409 réessayable au lieu d'un 500 (#16032) ; le titre de la tâche simultanée ne modifie plus 500 (#13898) ; un ID de commentaire mal formé ne bloque plus les réveils en file d'attente d'une tâche (#13912) ; les réveils de surveillance délivrent les instructions de l'opérateur (#13771) ; le plafond de tâche enfant ne compte que les enfants ouverts (#11542) ; un agent simple peut à nouveau commenter les tâches (#12621) ; un transfert humain à partir d'une exécution héritée n'est plus annulé par une restauration lente (#16082) ; et les exportations de commentaires maintiennent les identifiants publics lisibles tout en masquant les vrais jetons (#16168).

Améliorations

  • Les cas expérimentaux conservent une tâche principale lors des transferts d'agents avec un grand livre de transfert durable, des outils natifs create_case, read_case, update_case et handoff_case, des pages de cas en lecture seule et des invites de flux de travail nommées réutilisables qu'un cas adopte au lancement ou au transfert (#16959, #17114).
  • Un échec de vérification du cycle de vie de l'agent nomme l'étape ayant échoué et une action corrective (#16418), et l'intégration crée l'enregistrement de l'agent dès que vous soumettez son nom, de sorte que la configuration et les tentatives conservent une identité (#17005).
  • Les plugins peuvent s'abonner aux événements du cycle de vie des projets et des agents validés avec relecture au lieu d'interrogation (#16203) ; recevoir les modifications de configuration, d'instructions, de compétences, de connexions, d'outils et d'autorisations de l'agent via des hooks d'exécution durables (#16499, #16501, #16603, #16604, #16605) ; stocker les secrets d'instance appartenant à l'agent et au projet dans le magasin de secrets chiffrés (#16191, #17034) ; propre stockage de projet et espaces de travail de tâches, agir en tant que fournisseur d'espace de travail par défaut et exécuter des tâches Runner natives dans des environnements appartenant au plug-in vérifiés par le test d'environnement d'agent (#17001, #17247, #16978, #17029, #17252, #15406); et déclarez les routes WebSocket authentifiées et les vues détaillées de l'agent (#17111).
  • Plus de travail en arrière-plan attend les écritures validées et les délais connus au lieu d'interroger la base de données : maintenance des télégrammes (#16094), nettoyage de l'espace de travail du terminal (#16282), nettoyage de la connexion (#17106), récupération du contrôle d'exécution (#17094), abonnements aux événements MCP. (#17036) et synchronisation des compétences-sources (#17008) ; les routines et les moniteurs de tâches se déclenchent à leur date limite enregistrée au lieu d'attendre la prochaine analyse (#16514).
  • Démarrages plus rapides partout : le serveur est signalé prêt plus tôt après un redémarrage car le ménage s'exécute après la préparation et les finalisations réglées sont ignorées (#16329, #16485, #16328) ; l'image Docker démarre à partir d'un ensemble d'exécution précompilé, réduisant le temps de chargement du code de 24 secondes maximum à moins de 4 (#16672) ; les pages de tâches se chargent paresseusement, diffèrent le rendu masqué et actualisent la barre latérale des tâches récentes via une requête limitée (#16849, #16878, #16851, #16862) ; et les lancements d'agent chevauchent GitHub, la préparation des compétences, des outils et du sandbox, réutilisent un cache d'objets Git par entreprise et des fichiers image sandbox vérifiés, et effectuent beaucoup moins d'appels à la base de données et à Daytona (#16620, #16608, #16585, #16487, #16687, #16493, #16683, #16536, #16521, #16527, #16561, #16468, #16480, #16552, #16484, #16473, #16425, #16424, #16461, #16498, #16576, #16569, #16414, #17026).
  • Les tâches, les listes de projets, la découverte de la boîte de réception et les tâches bloquées créées par l'agent et le système sont masquées par défaut derrière un filtre « Afficher les tâches créées par l'agent » enregistré par entreprise (#16157), et la boîte de réception « Mine » exclut les tâches créées par le canal, la routine et l'agent, sauf si vous avez commenté, été assigné ou si vous avez une demande ouverte (#16356) ; les avis d'échec affichent uniquement la dernière erreur avec son action de nouvelle tentative (#16982) ; et une carte de demande de connexion expirée indique ce qui n'est toujours pas connecté (#14067).
  • Une présentation expérimentale Artefacts V1 affiche des piles de papier et des tuiles sur la page Artefacts, des lignes compactes dans le panneau et des lignes regroupées dans le fil de discussion (#17228) ; vous pouvez télécharger des fichiers directement dans le panneau Artefacts par icône ou par glisser-déposer sans envoyer de message (#15964) ; la page de récupération hors ligne correspond à l'application (#16904) ; le bouton d'entête "Exécuter avec trace du fournisseur" est remplacé par la configuration de débogage de l'agent (#17211) ; et l'onglet Accès d'une application affiche les photos des utilisateurs liés (#15577).
  • L'ajout d'une compétence de référentiel à un agent ne se bloque plus lors d'une lecture de bibliothèque complète (#16899) et les arguments non valides aux outils attribués, call_api et set_task_monitor renvoient les emplacements de schéma et les instructions de réparation (#16905, #16889, #16868, #16961).
  • Les agents paperclip_runner peuvent configurer homeMode: "preconfigured" pour qu'il exécute Codex natif ou ACPX Claude avec la connexion, les compétences et la configuration MCP existantes du compte d'exécution (#16486) ; le Runner signale des informations d'identification OAuth actualisées sans valeurs de jeton traversant le protocole (#16463) et peut enregistrer des serveurs MCP stdio locaux de session vérifiés sur Unix (#16526) ; la tâche PATCH API accepte expectedStatusVersion pour la promotion du backlog to-do (#16893) ; et un GET /api/liveness anonyme signale l'activité du processus sans toucher à la base de données (#16101).
  • Les rapports d'échec enregistrent pourquoi un tour OpenCode échoue lorsque son serveur s'arrête (#16863) ; Les rapports Sentry pour les échecs d'exécution renvoient aux pages de tâche et d'exécution, ignorent les limites de quota du fournisseur classifié et signalent une nouvelle tentative native uniquement à la fin de la nouvelle tentative (#16803, #16029, #16865) ; les moniteurs de tâches dues détenus par l'enregistrement de récupération pourquoi dans l'activité de tâche (#16891) ; et, lorsqu'un point de terminaison OTLP est configuré, trace les plages de gain pour la préparation du contrôleur, la configuration de l'exécution, la préparation de l'espace de travail et du connecteur et la finalisation (#16178, #16236, #16419, #16428, #16454, #16515).

Guide de mise à niveau

  • Les migrations 0334–0374 s'exécutent lors de la mise à niveau. Schéma additif : instantanés de compétences du référentiel 0334, 0341 et 0342, project_skill_sources et budgets d'importation ; 0335 chat_slack_manager_grants et son lien depuis les inscriptions Slack ; Tables de référentiel de l'espace de travail d'exécution 0336–0338 ; 0339 et 0370 appartenant à des agents, plugins et projets company_secrets ; Tables Grok Bot 0344 et 0346 ; Tables Muse 0349–0353 ; 0357 company_observability ; Tableaux de prévention des injections rapides 0362 ; Tableaux de transfert de cas et de flux de travail 0363–0368 et 0371 ; 0372–0374 execution_workspace_restore_points ; Colonnes de rejet d'interaction 0373. Réécritures de contraintes : 0340 autorise delete en tant qu'action d'événement de cycle de vie ; 0361 autorise github comme fournisseur IA par défaut. Déclencheurs : 0347, 0348 et 0354–0356 installent des déclencheurs d'invalidation d'exécution sur les agents, les compétences, les connexions, les subventions, les adhésions et les secrets ; 0358 supplante issues.status_version lors d'un changement de responsable ; 0372 expire les points de restauration lorsque les problèmes sont résolus. Mises à jour des lignes : 0343 remplit agents.created_by_user_id à partir du journal d'activité ; 0347 génère un événement agent_runtime par agent actif ; 0359 accorde commentary:view à chaque membre humain actif ; 0363 remplit case_access_sources. Index : 0360 ajoute un index partiel pour la récupération de l'espace de travail conservé ; 0345 et 0369 sont des CONCURRENTLY construits en dehors d'une transaction et peuvent être réexécutés en toute sécurité en cas d'interruption. Attendez-vous à ce que 0343, 0345 et 0369 prennent plus de temps sur les instances avec des historiques d'exécution volumineux, et la contrainte de vérification est réécrite dans 0339, 0362 et 0370 pour analyser company_secrets, budget_reservations et cost_events.
  • Les nouveaux agents utilisent par défaut Paperclip Runner (#15993, #15997, #15683, #17120, #17142) : sur des hôtes qualifiés (Apple Silicon, Intel macOS, Linux x64 avec glibc 2.39+ et Linux ARM64 pour Codex), les nouveaux agents Claude, Codex, OpenCode et Pi sont créés sur le Runner natif quel que soit le paramètre enableNativeRunner. Les agents existants restent inchangés ; choisissez « Legacy runner » sous Avancé pour désactiver un nouvel agent, ou utilisez Upgrade runner sur la configuration d'un agent existant pour le convertir (#17122).
  • Nouvelles variables d'environnement, aucune n'est requise. Nettoyage de l'espace de travail : PAPERCLIP_WORKSPACE_COMPACTION_ENABLED (activé à moins qu'exactement false) et PAPERCLIP_WORKSPACE_COMPACTION_DELAY_HOURS (par défaut 1) contrôlent la suppression des fichiers régénérables des arbres de travail de tâches terminées, et PAPERCLIP_WORKSPACE_REAPER_COOLDOWN_DAYS est désormais par défaut 1 au lieu de 7 (#16304) ; PAPERCLIP_GIT_CACHE_EXPIRATION_ENABLED et PAPERCLIP_GIT_BASE_EXPIRATION_ENABLED (false par défaut) avec PAPERCLIP_GIT_CACHE_EXPIRATION_DRY_RUN (true par défaut) optent pour l'expiration des arbres de travail finis et des clones de base (#16457) ; PAPERCLIP_GIT_RESTORE_POINTS_ENABLED (false par défaut) avec PAPERCLIP_GIT_RESTORE_POINT_TERMINAL_DELAY_DAYS (3 par défaut), PAPERCLIP_GIT_RESTORE_POINT_IDLE_DAYS (7 par défaut, 0 désactivé) et PAPERCLIP_GIT_RESTORE_POINT_RETENTION_DAYS (90 par défaut) régissent les points de restauration chiffrés (#17248, #17271, #17241); PAPERCLIP_SKILL_VERSION_RETENTION_ENABLED (true par défaut) avec _DRY_RUN (false), _KEEP (0) et _GRACE_MINUTES (60) supprime les versions de compétences matérialisées inutilisées (#16433) ; PAPERCLIP_NATIVE_HARNESS_BACKUP_EXPIRATION_ENABLED (true par défaut) avec _DAYS (7) et _DRY_RUN (false) fait expirer les sauvegardes de basculement de session à distance, donc la réouverture d'un problème fermé plus longtemps que cette fenêtre démarre une nouvelle session de fournisseur (#16866). Génération de rapports : PAPERCLIP_SENTRY_RUN_FAILURES (off, unexpected ou all ; off par défaut) (#16300). Les agents Claude honorent également un ANTHROPIC_BASE_URL et un ANTHROPIC_CUSTOM_HEADERS existants (#16850).
  • Nouveaux paramètres expérimentaux, tous désactivés par défaut : Grok Bot (enableGrokBot), qui nécessite des Connexions d'assistant (MCP), le Paperclip Runner, une connexion authentifiée et un HTTPS PAPERCLIP_PUBLIC_URL (#16219) ; Muse — Agent personnel (enableMuse), qui nécessite le Runner et le HTTPS public (#16450) ; Artefacts V1 (enableArtifactsV1) (#17228). La voix Speko apparaît sous le paramètre Connecteurs de chat existant (#15728) et les flux de travail sous Cases (#17114). enablePipelines est supprimé (#16834). Paramètres → Connexions est désormais toujours visible et ne dépend plus des Réponses rapides expérimentales (#16976).
  • commentary:view pour chaque rôle humain (#16903) : la migration 0359 et l'amorçage de démarrage accordent la nouvelle autorisation à chaque membre humain actif, y compris les spectateurs, afin que n'importe qui dans l'entreprise puisse ouvrir Audit → Commentaire. La suppression de cette autorisation d'un membre est temporaire : l'amorçage au démarrage rajoute chaque autorisation de rôle par défaut pour chaque membre humain actif au prochain démarrage du serveur, et cette version n'a aucun moyen durable de la refuser. La confidentialité des tâches source filtre toujours ce que chaque personne voit dans les commentaires.
  • Opérateurs sentinelles (#16300) : configurez PAPERCLIP_SENTRY_RUN_FAILURES=unexpected pour qu'il continue à recevoir des événements d'échec d'exécution ; ils sont désactivés par défaut même avec SENTRY_DSN_BACKEND configuré.
  • API clients : la liste de l'historique d'exécution est limitée à 1 000 lignes (200 par défaut) (#16286) ; le champ linkedCases et tous les itinéraires du pipeline ont disparu (#16834) ; un PATCH qui remplace executionPolicy et définit done pendant un cycle de révision en direct renvoie 422 unexecuted_review_stage (#13178) ; et tout ce qui analyse les titres de résumé des critiques de GitHub doit accepter les noms de robots (#16212).
  • Images Docker personnalisées (#16672) : l'image livrée commence désormais par node server/dist-runtime/index.mjs ; les images qui ont invoqué server/dist/index.js via tsx doivent passer au bundle d'exécution.
  • Les vues par défaut changent : les tâches créées par l'agent et le système sont masquées dans les listes de tâches jusqu'à ce que vous activiez « Afficher les tâches créées par l'agent » (#16157), et la boîte de réception « Mine » n'inclut plus l'automatisation à laquelle vous n'avez pas participé (#16356).
  • Google Workspace (#15545) : les nouvelles demandes Google Workspace dépendent de la mise à jour du courtier OAuth hébergé par Paperclip, et les anciens courtiers les rejettent ; Les connexions Google par service existantes continuent de fonctionner.
  • Les broches de harnais sont inchangées par rapport au v2026.1023.0 : Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286) et OpenCode 1.18.34. Le copilote GitHub est expédié à CLI 1.0.88 (#15701).
  • Aucune autre configuration ou modification du API ne nécessite d'action.
