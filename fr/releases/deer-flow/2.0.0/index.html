DeerFlow 2.0.0

DeerFlow 2.0 est une réécriture de fond autour d'un harnais "super agent" qui orchestre les sous-agents, la mémoire persistante, l'exécution en bac à sable, et un système extensible de compétences/outils. Il ne partage aucun code avec la ligne 1.x, qui réside sur la branche main-1.x.

Cette version clôture le jalon 2.0.0 avec 182 PR fusionnés depuis la première balise jalon 2.0.

📖 Notes complètes : CHANGELOG.md · 中文版

⚠️ Briser le changement

  • Exécuter l'hydratation — les exécutions s'hydratent désormais à partir de RunStore et persistent interrupted statut. L'annulation nécessite désormais le travailleur propriétaire de l'exécution ; travailleur transversal annule le retour 409 au lieu d'apparaître silencieusement comme réussi. ([#2932])

✨ Points forts

- Agents personnalisés qui se mettent à jour eux-mêmes : les agents peuvent conserver les modifications apportées à leur posséder SOUL.md / config.yaml à partir d'un chat normal, avec un accès complet par utilisateur isolement. ([#2713])

  • Connexions de canal de messagerie instantanée appartenant à l'utilisateur — les utilisateurs peuvent lier leur propre Slack, Comptes Telegram, Discord, Feishu/Lark, DingTalk, WeChat et WeCom en tête de robots configurés par l’opérateur. ([#3487])
  • Plus de modèles et recherche communautaire — Modèles de raisonnement StepFun et MiMo, MiniMax pour les compétences image/vidéo/podcast plus une nouvelle compétence de génération musicale, et les outils Brave Search / SearXNG / Browserless / Serper Google Images. ([#3461], [#3298], [#3437], [#3528], [#3451], [#3575])
  • Canaux plus riches — Discord obtient le mode mention uniquement, le routage des threads et indicateurs de saisie ; Telegram diffuse les réponses en modifiant l'espace réservé message en place. ([#2842], [#3534])
  • Détection de boucle configurable avec remplacements de fréquence par outil et injection d'avertissement différée. ([#2586], [#2711], [#2752])
  • Utilisation du jeton de sous-agent diffusé vers l'en-tête en temps réel, avec des intervalles attribué à la trace Langfuse du thread parent. ([#2882], [#3611])
  • Trace polish — nettoie les noms de trace lead_agent/agent personnalisé ; session_id
    • user_id propagé à Langfuse ; les traces mémoire non-ASCII ne s'échappent plus. ([#3101], [#2944], [#3104])
  • Suivi de l'utilisation des jetons activé par défaut, avec des modes d'affichage et d'utilisation affinés attribuée aux modèles réels. ([#2841], [#2329], [#3658])
  • Mémoire et suggestions flexibles — désactivez tiktoken en mode restreint réseaux via memory.token_counting ; rendre les suggestions de suivi de l'IA facultatives. ([#3465], [#3591])

🚀Performances

  • Poussez les filtres de métadonnées de thread dans SQL. ([#2865])
  • L'index est exécuté par thread_id dans RunManager pour éliminer les analyses O(n). ([#3499])
  • Indexer les messages dans MemoryRunEventStore pour éliminer les analyses O(n). ([#3531])
  • Cache la réflexion de la colonne Base.to_dict par classe. ([#3654])
  • Accélérez should_ignore_name dans les parcours sandbox glob/grep. ([#3657])

🔒 Sécurité

  • Rejetez les destinations de téléchargement avec liens symboliques sous Linux et Windows. ([#2623], [#2794])
  • Masquer les valeurs sensibles dans les réponses de configuration MCP ; durcir le point final. ([#2667], [#3425])
  • Rejeter les POST d'authentification intersites. ([#2740])
  • Décompression d'aperçu d'artefact de compétence Cap (défense zip-bomb). ([#2963])
  • Montez le socket hôte Docker uniquement en mode sandbox aio (DooD). ([#3517])
  • Ne pas lier les répertoires d'authentification de l'hôte CLI par défaut. ([#3521])

🐛 Corrections notables

  • Memory s'exécute sur une boucle d'événements persistante au lieu d'une boucle de courte durée asyncio.run() ; mises à jour en file d'attente isolées par agent ; réponses JSON enveloppées analysé correctement. ([#2627], [#2941], [#3252])
  • Exécute hydrate à partir du magasin persistant après un redémarrage de la passerelle, retour Horodatage ISO 8601 et annulation idempotente. ([#2989], [#2599], [#3058])
  • Sous-agents isolés du point de contrôle de l'exécution parent ; terminal d'expiration état atomique; respecter les remplacements de modèle pour les outils/middlewares. ([#3559], [#2583], [#2641])
  • L'interrogation de préparation au Sandbox ne bloque plus la boucle d'événements ; Contrat /mnt/user-data appliqué à la limite API ; Données PVC étendues par utilisateur ; Conversion du chemin Windows/Git Bash MSYS désactivée. ([#2822], [#2881], [#2973], [#2766])
  • Les secrets JWT Auth générés automatiquement persistent lors des redémarrages ; statut de configuration utilise les réponses mises en cache au lieu de 429. ([#2933], [#2915])
  • Frontend corrige un premier message avalé, scintillement de connexion / resize-observer boucle, messages optimistes en double, plantages de rendu de liste profondément imbriquée et isolation des threads sur les nouvelles discussions. ([#2731], [#2954], [#3002], [#3393], [#3570], [#3508])
  • Canaux : la messagerie instantanée appartenant à l'utilisateur nécessite désormais une identité liée, des fichiers de portée et commandes d'assistance au propriétaire, rend l'état du fournisseur faisant autorité et rend Le flux de connexion est déterministe, soutenu par des assistants de nouvelle tentative partagés et garde-corps opérationnels. ([#3578], [#3579], [#3580], [#3581], [#3582], [#3583], [#3584])
  • Streaming et historique — les interruptions se propagent via les événements de valeurs SSE pour les charges utiles des images LangGraph SDK et base64 sont supprimées des flux et historique des réponses pour que l'interface utilisateur reste réactive. ([#3605], [#3631], [#3535])
  • Frontend (plus) — la liste de discussion de l'espace de travail pagine au-delà de 50 threads, reste interactif lorsque la sonde d'authentification SSR ne peut pas atteindre la passerelle et obtient un mise en page adaptée aux mobiles. ([#3485], [#3495], [#3646])

📦 Déploiement et opérations

  • Docker La passerelle est par défaut un seul travailleur (casse multi-travailleurs). ([#3475])
  • Docker nginx résout les noms en amont au moment de la demande. ([#2717])
  • Packaging ajoute un supplément postgres pour la prise en charge du magasin/du point de contrôle. ([#2584])
  • Les scripts préservent les extras de uv lors des redémarrages de make dev ; nettoyer les locaux nginx à l'arrêt ; exclure l'état d'exécution du rechargement de la passerelle. ([#2767], [#3005], [#3426])
