Agents de trading v0.2.5

Résumé

TradingAgents v0.2.5 est livré avec l'analyste de sentiments ancré, la prise en charge double région Qwen/GLM/MiniMax, la configurabilité de la variable d'environnement `TRADINGAGENTS_*` avec détection automatique des touches API, la prise en charge d'Ollama à distance, des tests alpha configurables pour les tickers non américains et un correctif de parcours de ticker.

Analyste des sentiments

Le nouveau Sentiment Analyst lit désormais les données réelles de Yahoo News, StockTwits et Reddit avant de générer son rapport, remplaçant ainsi le flux antérieur qui pouvait fabriquer des publications sociales sous une pression rapide. Le nouveau nom apparaît dans la liste déroulante CLI, le panneau d'état et les rapports finaux ; `AnalystType.SOCIAL = "social"` est conservé pour la rétrocompatibilité de la configuration enregistrée.

Couverture du fournisseur

  • MiniMax avec le catalogue M2.x complet (contexte 204 Ko), plus double région Global (`MINIMAX_API_KEY`) et Chine (`MINIMAX_CN_API_KEY`).
  • Qwen et GLM double région avec des clés séparées par région (`DASHSCOPE_`, `ZHIPU_`), choisies via une invite de région secondaire afin que la liste déroulante du fournisseur principal reste propre.
  • Actualisation du catalogue pour tous les fournisseurs : frontière GPT-5.5, Claude Opus 4.7, Gemini 3.1 Flash-Lite GA, Grok 4.20, ligne Qwen 3.6. ID versionnés uniquement ; Les alias à changement automatique ont été déplacés vers une option "ID de modèle personnalisé".
  • La sortie structurée fonctionne désormais sur DeepSeek V4 / Reasoner et MiniMax M2.x — ces fournisseurs rejettent `tool_choice` ; le flux de liaison l’ignore désormais automatiquement.

Configuration via l'environnement

Les variables d'environnement `TRADINGAGENTS_*` remplacent les clés `DEFAULT_CONFIG` par une coercition sensible au type (string / int / bool) - `llm_provider`, les identifiants de modèle profonds/rapides, `backend_url`, `output_language`, le nombre de tours de débat, l'indicateur de point de contrôle et le ticker de référence. Lorsque la clé API d'un fournisseur sélectionné est manquante, le CLI la demande et conserve la valeur sur `.env` afin que l'exécution continue sans redémarrage.

Ollama

`OLLAMA_BASE_URL` rend `ollama-serve` distant de première classe pour les utilisateurs CLI et programmatiques. Le CLI imprime le point final résolu après avoir sélectionné Ollama et avertit en cas d'entrées mal formées courantes. Une nouvelle option « ID de modèle personnalisé » permet aux utilisateurs de choisir n'importe quel modèle qu'ils ont extrait via `ollama pull`.

Réflexion

L'alpha est désormais calculé par rapport à une référence régionale pour les tickers non américains : `.NS` (^NSEI), `.T` (^N225), `.HK` (^HSI), `.L` (^FTSE), `.TO` (^GSPTSE), `.AX` (^AXJO), `.BO` (^BSESN), SPY pour les cotations américaines. Élimine la dérive des changes qui domine le chiffre alpha pour les cotations non-USD. `benchmark_ticker` remplace la carte de suffixe lorsqu'elle est définie explicitement.

Les paramètres de récupération d'actualités (limite d'article par ticker, limite de titre de macro, fenêtre d'analyse, requêtes de recherche de macro) sont désormais exposés via `DEFAULT_CONFIG` pour un réglage spécifique à la stratégie.

Multilingue

`output_language` se propage désormais à tous les agents orientés utilisateur (chercheurs, débatteurs des risques, directeur de recherche et trader), mettant ainsi fin aux précédents rapports de localisation partielle où seuls les analystes et le gestionnaire de portefeuille respectaient le paramètre.

Correctifs

  • Sécurité : validation du parcours du ticker sur chaque site de chemin du système de fichiers.
  • Les installations `pip install .` récupèrent désormais le projet `.env` lors de l'exécution du CLI en tant que script de console.
  • Les rapports sont enregistrés de bout en bout — les morceaux diffusés en continu étaient auparavant supprimés de `complete_report.md`.
  • L'invite du téléscripteur préserve les suffixes d'échange (`.SH`, `.SZ`, `.SS`, `.HK`, `.T`, etc.).
  • Les erreurs d'autorisation Docker ne bloquent plus l'écriture de première exécution sur `~/.tradingagents/`.
  • L'état de configuration ne fuit plus entre les exécutions lorsque les sous-dicts sont mutés.
  • La configuration `max_recur_limit` s'applique réellement au propagateur.
  • L'erreur Missing-API-key nomme la variable d'environnement exacte à définir.
  • Démarrage plus silencieux — suppression de l'avertissement bruyant de dépréciation du point de contrôle du langgraph en amont.

Voir CHANGELOG.md pour la liste complète par élément avec les références PR/numéro.
