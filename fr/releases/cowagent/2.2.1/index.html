📁 Artefacts

Une nouvelle page Artefacts regroupe les fichiers créés dans vos conversations, à la fois dans la console Web et dans le bureau client :

  • Collection automatique : les documents, pages Web, images et vidéos créés par vos agents s'affichent automatiquement dans Artifacts, sur une chronologie unique pour tous les agents.
  • Prévisualiser et retracer : filtrer par type ou agent, rechercher, prévisualiser sur place et revenir à la conversation qui a produit un fichier (Merci @rudycelekli #3732).
  • Épingler et gérer : épingler, renommer ou supprimer des artefacts ; une fiche dans une conversation vous y amène directement dans Artifacts. La page Artefacts est masquée par défaut et peut être activée dans l'éditeur de menu.

🧭 Améliorations du menu personnalisé et de la console

  • Menu personnalisé : personnalisez les groupes, l'ordre, les noms, les icônes et la visibilité des entrées de menu dans la console Web et le bureau client, avec une configuration partagée ; des artefacts et des liens Web peuvent être ajoutés en tant qu'entrées de menu. Voir [Menu personnalisé] (https://docs.cowagent.ai/extensions/custom-menu).
  • Utilisation des jetons : chaque réponse affiche les jetons réellement utilisés au cours de ce tour, y compris les accès au cache. Merci @Harbor404 (#3440)
  • Diagrammes sirène : les blocs de code sirène peuvent passer à un diagramme rendu, avec zoom et plein écran. Merci @akushonkamen (#3620)
  • Sessions longues plus rapides : les sessions longues avec de nombreux appels d'outils s'ouvrent plus rapidement.
  • Corrections : les nouveaux titres de session ne sont plus perdus et les actions de session sur l'agent par défaut n'échouent plus (Merci @6vision #3625, #3617) ; les paramètres enregistrés ensemble prennent désormais tous effet et les fichiers de l'espace de travail sont enregistrés sous l'agent auquel ils appartiennent (Merci @aniruddhaadak80 #3454, #3488).
  • Barre latérale pliable : la barre latérale de la console Web peut se réduire en un rail d'icônes.

🔌 Ouvrir le chat d'agent API

Les agents sont désormais disponibles via un chat standard API, vous pouvez donc connecter des clients tiers ou appeler un agent directement depuis vos propres systèmes :

  • Switch and key : allumez le API et générez une clé API dans un click sur la page Config ; la clé est conservée lorsque le API est éteint. Il peut également être activé via le fichier de configuration ou les variables d'environnement (Merci @AaronZ345 #3068, @Bdysj #3342).
  • Sélection d'agent et de modèle : choisissez l'agent avec agent_id et le modèle avec model ; sans modèle, le modèle par défaut de l'agent est utilisé.
  • Conversations multi-tours : par défaut, l'appelant envoie l'historique complet des messages ; avec un conversation_id, le serveur conserve l'historique et seul le dernier message doit être envoyé.
  • Sortie complète : réponses en streaming et non-streaming, y compris le raisonnement, l'utilisation du jeton et la trace des appels d'outil (Merci @AaronZ345 #3068, @c020627 #3545, #3588).

📐 Mise en cache rapide et coût du contexte

  • Mise en cache des invites Claude : l'invite système, les définitions d'outils et le préfixe de conversation sont mis en cache, ce qui améliore considérablement les taux d'accès au cache et réduit le coût et la latence des jetons. La durée de vie du cache est configurable via claude_cache_ttl.
  • Marge après le découpage : le découpage du contexte laisse désormais une marge, de sorte que le préfixe reste inchangé pendant les tours suivants et que les longues sessions continuent d'atteindre le cache.
  • Les modifications du budget s'appliquent immédiatement : les modifications apportées au budget contextuel et aux étapes maximales s'appliquent immédiatement à l'exécution des agents, sans effacer la session.
  • Enregistrements d'outils conservés en compactage : les tours compactés conservent un résumé de leurs appels d'outils, afin que le modèle n'invente pas de résultats (Merci @tsumon #3634).
  • Corrections : les messages arrivant pendant le compactage ne sont plus perdus et les résultats des outils orphelins sont nettoyés plus précisément (Merci @c020627 #3518, @rudycelekli #3652, #3653).

🤖 Capacités du modèle

  • Réflexion étendue de Claude : la connexion reste ouverte pendant une longue réflexion, et lorsque la sortie se bloque, la requête est réessayée avec un effort de réflexion inférieur.
  • En-têtes personnalisés : les fournisseurs de modèles personnalisés prennent en charge headers, avec prise en charge d'OpenCode Go.
  • Découverte de modèles : lors de la modification d'une liste de modèles, les modèles disponibles peuvent être récupérés automatiquement auprès du fournisseur. Merci @Harbor404 (#3441)
  • Contenu de raisonnement : les champs reasoning et thinking sont pris en charge, et une balise <think> non fermée ne coupe plus la réponse (Merci @a1094174619 #3601, @fly0sheep-1734 #3538).
  • Modèles de repli : le modèle de repli est réinitialisé au début de chaque tour au lieu de rester utilisé.
  • OpenAI : gestion améliorée des réponses API et des réponses en streaming (Merci @rudycelekli #3659, #3660, #3661, #3663, @aniruddhaadak80 #3486).
  • Liste de modèles : correction des modifications simultanées qui s'écrasent les unes les autres, les modèles principaux personnalisés ne prennent pas effet et la correspondance des balises de capacité (Merci @rudycelekli #3577, #3662, #3666, @aniruddhaadak80 #3501).
  • Autres fournisseurs : problèmes de compatibilité résolus avec MiniMax, ModelScope, Baidu ERNIE et Azure DALL·E (Merci @aniruddhaadak80 #3464, #3476, #3479, #3507, #3512, @rudycelekli #3678).
  • Gestion des erreurs : les demandes rejetées ne sont plus renvoyées, les erreurs sont reconnues avec plus de précision et l'utilisation du contexte affiche le nombre réel de jetons (Merci @c020627 #3442, #3443, #3445, @aniruddhaadak80 #3505, @6vision #3624).
  • Images : la génération d'images conserve le format et l'invite d'origine, et la compréhension des images sur macOS ne met plus à l'échelle les images (Merci @aniruddhaadak80 #3503, #3504, @rudycelekli #3568).

🧠 Mémoire et base de connaissances

  • Édition de connaissances et création de compétences : modifiez les pages de la base de connaissances directement dans la console avec l'index mis à jour automatiquement, écrivez des compétences à partir de zéro et modifiez les fichiers dans le répertoire d'une compétence. Merci @zkjqd (#3377)
  • Classement basé sur les hits : un nouveau memory.hit_boost en option classe légèrement plus haut les souvenirs fréquemment récupérés. Désactivé par défaut. Merci @foreverjix (#3621)
  • Dégradation du temps : s'applique uniquement aux fichiers de mémoire quotidiens, donc les pages datées de la base de connaissances ne sont plus classées (Merci @fly0sheep-1734 #3376).
  • Indexation : contenu corrigé perdu sur de très longues lignes, morceaux dépassant le budget et entrées d'index obsolètes après avoir effacé les notes (Merci @fly0sheep-1734 #3585, @rudycelekli #3426, #3578, #3616).
  • Récupération : amélioration de la recherche en texte intégral, mots-clés Unicode et gestion des paramètres et vecteurs non valides (Merci @aniruddhaadak80 #3480, #3481, #3482, #3483, @rudycelekli #3559, #3656, #3658).
  • Écrits en mémoire : les écritures échouées peuvent être réessayées et les données de session des anciennes versions peuvent être importées (Merci @aniruddhaadak80 #3406, @c020627 #3590, @rudycelekli #3387).
  • Base de connaissances : correction des chemins des graphiques sous Windows et des documents avec des extensions majuscules non affichées, et validation renforcée du chemin d'importation (Merci @Lesereingrape #3332, @rudycelekli #3612, #3649, #3651).

🤝 Collaboration multi-agents

  • Autorisations et délégation : la délégation et le transfert conservent le mode d'autorisation de l'initiateur, et l'agent de réception revérifie la liste d'autorisation de la délégation, la profondeur et le temps d'attente (Merci @c020627 #3541, #3546, #3547, #3548, #3552).
  • Alias ​​d'agent par défaut : toujours résolus avec le véritable ID de l'agent par défaut (Merci @c020627 #3553, #3554).
  • Sessions d'équipe : la suppression d'une session d'équipe la supprime désormais pour chaque participant ; correction de l'affichage des paramètres du modèle et de l'envoi des messages de suivi (Merci @c020627 #3519, #3537, #3549, #3550, #3613).
  • Sous-agents : l'arrêt d'une tâche arrête également ses sous-agents ; correction de l'analyse rapide (Merci @rudycelekli #3637, #3638, #3639).
  • Sessions et projets : correction de la gestion des erreurs pour les paramètres de session et les chemins de projet (Merci @c020627 #3551, @rudycelekli #3640, #3654).

🛡 Renforcement de la sécurité

  • Autorisations : le mode lecture seule bloque désormais les opérations d'écriture git qu'il manquait auparavant (Merci @aniruddhaadak80 #3352, @drakeo338 #3357) ; des opérations dangereuses telles que la substitution de commandes, l'écriture via des arguments et la suppression du répertoire racine sont détectées (Merci @c020627 #3579, #3602, @aniruddhaadak80 #3506) ; en dehors du mode d’accès complet, la configuration MCP et les autorisations de session ne peuvent pas être modifiées.
  • Accès au chemin : vérifications de chemin plus strictes pour les téléchargements, les actifs statiques, la désinstallation des compétences, la restauration des sauvegardes, etc., et les fichiers d'informations d'identification sont bloqués (Merci @aniruddhaadak80 #3409, #3460, #3461, #3463, @c020627 #3446, @rudycelekli #3527, #3528, @Harbor404 #3436).
  • Ressources externes : une limite de taille de téléchargement unifiée, avec les URL des médias et les certificats validés (Merci @c020627 #3327, #3328, #3329, #3336, #3555, #3556, #3557, @rudycelekli #3428, @aniruddhaadak80 #3457, #3477).
  • Rédaction du journal : les jetons d'accès et les secrets ne sont plus écrits dans les journaux en texte brut (Merci @c020627 #3356, #3444, @aniruddhaadak80 #3369, #3399, #3511).
  • Configuration robuste : .env rejette les valeurs contenant des sauts de ligne (Merci @Lesereingrape #3344) ; les fichiers de configuration avec une nomenclature sont pris en charge, avec des vérifications de type plus strictes et des écritures atomiques (Merci @c020627 #3412, #3433, #3447, #3448, @aniruddhaadak80 #3431, #3499, @rudycelekli #3641).

📦 Comment mettre à niveau

  • Déploiement source : exécutez cow update pour une mise à niveau d'un click, mettez à jour à partir du menu de version dans la barre latérale de la console Web, ou extrayez le dernier code et redémarrez. Consultez le [guide de mise à niveau] (https://docs.cowagent.ai/guide/upgrade).
  • Bureau client : recherchez les mises à jour et mettez à jour avec un click dans le client, ​​ou obtenez la dernière version à partir de la [page de téléchargement] (https://cowagent.ai/download/).
