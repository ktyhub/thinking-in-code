daily_stock_analysis v3.6.0

Ajouté

  • 🗑️ Suppression par lots de l'historique — L'interface utilisateur Web prend désormais en charge la sélection multiple et la suppression par lots de l'historique d'analyse ; ajout du point de terminaison POST /api/v1/history/batch-delete et du composant ConfirmDialog.
  • 🔐 Paramètres d'authentification API — nouveau point de terminaison POST /api/v1/auth/settings pour activer ou désactiver l'authentification Web au moment de l'exécution et définir le mot de passe administrateur initial si nécessaire
  • openclaw Skill 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ Protocole de canal LLM/test UX — .env et les paramètres Web partagent désormais la même forme de canal (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED) ; La page des paramètres ajoute des tests de connexion par canal, une sélection de modèle principal/de secours/de vision et un préfixe de modèle prenant en compte le protocole.
  • 🤖 Architecture de l'agent Phase 0+1 — protocoles partagés (AgentContext, AgentOpinion, StageResult), exécuteur run_agent_loop() extrait, commutateur AGENT_ARCH (single/multi), entrées de registre de configuration
  • 🔍 Routage Bot NL — routage en langage naturel à deux couches : pré-filtre d'expression régulière bon marché (codes boursiers + mots-clés financiers) → analyse d'intention LLM légère ; contrôlé par AGENT_NL_ROUTING=true ; prend en charge l'extraction multi-stocks et stratégiques
  • 💬 Analyse multi-actions /ask — codes séparés par des virgules ou vs (max 5), exécution de threads parallèles avec un délai d'attente de 150 secondes (préserve les résultats partiels), tableau récapitulatif de comparaison Markdown en haut
  • 📋 Commande /history — isolation de session par utilisateur via le format {platform}_{user_id}:{scope} (le délimiteur deux-points empêche la collision de préfixes) ; répertorie les sessions /chat et /ask ; afficher les détails ou effacer
  • 📊 Commande /strategies — répertorie les fichiers de stratégie YAML disponibles regroupés par catégorie (趋势/形态/反转/框架) avec le statut d'activation ✅/⬜
  • 🔧 Outils de résumé de backtest — get_strategy_backtest_summary et get_stock_backtest_summary enregistrés en tant qu'outils d'agent en lecture seule
  • ⚙️ Détection automatique de l'agent — is_agent_available() se détecte automatiquement à partir de LITELLM_MODEL ; explicite AGENT_MODE=true/false a la pleine priorité
  • 🏗️ Orchestrateur multi-agents (Phase 2) — AgentOrchestrator avec 4 modes (quick/standard/full/strategy) ; remplacement immédiat du AgentExecutor via AGENT_ARCH=multi ; BaseAgent ABC avec filtrage de sous-ensembles d'outils, injection de données en cache et sortie AgentOpinion structurée
  • 🧩 Agents spécialisés (Phase 2-4) — TechnicalAgent (8 outils, analyse de tendance/MA/MACD/volume/modèle), IntelAgent (actualités et sentiments, propagation des indicateurs de risque), DecisionAgent (synthèse dans le tableau de bord de décision JSON), RiskAgent (7 catégories de risque, gravité à deux niveaux avec remplacement doux/dur)
  • 📈 Système de stratégie (Phase 3) — StrategyAgent (évaluation par stratégie à partir des compétences YAML), StrategyRouter (détection de régime basée sur des règles → sélection de stratégie), StrategyAggregator (consensus pondéré avec facteur de performance backtest)
  • 🔬 Agent de recherche approfondie (Phase 5) — ResearchAgent avec approche en 3 phases (décomposer → sous-questions de recherche → rapport de synthèse) ; suivi du budget symbolique ; nouvelle commande de bot /research avec alias (/深研, /deepsearch)
  • 🧠 Mémoire et calibrage (Phase 6) — AgentMemory avec suivi de la précision des prédictions, calibrage de confiance (s'active après le seuil d'échantillon minimum), pondération automatique de la stratégie basée sur le taux de victoire historique
  • 📊 Portfolio Agent (Phase 7) — PortfolioAgent pour l'analyse de portefeuille multi-actions (dimensionnement des positions, concentration sectorielle, risque de corrélation, liens entre marchés, suggestions de rééquilibrage)
  • 🔔 Alertes basées sur des événements (Phase 7) — EventMonitor avec règles PriceAlert, VolumeAlert, SentimentAlert ; vérification asynchrone, notifications de rappel, persistance sérialisable
  • ⚙️ Nouvelles entrées de configuration — AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING — toutes enregistrées dans config.py + config_registry.py (configurable par WebUI)

Modifié

  • 🔐 Sémantique de l'état du mot de passe d'authentification — l'existence du mot de passe stocké est désormais suivie indépendamment de l'activation de l'authentification ; lorsque l'authentification est désactivée, /api/v1/auth/status renvoie passwordSet=false tout en préservant le mot de passe enregistré pour une réactivation future
  • 🔐 Les paramètres d'authentification réactivent le renforcement — la réactivation de l'authentification avec un mot de passe stocké nécessite désormais currentPassword, et l'échec de la création de session annule la bascule d'authentification pour éviter le verrouillage
  • ♻️ AgentExecutor refactorisé — _run_loop délègue au runner.run_agent_loop() partagé ; suppression du code de sérialisation/analyse/étiquette de réflexion en double
  • ♻️ Commutateur d'agent unifié — Bot, API et Pipeline utilisent tous config.is_agent_available() au lieu de contrôles divergents config.agent_mode
  • 📖 README.md — section de commandes de robot étendue (ask/chat/strategies/history), ajout d'une note de routage NL, description du mode agent mise à jour
  • 📖 .env.example — ajout de la documentation de configuration AGENT_ARCH et AGENT_NL_ROUTING

Corrigé

  • 🐛 Rotation secrète des sessions sous Windows — utilisez le remplacement atomique pour que les bascules d'authentification invalident les sessions existantes même lorsque .session_secret existe déjà
  • 🐛 Auth toggle atomicity — persiste ADMIN_AUTH_ENABLED avant de faire tourner le secret de session ; en cas d'échec de la rotation, revenir à l'état d'authentification précédent
  • 🔧 Garde-corps de sélection du runtime LLM — L'éditeur de canal en mode YAML ne couvre plus LITELLM_MODEL / fallback / Vision ; la vérification de la configuration du système ajoute la vérification de la source d'exécution une fois que tous les canaux sont désactivés et résout le problème des modèles d'alias de protocole tels que vertexai/... étant préfixés à plusieurs reprises
  • 🐛 Régressions de suivi multi-actions /ask — la superposition de portefeuille partage désormais le même budget de délai d'attente que la phase par action et est ignorée en cas d'expiration au lieu de bloquer la réponse du bot ; /history stocke désormais le résumé lisible par stock au lieu du tableau de bord brut JSON ; la sortie multi-stocks condensée restitue désormais les valeurs numériques sniper_points
  • 🐛 Compatibilité des énumérations du tableau de bord de décision — le multi-agent DecisionAgent conserve désormais decision_type dans l'ancien contrat buy|hold|sell et normalise les sorties parasites de strong_* avant le remplacement des risques, la conversion du pipeline et en aval.
  • 🛟 Repli de résultats partiels multi-agents — IntelAgent met désormais en cache les informations analysées pour une réutilisation en aval, l'analyse partagée JSON tolère une sortie de modèle légèrement malformée et l'orchestrateur préserve/synthétise un tableau de bord minimal en cas d'expiration du délai d'attente ou d'échec d'analyse en cours de pipeline au lieu de toujours se réduire à 50/观望/未知.
  • 🐛 Routage LiteLLM partagé restauré — L'analyse des intentions NL du bot et la planification/synthèse ResearchAgent réutilisent désormais le même adaptateur LiteLLM/routeur/repli/chemin d'injection api_base comme flux d'agent principal, de sorte que les déploiements compatibles LLM_CHANNELS/LITELLM_CONFIG/OpenAI se comportent de manière cohérente
  • 🐛 Compatibilité ascendante des sessions de chat Bot — /chat continue désormais d'utiliser l'ancien identifiant de session {platform}_{user_id} lorsque l'ancien historique existe déjà, et /history peut toujours lister/afficher/effacer ces sessions de pré-migration aux côtés du nouveau format {platform}_{user_id}:chat.
  • 🐛 Rejet des règles non prises en charge par EventMonitor — la validation de la configuration/le chargement de l'exécution rejettent ou ignorent désormais les types d'alerte que le moniteur ne peut pas encore réellement évaluer, donc le mode planification n'accepte plus silencieusement les règles permanentes de non-opération
  • 🐛 P0 Fundamental Aggregation Stability Fix (#614) — Correction de la régression sémantique du secteur get_stock_info (ajoutez belong_boards et conservez les alias compatibles boards), introduisez des retours rationalisés de contexte fondamental pour contrôler les jetons, ajoutez une élimination maximale des entrées au cache fondamental et complétez l'agrégation de l'état global de l'ETF et le filtrage des champs de secteur NaN pour garantir une ouverture en cas d'échec et une intrusion minimale.
  • 🔧 Ajout de la variable d'environnement du moteur de recherche GitHub Actions — Workflow ajoute le mappage des variables d'environnement MINIMAX_API_KEYS, BRAVE_API_KEYS, SEARXNG_BASE_URLS, permettant aux utilisateurs de GitHub Actions de configurer les services de recherche MiniMax, Brave et SearXNG (auparavant, v3.5.0 avait ajouté l'implémentation du fournisseur mais manquait de configuration du flux de travail)
  • 🤖 Cohérence d'exécution multi-agent — AGENT_MAX_STEPS se propage désormais à chaque sous-agent orchestré ; ajout du budget coopératif AGENT_ORCHESTRATOR_TIMEOUT_S pour arrêter les pipelines trop longs avant qu'ils ne se répercutent davantage
  • 🔌 Câblage des fonctionnalités multi-agents — AGENT_RISK_OVERRIDE rétrograde désormais activement les tableaux de bord finaux en fonction des résultats de risques concrets ; AGENT_MEMORY_ENABLED injecte désormais une mémoire d'analyse récente + un étalonnage de confiance dans des agents spécialisés ; le /ask multi-actions exécute désormais PortfolioAgent pour ajouter une allocation au niveau du portefeuille et des conseils de concentration
  • 🔔 Câblage d'exécution d'EventMonitor — le mode planification peut désormais charger des règles d'alerte à partir de AGENT_EVENT_ALERT_RULES_JSON, les interroger sur AGENT_EVENT_MONITOR_INTERVAL_MINUTES et envoyer des alertes déclenchées via le service de notification existant.
  • 🛠️ Corrections de stabilité de suivi — le /ask multi-stocks revient désormais à une sortie de texte utilisable lorsque l'analyse du tableau de bord JSON échoue ; EventMonitor ignore les règles sémantiquement invalides au lieu d'interrompre le démarrage planifié ; L'interrogation des alertes en arrière-plan s'exécute désormais indépendamment de la boucle d'analyse principale planifiée.
  • 🧪 Couverture de régression multi-agent — ajout de tests d'exécution de l'orchestrateur pour run(), chat(), échec de phase critique, dégradation progressive et gestion des délais d'attente
  • 🧹 Nettoyage de PortfolioAgent — post_process() réutilise désormais l'analyse partagée de JSON et supprime les importations obsolètes et inutilisées.
  • 🚦 Envoi asynchrone de bot — CommandDispatcher expose désormais dispatch_async() ; L'analyse des intentions NL et l'exécution des commandes par défaut sont déchargées de la boucle d'événements, le flux DingTalk attend directement les gestionnaires asynchrones et le traitement du flux Feishu est déplacé du fil de rappel SDK.
  • 🌐 Gestionnaire de webhook asynchrone — nouvelle fonction handle_webhook_async() dans bot/handler.py pour une utilisation à partir de contextes asynchrones (par exemple FastAPI) ; appelle dispatch_async() directement sans pontage de threads
  • 🧵 Flux Feishu ThreadPoolExecutor — remplacement de la génération illimitée de Thread par message par un ThreadPoolExecutor(max_workers=8) plafonné pour empêcher l'explosion de threads sous les rafales de messages
  • 🔒 Sécurité EventMonitor — _check_volume() gère désormais en toute sécurité get_daily_data renvoyant None (pas de crash de déballage de tuple) ; Les rappels on_trigger prennent en charge les rappels synchrones et asynchrones via asyncio.to_thread/await
  • 🧹 Déduplication ResearchAgent — _filtered_registry() délègue désormais à BaseAgent._filtered_registry() au lieu de dupliquer la logique de filtrage
  • 🧹 Nettoyage des espaces de fin de robot — suppression des problèmes d'espaces W291/W293 dans bot/handler.py, bot/dispatcher.py, bot/commands/base.py, bot/platforms/feishu_stream.py, bot/platforms/dingtalk_stream.py
  • 🐛 Sécurité du répartiteur _parse_intent_via_llm — remplacement du fragile 'raw' in dir() par 'raw' in locals() pour une protection à variable indéfinie dans le gestionnaire JSONDecodeError
  • 🐛 Complétez la structure de la puce LLM lorsqu'elle n'est pas remplie (#589) — Lorsque DeepSeek et d'autres modèles ne remplissent pas correctement chip_structure, il le complétera automatiquement avec les données de la puce obtenues à partir de la source de données pour garantir que l'affichage de chaque modèle est cohérent ; l'analyse normale et le mode Agent sont valides
  • 🐛 Historique du rapport de tireur d'élite affichant le texte original (#452) — La page de détails historiques donne désormais la priorité à l'affichage de la chaîne d'origine dans raw_result.dashboard.battle_plan.sniper_points pour empêcher la colonne numérique analysis_history de compresser les intervalles, le texte explicatif ou les points complexes en un seul nombre ; conserver la colonne numérique d'origine comme solution de repli
  • 🐛 Collision de préfixe de session — l'ID utilisateur 123 pouvait voir les sessions de l'utilisateur 1234 via startswith ; corrigé avec le délimiteur deux-points au format session_id
  • 🐛 Faux positifs du pré-filtre NL — re.IGNORECASE a fait correspondre [A-Z]{2,5} à des mots anglais courants comme « bonjour » ; indicateur global supprimé, utilisez (?i:...) en ligne uniquement pour les mots-clés financiers en anglais
  • 🐛 Ticker en pointillés dans les arguments de stratégie — _get_strategy_args() n'a pas reconnu BRK.B comme code boursier, le laissant dans le texte de stratégie ; accepte désormais le format TICKER.CLASS
  • ⏱️ Correction de blocage d'appels longs efinance (#660) — Introduire le wrapper _ef_call_with_timeout() pour tous les appels efinance API (30 secondes par défaut, configurable via EFINANCE_CALL_TIMEOUT) ; utilisez executor.shutdown(wait=False) pour vous assurer que le thread principal n'est plus bloqué après un délai d'attente, éliminant ainsi complètement le problème de blocage de 81 minutes
  • 🛡️ Vérification de l'intégrité du contenu de type sécurisé (#660) — check_content_integrity() traite désormais les types non-chaînes operation_advice / analysis_summary comme des champs manquants pour éviter les plantages en aval du get_emoji() dus à dict.strip()
  • 📄 Découplage de l'enregistrement et de la notification des rapports (#660) — _save_local_report() ne repose plus sur le déclencheur d'indicateur send_notification et les rapports locaux sont enregistrés comme d'habitude en mode --no-notify
  • 🔄 normalisation du dictionnaire operation_advice (#660) — Pipeline et BacktestEngine mappent désormais le format dict operation_advice renvoyé par LLM à une chaîne standard via decision_type (insensible à la casse) pour éviter les plantages causés par des modifications du format de sortie du modèle
  • 🛡️ utilisation de runner.py Aucune protection (#660) — AttributeError n'est plus lancé lorsque response.usage est None, retour à 0 nombre de jetons
  • 📋 l'échec silencieux de l'orchestrateur a été remplacé par un avertissement de journal (#660) — L'échec de l'étape IntelAgent / RiskAgent enregistre désormais WARNING au lieu de sauter silencieusement, pour un diagnostic plus facile

Remarques

  • ⚠️ Bascules d'authentification multi-travailleurs — les mises à jour d'authentification d'exécution sont locales au processus ; les déploiements multi-travailleurs doivent redémarrer/rouler les travailleurs pour maintenir la cohérence de l'état d'authentification
