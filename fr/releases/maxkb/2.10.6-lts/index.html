MaxKo v2.10.6-lts

Correctifs de vulnérabilités de sécurité

  • Sécurité : Correction d'une vulnérabilité de sécurité où les téléchargements de fichiers Chat pouvaient usurper l'attribution de l'APPLICATION et être lus de manière anonyme, permettant l'injection de contenu dans l'espace de noms de l'application.
  • Sécurité : correction d'une vulnérabilité de sécurité où la migration de documents/paragraphes ne validait que les autorisations de la base de connaissances source, conduisant à une injection de contenu entre locataires et à un empoisonnement RAG.
  • Sécurité : Correction d'une vulnérabilité de sécurité où la décompression d'image intégrée XLSX n'avait pas de limite de nombre de pixels, permettant aux utilisateurs authentifiés de déclencher un déni de service (DoS) par épuisement de la mémoire.
  • Sécurité : correction d'une vulnérabilité de sécurité où problème/batch_association manquait de validation de propriété, conduisant à une divulgation du contenu des paragraphes entre locataires (IDOR).
  • Sécurité : correction d'une vulnérabilité de sécurité dans laquelle le point de terminaison du profil d'application anonyme sur-sérialisait les données, provoquant une divulgation de configuration sensible (/chat/api/application/profile).
  • Sécurité : Correction d'une vulnérabilité de sécurité où le point de terminaison du code de vérification de réinitialisation du mot de passe n'avait pas de limite de tentative de devinette, permettant une prise de contrôle de compte non autorisée.
  • Sécurité : Correction d'une vulnérabilité de sécurité où le bac à sable de la bibliothèque de fonctions pouvait être contourné (vérification de pile dlopen contournable + dlsym(RTLD_NEXT) non intercepté) (CVE-2026-79919).
  • Sécurité : Correction d'une vulnérabilité de sécurité où la prise en charge par Python du formulaire de descripteur de fichier os.execve(fd,...) pouvait être exploitée pour entrer dans le chemin d'appel de la libc fexecve, provoquant un contournement du bac à sable (NVDB-CAIVD-2026208648).
  • Sécurité : correction d'une vulnérabilité de sécurité où la validation de la propriété de la session invité était manquante, entraînant des écritures entre sessions invité (violation de l'intégrité de la session).
  • Sécurité : correction d'une vulnérabilité de sécurité dans laquelle le Django SECRET_KEY codé en dur par défaut permettait de falsifier des jetons signés hors ligne, entraînant un accès non autorisé aux fichiers.

Nouvelles fonctionnalités

  • Paramètres du modèle par défaut du flux de travail Dans l'édition communautaire MaxKB v2.10.6 LTS, les paramètres de modèle de flux de travail par défaut ont été introduits pour les flux de travail d'agent, les flux de travail de base de connaissances et les outils de flux de travail. Auparavant, les workflows multi-nœuds IA nécessitaient d'ouvrir chaque nœud individuellement pour modifier les configurations du modèle, ce qui était relativement fastidieux. Désormais, une configuration unique prend effet à l'échelle mondiale, réduisant considérablement les coûts de maintenance et améliorant la cohérence et l'efficacité du changement de modèle par lots. Les principales fonctionnalités des paramètres de modèle par défaut incluent :
  • Une entrée de configuration de modèle par défaut au niveau du flux de travail ;
  • Les nœuds nouvellement créés héritent automatiquement du modèle par défaut ;
  • Les nœuds prennent en charge des modes de sélection de modèle flexibles (par défaut/personnalisé/variable de référence, en fonction du type de nœud) ;
  • Le modèle par défaut peut être appliqué à tous les nœuds avec un click, basculant uniformément les sources de modèle de tous les nœuds vers le modèle par défaut ;
  • Une seule modification du modèle par défaut prend effet sur plusieurs nœuds ;
  • L'exhaustivité de la configuration est assurée avant la publication.
  • Les fournisseurs Tencent Hunyuan et Tencent Cloud ont fusionné pour former le nouveau fournisseur « Tencent Cloud » (intégré à Tencent Cloud TokenHub) En raison des ajustements effectués par Tencent Cloud, dans l'édition communautaire MaxKB v2.10.6 LTS, les fournisseurs Tencent Hunyuan et Tencent Cloud ont été fusionnés en un nouveau fournisseur « Tencent Cloud ». Tous les modèles précédemment configurés sur la base de l'intégration de Tencent Hunyuan ou de l'ancien fournisseur Tencent Cloud ne seront plus utilisables après la mise à niveau. Après la mise à niveau, veuillez accéder à la page « Fournisseurs de modèles », sélectionnez « Tencent Cloud » dans la liste des fournisseurs et reconfigurez les informations d'accès à votre modèle en fonction des exigences d'intégration de TokenHub. Une fois configurés, les modèles seront à nouveau disponibles. Optimisations des fonctionnalités
  • Base de connaissances : le sélecteur base de connaissances/liste de documents prend désormais en charge la recherche lors de la migration de documents/paragraphes.
  • Agent : Le composant de base de connaissances dans la zone de saisie utilisateur prend désormais en charge la recherche.
  • Agent : Dans la fonctionnalité "Ajouter à la base de connaissances" sur la page du journal des conversations, les sélecteurs de base de connaissances et de liste de documents prennent désormais en charge la recherche.

Corrections de bugs

  • Base de connaissances : correction d'un problème où l'importation d'un fichier CSV avec un contenu de cellule surdimensionné entraînait des lectures vides et une erreur "champ plus grand que la limite du champ (131072)" dans le backend (#6756).
  • Base de connaissances : correction d'un problème où l'importation de feuilles de calcul Excel sans reconnaître les limites des données entraînait l'importation d'un grand nombre de colonnes vides, entraînant des délais d'attente d'importation (#6355).
  • Base de connaissances : correction d'un problème où la saisie de 33 caractères "-" consécutifs dans une recherche en texte intégral lors d'un test de détection provoquait une erreur de recherche.
  • Agent : Correction d'un problème où les conversations étaient erronées lorsque le contenu de sortie contenait des caractères nuls (\u0000, \x00, etc.) (#6722).
  • Agent : Correction d'un problème où les nœuds IA dans les agents avancés ne pouvaient pas recevoir les données transmises par les nœuds précédents lors de l'utilisation du grand modèle Ascend MindIE (#6681).
  • Agent : Correction d'un problème où l'appel du modèle était erroné lorsque le "Paramètre de rôle" d'un nœud AI d'orchestration avancée était vide (#6662).
  • Agent : Correction d'un problème où, après avoir invoqué un outil, la source d'exécution affichée dans les enregistrements d'exécution de l'outil affichait le nom de l'outil au lieu du nom de l'agent (#6647).
  • Agent : Correction d'un problème où les fichiers téléchargés dans les bases de connaissances du flux de travail étaient des fichiers temporaires, provoquant des échecs de prévisualisation et de téléchargement après le nettoyage des fichiers (#6785).
  • Agent : Correction d'un problème où un agent utilisé comme compétence d'un nœud de conversation IA ne pouvait pas transmettre des paramètres autres que le message.
  • Agent : Correction d'un problème dans les agents avancés où la base de connaissances par défaut ne pouvait pas être définie après avoir modifié le type de composant des paramètres d'entrée utilisateur en base de connaissances.
  • Agent : Correction d'un problème où une erreur se produisait lors de la suppression des journaux de discussion (#6690).
  • Modèle : Correction d'un problème où le modèle texte-vidéo MiniMax H3 signalait des erreurs lors de l'utilisation après une intégration réussie.
