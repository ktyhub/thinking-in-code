Nouvelles méthodes

SHIRA

@kkb-code a contribué à Sparse High Rank Adapters (SHiRA, paper) qui promettent d'offrir un gain potentiel de performances par rapport aux LoRA - en particulier la perte de concept lors de l'utilisation de plusieurs adaptateurs est améliorée. Étant donné que les adaptateurs ne s'entraînent que sur 1 à 2 % des poids et sont intrinsèquement clairsemés, le passage d'un adaptateur à l'autre peut être moins cher qu'avec les LoRA. (#2584)

Mademoiselle

@JL-er a ajouté une nouvelle méthode PEFT, MiSS (Matrix Shard Shard) dans #2604. Cette méthode est une évolution de Bone, qui, selon notre benchmark de comparaison de méthodes PEFT, donne d'excellents résultats en termes de performances et d'efficacité de la mémoire. Si vous ne l'avez pas essayé, vous devriez le faire maintenant.

Dans le même temps, Bone sera obsolète au profit de MiSS et sera supprimé dans PEFT v0.19.0. Si vous disposez déjà d'un point de contrôle Bone, vous pouvez utiliser scripts/convert-bone-to-miss.py pour le convertir en point de contrôle MiSS et poursuivre l'entraînement à l'aide de MiSS.

Améliorations

LoRA pour nn.Parameter

LoRA est désormais capable de cibler directement nn.Parameter (#2638, #2665) ! Avez-vous déjà eu ce nn.Module compliqué avec des paramètres prometteurs à l'intérieur, mais il était trop personnalisé pour être pris en charge par votre bibliothèque de réglage fin préférée ? Pas de soucis, vous pouvez désormais cibler nn.Parameters directement en utilisant l'attribut de configuration target_parameters qui fonctionne de manière similaire à target_modules.

Cette option peut être particulièrement utile pour les modèles avec des couches Mélange d'Expert (MoE), car celles-ci utilisent souvent directement les nn.Parameter et ne peuvent pas être ciblées avec target_modules. Par exemple, pour la [famille de modèles Llama4] (https://huggingface.co/collections/meta-llama/llama-4-67f0c30d9fe03840bc9d0164), utilisez la configuration suivante pour cibler les pondérations MoE :

config = LoraConfig(
    ...,
    target_modules=[],  # <= prevent targeting any modules
    target_parameters=["feed_forward.experts.down_proj", "feed_forward.experts.gate_up_proj"],
)

Notez que cette fonctionnalité est encore expérimentale car elle comporte quelques mises en garde et pourrait donc changer à l'avenir. De plus, les pondérations MoE selon de nombreux experts peuvent être assez énormes, alors attendez-vous à une utilisation de la mémoire plus élevée que par rapport au ciblage des couches nn.Linear normales.

Adaptateurs d'injection basés sur un state_dict

Parfois, il est possible qu'il existe un point de contrôle d'adaptateur PEFT mais que la configuration PEFT correspondante ne soit pas connue pour une raison quelconque. Pour injecter les couches PEFT pour ce point de contrôle, vous devrez généralement effectuer une rétro-ingénierie de la configuration PEFT correspondante, notamment l'argument target_modules, basé sur le state_dict du point de contrôle. Cela peut être fastidieux et sujet aux erreurs. Pour éviter cela, il est également possible d'appeler inject_adapter_in_model et de passer le state_dict chargé en argument :

from safetensors.torch import load_file
from peft import LoraConfig, inject_adapter_in_model

model = ...
state_dict = load_file(<path-to-safetensors-file>)
lora_config = LoraConfig()  # <= no need to specify further
model = inject_adapter_in_model(lora_config, model, state_dict=state_dict)

En savoir plus sur [l'injection basée sur state_dict dans la documentation] (https://huggingface.co/docs/peft/main/en/developer_guides/low_level_api#injection-based-on-a-statedict).

Modifications

Compatibilité

Un bug dans les méthodes d’apprentissage rapide entraînait l’ignorance de modules_to_save. Les tâches de classification sont particulièrement affectées puisqu'elles ajoutent généralement la couche de classification/score à modules_to_save. En conséquence, ces couches n’ont été ni entraînées ni stockées après formation. Cela a été corrigé maintenant. (#2646)
