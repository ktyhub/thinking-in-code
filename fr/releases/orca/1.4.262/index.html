orque v1.4.262

Version précédente : 1.4.261 : améliorations majeures des performances, Cursor Chat et un menu + personnalisable.

Changement de chat plus rapide, utilisation réduite de la mémoire et blâme git ✨

Gardez plus de conversations ouvertes avec moins de mémoire sur macOS et Linux, et passez d'une discussion à l'autre avec moins de travail dans les vues masquées. Cette mise à jour permet également aux sessions de terminal de reprendre là où vous vous étiez arrêtées et de placer l'historique des lignes directement dans l'éditeur.

  • ⚡ Travailler sur de nombreux chats : L'interface utilisateur de chat utilise des aides plus légères sur macOS et Linux. Les vues de discussion cachées suspendent leurs mises à jour tout en conservant votre brouillon, votre position de lecture et votre état d'éditeur pour votre retour ; les agents continuent de travailler.
  • 🧹 Récupérer de l'espace disque : Paramètres → Workspace Cleanup peut supprimer les discussions Orca, Claude Code et Codex des espaces de travail supprimés. Il est désactivé par défaut ; son activation demande une confirmation et inclut les espaces de travail précédemment supprimés. Les discussions supprimées ne peuvent pas être récupérées.
  • ⌨️ Retour au même dossier de terminal : Les volets mémorisent l'endroit où vous avez modifié le répertoire pour la dernière fois lors des redémarrages, y compris dans les espaces de travail des dossiers. Windows corrige également les caractères parasites après le retour à un volet occupé.
  • 🔍 Voir qui a modifié une ligne : L'élément d'état de blâme Git affiche l'auteur et la date de la ligne du curseur. Dans les espaces de travail de dépôt, clicochez-le pour ouvrir le commit ; activez Inline git blâme dans Paramètres → Éditeur pour les annotations à côté de votre code.
  • 👤 Rendez le changement de compte plus clair : Nommez les comptes Claude et Codex enregistrés et consultez leurs derniers plans observés. Lorsque vous acceptez Redémarrer ou utilisez Toujours redémarrer, les sessions occupées du terminal Claude reprennent sur le compte sélectionné sans attendre la fin de leur travail en cours.

Faits saillants

  • Configurez un agent sur une seule carte : Choisissez ensemble l'agent, le modèle et l'effort pris en charge ou les options rapides, puis utilisez Ouvrir en tant que chat ou Ouvrir en tant que terminal. Lorsqu'il est proposé, l'effort Par défaut permet à l'agent de choisir son propre niveau.
  • Contrôler les interruptions : Cochez à droite cli un espace de travail pour désactiver ses notifications tout en conservant son point non lu. Les espaces de travail en veille restent endormis après la relance et l'aperçu de la carte d'espace de travail vous permet d'essayer différents styles.
  • Utilisez votre langue et vos plugins : Découvrez les traductions de la communauté dans les paramètres ou dans l'intégration. Les revues de mise à jour du plugin nomment l'accès ajouté et peuvent regrouper les approbations ; les mises à jour éligibles peuvent être approuvées à partir de leur notification.
  • Enregistrez les fichiers distants pour plus tard : Choisissez Télécharger… sur un lien de fichier distant pour l'enregistrer sans ouvrir une autre application. Windows reconnaît également les dossiers de projet sur les lettres de lecteur mappées aux distributions WSL.
  • Résoudre une action Codex bloquée : Le chat explique un refus de révision automatique et propose Approuver une fois pour cette action.

Notes de compatibilité et de mise à niveau

  • Partage de l'historique du Codex : Lorsque le partage est activé, les comptes sont déplacés vers une boutique de conversations avant leur prochain lancement ; cela peut retarder le premier lancement et les comptes occupés migreront plus tard. La désactivation du partage laisse l’historique partagé en place ; de longues conversations commencées alors que le partage était nécessaire, cela permettait de reprendre. Après une mise à niveau de Windows, les comptes supplémentaires reviennent à votre connexion Codex par défaut jusqu'à ce que vous effectuiez une nouvelle mise à jour.
  • Terminaux Windows : Fermez et rouvrez les terminaux existants pour récupérer le correctif de caractères parasites.
  • Étapes de configuration du dépôt : Les approbations antérieures de orca.yaml comptent désormais comme trust pour les futures versions des commandes de configuration de ce dépôt. La création de VM et les dépôts partageant un identifiant entre les hôtes conservent l'approbation par version.
