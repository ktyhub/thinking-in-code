orque v1.4.248

Des terminaux plus fiables, des discussions fiables et des choix d'IA plus faciles ✨

  • 🖥️ Terminaux plus fiables : Gardez les flux distants actifs connectés, préservez l'identité de l'agent lors des redémarrages du démon, améliorez la saisie mobile ordonnée et les messages longs vers le Codex Windows et restituez correctement les symboles de police Nerd après le chargement des polices.
  • 💬 Conversations plus fiables : Continuez à diffuser les réponses après leurs invites, maintenez les suivis en file d'attente lorsqu'un tour échoue et conservez le texte collé et les brouillons de terminal séparés des envois de chat.
  • 🎛️ Choisissez la façon dont l'IA écrit pour vous : Choisissez le modèle et l'effort pour les messages de validation, les descriptions de demandes d'extraction, les noms de branches et les noms de discussion dans les paramètres de contrôle de code source.
  • ⚡ Moins de travail de chat inutile : Les mises à jour d'aperçu évitent de copier la conversation entièrement chargée, et cette version supprime le nettoyage de l'historique en direct qui pourrait bloquer les discussions volumineuses.
  • 📱 Meilleure continuité téléphonique : Rouvrez les discussions à partir des messages mis en cache, maintenez les options à jour et envoyez des messages longs au Codex Windows de manière plus fiable.
  • ⏳ Choisissez quand les mises à jour arrivent : Ajoutez un délai de mise à jour facultatif dans les paramètres, avec une option unique pour ignorer l'attente.
  • 📝 Améliorations de l'éditeur et de l'espace de travail : Choisissez le format lors de l'enregistrement, recherchez les sélecteurs de thèmes et utilisez les actions click familières à droite sur les onglets de discussion.

Faits saillants

  • Terminaux : Les flux distants restent connectés pendant que la sortie circule, l'identité de l'agent survit aux redémarrages du démon, les entrées mobiles sont acheminées dans l'ordre et les longs messages téléphoniques atteignent le Codex Windows. Les symboles Nerd Font sont repeints une fois les polices chargées et les utilisateurs de terminaux fermés peuvent rouvrir à partir de leurs cartes d'orchestration.
  • Continuité du chat : Les réponses en streaming restent après l'invite à laquelle elles répondent. Les suivis restent en file d'attente après un échec, les pièces jointes expirées sont identifiées lorsqu'un envoi est refusé et le texte collé peut être ouvert à partir de discussions structurées.
  • Démarrage et choix de l'agent : Un refus final de démarrage s'affiche après la première tentative au lieu de tentatives répétées ; les échecs temporaires se rétablissent toujours. Les discussions conservent l'effort configuré lorsque vous n'avez pas choisi de remplacement, et les actions de texte du contrôle de code source utilisent les menus Modèle et Effort.
  • Téléphone : Les discussions en cache rouvrent avant de récupérer les modifications. Les options de discussion, les paramètres du terminal, les détails des branches et des demandes d'extraction sont actualisés de manière plus fiable ; les longs messages téléphoniques parviennent au Codex Windows et les onglets du navigateur hébergés par un serveur de bureau peuvent être diffusés sur le téléphone.
  • Mises à jour et Windows : Choisissez un délai de mise à jour, conservez l'emplacement d'une installation Windows déplacée pendant les mises à jour et obtenez une explication plus claire lorsque l'installation est incomplète.
  • Éditeur et navigation : Activez le format lors de l'enregistrement, recherchez les choix de thème, mettez en surbrillance les cellules du tableau Markdown sélectionnées et utilisez les raccourcis de zoom d'image en dehors des onglets de l'éditeur.
  • Orchestration et plugins : Le panneau Orchestration est à nouveau disponible en tant qu'opt-in expérimental. Les employés des terminaux fermés peuvent rouvrir à partir de leurs cartes, les discussions natives reçoivent des messages d'orchestration complets et les plugins de barre d'état activés permettent à leurs employés de continuer à fonctionner.
  • Performances et fiabilité : Les mises à jour de l'aperçu du chat évitent une copie redondante de l'historique complet, le défilement du texte en cache évite les mises à jour de la présentation des fichiers entiers et la journalisation des diagnostics utilise moins de données. La modification de l'aperçu supprime le travail inutile ; aucune amélioration de la latence de l’ensemble de l’application n’est revendiquée.

Notes de compatibilité et de mise à niveau

  • Le délai de mise à jour est facultatif : Paramètres → Général → Offres de mises à jour Aucune, 1, 3, 7, 14 ou 30 jours. Aucun ne reste la valeur par défaut et Skip Delay Once contourne une mise à jour suspendue.
  • Le format lors de l'enregistrement est facultatif : Le comportement d'édition existant reste le même jusqu'à ce que vous l'activiez.
  • Panneau d'orchestration : Cette version restaure l'opt-in expérimental après la désactivation précédente du panneau.
  • Modifications de téléphone : Les modifications de l'application téléphonique nécessitent une application Orca Mobile mise à jour ainsi qu'un ordinateur de bureau ou un serveur compatible.
  • Historique des discussions enregistré : Le nettoyage de l'historique en direct ajouté précédemment a été annulé. Les conversations enregistrées existantes, y compris les historiques déjà compactés, restent lisibles.

Problèmes connus

Stockage des discussions enregistré : Le compactage de l'historique en direct est suspendu, afin que le stockage des discussions puisse augmenter à mesure que les conversations se poursuivent. Cette version ne prétend pas supprimer toutes les sources de blocages de chat.

Longs délais de mise à jour : Avec un délai de 14 ou 30 jours, une version peut quitter le flux de mise à jour avant de devenir éligible. Aucun et Skip Delay Once restent disponibles.

Problèmes GitHub sur les anciens serveurs couplés : L'ouverture d'un numéro via un référentiel ou une URL peut rendre la modification du titre, de l'étiquette et du responsable indisponible. Les itinéraires locaux et d'origine du projet ne sont pas affectés ; Ouvert sur GitHub reste disponible.

Remplacements de commandes de plugin : Un plugin remplaçant une commande intégrée peut toujours se terminer après qu'Orca a utilisé la commande normale à la place, provoquant que l'action se produise deux fois.
