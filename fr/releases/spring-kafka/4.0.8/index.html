spring-kafka v4.0.8

Correctif Publié22 oct. 2026 Sourcespring-projects/spring-kafka Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

printemps-kafka v4.0.8

## :lady_beetle : corrections de bugs

  • KafkaTemplate.receive() renvoie un enregistrement à un décalage différent lorsque le décalage demandé est manquant #4831
  • GH-4823 : Maintenir la pause de partition entre les conteneurs enfants #4829
  • KafkaAdmin signale les échecs de modification de la configuration du sujet comme « Échec de l'obtention des descriptions de sujet » #4827
  • ContainerGroupSequencer ne désactive pas le démarrage automatique des conteneurs avec un ralentiEventInterval #4825
  • Flaky BatchListenerConversionTests.conversionError() #4822
  • DefaultErrorHandler ignore backOffFunction lorsque le BackOff par défaut n'a aucune tentative #4819
  • Le conteneur de partage isInExpectedState() ignore un thread consommateur qui s'est terminé suite à une erreur #4813
  • La réponse future de ReplyingKafkaTemplate expire au lieu d'échouer lorsque l'envoi échoue #4812
  • AbstractConsumerSeekAware.onPartitionsRevoked() supprime les rappels des autres consommateurs #4807
  • RoutingKafkaTemplate.partitionsFor() lève UnsupportedOperationException #4806
  • Les beans convertisseur Lambda ou référence de méthode interrompent le démarrage de @KafkaListener #4803
  • CommonMixedErrorHandler ne délègue pas onPartitionsAssigned(), perdant des enregistrements lors d'une nouvelle tentative par lots #4798
  • Prise en charge de la désérialisation à deux arguments dans DelegatingByTopicDeserializer #4793
  • En-têtes d'exception de désérialisation mappés sortants avec Kafka 4.4 clients #4776
  • Le rééquilibrage coopératif peut laisser les partitions qu'un consommateur conserve en permanence non consommées (écouteur asynchrone) #4771
  • Les sujets de nouvelle tentative utilisent BackOff.STOP (-1) comme délai lorsque le BackOff a sa propre limite #4769
  • AbstractConsumerSeekAware conserve les mappages de rappel après la désinscription #4768
  • Les gestionnaires d'erreurs mixtes et délégués suppriment les enregistrements de lots restants lorsque seekAfterError est faux #4766
  • ExponentialBackOffWithMaxRetries(0) réessaye toujours une fois #4759
  • Rendre le cache ExceptionMatcher thread-safe #4758
  • acknowledge() après un accusé de réception partiel par lots valide uniquement l'enregistrement suivant #4733
  • ConcurrentMessageListenerContainer ne signale pas les demandes de pause de partition provenant des conteneurs enfants #4731
  • Appliquer le fournisseur de serveurs d'amorçage dans DefaultShareConsumerFactory #4700
  • Suspendre @KafkaListener : le consommateur arrête définitivement de récupérer les partitions qu'il conserve lors d'un rééquilibrage #4697
  • Le chemin de réussite de la réponse de l'écouteur asynchrone ne signale jamais les échecs au récepteur Observation #4685
  • L'attente du réveil du consommateur annule la prochaine validation de décalage, qui est ensuite ignorée #4684
  • Copiez le résolveur de type dans copyWithType #4667
  • ShareKafkaMessageListenerContainer NPE au start() lorsqu'ils sont construits à partir d'un modèle de sujet ou d'une liste de partitions #4665
  • Ne pas valider une valeur désérialisée nulle #4657
  • Le mappage d'en-tête à valeurs multiples perd des valeurs lors des entrées lorsqu'un en-tête de type JSON est présent #4645
  • Les surcharges ReplyingKafkaOperations sendAndReceive exposent une nullité incorrecte pour ReplyTimeout et returnType #4641
  • Le mode assignable DelegatingByTypeSerializer peut sélectionner un délégué plus général grâce à un comparateur non transitif #4632
  • Les conteneurs de partage ignorent ContainerProperties.clientId #4628
  • ShareKafkaListenerContainerFactory.createContainer(String...) n'applique pas la configuration d'usine #4618
  • Les messages d'assertion dans setTopicPartitions et setDefaultReplyTimeout nomment la mauvaise propriété #4610
  • L'écouteur Kafka avec autoStartup=false est démarré sans condition sur ApplicationContext.restart() (alwaysStartAfterRefresh=true ignore autoStartup après la première actualisation) #4607
  • Fermez le délégué par défaut dans DelegatingByTopicSerialization #4590
  • DelegatingByTypeSerializer ne ferme pas ses délégués #4580

## :notebook_with_decorative_cover : Documentation

  • Correction des noms API obsolètes dans les documents de référence #4749
  • Propriété/documentation autoStartDltHandler trompeuse pour @RetryableTopic dans les tests #4702
  • Améliorer le guidage des messages d'erreur des packages trusted-packages #4631
  • Correction des noms DeadLetterPublishingRecoverer API dans les documents de gestion des erreurs #4613

:hammer: Mises à niveau des dépendances

  • Mise à niveau du traçage micrométrique vers 1.6.8 #4854
  • Mise à niveau du micromètre vers 1.16.8 #4851
  • Améliorer le réacteur vers 2025.0.8 #4849
  • Mettre à niveau spring-data-bom vers 2025.1.8 #4846
  • Mise à niveau du framework Spring vers 7.0.10 #4844 - Rump org.slf4j:slf4j-api de 2.0.19 à 2.0.20 #4721 - Rump org.slf4j:slf4j-api de 2.0.18 à 2.0.19 #4670
