écraser v0.93.1

## Désactiver la prise en charge de la souris et plus Hey, comment se passe ta semaine ? Nous avons quelques changements aujourd'hui, comprenant principalement des correctifs mais aussi quelques ajouts intéressants. ## Désactiver la prise en charge de la souris Vous souhaitez désactiver la prise en charge de la souris dans Crush ? Sentez-vous chanceux car notre contributeur préféré @timotheosh a ajouté exactement cela. Avec la configuration ci-dessous, vous pouvez y parvenir. Il est également possible de l'activer via la boîte de dialogue de la palette de commandes. crushrc :

option ui mouse false

crush.json :

{ "options": { "tui": { "mouse": false } } }
<img width="600" alt="image" src="https://github.com/user-attachments/assets/ad64e680-d244-4e7e-9cb4-1b7fff6271ed" /> <img width="600" alt="image" src="https://github.com/user-attachments/assets/a2fd43cd-bb46-4326-93cf-596e5361d77d" /> ## Correction de l'UX pour les modèles sans vision Dans certains cas, Crush vous permettait de joindre une image même lorsque le modèle sélectionné n'était pas capable de visionner. La pièce jointe a ensuite été supprimée silencieusement dans la demande. Maintenant, nous le validons correctement et affichons un message pour que vous sachiez quand il n'est pas pris en charge. ## Correction de certains modèles sur GitHub Copilot Sur Copilot certains modèles ne fonctionnent que sur le point de terminaison `/responses` : nommés GPT-6 Astra et les modèles Grok. ## Correction de certains modèles sur OpenCode Zen & Go OpenCode nécessite également que certains modèles utilisent des points de terminaison spécifiques. Tous les modèles ne prennent pas en charge le point de terminaison `/chat/completions` ; certains nécessitent `/responses` ou `/messages`. Nous avons résolu ce problème pour les modèles actuellement pris en charge par OpenCode. ## Correction de Sentry MCP + autres Une mauvaise configuration a rendu impossible l'authentification avec OAuth2 avec quelques MCP, y compris le [Sentry MCP](https://mcp.sentry.dev/). C'est maintenant corrigé ! ## Correction d'une fuite de mémoire potentielle @caniko a découvert une fuite de mémoire, en particulier lorsque `discover_models: true` est défini. Ce problème a été résolu ! Pour lire l'explication technique, voir #3162 et #3683. --- Rendez-vous dans la prochaine version !
