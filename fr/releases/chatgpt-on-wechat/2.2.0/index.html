chatgpt-sur-wechat 2.2.0

🌐 anglais | 中文

🧩 Centre de capacités

L'ancien menu Compétences s'appelle désormais Capacités, un emplacement unique dans la console Web et le bureau client pour gérer les outils intégrés, les outils MCP et les compétences :

  • Installation de compétences : installez depuis Cow Skill Hub, GitHub ou ClawHub, ou téléchargez une archive, un SKILL.md ou un dossier. Chaque compétence est prévisualisée en premier et installée uniquement après votre confirmation.
  • Configuration MCP : ajoutez, modifiez et supprimez des serveurs MCP dans l'interface utilisateur, couvrant les transports HTTP stdio, SSE et Streamable. L'édition de formulaire et l'édition JSON sont disponibles et vous pouvez coller directement une ou plusieurs entrées mcpServers. La sauvegarde vérifie la connexion et répertorie les outils du serveur ; les modifications prennent effet au message suivant sans redémarrage. Merci @tsumon (#3155)
  • Diagnostics de récupération d'outils : voyez comment les outils MCP ont été classés et pourquoi la récupération a reculé au cours d'une conversation, ce qui permet de découvrir plus facilement pourquoi un outil n'a pas été sélectionné. Merci @zhongjunqi7657 (#3165)

🤝 Collaboration multi-agents

  • Transfert de tâches sous forme de messages séparés : lorsqu'un agent délègue une tâche à un membre de l'équipe, la réponse du membre est diffusée sous la forme de son propre message sous son propre nom et avatar, à la fois sur la console Web et sur le bureau client.
  • Gestion des sessions d'équipe : l'effacement du contexte l'efface désormais pour chaque participant à une session d'équipe ; une discussion de groupe affiche ses membres dans la liste des sessions avant l'envoi du premier message ; le sélecteur @ peut sélectionner l'agent propriétaire de la session.
  • Isolement des données : les compétences, les aperçus de fichiers téléchargés et les répertoires de sites Web sont désormais définis par agent.
  • Corrections :
    • Correction d'un agent répondant au nom d'un membre de l'équipe et des appels de l'outil d'un agent disparaissant après une actualisation.
    • Correction des agents supprimés persistant dans les listes de membres, ce qui empêchait les discussions directes d'utiliser les outils (Merci @Frank-zhu0404 #3234).
    • Correction de l'agent par défaut qui n'était pas résolu lors de la création des membres de l'équipe et du nettoyage des équipes de canal (Merci @c020627 #3205).
    • Correction de certains points de terminaison qui ne parvenaient pas à localiser l'agent lorsque le paramètre était envoyé uniquement dans le corps de la requête (Merci @c020627 #3177).

🖥 Mises à niveau de la console

  • Reconstruction frontend et backend : les pages frontend de la console Web et les contrôleurs backend API sont divisés en modules de fonctionnalités, remplaçant les fichiers uniques surdimensionnés qui étaient devenus difficiles à maintenir. Les ressources frontales se chargent par module et sont mises en cache, donc une actualisation ne télécharge plus tout à nouveau. Chaque page a sa propre URL (telle que /agents, /settings, /scheduler), le travail de va-et-vient du navigateur, une actualisation reste sur la page actuelle et l'ancienne adresse /chat est automatiquement redirigée. Merci @zkjqd (#3167, #3172)
  • Navigateur de messages : accédez rapidement aux questions précédentes d'une session. La console Web ouvre une liste de questions à partir d'un bouton dans l'en-tête, et le bureau client ajoute un rail de navigation sur la droite.
  • Mise à jour One-click : le menu de version dans la barre latérale recherche et applique les mises à jour source dans un click. Les données utilisateur sont sauvegardées avant la mise à jour et un échec de mise à jour n'affecte pas le service en cours d'exécution. Merci @tsumon (#3154)
  • Statut de la réponse : les réponses arrêtées, interrompues et en cours sont étiquetées en conséquence. Une réponse interrompue par un redémarrage du service affiche un avis clair et, après une actualisation, vous pouvez continuer à suivre une réponse toujours en cours de génération.

🧠 Mémoire et base de connaissances

  • Reclassement : la récupération de mémoire prend en charge un modèle de reclassement facultatif qui réévalue les résultats rappelés pour une meilleure précision. Il est désactivé par défaut et activé via rerank_provider. Merci @SummerCaptain (#3230)
  • Score de récupération hybride : la récupération de vecteurs et de mots-clés est désormais fusionnée par des scores normalisés par classement, corrigeant les scores dilués lorsqu'un camp n'a aucun coup sûr et les échelles de score ne correspondent pas entre les deux. Merci @SummerCaptain (#3164)
  • Index de la base de connaissances : index.md est mis à jour lorsque les documents sont supprimés ou déplacés (Merci @alanyz106 #3237) ; un index volumineux n'injecte que la liste des titres pour éviter de prendre trop de contexte de conversation.
  • Base de connaissances partagée : correction de la lecture et de la synchronisation d'une base de connaissances partagée située en dehors de l'espace de travail de l'agent (Merci @lorenzozanee #3182, @Jeremy-xuan #3183) ; les modifications effectuées via les outils ou la console marquent désormais l'index pour actualisation (Merci @NBSW002 #3184, @c020627 #3206).
  • Mémoire à long terme : lorsque MEMORY.md dépasse sa limite de longueur, les entrées les plus récentes sont conservées en premier (Merci @SEVEN-us #3244).
  • Document chunking : correction du contenu avant le premier titre d'un long document Markdown qui n'est pas indexé et du contenu qui est indexé deux fois lorsque les niveaux de titre sont ignorés ; /memory status vous invite à reconstruire l'index (Merci @Bdysj #3309).
  • Chargement de session : l'ouverture d'une session ne déclenche plus une analyse de la mémoire et une reconstruction de l'index, le premier message d'une nouvelle session répond donc plus rapidement.

📐 Contexte et coût des jetons

  • Taux de réussite du cache de modèle plus élevé : l'invite du système affiche désormais uniquement la date actuelle et l'heure exacte provient d'un nouvel outil time. L'invite du système reste stable tout au long de la journée, ce qui améliore considérablement les taux de réussite du cache du modèle et réduit l'utilisation des jetons. Merci @a1094174619 (#3250)
  • Découpage du contexte : le découpage au tour par tour et le découpage du budget par jeton sont fusionnés en une seule passe axée sur le budget. Aucun appel de synthèse n'est effectué dans les limites du budget, évitant ainsi les demandes de modèles inutiles, et le tour précédent est toujours conservé. Merci @liuns-yang (#3188), @Frank-zhu0404 (#3199), @lorenzozanee (#3185)
  • Messages de suivi : les messages que vous envoyez pendant que le modèle est encore en streaming sont désormais récupérés rapidement (Merci @tsumon #3190).

🤖 Capacités du modèle

  • Nouveaux modèles : ajout de gpt-6.1-sol, gpt-6-luna et gpt-6-sol, avec gpt-6.1-sol comme modèle OpenAI recommandé par défaut (l'appel de l'outil passe par les réponses API) ; ajout du claude-opus-5-5 comme modèle Claude recommandé par défaut.
  • Fenêtre contextuelle : la famille Claude 5 (claude-opus-5-5, claude-opus-5, claude-sonnet-5, claude-fable-5, etc.) est désormais comptée avec une fenêtre contextuelle de 1M et une sortie maximale de 128K, au lieu des 200K précédents. Claude 4 et versions antérieures restent inchangées.
  • OpenAI Responses API : un nouveau paramètre open_ai_api_type. Définissez-le sur responses pour appeler les réponses API, pour les points de terminaison qui ne fournissent plus /chat/completions. Le auto par défaut conserve le comportement existant.
  • MiniMax : la compréhension des images utilise désormais la capacité multimodale native de M3 (Merci @octo-patch #3160).
  • Qwen : qwen3.8-max et qwen3.8-flash sont traités comme des modèles à pensée hybride ; correction des sessions DashScope ignorant l'invite système définie par le plugin de rôle (Merci @Bdysj #3310).
  • Reconnaissance vocale : utilise le modèle ASR configuré au lieu de toujours utiliser whisper-1.
  • AnySearch : région et langue de recherche configurables, avec une validation plus stricte des résultats renvoyés (Merci @WangPan59 #3153, #3163).

📡 Chaînes

  • DingTalk :
    • Le streaming de la carte AI répond lorsque dingtalk_card_enabled est activé (Merci @tsumon #3162) ; les réponses reviennent à Markdown lorsque les cartes sont éteintes ou qu'une carte ne parvient pas à être envoyée.
    • Reçoit les pièces jointes (Merci @tsumon #3161).
    • Correction d'erreurs et de notifications de réponses supprimées, de messages de groupe en dehors de la liste blanche générant des erreurs et de messages en texte enrichi sans images n'obtenant aucune réponse (Merci @Lesereingrape #3282, #3284, #3293).
  • QQ :
    • Les messages vocaux utilisent la transcription officielle et sont immédiatement remis à l'agent (Merci @HnBigVolibear #3195).
    • Reçoit les fichiers, restitue les réponses Markdown et conserve le nom du fichier d'origine lors de l'envoi de documents (Merci @c020627 #3209).
    • Les sessions de discussion de groupe suivent désormais group_shared_session, en cohérence avec les autres canaux : chaque membre obtient sa propre session par défaut, alors que les versions précédentes partageaient une session avec l'ensemble du groupe. Définissez "group_shared_session": true pour conserver le comportement précédent (Merci @c020627 #3209).
  • Feishu : les messages de groupe qui @-mentionnent uniquement les autres membres ne déclenchent plus de réponse, et les messages de groupe en texte enrichi sont vérifiés par rapport à leur liste @ (Merci @c020627 #3173) ; les réponses d'image et de fichier sont téléchargées directement depuis la mémoire (Merci @c020627 #3226) ; les rappels de webhook vérifient désormais le jeton.
  • WeCom : l'application WeCom prend en charge les réponses de fichiers et de vidéos (Merci @c020627 #3249) et les réponses avec des images générées localement (Merci @Lesereingrape #3312), et son rappel vérifie l'ID Corp (Merci @c020627 #3159) ; Les messages du groupe WeCom Bot sont correctement reconnus comme @-mentions (Merci @c020627 #3193).
  • Service client WeChat : envoie des fichiers multimédias locaux et les réponses aux fichiers incluent leur texte d'accompagnement (Merci @c020627 #3262) ; correction du curseur de synchronisation des messages qui n'avançait pas dans le temps (Merci @rudycelekli #3258).
  • WeChat : correction de la gestion de plusieurs instances de canal dans les configurations multi-agents ; l'état de connexion est conservé lorsque les instances de canal changent.
  • Réponses vidéo : Discord, Slack, Telegram, Feishu, DingTalk, le service client WeChat et le compte officiel WeChat téléchargent directement les vidéos générées localement, au lieu de les supprimer ou d'envoyer uniquement le chemin du fichier (Merci @Lesereingrape #3289, #3299, #3321, @c020627 #3297).
  • Slack / Telegram : Telegram restitue correctement les blocs de code ~~~ (Merci @huiq777 #3287) ; Les fichiers Slack portant le même nom ne s'écrasent plus (Merci @rudycelekli #3265).
  • Compte officiel WeChat : compatible avec Python 3.13 (Merci @c020627 #3214).

🛡 Stabilité et sécurité

Cette version fiabilise l'exécution des tâches et renforce systématiquement l'accès aux ressources externes et les écritures de fichiers locaux :

  • Exécution persistante : la réponse du modèle, les appels d'outils et les résultats de chaque étape sont écrits dans la base de données de session dès que l'étape est terminée, au lieu de tous en même temps à la fin du tour. Après un redémarrage du service ou une sortie inattendue d'un processus, un tour interrompu est restauré avec ses étapes terminées, et le message suivant peut continuer à partir de là. Merci @liuns-yang (#3191)
  • Limites de téléchargement : les téléchargements externes (médias de chaîne, images de terminal, compréhension des images, fichiers de mots clés, etc.) sont limités en termes de taille de fichier et de durée totale, de sorte que les fichiers surdimensionnés ou les connexions lentes ne peuvent pas ralentir le service. La compréhension de l’image revalide l’adresse à chaque redirection. Merci @rudycelekli (#3255, #3256, #3257, #3264, #3266, #3267, #3268, #3269, #3270, #3271, #3272), @c020627 (#3219, #3225, #3252, #3300, #3322)
  • Délai d'expiration des demandes : chaque demande externe de modèles, de voix, de traduction, etc. a désormais un délai d'attente, de sorte qu'un amont qui ne répond pas ne suspend plus la conversation. Merci @c020627 (#3217, #3220, #3240, #3254, #3275)
  • Écritures de configuration sécurisées : config.json, les configurations de plug-in, les listes de modèles, les tâches planifiées, les configurations de compétences, les fichiers d'informations d'identification, MEMORY.md et bien plus encore sont écrits de manière atomique, donc une écriture qui échoue à mi-chemin ne peut pas corrompre le fichier d'origine ; un fichier de tâche planifiée corrompu est automatiquement restauré à partir de sa sauvegarde. Merci @c020627 (#3223, #3239, #3241, #3242, #3259, #3273, #3274, #3276, #3279, #3280, #3281), @rudycelekli (#3260)
  • Fichiers temporaires : les noms de fichiers reçus par les chaînes sont confinés au répertoire temporaire et limités en longueur (Merci @Lesereingrape #3247, #3248, @c020627 #3212, #3301) ; les médias téléchargés, les pièces jointes de réponse et la parole synthétisée sont stockés dans le répertoire temporaire de l'agent propriétaire (Merci @c020627 #3198, #3207, #3208, #3213) ; le répertoire temporaire est nettoyé lorsqu'une archive de compétences ne parvient pas à être extraite (Merci @Lesereingrape #3325).
  • Rédaction du journal : les informations d'identification du canal sont masquées dans les journaux de débogage (Merci @fuxicodex #3228).

🛠 Autres améliorations et correctifs

  • Voix :
    • Convertit les fichiers voix en soie et amr avec des extensions majuscules (Merci @c020627 #3152).
    • Alibaba Cloud, Edge, ElevenLabs et d'autres services vocaux renvoient un message d'erreur en cas d'échec au lieu de supprimer silencieusement la réponse (Merci @c020627 #3243, #3263, #3278).
    • Correction des poignées de fichiers WAV qui n'étaient pas fermées (Merci @aniruddhaadak80 #3286).
    • La reconnaissance vocale Google renvoie un message d'erreur sur les exceptions au lieu de masquer l'erreur d'origine (Merci @aniruddhaadak80 #3326).
  • Tâches planifiées : les heures d'exécution locales sont conservées pendant les transitions à l'heure d'été (Merci @liuns-yang #3189, #3204) ; les fichiers produits par les exécutions de compétences planifiées sont livrés directement plutôt que sous forme de chemins de fichiers (Merci @c020627 #3253).
  • Sauvegarde : les sauvegardes peuvent être écrites sur un système de fichiers différent (Merci @zyc2022 #3200, @chen1070109514 #3246) ; la restauration d'une sauvegarde multi-agents conserve les chemins d'accès à l'espace de travail d'agent existants de cette machine (Merci @Lesereingrape #3319).
  • Plugins : les plugins démarrent normalement lorsque leur config est vide ou incomplète (Merci @c020627 #3224) ; Midjourney signale un index d'image invalide (Merci @Lesereingrape #3291) ; le plugin de rôle renvoie de l'aide lorsqu'un rôle personnalisé n'a pas de description (Merci @Lesereingrape #3296) ; les commandes d'administration signalent des arguments invalides lors de la définition de la priorité du plugin ou du changement de modèle (Merci @Lesereingrape #3303, #3305) ; une entrée manquante ou mal formée dans plugins.json est remplie de valeurs par défaut au lieu de casser chaque plugin (Merci @Lesereingrape #3314) ; nom de fichier corrigé et descripteurs non fermés dans le plugin de résumé (Merci @c020627 #3215).
  • Gestion des agents : la suppression d'un agent supprime également ses données de projet (Merci @c020627 #3216).
  • Agent Mail : Docker Compose ajoute une configuration facultative de messagerie d'agent qui permet à l'agent d'envoyer, de recevoir, de rechercher et de gérer des e-mails. Voir Agent Mail (Merci @tsumon #3236).
  • Gestion des messages : correction des paramètres de contexte de message partagés entre les sessions (Merci @c020627 #3222) ; l'expiration du cache de fichiers est mesurée à partir du fichier le plus récent (Merci @c020627 #3218) ; correction du problème de sortie du processus de blocage du limiteur de débit et d'échec à un taux de 0 (Merci @aniruddhaadak80 #3285) ; les types de réponse non pris en charge affichent le type d'origine dans le message d'erreur, et les sessions vocales n'affichent plus d'erreur après qu'un plugin abandonne la réponse (Merci @Bdysj #3306, #3307) ; correction de #reset, du rappel de message Feishu et de la suppression de session qui ne parvenait pas à effacer les messages en file d'attente sous des agents autres que ceux par défaut (Merci @Lesereingrape #3316).
  • Outil de navigateur : récupère automatiquement après la déconnexion du pilote du navigateur au lieu d'erreurs répétées.
  • Bureau client : correction de l'invite d'autorisation du microphone qui n'apparaissait pas sur macOS (Merci @cowagent #3181) ; correction d'un crash de démarrage provoqué par des raccourcis Windows et des lignes de journal backend dupliquées.
  • Ingénierie : ajout d'un pipeline de test complet et d'un filtre anti-peluches (Merci @fuxicodex #3166, #3203) ; isolation des tests améliorée (Merci @c020627 #3169, #3201, @rudycelekli #3261).
  • Documents :
    • Configuration MCP documentée avec authentification statique du porteur (Merci @ct-jaryn #3227).
    • Correction des liens brisés et du libellé du journal dans le README (Merci @yetuge #3194, #3196, #3197).

📦 Comment mettre à niveau

  • Déploiement source : exécutez cow update pour une mise à niveau d'un click, mettez à jour à partir du menu de version dans la barre latérale de la console Web, ou extrayez le dernier code et redémarrez. Consultez le [guide de mise à niveau] (https://docs.cowagent.ai/guide/upgrade).
  • Bureau client : recherchez les mises à jour et mettez à jour avec un click dans le client, ​​ou obtenez la dernière version à partir de la [page de téléchargement] (https://cowagent.ai/download/).
