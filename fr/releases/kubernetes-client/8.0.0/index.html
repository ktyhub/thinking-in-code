kubernetes-client v8.0.0

Bogues

  • Correctif #8105 : requêtes suspendues lorsqu'une action de nouvelle tentative, une décision de nouvelle tentative ou un nettoyage de réponse lève une exception.
  • Correctif #7374 : (crd-generator) Les CRD générés n'élaguent ou ne rejettent plus ce que le client écrit : Object, Map brut, List<Object>, collection brute, @JsonUnwrapped et les propriétés polymorphes conservent leur contenu, et les types de date et d'heure déclarent uniquement un format auquel leurs valeurs correspondent (Duration, LocalDateTime et les types partiels perdent date-time). Les propriétés Optional obtiennent le schéma de leur type de valeur au lieu de conserver les champs inconnus, consultez le guide de migration
  • Correctif n° 6779 : (httpclient-jetty) 401 réponses sans en-tête WWW-Authenticate, comme le serveur API les envoie, sont renvoyées avec leur corps au lieu d'échouer avec "Violation du protocole HTTP : défi d'authentification sans en-tête WWW-Authenticate".
  • Correctif n° 6779 : (httpclient-jetty, httpclient-vertx, httpclient-vertx-5) Un mot de passe proxy contenant deux points, ou une URL de proxy avec un utilisateur et aucun mot de passe, est désormais utilisé pour s'authentifier auprès du proxy, au lieu de recourir à un en-tête de requête Proxy-Authorization que les requêtes HTTPS transmettent via le tunnel proxy vers le serveur API.
  • Correctif #6779 : Un nom d'utilisateur proxy configuré sans mot de passe est envoyé avec un mot de passe vide au lieu de null, et une URL proxy avec un utilisateur et aucun mot de passe comme user: au lieu de user (RFC 7617)
  • Correctif n°8134 : (httpclient-jetty) Une négociation WebSocket ayant échoué n'appelle plus le onError de l'auditeur, le futur renvoyé échoue déjà avec lui. Lorsque la poignée de main a été réessayée, cela a mis fin aux sessions de surveillance et d'exécution/attachement avant que la nouvelle tentative ne puisse les ouvrir.
  • Correctif #8134 : (httpclient-jetty) Les informations d'identification d'un proxy SOCKS5 lui sont envoyées
  • Correctif n° 8134 : (httpclient-jetty, httpclient-vertx) Les informations d'identification du proxy qui ne sont pas Basic user:password sont uniquement ajoutées en tant qu'en-tête Proxy-Authorization aux requêtes lues par un proxy HTTP. Les requêtes HTTPS et WSS, les WebSockets tunnelisés par Vert.x et les requêtes via un proxy SOCKS les ont transportés vers le serveur API
  • Correctif #8134 : (httpclient-vertx-5) Les informations d'identification du proxy qui ne sont pas Basic user:password sont envoyées au proxy HTTP par Vert.x, sur le CONNECT également, donc les requêtes HTTPS et WebSocket via un proxy qui les nécessite de fonctionner, et elles n'atteignent plus le serveur API
  • Correctif #8134 : (httpclient-okhttp) Un 407 du serveur API (via pods/proxy par exemple) ne reçoit plus de réponse avec les informations d'identification du proxy, qui sont passées par le tunnel proxy, et les informations d'identification rejetées par le proxy ne sont plus renvoyées.
  • Correctif #8140 : (httpclient-vertx-5) Une requête dont la connexion est fermée avant de pouvoir être écrite échoue avec un IOException et est réessayée, au lieu de se bloquer jusqu'à l'expiration du délai d'attente de la requête (vu sous Windows).
  • Correctif #8134 : (httpclient-jetty) Les cookies définis par une réponse ne sont plus renvoyés lors des requêtes ultérieures et des mises à niveau de WebSocket, comme avec les autres implémentations de HttpClient
  • Correctif #8109 : Un java.sql.Date écrit comme yyyy-MM-dd est lu comme une date locale au lieu du jour précédent à l'ouest de UTC. Year, Month, java.sql.Date et Locale conservent leur format filaire 7.x, les mappeurs que vous construisez vous-même ont besoin du nouveau Jackson2JdkTypesModule, voir le guide de migration
  • Correctif #8109 : (crd-generator) Les schémas byte[], ByteBuffer, char[], Year et java.sql.Date correspondent à ce que le client écrit (byte[] et ByteBuffer sont des chaînes format: byte), donc le serveur API ne les rejette plus. @PrinterColumn sur un LocalDate est une colonne string au lieu d'une colonne date qui affichait <invalid>
  • Correctif #8008 : (httpclient-vertx-5) Les requêtes avec un corps InputStream et Expect: 100-continue (versions binaires) ne se bloquent plus, et un corps InputStream de longueur connue est envoyé avec Content-Length au lieu d'être fragmenté.
  • Correctif #8139 : (httpclient-okhttp) Les WebSockets répondent à la trame de fermeture du serveur même lorsque l'écouteur ne le fait pas, donc la redirection de port et les écouteurs personnalisés libèrent la connexion au lieu d'attendre que le serveur la supprime
  • Correctif n°8152 : (httpclient-vertx, httpclient-vertx-5, httpclient-jetty, httpclient-jdk) Les WebSockets envoient un ping tous les Config#websocketPingInterval (30 s par défaut), comme OkHttp l'a déjà fait, afin que les équilibreurs de charge qui ferment les connexions inactives ne suppriment plus les surveillances silencieuses.

Améliorations

  • Correctif #8109 : (crd-generator) Les propriétés int/Integer et long/Long obtiennent format: int32 et format: int64, comme Controller-gen
  • Correctif #7987 : (kubernetes-client-api) withShardSelector accepte un ShardSelector (ShardSelector.builder().addShard(0, 4).addShard(2, 4).build()) tapé à côté de l'expression brute String, de sorte que la grammaire CEL shardRange(...) et ses limites hexadécimales n'ont pas besoin d'être écrites à la main.

  • Correctif #8041 : DSL tapé pour les ressources ajoutées dans Kubernetes 1.37 : certificates().v1().podCertificateRequests(), dynamicResourceAllocation().v1().deviceTaintRules(), storageMigration().v1().storageVersionMigrations() et scheduling().v1beta1() podGroups() et workloads(), plus certificates().v1beta1().podCertificateRequests() et storageMigration().v1beta1().storageVersionMigrations(). kubernetes-model-policy expédie également le modèle lifecycle.k8s.io/v1alpha1 (Eviction et EvictionRequest)

Remarque : modifications majeures

  • Consultez la documentation détaillée de la migration pour connaître les modifications importantes dans 8.0.0
  • Correctif #8041 : (kubernetes-client-api) runtimeClasses() et network().ingresses() (et network().ingress()) utilisent les modèles v1 au lieu de ceux v1beta1. Kubernetes ne sert plus, voir le guide de migration
  • Correctif #7374 : déplacé vers Jackson 3 (coordonnées et packages tools.jackson). La sérialisation par défaut conserve le comportement de Jackson 2 pour les types personnalisés, voir le guide de migration
  • Correctif #7987 : (kubernetes-client-api) Filterable#withShardSelector accepte également un ShardSelector typé, donc un withShardSelector(null) littéral ne se compile plus, voir le guide de migration
  • Correctif #8031 : (crd-generator) Suppression du générateur CRD v1 obsolète (crd-generator-api et crd-generator-apt). Migrez vers crd-generator-api-v2 avec le plugin Maven, l'outil CLI, ou la Recette de script de build Gradle, voir la migration guide
  • Correctif #8009 : Déplacement de la ligne de base Java de 11 à 17. En plus des exigences d'exécution, les plugins Maven, le plugin Gradle et le processeur d'annotation nécessitent désormais un Java 17+ JVM pour exécuter la build, et les bundles OSGi déclarent osgi.ee=JavaSE 17
  • Correctif #8050 : (karaf) Le référentiel de fonctionnalités kubernetes-karaf ne définit plus sa propre fonctionnalité scr. kubernetes-client dépend désormais de la fonctionnalité scr fournie par la distribution Karaf, qui fournit les bundles Declarative Services API et les commandes shell scr:*
  • Correctif #8142 : (natif) Le service RevisionSpec remplace workloadRef par schedulingGroup et ajoute evictionResponders, comme le noyau PodSpec depuis Kubernetes 1.37
  • Correctif #8133 : (gestion de cluster ouvert) DiscoveredClusterSpec supprime owner et DiscoveredClusterCondition supprime lastUpdateTime
  • Correctif #8148 : (modèle openshift) Classe de modèle io.fabric8.openshift.api.model.customresourcestatus.conditions.v1.Condition supprimée, les conditions Hive ClusterDeploymentCustomizationStatus utilisent le Kubernetes Condition
  • Correctif #8148 : (openshift-model-config) Les politiques ClusterImagePolicySpec et ImagePolicySpec sont ImageSigstoreVerificationPolicy et leurs racines sont trust ImagePolicyFulcioCAWithRekorRootOfTrust, ImagePolicyPKIRootOfTrust et ImagePolicyPublicKeyRootOfTrust. Classes de modèles FulcioCAWithRekor, PKI, Policy et PublicKey supprimées
  • Correctif #8148 : (openshift-model-config) GCPPlatformStatus supprime serviceEndpoints, classe de modèle GCPServiceEndpoint supprimée
  • Correctif #8148 : (openshift-model-hive) Prise en charge d'oVirt supprimée : ClusterDeprovisionPlatform, MachinePoolPlatform et Platform suppriment ovirt, les classes de modèles OvirtClusterDeprovision et le package io.fabric8.openshift.api.model.hive.ovirt.v1 sont supprimés
  • Correctif #8148 : (openshift-model-hive) vSphere MachinePool.osDisk utilise le programme d'installation io.fabric8.openshift.api.model.installer.vsphere.v1.OSDisk, classe de modèle io.fabric8.openshift.api.model.hive.vsphere.v1.OSDisk supprimée. Le module dépend désormais des openshift-model-installer, openshift-model-machine et openshift-model-operator
  • Correctif #8148 : (openshift-model-installer) GCP PSCEndpoint supprime region
  • Correctif #8148 : (openshift-model-machineconfiguration) Classes de modèles v1alpha1 MachineConfigNode, PinnedImageSet et leurs types associés supprimés, utilisez ceux de v1
  • Correctif #8133 : (gestion de cluster ouvert) MultiClusterHubSpec supprime customCAConfigmap, enableClusterBackup, enableClusterProxyAddon, hive, ingress et separateCertificateManagement. Classes de modèles BackupConfig, ExternalDNSAWSConfig, ExternalDNSConfig, ExternalDNSGCPConfig, FailedProvisionConfig, HiveConfigSpec, HiveConfigStatus, IngressSpec et VeleroBackupConfig supprimées
  • Correctif #8133 : (gestion de cluster ouvert) Observabilité PlatformMetricsSpec et UserWorkloadMetricsSpec remplacent collection par default (PlatformMetricsCollectionSpec et UserWorkloadMetricsCollectionSpec supprimés) et PlatformNamespaceRightSizingRecommendationSpec est renommé PlatformRightSizingRecommendationSpec
  • Correctif #8100 : (tekton) Les classes de modèles Template et AffinityAssistantTemplate ont été déplacées du package io.fabric8.tekton.pod vers io.fabric8.tekton.unversioned, car le pipeline tekton 1.16.0 les déclare comme +versionName=unversioned
  • Correctif #6779 : (httpclient-jetty) Déplacé de Jetty 11 vers Jetty 12.1, voir le guide de migration
  • Correctif #8008 : kubernetes-client et openshift-client sont par défaut Vert.x 5 HttpClient (kubernetes-httpclient-vertx-5) au lieu de Vert.x 4 (kubernetes-httpclient-vertx), voir le guide de migration
