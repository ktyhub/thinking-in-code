kubernetes-client v7.7.0

Bogues

  • Correctif #7747 : (mockwebserver) évite l'exception RejectedExecutionException dans MockWebServer#shutdown() — linéarise la séquence de fermeture pour supprimer la course httpClose-listener vs wait et rend shutdown() idempotent contre les appels répétés (par exemple, les cascades JUnit @Nested afterAll)
  • Correctif #7734 : (mockwebserver) évite d'envoyer Content-Length avec Transfer-Encoding pour les réponses fragmentées
  • Correctif #7716 : (informer) SerialExecutor.execute() revient maintenant immédiatement après l'arrêt — aucun wrapper n'est proposé, planningNext() n'est pas appelé et l'exécuteur sous-jacent n'est pas touché, corrigeant une course NPE post-stop exposée par SharedProcessor.distribute(...) après stop()
  • Correctif n° 7702 : ExecWebSocketListener.onError encapsule désormais WebSocketHandshakeException via le constructeur de chaînage KubernetesClientException au lieu de initCause post-hoc — les échecs de prise de contact avec une réponse de mise à niveau non nulle ne lancent plus IllegalStateException de manière synchrone, donc onFailure/exitCode reçoit le statut analysé et l'exception de prise de contact d'origine comme cause
  • Correctif #7686 : (httpclient-vertx-5) StackBasedRecursionGuard.enter() n'incrémente plus la profondeur lors du refus d'entrée, corrigeant une boucle runOnContext infinie qui bloquait les téléchargements d'InputStreamReadStream en cas de conflit de CPU
  • Correctif #7700 : ExecWebSocketListener.onError reporte désormais la gestion des échecs via SerialExecutor afin qu'une tâche d'état de sortie du canal 3 en attente s'exécute en premier et que le code de sortie analysé soit préservé au lieu d'être écrasé par une exception de fermeture par les pairs.
  • Correctif #7698 : (httpclient-vertx-5) InputStreamReadStream déclenche désormais endHandler lorsqu'il est enregistré après que le signal de fin ait déjà été délivré, corrigeant une course aux flux vides/rapides
  • Correctif #7696 : (httpclient-vertx) efface le gestionnaire d'exceptions de réponse avant la réinitialisation dans Cancel() pour empêcher StreamResetException de s'emballer avec une annulation future
  • Correctif #7695 : ExecWebSocketListener reporte désormais l'achèvement du exitCode via SerialExecutor, de sorte que les écritures asynchrones stdout/stderr en attente sont vidées avant les signaux de sortie.
  • Correctif #7632 : le générateur Java échappe désormais au HTML <, > et & dans les descriptions CRD pour produire un Javadoc valide
  • Correctif #7543 : correction de processInlineDuplicateFields pour résoudre de manière récursive les intégrations en ligne imbriquées
  • Correctif #7450 : StandardHttpClient.shouldRetry() ne réessaye pas sur Vert.x HttpClosedException
  • Correctif #7350 : Un timing de rappel incorrect lors de l'élection du leader conduit au double leader
  • Correctif #7265 : correction de la suppression éphémère des entrées d'index des caches d'informateurs

Améliorations

  • Correctif #7426 : ajoutez HasMetadata#isSameResource pour tester si deux instances HasMetadata pointent vers la même ressource de cluster logique, avec un mode strict facultatif qui nécessite également une correspondance entre kind et resourceVersion.
  • Correctif #7662 : (mockwebserver) nouveau setter MockWebServer#setHttp2ClearTextEnabled(boolean) pour désactiver la mise à niveau HTTP/2 en texte clair (h2c)
  • Correctif #7522 : amélioration de la gestion des dépendances pour kubernetes-httpclient-okhttp
  • Correctif #7550 : ajout d'une méthode ResourceEventHandler onList et obsolète onNothing
  • Correctif #6922 : ajout d'une variante addOwnerReference pour définir les champs contrôleur et blockOwnerDeletion
  • Correctif n° 3396 : (mockwebserver) Améliore la génération de certificats auto-signés pour inclure les noms alternatifs du sujet (SAN) pour une vérification TLS appropriée par les clients modernes
  • Correctif #6923 : Faire en sorte que crd-generator-maven-plugin soit conscient de la chaîne d'outils
