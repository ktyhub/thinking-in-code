nanobot v0.1.5.post2

🐈 nanobot v0.1.5.post2 est là 🎉 — 67 PR fusionnés, 12 nouveaux contributeurs. Le monde des agents est devenu plus grand et plus stable. Si v0.1.5.post1 concernait l'agent apprenant à se gérer lui-même, v0.1.5.post2 concernait la portée et le raffinement. Windows et Python 3.14 ont rejoint la matrice prise en charge. L'outil read_file a appris à comprendre DOCX, XLSX et PPTX. Microsoft Teams est arrivé en tant que canal. Le API compatible OpenAI a commencé à diffuser via SSE. Et en dessous de tout cela, environ 50 correctifs plus petits concernant le cron, la mémoire, les nouvelles tentatives, les fichiers de session et les bizarreries du fournisseur ont continué à transformer « ça marche » en « c'est solide ». Une interface utilisateur de navigateur dédiée a également commencé à prendre forme dans le dépôt – aperçu des sources pour le moment.

Faits saillants

  • Windows + Python 3.14 — support de première classe — Une matrice CI complète couvrant les exécuteurs Windows et Python 3.14, ainsi que des marqueurs d'installation et des correctifs d'exécution pour les bizarreries exposées par ces plates-formes. Si vous avez exécuté nanobot sur WSL parce que « Windows n'a pas vraiment fonctionné », vous pouvez arrêter. (#3194)
  • Documents Office, lisibles nativement — L'outil read_file extrait désormais le texte de DOCX, XLSX et PPTX — tableaux et formes groupées inclus, poignées de classeur fermées en toute sécurité. Combiné avec la prise en charge PDF antérieure, l'agent peut ouvrir n'importe quel format que votre collègue vient de vous envoyer par courrier électronique sans passer par un convertisseur. (#3336, #3269, #3353)
  • API compatible OpenAI — Streaming SSE — /v1/chat/completions émet désormais des morceaux SSE lorsque stream=true, connectant les rappels on_stream / on_stream_end existants. Tout client construit pour OpenAI API – LangChain, LlamaIndex, votre propre interface – obtient des deltas en direct du nanobot au lieu d'attendre la réponse complète. Le point de terminaison a également arrêté de terminer les flux avec un marqueur de réussite après un échec du backend, de sorte que les erreurs apparaissent honnêtement. (#3222, #3262)
  • Microsoft Teams, MiniMax thinking, LM Studio, MyTool — Microsoft Teams a rejoint la liste des chaînes. MiniMax dispose d'un point de terminaison de réflexion dédié de style anthropique ainsi que d'un correctif de mappage reasoning_effort → reasoning_split. LM Studio est désormais pris en charge via des clés API nullables pour les serveurs locaux qui n'en attendent pas. Le nouveau MyTool permet à l'agent d'introspecter sa propre configuration d'exécution et masque les champs de configuration imbriqués sensibles dans la sortie check afin que l'auto-inspection ne divulgue pas de secrets. (#3197, #3160, #3363, #3186, #3177, #3261)
  • Fiabilité – la moitié peu glamour d'une version – Les fichiers de session utilisent désormais des écritures atomiques avec réparation de fichiers corrompus, de sorte qu'un arrêt incorrect ne consomme plus votre historique. La récupération du curseur mémoire gère la corruption des nombres non entiers. Le compactage automatique ignore les sessions avec des tâches actives et unifie l'injection de résumé sur les chemins de consolidation. Les fournisseurs obtiennent un disjoncteur pour le repli des réponses API et reconnaissent les limites de débit ZhiPu 1302. Cron arrête de divulguer les progrès intermédiaires, son schéma d'outil fonctionne avec OpenAI Codex/Responses et les battements de cœur des nouvelles tentatives ne se propagent plus dans les canaux utilisateur. Les suivis de sous-agents persistent dans l'historique des sessions. Vous ne remarquerez jamais la moitié d’entre eux – et c’est exactement le point. (#3312, #3340, #3081, #3304, #3302, #3356, #3320, #3295, #3229, #3242)
  • Canaux — plus silencieux et plus nets — Telegram a obtenu une division à mi-parcours pour les réponses longues et un meilleur rendu de démarque pour une sortie LLM moderne. Discord a cessé de traiter les messages de bot à robot comme des boucles automatiques et a ajouté des listes d'autorisation basées sur les canaux. Le courrier électronique déduplique les messages rejetés par SPF/DKIM pour arrêter le spam des journaux et ignore les messages de boîte aux lettres auto-envoyés. WeCom analyse correctement les messages entrants mixtes. Chacun individuellement petit ; ensemble, ils signifient moins de moments « pourquoi mon bot a-t-il fait ça ». (#3329, #3355, #3280, #3171, #3325, #3228, #3161)
  • WebUI — aperçu anticipé, source uniquement — Un webui/ dédié a atterri dans le dépôt avec un flux de discussion WebSocket, un sélecteur de paramètres régionaux i18n, une typographie inspirée d'Apple avec prise en charge CJK et un thème de bloc de code en mode sombre en direct. Le canal WebSocket sous-jacent a également appris à multiplexer plusieurs chat_id sur une seule connexion. Attention : il s'agit uniquement d'un aperçu des sources : la WebUI n'est pas encore intentionnellement intégrée à la roue publiée. Si vous souhaitez l'essayer, clonez le dépôt et exécutez-le à partir de webui/. Une version packagée suivra une fois l’UX réglé. (#3310, #3272, #3314, #3306)

Communauté

v0.1.5.post2 est à quoi ressemble une version lorsque la fondation est terminée et que les gens commencent à terminer les choses. Une matrice Windows CI de @JiajunBernoulli. Extraction de documents Office natif de @aiguozhi123456. Session atomique écrit du même auteur, détectant un véritable cas limite de perte de données. Une division Telegram à mi-parcours qui rend les réponses longues réellement lisibles. Douze nouveaux contributeurs, et beaucoup d'anciens contributeurs, ont discrètement décroché les choses qui figuraient sur la liste de souhaits de chacun. L'agent s'exécute sous Windows. Il lit vos documents. Il conserve son historique même lorsque l'alimentation clignote. Et une interface utilisateur prend forme dans webui/ pour quiconque veut y jeter un coup d'œil. Il s'agit d'un post-release effectuant un travail post-release - et plus encore.
