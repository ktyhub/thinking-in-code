clickhouse-java v0.10.0-rc1

Guide de migration des versions

Modifications radicales

  • [jdbc-v2] Le pilote ne code plus en dur les paramètres du serveur async_insert=0 et wait_end_of_query=0 sur chaque JDBC connexion. Cela débloque deux scénarios qui ne fonctionnaient pas auparavant : remplacer ces paramètres par connexion ou par et en utilisant le pilote avec des profils en lecture seule qui interdisent les remplacements de SETTINGS. Il y a deux conséquences :

    • Le pilote suit désormais les valeurs par défaut côté serveur pour ces paramètres (remarque : à partir de ClickHouse 26.3, async_insert la valeur par défaut est 1). La suppression du wait_end_of_query=0 explicite n'est pas une opération contre les paramètres par défaut du serveur, mais permet aux utilisateurs d'accepter wait_end_of_query=1.
    • Le nombre de lignes renvoyé par java.sql.Statement.executeUpdate(java.lang.String) (et le PreparedStatement correspondant méthode) n’est plus garantie d’être exacte pour les instructions INSERT lorsque le serveur les exécute de manière asynchrone, et les erreurs d'analyse/de données dans le corps INSERT peuvent ne pas apparaître de manière synchrone en tant que SQLException. Auparavant, il s'agissait de précis car les inserts étaient forcés d'être synchrones (voir aussi https://github.com/ClickHouse/ClickHouse/issues/57768). Pour restaurer le comportement précédent, définissez async_insert=0 (ou wait_for_async_insert=1) par connexion comme paramètre de serveur. En savoir plus sur l'insertion asynchrone : https://clickhouse.com/docs/optimize/asynchronous-inserts.

    (https://github.com/ClickHouse/clickhouse-java/issues/2652,https://github.com/ClickHouse/clickhouse-java/issues/2825)

  • [client-v2] Client.Builder#build() lance désormais ClientMisconfigurationException au lieu de IllegalArgumentException pour authentification et mauvaise configuration SSL (informations d'identification manquantes, conflits méthodes d'authentification, certificat client manquant lorsque l'authentification SSL est activée et magasin trust utilisé ensemble avec un certificat client). Appelants qui comptaient sur la capture de IllegalArgumentException auprès de build() pour ces cas doit attraper ClientMisconfigurationException (qui étend RuntimeException via ClientException). (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Combinaison de setUsername(...) + setPassword(...) avec un en-tête HTTP Authorization personnalisé ( httpHeader(HttpHeaders.AUTHORIZATION, ...)) échoue désormais sur Client.Builder#build() avec ClientMisconfigurationException sauf si l'authentification HTTP Basic est explicitement désactivée via useHTTPBasicAuth(false). Auparavant, cette combinaison était acceptée et l'en-tête personnalisé Authorization était remplacé l'utilisateur/mot de passe au moment de la demande. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] La propriété de configuration access_token (définie via Client.Builder#setAccessToken(String) ou directement via setOption) est désormais effectivement appliqué aux requêtes sortantes en tant que valeur d'en-tête HTTP Authorization textuellement. Auparavant, la valeur était stockée sous access_token mais n'était jamais envoyée sur le réseau, donc la fournir seule n'avait aucun effet sur l'authentification. Les appelants doivent inclure eux-mêmes le préfixe du schéma (par exemple setAccessToken("Bearer <token>")) ou utiliser useBearerTokenAuth(String) qui ajoute automatiquement Bearer . (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client.Builder#useBearerTokenAuth(String) stocke désormais le jeton du porteur sous le access_token clé de configuration (avec le préfixe Bearer ) au lieu de l'écrire directement dans http_header_authorization. Le Le format du fil HTTP est inchangé, mais le jeton n'est plus observable via Client#getReadOnlyConfig() sous le Clé http_header_authorization. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Correction de l'utilisation incohérente du paramètre executionTimeout dans le composant Client. Le délai d'attente était précédemment défini en millisecondes mais récupéré par erreur et utilisé en secondes à certains endroits. Maintenant, il utilise correctement millisecondes de manière constante. (https://github.com/ClickHouse/clickhouse-java/issues/2358)

Nouvelles fonctionnalités

  • [jdbc-v2, client-v2] Implémentation de la configuration des modes SSL. Il est désormais possible de régler ssl_mode sur DISABLED, TRUST, VERIFY_CA et STRICT. Remarque pour les utilisateurs de la V1 : NONE est pris en charge uniquement par le pilote JDBC et mappé à TRUST. Veuillez migrer vers le nouveau nom.

  • Exemples pour client-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/client-v2/src/main/java/com/clickhouse/examples/client_v2/SSLExamples.java

    • Exemples pour jdbc-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/jdbc/src/main/java/com/clickhouse/examples/jdbc/SSLExamples.java (https://github.com/ClickHouse/clickhouse-java/pull/2874, https://github.com/ClickHouse/clickhouse-java/issues/2389, https://github.com/ClickHouse/clickhouse-java/issues/2309, https://github.com/ClickHouse/clickhouse-java/issues/2819)

  • [jdbc-v2, client-v2] (bêta) Implémentation de lecteurs autonomes pour JSONEachRow afin de fournir un échafaudage pour lire ce format. De plus, il permet de mapper les colonnes Json à des types personnalisés à l'aide du pilote JDBC. Voir des exemples dans https://github.com/ClickHouse/clickhouse-java/tree/main/examples/jdbc-v2-json-processors et https://github.com/ClickHouse/clickhouse-java/tree/main/examples/client-v2-json-processors. (https://github.com/ClickHouse/clickhouse-java/pull/2871)

  • [client-v2] Ajout de Session API pour encapsuler et gérer les paramètres de session ClickHouse (session_id, session_check, session_timeout, session_timezone) comme objet réutilisable. L'instance Session peut être appliquée à tous les paramètres de demande utilisant applyTo() et l'état de session peuvent être effacés via clearSession(). De plus, ajouté resetOption(String) à InsertSettings, QuerySettings et CommonSettings pour permettre la suppression de paramètres spécifiques. Les paramètres explicitement définis sur null ne seront pas envoyés au serveur, ce qui est utile pour remplacer les paramètres globaux. (https://github.com/ClickHouse/clickhouse-java/pull/2810)

  • [client-v2] Ajout de la mise à jour des informations d'identification d'exécution API sur Client : updateUserAndPassword(String, String), updateAccessToken(String) et updateBearerToken(String). Requêtes ultérieures sur la même utilisation de l'instance Client les nouvelles informations d'identification sans reconstruire le client. La méthode d'authentification est fixée au moment de la construction ; appeler un le programme de mise à jour d'exécution qui ne correspond pas à la méthode configurée renvoie ClientMisconfigurationException. Voir docs/authentication.md pour plus de détails et des conseils de migration. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [jdbc-v2] Ajout de la propriété de configuration cluster_name pour spécifier un cluster cible pour des instructions telles que KILL QUERY qui nécessitent l'exécution d'une clause ON CLUSTER sur tous nœuds. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [client-v2, jdbc-v2] Ajout de la prise en charge du type ClickHouse Geometry pour ClickHouse 25.11+, où Geometry changé d'un alias String à Variant(Point, Ring, LineString, MultiLineString, Polygon, MultiPolygon) (client toujours compatible avec les anciennes versions). Inclut la gestion de lecture/écriture client et le mappage de type JDBC pour la récupération et insertion de valeurs géométriques. Les écritures actuelles déduisent la variante de géométrie cible à partir de la profondeur d'imbrication du tableau, donc Ring vs LineString et Polygon vs MultiLineString ne sont pas encore distinguables grâce à l'écriture générique Geometry chemin. (https://github.com/ClickHouse/clickhouse-java/pull/2815)

  • [jdbc-v2] ResultSet#getObject(int|String, Map<String, Class<?>>) accepte désormais les noms de type ClickHouse comme clés de carte en plus des noms JDBC SQLType, il a toujours accepté. Seuls les noms de types non enveloppés sont utilisés pour la recherche : Les wrappers Nullable(...) et LowCardinality(...) sont supprimés et n'affectent pas la résolution, donc une clé comme "Int32" correspond aux colonnes Int32 et Nullable(Int32) ; les clés comme "Nullable(Int32)" ne sont pas reconnues. L'ordre de recherche est le nom de l'énumération ClickHouseDataType (par exemple "Int32", "String", "DateTime") puis le nom JDBC SQLType (par exemple "INTEGER", "VARCHAR", "TIMESTAMP"); une entrée manquante laisse la valeur sans contrainte. La fonctionnalité est prise en charge pour Les types primitifs ClickHouse uniquement — Array, Tuple, Map, Nested et les types de géométrie ne sont pas pris en charge et continuent à renvoyer sous leur forme native quelle que soit la carte fournie par l'utilisateur. Cartes existantes saisies uniquement par JDBC SQLType les noms continuent de fonctionner sans changement. (https://github.com/ClickHouse/clickhouse-java/pull/2865)

    • [jdbc-v2] Ajout de la prise en charge du mappage personnalisé pour les types JDBC. Principalement utilisé dans les cas où les grands entiers doivent être présenté sous forme de chaîne. Utilisez DriverProperties.JDBC_TYPE_MAPPINGS (jdbc_type_mappings) et définissez le mappage de type nécessaire comme liste key=value[,] (par exemple, Int32=Long,UInt64=String). Avis de dépréciation : la propriété V1 typeMappings est pris en charge mais sera supprimé. Veuillez migrer vers la nouvelle propriété. (https://github.com/ClickHouse/clickhouse-java/issues/2858)

Améliorations

  • [jdbc-v2, client-v2] Ajout de la prise en charge des noms d'hôtes contenant un trait de soulignement (_). Il est désormais possible de spécifier le point de terminaison comme ch_db_01. Ceci est principalement utilisé dans l'environnement K8. (https://github.com/ClickHouse/clickhouse-java/issues/2792, https://github.com/ClickHouse/clickhouse-java/issues/2753)

Dépendances mises à jour

  • [tests] Bump org.postgresql:postgresql de 42.6.1 à 42.7.11

Documents et exemples

  • [client-v2] Ajout d'un exemple de travail avec la bibliothèque Apache Arrow à l'aide de client. (https://github.com/ClickHouse/clickhouse-java/pull/2820)

  • [repo] Ajout d'un guide de contribution. Veuillez examiner et nous envoyer vos commentaires. (https://github.com/ClickHouse/clickhouse-java/pull/2859)

Corrections de bugs

  • [jdbc-v2, client-v2] Correction de la gestion des erreurs pour les réponses qui ne sont pas une erreur ClickHouse, comme la réponse 404. (https://github.com/ClickHouse/clickhouse-java/issues/2803)

  • [jdbc-v2, client-v2] Correction du paramètre null comme mot de passe. Auparavant, il était converti en littéral null. Nous recommandons quand même passer une chaîne vide. (https://github.com/ClickHouse/clickhouse-java/pull/2809)

  • [jdbc-v2, client-v2] Correction de ClickHouseBinaryFormatReader::getBigDecimal tronquant silencieusement les grands entiers. (https://github.com/ClickHouse/clickhouse-java/issues/2748)

  • [jdbc-v2, client-v2] Correction de la gestion des valeurs NULL dans les colonnes Variant et Dynamic. Indicateur précédent du NULL n’a pas été défini ni lu. (https://github.com/ClickHouse/clickhouse-java/issues/2789,https://github.com/ClickHouse/clickhouse-java/issues/2791)

  • [jdbc-v2] Correction de Statement.cancel() lançant SESSION_IS_LOCKED lorsque l'instruction était exécutée dans un Séance ClickHouse. Le conducteur accepte désormais les session_id, session_check et session_timeout en première classe propriétés de connexion et les supprime correctement lors de l'émission d'un KILL QUERY lors de l'annulation. Cela garantit la la demande d'annulation s'exécute en dehors de la session et n'entre plus en conflit avec la requête en cours d'exécution pour la session verrouiller. (https://github.com/ClickHouse/clickhouse-java/issues/2690,https://github.com/ClickHouse/clickhouse-java/issues/2881)

  • [jdbc-v2] Option ajoutée pour spécifier le nom du cluster pour les opérations sur le cluster. L'un d'eux est KILL QUERY .. ON CLUSTER <cluster_name>. Utilisez DriverProperties.CLUSTER_NAME (jdbc_cluster_name) pour définir le nom du cluster à utiliser dans de telles requêtes. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [jdbc-v2, client-v2] Correction de l'écriture d'un marqueur nullable pour les valeurs imbriquées Tuple et `Map. (https://github.com/ClickHouse/clickhouse-java/issues/2721)
