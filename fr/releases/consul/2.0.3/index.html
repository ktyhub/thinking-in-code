#consul v2.0.3

2.0.3 (7 août 2026)

SÉCURITÉ :

  • Mettez à jour brace-expansion pour adresser GHSA-rgw5-rvv9-x895 (DoS via des tableaux intermédiaires illimités). [GH-23786]
  • Mettez à jour fast-uri pour adresser GHSA-7p8r-x3mc-p8w7 (Confusion de l'hôte via l'introducteur d'autorité de barre oblique inverse). [GH-23786]
  • Mettez à jour golang.org/x/text vers v0.39.0 pour adresser GO-2026-5970. [GH-23761]
  • Mettez à jour google.golang.org/grpc vers v1.82.1 pour adresser GHSA-hrxh-6v49-42gf. [GH-23761]
  • Mettez à jour socket.io-parser pour adresser CVE-2026-69185 (épuisement de la mémoire sans pièce jointe). [GH-23786]
  • Mise à niveau pour utiliser Go 1.26.5. Cela résout les vulnérabilités GO-2026-4970 (os). GO-2026-5856 (crypto/tls). [GH-23761]
  • agent : Correction d'une vulnérabilité de déni de service où GET /v1/agent/connect/ca/roots et POST /v1/agent/connect/authorize a utilisé le cache côté agent sans condition, même lorsque http_config { use_cache = false } a été configuré par l'opérateur. Un appelant distant pourrait contourner ce paramètre et augmenter le cache de l'agent sans contrainte en faisant varier la demande Jeton ACL. Les deux points de terminaison ignorent désormais le cache et émettent un RPC direct lorsque use_cache est désactivé. (SECVULN-50292, SECVULN-50293) [GH-23797]
  • agent : Correction d'une panique de déréférencement de pointeur nul dans ShadowServiceRouterConfigEntry.CheckEnt lorsqu'une entrée de configuration de routeur de service contenait une route avec un Destination nul. Un fabriqué Un message de restauration ou de réplication d'instantané contenant une telle entrée pourrait faire planter le FSM chemin de décodage. La garde nulle traite désormais une destination manquante comme des données non-entreprise et continue le décodage en toute sécurité. (SECVULN-50291) [GH-23797]
  • agent : Correction d'un contournement de sécurité où un auditeur public fourni par l'utilisateur (envoy_public_listener_json) avec un filtre HTTP Connection Manager ignorerait le Consul valeurs par défaut de normalisation des demandes entrantes. Un attaquant pourrait exploiter le chemin non normalisé pour contourner les règles deny d'intention L7 en utilisant des équivalents de chemin codés en pourcentage. Consul maintenant injecte la normalisation du chemin (activée par défaut, sauf si l'option de configuration du maillage InsecureDisablePathNormalization est défini) sur chaque chaîne de filtres HCM dans le format fourni par l'utilisateur auditeurs publics avant que l’application de l’intention L7 ne soit appliquée. (SECVULN-50295) [GH-23797]
  • agent : correction d'une vulnérabilité de déni de service non authentifié où PUT /v1/agent/check/update/:id, PUT /v1/agent/check/register, PUT /v1/agent/service/register et POST /v1/agent/connect/authorize décodé les corps de requête JSON illimités avant de résoudre l'ACL de l'appelant jeton. Un appelant non authentifié pourrait conserver plusieurs grands décodeurs JSON tampons simultanément dans le processus Consul avant que chaque demande ne soit rejeté avec HTTP 403, provoquant une croissance du tas contrôlée par l'attaquant. Tous les quatre les points de terminaison limitent désormais le corps de la requête à 512 Ko avant tout décodage, renvoyant HTTP 413 pour les corps surdimensionnés. Cette limite s'applique aux fragments transfert encodage ainsi que déclaré Content-Length. (SECVULN-50418) [GH-23796]
  • agent : correction d'une vulnérabilité de déni de service non authentifié où le gRPC externe et les auditeurs gRPC-TLS ont accepté un nombre illimité de connexions TCP par IP source avant qu'un traitement de demande, une vérification d'ACL ou une limitation de débit ne puissent avoir lieu. Un attaquant distant pourrait épuiser les descripteurs de fichiers d'agent, les goroutines et la mémoire en ouvrant de nombreuses connexions et en refusant la poignée de main gRPC ou TLS. Un nouveau limiteur de connexion par client-IP est désormais disponible appliqué avant que le serveur gRPC n'observe la connexion, contrôlée par le nouveau Option de configuration limits.grpc_max_conns_per_client (par défaut 100). La poignée de main du gRPC le délai d'attente a également été réduit de la valeur par défaut de la bibliothèque de 120 secondes à 20 secondes. (SECVULN-50294) [GH-23797]

AMÉLIORATIONS :

  • ui : migrer les tests d'acceptation yadda/Gherkin vers QUnit natif (harnais, intentions/création, composants, paramètres) [GH-23741]
  • xds : ajoutez deux nouvelles clés opt-in ProxyDefaults.spec.config pour contrôler l'en-tête de réponse server sur les écouteurs HTTP de la passerelle API : envoy_suppress_envoy_headers (supprime entièrement l'en-tête) et envoy_server_header_name (le renomme avec une valeur personnalisée). Si les deux sont définis, la suppression est prioritaire. [GH-13027]

CORRECTIONS DE BOGUES :

  • agent : Arrêtez de consigner le jeton ACL brut dans les journaux de type de contenu au niveau du débogage. [GH-23731]
  • Passerelle api : correction d'une régression qui entraînait le rejet par une passerelle HTTP API de sa configuration avec une erreur de « protocoles incohérents » (entraînant des 503 intermittents) lorsque le service-router d'un service backend composait une route vers une destination dans un service, un espace de noms ou une partition différent lors de la synthèse de la chaîne de découverte. [GH-23793]
  • serf : correction de la jonction WAN pour ignorer les membres de destination non vivants (départ/gauche/échec), permettant aux serveurs rejoints de revenir à la vie dans l'adhésion au WAN. [GH-23709]
  • xds : ajout d'en-têtes XFCC à la requête GPRC similaire à la requête HTTP pour l'écouteur entrant du proxy de connexion [GH-23744]
