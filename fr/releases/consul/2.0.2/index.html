#consul v2.0.2

2.0.2 (8 juillet 2026)

SÉCURITÉ :

  • Mettez à niveau la version de l'image de base alpine vers 3.24 pour répondre à [CVE-2026-41989], [ALPINE-CVE-2026-2100]. [GH-23711]
  • Dépendance : mettez à niveau Serf et Memberlist pour utiliser les dernières versions. [GH-23704]
  • xds : renvoie des erreurs lors de l'injection du filtre d'intention L4 (RBAC) ou du socket de transport mTLS sur un écouteur public entrant, afin que l'écouteur ne soit pas servi sans application d'intention ou mTLS. [GH-23686]

CARACTÉRISTIQUES :

  • config-entry (api-gateway) : (Enterprise uniquement) Ajoutez ExtAuthzFilter aux filtres HTTPRoute et basculez ExtAuthz à l'échelle de la passerelle vers l'entrée de configuration de la passerelle api [GH-23703]
  • entrée de configuration : (Entreprise uniquement) Ajout du processeur externe (ext_proc) Prise en charge de l'extension Envoy à la passerelle api et au proxy de connexion [GH-23705]

AMÉLIORATIONS :

  • ci : mettez à niveau les actions GitHub qui utilisaient le runtime obsolète Node 20 vers Node 24 et restaurez GOTOOLCHAIN=auto après la configuration-go afin que les pistes de test de compatibilité ascendante et d'intégration résolvent la chaîne d'outils Go correcte. [GH-23687]
  • Connect : mise à jour de la prise en charge des versions Nomad et Vault vers v2.0.3 [GH-23624]
  • deps : migrez armon/go-metrics vers hashicorp/go-metrics et mettez à jour les dépendances Go dans tous les modules [GH-23635]

CORRECTIONS DE BOGUES :

  • xds : n'émet le bloc SDS de certificat client que lorsque CertFile et KeyFile sont définis. [GH-23679]

PROBLEMES CONNUS :

  • consul-k8s : dans les configurations utilisant la version consul OSS, consul-k8s-connect-injector ne parvient pas à apparaître en raison d'un CRD RouteExtProc manquant. Une nouvelle version (2.0.2-oss) du tableau de bord du consul est publiée pour résoudre ce problème. Utilisez la version graphique '2.0.2-oss' pour la distribution OSS du consul de cette version v2.0.2.
  • consul (entreprise uniquement) : depuis (2.0.0) API-GW comprend le routage du trafic via les configurations de chaîne de découverte (résolveurs, routeurs, séparateurs) attachées aux services dans ses destinations de correspondance d'itinéraire. Les passerelles API comprennent les auditeurs sur la base d'un nom d'hôte et compilent des règles globales de routage du trafic pour les services pointés dans les routes pour ces auditeurs. Un bogue est apparu lorsque le service de destination a défini des basculements/redirections/sous-ensembles avec des cibles dans différents espaces de noms/partitions dans la configuration de ses résolveurs. Le rapprochement de la chaîne de découverte globale pour toutes les cibles routables de la passerelle api après cette fonctionnalité rencontre des problèmes en raison de l'absence de valeurs par défaut synthétiques pour les protocoles dans ledit cas d'utilisation et entraîne des problèmes de rendu xds.
