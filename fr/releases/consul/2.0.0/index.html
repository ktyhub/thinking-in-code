#consul v2.0.0

2.0.0 (22 mai 2026)

SÉCURITÉ :

  • Connect : Mettez à niveau la version Envoy vers 1.37.2 et les versions plus récentes [GH-23469]
  • aller : mettre à niveau la version aller vers 1.26 [GH-23493]
  • agent : augmentation des délais d'attente par défaut du serveur HTTP pour éviter d'interrompre les requêtes de blocage d'interrogations longues. read_timeout et write_timeout sont désormais réglés sur 15 minutes (au lieu de 30 secondes), tandis que read_header_timeout (10 s) et idle_timeout (120 s) offrent toujours une protection contre les attaques Slowloris. Tous les timeouts restent configurables via le bloc http_config. [GH-23267]
  • Passerelle api, passerelle de terminaison : appliquer la normalisation du chemin de requête HTTP sur la passerelle api et les écouteurs HTTP de la passerelle de terminaison pour empêcher le contournement RBAC d'intention L7 via des chemins non normalisés (CVE-2024-10005). [GH-23534]
  • docker : mettez à jour l'image de base d'Ubi vers ubi9-minimal:9.7. [GH-23553]
  • docker : mise à niveau de curl vers >= 8.20.0 depuis Alpine Edge dans l'image du conteneur vers l'adresse CVE-2026-6429, CVE-2026-4873, CVE-2026-5773, CVE-2026-6253, CVE-2026-6276, CVE-2026-7168, CVE-2026-5545. Alpine 3.23 stable ne propose pas encore la version corrigée. [GH-23750]
  • docker : mise à jour de l'image de base UBI vers 9.8 pour corriger [CVE_2026-2100] [GH-23588]

CARACTÉRISTIQUES :

  • (Entreprise uniquement) mise à jour vers go-licensing/v4 et go-census/v3 afin de s'adapter aux nouvelles licences de PAO.
  • Global Rate Limiter : (Entreprise uniquement) un nouveau type d'entrée de configuration « limite de débit » qui permet une limitation de débit RPC dynamique à l'échelle du cluster, stockée dans Raft et automatiquement répliquée sur tous les serveurs. Cela permet aux opérateurs d'appliquer ou d'ajuster les limites de débit globales au moment de l'exécution sans redémarrer les serveurs Consul — une capacité essentielle pour les scénarios d'urgence où le cluster est soumis à une charge excessive.
  • api-gateway : ajout de la prise en charge des certificats SDS pour les écouteurs de passerelle API, y compris les certificats TLS par défaut au niveau de l'écouteur et les remplacements TLS SDS du service de routage HTTP/TCP. Les remplacements de service héritent du cluster SDS d'écoute lorsqu'ils sont omis, et la validation de passerelle/la génération xDS rejette désormais les mappages de remplacement conflictuels pour que la sélection de certificat reste déterministe. [GH-23354]
  • Passerelle api : ajoute la prise en charge des limites en amont par défaut au niveau de la passerelle et achemine les remplacements de limites au niveau du service pour MaxConnections, MaxPendingRequests et MaxConcurrentRequests. [GH-23396]
  • api : ajout du nouveau API "/v1/internal/rpc/methods" qui répertorie tous les noms de méthodes RPC. Nécessite un opérateur : lire le jeton ACL. Ceci est utile lorsque les utilisateurs souhaitent configurer des limites de débit qui excluent des points de terminaison RPC spécifiques. [GH-23329]
  • ca : (Entreprise uniquement) Ajout d'un nouveau fournisseur Connect CA pour Cyberark WIM (connect.ca_provider = "pan-distributed-issuer"), permettant à Consul d'émettre des certificats via Cyberark WIM.
  • serveur : (Entreprise uniquement) ajoute une identité de cluster stable et une synchronisation de registre globale contrôlée par le leader pour la publication du résumé du service.
  • télémétrie : (Entreprise uniquement) Télémétrie du produit pour Consul autogéré avec rapports d'utilisation anonymes et facultatifs.
  • mesh : (Entreprise uniquement) Introduisez la prise en charge des services multiports (port nommé) dans Consul, y compris la possibilité de spécifier et d'acheminer le trafic à l'aide de noms de port, ainsi que de récupérer des adresses IP virtuelles pour des ports de service spécifiques. Il impose également que certaines fonctionnalités multiports avancées ne soient disponibles que dans Consul Enterprise et inclut de nouvelles fonctions utilitaires pour la dénomination de cluster et la génération de protocole ALPN.

AMÉLIORATIONS :

  • agent : (Entreprise uniquement) Ajoutez un cache d'arrière-plan finalement cohérent pour les métriques d'utilisation de l'entreprise, réduisant ainsi la latence GET /v1/operator/usage de O(PNK) à O(1) et réduisant la pression CPU/mémoire pendant le scraping haute fréquence via une routine de maintenance pilotée par la surveillance.
  • mesh : (Entreprise uniquement) Introduisez la prise en charge des services multiports (port nommé) dans Consul, y compris la possibilité de spécifier et d'acheminer le trafic à l'aide de noms de port, ainsi que de récupérer des adresses IP virtuelles pour des ports de service spécifiques. Il impose également que certaines fonctionnalités multiports avancées ne soient disponibles que dans Consul Enterprise et inclut de nouvelles fonctions utilitaires pour la dénomination de cluster et la génération de protocole ALPN.
  • passerelle de terminaison : mise à jour du tls en amont du cluster pour utiliser sds au lieu de certificats statiques, permettant des mises à jour dynamiques des certificats sans avoir besoin de redémarrer la passerelle de terminaison. [GH-23288]
  • télémétrie : ajoutez une surveillance de l'expiration des certificats avec des métriques Prometheus (étiquetées avec centre de données/partition/espace de noms), une journalisation structurée avec des seuils de gravité configurables et une Connect CA API améliorée pour inclure le champ NotAfter pour les certificats racine et intermédiaires. [GH-23147]
  • deps : Mettez à niveau github.com/hashicorp/vault/sdk de v0.7.0 vers v0.25.1 et github.com/hashicorp/vault/api de v1.12.2 vers v1.16.0. [GH-23574]
  • test-integ : mise à niveau de testcontainers-go (v0.22.0->v0.40.0) et docker/docker (v24.0.5->v28.5.1) dans le module de test d'intégration. Cela supprime opencontainers/runc en tant que dépendance Go du framework de test. Il s'agit uniquement de dépendances d'infrastructure de test et n'ont aucun impact sur le binaire consul ou sur tout déploiement de consul. [GH-23573]
  • xds : ajoutez les champs Consecutive5xx, ConsecutiveGatewayFailure et EnforcingConsecutiveGatewayFailure à PassiveHealthCheck, permettant aux opérateurs de configurer les seuils de détection des valeurs aberrantes d'Envoy pour les réponses 5xx et les échecs de passerelle (502/503/504) sur les valeurs par défaut en amont.

CORRECTIONS DE BOGUES :

  • Journalisation d'audit : (Entreprise uniquement) Correction de l'erreur de démarchage JSON lorsqu'un tableau d'objets est transmis pour le corps auditReq.
  • cli : messages d'erreur améliorés dans la commande consul config write pour fournir des conseils pratiques lorsque les entrées de configuration ne peuvent pas être modifiées en raison de références par des passerelles ou des routeurs. [GH-22921]
  • xds : correction du package XDS pour générer des points de terminaison et des configurations de cluster corrects pour les passerelles API lors de l'appairage, et mise à jour du gestionnaire de mise à jour de la passerelle API pour propager la configuration de la passerelle maillée à ses amonts. [GH-23454]
  • XDS : corrige le problème avec la passerelle maillée en mode distant sur AWS EKS, car les noms d'hôte DNS sont attribués aux AWS NLB au lieu des IP et la validation du point de terminaison EDS de l'envoyé s'attend à ce que l'adresse soit une IP. Désormais, l'attribution de charge EDS est ignorée pour les cibles de passerelle maillée distante non homologues, les passerelles basées sur le nom d'hôte gardant CDS/EDS synchronisés. [GH-23543]
  • Passerelle api : résolvez les sous-ensembles de services pour les routes lors de la synthèse de la chaîne de découverte de la passerelle API. [GH-23294]
  • ui : correction des liens de documentation brisés [GH-23578]
