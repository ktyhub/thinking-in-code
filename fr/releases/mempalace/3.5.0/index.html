mempalace v3.5.0

v3.5.0 — démon d'écriture local, transport HTTP opt-in et outils de nettoyage de palais

Ce cycle ajoute deux nouvelles façons d'exécuter le chemin d'écriture de MemPalace et un ensemble d'outils pour garder un palais propre. Un démon local opt-in sérialise les mines d'arrière-plan, les sauvegardes du journal et les acquisitions de hooks via un seul processus au lieu de se précipiter pour le handle du palais, et un transport HTTP opt-in permet au serveur MCP de fonctionner derrière un HTTP client/proxy de longue durée - bouclage par défaut, avec une garde de réinitialisation DNS hôte/origine et un jeton de support facultatif. Trois nouveaux outils MCP débarquent à côté : mempalace_checkpoint (regrouper une session entière en une seule sauvegarde), mempalace_delete_by_source (purger chirurgicalement la contamination de référence/d'évaluation extraite - tiroirs et leurs entrées d'index) et un filtre source_file pour la recherche ciblée. De nouveaux analyseurs de transcription (Continue.dev, Gemini CLI, Pi) et une couverture des mineurs pour C#/PHP/Swift/Kotlin/Java élargissent ce que vous pouvez exploiter, et un lot de correctifs de performances et de fiabilité de grande envergure complètent la version.

Fonctionnalités

  • Démon local d'activation pour les écritures en file d'attente. mempalace daemon sérialise toutes les écritures du palais via un processus local afin que le travail en arrière-plan arrête de parcourir le handle du palais. Opt-in et local uniquement. (#1826)
  • Transport HTTP opt-in pour le serveur MCP. mempalace-mcp --transport http sert JSON-RPC sur POST /mcp (avec GET /healthz) pour les déploiements proxy/de longue durée. stdio reste la valeur par défaut ; le chemin HTTP lie 127.0.0.1, épingle Host et rejette Origin sans bouclage (garde de reliure DNS) et prend en charge un jeton de support MEMPALACE_MCP_HTTP_TOKEN facultatif. (#1801, #1806)
  • Outil de sauvegarde par lots mempalace_checkpoint. Classe plusieurs appels add_drawer ainsi qu'une entrée de journal facultative en un seul aller-retour MCP, textuellement, en réutilisant le chemin d'ajout/de suppression idempotent. (#1851)
  • Outil de nettoyage en masse mempalace_delete_by_source. Correspondance exacte et suppression par défaut de chaque tiroir et de ses entrées d'index placard/AAAK pour un source_file — le recours lorsque les fichiers de référence/d'évaluation sont extraits dans une véritable aile. L'essai à sec indique le rayon de l'explosion ; le commit écrit une entrée d'audit WAL. (#1722, #1729)
  • Filtre source_file en option pour mempalace_search. Portez une recherche sur un chemin stocké exact ; enfilé dans chaque chemin de recherche afin de ne jamais abandonner silencieusement une correspondance. (#1815, #1817)
  • Nouveaux analyseurs de transcription — Sessions Continue.dev (#731), Gemini CLI / AI Studio (#204) et agent Pi JSONL (#169).
  • Couverture plus large du langage mineur — C#/.NET, PHP (#1819), Swift/Kotlin (#1368) et détection de projets Java, y compris. sous-projets sans racines (#1720).
  • Dernier mien sur le plugin Claude SessionEnd pour que les derniers échanges soient capturés à la clôture de la session. (#1814, #1820)

Performances

  • Présentation/statut et réponse graph_stats à partir de l'agrégat SQLite — corrige les délais d'attente des grands palais. (#1748, #1379)
  • L'intégration limite les threads intra-op d'exécution ONNX afin qu'une mine en arrière-plan n'épingle plus chaque cœur. (#1068)
  • Pagination pushdown SQL pour sqlite_exact (#1842) et pgvector (#1840), plus métadonnées groupées à défilement unique pour Qdrant (#1832).

Corrections de bugs

  • pgvector tolère les octets de transcription hostiles — un seul substitut (#1833) ou un octet NUL (#1829) n'abandonne plus la mine entière.
  • Points de récupération à index divergé sur repair --mode from-sqlite, pas une re-mine — la re-mine a supprimé silencieusement les tiroirs et les entrées de journal ajoutés par MCP. (#1843, #1847, #1849)
  • Les divergences ChromaDB HNSW obsolètes conduisent au repli SQLite au lieu d'échouer la lecture. (#1816, #1822)
  • Le serveur MCP refuse un deuxième rédacteur pour le même palais plutôt que de faire la course avec le pseudo HNSW. (#1818, #1823)
  • Le mineur de hook Windows apparaît avec CREATE_NO_WINDOW — pas de flash de console. (#1783, #1848)
  • URI SQLite en lecture seule codés en pourcentage afin que les chemins du palais espacés/à caractères spéciaux soient ouverts. ###CI
  • test-windows réessaye uniquement le flocon de compactage transitoire ChromaDB HNSW (--only-rerun) ; Linux/macOS ne conservent aucune réexécution afin que les vraies régressions restent fortes. (#1854) Un grand merci à tous ceux qui ont contribué à ce cycle : bon nombre de ces fonctionnalités et correctifs proviennent de la communauté, y compris plusieurs nouveaux contributeurs. Tout le monde est crédité ci-dessous.
