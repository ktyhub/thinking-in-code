mempalace v3.3.0

Visitez mempalaceofficial.com pour l'histoire complète de cette version et un guide visuel de l'architecture.

Faits saillants

Les placards sont ici

L’architecture que nous avons conçue – ailes, pièces, placards, tiroirs – est enfin terminée. Les placards constituent la couche d'index consultable : des pointeurs AAAK compacts qui indiquent au chercheur quel tiroir ouvrir. La recherche atteint d'abord les placards (rapidement), puis hydrate l'intégralité du contenu textuel des tiroirs. Les placards sont un signal d'appoint, pas une porte : la recherche directe des tiroirs s'effectue toujours comme le sol. Les placards ne peuvent qu’améliorer les résultats, ne jamais les cacher.

  • R@1 : 0.42 → 0.58 (+38%) avec placards regex
  • R@5 : verrouillé à 1.00 — pas de régression
  • Les placards LLM en option (apportez votre propre point de terminaison) poussent R@1 vers 0.67

Recherche hybride BM25

La recherche combine désormais la similarité vectorielle (60 %) avec la correspondance de mots clés BM25 (40 %). Récupère les noms exacts, les codes de projet et les messages d'erreur manqués par les intégrations. Véritable Okapi-BM25 avec Lucene IDF, pas un espace réservé.

8 langues

MemPalace parle anglais, français, coréen, japonais, espagnol, allemand, chinois simplifié et chinois traditionnel. Sortie CLI, instructions de compression AAAK et modèles d'expression régulière tous localisés. Ajoutez une langue en traduisant un fichier JSON.

Halls — routage du type de contenu

Les tiroirs sont désormais étiquetés par type de contenu : technique, émotions, famille, mémoire, créatif, identité, conscience. Les halls relient les pièces d'une aile en fonction du TYPE de contenu qu'elles contiennent : recherchez "moments émotionnels dans mon projet" et obtenez exactement ceux-là.

Sécurité multi-agents

Le verrouillage au niveau des fichiers empêche les agents simultanés de créer des tiroirs en double. Le cycle suppression+insertion est désormais atomique : deux agents exploitant le même fichier ne peuvent pas s'entrelacer.

Tunnels transversaux

Les agents peuvent créer des liens explicites entre les projets. "Cette conception API dans project_api concerne le schéma de base de données dans project_database." Quatre nouveaux outils MCP : créer, lister, supprimer, suivre les tunnels.

Contexte Tout

Les hooks de sauvegarde ne demandent plus à l'agent d'écrire dans le chat. Les conversations sont automatiquement extraites de la transcription — aucune configuration n'est nécessaire. Zéro jeton dépensé en comptabilité.

Quoi de neuf (depuis v3.1.0)

Nouvelles fonctionnalités

  • Couche de placard : index consultable pointant vers les tiroirs
  • Recherche hybride BM25 — mot-clé + vecteur combinés
  • i18n — 8 langues avec des modèles d'expression régulière par langue
  • Ingestion du journal : tiroirs journaliers, un par jour, ajoutés au fur et à mesure que la journée avance
  • Tunnels transversaux - liens explicites de projet à projet
  • Détection de salle - routage du type de contenu (7 types de salle)
  • Métadonnées d'entité – noms estampillés sur les tiroirs et les placards
  • Vérificateur de faits : vérifiez le texte par rapport au registre d'entités + graphique de connaissances
  • Régénération du placard LLM — point final à apporter (Haiku, Gemma, n'importe quel modèle)
  • Drawer-grep — la recherche renvoie le morceau + les voisins qui correspondent le mieux, pas le fichier entier
  • Couture arrière pour un stockage enfichable (#413)
  • mempalace migrate — récupère les palais dans les versions de ChromaDB (#502)
  • Nouveaux outils MCP : tiroir CRUD, gestion des tunnels, paramètres de hook, export (29 outils au total)
  • La sauvegarde automatique utilise le chemin de transcription - aucune variable d'environnement n'est nécessaire
