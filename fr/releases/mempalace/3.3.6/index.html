mempalace v3.3.6

3.3.6 est une version de fonctionnalités. L'œuvre phare du cycle : le rappel multilingue par défaut (l'intégration de gemma remplace MiniLM, les sauts de cosinus multilingues de 0.35 → 0.88), la première coupe du graphe de mémoire vivante (couloirs dans les ailes, tunnels à travers les ailes, potentialisation hebbienne + décroissance d'Ebbinghaus pour que les connexions se renforcent avec l'utilisation et s'estompent sans), l'exploration de documents de bureau (PDF, DOCX, PPTX, XLSX, RTF, EPUB via le nouveau --mode extract), des numéros de ligne virtuels + des pointeurs de cabinet chirurgical qui citent des plages de lignes exactes à des dates exactes, et la passe de nettoyage de détection d'entité qui garde le "Code" hors de vos couloirs et le "Claude Code" atomique. Les promesses n'ont pas bougé. Chaque mot stocké exactement. Tout reste sur votre machine. Pas de télémétrie. Chaque version affine ce qui existe déjà.

Fonctionnalités

  • Exploration de documents Office via --mode extract. Le nouveau mempalace mine <dir> --mode extract ingère les livres PDF, Word (.docx), PowerPoint (.pptx), Excel (.xlsx), RTF et EPUB en plus du chemin de code source/texte existant. Installer avec pip install mempalace[extract] — extrait striprtf pour RTF et MarkItDown (avec sous-extras [docx,pdf,pptx,xlsx]) pour les formats binaires. Les utilisateurs de Python 3.9 bénéficient d'une couverture RTF uniquement car MarkItDown nécessite 3.10+. Les tiroirs du chemin d'extraction contiennent des métadonnées extract_mode, de sorte que le mineur de convo "déjà extrait ?" la génération de chèques et d'identifiants de tiroir reste isolée par mode (#1528). (#1555)
  • Numéros de ligne virtuels + pointeurs de placard chirurgical. Les tiroirs stockés portent désormais des numéros de ligne virtuels afin que le verbe CLI lu et les pointeurs de placard puissent citer des plages de lignes exactes. Les pointeurs de placard (niveau 6a) incluent des informations de date et de plage de lignes dérivées de l'analyse du nom de fichier et de la date du corps du contenu (python-dateutil est désormais une application principale), afin que MemPalace puisse vous indiquer des lignes exactes à des dates exactes plutôt que simplement "quelque part dans ce tiroir". (#1555, #1584)
  • Couloirs à l'intérieur de l'aile. Lorsque deux entités (personnes, projets, sujets) coexistent dans le même tiroir, le mineur enregistre désormais un « couloir » — un bord graphique les reliant à l'intérieur de cette aile. Calculé automatiquement dans le cadre de l'étape post-mine dans compute_hallways_for_wing afin que le graphique grandisse progressivement avec le nouveau contenu, sans commande distincte. Fondation pour la navigation entre les entités à travers les pièces à l’intérieur d’un palais. (#1558, #1560)
  • Tunnels transversaux promus à partir des couloirs. Lorsque la même entité apparaît dans les couloirs de plusieurs ailes, MemPalace la promeut désormais automatiquement dans un tunnel - permettant aux requêtes de passer de l'aile d'une personne à l'aile du projet dans laquelle elle apparaît, sans que personne n'appelle manuellement create_tunnel. Les tunnels thématiques du chemin compute_topic_tunnels existant restent inchangés. (#1565)
  • Dynamique de la mémoire vivante (potentialisation hebbienne + désintégration d'Ebbinghaus). Les couloirs et les tunnels se renforcent à chaque fois que la même connexion est renforcée par un nouveau contenu ("ce qui s'allume ensemble se connecte") et s'estompent progressivement si une connexion cesse d'apparaître dans les tiroirs entrants. Les poids de navigation suivent l'utilisation réelle du palais au lieu d'être statiques, de sorte que le classement de récupération s'améliore au fil du temps à mesure que le palais est réellement utilisé. (#1578)
  • Les transcriptions de l'outil API sont automatiquement acheminées vers wing_api. Les transcriptions de conversation des outils d'IA de style API (Claude Code, Claude.ai, ChatGPT, exportations Slack-bot, forme générique OpenAI JSON, etc.) sont désormais acheminées vers un wing_api dédié au lieu de se mélanger aux ailes de conversation humaine. Empêche le trafic d'appels d'outils de polluer les ailes personnelles/projets et améliore la précision de la recherche lorsque vous recherchez « qu'est-ce que j'ai dit » par rapport à « qu'est-ce que l'agent a dit ». (#1236)
  • Intégration multilingue par défaut pour les nouvelles installations : embeddinggemma-300m ONNX (q8, MRL→384-dim). L'intégration précédente de MemPalace (all-MiniLM-L6-v2) est formée en anglais uniquement — similarité cosinus interlingue sur les moyennes de texte traduites en parallèle 0.35 à travers DE/FR/HI/IT/KO/RU (RU à 0.17, presque orthogonal). Un utilisateur russophone ne peut effectivement pas retrouver ses propres souvenirs, ce qui rompt la promesse de conception « 100 % de rappel » de CLAUDE.md. La nouvelle classe EmbeddinggemmaONNX dans mempalace/embedding.py amène cela à la moyenne 0.88 (validé sans perte par rapport au gguf Ollama via un test d'exécution ONNX direct). Téléchargements paresseux onnx-community/embeddinggemma-300m-ONNX (~ 300 Mo) lors de la première utilisation via huggingface_hub. La sortie est tronquée à 384 dimensions via Matryoshka Representation Learning, de sorte que le modèle est un ajout aux collections 384 dimensions de ChromaDB — aucun changement de schéma. Le préfixe Sim ("task: sentence similarity | query: ") est appliqué automatiquement. L'intégration (python -m mempalace.onboarding) propose désormais le modèle multilingue par défaut : en le choisissant, vous écrivez embedding_model: embeddinggemma dans config.json afin que les exécutions ultérieures le récupèrent sans nouvelle invite. Les installations existantes qui n'ont jamais défini la variable d'environnement ou exécuté l'intégration restent sur minilm (back-compat). MEMPALACE_EMBEDDING_MODEL=minilm|embeddinggemma remplace les deux. Changer de modèle sur un palais existant nécessite une réintégration – exécutez mempalace repair rebuild-index après le changement. (#1483)
  • Les dépôts multilingues ont été déplacés vers le noyau. huggingface_hub, tokenizers et numpy sont désormais des dépôts obligatoires afin que le chemin multilingue fonctionne immédiatement après pip install mempalace. L'extra [multilingual] est conservé comme alias sans opération pour la rétrocompatibilité avec les scripts d'installation. Le modèle ONNX de 300 Mo lui-même est toujours téléchargé paresseusement lors de la première utilisation, pas au moment de l'installation.
  • Erreur de non-concordance de nom EF ChromaDB plus conviviale. La commutation de MEMPALACE_EMBEDDING_MODEL sur un palais existant sans exécuter rebuild-index faisait auparavant apparaître le Embedding function conflict: new: X vs persisted: Y ValueError nu de ChromaDB - précis mais n'indiquait pas aux utilisateurs comment récupérer. ChromaBackend.get_collection() enveloppe désormais cette erreur et pointe vers les deux options : rétablir la variable d'environnement ou exécuter mempalace repair rebuild-index --palace <path>. (#1483)
  • Bascule hooks.auto_save pour les sessions en mode silencieux. Le nouveau bouton de configuration (et le câblage du drapeau --silent CLI via le crochet de sauvegarde) permet aux utilisateurs de désactiver les sauvegardes automatiques du journal sur Stop / PreCompact. Utile pour les sessions en « mode silencieux » où vous ne souhaitez pas que toutes les conversations soient capturées. Le comportement par défaut est inchangé : la sauvegarde automatique s'exécute toujours à moins qu'elle ne soit explicitement désactivée. (#711)
  • Filtrer les mots de contenu anglais courants à partir de la détection d'entités. Les mots de contenu anglais à haute fréquence ("système", "utilisateur", "mémoire", "projet", "contexte", etc.) étaient étiquetés comme entités par le détecteur par tiroir et polluaient le registre des entités en tant que "personnes". Une liste de mots COCA expédiée (les N premiers mots du contenu) est désormais consultée lors de la classification des entités afin qu'ils soient filtrés avant d'atteindre le registre. Renforcé contre le JSON malformé dans la liste de mots fournie. (#1605)
  • Correspondance d'entités insensibles à la casse au moment de la mine. La construction initiale du palais (mempalace init) correspondait aux noms d'entités sans tenir compte de la casse, mais pas le marqueur par tiroir utilisé lors de l'extraction incrémentielle - donc la même personne a été étiquetée différemment entre init et ingest ("Aya" contre "aya" sont devenus des entités distinctes). Le marqueur incrémentiel reflète désormais le comparateur insensible à la casse, rétablissant la cohérence des balises d'entité tout au long du cycle de vie du palais. (#1557)

Corrections de bugs

  • Perte de données silencieuse dans trois chemins d'upsert. Trois sites d'upsert (ingestion de fichiers, ingestion de conversation et une branche de réparation) appelaient l'intégrateur sur du contenu non fragmenté, tronquant silencieusement à la limite maximale de jetons de l'intégrateur. Les longs tiroirs ont atterri avec uniquement leur section principale indexée, rompant ainsi la promesse du « rappel à 100 % » sur le contenu long. Tous les trois transitent désormais d'abord par le chunker afin que le document complet soit intégré et stocké. (#1540, suite du #1539)
  • Le fragmenteur de paragraphes émettait des morceaux surdimensionnés pour les longs paragraphes. Le séparateur de paragraphes supposait que les paragraphes étaient toujours plus courts que CHUNK_SIZE et les émettait entiers ; de longs paragraphes (texte juridique, rédactions techniques denses) dépassaient silencieusement la fenêtre contextuelle de l'intégrateur. Le séparateur plafonne désormais chaque morceau émis pour honorer CHUNK_SIZE. (#1538, correctifs #1534)
  • Le plafond de fragments par fichier était codé en dur et trop faible pour les transcriptions volumineuses. Une limite de sécurité plafonnait les fragments par fichier à une valeur adaptée au code source ; l’extraction de très grandes transcriptions de conversations a silencieusement laissé tomber la queue au-delà de ce plafond. Désormais configurable, avec la valeur par défaut augmentée pour couvrir des tailles de transcription réalistes. (#1554, correctifs #1455)
  • Sous-processus Hook / blocage ChromaDB sous Windows. Les hooks Stop/PreCompact pourraient se bloquer contre un ChromaDB client déjà ouvert sous Windows, laissant l'hôte (Claude Code) bloqué en attente du crochet. Correctif en trois parties : délai d'expiration du PID périmé lors de la récupération du verrou minier, chemin de sortie inactif dans le serveur MCP et erreurs structurées lorsque le modèle de blocage est détecté afin que l'hôte puisse récupérer. (#1562, correctifs #1552)
  • create_tunnel a corrompu les noms d'ailes avec trait d'union. L'analyseur de point de terminaison s'est divisé sur -, donc les ailes dont le nom contenait un trait d'union (mem-palace, my-app) ont été tronquées au milieu du nom et le tunnel pointait vers un point de terminaison inexistant. L’analyse des points de terminaison préserve désormais le slug complet. (#1529, correctifs #1504)
  • Le cache de graphes de connaissances MCP produisait des graphiques en double pour les chemins de palais liés par un lien symbolique/avec une casse différente. La clé de cache était la chaîne de chemin brute, donc /Users/me/.mempalace/palace et /Users/me/.mempalace/Palace (pliés en casse sur macOS) ou un alias lié symboliquement produisaient deux instances KnowledgeGraph mises en cache distinctes pointant vers le même fichier SQLite, avec un risque de lecture obsolète. Le cache se normalise désormais via realpath + normcase afin qu'ils se replient sur une seule clé canonique. (#1383, correctifs #1372)
  • Noms de dossier de projet avec trait d'union tronqués par crochet de sauvegarde. L'analyseur de nom d'aile se divisait sur - et ne conservait que le premier segment, donc mem-palace est devenu mem. Le correctif préserve le slug complet du dossier de projet afin que les palais avec trait d'union restent cohérents lors des invocations de hook. (#1424, correctifs #1410)
  • Le mineur a ignoré les liens symboliques en silence. Les utilisateurs étaient confus quant aux données manquantes après l'extraction ; le mineur sautait les liens symboliques sans le faire apparaître. Enregistre désormais chaque lien symbolique ignoré avec la raison afin que l'écart soit visible. (#1466, correctifs #1462)
  • Le PYTHONPATH divulgué par l'hôte pourrait masquer les propres modules de MemPalace lors de l'importation. Le package __init__ supprime désormais les entrées divulguées lors de l'importation afin que le MemPalace importé soit toujours celui installé. (#1439, correctifs #1423)
  • Scripts hook macOS stock-bash. Les scripts hook utilisaient mapfile (bash 4+), cassant le stock /bin/bash 3.2 de macOS. Passé à un pipeline sed pour que les hooks fonctionnent immédiatement sur chaque Mac. (#1441, correctifs #1440)
  • Les hooks Plugin Stop/PreCompact pourraient rester indéfiniment bloqués sur un enfant bloqué. Un délai d'attente limité garantit que l'hôte peut toujours progresser même si le processus enfant de MemPalace n'est pas sain. (#1470, correctifs #1465)
  • Les gestionnaires MCP renvoient désormais des erreurs JSON-RPC structurées pour une entrée mal formée. Les noms de paramètres inconnus ont renvoyé -32602 Invalid params au lieu d'un Python non structuré TypeError ; les paramètres de forme incorrecte renvoient une erreur structurée au lieu d'un traçage brut. (#1500, #1513)
  • CLI distinguait "le palais n'existe pas" de "le palais existe mais est vide". Deux états qui se ressemblent pour un nouvel utilisateur sont désormais signalés séparément avec des messages d'étape suivante exploitables pour chacun. (#1532, correctifs #1498)
  • post-pass mempalace repair : VACUUM + reconstruction FTS5. Après une réparation de palais, le fichier Knowledge-Graph SQLite conservait des pages fragmentées et un index FTS5 obsolète ; l'exécution de VACUUM et la reconstruction de FTS5 à la fin récupèrent le disque et restaurent les performances de recherche. (#1523)
  • Isolement du mode mineur Convo. Le message "déjà extrait ?" la vérification et la génération d'identifiants de tiroir ont ignoré extract_mode, donc le changement de mode a soit reminé le même contenu (duplication de données), soit entré en collision les identifiants de tiroir entre les modes. La définition de la portée par mode permet de conserver les tiroirs de chaque mode isolés et de garantir une déduplication correcte. (#1528, correctifs #1505)
  • Validation FTS5 à la fin du mien. L'exploitation minière valide désormais l'intégrité de l'index FTS5 en tant qu'étape ultérieure afin que la corruption soit détectée au moment de l'écriture, et non au moment de la lecture. (#1548, correctifs #1537)
  • hooks_cli s'est écrasé sur des chemins d'installation peu profonds. Code indexé Path.parents[3] en supposant une arborescence d'installation profonde, soulevant IndexError lorsque MemPalace s'exécutait à partir d'un chemin peu profond (par exemple /opt/mp). Ajoute une protection pour que les installations superficielles ne plantent plus lors des commandes hook. (#1585)
  • Quarantaine de segment HNSW : zéro octet ou valeur manquante. Une heuristique de quarantaine antérieure signalait que tout segment HNSW manquant du champ de métadonnées dim était corrompu, mais la plupart étaient récupérables ; le contrôle distingue désormais les segments d'index de travail récupérables et manquants des segments d'index de travail réellement corrompus. Les fichiers de liste de liens de zéro octet (segments partiellement écrits) sont désormais purement et simplement rejetés. (#1452, #1461, correctifs #1457)
  • Fichier support de verrouillage de mine écrit en UTF-8 au lieu de cp1252. Les noms d'utilisateur et chemins d'accès Windows non ASCII ne corrompent plus le fichier de verrouillage et n'interrompent plus la détection des verrous obsolètes. (#1438)
  • La réclamation d'emplacement de mineur écrit désormais immédiatement un PID d'espace réservé. Un crash entre la réclamation et l'écriture du PID ne laisse plus de verrou fantôme. (#1543, correctifs #1443)
  • mine_convos s'exécute désormais dans mine_palace_lock. Deux invocations simultanées de convos mine ne peuvent plus corrompre l'index. (#1477)
  • Nettoyage de l'outil de migration. L'outil de migration de la version ChromaDB ferme désormais sa connexion SQLite et supprime le répertoire temporaire du palais si une exception se déclenche à mi-migration ; les migrations échouées arrêtent les fuites de descripteurs de fichiers et de disque. L'écriture atomique du registre d'entité supprime désormais son side-car .tmp si l'écriture ou le changement de nom échoue. (#1216, #1408, correctifs #1373)
  • L'outil de réparation tolère les cellules de métadonnées vides/Aucune. ChromaDB renvoie occasionnellement des cellules avec des dictionnaires de métadonnées vides ou None lors de la reconstruction ; tous deux sont désormais contraints à des défauts de paiement raisonnables afin que la reconstruction soit terminée et que les palais autrement bloqués se rétablissent. (#1459, #1445, correctifs #1426)
  • Le gestionnaire MCP create_tunnel propage désormais les erreurs. Un mauvais point de terminaison ou une mauvaise direction était avalé et renvoyé comme un succès trompeur ; se propage désormais comme une erreur MCP structurée. (#1546, correctifs #1473)
  • Les tunnels explicites ont été stockés dans un emplacement codé en dur ~/.mempalace/tunnels.json path that ignored MempalaceConfig.palace_path. Drawers, KG triples, the people map, and every other piece of palace state honour the configured palace_path (and the MEMPALACE_PALACE_PATH env var), but palace_graph._TUNNEL_FILE was a module-level constant initialised once from os.path.expanduser("~") + "/.mempalace/tunnels.json". Under any setup where $HOME is isolated from the configured palace — subagent profiles with their own $HOME, sandboxes, multi-tenant hosts, container mounts that move the palace to /srv/ — drawers landed in the configured palace while tunnels silently landed in a different file that no other process touching the same palace could see. Worst case is the agentic one: an isolated worker calls create_tunnel then list_tunnels`ZZPH10 0ZZ`palace_graph._TUNNEL_FILE is replaced by _get_tunnel_file() which derives the path from a new MempalaceConfig.tunnel_file property (sibling of palace_path). The default single-user install is unchanged because the default palace_path is still ~/.mempalace/palace and its sibling tunnels.json is the legacy path. Backwards-compatibility: if the configured tunnel file does not exist but a file is present at the pre-3.3.6 hardcoded ~/.mempalace/tunnels.json path AND the two paths differ, _load_tunnels logs a one-line WARNING nommer les deux chemins et renvoyer une liste vide - nous ne migrons PAS intentionnellement automatiquement, car la fusion silencieuse de l'état du tunnel sur deux emplacements risque d'encombrer les données les plus récentes ; l'utilisateur déplace ou copie lui-même le fichier. (#1467)
  • create_tunnel did not validate that the source and target rooms actually exist in the chroma index. _require_name only checked that wing/room names were non-empty strings; nothing queried the collection to confirm at least one drawer carried matching {wing, room} metadata. Pointing an explicit tunnel at a phantom room — common when an agent fabricates a room name it expects to exist, or types a slug wrong — silently succeeded. Combined with the read-bubble described in the previous fix, an agent could create_tunnel → list_tunnels and have both calls return its own bogus write. create_tunnel now calls _check_room_exists(wing, room, col) for both endpoints before persisting an explicit tunnel; if either endpoint has zero matching drawers the call raises ValueError naming the offending wing/room pair. Three deliberate carve-outs: (1) kind != "explicit" skips validation because topic tunnels generated by compute_topic_tunnels use synthetic topic:<name> room identifiers that don't correspond to real chroma rooms; (2) _get_collection returning None (palace not yet created, transient backend failure, tests without a real chroma backend) skips validation rather than fail-closed — matches the tolerance pattern used everywhere else in palace_graph; (3) exceptions raised by the underlying col.get(where=..., limit=1, include=[]) query are logged and treated as "can't verify, allow" so a temporary index fault never blocks legitimate writes. Behaviour change: existing callers that previously created tunnels pointing at empty rooms (e.g. as scaffolding before mining them) will now raise ValueError. Classez d’abord le tiroir, puis créez le tunnel – c’est l’ordre que la documentation a toujours recommandé. (#1468)

Performances

  • Le mineur Convo récupère l'ensemble miné une fois. Émettait une requête WHERE par fichier pour vérifier "déjà extrait ?" ; pré-récupère désormais l'ensemble complet extrait une fois, réduisant ainsi le temps passé sur les grands corpus de transcription. (#1474)
  • Rappel de progression rebuild_index. Les reconstructions sur plusieurs heures signalent désormais la progression avec l'imprimante ETA par défaut ; les utilisateurs n'ont plus à deviner si le processus progresse. (#1487)
  • Diagnostics de démarrage à froid MCP + préchauffage opt-in. Ajoute une visibilité sur l'intégration en cours de chargement et le temps que cela prend, ainsi qu'un chemin de préchauffage opt-in afin que les utilisateurs puissent voir et résoudre la latence lente de la première requête. (#1530, correctifs #1495)

Interne

  • palace_graph._TUNNEL_FILE (module-level constant) replaced by _get_tunnel_file(config=None) and _legacy_tunnel_file(). Tests previously monkeypatching the constant must now monkeypatch the resolver functions. The tests/test_palace_graph_tunnels.py::_use_tmp_tunnel_file helper, tests/test_closets.py::TestTunnels setup/teardown, and three tests in tests/test_miner.py were updated accordingly. Topic-tunnel tests in test_miner continue to work without stubbing _get_collection because kind="topic" court-circuite le nouveau chemin de validation.
