mempalace v3.3.3

Corrections de bugs

  • Installer la régression — Le script de console mempalace-mcp est désormais déclaré dans pyproject.toml avec la référence de .claude-plugin/plugin.json. Dans v3.3.2, les deux se sont séparés (plugin.json a expédié le nouveau formulaire "command": "mempalace-mcp" avant l'arrivée du point d'entrée correspondant), de sorte que chaque nouveau pip install mempalace==3.3.2 a produit une configuration de plugin Claude Code pointant vers un binaire qui n'était pas installé. (#1093, #340)
  • Restaurer la visibilité de la sauvegarde silencieuse après la régression Claude Code 2.1.114 client — les sauvegardes de transcription de production échouaient silencieusement jusqu'à ce PR. (#1021)
  • Paginez les métadonnées du chemin status afin que les grands palais ne dépassent pas les limites des variables SQLite. (#851)
  • Résoudre le hook runner du plugin Claude à travers les variations de plate-forme/plugin-dir ; auparavant en panne sous Windows et certaines mises en page macOS. (#942)
  • Résolution réelle python3 pour les crochets .sh avec un chemin de remplacement MEMPAL_PYTHON. (#833)
  • Ajoutez le paramètre facultatif wing à tool_diary_write / tool_diary_read et dérivez l'aile par projet à partir du chemin de transcription de Claude Code lors de l'écriture à partir du crochet d'arrêt - les entrées de journal de différents projets ne s'effondrent plus dans une aile par défaut partagée. (#659)
  • Traiter la chaîne vide comme "pas de filtre" dans mempalace_search wing/room ; Les agents LLM qui remplissent par défaut chaque paramètre facultatif avec "" ne sont plus renvoyés avec must be a non-empty string. (#1097, #1084)
  • Élargir _wing_from_transcript_path pour gérer les dossiers de projet Claude Code sans segment -Projects- (par exemple ~/dev/<parent>/<project>, ~/code/<project>). Le nom du projet est désormais dérivé du jeton final séparé par des tirets du dossier codé, de sorte que les utilisateurs Linux avec du code en dehors de ~/Projects/ obtiennent la portée du journal par projet au lieu de passer à wing_sessions. (#1145, suite au #659)
  • mempalace_diary_read(wing="") renvoie désormais les entrées du journal de chaque aile dans laquelle cet agent a écrit, correspondant au modèle #1097 "chaîne vide sans filtre". Auparavant, la valeur par défaut était wing_<agent>, silo les entrées que les hooks écrivaient dans les ailes dérivées du projet. (#1145)
  • mempalace mine ignore désormais le fichier entities.json généré afin que son contenu ne soit pas réingéré en tant que contenu du projet. (#1175)

Améliorations

  • Enregistrements de hook déterministes. Le hook de sauvegarde utilise désormais un chemin silencieux Python API, de sorte que les invocations de hook successives produisent des résultats reproductibles et aucune perte de données sur le chemin actif. (#673)
  • Cache graphique avec invalidation en écriture dans build_graph() — les appels à chemin chaud ne reconstruisent plus le graphe du palais par requête. (#661)
  • Révision de la détection d'entité mempalace init. Les noms de projets canoniques proviennent désormais des manifestes de packages (package.json, pyproject.toml, Cargo.toml, go.mod) et les personnes réelles proviennent des auteurs de commit git, plutôt que d'être déduites de la prose. Inclut la déduplication de recherche d'union sur les alias de nom/e-mail, le filtrage des robots qui conserve les humains @users.noreply.github.com et le marquage automatique des « mines » par partage de contribution. (#1148)
  • Précision du détecteur Regex. Extraction CamelCase afin que MemPalace, ChromaDB, OpenAI ne soient pas fragmentés ; Un modèle versionné/trait d'union plus serré tue les faux positifs context-manager / multi-word ; le dialogue ^NAME:\s nécessite ≥2 hits, donc les métadonnées Created: <date> arrêtent de classer les noms de champs comme personnes ; mots vides étendus pour les participes et descripteurs anglais courants ; le signal à pronom élevé est classé comme personne plutôt que comme incertain. (#1148)
  • Init → connexion du mineur. Les entités confirmées fusionnent dans ~/.mempalace/known_entities.json lors de l'initialisation, que le mineur lit pour baliser les métadonnées du tiroir pour la recherche filtrée par entité. Auparavant, la sortie d'Init n'était pas consommée par le mineur ; le entities.json par projet est conservé comme piste d'audit. (#1157)
  • Déduplication de projet insensible à la casse dans les sources de manifeste, git et convo afin que les variantes de casse du même nom de projet soient réduites à une seule entrée de révision. (#1175)

Ajouté

  • i18n : traduction biélorusse. (#1051)
  • i18n : détection d'entités pour les paramètres régionaux allemand, espagnol et français. (#1001)
  • i18n : Détection d'entités chinoises traditionnelles + simplifiées. (#945)
  • mempalace init --llm : classification facultative des entités assistée par LLM. La valeur par défaut est Ollama local (zéro-API) ; prend également en charge tout point de terminaison compatible OpenAI (LM Studio, serveur llama.cpp, vLLM, OpenRouter, etc.) et Anthropic Messages API. Fonctionne de manière interactive avec un indicateur de progression ; Ctrl-C annule proprement et renvoie des résultats partiels. Utile pour les dossiers lourds en prose où le détecteur d'expressions régulières a du mal (journaux, transcriptions, notes de recherche). Opt-in uniquement : le chemin d'initialisation par défaut reste zéro-API. (#1150)
  • Scanner de conversation Claude Code. Les répertoires ~/.claude/projects/<slug>/ contribuent désormais aux entités de projet en utilisant les métadonnées cwd faisant autorité de chaque session, évitant ainsi l'ambiguïté du décodage slug. (#1150)

Connu – reporté à v3.3.4

  • SIGSEGV à insertion parallèle HNSW lorsque hnsw:num_threads n'est pas défini lors de la création de la collection (#974) — correctif en vol comme #976, en attente de rebase contre le développement.

Installer

pip install --upgrade mempalace==3.3.3
