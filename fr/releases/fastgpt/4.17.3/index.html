Guide de mise à niveau

Modifications de la configuration

  • La version Node.js déployée à partir du code source doit répondre à ^22.23.4 || ^24.22.1 || ^26.12.1. Veuillez confirmer que l'environnement d'exploitation répond à cette plage avant la mise à niveau.
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED est toujours par défaut false ; lorsqu'il est activé, le groupe par défaut composé de tous les membres d'une nouvelle équipe se verra non seulement accorder l'autorisation de créer des applications, des compétences et des bases de connaissances, mais également l'autorisation de création de clé API. Les équipes existantes ne recevront pas automatiquement d'autorisations supplémentaires.
  • La limite supérieure totale des instances actives du bac à sable de l'agent est modifiée pour être configurée via AGENT_SANDBOX_MAX, avec une valeur par défaut de 100. Le quota est partagé entre les sessions d'application et l'édition des compétences ; le AGENT_SANDBOX_MAX_EDIT_DEBUG d'origine n'est plus utilisé. Ajout de AGENT_SANDBOX_MAX_PER_TEAM pour définir la limite supérieure pour une seule équipe. Il n'y a pas de limite par défaut. La configuration des quotas dans la console de gestion des versions commerciales est prioritaire sur les variables d'environnement.
  • OpenSandbox ajoute AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR et AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR, la valeur par défaut est 1 et la valeur ne doit pas être inférieure à 1. Kubernetes 运行态且 OpenSandbox Server 不低于 v0.2.1时生效，降低资源预留但保持资源上限不变，仅影响新建或重建的沙盒。
  • La console de gestion de la version commerciale a ajouté "Nombre maximum simultané de récupérations de vecteurs" (systemEnv.vectorRecallConcurrency), qui permet une configuration de 0 à 1000. La valeur par défaut de 0 signifie aucune limite. Les nombres positifs limitent la simultanéité de rappel partagé de toutes les instances de service et de toutes les bibliothèques de vecteurs ; la version open source n'active pas cette limite et n'a pas de variables d'environnement correspondantes.
  • Ajout de AUXILIARY_GENERATION_SHOW_RUN_DETAIL, false par défaut, pour contrôler si les entrées de détails d'opération générées par les compétences, les agents et l'assistance au workflow sont affichées.
  • MARKETPLACE_URL est un https://v3.marketplace.fastgpt.cn, un https://v3.marketplace.fastgpt.cn, un https://v3.marketplace.fastgpt.cn.

Script de mise à niveau

Le système effectue d'abord les tâches de démarrage nécessaires et sa chaîne de dépendances préalables, puis chaque instance d'application recharge le modèle, puis démarre l'entreprise. Les 3 nouvelles tâches suivantes sont alors automatiquement exécutées en arrière-plan, avec un maximum de 3 quotas simultanés dans le cluster partagé. L'échec ne bloquera pas les tâches non dépendantes ; vous pouvez afficher les résultats sur la page de gestion, réparer les données défaillantes et réessayer.

  • Remplissage de l'affiliation à l'équipe de l'instance sandbox (20261009_backfill_agent_sandbox_team_id) : complétez l'affiliation à l'équipe des instances historiques en fonction des applications sources ou des compétences pour les statistiques de quota d'équipe ; les enregistrements orphelins dont les sources ont été supprimées sont ignorés et comptés.
  • Remplissage des chemins d'ancêtre du répertoire (20261022_backfill_folder_ancestor_ids) : reconstruisez les chemins du répertoire des applications, des outils et de la base de connaissances et nettoyez les champs résiduels des ressources autres que les dossiers. Les dossiers suspendus directement sous d'autres types d'arborescences de répertoires sont déplacés vers le répertoire racine de cette équipe et les anciennes autorisations d'héritage parent sont effacées ; les chemins d'ancêtres entre arbres de niveau supérieur sont tronqués aux limites. Les enregistrements d'exception tels que les parents manquants, les équipes croisées ou les boucles sont conservés comme éléments ayant échoué et seront réessayés après réparation.
  • 迁移系统模型价格至百万单位（20261025_token_prices_per_million）：将历史系统模型价格换算并写入pricing，保留旧字段原值，跳过已有合法 pricing 的模型；团队模型不参与迁移。

Instructions de compatibilité

  • activation root et mot de passe : supprimez DEFAULT_ROOT_PSW, le démarrage n'écrasera plus le mot de passe root existant. Les modifications quotidiennes du mot de passe sont effectuées sur la page d'informations du compte. Lorsque vous oubliez votre mot de passe, utilisez le script de réinitialisation du mot de passe root et fournissez explicitement le nouveau mot de passe.
  • 模型计价单位：LLM 使用 pricing.tiers，其他模型使用 pricing.unitPrice。 Prix unitaire du jeton et échelle maxInputTokens La limite supérieure est modifiée à un million de jetons, le TTS est modifié à un million de caractères, le STT est toujours toutes les 60 secondes et le prix unitaire est maintenu à deux décimales. lieux. Après la mise à niveau, confirmez que la migration en arrière-plan est réussie et vérifiez le prix du modèle du système ; les modèles de système qui n'ont pas été migrés vers pricing sont temporairement traités comme gratuits, et les modèles d'équipe sont gratuits.
  • Vérification de l'orchestration du workflow : le canevas, le débogage et la génération auxiliaire suivent uniformément les [règles d'arrangement] (/guide/build/workflow/rules). Les bouclages série purs, les connexions de processus entre outils et plusieurs nœuds appelants partageant la même entrée d'outil sont interdits, et la redistribution contrôlée par des sorties de conditions valides est autorisée. Les sous-processus de l'outil peuvent lire en amont de l'appelant, mais ne peuvent pas faire référence à une sortie que l'appelant lui-même n'a pas produite. L'ancien flux de travail conserve les connexions existantes et peut enregistrer les brouillons. Les connexions non conformes aux règles doivent être corrigées avant le débogage et la publication.
  • Autorisations de gestion de la base de connaissances : La modification des informations de base de la base de connaissances, de la configuration du modèle et de ses propres attributs tels que les noms de fichiers, les balises, l'état désactivé, etc. nécessite des autorisations gérables (manage) ; les opérations de contenu continuent d'utiliser les autorisations d'édition d'origine. La modification des attributs lors du déplacement d'un fichier nécessite également des autorisations administratives pour le fichier.
  • Exportation de base de connaissances : /api/core/dataset/exportAll ne prend en charge qu'une seule base de connaissances et l'exportation de répertoire doit être demandée base par base ; lorsque les autorisations au niveau des fichiers sont activées, seuls les fichiers lisibles par les membres actuels seront exportés.
  • Type de fichier de conversation : Ajout de document et unknown à la catégorie des pièces jointes ; les anciens paramètres d'entrée et enregistrements historiques du file restent compatibles et sont classés par nom de fichier, lien et informations de réponse. Le client personnalisé doit être compatible avec la nouvelle classification et ne plus utiliser uniquement file pour juger des documents.
  • Paging et réponse d'erreur : La pagination générale traitera pageSize dépassant 500 comme 500, et certaines interfaces ont encore des restrictions plus petites ; lorsque offset et pageNum sont transmis en même temps, offset sera utilisé en premier, y compris offset=0, et les décalages illégaux ne seront pas restaurés aux numéros de page. La requête API identifiée comme une erreur de configuration utilisateur renvoie HTTP 400 et la partie d'accès doit la traiter comme une réponse d'échec.
