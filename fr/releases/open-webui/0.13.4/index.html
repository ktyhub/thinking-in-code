open-webui v0.13.4

Ajouté

  • Apportez votre propre ordinateur avec Tether. Tether transforme votre propre ordinateur en partie d'Open WebUI : les modèles d'Ollama, LM Studio ou de tout serveur compatible OpenAI, les serveurs d'outils OpenAPI et MCP et les serveurs Open Terminal que vous ajoutez dans l'application Tether s'affichent désormais juste pour vous dans le sélecteur de modèle, la liste Outils du menu + et le menu du terminal de tout Open WebUI que vous connectez, quel que soit l'appareil sur lequel vous l'ouvrez, et Open WebUI les atteint via Tether, de sorte que leur les adresses, commandes et touches ne quittent jamais votre ordinateur. Cela nécessite que Tether 0.1.14 ou version ultérieure, ou 0.1.16 pour les serveurs MCP, les serveurs d'outils et les terminaux doivent être activés, et un modèle Tether dont l'ID correspond à un modèle déjà dans Open WebUI reste masqué. Tether remplace les connexions directes. #34397
  • Agents en bac à sable sur votre propre ordinateur. Tether 0.1.13 ou version ultérieure peut verrouiller le terminal de votre ordinateur dans un bac à sable, de sorte que les modèles et les agents de codage fonctionnent dans vos fichiers réels sans atteindre le reste de votre machine : sur macOS et les appareils Windows pris en charge, Open Terminal et tout ce qu'il lance, agents de codage inclus, ne peuvent toucher que le dossier que vous choisissez, s'exécuter hors ligne sauf si vous activez l'accès réseau et n'acceptez aucune connexion entrante, sans Docker, machine virtuelle ou configuration d'administrateur nécessaire. Si le bac à sable ne peut pas être appliqué, le terminal reste arrêté au lieu de fonctionner silencieusement sans lui, et le contrôle du navigateur et du bureau reste désactivé tant qu'il est activé. Activez-le dans Tether sous Paramètres > Ouvrir le terminal > Sandbox.
  • Serveurs MCP locaux via Tether. Open WebUI peut désormais utiliser des serveurs MCP qui s'exécutent en tant que commande locale sur stdio, de la même manière que de nombreux serveurs MCP sont distribués, en les lançant sur votre ordinateur via Tether 0.1.16 ou version ultérieure, sans proxy tel que mcpo et sans port à ouvrir. Ajoutez-en un dans Tether sous Paramètres > Intégrations > Outils avec sa commande, ou connectez un serveur MCP par son adresse Web et sélectionnez-le dans la liste Outils du menu +. Les commandes locales s'exécutent avec l'accès de votre propre compte, en dehors du bac à sable de l'espace de travail de Tether.
  • Un ordinateur pour chaque utilisateur. Avec les terminaux 0.4.0 ou ultérieurs connectés, Open WebUI distribue désormais des ordinateurs en bac à sable à la demande : toute personne disposant d'un accès en écriture à la connexion peut créer un terminal directement à partir du menu du terminal de saisie du message, choisir si tout le monde partage une machine ou si chaque utilisateur, chat ou modèle obtient le sien, et définir son image, son processeur, sa mémoire, son stockage, son profil réseau, ses variables d'environnement, son répertoire de démarrage et un script d'installation qui, par exemple, clone un référentiel et installe ses dépendances, sans administrateur. mettre en place chacun. Les terminaux peuvent être partagés avec des utilisateurs et des groupes et leurs instances démarrées, arrêtées, redémarrées ou supprimées, une option Afficher les fichiers ouvre les fichiers de n'importe quel terminal sans le sélectionner pour le chat, les informations système montrent comment s'est déroulé le script de configuration et ceux qui gèrent un terminal peuvent ouvrir les fichiers et les informations système des instances en cours d'exécution d'autres personnes. Start et Stop nécessitent les terminaux 0.4.1 ou version ultérieure, le répertoire de démarrage et le script de configuration nécessitent Open Terminal 0.17.7 ou version ultérieure dans l'image du terminal, et les profils réseau sont ceux définis par un administrateur avec "TERMINALS_NETWORK_PROFILES".
  • Agents de codage en tant que modèles de chat. Les agents de codage fonctionnent désormais comme n'importe quel autre modèle de chat. Hermes, Antigravity, GitHub Copilot, Goose et Qwen Code rejoignent Codex, Claude Code, Cursor, Grok, OpenCode, Cline, Gemini CLI et Pi, et tout autre agent ACP ajouté à Open Terminal avec "OPEN_TERMINAL_ACP_AGENTS" fonctionne également, une fois installé et connecté sur le terminal. Les autorisations automatiques pour les outils permettent désormais à Codex, Claude Code et Grok d'approuver eux-mêmes les actions de routine et de transmettre uniquement ce qu'elles escaladent, et l'effort de raisonnement dans les paramètres avancés s'applique désormais également aux agents Claude Code, Pi et ACP qui offrent des niveaux d'effort, comme OpenCode, qui s'arrêtent avec une erreur lorsque le niveau choisi n'est pas proposé pour le modèle. Les réponses peuvent désormais être régénérées et les messages précédents modifiés, et une discussion d'agent dupliquée ou clonée reprend là où l'original s'est arrêté : le Codex continue sa propre conversation à partir de ce point, d'autres agents recommencent à partir de la discussion jusqu'à présent et les modifications de fichier que l'agent a déjà apportées restent. Claude Code poursuit également sa propre conversation avec la prochaine version d'Open Terminal après 0.17.20 et vous demande d'ici là de mettre à jour Open Terminal à la place. Les nouveaux agents et Auto pour Claude Code et Grok nécessitent Open Terminal 0.17.19 ou version ultérieure, et les efforts pour les agents Claude Code, Pi et ACP nécessitent 0.17.9 ou version ultérieure. #34167
  • Pages ouvertes sous forme d'onglets. Les notes, les canaux, l'espace de travail, les automatisations, le calendrier, le terrain de jeu, la page d'accueil et les nouvelles discussions des modèles épinglés s'ouvrent désormais sous forme d'onglets à côté de la discussion en cours lorsque vous les click ou les faites glisser depuis la barre latérale, les sélectionnez dans le menu utilisateur ou suivez un lien vers l'un d'eux dans un message de discussion, et le démarrage d'une nouvelle discussion, également à partir d'un dossier de la barre latérale, conserve les onglets ouverts.
  • Les messages en file d'attente orientent les réponses. Un message que vous envoyez à votre propre chat alors qu'une réponse est toujours en cours attend désormais sur le serveur, il est donc conservé lorsque vous quittez la page, et la réponse se termine à l'étape suivante afin que votre message reçoive immédiatement une réponse avec ce qu'il a fait jusqu'à présent.
  • Premier message instantané. Le premier message d'un nouveau chat apparaît désormais immédiatement pendant que le chat est encore en cours de création, au lieu de seulement une fois qu'il existe, à moins que des fichiers ne soient toujours en cours de téléchargement avec lui.
  • Chat complet dans les chats secondaires. Les chats secondaires exécutent désormais le même chat que la vue principale, donc les boutons de message, les sources, l'utilisation des jetons, les suggestions de suivi, les commandes slash, les messages en file d'attente, les variables de chat, les paramètres de recherche sur le Web, les événements d'outils tels que l'exécution de code et les demandes de saisie, les aperçus HTML et SVG, les notifications lorsque la fenêtre est en arrière-plan, le texte non envoyé après un rechargement de page et les réponses de plusieurs modèles à la fois fonctionnent désormais également là-bas, et un onglet de chat latéral a désormais le menu de discussion. #34064, #34165, #34147, #34031
  • Visualisations interactives. Les modèles peuvent désormais dessiner des graphiques, des diagrammes, des calculatrices et des explications interactifs directement dans le chat avec le nouvel outil intégré de visualisations, qui est désactivé par défaut et activé par modèle sous Outils intégrés, et les administrateurs peuvent réécrire ses instructions sous Paramètres d'administration > Interface > Invite de visualisation ou avec "VISUALIZATION_PROMPT_TEMPLATE".
  • Génération vidéo. Les modèles peuvent désormais générer des vidéos avec un outil intégré, également à partir d'une image dans le chat, une fois qu'un administrateur active la génération vidéo sous Paramètres d'administration > Vidéos, ajoute des connexions à OpenAI, LiteLLM ou OpenRouter, qui propose des modèles tels que Veo et Kling, avec un modèle vidéo par défaut, des paramètres par défaut et des paramètres d'accès par modèle, et accorde l'autorisation de génération vidéo, qui est désactivée par défaut, après quoi les utilisateurs activent la vidéo dans le menu +, peuvent y choisir le modèle et regarder le résultat dans la conversation. #13780, #13927
  • Plusieurs modèles d'image. Les administrateurs peuvent désormais ajouter plusieurs connexions d'images sous Paramètres d'administration > Images, chacune étant un serveur compatible OpenAI tel que LiteLLM, Gemini, ComfyUI ou AUTOMATIC1111 avec ses propres modèles, tailles, flux de travail et accès, utilisés pour générer des images, les éditer ou les deux, où ceux compatibles OpenAI offrent les mêmes options de connexion et en-têtes personnalisés que les connexions de modèles et répertorient les modèles d'image d'un serveur LiteLLM par eux-mêmes lorsqu'aucun ID de modèle n'est saisi, choisissez la valeur par défaut. générer et modifier des modèles et attribuer à un modèle son propre modèle d'image par défaut dans ses paramètres, et les utilisateurs possédant plusieurs modèles d'image en choisissent un dans l'entrée Image du menu + de la saisie du message. #10344
  • Le panneau Git devient un atelier GitHub. Avec Open Terminal 0.17.8 ou version ultérieure et le GitHub CLI connecté sur le terminal, comme inclus dans les images complètes, agents et cuda, le panneau Git couvre désormais toute la boucle GitHub : parcourir, rechercher, créer, modifier, commenter, fermer et rouvrir les problèmes du référentiel, voir les vérifications de chaque demande d'extraction, l'état de révision, les étiquettes, l'activité et entre en conflit avec un filtre d'état et un choix de méthode de fusion, et recherche des problèmes et des demandes d'extraction dans l'ensemble du référentiel au lieu de uniquement dans la liste chargée. Des boutons tels que Travailler dessus, Corriger, Adresser les commentaires et Résoudre les conflits dans le chat traitent le problème, examinent ou entrent en conflit avec le modèle sous la forme d'une demande prête à l'emploi dans la saisie du message, et les fichiers modifiés peuvent être sélectionnés avec Ctrl ou Maj click pour en supprimer plusieurs à la fois ou tous.
  • Les terminaux suivent vos discussions. Chaque discussion enregistre désormais son terminal et son dossier de travail et y revient lorsque vous le rouvrez, y compris un terminal que vous avez éteint, et les administrateurs peuvent choisir un terminal par défaut sous Paramètres d'administration > Modèles > Paramètres par défaut du modèle avec lequel les nouvelles discussions démarrent pour chaque modèle sans terminal propre, de sorte que chaque discussion peut démarrer avec un ordinateur connecté. Les discussions des versions antérieures s'ouvrent sans terminal, sauf s'il s'agit de discussions d'agent de codage.

  • Statuts de discussion dans les dossiers.   • Connaissances sur les pages de dossiers. Les balises peuvent désormais avoir une couleur sur la page du dossier qui s'applique partout où la balise est utilisée, et le menu de discussion comporte un sous-menu Balises pour rechercher, ajouter et créer des balises, et les personnes pouvant modifier un dossier partagé peuvent marquer chaque discussion qu'il contient.

La page d'une automatisation modifie désormais son nom, ses instructions, son statut, son calendrier, son modèle, son terminal et sa destination directement ici avec un bouton Enregistrer qui apparaît une fois que quelque chose a changé, affiche les instructions enregistrées réduites derrière Afficher plus, répertorie ses exécutions en tant qu'activité ci-dessous et a Copier le lien et Dupliquer dans son menu Plus.
  • Étapes lisibles de l'agent et du terminal. Les étapes des agents de codage et les appels d'outils de terminal d'autres modèles s'affichent désormais dans le chat comme ce qu'ils ont fait, une commande avec sa sortie et son code de sortie en cas d'échec, un diff de chaque fichier édité avec ses lignes ajoutées et supprimées, ou les fichiers lus, le code et les recherches sur le Web, les dossiers répertoriés et les pages récupérées, et un groupe d'étapes est résumé comme par exemple les commandes Ran 2, le fichier édité 1, lire 3 fichiers. Corrigé

  • Les discussions temporaires ne laissent aucun souvenir. L'examen de la mémoire en arrière-plan ignore désormais les discussions temporaires, de sorte que les faits qui en découlent ne sont plus enregistrés en tant que souvenirs qui apparaissent dans les discussions ultérieures. #34263, #34262
  • Nombres entiers dans les paramètres.   • Désépingler l'info-bulle sur les notes. Le bouton Détacher d'une note épinglée dans la barre latérale affiche désormais une info-bulle, comme c'est le cas sur les modèles épinglés. #34568, #34567

Modifié

  • Terminaux 0.4.0 requis. Les connexions à un serveur de terminaux ne comportent plus de stratégie dans Paramètres d'administration > Intégrations. Par conséquent, les paramètres d'ID de stratégie, d'image, de ressource, de stockage, de délai d'inactivité et de contextes de terminal ainsi que le bouton Actualiser les terminaux ont disparu, le serveur doit exécuter les terminaux 0.4.0 ou version ultérieure, et les modèles, dossiers, automatisations et discussions qui utilisaient l'ancienne connexion ont besoin de l'un des nouveaux terminaux sélectionnés. La mise à niveau des terminaux à partir de 0.3.x nécessite une migration manuelle, car il n'y en a pas automatiquement, les nouvelles installations de terminaux démarrent sans modèle, Open WebUI se connecte désormais à la clé du serveur Terminals et "TERMINALS_OPEN_WEBUI_URL" et "TERMINALS_TOKEN_CACHE_TTL" doivent être supprimés des paramètres des terminaux. Les connexions du terminal ouvert et du terminal Tether ne sont pas affectées.
  • Les connexions directes sont déplacées vers Tether. Paramètres > Connexions et paramètres > Outils ont disparu avec les commutateurs Connexions directes et Intégrations directes dans les paramètres d'administration, l'autorisation Serveurs d'outils directs et les paramètres "ENABLE_DIRECT_CONNECTIONS", "ENABLE_DIRECT_INTEGRATIONS" et "USER_PERMISSIONS_FEATURES_DIRECT_TOOL_SERVERS", de sorte que les modèles, serveurs d'outils et terminaux que les utilisateurs ont ajoutés dans leurs propres paramètres n'apparaissent plus. Les utilisateurs les ajoutent plutôt dans l'application Tether (0.1.14 ou version ultérieure, 0.1.16 pour les serveurs MCP), où ils restent sur leur propre ordinateur et travaillent dans chaque Open WebUI auquel ils se connectent.
  • Les paramètres d'image deviennent des connexions. Au premier démarrage de cette version, les paramètres de génération et d'édition d'images sont transformés en connexions d'images que tous ceux qui pouvaient les utiliser auparavant continuent d'utiliser, et à partir de là, les variables d'environnement d'image telles que "IMAGE_GENERATION_ENGINE", "IMAGES_OPENAI_API_BASE_URL" et "COMFYUI_BASE_URL" ne sont plus lues à moins que "ENABLE_PERSISTENT_CONFIG" soit désactivé.
  • Dépendances Docker verrouillées. Les images Docker standard et minces installent désormais tous les packages Python, à l'exception de PyTorch, à partir de fichiers de verrouillage épinglés avec des hachages, donc la reconstruction de la même version installe les mêmes packages, et les images personnalisées qui modifient "backend/requirements.txt" doivent régénérer les verrous avec "backend/update-locks.sh" pour que la modification prenne effet. #33981, #33979
  • Nouveaux identifiants de modèle d'agent de codage. Les modèles d'agent de codage obtiennent désormais des identifiants composés uniquement de lettres, de chiffres, de tirets et de traits de soulignement, ce qui permet aux modèles Cursor et Pi épinglés de fonctionner, et les épingles, les modèles par défaut et les automatisations qui pointent vers un modèle d'agent dont le nom avait d'autres caractères, des points inclus comme dans la plupart des modèles Codex, nécessitent que le modèle soit à nouveau sélectionné. #34171, #34168
  • Les sessions de l'agent de codage redémarrent une fois. Le premier nouveau message dans une conversation d'agent de codage d'une version antérieure démarre une nouvelle session d'agent qui amène la conversation jusqu'au texte, au lieu de reprendre la propre session de l'agent.
  • Vérifications du modèle d'image API. Les requêtes de génération et de modification d'image envoyées via le API s'exécutent désormais sur le modèle qu'ils nomment, qui doit être l'un des modèles d'image de l'appelant, sinon la requête échoue avec une erreur, au lieu de la génération d'image ignorant le modèle nommé.
  • Événements de mise à jour en direct renommés. Les mises à jour en temps réel pour les notes, les commentaires, la boîte de réception, les modifications d'accès, les chaînes cryptées et les erreurs d'application de chaîne arrivent désormais sous forme de messages saisis sur le canal socket principal « événements », donc les clients personnalisés qui écoutaient les anciens noms d'événements tels que « événements : note » ou « note : présence » doivent y écouter à la place.
  • Champ d'accès en écriture au chat. Les réponses au chat du API portent désormais le mode de partage enregistré dans "share_mode" et indiquent si vous pouvez répondre dans un nouveau champ "write_access", donc les clients personnalisés qui lisent "share_mode" doivent changer pour cela.
  • Les téléchargements de terminal vont vers les fichiers. Les nouvelles connexions de terminal démarrent désormais avec les téléchargements de chat définis sur Système de fichiers et les ordinateurs connectés via Tether l'utilisent toujours, de sorte que les fichiers joints à un chat sont enregistrés dans le dossier de travail du terminal sélectionné au lieu d'être traités comme des téléchargements de chat réguliers, tandis que les connexions existantes conservent leurs paramètres. Il est recommandé d'ouvrir le terminal 0.17.20 ou version ultérieure, car il corrige les téléchargements qui deviennent illisibles dans les configurations multi-utilisateurs.
  • Éléments du menu de discussion déplacés. Aperçu, artefacts et commentaires ne sont plus dans le menu du chat et s'ouvrent désormais à partir du menu + de la barre d'onglets, où l'aperçu s'ouvre sous la forme d'un onglet à côté du chat au lieu d'une fenêtre plein écran.
  • Bouton Commentaires de note. Les commentaires sur une note s'ouvrent désormais à partir d'un bouton dans la barre supérieure de la note plutôt que depuis son menu, et dans une note que vous pouvez modifier, commenter le texte sélectionné est désormais un bouton Commentaire dans la barre d'outils de formatage.
  • Un menu d'en-tête. La barre d'outils de formatage de la saisie des messages et des notes propose désormais les titres 1, 2 et 3 dans un seul menu d'en-tête au lieu de trois boutons séparés.
  • Menu Pièces jointes renommé. L'entrée Ajouter un contexte dans le menu + de la saisie du message, qui contient les options permettant de joindre des pages Web, des fichiers, des notes, des connaissances et des discussions, s'appelle désormais Pièces jointes. #34431
  • Capacités désormais fonctionnalités. La section Capacités de l'éditeur de modèle s'appelle désormais Fonctionnalités. #34433
  • Étiquettes de base de connaissances. Le sélecteur de connaissances dans le chat, le sélecteur de connaissances de l'éditeur de modèle et les bases de connaissances associées les appellent désormais Connaissance ou Base de connaissances au lieu de Collection, le terme de base de données vectorielles, et la zone de recherche à l'intérieur d'une base de connaissances indique désormais Rechercher des fichiers. #34432
