open-webui v0.9.5

Ajouté

  • 🛡️ Protection SSRF basée sur la redirection. Toutes les requêtes HTTP sortantes bloquent désormais les redirections 3xx par défaut via une nouvelle variable d'environnement AIOHTTP_CLIENT_ALLOW_REDIRECTS, empêchant le SSRF basé sur la redirection où une URL publique redirige silencieusement vers des adresses internes (RFC 1918, bouclage, points de terminaison de métadonnées cloud). Les sites d'appel concernés incluent la récupération Web, le chargement d'images, la découverte OAuth, l'exécution du serveur d'outils et la connexion à l'interpréteur de code. #24491
  • 🛡️ Politique de sécurité du contenu Iframe. Les administrateurs peuvent désormais configurer une politique de sécurité du contenu pour tous les iframes srcdoc (artefacts, intégrations d'outils, aperçus de fichiers, modaux de citation) via la variable d'environnement IFRAME_CSP, limitant ce que le HTML généré par LLM ou téléchargé par l'utilisateur peut charger et exécuter dans les aperçus. S'engager
  • 🎛️ Contrôles de rendu granulaire des démarques. Les utilisateurs peuvent désormais désactiver indépendamment le rendu Markdown pour les messages utilisateur et les réponses de l'assistant à partir des paramètres de l'interface, empêchant ainsi un formatage involontaire lors du collage de texte contenant des caractères sensibles au Markdown. S'engager
  • 🔧 En-têtes de réponse proxy de terminal. Les administrateurs peuvent désormais injecter des en-têtes de réponse personnalisés dans les réponses proxy de terminal via la variable d'environnement TERMINAL_PROXY_HEADERS (objet JSON), permettant des en-têtes de sécurité spécifiques au déploiement comme les politiques de bac à sable pour le contenu proxy. Commettre
  • 🔌 Streaming de canal et prise en charge des outils. La mention d'un modèle dans un canal diffuse désormais les réponses en temps réel et prend en charge le pipeline complet de complétion de chat, y compris les appels de fonctions natifs et par défaut, les outils intégrés (recherche sur le Web, génération d'images), les outils utilisateur, les outils MCP, les filtres et l'injection de connaissances RAG — les mêmes fonctionnalités disponibles dans les chats standard.

Corrigé

  • 📝 Les notes créent et ouvrent la fiabilité. La création de nouvelles notes et l'ouverture de notes existantes n'échouent plus avec une TypeError provoquée par le passage de is_pinned au modèle SQLAlchemy lors de la création et deux fois à NoteResponse lors de la lecture. #24484, #24486
  • 🔐 Application des autorisations de partage public des compétences. La création ou la mise à jour des compétences filtre désormais les autorisations d'accès via l'autorisation sharing.public_skills, empêchant les utilisateurs non administrateurs de rendre les compétences accessibles publiquement sans l'autorisation requise. #24494
  • 🔐 Application de l'autorisation de partage public du calendrier. La création ou la mise à jour de calendriers filtre désormais les autorisations d'accès via une nouvelle autorisation sharing.public_calendars, empêchant les utilisateurs de rendre les calendriers lisibles ou inscriptibles publiquement sans autorisation de partage explicite accordée par l'administrateur. #24493
  • 🔐 ** Usurpation de l'attribution des utilisateurs. ** La soumission de commentaires d'évaluation ne peut plus falsifier le champ user_id via une attribution de masse, empêchant les utilisateurs authentifiés d'attribuer des notes à d'autres utilisateurs et corrompant les classements du classement Elo et les exportations de commentaires d'administrateur. #24508
  • 🛡️ SSRF basé sur la redirection d'URL d'image. Les messages de discussion contenant des URL d'image ne suivent plus les redirections 3xx vers des adresses internes lors de la conversion base64, fermant ainsi la variante SSRF basée sur la redirection la plus accessible qui ne nécessitait aucune autorisation spéciale ni indicateur de fonctionnalité. #24524
  • 🛡️ Accès en écriture de la collection lors du traitement des fichiers. Les points de terminaison de récupération process_file et process_files_batch appliquent désormais des contrôles d'accès en écriture à la collection avant d'intégrer le contenu, empêchant les utilisateurs authentifiés d'injecter le contenu du fichier dans la collection de base de connaissances d'un autre utilisateur. #24524
  • 🔐 Autorisation de mise à jour du code source de l'outil. La mise à jour du code source Python d'un outil nécessite désormais l'autorisation workspace.tools ou workspace.tools_import, empêchant les utilisateurs disposant uniquement d'un accès en écriture d'écraser le code de l'outil exécutable tout en autorisant les modifications des métadonnées. #24513
  • 🔐 Application de la propriété des messages de la chaîne. La mise à jour ou la suppression de messages dans les canaux de groupe et DM nécessite désormais la propriété des messages, empêchant les membres de la chaîne de falsifier ou de supprimer silencieusement les messages des autres membres. #24506
  • 🔐 Autorisation d'écriture des épingles de chaîne. L'épinglage et le désépinglage de messages sur les chaînes standard nécessitent désormais une autorisation d'écriture au lieu d'une autorisation de lecture, empêchant les utilisateurs en lecture seule de modifier le contenu épinglé. #24521
  • 🛡️ Validation de l'URL de génération d'image. Les URL d'image générées sont désormais validées via validate_url() avant d'être récupérées, alignant la posture de défense en profondeur avec les chemins de chargement d'images frères. #24518
  • 🔐 Exposition des paramètres de modèle pour les utilisateurs en lecture seule. Le point de terminaison par modèle API supprime désormais le dict params (y compris les invites système) des réponses aux appelants sans accès en écriture, empêchant les utilisateurs en lecture seule d'afficher la configuration du modèle organisée par l'administrateur. #24525
  • 🛡️ Contournement SSRF de l'analyseur d'URL. La validation d'URL rejette désormais les caractères antislash, tabulation, CR et LF qui provoquent un désaccord entre urllib et request/aiohttp sur l'hôte cible, fermant ainsi un contournement SSRF de confusion par l'analyseur. #24534
  • 🛡️ Liste d'autorisation de type MIME d'image de profil. La diffusion d'images de profil à partir d'URI de données applique désormais une liste d'autorisation de type MIME stricte (PNG, JPEG, GIF, WEBP par défaut, configurable via PROFILE_IMAGE_ALLOWED_MIME_TYPES) et définit X-Content-Type-Options: nosniff, empêchant le XSS stocké via SVG ou d'autres types de contenu exécutables. Commettre
  • 🔐 Propriété des fichiers dans les pièces jointes de dossiers et de connaissances. La pièce jointe de fichiers à des dossiers ou à des bases de connaissances vérifie désormais l'accès en lecture par fichier, et les listes de fichiers de dossiers dans le middleware de discussion sont filtrées selon les entrées que l'appelant peut lire, empêchant ainsi l'injection de contenu de fichier non autorisé dans le contexte RAG. Commettre
  • 🔐 Accès au chat partagé pour les propriétaires et les administrateurs. Les propriétaires de chat peuvent désormais afficher et cloner leurs propres chats partagés sans nécessiter d'autorisation d'accès explicite, et les administrateurs peuvent gérer les contrôles d'accès au chat partagé sur n'importe quel chat. Valider, Valider
  • 🧵 Auto-réparation de l'historique des discussions héritées. Le chargement des conversations héritées détecte désormais automatiquement les graphiques de liens parents rompus dans les enregistrements de messages migrés, fusionne les messages manquants de l'historique JSON intégré et les remplit dans la table normalisée afin que les chargements futurs utilisent le chemin rapide sans perte de données. S'engager
  • 🎛️ Réactivité du sélecteur de filtre. Les cases à cocher des filtres de modèle dérivent désormais l'état de manière réactive de la liste de filtres actuelle et des ID sélectionnés au lieu de capturer un instantané unique lors du montage, de sorte que les cases à cocher se mettent à jour correctement lorsque les contextes du modèle ou les configurations de filtre changent au moment de l'exécution. Commettre
  • 🌐 Mises à jour de la traduction en portugais (Brésil). Les traductions des éléments d'interface utilisateur nouvellement ajoutés ont été ajoutées ainsi qu'une cohérence entre les entrées existantes. #24503

Modifié

  • 🧹 Suppression du point de terminaison d'état de récupération non authentifié. Le point de terminaison d'état non authentifié GET /api/v1/retrieval/ a été supprimé en tant que code mort — la configuration de récupération est déjà disponible via les points de terminaison d'administrateur authentifiés. #24497
  • 📋 Exigence de problème de modèle PR. Les demandes de tirage nécessitent désormais une référence de problème ou de discussion liée, garantissant une meilleure traçabilité de toutes les contributions. Les PR sans problème ou discussion lié peuvent être fermés sans examen.
