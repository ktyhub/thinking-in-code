Modifications cassantes

  • La configuration JUL (java.util.logging) n'est plus efficace pour les composants côté serveur (#26330)

    Auparavant, les journaux des bibliothèques tierces qui utilisent JUL (par exemple, Jersey/Jetty, gRPC, Guava) n'étaient pas gérés par la configuration Log4j2 de Pulsar, ce qui les rendait difficiles à contrôler et entraînait une sortie de journal incohérente. Pour résoudre ce problème, la journalisation des bibliothèques tierces est désormais reliée de JUL à Log4j2 via log4j-jul. Cela unifie toute la journalisation sous conf/log4j2.yaml, mais signifie que les JUL API et configurations suivants ne prennent plus effet :

    • -Djava.util.logging.config.file=logging.properties — l'intégralité du fichier de configuration JUL est ignorée
    • java.util.logging.Logger.setLevel() / addHandler() — deviennent no-ops
    • java.util.logging.LogManager.reset() — devient un no-op

    Migration : déplacez toute configuration de journalisation basée sur JUL vers conf/log4j2.yaml. Par exemple, pour supprimer les journaux gRPC précédemment configurés en tant que io.grpc.level=SEVERE dans logging.properties, ajoutez ce qui suit à conf/log4j2.yaml :

    Loggers:
  Logger:
    - name: io.grpc
      level: error

    Revert : pour restaurer le comportement du stock JUL, définissez :

    PULSAR_EXTRA_OPTS="-Djava.util.logging.manager=java.util.logging.LogManager"
