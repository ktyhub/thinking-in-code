#pulsar v5.0.0-M1

2026-06-23

Apache Pulsar 5.0.0-M1 est la première version marquante sur la route vers Apache Pulsar 5.0.0, avec une disponibilité générale attendue plus tard en 2026. Il s'agit d'un aperçu : une première version qui met entre vos mains les principales nouvelles fonctionnalités de 5.0 afin que vous puissiez les essayer sur des charges de travail réelles et envoyer des commentaires avant la version GA. Il n'est pas destiné à la production. Deux changements se démarquent : Scalable Topics, un nouveau type de sujet qui grandit et diminue tout seul, et la promotion de Oxia au magasin de métadonnées recommandé par Pulsar, parallèlement à une migration du système de build vers Gradle, la division des connecteurs IO dans un référentiel séparé et une journalisation structurée.

Pour une présentation complète, consultez l'annonce : [Apache Pulsar 5.0.0-M1 : un aperçu de la prochaine version majeure] (https://pulsar.apache.org/blog/2026/06/23/announcing-apache-pulsar-5-0-m1).

Faits saillants

Sujets évolutifs (Sujets v5). Un nouveau type de sujet qui remplace les partitions fixes par des segments basés sur une plage, afin qu'un sujet puisse évoluer vers le haut ou vers le bas en divisant et en fusionnant les segments de manière transparente tout en préservant l'ordre par clé. Cela évite les ruptures d'ordre et les dérives opérationnelles liées à la modification du nombre de partitions d'un sujet partitionné standard. Le travail couvre le contrôleur côté courtier (PIP-468), les transactions basées sur les métadonnées (PIP-473), la migration de sujets régulière à évolutive (PIP-475) et la division/fusion automatique (PIP-483). Voir PIP-460.

Nouveau V5 Java client API. Un client API entièrement conçu et spécialement conçu pour les sujets évolutifs, livré sous la forme d'un nouveau module pulsar-client-v5 additif — les modules pulsar-client et pulsar-client-api existants sont inchangés, de sorte que les applications actuelles continuent de fonctionner. Il remplace le classique Consumer/Reader et les quatre types d'abonnement par trois consommateurs spécialement conçus : QueueConsumer (consommation de file d'attente de travail parallèle et reconnue individuellement avec prise en charge des lettres mortes), StreamConsumer (accusés de réception ordonnés et cumulatifs) et CheckpointConsumer (pour les processeurs de flux tels que Flink et Spark qui suivent leur propre position). Le V5 client fonctionne également sur les sujets partitionnés et non partitionnés existants, et un consommateur peut s'abonner à un espace de noms entier. Dans M1, il est livré pour Java ; d'autres langues SDK suivront avant GA. Voir PIP-466.

Oxia est désormais le magasin de métadonnées recommandé. Oxia devient le magasin de métadonnées recommandé pour les nouveaux clusters Pulsar dans 5.0 et constitue le backend de choix pour les sujets évolutifs, dont les recherches s'appuient sur ses sessions de surveillance en streaming. ZooKeeper reste entièrement pris en charge et PIP-454 ajoute un cadre de migration en direct sans temps d'arrêt qui déplace un cluster existant de ZooKeeper vers Oxia pendant que le plan de données continue de publier et de consommer.

Le système de build a migré de Maven vers Gradle. Les builds utilisent désormais ./gradlew au lieu de mvn, avec une mise en cache et un parallélisme au niveau des tâches qui réduisent considérablement les temps de build locaux et CI, et un catalogue de versions central (gradle/libs.versions.toml) pour la gestion des dépendances. La migration est transparente pour les utilisateurs qui consomment les artefacts Maven publiés, les images Docker et les JAR client ombrés. Voir PIP-463.

Connecteurs IO divisés dans un référentiel séparé. Les connecteurs Pulsar IO intégrés ont été déplacés hors du référentiel principal afin qu'ils puissent suivre leur propre cadence de publication. Voir PIP-465. Journalisation structurée. Pulsar émet désormais des journaux structurés via slog à travers les modules de courtier, client, ​​de grand livre géré, de fonctions et de métadonnées, avec une sortie de journal plate JSON / OpenTelemetry et une variable d'environnement PULSAR_LOG_FORMAT pour changer facilement de format. Voir PIP-467.

API et modernisation de la plateforme. Pulsar a migré de javax.* vers jakarta.* APIs (PIP-472), a fait de Protobuf v4 la valeur par défaut, a migré les annotations REST API de Swagger vers OpenAPI 3 et prend désormais en charge la création et l'exécution sur Java 25. Les politiques de sujet ont acquis une prise en compte de l'héritage, backend de routage basé sur le stockage de métadonnées (PIP-469).

Mises à jour de sécurité et de dépendances. Cette version regroupe un large ensemble de mises à niveau de dépendances qui traitent de nombreux CVE dans Netty, Jetty, log4j, BouncyCastle, Thrift, vert.x et async-http-client, ​​et met à niveau BookKeeper vers 4.18.0. Voir Mises à jour de la bibliothèque ci-dessous.

Avis important

5.0.0-M1 est une version majeure qui supprime les fonctionnalités obsolètes et modifie certains API. Vérifiez les éléments suivants avant la mise à niveau :

  • Migration javax.* → jakarta.* (PIP-472). Les plug-ins de courtier personnalisés, les intercepteurs, les fournisseurs d'authentification/autorisation ou d'autres extensions faisant référence aux packages javax.* (par exemple javax.ws.rs ou javax.servlet) doivent être mis à jour vers les packages jakarta.* correspondants et recompilés.
  • Le backend du magasin de métadonnées Etcd a été supprimé (PIP-462). Les déploiements utilisant Etcd comme magasin de métadonnées doivent migrer vers ZooKeeper ou Oxia avant la mise à niveau.
  • Connecteurs IO déplacés vers un référentiel séparé (PIP-465). Les connecteurs ne sont plus libérés du référentiel Pulsar principal ; obtenez-les depuis le projet de connecteurs dédiés.
  • Le système de construction est désormais Gradle (PIP-463). Si vous construisez Pulsar à partir des sources, utilisez ./gradlew au lieu de mvn. Les artefacts publiés restent inchangés.
  • Dépendance fastutil supprimée (#25413).
