Changements notables

Tellement ! Consultez le Lighthouse 6.0 : Quoi de neuf article de blog pour un aperçu approfondi.

🆕 Nouveaux audits

  • Largest Contentful Paint (LCP) est une nouvelle métrique qui mesure le temps écoulé entre la navigation et le rendu du plus grand élément de contenu dans la fenêtre d'affichage (#9905, #10213, #10452, #10529).
    • largest-contentful-paint-element est un audit compagnon qui donne des informations sur l'élément qui a déclenché le LCP (#10517, #10713). * Cumulative Layout Shift (CLS) est une nouvelle mesure qui mesure la quantité de mouvement inattendu du contenu lors du chargement d'une page (#9037, #10427, #10495, #10570, #10728).
    • layout-shift-elements est un autre diagnostic compagnon qui donne des informations sur les éléments qui se sont déplacés lors du chargement de la page (#10702).
  • unused-javascript est un audit qui existe depuis un certain temps mais qui n'est activé que maintenant par défaut. Il tient compte de ce que JavaScript a été chargé mais n'a jamais été exécuté lors du chargement de la page et estime le temps de chargement qui pourrait être économisé via le fractionnement du code, l'élimination du code mort ou l'utilisation judicieuse de la touche de suppression (#9854).
  • Une PWA maskable-icon est tout simplement plus belle sur votre écran d'accueil, ce nouvel audit vous encourage donc à en avoir au moins une disponible dans votre manifeste (#10370).
  • timing-budget étend les [affirmations budgétaires] (https://github.com/GoogleChrome/lighthouse/blob/7e4fa55/docs/performance-budgets.md) pour qu'elles soient désormais réglables sur toutes les mesures de performances (#9901, #9925).
  • Le nouvel audit charset garantit un codage de caractères approprié pour le contenu de la page (#10284, #10389, #10689).
  • image-size-responsive vérifie que les images ont un rapport hauteur/largeur et une résolution qui correspondent bien à la façon dont elles sont affichées sur une page (#10460).
  • La mise à jour vers la dernière version de axe-core a débloqué un certain nombre de nouveaux audits d'accessibilité : aria-hidden-body, aria-hidden-focus, aria-input-field-name, aria-toggle-field-name, duplicate-id-active, duplicate-id-aria, form-field-multiple-labels, heading-order (#9798).

⚗️ Audits expérimentaux

Ces audits ne font pas encore partie de l'expérience Lighthouse par défaut, mais ils fourniront des conseils de performances basés sur l'analyse des bundles JavaScript d'une page. Ils peuvent être testés aujourd'hui en ligne de commande avec le flag --preset=experimental.

  • legacy-javascript fouille dans vos bundles à la recherche de polyfills et de transformations de bundler qui ne sont pas nécessaires ou qui sont obsolètes (#10303, #10568, #10564).
  • duplicated-javascript parcourt également le JavaScript d'une page à la recherche du code qui a fini par être dupliqué dans des bundles ou sur plusieurs bundles (#10314).
  • unused-javascript s'exécute désormais par défaut (comme mentionné ci-dessus), mais lorsqu'il est exécuté sous experimental, l'audit peut utiliser des cartes sources pour montrer quel code source original n'a jamais été exécuté et pourrait être reporté ou éliminé (#10090).

💥 Modifications radicales

  • Les scores des mesures de performances [ont été repondérés] (https://web.dev/performance-scoring/) pour mieux refléter l'expérience de chargement d'un utilisateur ([#9949] (https://github.com/GoogleChrome/lighthouse/pull/9949)).
  • Les courbes de score métrique ont été mises à jour lors de l'exécution d'un test Lighthouse sur ordinateur pour tenir compte de la connexion et du processeur plus rapides (#9911, #10756).
  • Les événements frameNavigated sont désormais utilisés pour suivre les redirections, ce qui signifie que les redirections JS sont désormais prises en compte lors de la détermination du finalUrl de l'exécution (#10339).
  • L'appareil mobile émulé est passé du Nexus 5x au Moto G4 (mais le DPR existant est resté inchangé) (#10191, #10749).
  • Le préréglage mixed-content a été supprimé car il n'était pas largement utilisé et prend trop de temps pour être ajouté à l'expérience Lighthouse par défaut (#10159, #10750).
  • Le préréglage full a été renommé experimental pour signifier que le code qui s'y trouve n'est peut-être pas prêt à être exécuté par défaut (#9930, #10311, #10333, #10585).
  • La chaîne Chrome UA émulée a été mise à jour vers Chrome 80 (#9967).
  • installable-manifest : les icônes du manifeste de l'application Web doivent pouvoir être récupérées pour être considérées comme installables (#10168, #10320).

🤖💥 Modifications majeures pour les utilisateurs programmatiques

Il est peu probable que ces modifications affectent les utilisateurs finaux, mais peuvent être importantes si vous écrivez des configurations personnalisées, des plugins ou si vous traitez la sortie Lighthouse JSON.

  • LH.Audit.Context passé en audits est désormais traité comme immuable. Si le code a déjà été transmis à context.LighthouseRunWarnings pour obtenir un avertissement de niveau supérieur, il doit maintenant le renvoyer dans runWarnings sur le produit de l'audit (#10555).
  • Audit.computeLogNormalScore a été redéfini pour spécifier des courbes log-normales avec des points médians et p10 (en supprimant le « point de rendement décroissant »). Les audits existants ont été déplacés vers cette nouvelle définition afin qu'aucun changement de score ne se produise (#10715).
  • Un paramètre loadFailureMode a été ajouté aux passes Config pour contrôler le comportement en cas d'échec de chargement de page. Auparavant, cela était implicitement contrôlé (par exemple, aucune page hors ligne disponible ne provoquait pas d'erreur) (#9987)
  • time-to-first-byte a été renommé server-response-time pour mieux refléter ce qui est mesuré par l'audit (#10735).
  • resource-summary : details.items.size a été renommé transferSize pour plus de clarté (#10700, #10743).
