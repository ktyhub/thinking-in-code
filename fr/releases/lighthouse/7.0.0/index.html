lighthouse v7.0.0

Majeure Publié18 déc. 2020 SourceGoogleChrome/lighthouse Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

phare v7.0.0

#7.0.0 (2020-12-17) Changelog complet Lighthouse 7.0 inclut un certain nombre de modifications programmatiques et de nouveaux audits dans les catégories Accessibilité et PWA. Certaines améliorations ont été apportées à la précision des calculs des mesures, mais il n'est pas prévu que les scores de Performances changent de manière significative pour presque tous les sites. Il peut y avoir des changements plus importants dans les scores d'Accessibilité et de PWA en raison des nouveaux audits. Cette version devrait être livrée dans les DevTools de [Chrome 89] (https://chromiumdash.appspot.com/schedule). Il a été mis en ligne sur PageSpeed Insights le 19 février 2021.

Changements notables

  • Une capture d'écran pleine page est prise et utilisée pour améliorer l'expérience de visualisation des détails des éléments DOM. Maintenant, une vignette sera affichée et clicking révèle une lightbox montrant où dans la page vivait le nœud DOM. Cette capture d'écran augmente la taille du Lighthouse JSON d'environ 33 %. (#11769, #11768, #11829, #11846, #11852)
  • La Catégorie PWA a changé de manière assez significative.
    • Le groupe Installable est entièrement alimenté par les vérifications de fonctionnalités qui activent les critères d'installation de Chrome. Ce sont les mêmes signaux que ceux observés dans le volet Manifest de Chrome DevTools. En tant que tel, l'audit « Enregistre un technicien de service … » est déplacé vers le groupe PWA Optimized, et l'audit « Utilise HTTPS » est désormais inclus dans le cadre de l'audit clé « Exigences d'installabilité ».
    • Le groupe Rapide et fiable s'est évaporé dans les airs. 🌬 Maintenant que l'audit remanié des « exigences d'installation » inclut la vérification des capacités hors ligne, nous avons supprimé les audits dédiés pour vérifier si la page actuelle et start_url répondent avec 200 lorsqu'ils sont hors ligne. Par ailleurs, l'audit « Le chargement de la page est assez rapide sur le réseau mobile » a été supprimé. Bien qu'il ne fasse plus partie de la section PWA, nous encourageons les personnes qui créent une PWA à consulter la catégorie Performances pour garantir que leur application Web est rapide et agréable.
  • Une version nocturne de Lighthouse est maintenant disponible sous le nom de lighthouse@next sur npm. Notez que même si les tests automatisés sont réussis avant la publication, on s'attend à ce que cette version soit plus instable que les versions régulières (#11792, #11805, #11810).
  • La bibliothèque de tests d'accessibilité axe-core a été mise à jour vers la dernière version 4.1.1. Les audits d'accessibilité sont désormais plus rapides, plus robustes et incluent plusieurs nouvelles vérifications (#11661)
  • Lighthouse exécute un petit benchmark au démarrage et inclura désormais un avertissement si la machine de test semble sous-alimentée et peut affecter la précision des métriques Lighthouse (#11350).
  • La détection Joomla et October CMS a été ajoutée, de sorte que les pages de ces plates-formes recevront désormais des conseils personnalisés sur certains audits Lighthouse (#11788)

Nouveaux contributeurs

Merci à Kohta Ito (@koh110) et Sam Stoelinga (@samos123) pour leurs premières contributions !

🆕 Nouveaux audits

  • Le nouvel audit PWA installable-manifest, mentionné ci-dessus, utilise les propres critères d'installation de Chrome afin qu'il reste toujours synchronisé avec les exigences d'installation (#11745).
  • third-party-facades recherche des intégrations tierces dans la page de test qui peuvent être chargées paresseusement avec une "façade" statique. Si l'intégration n'est pas nécessaire pour une interaction immédiate d'un utilisateur, envisagez d'utiliser l'une des façades pour accélérer le chargement de la page (#11290).
  • La mise à niveau de la version ax s'accompagne de nouveaux audits garantissant une dénomination accessible : aria-treeitem-name, aria-command-name, aria-tooltip-name, aria-meter-name et aria-progressbar-name (#11661)

♻️ Audits supprimés

  • La mise à jour vers le dernier axe-core supprime également deux audits qui ne vérifiaient pas grand-chose : layout-table et video-description (#11661).
  • Les audits works-offline et offline-start-url ont été supprimés car leurs contrôles sont désormais couverts par la nouvelle implémentation installable-manifest (#11806)
  • L'audit load-fast-enough-for-pwa a également été supprimé car les mesures de performances existantes de Lighthouse couvrent largement les besoins (#11764).
  • without-javascript a été supprimé (#11711)

💥 Modifications radicales

  • Les paramètres de configuration de l'émulation de périphérique et les indicateurs CLI ont été modifiés pour être plus clairs et se chevaucher moins. Si vous avez utilisé --emulated-form-factor ou une autre configuration liée à l'émulation, vous devrez apporter des modifications. Les nouveaux paramètres devraient être considérablement plus simples à utiliser avec des coureurs Lighthouse personnalisés utilisant de vrais appareils, Puppeteer ou une limitation au niveau du système. Consultez la documentation d'émulation pour obtenir des conseils sur la migration. (#11779)
  • En attendant que la page soit complètement chargée, Lighthouse attendra désormais s'il y a des demandes réseau actives de haute priorité. Dans de rares cas, comme lorsque l'initialisation de l'application dépend d'un seul XHR à retour lent, certaines mesures de performances peuvent se détériorer ; cependant, les nouvelles mesures sont désormais précises. (#11738, #11851)
  • La prise en charge de Node 10 a été abandonnée. La version minimale requise du nœud est désormais 12 (#11656)

🤖💥 Modifications majeures pour les utilisateurs programmatiques

Il est peu probable que ces modifications affectent les utilisateurs finaux, mais peuvent être importantes si vous écrivez des configurations personnalisées, des plugins ou si vous traitez la sortie Lighthouse JSON.

  • ConsoleMessages est un [nouvel artefact] (https://github.com/GoogleChrome/lighthouse/blob/a6738e0033e7e5ca308b97c1c36f298b7d399402/types/artifacts.d.ts#L753-L802) qui est une combinaison des anciens artefacts ConsoleMessages et RuntimeExceptions, avec des données étendues sur les éléments enregistrés sur la console. RuntimeExceptions a été supprimé (#11663)
  • Les données DOM "détails des nœuds" autrefois réparties dans les artefacts existants sont désormais rassemblées dans une propriété NodeDetails sur chaque élément (#11474, #11695, #11752).
  • L'artefact ImageElements a été rationalisé pour mieux représenter les données collectées et la façon dont elles sont utilisées (#11703, #11707, #11733).
  • Auparavant, extends: true était autorisé comme alias pour extends: 'lighthouse:default' pour [étendre une configuration] (https://github.com/GoogleChrome/lighthouse/blob/master/docs/configuration.md#config-extension) à partir du fichier de configuration Lighthouse par défaut. L'option booléenne a été supprimée pour préparer la voie à l'extension à partir de n'importe quel fichier de configuration valide (#11835)
  • Une fonctionnalité jamais utilisée pour transmettre les options de la configuration aux rassembleurs a été supprimée pour être compatible avec les modifications futures (#11743)
