DeepTutor v1.3.6

DeepTutor v1.3.6 Release Note

Date de sortie : 2026.05.03 v1.3.6 vise à rendre le routage des modèles explicite dans DeepTutor. Les utilisateurs peuvent choisissez les profils LLM configurés à partir des flux de discussion et TutorBot, des services d'exécution résoudre ces choix sans divulguer les secrets du fournisseur et RAG/base de connaissances La gestion des index est plus défensive lorsque les intégrations persistantes ne sont pas valides.

Faits saillants

Sélection de modèles basée sur le catalogue

  • Le chat peut cibler un modèle configuré - Les tours de chat unifié portent désormais un Sélection de profile_id et model_id via la charge utile WebSocket, session préférences, transformer des instantanés et régénérer les flux.
  • Les paramètres exposent les options LLM sécurisées - le nouveau point de terminaison des options de paramètres renvoie les choix de fournisseur/modèle prêts à être affichés tout en omettant les informations d'identification et secrets de connexion de la réponse.
  • Les remplacements du modèle d'exécution sont limités à chaque tour - les profils sélectionnés sont résolu via le catalogue des fournisseurs pour la demande active sans écrire les choix temporaires sur le disque ou la modification des valeurs par défaut globales.
  • L'interface utilisateur du sélecteur de modèle est partagée - les écrans de discussion et TutorBot utilisent la même chose sélecteur de modèle configuré, avec étiquettes localisées et gestion par défaut du système.

Contrôle du modèle TutorBot

  • Les robots peuvent conserver les sélections de modèles - Les flux de création/mise à jour de TutorBot sont désormais acceptés llm_selection, validez-le par rapport au catalogue configuré et stockez-le avec chaque robot.
  • Les robots en cours d'exécution peuvent recharger leur LLM - la modification du modèle d'un bot met à jour le boucle d'agent actif au lieu de nécessiter un redémarrage complet du bot.
  • L'historique récent des robots est plus stable - L'assemblage de l'historique de TutorBot est désormais trié par horodatage du message avec départage stable avant de prendre le dernier contexte.
  • Les changements d'itinéraire de chat du bot sont plus propres - la page de chat Web s'annule en vol le bot demande et réinitialise l’état de raisonnement transitoire lors du changement de bot.

RAG et fiabilité des connaissances

  • Les vecteurs invalides déclenchent des reconstructions - la réindexation ne traite plus une correspondance la signature du document est réutilisable lorsque l'intégration du magasin de vecteurs existant échoue validation.
  • Les reconstructions complètes utilisent les nouveaux répertoires de versions - base de connaissances complète reconstruit l'écriture dans une nouvelle version d'index plat tout en laissant l'ancien stockage défaillant disponible pour inspection.
  • Les journaux de l'outil RAG peuvent être diffusés vers clients - les exécutions de récupération peuvent transférer les captures Le processus de niveau INFO est journalisé sous forme d'événements d'outil bruts lorsqu'un récepteur d'événements est disponible.
  • Les contrôles de santé des connaissances reconnaissent les mauvaises intégrations - invalide persistant les vecteurs apparaissent plus tôt au lieu de produire des échecs de recherche opaques.

Correctifs du fournisseur et du lancement

  • Les limites des jetons OpenAI Responses sont normalisées - Les appels des réponses API sont désormais mappés style de chat max_completion_tokens et max_tokens à max_output_tokens, correction de l'erreur SDK signalée pour les modèles OpenAI plus récents dans #437.
  • Les chemins compatibles Azure et OpenAI partagent le mappage - à la fois le streaming et Réponses sans streaming Les itinéraires API utilisent le même assistant de conversion.
  • Les ports de lancement proviennent de .env et des variables d'environnement - configuration et lancement les assistants maintiennent désormais le comportement du port backend/frontend aligné autour du projet Fichier .env au lieu des anciens paramètres d'exécution JSON.

Web UX polonais

  • Les noms des compétences sont validés avant la sauvegarde - l'éditeur de compétences supprime les noms, signale les entrées en ligne invalides et empêche les échecs silencieux de API pour les majuscules lettres, espaces, traits de soulignement ou autres caractères non pris en charge.
  • Les modaux de l'éditeur de compétences sont opaques sur tous les thèmes - l'éditeur utilise désormais le jeton d'arrière-plan de la page, évitant le texte qui coule dans les thèmes translucides.
  • La navigation spatiale est plus facile à numériser - Mini-navigation spatiale, ordinateur portable, l'espacement de la banque de questions, des compétences et des listes de sessions a été resserré avec plus de clarté traitement des cartes et des séparateurs. ## Tests
  • Ajout de tests de service de sélection de modèle pour la liste des options sécurisées, les marqueurs actifs, rejet de profil/modèle invalide et remplacements de catalogue non mutants.
  • Ajout de tests d'exécution de tour WebSocket unifiés pour les sélections LLM persistantes, sélections non valides, changement de modèle, instantanés et comportement de régénération.
  • Ajout de TutorBot API et des tests du gestionnaire pour la persistance de llm_selection, validation, rechargement de l'exécution et comportement du modèle par défaut.
  • Ajout de paramètres, d'exécution du fournisseur et de tests de configuration LLM pour le catalogue étendu sélection et priorité de configuration par tour.
  • Ajout de tests RAG et Knowledge-Router pour les magasins de vecteurs invalides, réindexation les décisions de reconstruction et la résolution de la version de stockage.
  • Ajout des tests du convertisseur OpenAI Responses pour les alias de limite de jeton, la priorité, Filtrage None et immuabilité d’entrée.
  • Ajout de tests slug frontend pour la normalisation et la validation des noms de compétences.

Notes de mise à niveau

  • Les Chat et TutorBot clients qui souhaitent un routage de modèle explicite doivent envoyer llm_selection comme { "profile_id": "...", "model_id": "..." }. L'omettre continue d'utiliser la valeur par défaut du système configuré.
  • Les fichiers de configuration de TutorBot peuvent désormais contenir llm_selection. Bot existant les configurations sans ce champ continuent à se charger et les anciennes valeurs model restent utilisable comme remplacement de nom de modèle.
  • Les ports de lancement doivent être configurés dans .env ou dans les variables d'environnement de processus (BACKEND_PORT / FRONTEND_PORT). L'ancien data/user/settings/env.json le bloc de port n'est plus utilisé comme source de port de lancement.
  • Les bases de connaissances avec des vecteurs persistants obsolètes ou invalides peuvent être reconstruites sur le réindexez ensuite même lorsque les signatures des documents n'ont pas changé.
  • Les noms de compétences sont désormais normalisés et validés sous forme de slugs minuscules allant jusqu'à 64 caractères utilisant des lettres, des chiffres et des traits d’union. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.3.5...v1.3.6
