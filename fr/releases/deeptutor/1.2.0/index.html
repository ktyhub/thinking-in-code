DeepTutor v1.2.0

DeepTutor v1.2.0 Release Note

Date de sortie : 2026.04.20

Faits saillants

Book Engine — Compilateur multi-agents « Living Book »

Introduction d'un tout nouveau Book Engine (deeptutor/book/) qui compile les entrées des utilisateurs (historique des discussions, blocs-notes, bases de connaissances et intentions de forme libre) dans des « livres vivants » interactifs, structurés, basés sur des blocs. Le moteur est parallèle à ChatOrchestrator et pilote un pipeline multi-agents en cinq étapes :

  1. Idéation — un LLM propose un plan de livre à partir de l'intention de l'utilisateur et du matériel source.
  2. Exploration des sources — un agent SourceExplorer effectue une récupération RAG approfondie et des contrôles de santé de la base de connaissances (kb_health.py) pour faire apparaître les passages les plus pertinents.
  3. Synthèse de la colonne vertébrale — un agent SpineSynthesizer fusionne la proposition avec les sources explorées dans une arborescence de chapitres/pages (Spine → Chapter → Page).
  4. Planification de page — un agent PagePlanner conçoit chaque page comme une séquence ordonnée de blocs tapés.
  5. Compilation de blocs — un BookCompiler distribue chaque bloc à son générateur dédié. 14 types de blocs sont livrés dans la phase 1 : texte, légende, quiz, cartes flash, code, figure, immersion approfondie, animation, interactif, chronologie, graphique conceptuel, section, note utilisateur et un espace réservé pour les blocs en cours de compilation. Chaque générateur possède ses propres invites YAML bilingues (en/zh) et peut appeler les assistants RAG pour obtenir du contenu ancré. L'interface utilisateur Web (web/app/(workspace)/book/) comprend un assistant BookCreator (intention → proposition → confirmation du dos), un SpineEditor pour la réorganisation des chapitres par glisser-déposer, un PageReader avec un rail de navigation par plan et des rendus par bloc (graphiques conceptuels rendus sous forme de diagrammes interactifs dirigés par force, quiz avec notation en ligne, cartes flash avec animations inversées, etc.), un BookProgressTimeline pour le suivi de la compilation en temps réel, un BookChatPanel pour les questions et réponses en contexte et un BookHealthBanner qui avertit lorsque la base de connaissances sous-jacente n'est pas saine. Un flux WebSocket par livre diffuse les événements de compilation à tous les clients connectés. Backend : POST /api/v1/book/create, POST /confirm-proposal, POST /confirm-spine, POST /compile-page, GET /list, GET /{book_id}, DELETE /{book_id} et WS /ws/{book_id}. CLI : deeptutor book create, deeptutor book list, deeptutor book show, deeptutor book delete. ### Apprentissage guidé hérité supprimé Le module deeptutor/agents/guide/ (gestionnaire de guides, 4 agents, 8 invites YAML) et l'intégralité de l'interface utilisateur Web /guide (composants, hooks, types, routeur API — ~ 5 300 lignes) ont été supprimés. Le Book Engine remplace l'apprentissage guidé par une architecture plus riche et plus extensible.

Espace de travail de co-rédaction multi-documents

Co-Writer n'est plus un bloc-notes contenant un seul document. Chaque document dispose désormais de son propre répertoire persistant sous data/user/workspace/co-writer/documents/ avec des écritures de manifeste atomique (CoWriterStorage). L'interface utilisateur Web redirige vers les pages par document (/co-writer/[docId]) et la barre latérale affiche une section CoWriterRecent pour un accès rapide. Les nouveaux points de terminaison API gèrent l’intégralité du document CRUD (GET /list, POST /create, GET /{doc_id}, PATCH /{doc_id}, DELETE /{doc_id}).

Visualisations HTML interactives

La fonctionnalité Visualiser prend désormais en charge un quatrième type de rendu — html — aux côtés de svg, chartjs et mermaid. Lorsque le LLM détermine que la demande de l'utilisateur nécessite « une interaction de l'utilisateur + des changements d'état + un mélange de texte/graphiques » (par exemple, des démos déplaçables, des procédures pas à pas, des exercices pratiques clickable), il produit une page HTML à fichier unique autonome qui s'affiche dans une iframe. Une passe de validation locale (is_valid_html_document) vérifie la sortie avant de la diffuser ; si le modèle renvoie quelque chose qui ne peut pas être rendu, un modèle de secours stylisé est injecté à la place. L'étape de révision LLM est ignorée pour les pages HTML (ce qui permet d'économiser 30 à 60 secondes de latence avec une perte de qualité négligeable). Un nouveau mode de contrainte figure restreint le LLM à svg/chartjs/mermaid uniquement — utilisé en interne par le bloc figure du Book Engine.

Banque de questions @-Mention dans le chat

Un nouveau composant QuestionBankPicker permet aux utilisateurs de @-mentionner des entrées individuelles de la banque de questions directement dans l'éditeur de chat. Les entrées sélectionnées sont résolues par le runtime (_build_question_bank_context) dans un contexte Markdown structuré - comprenant le texte des questions, les options, les réponses de l'utilisateur/de référence et les explications - et injectées avec les références du bloc-notes et de l'historique afin que le LLM puisse raisonner sur les performances spécifiques du quiz passé.

Externalisation rapide – Phase 2

Poursuite de la migration des chaînes LLM codées en dur vers des fichiers YAML éditables :

  • answer_now — Les fonctionnalités question, research, solve et visualize chargent désormais leurs invites rapides à partir de prompts/{en,zh}/answer_now.yaml.
  • agents portables — Les invites analysis_agent et summarize_agent ont été déplacées vers YAML ; les modules Python délèguent désormais au gestionnaire d'invites.
  • Les modules de capacités (_answer_now.py, deep_question.py, deep_research.py, deep_solve.py, visualize.py) ont été allégés en conséquence.

Module de co-écriture restructuré

Déplacement de deeptutor/agents/co_writer/ vers deeptutor/co_writer/ (module de service de niveau supérieur) pour refléter sa nature autonome aux côtés de deeptutor/book/.

Révision de la barre latérale

  • Entrée de navigation « Apprentissage guidé » remplacée par Livre (icône de la bibliothèque).
  • Ajout des sections de la barre latérale BookRecent et CoWriterRecent avec navigation par élément.
  • L'état réduit/agrandi de la barre latérale a été levé dans AppShellContext afin qu'il persiste lors des transitions d'itinéraire.
  • Barre latérale réduite raffinée : logo + bascule d'agrandissement superposés avec révélation en survol, bouton circulaire "Nouveau chat", séparateurs subtils et espacement cohérent.

Actualisation du panneau de configuration et des fonctionnalités

Mise à jour des définitions de types partagés et des panneaux de configuration dans Quiz, Research, Visualize et Math Animator pour s'aligner sur les nouvelles options de fonctionnalités (par exemple, mode de rendu html, touches de paramètres régionaux étendues). TracePanels dans l'interface utilisateur de chat a reçu des améliorations de mise en page et de style.

README et mise à jour de la localisation

Les neuf fichiers README localisés (AR, CN, ES, FR, HI, JA, PT, RU, TH) ont été mis à jour pour refléter le Book Engine, le co-auteur multi-documents et d'autres fonctionnalités du v1.2.0.

Corrections de bugs

  • Crash au moment de l'importation du gestionnaire de canaux — loguru.logger a été importé au niveau du module, provoquant ImportError lorsque les dépendances de TutorBot étaient absentes. Remplacé par une fonction d'usine paresseuse _logger().
  • Obsolète test_app_facade.py — suppression d'un module de test obsolète faisant référence à des chemins de code supprimés.
  • __init__.py manquant dans les packages de test — ajout de fichiers d'initialisation dans tests/agents/, tests/api/, tests/cli/, tests/knowledge/, tests/scripts/, tests/services/llm/, tests/services/memory/, tests/services/search/, tests/services/session/ et tests/tools/ pour corriger la résolution d'importation.

Suite de tests et CI

  • CI installe désormais requirements/tutorbot.txt et le met en cache parallèlement aux exigences du serveur/cli.
  • Suppression du test_app_facade obsolète du manifeste de test CI.
  • Mise à jour du conftest.py pour les tests de pipeline RAG ; parité d'invite actualisée, temps d'exécution des fonctionnalités, configuration de la sonde LLM, fournisseur d'usine, catalogue de modèles, chargeur de configuration et tests de service de bloc-notes pour correspondre aux importations restructurées.
  • Ajout des ressources favicon et apple-touch-icon pour les métadonnées PWA. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.1.2...v1.2.0
