DeepTutor v1.3.1

DeepTutor v1.3.1 Release Note

Date de sortie : 2026.04.28 v1.3.1 est une version de stabilité après v1.3.0. Il se concentre sur un routage RAG plus sûr, une validation d'intégration plus forte, des redémarrages Docker/TutorBot plus fiables et un ensemble de correctifs Web UX petits mais importants.

Faits saillants

Routage RAG et base de connaissances plus sûr

  • La base de connaissances sélectionnée est désormais dans l'état système trusted - Les appels RAG de chat ne laissent plus le LLM invente ou remplace kb_name ; le modèle ne voit qu'un query, et DeepTutor l'achemine vers la base de connaissances sélectionnée dans l'interface utilisateur/la session.
  • Pas de repli silencieux lorsque RAG n'a pas de Ko - si RAG est activé mais qu'aucun Ko n'est sélectionné, le tour ignore la récupération de la base de connaissances avec un message de progression clair à la place d'interroger accidentellement un état obsolète/par défaut.
  • Les alias KB par défaut sont gérés de manière cohérente - default, current, selected et ses équivalents chinois sont résolus en Ko par défaut configuré pour appels d'outils, liste de fichiers et réindexation des API, tandis qu'un vrai KB nommé default l'emporte toujours sur le pseudonyme.
  • Les ajouts de documents incrémentiels utilisent la couche de service - l'ajout de fichiers se fait désormais via RAGService.add_documents, en gardant le comportement d'ajout/recherche/réindexation activé le même chemin de fournisseur et de version d’index.
  • Les composants internes de RAG sont plus faciles à maintenir - le pipeline LlamaIndex a été divisé en modules ciblés pour le chargement, l'intégration, le stockage, les erreurs et l'orchestration ; la récupération multi-requêtes intelligente réside désormais dans SmartRetriever.

Intégration et fiabilité de l'index

  • Les réponses d'intégration sont validées avant utilisation - DeepTutor les rejette désormais vecteurs supprimés, valeurs nulles, valeurs non numériques, valeurs non finies et dimensions incohérentes avant qu’elles n’atteignent LlamaIndex.
  • Les tests de connexion sondent le comportement du lot - l'intégration des tests de fumée envoie désormais un petit lot, attrapant les fournisseurs qui ne renvoient qu'un seul vecteur ou changement dimensions entre les entrées.
  • Les mauvais index échouent avec des messages exploitables - Incompatibilité de vecteur nul ou de forme les échecs de récupération renvoient désormais un indice de réindexation au lieu d'exposer des informations de bas niveau. Erreurs de style NoneType * float.
  • Le statut de l'index est moins bruyant lors des écritures - version vide en cours les répertoires ne marquent plus les nouvelles bases de connaissances comme needs_reindex et échouent vides les dossiers de version sont nettoyés lorsque cela est possible.
  • Les exemples d'intégration ont été clarifiés - services/embedding/.env.example documente désormais la sémantique complète des URL des points de terminaison et des exemples concrets de fournisseurs pour OpenAI, SiliconFlow, Ollama, Cohere, Jina, vLLM, Azure OpenAI, DashScope et Passerelles de style OpenAI-SDK.

Docker, mémoire et environnement d'exécution TutorBot

  • Les images Docker peuvent exposer la version de l'application - APP_VERSION est transmis aux variables d'environnement d'exécution backend et frontend.
  • La mémoire partagée a son propre volume Docker - les fichiers de composition sont maintenant montés ./data/memory:/app/data/memory ; Les documents de persistance README ont été mis à jour.
  • La migration de la mémoire est plus sûre - les anciens fichiers SUMMARY.md et PROFILE.md sont copié dans data/memory même si le répertoire cible existe déjà, tandis que les fichiers cibles existants sont conservés.
  • Les actualisations de la mémoire sont sérialisées - Réécritures simultanées du profil/résumé maintenant exécuter sous un verrou pour éviter les écritures accélérées.
  • L'intention de redémarrage de TutorBot est préservée - l'arrêt progressif du serveur conserve chacun L'indicateur auto_start du bot est intact pour le prochain redémarrage de Docker/hôte, alors qu'il est manuel les arrêts désactivent toujours le démarrage automatique.
  • TutorBot partage la mémoire à long terme - les agents bots démarrés reçoivent désormais le répertoire de mémoire partagée au lieu de fonctionner sans lui.

Correctifs UX Web et création

  • Envoi de messages sécurisé par IME - les compositeurs de chat ne soumettent plus lorsque Enter est étant utilisé pour confirmer les candidats IME chinois/japonais/coréens.
  • La liste de connaissances reste à jour dans le chat - la page de chat recharge les métadonnées de la base de connaissances sur le focus, l'affichage de la page et la visibilité changent, donc les bases de connaissances nouvellement créées ou réindexées apparaissent sans actualisation complète.
  • L'aperçu Markdown protège les pseudo-balises - Balises inconnues de type HTML telles que <think> sont échappés pour l'affichage tout en préservant le nombre de lignes source pour synchronisation éditeur/aperçu.
  • La sortie du Co-Writer supprime les balises de raisonnement - fermées, alias, attribuées et Les blocs <think> / <thinking> non fermés sont supprimés de la sortie d'édition finale.
  • L'initialisation du thème s'exécute avant l'hydratation - le script du thème est rendu depuis le serveur afin que la préférence sombre/clair soit appliquée avant que React ne s'hydrate.
  • Les commentaires sur les connaissances de l'interface utilisateur sont plus clairs - les puces de la version d'index ont des étiquettes plus propres, les index actifs vides ayant échoué sont expliqués, et les 404 de l'interface utilisateur la plus récente par rapport à l'ancienne Le backend Docker suggère désormais d'extraire/recréer le conteneur.
  • Le retour sur la page mémoire est plus clair - Les appels d'actualisation distinguent "coché, non mises à jour à long terme" des échecs réels.

Démarrage et robustesse de Windows

  • Les flux CLI/serveur tolèrent les pages de codes héritées - Scripts de démarrage et API les coureurs utilisent des flux de texte sécurisés pour éviter les plantages Unicode sous Windows paramètres régionaux tels que GBK/CP936.
  • Les processus enfants héritent d'un codage plus sûr - Ensemble de chemins de démarrage Web/visite PYTHONIOENCODING=utf-8:replace.
  • Les fichiers d'environnement frontend générés sont UTF-8 - start_web.py écrit maintenant web/.env.local avec encodage UTF-8 explicite.
  • GHCR compose extrait des images plus fraîches - docker-compose.ghcr.yml utilise désormais pull_policy: always pour l’image publiée.
  • Les documents/locales ont été actualisés - Les notes de persistance README ont été mises à jour, le Un lien README en polonais a été ajouté et la copie de l'interface utilisateur en anglais/chinois a disparu étiquettes pour les connaissances, la mémoire, les modèles d'âme TutorBot et les brouillons du co-auteur. ## Tests
  • Couverture ajoutée/mise à jour pour le routage du chat RAG KB, les alias KB par défaut, les connaissances fichier/réindexation des API, intégration de la validation par lots, vecteur invalide LlamaIndex échecs, état de la version d'index en cours, ajout incrémentiel de disposition de stockage, Démarrage automatique/mémoire partagée de TutorBot, migration de mémoire, encodage Windows CLI, Gestion du clavier IME, balise de démarque escaping et nettoyage des balises de raisonnement.

Notes de mise à niveau

  • Les utilisateurs de Docker doivent extraire et recréer le conteneur afin que l'interface utilisateur Web et le backend Les connaissances API restent synchronisées.
  • Si une base de connaissances a été indexée avec un fournisseur d'intégration défectueux ou modifié, utilisez Réindexez à partir de la page Connaissances après avoir corrigé les paramètres d'intégration.
  • Si vous conservez les données manuellement, ajoutez le nouveau montage de mémoire partagée : ./data/memory:/app/data/memory. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.3.0...v1.3.1
