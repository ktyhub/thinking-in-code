DeepTutor v1.3.10

DeepTutor v1.3.10 Release Note

Date de sortie : 2026.05.10 v1.3.10 est une version de fiabilité ciblée pour les problèmes signalés après v1.3.9. Il restaure un accès à distance plus fluide au Docker et fait fonctionner les points de terminaison LLM auto-signés de manière cohérente parmi les fournisseurs soutenus par SDK, protège les extraits de code contre les citations réécrit et divise Matrix E2EE en une dépendance opt-in explicite.

Faits saillants

Récupération à distance de Docker et CORS

  • Le Docker mono-utilisateur à distance fonctionne à nouveau immédiatement - quand AUTH_ENABLED=false, DeepTutor accepte désormais les origines du navigateur via HTTP/HTTPS donc Les interfaces LAN ou serveur distant n'atteignent plus le CORS v1.3.8/v1.3.9 régression rapportée au #463.
  • Les déploiements authentifiés restent explicites - lorsque AUTH_ENABLED=true, CORS nécessite toujours une liste blanche concrète via CORS_ORIGIN ou CORS_ORIGINS, en préservant la limite de sécurité de l'authentification authentifiée.
  • Plusieurs origines de déploiement sont prises en charge - CORS_ORIGINS accepte les virgules ou des valeurs séparées par une nouvelle ligne, et les deux fichiers Docker Compose transmettent le paramètre jusqu'au conteneur backend.
  • Les paramètres ne suppriment plus les indicateurs de réseau - CORS_ORIGIN, CORS_ORIGINS et DISABLE_SSL_VERIFY fait partie de l’ordre d’écriture canonique .env.

Fournisseur TLS et correctifs de rendu

  • DISABLE_SSL_VERIFY atteint désormais les chemins OpenAI SDK - Compatible OpenAI, Azure OpenAI, l'exécuteur, TutorBot et l'intégration héritée SDK clients reçoivent tous un httpx.AsyncClient(verify=False) partagé lorsque le drapeau est activé, corrigeant Points de terminaison HTTPS LLM auto-signés signalés dans #464.
  • La production bloque toujours les contournements TLS dangereux - ENVIRONMENT=prod ou ENVIRONMENT=production rejette DISABLE_SSL_VERIFY, avec un seul avertissement connecté en utilisation hors production.
  • Les blocs de code conservent les index des tableaux intacts - Linkification des citations Markdown maintenant masque le code clôturé et en ligne avant de réécrire les références, donc values[0] reste code au lieu de devenir un lien de citation #references (#468).

Compatibilité d'installation de Matrix

  • Matrix n'installe plus E2EE par défaut - le standard matrix supplémentaire et requirements/matrix.txt utilise désormais simplement matrix-nio, évitant ainsi le Échecs de build python-olm / libolm observés sur macOS Python 3.14 et Apple Clang 21 (#462).
  • Les salles cryptées sont un module complémentaire explicite - installez deeptutor[matrix-e2e] ou requirements/matrix-e2e.txt lorsque le support E2EE est nécessaire et que Libolm est disponible.
  • Les échecs d'exécution sont plus clairs - La matrice est par défaut en mode non-E2EE, et l'activation d'E2EE sans dépendances cryptographiques génère désormais une installation exploitable message au lieu d'échouer au moment de l'importation.

Compatibilité d'exécution multi-utilisateurs

  • Les chemins de l'espace de travail par défaut restent stables en dehors de la portée de l'utilisateur - en l'absence de courant le contexte multi-utilisateur est actif, la résolution du chemin revient aux données par défaut espace de travail plutôt que de forcer une portée d’administrateur.
  • Les hooks de test et Monkeypatch hérités restent disponibles - session et paramètres les routeurs conservent les cales de compatibilité utilisées par les tests et les anciennes intégrations.
  • Les artefacts de l'agent local sont ignorés - .claude/ est désormais exclu de Git donc les arbres de travail locaux et les métadonnées des agents n'entrent pas accidentellement dans les versions. ## Tests
  • Ajout de tests de paramétrage CORS pour les origines distantes non authentifiées et authentifiées listes autorisées explicites.
  • Ajout de tests OpenAI SDK HTTP-client partagés sur le fournisseur principal, Azure, exécuteurs, TutorBot et adaptateurs d’intégration.
  • Ajout de tests d'affichage Markdown pour les citations en prose, le code clôturé, le code en ligne, et des citations explicites et rétroactives.
  • Ajout de tests fractionnés de dépendance Matrix pour garder les installations par défaut exemptes de matrix-nio[e2e].
  • Réexécution des tests Python ciblés, des tests de nœuds Web, des vérifications Ruff et des espaces blancs diff validation du correctif de version.

Notes de mise à niveau

  • Si vous exécutez Docker distant avec AUTH_ENABLED=false, aucun paramètre CORS supplémentaire n'est requis pour les origines normales du navigateur HTTP/HTTPS.
  • Si vous exécutez un déploiement partagé ou authentifié avec AUTH_ENABLED=true, définissez CORS_ORIGIN ou CORS_ORIGINS à la ou aux origines exactes du frontend, par exemple https://learn.example.com.
  • Utilisez le DISABLE_SSL_VERIFY=true uniquement pour les tests locaux, auto-signés ou avec espace d'air Points de terminaison LLM. Il reste bloqué dans ENVIRONMENT=prod et ENVIRONMENT=production.
  • Les installations Matrix sont désormais non-E2EE par défaut. Pour les salles Matrix cryptées, installez .[matrix-e2e] ou requirements/matrix-e2e.txt, assurez-vous que libolm est présent et définissez e2ee_enabled=true dans la configuration du canal Matrix.
  • Si vous avez précédemment installé .[matrix] uniquement pour obtenir Matrix non crypté messagerie, la réinstallation après cette version ne devrait plus nécessiter de configuration native outils de construction Libolm.
