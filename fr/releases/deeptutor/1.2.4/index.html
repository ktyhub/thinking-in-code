DeepTutor v1.2.4

DeepTutor v1.2.4 Release Note

Date de sortie : 2026.04.25

Faits saillants

Prise en charge de plus de formats de pièces jointes dans le chat

Le pipeline de pièces jointes de documents v1.2.3 a été étendu au-delà des fichiers Office. Les pièces jointes de discussion acceptent désormais les mêmes formats de type texte que le routeur d'ingestion de la base de connaissances : Markdown, texte brut, journaux, JSON/YAML/TOML, CSV/TSV, LaTeX/BibTeX, HTML/XML/SVG, feuilles de style, scripts et fichiers de code source courants (.py, .js, .ts, .tsx, .java, .cpp, .go, .rs, .sql, .sh et plus).

  • Parité backend avec routage KB — deeptutor/utils/document_extractor.py importe FileTypeRouter.TEXT_EXTENSIONS, donc les pièces jointes de discussion et les téléchargements KB partagent une source de vérité pour les formats texte/code. FileTypeRouter.decode_bytes() centralise la chaîne de repli UTF-8 / UTF-8-BOM / GBK / GB18030 / Latin-1 / CP1252.
  • SVG comme source lisible — .svg a été ajouté à l'ensemble d'extensions de texte RAG et est traité comme une pièce jointe de document au lieu d'une image de vision, permettant au LLM d'inspecter la source XML tandis que l'interface affiche toujours un aperçu miniature sécurisé.
  • Pièce jointe typée UX — web/lib/doc-attachments.ts expose désormais OFFICE_EXTS, TEXT_LIKE_EXTS, la détection SVG, un repli MIME/extension plus riche et des icônes spécifiques à la catégorie pour le code, le shell, JSON, la configuration, les données, le balisage, les feuilles de style, le texte brut, les documents Office et SVG.
  • Copie de Composer mise à jour : l'indicateur de glisser-déposer annonce désormais "Images, documents Office, code et texte" au lieu de l'ancienne liste Office uniquement.

Visite guidée de la configuration en une seule commande

scripts/start_tour.py est passé d'un simple assistant de configuration à un chemin de nouvelle installation en 7 étapes qui peut détecter l'environnement local, installer les dépendances, puis guider la configuration du fournisseur.

  • Étape d'installation des dépendances — la visite vérifie Python, uv, Node.js et npm ; installe les exigences du backend, installe DeepTutor en mode modifiable et exécute le frontend npm install avec une sortie de terminal en direct.
  • Compatibilité uv pip (#376) — L'installation des dépendances Python préfère désormais uv pip lorsqu'il est disponible et lie --python <current-interpreter> afin que les packages atterrissent dans l'interpréteur exécutant la visite au lieu d'un .venv / $VIRTUAL_ENV sans rapport.
  • Détection Windows npm (#381) — Les invocations npm utilisent npm.cmd sous Windows, corrigeant les vérifications de version et installant des commandes sur les systèmes où npm est exposé en tant que cale de commande plutôt qu'en tant qu'exécutable.
  • Choix LLM basés sur le registre du fournisseur — l'assistant lit désormais le registre complet PROVIDERS, regroupe les fournisseurs par mode, met en évidence les services communs et inclut des options plus récentes telles que custom_anthropic, OpenRouter, SiliconFlow, Volcengine/BytePlus, GitHub Copilot, OpenAI Codex, lama.cpp, OVMS, MiniMax, Mistral, Qianfan, Step Fun et Xiaomi MiMo.
  • Conseils de recherche et de configuration — Serper est disponible dans la liste des fournisseurs de recherche ; La version Azure/API et les invites de proxy affichent désormais des instructions en ligne en anglais et en chinois.
  • Terminal à liste longue UX — scripts/_cli_kit.py affiche de longs menus de sélection dans une fenêtre défilante avec des indicateurs « plus au-dessus/en dessous », évitant ainsi les lignes de terminal obsolètes lorsque la liste des fournisseurs dépasse la hauteur de l'écran.

Exportation de démarques de chat

La page de discussion comporte désormais une action Télécharger Markdown à côté de « Enregistrer dans le bloc-notes » et « Nouvelle discussion ». web/lib/chat-export.ts sérialise la conversation en cours sous forme de Markdown avec un titre, un horodatage d'exportation ISO, des en-têtes de rôle, des étiquettes de capacité et des métadonnées de pièce jointe, puis la télécharge avec un nom de fichier horodaté et nettoyé. Cela offre aux utilisateurs un chemin d'exportation local léger pour partager, archiver ou déplacer une conversation vers des notes externes.

Polonais de l'interface utilisateur de gestion de la base de connaissances

La page Connaissances a été resserrée pour une gestion quotidienne plus dense :

  • Les zones de dépôt de création et de téléchargement sont désormais des cartes pointillées plus simples avec des résumés concis de la politique de téléchargement en ligne.
  • Les cartes KB sont passées de quatre grands panneaux de statistiques à des lignes compactes affichant le nombre de documents, l'état de préparation de l'index, l'heure de la dernière mise à jour, le fournisseur, le modèle d'intégration, la progression en direct et le chemin de stockage.
  • Les actions par défaut/suppression ont été simplifiées visuellement, réduisant la hauteur de la carte et facilitant l'analyse des grandes listes de Ko.

Actualisation de la documentation et de la localisation

La famille README a été mise à jour pour correspondre à la nouvelle histoire d'installation et à la surface du fournisseur :

  • Polish README — assets/README/README_PL.md ajoute une traduction polonaise complète du projet README (#379).
  • Documents de configuration — le README principal et les README multilingues décrivent désormais la visite guidée comme le chemin de nouveau clone recommandé : créez un environnement Python, exécutez python scripts/start_tour.py, puis utilisez python scripts/start_web.py pour le lancement quotidien.
  • Documents du fournisseur : les tableaux des fournisseurs ont été actualisés pour le registre des fournisseurs v1.2.3, y compris custom_anthropic, les points de terminaison canoniques de MiniMax, les fournisseurs de plans de codage, les fournisseurs locaux et les notes d'authentification clarifiées pour OpenAI Codex / GitHub Copilot.
  • Sections versions/actualités — les README multilingues incluent désormais les résumés v1.2.2 et v1.2.3, un guide de contribution et le jalon de la communauté des 20 000 étoiles.

Corrections de l'interface utilisateur et du thème

  • ** Popovers sensibles au thème ** — Les menus de capacité/outil/référence/compétence du compositeur utilisent désormais --popover plus le flou d'arrière-plan au lieu de --card, améliorant le contraste dans le thème Glass et les contextes de popover sombres.
  • Astuces de couleurs natives : les racines des thèmes clair, foncé, Neige et Verre déclarent le bon color-scheme, améliorant ainsi les contrôles natifs et les surfaces rendues par le navigateur.
  • Hydratation à défilement fluide — le défilement fluide global est désormais protégé par html[data-scroll-behavior="smooth"], avec l'attribut défini par la disposition racine pour éviter de l'appliquer involontairement.
  • Dimensionnement du logo de la barre latérale — Les images du logo de la barre latérale épinglent désormais les classes de largeur/hauteur explicites pour éviter de petits changements de disposition.

Nettoyage

Suppression du pointeur de sous-module nanobot obsolète et du stub scripts/extract_numbered_items.sh obsolète du référentiel. La base de code v1.2.x s'appuie désormais sur l'extraction de documents dans l'arborescence et les chemins de routage RAG au lieu de cet assistant existant.

Extension de la suite de tests

  • Extraction de documents backend — tests/utils/test_document_extractor.py couvre désormais le texte brut, la source Python, JSON, CSV, Markdown, l'entrée UTF-8-BOM, le décodage de secours GBK et l'extraction de source SVG.
  • Classification des pièces jointes frontales — web/tests/doc-attachments.test.ts couvre désormais l'acceptation du texte/code, le routage SVG en tant que document, la détection des noms de fichiers SVG insensibles à la casse et les nouvelles catégories d'icônes pour le code, JSON, la configuration, le shell, les données, le balisage, les feuilles de style et SVG.
