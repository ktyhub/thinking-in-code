DeepTutor v1.5.17

DeepTutor v1.5.17 Release Note

Date de sortie : 2026.08.25 v1.5.16 a connecté une bibliothèque MarginNote et a mis un terme à une série d'échecs de passerelle. Celui-ci change l'appartenance d'un Partenaire : il cesse d'être une ressource à l'échelle du déploiement que seul un administrateur peut toucher et devient quelque chose que chaque membre crée, possède et avec lequel il tient ses propres conversations privées - un administrateur prête toujours les siennes via des subventions. Autour de cela se trouvent une base de connaissances qui suit les dépôts GitHub, Antigravity CLI sous Mes agents, un code QR WeChat dessiné dans le navigateur au lieu d'un fichier journal et un conteneur qui conserve les extras facultatifs que vous avez déclarés. Les partenaires existants continuent de travailler et migrent eux-mêmes ; le seul changement de comportement concerne les utilisateurs non-administrateurs, qui peuvent désormais voir une page Partenaires qui leur était auparavant fermée.

Quoi de neuf

Les partenaires appartiennent aux personnes, pas au déploiement

Chaque itinéraire /api/v1/partners se trouvait derrière une porte d'administration générale, afin qu'un membre puisse parler à un partenaire qu'un administrateur lui avait assigné et rien d'autre. Trois droits s'imbriquent désormais à la place : gérer (son créateur, ainsi que tout administrateur) couvre l'âme, les chaînes, les modèles, les actifs, le cycle de vie et la suppression ; utiliser ajoute toute personne à qui un administrateur l'a attribué et signifie tenir une conversation ; personne d'autre ne peut voir que le partenaire existe - un partenaire sans propriétaire et un partenaire invisible répondent à la fois, donc les identifiants ne peuvent pas être énumérés. Les conversations suivent l'humain, pas le partenaire. Deux personnes qui parlent au même compagnon ne voient jamais les fils de discussion de l'autre, et chaque côté relit dans l'application Web sous son propre compte. Les subventions existent toujours et sont inchangées dans leur forme, mais elles n'offrent désormais que des partenaires gérés par l'administrateur : celui que quelqu'un a construit pour lui-même est à eux de le partager ou non, puisque son SOUL.md est généralement écrit personnellement.

Un compte de chat peut porter votre identité DeepTutor

Un partenaire contacté via QQ ou Telegram ne connaissait auparavant qu'un identifiant d'expéditeur local du canal, de sorte que chaque message entrant était anonyme : il atterrissait dans le pool de threads partagé et le partenaire répondait depuis l'espace de travail d'administration plutôt que depuis la propre bibliothèque de l'expéditeur. Demandez un code à votre partenaire dans l'application Web, envoyez-lui /link <code> depuis le compte de chat que vous souhaitez connecter, et à partir de là, cet expéditeur est vous : la conversation est privée sur votre compte, lisible dans le navigateur, et le partenaire lit vos connaissances, vos cahiers et votre mémoire comme il le ferait dans un tour Web.

Deux partenaires peuvent partager une chaîne

L'état d'exécution du canal (jetons de bot, curseurs d'interrogation longue, références de conversation, magasins de périphériques E2EE) vivait dans un répertoire par canal, et non par partenaire, de sorte que deux partenaires configurés sur le même canal lisaient les informations d'identification de chacun et écrasaient le curseur de l'autre. Un seul d’entre eux pourrait être en ligne. L'état réside désormais sous data/partners/<id>/channels/<channel>/, et l'ancienne arborescence est copiée au premier démarrage lorsque son propriétaire en est certain : le jeton enregistré correspond au jeton configuré d'un partenaire, ou un seul partenaire a ce canal activé. Une véritable égalité permet de se réauthentifier une fois plutôt que de recevoir le compte de quelqu'un d'autre.

Personal WeChat se connecte depuis le navigateur

L'échange de code QR a toujours fonctionné, mais il ne fonctionnait qu'à partir du propre start() du canal et dessinait le code sur la sortie standard du serveur - qui, sur tout déploiement de conteneur, est un journal de supervision que la personne qui configure le partenaire ne peut pas atteindre (#951). Le même échange s'exécute désormais pour l'application Web : appuyez sur Scan pour vous connecter sur la page de la chaîne du partenaire, numérisez et le jeton du bot est écrit dans la configuration du canal côté serveur. Une réponse d'état indique si la connexion a réussi, jamais ce qu'elle a produit. Le terminal imprime toujours un code en guise de solution de repli.

Une base de connaissances peut suivre les référentiels GitHub

Enregistrez un dépôt, une branche et un glob en tant que source GitHub et son Markdown est extrait dans la base de connaissances et resynchronisé à la demande, de sorte que la documentation que vous suivez reste à jour sans la re-télécharger. A contribué en tant que #903; les destinations de téléchargement sont contenues dans le répertoire raw/ de la base de connaissances, puisqu'un segment .. ou un chemin absolu dans une entrée d'arborescence aurait autrement été écrit - et, sur la branche de suppression, supprimé - en dehors de la base.

Antigravity CLI rejoint Mes Agents

Google a retiré Gemini CLI en juin et a orienté ses utilisateurs vers Antigravity CLI, de sorte que toute personne bénéficiant d'un plan Google AI Pro/Ultra ou Gemini Code Assist se retrouvait avec un backend gemini qui n'avait pas de CLI à détecter (#828). agy est désormais un backend à part entière : connectez-le, consultez-le à mi-tour, reprenez ses conversations. Le backend Gemini CLI reste : il fonctionne toujours pour toute personne détenant une clé Gemini API, et une connexion fonctionnelle ne doit pas être interrompue lors de la mise à niveau. ###deeptutor doctor Une commande qui répond « Cet espace de travail est-il prêt à démarrer une session ? » — paramètres, fournisseurs, dépendances, ports. --online envoie également une petite requête au fournisseur de modèles configuré ; --format json imprime le même rapport pour un script ou un agent. A contribué en tant que #959.

Les conteneurs conservent les extras que vous avez déclarés

Un conteneur est jetable, donc docker exec … pip install ".[partners]" survit exactement jusqu'au prochain compose down (#762). Déclarez-les plutôt sur le déploiement – ​​DEEPTUTOR_EXTRAS: "math-animator,partners" et DEEPTUTOR_APT_PACKAGES pour les bibliothèques système – et chaque conteneur démarré à partir de celui-ci les réapplique. Un conteneur chaud paie une recherche de métadonnées par exigence, le cache pip vit sur le volume de données et une roue manquante laisse cette fonctionnalité indisponible plutôt que de suspendre le déploiement.

Les intégrations survivent à un fournisseur à débit limité

La réindexation d'une grande bibliothèque par rapport à un fournisseur à faible RPM brûlait des heures puis mourait sur un 429. Trois choses ont changé : un pool de clés tourne sur provider × model avec un temps de recharge par clé afin qu'une clé limitée n'empoisonne plus l'exécution ; un budget de nouvelle tentative attend Retry-After au lieu de s'épuiser sur une fenêtre glissante ; et un régulateur à l'échelle du processus sérialise l'intervalle plus la publication lors des réindexations simultanées, ce qui a fait échouer une requête qui a réussi manuellement dans l'application. A contribué en tant que #962.

Fenêtres

L'analyse MinerU a décodé la sortie de son sous-processus avec la valeur par défaut de la plate-forme – GBK sur une installation zh-CN – et est morte sur le premier octet non-ASCII ; son moteur de rendu PDF multithread a corrompu séparément le tas. Les deux sont corrigés, la protection de rendu s'étendant uniquement à Windows (#844). Les écritures atomiques réessayent désormais un PermissionError transitoire à partir d'un antivirus ou d'un indexeur contenant la cible, et l'exécution de code fonctionne sur un hôte Windows (#964).

Assorti

  • L'effort de raisonnement s'effectue par conversation. Le contrôle au niveau du modèle de v1.5.9 peut désormais être remplacé pour une seule conversation (#641, contribué sous le nom de #958).
  • L'indexation échoue de manière limitée au lieu de se bloquer. Un fournisseur qui accepte une demande d'intégration et ne la termine jamais a bloqué l'avenir de l'exécuteur pour toujours ; une garde de battement de coeur se lève désormais après une fenêtre délimitée sans progression (#946).
  • Les blocs de mise en page MinerU cessent d'être indexés en tant que contenu. Les en-têtes, pieds de page et numéros de page sont filtrés avant l'ingestion ; un type de bloc non reconnu est indexé plutôt que d'échouer pendant toute l'exécution, donc une version MinerU qui en ajoute un ne peut pas interrompre l'indexation (#949).
  • La transcription vocale accepte ce que Chrome enregistre. audio/webm;codecs=opus est normalisé une fois, à la limite du fil, au lieu d'être rejeté en tant que format inconnu (#945).
  • Les cartes de quiz de maîtrise n'arrivent plus en dessous de la ligne de flottaison. Le spectateur monte après la fermeture de la fenêtre de défilement post-stream (#960), et un quiz dont les options répètent une étiquette ou une réponse est rejeté lors de l'inscription plutôt que d'être affiché comme une carte sans réponse (#956).
  • Un parcours d'apprentissage garde son nom. Trois surfaces l'ont chacune dérivé du premier module, donc reconstruire une carte a renommé le chemin et les trois pourraient être en désaccord ; une fonction répond maintenant, et la dérivation est la solution de secours, jamais l'enregistrement.
  • Un outil qui change ce sur quoi le tour opère en premier. Le changement de chemin de maîtrise à mi-tour a laissé les autres appels liés à l'état avec lequel le tour a commencé ; le répartiteur exécute désormais les outils de reliure, relie à nouveau tout le reste, puis exécute les outils de pause en dernier.
  • Les réponses LightRAG locales citent leurs sources (#754), et le pipeline LlamaIndex local ne gèle plus sa décision de barre de progression au moment de l'importation (#864).
  • Azure OpenAI accepte le point de terminaison que le portail vous remet. Une URL …/openai/deployments/<name>/chat/completions classique est réduite à la surface /openai/v1, donc le chat cesse de répondre à 404 Resource not found pendant que la sonde des paramètres passe.
  • Gemini intègre les images là où le modèle le prend en charge et refuse contents pour celles qui ne le font pas plutôt que de publier les parties que le point final rejettera (#814).
  • Une page peut demander si une fonctionnalité est installée. Les fonctionnalités servies par le plugin telles que la salle de pratique Whisper ont été proposées par une installation de stock qui ne pouvait pas les honorer, et le tour est revenu Unknown capability (#963).
  • Le package autonome CLI déclare ce qu'il importe réellement (#954).

Notes de mise à niveau

pip install -U deeptutor ; Les utilisateurs de Docker tirent ghcr.io/hkuds/deeptutor:latest. Pas de réindexation et pas de migration manuelle.

  • Les utilisateurs non administrateurs bénéficient d'une page Partenaires. Dans un déploiement multi-utilisateurs, les membres peuvent désormais créer et gérer leurs propres partenaires, et leurs conversations avec n'importe quel partenaire sont privées sur leur compte. Les partenaires existants n'ont pas de owner_id et sont donc lus comme étant gérés par l'administrateur - exactement ce qu'ils étaient - donc rien de ce que vous avez configuré ne change de mains.
  • L'état du canal se déplace par partenaire, par copie. Au premier démarrage, l'état sous data/partners/<channel>/ est copié dans data/partners/<id>/channels/<channel>/ lorsque son propriétaire est sans ambiguïté. L'arbre hérité reste intact, donc un mauvais résultat peut être récupéré manuellement ; un partenaire dont la propriété était ambiguë se réauthentifie simplement une fois.
  • Les subventions ne répertorient désormais que les partenaires gérés par l'administrateur. Un partenaire qu'un membre a créé pour lui-même n'apparaîtra pas dans le pool attribuable.
  • Les extras de conteneur sont facultatifs. Rien ne change tant que vous n'avez pas défini DEEPTUTOR_EXTRAS dans votre fichier Compose. Prévisualisez-en un avec python scripts/install_extras.py --dry-run "<name>".
  • Les connexions Gemini CLI continuent de fonctionner. L'antigravité est un backend supplémentaire, pas un remplacement. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.5.16...v1.5.17
