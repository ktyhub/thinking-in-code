# openhuman v0.64.14

# The Files, Memory & Voice Power-Up

This release is a big step forward in day-to-day usability: clearer files and sessions, a major memory evolution, and real-time voice agents—plus a ton of reliability and performance work across the stack. 🎉

## Highlights

### Files & project workspace clarity 🗂️
Agent outputs now land in a visible **Files** folder, you can choose where that folder lives, and the app can surface those generated files directly in-place—making it much easier to find and use what your agent created. Large tool outputs are also handled more safely to keep projects tidy. ([#6820](https://github.com/tinyhumansai/openhuman/pull/6820), [#6825](https://github.com/tinyhumansai/openhuman/pull/6825), [#6833](https://github.com/tinyhumansai/openhuman/pull/6833), [#6868](https://github.com/tinyhumansai/openhuman/pull/6868), [#6947](https://github.com/tinyhumansai/openhuman/pull/6947)) — Thank you @M3gA-Mind and @senamakel!

### Memory v2, imports, and safer organization 🧠
Memory gets a major upgrade: **engine-selectable memory v2**, better lifecycle handling around each turn, and stronger portability when switching engines. The Memory UI and provider cards were modernized (including CortexDB), credits/free-period behavior is more consistent (with top-up prompts), and recall becomes time-zone aware.

Imports and migrations are significantly hardened: clearer “building vs empty” states, smarter batching/retries, better failure visibility with retry controls, more reliable resuming, and improved document ingestion (PDF/Office). Organization also improves with connector-first filing, better GitHub scoping, optional attribution to senders, and multiple erasure/deletion correctness and privacy/security fixes. ### Live voice agents & voice foundations 🎙️
Voice agents are now truly live: talk to Tiny in real time with tool support (including Gemini Live, ElevenLabs, and Sarvam), plus a redesigned Voice agents experience with service cards, settings modals, and app-wide toasts. Under the hood, voice-related inference components were also reorganized for a cleaner foundation. ([#7046](https://github.com/tinyhumansai/openhuman/pull/7046), [#7092](https://github.com/tinyhumansai/openhuman/pull/7092), [#6840](https://github.com/tinyhumansai/openhuman/pull/6840)) — Thank you @senamakel!

### Chat UX upgrades & smoother conversation control 💬
Chat gets a substantial UI uplift: working folder support, per-model thinking controls, real thread titles, richer sidebar context, and clearer run-state cues. Reliability improves too—Stop is more resilient, streaming works even without a progress sink, reply-language directives are consistently sent, and several web chat delivery edge cases are fixed. The app also adds translatable error copy and improves transcript storage formats. ([#7048](https://github.com/tinyhumansai/openhuman/pull/7048), [#7045](https://github.com/tinyhumansai/openhuman/pull/7045), [#6916](https://github.com/tinyhumansai/openhuman/pull/6916), [#7088](https://github.com/tinyhumansai/openhuman/pull/7088), [#7097](https://github.com/tinyhumansai/openhuman/pull/7097), [#7098](https://github.com/tinyhumansai/openhuman/pull/7098), [#6844](https://github.com/tinyhumansai/openhuman/pull/6844), [#7087](https://github.com/tinyhumansai/openhuman/pull/7087), [#6881](https://github.com/tinyhumansai/openhuman/pull/6881), [#6883](https://github.com/tinyhumansai/openhuman/pull/6883)) — Thank you @senamakel and @M3gA-Mind!

### Agent intelligence, tool governance, and turn reliability 🧰
Agents are more robust and predictable: improved tool calling defaults (JSON auto) with a setting, better “finish” verification, fewer false failure classifications, clearer file-read behavior, and multiple fixes around context compaction, reasoning bounds, iteration caps, and hosted-path correctness/telemetry. Tool policy/approval gates were reworked, per-turn tool withholding was added, and timed-out commands now terminate their whole process group.

This also includes targeted fixes for web research budgets, credential scrubber behavior (including avoiding code redaction), handling HTTP status correctly, and improved orchestration behaviors. ### Sessions, scheduling, connectors & integrations 🧩
A new host-injected session store moves per-agent conversations outside the workspace, with follow-ups to ensure clean recovery and slot ownership. Scheduled (cron) runs can now deliver output back to the conversation that requested it. Composio and connectors were streamlined with direct-read paths, module routing improvements, and a configurable disabled mode—plus a deliberate removal of Composio→memory sync as memory evolves. ([#7044](https://github.com/tinyhumansai/openhuman/pull/7044), [#7052](https://github.com/tinyhumansai/openhuman/pull/7052), [#7049](https://github.com/tinyhumansai/openhuman/pull/7049), [#6831](https://github.com/tinyhumansai/openhuman/pull/6831), [#6885](https://github.com/tinyhumansai/openhuman/pull/6885), [#6897](https://github.com/tinyhumansai/openhuman/pull/6897), [#6920](https://github.com/tinyhumansai/openhuman/pull/6920)) — Thank you @senamakel!

### Sandbox, Windows, and platform robustness 🛠️
The Docker sandbox flow was reworked, local jail output is captured outside the project, and sandbox capability reporting and host switches are improved (including `OPENHUMAN_SANDBOX=off`). Windows sees key stability fixes around permission-state normalization and environment forwarding into sandboxed children. TinyComputer browser tasks are now runnable from the app, with additional improvements to reuse what completed tasks learned. ([#6862](https://github.com/tinyhumansai/openhuman/pull/6862), [#6970](https://github.com/tinyhumansai/openhuman/pull/6970), [#6981](https://github.com/tinyhumansai/openhuman/pull/6981), [#6988](https://github.com/tinyhumansai/openhuman/pull/6988), [#6847](https://github.com/tinyhumansai/openhuman/pull/6847), [#6998](https://github.com/tinyhumansai/openhuman/pull/6998), [#7008](https://github.com/tinyhumansai/openhuman/pull/7008), [#7127](https://github.com/tinyhumansai/openhuman/pull/7127)) — Thank you @senamakel, @ajabaabaa, and @YellowSnnowmann!

### Models, routing, search, and local AI direction 🧭
Routing and model selection were tightened across the UI and composer, including honoring provider picks and avoiding offering models/search tools that a session or offline profile can’t use. The tool-search path is expanded beyond the TinyHumans proxy, thinking-level controls are passed through to providers, and uploads are persisted with a preference for native multimodal input.

The local AI story is also simplified: in-app model downloads and Ollama lifecycle management were removed, while continuing to support local inference via user-run endpoints. ([#6978](https://github.com/tinyhumansai/openhuman/pull/6978), [#6996](https://github.com/tinyhumansai/openhuman/pull/6996), [#7004](https://github.com/tinyhumansai/openhuman/pull/7004), [#7026](https://github.com/tinyhumansai/openhuman/pull/7026), [#6908](https://github.com/tinyhumansai/openhuman/pull/6908), [#6911](https://github.com/tinyhumansai/openhuman/pull/6911), [#6987](https://github.com/tinyhumansai/openhuman/pull/6987), [#6858](https://github.com/tinyhumansai/openhuman/pull/6858)) — Thank you @SayrWolfridge, @sx4im, @obchain, and @senamakel!

### Internationalization & onboarding polish 🌍
New locales landed (Japanese and Turkish), Arabic translations were improved with added Arabic README docs, and the overall translation catalog was significantly pruned for maintainability. Onboarding is also shorter and more accurate for the local path. ([#6986](https://github.com/tinyhumansai/openhuman/pull/6986), [#7039](https://github.com/tinyhumansai/openhuman/pull/7039), [#7024](https://github.com/tinyhumansai/openhuman/pull/7024), [#6860](https://github.com/tinyhumansai/openhuman/pull/6860), [#7009](https://github.com/tinyhumansai/openhuman/pull/7009)) — Thank you @tjm8874, @moersoy, @taljeri, @graycyrus, and @senamakel!

### Release engineering, CI health, and build performance 🚀
This range includes a massive internal modernization: waves of refactors moving functionality into shared “tiny*” libraries, vendor pin hygiene, and major dead-code/dependency pruning. CI and tests were stabilized (including clippy/layout gates), redundant tests were removed or consolidated, and performance improvements landed for both runtime and build outputs (including module bundling at build time on every platform).

Release-specific work also improved macOS notarization of module bundles (with signature verification and tests), and headless deployments gained better keyring support. Benchmark tooling and docs expanded substantially, including a cross-harness rig and supporting runbooks and viewers.
