# 代码库内存-mcp v0.10.5

安装和启动版本。如果v0.10.4拒绝为您安装，拒绝写下您的
配置，或者告诉你一些事实证明不正确的事情，这就是要采取的。

其中一些是 **cbm 拒绝其自己的工作**的情况 - 我们自己的安装程序目录
然后二进制被拒绝，我们自己编写的配置条目，后来称为foreign，一个错误
消息指出错误的目录并派人检查一个正常的文件。

## Windows：安装自行拒绝

**安装程序正在创建一个我们自己的二进制文件目录，然后被拒绝。** `install.ps1` 使其成功
带有 `New-Item` 的暂存目录，它继承了 `%TEMP%` 所携带的任何内容。下载的二进制文件
验证自己的目录并拒绝继承的跨帐户突变补助金 - 所以我们交给了我们
自己检查一下我们刚刚弄错的目录。在 Windows VM 上测量：新的暂存目录
在没有受到保护的情况下获得了**五个继承的 ACE**；它现在带有一个仅限所有者的条目。

那就是`acl-grants-cross-account-mutation to S-1-5-21-…`故障。由 **@RoccoZero** 报道，
**@aecesr**、**@Kiborgik** 和 **@nasodaengineer**，他们的更正阻止了我们修复错误
重复两次 — @Kiborgik 警告说，键入沙箱组的 *名称* 会错过合成的 SID
变体，@nasodaengineer 通过证明 ACE 确实存在，反驳了离一 RID 理论
关于继承的 DACL。 **@spam0115** 独立编写了一个工作安装程序，其决定性行是
同样的`icacls /inheritance:r`，并将其交还给我们而不是保留它。

**沙盒应用程序不再阻止守护进程。**祖先行走拒绝任何
`%LOCALAPPDATA%` 上的突变授予条目，包括普通人留下的 AppContainer 身份
安装的软件。在报告的计算机上，阻止条目解析为运输桌面
应用程序——用户无法合理删除任何内容。祖先组件现在可以容忍 AppContainer
包和功能标识；私有运行时目录不断要求准确的当前
用户，不变。方法和仅祖先边界遵循 **@mlandolfi90** 的工作。

## 启动：无法访问守护进程时

- **集合点目录可以通过 `CBM_RUNTIME_DIR` 在发布的版本中重新定位**。以前
  除非启用测试接缝，否则唯一的重定位钩子会被编译出来 - 所以一个*测试*构建
  从 *product* 构建没有开始的地方，以及当默认祖先不可接受时开始
  **每次**调用都失败，包括 `config list`，无法到达设置界面
  并修复它。 （＃1537，＃1574，＃1621）

  **@tmonestudio** 和 **@Carnival-z** 在我们构建它之前各自独立地提出了这一点
  — @tmonestudio in #1574，祖先行走，违规组件名为 @Carnival-z in
  #1621 发现 `CBM_CACHE_DIR` 移动了缓存但从未移动过集合点。两个都已经开了
  拉取请求得出与此更改实现的相同结论；合并的提交积分
  @tmonestudio 按方法名称和变量名称。
- **拒绝消息现在命名实际拒绝的目录。** 祖先行走验证
  它已经在目录中，但打印了即将进入的孩子的名字 - 所以#1537是
  告诉 `.cache` 当主目录拒绝时出现错误，并告诉#1621
  当`/private/tmp`是`cbm-daemon-501`时。两位记者仔细检查了我们的名字，发现了它
干净，如此说道。 **他们是对的，我们几周来一直指出这一点。**现在的消息
  命名包含目录并明确表示不要检查它所指责的目录。

## 错误指出实际拒绝的内容

三项修复，一项投诉：我们的消息没有说明足够的内容来采取行动。

- **`secure CLI coordination could not be created (endpoint)`** 现在打印验证详细信息 —
  拒绝的目录和规则。四名不同的记者报道了这一消息；一个建造了一个
  检测二进制文件发现单个 ACE 是原因。
- **被拒绝的代理配置写入表明目标是什么** - 是否存在以及什么类型的文件
  是的。九种不同的故障关闭条件先前崩溃为一种无法区分的故障。
- 都不打印 `errno`。它是从 119 个站点调用的，并且可能是陈旧的，这正是
  早些时候发布的新闻稿向记者提供了一份捏造的“未找到文件”以供许可决定。

## 我们错误地拒绝触及的配置文件

- **您的 client 注释的 MCP 条目不再被视为外国条目**（#1630、#1582）。开放代码
  在我们写的`command`和`type`旁边写上`"enabled": true`；我们的所有权检查要求
  精确的按键设置匹配，因此具有两个可识别按键的三键条目被归类为某人
  别人的，就不管了——**我们拒绝碰我们自己写的条目**。在一位记者的报道中
  每个 MCP 服务器都携带密钥，因此这是 OpenCode 的正常形状，而不是不寻常的手动编辑：
  任何曾经在用户界面中打开或关闭服务器的人都会受到打击。
- **包含 `*` 或 `&` 的 YAML 值不再被误认为是别名和锚点**（#1631 的一部分）。
  散文星号、描述中的一团、颜文字——所有这些都被拒绝了，就好像它们开始了一个节点一样。
  现在测试是定位的。根源由 **@rg6304** 引起，他单独复制了它，请阅读
  来源，并纠正了我们的假设：我们猜测的结构在失败中没有出现
  文件。这是该报告中的四个结构之一；其余的仍然开放。

## 数据丢失和诊断

- **`uninstall --help` 不再执行真正的卸载** (#1038)。它删除了二进制文件和每个
  询问该命令的作用的人的代理配置。争论前检查警卫
  解析，因此线路上其他地方的 `-y` 无法自动确认正在阻止的破坏。
- **崩溃的工人日志现在存活下来并命名其运行**（#1145、#1130、#1132、#1450、#1133、#1070）。
  六份报告都以同一个死胡同结束：supervisor打印日志路径且文件为0字节，
  因此，能够解释故障的唯一诊断因故障本身而消失。
- **`cli <tool>` 不再阻止永远读取标准输入** (#1359) 对于声明不
  论据。 `--json` 和 `--progress` 在达到 stdin 回退之前被剥离，因此
  `cli list_projects --json` 也挂了——记者更正“无旗帜”不是触发因素
  是对的。

## 可靠性

- **生成重试不再无限制地增长** (**@moffermann**)。我们运送的夹子永远不会
  火，虽然它本来应该增加一倍，但它却自由了——未来的预算增加将意味着
  等待 40 秒并进行重试，以避免出现这种情况。目前的预算均保持不变。
- **两个并发会话不能再分配同一个临时目录**
(**@ertankucukoglu**) — Windows 临时目录帮助程序中的进程全局缓冲区。
- **仪表化测试版本现在知道它们已被仪表化** (**@moffermann**)。询问了四个地方
  这个问题有四种不同的方式，所以一些消毒通道测量了仪器代码
  本地时序预算。

## 正确性

- 当存储库有更多路径时，**`check_index_coverage` 不再将每个路径报告为不可用**
  超过 2,000 个被忽略的文件 (**@SunneeYang**)。被截断的目录被视为没有证据
  每个路径的答案都存在，包括具有当前哈希记录的路径。
- **通过字符串连接构建的 Go 路由现在可以解析** (**@AmirF194**)。注册处理程序
  `base + "/orders"` 没有生成可用的路由路径；现在已经恢复了字面量的一半，并且有一条路径
  从变量组装而成的仍然是未解决的而不是捏造的。
- **重复可变长度节点的 Cypher 查询不再将其加倍** (**@jstar0**)，匹配
  固定长度路径的统一已经完成。
- **Windows 发布失败说明了实际失败的原因。** 原子发布丢弃了 Win32
  错误并报告了一个裸 `errno`，并且一条路径返回了 `PERSIST_FAILED`，根本没有日志行 —
  这就是有 ACL 问题的记者被告知检查其存储库路径是否存在的方式。
- **跨存储库智能再次适用于任何曾经记录过解析缺失的项目**
  （**@vitaliy-shatskiy**，#1609）。索引将内部 `<name>::missed` 行写入同一行
  数据库，并且验证需要在“所有”数据库中恰好一行——所以这样的项目是
  作为源和目标都被拒绝为“未索引”，并且没有可用的解决方法
  运营商。 #1044 中的 `list_projects` 修复了相同的缺陷；这个网站从来没学过。

## 性能

  更长的扫描然后丢弃。到达 shell 的模式保留在允许列表之后，并且

## 可以再次从 0.9.x 更新

**如果您使用的是 0.9.x 且 `update` 一直拒绝安装，此版本可以修复该问题**
（＃1134）。 v0.10.0 每个平台合并为一个存档，因此 `codebase-memory-mcp-ui-*` 命名为
0.9.x 更新程序要求停止现有的更新程序并进行 404 处理。我们通过发布解决了这个问题
旧名称下的字节相同副本 - 但该步骤*在*`checksums.txt` 之后运行
生成并签名，因此别名从未出现在其中，并且更新程序会验证它的名称
要求拒绝无法检查的内容：

```
warning: codebase-memory-mcp-ui-darwin-arm64.tar.gz not found in checksums.txt
error: refusing to install an unverified download
```

我们修复了 404 并将故障移至验证。在 v0.10.4 上确认：八个 `ui-*` 档案
已发表，但没有列出。他们的摘要现在在证明步骤之前发出，因此
经过验证的校验和文件涵盖了两个名称 - 没有新字节，并且别名是副本，因此其摘要是
构造已经计算过的那个。由 **@AmooAti** 报告，其安装程序表现良好
始终正确。
