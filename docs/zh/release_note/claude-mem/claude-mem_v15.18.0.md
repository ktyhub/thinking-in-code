# claude-mem v15.18.0

## eve 特工获得与 Claude Code 和 Codex 相同的内存

`claude-mem/eve` 现在通过您的 cmem.ai 帐户为 eve 代理提供完整的 claude-mem 内存循环 (#6042)。

- **会话上下文：** 每个回合都从您记忆中的最近时间线开始。它在一个消息id下每回合都会刷新，因此它会替换自己而不是堆积起来。
- **回忆每个回合：** 与之前一样，在回合之前进行一次搜索。
- **现在默认开启记录。** 每次完成回合后，提供商都会向 cmem.ai 作为平台 `eve` 发送提示、每个工具调用的一次观察结果以及回合摘要。记录的工具调用和摘要来自您的 cmem.ai 观察员津贴，与您的其他 clients 使用的津贴相同。传递 `capture: false` 以保留旧的只读行为；会话上下文、回忆、搜索和 `remember` 继续工作。
  - 在发送任何内容之前，`<private>…</private>` 区域和秘密形状的文本会在您的部署中删除，其规则与 Cowork 插件使用的规则相同。
  - cmem.ai 会删除同一回合的重播（回合范围的工具调用 ID 和幂等性密钥）。
  - 每个请求发送一次。没有重试、假脱机或队列，因此中断永远不会在以后产生支出。记录失败并记录接受的事件数量。
- **工具：** `search`、`timeline`、`get_observations`（三步智能搜索）和 `remember`。
- **eve 版本：** 在 eve 0.84.0 和 1.0.0-rc.9 上测试。
- **模板：** 适用于免费信用 Vercel AI 网关（克劳德，当克劳德被拒绝免费信用时回退到 `openai/gpt-5-mini`），或设置 `ANTHROPIC_API_KEY` 直接呼叫克劳德，并设置 `EVE_MODEL` 选择确切的模型。预定的运行会获取所有者的记忆，所有者的电子邮件必须完全匹配，并且早晨摘要示例计划会关闭。

文件：https://docs.claude-mem.ai/eve-integration
