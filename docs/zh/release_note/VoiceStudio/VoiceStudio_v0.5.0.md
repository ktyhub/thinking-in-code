# VoiceStudio v0.5.0

**亮点**

- 该应用程序现在是 **VoiceStudio**（以前称为 OmniVoice-Studio）——跨应用程序、文档和安装程序的一种波形和火花标识。您的数据文件夹、设置和 Docker 图像路径保持不变。
- **模型目录** — 一个工作区中的引擎和模型：每个 TTS、转录和 LLM 引擎及其设备路由和安装状态，在那里选择默认值。
- 从状态栏或任何工作区切换 TTS、ASR 和 LLM 引擎 - 只读选项、内存状态、环境引脚保护、`Ctrl/Cmd+E`。 （＃1530）
- 通过加入代码和二维码扫描借出另一台机器的 GPU - 状态栏中的计算控件选择作业运行的位置，并且几个人可以通过可撤销的证书固定连接共享一个 GPU 盒。 （＃1516，＃1496）
- 服务器模式被锁定：管理操作需要 API 密钥 (#1525)，远程 UI 将其交换为永远不会存在于浏览器存储或 WebSocket URL 中的短期会话 (#1528) — 感谢 bultodepapas！
- 用于多语言制作的更快、更干净的 Dub 工作区，带有制作命令栏和每种语言卡。 (#1489)
- 应用程序一直宣传的演示音频和视频现在已实际发布，由 VoiceStudio 自己的引擎渲染。 (#1517)
- 听写功能现在可以在 Wayland 上运行 - 门户快捷方式实际上会触发（#1490，#1526） - 并且录音丸又回到了每个桌面上。
- Launchpad 将项目的信号场波形图呈现在更安静、无边界的布局上。 (#1533)
- 目录读起来是余量，而不是破损：可用的引擎首先排序，未安装的引擎说出他们需要什么（#1531），LLM 行命名实际回答的提供商（#1538）。
- 图库声音可以保存为本地配置文件 - 音频会通过经过验证的内容寻址参考存储在您的配置文件存储中。 (#1542)

### 已更改

- 图库角色现在可以通过本地后端预览，保留完整的语音设计配方，并直接在语音、故事或有声读物中打开。 (#1542)
- 现在支持金额选择使用每个主题的共享卡、重音和焦点标记。 （＃1530）
- 赞助、商业许可和联系现在只是一页。他们回答了相同的问题，而且每个人都曾经住在其他地方，所以它们是一个卷轴上的三个部分——页脚心、商业许可链接和联系方式都落在它上面，在你要求的部分。 (#1522)
- 模型目录使用选项卡而不是两种状态切换来切换窗格，引擎兼容性矩阵的 TTS / ASR / LLM 切换器现在也是选项卡 - 可使用箭头键导航，并且每个选项卡仍然显示它将使用的引擎。 (#1522)
- 您实际上可以使用的引擎排序到兼容性矩阵的顶部，并且不可用的引擎的名称会后退，而不是整行消失 - 状态徽章和 GPU 芯片说明*为什么*它不可用，保持清晰。 (#1522)
- 远程工作人员读取设备列表：状态点、地址、延迟、实时任务表、常驻模型和每台机器的最后查看时间，并在悬停时显示内务操作和三步空状态。 (#1516)
- GPU 选择器和新的状态栏控件从主题标记而不是固定调色板类绘制状态点和菜单表面，因此它们停止在 Midnight 和 Catppuccin 上显示 Gruvbox 颜色。 (#1516)
- 听写再次显示药丸：捕获会将一个始终在顶部的小胶囊放置在您正在处理的屏幕底部附近 - 聆听、转录、结果和任何错误 - 并在会话结束时将其拿走。它永远不会获得焦点，因此文本仍然会出现在您正在输入的应用程序中。在 Wayland 上，合成器决定它的位置；其他地方都是以底部为中心的。
- 引擎和模型从“设置”移至新的“模型目录”工作区，可从图标栏（或标题栏选项卡）访问；设置→引擎和设置→模型现在指向那里，设置保留模型目录和拥抱面部镜子。
- 设置侧边栏可通过键盘导航：按 ⌘K / Ctrl+K 跳转至过滤器，按 ↑/↓ 和 Home/End 在类别之间移动，按 Enter 或 ↓ 从过滤器落入列表。筛选类别名称中的匹配文本会突出显示，并且在列表滚动时组标题保持固定状态。
- Launchpad 具有更安静、更宽敞的外观：悬停或键盘焦点时点亮的无边框功能图块、纯数字计数、细线部分规则以及用于英雄、图块、最近文件和项目列表的一个共享页面列。
- Linux 版本烟雾现在验证 linuxdeploy 的包装自定义启动器，而不是拒绝健康的 AppImage。 (#1506)
- 远程 GPU 工作人员逐章渲染有声读物，并自动按章节进行本地回退，并在工作人员退出时发出综合通知。 (#1478)
- 远程 GPU 工作人员现在可以运行作业直至完成：长渲染不再在两分钟内终止，在渲染中途断开并重新连接的工作人员可以继续其工作，并且超时的工作不再使工作人员永久离线。放置工作仍然需要开发专用的`POST /workers/tasks`；接下来将应用程序自己的合成按钮连接到它。
- 语音、故事、有声读物、图库、设置、配置文件和启动板现在使用紧凑、响应式布局和可访问的控件。 (#1491)
- 配音的生成配音、验证和导出操作现在使用带有可见标签、响应式回流和运动安全反馈的紧凑层次结构。 (#1493)
- Dub 工作区现在拥有紧凑的制作命令栏、响应式基于标志的语言卡、Dub 历史记录中的媒体预览以及更窄的项目栏。 (#1489)
- VoiceStudio 现在在标题栏、关于屏幕、自述文件、浏览器图标和每个桌面/平台图标上使用一个波形和火花标记。 (#1487)
- PocketTTS 现在要求您在首次使用之前检查其代码许可证、模型许可证和门控访问条件，并解释如何解锁模型而不是显示原始下载失败 - 感谢 paoloantinori！ (#1442)
- 存储库移至 github.com/debpalash/VoiceStudio。应用程序、文档和脚本中的每个链接现在都指向那里； GitHub 重定向旧的 URL，并且 Docker 图像路径、应用程序包标识符和数据文件夹都被故意更改。 (#1394)
- 该应用程序现在是 **VoiceStudio**（以前称为 OmniVoice-Studio）。只有您看到的名称发生了变化 - 您的数据文件夹、设置和 Docker 图像路径保持不变，因此升级不需要您做任何事情。在 Linux 上，.deb 现在是 `voicestudio`；删除旧的 `omnivoice-studio` 包装一次。
- macOS 下限提升至 13.3 (Ventura) - 前端需要 Safari 16.4 一段时间了，因此 macOS 12 是堆栈无法兑现的承诺 (#1268)
- 首次运行设置屏幕不再过度承诺。它毫无保留地宣称“没有账户、没有云、没有遥测”——对于任何选择分析的人来说都是不真实的——现在却说出了实际上的情况：你的声音、录音和项目永远不会离开机器，云中也不会进行任何处理。
- 听写不再显示浮动药丸。热键记录、转录和粘贴，屏幕上没有任何内容；托盘图标仍然标记录制，并且任何需要您注意的内容（辅助功能、麦克风、失败的转录）现在都会作为通知到达主窗口中。

### 添加

- 通过本地后端预览图库角色，保留完整的语音设计配方，并直接在语音、故事或有声读物中打开 - 并且可以保存为带有经过验证的音频参考的本地配置文件。 (#1542)
- 该应用程序一直宣传的演示音频现在实际上已发布：所有七个语音设计预设的预览、三个听写重播 clips 以及配音演示的源视频以及四种带字幕的配音语言。其中每一个以前都是死链接 - 渲染它们的工具需要 macOS，因此在 Windows 和 Linux 上从未构建过文件。 (#1517)
- 演示资源由 VoiceStudio 自己的引擎呈现，因此工具可以在应用程序运行的任何地方运行，并且演示是由它们演示的内容制作的。 (#1517)
- 机器现在可以从应用程序加入控制平面：设置 → 系统 → 远程工作人员 → **借用该机器的 GPU**，粘贴加入代码，完成 - 无需环境变量，无需重新启动。地址随代码一起传输，因此机器随后会自行重新连接。 (#1516)
- 连接代码和连接字符串在文本旁边显示为 **QR 代码**，并带有实时到期倒计时 - 从另一台计算机扫描它，而不是重新键入 40 个字符。 (#1516)
- 状态栏中的 **计算** 控件：选择本地或远程计算机、打开或关闭远程工作人员以及创建加入代码，而无需打开“设置”。仅当您选择加入或注册计算机后，它才会出现。 (#1516)
- 等待批准的工人可以从其所在行获得批准。该小组之前曾标记过这种状态，但没有提供摆脱这种状态的方法。 (#1516)
- **模型目录** — 引擎和模型的专属工作区：浏览每个 TTS、转录和 LLM 引擎及其设备路由和安装状态，为每个引擎选择默认值，并安装或删除模型权重，所有这些都在一个屏幕上而不是两个设置类别中进行。
- 远程 GPU 机器现在可以接受连接而不是拨出，因此几个人可以同时使用同一个盒子 - 每个人都有自己的可撤销连接字符串，具有证书固定的 TLS、连接者的实时列表以及断开连接按钮。 (#1496)
- 远程 GPU 模型下载现在使用正常的模型安装流程并显示每个工作进程的进度。 (#1478)
- 设置 → 系统 → **远程工作人员** 将各个作业发送到其他计算机上的 GPU，而其他所有内容都保留在这里。默认关闭；每台机器都添加了一次性令牌，并在任何音频到达之前获得批准。请参阅[docs/remote-workers.md](docs/remote-workers.md)。
- 首次运行设置现在建议使用屏幕感知界面比例，并在整个设置过程中提供紧凑的控件。 (#1502)
- OrcaRouter 现已作为 OpenAI 兼容的 LLM 提供商提供 - 感谢 Marc-oss-hub！ (#1499)
- IndexTTS 2.5 作为固定的 one-click sidecar 提供，具有五种语言配音、表达性克隆和向后兼容的 IndexTTS-2 支持。 (#1482) — 感谢 marwanlhabti5-coder！
- 录音现在可以在每个桌面平台上通过实时输入电平表提供麦克风和通道选择。 (#1481)
- 设置 → 外观 → **导航样式** 在窗口边缘下方的图标栏和标题栏上的浏览器样式选项卡之间切换工作区切换器。两者都提供相同的工作空间；该选择在整个发射过程中都保持不变，并且导轨保持默认状态。当标题栏空间不足时，选项卡标签会向下折叠为图标 - 您所在的工作区保留其名称。 (#1412)
- 便携式模式允许您选择文件夹 - 在首次运行安装屏幕上按 **更改...** 并将整个安装放在外部驱动器上。默认程序文件安装后，它也不再显示为灰色。 (#766)
- 设置→隐私现在有一个**不可见水印**切换。默认情况下，所有人都可以使用，并且它仅影响更改后生成的音频。 (#1308)
- 一个新的选择加入崩溃隔离 TTS 引擎，因此本机崩溃会导致 sidecar 而不是整个后端崩溃 - 感谢 paoloantinori！ （＃1292，＃1298，＃1304）
- **PocketTTS** (Kyutai)，一种可选的仅 CPU 引擎，可通过参考 clip 进行零次克隆，以六种语言 (en/fr/de/pt/it/es) 进行快速、低延迟渲染。在“设置”→“引擎”中启用 - 感谢 paoloantinori！ （＃1306，＃1328）
- 在缓慢生成之前发出警告，而不是在五分钟等待之后发出警告。 (#1280)

### 已修复

- AMD/ROCm 主机不再因“CUDA 驱动程序版本不足”而导致 ASR 崩溃：ROCm torch 将自身报告为 CUDA，但在 CTranslate2 上运行 Whisperx/faster-whisper，后者仅适用于 NVIDIA — 它们现在采用 CPU 路径，并且自动检测更喜欢 pytorch-whisper，它真正使用 HIP GPU。 (#1529)
- 崩溃报告现在包含崩溃运行自己的 stderr：共享错误日志仅附加每次运行偏移量，因此重新启动无法再用替换的健康启动覆盖垂死进程的最终输出。 (#1510)
- Wayland：过时的门户身份不再杀死整个会话的听写快捷方式。应用程序为 GlobalShortcuts 门户编写的桌面条目可能指向已移动的二进制文件（`cargo clean`，重新定位的 AppImage）——然后 GNOME 会拒绝绑定并显示“未找到应用程序信息”，并且热键会默默消失。该条目现在在启动时进行验证并重写。 (#1526)
- 在降级的 ASR 加载器上保留转录的警卫现在扫描整个后端，而不仅仅是路由器 - 代表请求转录的服务同样彻底跳过了 `ensure_loaded()`。 (#1519) — 感谢 ahov520！
- Linux 应用程序图标不再是空白的。自 v0.4.2 以来的每个 AppImage 都将 `.DirIcon` 作为绝对符号链接发送到构建它的机器 (`/home/runner/work/…`) 中，因此该链接悬挂在每个用户的计算机上，文件管理器、应用程序菜单和桌面集成都没有任何效果。现在，发布版本会在发布之前验证捆绑包内的图标解析。 (#1518)
- Linux 桌面条目不再提供空的 `Categories=`，`desktop-file-validate` 会拒绝该空 `Categories=`，并且菜单构建器会跳过该空 `Categories=`。 (#1518)
- Wayland：听写快捷方式现在实际上开始听写。桌面门户正确注册了该键 - GNOME 和 KDE 甚至显示了它 - 但在解码合成器信号时每次按下都被丢弃，因此热键在任何 Wayland 会话中都没有任何作用。 (#1490)
- 当您坐在那里时，首次运行的“选择舒适的 UI 尺寸”屏幕不再卡顿。应用缩放会调整窗口自己的视口的大小，屏幕会读回该视口以重新选择尺寸 - 因此它会永远在两种尺寸之间翻转，而无需任何人触摸它。 (#1514)
- 当自动选择的引擎通过可用性检查但在第一次实际使用时中断时，转录现在会转移到下一个工作引擎，而不是返回内部错误 - 恢复配音已经存在。受影响的准确模式转录、兼容 OpenAI 的 API、批处理、配音验证和语音克隆参考文本。 (#1512)
- 格式错误的请求现在会收到明确的 422 而不是内部错误，并且将文件上传到期望 JSON 的端点不再将整个上传内容复制到应用程序日志中 - 145 KB 的 clip 写入大约 500 KB 的日志，将您的音频记录在人们粘贴到错误报告中的文件中。 (#1513)
- 简体中文 (zh-CN) 翻译不再误译品牌名称和技术术语 - Discord、Tailscale、Hugging Face、IPA 和 LLM（电影）被渲染为无意义的直译，大约 250 个尴尬的机器翻译字符串现在是自然中文。 (#1508) — 谢谢anyingiit！
- 工作线程重新启动覆盖范围现在等待注册响应以保留其身份，而不是与 CI 中的 client 回调竞争。 (#1505)
- 配音语言和导出选择现在可以恢复，不会出现错误的架构警告，并且远程工作人员端口 7443 会被识别，而不是报告为通用超时。 (#1504)
- 配置的远程后端现在绕过本地首次运行设置，在应用程序请求开始之前验证自身，并显示恢复，而不是让桌面停留在安装程序上。 (#1503)
- 空闲的语音模型现在实际上交还了它的记忆。卸载在释放模型之前清空了 GPU 缓存，因此它在报告成功的同时没有释放任何内容 - 借出其卡的 GPU 机器无限期地位于 3.6 GB 上。 (#1495)
- 在 NVIDIA GPU 上卸载模型现在也会返回最后的约 770 MB。单个 8.5 MB cuBLAS 工作区位于模型的内存块内，并保留整个块，因此无论您多久按一次刷新内存，闲置的机器都会保留 1.2 GB 而不是 470 MB。 (#1495)
- 刷新内存报告保留的 GPU 内存以及已分配的内存。卸载后单独分配的读数接近于零，而 GPU 仍然显示千兆字节，这正是人们报告的情况。 (#1495)
- AudioSeal 水印模型在与其他所有内容相同的空闲期后发布，而不是在任何内容加水印后在应用程序的整个生命周期中保留在内存中。 (#1495)
- 远程 GPU 工作人员现在将配音的新鲜片段合成为一项粗略工作，并具有实时进度和取消功能；装配、组装和 RVC 仍保留在本地。 (#1478)
- 当下载的 clip 无法解码时，图库语音预览现在会回退到本地渲染，而不是默默地失败。 (#1478)
- 第二个 VoiceStudio 实例无法再默默地共享远程工作人员端口；它在本地继续运行并解释如何解决冲突。 (#1478)
- 远程 GPU 作业在重试和重新启动时保持固定到选定的工作线程，在调用者离开时停止，并且无法在完成后从取消中返回。 (#1478)
