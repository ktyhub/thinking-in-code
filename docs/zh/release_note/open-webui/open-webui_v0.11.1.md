# open-webui v0.11.1

### 添加

- 🚦 **人在循环工具批准。** 如果管理员将其打开，您可以将对话从让工具自由运行切换为首先询问，因此想要使用工具的模型会停止并等待您允许或拒绝它，通过按钮或键盘快捷键在保存的对话中一次调用一个呼叫，并记住您对此对话和未来对话的选择，切换回自由运行释放任何已经等待的内容，并且自动化、频道回复和临时聊天不受影响。 [提交](https://github.com/open-webui/open-webui/commit/7d99b2716a0472b2100b3a71825d8eb3fcbbe877)、[提交](https://github.com/open-webui/open-webui/commit/ec36972c2b5a8d48713f1a240b0ed305e535b4cc)、[提交](https://github.com/open-webui/open-webui/commit/653562d660398c32a9a193450bbbee300d7195c3)、[提交](https://github.com/open-webui/open-webui/commit/fa94a5ab2431edba064150651a14dd4992ef29e8)、[提交](https://github.com/open-webui/open-webui/commit/55c202e841e76cd69679206cd0ecb4a65b039ea4)、[提交](https://github.com/open-webui/open-webui/commit/30f82788bc75e6965da3766e3bf43840dd971eed)、[提交](https://github.com/open-webui/open-webui/commit/bbfdbd59f29e246db1d8b5c2401bc7b11aa32c99)、[提交](https://github.com/open-webui/open-webui/commit/7fc5fa1ff3f6cd6f0efcbf847064ca8d21620ba6)、[提交](https://github.com/open-webui/open-webui/commit/3eb65f47151af4fb4ccfaf33d6e77154546e7259)、 [提交](https://github.com/open-webui/open-webui/commit/62fc436999ad32e82d1405ac14d1f03e0f0341ec)
- 🙋‍♂️ **可以问你问题的模型。** 新的内置工具可让模型暂停并向你提出最多三个多项选择题，然后再继续，并留出空间来输入你自己的答案，并且问题在已保存的对话中重新加载后仍然存在，因此你可以稍后返回并回答，而不是丢失对话。 [提交](https://github.com/open-webui/open-webui/commit/4465f52a3eb521854cf190f91b0ea7cf3fa21830)、[提交](https://github.com/open-webui/open-webui/commit/133549a87ee371577453d897c2db2d8071223f27)、[提交](https://github.com/open-webui/open-webui/commit/b018feb7419e68314378b3cdd8b7b1b389400a98)、[提交](https://github.com/open-webui/open-webui/commit/083e35144152d6a301bed01aa6d898db3871ddcf)、[提交](https://github.com/open-webui/open-webui/commit/256cce505be8ddd4930e8cb2536faea718d3f789)、[提交](https://github.com/open-webui/open-webui/commit/14e4d72d9a21a10196e8e6efb04180cd9104b8e6)、[提交](https://github.com/open-webui/open-webui/commit/57bd08304e45f707768a898de9f50894929008dd)、[提交](https://github.com/open-webui/open-webui/commit/d9014b3483d4c6e8d99e50395afcdc538bcf05cd)
- 🖇 **代理现在可以直接显示终端文件。** 模型现在可以直接在其回复中显示在终端中制作的文件，并带有预览和下载按钮，而不是描述 clicked 时无处可去的路径，并且新的界面设置可以选择这些文件是在回复中还是在文件窗格中打开。 [提交](https://github.com/open-webui/open-webui/commit/78f48a21eef330c0b78c33f2b5fc2169b084997c)、[提交](https://github.com/open-webui/open-webui/commit/e623c02acc70c4ee5d7f2eb2f32d9b7f39287663)、[提交](https://github.com/open-webui/open-webui/commit/f64c0c87e8d1bfdbe060ea5e5a3dee24c0323657)、[#27650](https://github.com/open-webui/open-webui/issues/27650)
- 📶 **从头开始重建流式传输。** 回复现在以小块新文本的形式进行流式传输，而不是在每次更新时重新发送整个消息，因此通过回复发送的数据随着其长度而不是其长度的平方而增长，这在有许多人同时聊天的服务器上意味着编码、传递和解码这些更新所花费的处理器时间要少得多，在实例之间承载它们的共享缓存上的负载和内存要少得多，浏览器中的工作也要少得多，浏览器不再需要整个回复并重新绘制每次更新时未更改的部分，在很长的回复中将发送的数据和附加到消息所花费的服务器工作量减少多达 1000 倍，并且仍在进行中的回复现在保留在服务器上，因此在 Redis 支持的部署上，刷新后重新打开对话会在原处重新打开对话，而不是显示空白消息。 [提交](https://github.com/open-webui/open-webui/commit/a1579a01ff43cacb357269707d36267ad35e01d6)、[提交](https://github.com/open-webui/open-webui/commit/c755ef60c6bd47ea25306bd898d9a6d1bd8e871d)、[提交](https://github.com/open-webui/open-webui/commit/d02b6a21fc02fb073782e25356968cfee3c45c36)、[提交](https://github.com/open-webui/open-webui/commit/3e186abdd91edee9e97e43c9b345714643a84cf5)
- 🪵 **整个过程速度更快。** 应用程序中的数百个地方不再收集关闭并丢弃未读的详细日志文本，因此发送消息、上传和索引文件、运行搜索、登录和加载管理页面都可以恢复时间，在繁忙的服务器、长时间的对话以及从大型知识库中提取的聊天中获得的收益最大。 [#27834](https://github.com/open-webui/open-webui/pull/27834), [#27837](https://github.com/open-webui/open-webui/pull/27837)
- 🚀 **更快的模型列表查找。** 标题生成、标签建议、自动完成和聊天轮次的其他后台步骤现在可以一次性获取模型列表，从而使其他人的响应在繁忙的 Redis 支持的具有许多模型的实例上保持流畅。 [#27821](https://github.com/open-webui/open-webui/pull/27821)
- 🛰️ **更便宜的日志导出。** 将日志导出到遥测收集器的部署，同时设置“ENABLE_OTEL”和“ENABLE_OTEL_LOGS”，现在准备每个导出的行一次而不是两次，这比以前更重要，因为日志文本仅在实际读取日志文本时才进行组装。 [#27840](https://github.com/open-webui/open-webui/pull/27840)
- 📇 **对大型实例进行更快的权限检查。** 现在可以直接查找而不是扫描服务器上的每个成员身份来确定您所属的组，因此随着组织的发展，聊天和管理员用户列表会保持快速。 [#27822](https://github.com/open-webui/open-webui/pull/27822)
- ⚙️ **更快的 JSON 处理。** 当打开“ENABLE_ORJSON”选项时，保存和打开聊天、读取设置、从内置工具返回结果、流式回复、登录和注册、确定您的权限以及在 Valkey 和 Oracle 矢量存储的知识库搜索期间读取存储的块详细信息都可以在整个应用程序中更快地处理。 [提交](https://github.com/open-webui/open-webui/commit/bb0f898b431d5aa45efa7805956657ed9c3dd78d)、[#28396](https://github.com/open-webui/open-webui/pull/28396)、[#27841](https://github.com/open-webui/open-webui/pull/27841)、[#27807](https://github.com/open-webui/open-webui/pull/27807)、[#27805](https://github.com/open-webui/open-webui/pull/27805)、[#27813](https://github.com/open-webui/open-webui/pull/27813)
- 📤 **更快的出站请求。** 发送到 Ollama 和 Anthropic 模型的对话和嵌入批次的打包交付速度要快得多，当打开“ENABLE_ORJSON”选项时，这在长时间聊天中最为明显。 [#27811](https://github.com/open-webui/open-webui/pull/27811), [#27810](https://github.com/open-webui/open-webui/pull/27810)
- 🐍 **代码解释器输出速度更快。** 当打开“ENABLE_ORJSON”选项时，聊天中运行的代码的打印输出和生成的图像显示得更快。 [#27812](https://github.com/open-webui/open-webui/pull/27812)
- 🪶 **更轻的页面加载。** 界面在每个页面加载时发出的几个小请求以及一些管理请求，不再设置他们从未使用过的数据库访问，这比其余请求加起来花费的时间长几倍。 [#28178](https://github.com/open-webui/open-webui/pull/28178)
- ♻️ **每条消息减少一次读取。** 发送消息不再从数据库加载整个对话两次，这在记录最大的长聊天中最为重要。 [#28809](https://github.com/open-webui/open-webui/pull/28809)
- 🏁 **在大型实例上更快的技能。** 打开技能列表或发送使用一项技能的消息，不再一次检查实例上的每一项技能，因此在存在许多技能且其中大多数技能不属于您的情况下，两者都会快得多。 [#28798](https://github.com/open-webui/open-webui/pull/28798)
- 🩻 **大型实例上的工具速度更快。** 列出或导出工具不再一次检查实例上的每个工具，因此集成菜单和工具工作区在存在多个工具的情况下打开得更快。 [提交](https://github.com/open-webui/open-webui/commit/4807866a1cf47340f1b5ea76fded95f8114305f9)
- 🧊 **更快的文件访问检查。** 检查您是否可以访问文件不再遍历您可以看到的每个工作区模型来查找它，因此在具有多个模型的实例上，打开文件文件夹、下载文件或从文件文件夹中检索文件要快得多。 [#28802](https://github.com/open-webui/open-webui/pull/28802)
- 🧱 **更快的文件夹列表。** 现在，列出文件夹可以为整个列表计算一次组成员身份，而不是为每个文件夹中的每个项目再次计算组成员身份。 [#28810](https://github.com/open-webui/open-webui/pull/28810)
- 🧼 **长时间聊天中每次更新的工作量更少。** 在回复流中保存的每个更新不再重新检查整个对话，而仅重新检查添加的部分，因此更新的成本不再随着聊天的长度而增加。 [#28820](https://github.com/open-webui/open-webui/pull/28820)
- 🗃 **将源和文件附加到回复的成本更低。** 将源、文件或嵌入项目添加到回复现在仅读取该字段，而不是重建整个对话来查找它，在 200 条消息聊天中，每个项目大约需要 3.1 毫秒，下降到 0.65 毫秒，并且不再随着对话的长度而增长。 [提交](https://github.com/open-webui/open-webui/commit/536b9edec00547d5b84ef2e6ea0f929c054c1333), [提交](https://github.com/open-webui/open-webui/commit/9dff5e93277aa1a2236d702e7e2f55dbb35ea7fa)
- 🚏 **更快的工作区模型查找。** 计算出您可以编辑的工作区模型不再加载实例上的每个模型并丢弃其中的大部分模型，这也加快了导出模型和依赖于它的文件访问检查的速度。 [#28795](https://github.com/open-webui/open-webui/pull/28795)
- 📮 **更快地传递流式回复。** 现在，在实例之间传递正在进行的回复只需写入一次，而不是来回转换并扫描仅在其他地方重要的字符，这在大型非英语对话中花费了每次写入所花费的大部分时间。 [#28833](https://github.com/open-webui/open-webui/pull/28833)
- 🥵 **空闲实例上的持续负载。** 空闲实例不再在您每秒一次寻找到期计时器的每次聊天中工作，这在很大的历史记录中使大约四分之一的处理器核心忙于无所事事，并且可能会耗尽内存，直到应用程序被终止。 [#27663](https://github.com/open-webui/open-webui/pull/27663)、[#27622](https://github.com/open-webui/open-webui/issues/27622)、[#27745](https://github.com/open-webui/open-webui/issues/27745)
- 📍 **侧边栏文件夹获取一次。** 刷新侧边栏现在会在页面加载和刷新页面的每个操作时要求您提供文件夹一次，而不是三次。 [#28662](https://github.com/open-webui/open-webui/pull/28662), [#28661](https://github.com/open-webui/open-webui/issues/28661)
- 💤 **仅仅登录后的写入次数就少得多。** 记录某人在线现在最多为每个人每分钟写入一次，而不是针对每个单独的请求，其中一个打开的选项卡在任何人接触任何内容之前每分钟都会导致两次写入事务。 [#28177](https://github.com/open-webui/open-webui/pull/28177), [#28165](https://github.com/open-webui/open-webui/issues/28165)
- 🛰 **每个请求的开销更少。** 每个请求在处理之前经过的层现在是一个而不是五个，这也从设置安全标头的实例上的流式回复的每个部分中消除了四分之一的成本。 [提交](https://github.com/open-webui/open-webui/commit/b96d2b12dae5e953e520bec03f74e9b85b955dc7)，[#28171](https://github.com/open-webui/open-webui/issues/28171)
- 🎏 **关闭实时更新的压缩。** 新的“UVICORN_WS_PER_MESSAGE_DEFLATE”设置会停止服务器压缩其发送的每个实时更新，这会花费每个更新的处理器时间，而且由于回复流为小块，因此几乎没有节省；除非关闭，否则压缩将保持打开状态。 [#28613](https://github.com/open-webui/open-webui/pull/28613)
- 🌡 **更快的聊天列表和未读计数。** 打开侧边栏和文件夹上的未读标记，不再阅读整个聊天历史记录以生成简短列表，在具有 15000 条聊天的实例上需要 2 到 4 秒。 [#27663](https://github.com/open-webui/open-webui/pull/27663)、[#27622](https://github.com/open-webui/open-webui/issues/27622)、[#27745](https://github.com/open-webui/open-webui/issues/27745)
- 🥁 **长回复不再随着增长而缓慢。** 长回复不再从头开始重新检查每条到达的推理和代码块，因此工作随着回复的长度而停止增长，在长回复上花费的时间大约减少了 190 倍。 [#28861](https://github.com/open-webui/open-webui/pull/28861)
- 💽 **更快地保存长聊天。** 聊天现在一次写入数据库，而不是一次一条消息，因此保存长对话要快得多，对数据库的压力要小得多，而保存没有任何更改的对话则根本不写入任何内容。 [#28806](https://github.com/open-webui/open-webui/pull/28806)
- 📦 **更快地加载共享文件夹。** 与您共享的文件夹现在会加载几个查询，而不是每个文件夹和每个所有者一个，因此对于拥有多个文件夹的任何人来说，该列表会更快显示。 [#28804](https://github.com/open-webui/open-webui/pull/28804)
- ⚡ **知识搜索过程中聊天不间断。** 现在，在知识库搜索运行时，响应会持续为服务器上的每个人提供流式传输，而不是暂停直到每次搜索完成。 [#27824](https://github.com/open-webui/open-webui/pull/27824)
- 🔍 **更智能的聊天搜索。** 现在，搜索聊天会发现包含任意顺序的所有单词的对话，而不仅仅是您键入的确切短语，精确匹配项仍列在最前面，预览片段会指向它找到的单词。 [提交](https://github.com/open-webui/open-webui/commit/0800c21c64c64810f24c2ec88cca5e36daebb10e)
- ⌨️ **从消息框切换模型。** 现在，输入“/model”会告诉您当前所在的模型，通过名称“/model”后跟其 ID 切换到另一个模型，或者直接从斜杠菜单打开模型选择器，而无需使用鼠标。 [提交](https://github.com/open-webui/open-webui/commit/29eeda9f9abeaedf77176908cb036ace7f175e76)、[提交](https://github.com/open-webui/open-webui/commit/9c7ce154e79a3baea3a8223ab1e5b1371ce80dbb)
- 📎 **在附件上传时发送。** 在文件上传完成之前发送消息现在会将其排队并在准备好后自动发送，而不是错误拒绝，并且每条排队的消息都会显示其附件的进度。 [提交](https://github.com/open-webui/open-webui/commit/6c4d0ace163a89aba6e8cd2aa9fef185167ebe0f)、[提交](https://github.com/open-webui/open-webui/commit/c1c07cbe0f847e4dd04e21f2a6c5f12cdc0fc7ee)、[#28381](https://github.com/open-webui/open-webui/pull/28381)、[#28380](https://github.com/open-webui/open-webui/issues/28380)
- 📖 **在右侧页面打开文档。** 从终端向您显示 PDF、Word 文档或幻灯片的模型现在可以在特定页面或幻灯片上打开它，因此引用第 76 页上的内容的回复可以将该页面放在您面前。 [提交](https://github.com/open-webui/open-webui/commit/fd8cc2ba4a226ccbf51e114c71f156676eabb2d9)、[提交](https://github.com/open-webui/open-webui/commit/cf4ac9c8db67031627f196fae894764367fba5b4)、[提交](https://github.com/open-webui/open-webui/commit/6cb2449ab70ed6aa5124fcd2b1291b48527af4cd)
- 💼 **直接发送到终端的附件。** 现在可以将终端连接设置为将聊天中附加的文件接收到其自己的工作目录而不是对话中，这也意味着可以在使用无法读取文件本身的模型时附加文件。 [提交](https://github.com/open-webui/open-webui/commit/8a42aa53e826d5f25d6443ca95e0173e3cf034cf)、[提交](https://github.com/open-webui/open-webui/commit/d7d935275a77fb185586a5130cd37acf1175ca0a)、[提交](https://github.com/open-webui/open-webui/commit/1b3b9375bb4de0f360782dd2f9d8c7c2903b8baa)、[提交](https://github.com/open-webui/open-webui/commit/d17f06a23501e5c39cf98d9c9642178da25343fb)
- 🔦 **在终端浏览器中搜索文件。** 文件浏览器现在有一个搜索框，可以按名称和文件内容查找文件，打开结果会将您带到匹配的行。 [提交](https://github.com/open-webui/open-webui/commit/7abe11346a1cc309da2c3fcec2f61faaeb47b96a)

### 已修复

- 🛡️ **安全建议**：此版本包括安全和访问控制修复。我们建议您尽早更新生产部署。修复部分中并未列出此版本中的所有安全修复。有些可能会被暂时保留，以便管理员有时间进行升级。 [咨询](https://github.com/open-webui/open-webui/security)
- 🛂 **知识搜索超出了您可能阅读的范围。** 搜索知识库现在应用允许您打开的集合列表，其中该限制被交给矢量存储并默默丢弃，因此结果可能包括您无法访问的知识库中的材料。 [提交](https://github.com/open-webui/open-webui/commit/1d6d4e6e6647e1d403438ede7bd9ba20bc4cc8f6)
- 💣 **解压后远远超出其大小的文档。** 扩展至远远超过其存储大小的 Word、Excel、PowerPoint、OpenDocument 或 EPUB 文件现在会在读取之前被拒绝，以前可能会耗尽服务器的内存。 [提交](https://github.com/open-webui/open-webui/commit/2a0274a0a039dbe0a1ad4d24003b085aae7b896b)
- ✂️ **长回复中途被切断。** 流回复的单个超大片段，例如长推理跟踪或携带许多工具调用的回合，不再以有关字节计数的误导性错误提前结束答案，这会影响每个默认安装。 [#28114](https://github.com/open-webui/open-webui/pull/28114), [#25664](https://github.com/open-webui/open-webui/issues/25664)
- 🚧 **可以跳过的网址检查。** 可获取地址测试和运营商的网络获取过滤器列表现在在每个传出请求上运行，其中代理或已打开的连接可以绕过它们，并且以地址范围形式编写的过滤器条目会默默地与任何内容都不匹配。 [#27823](https://github.com/open-webui/open-webui/pull/27823)
- 🧑‍💻 **可通过回复中的标签执行代码。** 在使用本机函数调用进行安装时，运行模型回复中标签内找到的代码的旧路径不再与内置工具一起处于活动状态，因此代码执行仅通过显式工具调用进行。 [#29024](https://github.com/open-webui/open-webui/pull/29024)
- ⌚ **可能会占用服务器的重复规则。** 自动化重复的频率现在取自调度程序实际解析的规则，而不是取自规则的文本，因此精心设计的规则不再与计划的内容不一致，并引导服务器完成无限制的事件运行，并且在其开始日期上带有时区的规则现在可以安排而不是出错。 [提交](https://github.com/open-webui/open-webui/commit/067114c28038b77045a3a1983e2e2719b1a32ad8)
- 🗝️ **更改密码现在会结束其他会话。** 更改密码或管理员为您重置密码，现在会停止所有已登录的设备，这些设备一直使用旧密码保持登录状态，直到会话自行过期（默认情况下最多四个星期）；进行更改的设备也会被注销并要求再次登录，这需要 Redis，如果没有它，任何内容都无法撤销，并且现在会记录一条警告，说明这一点。 [#28725](https://github.com/open-webui/open-webui/pull/28725)、[#28647](https://github.com/open-webui/open-webui/discussions/28647)
- 🧬 **工作空间模型掩盖了真实的模型。** 没有管理员权限的人无法再创建、导入或编辑工作空间模型，以便它接管由连接的提供者提供的模型的身份，这样做会改变其他人在选择该模型时获得的结果。 [提交](https://github.com/open-webui/open-webui/commit/ea55d38793014a4e3cd5a4046816fe22e69e9739)
- 🌳 **文件夹在移动到其自身的子文件夹中时会消失。** 现在拒绝将文件夹移动到其自己的子文件夹之一中，它被接受并使得该文件夹及其中的所有内容从侧边栏中消失，无法将其恢复，同时让服务器无休止地循环并在运行时查询数据库，这可能会耗尽工作人员及其内存；任何已处于该状态的文件夹都会返回到顶层。 [#28748](https://github.com/open-webui/open-webui/pull/28748)
- 🧨 **使用昂贵的模式搜索知识库。** 编写的搜索模式在运行之前就已经大幅扩展，现在会被拒绝，因为它可能会占用服务器；普通图案不受影响。 [提交](https://github.com/open-webui/open-webui/commit/d5b66533e7829654f6fb343abbaaeab988dbfde8)，[#28284](https://github.com/open-webui/open-webui/pull/28284)
- 💧 **从链接附加一个非常大的文件。** 从链接获取的文件现在会在到达时写入磁盘，并在配置的大小限制处停止，整个文件首先保存在内存中，没有应用限制，因此足够大的文件可能会耗尽服务器的资源；中途失败的下载不再留下部分文件。 [#28945](https://github.com/open-webui/open-webui/pull/28945)
- ⛓ **删除一个知识库，删除共享连接。** 删除外部知识库现在会保留其连接，而其他知识库仍在使用它，并且只有管理员删除最后一个知识库才能清除它，任何删除其知识库的用户都会从所有人那里夺走连接。 [#28113](https://github.com/open-webui/open-webui/pull/28113)
- 📡 **间歇性连接失败。** 对模型提供者和同一网络上的服务的请求不再因名称查找错误而间歇性失败，通常会显示为误导性的模型未找到消息，因为默认情况下会再次通过系统解析地址，但仍然可以通过“AIOHTTP_CLIENT_ASYNC_DNS_RESOLVER”使用更快的解析器。 [#28242](https://github.com/open-webui/open-webui/pull/28242)、[#28013](https://github.com/open-webui/open-webui/issues/28013)、[#28215](https://github.com/open-webui/open-webui/issues/28215)
