# paperclip v2026.916.0

# 纸clip v2026.916.0

> 发布时间：2026-09-16

Paperclip v2026.916.0 包含 503 次提交，从当天发布的 `2026.916.0-beta.0` 升级。标题是 Connections 列车：AI 运行时凭证（Claude 和 Codex 订阅、API 密钥、共享帐户）现在位于 Connections 中，与其他帐户具有相同的授权和权限边界，通过招聘和任务执行跟踪负责人，并且可以从需要它们的任务中进行内联连接或修复。围绕它：代理通过 AgentMail 获取自己的电子邮件地址，实验性聊天连接器将 Slack、Discord、Telegram、Microsoft Teams 和（通过 Photon）iMessage 对话带入任务中，GitHub 访问成为持久的个人身份而不是共享令牌，公告作为本机应用内卡片到达，实验性 Paperclip Runner 从上一个版本的基础工作发展成为完整的执行引擎 - 现在在自托管上默认打开大门为显式配置的代理安装。

## 重大变更

- **便宜的模型配置文件被删除。**允许恢复和覆盖在更便宜的模型上运行的第二种执行模式已从适配器元数据、代理运行时配置、任务覆盖、恢复规则、API 和主板 UI 中消失；迁移 `0236` 从代理配置中剥离存储的 `modelProfiles` 块。现在，正常工作和恢复工作有一种模型选择路径。 ([#12683](https://github.com/paperclipai/paperclip/pull/12683))
- **代理 API 不再返回明文凭据。** 序列化代理的每个端点（详细信息读取、公司代理列表和创建/更新/生命周期路由）用于回显存储的 `adapterConfig.env`，因此 `plain` 绑定（API 密钥、令牌）逐字返回给任何能够读取代理的调用者，包括通过 `GET /api/agents/me` 的代理本身。所有三个响应系列现在都通过一位编辑演示者进行路由。从这些响应中删除实时凭证的集成将停止工作——这就是泄漏。 （[#9860]（https://github.com/paperclipai/paperclip/pull/9860），@glovario）
- **自动生产力审查已退役。** 将运行计数、评论计数和经过时间转化为管理审查任务的检测器及其延续保留被删除 - 基础设施故障可以满足其规则和制造工作。有限的恢复、预算、明确的阻碍和正常的审查阶段都仍然存在；现有任务记录保持可读且不变。 ([#13263](https://github.com/paperclipai/paperclip/pull/13263))
- **`X-Forwarded-Host` 仅受到 trusted 代理的尊重。** 同源防护用于接受来自任何直接 client 的转发主机，让调用者将其自己的标头提升到 trusted 源集中。现在，仅当直接对等方通过操作员的 `TRUST_PROXY` 设置时，转发的主机才会计数 - 反向代理后面的部署应确认 `TRUST_PROXY` 已配置，或者代理的转发主机将被忽略，转而使用原始 `Host` 标头。 ([#12832](https://github.com/paperclipai/paperclip/pull/12832))
- **Anthropic 的旧版 REST 连接选项已消失，并且 REST 工具连接被验证为 REST。** 过时的 REST 设置路径已被删除，以支持支持的 AI 帐户流程，并且 stdio 验证不再允许不支持的 REST 连接通过（或因误导性的 `templateId` 错误而失败） - 现有的不支持的连接现在会收到准确的拒绝。 ([#13346](https://github.com/paperclipai/paperclip/pull/13346))

## 亮点
- **AI 凭证现在存在于 Connections 中** — 提供商登录不再是针对每个代理的配置，而是成为具有连接已强制执行的所有权、授权和访问权限的托管帐户：代理重复使用负责用户的帐户或允许的共享帐户，模型/线束选择保持独立于凭证选择，旧代理将保留其现有身份验证，直到他们明确采用托管连接 ([#13247](https://github.com/paperclipai/paperclip/pull/13247))。相同的登录组件在入职、代理配置和连接器页面中重复使用，而不是第二个登录向导 ([#13248](https://github.com/paperclipai/paperclip/pull/13248))。雇佣代理继承招聘代理的提供者凭证引用，以便委派的队友可以从其第一次运行进行身份验证 ([#13268](https://github.com/paperclipai/paperclip/pull/13268))，并且连接会跟随旧运行者和本地运行者的雇佣 — 丢失的帐户会暂停任务并提供内联连接表单，而不是失败 ([#13438](https://github.com/paperclipai/paperclip/pull/13438))。每个负责的用户都会获得每个提供商的默认值，因此同一代理可以在一个人的订阅和另一个人的 API 密钥上运行 ([#13351](https://github.com/paperclipai/paperclip/pull/13351))。火车在着陆时也变得更加坚固：订阅登录可以在经过身份验证的自托管实例上工作，而不会暴露服务器运营商的 CLI 帐户 ([#13344](https://github.com/paperclipai/paperclip/pull/13344))，凭证租约可以在事务池中生存，而不是报告幻象“连接繁忙”([#13347](https://github.com/paperclipai/paperclip/pull/13347))，一个 Anthropic 订阅连接支持并发运行 - 仅支持文件凭证仍然序列化（[#13445](https://github.com/paperclipai/paperclip/pull/13445)），并且连接探测、已保存帐户重用和任务切换获得了可靠性通过（[#13404](https://github.com/paperclipai/paperclip/pull/13404)、[#13161](https://github.com/paperclipai/paperclip/pull/13161)）。
- **代理获得自己的电子邮件** - AgentMail 连接（实验性）为代理提供专用收件箱：传入电子邮件成为任务中分配的工作，发送是通过 Paperclip 验证的显式代理操作，并且内部任务评论永远不会意外地作为外发邮件泄漏。提供商密钥保留在服务器保管库中，董事会通过任务电子邮件卡跟踪每个对话。 ([#13256](https://github.com/paperclipai/paperclip/pull/13256))
- **通过聊天工具联系您的客服人员** - 实验性本机聊天连接器将 Slack、Discord、Telegram、Microsoft Teams 或 GitHub 机器人身份绑定到一名客服人员，并将每个承认的外部对话绑定到一项任务，并具有持久的每个对话队列、问题、进度、文件和交付收据 - 董事会评论保留在内部，除非明确发送到渠道，并且根本不会发送原始推理、日志和凭据（[#13100]（https://github.com/paperclipai/paperclip/pull/13100），[#13038]（https://github.com/paperclipai/paperclip/pull/13038））。 iMessage 通过实验性 Photon 通道加入：共享 Pro DM 或专用号码，包括照片，Paperclip 保留任务所有权和批准权限 ([#13299](https://github.com/paperclipai/paperclip/pull/13299))。在应用程序本身中，实验性代理聊天为每个人提供了与每个代理的持久对话 - 由真实任务和正常治理支持，而不是并行聊天存储 - 并且每个公司代理都可以通过可搜索选择器从聊天侧边栏访问（[#13284]（https://github.com/paperclipai/paperclip/pull/13284），[#13420]（https://github.com/paperclipai/paperclip/pull/13420））。
- **GitHub 访问成为身份，而不是共享令牌** — GitHub 应用程序支持的身份具有持久刷新、存储库访问检查和 Webhook 交付，取代了临时令牌，建立在现有托管连接和加密授权的基础上 ([#12843](https://github.com/paperclipai/paperclip/pull/12843))。当多人控制一个代理时，托管的 Git、`gh` 和 GitHub 工具会根据接受的指令解析负责人的凭据 - 具有持久的延续规则，并且不会回退到队友的访问权限 ([#13005](https://github.com/paperclipai/paperclip/pull/13005))，并且该身份也会项目到沙箱运行程序中 ([#12907](https://github.com/paperclipai/paperclip/pull/12907))。围绕核心：浏览跨组织的存储库访问 ([#12998](https://github.com/paperclipai/paperclip/pull/12998))，为每个项目选择多个源存储库 ([#13010](https://github.com/paperclipai/paperclip/pull/13010))，干净地解析到同一 GitHub 帐户的重复连接 ([#13022](https://github.com/paperclipai/paperclip/pull/13022))，并且登录状态和连接存储库访问在 UI 中可见并简化（[#12993]（https://github.com/paperclipai/paperclip/pull/12993）、[#13047]（https://github.com/paperclipai/paperclip/pull/13047）、[#12893]（https://github.com/paperclipai/paperclip/pull/12893））。
- **公告到达应用程序** — 原生公告卡使用原生组件呈现经过验证的 JSON 提要（主角可以是静态图像或独立的 HTML/CSS 动画），因此发布或撤回卡片不需要发布应用程序。该实例上的每个帐户都会存在解雇情况 - 关闭的卡在公司和浏览器之间保持关闭状态 - 命名的临时提要允许作者在制作之前测试内容。默认情况下针对托管源启用；升级指南可以选择退出。 ([#13403](https://github.com/paperclipai/paperclip/pull/13403))
- **入职直接走向工作代理** - 连接步骤作为模型源问题打开，内置提供商登录 - 单张卡上的一个连续序列，包括 API 密钥输入，粘贴的登录代码保留在屏幕上并立即回答（[#12440](https://github.com/paperclipai/paperclip/pull/12440)、[#12863](https://github.com/paperclipai/paperclip/pull/12863)、 [#12801](https://github.com/paperclipai/paperclip/pull/12801)、[#12820](https://github.com/paperclipai/paperclip/pull/12820)、[#12613](https://github.com/paperclipai/paperclip/pull/12613)、[#13193](https://github.com/paperclipai/paperclip/pull/13193))。现在，您的第一个任务以与参谋长的聊天形式打开，参谋长等待您的答复而不是自行逃跑，并且参谋长的招聘是可靠的（[#13068]（https://github.com/paperclipai/paperclip/pull/13068），[#13317]（https://github.com/paperclipai/paperclip/pull/13317））。创建以后的代理会在简化的向导中借用相同的连接控件和重新组织的配置页面 ([#13011](https://github.com/paperclipai/paperclip/pull/13011))，并且在设置过程中会重复使用保存的模型连接，而不是要求您再次登录 ([#13161](https://github.com/paperclipai/paperclip/pull/13161))。

## 改进
- **应用程序和连接器目录不断增长** - 应用程序离开了其实验大门，连接设置更短，托管的 Google 访问可在具有安全默认来源的干净自托管安装上运行（[#12728](https://github.com/paperclipai/paperclip/pull/12728)）。下面：连接授予和委派身份 ([#12341](https://github.com/paperclipai/paperclip/pull/12341))、托管外部 MCP 连接器 ([#12346](https://github.com/paperclipai/paperclip/pull/12346))、安全远程 MCP 和 PostHog 设置 ([#12339](https://github.com/paperclipai/paperclip/pull/12339))、Composio 和 Gmail 连接器 ([#12342](https://github.com/paperclipai/paperclip/pull/12342))、扩展的自助服务目录，具有基于意图的设置（[#12344](https://github.com/paperclipai/paperclip/pull/12344)、[#12347](https://github.com/paperclipai/paperclip/pull/12347)、[#12345](https://github.com/paperclipai/paperclip/pull/12345))、精细的 Postman 和 Shopify 流程 ([#12357](https://github.com/paperclipai/paperclip/pull/12357)) 以及整合的连接器管理（[#12684]（https://github.com/paperclipai/paperclip/pull/12684））。 Google Workspace 设置后来进行了端到端修复：目录和创建使用相同的可用性规则，所有权选择在功能更改后仍然存在，Paperclip 是默认的 Google 身份验证方法，具有自定义 OAuth 一链接（[#13289](https://github.com/paperclipai/paperclip/pull/13289)、[#12619](https://github.com/paperclipai/paperclip/pull/12619)、[#12623](https://github.com/paperclipai/paperclip/pull/12623)）。代理还可以从本机任务源请求新的服务连接，并从任务中查看连接操作（[#13058](https://github.com/paperclipai/paperclip/pull/13058)、[#13063](https://github.com/paperclipai/paperclip/pull/13063)）。
- **模型和提供程序更新** — Claude Fable 5.1 可以在 Claude 适配器中选择，具有直接的人类和基岩推理配置文件 ID ([#12730](https://github.com/paperclipai/paperclip/pull/12730))； Codex 凭借其特定于模型的控件获得了 GPT-6 Astra ([#12851](https://github.com/paperclipai/paperclip/pull/12851))；未设置的 Claude 模型在任何地方都解析为 Opus 5，默认值在代理配置中可见 ([#13055](https://github.com/paperclipai/paperclip/pull/13055))。 Grok 将沙箱设备登录面板与一个私有的、公司范围的凭证主页一起加入，管理远程订阅运行并将刷新的凭证复制回主机（[#12469](https://github.com/paperclipai/paperclip/pull/12469)、[#12618](https://github.com/paperclipai/paperclip/pull/12618)、[#12696](https://github.com/paperclipai/paperclip/pull/12696)）。每个 Codex 帐户都有自己的主目录和路径秘密，并且代理可以绑定到公司默认登录之外的 Codex 登录名（[#12709](https://github.com/paperclipai/paperclip/pull/12709)、[#13067](https://github.com/paperclipai/paperclip/pull/13067)）。
- **原生 Paperclip Runner 现在可以完成全部工作 - 并且自托管安装默认情况下打开大门** - 上一个版本的基础工作成为 `enableNativeRunner` 标志背后的完整实验执行引擎，现在默认为**自托管实例启用**（云管理实例将其关闭）（[#13068]（https://github.com/paperclipai/paperclip/pull/13068））：本机 Codex 执行和 Claude ACPX 运行时加上合格的 OpenCode 运行时（[#12616](https://github.com/paperclipai/paperclip/pull/12616)、[#12590](https://github.com/paperclipai/paperclip/pull/12590)、[#12588](https://github.com/paperclipai/paperclip/pull/12588)、[#12691](https://github.com/paperclipai/paperclip/pull/12691))、托管提供程序后端 ([#12699](https://github.com/paperclipai/paperclip/pull/12699))、具有安全传输的远程执行基础（[#12638](https://github.com/paperclipai/paperclip/pull/12638)、[#12639](https://github.com/paperclipai/paperclip/pull/12639)）、管理和可观察性（[#12641](https://github.com/paperclipai/paperclip/pull/12641)）以及本机转投影到任务聊天（[#12617](https://github.com/paperclipai/paperclip/pull/12617)）。该控件是一个统一标志，用于控制每个设置路径（[#12656](https://github.com/paperclipai/paperclip/pull/12656)、[#12666](https://github.com/paperclipai/paperclip/pull/12666)）。开放默认设置仅解锁大门：显式配置的本地 Codex、OpenCode 和合格的 ACPX 代理可以使用运行器，登录保留在旧适配器上，不会自动切换，并且在实验设置中关闭 `enableNativeRunner` 会再次关闭它。
- **操作员控制** — 托管实验标志 `enableIsolatedWorkspacesByDefault` 使没有自己策略的每个项目都使用独立的每任务 git 工作树，因此舰队默认不再意味着手动编辑每个项目（[#13444](https://github.com/paperclipai/paperclip/pull/13444)）。新的标准 trust 代理可以默认雇用其他代理 - 低 trust 代理保留禁用的默认设置（[#12814](https://github.com/paperclipai/paperclip/pull/12814)）。哨兵监控分为 `SENTRY_DSN_FRONTEND` 和 `SENTRY_DSN_BACKEND`，旧的 `SENTRY_DSN` 仍然作为后备（[#12678](https://github.com/paperclipai/paperclip/pull/12678)）。实验设置页面摆脱了死控件和组开发人员工具（[#12681](https://github.com/paperclipai/paperclip/pull/12681)），并且 `PAPERCLIP_HIDDEN_SETTINGS` 也在生产切换器菜单中受到尊重（[#12788](https://github.com/paperclipai/paperclip/pull/12788)）。
- **任务界面焕然一新** - 简化的导航基础，具有精致的任务和工作区界面、一致的悬停/弹出/间距行为以及紧凑的仪表板和实时运行卡，您可以实际扫描（[#12746](https://github.com/paperclipai/paperclip/pull/12746)、[#12747](https://github.com/paperclipai/paperclip/pull/12747)、[#12748](https://github.com/paperclipai/paperclip/pull/12748)、 [#12854](https://github.com/paperclipai/paperclip/pull/12854)、[#12793](https://github.com/paperclipai/paperclip/pull/12793)、[#13269](https://github.com/paperclipai/paperclip/pull/13269))。工作产品在任务工件选项卡上获得丰富的卡片和运行工件清单 ([#12717](https://github.com/paperclipai/paperclip/pull/12717))，`viewer=full` 文档深层链接直接从外部通知打开最大化的侧窗格 ([#12812](https://github.com/paperclipai/paperclip/pull/12812))，作曲家获得带有简化的任务控件、状态徽章和内联阻止程序删除的停止控件（[#13104](https://github.com/paperclipai/paperclip/pull/13104)、[#13097](https://github.com/paperclipai/paperclip/pull/13097))、单项选择题在选择中提前 ([#13234](https://github.com/paperclipai/paperclip/pull/13234))、跑步者活动压缩为在实时和保存的视图中共享的滚动的每组摘要 ([#13255](https://github.com/paperclipai/paperclip/pull/13255)、 [#13274](https://github.com/paperclipai/paperclip/pull/13274)、[#13421](https://github.com/paperclipai/paperclip/pull/13421))、从任务创建的任务按项目显示 ([#13241](https://github.com/paperclipai/paperclip/pull/13241))、长任务聊天在流式传输期间保持响应 ([#13229](https://github.com/paperclipai/paperclip/pull/13229)、[#13228](https://github.com/paperclipai/paperclip/pull/13228))，以及移动设备获得真正的实体选择器表、全角任务树和间距通道（[#13343](https://github.com/paperclipai/paperclip/pull/13343)、[#13250](https://github.com/paperclipai/paperclip/pull/13250)、[#13304](https://github.com/paperclipai/paperclip/pull/13304)、[#13122](https://github.com/paperclipai/paperclip/pull/13122))。
- **找到任务的任务搜索** - 完整和快速的搜索统一围绕 PostgreSQL 术语覆盖范围，具有明确的相关带和保守的拼写错误恢复，并根据评分语料库进行判断。 ([#13335](https://github.com/paperclipai/paperclip/pull/13335))
- **在不接触数据的情况下尝试它** - 仅前台 `test-drive` CLI 命令使用自己的数据目录和提供商支持的 CEO 启动一个隔离实例，并具有重用保护措施和恢复的凭据输入（[#12894](https://github.com/paperclipai/paperclip/pull/12894)、[#12898](https://github.com/paperclipai/paperclip/pull/12898)）；除非明确要求，否则服务器启动不再打开浏览器（[#12435](https://github.com/paperclipai/paperclip/pull/12435)）。
