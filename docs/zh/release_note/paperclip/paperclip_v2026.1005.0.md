# paperclip v2026.1005.0

# 纸clip v2026.1005.0

> 发布时间：2026-10-05

Paperclip v2026.1005.0 包含 179 次提交，从 `2026.1002.0-beta.0` 升级。标题是代理携带更多内容：Grok Build 在本机运行器上运行，代理在任务之间保存自己的文件，公司技能从 GitHub 存储库同步，浏览器使用云为代理提供了一个实时浏览器，人们可以观看并接管任务。围绕这些：大多数连接器现在设置在一个 click 中，默认情况下打开 MCP 聚合器，Slack 对话在板和线程之间往返，代理聊天拥有自己的导航并手动完成工作返回对话，任务编辑器为每条消息选择模型和工作量。在下面，长可靠性传递强化了本机运行器、沙箱传输和心跳调度程序，包括修复因永久拒绝的排队运行而导致的服务器崩溃循环。

## 重大变更

- **删除了操作员 UI 片段注入。** `PAPERCLIP_CLOUD_UI_SNIPPET` 和 `PAPERCLIP_CLOUD_UI_SNIPPET_B64` 设置不再将 HTML 注入静态或开发页面。依赖它们的运营商应该在升级之前将集成转移到插件 UI 贡献中。 ([#13789](https://github.com/paperclipai/paperclip/pull/13789))
- **键盘快捷键始终打开，并且它们的设置消失了。** 实例范围的常规切换和每用户配置文件首选项以及 `GET`/`PATCH /api/auth/preferences` 路由都被删除； `PATCH /api/instance/settings/general` 不再接受 `keyboardShortcuts`。现在每个登录用户都启用了快捷方式。 （[#14141]（https://github.com/paperclipai/paperclip/pull/14141），[#14643]（https://github.com/paperclipai/paperclip/pull/14643））
- **@-提及代理不再启动运行。** 任务注释中的提及将保留为受让人的上下文；只有明确的分配和审查请求才开始工作。使用提及将第二个代理拉到任务上的工作流程必须改为分配或请求审核。 ([#14577](https://github.com/paperclipai/paperclip/pull/14577))

## 亮点

- **Grok Build 在本机运行器上** — Grok Build 通过 ACP 加入 Paperclip Runner，用于本地和 Daytona 执行，具有单独的订阅登录和 API 密钥凭证路径和受管理工具（[#13882](https://github.com/paperclipai/paperclip/pull/13882)）；它在公共安装中附带沙箱拥有的二进制文件，而不是在安装时下载（[#14024](https://github.com/paperclipai/paperclip/pull/14024)）。共享线束运行时移至 Codex 0.156.0、Claude Agent SDK 0.3.280 和 OpenCode 1.18.32 ([#13838](https://github.com/paperclipai/paperclip/pull/13838))，模型目录和推理控件在 Claude、Codex、Grok、Gemini、Cursor、Kimi 和 OpenCode 适配器上刷新([#13829](https://github.com/paperclipai/paperclip/pull/13829))，远程本机 Codex 接受来自 0.149.0 的兼容版本，而不是一个确切的引脚 ([#13853](https://github.com/paperclipai/paperclip/pull/13853))。
- **代理保留自己的文件** — 代理的目录（AGENTS.md 及其支持文件）现在在任务和会话中持续存在，并与指令编辑器共享；并发运行仅应用它们更改的文件，并且新的保存不再创建修订历史记录（[#14420](https://github.com/paperclipai/paperclip/pull/14420)），在具有冲突预检的新纯目录同步传输（[#14416](https://github.com/paperclipai/paperclip/pull/14416)）之上。温暖的本机 Codex 会话通过在每轮后仅对更改的文件进行检查点来保存托管文件收集（[#14735](https://github.com/paperclipai/paperclip/pull/14735)）。
- **从 GitHub 同步的技能** — 技能获得“来源”选项卡：通过现有 GitHub 连接选择存储库，选择要导入的技能文件夹，并按需刷新。安装的快照意味着代理永远不会在运行中获取 GitHub，并且刷新失败会保留最后一个好的版本（[#14713](https://github.com/paperclipai/paperclip/pull/14713)）。
- **浏览器使用云，实时参与任务** — 新的浏览器使用云连接器为代理提供了受管理的浏览器自动化，任务显示交互式浏览器选项卡，人们可以在其中跟踪、接管页面并在运行完成后保留浏览器，并根据运行记录成本 ([#14627](https://github.com/paperclipai/paperclip/pull/14627))。
- **在一台 click 中设置连接** — 连接器设置会折叠到一个屏幕，其中显示其默认设置，并将其余部分隐藏在“更改”和“权限”选项卡后面（[#14811](https://github.com/paperclipai/paperclip/pull/14811)）。 Zapier、Arcade、Composio Connect 和 Executor MCP 聚合器默认处于打开状态，并删除了实验切换 ([#13964](https://github.com/paperclipai/paperclip/pull/13964))，并且可以从内联任务卡 ([#13879](https://github.com/paperclipai/paperclip/pull/13879)) 进行配置。连接搜索更喜欢本机应用程序，要求用户在设置之前选择外部提供商 ([#13941](https://github.com/paperclipai/paperclip/pull/13941))，并理解自然语言查询 ([#14725](https://github.com/paperclipai/paperclip/pull/14725))。目录中的新增功能：Fireflies 具有摘要就绪例程 ([#13890](https://github.com/paperclipai/paperclip/pull/13890))、默认关闭 `enableMemoryConnectors` 设置背后的五个实验性内存提供程序（Mem0、Zep、Supermemory、Cognee、Honcho），以及交付给远程本机 Codex 的指定 MCP 工具 ([#13942](https://github.com/paperclipai/paperclip/pull/13942)) 和 GitHub 代码审查机器人它自己的卡与 GitHub 工具分开（[#14750](https://github.com/paperclipai/paperclip/pull/14750)）。个人粘贴的凭据在设置、运行状况检查和调用时以相同的方式进行验证，并且新连接请求其操作所需的写入范围（[#14739](https://github.com/paperclipai/paperclip/pull/14739)）。
- **Slack 是双向的** — 在板上输入的回复到达链接的 Slack 线程并恢复相同的对话，分配的代理在普通任务和计划例程期间获取其 Slack 工具 ([#13920](https://github.com/paperclipai/paperclip/pull/13920))。 Slack 起源的任务使用受管理的工具来阅读周围的讨论、创建后续内容并通过邀请机器人进行协作 ([#13828](https://github.com/paperclipai/paperclip/pull/13828))，并且已回答的对话将停留在“空闲”状态，而不是徘徊在“进行中”([#13809](https://github.com/paperclipai/paperclip/pull/13809))。
- **代理聊天成长** — 辅助聊天侧边栏和登陆页面为对话提供了自己的家（[#14706](https://github.com/paperclipai/paperclip/pull/14706)）；从聊天委派的任务将其完成情况持久地返回给它（[#14408](https://github.com/paperclipai/paperclip/pull/14408)）；在聊天中输入明确的批准即可解决待处理的卡，未回答的问题将进入历史记录，稍后可以回答（[#14613](https://github.com/paperclipai/paperclip/pull/14613)）；并且在其本机工作线程丢失后聊天继续（[#13813](https://github.com/paperclipai/paperclip/pull/13813)）。
- **选择运行的编辑器** - 任务编辑器获得每条消息的模型和工作量选择器，该模型和工作量选择器跟随所选代理，保持挂起的卡片在其上方可见，并在移动设备上工作（[#14322](https://github.com/paperclipai/paperclip/pull/14322)）；工作选项与每个适配器实际执行的内容相匹配，包括本机运行器上的 Codex（[#14568](https://github.com/paperclipai/paperclip/pull/14568)、[#14576](https://github.com/paperclipai/paperclip/pull/14576)）。可以仅根据提示创建任务，并由指定的代理为其命名（[#14761](https://github.com/paperclipai/paperclip/pull/14761)）。工件获得带有预览的丰富卡片 ([#14469](https://github.com/paperclipai/paperclip/pull/14469))、带有全行链接的图像和视频库 ([#13825](https://github.com/paperclipai/paperclip/pull/13825))，以及在任务选项卡中打开的 Markdown 和文本附件，其中包含渲染、原始和下载视图 ([#14297](https://github.com/paperclipai/paperclip/pull/14297))。
- **受管理的 API 工具，默认启用** — 无需环境变量即可启用本机运行程序的 `search_api` 和 `call_api` 工具 ([#14186](https://github.com/paperclipai/paperclip/pull/14186))；大型 API 响应流到磁盘最多 1 GiB，并且保存的文本在有界页面中可读（[#14301](https://github.com/paperclipai/paperclip/pull/14301)）；当指定的应用程序目录使工具合约超出其限制时，代理仍然可以通过搜索和调用来访问这些工具（[#14218](https://github.com/paperclipai/paperclip/pull/14218)）。
