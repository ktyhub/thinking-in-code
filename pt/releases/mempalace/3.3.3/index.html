#mempalace v3.3.3

Correções de bugs

  • Instalar regressão — O script do console mempalace-mcp agora é declarado em pyproject.toml junto com a referência de .claude-plugin/plugin.json a ele. No v3.3.2, os dois se separaram (plugin.json enviou o novo formato "command": "mempalace-mcp" antes do ponto de entrada correspondente chegar), então cada novo pip install mempalace==3.3.2 produzia uma configuração de plugin Claude Code apontando para um binário que não estava instalado. (#1093, #340)
  • Restaure a visibilidade do salvamento silencioso após a regressão do Código Claude 2.1.114 client - os salvamentos da transcrição de produção falhavam silenciosamente até este PR. (#1021)
  • Paginar buscas de metadados do caminho status para que grandes palácios não ultrapassem os limites das variáveis SQLite. (#851)
  • Resolver o runner do gancho do plugin Claude em variações de plataforma/diretório do plugin; quebrou anteriormente no Windows e em alguns layouts do macOS. (#942)
  • Resolução python3 real para ganchos .sh com um caminho de substituição MEMPAL_PYTHON. (#833)
  • Adicione o parâmetro opcional wing a tool_diary_write / tool_diary_read e derive a asa por projeto do caminho de transcrição do Código Claude ao escrever a partir do gancho de parada - as entradas do diário de projetos diferentes não são mais recolhidas em uma asa padrão compartilhada. (#659)
  • Tratar string vazia como “sem filtro” em mempalace_search wing/room; Os agentes LLM cujo padrão é preencher todos os parâmetros opcionais com "" não são mais devolvidos com must be a non-empty string. (#1097, #1084)
  • Amplie _wing_from_transcript_path para lidar com pastas de projetos Claude Code sem um segmento -Projects- (por exemplo, ~/dev/<parent>/<project>, ~/code/<project>). O nome do projeto agora é derivado do token final separado por traço da pasta codificada, para que os usuários do Linux com código fora de ~/Projects/ obtenham o escopo do diário por projeto em vez de passar para wing_sessions. (#1145, continuação de #659)
  • mempalace_diary_read(wing="") agora retorna entradas de diário de todas as alas nas quais este agente escreveu, correspondendo ao padrão #1097 "string vazia como sem filtro". Anteriormente o padrão era wing_<agent>, armazenando entradas que os ganchos escreviam nas asas derivadas do projeto. (#1145)
  • mempalace mine agora ignora o arquivo entities.json gerado para que seu conteúdo não seja reingerido como conteúdo do projeto. (#1175)

Melhorias

  • Ganchos determinísticos salvos. O gancho de salvamento agora usa um caminho silencioso Python API, portanto, invocações de gancho sucessivas produzem resultados reproduzíveis e zero perda de dados no caminho ativo. (#673)
  • Cache de gráfico com invalidação de gravação dentro de build_graph() — as chamadas de caminho quente não reconstroem mais o gráfico do palácio por solicitação. (#661)
  • Revisão da detecção de entidade mempalace init. Nomes de projetos canônicos agora vêm de manifestos de pacotes (package.json, pyproject.toml, Cargo.toml, go.mod) e pessoas reais vêm de autores de commit do git, em vez de serem inferidas da prosa. Inclui desduplicação de localização de união em aliases de nome/e-mail, filtragem de bot que mantém humanos @users.noreply.github.com e sinalização automática de "mina" por parcela de contribuição. (#1148)
  • Precisão do detector Regex. Extração de CamelCase para que MemPalace, ChromaDB, OpenAI não sejam fragmentados; padrão versionado/hifenizado mais rígido mata falsos positivos context-manager / multi-word; o diálogo ^NAME:\s requer ≥2 ocorrências para que os metadados Created: <date> parem de classificar nomes de campos como pessoas; palavras irrelevantes expandidas para particípios e descritores comuns em inglês; o sinal de pronome alto é classificado como pessoa, em vez de dumping para incerto. (#1148)
  • Init → miner wire-up. Entidades confirmadas se fundem em ~/.mempalace/known_entities.json no init, que o minerador lê para marcar os metadados da gaveta para pesquisa filtrada por entidade. Anteriormente, a produção do init não era consumida pelo minerador; o entities.json por projeto é mantido como trilha de auditoria. (#1157)
  • Desduplicação de projeto sem distinção entre maiúsculas e minúsculas em fontes de manifesto, git e convo, de modo que variantes de maiúsculas e minúsculas do mesmo nome de projeto sejam recolhidas em uma entrada de revisão. (#1175)

Adicionado

  • i18n: tradução para bielorrusso. (#1051)
  • i18n: detecção de entidade para localidades alemão, espanhol e francês. (#1001)
  • i18n: detecção de entidade chinesa tradicional + simplificada. (#945)
  • mempalace init --llm: classificação opcional de entidade assistida por LLM. O padrão é Ollama local (zero-API); também suporta qualquer endpoint compatível com OpenAI (LM Studio, servidor llama.cpp, vLLM, OpenRouter, etc.) e o Anthropic Messages API. Funciona de forma interativa com um indicador de progresso; Ctrl-C cancela de forma limpa e retorna resultados parciais. Útil para pastas com muita prosa onde o detector de regex tem dificuldades (diários, transcrições, notas de pesquisa). Somente aceitação – o caminho de inicialização padrão permanece zero-API. (#1150)
  • Scanner de conversas do Claude Code. Os diretórios ~/.claude/projects/<slug>/ agora contribuem com entidades do projeto usando os metadados cwd autorizados de cada sessão, evitando ambiguidade na decodificação de slug. (#1150)

Conhecido — adiado para v3.3.4

  • SIGSEGV de inserção paralela HNSW quando hnsw:num_threads não é definido na criação da coleção (#974) — correção em andamento como #976, aguardando rebase contra desenvolvimento.

Instalar

pip install --upgrade mempalace==3.3.3
