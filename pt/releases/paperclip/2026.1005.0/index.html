#papelclip v2026.1005.0

Papelclip v2026.1005.0

Lançado: 2026-10-05

Paperclip v2026.1005.0 carrega 179 commits, promovidos de 2026.1002.0-beta.0. O título é que os agentes carregam mais consigo: o Grok Build é executado no executor nativo, os agentes mantêm seus próprios arquivos nas tarefas, as habilidades da empresa são sincronizadas a partir dos repositórios GitHub e o Browser Use Cloud oferece aos agentes um navegador ativo que as pessoas podem assistir e assumir o controle da tarefa. Em torno deles: a maioria dos conectores agora configurados em um click com agregadores MCP ativados por padrão, conversas do Slack de ida e volta entre o quadro e o thread, o Agent Chat obtém sua própria navegação e entrega o trabalho concluído de volta à conversa, e o compositor de tarefas escolhe o modelo e o esforço por mensagem. Por baixo, uma longa passagem de confiabilidade fortalece o executor nativo, o transporte sandbox e o agendador de pulsação, incluindo uma correção para um loop de travamento do servidor causado por uma execução na fila permanentemente rejeitada.

Mudanças significativas

  • A injeção de snippet da UI do operador foi removida. As configurações PAPERCLIP_CLOUD_UI_SNIPPET e PAPERCLIP_CLOUD_UI_SNIPPET_B64 não injetam mais HTML em páginas estáticas ou de desenvolvimento. Os operadores que dependiam deles deveriam migrar a integração para uma contribuição de UI de plug-in antes de atualizar. (#13789)
  • Os atalhos de teclado estão sempre ativados e suas configurações desaparecem. A alternância Geral em toda a instância e a preferência de perfil por usuário foram removidas, junto com as rotas GET/PATCH /api/auth/preferences; PATCH /api/instance/settings/general não aceita mais keyboardShortcuts. Cada usuário conectado agora tem atalhos ativados. (#14141, #14643)
  • @-mencionar um agente não inicia mais uma execução. As menções nos comentários da tarefa são mantidas como contexto para o responsável; apenas solicitações explícitas de atribuição e revisão começam a funcionar. Os fluxos de trabalho que usaram uma menção para atrair um segundo agente para uma tarefa devem atribuir ou solicitar revisão. (#14577)

Destaques

  • Grok Build no runner nativo — Grok Build se junta ao Paperclip Runner por meio de ACP para execução local e Daytona, com login de assinatura separado e caminhos de credencial de chave API e ferramentas governadas (#13882); ele é fornecido em instalações públicas com binários de propriedade do sandbox, em vez de um download no momento da instalação (#14024). Os tempos de execução de chicote compartilhado passam para Codex 0.156.0, Claude Agent SDK 0.3.280 e OpenCode 1.18.32 (#13838), catálogos de modelos e controles de raciocínio são atualizados nos adaptadores Claude, Codex, Grok, Gemini, Cursor, Kimi e OpenCode (#13829), e o Codex nativo remoto aceita versões compatíveis do 0.149.0 em vez de um pino exato (#13853).
  • Os agentes mantêm seus próprios arquivos — O diretório de um agente (AGENTS.md e seus arquivos de suporte) agora persiste entre tarefas e sessões e é compartilhado com o Editor de Instruções; execuções simultâneas aplicam apenas os arquivos que eles alteraram e novos salvamentos não criam mais histórico de revisão (#14420), além de um novo transporte de sincronização de diretório simples com simulação de conflito (#14416). Sessões nativas quentes do Codex sobrevivem à coleta de arquivos gerenciados, verificando apenas os arquivos alterados após cada turno (#14735).
  • Habilidades sincronizadas de GitHub — Habilidades ganham uma guia Fontes: escolha um repositório por meio de uma conexão GitHub existente, escolha quais pastas de habilidades importar e atualize sob demanda. Os snapshots instalados significam que os agentes nunca buscam o GitHub no meio da execução, e uma atualização com falha deixa a última versão válida no lugar (#14713).
  • Navegador Use Cloud, ao vivo na tarefa — Um novo conector Browser Use Cloud oferece aos agentes automação de navegador controlada, e as tarefas mostram guias interativas do navegador onde as pessoas podem acompanhar, assumir o controle da página e manter o navegador após o término da execução, com custos registrados em relação à execução (#14627).
  • Conexões configuradas em um click — A configuração do conector é recolhida em uma tela que indica seus padrões e coloca o restante atrás de "Alterar" e da guia Permissões (#14811). Os agregadores Zapier, Arcade, Composio Connect e Executor MCP estão ativados por padrão com a alternância experimental removida (#13964) e podem ser configurados a partir de cartões de tarefas inline (#13879). A pesquisa de conexão prefere aplicativos nativos, pede ao usuário para escolher um provedor externo antes da configuração (#13941) e entende consultas em linguagem natural (#14725). Novidade no catálogo: Fireflies com rotinas prontas para resumo (#13890), cinco provedores de memória experimental (Mem0, Zep, Supermemory, Cognee, Honcho) por trás da configuração padrão enableMemoryConnectors, além de ferramentas MCP atribuídas entregues ao Codex nativo remoto (#13942) e GitHub Code Review Bot como seu próprio cartão separado de Ferramentas GitHub (#14750). As credenciais pessoais coladas são validadas da mesma maneira na configuração, verificação de integridade e invocação, e novas conexões solicitam os escopos de gravação de que suas ações precisam (#14739).
  • O Slack funciona nos dois sentidos — As respostas inseridas no quadro chegam ao tópico vinculado do Slack e retomam a mesma conversa, e os agentes designados obtêm suas ferramentas do Slack durante tarefas comuns e rotinas agendadas (#13920). As tarefas de origem do Slack recebem ferramentas controladas para ler a discussão ao redor, criar acompanhamentos e colaborar por meio do bot convidativo (#13828), e uma conversa respondida fica ociosa em vez de permanecer em andamento (#13809).
  • Agent Chat cresce — Uma barra lateral de chat secundária e uma página inicial dão às conversas sua própria casa (#14706); tarefas delegadas de um bate-papo devolvem sua conclusão de forma duradoura (#14408); uma aprovação clara digitada no chat resolve o cartão pendente e as perguntas não respondidas passam para o histórico, onde podem ser respondidas posteriormente (#14613); e um bate-papo continua após a perda de seu trabalhador nativo (#13813).
  • Um compositor que escolhe a execução — O compositor de tarefas ganha um modelo por mensagem e um seletor de esforço que segue o agente selecionado, mantém os cartões pendentes visíveis acima dele e funciona no celular (#14322); as opções de esforço correspondem ao que cada adaptador realmente executa, incluindo Codex no executor nativo (#14568, #14576). As tarefas podem ser criadas apenas a partir de um prompt e o agente atribuído as nomeia (#14761). Os artefatos recebem rich cards com visualizações (#14469), uma galeria de imagens e vídeos com links de linha completa (#13825) e Markdown e anexos de texto abertos em guias de tarefas com visualizações renderizadas, brutas e de download (#14297).
  • Ferramentas API governadas, ativadas por padrão — As ferramentas search_api e call_api do executor nativo são habilitadas sem uma variável de ambiente (#14186); grandes respostas API são transmitidas para disco de até 1 GiB e o texto salvo pode ser lido em páginas delimitadas (#14301); e quando um catálogo de aplicativos atribuído ultrapassa o limite do contrato de ferramenta, os agentes ainda acessam essas ferramentas por meio de pesquisa e chamada (#14218).

Correções

  • Executor e sessões nativos — Os resultados da ferramenta sobrevivem ao desligamento e à reinicialização em vez de registrar uma falha falsa (#14734); sessões quentes com falha são descontinuadas antes de sua sandbox parar (#14747) e a limpeza recuperada honra o resultado terminal da execução (#14767); mudar uma tarefa para um ciclo de vida quente adquire uma concessão reutilizável (#14187); o fluxo de eventos OpenCode permanece aberto durante os turnos (#14582) e entrega sua liquidação de desligamento (#14668); As notificações da conta Codex não abortam mais um turno (#13902); O esgotamento das cotas de Claude e Codex é classificado para a retirada adequada (#13831, #13945); As falhas do terminal ACP mantêm seus diagnósticos de provedor editados (#14573) e os guardas de identidade nomeiam a verificação com falha (#14481); o limite de leitura do diário nativo é de 256 MiB em todos os lugares (#14711); a finalização pendente de um resultado aceito é protegida da varredura de bloqueio obsoleto (#14219); adaptadores expõem uma parada de provedor verificada antes da restauração do espaço de trabalho (#14311); sessões quentes continuam sendo executadas sob acesso gerenciado GitHub (#13815); e uma execução que atinge uma falha de autenticação do provedor oferece um cartão de conexão em linha na tarefa para que o usuário possa reparar e continuar (#14629).
  • Sandboxes e espaços de trabalho — Os comandos Daytona permanecem ativos após o fechamento do soquete de log (#14799), a perda confirmada do contêiner é reconhecida ao retomar concessões (1f3ff75d), as alocações com falha são limpas (#13979) e os tempos limite de aquisição do provedor respeitam o padrão do driver (#14097). Novas tentativas de entrega de entrada ACP após um gateway 502 sem duplicação de entrada (#14485), cargas úteis de lançamento superdimensionadas e contexto de ativação duplicado não falham mais com E2BIG (#13793, #13891), proxies de processo fecham após saída remota (#13777), e links simbólicos relativos em repositórios secundários são preservados (#13953). As exportações do espaço de trabalho são finalizadas e recuperadas com segurança (#14402), falhas de restauração mantêm o resultado do adaptador e registram o que falhou (#14035, #14064), grandes instantâneos do Git são transmitidos através de manifestos de disco em vez de atingir um limite de saída de 1 MiB (#14194, #14253), verificações de prontidão aceitam saída de status maior (#14414), verificações em segundo plano param de atualizar o índice Git (#14666), substituições parciais de tarefas retêm comandos de configuração do projeto (#14502) e tarefas de baixo trust sem repositório obtêm um diretório privado (#14766).
  • Agendador e recuperação — Uma execução na fila cuja solicitação é rejeitada permanentemente é cancelada em vez de fazer um loop de falha no servidor (#14738); despertares que chegam durante um dreno permanecem na fila e execuções corretivas interrompidas recebem uma nova tentativa transitória (#14028); um problema cuja execução esgotou seu orçamento de novas tentativas é escalado para um estado visível bloqueado em vez de ser ignorado para sempre (#14046); orçamentos de continuação e repetição usam estado persistente (#13888); a propriedade da tarefa é reivindicada atomicamente com execuções na fila (#13973); continuações obsoletas são canceladas antes do envio (#13761); uma resposta de status que ainda lista o trabalho bloqueado mantém a tarefa em movimento (#14626); Tarefas concluídas e canceladas mantêm seu responsável na liberação (#14561); as continuações de interação permanecem no escopo de sua tarefa (ded156a9) e os destinatários das perguntas são derivados e validados (#14742); As tarefas originadas no Slack e no Discord que perdem seu caminho de revisão se recuperam com suas ligações de mensagens intactas, em vez de falharem na verificação de autorização de recuperação (#13818); as execuções remotas do Grok param antes que as mensagens na fila continuem (#14100); os bloqueios de identidade de execução não travam mais com inserções de auditoria (#14478); e desconexões ambíguas do banco de dados não são mais reproduzidas (#14773).
  • Conexões e aplicativos — Desafios de login do OAuth e estados de reconexão retornam 422 em vez de serem relatados como falhas (#13786, #13794); A configuração do MCP OAuth explica o consentimento falhado ou cancelado (#13855); um aplicativo Slack MCP desativado recebe instruções de configuração acionáveis ​​(a7d3b17a); As falhas do corretor e do AgentMail mantêm códigos de motivo permitidos (#14098, #14768); O Chat do Google e os perfis do Documentos, Planilhas, Apresentações e Agenda solicitam menos escopos (#13820, #14740); produtos de trabalho validam sua referência de espaço de trabalho de execução (#14063); e IDs de desafio de autenticação CLI malformados retornam 400 (#14095).
  • IU da placa — A placa se recupera durante as reinicializações do servidor com uma mensagem de conexão e tenta novamente, mantendo os editores abertos montados (#14560) e oferece uma tela de nova tentativa quando o aplicativo falha antes do React iniciar (#13970). O realce de código não trava mais em uma incompatibilidade de versão Lezer (a3749aac), botões de confirmação destrutivos são legíveis no tema claro (#14328), seletores móveis permanecem visíveis acima do teclado e rolam por toque (#14022, #14249, #14250, #14599), rascunhos mais recentes sobrevivem à limpeza do recibo (#14332), execuções com falha de outros usuários ficam fora do meu (#14572), "Recuperação necessária" é diferenciada de "Recuperação em andamento" (#14326) e uma nova tentativa enganosa não aparece mais quando a recuperação é bloqueada (#13775), novos artefatos registram uma guia sem abrir o painel (#14193), o painel Tarefas mostra ancestrais (#13823) e o conteúdo da tarefa aparece mais cedo com leituras de servidor paralelo (#14727). Além disso: ícones de propriedade alinhados com avatares (#13319), comentários do corredor alinhados com respostas (#14716), indicadores de salvamento de projeto empilhados abaixo de seu rótulo (#14765), arquivamento de uma empresa navega para longe (#13846), configurações experimentais são organizadas em ordem alfabética com grupos vazios ocultos (#13905), e o adaptador Cursor seleciona o erro real em um aviso de rastreamento (#14636).
  • Observabilidade — Erros do navegador carregam SENTRY_ENVIRONMENT (#13784) e contexto de componente limitado (#13904); erros de execução são isolados de exceções posteriores e um cabeçalho de capacidade de tempo de execução é editado (#13826); e relatórios de falha de execução retêm detalhes de saída, pilhas, causas, atividade de tempo de execução e classificação de restauração (#14575, #14585, #14665, #14639, #14787).

Melhorias

  • O menu da conta descarta suas linhas de perfil para um link de cabeçalho e ganha um atalho de convite (#14480); plug-ins podem fornecer um alternador de organização (#13832, #13854); PAPERCLIP_HIDDEN_SETTINGS aceita um curinga com exceções nomeadas para que novos sinalizadores experimentais permaneçam ocultos automaticamente (#13980) e uma chave workspaces.isolation oculta controles de isolamento (#13907); o executor nativo ganha uma base de transporte ACP rica compartilhada para os próximos provedores de Cursor, GitHub Copilot e Pi (#14430); agentes nativos podem contratar colegas de equipe por meio de uma ação hire_agent governada que herda a configuração de tempo de execução do chamador de uma lista de permissões fechada (#13852); a habilidade de coordenação não diz mais aos agentes para passarem pelos gerentes em vez de perguntar ao humano quem pode agir (#14188); falhas na fonte de sementes da árvore de trabalho explicam as configurações suportadas (#14795); Os conectores do Google Workspace ficam temporariamente ocultos na página Conexões enquanto a verificação do Google OAuth está pendente, com conexões salvas e acesso ao tempo de execução intactos (#14774); e o README é atualizado com chicotes atuais, links de guia e um início rápido npx-first (#14741, #14744).

Guia de atualização

  • Migrações 0284–0293 executadas na atualização: 0284 adiciona e 0289 elimina a coluna keyboard_shortcuts por usuário; 0285 amplia assets.byte_size para bigint; 0286 adiciona reservas de captura de resposta API; 0287 adiciona cabeçalhos de instrução de agente, revisões e cópias de trabalho para arquivos de agente persistentes; 0288 adiciona entregas de conclusão de chat e transferências de tarefas; 0290 adiciona sessões, execuções e navegadores de uso do navegador na nuvem; 0291 – 0292 adiciona fontes e entradas de habilidades da empresa, e 0291 também adota habilidades existentes importadas de github.com para eles (uma fonte por repositório e referência de rastreamento, uma entrada por habilidade e legacySkillSourceId / skillSourcePath carimbado nos metadados de cada habilidade; habilidades importadas de hosts corporativos GitHub, habilidades agrupadas e habilidades de catálogo são deixadas como estão, e nenhuma solicitação de provedor ou reescrita de conteúdo acontece); 0293 adiciona issues.title_needs_generation.
  • Os snippets da UI do operador foram removidos (#13789): PAPERCLIP_CLOUD_UI_SNIPPET e PAPERCLIP_CLOUD_UI_SNIPPET_B64 são ignorados. Mova a integração para uma contribuição de UI de plug-in antes de atualizar.
  • As configurações de atalho do teclado foram removidas (#14643): elimine qualquer automação que chame /api/auth/preferences ou envie keyboardShortcuts para a rota de configurações gerais.
  • Agente menciona não mais despacho (#14577): use uma atribuição ou uma solicitação de revisão para trazer outro agente para uma tarefa.
  • Novos padrões: as ferramentas API do runner nativo são habilitadas a menos que PAPERCLIP_RUNNER_API_TOOLS_ENABLED esteja configurado para algo diferente de true; PAPERCLIP_RUNNER_API_TOOLS_COMPANY_IDS ainda os restringe (#14186). Os agregadores MCP estão disponíveis sem o antigo sinalizador enableMcpAggregators (#13964).
  • Novas variáveis ​​de ambiente, todas opcionais: os limites PAPERCLIP_RUNNER_API_COMPANY_CAPTURE_MAX_BYTES capturaram bytes de resposta API por empresa (padrão 20 GiB, mínimo 1 GiB; #14301); PAPERCLIP_WORKSPACE_GIT_SNAPSHOT_TIMEOUT_MS limita o tempo de snapshot do espaço de trabalho (padrão 30 minutos, máximo 24 horas) e PAPERCLIP_WORKSPACE_MANIFEST_MIN_FREE_BYTES define a reserva de disco livre para manifestos de snapshot (padrão 256 MiB, mínimo 64 MiB; #14253). As execuções do Codex ACP aceitam CODEX_API_KEY como uma alternativa ao OPENAI_API_KEY (#14322).
  • Pinos de chicote movidos para Codex 0.156.0, Claude Agent SDK 0.3.280 e OpenCode 1.18.32 (#13838); instalações compartilhadas devem atualizar seus CLIs de provedor para corresponder.
  • Nenhuma outra configuração ou alteração do API requer ação.
