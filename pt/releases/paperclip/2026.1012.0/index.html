Papelclip v2026.1012.0

Lançado: 2026-10-12

Paperclip v2026.1012.0 carrega 130 commits, promovidos de 2026.1006.0-beta.0. A manchete é que assistentes externos agora podem se juntar à sua equipe: Claude Code, Codex, OpenCode e qualquer MCP client podem se conectar ao Paperclip como uma pessoa registrada, revisar trabalhos e delegar tarefas, tudo em um ambiente experimental. Em torno disso: o Chat lidera a navegação com as tarefas e artefatos de cada agente ao lado da conversa, o catálogo Connections extrai contas que você já vinculou no Composio e Arcade, as conexões carregam instruções de uso que chegam aos seus agentes automaticamente, Claude Sonnet 5.5 e GPT-6.1 Sol chegam com equipamentos atualizados e os agentes podem atualizar com segurança as habilidades da empresa. Por baixo, as execuções do Codex sobrevivem às reinicializações do servidor e aos erros de capacidade do modelo, os bloqueios de restauração do espaço de trabalho passam para bloqueios de arquivo SQLite seguros contra falhas e as instruções do agente padrão diminuem para uma fração de seu tamanho anterior.

Mudanças significativas

  • Protocolo de alteração de bloqueios de restauração do espaço de trabalho; interrompa todos os processos antigos antes de atualizar. Os bloqueios de restauração e coleta de arquivos do agente agora são bloqueios de arquivos SQLite apoiados pelo sistema operacional sob <instance root>/locks/directory-merge/, liberados pelo kernel quando um processo falha. Versões antigas e novas não devem gravar na mesma raiz da instância ao mesmo tempo: drenar e parar todos os servidores antigos e processos de trabalho (incluindo outros hosts ou contêineres) antes de atualizar ou reverter e, em seguida, mover quaisquer diretórios <hash>.lock/ legados restantes para um local temporário. Nunca exclua ou mova os novos arquivos .lock.sqlite. Consulte doc/workspace-restore-locks.md. (#14869)
  • As concessões de ferramentas armazenadas são aplicadas conforme escritas. Uma concessão cuja lista scope.allow não corresponde a uma ferramenta, conexão ou aplicativo não se enquadra mais em uma política mais ampla; concessões com seletores desconhecidos ou restrições malformadas agora negam acesso. Revise as concessões personalizadas após a atualização se um agente perder uma ferramenta usada anteriormente. (#14915)

Destaques

  • Assistentes se juntam à sua equipe pelo MCP — Um novo cartão "Assistant Connection (MCP)" no Connections permite que Claude Code, Codex, OpenCode e MCP clients genéricos se conectem ao Paperclip por meio do navegador OAuth ou consentimento do código do dispositivo e atuem como o usuário conectado: leia e pesquise tarefas, crie e delegue trabalho, deixe comentários humanos, leia documentos e entregas e acompanhe resultados por meio de webhooks de eventos assinados (#14846). O consentimento mostra o client e a organização, o acesso de gravação pode ser desativado, as solicitações podem ser fixadas em uma empresa e um login do dispositivo paperclip mcp CLI conecta o stdio local clients; ele está desativado por padrão em Configurações → Experimental → "Conexões do assistente (MCP)" e requer HTTPS PAPERCLIP_PUBLIC_URL (#14933).
  • O Chat lidera — Com o Chat do Agente habilitado na UI simplificada (o shell padrão), o Chat é a primeira linha na navegação Trabalho, o painel do chat lista todos os agentes elegíveis e o painel lateral mostra as tarefas e artefatos recentes do agente; uma nova configuração experimental "Caixa de entrada combinada + lista de tarefas" dobra a caixa de entrada em tarefas como visualizações (#15100). As instâncias que desativaram a "IU simplificada" mantêm a navegação legada e não veem essas alterações. A entrada Bate-papo reabre a última conversa que você visitou (#14848) e o cabeçalho do bate-papo mostra o avatar do agente (#14726).
  • Um catálogo para cada conta — O catálogo de aplicativos do Connections descobre contas já conectadas upstream no Composio, Arcade e gateways Executor suportados e as agrupa com contas nativas em um cartão de aplicativo, com chips de origem, pesquisa e paginação (#15254). AgentMail é uma conexão padrão com cartões de configuração in-line no Agent Chat (#14772), Neon entra no catálogo com OAuth ou login com chave API (#14980), Asana funciona novamente com um "Entrar com Asana" padrão (#14756), e as contas AI ganham uma ação "Verificar uso" que diz limites atuais do provedor para Codex, Claude, Grok e OpenRouter (#14936).
  • Conexões transportam instruções para agentes — Uma conexão pode conter instruções de uso editáveis ​​que são entregues a cada turno de agente autorizado no executor nativo, adaptadores legados e contratos HTTP/processo. Os padrões de envio Honcho, Mem0, Zep, Supermemory e Cognee, o editor aparece na configuração e no painel Permissões, e as instruções do agente mostram uma seção "De conexões" somente leitura (#15216).
  • Novos modelos, chicotes atualizados — Claude Sonnet 5.5 é selecionável para agentes Claude Code com esforço Baixo a Máximo, e o tempo de execução qualificado de Claude passa para Claude Code 2.1.286 (#14993); GPT-6.1 Sol se junta ao adaptador Codex com modo Rápido e Ultra esforço, Bedrock ganha Sonnet 5.5 e os pinos compartilhados passam para Codex 0.160.0 e OpenCode 1.18.34 (#14942). Os menus de modelos Claude e Codex agora listam os modelos na mesma ordem que os aplicativos Claude e ChatGPT (#14917, #14918).
  • Os agentes mantêm as habilidades da empresa — Os agentes executores nativos recebem uma ferramenta update_skill que reescreve uma habilidade da empresa com verificação de versão e novas tentativas seguras, registradas no histórico de versões e no log de auditoria; o arquivo de habilidade API ganha campos opcionais expectedVersionId e idempotencyKey (#15049). Os agentes recém-criados recebem um conjunto padrão de concessões de configuração para que possam concluir a configuração do agente, da ferramenta, da habilidade e da tarefa sem trabalho de permissão manual (#15283).
  • Execuções do Codex que sobrevivem a reinicializações e limites de capacidade — Um turno nativo do Codex eliminado por uma reinicialização do servidor é retomado na mesma conversa assim que o processo antigo for comprovado (#15297); um modelo com capacidade mostra um cartão "Modelo com capacidade" e tenta novamente automaticamente após um e dois minutos (#15347); um modelo que a conta ChatGPT não pode usar mostra "Modelo indisponível" com orientação em vez de recuperação genérica (#15299, #15304); e o Codex mantém sua base de estoque pronta, recebendo o contexto do Paperclip como instruções de desenvolvedor aditivo (#14920).
  • Uma caixa de diálogo Nova tarefa reconstruída — A caixa de diálogo é construída no compositor de tarefas compartilhadas com uma barra de Projeto e Árvores de Trabalho, responsável lembrado, projeto e esforço, e menções de tarefas em sugestões; os controles de status, revisor, aprovador e watchdog saem da caixa de diálogo para as propriedades da tarefa e as novas tarefas são padronizadas para o último responsável usado (#15091). As tarefas criadas sem título recebem um título provisório de texto simples e limpo (#15047).
  • Instruções padrão muito mais curtas — Novas empresas e contratações recebem descrições de funções em vez de manuais de procedimentos: as instruções padrão do CEO caem de cerca de 1.900 palavras para 20 (#14985), novas contratações não-CEO recebem um manual padrão de uma frase (#14948), e as habilidades de planejamento agrupadas diminuem para cerca de 400 palavras combinadas e não forçam mais uma tarefa infantil matriz (#15296). Os manuais salvos e pacotes personalizados existentes permanecem inalterados.

Correções

  • Executor e sessões nativos — Uma execução cuja resposta final foi salva, mas cujo encerramento falhou atinge seu status final correto, e a ferramenta list_projects do agente retorna resumos paginados em vez de estourar o limite de comando (#15217); tarefas interrompidas durante a preparação nativa em uma compilação mais antiga recuperam Tente novamente e aceite novas mensagens (#15020, #15022); uma continuação cancelada pela porta de revisão de execução na fila é tratada como uma espera de revisão em vez de uma suspensão de execução desconhecida (#15024); Trabalho de recuperação de novas tentativas e mensagens salvas em bancos de dados SQL_ASCII (#15033); uma execução legada continuada pelo usuário que atinge o tempo limite pode ser repetida automaticamente (#14987); uma execução concluída não informa mais "Falha na execução" quando a limpeza do arquivo de instruções expira posteriormente (#14945) e essa limpeza não bloqueia mais a liberação de arrendamento (#14866); write_document e outras chamadas de ferramentas semânticas não falham mais quando um documento apenas discute credenciais (#14937) ou contém texto com aparência de credencial (#15301); nomes longos de ferramentas MCP conectadas são alias para se ajustarem aos limites do provedor e o aviso de recuperação explica por que uma execução foi cancelada com uma opção Continuar (#14951); os agentes mantêm seu contexto de tarefa quando uma conexão de ferramenta muda no meio da tarefa (#14963); gateways MCP nativos rejeitam tokens de execução de qualquer agente que não seja seu proprietário (#14914); e os avisos de "informações de provedor não relacionadas ignoradas" do executor do Codex permanecem no log de execução em vez do bate-papo (#14929).
  • Sandboxes e espaços de trabalho — As execuções do sandbox não falham mais com workspace_restore_failed depois que um agente faz rebase ou altera sua ramificação (#15268); o driver Daytona recupera a saída de um soquete de log que fica silencioso (#14889); os comandos de controle da ponte são limitados a 30 segundos e as execuções ativas são sinalizadas como suspeitas após 5 minutos de silêncio e críticas após 15 (#14979); commits de ida e volta de projetos com vários repositórios em ambientes de execução SSH (#14782); tarefas de árvore de trabalho isolada no próprio repositório Paperclip configuradas sem uma configuração inicial local (#14810); e a imagem Docker padrão agrupa o pacote de provedor remoto para que as execuções remotas de OpenCode e ACPX não falhem mais com runner_remote_provider_artifact_incompatible (#14854).
  • IU de bate-papo e tarefas — Orientar e Interromper mostram sua mensagem imediatamente e entregam na execução ativa mesmo após uma mudança de modelo ou esforço, e uma inicialização nativa interrompida oferece Nova tentativa (#15015); uma mensagem enviada após uma execução nativa com falha não trava mais e é entregue exatamente uma vez (#14857); marcadores obsoletos "Falha na execução", "Parado" e "Aguardando para retomar" desaparecem quando uma tentativa posterior os substitui (#14874); as perguntas do agente dispensado permanecem no feed de tarefas e permanecem respondíveis (#15229); os cartões de confirmação mostram "Preparando aprovação…" até que o espaço de trabalho de origem esteja pronto, em vez de erro em click (#14893); um bate-papo do agente não salvo não pesquisa mais o painel do navegador com um ID de rascunho a cada três segundos (#15298); o thread não chama mais uma ação de envio ou cancelamento obsoleta (#14863); as páginas de tarefas móveis obtêm um rodapé opaco, rolagem mais estável, um painel de documentos de altura total e links de documentos no local (#15228) com a nova saída acima do compositor (#15282); o cursor do trabalho concluído fica ao lado de seu rótulo (#15048), os rótulos do compositor usam a largura disponível (#15050), os artefatos de ramificação sem um link remoto dizem isso (#15051), o Painel mostra cada tarefa uma vez (#14847) e uma assinatura salva selecionada pode ser usada sem cli selecionando o bloco do provedor (#14996).
  • Conexões e acesso — As configurações do agente podem reconectar uma conta pessoal de IA indisponível e uma conta recém-conectada se torna o padrão do usuário (#14916); OAuth MCP genérico solicita offline_access quando oferecido para que o acesso sobreviva à expiração do token (#14950); A descoberta da ferramenta MCP usa uma fração da memória e consultas em catálogos grandes, limita listagens simultâneas com um tool_discovery_busy 503 sob carga e responde GET em endpoints sem estado com 405 (#14864); agentes com baixo trust podem criar trabalho auto-atribuído dentro de seu escopo permitido e atualizar seu próprio AGENTS.md gerenciado no chat do proprietário (#14870) e aceitar mensagens diretas e tarefas atribuídas por humanos de seu proprietário fora de um limite de entrada (#14775); as importações de habilidades da empresa de um checkout de projeto gerenciado pelo servidor não falham mais com skill_workspace_boundary_denied (#10329); e o inicializador git/gh gerenciado tenta novamente uma solicitação do corretor de credenciais com falha antes de continuar sem credenciais gerenciadas (#14856).
  • Resiliência do servidor — leituras do painel (#14873), consultas de leitura com escopo (#15248) e a lista de execução de tarefas (#15300) tentam novamente desconexões PostgreSQL transitórias em vez de falhar na solicitação, e rotas de rotina retornam 404 para ids malformados em vez de um erro de banco de dados (#15313).

Melhorias

  • Pools experimentais de conexões de IA alternam novas tarefas entre contas de IA salvas enquanto cada tarefa permanece fixada em sua conta, atrás da configuração padrão enableAiConnectionRouters e de um plugin de roteador (#14967); o provedor de sandbox exe.dev pode clonar uma "VM de origem" preparada em vez de criar uma simples (#14975); o daemon do executor nativo aceita qualquer --listen-port para que vários executores ouvintes possam compartilhar um host (#15353); o servidor mantém um diário de ciclo de vida durável de eventos de contratação, pausa, retomada e encerramento de agentes e eventos de criação e atualização de projetos como base para ganchos de plug-in (#15280, #15306); Slack, GitHub, MCP, convite, rotina e prompts de transferência compartilham um controle animado de "prompt de cópia" (#14862) e o prompt de configuração do Slack corresponde ao fluxo atual (#14965); a caixa de diálogo Teste por ação renderiza os resultados do MCP como tabelas e cartões legíveis (#14859); os agentes podem criar cartões de perguntas a partir de um único conjunto de perguntas canônicas (#14946) e receber orientação de ferramenta de preenchimento idêntica em Codex, Claude e OpenCode (#14961) com texto de procedimento menos repetido e um link canônico de write_document (#15151); e restaurações com falha e tempos limite de parada registram qual estágio falhou e por que nos resultados de execução e no contexto do Sentry (#15005, #15291, #14990, #14986).

Guia de atualização

  • Migrações 0294–0305 executadas na atualização: 0294 adiciona um índice de expiração tool_mcp_gateway_tokens; 0295 e 0296 adicionam instantâneo de conta agregador e tabelas de sincronização; 0297 adiciona resource_lifecycle_events e 0300 reescreve sua restrição de verificação de ação; 0298 adiciona tool_connections.agent_instructions e preenche instruções padrão para conexões Honcho, Mem0, Zep, Supermemory e Cognee existentes; 0299 adiciona pool de conexão AI, cursor de roteador e tabelas de pinos de tarefas, além de company_secrets.ai_session_epoch; 0301 – 0305 adiciona o MCP OAuth client público, concessão, token, recebimento, assinatura de evento, fluxo de dispositivo e tabelas de admissão. Todos são aditivos; 0298 é o único que atualiza linhas existentes.
  • Pare todos os processos antigos antes de atualizar (#14869): o novo protocolo de bloqueio de restauração SQLite não pode coexistir com os bloqueios de diretório antigos. Drene todos os servidores e trabalhadores que gravam na raiz da instância, mova os diretórios <hash>.lock/ legados restantes para fora do <instance root>/locks/directory-merge/ e, em seguida, inicie a nova versão. O mesmo se aplica à reversão.
  • Revisar concessões de ferramentas personalizadas (#14915): concessões com seletores de escopo desconhecidos ou restrições malformadas agora são negadas em vez de não serem atendidas.
  • Novas configurações experimentais, todas desativadas por padrão: "Conexões assistentes (MCP)" (enablePublicMcp) expõe o endpoint MCP público e exige que PAPERCLIP_PUBLIC_URL seja uma origem HTTPS (#14933); "Caixa de entrada combinada + lista de tarefas" (enableCombinedInboxTasks) dobra a caixa de entrada em tarefas e entra em vigor apenas enquanto a "UI simplificada" está ativada (#15100); enableAiConnectionRouters ativa pools de conexão e não possui alternância de UI (#14967).
  • Instruções de conexão para adaptadores customizados (#15216): Os adaptadores HTTP recebem um campo connectionInstructions de nível superior no corpo da solicitação, seja um objeto { text, digest } ou null quando nenhuma instrução se aplica; os adaptadores de processo recebem PAPERCLIP_CONNECTION_INSTRUCTIONS_FILE, o caminho para um arquivo JSON privado que contém o mesmo objeto { text, digest }, e a variável é definida como uma string vazia (não um caminho) quando nenhuma instrução se aplica. Os adaptadores devem anexar o text do objeto ao prompt do modelo em vez de passar o objeto. Os arneses incorporados não necessitam de alteração.
  • Pinos de chicote movidos para Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286) e OpenCode 1.18.34 (#14942, #14993). Imagens de sandbox personalizadas construídas com Claude Code anteriores a 2.1.284 devem ser reconstruídas antes que o Sonnet 5.5 funcione no caminho CLI, e o controlador e o executor devem ser implantados antes de promover uma imagem de sandbox com os novos pinos; Codex remoto agora aceita 0.149.0 até, mas excluindo 0.161.0.
  • Novos padrões: agentes padrão recém-criados recebem concessões de configuração padrão, enquanto os agentes existentes permanecem inalterados (#15283); o --listen-port do executor ainda tem como padrão 43127 (#15353); execuções ativas silenciosas são sinalizadas após 5 e 15 minutos em vez de 1 e 4 horas, sem cancelamento automático (#14979).
  • Nenhuma outra configuração ou alteração do API requer ação.
