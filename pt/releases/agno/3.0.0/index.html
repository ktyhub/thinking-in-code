agno v3.0.0

Major Publicado24 de ago. de 2026 Fonteagno-agi/agno Original em inglês

Esta página é traduzida automaticamente. O texto original em inglês é a referência.

#agno v3.0.0 ⚠️ Lançamento de última hora. Uma migração do banco de dados é necessária antes que o v3.0 sirva o tráfego. Leia o Guia de migração v3 primeiro e veja o v3.0 Changelog completo completo para cada alteração.

Novos recursos

  • Descarregamento de resultados da ferramenta: Agent(offload_tool_results=True) / Team(...) grava qualquer resultado de ferramenta com mais de 16.000 caracteres em AgentFS e deixa um envelope curto (visualização, tamanho, result_id) na mensagem; o agente recebe read_result / search_result (+ assíncrono) para buscar o restante. Nenhuma chamada de modelo no caminho de gravação. Sintonize via ResultStore(threshold_chars=..., ttl_seconds=...). (#9436, #9684)
  • Descarregamento de mídia: media_storage=S3MediaStorage(bucket=...) em um agente/equipe/fluxo de trabalho faz upload de imagens, áudio, vídeo e arquivos para o disco local, S3 ou GCS antes da persistência; a linha mantém um pequeno MediaReference em vez de base64 (um JPEG de 113 KB cai de aproximadamente 151.000 caracteres para 2.897). Nenhuma alteração de esquema. (#9340) Documentos
  • CodeMode: CodeMode(tools=[...]) troca um amplo esquema de ferramenta por um kernel IPython programável que persiste durante uma sessão — o modelo escreve Python e chama ferramentas como identificadores aguardáveis, compondo-as (variáveis, loops, auxiliares) sem percorrer a transcrição.
  • FinanceTools: um kit de ferramentas financeiras unificado com provedores de dados trocáveis.
  • Modelo RampRouter: Novo provedor de modelo para Ramp Router (router.com).
  • SuperGrok OAuth: autenticação de código de dispositivo para o modelo xAI.

Banco de dados

  • As execuções recebem sua própria tabela: cada execução é uma linha em agno_runs com colunas reais (session_id, run_type, agent_id, team_id, workflow_id, user_id, parent_run_id, status, run_index) + carga útil JSON. Leva a amplificação de gravação da sessão de O(N²) para O(N) e remove o teto de tamanho de item do DynamoDB/Firestore. As rotas de sessão session.get_messages(), get_chat_history(), db.get_session() e AgentOS permanecem inalteradas (as execuções são reanexadas na leitura). (#8350)
    • APIs de execução direta: db.get_run(), db.get_runs(session_id=..., status=..., limit=..., page=...), db.upsert_run(), db.delete_run(), db.delete_runs() (sincronizado + assíncrono); db.get_session(runs_limit=N) e db.get_sessions(include_runs=False). (#8350)
    • Migração de uma linha: MigrationManager(db).up() cria o armazenamento de execuções e copia execuções legadas, de forma não destrutiva e idempotente, em 12 back-ends sincronizados + 4 back-ends assíncronos; bancos de dados não migrados ainda funcionam (lê tabela de execuções de mesclagem com blob herdado). Versões de esquema rastreadas em cada adaptador. (#8350)
    • Erros de banco de dados obsoletos digitados: MigrationRequiredError / SchemaMismatchError nomeiam ambas as soluções; AgentOS carrega error_id: "migration_required_error" no corpo JSON. (#9669, #9631)
    • Três novas tabelas: agno_runs, agno_jobs (fila de segundo plano durável), agno_tool_results (índice de descarregamento) — todas criadas automaticamente.

Isolamento por usuário

  • Estende-se além das sessões para métricas, cronogramas, avaliações, conhecimento, componentes, memória de entidade e 17 bancos de dados de vetores. Métricas agregadas por usuário por dia; componentes/conhecimentos sem propriedade são compartilhados (legíveis por todos, editáveis ​​pelo administrador), portanto, ativar o isolamento não 404 blocos de construção de pré-isolamento. (#8245, #8262)

AgentOS e Studio

  • Execução durável em segundo plano: AgentOS(queue=QueueConfig(durable=True)) — execuções aceitas são linhas confirmadas que sobrevivem a falhas/reinicializações/implantações, executadas por qualquer réplica. Simultaneidade limitada (padrão 32, AGNO_BACKGROUND_MAX_CONCURRENCY), cancelável durante a fila, Idempotency-Key desduplicação, 429 na fila completa. Superfície REST da fila (GET /queue/jobs, .../{job_id}, POST .../requeue, GET /queue/stats). Redis é uma coordenação opcional, nunca é verdade. (#9079, #9504)
  • Studio 3.0 — catálogo regido: create_* escreve um rascunho que não serve a ninguém até publish_component; proteções de comparação e definição (digitadas 409s), exclusões marcadas para exclusão, arquivamento/restauração, rastreamento de dependentes. StudioTools retorna um envelope legível por máquina ({ok, status, data, error{...}, warnings}) em aproximadamente 31 ferramentas. (#9604)

Ferramentas

  • Ferramentas de geração de vídeo MiniMax. (#9529)
  • Os kits de ferramentas agora têm um id estável usado pelo AgentOS para fazer referência a ferramentas.

Atualizações de modelo

  • Cerebras / CerebrasOpenAI o padrão é gpt-oss-120b (era llama-4-scout-17b-16e-instruct). (#9244)
  • Gemini padrões atualizados para 3.7 Flash. (#9666)
  • Groq: substituído llama-3.3-70b-versatile obsoleto por openai/gpt-oss-120b. (#9588)
  • OpenAI: reasoning_effort, reasoning_summary, service_tier, verbosity aceitam o conjunto completo de valores API (tipos ampliados; sem interrupções de chamada).
  • Claude trabalha com anthropic 1.0.0 (#9686): atualização compatível com SDK para modelos Claude

⚠️ Mudanças importantes

Todo usuário 2.x deve ler isto. Uma migração do banco de dados é necessária antes que o v3.0 sirva o tráfego.

Armazenamento e migrações

  • As execuções não são mais um blob JSON na tabela de sessões: elas residem em agno_runs. Execute MigrationManager(db).up() (ou AgentOS POST /databases/all/migrate) antes de veicular. A migração v2→v3 preserva a coluna herdada runs como backup; recupere-o com db.cleanup_legacy_runs_column() (SQL) / db.cleanup_legacy_runs_field() (documento/KV) após a verificação.
  • Bancos de dados obsoletos/não migrados geram erros de digitação em vez de se comportarem mal silenciosamente.
  • Paginação: page sem um limit (ou page < 1) agora gera ValueError em vez de retornar resultados ilimitados/negativos.

AgenteOS

  • JWT: secret_key removido de JWTMiddleware e authorization_config — use verification_keys (uma lista).
  • Rotas de metadados: GET /models removidos (dados do modelo movidos para GET /config em available_models); GET / retorna uma resposta de pouso mínima; GET /info é o único endpoint de metadados não autenticado.
  • Configuração do servidor MCP: AgentOS(enable_mcp_server=..., mcp_config=...) removido — em vez disso, passe um único mcp_server= .
  • A execução em segundo plano requer um db no componente (retorna 400 sem um). Agentes de estrutura externa (LangGraph, Claude, DSPy etc.) transmitem em linha para background=true e não são recuperáveis.

Agentes

  • Parâmetros renomeados:
    • enable_user_memories → update_memory_on_run
    • search_session_history → search_past_sessions
    • num_history_sessions → num_past_sessions_to_search
    • num_past_session_runs → num_past_session_runs_in_search
  • reasoning=True removido — defina reasoning_model=<native reasoning model> explicitamente.
  • continue_run / acontinue_run: updated_tools removido — passe requirements (lista de RunRequirement da saída de execução pausada).
  • Recurso de cultura removido: enable_agentic_culture, add_culture_to_context, CulturalKnowledge, ferramentas de cultura e a tabela agno_culture . Use o Knowledge para informações compartilhadas entre usuários.

Equipes e fluxos de trabalho

  • O construtor Workflow é somente palavra-chave: Workflow(name=..., steps=[...]). Team permanece inalterado — Team([agent_1, agent_2]) ainda funciona, embora Team(members=[...]) seja preferido.
  • Kwargs HITL planos removidos na etapa/etapas/loop/condição/roteador (requires_confirmation, confirmation_message, on_reject, requires_user_input, user_input_message, user_input_schema, requires_output_review, output_review_message, requires_iteration_review, iteration_review_message, on_error, hitl_max_retries, hitl_timeout, on_timeout). Use human_review=HumanReview(...) (de agno.workflow.types); nomes inalterados, exceto hitl_max_retries → max_retries, hitl_timeout → timeout.

Ferramentas

  • MultiMCPTools excluído (junto com allow_partial_failure) — use um MCPTools por servidor.
  • MCPToolbox: auth_tokens / auth_headers removido — use auth_token_getters.
  • DuckDuckGoTools.duckduckgo_search → web_search, duckduckgo_news → search_news (agora construído em WebSearchTools).
  • Módulos de ferramentas planas do Google excluídos (agno.tools.gmail, googlesheets, googlecalendar, google_maps, google_drive, google_bigquery) — importação de agno.tools.google.*.
  • Ferramentas do Google: creds_path / auth_port → credentials_path / oauth_port; Planilhas enable_read_sheet etc. → nomes de métodos simples.
  • FileTools.check_escape → Toolkit._check_path (LocalFileSystemTools.check_escape não afetado).
  • SQLTools: enable_list_tables / enable_describe_table / enable_run_sql_query → nomes de métodos simples.
  • Seltz: max_documents → max_results.
  • StudioTool alias removido — use StudioTools.
  • BrightData.get_screenshot: output_path não utilizado removido. PgVector.enable_prefix_matching removido (ajudante morto).

Bancos de dados de conhecimento e vetores

  • Knowledge.add_content / add_content_async / add_contents_async removido → use insert() / ainsert() / ainsert_many().
  • GDriveContextProvider renomeado → GoogleDriveContextProvider.
  • LanceDB: use_tantivy removido/ignorado.
  • Pesquisar uma tabela de vetores pré-v3 com user_id aumenta ValueError (direcionando você para a migração do banco de dados de vetores) em vez de retornar resultados vazios.

Agendador

  • update_schedule agora está na lista de permissões (apenas name, description, method, endpoint, payload, cron_expr, timezone, timeout_seconds, max_retries, retry_delay_seconds, enabled, next_run_at, disabled_reason); qualquer outra chave aumenta ValueError. Propriedade/proveniência/estado de bloqueio não são mais graváveis ​​por meio do caminho genérico. Novas colunas de proveniência adicionadas pela migração v3.0.0.
  • A chave exclusiva da programação muda de name para (user_id, name). Se existirem nomes de agendamento duplicados no mesmo usuário, a migração será cancelada – desduplicar antes de migrar.

Avaliações

  • eval_id → run_id (#9739): as classes de avaliação não carregam mais eval_id; cada execução recebe seu próprio run_id. store_result_in_file renomeia o parâmetro eval_id para run_id, o espaço reservado {eval_id} nos modelos file_path_to_save_results não é mais aceito (use {run_id}) e POST /eval-runs retorna o ID sob o qual a linha foi realmente armazenada (run_id). As novas execuções não se sobrepõem mais.

Modelos e aprendizagem

  • Mistral: camada de compatibilidade mistralai v1 removida — agno[mistral] requer mistralai>=2.0.0 (e está de volta no models extra).
  • Módulo agno.models.metrics e o alias Metrics removidos → importação de agno.metrics (RunMetrics).
  • Model.classify_error removido → use ModelProviderError.classify(error).
  • A memória da entidade em namespace="user" agora é isolada por usuário (as chaves de linha incorporam um resumo user_id ); linhas pré-v3 redigitadas pela migração v3.0.0 (agno.learn.migrations.rekey_user_entity_learnings); EntityMemoryStore.delete/get exigem apenas uma palavra-chave user_id nesse namespace.
  • Aliases de aprendizagem removidos: MemoriesConfig → UserMemoryConfig; MemoriesStore → UserMemoryStore; Decision → DecisionLog.

Descontinuado (ainda funcionando)

  • knowledge_retriever(dependencies=...) → prefira run_context. Um recuperador cuja assinatura ainda nomeia dependencies continua trabalhando por meio de uma ramificação explícita de compatibilidade com versões anteriores; run_context ganha quando ambos estão presentes.
  • Escopos: system:read / system:write → config:read / config:write. Os nomes antigos permanecem aliases válidos e os tokens existentes continuam funcionando.
  • RedisDB (vetor DB) → RedisDb. Observação RedisVectorDb também ainda é exportado, para desambiguar o adaptador de armazenamento agno.db.redis .

Referência rápida de migração

Docs: Guia passo a passo, migração de banco de dados e um prompt para colar em seu agente de codificação

import asyncio
from agno.db.migrations.manager import MigrationManager

# Step 1: run before serving v3.0 traffic (up() is async)
asyncio.run(MigrationManager(db).up())

# Step 2: VERIFY the runs landed before any cleanup
assert len(db.get_runs(limit=5)) > 0, "Migration copied nothing - do NOT clean up"

# Step 3 (optional, destructive): reclaim the legacy blob column.
# The migration preserves it as a backup, so force=True is required.
db.cleanup_legacy_runs_column(force=True)   # SQL adapters
# db.cleanup_legacy_runs_field(force=True)  # document / KV adapters

No AgentOS: POST /databases/all/migrate. Detalhes completos nos documentos v3.0 changelog.
