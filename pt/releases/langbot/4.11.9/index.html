#LangBot v4.11.9 LangBot é uma plataforma de chatbot e agente de IA de código aberto que oferece suporte a várias plataformas de mensagens instantâneas, grandes modelos de linguagem, bases de conhecimento e plug-ins para ajudá-lo a construir, implantar e gerenciar assistentes de IA. LangBot é um chatbot de IA de código aberto e plataforma de agente que conecta plataformas de mensagens, grandes modelos de linguagem, bases de conhecimento e plug-ins para ajudá-lo a construir, implantar e gerenciar assistentes de IA.

LangBot v4.11.9

O sandbox do Box agora é executado em hosts Windows, os agentes podem ler arquivos carregados sob demanda e publicar os arquivos que produzem, e novas instalações mantêm habilidades e uploads no banco de dados. Esta versão permite que o sandbox Box seja executado em hosts Windows; o Agente pode ler arquivos carregados sob demanda e publicar seus próprios arquivos gerados; novas instalações salvam habilidades e conteúdo carregado no banco de dados por padrão.

Nota de atualização/Dica de atualização: esta versão contém nova migração de banco de dados (0049–0053). Faça backup do diretório data/ antes de atualizar (faça backup do banco de dados ao mesmo tempo ao usar PostgreSQL); você precisa usar este backup para restaurar durante o downgrade. As configurações de armazenamento, habilidade e caixa já implantadas no config.yaml permanecem inalteradas. Esta versão adiciona migrações de banco de dados 0049–0053. Faça backup do data/ (e do PostgreSQL, se usado) antes de atualizar; a reversão precisa desse backup. As implantações existentes mantêm as configurações de armazenamento, Skill e Box em seu config.yaml.

Destaques

  • Windows host Box / Windows host sandbox: Plug-in SDK 0.7.26 permite que o backend host suporte Windows: o comando é executado primeiro com Git Bash, caso contrário, ele retorna ao PowerShell, e toda a árvore de processos é limpa no final. Nota: host não realiza nenhum isolamento (INSEGURO). O comando é executado diretamente pelo usuário que executa o LangBot. Usuários não confiáveis ​​no bate-papo em grupo podem executar o comando por meio de injeção imediata de palavras. Ele não é selecionado automaticamente e precisa ser explicitamente definido como box.backend: host em config.yaml ou gravado pela instalação nativa do lbctl (lbctl v0.5.14 em diante). A habilidade não pode ser executada no host Windows Box sob box.file_transfer_mode: network; use legacy quando LangBot e Box estiverem na mesma máquina (lbctl escreverá automaticamente). O backend host agora funciona no Windows (Git Bash, recorrendo ao PowerShell; toda a árvore de processos é limpa). host não tem isolamento e executa comandos como o usuário LangBot, portanto, usuários de bate-papo em grupo não rusted podem executar comandos por meio de injeção imediata. Nunca é selecionado automaticamente: defina box.backend: host explicitamente ou deixe lbctl (v0.5.14+) escrevê-lo para instalações nativas. As habilidades não podem ser executadas em uma caixa host do Windows no modo de transferência network; quando LangBot e Box compartilham uma máquina, use box.file_transfer_mode: legacy (lbctl define isso para você).
  • Arquivos para Agentes/Arquivos de Agente: os arquivos enviados são salvos como ativos de arquivo com permissões. O Agente primeiro obtém a referência do arquivo e depois lê o texto, imagem ou PDF segmento por segmento através da ferramenta quando necessário; o Runner pode publicar o arquivo gerado no destinatário designado e ainda pode ser baixado após a conclusão da execução ou a reinicialização do Core. Os arquivos da base de conhecimento e o plug-in SDK também estão conectados ao mesmo conjunto de ativos de arquivo. Os uploads tornam-se ativos de arquivos autorizados: os agentes obtêm referências e leem textos, imagens ou páginas PDF sob demanda por meio de ferramentas, e os executores podem publicar arquivos de saída que permanecem disponíveis para download após o término da execução ou a reinicialização do Core. Os arquivos da base de conhecimento e o plugin SDK usam os mesmos ativos.
  • Habilidades e uploads baseados em banco de dados por padrão/Armazenamento de banco de dados padrão recém-instalado: habilidades recém-instaladas (incluindo versões históricas) e conteúdo carregado são armazenados no banco de dados por padrão. O Box transfere arquivos pela rede por padrão. Core e Box não precisam mais compartilhar diretórios. Quando uma implantação existente é alternada para este modo, o Core importará o Skill antigo e os arquivos locais antes de iniciar e abrir o HTTP, que pode ser interrompido e restaurado. Após a conclusão da importação, ela não dependerá mais do diretório antigo. A caixa Docker em modo de rede pode montar conjuntos de dados locais somente leitura. Novas instalações armazenam Skills (com seu histórico de versão) e uploads no banco de dados, e o Box move arquivos pela rede em vez de um diretório compartilhado. Quando uma implantação existente é alternada, o Core importa habilidades antigas e arquivos locais antes de servir o HTTP, provavelmente. As caixas de modo de rede Docker podem montar conjuntos de dados locais somente leitura.
  • Operações API / Operação API: Adicionada interface /api/v1/operations (diretório, descrição, execução, fluxo SSE), a chave API também pode confirmar permissões de plug-in e clientes como lbctl podem usar a chave API para confirmar permissões de plug-in. Novas rotas /api/v1/operations (catalogar, descrever, executar, SSE) e confirmação de permissão do plugin com uma chave API, para que API clients como lbctl possam confirmar as permissões do plugin.
  • WebUI: A caixa de diálogo de atualização exibe diretamente o log de atualização em langbot.app; a página de detalhes do plug-in exibe a versão instalada e pode ser atualizada diretamente; após instalar o plug-in, a próxima etapa será solicitada de acordo com o tipo de componente. A caixa de diálogo de atualização mostra release notes de langbot.app; as páginas de detalhes do plugin mostram a versão instalada e oferecem atualizações; instalar um plugin sugere o próximo passo.
  • Inicialização/Inicialização: pip install não detecta mais automaticamente dependências ausentes na inicialização, mas lista pacotes ausentes e solicita reinstalação e saída. LangBot não instala mais pacotes ausentes na inicialização; ele os lista e sai com instruções de reinstalação.
  • Correções/Correções: Processos de plug-in que falham repetidamente ao iniciar irão recuar e tentar novamente e não atualizarão mais a tela; Edição de streaming de telegrama ignora “mensagem não modificada”; O MulticaAgent tentará novamente ao encontrar um erro temporário e as respostas perdidas durante a reinicialização serão reemitidas; o atendimento ao cliente corporativo do WeChat analisa automaticamente o open_kfid ao enviar mensagens para o external_userid simples; os alarmes no LangBot Cloud ainda precisam ser ativados manualmente; E2B A cota do espaço de trabalho entra em vigor; o pacote de plug-in exclui o diretório do ambiente virtual. Os trabalhadores do plugin com falha recuam; Streaming de telegrama ignora “mensagem não modificada”; O MulticaAgent tenta novamente erros transitórios e recupera respostas perdidas em reinicializações; O atendimento ao cliente da WeCom resolve open_kfid para alvos external_userid simples; os alertas permanecem ativados no LangBot Cloud; Os limites do espaço de trabalho E2B são aplicados; pacotes de plugins excluem virtualenvs.
  • SDK：langbot-plugin 由 0.7.25 固定到 0.7.26。Pinos principais langbot-plugin==0.7.26.

Com box.backend: host e file_transfer_mode: legacy, o agente executou um comando (exec) e escreveu e leu um arquivo através do host Box do Windows. Um plugin que imprime chinês e emoji manteve o tempo de execução conectado e, com os downloads do tokenizer, bloqueou a primeira conversa do LocalAgent respondida em 2 s (sem tempo limite do count_tokens).
