#repomix v1.18.1

Esta versão do patch corrige um problema de segurança no manuseio do git do CLI, junto com a falha do Windows .gitignore e um conjunto de correções de bugs de contribuidores!

Correção de segurança 🔒

A configuração do Git em nível de repositório não é mais executada (GHSA-4p5g-gh74-q524)

Repomix executa git log no diretório de destino para classificar os arquivos por frequência de alteração e git diff/git log para --include-diffs/--include-logs. O Git respeita as configurações do próprio .git/config do repositório que nomeia um executável, como gpg.program, diff.external, drivers textconv e core.fsmonitor. Um diretório fornecido com um .git criado (por exemplo, dentro de um arquivo zip) poderia, portanto, executar comandos arbitrários quando o Repomix fosse invocado dentro dele. Um git clone normal não carrega o .git/config do controle remoto e o --remote remove o .git do clone antes do processamento, portanto, esses caminhos não foram afetados.

Todos os comandos git que o Repomix executa em um diretório de destino agora desabilitam essas configurações. A saída para um repositório normal permanece inalterada.

Consulte o comunicado de segurança para obter detalhes. Obrigado a @kinehoo77-debug pelo relatório! 🙏 https://github.com/yamadashy/repomix/security/advisories/GHSA-4p5g-gh74-q524

Correções de bugs 🐛

Windows Crash em .gitignore com escapes de barra invertida (#1765, #1775)

No Windows, a compactação falhou com path should be a `path.relative()`d string when a .gitignore misturou uma regra de escape de barra invertida com uma regra de negação. O bug estava no globby e foi corrigido no globby 16.2.3, que esta versão aborda. Obrigado ao @iki pelo relatório e por persistir nele! 🙏

--remove-comments não corrompe mais arquivos Shell e YAML (#1752)

Os arquivos Shell e YAML foram removidos com o perfil Perl, que trata cada # não citado como um comentário. Nessas linguagens, # apenas inicia um comentário no início de uma linha ou após um espaço em branco, portanto, construções como ${name##*/}, $# e fragmentos de URL estavam sendo cortados. Shell e YAML agora usam um manipulador dedicado que respeita esta regra, heredocs e blocos escalares. Obrigado @serhiizghama!

--include-full-directory-structure mantém arquivos não incluídos (#1749)

Quando combinada com --include, a seção Estrutura de diretórios tem como objetivo mostrar toda a árvore do repositório enquanto compacta apenas o conteúdo dos arquivos incluídos. Arquivos não incluídos estavam sendo eliminados da árvore. Obrigado @serhiizghama!

A saída dividida mostra a própria árvore de diretórios de cada parte (#1815, #1822)

Com --split-output, cada parte listava a árvore de diretórios de toda a saída em vez dos arquivos dessa parte. Cada parte agora renderiza apenas seus próprios arquivos. Obrigado @Eliooon!

URLs remotos cujo nome de repositório começa com um ponto (#1772)

https://github.com/microsoft/.github e repositórios de perfis organizacionais semelhantes foram rejeitados como inválidos. Obrigado @serhiizghama!

Parâmetros URI de dados preservados ao truncar Base64 (#1819, #1820)

Truncar cargas longas de base64 manteve apenas o último ;param antes de ;base64,, descartando os outros. Obrigado @cyphercodes!

Pequenas correções CLI (#1808, #1809, #1810)

  • Os tamanhos --split-output que são arredondados para zero bytes (como 0.5b) agora são rejeitados em vez de ficarem em loop para sempre.
  • Os caminhos de saída e de habilidade são classificados por limites de diretório reais, portanto, um diretório irmão com um prefixo correspondente não é mais tratado como dentro da base.
  • Os nomes de habilidades remotas são derivados do proprietário e do repositório de URLs GitHub.

Obrigado @ Whxuan0701!
