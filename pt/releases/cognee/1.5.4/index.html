Resumo

Esta versão do patch se concentra na confiabilidade, na conveniência da ingestão de dados e no aprimoramento do front-end. Ele corrige vários problemas de migração, registro e proveniência, adiciona conveniências pequenas, mas úteis, API e Docker para ferramentas de ingestão e inclui um amplo conjunto de atualizações de front-end e correções de bugs.

Destaques

  • A imagem Docker agora instala o extra 'dlt' para que ferramentas comuns de ingestão de dados funcionem imediatamente.
  • API add endpoint aceita strings raw_data e URLs de repositório git para simplificar a adição de conjuntos de dados programaticamente.
  • Várias correções em migrações, registro e origem para melhorar a estabilidade durante atualizações e operações simultâneas.
  • Reorganizações de front-end e inúmeras correções de UI que melhoram o conjunto de dados, o painel e os fluxos de trabalho de integração.
  • Segurança e reforço de proteção: os tokens API são editados nos logs de inicialização e o acesso à raiz do arquivo local é desabilitado por padrão.

Mudanças significativas

  • Parâmetro 'repositórios' removido — O parâmetro 'repositórios' foi removido das chamadas API/CLI afetadas. Se você confiou nesse parâmetro, atualize suas integrações para o novo padrão de chamada (verifique os documentos OpenAPI ou SDK para obter a assinatura atualizada).
  • Padrão COGNEE_ALLOWED_LOCAL_FILE_ROOTS alterado — A configuração COGNEE_ALLOWED_LOCAL_FILE_ROOTS agora está desabilitada por padrão. Se você usou isso anteriormente para permitir acesso a arquivos locais, reative-o explicitamente em sua configuração e verifique os caminhos permitidos.

Novos recursos

  • Extra DLT na imagem Docker — A imagem oficial Docker agora instala o extra 'dlt' (um conjunto opcional de pacotes usados para carregamento de dados). Isso significa que os conectores ou fluxos de ingestão que dependem desse extra funcionarão sem exigir que você instale manualmente pacotes extras em seu contêiner.
  • Adicionar endpoint aceita dados brutos e URLs de repositório — O API que adiciona dados agora aceita raw_data como uma string (para que você possa postar texto diretamente) e também aceita URLs de clone de repositório. Isso torna mais fácil adicionar dados programaticamente de um repositório git ou texto embutido sem pré-carregar arquivos.
  • Refinamentos de front-end e novas páginas — A UI da web recebeu grandes atualizações no painel, conjuntos de dados, integrações e páginas de negócios/canvas. Essas mudanças reorganizam listas e painéis, melhoram os fluxos de upload e aprimoram as etapas de integração para tornar as tarefas diárias mais claras e fáceis.

Melhorias

  • As migrações são executadas uma vez por processo — As migrações de bancos de dados relacionais agora são realizadas apenas uma vez para um processo, reduzindo o trabalho duplicado e as condições de corrida durante a inicialização.
  • Inicialização de registro refinada — O registro é inicializado exatamente uma vez por processo e as alternâncias de registro detalhado/silencioso que causavam confusão foram removidas. Isso reduz entradas de log duplicadas e facilita a leitura dos logs.
  • Manipulação do delimitador de ingestão DLT — O pipeline de ingestão baseado em dlt agora lida corretamente com arquivos que usam delimitadores diferentes (vírgulas, tabulações, etc.), portanto, arquivos CSV/TSV de origem mista são importados de forma mais confiável.
  • Corrigida falha de dados vazios do FastAPI — Um bug do FastAPI que poderia travar em dados de solicitação vazios foi corrigido, melhorando a robustez do API para casos extremos.
  • Demo CLI mostra exemplos de respostas sem chamadas LLM extras - O modo de demonstração CLI agora exibe respostas de demonstração armazenadas por completo, sem recorrer a modelos de idioma, tornando as demonstrações mais rápidas e fáceis de usar off-line.
  • Citação de predicado do LanceDB — IDs em predicados de recuperação do LanceDB são citados corretamente para evitar erros de consulta para determinados formatos de id.
  • Leia EMBEDDING_API_BASE como alias — A variável de ambiente EMBEDDING_API_BASE agora é reconhecida como um alias de endpoint, simplificando configurações alternativas de endpoint.
  • Limpeza de proveniência — Correções no tratamento de proveniência impedem a propriedade duplicada de bordas criadas a partir de conteúdo fragmentado e declaram padrões corretos no modelo para que as migrações de proveniência se comportem de forma consistente.
  • Autorização de atualização e correções de propriedade — As atualizações incrementais agora são autorizadas pela ACL (lista de controle de acesso) do conjunto de dados, a pesquisa de orçamento de bloco é resolvida como o proprietário do conjunto de dados e o proprietário original do conjunto de dados é retido em substitutos de reconstrução completa.

Desempenho

  • Redução da contenção de bloqueio de origem — O ponto de verificação foi movido para fora do bloqueio de origem, reduzindo a contenção de bloqueio e melhorando a simultaneidade quando muitas operações gravam metadados de origem.
  • Ordenação de gravação mais robusta — O gráfico agora é escrito antes dos vetores durante as operações de armazenamento, reduzindo a chance de gravações parciais e melhorando a consistência geral dos dados durante a ingestão.
  • Provisionamento de banco de dados simplificado — Os bancos de dados de conjuntos de dados são provisionados apenas por ID de conjunto de dados, simplificando a lógica de provisionamento e reduzindo a sobrecarga durante a configuração do ambiente.

Segurança

  • Redação do token API no eco de inicialização — O ponto de entrada não imprime mais texto simples --token api em seu eco de inicialização; os tokens são redigidos para que não vazem nos logs.
  • Raízes de arquivos locais desabilitadas por padrão — A configuração COGNEE_ALLOWED_LOCAL_FILE_ROOTS agora está desabilitada por padrão para reduzir a exposição acidental de caminhos do sistema de arquivos local ao servidor.
  • Ignorar concessão de permissão de locatário para sentinela local — O front-end/servidor agora ignora uma concessão automática de permissão de locatário ao executar uma instância de sentinela local, evitando alterações inesperadas de permissão em execuções de desenvolvimento.

Correções de bugs

  • Removido um modo de registro 'silencioso' que suprimia mensagens úteis e causava confusão.
  • Corrigido um problema em que o parâmetro repositórios era removido incorretamente em algumas chamadas — superfícies de retorno de chamada atualizadas para corresponder ao novo padrão de chamada.
  • Corrigida a falha do FastAPI em cargas de dados vazias.
  • Redigido o argumento --api-token na saída de inicialização.
  • Corrigida a ingestão de dlt para lidar corretamente com vários delimitadores de arquivo.
  • Corrigidas regressões de refatoração DTO e extras sincronizados do OpenAPI com o aplicativo em execução para que os documentos e o API correspondam.
  • Correção de arestas de origem produzidas em pedaços sendo de propriedade dupla.
  • Correção de um problema que garante que a pesquisa de orçamento por partes seja resolvida com o contexto correto do proprietário do conjunto de dados.
  • Correção de vários bugs de front-end em conjunto de dados, painel e páginas de integração (progresso de upload, modais, renderização de lista e conectores).
  • Corrigido o comportamento de leitura para EMBEDDING_API_BASE para que a configuração do endpoint alternativo se comporte corretamente.

Mudanças Técnicas

  • Migrações refatoradas: um módulo de esquema congelado é usado para ambas as revisões e a escolha do dialeto é decidida a partir do vínculo do banco de dados; várias mudanças de re-parentalidade de migração para manter um único cabeçalho após fusões recentes.
  • Numerosas atualizações de CI e testes: reorganização de suítes de testes, divisões noturnas/de testes e testes de roteamento e2e adicionados para serve().
  • Ajustes de sincronização e documentação do OpenAPI: pequenas correções de sinopse e extras de especificações foram sincronizados com o aplicativo em execução.
  • Vários refatoradores internos e limpeza: migrações de agentes de re-parentalidade, alterações de provisionamento e diversas correções de acessórios de teste.
