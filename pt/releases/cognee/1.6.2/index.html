cognee v1.6.2

v1.6.2 — Incorporando confiabilidade e história do Slack

Data de lançamento: 29/09/2026 Alterações: v1.6.1 → v1.6.2

Pull Requests: #4932, #4951, #5146, #5196, #5231, #5235, #5236, #5240, #5241, #5242, #5247, #5250, #5251, #5274

Resumo

Esta versão se concentra em tornar os embeddings confiáveis e transparentes (sem mais truncamento silencioso), adiciona importação e sincronização de conversas do Slack e reorganiza como as 'habilidades' são armazenadas para melhores ferramentas entre plataformas. Você verá erros mais claros quando a incorporação falhar, dimensionamento de blocos mais seguro com base nos limites de token do modelo e CLI/docs atualizados para corresponder a esses comportamentos.

Destaques

  • A incorporação de correções evita o truncamento silencioso e dimensiona pedaços de acordo com o limite de token de cada modelo, para que seu conteúdo seja incorporado intacto e consistente.
  • Slack integration: import and continuously sync conversation history from Slack into Cognee.
  • Habilidades movidas para um novo local .agents/skills com suporte e recuperação de vinculação do Windows quando a vinculação falha.
  • Melhores erros e falhas mais rápidas em erros de incorporação irrecuperáveis ​​– você verá causas reais em vez de mensagens opacas.
  • CLI and docs refreshed (including database migration/commands and Docker quickstart auth fixes).

Mudanças significativas

  • Skills path change: Built-in and packaged skills are now under .agents/skills (moved from earlier locations). Se você mantiver scripts personalizados, automação, ganchos de construção ou CI que façam referência aos caminhos antigos, atualize-os para .agents/skills. A small helper script (link-skills.sh) and a Windows hook were added to assist linking.
  • env_file removed from settings: The runtime setting that automatically loaded an env_file was removed. Se você confiou nesse comportamento para carregar variáveis ​​de ambiente por meio do arquivo de configurações, mude para um carregador de ambiente explícito em seus scripts de início ou use o auxiliar recém-adicionado shared/env_file (consulte documentos/testes para obter exemplos).

Novos recursos

  • Slack conversation import and sync — A new integration to import and keep Slack conversation history in sync with Cognee. This pulls channel and thread messages into your datasets so search and memory features can use Slack content. Why it matters: you can build memories, search, and summaries from historical Slack data without manual export.
  • Pedaços dimensionados pelo limite de entrada do modelo — O sistema agora mede o limite de entrada de cada modelo incorporado (o número máximo de tokens que um modelo aceita) e divide o texto em pedaços dimensionados até esse limite. O que faz: o chunking não depende mais de uma heurística fixa; it respects the actual model/tokenizer limits to avoid unexpected truncation. Por que é importante: a pesquisa e a memória serão mais completas e consistentes porque os documentos não são encurtados silenciosamente quando enviados para um modelo de incorporação.
  • Reorganização do diretório de habilidades (.agents) e gancho de link do Windows — As habilidades (scripts e exemplos de agentes automatizados) foram movidas de locais mais antigos para um novo diretório .agents/skills e um gancho amigável ao Windows foi adicionado para vinculação. What it does: standardizes where built-in skills live and makes the linking process work on Windows. Why it matters: easier, more consistent workflows for installing, linking, and running skills across platforms.

Melhorias

  • Resolução robusta de limite de entrada de incorporação — O SDK agora resolve o limite de entrada de um modelo mesmo quando bibliotecas tokenizadoras opcionais (como transformadores) não estão instaladas, e o faz de forma assíncrona quando apropriado. Isso reduz surpresas na inicialização e melhora o comportamento para instalações leves.
  • Contagem precisa de tokens entre tokenizers — As contagens de tokens agora usam os tokenizers de cada provedor (incluindo os tokenizers HuggingFace, quando disponíveis), e os tokens especiais do próprio modelo são incluídos nas contagens. O que faz: melhora o tamanho do bloco e evita o truncamento de alguns tokens.
  • Preenchimento de lote incorporado rapidamente — Os lotes enviados para o back-end de incorporação rápida agora são preenchidos com o texto mais longo do lote para evitar truncamento inconsistente no nível do lote. Resultado: menos truncamentos silenciosos e incorporações mais previsíveis ao enviar entradas de comprimentos mistos.
  • Erros de incorporação mais claros e comportamento rápido contra falhas — As falhas de incorporação agora mostram a causa subjacente (não apenas uma mensagem genérica) e os erros de terminal interrompem as novas tentativas rapidamente. Por que é importante: você pode depurar e recuperar mais rapidamente quando um provedor externo ou uma configuração estiver errada.
  • Recuperar links de habilidades em caso de falha e validar links sem chaves — O processo de vinculação de habilidades é mais robusto: falhas parciais tentam recuperar links e o fluxo de trabalho de verificação de links pode ser executado sem uma chave secreta. Isso reduz operações frágeis e simplifica as verificações de CI.
  • Documentos do CLI e atualizações de comportamento — A documentação do CLI foi ampliada e esclarecida (comandos de migração de banco de dados, novos exemplos, notas sobre comandos de memória). A armadilha 401 do início rápido Docker foi aprimorada para que o início rápido se comporte corretamente quando a autenticação estiver faltando.

Desempenho

  • Taxa de transferência de incorporação mais confiável - Ao preencher lotes fastembed e dimensionar pedaços de acordo com os limites de entrada do modelo, as incorporações evitam o truncamento silencioso que costumava reduzir a taxa de transferência/qualidade efetiva. Isso melhora o rendimento prático de incorporações utilizáveis ​​para entradas de comprimentos mistos.
  • Detecção mais rápida de limites de incorporação em configurações leves — A resolução de limite de entrada agora funciona sem dependências pesadas de tokenizer e é resolvida de forma assíncrona, reduzindo atrasos durante a inicialização da incorporação.

Segurança

  • Tratamento do início rápido 401 do Docker — O início rápido do Docker e os documentos relacionados foram corrigidos para evitar uma armadilha 401 confusa e agora produzem orientações de autenticação mais claras.

Correções de bugs

  • As importações de transformadores opcionais marcadas corretamente para verificação de tipo, para que as dependências opcionais se comportem de maneira limpa durante as instalações.
  • Contagem de tokens HuggingFace corretamente usando tokenizers (evita contagem incorreta quando diferentes caminhos de código do tokenizer são usados).
  • Leia o limite de entrada de um modelo mesmo quando os transformadores não estão instalados, evitando fallbacks silenciosos que causavam tamanhos incorretos de blocos.
  • Ignorados metadados de truncamento/preenchimento salvos anteriormente que poderiam corromper decisões futuras de dimensionamento de blocos.
  • Links de habilidades recuperados quando a limpeza falha (recuperação de links para evitar instalações de habilidades quebradas).
  • Eliminada uma configuração env_file das configurações de tempo de execução para evitar comportamento surpreendente (consulte Alterações recentes).
  • Registrados rastreamentos completos em falhas de comandos delegados CLI para que os erros sejam mais fáceis de diagnosticar.
  • Alterada a ordem em que os bancos de dados são removidos para corrigir um bug de pedido de exclusão de casos extremos.

Mudanças Técnicas

  • Refatoração da incorporação de input_limit() na interface do mecanismo e manutenção de cada pesquisa de limite com seu provedor para tornar a resolução de limite conectável.
  • Eliminado um re-raise no-op na classificação de predicado de nova tentativa fastembed e simplificada para lidar com a incorporação ausente de SDKs de forma limpa.
  • Protetores de pedido de tokenizador refatorados (proteção de transformadores antes da tocha removida) e testes protegidos adicionados para evitar regressões na ordem de importação e no comportamento de preenchimento.
  • Grande conjunto de testes e adições de exemplos: muitos testes ponta a ponta, de unidade e de jornada foram adicionados ou expandidos (incorporação de limites, histórico de folga, chunking, jornadas), além de uma nova demonstração multifonte company_brain e fluxos de trabalho de CI expandidos.
  • Documentação e habilidades: inúmeras atualizações de documentação (AGENTS.md, documentos de habilidades, orientação de migração, alinhamento README) e correções de formatação para exemplos de habilidades Python.
