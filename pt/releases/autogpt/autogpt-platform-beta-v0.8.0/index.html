AutoGPT autogpt-platform-beta-v0.8.0

⚠️ Atualizando uma instalação auto-hospedada – alteração significativa

ENCRYPTION_KEY, UNSUBSCRIBE_SECRET_KEY e BETTER_AUTH_SECRET não são mais enviados com valores em .env.default; eles são gerados por instalação e o backend não inicia no valor que .env.default costumava conter. Uma nova instalação não precisa de nada além do make init-env (ou do instalador). Uma instalação que define seus próprios valores não precisa de nada. Se sua instalação foi executada nos padrões (sem linha ENCRYPTION_KEY em backend/.env ou a inicialização para com ENCRYPTION_KEY is set to a value that was published…), faça isso a partir de autogpt_platform/ — ele move suas integrações conectadas para a nova chave em vez de perdê-las:

1.docker compose down 2. Guarde a chave com a qual seus dados são criptografados: export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) (se você definiu sua própria chave e a está substituindo, exporte esse valor e mantenha uma cópia de backend/.env fora do checkout). 3. Em backend/.env certifique-se de que ENCRYPTION_KEY= e UNSUBSCRIBE_SECRET_KEY= existam sem nada depois de =, e BETTER_AUTH_SECRET= em frontend/.env; então make init-env (preenche todos os segredos vazios, nunca substitui um valor). 4. Criptografe novamente o que está armazenado - primeiro faça uma simulação e depois aplique: docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply 5. Limpe a chave de assinatura do token armazenada no antigo BETTER_AUTH_SECRET e inicie: docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

Instruções completas: Atualização: segredos são gerados por instalação.

Também nesta versão: o caminho de verificação JWT HS256 legado foi removido, portanto, um JWT_VERIFY_KEY em backend/.env não é mais lido (#14519); a tabela TrialNotificationDelivery não utilizada é eliminada pela migração.
