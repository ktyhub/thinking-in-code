lançamento do contador-4.18.0

O lançamento 4.18.0 é um lançamento de recurso importante. Ele introduz o registro estruturado em todo o base de código (BP-69), migra a serialização do protocolo wire para LightProto e o I/O nativo biblioteca para Rust e aumenta a versão Java mínima necessária para 17. Também inclui muitos melhorias, correções de bugs e atualizações de dependências/CVE.

Os usuários do Apache BookKeeper são incentivados a atualizar para 4.18.0. Por favor, revise o alterações importantes e problemas conhecidos abaixo antes de atualizar.

Destaques

  • Registro estruturado (BP-69) — Todos os registros do BookKeeper foram convertidos do SLF4J formatar strings para slog, um registro estruturado API onde cada evento carrega chave/valor digitado atributos (por exemplo, ledgerId, entryId). O contexto do logger é propagado por meio de client operações, para que todos os eventos relacionados ao mesmo razão sejam automaticamente marcados. Os atributos são renderizados por log4j2 em texto simples e saída JSON, com um exemplo configuração para logs JSON compatíveis com OpenTelemetry. PR #4751, #4754, #4755, #4756, #4757, #4758, #4765, #4766, #4767, #4770
  • Serialização LightProto — O protocolo de conexão BookKeeper, formatos de metadados e fluxo protos de armazenamento foram migrados de protobuf-java para LightProto, que analisa e serializa diretamente nos buffers Netty sem alocações intermediárias, reduzindo a pressão do GC no caminho quente. PR #4779, #4780, #4781, #4783
  • Biblioteca de E/S nativa reescrita em Rust — A biblioteca native-io usada para E/S direta em o apostador foi migrado de C para Rust. PR #4738
  • Linha de base do Java 17 — Java 17 ou posterior agora é necessário para construir e executar o BookKeeper. PR #4446
  • A desativação do bookie limpa o cookie (BP-68) — O administrador de desativação API agora exclui o cookie do bookie do armazenamento de metadados, para que um ID do bookie desativado possa ser reutilizado sem limpeza manual. PR #4500, #4592
  • ZooKeeper limitação de leitura durante a nova replicação (BP-66) — A nova replicação agora pode limitar suas leituras ZooKeeper, protegendo o armazenamento de metadados de tempestades de leitura quando muitos os livros contábeis estão sendo recuperados. PR #4258
  • Leituras em lote de entradas não confirmadas (BP-62) — batchReadUnconfirmedAsync agora é exposto em ReadHandle. PR #4739

Mudanças significativas

  • Java 17+ é necessário para construir e executar o BookKeeper (anteriormente Java 11) PR #4446
  • O valor padrão de readOnlyModeOnAnyDiskFullEnabled mudou para true: agora um apostador transições para somente leitura assim que qualquer disco contábil estiver cheio, em vez de apenas quando todos os discos estão cheios. Defina novamente para false para restaurar o comportamento anterior. PR #4520
  • O módulo bookkeeper-slogger foi removido, substituído pelo slog estruturado registrando API (BP-69) PR #4764
  • Removido o método obsoleto e com erros ortográficos setAllocatorPoolingConcurrenncy - use setAllocatorPoolingConcurrency em vez disso PR #4431
  • Removida a classe obsoleta MathUtils PR #4274

Problemas conhecidos

  • PR #4730 (leia a correção de bloqueio de thread em sendResponseAndWait), incluído nesta versão, pode causar potencialmente um impasse no caminho de leitura do bookmaker. Foi revertido em PR #4830, que fará parte do 4.18.1.
