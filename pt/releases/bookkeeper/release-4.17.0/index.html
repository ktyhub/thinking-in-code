bookkeeper release-4.17.0

Versão Publicado25 de mai. de 2024 Fonteapache/bookkeeper Original em inglês

Esta página é traduzida automaticamente. O texto original em inglês é a referência.

lançamento do contador-4.17.0

A versão 4.17.0 inclui vários recursos importantes, melhorias, correções de bugs e algumas dependências corrigidas por CVE.

Os detalhes técnicos desta versão estão resumidos abaixo.

Mudanças importantes

Sem alterações significativas. Alguns padrões são diferentes, mas no geral não há problemas de compatibilidade.

Recursos

  • Leitura em lote BP-62 API

Mudanças notáveis

  • Habilitar sequência de leitura de reordenamento para bk client por padrão PR #4139
  • Correção de algumas métricas geradas por prometheus client sem informações de tipo PR #3927
  • Corrija a vulnerabilidade de upload arbitrário de arquivos com httpServerEnabled PR #3982
  • Habilite logs kv na configuração log4j PR #3986
  • Torne compatível entre DefaultEntryLogger e DirectEntryLogger PR #4041

Apostador

  • Corrigido bug de JournalQueueSize negativo PR #4077
  • Corrigir imprecisão do acelerador de compactação PR #3192
  • Correção de dados perdidos quando vários diretórios contábeis são configurados PR #3329
  • Tente usar o jdk api para criar hardlink ao renomear o arquivo durante a compactação. PR #3876
  • [recurso] [servidor] adiciona propriedades dbStorage_readAheadCacheBatchBytesSize quando entradas de leitura antecipada PR #3895
  • Corrigido vazamento de chaves em EntryLocationIndex quando ledgersToDelete está vazio PR #3903
  • Corrigir coleta de lixo bloqueada por exceção de tempo de execução PR #3901
  • Pular sincronização do RocksDB quando não houver alterações PR #3904
  • Habilite o preenchimento automático de objetos de conclusão PCBC para reduzir o uso de memória e gc PR #3913
  • [Correção] Reciclagem de solicitações de leitura e gravação quando ocorreram várias exceções PR #3912
  • Corrigir o processo de desativação do bookie com falha de blocos replicados PR #3917
  • Suporte para pular registro de diário inválido na fase de resposta do diário PR #3956
  • Evite compactação para acionar liberações extras DbLedgerStorage PR #3959
  • Corrigir vazamento de memória direta no registrador de entrada direta de memória. PR #3983
  • Unifique ByteBufAllocator para o componente DirectIO PR #3985
  • Imprimir o progresso da compactação PR #4071
  • Otimize o intervalo de espera para verificação de desativação do agenciador de apostas PR #4070
  • Correção do gatilho do GC que não funciona PR #3998
  • Permitir definir números máximos de operação em um único lote rocksdb PR #4044
  • Adicionar log de falha de leitura para verificador de razão. PR #4010
  • Corrigido vazamento de solicitação de leitura e gravação quando o executor lança RejectedExecutionException PR #4024
  • Melhore o desempenho de leitura do DefaultEntryLogger. PR #4038

Client

  • [Bug] Sempre é criado um livro-razão órfão PR #3813
  • Corrigido bug de cálculo de checksum quando o payload é um CompositeByteBuf com readerIndex > 0 PR #4196
  • Corrigir nenhum corretor conhecido após redefinir os racks para todos os BKs PR #4128
  • Corrigido problema de compatibilidade binária com versões mais antigas do grpc em tempo de execução no client PR #3997
  • Política de posicionamento com reconhecimento de região de nó local com suporte para gravação de entrada PR #4063
  • A política de posicionamento Rackaware suporta reconhecimento de nó local por nome de host PR #4057
  • Use netty-bom para alinhar versões da biblioteca netty, adicione epoll para linux-aarch_64 PR #4204

AutoRecuperação

  • Faça com que a AutoRecuperação habilite stickyReadS como padrão. PR #4125
  • Suporta lógica de repetição para recuperação automática PR #3799 0
  • Corrigir problema de bloqueio do executor eleitor do auditor. PR #4165
  • Corrija a falha na replicação da recuperação automática adicionando erro de entrada protegida PR #4163
  • Corrigir problema de vazamento de thread de auditor. PR #4162
  • AutoRecovery suporta leitura em lote PR #4211

Outros

  • Adicionado comando CLI para iniciar o serviço de armazenamento de estado sem agente de apostas PR #2648
  • Adicionar comando de realocação de conjunto que segue a política de posicionamento PR #2931
  • Ajustando a simultaneidade do pool PR #3432
  • Problema 4136: Correção de configurações de registro quebradas na imagem docker PR #4137
  • [lançamento] Forçar o uso de linux/amd64 para compilar a versão PR #4060

Mudanças de dependência

Dependências notáveis atualizadas e CVEs de endereço, incluindo:

  • Atualize snappy-java para endereçar vários CVEs PR #3993
  • Atualize grpc e protobuf para endereço CVE-2023-32732 PR #3992
  • Atualize Zookeeper para 3.8.3 para endereçar CVE-2023-44981 PR #4112
  • Atualize Netty para 4.1.107.Final e io_uring para 0.0.25.Final PR #4224
  • Bump org.apache.commons:commons-compress de 1.21 para 1.26.0 PR #4214
  • Atualizar versão dos esboços de dados de 0.8.3 para 3.2.0 PR #3264
  • Problema 3567: Atualize a versão do rocksdb para evitar erro de incompatibilidade de soma de verificação PR #3568
  • correção (seg): atualização do codec comum para 1.13 PR #3508
  • Remova as dependências avro, hadoop-auth e jersey-json do hadoop-common para resolver CVE-2019-10202, CVE-2023-1370 e CVE-2022-45685 PR #3911
  • Atualize a imagem base docker para resolver CVE-2023-0286 PR #3916
  • Atualize bc-fips para 1.0.2.4 para corrigir CVE-2022-45146 PR #3915
  • Atualize a versão do cais para 9.4.51.v20230217 PR #3937
  • Versão Bump goiaba de 31.0.1-jre a 32.0.1-jre PR #4008
