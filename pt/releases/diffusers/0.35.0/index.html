Implementações de modelagem de arquivo único

Seguindo a 🤗 filosofia dos Transformers de implementações de modelagem de arquivo único, começamos a implementar código de modelagem em arquivos únicos e independentes. O Transformador de Fluxo código é um exemplo disso.

Refatoração de atenção

Refatoramos massivamente a forma como prestamos atenção nos modelos. Isso nos permite fornecer suporte para diferentes back-ends de atenção (como scaled_dot_product_attention nativo do PyTorch, Flash Attention 3, atenção SAGE, etc.) na biblioteca de forma integrada. Ter a atenção apoiada desta forma também nos permite integrar diferentes mecanismos de paralelização, nos quais estamos trabalhando ativamente. Siga [este PR] (https://github.com/huggingface/diffusers/pull/11941) se estiver interessado. Os usuários não devem ser afetados por essas mudanças. Abra um problema se tiver algum problema.

Compilação regional

A compilação regional reduz a latência de inicialização a frio compilando apenas os blocos pequenos e frequentemente repetidos de um modelo - normalmente uma camada de transformador - e permite a reutilização de artefatos compilados para cada ocorrência subsequente. Para muitas arquiteturas de difusão, isso oferece as mesmas acelerações de tempo de execução que a compilação de gráfico completo e reduz o tempo de compilação em 8–10x. Consulte este documento para saber mais. Obrigado a @anijain2305 por contribuir com este recurso neste PR. Também escrevemos uma série de postagens centradas no uso do torch.compile. Você pode conferi-los nos links abaixo:

  • Apresentando o Flux Fast: Fazendo o Flux ficar incrível no H100s
  • [torch.compile e difusores: um guia prático para desempenho máximo] (https://pytorch.org/blog/torch-compile-and-diffusers-a-hands-on-guide-to-peak-performance/)
  • [Inferência LoRA rápida para fluxo com difusores e PEFT] (https://huggingface.co/blog/lora-fast)

Carregamento de pipeline mais rápido ⚡️

Os usuários agora podem carregar pipelines diretamente em um dispositivo acelerador, resultando em tempos de carregamento significativamente mais rápidos. Isso fica particularmente evidente ao carregar grandes pipelines como Wan e Qwen-Image.

from diffusers import DiffusionPipeline
import torch 

ckpt_id = "Qwen/Qwen-Image"
pipe = DiffusionPipeline.from_pretrained(
-    ckpt_id, torch_dtype=torch.bfloat16
- ).to("cuda")
+    ckpt_id, torch_dtype=torch.bfloat16, device_map="cuda"
+ )

Você pode acelerar o carregamento ainda mais habilitando o carregamento paralelizado de fragmentos de dict de estado. Isso é particularmente útil quando você trabalha com modelos grandes como Wan e Qwen-Image, onde os ditados de estado do modelo são normalmente fragmentados em vários arquivos.

import os
os.environ["HF_ENABLE_PARALLEL_LOADING"] = "yes"

# rest of the loading code

Melhor integração do GGUF

@Isotr0py contribuiu com suporte para kernels nativos GGUF CUDA em este PR. Isso deve fornecer uma melhoria de aproximadamente 10% na velocidade de inferência. Também trabalhamos em uma ferramenta para converter pontos de verificação regulares em GGUF, permitindo que a comunidade compartilhe facilmente seus pontos de verificação GGUF. Saiba mais aqui. Agora oferecemos suporte ao carregamento de pontos de verificação GGUF no formato Difusores. Você pode aprender mais sobre tudo isso em nossos documentos oficiais do GGUF.

Difusores Modulares (Experimentais)

Difusores Modulares é um sistema para construir pipelines de difusão com blocos de pipeline individuais *. É altamente personalizável, com blocos que podem ser misturados e combinados para se adaptar ou criar um pipeline para um fluxo de trabalho específico ou para vários fluxos de trabalho.
O API está atualmente em desenvolvimento ativo e está sendo lançado como um recurso experimental. Saiba mais em nossos documentos.
