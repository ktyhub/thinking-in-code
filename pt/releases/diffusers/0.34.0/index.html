📹 Novos pipelines de geração de vídeos

Wan VACE

Wan VACE suporta várias técnicas de geração que alcançam geração de vídeo controlável. Ele vem em duas variantes: um modelo 1.3B para iteração e prototipagem rápidas e um modelo 14B para geração de alta qualidade. Alguns dos recursos incluem:

  • Controle para Vídeo (Profundidade, Pose, Esboço, Fluxo, Tons de Cinza, Rabisco, Layout, Caixa de Limite, etc.). Biblioteca recomendada para pré-processamento de vídeos para obter vídeos de controle: huggingface/controlnet_aux
  • Imagem/Vídeo para Vídeo (primeiro quadro, último quadro, começando clip, terminando clip, clips aleatório)
  • Pintura interna e externa
  • Sujeito ao Vídeo (rostos, objetos, personagens, etc.)
  • Composição para vídeo (referenciar qualquer coisa, animar qualquer coisa, trocar qualquer coisa, expandir qualquer coisa, mover qualquer coisa, etc.) Os snippets de código disponíveis na solicitação pull this demonstram alguns exemplos de como vídeos podem ser gerados com sinais de controlabilidade. Confira os documentos para saber mais.

Cosmos Predict2 Video2World

Cosmos-Predict2 é um ramo importante do ecossistema Cosmos World Foundation Models (WFMs) para IA física, especializado em previsão de estado futuro por meio de modelagem mundial avançada. Ele oferece dois recursos poderosos: geração de texto para imagem, para criar imagens de alta qualidade a partir de descrições de texto, e geração de vídeo para mundo, para produzir simulações visuais a partir de entradas de vídeo. O modelo Video2World vem em variantes 2B e 14B. Confira os documentos para saber mais.

LTX 0.9.7 e destilado

LTX 0.9.7 e suas variantes destiladas são os mais recentes na família de modelos lançados pela Lightricks. Confira os documentos para saber mais.

Framepack de vídeo Hunyuan e F1

Framepack é um novo método para permitir a geração de vídeos longos. Existem duas variantes lançadas do Hunyuan Video treinadas usando esta técnica. Confira os documentos para saber mais.

FusãoX

A família de modelos e LoRAs FusionX, construída sobre Wan2.1-14B, já deve ser suportada. Para carregar o modelo, use from_single_file():

from diffusers import WanTransformer3DModel

transformer = WanTransformer3DModel.from_single_file(
    "https://huggingface.co/vrgamedevgirl84/Wan14BT2VFusioniX/blob/main/Wan14Bi2vFusioniX_fp16.safetensors",
    torch_dtype=torch.bfloat16
)

Para carregar os LoRAs, use load_lora_weights():

pipe = DiffusionPipeline.from_pretrained(
    "Wan-AI/Wan2.1-T2V-14B-Diffusers",
    torch_dtype=torch.bfloat16
).to("cuda")
pipe.load_lora_weights(
    "vrgamedevgirl84/Wan14BT2VFusioniX", weight_name="FusionX_LoRa/Wan2.1_T2V_14B_FusionX_LoRA.safetensors"
)

AccVideo e CausVid (somente LoRAs)

AccVideo e CausVid são duas novas técnicas de destilação que aceleram o tempo de geração de modelos de difusão de vídeo enquanto preservam a qualidade. Os difusores suportam o carregamento de seus LoRAs extraídos com seus respectivos modelos.

Melhor suporte torch.compile

Trabalhamos com a equipe PyTorch para melhorar a forma como fornecemos compatibilidade com torch.compile() em toda a biblioteca. Mais especificamente, agora testamos os modelos amplamente utilizados, como o Flux, para quaisquer problemas de recompilação e quebra de gráfico que possam atrapalhar a realização total dos benefícios do torch.compile(). Consulte os seguintes links para saber mais: -https://github.com/huggingface/diffusers/pull/11085 -https://github.com/huggingface/diffusers/issues/11430 Além disso, os usuários podem combinar o descarregamento com a compilação para obter uma melhor compensação entre velocidade e memória. Você pode reduzir substancialmente os requisitos de memória combinando quantização com descarregamento e melhorando a velocidade com `torch.compile()`. Abaixo está um exemplo:
<detalhes>
<summary>Código</summary>
```py
from diffusers import BitsAndBytesConfig as DiffusersBitsAndBytesConfig
from transformers import BitsAndBytesConfig as TransformersBitsAndBytesConfig
from diffusers import AutoModel, FluxPipeline
from transformers import T5EncoderModel

import torch
torch._dynamo.config.recompile_limit = 1000 

quant_kwargs = {"load_in_4bit": True, "bnb_4bit_compute_dtype": torch_dtype, "bnb_4bit_quant_type": "nf4"}
text_encoder_2_quant_config = TransformersBitsAndBytesConfig(**quant_kwargs)
dit_quant_config = DiffusersBitsAndBytesConfig(**quant_kwargs)

ckpt_id = "black-forest-labs/FLUX.1-dev"
text_encoder_2 = T5EncoderModel.from_pretrained(
    ckpt_id,
    subfolder="text_encoder_2",
    quantization_config=text_encoder_2_quant_config,
    torch_dtype=torch_dtype,
)
transformer = AutoModel.from_pretrained(
    ckpt_id,
    subfolder="transformer",
    quantization_config=dit_quant_config,
    torch_dtype=torch_dtype,
)
pipe = FluxPipeline.from_pretrained(
    ckpt_id,
    transformer=transformer,
    text_encoder_2=text_encoder_2,
    torch_dtype=torch_dtype,
)
pipe.enable_model_cpu_offload()
pipe.transformer.compile()

image = pipeline(
    prompt="An astronaut riding a horse on Mars",
    guidance_scale=3.5,
    height=768,
    width=1360,
    num_inference_steps=28,
    max_sequence_length=512,
).images[0]
</detalhes> A partir do `bitsandbytes==0.46.0`, os modelos quantizados pelo bnb devem ser totalmente compatíveis com o `torch.compile()` sem quebras de gráfico. Isso significa que ao compilar um modelo quantizado em BNB, os usuários podem fazer: `model.compile(fullgraph=True)`. Isso pode melhorar significativamente a velocidade e, ao mesmo tempo, fornecer benefícios de memória. A figura abaixo fornece uma comparação com o Flux.1-Dev. Consulte [este script de benchmarking](https://gist.github.com/sayakpaul/0db9d8eeeb3d2a0e5ed7cf0d9ca19b7d) para saber mais. ![imagem](https://github.com/user-attachments/assets/d0fd34bf-618e-41d2-b2bb-e821fe02f59b) Observe que para modelos bnb de 4 bits, atualmente é necessário instalar o PyTorch todas as noites se `fullgraph=True` for especificado durante a compilação. ## Descarregamento de grupo com disco
Na [versão anterior](https://github.com/huggingface/diffusers/releases/tag/v0.33.0), lançamos o “descarregamento de grupo”, que permite descarregar blocos/nós dentro de um modelo, otimizando seu consumo de memória. Ele também permite sobrepor esse descarregamento à computação, proporcionando uma boa compensação entre velocidade e memória, especialmente em ambientes com pouca VRAM.
No entanto, você ainda precisa de uma quantidade considerável de RAM do sistema para que o descarregamento funcione de maneira eficaz. Portanto, ambientes com pouca VRAM e pouca RAM ainda não funcionariam. 
A partir desta versão, os usuários terão adicionalmente a opção de descarregar para disco em vez de RAM, reduzindo ainda mais o consumo de memória. Configure o `offload_to_disk_path` para ativar este recurso.
```python
pipeline.transformer.enable_group_offload(
    onload_device="cuda", 
    offload_device="cpu", 
    offload_type="leaf_level", 
    offload_to_disk_path="path/to/disk"
)
