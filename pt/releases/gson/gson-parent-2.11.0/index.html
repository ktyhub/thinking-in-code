Mudanças mais importantes

  • Adicionadas regras padrão do ProGuard/R8 (@Marcono1234, #2397, #2420; @sgjesse, #2448; @sfreilich)
    Se você estiver usando ProGuard ou R8 (por exemplo, para projetos Android), talvez não precise mais de nenhuma configuração especial do Gson se suas classes tiverem um construtor sem argumentos e usarem @SerializedName para seus campos.
  • No Android, Gson agora requer API nível 21 ou mais recente
  • Adicionado novo Strictness API (@marten-voorberg e colegas estudantes, #2437)
    Alguns dos API do Gson ainda são tolerantes por padrão, mas agora você pode usar os métodos recém-adicionados GsonBuilder#setStrictness, JsonReader#setStrictness e JsonWriter#setStrictness com Strictness.STRICT para substituir esse comportamento e, em vez disso, aderir estritamente à especificação JSON ao analisar.
  • Nova classe FormattingStyle para permitir configurar quebras de linha na saída JSON (@mihnita, #2231)
    Pode ser configurado usando GsonBuilder#setFormattingStyle e JsonWriter#setFormattingStyle.
  • TypeToken não pode mais capturar variáveis de tipo por padrão (@Marcono1234, #2376)
    Anteriormente, essa era uma fonte comum de problemas. A exceção lançada recentemente refere-se a um artigo do Guia de solução de problemas que explica isso com mais detalhes e fornece sugestões para atualizar o código afetado.
  • Adicionado suporte de serialização para classes locais e anônimas com um adaptador personalizado (@Marcono1234, #2498)
    Isso afeta, por exemplo, implementações de List retornadas por bibliotecas como Guava, que são implementadas como classes anônimas, que foram anteriormente serializadas como null. Classes anônimas e locais sem adaptador customizado ainda serão serializadas como null.
  • Adicionada dependência de com.google.errorprone:error_prone_annotations
    Seu projeto pode usar exclusões de dependência Maven ou Gradle para remover a dependência transitiva error_prone_annotations do Gson. Ou se você estiver mantendo dependências manualmente como JARs em seu projeto, poderá omitir error_prone_annotations. E ainda deve funcionar corretamente.
    Mas o próprio Gson a declara como uma dependência obrigatória e, se você não executar nenhuma configuração personalizada, o Maven ou o Gradle tentarão, por padrão, baixá-la e usá-la.
  • Muitas mensagens de exceção agora referem-se ao Guia de solução de problemas (@Marcono1234, #2357)
    Agradecemos comentários sobre o Guia de solução de problemas!
  • Documentado oficialmente que outras linguagens JVM além de Java podem não ser totalmente suportadas, consulte o README.
  • Garantir que JsonElement#toString produza saída JSON (@Marcono1234, #2659)

Outras mudanças

Correções de bugs

  • Corrigidos resultados incorretos de JsonPrimitive#equals para valores grandes de BigInteger (@MaicolAntali, #2311)
  • Corrigidos resultados incorretos de JsonPrimitive#equals para valores grandes de BigDecimal (@MaicolAntali, #2364)
  • Corrigido JsonReader lançando NumberFormatException em vez de MalformedJsonException para sequências de escape Unicode malformadas (@MaicolAntali, #2337)
  • Corrigido TypeToken#getParameterized retornando ParameterizedType falso para tipos não genéricos (@ Marcono1234, #2447)
  • Corrigido o adaptador Java Record que não funcionava para a imagem nativa GraalVM (@eamonnmcmanus, #2465)
  • Corrigido JsonWriter#name que não lançava exceção quando nenhum objeto JSON estava sendo gravado (@shivam-sehgal, #2475; @Marcono1234, #2476)
  • Corrigido Gson#getDelegateAdapter que não funcionava corretamente para @JsonAdapter (@Marcono1234, #2435)
    Observe que null agora não é mais permitido como valor skipPast, o que era permitido anteriormente, mas não documentado.
  • Corrigido GsonBuilder que não rejeitava adaptadores de tipo para Object e JsonElement, cujos adaptadores padrão não podem ser substituídos (@sachinp97; #2479)
  • Corrigida a não aplicação de limites ao desserializar BigDecimal e BigInteger (@Marcono1234, #2510)
    Os novos limites evitam possíveis problemas de desempenho quando o código do usuário usa números desserializados. O próprio Gson foi e não é afetado por esses problemas de desempenho. Os limites devem ser altos o suficiente para não causar problemas na maioria dos casos de uso, mas o feedback é apreciado.
  • Corrigido GsonBuilder#setDateFormat que não rejeitava formatos de data inválidos (@Carpe-Wang, #2538)
  • Corrigido GsonBuilder#setDateFormat que não rejeitava estilos de data inválidos (@Marcono1234, #2545)
  • Corrigido GsonBuilder#setDateFormat ignorando o estilo DEFAULT parcial (@Marcono1234, #2556)
  • Corrigido TypeToken#isAssignableFrom jogando AssertionError em alguns casos (@Marcono1234, #2544)
  • Corrigidos adaptadores de data que não restauravam o fuso horário após a análise (@Carpe-Wang, #2549)
  • Corrigido TypeToken#equals retornando erroneamente false para parâmetros de tipo genérico iguais em alguns casos (@d-william, #2599)
  • Correção de URLs herdados incorretos em pom.xml (@Marcono1234, #2351)

Melhorias de desempenho

  • Reduza ligeiramente o uso de memória para adaptador baseado em reflexão (@sembseth, #2325; @Marcono1234, #2440)
  • Melhor velocidade de análise de ToNumberPolicy#LONG_OR_DOUBLE (@ctasada, #2674)

  • Error Prone configurado para verificar automaticamente se há bugs durante a compilação (@MaicolAntali, #2308)
  • Tratamento simplificado de exceções esperadas em testes (@elevne, #2454)
  • Adicionado teste de integração para imagem nativa GraalVM (@Marcono1234, #2466)
  • Formatei o código de acordo com o Google Style Guide e configurei o Spotless (@MaicolAntali, #2531, #2537)
  • Tornou a compilação do Maven reproduzível (@ Marcono1234, #2543)
  • Removida a classe interna DateTypeAdapter para reduzir a duplicação de código (@Marcono1234, #2546)
  • Dependências e plugins atualizados pelo Dependabot
