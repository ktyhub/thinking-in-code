Codewhale v0.9.8

Codewhale é o produto público da Shannon Labs. O codewhale os nomes de comando, pacote npm e release-asset permanecem técnicos em letras minúsculas identificadores. O pacote npm legado deepseek-tui está obsoleto e não recebe mais lançamentos. Usuários provenientes do legado v0.8.x deepseek / Os nomes deepseek-tui deverão migrar com docs/REBRAND.md.

Instalar

Recomendado — npm (um comando, ambos os pontos de entrada)

npm install -g codewhale

O wrapper baixa os ativos de comando codewhale e codew correspondentes deste lançamento. Ambos contêm o mesmo tempo de execução compilado.

Docker/GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.8

A imagem expõe o mesmo tempo de execução que codewhale e codew. O A tag latest também é atualizada no lançamento.

Carga (Linux / macOS)

cargo install codewhale-cli --locked

O pacote Cargo instala o codewhale. Cargo não pode criar um segundo comando alias de um destino binário; usuários que desejam uma ortografia mais curta podem adicionar um Link simbólico codew para o executável instalado. O npm, Homebrew, arquivo, shell-installer e canais de contêiner instalam ambos os nomes de comando diretamente.

O que há em v0.9.8

Codewhale v0.9.8 envia o acabamento atribuído restante. Web restante o polimento das configurações muda para v0.9.9. Modelos pré-fabricados de terceiros que possuem um host publicado compatível com OpenAI é enviado aqui (#5350).

Corrigido

  • sudo (e ajudantes su/setuid) funcionam novamente para administradores de grupos de roda que desejam que o Codewhale seja capaz de escalar: o fortalecimento da inicialização do Linux sinalizador PR_SET_NO_NEW_PRIVS irreversível - herdado por cada processo filho - agora pode ser ignorado com CODEWHALE_NO_NEW_PRIVS=0 (#5413). A bandeira permanece acesa por padrão; as medidas no-ptrace e no-core-dump nunca são ignoradas.
  • As mortes em processos de classe de aborto não envenenam mais o terminal (#5424). Um estouro de pilha, falha de alocação ou pânico duplo ignora o gancho de pânico e todos os guardas de limpeza, que é como a saída no meio da curva de um usuário v0.9.7 saiu captura de mouse vazando sequências SGR em seu shell. Um O manipulador async-signal-safe agora restaura os modos do terminal e anexa um marcador de causa de uma linha para ~/.codewhale/crashes/last-fatal-signal.log antes de aumentar novamente, mantendo o status honesto de espera do sinal 128+. UM SIGKILL (OOM killer) permanece ininterceptável por design.

Alterado

  • O prefixo Prompt-cache está fixado para a sessão. O loop de ferramentas não é mais recompõe o prompt do sistema do disco em cada etapa do modelo, para que um agente gravar um arquivo não interrompe mais o cache de prefixo KV do provedor no meio do turno. O o prompt do sistema e o catálogo de ferramentas são recompostos apenas em um cabeçalho declarado mudança (/model, modo, objetivo, currículo da sessão), que é re-fixado em um logado razão; uma alteração não declarada é relatada como desvio e o pino original é mantido em vez de se tornar silenciosamente a nova linha de base. Espaço de trabalho, AGENTES.md, habilidades, memória e desvio de objetivos agora atingem o modelo como um Mensagem do usuário <context_update> na próxima vez do usuário - um acréscimo de histórico, não é uma reescrita de cabeçalho. /cache stats mostra o motivo do pin, o último erro motivo, a contagem de desvios não declarados e a contagem de atualizações de contexto. Veja docs/CACHE.md.

  • A compatibilidade do plugin agora é por componente. Um revisado, trusted, habilitado pacote que mistura Skills ou MCP com comandos, agentes, ganchos, Declarações LSP, nativas, raízes do sistema de arquivos ou mutação do ciclo de vida mantêm o adaptadores suportados ativos e relata o restante como inativo (full / partial/unsupported). Todos os pacotes não suportados ainda não podem ser ativados. O hash de capacidade agora é v2 e vincula a política de ativação desta compilação, portanto recibos v1 mais antigos e qualquer alteração posterior de ativação do adaptador falham no fechamento como revisão de necessidades. Habilidades e cada transporte MCP solicitam novamente sua própria capacidade na fronteira de consumo.

Removido

  • A catraca orçamentária da estrutura de origem (etapa CI, verificador, linha de base JSON). Ele mediu a contagem de linhas, não a qualidade: todos os recursos legítimos eram necessários um teto editado à mão e a "revisão" que o acompanha era uma auto-revisão, então comprou cerimônia, não proteção. Portas de medição de comportamento (código morto, contrato de tempo de execução, lista de pendências de persistência) permanecem aplicados.
  • DeepSeek pode reutilizar uma chave já armazenada pelo DeepSeek Harness oficial (dsh) depois codewhale auth external-consent --provider deepseek --mode read-only. Codewhale lê apenas DEEPSEEK_API_KEY do exato concedido $DSH_HOME/.credentials.yaml e nunca grava ou atualiza esse arquivo.
  • O analisador de remarcação TUI agora respeita as regras de comprimento de cerca do CommonMark: uma linha ```` opener is not closed by a shorter ```, portanto, o conteúdo > dentro de uma linha mais longa fence permanece código literal em vez de escaping em uma cotação.
  • Os subagentes finalizam quando o ID da sessão pai muda, portanto, um encerramento a sessão não pode bloquear novos filhos como proprietário ativo (#5372).
  • Os recibos da rota de geração de filhos permanecem ativos e o uso é desduplicado pela resposta (#5366).
  • O médico mantém a prontidão de configuração persistente durante a primeira execução/atualização pontos de verificação (#5340).
  • A seleção padrão de aprovação é aplicada e explicada; agentes são informados quando as aprovações estão desativadas (#5293).
  • Uma sonda /models 2xx é uma verificação de conexão, não de prontidão do modelo.
  • O layout do site usa um contêiner, o ticker não implica mais em falso a prontidão do provedor e os links de instalação permanecem na localidade ativa.
