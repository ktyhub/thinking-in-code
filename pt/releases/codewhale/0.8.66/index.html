Codewhale v0.8.66

CodeWhale é o projeto canônico, comando, pacote npm e nome do ativo de liberação. O pacote npm legado deepseek-tui é obsoleto e não recebe mais lançamentos. Usuários vindos de Nomes legados v0.8.x deepseek / deepseek-tui devem migrar com docs/REBRAND.md.

Instalar

Recomendado — npm (um comando, ambos os binários)

npm install -g codewhale

O wrapper faz download dos binários de tempo de execução correspondentes desta versão e os coloca no mesmo diretório.

Docker/GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.66

A imagem envia o despachante codewhale, o calço codew e o tempo de execução codewhale-tui. A tag latest também é atualizada no lançamento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Ambas as caixas são necessárias - codewhale-cli produz o despachante codewhale e o calço codew, enquanto codewhale-tui produz o tempo de execução interativo ao qual o despachante delega. A instalação de apenas uma caixa falhará em tempo de execução com um erro MISSING_COMPANION_BINARY.

Download manual — arquivos da plataforma (recomendado)

Cada arquivo abaixo contém o despachante codewhale, o shim codew e o tempo de execução codewhale-tui, além de um script de instalação: | Plataforma | Arquivo | Instalar script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | ARM do macOS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (instalador) | CodeWhaleSetup.exe | Configuração do NSIS | | Janelas x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portátil) | codewhale-windows-x64-portable.zip | — | Unix (Linux/macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Janelas:

  • Para o caminho do instalador, execute CodeWhaleSetup.exe; ele instala codewhale.exe, codew.exe e codewhale-tui.exe em %LOCALAPPDATA%\Programs\CodeWhale\bin e adiciona esse diretório ao PATH do usuário atual.
  • Extrair codewhale-windows-x64.zip
  • Execute install.bat (copia para %USERPROFILE%\bin)
  • Adicione %USERPROFILE%\bin ao seu PATH O arquivo portátil do Windows ignora o script de instalação – extraia e execute de qualquer diretório. O instalador NSIS não está assinado no momento e pode acionar o Windows SmartScreen até que um certificado de assinatura seja conectado ao pipeline de lançamento. Cada plataforma também possui binários ** simples e desarquivados ** anexados abaixo (codewhale-<platform>, codew-<platform> e codewhale-tui-<platform>) - o wrapper npm e o codewhale update no aplicativo baixam os binários de tempo de execução correspondentes, enquanto os arquivos .tar.gz / .zip acima são o download manual recomendado e, adicionalmente, agrupam um script de instalação. O pacote npm legado deepseek-tui está obsoleto e não foi republicado. Para migração de nomes binários legados v0.8.x, consulte docs/REBRAND.md.

Verificar (recomendado)

Baixe os manifestos de checksum desta versão e verifique:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

O que há em v0.8.66

Adicionado

  • Adicionado estado legado codewhale doctor / codewhale doctor --json diagnósticos que comparam caminhos de estado conhecidos do ~/.deepseek com seus Contrapartes ~/.codewhale e sinalizam dados não migrados ou de raiz dupla (#3727).
  • Adicionado Sakana AI Fugu como um provedor compatível com OpenAI de primeira classe com Aliases sakana/fugu, descoberta FUGU_API_KEY/SAKANA_API_KEY, fiação do seletor de provedor, conclusões de modelo e documentos do provedor. Colhido de #3748 por @lerugray.
  • Adicionada validação do formato de lançamento WhaleFlow-to-Fleet: o fluxo de trabalho padrão da frota contrato permite até 100 agentes no total e 5 anéis recursivos, requer faz loops/expande limitados antes do lançamento e preserva a seleção do modelo por slot.
  • Adicionada uma visualização /config ask-rules somente leitura para os problemas resolvidos Caminho permissions.toml, status do arquivo, contagem de regras e configuração regras de solicitação de ferramenta/comando/caminho. Mesclado de #3569 por @greyfreedom.
  • Adicionadas substituições context_window em nível de provedor para compatibilidade com OpenAI gateways e provedores auto-hospedados podem fazer orçamentos de acordo com seu modelo real janela de contexto (#3545).
  • Adicionado o shim nativo codew para liberar arquivos, entradas do instalador do Windows, preparação de ativos de liberação local e verificação de soma de verificação para instalações manuais receba o mesmo comando curto que o Cargo instala a compilação.
  • Adicionado OpenModel como provedor de mensagens antrópicas de primeira classe, com configuração, CLI, seletor de provedor, documentos e cobertura de registro. Colhido de #3585 por @noaft.
  • Adicionada documentação de implantação e segurança do WeCom Bridge, com envio comandos de tempo de execução/ponte e orientação do ambiente de tempo limite de aprovação. Colhido de #3640 por @pkeging.
  • Adicionado um comando token/cache/cost scorecard para liberação de liberação offline, verificações de regressão de linha de base e visibilidade de custo por turno (#3388). Stream-JSON metadados exec agora também relatam input_analysis conservador e visible_final_answer_chars, para que os chicotes de referência possam medir a transcrição crescimento e inchaço da resposta final sem adivinhação (#2956, #2957).
  • Adicionado um livro de evidências de liberação para v0.8.66 e aberto o ACP externo envio de registro para CodeWhale após validar o publicado Handshake de autenticação codewhale@0.8.65 ACP contra o verificador de registro upstream (#3192).
  • Adicionada uma tabela de configuração [verifier] digitada para a pista de visualização do verificador, com enabled e o mapeamento verdict_policy = "hunt" fornecido documentado e validado (#2093).
  • Adicionada comutação rápida de slot Hotbar Alt+1 – Alt+8 com chave de cartão de decisão desambiguação, além de um cartão introdutório que explica e pode descartar o Barra direta (#3796, #3788).
  • Higiene de lançamento/documentos: snippets de instalação/versão públicos protegidos e o npm Ponteiro codewhaleBinaryVersion contra desvio, feito check-docs/check-facts falha em snippets obsoletos ou provedores não mapeados e interrompeu sync-changelog de descartar um lançamento quando apenas [Unreleased] existir (#3767, #3768, #3769, #3770, #3771, #3772).

Alterado

  • Modo automático adiado do seletor de modo voltado para o usuário, ciclo, hotbar, /mode comando e o modo runtime-thread substitui até que tenha um prompt distinto e comportamento de revisão automática; o texto existente do modo auto agora volta para o Agente em vez de selecionar um modo vazio, e a cópia modal de aprovação não implica mais o modo atual é YOLO (#3730, #3733).
  • Esclarecida a superfície e a documentação de configuração do Fleet para que o Fleet seja tratado como durável camada de configuração do subagente enquanto WhaleFlow é de autoria do agente plano de orquestração que seleciona e monitora os slots da frota.
  • Reduziu o prompt de Constituição padrão, mantendo a estrutura necessária âncoras sob cobertura de regressão, reduzindo a pegada estática do prompt para voltas sensíveis ao cache (#2953).
  • Tornou o prompt de aprovação embutido e ancorado na parte inferior, em vez de tela inteira aquisição, para que o contexto e os controles permaneçam visíveis enquanto uma ferramenta aguarda uma decisão (#3799).
  • O Hotbar agora está oculto por padrão até a aceitação explícita da configuração (#3807); o O shell do agente interativo também é padronizado para aprovação com um recurso compartilhado linha de base (#3756).
  • A autoridade do modo agora resolve solicitações de aprovação por meio de uma única autoridade fonte em vez de verificações por superfície (#3795).

Corrigido

  • Realocação do estado legado com um aviso de migração visível ao usuário sempre que ~/.deepseek/<state> é movido ou copiado para ~/.codewhale/<state>, então usuários atualizados sabem que seus dados foram preservados e onde está o estado canônico agora vive (#3726).
  • Visibilidade herdada do .deepseek/sessions restaurada para instalações atualizadas onde já existia um diretório ~/.codewhale/sessions vazio, copiando faltando entradas de sessão herdadas no armazenamento de sessão CodeWhale principal sem substituir os dados mais recentes (#3724).
  • Classificação de risco de aprovação simplificada para comandos shell somente leitura, como codewhale --version, codewhale --help e git status --porcelain então o modal não rotula mais o shell somente leitura comprovado como destrutivo (#3730).
  • Adicionadas colunas de rota de provedor/modelo para /cache transformar telemetria para DeepSeek regressões de acertos de cache podem ser correlacionadas com alterações de rota automática (#3738).
  • Correção do tratamento de aprovação do tempo de execução API para que o espaço de trabalho trust não seja mais resolvido automaticamente aprovações de ferramentas comuns; trust agora participa apenas da nova tentativa de acesso total decisões enquanto YOLO/aprovação automática continua sendo o desvio de aprovação (#3736).
  • Correção de superfícies modais para que a pilha de visualizações compartilhadas pinte um cenário opaco antes qualquer sobreposição, enquanto os interiores pop-up de entrada do Plano/solicitação permanecem opacos e o Plano o rodapé de confirmação mantém as opções de ação visíveis em terminais estreitos (#3732).
  • Adicionado um protetor de modo plano turn-loop para ferramentas de gravação de arquivos e MCP com capacidade de gravação ferramentas para que a promessa de "não escrever" do Plan seja aplicada antes da aprovação ou execução, não apenas pela camada sandbox/catálogo (#3734).
  • Preservado o piso de segurança de revisão durável para ações de shell semelhantes a publicações em Modo YOLO, então cargo publish, npm publish e marcação/liberação empurram a força aprovação em vez de aprovação automática silenciosa (#3735).
  • Corrigido o editor externo Ctrl+O que congela onde a bomba de entrada do terminal do CodeWhale poderia continuar lendo as chaves enquanto o Vim/editor possuísse o terminal, especialmente em Conchas mintty/cygwin do Windows. Obrigado @buko pela reprodução precisa (#3657).
  • Fortaleceu a verificação de desvio de dependência OHOS contra EOFs transitórios do registro de carga tentando novamente a investigação do gráfico de dependência antes de falhar no CI.
  • Atualizado o substituto do provedor /links para o URL atual dos documentos do CodeWhale e adicionou um link de documentos do Baidu Qianfan. Colhido de #3621 por @noaft.
  • CODEWHALE_TOOL_SURFACE=shell-only reforçado para execuções de benchmark/exec: o superfície somente shell oculta ferramentas nativas do catálogo visível do modelo e valores desconhecidos de CODEWHALE_TOOL_SURFACE agora avisam em vez de cair silenciosamente de volta para toda a superfície da ferramenta (#2954).
  • Fanout de subagentes e lock hot paths: espaço preservado no canal de eventos para eventos de progresso (#3783, obrigado @cyq1017), deixe o subagente independente iniciar junte-se a um único lote de despacho paralelo em vez de serializar (#3801), renderizado a barra lateral do subagente/ListSubAgents de um instantâneo somente leitura com limite limpeza (#3803), usou envios de melhor esforço sem bloqueio para atualização de ListSubAgents enquanto ainda aguarda eventos críticos (#3802), mudou o estado do subagente E/S de disco de persistência fora do bloqueio de gravação do gerenciador (#3805) e usou try_lock para atualização do gerenciador de shell em caminhos de UI assíncronos (#3804).
  • Proveniência: continuações de tempo de execução e SubAgentHandoff agora herdam a posição Autoridade YOLO, enquanto MemoryRecall, ImportedTranscript e As entradas AssistantGenerated permanecem protegidas (#3817).
  • Honestidade na aprovação: rotulou as aprovações no escopo da sessão com precisão, em vez de "sempre" e decisões de aprovação reveladas nos resultados da ferramenta (#3766). Os créditos do contribuidor para este lançamento estão na entrada changelog acima - obrigado a todos cujos relatórios, relações públicas, análises e reproduções o moldaram. Consulte CHANGELOG.md para notas completas e docs/CHANGELOG_ARCHIVE.md para versões mais antigas.
