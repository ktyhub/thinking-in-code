firecrawl v2.10

Firecrawl v2.10

Melhorias

  • Endpoint /parse — Carregue arquivos locais (PDF, DOCX, DOC, ODT, RTF, XLSX, XLS, HTML) de até 50 MB e receba Markdown limpo e pronto para LLM, JSON ou um resumo. As tabelas e a ordem de leitura são preservadas, com suporte completo para Zero Data Retention para planos empresariais. Disponível em JS, Python, Go, Rust, Java, .NET, PHP, Ruby e Elixir SDKs.
  • Modo de bloqueio — Defina lockdown: true em /scrape para fornecer resultados exclusivamente do índice do Firecrawl com zero solicitações de saída e zero retenção de dados por padrão. Os caminhos de saída bloqueados incluem buscas HTTP, robots.txt, downloads de áudio e mídia. Disponível em todos os SDK, CLI (--lockdown) e MCP.
  • Formato question — Passe um prompt em linguagem natural para /scrape e obtenha uma resposta fundamentada e livre de alucinações em data.question. Funciona em uma cadeia de modelo gerenciado com fallback automático, isolamento de injeção de prompt por meio de marcação XML e escaping com espaço de largura zero e até 100 vezes menos tokens por chamada.
  • Formato highlights — Retorna as frases exatas, blocos de código e linhas de tabela em uma página que corresponde à sua consulta. Frases consecutivas são reunidas em parágrafos, linhas de código são agrupadas em blocos protegidos com seu idioma original e linhas de tabela são reconstruídas em tabelas Markdown com cabeçalhos — tudo a partir da página de origem, usando até 100 vezes menos tokens por chamada.
  • Formato video — Adicionado video para raspar formatos. Retorna um URL de vídeo assinado para download para sites suportados (por exemplo, YouTube), com encaminhamento de cookies para downloads autenticados e bloqueio de bloqueio explícito.
  • Filtros de domínio /search — Adicionados parâmetros includeDomains e excludeDomains ao /search para definir o escopo dos resultados para um conjunto específico de sites.
  • Endpoint de feedback /search — Envie uma classificação em um resultado de pesquisa com POST /v2/search/:jobId/feedback. Cada envio aceito reembolsa 1 crédito, limitado por dia UTC, com novas tentativas idempotentes.
  • Agente de usuário robots.txt personalizado — Adicionado robotsUserAgent para rastrear solicitações para avaliar regras de robots.txt e atrasos de rastreamento em relação a uma string de agente personalizada e um sinalizador de organização customRobotsAgent separado, independente de ignoreRobots. Disponível em JS, Python e Java SDKs.
  • Go SDK oficial — Adicionado um Go SDK original para o v2 API, substituindo o módulo da comunidade. Inclui espera de repetição com reconhecimento de contexto e digitação MapData.Links adequada.
  • Ruby SDK — Adicionado o Firecrawl Ruby SDK v2 oficial com cobertura completa de endpoint e digitação nativa v2.
  • PHP SDK — Adicionado o PHP SDK oficial com suporte Laravel, cobertura de raspagem/pesquisa/rastreamento/mapeamento/análise e um pacote firecrawl/firecrawl-sdk Composer publicado.
  • .NET SDK — Adicionado o .NET SDK oficial com suporte v2 API, análise e um pacote firecrawl-sdk NuGet.
  • Rust SDK v2 — O Rust SDK foi promovido para o v2 oficial SDK com paridade entre raspagem, pesquisa, rastreamento, mapa, agente e análise.
  • Sugestão /interact — Chamadas para /scrape que passam por um array actions agora retornam um aviso sugerindo /interact para automação de navegador com estado.
  • Limite de tamanho de PDF — Aumentou o limite de tamanho de upload de PDF de 10 MB para 30 MB.
  • Faturamento de páginas processadas em PDF — Faturamento de PDF atualizado para refletir as páginas processadas em vez da contagem bruta de páginas.
  • Arnês Docker — Exposto HARNESS_STARTUP_TIMEOUT_MS a docker-compose para usuários auto-hospedados que precisam de janelas de inicialização mais longas.
  • Elixir SDK — Adicionado parse_file/3 ao Elixir SDK para o endpoint /parse.
  • Tempo limite de solicitação JS SDK — Adicionada uma opção de tempo limite de solicitação explícita ao JS SDK para evitar solicitações suspensas.

Correções

  • Resolveu vários CVEs em API e SDKs, incluindo axios, postcss, fast-xml-parser, protobufjs, follow-redirects, langsmith, lodash, fast-uri e fast-xml-builder.
  • Correção da marca colors.secondary sendo preenchida incorretamente quando o LLM omitia um valor — secondary agora é opcional e não é mais aplicado como padrão.
  • Corrigido o serviço Playwright ignorando o cabeçalho de solicitação User-Agent do chamador.
  • URLs assinados screenshot corrigidos retornando resultados obsoletos do cache, forçando uma falha no cache quando o URL assinado expirou.
  • Correção das solicitações de bloqueio sendo cobradas duas vezes pelo ZDR, tratando o bloqueio como retenção zero de dados por padrão.
  • Corrigido o faturamento de proxy para scrapes em cache, cobrando incorretamente créditos de proxy quando não ocorria nenhuma saída de proxy.
  • Corrigidos scripts de transcrição do YouTube executados em scrapes somente de áudio e downloads de áudio que não recebiam cookies CDP.
  • Correção do serviço de conversão html-to-md ignorando retenção zero de dados.
  • Corrigido um estouro de pilha no marked.parse ao lidar com certas saídas de PDF.
  • Corrigido robotsUserAgent que não era respeitado pelo filtro de link nativo e não era incluído nas cargas úteis de rastreamento JS SDK.
  • Corrigidos endpoints de status /v1 que retornavam 500 em IDs de trabalho não UUID – agora retornam 400 adequados.
  • Corrigidos arrays actions: [] vazios sendo tratados como ações em sinalizadores de recursos.
  • Corrigido o observador JS SDK emitindo eventos duplicados, vazando tempos limite e travando start() nos tempos limite do observador.
  • Correção do desempacotamento Ruby SDK dos campos de dados credit_usage e padronização de skipTlsVerification para false.
  • Correção da validação de limite negativo ausente em Python, Java e Go SDKs.
  • Java SDK corrigido aceitando chaves API vazias e métodos de ciclo de vida assíncronos ausentes.
  • Registros de data e hora do período de cobrança fixos, pesquisas de assinatura e relatórios de crédito do plano.
  • Corrigido o tempo limite do crawl-backlog ilimitado – agora limitado a 48h.

##API

  • Adicionado POST /v2/parse para uploads de arquivos multipartes de até 50 MB. Retorna um documento padrão. Opções de raspagem não permitidas na análise: changeTracking, screenshot, branding, actions, waitFor, location, mobile; proxy está restrito a auto ou basic. Erros com PARSE_UNSUPPORTED_OPTIONS em entrada não permitida.
  • Adicionado lockdown: boolean a /scrape. As falhas de cache retornam 404 com SCRAPE_LOCKDOWN_CACHE_MISS. Faturamento: +4 créditos quando lockdown está habilitado, 1 crédito em falta de cache. Disponível em todos os SDKs.
  • Adicionados question e highlights aos formatos /scrape, retornando data.question e data.highlights respectivamente.
  • Adicionados formatos video aos /scrape. Retorna document.video como URL assinado. +4 créditos por solicitação. URLs não suportados geram SCRAPE_VIDEO_UNSUPPORTED_URL; parse rejeita o formato video client e do lado do servidor.
  • Adicionados arrays includeDomains e excludeDomains no /v2/search para definir o escopo dos resultados para domínios específicos.
  • Adicionado POST /v2/search/:jobId/feedback para classificação dos resultados da pesquisa. Cada envio aceito reembolsa 1 crédito, limitado por dia UTC via SEARCH_FEEDBACK_DAILY_CAP_CREDITS, com novas tentativas idempotentes retornando alreadySubmitted: true. Envios de feedback anteriores a SEARCH_FEEDBACK_MAX_AGE_SEC (padrão 120) são rejeitados. O faturamento da pesquisa agora é de créditos ceil(results/10) * 2, apresentados nas respostas.
  • Adicionado robotsUserAgent a /v2/crawl crawlerOptions para avaliação de robots.txt de agente personalizado. Fechado atrás da bandeira da organização ignoreRobots.
  • Adicionado um sinalizador de organização customRobotsAgent separado, independente de ignoreRobots, para que as equipes possam enviar agentes de usuário personalizados sem desativar a aplicação de robots.txt.
  • Migração da flag org ignoreRobots de um padrão booleano para um padrão disabled/allowed/forced. O formato de solicitação herdado ignoreRobots: boolean foi removido — clients deve usar os novos valores de sinalizador.
  • /v0/scrape, /v0/crawl, /v0/crawl/status/:jobId, DELETE /v0/crawl/cancel/:jobId, /v0/search, /v1/extract, /v1/extract/:jobId, /v2/extract, /v2/extract/:jobId, /v1/deep-research, /v1/deep-research/:jobId, /v1/llmstxt e /v1/llmstxt/:jobId obsoletos. Os terminais obsoletos emitem cabeçalhos Deprecation: true, Warning: 299 - "<message>", Link; rel="successor-version" e (quando configurados) Sunset, além de warnings[] e replacement no corpo JSON. JS e Python SDKs os transformam em clients.
