Novos métodos

SHiRA

@kkb-code contribuiu com Sparse High Rank Adapters (SHiRA, paper) que prometem oferecer um ganho potencial de desempenho em relação aos LoRAs - especialmente a perda de conceito ao usar vários adaptadores é melhorada. Como os adaptadores treinam apenas em 1-2% dos pesos e são inerentemente esparsos, alternar entre adaptadores pode ser mais barato do que com LoRAs. (#2584)

Senhorita

@JL-er adicionou um novo método PEFT, MiSS (Matrix Shard Sharing) em #2604. Este método é uma evolução do Bone, que, de acordo com nosso benchmark de comparação de métodos PEFT, oferece excelentes resultados quando se trata de desempenho e eficiência de memória. Se você ainda não experimentou, deveria fazê-lo agora.

Ao mesmo tempo, Bone será descontinuado em favor do MiSS e será removido no PEFT v0.19.0. Se você já possui um checkpoint Bone, você pode usar scripts/convert-bone-to-miss.py para convertê-lo em um checkpoint MiSS e prosseguir com o treinamento usando MiSS.

Melhorias

LoRA para nn.Parameter

LoRA agora é capaz de atingir nn.Parameter diretamente (#2638, #2665)! Você já teve esse nn.Module complicado com parâmetros promissores, mas era muito personalizado para ser suportado por sua biblioteca de ajuste fino favorita? Não se preocupe, agora você pode direcionar nn.Parameters diretamente usando o atributo de configuração target_parameters que funciona de forma semelhante a target_modules.

Esta opção pode ser especialmente útil para modelos com camadas Mixture of Expert (MoE), já que eles geralmente usam nn.Parameters diretamente e não podem ser direcionados com target_modules. Por exemplo, para a família de modelos Llama4, use a seguinte configuração para direcionar os pesos do MoE:

config = LoraConfig(
    ...,
    target_modules=[],  # <= prevent targeting any modules
    target_parameters=["feed_forward.experts.down_proj", "feed_forward.experts.gate_up_proj"],
)

Observe que esse recurso ainda é experimental, pois vem com algumas ressalvas e, portanto, pode mudar no futuro. Além disso, os pesos do MoE com muitos especialistas podem ser muito grandes, portanto, espere um uso de memória maior do que em comparação com as camadas nn.Linear normais.

Injetando adaptadores baseados em um state_dict

Às vezes, é possível que haja um ponto de verificação do adaptador PEFT, mas a configuração PEFT correspondente não seja conhecida por qualquer motivo. Para injetar as camadas PEFT para este ponto de verificação, normalmente você teria que fazer engenharia reversa da configuração PEFT correspondente, mais notavelmente o argumento target_modules, baseado no state_dict do ponto de verificação. Isso pode ser complicado e sujeito a erros. Para evitar isso, também é possível chamar inject_adapter_in_model e passar o state_dict carregado como argumento:

from safetensors.torch import load_file
from peft import LoraConfig, inject_adapter_in_model

model = ...
state_dict = load_file(<path-to-safetensors-file>)
lora_config = LoraConfig()  # <= no need to specify further
model = inject_adapter_in_model(lora_config, model, state_dict=state_dict)

Encontre mais sobre [injeção baseada em state_dict nos documentos] (https://huggingface.co/docs/peft/main/en/developer_guides/low_level_api#injection-based-on-a-statedict).

Mudanças

Compatibilidade

Um bug nos métodos de aprendizagem imediata fez com que modules_to_save fosse ignorado. Especialmente as tarefas de classificação são afetadas, uma vez que geralmente adicionam a camada de classificação/pontuação ao modules_to_save. Consequentemente, estas camadas não foram treinadas nem armazenadas após o treinamento. Isso foi corrigido agora. (#2646)
