opentelemetry-instrumentação java v2.31.0

Esta versão é direcionada ao OpenTelemetry SDK 1.65.0.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Remova o ConfigPropertiesBackedConfigProvider obsoleto e sua compatibilidade com create(ConfigProperties) API da ponte de configuração declarativa. (#19305)
  • Pare de expor opentelemetry-instrumentation-api-incubator em caminhos de classe de compilação de instrumentação de biblioteca. (#19612)

🚫 Depreciações

  • Preterir otel.instrumentation.experimental.span-suppression-strategy em favor de Experimental.setSpanSuppressionStrategy(...). (#19180)
  • Descontinuar HostIdResource.REGISTRY_QUERY em favor da pesquisa de caminho absoluto reg.exe usada por HostIdResource. (#19293)
  • Descontinuar MessageOperation em favor de MessagingOperationType e as sobrecargas de MessageOperation de MessagingAttributesExtractor, MessagingConsumerMetrics, MessagingProducerMetrics, MessagingSpanKindExtractor e MessagingSpanNameExtractor em favor dos MessagingOperationType APIs correspondentes. (#19357)
  • Preterir otel.traces.exporter=zipkin em favor de otel.traces.exporter=otlp e otel.exporter.zipkin.endpoint em favor de otel.exporter.otlp.traces.endpoint. (#19400)
  • Preterir OpenTelemetryMeterRegistryBuilder#setMicrometerHistogramGaugesEnabled(boolean) em favor de Experimental#setMicrometerHistogramGaugesEnabled(OpenTelemetryMeterRegistryBuilder, boolean). (#19404)
  • Descontinuar metadados gRPC legados, cabeçalho de mensagens e propriedades de captura de parâmetros de solicitação de servlet e APIs em favor da configuração .included/.excluded baseada em seletor e IncludeExclude APIs. (#19494, #19522, #19523, #19638)
  • Preterir otel.instrumentation.runtime-telemetry.experimental.prefer-jfr em favor de otel.instrumentation.runtime-telemetry.experimental.jfr-metrics.included e setPreferJfrMetrics(...) em favor de setJfrMetrics(RuntimeTelemetryBuilder, IncludeExclude). (#19495)
  • Descontinuar configuração booleana e de lista de captura para dados MDC/contexto, mensagens de mapa, pares de valores-chave, contexto de logger, marcadores Logstash e argumentos estruturados em favor de seletores .included/.excluded e IncludeExclude APIs. (#19519, #19520, #19521, #19599, #19600, #19605, #19609, #19610)
  • Descontinuar o campo de configuração declarativa general.semconv_stability.opt_in em favor de general.stability_opt_in_list e general.sanitization.url.sensitive_query_parameters/development em favor de general.sanitization.url.sensitive_query_parameters. (#19561)
  • Preterir otel.instrumentation.graphql.add-operation-name-to-span-name.enabled em favor de otel.instrumentation.graphql.operation-name-in-span-name.enabled e otel.instrumentation.runtime-telemetry.package-emitter.enabled/jars-per-second em favor de otel.instrumentation.runtime-telemetry.experimental.package-emitter.enabled/jars-per-second. (#19573)
  • Descontinuar métodos de construtor de cabeçalho de solicitação e resposta capturados em instrumentações de biblioteca HTTP em favor de requestHeaders(IncludeExclude) e responseHeaders(IncludeExclude) APIs baseados em seletores. (#19598, #19601, #19602, #19603, #19604, #19606, #19607, #19608)
  • Preterir otel.instrumentation.micrometer.histogram-gauges.enabled em favor de otel.instrumentation.micrometer.experimental.histogram-gauges.enabled. (#19613)

🌟 Nova instrumentação javaagent

  • Adicionar instrumentação do Apache Commons Pool 2 para métricas de pool de objetos. (#19091)
  • Adicionar instrumentação javaagent Apache HBase client 1.0. (#19243)
  • Adicionar métricas de pool de conexão Redisson para 3.26+. (#19392)
  • Adicionar suporte para métricas da incubadora OpenTelemetry API 1.65 no agente Java. (#19456)
  • Adicionar instrumentação javaagent Tomcat DBCP 8.0 para métricas de pool de banco de dados. (#19472)

📈 Melhorias

  • Adicione metadados de pacote OSGi opcionais para instrumentação selecionada, artefatos de extensão API e SDK para que possam ser consumidos diretamente em tempos de execução OSGi. (#18995)
  • Adicione medidores cassandra.compaction.progress.completed e cassandra.compaction.progress.size para compactações Cassandra em voo. (#19290)
  • Visualize as próximas convenções semânticas de mensagens 3.0 por trás do otel.semconv-stability.opt-in=messaging em AWS SQS e Lambda, JMS, Kafka, NATS, Pulsar, RabbitMQ, RocketMQ, Spring Integration e instrumentações de mensagens Spring. (#19347, #19348, #19349, #19350, #19351, #19353, #19354, #19355, #19356, #19476, #19477, #19478, #19479, #19480, #19481, #19482, #19486, #19487, #19499, #19500, #19504, #19505, #19507, #19508, #19535, #19544, #19565, #19567, #19639, #19640)
  • De acordo com as próximas convenções semânticas 3.0 RPC por trás de otel.semconv-stability.opt-in=rpc, as solicitações Dubbo para serviços desconhecidos emitem intervalos de servidor mesmo quando a decodificação falha antes de DubboProtocol.getInvoker() e registram o método original em rpc.method_original. (#16668)
  • Os dados de contexto Log4j agora incluem entradas baggage.* mesmo quando não há intervalo atual. (#19378)
  • Quando otel.instrumentation.common.v3-preview=true, a ponte Micrômetro não exporta mais medidores .max para Timer e DistributionSummary. (#19397)
  • Adicione o seletor IncludeExclude API a opentelemetry-instrumentation-api para combinar strings com padrões glob incluídos e excluídos. (#19451)
  • Emite atributos de consistência, coordenador, tamanho de página, idempotência e execução especulativa do driver Cassandra 3. (#19629)
  • Expanda as próximas convenções semânticas do banco de dados 3.0 por trás do otel.semconv-stability.opt-in=database, incluindo nomes de operação, namespaces, nomes de coleção, parâmetros de operação, telemetria de lote e tipos de erro para Couchbase, Redis clients, Elasticsearch, R2DBC, JDBC, ClickHouse, MongoDB e HBase. (#19616, #19623, #19664, #19665, #19668, #19670, #19704, #19705, #19706, #19707, #19708)
  • Adicione otel.instrumentation.influxdb.query-sanitization.enabled para controlar a sanitização de consultas do InfluxDB, tendo precedência sobre otel.instrumentation.common.db.query-sanitization.enabled. (#19703)

🛠️ Correções de bugs

  • Use nomes de métricas estáveis derivados de banco de dados para pools de conexões sem nome Alibaba Druid, c3p0, Tomcat JDBC, HikariCP e Vibur. (#19108, #19159, #19173, #19470, #19471)
  • As métricas Apache DBCP 2.0 agora são registradas quando o pool é iniciado mesmo sem registro JMX e cancelam o registro no close(). (#19160)
  • Ignore as ferramentas JDK de instrumentação iniciadas a partir de $JAVA_HOME/bin, a menos que otel.javaagent.enabled=true esteja definido. (#19203)
  • Correção das métricas Jetty JMX para emitir jetty.select.count em vez de jetty.io.select.count para contagens de chamadas selecionadas. (#19249)
  • Correção do pool de conexões Redisson que permite vazamento quando um comando assíncrono em espera é cancelado. (#19340)
  • Corrigida a detecção de rota do Spring WebFlux para que os spans do controlador mantenham um nome de rota legível no JDK 21+. (#19365)
  • Normalize os valores IPv6 JDBC server.address para endereços simples em vez de literais entre colchetes. (#19366)
  • Corrija a instrumentação do Lettuce 5.1 com indy injetando io.lettuce.core.protocol.OtelCommandArgsUtil como uma classe auxiliar. (#19373)
  • Adicione um tempo limite de 2 segundos à detecção de recursos do host.id para que os comandos de pesquisa lenta não bloqueiem mais a inicialização do SDK. (#19377)
  • Corrija a instrumentação do Azure-core para que os aplicativos que não usam o OpenTelemetry API ainda obtenham o rastreamento do Azure SDK. (#19387)
  • A análise de URL JDBC MySQL agora lida com hosts, portas e parâmetros de consulta em formatos de URL não padrão de forma mais confiável. (#19394)
  • Pré-carregue o MethodHandle$1 durante a inicialização do agente para evitar o ClassCircularityError no JDK 17, que pode interromper a vinculação do site de chamada invokedynamic. (#19398)
  • Edite dados confidenciais de parâmetros de consulta AWS SigV4, gateway AWS Lambda API e URLs REST Elasticsearch, credenciais de URL incorporadas e linhas de comando de processo. (#19422, #19424, #19425, #19514)
  • Corrija a nomenclatura personalizada do medidor Micrômetro e evite que as descrições das métricas vazem entre instrumentos ou registros relacionados. (#19463, #19466, #19467)
  • Corrigido activemq.destination.temp.utilization para converter valores % em uma fração sem unidade. (#19512)
  • Corrigido jetty.thread.queue.size para usar a unidade {job} em vez de {thread}. (#19513)
  • Correção dos pontos de extremidade métricos do atuador Spring Boot quando o registro do micrômetro OpenTelemetry faz parte de um registro composto ou não pode retornar valores métricos. (#19515, #19541)
  • Endereços IPv6 em cabeçalhos Host agora são analisados corretamente, incluindo portas entre colchetes. (#19540)
  • Correção dos intervalos de recebimento do Pulsar sob convenções semânticas de mensagens herdadas para avaliar a supressão em relação ao contexto do produtor extraído quando a telemetria de recebimento está desabilitada. (#19592)
  • Preservar o tipo ClusterInvoker do Dubbo ao capturar o endereço cadastral do consumidor. (#19568)
  • Pare de avisar sobre configurações de captura baseadas em seletor obsoletas quando a substituição .included ou .excluded correspondente também estiver configurada. (#19571)
  • Preservar a caixa original do nome do banco de dados configurado no legado db.name e no db.namespace estável para extensões R2DBC. (#19615)
  • Capture spans para consultas preparadas explícitas no Vert.x SQL client para que a execução do PreparedStatement.query() mantenha o db.system e as opções de conexão corretas. (#19619)
  • Corrigida a higienização do Cassandra 3 SimpleStatement para que os valores vinculados sejam detectados e ocultos no db.statement. (#19620)
  • Emitir eventos de exceção e logs para operações JDBC commit e rollback com falha. (#19621)
  • Limpe o estado de telemetria de lote JDBC após executeBatch() e executeLargeBatch() para que os intervalos de lote subsequentes não relatem mais conteúdos de lote obsoletos. (#19622)
  • Mantenha server.address e server.port para operações com falha do Cassandra 3, extraindo o coordenador de CoordinatorException. (#19627)
  • O texto da consulta SQL agora é limpo com db.system.name, para que os identificadores entre aspas permaneçam intactos para bancos de dados que os tratam como identificadores. (#19632)
  • Corrija a instrumentação do AWS Lambda RequestHandler para que os métodos handleRequest que retornam void sejam tratados corretamente. (#19714)
