opentelemetry-instrumentação java v2.28.0

Esta versão é direcionada ao OpenTelemetry SDK 1.62.0.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Removido o obsoleto interno ClassInjector/ProxyInjectionBuilder API usado pelo antigo caminho ExperimentalInstrumentationModule.injectClasses(ClassInjector); use ExperimentalInstrumentationModule.exposedClassNames() em vez disso. (#18112)
  • Removido os métodos API não estáveis anteriormente obsoletos e os aliases das bibliotecas opentelemetry-runtime-telemetry-java8 e opentelemetry-runtime-telemetry-java17 obsoletos. (#18136)
  • Removida a configuração do construtor de biblioteca captureEventName anteriormente obsoleta de logback-appender-1.0 e log4j-appender-2.17 OpenTelemetryAppender e as propriedades javaagent otel.instrumentation.{logback-appender,log4j-appender,jboss-logmanager}.experimental.capture-event-name correspondentes. Use a chave otel.event.name em MDC/dados de contexto/pares de valores-chave/marcadores Logstash/argumentos estruturados. (#18223)
  • Removidas propriedades de configuração experimental anteriormente obsoletas otel.instrumentation.http.client.experimental.redact-query-parameters e otel.instrumentation.common.experimental.db-sqlcommenter.enabled; use otel.instrumentation.sanitization.url.experimental.sensitive-query-parameters e otel.instrumentation.common.db.experimental.sqlcommenter.enabled. (#18229)
  • Removida a propriedade obsoleta otel.instrumentation.servlet.experimental.add-trace-id-request-attribute; use otel.instrumentation.servlet.experimental.trace-id-request-attribute.enabled em vez disso. (#18237)
  • Remodelou o auxiliar ktor Experimental de uma classe com companion object para um object de nível superior. Os chamadores de origem Kotlin (Experimental.emitExperimentalTelemetry(...)) não são afetados, mas os consumidores pré-compilados devem ser recompilados com base no novo artefato. (#18343)

🚫 Depreciações

  • Preterir otel.instrumentation.jaxws-cxf-3.0.enabled em favor de otel.instrumentation.jaxws-2.0-cxf-3.0.enabled e otel.instrumentation.jaxws-metro-2.2.enabled em favor de otel.instrumentation.jaxws-2.0-metro-2.2.enabled. (#18184)

🌟 Nova instrumentação javaagent

  • Adicione instrumentação Apache Thrift 0.13 para RPC client e extensões e métricas de servidor. (#18405)

🌟 Nova instrumentação de biblioteca

  • Adicionar instrumentação da biblioteca Apache Thrift 0.13 para RPC client e extensões e métricas de servidor. (#18405)

📈 Melhorias

  • A instrumentação javaagent Couchbase 3.1 agora emite o nome de escopo de instrumentação mais convencional io.opentelemetry.couchbase-3.1 em vez de io.opentelemetry.javaagent.couchbase-3.1 quando otel.instrumentation.common.v3-preview está habilitado. (#18426)
  • As solicitações de recursos Wicket agora usam o nome da classe de referência de recurso no nome do intervalo do servidor quando otel.instrumentation.common.v3-preview está ativado. (#18312, #18775)
  • Decida se as classes auxiliares javaagent serão injetadas no carregador de classes do aplicativo ou isoladas com base nas classes de aconselhamento usadas por uma instrumentação. (#17815)
  • Melhore a detecção de ID de contêiner cgroup v2 para Podman, suportando layouts mountinfo adicionais e avisando quando vários IDs de candidatos são encontrados. (#18272)

🛠️ Correções de bugs

  • Corrigido o rastreamento de rota do servidor Pekko HTTP e Tapir para que os nomes de intervalo do servidor e http.route preservem a rota correspondente mais específica através de diretivas aninhadas, exceções e tempos limite; isso pode alterar os nomes dos intervalos e os valores http.route das rotas afetadas. (#16390)
  • Correção da perda de contexto na instrumentação HTTP Finagle na conversão de solicitação Netty para Finagle e nos limites assíncronos twitter-util Future/Promise. (#17867)
  • Correção da fixação de thread virtual causada pela limpeza de entrada obsoleta de mapa fraco em execução em threads virtuais; a limpeza agora é executada a partir do thread em segundo plano. (#18113)
  • Evite vincular intervalos de consumo em lote ao intervalo de consumo ambiente quando registros ou mensagens não tiverem cabeçalhos de propagação. (#18154)
  • Corrigido resetOnEachOperator() para Reactor 3.1 para que também remova o gancho do agendador quando a instrumentação estiver desabilitada. (#18258)
  • Terminar intervalos quando as assinaturas RxJava 1.0 forem lançadas de forma síncrona. (#18265)
  • Corrigida a detecção automática da versão do serviço Spring Boot para que META-INF/build-info.properties seja lido na raiz do jar em vez de BOOT-INF/classes/. (#18292)
  • Limpe o Netty VirtualField após finalizar uma resposta na instrumentação do servidor Netty 3.8. (#18358)
  • Corrigido JarDetails para fechar identificadores JarFile durante a leitura de arquivos e jars incorporados, evitando vazamentos de recursos durante a coleta de telemetria em tempo de execução. (#18385)
  • Correção de um NullPointerException ao converter um contexto de agente sem um contexto de aplicativo associado para um contexto de aplicativo. (#18444)
  • Corrija a instrumentação do servidor Ktor para evitar vazamentos de contexto OpenTelemetry causados pela restauração incompleta do contexto da rotina. (#18456)
  • Corrija os atributos http.route do sub-roteador Vert.x acrescentando o ponto de montagem ao caminho de rota relativo; isso pode alterar os nomes dos intervalos do servidor e os valores http.route para subrotas montadas. (#18462)
  • Corrija a inicialização das métricas oshi e os relatórios de memória RSS com oshi 7.0.0. (#18478)
  • Correção da instrumentação Play MVC e Play WS em aplicativos Play 3.x. (#18624)
  • Registre um intervalo de recebimento de erro quando um consumidor Kafka empacotado poll() falhar. (#18625)
  • Corrija a limpeza do mapa fraco durante a inicialização do agente iniciando o WeakConcurrentMapCleaner antes da instalação do Byte Buddy. (#18628)
  • Corrija a instrumentação indy para que funcione com o gerenciador de segurança sem falhas recursivas de bootstrap. (#18634)
  • Evite um impasse em caches fracos quando entradas obsoletas forem eliminadas durante computeIfAbsent. (#18635)
  • Os personalizadores de configuração declarativos agora lidam com listas de processadores e detectores ausentes sem lançar NullPointerException durante a inicialização. (#18641)
  • Correção de uma corrida que poderia impedir que os intervalos do servidor HTTP terminassem corretamente na instrumentação Netty 3.8 e 4.0. (#18645)
  • Evite NumberFormatException quando uma porta URL JDBC for nula. (#18708)
  • Correção da execução de tarefas Vert.x TaskQueue e OrderedExecutorFactory para que o contexto de extensão se propague para executáveis na fila. (#18709)
  • Limite o comprimento do texto de consulta em lote Redisson para evitar valores db.statement superdimensionados para lotes grandes. (#18744)
  • Correção da limpeza de consulta SQL para que as cláusulas de senha nas instruções administrativas do SAP HANA sejam editadas sem editar os identificadores password. (#18754)
