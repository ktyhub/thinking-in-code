opentelemetry-instrumentação java v2.32.0

Esta versão é direcionada ao OpenTelemetry SDK 1.66.0.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Remova a constante HostIdResource.REGISTRY_QUERY obsoleta. (#19778)
  • O SPI ExperimentalJmxMetricHandler agora requer implementações para fornecer getMetricNames(). (#19781)
  • Adicione o método isRequestStreaming(REQUEST) necessário ao GenAiAttributesGetter. (#19879)
  • O seletor experimental java.common.messaging.headers/development YAML não configura mais captura de cabeçalho. Use java.common.messaging.headers em vez disso. (#20260)

🚫 Depreciações

  • Descontinuar otel.jmx.target.system em favor de otel.jmx.metrics.experimental.included. (#19783)
  • Descontinuar otel.instrumentation.elasticsearch.capture-search-query. Ele será removido em 3.0, quando os corpos das consultas de pesquisa forem sempre capturados. Não há substituto. (#19675)
  • Descontinuar otel.instrumentation.opensearch.capture-search-query. Ele será removido em 3.0, quando os corpos das consultas de pesquisa forem sempre capturados. Não há substituto. A higienização permanece habilitada por padrão e configurável com otel.instrumentation.opensearch.query-sanitization.enabled. (#19837)
  • Descontinuar otel.jmx.enabled em favor de otel.instrumentation.jmx.enabled para alinhar com outras propriedades de ativação de instrumentação. (#19945)
  • Descontinuar a reescrita automática de chamadas VirtualField.find(Class, Class) em conselhos de javaagent embutidos. Em vez disso, procure VirtualField uma vez e armazene-o no campo static final de uma classe auxiliar. O próprio método find permanece suportado. (#19980)
  • Descontinuar a instrumentação da biblioteca REST Elasticsearch. Use o suporte nativo OpenTelemetry do Elasticsearch Java API Client ou o agente Java para uso direto do RestClient. A instrumentação do agente Java não é afetada. (#19995)
  • Preterir otel.instrumentation.messaging.experimental.receive-telemetry.enabled em favor de otel.instrumentation.common.messaging.experimental.receive-telemetry.enabled. Para cabeçalhos, substitua otel.instrumentation.messaging.experimental.headers.included e .excluded por otel.instrumentation.common.messaging.headers.included e .excluded. Também descontinuar otel.instrumentation.messaging.experimental.capture-headers em favor de otel.instrumentation.common.messaging.headers.included. Os seletores estáveis ​​têm precedência por folha. (#20060, #20260)
  • Descontinuar as propriedades .included/.excluded em otel.instrumentation.log4j-appender.experimental.map-message-attributes, otel.instrumentation.logback-appender.experimental.key-value-pair-attributes, otel.instrumentation.logback-appender.experimental.logstash-marker-attributes e otel.instrumentation.logback-appender.experimental.logstash-structured-argument-attributes em favor do otel.instrumentation.common.logging.structured-attributes.included/.excluded estável e unificado. (#20066)
  • Descontinuar otel.instrumentation.couchbase.experimental-span-attributes em favor de otel.instrumentation.couchbase.emit-experimental-telemetry, um nome mais amplo para atributos experimentais e extensões internas do Couchbase client subjacente. (#20117)
  • Descontinuar otel.traces.sampler=linksbased_parentbased_always_on sem substituição e rule_based_routing declarativo em favor do amostrador composto/desenvolvimento da incubadora SDK rule_based, cuja configuração e comportamento de correspondência diferem. (#20249)
  • Promova o controlador e visualize a configuração de telemetria para as propriedades estáveis otel.instrumentation.common.controller-telemetry.enabled e otel.instrumentation.common.view-telemetry.enabled, descontinuando otel.instrumentation.common.experimental.controller-telemetry.enabled e otel.instrumentation.common.experimental.view-telemetry.enabled. (#20258)
  • Promova a configuração de supressão de extensão do agente Java para a propriedade estável otel.instrumentation.common.span-suppression-strategy, descontinuando otel.instrumentation.experimental.span-suppression-strategy. (#20259)
  • Descontinuar otel.instrumentation.oshi.experimental-metrics.enabled, ProcessMetrics e seus métodos registerObservers(...) em favor de jvm.memory.used e jvm.cpu.time. (#20323)
  • Descontinuar SystemMetrics.registerObservers(Meter) na instrumentação da biblioteca OSHI em favor de SystemMetrics.registerObservers(OpenTelemetry). (#20263)
  • Na configuração declarativa YAML, descontinuar os seletores pontilhados nas listas distribution.javaagent.instrumentation.enabled e .disabled. Use reactor_3_1 em vez de reactor_3.1. Nomes de propriedades planas, como otel.instrumentation.reactor-3.1.enabled, permanecem inalterados. (#20326)

🌟 Nova instrumentação javaagent

  • Adicionar métricas de conjunto de conexões de banco de dados Redisson para versões 2.3.0 a 3.25. (#19152, #19634)
  • Adicione instrumentação de agente Java para comunicação remota Pekko para que o contexto de rastreamento se propague entre chamadas remotas. (#19823)

📈 Melhorias

  • Expandir as futuras convenções semânticas do banco de dados 3.0 por trás do otel.semconv-stability.opt-in=database, incluindo destinos de servidor configurados e nomes de span, validação de endpoint, atributos de peer de rede, namespaces Redis, nomes de operação, tipos de erro, texto de consulta e nomes de métricas de pool de conexão e identidade de banco de dados para Cassandra, ClickHouse, Couchbase, Elasticsearch, Geode, HBase, JDBC, Redis clients, MongoDB, OpenSearch, R2DBC, Spymemcached e Vert.x. (#19728, #19747, #19749, #19753, #19757, #19795, #19830, #19831, #19832, #19834, #19838, #19839, #19844, #19845, #19846, #19848, #19850, #19864, #19868, #19872, #19877, #19883, #19901, #19902, #19903, #19904, #19981, #19983, #19986, #19988, #20008, #20011, #20015, #20017, #20041, #20065, #20068, #20070, #20071, #20072, #20073, #20074, #20075, #20076, #20077, #20078, #20080, #20082, #20084, #20086, #20089, #20105)
  • Expandir as futuras convenções semânticas de mensagens 3.0 por trás do otel.semconv-stability.opt-in=messaging, incluindo spans baseados em operação, client e métricas de processo, criação e propagação de lote por mensagem, carimbos de data/hora consistentes, nomes de assinatura duráveis e supressão de processamento duplicado para Camel, Kafka Connect, JMS, SQS e RocketMQ. (#19483, #19485, #19503, #19517, #19915, #20045, #20067, #20144)
  • As extensões e métricas do Kafka agora incluem messaging.kafka.cluster.id assim que os metadados do cluster são resolvidos. (#18978)
  • Adicionar atributos de banco de dados SQL aos intervalos de dados RDS API ExecuteStatement e BatchExecuteStatement do AWS SDK v2. (#19259)
  • Adicione logs WARNING para locais de extensão inválidos ou vazios e carregamentos de JAR de extensão com falha, além de logs FINE para JARs de extensão carregados com sucesso. (#19584)
  • A biblioteca de métricas JMX agora inclui o alvo experimental de métricas do corretor Kafka. (#19722)
  • Atualize as descrições de kafka.connect.connector.status e kafka.connect.task.status para omitir os valores de estado suportados listados. (#19724)
  • Os intervalos do banco de dados Geode client agora incluem server.address e server.port quando o pool da região tem exatamente um servidor configurado. (#19748)
  • Adicionar suporte de log de exceções para banco de dados HBase clients, SofaRPC clients e servidores e GWT RPC com otel.semconv.exception.signal.preview=logs. (#19750, #20253, #20254)
  • Adicione atributos server.address e server.port aos intervalos de banco de dados Couchbase. (#19758)
  • Adicione filtragem de nome de métrica para métricas JMX com otel.jmx.metrics.included e otel.jmx.metrics.excluded ou JmxTelemetryBuilder.setMetrics(IncludeExclude) na biblioteca. (#19782)
  • Os spans RabbitMQ agora incluem messaging.rabbitmq.vhost.name e messaging.rabbitmq.cluster.name quando otel.instrumentation.rabbitmq.experimental-span-attributes=true. (#19822)
  • As mensagens de criação de métricas JMX agora são registradas em FINE em vez de INFO, reduzindo o ruído de log padrão. (#19825)
  • Os intervalos do servidor HTTP Akka agora incluem o endereço de ponto remoto nos atributos de endereço de ponto de rede. (#19840)
  • Os spans do servidor HTTP Pekko agora incluem client.address do peer de soquete para solicitações HTTP/1.1 e HTTP/2. (#19841)
  • Adicione o atributo network.protocol.version às métricas de duração da solicitação Spring WebFlux 5.0 client. (#19842)
  • Os spans Ratpack HTTP client agora incluem o atributo network.protocol.version. (#19843)
  • Adicionar otel.instrumentation.opensearch.query-sanitization.enabled (padrão true) para controlar se os corpos das consultas de pesquisa capturadas são higienizados; configure-o para false para capturá-los literalmente. (#19869)
  • Os spans GenAI agora incluem o atributo gen_ai.request.stream quando a solicitação usa streaming. (#19879)
  • A instrumentação OpenAI Java 1.1 agora relata contagens de tokens de entrada em cache como gen_ai.usage.cache_read.input_tokens e contagens de tokens de saída de raciocínio como gen_ai.usage.reasoning.output_tokens quando detalhes de uso estão disponíveis. (#19906)
  • Estenda a instrumentação do agente Couchbase Java para suportar SDK 3.0.x. (#19996)
  • Adicione o atributo span aws.bedrock.guardrail.id às solicitações do AWS Bedrock Runtime quando um identificador de proteção for configurado. (#20040)
  • Faça com que a detecção de recursos host.id seja ativada para o agente Java com otel.resource.providers.host-id.enabled=true. (#20099)
  • Adicione URLs de esquema de convenções semânticas com reconhecimento de modo a escopos de banco de dados, mensagens e telemetria RPC. (#20127)
  • Adicione o URL do esquema de convenções semânticas às métricas JVM de tempo de execução cobertas pelo esquema. (#20255)
  • Os intervalos de operação GraphQL agora usam o URL do esquema OpenTelemetry das convenções semânticas v1.44.0. (#20262)
  • Adicione o URL do esquema de convenções semânticas às métricas do sistema OSHI. (#20263)

🛠️ Correções de bugs

  • Os spans de alface 5.1 client para falhas de comando Redis agora têm status de erro. (#19075)
  • Evite bloqueios de inicialização do javaagent causados por inicialização lenta de armazenamento de contexto sob bloqueios do carregador de classe. (#19265)
  • Corrigir nomes de intervalo de liquidação NATS JetStream de alta cardinalidade. Use $JS.ACK publish sob convenções semânticas legadas. (#19396)
  • Correção da propagação de contexto para métodos Kotlin @WithSpan delegados posteriormente para que seus intervalos mantenham o contexto do chamador correto. (#19446)
  • Corrigido envios assíncronos do Camel para que os escopos de contexto fechem no thread que iniciou o envio. (#19503)
  • Correção do rastreamento Vert.x HTTP client quando uma solicitação é liberada com sendHead() e posteriormente concluída com end(), para que o intervalo do servidor seja parentado do intervalo client exportado. (#19547)
  • Lidar com cadeias de causa de exceção cyclic sem interromper a extração de erros em instrumentações ou análise de regras JMX. (#19625)
  • Sanitize os corpos de consulta de pesquisa do agente REST Java Elasticsearch capturados por padrão, substituindo valores literais por ? enquanto preserva a estrutura da consulta. Desative a higienização com otel.instrumentation.elasticsearch.query-sanitization.enabled=false. (#19675)
  • Evite instrumentação duplicada do ouvinte Pulsar e suprima intervalos de recebimento duplicados durante entregas aninhadas, preservando o contexto pai para processamento de intervalos. (#19699, #20137)
  • Solicitações em pipeline do Apache HttpAsyncClient agora produzem spans client. (#19710)
  • As solicitações do servidor Async Thrift após uma solicitação com falha na mesma conexão não são mais relatadas incorretamente como erros. (#19712)
  • Suprima métricas duplicadas do Apache Commons Pool para pools que apoiam um Apache DBCP BasicDataSource quando ambas as instrumentações estão habilitadas. (#19721)
  • Corrigido o registro de depuração do starter Spring Boot quando otel.spring-starter.debug=true. (#19725, #20034)
  • Corrija intervalos de processamento e métricas duplicados no Spring Rabbit, RabbitMQ e Spring Integration, preservando a telemetria para consumidores registrados separadamente e intervalos de manipuladores corretamente parentados. (#19732, #20138, #20200)
  • As métricas do pool Oracle UCP agora usam um nome derivado de JDBC em vez do nome UCP gerado, consolidando pools conectados ao mesmo banco de dados sob um valor pool.name consistente. (#19745)
  • Preencha nomes de comando Redis para extensões client ao usar Lettuce 6.0.0–6.0.2. (#19763)
  • Correção do manuseio do @SpanAttribute para que valores genéricos e matrizes sejam registrados corretamente como atributos de span. (#19785)
  • Evite NullPointerExceptions ao encerrar solicitações Jedis parcialmente inicializadas ou quando o JSF não puder derivar um nome de extensão do servidor. (#19805)
  • Corrija a instrumentação do carregador de classes para que o javaagent não injete mais seu stub java.lang.ClassLoader reescrito como auxiliar. (#19811)
  • As solicitações do servidor Pekko HTTP/2 agora são rastreadas. (#19817)
  • Lidar com índices de escolha negativos em conclusões de chat de streaming OpenAI. (#19827)
  • As solicitações HTTP Pekko rejeitadas durante a análise agora produzem intervalos de servidor com seu status de resposta e cabeçalhos de resposta personalizados. (#19829)
  • Os intervalos de conclusão de bate-papo OpenAI agora usam o tipo de intervalo CLIENT. (#19858)
  • Correção de intervalos de consumo de mensagens RocketMQ ausentes para uma sobrecarga adicional do construtor ConsumeService. (#19860)
  • Correção da propagação de contexto para tarefas em lote do Pekko para que os intervalos criados em futuros agendados mantenham seu pai correto. (#19862)
  • Limite os corpos de consulta OpenSearch capturados a 32.768 caracteres, correspondendo ao limite de captura de consulta Elasticsearch. (#19870)
  • A captura do corpo da consulta OpenSearch agora usa o provedor JSON configurado, preservando as configurações de serialização específicas do mapeador. (#19875)
  • A instrumentação do servidor Thrift ignora campos repetidos de propagação de contexto após iniciar o intervalo de solicitação. (#19895)
  • Correção de uma corrida na captura da versão do protocolo Ratpack para que os spans registrem a versão correta do protocolo. (#19911)
  • A instrumentação do AWS Lambda agora extrai o cabeçalho de rastreamento do X-Ray de Context.getXrayTraceId() para continuar o rastreamento de entrada. (#19920)
  • Corrigir um vazamento de escopo de contexto no processamento de solicitações do servidor Thrift. (#19925)
  • Permitir que o agente Java processe a classe org.h2.command.dml.Update$$Lambda do H2. (#19993)
  • O agente Java agora inicia quando seu JAR já está no caminho de classe de autoinicialização sem anexar o JAR à procura de autoinicialização novamente. (#20001)
  • O JDBC OpenTelemetryDriver agora respeita otel.instrumentation.jdbc.query-sanitization.enabled, portanto, a limpeza de consulta específica do JDBC pode substituir a configuração comum. (#20020)
  • Corrija durações imprecisas para intervalos de interceptadores produtores e consumidores Kafka, encerrando-os imediatamente, uma vez que os interceptores não podem medir o tempo de envio ou pesquisa do corretor. (#20044)
  • Os intervalos de consulta Vert.x SQL client 5 agora relatam db.name, server.address e server.port para conexões configuradas com fornecedores connectingTo. (#20050)
  • Manter o agente Java e os personalizadores de configuração declarativa Spring Boot funcionando com OpenTelemetry SDK 1.66.0. (#20109)
  • Impedir que o truncamento de bancos de dados higienizados e consultas de pesquisa dividam pares substitutos Unicode. (#20123)
  • Evite intervalos de processamento duplicados do Kafka no Kafka Connect, Kafka Streams, Reactor Kafka e Vert.x, incluindo transferências assíncronas, sem suprimir lotes não relacionados. (#20139, #20142, #20143)
  • Evite intervalos de processamento JMS duplicados nas camadas de ouvinte JMS, Spring JMS, Camel e SJMS. (#20140)
  • A instrumentação do servidor Apache ShenYu não é mais lançada quando os metadados da rota são nulos, permitindo que o processamento da solicitação continue sem um valor de rota. (#20148)
  • Registrar exceções tratadas pelos manipuladores de erros do Spring Rabbit no intervalo de processamento de mensagens. (#20178)
  • Correção da detecção do sistema de banco de dados para pools Vert.x SQL client encapsulados pelo Vert.x 5.2. (#20191)
  • A instrumentação do Reactor agora propaga valores de contexto por meio de retornos de chamada do editor orientados externamente, mesmo quando o contexto capturado não tem extensão válida. (#20192)
  • Os intervalos de processamento do Spring Cloud AWS SQS agora terminam quando os ouvintes assíncronos são concluídos, registrando suas eventuais falhas ou status de cancelamento. (#20193)
  • Os intervalos de processamento SQS do AWS SDK v1 agora terminam com falhas de retorno de chamada e restauram o contexto anterior quando os manipuladores forEach ou forEachRemaining são lançados. (#20194)
  • Evite intervalos de processamento SQS duplicados quando manipuladores aninhados do AWS Lambda processam o mesmo evento. (#20195)
  • Os spans do servidor Spring MVC para endpoints do atuador Spring Boot agora incluem o atributo http.route. (#20216)
  • Correção de dicas de reflexão ausentes para campos interceptadores de ouvinte Spring Kafka e classes JWT portadoras OAuth em imagens nativas GraalVM. (#20332)
