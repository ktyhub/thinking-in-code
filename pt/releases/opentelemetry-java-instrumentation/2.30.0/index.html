opentelemetry-instrumentação java v2.30.0

Esta versão é direcionada ao OpenTelemetry SDK 1.64.0.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Remova ExperimentalInstrumentationModule#getModuleGroup(). Módulos Invokedynamic integrados agora compartilham um único InstrumentationModuleClassLoader e cada extensão é isolada por si só. (#18859)
  • Remova o InstrumentationModule.isIndyModule() obsoleto; se um módulo usa invocador dinâmico agora é determinado pelo agente em vez de declarado por módulo. (#19140)
  • Remova APIs obsoletos relacionados a consultas de SqlClientAttributesGetter, CassandraRequest e Experimental. (#19165)
  • Remova os APIs de captura de atributos Enduser* obsoletos da biblioteca Spring Security 6.0; use as substituições User*. (#19168)

🚫 Depreciações

  • Descontinuar apenas o bean de compatibilidade inicial Spring Boot ConfigProperties usado com configuração declarativa experimental, em favor do novo bean ConfigProvider; ele será removido em 3.0. O bean ConfigProperties permanece suportado para configuração não declarativa. (#19175)
  • Descontinuar DeclarativeConfigPropertiesBridge e DeclarativeConfigPropertiesBridgeBuilder. Use DeclarativeConfigProperties diretamente ou DeclarativeConfigBridge. Será removido em 3.0. (#19202)
  • Preterir ConfigPropertiesBackedConfigProvider em favor de DeclarativeConfigBridge. Ele será removido em 2.31.0. (#19220)

🌟 Nova instrumentação javaagent

  • Adicionar instrumentação Javaagent para HBase client 1.4. (#19087)

🌟 Nova instrumentação de biblioteca

  • Adicionar instrumentação de biblioteca (ThriftTelemetry) para o servidor assíncrono Apache Thrift 0.13. (#19062)

📈 Melhorias

  • Adicionar rastreamento de servidor assíncrono à instrumentação javaagent Apache Thrift 0.13; manipuladores de servidor assíncrono não eram instrumentados anteriormente. (#18994)
  • Suporte database= como um alias para databaseName ao extrair db.name de URLs MSSQL JDBC. (#19029)
  • Adicionar suporte à operação em lote à opção de convenção semântica de banco de dados estável experimental (otel.semconv-stability.opt-in=database) em instrumentações de banco de dados, incluindo nomes de intervalo de lote, db.operation.batch.size (incluindo lotes vazios) e db.query.summary. (#19034, #19037, #19054, #19055, #19056, #19057, #19143, #19147, #19161, #19162, #19164, #19172, #19189, #19199)
  • Adicionar rastreamento para comandos reativos do Lettuce 4.0, incluindo conclusão e cancelamento excepcionais. (#19071)
  • Adicionar o sistema experimental de metas de métricas Cassandra JMX. (#19080)
  • Adicionar métricas experimentais jvm.thread.virtual.pinned e jvm.thread.virtual.submit_failed baseadas em JFR para threads virtuais Java 19+; habilite com otel.instrumentation.runtime-telemetry.emit-experimental-jfr-metrics=true. (#19092)
  • Capture valores de objetos personalizados passados para PreparedStatement.setObject() em atributos de parâmetros de consulta. (#19093)
  • InstrumentationModule agora expõe injectedClassNames() e exposedClassNames() para instrumentações indy, então os autores de módulos não precisam mais de ExperimentalInstrumentationModule para essas declarações de classe auxiliar. (#19142)
  • Adicionar opções captureTemplate e captureArguments às instrumentações de log log4j, java-util-logging e jboss-logmanager, capturando o modelo de mensagem de log e argumentos como atributos log.body.template/log.body.parameters separados; logback já suportava essas opções (#15423). (#19154)
  • Adicione atributos server.address e server.port aos spans Redisson client. (#19191)
  • Adicionar atributos server.address e server.port aos vãos de alface Redis client. (#19192)
  • Adicione atributos server.address e server.port aos spans Rediscala client. (#19193)
  • Defina server.address em extensões Dubbo client apoiadas por registro para o endereço de registro mais o destino de serviço (registry://host:port/interface:version:group) e deixe server.port não definido, protegido por trás do opt-in rpc semconv estável (otel.semconv-stability.opt-in=rpc); o host e a porta do provedor resolvido são mantidos no semconv padrão. (#17244, #19285)

🛠️ Correções de bugs

  • Correção de um aviso falso de duplicação quando a ponte do logger do aplicativo é instalada várias vezes durante a inicialização. (#19088)
  • Corrija os valores MySQL e MariaDB db.connection_string para que os hosts IPv6 permaneçam entre colchetes em vez de se tornarem ambíguos. (#19078)
  • Corrigir consumidores Pulsar multitópicos para que o recebimento interno em segundo plano não crie mais uma extensão de recebimento extra espúria. (#19095)
  • SpringConfigProperties.getMap() não avalia mais valores de propriedades de mapas como expressões SpEL; propriedades de mapa não especiais agora são analisadas como pares key=value delimitados por vírgula por meio do DefaultConfigProperties do SDK, portanto, configurações como otel.instrumentation.common.peer-service-mapping funcionam sem sintaxe SpEL. (#19113)
  • Corrigida a extração de destino JMS para que um destino ilegível deixe messaging.destination.name indefinido em vez de reportá-lo como unknown. (#19115)
  • Correção das métricas JMX Metric Insight jvm.class.loaded e jvm.class.unloaded para usar instrumentos de contador. (#19141)
