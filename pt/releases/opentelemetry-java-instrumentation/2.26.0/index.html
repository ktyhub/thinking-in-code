opentelemetry-instrumentação java v2.26.0

Esta versão tem como alvo o OpenTelemetry SDK 1.60.1.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles ainda têm qualidade alfa e continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Remover wrappers obsoletos do AWS Lambda v2.2 e sobrecarga de forceFlush(int, TimeUnit) (#16170)
  • Remover métodos HTTP client/servidor obsoletos (#16167)
  • Remover métodos e classes obsoletos de instrumentação de banco de dados (#16164)
  • Remover APIs de mapeamento de serviço de mesmo nível obsoleto (#16165)
  • Tornar classes obsoletas de telemetria de tempo de execução agora internas (#16173)
  • Remover AttributesExtractorUtil (#16152)
  • Remover interface de marcador de SqlClientAttributesGetter (#16205)
  • Mesclar métodos getter de rede/servidor em getters de atributos de banco de dados (#16264, #16268)
  • Renomeie as classes do sanitizador SQL para analisador SQL (#16269)
  • Renomeie pacotes de módulos comuns internos para seguir a nova convenção de nomenclatura (#16284, #16308, #16327, #16341, #16373)

🚫 Depreciações

  • Classes individuais de módulo de telemetria de tempo de execução obsoletas em favor do módulo unificado (#16087)
  • Métodos antigos de parâmetros de consulta do servidor HTTP obsoletos em favor do tratamento de parâmetros de consulta confidenciais (#16097)
  • Métodos getter de atributos RPC antigos obsoletos em favor de novos que suportam convenções semânticas estáveis (#16130)
  • Métodos antigos de instrumentação ClickHouse obsoletos como parte da simplificação (#16206)
  • Métodos R2DBC antigos obsoletos em favor daqueles que suportam db.system.name (#16251)
  • Métodos antigos DbClientAttributesGetter obsoletos; adicionado getErrorType() com implementações (#16276)
  • Métodos antigos de métricas RPC obsoletos em favor daqueles que suportam convenções semânticas estáveis (#16298)
  • Métodos antigos DbClientAttributesGetter obsoletos; adicionado getDbName() para melhor suporte à divisão semconv antiga/estável (#16318)

📈 Melhorias

  • Adicionar endereço de servidor e atributos de porta para Spymemcached (#15242)
  • Adicionar Kafka Connect como um alvo de métricas JMX integrado (#15561)
  • Converter instrumentação Lettuce para usar Instrumenter (#15838)
  • OpenSearch Java client: captura corpos de consulta de pesquisa limpos (#15634)
  • Aplicar convenções semânticas estáveis às métricas Camel JMX (#16088)
  • Adicionar métrica jvm.file_descriptor.limit (#16174)
  • Execute retornos de chamada gRPC client com contexto pai (#16175)
  • Resumo SQL: lidar com instruções EXPLAIN (#16184)
  • Simplifique a instrumentação do InfluxDB (#16207)
  • Atualizar intervalos de histograma para db.client.operation.duration (#16222)
  • Resumo SQL: suporte à sintaxe Oracle dblink (#16230)
  • Adicionar instrumentação para rota do servidor HTTP ZIO (#16232)
  • Remover atributos de rede sob o sinalizador semconv estável do banco de dados (#16257)
  • Suporte Javalin 7 (#16261)
  • gRPC: suporte semconv estável inicial (#16304)
  • Preencher o atributo de recurso os.version (#16311)
  • Camel: não emite intervalos de banco de dados sob semconv estável (#16275)
  • Dubbo: suporte semconv estável (#16352)
  • Atualize a versão OpenTelemetry SDK para 1.60.0 (#16407)
  • Use o novo LogRecordBuilder.setException() estável (#16423)
  • Configure semconv-stability.opt-in com configuração declarativa API (#16443)
  • Suporte otel.event.name (#16220)

🛠️ Correções de bugs

  • O SQL Sanitizer agora trata fragmentos entre aspas duplas como literais de string por padrão (#15582)
  • Limpar exceção registrada quando a solicitação for concluída (#16138)
  • Limpar o estado da conexão do URL após encerrar o período (#16155)
  • Corrigir configuração declarativa do Spring com substituição de variável de ambiente (#15775)
  • Correção do tratamento de erros de pipeline de envio do servidor Ktor (#16192)
  • Anexadores de registro: atributos KeyValue devem ter prioridade sobre MDC (#16239)
  • Crie um novo PekkoRouteHolder para cada solicitação (#16258)
  • Tomcat JMX: ignore threads negativos e limites de sessão (#16355)
  • server.port é necessário em extensões HTTP client (#16388)
  • Correção da instrumentação do servidor Ktor resolvendo endereço de peer (#16392)
  • Correção da exceção de conversão de classe na instrumentação do servlet (#16403)
  • Corrigir corpo de resposta vazio em Jetty HttpClient 9.4.24 – 9.4.43 (#16406)
