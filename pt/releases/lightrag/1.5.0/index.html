LightRAG v1.5.0

Principais melhorias

  • 🎉✨Recurso: LightRAG agora oferece suporte ao processamento multimodal de documentos e pode aproveitar totalmente imagens, tabelas e fórmulas em documentos para responder a consultas. Todos os recursos de processamento multimodal do RagAnything são mesclados no LightRAG; (RagAnything não receberá mais atualizações de recursos principais ou manutenção daqui para frente)
  • ✨🎉Recurso: Atualização completa do pipeline de processamento de documentos, com suporte para usar MinerU e Docling para analisar e extrair conteúdo de arquivo, integrando-se perfeitamente com análise de conteúdo multimodal e extração de relacionamento de entidade.
  • 💡✨Recurso: LightRAG agora apresenta Análise Nativa, permitindo extração de conteúdo de alta qualidade de documentos DOCX. Ele suporta a reconstrução precisa da numeração automática do Word, bem como a extração de imagens, tabelas e fórmulas, proporcionando integração perfeita com análise de conteúdo multimodal e extração de relacionamento entre entidades. O suporte de formato expandido para o Analisador Nativo estará disponível em breve.
  • 💡🧠Recurso: Introduzidas quatro estratégias de agrupamento de texto selecionáveis: Fix, Recursive, Vector e Paragraph. Os parâmetros para cada estratégia de agrupamento podem ser configurados por meio de variáveis ​​de ambiente.
  • 💡🎯Recurso: O pipeline de processamento de arquivos suporta seleção do mecanismo de análise de arquivos e estratégia de agrupamento de texto com base em extensões de arquivo ou por arquivo. Para obter instruções de uso detalhadas, consulte FileProcessingPipeline.md.
  • 🚀⚡Desempenho: Otimizou a lógica de persistência do armazenamento vetorial adiando os cálculos vetoriais até o final de cada lote de processamento de arquivo, permitindo a computação em massa centralizada. Isso reduziu significativamente o número de invocações de modelos vetoriais e aumentou significativamente a velocidade de upsert de todos os bancos de dados vetoriais com suporte para LightRAG.
  • Habilite o suporte à incorporação com reconhecimento de tarefa para modelos assimétricos, incluindo voyage-3, text-embedding-004, embed-multilingual-v3.0 e jina-embeddings-v3.
  • Maior confiabilidade de extração de entidade/relação ao introduzir a saída estruturada LLM JSON; defina ENTITY_EXTRACTION_USE_JSON=true para habilitá-lo.
  • Apresente o ENTITY_TYPE_PROMPT_FILE para capacitar os usuários com orientação aprimorada para reconhecimento e extração de tipo de entidade orientados por LLM.
  • Suporte total aos modelos Amazon e Anthropic no AWS Bedrock API.
  • 🎯✨🎉Recurso: Implementado suporte à configuração LLM específica da função, introduzindo quatro funções distintas: EXTRACT, QUERY, KEYWORDS e VLM, cada uma com configurações LLM independentes. Recomenda-se configurar a função KEYWORDS com um modelo de parâmetros pequenos, sem raciocínio e de alta velocidade para otimizar a latência da consulta; a função EXTRACT com um modelo de parâmetros médios e sem raciocínio para equilibrar precisão e rendimento; e a função QUERY com um modelo de raciocínio de parâmetros grandes para melhorar a qualidade da consulta. Para obter instruções de uso detalhadas, consulte RoleSpecificLLMConfiguration.md.

O que está quebrado

  • 💥Aviso: as atualizações exigem um planejamento cuidadoso para usuários que atualmente utilizam armazenamento gráfico OpenSearch e MongoDB, pois a migração de dados e reinicializações do sistema podem causar interrupções prolongadas no serviço.
  • ⚠️A variável de ambiente ENTITY_TYPES foi descontinuada; Substitua-o por ENTITY_TYPE_PROMPT_FILE antes de lançar esta nova versão.
  • 💔Campo obsoleto removido: QueryParam.model_func excluído de lightrag/base.py
  • Para versões do OpenSearch anteriores ao 3.3.0, atualize o OpenSearch antes de atualizar o LightRAG (consulte https://github.com/HKUDS/LightRAG/pull/2991).
  • ⚠️Mova delete_entity/delete_relation do documento API para o gráfico API
