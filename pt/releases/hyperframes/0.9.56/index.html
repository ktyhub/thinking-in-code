hiperframes v0.9.56

#HiperFrames v0.9.56

Lançado em 16/11/2026.

A visualização do Studio e os servidores locais agora atuam apenas em suas próprias páginas. O CLI mantém seu cache, histórico e restaurações dentro do projeto. A imagem arm64 Lambda envia apenas a versão revisada do ffmpeg, e grandes visualizações são criadas mais rapidamente.

Correções

  • Servidor Studio: Os servidores de arquivos de composição não fornecem mais arquivos de credenciais ou de estado de ferramenta (014326b40, #7889).
  • Studio Server: Lint e probe são executados apenas para solicitações das próprias páginas do Studio (bbac8900e, #7894).
  • Studio Server: Uma restauração de histórico permanece dentro do projeto e usa apenas cópias intactas (478313ba0, #7902).
  • Estúdio: Veja os trabalhos de reprodução para uma prévia de seu servidor tornado opaco (1e542956d, #7815).
  • Studio: O quadro de visualização mantém a origem do sandbox em seu conjunto de host (b650d0d19, #7886).
  • Estúdio: Os decks atuais abrem apenas em seu próprio site, e a visualização lê apenas as mensagens de seu próprio frame (4067efc45, #7877).
  • Core: A ponte de tempo de execução verifica cada mensagem de controle antes de agir sobre ela (97d8f26e7, #7892).
  • CLI: render --docker mantém a restrição de rede de páginas do host dentro do contêiner (5d8605eb8, #7890).
  • CLI: preview --stop interrompe apenas o processo que o sistema relata que contém a porta (ace8a78dc, #7882).
  • CLI: O cache de verificação é salvo apenas como um registro do projeto, nunca através de um arquivo vinculado (7801e3ff3, #7884).
  • CLI: Os IDs de giro do histórico lidos na pasta do projeto são verificados e enviados codificados (6efa6b635, #7883).
  • CLI: Catch-up lista apenas os turnos que o aplicativo adicionou após a transferência (0f23f40f8, #7874).
  • CLI: Um registro de arquivos recebidos em uma pasta no projeto conta para uma renderização (1c159c550, #7900).
  • CLI: O uso de mídia copia apenas os efeitos sonoros de seus nomes de índice agrupados (ed93a1312, #7895).
  • Uso de mídia: Os modelos locais iniciam em uma pasta fora do projeto (756c2c6c1, #7888).
  • Mecanismo: Um navegador em cache é usado somente quando seus arquivos correspondem à compilação fixada (56a2d0c53, #7865).
  • Mecanismo: As previsões de quadros da linha de tempo permanecem dentro dos quadros da renderização (f5a74a567, #7885).
  • Engine: Cada extração de superconjunto funciona em uma pasta própria (a4139e9ea, #7901).
  • Analisadores: A leitura da largura e altura de um andaime de tela leva o mesmo tempo em qualquer entrada (b856a1d63, #7873).
  • Lint: Cenas e efeitos sonoros feitos por agentes permanecem em uma faixa da linha do tempo (98208241e, #7775).
  • Habilidades: Instalações autônomas também executam o CLI por meio de seu inicializador (3fc3050bc, #7879).
  • AWS Lambda: Uma versão envia o ffmpeg arm64 somente quando ele corresponde ao resumo confirmado ao lado de sua compilação (d9488119b, #7872).

Desempenho

  • Principal: Uma versão de visualização lê uma página grande sem copiá-la a cada passagem (082d63683, #7878).
  • Produtor: As verificações de tags de telemetria de compilação e renderização levam tempo de acordo com o tamanho da página (82fdf406c, #7896).

Interno

  • Publicar: Cada publicação npm aguarda a aprovação da publicação npm (a54de748e, #7870).
  • Publicar: Tarballs pré-construídos são publicados a partir de um trabalho que não executa nenhum código do commit de lançamento (af0560c85, #7869).
  • CI: Os fluxos de trabalho de publicação são executados apenas para principal (7bd6b9daf, #7875).
  • CI: Os equipamentos de teste não se parecem mais com chaves HeyGen reais, e o CI rejeita aquelas que o fazem (5dc3b336a, #7876).
