#go-ethereum v1.17.0

<!-- Circuito Eezo-Incrustado (v1.17.0) -->

Este é um lançamento de recurso, com todo o desenvolvimento acumulado dos últimos 3 meses. Veja abaixo os destaques.

Observe que esta versão contém várias correções críticas de segurança, bem como muitas correções de bugs, e é recomendada para todos os usuários. No entanto, se você for cauteloso com as atualizações, também poderá instalar o v1.16.9, que possui apenas as correções críticas de segurança. Especificamente, esta versão corrige CVE-2026-26313, CVE-2026-26314, CVE-2026-26315.

Recomendamos recriar sua chave de nó p2p após instalar esta atualização, o que você pode fazer removendo o arquivo DATADIR/geth/nodekey antes de reiniciar o geth. Observe que isso causará uma alteração no ID do nó p2p, o que pode interromper as configurações de peering estático.

Destaques

Nó de arquivo baseado em caminho com provas

O nó de arquivo baseado em caminho agora pode servir provas (via eth_getProof) para o estado de blocos mais antigos.

Você pode configurar o intervalo de blocos que oferece suporte à prova independentemente da disponibilidade de outros estados de arquivo. Especificamente, você pode usar o sinalizador de linha de comando --history.trienode para definir a quantidade de blocos para os quais os nós da árvore serão rastreados.

Este recurso está desabilitado por padrão. Observe que o histórico de estado não pode ser facilmente recuperado depois de excluído, pois só pode ser gerado pelo processamento de blocos. No entanto, você pode ativar o histórico de trienodos (e/ou histórico de estado) a qualquer momento para transformar um nó completo em um nó de arquivo parcial, mantendo o estado daquele momento em diante.

#32727, #32621, #33551, #32981, #33399, #32913, #33303, #33584, #33329, #33681, #33103, #33098, #33515, #32247

Suporte ao histórico EraE

Geth agora suporta o formato de arquivo EraE, um formato de arquivo para histórico de cadeia pós-mesclagem.

#32157, #33827

Rastreamento OpenTelemetry

O rastreamento OpenTelemetry agora é suportado pelo servidor RPC, incluindo suporte para rastreamento distribuído. Também adicionamos alguns intervalos de rastreamento para processamento de blocos por meio do mecanismo API, ou seja, engine_newPayload.

#33599, #33452, #33780, #33521

Todas as alterações

Geth CLI

  • O subcomando geth version-check foi removido. Este comando verificou o site geth em busca de avisos de vulnerabilidade assinados e informa se atualizações são necessárias (#33498)
  • Agora existe um sinalizador de linha de comando --miner.maxblobs para definir um limite de blobs incluídos em blocos construídos (#33129, #33302)
  • Geth agora suporta perfil contínuo com piroscópio Grafana (#33623)
  • Um bug raro que poderia interromper a produção de blocos no modo geth --dev foi corrigido (#33146)
  • Um novo flag --rpc.rangelimit configura o intervalo máximo de bloqueio para eth_getLogs (#33163)
  • geth --exitwhensynced agora definirá os blocos finalized e safe (#33038)
  • geth --ethstats agora reporta o tempo de processamento do newPayload ao servidor de estatísticas (#33395)
  • Vários problemas menores no processamento de sinalizadores de linha de comando do Geth foram corrigidos (#33379, #33338, #33330, #32999, #33279, #33252)
  • O comando evm blocktest agora pode ler nomes de arquivos do stdin quando nenhum caminho é fornecido (#32824)

Implementação de garfo

  • EIP-8024: SWAPN, DUPN, EXCHANGE compatível com versões anteriores (#33095, #33787, #33614, #33361)
  • Implementamos engine_getBlobsV3 (#33404, #33444)
  • O mecanismo API agora rejeita chamadas com versão de carga errada (#32754, #33322)
  • blsync foi atualizado para Fusaka (#33349, #33272, #33065, #32674)
  • Algum trabalho para a migração de estado para uma árvore binária foi lançado, e isso substitui a implementação da Verkle Tree (#33807, #33739, #33694, #32445, #33461)
  • Algumas semânticas da lista de acesso foram corrigidas ao trabalhar nas listas de acesso em nível de bloco EIP-7928 (#33281, #33637, #33450)

Núcleo

  • A biblioteca cripto/ecies permitiu a extração da chave privada usada para derivação da chave através da observação do tempo de resposta. Recomendamos girar a chave do nó após aplicar esta atualização. (#33669)
  • Quando um bloco ausente é encontrado durante a desindexação tx, Geth irá ignorá-lo e seguir em frente em vez de entrar em um loop infinito. (#33573)
  • Geth agora coleta e exporta opcionalmente métricas sobre o tamanho total do estado (#33254, #33376, #33415)
  • Existe um novo gancho OnStateUpdate, que é chamado após todo o estado de um bloco ter sido confirmado. Isso dá acesso ao conjunto de alterações do bloco. (#33490)
  • Alguns pequenos bugs de rastreamento foram corrigidos (#32919, #33148, #33644, #33214)
  • Vários pequenos problemas no banco de dados do freezer também foram corrigidos (#33747, #33025, #33203, #33344)
  • A operação setHead agora desarma o bloco finalizado, nos casos em que a faixa do bloco revertido se estende antes dele. (#33486)
  • O método SignatureValues do types.Signer agora reporta um erro para tamanhos de assinatura inválidos (#33647)
  • Geth imprime mensagens de log detalhadas para 'blocos lentos' (#33655, #33525, #33442, #32812, #33659, #33532)
  • A configuração do Pebble foi ajustada para melhorar o desempenho (#33697, #33353, #33315)
  • Uma falha rara no indexador de log relacionada ao tratamento de reorganização foi corrigida (#33810)
  • A contabilização do tamanho da diferença de estado interno foi corrigida, então as diferenças de estado agora serão liberadas para o armazenamento em disco com menos frequência (#33505)
  • Como a variante da função hash keccak256 usada pelo Ethereum não tem mais um atalho na biblioteca padrão, vendemos a implementação do keccak de volta ao nosso repositório (#33323)

Biblioteca

  • A biblioteca RLP agora possui um tipo RawList para lidar com listas não decodificadas de uma forma mais conveniente (#33755, #33834, #33840, #33841)
  • O iterador RLP de baixo nível e seus usos foram aprimorados (#33245, #33188, #33820)
  • Clef agora pode assinar transações de blob com provas de células (#32910)
  • Corrigidos alguns bugs na exportação de métricas (#33749, #33748)
  • A biblioteca de carteira de hardware agora suporta Ledger Nano Gen5 e habilita corretamente a assinatura EIP-712 para todas as versões suportadas. (#33297, #33113)
  • SignTextWithPassphrase agora funciona corretamente com todas as carteiras de hardware suportadas (#33138)
  • Alguns pequenos bugs foram corrigidos na implementação do keystore (#33606, #33602, #33090)
  • A função bitutil.XORBytes foi descontinuada em favor do pacote stdlib crypto/subtle (#33331)
  • Um vazamento de memória na luz da cadeia de farol client foi corrigido (#33483)

###RPC

  • eth_getTransactionByHash agora retorna blockTimestamp como parte do objeto de transação (#33709)
  • Os códigos de erro para algumas condições em eth_simulateV1, eth_getLogs, eth_getStorageAt foram aprimorados para melhor atender às especificações RPC de execução (#33007, #33320, #33282)
  • eth_simulateV1 agora seleciona o conjunto correto de pré-compilações para o cabeçalho simulado (#33363)
  • eth_sendTransaction e eth_fillTransaction agora usam como padrão EIP-1559 (#33058)
  • A implementação do GraphQL recebeu algumas correções de bugs para casos em que um item resolvido não foi encontrado. (#33184, #33225)
  • No GraphQL, o gasPrice agora pode ser recuperado para os tipos de transação 0x3 e 0x4 (#33542)
  • O servidor RPC agora permite HTTP2 de texto simples para melhorar o desempenho (#33812)
  • O RPC client não envia mais quadros RST_STREAM HTTP2 falsos (#33122)
  • Alguns pequenos bugs de codificação JSON foram corrigidos em ethclient (#33693, #33242, #33464)
  • O gethclient possui uma nova embalagem do callTracer (#31510)
  • No callTracer, os logs reportados agora contêm um campo index que é o índice do log dentro da transação (#33629)

Rede P2P

  • O mecanismo de pulsação do pool de transações teve algumas correções para possíveis vazamentos de recursos (#33704)
  • As implementações dos protocolos eth e snap agora validam a maioria das mensagens p2p antes de decodificar seu conteúdo. Isso melhora a segurança e o desempenho da sincronização em alguns casos. (#33835)
  • O pool de transações blob viu algumas correções de bugs e agora aceita transações sem lacunas de forma muito limitada (#32717, #33775, #33474, #33352, #33301, #33260)
  • O status de sincronização instantânea agora é rastreado melhor, garantindo que uma sincronização instantânea não seja acionada acidentalmente pelo mecanismo API (#33157)
  • O agendador de sincronização instantânea foi aprimorado para proteger melhor o banco de dados de teste contra mutações acidentais enquanto o nó processa blocos. Isso resolve alguns casos extremos em que o banco de dados pode estar corrompido (#33428)
  • A implementação de sincronização de cabeçalho foi corrigida para lidar melhor com as operações setHead durante a sincronização (#33481)
  • As conexões peer que entregam transações obsoletas serão menos penalizadas, uma vez que a entrega de algumas transações obsoletas é uma ocorrência comum. (#32725)
  • Os pares que anunciam transações de um tipo e entregam um tipo diferente agora são desconectados como penalidade (#33378)
  • Da mesma forma, os peers que entregam provas KZG inválidas serão agora desconectados (5b99d2bba4)
  • O pool de transações possui novas métricas para o número de contas com transações (#33646, #33654)

Para um resumo completo das mudanças, consulte o marco de lançamento do Geth 1.17.0.

Tal como acontece com todos os nossos lançamentos anteriores, você pode encontrar:

  • Binários pré-construídos para todas as plataformas em nossa página de downloads.
  • Imagens Docker publicadas sob ethereum/client-go (use a tag "stable").
  • Pacotes Ubuntu em nosso repositório PPA do Launchpad.
  • Pacotes macOS em nosso repositório Homebrew Tap.
