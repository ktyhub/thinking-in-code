  • Correção nº 7174: (httpclient-vertx-5) Adicionar verificação de tempo de execução para classes Vert.x 5 para fornecer erro claro quando ocorre conflito Vert.x 4/5
  • Correção nº 7174: (testes de caos) Corrige conflito de caminho de classe ao testar com Vert.x 5 HTTP client
  • Correção nº 7415: (java-generator) Corrige o apagamento de tipo genérico para matriz de enums com valores padrão
  • Correção nº 7422: (okhttp) Remova o uso interno do API e corrija chamadas obsoletas do OkHttp 5
  • Correção nº 7446: tornando o tempo limite de BaseOperation.createOrReplace() configurável

Melhorias

  • Correção nº 1105: adicionar link cruzado javadoc para módulos Fabric8 e dependências externas
  • Correção nº 5756: use interface editável em vez de reflexão para instanciar construtores de recursos
  • Correção nº 7422: aumento okhttp de 4.12.0 para 5.3.2
  • Correção nº 7252: chame adicionalConfig ao criar Vert.x HTTP clients com VertxHttpClientFactory

Atualização de Dependência

  • Correção # 7374: motor cobra yaml de 2.10 para 3.0.1

Novos recursos

  • Correção nº 7385: Suporte para Kubernetes v1.35 (Timbernetes)
  • Correção nº 7174: Adicionada implementação Vert.x 5 HTTP client com tratamento assíncrono aprimorado e separação WebSocket
  • Correção nº 7402: Adicionada geração de relatório de compatibilidade semver API em nível de código de byte usando Revapi

Observação: alterações importantes

  • Correção nº 5756: recursos editados com visitantes agora devem implementar io.fabric8.kubernetes.api.builder.Editable. Todas as classes de modelo fornecidas pelo client já implementam esta interface. Os recursos personalizados fornecidos pelo usuário que usam edição baseada em visitantes precisarão implementar Editable (trivial quando já existe um construtor).
  • Correção nº 7422: aumento okhttp de 4.12.0 para 5.3.2. As versões são compatíveis com binários, mas a atualização da versão principal pode causar efeitos colaterais.

Observação: Compatibilidade com Vert.x HTTP Client (edição nº 7174)

Os módulos kubernetes-httpclient-vertx (Vert.x 4.x) e kubernetes-httpclient-vertx-5 (Vert.x 5.x) são mutuamente exclusivos. Eles não devem ser incluídos juntos nas dependências do seu projeto. Ambos os módulos fornecem uma implementação de HttpClient.Factory e usam as mesmas coordenadas do artefato io.vertx, mas com versões principais incompatíveis.

-Problema*: Se ambos os módulos estiverem presentes no classpath, a resolução de dependência do Maven pode escolher JARs Vert.x 4.x enquanto o Vertx5HttpClientFactory é selecionado em tempo de execução. Isso causa NoClassDefFoundError para classes específicas do Vert.x 5, como io.vertx.core.impl.SysProps.

-Solução*: Certifique-se de que seu projeto inclua apenas UM destes módulos:

  • kubernetes-httpclient-vertx (padrão, usa Vert.x 4.x) - incluído transitivamente via kubernetes-client
  • kubernetes-httpclient-vertx-5 (opcional, usa Vert.x 5.x) - requer dependência explícita e exclusão de vertx-4

Ao usar Vert.x 5, exclua o Vert.x 4 client padrão e defina a propriedade vertx.version:

<properties>
  <vertx.version>${vertx5.version}</vertx.version> <!-- or explicit 5.0.7 -->
</properties>
<dependencies>
  <dependency>
    <groupId>io.fabric8</groupId>
    <artifactId>kubernetes-client</artifactId>
    <exclusions>
      <exclusion>
        <groupId>io.fabric8</groupId>
        <artifactId>kubernetes-httpclient-vertx</artifactId>
      </exclusion>
    </exclusions>
  </dependency>
  <dependency>
    <groupId>io.fabric8</groupId>
    <artifactId>kubernetes-httpclient-vertx-5</artifactId>
  </dependency>
</dependencies>
