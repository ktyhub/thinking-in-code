kubernetes-client v8.0.0

Erros

  • Correção nº 8105: solicitações suspensas quando uma ação de nova tentativa, decisão de nova tentativa ou limpeza de resposta gera uma exceção.
  • Correção nº 7374: (gerador de crd) CRDs gerados não removem ou rejeitam mais o que o client escreve: Object, Map bruto, List<Object>, coleção bruta, @JsonUnwrapped e propriedades polimórficas mantêm seu conteúdo, e os tipos de data e hora apenas declaram um formato que seus valores correspondem (Duration, LocalDateTime e os tipos parciais perdem date-time). As propriedades Optional obtêm o esquema de seu tipo de valor em vez de preservar campos desconhecidos, consulte o guia de migração
  • Correção nº 6779: (httpclient-jetty) 401 respostas sem um cabeçalho WWW-Authenticate, que é como o servidor API as envia, são retornadas com seu corpo em vez de falharem com "Violação do protocolo HTTP: Desafio de autenticação sem cabeçalho WWW-Authenticate"
  • Correção nº 6779: (httpclient-jetty, httpclient-vertx, httpclient-vertx-5) Uma senha de proxy contendo dois pontos ou um URL de proxy com um usuário e sem senha agora é usada para autenticar com o proxy, em vez de retornar a um cabeçalho de solicitação Proxy-Authorization que as solicitações HTTPS transportam através do túnel de proxy para o servidor API
  • Correção nº 6779: um nome de usuário proxy configurado sem senha é enviado com uma senha vazia em vez de null e um URL de proxy com um usuário e sem senha como user: em vez de user (RFC 7617)
  • Correção nº 8134: (httpclient-jetty) Um handshake WebSocket com falha não chama mais o onError do ouvinte, o futuro retornado já falha com ele. Quando o handshake foi tentado novamente, isso encerrou as sessões de observação e exec/attach antes que a nova tentativa pudesse abri-las
  • Correção nº 8134: (httpclient-jetty) Credenciais para um proxy SOCKS5 são enviadas para ele
  • Correção nº 8134: (httpclient-jetty, httpclient-vertx) Credenciais de proxy que não são Basic user:password são adicionadas apenas como um cabeçalho Proxy-Authorization às solicitações que um proxy HTTP lê. Solicitações HTTPS e WSS, WebSockets que túneis Vert.x e solicitações por meio de um proxy SOCKS os levaram para o servidor API
  • Correção nº 8134: (httpclient-vertx-5) Credenciais de proxy que não são Basic user:password são enviadas para o proxy HTTP pelo Vert.x, no CONNECT também, portanto, solicitações HTTPS e WebSocket por meio de um proxy que exige que elas funcionem e não alcançam mais o servidor API
  • Correção nº 8134: (httpclient-okhttp) Um 407 do servidor API (por meio de pods/proxy, por exemplo) não é mais respondido com as credenciais do proxy, que passaram pelo túnel do proxy até ele, e as credenciais rejeitadas pelo proxy não são enviadas novamente
  • Correção nº 8140: (httpclient-vertx-5) Uma solicitação cuja conexão foi fechada antes de poder ser gravada falha com um IOException e é tentada novamente, em vez de ser interrompida até o tempo limite da solicitação (visto no Windows)
  • Correção nº 8134: (httpclient-jetty) Os cookies definidos por uma resposta não são mais enviados de volta em solicitações posteriores e atualizações de WebSocket, como acontece com outras implementações de HttpClient
  • Correção nº 8109: um java.sql.Date escrito como yyyy-MM-dd é lido como uma data local em vez do dia anterior a oeste de UTC. Year, Month, java.sql.Date e Locale mantêm seu formato de fio 7.x. Os mapeadores que você mesmo constrói precisam do novo Jackson2JdkTypesModule, consulte o guia de migração
  • Correção # 8109: (gerador crd) Os esquemas byte[], ByteBuffer, char[], Year e java.sql.Date correspondem ao que o client escreve (byte[] e ByteBuffer são strings format: byte), então o servidor API não os rejeita mais. @PrinterColumn em um LocalDate é uma coluna string em vez de uma coluna date que mostrava <invalid>
  • Correção nº 8008: (httpclient-vertx-5) Solicitações com um corpo InputStream e Expect: 100-continue (compilações binárias) não travam mais e um corpo InputStream de comprimento conhecido é enviado com Content-Length em vez de fragmentado
  • Correção nº 8139: (httpclient-okhttp) WebSockets respondem ao quadro Fechar do servidor mesmo quando o ouvinte não o faz, portanto, o encaminhamento de porta e os ouvintes personalizados liberam a conexão em vez de esperar que o servidor a abandone
  • Correção nº 8152: (httpclient-vertx, httpclient-vertx-5, httpclient-jetty, httpclient-jdk) WebSockets enviam um ping a cada Config#websocketPingInterval (30s por padrão), como o OkHttp já fez, então balanceadores de carga que fecham conexões inativas não interrompem mais relógios silenciosos

Melhorias

  • Correção nº 8109: (gerador crd) As propriedades int/Integer e long/Long obtêm format: int32 e format: int64, como a geração do controlador
  • Correção nº 7987: (kubernetes-client-api) withShardSelector aceita um ShardSelector digitado (ShardSelector.builder().addShard(0, 4).addShard(2, 4).build()) próximo à expressão bruta String, portanto, a gramática CEL shardRange(...) e seus limites hexadecimais não precisam ser escritos à mão

Observação: alterações importantes

  • Verifique a documentação detalhada de migração para alterações significativas em 8.0.0
  • Correção nº 8041: (kubernetes-client-api) runtimeClasses() e network().ingresses() (e network().ingress()) usam os modelos v1 em vez dos v1beta1 que Kubernetes não atende mais, consulte o guia de migração
  • Correção #7374: Movido para Jackson 3 (coordenadas e pacotes tools.jackson). A serialização padrão mantém o comportamento do Jackson 2 para tipos personalizados, consulte o guia de migração
  • Correção nº 7987: (kubernetes-client-api) Filterable#withShardSelector também aceita um ShardSelector digitado, portanto, um withShardSelector(null) literal não é mais compilado, consulte o guia de migração
  • Correção nº 8031: (gerador crd) Removido o obsoleto gerador CRD v1 (crd-generator-api e crd-generator-apt). Migre para crd-generator-api-v2 com o plugin Maven, a ferramenta CLI ou a receita de script de construção do Gradle, consulte a migração guia
  • Correção nº 8009: linha de base Java movida de 11 para 17. Além do requisito de tempo de execução, os plug-ins Maven, o plug-in Gradle e o processador de anotação agora exigem um Java 17+ JVM para executar a compilação, e os pacotes OSGi declaram osgi.ee=JavaSE 17
  • Correção nº 8050: (karaf) O repositório de recursos kubernetes-karaf não define mais seu próprio recurso scr. kubernetes-client agora depende do recurso scr fornecido pela distribuição Karaf, que fornece os pacotes Declarative Services API e os comandos shell scr:*
  • Correção #8142: (knative) Servir RevisionSpec substitui workloadRef por schedulingGroup e adiciona evictionResponders, como o núcleo PodSpec desde Kubernetes 1.37
  • Correção nº 8133: (gerenciamento de cluster aberto) DiscoveredClusterSpec elimina owner e DiscoveredClusterCondition elimina lastUpdateTime
  • Correção # 8148: (modelo openshift) Classe de modelo io.fabric8.openshift.api.model.customresourcestatus.conditions.v1.Condition removida, condições Hive ClusterDeploymentCustomizationStatus usam o Kubernetes Condition
  • Correção nº 8148: (openshift-model-config) As políticas ClusterImagePolicySpec e ImagePolicySpec são ImageSigstoreVerificationPolicy e suas raízes são trust ImagePolicyFulcioCAWithRekorRootOfTrust, ImagePolicyPKIRootOfTrust e ImagePolicyPublicKeyRootOfTrust. Classes de modelo FulcioCAWithRekor, PKI, Policy e PublicKey removidas
  • Correção nº 8148: (openshift-model-config) GCPPlatformStatus descarta serviceEndpoints, classe de modelo GCPServiceEndpoint removida
  • Correção nº 8148: (openshift-model-hive) suporte oVirt removido: ClusterDeprovisionPlatform, MachinePoolPlatform e Platform eliminam ovirt, classes de modelo OvirtClusterDeprovision e o pacote io.fabric8.openshift.api.model.hive.ovirt.v1 removidos
  • Correção nº 8148: (openshift-model-hive) vSphere MachinePool.osDisk usa o instalador io.fabric8.openshift.api.model.installer.vsphere.v1.OSDisk, classe de modelo io.fabric8.openshift.api.model.hive.vsphere.v1.OSDisk removida. O módulo agora depende de openshift-model-installer, openshift-model-machine e openshift-model-operator
  • Correção # 8148: (instalador do modelo openshift) GCP PSCEndpoint elimina region
  • Correção # 8148: (openshift-model-machineconfiguration) Classes de modelo v1alpha1 MachineConfigNode, PinnedImageSet e seus tipos relacionados removidos, use os v1
  • Correção nº 8133: (gerenciamento de cluster aberto) MultiClusterHubSpec descarta customCAConfigmap, enableClusterBackup, enableClusterProxyAddon, hive, ingress e separateCertificateManagement. Classes de modelo BackupConfig, ExternalDNSAWSConfig, ExternalDNSConfig, ExternalDNSGCPConfig, FailedProvisionConfig, HiveConfigSpec, HiveConfigStatus, IngressSpec e VeleroBackupConfig removidas
  • Correção nº 8133: (gerenciamento de cluster aberto) Observabilidade PlatformMetricsSpec e UserWorkloadMetricsSpec substituem collection por default (PlatformMetricsCollectionSpec e UserWorkloadMetricsCollectionSpec removidos) e PlatformNamespaceRightSizingRecommendationSpec é renomeado para PlatformRightSizingRecommendationSpec
  • Correção nº 8100: (tekton) Classes de modelo Template e AffinityAssistantTemplate movidas do pacote io.fabric8.tekton.pod para io.fabric8.tekton.unversioned, já que o pipeline tekton 1.16.0 as declara como +versionName=unversioned
  • Correção nº 6779: (httpclient-jetty) movido do Jetty 11 para o Jetty 12.1, consulte o guia de migração
  • Correção nº 8008: kubernetes-client e openshift-client são padrão para Vert.x 5 HttpClient (kubernetes-httpclient-vertx-5) em vez de Vert.x 4 (kubernetes-httpclient-vertx), consulte o guia de migração
