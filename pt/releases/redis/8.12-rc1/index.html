#redis 8.12-rc1

Este é o primeiro Release Candidate do Redis 8.12 em Redis Open Source.

Release Candidates são pré-lançamentos com recursos completos. Os pré-lançamentos não são adequados para uso em produção.

Manchetes:

Redis 8.12 apresenta novos recursos e melhorias de desempenho.

Sistemas operacionais em que testamos Redis 8.12

  • Ubuntu 22.04 (Jammy Jellyfish), 24.04 (Noble Numbat), 26.04 (Resolute Raccoon) -Rocky Linux 8.10, 9.7, 10.1 -AlmaLinux 8.10, 9.7, 10.1
  • Debian 12.13 (Bookworm), Debian 13.4 (Trixie)
  • Alpino 3.23
  • macOS 14.8.4 (Sonoma), 15.7.4 (Sequoia), 26.3 (Tahoe) - para Intel e ARM

Correções de segurança

  • RediSearch/RediSearch#10073 O hash de valor indexado agora é resistente a colisões, evitando a degradação do índice no estilo HashDoS devido a entradas adversárias. (MOD-14459)
  • RediSearch/RediSearch#11202 Caracteres UTF-8 incompletos não são mais lidos fora dos limites em campos TEXT indexados. (MOD-18088)

Novos recursos

  • #15331 Bitmaps compactados — Rugido redis integrado ao núcleo Redis para menor uso de memória e operações de bitmap mais rápidas. Agradecimentos especiais a Antonio, o criador original do rugido redis, por contribuir com esta capacidade! https://redisroaring.com/redis-merge/#/1;
  • #15986 Novo comando: BITRANGEINTARRAY equivalente ao R.RANGEINTARRAY do redis-roaring, para retornar deslocamentos de bits definidos dentro de um intervalo especificado
  • #15938 Expiração do conjunto para membro individual do conjunto; Novos comandos: SEXPIRE, SPEXPIRE, SEXPIREAT, SPEXPIREAT para definir a expiração e STTL, SPTTL, SEXPIRETIME, SPEXPIRETIME para recuperar TTLs restantes ou carimbos de data e hora de expiração
  • #15649 Abençoe chaves: evite o despejo de chaves especificadas; Novo comando: BLESS
  • #15829 CLUSTER MIGRATION STATUS agora relata o progresso das fases de snapshot e migração incremental
  • #15556 Grupos nomeados TLS agora podem ser configurados usando tls-groups
  • RedisBloom/RedisBloom#1063 Extensões de esboço de contagem mínima: Adicionado suporte opcional CELL_SIZE para CMS.INITBYDIM e CMS.INITBYPROB para menor uso de memória, incrementos negativos em CMS.INCRBY para diminuir contagens e relatórios de tamanho de célula em CMS.INFO
  • RedisJSON/RedisJSON#1640 Criar automaticamente caminho profundo JSON
  • RediSearch/RediSearch#10151 EXPLAINSCORE agora é compatível com FT.HYBRID. (MOD-10044)
  • RediSearch/RediSearch#11330 A nova compactação SQ8 agora está disponível para campos vetoriais HNSW. (MOD-6132)
  • RediSearch/RediSearch#10247 O tratamento de tempo limite do RETURN_STRICT agora está habilitado para execução local do FT.HYBRID. (MOD-16492)
  • RediSearch/RediSearch#11278 FT.ALTER evita reindexação desnecessária de documentos durante adições de esquema. (MOD-18171)
  • RediSearch/RediSearch#11384 Atualizações de hash somente de pontuação/carga útil evitam a reindexação. (MOD-18182)
  • RediSearch/RediSearch#11230 Documentos hash não são mais reindexados quando nenhum campo indexado por vetor é tocado. (MOD-17688)

Melhorias de desempenho e utilização de recursos

  • #15618 Atualizações em lote de hashes usando modelos compartilhados agora são executadas com mais eficiência
  • #15018 Os sistemas x86 suportados agora usam o relógio monotônico baseado no processador por padrão, com calibração de tempo de execução para reduzir a sobrecarga de tempo
  • #15782 O carregamento RDB e AOF agora fornece dicas de leitura sequencial ao sistema operacional para melhorar a eficiência do carregamento
  • RediSearch/RediSearch#10169 As pesquisas em índices que usam expiração em nível de campo (HEXPIRE) são mais rápidas. (MOD-16350)
  • RediSearch/RediSearch#10981, RediSearch/RediSearch#11065 A pesquisa de campo do coordenador e a sobrecarga de serialização de resposta de linha são reduzidas. (MOD-17924)
  • RediSearch/RediSearch#11055, RediSearch/RediSearch#11056, RediSearch/RediSearch#11057 A conversão de resposta de cluster, a destruição de resultados e a limpeza de GROUPBY reduziram a sobrecarga. (MOD-17908, MOD-17909, MOD-17910)
  • RediSearch/RediSearch#11507, RediSearch/RediSearch#11506 As respostas de consulta agora formatam valores numéricos integrais sem snprintf e declaram antecipadamente os comprimentos da coleção de respostas. (MOD-18800, MOD-18799)
  • RediSearch/RediSearch#11509 O carregamento de campo hash para RETURN e LOAD não requer mais alocações por campo. (MOD-18811)
  • RediSearch/RediSearch#10246 Gravações simultâneas agora são permitidas durante consultas de intervalo de vetores. (MOD-16437)
  • RediSearch/RediSearch#10515 As solicitações do coordenador agora são alocadas no thread principal, removendo CoordRequestCtx. (MOD-16990)
  • RediSearch/RediSearch#11018 O uso de consultas agora está separado das operações administrativas de índice. (MOD-17536)
  • RediSearch/RediSearch#10066 Barreira de resposta de fragmento removida em favor do retorno de chamada de esgotamento do iterador assíncrono para FT.AGGREGATE WITHCOUNT. (MOD-16210)
  • RedisJSON/RedisJSON#1645 Relatórios de uso de memória mais precisos para strings compartilhadas: o uso de memória agora considera a parcela proporcional de cada referência na alocação de uma string compartilhada, incluindo seu cabeçalho e preenchimento, em vez de cobrar a alocação total para cada referência
  • J1660 Consumo reduzido de memória de objeto: a análise JSON agora usa alocação compacta de objeto para reduzir a memória real necessária para armazenar objetos JSON
  • RedisJSON/RedisJSON#1661 Análise e avaliação de JSONPath aprimoradas, reduzindo o retrocesso do analisador, alocações temporárias e travessias repetidas. As otimizações incluem o armazenamento em cache de operandos do caminho raiz entre candidatos a filtros, interrompendo verificações de existência na primeira correspondência e reduzindo a sobrecarga na correspondência de expressões regulares e comparações de strings
  • RedisJSON/RedisJSON#1631 Acesso aprimorado aos elementos da matriz digitada por meio de indexação direta, evitando iterações repetidas e trabalho quadrático durante varreduras indexadas completas
  • RedisBloom/RedisBloom#1049 Melhor desempenho de compactação t-digest para entradas contendo muitos valores duplicados. A classificação agora está limitada a O(n log n), evitando comportamento quadrático em entradas patológicas

Parâmetros de configuração

  • Redis-roaring:bitmap-default-roaring - para habilitar o novo tipo de bitmaps rugido, desabilitado por padrão
  • RedisJSON/RedisJSON#1657 Validação de profundidade RDB configurável: Adicionado json-legacy-rdb-depth-limit, desabilitado por padrão, para impor uma profundidade máxima de aninhamento de 128 ao carregar JSON do RDB ou por meio de RESTORE
  • RedisJSON/RedisJSON#1640 Adicionadojson-auto-create-deep-paths e está desabilitado por padrão e só pode ser configurado no tempo de carregamento. Use o mesmo valor em cada nó de um fragmento e ao reproduzir arquivos AOF, pois valores diferentes podem causar divergência de dados

Métricas

  • #15374 Os histogramas de tamanhos de chave do INFO agora incluem streams, fornecendo visibilidade dos tamanhos de chave de stream
  • #15682 Observabilidade de fluxos – Adicionado INFO STREAMS com histogramas por banco de dados de grupos de consumidores por fluxo, entradas pendentes por grupo e consumidores por grupo. Habilitar com stream-stats sim (desabilitado por padrão)
  • RediSearch/RediSearch#10097 FT.INFO agora expõe o EF_RUNTIME padrão. (MOD-16147)
  • RediSearch/RediSearch#10107 Disk GC bytes_collected e estatísticas de ciclo agora são relatadas em FT.INFO. (MOD-14621)
  • RediSearch/RediSearch#10464 FT.INFO no coordenador agora agrega métricas de disco por campo por meio do redutor. (MOD-14859)
  • RediSearch/RediSearch#10204 Redis INFO agora divide as métricas de tempo limite de consulta por estágio do pipeline. (MOD-13192)
  • As métricas do índice RediSearch/RediSearch#11521 não são mais coletadas para seções INFO não relacionadas. (MOD-18033)
  • RediSearch/RediSearch#10536 FT.PROFILE resolução de temporização do campo do carregador melhorada. (MOD-17132)

Mudanças de comportamento

  • RediSearch/RediSearch#10109 FT.CREATE rejeita RERANK em campos de vetor HNSW no modo RAM. (MOD-16015)
  • RediSearch/RediSearch#10200 Os índices de disco rejeitam DIALECT 4 e WITHOUTCOUNT. (MOD-15997)
  • RediSearch/RediSearch#10082 COLLECT requer um prefixo @ para nomes de campo. (MOD-16233)
  • RediSearch/RediSearch#11106 JSON Os campos HIGHLIGHT/SUMMARIZE com vários valores JSONPath agora são rejeitados. (MOD-16530)
  • RediSearch/RediSearch#10208 Comandos que não podem ser armazenados em cache agora são marcados com dont_cache. (MOD-16175)
  • RediSearch/RediSearch#10699 Os argumentos dos comandos numéricos agora são analisados estritamente. (MOD-17409)
  • RediSearch/RediSearch#11335 O módulo de pesquisa agora requer Redis 8.9.241 ou mais recente para carregar. (MOD-15868)
  • RedisBloom/RedisBloom#1063 Atualizações de itens CMS.INCRBY rejeitadas agora deixam os contadores e a contagem total inalterados em vez de saturar os contadores no estouro. Comandos de vários itens ainda podem ser parcialmente bem-sucedidos.
  • RedisBloom/RedisBloom#1063 CMS.MERGE agora requer tamanhos de células correspondentes no destino e em todas as fontes.

Módulos API

  • #15517 Os módulos agora podem recuperar a porta TLS de um nó de cluster usando o novo sinalizador REDISMODULE_NODE_PORT_TLS em RM_GetClusterNodeInfo()
  • RedisJSON/RedisJSON#1623 Adicionado getWithPath no API V9 compartilhado para avaliar um JSONPath pré-compilado, permitindo que os chamadores compilem um caminho uma vez e o reutilizem em documentos.
  • RedisJSON/RedisJSON#1666 Adicionado pathParseNoErrorMsg no API V10 compartilhado para compilar JSONPaths sem um contexto Redis ou uma mensagem de erro alocada. Retorna um identificador compilado em caso de sucesso ou NULL em caso de falha.
  • RedisJSON/RedisJSON#1653 Tornou os ganchos de pré-comando opcionais e permitiu erros de gancho para abortar comandos JSON antes da execução. Os ganchos agora retornam RedisResult<()>; chamadas C API compartilhadas continuam ignorando erros de gancho.
  • RedisJSON/RedisJSON#1640 Estendeu a interface do Rust Manager com clone_value e create_object para suportar a construção de caminhos ausentes. As implementações customizadas devem implementar esses métodos e satisfazer o novo requisito Borrow<Self::V> para valores próprios.
