Anteriormente, a pesquisa do console de administração correspondia apenas ao nome do domínio técnico, tornando mais difícil encontrar domínios em grandes implantações multilocatários.</p> </div> <div class="parágrafo"> <p>A pesquisa de domínio agora corresponde ao nome de exibição, além do nome do domínio, para que os administradores possam encontrar os domínios pelo nome que lembrarem.</p> </div> </div> <div class="sect3"> <h4 id="_type_safe_validation_for_parameterized_scopes_experimental">Validação de tipo seguro para escopos parametrizados (experimental)</h4> <div class="parágrafo"> <p>Os escopos parametrizados permitem que o OAuth clients solicite acesso específico ao contexto — por exemplo, <code>project:12345</code> para solicitar acesso a um projeto específico ou <code>account: saving</code> para definir o escopo de um token para uma conta bancária específica. Anteriormente, o valor do parâmetro era validado apenas por uma regex opcional, facilitando a transmissão de valores inválidos ou inesperados.</p> </div> <div class="parágrafo"> <p>Os escopos parametrizados agora podem definir um tipo de parâmetro que valida o valor capturado no momento da solicitação. Os tipos integrados incluem <code>string</code>, <code>integer</code>, <code>boolean</code>, <code>username</code> e <code>custom</code> (validado em uma regex definida pelo administrador). O tipo é obrigatório ao criar escopos parametrizados com o recurso habilitado, garantindo que os tokens sempre carreguem parâmetros de escopo bem formados.</p> </div> <div class="parágrafo"> <p>Para obter mais detalhes, consulte o <a href="https://www.keycloak.org/docs/26.7.0/upgrading/">Guia de atualização</a>.</p> </div> </div> <div class="sect3"> <h4 id="_additional_datasources_may_be_excluded_from_health_checks">Fontes de dados adicionais podem ser excluídas das verificações de integridade</h4> <div class="parágrafo"> <p>Ao usar várias fontes de dados, uma fonte de dados não crítica com falha pode fazer com que o endpoint da verificação de integridade relate toda a implantação como não íntegra. Agora, fontes de dados individuais podem ser excluídas das verificações de integridade para que fontes de dados opcionais ou secundárias não acionem alertas desnecessários nem afetem o roteamento do balanceador de carga.</p> </div> <div class="parágrafo"> <p>Leia mais sobre isso no guia <a href="https://www.keycloak.org/server/db#multiple-datasources">Configurar múltiplas fontes de dados</a>.</p> </div> </div> </div> <div class="sect2"> <h3 id="_configurando_and_running">Configurando e executando</h3> <div class="sect3"> <h4 id="_enhanced_reverse_proxy_guides_with_blueprints_for_haproxy_and_traefik">Guias de proxy reverso aprimorados com planos para HAProxy e Traefik</h4> <div class="parágrafo"> <p>A execução do Keycloak em produção requer um proxy reverso, mas a configuração correta da terminação TLS, do encaminhamento de certificados e da segurança administrativa API em diferentes proxies é propensa a erros.</p> </div> <div class="parágrafo"> <p>A documentação do proxy reverso foi significativamente expandida com guias passo a passo dedicados para HAProxy e Traefik, cobrindo os modos de passagem TLS e recriptografar, além de explicar os conceitos para que possam ser aplicados a outros proxies também.</p> </div> <div class="parágrafo"> <p>Para obter mais detalhes, consulte o guia <a href="https://www.keycloak.org/server/reverseproxy">Como usar um proxy reverso</a>.</p> </div> </div> <div class="sect3"> <h4 id="_simplified_multi_cluster_high_availability_without_external_caches_experimental">Alta disponibilidade simplificada de vários clusters sem caches externos (pré-visualização)</h4> <div class="parágrafo"> <p>A configuração existente de vários clusters para Keycloak requer a implantação e o gerenciamento de um cluster Infinispan externo para replicação de sessões entre sites, juntamente com uma infraestrutura de isolamento específica do fornecedor para failover automatizado. Isso adiciona uma complexidade operacional significativa e limita as implantações em ambientes específicos.</p> </div> <div class="parágrafo"> <p>O Multi-cluster v2 remove totalmente o requisito externo do Infinispan. As instâncias Keycloak conectam-se diretamente entre si usando caches Infinispan incorporados e contam com o banco de dados replicado de forma síncrona como a única fonte de verdade. A invalidação de cache entre sites é tratada por meio de um padrão de caixa de saída baseado em banco de dados. O balanceador de carga pode detectar o tempo de inatividade de um site sem exigir infraestrutura de cerca externa.</p> </div> <div class="parágrafo"> <p>Para ativar esta configuração, inicie o Keycloak com o recurso <code>stateless</code>. Para obter detalhes da arquitetura e um plano de implantação, consulte o guia <a href="https://www.keycloak.org/high-availability/multi-cluster-v2/introduction">Implantações de vários clusters (v2)</a>.</p> </div> </div> <div class="sect3"> <h4 id="_keycloak_operator_kustomize_installation">Instalação personalizada do Keycloak Operator</h4> <div class="parágrafo"> <p>A instalação do Keycloak Operator em clusters vanilla Kubernetes anteriormente exigia o download e a aplicação de arquivos de manifesto individuais, dificultando o gerenciamento de atualizações e personalizações. O Operador agora pode ser instalado usando kustomize, fornecendo um método de instalação declarativo e reproduzível.</p> </div> <div class="parágrafo"> <p>Para obter instruções de instalação, consulte o <a href="https://www.keycloak.org/guides#operator">Guia do Operador</a>.</p> </div> </div> <div class="sect3"> <h4 id="_cluster_wide_install_mode_for_the_keycloak_operator_preview">Modo de instalação em todo o cluster para o Keycloak Operator (pré-visualização)</h4> <div class="parágrafo"> <p>Organizações que executam múltiplas instâncias do Keycloak em diferentes namespaces Kubernetes anteriormente precisavam instalar um Operador separado em cada namespace. O Operador Keycloak agora expõe <code>AllNamespaces</code> como um modo de instalação OLM compatível, permitindo que uma única instância do Operador reconcilie recursos personalizados <code>Keycloak</code> em todos os namespaces no cluster. Para instalações não OLM, a implantação em todo o cluster está disponível por meio da sobreposição de personalização em todo o cluster.</p> </div> <div class="parágrafo"> <p>A instalação em todo o cluster está em versão prévia. Para obter instruções e limitações de instalação, consulte o <a href="https://www.keycloak.org/guides#operator">Guia do Operador</a>.</p> </div> </div> </div> <h2>Atualizando</h2> <p>Antes de
