logging-log4j2 rel/2.25.0

Esta versão secundária apresenta correções de bugs, melhorias de comportamento e suporte completo para geração de imagens nativas GraalVM.

GraalVM Metadados de acessibilidade

Log4j Core e todos os módulos de extensão agora incluem
Metadados de acessibilidade GraalVM,
permitindo a geração perfeita de imagens nativas com o GraalVM pronto para uso - sem necessidade de configuração manual.
Para obter mais informações, consulte nosso guia GraalVM.

[!NOTA]
Ao construir plug-ins Log4j de terceiros, usando o novo GraalVmProcessor
introduzido na versão 2.25.0 irá gerar automaticamente os metadados de acessibilidade necessários para imagens nativas GraalVM.
No entanto, o processador falhará na construção se os parâmetros log4j.graalvm.groupId e log4j.graalvm.artifactId necessários não forem fornecidos.
Para obter instruções detalhadas, consulte Registrando plug-ins.

Tratamento de exceções no layout de padrão

O tratamento de exceções em Layout de padrão passou por uma reescrita significativa.
Esta atualização resolve vários bugs e garante um comportamento consistente em todos os conversores de exceção.
As principais melhorias incluem:

  • Os rastreamentos de pilha agora são prefixados consistentemente com uma nova linha em vez de outros espaços em branco.
  • O conversor de exceção padrão mudou de estendido para simples, oferecendo melhor desempenho.
  • Foi removido o suporte para a opção {ansi} em conversores de exceção.

Formatação de data e hora

Historicamente, o Log4j fornece formatadores personalizados de data e hora para desempenho, como FixedDateFormat e FastDateFormat.
Eles agora estão obsoletos em favor do padrão Java DateTimeFormatter.

Se você encontrar problemas de formatação após a atualização — especialmente com as diretivas n ou x — você pode reverter temporariamente para os formatadores legados definindo a propriedade log4j2.instantFormatter como legacy.
Por favor, relate quaisquer problemas através do nosso rastreador de problemas.

Suporte ANSI no Windows

As versões modernas do Windows (10 e mais recentes) fornecem suporte nativo à sequência de escape ANSI.
Como resultado, a dependência da biblioteca JAnsi 1.x desatualizada foi removida.
Para obter detalhes, consulte Estilo ANSI no Windows.

Jacarta JMS Appender

Uma versão compatível com Jakarta do JMS Appender agora está incluída na distribuição principal.
