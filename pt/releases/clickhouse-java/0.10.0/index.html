clickhouse-java v0.10.0

Guia de migração de versão

Mudanças significativas

  • [jdbc-v2] O driver não codifica mais as configurações do servidor async_insert=0 e wait_end_of_query=0 em cada JDBC conexão. Isso desbloqueia dois cenários que anteriormente não funcionavam: substituir essas configurações por conexão ou por instrução e usando o driver em perfis somente leitura que não permitem substituições SETTINGS. Existem duas consequências:

    • O driver agora segue os padrões do lado do servidor para essas configurações (nota: começando com ClickHouse 26.3, async_insert o padrão é 1). A remoção do wait_end_of_query=0 explícito não funciona contra os padrões do servidor, mas permite que os usuários optem por wait_end_of_query=1.
    • A contagem de linhas retornada por java.sql.Statement.executeUpdate(java.lang.String) (e o PreparedStatement correspondente método) não tem mais garantia de precisão para instruções INSERT quando o servidor as executa de forma assíncrona, e erros de análise/dados no corpo INSERT podem não surgir de forma síncrona como um SQLException. Anteriormente estes eram preciso porque as inserções foram forçadas a serem síncronas (veja também https://github.com/ClickHouse/ClickHouse/issues/57768). Para restaurar o comportamento anterior, defina async_insert=0 (ou wait_for_async_insert=1) por conexão como configuração do servidor. Leia mais sobre inserto assíncrono: https://clickhouse.com/docs/optimize/asynchronous-inserts.

    (https://github.com/ClickHouse/clickhouse-java/issues/2652, https://github.com/ClickHouse/clickhouse-java/issues/2825)

  • [client-v2] Client.Builder#build() agora lança ClientMisconfigurationException em vez de IllegalArgumentException para autenticação e configuração incorreta de SSL (credenciais ausentes, conflito métodos de autenticação, certificado client ausente quando a autenticação SSL está habilitada e armazenamento trust usado juntos com um certificado client). Chamadores que dependiam da captura de IllegalArgumentException de build() para esses casos deve capturar ClientMisconfigurationException (que estende RuntimeException via ClientException). (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Combinando setUsername(...) + setPassword(...) com um cabeçalho HTTP Authorization personalizado ( httpHeader(HttpHeaders.AUTHORIZATION, ...)) agora falha em Client.Builder#build() com ClientMisconfigurationException, a menos que a autenticação HTTP Basic seja explicitamente desativada via useHTTPBasicAuth(false). Anteriormente, esta combinação era aceita e o cabeçalho Authorization personalizado era substituído o usuário/senha no momento da solicitação. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] A propriedade de configuração access_token (definida via Client.Builder#setAccessToken(String) ou diretamente através de setOption) agora é realmente aplicado a solicitações de saída como o valor do cabeçalho HTTP Authorization literalmente. Anteriormente, o valor era armazenado em access_token, mas nunca enviado na transmissão, portanto, fornecê-lo sozinho não tinha efeito na autenticação. Os próprios chamadores devem incluir o prefixo do esquema (por exemplo, setAccessToken("Bearer <token>")) ou usar useBearerTokenAuth(String) que precede Bearer automaticamente. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Client.Builder#useBearerTokenAuth(String) agora armazena o token ao portador no access_token chave de configuração (com o prefixo Bearer ) em vez de escrevê-la diretamente em http_header_authorization. O O formato de ligação HTTP permanece inalterado, mas o token não é mais observável por meio de Client#getReadOnlyConfig() sob o Chave http_header_authorization. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [client-v2] Corrigido uso inconsistente do parâmetro executionTimeout no componente Client. O tempo limite foi anteriormente definido em milissegundos, mas recuperado por engano e usado em segundos em alguns lugares. Agora ele usa corretamente milissegundos consistentemente. (https://github.com/ClickHouse/clickhouse-java/issues/2358)

  • [client-v2] A interface pública ClickHouseBinaryFormatWriter ganhou dois métodos, setString(String, byte[]) e setString(int, byte[]), para escrever bytes brutos String/FixedString. Código que apenas usa a interface não é afetado, mas qualquer terceiro que implemente ClickHouseBinaryFormatWriter diretamente é incompatível com código-fonte e binário até adicionar esses métodos (é necessária a recompilação com a nova versão; caso contrário, um AbstractMethodError pode ocorrer em tempo de execução).

  • [client-v2] As respostas HTTP 503 Service Unavailable agora aparecem como uma falha no estilo de conexão ( java.net.ConnectException) e são repetidas por padrão. Anteriormente, um 503 era tratado como um erro de servidor ( ServerException) e caiu na causa da falha ServerRetryable. Foi movido para a falha ConnectTimeout categoria de causa para que as falhas de conectividade/disponibilidade sejam tratadas uniformemente com outros erros de conexão. chamadores que excluíram especificamente ServerRetryable para evitar tentar novamente 503 devem agora ajustar seus Configuração client_retry_on_failures para excluir ConnectTimeout.

  • [client-v2] Códigos de status HTTP inesperados/desconhecidos (aqueles que o client não pode interpretar como uma resposta do ClickHouse) agora jogue um ClientException em vez de um ServerException. Como o client não consegue lidar de forma significativa com essas respostas, eles são relatados como um erro do lado client em vez de serem atribuídos ao servidor.

Novos recursos

  • [jdbc-v2, client-v2] Configuração de modos SSL implementada. Agora é possível configurar ssl_mode para DISABLED, TRUST, VERIFY_CA e STRICT. Nota para usuários V1: NONE é suportado apenas pelo driver JDBC e mapeado para TRUST. Migre para a nova nomenclatura.

    • Exemplos para client-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/client-v2/src/main/java/com/clickhouse/examples/client_v2/SSLExamples.java
    • Exemplos para jdbc-v2 https://github.com/ClickHouse/clickhouse-java/blob/main/examples/jdbc/src/main/java/com/clickhouse/examples/jdbc/SSLExamples.java (https://github.com/ClickHouse/clickhouse-java/pull/2874, https://github.com/ClickHouse/clickhouse-java/issues/2389, https://github.com/ClickHouse/clickhouse-java/issues/2309, https://github.com/ClickHouse/clickhouse-java/issues/2819)

  • [jdbc-v2, client-v2] (beta) Leitores autônomos implementados para JSONEachRow para fornecer estrutura para lendo este formato. Além disso, oferece uma maneira de mapear colunas Json para tipos personalizados usando o driver JDBC. Veja exemplos em https://github.com/ClickHouse/clickhouse-java/tree/main/examples/jdbc-v2-json-processors e https://github.com/ClickHouse/clickhouse-java/tree/main/examples/client-v2-json-processors. (https://github.com/ClickHouse/clickhouse-java/pull/2871)

  • [client-v2] Adicionado Session API para encapsular e gerenciar configurações de sessão ClickHouse (session_id, session_check, session_timeout, session_timezone) como objeto reutilizável. A instância Session pode ser aplicada a quaisquer configurações de solicitação usando applyTo() e estado da sessão podem ser apagados via clearSession(). Além disso, adicionado resetOption(String) a InsertSettings, QuerySettings e CommonSettings para permitir a remoção de configurações específicas. As configurações definidas explicitamente como null não serão enviadas ao servidor, o que é útil para substituir configurações globais. (https://github.com/ClickHouse/clickhouse-java/pull/2810)

  • [client-v2] Adicionada atualização de credencial de tempo de execução APIs em Client: updateUserAndPassword(String, String), updateAccessToken(String) e updateBearerToken(String). Solicitações subsequentes na mesma instância Client usam as novas credenciais sem reconstruir o client. O método de autenticação é fixado no momento da construção; ligando para um atualizador de tempo de execução que não corresponde ao método configurado lança ClientMisconfigurationException. Veja docs/authentication.md para obter detalhes e orientações de migração. (https://github.com/ClickHouse/clickhouse-java/pull/2812)

  • [jdbc-v2] Adicionada propriedade de configuração cluster_name para especificar um cluster de destino para instruções como KILL QUERY que exigem que uma cláusula ON CLUSTER seja executada em todos nós. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [client-v2, jdbc-v2] Adicionado suporte para ClickHouse tipo Geometry para ClickHouse 25.11+, onde Geometry alterado de um alias String para Variant(Point, Ring, LineString, MultiLineString, Polygon, MultiPolygon) (client ainda compatível com versões mais antigas). Inclui manipulação de leitura/gravação client e mapeamento de tipo JDBC para recuperação e inserir valores de geometria. As gravações atuais inferem a variante da geometria alvo a partir da profundidade do aninhamento da matriz, portanto, Ring vs. LineString e Polygon vs MultiLineString ainda não são distinguíveis através da gravação genérica Geometry caminho. (https://github.com/ClickHouse/clickhouse-java/pull/2815)

  • [jdbc-v2] ResultSet#getObject(int|String, Map<String, Class<?>>) agora aceita nomes de tipo ClickHouse como chaves de mapa além dos nomes JDBC SQLType que sempre aceitou. Somente nomes de tipos desembrulhados são usados para a pesquisa — Os wrappers Nullable(...) e LowCardinality(...) são removidos e não afetam a resolução, portanto, uma chave como "Int32" corresponde às colunas Int32 e Nullable(Int32); chaves como "Nullable(Int32)" não são reconhecidas. A ordem de pesquisa é o nome enum ClickHouseDataType (por exemplo, "Int32", "String", "DateTime") e depois o nome JDBC SQLType (por exemplo, "INTEGER", "VARCHAR", "TIMESTAMP"); uma entrada ausente deixa o valor não coagido. O recurso é compatível com Somente tipos primitivos ClickHouse — Array, Tuple, Map, Nested e tipos de geometria não são suportados e continuam a serem retornados em sua forma nativa, independentemente do mapa fornecido pelo usuário. Mapas existentes codificados apenas por JDBC SQLType os nomes continuam a funcionar inalterados. (https://github.com/ClickHouse/clickhouse-java/pull/2865)

  • [jdbc-v2] Adicionado suporte de mapeamento personalizado para tipos JDBC. Usado principalmente em casos em que números inteiros grandes devem ser apresentado como string. Use DriverProperties.JDBC_TYPE_MAPPINGS (jdbc_type_mappings) e defina o mapeamento de tipo necessário como lista key=value[,] (por exemplo, Int32=Long,UInt64=String). Aviso de descontinuação: a propriedade V1 typeMappings é suportado, mas será removido. Migre para a nova propriedade. (https://github.com/ClickHouse/clickhouse-java/issues/2858)

  • [client-v2, jdbc-v2] Adicionado suporte de sequência binária opcional por meio da propriedade de configuração binary_string_support (ou Client.Builder#binaryStringSupport(boolean)), desabilitado por padrão. A configuração é resolvida por operação de as configurações mescladas de client e de consulta, para que possam ser substituídas por uma única solicitação por meio do binary_string_support opção de operação (por exemplo, QuerySettings#setOption(ClientConfigProperties.BINARY_STRING_SUPPORT.getKey(), true)) independentemente do padrão de nível client. Quando ativado, as colunas String e FixedString de nível superior são lidas em um StringValue que preserva os bytes brutos em vez de decodificá-los em um String, permitindo não-UTF-8/binário conteúdo para ida e volta byte por byte. StringValue expõe os bytes via toByteArray()/asByteBuffer() e decodifica preguiçosamente um String via asString() (UTF-8 por padrão ou um Charset fornecido pelo chamador). Valores aninhados dentro contêineres (Array, Map, Tuple, Nested, Variant) continuam a ser lidos como String, uma vez que esses tipos não são espera-se que carregue strings grandes/binárias. No lado JDBC, ResultSet#getBinaryStream(int) e ResultSet#getBinaryStream(String) agora estão implementados (anteriormente sem suporte) e, junto com getBytes(...), retornar os bytes brutos da coluna.

  • [client-v2] Adicionado Client#cancelTransportRequest(String queryId) para cancelar uma solicitação em andamento que ainda não foi recebeu uma resposta do servidor, identificada pelo ID de consulta fornecido nas configurações da operação. Isto aborta o solicitação no lado client (cancela a operação IO subjacente), mas não emite um KILL QUERY no servidor, portanto, uma consulta que já começou a ser executada pode continuar a ser executada no lado do servidor. Recomenda-se usar o tempo limite de operação configurações sempre que possível; este API destina-se a abortar explicitamente uma solicitação do client.

Melhorias

  • [jdbc-v2, client-v2] Adicionado suporte para nomes de host com sublinhado (_). Agora é possível especificar o endpoint como ch_db_01. Isso é usado principalmente no ambiente k8s. (https://github.com/ClickHouse/clickhouse-java/issues/2792, https://github.com/ClickHouse/clickhouse-java/issues/2753)

Dependências atualizadas

  • [testes] Bump org.postgresql:postgresql de 42.6.1 para 42.7.11

Documentos e exemplos

  • [client-v2] Adicionado exemplo de trabalho com a biblioteca Apache Arrow usando client. (https://github.com/ClickHouse/clickhouse-java/pull/2820)

  • [repo] Adicionado um guia de contribuição. Por favor, revise e envie-nos seus comentários. (https://github.com/ClickHouse/clickhouse-java/pull/2859)

Correções de bugs

  • [jdbc-v2, client-v2] Corrigido o tratamento de erros para respostas que não são um erro ClickHouse, como a resposta 404. (https://github.com/ClickHouse/clickhouse-java/issues/2803)

  • [jdbc-v2, client-v2] Corrigida a configuração de null como senha. Anteriormente, ele foi convertido para literal null. Ainda assim recomendamos passando string vazia. (https://github.com/ClickHouse/clickhouse-java/pull/2809)

  • [jdbc-v2, client-v2] Corrigido ClickHouseBinaryFormatReader::getBigDecimal truncando silenciosamente um número inteiro grande. (https://github.com/ClickHouse/clickhouse-java/issues/2748)

  • [jdbc-v2, client-v2] Corrigido o tratamento de valores NULL para colunas Variant e Dynamic. Indicador anterior de NULL não foi configurado e lido. (https://github.com/ClickHouse/clickhouse-java/issues/2789, https://github.com/ClickHouse/clickhouse-java/issues/2791)

  • [jdbc-v2] Corrigido Statement.cancel() lançando SESSION_IS_LOCKED quando a instrução estava sendo executada dentro de um Sessão ClickHouse. O driver agora aceita session_id, session_check e session_timeout como primeira classe propriedades de conexão e as suprime corretamente ao emitir um KILL QUERY durante o cancelamento. Isto garante a a solicitação de cancelamento é executada fora da sessão e não responde mais à consulta em execução da sessão bloqueio. (https://github.com/ClickHouse/clickhouse-java/issues/2690, https://github.com/ClickHouse/clickhouse-java/issues/2881)

  • [jdbc-v2] Adicionada opção para especificar o nome do cluster para operações no cluster. Um deles é KILL QUERY .. ON CLUSTER <cluster_name>. Utilize DriverProperties.CLUSTER_NAME (jdbc_cluster_name) para definir o nome do cluster a ser utilizado nessas consultas. (https://github.com/ClickHouse/clickhouse-java/issues/2837)

  • [jdbc-v2, client-v2] Corrigida gravação de marcador anulável para Tuple aninhados e valores `Map. (https://github.com/ClickHouse/clickhouse-java/issues/2721)

  • [jdbc-v2] Corrigido ResultSet.getObject vazando no suporte interno StringValue para String/FixedString colunas quando binary_string_support está habilitado. getObject(column, byte[].class) agora retorna os bytes brutos exatos, e getObject(column, Object.class) e as sobrecargas sem tipo getObject(column) agora retornam um String decodificado em vez do suporte interno.
