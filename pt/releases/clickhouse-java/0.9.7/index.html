clickhouse-java v0.9.7

Notas importantes

  • Foi alterado o comportamento do Client.Builder.addEndpoint(String): agora ele salva o caminho base da URL (mais em https://github.com/ClickHouse/clickhouse-java/issues/2344). Anteriormente, esse método ignorava o caminho base. Preste atenção, pois este método ainda ignora os parâmetros de consulta. O endpoint NÃO é como o URL JDBC. Client designou um método construtor para definir a configuração.

Mudanças significativas

  • [client-v2] Client.Builder#build() agora lança ClientMisconfigurationException quando uma propriedade de configuração desconhecida é passada. Anteriormente, propriedades desconhecidas eram ignoradas silenciosamente, o que causava comportamentos e problemas inesperados. Para restaurar o comportamento antigo, adicione ignore_unknown_config_key=true às propriedades client. As propriedades somente do driver JDBC (por exemplo, ssl) não são mais encaminhadas para o client subjacente. (https://github.com/ClickHouse/clickhouse-java/issues/2658)

  • [client-v2] As colunas Date/Date32 agora são decodificadas como LocalDate sem qualquer ajuste de fuso horário. Anteriormente, os valores Date podiam ser retornados como ZonedDateTime. Os aplicativos que precisam de um ZonedDateTime devem construí-lo a partir do LocalDate retornado usando seu próprio contexto de fuso horário. Leia mais sobre isso - https://clickhouse.com/docs/integrations/language-clients/java/jdbc_date_time_guide (https://github.com/ClickHouse/clickhouse-java/pull/2727)

Melhorias

  • [client-v2] Adicionada opção para enviar parâmetros de consulta no corpo da solicitação HTTP usando codificação de formulário multipart. Habilitado através da nova propriedade de configuração client.http.use_form_request_for_query (ou Client.Builder#useHttpFormDataForQuery()). Útil quando os parâmetros de consulta excedem os limites de comprimento de URL. (https://github.com/ClickHouse/clickhouse-java/issues/2324)

  • [client-v2] QueryResponse, InsertResponse e CommandResponse agora expõem getServerDisplayName() para recuperar o valor do cabeçalho de resposta HTTP X-ClickHouse-Server-Display-Name. Um mapa completo dos cabeçalhos de resposta na lista de permissões pode ser acessado via getResponseHeaders(). (https://github.com/ClickHouse/clickhouse-java/issues/2347)

  • [client-v2] Adicionado getObjectArray() a ClickHouseBinaryFormatReader e GenericRecord para ler colunas Array(...) como Object[], incluindo suporte recursivo para matrizes aninhadas. getStringArray() agora também lida com Array(Enum*) retornando nomes de enum. (https://github.com/ClickHouse/clickhouse-java/issues/2738)

  • [jdbc-v2] Adicionado suporte para leitura e gravação byte[] para colunas String/FixedString. PreparedStatement#setBytes() codifica o valor como uma expressão ClickHouse unhex() para preservar bytes brutos; ResultSet#getBytes() retorna os bytes UTF-8 do valor da string. (https://github.com/ClickHouse/clickhouse-java/pull/2734)

  • [client-v2] Preservar parte do caminho da URL passada para o método construtor `addEndpoint() (https://github.com/ClickHouse/clickhouse-java/pull/2691)

Tratamento de data e hora

  • [docs] Adicionado um documento que explica como o driver lida com diferentes valores de data/hora.

  • [client-v2, jdbc-v2] Corrigida a gravação de valores Date/Time/Timestamp para que as conversões de fuso horário sejam executadas explicitamente. Anteriormente, a codificação ingênua de fuso horário causava erros de mudança de dia e de precisão, especialmente quando um fuso horário Calendar ou JVM não padrão estava em uso. (https://github.com/ClickHouse/clickhouse-java/issues/2701, https://github.com/ClickHouse/clickhouse-java/issues/2065, https://github.com/ClickHouse/clickhouse-java/issues/2496, https://github.com/ClickHouse/clickhouse-java/issues/1220, https://github.com/ClickHouse/clickhouse-java/issues/1117, https://github.com/ClickHouse/clickhouse-java/issues/1048, https://github.com/ClickHouse/clickhouse-java/issues/2381, https://github.com/ClickHouse/clickhouse-java/issues/1735, https://github.com/ClickHouse/clickhouse-java/issues/2542, https://github.com/ClickHouse/clickhouse-java/issues/2557)

  • [client-v2, jdbc-v2] Corrigida a leitura dos valores Date/Time/DateTime para serem consistentes e corretos. Date/Date32 agora são decodificados como LocalDate (sem fuso horário), enquanto Time/Time64 são decodificados como LocalDateTime baseado em UTC. Novo getLocalTime() API adicionado aos leitores para acesso LocalTime. A leitura de data/hora das colunas Dynamic e Variant também é fixa. (https://github.com/ClickHouse/clickhouse-java/pull/2727)

  • [jdbc-v2] DatabaseMetaDataImpl#getTypeInfo() agora retorna informações de tipo em ordem alfabética determinística, correspondendo ao comportamento do driver v1. (https://github.com/ClickHouse/clickhouse-java/pull/2733)

Analisador SQL (jdbc-v2)

  • [jdbc-v2] Corrigida falha do analisador SQL ao lidar com palavras-chave ClickHouse usadas como nomes de tabelas ou aliases de colunas (por exemplo, AS value, FROM date). Ambos os analisadores ANTLR4 e JavaCC agora mantêm uma lista de palavras-chave não reservadas permitidas em posições de identificadores. Também foi corrigida a análise de DESCRIBE (SELECT ...), operador IN em SELECT e acesso de array entre colchetes em expressões. (https://github.com/ClickHouse/clickhouse-java/issues/2718)

  • [jdbc-v2] Analisadores SQL atualizados para reconhecer novas palavras-chave ClickHouse (ABI, ARGUMENTS, DRY, LANGUAGE, RETURNS, RUN) introduzidas em compilações recentes do ClickHouse HEAD. Anteriormente, as consultas que usavam essas palavras-chave como identificadores falhavam na análise. (https://github.com/ClickHouse/clickhouse-java/pull/2761)

  • [jdbc-v2] Corrigida falha do analisador SQL em instruções contendo o operador ^ (caret), como toJSONString(data.^header_index). Um novo token CARET agora é reconhecido e permitido em cadeias de identificadores pontilhados. (https://github.com/ClickHouse/clickhouse-java/issues/2768)

Manipulação de array e coleção

  • [jdbc-v2] Corrigido DataTypeConverter causando NPE ao converter matrizes aninhadas em strings (por exemplo, ResultSet#getString() em uma coluna Array(Array(...))). O conversor agora é seguro para reentrada. Anteriormente estava jogando NullPointerException. (https://github.com/ClickHouse/clickhouse-java/issues/2723)

  • [client-v2, jdbc-v2] Corrigida a conversão de valores multidimensionais List/matriz em matrizes Java. As dimensões da matriz filho agora são calculadas corretamente a partir do nível de profundidade pai. Anteriormente, a conversão de List<List<T>> ou estruturas semelhantes produzia resultados incorretos. (https://github.com/ClickHouse/clickhouse-java/issues/2741)

  • [client-v2] Corrigida a decodificação de array binário quando o primeiro elemento de um array é um Map ou List vazio. Anteriormente, isso causava um erro de incompatibilidade de tipo durante o preenchimento da matriz. (https://github.com/ClickHouse/clickhouse-java/issues/2499, https://github.com/ClickHouse/clickhouse-java/issues/2657, https://github.com/ClickHouse/clickhouse-java/issues/2703)

Correções de bugs

  • [jdbc-v2] Corrigido DatabaseMetaDataImpl#getJDBCMajorVersion() e getJDBCMinorVersion() retornando a versão do driver ClickHouse em vez da versão da especificação JDBC suportada. Agora retorna corretamente 4 e 2 (JDBC 4.2). (https://github.com/ClickHouse/clickhouse-java/pull/2736)

  • [jdbc-v2] Adicionado mapeamento de todos os mecanismos de tabela ClickHouse conhecidos para tipos de tabela JDBC. Adicionado MATERIALIZED VIEW como um novo tipo de tabela. getTables() agora relata corretamente tabelas de mecanismo remoto/externo que antes eram invisíveis. (https://github.com/ClickHouse/clickhouse-java/issues/2664)

  • [jdbc-v2] Corrigido NullPointerException em metadados do tipo JDBC para colunas do tipo Map, IPv4, IPv6, UUID, BFloat16, Decimal256, Geometry, todos os tipos Interval*, JSON, LowCardinality, Nullable, Variant, Dynamic e outros. Anteriormente, esses tipos não tinham mapeamento de classe Java. (https://github.com/ClickHouse/clickhouse-java/issues/2711)

  • [jdbc-v2] Os códigos de erro do servidor ClickHouse agora são propagados para SQLException#getErrorCode(). Anteriormente, o SQLException era criado sem o código de erro do fornecedor, tornando impossível distinguir os tipos de erro de forma programática. (https://github.com/ClickHouse/clickhouse-java/issues/2717)

  • [client-v2] Corrigido max_execution_time que não estava sendo enviado corretamente ao servidor. Anteriormente, era tratado como uma opção client e ignorado por ClickHouse; agora é transmitido como uma configuração do servidor. (https://github.com/ClickHouse/clickhouse-java/issues/2750)

  • [client-v2] Corrigido hasValue(columnName) lançando uma exceção quando o nome da coluna não existe. Anteriormente, fazer referência a uma coluna desconhecida ou a um índice fora do intervalo por meio de hasValue() geraria; agora retorna false. (https://github.com/ClickHouse/clickhouse-java/issues/2755)

  • [jdbc-v2] Corrigido PreparedStatement relatando parâmetros ausentes usando índices baseados em 0 na mensagem de erro. As posições dos parâmetros JDBC são baseadas em 1; a mensagem de erro agora reflete isso corretamente. (https://github.com/ClickHouse/clickhouse-java/pull/2749)

  • [jdbc-v2] Propriedades de conexão JDBC v1 herdadas portadas (CUSTOM_HTTP_PARAMS, CUSTOM_SETTINGS, HTTP_CONNECTION_PROVIDER, REMEMBER_LAST_SET_ROLES, USE_SERVER_TIME_ZONE_FOR_DATES) para JDBC v2. Obrigatório para integrações que compartilham código de configuração JDBC v1/v2. Os valores custom_http_params e custom_settings são convertidos automaticamente nas configurações do servidor. (https://github.com/ClickHouse/clickhouse-java/pull/2757)

  • [client-v2, jdbc-v2] Corrigidas propriedades de configuração com prefixo custom_ que não eram encaminhadas ao servidor como configurações personalizadas ao usar o prefixo custom_. Também foram corrigidas propriedades somente de driver (por exemplo, ssl) sendo encaminhadas incorretamente para o HTTP client. (https://github.com/ClickHouse/clickhouse-java/issues/2658)
