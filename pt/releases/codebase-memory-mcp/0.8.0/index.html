codebase-memory-mcp 0.8.0

📦 Página de lançamento arquivada — os binários desta versão não são mais publicados. Obtenha o último lançamento.

O título: três novos mecanismos LSP com reconhecimento de tipo. Java, Kotlin e Rust agora obtêm resolução LSP totalmente híbrida — resolução de chamada com reconhecimento de tipo por meio de hierarquias de classe, ligação de anotação/atributo, correspondência de sobrecarga com reconhecimento de assinatura, manipulação de genéricos e inferência de tipo de arquivo cruzado — unindo C/C++, Python, TypeScript/JavaScript, Go, C# e PHP para 9 linguagens sob LSP híbrido.

Inteligência de arquitetura

  • Detecção de comunidade Leiden: get_architecture agora apresenta comunidades Leiden multinível (substituindo Louvain de nível único) — limites reais de módulo em gráficos do tamanho de kernel, calculados em segundos em vez de minutos.
  • Métricas de gargalo computacional consultáveis: as funções carregam métricas de complexidade, profundidade de loop e padrão de varredura no gráfico. Agora você pode consultar Cypher em sua base de código para obter seus próprios pontos de acesso algorítmicos. (Usamos exatamente isso para encontrar e consertar vários dos nossos, veja abaixo.)
  • Suporte Helm: modelos de gráficos, ligação de chamadas include e bordas de dependência Chart.yaml; Rótulos de bloco HCL dobrados em nomes de nós; As macros do pré-processador C/C++ agora são nós de macro de primeira classe (2,3 milhões deles no kernel Linux).

Estabilidade — o maior impulso de endurecimento até agora

A frota de lançamento agora indexa 16 grandes repositórios OSS de ponta a ponta – o kernel Linux (4,8 milhões de nós), elasticsearch, kubernetes, o compilador TypeScript, bitcoin, zig, symfony e muito mais – com portas de validade em nível de banco de dados. Essa busca, além de excelentes relatórios da comunidade, encerrou uma longa lista de falhas:

  • Família de falhas de código C++/modelado eliminada: matrizes de argumentos de modelo não inicializadas, pesquisas de parâmetros fora dos limites, recursão de resolução ilimitada, explosões de avaliação de expressão - relatadas em #424, #427/#428/#432, #312, #322/#323, #336, #344, #355, #360, #385.
  • Unificação de alocadores (#424): todo o binário — fornecedor de tree-sitter, SQLite, libgit2 — agora é executado em um alocador, encerrando uma classe de corrupção de heap de alocador cruzado em C++ complexo.
  • Loop de falha de inicialização corrigido (#235, #439): um estouro de buffer de pilha no caminho de erro da lista de projetos poderia SIGABRT o servidor para todos os projetos; um banco de dados de cache corrompido não interrompe mais todas as sessões.
  • Integridade do banco de dados, ponta a ponta: chaves de índice superdimensionadas agora transbordam corretamente para páginas overflow, todas as propriedades JSON são escapadas e validadas no produtor, o índice url_path sempre corresponde à coluna gerada e os arquivos WAL são verificados no fechamento/inicialização (#387). Cada banco de dados na frota de 16 repositórios passa pela limpeza PRAGMA integrity_check.
  • Ciclo de vida do servidor: os servidores stdio saem com seus pais por meio de um death watchdog (#406), MCP ping é suportado (#354), os IDs de string JSON-RPC são preservados (#253), o nível de log é configurável via CBM_LOG_LEVEL (#413).
  • Windows: API de caracteres largos para caminhos não ASCII (nº 386), passagem de histórico git compatível com cmd.exe (nº 324), sondagem PATHEXT (nº 221), travamento de empacotamento corrigido - o conjunto de testes completo é verde no Windows.
  • Mais: rotas fantasmas gRPC (#294), modo moderate eliminando subárvores silenciosamente (#411) com diretórios excluídos agora relatados nos resultados da indexação, nomes de projetos seguros para validadores (#349), diagnóstico de sinalizadores de UI (#350).

Desempenho em escala de kernel

  • Retrabalho de memória: streaming de gravador de dump SQLite, internação de string, recuperação de página do alocador e contrapressão de extração — o kernel Linux completo é indexado em aproximadamente 4 minutos em um laptop, dentro de um orçamento de memória limitado; A detecção de CPU/memória com reconhecimento de cgroup e uma substituição CBM_WORKERS (#364/#365) tornam o comportamento do contêiner previsível.
  • Caminhos quentes quadráticos eliminados, vários encontrados apontando as novas métricas de gargalo em nossa própria base de código: resolução de sobrecarga de LSP cruzado C/C++ (#410), construção de registro e caminhos de pesquisa nos resolvedores PHP/Python/Java/Kotlin e computação de limite de arquitetura. Grandes monorepos PHP e Java veem índices completos mais rápidos em ordem de magnitude (symfony 35x, elasticsearch 9x vs. compilações iniciais deste ciclo).
  • A qualidade do gráfico melhorou com essas correções – a cobertura da resolução e a fidelidade das bordas são melhores em todos os idiomas suportados.

Camada de consulta

  • Cypher: predicados EXISTS {} em WHERE, COUNT(DISTINCT) (#239), alternância de rótulo (n:A|B) (#242), testes de rótulo em WHERE (#241), WITH DISTINCT (#238), funções de introspecção de string/escalar/entidade, escalares multi-argumentos — e a sintaxe não suportada agora falha ruidosamente em vez de retornar vazios silenciosos (#373).
  • search_code: erros de regex inválidos em vez de resultados vazios (#283), & em caminhos, tempo nas respostas, file_pattern sem curinga como substring (#200), .mjs/.cjs/.mts/.cts indexado (#197), modelos Blade mapeados (#258), importações de R box::use()/library() (#218/#219).

Uma rede de segurança muito maior

  • Novo conjunto de regressão por gramática em todas as 159 gramáticas, além de conjuntos de testes para extração, criação de bordas e resolução de LSP — o conjunto agora executa 5.500+ testes sob uma política estrita de não pular (pular são falhas graves).
  • As reproduções de falhas são executadas como testes isolados de subprocessos com asserções de sinal de saída; ASan/LSan são executados em todo o conjunto; a perna de compilação do macOS Intel agora está bloqueando, então o darwin-amd64 sempre é enviado.

Distribuição e integrações

  • Publicado no Registro oficial do MCP e no Diretório Glama; binário Linux estático portátil em todos os caminhos de instalação/atualização.
  • Recibos legíveis por máquina install --plan antes de qualquer mutação de configuração (#388), detecção de Cursor IDE (#222), manipulação de PATH nativo de peixe (#319), $CLAUDE_CONFIG_DIR respeitado (#321), ganchos SessionStart para Codex, Gemini CLI e Antigravity (#330), armazenamento ADR unificado entre ferramentas MCP e a UI (#256).
