codebase-memory-mcp v0.5.7

v0.5.7 — Revisão de testes de estabilidade, instalação e resistência

53 commits, 3 PRs mesclados, 10 bugs fechados. A versão de estabilidade mais significativa desde a reescrita do Go→C.

Correção de simultaneidade de banco de dados (crítica)

  • Causa raiz encontrada: três threads (manipulador MCP, autoindex, observador) podem corromper o banco de dados - rename(.db.tmp, .db) em conexões SQLite abertas produziu mais de 48 mil linhas de lixo
  • Mudança de arquitetura: rename() totalmente eliminado. A indexação grava diretamente, a reindexação exclui primeiro o banco de dados antigo, os upserts incrementais inalterados
  • Pipeline lock serializa execuções simultâneas; banco de dados corrompido detectado e limpo automaticamente

Instalar e atualizar

  • install.sh + install.ps1 incluído em todos os arquivos de lançamento com flag --skip-config (#145)
  • Elimina servidores MCP obsoletos, elimina a quarentena do macOS, sinaliza binários ad-hoc
  • Atualiza todas as 10 configurações do agente em cada atualização
  • Extração zip na memória – não é necessário unzip no Windows
  • Manipulação de caminho do Windows .exe corrigida durante instalação, atualização e desinstalação

Normalização de caminho do Windows (PR #146)

  • Separadores de caminho misto normalizados para barras em todos os pontos de entrada
  • cbm_normalize_path_sep() funciona em TODAS as plataformas (arquivos de banco de dados multiplataforma)

Soak Test Suite (Novo)

  • Imersão rápida (10 min), imersão ASan (15 min), resistência semanal (4h) — tudo por plataforma
  • Rastreamento de RSS, desvio de FD, latência de consulta, recuperação de falhas (kill -9 + reinicialização limpa)
  • Todos os níveis de absorção são portões de liberação — não é permitido liberar navios sem passar

Correções de bugs

  • #139 Estouro de pilha no índice automático — pilha de threads padrão de 8 MB (obrigado @theron-sapp pelo relatório detalhado de falhas com endereços de pilha, tabela de frequência e solução alternativa!)
  • #140 index_repository falha no Windows — este relatório de @Flipper1994 desencadeou a revisão completa da arquitetura de simultaneidade!
  • #137 detect_changes falha em caminhos com espaços (obrigado @shekthesnek pela observação precisa de que 12 ferramentas funcionaram, mas 1 não!)
  • #135 macOS Gatekeeper bloqueia binários (obrigado @heraque pela análise completa de xattr/spctl/codesign!)
  • #133 search_code rejeita a barra invertida do Windows (obrigado @ckelly8 por identificar a causa raiz!)
  • #130 Extratores de importação O(N²) ficam pendurados em arquivos grandes (obrigado @halindrome pelo problema E pela correção no PR #131!)
  • #127 Conexão fechada constantemente — todos os caminhos de travamento corrigidos (obrigado @kingofthebongo2008!)
  • #145 Ignorar configuração do agente nos scripts de instalação (obrigado @sherif-fanous — implementado no mesmo dia!)
  • Estouro de buffer de arena, lacunas de detecção de teste, vazamentos de memória, CodeQL TOCTOU, auto-eliminação de taskkill, tradução de caminho MSYS2 python3, tre ssize_t vendido

Teste

  • 2.586 testes de unidade (acima de 2.042), zero ignorados, zero vazamentos de memória
  • Mais de 480 novos testes cobrindo arena, FQN, buffer gráfico, despacho MCP, pipeline, loja, YAML, observador
  • Suíte de fumaça de 15 fases em todas as plataformas, incluindo Windows
  • Testes de imersão como porta de lançamento – resistência verificada antes de cada lançamento

Segurança

  • Instale scripts no VirusTotal scan junto com binários (tempo limite de 120 minutos, todos os arquivos devem passar)
  • system() eliminado de todo o código de produção
  • Somas de verificação de integridade de dependência de fornecedor aplicadas
