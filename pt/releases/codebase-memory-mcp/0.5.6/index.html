codebase-memory-mcp v0.5.6

O que há de novo no v0.5.6

search_code v2 — Pesquisa de código aumentado em gráfico

A ferramenta search_code foi completamente reescrita com um pipeline de 4 fases que combina velocidade grep com inteligência de gráfico de conhecimento:

  • **3 modos de saída **: compact (padrão - nomes de funções + linhas de correspondência), full (corpos de função completos com correspondências destacadas), files (lista de arquivos com contagens de correspondências)
  • Classificação gráfica: resultados classificados por importância estrutural (definições primeiro, funções populares em seguida, testes por último)
  • Expansão de bloco: grep corresponde automaticamente expandido para conter limites de função - chega de trechos de linha fragmentados
  • path_filter: escopo de pesquisas em diretórios específicos (por exemplo, apenas src/)
  • Linhas context: contexto configurável em torno das partidas no modo completo
  • Resumo da distribuição de diretórios: mostra quais diretórios contêm correspondências Volta normalmente para grep bruto quando o projeto não está indexado.

Kubernetes e indexação Kustomize

Suporte completo de infraestrutura como código para manifestos Kubernetes:

  • Analisa implantações, serviços, ConfigMaps, segredos, Ingress, CronJobs e mais de 20 tipos de recursos
  • Kustomize resolução de sobreposição (base → relacionamentos de sobreposição)
  • Os nós de recursos aparecem no gráfico de conhecimento com rótulos, namespaces e especificações de contêiner
  • Novo rótulo do nó Resource no esquema gráfico

Mapeamentos de extensões definidos pelo usuário

Extensão de arquivo personalizada → mapeamentos de idioma via .codebase-memory.json (nível de projeto) ou $XDG_CONFIG_HOME/codebase-memory-mcp/config.json (global):

{"extra_extensions": {".blade.php": "php", ".mjs": "javascript"}}

A configuração do projeto tem prioridade sobre a configuração global.

Correções de segurança

  • Injeção de SQL na pesquisa de loja/BFS e injeção de argumento no servidor HTTP (#124 — @map588)
  • Use-after-free no caminho de obtenção do handle_manage_adr (#126 — @halindrome)
  • Prevenção de arquivo .db fantasma: os manipuladores de consulta agora verificam a existência do projeto antes de abrir o SQLite — evita o acúmulo de arquivos de banco de dados vazios (#120)
  • Substituição binária: novo cbm_replace_binary com padrão de desvinculação antes de gravação, lida com destinos somente leitura e substituto de renomeação do Windows (#114)

Correções de estabilidade e compatibilidade

  • Buffering stdio MCP: incompatibilidade corrigida de poll()/getline() FILE* que fazia com que tools/list travasse em alguns clients (#99 — @halindrome)
  • SQLite WAL busy_timeout: definido antes de journal_mode=WAL para evitar SQLITE_BUSY na contenção de bloqueio (#117 — @halindrome)
  • Analisador de importação O(N²) → O(N): substituiu o loop ts_node_child() indexado pelo TSTreeCursor walk — corrige a lentidão quadrática em arquivos com muitas importações (#107 — @halindrome)
  • Incompatibilidade de nome do projeto de sessão: detect_session agora usa o mesmo cbm_project_name_from_path() como pipeline
  • Windows: correção do nome do arquivo zip da UI, wrappers de compatibilidade setenv/unsetenv, fallback USERPROFILE quando HOME não definido
  • Linux: adicione -D_GNU_SOURCE para visibilidade strcasestr (#111 — @trollkotze)
  • libgit2: corrige erro de compilação -Wmissing-field-initializers (#91 — @jsyrjala)
  • Vazamento de memória: resolve_store vazou conexão SQLite ao consultar .db desvinculado após delete_project

Testes abrangentes de fumaça

Expandido de 4 fases para 7, cobrindo todo o ciclo de vida binário:

  • Fase 5: transporte stdio MCP — inicializar handshake, ferramentas/lista, ida e volta de chamada de ferramenta, enquadramento de comprimento de conteúdo (compatibilidade com OpenCode)
  • Fase 6: subcomandos CLI - instalar/desinstalar/atualizar --dry-run, definir/obter/redefinir configuração, substituição binária simulada com caso extremo somente leitura
  • Fase 7: Chamadas de ferramentas avançadas MCP — search_code v2, get_code_snippet via JSON-RPC Os testes de fumaça agora são executados na infraestrutura de teste Docker (test-infrastructure/run.sh smoke) e em CI em todas as 10 combinações de plataforma x variante.

Atualizar melhorias no comando

  • Sinalizador --dry-run: mostra o que aconteceria sem baixar ou modificar arquivos
  • Sinalizadores --standard / --ui: pular prompt de variante interativo (compatível com CI)
  • Lembrete de reinicialização após atualização bem-sucedida

CI e infraestrutura

  • Ações GitHub fixadas para confirmar SHAs (dependebot: VirusTotal 5.0.0, nó de configuração 6.3.0, cosign-installer, attest-build-provinance)
  • Infraestrutura de teste Docker: serviços smoke e smoke-amd64 para testes de fumaça entre plataformas locais
  • Limpeza de artefatos da era Go, atualização de THIRD_PARTY.md para projeto C puro
