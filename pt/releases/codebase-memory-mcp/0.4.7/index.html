#codebase-memory-mcp v0.4.7

Destaques

Resolução de tipo híbrido Go LSP (experimental)

Um novo mecanismo híbrido tree-sitter + LSP para Go traz resolução de chamadas com reconhecimento de tipo de arquivo cruzado - uma novidade para codebase-memory-mcp. O resolvedor de tipo baseado em C (internal/cbm/lsp/) combina análise AST de tree-sitter com um registro de tipo leve, rastreador de escopo e mais de 30.000 definições Go stdlib para resolver chamadas de método, despachos de interface e acessos de campo struct através dos limites do pacote. Este é um passo fundamental: a mesma abordagem híbrida será estendida para TypeScript, Python, Java e outras linguagens em versões futuras. Componentes principais:

  • lsp_bridge.go — estrutura CrossFileDef e ponte RunGoLSPCrossFile CGo
  • go_lsp_cross.go — índice de definição de arquivo cruzado com campo struct e enriquecimento de método de interface
  • go_dep_registry.go — analisador de módulo Go de terceiros para resolução com reconhecimento de dependência
  • lsp/go_lsp.c — Resolvedor tipo C com rastreamento de variáveis com reconhecimento de escopo, resolução de conjunto de métodos e inferência de direção de canal
  • lsp/generated/go_stdlib_data.c — 30K+ Go definições de tipo/função stdlib para resolução pronta para uso

Suporte .gitignore e .cbmignore

O indexador agora respeita os padrões .gitignore — código gerado, artefatos de construção e dependências de fornecedores que são gitignored não são mais indexados. Este é o recurso mais solicitado desde o lançamento.

  • Suporte completo à hierarquia .gitignore: arquivos .gitignore aninhados, .git/info/exclude, negação (!), globstar (**), padrões somente de diretório (logs/)
  • .cbmignore — um novo arquivo que empilha padrões de ignorar adicionais sobre .gitignore, específico para indexação codebase-memory-mcp
  • .cgrignore permanece com suporte para compatibilidade com versões anteriores
  • Zero vazamento de identificador de arquivo — o correspondente de repositório personalizado lê e fecha arquivos imediatamente, evitando vazamento de identificador da biblioteca upstream (crítico para Windows)

Correções de segurança de memória

  • Swift scanner heap-buffer-overflow — o scanner Swift tree-sitter vendido chamado calloc(0, sizeof(ScannerState)), alocando uma região de 0 ou 1 byte, então gravou um uint32_t (4 bytes) nela. Corrigido para calloc(1, ...). Detectado pelo novo trabalho de CI AddressSanitizer.
  • Vazamento de identificador de arquivo no Windows — o NewRepository da biblioteca go-gitignore abre arquivos .gitignore, mas nunca os fecha. Substituído por um repoMatcher personalizado que usa os.ReadFile + strings.NewReader — zero identificadores vazados. Corrige falhas de CI do Windows.

Novos recursos

  • Armazenamento de configuração persistente — ConfigStore apoiado por SQLite para configurações do servidor (auto_index, auto_index_limit, mem_limit). Subcomando de configuração CLI para obter/definir/listar/excluir.
  • Comprehensive --help / -h — todas as 14 ferramentas MCP documentadas com esquemas de parâmetros e exemplos de carga útil JSON
  • Symlink skipping — arquivos e diretórios com links simbólicos não são mais indexados, evitando nós duplicados no gráfico
  • .worktrees directory skip — os diretórios git worktree são excluídos da indexação (obrigado @wassertim, #37)

Correções de bugs

  • Cypher LIMIT respeitado — cláusulas LIMIT explícitas em query_graph Consultas Cypher agora são respeitadas em vez de serem silenciosamente limitadas (obrigado @re-thc, #40)
  • 54 problemas de golangci-lint corrigidos — errcheck, gocognit, funlen, nilerr, gocritic, gosec, noctx em 10 arquivos
  • Lista de ignorados codificada expandida — 28 novos diretórios específicos do ecossistema adicionados (.next, .nuxt, .terraform, zig-cache, .cargo, bazel-out, etc.). Diretórios genéricos (bin, build, out) movidos apenas para modo rápido para evitar falsas exclusões em projetos Go/CMake/Maven.

Infraestrutura

  • Trabalho de CI do AddressSanitizer — o novo trabalho de fluxo de trabalho test-asan detecta heap-buffer-overflow, use-after-free e outros bugs de memória no código C
  • Melhorias no teste de CI — melhorias no fluxo de trabalho para testes entre plataformas
