Agente Hermes v0.22.0

Data de lançamento: 13 de outubro de 2026 Desde v0.21.0: ~24.200 commits · ~6.080 PRs mesclados · ~15.600 arquivos alterados · ~2.045.000 inserções · ~1.140.000 exclusões · ~7.180 problemas encerrados · ~2.520 colaboradores

A Liberação do Limiar. Hermes era o deus dos limiares: a porta, a travessia, a pedra limite. v0.21.0 montou o panteão; v0.22.0 trata de passar pela porta. Uma nova instalação de desktop agora abre em um bate-papo de configuração guiada que funciona em um modelo de teste gratuito, então um novato está conversando com Hermes antes de possuir uma chave API. Os conectores transportam o agente para os aplicativos que você já usa, sem necessidade de conta para iniciar. Os modelos locais levam-no para o seu próprio hardware com um tempo de execução click llama.cpp. E o limite em si ficou mais robusto: versões estáveis ​​​​testadas do SemVer que são instaladas por padrão, pacotes de desktop assinados (incluindo a Microsoft Store) e um gerenciador de pacotes abaixo de tudo. Em torno dessa coluna: um catálogo de 600 plug-ins, o modelo wave Claude 5.5 / GPT-6, login do gerenciador de senhas para o navegador, uma tela de bot que você pode controlar, um back-end e um gateway para cada perfil e uma base de código um terço menor. Esta é a maior janela que a Hermes enviou, cerca de 2,5x o ciclo v0.21.0, e acumula e documenta totalmente os lançamentos de patch v0.21.1 – v0.21.7.

⚠️ Notas de atualização

  • Python 3.14 é o tempo de execução para instalações gerenciadas (o gerenciador de pacotes instala para você). KittenTTS não está disponível em 3.14. (#102765)
  • A área de trabalho do Windows é somente MSIX e precisa do Windows 11 22H2 ou mais recente; os instaladores NSIS/MSI desapareceram. O aplicativo macOS é Apple Silicon apenas em versões padrão. (#102765, #136603)
  • Um gateway por máquina é o padrão. hermes update dobra gateways por perfil no padrão multiplexado quando nada entra em conflito. (#112854)
  • Os bate-papos não são mais redefinidos em um cronômetro inativo/diário. Os modos inativo/diário do session_reset foram desativados (as configurações que ainda os definem registram um aviso); /new ou /reset começa do zero. (#105021, #126244)
  • Sessões antigas são removidas automaticamente. sessions.auto_prune agora está ativado por padrão: sessões encerradas inativas por 90 dias são excluídas na inicialização. Sessões fixadas e abertas nunca são tocadas; configure sessions.auto_prune: false para manter tudo.
  • Provedores de memória migraram para plug-ins de catálogo (Honcho, Supermemory, Hindsight, Mem0, OpenViking, Holographic), assim como Home Assistant, Spotify e Langfuse. Os usuários existentes são migrados na atualização ou na primeira inicialização, com os dados intactos. ByteRover e RetainDB permanecem agrupados.
  • Autores de plug-ins: a antiga camada de importação de compatibilidade de plug-ins desapareceu (#126164), hermes sync (Skill Sync) foi removido (#132465) e o scanner tirith incluído foi removido (#133832). Várias ferramentas foram renomeadas (todo → todo_list, cronjob → cronjob_manage, process → process_manage); os nomes antigos ainda funcionam. (#97979)

⏰ Cron, Kanban e Delegação

Cron

  • Os trabalhos seguem seu modelo principal — Os trabalhos não fixados usam o modelo configurado no momento do disparo; pinned bloqueia um. (#113679)
  • Programações de autocorreção — Um incêndio que nunca atingiu o modelo (por exemplo, após a ativação) é executado novamente após 5, 15 e 30 minutos, uma janela de "repetição após" do provedor estaciona o trabalho silenciosamente e um slot perdido durante uma reinicialização é acionado uma vez. (#108731, #115843)
  • Alertas mais silenciosos — Um alerta por incidente mais um lembrete a cada cron.failure_repeat_alert_hours; failure_deliver redireciona ou silencia avisos de falha; um agente pode falhar em sua execução com [CRON_FAILURE]. (#114807, #101373, #113155) — @victor-kyriazakos
  • Novas opções de trabalho — --paused cria um trabalho desarmado; --interpreter executa scripts em seu próprio ambiente. (#104984, #125392) — @M1racleShih
  • Perfis e entrega — Um gateway multiplexado executa os trabalhos de cada perfil com o ambiente e os segredos desse perfil; a entrega precisa de evidências positivas, os resultados são ocultados em segredo em todos os lugares e as execuções atrasadas ou por satélite são rotuladas. (#118027, #100908, #112830) — @yoniebans

Kanban

  • Trabalhadores resolvem problemas com o provedor — Turnos com falha tentam novamente no local com contexto; limites de taxa ou reenfileiramento 5xx em vez de novas tentativas. (#112318, #112500) - @EvgenyMettsler, @dmelkk-secondbrain
  • Um quadro que se explica — Os cartões mostram a última saída do trabalhador em caso de falha; o despacho diz por que um cartão é retido. (#112618) — @chelsealong
  • Fluxo de trabalho e ferramentas — Uma definição de fluxo de trabalho orienta colunas; os trabalhadores recebem kanban_schedule; kanban create --body-file; A área de trabalho segue os switches de gateway. (#134340, #130455, #116791, #119054) — @benbarclay, @unsupportedpastels, @fangliquanflq

Delegação e multiagente

  • Subagentes ao vivo, imagens e /stop (ver destaques). (#105593)
  • Fan-outs perdem menos — Os filhos com falha aparecem imediatamente, uma falha do proprietário mantém o trabalho concluído, os filhos podem entregar os processos aos pais e as conclusões por tarefa são opcionais. (#103549, #116707, #105125)
  • Roteamento filho — delegation.fallback_providers dá aos filhos sua própria cadeia; child_timeout_seconds mede a inatividade. (#105347, #117606) — @ayushnangia
  • /goal — Consistente em CLI, Desktop e mensagens; o juiz atende os subagentes; /goal pause for now não substitui mais a meta; portas são executadas no espaço de trabalho da sessão. (#104833, #132251, #125453) — @jayzhou2309
