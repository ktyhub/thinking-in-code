Agente Hermes v0.6.0 (v2026.3.30)

Data de lançamento: 30 de março de 2026

O lançamento de múltiplas instâncias — Perfis para execução de instâncias de agentes isolados, modo de servidor MCP, contêiner Docker, cadeias de provedores substitutos, duas novas plataformas de mensagens (Feishu/Lark e WeCom), modo webhook Telegram, OAuth multi-workspace Slack, 95 PRs e 16 problemas resolvidos em 2 dias.

✨ Destaques

  • Perfis — Multi-Instâncias Hermes — Execute múltiplas instâncias isoladas do Hermes na mesma instalação. Cada perfil obtém sua própria configuração, memória, sessões, habilidades e serviço de gateway. Crie com hermes profile create, alterne com hermes -p <name>, exporte/importe para compartilhamento. O isolamento total do token-lock evita que dois perfis usem a mesma credencial de bot. (#3681)
  • Modo Servidor MCP — Exponha conversas e sessões do Hermes a qualquer client compatível com MCP (Claude Desktop, Cursor, VS Code, etc.) via hermes mcp serve. Navegue por conversas, leia mensagens, pesquise sessões e gerencie anexos — tudo por meio do Model Context Protocol. Suporta transportes stdio e Streamable HTTP. (#3795)
  • Docker Container — Arquivo Docker oficial para executar o Agente Hermes em um contêiner. Suporta modos CLI e gateway com configuração montada em volume. (#3668, fecha #850)
  • Cadeia de provedores substitutos ordenados — Configure vários provedores de inferência com failover automático. Quando o seu provedor principal retorna erros ou está inacessível, o Hermes tenta automaticamente o próximo provedor na cadeia. Configure via fallback_providers em config.yaml. (#3813, fecha #1734)
  • Suporte à plataforma Feishu/Lark — Adaptador de gateway completo para Feishu (飞书) e Lark com assinaturas de eventos, cartões de mensagens, bate-papo em grupo, anexos de imagens/arquivos e retornos de chamada de cartões interativos. (#3799, #3817, fecha #1788)
  • Suporte à plataforma WeCom (Enterprise WeChat) — Novo adaptador de gateway para WeCom (企业微信) com mensagens de texto/imagem/voz, bate-papos em grupo e verificação de retorno de chamada. (#3847)
  • Slack Multi-Workspace OAuth — Conecte um único gateway Hermes a vários espaços de trabalho do Slack por meio do arquivo de token OAuth. Cada workspace recebe seu próprio token de bot, resolvido dinamicamente por evento recebido. (#3903)
  • Modo Telegram Webhook e controles de grupo — Execute o adaptador Telegram no modo webhook como uma alternativa à pesquisa — tempos de resposta mais rápidos e melhores para implantações de produção atrás de um proxy reverso. Novos controles de controle de menção de grupo quando o bot responde: sempre, somente quando @mencionado ou por meio de gatilhos regex. (#3880, #3870)
  • Exa Search Backend — Adicione Exa como um backend alternativo de pesquisa na web e extração de conteúdo junto com Firecrawl e DuckDuckGo. Defina EXA_API_KEY e configure como backend preferencial. (#3648)
  • Habilidades e credenciais em back-ends remotos — Monte diretórios de habilidades e arquivos de credenciais em contêineres Modal e Docker, para que sessões de terminal remoto tenham acesso às mesmas habilidades e segredos que a execução local. (#3890, #3671, fecha #3665, #3433)

🏗️ Agente Principal e Arquitetura

Provedor e Suporte ao Modelo

  • Cadeia de provedores substitutos ordenada — failover automático em vários provedores configurados (#3813)
  • Corrigir api_mode na troca de provedor — a troca de provedores via hermes model agora limpa corretamente api_mode obsoleto em vez de codificar chat_completions, corrigindo 404s para provedores com endpoints compatíveis com Anthropic (#3726, #3857, fecha #3685)
  • Parar o substituto silencioso do OpenRouter — quando nenhum provedor está configurado, o Hermes agora gera um erro claro em vez de rotear silenciosamente para o OpenRouter (#3807, #3862)
  • Modelos de visualização Gemini 3.1 — adicionados aos catálogos OpenRouter e Nous Portal (#3803, fecha #3753)
  • Comprimento do contexto Gemini direto API — resolução completa do comprimento do contexto para endpoints diretos de IA do Google (#3876)
  • gpt-5.4-mini adicionado ao catálogo substituto do Codex (#3855)
  • Listas de modelos selecionados são preferidas em relação ao probe API ativo quando o probe retorna menos modelos (#3856, #3867)
  • Mensagens de limite de taxa 429 fáceis de usar com contagem regressiva de repetição após (#3809)
  • Chave de espaço reservado client auxiliar para servidores locais sem requisitos de autenticação (#3842)
  • Registro em nível INFO para resolução de provedor auxiliar (#3866)

Loop e conversa do agente

  • Relatório de status do subagente — relata o status do completed quando existe um resumo em vez de falha genérica (#3829)
  • Arquivo de log de sessão atualizado durante a compactação — evita referências a arquivos obsoletos após a compactação de contexto (#3835)
  • Omitir parâmetro de ferramentas vazio — não envia nenhum parâmetro tools quando vazio em vez de None, corrigindo a compatibilidade com provedores estritos (#3820)

Perfis e Multi-Instâncias

  • Sistema de perfis — hermes profile create/list/switch/delete/export/import/rename. Cada perfil recebe HERMES_HOME isolado, serviço de gateway, wrapper CLI. Os bloqueios de token evitam colisões de credenciais. Preenchimento de guias para nomes de perfis. (#3681)
  • Caminhos de exibição com reconhecimento de perfil — todos os caminhos ~/.hermes voltados para o usuário substituídos por display_hermes_home() para mostrar o diretório de perfil correto (#3623)
  • Importações lentas de display_hermes_home — evita ImportError durante hermes update quando os módulos armazenam bytecode obsoleto em cache (#3776)
  • HERMES_HOME para caminhos protegidos — O caminho de negação de gravação .env agora respeita HERMES_HOME em vez de ~/.hermes codificado (#3840)
