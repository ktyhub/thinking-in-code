Agente Hermes v0.15.1 (v2026.5.29)

Data de lançamento: 29 de maio de 2026 Desde v0.15.0: 28 commits · 21 PRs mesclados · lançamento de hotfix · 9 colaboradores

O lançamento do patch. Um hotfix no mesmo dia para v0.15.0. Correção do título: o loop de recarga infinita do painel que atingiu qualquer pessoa executando o v0.15.0 no modo loopback (Docker, Hermes hospedado, novas instalações). Vários outros acompanhamentos do v0.15.0 acompanham o passeio - trabalhador kanban SIGTERM, unificação do seletor /model, desvio de sessão /yolo, o catálogo completo de 19.932 entradas skills.sh, restauração de entrega de mídia .md, segurança de redução de sonda de gateway, passagem de redação de URL da web, visão do trabalhador kanban em imagens referenciadas, padrão de observação retrospectiva. Os usuários do Docker obtêm um env var opt-in --insecure explícito (sem mais inferência de host de ligação), resolução PATH de comando simples do servidor MCP e correções de cache de construção PR arm64.

✨ Destaques

  • Loop de recarga do painel 401 corrigido — No modo loopback, a investigação de identidade do painel (/api/auth/me) retorna 401 por design, mas o protetor de recarga de token obsoleto do v0.15.0 trata cada 401 como um token de sessão rotacionado e recarregado de página inteira para pegar um novo. Cada chamada de irmão bem-sucedida limpava a proteção de recarga única, de modo que a página recarregava em loop para sempre (Firefox: tempestade "Navegado para/sessões"; Chrome: tempestade de re-renderização do React). Fix adiciona uma opção de exclusão de allowUnauthorized para fetchJSON que pula apenas a recarga de token obsoleto de loopback - 401 ainda lança, então AuthWidget o engole, os redirecionamentos login_url de modo fechado não são afetados. Fecha #34206, #34202. (#30698 — @austinpickett)
  • O painel Docker --insecure agora é uma opção de env explícita, nunca derivada do host de ligação — Anteriormente, o ponto de entrada Docker inferia --insecure quando o painel era vinculado a um host sem loopback. Isso combinava "Quero acesso à LAN" com "Quero desabilitar a proteção de mesma origem". A correção os divide: o host de ligação é o host de ligação e a desativação da autenticação de loopback do painel requer um HERMES_DASHBOARD_INSECURE=1 explícito. As configurações existentes que realmente queriam uma ligação insegura agora devem definir o env var. (#34188, #34204 — @benbarclay)
  • Resolução de comando simples MCP em Docker — Servidores MCP configurados com comandos básicos (npx, npm, node) agora resolvem contra /usr/local/bin para que eles realmente sejam iniciados dentro da imagem Docker onde esses binários residem. v0.15.0 deixou essas falhas silenciosamente em contêineres quando o PATH efetivo do agente não incluía a localização do conjunto de ferramentas do Node. (#34186 — @benbarclay)
  • Barra lateral da página de habilidades/pílulas de origem restauradas — Uma dependência obsoleta do useMemo na nova página de habilidades do painel reduziu as pílulas de origem e a barra lateral da categoria para "Todos" apenas. Fixo; ambas as superfícies agora refletem o estado do catálogo ativo. (#34194)
  • O trabalhador Kanban pode ser morto novamente — SIGTERM em um trabalhador kanban estava sendo absorvido por um processo intermediário e o trabalhador continuou em execução. Fecha #28181. (#34045)
  • Catálogo skills.sh completo (858 → 19.932 entradas) — A página do hub de habilidades estava extraindo um catálogo paginado parcial. A busca agora percorre o mapa do site, de modo que todas as 19.932 entradas skills.sh aparecem no seletor, em vez de apenas as primeiras 858. (#34025)
