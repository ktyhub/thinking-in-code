Mudanças notáveis

Tantos! Consulte a postagem do blog Lighthouse 6.0: Novidades para uma visão mais aprofundada.

🆕 Novas auditorias

  • Largest Contentful Paint (LCP) é uma nova métrica que mede o tempo desde a navegação até que o maior elemento de conteúdo na janela de visualização seja renderizado (#9905, #10213, #10452, #10529).
    • largest-contentful-paint-element é uma auditoria complementar que fornece informações sobre qual elemento acionou o LCP (#10517, #10713).
  • Mudança cumulativa de layout (CLS) é uma nova métrica que mede a quantidade de movimento inesperado de conteúdo conforme uma página carrega (#9037, #10427, #10495, #10570, #10728).
    • layout-shift-elements é outro diagnóstico complementar que fornece informações sobre os elementos que mudaram conforme a página foi carregada (#10702).
  • unused-javascript é uma auditoria que já existe há algum tempo, mas só agora está ativada por padrão. Ele contabiliza o que JavaScript foi carregado, mas nunca executado durante o carregamento da página e estima o tempo de carregamento que pode ser salvo por meio de divisão de código, eliminação de código morto ou uso criterioso da tecla delete (#9854).
  • Um PWA maskable-icon fica melhor na sua tela inicial, então esta nova auditoria incentiva você a ter pelo menos um disponível em seu manifesto (#10370).
  • timing-budget expande afirmações de orçamento para agora serem configuráveis ​​em todas as métricas de desempenho (#9901, #9925).
  • A nova auditoria charset garante uma codificação de caracteres adequada para o conteúdo da página (#10284, #10389, #10689).
  • image-size-responsive verifica se as imagens têm proporção e resolução que correspondem bem à forma como são exibidas em uma página (#10460).
  • A atualização para a versão mais recente do axe-core desbloqueou uma série de novas auditorias de acessibilidade: aria-hidden-body, aria-hidden-focus, aria-input-field-name, aria-toggle-field-name, duplicate-id-active, duplicate-id-aria, form-field-multiple-labels, heading-order (#9798).

⚗️ Auditorias experimentais

Essas auditorias ainda não fazem parte da experiência padrão do Lighthouse, mas fornecerão conselhos de desempenho com base na análise dos pacotes JavaScript de uma página. Eles podem ser testados hoje na linha de comando com o sinalizador --preset=experimental.

  • legacy-javascript vasculha seus pacotes em busca de polyfills e transformações de empacotador que não são necessários ou estão desatualizados (#10303, #10568, #10564).
  • duplicated-javascript também analisa o JavaScript de uma página em busca de código que acabou duplicado em pacotes ou em vários pacotes (#10314).
  • unused-javascript agora é executado por padrão (como mencionado acima), mas quando executado em experimental, a auditoria pode usar mapas de origem para mostrar qual código-fonte original nunca foi executado e pode ser adiado ou eliminado (#10090).

💥 Mudanças importantes

  • As pontuações das métricas de desempenho foram reponderadas para refletir melhor a experiência de carregamento do usuário (#9949).
  • As curvas de pontuação métrica foram atualizadas ao executar um teste Lighthouse de desktop para levar em conta a conexão e a CPU mais rápidas (#9911, #10756).
  • Os eventos frameNavigated agora são usados ​​para rastrear redirecionamentos, o que significa que os redirecionamentos JS agora são considerados ao determinar o finalUrl da execução (#10339).
  • O dispositivo móvel emulado migrou do Nexus 5x para o Moto G4 (mas o DPR existente permaneceu inalterado) (#10191, #10749).
  • A predefinição mixed-content foi removida porque não era amplamente usada e demora muito para ser adicionada à experiência padrão do Lighthouse (#10159, #10750).
  • A predefinição full foi renomeada como experimental para significar que o código pode não estar pronto para execução por padrão (#9930, #10311, #10333, #10585).
  • A string emulada do Chrome UA foi atualizada para o Chrome 80 (#9967).
  • installable-manifest: os ícones no manifesto do aplicativo Web devem ser obtidos para serem considerados instaláveis (#10168, #10320)

🤖💥 Mudanças importantes para usuários programáticos

É improvável que essas alterações afetem os usuários finais, mas podem ser importantes se você estiver escrevendo configurações personalizadas, plug-ins ou processando a saída do Lighthouse JSON.

  • LH.Audit.Context aprovado em auditorias agora é tratado como imutável. Se o código foi enviado anteriormente para context.LighthouseRunWarnings para obter um aviso de nível superior, ele agora deve passá-lo de volta em runWarnings no produto da auditoria (#10555).
  • Audit.computeLogNormalScore foi redefinido para especificar curvas log-normais com mediana e pontos p10 (eliminando o "ponto de retornos decrescentes"). As auditorias existentes foram movidas para esta nova definição para que nenhuma alteração de pontuação ocorra (#10715).
  • Uma configuração loadFailureMode foi adicionada às passagens Config para controlar o comportamento em caso de falha no carregamento da página. Anteriormente, isso era controlado implicitamente (por exemplo, nenhuma página off-line disponível não causava erro) (#9987)
  • time-to-first-byte foi renomeado como server-response-time para refletir melhor o que está sendo medido pela auditoria (#10735).
  • resource-summary: details.items.size foi renomeado para transferSize para maior clareza (#10700, #10743).
