farol v7.0.0

#7.0.0 (17/12/2020) Changelog completo O Lighthouse 7.0 inclui uma série de alterações programáticas importantes e novas auditorias nas categorias Acessibilidade e PWA. Houve algumas melhorias na precisão dos cálculos de métricas, mas não se espera que as pontuações de desempenho mudem significativamente em quase todos os sites. Pode haver mudanças maiores nas pontuações de Acessibilidade e PWA devido às novas auditorias. Espera-se que esta versão seja fornecida no DevTools do Chrome 89. Foi ao ar no PageSpeed ​​Insights em 19 de fevereiro de 2021.

Mudanças notáveis

  • Uma captura de tela de página inteira é tirada e usada para melhorar a experiência de visualização dos detalhes do elemento DOM. Agora uma miniatura será mostrada e clicking revela uma lightbox mostrando onde na página o nó DOM residia. Esta captura de tela aumenta o tamanho do Farol JSON em aproximadamente 33%. (#11769, #11768, #11829, #11846, #11852)
  • A Categoria PWA mudou bastante significativamente.
    • O grupo Instalável é inteiramente alimentado pelas verificações de capacidade que ativam os critérios instaláveis ​​do Chrome. Estes são os mesmos sinais vistos no painel Manifest no Chrome DevTools. Como tal, a auditoria "Registra um trabalhador de serviço…" passa para o grupo PWA Optimized, e a auditoria "Usa HTTPS" agora está incluída como parte da auditoria principal de "requisitos de instalação".
    • O grupo Rápido e confiável evaporou no ar. 🌬 Agora que a auditoria renovada de "requisitos de instalação" inclui verificação de capacidade offline, removemos as auditorias dedicadas para verificar se a página atual e start_url respondem com 200 quando offline. Separadamente, a auditoria "O carregamento da página é rápido o suficiente na rede móvel" foi removida - embora não faça mais parte da seção PWA, incentivamos as pessoas que criam um PWA a consultar a categoria Desempenho para garantir que seu aplicativo da web seja rápido e agradável.
  • Uma construção noturna do Farol agora está disponível como lighthouse@next no npm. Observe que, embora os testes automatizados sejam aprovados antes da publicação, espera-se que esta versão seja mais instável do que as versões regulares (#11792, #11805, #11810)
  • A biblioteca de testes de acessibilidade axe-core foi atualizada para a versão mais recente do 4.1.1. As auditorias de acessibilidade agora são mais rápidas, robustas e incluem diversas novas verificações (#11661)
  • O Lighthouse executa um pequeno benchmark na inicialização e agora incluirá um aviso se a máquina de teste parecer com potência insuficiente e puder estar afetando a precisão das métricas do Lighthouse (#11350)
  • A detecção de Joomla e CMS de outubro foi adicionada, então as páginas nessas plataformas agora receberão conselhos personalizados sobre algumas auditorias do Lighthouse (#11788)

Novos colaboradores

Obrigado a Kohta Ito (@ koh110) e Sam Stoelinga (@ samos123) por suas primeiras contribuições!

🆕 Novas auditorias

  • A nova auditoria installable-manifest PWA, mencionada acima, usa os próprios critérios de instalação do Chrome para que fique sempre sincronizado com os requisitos de instalação (#11745)
  • third-party-facades procura incorporações de terceiros na página de teste que podem ser carregadas lentamente com uma "fachada" estática. Se a incorporação não for necessária para interação imediata do usuário, considere usar uma das fachadas para acelerar o carregamento da página (#11290)
  • Com a atualização da versão ax, vêm novas auditorias garantindo nomenclatura acessível: aria-treeitem-name, aria-command-name, aria-tooltip-name, aria-meter-name e aria-progressbar-name (#11661)

♻️ Auditorias removidas

  • A atualização para o axe-core mais recente também remove duas auditorias que não estavam verificando muito: layout-table e video-description (#11661)
  • As auditorias works-offline e offline-start-url foram removidas, pois suas verificações agora são cobertas pela nova implementação installable-manifest (#11806)
  • A auditoria load-fast-enough-for-pwa também foi removida, pois as métricas de desempenho existentes do Lighthouse mais do que cobrem as necessidades (#11764)
  • without-javascript foi removido (#11711)

💥 Mudanças importantes

  • As configurações de emulação de dispositivo e os sinalizadores CLI foram alterados para serem mais claros e terem menos sobreposição. Se você usou --emulated-form-factor ou outra configuração relacionada à emulação, você precisará fazer alterações. As novas configurações devem ser consideravelmente mais simples de usar com executores Lighthouse personalizados usando dispositivos reais, Puppeteer ou aceleração em nível de sistema. Consulte a documentação de emulação para orientação sobre migração. (#11779)
  • Ao aguardar o carregamento completo da página, o Lighthouse agora aguardará se houver solicitações de rede ativas de alta prioridade. Em casos raros, como quando a inicialização do aplicativo depende de um único XHR de retorno lento, algumas métricas de desempenho podem piorar; no entanto, as novas medições agora são precisas. (#11738, #11851)
  • O suporte para o Nó 10 foi eliminado. A versão mínima necessária do Node agora é 12 (#11656)

🤖💥 Mudanças importantes para usuários programáticos

É improvável que essas alterações afetem os usuários finais, mas podem ser importantes se você estiver escrevendo configurações personalizadas, plug-ins ou processando a saída do Lighthouse JSON.

  • ConsoleMessages é um novo artefato que é uma combinação dos antigos artefatos ConsoleMessages e RuntimeExceptions, com alguns dados expandidos sobre itens registrados no console. RuntimeExceptions foi removido (#11663)
  • Os dados de "detalhes do nó" do DOM anteriormente espalhados pelos artefatos existentes agora são reunidos em uma propriedade NodeDetails em cada elemento (#11474, #11695, #11752)
  • O artefato ImageElements foi simplificado para melhor representar os dados coletados e como eles são usados (#11703, #11707, #11733)
  • Anteriormente, extends: true era permitido como um alias para extends: 'lighthouse:default' para estender uma configuração do arquivo de configuração padrão do Lighthouse. A opção booleana foi removida para preparar o caminho para a extensão de qualquer arquivo de configuração válido (#11835)
  • Um recurso nunca usado para passar opções da configuração para coletores foi removido para ser compatível com alterações futuras (#11743)
