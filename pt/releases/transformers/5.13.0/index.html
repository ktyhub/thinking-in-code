Nemotron 3.5 ASR

<img width="1632" height="735" alt="image" src="https://github.com/user-attachments/assets/597bbb9c-b046-4e47-b9fd-f242e0a5b04d" />

Nemotron 3.5 ASR é um modelo de reconhecimento de fala multilíngue de 600M parâmetros da NVIDIA, desenvolvido para transcrição de alta qualidade em streaming de baixa latência e configurações de lote de alto rendimento, com pontuação nativa e talização capi. Para streaming, ele oferece tamanhos de blocos configuráveis ​​– 80 ms, 160 ms, 560 ms e 1120 ms, permitindo que os usuários negociem latência com precisão para se adequar à sua aplicação. Sua arquitetura FastConformer-RNNT com reconhecimento de cache é central para esse recurso: ao contrário do streaming em buffer tradicional, que reprocessa repetidamente janelas de áudio sobrepostas, o modelo processa apenas cada novo pedaço de entrada enquanto reutiliza o contexto do codificador armazenado em cache de pedaços anteriores. Isso elimina a computação redundante, melhora significativamente a eficiência e minimiza o atraso de ponta a ponta sem sacrificar a precisão, tornando-o adequado para cargas de trabalho de transcrição em tempo real.

VídeoPrisma

O modelo VideoPrism foi proposto no artigo VideoPrism: A Foundational Visual Encoder for Video Understanding do Google DeepMind (blog post).

VideoPrism é um codificador de vídeo de uso geral que realiza diversas tarefas de compreensão de vídeo com um único modelo congelado. O modelo é pré-treinado em um corpus heterogêneo em grande escala contendo 36 milhões de pares de legendas de vídeo de alta qualidade e 582 milhões de vídeos clips com texto paralelo ruidoso (por exemplo, transcrições ASR). A abordagem de pré-treinamento melhora a codificação automática mascarada por meio da destilação global-local de incorporações semânticas de vídeo e um esquema de embaralhamento de tokens, permitindo que o modelo se concentre principalmente na modalidade de vídeo enquanto aproveita o texto associado aos vídeos. O VideoPrism alcança desempenho de última geração em 31 dos 33 benchmarks de compreensão de vídeo em quatro amplos grupos de tarefas, desde respostas a perguntas de vídeo na web até visão computacional para ciência.

###MiniCPM3

MiniCPM3 é o modelo de linguagem densa MiniCPM de terceira geração do OpenBMB. A variante 4B (openbmb/MiniCPM3-4B) supera muitos 7B–9B abertos modelos em benchmarks padrão, permanecendo leves o suficiente para uso no dispositivo.

MiniCPM3 combina várias ideias arquitetônicas:

  • Atenção Latente Multi-head (MLA) do DeepSeek-V2, que compacta o cache de chave/valor em uma representação latente de baixo nível enquanto ainda usa incorporações rotativas em uma parte do cabeças de consulta/chave.
  • Um SwiGLU MLP padrão (sem MoE).
  • Três fatores de escala escalar que governam o fluxo do sinal:
    • scale_emb — dimensiona incorporações de entrada.
    • scale_depth / sqrt(num_hidden_layers) — dimensiona conexões residuais.
    • hidden_size / dim_model_base — dimensiona estados ocultos antes do cabeçalho do modelo de linguagem.

HfExporters: exportação nativa e unificada para PyTorch / ONNX / ExecuTorch

<img alt="thumbnail" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

Um pipeline de exportação nativo em Transformers - uma classe base (HfExporter), três subclasses para os tempos de execução que nos interessam, um API unificado:

| Exportador | Saída | Tempo de execução | |---|---|---| | DynamoExporter | ExportedProgram | Qualquer tempo de execução PyTorch, compilação AOT | | OnnxExporter | ONNXProgram | Qualquer tempo de execução ONNX (ORT, TensorRT, OpenVINO,…) | | ExecutorchExporter | ExecutorchProgramManager | Móvel e de ponta (ExecuTorch) | O mesmo formato de chamada em todos os três. Formas dinâmicas por padrão. Os modelos de estilo de geração são divididos automaticamente em pré-preenchimento + decodificação (+ subcodificadores de visão/áudio para VLMs).

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

Troque uma linha por outro tempo de execução — DynamoExporter() / DynamoConfig ou ExecutorchExporter() / ExecutorchConfig(backend=...).

Para modelos generativos, a divisão de pré-preenchimento/decodificação é capturada automaticamente:

from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-LlamaForCausalLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")

artifacts = OnnxExporter().export_for_generation(model, inputs, config=OnnxConfig(dynamic=True))
# {"prefill": ONNXProgram, "decode": ONNXProgram}
# For VLMs: also vision_encoder, audio_encoder, multi_modal_projector, language_model, lm_head
