Aviso

Não baixe códigos-fonte desta página. Por favor, siga o documento de construção, se você quiser construir códigos-fonte sozinho.

Novo kernel de alerta

  • MQE (Metrics Query Expression) e um novo mecanismo de notificação são suportados.

Suporte Loki LogQL

  • Suporte recentemente adicionado para Loki LogQL e Grafana Loki Dashboard para registros coletados do SkyWalking

AVISO

  • Os testes relativos ao armazenamento do ElasticSearch 6 foram removidos. Funcionou e não está prometido oficialmente devido ao fim da vida.

Projeto

  • Aumente o Guava para 32.0.1 para evitar a lib listada como vulnerável devido ao CVE-2020-8908. Este API nunca é usado.
  • O artefato Maven skywalking-log-recevier-plugin foi renomeado para skywalking-log-receiver-plugin.
  • Aumente a versão cli 0.11 para 0.12.
  • Aumente a versão do pom pai do ASF para v30.
  • Torne as compilações reproduzíveis para lançamentos automáticos de CI.

Servidor OAP

  • Adicionar idioma do ID do componente Neo4j (112): Python.
  • Adicione o registro Istio ServiceEntry para resolver IPs desconhecidos no ALS.
  • Envolva deleteProperty API no BanyanDBStorageClient.
  • [Alteração significativa] Remova matchedCounter de HttpUriRecognitionService#feedRawData.
  • Remova padrões de HttpUriRecognitionService#feedRawData e adicione no máximo 10 candidatos de URIs brutos para cada padrão.
  • Adicione o ID do componente para WebSphere.
  • Corrigir exceções de cache NullPointer e IllegalArgument do AI Pipeline.
  • Corrigido NPE na consulta de métricas quando a métrica não existe.
  • Remova os testes E2E para Istio < 1.15, ElasticSearch < 7.16.3, eles ainda podem funcionar, mas não são suportados conforme planejado.
  • Role todos os resultados no armazenamento ElasticSearch e refatore as lógicas de rolagem, incluindo Serviço, Instância, Endpoint, Processo, etc
  • Melhore o coordenador Kubernetes para remover pods Terminating OAP no cluster.
  • Suporte SW_CORE_SYNC_PERIOD_HTTP_URI_RECOGNITION_PATTERN e SW_CORE_TRAINING_PERIOD_HTTP_URI_RECOGNITION_PATTERN para controlar o período de treinamento e sincronizar padrões de reconhecimento de URI HTTP. E reduza o período padrão para 10s para sincronização e 60 anos para treinamento.
  • Corrigido bug do scroller ElasticSearch.
  • Adicione o ID do componente para Aerospike (ID=149).
  • Pacotes com nome recevier foram renomeados para receiver.
  • BanyanDBMetricsDAO lida com storeIDTag em multiGet para BanyanDBModelExtension.
  • Corrija a lógica relacionada ao agrupamento de endpoints e melhore o desempenho da recuperação do PatternTree.
  • Corrigido o salvamento do cache de sessão métrica após inserção em lote ao usar mysql-connector-java.
  • Suporte para consulta de menu de UI dinâmica.
  • Adicione um comentário para docker/.env para explicar o uso.
  • Corrija o nome errado da variável de ambiente SW_OTEL_RECEIVER_ENABLED_OTEL_RULES para SW_OTEL_RECEIVER_ENABLED_OTEL_METRICS_RULES correto.
  • Correção de consulta de instância na implementação JDBC.
  • Defina o valor padrão de SW_QUERY_MAX_QUERY_COMPLEXITY para 3000 (era 1000).
  • Aceita o valor do parâmetro length=4000 do evento. Foi em 2000.
  • Tolerar valor do parâmetro em formato JSON ilegal.
  • Atualize BanyanDB Java Client para 0.4.0
  • Suporte agregado Labeled Value Metrics em MQE.
  • [Alteração significativa] Altere o nome do rótulo padrão no MQE de label para _.
  • Aumente a versão grpc para 1.53.0.
  • [Alteração significativa] Removidos os símbolos '&' dos scripts de shell para evitar que o processo do servidor OAP seja executado como um processo em segundo plano.
  • Reverta parte de #10616 para corrigir as alterações inesperadas: se não houver dados devemos retornar um array com 0s, mas em #10616, um array vazio é retornado.

  • Mova o índice mais recente criado antes da recuperação dos índices por aliases para evitar a exceção 404. Isso apenas evita alguma interferência de operações manuais.
  • Adicione mais métricas Go VM, como novo agente skywalking-go fornecido desde o lançamento do 0.2.

  • Aumente Armeria para 1.24.3.

  • Melhore o PromQL para permitir múltiplas operações métricas em uma única consulta.
  • Correção da operação binária MQE entre métricas rotuladas e outro tipo de resultado de valor.
  • Adicione o ID do componente para Nacos (ID=150).
  • Suporte Compare Operation em MQE.
  • Corrija o cache de recursos Kubernetes não atualizado.
  • Corrija o caminho de classe errado que pode causar OOM na inicialização.
  • Aprimore o serviceRelation no MAL adicionando configurações para os campos delimiter e component.
  • [Alteração significativa] Suporte MQE no alerta. A configuração das regras de alarme (alarm-settings.yml), adicione o campo expression e remova os campos metrics-name/count/threshold/op/only-as-condition e remova a configuração composite-rules.
  • Verifique os resultados no ALS conforme downstream/upstream em vez de por log.

  • Não inicie o servidor e o consumidor Kafka no modo init.
  • Adicione o ID do componente Iris (5018).
