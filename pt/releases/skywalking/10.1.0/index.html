skywalking v10.1.0

Baixar

https://skywalking.apache.org/downloads/

Aviso

Não baixe códigos-fonte desta página. Por favor, siga o documento de construção, se você quiser construir códigos-fonte sozinho.

Uma versão de PERFORMANCE

  • ** Grande melhoria no desempenho da interface do usuário. As consultas de widgets de métricas são agrupadas aproveitando os recursos do GraphQL.**
  • Suporte a consultas paralelas no mecanismo GraphQL. Melhore o desempenho da consulta.
  • Melhorar significativamente o desempenho do manipulador de métricas OTEL. Reduza os custos de CPU e GC em processos de métricas OTEL.
  • Com a adoção do BanyanDB 0.7, o desempenho e a estabilidade do banco de dados nativo são melhorados.

Projeto

  • E2E: aumente a versão do coletor opentelemetry para 0.102.1.
  • Envie a imagem docker do gerador de dados instantâneo para ghcr.io.
  • Aumente skywalking-infra-e2e para contornar o GHA removendo docker-compose v1.
  • Aumente as ações do CodeQL GitHub.
  • Corrija a fase errada do plugin delombok para reduzir os avisos de compilação.
  • Use a revisão ci-friendly para definir a versão do projeto.

Servidor OAP

  • Corrija índices errados nos modelos relacionados ao perfil eBPF.
  • Suporte exclui o tráfego de namespaces específicos no receptor de log de acesso eBPF.
  • Adicione Golang como idioma suportado para Elasticsearch.
  • Remova logs de liberação desnecessários do BanyanDB (informações).
  • Aumente SW_CORE_GRPC_MAX_MESSAGE_SIZE para 50 MB.
  • Suporte para consulta de métricas de relacionamento através do PromQL.
  • Suporte a consulta MQE de rastreamento para depuração.
  • Adicione o ID do componente (158) para a estrutura Solon.
  • Corrija a tag de métricas no manipulador HTTP do plugin receptor do navegador.
  • Aumente o comprimento da coluna alarm_record#message de 200 para 2.000.
  • Remova a indexação da coluna alarm_record#message.
  • Adicione Python como idioma suportado para Pulsar.
  • Faça intervalos de histograma mais adequados para o persistence_timer_bulk_prepare_latency, Métricas persistence_timer_bulk_execute_latency e persistence_timer_bulk_all_latency em PersistenceTimer.
  • [Break Change] Atualize a versão do Nacos para 2.3.2. O servidor Nacos 1.x não pode servir como coordenador de cluster e servidor de configuração.
  • Suporte para consulta de rastreamento (SkyWalking e Zipkin) para depuração.
  • Corrigida consulta de métricas BanyanDB: usou o tipo Downsampling errado para encontrar o esquema.
  • Suporte ao fluxo de busca do cilium para monitorar o tráfego de rede entre os serviços do cilium.
  • Suporte à função labelCount no mecanismo OAL.

  • Polonês grupo BanyanDB e lógica de criação de esquema para corrigir o problema de falha na criação de esquema em condições de corrida distribuídas.
  • Suporte para consulta de topologia de rastreamento para depuração.
  • Corrigida expressão do gráfico Current QPS no painel MySQL.
  • Suporte a consulta de logs de rastreamento para depuração.
  • BanyanDB: corrige o armazenamento e consulta de dados de preenchimento automático de tags.
  • Suporte a operadores de agregação em consultas PromQL.
  • Atualize a unidade de origem das métricas relacionadas à latência HTTP kubernetes de ns para ms.
  • Suporte ao rastreamento de execução de consulta de fluxo interno do BanyanDB.
  • Corrigir erros de digitação e expressões ausentes nos painéis Elasticsearch, MySQL, RabbitMQ.
  • BanyanDB: Módulo Zipkin define serviço como entidade para melhorar o desempenho da consulta.
  • MQE: verifique o valor das métricas antes de realizar a operação binária para melhorar a robustez.
  • Substitua a solução alternativa pelo caminho de contexto com suporte nativo da Armeria.
  • Adicione um wrapper de endpoint http para verificação de integridade.
  • Aumente Armeria e dependências transitivas.
  • BanyanDB: se a coluna do modelo já for @BanyanDB.TimestampColumn, configure @BanyanDB.NoIndexing nela para reduzir os índices.
  • BanyanDB: transmitir classificação por consulta time, usar série temporal interna em vez de index para melhorar o desempenho da consulta.
  • Aumente o graphql-java para 21.5.

  • Correção do aumento simultâneo do CounterWindow causa NPE por PriorityQueue
  • Corrigido o formato do nome do endpoint com string vazia.
  • Suporte a consulta assíncrona para a consulta GraphQL composta.
  • Obtenha a ordem da lista de endpoints por registro de data e hora.
  • Suporte a consultas de classificação em métricas geradas pelo receptor eBPF.
  • Corrigida a compatibilidade com Grafana 11 ao usar variáveis ​​de consulta label_values.

  • Atualize o formato do nome do endpoint para <Method>:<Path> no eBPF Access Log Receiver.
  • Adicione métricas de auto-observabilidade para o receptor OpenTelemetry.
  • Suporte a métricas de nível de serviço agregadas quando falta contexto de pod no receptor de log de acesso eBPF.
  • Correção da exceção de lançamento da consulta getGlobalTopology quando não foi encontrado nenhum serviço na camada fornecida.
  • Corrija o resultado da análise anterior ausente no analisador ALS k8s-mesh.
  • Correção da consulta findEndpoint requer keyword ao usar BanyanDB.
  • Suporte para análise do endereço IP mapeado ztunnel e modo mTLS no receptor de log de acesso eBPF.

  • Adicione ID do componente (5022) para a estrutura GoFrame.
  • Aumente as dependências do protobuf java para 3.25.5.
  • BanyanDB: suporte ao uso de pesquisa de termos nativos para keyword na consulta findEndpoint e getAlarm.
  • BanyanDB: suporta conexão e configuração TLS.
  • Serviço PromQL: consulta API suporta formato de hora RFC3399.
  • Melhorar o desempenho do manipulador de métricas OTEL.
  • Serviço PromQL: corrige o resultado dos operadores faltando o sinalizador rangeExpression.
  • BanyanDB: use TimestampRange para melhorar a consulta de "eventos" para BanyanDB.
  • Otimize a tabela network_address_alias para reduzir o número do índice.
  • Serviço PromQL: suporte ao operador de colchetes.
  • Consulta de suporte Tag de mensagem de alarme para preenchimento automático.
