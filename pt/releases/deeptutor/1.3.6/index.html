#Deep Tutor v1.3.6 #DeepTutor v1.3.6 Release Notes Data de lançamento: 2026.05.03 v1.3.6 se concentra em tornar o roteamento de modelo explícito no DeepTutor. Os usuários podem escolha perfis LLM configurados de fluxos de chat e TutorBot, serviços de tempo de execução resolver essas escolhas sem vazar segredos do provedor e RAG/base de conhecimento o tratamento do índice é mais defensivo quando os embeddings persistentes são inválidos.

Destaques

Seleção de modelo baseada em catálogo

  • O bate-papo pode ter como alvo um modelo configurado - os turnos de bate-papo unificados agora carregam um Seleção de profile_id e model_id por meio da carga útil do WebSocket, sessão preferências, transformar instantâneos e regenerar fluxos.
  • As configurações expõem opções seguras do LLM - o novo endpoint de opções de configurações retorna opções de provedor/modelo prontas para exibição enquanto omite credenciais e segredos de conexão da resposta.
  • As substituições do modelo de tempo de execução têm escopo definido por turno - os perfis selecionados são resolvido através do catálogo de provedores para a solicitação ativa sem escrever escolhas temporárias de volta ao disco ou alteração dos padrões globais.
  • A UI do seletor de modelo é compartilhada - as telas de chat e TutorBot usam o mesmo seletor de modelo configurado, com rótulos localizados e tratamento padrão do sistema.

Controle de modelo TutorBot

  • Os bots podem persistir nas seleções de modelo - Os fluxos de criação/atualização do TutorBot agora são aceitos llm_selection, valide-o em relação ao catálogo configurado e armazene-o com cada robô.
  • Bots em execução podem recarregar seu LLM - alterar o modelo de um bot atualiza o loop de agente ativo em vez de exigir uma reinicialização completa do bot.
  • O histórico recente do bot é mais estável - A montagem do histórico do TutorBot agora é classificada por carimbo de data/hora da mensagem com desempate estável antes de usar o contexto mais recente.
  • As alterações na rota do bate-papo do bot são mais limpas - a página de bate-papo na web é cancelada durante o voo solicitações de bot e redefine o estado de raciocínio transitório ao trocar de bot.

RAG e confiabilidade do conhecimento

  • Vetores inválidos acionam reconstruções - a reindexação não trata mais uma correspondência assinatura do documento como reutilizável quando o armazenamento de vetores existente falha na incorporação validação.
  • Reconstruções completas usam diretórios de versões recentes - base de conhecimento completa reconstrói a gravação em uma nova versão de índice simples, deixando o armazenamento antigo com falha disponível para inspeção.
  • Os logs da ferramenta RAG podem ser transmitidos para clients - as execuções de recuperação podem encaminhar as capturas O processo no nível INFO registra como eventos brutos da ferramenta quando um coletor de eventos está disponível.
  • As verificações de integridade do conhecimento reconhecem incorporações incorretas - inválido persistido os vetores aparecem mais cedo, em vez de produzir falhas de pesquisa opacas.

Provedor e correções de lançamento

  • Os limites do token de respostas OpenAI são normalizados - As chamadas de respostas API agora são mapeadas max_completion_tokens e max_tokens para max_output_tokens estilo chat, corrigindo o erro SDK relatado para modelos OpenAI mais recentes em #437.
  • Caminhos compatíveis com Azure e OpenAI compartilham o mapeamento - tanto streaming quanto Respostas sem streaming As rotas API usam o mesmo auxiliar de conversão.
  • As portas de inicialização vêm do .env e variáveis de ambiente - configuração e inicialização ajudantes agora mantêm o comportamento da porta backend/frontend alinhado ao projeto .env em vez das configurações de tempo de execução mais antigas JSON.

Polonês UX da Web

  • Nomes de habilidades são validados antes de salvar - o editor de habilidades coloca nomes em slug, sinaliza entrada inválida em linha e evita falhas silenciosas de API para letras maiúsculas letras, espaços, sublinhados ou outros caracteres não suportados.
  • Os modais do editor de habilidades são opacos entre os temas - o editor agora usa o token de fundo da página, evitando vazamento de texto em temas translúcidos.
  • A navegação espacial é mais fácil de digitalizar - Mininavegação espacial, notebook, o banco de perguntas, as habilidades e o espaçamento da lista de sessões foram reforçados com tratamento de cartão e divisor.

Testes

  • Adicionados testes de serviço de seleção de modelo para listagem de opções seguras, marcadores ativos, rejeição de perfil/modelo inválido e substituições de catálogo sem mutação.
  • Adicionados testes unificados de tempo de execução do WebSocket para seleções LLM persistentes, seleções inválidas, troca de modelo, instantâneos e comportamento regenerado.
  • Adicionados testes TutorBot API e gerenciador para persistência llm_selection, validação, recarga de tempo de execução e comportamento do modelo padrão.
  • Adicionadas configurações, tempo de execução do provedor e testes de configuração LLM para catálogo com escopo definido seleção e precedência de configuração por turno.
  • Adicionados testes RAG e roteador de conhecimento para armazenamentos de vetores inválidos, reindexação decisões de reconstrução e resolução de versão de armazenamento.
  • Adicionados testes de conversor de respostas OpenAI para aliases de limite de token, precedência, Filtragem None e imutabilidade de entrada.
  • Adicionados testes de front-end para normalização e validação de nomes de habilidades.

Notas de atualização

  • Chat e TutorBot clients que desejam roteamento de modelo explícito devem enviar llm_selection como { "profile_id": "...", "model_id": "..." }. Omitindo continua a usar o padrão do sistema configurado.
  • Os arquivos de configuração do TutorBot agora podem conter llm_selection. Bot existente configurações sem esse campo continuam a carregar e os valores model legados permanecem utilizável como substituições de nome de modelo.
  • As portas de lançamento devem ser configuradas em .env ou processar variáveis de ambiente (BACKEND_PORT/FRONTEND_PORT). O velho data/user/settings/env.json O bloco de porta não é mais usado como fonte de porta de lançamento.
  • Bases de conhecimento com vetores persistentes obsoletos ou inválidos podem ser reconstruídas no próxima reindexação mesmo quando as assinaturas dos documentos não tiverem sido alteradas.
  • Os nomes das habilidades agora são normalizados e validados como slugs minúsculos de até 64 caracteres usando letras, números e hífens. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.3.5...v1.3.6
