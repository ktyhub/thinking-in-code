#Deep Tutor v1.2.1 #DeepTutor v1.2.1 Release Notes Data de lançamento: 2026.04.21

Destaques

Limites de token por estágio e temperatura para bate-papo (#348)

Promoveu o pipeline de chat de agente para um cidadão de configuração de primeira classe em agents.yaml. Um novo bloco capabilities.chat expõe max_tokens por estágio (responding, answer_now, thinking, observing, acting, react_fallback) e um temperature compartilhado, profundamente mesclado sobre padrões integrados via services/config/loader.py::get_chat_params(). Os orçamentos responding e answer_now saltam do 1800 codificado anterior para 8000, eliminando o truncamento no meio da frase que fazia com que cli cortasse respostas longas. Internamente, o _ChatLimits.from_config força todas as formas legadas (chaves ausentes, escalar em vez de ditado, substituições parciais) em uma classe de dados estável para que as instalações existentes continuem funcionando sem tocar no YAML. 10 novos testes de unidade abrangem resolução do carregador, precedência de mesclagem profunda e coerção de classe de dados.

Gerar novamente a última resposta — CLI, WebSocket, Web UI (#349)

Adicionado um fluxo regenerate real que executa novamente a mensagem anterior do usuário no local, funcionando uniformemente em cada ponto de entrada:

  • CLI — /regenerate (também conhecido como /retry) dentro do deeptutor chat REPL.
  • WebSocket — Mensagem type: "regenerate" em /api/v1/ws, com overrides opcional para capability, tools, knowledge_bases, language, config.
  • Web UI — um botão Regenerar por mensagem (ícone RefreshCcw) no último turno do assistente para respostas com capacidade de bate-papo. No back-end, TurnRuntimeManager.regenerate_last_turn reverte o assistente final por meio dos novos auxiliares SQLiteSessionStore.delete_message/get_last_message e, em seguida, reutiliza start_turn com _persist_user_message=False e _regenerate=True para que a linha do usuário não seja duplicada e memory_service.refresh_from_turn não seja executado uma segunda vez. As verificações pré-voo geram erros não fatais regenerate_busy (outro turno está em execução) ou nothing_to_regenerate (nenhuma mensagem anterior do usuário) em vez de falhar silenciosamente. A chamada _stage_responding LLM também obteve diagnósticos de resposta vazia que exibem um aviso estruturado quando o modelo não retorna nenhum conteúdo. 18 novos testes cobrem todos os três caminhos de rejeição, o fluxo de exclusão e reinicialização, o contrato de atualização de memória e salto e a viagem de ida e volta do WebSocket.

UI Harmony Polish para Regenerar

Dois ajustes subsequentes para que o novo botão corresponda ao resto da interface do chat e se comporte de maneira previsível sob rejeição do servidor:

  • i18n — adicionou chaves Regenerate a web/locales/{en,zh}/app.json (Regenerate / 重新生成) e trocou ChatMessages.tsx de uma string "Regenerate" codificada para t("Regenerate"), correspondendo ao padrão t("Copy") existente na mesma linha.
  • Reversão de pop otimista — quando o servidor rejeita um pré-flight de solicitação de regeneração (regenerate_busy / nothing_to_regenerate), o espaço reservado otimista POP_LAST_ASSISTANT + STREAM_START agora é restaurado por meio de uma nova ação de redutor RESTORE_ASSISTANT. A mensagem exibida é mantida em um pendingRegenerateRef por chave e apagada em done ou em qualquer resultado de terminal, para que a transcrição nunca perca silenciosamente a última resposta do usuário.

Correções de bugs

  • Blocos de código escuro ilegíveis no tema claro (#352) — o fundo do bloco de código #1f2937 / #292524 codificado combinado com .prose pre (forçando #D6D3D1) e .prose code:not(.md-code-block__code):not(.md-inline-code) (substituindo var(--foreground)) estava produzindo texto quase preto em fundos quase pretos no modo claro. Adicionada uma regra .md-renderer .md-code-block { ,pre,code } de maior especificidade que fixa #e5e7eb independentemente do tema, e marcou os elementos <code> em substitutos RichMarkdownRenderer e SimpleMarkdownRenderer com a classe md-code-block__code existente para que a proteção :not() entre em ação. Obrigado **@DarkGenius **.
  • Nenhum embedding travou o pipeline LlamaIndex (#347, correções #346) — quando um provedor de incorporação retorna null para o vetor de um pedaço, o None acabou no índice do vetor e explodiu np.dot(NoneType) durante o cálculo de similaridade. Correção de duas camadas: _extract_embeddings_from_response agora usa or [] em vez de get(key, default) para que valores explícitos de None sejam capturados e CustomEmbedding._get_text_embeddings valide o resultado do lote e substitua um vetor zero por qualquer slot None. Obrigado @kagura-agente.
  • Modelos Gemma rejeitaram json_object response_format (#345, correções #344) — Gemma servido através do LM Studio (e servidores locais semelhantes compatíveis com OpenAI) responde 400 "'response_format.type' must be 'json_schema' or 'text'" quando entregue response_format={"type": "json_object"}. Adicionado supports_response_format: False à entrada gemma MODEL_OVERRIDES existente para que o caminho json_object seja ignorado; os utilitários extract_json_object existentes nos agentes de visualização e animação matemática já analisam JSON a partir de texto simples, para que todos os chamadores continuem a trabalhar sem mais alterações. Obrigado @octo-patch.

Expansão do conjunto de testes

Net +575 linhas de teste: 10 casos para o carregador de parâmetros de bate-papo / coerção _ChatLimits (tests/services/config/test_chat_params_config.py), 18 casos para o fluxo regenerado incluindo todos os três caminhos de rejeição, a exclusão + reinicialização no local, o salto de atualização de memória e o contrato de usuário sem duplicação de ponta a ponta (tests/services/session/test_regenerate.py), 14 casos para substituições de modelo supports_response_format (tests/services/llm/test_capabilities.py) e um teste de regressão para o caminho de extração de incorporação None (tests/services/embedding/test_extract_embeddings.py).
