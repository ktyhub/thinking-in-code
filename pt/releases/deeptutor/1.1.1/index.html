#Deep Tutor v1.1.1 #DeepTutor v1.1.1 Release Notes Data de lançamento: 2026.04.17

Destaques

Escotilha de escape universal "Responda agora" — Caminhos rápidos por capacidade

Promovido "Responda agora" de uma funcionalidade apenas de bate-papo para uma interrupção universal que respeita o formato de saída de cada capacidade. Um novo auxiliar compartilhado deeptutor/capabilities/_answer_now.py fornece a porta (extract_answer_now_context) e o resumo de rastreamento amigável, e cada recurso integrado agora possui seu próprio branch de caminho rápido no topo do run():

  • chat — sintetiza a resposta final do markdown a partir do rastreamento parcial (comportamento existente).
  • deep_solve — pule o planejamento + raciocínio, vá direto para o escritor.
  • deep_question — pule ideação/modelos, emita o quiz completo JSON em uma chamada estruturada (ainda renderizada por QuizViewer).
  • deep_research — pule a reformulação/decomposição/pesquisa, escreva o relatório diretamente a partir das evidências acumuladas.
  • math_animator — pula análise + design + resumo mas mantém geração de código + renderização, para que o usuário ainda obtenha uma animação real.
  • visualize — pula análise + revisão, emite o código renderizável final em uma chamada estruturada. Cada atalho preserva o mesmo envelope de resultados do pipeline normal (para que os visualizadores Quiz/MathAnimator/Visualization sejam renderizados inalterados) e acrescenta um aviso > ⚡ Skipped X stage(s) para que os usuários saibam que foi uma saída antecipada de melhor esforço. O orquestrador não redireciona mais answer_now para chat; agora ele mantém active_capability e só retorna para chat se o recurso originalmente selecionado tiver sido removido do registro. O frontend corresponde: handleAnswerNow não substitui mais a capacidade do snapshot e um componente AnswerNowRow protegido por disparo único renderiza a ação embutida abaixo do painel de rastreamento de streaming.

Co-Writer — Sincronização de rolagem dividida e ancorada em linha redimensionável

A página do Co-Writer possui um divisor arrastável entre o editor e os painéis de visualização (com uma proporção persistente em localStorage) e uma verdadeira sincronização de rolagem bidirecional que sobrevive às linhas suaves. Cada bloco de visualização agora carrega um atributo data-source-line apontando para sua linha inicial na fonte de redução (fornecida pelas posições AST da observação); no lado do editor, um elemento de espelho oculto imita a geometria envolvente da área de texto para que possamos ler o pixel-y real de cada linha de origem. Com ambos os lados expressos como coordenadas de pixel, a sincronização se torna uma única interpolação linear por partes em qualquer direção, com um cache por linha de origem que é invalidado apenas quando o conteúdo ou a largura do wrap mudam.

Salvar no Notebook — Modo de seleção de mensagens

SaveToNotebookModal agora aceita uma propriedade messages opcional que coloca o modal em "modo de seleção": o usuário escolhe exatamente qual usuário/assistente incluirá, e a transcrição + userQuery enviada para o backend é reconstruída a partir do subconjunto selecionado. Predefinições rápidas ("Selecionar tudo", "Último turno", "Últimos 3 turnos") e um título derivado automaticamente que rastreia a primeira mensagem do usuário selecionada mantêm o fluxo rápido para os casos comuns. O modal agora também usa ícones Check/MessageSquare/User para distinguir funções rapidamente e relata o estado de carregamento da lista de notebooks separadamente do botão giratório de salvamento.

Adoção real do sistema de notebook em toda a pilha

Migramos todas as superfícies restantes do notebook da categoria de teste herdada API para os endpoints /api/v1/notebook/* reais. Um novo bloco web/lib/notebook-api.ts exporta auxiliares digitados – listNotebooks, getNotebook, createNotebook, updateNotebook, deleteNotebook, deleteNotebookRecord – junto com os auxiliares preservados apenas de questionário. A guia Conhecimento → Cadernos, o seletor de referência de caderno da página Guia (useNotebookSelection) e o modal Salvar no Caderno agora resolvem UUIDs de ponta a ponta, para que os registros salvos do Co-Writer, Chat ou Aprendizado Guiado sejam imediatamente descobertos como referências em qualquer lugar.

Painel de configurações dobrável unificado

Extraída a seção recolhível "Configurações" que anteriormente existia apenas no ResearchConfigPanel em um componente CollapsibleConfigSection compartilhado. Os painéis Quiz, Math Animator e Visualize agora compartilham exatamente o mesmo cabeçalho de divisa + resumo, e cada formulário envia um auxiliar summarizeXxxConfig para que o estado recolhido mostre uma linha significativa (por exemplo, Personalizado · 5q · Difícil · MCQ ou Mimic · paper.pdf · máx. 10). A página de bate-papo agora mantém um único estado panelCollapsed para qualquer recurso que esteja ativo, expande-se automaticamente na alternância de recurso e recolhe-se automaticamente após enviar uma mensagem para que o compositor permaneça compacto durante a conversa.

Botão de parada de streaming e polonês do compositor

Substituído o botão giratório dentro do botão Enviar por um botão Parar dedicado que aparece no lugar de Enviar enquanto um turno está sendo transmitido. Um anel fraco gira lentamente ao redor da borda para sinalizar "ainda funcionando - click para cancelar", com um quadrado branco na frente e no centro como o alvo click. O cabeçalho acima das mensagens (rótulo de capacidade + botões Salvar/Novo bate-papo) agora é sempre renderizado, e o contêiner de mensagens pega um gradiente de máscara suave na parte superior e inferior para que o conteúdo do streaming apareça/desaparece gradualmente em vez de clipping na borda de rolagem. No modo Deep Research, as fontes foram movidas para um menu suspenso com uma linha de resumo compacta das escolhas ativas, correspondendo ao padrão usado pelo seletor de ferramentas.

Refatoração do TutorBot Config Manager

Reescreveu a persistência de configuração do TutorBotManager em um pequeno API público (load_bot_config, save_bot_config, merge_bot_config) com três melhorias significativas: as gravações agora são atômicas (write-temp + Path.replace) para que um processo eliminado nunca deixe um config.yaml pela metade; as mesclagens têm semântica de limpeza explícita - None significa "deixar como está", uma string vazia ou um ditado vazio é uma limpeza intencional - então clients pode limpar deliberadamente uma descrição ou lista de canais; e o terminal API encaminha apenas model_dump(exclude_unset=True), de modo que os campos omitidos passam para o valor no disco. Novos testes de regressão cobrem o contrato de gravação atômica, o fallback corrupt-yaml e os quatro casos de semântica de mesclagem.

Refinamentos do renderizador Markdown

A família MarkdownRenderer ganhou um suporte trackSourceLines que propaga atributos data-source-line através de cada elemento de bloco (títulos, listas, parágrafos, etc.) e ignora as passagens de normalização de mudança de linha (processMarkdownContent, normalizeMarkdownForDisplay) para que as posições AST permaneçam fiéis para consumidores de sincronização de editor/visualização. RichCodeBlock agora ignora react-syntax-highlighter inteiramente para cercas não rotuladas / text / plaintext (eliminando avisos de "linguagem desconhecida" do Prism) e as renderiza como um bloco monoespaçado simples e organizado. A detecção de sereia também foi estendida para reconhecer o estilo editor.md ```flow, ```seq e cercas ```sequence que são reescritas para sereia pelo pré-processador.

Atualização da UI do tema e do guia

Os temas padrão de luz e neve foram aprimorados com primeiros planos mais profundos, bordas mais quentes e um --primary (#B0501E) um pouco mais saturado para melhor legibilidade nas novas superfícies do cartão. A página de aprendizagem guiada (/guide) foi migrada das paletas slate-* / indigo-* codificadas para os tokens de design (var(--card), var(--primary), var(--muted-foreground), etc.), portanto, agora respeita o alternador de tema. HistorySessionPicker recebeu o mesmo tratamento, além de uma correção para carimbos de data/hora de sessão que estavam sendo tratados como milissegundos em vez de segundos (que produziam datas de 1970).

Correção de renderização de mensagens do sistema

As mensagens do sistema de back-end (por exemplo, contexto de aterramento de acompanhamento do questionário escrito pelo tempo de execução do turno) agora são filtradas no limite do UnifiedChatContext.hydrateMessages e novamente defensivamente no ChatMessageList, para que nunca apareçam como bolhas de bate-papo fantasmas na UI enquanto ainda fluem para o contexto LLM conforme pretendido.

Correções de bugs

  • Configuração do canal TutorBot apagada a cada reinicialização do servidor (#332) — create_and_start_bot estava construindo um novo BotConfig com padrões vazios em cada chamada, que _save_bot_config então persistia no config.yaml existente, limpando canais configurados pelo usuário (por exemplo, Telegram). O endpoint agora carrega primeiro a configuração existente e sobrepõe apenas os campos fornecidos pelo client.
  • Falha do middleware selective_access_log em cada resposta diferente de 200 (#334 / #335) — o middleware passou quatro argumentos para o AccessFormatter do uvicorn que espera cinco (omitindo http_version), aumentando ValueError: not enough values to unpack em cada resposta de erro. Agora lê http_version do osciloscópio ASGI com um fallback 1.1.
  • Vulnerabilidades de segurança de 15 npm (#330) — jspdf 4.0.0 → 4.2.0 (9 CVEs incluindo injeção crítica de PDF), next 16.1.1 → 16.2.3 (8 CVEs incluindo contrabando de HTTP, desvio de CSRF), mermaid 11.12.2 → 11.14.0 e o eslint-config-next correspondente. npm audit fix varreu a cadeia indireta (flatted, lodash-es, minimatch, picomatch, dompurify, ajv, brace-expansion). Estado final: 0 vulnerabilidades, sem alterações significativas.
  • .env.example_CN — removeu um sufixo // README acidental no comentário da lista de provedores.

Expansão do conjunto de testes

Adicionado um novo módulo tests/services/tutorbot/test_manager_config.py cobrindo viagens de ida e volta de carregamento/salvamento, o fallback corrompido-yaml, gravações de arquivo temporário atômico, recuperação de falha após uma gravação intermediária OSError e todas as quatro semânticas merge_bot_config (sem configuração existente, passagem de campo omitido, None-como-não-fornecido e valor vazio-como-explícito-claro). tests/api/test_tutorbot_router.py estendido com a classe de teste explícito-claro. Reescreveu os testes de roteamento resposta agora do orquestrador para fixar o novo contrato - active_capability é preservado quando answer_now_context é definido, o orquestrador volta para chat somente quando o recurso original está faltando e emite um erro claro quando nenhum deles é registrado. Adicionado um novo módulo tests/capabilities/test_answer_now.py com 28 casos cobrindo os auxiliares compartilhados (extract_answer_now_context, truncamento format_trace_summary/i18n, make_skip_notice, labeled_block, join_chunks) e todos os caminhos rápidos por capacidade: chat, deep_solve, deep_question (incluindo o não analisável-JSON fallback), deep_research, visualize (incluindo remoção de barreira de código e recuperação render_type inválida) e math_animator (verificando se run_analysis/run_design/run_summary não são invocados enquanto run_code_generation/run_render são). Um teste reverso confirma que os recursos ainda seguem seu pipeline normal quando nenhum answer_now_context está presente.
