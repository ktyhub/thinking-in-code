DeepTutor v1.3.10

#Deep Tutor v1.3.10 #DeepTutor v1.3.10 Release Notes Data de lançamento: 2026.05.10 v1.3.10 é uma versão de confiabilidade focada para os problemas relatados após v1.3.9. Ele restaura o acesso remoto Docker mais suave, faz com que os endpoints LLM autoassinados funcionem consistentemente em provedores apoiados por SDK, protege trechos de código contra citações reescreve e divide o Matrix E2EE em uma dependência de aceitação explícita.

Destaques

Docker remoto e recuperação CORS

  • O Docker de usuário único remoto funciona imediatamente novamente - quando AUTH_ENABLED=false, DeepTutor agora aceita origens de navegador via HTTP/HTTPS, então Front-ends de LAN ou de servidor remoto não atingem mais o v1.3.8/v1.3.9 CORS regressão relatada em #463.
  • Implantações autenticadas permanecem explícitas - quando AUTH_ENABLED=true, CORS ainda requer uma lista de permissões concreta por meio de CORS_ORIGIN ou CORS_ORIGINS, preservando o limite de segurança de autenticação credenciada.
  • Múltiplas origens de implantação são suportadas - CORS_ORIGINS aceita vírgula ou valores separados por nova linha, e ambos os arquivos Docker Compose passam a configuração até o contêiner de back-end.
  • As configurações não descartam mais sinalizadores de rede - CORS_ORIGIN, CORS_ORIGINS e DISABLE_SSL_VERIFY fazem parte da ordem de gravação canônica .env.

TLS do provedor e correções de renderização

  • DISABLE_SSL_VERIFY agora alcança caminhos OpenAI SDK - Compatível com OpenAI, Azure OpenAI, executor, TutorBot e incorporação herdada SDK clients recebem um httpx.AsyncClient(verify=False) compartilhado quando o flag está habilitado, corrigindo Endpoints HTTPS LLM autoassinados relatados em #464.
  • A produção ainda bloqueia desvios de TLS inseguros - ENVIRONMENT=prod ou ENVIRONMENT=production rejeita DISABLE_SSL_VERIFY, com um único aviso conectado em uso não produtivo.
  • Blocos de código mantêm os índices de array intactos - Linkificação de citação Markdown agora mascara o código protegido e embutido antes de reescrever as referências, então values[0] permanece código em vez de se tornar um link de citação #references (#468).

Compatibilidade de instalação de matriz

  • Matrix não instala mais E2EE por padrão - o extra padrão matrix e requirements/matrix.txt agora usa matrix-nio simples, evitando o Falhas de compilação python-olm / libolm observadas no macOS Python 3.14 e Apple Clang 21 (#462).
  • Salas criptografadas são um complemento explícito - instale deeptutor[matrix-e2e] ou requirements/matrix-e2e.txt quando o suporte E2EE é necessário e o libolm é disponível.
  • As falhas de tempo de execução são mais claras - O padrão da matriz é o modo não-E2EE e habilitar E2EE sem dependências de criptografia agora gera uma instalação acionável mensagem em vez de falhar no momento da importação.

Compatibilidade de tempo de execução multiusuário

  • Os caminhos padrão do espaço de trabalho permanecem estáveis fora do escopo do usuário - quando não há corrente contexto multiusuário está ativo, a resolução do caminho retorna aos dados padrão espaço de trabalho em vez de forçar um escopo administrativo.
  • O teste legado e os ganchos monkeypatch permanecem disponíveis - sessão e configurações os roteadores mantêm correções de compatibilidade usadas por testes e integrações mais antigas.
  • Os artefatos do agente local são ignorados - .claude/ agora está excluído do Git, então as árvores de trabalho locais e os metadados do agente não inserem versões acidentalmente.

Testes

  • Adicionados testes de configuração de CORS para origens remotas não autenticadas e autenticadas listas de permissões explícitas.
  • Adicionados testes OpenAI SDK HTTP-client compartilhados no núcleo do provedor, Azure, executores, TutorBot e adaptadores de incorporação.
  • Adicionados testes de exibição Markdown para citações em prosa, código protegido, código embutido, e citações explícitas com crase.
  • Adicionados testes de divisão de dependência Matrix para manter as instalações padrão livres de matrix-nio[e2e].
  • Executei novamente testes Python direcionados, testes de nó da web, verificações de Ruff e espaços em branco de diferenças validação para o patch de lançamento.

Notas de atualização

  • Se você executar Docker remoto com AUTH_ENABLED=false, nenhuma configuração extra de CORS será necessário para origens normais de navegador HTTP/HTTPS.
  • Se você executar uma implantação compartilhada ou autenticada com AUTH_ENABLED=true, defina CORS_ORIGIN ou CORS_ORIGINS para a(s) origem(ões) de frontend exata(s), por exemplo https://learn.example.com.
  • Use DISABLE_SSL_VERIFY=true apenas para testes locais, autoassinados ou sem ar Pontos finais do LLM. Permanece bloqueado em ENVIRONMENT=prod e ENVIRONMENT=production.
  • As instalações do Matrix agora não são E2EE por padrão. Para salas Matrix criptografadas, instale .[matrix-e2e] ou requirements/matrix-e2e.txt, certifique-se de que o libolm esteja presente e defina e2ee_enabled=true na configuração do canal Matrix.
  • Se você instalou anteriormente o .[matrix] apenas para obter o Matrix não criptografado mensagens, a reinstalação após esta versão não deverá mais exigir ferramentas de construção libolm. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.3.9...v1.3.10
