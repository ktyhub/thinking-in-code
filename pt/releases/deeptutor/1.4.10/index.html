#Deep Tutor v1.4.10 #DeepTutor v1.4.10 Release Notes Data de lançamento: 2026.06.21 Um acompanhamento de implantação e conta para v1.4.9: um autoatendimento página de perfil com avatares, uma história de contêiner reforçada que você pode executar sem root atrás de uma única porta e acesso mais restrito à ferramenta MCP em implantações multiusuário. Atendimento para todos — a única mudança de comportamento tem como escopo usuários não administradores em modo multiusuário.

Atenção para implantações multiusuário. As ferramentas MCP agora são negadas por padrão para usuários não administradores: um usuário normal não pode mais descobrir ou carregar ferramentas de host MCP para toda a implantação até que um administrador conceda os nomes de ferramentas específicos em sua concessão. Os administradores permanecem irrestritos e instalações de usuário único/sem autenticação não são afetados (sua sessão é executada como administrador). Nada migra e nada interrupções na atualização — se seus não administradores precisarem de ferramentas MCP, conceda os nomes no concessão do usuário.

Novidades

Página de perfil com avatares

Cada usuário conectado recebe uma página de Perfil de autoatendimento: escolha um ícone integrado (com uma cor) ou carregue sua própria imagem como avatar, veja sua conta e função, e saia. Seu avatar aparece na barra lateral e um anel de administrador marca contas de administrador rapidamente.

Execute o DeepTutor em um contêiner, pronto para rootless

Um novo CONTAINERIZATION.md a guia cobre três formatos - simples docker run, docker compose com o Sidecar PocketBase e um caminho Podman sem raiz reforçado (compose.yaml, sistema de arquivos raiz somente leitura, diretórios do sistema tmpfs) - mais um .env.example para iniciar de. O frontend agora faz proxy de /api/* e /ws/* para o backend a pedido vez, então o navegador só se comunica com uma porta (:3782): nenhum URL API criado no pacote JS, sem inicialização sed. Mapeie uma única porta e pronto.

Acesso mais restrito à ferramenta MCP no modo multiusuário

Conforme observado acima, os usuários não administradores agora falham ao fechar as ferramentas MCP até que um administrador concede os nomes. O editor de concessões apresenta concessões da ferramenta MCP junto com o lista de permissões de ferramentas integradas, para que você possa ver e definir exatamente o que cada usuário pode alcançar.

Registros mais silenciosos

200s de rotina - a pesquisa de front-end tagarela de /settings, /tools, /knowledge/list e amigos – não inundam mais o console. uvicórnio o log de acesso por solicitação agora está desabilitado em todos caminhos de inicialização (deeptutor start, o inicializador e o ponto de entrada Docker) e um único middleware apresenta apenas não 200s, aqueles que realmente valem a pena ver.

Correções

  • O estado de autenticação Client é resolvido no momento da solicitação por meio do novo proxy, que também dimensiona o corpo da solicitação para uploads (imagens de avatar, anexos).
  • A renderização do avatar retorna com segurança para cores desconhecidas em vez de virar invisível; a busca do status de autenticação é desduplicada.
  • Caminho de montagem do docker-compose.yml PocketBase corrigido.

Notas de atualização

Entrada de v1.4.9: pip install -U deeptutor; Os usuários do Docker puxam ghcr.io/hkuds/deeptutor:latest. Sem migrações, sem alterações de configuração. Somente implantações multiusuário: se os usuários não administradores dependem de ferramentas MCP, conceda os nomes de ferramentas específicos por usuário - eles falharão até que você o faça. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.4.9...v1.4.10
