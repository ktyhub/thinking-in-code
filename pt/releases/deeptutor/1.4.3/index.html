DeepTutor v1.4.3

#Deep Tutor v1.4.3 #DeepTutor v1.4.3 Release Notes Data de lançamento: 2026.06.12 O maior lançamento desde v1.4.0. TutorBot cresce em Parceiros, o Chat se resume em um único loop de agente, multiusuário se torna real isolamento por usuário e Visualize, Co-writer, o visualizador de arquivos, documento análise e o CLI sobe de nível. Os documentos em deeptutor.info foram reconstruídos ao lado de - cada canal parceiro agora tem seu próprio guia de configuração, em inglês e chinês.

Atualizando do TutorBot? A migração é automática e não destrutiva: na primeira inicialização, seus bots se tornam Parceiros — configurações do canal (segredos incluído), seleção de modelo e transferência da biblioteca de almas, e cada a persona do bot se torna seu SOUL.md. A velha árvore data/tutorbot/ é deixado intacto, para que a reversão permaneça segura. Uma mudança radical: o HTTP API movido de /api/v1/tutorbot/... para /api/v1/partners/... — atualize todos os scripts que o chamam. O pip [tutorbot] extra mantém trabalhando como apelido para [partners].

Novidades

TutorBot → Parceiros

Seus bots agora são Parceiros — mesma ideia, execução muito mais forte:

  • Os parceiros funcionam no mesmo circuito de agente que o Chat do produto (o separado o mecanismo nanobot desapareceu), então cada melhoria no bate-papo chega aos seus bots de mensagens instantâneas automaticamente.
  • Pipeline de mensagens de nível de produção: novas tentativas de envio, desduplicação, coalescência e uma matriz de entrega por canal.
  • Respostas de transmissão ao vivo no Telegram, Discord e Feishu — respostas renderizar à medida que são gerados.
  • Novo canal WeCom AI Bot; 15 conectores de canal no total, do Slack e Discord para DingTalk, QQ e WhatsApp.
  • O bate-papo na Web agora aceita anexos — coloque imagens ou arquivos diretamente uma conversa de parceiro.
  • Uma biblioteca de modelos de alma reescrita com um editor no aplicativo.

Um loop para bate-papo

O pipeline de segmentação/resposta de duas fases desapareceu. O bate-papo agora executa um único explorando o loop do agente com chamadas de ferramentas nativas de ponta a ponta - menos movimentação peças, uso mais inteligente de ferramentas, sem mais curvas mal roteadas. Uma nova Atividade header mantém a linha de status fixada no topo e dobra o pensamento/ferramenta rastreie assim que a resposta chegar.

Isolamento real multiusuário

  • Concessões por usuário v2: ferramentas, servidores MCP e acesso executivo são controlados por usuário na interface do administrador.
  • Layout do espaço de trabalho passa para data/users/<uid> + data/system; existente as implantações migram automaticamente.
  • O executor monta apenas a subárvore do espaço de trabalho do usuário chamador (novo Dockerfile.runner), para que o código em área restrita nunca veja os arquivos de outro usuário.

Visualize, reconstrua

Renderização SVG embutida e com reconhecimento de tema; prompts estruturados; e um local validar + passar de reparo substituindo a antiga revisão completa do LLM - mais rápido, mais barato e com muito menos diagramas quebrados. Tela cheia agora funciona para todos tipo visual.

Ferramentas diárias mais nítidas

  • Co-autor renderiza fluxogramas e diagramas de sequência via Mermaid, e perguntas com escopo de seleção podem ser extraídas de sua base de conhecimento e da web.
  • Visualizador de arquivos: visualizações reais de docx/xlsx no navegador, arrastar para redimensionar e o painel Atividade agora fica ao lado dos arquivos abertos.
  • Análise de nuvem MinerU como alternativa ao back-end local (/settings/mineru), e a extração de perguntas agora captura perguntas tipo, dificuldade e respostas.
  • Habilidades de escritório funcionam imediatamente — geração docx/pdf/pptx/xlsx não não requer mais a ativação de um botão sandbox.
  • CLI chat, reescrito: alinhado com o novo protocolo de loop, interativo ask_user solicita no terminal, cancelamento Ctrl-C e dobrável saída do pensamento.

Correções importantes

Os modelos Qwen não vazam mais os wrappers JSON nas respostas, o Windows instala acertar o UTF-8, os bots Zulip capturam menções de maneira confiável e um o bug de esgotamento do descritor de arquivo e as verificações de integridade falso-positivas desapareceram.

Documentos, sincronizados

deeptutor.info foi reconstruído com esta versão: um guia de configuração dedicado para cada canal de parceiro (inglês + 中文), capturas de tela atualizadas e CLI e servidor API atualizados referências.

Notas de atualização

  • pip install -U deeptutor — as migrações são executadas automaticamente no primeiro começar, e todos eles são idempotentes.
  • Árvores multi-user/ legadas passam para data/users/ no local; TutorBot bots tornam-se Parceiros (veja a nota no topo).
  • Habilidades baseadas em Exec agora permitem subprocessos por padrão. Para restaurar o antigo comportamento, defina sandbox_allow_subprocess como false nas configurações do sistema. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.4.2...v1.4.3
