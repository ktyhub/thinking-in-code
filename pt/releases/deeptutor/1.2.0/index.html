#Deep Tutor v1.2.0 #DeepTutor v1.2.0 Release Notes Data de lançamento: 2026.04.20

Destaques

Book Engine — Compilador multiagente "Living Book"

Introduzimos um novo Mecanismo de Livros (deeptutor/book/) que compila entradas do usuário — histórico de bate-papo, blocos de anotações, bases de conhecimento e intenção de formato livre — em "livros vivos" interativos, estruturados e baseados em blocos. O mecanismo fica paralelo ao ChatOrchestrator e aciona um pipeline multiagente de cinco estágios:

  1. Ideação — um LLM propõe um esboço de livro a partir da intenção do usuário e do material de origem.
  2. Exploração de origem — um agente SourceExplorer realiza recuperação profunda de RAG e verificações de integridade da base de conhecimento (kb_health.py) para revelar as passagens mais relevantes.
  3. Síntese de coluna — um agente SpineSynthesizer mescla a proposta com as fontes exploradas em uma árvore de capítulo/página (Spine → Chapter → Page).
  4. Planejamento de página — um agente PagePlanner projeta cada página como uma sequência ordenada de blocos digitados.
  5. Compilação de blocos — um BookCompiler despacha cada bloco para seu gerador dedicado. 14 tipos de bloco são fornecidos na Fase 1: texto, callout, quiz, flash cards, código, figura, aprofundamento, animação, interativo, linha do tempo, gráfico conceitual, seção, nota do usuário e um espaço reservado para blocos ainda em compilação. Cada gerador tem seus próprios prompts YAML bilíngues (en/zh) e pode chamar ajudantes RAG para conteúdo fundamentado. A UI da web (web/app/(workspace)/book/) inclui um assistente BookCreator (intenção → proposta → confirmação da lombada), um SpineEditor para reordenação de capítulos de arrastar e soltar, um PageReader com um trilho de navegação de contorno e renderizadores por bloco (gráficos conceituais renderizados como diagramas interativos direcionados à força, questionários com classificação in-line, cartões flash com animações invertidas, etc.), um BookProgressTimeline para rastreamento de compilação em tempo real, um BookChatPanel para perguntas e respostas no contexto e um BookHealthBanner que avisa quando a KB subjacente não está íntegra. Um fluxo WebSocket por livro distribui eventos de compilação para todos os clients conectados. Back-end: POST /api/v1/book/create, POST /confirm-proposal, POST /confirm-spine, POST /compile-page, GET /list, GET /{book_id}, DELETE /{book_id}, mais WS /ws/{book_id}. CLI: deeptutor book create, deeptutor book list, deeptutor book show, deeptutor book delete.

Aprendizado guiado herdado removido

O módulo deeptutor/agents/guide/ (gerenciador de guia, 4 agentes, 8 prompts YAMLs) e toda a UI web /guide (componentes, ganchos, tipos, roteador API — ~5.300 linhas) foram removidos. O Book Engine substitui o Aprendizado Guiado por uma arquitetura mais rica e extensível.

Espaço de trabalho do coautor de vários documentos

O Co-Writer não é mais um bloco de notas de documento único. Cada documento agora obtém seu próprio diretório persistente em data/user/workspace/co-writer/documents/ com gravações de manifesto atômico (CoWriterStorage). A UI da web direciona para páginas por documento (/co-writer/[docId]) e a barra lateral mostra uma seção CoWriterRecent para acesso rápido. Os novos endpoints API lidam com CRUD de documentos completos (GET /list, POST /create, GET /{doc_id}, PATCH /{doc_id}, DELETE /{doc_id}).

Visualizações HTML interativas

O recurso Visualize agora oferece suporte a um quarto tipo de renderização — html — junto com svg, chartjs e mermaid. Quando o LLM determina que a solicitação do usuário requer "interação do usuário + mudanças de estado + texto/gráficos mistos" (por exemplo, demonstrações arrastáveis, orientações passo a passo, exercícios práticos clickable), ele produz uma página HTML de arquivo único independente que é renderizada dentro de um iframe. Uma passagem de validação local (is_valid_html_document) verifica a saída antes de servir; se o modelo retornar algo não renderizável, um modelo substituto estilizado será injetado. O estágio de revisão do LLM é ignorado para páginas HTML (economizando de 30 a 60 segundos de latência com perda de qualidade insignificante). Um novo modo de restrição figure restringe o LLM apenas a svg/chartjs/mermaid - usado internamente pelo bloco de figuras do Book Engine.

Banco de Perguntas @-Menção no Chat

Um novo componente QuestionBankPicker permite que os usuários mencionem entradas individuais do banco de perguntas diretamente no compositor do chat. As entradas selecionadas são resolvidas no tempo de execução (_build_question_bank_context) em um contexto Markdown estruturado - incluindo texto da pergunta, opções, respostas do usuário/referência e explicações - e injetadas junto com referências de caderno e histórico para que o LLM possa raciocinar sobre o desempenho específico do questionário anterior.

Exteriorização imediata — Fase 2

Continuação da migração de strings LLM codificadas para arquivos YAML editáveis:

  • answer_now — Os recursos question, research, solve e visualize agora carregam seus prompts de atalho do prompts/{en,zh}/answer_now.yaml.
  • agentes notebook — prompts analysis_agent e summarize_agent movidos para YAML; os módulos Python agora delegam ao gerenciador de prompt.
  • Módulos de capacidade (_answer_now.py, deep_question.py, deep_research.py, deep_solve.py, visualize.py) reduzidos de acordo.

Módulo Co-Escritor Reestruturado

Mudou deeptutor/agents/co_writer/ para deeptutor/co_writer/ (módulo de serviço de nível superior) para refletir sua natureza autônoma junto com deeptutor/book/.

Revisão da barra lateral

  • Entrada de navegação "Aprendizagem guiada" substituída por Livro (ícone da biblioteca).
  • Adicionadas seções da barra lateral BookRecent e CoWriterRecent com navegação por item.
  • Estado recolhido/expandido da barra lateral elevado para AppShellContext para que persista nas transições de rota.
  • Barra lateral recolhida refinada: logotipo + alternância de expansão em camadas com revelação instantânea, botão circular "Novo bate-papo", divisórias sutis e espaçamento consistente.

Capacidade e atualização do painel de configuração

Atualizadas definições de tipo compartilhado e painéis de configuração em Quiz, Research, Visualize e Math Animator para alinhar com novas opções de recursos (por exemplo, modo de renderização html, chaves de localidade expandidas). TracePanels na interface do chat recebeu melhorias de layout e estilo.

README e atualização de localização

Todos os nove arquivos README localizados (AR, CN, ES, FR, HI, JA, PT, RU, TH) atualizados para refletir o Book Engine, o Co-Writer de vários documentos e outros recursos do v1.2.0.

Correções de bugs

  • Falha no momento da importação do gerenciador de canal — loguru.logger foi importado no escopo do módulo, causando ImportError quando as dependências do TutorBot estavam ausentes. Substituído por uma função preguiçosa de fábrica _logger().
  • test_app_facade.py obsoleto — removeu um módulo de teste obsoleto que fazia referência a caminhos de código excluídos.
  • __init__.py ausente em pacotes de teste — arquivos init adicionados em tests/agents/, tests/api/, tests/cli/, tests/knowledge/, tests/scripts/, tests/services/llm/, tests/services/memory/, tests/services/search/, tests/services/session/ e tests/tools/ para corrigir a resolução de importação.

Conjunto de testes e CI

  • CI agora instala o requirements/tutorbot.txt e o armazena em cache juntamente com os requisitos do servidor/cli.
  • Removido o obsoleto test_app_facade do manifesto de teste de CI.
  • conftest.py atualizado para testes de pipeline RAG; paridade de prompt atualizada, tempo de execução de recursos, configuração de sonda LLM, provedor de fábrica, catálogo de modelos, carregador de configuração e testes de serviço de notebook para corresponder às importações reestruturadas.
  • Adicionados ativos favicon e apple-touch-icon para metadados PWA. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.1.2...v1.2.0
