DeepTutor v1.3.1

#Deep Tutor v1.3.1 #DeepTutor v1.3.1 Release Notes Data de lançamento: 2026.04.28 v1.3.1 é uma versão de estabilidade após v1.3.0. Ele se concentra em roteamento RAG mais seguro, validação de incorporação mais forte, reinicializações Docker/TutorBot mais confiáveis e um conjunto de pequenas, mas importantes correções de Web UX.

Destaques

RAG mais seguro e roteamento da base de conhecimento

  • KB selecionado agora está no estado do sistema trusted - chamadas RAG de bate-papo não permitem mais LLM inventa ou substitui kb_name; o modelo vê apenas um query e DeepTutor roteia-o para a KB selecionada na UI/sessão.
  • Sem fallback silencioso quando o RAG não tiver KB - se o RAG estiver ativado, mas nenhum KB estiver selecionado, o turno ignora a recuperação de KB com uma mensagem de progresso clara de consultar acidentalmente o estado obsoleto/padrão.
  • Os aliases da KB padrão são tratados de forma consistente - default, current, selected e equivalentes chineses resolvem para o KB padrão configurado para chamadas de ferramentas, listagem de arquivos e reindexação de APIs, enquanto uma KB real chamada default ainda vence o pseudônimo.
  • Adições incrementais de documentos usam a camada de serviço - a adição de arquivos agora vai através de RAGService.add_documents, mantendo o comportamento de adição/pesquisa/reindexação ativado o mesmo provedor e caminho da versão do índice.
  • Os componentes internos do RAG são mais fáceis de manter - o pipeline LlamaIndex foi dividido em módulos focados para carregamento, incorporação, armazenamento, erros e orquestração; a recuperação inteligente de múltiplas consultas agora reside no SmartRetriever.

Incorporação e confiabilidade do índice

  • As respostas incorporadas são validadas antes do uso - DeepTutor agora rejeita vetores descartados, valores nulos, valores não numéricos, valores não finitos e dimensões inconsistentes antes de atingirem o LlamaIndex.
  • Testes de conexão sondam o comportamento do lote - a incorporação de testes de fumaça agora envia um lote minúsculo, capturando provedores que retornam apenas um vetor ou alteração dimensões entre entradas.
  • Índices incorretos falham com mensagens acionáveis - vetor nulo ou incompatibilidade de forma falhas de recuperação agora retornam uma dica de reindexação em vez de expor Erros de estilo NoneType * float.
  • O status do índice é menos barulhento durante as gravações - versão vazia em andamento os diretórios não marcam mais KBs novos como needs_reindex e falharam ao esvaziar as pastas de versão são limpas quando possível.
  • Exemplos de incorporação foram esclarecidos - services/embedding/.env.example agora documenta a semântica completa de URL de endpoint e exemplos concretos de provedores para OpenAI, SiliconFlow, Ollama, Cohere, Jina, vLLM, Azure OpenAI, DashScope e Gateways estilo OpenAI-SDK.

Docker, memória e tempo de execução do TutorBot

  • Imagens Docker podem expor a versão do aplicativo - APP_VERSION é transmitido para variáveis de ambiente de tempo de execução de back-end e front-end.
  • A memória compartilhada tem seu próprio volume Docker - componha arquivos agora montados ./data/memory:/app/data/memory; Os documentos de persistência README foram atualizados.
  • A migração de memória é mais segura - os arquivos legados SUMMARY.md e PROFILE.md são copiado para data/memory mesmo quando o diretório de destino já existe, enquanto os arquivos de destino existentes são preservados.
  • As atualizações de memória são serializadas - reescritas simultâneas de perfil/resumo agora execute sob um bloqueio para evitar gravações de corrida.
  • A intenção de reinicialização do TutorBot é preservada - o desligamento normal do servidor mantém cada sinalizador auto_start do bot intacto para a próxima reinicialização do Docker/host, enquanto manual paradas ainda desabilitam a inicialização automática.
  • TutorBot compartilha memória de longo prazo - os agentes bot iniciados agora recebem o diretório de memória compartilhada em vez de funcionar sem ele.

Correções de experiência do usuário na Web e na criação

  • Envio de mensagens seguras para IME - os compositores de bate-papo não enviam mais quando Enter é sendo usado para confirmar candidatos IME chineses/japoneses/coreanos.
  • A lista de conhecimento permanece atualizada no bate-papo - a página de bate-papo recarrega os metadados da base de conhecimento em mudanças de foco, exibição de página e visibilidade, portanto, KBs recém-criados ou reindexados aparecem sem uma atualização completa.
  • A visualização do Markdown protege pseudotags - tags desconhecidas semelhantes a HTML, como <think> são escapados para exibição enquanto preservam as contagens de linha de origem para sincronização do editor/visualização.
  • A saída do co-escritor tira tags de raciocínio - fechadas, com alias, atribuídas e os blocos <think> / <thinking> não fechados são removidos da saída de edição final.
  • A inicialização do tema é executada antes da hidratação - o script do tema é renderizado do servidor para que a preferência escuro/claro seja aplicada antes da hidratação do React.
  • O feedback da UI de conhecimento é mais claro - os chips da versão do índice têm rótulos mais limpos, índices ativos vazios com falha são explicados e 404s da UI mais recente versus mais antiga O back-end Docker agora sugere extrair/recriar o contêiner.
  • O feedback da página de memória é mais claro - as chamadas de atualização distinguem "marcado, não atualizações de longo prazo" de falhas reais.

Inicialização e robustez do Windows

  • Fluxos CLI/servidor toleram páginas de código herdadas - scripts de inicialização e API os executores usam fluxos de texto seguros para substituição para evitar falhas de Unicode no Windows localidades como GBK/CP936.
  • Os processos filhos herdam uma codificação mais segura - caminhos de inicialização da web/tour definidos PYTHONIOENCODING=utf-8:replace.
  • Arquivos env frontend gerados são UTF-8 - start_web.py agora grava web/.env.local com codificação UTF-8 explícita.
  • GHCR compose extrai imagens mais recentes - docker-compose.ghcr.yml agora usa pull_policy: always para a imagem publicada.
  • Documentos/localidades foram atualizados - As notas de persistência README foram atualizadas, o O link README em polonês foi adicionado e a cópia da IU em inglês/chinês desapareceu rótulos para conhecimento, memória, modelos de alma do TutorBot e rascunhos do Co-escritor.

Testes

  • Cobertura adicionada/atualizada para roteamento de KB RAG de bate-papo, aliases de KB padrão, conhecimento arquivar/reindexar APIs, incorporando validação de lote, vetor inválido LlamaIndex falhas, status da versão do índice em andamento, layout de armazenamento adicional incremental, Memória compartilhada/inicialização automática do TutorBot, migração de memória, codificação Windows CLI, Manipulação de teclado IME, marcação de marcação escaping e limpeza de marcação de raciocínio.

Notas de atualização

  • Os usuários do Docker devem extrair e recriar o contêiner para que a interface da Web e o back-end conhecimento APIs permanecem sincronizados.
  • Se uma KB foi indexada com um provedor de incorporação quebrado ou alterado, use Reindexar na página Knowledge após corrigir as configurações de incorporação.
  • Se você persistir os dados manualmente, adicione a nova montagem de memória compartilhada: ./data/memory:/app/data/memory. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.3.0...v1.3.1
