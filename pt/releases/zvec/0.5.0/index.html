#zvec v0.5.0

🚀 Zvec v0.5.0 Release Notes

📦 Novos recursos

  • Pesquisa de texto completo (FTS): Zvec agora oferece suporte nativo à pesquisa de texto completo - anexe um índice FTS a qualquer campo de string e consulte-o com linguagem natural ou expressões estruturadas, com gerenciamento de índice por meio de Collection::CreateIndex / DropIndex. (#408, #445)
  • Recuperação híbrida: Combine recuperação de texto completo, vetor denso e vetor esparso em uma única chamada de consulta, com filtragem escalar e reclassificação; a execução e a reclassificação nativas de múltiplas consultas agora se comportam de forma consistente em Python, Go, Rust e C++. (#459, #405)
  • Índice DiskANN: Adicionado um novo índice DiskANN que mantém a maior parte do índice no disco em vez de na RAM, reduzindo drasticamente o uso de memória para conjuntos de dados em escala de bilhões e tornando viável a pesquisa de ANN em grande escala em máquinas com restrição de memória. (#369)
  • Seleção de campo de saída: fetch() agora aceita um parâmetro output_fields para controlar quais campos são retornados. (#358)

🌐 Ecossistema

Além do motor principal, o ecossistema Zvec se expande com o novo idioma oficial SDKs e uma ferramenta de gerenciamento visual:

  • Go SDK oficial (zvec-go): ligações cgo envolvendo libzvec_c_api, com bibliotecas pré-construídas para Linux (x64/ARM64), macOS (ARM64) e Windows (x64).
  • Rust SDK oficial (zvec-rust): Ligações Rust seguras e idiomáticas com gerenciamento de recursos RAII, construtor APIs e tratamento de erros Result<T>; suporta macOS (x86_64/ARM64), Linux (x86_64/ARM64) e Windows (x86_64/MSVC).
  • Zvec Studio (zvec-studio): Uma ferramenta de gerenciamento visual para o banco de dados vetorial incorporado Zvec — navegue em dados, teste consultas e gerencie esquemas sem escrever código. Instale via pip install zvec-studio ou baixe o aplicativo desktop para macOS/Linux/Windows.

🚀 Melhorias de desempenho

  • Otimização mais rápida: Reutilize o primeiro arquivo de índice vetorial como base de mesclagem durante a otimização. (#440)
  • Lançamento do GIL nas ligações: Libera o GIL nas ligações da coleção para melhor simultaneidade do Python. (#363)

🐞 Correções de bugs

  • Correção de dados: Correção do SIGABRT de coluna anulável em coleções de vários segmentos, vazamento de nulo por meio de filtros escalares anuláveis, sincronização de esquema de consulta após DDL e contaminação cruzada do otimizador SQL via QueryInfo por segmento. (#415, #416, #410, #429, #449)
  • Estabilidade do índice: Hardened DiskANN (entrada medoide, falha de compilação simultânea, qualidade de remoção), RaBitQ (mesclagem de vetor bruto durante a otimização, caminho do conversor, validação ex_bits), ordenação de resultados de fertilização in vitro e nomenclatura de índice de vetor. (#433, #456, #425, #436, #422, #421)
  • Correções diversas: Conflito de macro do Windows, especificadores de formato uint64_t, busca de contexto HNSW e testes de unidade Python. (#435, #374, #386, #401)

🔧 Refatoração e limpeza

  • Consulta unificada API: VectorQuery foi eliminado, consulta unificada de destino único em SearchQuery e mudou a reclassificação para uma interface baseada em vetor. (#428, #431, #458, #267)
  • Limpeza da base de código: Aplicou modernize-use-override, esclareceu IDs de linha local de segmento, ajustou a compilação DiskANN, mudou para uma lista de permissões de CPU x86 explícita, removeu a métrica Hamming e o Buffer Manager e revisou mensagens de erro. (#442, #419, #432, #475, #258, #365, #437, #400)

🤖 Melhorias de CI e construção

  • Build Hardening: -Werror ativado em todas as plataformas CI, RISC-V FastPFOR corrigido via SIMDe, inclusões de terceiros marcadas como SYSTEM e caminhos DiskANN CMake corrigidos. (#460, #470, #413, #464)
  • CI mais rápido: Adicionado ccache/sccache (incl. Windows), testes paralelizados, acelerou o clang-tidy, definiu o escopo do fluxo de trabalho principal e reduziu o CRoaring a um amálgama (~292M → ~1MB). (#360, #439, #454, #384, #412, #417, #418, #438, #396, #448, #381)
  • Solavancos de dependência: actions/cache 4→5 e codecov/codecov-action 6→7. (#466, #467)
