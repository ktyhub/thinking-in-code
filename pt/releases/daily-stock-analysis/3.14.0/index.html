daily_stock_análise v3.14.0

Destaques do lançamento

  • 📊 A grande revisão do mercado é atualizada para uma estrutura de bancada após o expediente — A revisão das ações A fixa a saída da temperatura do mercado, detalhes do índice, tabela superior do setor, catalisador de notícias, plano de negociação de amanhã e aviso de risco, reduzindo a duplicação e o vazio da revisão de texto puro.
  • 🖥️ Novo lembrete de atualização de lançamento do GitHub na área de trabalho — A área de trabalho do Windows/macOS detectará automaticamente a nova versão após a inicialização. Você também pode verificar manualmente e ir para a página de download na página de configurações.
  • 🤖 O carregamento de dados do Pipeline Agent foi bastante reduzido em termos de ruído — a ferramenta K-line foi alterada para DB-first e pré-aquece 240 dias de dados históricos para evitar solicitações HTTP repetidas para o mesmo estoque.
  • 🐳 Organização do link de lançamento do Docker — O fluxo de trabalho de lançamento converge em dois caminhos: lançamento oficial e reedição manual. O nome oficial da imagem do Docker Hub é unificado para zhulinsen/daily_stock_analysis.
  • 🔧 Aprimoramento de configuração do canal LLM e DeepSeek V4 — A análise agendada de ações GitHub conclui a transmissão transparente variável multicanal, e os padrões e exemplos oficiais do canal DeepSeek são sincronizados com V4.
  • 🧩 Verificação de consistência de recursos estáticos do desktop — Tanto o link do pacote quanto o tempo de execução podem detectar incompatibilidades de recursos estáticos mais cedo, reduzindo o custo da solução de problemas de tela branca para pacotes de lançamento.

Novos recursos

  • 🏠 Nova entrada de reanálise na área de relatório histórico da página inicial da Web — suporta refazer a análise do mesmo estoque na mesma data com base no prompt original.
  • 🖥️ Lembrete de atualização do novo lançamento do GitHub na área de trabalho Windows/macOS - detecta automaticamente a nova versão após a inicialização e oferece suporte à verificação manual na página de configurações para ir para a página de download.

Melhorias

  • 📊 O relatório de análise do mercado de ações A foi alterado para um formato de bancada estruturado após o expediente - resultados fixos da temperatura do mercado, detalhes do índice, tabela superior do setor, catalisador de notícias e plano de negociação de amanhã.
  • 🐳 Convergência do fluxo de trabalho de lançamento do Docker — Distinguir mais claramente entre links de lançamento oficial e reemissão manual e unificar o nome da imagem oficial do Docker Hub como zhulinsen/daily_stock_analysis.
  • 🤖 A ferramenta diária do agente dá prioridade à reutilização do cache local - Ao mesmo tempo, persiste as informações diárias e de notícias recém-obtidas para reduzir chamadas repetidas de fontes de dados.

Correção

  • 🤖 Carregamento inicial do banco de dados da ferramenta K-line do Pipeline Agent — get_daily_history / analyze_trend / calculate_ma / get_volume_analysis / analyze_pattern alterado para ler o banco de dados local primeiro, eliminando 9x5=45 solicitações HTTP repetidas para o mesmo estoque (Correções #1066).
  • 🤖 O Pipeline Agent pré-aquece o histórico da linha K de 240 dias para o banco de dados sob demanda antes da execução — Em circunstâncias normais, as chamadas de ferramenta da linha K não exigem solicitações repetidas de rede.
  • 🕒 Congelar target_date e transmiti-lo de forma transparente para o thread da ferramenta Pipeline Agent K-line por meio do ContextVar — Elimine o desvio de tempo entre os limites de fechamento.
  • 🪟 Reparo de codificação de cópia de log de back-end da área de trabalho do Windows — UTF-8 é preferido ao copiar stdout/stderr e é compatível com fallback de página de código local para evitar logs chineses distorcidos.
  • ⚙️ O fluxo de trabalho de análise diária de ações GitHub conclui a transmissão transparente de variável de canal LLM — suporta LLM_CHANNELS, multi-chave e LLM_<NAME>_* comumente usado para evitar que configurações de vários modelos disponíveis localmente sejam invalidadas em tarefas agendadas na nuvem (Correções #1063, #872).
  • 📈 A interface de detalhes do relatório histórico corrige o valor change_pct — Use is None para julgar para evitar descartar 0.0 (mercado estável) como um valor ausente, remova o resultado final errado de change_60d e retorne ao campo original do mercado em tempo real quando estiver faltando (Correções #1084).
  • 🔧 As predefinições de canal oficial e configurações de amostra do DeepSeek são sincronizadas com V4 — retém o valor padrão legado deepseek-chat e adiciona um prompt de abandono, e também corrige o problema em que a seleção de tempo de execução antigo após a descoberta do modelo causa falha no salvamento (Correções #1108, #1109).
  • 🧩 Nova verificação de consistência de recursos estáticos para links de pacotes de desktop — scripts/check_static_assets.py verificará se os recursos referenciados por index.html realmente existem nos produtos de origem static/ e PyInstaller. O tempo de execução também gravará logs claros em caso de incompatibilidade para evitar o reaparecimento da tela branca após a abertura do pacote Release (Refs #1064/#1065/#1050).
  • 🧩 Backend /assets/* é alterado para hospedagem de roteamento explícito - quando o recurso está faltando, text/javascript / text/css 404 correspondente à extensão solicitada é retornado, reduzindo a solução de problemas enganosa causada pela resposta de erro padrão JSON (Refs #1064).
  • 🌙 kimi-k2.6 usa automaticamente temperatura fixa — temperature=1.0 é usado automaticamente quando a análise principal, revisão de disco grande e Agente chamam o modelo para evitar que o modelo rejeite a solicitação de temperatura padrão (Correções #1102).

Documentação

  • 🐳 Instruções oficiais complementares de uso de imagem Docker — Adicionadas instruções para extração de imagem, uso de docker run e mapeamento de diretório .env/dados, não cobrindo mais apenas o caminho de implantação do Compose.
  • 📨 Correção do exemplo de Webhook do robô personalizado Feishu — O exemplo em feishu_sender.py foi alterado para cartão interativo JSON, e o tutorial de configuração do gatilho Webhook automatizado Feishu foi complementado.
  • 📚 **Otimize a estrutura README raiz ** - retenha os recursos funcionais no nível da página inicial, pilha de tecnologia, início rápido, efeito push, Web, agente, patrocinador e entrada de fonte de notícias, feche a configuração detalhada, disciplina de transação e semântica fundamental para o guia completo e aponte o emblema Docker para a página espelhada oficial.
  • 🌐 Sincronize a estrutura de entrada simplificada do README em inglês e chinês tradicional - e preencha o uso do LLM API e as instruções de gerenciamento de posição no guia completo.
  • 🤝 Ajuste as regras de manutenção do README na colaboração de IA e nos modelos de relações públicas — Deixe claro que o README não será atualizado a menos que necessário, e os detalhes terão prioridade em documentos especiais.

Teste

  • 🧪 Estabilize o comportamento do stub do LiteLLM para testes relacionados à análise de mercado — Evite que o LiteLLM instalado localmente afete os testes unitários de análise de mercado quando a ordem de coleta de testes for alterada.
  • 🧪 pytest ignora o diretório dependente do front-end por padrão — Quando apps/dsa-web/node_modules existir localmente, ele não será mais verificado recursivamente pelo teste de back-end para evitar que o portão seja desacelerado por diretórios irrelevantes antes do lançamento.
