daily_stock_análise v3.6.0

Adicionado

  • 🗑️ Exclusão em lote do histórico — a UI da Web agora suporta seleção múltipla e exclusão em lote do histórico de análise; adicionado endpoint POST /api/v1/history/batch-delete e componente ConfirmDialog.
  • 🔐 Configurações de autenticação API — novo endpoint POST /api/v1/auth/settings para ativar ou desativar a autenticação da Web em tempo de execução e definir a senha de administrador inicial quando necessário
  • Openclaw Skill 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ Protocolo de canal LLM/teste UX — .env e configurações da Web agora compartilham o mesmo formato de canal (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED); A página de configurações adiciona testes de conexão por canal, seleção de modelo primário/substituto/visão e prefixação de modelo com reconhecimento de protocolo
  • 🤖 Arquitetura do agente Fase 0+1 — protocolos compartilhados (AgentContext, AgentOpinion, StageResult), executor run_agent_loop() extraído, switch AGENT_ARCH (single/multi), entradas de registro de configuração
  • 🔍 Roteamento Bot NL — roteamento de linguagem natural de duas camadas: pré-filtro regex barato (códigos de ações + palavras-chave financeiras) → análise leve de intenção LLM; controlado por AGENT_NL_ROUTING=true; suporta extração de vários estoques e estratégias
  • 💬 Análise multi-stock /ask — códigos separados por vírgula ou vs (máximo 5), execução de thread paralela com tempo limite de 150s (preserva resultados parciais), tabela de resumo de comparação de Markdown na parte superior
  • 📋 Comando /history — isolamento de sessão por usuário via formato {platform}_{user_id}:{scope} (delimitador de dois pontos evita colisão de prefixo); lista as sessões /chat e /ask; ver detalhes ou limpar
  • 📊 Comando /strategies — lista os arquivos de estratégia YAML disponíveis agrupados por categoria (趋势/形态/反转/框架) com status de ativação ✅/⬜
  • 🔧 Ferramentas de resumo de backtest — get_strategy_backtest_summary e get_stock_backtest_summary registrados como ferramentas de agente somente leitura
  • ⚙️ Detecção automática de agente — is_agent_available() detecta automaticamente de LITELLM_MODEL; AGENT_MODE=true/false explícito tem precedência total
  • 🏗️ Orquestrador Multiagente (Fase 2) — AgentOrchestrator com 4 modos (quick/standard/full/strategy); substituição imediata para AgentExecutor via AGENT_ARCH=multi; BaseAgent ABC com filtragem de subconjunto de ferramentas, injeção de dados em cache e saída estruturada AgentOpinion
  • 🧩 Agentes especializados (Fase 2-4) — TechnicalAgent (8 ferramentas, análise de tendência/MA/MACD/volume/padrão), IntelAgent (notícias e sentimento, propagação de sinalizadores de risco), DecisionAgent (síntese no painel de decisão JSON), RiskAgent (7 categorias de risco, gravidade de dois níveis com substituição suave/dura)
  • 📈 Sistema de estratégia (Fase 3) — StrategyAgent (avaliação por estratégia a partir de habilidades YAML), StrategyRouter (detecção de regime baseado em regras → seleção de estratégia), StrategyAggregator (consenso ponderado com fator de desempenho de backtest)
  • 🔬 Agente de Pesquisa Profunda (Fase 5) — ResearchAgent com abordagem em 3 fases (decompor → subquestões de pesquisa → sintetizar relatório); rastreamento de orçamento simbólico; novo comando de bot /research com aliases (/深研, /deepsearch)
  • 🧠 Memória e calibração (Fase 6) — AgentMemory com rastreamento de precisão de previsão, calibração de confiança (ativada após o limite mínimo de amostra), ponderação automática de estratégia com base na taxa de vitória histórica
  • 📊 Agente de portfólio (Fase 7) — PortfolioAgent para análise de portfólio multi-ações (dimensionamento de posição, concentração setorial, risco de correlação, ligação entre mercados, sugestões de reequilíbrio)
  • 🔔 Alertas orientados a eventos (Fase 7) — EventMonitor com regras PriceAlert, VolumeAlert, SentimentAlert; verificação assíncrona, notificações de retorno de chamada, persistência serializável
  • ⚙️ Novas entradas de configuração — AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING — todas registradas em config.py + config_registry.py (configurável por WebUI)

Alterado

  • 🔐 Semântica do estado da senha de autenticação — a existência da senha armazenada agora é rastreada independentemente da ativação da autenticação; quando a autenticação está desabilitada, /api/v1/auth/status retorna passwordSet=false preservando a senha salva para reativação futura
  • 🔐 As configurações de autenticação reativam a proteção — reativar a autenticação com uma senha armazenada agora requer currentPassword, e a falha na criação da sessão reverte a alternância de autenticação para evitar bloqueio
  • ♻️ AgentExecutor refatorado — _run_loop delega para runner.run_agent_loop() compartilhado; código de serialização/análise/rótulo de pensamento duplicado removido
  • ♻️ Troca de agente unificada — Bot, API e Pipeline usam config.is_agent_available() em vez de verificações divergentes de config.agent_mode
  • 📖 README.md — seção expandida de comandos do bot (ask/chat/strategies/history), nota de roteamento NL adicionada, descrição atualizada do modo de agente
  • 📖 .env.example — adicionada documentação de configuração AGENT_ARCH e AGENT_NL_ROUTING

Corrigido

  • 🐛 Rotação secreta de sessão no Windows — use substituição atômica para que as alternâncias de autenticação invalidem as sessões existentes, mesmo quando .session_secret já existe
  • 🐛 Auth toggle atomicity — persiste ADMIN_AUTH_ENABLED antes de girar o segredo da sessão; em caso de falha na rotação, reverta para o estado de autenticação anterior
  • 🔧 Proteções de seleção de tempo de execução LLM — O editor de canal no modo YAML não cobre mais LITELLM_MODEL / fallback / Vision; a verificação da configuração do sistema adiciona a verificação da fonte de tempo de execução depois que todos os canais são desabilitados e corrige o problema de modelos de alias de protocolo, como vertexai/..., serem prefixados repetidamente
  • 🐛 Regressões de acompanhamento /ask de múltiplas ações — a sobreposição de portfólio agora compartilha o mesmo orçamento de tempo limite da fase por ação e é ignorada no tempo limite em vez de bloquear a resposta do bot; /history agora armazena o resumo legível por ação em vez do painel bruto JSON; a saída multi-stock condensada agora renderiza valores numéricos sniper_points
  • 🐛 Compatibilidade de enum do painel de decisão — o multiagente DecisionAgent agora mantém decision_type dentro do contrato legado buy|hold|sell e normaliza saídas perdidas de strong_* antes da substituição de risco, conversão de pipeline e downstream统计/通知汇总
  • 🛟 Fullback de resultado parcial multiagente — IntelAgent agora armazena em cache a informação analisada para reutilização downstream, a análise compartilhada JSON tolera saída de modelo levemente malformada e o orquestrador preserva/sintetiza um painel mínimo em caso de tempo limite ou falha de análise no meio do pipeline, em vez de sempre colapsar para 50/观望/未知
  • 🐛 Roteamento LiteLLM compartilhado restaurado — a análise de intenção do bot NL e o planejamento/síntese ResearchAgent agora reutilizam o mesmo adaptador LiteLLM / roteador / fallback / caminho de injeção api_base como o fluxo do agente principal, para que as implantações compatíveis com LLM_CHANNELS / LITELLM_CONFIG / OpenAI se comportem de forma consistente
  • 🐛 Compatibilidade com versões anteriores da sessão de bate-papo do bot — /chat agora continua usando o ID de sessão legado {platform}_{user_id} quando o histórico antigo já existe, e /history ainda pode listar/visualizar/limpar essas sessões de pré-migração junto com o novo formato {platform}_{user_id}:chat
  • 🐛 Rejeição de regra não suportada do EventMonitor — validação de configuração/carregamento de tempo de execução agora rejeita ou ignora tipos de alerta que o monitor ainda não pode avaliar, portanto, o modo de agendamento não aceita mais silenciosamente regras permanentes de não operação
  • 🐛 Correção de estabilidade de agregação fundamental P0 (#614) — Corrija a regressão semântica do setor get_stock_info (adicione belong_boards e retenha aliases compatíveis com boards), introduza retornos simplificados de contexto fundamental para controlar tokens, adicione eliminação máxima de entrada ao cache fundamental e complete a agregação de status geral do ETF e filtragem de campo do setor NaN para garantir falha de abertura e intrusão mínima.
  • 🔧 Adição de variáveis ​​de ambiente do mecanismo de pesquisa GitHub Actions — Workflow adiciona mapeamento de variáveis ​​de ambiente MINIMAX_API_KEYS, BRAVE_API_KEYS, SEARXNG_BASE_URLS, permitindo que os usuários do GitHub Actions configurem serviços de pesquisa MiniMax, Brave, SearXNG (anteriormente v3.5.0 tinha implementação de provedor adicionada, mas não tinha configuração de fluxo de trabalho)
  • 🤖 Consistência de tempo de execução multiagente — AGENT_MAX_STEPS agora se propaga para cada subagente orquestrado; adicionado orçamento cooperativo AGENT_ORCHESTRATOR_TIMEOUT_S para interromper pipelines muito longos antes que eles se espalhem ainda mais
  • 🔌 Fiação de recurso multiagente — AGENT_RISK_OVERRIDE agora faz downgrade ativamente dos painéis finais em descobertas de riscos concretos; AGENT_MEMORY_ENABLED agora injeta memória de análise recente + calibração de confiança em agentes especializados; /ask multi-ações agora executa PortfolioAgent para adicionar alocação em nível de portfólio e orientação de concentração
  • 🔔 Fiação de tempo de execução do EventMonitor — o modo de agendamento agora pode carregar regras de alerta do AGENT_EVENT_ALERT_RULES_JSON, pesquisá-las no AGENT_EVENT_MONITOR_INTERVAL_MINUTES e enviar alertas acionados por meio do serviço de notificação existente
  • 🛠️ Correções de estabilidade de acompanhamento — /ask de vários estoques agora volta à saída de texto utilizável quando a análise do painel JSON falha; O EventMonitor ignora regras semanticamente inválidas em vez de abortar a inicialização do agendamento; a pesquisa de alertas em segundo plano agora é executada independentemente do loop de análise agendado principal
  • 🧪 Cobertura de regressão multiagente — testes de execução do orquestrador adicionados para run(), chat(), falha em estágio crítico, degradação normal e tratamento de tempo limite
  • 🧹 Limpeza do PortfolioAgent — post_process() agora reutiliza a análise compartilhada do JSON e remove importações obsoletas não utilizadas
  • 🚦 Envio assíncrono de bot — CommandDispatcher agora expõe dispatch_async(); A análise de intenção NL e a execução do comando padrão são descarregadas do loop de eventos, o fluxo DingTalk aguarda manipuladores assíncronos diretamente e o processamento do fluxo Feishu é movido para fora do thread de retorno de chamada SDK
  • 🌐 Async webhook handler — nova função handle_webhook_async() em bot/handler.py para uso em contextos assíncronos (por exemplo, FastAPI); chama dispatch_async() diretamente sem ponte de thread
  • 🧵 Fluxo Feishu ThreadPoolExecutor — substituiu a geração ilimitada de Thread por mensagem por um ThreadPoolExecutor(max_workers=8) limitado para evitar explosão de thread em rajadas de mensagens
  • 🔒 Segurança do EventMonitor — _check_volume() agora lida com segurança com get_daily_data retornando None (sem falha na descompactação da tupla); Os retornos de chamada on_trigger suportam chamadas sincronizadas e assíncronas via asyncio.to_thread/await
  • 🧹 Desduplicação do ResearchAgent — _filtered_registry() agora delega para BaseAgent._filtered_registry() em vez de duplicar a lógica de filtragem
  • 🧹 Limpeza de espaço em branco à direita do bot — removidos problemas de espaço em branco W291/W293 em bot/handler.py, bot/dispatcher.py, bot/commands/base.py, bot/platforms/feishu_stream.py, bot/platforms/dingtalk_stream.py
  • 🐛 Segurança do despachante _parse_intent_via_llm — substituiu o frágil 'raw' in dir() por 'raw' in locals() para proteção de variável indefinida no manipulador JSONDecodeError
  • 🐛 Complete a estrutura do chip LLM quando não estiver preenchida (#589) — Quando DeepSeek e outros modelos não preenchem chip_structure corretamente, ele irá completá-lo automaticamente com os dados do chip obtidos da fonte de dados para garantir que a exibição de cada modelo seja consistente; tanto a análise normal quanto o modo Agente são válidos
  • 🐛 Relatório de histórico de ponto de atirador exibe texto original (#452) — A página de detalhes históricos agora dá prioridade à exibição da string original em raw_result.dashboard.battle_plan.sniper_points para evitar que a coluna numérica analysis_history comprima intervalos, texto explicativo ou pontos complexos em um único número; manter a coluna numérica original como alternativa
  • 🐛 Colisão de prefixo de sessão — o ID do usuário 123 pode ver sessões do usuário 1234 via startswith; corrigido com delimitador de dois pontos no formato session_id
  • 🐛 Falsos positivos do pré-filtro NL — re.IGNORECASE fez com que [A-Z]{2,5} correspondesse a palavras comuns em inglês, como "hello"; sinalizador global removido, use (?i:...) embutido apenas para palavras-chave financeiras em inglês
  • 🐛 Ticker pontilhado em argumentos de estratégia — _get_strategy_args() não reconheceu BRK.B como um código de ação, deixando-o no texto de estratégia; agora aceita o formato TICKER.CLASS
  • ⏱️ correção de travamento de chamadas longas do efinance (#660) — Introduzir o wrapper _ef_call_with_timeout() para todas as chamadas efinance API (padrão 30 segundos, configurável via EFINANCE_CALL_TIMEOUT); use executor.shutdown(wait=False) para garantir que o thread principal não seja mais bloqueado após o tempo limite, eliminando completamente o problema de travamento de 81 minutos
  • 🛡️ Verificação de integridade de conteúdo de tipo seguro (#660) — check_content_integrity() agora trata tipos não-string operation_advice / analysis_summary como campos ausentes para evitar travamentos downstream de get_emoji() devido a dict.strip()
  • 📄 Desacoplando salvamento e notificação de relatório (#660) — _save_local_report() não depende mais do acionador de sinalização send_notification e os relatórios locais são salvos normalmente no modo --no-notify
  • 🔄 normalização de dicionário de operação_advice (#660) — Pipeline e BacktestEngine agora mapeiam o formato dict operation_advice retornado pelo LLM para uma string padrão via decision_type (sem distinção entre maiúsculas e minúsculas) para evitar falhas causadas por alterações no formato de saída do modelo
  • 🛡️ uso de runner.py Nenhuma proteção (#660) — AttributeError não é mais lançado quando response.usage é None, fallback para 0 contagem de token
  • 📋 falha silenciosa do orquestrador alterada para aviso de registro (#660) — A falha do estágio IntelAgent / RiskAgent agora registra WARNING em vez de pular silenciosamente, para facilitar o diagnóstico

Notas

  • ⚠️ Alterna a autenticação de vários trabalhadores — as atualizações de autenticação em tempo de execução são locais do processo; implantações com vários trabalhadores devem reiniciar/rolar trabalhadores para manter o estado de autenticação consistente
