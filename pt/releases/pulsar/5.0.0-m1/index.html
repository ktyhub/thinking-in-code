pulsar v5.0.0-M1

####2026-06-23

Apache Pulsar 5.0.0-M1 é o primeiro lançamento marcante no caminho para o Apache Pulsar 5.0.0, com disponibilidade geral esperada no final de 2026. É uma prévia: uma versão inicial que coloca os principais novos recursos do 5.0 em suas mãos para que você possa testá-los em cargas de trabalho reais e enviar feedback antes do lançamento GA. não se destina à produção. Duas mudanças se destacam — Scalable Topics, um novo tipo de tópico que cresce e diminui por conta própria, e a promoção do Oxia para o armazenamento de metadados recomendado da Pulsar — ​​junto com uma migração do sistema de compilação para Gradle, a divisão dos conectores IO em um repositório separado e registro estruturado.

Para um passo a passo completo, consulte o anúncio: Apache Pulsar 5.0.0-M1: uma prévia do próximo lançamento principal.

Destaques

Tópicos Escaláveis (Tópicos v5). Um novo tipo de tópico que substitui partições fixas por segmentos baseados em intervalo, para que um tópico possa aumentar ou diminuir dividindo e mesclando segmentos de forma transparente, preservando a ordem por chave. Isso evita a quebra de ordem e o desvio operacional resultante da alteração da contagem de partições de um tópico particionado regular. O trabalho abrange o controlador do lado do corretor (PIP-468), transações orientadas por metadados (PIP-473), migração de tópico regular para escalonável (PIP-475) e divisão/mesclagem automática (PIP-483). Consulte PIP-460.

Novo Java client API V5. Um client API totalmente limpo e específico para tópicos escaláveis, enviado como um novo módulo pulsar-client-v5 aditivo — os módulos pulsar-client e pulsar-client-api existentes permanecem inalterados, para que os aplicativos atuais continuem funcionando. Ele substitui o clássico Consumer/Reader e os quatro tipos de assinatura por três consumidores específicos: QueueConsumer (consumo de fila de trabalho paralelo e reconhecido individualmente com suporte a mensagens mortas), StreamConsumer (reconhecimentos ordenados e cumulativos) e CheckpointConsumer (para processadores de fluxo como Flink e Spark que rastreiam sua própria posição). O V5 client também funciona em tópicos particionados e não particionados existentes, e um consumidor pode assinar um namespace inteiro. No M1 ele é enviado para Java; outro idioma SDKs seguirá antes do GA. Consulte PIP-466.

Oxia agora é o armazenamento de metadados recomendado. Oxia se torna o armazenamento de metadados recomendado para novos clusters Pulsar no 5.0 e é o back-end preferido para tópicos escaláveis, cujas pesquisas são baseadas em suas sessões de exibição de streaming. ZooKeeper permanece totalmente compatível e PIP-454 adiciona uma estrutura de migração ativa e sem tempo de inatividade que move um cluster existente de ZooKeeper para Oxia enquanto o plano de dados continua publicando e consumindo.

Sistema de compilação migrado do Maven para Gradle. As compilações agora usam ./gradlew em vez de mvn, com cache e paralelismo em nível de tarefa que reduzem substancialmente os tempos de compilação locais e de CI, e um catálogo de versão central (gradle/libs.versions.toml) para gerenciamento de dependências. A migração é transparente para os usuários que consomem os artefatos Maven publicados, imagens Docker e JARs client sombreados. Consulte PIP-463.

Conectores IO divididos em um repositório separado. Os conectores Pulsar IO integrados foram movidos para fora do repositório principal para que possam seguir sua própria cadência de lançamento. Consulte PIP-465. Registro estruturado. Pulsar agora emite logs estruturados por meio de slog em todo o corretor, client, ​​livro-razão gerenciado, funções e módulos de metadados, com saída de log plana JSON/OpenTelemetry e uma variável de ambiente PULSAR_LOG_FORMAT para alternar formatos facilmente. Consulte PIP-467.

API e modernização da plataforma. Pulsar migrou de javax.* para jakarta.* APIs (PIP-472), tornou o Protobuf v4 o padrão, migrou anotações REST API de Swagger para OpenAPI 3 e agora oferece suporte à construção e execução em Java 25. As políticas de tópico ganharam reconhecimento de legado, back-end de roteamento apoiado por armazenamento de metadados (PIP-469).

Atualizações de segurança e dependências. Esta versão inclui um grande conjunto de atualizações de dependências que abordam vários CVEs em Netty, Jetty, log4j, BouncyCastle, Thrift, vert.x e async-http-client, ​​e atualiza o BookKeeper para 4.18.0. Consulte Atualizações da biblioteca abaixo.

Aviso importante

5.0.0-M1 é uma versão principal que remove funcionalidades obsoletas e altera alguns APIs. Revise o seguinte antes de atualizar:

  • Migração javax.* → jakarta.* (PIP-472). Plug-ins de corretor customizado, interceptores, provedores de autenticação/autorização ou outras extensões que fazem referência a pacotes javax.* (por exemplo, javax.ws.rs ou javax.servlet) devem ser atualizados para os pacotes jakarta.* correspondentes e recompilados.
  • Backend do armazenamento de metadados Etcd removido (PIP-462). As implantações que usam Etcd como armazenamento de metadados devem migrar para ZooKeeper ou Oxia antes da atualização.
  • Conectores IO movidos para um repositório separado (PIP-465). Os conectores não são mais liberados do repositório principal do Pulsar; obtenha-os no projeto de conectores dedicados.
  • O sistema de compilação agora é Gradle (PIP-463). Se você construir o Pulsar a partir do código-fonte, use ./gradlew em vez de mvn. Os artefatos publicados permanecem inalterados.
  • Dependência de fastutil removida (#25413).
