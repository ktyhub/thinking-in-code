Mudanças importantes

  • A configuração JUL (java.util.logging) não é mais eficaz para componentes do lado do servidor (#26330)

    Anteriormente, os logs de bibliotecas de terceiros que usam JUL (por exemplo, Jersey/Jetty, gRPC, Guava) não eram gerenciados pela configuração Log4j2 do Pulsar, tornando-os difíceis de controlar e causando saída de log inconsistente. Para resolver isso, o log de biblioteca de terceiros agora é interligado de JUL para Log4j2 via log4j-jul. Isso unifica todos os registros em conf/log4j2.yaml, mas significa que os seguintes JUL APIs e configurações não terão mais efeito:

    • -Djava.util.logging.config.file=logging.properties — todo o arquivo de configuração JUL é ignorado
    • java.util.logging.Logger.setLevel() / addHandler() — torne-se autônomo
    • java.util.logging.LogManager.reset() — torna-se autônomo

    Migração: mova qualquer configuração de log baseada em JUL para conf/log4j2.yaml. Por exemplo, para suprimir logs gRPC que foram configurados anteriormente como io.grpc.level=SEVERE em logging.properties, adicione o seguinte a conf/log4j2.yaml:

    Loggers:
  Logger:
    - name: io.grpc
      level: error

    Reverter: para restaurar o comportamento do estoque JUL, defina:

    PULSAR_EXTRA_OPTS="-Djava.util.logging.manager=java.util.logging.LogManager"
