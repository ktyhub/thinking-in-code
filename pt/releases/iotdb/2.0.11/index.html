#iotdb v2.0.11

Quebrar alteração

  • Esta versão aumenta a versão mínima necessária do JDK para 17.

Recursos e melhorias

  • Metadados: SHOW TIMESERIES suporta classificação por nome de medição.
  • Consulta: suporte a instruções SQL que contêm apenas uma cláusula SELECT.
  • Região: suporte ao reparo manual de tabelas particionadas usando SQL.
  • Visualizações: suporta visualizações lógicas.
  • Metadados: Adicione a instrução COUNT DATABASE para o modelo de tabela.
  • IoTConsensus: suporte a vários diretórios quando o IoTConsensus recebe instantâneos.
  • Região: as sintaxes EXTEND REGION e REMOVE REGION suportam uma lista regionId, permitindo que várias regiões sejam processadas de uma só vez.
  • Consulta: EXPLAIN ANALYZE suporta o formato de saída JSON.
  • Mods: Fortalece o controle de memória para consultas envolvendo mods. O uso de memória também deve ser controlável para um único arquivo mods2 grande de nível GB.
  • Ingestão de dados: Ao excluir dados, envie solicitações apenas para o grupo de regiões ao qual pertence a tabela atual.
  • Camada de Protocolo: Adicione controle de memória na camada de protocolo.
  • UDF: Adicione uma interface InternalSession ao UDF API.
  • Pipe: Modifique a lógica de definição de dados em tempo real.
  • Funções: Suporta preenchimento de valores subsequentes.
  • Cláusulas SQL: GROUP BY e ORDER BY suportam aliases definidos com AS na cláusula SELECT.
  • Configuração de parâmetros: oferece suporte ao recarregamento a quente de configurações de tempo de execução do cluster.
  • Criptografia de comunicação: suporta autenticação mútua para comunicações criptografadas client.
  • Consulta: suporte para gravação de resultados de consulta em um TsFile em um caminho especificado usando SQL.
  • Alta disponibilidade: oferece suporte a alta disponibilidade para gerenciamento de tabelas, gerenciamento de dispositivos, gerenciamento de visualização gravável, gerenciamento de TTL, gerenciamento de banco de dados e privilégios de usuário.
  • Client: Suporta um Node.js client. Somente a versão 2.x é suportada.
  • Edge Edition: Para facilitar o uso em dispositivos edge com memória limitada, introduza uma Edge Edition que limite o uso combinado de memória do ConfigNode e do DataNode a 512 MB. A carga de trabalho alvo é de aproximadamente 10.000 medições operando a 1 Hz para cargas de trabalho de leitura e gravação. A primeira versão ajustará principalmente certos parâmetros do JVM e de configuração padrão; versões futuras podem continuar evoluindo em direção a uma arquitetura DataNode-ConfigNode mais integrada.

Erros

  • Consulta: Nos modelos de árvore e tabela, as comparações entre valores inteiros e de ponto flutuante nas condições de filtro de consulta se comportam de forma inconsistente.
  • Escalabilidade: durante a validação de escala, IoTConsensusQueue em IoTConsensus Used Memory no painel de monitoramento exibe um valor negativo.
  • Carregar TsFile: Quando o destinatário tem privilégios de gravação, LOAD TSFILE falha sem permissões para esta operação, adicione o privilégio SYSTEM e os dados não são sincronizados.
  • SSL: correção de NullPointerException: não é possível invocar "String.contains(java.lang.CharSequence)" porque o valor de retorno de "java.lang.Throwable.getMessage()" é nulo.
  • SSL: Melhora a mensagem de erro exibida quando o SSL está habilitado no pacote de segurança mas o CLI se conecta ao cluster sem especificar SSL, tornando a mensagem mais explícita.
  • Gerenciamento de Cluster: Durante a validação do Issue 0228, foi encontrado um novo problema: após reiniciar o cluster, um nó permaneceu no estado Desconhecido e não produziu nenhum log de aproveitamento, indicando que o thread principal estava bloqueado. No entanto, o nó ainda poderia executar a compactação normalmente.
  • Dimensionamento: durante a redução, o campo CompressionRatio para um DataRegion no estado Adding exibe um valor negativo em SHOW REGIONS.
  • Região: preserve duas casas decimais para o campo CompressionRatio nos resultados SHOW REGIONS.
  • Dimensionamento: durante o aumento de escala, após reiniciar o cluster, o campo CompressionRatio para a maioria dos DataRegions em SHOW REGIONS é NaN, mesmo que tivesse um valor antes do reinício.
  • ConfigNode: corrige um vazamento de thread do ConfigNode. Em uma implantação IoTV2 3C3D com três réplicas, a execução de SQL cobrindo casos de teste de modelo de árvore fez com que o número de threads do ConfigNodeRPC-Processor atingisse 3.000. O cluster não pôde mais ser conectado e o ConfigNode/DataNode relatou NullPointerExceptions.
  • Consulta: Corrija um erro em CAST (1.1 AS FLOAT): java.lang.UnsupportedOperationException: org.apache.tsfile.read.common.block.column.DoubleColumn. A expectativa é de que a operação seja bem-sucedida.
  • DataNode: PipeTsFileEpochProgressIndexKeeper retém mais de 50.000 TsFileResources, fazendo com que o DataNode fique sem memória. Em uma implantação IoTV2 3C3D com duas réplicas, leituras, gravações e exclusões simultâneas foram realizadas enquanto um DataNode foi interrompido; após 54 horas de teste, um DataNode ficou sem memória e gerou um dump OOM de 23 GB com ON_HEAP_MEMORY="20G".
  • Gerenciamento de usuários: a execução simultânea de LIST USER, CREATE USER e DROP USER pode resultar em 301: falha na solicitação de taxa desconhecida. O log do ConfigNode mostra Causado por: java.util.ConcurrentModificationException: null.
  • IoTConsensus: Em uma implantação 3C3D com duas réplicas, leituras, gravações e exclusões simultâneas foram realizadas enquanto um DataNode estava parado. Um processo DataNode foi encerrado e gerou um arquivo de despejo de 25 GB.
  • Metadados: Proibir a criação de dispositivos em medidas de modelo e seus subcaminhos.
  • Região: um erro de tamanho de quadro, tamanho de quadro (69670459) maior que o tamanho máximo de proteção (67108864), pode fazer com que uma consulta seja interrompida. O sistema deverá retornar uma mensagem de erro apropriada.
