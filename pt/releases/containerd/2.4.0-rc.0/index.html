#containerd v2.4.0-rc.0

Bem-vindo ao lançamento v2.4.0-rc.0 do containerd! Este é um pré-lançamento do containerd

containerd 2.4 é uma versão regular (não LTS) com uma janela de suporte mais curta, destinado a usuários que desejam adotar novos recursos mais cedo. Como o lançamento seguindo o 2.3 LTS, é o ponto no ciclo de lançamento onde anteriormente recursos obsoletos podem ser removidos, portanto, esta versão pode incluir quebras mudanças; verifique as notas abaixo e limpe quaisquer avisos de depreciação do seu versão atual antes de atualizar.

Os usuários que priorizam a estabilidade e um ciclo de vida de suporte mais longo devem permanecer atentos Lançamento 2.3 LTS.

Destaques

Interface de tempo de execução do contêiner (CRI)

  • Habilite o gerenciador de montagem para montagens de imagens em CRI (#13542)
  • Exporte a imagem do sandbox e a configuração do diretório CNI nas informações do plugin CRI (#13940)
  • Defina runtimeFeatures.UserNamespacesHostNetwork padrão como verdadeiro (#13162)
  • Suporte à introspecção de recursos de tempo de execução OCI para tempos de execução não runc (#13504)

Distribuição de imagens

  • Aplique proteção para remover cabeçalhos de autenticação confidenciais ao buscar URLs de descritores (#12889)
  • Suporte à propagação de cabeçalhos de aviso HTTP 299 dos registros para o resolvedor (#12698)
  • Use klauspost/compress para descompactação da camada gzip (#13560)

Armazenamento de imagens

  • Adicione opções client para buscar todo o conteúdo da camada durante a descompactação, mesmo quando existirem instantâneos (#14126)
  • Incluir tipo de mídia em eventos de criação de conteúdo (#13833)
  • Adicionar referências futuras ao contexto da coleção GC (#13634)

Interface de recursos de nó (NRI)

  • Expor o nome da imagem do contêiner, resumo e resumo de configuração para plug-ins NRI (#13960)
  • Emitir avisos de descontinuação para plug-ins usando interfaces NRI obsoletas (#13916)

Tempo de execução

  • Mascarar /proc/interrupts e caminhos sysfs de aceleração térmica da CPU em contêineres Linux por padrão (#14090)
  • Adicione UpdateSandbox RPC para propagar atualizações do controlador sandbox para o shim (#14105)
  • Evite reiniciar contêineres imediatamente com a política restart=always após eles serem explicitamente interrompidos (#13993)
  • Passe o contexto de rastreamento de shim para runc e hooks (#14036)
  • Corrigir falhas de pesquisa de usuários e grupos em rootfs de contêiner contendo /etc/passwd ou /etc/group com link simbólico (#13818)
  • Implementar servidor de pipe nomeado do Windows e suporte a streaming de log em pkg/shim (#13948)
  • Habilite a limpeza de log por padrão no Windows (#13837)
  • Permitir especificar o diretório do ponto de verificação pai ao fazer checkpoint com runc (#13699)

Instantâneos

  • Adicionar métricas Prometheus para cache de conteúdo da camada snapshotter EROFS (#13941)
  • Suporte para cache de imagem quente para snapshotter erofs (#13813)
  • Adicione rótulo de tamanho máximo para instantâneos (#13520)

Quebrando

  • Remover restauração em CreateContainer (#13871)

Depreciações

  • Descontinuar a anotação de shim containerd.io/runtime-allow-mounts em favor da extensão de bootstrap MountCapabilities (#14002)
  • Remova shim.Command obsoleto do pacote (#13991)
  • Descontinuar os campos de endereço e versão da tarefa API nas opções runc e mover para CreateTaskRequest (#13360)

Experimente os binários de lançamento e relate quaisquer problemas em https://github.com/containerd/containerd/issues.

Qual arquivo devo baixar?

  • containerd-<VERSION>-<OS>-<ARCH>.tar.gz: ✅Recomendado. Vinculado dinamicamente com glibc 2.35 (Ubuntu 22.04).
  • containerd-static-<VERSION>-<OS>-<ARCH>.tar.gz: Vinculado estaticamente. Espera-se que seja usado em distribuições Linux que não usam glibc >= 2.35. Não independente de posição.

Além do containerd, normalmente você terá que instalar runc e plug-ins CNI também de seus sites oficiais.
