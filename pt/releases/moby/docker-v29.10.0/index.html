#moby docker-v29.10.0

##29.10.0

Para obter uma lista completa de solicitações pull e alterações nesta versão, consulte os marcos relevantes do GitHub:

  • docker/cli, marco 29.10.0
  • moby/moby, marco 29.10.0

⚠️ Potencial alteração significativa: conexões de registro local

Se você configurar explicitamente insecure-registries em daemon.json ou usar --insecure-registry, o mecanismo Docker não tratará mais automaticamente endereços de loopback (127.0.0.0/8 e ::1/128) como registros inseguros.

[!AVISO] Após a atualização, pulls e pushs para registros locais que usam certificados HTTP ou TLS não rusted podem falhar, a menos que esses registros sejam explicitamente incluídos em sua configuração de registro insegura. Configure o TLS com um certificado trusted ou adicione apenas os endereços de registro locais necessários, como localhost:5000, à sua configuração de registro insegura existente.

Quando insecure-registries é omitido, os registros de loopback permanecem inseguros por padrão. Definir "insecure-registries": [] em daemon.json desativa todos os registros inseguros padrão. moby/moby#53868

🧻 A especificação do motor API muda para OpenAPI 3.2

A especificação Engine API agora usa OpenAPI 3.2 como formato de origem, em api/openapi.yaml. Uma especificação Swagger 2.0 gerada a partir dele ainda é publicada para ferramentas existentes, em api/swagger.yaml. Para a transição, esta versão também inclui uma cópia do Swagger 2.0 fixada em API v1.57, em api/docs/v1.57-swagger.yaml. As versões futuras do API não receberão uma cópia do Swagger 2.0 por versão, portanto, atualize as ferramentas que dependem desses arquivos para usar as especificações do OpenAPI 3.2. moby/moby#53630

📦 Pacotes para AlmaLinux, Oracle Linux e Rocky Linux

Os pacotes do mecanismo Docker estão disponíveis para AlmaLinux, Oracle Linux e Rocky Linux. Para obter instruções de instalação, consulte AlmaLinux, Oracle Linux e Rocky Linux.

  • Correção da impressão de uma coluna NAMES vazia quando todos os nomes de um contêiner contêm uma barra, como quando conectado a um Swarm clássico API. docker/cli#7481
  • Corrigido o daemon excluindo a interface docker0 na reinicialização quando ele é configurado com uma ponte gerenciada pelo usuário e pools de endereços padrão. moby/moby#54157
  • Corrija as exportações da camada do Windows contendo arquivos NTFS esparsos. moby/moby#53745
  • Correção: inclui códigos de status HTTP em erros de streaming do JSON para permitir que o clients classifique corretamente as falhas. moby/moby#54133
  • Melhore a seleção de imagens em hosts Linux ARM64 para preferir a variante de imagem mais alta suportada pela CPU do host. moby/moby#53910
  • anotação de manifesto: adicione conclusão de shell para --os e --arch. docker/cli#7449
  • Rejeite contagens duplicadas de GPU de forma consistente quando as opções de contagem abreviada e explícita são misturadas. docker/cli#7312
  • Parar de tratar automaticamente os registros de loopback como inseguros quando insecure-registries estiver explicitamente configurado e permitir desabilitar os registros inseguros padrão configurando "insecure-registries": [] em daemon.json. moby/moby#53868

  • Correção de um contêiner que inicia sem rede após uma inicialização anterior ter falhado com um erro de rede, como uma porta publicada já em uso. moby/moby#52480
  • Corrige a resolução de DNS em redes definidas pelo usuário quando o /etc/resolv.conf do host está ausente ou não contém servidores de nomes válidos. moby/moby#54140
  • Corrigidas regras de iptables e uma cadeia DOCKER vazia deixada para trás quando o daemon muda para o back-end do firewall nftables após uma versão anterior a 28.0.1 ser executada com iptables. moby/moby#54129
  • Correção das regras do iptables que não são restauradas após o firewalld ser interrompido ou iniciado após o daemon. moby/moby#54012
  • Correção de erros de driver de rede de sobreposição quando um contêiner obtém o endereço IP de um contêiner que acabou de ser removido em outro nó. moby/moby#53833
  • Correção da falha de reconvergência da rede de sobreposição após uma partição de rede quando um gerenciador Swarm foi substituído em um novo endereço. moby/moby#53715
  • Corrigir serviços de enxame que vazam um endereço IP virtual em suas outras redes sempre que a alocação falha em uma rede, o que pode esgotar as sub-redes dessas redes. moby/moby#54148
  • Correção de tarefas do Swarm que não conseguem alcançar a porta publicada de um serviço por meio do endereço de seu próprio nó quando um firewall de host, como o ufw, descarta o tráfego de entrada não solicitado. moby/moby#54006
  • Corrigido o MTU das interfaces de rede de sobreposição sendo 20 bytes muito grandes quando o caminho de dados do Swarm é IPv6. moby/moby#54067
  • Reduza a sobrecarga de publicação de portas nftables agrupando atualizações de firewall em lote por endpoint e família de endereços. moby/moby#54011
  • Impedir que os nós em um cluster Swarm troquem o estado da rede de sobreposição completa com cada gerenciador uma vez por minuto quando o cluster estiver íntegro. moby/moby#53715
