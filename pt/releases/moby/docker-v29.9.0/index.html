#moby docker-v29.9.0

##29.9.0

Para obter uma lista completa de solicitações pull e alterações nesta versão, consulte os marcos relevantes do GitHub:

  • docker/cli, marco 29.9.0
  • moby/moby, marco 29.9.0

Segurança

A atualização do tempo de execução Go corrige as seguintes vulnerabilidades de segurança no mecanismo Docker:

  • CVE-2026-97032: Um HTTP/2 client pode travar o daemon alterando o tamanho da tabela de cabeçalho HPACK ao enviar solicitações. golang/go#81867
  • CVE-2026-78659: Um HTTP/2 client pode esgotar a memória do daemon declarando um grande número de campos em um cabeçalho Trailer, ignorando os limites de tamanho do cabeçalho. golang/go#81857
  • CVE-2026-78663: Um HTTP/2 client pode ignorar o limite de controle de fluxo no nível da conexão redefinindo fluxos, fazendo com que o daemon bufferize mais dados de solicitação do que o limite permite. golang/go#81743
  • CVE-2026-78669: Um HTTP/2 client pode causar uso excessivo da CPU do daemon abrindo muitos fluxos e alterando repetidamente o tamanho inicial da janela. golang/go#81742
  • CVE-2026-56857: No Windows, o daemon poderia criar um diretório fora de sua raiz de dados se alguém com acesso de gravação à raiz de dados tivesse colocado uma junção lá. golang/go#81739

A atualização golang.org/x/net para v0.60.0 aplica as mesmas correções HTTP/2 ao endpoint /grpc obsoleto e ao servidor gRPC que o BuildKit executa para contêineres de front-end, como imagens referenciadas por uma diretiva # syntax=.

Correções de bugs e melhorias

  • armazenamento de imagens containerd: adicione o recurso daemon lazy-pull para controlar se docker pull ignora o download do conteúdo da camada que o snapshotter já fornece. Lazy pulls são habilitados por padrão para snapshotters remotos conhecidos (nydus, overlaybd, soci, stargz). moby/moby#53877
  • armazenamento de imagens em contêiner: corrige pulls que ignoram blobs de camada necessários quando já existem camadas descompactadas, deixando as imagens executáveis, mas incompletas para exportação ou envio. moby/moby#53615
  • Corrigido docker container create --name relatando um erro de validação enganoso mencionando caracteres inválidos em vez de comprimento de nome inválido. moby/moby#53484
  • Corrija um vazamento de conexão no soquete RootlessKit API em cada solicitação GET /version no modo sem raiz. moby/moby#53836
  • Melhorar o registro de serviços do Windows e a limpeza de cancelamento de registro, incluindo tornar o cancelamento de registro de serviço (--unregister-service) idempotente. moby/moby#53845

Atualizações de embalagens

  • Atualize o BuildKit para v0.34.0. moby/moby#53882
  • Atualize o tempo de execução do Go para 1.26.9. docker/cli#7363
  • Atualize o containerd (binários estáticos) para v2.4.1. moby/moby#53773

Rede

  • Permitir a descoberta de vizinhos IPv6 entre contêineres em uma rede de ponte com a comunicação entre contêineres desabilitada, correspondendo ao comportamento IPv4 existente. moby/moby#53723
  • Corrigido docker ps e GET /containers/json omitindo portas publicadas para redes usando modo gateway roteado. moby/moby#53693
  • Correção de um bug em que um daemon reiniciado poderia ser descartado da descoberta de serviço e do balanceamento de carga de um peer até que ele voltasse ao cluster de fofoca. moby/moby#53688
  • Correção de uma porta publicada inacessível de outro contêiner na mesma rede quando a comunicação entre contêineres está desativada, incluindo serviços Swarm publicados por meio da malha de roteamento. moby/moby#53723
  • Correção de um problema em que erros de programação do kernel para criptografar o plano de dados da rede de sobreposição poderiam, em algumas circunstâncias, fazer com que o tráfego da rede de sobreposição criptografada para alguns nós fosse transmitido em texto não criptografado. Como o peer receptor descartaria pacotes de texto não criptografado para redes de sobreposição criptografadas como falsificados, a perda de confidencialidade é limitada a fluxos unidirecionais (por exemplo, consultas DNS UDP) e tentativas de handshake que nunca prosseguem (por exemplo, TCP SYN). moby/moby#53420
  • Correção da conexão de contêineres restaurados ao vivo com um mapeamento host-gateway implícito para redes adicionais. moby/moby#53093
  • Correção de peers de sobreposição que se tornam inacessíveis depois que um nó se ingressa novamente no cluster ou um serviço é reimplantado, quando o dispositivo VXLAN já havia aprendido uma entrada FDB dinâmica para o peer. moby/moby#53663
  • Correção de tarefas do Swarm em redes de sobreposição sendo rejeitadas quando o daemon não consegue gravar em /var/lib/docker. moby/moby#53848
  • As portas do serviço Swarm publicadas são acessíveis nos endereços IPv6 do host quando o proxy da área do usuário está habilitado. Uma mudança introduzida no v29.8.0 habilitou acidentalmente esta funcionalidade; é um recurso testado e suportado desde v29.9.0. moby/moby#53727
  • Liberar associações e políticas de segurança IPsec de um nó quando o último contêiner deixar uma rede de sobreposição criptografada, em vez de vazá-las até que o daemon seja reiniciado. moby/moby#53420
  • Restaure a lógica para remover a cadeia de iptables DOCKER-INGRESS vazia e a regra FORWARD que salta para ela, deixada para trás pelo mecanismo Docker 28.0.0 e anteriores. moby/moby#53825

Sem raiz

  • Atualize o RootlessKit (3.2.0). moby/moby#53607
