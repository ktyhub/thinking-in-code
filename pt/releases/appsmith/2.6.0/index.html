appsmith v2.6.0

⚠️ Para usuários EE, antes de atualizar para v2.6.0, conclua a execução do fluxo de trabalho temporal existente no v2.5.1

Appsmith está migrando para um novo mecanismo de fluxo de trabalho. Não se pode confiar que as execuções iniciadas no antigo mecanismo Temporal serão retomadas ou concluídas após a atualização para v2.6.0.

Uma execução é uma execução de um fluxo de trabalho. Isso inclui execuções que esperam que uma pessoa aprove uma solicitação, mesmo quando ela não está processando nada ativamente.

O que fazer antes de atualizar:

  1. Atualize para v2.5.1 primeiro se você estiver em uma versão anterior.
  2. Deixe todas as execuções no Temporal terminarem, incluindo aquelas que aguardam aprovação. Interrompa uma execução apenas se estiver disposto a abandonar o trabalho restante.
  3. Em Configurações de administrador → Instância → Central de administração, revise e confirme o ponto de verificação v2.5.0 · Transição do mecanismo de fluxo de trabalho. Siga o guia de transição do mecanismo de fluxo de trabalho.
  4. Atualize para v2.6.0.

Possível tempo de inatividade: a verificação de atualização pode impedir a inicialização de todo o servidor Appsmith se encontrar solicitações de aprovação pendentes do mecanismo antigo. Conclua as etapas acima antes de atualizar; não confie na verificação de inicialização para encontrar todas as execuções inacabadas.

Se a inicialização for bloqueada por este ponto de verificação, retorne para v2.5.1, termine ou interrompa deliberadamente as execuções afetadas, conclua o ponto de verificação e tente novamente a atualização.

🔐 Correção de segurança Brotli (CVE-2026-111497):

Appsmith v2.6.0 inclui a correção para uma vulnerabilidade no decodificador Node.js Brotli. O processamento de dados compactados por Brotli criados com códigos maliciosos pode corromper a memória e potencialmente causar uma falha no serviço, expor a memória do processo ou permitir a execução remota de código. Os clientes auto-hospedados devem atualizar para v2.6.0 para receber a correção. Consulte o aviso de segurança Node.js para obter detalhes.

⚠️ Notas importantes sobre atualização

  • Os arquivos docker.env customizados devem conter valores literais resolvidos. As expressões do shell interrompem a inicialização com um diagnóstico redigido. Mova as opções JVM de docker.env para Docker Compose ou configuração do ambiente Helm antes de atualizar. Os nomes OTEL_*, incluindo os terminais do exportador de rastreamento documentados, agora são aceitos. Os padrões gerados e os valores de configurações de administrador não precisam de alterações. (#42225, #42422)
  • As consultas Redis devem usar um nome de comando estático. Uma ligação no nome do comando retorna um erro de configuração de consulta. Os valores de ligação permanecem dentro de um único argumento. (#42465)
  • O plugin DynamoDB agora usa AWS SDK para Java 2.55.9. Uma região deve conter apenas letras, dígitos e hifens e ter no máximo 63 caracteres. As respostas podem incluir chaves adicionais; as chaves e os valores existentes permanecem os mesmos. Se o servidor definir AWS_ENDPOINT_URL, AWS_ENDPOINT_URL_DYNAMODB, AWS_USE_FIPS_ENDPOINT ou AWS_USE_DUALSTACK_ENDPOINT, o plugin agora os honrará. (#42346)

🔐 Segurança

  • Dependências agrupadas atualizadas para solucionar vulnerabilidades relatadas. (#42444, #42449, #42466, #42475, #42492)
  • As leituras de página e layout no modo editor agora exigem permissão de edição e retornam o rascunho. O modo de visualização ainda requer permissão de leitura e retorna a página publicada. (#42425)
  • A atualização de um aplicativo ou fonte de dados agora mantém o espaço de trabalho em que foi criado. (#42462)
  • A criação de um espaço de trabalho agora ignora um ID, políticas e grupos de permissão fornecidos pelo client. O servidor os gera. (#42478)
  • As ligações de consulta Redis permanecem dentro de um argumento de comando, portanto, um valor vinculado não pode adicionar argumentos extras. (#42465)

🛠️ Confiabilidade

  • Os aplicativos públicos recebem novamente a chave configurada do Google Maps, portanto, os widgets de mapas funcionam para visualizadores anônimos. (#42440)
  • Salvar credenciais de fonte de dados agora descarta a conexão em cache dessa fonte de dados em cada pod de servidor. (#42430)
  • O fechamento de uma conexão de fonte de dados removida não é mais executado no thread de solicitação compartilhada, portanto, um banco de dados travado não paralisa mais as verificações de integridade. (#42450)
  • As visualizações de página são registradas quando uma página é aberta, não quando o editor carrega o layout DSL. (#42429)
  • Objetos de solicitação aninhados do DynamoDB, incluindo itens de transação e configurações de índice, agora são criados sempre da mesma maneira. (#42346)

✨ Novos recursos e melhorias

  • Filtros SQL estruturados MCP podem testar isNull e notNull. (#42491)
  • Os filtros SQL estruturados do MCP podem agrupar condições com anyOf, que compila para OR e é combinado com os demais filtros. (#42495)
  • SQL estruturado MCP like pode corresponder contém, prefixo, sufixo ou texto exato. Consultas PostgreSQL podem usar ilike. (#42496)

🎨 Melhorias na interface e nos widgets

  • Em Configurações do aplicativo → Navegação, Mostrar logotipo e Mostrar título do aplicativo não mudam mais enquanto um salvamento está em andamento. (#42488)

🔧 Git, implantação e configuração

  • docker.env agora aceita nomes OTEL_*, incluindo os endpoints documentados do exportador de rastreamento OpenTelemetry. Um valor OTEL_* definido externamente ainda substitui o arquivo na reinicialização. (#42422)
  • A telemetria do navegador agora é enviada apenas para construtores. Visitantes anônimos e usuários finais de aplicativos publicados não são mais rastreados no navegador. (#42353)
