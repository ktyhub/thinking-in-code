Avisos

A resolução dos documentos usados ​​para recuperação agora verifica o acesso do chamador a cada arquivo referenciado e rejeita nomes de coleções fornecidos por client, ​​evitando que uma solicitação elaborada extraia arquivos ou coleções de vetores de outro usuário para seu contexto. Solicitações de recuperação para nomes de coleções que não correspondem a um arquivo conhecido, memória, pesquisa na web ou base de conhecimento agora são negadas para não administradores por padrão, com uma nova configuração "ENABLE_RETRIEVAL_UNSCOPED_COLLECTIONS" para restaurar o comportamento anterior, se necessário. Alterado

  • ⚠️ Migrações de banco de dados: esta versão inclui alterações no esquema do banco de dados; é altamente recomendável fazer backup do seu banco de dados e de todos os dados associados antes de atualizar em ambientes de produção. Se você estiver executando uma implantação com vários trabalhadores, vários servidores ou com balanceamento de carga, todas as instâncias deverão ser atualizadas simultaneamente. As atualizações contínuas não são suportadas e causarão falhas no aplicativo devido à incompatibilidade de esquema.
  • ⚙️ Capa de iteração de chamada de ferramenta renomeado e aumentado. A variável de ambiente que limita quantas chamadas de ferramenta uma única resposta de chat pode fazer agora é "CHAT_RESPONSE_MAX_TOOL_CALL_ITERATIONS", com seu padrão aumentado de 30 para 256 e um novo valor "-1" para ilimitado; o nome anterior "CHAT_RESPONSE_MAX_TOOL_CALL_RETRIES" continua funcionando como substituto, e os bate-papos que atingiram o limite agora mostram um erro claro no bate-papo em vez de parar silenciosamente. #24918, Confirmar
  • 🔐 Redução da exposição pública "/api/config". A resposta "/api/config" não inclui mais vários sinalizadores de recursos ("enable_api_keys", "enable_password_change_form", "enable_version_update_check", "enable_public_active_users_count", "enable_easter_eggs") para chamadores não autenticados, reduzindo informações divulgação a visitantes anônimos. Confirmar, Confirmar
  • 🔑 "WEBUI_SECRET_KEY" agora é um requisito difícil, mesmo para implantações não suportadas. Implantações que iniciam o back-end de uma forma explicitamente não suportada (como invocar o uvicorn diretamente) sem definir "WEBUI_SECRET_KEY" agora se recusarão a iniciar em vez de voltar para uma chave vazia; os métodos de início suportados (start.sh, start_windows.bat e "open-webui serve") ainda são definidos ou gerados automaticamente, portanto, as implantações padrão não são afetadas. A inicialização direta do Uvicorn não é suportada. #25218
