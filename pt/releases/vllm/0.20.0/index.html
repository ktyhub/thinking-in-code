#vllm v0.20.0

#vLLM v0.20.0

Destaques

Esta versão apresenta 752 commits de 320 colaboradores (123 novos)!

  • DeepSeek V4: suporte inicial para DeepSeek V4 (#40860), com correção de vazamento de token DSML em DSV4/3.2 (#40806), correção de DSA + MTP IMA (#40772) e um limite de fixação silu no especialista compartilhado (#40950).
  • Padrão CUDA 13.0: Roda CUDA padrão na imagem PyPI e vllm/vllm-openai:v0.20.0 alterada para CUDA 13.0; listas de arquitetura e argumentos de construção limpos (#39878) e CUDA passou para 13.0.2 para corresponder ao PyTorch 2.11.0 (#40669). Como regra geral, nossa política de versão CUDA segue a do PyTorch. É altamente recomendável instalar o vLLM com uv e usar --torch-backend=cu129 se você estiver no CUDA 12.9.
  • Atualização do PyTorch 2.11 (#34644): o vLLM é enviado na tocha 2.11 para CUDA, e o XPU agora também está na tocha 2.11 (#37947) — XPU não está mais fixado no 2.10. Esta é uma mudança significativa para a dependência do ambiente.
  • Python 3.14: Adicionado à lista de versões suportadas do Python (#34770).
  • Transformers v5: vLLM agora é executado em HuggingFace transformers>=5 (#30566), com vision-encoder torch.compile bypass (#30518) e correções de compatibilidade v4/v5 contínuas, incluindo processador de imagem PaddleOCR-VL max_pixels (#38629), aviso Mistral YaRN (#37292) e recomputação rotativa inv_freq Jina ColBERT (#39176).
  • Novos modelos grandes: visualização do Hunyuan v3 (Hy3) (#40681) com analisador de raciocínio HYV3 (#40713); Granito 4.1 Visão como modelo multimodal integrado (#40282).
  • FlashAttention 4 como pré-preenchimento MLA padrão: FA4 reativado como back-end de pré-preenchimento MLA padrão (#38819) com head-dim 512 e suporte a KV paginado no SM90+ (#38835), além de uma sincronização FA4 upstream (#38690).
  • Cache KV TurboQuant de 2 bits: Novo back-end de atenção que fornece compactação de cache KV de 2 bits com capacidade 4× (#38479), agora com suporte a pré-preenchimento FA3/FA4 (#40092).
  • Frontend de quantização online: Novo frontend de quantização online ponta a ponta (#38138), com documentação (#39736); experts_int8 consolidado no caminho on-line do FP8 (#38463); O quant online do MXFP8 foi movido para o novo frontend (#40152).
  • vLLM IR: Esqueleto IR inicial com operação rms_norm (#33825), importações de kernel da plataforma OOT (#38807), gemma_rms_norm retrabalhado em IR (#39014) e infraestrutura de teste/benchmarking de operação IR adicionada (#40167) — base para trabalho futuro do kernel.
  • Avanços do Model Runner V2: Eagle pré-preenchido gráfico CUDA completo (#37588), modo/tamanhos cudagraph de resolução automática do backend de atenção (#32936), kernels de amostra de rejeição probabilística fundidos (#38496), validação de configuração para recursos não suportados (#38758), fallback por partes desabilitado para decodificações de rascunho de eagle (#39773), suporte a múltiplos prompt-logprobs (#39937), cobertura de pré-preenchimento de aquecimento (#40746) e uma correção para regressão de precisão causada por tokens de amostra/rascunho obsoletos (#39833).
  • Série de refatoradores MoE: Não quantizado migrado para Full Oracle Flow (#36286), CT W8A8 para Oracle (#39187), classe SharedExperts (#35153), SharedFusedMoE removido (#35782), divisão DefaultMoERunner (#35326) e posteriormente combinado de volta em MoERunnerBase (#40560), soma de saída de especialista compartilhada/fundida movida para MoERunnerBase (#35949), ZeroExpertFusedMoE em nova estrutura (#35549), divisão compressed_tensors_moe.py (#38960), GPTQMarlinMoEMethod retrabalhado com MK (#37990), XPU e CUTLASS MoE realocados para fused_moe/experts/ (#40568, #40574), make_expert_params_mapping renomeado (#40671), refatoração MoE LoRA (#40338) e fragmentação MoE DP removida (#39107).
  • Desempenho: Otimize invariante de lote com norma RMS fundida — 2.1% melhoria de latência E2E (#40413); evite sincronização GPU → CPU seq_lens_cpu (#40654); cache InductorPass.hash_source (#39328); pule a desserialização do gráfico FX no carregamento para uma compilação quente mais rápida (#40151); Perfil de memória CUDAGraph habilitado por padrão para uma contabilidade de memória de inicialização mais clara (#38284).

  • AITER correção triton BUFFER_OPS + atualizações de versão (#38580), AITER revertido para v0.1.10.post3 (#39509); Nixl atingiu 0.10.1 (#39922) e foi fixado por CUDA major em CI (#39851); DeepGEMM integrado à roda via CMake (#37980); fastsafetensors adicionados ao arquivo NVIDIA Docker (#38950); Helion bateu 0.3.2 → 0.3.3 (#38062).
  • Removido/movido: dependência de resampy eliminada (#39524), dependência direta de librosa eliminada (#39079), pyav e soundfile movidos para requisitos comuns (#39997).

Mudanças importantes

  1. PyTorch 2.11 + CUDA 13.0(.2) padrão — mudança de dependência do ambiente, agora aplicada também ao XPU.
  2. Transformers v5 é a linha de base suportada (#30566).
  3. Retrabalho de métricas: vllm:prompt_tokens_recomputed removido (#38709); num_cached_tokens / num_external_computed_tokens substituído por PrefillStats (#37460).
  4. Renomeação da configuração do pooler: logit_bias/logit_scale → logit_mean/logit_sigma (#39530).
  5. Programação assíncrona padrão DESATIVADA para modelos de pooling (#39592).
  6. Perfil de memória CUDAGraph agora ativado por padrão (#38284) — alterações na contabilização da memória de inicialização.
  7. Quantização Petit NVFP4 removida (#32694); LLM.reward obsoleto, use LLM.encode (#40688); cprofile / cprofile_context obsoleto (#39100); V0 accept output buffer obsoleto (#39125).

Descontinuação V0

  • Petit NVFP4 (#32694), accept output buffer em atenção (#39125), cprofile / cprofile_context (#39100), LLM.reward offline API (#40688).
