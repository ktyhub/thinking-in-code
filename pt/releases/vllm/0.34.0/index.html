##TL;DR

  • 10 novos modelos (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe e muito mais!)
  • Cache KV extensível está ativado por padrão: o vLLM dimensiona o cache KV a partir da memória realmente livre após o aquecimento, para que a maioria dos modelos obtenha um cache maior e mais rendimento.
  • O Modelo Runner V1 desapareceu. O Modelo Runner V2 agora é o único executor de GPU.

  • Verificação de atualização: o tamanho do bloco padrão agora é 64, as imagens ROCm 7.2 desapareceram e huggingface_hub >= 2.0.0 é necessário. Consulte Antes de atualizar.

Destaques

Cache KV extensível, ativado por padrão

  • Em CUDA e ROCm, o cache KV é dimensionado a partir da memória realmente livre após captura e aquecimento do gráfico CUDA, não a partir de uma estimativa (#56492).
  • Resultado: um cache maior (por exemplo, MiniMax-M3 em H200: 433k → 672k tokens), então a taxa de transferência é maior e o TTFT menor em alta simultaneidade.
  • Compensação: a latência de decodificação por token pode aumentar em alguns modelos (TPOT +6–18% em alguns modelos H200 na simultaneidade 128). Desative com --gpu-memory-utilization 0.9 ou --no-enable-extensible-kv-cache.
  • Reforçado com correções para fragmentação do alocador, OOMs de inicialização e conectores KV (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Somente modelo Runner V2

  • O modelo Runner V1 foi removido (#63373).
  • A sobreposição de lote duplo agora é executada no MRV2, inclusive com decodificação especulativa e DCP (#61464).

Decodificação especulativa

  • Decodificação de sufixo roda em MRV2 com um especulador de GPU; A Inferência do Ártico não é mais necessária (#60339).
  • Especuladores personalizados: configurações declarativas mais um plugin register_speculative_method API (#63205).
  • Gráficos CUDA para especuladores de modelo preliminar MRV2 (#60989).
  • Verificação adaptativa funciona com XPress (#65175).
  • Cache KV de rascunho corresponde ao dtype do alvo, então um alvo FP8 obtém um cache de rascunho FP8 (#65198).

  • Redução de DP+EP tolerante a falhas: classificações mortas são removidas e seus especialistas redis são atribuídos sem reinicialização (#46370).
  • Melhor esforço ligação NUMA ativado por padrão (#61258).
