#vllm v0.22.0

Destaques

Esta versão apresenta 459 commits de 230 colaboradores (63 novos)!

  • Maturidade do DeepSeek V4: DeepSeek V4 recebeu uma grande aprovação de endurecimento neste ciclo - o modelo foi reorganizado em um pacote vllm/models/deepseek_v4/ dedicado (#43004, #43039, #43073, #43077, #43149), ganhou suporte MoE fundido NVFP4 (#42209), gráfico CUDA completo + por partes (#42604) e especulativo MTP decodificação (#43385). Um grande conjunto de kernels fundidos (MegaMoE, mhc, Q-norm, indexador, MLA esparso) e correções de paridade ROCm chegaram junto com correções de precisão (#42810, #43710).
  • Model Runner V2 avança em direção ao padrão: MRv2 agora é padrão para modelos densos Qwen3. O vLLM retornará ao MRv1 para recursos que ainda não são suportados no MRv2 (#39337). recarga de peso no modo de suspensão (#42673), update_config (#42783) e camadas de cache KV compartilhadas (#35045), além de muitas correções de correção.
  • Frontend Rust experimental: Uma nova integração de front-end Rust foi lançada (#40848), com a implementação movida para a árvore (#43283) e um Supervisor DP para serviço paralelo de dados (#40841).
  • Invariância de lote, mais rápida: A inferência invariante de lote ganhou suporte ao Cutlass FP8 para uma 28.9% melhoria de latência ponta a ponta (#40408), suporte ao modo de compilação no SM80 (#42456) e um caminho linear NVFP4 Cutlass (#39912).
  • Descarregamento de cache KV multicamadas: Uma nova estrutura de descarregamento de cache KV multicamadas (#40020) com uma camada secundária do sistema de arquivos Python (#41735), suporte DSv4 (#43142) e descarregamento de disco Mooncake (#42689) estende o descarregamento além da memória da CPU.

Suporte ao modelo

  • Novas arquiteturas: MiniCPM-V 4.6 (#41254), InternS2 Preview (#42705), OpenVLA (#42654), MolmoWeb hf_overrides docs (#42163); EXAONE-4.5 alinhado com a atualização dos Transformers (#42246).
  • Decodificação especulativa: back-end do proponente chamado personalizado (#39487), especuladores EAGLE-3 pós-norma (#42764), especuladores peagle (#41826), modelos de atenção híbrida em extract_hidden_states (#39949), especulação não-MTP para NemotronH (#43130), pesos MTP compartilhados em MRv2 (#42538).
  • DeepSeek V4: NVFP4 MoE (#42209), gráfico CUDA completo/por partes (#42604), MTP (#43385), refatorador de pacote de modelo (#43004, #43039, #43073, #43077), MLA esparso + refator de compressor (#43149, #43710), movimentação de kernel de preparação de entrada MegaMoE (#43632).
  • Qwen3.5/3.6: nivelamento de projeção de saída GDN (#42311), correção GatedDeltaNet Marlin TP≥2 (#36329), gráfico CUDA completo ViT (#42151), carregamento de peso runai-streamer para Qwen3.5/MTP/Qwen3-VL (#42521, #42716), KDA chunk-prefill exp2 semântica (#43195).
  • Gemma3/Gemma4: correção de travamento de co-lote de imagens de resolução mista (#42217), correção de fechamento de roteamento MoE (#42250), correção de corrupção flutuante do analisador de ferramentas (#42128), codificador de visão em lote para imagem/vídeo (#43169), correção multi-GPU (#42630).
  • Kimi-K2.5: ignora a conversão de dtype da torre de visão sob quantização (#42869), correção de dtype mm_projector (#42081).
  • Cohere: habilite Cohere MoE (#43143), paralelismo de pipeline para visão Cohere (#42819).
  • Chamada de ferramenta: analisador de ferramenta Apertus (#41154), resolução Qwen3Coder anyOf/oneOf/$ref (#37831), coerce_to_schema_type compartilhado entre analisadores MiniMax-M2 / DeepSeek-V3.2 / Seed-OSS (#43006, #43019, #43140).
  • Gráfico ViT CUDA: Qwen2-VL (#41736), codificador Step3-VL (#42224), Qwen3.5 (#42151), metadados FlashInfer para atenção visual Qwen2.5-VL (#42787).

Núcleo do motor

Hardware e desempenho

  • NVIDIA Blackwell / SM12x: FlashInfer b12x MoE + FP4 GEMM para SM120/121 (#40082), FP8 CUTLASS por tensor em SM12.1 (#41215), head_dim=512 para FlashInfer TRTLLM atenção (#38822), FlashInfer Blackwell GDN prefill (#40717), kernel de pré-preenchimento GDN para SM100 (#43273).
  • Desempenho: Cutlass FP8 invariável em lote (+28.9% E2E) (#40408), pré-processamento de preenchimento CutlassFP8 (+13.5% TTFT) (#42651), kernel quant NVFP4 acolchoado (+2.4–5.7% E2E) (#42774), eliminação de sincronização de GPU<->CPU 1/n (#41429) e 4/n (#42347), RoPE + KVCache + q_concat fundido para MLA (#40392), otimizações MLA compute_prefill_context / _v_up_proj (#42460, #42561), penalidades Triton kernel (#40657), do_not_specialize em FP8 RoPE fundido (#42849), FULL Captura de gráfico CUDA para decodificação TRITON_MLA (#42885).

  • CPU / RISC-V: Kernels de atenção otimizados para RVV para extensão de vetor RISC-V (#40119) com VLEN=256 (#42943), GDN fundido para CPU AMX (#42707), MXFP4 W4A16 MoE (#41922), Triton + MRv2 experimental na CPU (#43225), utilização de thread de CPU aprimorada (#42666), --cpu-distributed-timeout-seconds (#42968).
  • Intel XPU: suporte GPTQ int4 (#37844), mxfp8 MoE (#41918), quantização em escala de bloco FP8 (#42952), comportamento coletivo de operação personalizada (#41354), múltiplos kernels de atenção esparsa (#37888), roteamento topk MoE + fallback MXFP4 (#42951), caminho CT W4A4 MXFP4 (#38896), redução da sobrecarga do host XPU MoE (#42915).

  • Experimental: gráfico CUDA quebrável (#42304).
