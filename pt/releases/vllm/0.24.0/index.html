#vllm v0.24.0

#vLLM v0.24.0 Release Notes

Destaques

Esta versão apresenta 571 commits de 256 colaboradores (77 novos)!

  • MiniMax-M3: Adicionado suporte para o novo modelo MiniMax-M3 (#45381), com uma rápida continuação do indexador BF16/FP8 via MSA (#45892), suporte MXFP4 (#45896), GQA esparso FP8 (#45744) e ajuste extenso de AMD/ROCm — mxfp8 MoE/linear em gfx950 (#45725), fp8_per_channel para pesos bf16 no MI300X (#45854), correção de cache KV FP8 (#45720) e mapeamento de módulos compactados (#45794). Uma regressão de desempenho MiniMax-M2 também foi corrigida (#45935).
  • DeepSeek-V4 continua amadurecendo: Após sua estreia, DeepSeek-V4 recebeu outra grande passagem de otimização - um cache de índice esparso FlashInfer (2–4% TTFT) (#45863), otimização de planejamento de bloco de pré-preenchimento (4% de taxa de transferência E2E) (#45061), um kernel topK cooperativo em cluster para baixa latência (#43008), alocações de KV contíguas por bloco (#44577), TEP=16 para o especialista compartilhado do bloco FP8 (#46001) e decodificação do indexador DSA nativo para next_n > 2 no SM100 (#45322). Agora está habilitado no SM120 junto com GLM-5.1 (#43477), com caminhos de atenção/MoE XPU (#44144, #44517, #45240) e ROCm (#44899, #45103, #45681) adicionados.
  • Model Runner V2 (MRv2) continua a se expandir: MRv2 agora suporta modelos quantizados por padrão (#44446), habilita GraniteMoE por padrão (#45461) e obteve migração de modelos Qwen + DeepSeek-V2 MoE (#42667), decodificação especulativa DFlash (#44586) e amostragem FP32 Gumbel mais precisa (#45996).
  • Mecanismo de análise de streaming: um novo mecanismo de análise de streaming unifica a análise de chamada de ferramenta/raciocínio entre modelos, com analisadores para Qwen3 (#45413), MiniMax-M2 (#45701), GLM-4.7/5.1/5.2 (#45915) e Nemotron V3 (#45755).
  • Diffusion LLMs: Adicionado DiffusionGemma (#45163), incluindo um caminho de CPU (#45690) e proteções de saída estruturada para decodificadores de difusão (#45468).
  • WideEP / DeepEP v2: DeepEP v2 integrado para paralelismo especializado (#41183), com correções de robustez subsequentes (#46404, #46432).
  • O frontend Rust amadurece ainda mais: Adicionada autenticação de chave API (#44321), CORS (#45753), /tokenize + /detokenize (#44222), /pause /resume /is_paused (#44499), /abort_requests (#44382), /get_world_size (#44801), thinking_token_budget (#46137), uma ponte Python para analisadores de ferramentas Rust (#44624) e muitos novos analisadores e caminhos de validação.
  • Alteração na seleção do dispositivo: vLLM não configura mais CUDA_VISIBLE_DEVICES internamente; em vez disso, é fornecido um novo argumento device_ids (#45026). No ROCm, uma janela de descontinuação para CUDA_VISIBLE_DEVICES começou (#46636).

Suporte ao modelo

  • Novos modelos: MiniMax-M3 (#45381), DiffusionGemma (#45163) + Gemma Diffusion na CPU (#45690), Modelo de raciocínio hierárquico — Text / HrmTextForCausalLM (#43098), OpenMOSS (#44124).
  • Gemma 4: FlashAttention unificado (FA4) em todas as camadas + suporte mm_prefix (#42175); muitas correções de analisador/serviço — salto forçado de JSON para escolha de ferramenta necessária/nomeada (#45795), análise com pensamento desativado (#45832), inicialização de estado de raciocínio de streaming (#45852), renderização de raciocínio em turnos de assistente (#45867), truncamento do analisador offline/correção de vazamento de token (#45553); analisadores Gemma4 legados substituídos por uma implementação baseada em mecanismo (#45588).
  • DeepSeek-V4: correção OOM (#44914), prefixo de projeção MTP (#44821), dtypes de cache KV suportados (#44892).
  • Qwen / multimodal: carregador de vídeo Qwen3-VL (#44412), carregador de vídeo mapeado pelo processador Qwen2-VL/Qwen2.5-VL (#45555), otimização de processamento de vários vídeos Qwen3-VL (#46026) e correção de falha de vários vídeos (#46305), correção de dispositivo Qwen3-Omni VIT cu_seqlens (#44264), fundido qk-rmsnorm-rope-gate para Qwen3.5 (#44176), correção de carregamento de peso Qwen3.5 EP (#45002).
  • Gráfico CUDA completo do ViT: GLM-4.1V (#40576), caminho duplo DeepSeek-OCR (#43586), Kimi-VL (#41992), mllama4 (#40660), codificador Lfm2VL (#44930).
  • Outras correções de modelo: carregamento de peso Llama4 (#45047) e carregamento de streaming para evitar host-OOM (#44645), fragmentação MiMo v2.x QKV TP + FP4 (#45200), correção de recuperação ColQwen3.5 (#46108), codificador de visão EXAONE-4.5 (#45073), MiDashengLM TP>1 falha do codificador de áudio (#44408), posicionamento do dispositivo MiniCPM-o/V e correções de tamanho de imagem (#43844, #42332, #44980, #45244), carregamento de peso Cohere2 MoE + analisador (#44747, #44907), Nemotron V3 raciocínio como conteúdo (#39091), ColBERT AutoWeightsLoader + processador io de incorporação de consulta/documento (#44999, #45210).
  • Kernels: Dimensões irregulares de pré-preenchimento MLA GLM-5 TRT-LLM (#43525), roteador GLM-5 GEMM (#46385).

Núcleo do motor

  • Model Runner V2: Modelos quantizados por padrão (#44446), padrão GraniteMoE (#45461), migração Qwen/DSv2 MoE (#42667), DFlash (#44586), manipulação de saída assíncrona simplificada (#45442), divisão de grupo de atenção em num_heads_q (#45564), correção de aquecimento LoRA (#35536), FP32 mais preciso Amostragem Gumbel (#45996), correção min_tokens off-by-one no amostrador de GPU V2 (#46243), além de diversas correções de compatibilidade de modelo/configuração (#45868).
  • Decodificação especulativa: SD Dinâmico (#32374); DFlash com FlashInfer (#43081), tamanhos de página KV mistos (#45181) e alvos Qwen3Next (#45319); Suporte EAGLE3 para Qwen3 (#43132); comunicação TP reduzida para rascunhos de vocabulário extenso (#39419); correção de corrida em contagens assíncronas aceitas (#45100); Correções de cache do codificador multimodal EAGLE (#46315).
  • Cache e agendador KV: marca d’água de cache KV para reduzir preempções (#44594), alocação de duas fases para ocorrências de cache de prefixo entre grupos (#44409), política de admissão estilo Marconi para cache híbrido (#37898), retenção de cache de prefixo para Mamba/atenção linear (#45845), cópia final do DS Mamba para modo de alinhamento MTP (#45473), sobrecarga reduzida de cópia do agendador (#45840).
  • Atenção: Layout de cache KV de camada cruzada reativado para MLA por meio de kernels com reconhecimento de passada (#45111), saída FA4 fp8 pré-preenchida de MLA (#43050), mods de máscara personalizados FlexAttention totalmente cudagrafáveis ​​(#45232), back-end triton diff-kv para MiMo (#41797), correção de precisão esparsa FlashMLA (#36616).
  • Carregamento de peso e núcleo: fastsafetensors ParallelLoader para carregamento de peso (#40183), liberação de memória de dispositivo em cache sob pressão em GPUs UMA (#45179), saídas estruturadas para pesquisa de feixe (#35022), device_ids arg / sem CUDA_VISIBLE_DEVICES interno (#45026), fallback gracioso quando numactl --membind é bloqueado (#45438), registro de classe de configuração antes inicialização do tokenizer (#40299), agendamento assíncrono com incorporações de prompt para modelos multimodais (#45673).

  • Paralelo especialista: Integração DeepEP v2 (#41183) com correções de token-bound e topk-index (#46404, #46432); NIXL EP — DBO com NIXL EP (#45275), consulta dtype de índice top-k (#45298), salto de quantização pós-recebimento NVFP4 (#45606), comunicador elastic-EP (#45013); rejeitar EPLB baseado em NCCL com EPLB assíncrono (#44978).
  • Conectores KV/serviço desagregado: envio de KV do pré-preenchimento para decodificação via NIXL (#35264); classificação de transferência KV por região para grupos mistos de atenção total + MLA (#44583); Suporte PD paralelo ao pipeline Mooncake (#44528), pesquisa assíncrona (#45659), pesquisa compacta de cópia zero de hash de bloco (#45969), salto de bloco SWA (#45444); Correções P/D com supervisor DP (#46628) e desagregação DSV4 (#45831); removido P2pNcclConnector (#44854).

  • Núcleo distribuído: cadência de etapa de pré-preenchimento para melhor balanceamento DP não-PD (#44558), codificação de mapa de eventos KV (#42892), correção PDL NaN com fusão total e redução única (#45448).

Hardware e desempenho

  • NVIDIA / kernels: suporte SM90 CUTLASS FP8 mm ímpar-M via swap_ab (180–290% de aceleração do kernel) (#44572), fused_moe FP8 ajustado para Qwen3-Next-80B em H100 (+25%) (#44830), decodificação de indexador DSA nativo em SM100 (#45322), topK cooperativo de cluster para DeepSeek de baixa latência (#43008), suporte PDL para DeepGEMM (#46006), FlashInfer cutedsl NVFP4 GEMM (#42235) e kernel linear cute-dsl MXFP8 (#46393), novos kernels Helion para FP8/RMSNorm quant (#36902, #33790, #36895, #34432).
  • ABI estável da tocha: migração contínua (e concluída) de kernels para a ABI estável da libtorch — MoE [10c/n] (#44565), Marlin [11a/n] (#45176), Machete [11b/n] (#45304), migração final da biblioteca _C [12/n] (#45415).
  • AMD ROCm: Tocha 2.11 (#45362); fundido AR + RMSNorm + FP8 quant por grupo (#42864), roteador fundido softplus-sqrt-topk MoE sob AITER (#44945), DSv4 flash-decode split-K kernel (#44899) e fusão inverse-RoPE (#45103), W4A16 FlyDSL MoE (#44400), A8W4 MoE CDNA4 swizzle gate para gpt-oss (#44804); janela de descontinuação iniciada para CUDA_VISIBLE_DEVICES no ROCm (#46636).
  • Intel XPU: Suporte paralelo de sequência (#38608), torch-xpu 2.12 (#42262), vllm-xpu-kernels v0.1.10 (#40367), W4A16 int4 group_size=32 MoE (#45136), caminhos de atenção/MoE DeepSeek-V4 (#44144, #44517, #45240), correção de correção de amostragem top-p (#44470).
  • CPU e outras arquiteturas: 2.5× pré-processamento de CPU ASR mais rápido via multi-threading (#44612), CPU W4A16 INT4 MoE (#43409), dimensionamento de cache KV com reconhecimento de limite de memória cgroup (#45086), RISC-V oneDNN W8A8 INT8 (#44478) e RVV micro-GEMM para WNA16 (#44324), memória fixada para WSL2 (#41496), registro de tempo de execução ZenCPU (#42726).
  • TPU: inferência de tpu atualizada para v0.22.1 (#45793).
  • Desempenho diverso: VLLM_TRITON_FORCE_FIRST_CONFIG para pular o autoajuste do Triton (#42425), detecção de recompilação do Triton (#45631), gravações preparadas de tabela de blocos multigrupo fundidas (#44944).

Quantização

  • On-line e precisão mista: Quantização on-line FP8 por token por canal (PTPC) (#44132); Suporte modelopt_mixed estendido para Ampere/SM80-86 (#45306) e Turing/SM75 (#45375).
  • FP4 / MXFP: FlashInfer cutedsl NVFP4 GEMM backend (#42235) e kernel linear cute-dsl MXFP8 (#46393), correção de escala MXFP4 W4A4 MoE CUTLASS E8M0 (#43557), grampo SwiGLU conectado para NVFP4 MoE em não-Blackwell (#45836), flashinfer_cutlass permitido como fixado Backend NVFP4 MoE (#46492), correção de emulação NVFP4/OCP MX MoE (#46254), FP8 MoE reativado em NVIDIA Thor (#46339).
  • **GGUF / tensores compactados / AWQ **: quantização GGUF migrada para um plug-in (#39612), correção de atorder WNA16 MoE de tensores compactados (#41161) e rejeição de esquema de cache KV (#45312), formato AWQ em XPU (#43404) e correção de desquantização de AWQ em Intel XPU (#42727).
  • Kernels e correção: contrato de kernel linear QuantizedActivation (#44260), preenchimento de bloco de thread Marlin consolidado (#45295), layout de peso FP8 canonizado para (K, N) (#44735), correção de saída corrompida para MoE FP8 com LoRAs carregados (#42120), correção de regressão quantitativa simétrica em GPTQ/CT MoE (#45656), Cache fp8_e5m2 KV permitido para pontos de verificação não-fp8 (#45040).

  • Anthropic Messages API: Relatório de uso de cache em /v1/messages (#40912), tratamento de mensagens do sistema no meio da conversa (#46025), posição de mensagem do sistema inline preservada para cache de prefixo (#44602), correção de eliminação de argumentos tool_use (#45287).
  • Frontend Rust: autenticação de chave API (#44321), CORS (#45753), /tokenize + /detokenize (#44222), /pause /resume /is_paused (#44499), /abort_requests (#44382), /get_world_size (#44801), thinking_token_budget (#46137), parallel_tool_calls=false (#44760), estatísticas de uso contínuo (#43965), metadados de modelo em /v1/models (#45950), ponte Python para analisadores de ferramentas Rust (#44624), tempo de execução dedicado para HTTP/ZMQ (#46051) e muitas validações/correções correções.

Segurança

Este lançamento traz outro lote coordenado de reforço de segurança (grande parte dele do pesquisador de segurança @jperezdealgaba).

  • Negação de serviço: bomba de descompressão de áudio no endpoint de fala para texto (#44970), DoS remoto via reinjeção de token recuperado inválido em decodificação especulativa (#44744), DoS via prompt_embeds em modelos M-RoPE (#45252), proteção de tempo limite de compilação regex em saídas estruturadas (#45118), limite de tamanho de upload de áudio antes da materialização completa (#45510), limite de duração da decodificação de áudio no caminho de conclusão do bate-papo (#45908).
  • Divulgação de informações: truncamento int32 nos kernels de desquantização GGUF (#44971).
  • Validação e proteção de entrada: Orientação EXIF ​​de imagem e tratamento de transparência tRNS (#44974), rejeição de temperature/repetition_penalty não finito (#45116), sanitize_message aplicado a caminhos de erro antrópicos e STT (#45119).
  • Dependências: Atualize Starlette para ≥ 1.0.1 para corrigir CVE-2026-48710 (#45675).

Dependências

  • Tocha 2.11 em ROCm (#45362), tocha-xpu 2.12 (#42262), tpu-inferência v0.22.1 (#45793), NIXL v0.10.1 para XPU (#40287), Starlette ≥ 1.0.1 (#45675).
  • mistral_common agora é opcional via importação diferida (#45305); Arquivos CUDA Docker atualizados do GCC 10 para GCC 12 para C++20 (#44923); extensão spinloop ignorada em Python < 3.11 (#44783).

Depreciações e remoções

  • Modelos removidos: ERNIE (obsoleto) (#45127), Xverse (#45638), Dots1 (#45637), Bamba (#45990), Mono-InternVL (#45129), alias de registro InternLM (#45128).
