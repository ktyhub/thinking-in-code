#vllm v0.21.0

Destaques

Esta versão apresenta 367 commits de 202 colaboradores (49 novos)!

  • Transformers v4 obsoleto: Esta versão descontinua formalmente o suporte a transformers v4 (#40389). Os usuários devem migrar para transformers v5.
  • Requisito de compilação C++20: vLLM agora requer um compilador compatível com C++20 para compatibilidade com PyTorch (#40380). Esta é uma mudança de compilação significativa.
  • KV Offload + Hybrid Memory Allocator (HMA): O subsistema de offloading KV agora se integra ao Hybrid Memory Allocator, incluindo suporte a grupos de janelas deslizantes no lado do agendador e ativação completa de HMA (#41228, #41445, #39571).
  • Decodificação especulativa com orçamento de pensamento: A decodificação especulativa agora respeita orçamentos de raciocínio/pensamento, permitindo a decodificação de especificações correta para modelos de raciocínio (#34668).
  • Backend TOKENSPEED_MLA na Blackwell: Um novo backend de atenção TOKENSPEED_MLA está disponível para pré-preenchimento + decodificação DeepSeek-R1/Kimi-K25 em GPUs Blackwell (#41778).

Suporte ao modelo

  • Novas arquiteturas: MiMo-V2.5 (#40967), Laguna XS.2 (#41129, #41880), Moondream3 (#32325), Qianfan-OCR (#40136), Cohere MoE (#40817), Cohere Eagle (#42078).
  • Decodificação especulativa: EAGLE para Mistral (#41024), Gemma4 MTP (#41745), MTP para MiMo-V2.5 (#41905), Cohere Eagle (#42078).
  • DeepSeek V4: suporte AMD/ROCm (#40871), paralelismo de pipeline (#41694), esforço de raciocínio max (#40982), correções de serviços desagregados (#41957).
  • Chamada de ferramentas: Raciocínio Cohere e analisadores de ferramentas (#40422), analisador de ferramentas LFM2/2.5 (#39243).
  • Gemma3/Gemma4: suporte à variante hidden_act (#40588), correção de paralelismo de pipeline (#40786), correções de MoE (#41206, #41574, #41401), correção de falha do analisador de ferramentas (#41991, #42188).
  • Modelo Runner V2: suporte ao modelo híbrido Qwen3.5/Mamba (#35520), suporte logprob_token_ids (#40559).
  • Gráfico CUDA: suporte a gráfico ViT CUDA para Qwen2.5-VL (#40830).
  • Compatibilidade: Fornecedor HCXVisionConfig para Transformers v5 (#38447), suporte de ponto de verificação legado rope_type (#41734).

Núcleo do motor

  • Descarregamento de KV + HMA: grupos de janelas deslizantes do lado do agendador (#41228), ativação completa de HMA (#41445), HMA multiconector (#39571), conclusão de armazenamento por trabalho (#39186), suporte DCP/PCP em OffloadingConnector (#41549), MooncakeStoreConnector para descarregamento de KV distribuído (#40900).
  • Decodificação especulativa: suporte orçamentário de pensamento (#34668), seleção de back-end de atenção do redator independente (#39930), suporte de modelo multimodal com aviso (#41752), eliminação de alocação por etapa (#41043).
  • Model Runner V2: correção da taxa de aceitação de amostragem de rejeição (#40651), pular reconstrução de metadados antes do pré-preenchimento do rascunho (#40410), reconstruir metadados entre etapas de decodificação de rascunho (#41162), suporte híbrido Qwen3.5/Mamba (#35520).
  • Roteamento: Substitua a repetição de roteamento por cache de dispositivo e pipeline D2H assíncrono (#39917).
  • Ray: RayExecutorV2 habilitado por padrão (#41421), correção de colisão de nome de ator para DP > 1 (#40398).
  • Estabilidade: pausa de duas fases para evitar deadlock do agendador (#39366), wrappers de tokenizer HF thread-safe (#41181), prevenção de OOM via max_split_size_mb durante o carregamento do modelo (#41268).
  • Suporte IndexCache para modelos DSA (#37735).

Hardware e desempenho

  • NVIDIA Blackwell: back-end TOKENSPEED_MLA para DSR1/Kimi-K25 (#41778), kernel compactado quantitativo de grupo FP8 por token mais rápido (#41326), FP8 em NVIDIA Thor/SM110 (#39712), CUTLASS dimensionado em mm para tamanhos não compatíveis (#41868).
  • Desempenho: amostrador FlashInfer top-k/top-p habilitado por padrão (#40376), atenção FlashInfer FP8 para ViT (#38065), buffers de dequantidade compartilhados TurboQuant (#40941), AllPool.forward 51% mais rápido (#41163), GPU<->Eliminação de sincronização de CPU em pooling (#41433) e atenção (#41434), numpy zero-copy incorporação de serialização (#41681), salto de processador multimodal para somente texto (#41246), fusão TP assíncrona FlashInfer FP8 (#39505), fusão GEMM NVFP4 all-gather para AsyncTP (#41882), reativação de fusão allreduce + RMS para DP/PP (#41458), DeepSeek bf16→fp32 via torch.mm (#41300), MLA persistente para back-end esparso (#41990), pré-busca de ponto de verificação de safetensors configuráveis (#41499), kernel mhc_post_pre fundido (#41536), kernel quant de grupo W8W8 de grade 2D (#42153), ordenação de memória relaxada para trocas de cache KV (#39306).
  • AMD ROCm: ROCm 7.2.2 (#41386), DBO (Dynamic Batch Optimization) (#34726), AITER Fused Allreduce+RMSNorm (#37646), Fused Shared Expert (FSE) para Qwen3-Next (#39280), DeepSeek V3.2 TP4 AITER MLA (#41835), GDN fusão de atenção linear (#40711), eliminar cópias redundantes de buffer MoE em AITER (#41713), suporte de descarregamento de CPU (#40549), atualização DeepEP API (#39721), limitar o tamanho do bloco de atenção paginado Triton para corrigir OOM de memória compartilhada (#38502).
  • CPU: Atenção FP8 para AMX/AVX-512 (#39445), FP8 W8A16 linear (#41186), FP8 W8A16 MoE (#41314), DNNL AVX2 W8A8 Int8 (#41318), Gated DeltaNet Atenção para Qwen 3.5/3.6 (#41025), Ligação automática de thread RISC-V OMP (#40569).
  • Intel XPU: kernel de amostra Top-k/top-p (#39285), redução total fora do lugar (#41808), suporte LoRA (#38206).
  • IBM Power: back-end de atenção do VSX (#40451).
  • FlexAttention: Reativado para modo invariável em lote (#40842).
  • MLA: back-ends de pré-preenchimento de MLA abstraídos, eliminação da dependência de cuDNN (#32623).

Serviço em grande escala

  • Serviço desagregado: transferências bidirecionais de cache KV entre P e D (#32553), redesenho de transferência NIXL (#40731), otimização de sobrecarga de memória EPLB (#40013), conector NIXL aumentado para 1.x (#42364), Mooncake KVConnectorStats para observabilidade de transferência (#40414), notificação de rejeição de pré-admissão de nó P NIXL (#41269), liberação de bloco KV para pulou as classificações P (#40449).
  • DCP: Saída de pacote e LSE em DCP A2A (#41160).
  • MoE: interface PluggableLayer para executores MoE fora da árvore (#35178).
  • LoRA: Suporte inicial paralelo especializado (EP) (#40867), correção de fusão Qwen3.5 LoRA (#37912).

Quantização

  • NVFP4: suporte a cache KV (#40177), kernels de emulação Triton dequant/QDQ para Hopper e AMD (#40033), GELU em TRT-LLM NvFP4 fundido MoE para Gemma4 (#41050), ModelOpt NVFP4 W4A16 (#41769), NVFP4 all-gather GEMM fusion para AsyncTP (#41882), correção de carregamento GLM4-MoE NVFP4 (#41755).
  • MXFP4: back-end Humming MXFP4 MoE (#41083), correção FlashInfer CUTLASS MXFP4-MXFP8 MoE (#42089).
  • TurboQuant: modelo híbrido e suporte de quantização uniforme (#39931).
  • Tensores compactados: Permite configurações com ignorações não explícitas (#41965).
  • FP8: Correção de carregamento polarizado (#41424), ajuste automático do FlashInfer desativado temporariamente para correção (#41524).
  • DSV4: Kernel quant do Indexer Q fundido aprimorado (#41428).

API e interface

  • Respostas API: Chamada de ferramenta/função de streaming com required (#40700) e escolha de ferramenta/função nomeada (#41110), reenviando itens de saída com campos ausentes (#41355).
  • Compatibilidade OpenAI: campo system_fingerprint em respostas (#40537), suporte à parte de conteúdo prompt_embeds (#40720), suporte a defer_loading e tool_reference (#40190), texto de prompt renderizado na resposta de conclusão do bate-papo (#42052), tolera conteúdo vazio na escolha forçada da ferramenta (#40148).
  • Chamada de ferramenta: XGrammar 0.2.0 com tags estruturais para chamada de ferramenta estrita + raciocínio (#40894), analisadores de ferramentas/raciocínio Cohere (#40422), analisador de ferramentas LFM2/2.5 (#39243).
  • Tokenizer: Suporte a Fastokens (#41741).
  • RLHF: /start_weight_update e /finish_weight_update APIs explícitos (#39212).
  • ASR: Solicitação do mecanismo abortada no cancelamento (#41266).
  • Configuração: VLLM_SKIP_MODEL_NAME_VALIDATION env var (#34676), rastreamento de carregamento de pesos de modelo configuráveis ​​(#41086), monitor de compilação Triton JIT (#40137).

Construção e Dependências

  • Quebra: C++20 necessário para compatibilidade com PyTorch (#40380).
  • Quebra: Transformers v4 obsoleto (#40389).
  • Tamanho da imagem Docker reduzido em ~2.5 GB por meio do download diferido do FlashInfer cubin (#41134).
  • Rodas CUDA 13.0 trocadas para base PyTorch Manylinux_2_28 (#41416).
  • Roda empacotada DeepGEMM construída por Python para compatibilidade com CPython (#41516).
  • Metadados de origem da imagem do contêiner incorporados (#40653).
  • inferência tpu atualizada para v0.19.0 (#41844).
  • Conector NIXL aumentado para 1.x (#42364).
  • ROCm 7.2.2 (#41386).
