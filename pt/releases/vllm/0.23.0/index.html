#vllm v0.23.0

#vLLM v0.23.0 Release Notes

Observe que o Minimax M3 ainda não é compatível com esta versão. Siga a receita vLLM para obter guias de uso para M3.

Destaques

Esta versão apresenta 408 commits de 200 colaboradores (63 novos)!

  • DeepSeek-V4 amadurece em backends: Após sua introdução no v0.22.0, DeepSeek-V4 recebeu outra grande passagem de proteção e otimização. Seus metadados MLA esparsos agora estão desacoplados do DeepSeek-V3.2 (#44699), ele ganhou um kernel de atenção da geração TRTLLM (#43827), suporte EPLB para o Mega-MoE (#43339), retenção seletiva de cache de prefixo para cache KV de janela deslizante (#43447) e um recurso de compartilhamento de índice para DSA MTP (#44420). O modelo também foi separado do torch.compile (#43746, #43891), seus caminhos de atenção e RoPE foram refatorados (#44569, #44262, #43926) e um caminho de decodificação de atenção XPU foi adicionado (#42953).
  • Model Runner V2 se expande para modelos mais densos: MRv2 agora é selecionado por padrão para modelos densos Llama e Mistral (#43458) além de Qwen3. Ele ganhou um amostrador FlashInfer (#42472), gráficos CUDA quebráveis ​​(#44050), eliminação de bolhas paralelas ao pipeline (#42187), suporte de tamanho de bloco de kernel para modelos híbridos (#38831) e Gemma 4 MTP (#43241).
  • O frontend Rust cresce: O frontend experimental Rust adicionou um endpoint de streaming generate (#43779), endpoints LoRA dinâmicos (#43778), endpoints /version (#43854) e /server_info (#43942), um gancho de extensão servidor-roteador (#43774), cabeçalhos de ID de solicitação (#43883) e muitos novos analisadores de ferramentas (InternLM2 #43481, hy_v3 #43872, Phi-4-mini #44213, Gemma4 #43850).
  • Gemma 4: Adicionado suporte sem codificador Gemma 4 Unified (#44429) e Gemma 4 MTP (#43241), além de inúmeras correções de precisão e inicialização.
  • Compatibilidade com Transformers v5: vLLM agora tem como alvo Transformers v5, com processadores MiniCPM-V/O vendidos (#44282) e correções de compatibilidade para Sarvam (#38804) e Voxtral (#44559).
  • Descarregamento de cache KV multicamadas: a estrutura de descarregamento ganhou uma camada secundária de armazenamento de objetos (#41968), HMA habilitado por padrão para conectores capazes (#41847), suporte de camadas para modelos HMA (#44287) e uma política de descarregamento por solicitação por meio do gancho de ciclo de vida on_new_request (#43205).
  • Analisador unificado: O raciocínio e a análise de chamada de ferramenta agora são unificados por trás de uma única interface Parser.parse() (#44267), com o analisador de respostas migrado para ela (#42977).

  • Gemma 4: Suporte unificado sem codificador (#44429), MTP (#43241), camadas lineares ViT nativas (#43798), incorporador de visão excluído da quantização (#44571) e correções para MTP em TP>1 (#43909), incompatibilidade de tabela de blocos sob simultaneidade (#43982), falha na inicialização do processador de transformadores (#44232) e inicialização da CPU (#44615).
  • Transformadores v5: Processadores MiniCPM-V/O do fornecedor (#44282), compatibilidade com Sarvam (#38804), Voxtral fetch_audio para transformadores≥5.10 (#44559).
  • Correções e melhorias de modelo: precisão do deepstack Qwen3-VL/Qwen3-omni-thinker sob torch.compile (#43617), EVS para Qwen3-VL (#44205), carregamento GLM-5.1 PP (#42944), logits do processador GLM-4.1V (#43575), carregador de vídeo GLM-4.6V (#44417), OlmoHybrid init (#43846), remoção de código remoto HyperCLOVAX (#43860), fator rotativo Bailing-MoE (#43770), Step3 PP KeyError residual (#37622), vídeo MiniCPM-V-4.6 (#44509), despreenchimento de áudio MiniCPM-O (#38053), MiniCPM-V em lote pré-processamento (#44609), FunASR-Nano init (#44215), método de roteamento Cohere (#44021), metadados Kimi-K2.5 FlashInfer ViT (#44493).
  • Multimodal: seleção automática de carregador de vídeo registrado para VLMs (#44126), manipulação de itens multimodais O(log n) por etapa (#44212), codificação de imagem local em benchmarks (#43843), conjuntos de dados de benchmark de imagem personalizados intercalados (#43636).
  • Pooling/Classificação: exceções adequadas para pooling UX (#44593), extra_repr() para classes de pooler (#44805), correção de pooling de nome de adaptador LoRA (#44410), ponto de entrada de pontuação generativa reinstalado (#44153), testes de unidade de pooler expandidos (#43818, #44471).

Segurança

  • Criptografia de transporte: suporte SSL/TLS para o supervisor paralelo de dados (#43688).
