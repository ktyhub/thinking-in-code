#difícil 1.14.1

🚀 O que há de novo no v1.14.1?

v1.14.1 é um lançamento de patch focado no fortalecimento da segurança, fluxo de trabalho e estabilidade da base de conhecimento, limpeza de implantação e migração contínua da plataforma de UI após v1.14.0.

🔐 Segurança

  • Proteção SECRET_KEY auto-hospedada — As implantações do Docker não dependem mais de uma chave pública padrão. Quando SECRET_KEY é deixado vazio, o API gera e persiste uma chave de tempo de execução por meio do backend de armazenamento configurado, enquanto as chaves configuradas explicitamente continuam a funcionar como antes. Obrigado @laipz8200 em #36049.
  • Proteção de endpoint de métricas internas — /threads e /db-pool-stat são reforçados para evitar exposição não autenticada de tempo de execução interno e detalhes do pool de banco de dados. Obrigado @orbisai0security em #35665.
  • Isolamento de conta e ferramenta — corrigido um problema de IDOR no GET /account/avatar e limpeza de credenciais padrão da ferramenta integrada com escopo definido para o locatário atual. Obrigado @NeatGuyCoding e @GareArc em #35771 e #35887.
  • Segurança de dependências — LiteLLM atualizado para CVE-2026-42208 e várias dependências de back-end atualizadas, incluindo urllib3, gunicorn, gitpython, mako, pacotes Google SDK, bibliotecas de armazenamento e pacotes de exportação OpenTelemetry. Obrigado @crazywoola em #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017 e #36050.

Guia de atualização

Notas importantes

  • Esta versão inclui uma nova migração de banco de dados para categorias configuráveis de aplicativos Explore. Execute migrações de banco de dados como parte da atualização.
  • Docker As variáveis ​​de ambiente do Compose agora são divididas em arquivos categorizados em docker/envs/**. Se você mantiver um docker-compose.yaml ou .env personalizado, revise o novo layout e reaplique as personalizações locais com cuidado.
  • Para implantações auto-hospedadas, os valores SECRET_KEY configurados explicitamente continuam a ser respeitados. Se SECRET_KEY estiver vazio, o Dify agora gera e persiste uma chave de tempo de execução automaticamente.

Docker Compor implantações

  1. Faça backup de seus arquivos YAML e env personalizados do docker.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Obtenha o código mais recente do branch ou tag de lançamento.

    git fetch --tags
git checkout 1.14.1

  3. Pare o serviço. Execute no diretório docker.

    docker compose down

  4. Faça backup dos dados.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Revise o novo layout do arquivo env docker/envs/** e aplique novamente quaisquer personalizações locais.

  6. Atualizar serviços.

    docker compose up -d

Implantações de código-fonte

  1. Pare o servidor API, o Worker e o servidor front-end da Web.

  2. Obtenha o código mais recente da tag de lançamento.

    git fetch --tags
git checkout 1.14.1

  3. Atualize as dependências do Python.

    cd api
uv sync

  4. Execute o script de migração.

    uv run flask db upgrade

  5. Reinicie o servidor API, o Worker e o servidor front-end da Web.
