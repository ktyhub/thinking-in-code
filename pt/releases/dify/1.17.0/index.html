#difícil 1.17.0

Novos recursos

Agente: Sandbox E2B, Home Snapshots e Gerenciamento de habilidades

  • Backend de sandbox E2B: a execução de shell/código do agente agora pode ser executada em sandboxes de nuvem E2B, além da sandbox local. Selecione o backend com DIFY_AGENT_RUNTIME_BACKEND; um novo docker-compose.e2b.yaml envia a pilha E2B, o tráfego E2B é autenticado e o modelo E2B é sincronizado no lançamento (#39480, #39705, #39873, #39996, #40858, #40871, #40891, #40892).
  • Instantâneos iniciais em tempo de compilação: quando uma compilação de agente é aplicada (publicada), o diretório inicial da sandbox do agente — pacotes instalados, arquivos preparados, estado de funcionamento — é capturado e as execuções subsequentes do agente publicado restauram seu diretório inicial a partir desse instantâneo, para que o agente inicie a partir do estado exato do sistema de arquivos que tinha no momento da compilação. (#39702, #40876, #40996).
  • Gerenciamento de habilidades no nível do espaço de trabalho: as habilidades são recursos reutilizáveis ​​e versionados, empacotados com definições de código e ferramentas que os agentes podem descobrir e invocar. Um novo gerenciador de habilidades no nível do espaço de trabalho com rascunho → publicação → ciclo de vida da versão é fornecido junto com uma UI da web (lista de habilidades, painel do construtor, editor de arquivos). (#39675, #39798, #39799, #41180).
  • Compactação do histórico com reconhecimento de contexto: longas conversas entre agentes não ultrapassam mais a janela de contexto do modelo — o Dify resolve a compactação efetiva da janela e das camadas de cada modelo (limpa primeiro os resultados da ferramenta antiga e depois resume o histórico mais antigo) para que as execuções permaneçam dentro do orçamento sem perder o contexto recente (#40872).

Variáveis de ambiente LLM reutilizáveis em fluxos de trabalho

  • Defina uma configuração compartilhada de provedor/modelo/modo/parâmetro uma vez (por exemplo, for_summarize, for_research) e referencie-a a partir de qualquer nó LLM. As mudanças coordenadas no modelo agora acontecem em um só lugar, em vez de ficarem à deriva nó por nó, e as referências sobrevivem à importação/exportação DSL, snippets, pipelines RAG e edição colaborativa (#39125).

Entrada Humana em Loops e Iterações

  • Os formulários Human-in-the-loop agora funcionam dentro dos nós de Loop e Iteração, pausando e retomando corretamente nas atualizações de página para aplicativos de depuração e instalados, permitindo etapas de revisão/aprovação em trabalhos repetidos (#39243).

Rastreamento unificado neutro em relação ao provedor

  • O rastreamento unificado opcional (OPS_TRACE_UNIFIED_ENABLED) monta a árvore de extensão pai-filho completa (fluxos de trabalho, fluxos de chat, mensagens, nós, loops, iterações, fluxos de trabalho aninhados) uma vez no núcleo e delega apenas o transporte para adaptadores leves. Os adaptadores Phoenix e LangSmith são enviados primeiro; desativado por padrão e totalmente compatível com versões anteriores (#39451).
  • O novo GenAI abrange LLM TTFT de superfície, etapas ReAct do agente, chamadas de ferramentas e nós LLM com falha para uma observabilidade mais profunda (#39339).

Suporte à catraca Cloudflare (CAPTCHA)

  • Desafio Turnstile opcional no login e login com código de e-mail para proteger os endpoints de autenticação contra abuso, com chaves secretas/site configuráveis e nomes de host permitidos (#40494).

Azure Key Vault/KMS conectável

  • Introduz uma abstração de provedor KMS com suporte do Azure Key Vault para provisionamento, criptografia e descriptografia de chaves, além de configuração de rotação de chaves — um passo em direção a chaves de criptografia gerenciadas externamente (#39933).

Pesquisa híbrida e de texto completo de vetor TiDB

  • As implantações do TiDB Vector agora podem permitir a recuperação híbrida e de texto completo (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH, padrão desativado), usando um índice de texto completo multilíngue junto com a pesquisa vetorial (#38112).

Modelo mais amplo e tratamento de arquivos

  • Os nós e agentes do LLM agora podem passar arquivos de imagem diretamente para modelos multimodais, e os anexos não visuais não são mais descartados silenciosamente dos bate-papos dos agentes (#39848, #40179).
  • Nova orientação de recuperação multimodal ajuda os usuários a escolher modelos de incorporação corretamente para bases de conhecimento com imagens (#40566).
  • Audio ASR agora aceita audio/x-m4a e os tipos MIME de áudio são validados com mais precisão (#40776, #41043).

Vá para qualquer coisa (⌘K / Ctrl+K)

  • Pressione ⌘K (Ctrl+K no Windows/Linux) em qualquer lugar do console para abrir a paleta de comandos e acessar aplicativos, agentes, habilidades, bases de conhecimento, plug-ins ou nós de fluxo de trabalho, ou acionar ações rápidas por meio de comandos de barra. Novidade nesta versão: agentes e habilidades podem ser pesquisados, e o sistema de comando de ícones foi refatorado em todos os domínios para consistência (#40620, #40621, #40646–#40649, #41160).

Outras adições

  • Suporte para extração de documentos ODT (OpenDocument Text) (#39973).
  • Novo tipo de parâmetro date / date-picker para plugins de ferramentas (#36163).
  • Suporte ao idioma Lao (lo-LA) (#39474).
  • Tarefa de limpeza automática para conversas antigas (ENABLE_CONVERSATION_CLEANUP_TASK) para limitar o crescimento de dados (#40889-era).
  • Marketplace incorporado diretamente em categorias de integração para descoberta mais fácil de ferramentas/plugins (#40744).

Melhorias

Acessibilidade (passe grande a11y)

  • Um conjunto muito grande de mudanças torna o teclado do console amigável ao leitor de tela: semântica real do <button> para dezenas de controles interativos, nomes acessíveis para ações somente de ícones (copiar, fechar, excluir, menus), títulos primários em páginas de autenticação/instalação, seletores de membros/ferramentas acessíveis pelo teclado e estados ARIA corretos (#40192–#40377 e muitos outros).

Autoria de fluxo de trabalho

  • O gerador de fluxo de trabalho agora prefere ferramentas já instaladas e configuradas ao sugerir nós, para que os construtores busquem as ferramentas que realmente possuem (#40611, #39850).

Fluxo de trabalho e estabilidade de tempo de execução

  • Execuções de fluxo de trabalho da Web reproduzíveis, estado de tela preservado após atualizações de histórico, sem mais loops de renderização de atualização e fluxos SSE agora terminam de forma limpa em eventos de terminal (#40010, #40489, #41105, #40042).
  • stop agora é honrado entre nós sem streaming e fluxos de trabalho pausados, limpando sinais de cancelamento obsoletos corretamente (#41090, #40905, #40972).
  • Padrões APP_MAX_EXECUTION_TIME e WORKFLOW_MAX_EXECUTION_TIME aumentados de 1200s → 3600s para acomodar fluxos de trabalho de execução mais longa.

Qualidade Interna

  • Grande migração de testes unitários para modelos ORM reais/sessões SQLite para uma cobertura mais confiável, além de digitação mais forte em testes migrados (muitos #38xxx–#39xxx). Nenhuma mudança de comportamento voltada para o usuário.

Melhorias de segurança

  • Reforço de autenticação: desafio de catraca em fluxos de login/código de e-mail, verificação reforçada de código de e-mail com limites de tentativa e expiração de token (EMAIL_CODE_LOGIN_MAX_ATTEMPTS, EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES), manipulação de domínio de e-mail suspenso e tokens de autorização de agente de curta duração (#40494, #40960, #41004, #40884).
  • Escopo de controle de acesso/propriedade: conjunto de dados, documento, RAG, conversação, credencial de espaço de trabalho e recursos OAuth-client agora estão consistentemente vinculados a seus proprietários e escopo de aplicativo, fechando vários caminhos de acesso não autorizado (#40989, #40888, #40790, #40745, #40893, #40786 e relacionados).
  • SSRF e proteção de saída: as fases de conexão HTTP de saída são limitadas (5s), os tempos limite de download e execução do agente/ligação são configuráveis ​​e a mensagem de erro bloqueada por SSRF agora aponta para o problema correto (#40807, #41027, #40605).

Guia de atualização

Migração de tipo de modelo

[!IMPORTANTE]

Migração única de tipo de modelo legado para atualizações auto-hospedadas

Se esta implantação foi atualizada de uma versão Dify anterior a 1.15.0 e esta migração ainda não foi aplicada, execute-a após a atualização.

Esta migração não está incluída no flask db upgrade. Sem ele, os registros do modelo legado podem fazer com que as solicitações API relacionadas ao modelo falhem com erros, impedindo que os modelos afetados sejam carregados ou usados.

Faça backup do banco de dados antes de aplicar a migração. O comando é executado no modo de teste por padrão; revise a saída antes de executá-la novamente com --apply. A migração é idempotente e pode ser executada novamente com segurança.

Docker Compor

Execute a partir do diretório docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implantação do código-fonte

Execute a partir da raiz do repositório após concluir flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Depois de aplicar a migração, execute o comando de simulação novamente. Se não reportar atualizações ou exclusões de linha adicionais, reinicie os serviços relevantes e verifique se os modelos existentes podem ser carregados e invocados com sucesso.

[!IMPORTANTE]

  • Esta versão inclui novas migrações de banco de dados — execute-as como parte da atualização.
  • Variáveis ​​de ambiente alteradas substancialmente (muitas adicionadas, variável de edição renomeada EDITION → DEPLOYMENT_EDITION, vários padrões alterados). Revise a seção Mudanças nas variáveis ​​​​de ambiente e atualize seu .env de acordo. Em particular, renomeie EDITION para DEPLOYMENT_EDITION se você configurá-lo.
  • A configuração do Docker Compose foi alterada e um novo docker-compose.e2b.yaml foi adicionado. Se você mantiver um docker-compose.yaml personalizado, reaplique as personalizações locais com cuidado.
  • A migração add_conversation_cleanup_index cria índice nos dados existentes, o que pode demorar mais para ser executado se a tabela conversations for grande.
