#difícil 1.16.0

Apresentando o Dify Agent (Beta): uma nova experiência de agente no Dify

[!AVISO] Você deve fornecer serviços de Agente Dify ⚠️apenas para trusted, usuários não maliciosos⚠️.

Como muitos de vocês sabem, o paradigma do agente LLM baseado em shell trouxe um grande salto nas capacidades dos agentes e mudou a forma como pensamos sobre os agentes. Enquanto isso, as Skills fornecem uma maneira padronizada de empacotar e distribuir recursos, facilitando a construção de agentes poderosos.

Hoje estamos lançando o Dify Agent. Como outros agentes líderes, ele é executado em uma sandbox Linux. Esta versão inclui:

  • Um construtor para criar Agentes Dify

    • Você pode construir Agentes Dify por meio da IU: definir um prompt base, fazer upload de habilidades e arquivos e conectar ferramentas e conhecimento do ecossistema Dify.
    • Também fornecemos um agente que ajuda você a construir Agentes Dify. Por meio de conversação, ele pode configurar o ambiente sandbox Linux, instalar os pacotes necessários e criar novas habilidades e arquivos que seu agente Dify pode usar posteriormente.

  • Integração do Dify Workflow para o Dify Agent

    • Você pode usar um Dify Agent existente em um fluxo de trabalho Dify ou criar temporariamente um Dify Agent inline. Ele executará a tarefa definida pelo nó do fluxo de trabalho, gerará a saída necessária e a passará para o próximo nó.

  • Uma nova experiência de aplicativo da web

    • O Dify Agent que você cria pode ser publicado e usado como um aplicativo da web. Embora a experiência do usuário permaneça familiar, agora ela é desenvolvida pelo Dify Agent.

Documentos: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

⚠️ Ação necessária

Aviso de compatibilidade OpenAI GPT-5.6

O plug-in OpenAI anteriormente usava como padrão o Chat Completions API, que foi descontinuado pela OpenAI no início deste ano e tem suporte cada vez mais fraco para séries de modelos mais recentes. A família GPT-5.6 recém-lançada tem muitas restrições incomuns e exclusivas de combinação de parâmetros quando usada com completações de bate-papo, porque o OpenAI agora fornece apenas suporte mínimo de compatibilidade para conclusões de bate-papo com novos modelos. Este não é um problema do sistema Dify.

O tipo API padrão para novas configurações foi alterado de Conclusões de bate-papo para Respostas. No entanto, os usuários que salvaram anteriormente uma chave API personalizada com o padrão antigo (conclusões de bate-papo) manterão essa configuração, o que pode causar erros inesperados que parecem ter origem no Dify.

Se você configurou anteriormente uma chave OpenAI API personalizada, verifique a configuração do tipo API e mude para Respostas se ainda estiver definido para Conclusões de bate-papo, especialmente ao usar GPT-5.6 ou modelos posteriores.

Novos recursos

Aplicativo do agente (Beta aberto)

  • Agent App entra em versão beta aberta e agora está habilitado por padrão para todos os usuários. Ele apresenta uma sandbox integrada para execução de código e comandos shell, um sistema de habilidades que permite aos agentes chamar ferramentas e APIs, uma lista de agentes para gerenciar e reutilizar agentes em um espaço de trabalho e suporte para referenciar novos agentes a partir de nós de agentes de fluxo de trabalho.

Geração de fluxo de trabalho de IA mais inteligente

  • O gerador de fluxo de trabalho ⌘K → /create e /refine AI foi aprimorado de ponta a ponta: o campo de baixo valor "Saída ideal" foi removido, chips de exemplo estáticos foram substituídos por sugestões geradas por IA baseadas no contexto do seu espaço de trabalho e a geração de configuração de nó agora é paralelizada para resultados mais rápidos. Um tempo limite configurável (WORKFLOW_GENERATION_TIMEOUT_MS, padrão 180s) evita que gerações de longa duração sejam interrompidas. Atualização do protocolo MCP
  • O servidor de fluxo de trabalho como MCP agora suporta o protocolo MCP 2025-06-18 com negociação de versão e saída de ferramenta estruturada, enquanto permanece compatível com versões anteriores de clients mais antigos. As conexões MCPClient agora podem injetar cabeçalhos de solicitação HTTP dinâmicos em tempo de execução usando espaços reservados (por exemplo, {{request.headers.X-Custom-Auth}}), permitindo a passagem de autenticação por solicitação.

Personalização de aplicativos da Web

  • Os proprietários de aplicativos agora podem personalizar o texto do espaço reservado de entrada de bate-papo (até 64 caracteres) para aplicativos da web Chatbot, Agente e Chatflow. A UI de personalização foi refinada com nomenclatura mais clara ("Frontend personalizado"/"Branding") e melhor manuseio de rótulos. As descrições dos aplicativos agora são exibidas nas telas de bate-papo e de aplicativos de geração de texto com uma visualização recolhível para evitar empurrar o formulário de entrada para fora da tela.

Confiabilidade e operações do fluxo de trabalho

  • Os arquivos de execução do fluxo de trabalho agora podem ser exportados e as execuções ativas são abortadas corretamente durante o desligamento a quente do Celery para evitar tarefas órfãs. As conexões Redis são mais resilientes com suporte de manutenção de atividade TCP e cobertura expandida de novas tentativas. Os provedores de modelos agora recebem app_id para atribuição de custos do lado do provedor (por exemplo, Bedrock requestMetadata, metadados OpenAI, rótulos Vertex AI). Os fluxos de login OAuth e SSO agora preservam URLs de redirecionamento de forma mais confiável, com uma visualização de erro dedicada para conclusões de SSO com falha.

Guia de atualização

Migração de tipo de modelo

[!IMPORTANTE]

Migração única de tipo de modelo legado para atualizações auto-hospedadas

Se esta implantação foi atualizada de uma versão Dify anterior a 1.15.0 e esta migração ainda não foi aplicada, execute-a após a atualização.

Esta migração não está incluída no flask db upgrade. Sem ele, os registros do modelo legado podem fazer com que as solicitações API relacionadas ao modelo falhem com erros, impedindo que os modelos afetados sejam carregados ou usados.

Faça backup do banco de dados antes de aplicar a migração. O comando é executado no modo de teste por padrão; revise a saída antes de executá-la novamente com --apply. A migração é idempotente e pode ser executada novamente com segurança.

Docker Compor

Execute a partir do diretório docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implantação do código-fonte

Execute a partir da raiz do repositório após concluir flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Depois de aplicar a migração, execute o comando de simulação novamente. Se não reportar atualizações ou exclusões de linha adicionais, reinicie os serviços relevantes e verifique se os modelos existentes podem ser carregados e invocados com sucesso.
