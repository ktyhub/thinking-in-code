#rouxinol v9.1.0

O que mudou

  • talento: banco de dados de série temporal integrado - as métricas enviadas pelo Categraf são armazenadas localmente, portanto, nenhum Prometheus / VictoriaMetrics externo é necessário para começar; uma fonte de dados Prometheus chamada embedded-tsdb é registrada automaticamente na primeira inicialização. As configurações existentes são respeitadas: se alguma fonte de dados Prometheus habilitada já estiver presente, a fonte de dados não será criada automaticamente — as amostras ainda serão gravadas localmente e você poderá adicionar uma fonte de dados Prometheus apontando para o TSDB integrado para consultá-las (#3283)
  • façanha: importar fontes de dados de Grafana em um click, com um resumo de resultados por fonte de dados (#3295)
  • talento: reformulação da página da fonte de dados - depois de salvar uma fonte de dados, Nightingale a investiga com métricas sentinela para relatar quais modelos de regras de alerta/painel integrados já possuem dados e orienta você para sua primeira consulta (#3301)
  • talento: registros de avaliação de alerta por ciclo — cada avaliação de regra persiste o que foi consultado e como foi julgado no disco local do mecanismo de alerta, inspecionável em uma gaveta na página de regra de alerta (#3305)
  • façanha: as configurações do canal de notificação podem ser testadas e os modelos de mensagens visualizados antes de serem salvos (#3302)
  • feat: Assistente de coleta Categraf - um novo endpoint /agents/categraf/collect.sh serve o script do aplicador, com modelos de plugins e verificação de métricas no console (#3286)
  • talento: o pipeline de eventos suporta eventos simulados em tentativa de execução, filtragem de intervalo de tempo em registros de execução, ativação/desativação de lote e uma nova alteração API (#3281, #3285)
  • talento: modelos de regras de alerta integrados em integrações bastante expandidos e revisados, com en_US i18n (#3282)
  • façanha: fontes de dados MySQL podem anexar parâmetros extras ao DSN (#3299)
  • façanha: fontes de dados Doris suportam doris.internal_addr para que o processo de borda alcance FE MySQL (#3298)
  • talento: lista de regras de alerta suporta filtragem por tipo de gatilho
  • façanha: a lista de eventos de alerta ativo mostra o valor no momento do acionamento, adiciona tags de três estados e lembra o painel de filtros, o intervalo de atualização automática e o intervalo de tempo entre as visitas
  • feat: log explorer adiciona um botão de consulta para Loki e VictoriaLogs, permite anexar um filtro de campo diretamente do visualizador de logs e suporta detalhamento BCE BLS
  • talento: o painel TableNG do painel suporta uma gaveta de detalhes de linha
  • talento: integração da página do host - pacote de monitoramento de host click, ação de alerta de teste e cartões de próximas etapas
  • façanha: o proxy da fonte de dados e o acesso à consulta de log agora são gravados no log de auditoria com o usuário e a carga útil
  • talento: a borda tenta novamente a persistência do evento para o centro, com um tempo limite por solicitação reduzido
  • talento: novo API para verificar se alguma notificação foi entregue com sucesso (#3300)
  • perf: acelera as consultas de registro de notificação e a limpeza diária, apoiado por dois novos índices notification_record criados online na inicialização (#3311)
  • correção: copie profundamente os eventos antes de enviá-los para a fila, para que um evento de recuperação não substitua mais um evento de gatilho ainda não consumido no local
  • correção: uma configuração em branco do aplicativo DingTalk não interrompe mais as notificações do robô do grupo (#3309)
  • correção: fixar tipos de colunas explícitas nos modelos ai_* para impedir o desvio do esquema AutoMigrate, que estava falhando na migração dessas tabelas
  • correção: suporte max_completion_tokens para modelos OpenAI mais recentes (#3306)
  • correção: proteja nomes de rótulos inválidos na regra de alerta event_relabel_config (#3287, #3296)
  • correção: aceitar conteúdo YAML para coletar cargas úteis integradas (#3307)
  • correção: permitir o salvamento forçado de uma fonte de dados que falhou na verificação de integridade (#3304)
  • correção: teste a fonte de dados padrão global em relação à lista completa de fontes de dados antes da filtragem do cluster por mecanismo, para que uma fonte de dados padrão pertencente a outro cluster não seja mais limpa
  • correção: unidades de regras de alerta corretas
  • correção: reparar o frontmatter da habilidade integrada YAML e expor ferramentas de pesquisa de código no chat
  • correção: dê à migração da tabela assíncrona sua própria sessão gorm, para que uma instrução com falha não envenene mais o resto

Novo recurso V9

  • talento: Apresentar Nightingale AI - assistente de IA integrado, mercado de habilidades, gerenciamento de configuração LLM, com recomendações imediatas específicas de página
  • talento: banco de dados de série temporal integrado - funciona imediatamente, não é necessário Prometheus / VictoriaMetrics externo para configurações de pequena escala
  • talento: menu de navegação redesenhado, layout global e interface de tabela
  • talento: gerenciamento de canal de notificação refatorado
  • talento: Nova página de rastreamento de execução de pipeline de evento com visualização detalhada da execução

Nota de atualização ⚠️

  • O novo assistente de IA depende de fluxos Redis, portanto, Redis 5.0 ou posterior é necessário (Redis 7.0+ recomendado para usuários de cluster para ativar o Pub/Sub fragmentado).
  • Os registros de avaliação de alerta estão ativados por padrão. O mecanismo de alerta os grava em seu disco local em ./evallog, retidos por 8 dias e limitados a 20 GB. Sintonize ou desligue com a seção [Alert.EvalLog] - veja o novo etc/config.toml.
  • O TSDB integrado não é habilitado por uma atualização binária local: [EmbeddedTSDB] só existe no novo etc/config.toml, portanto, um arquivo de configuração transportado de uma versão anterior o deixa desativado. Copie a seção para habilitá-la. Ele é tratado apenas pelo processo central (n9e-edge / n9e-alert / n9e-pushgw ignore-o) e armazena dados no disco local dessa instância central, portanto, cabe em implantações de instância única - com várias réplicas centrais, use um TSDB externo.
