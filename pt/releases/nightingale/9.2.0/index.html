nightingale v9.2.0

#rouxinol v9.2.0

O que mudou

  • talento: canais de notificação nativos Jira, Discord, JSM Alert, Slack e Mattermost (#3408) e configurações de canal de notificação podem referenciar variáveis de usuário (#3349)
  • façanha: os painéis do painel podem misturar fontes de dados - cada destino de consulta carrega sua própria fonte de dados, apoiada por uma nova consulta em lote de várias fontes de dados v2 API com suporte KQL (#3292)
  • talento: links de compartilhamento de painel anônimos e por tempo limitado, além de uma visualização em tela cheia somente leitura com opções de URL para ocultar o cabeçalho e as variáveis (#3345)
  • talento: importação do painel Grafana reescrita - um relatório de conversão mostra o que foi migrado e o que não é compatível antes de salvar
  • façanha: variáveis de consulta do painel suportam opções de rótulo/valor e macros de tempo Doris SQL; painéis Grafana (iframe) integrados sincronizam o intervalo de tempo e o intervalo de atualização
  • talento: contas de usuários podem ser desabilitadas e reativadas sem perder suas funções, equipes e permissões (#3395)
  • façanha: o login OAuth2 pode atribuir equipes padrão a novos usuários (#3406) e /login?sso=xxx redireciona diretamente para o provedor de SSO fornecido
  • façanha: o conteúdo integrado suporta idiomas arbitrários; ja / ru / pt-BR / es / id / ko / fr adicionado no backend e pt-BR / es / id / ko / fr adicionado ao console (#3352)
  • talento: nomes de gravidade de alerta personalizados, visualização ao vivo em tela cheia para eventos de alerta ativos e filtragem de eventos históricos de alerta por hash (#3392)
  • talento: uma página agregada da Nightingale AI com conversas renomeáveis e compartilháveis (#3325); o assistente de IA pode despachar tarefas de script através do ibex (#3378)
  • talento: guia de integração do centro de integração (modelo de coleta → painel → regra de alerta); nova integração x509_cert, modelo de coleta RabbitMQ_Exporter e regras de alerta de integridade do dispositivo SNMP (#3394, #3348)
  • façanha: 403 respostas são renderizadas no local em vez de redirecionar para /403, então a URL sobrevive e voltar funciona
  • talento: entrada de login de demonstração sem senha para sites de demonstração públicos, desativado por padrão (#3426) - consulte Notas
  • desempenho: o bate-papo AI renderiza a redução de forma incremental e a amplificação de gravação do armazenamento de tarefas A2A é cortada em aproximadamente 30x (#3413)
  • segurança: fechar um desvio de proteção SSRF por meio de endereços IPv6 locais 6to4 / NAT64 / site (#3364), redigir credenciais incorporadas em URLs de fonte de dados (#3424), validar nomes de banco de dados/tabelas TDengine (#3423), restringir o escopo do token de compartilhamento do painel (#3368) e atualizar dependências vulneráveis (#3419, #3422)
  • correção: a inicialização da chave de configuração agora converge entre as instâncias, corrigindo um loop 401/login em implantações de múltiplas instâncias (#3385)
  • correção: um padrão cron de regra não programável não trava mais n9e / n9e-edge / n9e-alert em cada reinicialização e os padrões cron são validados ao salvar (#3407)
  • correção: silenciamentos de alerta que ainda não estão ativos agora são sincronizados no cache do mecanismo (#3386) e tags de silenciamento vazias são normalizadas (#3425)
  • correção: preencha o tempo de recuperação antes de enviar eventos de alerta (#3382)
  • correção: canais de retorno de chamada podem notificar sem um modelo de mensagem (#3350)
  • correção: fontes de dados desativadas ainda podem ser consultadas e são mantidas fora dos destinos de gravação
  • correção: uma linha VictoriaLogs superdimensionada não falha mais em toda a consulta (#3344)
  • correção: fontes de dados PostgreSQL usam o banco de dados configurado ao inicializar o client (#3367)

destaques da v9

  • Apresentando Nightingale AI: um assistente de IA integrado, um mercado de habilidades, gerenciamento de configuração LLM e recomendações imediatas com reconhecimento de página
  • Um banco de dados de série temporal integrado que funciona imediatamente, de modo que configurações de pequena escala não precisam mais de um Prometheus / VictoriaMetrics separado
  • Menu de navegação redesenhado, layout global e UI de tabela
  • Formulários de regra de alerta / regra de silenciamento / regra de assinatura / regra de notificação totalmente reconstruídos
  • Gerenciamento de canal de notificação reformulado
  • Uma nova página de rastreamento de execução do pipeline de eventos que mostra o processamento em detalhes
  • Uma nova geração de explorador de logs com suporte unificado para Elasticsearch, Loki e VictoriaLogs

Etapas de atualização

Substitua o binário e o diretório integrations e reinicie. Para obter as novas descrições de métricas nos idiomas adicionados, substitua também etc/metrics.yaml.

Mudanças de esquema (pule isso se sua conta de banco de dados puder criar tabelas)

Nightingale aplica isso para você na inicialização. Se a conta de banco de dados com a qual Nightingale se conecta não puder alterar as tabelas, execute-as manualmente - o DDL está em https://github.com/ccfos/nightingale/blob/main/docker/migratesql/migrate.sql

ALTER TABLE `source_token` ADD COLUMN `note` varchar(255) NOT NULL DEFAULT '' COMMENT 'note';
ALTER TABLE `source_token` ADD KEY `idx_source_token_token` (`token`);
ALTER TABLE `users` ADD COLUMN `disabled` int NOT NULL DEFAULT 0 COMMENT '0:enabled 1:disabled';

PostgreSQL:

ALTER TABLE source_token ADD COLUMN note varchar(255) NOT NULL DEFAULT '';
CREATE INDEX idx_source_token_token ON source_token (token);
ALTER TABLE users ADD COLUMN disabled int NOT NULL DEFAULT 0;

Notas

  • O novo assistente de IA depende de Redis Streams, portanto, Redis 5.0 ou posterior é necessário (Redis 7.0+ recomendado para usuários de cluster, para ativar Pub/Sub fragmentado)
  • Substituir apenas o binário não habilita o TSDB integrado: a seção [EmbeddedTSDB] existe apenas no novo etc/config.toml, portanto, carregar um arquivo de configuração antigo deixa o recurso desativado - copie a seção para você mesmo. Ele é tratado apenas pelo processo central (n9e-edge / n9e-alert / n9e-pushgw ignore-o e registre um aviso) e os dados residem no disco local dessa instância central, portanto, são adequados apenas para implantações de instância única; com várias réplicas centrais, use um TSDB externo
  • os usuários do telegraf precisam anexar ignore_host=false ao endereço de gravação das métricas, caso contrário, os hosts que executam o telegraf não serão mais registrados na lista de hosts
  • Se você executar n9e-edge ou n9e-pushgw, atualize-os junto com n9e
