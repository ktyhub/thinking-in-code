claude-code v2.1.305

código claude v2.1.305

O que mudou

  • Adicionado sandbox.allowNestedUserNamespaces para que comandos em sandbox no Linux possam criar namespaces de usuário (Chromium, podman sem root); isso permite que eles contornem as proteções de arquivos da sandbox
  • Adicionado CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS para que o modo de nova tentativa autônoma (CLAUDE_CODE_RETRY_WATCHDOG) perceba um limite de uso que foi suspenso antes de sua redefinição
  • Corrigidas todas as solicitações que falhavam no Vertex, Bedrock e outros provedores quando o endpoint ou gateway rejeitava a pesquisa de ferramenta e atrás de gateways com ToolSearch não permitido ou deixado de fora do --tools (uma regressão 2.1.304): Claude Code agora tenta novamente sem ele
  • Correção das configurações de /effort e /autocompact que não se aplicavam quando o nome do modelo diferia de um valor modelOverrides por letras maiúsculas ou uma tag [1m]
  • Novas árvores de trabalho corrigidas em um repositório vazio, às vezes começando no HEAD local em vez da ramificação padrão, e árvores de trabalho de subagentes inalteradas às vezes não sendo limpas
  • Correção de comandos Bash em um disco cheio falhando com um caminho de arquivo ENOSPC bruto: o erro agora diz que o disco está cheio e que nada foi executado
  • Corrigido um servidor MCP passado por uma sessão de nuvem ou pelo setMcpServers do SDK sendo substituído posteriormente na sessão por um servidor com o mesmo nome a partir de suas próprias configurações
  • Corrigido Claude nomeando o modelo errado para o trabalho de um subagente depois que o subagente mudou para um modelo substituto
  • Correção de sessões na nuvem e colegas de equipe que não informavam ao Claude quando uma compactação precisava deixar as mensagens mais antigas fora do resumo para caber
  • Foram corrigidos mais casos de sessões agendadas na nuvem do Cowork que aguardavam cinco minutos para cada subagente cujo WebFetch precisava de uma aprovação de URL que ninguém estava lá para dar
  • Correção do fluxo de trabalho que reinicia a execução de agentes pipeline() e parallel() já concluídos em vez de atendê-los a partir do diário de execução
  • Corrigido controle remoto deixando entradas "(sessão)" vazias em /resume após trocar conversas com /resume
  • Corrigidas linhas /usage sendo cortadas em terminais estreitos
  • Corrigida a impressão de avisos de inicialização como texto bruto acima do logotipo: eles agora vão para o log de depuração e as regras de permissão que não restringem nada são exibidas como linhas de aviso sob o banner
  • Modo de leitor de tela corrigido: as caixas de pesquisa agora dizem "Pesquisar:" em vez de um símbolo O VoiceOver é lido como "gravador de telefone" e o texto de prompt destacado, como correspondências de pesquisa Ctrl + R e "ultrathink", não possui mais espaços dentro das palavras
  • Executor auto-hospedado: Corrigido um script de início que compartilha apenas seu stdout com o executor ou orquestrador falhando com Resource temporarily unavailable quando TERM está definido (uma regressão 2.1.300)
  • Executor auto-hospedado: Corrigida falha no acesso ao repositório desde 2.1.296 quando um auxiliar de credencial git ou programa askpass lê suas configurações por meio de GIT_CONFIG
  • Executor auto-hospedado: corrigido o orquestrador que relatava um gancho do spawn-runner como tendo expirado quando um executor iniciado em segundo plano mantinha sua saída aberta
  • /usage aprimorado: cada aviso agora é uma correção de uma linha que nomeia sua fonte e f aplica as correções; as mesmas correções aparecem no VS Code e /doctor
  • Diálogos de consentimento do MCP aprimorados para que um Enter destinado ao prompt seja menos provável de ser considerado como Aceitar
  • Melhorado o Image de um mod para desenhar sua imagem no iTerm2 3.5 e posteriormente com renderização em tela cheia, onde mostrava apenas seu texto alt
  • Controle remoto: Melhoradas as mensagens do modo spawn: pressionar w agora diz que o novo modo está salvo para a pasta, e uma inicialização posterior do claude remote-control que usa o modo salvo diz de onde ele veio
  • allowedMcpServers alterado para parar de filtrar servidores stdio managed-mcp.json que usam ${VAR} apenas em env: uma lista de permissões deixada de fora agora carrega na atualização; use deniedMcpServers para mantê-lo desligado
  • Plugins alterados que Claude Desktop monta por caminho para não manterem mais seu allowed-tools quando as configurações gerenciadas da sua organização definirem allowManagedPermissionRulesOnly
  • Alterada a confirmação de exclusão do /artifacts para pegar 1 ou Enter para manter, 2 para excluir e Esc para cancelar; y e n não atendem mais
  • Alterado o painel encaixado de um mod para ficar dentro de 45% da largura do terminal, incluindo uma largura mantida em um terminal mais largo
  • [VSCode] Adicionado um status giratório "Executando ganchos de inicialização", com um anúncio de leitor de tela, enquanto os ganchos SessionStart ou Setup são executados
  • [VSCode] Corrigido o botão giratório cortando "Compactação..." quando a configuração do spinnerVerbs substitui os verbos integrados por verbos curtos
  • [VSCode] Alterada a mensagem mostrada quando uma sessão não inicia a tempo e nenhum gancho está em execução: agora ele leva aos logs de saída e lista as causas, em vez de apontar primeiro para o login e a rede
  • [Sessões de nuvem] Corrigida a página de administração de ambientes de nuvem que se recusava erroneamente a salvar um ambiente existente com um erro de "instala pacotes"
  • [Sessões na nuvem] Melhor exclusão de um ambiente auto-hospedado para que a caixa de diálogo e as mensagens de erro digam o que bloqueia a exclusão e o que isso afetará
  • [Claude Tag] Adicionados canais públicos do Slack Claude não se juntou ao administrador da Claude Tag Adicionar pesquisa de local, para que os administradores possam configurar uma a partir daí
  • [Claude Tag] Corrigidos pacotes de acesso à Claude Tag para que um repositório que foi movido para outra conta GitHub possa ser adicionado novamente
  • [Claude Tag] Corrigida uma rotina configurada em um tópico do Slack DM que não postava mais após outra rotina naquele tópico reiniciar a conversa; os dois agora continuam postando lá
  • [Claude Tag] Corrigidas rotinas configuradas em um tópico do Slack reportando sucesso sem postar após o término da conversa; essas execuções agora são ignoradas e o criador é informado
  • [Claude Tag] Páginas de administração do Claude Tag aprimoradas em grandes organizações para que as edições de plug-ins, habilidades e pacotes funcionem enquanto a lista de canais ainda está carregando
  • [Revisão de código] Corrigida a revisão de código que às vezes não revisava o commit mais recente quando vários push aconteciam em uma solicitação pull durante uma revisão
  • [Revisão de código] Reavaliações de revisão de código alteradas para que não abram mais com LGTM enquanto as descobertas de bloqueio anteriores ainda estiverem abertas
