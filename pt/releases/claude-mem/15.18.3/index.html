#claude-mem v15.18.3

Correções críticas

  • Codex continua gravando após atualizações de claude-mem (#6058, obrigado @wiesenthal). O Codex aprova um gancho que vem dentro de um plugin contra uma impressão digital de toda a pasta do plugin. Cada atualização do claude-mem reescreve essa pasta, portanto, após cada atualização, o Codex desativa todos os sete ganchos do claude-mem ("conteúdo do plug-in alterado; aprovação do gancho necessária") e as sessões do Codex param de ser salvas, sem nenhuma mensagem. O instalador agora registra os ganchos Codex de claude-mem em seu próprio ~/.codex/hooks.json, e cada gancho executa o inicializador on-PATH claude-mem, que encontra a instalação mais recente por si só. O Codex trusts é um gancho no hooks.json por sua própria definição e posição, portanto, uma aprovação agora dura entre as atualizações. Os ganchos de outras ferramentas nesse arquivo são mantidos, uma segunda instalação não muda nada, um hooks.json que não pode ser analisado é recusado e deixado intocado, e a desinstalação remove apenas as entradas de claude-mem. Desligar o plugin claude-mem no Codex ainda interrompe a captura. npx claude-mem doctor tem uma nova linha Codex hooks que avisa quando o plugin está ativado, mas seus ganchos estão faltando no hooks.json.

    Usuários do Codex: façam isso uma vez após a atualização.

    1. Execute npx claude-mem install e selecione Codex. npx claude-mem update e a atualização automática não movem os ganchos, porque os instaladores mais antigos não salvaram nenhuma seleção de agente. O instalador imprime Registered 7 claude-mem hooks in <codex home>/hooks.json.
    2. Abra o Codex interativo, execute /hooks e aprove os sete ganchos claude-mem. codex exec não pode pedir aprovação, então faça isso primeiro no Codex interativo.

    Depois disso, as atualizações não precisam de nova aprovação. O Codex pergunta novamente apenas quando a definição de um gancho claude-mem muda, quando claude-mem adiciona um gancho ou quando o gancho de outra ferramenta listado antes do de claude-mem é removido.

Melhorias

  • Token API local opcional para o trabalhador API e transporte HTTP MCP (#6056, obrigado @kartik70, fecha #5141). Isto é para máquinas com mais de um usuário de sistema operacional. Está desativado por padrão e nada muda a menos que você o configure. Configure CLAUDE_MEM_LOCAL_API_TOKEN em ~/.claude-mem/settings.json e reinicie o trabalhador e o servidor HTTP MCP. Depois disso, o trabalhador API e o transporte HTTP MCP recusam qualquer solicitação que não contenha o token (X-Claude-Mem-Token ou Authorization: Bearer), exceto os health checks. Abra o visualizador como /?token=... ou /viewer?token=.... O token só pode ser definido no arquivo: as configurações do API não podem ser definidas ou apagadas e ele fica mascarado quando lido. omp, hermes e openclaw ainda não enviam o token. Consulte "Token API local" nos documentos de configuração.
  • O aviso de reserva de cota nomeia ambos os provedores (#6071, obrigado @bulanovk). Quando o fallback de cota move o trabalho de memória para outro provedor, o log do trabalhador agora nomeia o provedor que você selecionou e aquele que realmente está fazendo o trabalho, informa quando o substituto gasta sua conta Antrópica e nomeia CLAUDE_MEM_QUOTA_FALLBACK_PROVIDER=off para desligá-lo. O substituto padrão permanece inalterado.
  • fluxo de trabalho n8n para salvar e encontrar memórias (#6066, obrigado @Kirat0201, fecha #5923). Um fluxo de trabalho n8n importável salva uma nota, verifica se o trabalhador confirmou o salvamento e, em seguida, pesquisa e recupera-a no projeto escolhido. Ele fica inativo até que você o execute e não adiciona captura automática. A configuração está na nova página de documentos do n8n.

Correções

  • leitura inteligente (obrigado @ Afloat16):
    • Getters e setters com o mesmo nome agora são desdobrados separadamente (#6060).
    • Os níveis de cabeçalho de redução são mantidos conforme estão escritos (#6064).
    • Os corpos da rotina Pascal são encontrados mesmo quando o caso da declaração é diferente (#6063).
  • As docstrings Python mantêm seus intervalos de instruções (#6057).
    • A fonte capturada é analisada em lotes nativos (#6059).
  • O analisador de observação aceita espaços em branco XML antes dos delimitadores de tags (#6065, obrigado @Afloat16).
  • As exclusões Globstar agora também se aplicam a caminhos que contêm terminadores de linha (#6061, obrigado @Afloat16).
  • Relatório de custos: vitórias em todo o repositório são pesquisadas somente quando solicitadas explicitamente (#6081), e relés de direção nomeados são reconhecidos (#6082) (obrigado @Kirat0201).
  • O guia de instalação lista os mínimos reais de Node.js e Bun (# 6076, obrigado @DeryFerd).

CI e testes

  • Os trabalhos de publicação e ods-native fixam Bun em vez de usar a versão mais recente (#6075), e o CI agora executa as verificações de hook-io e spawn-env (#6074) (obrigado @DeryFerd).
  • Correções de teste do Windows: novas tentativas de limpeza de temp-dir, caminhos de memória por plataforma e casos de gancho de pipe pausado ignorados onde o Node não pode executá-los (#6072, #6073, obrigado @DeryFerd). O stub de teste do sync-hub é digitado para que o pacote seja verificado (# 6077, obrigado @DeryFerd).
  • O teste de env-fallback #4689 não depende mais de um login real de Claude na máquina (#6068, obrigado @bulanovk).
