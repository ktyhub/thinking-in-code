#claude-mem v15.19.0

Continuar uma conversa sobre Claude Code ou Codex em Meu Trabalho

Abra uma solicitação em Meu Trabalho e, em seguida, abra "De onde veio". Em cada conversa do Claude Code ou do Codex agora há uma caixa de mensagem. Digite uma mensagem e pressione Enviar, e essa mesma conversa muda. A resposta aparece ali (#6191; as formas de comando seguem o código de resposta de @wiesenthal em #6054, e o commit dá crédito a ele).

  • Cada conversa mantém as mensagens que você enviou do Meu Trabalho e suas respostas, em ordem. Stop encerra uma curva de corrida.
  • A caixa indica em qual pasta o turno é executado. Quando a pasta gravada não existe mais (comum após a limpeza de uma árvore de trabalho), o turno é executado na pasta existente mais próxima acima dela.
  • "Copiar comando de continuação" copia claude --resume <id> ou codex resume <id>. Em um Mac, "Abrir no Claude" abre uma conversa do Claude Code no aplicativo de desktop Claude.
  • One Send inicia um currículo sem cabeça (claude --resume <id> -p --output-format json ou codex exec resume <id> - --skip-git-repo-check) com sua mensagem em stdin. Uma curva com falha é registrada como falha e nunca mais é tentada. Nada é colocado na fila ou salvo para reprodução e nada é iniciado na inicialização, em um cronômetro ou na reconexão.
  • Uma reinicialização ou desligamento do trabalhador interrompe primeiro cada turno de execução, de modo que um trabalhador reiniciado nunca se torna um segundo escritor na mesma conversa. Nada reenvia uma curva parada.
  • Uma curva é executada em seu próprio modo de permissão padrão, o mesmo que claude -p --resume usa em seu terminal. No modo Manual, as chamadas de ferramenta que necessitam de aprovação são negadas e a linha as conta. Nenhuma permissão, modelo ou sinalizador de sandbox é passado.
  • As novas rotas atendem apenas em loopback e recusam outras origens. Com o modo de token API local desativado, outro programa no mesmo computador pode chamá-los, assim como qualquer outra rota de trabalho. Em um computador compartilhado, ative o modo de token API local.
  • Uma alteração para cada solicitação: enquanto uma versão mais recente de uma solicitação aberta é carregada, a gaveta continua mostrando a versão que já possui em vez de "Carregando detalhes da solicitação…".

Limites conhecidos:

  • O caminho do Codex pela página não foi executado de ponta a ponta na máquina de teste. As curvas do Codex foram verificadas no nível do corredor com o CLI real.
  • No Windows, Stop pode não alcançar um CLI atrás de um calço .cmd e "Open in Claude" não é oferecido.
  • Uma conversa que está no meio do turno em um terminal ainda pode obter um turno em Meu Trabalho. Os documentos de Claude Code dizem que dois escritores em uma sessão podem perder mensagens. Meu trabalho bloqueia dois turnos próprios em uma conversa.
  • Uma falha de trabalho (não uma reinicialização normal) não pode interromper uma curva em execução. Termina sozinho.
  • Um auxiliar que o CLI deixa para trás, como um servidor MCP de saída lenta, mantém a curva marcada como em execução até que ela saia ou você pressione Parar.

Traga sua memória existente

npx claude-mem import busca memórias diretamente da plataforma Mem0 ou Supermemory e as salva como observações pesquisáveis em um projeto que você escolher. Nenhum arquivo de exportação e nenhuma chamada de modelo (#6106).

# MEM0_API_KEY in the environment
npx claude-mem import --from mem0 --source-account personal-mem0 --user my-user-id --project imported-memory

# SUPERMEMORY_API_KEY in the environment
npx claude-mem import --from supermemory --source-account personal-supermemory --namespace my_namespace --project imported-memory
  • Inicie o trabalhador primeiro (npx claude-mem start). Adicione --dry-run para buscar e verificar as contagens de origem e impressão sem escrever nada.
  • Cada página de origem é buscada e verificada antes de qualquer coisa ser escrita. As memórias Mem0 expiradas ou substituídas e as memórias Supermemória esquecidas ou antigas são ignoradas. Para Supermemória, --documents importa texto de documento extraído em vez de memórias.
  • As memórias importadas são arquivadas para Claude Code (claude), para que sua busca na memória as encontre. --platform <host> (por exemplo codex ou cursor) os arquiva em outro host. Cada observação mantém o registro de origem, ID, carimbos de data/hora, metadados, rótulo da conta e escopo.
  • Executar o mesmo comando novamente é seguro: os registros já salvos são contados como existentes. Não há trabalho em segundo plano nem nova tentativa automática.
  • Esta é uma importação unilateral, não uma sincronização. As edições na fonte fazem novas observações. As exclusões e expirações na origem não são transferidas.
  • Limites: 10.000 registros por padrão (--max-records até 100.000), 100 MiB de respostas de origem, prazo de solicitação de 15 segundos (--timeout-ms até 120.000) e 100.000 caracteres por registro. Nada é interrompido silenciosamente: um registro superdimensionado ou uma solicitação com falha interrompe a execução.
  • Os testes usam respostas sintéticas Mem0 e Supermemory, não contas ativas.

Documentos: https://docs.claude-mem.ai/usage/import-providers

Codex: threads bifurcadas ganham memória

  • Threads bifurcados do Codex começam com memória recuperada (#6101). Codex 0.165 adicionou um início de sessão fork para seus garfos de thread anexados experimentais. O gancho SessionStart de claude-mem não correspondeu, então um thread bifurcado começou sem memória. O gancho agora corresponde a fork.

    Usuários do Codex: aprovem um gancho novamente. O correspondente do gancho SessionStart foi alterado e o Codex solicita aprovação novamente sempre que a definição de um gancho muda.

    1. Coloque o novo matcher em ~/.codex/hooks.json. npx claude-mem update e atualização automática fazem isso quando sua última instalação selecionou Codex. Caso contrário, execute npx claude-mem install e selecione Codex.
    2. Abra o Codex interativo, execute /hooks e aprove o gancho SessionStart de claude-mem.

    Até que você aprove, as sessões do Codex começam sem memória recuperada. A captura continua funcionando. Até que o novo matcher esteja em hooks.json, npx claude-mem doctor mostra a linha Codex hooks como desatualizada.

Também novo

  • Tempo de execução do servidor: os resultados da pesquisa indicam qual agente criou uma memória (#6100). O tempo de execução do servidor agora armazena o agente em cada memória e o preenche com as memórias existentes de sua sessão. Suas linhas de pesquisa e detalhe MCP adicionam [via <agent>], por exemplo #8 — Auth redirect decision (myproject) [via cursor]. Memórias sem agente registrado não mostram nenhuma etiqueta. /api/sessions/observations não rotula mais cada client como Código Claude. Os resultados da observação do trabalhador local ainda não trazem o agente, portanto não mostram nenhuma etiqueta.
  • Zed (#6111, obrigado @AdityaxDeore, fecha #5900). npx claude-mem install (ou --ide zed) registra o servidor MCP de claude-mem no context_servers de Zed, para pesquisa, linha do tempo, detalhes e salvamentos explícitos. Os comentários no arquivo de configurações do Zed são mantidos. Não há captura automática, porque Zed não tem ganchos ou acesso à transcrição. Documentos: https://docs.claude-mem.ai/zed-integration
  • Aider (#6112, obrigado @AdityaxDeore, fecha #5893). Execute npx claude-mem aider install dentro de um projeto. Ele adiciona .claude-mem/aider-memory.md à lista read: em .aider.conf.yml e npx claude-mem aider sync atualiza esse arquivo do trabalhador. É opcional por projeto: npx claude-mem install não oferece isso, o arquivo de memória é mantido fora do git por meio de .git/info/exclude e se recusa a ser executado em sua pasta pessoal. Sem captura automática. Documentos: https://docs.claude-mem.ai/aider-integration
  • Grok Build obtém memória recuperada no início da sessão (#6180, obrigado @krishnadobhal, fecha #5950). O Grok Build ignora o que os ganchos SessionStart imprimem, portanto, as notas recuperadas nunca chegam ao modelo. claude-mem grok install grava .grok/rules/claude-mem-context.md na pasta atual, que o Grok Build carrega das pastas trusted. O trabalhador o atualiza após cada resumo da sessão, apenas nas pastas em que você o instalou. Um projeto excluído recebe uma linha "excluída" em vez de notas. A captura permanece inalterada. Documentos: https://docs.claude-mem.ai/grok-build
  • Francês no seletor de idioma para Meu Trabalho, visualizador, configuração inicial e TV de Observação (#6107, obrigado @QuantScorpus). Suas memórias, regras e citações permanecem como estão escritas.
  • Três novas predefinições para o provedor compatível com OpenAI. Cada padrão é um modelo pequeno e rápido, porque a extração de memória é de alto volume:
    • AtmoRouter, zai/glm-5.3-flash (#6108, obrigado @BeckleyTenriajeng)
    • TrustedRouter, deepseek/deepseek-v4-flash (#6174, obrigado @jperla). trustedrouter/auto permanece disponível como opção. Ele pode encaminhar uma solicitação para um modelo com preços de fronteira.
    • HopBase, deepseek-v4.1-flash (#6181, obrigado @victor-zzh)

Correções

Privacidade e segurança

  • A pasta de dados claude-mem é exclusiva do proprietário (#6091, obrigado @DeryFerd). No macOS e Linux, ~/.claude-mem (banco de dados, configurações, .env, spool de gancho, backups) foi criado com um mkdir simples, portanto, sob o 022 umask comum, outras contas na máquina poderiam lê-lo. Agora ele é criado como 0700, uma pasta existente é compactada na próxima inicialização e novas entradas do spool de gancho são gravadas como 0600.
  • MCP save_memory homenageia CLAUDE_MEM_EXCLUDED_PROJECTS (#6105, obrigado @Zhong-fan, relatado por @Kirat0201 em #6098; @0xABCD01 enviou a mesma correção em #6166). Um salvamento de um checkout excluído foi armazenado no MCP, enquanto o mesmo salvamento no HTTP foi ignorado. Ele foi ignorado agora e a resposta diz "Não salvo: este checkout foi excluído por CLAUDE_MEM_EXCLUDED_PROJECTS." em vez de "Memória salva #?: Sem título.". Os guias Cline e Kilo agora dizem isso (#6190).
  • Tempo de execução do servidor: o comando MCP connect recusa um Host inutilizável (#6176, obrigado @DeryFerd). Sem CLAUDE_MEM_PUBLIC_URL, GET /v1/connect e POST /v1/keys criaram o comando pronto para colar a partir do cabeçalho Host da solicitação e copiaram espaços em branco, aspas ou caminhos nele. Um valor que não pode ser um host agora obtém 400 InvalidHost e nenhuma chave é cunhada.
  • Hub de sincronização: FORWARD_ORIGIN deve usar https:// (#6175, obrigado @DeryFerd). O proxy de encaminhamento copia o cabeçalho Authorization de entrada para o destino, de modo que uma origem http:// simples possa enviá-lo sem TLS. http:// é permitido apenas para hosts de loopback. Um valor que não é um URL utilizável agora falha ruidosamente em vez de retornar silenciosamente ao caminho do Objeto Durável.

Instalar e desinstalar

  • A desinstalação remove os ganchos Gemini CLI (#6088, obrigado @tanishqbaweja). npx claude-mem uninstall excluiu o plugin, mas deixou os cinco ganchos Gemini CLI de claude-mem em ~/.gemini/settings.json, então Gemini CLI imprimiu uma mensagem de gancho com falha em cada início de sessão, prompt, chamada de ferramenta e final de turno. Desinstalar agora os remove e mantém suas próprias configurações e ganchos. Um settings.json com comentários permanece intacto, então remova esses ganchos manualmente.
  • Cancelar o prompt da tecla API não muda mais você para Claude (#6161, obrigado @bulanovk). Com --provider gemini ou --provider openrouter e nenhuma chave salva, o cancelamento do prompt da chave escreveu CLAUDE_MEM_PROVIDER='claude' e continuou. Agora para com um erro e não muda nada.
  • A verificação de configuração herdada do instalador do Codex expande um ~\ líder apenas no Windows, como o resto do claude-mem (# 6093, obrigado @DeryFerd).

Trabalhador e armazenamento

  • Um trabalhador que encontra um banco de dados ocupado na inicialização tenta novamente em vez de responder 503 por minutos (#6145, obrigado @montjeffrey, refs #3603). Um trabalhador substituto poderia acessar SQLITE_BUSY_SNAPSHOT uma vez durante a inicialização do banco de dados, nunca tentar novamente e responder a todas as solicitações com "Inicialização do serviço" até uma reinicialização manual (cerca de 11 minutos no relatório). A inicialização agora tenta novamente um erro de ocupado 3 vezes, após 1, 2 e 4 segundos. O pior caso (27 s) cabe dentro dos 30 s que o gancho espera que o trabalhador esteja pronto. Outros erros ainda falham imediatamente.
  • Fechar o banco de dados o libera (#6090, obrigado @DeryFerd). As instruções preparadas em cache mantiveram a conexão e o arquivo de banco de dados abertos após o fechamento. No Windows, isso bloqueou as trocas de restauração e a limpeza da pasta temporária com EPERM ou EBUSY.
  • A limpeza do Chroma para sessões excluídas sobrevive à saída do trabalhador (#6163, obrigado @Afloat16). Se o trabalhador saísse antes da execução da limpeza da fila, os vetores das linhas excluídas nunca seriam removidos. A limpeza agora é gravada antes de começar. A mesma mudança corrige uma verificação que tratava uma linha ausente como restaurada no Bun.
  • No Bun, um banco de dados cuja tabela de exclusões de inicialização de sincronização desapareceu, reconstrói-o em vez de manter uma lista vazia (#6189).
  • Um assinante /api/ready com falha não interrompe mais o progresso de inicialização dos outros ou se transforma em uma falha de inicialização (#6127, obrigado @Afloat16).

Notas de captura e memória

  • CLAUDE_MEM_SKIP_BASH_PATTERNS aplica-se ao Antigravidade CLI (#6096, obrigado @tanishqbaweja). agy relata sua ferramenta shell como run_command, que a verificação de padrão não leu, então os comandos excluídos foram armazenados e enviados ao observador.
  • Uma nota explícita contendo um caractere nulo poderia obter o ID de outra nota enquanto seu próprio texto não fosse salvo (#6170, obrigado @Kirat0201, fecha #6169).
  • Um arquivo de memória Claude Code cuja descrição ou metadata.type alterada é armazenada como uma nova revisão em vez de ser relatada como já importada (#6186, obrigado @Kirat0201, fecha #6171).
  • Notas de memória (obrigado @Afloat16):
    • O título de uma nota vem de seus títulos reais, não de um # comment dentro de um exemplo de código (#6156).
    • Os campos aninhados sob o metadata: de uma nota não substituem mais o próprio tipo ou sessão da nota, e um comentário YAML não encerra mais o bloco (#6157).
    • memory ingest --source ou --cwd sem valor para com erro de uso ao invés de importar o checkout atual (#6150).
    • A digitalização de uma transcrição novamente não insere mais uma curva importada duas vezes quando duas curvas próximas têm o mesmo texto (#6149).
    • Com CLAUDE_MEM_DEDUP_ENABLED=true, títulos que diferem apenas em caracteres de código (C++ e C#, src/config.ts e src config ts, números de versão) não são mais mesclados em uma linha, perdendo a segunda (#6120).
    • Observações importadas cujos fatos ou arquivos foram armazenados como uma string mostram-nos novamente na recuperação (#6134).

Pesquisa e contexto (obrigado @ Afloat16, salvo indicação em contrário)

  • A pesquisa semântica verifica as janelas de data nas linhas salvas, não na cópia do Chroma, portanto, uma linha atualizada no SQLite, mas ainda não no Chroma, chega à janela direita (#6153).
  • As pesquisas de arquivos ordenadas por data ignoram o Chroma, portanto, uma interrupção do Chroma ou uma incorporação lenta não falha mais (#6123).
  • O contexto do arquivo retorna as observações mais recentes quando vários compartilham um carimbo de data/hora (#6118).
  • O cache de contexto mantém o escopo de invalidação correto quando a renderização termina fora de ordem, portanto, uma gravação posterior em um projeto adotado o atualiza (#6164).
  • A pesquisa profunda fornece ao processo filho apenas o tempo realmente restante, portanto, uma etapa do relógio, como uma correção NTP, não causa mais um tempo limite vazio antecipado (# 6177, obrigado @DeryFerd).

Codex como provedor de memória (obrigado @Afloat16)

  • O limite do protocolo de 8 MiB se aplica a cada linha JSON, não a tudo que está armazenado em buffer, portanto a saída válida não é mais rejeitada (#6119).
  • Um tubo stdin fechado durante uma curva falha na curva limpa em vez de escaping como um erro não tratado (#6130).
  • Uma solicitação expirada não deixa mais um manipulador de aborto para trás que poderia falhar na próxima vez em um novo servidor de aplicativos (#6133).

Leitura inteligente de arquivo

  • smart_outline não marca mais declarações próximas a uma exportação na mesma linha que [exported] (#6141, obrigado @liuyinchu).
  • Agora indexados (obrigado @ Afloat16): funções, setas e classes anônimas export default (#6151), métodos de protocolo Swift e métodos Scala sem corpo (#6154) e declarações Java @interface e seus elementos (#6160).
  • A pesquisa inteligente de código lê cada arquivo por meio de um identificador e para no limite de 512 KiB, portanto, um arquivo substituído após a verificação de tamanho não pode ultrapassar o limite (# 6124, obrigado @Afloat16).

Meu Trabalho

  • A etapa de metas usa a linguagem da corrida (#6187, obrigado @0xABCD01, fecha #6185 relatado por @Fly-onlyone). A linha do idioma atingiu todas as etapas, exceto as metas, portanto, em # 6185, 147 instruções em inglês produziram metas em espanhol. Uma primeira corrida apenas com objetivos, sem idioma definido, ainda pode ser adivinhada. CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE define isso.
  • Também em Meu Trabalho (obrigado @Afloat16):
    • Uma resposta Jev cortada no meio do corpo conta como uma interrupção, não uma falha permanente para aquele item, então a próxima atualização pergunta novamente (#6158).
    • Um novo git init, um novo repositório aninhado ou um .git removido será selecionado na próxima vez que My Work trabalhar no projeto de uma sessão, em vez de apenas após a reinicialização do trabalhador (#6165).
    • A limpeza automática ignora leituras atrasadas de um turno ou conversa que já terminou (#6152).
    • As instruções do proprietário mantêm seu orçamento total de 3.000 caracteres quando contêm emojis e outros caracteres fora do plano básico (#6162).
    • O agente de corpus API opcional corresponde a palavras com sotaque, hindi, bengali e hebraico pontiagudo (#6168).
    • Os totais de uso do Gemini na configuração mantêm a contagem de tokens concluída quando a mesma resposta foi salva duas vezes (#6146).

Visualizador

  • Abrir uma janela do visualizador envia sua primeira lista de projetos e status apenas para essa janela, não para todos os visualizadores abertos (#6126, obrigado @Afloat16).
  • Cli clicar no botão de ações da sessão novamente fecha seu menu (#6143, obrigado @liuyinchu).

Outros

  • agent-cost-report grava CHECKSUMS.txt com barras no Windows (# 6089, obrigado @DeryFerd).

Desempenho (obrigado @Afloat16)

  • Longas linhas de transcrição são montadas uma vez em vez de copiadas em cada passagem de leitura, no leitor reverso (#6116) e no observador ao vivo (#6117).
  • O histórico de prompts do OpenCode é lido uma mensagem por vez (#6121).
  • Grandes cargas úteis de ferramentas são limitadas e criptografadas sem cópias completas (#6128).
  • As linhas do tempo carregam apenas as linhas que mostram (#6129). As sessões recentes usam uma verificação de resumo indexado (#6132). Os formatadores de data são reutilizados em uma renderização (#6125).
  • A recuperação no escopo do projeto interrompe uma verificação de mesclagem na primeira linha não adotada (#6131). O catálogo de projetos remove duplicatas com conjuntos (#6135). Consultas coladas há muito tempo param a verificação no limite de 500 termos (#6147).
  • A leitura inteligente de arquivo encontra o contêiner de cada símbolo com um índice em vez de uma varredura (#6122).
  • Meu trabalho indexa registros de proveniência (#6148), associações de solicitação de foco (#6155) e versões de itens de estado de trabalho (#6159) uma vez por chamada.

Documentos

  • Guias Cline CLI e Kilo CLI para salvar e encontrar memórias através do servidor stdio MCP (#6097, #6114, obrigado @Kirat0201). Documentos: https://docs.claude-mem.ai/cline e https://docs.claude-mem.ai/kilo
  • Habilidades agrupadas caem SEMPRE e marcadores OBRIGATÓRIOS (#6183, obrigado @jcole666, fecha #6144 relatado por @scu-lixiao).
  • A especificação do endpoint CMEM Pro define um escopo write:memory OAuth para ingestão de gancho (#6099).

CI e testes

  • Os trabalhos do Windows (#6092) e o fluxo de trabalho do tempo de execução de mídia (#6178) fixam Bun 1.4.4 como o resto do CI (obrigado @DeryFerd).
  • Os conjuntos de visualização de trabalho removem pastas temporárias com o auxiliar de nova tentativa compartilhado (#6094). A pista Windows executa ambos os conjuntos Python, e o conjunto Hermes foi reparado (# 6095) (obrigado @DeryFerd).
  • Um teste fixa os nomes dos eventos OpenCode 2.0, de modo que um evento upstream renomeado falha ruidosamente (#6102).
