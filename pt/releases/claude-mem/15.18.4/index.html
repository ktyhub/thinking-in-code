#claude-mem v15.18.4

Correções

  • Claude Code obtém as regras e ferramentas de Claude-mem uma vez (#6179). Antes disso, uma sessão do Claude Code recebia a mesma orientação de até três lugares: as instruções do servidor MCP, um bloco de memória que o script de ativação local gravou em CLAUDE.md e uma linha de ponteiro para RULES-AND-TOOLS.md (cuja legenda da linha do tempo nunca foi realmente carregada). Agora existe um caminho. MY-RULES.md, que seu CLAUDE.md já importa, termina com uma importação de RULES-AND-TOOLS.md, e Claude Code carrega a partir daí.
    • Quando essa cadeia de importação é concluída no Claude Code, o servidor MCP não envia instruções e o gancho SessionStart descarta a linha do ponteiro Access Claude-Mem Rules + Tools:. O servidor apenas ignora suas instruções quando o arquivo importado contém exatamente o texto que enviaria.
    • Outros hosts e usuários do Claude Code que nunca configuraram Minhas Regras permanecem inalterados.
    • O trabalhador adiciona a importação a um MY-RULES.md existente uma vez na inicialização, para que os usuários atuais a obtenham sem fazer nada. Ele nunca cria o arquivo. Escrever MY-RULES.md também garante que RULES-AND-TOOLS.md exista, para que a importação nunca aponte para um arquivo ausente.
    • scripts/activate-progressive-memory-local.mjs não grava mais o bloco de memória no CLAUDE.md de Claude. O Codex AGENTS.md o mantém, porque AGENTS.md não possui importações.
  • Os endpoints da listagem de trabalhadores param no deslocamento 10.000 (#6083, obrigado @xunguangzlj-cloud). /api/observations, /api/summaries, /api/prompts, os feeds de sessão e /api/tool-uses usados ​​para passar qualquer deslocamento direto para o SQLite, onde um deslocamento profundo faz o banco de dados varrer e descartar cada linha ignorada. Eles agora respondem 400 acima de 10.000 com a mesma mensagem que a lista de empregos usa. Em vez disso, os feeds do visualizador marcam sua última página, de modo que o visualizador mostra "esta lista termina nos 10.000 itens mais recentes" em vez de um erro.
  • Pastas cujos nomes começam com dois pontos permanecem dentro dos diretórios excluídos (#6062, obrigado @Afloat16). Uma pasta filha chamada ..cache foi confundida com um caminho de diretório pai, então ela passou pelas exclusões para sessões de observação, o cache do plugin e o tempo de execução do mercado, e um marcador na pasta de configuração de Claude poderia se tornar uma raiz do projeto.
  • O relatório de custos usa seu nome, não o do mantenedor (#6085, obrigado @MaxWang007). As verificações restantes baseadas em nome ("Bloqueado em <nome>", relés, detecção de revisão humana) recebem o nome de --owner-name, depois ACR_OWNER_NAME e depois git config user.name, e usam padrões sem nome quando nenhum é definido. Somente o primeiro nome também corresponde, e nomes não latinos funcionam.

Desempenho

  • Listas de sessões filtradas por projetos mais rápidas no visualizador (#6053, obrigado @Afloat16). Um novo índice de projeto, hora de início e ID permite ao visualizador ler uma página de um longo histórico do projeto sem classificar cada sessão. Os bancos de dados existentes obtêm o índice na próxima inicialização do trabalhador.
  • Memória de pico mais baixa durante a varredura quase duplicada (#6052, obrigado @Afloat16). A contagem de pares agora funciona com um título por vez, em vez de manter todos os pares de títulos compartilhados na memória. Os resultados são os mesmos.

Documentos e exemplos

  • Exemplo Vercel Chat SDK para memória de projeto explícita (#6084, obrigado @Kirat0201). Um bate-papo local autenticado pelo portador pode salvar uma nota, pesquisar seu projeto e buscar uma observação. Sem modelo e sem captura automática. Necessita do conjunto CLAUDE_MEM_WORKER_URL, e o guia mostra como encontrar a porta do seu trabalhador.
  • Marca do logotipo README atualizada (#6104).
