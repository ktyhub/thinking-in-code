#FastGPT v4.16.0-beta1

📦 Guia de atualização

1. Atualize a variável de ambiente Agent-sandbox-proxy (opcional)

4.16.0 precisa contar com proxy para acesso de proxy de recurso estático. Se o gateway suportar ws e http na mesma porta, você poderá abrir apenas uma porta. Se não for compatível, você pode definir a porta de acesso http configurando PREVIEW_PORT.

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

O endereço de acesso começa com http:// ou https://. Quando implantado com uma única porta, ele pode apontar para o mesmo nome de domínio e porta que AGENT_SANDBOX_PROXY_URL, mas os protocolos usam HTTP(S) e WebSocket(S), respectivamente. É altamente recomendável que o nome de domínio configurado e o site principal FastGPT usem origens diferentes. A implantação da mesma origem permitirá que esses scripts entrem no limite de segurança da mesma origem do site principal e potencialmente acessem as credenciais ou interfaces do site principal. O sistema atualmente não impõe a verificação da origem para isolamento.

Você pode verificar se está acessível visitando: https://{{host}}/health.

2. Atualize a variável de ambiente fastgpt-app (precisa ser atualizada se o sandbox estiver ativado)

As variáveis são modificadas simultaneamente em fastgpt-app e fastgpt-pro.

  1. Adicione variáveis de ambiente
# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. Variáveis de ambiente sandbox obsoletas

AGENT_SANDBOX_DISK_MB, variáveis relacionadas a E2B.

  1. Novas variáveis de configuração opcionais de sandbox

| variável | valor padrão | descrição | | ---------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------- | | AGENT_SANDBOX_CPU_COUNT | 1 | Limite de núcleo de CPU de instância única do Agent Sandbox. | | AGENT_SANDBOX_MEMORY_MIB | 2048 | Limite de memória de instância única do Agent Sandbox, unidade MiB. | | AGENT_SANDBOX_STORAGE_SIZE_GI | 1 | Capacidade de armazenamento do Agent Sandbox, em Gi; usado para limite de armazenamento Sealos Devbox e para criar novos PVCs no modo OpenSandbox Kubernetes. | | AGENT_SANDBOX_SUSPEND_MINUTES | 60 | Por quanto tempo o Sandbox em execução ficará pausado automaticamente após ficar inativo, em minutos. | | AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS | 7 | O Sandbox pausado é arquivado automaticamente após o tempo que ficará inativo, em dias. |

O provedor Sandbox E2B foi removido. Ambientes que possuem E2B previamente configurado precisam mudar para opensandbox ou sealosdevbox, e deletar AGENT_SANDBOX_E2B_API_KEY.

Os protocolos de visualização de FastGPT, fastgpt-agent-sandbox-proxy e fastgpt-agent-sandbox foram alterados simultaneamente. Esta versão da imagem de suporte deve ser usada ao ativar o Agent Sandbox, e a implantação mista de versões antigas e novas não é suportada.

4. Migrar dados do Agent Sandbox

Esta versão ajusta o Agent Sandbox do App Chat de “uma instância por conversa” para “uma instância compartilhada pelo mesmo aplicativo e pelo mesmo usuário”. Os arquivos das diferentes conversas ainda são salvos no diretório sessions/<chatId> respectivamente, e as Skills publicadas são salvas no diretório compartilhado projects.

Se o Agent Sandbox tiver sido habilitado anteriormente, a migração do Workspace legado deverá ser concluída na seguinte ordem. Os ambientes que não ativaram o Agent Sandbox podem ignorar esta seção.

Execute primeiro um teste para visualizar a contagem pendente de normalização de campos do Sandbox beta6 e limpeza antiga do Skill Debug Chat. a simulação não cria recursos, acessa o armazenamento de objetos ou modifica dados:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Execute a migração oficial depois de visualizar os resultados do teste. A migração oficial realizará primeiro a normalização beta6 e só continuará o arquivamento do Workspace na mesma solicitação quando a contagem pendente restante chegar a zero:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Se failures contiver apenas Sandbox source is missing or deleted e tiver sido confirmado que o aplicativo ou habilidade correspondente não existe mais, você poderá ignorar explicitamente essas sandboxes residuais:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError O padrão é false, mantendo a migração estrita quando omitido. Essa opção ignora apenas o grupo inteiro cuja origem está ausente ou excluída de forma reversível e não arquiva, exclui ou migra o sandbox dentro dele; detalhes de salto são retornados via skippedCount e skipped. Outros erros, como arquivamento, armazenamento de objetos, provedores e controle de simultaneidade, ainda podem bloquear migrações. A migração executará primeiro a pré-lógica completa de V4.15.0-beta6: preencha o sourceType/sourceId do antigo Sandbox, limpe os campos legados, exclua os recursos órfãos que não podem ser atribuídos e limpe os dados antigos de três tabelas do Skill Debug Chat que faltam sourceType e os prefixos antigos dos buckets privados e públicos. Habilidades com o mesmo ID do aplicativo ignorarão a limpeza do bate-papo. Depois de reafirmar os dois tipos de dados, o total é normalization.pendingCount; quando a quantidade não for 0, ela não será inserida no arquivo do Workspace. Após zerar, arquive diretamente todos os espaços de trabalho antigos e limpe os recursos de computação antigos, depois migre as habilidades e, finalmente, agregue-as em sandboxes de nível de usuário por aplicativo e usuário. Enquanto houver uma falha na fase de arquivo, a fase de instalação não será iniciada. O novo Sandbox será pausado após a conclusão da instalação do Workspace e será iniciado de acordo com o processo normal quando usado pela primeira vez. É seguro tentar novamente os scripts e os arquivamentos e migrações concluídos não são reexecutados; arquivos antigos e registros antigos do MongoDB são retidos como backups após a conclusão da migração.

Verifique os resultados retornados para normalization.pendingCount, normalizationBlocked, failedCount, failures, skippedCount e skipped. Somente quando normalization.pendingCount e failedCount são ambos 0 e normalizationBlocked é false, isso significa que todas as migrações de Sandbox não ignoradas foram concluídas; Os registros legados em skipped serão retidos e não serão migrados.

5. Migrar dados da ferramenta HTTP

Esta versão altera os parâmetros de array da ferramenta HTTP de modo manual para o esquema JSON padrão. Os ambientes que criaram ferramentas HTTP manuais antes da atualização precisam realizar esta migração; As ferramentas HTTP no modo OpenAPI não precisam ser migradas e o script será ignorado automaticamente.

Primeiro, execute o teste para visualizar os dados pendentes no aplicativo atual e nas versões históricas. o teste não modifica os dados:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Após confirmar o resultado, realize a migração oficial:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

O script primeiro filtrará os aplicativos por tipo de ferramenta HTTP e, em seguida, migrará as versões históricas correspondentes com base no appId desses aplicativos. Somente os modos manuais que não existem para apiSchemaStr serão processados, outras aplicações e modos OpenAPI não serão modificados. A migração é executada em lotes e pode ser repetida com segurança; total.changedDocumentCount no resultado retornado indica o número de documentos encontrados para serem processados. Após a execução formal, você pode testar novamente para confirmar se o valor é 0.

6. Outras alterações (opcional)

  1. Abandone a variável PASSWORD_LOGIN_LOCK_SECONDS e altere para PASSWORD_LOGIN_MINUTE_LIMIT_COUNT, que é utilizada para controlar a frequência de login por minuto.

🚀 Novo conteúdo

  1. O Agent Sandbox é alterado para uma instância de nível de usuário do aplicativo. Múltiplas conversas do mesmo App e do mesmo usuário reutilizam o Sandbox e isolam cada arquivo de conversa através de um diretório de sessão independente.
  2. HTML e arquivos sandbox suportam visualização direta por meio de links somente leitura de curto prazo e não precisam mais ser carregados repetidamente no armazenamento de objetos para visualização.
  3. O App Workflow arquiva e restaura automaticamente o Workspace quando o Sandbox Provider ou a imagem do tempo de execução são alterados, e o processo de atualização é concluído silenciosamente durante a execução atual.
  4. O nó da ferramenta de fluxo de trabalho oferece suporte à geração automática de parâmetros de entrada especificados pelo Agente e mantém configurações existentes, como valores fixos, referências e entrada do usuário.
  5. Quando o ChatAgent seleciona uma ferramenta, ele suporta a especificação manual se deseja gerar parâmetros para IA.
  6. Os dados da base de conhecimento suportam a personalização do metadata, e os metadados do JSON podem ser importados por meio de modelos API, CSV ou Excel; este campo será mantido nos resultados da pesquisa e nas exportações de backup. Tanto a importação de modelo quanto a importação de backup suportam arquivos .csv e .xlsx, usando cabeçalhos q, a, index e metadata; q, a e metadata possuem uma coluna cada e index pode ter múltiplas colunas em qualquer ordem. Os arquivos Excel suportam apenas uma única planilha e não podem conter células mescladas. Arquivos CSV ou Excel que não podem ser analisados ​​corretamente gerarão uma exceção de formato de arquivo.
  7. Faça upload de arquivos grandes em pedaços.
  8. Quando o administrador configura a chave da ferramenta do sistema, ela é criptografada (compatível com a chave configurada).
  9. Orientação de status vazia na lista de habilidades e vinculação ao selecionar habilidades.

⚙️ Otimização

  1. Reconstrua o ciclo de vida e o processo de migração do Agent Sandbox. Criar, pausar, arquivar, restaurar, excluir e comutação de provedor oferecem suporte à proteção de simultaneidade, retomada de ponto de interrupção e nova tentativa idempotente.
  2. Quando o Agent Sandbox não está disponível ou não é compatível com o pacote de equipe atual, o App Chat desativa automaticamente o recurso Sandbox e outros modelos, ferramentas, bases de conhecimento e nós de fluxo de trabalho ainda podem continuar em execução.
  3. Os volumes persistentes podem ser retidos após o OpenSandbox ser interrompido e reutilizados durante execuções subsequentes; os limites de pausa e arquivamento suportam configuração por meio de variáveis ​​de ambiente.
  4. O aplicativo e a habilidade têm status de atualização de imagem de tempo de execução unificado e a página de edição da habilidade pode pesquisar continuamente os resultados da atualização.
  5. Crie diretórios pais automaticamente antes de gravar arquivos Sandbox para evitar falhas na gravação de caminhos aninhados.
  6. Otimize problemas de compatibilidade, como dados de fluxo de trabalho antigos e parâmetros de ferramentas.
  7. UI de solicitação do agente.

🐛 Correção

  1. Corrigido o problema em que os recursos do OpenSandbox não eram liberados ou reutilizados corretamente após serem interrompidos.
  2. Corrija problemas de corrida de estado e operações duplicadas durante a criação, restauração ou atualização do tempo de execução do Agent Sandbox.
  3. Corrigido o problema em que o Sandbox falhava ao gravar arquivos em diretórios aninhados porque o diretório pai não existia.
  4. Corrigido o problema em que a entrada do número se torna uma caixa de texto normal após alternar entre a geração do Agente e a entrada manual.
  5. Corrigido o problema em que a entrada de texto de string era renderizada incorretamente como uma seleção suspensa.
  6. Corrigido o problema em que o Editor JSON era adicionado incorretamente à configuração da ferramenta de fluxo de trabalho.
  7. Corrigido o problema em que erros de execução da ferramenta eram exibidos incorretamente na interface da ferramenta Agente/fluxo de trabalho.
  8. Corrigido o problema de exibição de ferramentas desinstaladas na lista de ferramentas do sistema.
  9. Corrija a lógica de seleção de versão padrão do Agente/Agente V2 para que ele selecione a versão mais recente por padrão.
  10. Se houver espaços no arquivo S3, ocorrerá um erro 404 devido à exceção de chave ao analisar as imagens no arquivo.
  11. Modo MCP SSE, cabeçalho é repetido.
  12. A chave da ferramenta do sistema Agent V2 não está criptografada.

🛠️ Otimização de código

  1. O Adaptador Sandbox é dividido novamente por ciclo de vida, sistema de arquivos, execução de comandos e contrato do Provedor, e o Adaptador E2B é removido.
  2. Agent Sandbox Proxy e IDE Agent adicionam visualização de conexão direta do Workspace, solicitação de intervalo, proteção de escape de caminho e autenticação de sessão.
  3. Otimização do esquema de fluxo de trabalho, chamada de ferramenta unificada e renderização de formulário.
  4. Esquema JSON da ferramenta estendida para suportar mais tipos de dados.
  5. Tempo limite de leitura do arquivo do serviço unificado.
  6. Otimize o problema de segurança de permissão de vários processos das ferramentas do sistema.
  7. Refatore o login e o código de autenticação.
  8. Reconstrua o módulo limitador de corrente.
