<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> Novos Overlord APIs

APIs para marcação de segmentos como usados ou não utilizados foram movidos do serviço Coordenador para o serviço Overlord:

  • Marcar todos os segmentos de uma fonte de dados como não utilizados: POST /druid/indexer/v1/datasources/{dataSourceName}

  • Marcar todos os segmentos (não ofuscados) de uma fonte de dados como usados: DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • Marcar vários segmentos como usados POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • Marcar vários segmentos (não ofuscados) como não utilizados POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • Marcar um único segmento como usado: POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • Marcar um único segmento como não utilizado: DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

Como parte desta mudança, os Coordenadores APIs correspondentes foram descontinuados e serão removidos em uma versão futura:

-POST /druid/coordinator/v1/datasources/{dataSourceName} -POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed -POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused -POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId} -DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId} -DELETE /druid/coordinator/v1/datasources/{dataSourceName}

O Coordenador agora chama o Overlord para atender a essas solicitações.

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> Processamento de consulta em tempo real para strings de vários valores

O processamento de consultas em tempo real não considera mais todas as strings como strings de vários valores durante o processamento de expressões, corrigindo vários bugs e falhas inesperadas. Isso também deve melhorar o desempenho de consultas em tempo real de expressões em colunas de strings.

Essa alteração afeta as consultas topN para segmentos em tempo real onde as linhas de dados são implicitamente nulas, como de uma propriedade ausente em um objeto JSON.

Antes dessa mudança, eles eram tratados como [] em vez de nulos, levando à inconsistência entre o processamento de segmentos em tempo real e os segmentos publicados. Ao processar segmentos, o valor foi tratado como [], que topN ignora. Após a publicação, o valor tornou-se nulo, o que topN não ignora. A mesma consulta pode ter resultados diferentes antes e depois de ser persistida

Após essa alteração, o mecanismo topN agora trata [] como nulo ao processar segmentos em tempo real, o que é consistente com os segmentos publicados.

Essa alteração não afeta as colunas reais de strings com vários valores, independentemente de serem em tempo real.

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> Junte dicas em consultas do mecanismo de tarefas MSQ

Druid agora oferece suporte a dicas para consultas SQL JOIN que usam o mecanismo de tarefas MSQ. Isso permite que as consultas forneçam dicas para o tipo JOIN que deve ser usado em nível por junção. As dicas de junção afetam recursivamente as subconsultas.

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> Compatibilidade ANSI-SQL e resultados de consulta

O suporte para configurações que permitem manter comportamentos antigos que não eram compatíveis com ANSI-SQL foi removido:

-druid.generic.useDefaultValueForNull=true -druid.expressions.useStrictBooleans=false -druid.generic.useThreeValueLogicForNativeFilters=false

Eles não afetam mais os resultados da sua consulta. Somente comportamento não herdado compatível com SQL é suportado agora.

Se as configurações estiverem definidas para o comportamento legado, os serviços Druid não serão iniciados.

Se quiser continuar obtendo os mesmos resultados sem essas configurações, você deverá atualizar suas consultas ou seus resultados ficarão incorretos após a atualização.

Para obter mais informações sobre como atualizar suas consultas, consulte o guia de migração.

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> Junte dicas em consultas do mecanismo de tarefas MSQ

Druid agora oferece suporte a dicas para consultas SQL JOIN que usam o mecanismo de tarefas MSQ. Isso permite que as consultas forneçam dicas para o tipo JOIN que deve ser usado em nível por junção. As dicas de junção afetam recursivamente as subconsultas.

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

<a name="32.0.0-functional-area-and-related-changes-ingestion" href="#32.0.0-functional-area-and-related-changes-ingestion">#</a> Ingestão

<a name="32.0.0-functional-area-and-related-changes-ingestion-numbers-for-csv-and-tsv-input-formats" href="#32.0.0-functional-area-and-related-changes-ingestion-numbers-for-csv-and-tsv-input-formats">#</a> Números para formatos de entrada CSV e TSV

Use a nova configuração opcional tryParseNumbers para formatos de entrada CSV e TSV para controlar como os números são tratados. Se habilitado, quaisquer números presentes na entrada serão analisados da seguinte maneira:

  • tipo de dados longo para tipos inteiros e
  • double para números de ponto flutuante

Por padrão, esta configuração é definida como falsa, portanto strings numéricas serão tratadas como strings.

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing">#</a> Controle quantos segmentos serão mesclados para publicação

Agora você pode usar a propriedade maxColumnsToMerge em sua especificação de supervisor para especificar o número de segmentos a serem mesclados em uma única fase ao mesclar segmentos para publicação. Este limite afeta o número total de colunas presentes em um conjunto de segmentos a serem mesclados. Se o limite for excedido, a fusão de segmentos ocorrerá em múltiplas fases. Druida mescla pelo menos 2 segmentos em cada fase, independentemente desta configuração.

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates">#</a> Atualizações de dependências

As seguintes dependências tiveram suas versões alteradas:

  • javax.xml.bind não é mais usado. Druida agora usa jakarta.xml.bind #17370
  • Várias dependências do console web tiveram suas dependências atualizadas. Para obter uma lista completa, consulte #17381, #17365, #17363
  • Removida a dependência de file-loader para o console web #17346
  • Guia de 4.2.2 para 5.1.0
  • git-commit-id-maven-plugin de 4.9.10 a 9.0.1 #17571
  • Netty da versão 4.1.108.Final a 4.1.116.Final
