<a name="33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29" href="#33.0.0-important-features%2C-changes%2C-and-deprecations-scheduled-batch-ingestion-%28experimental%29">#</a> Ingestão de lote agendada (experimental)

Agora você pode agendar ingestões em lote com o mecanismo de tarefa MSQ usando o supervisor de lote agendado. Você pode especificar o agendamento usando a sintaxe cron padrão do Unix ou a sintaxe cron do Quartz, definindo o campo type como unix ou quartz. Unix também suporta expressões macro como @daily e outras.

Envie suas especificações de supervisor para o endpoint /druid/v2/sql/task/.

O exemplo de especificação de supervisor de lote agendado a seguir envia uma consulta REPLACE a cada 5 minutos:

{
    "type": "scheduled_batch",
    "schedulerConfig": {
        "type": "unix",
        "schedule": "*/5 * * * *"
    },
    "spec": {
        "query": "REPLACE INTO foo OVERWRITE ALL SELECT * FROM bar PARTITIONED BY DAY"
    },
    "suspended": false
}

<a name="faster-segment-metadata-operations" href="#faster-segment-metadata-operations">#</a> Operações de metadados de segmento mais rápidas

Ative o cache de metadados de segmento no Overlord com a propriedade de tempo de execução druid.manager.segments.useCache. Este recurso está desativado por padrão.

Você pode definir a propriedade com os seguintes valores:

  • never: Cache está desabilitado (padrão)
  • always: As leituras são sempre feitas a partir do cache. A inicialização do serviço será bloqueada até que o cache seja sincronizado com o armazenamento de metadados pelo menos uma vez. As transações são bloqueadas até que o cache seja sincronizado com o armazenamento de metadados pelo menos uma vez após se tornar líder.
  • ifSynced: As leituras são feitas a partir do cache somente se ele já estiver sincronizado com o armazenamento de metadados. Este modo não bloqueia a inicialização de serviços ou transações ao contrário da configuração always.

Como parte desta mudança, foram introduzidas métricas adicionais. Para obter mais informações sobre essas métricas, consulte Métricas de cache de metadados de segmento.

<a name="33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval" href="#33.0.0-functional-area-and-related-changes-data-management-automatic-kill-task-interval">#</a> Intervalo automático da tarefa de eliminação

O Coordenador pode opcionalmente emitir tarefas kill para limpar segmentos não utilizados. A partir desta versão, as tarefas de eliminação individuais estão limitadas ao processamento de 30 dias ou menos de segmentos por tarefa, por padrão. Isso melhora o desempenho das tarefas individuais de eliminação.

O comportamento anterior (sem limite de intervalo por tarefa de eliminação) pode ser restaurado configurando druid.coordinator.kill.maxInterval = P0D.

Por padrão, a imagem Docker agora usa o nome de host canônico para registrar serviços em ZooKeeper para comunicação interna se você estiver executando o Druid em Kubernetes. Caso contrário, ele usa o endereço IP. #17697.

Você pode definir a variável de ambiente DRUID_SET_HOST_IP como 1 para restaurar o comportamento antigo.

<a name="33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-metadata-cache-configs" href="#33.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-metadata-cache-configs">#</a> Configurações de cache de metadados de segmento

Se você precisar fazer downgrade para uma versão em que o Druid não suporte o cache de metadados de segmento, você deverá definir a configuração do druid.manager.segments.useCache como falsa ou removê-la antes da atualização.

Este recurso é introduzido no Druid 33.0.
