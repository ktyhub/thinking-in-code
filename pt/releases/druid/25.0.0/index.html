druida druida-25.0.0

Apache Druid 25.0.0 contém mais de 300 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de testes adicionais de 51 colaboradores. Veja o conjunto completo de alterações para detalhes adicionais.

<a name="25-highlights" href="#25-highlights">#</a> Destaques

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> Mecanismo de tarefa MSQ agora pronto para produção

O mecanismo de tarefa de consulta multiestágio (MSQ) usado para ingestão baseada em SQL agora está pronto para produção. Use-o para qualquer carga de trabalho compatível. Para obter mais informações, consulte as seguintes páginas:

  • Ingestão
  • Ingestão baseada em SQL

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Implantações simplificadas de Druidas

O novo script start-druid simplifica bastante a implantação de qualquer combinação de serviços Druid em um único servidor. Ele vem pré-empacotado com as configurações necessárias e pode ser usado para lançar um cluster Druid totalmente funcional simplesmente invocando ./start-druid. Para druidas experientes, também oferece controle completo sobre as propriedades de tempo de execução e os argumentos JVM para ter um cluster que atenda exatamente às suas necessidades. O script start-druid descontinua os perfis existentes, como start-micro-quickstart e start-nano-quickstart. Esses perfis poderão ser removidos em versões futuras. Para obter mais informações, consulte Implantação de servidor único.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> Compressão de dicionário de strings (experimental)

Adicionado suporte para dicionários de strings codificados frontalmente para colunas de strings menores, levando a tamanhos de segmento reduzidos com apenas pequenas penalidades de desempenho para a maioria das consultas Druidas. Isso pode ser habilitado configurando IndexSpec.stringDictionaryEncoding como {"type":"frontCoded", "bucketSize": 4} , onde bucketSize é qualquer potência de 2 menor ou igual a 128. A configuração dessa propriedade instrui as tarefas de indexação a gravar segmentos usando dicionários compactados do tamanho de bucket especificado.

Qualquer segmento escrito usando compactação de dicionário de string não pode ser lido por versões mais antigas do Druid. Para obter mais informações, consulte Codificação frontal. https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> tarefas nativas do Kubernetes

O Druid agora pode usar o Kubernetes para iniciar e gerenciar tarefas, eliminando a necessidade de gerentes intermediários. Para usar este recurso, habilite druid-kubernetes-overlord-extensions na lista de carregamento de extensões para seu processo Overlord. https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-compatível-binary" href="#25-highlights-hadoop-3-compatível-binary">#</a> Binário compatível com Hadoop-3

Druid agora vem empacotado como um binário dedicado para usuários do Hadoop-3, que contém jars compatíveis com o Hadoop-3. Se você não usar o Hadoop-3 com seu cluster Druid, poderá continuar usando o binário clássico.

<a name="25-msq-docker-enabled" href="#25-msq-docker-enabled">#</a> MSQ habilitado para Docker

O mecanismo de consulta de tarefas MSQ agora está habilitado para Docker por padrão. https://github.com/apache/druid/pull/13069

<a name="25-msq-query-history" href="#25-msq-query-history">#</a> Histórico de consultas

Consultas em vários estágios não aparecem mais na caixa de diálogo Histórico de consultas. Eles ainda estão disponíveis no painel Tarefas de consulta recentes.

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> Limite de colunas CLUSTERED BY

Ao usar o mecanismo de tarefa MSQ para ingerir dados, o número de colunas que podem ser transmitidas na cláusula CLUSTERED BY agora está limitado a 1.500. https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> Suporte para compactação de dicionário de strings

O mecanismo de tarefas MSQ oferece suporte à codificação frontal de dicionários String para melhor compactação. Isso pode ser ativado para instruções INSERT ou REPLACE configurando indexSpec como uma sequência json válida no contexto da consulta. https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> Modo de mesclagem de esboço

Os trabalhadores agora podem coletar estatísticas importantes, usadas para gerar limites de partição, sequencialmente ou em paralelo. Configure clusterStatisticsMergeMode como PARALLEL, SEQUENTIAL ou AUTO no contexto de consulta para usar o modo de mesclagem de esboço correspondente. Para obter mais informações, consulte Modo de mesclagem de esboço. https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> Melhorias operacionais e de desempenho

  • Mensagens de erro: para avisos MSQ não permitidos de certos tipos, o aviso agora aparece como o erro. https://github.com/apache/druid/pull/13198
  • Secrets: Para tarefas contendo SQL com chaves confidenciais, o Druid agora mascara as chaves durante o registro com a ajuda de expressões regulares. https://github.com/apache/druid/pull/13231
  • Precisão da amostragem: o mecanismo de tarefa MSQ agora usa o número de bytes em vez do número de chaves ao reduzir a resolução dos dados. https://github.com/apache/druid/pull/12998
  • Uso de memória: ao determinar os limites da partição, o espaço de heap dos esboços internos usados pelo MSQ agora é limitado a 10% da memória disponível ou 300 MB, o que for menor. Anteriormente, o limite era estritamente de 300 MB. https://github.com/apache/druid/pull/13274
  • Relatórios de tarefas: Adicionados campos pendingTasks e runningTasks ao relatório do trabalhador. Consulte Consultar informações de status da tarefa para obter alterações relacionadas ao console da web. https://github.com/apache/druid/pull/13263

<a name="25-querying-context-security" href="#25-querying-context-security">#</a> Segurança aprimorada do contexto de consulta

Adicionadas as seguintes propriedades de configuração que refinam o modelo de segurança do contexto de consulta controlado por druid.auth.authorizeQueryContextParams:

  • druid.auth.unsecuredContextKeys: Uma lista JSON de chaves de contexto de consulta que não requerem verificação de segurança.
  • druid.auth.securedContextKeys: Uma lista JSON de chaves de contexto de consulta que exigem uma verificação de segurança. Se ambos estiverem configurados, unsecuredContextKeys atua como exceção para securedContextKeys. https://github.com/apache/druid/pull/13071

A resposta HTTP para uma consulta SQL agora define corretamente os cabeçalhos de resposta, da mesma forma que uma consulta nativa. https://github.com/apache/druid/pull/13052

<a name="25-Operations-Compaction" href="#25-Operations-Compaction">#</a> Compactação

O comportamento da compactação mudou para melhorar o tempo necessário e o espaço em disco necessário:

  • Quando os segmentos precisarem ser buscados, baixe-os um de cada vez e exclua-os quando o Druid terminar de usá-los. Isso ainda leva tempo, mas minimiza o espaço em disco necessário.
  • Não busque segmentos na tarefa compacta principal quando eles não forem necessários. Se o usuário fornecer granularitySpec, dimensionsSpec e metricsSpec completos, o Druid pulará a busca de segmentos. Para mais informações, consulte a documentação sobre Compactação e Compactação automática. https://github.com/apache/druid/pull/13280

  • Operações Overlord

<a name="25-Operations-segment-loading-and-balancing-cachingcost-balancer-strategy" href="#25-Operations-segment-loading-and-balancing-cachingcost-balancer-strategy">#</a> Estratégia aprimorada do balanceador de custos de cache

A estratégia do balanceador cachingCost agora se comporta de forma mais semelhante à estratégia de custos. Ao calcular o custo de mover um segmento para um servidor, são realizados os seguintes cálculos:

  • Subtraia o custo próprio de um segmento se ele estiver sendo atendido pelo servidor de destino
  • Subtraia o custo dos segmentos marcados para serem descartados https://github.com/apache/druid/pull/13321

<a name="25-operações-segment-loading-and-balancing-segment-assignment" href="#25-operations-segment-loading-and-balancing-segment-assignment">#</a> Atribuição de segmento mais rápida

Agora você pode usar uma estratégia de segmento round-robin para acelerar as atribuições iniciais de segmento. Defina useRoundRobinSegmentAssigment como true na configuração dinâmica do Coordenador para ativar esse recurso. https://github.com/apache/druid/pull/13367

<a name="25-operações-segment-batch-sampling" href="#25-operações-segment-batch-sampling">#</a> Padrão para amostragem em lote para segmentos de balanceamento

A amostragem em lote é agora o método padrão para amostragem de segmentos durante o balanceamento, pois tem um desempenho significativamente melhor do que a alternativa quando há um grande número de segmentos usados no cluster. Como parte dessa mudança, os itens a seguir foram descontinuados e serão removidos em versões futuras:

  • configuração dinâmica do coordenador useBatchedSegmentSampler
  • configuração dinâmica do coordenador percentOfSegmentsToConsiderPerMove
  • antigo método sem lote de amostragem de segmentos

<a name="25-operations-segment-unused-property" href="#25-operations-segment-unused-property">#</a> Remover propriedade não utilizada

A propriedade do coordenador não utilizada druid.coordinator.loadqueuepeon.repeatDelay foi removida. Use apenas druid.coordinator.loadqueuepeon.http.repeatDelay para configurar o atraso de repetição para a fila de carregamento de segmento baseada em HTTP. https://github.com/apache/druid/pull/13391

<a name="25-upgrade" href="#25-upgrade">#</a> Atualizando para 25.0.0

Considere as seguintes alterações e atualizações ao atualizar do Druid 24.0.x para 25.0.0. Se você estiver atualizando de uma versão anterior, consulte os release notes das versões intermediárias relevantes.

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> Descoberta de segmento e gerenciamento de tarefas padrão baseado em HTTP

O método padrão de descoberta de segmento agora usa HTTP em vez de ZooKeeper. Esta atualização altera os padrões das seguintes propriedades: | Propriedade | Novo padrão | Padrão anterior | | - | - | - | | druid.serverview.type para gerenciamento de segmento | http | lote | | druid.coordinator.loadqueuepeon.type para gerenciamento de segmento | http | curador | | druid.indexer.runner.type para o Overlord | httpRemoto | locais | Para usar ZooKeeper em vez de HTTP, altere os valores das propriedades de volta aos padrões anteriores. As implementações baseadas em ZooKeeper para essas propriedades estão obsoletas e serão removidas em uma versão subsequente. https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> Finalizando agregados de esboço de HLL e quantis

As funções de agregação para esboços HLL e quantis retornaram esboços ou números quando são finalizados, dependendo de onde estavam no plano de consulta nativo. Druid não finaliza mais agregadores nos dois casos a seguir:

  • os agregadores aparecem no nível externo de uma consulta
  • agregadores são usados como entrada para uma expressão ou pós-agregador de acesso ao campo de finalização Essa alteração alinha o comportamento dos esboços HLL e quantis com os esboços teta. Para restaurar o comportamento antigo, você pode definir sqlFinalizeOuterSketches=true no contexto da consulta. https://github.com/apache/druid/pull/13247

<a name="25-upgrade-kill-tasks-mark-unused" href="#25-upgrade-kill-tasks-mark-unused">#</a> Eliminar tarefas marca segmentos como não utilizados somente se especificado

Quando você emite uma tarefa kill, o Druid marca os segmentos subjacentes como não utilizados somente se especificado explicitamente. Para obter mais informações, consulte a referência API https://github.com/apache/druid/pull/13104

<a name='25-upgrade-incompatível' href='#25-upgrade-incompatível'>#</a> Alterações incompatíveis

<a name='25-upgrade-incompatível-curator' href='#25-upgrade-incompatível-curator'>#</a> Atualize o curador para 5.3.0

Apache Curator atualizado para a versão mais recente, 5.3.0. Esta versão elimina o suporte para ZooKeeper 3.4, mas o Druid já abandonou oficialmente o suporte para 0.22. No 5.3.0, o Curator removeu o suporte para o Expositor, portanto todas as configurações e testes relacionados foram removidos. https://github.com/apache/druid/pull/12939

<a name="25-upgrade-incompatível-parquet" href="#25-upgrade-incompatível-parquet">#</a> Conversão de lista Parquet corrigida

O comportamento do leitor parquet para listas de objetos estruturados foi alterado para ser consistente com outras conversões de lista lógica parquet. Os dados agora são buscados diretamente, correspondendo mais de perto à estrutura esperada. Consulte conversão de lista de parquet para obter mais detalhes. https://github.com/apache/druid/pull/13294
