Operador Druida

Druid Operator é um controlador Kubernetes que gerencia o ciclo de vida de seus clusters Druid. O operador simplifica o gerenciamento de clusters Druid com sua lógica customizada que é configurável através CRDs Kubernetes.

#18435

Escalonamento automático baseado em custo para ingestão de streaming

O Druid agora oferece suporte ao escalonamento automático baseado em custos para ingestão de streaming que otimiza a contagem de tarefas equilibrando a redução do atraso com a eficiência dos recursos. Esta estratégia de escalonamento automático usa a seguinte fórmula:

totalCost = lagWeight × lagRecoveryTime + idleWeight × idlenessCost

que leva em conta o tempo para limpar o backlog e o tempo de computação:

lagRecoveryTime = aggregateLag / (taskCount × avgProcessingRate) — time to clear backlog
idlenessCost = taskCount × taskDuration × predictedIdleRatio — wasted compute time

#18819

Kubernetes client modo (experimental)

No kubernetes-overlord-extensions foi adicionado um modo experimental Kubernetes client. O novo modo usa fabric8 SharedInformers para armazenar metadados k8s em cache. Isso reduz bastante o tráfego API entre o plano de controle Overlord e k8s. Você pode experimentar esse recurso usando a seguinte configuração:

druid.indexer.runner.useK8sSharedInformers=true

#18599

suporte cgroup v2

O cgroup v2 agora é suportado e todas as métricas do cgroup agora emitem cgroupversion para identificar qual versão está sendo usada.

As seguintes métricas mudam automaticamente para v2 se v2 for detectada: CgroupCpuMonitor , CgroupCpuSetMonitor, CgroupDiskMonitor,MemoryMonitor. CpuAcctDeltaMonitor falha normalmente se v2 for detectado.

Além disso, CgroupV2CpuMonitor agora também emite cgroup/cpu/shares e cgroup/cpu/cores_quota.

#18705

Consultar relatórios para Dart

O Dart agora oferece suporte a relatórios de consulta para consultas em execução e concluídas recentemente. Os relatórios podem ser obtidos do endpoint /druid/v2/sql/queries/<sqlQueryId>/reports.

O formato da resposta é um objeto JSON com duas chaves, “consulta” e “relatório”. A chave "query" é a mesma informação que está disponível no endpoint /druid/v2/sql/queries existente. A chave "relatório" é um mapa de relatório que inclui um relatório MSQ. Você pode controlar o comportamento de retenção de relatórios usando as seguintes configurações:

  • druid.msq.dart.controller.maxRetainedReportCount: Número máximo de relatórios retidos. O padrão é 0, o que significa que nenhum relatório será retido
  • druid.msq.dart.controller.maxRetainedReportDuration: Por quanto tempo os relatórios são retidos no formato de duração ISO 8601. O padrão é PT0S, o que significa que a expiração baseada em tempo está desativada

#18886

Novo formato de segmento

O novo formato de segmento da versão 10 é melhorado em relação à versão 9. Ele está desativado por padrão e não é compatível com versões mais antigas de formato de segmento.

Configure druid.indexer.task.buildV10=true para fazer segmentos no novo formato.

Se você fizer downgrade, deverá reindexar seus dados com uma versão de formato de segmento compatível.

Você pode usar a ferramenta bin/dump-segment para visualizar metadados de segmento. A ferramenta gera JSON serializado.

Novas informações disponíveis no console web

O console web agora inclui informações sobre o número de processadores disponíveis e a memória total (em bytes binários).

Esta informação também está disponível através da tabela sys.servers.

Ingestão

  • Adicionado suporte para novas tentativas de código AWS InternalError #18720
  • Ingestão melhorada para ser mais resistente. As tarefas de ingestão não falharão mais se o upload do log de tarefas falhar com uma exceção #18748
  • Melhorou a forma como o Druid lida com situações em que os dados não correspondem ao tipo esperado #18878
  • Ingestão JSON aprimorada para que o Druid possa calcular valores JSON diretamente do dicionário ou estruturas de índice, permitindo que a ingestão ignore completamente os dados brutos persistentes do JSON. Isso reduz o tamanho do armazenamento em disco #18589
  • Agora você pode escolher entre indexação completa baseada em dicionário e indexação somente nulos para campos longos/duplos em uma coluna aninhada #18722

Ingestão baseada em SQL

Configurações adicionais de ingestão

Agora você pode usar as seguintes configurações para controlar como seus dados são ingeridos e armazenados:

  • maxInputFilesPerWorker: Controla o número máximo de arquivos ou segmentos de entrada por trabalhador.
  • maxPartitions: Controla o número máximo de partições de saída para qualquer estágio único, o que afeta quantos segmentos são gerados durante a ingestão.

#18826

Outras melhorias de ingestão baseadas em SQL
  • Adicionado maxRowsInMemory para substituir rowsInMemory. rowsInMemory agora funciona como uma forma alternativa de fornecer essa configuração e é ignorado se maxRowsInMemory for especificado. Anteriormente, existia apenas rowsInMemory #18832

Ingestão de streaming

Registro de deslocamento e partição

Agora você pode ingerir o deslocamento de registro (offsetColumnName) e a partição (partitionColumnName) usando o KafkaInputFormat. Seus nomes padrão são kafka.offset e kafka.partition respectivamente.

#18757

Outras melhorias na ingestão de streaming
  • Supervisores aprimorados para que não possam encerrar tarefas enquanto o supervisor estiver parando #18767
  • Melhorado o escalonador automático baseado em atraso para ingestão de streaming #18745
  • Melhorado o escalonador automático do supervisor SeekableStream para aguardar a conclusão das tarefas antes de tentar operações de escala subsequentes. Isso ajuda a evitar entradas duplicadas no histórico do supervisor #18715

Gerenciamento de cluster

Capacidade dinâmica para implantações baseadas em Kubernetes

O Druid agora pode ajustar dinamicamente a capacidade do executor de tarefas.

Inclua o campo capacity em uma chamada POST API para /druid/indexer/v1/k8s/taskrunner/executionconfig. Definir um valor desta forma substitui druid.indexer.runner.capacity.

A tabela sys.server_properties expõe as propriedades de tempo de execução configuradas para cada servidor Druid. Cada linha representa um único par de valores-chave de propriedade associado a um servidor específico.

Notas de atualização e alterações incompatíveis

Notas de atualização

Tarefas do controlador MSQ

Ao atualizar do Druid 30 ou anterior, as tarefas do MSQ query_controller podem falhar durante uma atualização contínua devido à adição de novos contadores que não são compatíveis com versões anteriores dessas versões mais antigas. Você pode tentar novamente quaisquer consultas com falha após a conclusão da atualização; ou você pode definir includeAllCounters como false no contexto de consulta para quaisquer trabalhos MSQ que precisem ser executados durante a atualização contínua; ou você pode atualizar para o Druid 31–35 primeiro, antes de atualizar para o Druid 36.

#18761

Formato do segmento

Druid 36.0.0 suporta formato de segmento versão 10. Versões anteriores do Druid não suportam versão 10. Se você fizer downgrade, deverá reindexar seus dados com uma versão de formato de segmento compatível.

#18880

Métricas obsoletas

Os monitores em peons que emitiram anteriormente a dimensão id de JettyMonitor, OshiSysMonitor, JvmMonitor, JvmCpuMonitor, JvmThreadsMonitor e SysMonitor para representar o ID da tarefa estão obsoletos e serão removidos em uma versão futura. Use a dimensão taskId.

#18709

Métricas removidas

As seguintes métricas obsoletas foram removidas:

  • segment/cost/raw #18846
  • segment/cost/normalized #18846
  • segment/cost/normalization #18846
  • task/action/log/time #18649

Notas do desenvolvedor

Interfaces de arquivo de segmento

Novas interfaces SegmentFileBuilder e SegmentFileMapper foram definidas para substituir o uso direto de FileSmoosher e SmooshedFileMapper para abstrair o processo de construção e leitura de segmentos.

A principal mudança visível do desenvolvedor para gravadores de extensão com implementações de colunas customizadas é que a interface Serializer mudou o método writeTo:

  • Agora aceita um SegmentFileBuilder em vez de um FileSmoosher
  • O método ColumnBuilder getFileMapper agora retorna um SegmentFileMapper em vez de SmooshedFileMapper.

Extensões que não fornecem implementações de colunas personalizadas não devem ser afetadas por essas alterações.

#18608

Outras melhorias para desenvolvedores

  • Adicionada a capacidade de substituir a imagem Kafka padrão para teste #18739
  • fastDecompressor alterado para safeDecompressor #18930
  • As extensões agora podem fornecer implementações de kit de consulta #18875
  • Substituições de versão removidas em arquivos pom individuais. Para obter uma lista completa, consulte a solicitação pull #18708
