Recursos, alterações e descontinuações importantes

Esta seção contém informações importantes sobre recursos novos e existentes. ###Java O suporte para Java 21 foi eliminado. Você deve atualizar para Java 25.

Instruções DDL para o catálogo (experimental)

Druid agora oferece suporte a instruções CREATE e ALTER para gerenciar metadados no catálogo. Use-os para declarar colunas de uma tabela, particionamento de tempo, clustering, projeções agregadas e layout físico, em vez de defini-los em cada especificação de ingestão. Este recurso está desativado por padrão. Para habilitá-lo, defina druid.sql.planner.enableCatalogDdl como true. Para obter mais informações, consulte Catálogo. #19830 #20377 #20452 #19770 #19711

Filtragem baseada em cabeçalho Kafka

Os supervisores Kafka agora podem filtrar registros por seus cabeçalhos. Isso reduz o uso de CPU e memória de ingestão quando você só precisa de alguns registros de um tópico. Para utilizar o filtro, adicione headerBasedFilterConfig ao ioConfig do supervisor. Use um filtro in em que dimension é o nome do cabeçalho e values lista os valores do cabeçalho a serem ingeridos. Os registros cujo valor de cabeçalho não está na lista são eliminados e os deslocamentos ainda avançam. A filtragem é permissiva: os registros são ingeridos se não tiverem o cabeçalho, se o valor do cabeçalho for nulo, vazio ou não puder ser decodificado ou se a avaliação falhar. A nova métrica ingest/events/filtered informa quantos registros a filtragem de cabeçalhos caiu. #18525

Parâmetros de contexto de consulta digitados

Parâmetros de contexto de consulta comuns listados em Referência de contexto de consulta e Consultas de verificação agora são descritores digitados QueryContextParameter. As seguintes alterações se aplicam ao tratamento do contexto da consulta:

  • Parâmetros inteiros e longos rejeitam valores que não são inteiros exatos em vez de truncá-los ou agrupá-los. Por exemplo 1.5 e valores fora do intervalo. Valores integrais como 5.0 ou “5.0” ainda são aceitos. Valores inválidos agora falham com uma mensagem de erro: "O parâmetro de contexto de consulta [x] deve ser ...."
  • Um nulo no contexto da consulta, ou SET x = NULL, não limpa mais um padrão configurado com druid.query.default.context ou a configuração dinâmica do Broker. O padrão se aplica como se a chave não tivesse sido definida. Anteriormente, o nulo atingia os leitores, que usavam o padrão integrado. Para substituir um padrão configurado, defina um valor explícito.
  • maxSubqueryBytes é um parâmetro de string digitado que aceita um número de bytes automático, desabilitado ou não negativo, como faz o guardrail da subconsulta. Valores inválidos como SET maxSubqueryBytes = TRUE agora falham durante a validação e números como 1e9 agora são aceitos. #20555

Driver Druida JDBC

Druid agora fornece seu próprio driver JDBC que usa o endpoint /druid/v2/sql/. Recomendamos que você mude do driver Avatica para este driver. O novo driver oferece os seguintes benefícios: gerenciamento de conexão do lado do driver que não requer balanceamento de carga persistente, resultados de streaming, suporte para instruções SET e suporte para mecanismos SQL não nativos. #19951

Netty 4.2

Druid agora usa Netty 4.2 para seu HTTP client. Anteriormente, o Druid usava Netty 3. Esta é uma mudança substantiva nas características da memória:

  • Memória direta: O HTTP client agora consome alguma memória direta. As operadoras que operam perto do orçamento do -XX:MaxDirectMemorySize podem precisar aumentá-lo.
  • Buffers em pool: Os buffers agora estão em pool, portanto a memória residente pode parecer maior do que no Netty 3, mesmo quando ociosa. Isso é normal para um alocador em pool. Existem novas configurações que controlam o comportamento do HTTP client: druid.global.http.connectTimeout, druid.global.http.allocator, druid.broker.http.connectTimeout e druid.broker.http.allocator. Você também pode definir algumas configurações do Netty diretamente. #19567

Filtragem de qualidade de serviço para o Coordenador

Agora você pode ativar a filtragem de QoS para o Coordenador para evitar que uma explosão de solicitações API lentas esgote o conjunto de encadeamentos e bloqueie as verificações de integridade. Use druid.coordinator.server.maxConcurrentRequests para configurar este recurso (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Configure esta propriedade como 0 para desligá-la. Os endpoints com status líder são excluídos do limite para que os balanceadores/monitores de carga não sejam afetados. #19271

Área funcional e mudanças relacionadas

Esta seção contém release notes detalhados separados por áreas.

Ingestão

  • Adicionado suporte para regex RE2/J para o formato de entrada regex #19514
  • Alteração do S3 client para usar a política de repetição padrão recomendada pela AWS. Você pode personalizar a estratégia de nova tentativa usando druid.s3.retryMode e druid.s3.maxAttempts #19892
  • A ingestão do Protobuf agora mantém o valor padrão dos campos proto3 que não estão marcados como opcionais. Anteriormente, um campo int32 contendo 0 (ou uma string contendo "", um bool contendo falso, um enum contendo seu primeiro valor) era ingerido como nulo. Esses campos agora são ingeridos como seu valor real. #20485

Ingestão baseada em SQL

  • Os trabalhadores agora passam apenas o contexto de trabalho necessário em vez de todo o contexto de trabalho para o contexto de tarefa. #20650

Ingestão de streaming

Ingestão de partições selecionadas

Os supervisores Kafka agora aceitam ioConfig.partitionIds, que permite ingerir apenas partições selecionadas de um tópico. Por exemplo, você pode usar isso para ingestão de diagnóstico independente. #20474

Melhorias no escalonador automático baseado em custos
  • Agora você pode simular o escalonador automático baseado em custos do Kafka para ajudar a determinar a contagem ideal de tarefas para diferentes quantidades de atraso. #19687
  • Agora você pode definir um limite de atraso crítico para o escalonador automático baseado em custos. Quando o atraso atinge 75% do limite, o autoescalador ignora o limite de aumento de escala. Quando o atraso atinge 100%, o escalonador automático aumenta até a contagem máxima de tarefas. #19655
  • Agora você pode optar por configurar o tempo de espera para o escalonador automático baseado em custos para um supervisor de duas maneiras:
    • Alta sensibilidade: Defina minScaleUpDelay / minScaleDownDelay < taskDuration. Por exemplo, se minScaleUpDelay = taskDuration / 2, haveria no máximo 1 evento de escalonamento entre 2 sobreposições de tarefas
    • Baixa sensibilidade: Defina minScaleUpDelay / minScaleDownDelay > taskDuration. Nesse caso, o resfriamento é efetivamente ignorado e o escalonamento ocorre apenas na substituição da tarefa. #20706
  • O escalonador automático baseado em custos agora usa médias em vez de valores instantâneos de métricas de tarefas para tomar decisões para o escalonador automático baseado em custos. Isso leva a um dimensionamento mais suave, mas às vezes pode custar respostas ligeiramente atrasadas às mudanças nas tendências métricas que ocorrem no final do ciclo de vida da tarefa. Para maior sensibilidade às mudanças de tendências, defina minScaleUpDelay e minScaleDownDelay para serem menores que taskDuration.
Outras melhorias na ingestão de streaming
  • Corrigido um bug em que uma tarefa de indexação Kafka relataria uma taxa de inatividade de pesquisa de 1.0 (ou seja, totalmente inativa) antes que qualquer amostra estivesse realmente disponível, o que poderia distorcer a taxa de inatividade média do escalonador automático do supervisor entre as tarefas. #20783

Consultando

Tempo de planejamento da consulta

Agora você pode limitar quanto tempo o Broker gasta planejando uma consulta SQL com a nova propriedade de tempo de execução druid.sql.planner.maxPlanningTimeMs. Você também pode configurá-lo por consulta usando o parâmetro de contexto de consulta maxPlanningTimeMs. Quando o planejamento excede o orçamento configurado, a consulta falha com um erro de tempo limite de consulta HTTP 504 em vez de vincular um encadeamento do Broker. O valor padrão é 0, que desativa o tempo limite. #20314

Corrigidas falhas JDK HTTP client causadas por trailers de resposta de consulta

Brokers e Historicals agora enviam os trailers HTTP X-Druid-Response-Complete e X-Error-Message somente quando a solicitação inclui o cabeçalho TE: trailers. Clients que leem esses trailers devem enviar esse cabeçalho. Isso corrige falhas de consulta (java.net.ProtocolException: CR expected) em java.net.http.HttpClient-based clients, incluindo o driver Druid JDBC, em JDK 17.0.21, 21.0.13 e 25.0.5. #20717

Outras melhorias de consulta

  • Agora você pode usar o Dart para consultar tabelas de metadados, como aquelas no esquema sys #19952
  • CAST(x AS LONG) agora é aceito como um alias para CAST(x AS BIGINT) no Druid SQL #20402
  • Adicionado pushdown do filtro datasource à tabela sys.segments #19718
  • Adicionado suporte de enquadramento para as funções de janela FIRST_VALUE e LAST_VALUE #19301
  • Melhorou o desempenho de consultas de série temporal, timeBoundary e varredura que são executadas em ordem decrescente #19947
  • Melhorou o desempenho do COALESCE #18400
  • Melhor eficiência de uso do S3 API para tarefas MSQ usando armazenamento durável e exportação MSQ #19893
  • Validação aprimorada para tipos de catálogo e análise de strings de tipo nativo #19769
  • Atualizado para Calcita 1.42.0 #19976 #19370

Gerenciamento de cluster

Rótulos de nó Kubernetes

A extensão druid-kubernetes-extensions agora suporta um provedor de configuração dinâmica k8sNodeLabel, que resolve valores de configuração dos rótulos do nó Kubernetes em que um processo Druida é executado. #20404

Modelo de pod Peon

Agora você pode recuperar os nomes dos modelos de pod Peon atualmente configurados no Overlord usando o novo endpoint GET /druid/indexer/v1/k8s/taskrunner/podTemplates. Ele retorna o nome de cada modelo configurado. O endpoint requer permissão de leitura CONFIG e retorna 404 quando o Overlord não está usando o adaptador de pod de modelo personalizado. #19712

Variáveis de ambiente

O provedor de configuração dinâmica environment agora omite variáveis que não estão definidas no ambiente em vez de produzir um valor nulo que falha em consumidores como o supervisor Kafka com um NullPointerException. Uma variável ignorada é registrada no nível de informação. #20381

Conjuntos de conexões

Agora você pode configurar como o pool de conexões Druid rastreia a demanda de conexão usando druid.global.http.poolImplementation. O padrão é retaining. Com retaining, a piscina mantém todas as conexões que abre e substitui cada conexão obsoleta ou quebrada por uma nova, para que a piscina permaneça em seu limite máximo. #20542 #20273

Cabeçalhos de resposta HTTP

O Druid agora pode retornar opcionalmente X-Druid-Server, X-Druid-Service e X-Druid-Version em respostas HTTP, permitindo que os operadores identifiquem o processo e a versão que atendeu uma solicitação direta ou por proxy do roteador. Esses cabeçalhos expõem informações de topologia e versão do cluster, portanto, habilite-os apenas se todos os clients tiverem permissão para recebê-los. Para habilitá-los, defina druid.server.http.enableResponseIdentityHeaders como true. #20268

Suporte LDAP aprimorado

Adicionado suporte para autorização baseada em grupo LDAP em servidores que não retornam o atributo memberOf (como OpenLDAP). Configure groupBaseDn e groupSearch no validador de credenciais LDAP para ativar uma pesquisa reversa de grupo que resolva associações de grupo automaticamente. #19432

Visibilidade da tabela

Os usuários que consultam tabelas para os quais não têm permissão READ agora veem um erro "não encontrado" em vez de um erro "proibido". Para restaurar o comportamento anterior, configure druid.sql.planner.authorizeTableVisibility como false. Além disso, quando configurados como true, INSERT e REPLACE requerem acesso de LEITURA e ESCRITA à tabela de destino. Se esta propriedade estiver definida como false, eles requerem apenas permissão WRITE. Independentemente do valor desta propriedade, as tabelas só aparecem em INFORMATION_SCHEMA se o usuário tiver acesso READ às mesmas. Esta é uma alteração significativa que afeta as permissões de que você precisa. Para obter mais informações, consulte alterações de permissões para ingestão baseada em SQL. #20075

Variável inicial Java

Os gerentes intermediários agora honram JAVA_HOME ao usar o script bin/java, que deve estar presente no diretório de trabalho. Druid usa a seguinte lógica

  • Se você especificou um comando (como se config.getJavaCommand não for nulo), use-o.
  • Se bin/run-java existir, use-o
  • Usar java #19709

Adicionar filtragem de QoS para endpoints do Coordinator

Adicionada filtragem de QoS configurável ao Coordenador para evitar que uma explosão de solicitações API lentas esgote o pool de threads e bloqueie as verificações de integridade. Adicionada uma nova configuração: druid.coordinator.server.maxConcurrentRequests (padrão: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8)), defina <= 0 para desabilitar). Os endpoints com status líder são excluídos do limite para que balanceadores de carga e monitores permaneçam inalterados. #19271

Outras melhorias no gerenciamento de cluster

  • Adicionado um tipo de bloqueio de tarefa KILL que pode ser usado por tarefas kill incorporadas para que o UnusedSegmentsKiller não pule intervalos com ingestões ativas #19921
  • Adicionado suporte para PostgreSQL à ferramenta export-metadata #19698
  • Os peões que executam tarefas que não atendem a consultas (por exemplo, tarefas em lote, compactação e MSQ) agora ignoram druid.server.http.unannouncePropagationDelay e desligam sem esperar. As tarefas de streaming em tempo real ainda respeitam o atraso #20444
  • Ligação de porta aprimorada. Os nós druidas agora podem anunciar uma porta de texto simples diferente para descoberta de pares enquanto vinculam o Jetty à porta de serviço real #19598
  • Redução do volume de heap dos segmentos carregados #20467
  • Corrigido o Overlord shutdownAllTasks API (POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks), que retornava um erro 404 desde o Druida 32.0.0. #20824

Gerenciamento de dados

Ignorar intervalos durante a compactação

A compactação automática agora suporta uma configuração skipIntervals na configuração de compactação da fonte de dados, permitindo que intervalos específicos sejam excluídos da compactação, além do comportamento existente do skipOffsetFromLatest. Isso é útil, por exemplo, para excluir um intervalo no qual uma tarefa de aterramento está gravando ativamente ou um intervalo que falha consistentemente na compactação. #19792

Melhor visibilidade para arquivos de segmentos grandes

O Druid agora informa quando suas configurações de particionamento de intervalo ou hash produzem arquivos de segmento excessivamente grandes (partições ativas) em um intervalo de tempo. A ingestão de lote nativo com hash ou particionamento de intervalo agora registra um aviso e emite a métrica ingest/segments/oversized. A métrica conta segmentos publicados com mais que o dobro de linhas maxRowsPerSegment ou mais que o triplo de targetRowsPerSegment para particionamento de intervalo. O relatório de conclusão da tarefa também inclui esta contagem como oversizedSegments. #20173

Pesquisas de segmento mais rápidas

Agora você pode acelerar pesquisas de segmento na linha do tempo da memória ativando a pesquisa rápida em intervalos. Este recurso usa um índice [árvore de intervalo] (https://en.wikipedia.org/wiki/Interval_tree) para organizar a linha do tempo na memória para carregamento e pesquisa mais rápidos de segmentos. Para usar este recurso, defina druid.segment.timeline.fastIntervalSearch como true. #19138 #19861

Carregamento parcial do segmento

Druid agora oferece suporte ao carregamento parcial de segmentos para armazenamento virtual (ativado por padrão). Para desligá-lo, defina um dos seguintes itens para false:

  • a propriedade de tempo de execução druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • o parâmetro de contexto de consulta virtualStoragePartialDownloadsEnabled #19739

Outras melhorias no gerenciamento de dados

  • Adicionado suporte para somas de verificação de solicitação MD5 para armazenamento compatível com S3. Para ativar este recurso, defina druid.s3.enableLegacyMd5 como true #20055
  • Adicionado suporte para empurrar, extrair e eliminar segmentos no armazenamento profundo do Azure e do Google Cloud sem compactação zip #20454 #20327 #20382 #20380
  • Melhorou o algoritmo de carregamento para dispersar melhor as solicitações nas camadas históricas ao usar armazenamento virtual #20155
  • Melhorou a eficiência das tarefas de eliminação incorporadas #19772

Métricas e monitoramento

Métricas de armazenamento em camadas

As métricas de armazenamento em camadas agora fornecem melhor observabilidade para históricos, com ou sem armazenamento virtual. Duas métricas, tier/required/capacity e tier/total/capacity, estão obsoletas e serão removidas em uma versão futura. Use tier/storage/required e tier/storage/capacity. #20199

Métrica task/run/time

Os emissores statsd e prometheus agora emitem a dimensão taskStatus no task/run/time. Esta é uma mudança radical. Para obter mais informações, consulte alertas em task/run/time. #20122

Outras métricas e melhorias de monitoramento

  • As métricas de tarefa Peon para clusters que usam a extensão Kubernetes Overlord agora incluem uma dimensão podTemplate. Isso torna mais fácil monitorar clusters que mapeiam tarefas diferentes para modelos de pod diferentes #20001
  • Adicionado mergeBuffer/maxSpillProximity, que mede o quão próximo qualquer consulta groupBy chegou de derramamento durante o período de emissão, como uma fração em [0.0, 1.0] #19627
  • Adicionado taskType às diversas métricas de contagem de tarefas, para que você possa filtrá-las por tipo de tarefa #20123

Extensões de contribuidor

Iceberg

A ingestão do Apache Iceberg agora oferece suporte a um leitor vetorizado opcional apoiado por iceberg-arrow. Habilite-o com "useArrowReader": true; ajuste o lote com arrowBatchSize (padrão 1024). O caminho Arrow oferece suporte a arquivos de dados Parquet, valores codificados em dicionário, evolução de esquema, instantâneos de viagem no tempo, projeção de coluna e empilhamento de predicado. Instantâneos contendo arquivos de exclusão posicional ou de igualdade não são suportados e o Druid os rejeita com um erro; use o leitor padrão com reconhecimento de exclusão para esses instantâneos. O caminho Arrow não pode ser dividido, portanto, mantenha-o desabilitado onde a produção de lote paralela for necessária. O leitor padrão permanece inalterado e ambos os caminhos coexistem sob o mesmo tipo de fonte de entrada Iceberg. #19510

Agente de política aberta

Adicionada a extensão de contribuidor druid-opa-authorizer, que permite a autorização através do Open Policy Agent (OPA). Você pode escrever políticas Rego para controlar o acesso aos recursos Druidas com base na identidade do usuário, ação e tipo de recurso. A extensão oferece suporte a fluxos de trabalho de autenticação básica e autenticação LDAP. #19670

Agora você pode ativar a filtragem de QoS para o Coordenador para evitar que uma explosão de solicitações API lentas esgote o conjunto de encadeamentos e bloqueie as verificações de integridade. Use druid.coordinator.server.maxConcurrentRequests para configurar este recurso (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Configure esta propriedade como 0 para desligá-la. Os endpoints com status líder são excluídos do limite para que os balanceadores/monitores de carga não sejam afetados. #19271

Alterações incompatíveis

Mudanças nas permissões para ingestão baseada em SQL

As alterações na visibilidade da tabela afetam as permissões necessárias para a ingestão baseada em SQL. INSERT e REPLACE agora requerem acesso READ (além de WRITE) na tabela de destino. Para restaurar o comportamento anterior, configure druid.sql.planner.authorizeTableVisibility como false. #20075

Alertas em task/run/time

Os emissores statsd e prometheus agora emitem a dimensão taskStatus no task/run/time. Esta é uma alteração significativa para painéis e alertas no task/run/time:

  • statsd (modo não DogStatsD): os valores das dimensões são unidos no nome da métrica pontilhada, então druid.overlord.task.run.time.DATASOURCE.TASKTYPE se torna druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE. As consultas no nome antigo param de receber dados.
  • statsd (modo DogStatsD): Uma tag taskStatus é adicionada. As consultas existentes continuam funcionando e agregando-as.
  • prometheus: Uma etiqueta taskStatus é adicionada. Atualize quaisquer consultas que selecionem um conjunto de rótulos exato e quaisquer regras de gravação que assumam o conjunto de rótulos antigo. Para manter o comportamento anterior, fixe a lista de dimensões antiga com druid.emitter.statsd.dimensionMapPath ou druid.emitter.prometheus.dimensionMapPath. #20122

SysMonitor removido

SysMonitor foi removido após ser obsoleto no Druid 27. Use OshiSysMonitor. #20200

MariaDB Connector/J 3.x altera o comportamento do URI de conexão

O conector MariaDB JDBC foi atualizado de 2.7.3 para 3.5.10, o que tem o seguinte impacto:

  • Para druid.metadata.storage.connector.connectURI com org.mariadb.jdbc.Driver, use jdbc:mariadb:. Um URI jdbc:mysql: herdado permanece utilizável somente se incluir permitMysqlScheme. Por exemplo, jdbc:mysql://<host>/druid?permitMysqlScheme, porque o armazenamento de metadados passa o URI diretamente para o driver.
  • Para fontes de entrada SQL apoiadas por MariaDB e pesquisas JDBC com o druid.access.jdbc.enforceAllowedProperties=true padrão, use jdbc:mariadb:. A validação da propriedade JDBC do Druid não roteia jdbc:mysql: para o analisador Connector/J 3.x e permitMysqlScheme não está no druid.access.jdbc.allowedProperties padrão. Adicionar a opção por si só não é suficiente.
  • Os usuários que continuam fornecendo o Connector/J 2.x não precisam alterar os URIs jdbc:mysql: ou jdbc:mariadb: existentes. Os usuários do Conector MySQL/J não são afetados.
  • Imagens reconstruídas a partir de distribution/docker/Dockerfile.mariadb agora instalam o Connector/J 3.5.10 e devem seguir a orientação 3.x acima. #20036

Notas do desenvolvedor

Editor de código do console da Web

Os editores de código do console da web mudaram de Ace (ace-builds e react-ace) para Code Mirror 6. Todos os editores agora compartilham um único componente CodeEditor, incluindo o ambiente de trabalho, as entradas SQL da visualização de exploração, entradas JSON, diálogos de especificações e valores, histórico e explicação. Duas gramáticas Lezer, uma para DruidSQL e outra para Hjson, orientam o realce e as completações. #20507

Atualizações de dependências

Druid 39.0.0 inclui uma variedade de atualizações para dependências como Calcite. Para obter uma lista completa, consulte Área - Etiqueta de dependências no marco.
