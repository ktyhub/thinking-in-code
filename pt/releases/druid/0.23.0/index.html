Fizemos as seguintes melhorias na ingestão de kinesis

  • A refragmentação pode afetar e retardar a ingestão, pois muitos fragmentos vazios intermediários são criados. Esses fragmentos são atribuídos a tarefas que causam desequilíbrio na atribuição de carga. Você pode definir skipIgnorableShards como true na configuração de ajuste de ingestão do kinesis para ignorar esses fragmentos. (#12235)
  • Atualmente, a ingestão do kinesis usa DescribeStream para buscar a lista de fragmentos. Esta chamada está obsoleta e mais lenta. Nesta versão, você pode mudar para um API listShards mais recente configurando useListShards como true na configuração de ajuste de ingestão do kinesis. (#12161)

<a name="0.23.0-security-fixes" href="#0.23.0-security-fixes">#</a> Correções de segurança

<a name="0.23.0-security-fixes-support-for-access-control-on-setting-query-contexts" href="#0.23.0-security-fixes-support-for-access-control-on-setting-query-contexts">#</a> Suporte para controle de acesso na configuração de contextos de consulta

Hoje, quaisquer parâmetros de contexto são permitidos aos usuários. Isso pode causar 1) uma UX ruim se o parâmetro de contexto ainda não estiver maduro ou 2) até mesmo falha de consulta ou falha do sistema no pior caso, se um parâmetro sensível for abusado, ex) maxSubqueryRows. Druid agora tem a capacidade de limitar parâmetros de contexto por função de usuário. Isso significa que uma consulta falhará se você tiver um parâmetro de contexto definido na consulta que não é permitido para você. A autorização do parâmetro de contexto pode ser habilitada usando Druid.auth.authorizeQueryContextParams. Isso está desabilitado por padrão para permitir uma experiência de atualização mais tranquila. (#12396)

<a name="0.23.0-upgrading-to-0.23.0" href="#0.23.0-upgrading-to-0.23.0">#</a> Atualizando para 0.23.0

Considere as seguintes alterações e atualizações ao atualizar do Druid 0.22.x para 0.23.0. Se você estiver atualizando de uma versão anterior à 0.22.1, consulte os release notes das versões intermediárias relevantes.

<a name="0.23.0-upgrading-to-0.23.0-autokill" href="#0.23.0-upgrading-to-0.23.0-autokill">#</a> Eliminação automática de segmentos

No 0.23.0, a eliminação automática de segmentos agora está habilitada por padrão (#12187). Os novos padrões devem eliminar todos os segmentos não utilizados com mais de 90 dias. Se os usuários não quiserem esse comportamento em uma atualização, eles deverão desabilitar explicitamente o comportamento. Esta é uma mudança arriscada, pois dependendo do intervalo, os segmentos serão eliminados imediatamente após serem marcados como não utilizados. este comportamento será revertido ou alterado na próxima versão do druida. Consulte (#12693) para obter mais detalhes.

<a name="0.23.0-upgrading-to-0.23.0-other-changes" href="#0.23.0-upgrading-to-0.23.0-other-changes">#</a> Outras alterações

  • A ingestão do Kinesis requer acesso listShards API no stream.
  • As bibliotecas Kafka clients foram atualizadas para 3.0.0 (#11735)
  • A configuração do coordenador dinâmico, percentOfSegmentsToConsiderPerMove, foi descontinuada e será removida em uma versão futura do Druid. Ela está sendo substituída por uma nova estratégia de seleção de segmentos introduzida em (#11257). Esta nova estratégia está atualmente desativada por padrão, mas pode ser ativada se você definir a configuração do coordenador dinâmico useBatchedSegmentSampler como true. Definir isso como tal desabilitará o uso do obsoleto percentOfSegmentsToConsiderPerMove. Em uma versão futura, useBatchedSegmentSampler se tornará permanentemente verdadeiro. (#11960)

<a name="0.23.0-developer-notices" href="#0.23.0-developer-notices">#</a> Avisos do desenvolvedor

<a name="0.23.0-developer-notices-updated-airline-dependency-to-2.x" href="#0.23.0-developer-notices-updated-airline-dependency-to-2.x">#</a> atualizou a dependência da companhia aérea para 2.x

https://github.com/airlift/airline não é mais mantido e então o druida atualizou para https://github.com/rvesse/airline (Companhia Aérea 2) para usar ativamente versão mantida, minimizando alterações significativas. Esta é uma alteração incompatível com versões anteriores e as extensões personalizadas que dependem do ponto de extensão CliCommandCreator também precisarão ser atualizadas. 12270

<a name="0.23.0-developer-notices-return-404-instead-of-400-for-unknown-supervisors-or-tasks" href="#0.23.0-developer-notices-return-404-instead-of-400-for-unknown-supervisors-or-tasks">#</a> Retorna 404 em vez de 400 para supervisores ou tarefas desconhecidas

O ponto de extremidade anterior do supervisor/tarefa retorna 400 quando um supervisor ou uma tarefa não é encontrado. Este código de status não é amigável e confuso para o terceiro sistema. E de acordo com a definição do código de status HTTP, 404 é o código correto para tal caso. Portanto, alteramos o código de status de 400 para 404 para eliminar a ambigüidade. Quaisquer clients desses terminais devem alterar o tratamento do código de resposta de acordo. 11724

<a name="0.23.0-developer-notices-return-400-instead-of-500-when-sql-query-cannot-be-planned" href="#0.23.0-developer-notices-return-400-instead-of-500-when-sql-query-cannot-be-planned">#</a> Retorna 400 em vez de 500 quando a consulta SQL não pode ser planejada

Qualquer consulta SQL que não possa ser planejada pelo Druid não é considerada uma solicitação incorreta. Para tais consultas, agora retornamos 400. Os desenvolvedores que usam SQL API devem alterar o tratamento do código de resposta, se necessário. 12033

<a name="0.23.0-developer-notices-responsecontext-refactoring" href="#0.23.0-developer-notices-responsecontext-refactoring">#</a> Refatoração ResponseContext

0.23.0 muda o ResponseContext e suas teclas de forma quebradiça. A versão anterior do contexto de resposta sugeria que as chaves fossem definidas em um enum e depois registradas. Esta versão sugere que as chaves sejam definidas como objetos e depois registradas. Consulte a própria classe ResponseContext para obter detalhes. (#11828)

<a name="0.23.0-developer-notices-other-changes" href="#0.23.0-developer-notices-other-changes">#</a> Outras alterações

  • SingleServerInventoryView foi removido. (#11770)
  • LocalInputSource não permite a ingestão do mesmo arquivo várias vezes. (#11965)
  • getType() em PostAggregator foi descontinuado em favor de getType(ColumnInspector) (#11818)
