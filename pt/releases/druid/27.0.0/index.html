O Druid agora oferece suporte à consulta de segmentos armazenados apenas em armazenamento profundo. <a name="27.0.0-highlights-smart-segment-loading" href="#27.0.0-highlights-smart-segment-loading">#</a> Carregamento de segmento inteligente

O Coordenador agora é muito mais estável e fácil de usar. No novo modo smartSegmentLoading, ele calcula valores dinamicamente para diversas configurações que maximizam o desempenho. O Coordenador agora pode priorizar a carga de segmentos mais recentes e segmentos que estão completamente indisponíveis em relação à carga de segmentos que já possuem algumas réplicas carregadas no cluster. Também pode reavaliar decisões tomadas em execuções anteriores e cancelar operações que não são mais necessárias. Além disso, as operações de movimentação iniciadas pelo balanceamento de segmentos não competem com a carga de segmentos indisponíveis, reduzindo assim o tempo de reação para mudanças no cluster e acelerando as decisões de atribuição de segmentos.

Além disso, as mudanças de liderança têm menos impacto agora, e o Coordenador não fica preso, mesmo que a reeleição aconteça enquanto uma candidatura de Coordenador estiver em andamento.

Por último, a estratégia do balanceador cost tem um desempenho muito melhor agora e é capaz de mover mais segmentos em uma única execução do Coordenador. Estas melhorias foram feitas tomando emprestadas ideias da estratégia cachingCost. Recomendamos usar cost em vez de cachingCost, pois cachingCost agora está obsoleto.

Para obter mais informações, consulte o seguinte:

  • Nota de atualização para alterações de configuração relacionadas ao carregamento de segmento inteligente
  • Novas métricas do coordenador
  • Documentação de carregamento de segmento inteligente

<a name="27.0.0-highlights-smart-segment-loading-new-query-filters" href="#27.0.0-highlights-smart-segment-loading-new-query-filters">#</a> Novos filtros de consulta

Druid agora suporta os seguintes filtros:

  • Igualdade: Utilize no lugar do filtro seletor. Nunca corresponde a valores nulos.
  • Nulo: corresponde a valores nulos. Use no lugar do filtro seletor.
  • Intervalo: Filtrar intervalos de valores de dimensão. Use no lugar do filtro vinculado. Nunca corresponde a valores nulos

Observe que o planejador SQL do Druid usa esses novos filtros no lugar de seus equivalentes mais antigos por padrão sempre que druid.generic.useDefaultValueForNull=false ou se sqlUseBoundAndSelectors estiver definido como falso no contexto de consulta SQL.

Você pode usar esses filtros para filtrar igualdade e intervalos em colunas ARRAY em vez de apenas strings com o seletor anterior e filtros vinculados.

Para obter mais informações, consulte Filtros de consulta.

<a name="27.0.0-additional-features-and-improvements-querying-new-broker-configuration-for-sql-schema-migrations" href="#27.0.0-additional-features-and-improvements-querying-new-broker-configuration-for-sql-schema-migrations">#</a> Nova configuração do Broker para migrações de esquema SQL

Agora você pode controlar melhor como o Druid reage às alterações de esquema entre segmentos. Isto pode tornar a consulta mais resiliente quando os segmentos mais recentes introduzem tipos diferentes, como se uma coluna anteriormente contivesse valores LONG e os segmentos mais recentes contivessem STRING.

Use a nova configuração do Broker, druid.sql.planner.metadataColumnTypeMergePolicy, para controlar como os tipos de coluna são calculados para o esquema da tabela SQL quando confrontados com diferenças entre segmentos.

Defina-o como um dos seguintes:

  • leastRestrictive: o esquema só é atualizado quando todos os segmentos forem reindexados para o novo tipo.
  • latestInterval: o esquema SQL é atualizado assim que o primeiro job com o novo esquema publica segmentos no último intervalo de tempo dos dados.

leastRestrictive pode ter melhor comportamento de tempo de consulta e elimina alguns erros de tempo de consulta que podem ocorrer ao usar latestInterval.

<a name="27.0.0-additional-features-and-improvements-dependency-updates" href="#27.0.0-additional-features-and-improvements-dependency-updates">#</a> Atualizações de dependências

As seguintes dependências tiveram suas versões alteradas:

  • Apache DataSketches foi atualizado para 4.1.0. Além disso, o componente datasketches-memory foi atualizado para a versão 2.2.0. #14430
  • O Hadoop foi atualizado para a versão 3.3.6. #14489
  • Avro foi atualizado para a versão 1.11.1. #14440

<a name="27.0.0-additional-features-and-improvements-developer-notes" href="#27.0.0-additional-features-and-improvements-developer-notes">#</a> Notas do desenvolvedor

Introduziu uma nova exceção unificada, DruidException, para revelar erros. É parcialmente compatível com a antiga forma de relatar mensagens de erro. Os códigos de resposta permanecem os mesmos, todos os campos que existiam anteriormente na resposta continuarão existindo e sendo preenchidos, inclusive errorMessage. Algumas mensagens de erro foram alteradas para serem mais consumíveis por humanos e em alguns casos a mensagem foi reestruturada. Não deve haver impacto nos códigos de resposta.

org.apache.druid.common.exception.DruidException foi descontinuado em favor do mais abrangente org.apache.druid.error.DruidException.

org.apache.druid.metadata.EntryExistsException está obsoleto e será removido em uma versão futura. #14004 #14554

<a name="27.0.0-upgrade-notes-and-incompatible-changes" href="#27.0.0-upgrade-notes-and-incompatible-changes">#</a> Notas de atualização e alterações incompatíveis

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Notas de atualização

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-hadoop-2-deprecated" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-hadoop-2-deprecated">#</a> Hadoop 2 obsoleto

Muitas das bibliotecas dependentes importantes que o Druid usa não suportam mais o Hadoop 2. Para que o Druid se mantenha atualizado e tenha caminhos para mitigar vulnerabilidades de segurança, a comunidade decidiu descontinuar o suporte para versões do Hadoop 2.x a partir desta versão. A partir do Druid 28.x, o Hadoop 3.x é a única versão suportada do Hadoop.

Considere migrar para ingestão baseada em SQL ou ingestão nativa se você estiver usando o Hadoop 2.x para ingestão hoje. Se a migração para a ingestão do Druid não for possível, planeje atualizar sua infraestrutura do Hadoop antes de atualizar para a próxima versão do Druid.

Observe que o druid 27 não é compatível com o Hadoop 2. Você deve atualizar seu cluster Hadoop para 3.x antes de atualizar para 27.0.0. Ou você pode construir uma distribuição compatível com Hadoop 2 selecionando explicitamente o perfil Hadoop 2 do artefato de origem druid 27.

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-worker-input-bytes-for-sql-based-ingestion" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-worker-input-bytes-for-sql-based-ingestion">#</a> Bytes de entrada do trabalhador para ingestão baseada em SQL

O máximo de bytes de entrada para cada trabalhador para ingestão baseada em SQL é agora de 512 MiB (anteriormente 10 GiB).

#14307

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-parameter-execution-changes-for-kafka" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-parameter-execution-changes-for-kafka">#</a> Mudanças na execução de parâmetros para Kafka

Ao usar o FileConfigProvider integrado para Kafka, as interpolações agora são interceptadas pelo JsonConfigurator em vez de serem transmitidas ao provedor Kafka. Isso interrompe as implantações existentes.

Para obter mais informações, consulte KIP-297.

#13023

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-groupby-v1-deprecated" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-groupby-v1-deprecated">#</a> GroupBy v1 obsoleto

As consultas GroupBy que usam o mecanismo legado v1 foram descontinuadas. Ele será removido em versões futuras. Use v2 em vez disso. Observe que v2 tem sido o mecanismo GroupBy padrão.

Para obter mais informações, consulte Consultas GroupBy.

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-push-based-real-time-ingestion-deprecated" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-push-based-real-time-ingestion-deprecated">#</a> Ingestão em tempo real baseada em push obsoleta

O suporte para ingestão em tempo real baseada em push foi descontinuado. Ele será removido em versões futuras.

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60cachingcost%60-segment-balancing-strategy-deprecated" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60cachingcost%60-segment-balancing-strategy-deprecated">#</a> Estratégia de balanceamento de segmento cachingCost obsoleta

A estratégia cachingCost foi descontinuada e será removida em versões futuras. Use uma estratégia alternativa de balanceamento de segmento, como cost.

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-loading-config-changes" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-segment-loading-config-changes">#</a> Alterações na configuração de carregamento do segmento

As seguintes configurações relacionadas ao segmento estão obsoletas e serão removidas em versões futuras:

*maxSegmentsInNodeLoadingQueue *maxSegmentsToMove *replicationThrottleLimit *useRoundRobinSegmentAssignment *replicantLifetime *maxNonPrimaryReplicantsToLoad *decommissioningMaxPercentOfMaxSegmentsToMove

Use o modo smartSegmentLoading, que calcula valores para essas variáveis automaticamente.

Além disso, os padrões para as seguintes configurações dinâmicas do Coordenador foram alterados:

  • maxsegmentsInNodeLoadingQueue: 500, anteriormente 100
  • maxSegmentsToMove: 100, anteriormente 5
  • replicationThrottleLimit: 500, anteriormente 10

Esses novos padrões podem melhorar o desempenho na maioria dos casos de uso.

#13197 #14269

<a name="27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60sysmonitor%60-support-deprecated" href="#27.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60sysmonitor%60-support-deprecated">#</a> Suporte SysMonitor obsoleto

Mude para OshiSysMonitor, pois SysMonitor agora está obsoleto e será removido em versões futuras.

<a name="27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Alterações incompatíveis

<a name="27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-property-for-setting-max-bytes-for-dimension-lookup-cache" href="#27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-property-for-setting-max-bytes-for-dimension-lookup-cache">#</a> Propriedade removida para definir o máximo de bytes para cache de pesquisa de dimensão

druid.processing.columnCache.sizeBytes foi removido porque fornecia utilidade limitada após uma série de alterações internas. Deixar esta configuração é inofensivo, mas não faz nada.

#14500

<a name="27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-coordinator-dynamic-configs" href="#27.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-removed-coordinator-dynamic-configs">#</a> Configurações dinâmicas do coordenador removidas

As seguintes configurações dinâmicas do Coordenador foram removidas:

  • emitBalancingStats: Estatísticas de erros encontrados durante o balanceamento sempre serão emitidas. Outras estatísticas de depuração não serão emitidas, mas podem ser registradas configurando o debugDimensions apropriado.
  • useBatchedSegmentSampler e percentOfSegmentsToConsiderPerMove: A amostragem de segmentos em lote agora é o padrão e estará sempre ativada.

Use o novo modo carregamento de segmento inteligente.
