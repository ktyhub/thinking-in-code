<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT e UNPIVOT (experimental)

Druid 29.0.0 adiciona suporte experimental para os operadores SQL PIVOT e UNPIVOT.

O operador PIVOT realiza uma agregação e transforma linhas em colunas na saída. A seguir está a sintaxe geral do operador PIVOT:

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

O operador UNPIVOT transforma valores de colunas existentes em linhas. A seguir está a sintaxe geral do operador UNPIVOT:

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> Suporte de intervalo em funções de janela (experimental)

As funções de janela (experimentais) agora suportam intervalos onde ambos os pontos de extremidade são ilimitados ou são a linha atual. Os intervalos funcionam em modo estrito, o que significa que o Druid falhará em consultas que não são suportadas. Você pode desativar o modo estrito para intervalos definindo o parâmetro de contexto windowingStrictValidation como false.

O exemplo a seguir mostra uma expressão de janela com especificações de quadro RANGE:

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

Tarefas de eliminação aprimoradas da seguinte forma:

  • Resolvido um problema em que o recurso de eliminação automática falhava em respeitar o período de buffer especificado. Isso ocorria quando vários segmentos não utilizados dentro de um intervalo eram marcados como não utilizados em momentos diferentes.
  • Você pode enviar tarefas kill com um parâmetro opcional maxUsedStatusLastUpdatedTime. Quando definida como uma data e hora, a tarefa kill considera os segmentos no intervalo especificado marcados como não utilizados até esse horário. O comportamento padrão é eliminar todos os segmentos não utilizados no intervalo, independentemente do momento em que os segmentos foram marcados como não utilizados.
