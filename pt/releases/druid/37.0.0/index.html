Ingestão baseada em Hadoop

O suporte para ingestão baseada em Hadoop foi removido. O recurso foi descontinuado no Druid 34.

Use um dos outros métodos de ingestão suportados pelo Druid, como ingestão baseada em SQL ou ingestão sem MiddleManager usando Kubernetes.

#19109

Consultar lista de bloqueio

Agora você pode usar o Broker API (/druid/coordinator/v1/config/broker) para criar uma lista de bloqueio de consulta para bloquear consultas dinamicamente por fonte de dados, tipo de consulta ou contexto de consulta. A lista de bloqueio entra em vigor sem reiniciar o Druida. As regras de bloqueio usam a lógica AND, o que significa que todos os critérios devem corresponder.

O exemplo a seguir bloqueia todas as consultas groupBy na origem de dados wikipedia com um parâmetro de contexto de consulta priority igual a 0:

POST /druid/coordinator/v1/config/broker
  {
    "queryBlocklist": [
      {
        "ruleName": "block-wikipedia-groupbys",
        "dataSources": ["wikipedia"],
        "queryTypes": ["groupBy"],
        "contextMatches": {"priority": "0"}
      }
    ]
  }

#19011

Compactação menor para compactação baseada em Overlord (experimental)

Agora você pode configurar a compactação secundária para compactar apenas os segmentos recém-ingeridos enquanto atualiza os segmentos compactados existentes. Quando o Druid atualiza segmentos, ele atualiza os metadados em vez de usar recursos para compactá-los novamente. Você pode usar o mecanismo de compactação nativo ou o mecanismo de tarefa MSQ.

Use a política de compactação mostFragmentedFirst e configure uma porcentagem de limite baseado em linhas ou baseado em bytes para compactação menor.

#19059 #19205 #19016

Reindexação em cascata (experimental)

Usando a reindexação em cascata, agora você pode definir regras baseadas na idade para aplicar automaticamente diferentes configurações de compactação com base na idade dos seus dados. Embora a compactação automática padrão aplique uma única configuração plana em toda uma fonte de dados, a reindexação em cascata permite adaptar as configurações de compactação às características dos seus dados.

Por exemplo, você pode manter os dados recentes em segmentos de hora em hora enquanto acumula automaticamente para segmentos diários após 90 dias para reduzir a contagem de segmentos. Você também pode adicionar camadas à exclusão de linhas com base na idade (como eliminar o tráfego de bot de dados mais antigos), alterar as configurações de compactação ou mudar para rollup com granularidade de consulta mais grosseira à medida que os dados envelhecem. As regras são definidas em linha nas especificações do supervisor.

Você deve usar supervisores de compactação com o mecanismo de tarefa MSQ para usar a reindexação em cascata.

#18983

Autorizador somente leitura

Adicionado um autorizador ReadOnly ao Druid. Este é o primeiro autorizador global para Druid. O autorizador impõe uma restrição global a todas as operações não-READ, negando-as independentemente das permissões individuais do usuário. Você pode usar esse recurso para garantir que todos os usuários de um autorizador específico estejam limitados ao acesso READ.

Há uma limitação conhecida em que alguns terminais atualmente exigem acesso de ESCRITA, apesar de serem somente LEITURA, como GET /druid/indexer/v1/supervisor. Essas operações falharão.

#19128

Contexto de consulta padrão dinâmico

Agora você pode adicionar parâmetros de contexto de consulta padrão como uma configuração dinâmica ao Broker. Isso permite substituir padrões estáticos definidos nas propriedades de tempo de execução sem reiniciar a implantação ou ter que atualizar diversas consultas individualmente. Druid aplica parâmetros de contexto de consulta com base na seguinte prioridade:

  1. O contexto de consulta incluído na consulta
  2. O contexto de consulta definido como uma configuração dinâmica no Broker
  3. Os parâmetros de contexto de consulta definidos nas propriedades de tempo de execução
  4. Os padrões fornecidos com o Druid

Observe que, como outras configurações dinâmicas do Broker, esse é o melhor esforço. As configurações podem não ser aplicadas em determinados casos, como quando um Broker foi iniciado recentemente e ainda não recebeu a configuração, ou se o O corretor não consegue entrar em contato com o coordenador. Se um parâmetro de contexto de consulta for crítico para todas as suas consultas, configure-o nas propriedades de tempo de execução.

#19144

Tabela sys.queries (experimental)

A nova tabela de consultas do sistema fornece informações sobre consultas em execução e consultas concluídas recentemente que usam o mecanismo Dart. Esta tabela está desativada por padrão. Para ativar a tabela, defina o seguinte:

druid.sql.planner.enableSysQueriesTable = true

Como parte dessa mudança, o /druid/v2/sql/queries API agora suporta um parâmetro includeComplete que mostra consultas concluídas recentemente.

#18923

Compactação automática com supervisores de compactação

A compactação automática usando supervisores de compactação foi aprimorada, agora está disponível para todos e é o padrão recomendado. As tarefas de compactação automática agora têm o prefixo auto em vez de coordinator-issued.

Como parte da melhoria, os estados de compactação são agora armazenados num local central, uma nova tabela indexingStates. Os segmentos individuais só precisam armazenar uma referência exclusiva (indexing_state_fingerprint) para o seu estado de compactação total.

Como muitos segmentos em uma única fonte de dados compartilham o mesmo estado de compactação subjacente, isso reduz bastante os requisitos de armazenamento de metadados para compactação automática.

Para compatibilidade com versões anteriores, o Druid continua a persistir o estado detalhado de compactação em cada segmento. Esta funcionalidade será removida em uma versão futura. Você pode parar de armazenar o estado de compactação detalhado configurando storeCompactionStatePerSegment como false na configuração de compactação de cluster. Se você desligá-lo e precisar fazer o downgrade, o Druid precisará recompactar todos os segmentos que foram compactados desde que você alterou a configuração.

Essa alteração tem impactos de atualização no armazenamento de metadados e no cache de metadados. Para obter mais informações, consulte a nota de atualização Armazenamento de metadados para compactação automática com supervisores de compactação.

#19141

Manipulação aprimorada de agregações aninhadas

Druida agora pode mesclar dois agregados com uma projeção entre eles. Por exemplo, a seguinte consulta:

SELECT
  hr,
  UPPER(t1.x) x,
  SUM(t1.cnt) cnt,
  MIN(t1.mn) mn,
  MAX(t1.mx) mx
FROM (
  SELECT
    floor(__time to hour) hr,
    dim2 x,
    COUNT(*) cnt,
    MIN(m1 * 5) mn,
    MAX(m1 + m2) mx
  FROM druid.foo
  WHERE dim2 IN ('abc', 'def', 'a', 'b', '')
  GROUP BY 1, 2
) t1
WHERE t1.x IN ('abc', 'foo', 'bar', 'a', '')
GROUP BY 1, 2

pode ser simplificado para o seguinte:

SELECT
  FLOOR(__time TO hour) hr,
  UPPER(dim2) x,
  COUNT(*) cnt,
  MIN(m1 * 5) mn,
  MAX(m1 + m2) mx
FROM druid.foo
WHERE dim2 IN ('abc', 'a', '')
GROUP BY 1, 2

Gerenciamento de cluster

Novas estratégias de seleção de nível de corretor

As operadoras agora podem configurar duas novas implementações do Broker TierSelectorStrategy:

  • strict - Seleciona apenas servidores cujas prioridades correspondam à lista configurada. Exemplo de configuração: druid.broker.select.tier=strict e druid.broker.select.tier.strict.priorities=[1].
  • pooled – Agrupa servidores nas prioridades configuradas e seleciona entre elas, permitindo que as consultas usem vários níveis de prioridade para melhorar a disponibilidade. Configuração de exemplo: druid.broker.select.tier=pooled e druid.broker.select.tier.pooled.priorities=[2,1].

Você também pode usar druid.broker.realtime.select.tier para configurar essas estratégias para servidores em tempo real.

Gerenciamento de dados

Configuração de tempo limite por segmento

Agora você pode definir um tempo limite para os segmentos em uma fonte de dados específica usando uma configuração dinâmica:

POST /druid/coordinator/v1/config/broker
  {
    "perSegmentTimeoutConfig": {
      "my_large_datasource": { "perSegmentTimeoutMs": 5000, "monitorOnly": false },

Isso é útil quando fontes de dados diferentes têm características de desempenho diferentes — por exemplo, permitindo tempos limites mais longos para conjuntos de dados maiores.

#19221

Limpador de armazenamento durável

O limpador de armazenamento durável agora oferece suporte à retenção configurável baseada em tempo para resultados de consultas MSQ. Anteriormente, os resultados da consulta eram retidos para todas as tarefas conhecidas, o que não era confiável para tarefas concluídas. Com essa alteração, os resultados da consulta são retidos por um período configurável com base no horário de criação da tarefa.

A nova propriedade de configuração druid.msq.intermediate.storage.cleaner.durationToRetain controla o período de retenção dos resultados da consulta. O período de retenção padrão é de 6 horas.

Segmentar cache de metadados ativado por padrão

A partir do Druid 37, o cache de metadados de segmento está ativado por padrão. Esse recurso permite que o Broker armazene em cache os metadados do segmento pesquisados ​​no Coordenador, em vez de ter que buscar metadados para cada consulta na tabela sys.segments. Isso melhora o desempenho, mas aumenta o uso de memória nos Brokers.

A configuração do druid.sql.planner.metadataSegmentCacheEnable controla esse recurso.

#19075

Mudanças no analisador

Ingestão de streaming parser

O suporte para o obsoleto parser foi removido para tarefas de ingestão de streaming, como Kafka e Kinesis. Os operadores agora devem especificar inputSource/inputFormat no ioConfig da especificação do supervisor, e o dataSchema não deve especificar um analisador. Faça isso antes de atualizar para o Druid 37 ou mais recente.

#19173 #19166

ParseSpec removido e analisadores obsoletos

O analisador para tarefas em lote nativas e serviços de indexação de ingestão de streaming foi removido. Sempre que possível, use o formato de entrada. Observe que JavascriptParseSpec e JSONLowercaseParseSpec não possuem equivalentes de InputFormat.

Druid suporta formatos de dados de texto personalizados e pode usar o formato de entrada Regex para analisá-los. No entanto, esteja ciente de fazer isso para analisar dados é menos eficiente do que escrever uma extensão Java InputFormat nativa ou usar um processador de fluxo externo. Aceitamos contribuições de novos formatos de entrada.

#19239

Atualizações contínuas de versões Druid anteriores à versão 0.23

Você não pode realizar uma atualização contínua de versões anteriores ao Druid 0.23.

#18961

Armazenamento de metadados para compactação automática com supervisores de compactação

A compactação automática com supervisores requer cache incremental de metadados de segmento no Overlord e uma nova tabela de armazenamento de metadados; nenhuma ação será necessária se você estiver usando as configurações padrão para as seguintes configurações:

-druid.manager.segments.useIncrementalCache -druid.metadata.storage.connector.createTables

Se druid.manager.segments.useIncrementalCache estiver definido como never, atualize-o para ifSynced ou always. Para obter mais informações sobre a configuração, consulte Cache de metadados de segmento.

Se você definir a configuração druid.metadata.storage.connector.createTables como false, será necessário alterar manualmente a tabela de segmentos e criar a tabela compactionStates. O DDL do Postgres é fornecido abaixo como um guia:

-- create the indexing states lookup table and associated indices
CREATE TABLE druid_indexingStates (
    created_date VARCHAR(255) NOT NULL,
    datasource VARCHAR(255) NOT NULL,
    fingerprint VARCHAR(255) NOT NULL,
    payload BYTEA NOT NULL,
    used BOOLEAN NOT NULL,
    pending BOOLEAN NOT NULL,
    used_status_last_updated VARCHAR(255) NOT NULL,
    PRIMARY KEY (fingerprint),
  );

  CREATE INDEX idx_druid_compactionStates_used ON druid_compactionStates(used, used_status_last_updated);

-- modify druid_segments table to have a column for storing compaction state fingerprints
ALTER TABLE druid_segments ADD COLUMN indexing_state_fingerprint VARCHAR(255);

Talvez seja necessário adaptar a sintaxe para se adequar ao prefixo de nomenclatura da tabela e ao back-end do armazenamento de metadados.

#18844

Bloqueio de segmento

O bloqueio de segmento e NumberedOverwriteShardSpec estão obsoletos e serão removidos em uma versão futura. Use o bloqueio de bloco de tempo. Você pode garantir que apenas o bloqueio de bloco de tempo seja usado configurando druid.indexer.tasklock.forceTimeChunkLock como true, que é o padrão.

#19050

Alterações incompatíveis

Configuração defaultProcessingRate removida

Essa configuração permitiu que as ações de escalonamento começassem antes da disponibilização das primeiras métricas.

#19028

Formato de codificação frontal

Druid agora tem como padrão v1 do formato de código frontal em vez da versão 0, se habilitado. A versão 1 foi introduzida no Druid 26. Fazer o downgrade ou atualizar de uma versão do Druid anterior à 26 pode exigir reindexação se você tiver a codificação frontal habilitada na versão 0.
