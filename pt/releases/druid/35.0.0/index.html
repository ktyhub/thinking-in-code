druida druida-35.0.0

Apache Druid 35.0.0 contém mais de 229 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de teste adicional de 29 colaboradores.

Consulte o conjunto completo de alterações para obter detalhes adicionais, incluindo correções de bugs.

Revise as notas de atualização e alterações incompatíveis antes de atualizar para o Druid 35.0.0. Se você estiver atualizando várias versões, consulte a página Notas de atualização, que lista notas de atualização para as versões mais recentes do Druid.

<a name="35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29" href="#35.0.0-important-features%2C-changes%2C-and-deprecations-virtual-storage-%28experimental%29">#</a> Armazenamento virtual (experimental)

O modo de malha de armazenamento virtual permite que os servidores históricos sirvam mais segmentos do que o disco físico pode conter. Em vez de carregar segmentos quando são publicados, os segmentos são carregados sob demanda durante as consultas. Quaisquer segmentos desnecessários são removidos do disco, mas são carregados novamente quando o processamento de uma consulta requer esse segmento específico.

Para ativar o armazenamento virtual, configure druid.segmentCache.virtualStorage como true.

Druid agora suporta um formato de entrada lines. Druid lê cada linha de uma entrada como texto UTF-8 e cria uma única coluna chamada line que contém a linha inteira como uma string. Use isto para ler dados orientados a linhas em um formato simples para processamento posterior.

O mecanismo de tarefas MSQ agora é um recurso central do Druid, em vez de uma extensão. Ela está na lista de carregamento de extensões padrão há vários lançamentos.

Remova druid-multi-stage-query de druid.extensions.loadList em common.runtimes.properties antes de atualizar.

Druid 35.0.0 irá ignorar a extensão se estiver na lista de carregamento. Versões futuras do Druid não serão iniciadas porque não conseguem localizar a extensão.

Agora você pode especificar monitores em common.runtime.properties e cada monitor será carregado somente nos tipos de servidor aplicáveis. Anteriormente, era necessário definir monitores no arquivo runtime.properties específico para o serviço ao qual o monitor se destina.

<a name="35.0.0-functional-area-and-related-changes-querying-segment-timeout" href="#35.0.0-functional-area-and-related-changes-querying-segment-timeout">#</a> Tempo limite do segmento

Agora você pode configurar o tempo limite para o processamento do segmento de uma consulta.

Para definir um tempo limite, defina druid.processing.numTimeoutThreads para um número baixo, como 3, em todos os nós de dados onde deseja que esse recurso seja ativado.

Em seguida, inclua o parâmetro de contexto de consulta perSegmentTimeout em sua consulta e configure-o com um valor em milissegundos.

Druid agora oferece suporte ao cache em nível de resultado para consultas de verificação.

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-jetty-12-">#</a> Cais 12

O Druid agora usa Jetty 12. Sua implantação pode ser afetada dependendo, especificamente no que diz respeito à conformidade de URI e verificações de host SNI.

Uma nova opção de configuração de servidor foi adicionada: druid.server.http.uriCompliance. Por padrão, o Jetty 12 tem aplicação estrita do formato URI RFC3986. Esta é uma mudança do Jetty 9. Para evitar possíveis alterações significativas nas implantações existentes do Druid, esta configuração é padronizada como LEGACY, que usa a imposição de formato URI mais permissiva que o Jetty 9 usou. Se o cluster que você opera não requer compatibilidade herdada, recomendamos que você use o padrão upstream Jetty de RFC3986 em sua implantação Druid. Consulte a documentação do cais para obter mais informações.

Os servidores Jetty 12 fazem verificações rigorosas do SNI host0 quando o TLS está ativado. Se o host com o qual seu client está se conectando ao servidor não corresponder ao que está no keystore, mesmo que haja apenas um certificado nesse keystore, ele retornará uma resposta 400. Isso pode afetar alguns casos de uso, como pessoas que se conectam pelo localhost por qualquer motivo. Se essa alteração interromper sua implementação, você poderá cancelar a alteração definindo druid.server.http.enforceStrictSNIHostChecking como false em runtime.properties para alguns ou todos os seus serviços Druid. É recomendado que você modifique o comportamento do client para acomodar essa alteração no jetty em vez de substituir a configuração sempre que possível.

#18424 #18623

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-kerberos-authentication">#</a> Autenticação Kerberos

A configuração do druid.auth.authenticator.kerberos.cookieSignatureSecret agora é obrigatória.

#18368

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-multi-stage-query-task-engine">#</a> Mecanismo de tarefa de consulta em vários estágios

O mecanismo de tarefas MSQ agora é um recurso central do Druid, em vez de uma extensão. Ela está na lista de carregamento de extensões padrão há vários lançamentos.

Remova druid-multi-stage-query de druid.extensions.loadList em common.runtimes.properties antes de atualizar.

Druid 35.0.0 irá ignorar a extensão se estiver na lista de carregamento. Versões futuras do Druid não serão iniciadas porque não conseguem localizar a extensão.

#18394

<a name="35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension" href="#35.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-pac4j-extension">#</a> extensão pac4j

Devido à atualização do pac4j 4 para 5, a serialização da sessão mudou do JavaSerializer do pac4j para a serialização Java padrão. Como resultado, clients de clusters que usam a extensão pac4j podem ser desconectados durante atualizações contínuas e precisarem ser autenticados novamente.

#18259

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Alterações incompatíveis

<a name="35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes-java-11-support-removed">#</a> Suporte a Java 11 removido

Atualize para Java 17 ou 21. Observe que algumas versões do Java 21 encontraram problemas durante o teste, especificamente Java 21.05-21.07. Se possível, evite essas versões.

#18424

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Notas do desenvolvedor

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-embedded-cluster-tests">#</a> Testes de cluster incorporados

Você pode usar a nova estrutura de teste de cluster incorporada para executar testes de integração leves usando um cluster Druid totalmente funcional que é executado em um único processo, incluindo quaisquer extensões que você deseja carregar, bem como armazenamento de metadados ZooKeeper e Derby. Você não precisa mais executar o mvn build, criar uma imagem docker ou até mesmo executar scripts de inicialização para realizar testes de integração.

#18147

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-specialized-virtual-columns-for-json">#</a> Colunas virtuais especializadas para JSON

O ColumnHolder retornado por ColumnSelector agora retorna um SelectableColumn em vez de BaseColumn de getColumn(). O SelectableColumn pode ser um BaseColumn ou pode ser uma implementação fornecida por uma coluna virtual. Extensões que precisam recuperar colunas físicas de um ColumnSelector podem verificar se a coluna é um BaseColumn usando instanceof. Por conveniência, o tipo de retorno getColumnHolder em QueryableIndex foi especializado para BaseColumnHolder, que sempre retorna BaseColumn de getColumn(). Extensões que chamam esse método em QueryableIndex podem armazenar o resultado em uma variável do tipo BaseColumnHolder para evitar a necessidade de converter a coluna.

#18521

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60reset-cluster%60-tool-removed">#</a> Ferramenta reset-cluster removida

A ferramenta orientada ao ambiente de desenvolvimento e teste reset-cluster foi removida. Ele estava desatualizado e não conseguia limpar completamente o armazenamento de metadados (tabelas upgradeSegments e segmentSchemas ausentes adicionadas no Druid 28 e 30, respectivamente). Esta ferramenta não se destina a casos de uso de produção, portanto não deverá haver impacto para os operadores de cluster.

#18246

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-breaking-change-for-sql-metadata-extensions">#</a> Alteração significativa para extensões de metadados SQL

O ponto de extensão MetadataStorageActionHandler agora possui APIs mais simples. Esta é uma alteração significativa para quaisquer extensões de metadados SQL existentes. As alterações para PostgreSQL, MySQL e SQLServer já foram concluídas. #18479

<a name="35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed" href="#35.0.0-upgrade-notes-and-incompatible-changes-developer-notes-%60driudleaderclient%60-removed">#</a> DriudLeaderClient removido

DruidLeaderClient foi removido das extensões e substituído por uma implementação baseada em ServiceClient. Além disso, CoordinatorServiceClient para consultar APIs não essenciais expostos pelo Coordenador está disponível por meio de druid-server.
