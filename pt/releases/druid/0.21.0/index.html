druida druida-0.21.0

Apache Druid 0.21.0 contém cerca de 120 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de teste adicional de 36 colaboradores. Consulte a lista completa de alterações e tudo o que está marcado no marco para obter mais detalhes.

<a name="21-new-features" href="#21-new-features">#</a> Novos recursos

<a name="21-operação" href="#21-operação">#</a> Operação

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Descoberta de serviço e eleição de líder com base em Kubernetes

A nova extensão Kubernetes suporta descoberta de serviço e eleição de líder com base em Kubernetes. Esta extensão funciona em conjunto com a visualização do servidor baseada em HTTP (druid.serverview.type=http) e o gerenciamento de tarefas (druid.indexer.runner.type=httpRemote) para permitir que você execute um cluster Druid com zero dependências ZooKeeper. Esta extensão ainda é experimental. Consulte extensão Kubernetes para obter mais detalhes. https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> Nova configuração de coordenador dinâmico para limitar o número de segmentos ao encontrar um segmento candidato para balanceamento de segmento

Você pode configurar o percentOfSegmentsToConsiderPerMove para limitar o número de segmentos considerados ao escolher um segmento candidato para mover. Os candidatos são pesquisados ​​até maxSegmentsToMove * 2 vezes. Essa nova configuração evita que o Druid itere por todos os segmentos disponíveis para acelerar o processo de balanceamento de segmentos, especialmente se você tiver muitos segmentos disponíveis em seu cluster. Consulte Configuração dinâmica do coordenador para obter mais detalhes. https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> endpoints status e selfDiscovered para indexadores

O indexador agora suporta endpoints status e selfDiscovered. Consulte Informações do processador APIs para obter detalhes. https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Consultando

<a name="21-grouping-function" href="#21-grouping-function">#</a> Nova função agregadora grouping

É possível usar a nova função SQL do agregador grouping com GROUPING SETS ou CUBE para indicar quais dimensões de agrupamento estão incluídas no conjunto de agrupamento atual. Consulte Funções de agregação para obter mais detalhes. https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Tratamento aprimorado de argumentos ausentes em expressões e funções

O processamento de expressões agora pode ser vetorizado quando faltam entradas. Por exemplo, uma coluna inexistente. Quando falta um argumento em uma expressão, o Druida agora pode inferir o tipo adequado de resultado com base em argumentos não nulos. Por exemplo, para longColumn + nonExistentColumn, nonExistentColumn é tratado como (long) 0 em vez de (double) 0.0. Finalmente, no modo de tratamento de nulos padrão, as funções matemáticas podem produzir resultados adequadamente tratando os argumentos ausentes como zeros. https://github.com/apache/druid/pull/10499

<a name="21-timestapadd" href="#21-timestapadd">#</a> Permitir período zero para TIMESTAMPADD

A função TIMESTAMPADD agora permite período zero. Esta funcionalidade é necessária para algumas ferramentas de BI, como o Tableau. https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Ingestão

<a name="21-parallel-ingestion-without-intervals" href="#21-parallel-ingestion-without-intervals">#</a> A ingestão paralela nativa não requer mais intervalos explícitos

A tarefa paralela não exige mais que você defina intervalos explícitos no granularitySpec. Se faltarem intervalos, a tarefa paralela executa uma etapa extra para amostragem de entrada que coleta os intervalos para indexar. https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Suporte à versão antiga do Kafka

Druid agora suporta Apache Kafka mais antigo que 0.11. Para ler uma versão antiga do Kafka, defina isolation.level como read_uncommitted em consumerProperties. Apenas 0.10.2.1 foram testados até este lançamento. Consulte Configurações do supervisor Kafka para obter detalhes. https://github.com/apache/druid/pull/10551

Mesclagem de segmentos multifásicos para ingestão de lote nativo

Um novo tuningConfig, maxColumnsToMerge, controla quantos segmentos podem ser mesclados ao mesmo tempo na tarefa. Essa configuração pode ser útil para evitar alta pressão de memória durante a mesclagem. Consulte tuningConfig para ingestão de lote nativo para obter mais detalhes. https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> A reingestão nativa consome menos memória

As tarefas paralelas agora classificam os segmentos por ID antes de atribuí-los às subtarefas. Essa classificação minimiza o número de intervalos de tempo para cada subtarefa manipular. Como resultado, espera-se que cada subtarefa utilize menos memória, especialmente quando uma única tarefa Paralela é emitida para reingerir segmentos que cobrem um longo período de tempo. https://github.com/apache/druid/pull/10646

<a name="21-web-console" href="#21-web-console">#</a> Console web

<a name="21-refresh-console-style" href="#21-refresh-console-style">#</a> Estilos de console web atualizados e aprimorados

Os novos estilos de console da web fazem melhor uso das cores da marca Druid e padronizam preenchimentos e margens. O ícone e as cores de fundo agora são derivados do logotipo do Druida. https://github.com/apache/druid/pull/10515

<a name="21-web-console-partitioning" href="#21-web-console-partitioning">#</a> As informações de particionamento estão disponíveis no console da web

O console da web agora mostra informações de particionamento da fonte de dados nas novas colunas Segment granularity e Partitioning.

Coluna Segment granularity na guia Datasources

Coluna Partitioning na aba Segments

https://github.com/apache/druid/pull/10533

<a name="21-web-console-dim-ordering" href="#21-web-console-dim-ordering">#</a> A ordem das colunas na tabela Schema corresponde à dimensionsSpec

A tabela Schema agora reflete a ordem das dimensões no dimensionsSpec. https://github.com/apache/druid/pull/10588

<a name="21-metrics" href="#21-metrics">#</a> Métricas

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Métricas de tempo de execução de serviço do coordenador

O coordenador executa diversas tarefas de “dever”. Por exemplo, balanceamento de segmentos, carregamento de novos segmentos, etc. Agora existem duas novas métricas para ajudá-lo a analisar a rapidez com que o Coordenador está executando essas tarefas.

  • coordinator/time: o tempo de execução de um dever individual
  • coordinator/global/time: o tempo para todas as tarefas executáveis serem executadas https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Métrica de tempo limite de consulta

Uma nova métrica fornece o número de consultas que atingiram o tempo limite. Consultas anteriormente expiradas foram tratadas como interrompidas e incluídas no query/interrupted/count (consulte [Códigos de status HTTP alterados para erros de consulta](#21-códigos de erro http) para obter mais detalhes). query/timeout/count: o número de consultas expiradas durante o período de emissão https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Métricas aleatórias para ingestão em lote

Duas novas métricas fornecem estatísticas aleatórias para MiddleManagers e Indexadores. Essas métricas têm como dimensão o supervisorTaskId.

  • ingest/shuffle/bytes: número de bytes embaralhados por período de emissão
  • ingest/shuffle/requests: número de solicitações de embaralhamento por período de emissão Para ativar as métricas aleatórias, adicione org.apache.druid.indexing.worker.shuffle.ShuffleMonitor em druid.monitoring.monitors. Consulte Métricas aleatórias para obter mais detalhes. https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> Novo agendador de monitoramento de métricas seguro contra desvio de relógio

O agendador de monitor de métricas padrão é implementado com base em ScheduledThreadPoolExecutor, que é propenso a [desvio de clock] ilimitado (https://en.wikipedia.org/wiki/Clock_drift). Um novo agendador de monitor, ClockDriftSafeMonitorScheduler, supera esta limitação. Para usar o novo planejador, configure druid.monitoring.schedulerClassName como org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler no arquivo runtime.properties. https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

Uma nova coluna de tipo longo is_leader na tabela sys.servers indica se o servidor é ou não o líder. https://github.com/apache/druid/pull/10680

<a name="21-development" href="#21-development">#</a> Desenvolvimento

<a name="21-dynamic-config-provider" href="#21-dynamic-config-provider">#</a> Propriedades extensíveis do consumidor Kafka por meio de um novo DynamicConfigProvider

Uma nova classe DynamicConfigProvider permite buscar propriedades do consumidor em tempo de execução. Por exemplo, você pode usar DynamicConfigProvider para buscar bootstrap.servers de um local, como uma variável de ambiente local, se não for estático. Atualmente, apenas um provedor de configuração baseado em mapa é compatível por padrão. Consulte DynamicConfigProvider para saber como implementar um provedor de configuração personalizado. https://github.com/apache/druid/pull/10309

<a name="21-bug-fixes" href="#21-bug-fixes">#</a> Correções de bugs

Druida 0.21.0 contém 30 correções de bugs, você pode ver a lista completa aqui.

<a name="21-post-agg-subtotal" href="#21-post-agg-subtotal">#</a> Cálculo pós-agregador com subtotais

Antes de 0.21.0, a consulta falhava com um erro ao usar agregadores de postagem com subtotais. Agora esse bug foi corrigido e você pode usar agregadores de postagem com subtotais. https://github.com/apache/druid/pull/10653

<a name="21-indexer-announce" href="#21-indexer-announce">#</a> Indexadores se anunciam como servidores de segmento

Em 0.19.0 e 0.20.0, os indexadores não puderam processar consultas em dados de streaming porque não se anunciaram como servidores de segmento. Eles foram configurados para se anunciarem corretamente no 0.21.0. https://github.com/apache/druid/pull/10631

<a name="21-historical-segment-loading" href="#21-historical-segment-loading">#</a> Verificação de validade para arquivos de segmento em históricos

Os históricos agora realizam verificação de validade depois de baixarem arquivos de segmento e baixam novamente automaticamente se esses arquivos travarem. https://github.com/apache/druid/pull/10650

<a name="21-storage-location-selector" href="#21-storage-location-selector">#</a> A falha de injeção do StorageLocationSelectorStrategy foi corrigida

A falha de injeção durante a leitura das configurações do StorageLocationSelectorStrategy foi corrigida. https://github.com/apache/druid/pull/10363

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> Atualizando para 0.21.0

Considere as seguintes alterações e atualizações ao atualizar do Druid 0.20.0 para 0.21.0. Se você estiver atualizando de uma versão anterior à 0.20.0, consulte os release notes das versões intermediárias relevantes.

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Códigos de status HTTP aprimorados para erros de consulta

Antes deste lançamento, o Druid retornava o "erro interno (500)" para a maioria dos erros de consulta. Agora o Druid retorna diferentes códigos de erro com base em sua causa. A tabela a seguir lista os erros e seus códigos correspondentes que foram alterados: Exceção | Descrição| Código antigo | Novo código ------------ | ------------- | ------------- | ------------- SqlParseException e ValidationException da Calcite | Falha no planejamento da consulta | 500 | 400 QueryTimeoutException | A execução da consulta não terminou no tempo limite | 500 | 504 ResourceLimitExceededException | A consulta solicitou mais recursos do que o limite configurado | 500 | 400 InsuficienteResourceException | Falha no agendamento da consulta devido à falta de buffers de mesclagem disponíveis no momento em que foi enviada | 500 | 429, mesclado com QueryCapacityExceededException QueryUnsupportedException | Funcionalidade não suportada | 400 | 501 Há também uma nova métrica de consulta para erros de tempo limite de consulta. Consulte Nova métrica de tempo limite de consulta para obter mais detalhes. https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Métrica de consulta interrompida

query/interrupted/count não conta mais as consultas que expiraram. Essas consultas são contadas pelo query/timeout/count.

<a name="21-context-dimension" href="#21-context-dimension">#</a> Dimensão context em métricas de consulta

context agora é uma dimensão padrão emitida para todas as métricas de consulta. context é uma string formatada em JSON que contém o contexto da consulta à qual a métrica emitida se refere. A adição de uma dimensão que não existia anteriormente altera algumas métricas emitidas pelo Druida. Você deve planejar lidar com essa nova dimensão context em seu pipeline de métricas. Como a dimensão é uma string formatada em JSON, uma solução comum é analisar a dimensão e achatá-la ou extrair os bits desejados e descartar o blob de string completo no formato JSON. https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Suporte obsoleto para Apache ZooKeeper 3.4

Como ZooKeeper 3.4 está em fim de vida há algum tempo, o suporte para ZooKeeper 3.4 está obsoleto em 0.21.0 e será removido em um futuro próximo. https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Formato de serialização consistente e convenção de nomenclatura de coluna para a tabela sys.segments

Todas as colunas da tabela sys.segments agora são serializadas no formato JSON para torná-las consistentes com outras tabelas do sistema. Os nomes das colunas agora usam a mesma convenção de "caso de cobra". https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Problemas conhecidos

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Vulnerabilidade de segurança conhecida na biblioteca Thrift

A extensão Thrift pode ser útil para ingerir arquivos do formato Thrift no Druid. No entanto, existe uma vulnerabilidade de segurança conhecida na versão da biblioteca Thrift que o Druid usa. A vulnerabilidade pode ser explorada pela ingestão de arquivos Thrift criados com códigos maliciosos ao usar indexadores. Recomendamos conceder a permissão DATASOURCE WRITE apenas a usuários trusted.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Problemas de permissão na execução do cluster Druid baseado em docker

Se você executar o cluster Druid docker pela primeira vez em sua máquina, usando a imagem 0.21.0 poderá criar diretórios internos com a conta root. Como resultado, os serviços Druidas podem falhar devido à falta de permissões. Este problema está arquivado em https://github.com/apache/druid/issues/11166. Se estiver usando o docker compose, você pode usar os comandos abaixo para solucionar esse problema. Esses comandos criarão diretórios internos primeiro usando uma imagem antiga e depois iniciarão serviços usando a imagem 0.21.0.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

Se você não estiver usando o docker compose, poderá passar diretamente o parâmetro de volume para /opt/druid/var ao iniciar serviços usando a imagem 0.21.0. Por exemplo, você pode executar o comando abaixo para iniciar o serviço de coordenador.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

Para obter uma lista completa de problemas em aberto, consulte https://github.com/apache/druid/labels/Bug.
