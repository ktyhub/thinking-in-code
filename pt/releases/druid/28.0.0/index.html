druida druida-28.0.0

Apache Druid 28.0.0 contém mais de 420 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de testes adicionais de 57 colaboradores.

Consulte o conjunto completo de alterações para obter detalhes adicionais, incluindo correções de bugs.

Revise as notas de atualização e alterações incompatíveis antes de atualizar para o Druid 28.0.0.

<a name="28.0.0-important-changes-and-deprecations" href="#28.0.0-important-changes-and-deprecations">#</a> Recursos importantes, alterações e descontinuações

No Druid 28.0.0, fizemos melhorias substanciais nas consultas para tornar o sistema mais compatível com ANSI SQL. Isso inclui alterações no tratamento de valores NULL e booleanos, bem como na lógica booleana. Ao mesmo tempo, a biblioteca Apache Calcite foi atualizada para a versão mais recente. Embora tenhamos documentado alterações conhecidas no comportamento da consulta, leia a seção notas de atualização com atenção. Teste seu aplicativo antes de implementá-lo em cenários de produção amplos enquanto monitora de perto o status da consulta.

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility" href="#28.0.0-important-changes-and-deprecations-sql-compatibility">#</a> Compatibilidade SQL

Druid continua a tornar a execução de consultas SQL mais consistente com o comportamento do SQL padrão. No entanto, existem sinalizadores de recursos disponíveis para restaurar o comportamento antigo, se necessário.

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-three-valued-logic">#</a> Lógica de três valores

Os filtros nativos do Druida agora observam SQL lógica de três valores (true, false ou unknown) em vez da lógica clássica de dois estados do Druida por padrão, quando as seguintes configurações padrão se aplicam:

*druid.generic.useThreeValueLogicForNativeFilters = true *druid.expressions.useStrictBooleans = true *druid.generic.useDefaultValueForNull = false

#15058

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-strict-booleans">#</a> Booleanos estritos

druid.expressions.useStrictBooleans agora está habilitado por padrão. Druid agora lida com booleanos estritamente usando 1 (true) ou 0 (false). Anteriormente, verdadeiro e falso podiam ser representados como true e false, bem como 1 e 0, respectivamente. Além disso, Druid agora retorna um valor nulo para comparações booleanas como True && NULL.

Se você não configurar explicitamente essa propriedade em runtime.properties, os clusters agora usarão tipos LONG para quaisquer valores booleanos ingeridos e na saída de funções booleanas para transformações e operações de tempo de consulta. Para obter mais informações, consulte Compatibilidade SQL nas notas de atualização.

#14734

<a name="28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling" href="#28.0.0-important-changes-and-deprecations-sql-compatibility-null-handling">#</a> Tratamento NULL

druid.generic.useDefaultValueForNull agora está desabilitado por padrão. Druid agora diferencia entre registros vazios e registros nulos. Anteriormente, o Druida poderia tratar registros vazios como vazios ou nulos. Para obter mais informações, consulte Compatibilidade SQL nas notas de atualização.

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements">#</a> Melhorias no planejador SQL

Druid usa Apache Calcite para planejamento e otimização de SQL. Começando no Druid 28.0.0, a versão Calcite foi atualizada de 1.21 para 1.35. Esta atualização traz muitas correções de bugs no planejamento SQL do Calcite.

<a name="28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters" href="#28.0.0-important-changes-and-deprecations-sql-planner-improvements-dynamic-parameters">#</a> Parâmetros dinâmicos

Como parte da atualização do Calcite, o comportamento da inferência de tipo para parâmetros dinâmicos mudou. Para evitar qualquer problema de interferência de tipo, CAST explicitamente todos os parâmetros dinâmicos como um tipo de dados específico em consultas SQL. Por exemplo, use:

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

Não use:

SELECT (1 * ?)/2 as tmp

Consulta de armazenamento profundo não é mais um recurso experimental. Quando você consulta no armazenamento profundo, mais dados ficam disponíveis para consultas sem precisar dimensionar seus serviços históricos para acomodar mais dados. Para aproveitar a economia de espaço que a consulta do armazenamento profundo oferece, configure suas regras de carregamento para descarregar dados dos seus serviços históricos.

<a name="28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats" href="#28.0.0-important-changes-and-deprecations-async-query-and-query-from-deep-storage-support-for-multiple-result-formats">#</a> Suporte para vários formatos de resultados

A consulta do armazenamento profundo agora oferece suporte a vários formatos de resultados. Anteriormente, o endpoint /druid/v2/sql/statements/ suportava apenas resultados no formato object. Agora os resultados podem ser escritos em qualquer formato especificado no parâmetro resultFormat. Para obter mais informações sobre parâmetros de resultado suportados pelo Druid SQL API, consulte Respostas.

<a name="28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource" href="#28.0.0-important-changes-and-deprecations-ingest-from-multiple-kafka-topics-to-a-single-datasource">#</a> Ingestão de vários tópicos do Kafka em uma única fonte de dados

Agora você pode ingerir dados de streaming de vários tópicos do Kafka para uma fonte de dados usando um único supervisor. A função UNNEST não é mais experimental.

Druid agora oferece suporte a UNNEST na ingestão de lote baseada em SQL e consulta de armazenamento profundo, para que você possa nivelar arrays facilmente. Para obter mais informações, consulte UNNEST e Desaninhar matrizes em uma coluna.

<a name="28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest" href="#28.0.0-important-changes-and-deprecations-sql-unnest-and-ingestion-flattening-recommended-syntax-for-sql-unnest">#</a> Sintaxe recomendada para SQL UNNEST

A sintaxe recomendada para SQL UNNEST foi alterada. Recomendamos usar CROSS JOIN em vez de vírgulas para a maioria das consultas para evitar problemas de precedência. Por exemplo, use:

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

Não use:

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

<a name="28.0.0-important-changes-and-deprecations-window-functions-%28experimental%29" href="#28.0.0-important-changes-and-deprecations-window-functions-%28experimental%29">#</a> Funções de janela (experimental)

Você pode usar funções de janela no Apache Druid para produzir valores com base no relacionamento de uma linha dentro de uma janela de linhas com as outras linhas dentro da mesma janela. Uma janela é um grupo de linhas relacionadas dentro de um conjunto de resultados. Por exemplo, linhas com o mesmo valor para uma dimensão específica.

Habilite funções de janela em sua consulta com o parâmetro de contexto enableWindowing: true.

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29">#</a> Anexação e substituição simultâneas (experimental)

Druid 28.0.0 adiciona suporte experimental para acréscimo e substituição simultâneos. Este recurso permite substituir com segurança os dados existentes em um intervalo de uma fonte de dados enquanto novos dados são anexados a esse intervalo. Uma das aplicações mais comuns disso é anexar novos dados a um intervalo enquanto a compactação desse intervalo já está em andamento. Para obter mais informações, consulte Anexar e substituir simultaneamente.

O bloqueio de segmento será descontinuado e removido em favor de acréscimo e substituição simultâneos, que são muito mais simples em design. Com acréscimo e substituição simultâneos, o Druid não bloqueia trabalhos de compactação devido à ingestão ativa em tempo real.

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-task-locks-for-append-and-replace-batch-ingestion-jobs">#</a> Bloqueios de tarefas para anexar e substituir trabalhos de ingestão em lote

Os trabalhos de inclusão em lote agora podem compartilhar bloqueios. Isso permite que você execute vários trabalhos de ingestão em lote anexados ao mesmo tempo interno. Os trabalhos de ingestão em lote de substituição ainda exigem um bloqueio exclusivo. Isso significa que você pode executar vários trabalhos de ingestão em lote de acréscimo e um trabalho de ingestão em lote de substituição para um determinado intervalo.

#14407

<a name="28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-streaming-ingestion-with-concurrent-replace" href="#28.0.0-important-changes-and-deprecations-concurrent-append-and-replace-%28experimental%29-streaming-ingestion-with-concurrent-replace">#</a> Ingestão de streaming com substituição simultânea

A leitura de tarefas de streaming do Kafka e do Kinesis com bloqueios APPEND agora pode ser ingerida simultaneamente com a compactação executada com bloqueios REPLACE. A granularidade do segmento do trabalho de streaming deve ser igual ou superior à do trabalho de substituição simultâneo.

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-ability-to-ingest-array-types">#</a> Capacidade de ingerir tipos ARRAY

A ingestão baseada em SQL agora suporta o armazenamento de valores digitados ARRAY em colunas digitadas ARRAY, bem como o armazenamento de matrizes digitadas VARCHAR e numéricas. Anteriormente, o mecanismo de tarefa MSQ armazenava valores digitados em ARRAY como dimensões de vários valores em vez de colunas digitadas em ARRAY.

O mecanismo de tarefas MSQ agora inclui o parâmetro de contexto de consulta arrayIngestMode, que controla como Os tipos ARRAY são armazenados em segmentos Druid. Configure o parâmetro de contexto de consulta arrayIngestMode como array para ingerir tipos ARRAY.

No Druid 28.0.0, o modo padrão para arrayIngestMode é mvd para compatibilidade com versões anteriores, que suporta apenas matrizes do tipo VARCHAR e as armazena como dimensões de vários valores. Este padrão está sujeito a alterações em versões futuras.

Para obter informações sobre como migrar para o novo comportamento, consulte Opções de ingestão para colunas digitadas em ARRAY nas notas de atualização. Para obter informações sobre comportamento de inserção, filtragem e agrupamento para colunas digitadas ARRAY, consulte Colunas de matriz.

<a name="28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-numeric-array-type-support" href="#28.0.0-functional-area-and-related-changes-ingestion-sql-based-ingestion-numeric-array-type-support">#</a> Suporte a tipo de matriz numérica

Os quadros baseados em linha e, por extensão, o mecanismo de tarefa MSQ agora suportam tipos de matriz numérica. Por exemplo, consultas como SELECT [1, 2] são válidas agora, pois consomem uma matriz numérica em vez de falharem com uma exceção de tipo de coluna não suportada.

Novas funções SQL e de consulta nativa permitem avaliar se duas expressões são distintas ou não. As expressões são distintas se tiverem valores diferentes ou se um deles for NULL. As expressões não são distintas se seus valores forem iguais ou se ambos forem NULL.

<a name="28.0.0-functional-area-and-related-changes-querying-improved-subquery-guardrail" href="#28.0.0-functional-area-and-related-changes-querying-improved-subquery-guardrail">#</a> Proteção de subconsulta aprimorada

Agora você pode definir o guarda-corpo maxSubqueryBytes para um dos seguintes:

  • disabled: Configuração padrão. O Druid não aplica proteção ao número de bytes que uma subconsulta pode gerar.

  • auto: Druid calcula a quantidade de memória a ser utilizada para a materialização dos resultados como parte da memória fixa do heap.
    No contexto da consulta, o Druid usa a seguinte fórmula para determinar o limite superior do número de bytes que uma subconsulta pode gerar:

    ((total JVM space - memory occupied by lookups) * 0.5) / maximum queries that the system can handle concurrently

  • INTEGER: O número de bytes a serem usados para materializar os resultados da subconsulta. Defina um valor específico se você entender os padrões de consulta e quiser otimizar o uso da memória.
    Por exemplo, defina o parâmetro maxSubqueryBytes como 300000000 (300 * 1000 * 1000) para um limite de 300 MB. Defina o parâmetro maxSubqueryBytes como 314572800 (300 * 1024 * 1024) para um limite de 300 MiB.

Se druid.metadata.storage.connector.createTables estiver configurado como true e o usuário do armazenamento de metadados tiver privilégios DDL, a tabela de segmentos será atualizada automaticamente na inicialização para incluir a nova coluna used_status_last_updated. Nenhum trabalho adicional é necessário para a atualização.

Se algum desses requisitos não for atendido, serão necessárias etapas de pré-atualização. Você deve fazer essas atualizações antes de atualizar para o Druid 28.0.0, ou os processos do Coordenador e do Overlord falharão.

Embora você possa alterar manualmente sua tabela para adicionar a nova coluna used_status_last_updated, o Druid também fornece uma ferramenta CLI para fazer isso.

#12599

Nos comandos de exemplo abaixo:

  • lib é o diretório lib do Druida
  • extensions é o diretório de extensões Druid
  • base corresponde ao valor de druid.metadata.storage.tables.base na configuração, druid por padrão.
  • O parâmetro --connectURI corresponde ao valor de druid.metadata.storage.connector.connectURI.
  • O parâmetro --user corresponde ao valor de druid.metadata.storage.connector.user.
  • O parâmetro --password corresponde ao valor de druid.metadata.storage.connector.password.
  • O parâmetro --action corresponde à ação de atualização que você está executando. Neste caso, é add-last-used-to-segments

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-recommended-syntax-for-sql-unnest">#</a> Sintaxe recomendada para SQL UNNEST

A sintaxe recomendada para SQL UNNEST foi alterada. Recomendamos usar CROSS JOIN em vez de vírgulas para a maioria das consultas para evitar problemas de precedência. Por exemplo, use:

SELECT column_alias_name1 FROM datasource CROSS JOIN UNNEST(source_expression1) AS table_alias_name1(column_alias_name1) CROSS JOIN UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

Não use:

SELECT column_alias_name FROM datasource, UNNEST(source_expression1) AS table_alias_name1(column_alias_name1), UNNEST(source_expression2) AS table_alias_name2(column_alias_name2), ...

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-dynamic-parameters">#</a> Parâmetros dinâmicos

A versão Apache Calcite foi atualizada de 1.21 para 1.35. Como parte da atualização do Calcite, o comportamento da inferência de tipo para parâmetros dinâmicos mudou. Para evitar qualquer problema de interferência de tipo, CAST explicitamente todos os parâmetros dinâmicos como um tipo de dados específico em consultas SQL. Por exemplo, use:

SELECT (1 * CAST (? as DOUBLE))/2 as tmp

Não use:

SELECT (1 * ?)/2 as tmp

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-nested-column-format">#</a> Formato de coluna aninhada

Colunas do tipo json criadas com Druid 28.0.0 não são compatíveis com versões anteriores de Druid anteriores a 26.0.0. Se você estiver atualizando de uma versão anterior ao Druid 26.0.0 e usar colunas json, atualize para o Druid 26.0.0 antes de atualizar para o Druid 28.0.0. Além disso, para fazer o downgrade para uma versão anterior ao Druid 26.0.0, quaisquer novos segmentos criados no Druid 28.0.0 devem ser reingeridos usando o Druid 26.0.0 ou 27.0.0 antes de fazer o downgrade.

Ao atualizar de uma versão anterior, você pode continuar a escrever colunas aninhadas em um formato compatível com versões anteriores (versão 4).

Em uma tarefa clássica de ingestão em lote, inclua formatVersion na lista dimensions da propriedade dimensionsSpec. Por exemplo:

      "dimensionsSpec": {
        "dimensions": [
          "product",
          "department",
          {
            "type": "json",
            "name": "shipTo",
            "formatVersion": 4
          }
        ]
      },

Para configurar a versão da coluna aninhada padrão, configure a versão do formato desejado nas propriedades de tempo de execução comum. Por exemplo:

druid.indexing.formats.nestedColumnFormatVersion=4

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility">#</a> Compatibilidade SQL

Começando com Druid 28.0.0, a maneira padrão como o Druid trata nulos e booleanos mudou.

Para nulos, o Druid agora diferencia entre uma string vazia e um registro sem dados, bem como entre um registro numérico vazio e 0.
Você pode reverter ao comportamento anterior configurando druid.generic.useDefaultValueForNull como true.

Esta propriedade afeta o armazenamento e a consulta e deve ser definida em todos os tipos de serviço Druid para estar disponível no momento da ingestão e no momento da consulta. Reverter esta configuração para o valor antigo restaura o comportamento anterior sem reingestão.

Para booleanos, o Druida agora usa estritamente 1 (verdadeiro) ou 0 (falso). Anteriormente, verdadeiro e falso podiam ser representados como true e false, bem como 1 e 0, respectivamente. Além disso, Druid agora retorna um valor nulo para comparações booleanas como True && NULL.

Você pode reverter ao comportamento anterior configurando druid.expressions.useStrictBooleans como false. Esta propriedade afeta o armazenamento e a consulta e deve ser definida em todos os tipos de serviço Druid para estar disponível no momento da ingestão e no momento da consulta. Reverter esta configuração para o valor antigo restaura o comportamento anterior sem reingestão.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-null-filters" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-null-filters">#</a> filtros NULL

Se suas consultas usarem NULL na condição de filtro para corresponder cadeias nulas e vazias, você deverá adicionar uma cláusula de filtro explícita para cadeias vazias. Por exemplo, atualize s IS NULL para s IS NULL OR s = ''.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-count-functions" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-count-functions">#</a> COUNT funções

COUNT(column) agora conta strings vazias. Se quiser continuar excluindo strings vazias da contagem, substitua COUNT(column) por COUNT(column) FILTER(WHERE column <> '').

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-groupby-queries" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-sql-compatibility-groupby-queries">#</a> Consultas GroupBy

Consultas GroupBy em colunas contendo valores nulos agora podem ter entradas adicionais, pois nulos podem coexistir com strings vazias.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-stop-supervisors-that-ingest-from-multiple-kafka-topics-before-downgrading" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-stop-supervisors-that-ingest-from-multiple-kafka-topics-before-downgrading">#</a> Interromper Supervisores que ingerem vários tópicos Kafka antes de fazer downgrade

Se você adicionou supervisores que ingerem vários tópicos Kafka no Druid 28.0.0 ou posterior, interrompa esses supervisores antes de fazer downgrade para uma versão anterior ao Druid 28.0.0 porque os supervisores falharão em versões anteriores ao Druid 28.0.0.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60lenientgregtormerge%60-deprecated" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-%60lenientgregtormerge%60-deprecated">#</a> lenientAggregatorMerge obsoleto

A propriedade lenientAggregatorMerge em consultas de metadados de segmento foi descontinuada. Ele será removido em versões futuras. Use aggregatorMergeStrategy. aggregatorMergeStrategy também suporta as estratégias latest e earliest, além das estratégias strict e lenient de lenientAggregatorMerge.

<a name="28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns" href="#28.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-ingestion-options-for-array-typed-columns">#</a> Opções de ingestão para colunas digitadas em ARRAY

A partir do Druid 28.0.0, o mecanismo de tarefa MSQ pode detectar e ingerir matrizes como colunas digitadas ARRAY quando você configura o parâmetro de contexto de consulta arrayIngestMode como array. O parâmetro de contexto arrayIngestMode controla como os valores do tipo ARRAY são armazenados em segmentos Druid.

Quando você configura arrayIngestMode como array (recomendado para conformidade com SQL), o mecanismo de tarefa MSQ armazena todos os valores digitados ARRAY em colunas digitadas ARRAY e suporta o armazenamento de matrizes digitadas VARCHAR e numéricas.

Para compatibilidade com versões anteriores, o padrão arrayIngestMode é mvd. Quando "arrayIngestMode":"mvd", o Druid suporta apenas matrizes digitadas VARCHAR e as armazena como [colunas de string de vários valores] (https://druid.apache.org/docs/latest/querying/multi-value-dimensions).

Quando você define arrayIngestMode como none, o Druid lança uma exceção ao tentar armazenar qualquer tipo de array.

Para obter mais informações sobre como ingerir colunas digitadas ARRAY com ingestão baseada em SQL, consulte Tipos de dados SQL e Colunas de matriz.

O mecanismo GroupBy v1 foi removido. Em vez disso, use o mecanismo GroupBy v2, que tem sido o mecanismo GroupBy padrão em várias versões. Não deve haver impacto em suas consultas. Se você possui uma extensão que implementa AggregatorFactory, esse método deve ser removido de sua implementação.
