druida druida-24.0.0

Apache Druid 24.0.0 contém mais de 300 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de testes adicionais de 67 colaboradores. Veja o conjunto completo de alterações para detalhes adicionais.

<a name="24.0.0-new-features" href="#24.0.0-major-version">#</a> Versão principal

A partir deste lançamento, retiramos o 0 líder da versão de lançamento e promovemos todos os outros dígitos uma posição à esquerda. Druid está agora na versão principal 24, um salto em relação ao lançamento anterior do 0.23.0. Em termos de compatibilidade com versões anteriores ou alterações significativas, esta versão não é significativamente diferente de outras versões principais anteriores, como 0.23.0 ou 0.22.0. Continuamos com a mesma política que usamos em versões anteriores: minimizando o número de alterações que requerem atenção especial durante a atualização e destacando quaisquer que existam nos release notes. Para esta versão, consulte a seção Atualizando para 24.0.0 para obter uma lista de alterações incompatíveis com versões anteriores nesta versão.

<a name="24.0.0-new-features" href="#24.0.0-new-features">#</a> Novos recursos

<a name="24.0.0-new-features-multi-stage-query-task-engine" href="#24.0.0-new-features-multi-stage-query-task-engine">#</a> Mecanismo de tarefa de consulta em vários estágios

Ingestão baseada em SQL para Apache Druid usa uma arquitetura de consulta distribuída de vários estágios, que inclui um mecanismo de consulta chamado mecanismo de tarefa de consulta de vários estágios (mecanismo de tarefa MSQ). O mecanismo de tarefas MSQ estende os recursos de consulta do Druid, para que você possa escrever consultas que façam referência a dados externos, bem como realizar ingestão com SQL INSERT e REPLACE. Essencialmente, você pode realizar a ingestão baseada em SQL em vez de usar as especificações de ingestão JSON usadas pela ingestão nativa do Druid. Além da sintaxe fácil de usar, a interface SQL permite realizar transformações que envolvem vários embaralhamentos de dados. A ingestão baseada em SQL usando o mecanismo de tarefa de consulta de vários estágios é recomendada para ingestão em lote começando no Druid 24.0.0. O lote nativo e a ingestão baseada em Hadoop também continuam a ser suportados. Recomendamos que você revise os problemas conhecidos e teste o recurso em um ambiente de teste antes de implementá-lo na produção. Usar o mecanismo de tarefa de consulta de vários estágios com instruções SELECT simples (não INSERT ... SELECT ou REPLACE ... SELECT) é experimental. Se você estiver atualizando de uma versão anterior do Druid ou usando Docker, você precisará adicionar a extensão druid-multi-stage-query a druid.extensions.loadlist em seu arquivo common.runtime.properties. Para obter mais informações, consulte a documentação Visão geral para ingestão baseada em SQL. #12524 #12386 #12523 #12589

<a name="24.0.0-new-features-nested-columns-" href="#24.0.0-new-features-nested-columns-">#</a> Colunas aninhadas

Druid agora suporta o armazenamento direto de estruturas de dados aninhadas em um tipo de coluna COMPLEX<json> recém-adicionado. As colunas COMPLEX<json> armazenam uma cópia dos dados estruturados no formato JSON, bem como colunas e índices internos especializados para valores literais aninhados – tipos STRING, LONG e DOUBLE. Uma coluna virtual otimizada permite que o Druid leia e filtre esses valores em velocidades consistentes com as colunas Druid LONG, DOUBLE e STRING padrão. Druid SQL recém-adicionado, funções nativas JSON e coluna virtual permitem extrair, transformar e criar valores COMPLEX<json> no momento da consulta. Você também pode usar as funções JSON em instruções INSERT e REPLACE na ingestão baseada em SQL ou em um transformSpec na ingestão nativa como uma alternativa ao uso de um objeto flattenSpec para "nivelar" dados aninhados para ingestão. Consulte Funções SQL JSON, funções nativas JSON, Colunas aninhadas, virtual colunas e o resumo do recurso para obter mais detalhes. #12753 #12714 #12753 #12920

<a name="24.0.0-coordinator%2Foverlord" href="#24.0.0-coordinator%2Foverlord">#</a> Coordenador/Overlord

<a name="24.0.0-coordinator%2Foverlord-you-can-configure-the-coordinator-to-kill-segments-in-the-future" href="#24.0.0-coordinator%2Foverlord-you-can-configure-the-coordinator-to-kill-segments-in-the-future">#</a> Você pode configurar o Coordenador para eliminar segmentos no futuro

Agora você pode definir druid.coordinator.kill.durationToRetain para um período negativo para configurar o cluster Druida para eliminar segmentos cujo interval_end é uma data no futuro. Por exemplo, o PT-24H permitiria que os segmentos fossem eliminados se a data interval_end fosse 24 horas ou menos no futuro, no momento em que a tarefa de eliminação fosse gerada pelo sistema. Um operador de cluster também pode desconsiderar totalmente o druid.coordinator.kill.durationToRetain definindo uma nova configuração, druid.coordinator.kill.ignoreDurationToRetain=true. Isso ignora a data interval_end ao procurar segmentos para eliminar e, em vez disso, pode eliminar qualquer segmento marcado como não utilizado. Esta nova configuração está desativada por padrão e um operador de cluster deve compreender e aceitar totalmente os riscos antes de ativá-la.

<a name="24.0.0-coordinator%2Foverlord-improved-overlord-stability" href="#24.0.0-coordinator%2Foverlord-improved-overlord-stability">#</a> Estabilidade Overlord aprimorada

Contenção reduzida entre o thread de gerenciamento e o recebimento de atualizações de status do cluster. Isso melhora a estabilidade do Overlord e de todas as tarefas em um cluster quando há contagens grandes (mais de 1.000) de tarefas. #12099

<a name="24.0.0-coordinator%2Foverlord-improved-coordinator-segment-logging" href="#24.0.0-coordinator%2Foverlord-improved-coordinator-segment-logging">#</a> Registro de segmento do coordenador aprimorado

Registro de regras de carregamento do Coordenador atualizado para incluir os níveis de replicação atuais. Adicionado ID de segmento ausente e informações de camada de algumas mensagens de log. #12511

<a name="24.0.0-coordinator%2Foverlord-optimized-overlord-get-tasks-memory-usage" href="#24.0.0-coordinator%2Foverlord-optimized-overlord-get-tasks-memory-usage">#</a> Uso de memória de tarefas overlord GET otimizadas

Resolveu a sobrecarga significativa de memória causada pelo console da web chamando indiretamente as tarefas GET do Overlord de API. Isso poderia causar falta de resposta ou falha do Overlord quando a guia de ingestão fosse aberta várias vezes. #12404

<a name="24.0.0-coordinator%2Foverlord-reduced-time-to-create-intervals" href="#24.0.0-coordinator%2Foverlord-reduced-time-to-create-intervals">#</a> Tempo reduzido para criar intervalos

Para otimizar o tempo de cálculo do custo do segmento, reduzindo o tempo necessário para a criação do intervalo, armazene o intervalo do segmento em vez de criá-lo a cada vez a partir de primitivos e reduza a sobrecarga de memória para armazenar intervalos internando-os. O conjunto de intervalos para segmentos tem baixa cardinalidade. #12670

<a name="24.0.0--brokers%2Foverlord" href="#24.0.0--brokers%2Foverlord">#</a> Corretores/Overlord

<a name="24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-preview-button" href="#24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-preview-button">#</a> Botão de visualização

O botão Visualizar aparece quando você digita uma consulta SQL INSERT ou REPLACE. Click o botão para remover a cláusula INSERT ou REPLACE e executar sua consulta como uma consulta "inline" com um limite). Isso lhe dá uma ideia do formato dos seus dados depois que o Druid aplica todas as transformações da sua consulta SQL.

<a name="24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-results-table" href="#24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-results-table">#</a> Tabela de resultados

A tabela de resultados da consulta foi aprimorada em estilo e função. Agora ele mostra ícones de digitação para os tipos de coluna e oferece suporte à capacidade de manipular colunas aninhadas com facilidade.

<a name="24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-helper-queries" href="#24.0.0--brokers%2Foverlord-web-console-new-query-view-%28workbenchview%29-with-tabs-and-long-running-query-support-helper-queries">#</a> Consultas auxiliares

O Web Console agora tem alguns recursos de UI para usuários de notebook e CTE. Você pode fazer referência a consultas auxiliares, elementos recolhíveis que contêm uma consulta, a partir da consulta principal, assim como foram definidas com uma instrução WITH. Ao compor uma consulta complicada, é útil dividi-la em diversas consultas para visualizar as partes individualmente.

<a name="24.0.0--brokers%2Foverlord-web-console-new-sql-based-data-loader" href="#24.0.0--brokers%2Foverlord-web-console-new-sql-based-data-loader">#</a> Novo carregador de dados baseado em SQL

O carregador de dados existe como um assistente GUI para ajudar os usuários a criar uma especificação de ingestão JSON usando ponto e click e visualizações rápidas. O carregador de dados SQL é o análogo de ingestão baseado em SQL. Assim como o carregador de dados nativo, o carregador de dados baseado em SQL armazena todo o estado na própria consulta SQL. Consulte (#12919) para obter mais informações sobre como o carregador de dados difere do fluxo de trabalho Conectar dados externos.

<a name="24.0.0-upgrading-to-24.0-behavior-for-unused-segments" href="#24.0.0-upgrading-to-24.0-behavior-for-unused-segments">#</a> Comportamento para segmentos não utilizados

O Druid retém automaticamente todos os segmentos marcados como não utilizados. Anteriormente, o Druid excluía permanentemente segmentos não utilizados do armazenamento de metadados e do armazenamento profundo após sua duração para retê-los. Este comportamento foi revertido no 0.23.0. #12693

<a name="24.0.0-upgrading-to-24.0-default-for-%60druid.processing.fifo%60" href="#24.0.0-upgrading-to-24.0-default-for-%60druid.processing.fifo%60">#</a> Padrão para druid.processing.fifo

O padrão para druid.processing.fifo agora é verdadeiro. Isto significa que as tarefas de igual prioridade são tratadas de forma FIFO. Na maioria dos casos de uso, essa alteração pode melhorar o desempenho em clusters muito carregados. #12571

<a name="24.0.0-upgrading-to-24.0-update-to-jdbc-statement-closure" href="#24.0.0-upgrading-to-24.0-update-to-jdbc-statement-closure">#</a> Atualização para fechamento de instrução JDBC

Nas versões anteriores, o Druid fechava automaticamente a instrução JDBC quando o ResultSet era fechado. Druid fechou o ResultSet no EOF. Druid encerrou a declaração em qualquer exceção. Este comportamento é, no entanto, fora do padrão. Nesta versão, o driver JDBC do Druid segue os padrões JDBC mais de perto: O ResultSet fecha automaticamente no EOF, mas não fecha o Statement ou PreparedStatement. Seu código deve fechar essas instruções, talvez usando um bloco try-with-resources. O PreparedStatement agora pode ser usado várias vezes com parâmetros diferentes. (Anteriormente, isso não era verdade, pois fechar o ResultSet fechava o PreparedStatement.) Se qualquer chamada para uma Declaração ou PreparedStatement gerar um erro, o código client ainda deverá fechar explicitamente a instrução. De acordo com os padrões JDBC, as instruções não são fechadas automaticamente em caso de erros. Isso permite obter informações sobre uma instrução com falha antes de fechá-la. Se você tiver um código que dependia do comportamento antigo, talvez seja necessário alterá-lo para adicionar a instrução close necessária. #12709
