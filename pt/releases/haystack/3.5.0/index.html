🧭 Classifique e encaminhe com as decisões OpenAI API

Três novos componentes usam o OpenAI Decisions API para escolher como lidar com seus dados sem instruções. OpenAIDecisionsTextRouter envia texto para uma saída nomeada por rótulo, OpenAIDecisionsImageRouter faz o mesmo para imagens e pode enviar decisões de baixa confiança para uma ramificação substituta e OpenAIDecisionsDocumentClassifier responde a perguntas de escolha, pontuação e sim/não sobre documentos e armazena as respostas em seus metadados.

from haystack.components.routers import OpenAIDecisionsTextRouter

router = OpenAIDecisionsTextRouter(
    labels={
        "billing": "Payments, invoices, refunds and charges",
        "technical": "Bugs, crashes and errors in the product",
    },
    instructions="Which team should handle this support request?",
    min_confidence=0.6,
)

print(router.run(text="I was charged twice for my subscription."))
# >> {'billing': 'I was charged twice for my subscription.'}

🧱 Saída estruturada para agentes

O novo StructuredOutputHook valida a resposta final do Agente em relação a um modelo Pydantic ou esquema JSON e a retorna como um ditado em result["structured_output"]. Se a resposta não for validada, o gancho envia o erro de volta ao modelo e permite que ele tente novamente, até max_retries vezes.

from pydantic import BaseModel

from haystack.components.agents import Agent
from haystack.components.generators.chat import OpenAIResponsesChatGenerator
from haystack.dataclasses import ChatMessage
from haystack.hooks.structured_output import StructuredOutputHook

class CityInfo(BaseModel):
    city: str
    country: str

agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(generation_kwargs={"text_format": CityInfo}),
    state_schema={"structured_output": {"type": dict}},
    hooks={"on_exit": [StructuredOutputHook(schema=CityInfo)]},
)

result = agent.run(messages=[ChatMessage.from_user("Which city is the Eiffel Tower in?")])
print(result["structured_output"])
# >> {'city': 'Paris', 'country': 'France'}

Outra novidade para Agentes: o experimental StepBudgetReminderHook informa ao modelo quantos passos faltam ao se aproximar de max_agent_steps, então ele termina com uma resposta em vez de ser cortado.

🎯 Embeddings multivetoriais e MaxSimRanker

Document possui um novo campo multivector_embedding para modelos de interação tardia, como ColBERT, e o novo MaxSimRanker reclassifica os candidatos comparando cada vetor de consulta com os vetores de documento e somando as melhores correspondências. DocumentJoiner(join_mode="merge_embeddings") também pode combinar embeddings densos, esparsos e multivetoriais calculados em paralelo para os mesmos documentos.

Este é o primeiro passo para a recuperação multivetorial no Haystack (#13257). Embedders que produzem embeddings multivetoriais estão em andamento em Haystack Core Integrations: Sentence Transformers e vLLM.

from haystack import Document
from haystack.components.rankers import MaxSimRanker

# Representative multivector embedding for "How do solar panels work?"
query_multivector_embedding = [[1.0, 0.0], [0.0, 1.0]]

documents = [
    Document(content="Wind turbines generate electricity.", multivector_embedding=[[1.0, 0.0], [0.0, 0.2]]),
    Document(content="Solar panels turn sunlight into power.", multivector_embedding=[[0.95, 0.05], [0.15, 0.9]]),
    Document(content="Solar cells absorb light.", multivector_embedding=[[0.9, 0.1], [0.1, 0.9]]),
]

ranker = MaxSimRanker(top_k=2)
result = ranker.run(query_multivector_embedding=query_multivector_embedding, documents=documents)
for document in result["documents"]:
    print(f"{document.score:.2f}: {document.content}")
# >> 1.85: Solar panels turn sunlight into power.
# >> 1.80: Solar cells absorb light.

⚠️ Novo modelo OpenAI padrão

OpenAIChatGenerator, OpenAIResponsesChatGenerator e os avaliadores baseados em LLM agora usam como padrão gpt-5.6-terra, a substituição que a OpenAI recomenda para gpt-5-mini. OpenAI encerra gpt-5-mini em 11 de dezembro de 2026. Pipelines salvos com model: gpt-5-mini continuam usando-o, então atualize seu YAML antes disso.

⬆️ Notas de atualização

  • Aumentar a versão mínima suportada do openai SDK de 2.6.0 para 3.26.0 para suportar as Decisões API.

  • pydantic>=2.12 declarado (>=2.14 em Python 3.15) como a versão mínima suportada. Versões pydantic anteriores a 2.11 geram esquemas JSON diferentes para parâmetros de ferramenta em create_tool_from_function/@tool, ComponentTool e PipelineTool.

  • Se você não definir keep_default_na ou na_values em read_excel_kwargs, XLSXToDocument agora manterá o texto da célula como "NA", "N/A", "NULL" e "None" em vez de tratá-lo como ausente. Uma coluna numérica que contém esse texto não é mais convertida em pontos flutuantes; portanto, na saída CSV, seus números inteiros são renderizados como 1 em vez de 1.0. Para restaurar o comportamento anterior, passe read_excel_kwargs={"keep_default_na": True}.

  • Componentes com entrada Variadic, ou entrada list conectada a vários remetentes, agora recebem os valores na ordem em que os remetentes foram conectados ao Pipeline.connect(). Antes, Pipeline.run() os passava na ordem em que os remetentes eram executados, portanto, os resultados de componentes dependentes de ordem, como DocumentJoiner com weights, podem mudar: conecte os remetentes na ordem em que deseja que os valores cheguem. Se você carregar pipelines do YAML, verifique a ordem das entradas do connections. Pipelines salvos antes deste lançamento listam connections agrupados por remetente, não na ordem em que foram feitos, e a ordem das entradas agora decide a ordem em que um soquete recebe seus valores. Por exemplo, se embedding_retriever estiver listado antes de bm25_retriever em connections, DocumentJoiner agora aplica weights[0] ao recuperador de incorporação, onde antes poderia aplicá-lo ao recuperador BM25. Reordene as entradas que alimentam um soquete Variadic ou list multi-remetente para que os remetentes venham na ordem esperada.

  • O modelo padrão de OpenAIChatGenerator e OpenAIResponsesChatGenerator mudou de gpt-5-mini para gpt-5.6-terra, recomenda a substituição OpenAI. OpenAI encerra gpt-5-mini em 11 de dezembro de 2026. LLMEvaluator, ContextRelevanceEvaluator e FaithfulnessEvaluator também usam o novo padrão.

    Pipelines serializados antes dessa alteração armazenam model: gpt-5-mini e continuam usando-o. Atualize o valor model em seu YAML antes de 11 de dezembro de 2026. Para manter gpt-5-mini até então, passe-o explicitamente: OpenAIChatGenerator(model="gpt-5-mini").

  • Se você ler id, encrypted_content ou status diretamente de reply.reasoning.extra nas respostas de OpenAIResponsesChatGenerator, leia-as nas entradas de reply.reasoning.extra["reasoning_items"]. Por exemplo, substitua reply.reasoning.extra["id"] por reply.reasoning.extra["reasoning_items"][0]["id"] para o primeiro item ou repita a lista para lidar com todos os itens de raciocínio.

  • OpenAIChatGenerator e AzureOpenAIChatGenerator agora solicitam metadados de uso de token por padrão durante o streaming. Para restaurar o comportamento anterior, passe generation_kwargs={"stream_options": {"include_usage": False}}.

  • max_agent_steps agora é uma chave de estado reservada em Agent. Se você definiu uma chave state_schema personalizada chamada max_agent_steps, renomeie-a (por exemplo, my_max_agent_steps): o Agente agora gera um ValueError na inicialização quando uma chave reservada é redefinida.

🚀 Novos recursos

  • Adicione o campo opcional multivector_embedding a Document para armazenar representações multivetoriais, como aquelas geradas por modelos de interação tardia como ColBERT. Este é um primeiro passo para oferecer suporte a incorporadores, recuperadores e classificadores multivetoriais.

  • Adicione MaxSimRanker para classificar documentos por sua semelhança com uma consulta usando embeddings multivetoriais pré-computados. Na recuperação em dois estágios, um recuperador de incorporação pode selecionar rapidamente candidatos usando similaridade densa e, em seguida, o MaxSimRanker realiza uma comparação mais refinada da consulta e do conteúdo de cada candidato para retornar os documentos mais relevantes.

  • Adicione OpenAIDecisionsDocumentClassifier para responder a perguntas de escolha, pontuação e predicados sobre documentos usando o OpenAI Decisions API. As respostas são armazenadas nos metadados do documento.

  • Adicione OpenAIDecisionsImageRouter para rotear imagens para diferentes ramificações do pipeline com base em seu conteúdo, com contexto de texto opcional. Imagens com decisões de baixa confiança podem ser enviadas para uma filial substituta.

  • Adicione OpenAIDecisionsTextRouter para rotear texto para categorias nomeadas usando o OpenAI Decisions API.

  • Adicionado StructuredOutputHook ao haystack.hooks.structured_output. Registrado em on_exit, ele analisa a resposta final do Agente como JSON, valida-a em um modelo Pydantic ou esquema JSON e armazena o resultado como um ditado na chave structured_output por padrão. A chave deve ser declarada no state_schema do Agente, caso contrário o hook gerará um erro em tempo de execução.

    Quando uma resposta não pode ser analisada, o gancho envia o erro de validação de volta ao modelo e mantém o Agente em execução para que possa corrigir sua resposta, até max_retries vezes (2 por padrão). Quando a resposta ainda não pode ser analisada ou o Agente para em outra condição de saída, None é armazenado.

    from pydantic import BaseModel

from haystack.components.agents import Agent
from haystack.components.generators.chat import OpenAIResponsesChatGenerator
from haystack.dataclasses import ChatMessage
from haystack.hooks.structured_output import StructuredOutputHook


class CityInfo(BaseModel):
    city: str
    country: str


agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(generation_kwargs={"text_format": CityInfo}),
    state_schema={"structured_output": {"type": dict}},
    hooks={"on_exit": [StructuredOutputHook(schema=CityInfo)]},
)

result = agent.run(messages=[ChatMessage.from_user("Which city is the Eiffel Tower in?")])
print(result["structured_output"])
# {'city': 'Paris', 'country': 'France'}

  • DocumentJoiner agora suporta join_mode="merge_embeddings" para combinar os campos embedding e sparse_embedding de documentos com o mesmo ID. Isso permite que incorporadores de documentos densos e esparsos sejam executados em paralelo e que suas saídas sejam combinadas antes de passá-las para DocumentWriter.

  • Adicionado StepBudgetReminderHook (experimental), um gancho before_llm que informa ao modelo quantas etapas faltam quando uma execução do Agente se aproxima de max_agent_steps. Antes de cada uma das últimas chamadas remind_within_steps LLM, ele adiciona uma mensagem do usuário envolvida em tags <system-reminder>, como "Você tem 2 de 10 etapas restantes", e na última etapa solicita a resposta final. Isso permite que o Agente conclua a investigação em vez de ser interrompido no meio da investigação.

    from haystack.hooks.budget import StepBudgetReminderHook

agent = Agent(
    chat_generator=OpenAIChatGenerator(model="gpt-5.4-nano"),
    tools=[search],
    max_agent_steps=20,
    hooks={"before_llm": [StepBudgetReminderHook(remind_within_steps=3)]},
)

    As mensagens de lembrete são marcadas com meta={"system_reminder": True}. A compactação de contexto reconhece o marcador e nunca trata um lembrete como tarefa do usuário.

⚡️ Notas de aprimoramento

  • Adicionado o método delete_by_filter_async() ausente ao InMemoryDocumentStore. Anteriormente, apenas o sincronismo delete_by_filter() estava disponível, ao contrário dos demais métodos da loja, que possuem uma contraparte assíncrona. O novo método executa delete_by_filter() no executor do pool de threads da loja e retorna o número de documentos excluídos.
  • O padrão modify_template de BlockingConfirmationStrategy agora informa ao LLM que o usuário deseja que o resultado da chamada da ferramenta modificada seja utilizado e que não deve chamar a ferramenta novamente com os argumentos originais. Com a redação anterior, os modelos frequentemente repetiam a chamada da ferramenta original depois que um usuário modificava seus parâmetros. Passe modify_template explicitamente para manter a mensagem anterior.
  • DocumentJoiner(join_mode="merge_embeddings") agora suporta incorporações multivetoriais, além de incorporações densas e esparsas ao combinar documentos com o mesmo ID.
  • OpenAIChatGenerator agora inclui vários métodos para facilitar às subclasses a personalização do comportamento do componente e, ao mesmo tempo, reduzir a duplicação de código.
  • Cópias profundas de objetos Document e entradas de pipeline agora são mais rápidas, com os mesmos resultados de antes. Document agora implementa __deepcopy__, que copia a lista embedding em uma etapa, em vez de elemento por elemento. Pipeline também retorna valores imutáveis, como strings e números inalterados ao copiar entradas de componentes, sem executar verificações mais caras destinadas a outros objetos. Pipelines que passam incorporações ou muitos documentos incorporados entre componentes são os mais beneficiados.
  • EvaluationRunResult.comparative_detailed_report possui um novo parâmetro align_on para combinar as linhas das duas execuções por uma coluna de entrada, como um ID de pergunta ou a própria pergunta, em vez de por posição. Isso compara as execuções corretamente, mesmo que as mesmas questões sejam avaliadas em uma ordem diferente ou que não sejam todas as mesmas questões. As linhas sem correspondência são mantidas com None para a outra execução.
  • HierarchicalDocumentSplitter agora suporta split_by="token" (requer pip install tiktoken), com a codificação definida pelo novo parâmetro tokenizer_encoding (padrão "o200k_base"). Um novo método warm_up() carrega o tokenizer antecipadamente, em vez de no primeiro run().
  • PPTXToDocument agora extrai texto de formas e tabelas agrupadas, que antes eram ignoradas. As tabelas são incluídas no conteúdo do documento como CSV.
  • OpenAIChatGenerator e OpenAIResponsesChatGenerator agora preservam recusas OpenAI API em ChatMessage.meta["refusal"]. Os aplicativos podem inspecionar esses metadados para detectar e lidar com recusas.
  • OpenAIResponsesChatGenerator agora preserva anotações de texto em reply.meta["annotations"], com annotation_offsets alinhado para localizar citações no texto de resposta concatenado.
  • Adicione um parâmetro tokenizer_encoding a RecursiveDocumentSplitter para escolher a codificação tiktoken usada quando split_unit="token", como em DocumentSplitter. O padrão é "o200k_base", a codificação usada até agora. Defina-o para corresponder ao seu modelo, por exemplo "cl100k_base" para modelos text-embedding-3 da OpenAI, para que os pedaços se ajustem ao limite de token do modelo.
  • RecursiveDocumentSplitter agora valida split_unit na inicialização, gerando um ValueError para valores diferentes de "word", "char" ou "token" em vez de falhar posteriormente durante run().
  • Simplifique a serialização do ChatMessage e a conversão do formato OpenAI para melhorar a legibilidade e a manutenção.
  • Os ganchos agora podem ler o limite de passos do Agente a partir da chave de estado interna max_agent_steps, por exemplo com state.get("max_agent_steps"). Não é retornado como saída do Agente.

🐛 Correções de bugs

  • Corrigida a perda de contagens de tokens de Agent em token_usage quando uma chamada LLM posterior relata um campo de uso como null, por exemplo, prompt_tokens_details relatado em uma chamada e null na próxima. Um valor null agora conta como não reportado, portanto os totais não dependem mais da ordem das chamadas.

  • FilterRetriever, AutoMergingRetriever, SentenceWindowRetriever, CacheChecker e DocumentWriter agora trabalham com armazenamentos de documentos que implementam apenas o API síncrono. Seus métodos run_async usam o método assíncrono do armazenamento quando ele existe e, caso contrário, executam o método síncrono em um thread de trabalho, em vez de falhar no método assíncrono ausente.

  • Corrigido AutoMergingRetriever.run() e run_async() quando as folhas recuperadas de HierarchicalDocumentSplitter têm profundidades diferentes. Folhas mais rasas agora se fundem com irmãos promovidos de ramificações mais profundas, evitando fusões de pais perdidas e documentos pais duplicados no contexto recuperado.

  • ComponentTool agora ignora argumentos de invocação desconhecidos com um aviso em vez de gerar KeyError, incluindo propriedades extras em esquemas personalizados e argumentos adicionados pelo LLM. Esquemas customizados com propriedades desconhecidas também produzem um aviso durante a construção. Um ValueError é gerado quando um esquema customizado omite entradas obrigatórias de componentes não fornecidas por meio de inputs_from_state. As entradas State injetadas automaticamente são excluídas. Isso também se aplica a AgentTool quando um esquema parameters customizado omite messages e não é fornecido por meio de inputs_from_state. Anteriormente, a construção era bem-sucedida, mas a invocação falhava porque faltava a entrada necessária.

  • ImageContent.from_dict, FileContent.from_dict e TextContent.from_dict agora constroem a classe de chamada em vez da classe base, portanto, uma subclasse sobrevive a uma viagem de ida e volta de to_dict/from_dict. Isso corresponde ao comportamento do ByteStream.from_dict.

  • Corrigido DocumentCleaner removendo recuo e novas linhas no início e no final de cada página quando remove_regex estava definido, mesmo em páginas onde o regex não correspondia a nada. As páginas sem correspondência agora permanecem inalteradas, o que preserva o Markdown e o conteúdo do código quando remove_extra_whitespaces, remove_empty_lines e strip_whitespaces estão desativados. As páginas onde as correspondências de regex ainda são removidas como antes.

  • DocumentJoiner agora gera um ValueError quando weights contém NaN ou valores infinitos. Anteriormente, esses valores eram aceitos e transformavam as pontuações do documento em NaN nos modos de junção merge e reciprocal_rank_fusion.

  • DOCXToDocument agora lê texto que um parágrafo mantém dentro de uma inserção rastreada, texto movido, uma tag inteligente, XML personalizado, um campo simples ou um controle de conteúdo embutido preenchido. Anteriormente, apenas as execuções diretas e os hiperlinks de um parágrafo eram lidos; portanto, um documento com alterações controladas não aceitas perdia todas as palavras inseridas e um campo de formulário preenchido perdia seu valor. O texto excluído, o local antigo do texto movido e os controles de conteúdo que ainda mostram seu prompt de espaço reservado são deixados de fora, pois o documento não os mostra.

  • DocumentRecallEvaluator e DocumentNDCGEvaluator agora suportam valores de metadados de lista e dicionário em document_comparison_field em vez de aumentar TypeError. Os valores aninhados são suportados e os documentos duplicados mantêm o comportamento existente de recuperação e pontuação de relevância.

  • FileTypeRouter não perde mais o tipo MIME detectado quando meta é passado junto com caminhos de arquivo.

  • Correção da contagem incorreta de documentos filho duplicados do AutoMergingRetriever ao avaliar limites de mesclagem. Os documentos agora são desduplicados por ID antes da mesclagem, mantendo a cópia com pontuação mais alta na recuperação síncrona e assíncrona.

  • EvaluationRunResult.comparative_detailed_report não perde mais a pontuação da primeira corrida quando ambas as corridas têm o mesmo run_name. Suas colunas são nomeadas novamente como _first e _second, como eram antes do relatório parar de usar pandas. Quando align_on não está definido e as duas execuções têm um número diferente de linhas, ele registra um aviso e preenche a execução mais curta com None em vez de retornar colunas de comprimentos diferentes.

  • DocumentToImageContent agora ignora um arquivo de imagem que não pode ser decodificado em vez de falhar em toda a chamada run(). O documento ignorado obtém None em image_contents e um aviso é registrado.

  • ImageFileToImageContent agora ignora uma fonte que não é uma imagem válida em vez de falhar em toda a chamada run(). Um arquivo que não seja de imagem em um lote misto, como um arquivo .txt, é registrado e omitido do image_contents, enquanto as outras fontes ainda são convertidas.

  • Corrigida a mutação do ListJoiner.from_dict do chamador no lugar: a string list_type_ serializada foi substituída pelo tipo desserializado, portanto, uma segunda chamada from_dict no mesmo dicionário falhou e o dicionário não pôde mais ser despejado para JSON ou YAML. from_dict agora funciona em uma cópia e os dados do chamador permanecem intactos.

  • TiktokenCounter não gera mais ValueError quando o conteúdo da mensagem ou ferramenta contém strings literais de token especial, como <|endoftext|>. Eles agora são codificados como texto comum e contados, de acordo com DocumentSplitter e RecursiveDocumentSplitter.

  • Correção da validação de entrada LLMEvaluator para rejeitar tuplas malformadas e tipos não listados com ValueError.

  • LLMRanker agora ignora índices de resposta que não representam números inteiros válidos.

  • Correção do MetadataRouter.from_dict alterando o dicionário serializado do chamador, o que fazia com que uma segunda chamada from_dict no mesmo dicionário falhasse.

  • Corrija MSGToDocument incluindo incorretamente destinatários Cc e Cco na linha Para. Para isso, Cc e Cco agora usam cabeçalhos de transporte quando disponíveis, retornando aos destinatários do Outlook quando os cabeçalhos estão ausentes ou em branco.

  • ChatMessage.from_openai_dict_format agora aceita uma string vazia como content para mensagens de usuário, sistema, desenvolvedor e ferramenta em vez de gerar ValueError. Mensagens como ChatMessage.from_tool(tool_result="", ...) ou ChatMessage.from_user(text="") agora passam por to_openai_dict_format.

  • Garante que PythonCodeSplitter emita pedaços sintaticamente válidos quando strip_docstrings=True é usado em uma função ou classe cuja docstring é sua única instrução.

  • Corrigido um problema em PythonCodeSplitter onde caracteres de feed de formulário (\f) e certos separadores Unicode podiam fazer com que as funções fossem divididas incorretamente em pedaços. Os limites do pedaço e os metadados start_line/end_line agora permanecem corretos quando esses caracteres aparecem na fonte.

  • DocumentMRREvaluator, DocumentMAPEvaluator e DocumentNDCGEvaluator não contam mais um valor de comparação vazio como correspondência. Anteriormente, quando document_comparison_field era uma string vazia tanto em uma verdade básica quanto em um Documento recuperado, por exemplo meta.file_id="", Documentos não relacionados eram pontuados como relevantes e podiam obter uma pontuação perfeita. DocumentRecallEvaluator já ignorou valores vazios. Com o campo content padrão, isso também significa que um documento verdadeiro com content="" agora está excluído. DocumentMRREvaluator e DocumentMAPEvaluator agora registram um aviso quando nenhum dos documentos verdadeiros de uma pergunta tem um valor de comparação válido, como DocumentRecallEvaluator.

  • RecursiveDocumentSplitter com split_unit="word" não conta mais uma peça somente com espaço em branco, como uma quebra de página (\f) ou uma tabulação entre dois espaços, como uma palavra ao medir pedaços em relação a split_length. O substituto de tamanho fixo do modo de palavra já os ignorou, então produziu pedaços que o resto do divisor mediu como maiores que split_length, e pedaços divididos em separadores continham menos palavras reais do que split_length sempre que continham uma quebra de página. Com split_overlap, tal peça também pode ser considerada uma palavra sobreposta.

    Isso altera os limites dos blocos de texto que contêm quebras de página ou outros espaços em branco cercados por espaços. Divida novamente e reindexe documentos se você confiar em limites de blocos estáveis.

  • OpenAIResponsesChatGenerator e AzureOpenAIResponsesChatGenerator agora aceitam históricos de chat com mensagens assistentes produzidas por outros provedores, por exemplo quando FallbackChatGenerator muda de AmazonBedrockChatGenerator. Raciocínio sem Respostas API O item de raciocínio id é eliminado em vez de ser enviado como um item de entrada inválido e as chamadas de ferramenta sem call_id em extra usam a chamada de ferramenta id como call_id. Anteriormente, o API rejeitava essas solicitações com um erro 400.

  • SASEvaluator agora normaliza as pontuações do Cross Encoder com base no modelo, em vez das pontuações do lote. Anteriormente, logits brutos só eram passados ​​por um sigmóide se pelo menos uma pontuação no lote estivesse acima de 1, então a mesma resposta poderia obter uma pontuação diferente dependendo das outras respostas no lote, e lotes apenas de respostas erradas retornavam pontuações negativas. Isso afetou modelos que retornam logits brutos, como cross-encoder/ms-marco-MiniLM-L-6-v2.

  • Corrigida a sobreposição do limite da frase DocumentSplitter, mantendo uma frase extra quando uma frase já continha exatamente palavras split_overlap. O próximo pedaço agora para nessa contagem de palavras, em vez de inserir a frase anterior.

  • SlidingWindowCompactor não remove mais sempre o resumo que um SummarizationCompactor deixa na tarefa atual. O resumo agora é mantido ou removido junto com a etapa do Agente após ele. Um resumo no início da história é agora tratado como a virada histórica mais antiga.

  • Corrigida falha de StructuredOutputHook ao analisar JSON envolvido em limites de código Markdown usando finais de linha CRLF. As respostas protegidas usando finais de linha LF ou CRLF agora são removidas antes da análise de saída estruturada.

  • Corrigido um problema em que XLSXToDocument eliminava valores de texto literal, como "NA" e "N/A", convertendo-os em células vazias. Quando nem keep_default_na nem na_values são fornecidos em read_excel_kwargs, o conversor usa keep_default_na=False e na_values=[""] para preservar o texto literal enquanto ainda reconhece células vazias como ausentes.

  • Corrigido XLSXToDocument anexando hiperlinks às células erradas quando read_excel_kwargs inclui skiprows, usecols ou names.

  • HierarchicalDocumentSplitter agora define page_number e split_idx_start em relação ao documento original para documentos abaixo do primeiro nível. Anteriormente, eles eram contados a partir do início do bloco pai, portanto, as folhas mais profundas informavam a página errada.

  • InMemoryDocumentStore.bm25_retrieval() e embedding_retrieval(), e suas variantes assíncronas, agora aumentam um ValueError para um top_k negativo. Anteriormente, um valor negativo eliminava silenciosamente os documentos do final dos resultados, por exemplo, top_k=-1 retornava 9 de 10 correspondências.

  • Em JSONConverter, rejeite um valor extra_meta_fields que seja uma string diferente do literal '*' na criação do componente. Anteriormente, essa string era iterada silenciosamente caractere por caractere, produzindo chaves de metadados sem sentido e eliminando os campos pretendidos dos documentos convertidos.

  • PythonCodeSplitter com strip_docstrings=True não descarta mais código que segue uma docstring na mesma linha, como """Docs."""; return 5. Anteriormente, toda a linha era removida, excluindo silenciosamente a instrução e possivelmente deixando um pedaço que não conseguia ser analisado. Neste caso, a docstring agora é mantida no conteúdo do bloco.

  • Pipeline.run_async() passou os valores de uma entrada Variadic, ou de uma entrada list conectada a vários remetentes, na ordem em que os remetentes terminaram, o que poderia mudar entre as execuções, para que DocumentJoiner pudesse aplicar seu weights ao recuperador errado. Os valores agora chegam em ordem de conexão, como em Pipeline.run(), com as entradas do pipeline passadas diretamente para esse soquete primeiro. Pipeline.to_dict() agora salva as conexões na ordem em que foram feitas, portanto, um pipeline carregado com Pipeline.from_dict() mantém a mesma ordem.

  • LinkContentFetcher não adiciona mais uma entrada text/plain ao seu dicionário handlers quando busca conteúdo cujo tipo não corresponde a nenhum padrão registrado (por exemplo font/woff ou multipart/form-data). Esse conteúdo ainda é tratado como texto, como antes.

  • LLM agora declara exit_reason como saída, para que possa ser conectado a outros componentes de um Pipeline. É um dos "text" (resposta completa), "length" (a resposta foi cortada pelo limite de token) ou "content_filter" (a resposta foi cortada pelo filtro de conteúdo do provedor), retirado do finish_reason do gerador de chat. Por exemplo, você pode rotear uma resposta truncada para uma nova tentativa com um max_tokens mais alto.

  • ConfirmationHook agora marca a mensagem do usuário que adiciona quando o usuário modifica os argumentos de uma chamada de ferramenta com meta={"system_reminder": True}. SlidingWindowCompactor e SummarizationCompactor levaram essa mensagem para a tarefa do usuário, para que a compactação pudesse remover a solicitação real. Eles agora ignoram ao encontrar a tarefa. StructuredOutputHook marca suas mensagens de correção da mesma forma.

  • MarkdownHeaderSplitter não inclui mais a sequência de fechamento opcional de um cabeçalho ATX nos metadados header e parent_headers. Por exemplo, ## Install ## agora produz o cabeçalho Install em vez de Install ##. O conteúdo do bloco permanece inalterado.

  • MarkdownHeaderSplitter agora segue as regras CommonMark para blocos de código protegidos, portanto as linhas # dentro deles não são mais divididas como cabeçalhos. Um bloco agora pode fechar com uma cerca mais longa do que aquela que o abriu, as cercas podem ser recuadas em até três espaços e um bloco que nunca é fechado vai até o final do documento. Uma linha que começa com código embutido, onde mais crases seguem os de abertura na mesma linha, não é tratada como uma cerca.

  • MarkdownHeaderSplitter agora reconhece cabeçalhos ATX com até três espaços iniciais, preservando limites de seção e metadados de hierarquia de cabeçalho para cabeçalhos Markdown recuados. As linhas recuadas por quatro ou mais espaços permanecem como conteúdo comum.

  • MarkdownToDocument com table_to_single_line=True agora separa células de tabela com espaços e tabelas do conteúdo circundante com novas linhas. Anteriormente, o conteúdo das células e as tabelas consecutivas eram concatenadas sem separadores, perdendo os limites das palavras.

  • MetaFieldRanker agora rejeita um peso NaN em seu construtor e em run() com um ValueError ao invés de retornar documentos com pontuações NaN.

  • MultiRetriever agora gera um ValueError na inicialização se join_mode não for "concatenate" ou "reciprocal_rank_fusion". Anteriormente, valores não suportados, como "rrf", eram tratados silenciosamente como "concatenate" quando top_k não estava definido.

  • OpenAIChatGenerator agora funciona com ferramentas nos modelos gpt-5.6, gpt-6-sol e gpt-6-luna. Nos Chat Completions API, esses modelos aceitam ferramentas apenas com reasoning_effort="none" e retornam HTTP 400 quando as ferramentas são enviadas sem ele. Quando uma solicitação para um desses modelos inclui ferramentas e generation_kwargs não configura reasoning_effort, OpenAIChatGenerator agora envia reasoning_effort="none", portanto essas solicitações são executadas sem raciocínio. Para combinar raciocínio com ferramentas, use OpenAIResponsesChatGenerator.

  • OpenAIResponsesChatGenerator e AzureOpenAIResponsesChatGenerator agora geram um RuntimeError quando uma resposta transmitida falha, ou seja, quando o fluxo termina com um evento response.failed ou contém um evento error. Anteriormente esses eventos eram ignorados e o gerador retornava uma resposta vazia sem motivo final, portanto a falha passava despercebida.

  • ByteStream.from_dict() agora preserva subclasses ao desserializar um dicionário, em vez de sempre retornar uma instância ByteStream.

  • MockChatGenerator.from_dict() agora preserva a configuração serializada fornecida, para que o mesmo dicionário possa ser carregado mais de uma vez ao usar respostas predefinidas, uma função de resposta ou um retorno de chamada de streaming.

  • Pipeline.run() não altera mais as contagens de visitas armazenadas em um PipelineSnapshot ao retomá-lo. Reproduzir o mesmo instantâneo ou tentar novamente após uma falha downstream agora preserva o estado salvo e não esgota incorretamente o max_runs_per_component.

  • Preservar o texto do campo, como números de slides, em PPTXToDocument quando link_format for "markdown" ou "plain". Os valores dos campos nas caixas de texto e nas células da tabela são mantidos em sua posição original junto com o texto e os links.

  • Preservar todos os itens de raciocínio retornados por OpenAIResponsesChatGenerator em respostas de streaming e não streaming, incluindo o ID de cada item e o conteúdo criptografado. Itens individuais são armazenados em uma única lista ReasoningContent.extra["reasoning_items"]. Itens de raciocínio e chamadas de função mantêm sua ordem relativa original quando reproduzidos em uma conversa de vários turnos. Os metadados de raciocínio de item único serializados anteriormente permanecem com suporte.

  • PythonCodeSplitter agora mantém os decoradores com os métodos ou classes aos quais pertencem, sem copiá-los para outros pedaços. Isso também funciona com decoradores multilinhas.

  • MetaFieldRanker agora trata uma pontuação de relevância NaN como fora do intervalo no modo linear_score. Ele registra o aviso existente e padroniza a pontuação como 0 em vez de classificar o documento por uma pontuação NaN.

  • create_tool_from_function e o decorador @tool agora aumentam ValueError quando um nome de parâmetro obrigatório começa com um sublinhado, como _tenant, e esse parâmetro não está listado em inputs_from_state. Esses nomes não estão expostos ao LLM, portanto uma ferramenta criada sem o valor não poderia ser chamada. Forneça o parâmetro através de inputs_from_state ou forneça um padrão. Parâmetros com prefixo de sublinhado que já possuem um padrão permanecem omitidos do esquema.

  • Correção da classificação MultiQueryEmbeddingRetriever, MultiQueryTextRetriever e TextEmbeddingRetriever para que os documentos sem pontuação sejam colocados depois de todos os documentos pontuados, incluindo documentos com pontuações negativas.

  • Os retornos de chamada de streaming em tempo de execução agora substituem corretamente os retornos de inicialização, evitando erros e avisos causados ​​por retornos de chamada não utilizados. A seleção de retorno de chamada também lida corretamente com objetos que podem ser chamados que são avaliados como falsos.

  • SearchableToolset agora rejeita ferramentas de catálogo que compartilham o nome da ferramenta de pesquisa bootstrap quando o catálogo possui pelo menos ferramentas search_threshold. Anteriormente, a descoberta de tal ferramenta produzia nomes duplicados e falhava na execução do Agente. Defina search_tool_name com um nome diferente para usar esse catálogo.

  • create_tool_from_function e ComponentTool agora excluem parâmetros de retorno de chamada agrupados em typing.Annotated de seus esquemas de ferramentas, incluindo retornos de chamada opcionais. Anotar um retorno de chamada não causa mais falha na construção da ferramenta com SchemaGenerationError; o padrão do retorno de chamada permanece disponível quando a ferramenta é invocada.

  • ImageContent.from_file_path() agora gera um ValueError nomeando o arquivo quando ele não pode ser convertido em imagem, por exemplo porque não existe ou não é uma imagem. Anteriormente, ele gerou um IndexError: list index out of range inútil.

  • SlidingWindowCompactor não remove mais lembretes do sistema da tarefa atual, como os que o StepBudgetReminderHook adiciona. Antes, cada compactação os removia, incluindo um lembrete adicionado para a chamada do LLM prestes a acontecer, que o modelo nunca viu. Agora um lembrete é mantido ou removido junto com a próxima mensagem do assistente e seus resultados de ferramenta, e os lembretes após a última mensagem do assistente são sempre mantidos.

  • Correção de StructuredOutputHook para chaves de estado digitadas em lista, como {"type": list[str]}. O gancho agora substitui o valor do estado pelo resultado validado, ou None em caso de falha, em vez de anexar a ele. Anteriormente, uma tentativa fracassada seguida por uma nova tentativa bem-sucedida retornava [None, "Paris"] em vez de ["Paris"].

  • StructuredOutputHook agora honra max_retries quando StepBudgetReminderHook (ou outro gancho adicionando mensagens system_reminder) é registrado. O gancho conta suas correções desde a última mensagem do usuário, e trata cada lembrete como um novo turno do usuário, então a contagem zera a cada passo: o Agente continuou pedindo correções até max_agent_steps e parou com exit_reason="max_agent_steps". Os lembretes agora são ignorados durante a contagem.

  • create_tool_from_function e o decorador @tool agora deixam *args e **kwargs fora do esquema de parâmetros da Ferramenta. Antes, eles eram adicionados como parâmetros obrigatórios com nomes próprios, como args e kwargs, e era solicitado ao LLM que os preenchesse. Um valor enviado pelo LLM para *args fez com que a chamada da ferramenta falhasse com ToolInvocationError, e um valor para **kwargs atingiu a função aninhada sob o nome do parâmetro. Um *args ou **kwargs não digitado não gera mais uma dica de tipo ausente ValueError.

  • Tool agora rejeita mapeamentos inputs_from_state não vazios para ferramentas que não aceitam entradas. O erro é gerado quando a ferramenta é criada, e não quando é invocada. Se a assinatura do callable não puder ser inspecionada, os nomes dos parâmetros em inputs_from_state não serão verificados no momento da construção.

  • Corrigido FileSystemToolResultStore alterando finais de linha em resultados de texto no Windows.

  • Pipeline.connect agora aceita uma saída Union conectada a uma entrada Union quando cada membro da saída se ajusta a um membro da entrada, em qualquer ordem. Por exemplo, str | None conecta-se a str | int | None e list[Path | ByteStream] conecta-se à entrada list[str | Path | ByteStream] de conversores como TextFileToDocument. Antes, os membros eram comparados por posição, e essas conexões geravam PipelineConnectError. Os tipos Literal são combinados da mesma maneira: Literal["b", "c"] agora se conecta ao Literal["a", "b", "c"].

  • OpenAIDocumentEmbedder e AzureOpenAIDocumentEmbedder agora verificam batch_size quando o componente é criado e geram um ValueError se não for um número inteiro positivo, como 0, -1 ou 0.5 (por exemplo ValueError: batch_size must be a positive integer, but got 0). Antes desta correção, um batch_size inválido era aceito sem nenhum erro. O problema só apareceu mais tarde, quando foi chamado run ou run_async, com erros como ValueError: n must be at least one que não mencionam batch_size.

  • MultiRetriever, MultiQueryTextRetriever, MultiQueryEmbeddingRetriever, LLMMetadataExtractor e LLMDocumentContentExtractor agora geram um ValueError na inicialização quando max_workers é menor que 1. Anteriormente, o valor inválido era aceito, run falhou posteriormente dentro de ThreadPoolExecutor e run_async o tratou silenciosamente como 1.
