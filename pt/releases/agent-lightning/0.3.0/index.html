agente-relâmpago v0.3.0

Agent-lightning v0.3.0 é uma versão importante que apresenta vários novos recursos e correções de bugs. O lançamento é um esforço colaborativo entre as equipes principais do Agent-lightning e a comunidade. Obrigado a todos os colaboradores que tornaram este lançamento possível.

Destaques

  • Integração do Tinker: Apoie o Tinker como um back-end alternativo para Aprendizado por Reforço (#226 #245 #264 #269 #327). Veja código de exemplo, blog 1 e blog 2.
  • Integração do Azure OpenAI: suporte ao Azure OpenAI como back-end para inferência LLM e ajuste fino supervisionado (#256 #327). Código de exemplo.
  • O Lightning Store baseado em MongoDB foi adicionado como um back-end alternativo para o Lightning Store (#323). Documentação.
  • Pacote Contrib: Adicione o pacote contrib para projetos comunitários. Search-R1 está integrado como uma receita de contribuição. Mais chegando. (#239 #396 #410 #412 #417).
  • RESTful API: Estabilize e documente RESTful API para Lightning Store (#241 #275). Documentação.
  • Convenções semânticas do OTel que são projetadas especificamente para áreas de otimização de agentes (#340). Documentação.
  • [Pré-visualização] Painel do Agent-lightning já está disponível (#288 #289 #291 #296 #371 #375). É o aplicativo da web oficial para inspecionar e depurar experimentos do Agent-lightning. Veja detalhes aqui.
  • [Visualização] Exemplo de multimodalidade apresentando VERL e um agente LangGraph no conjunto de dados ChartQA (#379). Código de exemplo.
  • [Pré-visualização] Integre Claude Code como LitAgent e apoie o treinamento no SWE-Bench (#332 #346 #348). Código de exemplo.
  • [Pré-visualização] Weave tracer como substituto do rastreador AgentOps (#277 #411 #420 #423). Documentação.
  • [Pré-visualização] Agregação de nível de trajetória para treinamento mais eficiente com VERL. Veja blog e documentação.

Referência da loja

Nesta versão, o núcleo da Lightning Store foi reprojetado para maior eficiência e escalabilidade (#315 #318 #328 #342 #344 #356 #380 #388 #418 #421). Os resultados de benchmark abaixo demonstram o impacto: com um grande número de executores simultâneos, o v0.3.0 oferece um aumento de até 15x no rendimento em comparação com o v0.2.2.

| Taxa de transferência (#rollout/seg) | v0.2.2 | v0.3.0 (na memória) | v0.3.0 (Mongo) | | :---- | :---- | :---- | :---- | | Mínimo (lote, #runner=32, #turnos=6) | 8.73 | 9.06 | 8.71 | | Médio (lote, #runners=100, #turns=10) | 12.03 | 23.26 | 32.79 | | Médio-alto (lote, #runners=300, #turns=6) | 10.61 | 24.42 | 40.24 | | Grande (lote, #runners=1000, #turns=3) | 3.36 | 14.60 | 50.05 | | Fila longa (fila, #runners=256, #turns=4) | 7.42 | 30.86 | 57.01 | | Rastreamento pesado (fila, #runners=512, #turns=20) | 5.93 | 13.28 | 29.41 |

Notas:

  1. Os benchmarks foram executados em uma única VM do Azure Standard_D32as_v4 (testes de rastreamento grandes e pesados usaram Standard_D64ads_v5), executados por meio de ações GitHub.
  2. Dois padrões de algoritmo são avaliados: o padrão em lote envia um grupo de implementações e espera que todas terminem antes de iniciar o próximo grupo, enquanto o padrão de fila mantém um número definido de implementações em andamento, enviando novas assim que a capacidade for liberada. Detalhes de configuração estão disponíveis aqui.
  3. O número de voltas é diretamente proporcional ao número de vãos gerados por cada implementação.
