Mudanças no API

  1. Remova o recurso de passagem SQL para fonte de dados
  2. Adicione novo assistedQueryEncryptorName e remova a interface QueryAssistedEncryptAlgorithm
  3. Refatore a divisão de leitura e gravação api para melhorar a experiência do usuário
  4. Remova a configuração habilitada para verificação de tabela duplicada
  5. Remova a configuração inútil do item de configuração show-process-list-enabled
  6. Dimensionamento: alteração da palavra-chave para parte da migração de dados DistSQL
  7. Dimensionamento: redesenhar parte da migração de dados DistSQL
  8. DistSQL: Unificar especificação do tipo de parâmetro
  9. DistSQL: Divida SHOW INSTANCE MODE em SHOW MODE INFO e SHOW INSTANCE INFO
  10. DistSQL: Altere DROP SCALING jobId para CLEAN MIGRATION jobId
  11. DistSQL: Remover COUNT INSTANCE RULES
  12. Adicionar banco de dados descobriu que a alta disponibilidade suporta todas as bibliotecas escravas para ficarem offline, e a biblioteca principal assume a configuração do tráfego de leitura
  13. SnowflakeKeyGenerateAlgorithm oferece suporte à configuração do ID do trabalhador no modo autônomo
  14. Substitua sourceDataSourceName por productionDataSourceName na configuração Shadow API
  15. Autoridade: Remova o provedor de autoridade nativo obsoleto

Refatorar

  1. Refatoração de metadados ShardingSphere para dividir metadados reais e metadados lógicos
  2. Use ConnectionContext, QueryContext para remover ThreadLocal em FetchOrderByValueQueuesHolder, TrafficContextHolder, SQLStatementDatabaseHolder e TransactionHolder
  3. Modifique o valor padrão da versão do ShardingSphere-Proxy no gráfico do helm
  4. O contêiner Docker será encerrado se o ShardingSphere-Proxy falhar na inicialização
  5. Helm Charts no repositório ShardingSphere são transferidos para o subprojeto shardingsphere-on-cloud
  6. Dimensionamento: bastante refatoração para melhor reutilização de código
  7. DistSQL: Adicione uma nova categoria chamada RUL
  8. Refatore o módulo de cronograma e divida-o em cronograma de cluster e cronograma autônomo
  9. Remova o modo de memória, mantenha o modo autônomo e o modo cluster
  10. Refatorando a lógica de carregamento da tabela de metadados e a lógica de persistência
  11. Refatoração de bloqueios distribuídos para manter o design de interface mais conciso
  12. Refatorar: Unificar a criação de contêineres proxy em TI a partir de módulos ENV
  13. Refatorar: unificar a configuração do contêiner criado por testcontainer
