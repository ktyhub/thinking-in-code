#netdata v2.12.3

#Release notes

Netdata v2.12.3 é uma versão de patch para solucionar problemas descobertos desde v2.12.2.

Esta versão faz com que o agente detecte uma conexão Netdata Cloud morta mesmo enquanto o tráfego continua fluindo, corrige travamentos de uso após liberação quando um nó obsoleto é removido enquanto um filho ou plug-in ainda o está usando, impede que filhos configurados com parent using h2o travem em todas as conexões, faz com que um IP negado em uma lista de acesso tenha precedência sobre a correspondência de nome de host, rejeita escapes de porcentagem malformados em URLs, limita solicitações de lote MCP, remove travamentos SQLite globais, corrige falhas quando gráficos obsoletos são limpos enquanto eles ainda estão sendo lidos, evita que o agente seja interrompido na inicialização quando uma camada dbengine não pode ser criada, evita que os pais que usam os modos de armazenamento ram ou alloc alterem o histórico de seus filhos após uma lacuna e travem em correlações métricas de vários nós, permite que o SNMP e outros nós virtuais fiquem off-line novamente quando o coletor parar de reportá-los, faz com que os gráficos do PowerStore mostrem os valores que a matriz relata em vez de zeros, faz com que os plug-ins eBPF ignorem substituições de diretório de o ambiente quando eles são executados com privilégios elevados e recarrega rótulos de host do arquivo de configuração que o Agente realmente carregou.

Streaming e Netdata Cloud

  • Corrigido o keepalive MQTT da conexão Cloud. Ele só era verificado quando a conexão estava ociosa, portanto, um link com tráfego de entrada constante nunca percebia um ping sem resposta e poderia ficar parado indefinidamente. Os prazos de ping e confirmação também seguiam o relógio de parede, portanto, uma etapa do relógio causava um falso tempo limite de ping ou detecção atrasada, e em placas sem reconhecimentos RTC nunca expiravam antes da primeira sincronização NTP. Os prazos agora usam um relógio monotônico e uma conexão inoperante é detectada 60 segundos após um ping não respondido (#24427, @stelfrag)
  • O HTTPS client do Agente para Netdata Cloud agora verifica estritamente os tamanhos dos blocos de respostas em blocos e limita essas respostas a 1 MiB. Um tamanho de bloco malformado ou muito grande pode fazer com que o Agente saia enquanto aloca memória para ele (#24483, @stelfrag)
  • Corrigidas falhas de uso após liberação quando netdatacli remove-stale-node ou a limpeza de host órfão e efêmero removiam um host que ainda estava em uso, seja por uma criança se reconectando a ele ou por um plugin que o tinha selecionado como um nó virtual. Um filho que se reconecta durante uma remoção agora é solicitado a tentar novamente, e um nó virtual selecionado por um plug-in é relatado como online e deixado sozinho (#24353, @stelfrag)
  • Removida a opção [stream] parent using h2o. O servidor web h2o foi removido em v2.7.0, e desde v2.8.0 um filho com esta opção habilitada travava em todas as tentativas de conexão com seu pai. Um stream.conf que ainda o define é aceito e a opção é ignorada (#24426, @stelfrag)

Servidor Web e APIs

  • Listas de acesso: um client cujo IP corresponde a uma entrada negada, como !203.0.113.7 em allow connections from = !203.0.113.7 *, agora é negado sem que seu nome de host seja verificado na lista. Isso se aplica a todas as listas de acesso em netdata.conf quando as verificações de DNS estão habilitadas, incluindo o modo heuristic padrão para listas com curinga (#24404, @ArjunD3456)
  • URLs com escapes percentuais malformados agora são rejeitados com HTTP 400. Um % teve que ser seguido por dois dígitos hexadecimais, mas não foi verificado, e um URL que falhou na decodificação foi servido usando a parte decodificada até agora, então /api/v1/info%zz foi respondido como /api/v1/info. Uma solicitação contendo um literal % que não é seguido por dois dígitos hexadecimais, como ?x=100%, agora obtém 400 (#24248, @stelfrag)
  • A chave MCP API e a chave de gerenciamento API agora são comparadas em tempo constante, portanto, o tempo de resposta não revela mais o quão próxima está uma chave adivinhada (#24418, @ArjunD3456)
  • MCP: os lotes JSON-RPC são limitados a 64 solicitações e 16 MiB de respostas, e as mensagens WebSocket a 1 MiB, o mesmo que as solicitações HTTP. Solicitações cujo id não seja uma string, número ou nulo são rejeitadas (#24425, @stelfrag)
  • X-Forwarded-For: o Agente passa a manter apenas o primeiro endereço do cabeçalho, e somente quando for um endereço IPv4 ou IPv6 válido. Este é o endereço client encaminhado mostrado no log de acesso e nas entradas de auditoria de alterações dinâmicas de configuração. Outros valores, como unknown, são descartados (#24452, @ArjunD3456)
  • Registro: a identidade netdata_registry_id agora é lida somente no cabeçalho Cookie, e não em qualquer outro lugar da solicitação, como a string de consulta. Isso afeta apenas Agentes com registro habilitado, que está desativado por padrão (#24494, @ArjunD3456)
  • Reclamação: uma solicitação para /api/v2/claim ou /api/v3/claim com uma chave errada não regenera mais o desafio de reclamação, portanto não pode interromper uma reclamação que um administrador esteja fazendo. O desafio ainda é regenerado na inicialização e após uma reivindicação com uma chave válida (#24531, @stelfrag)

Banco de dados

  • Correção de travamentos do SQLite no Agente. Um bloqueio global foi mantido em torno das chamadas SQLite, então uma instrução lenta bloqueou todos os threads usando SQLite, não apenas aqueles que usam a mesma conexão de banco de dados (#24099, @stelfrag)

  • A corrupção do banco de dados de metadados que aparece enquanto o Agente está em execução agora é marcada para recuperação na primeira consulta com falha, em vez de apenas em um desligamento limpo ou nunca após uma falha. As estatísticas de consulta SQLite não contam mais uma nova tentativa ocupada que posteriormente foi bem-sucedida como uma consulta com falha (#24225, @stelfrag)

  • Os pais que usam os modos de armazenamento ram ou alloc não mudam mais o histórico transmitido e replicado de seus filhos após um intervalo. Cada lacuna moveu todos os valores mais antigos um intervalo antes e exagerou a retenção em um intervalo (#24434, @stelfrag)

  • dbengine agora carrega apenas arquivos de dados com o nome exato que escreve. Uma cópia como datafile-1-0000000001.ndf.bak foi carregada uma segunda vez junto com o arquivo real, e um datafile-2-*.ndf perdido interrompeu o Agente na inicialização. Outros nomes agora são relatados como arquivos desconhecidos e ignorados (#24436, @stelfrag)

  • Corrigidas falhas quando a limpeza de gráficos obsoletos liberava um gráfico, ou seus rótulos, enquanto pesquisas de variáveis de saúde, exportação de Prometheus, alertas e solicitações ou consultas de contexto de API ainda o estavam lendo. Isso inclui a saída do Agente em uma alocação de tamanho enorme (#24466, #24474, @stelfrag)

  • dbengine: o Agente não trava mais na inicialização quando o diretório de uma camada não pode ser criado ou seu thread de inicialização não pode ser iniciado. Uma camada ausente acima da camada 0 agora deixa o Agente em execução com as camadas abaixo dele, e uma camada 0 ausente interrompe a inicialização com um erro (#24435, @stelfrag)

Consultas

  • Corrigida uma falha nas correlações métricas e outras consultas de pesos em dois ou mais nós em Agentes sem uma camada dbengine, como um Pai usando os modos de armazenamento ram ou alloc. Esses agentes agora processam os nós um de cada vez (#24433, @stelfrag)
  • A seção summary.nodes[] de respostas de consulta agora inclui o tempo de consulta do último nó, que estava faltando. Com o options=percentage, a taxa de anomalia da visualização das dimensões não é mais inflacionada. As matrizes chart_labels de /api/v1/data agora têm uma entrada por dimensão, com null onde um gráfico não possui o rótulo (#24460, #24474, @stelfrag)

Aprendizado de máquina

  • [ml] dimension anomaly score threshold agora está limitado a 0.01 a 1.00, com aviso no log quando o valor configurado for alterado. Valores até 5.00 foram aceitos, mas qualquer valor acima de 1.00 desativou silenciosamente a detecção de anomalias, porque a pontuação de anomalia de um modelo não pode exceder 100. Esses valores agora são executados em 1.00, a configuração menos sensível (#24499, @stelfrag)

Colecionadores

  • ebpf.plugin e ebpf-go.plugin são instalados como root setuid. Quando eles são executados com privilégios elevados, eles agora ignoram as variáveis ​​de ambiente NETDATA_*_DIR e usam o plugin, configuração e diretórios de log com os quais foram construídos. As instalações padrão não são afetadas. Uma substituição de [directories] em netdata.conf que aponta esses diretórios para outro lugar não alcança mais os plug-ins eBPF, que registram uma linha para cada variável ignorada (#24412, @stelfrag)
  • Redfish: portas de rede do gerenciador expostas como padrão Os recursos portuários agora são coletados, incluindo seu estado de link e velocidade. Eles foram rejeitados, deixando a coleção permanentemente parcial (#24270, @ilyam8)
  • PAN-OS: panos.ipsec.tunnels agora conta os túneis IPsec estabelecidos em vez de reportar os configurados, e um túnel com SAs sobrepostas durante a rechaveamento conta uma vez. A vida útil restante do SA agora informa a vida útil válida mais longa de um túnel em vez de um valor variável ou somado (#24385, @macmandr197)
  • go.d.plugin: coletores corrigidos, como Cato Networks, falhavam em um ciclo de coleta com um conflito de escopo de host quando os metadados de um host eram alterados enquanto sua identidade permanecia a mesma (#24415, @ktsaou)
  • Cato Networks: a função de topologia agora conecta cada site aos seus dispositivos, mantém todos os túneis WAN observados em vez de mesclar os paralelos e marca os túneis como conectados, desconectados ou desconhecidos. Sites, dispositivos e túneis trazem mais detalhes para solução de problemas, como funções de alta disponibilidade, perda, jitter, medições de última milha e sessões de BGP, e o gráfico observa quando inventário, métricas ou dados de BGP estão faltando. O coletor agora usa Cato SDK v1.1.0 (#24413, @ktsaou, #24362, @ilyam8)
  • ebpf.plugin: o número de PIDs rastreados no ebpf.monitoring_pid não continua mais crescendo em hosts com processos de curta duração. Um processo que saiu antes de sua entrada /proc ser lida foi liberado sem ser subtraído (#24423, @stelfrag)
  • statsd.plugin: com [statsd] set charts as obsolete after habilitado (desativado por padrão), o Agente não trava mais na primeira vez que uma métrica de inatividade é removida. A remoção também não vaza mais os valores da métrica e as métricas usadas pelos gráficos sintéticos são mantidas. A contagem do gráfico privado não é mais completa e bloqueia cada novo gráfico privado (#24440, @stelfrag)
  • Nós virtuais: o tempo limite de inatividade definido por um coletor, como aquele utilizado pelos dispositivos SNMP, volta a funcionar. Ele foi descartado quando o nó foi definido, portanto, um nó virtual nunca ficou offline depois que seu coletor parou de reportá-lo. Um nó virtual assumido novamente por seu coletor local após uma cópia transmitida dele parar agora tem suas verificações de integridade e operação normal restauradas (#24495, @ilyam8)
  • SNMP: uma enquete na qual o dispositivo não respondeu a nenhuma solicitação agora falha. As estatísticas de perfil criadas a partir de metadados armazenados em cache ainda eram relatadas para o nó virtual do dispositivo, mantendo-o ativo após a interrupção de suas medições (#24497, @ilyam8)
  • PowerStore: os gráficos de desempenho, Ethernet e capacidade agora mostram os valores relatados pelo array. O coletor lia os nomes dos campos das amostras brutas, enquanto os rollups diários e de cinco minutos que ele solicita usam nomes diferentes, portanto, esses gráficos mostravam zeros ou estavam ausentes. A CPU agora mostra o pico de utilização do intervalo como uma porcentagem, e as contagens médias de login mantêm suas frações (#24448, @ilyam8)
  • log2journal: linhas JSON que terminam dentro de um escape de barra invertida agora são rejeitadas em vez de serem analisadas com bytes além do final da linha (#24365, @ArjunD3456)
  • log2journal: um grupo nomeado de um padrão PCRE2 ou regra de reescrita que não participa de uma correspondência, como um grupo opcional, não faz mais o analisador ler um byte antes de seu buffer. A saída não muda (#24380, @ArjunD3456)
  • log2journal: corrigidos vários problemas de análise e saída do JSON. Números muito longos com um expoente podem estourar o buffer numérico ou travar o processo, os escapes \u000a e \u0009 descartaram o restante do valor, substitutos não pareados produziram UTF-8 inválido e uma linha que falhou na análise deixou seus campos para a próxima linha no modo JSON e logfmt. Um --inject agora substitui um valor lido do log em vez de ser anexado a ele, e uma reescrita que se refere à sua própria chave lê o valor original (#24443, @stelfrag)
  • go.d.plugin: corrigidas duas corridas de desligamento no gerenciador de tarefas. Um desligamento ou reinicialização com falha poderia esperar até o prazo em vez de terminar, e uma solicitação de função que já tivesse sido aceita poderia ser relatada como rejeitada porque o plug-in estava parando (#24491, @ilyam8)
  • Descoberta de serviço go.d.plugin: nomes e endereços descobertos agora são codificados como dados nos trabalhos gerados pelas regras de descoberta. Eles foram inseridos no YAML como texto, portanto, um endereço IPv6 poderia fazer com que um trabalho falhasse na análise e um nome como on se tornasse booleano. As regras de estoque usam um novo modelo auxiliar job, por exemplo {{ job "name" .Name "url" .Address }}, que as regras personalizadas também podem usar. As regras existentes e as configurações dinâmicas salvas continuam funcionando (#24469, @ilyam8)
  • go.d.plugin: logs e erros do coletor, incluindo aqueles retornados por verificações de configuração dinâmica, não incluem mais conteúdo bruto dos arquivos que um coletor lê, como amostras de log, linhas de configuração ou certificados. Em vez disso, eles nomeiam o arquivo, a linha, o campo e o motivo, portanto, algumas mensagens são menos detalhadas (#24496, @ilyam8)
  • go.d.plugin e ibm.d.plugin: as respostas HTTP lidas pelos coletores, incluindo endpoints Prometheus e OpenMetrics, agora estão limitadas a 64 MiB, medidas após a descompactação gzip. Uma resposta maior falha na coleção em vez de aumentar a memória sem limites. HTTPCheck relata uma resposta como bad_content; use um endpoint menor para verificações de integridade (#24490, @ilyam8)
  • Traps SNMP e S3: os arquivos de estado mantidos por esses coletores agora são lidos e gravados com segurança. Links simbólicos e arquivos especiais são rejeitados, e um arquivo temporário deixado por uma falha não bloqueia mais gravações posteriores (#24462, @ilyam8)
  • Corrigidos problemas de alerta de estoque e metadados: o alerta Portcheck portcheck_connection_fails não procura mais uma dimensão que não existe, os metadados Elasticsearch, OpenSearch e Unbound agora correspondem aos gráficos que descrevem, e os gráficos do módulo Unbound e ethtool são intitulados "Module ..." novamente em vez de "CollectorV1 ..." (#24308, @ilyam8)

Funções

  • A função de progresso agora mostra as chamadas API que falharam com um erro do servidor como erros. Eles foram estilizados com uma severidade que o painel não reconhece e pareciam chamadas bem-sucedidas (#24185, @ilyam8)

Agente

  • Os rótulos de host agora são lidos do arquivo de configuração que o Agente carregou, incluindo aquele fornecido com -c, na inicialização e no netdatacli reload-labels. Os rótulos removidos desse arquivo também são removidos na recarga (#24117, @stelfrag)
  • Os relatórios de falhas agora incluem um rastreamento de pilha para SIGABRT gerado fora do tratamento de erros fatais do próprio Agente (#24094, @stelfrag)
  • Em compilações macOS e Linux sem libbacktrace, o Agente salva novamente seu arquivo de status quando trava, então a próxima inicialização informa o motivo e o sinal de saída (#24345, @stelfrag)
  • Corrigido um uso após livre no desligamento em Pais com filhos arquivados, quando o carregamento de seus contextos ultrapassava a espera de desligamento (#24492, @stelfrag)
  • Correção de mensagens de log com taxa limitada sendo emitidas com mais frequência do que seu limite quando vários threads eram registrados através do mesmo limitador ao mesmo tempo (#24249, @stelfrag)
  • Quando [db] update every está acima de 3600, o aviso agora informa o valor em que foi fixado (3600) em vez de 1. O próprio grampo já estava correto (#24378, @stelfrag)
  • Quando um coletor tenta adicionar uma dimensão sem id, o erro fatal agora diz isso, em vez de culpar a destruição do índice de dimensão do gráfico (#24528, @stelfrag)

Instalação e embalagem

  • O instalador e o atualizador agora tratam o status de saída curl 56, que algumas versões curl retornam em erros de protocolo, como uma falha de download, como os status de saída 22 e 78 (#24276, @Ferroin)
  • Os pacotes do Windows agora incluem pacotes MSYS2 atualizados além da base MSYS2 incluída, incluindo OpenSSL 3.6.5, curl 8.23.0 e msys2-runtime 3.6.11. Cada atualização é fixada por URL e soma de verificação, e o banco de dados do pacote agrupado corresponde aos arquivos enviados (#24473, @stelfrag)
  • Quando a compilação a partir do código-fonte precisa de um conjunto de ferramentas Go e nenhum está instalado, o instalador agora baixa Go 1.27.3 em vez de 1.27.0. Vá para 1.27.0 e versões posteriores permanecem compatíveis (#24411, @ilyam8)

Agradecimentos <a id="v2123-acknowledgements"></a>

Gostaríamos de agradecer aos nossos colaboradores dedicados e talentosos que compõem esta comunidade incrível. O tempo e a experiência que você seja voluntário é essencial para o nosso sucesso.

Opções de suporte <a id="v2123-support-options"></a>

À medida que crescemos, continuamos comprometidos em fornecer o melhor suporte já visto em uma solução de código aberto. Caso você encontre algum problema com alguma das alterações feitas nesta versão ou em qualquer recurso do Agente Netdata, sinta-se à vontade para nos contatar por meio de um dos seguintes canais:

  • Netdata Learn: Encontre documentação, guias e material de referência para monitorar e solucionar problemas de seus sistemas com Netdata.
  • Problemas do GitHub: Use o repositório Netdata para relatar bugs ou abrir uma nova solicitação de recurso.
  • Discussões GitHub: Participe da conversa sobre o processo de desenvolvimento do Netdata e faça parte dele.
  • Fóruns da Comunidade: Visite os Fóruns da Comunidade e contribua para a base de conhecimento colaborativa.
  • Servidor Discord: entre no Netdata Discord e converse com administradores de sistemas, DevOps, SREs e outros solucionadores de problemas que pensam como você. Mais de 2.000 engenheiros já o estão usando!
