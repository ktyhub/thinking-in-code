O que você pode fazer:

  • **Identificar consumo de recursos **: classificar por tempo total de execução, tempo de CPU ou E/S
  • Localize consultas frequentes: encontre consultas com grande número de chamadas que podem se beneficiar do armazenamento em cache
  • Depurar em tempo real: veja as consultas em execução no momento e qual client as iniciou
  • Não são necessárias ferramentas extras: todas as análises acontecem na guia superior do painel Netdata

[!IMPORTANTE] Algumas funções requerem configuração específica do banco de dados (por exemplo, habilitar Query Store, pg_stat_statements ou profiling).

Consulte a documentação de cada coletor para conhecer os pré-requisitos.

Coletor do Microsoft SQL Server (Go) <a id="v290-highlight-mssql-go"></a>

Reconstruímos o coletor do Microsoft SQL Server desde o início em Go, substituindo a implementação C herdada. Isso traz monitoramento abrangente do SQL Server com recursos de análise de consultas em tempo real.

O que você ganha:

| Recurso | Detalhes | |--------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------| | Cobertura completa de métricas | Conexões, solicitações em lote, gerenciador de buffer, memória, estatísticas de espera, bloqueios, transações por banco de dados, latência de E/S, tamanhos de arquivo e status de trabalho do SQL Agent | | Função de principais consultas | Visualização em tempo real de suas consultas que consomem mais recursos diretamente no painel – veja tempo de execução, CPU, E/S, concessões de memória e métricas de paralelismo | | Configuração da IU | Crie e gerencie trabalhos de monitoramento por meio do painel Netdata — não é necessária edição manual do arquivo de configuração | | Monitoramento de replicação | Rastreie o status de replicação, a latência e os avisos para publicações transacionais/mesclagem | | Autenticação flexível | Autenticação SQL, autenticação integrada do Windows, instâncias nomeadas e servidores remotos |

Principais consultas: identifique gargalos de desempenho

A nova função Top Queries extrai dados do Query Store do SQL Server para mostrar:

  • Consultas que consomem o maior tempo total de execução ou CPU
  • Padrões de E/S (leituras lógicas, leituras físicas, gravações)
  • Concessões de memória e uso de tempdb
  • Paralelismo (DOP) entre execuções

[!IMPORTANTE] Requer Query Store habilitado em bancos de dados monitorados (SQL Server 2016+).

O texto da consulta pode conter dados confidenciais – garanta controles de acesso adequados ao painel.

OpenTelemetry Ingestão de registros <a id="v290-highlight-otel-logs-ingestion"></a>

Estamos expandindo nosso suporte ao OpenTelemetry! Seguindo o suporte de métricas adicionado em v2.7.0, o plug-in otel agora ingere logs OpenTelemetry por meio do mesmo endpoint OTLP gRPC.

O que há de novo

  • Ingestão de logs: Envie logs do seu coletor OpenTelemetry ou aplicativos instrumentados diretamente para o Netdata.
  • Armazenamento personalizado: os logs são armazenados em arquivos de diário compatíveis com systemd\ usando uma implementação Rust (não é necessária dependência de libsystemd).
  • Interface unificada: visualize os logs do OpenTelemetry junto com os logs do sistema na guia Logs com recursos completos de pesquisa e filtragem.

Configuração e retenção

Controle seu armazenamento de logs com políticas de retenção configuráveis:

  • Defina limites por uso de disco, contagem de arquivos ou idade
  • Defina locais de armazenamento personalizados
  • Ajuste o tamanho do arquivo e as configurações de intervalo de tempo

Disponibilidade

Disponível em agentes Linux (beta), com suporte para plataformas adicionais em breve.

[!NOTA]
Este recurso está em versão beta. Agradecemos seus comentários!

Aviso de suspensão de uso <a id="v290-deprecation-notice"></a>

Alterado nesta versão

Mudanças importantes na próxima versão secundária

Coletor MS SQL Server: Remoção da versão C

O coletor legado do MS SQL Server baseado em C (parte do windows.plugin) será removido na próxima versão secundária. O coletor baseado em Go (go.d/mssql) agora é a opção padrão e recomendada.

A versão Go oferece vantagens significativas:

  • Mais recursos — inclui a nova função Principais consultas para análise de consultas em tempo real.
  • Suporte a vários trabalhos — monitore diversas instâncias do SQL Server a partir de um único agente.
  • Conexões remotas — conecte-se a instâncias do SQL Server pela rede, não apenas pelo host local.
  • Configuração da UI — crie e gerencie trabalhos de monitoramento diretamente no painel do Netdata.
  • Manutenção mais fácil — beneficia-se da infraestrutura compartilhada da estrutura go.d e dos ciclos de desenvolvimento mais rápidos. Se você estiver usando atualmente o coletor C, consulte o coletor Go documentação de configuração para obter instruções de configuração.

Mudanças importantes na próxima versão principal

Componentes obsoletos

| Tipo de componente | Versões sendo obsoletas | |----------------|--------------------------| | APIs | v1, v2 |

O que isso significa

Somente o v3 API e o v3 Dashboard serão suportados a partir da próxima versão principal. Essas versões mais recentes oferecem desempenho aprimorado, recursos aprimorados e melhor segurança.

Opções de suporte <a id="v290-support-options"></a>

À medida que crescemos, continuamos comprometidos em fornecer o melhor suporte já visto em uma solução de código aberto. Caso você encontre algum problema com alguma das alterações feitas nesta versão ou em qualquer recurso do Agente Netdata, sinta-se à vontade para nos contatar por meio de um dos seguintes canais:

  • Suporte Premium: Clientes que desejam ter um canal direto com a Netdata e suporte priorizado com SLAs definidos podem entrar em contato conosco.
  • Netdata Learn: Encontre documentação, guias e material de referência para monitorar e solucionar problemas de seus sistemas com Netdata.
  • Problemas do GitHub: Use o repositório Netdata para relatar bugs ou abrir uma nova solicitação de recurso.
  • Discussões GitHub: Participe da conversa sobre o processo de desenvolvimento do Netdata e faça parte dele.
  • Fóruns da Comunidade: Visite os Fóruns da Comunidade e contribua para a base de conhecimento colaborativa.
  • Servidor Discord: entre no Netdata Discord e converse com administradores de sistemas, DevOps, SREs e outros solucionadores de problemas que pensam como você. Mais de 2.000 engenheiros já o estão usando!
